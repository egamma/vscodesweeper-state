## Change summary

In the Agents Window / SCM changeset view, there's no discoverable way to undo/discard uncommitted changes (e.g. after running `npm i`) unless the 'Uncommitted Changes' changeset happens to be the one selected.

## Best solution

Either make the Discard Changes action discoverable/available regardless of which changeset is currently selected (when uncommitted changes exist), or improve UI affordance so users landing on another changeset can still reach it — this is a product decision for the agent-host changeset operations owner (src/vs/platform/agentHost/node/agentHostDiscardChangesOperationProvider.ts).
