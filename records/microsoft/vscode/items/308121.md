# Issue #308121 — Support additionalContext output in PreCompact hook

[https://github.com/microsoft/vscode/issues/308121](https://github.com/microsoft/vscode/issues/308121)

## Summary

The requested capability remains absent on current main: PreCompact hooks execute, but their successful output is discarded instead of contributing `additionalContext` to the summarization prompt. The request is bounded and aligned with VS Code's agent customization direction, but the prompt provenance contract needs a maintainer decision before implementation.

## Change summary

Allow PreCompact hooks to return `additionalContext` that is included when generating the compacted conversation summary.

## Best solution

Define a typed PreCompact output contract, collect context from every successful hook in execution order, and include it in the compaction prompt without replacing existing user-provided summarization instructions. Preserve distinct provenance for hook context rather than presenting it as user-authored instructions.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/chat/common/chatHookService.ts`, `extensions/copilot/src/platform/chat/common/hookCommandTypes.ts`, `extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx`, `extensions/copilot/src/extension/prompts/node/agent/test/summarization.spec.tsx`
- **Validation:** Extend the Copilot summarization unit tests to execute multiple successful PreCompact hooks and assert that each returned `additionalContext` value reaches the rendered summarization request in execution order, while existing user summarization instructions remain present; also assert that absent, failed, and empty hook outputs do not alter the prompt.
- **Behavior:**

  > When automatic conversation compaction invokes configured PreCompact hooks, every non-empty `additionalContext` value returned by successful hooks is supplied to the model producing the summary. Context from multiple hooks is retained in execution order, and existing user-provided summarization instructions are not replaced. Failed hooks retain the current error handling and do not inject output. Compaction without hook context produces the same prompt as today.
- **Trace:**

  > `ConversationHistorySummarizer.summarizeHistory` in extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx awaits `executePreCompactHook`, then independently builds `propsInfo` and calls `getSummaryWithFallback`; `executePreCompactHook` currently returns void and ignores every successful result. `PreCompactHookInput` exists in extensions/copilot/src/platform/chat/common/chatHookService.ts, but there is no corresponding output interface, unlike neighboring hook types. The summarization prompt already accepts `summarizationInstructions`, currently rendered under an 'Additional instructions from the user' heading. The reporter's closed draft https://github.com/microsoft/vscode-copilot-chat/pull/4980 demonstrates the relevant boundary and test approach; do not alter hook execution timing, failure behavior, unrelated hook contracts, or general conversation-history selection.
- **Open decisions:**
  - Should PreCompact `additionalContext` be rendered in a separately identified hook-context section, or be combined with the existing user-authored summarization-instructions section? The former preserves provenance; the latter keeps the prompt structure smaller but describes hook-authored content as coming from the user.
