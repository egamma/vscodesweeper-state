# Issue #302684 — bug: File decorations missing for initially opened files when launching VS Code with path argument

[https://github.com/microsoft/vscode/issues/302684](https://github.com/microsoft/vscode/issues/302684)

## Summary

The missing colors are caused by Folder Path Color comparing Windows URI paths case-sensitively, while VS Code correctly treats differently-cased paths as the same resource. Which component requests the resource first can therefore determine which spelling the extension evaluates and caches.

## Change summary

File colors supplied by Folder Path Color disappear for resources first encountered through a CLI-opened path or another extension tree.

## Best solution

Folder Path Color should compare Windows resources using filesystem-aware, case-insensitive path semantics rather than `string.includes`; VS Code's decoration cache should continue sharing results for URIs that identify the same resource.

## Evidence

- **extension implementation:** The Folder Path Color implementation at https://github.com/jacob-j/vscode-folder-path-color/blob/aef9d1bd8e4985b0ab796102d7fb05a910eff83f/src/extension.ts normalizes separators but then uses the case-sensitive expression `normalizedUriPath.includes(fullPath)`. That is not a valid resource-identity comparison on Windows.
- **core resource identity:** On current main, src/vs/workbench/services/decorations/browser/decorationsService.ts constructs its cache with `TernarySearchTree.forUris(key => uriIdentityService.extUri.ignorePathCasing(key))`, so equivalent Windows URI spellings intentionally share one decoration entry. The first request consequently exposes the extension's case-sensitive result to later consumers.
- **reported behavior:** The reporter says changing the extension settings reapplies the colors in https://github.com/jacob-j/vscode-folder-path-color/issues/36#issuecomment-4078662957, consistent with invalidating and recomputing the extension's cached decoration result.
- **extension tracker:** The same behavior was originally reported against the owning extension at https://github.com/jacob-j/vscode-folder-path-color/issues/36.
