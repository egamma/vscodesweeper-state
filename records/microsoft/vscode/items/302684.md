# Issue #302684 — bug: File decorations missing for initially opened files when launching VS Code with path argument

[https://github.com/microsoft/vscode/issues/302684](https://github.com/microsoft/vscode/issues/302684)

## Summary

The missing custom colors originate in the third-party Folder Path Color provider, whose Windows path comparison is case-sensitive. VS Code correctly treats differently-cased Windows file URIs as the same resource, so the provider's first result is cached for subsequent views.

## Change summary

Folder Path Color decorations disappear when differently sourced URI representations reach its provider during startup.

## Best solution

Fix Folder Path Color's `provideFileDecoration` implementation to compare Windows paths using filesystem-aware, case-insensitive semantics rather than raw string containment.

## Evidence

- **extension implementation:** https://github.com/jacob-j/vscode-folder-path-color/blob/main/src/extension.ts compares `uri.path` and configured paths with case-sensitive `String.includes`, despite Windows file paths being case-insensitive.
- **core behavior:** Current `src/vs/workbench/services/decorations/browser/decorationsService.ts` keys cached provider results using `IUriIdentityService` and `ignorePathCasing`, correctly treating differently-cased Windows URIs as the same resource.
- **environment isolation:** The reporter states that the behavior does not reproduce in the OSS build or Extension Development Host and requires custom decorations supplied by third-party extensions.
- **extension tracker:** The same symptom was reported at https://github.com/jacob-j/vscode-folder-path-color/issues/36; changing the extension's settings flushes its provider and restores colors.
