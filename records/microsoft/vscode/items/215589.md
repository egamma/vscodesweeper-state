# Issue #215589 — Go to definition opens another code editor if custom editor is opened

[https://github.com/microsoft/vscode/issues/215589](https://github.com/microsoft/vscode/issues/215589)

## Summary

Still reproducible on main: `doOpenCodeEditor` in the workbench `CodeEditorService` calls `editorService.openEditor(input)` without checking whether a code editor for the same resource is already open in another editor group, so "Go to Definition" from a custom editor's embedded code editor opens a duplicate text editor tab instead of navigating to the existing one.

## Change summary

"Go to Definition" opens a new code editor tab instead of reusing an already-open code editor when a custom editor is active for the same file in a split layout.

## Best solution

In `src/vs/workbench/services/editor/browser/codeEditorService.ts`, the `doOpenCodeEditor` method should check visible editor panes across all groups for an existing code editor matching `input.resource` before falling through to `editorService.openEditor`. If found, apply text editor options to the existing code editor and activate its group. Related broader debt is tracked in https://github.com/microsoft/vscode/issues/124498 (editor override for UI components opening text editors), but this issue is a specific, actionable bug fix worth addressing independently.
