# Issue #321729 — Workspace becomes invalid after running Copilot CLI

[https://github.com/microsoft/vscode/issues/321729](https://github.com/microsoft/vscode/issues/321729)

## Summary

Keep open: an independent reporter confirmed workspace failure in non-Git folders, with git initialization restoring access. The provider implementation has changed since the report; the supplied steps suffice to retest, but neither a complete fix nor a canonical covering both local and WSL failures is established.

## Change summary

Starting an agent session replaces a usable workspace with an inaccessible unknown:/ or vscode-agent-host: workspace, breaking file access and terminal working-directory selection.

## Best solution

Preserve the selected folder and its usable filesystem identity throughout session creation, including non-Git folders and WSL. Reproduce both variants against the current providers before deciding whether workspace mounting and remote-provider availability require separate fixes.
