# Issue #148634 — screenreader reading of inline errors

[https://github.com/microsoft/vscode/issues/148634](https://github.com/microsoft/vscode/issues/148634)

## Summary

Thanks for the context. Current main announces the diagnostic selected through F8, but it can still skip a diagnostic on the cursor's line when the cursor is beyond that diagnostic's range, so the central accessibility gap remains.

## Change summary

Let screen-reader users read an inline diagnostic on the current line without locating its exact underlined column.

## Best solution

Update marker navigation in `src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts` to prioritize a diagnostic on the current line before advancing, then use the existing announcement in the goto-error widget.

## Evidence

- **remaining source gap:** `src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts` `_initIdx` selects a marker only when it contains the cursor or begins at/after the cursor; a diagnostic earlier on the same line is therefore skipped.
- **partial implementation:** Commit 4f311006cd74de167941cdd212340430448de666, merged through https://github.com/microsoft/vscode/pull/316835, added `aria.status` announcement of the selected marker's message in `src/vs/editor/contrib/gotoError/browser/gotoErrorWidget.ts`.
- **related report:** https://github.com/microsoft/vscode/issues/174003 was closed as a duplicate of this issue, confirming that announcement during previous/next-problem navigation belongs here.
- **accepted behavior:** The reporter agreed that F8 would be sufficient if it first selected the diagnostic on the current line and moved the cursor to its range; current main does not consistently provide that line-first behavior.
