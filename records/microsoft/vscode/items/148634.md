# Issue #148634 — screenreader reading of inline errors

[https://github.com/microsoft/vscode/issues/148634](https://github.com/microsoft/vscode/issues/148634)

## Summary

Keep open: current problem navigation can still skip a diagnostic earlier on the cursor's line, while line accessibility signals announce its presence rather than its message. The maintainer-proposed, reporter-accepted current-line-first navigation remains a concrete accessibility improvement.

## Change summary

Let screen-reader users discover and hear the diagnostic on their current editor line without knowing its exact column.

## Best solution

Deliver the accepted current-line-first F8 experience in editor marker navigation, exposing the diagnostic message and moving to its location before navigating elsewhere. Preserve subsequent problem traversal and avoid requiring automatic, potentially noisy diagnostic speech.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts`, `src/vs/editor/contrib/gotoError/browser/gotoError.ts`, `src/vs/editor/contrib/gotoError/browser/gotoErrorWidget.ts`
- **Validation:** Create a file with a diagnostic ending before the cursor on the same line and another diagnostic later in the file. With a screen reader enabled, invoke F8: the first invocation must visit and announce the current-line diagnostic; subsequent navigation must advance normally. Repeat with the cursor before and inside the diagnostic, with no current-line diagnostic, and with Alt+F8 current-file navigation. Establish automated MarkerList initialization checks alongside the manual speech check.
- **Behavior:**

  > A screen-reader user on a line containing a diagnostic must be able to discover its message without knowing the diagnostic's exact column. The accepted interaction is for initial F8 navigation to visit the current-line diagnostic even when its range precedes the cursor, moving the cursor to the diagnostic's location and exposing its message. Subsequent invocations continue normal problem traversal, and lines without diagnostics retain existing navigation behavior. Verify both target selection and actual screen-reader speech; automatic reading while arrowing through lines is not required by the accepted direction.
- **Trace:**

  > MarkerController.navigate in src/vs/editor/contrib/gotoError/browser/gotoError.ts passes the cursor position to MarkerList.move; initial selection is computed by MarkerList._initIdx in markerNavigationService.ts. That method tests range containment or whether the cursor precedes the marker start, so it can miss a diagnostic wholly before the cursor on the same line. MessageWidget.update in gotoErrorWidget.ts already sends the selected marker's accessible label, including its message, through aria.status; speech reliability was not executed or verified. The line accessibility signal separately detects diagnostic presence but announces only 'Error on Line'. The accepted product direction is recorded at https://github.com/microsoft/vscode/issues/148634#issuecomment-1118676567 and https://github.com/microsoft/vscode/issues/148634#issuecomment-1126908811. Preserve subsequent traversal, existing severity ordering, and current-file versus cross-file command boundaries; the session must establish automated selection coverage and a manual screen-reader acceptance check before claiming completion.

## Evidence

- **Accepted direction:** https://github.com/microsoft/vscode/issues/148634#issuecomment-1118676567 proposes making F8 first visit the current line even when the diagnostic precedes the cursor's column. The reporter accepts that behavior in https://github.com/microsoft/vscode/issues/148634#issuecomment-1126908811; a decline close would contradict the established direction.
- **Remaining navigation gap:** In src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts, MarkerList._initIdx selects a marker when its range contains the cursor or its start follows the cursor. A single-line diagnostic ending before the cursor does not satisfy either condition, even on the same line. In gotoError.ts, MarkerController.navigate passes the actual cursor position, and editor.action.marker.nextInFiles binds this traversal to F8.
- **Existing capabilities are partial:** gotoError.ts also registers editor.action.marker.next on Alt+F8 for current-file traversal, but it uses the same column-sensitive initialization. gotoErrorWidget.ts already calls aria.status with the selected diagnostic's message in MessageWidget.update. EditorTextPropertySignalsContribution's MarkerTextProperty detects diagnostics anywhere on a line, but src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts defines the corresponding announcement as 'Error on Line', not the diagnostic text. These capabilities do not cover current-line-first discovery.
