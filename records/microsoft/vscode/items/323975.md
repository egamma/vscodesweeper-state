# Issue #323975 — shellIntegration.ps1 Script digital signatures do not match file hashes

[https://github.com/microsoft/vscode/issues/323975](https://github.com/microsoft/vscode/issues/323975)

## Summary

The reporter uses portable mode (zip installation) and gets a signature hash mismatch on shellIntegration.ps1. The script IS signed since the fix in issue #174021, but Windows marks files extracted from a downloaded zip with a Zone.Identifier that causes signature verification to fail. This is either a Windows-side restriction requiring the user to unblock the zip before extracting, or a remaining gap in how VS Code handles this scenario. Needs more info to confirm.

## Change summary

Shell integration fails to activate in portable mode because shellIntegration.ps1's digital signature does not match the file hash, likely due to Windows Zone.Identifier tagging on zip-extracted files.

## Best solution

Confirm whether the reporter downloaded the zip and extracted without unblocking first. If so, this is the same Windows zone-marking behavior discussed in https://github.com/microsoft/vscode/issues/174021 — the workaround is to right-click the zip → Properties → Unblock before extracting. If the issue persists even after unblocking, it indicates a real signing or hash problem that the terminal-shell-pwsh area should investigate.
