# Issue #90005 — Allow to reveal an empty TreeView programmatically

[https://github.com/microsoft/vscode/issues/90005](https://github.com/microsoft/vscode/issues/90005)

## Summary

Keep open: revealing an empty tree is implemented behind the treeViewReveal proposal, but the stable TreeView API still requires an element. The api-proposal label protects this tracking issue from closure until the API owners finalize or abandon the proposal.

## Change summary

Provide a supported, typed TreeView API for showing a contributed tree even when it contains no elements.

## Best solution

Have the API owners resolve and finalize the empty-tree reveal contract, following the recorded preference for accepting undefined. The generated view-focus command provides a workaround, but does not finalize the typed TreeView API.

## Evidence

- **Stable versus proposed API:** src/vscode-dts/vscode.d.ts:12217 declares TreeView.reveal(element: T, ...), whereas src/vscode-dts/vscode.proposed.treeViewReveal.d.ts adds reveal(element: T | undefined, ...). The capability remains proposed rather than finalized; the api-proposal hard keep-open rule applies.
- **Existing runtime behavior:** src/vs/workbench/api/common/extHostTreeViews.ts:522-539 forwards an absent element to $reveal, although it first requires TreeDataProvider.getParent. src/vs/workbench/api/browser/mainThreadTreeViews.ts:75-86 opens the view before checking itemInfo, so the runtime can show an empty tree without revealing an item. This agrees with the discussion's reports that reveal(undefined) works, while leaving the stable typing gap.
- **Existing command workaround:** src/vs/workbench/services/views/browser/viewsService.ts:557-600 registers the generated `${viewDescriptor.id}.focus` command unless a custom focus command is supplied. It calls IViewsService.openView without requiring a tree element, providing a command-based workaround rather than a finalized TreeView method.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/90005#issuecomment-723089875 proposes accepting undefined as the first reveal argument. https://github.com/microsoft/vscode/issues/90005#issuecomment-1068121391 reiterates that preference and suggests treating show/hide as a separate proposal.
