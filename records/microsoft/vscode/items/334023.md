# Issue #334023 — Steering message remains queued when sent during Copilot SDK session refresh

[https://github.com/microsoft/vscode/issues/334023](https://github.com/microsoft/vscode/issues/334023)

## Summary

Fresh, precisely traced team-authored report; verified in current source that CopilotAgent.setPendingMessages silently drops a steering message when the live SDK entry is mid-resume, and _registerLiveChat has no logic to replay pending state once the entry is restored — no fix exists yet on main.

## Change summary

A steering message sent while the Copilot SDK session is mid-restart due to an active-client config change is accepted into protocol state but never delivered or retried, and appears silently stuck in the queue indefinitely.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotAgent.ts, either buffer the steering/pending message when setPendingMessages can't find a live target (instead of warn+return) and flush it from _registerLiveChat once the resumed session is registered, or have the active-client restart path replay any pending chat state after _destroyLiveSession/_registerLiveChat completes.
