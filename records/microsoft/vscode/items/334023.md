# Issue #334023 — Steering message remains queued when sent during Copilot SDK session refresh

[https://github.com/microsoft/vscode/issues/334023](https://github.com/microsoft/vscode/issues/334023)

## Summary

The lost-steering race remains present on current main: Copilot removes the live SDK entry during configuration refresh, and a concurrent pending-message sync returns without delivery or retry. This is a bounded, source-confirmed Agent Host bug that should remain open.

## Change summary

Preserve and deliver a steering message submitted while its Copilot SDK session is temporarily unavailable during refresh.

## Best solution

Make Copilot's pending-message synchronization durable across its per-chat refresh lifecycle so the current authoritative steering message is delivered after the live SDK entry is restored, without changing queued-message or ordinary send behavior. Treat the earlier restore/configuration ordering race as separate follow-up work unless needed for correctness.
