# Issue #262711 — MCP view leaks

[https://github.com/microsoft/vscode/issues/262711](https://github.com/microsoft/vscode/issues/262711)

## Summary

The leak remains source-reproducible on current main, and an open draft PR explicitly addresses it. Keep the issue open while that human-owned fix attempt is reviewed or replaced.

## Change summary

Rapidly hiding and restoring AI-related views can leak the disposable store created for an asynchronous MCP server query.

## Best solution

Review and either land or supersede https://github.com/microsoft/vscode/pull/266174, ensuring overlapping MCP view queries and view disposal cannot orphan query-scoped disposable stores.

## Evidence

- **current source:** In src/vs/workbench/contrib/mcp/browser/mcpServersView.ts, McpServersListView.show() clears the current input and then awaits query(); query() creates its DisposableStore before awaiting queryGallery() or queryLocal(). Overlapping show() calls can therefore complete out of order and replace this.input without disposing the displaced result.
- **reported trigger:** The reporter observed GCBasedDisposableTracker failures rooted at DefaultBrowseMcpServersView.query() while hiding AI and toggling that state, matching the overlapping asynchronous show() path still present on main.
- **open fix PR:** https://github.com/microsoft/vscode/pull/266174 is an open draft with `Fixes #262711`; it modifies src/vs/workbench/contrib/mcp/browser/mcpServersView.ts to serialize outstanding queries and add disposal cleanup. It remains review-required and unmerged.
