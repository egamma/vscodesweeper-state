# Issue #280816 — Agents are limited over SSH

[https://github.com/microsoft/vscode/issues/280816](https://github.com/microsoft/vscode/issues/280816)

## Summary

The reporter confirmed that removing forced UI-side Copilot extension placement restored all file tools. The remaining capability—working with remote workspace files while Copilot runs locally—is already tracked by an older, verified open issue with the same observable SSH file-tool failure.

## Change summary

Allow Copilot agent file tools to access an SSH workspace when remote.extensionKind forces Copilot to run on the local UI host.

- **Reporter-confirmed resolution:** In https://github.com/microsoft/vscode/issues/280816#issuecomment-3899484367, the reporter identifies remote.extensionKind overrides forcing GitHub.copilot and GitHub.copilot-chat to ["ui"]. Removing the overrides from both Windows user settings and remote workspace settings, reloading, and starting a new chat restored read_file, list_dir, replace_string_in_file, and create_file.
- **Verified older canonical:** https://github.com/microsoft/vscode/issues/269919 is currently OPEN and was created on 2025-10-05, before this report. Its body explicitly describes Copilot Agent failing to edit/add remote SSH files with the same ["ui"] overrides, and comments independently confirm that symptom. Its requested UI-side remote-file support encompasses this report, although its motivating environment lacks remote internet access.
- **Established product boundary:** The canonical issue quotes maintainer guidance that Copilot must run on the remote extension host by default and that forcing local execution prevents workspace-file access. https://github.com/microsoft/vscode/issues/289166#issuecomment-3840704632 likewise recommends removing remote.extensionKind and using the defaults. This supports treating the remaining request as additional supported capability rather than a confirmed defect in normal remote placement.
- **Current source:** src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts:getUserConfiguredExtensionKind reads remote.extensionKind, and getConfiguredExtensionKind prioritizes that override over product and manifest declarations. extensions/copilot/src/extension/tools/node/listDirTool.tsx resolves input through resolveToolInputPath before reading through IFileSystemService; extension-host placement remains relevant to the reported path.
- **Related fix does not establish completion:** https://github.com/microsoft/vscode-copilot-chat/pull/3795 addresses unnecessary external-file confirmation for nonexistent paths and explicitly fixes https://github.com/microsoft/vscode/issues/292424. It does not establish support for SSH workspace file access from a forced Windows UI host, so it is not a fixing commit for this report.
