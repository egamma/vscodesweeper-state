## Evidence

- **Reporter evidence identifies the trigger:** The supplied Git log, https://github.com/user-attachments/files/24059626/git_output_log.txt, records the repository root and real path as e:\. The reporter explicitly confirmed this is a local internal SSD, not a remote or mapped drive.
- **Failure is not only visual:** https://github.com/user-attachments/files/24059666/window_logs_from_error_show_logs_button.txt records failure to resolve the git: original resource for a tracked file under E:\ with ref '~'. The thread supplies working/nonworking screenshots and independent reports of missing decorations, including another confirmation in August 2026.
- **Current-source root cause:** extensions/git/src/util.ts:308–339 strips the trailing separator before path.normalize(). On Windows, a drive root such as e:\ becomes e:, which normalizes to the drive-relative e:.; isDescendant consequently rejects files beneath that root.
- **Both symptoms share the failing lookup:** Model.getOpenRepository in extensions/git/src/model.ts:956–1000 uses isDescendant to select a repository. GitQuickDiffProvider.provideOriginalResource in extensions/git/src/quickDiffProvider.ts rejects files when that lookup does not return its repository, suppressing gutter diffs. GitFileSystemProvider.stat/readFile in extensions/git/src/fileSystemProvider.ts throw FileNotFound when the same lookup fails, explaining the attached editor error.
- **Verified canonical:** https://github.com/microsoft/vscode/issues/297275 is currently open and reports the same Windows 11 build 26200, 1.104-to-1.105 regression and unreadable git: original resources. Its discussion confirms persistence in 1.109.5 and identifies the same normalizePath/Model.getOpenRepository defect, with a reporter-tested local correction: https://github.com/microsoft/vscode/issues/297275#issuecomment-4971886852. Although newer, it provides the stronger diagnosis of the shared root cause.
- **Regression history, not a landed fix:** https://github.com/microsoft/vscode/commit/b276d35cd60b69b24cd047c79cad8118b3453de3 introduced trailing-separator removal followed by normalization and moved normalization ahead of the isDescendant prefix comparison. The implicated behavior remains in the checkout; this commit is regression evidence, not fix provenance.
- **Other candidates do not establish the same defect:** https://github.com/microsoft/vscode/issues/184638 discusses symlink-related missing decorations with working diff editors; https://github.com/microsoft/vscode/issues/252145 concerns staged highlights disappearing beside new edits; https://github.com/microsoft/vscode/issues/330695 concerns font-property extension decorations. https://github.com/microsoft/vscode/issues/331774 additionally reports non-root repository lookup failures, whose equivalence is not established.
