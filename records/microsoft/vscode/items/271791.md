## Evidence

- **Reporter logs identify the trigger:** https://github.com/user-attachments/files/24059626/git_output_log.txt records the opened repository root as e:\, followed by GitFileSystemProvider readFile/stat warnings saying Repository not found for a tracked file beneath that root. https://github.com/user-attachments/files/24059666/window_logs_from_error_show_logs_button.txt records the corresponding git: resource resolution failure. This is more specific than a gutter painting problem.
- **Current source confirms the defect:** extensions/git/src/util.ts:308-340 unconditionally removes a trailing separator before path.normalize(). On Windows, e:\ becomes the drive-relative e: and normalizes to e:.; isDescendant consequently rejects ordinary files beneath e:\. extensions/git/src/model.ts:956-999 uses that check in Model.getOpenRepository, and GitFileSystemProvider.stat/readFile in extensions/git/src/fileSystemProvider.ts throws FileNotFound when repository lookup fails.
- **Gutter failure follows the same lookup:** GitQuickDiffProvider.provideOriginalResource in extensions/git/src/quickDiffProvider.ts rejects a file when repositoryResolver.getRepository(uri) does not return its repository. Thus the drive-root lookup failure prevents supplying the original resource needed for gutter decorations, while Source Control can still list changes.
