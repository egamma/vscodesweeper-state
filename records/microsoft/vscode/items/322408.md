# Issue #322408 — setModelConfiguration write per-model settings to the wrong provider group when multiple groups share the same vendor

[https://github.com/microsoft/vscode/issues/322408](https://github.com/microsoft/vscode/issues/322408)

## Summary

Verified duplicate of the older, still-open https://github.com/microsoft/vscode/issues/317500, which reports the same symptom (per-model config saved to the wrong provider group when several groups share a vendor) and is already assigned to the engineer who authored the partial fix in #322872/PR #322974. Part of this bug (the 'model never configured yet' fallback) is fixed on main, but the 'Additionally' half the reporter called out — the first-step `g.settings?.[metadata.id]` lookup still matching by vendor only, ahead of the model→group map — remains unfixed; closing here and carrying that detail into #317500 keeps the remaining work in one place.

## Change summary

setModelConfiguration can still write per-model settings to the wrong provider-group entry when two same-vendor groups already have colliding settings keys for a model id, because the first lookup step only matches by vendor + settings presence and never consults the model→group map.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/317500 (open, assigned) — the remaining fix is to make the first lookup step in setModelConfiguration (src/vs/workbench/contrib/chat/common/languageModels.ts, ~line 1656) consult `_modelsGroups` the same way the second step already does (line 1664), instead of matching purely on vendor + `settings?.[metadata.id] !== undefined`.
