# Issue #322408 — setModelConfiguration write per-model settings to the wrong provider group when multiple groups share the same vendor

[https://github.com/microsoft/vscode/issues/322408](https://github.com/microsoft/vscode/issues/322408)

## Summary

This is a duplicate of #322872, which reported the same vendor-matching bug in setModelConfiguration and was fixed by PR #322974 (commit fa3b663f7234), now verified and shipped in Insiders.

## Change summary

setModelConfiguration writes per-model settings to the wrong provider group when multiple groups share the same vendor, because the group lookup matches by vendor name alone instead of using the model→group mapping.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/322872 — the core bug (vendor-only fallback) was fixed there. The reporter's note about a remaining first-step ambiguity (line 1403, when two same-vendor groups both have settings for the same model id) is a valid but narrower edge case; if it matters in practice, a new focused issue would be appropriate.
