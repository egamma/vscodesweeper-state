# Issue #322408 — setModelConfiguration write per-model settings to the wrong provider group when multiple groups share the same vendor

[https://github.com/microsoft/vscode/issues/322408](https://github.com/microsoft/vscode/issues/322408)

## Summary

This is a duplicate of the verified open issue tracking per-model settings being saved to the wrong same-vendor provider group. Consolidate there, preserving this report's additional finding that existing settings can also select the wrong group.

## Change summary

Per-model configuration changes can target another provider group sharing the same vendor and model ID.

## Best solution

Track the remaining work in https://github.com/microsoft/vscode/issues/317500 so configuration writes consistently target the selected model's owning provider group, including when another group already contains settings for the same model ID.

## Evidence

Its body provides reproduction steps through Manage Language Models and explicitly expects settings to be saved to the group that owns or exposed the selected model. That ownership requirement covers this report's full scope.
- **Same underlying defect:** Both reports identify setModelConfiguration selecting a destination by vendor and existing settings rather than the selected model's provider-group ownership. Different operating systems and example providers do not establish separate root causes.
- **Remaining defect on current main:** src/vs/workbench/contrib/chat/common/languageModels.ts:1663-1697 now consults _modelsGroups when no existing settings match, but first assigns group using allGroups.find(g => g.vendor === metadata.vendor && g.settings?.[metadata.id] !== undefined). An existing entry in the wrong same-vendor group therefore still bypasses the ownership lookup. The fallback improvement does not resolve this report's existing-settings case.
- **Evidence to preserve:** https://github.com/microsoft/vscode/issues/322408 adds the shared metadata.id case: separate endpoints can expose the same model ID, and an existing settings entry in the first group can capture configuration writes intended for the second group.
