# Issue #267476 — Source Control: Cannot commit no-diff merge resolution when other modified tracked files are unstaged

[https://github.com/microsoft/vscode/issues/267476](https://github.com/microsoft/vscode/issues/267476)

## Summary

Confirmed on current main: the smart-commit prompt in `smartCommit()` does not check for an in-progress merge, so a no-diff merge resolution with unstaged tracked files triggers the 'stage all changes?' dialog instead of allowing the merge commit. The fix pattern already exists at line 2484 for the empty-commit guard.

## Change summary

During a no-diff merge resolution, the Source Control GUI's smart commit logic blocks committing when other tracked files have unstaged modifications, forcing the user to the CLI.

## Best solution

Add `&& !repository.mergeInProgress` (and likely `&& repository.rebaseCommit === undefined`) to the condition at line 2419 of `extensions/git/src/commands.ts`, mirroring the guard already present at line 2484 for the empty-commit check. This lets merge/rebase commits proceed without the smart-commit prompt interfering.
