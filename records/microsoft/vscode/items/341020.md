# Issue #341020 — Agents window: cannot hide the file editor area while keeping the file tree open

[https://github.com/microsoft/vscode/issues/341020](https://github.com/microsoft/vscode/issues/341020)

## Summary

Thanks for the detailed report. The Agents window deliberately docks an empty Files placeholder tab in the side pane, and the layout docs describe it as a managed, intended part of the layout. The reporter has a fair point that it wastes space for users who open files in popups (`workbench.editor.useModal: all`). The request is new and has no maintainer input yet, so it stays open for the Agents-window owners to decide.

## Change summary

Allow hiding the inline editor area beside the Files tree in the Agents window side pane, for users whose files open in modal editors.

## Best solution

Agents-window owners decide whether the empty Files placeholder editor area should be skipped or collapsible when `workbench.editor.useModal` is `all`. The likely place is the desktop layout controller, which manages the docked Files and Changes tabs.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/layout/browser/desktop/desktopDockedTabsCoordinator.ts`, `src/vs/sessions/contrib/layout/browser/baseSessionLayoutController.ts`, `src/vs/sessions/contrib/editor/browser/emptyFileEditor.ts`
- **Validation:** A desktopLayoutController test with useModal 'all' that asserts the expected Files/Changes tab and editor-part visibility after the Changes -> Files round trip from the issue's repro steps.
- **Behavior:**

  > With `workbench.editor.useModal: all` in the Agents window, the user can keep the Files tree visible without a reserved empty editor area beside it. Opening a file still shows it in a popup. Without `useModal: all`, behavior is unchanged.
- **Trace:**

  > The empty Files placeholder (EmptyFileEditorInput, rendered by EmptyFileEditor) is docked by desktopDockedTabsCoordinator.ts and the desktop strategies. DESKTOP.md documents that managed Files tab behavior, so the change must stay consistent with it. Uncertainty starts at whether the fix is to skip the placeholder, make the editor part collapsible, or add a toggle. The related classic-layout removal is https://github.com/microsoft/vscode/commit/64bb1c151b641cb67f9f1a46fb93b6e35192e7b5.
- **Open decisions:**
  - In modal-editor mode, should the Files tab skip the inline placeholder editor entirely, or add a user toggle to hide it?
  - Should this be keyed off `workbench.editor.useModal: all`, or be a separate Agents-window layout option?

## Evidence

- **Placeholder is intentional:** src/vs/sessions/contrib/layout/DESKTOP.md ('Managed Files tab') says the empty Files placeholder tab (EmptyFileEditorInput) is opened on session switch or side-pane reveal. It also says both it and Changes remain whenever the layout is Detail only.
- **Modal mode handling:** baseSessionLayoutController.ts only consults workbench.editor.useModal to skip auto-revealing the editor part. The managed Files tab logic in desktopDockedTabsCoordinator.ts does not appear to special-case modal mode.
- **No existing control:** I found no setting or command that hides only the editor area while keeping the Files tree. This was a read-only code search, not a runtime check.
