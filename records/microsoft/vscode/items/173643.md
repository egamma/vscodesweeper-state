# Issue #173643 — Support find widget in WebviewViewProvider

[https://github.com/microsoft/vscode/issues/173643](https://github.com/microsoft/vscode/issues/173643)

## Summary

Keep open: current main still exposes the built-in find widget for webview panels but not WebviewViewProvider views. This accepted Backlog request has 42 upvotes and a later report explicitly consolidated into it.

## Change summary

Allow extension authors to enable VS Code's built-in find widget in WebviewViewProvider views.

## Best solution

Provide an opt-in find capability for webview views consistent with webview panels, retaining the existing default behavior. Keep this issue as the canonical request and settle the public API contract before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHost.api.impl.ts`, `src/vs/workbench/api/common/extHostWebviewView.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadWebviewViews.ts`, `src/vs/workbench/contrib/webviewView/browser/webviewViewPane.ts`
- **Validation:** Using a minimal extension contributing a WebviewViewProvider view, enable the agreed find option and verify that the standard Find shortcut opens the built-in widget, finds rendered text, and navigates matches. Repeat after hiding and restoring the view with retainContextWhenHidden both enabled and disabled; confirm that views without the option and existing webview panels preserve their behavior.
- **Behavior:**

  > Extension authors cannot currently opt into VS Code's built-in find widget for WebviewViewProvider views, although editor webview panels support it. The requested capability lets users search rendered content in those views using the standard find interaction. Acceptance should cover opening search, navigating matches, and hiding/restoring the view, while preserving existing behavior for extensions that do not opt in.
- **Trace:**

  > The public registration signature in src/vscode-dts/vscode.d.ts accepts only retainContextWhenHidden under webviewOptions. ExtHostWebviewViews.registerWebviewViewProvider in src/vs/workbench/api/common/extHostWebviewView.ts and the MainThreadWebviewViews registration protocol carry no find option; mainThreadWebviewViews.ts applies the received options to the webview. WebviewViewPane creates the overlay without enabling find, while the shared WebviewElement constructs its built-in widget only when enableFindWidget is true. Existing WebviewPanelOptions demonstrates the neighboring capability, but its public contract does not apply to webview-view registration. Preserve existing panel behavior and view lifecycle/resource-retention semantics; no new custom search UI is implied. The API contract remains to be agreed, and https://github.com/microsoft/vscode/issues/233045 is already consolidated into this request.
- **Open decisions:**
  - Should WebviewViewProvider registration expose an optional enableFindWidget flag defaulting to false, matching WebviewPanelOptions?
