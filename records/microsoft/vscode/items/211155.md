# Issue #211155 — `HoverContext` should pass back the specific type of hover I provided

[https://github.com/microsoft/vscode/issues/211155](https://github.com/microsoft/vscode/issues/211155)

## Summary

The extension-facing API still loses the provider's specific hover type. Keep this on-hold API cleanup open: the linked implementation PR was closed without merging, and its maintainer discussion explicitly deferred review until verbosity API finalization.

## Change summary

Preserve a hover provider's returned subtype in HoverContext.previousHover so extension authors do not need a cast.

## Best solution

Complete the type-preserving extension API contract when the hover verbosity API resumes finalization, retaining compatibility for existing nongeneric providers. The editor-internal generic interfaces already demonstrate the distinction, but do not satisfy extension authors' request.
