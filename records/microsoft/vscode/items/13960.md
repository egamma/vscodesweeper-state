# Issue #13960 — Virtual Space is not implemented.

[https://github.com/microsoft/vscode/issues/13960](https://github.com/microsoft/vscode/issues/13960)

## Summary

Keep open: virtual space remains missing from current main, and the existing column-selection setting does not cover it. The request has 309 upvotes, explicit maintainer interest, and an open implementation PR that should remain the implementation lane.

## Change summary

Support caret movement and rectangular selections beyond line endings without inserting whitespace until an edit requires it.

## Best solution

Review and resolve the remaining correctness and architectural concerns in https://github.com/microsoft/vscode/pull/228680, then land an optional virtual-space capability covering rectangular selection and ordinary caret navigation.

## Evidence

- **Existing capability does not cover the request:** src/vs/editor/common/config/editorOptions.ts:6238-6240 registers editor.columnSelection as a mouse-and-key selection mode. CursorConfiguration.columnFromVisibleColumn in src/vs/editor/common/cursorCommon.ts:233-246 clamps the resulting column to getLineMaxColumn, so this setting does not permit virtual positions beyond existing text.
- **Current column-selection limitation:** In src/vs/editor/common/cursor/cursorColumnSelection.ts, ColumnSelection.columnSelect converts rectangle endpoints to bounded text columns and falls back to end-of-line cursors when the rectangle lies beyond all selected lines. columnSelectRight also stops extending at the maximum existing visual line length. These paths do not provide the requested virtual rectangle with whitespace materialized on demand.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/228680 was verified OPEN with mergedAt null. Its body explicitly references https://github.com/microsoft/vscode/issues/13960 and describes beyond-EOL cursor movement, typing-time padding, and mouse targeting. This is pending work, not a landed fix.
- **Maintainer commitment and technical blocker:** https://github.com/microsoft/vscode/issues/13960#issuecomment-3996623286 states that the obstacle is technical: the original PR spreads virtual-space knowledge across many components, while the narrower approach loses functionality or exhibits bugs.
