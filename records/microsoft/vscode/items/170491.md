# Issue #170491 — VSCode does not remember the size of the suggest widget when the size is reset with double click

[https://github.com/microsoft/vscode/issues/170491](https://github.com/microsoft/vscode/issues/170491)

## Summary

Still reproduces on main: double-clicking the suggest widget's sash to reset its size fires `onDidResize` without directional flags and without a preceding `onDidWillResize`, so the `ResizeState` is never created and the new size is never persisted. A maintainer (jrieken) confirmed the bug in comment #3.

## Change summary

Double-clicking the suggest widget's resize sash resets the visual size but does not persist it, so the next time the widget opens it reverts to the old size.

## Best solution

In the suggest widget's resize handler (suggestWidget.ts ~line 174–210), handle the case where a sash reset (double-click) fires `onDidResize` with `done: true` but no prior `onDidWillResize` — either by listening for reset events on the ResizableHTMLElement (which would need a new event), or by persisting the resulting size directly when `state` is undefined and `e.done` is true. Alternatively, the ResizableHTMLElement's reset handler could fire `onDidWillResize` before `onDidResize` to match the normal drag flow.
