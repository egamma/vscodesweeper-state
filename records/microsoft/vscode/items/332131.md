# Issue #332131 — Custom title bar overlaps left-side window controls with Electron 43

[https://github.com/microsoft/vscode/issues/332131](https://github.com/microsoft/vscode/issues/332131)

## Summary

Traced on current main: the desktop native window-controls container only reserves space and gets the `wco-enabled` sizing class when it's on the right side (Linux/Windows default), so when Electron 43 respects a left-side control layout (e.g. KDE), the custom titlebar app icon/menu overlaps the native controls. An open PR already fixes exactly this, so keep open pending its review/merge.

## Change summary

With Electron 43 on Linux (KDE, controls on the left), VS Code's custom title bar doesn't reserve space for the native window controls, causing the app icon/menu to overlap them.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/310602, which reworks the window-controls-container logic in titlebarPart.ts / titlebarpart.css to apply `wco-enabled` sizing regardless of left/right side, based on `isWCOEnabled()` rather than only web vs. desktop.

## Evidence

- **current main code:** src/vs/workbench/browser/parts/titlebar/titlebarPart.ts lines ~548-577: the `wco-enabled` class is only added to the single windowControlsContainer created at primaryWindowControlsLocation ('right' on non-mac), and the secondary/opposite-side container is only appended `if (isWeb)` — so on desktop with WCO active on the left (as this issue describes), no properly-sized reserved area is created there.
