# Issue #262216 — Not respecting per monitor subpixel rendering cleartype config

[https://github.com/microsoft/vscode/issues/262216](https://github.com/microsoft/vscode/issues/262216)

## Summary

Per-monitor ClearType subpixel ordering (RGB vs BGR) is controlled by Chromium's font rendering pipeline inside Electron, not by VS Code's own code. Two prior issues covering the same root cause (#65132, #110864) were closed as *out-of-scope/upstream with the chromium and electron labels — the precedent is clear and the situation hasn't changed.

## Change summary

VS Code does not respect per-monitor ClearType subpixel rendering configuration (RGB vs BGR) on Windows multi-monitor setups.

## Best solution

This needs to be fixed in Chromium's DirectWrite integration. VS Code exposes a `--disable-lcd-text` CLI flag and an `argv.json` `disable-lcd-text` setting as workarounds. The reporter's workaround of disabling subpixel rendering is the best available mitigation until Chromium addresses this upstream.

  > As a workaround, you can disable subpixel rendering entirely by adding `"disable-lcd-text": true` to your `argv.json` (open it via **Preferences: Configure Runtime Arguments** from the Command Palette). This switches to greyscale antialiasing which avoids the RGB/BGR mismatch.

  > Regarding the terminal still showing subpixel rendering after that flag — the terminal's GPU renderer has its own text rasterization path, but it should also respect the LCD text setting. If you're still seeing subpixel artifacts in the terminal specifically, that could be a separate issue worth tracking.
