# Issue #346102 — Use Compare Models to generate a plan, then implement it

[https://github.com/microsoft/vscode/issues/346102](https://github.com/microsoft/vscode/issues/346102)

## Summary

Keep open: existing comparisons evaluate implementations and synthesize code, not an editable, approved plan followed by implementation. This team-authored request identifies a distinct workflow gap and already has the appropriate area label.

## Change summary

Support comparing multiple models' plans, selecting or combining and editing them, then launching implementation from the final plan.

## Best solution

Extend the existing comparison workflow with a planning stage and an explicit handoff of the user-approved plan to implementation, preserving the current implementation-comparison behavior.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/modelPicker.ts`, `src/vs/workbench/contrib/sessions/common/sessionComparison.ts`, `src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts`, `src/vs/workbench/contrib/sessions/browser/chat/sessionComparisonResult.ts`, `src/vs/platform/agentHost/common/sessionComparisonPrompts.ts`, `src/vs/sessions/contrib/sessionComparison/browser/sessionComparisonTool.ts`
- **Validation:** Acceptance scenario: compare plans from two models, inspect them side by side, select or combine their content, edit the final plan, and explicitly launch implementation using the edited content. Add focused coverage in sessionComparisonService.test.ts and sessionComparisonResult.test.ts; existing implementation comparisons must remain unchanged.
- **Behavior:**

  > Users can ask multiple models to plan the same task and inspect the resulting plans side by side. They can select one plan or combine useful parts, edit the final result, and explicitly start an implementation session from that approved content. Implementation must receive the edited final plan rather than an earlier draft. An optional Judge can explain comparative strengths and gaps without treating missing implementation changes as a failed plan.
- **Trace:**

  > The existing workflow is documented in src/vs/sessions/SESSION_COMPARISONS.md and orchestrated by SessionComparisonService in src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts. Comparison harnesses already carry modeId, but createSessionComparisonJudgePrompt in src/vs/platform/agentHost/common/sessionComparisonPrompts.ts is explicitly implementation-oriented. ISessionComparisonSynthesisPlan in src/vs/workbench/contrib/sessions/common/sessionComparison.ts stores only additional instructions, and the result UI's Synthesize action starts implementation rather than presenting a consolidated editable plan. Existing parallel execution and tiled chats are useful foundations, not proof that this request is implemented. Preserve provider-neutral orchestration, original attempts, and current implementation comparisons. The uncertainty starts at the user-visible representation and persistence of the approved plan and its handoff to a new implementation session.
- **Open decisions:**
  - Should the editable final plan be a workspace document or a comparison-owned artifact, and should it survive reloads?
  - Should the implementation handoff include only the approved plan and original task context, or also the competing plans and Judge discussion?
