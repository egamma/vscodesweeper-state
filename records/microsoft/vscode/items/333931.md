# Issue #333931 — Agent host: a subagent's tool call is never executed and its turn is never closed, so the chat spins forever

[https://github.com/microsoft/vscode/issues/333931](https://github.com/microsoft/vscode/issues/333931)

## Summary

Well-diagnosed, currently-unlabeled bug: the code confirms both of the reporter's claims — `subagent_completed` is only fired by two producers that both depend on the spawning tool call finishing, and the hang watchdog in `agentHostTurnTracker.ts` only reports telemetry (`turnHung`) and never terminates a stuck turn — so an abandoned subagent turn genuinely has no path to close. No fix exists on main; routing to the chat/agent-host area is the right next step.

## Change summary

In dev-container agent-host sessions, a subagent's announced tool call sometimes never executes or completes, and because nothing reaps abandoned turns, the chat spins open forever.

## Best solution

Two independent, actionable follow-ups: (1) resolve the still-unidentified root cause of the dropped tool-call execution (candidates already filed as https://github.com/microsoft/vscode/issues/330899 and https://github.com/microsoft/vscode/issues/331595), and (2) add an actual termination path to the hang watchdog in src/vs/platform/agentHost/node/agentHostTurnTracker.ts so a turn with no in-flight work for too long is cancelled/errored rather than left open indefinitely — today `_onHangWatchdogFired` only calls `this._reporter.turnHung(...)`.
