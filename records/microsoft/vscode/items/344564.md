# Issue #344564 — Opening a chat renders its last response twice: once at the top, again after scrolling to the end

[https://github.com/microsoft/vscode/issues/344564](https://github.com/microsoft/vscode/issues/344564)

## Summary

Keep open as a specifically diagnosed chat-rendering performance defect: the supplied trace records two expensive renders of the same response during one open, and current source retains the implicated path. The broader remote-chat navigation report explicitly tracks this as separate work.

## Change summary

Avoid rebuilding an unchanged, already-rendered response when opening a completed chat and automatically scrolling to its end.

## Best solution

Opening a completed chat should reach the intended final scroll position without redundantly rebuilding its response content. Resolve the bounded chat/list rendering path while preserving dynamic-height measurement, intentional refreshes, and scroll restoration.
