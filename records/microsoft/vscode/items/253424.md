# Issue #253424 — Add "confirmation pending"  to window title

[https://github.com/microsoft/vscode/issues/253424](https://github.com/microsoft/vscode/issues/253424)

## Summary

Still a real gap on main: no window title, titlebar, or Switch-Window quick-pick indicator exists for a pending agent confirmation — only the application-wide dock/taskbar badge does, which can't distinguish between windows. Keeping open; a prior review's implemented-on-main claim (commit bb25992d5c55d8eb6ca74d6f00df0fbc86b05c84) was independently refuted and is not being re-cited.

## Change summary

Add a per-window indicator (window title and/or Switch Window quick pick) showing which open window has a pending agent/chat confirmation.

## Best solution

Plumb a per-window 'needs confirmation' signal (likely derived from the same session input-needed state that feeds SessionsApplicationBadge) through to BaseSwitchWindow's quick pick entries (src/vs/workbench/electron-browser/actions/windowActions.ts) and/or WindowTitle's template variables (src/vs/workbench/browser/parts/titlebar/windowTitle.ts); a maintainer should pick which surface(s) to use first.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/windowTitle.ts`, `src/vs/workbench/electron-browser/actions/windowActions.ts`, `src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts`
- **Validation:** A test asserting that a window with a session in SessionStatus.NeedsInput produces a distinguishable window title and/or a distinguishable Switch Window quick-pick entry, once the surface is chosen.
- **Behavior:**

  > When a chat/agent session in a given window has a pending confirmation (tool approval, input request, etc. — i.e. SessionStatus.NeedsInput), that specific window should be visibly distinguishable from other open windows, either via its window title or via its entry in the Switch Window quick pick (or both). This is in addition to, not a replacement for, the existing application-wide dock/taskbar badge, which only tells the user that *some* window needs attention, not which one.
- **Trace:**

  > SessionsApplicationBadge (src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts) already computes an eligible count of sessions with SessionStatus.NeedsInput and feeds a single aggregated badge through INativeHostService.setApplicationBadge → DockBadgeManager in src/vs/platform/windows/electron-main/windowImpl.ts, with no per-window dimension. WindowTitle (src/vs/workbench/browser/parts/titlebar/windowTitle.ts) derives its title purely from editor/workspace state. BaseSwitchWindow (src/vs/workbench/electron-browser/actions/windowActions.ts, ~lines 254-322) builds its quick pick purely from IOpenedMainWindow/IOpenedAuxiliaryWindow data returned by nativeHostService.getWindows(), which carries title/dirty/filename but no session state. Boundary: do not alter the existing global DockBadgeManager aggregation behavior; any new signal is additive and per-window.
- **Open decisions:**
  - Should the indicator live in the window title, the Switch Window quick pick, or both?
  - Which input-needed states qualify (just tool confirmations, or the full SessionStatus.NeedsInput set already used by the dock badge)?
  - Does this apply to every workbench window, or only Agents Window / sessions-owning windows?

## Evidence

- **existing badge is global, not per-window:** src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts aggregates a single OS dock/taskbar badge count across all sessions via DockBadgeManager in src/vs/platform/windows/electron-main/windowImpl.ts (lines ~90-143); there is no per-window breakdown.
- **window title has no session/chat awareness:** src/vs/workbench/browser/parts/titlebar/windowTitle.ts template variables (activeEditor*, dirty, rootName, profileName, appName) include nothing related to chat/agent confirmation state.
- **Switch Window quick pick has no such signal either:** BaseSwitchWindow.run in src/vs/workbench/electron-browser/actions/windowActions.ts (lines 254-322) builds pick items purely from nativeHostService.getWindows() (title, dirty, filename); no input-needed/confirmation state is surfaced.
