# Issue #53959 — Counter-intuitive "editor.suggestSelection" behavior when completion is "kept open"

[https://github.com/microsoft/vscode/issues/53959](https://github.com/microsoft/vscode/issues/53959)

## Summary

The default for `editor.suggestSelection` was changed to `first` in late 2021 (commit e9e4deef80b), which mitigates this for most users. However, the underlying request — skip memory-based selection during a refilter when completions are "kept open" — is still valid for users who opt into `recentlyUsed`. Keeping open as `under-discussion` since the existing label is appropriate and the niche scenario still lacks a resolution.

## Change summary

When `editor.suggestSelection` is set to `recentlyUsed`, re-triggering completions via a trigger character (keeping the suggest widget open with filtered results) incorrectly applies the memory-based selection, jumping to a previously-used item instead of preserving the current filter position.

## Best solution

In the suggest controller's `onDidSuggest` handler, skip the `_memoryService.select()` call when the trigger has `refilter: true`, so that refiltering within an existing completion session preserves the current selection position rather than jumping to a memorized item. The fix would be in `src/vs/editor/contrib/suggest/browser/suggestController.ts` around the `showSuggestions` path.
