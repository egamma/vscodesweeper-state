# Issue #53959 — Counter-intuitive "editor.suggestSelection" behavior when completion is "kept open"

[https://github.com/microsoft/vscode/issues/53959](https://github.com/microsoft/vscode/issues/53959)

## Summary

Keep open for the completion-session improvement discussed by the maintainer. Current defaults and preselection handling have changed, but they do not provide session-aware suppression of suggestion memory when a trigger character refreshes otherwise continuous results.

## Change summary

Avoid jumping to a remembered completion when typing a dot refreshes the same package-path suggestions within an ongoing completion session.

## Best solution

Define selection continuity for trigger-character refreshes in the editor suggest controller and model, retaining useful recently-used selection for genuinely new completions. Distinguish continued package-path filtering from member completion before changing the selection policy.

- **Behavior:**

The goal is stable selection during a logically continuous filtering session without losing recently-used selection for genuinely new completion contexts. Acceptance must cover both the supplied haxe. package-path case and Json. member completion. The current first default and provider preselect support are mitigations, not substitutes for the requested session distinction.
- **Trace:**

- **Open decisions:**
