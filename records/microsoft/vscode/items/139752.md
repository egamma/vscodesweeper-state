# Issue #139752 — [json] Local JSON schemas should find each other based on their id fields

[https://github.com/microsoft/vscode/issues/139752](https://github.com/microsoft/vscode/issues/139752)

## Summary

A real capability gap remains: current VS Code only registers explicitly configured or contributed JSON schemas and does not discover workspace schemas by `$id`. The Backlog request has sustained demand and no verified canonical or fixing PR, so it should remain open in the JSON area.

## Change summary

Discover local JSON schemas by their `$id` fields so absolute `$schema` and `$ref` URLs can resolve to workspace files.

## Best solution

Add workspace-aware schema discovery that indexes eligible local schemas by `$id`, resolves matching absolute references locally, and preserves existing explicit `json.schemas` associations and remote resolution when no local match exists.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/server/src/jsonServer.ts`, `extensions/json-language-features/client/src/test/schemaRequests.test.ts`
- **Validation:** Add a focused JSON language-features test using two local schema files where one references the other's absolute `$id`; validation and completion must resolve locally, while an unmatched URI must retain existing remote-resolution behavior.
- **Behavior:**

  > Within a workspace, an eligible local JSON schema declaring an absolute `$id` can satisfy `$schema` and `$ref` references to that identifier from other JSON schemas and documents. References with no matching local schema retain the existing configured or remote resolution behavior. Explicit `json.schemas` mappings remain supported and take a documented precedence. Acceptance must cover local resolution, an unmatched identifier, workspace changes, and duplicate identifiers.
- **Trace:**

  > The JSON client in extensions/json-language-features/client/src/jsonClient.ts currently builds schema configuration only from `json.schemas`, extension `jsonValidation` contributions, and schema registries. The server's `updateConfiguration` in extensions/json-language-features/server/src/jsonServer.ts forwards only those registrations to `vscode-json-languageservice`; `getSchemaRequestService` otherwise resolves by URI protocol, so an HTTPS `$ref` cannot discover a local file by its `$id`. The explicit mapping discussed at https://github.com/microsoft/vscode/issues/174672 is a workaround, not automatic discovery. Preserve existing explicit associations, trusted-domain handling, and network fallback for identifiers with no local match. The uncertainty begins at which workspace files are indexed, how multi-root and duplicate identifiers are handled, and how indexing is invalidated without imposing an always-on workspace scan.
- **Open decisions:**
  - Which files are eligible for `$id` discovery: every JSON/JSONC file in the workspace, only schema-like filename patterns, or user-configured roots and patterns?
  - In a multi-root workspace or when multiple local schemas declare the same `$id`, should resolution prefer the referencing document's folder, report an ambiguity, or use a deterministic workspace order?
  - What precedence should apply among explicit `json.schemas` mappings, discovered local `$id` mappings, and remote retrieval, and should users be able to disable local overriding?

## Evidence

- **current configuration path:** extensions/json-language-features/client/src/jsonClient.ts `computeSettings` collects schemas only from `json.schemas`, while `computeSchemaAssociations` collects extension and registry contributions; neither scans workspace schemas for `$id`.
- **server resolution path:** extensions/json-language-features/server/src/jsonServer.ts `updateConfiguration` passes only contributed and configured schemas to the JSON language service, and `getSchemaRequestService` dispatches unresolved HTTP/file URIs directly to their protocol handlers.
- **workaround is incomplete:** https://github.com/microsoft/vscode/issues/174672 documents an explicit `json.schemas` mapping through an inline `$ref`, but the discussion on this issue explains that absolute local paths and file-pattern associations do not provide automatic, portable `$id` discovery.
