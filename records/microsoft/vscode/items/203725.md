# Issue #203725 — LaTeX not rendering in cell text/html encoded outputs when embedded inside html

[https://github.com/microsoft/vscode/issues/203725](https://github.com/microsoft/vscode/issues/203725)

## Summary

Keep open: the built-in HTML output renderer still has no automatic math typesetting, and the existing Markdown math support does not cover this request. The related Markdown-cell report covers a different rendering path, not a verified canonical for this team-authored item.

## Change summary

Render LaTeX embedded in notebook text/html outputs, including nested divs and table cells, without requiring injected scripts or Markdown whitespace workarounds.

## Best solution

Define and deliver math typesetting for notebook HTML outputs while preserving ordinary HTML, existing rendered math, and notebook trust behavior. Coordinate with the related Markdown-cell request without conflating the two rendering paths or requiring a switch to MathJax.

## Plan brief

- **Likely files:** `extensions/notebook-renderers/src/index.ts`, `extensions/notebook-renderers/src/test/notebookRenderer.test.ts`, `extensions/markdown-math/notebook/katex.ts`, `extensions/markdown-math/package.json`
- **Validation:** In a trusted Python notebook, run %%html followed by <div>$\sqrt{2}$</div>, then exercise inline and display math in nested table cells without injected scripts. Verify rendered math, unchanged ordinary HTML and literal-dollar content under the chosen policy, no duplicate processing of pre-rendered math, correct output replacement, and unchanged untrusted-notebook behavior; add renderer regression coverage for the agreed contract.
- **Behavior:**

  > Notebook text/html output containing LaTeX currently leaves math delimiters and expressions visible as raw text, unlike the reporter's Jupyter experience. The requested outcome is readable math inside nested HTML, including tables, without rewriting output as Markdown or injecting external scripts. Acceptance should cover inline and display math, output replacement, and preservation of unrelated HTML and already-rendered math. The policy for distinguishing math delimiters from literal dollar signs must be agreed before implementation.
- **Trace:**

  > extensions/notebook-renderers/package.json maps text/html to vscode.builtin-renderer; renderOutputItem and renderHTML in extensions/notebook-renderers/src/index.ts handle this path. renderHTML inserts HTML and invokes optional HtmlRenderingHook.postRender callbacks, but contains no built-in math typesetting. Separately, extensions/markdown-math/notebook/katex.ts extends vscode.markdown-it-renderer through a Markdown-It plugin, so loading its styles or changing Markdown settings does not bridge the HTML-output path. The script-injection workaround at https://github.com/microsoft/vscode/issues/203725#issuecomment-2217367218 is evidence of the requested outcome, not a suitable default implementation prescription. Preserve existing trust gating, ordinary HTML behavior, and output lifecycle; changing math engines is outside the central request. https://github.com/microsoft/vscode/issues/185619 concerns HTML inside Markdown cells and should inform compatibility discussions without replacing this output-specific item.
- **Open decisions:**
  - Should math interpretation in HTML outputs be automatic by default or explicitly opted into, and which delimiters should count as math rather than literal text?

## Evidence

- **Current HTML output path:** extensions/notebook-renderers/package.json assigns text/html to vscode.builtin-renderer. In extensions/notebook-renderers/src/index.ts, renderOutputItem dispatches trusted HTML outputs to renderHTML, which assigns innerHTML, applies registered HTML hooks, appends the element, and evaluates supplied scripts; it does not itself typeset math.
- **Existing capability does not cover the request:** extensions/markdown-math/package.json registers vscode.markdown-it-katex-extension as extending vscode.markdown-it-renderer, not vscode.builtin-renderer. extensions/markdown-math/notebook/katex.ts installs a Markdown-It KaTeX plugin and styles, with no HTML-output auto-render registration. The markdown.math.enabled and markdown.math.macros settings do not add math processing to text/html outputs.
- **Workarounds are partial:** https://github.com/microsoft/vscode/issues/203725#issuecomment-2217367218 describes explicitly injecting KaTeX auto-render scripts into HTML output. https://github.com/microsoft/vscode/issues/203725#issuecomment-2330321639 describes whitespace changes for Markdown tables; that workaround does not supply typesetting to the original %%html output path.
