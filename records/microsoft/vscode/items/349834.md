# Issue #349834 — Closing the troubleshoot dialogs also close the Remote Env dialog

[https://github.com/microsoft/vscode/issues/349834](https://github.com/microsoft/vscode/issues/349834)

## Summary

The troubleshooting page has local Back/Escape navigation, but the modal's close button still closes the entire Remote Environments editor. Keep open to address the maintainer-confirmed modal consistency issue.

## Change summary

Closing troubleshooting should return to Remote Environments instead of dismissing the containing modal.

## Best solution

Make dismissing the troubleshooting surface return to the Remote Environments overview, consistent with the maintainer's stated direction, while preserving ordinary modal closing elsewhere.

- **Behavior:**

  > Closing the troubleshooting surface opened from Remote Environments should return to the overview rather than dismiss the whole Remote Environments modal. Back and Escape must retain their existing navigation behavior. Acceptance includes usable focus on return and unchanged ordinary closing behavior from the overview and unrelated modals.
- **Trace:**

  > RemoteEnvironmentDetails.goBack() invokes the delegate supplied by RemotesWidget.openDetails(); RemotesWidget.closeDetails() restores the overview and table focus. RemotesEditor.closeEnvironmentDetails() already exposes that local operation. In contrast, the title close action workbench.action.closeModalEditor calls ModalEditorPart.close(), which closes all editors in the modal without consulting the detail-page state. This confirms the reported outcome from source without executing the UI. The remaining investigation is how to integrate this behavior safely with the shared modal title and lifecycle; the affected shared consumers have not been enumerated. Preserve unrelated modal behavior and explicit actions that intentionally dismiss Remote Environments. The accepted direction is recorded at https://github.com/microsoft/vscode/issues/349834#issuecomment-7112842620.
