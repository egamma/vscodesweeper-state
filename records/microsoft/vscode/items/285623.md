- **Behavior:**

  > MCP tools can return generated text files and binary archives that users can inspect and deliberately save into their workspace. Current source already provides resource attachments and generic saving, so the remaining product goal is richer artifact metadata and an integrated archive-extraction experience. Acceptance should exercise the supplied ZIP response alongside text resources, preserve existing save behavior, and verify the agreed destination, overwrite, cancellation, and invalid-archive behavior. Automatic extraction and new preferences require an explicit product decision rather than being assumed.
- **Trace:**

  > McpToolImplementation in src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts translates embedded resources into tool-result output with URI, MIME type, text or base64 content, and asResource. ChatInputOutputMarkdownProgressPart converts that output to data attachments, and ChatToolOutputContentSubPart renders them through ChatResourceGroupWidget. SaveResourcesAction, registered as chat.toolOutput.save, already copies resource bytes to a user-selected destination. The traced path does not propagate the proposed artifact filename, description, and size metadata or expose archive extraction. Preserve ordinary resource links, image handling, and generic saving; the request does not establish a skill-installation contract. https://github.com/microsoft/vscode/issues/340232 separately tracks Agent Host fidelity and should inform compatibility planning, not absorb this older request. No runtime validation was performed in the read-only checkout.
- **Open decisions:**
  - Should the supported artifact experience include ZIP extraction, or remain preview and save with archive extraction outside this surface?
  - If extraction is supported, must every operation require an explicit destination and confirmation, or may users enable automatic extraction?
  - Which artifact metadata should be recognized and displayed, and what size-limit and overwrite behavior should users encounter?
