# Issue #158575 — Add "Disconnect single session" command

[https://github.com/microsoft/vscode/issues/158575](https://github.com/microsoft/vscode/issues/158575)

## Summary

Keep open: current disconnect commands still honor compound stopAll, so selectively disconnecting the extension-host session remains unsupported. The maintainer explicitly endorsed a separate command; the existing focus setting and launch-configuration workarounds do not deliver that behavior.

## Change summary

Provide an explicit command to disconnect one debug session without stopping its compound siblings, even when stopAll is enabled.

## Best solution

Offer a distinct single-session disconnect operation while preserving ordinary Disconnect and compound stopAll behavior. It should target the selected or focused session without requiring changes to shared launch configurations.

Manually launch a compound with stopAll enabled, invoke the new command on its extension-host session, and confirm other sessions remain attached and subsequent ordinary compound stopping still works.
- **Behavior:**

  > A user debugging several processes in a stopAll compound can explicitly disconnect only the extension-host session without editing launch.json. The target detaches without terminating its debuggee, while sibling sessions remain attached. Ordinary Disconnect and Stop retain their existing compound-wide behavior, including after the selective disconnect. A session-context invocation must act on that session rather than an unrelated focused session.
- **Trace:**

  > The accepted direction is recorded at https://github.com/microsoft/vscode/issues/158575#issuecomment-1224443493. In src/vs/workbench/contrib/debug/browser/debugCommands.ts, stopHandler resolves the session context or focused session and invokes DebugService.stopSession; the service delegates to DebugSession.disconnect. In src/vs/workbench/contrib/debug/browser/debugSession.ts, disconnect notifies the shared DebugCompoundRoot on every non-restart path, and compound listeners terminate sibling sessions. Existing command registrations in debug.contribution.ts expose ordinary Disconnect but no single-session override. debug.focusWindowOnBreak only mitigates the original focus symptom. Preserve normal stopAll propagation, restart semantics, and existing parent-managed session behavior; cross-window focus arbitration is outside this request. The remaining product choice is where the distinct operation should be exposed.
- **Open decisions:**
  - Should Disconnect Single Session be available only through the Command Palette, or also in the per-session Call Stack context menu?
