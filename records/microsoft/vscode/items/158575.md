# Issue #158575 — Add "Disconnect single session" command

[https://github.com/microsoft/vscode/issues/158575](https://github.com/microsoft/vscode/issues/158575)

## Summary

The requested command remains necessary on current main: disconnecting one session in a compound with `stopAll` still signals the compound root and terminates its sibling sessions. A debug maintainer explicitly agreed that a single-session override makes sense, and no older canonical issue was found.

## Change summary

Add a command that disconnects one selected debug session without activating the compound configuration's `stopAll` behavior.

## Best solution

Provide a session-targeted disconnect action that bypasses `stopAll` only for that invocation, while preserving the existing Disconnect and Stop behavior for compounds. Make it available from the selected session's Call Stack actions, with any broader Command Palette or toolbar exposure decided by the debug maintainer.

- **Behavior:**

  > A user can select a debug session that belongs to a compound configured with `stopAll` and disconnect only that session. Other sessions in the compound remain active for this explicit single-session action. Existing Disconnect and Stop actions continue honoring `stopAll`, and non-compound session behavior remains unchanged.
- **Trace:**

  > `stopHandler` in `src/vs/workbench/contrib/debug/browser/debugCommands.ts` sends the selected or focused session to `IDebugService.stopSession`. `DebugSession.disconnect` in `src/vs/workbench/contrib/debug/browser/debugSession.ts` unconditionally invokes `compoundRoot.sessionStopped()`, whose event listener terminates the compound's other sessions; `IDebugSession.disconnect` in `src/vs/workbench/contrib/debug/common/debug.ts` has no way to distinguish the requested override. The Call Stack session menu is registered in `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`. Preserve ordinary Disconnect, Stop, lifecycle-managed child behavior, and `stopAll` semantics; only the explicitly named single-session action should bypass compound propagation. The motivating workflow and maintainer endorsement are recorded at https://github.com/microsoft/vscode/issues/158575.
- **Open decisions:**
  - Should "Disconnect Single Session" appear only in the selected session's Call Stack context menu, or also in the Command Palette and debug-toolbar overflow where it would act on the focused session?
