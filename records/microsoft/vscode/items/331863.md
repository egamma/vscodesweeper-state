# Issue #331863 — Generate Commit Message silently fails until a Copilot Chat request is made in the window

[https://github.com/microsoft/vscode/issues/331863](https://github.com/microsoft/vscode/issues/331863)

## Summary

Traced a real, confirmed defect in the commit-message generator: any non-success chat fetch result other than quota-exceeded/no-auth-rate-limit is swallowed silently — no message is ever shown to the user, matching the exact symptom reported (spinner runs, nothing happens, no error). The specific server-side trigger (why the very first request in a fresh window comes back `promptFiltered` before any chat warm-up) is outside this repo's control, but the client-side silent-failure gap is fixable here.

## Change summary

Generate Commit Message silently produces no result and no error until the user has sent at least one Copilot Chat message in the same window.

## Best solution

In GitCommitMessageGenerator.generateGitCommitMessage (extensions/copilot/src/extension/prompt/node/gitCommitMessageGenerator.ts), surface a warning via INotificationService (already injected, showWarningMessage exists) whenever fetchResult.type !== Success and isn't already handled by the quota-exceeded dialog, so users get feedback instead of a silently-vanishing spinner; the underlying reason the first request returns promptFiltered before a chat warm-up is a separate, likely server-side investigation.
