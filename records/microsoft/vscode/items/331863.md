# Issue #331863 — Generate Commit Message silently fails until a Copilot Chat request is made in the window

[https://github.com/microsoft/vscode/issues/331863](https://github.com/microsoft/vscode/issues/331863)

## Summary

Real, reproduced bug in the Copilot Chat git integration: generateCommitMessage silently swallows any non-Success ChatFetchResponseType (see the unconditional `return undefined` in gitCommitMessageGenerator.ts), and multiple independent reporters across three VS Code releases confirm the sparkle button only works after a Copilot Chat message has been sent in that window, with one comment showing a real server-side 422/promptFiltered response backing the repro — needs area-owner investigation into why the request fails pre-warm-up, not a triage close.

## Change summary

Generate Commit Message (sparkle button) does nothing on a fresh window until the user has sent at least one Copilot Chat message, and no error is shown.

## Best solution

Investigate why the git commit message request (endpoint 'copilot-utility-small' in extensions/copilot/src/extension/prompt/node/gitCommitMessageGenerator.ts) gets a promptFiltered/non-Success response before any chat interaction has occurred in the window — likely a token/endpoint/capability warm-up ordering issue in the chat platform init path — and, independently, stop silently discarding non-Success fetch results (currently `if (fetchResult.type !== ChatFetchResponseType.Success) { return undefined; }`) so users at least see a diagnostic instead of a silent no-op.
