# Issue #338818 — Activated tool group is collapsed again when over 128 tools

[https://github.com/microsoft/vscode/issues/338818](https://github.com/microsoft/vscode/issues/338818)

## Summary

Confirmed real bug in current main, with an open fixing PR already up — keeping open so the PR can be reviewed and merged rather than closing.

## Change summary

When more than 128 tools are enabled, activating a virtual tool group doesn't refresh its recency, so the trim logic can immediately re-collapse the group the model just activated, causing it to never reach the real tools inside.

## Best solution

Land https://github.com/microsoft/vscode/pull/338812, which adds `tool.lastUsedOnTurn = this._turnNo;` right after `tool.isExpanded = true;` in `ToolGrouping.didCall` (extensions/copilot/src/extension/tools/common/virtualTools/toolGrouping.ts) — the PR already includes a regression test for this exact scenario.

## Evidence

- **confirmed root cause:** extensions/copilot/src/extension/tools/common/virtualTools/virtualTool.ts VirtualTool.find(name): when `name` matches the group being activated itself, it returns immediately with `path: []` (line 55-57), so back in ToolGrouping.didCall (toolGrouping.ts lines 62-65) the `for (const part of path) { part.lastUsedOnTurn = this._turnNo; }` loop never touches the activated group — only its ancestors. `tool.isExpanded = true` is set (line 97) but `lastUsedOnTurn` is left stale, so `getLowestExpandedTool()` (virtualTool.ts line 79) can pick the just-activated group as least-recently-used and collapse it again on the next `compute()` trim.
- **open fix PR:** https://github.com/microsoft/vscode/pull/338812 adds the missing `tool.lastUsedOnTurn = this._turnNo;` line and a new spec 'should keep a just-activated group expanded over less recently used groups when trimming' in extensions/copilot/src/extension/tools/test/node/virtualTools/virtualToolGrouping.spec.ts (verified via the PR diff) — matches the reported symptom exactly. The PR is still open on main, not merged.
- **related prior fix:** https://github.com/microsoft/vscode/pull/327576 (closed/merged) previously addressed a related but distinct virtual-tool-grouping bug, consistent with this being an actively maintained but still-imperfect area.
