# Issue #331915 — Automation X failed: Agent session failed should reveal the failed session

[https://github.com/microsoft/vscode/issues/331915](https://github.com/microsoft/vscode/issues/331915)

## Summary

Fresh, team-authored request (author alexdima is a VS Code core maintainer) asking that the 'Automation X failed' error notification let you jump to the failed session; traced the code and confirmed no such action exists today, so this stays open as a small, well-scoped enhancement.

## Change summary

When an automation run fails, the resulting error notification has no way to reveal/open the failed agent session.

## Best solution

In src/vs/sessions/contrib/automations/browser/automationRunner.ts (around the notificationService.error(...) call at line 203), switch to notificationService.notify(...) with a primary action that opens the failed session via ISessionsService.openSession(sessionResource) — the codebase already has this exact pattern in src/vs/sessions/contrib/sessions/browser/sessionsWindowNotifier.ts (localize('sessions.notification.openSession', "Open Session") + sessionsService.openSession(session.resource)), so the fix can reuse that convention rather than inventing a new one.
