# Issue #327561 — feat: Standardized Chat Panel Extension API (transcript access, scroll state, overlay decorations)

[https://github.com/microsoft/vscode/issues/327561](https://github.com/microsoft/vscode/issues/327561)

## Summary

A real extension-API gap remains, and this Backlog Candidates request is still inside the established community voting period. Keep it open for that process and for an API/privacy design decision rather than closing or treating the related UI request as a duplicate.

## Change summary

Expose chat-panel discovery, transcript observation, scroll state, turn navigation, and decorations to extensions through a standardized API.

## Best solution

Define a narrower VS Code API proposal around observable VS Code chat sessions, with explicit transcript-consent and provider opt-in semantics; scroll and decoration capabilities should be evaluated separately because they expose workbench UI implementation details. Cross-editor adoption may follow, but commitments from Cursor or Windsurf should not be a VS Code acceptance criterion.

## Evidence

- **current API gap:** Current stable API in src/vscode-dts/vscode.d.ts exposes ChatContext.history only to the participant handling that request and explicitly limits it to messages for the current participant; it does not expose active panels, scroll state, or panel decorations.
- **partial private capability:** src/vscode-dts/vscode.proposed.chatParticipantPrivate.d.ts exposes only window.activeChatPanelSessionResource and onDidChangeActiveChatPanelSessionResource for active-panel discovery; no transcript-observation, scrolling, or decoration surface matching this request exists.
- **provider API boundary:** src/vscode-dts/vscode.proposed.chatSessionsProvider.d.ts provides registerChatSessionContentProvider for extensions that own chat-session content, but it does not let unrelated extensions inspect or decorate another provider's rendered panel.
