# Issue #334454 — Custom skills from `chat.agentSkillsLocations` are not inherited by Git submodules (and potentially subfolders)

[https://github.com/microsoft/vscode/issues/334454](https://github.com/microsoft/vscode/issues/334454)

## Summary

Traced this on main: `chat.agentSkillsLocations` locations are resolved purely against `workspaceService.getWorkspaceFolders()` in both `resolveSkillConfigLocations` (extensions/copilot/src/extension/chatSessions/common/skillConfigLocations.ts) and `_matchInstructionLocationsFromSkills` in customInstructionsService.ts, with no awareness of `chat.useCustomizationsInParentRepositories` at all — unlike `AgentInstructionsLocator.listAgentInstructions`, which explicitly walks up to parent repo roots via `getWorkspaceFolderRoots`/`findParentRepoFolders`. This is a genuine gap, not a duplicate of the linked (already-fixed) issue.

## Change summary

Skills configured via `chat.agentSkillsLocations` in a parent repository are not discovered when working inside a Git submodule, even with `chat.useCustomizationsInParentRepositories` enabled.

## Best solution

Extend skill-location resolution (extensions/copilot/src/extension/chatSessions/common/skillConfigLocations.ts and the `_matchInstructionLocationsFromSkills` observable in extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts) to compute roots the same way `AgentInstructionsLocator.getWorkspaceFolderRoots` does — including trusted parent repo roots when `chat.useCustomizationsInParentRepositories` is set — instead of only using `workspaceService.getWorkspaceFolders()`.
