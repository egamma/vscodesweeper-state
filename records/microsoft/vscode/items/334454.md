# Issue #334454 — Custom skills from `chat.agentSkillsLocations` are not inherited by Git submodules (and potentially subfolders)

[https://github.com/microsoft/vscode/issues/334454](https://github.com/microsoft/vscode/issues/334454)

## Summary

Detailed, specific repro from a reporter who just had a closely-related bug (#329169) fixed, but source tracing on main is inconclusive — the exact code path that fixed #329169 (the parent-repo `.git` walk in `promptFilesLocator.ts`) is type-agnostic and already applies to custom `chat.agentSkillsLocations` paths too, so I can't confirm the defect from reading source alone; needs a maintainer or reporter to actually reproduce against current Insiders.

## Change summary

Custom skill folders configured via `chat.agentSkillsLocations` in a parent repository's settings are not discovered when working inside a Git submodule, even though `chat.useCustomizationsInParentRepositories` is enabled and other customizations (AGENTS.md, instructions) are inherited correctly.

## Best solution

A maintainer familiar with src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts (findAgentSkills/toAbsoluteLocations/getWorkspaceFolderRoots) should reproduce with a real submodule + custom chat.agentSkillsLocations setup on current Insiders (post PR #332893) and use the chat customization-discovery debug panel to see which folders were actually searched for skills vs. instructions — if the generic parent-repo walk really does cover skills, the gap may be in a skills-specific caching or session-scoping path (e.g. computeAutomaticInstructions.ts's findAgentSkills usage) rather than the git-walk itself.
