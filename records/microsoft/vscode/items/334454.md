# Issue #334454 — Custom skills from `chat.agentSkillsLocations` are not inherited by Git submodules (and potentially subfolders)

[https://github.com/microsoft/vscode/issues/334454](https://github.com/microsoft/vscode/issues/334454)

## Summary

Legitimate, well-diagnosed gap — `resolveSkillConfigLocations` in extensions/copilot/src/extension/chatSessions/common/skillConfigLocations.ts only resolves `chat.agentSkillsLocations` against the current workspace folders, unlike the dedicated parent-repo walk used for agent/instruction files — but a maintainer has already raised a substantive design objection and the issue is only 22 days into the normal 60-day Backlog Candidates window with 0 upvotes, so this should stay in the community process rather than being closed by us either way.

## Change summary

When `chat.useCustomizationsInParentRepositories` is enabled, skills configured via `chat.agentSkillsLocations` in a parent repo are not discovered inside a Git submodule, unlike other chat customizations which are.

## Best solution

A maintainer should decide whether `chat.agentSkillsLocations` gets folded into the same parent-repo customization walk used for instructions/agents (extensions/copilot/src/platform/promptFiles/common/promptsService.ts), given `agentSkillsLocations` is itself already marked deprecated in favor of the Agent Customizations editor migration path — worth confirming the setting is even worth extending before adding cross-repo resolution to it.
