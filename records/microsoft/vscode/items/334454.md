# Issue #334454 — Custom skills from `chat.agentSkillsLocations` are not inherited by Git submodules (and potentially subfolders)

[https://github.com/microsoft/vscode/issues/334454](https://github.com/microsoft/vscode/issues/334454)

## Summary

Decline close (as-designed) gated off: the issue sits in the Backlog Candidates milestone — the owner already triaged it as accepted work. Original assessment: Maintainer aeschli explained this is intentional design (PR #338059, merged): a submodule's `.git` pointer file is treated as an independent repository root, so parent-repo customizations — including `chat.agentSkillsLocations` — intentionally stop at that boundary, to stay consistent with how GitHub Copilot itself draws the line. Current main's code and tests confirm this is the shipped, deliberate behavior rather than a bug.

## Change summary

Skills configured via chat.agentSkillsLocations in a parent repo are not inherited inside a Git submodule, even with chat.useCustomizationsInParentRepositories enabled.

## Best solution

Keep the current design: a submodule (or worktree) is its own repo root for customization discovery. If a reporter wants shared skills across a superproject and its submodules, the workaround is to configure chat.agentSkillsLocations directly in the submodule's own .vscode/settings.json rather than relying on parent-repo inheritance.

## Vision fit

- **Fit:** rejected
- **Reason:** Adding another settings-inheritance layer across submodule boundaries conflicts with the project's preference for a simple, uniform settings hierarchy rather than deeper cascading rules.
- **Evidence:** Value: 'Simple, uniform UI and UI interactions.' Maintainer aeschli echoed this directly in the thread: 'We don't want to read the settings of the parent folder. It would add another layer of settings to an already very rich hierarchy: default - machine - user - workspace folder - workspace...'
