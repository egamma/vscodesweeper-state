# Issue #328605 — [Bug] Custom AI models configured in Copilot Chat Agent interface are not selectable or persist incorrectly

[https://github.com/microsoft/vscode/issues/328605](https://github.com/microsoft/vscode/issues/328605)

## Summary

Keep open as an accepted remote Agent Host capability gap, reclassified from bug to feature request. A maintainer confirmed that remote BYOK is intentionally unsupported today but that support, particularly for custom endpoints, is planned.

## Change summary

Make saved custom endpoint models available and persistently selectable in Copilot Agent sessions running in Remote WSL and other remote Agent Host environments.

## Best solution

Define and implement a secure remote-compatible BYOK path, initially covering built-in custom endpoints if necessary, so their catalog and inference remain available when the Agent Host runs remotely without an extension host.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentHostBootstrap.ts`, `src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts`, `src/vs/platform/agentHost/common/agentHostByokLm.ts`, `src/vs/platform/agentHost/common/agentHostClientByokLmChannel.ts`, `src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts`, `src/vs/platform/agentHost/test/node/agentHostBootstrap.test.ts`
- **Validation:** Add an Agent Host bootstrap/integration test for the remote configuration that supplies a saved custom endpoint, asserts it appears in the Copilot model catalog, selects it for a new chat, and verifies inference is routed through the chosen remote-compatible path instead of reverting to Auto.
- **Behavior:**

  > A custom endpoint saved in VS Code remains available when a Copilot Agent session runs in Remote WSL or another remote Agent Host environment. The model appears in the remote session's picker, remains selected when the chat starts, and is used for inference rather than silently reverting to Auto. Local Agent Host BYOK behavior remains unchanged. Extension-provided models outside the approved first-slice scope must not be advertised as usable remotely.
- **Trace:**

  > The reporter confirmed that the DeepSeek endpoint works in the Local harness and fails only in Remote WSL. The current local path registers AgentHostClientByokLmChannel from src/vs/platform/agentHost/electron-browser/localAgentHostService.ts, and Agent Host consumes it through IByokLmBridgeRegistry. Remote bootstrap instead supplies the unavailable variant, producing NullByokLmBridgeRegistry in src/vs/platform/agentHost/node/agentHostBootstrap.ts; that registry intentionally exposes no models or serving connection. The maintainer explanation at https://github.com/microsoft/vscode/issues/328605#issuecomment-5346478800 confirms this boundary and indicates custom endpoint support is planned. Preserve the existing local renderer bridge and do not imply that arbitrary extension-provided models can execute remotely unless the selected design provides an actual serving extension host or transport.
- **Open decisions:**
  - Should the first remote-support contract cover only VS Code's configured custom endpoints, or also arbitrary extension-provided BYOK models?
  - For custom endpoints, should credentials and inference remain on the client through a secure reverse transport, or be provisioned to and executed by the remote Agent Host?

## Evidence

- **maintainer direction:** https://github.com/microsoft/vscode/issues/328605#issuecomment-5346478800 confirms that remote Agent Host BYOK is not supported yet because no extension host is available there, while also stating that the team is working on the scenario and expects custom endpoint support.
- **confirmed scope:** https://github.com/microsoft/vscode/issues/328605#issuecomment-5224330502 confirms that the same DeepSeek custom endpoint works in the Local harness with chat.agentHost.byokModels.enabled, but disappears and falls back to Auto specifically in Remote WSL.
- **current source:** src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts:182-200 still defines NullByokLmBridgeRegistry for remote Agent Host entrypoints where no extension host runs; getModels() returns an empty list and getServingConnection() returns undefined.
- **bootstrap boundary:** src/vs/platform/agentHost/node/agentHostBootstrap.ts:152 selects NullByokLmBridgeRegistry whenever BYOK is marked unavailable, while src/vs/platform/agentHost/electron-browser/localAgentHostService.ts:618-630 registers the renderer-backed BYOK channel only for the local path.
- **related issue:** https://github.com/microsoft/vscode/issues/326344 is older and related, but its primary report concerns the local Agent Host BYOK bridge failing despite a renderer extension host being available; this issue isolates the separately acknowledged remote-host limitation, so it is not a verified duplicate.
