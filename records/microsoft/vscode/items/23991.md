# Issue #23991 — Keyboard mappings with `setxkbmap` on Linux not working

[https://github.com/microsoft/vscode/issues/23991](https://github.com/microsoft/vscode/issues/23991)

## Summary

Long-standing, well-understood bug with 286 upvotes: VS Code's scan-code-based keyboard dispatch ignores xkb customizations (setxkbmap, xmodmap) on Linux. The root cause lives in the native-keymap module, and the workaround (`keyboard.dispatch: keyCode`) has its own trade-offs. No fix has landed; the issue remains valid and should stay open.

## Change summary

Custom keyboard mappings set via setxkbmap/xmodmap on Linux (e.g. Caps Lock → Escape) are ignored by VS Code because it dispatches on scan codes rather than honoring xkb-level remappings.

## Best solution

Enhance `node-native-keymap` (the `_GetKeyMap` method in `keyboard_x.cc`) to read xkb option customizations and expose them, then consume those mappings in `macLinuxKeyboardMapper.ts` so scan-code dispatch respects xkb remappings. The `help wanted` label is appropriate — this needs someone with X11/xkb API expertise. The `keyboard.dispatch: keyCode` workaround remains available but breaks other shortcuts for some layouts.
