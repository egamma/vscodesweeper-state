# Issue #10952 — Auto hide panel

[https://github.com/microsoft/vscode/issues/10952](https://github.com/microsoft/vscode/issues/10952)

## Summary

Keep this accepted, strongly supported request open: current controls provide manual visibility and task-specific presentation, not the requested output-triggered reveal and automatic collapse. Related reports already consolidate here; the older sidebar request does not cover the terminal behavior.

## Change summary

Add an optional panel auto-hide mode with hover or terminal-output reveal and collapse on outside interaction or output inactivity.

## Best solution

Define an opt-in panel auto-hide interaction that preserves running terminals and makes hidden content readily discoverable, then coordinate workbench layout with terminal output events. Settle the precedence of editor interaction, pointer hover, and inactivity before implementation; retain the current default behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/panel/panelPart.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/contrib/terminal/browser/terminalService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalGroupService.ts`
- **Validation:** With the chosen mode enabled, run a persistent terminal command that emits output, pauses longer than the selected inactivity interval, and emits again. Verify automatic reveal and collapse, preservation of the same process and buffer, reopening through the retained affordance, and the agreed editor-focus/hover precedence. Repeat with the mode disabled to confirm existing behavior is unchanged.
- **Behavior:**

  > A user running a persistent build watcher can see fresh terminal output without manually opening the panel and recover editor space without manually hiding it. The requested mode includes a discoverable hover-to-reopen affordance and automatic collapse after outside interaction or output inactivity. Hiding must preserve the running terminal and its output. Acceptance checks must cover repeated output bursts, reopening, focus preservation, and unchanged behavior when the mode is disabled; the exact interaction precedence remains a product decision.
- **Trace:**

  > Manual panel visibility is controlled by TogglePanelAction and workbench.action.closePanel in src/vs/workbench/browser/parts/panel/panelActions.ts. TerminalService.onAnyInstanceData exposes output events in src/vs/workbench/contrib/terminal/browser/terminalService.ts, while TerminalGroupService.showPanel/hidePanel manages the terminal view and guards hiding when sibling views exist. Existing hideOnStartup/hideOnLastClosed settings and task presentation options address different lifecycle events, not the persistent-watcher scenario. The discussion supplies substantial demand and extension workarounds but leaves disagreements about hover versus editor interaction and the scope across other panel views. Preserve process lifetime, explicit visibility controls, and disabled-mode behavior; do not conflate hiding with task termination. Related panel reports already consolidate at https://github.com/microsoft/vscode/issues/10952, while https://github.com/microsoft/vscode/issues/3742 concerns the sidebar.
- **Open decisions:**
  - Should the initial mode apply only to the terminal or to the whole panel, including Output, Problems, and Debug Console?
  - Should clicking or typing in the editor collapse the panel even while the pointer remains over it, or should pointer hover keep it visible?
  - Should an explicitly opened or focused panel remain pinned until dismissed, or follow the same output-inactivity collapse rules as an automatically revealed panel?

## Evidence

- **Accepted request and demand:** https://github.com/microsoft/vscode/issues/10952 is in Backlog with feature-request and layout labels and 251 community upvotes. The central scenario is a long-running build watcher: new terminal output reveals the panel, which subsequently hides without terminating the process.
- **Existing manual controls:** src/vs/workbench/browser/parts/panel/panelActions.ts:30–99 registers workbench.action.togglePanel and workbench.action.closePanel, both using IWorkbenchLayoutService.setPartHidden. These are explicit actions, not automatic output-, hover-, or inactivity-driven visibility.
- **Existing automatic controls have different triggers:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:570–585 defines terminal.integrated.hideOnStartup and terminal.integrated.hideOnLastClosed. src/vs/workbench/contrib/terminal/browser/terminalService.ts:205–213 hides the terminal when no active instance remains; neither setting implements auto-hide while a build watcher remains running.
- **Task workaround is partial:** Comment 14 identifies presentation.reveal: "never" as a solution for suppressing task output. src/vs/workbench/contrib/tasks/common/jsonSchema_v2.ts defines reveal as execution/error-based visibility and close as closing the terminal when the task exits; these do not deliver repeated output-triggered reveal and idle collapse for a persistent process.
- **Extension workarounds and interaction concerns:** The discussion recommends venryx.vscode-vtools, sirmspencer.vscode-autohide, and SR-team.vscode-autohide-fork, but also records incomplete behavior: comment 14 describes failure to hide a terminal that never received focus, comment 19 notes missing reopening affordances, and comment 23 asks that editor typing override pointer hover. These are workaround and design evidence, not an established maintainer decision to exclude the feature from core.
