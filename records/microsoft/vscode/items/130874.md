# Issue #130874 — Test UI: Ability to `preserveFocus` when running tests

[https://github.com/microsoft/vscode/issues/130874](https://github.com/microsoft/vscode/issues/130874)

## Summary

Thanks for the report. The Testing API has no way for an extension to opt a run out of the explorer 'follow running test' behavior, so this stays open as under-discussion in the Backlog.

## Change summary

Let extensions opt a test run out of the explorer following (revealing and focusing) running tests, for example through a TestRunRequest option.

## Best solution

Decide whether the existing auto-run semantics or a per-request opt-out is the right extension-facing control, then wire it into the explorer follow logic in testingExplorerView.ts. Otherwise users keep disabling testing.followRunningTest globally.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/contrib/testing/browser/testingExplorerView.ts`
- **Validation:** A testing explorer test asserting that a run flagged to preserve explorer state does not reveal or focus tests while testing.followRunningTest is true.
- **Behavior:**

  > An extension can start a test run that does not make the Test Explorer reveal, scroll to, or focus running tests, even when testing.followRunningTest is true. Runs without the option behave as they do today.
- **Trace:**

  > The explorer follow logic in testingExplorerView.ts (around lines 899-914) is driven only by the testing.followRunningTest setting. TestRunRequest.preserveFocus already exists in vscode.d.ts but is documented as controlling the Results view. Uncertainty starts at whether to extend the meaning of preserveFocus or add a new property or option.
- **Open decisions:**
  - Reuse and broaden TestRunRequest.preserveFocus, or add a separate option for explorer following?
  - Does the opt-out override the user's testing.followRunningTest setting, or only apply when the setting is on?
