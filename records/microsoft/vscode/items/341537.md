# Issue #341537 — Agents: messages sent to a running sub-agent don't render in the chat

[https://github.com/microsoft/vscode/issues/341537](https://github.com/microsoft/vscode/issues/341537)

## Summary

Thanks for the detailed report. In the agent host's Copilot provider, a `user.message` with an `agentId` goes through `_resumeSubagentForEvent`, which only surfaces the message when it resumes an idle sub-agent. For a sub-agent that is still running, the function returns early, so the forwarded message is never emitted to the chat. The bug is source-traced but not executed.

## Change summary

Messages forwarded to a running background sub-agent via write_agent or steering are delivered to the sub-agent but not rendered in the chat.

## Best solution

Make the Copilot agent-host provider surface a sub-agent-addressed `user.message` in that sub-agent's thread even when the sub-agent is already active, not only on the `subagent_resumed` path. Cover it with a copilotAgentSession test that sends a sub-agent user.message while the sub-agent is active.

- **Open decisions:**

## Evidence

- **code path:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts: the `wrapper.onUserMessage` handler (around line 7227) routes events with `agentId` to `_resumeSubagentForEvent(e, { text, origin: User })`. At line ~2166, if `_activeSubagentAgentIds.has(agentId)` the function only reschedules the completion scheduler and returns. The `subagent_resumed` progress event that carries `message` (lines ~2179-2184) is fired only for an inactive sub-agent. For a running background sub-agent the message is therefore dropped. `_clearSubagentResponseParts` is also called when a message is present, so later behavior around response parts needs care.
- **reporter log:** events.jsonl shows `user.message` with the sub-agent's `agentId` followed by sub-agent assistant events, which matches an active sub-agent taking the early-return path. The sub-agent's later output is also missing from the chat, so the sub-agent thread's rendering after the forwarded message needs checking too.
- **caveat:** Code was not executed. A second possible cause, `_dropLateRootTurnEvents` or a missing `_parentToolCallIdsByAgentId` entry, also returns early and should be ruled out during the fix.
