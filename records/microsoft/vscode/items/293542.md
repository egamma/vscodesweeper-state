# Issue #293542 — package search form keeps resetting query terms

[https://github.com/microsoft/vscode/issues/293542](https://github.com/microsoft/vscode/issues/293542)

## Summary

The Installed menu action still replaces the search text, while Sort By preserves it. Keep this as a request for composable menu filtering: typing combined queries works, but does not satisfy the requested menu interaction.

## Change summary

Preserve existing search terms when applying filters through the Extensions search menu.

## Best solution

Let users narrow an existing Extensions search through menu filters without losing its text. The Extensions area should decide whether menu filtering should compose with the current query while explicit Show commands retain their preset-search behavior.

## Evidence

- **Reporter clarification:** The discussion in https://github.com/microsoft/vscode/issues/293542 clarifies the trigger: search for jinja, then select installed packages through the GUI menu; the search term disappears. This matches the Extensions menu path in current source.
- **Current replacement path:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts registers workbench.extensions.action.installedExtensions with openSearch('@installed '). ExtensionsWorkbenchService.openSearch in extensionsWorkbenchService.ts forwards that complete string to ExtensionsViewPaneContainer.search, whose implementation in extensionsViewlet.ts calls searchBox.setValue(value). The existing term is therefore replaced.
- **Existing capabilities and remaining gap:** In extensions.contribution.ts, extensions.sort.installs parses the current searchValue and preserves currentQuery.value while changing the sort. Query.parse/toString in src/vs/workbench/contrib/extensions/common/extensionQuery.ts supports that composition. ExtensionsListView.filterInstalledExtensions in extensionsViews.ts supports manually entered '@installed jinja', but the Installed menu action does not construct such a combined query.
- **Related maintainer guidance:** https://github.com/microsoft/vscode/issues/188483 is closed and reports menu filters replacing one another. A maintainer recommends manually typing combined filters at https://github.com/microsoft/vscode/issues/188483#issuecomment-1646577060. This supports treating menu composition as an improvement rather than a demonstrated regression, but does not explicitly decline preservation of ordinary search terms.
- **Canonical search:** Searches for Extensions search resets, filter composition, and query preservation found no verified open canonical owning this interaction. https://github.com/microsoft/vscode/issues/55697 and https://github.com/microsoft/vscode/issues/68529 are closed and concern combining query filters. The supplied open lead, https://github.com/microsoft/vscode/issues/334285, concerns interface modernization, was created after this report, and does not describe the same symptom.
