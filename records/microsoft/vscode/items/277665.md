# Issue #277665 — Require manual accepting of Copilot Edits

[https://github.com/microsoft/vscode/issues/277665](https://github.com/microsoft/vscode/issues/277665)

## Summary

A real UX gap remains despite existing approval settings: users can configure edits to require confirmation, but there is no clear, dedicated switch between automatic and manual edit acceptance. The Backlog milestone and existing chat-agent-editing label support keeping this open for design.

## Change summary

Provide an easy UI control for switching Copilot edits between automatic acceptance and explicit manual approval.

## Best solution

Expose a clearly labeled edit-approval choice in the Copilot permissions UI, with explicit scope and persistence semantics, while retaining the existing path-based safety rules for sensitive files.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostModePickerPresentation.ts`, `src/vs/platform/agentHost/node/sessionPermissions.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostChatInputPicker.test.ts`, `src/vs/platform/agentHost/test/node/sessionPermissions.test.ts`
- **Validation:** Extend the Agent Host permissions-picker tests to select the chosen manual-edit mode and verify its scope/persistence, plus a sessionPermissions test proving an ordinary workspace-file write requires confirmation while automatic mode preserves the existing behavior.
- **Behavior:**

  > Users can clearly switch Copilot edits between automatic and manual approval without editing glob-pattern JSON. In manual mode, the UI must unambiguously indicate when approval occurs and edits must not cross that boundary without user action. Automatic mode and the existing protections for sensitive or out-of-workspace files must remain intact. The selected scope and persistence must match the maintainer's decision.
- **Trace:**

  > Current pre-write approval is controlled globally by `chat.tools.edits.autoApprove`, registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts and enforced by `SessionPermissionManager` in src/vs/platform/agentHost/node/sessionPermissions.ts. The Agent Host picker in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostModePickerPresentation.ts offers Manual and Allow all, but Manual still defers to configured per-tool rules, whose default auto-approves most workspace edits. A separate post-edit mechanism, `chat.editing.autoAcceptDelay`, governs Keep/Undo acceptance, so "manual accepting" can describe two distinct user-visible checkpoints. https://github.com/microsoft/vscode/issues/274770 concerns centralizing the underlying rules and should not absorb this UX decision. Preserve protected-file checks and unrelated terminal/tool approval behavior.
- **Open decisions:**
  - Should the switch require approval before each file write, retain edits for explicit Keep/Discard review after application, or control both checkpoints?
  - Is the selected edit-approval mode global across VS Code, persisted per workspace, or selectable independently for each agent session?
  - Should the control affect only file-edit tools, or also shell commands detected as writing files?

## Evidence

- **existing capability:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.tools.edits.autoApprove`; configuring `"**/*": false` requires explicit approval for ordinary edits, so the underlying capability exists but is exposed as a pattern object rather than a simple workflow switch.
- **approval path:** src/vs/platform/agentHost/node/sessionPermissions.ts evaluates edit paths through `_isEditAutoApproved` and `_matchesEditAutoApprovePatterns`; src/vs/platform/agentHost/test/node/sessionPermissions.test.ts confirms that `"**/*": false` prompts for non-matching workspace writes.
- **current UI:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostModePickerPresentation.ts exposes Manual, Assisted, and Allow all permission levels plus Configure Permissions, but Manual still honors configured edit auto-approval rules and therefore is not a dedicated manual-edits toggle.
- **related architecture work:** https://github.com/microsoft/vscode/issues/274770 remains open for moving edit auto-approval logic into core. It concerns implementation ownership rather than this report's user-observable switching workflow, so it is related but not a duplicate.
- **related opposite workflow:** https://github.com/microsoft/vscode/issues/304539 was created after this issue and asks to eliminate or automatically resolve Keep/Discard state. It does not satisfy the stronger duplicate bar for this re-reviewed request for manual acceptance.
