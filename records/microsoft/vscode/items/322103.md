# Issue #322103 — VS Code allows incompatible local extension installation into Linux Codespace, leading to platform mismatch and "bad image format" errors

[https://github.com/microsoft/vscode/issues/322103](https://github.com/microsoft/vscode/issues/322103)

## Summary

Current main still has the incompatible-install path: the bulk “Install Local Extensions in Remote” fallback copies a local VSIX to the remote server without the target-platform check used by the single-extension path. This should remain open and be routed to extension management.

## Change summary

Prevent a platform-specific extension installed locally on one OS from being copied into an incompatible remote environment when Marketplace installation is unavailable.

## Best solution

Apply the existing target-platform compatibility rule to VSIX and bulk local-to-remote installation, rejecting an incompatible package before extraction with the standard incompatibility error while preserving universal-extension and compatible Marketplace behavior.

## Evidence

- **unguarded bulk fallback:** In src/vs/workbench/contrib/extensions/browser/extensionsActions.ts, InstallLocalExtensionsInRemoteAction.installExtensions obtains a compatible Marketplace package when available, but otherwise zips the locally installed extension and calls remoteExtensionManagementServer.extensionManagementService.install(vsix) without comparing the local and remote target platforms.
- **existing intended behavior:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts already checks isTargetPlatformCompatible in ExtensionsWorkbenchService.installInServer and throws "Can't install ... because it is not compatible" before copying an incompatible local extension to another server.
- **VSIX metadata loss:** src/vs/platform/extensionManagement/node/extensionManagementService.ts creates an ExtensionKey for a URI/VSIX using only the extension ID and version, omitting manifest.__metadata.targetPlatform. Extraction then writes that undefined target platform into installed metadata, so the incompatible package is accepted and loses the information needed to identify the mismatch.
