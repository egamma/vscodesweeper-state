# Issue #339695 — Copilot Chat "Local" harness hangs on "Considering…" in VS Code for the Web on a custom HTTPS origin (GitHub login fails)

[https://github.com/microsoft/vscode/issues/339695](https://github.com/microsoft/vscode/issues/339695)

## Summary

Fresh but unusually thorough report (exact log lines match the code path) of the built-in Copilot Chat extension silently failing GitHub auth and hanging forever on the Local harness when VS Code for the Web is served behind a custom HTTPS reverse-proxy origin; real gap, stays open and should route to the chat/authentication area for triage.

## Change summary

On a custom HTTPS reverse-proxy origin, the Copilot Chat extension's own GitHub login silently fails (even though a valid GitHub session exists via Agent Host/AHP), so the Local harness hangs on "Considering…" forever with no error, while the Copilot harness still works.

## Best solution

Two distinct, separable fixes: (1) make the GitHub authentication session resolution work correctly on arbitrary custom origins behind a reverse proxy (likely in the built-in GitHub auth provider or how the Copilot extension resolves sessions for web-served workbenches), and (2) have the Local harness fail fast with a visible error (or fall back to the Copilot harness) when `getCopilotToken`/`_auth` returns a `GitHubLoginFailed` result, instead of hanging silently on "Considering…".
