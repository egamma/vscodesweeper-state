## Evidence

- **confirmation editor already wraps:** chatTerminalToolConfirmationSubPart.ts sets `wordWrap: 'on'` and no `maxHeightInLines` for the run-in-terminal confirmation editor, so the full command should render (wrapped) rather than being cut off.
- **collapsed row intentionally truncates:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatTerminalToolProgressPart.css defines `.chat-terminal-command { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }` for the collapsed progress-row header — this is a deliberate one-line summary design, distinct from the confirmation dialog the user describes.
- **generic tool confirmation is capped:** chatToolConfirmationSubPart.ts (non-terminal tools) sets `wordWrap: 'off'` with `maxHeightInLines: 13` and relies on a visible scrollbar (per the #283242 fix) rather than wrapping — a candidate area if the screenshot is actually from a generic tool confirmation rather than the terminal-specific one.
- **persistence across versions:** Reported against 1.127.0; a second commenter confirms it still occurs in 1.132.0, but neither comment adds which specific widget/view was affected.
