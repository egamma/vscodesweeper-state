# Issue #326286 — Long commands are truncated

[https://github.com/microsoft/vscode/issues/326286](https://github.com/microsoft/vscode/issues/326286)

## Summary

Command text is genuinely truncated in multiple places in the terminal tool UI on current main — a fixed 80-character cutoff when building the invocation message and a 50-character cutoff for the collapsed progress header — and three separate reporters confirm this on 1.132.0, so this looks like a real, still-open display bug rather than something already fixed.

## Change summary

When Copilot runs a long/chained terminal command (especially outside the sandbox), the command shown to the user for review is truncated instead of showing the full text.

## Best solution

In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts (rawDisplayCommand/displayCommand, ~line 1307-1310) and chatTerminalToolProgressPart.ts (MAX_COMMAND_TITLE_LENGTH truncation, ~line 578-582), ensure the full command is always reachable/visible before a user approves unsandboxed execution — e.g. by not truncating the header used in the outside-sandbox confirmation flow, or by making sure the full-text codeblock is always shown (not just a truncated title) whenever unsandboxed confirmation is required.

## Evidence

- **80-char truncation:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts lines 1307-1310: `rawDisplayCommand.length > 80 ? rawDisplayCommand.substring(0, 77) + '...' : rawDisplayCommand` feeds the `invocationMessage` shown for both sandboxed and unsandboxed runs.
- **50-char header truncation:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts lines 78-582: `MAX_COMMAND_TITLE_LENGTH = 50` truncates the collapsible progress header text (`commandText.substring(0, MAX_COMMAND_TITLE_LENGTH) + '...'`).
- **confirmation codeblock is full text:** ChatTerminalToolConfirmationSubPart.ts line 107 renders `initialContent` (untruncated commandLine.original/toolEdited) into an editable code block, so the confirmation dialog itself is not always the truncation source — the truncated text more likely comes from the invocationMessage/header paths above, which matches reports that only the 'outside the sandbox' run shows a truncated command while the 'inside the sandbox' one does not.
- **community confirmation:** Comments from adamdodev and pmarkus confirm reproduction on 1.132.0, with pmarkus noting it specifically happens when Copilot retries a command 'outside the sandbox' after the sandboxed attempt fails.
