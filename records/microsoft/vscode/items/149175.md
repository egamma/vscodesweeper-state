# Issue #149175 — Problems without column information are always shown as column 1,1

[https://github.com/microsoft/vscode/issues/149175](https://github.com/microsoft/vscode/issues/149175)

## Summary

Still an open design question: the Problems view always displays column 1 when no column was matched by the task problem matcher. The marker model intentionally has no 'undefined column' concept (per jrieken), and no follow-up work changed the display. The discussion stalled in mid-2022 without consensus. Keeping open as under-discussion.

## Change summary

When a task problem matcher has no column capture group, the Problems view displays column 1 instead of omitting the column or indicating 'whole line'.

## Best solution

Decide whether the display layer (markersTreeViewer.ts) should suppress the column indicator when startColumn is 1 and endColumn is very large (the 'whole line' sentinel), or whether the marker model should gain an explicit 'no column' state. The former is lower-risk and self-contained in `src/vs/workbench/contrib/markers/browser/markersTreeViewer.ts`; the latter requires model changes jrieken declined. This is a UX design decision that needs maintainer input.
