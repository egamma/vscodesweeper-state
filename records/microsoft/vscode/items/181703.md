# Issue #181703 — Allow to preserve all state in the duplicated new window

[https://github.com/microsoft/vscode/issues/181703](https://github.com/microsoft/vscode/issues/181703)

## Summary

Floating editor windows now cover opening a file in another window within the same workspace, but duplicating a complete workbench still creates a separate workspace without preserving workspace-scoped extension enablement. Keep this accepted request open while the owner decides whether the remaining full-workbench duplication requirement is still needed.

## Change summary

Preserve workspace context, settings, and extension enablement when duplicating a workspace into another window.

## Best solution

Use floating editor windows for the same-workspace, separate-file workflow already supported. For full workbench duplication, settle which state should remain shared versus independently copied, with workspace-scoped extension enablement explicitly included.

- **Behavior:**

  > The reporter wants another window using the same workspace context, especially the same enabled and disabled extensions. Floating editor windows already provide a separate file window within that context, but the existing full-workbench duplication command creates another workspace. A full-workbench solution must preserve the agreed workspace state, including workspace-specific extension enablement. Acceptance must distinguish an initial copy from continuing synchronization between windows.
- **Trace:**

  > DuplicateWorkspaceInNewWindowAction.run() in src/vs/workbench/browser/actions/workspaceActions.ts creates an untitled workspace, calls copyWorkspaceSettings(), and opens that new workspace. AbstractWorkspaceEditingService.doCopyWorkspaceSettings() copies registered configuration values, whereas ExtensionEnablementService keeps extension overrides in workspace-scoped storage. BaseMoveCopyEditorToNewWindowAction in editorActions.ts instead creates an auxiliary editor part within the existing workbench service hierarchy, providing an already-shipped alternative for the separate-file use case. The remaining uncertainty is the product contract for a complete second workbench, not whether settings can already be copied. Preserve existing floating-editor behavior and do not equate all workspace storage with safely transferable state. The owner's acceptance is recorded at https://github.com/microsoft/vscode/issues/181703#issuecomment-1545475338.
- **Open decisions:**
  - Should the remaining capability create a complete second workbench sharing the original workspace context, or an independent workspace initialized with selected state?
  - Beyond workspace settings and extension enablement, which observable state must be preserved, and should subsequent changes remain synchronized between the windows?
