# Issue #318198 — Default themes should not include markdown suffix

[https://github.com/microsoft/vscode/issues/318198](https://github.com/microsoft/vscode/issues/318198)

## Summary

A real cross-language theming gap remains on current main: bundled themes still use Markdown-specific quote/list punctuation selectors, preventing compatible markup grammars from inheriting those colors. The exact generic selector needs a theme-owner decision because the alternatives differ in whether only punctuation or entire markup spans receive the color.

## Change summary

Generalize default-theme TextMate selectors for quote and list punctuation so compatible non-Markdown markup grammars can reuse the styling.

## Best solution

Standardize the affected bundled themes on language-neutral selectors that preserve marker-only coloring, then cover selector resolution across Markdown and an equivalent non-Markdown scope stack with a theme service test.

## Plan brief

- **Likely files:** `extensions/theme-defaults/themes/dark_vs.json`, `extensions/theme-defaults/themes/light_vs.json`, `extensions/theme-defaults/themes/hc_light.json`, `extensions/theme-defaults/themes/2026-dark.json`, `extensions/theme-defaults/themes/2026-light.json`, `src/vs/workbench/services/themes/test/node/tokenStyleResolving.test.ts`
- **Validation:** Extend the `Themes - TokenStyleResolving` unit suite to load the affected rules and assert that equivalent Markdown and non-Markdown quote/list marker scope stacks resolve to the intended colors while surrounding list or quote content does not acquire marker coloring; run `scripts/test.sh --grep "Themes - TokenStyleResolving"`.
- **Behavior:**

  > Default themes give equivalent quote and list markers the same syntax colors when a markup grammar emits the agreed language-neutral TextMate scopes, regardless of whether the language is Markdown. Existing Markdown marker colors remain unchanged. Text inside a quote or list must not inherit marker-only coloring unless the selected scope policy explicitly intends that broader behavior. All affected standard, high-contrast, and 2026 default themes follow the same selector policy.
- **Trace:**

  > The affected token rules are in extensions/theme-defaults/themes/dark_vs.json, light_vs.json, hc_light.json, 2026-dark.json, and 2026-light.json. The Markdown grammar emits `punctuation.definition.quote.begin.markdown` inside `markup.quote.markdown` and `punctuation.definition.list.begin.markdown` inside numbered or unnumbered list parents. The color-theme schema recognizes generic `markup.quote` and `markup.list*` vocabulary, but parent-scope matching can affect an entire markup span rather than only its marker. Existing scope-resolution coverage lives in src/vs/workbench/services/themes/test/node/tokenStyleResolving.test.ts. Keep the boundary to bundled theme selectors and their tests; do not redesign the Markdown grammar or change unrelated token colors. The broader 2026-theme trackers at https://github.com/microsoft/vscode/issues/293405 and https://github.com/microsoft/vscode/issues/295783 do not settle this selector-semantic choice.
- **Open decisions:**
  - Should cross-language reuse apply only to quote/list punctuation markers through language-neutral punctuation selectors, or should the generic `markup.quote` and `markup.list*` parent scopes intentionally color the broader markup spans?
