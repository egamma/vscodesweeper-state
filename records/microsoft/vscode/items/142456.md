# Issue #142456 — Inconsistent keyboard shortcuts between Windows and Linux

[https://github.com/microsoft/vscode/issues/142456](https://github.com/microsoft/vscode/issues/142456)

## Summary

Keep open under discussion: this remains a well-supported cross-platform consistency request with 40 upvotes and sustained reports from Windows/Linux users. The cited extension is an incomplete workaround rather than coverage of the central ask to select and synchronize a built-in keybinding profile.

## Change summary

Allow Linux users to select the Windows default keybinding set, ideally preserving and synchronizing that choice across operating systems.

## Best solution

Provide a built-in, syncable keybinding-profile choice that can apply another platform's default bindings while retaining explicit user overrides and exposing unavoidable OS conflicts.

## Plan brief

- **Likely files:** `src/vs/workbench/services/keybinding/common/keybindingIO.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/platform/keybinding/common/keybindingsRegistry.ts`, `src/vs/workbench/services/userDataProfile/common/userDataProfile.ts`, `src/vs/platform/userDataSync/common/userDataSync.ts`
- **Validation:** Add automated keybinding/profile tests that select Windows defaults on Linux, verify representative commands resolve to the Windows bindings, preserve explicit user overrides, and round-trip the selected profile through synchronization.
- **Behavior:**

  > Users can choose a built-in platform keybinding profile independently of the host operating system. Selecting the Windows profile on Linux makes representative default commands such as Back/Forward, Format Document, and Copy Line Up/Down resolve as they do on Windows, while explicit user keybindings continue to win. The selected profile can follow the user across systems through Settings Sync, with platform-unavailable or conflicting bindings surfaced rather than silently discarded.
- **Trace:**

  > The report concerns VS Code's platform-specific default keybinding layer, not keyboard-layout dispatch or a single broken command. Existing user keybindings and Settings Sync provide customization and portability, while the community extension https://marketplace.visualstudio.com/items?itemName=smcpeak.default-keys-windows approximates Windows defaults; neither supplies a first-party selectable default profile with defined precedence and conflict behavior. Historical discussions at https://github.com/microsoft/vscode/issues/17550 and https://github.com/microsoft/vscode/issues/38388 explain some Linux differences but are not verified here as canonical owners of this broader selectable-profile request. Keep command implementations and physical keyboard-layout handling out of scope; the unresolved boundary is how a chosen default profile composes with host-specific defaults, user overrides, and synchronization.
- **Open decisions:**
  - Should the selected keybinding profile replace all host-platform defaults, or only substitute bindings that are valid on the current host while retaining host-specific fallbacks?
  - Should Settings Sync carry one global preferred keybinding profile across operating systems, or retain a separate profile choice per operating system?
  - When a selected profile contains a host-reserved or unavailable binding, should VS Code keep it with a conflict indication, omit it with a warning, or fall back to the host default?
