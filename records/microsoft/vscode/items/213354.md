# Issue #213354 — Regex match doesn't start at cursor

[https://github.com/microsoft/vscode/issues/213354](https://github.com/microsoft/vscode/issues/213354)

## Summary

The reported jump to (bar) remains explainable from current source: Find navigates document-wide, non-overlapping matches rather than evaluating the regex from the cursor. Keep this accepted editor-find bug open; cursor-relative matching needs a coherent contract with the highlighted results and match count.

## Change summary

Starting regex Find immediately before the inner (foo) skips it and selects (bar) instead.

## Best solution

Make initial regex navigation honor the requested cursor starting point without making navigation, highlighted matches, match counts, and replacement disagree. The editor-find owner should settle how cursor-relative matches relate to the document-wide result set before implementation.
