# Issue #213354 — Regex match doesn't start at cursor

[https://github.com/microsoft/vscode/issues/213354](https://github.com/microsoft/vscode/issues/213354)

## Summary

The observed behavior is intentional: the regex's first match begins before the cursor, so Find Next advances to `(bar)`.

## Change summary

Make regex Find Next select a match containing the cursor rather than only one starting at or after it.

## Best solution

Keep the existing forward-navigation semantics. To match only non-nested parenthesized text such as `(foo)`, use a pattern like `\([^()]*\)`.

- **Proposed comment:**

  > Thanks for the report. The first match of `(\\()(.+?)(\\))` is actually `([foo](foo)`: it starts at the line's first opening parenthesis, so the cursor after `]` is inside that match. Find Next selects a match whose start is at or after the cursor, which makes `(bar)` the next result here. To match `(foo)` independently, a pattern such as `\([^()]*\)` excludes nested parentheses.

## Evidence

- **regex result:** Against `([foo](foo))`, `(\\()(.+?)(\\))` matches `([foo](foo)` from the first opening parenthesis through the first closing parenthesis. The stated cursor position is therefore inside that match, not before it.
- **current source:** `src/vs/editor/contrib/find/browser/findDecorations.ts` lines 251-270 implements Find Next by selecting the first match whose start is at or after the cursor; matches starting before the cursor are skipped.
- **established behavior:** The relevant `matchAfterPosition` behavior dates to commit c166beabe59d860c138a8aa229e6425f2a152abe and remains unchanged on current main.
