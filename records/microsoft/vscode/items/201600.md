# Issue #201600 — Enter custom tab size from the UI

[https://github.com/microsoft/vscode/issues/201600](https://github.com/microsoft/vscode/issues/201600)

## Summary

The requested UI capability is still missing: the indentation picker only offers sizes 1–8. A maintainer reopened this request and moved it to Backlog after the community timeout, so the earlier lack of 20 upvotes is not grounds to close it.

## Change summary

Allow entering a custom tab size through the Indent Using Tabs selection UI.

## Best solution

Support a custom numeric size within the existing current-file indentation workflow while preserving the preset choices and avoiding changes to persistent settings. Agree on the input interaction before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/indentation/browser/indentation.ts`, `src/vs/editor/contrib/indentation/test/browser/indentation.test.ts`
- **Validation:** Exercise editor.action.indentUsingTabs on an editable file: enter a supported custom size outside 1–8, such as 12, and verify the current model uses tabSize 12, indentSize 12, and insertSpaces false without modifying file contents or persistent settings. Verify preset selection still works, cancellation leaves model options unchanged, and invalid input cannot apply an invalid size.
- **Behavior:**

  > The Indent Using Tabs workflow currently restricts users to sizes 1–8 even though editor configuration supports larger values. Users should be able to enter a supported custom size for the current file without editing persistent settings. Acceptance includes applying size 12 with tabs enabled, retaining preset selection, and leaving the model unchanged on cancellation or invalid input.
- **Trace:**

  > In src/vs/editor/contrib/indentation/browser/indentation.ts, IndentUsingTabs delegates to ChangeIndentationSizeAction.run, which creates a fixed 1–8 list and applies the selected label through model.updateOptions. The same action also serves IndentUsingSpaces and ChangeTabDisplaySize; the latter intentionally changes only tabSize, while the indentation actions also change indentSize and insertSpaces. src/vs/editor/common/config/editorConfigurationSchema.ts establishes the existing editor.tabSize range of 1–100, so arbitrary numeric configuration is available but does not cover the requested picker interaction. Preserve current-file scope, file contents, and the distinct semantics of the shared actions. The remaining uncertainty is how custom entry should appear to users; the issue does not settle that interaction. The accepted request is https://github.com/microsoft/vscode/issues/201600.
- **Open decisions:**
  - Should users enter a custom number directly in the existing picker, or select an explicit Custom entry that opens a numeric input?
