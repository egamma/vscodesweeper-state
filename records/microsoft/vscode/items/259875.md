# Issue #259875 — One should be able to use a separator item

[https://github.com/microsoft/vscode/issues/259875](https://github.com/microsoft/vscode/issues/259875)

## Summary

Keep open: this requests separator support in QuickTree, not the existing flat QuickPick separator capability. Current source still lacks that support, and no verified older canonical owns the same request.

## Change summary

Allow separator items in the core QuickTree API, as requested during SCM repository-picker adoption.

## Best solution

Provide QuickTree section separators consistent with QuickPick grouping while preserving hierarchical selection. Agree on separator placement and filtering/sorting semantics before implementing the API and rendering support.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/tree/quickTree.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeController.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeRenderer.ts`, `src/vs/platform/quickinput/browser/tree/quickInputDelegate.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeFilter.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeSorter.ts`
- **Validation:** Add browser tests under src/vs/platform/quickinput/test/browser/tree for the agreed separator contract: section rendering, keyboard navigation, exclusion from checkedLeafItems, and grouping during filtering and sorting. Manually verify a QuickTree with repository parents, children and separators using mouse, keyboard and a screen reader; existing flat QuickPick separators and ordinary QuickTree selection must remain unchanged.
- **Behavior:**

  > The core QuickTree API should support separator entries for grouping choices, motivated by an SCM picker containing repositories and their submodules or worktrees. Ordinary QuickPick already supports separators, but QuickTree currently does not. Acceptance must establish visible section separation without treating separators as selectable repository items, and define how grouping behaves during filtering and sorting. Ordinary tree-item selection and flat QuickPick behavior must remain unchanged.
- **Trace:**

  > The request originates in https://github.com/microsoft/vscode/issues/258769, whose maintainer explicitly split the adoption feedback into individual issues. In src/vs/platform/quickinput/common/quickInput.ts, IQuickPickSeparator and QuickPickInput provide the flat-list capability, whereas IQuickTree.setItemTree and IQuickTreeItem.children accept only ordinary tree items. QuickInputTreeController.setTreeData constructs ordinary tree nodes; QuickInputTreeDelegate selects one template, and QuickInputTreeRenderer has no separator branch. Non-pickable entries hide their checkbox but remain ordinary rows, so they are not full separator support. QuickInputTreeFilter matches labels and descriptions, while QuickInputTreeSorter sorts ordinary siblings by label and description; neither models section boundaries. The remaining uncertainty is the user-visible separator contract within a hierarchy, not whether flat QuickPick separators already exist. Keep flat QuickPick behavior and unrelated QuickTree requests outside this change.
- **Open decisions:**
  - Should separators be supported only between root entries, or also between siblings within nested child lists?
  - During filtering and label sorting, should separators define sections whose items remain grouped, and should a section header disappear when none of its items match?
