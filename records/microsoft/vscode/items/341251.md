# Issue #341251 — Terminal: stale frame left on screen after committing full-width punctuation via IME (Remote SSH, TUI app)

[https://github.com/microsoft/vscode/issues/341251](https://github.com/microsoft/vscode/issues/341251)

## Summary

Thanks for the detailed report and for finding the root cause. With Screen Reader Optimized mode on, committing IME full-width punctuation appears to send the mirrored screen text to the pty instead of only the committed character. That mirroring comes from xterm.js's screen-reader textarea handling rather than VS Code's own terminal code, so this stays open as an upstream issue. I could not execute the flow or trace it in this repo.

## Change summary

In screen reader mode, committing full-width punctuation via an IME sends the whole mirrored terminal screen as input, which corrupts TUI output.

## Best solution

Confirm the textarea-mirroring and composition handling in xterm.js's accessibility/screen-reader mode, then fix or work around it there so only the committed IME text reaches the pty. Separately, consider whether `editor.accessibilitySupport: auto` should enable this mode when no screen reader is actually in use.
