# Issue #251076 — File protocol links in editor do not open in WSL

[https://github.com/microsoft/vscode/issues/251076](https://github.com/microsoft/vscode/issues/251076)

## Summary

Confirmed bug, still present on main: the editor's default link handler opens file:// URIs directly without remapping them to the remote authority when connected via WSL (or any remote), so clicks try to open the file on the local host instead of the remote.

## Change summary

Clicking a file:// protocol link in the editor while connected to WSL opens (or tries to create) the file on the Windows host filesystem instead of the WSL filesystem.

## Best solution

The editor link handler in `src/vs/editor/contrib/links/browser/links.ts` (and/or the editor opener service) should detect when a remote authority is active and remap `file://` URIs to the corresponding `vscode-remote://` scheme before opening, similar to how the terminal link handler already does. The fix likely involves checking `IWorkbenchEnvironmentService.remoteAuthority` or equivalent context and transforming the URI before passing it to the opener service.
