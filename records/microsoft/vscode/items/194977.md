[https://github.com/microsoft/vscode/issues/194977](https://github.com/microsoft/vscode/issues/194977)

## Summary

The reporter's keyboard log identifies the same AltGr-triggered cursor-left movement tracked by the older, still-open canonical issue. Consolidate there while preserving this report's diagnostic log and confirmed workaround.

## Change summary

Typing an opening bracket moves the cursor left before inserting the character.

Its reproduction explicitly describes AltGr used to compose a bracket causing both cursor-left movement and character insertion. This matches the reporter-observable symptom, satisfying the stronger duplicate bar for this re-reviewed item.
- **Diagnostic log identifies dispatch rather than auto-closing:** https://github.com/microsoft/vscode/issues/194977#issuecomment-1840679320 shows an event with code: ArrowLeft, keyCode: 225, key: AltGraph, followed by invocation of the built-in cursorLeft command. - **Same confirmed workaround:** The reporter confirms that keyboard.dispatch = keyCode avoids the problem in https://github.com/microsoft/vscode/issues/194977#issuecomment-1940651040, while default code dispatch still fails in 1.89.0 according to https://github.com/microsoft/vscode/issues/194977#issuecomment-2095290883. The canonical documents the same workaround in https://github.com/microsoft/vscode/issues/24783#issuecomment-297283849 and the same bracket-entry symptom in https://github.com/microsoft/vscode/issues/24783#issuecomment-690053818.
- **Current source is consistent with the reported mechanism:** src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts:937-996 derives a ScanCodeChord from keyboardEvent.code; an ArrowLeft code with an unknown keyCode is not corrected by its navigation-key overrides. src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts selects FallbackKeyboardMapper for keyCode dispatch. src/vs/platform/keyboardLayout/common/keyboardConfig.ts registers keyboard.dispatch with default code.
