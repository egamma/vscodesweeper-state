# Issue #343696 — Copilot harness drops the `include-custom-instructions` custom agent frontmatter, so custom subagents never get AGENTS.md

[https://github.com/microsoft/vscode/issues/343696](https://github.com/microsoft/vscode/issues/343696)

## Summary

Keep open: current source still discards the instruction opt-in, and independent confirmations describe missing custom-subagent instructions on macOS and Windows. The related merged PRs implement consumer workarounds, not a VS Code fix.

## Change summary

Honor include-custom-instructions: true so Copilot custom subagents receive applicable repository instructions automatically.

## Best solution

Preserve the authored instruction opt-in through Copilot custom-agent conversion and the SDK/runtime boundary, with actual instruction delivery verified. Retain existing behavior for agents that do not opt in.

- **Behavior:**

  > A Copilot custom agent declaring include-custom-instructions: true receives applicable repository instructions when invoked as a subagent, without needing to read them with tools or receive them manually in the parent's dispatch prompt. Validate with a unique repository instruction sentinel in the subagent's actual model context. Agents with false or omitted flags retain the runtime's existing semantics, and built-in general-purpose instruction delivery remains unchanged.
- **Trace:**

  > toSdkCustomAgents in src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts constructs an explicit SDK configuration but omits the authored instruction-inclusion attribute. CopilotSessionLauncher passes these configurations through mapCopilotCustomAgentTools into sessionConfig.customAgents. The editor already recognizes the boolean attribute in promptFileAttributes.ts. Independent system-message inspection is recorded at https://github.com/microsoft/vscode/issues/343696#issuecomment-6568697153. The locally installed SDK declaration lacks the field, so first establish the exact pinned SDK/runtime wire contract and whether runtime support exists before treating this as a converter-only fix. Keep the boundary to custom-agent instruction opt-in; other discarded frontmatter fields and unrelated instruction discovery behavior are outside this issue's central acceptance case.

## Evidence

- **current conversion defect:** src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts: toSdkCustomAgents reads selected frontmatter fields and constructs an explicit config containing model, reasoningEffort, tools, skills, hooks, infer, disableModelInvocation and prompt. It never reads or forwards include-custom-instructions; ICopilotCustomAgentConfig adds only disableModelInvocation.
- **SDK handoff:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts obtains authored configs through toSdkCustomAgents(getCopilotCustomAgents(plan.snapshot), ...) and places their tool-remapped results into sessionConfig.customAgents. mapCopilotCustomAgentTools preserves existing fields but cannot restore the discarded flag.
- **recognized attribute:** src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts recognizes include-custom-instructions as a boolean and describes it as controlling whether repository custom instructions are included in the custom agent context.
- **confirmed reproduction:** https://github.com/microsoft/vscode/issues/343696#issuecomment-6568697153 reports inspection of six custom-subagent system messages on macOS 1.145.0-insider, all missing repository instructions. https://github.com/microsoft/vscode/issues/343696#issuecomment-7012084393 independently confirms missing automatic AGENTS.md context on Windows 1.147.0 with runtime 1.0.111.

The checkout package.json pins @github/copilot-sdk 1.0.27-unstable.41214319014.g4f70995; the installed declaration alone does not establish the pinned runtime's supported wire contract, so an executable fix cannot yet be bounded to forwarding one property.

Neither changes VS Code's automatic instruction delivery.
