# Issue #346258 — First Agent chat after signing in to an MCP server gets none of its tools (agent host's connection stays `needs-auth`)

## Summary

Keep open: the supplied steps and timestamped logs suffice to retest the first-turn authentication hand-off. Current main has silent credential forwarding and inline authentication UI, but those mechanisms do not establish that this startup race is resolved.

## Change summary

A first Agent chat starts without an already-authorized MCP server's tools because the agent host receives its token too late.

## Best solution

Make first-turn MCP availability reflect pending authentication rather than silently treating the server as absent. Diagnose the credential-forwarding delay across the workbench and Copilot session, preserving account consent and cancellation behavior.
