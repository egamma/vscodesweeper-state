# Issue #337479 — Sessions: Polish layout when many related session pills are shown

[https://github.com/microsoft/vscode/issues/337479](https://github.com/microsoft/vscode/issues/337479)

## Summary

Current main still gives every related subagent/session pill a full-width row, so several interactions necessarily form a tall stack. This is valid Agents Window polish, but the compact behavior needs a product decision between wrapping and overflow disclosure.

## Change summary

Present large sets of related-session pills compactly instead of stacking every pill as a full-width row.

## Best solution

Use a responsive presentation that keeps active and attention-requiring sessions immediately visible while compacting completed overflow, preserving keyboard access, accessible names, status, and direct navigation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentOpenChat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatSubagentOpenChat.css`
- **Validation:** Exercise a chat response containing many related subagent sessions at wide and narrow transcript widths; verify bounded vertical growth, keyboard access to every session, correct focus restoration, and unchanged status/confirmation visibility.
- **Behavior:**

  > A response with many related sessions must not be dominated by a full-width vertical pill stack. Users must still be able to scan and open every related session with mouse or keyboard, and running, waiting, or confirmation-required state must remain discoverable. The presentation must remain usable at narrow and wide transcript widths and with reduced motion.
- **Trace:**

  > Each subagent interaction is rendered by ChatSubagentContentPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts, which creates a dedicated `.chat-subagent-open-chat-toolbar` containing one OpenSubagentChatActionViewItem. src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatSubagentOpenChat.css gives that pill widget `width: 100%`, making several sibling subagent parts form the reported tall stack. The action view item in chatSubagentOpenChat.ts carries navigation, keyboard behavior, accessible state, active-tool text, duration, credits, and confirmation state; those semantics must not be lost. The existing compact ChatPillsRow is relevant precedent but represents input-status categories rather than transcript subagent interactions. https://github.com/microsoft/vscode/issues/331659 is related broad UX work, not a duplicate of this exact symptom.
- **Open decisions:**
  - Should large related-session sets wrap into multiple compact rows, or collapse completed overflow behind a summary affordance?
  - Which session states must remain individually visible when overflow is collapsed: active, waiting, failed, or confirmation-required?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatSubagentOpenChat.css sets `.chat-subagent-pill-widget` to `width: 100%` and lays each widget out as a column, which makes multiple related-session pills consume one full row each.
- **rendering path:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts creates a separate `.chat-subagent-open-chat-toolbar` containing one pill for each subagent chat; no grouping or overflow behavior is applied across those parts.
- **existing compact precedent:** src/vs/workbench/browser/chatPills.ts and src/vs/workbench/browser/media/chatPills.css already implement a horizontally scrollable, keyboard-accessible compact row for chat-input status pills, but that shared row does not govern transcript subagent pills.
- **canonical search:** The older https://github.com/microsoft/vscode/issues/331659 tracks broader subagent and multi-chat polish but does not report this same observable many-pill vertical-stack symptom, so the stronger re-review duplicate bar is not met.
