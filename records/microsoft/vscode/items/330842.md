# Issue #330842 — Microsoft account sign in isn't properly dark themed so it flashes black to white repeatedly -- giving me a headache

[https://github.com/microsoft/vscode/issues/330842](https://github.com/microsoft/vscode/issues/330842)

## Summary

Reporter did excellent tracing: the flashing white window is the native Windows Web Account Manager (WAM) broker UI invoked via `@azure/msal-node-extensions`/`msal-node-runtime`, not a VS Code-rendered webview — VS Code only passes a window handle, with no theme/appearance hook available in the current MSAL native-broker API, so this is upstream in the Windows broker/MSAL stack rather than something fixable in this repo's code.

## Change summary

The native Microsoft account sign-in broker window flashes black/white repeatedly instead of following VS Code's dark theme.

## Best solution

Track this against the native broker path (`@azure/msal-node-extensions` / Windows WAM), since VS Code has no control over that window's rendering; in the meantime consider surfacing the `microsoft-authentication.implementation: msal-no-broker` setting more prominently as a documented workaround, since the reporter confirmed it avoids the flashing and the repeated prompts.

## Evidence

- **broker construction:** extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts constructs `NativeBrokerPlugin` from `@azure/msal-node-extensions` when broker is available and not disabled via `microsoft-authentication.implementation`; this plugin drives Windows WAM UI, which VS Code does not render or theme.
- **upstream precedent:** Reporter linked a very similar unresolved WAM-flashing report at https://github.com/AzureAD/microsoft-authentication-library-for-dotnet/issues/6055, corroborating this is a broker-level issue, not VS Code-specific.
- **workaround confirmed:** Reporter confirmed setting `microsoft-authentication.implementation: msal-no-broker` avoids both the flashing and the repeated hourly prompts (comment 2026-08-31).
