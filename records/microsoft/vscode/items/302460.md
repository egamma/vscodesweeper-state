# Issue #302460 — MCP Registry URL not retreived although properly set in Enterprise settings (Github Enterprise Managed Users)

[https://github.com/microsoft/vscode/issues/302460](https://github.com/microsoft/vscode/issues/302460)

## Summary

Keep open and route to Copilot MCP management: multiple enterprise users confirmed that the configured registry is lost because the GitHub service returns 404 from `/copilot/mcp_registry`. Current VS Code source requests the expected endpoint, and a maintainer identified server-side provisioning as the likely root cause.

## Change summary

Enterprise MCP registry policy is not delivered to VS Code for EU data-residency EMU tenants and some GHES environments.

## Best solution

Provision and serve the effective MCP registry policy consistently from `/copilot/mcp_registry` for supported enterprise configurations; VS Code's existing account-policy path will consume the registry once that endpoint returns a successful response.

- **independent confirmations:** Two additional reporters confirmed missing registry policy with enterprise configurations; one reports the same 404 for EU data residency, while another reports absent registry fields on GHES even though Copilot CLI enforces the policy: https://github.com/microsoft/vscode/issues/302460#issuecomment-4135452481 and https://github.com/microsoft/vscode/issues/302460#issuecomment-4295801419
- **current source path:** src/vs/workbench/services/accounts/browser/defaultAccount.ts:getMcpRegistryDataUrl constructs the enterprise `/copilot/mcp_registry` URL; requestMcpRegistryProvider performs the authenticated GET and treats a 4xx response as no registry. The returned registry would otherwise populate policyData.mcpRegistryUrl and policyData.mcpAccess.
- **workaround:** The reporter confirmed that configuring MCP through VS Code Enterprise policies works around the missing service response, but does not resolve enterprise-level GitHub policy delivery: https://github.com/microsoft/vscode/issues/302460#issuecomment-4334067524
