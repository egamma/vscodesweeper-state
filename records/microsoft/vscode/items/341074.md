# Issue #341074 — Browse MCP Servers command does nothing

[https://github.com/microsoft/vscode/issues/341074](https://github.com/microsoft/vscode/issues/341074)

## Summary

Thanks for the report. The command is a thin wrapper around the Extensions view search, and that view does not exist in the Agents window. That explains focus moving to the sidebar with no visible result. This is a fresh, team-authored report with no existing fix found, so it stays open.

## Change summary

In the Agents window, 'Browse MCP Servers' (workbench.mcp.browseServers) focuses the customizations sidebar but shows no MCP server browser.

## Best solution

Make the Agents window handle Browse MCP Servers by opening its own MCP browse surface, for example the MCP section of the customizations editor. Alternatively, hide the command there.

- **Behavior:**

  > In the Agents window, running workbench.mcp.browseServers shows a usable MCP server browsing experience instead of only moving focus to the customizations sidebar. In the main workbench the command still opens the Extensions view with '@mcp '.
- **Trace:**

  > McpBrowseCommand (src/vs/workbench/contrib/mcp/browser/mcpCommands.ts) calls IExtensionsWorkbenchService.openSearch('@mcp '). openSearch opens the Extensions viewlet container and searches. The Agents window registers the same service (src/vs/sessions/sessions.common.main.ts) but has no handling of its own. Confirm at runtime which container openViewContainer resolves to there. Do not change main-workbench behavior. Where the uncertainty starts: the right Agents-window destination for MCP browsing.
- **Open decisions:**

## Evidence

- **command impl:** src/vs/workbench/contrib/mcp/browser/mcpCommands.ts (McpBrowseCommand.run) only calls IExtensionsWorkbenchService.openSearch('@mcp ').
- **openSearch:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts openSearch opens VIEWLET_ID and calls search() on its view pane container. If the Agents window does not host that container, nothing visible happens. I did not verify what the Agents window registers.
- **no sessions override:** grep of src/vs/sessions found no Agents-window handling of '@mcp' or openSearch, so the command is not adapted there.
