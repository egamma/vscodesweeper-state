# Issue #349131 — Model router: add command to open folder containing router files

[https://github.com/microsoft/vscode/issues/349131](https://github.com/microsoft/vscode/issues/349131)

## Summary

Keep open: the existing model-picker link opens an individual router definition, but cannot provide recovery navigation when its model disappears. This team-authored request identifies a remaining discoverability gap.

## Change summary

Provide a discoverable command to open router-definition folders even when no router models are listed.

## Best solution

Expose router-folder navigation independently of model-picker entries, using the owning host's actual router locations. Account for both supported locations and an overridden Copilot home without changing router discovery or filename rules.

- **Behavior:**

  > Users can discover and invoke router-folder navigation without selecting a router model. Renaming a router file so that it no longer appears in the picker must not remove access to its containing folder. Acceptance covers both supported router locations and an overridden Copilot home; opening the folder must not modify router definitions.
- **Trace:**

  > CopilotAgent._modelRouterFolders() in src/vs/platform/agentHost/node/copilot/copilotAgent.ts supplies two discovery roots: userHome/.agents/model-routers and copilotHomeService.home/model-routers. UserModelRouterSource.read() in copilotModelRouterCatalog.ts scans those roots and recognizes only filenames accepted by modelRouterNameFromFileName(). Preserve discovery precedence, filename validation, model availability, and host/client URI boundaries; this request is navigation, not a change to rename semantics. The remaining product uncertainty is which destination the command exposes when both roots are relevant.
