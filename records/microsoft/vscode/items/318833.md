# Issue #318833 — mermaid support for init string

[https://github.com/microsoft/vscode/issues/318833](https://github.com/microsoft/vscode/issues/318833)

## Summary

The built-in mermaid renderer calls `mermaid.initialize()` with a fixed theme before each render pass. Mermaid 11's default `secure` array blocks certain directive keys (including `theme` and `themeVariables`) from being overridden via `%%{init: ...}%%` directives. The diagram content — including the directive — is passed to `mermaid.parse()`/`mermaid.render()`, but the directive is silently rejected for the blocked keys, causing the diagram to fail or render without the requested customization. This is a real gap in the built-in mermaid support; keeping open for the community process.

## Change summary

Mermaid diagrams using `%%{init: ...}%%` directives for theme/layout customization fail to render in the built-in markdown preview.

## Best solution

Investigate whether `mermaid.initialize()` in the built-in renderers (both `mermaid-markdown-features` and the markdown-editor mermaid path) should relax the `secure` array or adjust how it interacts with per-diagram directives. The fix likely lives in `extensions/mermaid-markdown-features/preview-src/shared/index.ts` (`buildMermaidConfig`) and/or `extensions/markdown-language-features/markdown-editor-src/editor.ts`. Consider allowing safe directive keys like `themeVariables` and flowchart layout options while keeping security-sensitive keys blocked.
