# Issue #331534 — "The PR workflow skill is unavailable in this checkout"

[https://github.com/microsoft/vscode/issues/331534](https://github.com/microsoft/vscode/issues/331534)

## Summary

Confirmed against current main: `AgentPluginManager._cleanupStaleNoncesFor` (src/vs/platform/agentHost/node/agentPluginManager.ts:218-228) deletes every non-current nonce directory for a plugin immediately after each sync, relying only on filesystem delete-failure as a proxy for in-use state — there is no lease/reference-count tying a materialized path to an active session. The existing unit test at agentPluginManager.test.ts:171-186 explicitly asserts the stale nonce directory is gone right after the new nonce syncs, matching the report precisely. This is a real, well-diagnosed race that can strand an active session's advertised skill path.

## Change summary

A synchronized-customization nonce directory an active Agent Host session is still using can be deleted the moment a new nonce is materialized, causing skill invocations to fail with ENOENT.

## Best solution

Implement the reporter's suggested fix: track explicit leases/reference counts per (plugin URI, nonce) acquired when a revision is handed to a session/provider and released on session disposal or revision switch, so `_cleanupStaleNoncesFor` only evicts unreferenced revisions; add the regression test the reporter proposes (retain nonce A's dir, sync nonce B, assert A still exists, release A, assert it becomes eligible for cleanup).
