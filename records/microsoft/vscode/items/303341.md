# Issue #303341 — Downloaded update lost on quit, triggers re-download

[https://github.com/microsoft/vscode/issues/303341](https://github.com/microsoft/vscode/issues/303341)

## Summary

Valid request: on macOS, quitting instead of restarting after an update downloads discards the update state, triggering a re-download on next launch. This is constrained by Electron's Squirrel.Mac auto-updater which only applies via quitAndInstall(). The request for smarter caching or apply-on-quit is reasonable but requires non-trivial work.

## Change summary

On macOS, quitting VS Code after an update is downloaded (instead of clicking 'Restart') loses the downloaded update and forces a re-download on next launch.

## Best solution

Persist the 'Ready' state and downloaded update reference across restarts so that on next launch, the service can skip re-downloading if the cached update is still valid. This would need changes in the abstract/darwin update service to store the pending update info in application storage and restore it during initialize(). Alternatively, hook into the quit path to apply the pending update automatically. Both approaches touch src/vs/platform/update/electron-main/abstractUpdateService.ts and updateService.darwin.ts.
