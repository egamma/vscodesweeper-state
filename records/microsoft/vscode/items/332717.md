# Issue #332717 — Copilot chat feedback

[https://github.com/microsoft/vscode/issues/332717](https://github.com/microsoft/vscode/issues/332717)

## Summary

Real, traceable bug in the Agents window's chat input: draft text for a new/unsent conversation is stored in a single shared memento (`_emptyInputState`) keyed only by view kind, not per session, so switching between two empty chats can silently overwrite one draft with the other's. A second commenter reports a related but distinct loss (entire session history missing after upgrading to 1.135) which needs separate investigation.

## Change summary

Text typed into a new/unsent chat is lost after opening another chat and returning to the first.

## Best solution

Key the empty-conversation draft persistence in ChatInputPart (chatInputPart.ts, `_emptyInputState`/`_getPersistedEmptyInputState`) per session resource instead of a single shared memento per view kind, so two concurrently open empty conversations don't clobber each other's drafts; this area is under active same-day work (see commit e782f88c) so coordinate with that effort before changing it.

## Evidence

- **restore path:** `_getPersistedEmptyInputState()` (line 1699) and `setInputModel` (line 1630-1636) load this same shared state for ANY session where `chatSessionIsEmpty` is true, so switching between two new/empty chats reads/writes the same slot and can overwrite the other's draft text.
