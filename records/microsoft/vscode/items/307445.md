# Issue #307445 — Carousel view should render within Chat at end of turn

[https://github.com/microsoft/vscode/issues/307445](https://github.com/microsoft/vscode/issues/307445)

## Summary

A real gap remains: current main provides a conversation-level artifact inventory above the chat input and a click-open image carousel, but no artifact collection rendered at the end of each turn. This maintainer-authored Backlog request should remain open for product design around per-turn versus conversation-wide presentation.

## Change summary

Render a collection of the artifacts produced by a chat turn directly after that turn, with images opening in the carousel.

## Best solution

Show a compact, accessible artifact collection immediately after each relevant completed response, preserving carousel activation for images and avoiding redundant presentation with the existing conversation-level artifact widget.

- **Reason:** Making agent-produced artifacts discoverable in the conversation advances the AI-assisted development theme while keeping outputs connected to the turn that produced them.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatArtifactsWidget.ts`, `src/vs/workbench/contrib/chat/common/tools/chatArtifactsService.ts`, `src/vs/workbench/test/browser/componentFixtures/chat/chatArtifacts.fixture.ts`
- **Validation:** Add a chat component fixture with two completed responses producing different artifacts and verify that each response shows the intended artifact set at its end, image activation opens the carousel, keyboard navigation and accessible labels work, and the conversation-level input widget follows the chosen coexistence behavior.
- **Behavior:**

  > When a completed chat turn produces artifacts, the artifacts are discoverable directly at the end of that turn. Images open in the existing carousel, and non-image artifacts retain their appropriate open behavior. Artifact controls must be keyboard-operable and screen-reader labeled. Two turns producing different artifacts must display the artifact scope selected by the maintainer without misleading duplication elsewhere in Chat.
- **Trace:**

  > ChatArtifactsService in src/vs/workbench/contrib/chat/common/tools/chatArtifactsService.ts currently derives one session-wide artifactGroups observable by scanning all requests. ChatArtifactsWidget in src/vs/workbench/contrib/chat/browser/widget/chatArtifactsWidget.ts consumes that observable, while ChatInputPart.renderArtifactsWidget() attaches it to the docked input stack. Individual responses are rendered by ChatListItemRenderer in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts, which currently has no artifact content part at the end of a turn. ChatImageCarouselService already owns image collection and click-to-carousel behavior and should remain the activation path. Preserve existing inline-image rendering and do not fold in the separate live-refresh work tracked by https://github.com/microsoft/vscode/issues/302008.
- **Open decisions:**
  - Should an end-of-turn collection contain only artifacts produced by that turn, or the cumulative conversation artifact set as of that turn?
  - Should the end-of-turn collection supplement the existing conversation-level artifact widget above the input, or replace that widget to avoid duplicate artifact surfaces?

## Evidence

- **current artifact surface:** src/vs/workbench/contrib/chat/browser/widget/chatArtifactsWidget.ts derives artifacts from a session resource and renders a conversation-wide tree; src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts attaches that widget to the docked chat input stack through renderArtifactsWidget(), not to an individual response turn.
- **session-wide data model:** src/vs/workbench/contrib/chat/common/tools/chatArtifactsService.ts scans every request in the chat model and exposes combined session-level artifactGroups; it does not expose a turn-bound rendered response part.
- **carousel behavior:** src/vs/workbench/contrib/chat/browser/chatImageCarouselService.ts opens the carousel only after an image resource is activated and collectCarouselSections() gathers images across chat items; it does not render an artifact gallery at response completion.
