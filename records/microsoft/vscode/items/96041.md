# Issue #96041 — unable to input chinese character

[https://github.com/microsoft/vscode/issues/96041](https://github.com/microsoft/vscode/issues/96041)

## Summary

Long-standing snap-specific IME input bug — the snap packaging includes ibus/fcitx immodule setup (electron-launch lines 263–272) and stages libibus-1.0-5, but the sandboxed environment still cannot reliably communicate with the host's input method framework. Still reproduces per multiple confirmations; the `help wanted` label signals the team acknowledges it but hasn't found a viable fix within snap's constraints.

## Change summary

Chinese (and other CJK/IME-based) character input does not work in the VS Code snap package on Linux, while .deb and .tar.gz distributions work fine.

## Best solution

Investigate whether upgrading to core22 (or core24) and adopting the content-interface approach for GTK/ibus libraries resolves the toolkit version mismatch that prevents IME communication. The fix lives in `resources/linux/snap/` — specifically the base, stage-packages, and the immodule wiring in `electron-launch`. Alternatively, moving the snap to use the Wayland input-method protocol (when available) may bypass the GTK immodule issue entirely.
