# Issue #332973 — Show session has copilot comments / CI failures as OS notification or in command center

[https://github.com/microsoft/vscode/issues/332973](https://github.com/microsoft/vscode/issues/332973)

## Summary

Current source already surfaces eligible CI failures in the session title-bar indicator, but pending Copilot review comments are not included and the OS notifiers do not observe either condition directly. Keep this team-authored request open for the remaining discoverability work; no verified canonical or issue-referencing fix establishes completion.

## Change summary

Surface pending Copilot comments and CI failures outside the individual session so users can discover available follow-up actions without opening it.

## Best solution

Extend the existing session-attention experience to expose actionable review comments alongside CI failures, with a maintainer decision on whether OS notifications are also wanted. Preserve existing suppression for work already being handled by Agent Merge.

Check that existing CI indicators remain intact, handled Agent Merge work stays suppressed, and any OS notification follows the agreed focus and deduplication policy.
- **Behavior:**

  > Users should discover that a session has pending Copilot review comments or failing CI without first selecting that session. Current title-bar behavior already covers eligible CI failures, but review comments remain discoverable through the active session's banners. Acceptance should demonstrate pending feedback becoming visible while another session is active, clearing when addressed, and not repeatedly demanding attention for work already being handled automatically. Whether that discovery uses the command center, OS notifications, or both remains to be decided.
- **Trace:**

  > BlockedSessions in src/vs/sessions/contrib/blockedSessions/browser/blockedSessions.ts derives NeedsInput and FailingCI conditions, and BlockedSessionsIndicatorModel feeds those into SessionsTitleBarWidget. Review feedback is instead consumed by SessionInputBanners in src/vs/sessions/contrib/sessionInputBanners/browser/sessionInputBanners.ts, gated to the active completed session and separated into PRReview and AgentReview items. SessionsWindowNotifier observes session-status transitions rather than review or CI state; ChatWindowNotifier similarly handles input requests and completed responses. Preserve existing Agent Merge suppression and notification correlation rather than treating every background change as a new alert. https://github.com/microsoft/vscode/issues/325362 contains related attention-indicator design discussion but does not settle this request's remaining surface choice.
- **Open decisions:**
  - Should pending review comments be surfaced through the existing command-center attention indicator, OS notifications, or both, and should OS alerts also cover CI failures already represented by that indicator?

## Evidence

- **Existing CI capability:** src/vs/sessions/contrib/blockedSessions/browser/blockedSessions.ts defines NeedsInput and FailingCI reasons. Its _getFailingCISession detects failed CI on open, non-draft pull requests, excluding archived or in-progress sessions and failures handled by Agent Merge. src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts consumes BlockedSessionsIndicatorModel, whose getRequiresInputLabel includes '1 session is failing CI'. This partially satisfies the request without opening a session.
- **Remaining review-comment gap:** BlockedSessions has no review-comment reason. src/vs/sessions/contrib/sessionInputBanners/browser/sessionInputBanners.ts derives actionable PR-review and AgentReview feedback, but its _session observable requires the active, completed session.
