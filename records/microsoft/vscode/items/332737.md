# Issue #332737 — Local history: first save after reload duplicates an entry instead of merging within the merge window

[https://github.com/microsoft/vscode/issues/332737](https://github.com/microsoft/vscode/issues/332737)

## Summary

Confirmed on main: `WorkingCopyHistoryModel.addEntry` reads `this.entries.at(-1)` without awaiting `resolveEntriesOnce()` first, unlike its sibling methods (`removeEntry`, `updateEntry`, `getEntries`), so a freshly constructed model (empty `entries` until resolved) always misses the merge-window replacement on the first save after reload. A PR is already open to fix this, so it should be reviewed/landed rather than the issue closed now.

## Change summary

First save after a window reload creates a duplicate local-history entry instead of merging into the previous one within the configured merge window, because addEntry doesn't await pending entry resolution before checking the last entry.

## Best solution

Land https://github.com/microsoft/vscode/pull/332738 (or an equivalent fix) that awaits `resolveEntriesOnce()` in `addEntry` before computing `lastEntry`, mirroring `removeEntry`/`updateEntry` in src/vs/workbench/services/workingCopy/common/workingCopyHistoryService.ts.
