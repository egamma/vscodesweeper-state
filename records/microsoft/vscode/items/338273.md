# Issue #338273 — /remote on fails in Agent Host Copilot session with "Failed to get authentication token" (works in standalone Copilot CLI)

[https://github.com/microsoft/vscode/issues/338273](https://github.com/microsoft/vscode/issues/338273)

## Summary

Two independent reporters (Windows and RHEL, different accounts/subscriptions) confirm `/remote on` fails in an Agent Host Copilot session with 'Failed to get authentication token', while the standalone Copilot CLI works in the same folder/account — a second reporter pins the regression to the 1.139.1 update. This is a real, reproducible defect, but the failing call (`session.rpc.commands.invoke` handling the `remote` command) executes inside the `@github/copilot-sdk` runtime, whose source isn't in this checkout, so I can't trace the exact fault line from code alone.

## Change summary

`/remote on` in an Agent Host Copilot chat session fails with an authentication-token error, even though the session is otherwise authenticated to GitHub and the same feature works in the standalone Copilot CLI.

## Best solution

A Copilot Chat/Agent Host engineer should diagnose whether VS Code's GitHub credential threading (`CopilotAgent.updateGitHubCredentials`/`gitHubAuth.setCredentials` in src/vs/platform/agentHost/node/copilot/copilotAgent.ts and copilotAgentSession.ts) supplies the token/host the SDK's remote-control command needs, or whether the regression is inside `@github/copilot-sdk`'s own remote-command auth path (version 1.0.15 per both reports) — coordinate with the SDK owners given the reporter's github/copilot-cli#4954 comparison.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`
- **Validation:** A manual repro: enable github.copilot.chat.cli.remote.enabled, start an Agent Host Copilot session, run /remote on, and confirm it succeeds (matching standalone Copilot CLI behavior) with the token flow that turns out to be correct.
- **Behavior:**

  > In a Copilot chat session running on the Agent Host, sending `/remote on` should enable remote control (create a linked GitHub task page) the same way it does in the standalone Copilot CLI with the same account and folder. Currently it fails immediately with 'Failed to get authentication token', even though the session is already authenticated to api.github.com for normal chat use. Acceptance: `/remote on` succeeds in an Agent Host session under the same conditions where standalone `copilot --remote` succeeds.
- **Trace:**

  > The failure surfaces from `session.rpc.commands.invoke({name:'remote', input:'on'})` inside CopilotAgentSession.sendTurn (src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts around line 3429-3448); the SDK's own error message is re-thrown after stripping the 'Request session.commands.invoke failed with message: ' prefix. GitHub token propagation to the SDK runtime goes through CopilotAgent's onDidChangeSessions handler (copilotAgent.ts:2016-2042), which calls CopilotAgentSession.updateGitHubCredentials → session.rpc.gitHubAuth.setCredentials (copilotAgentSession.ts:2831). Where the uncertainty starts: whether the token/host passed there is what the SDK's remote-control command internally requires (it may need a differently-scoped token or a distinct auth flow that only the standalone CLI's `gh` credential satisfies), or whether this is purely an upstream regression in @github/copilot-sdk 1.0.15 unrelated to what VS Code supplies. That determination requires access to the SDK's remote-command implementation, which isn't in this checkout. Do not change unrelated credential-update paths (MCP auth, Copilot SKU resolution) while investigating.
- **Open decisions:**
  - Does the remote-control command need a different/differently-scoped GitHub token than the one VS Code currently threads through gitHubAuth.setCredentials, or is the regression entirely inside the SDK's remote-command handling?
  - Is this fixable in VS Code's copilotAgent.ts credential-threading code, or does it require an upstream @github/copilot-sdk fix and a dependency bump?
