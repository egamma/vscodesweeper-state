# Issue #300873 — `Chat: Review` command silently does nothing when active file has not been pushed to remote

[https://github.com/microsoft/vscode/issues/300873](https://github.com/microsoft/vscode/issues/300873)

## Summary

Thanks for the report. Keeping this open: on current main the no-selection `github.copilot.chat.review` path can still exit with no feedback. In the source, the trigger is not whether the file was pushed. It is the enclosing-scope picker returning undefined, for example when the file has no DocumentSymbol provider.

## Change summary

Running Chat: Review with no selection sometimes does nothing and shows no message, when the reporter expects it to start reviewing the current file.

## Best solution

In ReviewSession.review (extensions/copilot/src/extension/review/node/doReview.ts), stop returning silently when no selection or scope can be resolved. Either fall back to reviewing the whole current file with a 'Reviewing current file…' progress notification, or at least tell the user why nothing happened.

Explicit selections and an explicit dismissal of the scope quick pick behave as decided below.
- **Trace:**

  > Entry point: inlineChatCommands.ts:267 → ReviewSession.review('selection') in extensions/copilot/src/extension/review/node/doReview.ts. resolveSelection calls IScopeSelector.selectEnclosingScope (scopeSelectionImpl.ts) when the selection is empty. That call returns undefined when there are no DocumentSymbols, when the provider returns SymbolInformation[], or when the selection is already non-empty, and it throws a CancellationError on quick-pick dismissal. review() then returns undefined before executeWithProgress, so no notification appears. The review path never checks the remote, so the 'unpushed' trigger is a red herring. Do not change the diff-based review groups (index/workingTree/all) or githubReview's request shape for real selections. Existing doReview.spec.ts tests around lines 500-640 cover the selection paths.
- **Open decisions:**
  - With no selection, should Chat: Review always review the whole current file (dropping the enclosing-scope quick pick), or keep the picker and fall back to the whole file only when no scope resolves?
