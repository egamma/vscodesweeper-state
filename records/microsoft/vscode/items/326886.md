# Issue #326886 — GitHub Copilot extension can't be re-enabled via the Extensions window after disabling it

[https://github.com/microsoft/vscode/issues/326886](https://github.com/microsoft/vscode/issues/326886)

## Summary

The dead state remains source-reproducible on current main: the Extensions context menu substitutes AI-specific actions for the default chat extension, but neither enable action is available after the extension itself was disabled while `chat.disableAIFeatures` remains false. This team-authored, accepted bug should remain open for a bounded fix.

## Change summary

Re-enable the built-in GitHub Copilot Chat extension from its Extensions view after it was disabled through another extension-management surface.

## Best solution

The Copilot Chat extension's management menu should always provide an action that restores the extension's actual enablement state, independently of whether AI was disabled through `chat.disableAIFeatures`, without requiring Enable All Extensions.

- **Trace:**

  > ManageExtensionAction in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts detects the product's default chat extension and substitutes the AI-specific action groups for EnableGloballyAction and EnableForWorkspaceAction.
