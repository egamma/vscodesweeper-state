# Issue #326886 — GitHub Copilot extension can't be re-enabled via the Extensions window after disabling it

[https://github.com/microsoft/vscode/issues/326886](https://github.com/microsoft/vscode/issues/326886)

## Summary

Traced in current main: EnableGloballyAction/DisableGloballyAction deliberately no-op for the Copilot (chat) extension, routing enable/disable through the 'AI Features' actions instead — but those only flip the chat.disableAIFeatures setting, not the extension's real EnablementState. If Copilot ends up DisabledGlobally by some other path (e.g. Show Running Extensions), no UI action can flip it back, exactly as reported.

## Change summary

After disabling the GitHub Copilot extension globally (e.g. via Show Running Extensions) and reloading, the Extensions view offers no working way to re-enable it, and a confusingly-enabled 'Disable AI Features' option is shown alongside it.

## Best solution

In src/vs/workbench/contrib/extensions/browser/extensionsActions.ts, reconcile the two enablement mechanisms for the chat extension: either let EnableGloballyAction become enabled when the chat extension is DisabledGlobally (not just via the AI-features setting), or have EnableAIFeaturesGloballyAction/DisableAIFeaturesGloballyAction also account for and correct the raw EnablementState so 'Enable AI Features' actually clears a stray DisabledGlobally state.
