# Issue #137401 — "Keybinding" shown is misleading for Ctrl-modified keyboard layouts (like Dvorak+QWERTY)

[https://github.com/microsoft/vscode/issues/137401](https://github.com/microsoft/vscode/issues/137401)

## Summary

The misleading labels and merged search results remain source-reproducible on current main. The issue is correctly routed to the Windows keyboard-layout backlog, and no broader open issue was found that owns this distinct display-and-search defect.

## Change summary

Make keybinding labels, recording feedback, chord display, and exact searches correctly represent layouts that switch to QWERTY while Ctrl is held.

## Best solution

Make Windows keybinding presentation and matching modifier-aware for layouts such as Dvorak+QWERTY, while preserving the existing dispatch and serialized keybinding representation. The likely boundary is WindowsKeyboardMapper label resolution together with KeybindingsEditorModel's matching of UI and user-settings labels.

## Evidence

- **source reproduction:** src/vs/workbench/services/keybinding/common/windowsKeyboardMapper.ts constructs labels through WindowsNativeResolvedKeybinding._getLabel and WindowsKeyboardMapper.getUILabelForKeyCode using only the keyCode; the chord's Ctrl state is not considered. resolveKeyboardEvent preserves Ctrl on the chord but cannot alter that label lookup.
- **recording path:** src/vs/workbench/contrib/preferences/browser/keybindingWidgets.ts records the user-settings label but renders the same resolved keybinding through KeybindingLabel, reproducing the reported disagreement between the input text and the styled label.
- **search path:** src/vs/workbench/services/preferences/browser/keybindingsEditorModel.ts treats an exact match against any of getUserSettingsLabel(), getAriaLabel(), or getLabel() as a result. When modifier-independent layout labels disagree with the Ctrl/QWERTY user-settings identity, a query such as ctrl+j therefore combines both sets described in the report.
- **mapping limitation:** IWindowsKeyMapping in src/vs/platform/keyboardLayout/common/keyboardLayout.ts contains value, Shift, AltGr, and Shift+AltGr variants, but no Ctrl-specific value, so the current mapper cannot directly represent a layout whose character mapping changes only while Ctrl is held.
- **canonical search:** https://github.com/microsoft/vscode/issues/187128 remains open but concerns incorrect shortcut dispatch on Linux/QWERTZ, while https://github.com/microsoft/vscode/issues/169826 concerns macOS Dvorak-QWERTY command dispatch. Neither owns this Windows keybinding-label and search-result defect.
