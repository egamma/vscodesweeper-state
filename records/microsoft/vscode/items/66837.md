# Issue #66837 — Windows uninstaller should have option to also remove user data dir and extensions dir

[https://github.com/microsoft/vscode/issues/66837](https://github.com/microsoft/vscode/issues/66837)

## Summary

The Windows uninstaller still lacks the requested optional removal of user data and extensions; documented manual cleanup does not provide that capability. Keep this accepted Backlog request open, while considering the later maintainer preference for documentation before commissioning implementation.

## Change summary

Add an opt-in Windows uninstall option to remove user data and installed extensions while preserving them by default.

## Best solution

Decide whether Windows should offer an explicit destructive-cleanup option despite the later documentation-only position on factory reset. If approved, preserve ordinary uninstall behavior and define exactly whose data and which installation-specific directories the option removes.

## Plan brief

- **Likely files:** `build/win32/code.iss`, `build/win32/i18n/messages.en.isl`
- **Validation:** On disposable Windows user accounts, install Stable and Insiders, add distinct settings and extensions, then uninstall each with cleanup declined and accepted. Verify default preservation, approved cleanup scope, cancellation behavior, and preservation of the other channel's data; repeat for User and System installers, including elevation under a different account.
- **Behavior:**

  > Users who want a clean reinstall currently must locate and delete retained data manually after Windows uninstall. The requested outcome is an explicit opt-in uninstall choice covering user data and extensions, with ordinary uninstall continuing to retain them. Acceptance must demonstrate that the selected cleanup affects only the approved user and installation scope and that declining or cancelling cleanup preserves existing data.
- **Trace:**

  > build/win32/code.iss owns the Windows installer and uninstaller for both User and System installations. Its [UninstallDelete] section targets application-directory remnants, and CurUninstallStepChanged handles shell integration and PATH cleanup without a user-data removal choice. The CLI directory-selection options in src/vs/platform/environment/node/argv.ts and the manual instructions at https://code.visualstudio.com/docs/setup/uninstall do not implement this UI request. The original thread accepted optional cleanup, but https://github.com/microsoft/vscode/issues/127726#issuecomment-872181689 later favored documentation for full uninstall, so product approval is not settled. The related directory-layout work at https://github.com/microsoft/vscode/issues/3884 is not a prerequisite proven by the source. Preserve default retention and avoid broadening this into cross-platform factory reset or extension-uninstall garbage collection.
- **Open decisions:**
  - Should Windows offer opt-in data removal, or should the later documentation-only position also govern this previously accepted request?
  - If approved, is cleanup limited to the uninstalling user's standard directories for that release channel, or does it also cover custom directories, shared state, or other users under a System installation?
