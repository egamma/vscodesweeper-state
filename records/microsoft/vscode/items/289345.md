# Issue #289345 — Agents: globally unique URIs

[https://github.com/microsoft/vscode/issues/289345](https://github.com/microsoft/vscode/issues/289345)

## Summary

Valid architectural concern about session URI global uniqueness for state roaming. The `important` label bars a close, and the issue remains actionable — current URI construction (`provider:/<rawSessionId>`) relies on `rawSessionId` being globally unique, which is not guaranteed for all providers (particularly cloud sessions).

## Change summary

Ensure session resource URIs are globally unique across workspaces, profiles, and machines so that per-session state (read/unread, archived) can roam without collisions.

## Best solution

Audit and fix the session URI scheme so that `AgentSession.uri()` (in `src/vs/platform/agentHost/common/agentService.ts`) and the Copilot chat session resource construction (in `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`) produce globally unique URIs — likely by incorporating the cloud task ID or a UUID. The `toSessionId()` helper in `src/vs/sessions/services/sessions/common/session.ts` that concatenates `providerId:resourceUri` should also be verified for uniqueness across machines.
