# Issue #163586 — Add individual folder select on compressed folders for search tree

[https://github.com/microsoft/vscode/issues/163586](https://github.com/microsoft/vscode/issues/163586)

## Summary

Keep open: Search still lacks Explorer-style selection of individual folders within a compressed path. Existing folder actions do not cover that selection gap, and no verified older canonical was found.

## Change summary

Allow individual folders within compressed Search result paths to be selected and targeted by folder-based actions.

## Best solution

Provide Explorer-consistent segment selection in the Search tree, with mouse and keyboard targeting reflected in folder context actions and accessible focus. Preserve compressed presentation and existing whole-row selection behavior.

## Evidence

- **Current Search selection gap:** src/vs/workbench/contrib/search/browser/searchResultsView.ts:192–207, FolderMatchRenderer.renderCompressedElements, renders names for every compressed segment but associates the resource and folder details with the final folder. It does not establish individual-segment selection.
- **Action targeting:** src/vs/workbench/contrib/search/browser/searchView.ts:1091–1111, SearchView.onContextMenu, forwards the tree event element and current selection without resolving a clicked compressed-path segment.
- **Existing Explorer capability:** src/vs/workbench/contrib/files/browser/views/explorerViewer.ts:715–749 and 921–960 implements CompressedNavigationController, per-segment accessibility state, and mouse targeting through setIndex(result.index). Search's compressed renderer lacks the corresponding interaction layer.
- **Related actions do not complete this request:** https://github.com/microsoft/vscode/issues/162628 and https://github.com/microsoft/vscode/issues/161864 are closed requests for Exclude Folder from Search and Find in Folder. Those actions exist in src/vs/workbench/contrib/search/browser/searchActionsFind.ts, but their availability does not make intermediate compressed folders selectable.
- **Canonical and existing-setting check:** Open-issue searches for compressed Search paths, compact folders, and folder selection found no verified older issue owning this capability. https://github.com/microsoft/vscode/issues/301832 requests disabling Search folder compression; it is newer and addresses a different observable behavior. Disabling compression would not deliver individual selection while retaining compressed paths.
- **Accepted maintainer request:** https://github.com/microsoft/vscode/issues/163586 is MEMBER-authored and accepted into Backlog. Current source demonstrates a remaining capability gap, not a factual basis for closing it.
