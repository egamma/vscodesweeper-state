# Issue #280852 — `ctrl` activates hover on macOS when hover is set to `onKeyboardModifier`

[https://github.com/microsoft/vscode/issues/280852](https://github.com/microsoft/vscode/issues/280852)

## Summary

The macOS modifier mismatch remains in current source. Keep this open while the explicitly linked, still-open fixing PR is reviewed; it is not a completed fix.

## Change summary

With modifier-only hover enabled and the multi-cursor modifier set to Alt, macOS incorrectly accepts Control as well as Command.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/309138 so hover uses Command on macOS and Control on Windows/Linux, while preserving Alt/Option activation when multi-cursor uses ctrlCmd.

- **Affected execution paths:** src/vs/editor/contrib/hover/browser/contentHoverController.ts:258–280 and src/vs/editor/contrib/hover/browser/glyphHoverController.ts:179–211 use shouldShowHover for mouse movement and isTriggerModifierPressed for keyboard handling, exposing the same mismatch in both hover controllers.
- **Intended platform behavior:** src/vs/editor/common/config/editorOptions.ts:2416 documents Command on macOS versus Control elsewhere for modifier-only hover; _multiCursorModifierFromString at lines 3629–3633 likewise resolves ctrlCmd to metaKey on macOS and ctrlKey elsewhere.
