# Issue #298401 — After updating to the latest version of VS Code, the coding process has become extremely laggy, and memory usage spikes dramatically.

[https://github.com/microsoft/vscode/issues/298401](https://github.com/microsoft/vscode/issues/298401)

## Summary

Keep open: multiple users confirmed severe extension-host CPU and memory growth when C/C++ Copilot hover calls `vscode.lm.selectChatModels` in remote environments. The extension-side mitigation reduces the trigger frequency, but it does not establish that the underlying VS Code API behavior is resolved, and the previously proposed core fix was independently refuted.

## Change summary

Prevent language-model selection from entering a high-frequency model-resolution loop that makes Remote-WSL editing lag and sharply increases resource usage.

## Best solution

Reproduce the interaction on current main with a remote extension host and determine whether repeated `selectChatModels` calls remain bounded when Copilot models are unavailable or hosted in another extension host. Preserve normal model discovery and change notifications while ensuring a missing remote model cannot produce an unbounded retry or event-feedback loop.

## Evidence

- **confirmed trigger:** The maintainer comments on https://github.com/microsoft/vscode/issues/298401 report that three users stopped the resource problem by disabling `C_Cpp.copilotHover`, which prevents the extension from calling `vscode.lm.selectChatModels`; the reporter also confirmed the leak disappeared with that workaround.
- **independent confirmation:** https://github.com/microsoft/vscode-cpptools/issues/14241 records repeated `LanguageModelProxy` missing-model warnings, sustained extension-host CPU usage, and another user who reproduced the behavior; the VS Code issue https://github.com/microsoft/vscode/issues/299689 later recorded the same warning storm with both C/C++ and Python callers.
- **extension mitigation:** https://github.com/microsoft/vscode-cpptools/pull/14327 was merged to cache the selected model instead of calling `selectChatModels` on every hover. That reduces calls from C/C++ but is a caller-side mitigation, not proof that the core API path is safe for other extensions.
- **current source path:** Current main routes selection through `ExtHostLanguageModels.selectLanguageModels` in src/vs/workbench/api/common/extHostLanguageModels.ts and `$selectChatModels` in src/vs/workbench/api/browser/mainThreadLanguageModels.ts; cross-extension-host model availability and model-change events remain the relevant boundary to verify.
