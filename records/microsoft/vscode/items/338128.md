# Issue #338128 — Windows emojis aren't registering in VS Code following the latest update.

[https://github.com/microsoft/vscode/issues/338128](https://github.com/microsoft/vscode/issues/338128)

## Summary

Multiple independent Windows users confirm a regression between 1.138 and 1.139.1 where the OS emoji picker's synthetic keystrokes stop being inserted into the editor/chat input (clipboard paste still works). This was already reviewed and kept open; I could not pin an exact fix commit or root-cause line from the checkout (shallow history, no diff between 1.138 and 1.139.1 available), so it stays open pending diagnosis.

## Change summary

Windows' Win+. emoji picker intermittently or progressively fails to insert emojis into VS Code text inputs after upgrading to 1.139.1, while other apps and clipboard paste are unaffected.

## Best solution

Bisect the synthetic-keystroke insertion path in the native edit context (textupdate handling in src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts and the textArea fallback in .../textArea/textAreaEditContextInput.ts) between 1.138 and 1.139.1 to find what changed for non-clipboard, non-IME synthetic insertion (the emoji picker's insertion mechanism), then restore correct handling without breaking real IME composition or surrogate-pair handling.
