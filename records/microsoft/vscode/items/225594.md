# Issue #225594 — `Load More Stack Frames` renders poorly when horizontalScrolling enabled

[https://github.com/microsoft/vscode/issues/225594](https://github.com/microsoft/vscode/issues/225594)

## Summary

Confirmed visual defect with horizontal scrolling enabled: the load-more row is centered within the horizontally scrollable content width, so long stack-frame labels can move it outside the visible Debug view. The report remains necessary because no existing issue owns this exact symptom and the current discussion confirms the configuration-specific reproduction.

## Change summary

Keep the Load/Show More Stack Frames control visible by centering it against the Debug panel viewport rather than the widest horizontally scrollable stack-frame row.

## Best solution

Adjust the debug call-stack load-more row so its label remains centered in the visible tree viewport while ordinary stack-frame rows retain horizontal scrolling.

Acceptance should cover both load-more label variants in a narrow viewport with over-wide frame content.
- **Trace:**

  > The issue and maintainer exchange isolate the failure to the workbench list horizontal-scrolling mode: long call-stack rows expand the scrollable content width, and the special load-more row is then centered against that content rather than the visible panel. The likely rendering path is the call-stack tree renderer in `src/vs/workbench/contrib/debug/browser/callStackView.ts` together with its styles in `src/vs/workbench/contrib/debug/browser/media/debug.css`. The boundary is the special load-more presentation; do not disable horizontal scrolling or alter ordinary frame-label sizing. https://github.com/microsoft/vscode/issues/164957 is related only by control name and tracks stale visibility after the full stack arrives, not this layout symptom.
