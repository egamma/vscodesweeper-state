# Issue #144216 — Cannot open menu via shortcut when activity bar is hidden

[https://github.com/microsoft/vscode/issues/144216](https://github.com/microsoft/vscode/issues/144216)

## Summary

The bug remains source-reproducible on current main: compact mode mounts the menu inside the Activity Bar, while the global Alt+letter handler still targets that menu after the Activity Bar is hidden. A maintainer has already suggested handling this case, so the accepted bug should remain open pending a decision about where the invoked menu appears.

## Change summary

Alt+letter menu shortcuts do nothing when compact menu mode is enabled and the Activity Bar containing the menu is hidden.

## Best solution

Keep Alt+letter mnemonics functional when the compact menu's Activity Bar host is hidden, without changing the user's persisted Activity Bar visibility unexpectedly. The work belongs in the Activity Bar/menu-bar integration, with a maintainer choosing whether invocation temporarily reveals the bar or presents the menu from another visible anchor.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/activitybar/activitybarPart.ts`, `src/vs/workbench/browser/parts/titlebar/menubarControl.ts`, `src/vs/base/browser/ui/menu/menubar.ts`, `src/vs/workbench/test/browser/parts/activitybar/activitybarPart.test.ts`
- **Validation:** With `window.menuBarVisibility` set to `compact` and the Activity Bar hidden, press Alt+F on Windows and verify that the File menu becomes usable; repeat with another mnemonic, then confirm the chosen Activity Bar visibility semantics and that compact mode remains unchanged while the bar is visible.
- **Behavior:**

  > When compact menu mode is active, hiding the Activity Bar must not make application-menu mnemonics such as Alt+F stop working. Invoking a mnemonic must expose the requested menu in a usable position. Normal compact-menu behavior with a visible Activity Bar and the user's persisted visibility preference must remain intact.
- **Trace:**

  > ActivitybarPart in src/vs/workbench/browser/parts/activitybar/activitybarPart.ts creates CustomMenubarControl inside the Activity Bar whenever `window.menuBarVisibility` is `compact`. The workbench layout can hide that entire part independently in src/vs/workbench/browser/layout.ts. MenuBar in src/vs/base/browser/ui/menu/menubar.ts still receives the window-level Alt+letter event and calls `onMenuTriggered`, but its visual anchor remains inside the hidden part. The same hidden-side-Activity-Bar symptom was later confirmed in https://github.com/microsoft/vscode/issues/201613, while that issue also covers a distinct top-position layout case. Preserve mnemonic behavior for visible menu bars and do not broaden the work to that separate positioning defect.
- **Open decisions:**
  - When an Alt+letter mnemonic is invoked while the compact menu's Activity Bar host is hidden, should VS Code temporarily reveal the Activity Bar or present the menu from another visible anchor while leaving the bar hidden?
