# Issue #173742 — Make tree find controls more discoverable

[https://github.com/microsoft/vscode/issues/173742](https://github.com/microsoft/vscode/issues/173742)

## Summary

The discoverability gap remains on current main: custom tree views support keyboard-invoked Find, but `TreeViewOptions` has no equivalent to `showCollapseAll` for exposing a correctly targeted title action. This team-authored backlog request has continued extension-author feedback and no verified older canonical, so it should remain open.

## Change summary

Let custom tree views expose a Find control in the view title so users can discover and invoke tree filtering without first focusing the tree and knowing its shortcut.

## Best solution

Define the intended product behavior for a generic tree Find affordance, then carry an opt-in or automatic capability through the TreeView extension API and render a localized, accessible view-title action that focuses and opens Find on the originating tree.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTreeViews.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadTreeViews.ts`, `src/vs/workbench/browser/parts/views/treeView.ts`, `src/vs/workbench/api/test/browser/mainThreadTreeViews.test.ts`
- **Validation:** Add API/main-thread tree-view tests proving the chosen capability shows a Find title action only for eligible views and that invoking it focuses and opens Find on that exact tree; verify existing Collapse All behavior remains unchanged.
- **Behavior:**

  > Users can discover tree Find from an eligible custom tree view without knowing a shortcut or focusing the tree first. Invoking the view-title action opens Find on that exact tree, never another previously focused list. Views that do not support Find must not show an unusable action, and keyboard invocation must continue to work. The icon-only action needs a localized accessible label.
- **Trace:**

  > Current `TreeViewOptions` in src/vscode-dts/vscode.d.ts exposes `showCollapseAll` but no Find equivalent. That option flows through ExtHostTreeViews.createTreeView in src/vs/workbench/api/common/extHostTreeViews.ts, MainThreadTreeViewsShape in src/vs/workbench/api/common/extHost.protocol.ts, and MainThreadTreeViews.$registerTreeViewDataProvider in src/vs/workbench/api/browser/mainThreadTreeViews.ts before TreeView registers its view-title action in src/vs/workbench/browser/parts/views/treeView.ts. The existing `list.find` command in src/vs/workbench/browser/actions/listCommands.ts acts on `IListService.lastFocusedList`, which explains the wrong-view behavior described in https://github.com/microsoft/vscode/issues/173742#issuecomment-3059745456. Preserve existing keyboard Find, Find mode semantics, and Collapse All behavior; the unresolved boundary is whether discoverability is extension-controlled or automatic for all find-capable trees.
- **Open decisions:**
  - Should the Find title action be an explicit `TreeViewOptions` opt-in like `showCollapseAll`, or appear automatically for every tree that advertises Find support?
  - Is this request limited to opening the existing Find widget, or should the public contract also let extensions prefill the query and control match/filter options?

## Evidence

- **current API gap:** On current main, src/vscode-dts/vscode.d.ts defines `TreeViewOptions.showCollapseAll` but no `showFindControl` or comparable Find affordance option.
- **extension-host path:** src/vs/workbench/api/common/extHostTreeViews.ts, src/vs/workbench/api/common/extHost.protocol.ts, and src/vs/workbench/api/browser/mainThreadTreeViews.ts transport and apply `showCollapseAll`, but transport no corresponding tree Find capability.
- **existing command limitation:** src/vs/workbench/browser/actions/listCommands.ts implements `list.find` against `IListService.lastFocusedList`; it does not identify or focus the tree whose view-title action was invoked.
- **existing title-action pattern:** src/vs/workbench/browser/parts/views/treeView.ts registers per-view Refresh and Collapse All title actions using view-specific context keys, but has no analogous Find action.
- **maintainer and extension-author demand:** The maintainer comment at https://github.com/microsoft/vscode/issues/173742#issuecomment-1535992495 cites consistent extension-author feedback, while https://github.com/microsoft/vscode/issues/173742#issuecomment-3059745456 documents why extensions cannot implement a reliable generic button with the current focus and command context.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/115641 is a broad new-user design exploration and does not report the same tree Find symptom or own this extension API work; no matching open canonical was found.
