# Issue #20266 — Offline spell checker for VSCode

[https://github.com/microsoft/vscode/issues/20266](https://github.com/microsoft/vscode/issues/20266)

## Summary

Keep this accepted, well-supported request open: current editor code does not provide the requested built-in offline spellchecking capability. Existing extensions mitigate the original limitations, but the platform-service and extension-API questions remain unresolved.

## Change summary

Provide efficient offline spellchecking across platforms without requiring extension authors to maintain Electron-version-specific native binaries.

## Best solution

Define a supported offline spellchecking service and its extension-facing contract, keeping language-specific parsing and specialized dictionary behavior extensible. Decide whether that service also provides a built-in editor experience, with explicit performance and distribution constraints.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts`, `src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** The plan should define a runnable acceptance scenario that checks an English and Polish document while disconnected, obtains correction suggestions, and verifies that an Electron upgrade does not require rebuilding an installed consumer extension. For the agreed editor scope, check Markdown and code-comment handling, custom words, and responsiveness with a large dictionary; establish measurable resource limits before implementation.
- **Behavior:**

  > Users need reliable offline spellchecking without excessive dictionary expansion or extension failures after Electron upgrades. Extension authors should be able to consume the supported capability without maintaining VS Code-version-specific native binaries. Acceptance should demonstrate offline word checking and suggestions with English and Polish dictionaries on the agreed supported platforms, while preserving editor responsiveness. Whether VS Code supplies a built-in editor experience in addition to the shared capability remains a product decision.
- **Trace:**

  > Current desktop window defaults disable Electron spellchecking in src/vs/platform/windows/electron-main/windows.ts, and both editor input implementations disable DOM spellchecking in textAreaEditContext.ts and nativeEditContext.ts. Searches found no existing shared spellchecking API in the extension API implementation or src/vscode-dts declarations; Electron availability alone therefore does not establish adoption on the reported editor path. The full investigation at https://github.com/microsoft/vscode/issues/20266#issuecomment-288271306 establishes performance isolation and cross-platform dictionary differences but leaves the public experience unresolved. Spell Right and Code Spell Checker are meaningful alternatives described in the thread, not proof that the requested platform contract exists. Preserve language-aware extension behavior and existing editor input, accessibility, and composition semantics; merely enabling browser spellchecking would not establish the requested service. The listed files identify inspected integration boundaries, not a complete implementation footprint.
- **Open decisions:**
  - Should VS Code provide an extension-consumable offline spellchecking service only, or also a built-in editor experience, and which document surfaces are included?
  - Which platforms and execution environments must the public capability support, including remote extension hosts and VS Code for the web?
  - Which dictionary-selection and custom-word semantics are guaranteed across platforms, and which dictionaries must be available without a network connection?
