# Issue #349279 — Agents: Support volume-based Dev Containers

[https://github.com/microsoft/vscode/issues/349279](https://github.com/microsoft/vscode/issues/349279)

## Summary

Keep open: current source explicitly drops volume-backed Dev Container workspace identity during Open in Agents. Existing volume-backed samples and standalone environments provide related capabilities, but do not cover reopening an arbitrary repository cloned through Dev Containers.

## Change summary

Support creating, selecting, and reconnecting Agents-window sessions for repository-backed Dev Containers without a host filesystem checkout.

## Best solution

Extend the Agents-window Dev Container integration to retain repository-volume identity and reopen the corresponding workspace with its Agent Host inside the container. Coordinate the workspace picker, editor handoff, and persisted connection identity rather than requiring a host-path substitute.

## Evidence

- **Current handoff limitation:** src/vs/sessions/contrib/chat/browser/agentsWindowOpenIntent.ts: readDevContainerHostPath reads only hostPath from JSON authorities; resolveAgentsWindowFolderIntent returns no folder and preferDevContainer=false when that path is absent.
- **Explicit existing expectations:** src/vs/sessions/contrib/chat/test/browser/agentsWindowOpenIntent.test.ts includes devContainerInVolume and devContainerInVolumeOnRemoteHost inputs containing volumeName and folder, and expects neither to select a workspace. This supports a missing capability classification rather than a regression claim.
- **Existing capabilities are partial:** chat.agentHost.devContainer.samples.enabled exposes a fixed sample catalog in src/vs/platform/agentHost/common/devContainerSamples.ts. chat.agentHost.devContainer.environments.enabled creates standalone image-based environments identified by environmentId in src/vs/platform/agentHost/common/devContainerEnvironments.ts. Neither establishes adoption of arbitrary existing Dev Containers repository volumes.
- **Related reports do not own this scope:** https://github.com/microsoft/vscode/issues/349059 is open but concerns recovering an editor Dev Container after a failed rebuild, not Agents-window workspace selection. https://github.com/microsoft/vscode/issues/348203 is a closed verification item for preserving chat state across rebuilds. https://github.com/microsoft/vscode/issues/315116 and its referenced canonical https://github.com/microsoft/vscode/issues/317380 are closed and cannot serve as open duplicate targets.
- **Related open implementation:** https://github.com/microsoft/vscode/pull/349231 proposes agent-driven creation of empty Ubuntu volume-backed environments and session handoff. Its described scope does not include importing existing repository-volume Dev Containers or implementing Clone Repository in Container Volume, so it does not establish completion or a duplicate.
