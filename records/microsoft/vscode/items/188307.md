# Issue #188307 — ExtensionHostManager: Trying to add a disposable to a DisposableStore that has already been disposed of

[https://github.com/microsoft/vscode/issues/188307](https://github.com/microsoft/vscode/issues/188307)

## Summary

Still reproduces on main: the async `.then()` callback at line 155 of extensionHostManager.ts does not guard against disposal before calling `this._register()`, leaking a disposable when the extension host startup races against disposal.

## Change summary

ExtensionHostManager leaks a disposable when disposed before its startup promise resolves, because the async callback calls `_register` on an already-disposed store.

## Best solution

Add an `isDisposed` guard (or use a cancellation token) inside the `this._proxy.then()` callback at line 155 of `src/vs/workbench/services/extensions/common/extensionHostManager.ts` so that `_register` is not called after disposal. The latency test provider registration should be skipped if the manager is already disposed.
