# Issue #119492 — Debug: current stopped line should indicate better?

[https://github.com/microsoft/vscode/issues/119492](https://github.com/microsoft/vscode/issues/119492)

## Summary

The visual-hierarchy concern remains on current main: inline values and the stopped line use similarly weighted yellow backgrounds, making the active frame harder to identify when many values are visible. The maintainer discussion supports refinement but does not settle whether inline values should be demoted, the stopped line strengthened, or both.

## Change summary

Make the current stopped line remain visually prominent when numerous debug inline-value decorations are displayed.

## Best solution

Establish a calmer hierarchy in which inline values remain readable but secondary, while the active stack frame is immediately distinguishable across default light, dark, and high-contrast themes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts`, `src/vs/workbench/contrib/debug/browser/callStackEditorContribution.ts`, `src/vs/workbench/contrib/debug/browser/media/debug.contribution.css`, `src/vs/workbench/contrib/debug/browser/media/callStackEditorContribution.css`
- **Validation:** Run a debug session with `debug.inlineValues` enabled and values decorating several lines; verify in default dark, light, high-contrast dark, and high-contrast light themes that the stopped line is immediately identifiable, inline values remain readable, and custom `editor.inlineValues*` and `editor.stackFrameHighlightBackground` colors still take effect.
- **Behavior:**

  > When a paused debug session displays inline values on several lines, the current stopped line must remain the clear visual focus and be identifiable at a glance. Inline values should remain readable without creating a field of equally prominent highlights. Existing color customization must continue to work, and the result must remain distinguishable in default light, dark, and high-contrast themes.
- **Trace:**

  > Inline values are created by `createInlineValueDecoration` in src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts and receive the `.debug-inline-value` class, whose foreground and background are applied in media/debug.contribution.css. The stopped frame is represented separately by `TOP_STACK_FRAME_DECORATION` in src/vs/workbench/contrib/debug/browser/callStackEditorContribution.ts and `.debug-top-stack-frame-line` in media/callStackEditorContribution.css. Current defaults give both surfaces translucent yellow backgrounds, so numerous inline decorations compete with the stopped-line signal. The theming work tracked by https://github.com/microsoft/vscode/issues/120936 exposed both colors but did not choose a quieter default. Preserve inline-value content, placement, hover behavior, debugger-provider behavior, and the existing public theme-color IDs.
- **Open decisions:**
  - Should the default hierarchy be achieved by visually demoting inline values, strengthening the stopped-line treatment, or combining both while preserving accessibility and theme customization?

## Evidence

- **current source:** src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts registers `editor.inlineValuesBackground` as `#ffc80033`; src/vs/workbench/contrib/debug/browser/media/debug.contribution.css applies it to every `.debug-inline-value` decoration.
- **competing highlight:** src/vs/workbench/contrib/debug/browser/callStackEditorContribution.ts registers `editor.stackFrameHighlightBackground` with a similarly translucent yellow, while callStackEditorContribution.css applies it to the whole stopped line. The two independent fills still compete on current main.
- **maintainer discussion:** The discussion proposes making inline decorations darker and less prominent, while later comments ask for stronger contrast and compare Chrome DevTools. This confirms the concern but leaves the intended visual treatment unresolved.
- **existing customization:** https://github.com/microsoft/vscode/issues/120936 added `editor.inlineValuesBackground` and `editor.inlineValuesForeground`, and `editor.stackFrameHighlightBackground` can customize the active line. These provide workarounds for themes or users but do not correct the default hierarchy requested here.
- **related issue:** https://github.com/microsoft/vscode/issues/119485 is closed and concerns displaying the precise stopped statement within a line, not the noise created by inline-value backgrounds, so it does not own this remaining polish work.
