# Issue #254027 — Copilot chat history should support full‑text search across all chat messages, not just conversation titles

[https://github.com/microsoft/vscode/issues/254027](https://github.com/microsoft/vscode/issues/254027)

## Summary

A real gap remains: current main can find text within the active transcript but session-history search still exposes only titles and metadata. This Backlog request has 28 community upvotes and is the oldest open issue specifically covering full-text search across conversations.

## Change summary

Extend Copilot chat-history search so terms found only in request or response content locate the corresponding past conversations, including agent sessions where supported.

## Best solution

Provide content-aware session search with enough match context to identify and open the relevant conversation, while defining a consistent scope for local, agent-host, and remote session providers. Keep active-transcript Ctrl+F behavior separate from this cross-session search.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsPicker.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/localAgentSessionsController.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`
- **Validation:** Add session-search tests proving that a term present only in persisted request or response content returns the owning session, a nonmatching session is omitted, and title-based matching remains intact; include provider-specific tests for every session source selected during planning.
- **Behavior:**

  > Searching session history for text that appears only inside a past user request or assistant response finds the conversation containing it. The result provides enough context to distinguish matches and opens the selected conversation. Existing title-based search continues to work, and active-chat Ctrl+F remains scoped to the currently open transcript. The supported local and agent-session scope must be stated consistently in the UI.
- **Trace:**

  > AgentSessionsPicker in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsPicker.ts currently exposes session label and metadata to Quick Pick and explicitly describes its scope as searching by name. LocalAgentSessionsController obtains unloaded sessions through ChatService#getHistorySessionItems, which reads the metadata-only index defined in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts; transcript bodies are not part of those list items. Commit https://github.com/microsoft/vscode/commit/f5929d2a1e34b2dc062e80f9b14958d915928a44 implements search only inside the loaded ChatWidget. The uncertainty begins at cross-provider transcript retrieval: local persisted chats, agent-host sessions, and contributed or remote sessions do not currently expose one uniform searchable-content contract. Preserve active-transcript find behavior and session storage semantics while planning this separate cross-session capability.
- **Open decisions:**
  - Must full-text history search cover only locally persisted Copilot chats, or every local, agent-host, cloud, and contributed session provider; how should providers without searchable transcript access appear?
  - Should a matching result show only the conversation entry, or also a message excerpt and navigation to the matched message when the conversation opens?
  - Should archived sessions participate in ordinary searches by default, or require the existing archived-session filter to be enabled?
