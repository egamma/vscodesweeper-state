# Issue #331987 — Agent host client tool is cancelled when the derived request collection reads empty for a tick

[https://github.com/microsoft/vscode/issues/331987](https://github.com/microsoft/vscode/issues/331987)

## Summary

The traced code path exists verbatim on current main: `autorunPerKeyedItem` disposes any keyed item whose request drops out of the derived collection, and that disposal cancels a client tool's shared execution token if it is still Streaming/WaitingForConfirmation/Executing — matching the reporter's stack trace and logic exactly. Root cause (why the derived `inputNeeded` collection briefly reads empty) remains unconfirmed, so this needs maintainer investigation rather than an immediate close.

## Change summary

An in-flight agent-host client tool call is spuriously cancelled when the derived input-request collection momentarily reads empty during a state update, leaving the tool permanently stuck (no completion dispatched).

## Best solution

Investigate why `derivedOpts(... state.read(reader)?.inputNeeded ?? [])` in `_watchForSessionInputNeeded` (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts, around line 2325-2401) can transiently read empty for MCP tool calls that receive two `ChatToolCallReady` actions with identical `toolInput`; once the transient-empty cause is understood, harden either the reconciliation in `autorunPerKeyedItem` (src/vs/base/common/observableInternal/reactions/autorun.ts) or this call site so a genuinely transient empty read doesn't tear down and cancel an active client-tool execution.
