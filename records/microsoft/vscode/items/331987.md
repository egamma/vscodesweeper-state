# Issue #331987 — Agent host client tool is cancelled when the derived request collection reads empty for a tick

[https://github.com/microsoft/vscode/issues/331987](https://github.com/microsoft/vscode/issues/331987)

## Summary

Thanks for the deep investigation. The described disposal path is real and matches current main exactly — this needs area-owner attention on the shared `autorunPerKeyedItem` reconciliation and/or whatever upstream update produces a transient empty `inputNeeded` read, so routing it rather than leaving it unlabeled.

## Change summary

An in-flight agent-host client tool is spuriously cancelled when the derived `inputNeeded`/requests collection reads empty for a single reconciliation tick, because `autorunPerKeyedItem` treats a fully-empty incoming array as 'every key was withdrawn' and disposes stores (and cancels their live tool executions) that are still outstanding.

## Best solution

Either harden `autorunPerKeyedItem` (src/vs/base/common/observableInternal/reactions/autorun.ts) so a transient empty read doesn't tear down all keyed items, or find and fix the upstream state-derivation bug in the agent host session/tool-call pipeline (sessionInputNeededContribution.ts / the `requests` derived in agentHostSessionHandler.ts) that produces the empty tick in the first place for MCP tools receiving two `ChatToolCallReady` actions with the same `toolInput`.
