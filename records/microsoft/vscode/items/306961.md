# Issue #306961 — Sessions App: Cannot attach file from chosen branch

[https://github.com/microsoft/vscode/issues/306961](https://github.com/microsoft/vscode/issues/306961)

## Summary

The bug remains source-reproducible on current main: before the first send, attachment search stays rooted at the originally selected repository rather than the worktree for the chosen branch. This team-authored, accepted bug is parked in On Deck and must remain open.

## Change summary

Allow a new worktree session to attach files that exist only on its selected starting branch before the first prompt is sent.

## Best solution

Make pre-send file references resolve against the selected branch's eventual session workspace, while preserving the existing repository-root behavior for non-worktree sessions. The Sessions owners should first decide whether that means materializing the worktree before send or exposing a read-only branch-backed file source to the picker.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/newChatWidget.ts`, `src/vs/sessions/contrib/chat/browser/newChatContextAttachments.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/sessions/contrib/chat/test/browser/newChatWidget.test.ts`, `src/vs/sessions/contrib/chat/test/browser/newChatInput.test.ts`
- **Validation:** Add a focused Sessions test that selects worktree isolation and a non-checked-out branch, then asserts the pre-send context picker can resolve a file unique to that branch while ordinary folder sessions still search the selected folder.
- **Behavior:**

  > In a new worktree session, after the user selects a starting branch, `#file` completion and the attachment picker must expose files from that branch before the first prompt is sent. Files absent from the currently checked-out branch but present in the selected branch must be attachable. Non-worktree sessions must continue searching their selected workspace, and changing the branch must refresh the available context without losing the draft.
- **Trace:**

  > The new-session composer obtains attachment context through `NewChatWidget._getContextFolderUri()` in src/vs/sessions/contrib/chat/browser/newChatWidget.ts, which currently returns only `WorkspacePicker.selectedFolderUri`. `NewChatContextAttachments.showPicker()` in src/vs/sessions/contrib/chat/browser/newChatContextAttachments.ts searches that URI directly, so branch selection cannot affect results. By contrast, `NewChatInSessionWidget._getContextFolderUri()` uses the active session folder's `workingDirectory`, explaining why the same file becomes available after the first send. The worktree lifecycle in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts keeps a new isolated session pending while its workspace still represents the source checkout. Preserve folder-session search semantics and avoid exposing stale files when branch selection changes.
- **Open decisions:**
  - Should selecting a worktree branch materialize and expose the worktree before the first send, or should pre-send attachment search use a read-only branch-backed file view without creating the worktree yet?

## Evidence

- **pre-send source path:** src/vs/sessions/contrib/chat/browser/newChatWidget.ts `_getContextFolderUri()` returns `_workspacePicker.selectedFolderUri`; it does not consult the pending session's selected branch or working directory.
- **attachment search:** src/vs/sessions/contrib/chat/browser/newChatContextAttachments.ts `showPicker()` passes that URI to `_collectFilePicks()`, whose local search uses it directly as the sole `folderQueries[].folder`. Files present only in another branch therefore cannot appear.
- **post-send contrast:** src/vs/sessions/contrib/chat/browser/newChatInSessionWidget.ts `_getContextFolderUri()` instead uses `session.workspace.get()?.folders[0]?.workingDirectory`, matching the reporter's observation that the file becomes attachable after the worktree-backed session exists.
- **worktree lifecycle:** src/vs/sessions/services/sessions/common/session.ts documents that while `worktreePending` is true the workspace still describes the checkout the session started from; `NewSession._syncWorktreePending()` in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts marks worktree isolation pending during composition.
- **maintainer confirmation:** https://github.com/microsoft/vscode/issues/306961#issuecomment-4166266514 identifies the likely defect as failing to update the file picker's context when the branch changes, and https://github.com/microsoft/vscode/issues/306961#issuecomment-4178901424 clarifies the exact pre-send versus post-worktree behavior.
