# Issue #147447 — cmd+click behavior for Goto Definition and a Document Link

[https://github.com/microsoft/vscode/issues/147447](https://github.com/microsoft/vscode/issues/147447)

## Summary

Still reproduces on main: both goToDefinitionAtPosition and the links contribution independently listen to ClickLinkGesture.onExecute, so cmd+click fires both goto-definition AND opens the document link. The attempted fix (commit 65499e56dbb) was reverted due to a regression.

## Change summary

When both a document link and a goto-definition target exist for the same range, cmd+click fires both actions instead of picking one.

## Best solution

Introduce coordination between the two ClickLinkGesture subscribers in goToDefinitionAtPosition.ts and links.ts so that when both a documentLink and a definition exist for the same range, only one action fires on cmd+click (likely definition wins, with the link available via context menu). The reverted LinkOpener approach (65499e56dbb) was on the right track but needs a less fragile implementation that doesn't break plain link clicking.
