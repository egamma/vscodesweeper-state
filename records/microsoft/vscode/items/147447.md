# Issue #147447 — cmd+click behavior for Goto Definition and a Document Link

[https://github.com/microsoft/vscode/issues/147447](https://github.com/microsoft/vscode/issues/147447)

## Summary

The defect remains in current source, but the older, open canonical issue reports the same observable behavior: one Ctrl/Cmd+click both opens a document link and navigates to a definition. Consolidate this report into that issue, preserving the Terraform and Ruby examples and the reverted-fix history.

## Change summary

Prevent Ctrl/Cmd+click on a range with both a document link and a definition from executing both navigation actions.

## Best solution

Resolve the competing navigation handlers under https://github.com/microsoft/vscode/issues/81520, preserving explicit access to both actions and ensuring links still open when a registered definition provider returns no result.

- **Current-source confirmation:** At checkout d771f022, src/vs/editor/contrib/gotoSymbol/browser/link/goToDefinitionAtPosition.ts constructs its own ClickLinkGesture and invokes gotoDefinition from onExecute. Independently, src/vs/editor/contrib/links/browser/links.ts constructs another ClickLinkGesture and invokes openLinkOccurrence through onEditorMouseUp. Both accept the modifier-click on content text; neither arbitrates with the other. src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts delivers the same eligible mouse-up to each gesture instance, supporting both actions when both providers supply targets.
