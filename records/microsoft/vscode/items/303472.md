# Issue #303472 — Title bar becomes hard to read when the window is inactive

[https://github.com/microsoft/vscode/issues/303472](https://github.com/microsoft/vscode/issues/303472)

## Summary

A prior review's implemented-on-main close (citing commit 9dcb3770d70761890506c9b4b764a8cb7b6d6e82) was already refuted, and I can't supply a different verifiable fix commit — this checkout is shallow (single commit) so git forensics can't trace the actual landing commit. Current main still shows the core defect traced in source: `.titlebar.inactive > *` applies a blanket `opacity: 0.6` on top of elements whose color is separately set to `var(--vscode-titleBar-inactiveForeground)`, so the configured color is still diluted, and native Windows caption buttons (set via Electron's title-bar-overlay API, outside this CSS) remain a different, unaffected color — exactly the inconsistency the reporter and howiejc described.

## Change summary

Title bar text/icons become too faint when the window is inactive because CSS opacity is layered on top of the theme's inactiveForeground color, and native caption buttons don't follow the same color, producing visible inconsistency.

## Best solution

Replace the blanket `opacity: 0.6` rule in src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css with direct `color: var(--vscode-titleBar-inactiveForeground)` styling (as done pre-regression and as already done for some sub-elements like the command center and window icon), and align the native caption-button overlay color with the same theme token so active/inactive colors stay visually consistent across both rendering paths.
