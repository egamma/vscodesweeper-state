# Issue #298712 — Cannot edit messages in Claude Agent or Copilot CLI chat sessions

[https://github.com/microsoft/vscode/issues/298712](https://github.com/microsoft/vscode/issues/298712)

## Summary

Message editing is now wired into Agent Host sessions, but the legacy Copilot CLI contribution still lacks the capability that enables editing. Keep this accepted request open until coverage across the reported session types is established; the checkpoint API proposal is related work, not a duplicate.

## Change summary

Allow users to edit and resubmit previously sent messages in Claude Agent and Copilot CLI chat sessions.

## Best solution

Provide consistent message editing for supported Claude and Copilot CLI sessions, keeping the displayed conversation and provider history synchronized after resubmission. Establish whether legacy sessions receive this capability directly or through a supported transition to Agent Host before considering the request complete.

- **Validation:** For Claude and Copilot CLI, create a conversation with at least three completed turns, edit an earlier user message, and resubmit it. Check that editing is available in supported session paths, the replacement message is used, superseded turns are absent from both the transcript and subsequent provider context, and cancelling an edit leaves the conversation unchanged. Repeat after reopening the session and distinguish Agent Host from legacy contributed sessions.
- **Behavior:**

  > Users should be able to edit and resubmit previously sent messages in supported Claude Agent and Copilot CLI chat sessions. Resubmission must replace the selected conversation branch consistently in the UI and the agent's subsequent context. Cancelling an edit must leave the existing conversation unchanged. Checkpoint restoration and forking are separate work tracked at https://github.com/microsoft/vscode/issues/295713.
- **Trace:**

  > ChatWidget.lockToCodingAgent in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts enables editable rendering only when the selected agent advertises supportsCheckpoints. AgentHostChatContribution._registerAgent advertises this capability, and ChatWidget.acceptInput preserves checkpoint state when submitting an edited request. src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts translates shortened chat history into ChatTruncated before starting the replacement turn. In contrast, the legacy copilotcli contribution in extensions/copilot/package.json omits supportsCheckpoints and therefore remains excluded by that renderer gate. These paths were inspected without executing the application; end-to-end Claude behavior and restored-session coverage remain unverified. Preserve read-only restrictions and ordinary submission behavior, and do not treat the separate checkpoint API proposal as completion of this editing request.
- **Open decisions:**
  - Should legacy contributed Copilot CLI sessions support editing in place, or should users transition those sessions to Agent Host to obtain editing while preserving their conversation?
