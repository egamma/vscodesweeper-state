# Issue #185135 — "self signed certificate in certificate chain" while attempting to install an extension via command line

[https://github.com/microsoft/vscode/issues/185135](https://github.com/microsoft/vscode/issues/185135)

## Summary

Valid feature request, explicitly acknowledged by maintainer chrmarti as the tracking issue for automatically picking up system certificate files (e.g. /etc/ssl/certs/ca-certificates.crt) in CLI/Node.js paths. The gap still exists on current main — the CLI's RequestService has loadCertificates() but doesn't integrate it into the https.request flow. Keep open as tracked work.

## Change summary

The VS Code CLI (--install-extension and serve-web) fails with 'self signed certificate in certificate chain' because the Node.js request path doesn't automatically load system CA certificate files the way Electron's net.request does.

## Best solution

Integrate the existing loadCertificates() / loadSystemCertificates() capability into the CLI's Node.js request path (src/vs/platform/request/node/requestService.ts) so that system CA certificates are automatically used when making HTTPS requests, matching the behavior of the Electron UI path. On Linux, this means auto-reading well-known certificate bundle paths; on Windows, reading from the system store.
