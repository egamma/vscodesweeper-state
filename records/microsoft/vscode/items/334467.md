# Issue #334467 — Agent merge sessions have weird XML tags when viewed as restored sessions in the editor window

[https://github.com/microsoft/vscode/issues/334467](https://github.com/microsoft/vscode/issues/334467)

## Summary

Team-authored bug report (with screenshot) about Agent Merge's internal `<agent_merge_state>` prompt markup leaking into the transcript when a merge session is restored in an editor window; I traced the relevant summarization pipeline but could not conclusively confirm the failing code path from source alone, so this stays open for further investigation.

## Change summary

When an Agent Merge-driven session is restored/viewed in the editor window, the transcript shows the raw machine-facing XML state block instead of the summarized widget users normally see.

## Best solution

Trace why the editor-window restore path renders the raw prompt: src/vs/platform/agentHost/common/agentMergePrompt.ts emits a `<agent_merge_state>...</agent_merge_state>` block that src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts (renderSystemInitiatedRequest, gated on element.isSystemInitiated) is supposed to summarize via ChatAgentMergeContentPart/parseAgentMergePrompt; something in the restored/editor-window flow (possibly stateToProgressAdapter.ts's turnsToHistory or a separate editor rendering path) isn't preserving or honoring isSystemInitiated/systemInitiatedLabel the same way the live Sessions Window does.
