# Issue #330873 — [Error] unhandlederror-s.getId is not a function

[https://github.com/microsoft/vscode/issues/330873](https://github.com/microsoft/vscode/issues/330873)

## Summary

Traced a real defect in the async tree's diagnostic path: when a lookup misses, `getDataNode` unconditionally calls `identityProvider.getId(element as T)` even though `element` may be a `TInput` value (e.g. the explorer's root `ExplorerItem[]`) that has no `getId`, so the intended 'Data tree node not found' error is masked by an unrelated `TypeError`. Root trigger (a stale root reference reaching `updateChildren` during an async refresh) isn't confirmed, but the crash mechanism itself is verified in source.

## Change summary

Auto-generated stable-anomaly report: `s.getId is not a function` thrown from `AsyncDataTree.getDataNode` while refreshing the file Explorer tree.

## Best solution

Harden `getDataNode` in src/vs/base/browser/ui/tree/asyncDataTree.ts so building the diagnostic node-identity string can't itself throw (guard the call or check the element is actually of type T before invoking `identityProvider.getId`), preserving the original 'Data tree node not found' TreeError instead of surfacing a secondary TypeError.
