## Summary

Keep open: the native node-pty callback fails during Electron's Node-environment teardown, and no verified fix adopted by VS Code was found. The external applications' shutdown mitigations do not establish that this team-authored report is resolved.

## Change summary

Prevent node-pty exit callbacks from aborting the utility process during JavaScript-environment shutdown.

## Best solution

Make node-pty's native exit-callback lifecycle safe during Electron environment teardown, then verify the adopted fix on VS Code's utility-process shutdown path. Evaluate graceful callback draining as a possible mitigation, without assuming another application's quit handling transfers directly to the pty host.

## Evidence

- **Crash and maintainer diagnosis:** https://github.com/microsoft/vscode/issues/243952 contains a native crash through Napi::ThreadSafeFunction::CallJS and ThrowAsJavaScriptException beneath node::Environment::CleanupHandles, node::FreeEnvironment, and electron::NodeService destruction. The author confirms that pty attempts to throw after the JavaScript environment shuts down: https://github.com/microsoft/vscode/issues/243952#issuecomment-2735583766.
- **Current VS Code shutdown boundary:** src/vs/platform/terminal/node/ptyHostMain.ts disposes PtyService from process.once('exit'). PtyService.shutdownAll() in src/vs/platform/terminal/node/ptyService.ts calls dispose(), whose cleanup invokes pty.shutdown(true) without awaiting native exit callbacks. TerminalProcess.shutdown() invokes asynchronous _kill() without awaiting it; _kill() emits its own process-exit event after requesting the native kill. These paths do not prove native callbacks have drained before teardown, but source inspection alone cannot establish current crash reproduction.
- **Native dependency ownership:** https://github.com/microsoft/node-pty/blob/main/src/unix/pty.cc, SetupExitCallback (lines 149–249), creates a ThreadSafeFunction for a child-exit watcher, queues a callback that invokes JavaScript, and releases the function after BlockingCall. https://github.com/microsoft/node-pty/blob/main/binding.gyp selects node_addon_api_except. This matches the native callback boundary in the report; VS Code's root and remote package.json currently declare node-pty ^1.2.0-beta.15, which alone is not fix evidence.
- **Related mitigation, not a VS Code fix:** https://github.com/RobCvdV/claude-term/pull/43 and https://github.com/Kangentic/kangentic/pull/350 are merged changes in other applications that explicitly reference this report and drain PTY exits before quitting. Neither changes VS Code or establishes an adopted upstream fix; Kangentic also describes its settling delay as heuristic.
