# Issue #276145 — Remove intent detection from agentic ask

[https://github.com/microsoft/vscode/issues/276145](https://github.com/microsoft/vscode/issues/276145)

## Summary

The requested cleanup remains relevant on current main: Agentic Ask still registers and invokes model-backed participant/intent detection. The On Deck milestone and existing feature classification protect the accepted direction, but the participant-routing contract needs a maintainer decision before implementation.

## Change summary

Remove intent detection from Agentic Ask, with the eventual goal of eliminating intent detection from every chat experience.

## Best solution

Define which automatic routing behaviors must remain for built-in and third-party participants, then eliminate the preliminary model-backed intent-detection request from Agentic Ask while preserving explicit participant and command selection.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/conversation/vscode-node/conversationFeature.ts`, `extensions/copilot/src/extension/prompt/node/intentDetector.tsx`, `extensions/copilot/test/intent/intentTest.ts`
- **Validation:** Add or update intent-routing tests to demonstrate that an Agentic Ask request does not issue an `intentDetection` model request, while explicit participant/command selection and the maintainer-approved third-party routing behavior remain intact.
- **Behavior:**

  > Agentic Ask should process an ordinary prompt without first issuing a separate model request to infer an intent. Explicit participant and slash-command choices must continue to route deterministically. Acceptance must also cover the agreed behavior for automatic third-party participant routing so the extension-facing contract is intentional rather than accidentally removed.
- **Trace:**

  > ConversationFeature.registerParticipantDetectionProvider in extensions/copilot/src/extension/conversation/vscode-node/conversationFeature.ts registers IntentDetector globally. IntentDetector.provideParticipantDetection in extensions/copilot/src/extension/prompt/node/intentDetector.tsx gathers built-in and third-party candidates, then detectIntent renders a classifier prompt and calls the `copilot-utility-small` endpoint with request type `intentDetection`. The existing empty-candidate guard avoids unnecessary calls but does not satisfy the requested removal when candidates exist. Keep explicit participant and command routing outside the cleanup boundary; uncertainty begins at automatic routing for third-party participants and any remaining non-Agentic-Ask experiences.
- **Open decisions:**
  - Should removing intent detection from Agentic Ask disable all automatic participant selection, or only Copilot's model-backed built-in intent selection while retaining third-party participant detection?
  - Is this change scoped to Agentic Ask first, or should the accepted behavior and validation cover every remaining panel/editor experience in one step?
