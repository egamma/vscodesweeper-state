# Issue #343079 — Bound the Agent Host client's copy of output-only terminal state

[https://github.com/microsoft/vscode/issues/343079](https://github.com/microsoft/vscode/issues/343079)

## Summary

The unbounded client-state path remains present on current main. The merged inline-output optimization explicitly excludes the shared subscription and its other readers, so this follow-up remains necessary.

## Change summary

Bound subscribed output-only terminal state and keep the Background Shells preview and full-output editor incremental when retained output is trimmed.

## Best solution

Keep live client subscriptions consistent with the host's bounded output history, with compatible trim semantics across AHP clients. Ensure both output readers process continued streaming and front trims without repeatedly rebuilding their entire contents.

- **Trace:**

  > AgentHostTerminalManager.appendOutputTerminalData trims only its private content before emitting the original TerminalData chunk. TerminalStateSubscription applies the generated terminalReducer, which concatenates that chunk without learning about the discarded prefix; this confirms the client-state growth directly from current source. Background Shells joins this state, while its view uses prefix comparison and a clear-and-rewrite fallback; TerminalTextModelSynchronizer similarly reconciles the whole model when append-length checks fail. The merged https://github.com/microsoft/vscode/pull/343011 bounds only the inline output channel and explicitly leaves these consumers unchanged. The uncertainty is the compatible end-to-end trim representation and its interaction with incremental readers, not whether the growth exists. Protocol files are generated from the separate AHP source repository, so any protocol change must originate there rather than editing the generated copy. Preserve PTY behavior, explicit resets, snapshot/reconnect ordering, and the existing inline-output optimization; include version-skew and conforming-host coverage in the design.
