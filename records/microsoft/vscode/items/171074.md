# Issue #171074 — Feature request: prettify symbols mode

[https://github.com/microsoft/vscode/issues/171074](https://github.com/microsoft/vscode/issues/171074)

## Summary

Keep this accepted, well-supported request open: current editor APIs do not provide view-model-aware symbol replacement, and font ligatures do not cover its central ask. A recent contributor proof of concept provides a useful starting point for maintainer-led API and interaction design.

## Change summary

Support context-sensitive, language-specific display substitutions such as showing F# `fun` as `λ`, preserving the original document and exposing the original text on hover.

## Best solution

Provide supported editor rendering primitives for extensions to conceal or replace source ranges with correct cursor positioning and wrapping, while preserving underlying text. Evaluate the contributor's proof of concept and coordinate with the related hide-character work before committing to public API and editing semantics.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/model.ts`, `src/vs/editor/common/modelLineProjectionData.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/test/common/viewModel/lineBreakData.test.ts`, `src/vs/editor/test/common/viewModel/monospaceLineBreaksComputer.test.ts`, `src/vs/editor/test/browser/viewModel/viewModelImpl.test.ts`
- **Validation:** The plan should end with projection and wrapping tests covering replacement ranges of different source/display lengths, plus an extension-host manual scenario displaying `fun` as `λ`: verify cursor navigation, mouse positioning, wrapping and original-text hover; copying, searching, saving and diffing must retain the original text. Validate deletion against the maintainer-selected editing contract.
- **Behavior:**

  > Users or language extensions can display selected source sequences as other symbols without changing document contents or requiring a custom font. The representative case is displaying F# `fun` as `λ`, with the original sequence available on hover. Cursor navigation, mouse positioning and wrapping must remain coherent around substitutions. Copy, search, save and diff continue to operate on the original source; editing behavior at substituted ranges needs an explicit contract.
- **Trace:**

  > EditorFontLigatures in src/vs/editor/common/config/editorOptions.ts controls font features, not source-sequence replacement. DecorationRenderOptions in src/vscode-dts/vscode.d.ts offers styling and before/after attachments but no supported conceal property. InjectedTextOptions in src/vs/editor/common/model.ts and ModelLineProjectionData in src/vs/editor/common/modelLineProjectionData.ts account for inserted view text, not replacement of model ranges. This establishes an API and projection gap, not a confirmed defect in an existing conceal feature. The contributor's proof of concept is described at https://github.com/microsoft/vscode/issues/171074#issuecomment-5703869503; its implementation has not been reviewed here. Coordinate shared primitives with https://github.com/microsoft/vscode/issues/286296 without treating that newer, narrower request as a duplicate canonical. Preserve underlying document semantics and ordinary non-substituted editing; scope and interaction design remain unsettled.
- **Open decisions:**
  - Should the supported surface be an extension rendering API alone, or also a built-in per-language substitution mode with user settings?
  - When the caret enters a substituted range, should the editor reveal and edit the original characters or retain an atomic displayed replacement, and what should deletion do?
