# Issue #215617 — Long prompt text with shell integration causes "ghost" text display in the VSCode bash terminal

[https://github.com/microsoft/vscode/issues/215617](https://github.com/microsoft/vscode/issues/215617)

## Summary

Still reproduces on current main. The bash shell integration wraps PS1 with OSC 633 escape sequences in `__vsc_update_prompt()`, and when the original PS1 is long enough, bash's internal line-wrapping calculation breaks, causing fragments of the escape sequences (including the nonce UUID) to render as visible 'ghost' text. No fix commit references this issue.

## Change summary

Long PS1 prompts in bash with shell integration enabled cause fragments of VS Code's OSC escape sequences to appear as visible ghost text before the prompt.

## Best solution

The fix likely needs to happen in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh` in `__vsc_update_prompt()`. The current approach embeds OSC sequences directly into PS1 via subshell expansion (`$(__vsc_prompt_start)`), which adds significant byte length. A potential fix could use PROMPT_COMMAND to emit the OSC sequences outside of PS1 entirely (before and after the prompt renders), avoiding the bash line-length issue altogether — similar to how `__vsc_command_complete` already works via PROMPT_COMMAND.

## Evidence

- **root cause in source:** In `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh` line 386, `__vsc_update_prompt()` sets `__vsc_custom_PS1="\[$(__vsc_prompt_start)\]$__vsc_original_PS1\[$(__vsc_prompt_end)\]"` — the subshell-expanded OSC sequences add ~20 bytes marked as non-printing, and when the original PS1 is long (200+ chars with escape sequences), bash's line-wrapping calculation overflows, causing visible leakage.
- **no fix on main:** git log --all --grep=215617 returns no commits. git log on the bash SI script since June 2024 shows related fixes (prompt glitch #243804, nonce/PS1 env reporting) but none addressing the long-prompt ghost text.
- **confirmed by multiple users:** Original reporter and comment 1 (mcdurdin) both reproduce the issue with Git Bash on Windows with standard long PS1 prompts including git branch info. Comment 7 confirms v1.90.2 did not fix the bash variant.
- **shell integration specific:** Reporter confirmed: does not occur with shell integration disabled, does not occur in standalone Git Bash, occurs even with all extensions disabled.
