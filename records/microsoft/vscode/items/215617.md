# Issue #215617 — Long prompt text with shell integration causes "ghost" text display in the VSCode bash terminal

[https://github.com/microsoft/vscode/issues/215617](https://github.com/microsoft/vscode/issues/215617)

## Summary

Still reproduces on main: the bash shell integration script wraps PS1 with escape sequences (prompt-start/end markers) at line 386 of shellIntegration-bash.sh, and when the combined PS1 is long enough, fragments of those injected sequences (including the nonce UUID) leak as visible text in the terminal. No fix commit found.

## Change summary

Long PS1 prompts in bash terminals with shell integration enabled cause fragments of injected escape sequences to appear as visible 'ghost' text before each prompt.

## Best solution

Fix the PS1 wrapping in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh` (around line 386) so that the injected prompt-start/end markers do not cause escape sequence fragments to become visible when the total PS1 length is large. The root cause is likely that the `\[...\]` non-printing markers plus the OSC 633 sequences exceed a threshold where bash's line-wrapping logic or the terminal emulator mishandles them. One approach would be to reduce the byte length of the injected sequences or restructure how they are embedded.
