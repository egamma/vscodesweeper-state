# Issue #133843 — Toggle Line Comment can produce invalid block comment in JSX and CSS (should use single-line comments instead)

[https://github.com/microsoft/vscode/issues/133843](https://github.com/microsoft/vscode/issues/133843)

## Summary

The clarified request remains unimplemented on current main: Toggle Line Comment still wraps selections with block delimiters without preserving nested or intersecting comments. This issue is also the established canonical for that behavior and is already correctly routed to the editor comments backlog.

## Change summary

Make Toggle Line Comment reversibly handle selections that overlap existing block comments in JSX, CSS, and HTML without producing invalid syntax.

## Best solution

Define reversible semantics for nested or partially selected block comments, then implement them in the block-comment fallback used by Toggle Line Comment while leaving ordinary line-comment behavior unchanged.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/comment/browser/lineCommentCommand.ts`, `src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts`
- **Validation:** Add JSX-, CSS-, and HTML-style cases to the Line Comment As Block Comment suite and run scripts/test.sh --grep "Editor Contrib - Line Comment As Block Comment"; each case should verify valid nested output and an exact round trip back to the original text.
- **Behavior:**

  > When Toggle Line Comment is invoked on a multiline JSX, CSS, or HTML selection that intersects existing block comments, the result must remain syntactically valid rather than introducing an active nested delimiter. Toggling the generated comment back off must restore the original comment text exactly. Partial selections need predictable behavior, and languages with native line-comment tokens must remain unchanged.
- **Trace:**

  > LineCommentCommand.getEditOperations in src/vs/editor/contrib/comment/browser/lineCommentCommand.ts uses line-comment operations when the language supplies a line token and otherwise delegates to _executeBlockComment. That fallback only checks for removable delimiters at the selection boundaries; when adding a comment it passes the full selected range to BlockCommentCommand._createAddBlockCommentOperations, which inserts outer delimiters without examining inner ones. The existing Line Comment As Block Comment tests cover basic insertion and removal but contain no nested or intersecting delimiter cases. The scope is the Toggle Line Comment fallback for block-only languages; native line-comment behavior and the separately exposed Toggle Block Comment command should not change without an explicit decision. Related https://github.com/microsoft/vscode/issues/32541 concerns locating an enclosing comment and does not own this overlap behavior.
- **Open decisions:**
  - What reversible encoding should be used for inner delimiters in JSX, CSS, and HTML, and can it be represented by one language-agnostic algorithm?
  - How should toggling a selection that covers only part of a previously generated outer comment determine which delimiters to remove or restore?
  - Should the new semantics apply only to Toggle Line Comment's block fallback, or also to the explicit Toggle Block Comment command?

## Evidence

- **current source:** src/vs/editor/contrib/comment/browser/lineCommentCommand.ts routes languages without a line-comment token from getEditOperations to _executeBlockComment; that method calls BlockCommentCommand._createAddBlockCommentOperations and does not inspect or escape delimiters inside the selection.
- **operation behavior:** src/vs/editor/contrib/comment/browser/blockCommentCommand.ts::_createAddBlockCommentOperations only inserts one start token and one end token around a non-empty range, so an existing inner end token still terminates the resulting comment prematurely.
- **canonical status:** A maintainer closed https://github.com/microsoft/vscode/issues/172235 as a duplicate of this issue in 2023, confirming that this issue owns the remaining nested/intersecting block-comment behavior.
- **distinct scope:** https://github.com/microsoft/vscode/issues/32541 remains open but concerns finding and removing the enclosing block comment from a caret; the reporter clarified that this issue instead requires reversible handling when a new selection intersects existing comments.
