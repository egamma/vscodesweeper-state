# Issue #133843 — Toggle Line Comment can produce invalid block comment in JSX and CSS (should use single-line comments instead)

[https://github.com/microsoft/vscode/issues/133843](https://github.com/microsoft/vscode/issues/133843)

## Summary

Keep open: Toggle Line Comment still lacks reversible handling of overlapping block comments. The maintainer acknowledged the clarified request, and the older linked issue concerns uncommenting an entire block from the caret rather than safely commenting overlapping selections.

## Change summary

Make line-comment toggling safe and reversible across existing comments in JSX, CSS, and HTML, including uncommenting only selected lines.

## Best solution

Define a reversible commenting contract for languages without line-comment tokens, covering nested delimiters and partial uncommenting, then implement it in the editor comment commands. Preserve existing behavior for languages with genuine line comments.

Assert exact text and restoration of original delimiters, then run scripts/test.sh --run src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts --run src/vs/editor/contrib/comment/test/browser/blockCommentCommand.test.ts in an implementation workspace.
- **Behavior:**

  > In JSX, CSS, and HTML, commenting a selection that contains or intersects existing comments should not leave selected code active because an inner delimiter prematurely terminates the new comment. Reversing the operation should restore the original text, including prior comments. Users should also be able to uncomment a selected subset of previously commented lines. Acceptance checks must cover both overlapping ranges and partial uncommenting while preserving ordinary JavaScript line-comment behavior.
- **Trace:**

  > Toggle Line Comment is registered as editor.action.commentLine in src/vs/editor/contrib/comment/browser/comment.ts and executes LineCommentCommand. In src/vs/editor/contrib/comment/browser/lineCommentCommand.ts, missing line-comment tokens trigger _executeBlockComment; that path operates on selection boundaries and inserts a single block-comment pair without transforming interior delimiters. CSS and HTML configurations declare only block-comment tokens, and the line-comment test suite also models JSX with block-only comment tokens. The remaining uncertainty is the user-visible reversible representation and its interaction with partial selections, not the existence of the fallback. Keep native line-comment behavior and unrelated editor commands outside the scope unless the agreed contract requires otherwise. https://github.com/microsoft/vscode/issues/32541 concerns whole-block removal from a caret and is related, not equivalent; https://github.com/microsoft/vscode/issues/172235 was consolidated into this request.
- **Open decisions:**
  - Should Toggle Line Comment use independently wrapped lines for block-only languages by default, or expose this as an opt-in behavior while retaining whole-selection wrapping?
  - What reversible delimiter representation should each supported language use, and how should uncommenting distinguish generated escapes from identical text originally present in the source?
