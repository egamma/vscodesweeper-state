# Issue #95021 — Task terminal truncates long/quick output.

[https://github.com/microsoft/vscode/issues/95021](https://github.com/microsoft/vscode/issues/95021)

## Summary

Still a valid bug on main. The existing 250ms DataFlushTimeout workaround in terminalProcess.ts mitigates but does not fully solve the node-pty data-flush-on-exit race (node-pty#72). Fast-exiting tasks that produce large output still truncate, as multiple reporters confirmed across versions through 1.62.

## Change summary

Task terminal truncates output when a process produces large amounts of data and exits quickly, because not all pty data is flushed before the exit event fires.

## Best solution

The fix needs to happen in the data flush mechanism in `src/vs/platform/terminal/node/terminalProcess.ts` — the 250ms `DataFlushTimeout` is a heuristic that's too short for large bursts. A more robust approach would wait for the pty's data stream to actually drain (or use a longer/adaptive timeout). Ultimately this depends on upstream node-pty improvements (microsoft/node-pty#72). Related issue https://github.com/microsoft/vscode/issues/92868 tracks a similar flush problem for CustomExecution tasks but targets a different code path, so both should stay open.

- **exit queue mechanism:** Lines 340-387: on pty exit, _queueProcessExit sets a 250ms timer; incoming data resets it, but if the pty buffer drains slowly the timer fires and _kill() runs before all data arrives.
- **upstream root cause:** https://github.com/microsoft/node-pty/issues/72 — node-pty does not guarantee all buffered data is delivered before the exit event.
