# Issue #323668 — Per-session VSCODE_TARGET_SESSION_LOG template variable sits inside the cached system prefix and cold-busts BYOK Anthropic prompt caching

[https://github.com/microsoft/vscode/issues/323668](https://github.com/microsoft/vscode/issues/323668)

## Summary

Confirmed in current source: the per-session VSCODE_TARGET_SESSION_LOG value (containing a per-conversation UUID) is eagerly resolved and injected into a SystemMessage that sits before the cache breakpoint in the GlobalAgentContext UserMessage — this busts Anthropic prompt caching on every session-ID change for BYOK users.

## Change summary

Per-session UUID in VSCODE_TARGET_SESSION_LOG template variable invalidates the entire Anthropic cached system prefix on every conversation or session change.

## Best solution

Move the template-variables SystemMessage after the cache breakpoint (option 2 from the reporter), or resolve VSCODE_TARGET_SESSION_LOG lazily only when a loaded skill actually references it. The fix lives in `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx` (line ~143) and/or `extensions/copilot/src/extension/prompt/vscode-node/promptVariablesService.ts`.
