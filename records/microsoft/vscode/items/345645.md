# Issue #345645 — Explicit Force Remove recovery fails with "The worktree registration changed" after a partial removal on Windows

[https://github.com/microsoft/vscode/issues/345645](https://github.com/microsoft/vscode/issues/345645)

## Summary

The retry failure is confirmed in current source: forced cleanup rejects an unregistered worktree while its leftover directory still exists, preventing the existing residual-directory removal path from running.

## Change summary

Allow explicit forced cleanup to finish removing a known leftover directory after a previous attempt unregistered its worktree.

## Best solution

Make forced recovery of a previously recorded removal retryable after partial Git removal, while retaining managed-path validation and ordinary cleanup protections.
