# Issue #303032 — Open With Code no longer available in file Explorer

[https://github.com/microsoft/vscode/issues/303032](https://github.com/microsoft/vscode/issues/303032)

## Summary

Keep open for installer investigation: multiple users confirmed missing folder/background actions while file actions remained, and the requested setup logs were supplied. The reporter's log identifies a classic-menu installation path that the existing background-update repair does not cover.

## Change summary

Windows Explorer loses the folder/background 'Open with Code' action after updating VS Code, while the file action remains available.

## Best solution

Preserve previously enabled folder/background integration across installer upgrades without enabling it for users who deliberately declined it. Establish why the supplied installation selected only file integration before changing the installer behavior.

## Plan brief

- **Likely files:** `build/win32/code.iss`
- **Validation:** On Windows 11 with classic menus forced, install VS Code with file and folder integration enabled, then exercise silent/system and background updates. Check the resulting setup task states and verify that file, folder, and folder-background actions remain usable; repeat with folder integration deliberately disabled to ensure it is not newly enabled.
- **Behavior:**

  > Users report losing folder/background 'Open with Code' after an update while file integration remains. Previously enabled folder integration should survive upgrading, and users who deliberately declined folder integration should not acquire it. Acceptance requires exercising both upgrade modes and checking actual Explorer actions, not only registry predicates.
- **Trace:**

  > The reporter's attached setup log shows forced classic menus, existing file integration, missing folder integration, addcontextmenufolders=false, and isBackgroundUpdate=false. In build/win32/code.iss, ShouldRepairFolderContextMenu only handles background updates, and ShouldInstallLegacyFolderContextMenu otherwise follows the selected folder task; the logged state excludes both branches. The same predicates gate directory, background, and drive registry entries. The trace does not establish whether the installer lost a prior task selection or faithfully retained an earlier choice; resolve that provenance before treating the predicate as defective. Preserve deliberate opt-outs and keep AppX-registration failures separate from this classic-menu case. Related reports: https://github.com/microsoft/vscode/issues/303103 and https://github.com/microsoft/vscode/issues/316870.
