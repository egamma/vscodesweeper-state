# Issue #149673 — The "$tsc-webpack-watch" from "amodio.tsl-problem-matcher" problem matcher does match, but doesn't mark the task as failed

[https://github.com/microsoft/vscode/issues/149673](https://github.com/microsoft/vscode/issues/149673)

## Summary

Still reproduces on main: when multiple background problem matchers are active, one matcher's end pattern can prematurely trigger `tryFinish` for the cycle, causing errors to be missed and the task to be marked successful. The core logic in `WatchingProblemCollector.tryFinish` is unchanged. A workaround exists (comment 13 by alexdima) but the underlying bug remains.

## Change summary

When using the `$tsc-webpack-watch` problem matcher alongside built-in `$ts` matchers, the task is incorrectly marked as successful even when compilation errors exist, because one matcher's end pattern prematurely closes another's begin/end cycle.

## Best solution

Fix the interaction between multiple background problem matchers in `WatchingProblemCollector` (src/vs/workbench/contrib/tasks/common/problemCollectors.ts) so that each matcher's begin/end cycle is independent — a `tryFinish` match should only close the cycle for the specific matcher whose end pattern matched, not interfere with error collection for other matchers in the same collector. Related to https://github.com/microsoft/vscode/issues/157096 (multiple patterns). The team has investigated extensively (comments 3–11) and identified the root cause.
