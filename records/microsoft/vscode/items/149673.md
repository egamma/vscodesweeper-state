## Change summary

A webpack watch task displays a success checkmark despite TypeScript compilation errors appearing in the Problems panel.

## Best solution

Establish which matcher supplies the diagnostics and which background boundary causes the success indicator, then ensure the indicator reflects errors from the completed compilation cycle. Preserve independent watch cycles and distinguish a core lifecycle defect from an incompatible contributed matcher.

- **Behavior:**

  > The reported webpack watch task shows a success checkmark despite compilation errors being visible in Problems. A completed compilation cycle containing errors recognized by that task's problem matchers should show an error indicator, including after splitting the terminal. A subsequent error-free cycle should restore success, and an actively compiling cycle should retain its running indication. Establish this behavior using the original matcher configuration and captured output, not only the workaround.
- **Trace:**

  > WatchingProblemCollector in src/vs/workbench/contrib/tasks/common/problemCollectors.ts consumes background boundary lines before diagnostic matching and shares diagnostic counters across its matchers; cleanMarkerCaches resets those counters on begin/end transitions. TerminalTaskSystem in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts forwards background end events as task inactivity, and TaskTerminalStatus in src/vs/workbench/contrib/tasks/browser/taskTerminalStatus.ts chooses success from a zero collector match count. Maintainers confirmed the symptom and investigated premature background completion, but also questioned whether fork-ts-checker-webpack-plugin output matches the contributed regexes: https://github.com/microsoft/vscode/issues/149673#issuecomment-1246008507 and https://github.com/microsoft/vscode/issues/149673#issuecomment-1247073876. The uncertainty starts at the exact output and matcher combination that produces the incorrect status on current builds. Preserve independent background cycles, existing diagnostic ownership and applyTo behavior, and process-exit status semantics; do not substitute all Problems-panel diagnostics for task-owned errors. The override at https://github.com/microsoft/vscode/issues/149673#issuecomment-1644427626 is a useful comparison case, not proof of a core fix.
