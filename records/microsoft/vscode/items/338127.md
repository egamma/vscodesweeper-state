# Issue #338127 — Copilot Chat gets stuck on "Considering..."/"Working..." - "no session host is registered"

[https://github.com/microsoft/vscode/issues/338127](https://github.com/microsoft/vscode/issues/338127)

## Summary

Detailed, well-diagnosed report of Copilot Chat hanging indefinitely on 'Considering...'/'Working...' due to the copilot-runtime losing track of the session host; the reporter backs it with consistent log evidence (14/14 recent runtime logs). This is a real, in-scope Copilot Chat bug, but the actual fault lives in the closed-source `copilot-runtime.exe` binary (not TypeScript source in this checkout), so it needs a maintainer with access to that runtime/session-host registration code, not an agent session against this repo.

## Change summary

Copilot Chat gets permanently stuck in an in-progress state when the runtime's response can't be delivered because 'no session host is registered' for the session, requiring a full VS Code reload to recover.

## Best solution

Have the Agent Host / copilot-runtime team investigate session-host deregistration (likely tied to window reload/sleep/session cleanup) and add either a delivery-failure surface to the chat UI or automatic re-registration, so a dropped response doesn't leave the UI hung forever.
