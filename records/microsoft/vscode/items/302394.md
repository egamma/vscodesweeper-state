# Issue #302394 — MCP Streamable HTTP client does not send cookies, breaking ARR affinity on multi-instance Azure App Service

[https://github.com/microsoft/vscode/issues/302394](https://github.com/microsoft/vscode/issues/302394)

## Summary

Confirmed in source: the MCP HTTP transport in `extHostMcp.ts` never passes `credentials: "include"` to `fetch()`, so cookies (including Azure ARR affinity cookies) are silently dropped. Team-authored, no fix found — keeping open.

## Change summary

MCP Streamable HTTP client does not send cookies on subsequent requests, breaking cookie-based session affinity behind load balancers like Azure App Service ARR.

## Best solution

Add `credentials: "include"` to the `CommonRequestInit` passed through `_fetchInternal` in `McpHTTPHandle._fetch()` (src/vs/workbench/api/common/extHostMcp.ts). The existing `CROSS_ORIGIN_STRIPPED_HEADERS` set already handles cross-origin cookie stripping on redirects, so the security boundary is in place.
