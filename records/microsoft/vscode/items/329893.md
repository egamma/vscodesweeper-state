# Issue #329893 — Agent host: set GIT_OPTIONAL_LOCKS=0 on read-only git probes to avoid worktree-removal races

[https://github.com/microsoft/vscode/issues/329893](https://github.com/microsoft/vscode/issues/329893)

## Summary

Well-diagnosed root-cause fix: read-only git probes in agentHostGitService.ts never set GIT_OPTIONAL_LOCKS=0, unlike the built-in git extension's idiom, so they can race git worktree remove's rmdir of the admin directory during session teardown, causing an intermittent E2E teardown failure.

## Change summary

Add GIT_OPTIONAL_LOCKS=0 to the read-only git status/diff invocations in the agent host's git service to avoid a worktree-removal race.

## Best solution

Pass env: { GIT_OPTIONAL_LOCKS: '0' } to the read-only _runGit calls in src/vs/platform/agentHost/node/agentHostGitService.ts (status/diff helpers), leaving mutating calls (commitAll, restore, update-index, temp-index writes) untouched, matching extensions/git/src/git.ts's existing idiom.
