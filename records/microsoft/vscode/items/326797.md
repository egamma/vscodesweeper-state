# Issue #326797 — Agent/Ask/Plan not switching properly with customendpoint BYOK model

[https://github.com/microsoft/vscode/issues/326797](https://github.com/microsoft/vscode/issues/326797)

## Summary

Credible bug report: Plan→Agent handoff fails specifically with BYOK customendpoint models while working correctly with built-in Copilot models. The reporter has done thorough differential diagnosis. The fix for the similar issue https://github.com/microsoft/vscode/issues/313121 (commit b5f0a81fbbe) addressed stateful marker handling on mode change for the Responses API, but the BYOK customendpoint path may have a subtle difference in how `modeChanged` or `previous_response_id` is handled. Needs investigation by the Copilot/BYOK team.

## Change summary

Clicking 'Start Implementation' after planning with a BYOK customendpoint model fails to switch from Plan to Agent mode — the model still reports being in planning mode.

## Best solution

Investigate whether the BYOK customendpoint Responses API path correctly clears `previous_response_id` on mode change. The fix in commit b5f0a81fbbe added `modeChanged` support to `rawMessagesToResponseAPI`, and the BYOK `OpenAIEndpoint.createRequestBody` delegates to this via `super.createRequestBody`. The issue may be in how `modeInstructions2` or turn history is populated for BYOK sessions, causing `didModeChangeSincePreviousRequest()` to return `false` when it should return `true`. Likely files: `extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts` (mode change detection), `extensions/copilot/src/extension/byok/node/openAIEndpoint.ts` (BYOK body construction), `extensions/copilot/src/platform/endpoint/node/responsesApi.ts` (stateful marker clearing).
