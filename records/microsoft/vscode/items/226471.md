# Issue #226471 — Cannot run dynamically-created shell tasks when a workspace folder is not opened

[https://github.com/microsoft/vscode/issues/226471](https://github.com/microsoft/vscode/issues/226471)

## Summary

Keep open: current source can select a web-worker task system instead of the local Windows task system when no folder is open, causing shell-profile resolution to request Linux defaults. This team-authored bug is already correctly routed to tasks; no qualifying fix or canonical duplicate was found.

## Change summary

Dynamically created shell tasks should use the appropriate execution platform and shell when no workspace folder is open.

## Best solution

Ensure folderless shell tasks resolve their execution platform from the actual terminal backend rather than a web-worker registration, while preserving remote-task and custom-execution behavior.

- **Conflicting task-system registrations:** src/vs/workbench/api/node/extHostTask.ts registers the local task system under Schemas.file with process.platform. AbstractTaskService.registerTaskSystem in src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts:881-901 retains that non-file key when no workspace folder exists.
- **Current source failure path:** AbstractTaskService._createTerminalTaskSystem in src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts:2268-2278 preferentially selects a non-file registration when workspaceFolder is undefined, even if that registration is Platform.Web and a local Windows registration exists. TerminalTaskSystem._createTerminal uses the selected task-system platform; _createShellLaunchConfig in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1220-1232 maps Web through the default switch branch to OperatingSystem.Linux and requests that OS's automation/default profile.
