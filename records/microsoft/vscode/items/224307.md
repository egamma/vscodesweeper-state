# Issue #224307 — Bring true inline view to all diff viewers

[https://github.com/microsoft/vscode/issues/224307](https://github.com/microsoft/vscode/issues/224307)

## Summary

Keep open: the existing true-inline setting is not propagated to the SCM gutter diff widget, so the requested consistency remains missing. This team-authored, accepted Backlog request has no verified fixing commit or canonical duplicate.

## Change summary

Honor the enabled true-inline diff preference across diff viewers, including SCM gutter change previews.

## Best solution

Make eligible inline diff viewers consistently honor diffEditor.experimental.useTrueInlineView while preserving their existing editing and navigation behavior. Start with the confirmed SCM gutter configuration gap and establish which other diff surfaces the broader request should cover.

- **Behavior:**

  > Users who enable true-inline diff rendering should receive that rendering in eligible inline diff viewers, including the SCM gutter preview named in the report. Disabling the preference should preserve legacy inline rendering; existing staging, reverting, navigation, and editing behavior should remain unchanged. Planning must identify the additional user-facing diff viewers included in the request.
- **Trace:**

  > QuickDiffWidget._fillBody in src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts creates an EmbeddedDiffEditorWidget in inline mode without the true-inline option. DiffEditorOptions already gates true-inline rendering on the experimental flag and inline layout, so this is a configuration-coverage gap rather than an absent renderer. Preserve existing widget-specific options, side-by-side behavior, and renderer eligibility restrictions. The trace establishes the SCM example but does not enumerate every specialized diff viewer; the intended coverage of https://github.com/microsoft/vscode/issues/224307 remains the planning boundary.
