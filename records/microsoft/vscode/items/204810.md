# Issue #204810 — "runCommands": "workbench.action.focusActiveEditorGroup" command does not work after "workbench.action.terminal.focus" command

[https://github.com/microsoft/vscode/issues/204810](https://github.com/microsoft/vscode/issues/204810)

## Summary

Still reproducible on main: `runCommands` awaits each command's promise, but focus-changing commands (terminal.focus, togglePanel, etc.) resolve before the DOM/UI focus has actually settled, so subsequent commands like `focusActiveEditorGroup` execute against stale focus state.

## Change summary

Sequential focus commands in `runCommands` fail because the first focus command's promise resolves before the DOM focus transfer completes, causing the next focus command to be a no-op.

## Best solution

The `focusActiveTerminal` path (via `focusInstance`) and similar panel-reveal commands need to ensure their returned promise only resolves after the target element has actually received DOM focus. Likely fix locations are `src/vs/workbench/contrib/terminal/browser/terminalActions.ts` (focusActiveTerminal) and possibly the panel show/focus infrastructure. Alternatively, `runCommands` itself could wait for a microtask or requestAnimationFrame between commands that change focus.
