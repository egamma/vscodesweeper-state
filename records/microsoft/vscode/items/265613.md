# Issue #265613 — Better integration of pre-commit hooks with Python virtual environments.

[https://github.com/microsoft/vscode/issues/265613](https://github.com/microsoft/vscode/issues/265613)

## Summary

Keep open: the built-in Git extension does not select a project's Python environment for commits, so the requested integration remains missing. The existing git routing, Backlog milestone, and help wanted label support retaining this for design rather than declining it.

## Change summary

Let Git commits initiated in VS Code run hooks with the project's Python virtual environment without requiring VS Code to be launched from an activated shell.

## Best solution

Provide repository-scoped environment integration for Git hooks that can use the project's chosen Python environment without changing unrelated repositories or requiring an activated launcher shell. Settle the environment-selection and activation contract before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/main.ts`, `extensions/git/src/git.ts`, `extensions/git/package.json`
- **Validation:** Create a repository with a venv-only executable and an explicit hook that invokes it by name. Launch VS Code without that venv in its environment and commit through Source Control; verify the hook resolves the chosen environment's executable. Repeat with two repositories using different environments, no selected environment, and an already activated launcher shell to check isolation and fallback behavior.
- **Behavior:**

  > A user should be able to commit through Source Control with hooks that require tools from the project's Python environment, without launching VS Code from an activated shell. Hook execution should consistently use the environment selected under the agreed product contract. Acceptance should cover a venv-only executable, two repositories with different environments, and a repository without a selected environment. Existing authentication, signing, and hook verification behavior must remain intact.
- **Trace:**

  > Repository.commit in extensions/git/src/git.ts creates the commit command and passes its spawn options to Git execution; Git.spawn merges inherited process.env with Git-wide and invocation-specific overrides. extensions/git/src/main.ts creates the Git-wide environment from authentication, editor, and IPC providers, with no Python environment provider. TerminalEnvironmentManager in extensions/git/src/terminal.ts manages terminal environment contributions, not SCM subprocess environment acquisition. This confirms a missing integration surface, not the exact behavior of the reporter's unspecified pre-commit configuration. The uncertainty starts at which project environment is authoritative and what activation means for hook execution; any integration must preserve unrelated repositories and existing Git controls. https://github.com/microsoft/vscode/issues/130100 is related launch-environment evidence, not a verified canonical for this Python request.
- **Open decisions:**
  - Should Git hooks use the Python extension's selected environment, independently discover a repository-local venv, or require explicit repository opt-in?
  - Should the integration provide only the environment's executable search path or the full activation environment, and should it affect only hook-running operations or all Git subprocesses?
