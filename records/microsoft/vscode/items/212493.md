# Issue #212493 — code-insiders crashing with Russian language pack

[https://github.com/microsoft/vscode/issues/212493](https://github.com/microsoft/vscode/issues/212493)

## Summary

The supplied dumps match a diagnosed Chromium X11 software-compositor crash, rather than establishing that the Russian language pack caused it. Keep open under the upstream-issue rule, with the known runtime fix recorded for maintainer follow-up.

## Change summary

VS Code and Insiders terminate on Ubuntu while the reporter uses the Russian language pack.

## Best solution

Retain the upstream fix that prevents GPU-process display enumeration from accessing browser-only localization resources. Establish whether any crash remains on a current build before pursuing a separate language-pack defect.

## Evidence

- **Confirmed historical crash:** https://github.com/microsoft/vscode/issues/212493#issuecomment-2142977783 contains maintainer-symbolicated dumps. Another reporter confirmed the regression at https://github.com/microsoft/vscode/issues/212493#issuecomment-2106223049; the original reporter subsequently reported both stable and Insiders affected.
- **Exact native failure:** https://github.com/user-attachments/files/15518767/symbolicated-f0.log shows SIGTRAP in ui::ResourceBundle::GetSharedInstance(), called through l10n_util::GetStringUTF8(), BuildDisplaysFromXRandRInfo(), GetPrimaryDisplayRefreshIntervalFromXrandr(), and SoftwareOutputSurface::SwapBuffers(). This is GPU-process software rendering, not a demonstrated failure loading Russian translations.
- **Browser termination:** https://github.com/user-attachments/files/15518766/symbolicated-b5.log shows IntentionallyCrashBrowserForUnusableGpuProcess() after GPU-process failures, explaining the application termination.
- **Matching diagnosed reports:** https://github.com/microsoft/vscode/issues/214830 documents the identical native stack. Its maintainer diagnosis at https://github.com/microsoft/vscode/issues/214830#issuecomment-2165650497 identifies a Chromium regression allowing software-compositor GPU processes to access localization resources. Both it and https://github.com/microsoft/vscode/issues/212494 are closed, so neither is eligible as a duplicate canonical.
- **Actual upstream fix:** Chromium commit https://chromium.googlesource.com/chromium/src/+/f8010390a47322ddfe62aba8f7e568a122240dcc changes ui/base/x/x11_display_util.cc so BuildDisplaysFromXRandRInfo() calls l10n_util::GetStringUTF8(IDS_DISPLAY_NAME_INTERNAL) only when the process type is empty; child processes use an unlocalized display label. Its commit message explicitly identifies the SoftwareOutputSurface::SwapBuffers() trigger found in this reporter's dump.
- **Runtime delivery and remaining uncertainty:** https://github.com/microsoft/vscode/pull/215954 explicitly backports that Chromium change; https://github.com/microsoft/vscode/pull/216661 ports it to main. Maintainers report delivery through 1.90.2 at https://github.com/microsoft/vscode/issues/212494#issuecomment-2177372049. Current checkout .npmrc selects Electron 43.7.7, and src/mainImpl.ts:171-173 still passes the selected locale to Electron on Linux. No current runtime reproduction was performed, and this thread has no post-fix confirmation; a dependency-version change alone is not proof of non-reproduction.
