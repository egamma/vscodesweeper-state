## Evidence

- **Concrete native crash evidence:** The maintainer-symbolicated attachment https://github.com/user-attachments/files/15518767/symbolicated-f0.log records a startup SIGTRAP in ui::ResourceBundle::GetSharedInstance(), called through l10n_util::GetStringUTF8(), BuildDisplaysFromXRandRInfo(), XRandr interval calculation, and viz::SoftwareOutputSurface::SwapBuffers(). This is a native Chromium display/compositor path, not VS Code's translation-file loading.
- **Second dump is consistent with GPU-process failure:** https://github.com/user-attachments/files/15518766/symbolicated-b5.log records IntentionallyCrashBrowserForUnusableGpuProcess(), reached through GPU-mode fallback and GpuProcessHost::RecordProcessCrash(). The reporter supplied actual crash artifacts, and another user independently reported the same release-time failure in https://github.com/microsoft/vscode/issues/212493#issuecomment-2106223049.
- **Matching upstream diagnosis and behavior-changing fix:** https://github.com/microsoft/vscode/issues/214830#issuecomment-2165650497 identifies the Chromium regression that allowed the software-compositing GPU process to request localized display labels without a resource bundle. https://github.com/chromium/chromium/commit/f8010390a47322ddfe62aba8f7e568a122240dcc changes ui/base/x/x11_display_util.cc so BuildDisplaysFromXRandRInfo calls l10n_util::GetStringUTF8 only in the browser process and uses an unlocalized label in other processes. That directly addresses the failing function sequence in the attached dump.
- **Backport and shipping evidence:** https://github.com/microsoft/vscode/pull/215954 explicitly backports Chromium change 5631219; https://github.com/microsoft/vscode/pull/216661 ports the runtime update to main. A maintainer states that the verified fix was merged for release 1.90.2 in https://github.com/microsoft/vscode/issues/212494#issuecomment-2177372049. These VS Code changes deliver the runtime fix rather than themselves containing the native behavior change.
- **Canonical search:** Searches for language-pack crashes, Russian crashes, l10n_util, and ResourceBundle found the closely matching https://github.com/microsoft/vscode/issues/212494 and its investigation https://github.com/microsoft/vscode/issues/214830, both closed. The former was created after this report, so it also fails the older-canonical requirement for this re-reviewed item; neither is a valid duplicate target.
- **Current-source boundary and verification limit:** src/mainImpl.ts passes the selected locale to Electron on Linux; src/vs/base/node/nls.ts separately resolves and caches VS Code translation messages. Neither inspected path implements the failing native XRandR resource access. No application execution was performed, and the shallow checkout does not contain Chromium's implementation, so current non-reproduction is not established.
