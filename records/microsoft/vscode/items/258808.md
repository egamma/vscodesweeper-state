# Issue #258808 — Customizable Cancel Button Label in withProgress

[https://github.com/microsoft/vscode/issues/258808](https://github.com/microsoft/vscode/issues/258808)

## Summary

Keep this accepted API request open: the notification renderer supports custom cancellation labels internally, but the public window.withProgress API still exposes only a boolean. The request has 23 upvotes and was promoted to Backlog; no verified duplicate or open implementation PR was found.

## Change summary

Allow extensions to customize the cancellation button label for window.withProgress notifications.

## Best solution

Expose a supported, backward-compatible public API for custom cancellation labels while retaining the existing Cancel default and cancellation-token behavior. The API owner should choose between a separate label property and string-valued cancellable before implementation.

- **Behavior:**

  > Extensions can specify a context-specific cancellation button label for window.withProgress at ProgressLocation.Notification through a supported public API. Invoking that button requests cancellation through the existing task token. Existing boolean options retain their current behavior, including the localized Cancel default and no cancellation button when cancellation is disabled. Acceptance includes type-checking a public API example and checking the rendered label and cancellation callback end to end.
- **Trace:**

  > The public ProgressOptions declaration in src/vscode-dts/vscode.d.ts permits only boolean cancellable, while IProgressOptions in src/vs/platform/progress/common/progress.ts already permits boolean | string. ExtHostProgress.withProgress forwards cancellable unchanged, and MainThreadProgress.$startProgress forwards those options into ProgressService. The notification renderer in src/vs/workbench/services/progress/browser/progressService.ts already interprets a string as the cancellation action label. Consequently the missing capability is the supported extension-facing contract, not a missing notification rendering mechanism. Preserve cancellation-token delivery, default localization, other progress locations, and existing notification attribution. https://github.com/microsoft/vscode/issues/258808 proposes cancelLabel, while its discussion also proposes string-valued cancellable; neither contract has been selected on the supplied record.
- **Open decisions:**
  - Should the public API expose a separate cancellation-label property or expand cancellable to boolean | string, and what should empty labels or a label combined with disabled cancellation mean?
