# Issue #64657 — Way to Re-enter Context of the Placeholder Tab Progression While Using Snippets

[https://github.com/microsoft/vscode/issues/64657](https://github.com/microsoft/vscode/issues/64657)

## Summary

The requested recovery of snippet placeholder navigation remains missing: leaving snippet mode disposes its session, and Undo does not restore that session. Keep this accepted Backlog request open; no verified open canonical or concrete implementing fix was found.

## Change summary

Allow Undo to restore snippet placeholder progression after an accidental exit, returning to the placeholder associated with the last edit.

## Best solution

Provide recoverable snippet navigation in the editor snippet controller, preserving ordinary text undo and explicit snippet completion semantics. The product decision should distinguish accidental navigation away from intentional cancellation or completion before implementation.

## Evidence

- **Current session lifecycle:** In src/vs/editor/contrib/snippet/browser/snippetController2.ts, _updateState() calls cancel() when the selection leaves the placeholders. cancel() clears listeners, disposes _session, sets it to undefined, and resets snippet context keys. The existing undo-related version check cancels snippet mode when undo reaches the pre-insertion state; it does not reconstruct a canceled session.
- **Placeholder state is discarded:** In src/vs/editor/contrib/snippet/browser/snippetSession.ts, SnippetSession.dispose() disposes its constituent snippets; their dispose() removes placeholder decorations and clears placeholder groups. Returning the text or cursor to an earlier position therefore does not itself recover placeholder progression.
- **Existing-capability check:** The snippet controller registers jumpToNextSnippetPlaceholder, jumpToPrevSnippetPlaceholder, leaveSnippet, and acceptSnippet. Navigation requires inSnippetMode, so it cannot resume a disposed session. Snippet-related settings in src/vs/editor/common/config/editorOptions.ts control suggestions and tab completion, not canceled-session recovery. The undo test in src/vs/editor/contrib/snippet/test/browser/snippetController2.test.ts covers restoring the original selection after apply(), not resuming an interrupted snippet.
- **Canonical-search result:** GitHub searches for snippet context, snippet resume, snippet undo, and snippet tabstop did not establish an open canonical for this request. The older https://github.com/microsoft/vscode/issues/35099 concerns losing tabstops when switching editor tabs and is closed as a duplicate of https://github.com/microsoft/vscode/issues/27513, which is also closed. Neither is an eligible duplicate target, and switching editor models is a different observable trigger from Undo after accidental snippet cancellation.

Its two upvotes and empty discussion provide no additional maintainer commitment or demand supporting an agent planning session; age alone does not justify declining accepted work.
