# Issue #333933 — Terminal: empty rename does not restore dynamic tab title — stale staticTitle is never cleared

[https://github.com/microsoft/vscode/issues/333933](https://github.com/microsoft/vscode/issues/333933)

## Summary

Traced and confirmed on current main: `_updateTitleProperties` returns early for `undefined` before clearing `_staticTitle`, so an empty rename never clears the stale static title, and `computeLabel`'s `!reset` guard makes it win again on the next refresh — a well-diagnosed, localized bug worth routing to the terminal area.

## Change summary

Renaming a terminal tab to an empty string is supposed to clear the static title and restore the dynamic (process/sequence) title, but the stale static title reasserts itself on the next title update.

## Best solution

In `_updateTitleProperties`/`rename` in `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, clear `_staticTitle` (and reset `_titleSource`) on the empty-rename Api path before the early `undefined` return, so subsequent `computeLabel` calls fall through to the process/sequence title instead of the guard at line 2806.

  > The bug: renaming a VS Code integrated terminal tab to an empty string is meant to clear the custom static title and let the dynamic (process/sequence) title show again, but the stale static title comes back after the next title update.
