# Issue #333933 — Terminal: empty rename does not restore dynamic tab title — stale staticTitle is never cleared

[https://github.com/microsoft/vscode/issues/333933](https://github.com/microsoft/vscode/issues/333933)

## Summary

The original bug (empty rename never clearing `_staticTitle`) was fixed and merged in PR #336599, which closed this issue on 2026-09-17 — but a collaborator reopened it on 2026-09-21 with screenshots showing the default agent-host terminal in the Agents window still doesn't reset its title, so a residual, more specific defect remains that the merged fix doesn't cover.

## Change summary

Empty-renaming a terminal tab should permanently clear the custom static title and restore the dynamic/process title; in the Agents window's default agent-host terminal it still reverts.

## Best solution

Guard the fixed-name reapplication path for agent-host-backed terminals (whose shellLaunchConfig always carries a `name`) so a process-ready/reconnect event never re-stamps the static title after the user has explicitly cleared it — likely a small follow-up in TerminalInstance's onProcessReady handler or in how agentHostTerminalService assigns the fixed profile name.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/browser/agentHostTerminalService.ts`
- **Validation:** Add a regression test creating a terminal with a fixed shellLaunchConfig.name (mirroring the agent-host profile), clear the title via rename(''), simulate a second process-ready/reconnect event, and assert the dynamic title is not overwritten by the static name again.
- **Behavior:**

  > For any terminal whose shellLaunchConfig carries a fixed `name` (as used by agent-host-backed terminals in the Agents window), clearing the custom title via Rename must permanently restore the dynamic title, matching the behavior #336599 already delivers for ordinary terminals. A later process-ready or reconnect event must not silently reapply the original fixed name.
- **Trace:**

  > PR https://github.com/microsoft/vscode/pull/336599 fixed `_updateTitleProperties` in terminalInstance.ts (~L2141) so `rename()` with an empty/undefined title from the API source clears `_staticTitle` and resets `_titleSource` to `Process` — this is confirmed present on main and fixes the general case. However, agent-host-backed terminals get a fixed `shellLaunchConfig.name` (agentHostTerminalService.ts:270), and terminalInstance.ts's onProcessReady handler (~L1528-1529) unconditionally does `this._setTitle(this._shellLaunchConfig.name, TitleEventSource.Api)` whenever that name is set — this reapplies the static title from scratch, bypassing any prior clear, if the handler runs again. Whether onProcessReady actually re-fires for these terminals (e.g. on agent-host reconnect) is the open question a maintainer/agent should confirm before touching anything; do not alter the now-working general rename/clear path for ordinary terminals.
- **Open decisions:**
  - Should the fixed agent-host profile name ever be reapplied after the user explicitly clears the title, or should clearing permanently opt that instance out of the profile-name title until manually renamed again?
  - Is the trigger a repeated onProcessReady firing (e.g. agent-host reconnect) or a different Agents-window-specific title-refresh path — which needs to be confirmed by reproducing in the Agents window before deciding where the guard belongs?
