## Summary

Still present on main: each visible notebook cell subscribes individually to the global `onDidChangeExecution` emitter, triggering the listener leak warning when notebooks have ~200+ visible cells during scrolling. The telemetry re-bucketing in PR #303543 surfaced this pre-existing pattern as a new error bucket, but the underlying per-cell subscription design remains unfixed.

## Change summary

Notebook listener leak warning fires because each visible cell creates a separate subscription to `INotebookExecutionStateService.onDidChangeExecution`.

## Best solution

Restructure `NotebookStatusBarController` to use a single listener on `onDidChangeExecution` that dispatches to the relevant cell's status bar item (keyed by cell handle/URI), instead of creating N independent subscriptions. Alternatively, set an appropriate `leakWarningThreshold` on the emitter if the per-cell pattern is intentional.
