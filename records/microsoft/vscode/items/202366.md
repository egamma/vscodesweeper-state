# Issue #202366 — Add options for closing Tab/TabGroup without saving 

[https://github.com/microsoft/vscode/issues/202366](https://github.com/microsoft/vscode/issues/202366)

## Summary

A real extension API gap remains: `TabGroups.close` still prompts for dirty editors and cannot discard changes for a specified tab or group. This accepted Backlog request exceeded the community upvote threshold and already has appropriate area labels.

## Change summary

Allow extensions to close selected tabs or tab groups programmatically while discarding unsaved changes without showing the save-confirmation modal.

## Best solution

Extend `TabGroups.close` with an explicit, carefully documented close mode for reverting or discarding dirty editors, implemented consistently for individual tabs and groups with safeguards appropriate to a destructive extension API.

- **Fit:** aligned
- **Reason:** Closing this API gap enables extensions to manage their editor workflows without modifying user settings or relying on active-editor commands.
- **Evidence:** Values and durable themes: “The power lives in extensions” and continued investment in extension API hygiene.

## Evidence

- **current API:** src/vscode-dts/vscode.d.ts documents that `TabGroups.close` shows a confirmation dialog for dirty tabs; its only optional argument is `preserveFocus`.
- **current implementation:** src/vs/workbench/api/browser/mainThreadEditorTabs.ts forwards tab closes to `group.closeEditors(editors, { preserveFocus })` and group closes to `group.closeAllEditors()`, exposing no revert or discard option.
- **partial existing capability:** src/vs/workbench/browser/parts/editor/editorActions.ts implements `workbench.action.revertAndCloseActiveEditor`, but it operates only on the active editor and cannot target an arbitrary `Tab` or `TabGroup`; the command was cited for the narrower request https://github.com/microsoft/vscode/issues/183999.
