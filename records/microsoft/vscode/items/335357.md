# Issue #335357 — Wrong error message when remote AH is not available

[https://github.com/microsoft/vscode/issues/335357](https://github.com/microsoft/vscode/issues/335357)

## Summary

The current source still contains the reported mismatch: an unavailable tunnel host is marked disconnected and its cached sessions are then unpublished, preventing the remote-unavailable recovery UI from handling a reopen. This member-authored issue must remain open, and no issue-linked fix or canonical duplicate was found.

## Change summary

Reopening a remote Agent Host chat while remote access is unavailable shows a misleading legacy-chat compatibility error instead of explaining that the remote host is offline.

## Best solution

Keep a known remote session addressable during temporary host unavailability, or otherwise preserve enough routing information for reopening it to show the existing disconnected-host recovery state rather than falling into a legacy compatibility path.
