# Issue #345315 — hasByokModels ignores models from third-party LanguageModelChatProvider extensions unless a provider group exists (signed-out users still see Sign In)

[https://github.com/microsoft/vscode/issues/345315](https://github.com/microsoft/vscode/issues/345315)

## Summary

The detection gap remains in current source: after extension registration, usable extension-provided models cannot make hasByokModels true without a configured provider group. Keep this separate from the related SCM change, which consumes that flag rather than correcting its detection.

## Change summary

Recognize usable extension-provided BYOK models when computing signed-out chat availability, without requiring an unrelated Custom Endpoint group.

## Best solution

Make BYOK availability reflect legitimate extension-provided models as well as configured provider groups, while preserving startup restoration, feature-disable gates, and protection against stale models after group removal.
