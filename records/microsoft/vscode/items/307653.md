# Issue #307653 — Insiders failing to update, logs show "Failed to rename current to old: Access is denied."

[https://github.com/microsoft/vscode/issues/307653](https://github.com/microsoft/vscode/issues/307653)

## Summary

Real Windows update failure caused by the crashpad handler holding a handle on the old executable during inno_updater rename. No fix found on main that addresses this specific file-handle retention issue; the issue remains valid.

## Change summary

VS Code Insiders update fails on Windows because the crashpad-handler process keeps a handle on the old executable, blocking the inno_updater rename step.

## Best solution

The inno_updater or the update flow needs to terminate/release the crashpad handler process before attempting the rename of the current executable to old. Likely involves changes in `build/win32/` (inno_updater Rust source) or `src/vs/platform/update/electron-main/updateService.win32.ts` to ensure the crashpad child process is killed before the update rename proceeds.
