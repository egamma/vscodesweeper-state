# Issue #348222 — EditContext becomes desynchronized when an extension consumes "type"-command without applying a text edit

[https://github.com/microsoft/vscode/issues/348222](https://github.com/microsoft/vscode/issues/348222)

## Summary

The native EditContext synchronization gap remains in current source: consuming typing without changing model text can leave browser text inconsistent with the editor. Route this unlabeled report to the editor area.

## Change summary

Prevent consumed type commands from desynchronizing EditContext and causing subsequent keystrokes to replace document text.

## Best solution

Keep native EditContext consistent with the authoritative editor state when an extension intercepts typing without editing the model, while preserving ordinary typing and IME composition behavior.

- **Behavior:**

  > An extension that consumes the type command without editing the model must not cause later keystrokes to replace document text through a different command. With the supplied cancelSelection override, selecting a line and pressing two printable keys must leave the document unchanged. Ordinary typing over a selection and IME composition must retain their existing behavior.
- **Trace:**

  > In nativeEditContext.ts, browser textupdate events reach _emitTypeEvent, which advances cached selection offsets but leaves _previousEditContextText unchanged. The extension's cancelSelection changes the editor selection, invoking onCursorStateChanged and _updateEditContext; unchanged model text equals the stale text cache, so the browser text is not restored. Subsequent replacement deltas pass through _onType and CodeEditorWidget._createView's compositionType delegate, which can dispatch ReplacePreviousChar independently of composition lifecycle events. Preserve extension command interception, ordinary typing, and composition semantics; do not treat this as a third-party extension defect. The remaining planning work is establishing regression coverage that exercises browser-buffer mutation and asynchronous command interception rather than only testing offset calculations.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode/issues/348222 supplies a minimal type-command override that executes cancelSelection, followed by selecting a line and pressing a key twice. The reporter observed unintended replacePreviousChar commands on Windows and could not reproduce with editor.editContext disabled.
- **Current synchronization defect:** In src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts:427-479, _emitTypeEvent updates _previousEditContextSelection after a browser textupdate but does not update _previousEditContextText. When cancelSelection produces onCursorStateChanged, _updateEditContext compares unchanged model text against that unchanged cached text and skips updateText, although the browser buffer has already changed. This leaves browser text and editor state inconsistent.
- **Unexpected replacement command explained:** NativeEditContext._onType in src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts:482-488 sends nonzero replacement counts through compositionType without requiring compositionstart. In src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts:1961-1971, the command delegate maps a previous-character replacement without other deltas to Handler.ReplacePreviousChar. This matches the reported command despite the absence of composition lifecycle events.
