# Issue #317052 — changed files in agent view have confusing UX

[https://github.com/microsoft/vscode/issues/317052](https://github.com/microsoft/vscode/issues/317052)

## Summary

Keep open for a focused UX decision: pending-edit indicators, viewed state, and the non-Git Changes empty state still convey different concepts without making the distinction clear. Existing diff and review controls partially address the report, but no verified fix or older canonical covers its full scope.

## Change summary

Make agent-created file changes discoverable, clarify whether opening a file clears its indicator, and explain the Changes view when the folder has no Git repository.

## Best solution

Make the Agents Window distinguish pending edits, viewed files, and Git-backed changes clearly, including added files and non-Git folders. Decide whether opening a file records review or whether explicit review remains required, without implicitly accepting edits.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/changes/browser/changesView.ts`, `src/vs/sessions/contrib/changes/browser/changesetReviewActions.ts`, `src/vs/sessions/contrib/changes/browser/changesViewService.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingServiceImpl.ts`
- **Validation:** In the Agents Window, create a session in a folder without Git and ask the agent to create one file and modify another. Open each decorated file and check change visibility, indicator behavior against the chosen review contract, and explanatory Changes empty-state text. Repeat in a Git folder and verify explicit Viewed toggling and added-file diffs still work.
- **Behavior:**

  > Agent-created and modified files should make their changes understandable when opened, including newly created files. Indicators must communicate whether edits are pending or a file has been viewed, without making the user infer that the two states are interchangeable. When Git-backed changes are unavailable because the folder has no repository, the Changes surface should explain that condition rather than imply that the agent changed nothing. Acceptance checks cover both non-Git and Git folders, added and modified files, and the agreed opening/review behavior.
- **Trace:**

  > The chat editing decoration provider in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingServiceImpl.ts maps ModifiedFileEntryState.Modified to Codicon.diffModified with the tooltip “Pending changes from chat”; this is separate from changeset review state. ChangesetReviewAction in src/vs/sessions/contrib/changes/browser/changesetReviewActions.ts provides explicit Viewed toggling. In changesView.ts, _openSingleFileDiffEditor handles added files against an empty original side, while _openFileItem opens a regular file when no originalUri exists; the empty state always says “No changed files” despite an available repository-presence observable. The precise original sidebar route still needs runtime confirmation. Preserve the distinction between viewing and accepting edits and do not change shared workbench decoration semantics solely for Sessions UX without establishing its consumers. https://github.com/microsoft/vscode/issues/316196 covers related missing diff indications; https://github.com/microsoft/vscode/issues/336620 provides broader design context, not replacement ownership.
- **Open decisions:**
  - Should opening an agent-changed file automatically mark it viewed, or should Viewed remain an explicit action with pending-edit indicators clearly distinguished from review state?
