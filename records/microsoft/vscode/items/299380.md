- **Exact-key upstream fix lead:** https://github.com/xtermjs/xterm.js/pull/5752 merged commit 70fe22993b4e923cc6610dde19859ac1631f5f92. Its src/common/input/KittyKeyboard.ts diff changes DISAMBIGUATE_ESCAPE_CODES handling so unmodified Space produces a plain space and Backspace produces legacy \x7f instead of CSI-u sequences. The fix is conditional on negotiated protocol flags, which this Droid report does not establish.
- **Adoption and related resolution:** Merged https://github.com/microsoft/vscode/pull/300822 explicitly adopts xtermjs/xterm.js pull request 5752 and resolves the Textual space-input report https://github.com/microsoft/vscode/issues/299822. This is strong evidence of a potentially covering upstream fix, not proof that Droid on Windows uses the affected disambiguation-only path.
- **Current source trace:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts enables the Kitty keyboard protocol by default. src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts passes config.enableKittyKeyboardProtocol into raw terminal vtExtensions.kittyKeyboard. TerminalInstance's attachCustomKeyEventHandler in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts has no unconditional rejection of unmodified Space or Backspace; its onData handler forwards generated input through _handleOnData to the process manager.
- **Canonical search:** Searches for Droid and terminal keyboard regressions found no verified open issue owning this exact failure. https://github.com/microsoft/vscode/issues/299374 concerns numpad input in enhanced keyboard mode, not ordinary Space and Backspace; sharing the terminal protocol area does not establish a shared root cause.
