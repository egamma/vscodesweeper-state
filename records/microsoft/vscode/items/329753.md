## Summary

Freshly filed, well-evidenced tech-debt issue describing a real architectural split (two unsynchronized 'disabled customization' stores) that already caused a user-visible bug; already correctly labeled `debt`/`chat` and needs a design decision, not triage cleanup.

## Change summary

Consolidate the two independent, unsynchronized stores that track whether a chat customization (prompt/skill) is disabled, so consumers don't have to query both.

## Best solution

A maintainer should decide the consolidation direction (fold the sync-provider overlay into IPromptsService, or make it an explicitly documented harness-scoped overlay with one precedence rule) and land it in promptsServiceImpl.ts / agentCustomizationSyncProvider.ts.
