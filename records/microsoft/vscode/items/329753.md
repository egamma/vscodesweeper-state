# Issue #329753 — Customizations: consolidate the two independent "disabled" stores

[https://github.com/microsoft/vscode/issues/329753](https://github.com/microsoft/vscode/issues/329753)

## Summary

Legitimate, well-diagnosed technical debt: the interim fix for #329751 (merged via PR #329786) already ORs the two disabled-customization stores together in enumerateLocalCustomizationsForHarness, confirming the split is real and unresolved — this issue tracks the structural consolidation that hasn't happened yet.

## Change summary

Consolidate the two independent, unsynchronized 'is this customization disabled' stores (IPromptsService's per-type disabled list vs. the per-harness ICustomizationSyncProvider) into a single source of truth.

## Best solution

Design and land a single disabled-state API (likely on IPromptsService, with the sync provider folded in or made an explicit documented overlay) so future consumers/writers don't need to remember to OR two stores together; the current workaround lives in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLocalCustomizations.ts lines 138-139 and src/vs/sessions/AI_CUSTOMIZATIONS.md documents the split.
