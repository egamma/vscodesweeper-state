## Evidence

- **Current-source defect:** src/vs/platform/terminal/common/environmentVariableCollection.ts:101-110 serializes applyAtShellIntegration mutations into VSCODE_ENV_* using _encodeColons, which replaces ':' with '\x3a' but leaves literal backslashes unchanged. src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh:72-97 then decodes replacement, prepend and append values with echo -e. For the reported HOME=C:\Users\abrahan value, this decodes the colon correctly but also turns '\a' into a bell character.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/240614 was verified OPEN with mergedAt=null and an explicit closing reference to this issue. Its diff changes _encodeColons to escape backslashes before encoding colons. Policy requires keeping an issue with an open linked fixing PR open and forbids a competing agent implementation.
- **Reporter confirmation and workaround:** The supplied discussion confirms the behavior on 1.97.1 and 1.98.0-insider, identifies the encoder/echo -e mismatch, and supplies a workaround that disables automatic injection and preserves HOME around manual shell integration. Python triggers the environment mutation, but the literal-value corruption occurs in VS Code core's serialization/decoding path.
- **Older overlapping report:** https://github.com/microsoft/vscode/issues/212508 was verified OPEN and created on 2024-05-11. https://github.com/microsoft/vscode/issues/212508#issuecomment-2117962943 describes the same observable HOME corruption, with '\t' becoming a tab during shell integration. Its discussion also contains working-directory and activation symptoms; the open PR explicitly linked to the reviewed issue remains the active implementation candidate.
- **Scope boundary:** Preserving literal backslashes addresses escape corruption, not conversion of Windows paths to POSIX paths. The final comment about task substitution of ${userHome} does not by itself establish the same decoding defect and should not expand this fix into general task-path normalization.
