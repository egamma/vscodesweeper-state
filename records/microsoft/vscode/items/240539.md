# Issue #240539 — \ path separators are interpreted as escape sequences when HOME is set in bash terminal

[https://github.com/microsoft/vscode/issues/240539](https://github.com/microsoft/vscode/issues/240539)

## Summary

Confirmed on current main: `_encodeColons` in `environmentVariableCollection.ts` escapes only `:` to `\x3a` but does not escape literal backslashes, so `echo -e` in the bash shell integration script interprets Windows path separators as escape sequences. An open fix PR (#240614) exists but has not been merged.

## Change summary

Windows backslash path separators in environment variable values (e.g. HOME) are corrupted by `echo -e` interpretation in the bash shell integration script because backslashes are not escaped before encoding.

## Best solution

Land the fix from PR https://github.com/microsoft/vscode/pull/240614 (or an equivalent): escape `\` to `\\` in `_encodeColons` in `src/vs/platform/terminal/common/environmentVariableCollection.ts` before the colon encoding, and update the bash/zsh shell integration scripts to decode accordingly. The PR has been open since February 2025 and needs review.
