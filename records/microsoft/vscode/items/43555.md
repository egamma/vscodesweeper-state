## Evidence

- **Verified older open canonical:** https://github.com/microsoft/vscode/issues/15135 is open, was created on 2016-11-07, and requests remembering undo history across restarts/crashes. The maintainer comment at https://github.com/microsoft/vscode/issues/15135#issuecomment-260173681 explicitly calls for persisting any undo stack across all editors, covering the central restart-persistence request here rather than only a particular unsaved-file case.
- **Existing setting does not cover restart persistence:** src/vs/workbench/contrib/files/browser/files.contribution.ts:349-353 registers files.restoreUndoStack. In src/vs/editor/common/services/modelService.ts, _onWillDispose retains undo elements and disposed-model metadata in memory; _createModelData restores them only when that service's _disposedModels map contains the resource. ModelService initializes that map empty, and src/vs/platform/undoRedo/common/undoRedoService.ts:458-469 initializes the edit-stack map empty. This preserves same-session file reopening, not history across a fresh application session.
- **Local history is a partial alternative:** src/vs/workbench/services/workingCopy/common/workingCopyHistoryTracker.ts:70-145 records history entries on saves, while content-change events update version tracking. Local History's restore commands in src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts restore snapshots, not the original granular Ctrl+Z/redo stack. The issue's 2020 comments likewise distinguish tab reopening from application restart.
