# Issue #116989 — DND to download out of remote doesn't work

[https://github.com/microsoft/vscode/issues/116989](https://github.com/microsoft/vscode/issues/116989)

## Summary

Keep open as an upstream drag-and-drop limitation. Current source still exports only local `file:` resources to the browser's `DownloadURL` transfer, while this team-authored Backlog issue tracks remote resources that Electron/Chromium cannot currently materialize on the desktop.

## Change summary

Dragging a file from a remote Explorer to Finder or the desktop should download the file instead of failing or creating a remote-URI link.

## Best solution

Electron/Chromium needs a safe streaming transfer mechanism for non-local resources, after which VS Code can expose remote Explorer files through `fillEditorsDragData`; until then, preserve the context-menu Download action and avoid presenting a misleading external drop where the platform permits that distinction.

- **current source:** `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` calls `fillEditorsDragData` for Explorer drags, but `src/vs/workbench/browser/dnd.ts` sets `DataTransfers.DOWNLOAD_URL` only when `FileAccess.uriToFileUri(firstFile.resource)` has the `file:` scheme. `vscode-remote:` resources therefore still have no downloadable external transfer on current main.
