# Issue #259707 — Consolidate File Changes response part

[https://github.com/microsoft/vscode/issues/259707](https://github.com/microsoft/vscode/issues/259707)

## Summary

The consolidation remains incomplete on current main: extension-contributed file changes and checkpoint/session changes still use separate content parts with overlapping headers, lists, and multi-diff actions. A newer design discussion favors a single working-set UI, so the desired end state should be settled before refactoring.

## Change summary

Consolidate the duplicated inline chat renderers for extension-contributed file changes and checkpoint file-change summaries.

## Best solution

First decide whether extension-contributed file changes should remain inline after the single-working-set direction in https://github.com/microsoft/vscode/issues/282043. Then retain one file-change presentation and shared diff model rather than maintaining parallel list, statistics, expansion, and open-changes implementations.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatChangesSummaryPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/chatResponseFileChangesService.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatChangesSummaryPart.test.ts`
- **Validation:** Exercise both an extension-contributed multi-diff response and checkpoint/provider-backed file changes, verifying that the chosen single presentation reports identical files and line statistics, opens the correct multi-file diff, and does not render a duplicate working set.
- **Behavior:**

  > Chat should have one consistent presentation for a set of changed files, including file count, line statistics, expansion behavior, and opening the multi-file diff. Extension-contributed changes and VS Code-computed checkpoint changes must not produce competing or visually divergent working sets. Acceptance requires validating both response sources and confirming that each set of changes appears exactly once.
- **Trace:**

  > The extension API path introduced by https://github.com/microsoft/vscode/pull/257906 reaches ChatMultiDiffContentPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts. Checkpoint and provider-backed changes reach ChatCheckpointFileChangesSummaryContentPart in chatChangesSummaryPart.ts through separate dispatch in chatListRenderer.ts. Both parts independently build a collapsible file list and an open-changes action, while only the checkpoint path currently exposes aggregate added/deleted counts. The later direction in https://github.com/microsoft/vscode/issues/282043#issuecomment-3656492379 proposes one docked working set and removing response-level change UI; the uncertainty begins where that direction intersects the public extension-contributed response type. Preserve the contributed API's ability to describe original and modified resources, and do not alter unrelated text-edit or notebook-edit rendering.
- **Open decisions:**
  - Should extension-contributed file changes remain as an inline response part, or feed the single docked working-set UI described in the later session design?
  - If an inline contributed part remains, should it expose the same line statistics and interaction semantics as checkpoint changes, or intentionally remain a simpler read-only presentation?

## Evidence

- **original implementation:** https://github.com/microsoft/vscode/pull/257906 introduced the extension-contributed file-changes response part and explicitly noted that its UI duplicated the checkpoint summary.
- **current source:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts still defines ChatMultiDiffContentPart with its own collapsible header, WorkbenchList, file rows, and multi-diff action.
- **parallel implementation:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatChangesSummaryPart.ts still defines ChatCheckpointFileChangesSummaryContentPart and a separate list renderer, including line statistics and its own multi-diff action.
