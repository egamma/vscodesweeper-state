# Issue #334247 — Copliot: Explore agents terminate without prompting or producing output

[https://github.com/microsoft/vscode/issues/334247](https://github.com/microsoft/vscode/issues/334247)

## Summary

Traced this in the source: subagent tool-calling loops (e.g. the search/execution subagents in extensions/copilot, and the core RunSubagentTool) have no special handling for hitting the tool-call/request limit — they can't surface the 'Continue to iterate?' confirmation a top-level agent gets, and can stop mid-round with nothing synthesized, which matches the reporter's exact experience and even the literal 'Agent completed with no output' fallback string in core.

## Change summary

When a subagent (e.g. an Explore agent) hits the configured max-requests/tool-call limit mid-task, it silently terminates without producing a final report or any way to continue, instead of prompting like the top-level agent does.

## Best solution

Give subagent tool-calling loops explicit limit-handling: either force one final 'wrap up and answer now' turn when the limit is hit (similar to the existing background-command nudge in executionSubagentToolCallingLoop.ts) or auto-extend the limit like autopilot mode does, instead of falling through to hitToolCallLimit()'s Stop path with no stream to confirm on.
