# Issue #326920 — Terminal suggest spawns runaway bash processes when npm/yarn package.json lookup reaches /

[https://github.com/microsoft/vscode/issues/326920](https://github.com/microsoft/vscode/issues/326920)

## Summary

Keep open: both package.json lookup loops still contain the malformed root comparison on current main, conclusively explaining the runaway bash processes. Independent Linux and local macOS confirmations support fixing this built-in terminal-suggest defect.

## Change summary

Ensure npm/yarn completion lookups terminate at the filesystem root when no ancestor contains package.json.

## Best solution

Make both package.json generators terminate without package-derived suggestions when no manifest exists, while preserving nearest-ancestor discovery. Track timeout-driven child-process termination as a related hardening concern rather than requiring a shared execution-layer redesign for this bounded fix.

## Evidence

With no package.json ancestor, reaching / leaves both loop conditions false and cd .. makes no progress.
- **Active completion paths:** npm.ts:523 wires npmScriptsGenerator into script completion; yarn.ts imports that generator and uses it at lines 414 and 1286, and uses its own dependenciesGenerator at lines 1260 and 1364. extensions/terminal-suggest/src/fig/autocomplete/generators/scriptSuggestionsGenerator.ts passes the script array directly as a command and arguments with the terminal working directory, so the malformed comparison reaches bash unchanged.

These array-script generators do not set input.timeout. extensions/terminal-suggest/src/fig/shared/utils.ts:65-79 implements the outer timeout as Promise.race with timer cleanup only, while src/shell/common.ts:36-55 contains no explicit child cancellation. Consequently the default promise timeout does not terminate these looping bash processes.
