# Issue #337742 — Agent Host: auto-restored chat registers no BYOK models when restored before the BYOK bridge is wired, so every message fails with modelSelectionFailed

[https://github.com/microsoft/vscode/issues/337742](https://github.com/microsoft/vscode/issues/337742)

## Summary

Confirmed startup race in current main: `_buildSessionConfig` snapshots `bridgeRegistry.getModels()` once via `resolveByokSessionConfig` at resume time, and `_refreshByokModels` only republishes the picker catalog (`_publishModels`) — it never re-applies BYOK provider/model config to an already-launched SDK session. A chat auto-restored before the BYOK bridge is wired is permanently missing its BYOK provider registration, so every later `switchTo` to that model fails.

## Change summary

An Agent Host chat restored at startup before the BYOK bridge connects never gets its BYOK models registered with the SDK session, so every subsequent model-switch to a BYOK/custom-endpoint model fails with 'Provider model ... is not registered'.

## Best solution

Either delay/gate session resume completion on BYOK bridge readiness (with a bounded timeout) or make `_refreshByokModels`/the model-switch failure path re-resolve and re-apply BYOK provider config to already-launched sessions when the bridge becomes ready — likely in `copilotSessionLauncher.ts` / `copilotAgent.ts` (`_resolveByokSessionConfig`, `_refreshByokModels`, `_changeModelOnce`).
