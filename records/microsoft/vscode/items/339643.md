# Issue #339643 — Agent host (Copilot): most of the system prompt is re-written to the prompt cache in every session

[https://github.com/microsoft/vscode/issues/339643](https://github.com/microsoft/vscode/issues/339643)

## Summary

Well-researched, measured cost/latency inefficiency report from a VS Code collaborator, filed to track a real issue with concrete data; the code path matches the described two-block cache structure. No fix exists yet and the right design (runtime-side change vs. restructuring agent-host section contribution) needs a decision, so this stays open for planning.

## Change summary

The agent-host's Copilot system prompt puts a per-session-unique line (session folder path) in the same prompt-cache block as ~20K characters of otherwise-fixed instruction text, so that whole block is rewritten to the cache on every new session instead of being reused.

## Best solution

Either get the Copilot SDK/runtime to apply its stable-sections-first cache layout even for `customize`-mode prompts, or restructure the agent-host's section overrides (src/vs/platform/agentHost/node/copilot/prompts/) so varying content (session folder, commit trailer, environment specifics) is ordered after the fixed tool-instruction text, with behavior-impact of reordering verified via the e2e prompt snapshots.
