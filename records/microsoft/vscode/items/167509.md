# Issue #167509 — Container badges - command to reset all badges

[https://github.com/microsoft/vscode/issues/167509](https://github.com/microsoft/vscode/issues/167509)

## Summary

The capability remains missing on current main: badge visibility can only be restored one container at a time, while the global reset command resets locations but leaves disabled badges unchanged. This team-authored request is accepted in the On Deck milestone and should remain open for workbench design and implementation.

## Change summary

Provide a command that restores badges across all view containers after individual badges have been hidden.

## Best solution

Provide a workbench command that restores badge visibility for every view container and immediately refreshes the activity bar, panel, and secondary-sidebar container actions without changing their locations or other customizations.

## Plan brief

- **Likely files:** `src/vs/workbench/common/views.ts`, `src/vs/workbench/services/views/browser/viewDescriptorService.ts`, `src/vs/workbench/browser/actions/layoutActions.ts`, `src/vs/workbench/browser/parts/compositeBar.ts`, `src/vs/workbench/services/views/test/browser/viewDescriptorService.test.ts`
- **Validation:** Add a view-descriptor-service test that disables badges for multiple containers, invokes the chosen reset command path, and asserts all badge enablement states and persisted views.customizations entries return to their defaults; also validate that rendered container actions in the activity bar, panel, and secondary sidebar update without reload.
- **Behavior:**

  > After users hide badges on any number of view containers, one command restores badge visibility for all containers. The activity bar, panel, and secondary sidebar update immediately without requiring a reload. View locations, pinning, and unrelated view customizations remain unchanged. Re-running the command when all badges are enabled is harmless.
- **Trace:**

  > Badge visibility is profile-persisted through viewContainerBadgeEnablementStates in src/vs/workbench/services/views/browser/viewDescriptorService.ts; saveViewCustomizations() serializes false entries, while reset() currently clears only location maps. The only mutation API in IViewDescriptorService is setViewContainerBadgeEnablementState(id, badgesEnabled). Rendering is owned by CompositeBar.toggleBadgeEnablement() in src/vs/workbench/browser/parts/compositeBar.ts, which refreshes one composite by reassigning its activity list, so a service-level bulk state change alone would not establish live refresh behavior across all pane composite bars. The existing global command registration is workbench.action.resetViewLocations in src/vs/workbench/browser/actions/layoutActions.ts. Preserve view locations and other customization state; this request is limited to restoring badge visibility.
