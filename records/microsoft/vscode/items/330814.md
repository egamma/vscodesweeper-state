# Issue #330814 — Clipboard writes are not visible to other applications since 1.133.0 (Windows)

[https://github.com/microsoft/vscode/issues/330814](https://github.com/microsoft/vscode/issues/330814)

## Summary

Detailed, methodically-ruled-out regression report (reproduces with extensions disabled, affects editor/terminal/About-dialog copy alike) pointing at a Windows clipboard-format regression coinciding with the Electron 42.6.0→42.8.1 bump between 1.129.1 and 1.133.0; no fix exists on main and I cannot execute Windows repro steps from this Linux checkout, so this needs routing and reporter/maintainer confirmation rather than a close.

## Change summary

On Windows, text copied from VS Code (editor, terminal, or the Help > About Copy button) since 1.133.0 can no longer be pasted into any other application, and the previous clipboard content is also destroyed.

## Best solution

Route to the workbench/Electron owners to bisect the Electron 42.6.0→42.8.1 update (or the intervening clipboard-writing code) for a Windows-specific multi-format clipboard write regression — likely in how `clipboard.writeText`/`clipboard.write` is invoked in src/vs/platform/native/electron-main/nativeHostMainService.ts, or an upstream Electron/Chromium clipboard-format bug on Windows; if confirmed upstream, track as `electron-42-update`/`electron-blocker` and consider pinning or patching.
