# Issue #58987 — moving TypeScript files in explorer fails to update/prompt imports when containing folder is moved

[https://github.com/microsoft/vscode/issues/58987](https://github.com/microsoft/vscode/issues/58987)

## Summary

This is a long-standing, actively reported bug with 16 upvotes. The code in updatePathsOnRename.ts does handle folder moves by passing directory paths to TS server's getEditsForFileRename, but the behavior is unreliable — users consistently report that folder moves fail to update imports. The bug is real and unresolved; it carries `help wanted` and belongs in Backlog.

## Change summary

Moving a folder containing TypeScript/JavaScript files in the Explorer fails to prompt for or automatically update import paths in other files that reference those moved files.

## Best solution

Investigate whether the unreliable behavior stems from the VS Code side (e.g. race conditions in buffer syncing, the TS server not being aware of all files in the moved directory) or the TypeScript server's `getEditsForFileRename` implementation for directory paths. The fix likely lives in `extensions/typescript-language-features/src/languageFeatures/updatePathsOnRename.ts`, possibly needing to ensure all files under a moved directory are synced with the TS server before requesting rename edits, or handling the TS server response more robustly.
