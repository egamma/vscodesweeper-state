# Issue #339712 — Same, built-in, message used every time when using append mode in `sessions.chat.experimental.welcomeName`

[https://github.com/microsoft/vscode/issues/339712](https://github.com/microsoft/vscode/issues/339712)

## Summary

Real, source-confirmed bug: the module-level welcome-phrase counter resets to 0 on every window/renderer reload, so the first new-session widget after a reload always lands on index 0 — the first default phrase — regardless of the `append`/`replace` pool, defeating the point of rotating welcome phrases.

## Change summary

With `sessions.chat.experimental.welcomeMessages` set to append mode, the new-session welcome message shows the same built-in phrase on every reload instead of varying.

## Best solution

Replace the simple incrementing `nextNewSessionWelcomePhraseIndex` module counter in newChatWidget.ts with a selection strategy that varies across reloads (e.g. a random pick, or a persisted rotation via storage service) so append-mode custom phrases actually get a chance to show.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/newChatWidget.ts`, `src/vs/sessions/contrib/chat/common/welcomePhrases.ts`
- **Validation:** A test (or manual check) that simulates two separate widget-creation 'sessions' (i.e., resetting the module state as a reload would) and asserts the welcome phrase shown differs, or cycles through the pool, rather than always landing on the same default phrase.
- **Behavior:**

  > Reloading the window (or otherwise getting a fresh new-session composer) should not always show the exact same welcome phrase every time, especially when the user has configured `sessions.chat.experimental.welcomeMessages` in append mode with custom phrases. The shown phrase should vary across reloads so both defaults and appended custom phrases get a chance to appear. Acceptance: after the fix, simulating repeated fresh widget creations (as happens on reload) does not deterministically keep returning index 0 / the same first default phrase every time.
- **Trace:**

  > `nextNewSessionWelcomePhraseIndex` (newChatWidget.ts:99) is a plain module-scope `let`, incremented by `_takeNextWelcomePhraseIndex()` (lines 190-194) each time a `NewChatWidget` is constructed; a full window/renderer reload reinitializes the module, resetting the counter to 0, so the first composer created post-reload always calls `_updateWelcomeMessage(...)` (line 696) with `phraseIndex = 0` against the pool from `getNewSessionWelcomePhrases` (common/welcomePhrases.ts), whose append-mode pool always places the 5 defaults first. Do not change the pool-construction logic in welcomePhrases.ts (its append/replace/fallback semantics are covered by existing tests) — the boundary is purely how `_welcomePhraseIndex` is derived. Open question for the maintainer: should variety come from randomization each load, or from persisting an incrementing/shuffled index via a storage-service key (similar to how `SESSION_OPTIONS_EXPANDED_STORAGE_KEY` is already persisted in this file)?
- **Open decisions:**
  - Should the welcome phrase selection be randomized fresh on every reload, or should rotation state persist across reloads (e.g. via IStorageService) so phrases cycle in order over time?
  - If persisted, at what storage scope (profile/application) should the rotation index live, mirroring the APPLICATION scope of the related settings?

## Evidence

- **root cause:** src/vs/sessions/contrib/chat/browser/newChatWidget.ts:99 declares `let nextNewSessionWelcomePhraseIndex = 0;` at module scope; `_takeNextWelcomePhraseIndex()` (line 190-194) just increments it per widget instance. Since it's a module-level JS variable, it resets to 0 on every full window/renderer reload, so the very first NewChatWidget created after a reload always gets index 0.
- **selection code path:** newChatWidget.ts:692-702 builds the phrase pool via getNewSessionWelcomePhrases(...) (src/vs/sessions/contrib/chat/common/welcomePhrases.ts) which, in append mode, returns `[...defaults, ...customPhrases]` — so index 0 is always the first built-in default phrase, explaining why the reporter always sees the same built-in message after repeated reloads even with custom append phrases configured.
- **feature is experimental/new:** The whole welcome-phrases feature and `NEW_SESSION_WELCOME_MESSAGES_SETTING`/`NEW_SESSION_WELCOME_NAME_SETTING` settings are tagged 'experimental' and were introduced very recently (git log shows newChatWidget.ts's only recent touch is commit 3d5764c1, 'Enable New Session V2 tour in Insiders'); no test exercises reload/rotation behavior (src/vs/sessions/contrib/chat/test/common/welcomePhrases.test.ts only covers pool construction, not index persistence).
