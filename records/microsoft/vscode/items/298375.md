# Issue #298375 — confirmation widget cleanup

[https://github.com/microsoft/vscode/issues/298375](https://github.com/microsoft/vscode/issues/298375)

## Summary

Keep open as accepted UX polish. Current main implements an above-input confirmation carousel and substantial keyboard support, but the member-authored Backlog item has no explicitly linked completion and still leaves user-visible approval hierarchy and interaction decisions unresolved.

## Change summary

Consolidate confirmation prompts above the chat input, clarify one-time versus session-scoped approval choices, and provide predictable keyboard interaction.

## Best solution

Finish the existing above-input confirmation-carousel design so single, batched, and subagent confirmations use one predictable surface, expose one-time and session-scoped approval choices with a deliberate hierarchy, and remain fully operable and discoverable by keyboard and screen reader.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatToolConfirmationCarouselPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatConfirmationWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatToolConfirmationCarousel.css`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`
- **Validation:** Exercise single, batched, and subagent confirmations in local chat, the Agents window, and CLI-backed chat; verify keyboard-only focus, carousel navigation, one-time/session approval selection, skip behavior, focus restoration, and screen-reader help. Add targeted browser tests for the selected action hierarchy and ChatToolConfirmationCarouselPart keyboard navigation.
- **Behavior:**

  > Pending tool confirmations should appear in one predictable surface above the chat input rather than being buried in transcript or collapsed subagent content. The interface must clearly distinguish one-time and session-scoped approval and support completing or skipping confirmations without a mouse. Acceptance covers single, batched, and subagent confirmations in local chat, the Agents window, and CLI-backed sessions, without regressing screen-reader focus or announcements.
- **Trace:**

  > Current main routes eligible tool confirmations from ChatListRenderer into ChatInputPart, which hosts ChatToolConfirmationCarouselPart above the input; the setting is enabled by default. The carousel already implements Left/Right, Home, and End navigation, aggregate Allow All and Skip All actions, and accessible labels. AbstractToolConfirmationSubPart currently determines whether a session-scoped approval or Allow Once is primary, with the other action placed in a dropdown, so the uncertainty starts at the intended user-visible hierarchy and whether it should vary by confirmation type. Chat accessibility help documents the focus and accept commands but should remain synchronized with any interaction changes. Preserve the underlying approval semantics, auto-approval policy, and completed-confirmation transcript behavior. https://github.com/microsoft/vscode/issues/306186 is related subagent evidence, not a canonical replacement for this older polish issue.
- **Open decisions:**
  - When both one-time and session-scoped approval are available, which choice should be the visible primary action and which should live in secondary UI?
  - Should keyboard interaction emulate a CLI-style prompt with direct choice/navigation keys, or retain standard VS Code focus and button navigation?
  - Which confirmation categories should use the above-input carousel, and which, if any, should remain in the transcript because their content or workflow differs?
