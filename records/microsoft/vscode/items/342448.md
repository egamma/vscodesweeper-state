# Issue #342448 — Reconnect only the newest tool call for each shell ID when restoring detached shells in Agent Host chats

[https://github.com/microsoft/vscode/issues/342448](https://github.com/microsoft/vscode/issues/342448)

## Summary

Keep open: current source still does not reconnect restored detached shells to their newest matching tool call. This team-authored follow-up remains distinct from the completed live-streaming and restored-label work.

## Change summary

Restore detached-shell output streaming only into the newest tool call associated with each reused shell ID.

## Best solution

Restored running detached shells should resume streaming into their newest matching tool cards, while older calls sharing their shell IDs remain settled. Keep this within the Copilot shell restoration and terminal-stream paths.

Run the two Copilot shell/session unit suites with scripts/test.sh; no tests were executed during this read-only review.
- **Behavior:**

  > After an Agent Host or Copilot-client restart, a still-running detached shell resumes showing output in its originating tool card. When several historical calls share its shell ID, only the newest matching call receives that output; older calls remain settled. Reobserving the chat must not start duplicate readers. Live streaming and historical output for finished calls remain unchanged.
- **Trace:**

  > CopilotAgentSession.observeBackgroundWork triggers tasks.refresh and tasks.list through _reconcileBackgroundTasks, but that path only reconciles and publishes background work. History reconstruction through _computeMappedEvents restores stored output resources, not live shell streams. _readDetachedShellOutput currently starts only from live tool.execution_complete. NonPtyShellTerminalStreams._continueInBackground replaces ownership for a reused shell ID and finalizes its previous owner; appendChunk then rejects output for that finalized stream. The remaining design work is connecting restored history to task reconciliation while preserving reader lifetime and existing live ownership behavior. https://github.com/microsoft/vscode/pull/341700 explicitly left restart restoration out of scope.
