# Issue #311716 — Sessions: Permission request dialog exposes raw toolCallId to users

[https://github.com/microsoft/vscode/issues/311716](https://github.com/microsoft/vscode/issues/311716)

## Summary

Still reproduces on main: the permission dialog's `toolInput` field is populated by `tryStringify(request)` in the default/custom-tool fallback paths, which serializes internal fields like `toolCallId` and `kind` into the user-facing confirmation UI.

## Change summary

The Copilot CLI permission confirmation dialog exposes raw internal fields (`toolCallId`, `kind`) in the tool input display when falling back to serializing the full request object.

## Best solution

In `getPermissionDisplay` (src/vs/platform/agentHost/node/copilot/copilotToolDisplay.ts), strip internal fields (`toolCallId`, `kind`) before passing the request to `tryStringify` in the default and custom-tool fallback paths — e.g. destructure out `toolCallId` and `kind` and only serialize the remaining user-relevant fields.
