# Issue #339906 — Comparison fails to start due to workspace isolation

[https://github.com/microsoft/vscode/issues/339906](https://github.com/microsoft/vscode/issues/339906)

## Summary

Team-authored, hours-old bug report from a maintainer's own comparison testing (hard keep-open rule applies regardless). The reporter's own follow-up comment already names the likely cause, and tracing the code confirms a plausible mechanism, but there's no fix yet and the right remediation (test setup vs. host fallback) isn't settled.

## Change summary

Starting a model comparison on a brand-new, commit-less git repo fails every attempt with 'Workspace isolation is not supported by this host.'

## Best solution

Either have the comparison test harness seed an initial commit before requesting worktree isolation, or make the comparison/session-creation path gracefully fall back to folder isolation when the host reports only 'folder' as available (instead of throwing) — a maintainer should decide which.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`
- **Validation:** A reproduction/test that starts a comparison (or calls setWorktreeConfiguration with isolationMode: 'worktree') against a freshly `git init`-ed repo with no commits should either succeed with folder isolation or be prevented by the test harness from requesting worktree in the first place.
- **Behavior:**

  > Starting a model comparison (or any session) against a brand-new git repo with no commits should not hard-fail. Either the comparison flow should not request worktree isolation for such a repo, or the host should accept the request and fall back to folder isolation rather than throwing 'Workspace isolation is not supported by this host.'
- **Trace:**

  > resolveIsolationConfig (worktreeIsolation.ts:852-866) forces the isolation schema property to enum ['folder'] / readOnly when _getGitInfo (via _readGitInfo, lines 1779-1798) finds no HEAD commit. setIsolationMode and setWorktreeConfiguration (baseAgentHostSessionsProvider.ts:5782-5799) then call writeSessionIsolation against that restricted enum; requesting 'worktree' returns undefined and both throw the exact error text reported. Do not change the commit-less-repo detection itself (`git rev-parse HEAD` check) — that guard is intentional (git worktree add fails without a commit); the open question is only what the caller does when faced with the resulting folder-only schema.
- **Open decisions:**
  - Should the comparison test harness/tooling (#339373) seed an initial commit in the test repo so worktree isolation is offered, or should the host-side request path accept a 'worktree' request against a commit-less repo and silently fall back to 'folder' isolation instead of throwing?
