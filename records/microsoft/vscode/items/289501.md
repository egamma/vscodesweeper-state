# Issue #289501 — log volume from chat affects perf

[https://github.com/microsoft/vscode/issues/289501](https://github.com/microsoft/vscode/issues/289501)

## Summary

The performance defect remains source-reproducible on current main: content exclusion performs a Git lookup for every uncached file in a non-Git workspace, and each lookup emits multiple trace records. The team-authored report has a confirmed 18,000-line, 30-second impact and should remain open for a bounded fix.

## Change summary

Avoid flooding the Copilot Chat output and consuming CPU when content exclusion examines many files outside a Git repository.

## Best solution

Bound repository discovery and trace output for files in an initialized non-Git workspace while preserving correct invalidation when a repository is later opened or acquires a usable remote.

- **Behavior:**

  > Scanning many files in an initialized workspace with no Git repository must not generate repository-discovery trace records per file or cause output-channel update pressure. - **Trace:**

  > RemoteContentExclusion.isIgnored in extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts first checks `_repoRootCache`, but that cache contains only resolved repository metadata; every distinct file in a non-Git workspace therefore calls IGitService.getRepositoryFetchUrls. GitServiceImpl.getRepositoryFetchUrls in extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts emits a URI trace before discovery and a second trace when getRepositoryRoot returns undefined, producing the reported flood. The existing `should handle files outside any git repository` test exercises only one file, so it does not expose per-file amplification. Preserve the distinction between a workspace with no repository and an existing repository whose remote may appear later; the latter behavior is pinned by `does not cache a repository that resolved without a usable remote`. Do not alter repository-scoped content-exclusion semantics or suppress actionable Git failures.
