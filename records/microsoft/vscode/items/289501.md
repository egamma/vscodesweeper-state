# Issue #289501 — log volume from chat affects perf

[https://github.com/microsoft/vscode/issues/289501](https://github.com/microsoft/vscode/issues/289501)

## Summary

The core log volume issue is partially mitigated by a negative directory cache added in commit 3926f094793 (for a related issue), but the verbose per-call trace logging in getRepositoryFetchUrls remains, and the fix doesn't fully address the first-pass flood when many files are encountered before caching kicks in.

## Change summary

In non-git workspaces with many files (e.g. Python venvs), getRepositoryFetchUrls emits trace logs for every file, flooding the output channel and causing CPU pressure.

## Best solution

Reduce or batch the trace logging in GitServiceImpl.getRepositoryFetchUrls (extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts) — either remove the per-URI entry trace log or gate it behind a counter/summary pattern. The negative directory cache (3926f094793) helps on subsequent lookups but doesn't prevent the initial flood.
