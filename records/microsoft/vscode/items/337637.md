# Issue #337637 — Agent host: pasted images lose their position in the prompt (no inline marker, all files named 'Pasted Image.png')

[https://github.com/microsoft/vscode/issues/337637](https://github.com/microsoft/vscode/issues/337637)

## Summary

Confirmed against current main: the Claude prompt resolver never emits a positional marker tying reference-list entries back to the prompt text, and the on-disk attachment filename is derived from the pasted item's display label rather than a distinct name, so multiple pasted images really do collide on the same basename. This is a real, well-diagnosed gap worth planning, not a bug in existing intended behavior.

## Change summary

Pasted images sent to the agent host lose their position in the prompt text (no inline marker) and are all written to disk under the same generic filename, so a multi-image prompt can't be mapped back to which image is which.

## Best solution

Have the Claude (and likely Codex/Copilot) prompt resolvers emit a stable positional token per pasted image and label the matching reference-list line with the same token, and derive the on-disk attachment basename from something unique (index or hash) instead of the display label; the restore-time raw system-reminder rendering is a related but separate chat-history-rendering issue worth tracking apart from this.

The boundary: do not change how attachments are read from the client or how the reference-list text is otherwise formatted; the fix is scoped to marker insertion + basename uniqueness.
- **Open decisions:**
  - What exact placeholder token/format should be inserted at the paste position (e.g. `[Image 1]`) and how should it be chosen when the user's prompt already contains bracketed text?
  - Should the on-disk basename use a sequential index, a hash, or the existing client-generated unique name, and does changing it risk breaking any existing restore/back-compat assumption about attachment paths?
  - Should this positional-marker/unique-naming fix be applied only to the Claude resolver, or also to the Codex and Copilot prompt resolvers for parity?
  - Is the separate restore-time rendering bug (raw system-reminder text shown instead of a thumbnail) in scope for this issue, or should it be tracked and fixed independently in the chat-history rendering code?

## Evidence

- **filename collision root cause:** src/vs/platform/agentHost/node/agentService.ts:_rewriteSingleAttachment calls `this._attachmentBasename(attachment.label, contentType)` (lines 7178, 7198) to name the on-disk copy written by `_writeAndRewrite` (`joinPath(attachmentsRoot, id, basename)`, line 7264); the label comes from the pasted item's display name (`localize('pastedImageName', 'Pasted Image')` in chatPasteProviders.ts:118), so every pasted image can end up written as the same basename inside its own uuid folder, matching the reporter's `attachments/<uuid>/Pasted Image.png` paths.
