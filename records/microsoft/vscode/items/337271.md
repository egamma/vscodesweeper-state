# Issue #337271 — Title: Copilot Chat agent emits unquoted Windows paths in terminal commands, triggering repeated OpenWith.exe dialogs on profile paths with spaces

[https://github.com/microsoft/vscode/issues/337271](https://github.com/microsoft/vscode/issues/337271)

## Summary

The terminal tool's PowerShell prompt already tells the model to 'Quote paths with spaces: "C:\Path With Spaces"' (src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts, createPowerShellModelDescription), so this isn't a missing-guidance code defect — it's the model not reliably following existing guidance, plus the guidance being conditioned on 'known to have spaces' rather than unconditional. Worth strengthening the wording, but there's no deterministic way to guarantee an LLM always quotes, so this is a prompt-tuning improvement, not a fixable bug.

## Change summary

On Windows, when a user profile path contains a space, the Copilot agent sometimes emits unquoted paths in generated terminal commands (start/Invoke-Item), causing Windows to argument-split the path and pop repeated OpenWith.exe dialogs.

## Best solution

Strengthen the Best Practices bullet in createPowerShellModelDescription (and consider the generic/cmd description) to say paths should ALWAYS be quoted (not just ones already known to contain spaces), since %USERPROFILE%/user-supplied paths aren't guaranteed space-free — this is a prompt wording tweak, not a guaranteed fix given LLM non-determinism.
