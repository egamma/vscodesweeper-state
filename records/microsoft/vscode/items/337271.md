## Summary

Keep open: current terminal-tool guidance already instructs PowerShell agents to quote paths containing spaces, but that does not establish that the reported command-generation failure is fixed. The current execution pipeline has evolved since the report; the supplied Windows profile-path example and shell commands suffice to retest it without requesting basic reproduction information again.

## Change summary

Prevent agent-generated Windows file-opening commands from splitting profile paths containing spaces and producing repeated OpenWith dialogs.

## Best solution

Ensure agent-generated file-opening commands preserve the intended path using syntax appropriate to the actual shell, including cmd.exe start's separate window-title argument. First reproduce the agent-generated command and dialog behavior on Windows, then establish regression checks without changing intentional shell expressions or unrelated terminal execution.
