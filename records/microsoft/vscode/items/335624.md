# Issue #335624 — Word wrapping breaks when line contains right arrow characters (→) with Iosevka SS11 font

[https://github.com/microsoft/vscode/issues/335624](https://github.com/microsoft/vscode/issues/335624)

## Summary

Word wrap in VS Code always estimates pixel widths from a single 'typical halfwidth character' rather than measuring each glyph, so a font whose rendered arrow glyph is wider than that reference (as reported for Iosevka SS11) can defeat the wrap calculation — a real, if narrow, gap worth routing to the editor area rather than closing on a title-only read.

## Change summary

A line made only of repeated → (U+2192) characters does not wrap in the editor when the font is set to Iosevka SS11, even with word wrap enabled.

## Best solution

Editor team should decide whether the fast monospace line-break heuristic in monospaceLineBreaksComputer.ts needs a fallback (or the font-measurement pass in fontMeasurements.ts needs to flag this specific font/glyph combination) when a font's rendered width for common wrap-relevant characters diverges from the measured 'n' reference, or document this as an accepted perf/correctness trade-off for non-standard fonts.
