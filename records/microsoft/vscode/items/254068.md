# Issue #254068 — Asking about `#codebase` on an ADO repo doesn't ask to authenticate

[https://github.com/microsoft/vscode/issues/254068](https://github.com/microsoft/vscode/issues/254068)

## Summary

Still reproduces on main: when `#codebase` triggers `isCodeSearchAvailable(canPrompt=true)`, the canPrompt path only handles GitHub permissive session upgrades via `shouldRequestPermissiveSessionUpgrade()` — it never calls `tryAuthenticating` for ADO repos. The separate `tryAuthIfNeeded` method does handle ADO, but it is not invoked in the availability-check flow that `#codebase` uses. No fix commit references this issue.

## Change summary

Using `#codebase` in Chat on an Azure DevOps repo that requires authentication does not prompt the user to sign in.

## Best solution

In `codeSearchChunkSearch.ts`, the `isCodeSearchAvailable` method's `canPrompt` branch (around line 406) should also trigger ADO authentication (via `tryAuthenticating` or an equivalent path) when repos have `NotAuthorized` status, not just GitHub permissive session upgrades. The `tryAuthIfNeeded` method already has the right ADO logic — it could be called or its logic integrated into the availability check.
