Keep open and route to the Agents Window/Agent Host owners. A maintainer reproduced the missing feedback after the existing notification code had already landed, so current source does not establish that the reported browser-link path is fixed.

- **Behavior:**

  > Opening an external Agents product URL for a nonexistent Agent Host session must open or focus the Agents window and then show one localized error notification explaining that the linked session could not be found. The behavior must work for both cold startup and an already-running Agents window, including when the browser automatically opens VS Code. No unrelated session or chat may be activated.
- **Trace:**

  > The external URL is parsed in `src/vs/code/electron-main/app.ts` by `handleProtocolUrl` or the initial-protocol handling in `openFirstWindow`. `src/vs/platform/windows/electron-main/windowsMainService.ts` forwards the internal session link through the `vscode:selectAgentsFolder` IPC event, and `SelectAgentsFolderContribution` in `src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts` waits for provider discovery before calling `notificationService.error`. That notification branch was introduced by https://github.com/microsoft/vscode/commit/2a9df49a6209a44af84267969ede0c256797c3e1 before this report, so the uncertainty begins at runtime delivery, lifecycle timing, or notification presentation rather than the intended missing-session behavior. Preserve valid-session routing, provider-scoped identifiers, cancellation of superseded opens, and Agent Host interoperability.
