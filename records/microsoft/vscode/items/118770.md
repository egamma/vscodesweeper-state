# Issue #118770 — 3rd button in "Cannot reconnect" dialog that allows you to disconnect

[https://github.com/microsoft/vscode/issues/118770](https://github.com/microsoft/vscode/issues/118770)

## Summary

The requested recovery action remains absent on current main: the permanent reconnect-failure dialog still offers only Reload Window and Cancel. This member-authored feature request has no verified duplicate or implementation and should remain open.

## Change summary

Add a disconnect action to the permanent remote reconnection-failure dialog so users can leave the failed remote and select another Codespace or local folder.

## Best solution

When permanent reconnection fails on desktop, offer the same user-visible outcome as Close Remote Connection directly from the dialog, reusing the window locally without requiring a successful reconnect first.

- **Reason:** A direct recovery path from a failed remote session supports VS Code's durable remote-development direction and reduces unnecessary interaction.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/remote/browser/remote.ts`, `src/vs/workbench/contrib/remote/browser/remoteIndicator.ts`
- **Validation:** Using the test resolver on desktop, force a permanent reconnection failure and verify the dialog exposes keyboard-accessible Reload Window, Close Remote Connection, and Cancel choices; Close Remote Connection must reuse the window locally without reconnecting, while existing web behavior remains unchanged.
- **Behavior:**

  > After a desktop remote connection permanently fails, the dialog should let the user leave that remote without first reconnecting or closing the window. Choosing the disconnect action should reuse the window locally so another remote or local folder can be opened. Reload Window and Cancel must retain their current behavior, and every dialog action must remain keyboard accessible and localized.
- **Trace:**

  > RemoteAgentConnectionStatusListener in src/vs/workbench/contrib/remote/browser/remote.ts handles PersistentConnectionEventType.ReconnectionPermanentFailure by calling dialogService.confirm with only Reload Window as an explicit action. RemoteStatusIndicator in src/vs/workbench/contrib/remote/browser/remoteIndicator.ts already defines the desktop Close Remote Connection outcome through hostService.openWindow({ forceReuseWindow: true, remoteAuthority: null }). That command is deliberately unavailable on web through SHOW_CLOSE_REMOTE_COMMAND_ID = !isWeb, so the scope should preserve the existing platform boundary. Existing reconnect progress states, automatic retries, Reload Window behavior, and resolver-owned handled failures are outside this request. The related https://github.com/microsoft/vscode/issues/318383 concerns application exit while the modal is active and is not a canonical for this work.
