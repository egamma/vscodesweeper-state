# Issue #331832 — Agents window does not restore completed remote AHP turn after laptop wake

[https://github.com/microsoft/vscode/issues/331832](https://github.com/microsoft/vscode/issues/331832)

## Summary

Plausible, well-described defect in the Agents window's reconnect-after-wake path for remote AHP sessions, but without captured Agent Host debug logs or a source-level trace of exactly where the reconnect resync drops the terminal turn state, it isn't verifiable yet — asking for logs (as the two related issues did) is the useful next step.

## Change summary

After a laptop sleeps mid-turn against a remote AHP host and the turn completes remotely, reopening the laptop and reconnecting leaves the turn looking stuck in the Agents window until a full window reload.

## Best solution

Have the reporter attach an Export Agent Host Debug Logs bundle (or sanitized excerpts) covering the sleep/reconnect window, then trace whether the soft-reconnect path in agentHostProtocolClient.ts / the session subscription in agentHostSessionHandler.ts (`_reconnectToActiveTurn`, `_observeTurn`) properly re-syncs `activeTurn` completion after a hard transport drop, versus only picking it up on a fresh `provideChatSessionContent` call at reload.

## Evidence

- **reconnect infra:** src/vs/platform/agentHost/browser/agentHostProtocolClient.ts implements a soft-reconnect state machine (`AgentHostClientState.Reconnecting`) that replays missed root state via a protocol-level `reconnect` RPC, so a resync path exists but its coverage of turn-completion for an already-open session isn't traced here.
- **reconnect-to-turn wiring:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts `_reconnectToActiveTurn` (~line 4858) wires an `_observeTurn` watcher with `onTurnEnded: () => chatSession.complete()`, driven by a derived observable over the session subscription — if that subscription doesn't re-emit after a hard drop/reconnect, completion would silently not fire, matching the reported symptom.
- **related but distinct:** https://github.com/microsoft/vscode/issues/330888 (closed, fixed in 1.134.0) is a different mechanism — an SDK queue-processing failure orphaning an active turn, not a client-reconnect resync gap.
- **related but distinct:** https://github.com/microsoft/vscode/pull/331310 (open PR) fixes turn-ownership confusion when two turns overlap and a later turn's completion incorrectly closes an earlier one's response — a different race, not a wake/reconnect scenario.
- **no logs:** Issue body states 'Logs: Not captured'; the two related, team-diagnosed issues relied on exported Agent Host debug bundles with correlated timestamps to pin the exact failure point.
