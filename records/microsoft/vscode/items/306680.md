# Issue #306680 — Built-in Source Control does not properly work with a worktree in WSL

[https://github.com/microsoft/vscode/issues/306680](https://github.com/microsoft/vscode/issues/306680)

## Summary

The report conflates installing VS Code on Windows with running Git on Windows. The documented WSL workflow keeps the Windows application but runs workspace tools inside WSL, where the worktree's /mnt/c gitdir path is meaningful.

## Change summary

Recognize a WSL-created Git worktree whose .git file references /mnt/c when opening it from the Windows application.

## Best solution

Use the Windows-installed VS Code with the WSL extension and open the worktree in a WSL-connected window, so repository discovery uses WSL Git rather than Windows Git. No core change is established by the reported local-window behavior.
