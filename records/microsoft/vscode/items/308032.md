[https://github.com/microsoft/vscode/issues/308032](https://github.com/microsoft/vscode/issues/308032)

## Summary

Team-authored UX polish request: the Customizations view in the Agents window should default its harness target to match the user's current session rather than showing Copilot CLI customizations. No commit references this issue, and while significant refactoring has happened in the harness service area, the specific default-on-open behavior may still be wrong.

## Change summary

The Customizations view in the sessions/agents window defaults to showing Copilot CLI customizations instead of the agent host customizations matching the current session.

## Best solution

Ensure that when the Customizations view opens, `setActiveSession` in the harness service is called with the current active session's resource so the view reflects the correct harness. The logic likely lives in `src/vs/sessions/contrib/sessions/browser/customizationsToolbar.contribution.ts` (the `ActiveSessionHarnessSyncContribution`) or in the customization editor open path. The `openCustomizationOverviewPage` function already calls `harnessService.setActiveSession(sessionResource)` — verify this fires reliably before the view renders.
