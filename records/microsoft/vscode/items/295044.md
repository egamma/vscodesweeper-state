# Issue #295044 — Add an enterprise policy to accept JSON settings

[https://github.com/microsoft/vscode/issues/295044](https://github.com/microsoft/vscode/issues/295044)

## Summary

The requested generic JSON policy remains missing: current extension policies require individually registered metadata. Keep this older report open; the closely matching request at https://github.com/microsoft/vscode/issues/312764 is newer and cannot be its duplicate canonical under the re-review rules.

## Change summary

Allow administrators to enforce extension-contributed settings through a generic JSON enterprise policy without adding a dedicated policy for each setting.

## Best solution

Design a supported JSON settings policy with explicit eligibility, validation, and precedence semantics, retaining the Live Share example as an acceptance case. Coordinate the overlapping work with https://github.com/microsoft/vscode/issues/312764 without closing this older report against it.

## Plan brief

- **Likely files:** `src/vs/platform/configuration/common/configurations.ts`, `src/vs/platform/configuration/common/configurationModels.ts`, `src/vs/workbench/api/common/configurationExtensionPoint.ts`, `src/vs/platform/configuration/test/common/policyConfiguration.test.ts`, `src/vs/platform/configuration/test/common/configurationModels.test.ts`
- **Validation:** After the policy contract is agreed, add targeted tests in policyConfiguration.test.ts and configurationModels.test.ts showing that an extension-contributed setting without dedicated policy metadata receives its administered value despite conflicting user/workspace values, that policy removal restores ordinary configuration resolution, and that invalid entries follow the agreed validation semantics. Exercise the agreed JSON payload through the supported enterprise backends.
- **Behavior:**

  > Administrators want to supply a JSON map of extension-contributed settings and enforce those values without a dedicated policy registration for every key. The concrete acceptance example is the three Live Share settings in https://github.com/microsoft/vscode/issues/295044. Managed values should take precedence over ordinary settings, and removing the policy should restore ordinary resolution. The plan must settle eligible settings, invalid-entry behavior, and conflicts with existing dedicated policies; system-wide defaults are a separate request.
- **Trace:**

  > PolicyConfiguration in src/vs/platform/configuration/common/configurations.ts discovers and applies only settings with policy or policyReference metadata. Extension metadata is attached from product.extensionConfigurationPolicy in src/vs/workbench/api/common/configurationExtensionPoint.ts, so supporting selected extension settings still requires individual catalog entries. FilePolicyService.read in src/vs/platform/policy/common/filePolicyService.ts filters JSON input against registered policy definitions. Configuration.getConsolidatedConfigurationModel in src/vs/platform/configuration/common/configurationModels.ts applies the resulting policy layer after normal configuration consolidation. The uncertainty is the public contract for admitting arbitrary extension settings into that layer, not whether JSON parsing already exists. Preserve dedicated policy behavior and ordinary configuration resolution outside the administered keys; do not imply that configuration enforcement can constrain an extension that ignores configuration. Coordinate with the newer overlapping request at https://github.com/microsoft/vscode/issues/312764, whose additional defaults scope is not required by this report.
- **Open decisions:**
  - Which extension settings are eligible for generic enforcement, including resource-scoped or language-specific settings and keys not yet registered by an installed extension?
  - When a generic JSON entry conflicts with an existing dedicated enterprise policy for the same setting, which value is authoritative?
  - Does an invalid or unsupported entry reject the entire JSON payload, or are valid entries applied with explicit diagnostics for rejected entries?
