# Issue #110459 — Make API commands simpler to consume

[https://github.com/microsoft/vscode/issues/110459](https://github.com/microsoft/vscode/issues/110459)

## Summary

This API design proposal to add typed overloads for well-known API commands (via an ApiCommandMap interface) has not been implemented — the current executeCommand signature remains fully generic with no type-safe overloads. Filed by a team contributor and labeled under-discussion; keeping open.

## Change summary

Add TypeScript-typed overloads for known VS Code API commands so extension authors get parameter and return type checking when calling executeCommand.

## Best solution

The API team should revisit whether a typed ApiCommandMap pattern (or similar TypeScript gymnastics) can be layered onto vscode.d.ts to provide compile-time safety for known API commands like vscode.open and vscode.diff, while keeping the generic fallback for arbitrary commands.
