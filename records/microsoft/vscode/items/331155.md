# Issue #331155 — Copilot Agent Host sessions take ~60 seconds to appear after restart with a large ~/.copilot catalog

[https://github.com/microsoft/vscode/issues/331155](https://github.com/microsoft/vscode/issues/331155)

## Summary

Active, still-unresolved perf regression under maintainer investigation by sandy081, with a real 1.136.0 milestone and reported by a collaborator on a reopened issue — hard keep-open rules (team-authored, assigned non-holding-bin milestone, mid-investigation) all bar a close here.

## Change summary

After VS Code restart with a large ~/.copilot session catalog (1,000+ sessions), Copilot Agent Host sessions take tens of seconds to appear because listSessions() queues behind a full SDK catalog discovery/classification pass instead of rendering from the cached session list.

## Best solution

Maintainer (sandy081) is actively diagnosing this in AgentService/CopilotSessionProvider discovery code (introduced by PR #331082 on top of PR #329633); the fix should decouple listSessions() from the discovery classification pass so cached sessions render immediately while discovery runs in the background. No fix has landed yet as of the latest comment (2026-08-30).
