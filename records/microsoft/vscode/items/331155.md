# Issue #331155 — Copilot Agent Host sessions take ~60 seconds to appear after restart with a large ~/.copilot catalog

[https://github.com/microsoft/vscode/issues/331155](https://github.com/microsoft/vscode/issues/331155)

## Summary

Traced on current main and still open: `AgentService.listSessions()` → `_computeSessions()` still calls `_awaitInitialProviderMigration()` before returning (agentService.ts:1930, explicit comment 'The first list waits for registration-time legacy migration if it is still in flight'), which for Copilot drives `listChatsToMigrate()` (copilotAgent.ts:2317) to open a per-session database for every entry in the SDK catalog via `_readStoredSessionMetadata`, bounded only by a 4-way `Limiter`. With ~1,200+ sessions this still blocks every window's first session list for a long time, matching the reporter's second recording (still ~100s) after reopening.

## Change summary

On restart with a very large ~/.copilot session catalog, Agents-window session listing blocks on a full legacy-migration classification pass instead of rendering from the persisted cache, delaying visible sessions by roughly a minute or more.

## Best solution

Decouple `listSessions()` from the one-time legacy-migration completion for large catalogs — e.g. serve the persisted `localAgentHost.cachedSessions.v2` snapshot immediately while `_ensureLegacyChatsMigrated`/`listChatsToMigrate` runs in the background and additively registers newly-classified sessions, rather than awaiting the full per-database classification pass in `_awaitInitialProviderMigration` before any list is returned.
