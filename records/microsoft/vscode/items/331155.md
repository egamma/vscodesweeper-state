# Issue #331155 — Copilot Agent Host sessions take ~60 seconds to appear after restart with a large ~/.copilot catalog

[https://github.com/microsoft/vscode/issues/331155](https://github.com/microsoft/vscode/issues/331155)

## Summary

Freshly filed, well-diagnosed performance bug by a VS Code collaborator with a precise root-cause trace; code on main confirms the described blocking behavior, and no fix has landed yet — correctly labeled and needs no triage change beyond staying open for a fix.

## Change summary

listSessions() blocks on Copilot's full SDK catalog discovery/classification before returning, so with a large ~/.copilot catalog (~1,200 sessions) Copilot sessions take ~60s to appear in the Agents window after restart instead of rendering from the existing cache.

## Best solution

In AgentService.listSessions() / _awaitInitialProviderMigration() (src/vs/platform/agentHost/node/agentService.ts) and CopilotAgent._discoverCopilotChats() (src/vs/platform/agentHost/node/copilot/copilotAgent.ts), let Copilot sessions render from the existing localAgentHost.cachedSessions.v2 cache immediately while the classification/discovery pass introduced by PR #331082 continues in the background, instead of gating the whole list on it.
