# Issue #331155 — Copilot Agent Host sessions take ~60 seconds to appear after restart with a large ~/.copilot catalog

[https://github.com/microsoft/vscode/issues/331155](https://github.com/microsoft/vscode/issues/331155)

## Summary

Real, actively-reproducing performance bug reported by a team member and confirmed still present in a follow-up comment; it also carries an assigned version milestone (1.135.0), which is a hard keep-open rule regardless of other evidence.

## Change summary

listSessions() blocks on Copilot's full-catalog discovery/classification pass on restart, so Copilot sessions in the Agents window take up to ~60-100s to appear when ~/.copilot has a large session store, instead of rendering from the persisted cache immediately like other providers.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts, listSessions() (via _awaitInitialProviderMigration) should not block on the Copilot provider's full catalog classification (src/vs/platform/agentHost/node/copilot/copilotAgent.ts, _discoverCopilotChats); instead render from the persisted localAgentHost.cachedSessions.v2 cache immediately and merge in newly discovered sessions incrementally, mirroring how other providers already behave.
