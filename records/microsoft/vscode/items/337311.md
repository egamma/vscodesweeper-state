# Issue #337311 — Support env configuration in .mcp.json and migrate from .vscode/mcp.json

[https://github.com/microsoft/vscode/issues/337311](https://github.com/microsoft/vscode/issues/337311)

## Summary

Thanks for the proposal. It is a maintainer-driven feature with a confirmed user impact, and the gap still exists on main. It stays open. The newer related issue 340161 is narrower (inputs and variables), so it is not a duplicate target.

## Change summary

Add env-variable references to .mcp.json and the user-level .copilot MCP config, and provide a migration path from .vscode/mcp.json with ${input:...} variables.

## Best solution

Define portable env-variable reference semantics for .mcp.json and the .copilot config. Then add a migration or refactor from .vscode/mcp.json that converts eligible inputs to env references, reports which variables must be set, never writes secret values, and keeps a compatibility period. Coordinate with the narrower follow-up at https://github.com/microsoft/vscode/issues/340161.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupportScope.ts`
- **Validation:** A unit test, alongside agentHostMcpServerSupport.test.ts, that a migrated server with an env reference is supported and that no resolved secret is written to the output file.
- **Behavior:**

  > Users can reference environment variables in .mcp.json and in user-level .copilot MCP config. A migration converts .vscode/mcp.json servers to the right target by scope, turns eligible ${input:...} secrets into env references, and tells users which variables to set. Resolved secrets are never written to files, logs, or telemetry. Existing .vscode/mcp.json keeps working during a defined deprecation window.
- **Trace:**

  > The agent host currently flags input and command variables as unsupported in agentHostMcpServerSupportScope.ts and its test. Where the uncertainty starts: the env reference syntax, which servers count as repo-scoped vs user-scoped, and how inputs map to env. The boundary is not to extend .vscode/mcp.json further and not to break existing configs. Related: https://github.com/microsoft/vscode/issues/340161.
- **Open decisions:**
  - Which env-reference syntax should .mcp.json use, and should it match Copilot or Claude Code behavior?
  - How are servers split between repo .mcp.json and user .copilot config?
  - What is the compatibility and deprecation behavior for .vscode/mcp.json?
  - What is the in-editor experience when a required variable is missing?
