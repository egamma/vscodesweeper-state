# Issue #337311 — Support env configuration in .mcp.json and migrate from .vscode/mcp.json

[https://github.com/microsoft/vscode/issues/337311](https://github.com/microsoft/vscode/issues/337311)

## Summary

Portable environment-variable expansion and part of the migration already exist, but migration of secret-bearing `${input:...}` references remains unsupported in current source. Keep this open for maintainer review: the credential-exposure concern also invokes the security-sensitive keep-open rule.

## Change summary

Support portable MCP environment references and safely migrate workspace and user configurations without exporting secret values.

## Best solution

Complete reference-only input migration to workspace `.mcp.json` and user `.copilot/mcp-config.json`, explain which variables users must set, and preserve legacy configurations that cannot migrate safely. Coordinate the remaining behavior with https://github.com/microsoft/vscode/issues/340161, retaining the configuration-versus-secret boundary highlighted in this discussion.

## Evidence

- **Confirmed user scenario:** https://github.com/microsoft/vscode/issues/337311#issuecomment-6086270588 describes a working legacy server using `${input:discord-bot-token}` with a password prompt becoming unavailable in the Copilot Agent Host. Replacing the reference with a literal restored functionality, but exposed the credential in agent-visible configuration artifacts.
- **Existing capability covers only part of the request:** src/vs/workbench/contrib/mcp/common/mcpEnvironmentVariableExpansion.ts implements `${VAR}` and `${VAR:-default}` expansion in stdio command, args and env values, plus accepted HTTP URLs and header values. workspaceDotMcpDiscovery.ts enables this for workspace portable configurations; nativeMcpDiscoveryAdapters.ts enables it for Copilot user configuration.
- **Migration gap remains in current source:** src/vs/workbench/contrib/chat/browser/aiCustomization/mcpServerCustomizationMigration.ts:789-834, analyzeSourceConfiguration, handles `${env:...}` but rejects other non-portable variables, including `${input:...}`, as UnrepresentableConfiguration. rewriteEnvironmentVariables at lines 918-968 rewrites `${env:NAME}` to `${NAME}`; it does not convert input definitions.
- **Observed message matches the source:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupportScope.ts:96 contains the reported 'Input and command variables are not supported by the Copilot harness' message. Existing migration infrastructure therefore does not establish completion of the reported input-based migration.
