# Issue #340966 — Agent host: no-op root config changes make every Copilot session re-push sandbox config (and more) to copilot-runtime

[https://github.com/microsoft/vscode/issues/340966](https://github.com/microsoft/vscode/issues/340966)

## Summary

Thanks for the detailed write-up. This is a team-authored perf issue filed one day ago with no fix or canonical duplicate identified, so it stays open. I did not trace the cited code paths in the checkout, so the diagnosis is taken from the report and is not independently confirmed.

## Change summary

Unchanged root/configChanged dispatches make every loaded Copilot agent-host session re-push sandbox config, shell init script and other state to copilot-runtime, which may contribute to a CPU spike.

## Best solution

Drop no-op root config changes in AgentConfigurationService, or include the changed keys in the event, so onDidRootConfigChange only fires on real changes. Scope CopilotAgentSession handlers to the relevant keys and have the workbench stop re-sending identical workspaceTrust and terminalAutoApproveRules values.
