# Issue #340966 — Agent host: no-op root config changes make every Copilot session re-push sandbox config (and more) to copilot-runtime

[https://github.com/microsoft/vscode/issues/340966](https://github.com/microsoft/vscode/issues/340966)

## Summary

Keep open: current main suppresses identical root-config actions and deduplicates sandbox updates, but genuinely changed, unrelated root keys still fan out into every loaded Copilot session. The remaining fan-out is traceable in source; its contribution to the reported runtime CPU spike still needs measurement.

## Change summary

Prevent unchanged or unrelated root configuration updates from triggering redundant Copilot session and runtime work.

## Best solution

Retain the existing no-op and sandbox deduplication guards, and eliminate remaining unrelated-key work in the agent-host configuration consumers. Measure per-change runtime requests across multiple loaded sessions before attributing the CPU spike to a particular handler.
