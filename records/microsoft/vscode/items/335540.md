# Issue #335540 — Inter-session communication should use steering messages

[https://github.com/microsoft/vscode/issues/335540](https://github.com/microsoft/vscode/issues/335540)

## Summary

Coherent, freshly filed feature request with no maintainer signal yet — routing to the chat/agent-host area so it can be triaged by the team that owns the steering-message mechanism.

## Change summary

When a follow-up message is sent while an agent session is mid-turn, it should be delivered as a real-time steering message (injected into the active turn) rather than only queued to be sent after the turn ends, since long-running turns can leave queued messages waiting indefinitely.

## Best solution

Have the chat queue-drain logic (src/vs/workbench/contrib/chat/browser/actions/chatQueueActions.ts) hand off to the existing agent-host steering-message channel (setPendingMessages / steeringMessage in src/vs/platform/agentHost/common/agent.ts and channels-chat/state.ts) instead of strictly waiting for turn completion, at least as an option — this is a design/product decision for the chat and agent-host owners, not a small localized fix.
