# Issue #332917 — BYOK OpenRouter: hover shows Max context 1M instead of 256K for ":free" variants (discovery prefers top-level context_length over top_provider.context_length)

[https://github.com/microsoft/vscode/issues/332917](https://github.com/microsoft/vscode/issues/332917)

## Summary

Confirmed on current main: `resolveModelCapabilities` in `openRouterProvider.ts` deliberately prefers the top-level `context_length` over `top_provider.context_length`, which is correct for most multi-provider models but wrong for `:free` variants where OpenRouter's filtered discovery endpoint reports the parent paid model's larger context at the top level. This causes the hover to overstate the max context and can lead to requests exceeding the true limit.

## Change summary

BYOK OpenRouter model discovery picks the wrong (larger) context-length field for `:free` model variants, so the model picker hover advertises a bigger max context than the route actually supports.

## Best solution

In `resolveModelCapabilities` (extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts), take the smaller of `context_length` and `top_provider.context_length` (falling back to whichever is present) instead of unconditionally preferring the top-level value, so `:free` routes report their true, smaller cap while multi-provider models keep the larger, correct top-level value.
