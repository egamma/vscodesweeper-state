# Issue #332917 — BYOK OpenRouter: hover shows Max context 1M instead of 256K for ":free" variants (discovery prefers top-level context_length over top_provider.context_length)

[https://github.com/microsoft/vscode/issues/332917](https://github.com/microsoft/vscode/issues/332917)

## Summary

Keep open: the public OpenRouter catalog still returns conflicting context limits for the reported free route, and current discovery propagates the larger value. This is an upstream metadata inconsistency; globally taking the smaller value would regress the multi-provider behavior explicitly covered by existing tests.

## Change summary

Make the advertised context window for OpenRouter free variants match the route's actual limit rather than its paid parent's limit.

## Best solution

OpenRouter should return the free route's correct context_length consistently on its filtered catalog endpoint. Any VS Code-side mitigation should preserve full context windows for multi-provider models rather than universally treating top_provider.context_length as a cap.

## Evidence

- **Current public API evidence:** Read-only unauthenticated requests during this review confirmed that https://openrouter.ai/api/v1/models?supported_parameters=tools returns context_length=1048576 and top_provider.context_length=262144 for poolside/laguna-s-2.1:free, while https://openrouter.ai/api/v1/models returns 262144 for both fields. The upstream inconsistency reported on 2026-08-27 remains observable.
- **Current discovery path:** extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts: OpenRouterLMProvider.getModelsDiscoveryUrl selects the tools-filtered endpoint, and resolveModelCapabilities intentionally prefers context_length over top_provider.context_length. For the observed response it calculates maxInputTokens=1015808 and maxOutputTokens=32768, totaling 1048576.
- **Metadata propagation:** extensions/copilot/src/extension/byok/vscode-node/abstractLanguageModelChatProvider.ts:getModelsFromEndpoint passes discovered entries to resolveModelCapabilities and caches their capabilities. extensions/copilot/src/extension/byok/common/byokProvider.ts:resolveModelTokenLimits and byokKnownModelToAPIInfo preserve that total as maxContextWindowTokens; the newer explicit context-window metadata does not correct the catalog discrepancy.
- **Conflicting regression requirement:** extensions/copilot/src/extension/byok/vscode-node/test/openRouterProvider.spec.ts explicitly requires retaining a 1048576-token model window when the highest-ranked provider reports only 32000. Its associated issue, https://github.com/microsoft/vscode/issues/324671, is closed and describes underestimating multi-provider capacity, not overestimating a free variant. It is neither a duplicate target nor proof that this report is fixed.
- **Canonical search:** The OpenRouter/context search found https://github.com/microsoft/vscode/issues/316402, which remains open but requests increasing an advertised limit to 1M, and https://github.com/microsoft/vscode/issues/293125, whose discussion concerns stale context-usage updates and model switching. Neither establishes the same free-route overstatement required for a duplicate close of this re-reviewed item.
- **Discussion and ownership:** The reporter confirmed the same symptom on VS Code 1.135.0 after the upgrade request and documented an upstream report at https://discord.com/channels/1091220969173028894/1542502332435267604. Copilot's OpenRouter integration is in this repository, so this is not a caused-by-extension close or a reason to redirect the VS Code report.
