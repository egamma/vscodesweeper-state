# Issue #207547 — Clicking on an output and using Up/Down arrows scrolls through cells of another notebook

[https://github.com/microsoft/vscode/issues/207547](https://github.com/microsoft/vscode/issues/207547)

## Summary

Still appears unfixed on main: no commit references this issue, and the focus-tracking mechanism in notebookEditorWidget.ts relies on DOM ancestry checks that can leave the wrong notebook's NOTEBOOK_EDITOR_FOCUSED context key set when focus moves to an output webview in a different notebook.

## Change summary

When clicking an output in a side-by-side notebook and pressing Up/Down arrows, cell navigation incorrectly activates in the previously focused notebook instead of the one owning the output.

## Best solution

The fix likely needs to ensure that when a BackLayerWebView output gains focus, the NOTEBOOK_EDITOR_FOCUSED context key is properly cleared on sibling notebook editors. The focus-tracking in notebookEditorWidget.ts (around updateEditorFocus/editorHasDomFocus) and the webview focus notification path need to coordinate across editors — likely in the notebook editor service or via the focus tracker's blur handling when focus leaves for a webview in a different editor instance.
