# Issue #324615 — I should be able to drag and drop sessions into the chat editor

[https://github.com/microsoft/vscode/issues/324615](https://github.com/microsoft/vscode/issues/324615)

## Summary

Keep open: current source supports dragging certain chat tabs into agent-host inputs, but session-list dragging still takes the generic editor attachment path. This team-authored request has no verified issue-referencing fix or older canonical covering the same behavior.

## Change summary

Allow dragging a supported prior session into the chat input to attach it as conversation context.

## Best solution

Make supported session-list drops provide the same session context as the existing session attachment picker, preserving its provider restrictions and existing editor-opening drag behavior. The newer chat-tab reference capability is partial coverage, not a replacement for session-list attachment.

## Evidence

- **Requested context:** https://github.com/microsoft/vscode/issues/324615 reports that dragging a chat into the input does nothing while testing https://github.com/microsoft/vscode/issues/324418. That test plan explicitly covers attaching prior agent-host and extension-host Copilot CLI sessions as context, with other session providers excluded.
- **Existing capability and remaining gap:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts registers sessionReference completion through #session:. However, AgentSessionsDragAndDrop.onDragStart in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsViewer.ts exports session resources using fillEditorsDragData, not the CHAT_REFERENCE payload understood by the newer chat-specific drop handler.
- **Session-list drop path:** In src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts, generic editor payloads go through resolveEditorAttachContext. In src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentResolveService.ts, that path handles browser views, untitled resources and filesystem-backed resources; it has no sessionReference conversion and returns undefined when fileService.stat fails. Session-list dragging therefore does not reuse the session attachment capability.
- **Partial implementation, not a qualifying fix:** https://github.com/microsoft/vscode/commit/bffadde2f0ab0d7381284f8086a90b40b9c184c1 adds chat-tab drops into agent-host inputs, producing chatReference attachment pills with self-reference and cross-host restrictions. Its changed files do not include the workbench session-list drag producer, and its commit message does not reference this issue. It does not establish completion of this team-authored request.
