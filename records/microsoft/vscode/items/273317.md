# Issue #273317 — Walkthrough pops up after creating a devcontainer

[https://github.com/microsoft/vscode/issues/273317](https://github.com/microsoft/vscode/issues/273317)

## Summary

Still appears unfixed on main: when a devcontainer is created the window reconnects as a new remote window (not `StartupKind.ReloadedWindow`), so the startup page guard on line 139 of startupPage.ts doesn't suppress the walkthrough — the fresh application-scoped storage with a new data dir makes it eligible to show.

## Change summary

The VS Code setup walkthrough incorrectly pops up after creating a devcontainer because the remote reconnection is treated as a new window rather than a reload.

## Best solution

The `StartupPageRunnerContribution.run()` method in `src/vs/workbench/contrib/welcomeGettingStarted/browser/startupPage.ts` should detect that the window is reconnecting to a remote (devcontainer) after the user was already interacting with the workspace, and suppress the welcome page in that case — e.g. by checking whether a remote connection is being established from a prior local session, or by persisting a 'user has already seen startup content this session' flag in profile storage before the reload.
