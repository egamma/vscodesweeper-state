# Issue #277880 — editor.find.loop set to false not respected in larger files

[https://github.com/microsoft/vscode/issues/277880](https://github.com/microsoft/vscode/issues/277880)

## Summary

The current source still permits search wrapping with editor.find.loop disabled once the match count reaches MATCHES_LIMIT. Keep this open while the explicitly linked, still-open fixing PR is reviewed.

## Change summary

Honor editor.find.loop=false when navigating searches with at least 19,999 matches.

## Best solution

Review and land an appropriate fix through https://github.com/microsoft/vscode/pull/307998 so large-result searches respect the loop setting without preventing navigation to matches beyond the highlighting limit.

## Evidence

- **Current source overrides the setting:** src/vs/editor/contrib/find/browser/findState.ts:321-330 makes both navigation guards depend on canNavigateInLoop(), which returns this._loop || (this.matchesCount >= MATCHES_LIMIT). src/vs/editor/contrib/find/browser/findModel.ts:81 defines MATCHES_LIMIT as 19999.
- **Wrapping path traced:** At the limit, src/vs/editor/contrib/find/browser/findModel.ts:384-456 bypasses decoration-based navigation and calls model.findNextMatch(), returning its result without rejecting wraparound when loop is disabled. src/vs/editor/common/model/textModelSearch.ts:_doFindNextMatchLineByLine searches subsequent lines modulo lineCount, so reaching the final occurrence can return a match at the beginning. This establishes the reported high-match-count failure from source without executing the application.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/307998 was verified OPEN with mergedAt=null. Its body explicitly says Fixes #277880 and proposes removing the match-limit loop override while detecting wraparound in the large-result navigation paths. It is not a landed fix.
- **Related report is not a canonical duplicate:** The older open issue https://github.com/microsoft/vscode/issues/264815 concerns reverse-direction refocusing and missing accessible feedback with only three matches. That is distinct from wrapping to the opposite end after crossing the match-count threshold, so it does not meet the same-observable-symptom duplicate bar for this re-reviewed item.
