# Issue #344932 — Agent host: chat created while the remote host connection is down cannot be restored (Session identity was not advertised)

[https://github.com/microsoft/vscode/issues/344932](https://github.com/microsoft/vscode/issues/344932)

## Summary

Keep open: the latest locally available main still permits client-only session materialization before backend creation, and restoration rejects the missing identity. This team-authored report has no verified fixing commit or qualifying duplicate.

## Change summary

A first message sent while a remote agent host is disconnected leaves an unrestorable chat and loses the prompt after reload.

## Best solution

Preserve recoverable draft content when backend creation fails, and distinguish an unavailable host or unknown session from a generic editor failure. Settle the reconnect and send-admission behavior without changing authoritative host identities or replaying potentially delivered messages.

- **Validation:** With a remote WebSocket host disconnected and retries exhausted, submit the first message in a new chat, reconnect, and reload. Add client-boundary coverage with failed createSession and fresh service instances after reload.
- **Behavior:**

  > Sending the first message while the remote host is unreachable must not strand the conversation under an identity that exists only on the client. If the host never created the session, retain the prompt so the user can resend after reconnect, including after reload. A restored reference to an unknown host session must explain the failure specifically. Recovery must not automatically duplicate a message whose delivery outcome is uncertain.
- **Trace:**

  > The working checkout and origin/main f31439d32be99bcc503fcbad0e2b075e189ca9d9 retain the same failure boundary. AgentHostSessionListController.newChatSessionItem can return a local pending resource when AgentHostUntitledProvisionalSessionService.tryRebind has no owned backend. ChatService._materializeUntitledSession publishes that resource before AgentHostSessionHandler._invokeAgent performs backend creation through _createAndSubscribe. The pending-new marker lives only in AgentHostSessionListStore memory, so fresh instances restore through _discoverSessionIdentity and reject an identity absent from listSessions. AgentHostProtocolClient terminates automatic retries on exhaustion. Preserve host-advertised identities, successful-session behavior, and uncertain-delivery safety; the complete UI and persistence recovery path still needs design. https://github.com/microsoft/vscode/issues/348946 is related activation work, not a canonical for this defect.
- **Open decisions:**
  - After automatic retries are exhausted, should sending trigger an on-demand reconnect, or remain blocked until explicit reconnection?
  - For already-orphaned editors, should the recovery surface offer conversion to a recoverable draft, or explain the missing session and expose any retained prompt for manual recovery?
