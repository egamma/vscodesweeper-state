# Issue #315766 — agent sessions window: uv not working

[https://github.com/microsoft/vscode/issues/315766](https://github.com/microsoft/vscode/issues/315766)

## Summary

Keep open: the team-authored report includes a recorded reproduction and maintainer confirmation of a probable Copilot CLI bug. Current main propagates the login-shell environment through the Agent Host and Copilot CLI, but no issue-linked fix proves that the reported failure was resolved.

## Change summary

Agent Sessions could not execute the installed `uv` command even though it was available from VS Code's local and integrated terminals.

## Best solution

Ensure Copilot CLI shell tools inherit the same effective PATH as the Agent Host and integrated terminal, then cover the full Agent Host-to-Copilot subprocess path with a regression test.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/electron-main/electronAgentHostStarter.ts`, `src/vs/platform/agentHost/node/nodeAgentHostStarter.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/copilot/copilotCliEnvironment.ts`, `src/vs/platform/agentHost/test/node`
- **Validation:** Run an Agent Host integration test with a synthetic executable available only through the resolved shell PATH, invoke it through the Copilot CLI shell tool, and assert that the command succeeds and returns the shim's output.
- **Behavior:**

  > Commands available on the user's effective terminal PATH must also be executable from a local Copilot Agent Session. In particular, invoking `uv` from the agent must succeed when the same VS Code instance can invoke it from an integrated terminal. The behavior must hold for the normal Electron Agent Host launch path without weakening environment sanitization for the Copilot CLI subprocess.
- **Trace:**

  > ElectronAgentHostStarter and NodeAgentHostStarter resolve the login-shell environment through `getResolvedShellEnv` and pass it to the Agent Host process. CopilotAgent subsequently builds the SDK subprocess environment from `process.env` through `createCopilotCliEnvironment`, which preserves PATH while removing Electron- and VS Code-specific variables. Commit https://github.com/microsoft/vscode/commit/f158e93d346f68cf1dffb283ee98ed519441df16 introduced the outer shell-environment propagation before the reported reproduction, so the remaining uncertainty begins inside the effective environment received or used by the Copilot CLI shell tool. Preserve the existing environment-sanitization boundary and avoid changing unrelated terminal or provider behavior.
