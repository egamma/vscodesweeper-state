# Issue #225577 — InstantiationService has been disposed

[https://github.com/microsoft/vscode/issues/225577](https://github.com/microsoft/vscode/issues/225577)

## Summary

The disposal race remains visible on current main: asynchronous markdown-cell model resolution can call `setModel` after its editor and child instantiation service have been disposed. This team-authored telemetry issue should remain open because no explicitly linked fix has landed.

## Change summary

Prevent markdown-cell editor initialization from using a disposed child InstantiationService.

## Best solution

Guard the resolved-model callback in `MarkupCell.viewUpdateEditing` against cancellation or disposal before accessing the editor, and add lifecycle coverage for disposing the cell while model resolution completes.
