# Issue #224527 — Git - During repo initialization a gitignore file should be created

[https://github.com/microsoft/vscode/issues/224527](https://github.com/microsoft/vscode/issues/224527)

## Summary

Keep this accepted Git feature request open: repository initialization still does not offer .gitignore creation. Existing ignore commands and GitHub publishing provide partial alternatives, but neither covers the requested initialization workflow.

## Change summary

Offer to create a .gitignore when initializing a repository whose root does not already contain one.

## Best solution

Provide an optional .gitignore creation step in the built-in Git initialization workflow, preserving existing ignore files and allowing initialization without creating one. The Git owner should decide the template-selection and prompting behavior before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/github/src/publish.ts`
- **Validation:** In a temporary folder without .git or .gitignore, invoke Initialize Repository from Source Control and verify the agreed creation offer and selected ignore contents. Repeat with an existing .gitignore and confirm its bytes remain unchanged; decline or cancel the optional creation step and verify repository initialization remains usable. Check both the single-workspace-folder shortcut and Choose Folder flow.
- **Behavior:**

  > Initializing a repository from Source Control should offer an optional way to create a missing root .gitignore. Existing .gitignore files must remain unchanged, and users must be able to initialize without accepting ignore-file creation. Acceptance should cover selecting an ignore configuration, declining the offer, an existing ignore file, and both workspace-folder and explicitly chosen-folder initialization.
- **Trace:**

  > Commands.init in extensions/git/src/commands.ts resolves the folder and branch, calls Git.init, then opens the repository or prompts about opening it. Git.init in extensions/git/src/git.ts only executes git init, so the ordinary initialization path has no ignore-file offer. Commands.ignore handles selected SCM resources separately, while publishRepository in extensions/github/src/publish.ts has a GitHub-publication-specific file-selection flow; that is partial prior art, not coverage of this request. Preserve existing ignore contents, ordinary repository opening, and the separate publishing workflow. https://github.com/microsoft/vscode-dotnettools/issues/751 supplies corroborating demand and a .NET-specific CLI workaround, while its discussion points to https://github.com/microsoft/vscode/issues/224527 for the general initialization capability. The unresolved boundary is the user-facing choice of ignore contents and how the optional step is presented, not whether the current initialization path already implements it.
- **Open decisions:**
  - Should the creation offer select language/framework templates, let users choose files to exclude, or provide an editable generic starting file?
  - Should the optional offer appear on every initialization with a missing .gitignore, or be controlled by a remembered preference?
