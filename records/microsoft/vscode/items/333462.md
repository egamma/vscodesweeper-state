# Issue #333462 — Very confusing free Copilot Pro upgrade flow

[https://github.com/microsoft/vscode/issues/333462](https://github.com/microsoft/vscode/issues/333462)

## Summary

The upgrade flow remains broken on current main: the free activation path can miss the success callback, the fallback checks entitlement only once, and the refresh command can reuse both the pre-upgrade token and cached model metadata. A maintainer has confirmed these interacting failures, so the issue should remain open.

## Change summary

Completing a free Copilot Pro activation does not reliably update VS Code, leaving upgrade prompts and stale model availability until the window is reloaded.

## Best solution

Make both paid and free activation paths converge on a reliable entitlement, Copilot-token, and model-metadata refresh, with clear pending and success feedback while GitHub propagates the new plan.

- **Behavior:**

  > After a user completes either a paid Copilot upgrade or an eligible free Copilot Pro activation, VS Code must recognize the new plan without requiring a window reload. Upgrade affordances and model availability must update after account propagation completes, while the UI communicates that activation may still be pending. Returning to VS Code before propagation finishes must not permanently abandon detection, and existing paid callback behavior must remain intact.
- **Trace:**

  > The confirmed report is https://github.com/microsoft/vscode/issues/333462, with the maintainer root-cause analysis at https://github.com/microsoft/vscode/issues/333462#issuecomment-5495649388. `UpgradePlanAction` in src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts opens the URL and installs a focus fallback, but `onWindowFocus` clears that listener before making its sole entitlement request. `buildUpgradeUrlWithRedirect` in src/vs/workbench/contrib/chat/browser/chatSetup/chatSetup.ts depends on `/upgrade-success`, which GitHub does not invoke for this free activation path. The downstream `github.copilot.refreshToken` handler in extensions/copilot/src/extension/contextKeys/vscode-node/contextKeys.contribution.ts reaches `getCopilotToken()` without forcing a refresh, while `ModelMetadataFetcher` retains `/models` for ten minutes and only invalidates on authentication-identity changes. The boundary is plan-state propagation and model availability after an upgrade; do not change eligibility, billing, account selection, or which models each plan is entitled to use.
- **Open decisions:**
  - How long should VS Code continue checking for delayed entitlement propagation after the user returns from the free activation flow, and what terminal state should it show if the plan never updates?
  - What pending feedback should replace the stale upgrade affordances while VS Code is waiting for the new entitlement?

## Evidence

- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/333462#issuecomment-5495649388 confirms that the refresh command reuses the cached token, `/models` remains cached, the focus fallback is one-shot, and GitHub skips the `/upgrade-success` callback for the free activation path.
- **stale token path:** On current main, extensions/copilot/src/extension/contextKeys/vscode-node/contextKeys.contribution.ts registers `github.copilot.refreshToken` by calling `_inspectContext()`, which calls `getCopilotToken()` without `force`; extensions/copilot/src/platform/authentication/common/authentication.ts forwards that optional flag to the token manager.
- **stale model path:** extensions/copilot/src/platform/endpoint/node/modelMetadataFetcher.ts caches model metadata for ten minutes and invalidates it on `onDidAuthenticationChange`, but does not subscribe to `onDidCopilotTokenChange`, so a refreshed plan token alone does not refresh the model picker.
- **missed callback fallback:** src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts clears `windowFocusListener` before its single `forceResolveEntitlement()` check. If account propagation has not completed at that moment, there is no retry and no token refresh.
- **callback dependency:** src/vs/workbench/contrib/chat/browser/chatSetup/chatSetup.ts appends a `/upgrade-success` return URI, while the issue's confirmed free-plan path does not honor that redirect; current tests only validate construction of the return URL, not completion after delayed free-plan activation.
- **canonical search:** No older open microsoft/vscode issue was found that reports the same observable free-upgrade flow remaining stale until window reload; the supplied candidate issues concern unrelated problems.
