# Issue #339156 — [AutomaticInstructionsCollector] Core vs extension instructions mismatch filling the chat log

[https://github.com/microsoft/vscode/issues/339156](https://github.com/microsoft/vscode/issues/339156)

## Summary

Confirmed from source: the extension's own nested-AGENTS.md lookup (`AgentInstructionsLocator.listNestedAgentMDs`) calls `vscode.workspace.findFiles('**/AGENTS.md', undefined, ...)`, which per the API only applies `files.exclude` and NOT `search.exclude` — so it misses the default `node_modules`/`bower_components` exclusion that VS Code core's equivalent (`PromptFilesLocator.findAgentMDsInFolder`, via `getExcludes()`) correctly applies. That's exactly the divergence the `[AutomaticInstructionsCollector] Core vs extension instructions mismatch` log is designed to surface, and matches aeschli's diagnosis in the thread.

## Change summary

Massive 'Core vs extension instructions mismatch' log/diff appears because the extension's AGENTS.md discovery picks up thousands of nested AGENTS.md files under node_modules that core's own discovery correctly excludes.

## Best solution

Swap the raw `vscode.workspace.findFiles` call in `AgentInstructionsLocator.listNestedAgentMDs` for the existing `ISearchService.findFilesWithDefaultExcludes` helper (already used from the same vscode-node layer elsewhere, e.g. devContainerConfigurationServiceImpl.ts and ignoreServiceImpl.ts), which applies `search.exclude` + `files.exclude` together and restores parity with core's node_modules exclusion.
