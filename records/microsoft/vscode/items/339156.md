# Issue #339156 — [AutomaticInstructionsCollector] Core vs extension instructions mismatch filling the chat log

[https://github.com/microsoft/vscode/issues/339156](https://github.com/microsoft/vscode/issues/339156)

## Summary

Real, traced mechanism (an internal core-vs-extension instruction-collection parity check logs a huge diff on mismatch), but it's gated behind an internal experiment flag and a maintainer is already mid-investigation awaiting the reporter's answer about settings/node_modules — stays open, no close warranted.

## Change summary

An internal `[AutomaticInstructionsCollector] Core vs extension instructions mismatch` diagnostic logs an enormous diff (33k lines) into the chat/output log on nearly every turn, apparently picking up nested AGENTS.md files even under node_modules in a multi-repo workspace.

## Best solution

Clarify that this message comes from `CustomInstructionsReferenceLogger.compare()` in extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts (only runs when the internal `chat.experimental.collectInstructionsInExtension` flag is on) and only writes to the log/output channel via `_logService.info`, not into the model's context — so it isn't the cause of hitting the 1M context window, but it is wasteful (double instruction collection every turn) and noisy. Once the reporter confirms their `chat.useNestedAgentsMdFiles` setting and whether the extra AGENTS.md hits are really under node_modules, either tighten the nested-AGENTS.md exclude handling in agentInstructionsLocator.ts's `listNestedAgentMDs`, or bound/throttle this parity-diff logging so it doesn't repeat every turn for flighted users.
