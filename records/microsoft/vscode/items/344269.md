# Issue #344269 — Tree item checkbox ignores the click that moves focus into the tree when any view/item/context command has an enablement using focusedView

[https://github.com/microsoft/vscode/issues/344269](https://github.com/microsoft/vscode/issues/344269)

## Summary

The current source confirms that a focus-driven menu-context change destroys and recreates rendered tree checkboxes during the mouse gesture. Keep this open: the report provides a complete minimal reproduction, and the earlier fixes address different triggers.

## Change summary

Ensure the first checkbox click registers when focus enters an extension tree, even when an unrelated tree command uses focusedView enablement.

## Best solution

Preserve checkbox interaction through menu-context updates in the custom tree renderer while continuing to refresh applicable action visibility and enablement. Cover the unrelated-view contribution case without changing checkbox cascading or extension API semantics.
