# Issue #282393 — Background agent: Apply changed files should change state after I applied once

[https://github.com/microsoft/vscode/issues/282393](https://github.com/microsoft/vscode/issues/282393)

## Summary

Team-authored bug about background agent apply state not updating. Related state-management improvements have landed (31d554803a5, d1e403ebbfe) but none reference this issue directly, and the specific UI stale-state after a successful apply may still remain.

## Change summary

After applying background agent changes, the UI still shows 'N files ready to merge' and a second click produces a merge conflict error.

## Best solution

Ensure the apply action updates the session item UI (disables Apply button, updates file count text) immediately after a successful `applyWorktreeChanges` call, and optionally offer archiving. The logic lives in `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts` around the `applyChanges` function.
