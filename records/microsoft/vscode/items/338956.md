# Issue #338956 — VoiceOver typing echo is silent on first launch, and speech stops after Command+Down Arrow in VS Code Insiders

[https://github.com/microsoft/vscode/issues/338956](https://github.com/microsoft/vscode/issues/338956)

## Summary

Well-diagnosed VoiceOver regression traced by the reporter to a Chromium accessibility bug (Chromium issue 534441751) affecting Electron 43–44 builds and fixed starting in Electron 45 alpha; this repo still ships Electron 43.7.3, so the report still reproduces on main and needs an Electron version bump to resolve, not a VS Code code fix.

## Change summary

On first launch, VoiceOver gives no typing echo in the editor (and in plain Electron HTML inputs) until the window is reloaded; separately, Command+Down Arrow silences VoiceOver speech unless `editor.editContext` is disabled.

## Best solution

Track this against the Electron/Chromium upgrade: once VS Code adopts an Electron build on Chromium 45+ (where the reporter confirms the VoiceOver regression is fixed), the typing-echo symptom should resolve on its own; the Command+Down Arrow/EditContext speech-stopping symptom should be re-verified against the same Electron bump and, if it persists, reported upstream or investigated separately in the EditContext accessibility code.
