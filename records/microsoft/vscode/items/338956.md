# Issue #338956 — VoiceOver typing echo is silent on first launch, and speech stops after Command+Down Arrow in VS Code Insiders

[https://github.com/microsoft/vscode/issues/338956](https://github.com/microsoft/vscode/issues/338956)

## Summary

Thanks for the detailed diagnosis — the typing-echo silence traces to a Chromium/VoiceOver regression the reporter bisected between Electron 43.0.0-beta.3 and 43.0.0-beta.4, and the repo's current `.npmrc` still pins Electron target `43.7.7`, squarely inside the broken range the reporter identified (fixed starting in Chromium-based Electron 45 alphas). Keeping open as upstream; the separate Command+Down/editContext speech-stop needs its own look in VS Code's accessibility code.

## Change summary

VoiceOver gives no typing-echo feedback on first launch of VS Code (regular and Insiders), and separately, speech stops after Command+Down Arrow when editor.editContext is enabled.

## Best solution

Track the Electron bump to a Chromium-45-based release as the fix for the typing-echo silence (root cause confirmed upstream in Chromium); file/trace the Command+Down + editContext speech-stop as a distinct, VS-Code-owned accessibility investigation since disabling editContext works around it.
