Later comments explicitly confirm the same error through January 2026; the latest says credential cleanup did not help.

Both related issues are now closed and concern different diagnosed runtime failures; their runtime-update resolution cannot establish that this issue was fixed.
- **Upstream investigation remains necessary:** The May 9 maintainer comments in the supplied thread identify substantial telemetry specifically for error 3399614467 and request Auth runtime logs for the Identity team. This is evidence of a recognized upstream investigation, not an unsupported or merely stale report.
- **Current source explains session disappearance:** extensions/microsoft-authentication/src/node/authProvider.ts:468-561, MsalAuthProvider.getAllSessionsForPca, calls silent token acquisition and skips an account when acquisition throws. extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts:115-117 delegates that operation directly to MSAL. This explains zero returned sessions after a dependency failure, but does not reproduce the environment-specific broker defect.
- **Relevant unresolved upstream defect:** https://github.com/AzureAD/microsoft-authentication-library-for-js/issues/8849 is open. The checkout depends on MSAL Node ~5.4.0, and extensions/microsoft-authentication/src/common/cachePlugin.ts:35-49 uses the corresponding beforeCacheAccess/afterCacheAccess persistence contract. This is a concrete related lead, not proof that the original broker error shares that root cause.
