# Issue #173306 — Git - Close repository (Git) doesn't forget openened parent repository

[https://github.com/microsoft/vscode/issues/173306](https://github.com/microsoft/vscode/issues/173306)

## Summary

Still valid on current main: `git.close` never clears the global `parentRepository:<root>` flag, so a mistakenly opened parent repository stays permanently remembered and can never be re-offered; the issue's second ask (a command listing parent repositories) has since shipped as `git.openRepositoriesInParentFolders`, so the remaining work is the 'forget on close' half.

## Change summary

Closing a repository that was opened from the 'repository in parent folder' prompt should also forget it from the remembered parent repositories.

## Best solution

Have `Model.close()` (extensions/git/src/model.ts) clear the `parentRepository:<root>` global-state flag — ideally via a `forget`/`deleteRepository` method on `ParentRepositoriesManager` — so the folder is treated as an unopened parent repository again and reappears in the prompt/`git.openRepositoriesInParentFolders` picker; decide first how that interacts with the workspace-scoped closed-repositories list.

## Plan brief

- **Likely files:** `extensions/git/src/model.ts`, `extensions/git/src/commands.ts`
- **Validation:** Close a repository that was opened via the parent-folder prompt, reload the window, and confirm it is not auto-opened and that it appears again under `Git: Open Repositories In Parent Folders` (or the prompt) — plus a unit test over the parent/closed repository managers if they are made testable.
- **Behavior:**

  > When a user runs 'Close Repository' on a repository that was opened from the 'git repository found in a parent folder' prompt, VS Code should forget that it was ever opened: it must not be auto-opened in later sessions (including other windows/workspaces), and the folder should once again be treated as an un-opened parent repository so it can be picked from `Git: Open Repositories In Parent Folders` or the prompt. Closing a normal in-workspace repository must keep its current behavior (stays closed for that workspace, reopenable via 'Reopen Closed Repositories'). Acceptance: after close + reload, the repository is not opened and is reachable again through the parent-repository picker.
- **Trace:**

  > In extensions/git/src/model.ts, `ParentRepositoriesManager.openRepository()` persists `parentRepository:<root> = true` in global state and removes the root from the in-memory parent set; no code path ever deletes that key (verified with `rg globalState` across extensions/git/src — one write at line ~134, one read at line ~633). `Model.close()` (line ~885) only records the root in `ClosedRepositoriesManager`, which is workspace state, so the global 'this parent repo was opened' flag survives the close and survives other workspaces. The parent check in `Model.openRepository()` runs before the closed-repository check, so with the flag set the folder is never re-classified as a parent repository and therefore never shows up in `git.openRepositoriesInParentFolders` (extensions/git/src/commands.ts ~4983), which reads `model.parentRepositories`. Boundary: do not change the parent-repository prompt/`git.openRepositoryInParentFolders` settings semantics, the `always`/`never`/`prompt` configuration, or the existing closed-repository reopen flow. The issue's second request (a command to list parent repositories) is already implemented and is not part of the remaining work.
- **Open decisions:**
  - After 'Close Repository', should the folder immediately re-appear as a detected parent repository (and potentially re-prompt in the same session), or only be forgotten so that a future session treats it as new?
  - Should forgetting the global parent flag be limited to repositories outside the workspace that were opened via the parent prompt, or applied on every close?
  - How should the workspace-scoped closed-repositories entry interact — is a parent repository that was closed still listed under 'Reopen Closed Repositories', or removed from that list once forgotten?

## Evidence

- **flag is never cleared:** extensions/git/src/model.ts: `ParentRepositoriesManager.openRepository()` writes `globalState.update('parentRepository:' + repository, true)` (line ~134) and nothing anywhere in the extension ever deletes that key — `rg globalState` over extensions/git/src shows only the write (line 134) and the read in `Model.openRepository()` (line ~633).
- **close path:** extensions/git/src/model.ts `Model.close()` (line ~885) only adds the root to `ClosedRepositoriesManager` (workspace state key `closedRepositories`) and disposes the open repository; it does not touch the parent-repository global state, so the folder is permanently treated as an explicitly-opened parent repository and is never offered in the parent-repository prompt or picker again.
- **second ask already shipped:** The requested command exists on main: `git.openRepositoriesInParentFolders` in extensions/git/src/commands.ts (~line 4983), contributed in extensions/git/package.json with `when: config.git.enabled && !git.missing && git.parentRepositoryCount != 0`. It only lists repositories still in `model.parentRepositories`, which a closed-but-remembered repository is not — which is exactly the gap this issue describes.
- **milestone:** Milestone `On Deck` is a holding bin, so it does not block a close; nothing here is closeable though — no fix commit exists and the reported behavior still holds on main.
