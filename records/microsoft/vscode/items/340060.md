# Issue #340060 — [Error] [GitHub.copilot-chat] unhandlederror-Cannot read properties of null (reading 'allowRepositoryUrl')

[https://github.com/microsoft/vscode/issues/340060](https://github.com/microsoft/vscode/issues/340060)

## Summary

Confirmed regression: the core `_chat.pickRepository` command handler only defaults `options` when the argument is `undefined`, but a `null` options value (as can arrive across the command RPC boundary from the extension) bypasses that default and throws on `options.allowRepositoryUrl`. An open PR (#340065) already targets this exact fix, so this should stay open pending that merge rather than being treated as agent work.

## Change summary

Picking a repository for a cloud chat session throws an unhandled TypeError when the repository-picker options argument arrives as null instead of undefined.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/340065, which normalizes/guards the `options` parameter in `_chat.pickRepository` (src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts / agentSessions/repositoryPicker.ts) so a null options value doesn't bypass the default parameter.
