# Issue #208069 — Confusion with copy/paste key bindings with file explorer 

[https://github.com/microsoft/vscode/issues/208069](https://github.com/microsoft/vscode/issues/208069)

## Summary

A real gap remains on current main: copying a resource in the VS Code Explorer records VS Code-specific resource data but does not expose a plain-text path that external text editors can paste. The earlier stale-web-clipboard symptom was not reproduced by the contributor, but the external-paste scenario was reproduced and is still evident in source.

## Change summary

Copying a file in the VS Code Explorer should let external text editors paste its path without breaking VS Code's internal file-copy behavior.

## Best solution

Preserve the resource clipboard payload used for Explorer file operations while also making copied resources available to external text consumers using the established Copy Path representation. Browser and native behavior should agree, including a defined representation for multiple resources and non-file URIs.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/explorerService.ts`, `src/vs/workbench/contrib/files/browser/fileCommands.ts`, `src/vs/platform/clipboard/browser/clipboardService.ts`, `src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts`
- **Validation:** Manually verify on vscode.dev and desktop that copying one and multiple Explorer resources pastes the expected paths into an external plain-text editor, while pasting back into the VS Code Explorer still copies or moves the resources and pasting into a VS Code editor retains its existing paste behavior.
- **Behavior:**

  > Copying a resource from the VS Code Explorer must produce clipboard content that an external plain-text editor can paste as a meaningful path. VS Code must retain its richer resource identity so Explorer paste and editor paste behavior do not regress. Acceptance should cover one and multiple selections on vscode.dev and desktop, followed by paste into an external editor, the VS Code editor, and the VS Code Explorer.
- **Trace:**

  > Explorer Copy reaches ExplorerService.setToCopy in src/vs/workbench/contrib/files/browser/explorerService.ts, which calls IClipboardService.writeResources. The browser implementation in src/vs/platform/clipboard/browser/clipboardService.ts writes only the VS Code resource MIME payload plus fallback in-memory state; the native implementation in src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts writes only `code/file-list`. Neither path supplies external text consumers with the path text already formatted by resourcesToClipboard in src/vs/workbench/contrib/files/browser/fileCommands.ts. The boundary is clipboard interoperability: do not change Explorer copy-versus-cut semantics, resource identity used by internal paste, or the existing Copy Path command. https://github.com/microsoft/vscode/issues/170708 concerns the opposite clipboard direction and should remain separate.
- **Open decisions:**
  - Should Explorer Copy expose plain text for every selected resource using the existing Copy Path multi-selection format, or only for a single selected resource?
  - For non-file resources on vscode.dev, should external plain-text paste use the user-facing resource label or the serialized URI?

## Evidence

- **confirmed remaining scenario:** https://github.com/microsoft/vscode/issues/208069#issuecomment-2048981166 reports that the original stale-paste symptom was no longer reproducible, but confirms that a file copied from the VS Code Explorer still cannot be pasted into an external editor.
- **explorer copy path:** src/vs/workbench/contrib/files/browser/explorerService.ts:284-291 routes Explorer Copy through IClipboardService.writeResources only.
- **web clipboard implementation:** src/vs/platform/clipboard/browser/clipboardService.ts:224-257 writes the custom `web application/vnd.code.resources` payload and in-memory resource state, but no `text/plain` representation consumable by an external text editor.
- **native clipboard implementation:** src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts:58-62 writes only the internal `code/file-list` buffer for copied resources.
- **existing path convention:** src/vs/workbench/contrib/files/browser/fileCommands.ts:228-245 already defines Copy Path text formatting through ILabelService, platform line delimiters, and the configured path separator.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/170708 is open but covers the inverse flow—copying from an operating-system file manager and pasting into VS Code—so it does not absorb this report.
