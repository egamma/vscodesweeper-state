# Issue #191648 — Should json sort on save also apply to JsonL

[https://github.com/microsoft/vscode/issues/191648](https://github.com/microsoft/vscode/issues/191648)

## Summary

Keep open: JSONL syntax support exists, but the built-in JSON language-service selector still excludes JSONL, so the current sorting surface does not cover this request. A maintainer accepted the direction; the related formatter request is newer and does not establish a duplicate.

## Change summary

Support sorting object properties within each JSONL record on save without changing record order or breaking the one-record-per-line format.

## Best solution

Provide JSONL-aware property sorting through the JSON sorting source action, preserving record boundaries and existing JSON/JSONC behavior. Establish the required language-service support before extending the built-in language participation.

- **Behavior:**

  > Users should be able to sort properties within each JSONL record on save through the built-in JSON sorting capability. Saving the supplied sample should put a before x in the first record and b before y in the second, while preserving record order and one JSON value per line. Existing JSON and JSONC sorting behavior must remain unchanged.
- **Trace:**

  > JSONL is registered in extensions/json/package.json, but getLanguageParticipants in extensions/json-language-features/client/src/languageParticipants.ts excludes it from built-in JSON language-service participation. The json.sort command and getSortTextEdits in client/src/jsonClient.ts send a document-level json/sort request; server/src/jsonServer.ts forwards it to vscode-json-languageservice and advertises source.sort.json. The original json.sortOnSave.enable setting is no longer registered, so the acceptance path must use the current source-action mechanism. The maintainer accepted JSONL sorting in https://github.com/microsoft/vscode/issues/191648#issuecomment-1698635139. Related https://github.com/microsoft/vscode/issues/208647 documents that broader JSONL language-server support requires several adaptations; it is not a duplicate canonical. The remaining uncertainty is the language service's required record-aware support and its safe integration boundary, not whether line order should change. Keep unrelated JSONL language features outside this request and preserve JSON/JSONC behavior.
