# Issue #60851 — Open next build error file+line based on regex parsing of build output.

[https://github.com/microsoft/vscode/issues/60851](https://github.com/microsoft/vscode/issues/60851)

## Summary

Keep open: regex-based task diagnostics already work without language extensions, but existing navigation does not deliver build-only traversal in output order with synchronized terminal positioning. The discussion establishes a distinct tasks requirement, and no verified canonical or covering fix was found.

## Change summary

Provide single-shortcut next/previous navigation through regex-matched build errors in terminal output order, opening the source location and revealing the corresponding output.

## Best solution

Provide task-scoped build-error navigation using configured output matchers, preserving compiler-output order and excluding unrelated diagnostics. Retain existing Problems navigation and terminal link commands; decide which build invocation navigation targets when multiple tasks exist.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/browser/task.contribution.ts`, `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`, `src/vs/workbench/contrib/tasks/common/problemCollectors.ts`, `src/vs/workbench/contrib/tasks/common/problemMatcher.ts`, `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts`
- **Validation:** Run a build task with a custom regex and three errors whose output order differs from filename and source-line order, with language extensions disabled. Invoke next/previous repeatedly and verify the expected file/line/column and corresponding terminal output are revealed in build order. Include unrelated diagnostics and nonmatching terminal links; neither should enter the sequence. Repeat after rebuilding and with two build tasks to validate the chosen invocation semantics.
- **Behavior:**

  > A user can run a build task and use one shortcut per step to navigate forward or backward through compiler errors identified by the task's configured regex, without installing language-support extensions or focusing the Problems view. Navigation follows compiler-output order, opens the matched file at its line/column, and reveals the corresponding terminal output. Unrelated language-service or linter diagnostics and nonmatching terminal links are excluded. Acceptance includes deliberately nonalphabetical output order, repeated builds, and unchanged existing Problems navigation.
- **Trace:**

  > TerminalTaskSystem feeds terminal.onLineData into StartStopProblemCollector or WatchingProblemCollector; ProblemMatcher already supports regex capture of source locations. AbstractProblemCollector.recordMarker groups and deduplicates by owner/resource, while MarkerList in src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts sorts global diagnostics by resource and severity/position rather than output occurrence. TerminalLinkManager supplies link selection and recent-link opening, not the requested task-regex sequence. These paths establish the capability gap but do not establish how navigation should retain invocation identity and corresponding terminal positions across rebuilds and terminal reuse. Preserve existing marker publication, F8 behavior, and generic terminal-link detection. The clarified contract is at https://github.com/microsoft/vscode/issues/60851#issuecomment-451495231; a Problems-filter-only solution would not establish output ordering or synchronized terminal reveal.
- **Open decisions:**
  - When multiple build tasks or retained build terminals exist, should next/previous target the most recently invoked build, the active task terminal's build, or an explicitly selected build invocation?
