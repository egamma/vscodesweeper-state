# Issue #336379 — Built-in Git extension writes branch.*.vscode-merge-base via git config --add and can wipe remotes from .git/config

[https://github.com/microsoft/vscode/issues/336379](https://github.com/microsoft/vscode/issues/336379)

## Summary

The cited call path is real — Repository.setConfig() shells out to `git config --add --local` on branch switch, matching the reporter's analysis — but the claimed full-file wipe/truncation of .git/config is a race-condition/environment-dependent outcome that can't be confirmed from source alone, and no one else has reproduced it, so this needs the reporter's confirmation rather than a keep-open parking or a close.

## Change summary

Reports that the built-in Git extension's `git config --add --local branch.<name>.vscode-merge-base` write can, in rare cases, wipe remotes/branch-tracking (or truncate .git/config to 0 bytes) instead of just adding the key.

## Best solution

If reproducible, the fix likely belongs in extensions/git/src/repository.ts's setConfig()/git.ts's config() — e.g. checking for an existing value before `--add`, or serializing concurrent config writes per-repo — but that work should wait until the corruption mechanism is confirmed, since `git config --add` alone does not normally truncate unrelated sections.
