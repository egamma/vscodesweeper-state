# Issue #308213 — Export Chat truncates file to 0 bytes when disk is full instead of failing gracefully

[https://github.com/microsoft/vscode/issues/308213](https://github.com/microsoft/vscode/issues/308213)

## Summary

Keep open: the current export path still overwrites the destination non-atomically, allowing a failed write to destroy an existing export. The data-loss mechanism is confirmed from source; the separate claim that no error appears remains unverified.

## Change summary

Preserve an existing chat export when exporting its replacement fails because the destination disk is full, and clearly report the failure.

## Best solution

Make chat export failure-safe for existing destination files without changing ordinary file-service write defaults. A failed export should preserve the previous backup and surface an actionable error.
