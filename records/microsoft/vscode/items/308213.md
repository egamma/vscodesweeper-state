# Issue #308213 — Export Chat truncates file to 0 bytes when disk is full instead of failing gracefully

[https://github.com/microsoft/vscode/issues/308213](https://github.com/microsoft/vscode/issues/308213)

## Summary

Valid bug: the chat export action uses a plain `fileService.writeFile` without the `atomic: true` option, so on a full disk the file is truncated to 0 bytes with no recovery. The fix is straightforward — pass `{ atomic: true }` to leverage the existing atomic-write infrastructure.

## Change summary

Exporting a chat session on a full disk truncates the target file to 0 bytes instead of failing gracefully.

## Best solution

Pass `{ atomic: true }` to `fileService.writeFile` in `src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts` (line 80). The disk file system provider already supports `FileAtomicWrite`, which writes to a temp file and renames atomically — this prevents data loss on ENOSPC. Optionally surface the write error to the user via a notification.
