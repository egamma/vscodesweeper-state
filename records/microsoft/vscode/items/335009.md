# Issue #335009 — Expected legacy Copilot CLI migration refusal is logged as an Agent Host error

[https://github.com/microsoft/vscode/issues/335009](https://github.com/microsoft/vscode/issues/335009)

## Summary

Confirmed in source: the legacy Copilot CLI migration probe's expected `AHP_SESSION_NOT_FOUND` refusal is unconditionally logged as a server error and client warning, because neither log-suppression check knows about this specific probe. This is real, still open on main, and matches an existing precedent for exactly this kind of scoped suppression.

## Change summary

The legacy Copilot CLI adopt-in-place probe's expected 'not an adoptable legacy chat' refusal produces a generic `[ProtocolServer] Request 'subscribe' failed` error and a `[RemoteAgentHostProtocol] Request N failed` warning, adding noise to Agent Host logs even though the migration layer already treats it as a normal `declined` outcome.

## Best solution

Extend the existing suppression pattern (`isFileResourceRead` / `suppressNotFoundWarning` in agentHostProtocolClient.ts, and `shouldLogFailedRequest` in protocolServerHandler.ts) to also recognize the migration probe's `subscribe` call to the legacy twin channel, so only that specific NotFound refusal is dropped from error/warning logs while all other failed subscribes keep logging normally.

## Evidence

- **client-side unconditional warn log:** src/vs/platform/agentHost/browser/agentHostProtocolClient.ts:1784-1785 logs `[RemoteAgentHostProtocol] Request ${msg.id} failed` unless `_shouldLogFailedRequest` (line 2222) returns false; `suppressNotFoundWarning` is only set for `isFileResourceRead` requests in `_createRequest` (line 2215), not for the migration probe's `subscribe` call.
- **migration probe path:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLegacyMigration.ts:139 calls `connection.getSubscription(StateComponents.Session, backendSession, 'AgentHostLegacyMigration')`, whose refusal is deliberately treated as `declined` (not an error) by `whenSubscriptionSettles`, yet the underlying `subscribe` RPC still logs on both ends.
- **server refusal path:** src/vs/platform/agentHost/node/agentService.ts:5292-5293 logs an info line and throws `ProtocolError(AHP_SESSION_NOT_FOUND, ...)` for an unregistered, non-adoptable legacy chat — this is the expected refusal the probe already handles as `declined`.
