# Issue #338553 — Sandbox on Ubuntu 26 with network enabled still cannot access example.com

[https://github.com/microsoft/vscode/issues/338553](https://github.com/microsoft/vscode/issues/338553)

## Summary

Real, specifically-reproduced bug by a VS Code collaborator dogfooding the new network-enabled agent sandbox (following up on issue #338294): DNS resolution fails inside the sandbox on Ubuntu 26/Hyper-V even with `chat.agent.sandbox.allowNetwork` enabled. The actual network/DNS setup lives outside this checkout, so I can't trace or fix it here — this stays open for investigation.

## Change summary

With the agent sandbox's allow-network setting enabled, `curl http://example.com` fails with 'Could not resolve host' on Ubuntu 26, though it works with the sandbox fully disabled.

## Best solution

Investigate DNS handling in the external `@vscode/sandbox-runtime` package for systemd-resolved-based distros like Ubuntu 26 — likely the stub resolver (127.0.0.53) or /etc/resolv.conf isn't reachable from inside the sandboxed network namespace; the fix almost certainly belongs in that package, not in this repo's TS glue code.
