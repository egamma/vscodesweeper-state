# Issue #347480 — Agents Window: set an emoji for a chat

[https://github.com/microsoft/vscode/issues/347480](https://github.com/microsoft/vscode/issues/347480)

## Summary

Keep open for a focused product decision on user-assigned chat emojis. Renaming already permits emoji text, but no dedicated emoji assignment capability or verified duplicate was found; this team-authored, On Deck request should not receive a decline close.

## Change summary

Allow users to mark individual chats with a chosen emoji, such as a test tube or star.

## Best solution

Provide a consistent way to assign and clear a chat's visual marker, after deciding whether it is independent presentation metadata or part of its title. Preserve status and agent identity indicators, and keep individual markers distinct from group appearance.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/sessionsActions.ts`, `src/vs/sessions/services/sessions/common/session.ts`, `src/vs/sessions/services/sessions/common/sessionsManagement.ts`, `src/vs/sessions/browser/parts/chatCompositeBar.ts`, `src/vs/sessions/browser/parts/sessionHeaderBar.ts`
- **Validation:** Acceptance scenario: assign different emojis to two chats, switch between them, clear one marker, and reload the window; verify the agreed persistence and display semantics, unchanged chat titles if markers are independent, and intact status indicators. Include nested chats and keyboard-only operation.
- **Behavior:**

  > Users can choose an emoji to recognize a particular chat, such as a test tube or star. Choosing or clearing one chat's marker must not affect other chats. The product decision should establish whether this changes the title or creates an independent marker, where the marker appears, and whether it survives reload. Acceptance should cover assigning, changing, clearing, switching chats, and keyboard access.
- **Trace:**

  > renameChatWithQuickInput in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts already accepts emoji as ordinary title text and delegates through ISessionsManagementService.renameChat. IChat in src/vs/sessions/services/sessions/common/session.ts exposes observable titles but no user emoji field; ISession.icon is a ThemeIcon, not a user-assigned emoji. The Sessions list specification separates local presentation state from provider metadata, so persistence ownership depends on the chosen product contract. Chat tabs and headers live in src/vs/sessions/browser/parts/chatCompositeBar.ts and sessionHeaderBar.ts. Preserve provider-neutral boundaries and existing status and harness identity behavior. https://github.com/microsoft/vscode/issues/338822 covers group appearance, while https://github.com/microsoft/vscode/issues/338965 covers rendering emojis already embedded in titles; neither substitutes for this feature.
- **Open decisions:**
  - Should choosing an emoji modify the chat title or assign a separate visual marker?
  - Should the marker belong to each individual chat, including nested chats, or to the enclosing session, and which navigation surfaces should display it?
  - Should independent markers persist only in the local profile or travel with the chat across clients?
