# Issue #100725 — Git - git sync issue on an empty repo

[https://github.com/microsoft/vscode/issues/100725](https://github.com/microsoft/vscode/issues/100725)

## Summary

Keep open: current source still disables Sync for a clone with no local commits and loses its configured upstream during branch discovery. The linked fix PR remains open and needs maintainer review rather than a competing implementation.

## Change summary

Allow a repository cloned while empty to sync commits subsequently added to its remote.

## Best solution

Resolve the unborn-branch upstream discovery and Sync availability together in the built-in Git extension. Review and update https://github.com/microsoft/vscode/pull/114163 against current main, addressing the remaining remote-ref failure reported during maintainer testing before landing it.

## Evidence

- **Confirmed reported trigger:** The reporter cloned an empty remote twice, pushed the first commit from one clone, then found Sync unresponsive in the other. Maintainer confirmation appears at https://github.com/microsoft/vscode/issues/100725#issuecomment-649019629, and plainerman independently reproduced and diagnosed the empty-local-history case in the supplied discussion.
- **Current status-bar defect:** extensions/git/src/statusbar.ts:241, SyncStatusBar.command, requires HEAD.name and HEAD.commit before assigning git.sync. With a configured remote but no local commit, it returns the sync icon with an empty command and tooltip, matching the reported unresponsive button.
- **Current upstream discovery and command path:** In extensions/git/src/git.ts, getHEADFS returns the unborn branch name with commit undefined. getHEADRef then calls getBranch, whose for-each-ref lookup finds no local branch ref and rejects without recovering branch.remote/branch.merge configuration; getHEADRef retains the initial HEAD without an upstream. In extensions/git/src/commands.ts, Commands._sync sends a HEAD without upstream to _push rather than pulling the remote's newly added commits. This source trace establishes the failing path without executing code.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/114163 is verified OPEN with mergedAt null and explicitly states that it fixes this issue. Its proposed changes address upstream discovery and the commit-dependent status-bar gate; it is not evidence of a landed fix.
- **Outstanding PR review evidence:** At https://github.com/microsoft/vscode/pull/114163#issuecomment-1006684762, a maintainer reported that manually porting the proposed changes enabled Sync but still produced 'fatal: couldn't find remote ref master'. The PR therefore needs renewed validation of the remote branch configuration, not an assumption that its existing patch completes the work.
- **Canonical ownership:** https://github.com/microsoft/vscode/issues/139415 is closed, and https://github.com/microsoft/vscode/issues/139415#issuecomment-2538097219 explicitly closes it as a duplicate of this issue.
