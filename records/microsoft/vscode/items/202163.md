# Issue #202163 — `languages.match` doesn't work for notebook cell documents in document close events

[https://github.com/microsoft/vscode/issues/202163](https://github.com/microsoft/vscode/issues/202163)

## Summary

Still reproducible on main: when a notebook is closed, the notebook document is deleted from `_documents` (line 620) before cell document close events are fired (line 621), so `languages.match` cannot find the parent notebook during `onDidCloseTextDocument` handlers and returns 0.

## Change summary

`languages.match` returns 0 for notebook cell documents during document close events because the parent notebook is already removed from the registry.

## Best solution

In `extHostNotebook.ts` `$acceptDocumentAndEditorsDelta`, defer deleting the notebook from `this._documents` until after `$acceptDocumentsAndEditorsDelta` has fired for the cell documents — or capture the notebook reference before deletion so `languages.match` can still resolve it during close events. The fix for https://github.com/microsoft/vscode/issues/202232 (commit b28c2debc50) changed `languages.match` to search `notebookDocuments` directly, but didn't address this ordering issue.
