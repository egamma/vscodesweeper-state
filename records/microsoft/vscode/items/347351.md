# Issue #347351 — Agent Host BYOK bridge hardcodes 128-tool ceiling; no way for a provider to declare the model's real tool limit

[https://github.com/microsoft/vscode/issues/347351](https://github.com/microsoft/vscode/issues/347351)

## Summary

Keep open: the Agent Host bridge still imposes an unconditional 128-tool ceiling. Current public API already permits a numeric tool limit, but registration discards that value and the bridge cannot honor it.

## Change summary

Allow extension-provided BYOK models to declare their supported tool-definition count instead of always truncating requests at 128.

## Best solution

Honor provider-declared tool limits end to end, preferably using the existing numeric capabilities.toolCalling contract, while retaining 128 when no limit is declared. Coordinate with the pending tool-search capability work without requiring tool-search support from servers that can accept larger ordinary tool lists.
