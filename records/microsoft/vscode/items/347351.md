# Issue #347351 — Agent Host BYOK bridge hardcodes 128-tool ceiling; no way for a provider to declare the model's real tool limit

[https://github.com/microsoft/vscode/issues/347351](https://github.com/microsoft/vscode/issues/347351)

## Summary

The provider-specific tool-limit gap remains on main. The public API already accepts a numeric tool limit, but registration discards that number and the Agent Host bridge still unconditionally caps requests at 128.

## Change summary

Allow BYOK providers to declare their supported tool-definition count instead of imposing a universal 128-tool ceiling.

## Best solution

Honor provider-declared tool limits throughout model registration and the BYOK bridge, retaining the existing fallback for unspecified limits. Coordinate provider-neutral tool search separately; deferral does not replace correct limits when search is disabled.

- **Behavior:**

- **Trace:**
