# Issue #330383 — Sessions that I didn't click on were migrated

[https://github.com/microsoft/vscode/issues/330383](https://github.com/microsoft/vscode/issues/330383)

## Summary

Team-authored bug report from a VS Code maintainer, filed hours ago while actively testing a related session-migration feature (issue #329773); the author has already root-caused two interacting bugs in the migration/eligibility logic with detailed timeline evidence, so this stays open for a fix, not triage.

## Change summary

Enabling then disabling a session-migration setting caused ~169 unrelated legacy sessions to be silently adopted/migrated, including many that failed restore after their working directories no longer existed.

## Best solution

Fix the two root causes described in the author's own investigation: (1) tighten the migration eligibility check so it doesn't rely solely on the presence of `vscode.metadata.json`, and (2) stop treating a `session/isReadChanged` event (triggered by merely refreshing the sessions list) as an open/restore/adopt signal in the Agent Host.
