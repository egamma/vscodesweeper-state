# Issue #329142 — Add a way to override using Wayland instead of X11 in the Snap package.

[https://github.com/microsoft/vscode/issues/329142](https://github.com/microsoft/vscode/issues/329142)

## Summary

Reasonable, well-diagnosed request: the Snap `electron-launch` script unconditionally appends `--ozone-platform=x11` after `"$@"`, so any user-supplied Wayland/ozone flag is overridden by the later `x11` value (Chromium takes the last occurrence of a repeated flag) — routing to the Linux/Snap area owners for a decision, since this is fresh (1 day old, no upvotes/comments) and I found no prior maintainer rationale that this forcing is intentional.

## Change summary

Requests a way to override the Snap package's hardcoded `--ozone-platform=x11` so VS Code can run natively under Wayland.

## Best solution

A maintainer should confirm whether forcing X11 in the snap was a deliberate stability workaround (given known Wayland/snap crash reports) or just an oversight; if not deliberate, reorder the flag (e.g. `exec --ozone-platform=x11 "$@"`) or gate it behind a check for an existing user-supplied `--ozone-platform`/`--ozone-platform-hint` flag in resources/linux/snap/electron-launch.
