# Issue #19534 — Customizing the rendering of matching brackets

[https://github.com/microsoft/vscode/issues/19534](https://github.com/microsoft/vscode/issues/19534)

## Summary

Native underline styling remains unavailable: current bracket matching supports color customization but still draws a fixed box. Keep this accepted Backlog request open; it has 113 upvotes, and a maintainer explicitly consolidated related border-styling work here.

## Change summary

Allow matching brackets to use an underline or another configurable visual treatment instead of the default box.

## Best solution

Provide a small, consistent native bracket-match styling contract that includes underline while preserving existing defaults and theme colors. Settle the public configuration surface with the editor-theming owner before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.css`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/core/editorColorRegistry.ts`
- **Validation:** The plan should define an executable rendering check and a manual acceptance scenario: in nested bracket expressions, move the caret next to each bracket and confirm the chosen underline treatment replaces the box without shifting text; verify unchanged defaults, foreground/background/border color customization, high-contrast visibility, and editor.matchBrackets always/near/never behavior.
- **Behavior:**

  > Users want native matching-bracket highlights that can be underlined rather than boxed. Existing color customization and disabling matching do not satisfy that goal. Acceptance should demonstrate underline on matched bracket pairs without changing text layout, matching locations, or default rendering. Existing theme-color customization and high-contrast visibility must remain usable.
- **Trace:**

  > BracketMatchingController in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts assigns bracket-match to decorations with and without overview-ruler markers. The corresponding CSS fixes a solid box, while editorColorRegistry.ts exposes background, border, and foreground colors only; editorOptions.ts controls matching activation rather than style. This establishes the missing capability without running the editor. The boundary is native match decoration presentation, not bracket parsing, bracket-pair colorization timing, or full-expression highlighting. Maintainers consolidated border-styling discussion here from https://github.com/microsoft/vscode/issues/46804 and favored a limited style vocabulary. The remaining uncertainty is the public configuration contract, not whether underline is already available.
- **Open decisions:**
  - Should bracket-match geometry be controlled by an editor preference independent of the selected theme, or by a theme-owned styling contract?
  - Should the initial public contract offer only box and underline, or also expose the limited border-style and width customization discussed in the consolidated issue?
