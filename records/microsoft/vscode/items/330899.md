# Issue #330899 — Agent host: client tools execute off the stream-mapper ready rather than the SDK invocation

[https://github.com/microsoft/vscode/issues/330899](https://github.com/microsoft/vscode/issues/330899)

## Summary

Well-documented architectural root-cause analysis tying together three already-reported agent-host defects, with an open proposal PR (#330933) awaiting a maintainer design call on whether the stream-mapper ready should remain actionable; this needs human review, not a triage close.

## Change summary

Client tools currently execute off the stream-mapper's toolCallReady event rather than the SDK's actual invocation, and the author argues this single seam is the root cause of three separate bugs (double invocation, empty-argument execution, dropped results) each already filed as its own PR.

## Best solution

A maintainer should decide whether the stream-mapper ready is deliberately actionable (a latency optimization) or should be rendering-only, with tool execution gated on the SDK's own invocation as proposed in https://github.com/microsoft/vscode/pull/330933; until that design call is made, the three symptom PRs (#330683, #330684, #330730) can land independently.
