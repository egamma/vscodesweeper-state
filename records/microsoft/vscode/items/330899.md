## Summary

Well-documented architecture question filed by a contributor to consolidate three related agent-host bug PRs into one root-cause discussion; a concrete proposal PR already exists, so this should stay open for maintainer design review rather than being closed.

## Change summary

Asks whether client tools should execute only on the SDK's own invocation (with the stream-mapper ready used for rendering only) instead of on the stream-mapper `chat/toolCallReady`, since the current dual-trigger seam causes double invocation, empty-argument invocation, and dropped results.

## Best solution

A maintainer with agent-host context should decide whether the single-trigger redesign proposed in https://github.com/microsoft/vscode/pull/330933 is correct (i.e. whether the stream-mapper ready is deliberately actionable for latency, per the reporter's own open question); until decided, keep this open as the umbrella issue and let the three symptom PRs (#330683, #330684, #330730) land independently.
