# Issue #330899 — Agent host: client tools execute off the stream-mapper ready rather than the SDK invocation

[https://github.com/microsoft/vscode/issues/330899](https://github.com/microsoft/vscode/issues/330899)

## Summary

Keep open as the design-level owner for client-tool execution ordering. Current main still exposes client execution when protocol state becomes `Running`, independently of the SDK handler, while two open PRs address resulting symptom classes and the single-trigger proposal was closed without merging.

## Change summary

Choose one authoritative trigger for client-tool execution so streamed readiness cannot cause duplicate calls, incomplete arguments, or results arriving before the SDK handler.

## Best solution

The agent-host maintainers should settle whether SDK invocation or protocol readiness owns client-tool execution, then align the workbench execution path and resolve the remaining symptom PRs consistently with that decision.
