# Issue #330899 — Agent host: client tools execute off the stream-mapper ready rather than the SDK invocation

[https://github.com/microsoft/vscode/issues/330899](https://github.com/microsoft/vscode/issues/330899)

## Summary

Well-documented architectural root-cause issue tying together three separate agent-host bugs (double invocation, empty arguments, dropped results); an open PR (#330933) already proposes the structural fix, so this needs a maintainer design decision, not a close.

## Change summary

Client tools currently execute off the stream-mapper's toolCallReady event rather than the SDK's actual tool invocation, causing three distinct defects (double execution, empty-arg invocation, dropped results); the issue asks whether the trigger should instead be the SDK invocation itself.

## Best solution

A maintainer familiar with agentSideEffects.ts and the stream-mapper/SDK invocation ordering should decide whether client tool execution should be gated on the SDK's own tool invocation (as proposed in PR #330933) rather than the streamed 'ready' event; this determines whether the three symptom PRs (#330683, #330684, #330730) are patches-until-then or can be superseded by the single-trigger fix.
