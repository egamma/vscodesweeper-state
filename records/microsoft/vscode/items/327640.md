# Issue #327640 — MCP auth in Agent Sessions: "Authenticate" notification link is a no-op (targets sessions.html), and the whole auth flow completes silently

[https://github.com/microsoft/vscode/issues/327640](https://github.com/microsoft/vscode/issues/327640)

## Summary

Well-documented, still-reproducing feedback gap in Agent Sessions' MCP authentication flow (dead notification link, silent sign-in) that the reporter has actively tracked across several VS Code versions through 1.133.0; already correctly labeled `agents-window`, with the credential-recovery root cause split out into #330837.

## Change summary

When an MCP server (e.g. GitHub) needs auth in Agent Sessions, the 'Authenticate' notification action is a no-op (link targets sessions.html itself) and neither the notification path nor the Command Palette sign-in path gives any progress/success/error feedback.

## Best solution

Fix the auth-required notification/action so its link actually invokes the sign-in flow (not a same-page anchor navigation to sessions.html), and add explicit progress/success/error feedback to both the notification and the MCP: List Servers sign-in command; likely touches the local agent host's AuthRequired notification handling in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts and the related MCP auth surfacing in agentHostSessionHandler.ts / agentHostCustomizationService.ts.
