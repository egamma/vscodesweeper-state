# Issue #195960 — Add "resourceWebviewId" context key for webviews in `editor/title/context` contribution point

[https://github.com/microsoft/vscode/issues/195960](https://github.com/microsoft/vscode/issues/195960)

## Summary

Valid feature request — no `resourceWebviewId` context key exists on current main. The `activeWebviewPanelId` context key is scoped per editor group (via `registerContextKeyProvider`) but still reflects only the *active* editor, not the right-clicked tab. The request remains unimplemented and already carries `help wanted`.

## Change summary

Add a context key that identifies the webview type of the right-clicked tab in `editor/title/context`, so extensions can properly scope their context menu contributions to specific webview types even on inactive tabs.

## Best solution

Add a `resourceWebviewId` (or similar) context key that is set in `editorTabsControl.ts` → `onTabContextMenu()` alongside the existing per-tab context keys (resource, pinned, sticky, etc.), reading the viewType from the right-clicked `EditorInput` when it is a `WebviewInput`. This parallels how `resourceContext` is already set per-tab for non-active editors. The related issue https://github.com/microsoft/vscode/issues/174905 is distinct (a `webview/title` menu point); both are valid requests.
