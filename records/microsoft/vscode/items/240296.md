# Issue #240296 — Resuming after OS suspend can cause sticky scroll to not work correctly until hovered

[https://github.com/microsoft/vscode/issues/240296](https://github.com/microsoft/vscode/issues/240296)

## Summary

Still present on main: the OS-resume handler in terminalNativeContribution.ts clears the texture atlas only for main terminal xterm instances, not for the sticky scroll overlay's separate xterm — the overlay needs the same forceRedraw treatment.

## Change summary

After OS suspend/resume, the terminal sticky scroll overlay renders corrupted glyphs because its WebGL texture atlas is stale.

## Best solution

Extend `_onOsResume` in `terminalNativeContribution.ts` to also call `clearTextureAtlas()` on the sticky scroll overlay's xterm instance, or expose the overlay's xterm through the contribution so the existing forceRedraw loop can reach it. The fix is small and localized.
