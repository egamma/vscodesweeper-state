# Issue #16082 — [folding] retain folded state on copy/paste

[https://github.com/microsoft/vscode/issues/16082](https://github.com/microsoft/vscode/issues/16082)

## Summary

This remains the canonical, well-supported request: current main preserves existing folding decorations across edits but does not transfer collapsed-region state with copied text. With 53 upvotes, two confirmed duplicates, and a Backlog milestone, it should remain open for design and implementation.

## Change summary

Preserve the folding state of copied or cut code when that code is pasted elsewhere.

## Best solution

Define consistent editor-owned semantics for carrying fully selected collapsed regions through copy, cut, and paste, including nested folds and same-file versus cross-editor pastes. The design should also decide whether line-duplication commands share those semantics and whether preservation is automatic or explicitly requested.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Add an editor-level copy/paste test that copies a selection containing collapsed and nested foldable regions, pastes it at another location, waits for folding-range recomputation, and verifies the agreed collapsed states at the destination while the source state remains unchanged; also cover cut/paste and the chosen partial-selection behavior.
- **Behavior:**

  > When code containing collapsed regions is copied or cut and pasted within the supported editor scope, eligible destination regions retain the source collapsed state after folding ranges are recomputed. Nested collapsed regions follow the agreed containment rules, while unfolded regions and ordinary external clipboard text retain current behavior. The original folding state must remain unchanged after copy, and cut/paste must not leave stale hidden ranges. Acceptance must also cover the agreed behavior for Copy Line Up/Down.
- **Trace:**

  > CopyPasteController in src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts observes copy, cut, and paste events and already transfers editor-owned metadata through application/vnd.code.copymetadata, but CopyMetadata currently contains only provider and default paste payload information. FoldingController in src/vs/editor/contrib/folding/browser/folding.ts reacts to model content changes by recomputing ranges, while FoldingModel._currentFoldedOrManualRanges in src/vs/editor/contrib/folding/browser/foldingModel.ts preserves collapse state only for existing decoration-tracked ranges. Therefore pasted text can become foldable after recomputation but has no source collapse metadata to apply. Copy Line Up/Down follows a separate command path in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts, matching the distinct behavior reported in the thread. Keep external plain-text clipboard behavior and unrelated document-paste providers unchanged. Related reports https://github.com/microsoft/vscode/issues/91948 and https://github.com/microsoft/vscode/issues/128323 were explicitly consolidated into this canonical issue.
- **Open decisions:**
  - Should fold preservation happen automatically for ordinary paste, or only through an explicit Paste Folded command or setting?
  - Should folding metadata be supported only within the same VS Code window, or also across windows where CopyPasteController's current in-memory copy operation is not shared?
  - Which collapsed regions are eligible when the copied selection only partially contains a fold, and how should nested collapsed regions be represented?
  - Should Copy Line Up/Down preserve the original and duplicated folding states using the same contract as clipboard paste?

## Evidence

- **current source gap:** src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts stores text-paste metadata such as multicursor text and paste-on-new-line behavior, but CopyMetadata contains no folding-state information and applyDefaultPasteHandler forwards no collapsed ranges.
- **folding behavior:** src/vs/editor/contrib/folding/browser/folding.ts handles content changes by notifying HiddenRangeModel and recomputing folding ranges; src/vs/editor/contrib/folding/browser/foldingModel.ts carries forward collapsed state only from existing tracked decorations, so newly pasted foldable regions are not restored as collapsed.
- **no existing setting:** The folding options registered in src/vs/editor/common/config/editorOptions.ts cover strategy, limits, controls, highlighting, imports, and unfolding behavior; none preserves folding state during copy and paste.
- **canonical issue:** A maintainer explicitly closed https://github.com/microsoft/vscode/issues/91948 as a duplicate of this issue and reopened this canonical tracker; https://github.com/microsoft/vscode/issues/128323 was later closed for the same reason.
- **community demand:** The issue has 53 body upvotes, exceeds the 20-vote Backlog threshold, carries the Backlog milestone, and has continued receiving support through October 2025.
