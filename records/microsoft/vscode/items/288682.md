# Issue #288682 — Terminal rendering corruption on macOS Apple Silicon - GPU acceleration workaround ineffective

[https://github.com/microsoft/vscode/issues/288682](https://github.com/microsoft/vscode/issues/288682)

## Summary

Genuine terminal WebGL rendering corruption on macOS Apple Silicon, confirmed by multiple users across M1 and M4 chips and multiple macOS versions. The existing `onContextLoss` fallback doesn't catch all corruption cases. Needs area-owner attention and the `terminal-rendering` label.

## Change summary

The integrated terminal intermittently shows garbled/corrupted rendering on macOS Apple Silicon; setting gpuAcceleration to 'auto' does not reliably prevent it (unlike on Windows), and only 'off' fully resolves the issue.

## Best solution

Investigate whether the WebGL renderer on macOS Apple Silicon is failing to detect corruption that doesn't trigger a full context loss event. The fallback in `xtermTerminal.ts` (line ~869) only fires on `onContextLoss`; partial corruption without a context loss goes undetected. Consider proactive corruption detection (e.g. periodic frame validation) or making 'auto' mode more aggressive about falling back to DOM on macOS ARM. This may ultimately be an xterm.js/Chromium upstream issue, but the VS Code layer could mitigate it.
