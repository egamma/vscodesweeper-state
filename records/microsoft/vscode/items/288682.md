## Evidence

- **Independent confirmations:** https://github.com/microsoft/vscode/issues/288682 contains multiple independent confirmations across M1 and M4 Macs and macOS versions. The July 7 comment reports corruption on VS Code 1.127.0; the April 17 comment reports that gpuAcceleration=off avoids it while auto brings it back. These establish reported reproduction, not a current-checkout reproduction.
- **Renderer selection on current main:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:345-354 defaults terminal.integrated.gpuAcceleration to auto. In src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:644-650, _shouldLoadWebgl enables WebGL for auto unless a DOM fallback was suggested, and forceRedraw clears the texture atlas. Auto is not equivalent to disabling GPU rendering.
- **Recovery path and diagnosis boundary:** XtermTerminal._enableWebglRenderer registers onContextLoss and disposes the WebGL renderer at xtermTerminal.ts:958-961. TerminalNativeContribution in src/vs/workbench/contrib/terminal/electron-browser/terminalNativeContribution.ts clears terminal atlases on OS resume. Neither path proves the cause of this intermittent corruption; GPU context loss, stale atlas state, and visibility transitions remain hypotheses.
- **Original report was not fixed:** https://github.com/microsoft/vscode/issues/284827 was closed after an info-needed timeout, not a landed fix. Its maintainer suggested changing GPU acceleration, and the reporter confirmed it had previously been off. This follow-up explicitly reports occurrence with extensions disabled.
- **Related issue is newer:** https://github.com/microsoft/vscode/issues/311614 is open, was created April 21, 2026, and describes intermittent macOS terminal corruption around lock/unlock and desktop switching. This report predates it by three months, so the prior-review duplicate rule prohibits closing this older item into it. Searches for terminal corruption and macOS garbled/rendering reports did not establish an eligible older open canonical.
- **Relevant upstream fixes, resolution unconfirmed:** Merged https://github.com/microsoft/vscode/pull/326772 adopted xterm atlas fixes from https://github.com/xtermjs/xterm.js/pull/6042 and https://github.com/xtermjs/xterm.js/pull/6043. They address shared-atlas page mapping invalidation and texture-capacity overflow. Current package.json uses newer xterm versions, and XtermTerminal loads the WebGL addon, but this report does not establish either specific trigger or confirm recovery after those fixes. The associated https://github.com/microsoft/vscode/issues/322756 is closed and younger, so it is not a duplicate canonical.

These observations should not be collapsed into an assumed single GPU root cause.
