# Issue #340176 — LM API's `selectChatModels` returns no models for vendor `agent-host-copilotcli`

[https://github.com/microsoft/vscode/issues/340176](https://github.com/microsoft/vscode/issues/340176)

## Summary

The empty model selection is explained by the current source: agent-host models reach the workbench catalogue but not the extension-host cache used to construct LM API objects. Keep this open; the comments also establish an extension-handler failure at this boundary, and fixing identifier parsing alone would not provide usable model requests.

## Change summary

Resolve the mismatch between agent-host model availability in the picker and model discovery and resolution through the extension LM API.

## Best solution

Establish a supported contract for agent-host models at the extension LM boundary, then make discovery and request.model resolution consistent with it without silently substituting another model. Address the missing metadata bridge and request-routing capability together rather than exposing model objects whose requests necessarily fail.

- **Trace:**

  > AgentHostChatContribution registers AgentHostLanguageModelProvider directly in the workbench language-model service; its identifiers use vendor:model formatting.
