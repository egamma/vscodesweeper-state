# Issue #340176 — LM API's `selectChatModels` returns no models for vendor `agent-host-copilotcli`

[https://github.com/microsoft/vscode/issues/340176](https://github.com/microsoft/vscode/issues/340176)

## Summary

Live, active investigation (1 day old, already labeled `agent-host`) into a real defect in the agent-host language-model bridge: `AgentHostLanguageModelProvider` builds model identifiers with a `:` separator while `extHostLanguageModels.getVendorFromModelIdentifier` only recognizes `/`, which is consistent with both the reporter's empty `selectChatModels` result and a second contributor's independently traced routing failure. Not enough to pin the exact fix yet, so this stays open for the ongoing diagnosis.

## Change summary

`vscode.lm.selectChatModels({ vendor: 'agent-host-copilotcli' })` returns no models even though the vendor is active and visible in the model picker.

## Best solution

Reconcile the agent-host model identifier format (`${vendor}:${id}` in agentHostLanguageModelProvider.ts) with the `/`-delimited format `getVendorFromModelIdentifier` expects in extHostLanguageModels.ts, and verify end-to-end that `selectChatModels`/`getLanguageModelForRequest` resolve agent-host vendors correctly after #339307 removed the silent default-model fallback.

- **regression context:** A second reporter (zhen9910) traces the behavior change to PR #339307 (commit 0af48c2), which removed the silent fallback to `getDefaultLanguageModel()` in `getLanguageModelForRequest` (src/vs/workbench/api/common/extHostLanguageModels.ts:457-470) — before that, the mismatch was silently masked by falling back to 'auto'; now it surfaces as a hard failure.
- **vendor filtering path:** selectLanguageModels in src/vs/workbench/contrib/chat/common/languageModels.ts:1473-1490 filters by `model.vendor === selector.vendor` metadata, not the identifier string, so the root cause of the reporter's empty-list symptom specifically (vs. the routing-crash symptom in the comment) is not fully confirmed from source alone — plausibly a related but distinct manifestation of the same registration/identifier issue.
