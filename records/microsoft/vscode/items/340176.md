## Evidence

- **Current-source discovery defect:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLanguageModelProvider.ts publishes workbench-side models with identifiers `${this._vendor}:${m.id}`. In src/vs/workbench/api/common/extHostLanguageModels.ts, selectLanguageModels calls _createLanguageModelChatApi for returned identifiers; that helper requires an entry in _localModels and returns undefined when absent. The selection method filters those results out, explaining an empty agent-host-copilotcli selection despite models appearing in the picker.
- **Related resolution and request limitations:** getVendorFromModelIdentifier in src/vs/workbench/api/common/extHostLanguageModels.ts still requires a slash, so colon-form agent-host identifiers fail vendor extraction on a cache miss. AgentHostLanguageModelProvider.sendChatRequest still throws 'Agent-host models do not support direct chat requests'; changing the delimiter alone would not provide working extension requests.
- **Confirmed discussion:** https://github.com/microsoft/vscode/issues/340176#issuecomment-6052641881 documents a Windows reproduction where explicit agent-host model resolution fails before the extension handler executes. https://github.com/microsoft/vscode/issues/340176#issuecomment-6285370692 adds Codex-through-AHP vendor warnings, but explicitly does not establish a resulting tool failure.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/343139 is OPEN, is no longer a draft, and has no merge timestamp. Its body explicitly says 'Fixes #340176' and describes discovery, exact Copilot/BYOK forwarding, authorization, and rejection of unsupported direct requests. Reported local testing is candidate evidence, not a landed fix.
