# Issue #340176 — LM API's `selectChatModels` returns no models for vendor `agent-host-copilotcli`

[https://github.com/microsoft/vscode/issues/340176](https://github.com/microsoft/vscode/issues/340176)

## Summary

Thanks for the detailed report. Vendor ids for the local Agent Host harnesses (e.g. `agent-host-copilotcli`) are registered dynamically per active agent in `AgentHostChatContribution._registerAgent` (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts), and `vscode.lm.selectChatModels` only returns models once that vendor is actually registered with `ILanguageModelsService` — so the result can legitimately depend on whether/when the Agent Host Copilot CLI harness has started in that window. I can't confirm from source alone whether this is a registration-timing gap, a window-context restriction, or working as intended (since `agent-host-*` vendors look like an internal harness-selection mechanism, with `copilotcli`/`copilot` as the documented stable vendors for extensions).

## Change summary

`vscode.lm.selectChatModels({ vendor: 'agent-host-copilotcli' })` returns an empty array even though models are visible for that harness in the chat UI, while `copilot`/`copilotcli` vendors do return models.

## Best solution

An agent-host maintainer should clarify (and if needed fix) whether `agent-host-copilotcli` is meant to be a publicly consumable `vscode.lm` vendor at all, or whether the request should instead use `copilotcli`/`copilot`; if it is meant to work, confirm why the dynamic vendor registration in agentHostChatContribution.ts isn't visible to this extension's `selectChatModels` call (timing, window type, or enablement gate).
