# Issue #349914 — Agent Host: secondary window/profile overwrites shared sandbox root config and enables sandbox for other windows

[https://github.com/microsoft/vscode/issues/349914](https://github.com/microsoft/vscode/issues/349914)

## Summary

Keep open: current source still allows a connecting window's effective sandbox settings to overwrite shared host configuration. This sandbox-boundary concern requires human review, and the reported diagnostics gap also remains.

## Change summary

Prevent secondary windows and profiles from silently changing other sessions' sandbox configuration, and make configuration changes attributable in logs.

## Best solution

Establish explicit ownership and scope for sandbox configuration so connecting another profile cannot alter unrelated sessions, while preserving runtime-managed restrictions. Coordinate with the sandbox-profile proposal and provide bounded, privacy-safe diagnostics for effective flags and change origin.

## Evidence

- **Current overwrite path:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/agentHostSandboxForwarder.ts: _scheduleInitialPush calls _tryPush on connection; _tryPush dispatches RootConfigChanged with the window's entire desired sandbox object whenever it differs from shared root state. There is no profile ownership or explicit-setting precedence check.
- **Defaults are forwarded:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/sandboxSettingsReader.ts: readSandboxSetting reads configurationService.inspect(settingId).value, and readAgentHostSandboxValues includes effective registered defaults. Consequently, a secondary profile with different inherited defaults generates a real configuration overwrite, not an unchanged-value update.
- **Host handling:** src/vs/platform/agentHost/node/agentHostStateManager.ts: _applyAndEmit validates sandbox values and suppresses identical root patches, but accepts differing values into shared root state. src/vs/platform/agentHost/node/agentConfigurationService.ts fires onDidRootConfigChange for accepted root changes. No-op suppression does not prevent the reported differing-profile overwrite.
- **Diagnostics gap:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:1109-1120: applySandboxConfig sends permissions.sandbox through session.rpc.options.update, then logs only the session identifier and a generic success message, without applied flags or originating client.
