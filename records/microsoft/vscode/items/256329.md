# Issue #256329 — GitHub Copilot Chat diff UI does not wrap deleted (red) lines, as it does added (green) lines, when word wrap is enabled

[https://github.com/microsoft/vscode/issues/256329](https://github.com/microsoft/vscode/issues/256329)

## Summary

Keep open: current source still renders Agent review's deleted lines without wrapping information, unlike the added lines. The linked fix PR remains open and needs assessment against this specific rendering path before the issue can be considered resolved.

## Change summary

Make deleted lines in Copilot Agent edit review honor word wrap consistently with added lines.

## Best solution

Agent edit review should wrap both original and modified content according to the editor's effective wrapping behavior. Review https://github.com/microsoft/vscode/pull/292094 against the Agent review path; its diff-editor option change alone does not address the missing line-break data in that path.

## Evidence

- **Confirmed reporter-observable behavior:** https://github.com/microsoft/vscode/issues/256329 describes enabling word wrap while reviewing Agent edits: green lines wrap but red lines do not. The December 9 commenter independently confirms the same symptom with screenshots and distinguishes it from NES, where the opposite side fails to wrap.
- **Defect in current source:** At checkout HEAD 959031245ebb1fe077e0d512e1397c0ae82006e4, src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts:367-372 constructs the original-content LineSource with an empty lineBreakData array. Lines 424-438 render that source into the deleted-content review zone and derive its height from the render result.
- **Why deleted lines cannot wrap:** src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/renderLines.ts checks source.lineBreakData for each original line. Without break data, it renders the whole model line as one view line; RenderOptions.fromEditor does not compute wrapping projections. The Agent review caller therefore bypasses wrapping even when the underlying editor wraps modified content.
- **Existing wrapping support does not cover this caller:** The ordinary diff view in src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/diffEditorViewZones.ts:218-222 supplies line-break data to the same renderer and observes wrapping configuration changes. The chat.editor.wordWrap setting in chat.shared.contribution.ts controls chat codeblocks, not Agent deleted-content review zones.
- **Open human-owned implementation candidate:** https://github.com/microsoft/vscode/pull/292094 is verified OPEN and unmerged and explicitly references this issue. Its sole changed file is src/vs/editor/browser/widget/diffEditor/components/diffEditorEditors.ts, addressing a wordWrapOverride2 state left behind when switching diff layouts; that is distinct from the Agent review caller passing no line-break data.
