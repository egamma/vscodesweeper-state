## Summary

Keep open: current source still renders Agent-edit deleted lines without wrapping information, matching the reported asymmetry. The linked implementation PR remains open and needs assessment against this specific rendering path before the issue can be considered fixed.

## Change summary

Make deleted red lines honor word wrap alongside added green lines in the Agent-edit Keep/Undo review.

## Evidence

- **Current-source defect:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts:367–372 constructs LineSource for the original deleted content with an empty lineBreakData array, then passes it to renderLines at line 427 for the inline review view zone. src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/renderLines.ts renders wrapped segments only when source.lineBreakData[lineIndex] exists; otherwise it emits one visual line per original line. This directly explains why enabling editor wrapping does not wrap the deleted content.
- **Existing capability does not cover this path:** The standard diff editor already computes deleted-code wrapping in src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/diffEditorViewZones.ts:175–193 using createLineBreaksComputer. The Agent-edit rendering path supplies no equivalent projection data. Enabling word wrap therefore does not by itself satisfy the central ask.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/292094 is verified OPEN with no merge commit and explicitly references this issue. Its current patch adds wordWrapOverride2 in DiffEditorEditors, in src/vs/editor/browser/widget/diffEditor/components/diffEditorEditors.ts; it does not change the Agent-edit LineSource construction identified above. The open linked PR precludes a completed-close proposal and competing agent implementation.
