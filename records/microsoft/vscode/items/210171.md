# Issue #210171 — CodeAction previews don't work on "Source" actions

[https://github.com/microsoft/vscode/issues/210171](https://github.com/microsoft/vscode/issues/210171)

## Summary

The original TypeScript organize-imports case was improved, but the underlying defect remains on current main for command-backed source actions: preview intent is applied only to inline edits, while the command executes separately without it. The linked open PR is a partial implementation candidate, so the issue should remain open.

## Change summary

Command-backed source and refactor code actions cannot show the standard Code Action preview when invoked with Ctrl/Cmd+Enter.

## Best solution

Define a supported path for command-backed code actions to produce or associate a WorkspaceEdit after any required user input, then honor the user's preview request before applying that edit. Preserve lazy computation and interactive commands rather than requiring every provider to eagerly return edits.

## Evidence

- **current source:** In src/vs/editor/contrib/codeAction/browser/codeAction.ts, applyCodeAction passes `options?.preview` to `bulkEditService.apply` only for `item.action.edit`; it then invokes `item.action.command` through `commandService.executeCommand` without carrying the preview request or associating subsequent edits with that invocation.
- **preview entry point:** src/vs/editor/contrib/codeAction/browser/codeActionController.ts classifies `CodeActionKind.Source` as previewable and forwards the preview selection to applyCodeAction, while src/vs/platform/actionWidget/browser/actionWidget.ts binds Ctrl/Cmd+Enter to the preview action. The preview request therefore reaches the code-action application path but cannot affect a command-only action.
- **partial TypeScript fix:** https://github.com/microsoft/vscode/commit/9d2deb650d1658739d7adff6cfa352ebc5f204e5 changed TypeScript organize imports from a command-produced edit to `resolveCodeAction`, directly addressing that provider but not command-backed actions generally.
- **label-only improvement:** https://github.com/microsoft/vscode/commit/df0a6ebd8b1b7ab042a610fbcd09da418ac78dd4 added Source actions to the kinds advertised as previewable; its diff does not change how command-produced edits are applied.
- **open implementation lead:** https://github.com/microsoft/vscode/pull/210175 remains open and proposes WorkspaceEdit metadata for requesting a preview. The issue discussion identifies it as a possible step, but it does not yet establish how Ctrl/Cmd+Enter preview intent is propagated through a command-backed CodeAction.
- **related issue:** https://github.com/microsoft/vscode/issues/205857 is older and related to discoverability and consistency of refactor previews, but it does not report the same command-backed Source-action failure and therefore does not meet the stronger duplicate bar for this re-reviewed issue.
