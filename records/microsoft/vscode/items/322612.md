# Issue #322612 — Maximized secondary windows are not restored properly when main window reloads or app relaunches

[https://github.com/microsoft/vscode/issues/322612](https://github.com/microsoft/vscode/issues/322612)

## Summary

This remains a confirmed cross-platform auxiliary-window restoration bug. The newer https://github.com/microsoft/vscode/issues/330650 reports the same observable failure but was filed after this re-reviewed issue, so this older report should remain the canonical item.

## Change summary

Maximized auxiliary editor windows can disappear for one reload or be permanently omitted after relaunch instead of restoring with their saved window state.

## Best solution

Diagnose the state handoff from editor-part persistence through auxiliary BrowserWindow creation, then ensure maximized auxiliary windows are restored on the first reload or relaunch with their editor contents and window mode intact. The newer matching report should be consolidated into this older issue rather than replacing it as canonical.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorParts.ts`, `src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts`, `src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts`, `src/vs/platform/auxiliaryWindow/electron-main/auxiliaryWindowsMainService.ts`, `src/vs/platform/auxiliaryWindow/electron-main/auxiliaryWindow.ts`
- **Validation:** On Windows, open an editor in an auxiliary window, maximize it, reload from both the main and auxiliary window, and then quit and relaunch; after each operation the auxiliary window must appear on the first attempt with its editor contents and maximized mode restored. Repeat the relaunch case on Linux where feasible, and verify that non-maximized auxiliary-window restoration remains unchanged.
- **Behavior:**

  > A maximized auxiliary editor window must be restored on the first reload or application relaunch, with its editor contents present and its maximized state retained. It must not disappear until a second reload, and relaunching must not permanently discard its persisted entry. Non-maximized auxiliary windows and ordinary main-window restoration must continue to behave as before.
- **Trace:**

  > EditorParts.createState() in src/vs/workbench/browser/parts/editor/editorParts.ts combines each auxiliary editor-part state with AuxiliaryWindow.createState(), while restoreState() recreates each saved part. NativeAuxiliaryWindow in src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts tracks maximization through an asynchronous native-host query and maximize/unmaximize events. BrowserAuxiliaryWindowService.openWindow() serializes the saved mode into window-maximized=yes; AuxiliaryWindowsMainService.computeWindowStateAndOverrides() maps it to WindowMode.Maximized, and AuxiliaryWindow.tryClaimWindow() applies the state to the BrowserWindow. The matching reports confirm the user-visible failure, but source inspection does not establish whether the saved entry is stale, the maximized flag races shutdown, or the Electron window is claimed/applied in the wrong order. Keep the investigation bounded to auxiliary-window persistence and native creation; do not change main-window restoration or non-maximized semantics. The newer same-symptom report is https://github.com/microsoft/vscode/issues/330650 and should feed evidence into this older canonical issue.
