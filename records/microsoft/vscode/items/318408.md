# Issue #318408 — Selected model in a session isn't always preserved on Reload

[https://github.com/microsoft/vscode/issues/318408](https://github.com/microsoft/vscode/issues/318408)

## Summary

The per-session model selection is not reliably restored on reload. The model picker stores the last-used model per provider/session-type in profile storage, but the per-session `modelId` observable may not be restored in time, causing the fallback (remembered or default) model to override the session-specific choice. No fixing commit references this issue.

## Change summary

Reloading the Agents window can reset a session's selected model to the default instead of preserving the per-session choice.

## Best solution

The restore path in `ModelPicker._initModel()` (src/vs/sessions/contrib/chat/browser/modelPicker.ts, lines 256–264) relies on `session.modelId` being populated before the model picker re-evaluates. If the session provider hasn't yet restored the model ID when `_initModel()` runs, the picker falls through to the fallback. The fix likely needs to ensure the session's `modelId` is persisted per-session (not just per provider/session-type) and restored before the model picker seeds its selection, or to defer seeding until the session model is confirmed.

## Evidence

- **persistence mechanism:** src/vs/sessions/contrib/chat/browser/modelPicker.ts line 129 stores model per provider+sessionType in StorageScope.PROFILE, but not per individual session ID — so all sessions of the same type share one remembered model.
- **restore logic:** Lines 256–264: for existing (non-untitled) sessions, the picker uses session.modelId.get(), falling back to _getFallbackModel (the shared remembered model) only when the session's vendor has resolved. A timing race on reload could cause it to skip the session's actual model.
