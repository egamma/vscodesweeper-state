# Issue #318029 — Setup gets stuck due to dllhost.exe blocking inno_updater.exe from finishing cleanup

[https://github.com/microsoft/vscode/issues/318029](https://github.com/microsoft/vscode/issues/318029)

## Summary

This is a real continuation/regression of the previously 'fixed' #294546: the KillContextMenuComSurrogate PowerShell kill command in code.iss still fails in production (PowerShell exits non-zero), leaving the COM surrogate alive and inno_updater stuck retrying for minutes — confirmed on two machines plus a second reporter across several releases.

## Change summary

The installer's attempt to kill the context-menu COM surrogate (dllhost.exe) via an inline-quoted PowerShell -Command string fails, so inno_updater can't delete the old commit folder and setup stalls/retries.

## Best solution

Replace the fragile nested double-quote '-Command "..."' invocation in build/win32/code.iss's KillContextMenuComSurrogate with a more robust mechanism — e.g. write the script to a temp .ps1 and invoke `powershell.exe -File <path>`, or use -EncodedCommand (base64 UTF-16) — to eliminate the quote-escaping that appears to break on real Windows CreateProcess argument parsing.

## Plan brief

- **Likely files:** `build/win32/code.iss`
- **Validation:** Manual verification on Windows: lock the context-menu COM surrogate DLL via an open Explorer window, run the silent installer over an existing install, and confirm inno_updater's log shows the dllhost.exe process killed and the old commit folder removed without retry-looping.
- **Behavior:**

  > When VS Code auto-updates or is silently reinstalled while a File Explorer COM surrogate (dllhost.exe) holds the context-menu DLL open, the installer must successfully terminate that surrogate so inno_updater can delete the old commit folder without retrying for an extended period or getting stuck. Today, per the reporter's logs, the kill command exits with code 1 and the surrogate is not terminated, exactly reproducing the behavior #294546 claimed to fix.
- **Trace:**

  > KillContextMenuComSurrogate in build/win32/code.iss (around lines 1712-1733) builds a 'powershell.exe' command line using Pascal string concatenation with nested '' and "" quote-doubling to embed a Get-CimInstance/Stop-Process one-liner inside a -Command "..." argument, then calls ShellExec directly (bypassing cmd.exe). I confirmed with pwsh that the *intended* post-quote-resolution script is syntactically valid, which points the suspect root cause at how the literal doubled-quote command-line string is actually re-split into argv by Windows when CreateProcess/ShellExecuteEx parses it — the reporter's own manual reproduction of 'the exact same command line' produced a parser error ('string is missing the terminator'), and production logs show PowerShell exiting non-zero. The boundary: this is purely about the quoting/invocation mechanism for the surrogate-kill step — do not change the Stop-Process/CIM filter logic, the retry/backoff behavior of inno_updater itself, or other parts of the installer script. Related: https://github.com/microsoft/vscode/issues/294546 (the original, closed, incomplete fix).
