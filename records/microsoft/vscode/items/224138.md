# Issue #224138 — Catch-all check for deletion of nameless folder

[https://github.com/microsoft/vscode/issues/224138](https://github.com/microsoft/vscode/issues/224138)

## Summary

The destructive path remains present on current main: a transient nameless explorer item can reach permanent deletion with a synthetic resource rather than a real child resource. A newer independent report provides current reproduction steps, so this data-loss issue should remain open as the older canonical report.

## Change summary

Prevent deletion commands on a nameless transient Explorer item from deleting an unintended directory.

## Best solution

Keep deletion unavailable for transient or otherwise invalid nameless Explorer entries, while preserving normal deletion for resolved files and folders. Add regression coverage proving that selecting such an entry never produces a ResourceFileEdit.

- **Trace:**

  > NewExplorerItem in src/vs/workbench/contrib/files/common/explorerModel.ts is constructed with URI.file('') and derives an empty name from that synthetic resource. Both moveFileToTrashHandler and deleteFileHandler in src/vs/workbench/contrib/files/browser/fileActions.ts accept every selected non-root ExplorerItem, and deleteFiles converts its resource into a recursive ResourceFileEdit without validating that the entry represents a resolved filesystem child.
