# Issue #309693 — Agents: Multiple sessions in same worktree cause changes Sync Pull Requests button to duplicate and to fire in the wrong session

[https://github.com/microsoft/vscode/issues/309693](https://github.com/microsoft/vscode/issues/309693)

## Summary

Confirmed bug (MEMBER-reproduced) where multiple agent sessions sharing the same worktree cause action buttons to duplicate and dispatch to the wrong session. No fix found on current main; the button registration and action dispatch in agentHostSkillButtons.ts uses the global active session rather than scoping to the session that owns the button instance.

## Change summary

When multiple agent sessions use the same worktree, the Changes view's Sync Pull Requests button (and other action buttons) duplicates and fires actions against the wrong session.

## Best solution

The button actions in `src/vs/sessions/contrib/providers/agentHost/browser/agentHostSkillButtons.ts` dispatch via `sessionsService.activeSession.get()`, and the menu contributions likely accumulate across sessions sharing a worktree. The fix should scope button contributions and action dispatch to the owning session, likely in the changes view toolbar and the skill-button registration. The changes view (`src/vs/sessions/contrib/changes/browser/changesView.ts`) may also need session-scoped toolbar management.
