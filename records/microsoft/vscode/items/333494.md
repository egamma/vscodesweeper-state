[https://github.com/microsoft/vscode/issues/333494](https://github.com/microsoft/vscode/issues/333494)

## Summary

Keep open for design: the request is for agent-accessible background customization, not a failure of the existing image picker. Human-facing settings and commands exist, but the inspected source does not establish equivalent agent affordances or the suggested generated-background flow.

## Change summary

Let agents discover and configure chat backgrounds, with AI-generated backgrounds as a possible follow-on.

Define an agent-accessible configuration contract that can discover supported background settings, apply a requested image, and report the result while preserving existing theme-specific behavior. Decide separately whether generated or topic-driven backgrounds belong in the initial scope.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/chat.contribution.ts`, `src/vs/sessions/services/chatBackground/browser/chatBackgroundService.ts`
- **Validation:** In an Agents window, ask the agent to set a known local image without manually using the picker, verify the requested theme-specific setting and rendered background, then ask it to change the layout and clear the background. Confirm the other theme's configuration is unchanged and high-contrast suppression remains intact.
- **Behavior:**

  > A user should be able to ask an agent to configure a chat background with affordances equivalent to the existing human workflow. The agent must discover supported options, apply the requested background, and accurately communicate whether the operation completed. Acceptance should cover selecting a local image, changing its layout, clearing it, and preserving separate dark/light configuration and high-contrast suppression. Generated and automatically topic-selected backgrounds are additional requested possibilities whose inclusion is not yet settled.
- **Trace:**

  > SetChatBackgroundAction.run in src/vs/sessions/contrib/chat/browser/chat.contribution.ts is interactive: it accepts no background argument and uses a Quick Pick and file dialog. SessionsChatBackgroundService.setBackground in src/vs/sessions/services/chatBackground/browser/chatBackgroundService.ts already persists the chosen path or preset to the appropriate user setting. Thus the existing rendering and configuration substrate is present, while equivalent agent discovery and operation have not been established by this trace. The inspected Copilot settings schema concerns internal advanced settings, and VSCodeAPITool supplies extension API context rather than this operation. Preserve existing human customization, theme separation, and high-contrast behavior. https://github.com/microsoft/vscode/issues/333494 proposes both general agent-first affordances and a possible generated-background flow; https://github.com/microsoft/vscode/issues/333232 documents the existing human-facing feature.
- **Open decisions:**
  - Should the initial user-facing capability cover background customization specifically, or general discovery and modification of supported VS Code settings and commands?
  - Should the initial scope only configure existing local images and presets, or also offer image generation; if generation is included, should topic-driven background changes require an explicit user request?
