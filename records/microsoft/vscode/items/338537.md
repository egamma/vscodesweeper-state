# Issue #338537 — Peer chat doesn't show customizations for separate workspace

[https://github.com/microsoft/vscode/issues/338537](https://github.com/microsoft/vscode/issues/338537)

## Summary

Team-authored bug tied to a real version milestone (1.141.0), so it stays open regardless of staleness or workaround availability — no fix commit references this issue's number, so no implemented-on-main close applies either.

## Change summary

When a chat session spawns a peer/nested chat session rooted at a different workspace folder (e.g. a docs repo), customizations (instructions/agents/etc.) configured for that separate workspace are not picked up, unlike opening a fresh chat session directly in that workspace.

## Best solution

Trace how customization discovery is scoped to a working directory for nested/peer sessions in the agent host (working-directory-change handling and customizationDirectory tracking in copilotAgent.ts) and ensure it re-resolves customizations against the peer session's workspace root rather than inheriting the parent session's.
