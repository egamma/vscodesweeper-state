# Issue #184326 — Clipboard access is blocked when not via a user gesture

[https://github.com/microsoft/vscode/issues/184326](https://github.com/microsoft/vscode/issues/184326)

## Summary

Still valid on current main: the extension clipboard API (`env.clipboard`) still only exposes `readText`/`writeText` — there is no equivalent to `navigator.clipboard.read()` for binary/multi-MIME clipboard data. The webview iframe permissions policy now includes `clipboard-read`/`clipboard-write`, but the underlying user-gesture browser requirement and the missing rich-clipboard extension API remain unaddressed. Assigned to deepak1556 and mjbvz with `help wanted`.

## Change summary

Webview clipboard access blocked without a user gesture, and the extension API lacks a `clipboard.read()` equivalent for binary/multi-MIME clipboard items.

## Best solution

Add an `env.clipboard.read()` API (or equivalent) that returns structured clipboard items with multiple MIME types, mirroring `navigator.clipboard.read()`. For webviews, explore forwarding clipboard reads through the extension host to bypass the user-gesture requirement. The `help wanted` label is appropriate — this is a well-scoped API addition.
