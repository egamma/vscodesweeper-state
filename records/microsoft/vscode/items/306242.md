# Issue #306242 — he image data you provided does not represent a valid image. Please check your input and try again with one of the supported image formats:

[https://github.com/microsoft/vscode/issues/306242](https://github.com/microsoft/vscode/issues/306242)

## Summary

Keep open: multiple reporters confirmed that generated or implicitly supplied images can produce persistent 400 errors, including on 1.114 after the terminal-result fix. Current main still contains paths that forward original image bytes after validation or resizing fails.

## Change summary

Copilot Chat can send an invalid image that the user did not intentionally attach, causing the request and subsequent turns to fail with an image-processing 400.

## Best solution

Identify every generated/tool-image ingress path, reject or omit invalid image data before it enters conversation history, and ensure one malformed image cannot make later text-only turns fail. The investigation should distinguish the already-fixed terminal-output path from remaining view-image and MCP/tool-result paths.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/image/vscode-node/imageServiceImpl.ts`, `extensions/copilot/src/extension/tools/node/viewImageTool.tsx`, `extensions/copilot/src/extension/tools/node/imageToolUtils.ts`, `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`, `src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts`, `src/vs/workbench/contrib/chat/browser/chatImageUtils.ts`
- **Validation:** Add targeted tests using invalid bytes and MIME-mismatched image data from generated/view-image and MCP tool results; each request must avoid sending an invalid image, and a subsequent text-only turn in the same conversation must succeed.
- **Behavior:**

  > A generated or tool-provided image must not cause an image-validation 400 when the user did not intentionally attach it. Invalid or MIME-mismatched image content must not be retained in a form that makes every later turn fail. Valid PNG, JPEG, GIF, and WebP inputs must continue reaching vision-capable models, and the terminal-output behavior verified in 1.114 must remain unchanged.
- **Trace:**

  > The issue has multiple confirmations, including one on 1.114 after the terminal-result image fix documented at https://github.com/microsoft/vscode/issues/307062. In extensions/copilot/src/platform/image/vscode-node/imageServiceImpl.ts, a failed `_chat.resizeImage` call falls back to the original bytes; ViewImageTool in extensions/copilot/src/extension/tools/node/viewImageTool.tsx supplies a MIME type inferred only from the extension by imageToolUtils.ts. The model adapter in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts serializes those image parts into the request. A parallel path exists in src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts, where failed resizing also falls back to original decoded data with the declared MIME type. The uncertainty starts at determining which path produced the implicit image in this report and where failed image content becomes durable conversation history. Preserve valid-image support and do not regress the terminal-output exclusion already verified in 1.114.

## Evidence

- **confirmed reports:** https://github.com/microsoft/vscode/issues/306242 contains independent reports across several models; one reporter identified a generated PNG with embedded draw.io metadata, while another still reproduced on VS Code 1.114.0 without intentionally uploading an image.
- **remaining source path:** extensions/copilot/src/platform/image/vscode-node/imageServiceImpl.ts catches `_chat.resizeImage` failures and returns the original bytes with the declared MIME type; extensions/copilot/src/extension/tools/node/viewImageTool.tsx then wraps those bytes in `LanguageModelDataPart.image`.
- **extension-derived MIME:** extensions/copilot/src/extension/tools/node/imageToolUtils.ts determines MIME type solely from the filename extension, while extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts serializes accepted image parts directly into model requests.
- **MCP fallback:** src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts catches image-resize failures and forwards the original decoded bytes with the tool-declared MIME type, leaving malformed or MIME-mismatched data able to reach model history.
- **distinct remaining path:** https://github.com/microsoft/vscode/issues/307062 records that VS Code 1.114 stopped returning images from terminal tool results to the model, but the later 1.114 confirmation here shows that fix did not cover every trigger.
- **related narrower report:** https://github.com/microsoft/vscode/issues/311732 is a younger open report describing the narrower MIME-mismatched MCP-image case and the same persistent conversation poisoning; it is related evidence, not an older canonical for this broader report.
