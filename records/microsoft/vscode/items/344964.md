## Summary

The reported link loss is confirmed in current source: the @template renderer discards structured link parts before converting the description to Markdown. Keep this open as a bounded bug in the built-in TypeScript extension.

## Change summary

Render @template descriptions without losing structured link content, while preserving type-parameter labels and existing description formatting. Cover the reported symbol-link case in the existing text-rendering unit suite.

The reporter subsequently confirmed the same behavior on 1.144.0; the automated upgrade suggestion does not resolve the report.
- **Confirmed source defect:** In extensions/typescript-language-features/src/languageFeatures/util/textRendering.ts, getTagBody() handles template tags by retaining only parts whose kind is text. This removes link, linkName, and linkText parts. Each surviving text string is passed to convertLinkTags(), whose string branch returns it unchanged, so the discarded Foo.bar link cannot reach the rendered tag description.
- **Exact hover path:** In extensions/typescript-language-features/src/languageFeatures/hover.ts, getContents() passes quickinfo documentation and tags to documentationToMarkdown(). In textRendering.ts, ordinary documentation goes through asPlainTextWithLinks(), while tags go through tagsToMarkdown(), getTagDocumentation(), and the defective template-specific getTagBody() branch. This explains why the type-parameter documentation can retain a link while its @template line loses it.
