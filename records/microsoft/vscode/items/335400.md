# Issue #335400 — Integrated browser MCP tool calls always aborted with "interrupted before a result was received"

[https://github.com/microsoft/vscode/issues/335400](https://github.com/microsoft/vscode/issues/335400)

## Summary

The detailed report shows a real Claude Agent Host client-tool failure, not an isolated page problem: eight consecutive browser calls failed and `toolSearch` was interrupted through the same tool bridge. This should remain open and be routed to the Agent Host and integrated-browser owners for diagnosis.

## Change summary

Claude agent sessions begin aborting integrated-browser and tool-search calls after those tools initially worked in the same session.

## Best solution

Identify which Agent Host lifecycle event cancels or invalidates pending Claude client-tool requests, then preserve valid calls across that transition or return a specific actionable error. Validate the complete Claude-to-workbench round trip with consecutive browser and tool-search calls in one session.

- **Trace:**

  > The report at https://github.com/microsoft/vscode/issues/335400 records eight consecutive interruptions after browser tools had worked earlier in the same session; `toolSearch` failing too rules out a page-specific Playwright problem. ClaudeAgentSession._rebindForSyncedState rejects all parked client-tool requests before rebuilding the SDK query, while agentSideEffects.ts transports workbench completions back to the provider. The trace has not established whether a tool-set/customization rebind, session teardown race, duplicate tool-use ID, or another SDK lifecycle event causes the observed abort. Keep explicit user cancellation and genuine session disposal semantics unchanged; the investigation should focus on why ordinary late-session calls enter a cancellation path.

## Evidence

- **confirmed report:** https://github.com/microsoft/vscode/issues/335400 documents eight consecutive failures in one session, including `MCP error -32001: AbortError: interrupt`, while the page remained loaded and no user cancellation or consent prompt occurred.
- **cross-tool scope:** The same session also interrupted `toolSearch`, which does not access the browser page. That evidence places the likely failure in the shared Claude client-tool lifecycle rather than Notion, Playwright evaluation, or browser page state.
- **client-tool bridge:** src/vs/platform/agentHost/node/claude/clientTools/claudeClientToolMcpServer.ts parks each in-process MCP handler while awaiting a workbench result; src/vs/platform/agentHost/node/claude/claudeAgentSession.ts completes those requests through `_pendingClientToolCalls`.
- **cancellation path:** ClaudeAgentSession._rebindForSyncedState in src/vs/platform/agentHost/node/claude/claudeAgentSession.ts rejects every pending client-tool call with CancellationError before rebuilding the SDK query. Session disposal has a similar rejection path, but the supplied evidence does not establish which lifecycle transition fired.
- **browser path:** src/vs/workbench/contrib/browserView/electron-browser/tools/readBrowserTool.ts and runPlaywrightCodeTool.ts invoke IPlaywrightService normally; their invocation cancellation tokens are not forwarded into the Playwright operation, making a shared upstream interruption more consistent with the reported cross-tool failures.
- **no known resolution:** Repository history after the 2026-09-10 report contains no concrete commit tied to this issue or clearly changing the implicated Claude client-tool completion path, and no related open PR is linked.
