# Issue #294883 — Background agent: Worktree

[https://github.com/microsoft/vscode/issues/294883](https://github.com/microsoft/vscode/issues/294883)

## Summary

Keep open: automatic background-agent worktrees still use a nested layout that changes sibling-relative project references. Existing manual destination selection does not cover this workflow, and the related older configuration request does not report the same observable failure required for a duplicate close on re-review.

## Change summary

Support background-agent worktree placement that preserves relative references to projects in sibling repositories.

## Best solution

Provide a supported way to place automatic background-agent worktrees alongside the original repository so unchanged sibling-relative ProjectReference paths continue to resolve. Coordinate with the worktree-location configuration proposal without assuming that general multi-root support alone preserves these paths.

The reporter clarified that VS Code 1.109.2 was already installed, so the automated upgrade comment does not establish resolution.
- **Current automatic creation path:** extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorktreeServiceImpl.ts:113 calls gitService.createWorktree with branch, commitish and noTrack, but no destination path. extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:377-380 forwards those options to the built-in Git repository API.
- **Default layout remains nested:** extensions/git/src/repository.ts:1952-1969 uses a stored worktree root when available; otherwise it constructs <repository-parent>/<repository-name>.worktrees/<worktree-name>. For the reported layout, ../project-b-dir therefore resolves beneath the .worktrees container rather than beside the original repository. This is explicit placement behavior; preserving external project references requires an additional supported capability rather than correcting C# reference resolution.
- **Existing capability is partial:** extensions/git/src/commands.ts:3670-3712 provides an editable destination when manually creating a Git worktree. The automatic background-agent call does not invoke that picker, and no worktree-root configuration registration was found in extensions/git/package.json. Manual destination selection is not automatic preservation of the reporter's project layout.
