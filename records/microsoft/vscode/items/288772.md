# Issue #288772 — Prevent viewType collisions by enforcing extension ID prefixing

[https://github.com/microsoft/vscode/issues/288772](https://github.com/microsoft/vscode/issues/288772)

## Summary

This is a feature request to enforce viewType uniqueness via extension ID prefixing. VS Code currently documents that viewType 'must be unique' and recommends including the extension ID, but does not enforce it — the current behavior is by-design advisory, not a bug.

## Change summary

Enforce extension ID prefixing on custom editor viewType registrations to prevent collisions between extensions.

## Best solution

The custom-editors area owner should decide whether to enforce prefixing (a breaking change for existing extensions) or improve the collision UX — e.g. disambiguating duplicate viewTypes in the 'Open With' menu by showing the extension name. A softer approach (warning at activation, better disambiguation in UI) is more realistic than hard enforcement given the ecosystem impact.
