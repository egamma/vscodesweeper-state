# Issue #256188 — Minimized windows cannot be restored

[https://github.com/microsoft/vscode/issues/256188](https://github.com/microsoft/vscode/issues/256188)

## Summary

Keep open: restoring each window's minimized state remains unsupported on current main. The source deliberately excludes that state, making this a capability request rather than a deviation from the implemented behavior; that does not justify declining the already accepted report.

## Change summary

Preserve which VS Code windows were minimized when restoring a multi-window session after quitting, updating, or restarting Windows.

## Best solution

Support per-window minimized-state restoration in the desktop window persistence and startup paths, preserving the visible working window without bringing every background window onto the screen. An area maintainer should first settle whether this changes the default restoration behavior or is opt-in.

## Evidence

- **reported trigger:** https://github.com/microsoft/vscode/issues/256188 describes Windows 11 23H2 with VS Code 1.102.0: minimize all but one window, use the taskbar's Close all windows action, then reopen VS Code; all restored windows appear on screen.
- **current persistence behavior:** src/vs/platform/windows/electron-main/windowImpl.ts:1443–1513, CodeWindow.serializeWindowState(), explicitly says 'we don't want to save minimized state' and serializes non-fullscreen windows as Normal or Maximized. src/vs/platform/windows/electron-main/windowsStateHandler.ts:258–267 persists that result as uiState.
- **current restoration model:** src/vs/platform/window/electron-main/window.ts:179–184 retains WindowMode.Minimized only for compatibility with existing stored state and marks it unused. src/vs/platform/windows/electron-main/windows.ts:147 creates normal restored windows with show enabled. These paths establish the missing capability without executing Windows UI behavior.
- **existing-capability check:** src/vs/workbench/electron-browser/desktop.contribution.ts:183–206 registers window.restoreWindows and window.restoreFullscreen. The former selects which windows reopen; even 'preserve' does not preserve minimized state. 'one' avoids reopening other windows rather than restoring them minimized, so it does not satisfy the request.
- **related upstream issue is not the same requirement:** https://github.com/electron/electron/issues/37494 is open and concerns Virtual Desktop/macOS Space assignments. The reporter linked this report there at https://github.com/electron/electron/issues/37494#issuecomment-3500066639, but that association does not establish an upstream cause for VS Code's explicit omission of minimized state.
- **canonical search:** Searched open microsoft/vscode issues for minimized restoration, restart, session, and reopening. Verified https://github.com/microsoft/vscode/issues/146915 and https://github.com/microsoft/vscode/issues/123517 are open, but both concern virtual-desktop assignment rather than minimized-state persistence; neither is a verified canonical for this request.
