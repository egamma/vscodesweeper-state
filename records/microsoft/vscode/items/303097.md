# Issue #303097 — Respect Per-Prompt `model` Declaration in Nested / Chained Prompt Calls

[https://github.com/microsoft/vscode/issues/303097](https://github.com/microsoft/vscode/issues/303097)

## Summary

A real customization-design request remains, but current prompt-file references are context composition rather than independent model invocations. Route this to chat customizations to decide whether nested execution belongs in prompt files or should remain an agents/subagents capability.

## Change summary

Allow each reusable prompt invoked from another prompt or agent to execute with its own declared language model and defined fallback order.

## Best solution

Establish one clear orchestration contract: either make nested prompt execution a first-class request boundary with explicit model, fallback, cost, and failure semantics, or document prompt files as single-request composition and direct multi-model pipelines to custom agents and `runSubagent`.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts`
- **Validation:** The plan should end with an automated chat-customization test that records the model used for a nested task and verifies the chosen declaration/fallback policy, including unavailable or disallowed models.
- **Behavior:**

  > Reusable customization pipelines need predictable, observable model routing for child tasks without silently charging every task to the parent model. The accepted design must define whether invoking one prompt from another creates an independent model request, which declaration wins, and what happens when the requested model is unavailable or exceeds cost policy. Direct prompt execution and ordinary single-model chat behavior must remain unchanged.
- **Trace:**

  > Current prompt execution enters through `ChatWidget._applyPromptFileIfSet` in `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`: it resolves a slash prompt, attaches the file as request context, and applies only that prompt header's model through `_applyPromptMetadata`. `IChatPromptSlashCommand` and its construction in `promptsService.ts` / `promptsServiceImpl.ts` describe discoverable prompt files but do not model nested execution frames. Independent child requests instead run through `RunSubagentTool`; https://github.com/microsoft/vscode/pull/308784 added explicit and custom-agent model selection there. The boundary is customization orchestration: do not treat textual prompt-file inclusion as an independent request unless the public prompt contract is intentionally changed, and preserve existing direct prompt model selection.
- **Open decisions:**
  - Should a prompt-file reference create an independently billed model invocation, or should prompt files remain content composition while multi-model orchestration uses custom agents and `runSubagent`?
  - If nested prompt invocations are introduced, should their declared model be mandatory when available or remain constrained by the parent model's cost tier and availability policy?

## Evidence

- **current prompt execution path:** On current main, `ChatWidget._applyPromptFileIfSet` in `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts` resolves one slash prompt, attaches it as prompt-file context, and applies that prompt's header through `_applyPromptMetadata`; referenced prompt content does not establish additional request/model invocation frames.
- **partial existing capability:** https://github.com/microsoft/vscode/pull/308784 added model selection for true `runSubagent` invocations. Current `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts` resolves an explicit model first, then a custom agent's declared model, then the parent model, subject to cost-tier constraints.
- **not a duplicate:** The older https://github.com/microsoft/vscode/issues/298380 covered the narrower `runSubagent` model parameter and is closed after its implementation; it does not establish the requested `.prompt.md` nested-execution contract and cannot serve as an open duplicate canonical.
- **evolving product boundary:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts` and `aiCustomization/customizationMigrationCategories.ts` state that agent-host harnesses ignore prompt files and offer migration from deprecated prompt files to skills, making the prompt-versus-agent orchestration boundary an explicit product decision.
