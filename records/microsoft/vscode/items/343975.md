# Issue #343975 — Git: repository.show(ref, filePath) on an untracked or newly added file runs recursive git ls-tree across the entire repo and stringifies all paths on failure

[https://github.com/microsoft/vscode/issues/343975](https://github.com/microsoft/vscode/issues/343975)

## Summary

The reported API failure path remains present on current main: a missing historical file triggers recursive enumeration and serialization of the repository tree. Route to Git for a bounded performance fix that preserves case-mismatch recovery.

## Change summary

Reading an untracked or newly added file at an earlier Git ref can enumerate the entire repository and stringify every path before failing.

## Best solution

Missing historical files should fail with bounded lookup work and a concise diagnostic, while genuine case mismatches continue resolving correctly in the built-in Git extension.
