# Issue #66703 — [css] support IE10 repeat syntax

[https://github.com/microsoft/vscode/issues/66703](https://github.com/microsoft/vscode/issues/66703)

## Summary

A real parser gap remains in the bundled CSS language service: current main still interprets IE10's numeric `[3]` repetition as a named grid line and requires an identifier. Keep this open as upstream work rather than closing a valid legacy-syntax request.

## Change summary

Accept the IE10 `-ms-grid-columns: (1fr)[3]` repetition syntax without reporting a CSS parsing error.

## Best solution

Teach the parser in https://github.com/microsoft/vscode-css-languageservice to recognize IE10's parenthesized track followed by a numeric repetition count, add a parser/validation regression test, and then consume the updated language-service version in VS Code.

## Evidence

- **current parser path:** In https://github.com/microsoft/vscode-css-languageservice/blob/main/src/parser/cssParser.ts, `_parseTermExpression` routes `[3]` to `_parseNamedLine`, whose loop accepts identifiers only; the numeric token therefore leaves the closing bracket unconsumed and produces `RightSquareBracketExpected`.
- **property metadata:** The current CSS language-service data in `src/data/webCustomData.ts` recognizes `-ms-grid-columns` as a nonstandard IE10 property, but its generic `<track-list>` syntax metadata does not add parser support for the legacy `(track-size)[count]` form.
- **VS Code integration:** `extensions/css-language-features/server/package.json` delegates CSS parsing and validation to `vscode-css-languageservice` (`^7.0.0-next.2`), so the parser correction belongs in that dependency before VS Code consumes it.
