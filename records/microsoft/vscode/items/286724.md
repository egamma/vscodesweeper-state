# Issue #286724 — Chat: support an action to send a chat request and clear widget

[https://github.com/microsoft/vscode/issues/286724](https://github.com/microsoft/vscode/issues/286724)

## Summary

The requested send-current-request-and-return-to-an-empty-chat flow remains absent on current main. The previous implementation attempt was closed unmerged after review identified an unresolved UX distinction from the existing “Send to New Chat” action, so this should remain open for that design decision.

## Change summary

Add an action that submits the current chat request in its existing session and immediately returns the widget to an empty new session.

## Best solution

Preserve the existing “Send to New Chat” behavior while exposing the inverse background-submit flow through a clearly named action or new-chat affordance. A maintainer should first decide where that distinct behavior appears and how it is described to users.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`, `src/vs/workbench/contrib/chat/browser/chat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatExecuteActions.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`
- **Validation:** Add focused chat action/widget tests proving that the request is accepted by the original session before the widget displays an empty new session, while the existing “Send to New Chat” action continues submitting into the new session; run scripts/test.sh --grep "SendToNewChatAction".
- **Behavior:**

  > Users can submit the current draft to its current chat session and immediately continue from an empty chat without waiting for the response. The submitted request remains associated with the original session and completes there. The existing “Send to New Chat” behavior remains available and continues sending the draft into the newly created session. The new behavior must have wording and placement that distinguish these two outcomes.
- **Trace:**

  > SendToNewChatAction in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts currently saves the draft, clears the current session, and submits the draft into the replacement session. ChatWidget.acceptInput and _acceptInput in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts submit through IChatService and expose an onRequestAccepted callback, while IChatAcceptInputOptions is declared in src/vs/workbench/contrib/chat/browser/chat.ts. The abandoned https://github.com/microsoft/vscode/pull/286767 demonstrated a bounded widget/action approach, but it altered the existing action and was closed after maintainers questioned that semantic change. Preserve ordinary submission, queueing, editing-session handling, and the existing “Send to New Chat” contract; the uncertainty is the user-facing entry point and naming for the inverse flow.
- **Open decisions:**
  - Should the background-submit behavior be a distinct alternate submit action, an option on the empty/new-chat screen, or another explicit affordance?
  - What user-facing label should distinguish “submit to the current session, then open an empty chat” from the existing “Send to New Chat,” which submits the draft into the new session?

## Evidence

- **current behavior:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts defines SendToNewChatAction by clearing the current session through clearChatSessionPreservingType and then submitting the saved draft into the new session; it does not submit to the original session and leave an empty widget.
- **missing widget capability:** IChatAcceptInputOptions in src/vs/workbench/contrib/chat/browser/chat.ts has queueing, cancellation, input-preservation, and onRequestAccepted options, but no option representing submit-to-current-session followed by clearing the widget.
- **closed implementation attempt:** https://github.com/microsoft/vscode/pull/286767 proposed the requested widget option and tests but was closed without merging. Review discussion objected that it changed the meaning of the existing “Send to New Chat” action rather than preserving both behaviors.
