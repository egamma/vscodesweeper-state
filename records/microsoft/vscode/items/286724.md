# Issue #286724 — Chat: support an action to send a chat request and clear widget

[https://github.com/microsoft/vscode/issues/286724](https://github.com/microsoft/vscode/issues/286724)

## Summary

The requested send-in-background workflow remains absent on current main. A closed, unmerged prototype demonstrated a bounded implementation, but maintainer feedback left an observable product decision open: preserve the existing “Send to New Chat” behavior and expose this as a distinct, clearly named action.

## Change summary

Add an action that submits a chat request to the current session and immediately presents an empty new chat for another request.

## Best solution

Keep “Send to New Chat” submitting into the new session, and add a separate, clearly labeled background-send action that submits to the original session before presenting a fresh chat input.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`, `src/vs/workbench/contrib/chat/browser/chat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`
- **Validation:** Add chat action tests proving that the new action sends to the original session and immediately exposes an empty new session, while the existing `workbench.action.chat.sendToNewChat` continues sending into the newly created session.
- **Behavior:**

  > A user can submit the current prompt in the background and immediately receive an empty chat input for another request, without waiting for or navigating through the first response. The submitted request remains attached to the session visible before the action. Existing “Send to New Chat” behavior remains available and continues to send the prompt into the new session. The two actions must be distinguishable and keyboard-operable with clear accessible labels.
- **Trace:**

  > `SendToNewChatAction` in `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts` currently captures the prompt, clears through `clearChatSessionPreservingType`, then calls `acceptInput`, so submission targets the new `viewModel`. `IChatAcceptInputOptions` in `src/vs/workbench/contrib/chat/browser/chat.ts` has no send-and-switch capability, while `ChatWidget._acceptInput` in `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts` sends through the widget's current session resource. The closed prototype https://github.com/microsoft/vscode/pull/286767 established that the path is bounded and testable, but it changed the semantics of the existing action. Preserve the distinction between sending into a new chat and sending to the original chat before opening another; do not fold in the separate handoff/context-transfer scope from https://github.com/microsoft/vscode/issues/287170.
- **Open decisions:**
  - Should the new behavior be exposed as a separate alternate submit action such as “Work in Background,” or as an option on the new-chat surface, while retaining the existing “Send to New Chat” action?

## Evidence

- **current source:** On current main, `SendToNewChatAction` in `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts` saves the input, clears the current session through `clearChatSessionPreservingType`, and only then calls `widget.acceptInput`; the request therefore runs in the new session rather than the original session.
- **missing widget capability:** `IChatAcceptInputOptions` in `src/vs/workbench/contrib/chat/browser/chat.ts` has queue, cancellation, focus, and input-preservation options, but no option for submitting to the original session while switching the widget to a new session.
- **closed implementation attempt:** https://github.com/microsoft/vscode/pull/286767 proposed the required session-preserving submission path and unit coverage, but it was closed without merging; its commit `ebe3cd34b1b7e9507f7a17ec92d00c4ffb314d3b` is not present on current main.
- **open product decision:** Maintainer feedback at https://github.com/microsoft/vscode/issues/286724#issuecomment-3756290376 agreed with the general approach but noted that replacing “Send to New Chat” would remove a distinct existing behavior and make the action name inaccurate. A subsequent suggestion at https://github.com/microsoft/vscode/issues/286724#issuecomment-3842481171 proposed an explicit “work in background” affordance.
- **related issue:** https://github.com/microsoft/vscode/issues/287170 is newer and concerns handoff buttons, context transfer, and fresh-session semantics rather than the same submit-button workflow, so it does not satisfy the stronger duplicate bar for this re-reviewed item.
