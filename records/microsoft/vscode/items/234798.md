# Issue #234798 — vscode keyboard shortcuts interfering with OS level shortcuts

[https://github.com/microsoft/vscode/issues/234798](https://github.com/microsoft/vscode/issues/234798)

## Summary

Keep open to investigate the state-dependent failure of macOS Fill shortcuts, including when no VS Code keybinding matches. The discussion contains independent confirmations and a workaround; neither a fixing commit nor an eligible canonical issue was found.

## Change summary

macOS Globe/Fn+Control+F inconsistently fails to fill the window depending on editor state, even after removing the conflicting cursorRight binding.

## Best solution

Establish why the native Fill shortcut fails after the VS Code binding is removed, then correct the responsible keyboard-event or native-menu path without changing ordinary Control+F cursor navigation. Treat the related tiling reports as diagnostic context rather than assuming all failures are ordinary shortcut conflicts.
