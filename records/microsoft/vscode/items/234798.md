# Issue #234798 — vscode keyboard shortcuts interfering with OS level shortcuts

[https://github.com/microsoft/vscode/issues/234798](https://github.com/microsoft/vscode/issues/234798)

## Summary

Still relevant: macOS Sequoia's fn+ctrl window tiling shortcuts are intercepted by VS Code because Electron does not distinguish the fn/globe modifier from a plain ctrl keystroke. The keybinding troubleshooting logs confirm VS Code resolves ctrl+[KeyF] without seeing the fn modifier. Related issue #228850 was closed without a full fix.

## Change summary

macOS Sequoia fn+ctrl+f (fill screen) window tiling shortcut is blocked by VS Code's ctrl+f keybinding dispatch.

## Best solution

Investigate whether Electron now exposes the fn/globe modifier on macOS Sequoia and, if so, exclude fn-modified keystrokes from VS Code's keybinding dispatch so they pass through to the OS window manager. If Electron does not expose the modifier, file or track the upstream Electron issue and mark this as upstream-blocked.

## Evidence

- **keybinding logs:** Reporter's troubleshooting logs show VS Code resolving ctrl+[KeyF] when fn+ctrl+f is pressed — the fn modifier is invisible to the keybinding service.
- **related closed issue:** https://github.com/microsoft/vscode/issues/228850 reported the same class of problem for macOS Sequoia tiling shortcuts; closed without a code fix, with comments confirming the problem persists for certain combinations.
- **ctrl+f binding:** src/vs/editor/contrib/find/browser/findController.ts:572 registers CtrlCmd|KeyF as the primary find keybinding, which matches the ctrl+f that Electron delivers when fn+ctrl+f is pressed.
- **upstream nature:** Electron/Chromium does not surface the macOS globe/fn key as a distinct modifier in keyboard events, making it impossible for VS Code to differentiate fn+ctrl+f from ctrl+f at the keybinding layer.
