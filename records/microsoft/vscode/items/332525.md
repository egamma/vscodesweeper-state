# Issue #332525 — Rename input does not provide horizontal scroll for long file names in Explorer

[https://github.com/microsoft/vscode/issues/332525](https://github.com/microsoft/vscode/issues/332525)

## Summary

Reasonable report with a traceable root cause: the Explorer tree's row-widening mechanism used for horizontal scroll on long names is only wired to the normal label render path, not to the rename input box, so very long names get clipped during rename with no way to scroll.

## Change summary

The inline rename input in the Explorer doesn't expand or horizontally scroll to show the full filename when it's very long.

## Best solution

Wire the rename input box into the same width/horizontal-scroll mechanism used for normal rows (FilesRenderer.updateWidth / ExplorerView.setEditable in explorerView.ts and explorerViewer.ts), or explicitly size/scroll the input while editing so the full name stays reachable.

## Evidence

- **renderTemplate:** explorerViewer.ts lines 877-891: templateData.label.onDidRender schedules this.updateWidth(templateData.currentContext), which calls this.tree.updateWidth(stat) to widen/scroll the row for the visible label — but this only fires for the normal (non-editing) label render.
- **renderInputBox:** explorerViewer.ts lines 1032-1077 (renderInputBox, invoked from renderElement's editableData branch, line 922) creates the rename `InputBox` but never calls updateWidth, so the input's containing row keeps its normal column width.
- **input CSS:** src/vs/base/browser/ui/inputbox/inputBox.css line 43 sets text-overflow: ellipsis on the `.ibwrapper > input`, consistent with a fixed-width box that isn't expected to grow.
