# Issue #345777 — [GB Cert][VS Code]: When I open the history in the Integrated Browser, it opens a new page instead.

[https://github.com/microsoft/vscode/issues/345777](https://github.com/microsoft/vscode/issues/345777)

## Summary

The attached page keeps the entered string only in its live DOM. Browser History intentionally reloads the recorded URL, rather than restoring a snapshot of that DOM, so the reported result is expected.

## Change summary

Selecting a browser history entry should restore the string previously entered and displayed by the test page.

## Best solution

Keep URL-based browser history behavior. The test page must persist and restore its own application state if the entered string should survive reopening its URL.

- **Proposed comment:**

  > Thanks for the report and attached test page. Browser History records the page's URL and title; selecting an entry loads that URL again, rather than restoring its previous DOM state. Your page puts the string in the title and displayed text but does not save or restore it, so seeing the string in the history entry does not mean it will reappear after navigation. This is expected browser-history behavior and is unrelated to the characters used. To retain the string when reopening the page, the page needs to persist and restore it.

## Evidence

- **Attached reproduction:** Read https://github.com/user-attachments/files/34313788/GB23-1.html in full. Its Show string handler assigns input.value to two elements' textContent and document.title; it does not persist the string, encode it in the URL, or restore it on load. The initial output is explicitly 'Waiting for input'.
- **History selection contract:** src/vs/workbench/contrib/browserView/electron-browser/features/browserHistoryFeature.ts: showHistoryPicker handles selection by calling model.loadURL(selected.entryUrl). It reopens a URL rather than restoring the original document.
- **History stores metadata, not page snapshots:** src/vs/platform/browserView/common/browserHistory.ts: ISerializedBrowserHistoryEntry stores id, URL, time, title, icon and an explicit-navigation flag. src/vs/platform/browserView/electron-main/browserView.ts:357–360 updates the stored title when document.title changes, explaining why the string appears in the history label without its DOM state being saved.
- **Navigation behavior:** src/vs/platform/browserView/electron-main/browserView.ts:766–774 forwards loadURL to Electron webContents.loadURL. Back/Forward separately use webContents.navigationHistory at lines 800–811. Selecting an entry from the History picker is therefore a fresh URL navigation, not traversal to a retained document.
