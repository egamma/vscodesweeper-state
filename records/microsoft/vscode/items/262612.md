# Issue #262612 — Copilot model picker hover text is ambiguous, inconsistent between models

[https://github.com/microsoft/vscode/issues/262612](https://github.com/microsoft/vscode/issues/262612)

## Summary

Keep open: the redesigned model hover removes the empty-parentheses presentation and gives token-priced models explicit units, but multiplier-priced models still show only labels such as “Cost: 1x,” leaving the reporter’s central billing-baseline question unanswered. Maintainers explicitly accepted this polish and tied it to the improved model-dropdown hover.

## Change summary

Make model-picker hover information consistent and explain what premium-request multipliers mean, including their relationship to Agent and Ask interactions.

## Best solution

Give multiplier-priced models a consistent, accessible explanation of the multiplier’s unit and scope, while retaining the structured token-cost presentation for usage-based billing. The billing wording should accurately distinguish a model invocation from a user-visible Agent or Ask turn.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerHover.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerDetails.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/modelPicker/modelPickerHover.test.ts`, `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`
- **Validation:** Extend the ModelPickerHover unit suite with multiplier-priced and token-priced models, asserting that each rendered hover identifies its billing unit, emits no empty placeholder text, and preserves the existing “Credits per 1M tokens” presentation.
- **Behavior:**

  > Every model-picker hover should describe cost using a consistent, understandable unit. A multiplier such as 1x must identify what it multiplies, and the UI must not imply that one Agent or Ask turn always equals one model invocation when that is not guaranteed. Models without optional metadata must not show empty parentheses or other empty placeholders. Token-priced models must retain their explicit per-million-token units, and the same meaningful information must remain available to keyboard and screen-reader users.
- **Trace:**

  > Copilot model metadata is assembled in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts, where `endpoint.multiplier` becomes both a numeric multiplier and a compact `${endpoint.multiplier}x` pricing string. The picker passes that metadata through createModelItem in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemPrimitives.ts to getModelHoverContent in modelPickerHover.ts. That hover renders multiplier pricing through appendCostSection as only `Cost: {pricing}` and suppresses the general tooltip once cost information is present; token-priced models instead use the structured metrics and explicit unit from modelPickerDetails.ts. Current conditional rendering no longer synthesizes the reported empty-parentheses suffix. Preserve token-pricing behavior and model selection semantics; the uncertainty starts at the product wording and scope of the premium-request explanation, not at the bounded rendering path.
- **Open decisions:**
  - Should the hover define a multiplier strictly per model invocation, and how should it explain that one user-visible Agent or Ask turn may involve a variable number of invocations?
  - Should the complete premium-request explanation appear inline for every multiplier-priced model, or should the hover provide a concise definition with a shared details destination?

## Evidence

- **remaining source gap:** extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts formats non-usage-based pricing as `${endpoint.multiplier}x`; src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerHover.ts then renders only `Cost: {pricing}` through appendCostSection. For a 1x model, the observable result remains “Cost: 1x” with no definition of the baseline.
- **description suppression:** In getModelHoverContent, rendering multiplier pricing sets `costInfoRendered`; the model tooltip is subsequently rendered only when `!costInfoRendered`. The hover therefore cannot currently use the supplied capability description to supplement the unexplained multiplier.
- **partial current improvement:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerDetails.ts now labels token-based values as “Credits per 1M tokens,” and the current hover conditionally emits populated badges and sections rather than constructing the reported empty-parentheses suffix. This addresses part, but not all, of the report.
- **maintainer direction:** A maintainer accepted the feedback as polish at https://github.com/microsoft/vscode/issues/262612#issuecomment-3209742611, and the later direction at https://github.com/microsoft/vscode/issues/262612#issuecomment-3480101079 says to tackle it with the improved model-dropdown hover.
