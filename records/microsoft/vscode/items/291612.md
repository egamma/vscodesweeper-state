# Issue #291612 — Copilot: tokenization issue

[https://github.com/microsoft/vscode/issues/291612](https://github.com/microsoft/vscode/issues/291612)

## Summary

This remains a recurring remote-extension failure: Copilot tries to start a tokenizer worker that its installed extension path cannot load. Later reports reproduce the same symptom on newer releases, while current main still requires and separately bundles this worker, so there is no substantiated fix to close against.

## Change summary

Copilot conversation requests fail in a Remote-SSH environment because `dist/tikTokenizerWorker.js` cannot be loaded from the remote Copilot Chat installation.

## Best solution

Determine why remote Copilot Chat installations or extension-update transitions intermittently leave the running extension host unable to access `tikTokenizerWorker.js`, then cover that lifecycle with packaging and remote-update validation. This older report is a reasonable canonical for the younger exact-symptom reports.

## Plan brief

- **Likely files:** `extensions/copilot/.esbuild.mts`, `extensions/copilot/src/platform/tokenizer/node/tokenizer.ts`, `extensions/copilot/src/platform/tokenizer/node/tikTokenizerWorker.ts`
- **Validation:** Package Copilot Chat, install or update it in a Remote-SSH extension host, allow the prior installation to transition or reload, and verify a chat request can repeatedly initialize tokenization without a module-resolution error and that the active remote extension's `dist/tikTokenizerWorker.js` remains accessible.
- **Behavior:**

  > Copilot chat requests in Remote-SSH and other remote extension hosts must initialize tokenization without reporting that `dist/tikTokenizerWorker.js` is missing. Updating, reloading, or switching the active Copilot Chat installation must not leave the running extension host referring to an incomplete or obsolete installation directory. Acceptance should cover repeated chat requests after a remote extension update or reload, not only a clean initial installation.
- **Trace:**

  > Tokenizer initialization in extensions/copilot/src/platform/tokenizer/node/tokenizer.ts resolves `tikTokenizerWorker.js` beside the bundled extension entry and starts it through `WorkerWithRpcProxy`. extensions/copilot/.esbuild.mts declares that worker as a separate node extension-host build entry, so the source expects packaging to place the artifact in `dist`. The issue log shows the failure under Remote-SSH, and the same path failure recurs in https://github.com/microsoft/vscode/issues/303477 and https://github.com/microsoft/vscode/issues/306731 across later versions. Earlier investigation in https://github.com/microsoft/vscode/issues/271599 found installations where the remote worker availability was the unresolved question. The uncertainty starts at whether the artifact is absent on disk, removed during an extension update, or present under a newer installation while the running host retains the older path; preserve normal tokenizer behavior and keep the unrelated Epic Games custom-instructions error out of scope.

## Evidence

- **current source path:** extensions/copilot/src/platform/tokenizer/node/tokenizer.ts still constructs a worker from `join(__dirname, 'tikTokenizerWorker.js')`, while extensions/copilot/.esbuild.mts declares `src/platform/tokenizer/node/tikTokenizerWorker.ts` as a separate `tikTokenizerWorker` build entry.
- **recurring reports:** The same missing-worker symptom was independently reported on newer Copilot Chat versions in https://github.com/microsoft/vscode/issues/303477 and https://github.com/microsoft/vscode/issues/306731; both are open and younger than this issue.
- **prior investigation:** In https://github.com/microsoft/vscode/issues/271599, a maintainer established that an installation without this worker is incomplete and suspected the remote extension-installation path; that issue later auto-closed for missing diagnostic information rather than because of a fix.
- **transient recovery evidence:** Reports at https://github.com/microsoft/vscode/issues/282196 and https://github.com/microsoft/vscode/issues/285252 say restarting or reloading cleared the error, which points toward an installation/update lifecycle problem but does not eliminate the recurring defect.
