# Issue #206769 — Advanced diff algorithm hangs when dealing with large diff

Keep this accepted diff-editor bug open: the reporter supplied a concrete large-change fixture, and later users confirmed prolonged computation that blocks subsequent comparisons. No verified fix or eligible older canonical covers the full reported symptom.

## Change summary

Large CSV, YAML, and lockfile changes can leave advanced diff computation running for a prolonged period with no usable comparison.

## Best solution

Profile the supplied CSV comparison on current main and address the expensive advanced-diff path, including work that continues after its editor closes. Preserve accurate diff results and the documented unlimited-time option; switching to legacy is a workaround, not resolution.

- **Trace:**

  > The supplied attachment replaces a 2,772-line CSV, and the discussion independently confirms similar behavior for lockfiles. EditorWorker.$computeDiff resolves advanced to the default synchronous lines diff computer; DefaultLinesDiffComputer performs line alignment followed by character refinement, using Myers for large sequences. WorkerBasedDocumentDiffProvider checks its cancellation token only after the worker request returns, so editor disposal does not interrupt the computation through that token. Preserve the unlimited-time setting and do not expand this into automatic fallback design; that separate request is https://github.com/microsoft/vscode/issues/216953.
