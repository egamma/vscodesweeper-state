# Issue #11828 — [json] validation doesn't work offline

[https://github.com/microsoft/vscode/issues/11828](https://github.com/microsoft/vscode/issues/11828)

## Summary

The offline JSON-validation gap remains worth tracking: the report asks VS Code to retain remotely downloaded schemas for offline reuse, and the discussion confirms that cached schemas should remain a fallback rather than replace online refreshes. The related cache requests are newer and closed, so they cannot serve as duplicate canonicals for this re-reviewed issue.

## Change summary

Cache downloaded JSON schemas so validation continues offline while refreshing schemas normally when connectivity is available.

## Best solution

Add a persistent, freshness-aware cache to the JSON language service's schema request path, using cached content only when a network fetch is unavailable and preserving normal online refresh behavior.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add an integration test that resolves a remote schema online, makes the schema endpoint unavailable, restarts the relevant JSON service state, and verifies that validation still uses the cached schema while a later successful online fetch refreshes it.
- **Behavior:**

  > After VS Code has successfully downloaded a remote JSON schema, reopening a matching JSON document without network access should retain schema-based validation and should not surface a schema-download error when usable cached content exists. While online, VS Code should continue fetching current schema content rather than permanently preferring the cache. Acceptance should cover initial online resolution, offline reuse across a restart-equivalent lifecycle, and subsequent online refresh.
- **Trace:**

  > The request belongs in the JSON language feature's schema request path, likely around the client/server request plumbing in extensions/json-language-features/client/src/jsonClient.ts and extensions/json-language-features/server/src/jsonServer.ts. The report and comments establish fallback behavior but do not settle persistence lifetime, freshness, or whether stale cached schemas may be used after an HTTP failure. Preserve ordinary online schema resolution and validation behavior; do not turn the cache into the preferred online source. The newer related requests https://github.com/microsoft/vscode/issues/31121 and https://github.com/microsoft/vscode/issues/162000 are closed and cannot absorb this re-reviewed issue.
- **Open decisions:**
  - Should cached remote schemas persist across VS Code restarts, and if so, what user-visible freshness or expiry policy should govern them?
  - When an online refresh fails, should VS Code silently use stale cached content, use it with a warning, or stop validation?
  - Should cache behavior apply to every remote schema URL or only schemas discovered through known schema associations?
