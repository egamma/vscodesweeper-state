# Issue #331259 — External session continued in both apps appears strange in both apps

[https://github.com/microsoft/vscode/issues/331259](https://github.com/microsoft/vscode/issues/331259)

## Summary

Keep open: a team member reproduced stale cross-application Copilot session history during the external-session test plan, and current source still lacks passive Copilot transcript reconciliation. A later change appears to filter system messages during restoration, but it does not reference this issue and does not resolve the remaining synchronization gap.

## Change summary

Continuing one external Copilot session concurrently in VS Code and the GitHub Copilot app leaves each open client stale until reload and can expose system-prompt-like transcript content.

## Best solution

Define the supported concurrent-client contract for Copilot SDK conversations, then make an already-open VS Code chat reconcile externally persisted turns without a window reload while continuing to exclude system events from visible history.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/agent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/test/node/copilotAgent.test.ts`, `src/vs/platform/agentHost/test/node/copilotAgentSession.test.ts`
- **Validation:** Add focused Agent Host tests that keep a Copilot chat subscribed, append an external persisted turn, and assert the existing chat state updates without reload while system.message events remain absent from visible turns.
- **Behavior:**

  > When the same supported Copilot conversation is open in VS Code and another Copilot application, completed persisted turns from either client should become visible in the other without reopening the application or reloading the VS Code window. Reconciliation must not expose system messages or prompt scaffolding as user-visible transcript content. Existing local streaming and input state must remain stable while passive history updates arrive.
- **Trace:**

  > The report was reproduced by a team member during https://github.com/microsoft/vscode/issues/331122. AgentService already has provider-neutral passive-history handling through IAgent.watchChatHistory and onDidChangeChatHistory in src/vs/platform/agentHost/common/agent.ts, but the Copilot provider does not implement those hooks; Codex is the existing reference implementation. CopilotAgentSession.getMessages reconstructs persisted events into a memoized _mappedEventsMemo, whose invalidation is driven by events from its own live wrapper rather than writes made by another process. Current restoration filters system.message events after commit fa3fc6cc43916f60c411e507f3f863ad6e8f20a9, so preserve that boundary. Do not turn passive reconciliation into host-side turn execution or disturb local in-progress turns.
- **Open decisions:**
  - Is simultaneous continuation of one Copilot SDK conversation by multiple applications a supported product contract, or should a second client present the session as read-only or warn before taking ownership?
  - If concurrent continuation is supported, should externally persisted history update automatically at completed-turn boundaries, or only through an explicit refresh action?
