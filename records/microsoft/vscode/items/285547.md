# Issue #285547 — Better visibility of long filenames

[https://github.com/microsoft/vscode/issues/285547](https://github.com/microsoft/vscode/issues/285547)

## Summary

A real Explorer usability request remains, but part of it is already configurable and the metadata portion belongs to an older open backlog issue. Route this to the file-explorer area and keep it open for the narrower question of performant filename disambiguation.

## Change summary

Improve identification of similarly prefixed long filenames through middle truncation, faster hovers, and optional file metadata.

## Best solution

Use the existing `workbench.hover.delay` setting for hover timing and consolidate file size, modification date, and permissions work in https://github.com/microsoft/vscode/issues/164033. Keep this issue focused on an RTL-safe, performance-neutral way to preserve distinguishing filename suffixes in narrow Explorer layouts.

## Evidence

- **existing hover setting:** `workbench.hover.delay` is registered in src/vs/workbench/browser/workbench.contribution.ts and consumed by src/vs/platform/hover/browser/hoverService.ts; it accepts values down to 0 milliseconds, covering the requested hover-timing option.
- **current rendering:** src/vs/base/browser/ui/iconLabel/iconlabel.css applies end ellipsis to resource labels, while src/vs/workbench/contrib/files/browser/views/explorerViewer.ts renders Explorer entries through ResourceLabel without a middle-truncation mode.
- **metadata canonical:** https://github.com/microsoft/vscode/issues/164033 is an older open `file-explorer` feature request covering file size and modified date, including maintainer discussion of configurable fields and hover presentation. It owns only that subset, so it cannot absorb this broader re-reviewed issue as a duplicate.
- **maintainer assessment:** https://github.com/microsoft/vscode/issues/285547#issuecomment-3724970810 explains that JavaScript middle truncation would have a large performance impact; https://github.com/microsoft/vscode/issues/285547#issuecomment-3725217654 adds that split-span approaches lose semantic information and break down for RTL languages.
- **precedent:** https://github.com/microsoft/vscode/issues/111411 and https://github.com/microsoft/vscode/issues/233509 declined filename wrapping because Explorer rows are virtualized and variable-height rendering carries performance costs. Neither is an open canonical for the requested middle truncation.
- **existing fallback:** The current Explorer hover supplies the full resource path through src/vs/workbench/browser/labels.ts, and `workbench.list.horizontalScrolling` provides another existing way to reach overflowed text, but neither preserves distinguishing suffixes at a glance.
