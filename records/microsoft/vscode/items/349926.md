# Issue #349926 — Manage remote environments: allow deleting a remote ssh connection

[https://github.com/microsoft/vscode/issues/349926](https://github.com/microsoft/vscode/issues/349926)

## Summary

Keep open: current management can forget saved SSH connections only after their hosts disappear from SSH configuration, leaving a meaningful gap for configured hosts. This team-authored request needs a decision about removal semantics, not an as-designed close.

## Change summary

Allow users to remove unwanted SSH connections from Manage Remote Environments.

## Best solution

Provide an explicit removal workflow for SSH environments, including configuration-backed hosts, with clear semantics about rediscovery and whether SSH configuration changes. Preserve the existing safe forgetting behavior for orphaned saved connections.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/sessions/providers/remoteAgentHost/browser/remotesModel.ts`, `src/vs/workbench/contrib/sessions/providers/remoteAgentHost/browser/remotesTable.ts`, `src/vs/workbench/contrib/sessions/providers/remoteAgentHost/test/browser/remotesModel.test.ts`, `src/vs/workbench/contrib/sessions/providers/remoteAgentHost/test/browser/remotesWidget.test.ts`
- **Validation:** Extend the remotes model and widget tests for a configuration-backed SSH host, checking action availability, confirmation, cancellation, and the agreed result after refresh and reopening management; retain orphaned saved-host deletion coverage.
- **Behavior:**

  > Users should have an understandable way to remove an unwanted SSH connection from Manage Remote Environments. Currently, SSH hosts still present in configuration cannot be forgotten from this surface. Acceptance must cover configuration-backed and saved-only hosts, cancellation, and whether removed entries return after refresh or reopening. Removal must not delete files on the remote computer.
- **Trace:**

  > RemotesModel computes SSH canDelete from saved registration and absence from successfully read SSH configuration; RemotesTable uses that capability to omit Forget SSH Connection. RemotesModel.checkSSHHostDeletion independently enforces the same restriction, while deleteSSHHost removes saved registration and disconnects without changing SSH configuration. Existing remotesModel tests explicitly preserve this restriction. Picker hiding is separate and retains management rows, so it is not equivalent to removal. The remaining uncertainty is the desired contract for configuration-backed hosts, not where to place a guard. Keep remote filesystem contents and unrelated connection types outside the change. The disconnect/session-loss report at https://github.com/microsoft/vscode/issues/348758 is separate work.
- **Open decisions:**
  - For an SSH host still present in configuration, should removal leave that configuration untouched and suppress rediscovery in management, or explicitly offer to remove its SSH configuration entry?
