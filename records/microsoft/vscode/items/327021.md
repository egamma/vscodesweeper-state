# Issue #327021 — Copilot Chat re-walks the entire CLI session store on every refresh — extension host stalls for minutes with a large store

[https://github.com/microsoft/vscode/issues/327021](https://github.com/microsoft/vscode/issues/327021)

## Summary

The performance defect remains on current main: the default legacy provider re-enumerates and maps the complete CLI session catalogue whenever session state changes. Two independent reports provide measured extension-host stalls, and no older symptom-equivalent canonical issue or fixing commit was found.

## Change summary

Avoid repeatedly walking and materializing the entire Copilot CLI session store when an individual session changes.

## Best solution

Keep session-list refresh cost bounded independently of total historical store size, while preserving prompt status updates and discovery of sessions created by other processes. The work belongs in the Copilot CLI session provider/service, with a regression test proving that repeated single-session state changes do not repeatedly invoke the SDK's full `listSessions()` enumeration.

- **Trace:**

  > The default registration in extensions/copilot/src/extension/chatSessions/vscode-node/chatSessions.ts uses CopilotCLIChatSessionItemProvider because both controller feature settings default to false. Its `provideChatSessionItems` method in copilotCLIChatSessionsContribution.ts calls `CopilotCLISessionService.getAllSessions`, which invokes SDK `sessionManager.listSessions()` after every previous call completes and then processes the entire metadata array in copilotcliSessionService.ts. Status changes fire `onDidChangeSessions`, and the item provider turns that into a bulk change event, closing the loop that repeatedly triggers full enumeration.
