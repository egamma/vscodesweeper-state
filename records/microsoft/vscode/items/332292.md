# Issue #332292 — Agents Window - Support sessions for muilt-root workspaces

[https://github.com/microsoft/vscode/issues/332292](https://github.com/microsoft/vscode/issues/332292)

## Summary

Keep open: current main has substantial multi-root session infrastructure, but the new-session recent-workspace path still flattens `.code-workspace` entries into separate folders. This is a team-authored Backlog request, and no commit referencing #332292 establishes that its intended scope is complete.

## Change summary

Support creating, restoring, and opening Agents Window sessions for multi-root VS Code workspaces.

## Best solution

Define the remaining multi-root contract, then represent a `.code-workspace` as one selectable session workspace whose ordered folders survive creation, restoration, session switching, and opening in an editor window.

## Plan brief

- **Likely files:** `src/vs/sessions/services/sessions/browser/sessionsRecentWorkspacesService.ts`, `src/vs/sessions/services/sessions/test/browser/sessionsRecentWorkspacesService.test.ts`, `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/sessions/contrib/workspace/browser/workspaceFolderManagement.ts`
- **Validation:** Add a SessionsRecentWorkspacesService test proving a recent multi-root `.code-workspace` is exposed according to the chosen composite-workspace semantics, then verify workspaceFolderManagement mounts the same ordered folder set when that session becomes active.
- **Behavior:**

  > Users can select a multi-root VS Code workspace when creating an Agents Window session. The resulting session retains the complete ordered folder set across creation, restoration, session switching, and Open in VS Code. Single-folder and No Workspace flows remain unchanged. Acceptance includes a recent `.code-workspace` containing two folders being represented and restored according to the chosen workspace identity semantics.
- **Trace:**

  > The provider-neutral model already supports multiple folders through `ISessionWorkspace.folders` in src/vs/sessions/services/sessions/common/session.ts. WorkspaceFolderManagement mounts every folder and Open in VS Code passes every active-chat folder to the editor window. The remaining visible gap is the recent-workspace ingestion path: `SessionsRecentWorkspacesService._refreshVSCodeRecentWorkspaces` reads workspace files but flattens their folders into independent picker entries, as codified by its current multi-root history test. Keep existing single-folder, trust, worktree, and chat-subset behavior unchanged. The uncertainty begins at whether a `.code-workspace` should appear as one composite selection with its own identity or whether multi-folder composition should be managed through another picker interaction.
- **Open decisions:**
  - Should a recent `.code-workspace` appear as one composite selectable workspace, preserving the workspace-file identity and ordered folder set, or should users compose a multi-root session by selecting individual folders in the Agents Window?
