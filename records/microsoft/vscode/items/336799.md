# Issue #336799 — Allow marking chats as done in addition to sessions

[https://github.com/microsoft/vscode/issues/336799](https://github.com/microsoft/vscode/issues/336799)

## Summary

Fresh, coherent feature request with no maintainer discussion yet; confirmed in the code that archive/'Mark as Done' actions only operate on top-level sessions, not nested chats, so the gap is real but the design for how it should work is undecided.

## Change summary

Let nested chats within a session be marked as done / archived independently, the same way top-level sessions can be.

## Best solution

Extend the session archive/done model in sessionsManagementService.ts and the sessionsViewActions.ts context-menu/toolbar actions to cover nested chat rows, deciding first whether a chat's done state is independent of its parent session's.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts`, `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`
- **Validation:** A sessionsManagementService test asserting a nested chat can be archived/restored independently of its parent session's archive state.
- **Behavior:**

  > A nested chat row (within a session, as distinct from a quick chat) can be marked Done/archived and later restored, the same way a top-level session can today. Archiving a chat removes it from the active list without requiring the whole session to be archived. Acceptance: the new action appears in the nested chat's context menu/toolbar and a management-service test confirms independent archive/restore.
- **Trace:**

  > BaseArchiveSectionAction and the per-session archive actions in sessionsViewActions.ts operate on `ISession`/`ISessionSection` via `sessionsManagementService.archiveSession(session)`; nested chat rows rendered in sessionsList.ts (see 'nested chat' rows and their compact rendering path) do not currently expose this action, and the quick-chats section is explicitly excluded from the bulk archive menu ('Not on Done itself, and not on the "Chats" (quick chats) section'). The boundary: do not change the existing session-level archive/unarchive persistence or its confirmation dialogs; only extend the model to cover a chat-level unit. Where uncertainty starts: whether 'done' state for a chat is stored per-chat in the session's persisted layout or is purely derived, and whether archiving all chats in a session should auto-archive the session.
- **Open decisions:**
  - Is a chat's done/archived state persisted independently of its session, or derived from all-chats-done?
  - Does marking the last active chat as done have any effect on the parent session's own Done/archive state?
  - Should this apply to quick chats (the currently-excluded 'Chats' section) too, or only nested chats within a full session?

## Evidence

- **archive action scoped to sessions:** src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts calls `sessionsManagementService.archiveSession(session)` for sections/groups, and the section-archive menu explicitly excludes the quick-chats section ('Not on Done itself, and not on the "Chats" (quick chats) section').
- **nested chat rows lack this action:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts renders nested chat rows (search hits for 'nested chat' throughout the tree/list and its tests) but exposes only rename/open-to-side/delete for them (per sessionsChatAccessibilityHelp.ts), not archive/mark-done.
