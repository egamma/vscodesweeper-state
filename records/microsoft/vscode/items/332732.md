# Issue #332732 — Markdown Editor (rich webview editor) ignores font size: uses var(--markdown-font-size) but never receives it

[https://github.com/microsoft/vscode/issues/332732](https://github.com/microsoft/vscode/issues/332732)

## Summary

Traced and confirmed in source: the Markdown Editor's `#getHtml` in markdownEditorProvider.ts never reads `markdown.preview.fontSize` or injects a `--markdown-font-size` style, unlike the Markdown preview's documentRenderer.ts which does exactly that — the editor's CSS variable is genuinely dead. Real gap, no fix on main yet.

## Change summary

The new rich Markdown Editor webview ignores `markdown.preview.fontSize` (and font-family/line-height), always rendering at the hardcoded 14px fallback because no CSS custom property is ever injected into its HTML.

## Best solution

In extensions/markdown-language-features/src/preview/markdownEditorProvider.ts `#getHtml`, mirror documentRenderer.ts's pattern (lines ~211-213) by reading the relevant markdown config and injecting `--markdown-font-size`/`--markdown-line-height`/`--markdown-font-family` into a `<style>` block or the initial state passed to the webview; the maintainers still need to decide whether to reuse `markdown.preview.fontSize` or add a dedicated `markdown.editor.fontSize` setting.

## Evidence

- **editor HTML builder misses font injection:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts `#getHtml` (~line 953) only builds `initialState` with content/documentVersion/readonly/richLinksEnabled/linkPresentationRules and links `editor.css` via `<link rel="stylesheet">` — no font-size/line-height/font-family CSS variables or config values are read or emitted anywhere in that function.
- **preview does inject the same variable:** extensions/markdown-language-features/src/preview/documentRenderer.ts lines 211-213 explicitly build `--markdown-font-family`, `--markdown-font-size`, and `--markdown-line-height` from the markdown preview font config and inject them as inline CSS, confirming the pattern the editor is missing.
- **no fix on main:** `git log` on markdownEditorProvider.ts shows only an unrelated commit (4043ece7, chat UI twistie transitions); no font-size-related change exists.
- **second confirmation:** Comment from mindprint (2026-09-01) reproduces on 1.135.0 and adds that inline code/code-block sizing and per-language `editor.fontFamily` overrides are also unreachable, reinforcing the same root cause.
