# Issue #330036 — Error: (sendFailed) Error: Copilot SDK rejected permission mode 'on'

[https://github.com/microsoft/vscode/issues/330036](https://github.com/microsoft/vscode/issues/330036)

## Summary

Team-authored bug (roblourens, MEMBER) with a real version milestone (1.135.0) assigned, so per policy this must stay open regardless of other findings — but the trace also confirms a real gap: when the Copilot SDK's managed-settings fail-closed logic blocks bypass-permissions mode, `syncPermissionMode` throws instead of falling back, so the whole `send()` fails.

## Change summary

Sending a message with auto-approve/'Allow All' enabled throws 'Copilot SDK rejected permission mode on' when the SDK's managed-settings resolution fails closed and blocks bypass-permissions mode.

## Best solution

In `syncPermissionMode`/`_getSdkPermissionMode` (src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, around lines 3250–3330), handle a `setAllowAll({mode:'on'})` rejection by falling back to a non-bypass mode (e.g. 'auto'/'off') and surfacing a clear, actionable error/notification to the user instead of failing the whole send with an opaque SDK error — the log shows the SDK reports 'Enterprise managed settings could not be determined, so bypass-permissions mode is disabled (fail-closed)', which is a legitimate state the host should handle gracefully rather than let bubble up as `entry.send() failed`.
