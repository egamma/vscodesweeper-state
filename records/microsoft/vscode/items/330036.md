# Issue #330036 — Error: (sendFailed) Error: Copilot SDK rejected permission mode 'on'

[https://github.com/microsoft/vscode/issues/330036](https://github.com/microsoft/vscode/issues/330036)

## Summary

Fresh, team-authored bug report from active testing of #329613, with real logs showing the Copilot SDK rejecting permission mode 'on' due to a fail-closed managed-settings check; a second maintainer already has a plausible root-cause hypothesis (a wildcard `Shell(*)` permission rule). No fix has landed yet, so this stays open per the hard team-authored keep-open rule.

## Change summary

Sending a message with permission mode set to allow-all ('on') fails because the Copilot SDK's managed-settings enforcement fail-closes (bypass_permissions_blocked) when enterprise managed settings can't be determined, and this may be triggered incorrectly by wildcard Shell permission rules like `Shell(*)`.

## Best solution

Investigate why `_getSdkPermissionMode()`/`syncPermissionMode()` in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts (around line 3098, `rpc.permissions.setAllowAll`) hits the SDK's fail-closed managed-settings path when a `Shell(*)`-style wildcard rule is present in the permissions config, and either fix the rule parsing/config resolution or the managed-settings determination so bypass mode isn't blocked in non-enterprise/local testing scenarios; likely requires collaboration with the Copilot SDK owners since the rejection originates in `@github/copilot-sdk`.
