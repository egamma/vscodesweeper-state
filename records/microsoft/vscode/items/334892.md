# Issue #334892 — Agents window renderer OOM during plugin sync: resourceRead Base64 encoding reaches 4 GB heap

[https://github.com/microsoft/vscode/issues/334892](https://github.com/microsoft/vscode/issues/334892)

## Summary

Traced the reporter's stack into real code: resourceRead's reply path base64-encodes the entire file via naive per-character string concatenation, and AgentPluginManager.syncCustomizations copies an installed plugin's full directory (including large binaries) through that same client-filesystem round trip with no size guard — a genuine, well-diagnosed renderer OOM risk that deserves area-owner attention rather than being closed.

## Change summary

Opening the Agents window while a large-binary plugin (e.g. a 228 MB executable) syncs causes the renderer to OOM crash because the file is base64-encoded via unbounded string concatenation.

## Best solution

In src/vs/platform/agentHost/browser/agentHostProtocolClient.ts (the `resourceRead` reverse-request handler) and/or src/vs/base/common/buffer.ts's `encodeBase64`, bound or chunk large-file transfers instead of building one giant in-memory base64 string; separately, AgentPluginManager._syncPlugin (src/vs/platform/agentHost/node/agentPluginManager.ts) should consider excluding or size-capping large binaries (e.g. bundled executables under node_modules) before triggering a full-directory copy through the client filesystem provider. Also worth a maintainer decision on the disablement-setting mismatch (`chat.plugins.enabledPlugins` vs the URI-based enablement model) raised in the report.
