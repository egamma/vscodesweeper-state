# Issue #278066 — Adopt gh.com private marketplace policy

[https://github.com/microsoft/vscode/issues/278066](https://github.com/microsoft/vscode/issues/278066)

## Summary

Keep open: this is a protected plan item, and current main still requires an administratively configured marketplace URL rather than discovering private-marketplace policy from GitHub.com. The related Entra authentication issue is newer and narrower, so it cannot absorb this re-reviewed policy-discovery work.

## Change summary

Automatically consume GitHub.com's enterprise private-marketplace policy and resolve conflicts between multiple enterprises or an existing GPO configuration.

## Best solution

Feed GitHub.com's private-marketplace policy into the extension-gallery manifest selection path, with deterministic client-side handling for multiple enterprise URLs and an explicitly decided precedence between GitHub policy and GPO configuration.

## Plan brief

- **Likely files:** `src/vs/workbench/services/accounts/browser/defaultAccount.ts`, `src/vs/platform/defaultAccount/common/defaultAccount.ts`, `src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryManifestService.ts`, `src/vs/workbench/services/extensionManagement/test/electron-browser/extensionGalleryManifestService.test.ts`
- **Validation:** Add and run focused extension-gallery/default-account unit tests covering one discovered marketplace, multiple enterprise marketplaces, no discovered policy, and simultaneous GitHub.com and GPO configuration; each case must select the maintainer-approved URL without changing the existing default-gallery fallback.
- **Behavior:**

  > A signed-in enterprise user whose GitHub.com policy supplies a private-marketplace URL should connect to that marketplace without requiring the same URL through GPO. Selection must remain deterministic when several enterprises publish URLs or when GPO also configures one. With no applicable GitHub.com policy, existing configured-marketplace and default-gallery behavior must remain unchanged. Acceptance requires tests for each source and conflict combination.
- **Trace:**

  > Current gallery selection begins in `WorkbenchExtensionGalleryManifestService.doGetExtensionGalleryManifest` in `src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryManifestService.ts`; it reads `extensions.gallery.serviceUrl` and otherwise falls back to the product gallery. `GitHubGalleryAccountProvider` in `extensionGalleryAccountService.ts` receives default-account entitlement data but only determines eligibility, while the account abstraction in `src/vs/platform/defaultAccount/common/defaultAccount.ts` exposes no private-marketplace policy value. The uncertainty starts at source resolution: the issue leans toward selecting the first enterprise URL client-side, while https://github.com/microsoft/vscode/issues/278066#issuecomment-3598104242 separately proposes GitHub.com policy taking precedence over GPO. Preserve the existing gallery authentication paths and the default-gallery fallback; Entra authentication tracked by https://github.com/microsoft/vscode/issues/280376 is related but not the discovery contract being decided here.
- **Open decisions:**
  - When several GitHub enterprises return private-marketplace URLs, is the API's first configured enterprise authoritative, or must VS Code apply another deterministic user-visible selection rule?
  - When both GitHub.com policy and `extensions.gallery.serviceUrl` GPO are present, which source is authoritative?

## Evidence

- **protected tracking item:** https://github.com/microsoft/vscode/issues/278066 carries the `plan-item` label and the On Deck milestone; plan items are deliberately long-lived and must remain open.
- **current source gap:** On current main, `WorkbenchExtensionGalleryManifestService.doGetExtensionGalleryManifest` in `src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryManifestService.ts` reads only `extensions.gallery.serviceUrl`; when that setting is absent it uses the default gallery manifest. - **unresolved precedence:** https://github.com/microsoft/vscode/issues/278066#issuecomment-3598104242 raises the still-unanswered observable case where both GPO and GitHub.com configure a marketplace, proposing that GitHub.com take precedence.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/280376 was created after this issue and concerns Entra ID authentication for an already configured private marketplace, not discovery of GitHub enterprise marketplace URLs. It therefore fails the stronger duplicate bar for this re-reviewed item.
