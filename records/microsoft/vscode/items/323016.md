# Issue #323016 — Agent copilot terminal snapshots can be the only remaining execution record, and misreport edited commands

[https://github.com/microsoft/vscode/issues/323016](https://github.com/microsoft/vscode/issues/323016)

## Summary

Confirmed via source: the `forDisplay` field on `commandLine` is always populated at tool-creation time and takes priority over `userEdited` in every display path, so user edits to the approval control are stored but never shown in the chat transcript. The execution path correctly uses `userEdited`, so the terminal runs the right command but the chat record is wrong. No fix on main.

## Change summary

When a user edits a terminal command in the agent approval control before approving, the chat transcript shows the agent's original proposed command instead of the user-edited command that actually executed.

## Best solution

When `userEdited` is set in the confirmation sub-part (`chatTerminalToolConfirmationSubPart.ts` line 177), clear or update `forDisplay` so that the display chain (`forDisplay ?? userEdited ?? toolEdited ?? original`) reflects the user's edit. Alternatively, change the display chain in `chatTerminalToolProgressPart.ts`, `chatModel.ts`, `chatWindowNotifier.ts`, and `agentSessionApprovalModel.ts` to check `userEdited` before `forDisplay`. The second approach is cleaner because `forDisplay` is a cosmetic normalization of the original, while `userEdited` represents an explicit user action that should always win.
