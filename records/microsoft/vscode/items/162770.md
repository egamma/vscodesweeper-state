# Issue #162770 — errors thrown by openerService.resolveExternalUri not surfaced to MainThreadWindow.$asExternalUri in VS Code Web

[https://github.com/microsoft/vscode/issues/162770](https://github.com/microsoft/vscode/issues/162770)

## Summary

Bug is confirmed on current main — resolver errors in `$asExternalUri` are still swallowed for HTTP/HTTPS URIs and not surfaced to extensions. An open PR (#325925) is in progress to fix this; keeping open pending its review.

## Change summary

Errors thrown by `openerService.resolveExternalUri` are silently swallowed for HTTP/HTTPS URIs in `asExternalUri`, preventing extensions from receiving resolver failures.

## Best solution

Review and land the open PR https://github.com/microsoft/vscode/pull/325925 which propagates resolver errors back to extensions while preserving the fallback behavior for unhandled (as opposed to failed) resolutions.
