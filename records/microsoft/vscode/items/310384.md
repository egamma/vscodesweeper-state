# Issue #310384 — VS Code's C:\Users\username\AppData\Roaming\Code\WebStorage\2\CacheStorage folder grows indefinitely and has currently reached over 30GB.

[https://github.com/microsoft/vscode/issues/310384](https://github.com/microsoft/vscode/issues/310384)

## Summary

Verified duplicate: this report describes the same unbounded CacheStorage growth caused by the media-preview cache-busting with Date.now() and the service worker's lack of eviction, which is thoroughly diagnosed and tracked in the canonical issue #320928.

## Change summary

VS Code's CacheStorage folder grows indefinitely (30+ GB observed) because the webview service worker caches every resource response and never evicts, compounded by media-preview's Date.now() cache-busting.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/320928, which provides the root-cause analysis and identifies the two fixes needed: key cache-busting on file mtime instead of Date.now(), and add eviction/size-cap logic to the service worker.
