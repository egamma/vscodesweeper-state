  > In a workspace opened through Remote Repositories, the Copilot harness can discover the active virtual repository and edit its files. Local remains the default or fallback until the remote-capable path is explicitly supported, and ordinary local and remote-server workspaces retain their current behavior.
- **Trace:**

  > The issue demonstrates that Local works while Copilot cannot resolve or edit files in a Remote Repositories virtual workspace. A maintainer confirmed the capability gap and said Local is the default until an agent host can properly support remote repositories. https://github.com/microsoft/vscode/pull/329706 moved agent-host execution onto remote servers, but a virtual Remote Repositories workspace is a distinct file-system boundary and the provided evidence does not show that this PR completed it. Investigation should start at the agent-host workspace/file transport under src/vs/platform/agentHost and its Copilot integration under extensions/copilot; preserve existing behavior for local workspaces and actual remote extension hosts.
- **Open decisions:**
  - Should a Remote Repositories workspace use a remote-capable Copilot harness, or must the product continue selecting Local until virtual file-system operations are fully exposed to the agent host?
