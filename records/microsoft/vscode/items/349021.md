# Issue #349021 — Multi-cursor copy with mixed empty and non-empty selections copies entire unselected line (`editor.emptySelectionClipboard`)

[https://github.com/microsoft/vscode/issues/349021](https://github.com/microsoft/vscode/issues/349021)

## Summary

The reported output matches an explicit existing test, so this is a request to change mixed-selection clipboard semantics rather than a regression. Keep it open for an editor-owner decision: no inspected setting provides the requested preservation of empty selection slots.

## Change summary

Copy empty strings for empty selections when other cursors have selected text, preserving their positions without copying unselected line content.

## Best solution

Have the editor owner consider preserving empty entries when copying mixed selections while retaining whole-line copy when all selections are empty. Any accepted change should keep clipboard text and multicursor metadata consistent.

- **Existing expectation is explicit:** src/vs/editor/test/browser/viewModel/viewModelImpl.test.ts:267-276, test 'getPlainTextToCopy 1/2 - emptySelectionClipboard', expects ['ine2', 'line3\n'] for a non-empty selection paired with an empty selection. The reported behavior therefore matches the repository's tested contract.
- **Clipboard assembly:** src/vs/editor/browser/controller/editContext/clipboardUtils.ts, getDataToCopy, joins the returned entries with the model newline and preserves the array as multicursorText. Whole-line entries already ending in a newline consequently produce the additional blank lines described in the report.
- **Existing settings do not cover the request:** editor.emptySelectionClipboard is registered in src/vs/editor/common/config/editorOptions.ts:1730-1740. Disabling it avoids whole-line copying but ViewModel.getPlainTextToCopy:1047-1051 drops empty selections entirely, losing the requested blank slots. editor.multiCursorPaste controls paste distribution, not which source content is copied.
