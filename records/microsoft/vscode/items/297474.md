# Issue #297474 — Headless browsers

[https://github.com/microsoft/vscode/issues/297474](https://github.com/microsoft/vscode/issues/297474)

## Summary

Keep open: current browser tools preserve keyboard focus and sometimes open inactive tabs, but do not expose headless browser testing for parallel subagents. The related background-page request is newer, so it cannot serve as a duplicate canonical for this re-reviewed, team-authored issue.

## Change summary

Support browser testing by parallel agents without displaying browser pages or interrupting the user's work.

## Best solution

Provide session-owned browser automation that can operate without presenting an editor or taking focus, coordinated with https://github.com/microsoft/vscode/issues/311974. Establish whether the supported contract also includes execution without a desktop browser host before choosing the implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts`, `src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts`, `src/vs/platform/browserView/common/browserView.ts`, `src/vs/platform/browserView/electron-main/browserView.ts`, `src/vs/platform/browserView/node/playwrightService.ts`
- **Validation:** After the execution contract is agreed, run a desktop integration scenario with two agent sessions testing different local pages concurrently: neither operation opens or activates a browser editor or changes the user's focused editor, and both agents can read, interact with, and capture their respective pages. Verify session cleanup and unchanged ordinary visible-browser behavior; if desktop-independent execution is included, repeat the browser workflow without a graphical host.
- **Behavior:**

  > Agents and subagents should be able to test browser pages concurrently without presenting those pages or interrupting the user's active work. Each agent must retain the correct page references and be able to read, interact with, and capture its pages. Ordinary user-visible browser workflows must remain available. Acceptance should cover two concurrent agent sessions, focus preservation, page lifetime, and cleanup; whether a graphical host may be required is not yet settled.
- **Trace:**

  > OpenBrowserTool._openNewPage in src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts passes preserveFocus to BrowserViewWorkbenchService.createBrowserView, which still requests editor opening. BrowserViewWorkbenchService._openEditorForCreatedView can make tabs inactive, but inactive editor presentation is not a headless execution contract. BrowserViewPresentation.Unlisted and createExternalBrowserView demonstrate nonlisted infrastructure, but that creation path is user-owned and does not establish agent-tool support. PlaywrightService connects over CDP to Electron WebContentsView instances rather than launching an independent headless browser. Coordinate with https://github.com/microsoft/vscode/issues/311974 on session-owned lifetime, while retaining this older request and distinguishing it from external cross-browser testing in https://github.com/microsoft/vscode/issues/297470. Preserve existing sharing, network restrictions, visible-browser behavior, and session boundaries; the uncertainty begins at whether hidden desktop-hosted pages satisfy the requested product contract.
- **Open decisions:**
  - Does headless support mean agent-owned pages hidden within a running desktop VS Code instance, or must browser testing also work without a graphical desktop host?
