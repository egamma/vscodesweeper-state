# Issue #121799 — [remote][connection] Allow offline editing in Remote-WSL

[https://github.com/microsoft/vscode/issues/121799](https://github.com/microsoft/vscode/issues/121799)

## Summary

The reconnection UX has improved significantly since 2021 (40s delay before showing dialog, dismissable to notification, configurable 3-hour grace time), but the core request — continuing to edit files while the WSL remote connection is temporarily down — remains unimplemented and is a valid feature request requiring architectural changes to the remote editing model.

## Change summary

Allow editing files in Remote-WSL mode to continue while the remote connection is temporarily lost, rather than blocking the editor with a reconnection dialog.

## Best solution

This is an architectural feature request: allow a degraded-but-usable editing mode when the remote connection drops in WSL (where files are technically local). The reconnection dialog UX has improved (dismiss-to-notification, 40s delay, configurable grace time via `reconnectionGraceTime`), so the worst pain point — the inescapable modal — is partially mitigated. The remaining gap belongs with the Remote Development team. A narrower fix could ensure the reconnection prompt never uses `ProgressLocation.Dialog` for WSL connections specifically, keeping it as a notification so editing isn't interrupted.
