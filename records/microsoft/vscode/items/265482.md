# Issue #265482 — Copilot Suggestion Struggles With non-ASCII Characters

[https://github.com/microsoft/vscode/issues/265482](https://github.com/microsoft/vscode/issues/265482)

## Summary

Still reproduces on main: the `acceptNextWord` path in `inlineCompletionsModel.ts` computes an accept-until index via regex matching on UTF-16 code units, then uses `substring` to slice the ghost text — this can corrupt non-BMP characters (surrogate pairs) or mishandle characters the language's `wordDefinition` regex doesn't cover. No fix found in git history. Issue is properly triaged with `bug` + `inline-completions` on the `On Deck` milestone; keeping open.

## Change summary

Accepting inline completions word-by-word (Ctrl+Right) corrupts non-ASCII glyphs and drops the remaining suggestion.

## Best solution

Guard the `acceptNextWord` index computation in `src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts` (around line 1024–1042) to respect code-point boundaries — snap `acceptUntilIndexExclusive` forward past any trailing low surrogate before calling `substring`. Also verify that the language `wordDefinition` regex uses the `u` flag so multi-byte characters are treated as single units.
