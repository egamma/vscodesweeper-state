# Issue #276708 — Allow model selection defaults for auto mode in copilot chat

[https://github.com/microsoft/vscode/issues/276708](https://github.com/microsoft/vscode/issues/276708)

## Summary

Keep open: current Auto routing tiers do not let users choose the specific free and premium models Auto may select. The request has maintainer acceptance and 22 upvotes; the related reports do not establish a canonical for this exact capability.

## Change summary

Allow users to choose preferred free and premium models for Copilot Chat's Auto selection.

## Best solution

Define user-selectable model preferences for Auto with an explicit contract for how routing honors them, then coordinate the picker configuration with the Auto service. Preserve automatic selection rather than treating manual model selection or picker visibility as equivalent.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`, `extensions/copilot/src/platform/endpoint/node/automodeService.ts`, `extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts`, `extensions/copilot/src/platform/endpoint/node/test/automodeService.spec.ts`
- **Validation:** Extend Auto routing unit tests to verify the agreed preference contract, including unavailable preferred models and unchanged behavior without preferences. Manually verify that selecting the requested free/premium preferences affects Auto routing rather than merely hiding picker entries.
- **Behavior:**

  > Users want Auto to select between their chosen free and premium models rather than an exclusively service-defined set. Current routing tiers do not satisfy this request because they express broad routing preferences, not model identities. Acceptance should demonstrate that configured preferences affect actual routed requests and that users without preferences retain existing Auto behavior. The outcome when a preferred model is unavailable must be defined before implementation.
- **Trace:**

  > In extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts, buildConfigurationSchema exposes only a tier property for AutoChatEndpoint. AutomodeService._resolveTier and _route in extensions/copilot/src/platform/endpoint/node/automodeService.ts resolve that tier and ask the routing service for a concrete model. AutoV2Fetcher.getAutoDecision in extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts sends no preferred model IDs, so a picker-only change would not deliver the request. Service support for model preferences remains unestablished. Preserve manual model selection, existing tier behavior without preferences, and organization-controlled model availability. https://github.com/microsoft/vscode/issues/266950 is related local model-management work, while https://github.com/microsoft/vscode/issues/295949 concerns selection persistence rather than this routing contract.
- **Open decisions:**
  - Are the selected free and premium models strict routing constraints or preferences that Auto may override?
  - If a selected model is unavailable or unsuitable for the request, should Auto stop and ask the user or choose another eligible model?
