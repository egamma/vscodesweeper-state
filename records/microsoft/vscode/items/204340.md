- **Behavior:**

  > The reporter wants to use workbench.action.compareEditor.nextChange while reviewing multiple files in one editor, moving between changes across file boundaries. A separate multi-diff command already offers that navigation, so the remaining goal is compatibility with the established command rather than a new navigation algorithm. Acceptance should cover command invocation at a file boundary and preservation of ordinary diff navigation and existing multi-diff shortcuts.
- **Trace:**

  > src/vs/workbench/browser/parts/editor/diffEditorCommands.ts routes the established command to IDiffEditorCommandsService.navigateInDiffEditor. In diffEditorCommandsService.ts, getActiveTextDiffEditor searches the active pane followed by visible panes and accepts only TextDiffEditor; this excludes MultiDiffEditor and may target a different visible ordinary diff. The separate GoToNextChangeAction in src/vs/workbench/contrib/multiDiffEditor/browser/actions.ts calls MultiDiffEditor.goToNextChange, ultimately reaching MultiDiffEditorWidgetImpl._navigateToChange, which already crosses file boundaries. Preserve that existing navigation behavior and ordinary diff command semantics; no widget redesign is required by this report. https://github.com/microsoft/vscode/issues/282733 explicitly collects this request under the area owner's commands/keybindings work. The remaining uncertainty concerns the public command contract when an explicit resource argument and an active multi-diff editor coexist.
