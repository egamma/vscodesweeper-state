# Issue #236602 — Link parsing stoped where comments include a single quote

[https://github.com/microsoft/vscode/issues/236602](https://github.com/microsoft/vscode/issues/236602)

## Summary

The defect remains source-reproducible on current main: the syntax-agnostic link detector deliberately terminates a bare URL at a single quote, truncating the reported valid URL. Keep this accepted bug open because resolving it requires a link-boundary rule that does not regress quoted source text.

## Change summary

Recognize a valid URL containing an unescaped single quote instead of ending the clickable link at that character.

## Best solution

Define and implement a link-boundary heuristic that includes valid internal quote characters while continuing to exclude quotes that delimit surrounding source text, preserving the scenarios covered by https://github.com/microsoft/vscode/issues/156875 and https://github.com/microsoft/vscode/issues/17939.

- **Behavior:**

  > A valid URL containing a raw single quote must remain one complete clickable link. Quotes that delimit prose or source strings must not become part of the link, and existing links containing quoted URL syntax must continue to work. Acceptance requires the reported regexper URL, the trailing-quote regression case, and the existing quoted-parentheses case all to produce their intended link ranges.
- **Trace:**

  > LinkComputer.computeLinks in src/vs/editor/common/languages/linkComputer.ts handles SingleQuote, DoubleQuote, and BackTick together and forces termination for a bare URL, which conclusively truncates this report's URL. The earlier test for https://github.com/microsoft/vscode/issues/151631 is commented out in src/vs/editor/test/common/modes/linkComputer.test.ts because commit a81cd28ea892ce689292c5dc50ccdda5a241da2e chose the competing behavior required by https://github.com/microsoft/vscode/issues/156875. Keep the work bounded to syntax-agnostic editor link detection and its tests; do not change language tokenization or terminal-specific link detection.
- **Open decisions:**
  - When a bare URL contains a quote that is legal URL data but could also delimit surrounding text, which observable interpretation should the syntax-agnostic detector prefer?
  - Should quote inclusion be determined uniformly for single quotes, double quotes, and backticks, or may their user-visible boundary semantics differ?
