# Issue #236602 — Link parsing stoped where comments include a single quote

[https://github.com/microsoft/vscode/issues/236602](https://github.com/microsoft/vscode/issues/236602)

## Summary

The truncation is reproducible from current source, but it reflects an intentional ambiguity tradeoff: the language-agnostic detector treats quotes in unwrapped links as delimiters to avoid including source-code closing quotes.

## Change summary

Recognize a literal single quote inside an otherwise unwrapped URL instead of ending the detected link there.

## Best solution

Keep the conservative quote-delimiter behavior established for https://github.com/microsoft/vscode/issues/156875; URLs requiring an apostrophe can percent-encode it as `%27` or be wrapped in a different quote character.

  > Thanks for the report. This is the intentional tradeoff documented in https://github.com/microsoft/vscode/issues/156875: the language-agnostic link detector treats a quote in an unwrapped URL as a delimiter, because otherwise common source-code links absorb their closing quote. For this URL, encoding the apostrophe as `%27` or wrapping the URL in a different quote character avoids the ambiguity.

## Evidence

- **intentional parser rule:** `src/vs/editor/common/languages/linkComputer.ts` explicitly force-terminates on single, double, and backtick quotes unless the link began after a different quote character, so the reported bare URL is deliberately truncated at the apostrophe.
- **documented tradeoff:** In https://github.com/microsoft/vscode/issues/156875#issuecomment-1288810318, the editor maintainer explained that a syntax-agnostic detector cannot reliably distinguish an apostrophe inside a URL from a source-code closing quote and chose the more common delimiter behavior.
- **implementation history:** Commit https://github.com/microsoft/vscode/commit/a81cd28ea892ce689292c5dc50ccdda5a241da2e intentionally changed the parser to “Prefer that quotes terminate links in ambiguous cases” and disabled the regression test for https://github.com/microsoft/vscode/issues/151631.
- **no replacement fix:** The only referenced fix attempt, https://github.com/microsoft/vscode/pull/237126, was closed without merging; current main retains the intentional quote-handling rule.
