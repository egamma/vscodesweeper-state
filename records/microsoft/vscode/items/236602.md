# Issue #236602 — Link parsing stoped where comments include a single quote

[https://github.com/microsoft/vscode/issues/236602](https://github.com/microsoft/vscode/issues/236602)

## Summary

Still reproduces on main: the link parser in linkComputer.ts treats a literal single quote inside a URL as ForceTermination when the link is not wrapped in quotes, truncating the detected link. The related external PR #237126 was closed without merge, and no other fix has landed.

## Change summary

URLs containing literal single quotes (valid in URL syntax) are truncated by the link parser when the link is not wrapped in a different quote character.

## Best solution

Update the quote-handling logic in `src/vs/editor/common/languages/linkComputer.ts` (lines 264–274) to allow percent-encoded and literal quotes inside URLs when they appear after the `#` fragment or `?` query delimiters, or when the quote is not acting as a string delimiter in the surrounding context. The fix must preserve the existing behavior where quotes terminate links in truly ambiguous cases (commit a81cd28ea89).

  > The link parser truncates URLs containing literal single quotes because of the quote-handling logic in src/vs/editor/common/languages/linkComputer.ts lines 264–274. When the parser is in the Accept state and encounters a SingleQuote (or DoubleQuote/BackTick), it checks `linkBeginChCode` — the character immediately before the link. If that character is not itself a quote, the else branch (line 272) sets `chClass = ForceTermination`, ending the link at the quote. This breaks valid URLs like `https://regexper.com/#%2F%28%5B'%22%5D%29%3F%28foo%7Cbar%29%5C%5C1%3F%2Fgi` when they appear in comment lines where the preceding character is a space. The fix should allow single quotes inside URLs in contexts where they are clearly part of the URL (e.g. after `#` or `?` fragments, or when percent-encoded content surrounds them). Be careful to preserve the behavior from commit a81cd28ea89 where quotes DO terminate links in genuinely ambiguous cases (e.g. `href='https://example.com'` — the closing quote must end the link). One approach: track whether the URL has entered a fragment (`#`) or query (`?`) section, and allow quotes there. Add a test in src/vs/editor/test/common/modes/linkComputer.test.ts for the URL from the issue, and verify existing quote-termination tests still pass.
