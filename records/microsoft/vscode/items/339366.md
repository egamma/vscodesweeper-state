# Issue #339366 — Should the simple "open file" picker auto-select the pre-filled text?

[https://github.com/microsoft/vscode/issues/339366](https://github.com/microsoft/vscode/issues/339366)

## Summary

Keep open for an accessibility interaction decision: current source explicitly places the caret after the pre-filled directory rather than selecting it. No existing selection setting or verified canonical duplicate was found, and this collaborator-authored request should not receive a judgment close.

## Change summary

Reconsider whether the simple Open File picker should initially select its entire pre-filled path.

## Best solution

Agree on an initial-selection policy that makes replacing the path easier without unnecessarily disrupting relative-path entry. Apply the agreed behavior to the simple dialog's opening flow while preserving navigation, completion, and Save As filename-selection behavior.

Manually enable files.simpleDialog.enable, invoke Ctrl+O, inspect initial selection, and verify path replacement, relative-path entry, directory navigation, and unchanged Save As filename selection.
- **Behavior:**

  > With files.simpleDialog.enable enabled, opening the file picker currently leaves the caret after the pre-filled directory, requiring a separate select-all action to replace the path. The goal is an accessible, consistent initial-selection policy whose path-replacement and relative-entry behavior is explicitly agreed with a maintainer. Acceptance must inspect selection after initial loading completes, not only when the picker first appears. Subsequent directory navigation, completion, and Save As filename selection should retain their established behavior.
- **Trace:**

  > SimpleFileDialog.pickResource in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts explicitly collapses selection at the end both before showing the picker and after its initial updateItems call when no trailing filename exists. updateItems independently adjusts selection during navigation, so a change to shared selection handling could affect more than opening. The trailing-filename branch selects the name without its extension and is a separate behavior to preserve. Existing tests are in src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts. Source inspection establishes the current interaction, but https://github.com/microsoft/vscode/issues/339366 deliberately asks whether that interaction should change; it does not establish a broken existing contract.
- **Open decisions:**
  - On initial Open File display, should the entire pre-filled directory be selected so typing replaces it, or should the caret remain at the end so typing appends a relative path?
