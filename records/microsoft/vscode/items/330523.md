# Issue #330523 — Inconsistent Auto-Closing and Deletion for JSX/TSX Props

[https://github.com/microsoft/vscode/issues/330523](https://github.com/microsoft/vscode/issues/330523)

## Summary

Real, traceable inconsistency, but it bundles two separate root causes in different subsystems: the string-quote deletion asymmetry is core editor behavior (already the exact subject of an open issue proposing a default change), while the missing `={}` for boolean props is tsserver's JSX attribute completion heuristic, not core VS Code code.

## Change summary

JSX/TSX attribute completions are inconsistent: boolean props don't get `={}` auto-inserted, and deleting an auto-inserted `""` only removes the closing quote instead of both.

## Best solution

Split the concerns: for the quote-deletion asymmetry, `src/vs/editor/common/cursor/cursorDeleteOperations.ts` only treats a closing quote/bracket as deletable-as-pair when it's tracked in `autoClosedCharacters` (i.e. inserted via the editor's own auto-closing-pair mechanism, not via a completion snippet) — this is exactly what https://github.com/microsoft/vscode/issues/129980 is already tracking via the `editor.autoClosingDelete` default; for the boolean-prop `={}` insertion gap, that decision is made server-side by tsserver's `jsxAttributeCompletionStyle: 'auto'` heuristic (extensions/typescript-language-features/src/languageFeatures/fileConfigurationManager.ts) and likely needs a TypeScript-side fix or the user can opt into `js/ts.preferences.jsxAttributeCompletionStyle: 'braces'` today.

## Auto-fix candidate

## Evidence

- **quote deletion logic:** src/vs/editor/common/cursor/cursorDeleteOperations.ts:133-136 only deletes the pair when `autoClosingDelete === 'auto'` AND the closing char is found in `autoClosedCharacters` — quotes inserted by a completion snippet (not the editor's own auto-close mechanism) aren't tracked there, so only the single character is deleted.
- **related open issue (partial overlap):** https://github.com/microsoft/vscode/issues/129980 proposes changing the default of `editor.autoClosingDelete` to 'always', which would directly address the string-quote half of this report, but does not cover the boolean-prop `={}` insertion complaint.
- **boolean prop insertion is tsserver-driven:** extensions/typescript-language-features/src/languageFeatures/fileConfigurationManager.ts:301-306 reads `preferences.jsxAttributeCompletionStyle` ('auto' by default) and passes it to tsserver, which decides whether to insert `={}`/`=""` per prop type server-side; the 'auto' docs (package.nls.json:210) say it should insert `={}` for non-string props, so a miss here is either a TS-side heuristic gap or a type-inference edge case, not core editor code.
