## Summary

Valid, still-open polish report from a team member: on main, `AgentHostSessionConfigPicker._renderConfigPickers` still renders the Isolation/Worktree checkbox and Branch chip as disabled/read-only chrome rather than hiding them when the session config isn't yet resolvable, matching the reported screenshot; no fix has landed yet, so it should stay open under its existing labels.

## Change summary

In the Agents window, starting a new chat within a session shows the worktree/branch pickers rendered disabled instead of being hidden until they're actually usable.

## Best solution

In `src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionConfigPicker.ts`, extend `_shouldRenderProperty`/`_renderIsolationCheckbox` (and the mobile subclass) so Isolation/Branch are skipped entirely while not yet actionable in the new-chat-in-session flow, rather than rendered as disabled chips/checkbox — this is a UX call for the agents-window/chat owners, not a one-line fix.
