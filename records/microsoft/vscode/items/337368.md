# Issue #337368 — Clarify organization-managed Auto default in model picker

[https://github.com/microsoft/vscode/issues/337368](https://github.com/microsoft/vscode/issues/337368)

## Summary

Legitimate, well-scoped follow-up to the recently-landed managed-Auto-default feature: traced the code and confirmed the gap the reporter describes — the model picker's config dropdown marks a managed tier as "Default" but the hover/aria text is identical to an ordinary default, so there is no way to tell the two apart. Correctly labeled already (chat, chat-input); keep open for implementation.

## Change summary

When an Auto routing tier's "Default" badge comes from an org-managed setting rather than an ordinary default, add a hover tooltip (and matching screen-reader text) that says so, without changing the presentation of a non-managed default.

## Best solution

Implement in the model-picker configuration dropdown: thread a managed/non-managed distinction through the effective schema built in chatModelConfigurationStore.ts so modelPickerConfiguration.ts can render a different tooltip/aria-description only for the managed-default case.
