# Issue #150186 — Table: Support horizontal scrolling

[https://github.com/microsoft/vscode/issues/150186](https://github.com/microsoft/vscode/issues/150186)

## Summary

Keep open: the existing horizontal-scrolling setting does not provide coordinated scrolling of table headers and rows. This is accepted, team-authored work, and neither a concrete fixing commit nor an older canonical covering the same request was verified.

## Change summary

Support usable horizontal scrolling in the shared table widget when columns exceed the available viewport width.

## Best solution

Provide coordinated horizontal scrolling of table headers and rows, with consistent column sizing during viewport changes and column resizing. Settle when columns should stop shrinking and begin overflowing before implementation.

## Plan brief

- **Validation:** Exercise a WorkbenchTable with horizontal scrolling enabled and a viewport narrower than its columns: scroll to the rightmost column, verify header/body alignment, resize columns and the viewport, and toggle the setting. - **Behavior:**

  > Tables whose columns exceed the available viewport should allow users to reach the overflowing columns horizontally. Headers and corresponding row cells must remain aligned throughout scrolling and resizing. Acceptance should cover narrow layouts, column resizing, viewport resizing, and changes to the existing horizontal-scrolling setting, without altering vertical navigation or selection.
- **Trace:**

  > WorkbenchTable in src/vs/platform/list/browser/listService.ts already forwards workbench.list.horizontalScrolling and its updates to Table. Table in src/vs/base/browser/ui/table/tableWidget.ts creates a separate SplitView for headers and List for rows; scrollLeft is forwarded only to the List, and the constructor does not coordinate header scrolling. Table.layout gives both components the viewport width, while table.css clips overflowing content. The maintainer identifies this work as a solution for narrow Problems tables at https://github.com/microsoft/vscode/issues/150793#issuecomment-1142570554. Preserve existing list navigation, selection, and non-scrolling behavior; automatic column hiding and reordering are separate requests. The unresolved product boundary is how column widths should behave when the viewport becomes too narrow.
- **Open decisions:**
  - With horizontal scrolling enabled, should columns continue shrinking to their configured minimum widths before overflowing, or retain user-resized widths and begin overflowing earlier?
