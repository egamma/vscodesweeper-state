# Issue #252269 — remote os calls in remote installed extension do not work

[https://github.com/microsoft/vscode/issues/252269](https://github.com/microsoft/vscode/issues/252269)

## Summary

The supplied extension-kind order intentionally prefers local execution, even when the extension is also installed remotely. The follow-up about installing the Marketplace version is also documented behavior; both questions have supported configuration and installation paths.

## Change summary

Run an extension's Node.js child processes on the remote container and install an unpublished VSIX there instead of its Marketplace version.

## Best solution

Use "extensionKind": ["workspace"] for an extension that requires remote workspace OS access, and install its development VSIX through Install from VSIX in the remote-connected window. Confirm the execution location with Developer: Show Running Extensions rather than inferring it from installation location.

## Evidence

- **Documented execution preference:** https://code.visualstudio.com/api/advanced-topics/extension-host#preferred-extension-location explicitly states that "extensionKind": ["ui", "workspace"] prefers the local extension host when installed locally, whereas ["workspace"] requires execution where the workspace resides. Remote installation alone does not override this order.
- **Current source matches the reported result:** src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts:709-727, NativeExtensionHostKindPicker.pickExtensionHostKind, iterates extension kinds in order. For 'ui' with a local installation and no overriding running preference, it returns LocalProcess before reaching the remote 'workspace' branch. This explains local child_process.exec output without a defect in remote OS access.
- **VSIX follow-up is documented and implemented:** https://code.visualstudio.com/api/advanced-topics/remote-extensions#installing-a-development-version-of-your-extension says automatic remote installation uses the Marketplace version, not the locally installed development version, and documents Install from VSIX in a remote-connected window. src/vs/workbench/contrib/extensions/browser/extensionsActions.ts:3325-3343 likewise resolves gallery entries first and packages the local installation only when no gallery entry is available.
- **Discussion clarification:** The reporter's 2025-12-15 comment on https://github.com/microsoft/vscode/issues/252269 confirms that the SSH target is a Docker instance, so localhost does not establish that local and remote OS environments are identical.
