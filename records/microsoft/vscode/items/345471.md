## Summary

Keep open: a second maintainer confirmed the duplicate trust prompt and indefinite Working state on Windows with a standalone Dev Container. No issue-referencing fix or verified canonical covers both symptoms; this team-authored report remains necessary.

## Change summary

An already-trusted remote folder prompts again on the first message, and cancelling leaves an empty response and a permanently Working session.

## Best solution

Make folder selection and first-message trust checks recognize the same remote folder identity while preserving host isolation. Declining trust must visibly settle the request without running it; also verify that disconnecting and reconnecting preserves the session.
