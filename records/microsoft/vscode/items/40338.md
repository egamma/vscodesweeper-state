# Issue #40338 — [folding] configure initial collapse state

[https://github.com/microsoft/vscode/issues/40338](https://github.com/microsoft/vscode/issues/40338)

## Summary

Keep open as a well-supported backlog feature request: automatic import folding addressed only one case, while configurable initial collapse for regions, comments, and matching ranges remains requested. With 85 upvotes and no verified older canonical covering the same observable request, this should remain under discussion.

## Change summary

Allow folding ranges to declare or configure whether they are collapsed when a file is initially opened, including regions and selected range kinds or patterns.

## Best solution

Define a general initial-fold policy in the editor folding contribution, preferably keyed by folding-range kind with a clearly bounded mechanism for explicit regions; separately decide whether arbitrary tag or regex matching belongs in core or an extension.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Add editor folding tests that open a model with imports, comments, and marker regions and assert only ranges selected by the chosen initial-fold policy start collapsed, while restored user folding state and the existing `editor.foldingImportsByDefault` behavior remain intact.
- **Behavior:**

  > When a document is first opened, users can opt selected folding ranges into an initially collapsed state instead of manually folding them every time. The policy must cover the agreed range categories or explicit region marker semantics without changing the default expanded behavior for users who do not enable it. Existing import folding and restored per-file fold state must continue to work. Acceptance should include regions and at least one non-region folding-range kind.
- **Trace:**

  > The current editor already has a narrow initial-collapse mechanism: `editor.foldingImportsByDefault` is registered in src/vs/editor/common/config/editorOptions.ts and consumed by the folding contribution in src/vs/editor/contrib/folding/browser/folding.ts for `FoldingRangeKind.Imports`. The issue asks to generalize the observable behavior to regions and other selected ranges; comments after the import feature landed confirm that gap remains. Related requests https://github.com/microsoft/vscode/issues/84844 and https://github.com/microsoft/vscode/issues/142062 broaden the desired matching semantics, but they do not settle whether arbitrary tag or regex rules belong in core. Preserve normal fold-state restoration and do not conflate this work with language-specific folding-range generation.
- **Open decisions:**
  - Should the public setting select standardized folding-range kinds only, or also support explicit per-region collapsed markers?
  - Should initially collapsed state apply only on the first open of a document, or override a previously restored user folding state?
  - Are arbitrary tag or regex-based initial folds part of the core contract, or should core stop at folding-range kinds and explicit regions?
