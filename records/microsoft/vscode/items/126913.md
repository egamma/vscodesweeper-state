# Issue #126913 — Workspace Trust - Investigate what it means to support the notion of trust for virtual workspaces

[https://github.com/microsoft/vscode/issues/126913](https://github.com/microsoft/vscode/issues/126913)

## Summary

This team-authored exploration remains an active design question: current Workspace Trust still special-cases remote and `vscode-vfs` URIs rather than supporting general virtual-workspace trust aliases. As an exploration/umbrella item, it is protected from cleanup closure.

## Change summary

Define how Workspace Trust should evaluate and persist trust for virtual workspace folders and virtual documents supplied by extension-backed URI schemes.

## Best solution

Keep this as the Workspace Trust design umbrella until maintainers settle the startup lifecycle, provider ownership, and virtual-folder-versus-virtual-document boundaries. Coordinate that decision with the open canonical URI API proposal at https://github.com/microsoft/vscode/issues/180582, then adopt the resulting provider mechanism in WorkspaceTrustManagementService rather than retaining scheme-specific handling.
