# Issue #339486 — Feature Request: Independent text zoom for individual editor groups

[https://github.com/microsoft/vscode/issues/339486](https://github.com/microsoft/vscode/issues/339486)

## Summary

Genuine feature gap confirmed in source — EditorZoom is a single global singleton, not per-group — and the issue is now correctly in the Backlog Candidates 60-day upvote window with 0 upvotes so far; nothing to close yet.

## Change summary

Let each editor group/view have its own independent text zoom level, similar to per-tab browser zoom, instead of one global zoom applied to all editors.

## Best solution

Keep open through the Backlog Candidates upvote window; if it gains traction, the design work belongs in src/vs/editor/common/config/editorZoom.ts (currently a single global singleton consumed across editor widgets) to become per-editor-group state, plus a decision on how zoom should propagate across split groups.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorZoom.ts`, `src/vs/editor/browser/controller/mouseHandler.ts`, `src/vs/editor/contrib/fontZoom/browser/fontZoom.ts`
- **Validation:** A test asserting that setting zoom while one editor group is focused does not change the zoom level reported by EditorZoom for an editor in a different group.
- **Trace:**

  > EditorZoom (src/vs/editor/common/config/editorZoom.ts) is a module-level singleton with one _zoomLevel field and one onDidChangeZoomLevel emitter; every editor widget and the fontZoom contribution (src/vs/editor/contrib/fontZoom/browser/fontZoom.ts) read/write this single instance, so all editors zoom together. Making zoom per-group would require scoping this state to an editor group or editor instance and deciding how it is created, inherited on split, and restored across sessions.
- **Open decisions:**
  - Should zoom be per editor-group, per individual editor tab, or per editor pane instance?
  - When a group is split, does the new group inherit the current zoom level or start at the default?
  - Should per-group zoom be persisted across window reloads/workspace restores, and if so, where?
