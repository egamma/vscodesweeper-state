# Issue #329764 — [regression] GitHub Copilot chat up arrow deletes current chat content.

[https://github.com/microsoft/vscode/issues/329764](https://github.com/microsoft/vscode/issues/329764)

## Summary

Confirmed regression: PR https://github.com/microsoft/vscode/pull/328269 removed the `not('isComposing')` clause from the built-in `history.showPrevious`/`history.showNext` keybinding `when` (in src/vs/platform/history/browser/contextScopedHistoryWidget.ts) as part of centralizing IME-composition handling at the keyboard-event layer. That changes the exact `when` string, so a user's keybindings.json override that unbinds the old exact clause no longer matches the new default rule, and the up/down history navigation silently reappears for them. A collaborator has already linked the same PR in the thread but hasn't resolved it, so this needs a maintainer decision rather than a close.

## Change summary

After PR #328269 changed the default history-navigation keybinding's `when` clause (dropping `!isComposing`), a user's keybindings.json override targeting the old clause no longer suppresses Up/Down history navigation in chat.

## Best solution

A maintainer should decide whether to update docs/release notes calling out the `when`-clause change (so overrides can be adjusted), or add a compatibility note in the keybindings.json migration guidance; the underlying `isComposing` normalization from #328269 is intentional and shouldn't be reverted, but the silent break of user overrides is worth acknowledging in that PR's area (keybindings/history navigation).
