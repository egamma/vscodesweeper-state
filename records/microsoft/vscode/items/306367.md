# Issue #306367 — Failures when running tests for a newly-created extension project in a folder with spaces in the name

[https://github.com/microsoft/vscode/issues/306367](https://github.com/microsoft/vscode/issues/306367)

## Summary

The failure is in the external `@vscode/test-electron` launcher, which passed Windows arguments containing spaces through a shell without quoting them. The upstream fix has landed, so this should remain open as upstream until the updated test package is confirmed in newly generated projects.

## Change summary

Extension tests should launch successfully on Windows when the generated project path contains spaces.

## Best solution

Use `@vscode/test-electron` 3.0.0 or newer in generated extension projects and confirm the original workflow succeeds; no VS Code core change is needed.

## Evidence

- **upstream root cause:** The failing stack enters `@vscode/test-electron/out/runTest.js`; its old Windows path used `child_process.spawn` with `shell: true` while passing arguments containing spaces unquoted.
- **upstream report:** https://github.com/microsoft/vscode-test/issues/298 documents the same Windows argument splitting for paths containing spaces.
- **upstream fix:** https://github.com/microsoft/vscode-test/commit/6e17df7ed031ca7a613515846cec94e8499a49df disables shell launching except for `.cmd` executables and quotes arguments when a shell is required.
- **current generator:** microsoft/vscode-generator-code currently specifies `@vscode/test-electron` `^3.0.0`, which includes the upstream fix.
