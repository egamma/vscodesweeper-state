It should stay open under discussion while the remaining scope is separated from capabilities already delivered or tracked elsewhere.

## Change summary

Provide configurable folding-region visualization and interactions, including region guides, active-region highlighting, offscreen opening-bracket context, and folding from a closing bracket.

A maintainer design pass should decide which remaining interactions form one coherent editor feature before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingDecorations.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`
- **Validation:** End the plan with focused editor tests demonstrating each selected behavior: active-region guide rendering, unchanged existing bracket-guide behavior, and any approved closing-line folding interaction.
- **Behavior:**

  > Users should be able to understand the boundaries of the active foldable region and its relationship between opening and closing lines without losing existing folding or bracket-guide behavior. Any added presentation must have explicit configuration and theme behavior where the design calls for it. If folding from a closing line is included, invoking it must toggle the same region as its opening-line control. Existing single-line folding behavior remains owned by https://github.com/microsoft/vscode/issues/3352.
- **Trace:**

  > Current bracket visualization is configured by `GuideOptions` in src/vs/editor/common/config/editorOptions.ts through `editor.guides.bracketPairs`, `editor.guides.bracketPairsHorizontal`, and `editor.guides.highlightActiveBracketPair`. Folding visuals are produced by `FoldingDecorationProvider` in src/vs/editor/contrib/folding/browser/foldingDecorations.ts, while pointer-driven folding in `FoldingController.onEditorMouseUp` only toggles a region whose start line matches the clicked line. The issue is the canonical folding-lines discussion by explicit maintainer decision in https://github.com/microsoft/vscode/issues/139425, but its single-line-collapse portion is separately tracked by https://github.com/microsoft/vscode/issues/3352. Preserve language folding-range computation and existing guide defaults unless the maintainer explicitly expands the scope.
- **Open decisions:**
  - Should this issue retain only folding-region lines and active-region highlighting, or also include offscreen opening-bracket context and closing-line folding?
  - Should folding-region visualization be always visible, active-region-only, or selectable through a setting?
  - Are existing bracket-pair guides sufficient for the anchor/lead portion of the request, or must folding regions have a distinct visual treatment?

## Evidence

- **canonical ownership:** A maintainer explicitly reopened this issue as the canonical request for folding lines when closing https://github.com/microsoft/vscode/issues/139425; older https://github.com/microsoft/vscode/issues/4096 and later https://github.com/microsoft/vscode/issues/25132 were also closed as duplicates of this issue.
- **existing partial capability:** Current main registers `editor.guides.bracketPairs`, `editor.guides.bracketPairsHorizontal`, and `editor.guides.highlightActiveBracketPair` in src/vs/editor/common/config/editorOptions.ts, covering much of the requested bracket-anchor/guide presentation.
- **remaining folding gap:** src/vs/editor/contrib/folding/browser/folding.ts only toggles a clicked region when `region.startLineNumber === lineNumber`; there is no corresponding closing-line folding interaction, so the bottom-bracket request remains unmet.
- **separate narrower request:** https://github.com/microsoft/vscode/issues/3352 is open and owns collapse-to-one-line/ending-brace behavior, but it covers only one part of this broader request and therefore is not a valid canonical duplicate target for this re-reviewed item.
