# Issue #350741 — P2 Every keystroke recomputes glyph margin lanes by walking all decorations of the model (~7 ms per call, 2 calls per key on a 100k-line CSS file with 0 margin decorations)

[https://github.com/microsoft/vscode/issues/350741](https://github.com/microsoft/vscode/issues/350741)

## Summary

Keep open: current source confirms that typing invalidates glyph lanes and scans every decoration even when no glyph-margin decorations exist. This is a bounded editor performance defect, distinct from the related glyph-margin design and outline performance issues.

## Change summary

Eliminate full-model decoration traversal for glyph-lane recomputation when typing with no glyph-margin decorations.

## Best solution

Make the empty glyph-margin case independent of unrelated decoration count while preserving correct lane updates for real glyph decorations and widgets. Keep existing decoration notifications and edit-driven range movement correct.
