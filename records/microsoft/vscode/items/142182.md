# Issue #142182 — Consider reducing requirements for results provided by extensions

[https://github.com/microsoft/vscode/issues/142182](https://github.com/microsoft/vscode/issues/142182)

## Summary

The public completion-provider contract still requires full Range and Position shapes, although the runtime already accepts structural ranges. Keep this team-authored API discussion open: maintainers agreed to measure conversion savings, and neither a completed implementation nor an older canonical was established.

## Change summary

Allow extension providers to return data-only result objects without constructing full VS Code API class instances.

## Best solution

Measure allocation and conversion costs for completions and diagnostics, then decide whether to expose data-only provider results or pursue the discussed lazy LSP-compatible representation. Preserve existing provider contracts and resolve behavior while making any supported lightweight representation explicit in the public API.
