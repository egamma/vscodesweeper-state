# Issue #24043 — Neo keyboard layout: Some Keys stopped working

[https://github.com/microsoft/vscode/issues/24043](https://github.com/microsoft/vscode/issues/24043)

## Summary

Keep open: multiple users confirmed Neo-family layer keys invoking the wrong shortcuts, including with extensions disabled and both dispatch modes tested. The keyCode workaround only partially covers the report, and neither a complete fix nor an older canonical with the same observable symptom was established.

## Change summary

Correctly recognize Neo-family navigation-layer keys and shortcuts containing higher-layer characters instead of ignoring them or invoking base-layer shortcuts.

## Best solution

Make Neo-family layered navigation and character shortcuts resolve consistently through the Linux keyboard pipeline. Diagnose the remaining browser-event versus VS Code mapping boundary using the recorded Bone Ctrl+/ failure before choosing the implementation scope.

## Plan brief

- **Likely files:** `src/vs/base/browser/keyboardEvent.ts`, `src/vs/platform/keyboardLayout/common/keyboardLayout.ts`, `src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts`, `src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts`, `src/vs/workbench/services/keybinding/common/fallbackKeyboardMapper.ts`, `src/vs/workbench/services/keybinding/test/node/macLinuxKeyboardMapper.test.ts`, `src/vs/workbench/services/keybinding/test/node/fallbackKeyboardMapper.test.ts`
- **Validation:** On current Linux with Neo2 or Bone and extensions disabled, record raw events and resolved commands for layer-four Left/Backspace, Ctrl+layer-four Right, and the documented Bone Ctrl+/ sequence under both dispatch modes. Verify navigation, word movement, and the intended character shortcut without triggering base-layer commands; encode the confirmed event sequences in focused keyboard-event/mapper regression tests.
- **Behavior:**

  > Neo-family layer keys must retain their intended navigation or character meaning when used in shortcuts. Reported failures include layer-four navigation being ignored and higher-layer Ctrl shortcuts invoking commands for a base-layer letter instead. Acceptance should cover the documented Bone Ctrl+/ case and Neo navigation with Ctrl, while preserving ordinary typing and established non-Neo keybindings.
- **Trace:**

  > The extension-disabled diagnostic at https://github.com/microsoft/vscode/issues/24043#issuecomment-1890465193 supplies a concrete Ctrl+/ event with key='/' and numeric keyCode=84. StandardKeyboardEvent in src/vs/base/browser/keyboardEvent.ts translates that numeric code, and FallbackKeyboardMapper.resolveKeyboardEvent uses it directly after nativeKeyboardLayout.ts selects keyCode dispatch. MacLinuxKeyboardMapper handles the alternative scan-code path; the Linux mapping contract currently has no explicit Level5 fields. The merged https://github.com/microsoft/node-native-keymap/pull/19 is a relevant capability lead, not proof of a complete adopted fix. Uncertainty begins with which events current Linux sessions deliver and how much remaining work belongs to browser event generation versus VS Code's mapping consumers. Preserve default dispatch semantics, unrelated layouts, and ordinary character input; do not treat the separate NeoX conflict as the root cause of all reports.

## Evidence

- **Confirmed reproduction with isolation:** https://github.com/microsoft/vscode/issues/24043#issuecomment-1890465193 reports Bone Ctrl+/ invoking workbench.action.showAllSymbols after testing code and keyCode dispatch, a clean user-data directory, disabled extensions, and a single configured layout. The log records key='/' but keyCode=84, subsequently resolved as Ctrl+T. The supplied February 2025 comment independently reports Neo2 Ctrl+( failing in both dispatch modes.

Disabling NeoX resolved one commenter's separate typing failure, not the original report or the later extension-disabled reproduction.
- **Current source preserves the recorded failure path:** src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts selects FallbackKeyboardMapper for keyboard.dispatch='keyCode'. src/vs/base/browser/keyboardEvent.ts extractKeyCode translates the DOM numeric keyCode rather than the reported key character, and src/vs/workbench/services/keybinding/common/fallbackKeyboardMapper.ts resolveKeyboardEvent constructs its chord from that translated keyCode. Given the recorded Ctrl+/ event, this path still resolves Ctrl+T; no current Linux runtime reproduction was executed.
