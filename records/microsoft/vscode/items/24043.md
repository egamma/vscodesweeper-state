# Issue #24043 — Neo keyboard layout: Some Keys stopped working

[https://github.com/microsoft/vscode/issues/24043](https://github.com/microsoft/vscode/issues/24043)

## Summary

Still reproduces on main: VS Code's Linux keyboard mapper (`ILinuxKeyMapping`) only supports 4 levels (value, withShift, withAltGr, withShiftAltGr), but Neo-family layouts use ISO_Level3_Shift (CapsLock) and ISO_Level5_Shift for up to 6 levels. The higher layers are simply not captured by `node-native-keymap` or the mapper, so keys on those layers don't dispatch correctly without the `keyboard.dispatch: keyCode` workaround.

## Change summary

Neo keyboard layout's higher layers (3+) don't work in VS Code on Linux because the keyboard mapper only captures 4 XKB levels.

## Best solution

Extend `node-native-keymap` (now `native-keymap` ^3.3.5) to report ISO_Level3_Shift and ISO_Level5_Shift layers separately from AltGr, and update `ILinuxKeyMapping` plus `MacLinuxKeyboardMapper` to handle 6+ XKB levels. The merged PR https://github.com/microsoft/node-native-keymap/pull/19 added partial Level3/Level5 shift support but the VS Code side was never completed. This is a non-trivial change spanning `native-keymap`, `src/vs/platform/keyboardLayout/common/keyboardLayout.ts`, and `src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts`.
