# Issue #336137 — Create PR title bar action overlaps navigation controls when zoomed

[https://github.com/microsoft/vscode/issues/336137](https://github.com/microsoft/vscode/issues/336137)

## Summary

Plausible, traceable layout defect: the Agents-window titlebar's overflow system only recomputes on zoom/resize or on a registered toolbar's own menu-items changing, but the "Create Pull Request" button lives inside a nested WorkbenchButtonBar (ChangesWorkbenchButtonBarWidget) whose internal buttons/labels can change width independently — those changes never notify the titlebar's overflow scheduler, so the right-side actions container can grow past its available space without the overlap-prevention (`overflowing` class) kicking in. Already correctly labeled bug/zoom/titlebar, so it just needs to stay open for a fix.

## Change summary

At higher zoom levels the Create PR title-bar button overlaps the navigation controls to its left instead of the title bar reflowing/hiding actions to fit.

## Best solution

In src/vs/sessions/browser/parts/titlebarPart.ts, make the overflow recheck resilient to internal width changes of custom action view items (e.g. observe size via ResizeObserver on titlebar-right/-center containers, or have ChangesActionsBar's onDidChangeActions in src/vs/sessions/contrib/changes/browser/changesView.ts explicitly trigger the titlebar's overflow scheduler) so the Create PR button is folded into the existing hide-on-overflow mechanism instead of overlapping.

## Evidence

- **overflow scheduler triggers:** src/vs/sessions/browser/parts/titlebarPart.ts registerOverflowManagedToolBar() only schedules a recheck via toolBar.onDidChangeMenuItems and via layout()/zoom changes (lines ~331-360); it has no path for a custom action view item's internal content changing width.
- **Create PR button is a nested custom widget:** ChangesActionsBarActionViewItem (changesView.ts:633) renders ChangesActionsBar (line 575) into the sessionActionsContainer toolbar as a single MenuItemAction; the actual 'Create Pull Request' button/label lives inside ChangesWorkbenchButtonBarWidget's WorkbenchButtonBar (changesView.ts:302-340), whose label/busy-state can change without the parent toolbar's menu items changing.
- **hide-on-overflow only, no reflow:** titlebarpart.css lines 113-116 hide the whole '.titlebar-actions-container.overflowing' via display:none rather than shrinking it, so if the overflow check runs stale, the container is left at full (overlapping) width instead of adapting.
