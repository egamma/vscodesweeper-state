# Issue #299826 — Add `forceInstall` to `extensions.json` for auto-installing workspace extensions

[https://github.com/microsoft/vscode/issues/299826](https://github.com/microsoft/vscode/issues/299826)

## Summary

The requested capability remains absent from current main, and the related implementation PR was closed without merging after raising an unresolved web-workspace trust concern. This maintainer-authored feature request has no factual close basis and should remain open for a security and product decision.

## Change summary

Allow trusted workspaces to declare bundled workspace resource extensions in `.vscode/extensions.json` for automatic version-aware installation while preserving user opt-out.

## Best solution

Settle whether automatic installation is permitted in web hosts where workspaces are treated as trusted, then implement the narrowly scoped resource-extension flow with version tracking, trust enforcement, disablement preservation, and targeted tests.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts`, `src/vs/workbench/services/extensionRecommendations/common/workspaceExtensionsConfig.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/contrib/extensions/browser/forceInstallExtensions.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionRecommendationsService.test.ts`
- **Validation:** Add targeted unit tests covering configuration parsing, trusted versus untrusted workspaces, one installation per extension version, reinstallation after a version bump, exclusion of non-resource extensions, and preservation of user disablement; run them with `scripts/test.sh --grep "Force Install Extensions"`.
- **Behavior:**

  > A trusted workspace may list extensions bundled under its workspace resource-extension locations in `forceInstall` within `.vscode/extensions.json`. Each listed extension version is installed as a workspace extension at most once, and a version change triggers another installation. Untrusted workspaces and marketplace-only identifiers must not trigger installation, and disabling an installed extension must remain an effective opt-out. The accepted design must explicitly define whether and under what trust condition this behavior is available in web hosts.
- **Trace:**

  > Current parsing runs through `WorkspaceExtensionsConfigService` in src/vs/workbench/services/extensionRecommendations/common/workspaceExtensionsConfig.ts, and the JSON schema is registered from src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts by src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts; neither currently recognizes `forceInstall`. The closed implementation attempt https://github.com/microsoft/vscode/pull/299830 added a dedicated `ForceInstallExtensionsContribution` and used the existing workspace-extension scanning and installation services, confirming the likely boundary. Its review identified missing tests for version deduplication and opt-out behavior, plus the unresolved web trust concern at https://github.com/microsoft/vscode/pull/299830#discussion_r3352400669. Keep the scope limited to workspace resource extensions: do not turn workspace recommendations into unattended Marketplace installs or re-enable extensions the user disabled.
- **Open decisions:**
  - Should `forceInstall` be unavailable on web hosts, or what additional user-consent or provenance requirement must web workspaces satisfy before repository-bundled code can be installed automatically?

## Evidence

- **current source gap:** On current main, src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts defines only `recommendations` and `unwantedRecommendations`, while src/vs/workbench/services/extensionRecommendations/common/workspaceExtensionsConfig.ts parses only those fields; no `forceInstall` field or automatic-install contribution exists.
- **closed implementation attempt:** https://github.com/microsoft/vscode/pull/299830 proposed the exact feature across the extensions configuration parser, schema, and a new workbench contribution, but it was closed on 2026-09-02 without merging.
- **open product decision:** The review at https://github.com/microsoft/vscode/pull/299830#discussion_r3352400669 identifies a distinct security concern: browser VS Code instances treat workspaces as trusted while github.dev and vscode.dev can open repositories directly from links, so the proposed trust gate may be insufficient on web.
- **related request is not canonical:** https://github.com/microsoft/vscode/issues/312120 is newer and requests automatic synchronization of installed extensions into `extensions.json`; it does not own this issue's narrower behavior of force-installing repository-bundled workspace resource extensions.
