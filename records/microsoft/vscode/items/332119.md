# Issue #332119 — Rendered Markdown diff in Source Control turns tables into raw pipes and dashes

[https://github.com/microsoft/vscode/issues/332119](https://github.com/microsoft/vscode/issues/332119)

## Summary

Real bug confirmed in source: the SCM diff preview injects raw `<span data-diff-...>` marker tags into markdown text before rendering, which breaks table row parsing when a whole row (or many cells) is marked changed. An open PR already targets this exact issue, so it should stay open pending that PR's review/merge rather than being closed or auto-fixed here.

## Change summary

When a Markdown table's column width changes and every row gets rewritten, the modified side of the rendered SCM diff preview shows raw pipes/dashes instead of a table.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/332298, which already proposes preserving table delimiter rows when injecting diff markers in extensions/markdown-language-features/src/preview/documentRenderer.ts; no separate fix effort is needed while that PR is open.

## Evidence

- **traced defect:** extensions/markdown-language-features/src/preview/documentRenderer.ts:283 injectInnerChangeMarkers() splices raw `<span data-diff-start=...>`/`<span data-diff-end=...>` HTML into markdown source before it's handed to the markdown-it engine; when a table row's cells change (e.g. after a formatter re-aligns pipes on a width change), every cell in that row gets wrapped, which plausibly breaks markdown-it's table-row/delimiter-row detection for that line.
- **linked open PR:** https://github.com/microsoft/vscode/pull/332298 — 'fix(markdown): preserve table delimiter rows when injecting diff markers (closes #332119)', confirmed open via GitHub API (state: open), authored by an external contributor, explicitly closes this issue.
