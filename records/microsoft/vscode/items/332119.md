# Issue #332119 — Rendered Markdown diff in Source Control turns tables into raw pipes and dashes

[https://github.com/microsoft/vscode/issues/332119](https://github.com/microsoft/vscode/issues/332119)

## Summary

Traced this to a real defect in the new Markdown preview inline-diff highlighting: `injectInnerChangeMarkers` in documentRenderer.ts splices raw `<span data-diff-*>` markers straight into the Markdown source line-by-line, and when a table's header-separator row (or another syntax-sensitive line) gets a marker, markdown-it's GFM table rule fails to match and the whole table falls back to raw pipes/dashes text — matching the reported symptom exactly.

## Change summary

In the SCM 'Reopen Editor With… Markdown Preview' inline diff, editing one table cell (which reflows every row) causes the modified side to render the whole table as raw pipe/dash text instead of a table.

## Best solution

In extensions/markdown-language-features/src/preview/documentRenderer.ts, make `injectInnerChangeMarkers`/`renderBody` syntax-aware: skip or defer marker injection for lines that are part of a table (especially the delimiter row) or other constructs whose exact line content markdown-it depends on, so the underlying block still parses correctly even when it's flagged as changed. The related issue https://github.com/microsoft/vscode/issues/332107 (Mermaid code blocks) looks like the same root cause hitting a different construct — worth fixing together.
