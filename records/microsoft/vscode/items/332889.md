# Issue #332889 — Support Ctrl+scroll wheel zoom for text size in the Markdown WYSIWYG editor

[https://github.com/microsoft/vscode/issues/332889](https://github.com/microsoft/vscode/issues/332889)

## Summary

Keep open: the built-in Markdown Editor has no identified text-only wheel-zoom capability. The related preview zoom and editor font-configuration reports cover different observable behavior, so neither is a verified duplicate canonical.

## Change summary

Support Ctrl+mouse-wheel adjustment of text size in the built-in Markdown WYSIWYG editor without resizing the surrounding workbench.

## Best solution

Provide editor-local text zoom in the Markdown custom editor, preserving document content and ordinary scrolling. Settle its relationship to editor.mouseWheelZoom and its persistence semantics before implementation; coordinate with the separate font-configuration request.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/markdown-editor-src/editor.ts`, `extensions/markdown-language-features/markdown-editor-src/markdownEditor.css`, `extensions/markdown-language-features/src/preview/markdownEditorProvider.ts`, `extensions/markdown-language-features/src/preview/markdownEditorProtocol.ts`, `extensions/markdown-language-features/package.json`
- **Validation:** In the built-in Markdown Editor, Ctrl+wheel in both directions must change rendered text size without changing window zoom or Markdown source. Verify ordinary wheel scrolling, selection and editing, independently opened documents, and reload behavior against the agreed persistence contract; verify the agreed disabled-setting behavior. Establish executable wheel-event regression coverage during planning.
- **Behavior:**

  > Users need to enlarge or reduce text quickly inside the built-in Markdown WYSIWYG editor using Ctrl+mouse wheel, independently of workbench zoom. The gesture must not modify the Markdown document, and unmodified wheel scrolling must remain unchanged. Acceptance includes both zoom directions, continued selection and editing, and the agreed behavior for independent documents and reloads. This request is for an interactive gesture, not merely a configurable initial font size.
- **Trace:**

  > MarkdownEditorProvider in extensions/markdown-language-features/src/preview/markdownEditorProvider.ts builds the vscode.markdown.editor webview and currently supplies only highlightActiveBlock as editor configuration. The protocol in src/preview/markdownEditorProtocol.ts mirrors that configuration, and markdown-editor-src/editor.ts constructs an EditorView from @vscode/markdown-editor with no wheel-zoom handling identified in the integration. PersistedViewState currently records scroll position and selection, not text zoom. The imported library's own event handling and sizing behavior were not established, so planning should trace that boundary before choosing an implementation. Preserve source synchronization, ordinary scrolling, and existing embedded-editor interactions; do not conflate this feature with preview zoom at https://github.com/microsoft/vscode/issues/332888 or initial font configuration at https://github.com/microsoft/vscode/issues/332732.
- **Open decisions:**
  - Should WYSIWYG Ctrl+wheel zoom follow editor.mouseWheelZoom, be enabled independently by default, or have a dedicated opt-in?
  - Should the zoom adjustment remain local to the current editor view, persist per document across reloads, or be shared across Markdown Editor views?
