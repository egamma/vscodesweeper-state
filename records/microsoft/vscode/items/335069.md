# Issue #335069 — First agent handoff blocked by process-wide message limit

[https://github.com/microsoft/vscode/issues/335069](https://github.com/microsoft/vscode/issues/335069)

## Summary

Traced this in the Agent Host source: `sentMessageCount`/`maxSentMessages` in sessionServerTools.ts is a process-wide, never-reset counter capping `send_message` at 50 for the whole lifetime of the (long-lived, multi-session) Agent Host process, so unrelated legitimate handoffs across many sessions can exhaust it, not just a single runaway fan-out — and the thrown error gives the model no usage/recovery detail. That matches the report, but the right fix (per-session scoping vs. a reset policy vs. a friendlier error) is a design call, so this stays open for routing rather than closing.

## Change summary

A completed task session's first coordinator handoff (`send_message`) fails because the agent host process had already exhausted a shared, process-wide cap of 50 sent messages, with an opaque error.

## Best solution

Have the Agent Host / session-tools owners (src/vs/platform/agentHost/node/shared/sessionServerTools.ts) decide whether `maxSentMessages` should be scoped per-session/per-turn instead of process-wide, whether it should ever reset, and enrich the thrown error with current usage and a recovery path; today none of that is tested (no coverage for this limit in sessionServerTools.test.ts).
