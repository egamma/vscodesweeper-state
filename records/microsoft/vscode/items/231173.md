# Issue #231173 — [BUG] [1.94 Regression] VS Code uses the wrong, deprecated file/folder picker on Gnome.

[https://github.com/microsoft/vscode/issues/231173](https://github.com/microsoft/vscode/issues/231173)

## Summary

Keep open: current VS Code still requires FileChooser portal version 4, so Electron's upstream restoration of version-3 support does not resolve this report for older portal installations. This issue remains the established tracker for the native-picker regression.

## Change summary

Restore the GNOME-native file/folder chooser instead of falling back to the older GTK chooser after the VS Code 1.94 update.

## Best solution

Retain this tracker until native portal selection and defaultPath support work together on the affected GNOME configurations. Evaluate Electron and desktop-portal compatibility alongside VS Code's explicit version-4 requirement, without reintroducing the initial-folder regression.

## Evidence

- **Reporter trigger and maintainer diagnosis:** https://github.com/microsoft/vscode/issues/231173 reports Open Folder using the GTK fallback on GNOME 47 after upgrading to VS Code 1.94.2. The supplied October 14 maintainer comment attributes this to the raised portal-version requirement needed for defaultPath and references https://github.com/microsoft/vscode/issues/213780 and https://github.com/electron/electron/issues/43819.
- **Current adoption boundary:** src/mainImpl.ts:388-391 explicitly calls app.commandLine.appendSwitch('xdg-portal-required-version', '4'). Its comments acknowledge Electron's default of 3 and deliberately retain 4 for current_folder support. src/vs/platform/dialogs/electron-main/dialogMainService.ts passes defaultPath and openDirectory through doPick to electron.dialog.showOpenDialog; it does not independently select Nautilus.
- **Upstream change does not establish resolution here:** Merged https://github.com/electron/electron/pull/44426 restores the default requirement to 3 and introduces the override flag. Its Chromium patch compares the advertised FileChooser version against that flag; its documentation states that insufficient versions fall back to GTK or KDE and that defaultPath needs portal version 4. VS Code explicitly selects 4, so the upstream revert is not a fixing commit for this application's affected path. https://github.com/electron/electron/issues/43819 was subsequently closed through https://github.com/electron/electron/pull/45193.
- **Canonical search and ownership:** Open-issue searches for portal/dialog and GNOME/picker found no verified older canonical owning this regression. Maintainers instead closed https://github.com/microsoft/vscode/issues/231855 and https://github.com/microsoft/vscode/issues/212171 as duplicates of this issue. https://github.com/microsoft/vscode/issues/252497 describes related version-gating behavior on COSMIC, but was created later and does not meet the re-review duplicate bar.
