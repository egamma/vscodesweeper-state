# Issue #329649 — send_message server tool does not block a chat from messaging itself (Codex + Claude)

[https://github.com/microsoft/vscode/issues/329649](https://github.com/microsoft/vscode/issues/329649)

## Summary

Team-authored, well-diagnosed bug confirmed on current main: the self-send guard in sessionServerTools.ts compares a chat URI to whatever the provider passes as `currentChannel`, and Codex/Claude pass session URIs (not chat URIs), so the string comparison never matches and the guard silently no-ops for them.

## Change summary

The send_message server tool's guard against a chat messaging itself works for Copilot but silently does nothing for Codex and Claude, letting a chat start a new turn on itself.

## Best solution

Add the proposed `currentChatUri()` helper (mirroring `currentSessionUri()`) in sessionServerTools.ts so `applySendMessageTool`'s guard at line 743 compares like with like across all three providers, following the same normalization pattern `delete_session` already uses successfully at line 974; then un-skip `supportsSelfSendRejection` in serverToolsSuite.ts and remove the two KNOWN_ISSUES.md entries.
