# Issue #329649 — send_message server tool does not block a chat from messaging itself (Codex + Claude)

[https://github.com/microsoft/vscode/issues/329649](https://github.com/microsoft/vscode/issues/329649)

## Summary

Confirmed still-open on main: the self-send guard at sessionServerTools.ts's applySendMessageTool does a plain string comparison (`chat.toString() === URI.parse(currentChannel).toString()`), which only matches when the provider already hands back a chat URI (Copilot); Codex and Claude hand back session URIs so the check never fires. Team-authored with a real release milestone (1.136.0), so it's protected from any close regardless — this is purely a keep-open with a clear fix path already laid out in the issue body.

## Change summary

The send_message tool's self-target guard silently fails to block a chat from messaging itself when running under Codex or Claude, letting a chat trigger a new turn on itself repeatedly.

## Best solution

Add the proposed `currentChatUri`-normalizing guard (or equivalent) in applySendMessageTool at sessionServerTools.ts so the comparison normalizes the provider-supplied channel to a chat URI before comparing, matching the existing correct pattern in applyDeleteSessionTool's currentSessionUri usage; then un-skip `supportsSelfSendRejection` for Codex and Claude in serverToolsSuite.ts and extend the unit test at sessionServerTools.test.ts:441 to cover non-chat-shaped channels.
