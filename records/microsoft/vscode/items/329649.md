# Issue #329649 — send_message server tool does not block a chat from messaging itself (Codex + Claude)

[https://github.com/microsoft/vscode/issues/329649](https://github.com/microsoft/vscode/issues/329649)

## Summary

Confirmed real and unfixed on main: the self-send guard at sessionServerTools.ts:743 does a plain string comparison between a chat URI and whatever the provider passes as `currentChannel` — Codex and Claude pass session URIs (`codex:/x`, `claude:/x`), not chat URIs, so the comparison never matches and the guard is a no-op for them. Team-authored with milestone 1.134.0 assigned, so this stays open regardless (no fix commit exists yet).

## Change summary

The send_message tool's self-messaging guard silently fails to block a chat from messaging itself when running under Codex or Claude (only works for Copilot).

## Best solution

Implement the `currentChatUri` normalization helper proposed in the issue body (mirroring `currentSessionUri` at sessionServerTools.ts:175) and use it at the guard on line 743 so the comparison always compares chat URIs regardless of provider; extend the unit test at test/node/sessionServerTools.test.ts:441 to cover Codex/Claude-shaped channels, and flip `supportsSelfSendRejection` in serverToolsSuite.ts:79 to true for all providers.
