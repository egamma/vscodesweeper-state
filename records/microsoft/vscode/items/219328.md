# Issue #219328 — Recognize paths with ~ on Windows

[https://github.com/microsoft/vscode/issues/219328](https://github.com/microsoft/vscode/issues/219328)

## Summary

Windows CLI path handling still does not expand a leading tilde. Keep this accepted Backlog request open: an older maintainer decision declined the same capability, but it predates this issue's acceptance and does not justify overriding that triage.

## Change summary

Recognize a leading tilde as the user's home directory when opening Windows paths through the code CLI.

## Best solution

Have the CLI owner reconsider the earlier shell-owned expansion decision against PowerShell's reported completion behavior. If support is accepted, define leading-tilde handling while preserving access to literal tilde-named paths and existing relative-path semantics.

## Evidence

- **Current CLI behavior:** In src/vs/code/electron-main/main.ts, CodeMain.doValidatePaths calls preparePath, which resolves Windows arguments against cwd without home-directory expansion. Consequently, a literal ~\.ssh argument remains a path beneath the current directory rather than the user's home.
- **Existing-capability check:** resources/win32/bin/code.cmd forwards arguments through %*. src/vs/base/common/extpath.ts sanitizeFilePath makes paths absolute and normalizes separators but does not expand tilde. Inspection of the CLI and argument parser found no tilde-expansion option covering the request; supplying an absolute home path remains a workaround, not the requested capability.
- **Earlier maintainer decision:** https://github.com/microsoft/vscode/issues/146116 describes the same Windows CLI symptom. In https://github.com/microsoft/vscode/issues/146116#issuecomment-1080589513, a maintainer stated that expansion belongs to the shell and there were no plans to add PowerShell support. That issue is closed, so it cannot serve as an open duplicate canonical, and its decision predates this report's Backlog acceptance.
