# Issue #334251 — Agent sessions: memory tool not provisioned — agent sessions have no access to the memory tool available in editor chat (surface toolset parity gap)

[https://github.com/microsoft/vscode/issues/334251](https://github.com/microsoft/vscode/issues/334251)

## Summary

Well-documented report of a plausible tool-parity gap between editor chat and Copilot agent sessions (memory tool missing), but it's brand new (0 days), has no maintainer input, and the actual provisioning logic spans two very different code paths (extension-host `ToolRegistry`/`MemoryTool` for editor chat vs. the agent-host's Copilot SDK session runtime) that I can't conclusively confirm is unintentional rather than a known architectural limitation.

## Change summary

Agent sessions run a smaller fixed built-in toolset than editor chat and never provision the `memory` tool, so agent sessions can't read/write the same `/memories/` store as editor chat.

## Best solution

A maintainer familiar with the agent-host/Copilot session tool-provisioning pipeline (src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts and copilotSessionLauncher.ts, vs. extensions/copilot's ToolRegistry-based MemoryTool in src/extension/tools/node/memoryTool.tsx) should confirm whether the omission is deliberate (fixed SDK-side core toolset) or an oversight, and either document the parity gap or wire the memory tool into the agent session's client tool set.
