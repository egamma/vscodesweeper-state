## Summary

Keep open: the supplied selection-review steps and logs suffice to retest, but the size-dependent failure is not confirmed on current main. Current code has two review backends, and a pending replacement changes the implementation context without establishing that this report is fixed.

## Change summary

Reviewing several hundred selected lines fails after a long wait and exposes a raw connection-closed error instead of completing or explaining an actual review limit.

## Best solution

Preserve this acceptance case through the replacement discussed in https://github.com/microsoft/vscode/issues/321544.

## Evidence

- **Concrete reproduction steps:** https://github.com/microsoft/vscode/issues/289001 specifies selecting several hundred lines, invoking the blue-lightbulb Review action, and observing a failed review after more than a minute on VS Code 1.108.1/macOS arm64. There are no independent confirmations; the logs show request failure, not a VS Code or extension-host crash.
- **Transport evidence does not prove a size limit:** The supplied log records net::ERR_CONNECTION_CLOSED and an HTTP/2 session draining because the connection closed. Other Copilot requests succeeding does not exclude failure of this connection, and the log contains no payload-limit response.
- **Current error propagation:** extensions/copilot/src/extension/review/node/doReview.ts: ReviewSession.performReview chooses githubReview or the legacy FeedbackGenerator based on isCopilotCodeReviewEnabled. Its catch returns err.message, and handleReviewResult displays that reason as the failure detail; raw transport errors can therefore still reach the reporter.
- **Current payload and limit handling:** extensions/copilot/src/extension/review/node/githubReviewAgent.ts: collectSelectionChanges retains the entire document, while fetchComments submits file contents plus selected line regions. The legacy extensions/copilot/src/extension/prompt/node/feedbackGenerator.ts already has batching and a 'too much text to review' response when more than ten prompts are generated. Neither observation establishes why this reporter's request failed.
- **Canonical search:** Searches for review connection failures, large inputs, timeouts, and selected-code review found https://github.com/microsoft/vscode/issues/253136 and https://github.com/microsoft/vscode/issues/253137. Their bodies describe general chat-request failures and model availability, respectively; neither establishes ownership of this selection-size-dependent review failure.
- **Related replacement work, not a duplicate or landed fix:** https://github.com/microsoft/vscode/issues/321544 is open and proposes replacing non-agentic review in SCM and code-selection surfaces with SDK-based /review. It does not diagnose this failure or establish a fix. The current extensions/copilot/package.json still registers github.copilot.chat.review.
