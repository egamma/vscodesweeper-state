# Issue #338110 — Extension host did not start (debugBrk: true) on macOS — js-debug polls ::1 while the extension host listens on 127.0.0.1

[https://github.com/microsoft/vscode/issues/338110](https://github.com/microsoft/vscode/issues/338110)

## Summary

Real, well-diagnosed bug, but the fix lives in the js-debug extension's polling logic, not in this repo — js-debug is a separately-maintained, VS Code-team-owned built-in extension (microsoft/vscode-js-debug), so this should be routed/moved there rather than closed as caused-by-extension.

## Change summary

On macOS with IPv6-first `localhost` resolution, js-debug polls `::1:<port>` for the extension host's inspector while the host only listens on `127.0.0.1:<port>`, so attach never succeeds and the dev extension host hangs paused forever.

## Best solution

Fix belongs in microsoft/vscode-js-debug: make the extension-host inspector attach/poll path fall back across address families (or resolve `localhost` IPv4-first / connect directly to 127.0.0.1) instead of only trying `::1`. This VS Code repo's side (binding `--inspect-brk` to `127.0.0.1`) is reasonable and doesn't need to change.
