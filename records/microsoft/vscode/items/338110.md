# Issue #338110 — Extension host did not start (debugBrk: true) on macOS — js-debug polls ::1 while the extension host listens on 127.0.0.1

[https://github.com/microsoft/vscode/issues/338110](https://github.com/microsoft/vscode/issues/338110)

## Summary

Confirmed from source: VS Code core already spawns the debuggee extension host with `--inspect-brk=127.0.0.1:<port>` (localProcessExtensionHost.ts), so the defect is on the other side of the connection — the bundled JavaScript debugger (ms-vscode.js-debug) polling `localhost` without an IPv4 fallback. That extension ships from its own repo, so this should move there rather than be worked in vscode core.

## Change summary

On systems that resolve `localhost` to `::1` first (macOS default, some Windows configs), F5 extension debugging hangs forever because js-debug's inspector-polling only tries `::1` and never falls back to the IPv4 address the extension host actually listens on.

## Best solution

Fix belongs in microsoft/vscode-js-debug: either poll `127.0.0.1` explicitly (matching what core binds to) or add an address-family fallback in the inspector attach/poll path (ms-vscode.js-debug/src/extension.js). No core VS Code change is indicated since the extension host already binds the debug port to a concrete IPv4 address.
