# Issue #343589 — MCP registry_only: local servers randomly stay disabled after window load because the registry check runs before installed servers load

[https://github.com/microsoft/vscode/issues/343589](https://github.com/microsoft/vscode/issues/343589)

## Summary

The reported startup race remains possible in current main: an obsolete local scan can trigger registry synchronization against an empty list, while the winning scan never schedules verification. Keep this open as a bounded MCP initialization bug.

## Change summary

Ensure registry-listed local MCP servers are verified after startup scans complete so registry_only access does not leave them incorrectly disabled.

## Best solution

Make initial registry verification reliable when local scans overlap, without requiring an mcp.json edit. Preserve registry membership checks, HTTP URL matching, and protection against stale profile or registry results.
