# Issue #102236 — Add support for SteppingGranularity in the UI

[https://github.com/microsoft/vscode/issues/102236](https://github.com/microsoft/vscode/issues/102236)

## Summary

This remains a valid, well-supported debug feature request: current main automatically requests instruction-level stepping when the Disassembly View has focus, but provides no general UI for choosing statement, line, or instruction granularity. Its Backlog milestone and 92 community upvotes support keeping it open for design.

## Change summary

Expose DAP stepping granularity in the debug UI so users can choose statement-, line-, or instruction-level stepping.

## Best solution

Provide a user-visible granularity selection for sessions advertising `supportsSteppingGranularity`, pass the selected value through all applicable stepping commands, and define how that selection interacts with the existing automatic instruction stepping in the Disassembly View.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugCommands.ts`, `src/vs/workbench/contrib/debug/browser/debugToolBar.ts`, `src/vs/workbench/contrib/debug/browser/debugService.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`
- **Validation:** Add focused debug command/UI tests covering a session with `supportsSteppingGranularity`: select each supported granularity and assert that Step Over, Step Into, Step Out, and Step Back send the selected DAP value; run them with `scripts/test.sh --grep "stepping granularity"`.
- **Behavior:**

  > When the active debug adapter advertises `supportsSteppingGranularity`, users can choose among statement, line, and instruction stepping. Step Over, Step Into, Step Out, and Step Back send the effective selection in their DAP requests. Sessions without the capability retain their current stepping UI and request behavior. The existing Disassembly View behavior must remain coherent with an explicitly selected granularity.
- **Trace:**

  > The DAP types and request plumbing already exist: `DebugProtocol.SteppingGranularity` and `supportsSteppingGranularity` are declared in src/vs/workbench/contrib/debug/common/debugProtocol.d.ts, and DebugSession/IThread forward optional granularity values. In src/vs/workbench/contrib/debug/browser/debugCommands.ts, the four stepping commands currently pass `'instruction'` only when `CONTEXT_DISASSEMBLY_VIEW_FOCUS` is true and otherwise omit the value. The toolbar in src/vs/workbench/contrib/debug/browser/debugToolBar.ts exposes only the ordinary stepping actions, while no context key or UI state exposes the adapter capability or selected granularity. Commit https://github.com/microsoft/vscode/commit/cc5619492f2df929be09125f30491f73893775d8 is the origin of the existing focus-driven instruction behavior. Keep the DAP contract and debugger-adapter implementations unchanged; the uncertainty begins at the user-facing selection and its precedence over view-driven behavior.
- **Open decisions:**
  - Should granularity be selected through a persistent setting, per-debug-session state, or a toolbar/command control whose state resets with the session?
  - When the Disassembly View has focus, should it always force instruction stepping, temporarily override the user's selection, or merely change the selection to instruction?
  - Should the UI expose all three protocol values whenever the capability is advertised, or allow debug adapters or language integrations to constrain the choices and default?

## Evidence

- **current source:** src/vs/workbench/contrib/debug/browser/debugCommands.ts passes `'instruction'` to Step Over, Step Into, Step Out, and Step Back only when `CONTEXT_DISASSEMBLY_VIEW_FOCUS` is true; outside that view the requests omit granularity and therefore default to `statement`.
- **protocol support:** src/vs/workbench/contrib/debug/common/debugProtocol.d.ts defines `SteppingGranularity` as `statement | line | instruction` and exposes `supportsSteppingGranularity`, while src/vs/workbench/contrib/debug/browser/debugSession.ts already forwards an optional granularity through each stepping request.
