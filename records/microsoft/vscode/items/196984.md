# Issue #196984 — Editor - use editor space when vertical scrollbar is hidden

[https://github.com/microsoft/vscode/issues/196984](https://github.com/microsoft/vscode/issues/196984)

## Summary

The requested layout improvement remains missing: explicitly hiding the vertical scrollbar still reserves its configured width when calculating wrapping. Keep this team-authored request open under editor-core; no qualifying fix or canonical duplicate was established.

## Change summary

Allow wrapped text to use the space otherwise reserved for an explicitly hidden vertical scrollbar.

## Best solution

Make editor wrapping account for explicitly hidden scrollbar space without changing automatic-scrollbar layout stability. The editor-core owner should settle how this interacts with the overview ruler, which currently shares the scrollbar width.

- **Behavior:**

  > When the vertical scrollbar is explicitly hidden, viewport-wrapped text should use the available editor space rather than wrap early solely because of an invisible scrollbar's configured width. Verify this with repeated short tokens while narrowing the editor. Visible and automatic scrollbar modes should preserve their existing wrapping behavior. The acceptance contract must also specify whether the overview ruler retains a separate reserved area.
- **Trace:**

  > EditorLayoutInfoComputer.computeLayout in src/vs/editor/common/config/editorOptions.ts obtains verticalScrollbarWidth from verticalScrollbarSize regardless of scrollbar.vertical. It passes that width into _computeMinimapLayout and subtracts it from contentWidth before computing viewportColumn and wrappingColumn. The returned overviewRuler.width also uses the same value, so scrollbar visibility, text space, and overview-ruler space are currently coupled. EditorScrollbar validates visibility and size independently; zero size offers a workaround but does not implement visibility-aware reclamation. The existing suite in src/vs/editor/test/browser/config/editorLayoutProvider.test.ts constructs scrollbar options with default vertical visibility, so hidden-mode behavior is not represented by that helper. Preserve automatic-scrollbar layout stability and unrelated wrapping modes; uncertainty starts at the intended overview-ruler allocation when the scrollbar is explicitly hidden.
- **Open decisions:**
  - When the vertical scrollbar is explicitly hidden, should the overview ruler retain separately reserved space, or should text reclaim that area as well?
