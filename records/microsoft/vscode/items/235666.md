# Issue #235666 — (Web, Safari) Copying and pasting line with colon and no leading space results in URL encoding of pasted text

[https://github.com/microsoft/vscode/issues/235666](https://github.com/microsoft/vscode/issues/235666)

## Summary

Still reproduces on main: Safari iPadOS synthesizes a `text/uri-list` clipboard entry from colon-prefixed text, causing the paste to use the URL-encoded form. An open PR (#313020) addresses this but has not merged.

## Change summary

On iPadOS Safari, copying text like `foo: bar` and pasting within VS Code Web results in `foo:%20bar` because Safari synthesizes a spurious `text/uri-list` clipboard entry.

## Best solution

Land or iterate on https://github.com/microsoft/vscode/pull/313020, which filters spurious uri-list entries in `extractUriList` in `src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts`. The fix is small and well-scoped.

## Evidence

- **bug path on main:** In `src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts`, `DefaultTextPasteOrDropEditProvider` suppresses itself when `dataTransfer.has(Mimes.uriList)` (line 87), then `PathProvider` runs `extractUriList` which `URI.parse`s the Safari-synthesized entry `foo:%20bar` and pastes the encoded form. No guard against spurious uri-list entries exists on current main.
- **open fix PR:** https://github.com/microsoft/vscode/pull/313020 — 'Drop spurious uri-list entries that are encoded plain text' — is open, targets this exact issue, and references `Fixes #235666`. Not yet merged.
- **maintainer confirmation:** Comment by @mjbvz (CONTRIBUTOR) confirmed the copy is the source and pointed to the copy/paste controller as the starting point; workaround is `editor.pasteAs.enabled: false`.
- **related external report:** Comment #5 links https://github.com/coder/code-server/issues/7116, the same root cause in code-server.
