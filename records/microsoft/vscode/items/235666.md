The reporter also reproduced in a clean private session. mjbvz confirmed corrupted clipboard content and identified `editor.pasteAs.enabled: false` as a workaround; macOS non-reproduction does not refute the iPadOS report.
- **Current provider behavior:** In src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts, DefaultTextPasteOrDropEditProvider.getEdit suppresses plain-text edits whenever Mimes.uriList exists. extractUriList accepts parseable URI entries without comparing them with text/plain, and PathProvider.getEdit inserts originalText for non-file schemes. Given the reported encoded URI-list payload, this path preserves `foo:%20bar` rather than the literal plain text.
- **Workaround matches controller boundary:** src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts gates normal paste-provider handling on isPasteAsEnabled(), consistent with the workaround reported in the discussion. Disabling enhanced paste is a workaround, not resolution of the default behavior.
