# Issue #324097 — minimum release age should not show badging for deferred updates

[https://github.com/microsoft/vscode/issues/324097](https://github.com/microsoft/vscode/issues/324097)

## Summary

A meaningful gap remains for manual updates: current main distinguishes deferred auto-updates, but disabling auto-update removes that indication and leaves the Update action able to install a young release immediately. The Backlog milestone and maintainer consolidation of https://github.com/microsoft/vscode/issues/324202 into this issue establish it as the accepted canonical for that broader UX.

## Change summary

Distinguish extension updates deferred by the configured release-age window from actionable updates, including when updates are installed manually.

## Best solution

Present releases inside the minimum-age window as deferred rather than ordinary actionable updates, with their eligibility time visible. Manual update behavior should consistently warn, block, or offer an explicit override according to a maintainer-chosen policy.

- **Behavior:**

  > An extension release still inside the configured minimum-age window must not appear indistinguishable from an update that is ready to install. The Extensions view should communicate that it is deferred and when it becomes eligible. Manual update behavior must follow the chosen warning, blocking, and override semantics, while releases older than the threshold retain existing behavior.
- **Trace:**

  > Current main calculates remaining release age in `ExtensionsWorkbenchService.getAutoUpdateDelayRemaining`, but `isAutoUpdateDelayed` additionally requires `shouldAutoUpdateExtension`, so disabling auto-update suppresses the deferred state. `StatusUpdater` in src/vs/workbench/contrib/extensions/browser/extensionsViewlet.ts omits delayed auto-updates from the Activity Bar badge, and `ExtensionStatusAction` in extensionsActions.ts supplies an informational status only for that auto-update state. `UpdateAction.computeAndUpdateEnablement` enables any outdated installable extension, and `run` installs it without checking release age. `ExtensionHoverWidget` in extensionsWidgets.ts still describes every outdated extension as having a latest version without identifying its embargo state. Preserve trusted-publisher exemptions, consent warnings, ordinary mature updates, and automatic scheduling behavior. Related accepted scope: https://github.com/microsoft/vscode/issues/324202 and broader install-path work in https://github.com/microsoft/vscode/issues/321136.
- **Open decisions:**
  - During the release-age window, should a manual update be blocked, require a warning with explicit override, or remain immediately installable with informational labeling?
  - Should deferred releases remain visible in installed-extension results with a distinct non-actionable state, or be hidden until they become eligible?
