Cover grouping and checked-edit propagation in the BulkEditPreview suite, preserving existing category-selection behavior.
- **Behavior:**

  > The reporter wants a more detailed Rename Symbol preview tree and selectable blocks, referencing Visual Assist X. Existing VS Code already permits selection of files and individual edits, so the enhancement must add meaningful presentation or grouping beyond those controls. Acceptance should verify that the agreed blocks provide useful context and that selecting or deselecting them affects exactly their represented edits. Existing file and individual-edit selection must remain available.
- **Trace:**

  > RenameController in src/vs/editor/contrib/rename/browser/rename.ts forwards provider edits to the bulk-edit service with showPreview. In the shared preview, BulkEditDataSource.getChildren in bulkEditTree.ts constructs only category, file and text-edit nodes, with snippets taken from text-model ranges and tokens. BulkCategory.keyOf in bulkEditPreview.ts derives categories from WorkspaceEditMetadata.label; BulkEditPane.setInput enables alternative grouping only for multiple categories. This establishes the current presentation boundary, not a broken rename implementation. The uncertainty is which additional source blocks and context the requested tree should represent, and whether existing edit data suffices. Preserve provider rename results, individual-edit selection and existing metadata-category behavior. Related https://github.com/microsoft/vscode/issues/156886 is workflow context, not a verified duplicate canonical.
- **Open decisions:**
  - Which additional block hierarchy and context should the preview expose beyond today's file nodes and individual edit snippets?
  - Should the richer presentation be the default rename preview or an alternative grouping mode?
