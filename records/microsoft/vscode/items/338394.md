# Issue #338394 — agentHost: Avoid rescanning Codex sessions on existing rollout updates

[https://github.com/microsoft/vscode/issues/338394](https://github.com/microsoft/vscode/issues/338394)

## Summary

Real, well-diagnosed perf issue in CodexChatDiscovery's rescan-on-any-file-change behavior, and an open PR (https://github.com/microsoft/vscode/pull/338425) already implements the fix — keep the issue open until that PR merges rather than closing or treating it as unclaimed work.

## Change summary

CodexChatDiscovery rescans the entire external Codex session catalog (calling thread/list) on every rollout file append, not just on new-session creation, causing redundant work during long streaming turns.

## Best solution

Land https://github.com/microsoft/vscode/pull/338425 (or a revised version of it) that scopes catalog invalidation to ADDED rollout files / session_index.jsonl changes while treating UPDATED rollout appends as transcript-only invalidations, per the issue's suggested direction.
