# Issue #213110 — Project Tabs on Windows

[https://github.com/microsoft/vscode/issues/213110](https://github.com/microsoft/vscode/issues/213110)

## Summary

Keep this accepted, well-supported request open: current window-tab support remains macOS-only, and Windows still lacks the requested project-tab experience. The related reports do not establish an older canonical for this same Windows window-grouping request.

## Change summary

Allow multiple independent VS Code projects to appear as window-level tabs on Windows, comparable to macOS native tabs.

## Best solution

Provide an opt-in Windows project-tab experience that groups independent project workbenches without merging their workspace contexts. First establish the window-hosting architecture and feasibility; exposing the existing macOS commands on Windows would not deliver the feature.

## Plan brief

- **Likely files:** `src/vs/workbench/electron-browser/desktop.contribution.ts`, `src/vs/workbench/electron-browser/actions/windowActions.ts`, `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/platform/native/electron-main/nativeHostMainService.ts`
- **Validation:** On Windows, open two distinct projects and group them as window-level tabs; switching tabs must reveal each project's own editors, workspace settings, and terminals without combining the projects. Verify that ordinary separate-window operation and macOS native tabs remain unchanged.
- **Behavior:**

  > Windows users should be able to organize multiple independent projects into window-level tabs comparable to the macOS experience. Switching a project tab must retain that project's workbench context rather than combine projects into a multi-root workspace. Acceptance should exercise two distinct projects, switching between them, and preservation of their editors, settings, and terminals. Existing separate-window workflows and macOS native tabs must remain available.
- **Trace:**

  > desktop.contribution.ts limits both window.nativeTabs and its command registrations to macOS. windowActions.ts independently enforces that platform restriction in canRunNativeTabsHandler. windows.ts opts into macOS tabbing through BrowserWindow.tabbingIdentifier, while NativeHostMainService delegates navigation and merging to macOS first-responder actions. This establishes a missing Windows capability, not an incorrectly hidden cross-platform feature. The unresolved technical boundary is how independent project workbenches can be hosted together on Windows; the inspected path does not provide that architecture. Preserve project isolation and do not substitute editor-grid tabs from https://github.com/microsoft/vscode/issues/143024 or Explorer workspace grouping from https://github.com/microsoft/vscode/issues/43188.

## Evidence

- **Accepted community demand:** https://github.com/microsoft/vscode/issues/213110 has 95 body upvotes, a Backlog milestone, and a May 30, 2024 comment confirming promotion after sufficient community support. Subsequent comments explicitly request the macOS native-tab experience on Windows.
- **Existing capability does not cover Windows:** src/vs/workbench/electron-browser/desktop.contribution.ts registers window.nativeTabs with included: isMacintosh and registers workbench.action.newWindowTab and workbench.action.mergeAllWindowTabs only inside an isMacintosh branch. src/vs/workbench/electron-browser/actions/windowActions.ts additionally rejects non-macOS execution in canRunNativeTabsHandler.
- **Platform implementation boundary:** src/vs/platform/windows/electron-main/windows.ts sets BrowserWindow tabbingIdentifier only when isMacintosh && windowSettings?.nativeTabs === true. src/vs/platform/native/electron-main/nativeHostMainService.ts implements tab navigation and merging through macOS first-responder actions such as selectNextTab: and mergeAllWindows:, not a cross-platform project-tab host.
- **Available workaround is partial:** workbench.action.switchWindow in src/vs/workbench/electron-browser/actions/windowActions.ts selects and focuses an existing window through a quick picker; it does not group projects into tabs.
- **Same-request satellite already consolidated here:** https://github.com/microsoft/vscode/issues/236345 is closed. Its author explicitly closed it in favor of this issue: https://github.com/microsoft/vscode/issues/236345#issuecomment-2549675326. It is not a fixing PR or an open duplicate target.
