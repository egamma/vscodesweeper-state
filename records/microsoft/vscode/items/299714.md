# Issue #299714 — Feature Request: Auto-expand or remember toggle state of "> Other Models" in Chat Picker

[https://github.com/microsoft/vscode/issues/299714](https://github.com/microsoft/vscode/issues/299714)

## Summary

The request remains necessary on current main: both model-picker implementations explicitly collapse Other Models whenever promoted models exist. This issue is the maintainer-selected canonical for the request and should remain open for a persistence/default-behavior decision.

## Change summary

Let users keep Other Models expanded, either by remembering the toggle state or through a configurable default.

## Best solution

Preserve the user's preferred expansion behavior across picker openings while retaining the compact default for users who have not expressed a preference. Apply the behavior consistently to both the flat and experimental tabbed model pickers.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/modelPicker/modelPickerItems.test.ts`, `src/vs/platform/actionWidget/test/browser/tabbedActionListWidget.test.ts`
- **Validation:** Add targeted model-picker tests that open the picker, expand Other Models, close and reopen it, then assert the chosen persistence/default behavior in both flat and tabbed variants while confirming first-use behavior remains as designed.
- **Behavior:**

  > Users who regularly browse the full model catalog should not have to expand Other Models every time the picker opens. The chosen behavior must apply consistently to the flat and tabbed model pickers, preserve keyboard interaction, and leave filtering, pinning, and model selection unchanged. Acceptance should cover first open, user expansion or configured expansion, picker reopen, and window reload according to the selected persistence contract.
- **Trace:**

  > The flat path in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts constructs each action list with ModelPickerSection.Other in `collapsedByDefault`; `onDidToggleOtherModels` records telemetry only. TabbedModelPicker in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts independently places OTHER_MODELS_SECTION in `collapsedByDefault` whenever `hasPromotedModels(sections)` is true. ActionListWidget owns only the lifetime of one popup's `_collapsedSections`, so reopening reconstructs the collapsed state. Pinning is an existing partial workaround but does not expose the complete list. The boundary is model-picker expansion preference: do not alter promotion, recent-model ordering, pinning, search, or provider grouping. Related context is https://github.com/microsoft/vscode/issues/299620, https://github.com/microsoft/vscode/issues/299909, and the newer overlapping request https://github.com/microsoft/vscode/issues/322935.
- **Open decisions:**
  - Should the product remember the user's last expanded/collapsed choice, expose an explicit expand-by-default setting, or support both contracts?
  - If the choice is remembered, should it persist globally across windows and profiles, per profile, or only for the current window/session?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts initializes the flat picker with `collapsedByDefault: new Set([ModelPickerSection.Other])` on every opening; its toggle callback records telemetry but stores no preference.
- **tabbed picker:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts similarly supplies `collapsedByDefault: hasPromotedModels(sections) ? new Set([OTHER_MODELS_SECTION]) : undefined`, so the experimental picker also forgets expansion.
- **canonical ownership:** A maintainer explicitly closed https://github.com/microsoft/vscode/issues/299620 and https://github.com/microsoft/vscode/issues/299909 as duplicates of this issue; those reports independently describe the extra interaction and desire to see the full model list.
- **existing capability gap:** Current source supports pinning selected models through `ILanguageModelsService.pinModel`, but pinning only promotes chosen models and does not preserve access to or visibility of the complete Other Models list.
- **related request:** https://github.com/microsoft/vscode/issues/322935 repeats the expand-by-default request but was created after this re-reviewed issue, so it cannot replace this issue as the canonical.
