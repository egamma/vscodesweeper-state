# Issue #330214 — Comment toggle corrupts CSS containing commented blocks

[https://github.com/microsoft/vscode/issues/330214](https://github.com/microsoft/vscode/issues/330214)

## Summary

Traced this to the block-comment fallback path in the comment-toggle command: it only special-cases a selection that is entirely wrapped by one outer block comment, and otherwise wraps the whole selection with a fresh /* */ pair without checking for comment markers already inside it. CSS block comments don't nest, so the result is invalid syntax exactly as reported. This is real and still open on main.

## Change summary

Toggling line comment (Cmd+/) on a CSS selection that already contains block comments wraps/unwraps naively and produces invalid, non-nesting /* */ syntax.

## Best solution

In src/vs/editor/contrib/comment/browser/lineCommentCommand.ts (_executeBlockComment / _attemptRemoveBlockComment) and blockCommentCommand.ts, detect pre-existing block-comment tokens inside the selection before wrapping or unwrapping — either refuse/no-op when the selection contains internal unmatched comment markers, or wrap only the truly-uncommented spans. This is a non-trivial correctness fix in the block-comment fallback used by any language lacking a line-comment token (CSS, block-comment-only languages), not a one-line guard.
