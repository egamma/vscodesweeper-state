# Issue #330214 — Comment toggle corrupts CSS containing commented blocks

[https://github.com/microsoft/vscode/issues/330214](https://github.com/microsoft/vscode/issues/330214)

## Summary

Traced this in the source: CSS has no line-comment token, so Cmd+/ falls back to LineCommentCommand._executeBlockComment, which naively wraps the whole selection in one block comment (or strips a single outer one) without checking whether the selection already contains inner /* */ pairs — since CSS has no nested-comment support, the inner closing */ terminates the wrapper comment early and leaves stray tokens, producing invalid CSS exactly as reported.

## Change summary

Toggling line comment (Cmd+/) on a CSS selection that already contains commented block(s) mixed with uncommented code produces syntactically broken CSS instead of a clean toggle.

## Best solution

In src/vs/editor/contrib/comment/browser/lineCommentCommand.ts (_executeBlockComment / _attemptRemoveBlockComment), detect pre-existing block-comment tokens inside the selection before blindly wrapping, and either segment the toggle or decline gracefully instead of emitting invalid CSS; this likely needs an editor-comments owner's design call on the intended behavior for nested block-comment-only languages.

## Evidence

- **fallback path:** src/vs/editor/contrib/comment/browser/lineCommentCommand.ts getEditOperations() calls _executeBlockComment() whenever _gatherPreflightData() reports `supported: false`, which is the case for CSS since its language configuration defines only blockComment tokens, no lineComment.
- **naive wrap:** _executeBlockComment() only tries `_attemptRemoveBlockComment` (a single outer /* */ match) and otherwise calls `BlockCommentCommand._createAddBlockCommentOperations` over the *entire* selection range with no scan for embedded start/end tokens, so a selection already containing `/*...*/` blocks gets a second outer wrap that closes prematurely at the first inner `*/`.
- **repro steps:** Reporter's two repro cases (mixed commented/uncommented CSS, Cmd+/ on full selection) both match this code path and produce mismatched comment delimiters, consistent with the reported syntax errors.
