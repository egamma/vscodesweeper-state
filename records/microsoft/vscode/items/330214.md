## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/133843 is open and was created on 2021-09-27, before this report. Its body explicitly demonstrates Toggle Line Comment producing invalid CSS when the selection intersects an existing comment; it also requests safe per-line handling.
- **Matching requested behavior:** https://github.com/microsoft/vscode/issues/133843#issuecomment-928210381 explicitly requests commenting around existing comments, partial uncommenting, and reversible escaping using /*!* ... *!*/, matching this report's expected output. A maintainer acknowledged that clarification at https://github.com/microsoft/vscode/issues/133843#issuecomment-928218023.
- **Current-source reproduction:** extensions/css/language-configuration.json declares only block-comment tokens. CMD+/ invokes editor.action.commentLine in src/vs/editor/contrib/comment/browser/comment.ts, which reaches LineCommentCommand._executeBlockComment. For the supplied multiline-comment sample, _attemptRemoveBlockComment cannot find an opening delimiter on the first or last selected line, so _createAddBlockCommentOperations wraps the entire selection without escaping its existing */; the inner terminator closes the new comment prematurely.
- **Second supplied failure:** For the supplied individually commented lines, LineCommentCommand._attemptRemoveBlockComment finds the final line's closing token, then finds that same line's opening token and removes only that pair. This leaves the final } uncommented, matching the reported syntax error. https://github.com/microsoft/vscode/issues/184666 is another verified older open report of delimiter removal corrupting selected CSS comments.
