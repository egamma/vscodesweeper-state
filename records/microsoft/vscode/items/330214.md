# Issue #330214 — Comment toggle corrupts CSS containing commented blocks

[https://github.com/microsoft/vscode/issues/330214](https://github.com/microsoft/vscode/issues/330214)

## Summary

Real, traceable defect: toggling block comment on a CSS selection that already contains an internal `/*...*/` pair wraps the whole selection in a new outer `/* */` without checking for embedded comment tokens, and since CSS (unlike languages with `//`) has no nested-comment syntax, the result is invalid CSS.

## Change summary

Toggling comment (Cmd+/) on a CSS selection containing existing `/* */` blocks produces syntax-breaking, incorrectly nested comments instead of cleanly commenting/uncommenting.

## Best solution

In src/vs/editor/contrib/comment/browser/blockCommentCommand.ts, `_createOperationsForBlockComment` only inspects tokens right at the selection's start/end boundaries; it never scans the selection interior for existing `/*`/`*/` occurrences before deciding to add a wrapping comment. A maintainer needs to decide the intended behavior for CSS/LESS/SCSS (which have no line-comment token) when a selection contains already-commented sub-ranges — e.g. detect and skip/refuse rather than blindly wrap — since CSS itself doesn't support nested block comments, so no output can be both valid CSS and preserve the original comment nesting exactly as the reporter's proposed (non-standard) `/*!* ... *!*/` escaping.
