# Issue #310124 — Extension host proxy support does not cover http2.connect() paths; patched tls.connect still allows direct target DNS/connect instead of proxy tunnel

[https://github.com/microsoft/vscode/issues/310124](https://github.com/microsoft/vscode/issues/310124)

## Summary

Confirmed gap: the extension host proxy patching covers http, https, net, tls, and undici but has no interception for the http2 module. The reporter's analysis is accurate and the proposed fix follows the established pattern. Keeping open as a valid feature request.

## Change summary

Extension host proxy support does not intercept or patch Node.js http2.connect(), causing failures on proxy-mandatory networks for extensions using raw HTTP/2 or gRPC.

## Best solution

Add a createHttp2Patch function in @vscode/proxy-agent (following the established createHttpPatch/createNetPatch/createTlsPatch pattern) and wire it into proxyResolver.ts to intercept require('http2'). The reporter has already proposed a detailed implementation in the comments. The upstream @vscode/proxy-agent package needs the change first, then proxyResolver.ts adds the http2 module interception alongside the existing http/https/net/tls entries.
