# Issue #288860 — .copilotignore pattern **/copilot-instructions.md not working in multi-folder workspaces - All repository attachments sent despite ignore rules

[https://github.com/microsoft/vscode/issues/288860](https://github.com/microsoft/vscode/issues/288860)

## Summary

Keep open as a confirmed multi-root content-exclusion bug. Two independent commenters reproduced ignored paths remaining available in multi-folder workspaces, while current source has no multi-root regression coverage and leaves the original workspace-level metadata expectation unresolved.

## Change summary

Make `.copilotignore` exclusions work consistently in multi-folder workspaces and clarify whether they can suppress automatically attached repository metadata.

## Best solution

Ensure each workspace folder's `.copilotignore` is discovered and evaluated relative to that folder without leaking or dropping rules across roots. Separately decide whether repository metadata is outside file-exclusion semantics or needs its own opt-out; ignoring one file should not implicitly suppress an entire repository without an explicit contract.

- **Validation:** Add a multi-root regression test with two workspace folders and independent `.copilotignore` files, asserting excluded files are blocked only in their owning roots and ordinary files remain available; then reproduce the same layout in an Extension Host test or manual VS Code window.
- **Behavior:**

  > In a multi-folder workspace, a `.copilotignore` at a workspace-folder root must exclude matching files from Copilot exactly as it does when that folder is opened alone. Rules from one root must neither disappear nor affect unrelated roots. Acceptance includes separate roots with directory patterns such as `data/` and `out/`, plus a control file that remains available. Repository metadata behavior must follow the explicit product decision rather than being inferred from whether a repository contains an ignored file.
- **Trace:**

  > `BaseIgnoreService.init` in `extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts` iterates workspace-folder URIs and `addWorkspace` searches each root through `ISearchService.findFilesWithDefaultExcludes` using a `RelativePattern`. `IgnoreFile.isIgnored` in `extensions/copilot/src/platform/ignore/node/ignoreFile.ts` then selects a discovered ignore file and tests a path relative to its directory. Independent reports at https://github.com/microsoft/vscode/issues/288860 show the behavior diverging only after the same folder enters a multi-root workspace, but the unit suite models only one root and bypasses the real VS Code search implementation. First reproduce against current main to determine whether discovery, path normalization, or the caller that enforces `isCopilotIgnored` drops the rule. Keep repository-scoped metadata attachments distinct from file-content exclusion unless the maintainer explicitly chooses to couple them; do not broaden the fix to remote organization exclusions tracked by https://github.com/microsoft/vscode/issues/338368.
- **Open decisions:**
  - Should a `.copilotignore` located beside a `.code-workspace` file apply across its configured folders even when that directory is not itself a workspace folder?
  - Does excluding `copilot-instructions.md` exclude only that file's content, or should users also have an explicit way to suppress automatically attached repository metadata for the containing workspace folder?

## Evidence

- **confirmed reproduction:** The discussion at https://github.com/microsoft/vscode/issues/288860 contains independent reproductions: one shows `data/` and `out/` exclusions working for a single-folder window but failing when the same project is added to a multi-folder workspace; another confirms the behavior on VS Code 1.112.0 on macOS.
- **current discovery path:** `extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts` initializes by iterating `IWorkspaceService.getWorkspaceFolders()` and searching each folder root for `.copilotignore` with a `RelativePattern`. A `.copilotignore` beside a `.code-workspace` file but outside all configured folders is therefore not discovered.
- **current rule scoping:** `extensions/copilot/src/platform/ignore/node/ignoreFile.ts` evaluates a candidate relative to the directory containing each discovered ignore file. This should support per-folder rules, but the current tests do not exercise multiple workspace roots or VS Code's real `RelativePattern` search behavior.
- **missing regression coverage:** `extensions/copilot/src/platform/ignore/node/test/ignoreServiceImpl.spec.ts` uses one `/workspace` root throughout its local-ignore tests; it does not cover two workspace folders, independent ignore files, or an ignore file located relative to a `.code-workspace` file.
- **not a duplicate:** https://github.com/microsoft/vscode/issues/278829 is an older, open request to add general path-exclusion capability, not the same observable symptom of existing exclusions failing only in multi-folder workspaces. The closed https://github.com/microsoft/vscode/issues/260344 concerns making `.copilotignore` officially supported and explicitly points to this issue as separate work.
