# Issue #223750 — `GNOME_LIBSECRET` chosen but libsecret isn't available in a fresh Debian install

[https://github.com/microsoft/vscode/issues/223750](https://github.com/microsoft/vscode/issues/223750)

## Summary

Team-authored upstream bug: Chromium/Electron's `key_storage_linux.cc` selects `GNOME_LIBSECRET` based on desktop-environment detection without verifying that `libsecret` is actually installed. The backend selection logic lives entirely in Electron/Chromium, not in VS Code's TypeScript — VS Code only reads the result via `safeStorage.getSelectedStorageBackend()`. Keeping open for upstream tracking.

## Change summary

On fresh Debian GNOME installs without libsecret, Electron's OSCrypt backend detection incorrectly selects GNOME_LIBSECRET, causing credential storage failures.

## Best solution

The fix belongs in Chromium's `components/os_crypt/sync/key_storage_linux.cc` (or Electron's fork of it): the backend selection should verify that the libsecret library is loadable before choosing `GNOME_LIBSECRET`. VS Code could mitigate by detecting the mismatch via `safeStorage.isEncryptionAvailable()` and falling back to `basic_text` with a user notification, but the root fix is upstream.
