# Issue #168807 — Cell collapse doesn't persist between VSC sessions

[https://github.com/microsoft/vscode/issues/168807](https://github.com/microsoft/vscode/issues/168807)

## Summary

Still present on main: when the notebook view model is disposed before the final getEditorViewState() call during VS Code shutdown, an empty collapse state is returned and persisted, causing all cells to appear expanded on next session. A fix attempt (PR #282614) was closed without merging.

## Change summary

Notebook cell collapse (input/output) state is lost between VS Code sessions because the view model may be disposed before the final view-state save.

## Best solution

Cache the last valid editor view state before the view model is disposed, so that getEditorViewState() can return the cached state during shutdown. The fix belongs in src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts around the getEditorViewState() fallback path. The closed PR #282614 had the right approach but was never merged.
