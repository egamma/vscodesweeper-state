# Issue #337224 — Allow hiding bulk Keep/Undo controls in the editor overlay while preserving per-change review actions

[https://github.com/microsoft/vscode/issues/337224](https://github.com/microsoft/vscode/issues/337224)

## Summary

The editor overlay already supports the central request through persistent toolbar customization: users can hide its file-level Keep and Undo actions independently while per-change review controls remain available.

## Change summary

Provide a persistent preference that removes file-level Keep/Undo click targets from the chat-editing editor overlay without removing per-change review actions.

## Best solution

Use the overlay toolbar's existing Hide customization for “Keep Chat Edits” and “Undo Chat Edits”; keep per-change actions on their separate hunk toolbar and retain the hidden file actions through the Command Palette or their configurable keybindings.

## Vision fit

- **Fit:** unclear
- **Reason:** Preventing accidental broad review actions fits workbench UX, while adding a dedicated setting would duplicate the uniform toolbar-customization mechanism and add configuration surface.
- **Evidence:** Values and guardrails: “Simple, uniform UI and UI interactions” and the lean-default guardrail against configuration sprawl.

## Evidence

- **existing toolbar customization:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorOverlay.ts constructs the editor overlay with MenuWorkbenchToolBar and HiddenItemStrategy.Ignore, enabling its actions to be hidden from the toolbar.
- **persistent preference:** src/vs/platform/actions/common/menuService.ts stores hidden menu-command state under menu.hiddenCommands in StorageScope.PROFILE, so toolbar choices persist across sessions and restarts.
- **scope separation:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts registers file-level chatEditor.action.accept/reject on MenuId.ChatEditingEditorContent, while per-change chatEditor.action.acceptHunk/undoHunk use the separate MenuId.ChatEditingEditorHunk; hiding the former does not disable the latter.
- **explicit fallback access:** The file-level Keep/Undo actions remain F1 commands with configurable keybindings in chatEditingEditorActions.ts even when their overlay buttons are hidden.
- **canonical search:** Repository issue searches for hiding these exact overlay actions found no older issue with the same observable request; the issues cited in the report concern keyboard activation, navigation, or recovery instead.
