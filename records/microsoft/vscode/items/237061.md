# Issue #237061 — `--enable-wayland-ime` is not supported in `~/.vscode/argv.json`

[https://github.com/microsoft/vscode/issues/237061](https://github.com/microsoft/vscode/issues/237061)

## Summary

The requested argv.json support is still missing on current main. Keep this open for a maintainer decision on supported runtime flags; the thread explicitly considers adding support, and neither the workarounds nor the related Wayland input issue covers this request.

## Change summary

Allow users to persist Wayland IME runtime options in argv.json instead of supplying them on every launch.

## Best solution

Provide a supported argv.json configuration that delivers the reporter's existing --enable-wayland-ime behavior. Resolve whether that contract includes dedicated Wayland options, generic enable-features/disable-features support, or both, without changing default input behavior.

- **Behavior:**

  > Users who currently need --enable-wayland-ime should be able to persist an equivalent supported configuration in argv.json and launch VS Code normally. Acceptance requires equivalent IME behavior on the same Wayland environment, not merely successful parsing of the JSON. Existing supported argv.json options and launches without the new configuration must remain unchanged. If generic feature flags are included, their values must coexist with VS Code's built-in runtime feature configuration.
- **Trace:**

  > configureCommandlineSwitchesSync in src/mainImpl.ts reads argv.json and forwards only SUPPORTED_ELECTRON_SWITCHES and SUPPORTED_MAIN_PROCESS_SWITCHES; the requested Wayland and generic feature keys are absent. Later enable-features/disable-features construction preserves existing app.commandLine values, but does not itself read these values from argv.json. The discussion at https://github.com/microsoft/vscode/issues/237061#issuecomment-2613754326 introduces dedicated Wayland options and generic feature flags as possible contracts, while https://github.com/microsoft/vscode/issues/237061#issuecomment-2613770993 establishes only that enable-wayland-ime works for the reporter. The uncertainty is which configuration surface to support and whether the proposed generic alternative actually delivers that behavior on current Electron. Preserve existing runtime defaults and unrelated argv handling; resolving general Wayland IME defects such as https://github.com/microsoft/vscode/issues/167757 is outside this persistence request.
- **Open decisions:**
  - Should argv.json expose enable-wayland-ime directly, generic enable-features/disable-features, or both? A generic-only contract must demonstrably cover the reporter's working IME behavior.
  - Should the supported Wayland configuration also expose wayland-text-input-version, or leave protocol selection to runtime defaults and generic feature flags?
