# Issue #120600 — Allow notebook-output to be marked as transient per instance

[https://github.com/microsoft/vscode/issues/120600](https://github.com/microsoft/vscode/issues/120600)

## Summary

The API gap remains: output transience is configured per serializer, not per output instance, so selective persistence cannot also produce accurate dirty tracking. The discussion supports an instance-level capability; the former dirty-tracking blocker is closed, but the public contract still needs design.

## Change summary

Allow extensions to control output persistence and corresponding dirty tracking per notebook or output instance rather than uniformly per notebook type.

## Best solution

Provide an extension-controlled output-instance persistence contract that keeps serialization, dirty tracking, and notebook diffs consistent while preserving existing serializer defaults. Settle how that contract changes during execution before implementing it across the notebook API and model.

- **Behavior:**

  > An extension should be able to retain selected outputs while treating other outputs as transient within the same notebook type. Changes confined to transient outputs should not dirty the notebook, whereas changes to persisted outputs should. Saving should retain the selected persistent outputs without clearing transient outputs from the live notebook. Existing extensions that supply only serializer-wide content options must retain their current behavior.
- **Trace:**

  > workspace.registerNotebookSerializer in src/vscode-dts/vscode.d.ts supplies one NotebookDocumentContentOptions object per registration; NotebookCellOutput currently carries only items and arbitrary metadata. NotebookTextModel.createSnapshot and its output-change events in src/vs/workbench/contrib/notebook/common/model/notebookTextModel.ts use a shared transientOutputs flag, while ExtHostNotebookController's save path in src/vs/workbench/api/common/extHostNotebook.ts independently filters outputs using serializer options. NotebookCellTextModel also uses that flag for hashing and equality, and notebook diff consumers depend on the same global policy. The thread favors output-instance transience and explicitly identifies changes after initial NotebookData delivery as relevant. https://github.com/microsoft/vscode/issues/121807 resolves the earlier dirty-tracking prerequisite; https://github.com/microsoft/vscode/issues/124551 concerns a separate generic setting. Preserve serializer ownership of the file format, existing defaults, and execution/undo semantics; uncertainty begins at the public contract for dynamically changing persistence.
- **Open decisions:**
