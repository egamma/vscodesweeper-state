# Issue #326151 — Support writing to the local clipboard from Dev Containers and Remote SSH sessions

[https://github.com/microsoft/vscode/issues/326151](https://github.com/microsoft/vscode/issues/326151)

## Summary

Keep open as a feature request: terminal OSC 52 support and the extension clipboard API do not provide the requested clipboard bridge for standalone hooks launched through Source Control. No verified older canonical covers that workflow.

## Change summary

Allow standalone scripts and Git hooks in remote sessions to explicitly write generated text to the local desktop clipboard without manual copying.

## Best solution

Decide whether to expose a supported, write-only remote CLI clipboard bridge with explicit access semantics. Preserve the distinction between terminal escape-sequence handling and ordinary Source Control process output rather than treating arbitrary hook output as terminal commands.

## Evidence

- **Concrete workflow:** https://github.com/microsoft/vscode/issues/326151 and the reporter's follow-up describe a pre-commit hook that generates and transfers a file to an IBM Mainframe, then produces a dataset name needed immediately in another application. Interactive terminal copying does not cover the Source Control-launched hook.
- **Existing terminal capability is partial:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:341-353 loads the xterm clipboard addon and routes its writes to IClipboardService.writeText. This supports escape sequences processed by a terminal instance, not every background process's output.
- **Source Control takes a different path:** extensions/git/src/git.ts:2082-2142 runs commit through exec; Git._exec at lines 624-679 captures stdout/stderr and logs output, while Git.spawn uses child_process.spawn. This flow does not send hook output through the xterm clipboard parser, explaining why terminal OSC 52 support does not satisfy the central request.
- **No existing CLI clipboard operation:** src/vs/server/node/server.cli.ts restricts pipe-supported CLI options and contains no clipboard-write option. src/vs/workbench/api/node/extHostCLIServer.ts defines and dispatches only open, openExternal, status, and extensionManagement pipe commands; no clipboard operation is exposed.
- **Extension API is not standalone script access:** src/vs/workbench/api/browser/mainThreadClipboard.ts implements $writeText by calling the client clipboard service. This confirms an extension-to-client bridge exists, but it does not expose a supported standalone CLI or Git-hook interface.

The supplied candidates https://github.com/microsoft/vscode/issues/52116 and https://github.com/microsoft/vscode/issues/40239 concern extension permissions and extension enablement, respectively; neither owns this request.
