# Issue #333625 — Allow custom instructions for automatically generated chat session titles

[https://github.com/microsoft/vscode/issues/333625](https://github.com/microsoft/vscode/issues/333625)

## Summary

This team-authored feature request identifies a real gap: current title-generation prompts and settings do not accept persistent user- or workspace-level naming instructions. No older issue reports the same observable request, so it should remain open and be classified as a feature request.

## Change summary

Allow users to customize automatic chat-session title generation while preserving task identifiers and respecting explicit renames.

## Best solution

Provide one user- and workspace-scoped title policy that is consumed consistently by automatic title-generation paths, including first-turn refinement, while preserving existing behavior when unset and never overriding a manually assigned title.

- **Validation:** Extend the AgentHostSessionTitleController tests and Copilot title-prompt tests to verify user/workspace policy propagation, identifier retention during automatic refinement, unchanged defaults when unset, and precedence of explicit renames.
- **Behavior:**

  > Users can define a title-generation policy at user or workspace scope. Automatic titles follow that policy and can retain repository, pull-request, issue, or work-item identifiers supplied by the request or attached context. The policy applies to the supported automatic generation stages, while an unset policy preserves existing output and an explicit rename is never overwritten.
- **Trace:**

  > Agent Host title generation is coordinated by AgentHostSessionTitleController in src/vs/platform/agentHost/node/agentHostSessionTitleController.ts; its `_buildTitlePrompt` is fixed, while `_appendGitHubContext` already enriches linked issues and pull requests. Its existing generation controls are application-scoped booleans registered in src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts and mirrored into src/vs/platform/agentHost/common/agentHostSchema.ts. Integrated Copilot chat uses ChatTitleProvider in extensions/copilot/src/extension/prompt/node/title.ts with the fixed TitlePrompt in extensions/copilot/src/extension/prompts/node/panel/title.tsx. Existing manual-rename protections in the controller must remain unchanged. https://github.com/microsoft/vscode/issues/308186 covers the automatic lifecycle, while https://github.com/microsoft/vscode/issues/313971 covers explicit regeneration rather than persistent policy.
- **Open decisions:**
  - Should the public customization contract be free-form title-generation instructions, a structured template with named metadata fields, or both?
  - Which automatic title providers must honor the policy: Agent Host sessions only, or every integrated chat title provider?
  - When structured metadata is attached rather than present as text, which repository, pull-request, issue, and work-item fields are part of the supported title-generation contract?
