# Issue #333625 — Allow custom instructions for automatically generated chat session titles

[https://github.com/microsoft/vscode/issues/333625](https://github.com/microsoft/vscode/issues/333625)

## Summary

Well-articulated feature request for customizable automatic chat-title generation (repo/PR/ticket-key identifiers); no existing setting or hook covers this today, and a second commenter confirms demand beyond the reporter (Jira/Azure Boards use case). Stays open as under-discussion pending a maintainer design call.

## Change summary

Let users configure instructions/templates so auto-generated chat session titles retain identifiers like repo name, PR number, or ticket key.

## Best solution

A maintainer should decide the shape of the customization surface (instructions vs. template vs. hook/session API) for the title-generation lifecycle in the chat contrib area before any implementation; the reporter's own related-issue survey (#308186, #329380, #288265, #313971) is a good starting map.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatSessions/chatSessions.contribution.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts`
- **Validation:** A test asserting a configured title convention (e.g. user/workspace setting) produces a title retaining the PR/repo identifier after both first-turn and summary-based title generation.
- **Behavior:**

  > Users can configure how automatically generated chat session titles are formed (e.g. a template or instructions retaining repo name, PR/issue number, or ticket key) at user or workspace scope. Default behavior is unchanged when no customization is configured. A manually renamed title is never overwritten by auto-generation. Required identifiers survive both the initial title and any later summary-based title upgrade.
- **Trace:**

  > Automatic title generation lives in the chat sessions/agent-host title lifecycle (e.g. agentHostUntitledProvisionalSessionService.ts, chatSessions.contribution.ts, and the async title-gen work from https://github.com/microsoft/vscode/issues/308186); no code path today reads a user/workspace-level title template or instruction. The open question is the shape of the configuration surface and how structured context (repo, PR number, branch-derived ticket key) is extracted and merged into the prompt used for title generation — that is a product decision, not an implementation detail.
- **Open decisions:**
  - Should customization be free-form instructions fed into the title-generation prompt, a structured template with named placeholders, or a session/hook API a caller can set programmatically?
  - How should identifiers be sourced when not present in the prompt text (e.g. parsed from branch name for ticket keys) — and is that in scope for this issue or a follow-on?
  - Should this be user-only, workspace-only, or both, and how do the two combine when both are set?
