# Issue #271711 — Failed to apply code block: Response contained no choices.

[https://github.com/microsoft/vscode/issues/271711](https://github.com/microsoft/vscode/issues/271711)

## Summary

Keep this open as the canonical report: many users reproduced the failed code-block application and lingering request across macOS, Windows, and Linux, and maintainers explicitly consolidated later matching reports here. Current source still exposes the generic no-choices fallback, while the older same-title issue contains only an unrelated network-timeout diagnostic and does not safely supersede this re-reviewed item.

## Change summary

Applying a Copilot-generated code block can receive an empty mapped-edit response, show “Response contained no choices,” and leave the editor or chat request stuck until VS Code restarts.

## Best solution

Define and implement graceful handling for an empty mapped-edit response: the apply operation must terminate, release progress and editor state, and surface an actionable result instead of leaving a request active. The investigation should distinguish the model-service failure from the client lifecycle problem and preserve the diagnostic request identifiers.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts`, `src/vs/workbench/contrib/chat/browser/actions/codeBlockOperations.ts`
- **Validation:** Exercise code-block application with a mapped-edit provider that returns no choices: verify the operation settles, progress and request state end, the editor remains editable without restarting, and the selected actionable fallback or error is shown.
- **Behavior:**

  > When applying a chat code block receives no usable mapped-edit choice, the operation must finish rather than remain in progress, and the target editor must remain editable. The user must receive an actionable outcome appropriate to the selected fallback policy rather than the opaque “Response contained no choices” message. Successful mapped edits and user cancellation must retain their current behavior.
- **Trace:**

  > The reported logs show `editingSession/speculate` returning no message choice before `insert_edit_into_file` fails. On current main, `ChatMLFetcher` in `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts` maps an empty or unrecognized completion set to `ChatFetchResponseType.Unknown` with `RESPONSE_CONTAINED_NO_CHOICES`; the mapped-edit result reaches `CodeBlockOperations.getTextEdits` and is displayed by `handleTextEditor` in `src/vs/workbench/contrib/chat/browser/actions/codeBlockOperations.ts`. That core path disposes its local cancellation source in `finally`, so the reported lingering request may be owned above or inside the mapper rather than by the notification catch itself. Preserve successful edit application, explicit cancellation, and request identifiers used for service diagnostics. https://github.com/microsoft/vscode/issues/273424 and https://github.com/microsoft/vscode/issues/274260 were consolidated into this report; https://github.com/microsoft/vscode/issues/257982 is related but has a different network-timeout diagnostic.
- **Open decisions:**
  - When a mapped-edit request returns no choices, should VS Code retry or fall back to another mapper, treat it as a completed no-edit result, or terminate with an actionable error?
