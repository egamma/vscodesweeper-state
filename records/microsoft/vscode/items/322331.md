# Issue #322331 — files.exclude glob pattern: negation does not work with the path separator /

[https://github.com/microsoft/vscode/issues/322331](https://github.com/microsoft/vscode/issues/322331)

## Summary

The defect remains on current main and is conclusively traced to the glob parser. Keep the issue open while the directly linked fixing PR is reviewed.

## Change summary

Negated glob bracket ranges in `files.exclude` incorrectly match path separators because `/` is discarded while compiling the range.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/337898, which preserves `/` in negated bracket ranges and adds regression coverage for the reporter's exact pattern.

## Evidence

- **source reproduction:** Current main in src/vs/base/common/glob.ts:161-186 discards `GLOB_SPLIT` from every bracket range. Consequently `Source[^M/]*` is compiled as `Source[^M]*`, allowing the negated class to match `/` and hide descendants of `Source/`.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/337898 is open, references this issue with `Fixes #322331`, changes the exact parser branch, and adds regression assertions for `Source/`, `Source/sub`, `SourceM`, and `SourceX` in src/vs/base/test/common/glob.test.ts.
- **canonical check:** https://github.com/microsoft/vscode/issues/869 requests general include/exception semantics for `files.exclude`; it does not own this parser bug involving `/` inside a negated bracket range.
