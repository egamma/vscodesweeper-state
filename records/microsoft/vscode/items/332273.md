# Issue #332273 — Rename action does not use the easiest UX

[https://github.com/microsoft/vscode/issues/332273](https://github.com/microsoft/vscode/issues/332273)

## Summary

Team-authored bug with a real scheduled milestone (1.136.0), so it must stay open regardless of other evidence — but the report also holds up on inspection: the Agents Window's list/'…' Rename action still routes through a modal quick-input prompt instead of the inline title-editing UX already used elsewhere in the same feature.

## Change summary

The session list's 'Rename…' action (and double-click on a session title) opens a `quickInputService.input()` modal prompt, instead of an inline in-place edit like the session header's rename already provides.

## Best solution

Wire `RenameSessionAction` (and the `onDidRequestRename` double-click handler) in src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts and sessionsList.ts to trigger the same inline title-editing affordance that `RenameSessionHeaderAction`/`startTitleEditing()` already use in sessionHeader.ts, rather than `quickInputService.input()`.

- **Reason:** A more direct, in-place rename interaction is a simpler, more uniform UI pattern than an extra modal prompt, matching the project's 'simple, uniform UI and UI interactions' value.
