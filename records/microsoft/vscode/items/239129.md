# Issue #239129 — vscode is not respecting users choice to not be part of the experiments.

[https://github.com/microsoft/vscode/issues/239129](https://github.com/microsoft/vscode/issues/239129)

## Summary

The defect remains source-reproducible on main: core experiment assignment fetching honors `workbench.enableExperiments`, but bundled first-party extensions can independently initialize TAS clients without checking that setting. This is in scope for this repository and should remain open.

## Change summary

Setting `workbench.enableExperiments` to false does not prevent all bundled VS Code components from contacting the experimentation service.

## Best solution

Make every bundled first-party TAS client consistently honor `workbench.enableExperiments`, while preserving current behavior when experiments are enabled. In particular, the TypeScript language-features activation path should not initialize or fetch assignments after the user opts out.

## Evidence

- **core setting honored:** src/vs/workbench/services/telemetry/common/workbenchTelemetryUtils.ts requires `workbench.enableExperiments === true`, and src/vs/workbench/services/assignment/common/assignmentService.ts uses that helper for the core assignment service.
- **bundled extension bypass:** extensions/typescript-language-features/src/extension.ts constructs `ExperimentationService` during activation without reading `workbench.enableExperiments`; extensions/typescript-language-features/src/experimentationService.ts then creates a `vscode-tas-client` service and awaits `initialFetch`.
- **activation trigger:** extensions/typescript-language-features/package.json activates the bundled `vscode.typescript-language-features` extension for JavaScript, JSX, TypeScript, and TSX documents, so disabling ordinary installed extensions does not eliminate this first-party path.
- **additional inconsistent client:** extensions/github-authentication/src/common/experimentationService.ts also lazily creates a TAS client without checking `workbench.enableExperiments`, whereas extensions/copilot/src/extension/extension/vscode-node/services.ts explicitly checks the setting before enabling its experimentation service.
