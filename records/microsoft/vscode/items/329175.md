# Issue #329175 — [Microsoft Authentication] Native broker logs full account PII at warning level during account discovery

[https://github.com/microsoft/vscode/issues/329175](https://github.com/microsoft/vscode/issues/329175)

## Summary

Confirmed on current main: MSAL is configured with `piiLoggingEnabled: true` and the logger callback discards the `containsPii` flag, so account PII lands in the default Warning-level output channel during normal native-broker account discovery. This is a privacy/data-exposure defect, so it stays open per the security-sensitive hard keep-open rule rather than being closed or auto-fixed.

## Change summary

The built-in Microsoft Authentication extension's native-broker account discovery logs full MSAL account objects (name, email, birth date, tenant/object/device IDs, login hints, ID-token claims) at Warning level by default.

## Best solution

In `extensions/microsoft-authentication/src/common/loggerOptions.ts`, honor the `containsPii` argument (skip or redact when true) and/or stop forcing `piiLoggingEnabled: true` unconditionally in `extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts`, gating verbose PII logging behind an explicit diagnostic setting.
