# Issue #329175 — [Microsoft Authentication] Native broker logs full account PII at warning level during account discovery

[https://github.com/microsoft/vscode/issues/329175](https://github.com/microsoft/vscode/issues/329175)

## Summary

Keep open for human privacy/security review: current source still enables PII logging and forwards warning messages without checking their PII flag. The reported personal-data exposure triggers the security-sensitive keep-open rule.

## Change summary

Prevent native-broker account discovery from persisting full PII-bearing account dumps in ordinary Microsoft Authentication logs.

## Best solution

Microsoft Authentication should exclude PII-bearing account diagnostics from ordinary output while preserving useful non-sensitive warnings. The authentication owner should confirm the native broker's PII flagging and review the logging boundary before considering this resolved.

## Evidence

- **Current logging configuration:** extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts:67-79 constructs PublicClientApplication with LogLevel.Trace and piiLoggingEnabled: true, forwarding containsPii to MsalLoggerOptions.loggerCallback. The helper's separate piiLoggingEnabled = false property does not override this explicit configuration.
- **Source-confirmed output path:** extensions/microsoft-authentication/src/common/loggerOptions.ts:22-32 ignores _containsPii and forwards every MSAL Warning message to LogOutputChannel.warn. A PII-marked warning therefore reaches ordinary warning output unchanged.
- **Account-discovery trigger:** CachedPublicClientApplication.create calls initialize, which invokes _update; extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts:352-360 calls getAllAccounts before filtering broker accounts for allowed access. This matches the reported initialization/account-discovery trigger. Native Windows broker execution and its message flagging were not tested in this read-only review.
- **Related report is not a canonical duplicate:** Verified https://github.com/microsoft/vscode/issues/291738 is open and contains the same LogAccountInfoNoThrow account-dump lines, but its requested outcome is successful sign-in after ReadAccountById and StatusInternal::Unexpected errors. Resolving those authentication failures would not necessarily prevent the normal-discovery PII logging reported here. Searches for account/PII, authentication/logging/PII, and LogAccountInfoNoThrow found no verified canonical owning this privacy requirement.
- **Security-sensitive protection:** https://github.com/microsoft/vscode/issues/329175 describes disclosure of names, email addresses, birth dates, identity claims, and account/device identifiers into persisted logs. No access or refresh token was reported. The personal-data exposure nevertheless requires keeping the issue open for human handling and excludes agent readiness.
