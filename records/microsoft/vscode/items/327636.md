# Issue #327636 — Keyboard shortcut for GitHub Copilot thinking effort in Configure Model

[https://github.com/microsoft/vscode/issues/327636](https://github.com/microsoft/vscode/issues/327636)

## Summary

A real gap remains: current main provides a keyboard command for opening the model picker and keyboard-accessible configuration controls, but no bindable commands that directly increase or decrease thinking effort. The existing Backlog and under-discussion classification should remain open while command semantics are decided.

## Change summary

Add bindable commands that increase or decrease the active chat model's thinking-effort setting without navigating the model picker.

## Best solution

Expose AI-gated chat commands that move the active model's thinking-effort configuration by one supported level in the current chat scope, with accessible feedback when the value changes or cannot change. Keep Auto routing preferences distinct unless maintainers explicitly decide those should share the commands.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerModelConfig.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatExecuteActions.test.ts`, `src/vs/workbench/contrib/chat/test/browser/accessibility/chatAccessibilityHelp.test.ts`
- **Validation:** Add command-action tests proving increase and decrease select adjacent supported effort values in the last-focused chat, preserve the value at configured boundaries, and do not alter unsupported model configurations; update the chat accessibility-help test to discover the new commands.
- **Behavior:**

  > Users can bind commands to increase or decrease the current chat model's thinking effort without opening the model picker. Each invocation moves exactly one step through the model's supported ordered effort levels and affects the same session-scoped configuration shown by the picker. The action provides accessible feedback for a successful change and for states where no change is available. Existing model selection, context-size configuration, and picker keyboard behavior remain unchanged.
- **Trace:**

  > OpenModelPickerAction and SwitchToNextPinnedModelAction in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts establish the command-to-last-focused-widget pattern. ChatInputPart in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts owns the active model and its editor-scoped ChatModelConfigurationStore. The shared configuration path in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerModelConfig.ts locates the `navigation` group, exposes ordered enum choices, and serializes writes, but that group also represents Auto's “Optimize for” tier. Current accessibility guidance in src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts documents only opening and navigating the picker. Do not change model selection, context-size values, configuration persistence scope, or unrelated picker interactions. https://github.com/microsoft/vscode/issues/317991 concerns direct model switching and is related but does not own thinking-effort adjustment.
- **Open decisions:**
  - Should the commands operate only on genuine Thinking Effort properties, or also change the Auto model's `Optimize for` routing tier, which currently shares the `navigation` configuration group?
  - At the minimum or maximum supported effort, should invocation be a non-wrapping no-op with accessible status feedback, or wrap to the opposite end?
  - When the active model has no configurable effort property, should the command remain available and announce that it is unsupported, or be disabled through context-key state?

## Evidence

- **existing partial capability:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts registers `workbench.action.chat.openModelPicker` with Ctrl/Cmd+Alt+Period, while src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts documents keyboard navigation through model details and thinking-effort choices.
- **remaining source gap:** The command registrations in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts include opening the picker and switching to the next pinned model, but no action for changing thinking effort directly.
