## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/explorerService.ts`, `src/vs/workbench/contrib/files/browser/views/explorerView.ts`, `src/vs/workbench/contrib/files/common/explorerModel.ts`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`
- **Validation:** Open folders in a Remote-SSH Explorer, trigger the connection failure that presents Reload/Reopen, reconnect through that action, and verify the same folders remain expanded; the plan should also add or identify an Explorer test that exercises equivalent provider/input churn without losing view state.
- **Behavior:**

  > Expanded and collapsed folders in the Side Bar Explorer must retain their state when a remote connection fails and VS Code reconnects through the Reload/Reopen prompt. A normal timeout/reconnect and an ordinary local workspace reload must remain unchanged. Acceptance requires reproducing the historical trigger on current main and showing that the folder state before and after reconnection is identical.
- **Trace:**

  > The remote provider-change path runs through ExplorerService in src/vs/workbench/contrib/files/browser/explorerService.ts: provider registration or capability changes forget root children and request `setTreeInput()`. ExplorerView.doSetTreeInput in src/vs/workbench/contrib/files/browser/views/explorerView.ts captures the current tree view state, derives either a root item or roots array from root error/workbench state, and calls `tree.setInput(input, viewState)`. ExplorerItem identities come from root and item resource URIs in src/vs/workbench/contrib/files/common/explorerModel.ts. The existing src/vs/workbench/contrib/files/test/browser/explorerView.test.ts coverage exercises repeated input updates and hidden-view reopening, but not remote provider loss/reconnection or the reload prompt. Preserve behavior for normal refreshes, workspace-folder additions, and the intentional initial root expansion rules; https://github.com/microsoft/vscode/issues/134665 is a different, closed workspace-reopen regression.

## Evidence

- **confirmed regression:** The reporter supplied a specific Remote-SSH trigger, and a maintainer explicitly identified it as a 1.60 regression and committed to investigating: https://github.com/microsoft/vscode/issues/132813#issuecomment-953404529
- **source path:** On current main, src/vs/workbench/contrib/files/browser/explorerService.ts reacts to file-system provider registration or capability changes by forgetting root children and calling `view.setTreeInput()`; src/vs/workbench/contrib/files/browser/views/explorerView.ts then captures `tree.getViewState()` and replaces the input through `tree.setInput(input, viewState)`.
