# Issue #337382 — Agent Host: native sdk of codex and claude are both 3 weeks behind latest version, needs to keep it up or feature failed.

[https://github.com/microsoft/vscode/issues/337382](https://github.com/microsoft/vscode/issues/337382)

## Summary

Real, ongoing concern: Agent Host vendors pinned versions of the Codex and Claude SDKs (package.json shows @openai/codex 0.157.0 and @anthropic-ai/claude-agent-sdk 0.3.281) that lag behind the standalone CLIs users install, causing model-support failures; a follow-up comment adds a concrete reproduction where the older bundled Codex SDK overwrites a newer CLI's shared ~/.codex/models_cache.json, reverting the user's model list. This is a dependency-update/process issue rather than a single bounded code fix, so it stays open for the Agent Host owners to address via update cadence or cache isolation.

## Change summary

Agent Host bundles outdated Codex/Claude SDK versions, so newer models and features the user's external CLI supports fail inside VS Code.

## Best solution

Bump the pinned @openai/codex and @anthropic-ai/claude-agent-sdk versions in package.json on a tighter cadence, and separately, have Agent Host's Codex integration avoid clobbering the shared ~/.codex/models_cache.json with a stale catalogue when a newer external CLI has already refreshed it (e.g. version/ETag-aware cache handling or a dedicated cache path).
