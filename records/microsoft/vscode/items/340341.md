# Issue #340341 — Agent Host: advertise the existing Web PubSub batch receive capability

[https://github.com/microsoft/vscode/issues/340341](https://github.com/microsoft/vscode/issues/340341)

## Summary

Team-authored (MEMBER), freshly filed feature request with a concrete, source-verified gap: the Web PubSub relay client decodes `capabilities`/`batch` framing but never publishes its own `capabilities` advertisement. No fix has landed yet, so this stays open regardless of other factors.

## Change summary

The Agent Host Web PubSub relay transport decodes the existing `capabilities`/`batch` framing on receive but has no path to advertise its own batch-receive capability on send, so the server-side peer can't learn the client supports batching.

## Best solution

Add a dedicated framing-control publish path (distinct from `buildPublish`'s ordinary AHP payload wrapping) that emits `{"kind":"capabilities","accepts":["batch"]}` on initial connect and reconnect/recovery, wired into webPubSubRelayTransport.ts's handshake lifecycle; server-side negotiation (MissionControlProtocolServer currently ignores these) is explicitly out of scope per the issue and should be tracked separately if pursued.
