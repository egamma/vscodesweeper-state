## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/327430 is open and was created on 2026-07-25. Its reproduction explicitly drags the CSS color picker toward black or white and outside its bounds while holding the mouse button, causing dismissal without saving. This matches the central symptom and requested behavior here.
- **Current source confirms premature dismissal:** In src/vs/editor/contrib/hover/browser/contentHoverController.ts, _onEditorMouseDown sets _isMouseDown. When the drag leaves the widget over ordinary editor content, _onEditorMouseMove calls _cancelSchedulerAndHide because _shouldKeepHoverWidgetVisible checks only widget bounds, resizing, and color decorations. This precedes _shouldKeepCurrentHover, whose color-picker-visible plus mouse-down condition would otherwise preserve the picker.
- **Edge clamping already exists:** src/vs/editor/contrib/colorPicker/browser/colorPickerParts/colorPickerSaturationBox.ts clamps saturation and value to [0, 1] in onDidChangePosition and flushes the selection on pointer-up. colorPickerStrip.ts similarly clamps strip values. Premature hover dismissal interrupts this existing interaction rather than exposing a separate missing edge-selection capability.
- **Existing unmerged implementation candidate:** https://github.com/microsoft/vscode/pull/327575 is open and unmerged, explicitly references the canonical issue with closing syntax, and describes the same conflicting hover-retention checks. It is an implementation candidate, not evidence that the bug is fixed.
