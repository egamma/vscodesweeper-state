# Issue #333978 — Chat / Agents: Git ignored files cannot be referenced in the chat or agents

[https://github.com/microsoft/vscode/issues/333978](https://github.com/microsoft/vscode/issues/333978)

## Summary

Current source intentionally filters file-reference searches through ignore rules, so exposing Git-ignored files is a product-behavior request rather than a confirmed regression. Keep it open and route it to Chat because the desired policy must be made consistent across classic Chat and Agent Host-backed sessions.

## Change summary

Allow users to attach or reference workspace files hidden by `.gitignore` from Chat and Agents input completions.

## Best solution

Define one explicit Chat file-reference policy that lets users deliberately select Git-ignored files without flooding normal suggestions, and apply it consistently to classic Chat attachments and Agent Host-backed completions. A chat-specific setting or explicit include-ignored affordance would avoid coupling this behavior to Explorer visibility.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/searchChatContext.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/agentHostInputCompletionsBase.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/search/test/browser/searchChatContext.test.ts`
- **Validation:** In a workspace containing a uniquely named Git-ignored file, verify the chosen policy with targeted completion tests and a manual check that both classic Chat and an Agent Host-backed Agents session either expose or suppress that file consistently, while ordinary non-ignored file suggestions remain unchanged.
- **Behavior:**

  > Users need a deliberate way to attach or reference a Git-ignored workspace file from Chat and Agents input completions. The default suggestion list must remain useful for repositories containing large ignored dependency or build directories. Acceptance requires the selected ignore policy to behave consistently for `@`/`#` references and the Files & Folders picker across classic Chat and Agent Host-backed sessions.
- **Trace:**

  > Classic Chat file and folder suggestions call `searchFilesAndFolders` in src/vs/workbench/contrib/search/browser/searchChatContext.ts; that helper constructs an `IFileQuery` whose ignore handling currently depends on `explorer.excludeGitIgnore`. Agent Host-backed widgets short-circuit those in-process providers and obtain completions through `AgentHostInputCompletionsBase._provide`, `IChatSessionsService.provideChatInputCompletions`, and `AgentHostSessionHandler.provideChatInputCompletions`. The related https://github.com/microsoft/vscode/issues/260220 covers agent search-tool access and separate Copilot exclusions, not this exact manual-reference surface. Preserve existing search-exclude behavior and avoid making large ignored trees unconditionally dominate completion results.
- **Open decisions:**
  - Should manual file references always permit Git-ignored files, expose them only through an explicit include-ignored action, or follow a configurable Chat-specific policy?
  - Should the same policy govern agent search tools and manual attachments, or should manual user selection remain independently configurable?

## Evidence

- **current classic-chat path:** src/vs/workbench/contrib/search/browser/searchChatContext.ts:232-268 implements `searchFilesAndFolders`; its `IFileQuery` passes `disregardIgnoreFiles` from `explorer.excludeGitIgnore`, and the default false value therefore leaves ripgrep ignore-file filtering enabled. The helper is used by the `#` completion provider in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts and by the Files & Folders attachment picker.
- **Agents path:** Agent Host-backed widgets bypass the workbench's ordinary file completion provider in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts. Their suggestions are delegated through `AgentHostInputCompletionsBase._provide` and `AgentHostSessionHandler.provideChatInputCompletions` in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:1366-1399, so consistency requires considering both paths.
- **related open request:** https://github.com/microsoft/vscode/issues/260220 is older and open, with a maintainer discussion about searching Git-ignored files and separate Copilot exclusion controls. It concerns agent search tools and exclusion policy rather than the same manual `@`/`#` completion symptom, so it does not meet the stronger duplicate bar for this re-reviewed item.
- **opposite picker request:** https://github.com/microsoft/vscode/issues/271628 requested the opposite `#` picker behavior—excluding Git-ignored files—and was classified as a feature request. That confirms this is a user-visible policy choice rather than an unambiguous correctness defect.
