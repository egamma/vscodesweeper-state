# Issue #153095 — Support multline details in quickpick items

[https://github.com/microsoft/vscode/issues/153095](https://github.com/microsoft/vscode/issues/153095)

## Summary

Keep this accepted Backlog request open: current Quick Pick rendering still limits details to one additional line. The request has 21 upvotes and explicit maintainer support; the related terminal issue depends on this capability rather than replacing it.

## Change summary

Allow Quick Pick item details to display multiple lines, with access to complete content when it exceeds the available space.

## Best solution

Support multiline detail presentation in the shared Quick Pick surface while preserving efficient scanning and keyboard navigation. Settle the height and overflow behavior before implementation, including how users inspect a complete long terminal command.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vscode-dts/vscode.d.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Extend the QuickInput browser suite to exercise details containing explicit line breaks, content exceeding the chosen height limit, and selection/navigation across differently sized items. Run ./scripts/test.sh --run src/vs/platform/quickinput/test/browser/quickinput.test.ts in an implementation workspace; manually confirm that the complete long detail remains accessible and ordinary one-line items retain their existing presentation.
- **Behavior:**

  > Quick Pick items should be able to present detail text across multiple lines instead of restricting the label, description, and detail to two total lines. The reporter's principal use case is choosing among a handful of options with substantial context. A built-in terminal consumer also needs access to the complete command before execution, even when it exceeds the picker viewport. Acceptance should cover explicit line breaks, long-content overflow, keyboard selection, and unchanged ordinary single-line picks.
- **Trace:**

  > QuickInputItemDelegate.getHeight in src/vs/platform/quickinput/browser/quickInputList.ts returns 44 for every item with detail, independent of line count. The detail renderer uses IconLabel with labelEscapeNewLines: true, while src/vs/platform/quickinput/browser/media/quickInput.css clips overflow. The existing detail hover and quickInput.toggleHover command provide partial inspection but do not satisfy inline multiline presentation. The public QuickPickItem contract is in src/vscode-dts/vscode.d.ts, with the internal counterpart in src/vs/platform/quickinput/common/quickInput.ts. Maintainers accepted the feature in https://github.com/microsoft/vscode/issues/153095; https://github.com/microsoft/vscode/issues/158120 is a dependent terminal use case, not a duplicate. Preserve ordinary item presentation, filtering, keyboard navigation, and accessible content; resolving terminal protocol concerns is outside this request. The remaining uncertainty is the observable expansion and overflow contract, not whether the capability is wanted.
- **Open decisions:**
  - Should multiline details appear automatically when detail contains line breaks, or require an explicit opt-in so existing consumers retain compact rows?
  - Should detail rows grow to show all content, or stop at a height limit with the complete content available through a hover or other preview?
