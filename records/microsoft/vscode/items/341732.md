# Issue #341732 — Copilot Harness approval system is dangerous

[https://github.com/microsoft/vscode/issues/341732](https://github.com/microsoft/vscode/issues/341732)

## Summary

Keep open for human review of approval scope and precedence: current source grants subsequent calls of the approved tool permission before evaluating terminal approval rules. This is a security-sensitive authorization concern, so it must not receive a cleanup close.

## Change summary

Make Copilot harness approvals communicate their scope clearly and resolve whether session-level tool grants should override command-level approval restrictions.

## Best solution

Have the permission owners settle the contract between one-time approval, session-wide tool approval, and configured command restrictions, then make enforcement and confirmation wording match that contract. Investigate the original reporter's claimed single-command and single-page approvals separately from the commenter's explicit session-wide selection; the workflow-quality complaint is not explained by the permission path.
