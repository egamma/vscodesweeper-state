# Issue #335192 — Integrated Browser: Very difficult to use Add Element to Chat in Mobile view

[https://github.com/microsoft/vscode/issues/335192](https://github.com/microsoft/vscode/issues/335192)

## Summary

Real, source-traceable interaction bug in the Integrated Browser's mobile/device emulation: the element picker's live highlight depends on `pointermove`, which mobile/touch-mode pointer input doesn't fire on simple taps, so users get no visual feedback before committing an element; the follow-up report that links actually navigate in this mode needs further tracing (possibly a distinct touch-to-click path bypassing the window-capture click interceptor). Reporter's own comments (comparing built-in Mobile Emulation vs DevTools 'Toggle device toolbar') corroborate this is specific to the built-in emulation toggle.

## Change summary

In the Integrated Browser, using 'Add Element to Chat' while Mobile Emulation is active doesn't highlight hovered elements, and clicks on links navigate instead of being intercepted for selection.

## Best solution

Redesign element-selection feedback for touch/mobile-emulated pointer input in src/vs/platform/browserView/electron-browser/preload-browserView.ts's ElementPicker — e.g. show a highlight preview on tap-and-hold or first tap before commit — and verify the click-interception path actually blocks navigation when `device.mobile` is set via browserEditorEmulationFeatures.ts.

## Plan brief

- **Likely files:** `src/vs/platform/browserView/electron-browser/preload-browserView.ts`, `src/vs/workbench/contrib/browserView/electron-browser/features/browserEditorEmulationFeatures.ts`
- **Validation:** Manually verify: enable Mobile Emulation + Add Element to Chat selection mode, tap an element (highlight should appear before commit) and tap a link (should attach to chat, not navigate); ideally add an automated test simulating touch-type PointerEvents against ElementPicker.
- **Trace:**

  > The ElementPicker in preload-browserView.ts drives its hover highlight purely from `pointermove` (line ~848), which does not fire for a simple tap under touch-type pointer input; mobile emulation (browserEditorEmulationFeatures.ts `toggleMobile()`) explicitly sets `device.mobile`, which per its own comment 'drives touch + pointer media'. The `_onClick`/`_onPointerDown`/`_onPointerUp` handlers do call `preventDefault`/`stopPropagation` at window capture regardless of pointer type, so why real navigation still occurs under mobile emulation is not yet confirmed from source and needs live tracing (e.g. whether Chromium's touch-emulation gesture recognizer dispatches a trusted click that bypasses this capture listener, or whether emulation is applied via a CDP path that doesn't go through this preload script at all).
- **Open decisions:**
  - What should element highlighting look like for touch/mobile-emulated input given there is no hover — highlight on tap-and-hold before commit, or a different preview mechanism?
  - Is the link-navigation-instead-of-select behavior caused by a gap in this picker's interception, or by CDP-level touch emulation not routing through the preload script at all — and if the latter, should mobile emulation even support element selection the same way?

## Evidence

- **highlight relies on hover:** src/vs/platform/browserView/electron-browser/preload-browserView.ts:824-849 — `_onPointerMove` drives `_updateHighlight` on hover; touch-type pointers generally don't fire `pointermove` on a simple tap, so no highlight appears before commit.
- **mobile flag drives touch pointer type:** src/vs/workbench/contrib/browserView/electron-browser/features/browserEditorEmulationFeatures.ts:567 comment: 'Flip the mobile flag on the current device (drives touch + pointer media)' — confirms mobile emulation changes pointer semantics used by the picker.
- **click interception exists but path unconfirmed for touch:** preload-browserView.ts:972-988 `_onClick` calls `preventDefault`/`stopPropagation` at window capture, which should block navigation regardless of pointer type; why it fails specifically under mobile emulation is not yet traced from source alone.
- **reporter corroboration:** Comments on 2026-09-13 note the built-in Mobile Emulation lets you click elements but the DevTools console is constrained, while DevTools' own device toolbar allows proper selection — suggesting the built-in mobile toggle's event handling differs from the reference case.
