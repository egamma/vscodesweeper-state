# Issue #337331 — Sandbox cannot start commands when firewall mode requires missing slirp4netns

[https://github.com/microsoft/vscode/issues/337331](https://github.com/microsoft/vscode/issues/337331)

## Summary

Team-authored, same-day bug report with a source-confirmed gap: the sandbox's dependency probing and Linux packaging never account for slirp4netns, which the firewall network-enforcement mode hard-requires, so commands fail outright when that mode is selected.

## Change summary

Agent command sandbox fails to run any command when network.enforcementMode is 'firewall' (or 'both') because slirp4netns isn't installed and isn't checked/installed like bubblewrap and socat are.

## Best solution

Extend the Linux sandbox prerequisite check (SandboxHelperService.checkSandboxDependenciesWith in sandboxHelper.ts) to probe for slirp4netns when the configured enforcementMode needs it, add it to the guided install command and to build/linux/debian and rpm dep-lists.ts, and surface a clear missing-dependency message consistent with the existing bubblewrap/socat flow.
