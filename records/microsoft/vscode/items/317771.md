# Issue #317771 — [BUG] No results returned for the `fileSearch` tool when querying a network drive, works fine when ommited

[https://github.com/microsoft/vscode/issues/317771](https://github.com/microsoft/vscode/issues/317771)

## Summary

The defect remains visible in current source and should be routed to the chat-agent area. The file-search tool does not recognize the reported single-slash representation of a UNC workspace path, so it forwards an absolute-looking string glob instead of a workspace-scoped relative pattern.

## Change summary

Make the Copilot file-search tool return workspace files when the model queries a Windows network-drive path in forward-slash form.

## Best solution

Normalize model-generated network-workspace paths against the actual workspace-folder URI before invoking `findFiles2`, while preserving existing local absolute-path, relative-glob, multi-root, and explicit-working-directory behavior.

## Evidence

- **source trace:** `extensions/copilot/src/extension/tools/node/toolUtils.ts` passes absolute inputs through `URI.file(query)` and scopes them only when `WorkingDirectory.getFolder` recognizes the resulting URI. On Windows, `/192.168.1.50/path/**` becomes a file URI with no authority, whereas the opened UNC workspace has authority `192.168.1.50`, so the containment lookup fails and the raw string reaches file search.
- **UNC representation:** `extensions/copilot/src/util/vs/base/common/uri.ts` assigns a UNC authority only when a path begins with two slashes. The reported single-slash form therefore cannot match the network workspace URI.
