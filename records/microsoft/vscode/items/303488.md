# Issue #303488 — Terminal briefly shows as completely white with a sad face in the corner when switching back to VS Code after using another app for a while

[https://github.com/microsoft/vscode/issues/303488](https://github.com/microsoft/vscode/issues/303488)

## Summary

Valid terminal GPU context loss bug on macOS when resuming from idle — team member engaged and confirmed it sounds like context loss. The reporter provided dev-tools console errors confirming the diagnosis. No fix found on main; the workaround (`experimentalGpuAcceleration`) does not fully resolve it.

## Change summary

Terminal briefly renders as completely white with a broken-image icon when switching back to VS Code after a period of inactivity on macOS, due to WebGL context loss.

## Best solution

The terminal's WebGL renderer needs more robust context-loss recovery (or a graceful fallback to canvas) when macOS reclaims GPU resources during idle. This likely involves xterm.js upstream handling of the `webglcontextlost` event and may also relate to Electron/Chromium GPU process behavior. The prior fix for https://github.com/microsoft/vscode/issues/69665 (upstream) addressed a similar symptom but this appears to be a recurrence under newer GPU/driver conditions (Apple M4 Max, macOS 26). Keep open for investigation — may need an upstream xterm.js or Chromium fix.
