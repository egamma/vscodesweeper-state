# Issue #336761 — Agent Host ignores the selected custom agent: picker resets to "Agent" and the agent prompt is never applied

[https://github.com/microsoft/vscode/issues/336761](https://github.com/microsoft/vscode/issues/336761)

## Summary

Keep open: the picker synchronization fixes do not resolve the Remote-SSH Chat view's agent-URI mismatch. Current source still forwards a vscode-remote: selection to a host that resolves file-based agents by exact URI equality, consistent with the October 16 confirmation on stable 1.142.0.

## Change summary

Preserve the selected custom agent's identity, instructions, and tool allowlist when sending an Agent Host turn from a Remote-SSH window.

## Best solution

The selected file-based agent should resolve to the same host customization advertised in the registry, so both the picker and runtime use that agent. Cover the editor-remote connection boundary without changing opaque host identities or conflating agents that merely share a path or name.
