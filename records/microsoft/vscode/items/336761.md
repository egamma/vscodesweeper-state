# Issue #336761 — Agent Host ignores the selected custom agent: picker resets to "Agent" and the agent prompt is never applied

[https://github.com/microsoft/vscode/issues/336761](https://github.com/microsoft/vscode/issues/336761)

## Summary

Reporter's diagnostics (session-state event traces showing the custom agent's text never entering the system message) are highly credible, and tracing the source turns up a plausible mechanism: this stays open pending a maintainer session to pin the exact fix point.

## Change summary

Selecting a custom agent for a new Agent Host session is dropped — the picker resets to 'Agent' and the model runs with the stock system prompt instead of the custom agent's instructions.

## Best solution

Trace whether the new-session flow's eager `connection.createSession` (baseAgentHostSessionsProvider.ts ~L2577, which embeds `agent` only from `this._selectedAgent` at eager-create time) races ahead of the user's picker choice, and whether the deferred first-send path (`_sendNewSessionRequest` ~L5197, via `sendOptions.modeInfo`) actually threads a post-eager-create agent change into the backend's `provisional.agent` (copilotAgent.ts `_reserveChatBacking`/`_resolveAgentWhenMaterializing`) before materialization.

- **Likely files:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`
- **Validation:** An agent-host session test that creates a session, changes the selected custom agent after eager-create, sends a first message, and asserts the resulting SDK session-start config carries the picked agent's name/uri.
- **Trace:**

  > The eager `connection.createSession` call in baseAgentHostSessionsProvider.ts (~L2577) embeds `agent` only from `this._selectedAgent` at the moment the backend session is created; `setAgent()` on a still-draft NewSession (~L4569) only updates local observables per its own comment, deferring to first-send. Whether `_sendNewSessionRequest`'s `sendOptions.modeInfo` (~L5218) reliably updates the backend's already-created `provisional.agent` (copilotAgent.ts `_reserveChatBacking`/`_resolveAgentWhenMaterializing`) before materialization is the open question — do not assume either side already works; a maintainer should trace the modeInfo→backend path end to end before scoping the fix.
- **Open decisions:**
  - Should picking a custom agent on an already eagerly-created draft session issue an explicit backend RPC to update the provisional session's agent immediately, or should the eager-create itself be delayed until the agent selection settles?
  - Does the first-send `modeInfo` payload actually update the backend's `provisional.agent` before materialization today, or is that wiring incomplete/missing — this determines where the real fix belongs.

## Evidence

- **eager create embeds agent only at construction:** baseAgentHostSessionsProvider.ts ~L2577-2589: `connection.createSession({... ...(this._selectedAgent ? { agent: { uri: this._selectedAgent.uri } } : {}), ...})` runs once when the NewSession eagerly creates the backend session; there is no evidence it re-fires if the agent is picked afterward.
- **post-eager-create picks only update local state:** baseAgentHostSessionsProvider.ts `setAgent(sessionId, agent)` (~L4569-4577): for a still-draft NewSession it only calls `newSession.setSelectedAgent(agent)` (updates local observables), with a comment claiming the selection is 'forwarded to the host at first-message time' — no RPC updates the already-created backend session's agent at pick time.
- **backend provisional.agent is set once at creation:** copilotAgent.ts `_reserveChatBacking` sets `agent: options.agent` into `IProvisionalSession` at creation; the only other mutation site is `provisional.agent = agent` at line ~5190, whose trigger path (from `modeInfo`/first-send) I could not fully confirm reaches it for a NEW session before materialization.
- **reporter's own diagnostic evidence:** Reporter compared `events.jsonl` `system.message` payload lengths/content across two real sessions (a 7-line probe agent and a large custom agent) and found neither's distinctive text present, with the stock 'You are an AI assistant using Copilot SDK in VS Code.' prompt used instead — a credible, technical confirmed repro.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/317944 (closed, fixed in 1.125.0) covered only picker pre-selection at session creation, not this report's broader claim that an explicitly, manually selected agent's prompt is silently never applied — not the same symptom, so not a duplicate canonical.
