# Issue #336761 — Agent Host ignores the selected custom agent: picker resets to "Agent" and the agent prompt is never applied

[https://github.com/microsoft/vscode/issues/336761](https://github.com/microsoft/vscode/issues/336761)

## Summary

Well-diagnosed, credible bug: the reporter's session-state evidence (system.message length/content unchanged regardless of the selected custom agent, deselection events firing on send) shows the selected custom agent's prompt is never applied and the picker resets. I traced a plausible concrete cause in source but could not conclusively pin it down, so this stays open for deeper investigation rather than a close.

## Change summary

Selecting a custom agent in the Agent Host picker and sending a message silently drops the selection — the picker resets to "Agent" and the custom agent's system prompt never reaches the model.

## Best solution

Trace why `message.agent` ends up unresolved/undefined on the first send after picking a custom agent — likely a mismatch between how the outgoing draft's agent URI is derived (`agentHostSessionHandler.ts`'s `_inputStateToDraft`, which uses the raw `mode.id`) versus how `CopilotAgent._resolveAgentName` matches it against the SDK's plugin/agent snapshot (`copilotAgent.ts`), or a race where that snapshot hasn't yet been updated with the newly picked agent when `changeAgent` fires on send.

## Evidence

- **reporter diagnostics:** events.jsonl shows the system.message event length/content is identical (~56.8k chars, stock 'You are an AI assistant using Copilot SDK in VS Code.' preamble) whether a 7-line probe agent or a large custom agent is selected — nothing from the agent file is concatenated into the prompt.
- **changeAgent call site:** src/vs/platform/agentHost/node/agentSideEffects.ts:2002 calls `agent.chats.changeAgent(chatUri, message.agent, ...)` on every send; if `message.agent` is undefined the backend treats this as a deselect (copilotAgent.ts's `_changeAgentOnce` → `entry.setAgent(undefined)`), matching the reporter's observed 'deselection event fires' symptom.
- **possible URI derivation mismatch:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:6019 (`_inputStateToDraft`) builds the outgoing agent URI from the raw `state.mode.id`, while agentHostModeSynchronizer.ts's `_agentUriFromMode` prefers `mode.uri` decoded via `fromAgentHostUri`; `CopilotAgent._resolveAgentName` (copilotAgent.ts:2852) matches against `plugin.agents[].uri.toString()` from the SDK's active snapshot — any mismatch there silently returns `undefined` and clears the agent.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/317944 covers picker *pre-selection* on session creation and is already closed/verified for 1.125.0; this report is about an explicitly, manually selected agent being dropped on send, which is broader and not covered by that fix.
- **second report:** A commenter reports a related but distinct symptom — a custom agent disappearing entirely from the picker/settings UI despite the file still existing — which may share a root cause in custom-agent discovery/sync but isn't confirmed as the same defect.
