# Issue #340383 — Allow editor font settings to be scoped by file encoding

[https://github.com/microsoft/vscode/issues/340383](https://github.com/microsoft/vscode/issues/340383)

## Summary

Keep open for the community review that began on October 26. Current configuration supports language-specific fonts, not encoding-specific fonts, and the older file-extension settings request does not cover the same selection criterion.

## Change summary

Allow editor.fontFamily to vary with a file’s detected or selected encoding independently of its language mode.

## Best solution

Let the Backlog Candidates process establish demand before expanding configuration semantics. If accepted, support encoding-dependent font selection while preserving language mode and ordinary font settings for other encodings.

## Evidence

- **Existing capability and remaining gap:** src/vs/editor/common/config/editorOptions.ts:6415-6418 registers fontFamily as a string setting. TextResourceConfigurationService._getValue in src/vs/editor/common/services/textResourceConfigurationService.ts resolves settings using resource and overrideIdentifier derived from the language; it does not use the file encoding. Language overrides therefore cannot select different fonts for otherwise equivalent files with different encodings.
- **Encoding settings are not font selectors:** src/vs/workbench/contrib/files/browser/files.contribution.ts:190-203 registers files.encoding and files.autoGuessEncoding for reading/writing and encoding detection, with language-overridable scope. Neither provides an encoding-based override for editor.fontFamily.
- **Related request is not a verified duplicate:** https://github.com/microsoft/vscode/issues/35350 is open and requests settings selected by file extension while preserving language mode. This report instead selects fonts by detected or selected encoding, which can differ between files sharing the same extension; the older issue does not establish coverage of that requirement.
