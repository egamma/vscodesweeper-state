# Issue #1214 — Support regex in files.exclude => when

[https://github.com/microsoft/vscode/issues/1214](https://github.com/microsoft/vscode/issues/1214)

## Summary

This remains an accepted, well-supported feature request: current main still treats the `when` value as one exact sibling filename, so a single rule cannot cover both `.ts` and `.tsx`. This issue is the canonical tracker, with several later reports already closed into it.

## Change summary

Allow a `files.exclude` sibling `when` clause to match alternatives so generated JavaScript is hidden when either a corresponding TypeScript or TSX file exists.

## Best solution

Give sibling `when` clauses an explicit multi-pattern syntax consistent across Explorer and Search, allowing one exclusion entry to test for `.ts` or `.tsx` siblings without duplicate JSON keys or pattern-key workarounds.

## Plan brief

- **Likely files:** `src/vs/base/common/glob.ts`, `src/vs/base/test/common/glob.test.ts`, `src/vs/workbench/contrib/files/browser/files.contribution.ts`, `src/vs/workbench/contrib/search/browser/search.common.contribution.ts`
- **Validation:** Add a glob unit test proving one sibling clause excludes `foo.js` when either `foo.ts` or `foo.tsx` exists, does not exclude it for unrelated siblings, and behaves identically for the shared Explorer/Search expression parser.
- **Behavior:**

  > A single exclusion rule can hide a generated file when any of several corresponding source-file patterns exists. The central acceptance case is that `foo.js` is excluded when either `foo.ts` or `foo.tsx` is a sibling, while remaining visible when neither exists. Explorer and Search must interpret the supported sibling syntax consistently, and existing exact-name `when` clauses must retain their behavior.
- **Trace:**

  > Sibling exclusions are represented by `SiblingClause` and evaluated in `parseExpressionPattern` in src/vs/base/common/glob.ts. Current evaluation replaces `$(basename)` and performs one exact `hasSibling` lookup; src/vs/base/test/common/glob.test.ts covers only exact sibling names. The setting schemas in src/vs/workbench/contrib/files/browser/files.contribution.ts and src/vs/workbench/contrib/search/browser/search.common.contribution.ts expose the same single-string contract. Later requests https://github.com/microsoft/vscode/issues/35375 and https://github.com/microsoft/vscode/issues/78652 were consolidated here. Keep the boundary to sibling-clause syntax and evaluation; do not change ordinary exclusion-key glob semantics or unrelated file-nesting behavior.
- **Open decisions:**
  - Should the public `when` contract use glob syntax, regular expressions, or an array of exact sibling patterns? The choice affects user-authored settings, validation, documentation, and backward-compatible interpretation.

## Evidence

- **current source:** In src/vs/base/common/glob.ts, `SiblingClause.when` remains a single string, and `parseExpressionPattern` only substitutes `$(basename)` before passing the resulting literal name to `hasSibling`; it does not parse the right-hand side as regex or glob syntax.
- **configuration surface:** src/vs/workbench/contrib/files/browser/files.contribution.ts and src/vs/workbench/contrib/search/browser/search.common.contribution.ts still describe `when` as one string containing `$(basename)`, with no alternative-pattern capability.
