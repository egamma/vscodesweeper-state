# Issue #201519 — `DEL` appearing after dead key along with Ctrl key actions

[https://github.com/microsoft/vscode/issues/201519](https://github.com/microsoft/vscode/issues/201519)

## Summary

The existing DEL-character workaround (commit be0b619bbfe, fixing #165982) only covers the case where a single DEL character is typed with no replacement. The reporter's steps — dead key + Ctrl+V + Ctrl+Backspace + type — likely hit a different code path not guarded by that check. No further fix has landed on main for this scenario.

## Change summary

A DEL control character (U+007F) visibly appears in the editor after specific dead-key + Ctrl-key action sequences on Windows with the US International keyboard layout.

## Best solution

Extend the existing DEL-filtering guard in `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContextInput.ts` (around line 338–347) to also cover the case where the DEL character appears in combination with `replacePrevCharCnt > 0` or multi-character input after dead-key composition state is interrupted by Ctrl shortcuts.
