# Issue #328434 — Enhanced support for legacy terminal shells

[https://github.com/microsoft/vscode/issues/328434](https://github.com/microsoft/vscode/issues/328434)

## Summary

A real Copilot terminal-context gap remains for unsupported shells such as TCSH. Existing buffering is neither configurable nor exposed as automatic chat context, and agent-created terminals do not inherit runtime changes from the active shell.

## Change summary

Provide bounded terminal-output context and active-shell environment continuity for Copilot when full shell integration is unavailable.

## Best solution

Route this to the chat-terminal owners to design an opt-in, bounded fallback that exposes recent active-terminal output without command detection. Treat environment transfer separately, with explicit user consent and clear limits where an unsupported shell cannot report its current environment.

## Evidence

- **unsupported shell:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts documents automatic shell integration support for bash, fish, pwsh, and zsh on Linux/macOS, but not TCSH.
- **partial existing capability:** extensions/copilot/src/platform/terminal/vscode/terminalBufferListener.ts already listens to onDidWriteTerminalData and retains 40 output events, while getBufferForTerminal returns up to 16,000 characters; there is no requested line-count setting or automatic chat-context integration.
- **current exposure:** The active terminalBuffer is consumed by the developer workspace-state snapshot in extensions/copilot/src/extension/conversation/vscode-node/logWorkspaceState.ts, while the built-in get_terminal_output tool is scoped to commands previously started by run_in_terminal rather than arbitrary active-terminal output.
- **environment boundary:** src/vs/platform/agentHost/node/agentHostTerminalManager.ts creates agent terminals from the agent-host process environment, so environment changes sourced inside an existing interactive TCSH process are not inherited.
- **canonical search:** Repository searches for TCSH, active-terminal inheritance, and Copilot terminal output found no separate open issue that clearly owns both requested capabilities.
