# Issue #343935 — Composer's pickers load is slow without indication on app start

[https://github.com/microsoft/vscode/issues/343935](https://github.com/microsoft/vscode/issues/343935)

## Summary

Keep open: the merged picker-polish PR explicitly leaves this startup-loading concern unresolved. Current source has individual loading affordances but does not establish that the composer's progressively appearing controls are covered.

## Change summary

Make new-session composer pickers appear immediately at startup or indicate that additional controls are still loading.

## Best solution

Establish a consistent startup-readiness presentation for the new-session composer so delayed picker availability is understandable without delaying already usable controls. The maintainer should settle whether this uses stable placeholders or a shared loading indication.
