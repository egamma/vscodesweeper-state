# Issue #339926 — Copilot integrated browser cannot complete authentication when browser-compliance policies are enforced

[https://github.com/microsoft/vscode/issues/339926](https://github.com/microsoft/vscode/issues/339926)

## Summary

Real, newly-reported gap: the integrated browser (an embedded Chromium, not registered with the OS/identity broker) gets rejected by Azure AD conditional-access/device-compliance policies that only trust managed browsers. One other user confirmed seeing it, but the report is a day old with no maintainer input yet, so this stays open for triage rather than being routed or closed.

## Change summary

Agent-opened sign-in pages in the integrated browser fail when the target enforces browser/device-compliance conditional-access policies, with no guidance or fallback offered to the user.

## Best solution

Detect the compliance-denial response (or let the user trigger it proactively) and offer a clear path to continue the sign-in in the system browser — the integrated browser already has an 'Open in External Browser' command (src/vs/workbench/contrib/browserView/electron-browser/features/browserNavigationFeatures.ts) that could be surfaced contextually here; full broker/WAM integration is a larger, separate investment.
