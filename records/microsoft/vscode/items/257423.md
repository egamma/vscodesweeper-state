# Issue #257423 — Git:Autofetch failing for private Github repositories

[https://github.com/microsoft/vscode/issues/257423](https://github.com/microsoft/vscode/issues/257423)

## Summary

The manual-versus-automatic fetch failure remains explained by current source: silent fetch exits before consulting VS Code's registered credential providers. Keep this Git bug open; the older related authentication issue does not establish the same observable symptom.

## Change summary

Automatic fetching of private GitHub HTTPS repositories fails even when manual fetching succeeds through VS Code's GitHub authentication.

## Best solution

Allow background fetch to obtain already-available GitHub credentials without opening authentication or password dialogs. Establish a noninteractive credential-provider boundary rather than removing silent-fetch protection wholesale.

## Plan brief

- **Likely files:** `extensions/git/src/askpass-main.ts`, `extensions/git/src/askpass.ts`, `extensions/git/src/api/git.d.ts`, `extensions/github/src/credentialProvider.ts`, `extensions/github/src/auth.ts`, `extensions/github/src/typings/git.d.ts`
- **Validation:** Establish executable coverage showing that silent fetch succeeds with an existing authorized GitHub session and a private HTTPS remote, but invokes neither password input nor sign-in/account-selection UI when credentials are unavailable. Verify manual fetch retains interactive authentication and SSH silent-fetch behavior remains unchanged.
- **Behavior:**

  > With git.autofetch enabled, a private GitHub HTTPS repository whose manual fetch succeeds using an existing VS Code GitHub session should also fetch automatically using that session. Background fetching must not open password, account-selection, or sign-in dialogs. Acceptance must cover both available and unavailable credentials, while preserving interactive manual fetch and existing SSH behavior.
- **Trace:**

  > AutoFetcher.run in extensions/git/src/autofetch.ts passes silent: true through Repository._fetch to the Git process, where extensions/git/src/git.ts sets VSCODE_GIT_FETCH_SILENT. extensions/git/src/askpass-main.ts exits on that flag before IPC, preventing Askpass.handleAskpass in extensions/git/src/askpass.ts from consulting credential providers; the reporter's paired logs directly match this path. The built-in GitHub provider in extensions/github/src/credentialProvider.ts calls getSession in extensions/github/src/auth.ts, which currently uses createIfNone: true and can request interaction. CredentialsProvider is exposed through extensions/git/src/api/git.d.ts and mirrored in the GitHub extension typings, so arbitrary registered providers cannot be assumed noninteractive. The unresolved boundary is how background credential acquisition is represented without changing existing providers' interactive behavior. https://github.com/microsoft/vscode/issues/182316 is related but does not own this specific silent-only failure; https://github.com/microsoft/vscode/issues/162508 supplies related background-prompting context.
- **Open decisions:**
  - Should noninteractive background credential acquisition be supported through the exported Git credential-provider contract for all providers, or remain limited to the built-in GitHub integration?
