# Issue #26604 — Marked brackets range on scrollbar

[https://github.com/microsoft/vscode/issues/26604](https://github.com/microsoft/vscode/issues/26604)

## Summary

Keep open: current bracket matching marks individual bracket endpoints, not the requested enclosing ranges with distinct active and outer-scope colors. The accepted Backlog request still needs UX design; the related ruler request does not clearly own its full nested-range behavior.

## Change summary

Show the active enclosing bracket range and its outer enclosing ranges in the scrollbar overview ruler, using a primary color for the active scope and gray for outer scopes.

## Best solution

Design an overview-ruler representation that communicates active and enclosing bracket ranges without obscuring existing markers. Coordinate with the related bracket-ruler request while preserving this issue's distinct nested-scope requirements; extension prototyping remains a useful way to evaluate the presentation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** In a document containing three nested bracket pairs spanning multiple screens, place the cursor inside the innermost block away from any bracket. Verify the approved overview-ruler design identifies its full range and the enclosing ranges distinctly, updates when the cursor moves between scopes, and remains legible alongside diagnostic and search markers.
- **Behavior:**

  > The request is to identify long enclosing code-block boundaries from the scrollbar without navigating to their brackets. The active innermost bracket range should be visually distinct from its enclosing ranges, including when the cursor is inside the block rather than beside a bracket. Acceptance should exercise multiple nesting levels, movement between scopes, and coexistence with existing overview-ruler markers. Existing bracket highlighting and editor guides should retain their behavior.
- **Trace:**

  > BracketMatchingController in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts emits two endpoint decorations through _updateBrackets. In _recomputeBrackets, direct bracket matches receive overview-ruler decoration options, while enclosing matches found for editor.matchBrackets='always' receive options without ruler markers. The configuration in src/vs/editor/common/config/editorOptions.ts exposes bracket matching, colorization, and guides but no enclosing-range ruler presentation. The public decoration API in src/vscode-dts/vscode.d.ts exposes overviewRulerColor and overviewRulerLane, consistent with the maintainer's extension-prototyping suggestion. https://github.com/microsoft/vscode/issues/131078 concerns related bracket-ruler markers but does not settle this request's full nested-range design. Uncertainty begins at the user-visible representation and activation policy, not at whether endpoint matching already provides the requested capability.
- **Open decisions:**
  - What overview-ruler presentation should distinguish the active full bracket range from overlapping outer ranges while keeping diagnostics and other markers legible?
  - Should enclosing-range indicators be opt-in through a separate setting or follow the existing bracket-matching configuration?

## Evidence

- **Requested behavior:** https://github.com/microsoft/vscode/issues/26604 requests cursor-inside-brackets range indicators, with the innermost scope in a primary color and all enclosing scopes in gray; endpoint markers alone do not satisfy this.
- **Current source:** src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts: BracketMatchingController._updateBrackets creates separate decorations for brackets[0] and brackets[1]. _recomputeBrackets uses overview-ruler decorations for a directly matched bracket, but explicitly chooses _DECORATION_OPTIONS_WITHOUT_OVERVIEW_RULER when editor.matchBrackets='always' finds enclosing brackets. It does not decorate full enclosing ranges or enumerate outer scopes.
