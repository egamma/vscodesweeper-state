# Issue #336233 — Extension host utility process crashes intermittently (exit code 134) when launching Extension Development Host via F5 (js-debug auto-attach)

[https://github.com/microsoft/vscode/issues/336233](https://github.com/microsoft/vscode/issues/336233)

## Summary

Still an open, well-corroborated bug: multiple independent Windows users (reporter, WilliamSmithEdward, datho7561, cesaryuan) confirm the extension host utility process aborts with code 134 within ~1s of an F5 launch, specifically on the js-debug auto-attach path, while Ctrl+F5 and manual CLI+attach are stable. A maintainer (connor4312) is actively engaged but the exact root cause isn't yet confirmed from a native crash dump, so this stays open pending further diagnosis — not a close.

## Change summary

F5 (Extension Development Host via js-debug auto-attach) intermittently/consistently crashes the extension host utility process with exit code 134 on Windows, while non-debug launch paths are stable.

## Best solution

Needs a confirmed native crash trace or js-debug-side diagnosis tying the SIGABRT to the IPv6/localhost inspector-attach path (js-debug PR https://github.com/microsoft/vscode-js-debug/pull/2417, merged 2026-09-21, addressed a related 'debugger attach retries on Node 24.20' issue, and a related IPv6 ECONNREFUSED report was vscode-js-debug issue https://github.com/microsoft/vscode-js-debug/issues/2419) — but that PR's diff only touches tests/deps, not production retry code, so it's not yet clear it actually fixes this crash (vs. the separate hang/ECONNREFUSED symptom). A maintainer or the js-debug team should confirm whether the utility-process abort is the same root cause or a distinct native crash before this can be closed as fixed.
