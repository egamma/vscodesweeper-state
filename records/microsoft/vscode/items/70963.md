# Issue #70963 — Git - .gitignore'd files sometimes not greyed-out

[https://github.com/microsoft/vscode/issues/70963](https://github.com/microsoft/vscode/issues/70963)

## Summary

Keep open: multiple reporters confirm intermittent loss of ignored-file decorations, including a June 2026 report. Related fixes address particular path configurations, but neither a fix covering the full report nor an eligible canonical duplicate was established.

## Change summary

Files and folders ignored by Git intermittently lose their grey Explorer decoration until the window reloads or .gitignore is saved.

## Best solution

Isolate the remaining decoration failure in the built-in Git integration and make ignored-file presentation update reliably without reloading the window. Distinguish stale decoration results from repository-selection changes and Git executable/path failures before choosing a fix.

- **Behavior:**

  > An untracked file or folder ignored by its applicable Git repository should display the ignored-resource decoration consistently in Explorer. Reporters describe that decoration disappearing and returning after a reload or .gitignore save. First establish a current-main reproduction and the applicable repository for each affected resource. Acceptance should cover the isolated trigger without requiring a window reload, while preserving normal tracked-file and nested-repository behavior.
- **Trace:**

  > GitIgnoreDecorationProvider in extensions/git/src/decorationProvider.ts obtains a repository through Model.getRepository, batches requests, and resolves decorations from Repository.checkIgnore. Its invalidation subscriptions cover ignore-file saves and repository opening/closing, whereas ordinary Git status decorations also respond to onDidRunGitStatus. Model.getOpenRepository in extensions/git/src/model.ts chooses the deepest matching open repository, and Repository.checkIgnore in extensions/git/src/repository.ts delegates to git check-ignore after filtering paths by repository root. These paths suggest distinct stale-state and repository-selection cases, but neither was conclusively diagnosed through read-only inspection. Preserve Git's tracked-file semantics and legitimate nested-repository ownership; do not assume every comment shares one cause. Related refresh investigation is at https://github.com/microsoft/vscode/issues/239851, while the narrower network-symlink fix is documented at https://github.com/microsoft/vscode/issues/229661.

## Evidence

- **Confirmed reports and recovery triggers:** https://github.com/microsoft/vscode/issues/70963 contains repeated confirmations across macOS, Windows, and Linux. The March 9, 2023 comment supplies a nested-repository trigger; the February 8, 2024 comment reports recurrence after modifying another file; the June 22, 2026 comment reports recovery after saving .gitignore. These establish reported reproductions, not a verified current-main runtime reproduction.
- **Current ignore-decoration path:** extensions/git/src/decorationProvider.ts: GitIgnoreDecorationProvider.provideFileDecoration selects model.getRepository(uri), batches paths, and returns the ignoredResourceForeground decoration according to Repository.checkIgnore. Its invalidation events are saves of .gitignore or .git/info/exclude and repository opening/closing; unlike GitDecorationProvider, it does not subscribe to repository.onDidRunGitStatus. This is consistent with save-based recovery but does not conclusively establish the intermittent root cause.
- **Repository-selection boundary:** extensions/git/src/model.ts: Model.getOpenRepository selects the deepest matching open repository by root-path length. extensions/git/src/repository.ts: Repository.checkIgnore filters paths to descendants of that repository root and runs git check-ignore -v -z --stdin. Opening a nested repository can therefore change which repository supplies ignore results; that scenario must be distinguished from stale decoration state.
- **Related refresh work is not a canonical duplicate:** https://github.com/microsoft/vscode/issues/239851 is open but was created in 2025, after this issue. It requests broader refresh behavior, and its reporter confirms Git: Refresh did not restore ignored-file decorations at https://github.com/microsoft/vscode/issues/239851#issuecomment-2787665081. The maintainer distinguishes Source Control refresh from Explorer refresh at https://github.com/microsoft/vscode/issues/239851#issuecomment-2788712706.
