# Issue #320338 — For port forwarding in WSL, use `localhost` rather than an internet address or `192.168`.

[https://github.com/microsoft/vscode/issues/320338](https://github.com/microsoft/vscode/issues/320338)

## Summary

Feature request to show a public/internet-accessible address instead of localhost in the Ports panel when using WSL. The community backlog-candidates process is running (2/20 upvotes, ~13 days remaining). Port forwarding intentionally maps to localhost by design; exposing a public address would require a tunnel provider (e.g. dev tunnels). Keeping open for the community process.

## Change summary

Show an internet-routable IP address rather than localhost in the Ports panel for WSL port forwarding.

## Best solution

This likely belongs in the remote/tunnel-provider layer rather than base port forwarding. The existing tunnel privacy/public mechanism (`TunnelPrivacyId`) supports public tunnels when a tunnel provider is registered (e.g. dev tunnels), but the basic WSL forwarding intentionally binds to localhost. The reporter may benefit from using VS Code's dev tunnels feature or a third-party tunnel service. If the team wants to surface public tunnel options more prominently in WSL, the work would touch `src/vs/workbench/contrib/remote/browser/tunnelView.ts` and the tunnel provider registration.
