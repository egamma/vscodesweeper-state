Still present on main — the test writes a real temp directory and the rmSync teardown races with Windows file-handle release, causing intermittent EPERM. No fix commit references this issue. Keeping open for the area owner.

## Change summary

The "applies and persists root config changes from clients" unit test flakes on Windows CI with EPERM during temp-directory cleanup.

## Best solution

Eliminate the on-disk temp directory entirely: use the in-memory `IFileService` already available in the test (or mock the config persistence path) so the test never calls `rmSync`. The existing `maxRetries: 3, retryDelay: 100` mitigation is insufficient against Windows antivirus / indexer file locks on CI.
