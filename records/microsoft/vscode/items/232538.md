# Issue #232538 — Give more control over syncing rapidly updating documents with extensions

[https://github.com/microsoft/vscode/issues/232538](https://github.com/microsoft/vscode/issues/232538)

## Summary

Still an open, valid API feature request. The initial fix attempt was reverted (PR #233821), and the follow-up PR #233455 proposing a proper solution via controllable `shouldSynchronizeModel` remains open but stale. The underlying need — throttling or deferring extension document sync for rapidly updating models like streaming chat code blocks — is unaddressed on current main.

## Change summary

Allow extensions or internal consumers to control when rapidly updating text models are synchronized to the extension host, avoiding unnecessary churn during streaming.

## Best solution

Land a mechanism to control `shouldSynchronizeModel` (or equivalent) so that documents like streaming chat code blocks can defer extension sync until content is stable. The open PR https://github.com/microsoft/vscode/pull/233455 is one implementation candidate; a maintainer should decide whether to revive it or take a different approach. The parent issue https://github.com/microsoft/vscode/issues/230326 tracks the user-facing symptom.
