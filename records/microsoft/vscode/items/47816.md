# Issue #47816 — Use fresh environment block on new terminals in Windows

[https://github.com/microsoft/vscode/issues/47816](https://github.com/microsoft/vscode/issues/47816)

## Summary

Legitimate, well-supported feature request (123 upvotes) for refreshing Windows environment variables without restarting VS Code. The Linux/macOS side was addressed via `terminal.integrated.inheritEnv` (issue #70248), but Windows remains unresolved — `getEnvironment()` is `@memoize`d in `localTerminalBackend.ts`, so the process environment is cached for VS Code's lifetime with no Windows-specific refresh path.

## Change summary

On Windows, environment variable changes (PATH, new tools) are not picked up by new terminal instances until all VS Code processes are restarted.

## Best solution

Implement a Windows-specific environment refresh mechanism — e.g., re-reading `HKCU\Environment` and `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` from the registry when spawning a new terminal — so that `getEnvironment()` in `localTerminalBackend.ts` can provide a fresh environment block instead of returning the memoized process environment. This parallels the login-shell approach used on macOS/Linux via `inheritEnv`.
