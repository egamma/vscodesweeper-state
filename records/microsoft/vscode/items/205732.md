Still present on main: the GitHub rate-limit error in the issue reporter's similar-issues search is silently swallowed with only a `console.warn` — no user-facing message or retry guidance is shown. Team-authored polish item; keeping open.

## Change summary

When the GitHub search API rate limit is hit while searching for similar issues in the issue reporter, only a console warning is logged — no user-facing feedback or wait-time estimate is provided.

## Best solution

In `src/vs/workbench/contrib/issue/browser/baseIssueReporterService.ts`, the `searchGitHub` method's catch handler (line ~928) should either surface a localized message in the similar-issues area telling the user the rate limit was hit (with a rough wait estimate or retry link), or — as the internal comment suggests — suppress the warning entirely so users aren't confused by silent failures. The team should decide which path to take.
