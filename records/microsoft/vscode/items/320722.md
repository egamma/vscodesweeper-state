# Issue #320722 — Provide keyboard shortcuts to scroll chat history when the chat panel is open

[https://github.com/microsoft/vscode/issues/320722](https://github.com/microsoft/vscode/issues/320722)

## Summary

A real keyboard-access gap remains on current main: existing prompt-navigation commands move focus into the transcript instead of scrolling it while composition focus stays in the chat input. The request is clear, but the default shortcuts and scrolling granularity need a maintainer decision.

## Change summary

Add keyboard commands that scroll the chat transcript up and down while focus remains in the chat input.

## Best solution

Provide chat transcript scrolling commands with conflict-free default keybindings that work from the chat input without moving focus, and document them in Chat Accessibility Help.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts`, `src/vs/workbench/contrib/chat/browser/chat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`
- **Validation:** Add a targeted chat widget/action test that focuses the input, invokes each transcript-scroll command, and asserts that scrollTop changes in the requested direction while the input editor retains focus.
- **Behavior:**

  > While composing in the chat input, users can invoke keyboard commands to move the visible transcript upward or downward without moving keyboard focus or changing the draft. Scrolling clamps at the transcript boundaries and remains usable during long conversations. Existing request-history and prompt-navigation shortcuts retain their current behavior. Acceptance requires tests proving both scroll movement and preserved input focus.
- **Trace:**

  > Current prompt navigation is registered in src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts and calls IChatWidget.focus followed by reveal, so it intentionally transfers focus to a transcript item. Transcript position is maintained by ChatListWidget in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts through scrollTop, scrollHeight, and renderHeight; ChatWidget already delegates some of that state, while IChatWidget in src/vs/workbench/contrib/chat/browser/chat.ts does not expose a dedicated focus-preserving transcript-scroll operation. ChatContextKeys.inChatInput is available for input-scoped keybindings. Keep request-history navigation, prompt-to-prompt navigation, transcript item focus, and automatic streaming-scroll behavior outside the requested behavior unchanged. Any commands must also be represented in src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts.
- **Open decisions:**
  - Should the default commands scroll by a full viewport, by a smaller fixed increment, or provide separate line and page commands?
  - Which default keybindings should be used so the commands remain available in the input editor without conflicting with text editing, request-history navigation, or the existing Previous/Next User Prompt bindings?

## Evidence

- **existing capability is incomplete:** src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts registers Previous/Next User Prompt, but navigateUserPrompts calls widget.focus(targetPrompt) before revealing it, moving focus away from the input rather than preserving composition focus.
- **scrolling surface exists:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts exposes scrollTop, scrollHeight, and renderHeight over the transcript tree; src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts already delegates transcript scroll state.
- **input-focus context exists:** src/vs/workbench/contrib/chat/common/actions/chatContextKeys.ts defines ChatContextKeys.inChatInput specifically for commands active while focus is in the chat input.
- **no canonical found:** Focused open-issue searches for chat transcript scrolling, Page Up/Page Down, and scrolling while the chat input is focused found no older issue owning this behavior.
- **accessibility documentation:** src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts documents chat keyboard interaction and would need to describe any new transcript-scrolling commands.
