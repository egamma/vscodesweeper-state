# Issue #308918 — "retry" on async terminal steering message causes it to rerender incorrectly

[https://github.com/microsoft/vscode/issues/308918](https://github.com/microsoft/vscode/issues/308918)

## Summary

Team-authored issue, keeping open. The bug is confirmed in the source: `resendRequest` in `chatServiceImpl.ts` builds `resendOptions` without carrying over `isSystemInitiated`, `systemInitiatedLabel`, or `terminalExecutionId` from the original request model, so retried async terminal steering messages lose their compact rendering.

## Change summary

Retrying a failed async terminal steering message causes it to render as a normal chat request instead of the compact terminal notification style.

## Best solution

In `ChatService.resendRequest` (src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts ~line 977), add `isSystemInitiated: request.isSystemInitiated`, `systemInitiatedLabel: request.systemInitiatedLabel`, and `terminalExecutionId: request.terminalExecutionId` to the `resendOptions` object so the re-sent request preserves its special rendering type.
