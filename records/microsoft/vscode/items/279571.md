# Issue #279571 — Suggest import NES for a not-found symbol even if I didn't type it

[https://github.com/microsoft/vscode/issues/279571](https://github.com/microsoft/vscode/issues/279571)

## Summary

A real import-NES gap remains: current main limits eligible diagnostics to those intersecting or touching a recent edit, rather than all missing-symbol diagnostics caused by that edit. This team-authored On Deck feature request should remain open for design and implementation.

## Change summary

Offer import next edit suggestions when an edit makes an existing symbol unresolved, even when the user did not type the symbol itself.

## Best solution

Import NES should recognize newly introduced missing-symbol diagnostics caused by edits such as extracting a method or removing a member qualifier, while preserving rejection, undo, proximity, and language-specific safeguards.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/inlineEdits/vscode-node/features/diagnosticsCompletionProcessor.ts`, `extensions/copilot/src/extension/inlineEdits/test/vscode-node/diagnosticsCollection.spec.ts`
- **Validation:** Add a processor-level test that starts with `this.foo`, applies an edit removing `this.` after `foo` has been extracted and exported elsewhere, publishes the resulting missing-symbol diagnostic, and verifies that an import diagnostic completion is offered without enabling suggestions for unrelated pre-existing diagnostics.
- **Behavior:**

  > When an edit makes an existing identifier unresolved, import NES should offer the same valid import suggestion it would offer if that identifier had just been typed. The extraction scenario from the issue—changing `this.foo` to `foo` after exporting `foo` from another file—must produce an import suggestion. Unrelated diagnostics that predate the triggering edit must not suddenly become suggestions, and existing rejection and undo behavior must remain unchanged.
- **Trace:**

  > DiagnosticsCompletionProcessor in extensions/copilot/src/extension/inlineEdits/vscode-node/features/diagnosticsCompletionProcessor.ts gathers diagnostics in `_getDiagnostics` and then calls `_filterDiagnosticsByRecentEditNearby`. That filter compares diagnostic ranges only with `WorkspaceDocumentEditHistory.getRecentEdits(...).edits.getNewRanges()`, so it models textual overlap rather than whether an edit caused a diagnostic to appear. ImportDiagnosticCompletionProvider in extensions/copilot/src/extension/inlineEdits/vscode-node/features/diagnosticsBasedCompletions/importDiagnosticsCompletionProvider.ts already recognizes supported missing-import diagnostics and obtains language code actions after the processor admits them. The uncertainty starts at reliably correlating asynchronously published diagnostics with the edit or refactor that introduced them, including multi-file operations. Keep provider ranking, cursor-distance limits, rejected-import tracking, undo protection, and language-specific import selection outside the behavioral change.
