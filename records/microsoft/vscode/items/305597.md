# Issue #305597 — Bad contrast for search bar options in dark theme

[https://github.com/microsoft/vscode/issues/305597](https://github.com/microsoft/vscode/issues/305597)

## Summary

The current VS Code Dark palette still provides very little contrast between enabled search options and their surroundings. Keep this report open: the source confirms the weak state indicator, and no verified canonical or fixing commit establishes that it is resolved.

## Change summary

Make enabled search options clearly distinguishable from disabled options in the built-in VS Code Dark theme.

## Best solution

Restore a clearly visible selected-state treatment through the theme's shared inputOption colors, preserving the separate keyboard-focus indicator. Agree on the theme-consistent visual treatment and verify it across search and editor find controls.

Verify enabled options remain clearly distinguishable from disabled options, measure the agreed state-indicator contrast, and separately verify keyboard focus, hover and high-contrast themes remain distinguishable.
- **Behavior:**

  > Enabled search options are difficult to distinguish from disabled options in VS Code Dark, even though their glyphs remain readable. Enabled state must remain clearly visible when the control is neither hovered nor focused. Acceptance should cover case-sensitive, whole-word and regex options in Search and editor Find, while preserving independent keyboard-focus indication and existing toggle behavior.
- **Trace:**

  > The Dark 2026 theme is registered in extensions/theme-defaults/package.json and loads extensions/theme-defaults/themes/2026-dark.json. Its selected fill #313233 and border #2A2B2C have approximately 1.36:1 and 1.23:1 contrast respectively against input.background #191A1B. defaultToggleStyles in src/vs/platform/theme/browser/defaultStyles.ts carries these tokens into the find-input toggles, and Toggle.applyStyles in src/vs/base/browser/ui/toggle/toggle.ts applies them when checked. The shared CSS provides an independent focus-visible border; do not conflate selection with focus or change search semantics. https://github.com/microsoft/vscode/issues/208199 concerns focus visibility, while https://github.com/microsoft/vscode/issues/293405 supplies theme-design context and invites separate reports. The remaining uncertainty is the approved visual treatment and measurable contrast target, not whether the current source supplies weak selected-state contrast.
- **Open decisions:**
  - Should enabled input options retain a neutral selected treatment with stronger luminance contrast, or use a restrained accent treatment, and what minimum state-indicator contrast should the theme guarantee?
