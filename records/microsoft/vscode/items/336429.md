## Evidence

- **Confirmed reproduction and isolation:** https://github.com/microsoft/vscode/issues/336429#issuecomment-5703099572 documents reproduction on the exact reported Insiders build and standalone node-pty. Changing only msys-2.0.dll reduced a 2,048-character paste from 21.49 seconds to 1.87 seconds inside VS Code and a queued 256-key left-arrow burst from 3.66 seconds to 671 milliseconds.
- **Native root cause:** The same maintainer comment identifies repeated console-input processing and process enumeration in MSYS2, introduced by https://github.com/git-for-windows/msys2-runtime/commit/c92d8015863d71c5210f3793df7b8f1af0d2e88d. The renderer was 95.26% idle; disabling shell integration or switching ConPTY implementations did not resolve the slowdown.
- **Upstream delivery remains pending:** Verified https://github.com/git-for-windows/msys2-runtime/pull/141 is open and unmerged, and https://github.com/git-for-windows/git/issues/6402 is open. https://github.com/msys2/msys2-runtime/pull/361 merged on 2026-09-08, but that MSYS2 backport does not establish delivery in the reporter's Git for Windows installation.
- **Independent matching report:** https://github.com/msys2/msys2-runtime/issues/358 reports slow pasting and full-core Bash/Zsh CPU usage with MSYS2 3.6.10, absent with 3.6.9. It is closed and external, so it is supporting upstream evidence, not an open canonical for a duplicate close.
- **Current checkout boundary:** src/vs/platform/terminal/node/terminalProcess.ts:316 launches the configured shell through node-pty; TerminalProcess.input at lines 485–492 forwards input to the pty. This boundary is consistent with the maintainer's renderer-free reproduction and does not establish a VS Code-owned fix. No code was executed or modified.
- **Remaining reporter confirmation:** https://github.com/microsoft/vscode/issues/336429#issuecomment-5703099572 requests git --version and uname -r because the investigation used Windows 11 and did not reproduce the exact Windows 10 timing or command-length-dependent cursor behavior. https://github.com/microsoft/vscode/issues/336429#issuecomment-5703133446 asks the reporter to confirm the upstream fix; no response is present.
- **Canonical search:** An open-issue search for Git Bash slowness returned this report and unrelated link, SCM, UI, and mouse-customization issues. No verified older microsoft/vscode canonical owns the same paste and cursor-delay symptom.
