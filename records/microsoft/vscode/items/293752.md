# Issue #293752 — Allow pre-loading skills for custom agents

[https://github.com/microsoft/vscode/issues/293752](https://github.com/microsoft/vscode/issues/293752)

## Summary

Keep open: local Chat still advertises skills for on-demand loading rather than preloading an agent's declared skill contents. Agent Host already forwards a skills field to the Copilot SDK, but that partial support does not establish completion across the requested VS Code custom-agent workflow.

## Change summary

Allow custom agents to declare skills whose instructions are loaded into their context automatically at startup.

## Best solution

Provide deterministic startup skill loading for VS Code custom agents, consistent with the SDK-backed path, while preserving existing discovery when no skills are declared. Keep preloading distinct from restricting which skills an agent can discover or invoke.

Cover direct selection and subagent invocation on the supported local and SDK-backed paths; an agent without declarations must retain existing discovery behavior. Existing converter tests establish forwarding only and are insufficient for this acceptance check.
- **Behavior:**

  > A custom agent can declare skills whose full instructions are available when that agent starts, without relying on the model to discover and retrieve them. The declared instructions must be present before the agent's first model action, including when invoked as a subagent. Agents without declarations retain existing skill discovery behavior. Preloading must not implicitly become an allow-list that hides unrelated skills.
- **Trace:**

  > The local custom-agent attribute registry in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts lacks a skills field, although the separate Claude-format registry documents one. ComputeAutomaticInstructions and the extension's AutomaticInstructionsCollector produce skill catalogs and ask the model to load relevant contents later. In contrast, toSdkCustomAgents in src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts already forwards skills, and CopilotSessionLauncher adopts those configs for SDK sessions; actual preload timing was not executed or verified. https://github.com/microsoft/vscode/pull/328237 was withdrawn without merging and distinguishes preloading from the availability restrictions requested by https://github.com/microsoft/vscode/issues/307630. The remaining investigation is the startup-context contract across local Chat and SDK-backed agents, not merely parsing another header. Preserve existing discovery, invocation controls and undeclared-agent behavior; do not expand this into skill isolation.
- **Open decisions:**
  - If a declared skill is missing, disabled or cannot be read, should agent startup fail, or continue with an explicit warning and the remaining skills?
