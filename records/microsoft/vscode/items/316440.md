# Issue #316440 — [Error] unhandlederror-TreeError [FileExplorer] Tree element not found: [object Object]

[https://github.com/microsoft/vscode/issues/316440](https://github.com/microsoft/vscode/issues/316440)

## Summary

The original `isCollapsed` failure path was fixed, but current stable telemetry confirms a distinct stale-node race in `AsyncDataTree.refreshNode`; the unguarded path remains on main, so the issue is still necessary.

## Change summary

Concurrent File Explorer tree refreshes can query a node after another structural update has removed it from the compressed tree model, producing an unhandled `TreeError`.

## Best solution

Revalidate inner-tree membership before `refreshNode` calls `this.tree.getNode(node)`, treating a refresh for a concurrently removed node as obsolete, and cover that ordering with a deterministic async-tree regression test. Coordinate this with https://github.com/microsoft/vscode/pull/331829, whose later guard addresses stale rendering but is too late for the `getNode` stack reported here.
