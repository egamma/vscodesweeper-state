# Issue #332995 — Do not derive model context from prompt and output token limits

[https://github.com/microsoft/vscode/issues/332995](https://github.com/microsoft/vscode/issues/332995)

## Summary

Traced on current main: both the model-picker hover and the context-usage widget compute total context as maxInputTokens + maxOutputTokens, which overstates the window for models (e.g. some BYOK/Ollama configs) whose prompt and output limits aren't meant to be summed — this matches the reporter's exact scenario.

## Change summary

Chat's model picker hover and context-usage widget derive 'max context' by summing maxInputTokens + maxOutputTokens instead of using a model's actual declared context window, overstating it for models where those limits aren't additive.

## Best solution

This needs an API/design decision, not just a UI tweak: the LanguageModelChatMetadata / vscode.LanguageModelChatInformation surface (src/vs/workbench/contrib/chat/common/languageModels.ts, src/vscode-dts/vscode.d.ts) has no distinct context-window field today — only maxInputTokens/maxOutputTokens. A maintainer should decide whether to add an optional total-context-window field to that (stable) API and have modelPickerHover.ts and chatContextUsageWidget.ts prefer it over the sum, with BYOK providers (e.g. ollamaProvider.ts) populating it.
