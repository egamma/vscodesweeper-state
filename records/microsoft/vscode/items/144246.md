# Issue #144246 — Indicate if Task Exited for both dependency tasks

[https://github.com/microsoft/vscode/issues/144246](https://github.com/microsoft/vscode/issues/144246)

## Summary

Keep open: current task statuses partially distinguish background-task completion, but waiting and exited tasks can still share the same error icon. The separate deemon exit-code problem was resolved upstream; that does not establish completion of this team-authored request for clearer lifecycle information.

## Change summary

Make the terminal overview clearly distinguish running or waiting dependency tasks from tasks whose processes have exited.

## Best solution

Make background-task lifecycle visible independently of diagnostic severity in the terminal tabs, while preserving useful completion results for ordinary compile tasks. Agree on the exited-state presentation before implementing it in the task terminal status contribution.

Manually run two dependency watch tasks in split terminals and verify that their exited states are distinguishable in the terminal overview without relying on hover, while ordinary compile-task result indicators remain useful.
- **Behavior:**

  > The terminal overview should make it easy to distinguish a dependency watcher that is still alive and waiting from one whose process has exited. Diagnostic success or failure must not falsely imply that a watcher remains running. Validate both successful and error-bearing watchers across waiting and exit states, including two dependency tasks displayed together. Ordinary compile tasks should retain useful completion-result feedback.
- **Trace:**

  > TaskTerminalStatus in src/vs/workbench/contrib/tasks/browser/taskTerminalStatus.ts handles Active, Inactive and ProcessEnded events. eventInactive uses waiting-specific tooltips but the same check and error icons as completed states; eventEnd clears successful background statuses while retaining failed or warning results. TerminalTaskSystem in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts emits ProcessEnded from terminal exit callbacks, and terminalTabsList.ts renders the primary status icon and tooltip. Source inspection establishes partial coverage, not a completed implementation of the full request. Preserve ordinary compile-task result feedback and do not change dependency execution, problem-matcher semantics or process exit codes. The separate deemon correction is documented at https://github.com/joaomoreno/deemon/issues/4; the unresolved presentation tradeoff is recorded at https://github.com/microsoft/vscode/issues/144246#issuecomment-1083480500.
- **Open decisions:**
  - For an exited background task, should the overview remove diagnostic icons as originally requested, or retain diagnostic results alongside a distinct exited-state indicator?
