# Issue #293957 — Showing error 500 when actually 'cannot resolve host'

[https://github.com/microsoft/vscode/issues/293957](https://github.com/microsoft/vscode/issues/293957)

## Summary

The reported 500 accurately describes a Copilot service failure, not a client-side DNS failure. The internal hostname appears only in the backend's diagnostic response, so the external curl result does not indicate a VS Code defect.

## Change summary

Replace a detailed Copilot HTTP 500 error with a simpler service-unavailable message.

## Best solution

Keep the HTTP 500 classification and diagnostic detail in logs; the client should not reinterpret an internal dependency timeout as a local host-resolution failure.
