# Issue #293957 — Showing error 500 when actually 'cannot resolve host'

[https://github.com/microsoft/vscode/issues/293957](https://github.com/microsoft/vscode/issues/293957)

## Summary

Keep open as a Copilot error-message improvement: current code still exposes a generic “Server error: 500” reason. The logs show a server-side timeout, not a demonstrated client-side DNS failure, so clearer wording should explain the service failure without claiming the server is offline.

## Change summary

Make Copilot server-failure messages more understandable and distinguish service-side failures from local connectivity problems.

## Best solution

Improve the Copilot chat error presentation to explain service-side failures in plain language while retaining HTTP status and request IDs as diagnostic details. Do not relabel a received HTTP 500 as a local DNS failure based on a separate curl request to an internal backend hostname.
