# Issue #256702 — Chat: Reflect multiple editor selections in current document bubble

[https://github.com/microsoft/vscode/issues/256702](https://github.com/microsoft/vscode/issues/256702)

## Summary

The multi-selection defect remains on current main: chat observes cursor-selection changes but retains only the editor's primary selection. Keep this open for the accepted UX direction to be finalized and implemented.

## Change summary

Reflect every active editor selection in the chat current-document context instead of showing and sending only the primary selection.

## Best solution

Represent every non-empty selection from the active document in chat context while preserving the existing single-selection experience. The chat UX owners should first settle whether those ranges appear as independent pinnable pills or one aggregate pill.

- **Behavior:**

  > When the active document has multiple non-empty editor selections, chat context reflects every selection rather than only the primary one. Adding, changing, or removing one selection updates the displayed and submitted context without losing the other selections. The existing single-selection, whole-file, viewport, notebook-cell, and contributed-context behavior remains unchanged. Acceptance includes coverage for two selections and for removing the original primary selection while the second remains.
- **Trace:**

  > ChatImplicitContextContribution.updateImplicitContext in src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts receives onDidChangeCursorSelection events but reads only ICodeEditor.getSelection() in both the regular editor and notebook-cell paths. It then supplies a singleton selection value plus optional provider context to ChatImplicitContexts.setValues(), so secondary ranges are discarded before rendering or request construction. ChatImplicitContexts and ImplicitContextAttachmentWidget already iterate multiple values, but the widget's representation and pinning semantics for several simultaneous selections remain a product choice. Preserve current single-selection behavior, provider context, explicit-attachment de-duplication, ignored-file checks, and non-selection fallback behavior. The inverse duplicate-selection work tracked by https://github.com/microsoft/vscode/issues/277708 does not cover this path.
- **Open decisions:**
  - Should multiple selections appear as separate independently pinnable/dismissible pills, or as one aggregate current-document pill representing all ranges?
