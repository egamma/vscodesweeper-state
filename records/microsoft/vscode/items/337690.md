# Issue #337690 — Always show a close button on each tab

[https://github.com/microsoft/vscode/issues/337690](https://github.com/microsoft/vscode/issues/337690)

## Summary

Fresh feature request (0 upvotes, filed hours ago) asking that tab close buttons always be visible; current default only shows the close action for active/hovered/dirty/sticky tabs to save horizontal space, so a real gap exists, but there's no traction yet and no maintainer precedent to act on.

## Change summary

Requests that the tab close (x) button be shown on every tab at all times, not just on hover/active/dirty/sticky tabs.

## Best solution

If pursued, add an option alongside workbench.editor.tabActionCloseVisibility (or a variant of tabActionReserveSpace) that forces the close action to always render regardless of hover/active/dirty state, in multiEditorTabsControl.ts and multieditortabscontrol.css; otherwise this stays a design trade-off (compact tabs vs. discoverability) for maintainers to weigh.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`, `src/vs/workbench/browser/parts/editor/editor.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** A visual/manual check that with the new option enabled, close buttons render on every open tab (not just active/hover/dirty/sticky) without regressing existing tabActionCloseVisibility/tabActionReserveSpace behavior.
- **Behavior:**

  > When the new option is enabled, every tab's close (x) button is rendered at all times, including tabs that are neither active, hovered, dirty, nor sticky. With the option off (or unset), today's hover/active/dirty/sticky-only visibility is unchanged. Acceptance: toggling the setting flips between the two visual states without affecting tab width/reserve-space behavior for other options.
- **Trace:**

  > Close-button visibility is CSS-driven: multieditortabscontrol.css (~lines 463-502) only sets `.action-label` opacity/display to visible for `.tab.active`, `:hover`, `.dirty`, `.sticky` — otherwise it stays hidden via the `.close-action-off` and default state classes. multiEditorTabsControl.ts around line 1725 (`hasCloseAction`) and line 1752 (`close-action-off` class toggle) drive which CSS classes get applied per tab based on `options.tabActionCloseVisibility`. The existing boolean `tabActionCloseVisibility` only turns the action fully on/off, not 'always vs. on-hover'. Boundary: do not change tabActionReserveSpace's compact-tab space-saving behavior for other action types (pin/dirty indicators); scope any new toggle to the close action's display trigger only.
- **Open decisions:**
  - Should this be a new dedicated setting (e.g. always-show close button) or a value/mode on the existing tabActionCloseVisibility setting?
  - Should 'always show' apply per tab individually or be an editor-part-wide toggle, and what should the default be?

## Evidence

- **current behavior:** src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css lines 463-502 only reveal `.tab-actions .action-label` (the close/pin action) for `.tab.active`, `:hover`, `.dirty`, and `.sticky` tabs — not all tabs at rest.
- **existing setting:** workbench.editor.tabActionCloseVisibility (src/vs/workbench/browser/workbench.contribution.ts:216) only toggles the close action on/off entirely; it does not control always-visible vs. hover-only display.
- **related design tension:** workbench.editor.tabActionReserveSpace description explicitly frames the compact-vs-always-visible trade-off for Modern UI tabs, suggesting this is a known, deliberate design area rather than an oversight.
