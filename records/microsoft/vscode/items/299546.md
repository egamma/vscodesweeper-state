# Issue #299546 — Hooks feel slow when using sound bytes

[https://github.com/microsoft/vscode/issues/299546](https://github.com/microsoft/vscode/issues/299546)

## Summary

Real latency issue — hooks execute in the request-handling path (after start hooks and a transcript flush with up to 500ms timeout), not immediately at prompt submission or agent stop. Team-authored, no fix found on main.

## Change summary

UserPromptSubmit and Stop hooks execute with noticeable delay relative to the triggering user action, making time-sensitive hooks (like sound effects) feel sluggish.

## Best solution

Investigate the hook execution timing in the request flow. The `UserPromptSubmit` hook fires inside `DefaultIntentRequestHandler` after SessionStart hooks and a `raceTimeout(flush, 500)` call (`extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts:356-359`). For non-blocking hooks (no output consumed), consider firing them earlier or in parallel with the transcript flush. Similarly, the `Stop` hook timing should be audited relative to when the agent visibly finishes.
