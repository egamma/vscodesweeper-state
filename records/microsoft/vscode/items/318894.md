# Issue #318894 — Feature Request: Add accordion to copilot chat's custom model group selection header or enable selecting models from Language Selection dialog

[https://github.com/microsoft/vscode/issues/318894](https://github.com/microsoft/vscode/issues/318894)

## Summary

A real interaction gap remains for users with large custom-model catalogs: current main separates provider groups into tabs, but does not collapse models within those groups or allow choosing a chat model from the management editor. Route this to the model-picker and language-model-management owners for a product decision.

## Change summary

Make large custom-model lists easier to navigate by collapsing provider groups in the chat picker or allowing model selection from Manage Language Models.

## Best solution

Choose one clear selection surface: either let provider groups progressively disclose their models in the chat picker, or make model activation in Manage Language Models select that model for chat. Preserve keyboard operation, communicate expanded or selected state through ARIA, and keep the compact picker focused rather than duplicating management controls across both surfaces.

- **Behavior:**

  > Users with multiple custom provider groups or a provider exposing many models can narrow the visible catalog and select a model without scrolling through every group. The chosen interaction must work with mouse and keyboard, expose expanded or selected state to assistive technology, and preserve search and built-in Copilot model behavior. Acceptance should cover multiple provider groups, a large single-provider catalog, model selection, and focus restoration after the picker or management editor closes.
- **Trace:**

  > Current provider routing starts in buildModelPickerDestinations in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabs.ts, where each custom vendor/group becomes a tab destination. ModelPickerTabbedWidget._buildItems in modelPickerTabbedWidget.ts renders each destination's models and only provides the existing collapsible Other Models section under promoted-model conditions, leaving a custom provider's catalog flat. ChatModelsWidget in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts already renders collapsible provider/group rows with aria-expanded, but its onDidOpen handler only toggles those structural rows and does nothing for model-row activation. Keep search, pinned/recent behavior, model configuration, and provider management semantics outside the change unless the selected product design explicitly requires them. The broader design discussions are https://github.com/microsoft/vscode/issues/317128 and https://github.com/microsoft/vscode/issues/333609.
- **Open decisions:**
  - Should choosing the active chat model remain exclusive to the chat picker, with provider groups made collapsible or otherwise progressively disclosed, or should Manage Language Models also become a model-selection surface?
  - If provider groups remain in the chat picker, should the current provider tabs be sufficient navigation, be replaced or supplemented by collapsible sections, and should each group's expanded state persist across picker openings?
  - If Manage Language Models supports selection, which explicit activation gesture should select the model and how should the editor communicate the currently active model without conflicting with its existing multi-selection and management actions?
