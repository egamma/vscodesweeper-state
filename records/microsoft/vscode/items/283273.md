# Issue #283273 — VS Code does not open file paths with line numbers in plain text (.log) files

[https://github.com/microsoft/vscode/issues/283273](https://github.com/microsoft/vscode/issues/283273)

## Summary

This is a duplicate of the open feature request #163778 — the OutputLinkComputer only detects links for paths rooted in the workspace folder. The reporter's path likely doesn't match the workspace prefix.

## Change summary

Ctrl+clicking file paths with line numbers in .log files does not open the file when the path is outside the current workspace.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/163778, which tracks supporting file-path links regardless of workspace membership. Implementing workspace-independent path detection in OutputLinkComputer would resolve both issues.

- **language registration:** The OutputLinkProvider registers for language 'log' (LOG_MODE_ID), which is the language assigned to .log files via extensions/log/package.json — so the link provider IS active, but the patterns won't match paths outside the workspace.
- **canonical issue:** https://github.com/microsoft/vscode/issues/163778 is open, labeled feature-request+output, with a maintainer (bpasero) confirming the design: 'this is simply not how output link detection works: it will only detect links for paths that are inside the workspace'.
- **same root cause:** Both issues ask for the same thing: clickable file path links in log/output that don't require the path to be inside the workspace. The (364) line-number format is already handled by the pattern at line 109 when the workspace prefix matches.
