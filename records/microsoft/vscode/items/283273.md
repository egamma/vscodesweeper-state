# Issue #283273 — VS Code does not open file paths with line numbers in plain text (.log) files

[https://github.com/microsoft/vscode/issues/283273](https://github.com/microsoft/vscode/issues/283273)

## Summary

Generic filesystem-path detection in editor documents is intentionally extension-owned because path formats and resolution rules are language-specific. This narrower `.log` stack-trace format follows the established *extension-candidate decision.

## Change summary

Recognize absolute paths such as `/var/www/app/File.php(364)` in `.log` editors and navigate to the referenced line on Ctrl-click.

## Best solution

Implement a document-link provider for Log or PHP stack-trace formats that recognizes this syntax, validates the target, and converts the parenthesized line number into an editor location.

## Vision fit

- **Fit:** rejected
- **Reason:** Format-specific path recognition can be implemented through the document-link extension API and does not need to expand core link detection.
- **Evidence:** Values and guardrails: “The power lives in extensions” and capabilities that work through existing extension APIs should generally remain outside core.

  > Thanks for the report. Generic filesystem-path detection in editor documents is intentionally left to language extensions because path formats, resolution rules, and false positives are language-specific; that decision is documented in https://github.com/microsoft/vscode/issues/108527. A Log or PHP stack-trace document-link provider is the appropriate place to support `/path/File.php(364)`.

## Evidence

- **maintainer precedent:** https://github.com/microsoft/vscode/issues/108527 covers Ctrl-clicking file paths in editor documents. Maintainers closed it as *extension-candidate, explaining that platform syntax, relative paths, and false positives make detection better suited to per-language extensions.
- **current source:** src/vs/editor/common/languages/linkComputer.ts defines the default detector specifically for `http://`, `https://`, and `file://`; bare filesystem paths and `(line)` suffixes are not recognized.
- **existing extension API:** src/vs/editor/browser/services/editorWorkerService.ts registers the generic link provider, while the DocumentLinkProvider extension API permits language-specific providers to add formats such as PHP stack-trace paths.
