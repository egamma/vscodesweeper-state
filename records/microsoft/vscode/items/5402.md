# Issue #5402 — Improved column selection (Alt+select)

[https://github.com/microsoft/vscode/issues/5402](https://github.com/microsoft/vscode/issues/5402)

## Summary

Keep open: current settings partially cover mouse-origin column selection, but do not provide the requested rectangle across virtual whitespace or Alt-drag behavior with the default multicursor modifier. Neither related open issue owns the full request; 407 upvotes support retaining this accepted backlog item.

## Change summary

Provide intuitive mouse-origin Alt-drag column selection, including rectangular selection beyond short or empty lines.

## Best solution

Define the intended Alt-click versus Alt-drag contract and deliver rectangular selection across virtual whitespace in the editor selection pipeline. Coordinate the virtual-space portion with https://github.com/microsoft/vscode/issues/13960 and mouse-binding customization with https://github.com/microsoft/vscode/issues/3130 without treating either partial overlap as full resolution.

## Plan brief

- **Likely files:** `src/vs/editor/browser/view/viewController.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/cursor/cursorColumnSelection.ts`, `src/vs/editor/common/cursorCommon.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** The plan should end with mouse-dispatch checks for both editor.multiCursorModifier values and editor cursor tests covering rectangles across long, short, empty, and tab-containing lines. Manually verify that a drag begins at the clicked location rather than the previous caret, and that virtual-space typing, copying, and undo follow the agreed contract without changing ordinary selection.
- **Behavior:**

  > Users want Alt-drag to begin a column selection at the mouse-down location, independent of the previous caret. The requested rectangle must remain aligned across short and empty lines, including positions beyond existing text. Existing alternate gestures are partial workarounds, not acceptance of the full request. Acceptance must cover both multicursor-modifier configurations and the agreed behavior when editing or copying virtual portions of the rectangle.
- **Trace:**

  > ViewController.dispatchMouse in src/vs/editor/browser/view/viewController.ts distinguishes the configured multicursor modifier from Alt-based column dragging; default Alt currently follows multicursor creation or extension unless Shift is pressed. editor.columnSelection and editor.action.toggleColumnSelection provide a persistent alternate mode, while the ctrlCmd modifier enables the mouse-origin Alt-drag path described in merged https://github.com/microsoft/vscode/pull/66445. ColumnSelection in src/vs/editor/common/cursor/cursorColumnSelection.ts represents rectangles through text-bound per-line cursor states; the 'column select 1' test in src/vs/editor/test/browser/controller/cursor.test.ts records collapsed selection at a short line's end. The virtual-space representation and editing contract remain unresolved, so the implementation boundary extends beyond mouse dispatch. Coordinate with https://github.com/microsoft/vscode/issues/13960 and https://github.com/microsoft/vscode/issues/3130; neither absorbs the entire report. Preserve ordinary selection, existing multicursor click behavior, and link/definition gestures unless a maintainer explicitly approves a compatibility change.
- **Open decisions:**
  - Should Alt-drag become column selection under the default Alt multicursor modifier while Alt-click continues adding cursors, or should the gesture remain opt-in through configuration?
  - For a rectangle extending beyond line ends, what should copying include, and when should typing or pasting materialize whitespace?

## Evidence

- **Existing capabilities and limits:** src/vs/editor/common/config/editorOptions.ts registers editor.multiCursorModifier with default alt and editor.columnSelection with default false. src/vs/workbench/contrib/codeEditor/browser/toggleColumnSelection.ts exposes editor.action.toggleColumnSelection. These provide alternate selection workflows, not virtual whitespace or an independent Alt-drag binding.
- **Current mouse dispatch:** src/vs/editor/browser/view/viewController.ts:217–310 routes middle-button gestures to _columnSelect, subject to Linux selection-clipboard and scrolling options. With the default Alt multicursor modifier, unshifted Alt dispatch creates or extends a cursor selection; when Alt is not the multicursor modifier, Alt-drag invokes _columnSelect. This corroborates the configuration distinction described in comment 20.
- **Virtual-space gap:** src/vs/editor/common/cursor/cursorColumnSelection.ts constructs per-line SingleCursorState selections from existing text columns, skips lines outside the horizontal selection span, and falls back to line-end cursors when no selections remain. Its columnSelectRight also limits movement to the maximum existing visual line length. src/vs/editor/test/browser/controller/cursor.test.ts, test 'column select 1', explicitly expects a short line's selection to collapse at its end rather than form a virtual rectangle.
- **Partial historical implementation:** https://github.com/microsoft/vscode/issues/66444 was closed through merged https://github.com/microsoft/vscode/pull/66445, titled 'Improve column selection by setting origin to clicked position'. The described improvement pairs Alt-drag with editor.multiCursorModifier=ctrlCmd; it does not satisfy the virtual-space portion or the requested default-modifier interaction.
