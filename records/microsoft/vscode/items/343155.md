# Issue #343155 — Extensions: Uninstall remains enabled after removing a local or remote copy

[https://github.com/microsoft/vscode/issues/343155](https://github.com/microsoft/vscode/issues/343155)

## Summary

The reported cross-server state defect remains in current main. Keep this issue open while the explicitly linked fix in https://github.com/microsoft/vscode/pull/343171 is reviewed and landed.

## Change summary

After uninstalling one local or remote extension installation, its remaining model can incorrectly report Installed and retain an enabled Uninstall action.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/343171 so server-owned extension models reflect their own installation state while serverless Marketplace models retain aggregate state.

## Evidence

- **Current-main state aggregation:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts:2008-2028 queries remote, web and local collections without restricting them to extension.server. The constructors at lines 1048-1077 wire models from each collection to this shared state provider.
- **Exact failing path:** When one of two Marketplace-backed installations is removed, onDidUninstallExtension at extensionsWorkbenchService.ts:940-948 correctly removes it from that server's installed collection. However, Extensions.getExtensionState at lines 964-972 matches the surviving installation by gallery identity without a server check. Removing the remote copy therefore falls through to the local copy's Installed state; removing the local copy can return the remote copy's Installed state before consulting local Uninstalling state.
- **Observable action consequence:** src/vs/workbench/contrib/extensions/browser/extensionsActions.ts:908-937 enables Uninstall for a non-built-in model reporting Installed and derives the All Profiles label from that model's local metadata. This directly connects the incorrect state to the reporter's stale enabled action.

Its body explicitly says 'Fixes microsoft/vscode#343155' and describes a server-ownership guard preserving serverless aggregation. It reports eight regression tests failing before the fix and 356 tests passing afterward; these are the PR author's results, not checks executed during this read-only review.
