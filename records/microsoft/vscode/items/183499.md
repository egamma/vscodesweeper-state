# Issue #183499 — Remove polyfill for nested worker

[https://github.com/microsoft/vscode/issues/183499](https://github.com/microsoft/vscode/issues/183499)

## Summary

The nested-worker polyfill remains wired into current main, so this cleanup is still necessary. Native nested-worker support already bypasses it, but does not remove the fallback or its iframe-side protocol.

## Change summary

Remove the legacy nested-worker polyfill now that Safari supports native nested workers.

## Best solution

Retire the unsupported-browser fallback and its dedicated message protocol while preserving the native worker wrapper's resource-URL handling and worker naming. Establish browser-level validation before removing the compatibility path.

- **Trace:**

  > src/vs/workbench/api/worker/extensionHostWorker.ts has distinct native and fallback branches: the native branch wraps Worker for resource handling and naming, while the fallback installs NestedWorker. The fallback implementation in src/vs/workbench/services/extensions/worker/polyfillNestedWorker.ts forwards creation and termination through messages declared in src/vs/workbench/services/extensions/common/polyfillNestedWorker.protocol.ts. The prerequisite https://github.com/microsoft/vscode/pull/183482 has merged. The remaining uncertainty is compatibility validation and how to exercise this path reliably; no dedicated regression harness was identified. Keep the native wrapper and unrelated iframe initialization behavior outside the cleanup boundary.

## Evidence

- **fallback remains active in source:** src/vs/workbench/api/worker/extensionHostWorker.ts imports NestedWorker and installs a subclass when self.Worker is absent. When native Worker exists, a separate wrapper handles blob bootstrapping, resource URLs, and worker names; that wrapper is not the obsolete polyfill.
- **polyfill and host protocol remain:** src/vs/workbench/services/extensions/worker/polyfillNestedWorker.ts still implements MessageChannel-based worker forwarding. src/vs/workbench/services/extensions/common/polyfillNestedWorker.protocol.ts defines _newWorker and _terminateWorker messages, and src/vs/workbench/services/extensions/worker/webWorkerExtensionHostIframe.html still processes both and maintains a nestedWorkers map.
