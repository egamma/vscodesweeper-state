# Issue #338926 — Agent Host: reused multi-turn subagent remains running after child turn completes

[https://github.com/microsoft/vscode/issues/338926](https://github.com/microsoft/vscode/issues/338926)

## Summary

Well-diagnosed, reproducible-from-source bug in Copilot subagent completion reconciliation: when a reused multi-turn subagent's final turn ends while `tasks.list()` still reports `running`, the pending completion scheduler is torn down with nothing re-armed, so the parent can be left permanently reporting the subagent as running.

## Change summary

A reactivated, multi-turn background subagent's final turn completes, but the parent never clears its 'subagent running' state because the matching `subagent_completed` signal is never emitted.

## Best solution

In `CopilotAgentSession._reconcileSubagentTaskStatuses()` (src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts), when a task's status is still non-terminal at `turn_end` time, re-arm reconciliation (reuse the existing `_scheduleSubagentTurnCompletion`/RunOnceScheduler confirmation path) instead of unconditionally deleting the completion scheduler, so the host keeps polling until the task goes idle/completed/failed/cancelled or a newer turn starts for that agent.
