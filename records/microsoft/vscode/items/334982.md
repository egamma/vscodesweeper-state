# Issue #334982 — Chat Window's `LLM Request Failed` message is too big, and unnecessary.

[https://github.com/microsoft/vscode/issues/334982](https://github.com/microsoft/vscode/issues/334982)

## Summary

Traced the code path: when a `vscode.lm` chat provider request fails (e.g. via `CopilotLanguageModelWrapper._provideLanguageModelResponse` in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts), the underlying JS error's raw text/stack ends up interpolated verbatim into the `reason` placeholder of the user-facing error templates in extensions/copilot/src/platform/chat/common/commonTypes.ts and src/vs/workbench/contrib/chat/common/chatErrorMessages.ts, producing the oversized, developer-oriented message the reporter saw. Real, still-present UX rough edge, not yet fixed on main.

## Change summary

The chat 'Sorry, your request failed' error message embeds a full raw stack trace as the 'Reason', making it unnecessarily long and unreadable for end users.

## Best solution

Sanitize/shorten the `reason` text before interpolating it into the user-facing failure templates (e.g. strip stack frames, cap length, or move technical detail behind a collapsible 'details' affordance) in chatErrorMessages.ts / commonTypes.ts, while still keeping request IDs for support diagnostics.

## Plan brief

- **Trace:**

  > The 'reason' string embedded in ChatFetchResponseType.Failed/NetworkError messages (chatErrorMessages.ts:300-304, commonTypes.ts:458-474) can carry a full JS Error toString/stack when the failure originates from a vscode.lm chat-provider throw (e.g. languageModelAccess.ts:705 _provideLanguageModelResponse). Do not touch the request-id/server-request-id fields — those are useful for support; only the free-form reason text needs bounding.
- **Open decisions:**
  - Should the raw error detail be stripped/truncated outright, or kept but hidden behind a collapsible 'show details' UI affordance?
  - Should the cap apply uniformly to all ChatFetchResponseType error variants, or only ones known to wrap raw JS errors (Failed/NetworkError)?
