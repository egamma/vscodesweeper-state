# Issue #334982 — Chat Window's `LLM Request Failed` message is too big, and unnecessary.

[https://github.com/microsoft/vscode/issues/334982](https://github.com/microsoft/vscode/issues/334982)

## Summary

The reported stack-trace-laden error text is real: `_provideLanguageModelResponse` in the Copilot extension's LM API provider throws `new Error(result.reason)` at a line matching the exact stack frame in the report (extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts:885), and errors crossing the extension-host boundary carry their full `.stack` via `transformErrorForSerialization` (src/vs/base/common/errors.ts). Somewhere downstream the raw stack is surfaced verbatim instead of just `error.message`, but I could not pin the single display site that does this, so I'm routing rather than closing or auto-fixing.

## Change summary

When an LM/agent request fails (e.g. 'Response contained no choices'), the chat error box shows the raw JS Error plus full stack trace instead of a short, user-friendly reason, and Retry doesn't clear/replace it.

## Best solution

Whichever consumer renders the failed-request message (likely in src/vs/workbench/contrib/chat or the Copilot extension's response-error formatting) should show only `error.message`, never `error.stack`, when surfacing LanguageModelError/APIUsage failures to the user; the stack should stay in logs only.
