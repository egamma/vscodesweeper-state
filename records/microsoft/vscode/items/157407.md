[https://github.com/microsoft/vscode/issues/157407](https://github.com/microsoft/vscode/issues/157407)

## Summary

Keep this open: the reporter identified a Chromium keyCode collision between Neo2 ö and x, and current VS Code's keyCode dispatch path still cannot distinguish those inputs. The older related issues do not establish a canonical for this specific collision.

## Change summary

Allow separate Neo2 ö and x keybindings on Linux without losing the layout's navigation-layer behavior.

## Best solution

Resolve the ambiguous keyboard-event values in Chromium/Electron, or establish a compatible VS Code mitigation that distinguishes ö from x while preserving Neo2 navigation keys. Track this collision separately from the related navigation-layer and Wayland layout-detection problems.

Consequently, the two reported events with keyCode=88 resolve identically if Chromium still emits them.
