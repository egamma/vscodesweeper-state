## Evidence

- **terminal output rendering:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts renders tool terminal output via an embedded ITerminalInstance/mirror (DetachedTerminalSnapshotMirror/DetachedTerminalCommandMirror), not plain DOM text — this file has no copy-specific handling of its own.
- **copy fallback path:** src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts CopyItemAction only copies dom.getActiveWindow().getSelection() text when non-empty and inside widget.domNode; otherwise it falls back to stringifyItem(item) for the whole response item, which could look like 'the whole chat history' if the tool invocation's containing response item is large.
- **container-level copy listener:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts handleCopy() only rewrites clipboard data when the selection touches an <a>/<img>, so it's an unlikely but not ruled-out contributor.
