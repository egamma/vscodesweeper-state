## Summary

Active, fresh discussion (last reply hours ago) where the maintainer is still diagnosing; the reporter has now confirmed the root cause is that `git clone` itself fails for the EMU-account repo outside VS Code (likely a GitHub SSO/authorization issue on their git credentials), but VS Code surfaces no friendly error when that happens — worth keeping open for a UX fix, not a close.

## Change summary

Listing/installing an Agent Plugin from a GitHub Enterprise Managed User (EMU) org repo silently fails, with no clear error shown to the user.

## Best solution

Since plugin fetching just shells out to `git clone` (src/vs/platform/git/node/localGitService.ts, wired through src/vs/workbench/contrib/chat/electron-browser/pluginGitCommandService.ts) and propagates the raw process error, surface that failure to the user with an actionable message (e.g. suggest checking SSO authorization on the PAT/credential) instead of failing silently — as the reporter themselves suggested. The underlying git auth failure for the EMU repo is outside VS Code's control.
