# Issue #333280 — Terminal Auto-Approve ignores wildcard/regex rules in settings.json (Forces manual approval)

[https://github.com/microsoft/vscode/issues/333280](https://github.com/microsoft/vscode/issues/333280)

## Summary

Traced on current main: terminal auto-approve rules from settings.json are intentionally gated behind a one-time in-product opt-in, not ignored — the reporter almost certainly hasn't clicked 'Enable Auto Approve...' yet, so every command still requires manual confirmation regardless of the wildcard/regex rule.

## Change summary

Wildcard/regex rules configured in `chat.tools.terminal.autoApprove` don't stop the manual approval popup for terminal commands run by chat/agent tools.

## Best solution

As-designed: keep the deliberate `chat.tools.terminal.autoApprove.warningAccepted` opt-in gate (a security guardrail so a synced/extension-set wildcard rule can't silently bypass approval) and help the reporter locate the 'Enable Auto Approve...' action in the confirmation dialog's overflow menu, after which the configured rule takes effect exactly as written.

  > Thanks for the report. I traced this on current main and it's expected behavior, not a bug: matching a rule in `chat.tools.terminal.autoApprove` isn't enough on its own — auto-approve also requires the one-time 'Enable Auto Approve...' opt-in, which sets a separate flag (`chat.tools.terminal.autoApprove.warningAccepted`) the first time you accept it from the confirmation dialog's overflow menu. Until that's accepted, even a `"*": { "approve": true }` rule is overridden and every command still prompts. Once you click 'Enable Auto Approve...' once, your configured wildcard/regex rules should be respected going forward. (Separately, 'Yes, and always allow...' does add its rule to the real `chat.tools.terminal.autoApprove` setting — it isn't writing to a hidden state DB.)
