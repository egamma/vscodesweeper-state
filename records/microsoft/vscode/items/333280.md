## Evidence

- **Literal wildcard is not supported:** In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/commandLineAnalyzer/autoApprove/commandLineAutoApprover.ts, _doConvertAutoApproveEntryToRegex recognizes slash-delimited regexes but escapes other strings and adds a start anchor and word boundary. Consequently, '*' is literal and cannot match the reported 'git add . && git commit -m "test"' command.
- **Supported regex and precedence:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalChatAgentToolsConfiguration.ts explicitly documents '"/.*/": true' as allowing all commands except denied commands. CommandLineAutoApprover explicitly accepts the '.*' regex, reads chat.tools.terminal.autoApprove through IConfigurationService, and checks deny rules before allow rules; source inspection does not support the claim that matching relies exclusively on a state database.
- **Additional approval gates:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/terminalToolAutoApprove.ts, isTerminalAutoApproveAllowed, also requires auto-approval enablement, warning acceptance stored in application storage, and tool eligibility. CommandLineAutoApproveAnalyzer additionally rejects unanalyzable syntax. A matching settings rule alone therefore does not establish that every approval prompt is erroneous.
- **Report lacks a confirmed regex failure:** https://github.com/microsoft/vscode/issues/333280 supplies a '*' configuration, but no complete reproduction using '/.*/', active harness, terminal tool identity, or approval-reason logs. Its only comment is an automated version reminder, not an independent reproduction. The parameter-variation claim remains unverified.
- **Related report is closed, not a duplicate target:** https://github.com/microsoft/vscode/issues/266651 is closed. In https://github.com/microsoft/vscode/issues/266651#issuecomment-3292581459, the terminal maintainer explains that default false rules can intentionally defeat '/.*/'; https://github.com/microsoft/vscode/issues/266651#issuecomment-3363906427 reiterates that default denials must be explicitly unset. This establishes relevant precedence, not proof that every symptom here is intentional.
- **Harness distinction remains relevant:** https://github.com/microsoft/vscode/issues/326766 is open and tracks terminal approval parity across harnesses. https://github.com/microsoft/vscode/issues/326766#issuecomment-5996070211 reports matching rules failing in the Local harness but working in the Copilot harness. The present report does not identify its harness, so shared ownership of the same defect is not established.
