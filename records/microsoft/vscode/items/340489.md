# Issue #340489 — Agent Host retries orphaned Claude sessions forever (sourceUnresolvable), pinning ~170% CPU

[https://github.com/microsoft/vscode/issues/340489](https://github.com/microsoft/vscode/issues/340489)

## Summary

Current main already implements exactly the fix the reporter asks for: a session whose source is unresolvable is parked after the first failed pass and excluded from every subsequent reconciliation pass (`_park`/`_parkedSessions` in agentHostCatalogReconciliationService.ts), instead of being retried every pass with no cap. Dedicated tests assert this ('a source that cannot resolve is parked instead of retried every pass').

## Change summary

On 1.141.0, orphaned discovered Claude sessions (source transcript deleted) are retried every reconciliation pass forever with no backoff/cap, pinning the Agent Host utility process at ~170% CPU indefinitely.

## Best solution

Keep the current main design: `sourceUnresolvable` sessions are parked in-memory after one failed resolution attempt per process lifetime, filtered out of `_listDirtySessions`, and only re-attempted on an explicit wake signal (provider registration, a mutation of that session, or the hourly full-verification sweep) rather than on the ~30s/5min reconciliation cadence.
