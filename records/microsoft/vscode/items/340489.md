# Issue #340489 — Agent Host retries orphaned Claude sessions forever (sourceUnresolvable), pinning ~170% CPU

[https://github.com/microsoft/vscode/issues/340489](https://github.com/microsoft/vscode/issues/340489)

## Summary

Keep open: a maintainer independently reproduced the sustained CPU load and traced a self-sustaining catalog-repair loop across providers. Current main still contains the listing-driven wake-up, immediate reconciliation, and repeated provisional notifications that sustain it.

## Change summary

Prevent orphaned agent sessions from driving continuous catalog reconciliation, SQLite activity, and log churn.

## Best solution

Make background catalog repair converge when a source cannot resolve, without treating ordinary listing as fresh source evidence or repeatedly publishing unchanged provisional state. Preserve recovery when a provider becomes available or a session genuinely changes; permanent orphan deletion is not required to resolve this performance defect.
