# Issue #312783 — The progress border looks a little narrow in its shrunken state

[https://github.com/microsoft/vscode/issues/312783](https://github.com/microsoft/vscode/issues/312783)

## Summary

Thanks for the focused polish feedback. This member-authored Backlog item remains valid: current main still uses fixed angular stops and fixed beam/glow thicknesses as the input perimeter shrinks, and no linked change or older same-symptom canonical settles the desired compact-state appearance.

## Change summary

Keep the animated chat-input progress border looking like a soft glow instead of a short, thick band when the input becomes narrow or compact.

## Best solution

Define the intended compact-state treatment with the chat UX owner, then preserve the progress comet's perceived trail length and softness across responsive input sizes without changing its full-width appearance, reduced-motion behavior, or theme contrast.

- **Behavior:**

  > While an agent is working, the animated border around a narrow or compact chat input should retain the soft glowing-comet character visible at larger widths rather than collapsing into a short, visually heavy band. The full-width treatment should remain consistent, theme contrast must remain legible, and reduced-motion mode must not animate. Acceptance should compare full, narrow, and compact inputs across light, dark, and high-contrast themes.
- **Trace:**

  > The relevant styling is in src/vs/workbench/contrib/chat/browser/widget/media/chat.css. `.interactive-input-part.compact` changes the input radius, while `.chat-input-container::before` draws a fixed-angle one-stroke beam and `::after` draws a fixed 2px blurred glow; only animation duration is adjusted responsively elsewhere. This makes the physical trail shorter as the perimeter contracts while its thickness remains fixed, matching the reported visual imbalance. Commit 9ffb703bd6a1cf67b4a049806e07fd3552a3946b predates the report and addressed responsive travel speed, not this compact-state polish. Keep full-width rendering, theme tokens, focus contrast, and `prefers-reduced-motion` behavior outside the scope of the design change.
- **Open decisions:**
  - Should compact and narrow inputs preserve an approximately constant physical comet-trail length and glow softness, or intentionally use a distinct compact progress treatment?
