# Issue #163748 — Repositories - svg icons stay dark when the repository row is selected.

[https://github.com/microsoft/vscode/issues/163748](https://github.com/microsoft/vscode/issues/163748)

## Summary

Keep open: custom SVG inline actions still lack selection-state color adaptation, matching the reporter's renewed Light/Light+ reproduction. Maintainers confirmed this is shared list/action rendering behavior, not an incorrectly supplied extension icon.

## Change summary

Custom SVG inline action icons remain dark on blue selected rows in Light and Light+ instead of adapting like product icons.

## Best solution

Make custom inline action icons remain legible across list selection states in the shared action-rendering surface, rather than fixing only SCM. First settle how selection adaptation should preserve extension-authored multicolor artwork and the existing light/dark icon contract.

Under Light and Light+, select and deselect rows with mouse and keyboard and verify that the icon remains legible alongside product icons; repeat with inactive selection, dark and high-contrast themes, disabled actions, and multicolor SVG artwork to verify the chosen compatibility contract.
- **Behavior:**

  > In Light and Light+, selecting a repository or custom-tree row gives it a blue background and light foreground, but custom SVG inline action icons retain their dark authored colors. The selected action should remain legible and consistent with the row's selection presentation. Acceptance must cover both SCM and a contributed tree view, selection and deselection, keyboard and mouse interaction, and active versus inactive selection. Existing theme-specific assets, disabled appearance, and multicolor artwork must retain the behavior agreed with the maintainer.
- **Trace:**

  > MenuEntryActionViewItem._updateItemClass in src/vs/platform/actions/browser/menuEntryActionViewItem.ts renders custom URI icons as CSS background images and chooses their asset solely from the active theme's light/dark classification. List selection styling in src/vs/base/browser/ui/list/listWidget.ts changes CSS foreground colors, including .codicon overrides, without changing the SVG image's authored fill. SCM's provider in src/vs/workbench/contrib/scm/browser/util.ts and custom tree rendering in src/vs/workbench/browser/parts/views/treeView.ts both reach the shared menu-action renderer. Maintainers confirmed correct extension assets and reproduced the broader problem at https://github.com/microsoft/vscode/issues/163748#issuecomment-1284588349 and https://github.com/microsoft/vscode/issues/163748#issuecomment-1862724940. The disabled-opacity issue https://github.com/microsoft/vscode/issues/209397 is distinct and must not be treated as the fix. The uncertainty is the selection-color contract for arbitrary SVG artwork, not whether the reported monochrome contrast problem exists; do not globally recolor unrelated image surfaces or change command execution semantics.
- **Open decisions:**
  - Should selection-color adaptation apply automatically to existing custom SVG inline actions, or require an explicit monochrome/themable opt-in so extension-authored multicolor artwork retains its original colors?
