# Issue #331006 — Opening editor Chat destroys standalone Agent session and creates phantom copilotcli session

[https://github.com/microsoft/vscode/issues/331006](https://github.com/microsoft/vscode/issues/331006)

## Summary

Detailed, well-evidenced report (backend log excerpts, screenshots, and repeated reproduction across a clean reinstall) that opening the editor Chat panel tears down a live standalone Agent-window session and leaves the UI referencing phantom copilotcli session IDs. This spans the multi-surface agent-host/chat session architecture, so it needs a maintainer with agent-host session-identity context rather than a mechanical close.

## Change summary

Opening the editor Chat panel destroys the backend session backing an active standalone Agent-window session and causes the Agent window to reference nonexistent phantom session IDs, hanging indefinitely.

## Best solution

Route to the agent-host/session-ownership owners to trace why a second client (editor Chat) tears down or collides with an existing session's backing instead of getting its own; the repo's own agentHost E2E known-issues doc already documents a related gap ("Duplicate session creation is accepted" — a retried/duplicate createSession is accepted instead of rejected as SessionAlreadyExists), which is a plausible contributing mechanism worth checking against this report, though it isn't a confirmed root cause for this exact case.
