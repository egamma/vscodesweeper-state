# Issue #331006 — Opening editor Chat destroys standalone Agent session and creates phantom copilotcli session

[https://github.com/microsoft/vscode/issues/331006](https://github.com/microsoft/vscode/issues/331006)

## Summary

Detailed single-reporter repro describing a shared Copilot CLI session (LocalSessionManager/session-wrapper) being disposed when the editor Chat panel is opened while a standalone Agent window session is active, destroying a valid persisted session and leaving the Agent UI hung on a phantom session id; the code does contain a shared ref-counted session-wrapper/dispose path (copilotcliSessionService.ts) that is architecturally consistent with this, but I could not trace the exact faulty call site, so this needs maintainer/engineering investigation rather than a mechanical fix.

## Change summary

Opening the editor's Chat panel appears to close/destroy the backend Copilot CLI session that the standalone Agent window is actively using, and the editor Chat panel then references non-existent phantom session IDs.

## Best solution

Have the Copilot CLI/agent-host team trace how CopilotCLISessionService's RefCountedSession/`_sessionWrappers` (extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts) is shared between the editor Chat panel and the standalone Agent window session provider, and ensure opening one surface cannot dispose/close a session still referenced by the other; a two-window/two-view reproduction with debug logs would confirm the exact acquire/release mismatch.
