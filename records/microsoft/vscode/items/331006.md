[https://github.com/microsoft/vscode/issues/331006](https://github.com/microsoft/vscode/issues/331006)

## Summary

Well-documented single-reporter report of a real architectural risk (a shared Copilot CLI backend session being destroyed when the editor Chat panel connects while a standalone Agent window session is active), but I could not trace the exact code path or confirm a concrete defect in the checkout, so this needs engineering triage rather than a close.

## Change summary

Opening the editor Chat panel appears to destroy an active standalone Agent-window Copilot CLI session and leaves the Agent UI referencing phantom, non-existent session IDs.

## Best solution

An Agent Host / Copilot maintainer should trace how `CopilotAgent._destroyLiveSession` / `_chatBackings` resolve which SDK session backs the editor Chat panel vs. the Sessions-window Agent session on the same workspace — per the module's own architecture doc, each exact chat should resolve to its own backing without cascading disposal, so a cross-chat destroy here would be a boundary bug in `node/copilot/copilotAgent.ts` or `copilotAgentSession.ts`.
