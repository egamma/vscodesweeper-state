# Issue #138727 — support theme icons in menus in the shadow dom

[https://github.com/microsoft/vscode/issues/138727](https://github.com/microsoft/vscode/issues/138727)

## Summary

Keep open: this team-authored Backlog debt identifies a real layering gap—shadow-DOM menus use fixed Codicon rules rather than product-icon-theme definitions—and the discussion does not establish a completed fix or duplicate.

## Change summary

Make menu icons rendered inside a shadow DOM honor configured product icon themes without duplicating fixed Codicon rules in the base menu widget.

## Best solution

Provide the menu/context-view styling path with resolved icon definitions, including font family and character data, while preserving the base/platform layer boundary and ordinary document menus.

- **Behavior:**

  > Menus rendered inside a shadow DOM must honor product icon theme replacements, including replacements that use a different font family and character code. The editor context menu/dropdown should show the same themed submenu icon as a menu rendered in the document. Existing Codicon rendering and non-shadow-DOM menus must remain unchanged.
- **Trace:**

  > The issue points to fixed Codicon rules in `src/vs/base/browser/ui/menu/menu.ts`, while dynamic product-icon rules are generated by `src/vs/platform/theme/browser/iconsStyleSheet.ts`. The maintainer discussion confirms editor dropdown/context menus render in a shadow DOM and that document-level font definitions are available, but product icon definitions are not propagated into that menu styling path. The uncertainty begins at the architectural boundary: menu widget code is in `base`, while resolved product-theme icon data belongs to the platform theme service. Related PR https://github.com/microsoft/vscode/pull/138662 does not settle this remaining shadow-DOM behavior.
- **Open decisions:**
