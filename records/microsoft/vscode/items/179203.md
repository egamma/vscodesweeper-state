# Issue #179203 — vscode.workspace.findFiles returns nothing if executed early in extension startup

[https://github.com/microsoft/vscode/issues/179203](https://github.com/microsoft/vscode/issues/179203)

## Summary

Confirmed race condition in the file search pipeline during early extension startup — the bug is still present on current main and still being reported (most recently April 2026). Keep open.

## Change summary

`vscode.workspace.findFiles` returns empty results when called early in extension activation because the search infrastructure is not yet fully initialized.

## Best solution

Add a readiness gate in the file search path so that `$startFileSearch` waits until the search provider and workspace folders are fully initialized before executing the query. The likely fix area is the interaction between `MainThreadWorkspace.$startFileSearch` (which immediately queries workspace folders) and `SearchService.doSearch` (which filters out folders where `fileService.exists` returns false during early init). The fix should ensure the workspace is fully resolved before the search runs, similar to how `ExtHostWorkspace` uses a `Barrier` for workspace folder operations.

## Evidence

- **race in doSearch:** In `src/vs/workbench/services/search/common/searchService.ts` lines 201-202, `doSearch` filters out folder queries where `fileService.exists()` returns false. During early startup, this can eliminate all folders before the file system is ready, yielding zero results.
- **no barrier in findFiles path:** Unlike `getWorkspaceFolder`/`resolveWorkspaceFolder` which await `this._barrier.wait()` in `src/vs/workbench/api/common/extHostWorkspace.ts`, the `findFiles` → `_findFilesImpl` → `_findFilesBase` path does not wait on any readiness gate.
- **no fix commit:** No commit referencing issue 179203 exists in the git history; `git log --all --grep=179203` returns nothing.
- **still reproduces:** Comment by yangskyboxlabs on 2026-04-30 confirms the issue still reproduces in VS Code 1.118.0.
- **extension workaround:** The dbt-power-user extension merged a retry workaround (https://github.com/AltimateAI/vscode-dbt-power-user/pull/1615), confirming the issue affects real-world extensions.
