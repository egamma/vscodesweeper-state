# Issue #349810 — Migrate with Agent can't migrate a guard hook that is still active

[https://github.com/microsoft/vscode/issues/349810](https://github.com/microsoft/vscode/issues/349810)

## Summary

Keep open: the supplied fixture and steps suffice to retest the blocked migration. Current source honors user-level chat.useHooks changes at a subsequent turn boundary, but that does not establish that answering the migration's pending confirmation releases its active guard.

## Change summary

Agent-guided migration cannot convert an active legacy guard hook because the guard blocks migration tools and the attempted pause does not unblock them.

## Best solution

Provide a supported, explicitly user-authorized way to complete migration of an active workspace guard and its backed-up scripts while preserving its protection afterward. First distinguish a workspace-scoped setting change from a user-scoped change and a pending confirmation response from a new chat turn; do not silently exempt migration tools from guards.
