# Issue #339451 — Integrated Browser blocks Encrypted Media on every page; videos won't play

[https://github.com/microsoft/vscode/issues/339451](https://github.com/microsoft/vscode/issues/339451)

## Summary

Traced the integrated browser's Electron wiring (browserView.ts, browserSessionPermissions.ts) and found no Permissions-Policy header manipulation or EME-specific blocking code in VS Code itself — the repo contains zero references to Widevine. This matches the well-known fact that stock/open-source Electron builds don't ship the proprietary Widevine CDM, so `encrypted-media` is unavailable by design in any vanilla Electron app; fixing it would mean VS Code bundling a licensed, closed-source CDM component, which is a product/licensing decision, not a code bug to patch. A maintainer (jruales) is already assigned, so this stays open pending their call rather than being closed here.

## Change summary

Video sites requiring Encrypted Media Extensions (Widevine DRM), like YouTube and Instagram, won't play video in the Integrated Browser because requestMediaKeySystemAccess is rejected on every page.

## Best solution

If the team wants DRM video to work in the Integrated Browser, it requires bundling a licensed Widevine CDM component into VS Code's Electron build (as some other open-source Electron apps optionally do) — a licensing and packaging decision beyond a normal code change. If that's not something the project will pursue, the right outcome is a maintainer comment setting expectations (e.g. *out-of-scope) rather than an engineering fix.
