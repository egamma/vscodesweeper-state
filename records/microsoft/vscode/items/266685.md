# Issue #266685 — Add support for SVGs for product icons

[https://github.com/microsoft/vscode/issues/266685](https://github.com/microsoft/vscode/issues/266685)

## Summary

A real product-icon theming gap remains on current main: themes can supply icon fonts but not SVG symbols. Keep this Backlog request open as under discussion because the API, rendering, security, and performance contracts need product design, and there is currently no broader community demand or verified canonical issue.

## Change summary

Allow product icon themes to define icons using SVG assets or sprite symbols instead of requiring icon-font characters.

## Best solution

Design an SVG-backed product-icon representation that preserves ThemeIcon fallback behavior and current theming semantics while defining safe extension-resource loading, color inheritance, caching, and rendering-performance constraints.

## Evidence

- **current schema:** src/vs/workbench/services/themes/common/productIconThemeSchema.ts exposes only `fonts` and font-character-based `iconDefinitions`; it has no SVG asset, sprite, or symbol-ID definition.
- **current loader:** src/vs/workbench/services/themes/browser/productIconThemeData.ts rejects theme documents without a non-empty `fonts` array and only constructs `IconDefinition` values from `fontCharacter` and `fontId`.
- **rendering contract:** src/vs/platform/theme/common/iconRegistry.ts models IconDefinition as a font character with an optional font, while src/vs/platform/theme/browser/iconsStyleSheet.ts renders product icons through `@font-face` and `.codicon-*:before { content: ... }`; SVG-backed definitions are not supported.
- **canonical search:** Repository searches for open issues covering SVG product-icon themes or replacing product icon fonts found no canonical issue. https://github.com/microsoft/vscode/issues/163748 is older but concerns the selected-state color of extension-provided static SVG icons, not SVG support in product icon themes, so it does not meet the stronger re-review duplicate bar.
- **demand and scheduling:** The issue is assigned to the Backlog holding milestone but has no comments or community upvotes, so it remains a valid unscheduled design request rather than an agent-ready implementation candidate.
