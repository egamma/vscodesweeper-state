# Issue #189374 — Git - Add audio cues for sync changes operation

[https://github.com/microsoft/vscode/issues/189374](https://github.com/microsoft/vscode/issues/189374)

## Summary

Keep open: Git sync still lacks dedicated audible outcome feedback, and the discussion establishes maintainer interest in adding it. The existing task signals do not cover Git sync; sound design remains unresolved.

## Change summary

Provide distinguishable audio feedback when a user-initiated Git sync succeeds or fails.

## Best solution

Provide configurable accessibility signals for the final outcome of user-initiated Git sync, without requiring users to inspect the status bar. Settle the success and failure sound identities with the accessibility owner, then connect Git operation outcomes to the workbench signal infrastructure.

- **Validation:** With a screen reader and the intended sound settings enabled, use two local Git clones and a bare remote: verify a successful Git: Sync produces one success cue after the complete pull/push operation, and a rejected push produces one distinct failure cue. Repeat through the status-bar and SCM Sync Changes actions; verify cancellation and declining confirmation do not produce a success cue, background fetch produces neither outcome cue, and disabling the sound suppresses it.
- **Behavior:**

  > A screen-reader user should learn the final outcome of an explicitly initiated Git sync without navigating to the status bar. Success and failure must be audibly distinguishable, and the save sound must remain distinct as requested in the discussion. Feedback should represent the complete sync operation, not each nested pull or push. Acceptance covers the command palette, SCM action, and status-bar triggers, with no success indication for cancellation and with sound preferences respected.
- **Trace:**

  > Commands._sync in extensions/git/src/commands.ts checks HEAD/upstream and optional confirmation before calling Repository.sync; a missing upstream takes a separate push path, and sync/syncRebase suppress cancellation errors. Repository._sync in extensions/git/src/repository.ts runs Operation.Sync around pull and optional push, while Repository.run emits onDidRunOperation with the recorded error after operation cleanup. No sync signal integration was found in the Git extension or SCM contribution. Task outcome signals already exist in src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts, but their announcements identify tasks and their callers are task-specific. The trace stops at how Git extension outcomes should reach the workbench signal service; no bridge was established. Preserve Git execution, confirmation, cancellation, error reporting, and background-fetch behavior. The sound discussion at https://github.com/microsoft/vscode/issues/189374#issuecomment-1662795305 remains unresolved, while https://github.com/microsoft/vscode/issues/189374#issuecomment-1698937885 establishes the explicit-user-action scope.
- **Open decisions:**
