# Issue #141801 — Untitled custom editor in web version

[https://github.com/microsoft/vscode/issues/141801](https://github.com/microsoft/vscode/issues/141801)

## Summary

Keep open: custom documents still bypass the default-save-path logic used by untitled text documents. The dialog now has additional authority handling, so the reported github.dev failure needs retesting; the report already identifies the trigger and expected behavior sufficiently.

## Change summary

Saving an untitled custom document on github.dev should select a valid workspace destination without requiring the extension to supply the workspace authority.

## Best solution

Make untitled custom-document saving resolve a valid default destination consistently with text-document saving, while preserving explicitly associated destinations. Treat the optional preferred-filename/default-path API request separately from correcting the save failure.

Compare with a URI containing the correct authority and verify explicitly associated destinations and cancellation retain their existing behavior.
- **Behavior:**

  > An extension opening an untitled custom document on github.dev should not need to discover and copy the repository filesystem authority merely to make Save work. Saving should offer a valid destination and persist the document when accepted. Retest the reported failure first, then verify the authority-free and correct-authority cases, cancellation, and preservation of explicitly associated destinations. Adding a public preferred-filename or default-path API is outside the narrow bug acceptance criteria.
- **Trace:**

  > MainThreadCustomEditorModel.saveCustomEditor calls suggestUntitledSavePath in src/vs/workbench/api/browser/mainThreadCustomEditors.ts, which converts the untitled URI with toLocalResource and supplies it directly to pickFileToSave. Without a replacement remote authority, toLocalResource in src/vs/base/common/resources.ts preserves the input authority, including an empty one. TextFileService.suggestSavePath instead obtains the dialog defaultFilePath for untitled text documents without associated destinations. AbstractFileDialogService.defaultFilePath derives a location from file/workspace history or the preferred home. SimpleFileDialog now handles scoped authorities, so the unresolved question is whether the reported github.dev failure still occurs through the complete provider/dialog path. Preserve explicit destination semantics; https://github.com/microsoft/vscode/issues/127212 tracks related factory behavior, and https://github.com/microsoft/vscode/issues/141561 records the separate filename API request.
