# Issue #277212 — Code review: Allow reviewing stacked commits and vs base branch

[https://github.com/microsoft/vscode/issues/277212](https://github.com/microsoft/vscode/issues/277212)

## Summary

This team-authored feature request remains necessary: current built-in code-review commands cover selections and uncommitted changes, but provide no user-facing way to review a commit range or compare the branch with a chosen base. The related reports do not qualify as older, same-symptom canonicals for this re-reviewed issue.

## Change summary

Allow Copilot code review to review committed branch work against a base ref and support stacked-commit review without relying on GitHub Pull Requests.

## Best solution

Provide a provider-neutral review target in the built-in Code Review surface, allowing users to select or infer a base ref and review either the aggregate branch diff or meaningful ranges within a commit stack. The design should work with local Git and non-GitHub remotes rather than depending on GitHub Pull Requests.

- **Behavior:**

  > Users can start Code Review for the committed work on their current branch relative to an inferred or selected base ref, without installing GitHub Pull Requests and without requiring a GitHub remote. The review includes the intended committed range and maps comments to current working-tree files. Existing selection, staged, unstaged, and uncommitted review commands retain their current behavior. The design must also define whether stacked commits are reviewed as one aggregate result or as separately navigable units.
- **Trace:**

  > The command registrations in extensions/copilot/src/extension/inlineChat/vscode-node/inlineChatCommands.ts currently map only to selection/index/workingTree/all ReviewGroup values. ReviewSession and ReviewGroup in extensions/copilot/src/extension/review/node/doReview.ts carry no base-ref or commit-range representation. collectDiffChanges in extensions/copilot/src/extension/review/node/githubReviewAgent.ts enumerates index and working-tree state and compares it with HEAD, while the vendored Git Repository API already exposes diffWith(ref), diffBetween(ref1, ref2), and show(ref, path). The lower-level github.copilot.chat.codeReview.run path can consume caller-prepared base content, but it does not provide the requested user-facing target selection. Keep GitHub PR-stack management and rebase operations out of scope; https://github.com/microsoft/vscode/issues/328721 and https://github.com/microsoft/vscode-pull-request-github/issues/8887 track that broader product surface.
- **Open decisions:**
  - Should the review target default to an automatically inferred upstream/base branch, require an explicit ref picker, or expose both behaviors?
  - Should stacked commits produce one aggregate base-to-HEAD review or separately navigable per-commit reviews?
  - When the branch also has staged or unstaged changes, should branch review exclude them by default or offer an explicit combined mode?
