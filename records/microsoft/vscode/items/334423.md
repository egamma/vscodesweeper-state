# Issue #334423 — Agent host: a slash command is never executed when the turn carries host context

[https://github.com/microsoft/vscode/issues/334423](https://github.com/microsoft/vscode/issues/334423)

## Summary

Real, freshly-reported bug with a precise mechanism: `resolvePromptToContentBlocks` in claudePromptResolver.ts always emits the user's text as the first content block and then pushes separate additional text blocks for feedback/simple attachments and reference lines, so any turn carrying attachments becomes a multi-text-block message — exactly the shape the reporter's SDK-level table shows silently breaks slash-command execution.

## Change summary

Slash commands in the agent chat stop being recognized/executed by the Claude CLI whenever the turn also carries attachment or reference context, because the prompt is split across multiple text content blocks instead of one.

## Best solution

In claudePromptResolver.ts, when the prompt is a slash command, merge the appended feedback/simple/reference text into the first text block (as the reporter's own repro table shows this still expands correctly) instead of pushing them as additional blocks, leaving non-text blocks and the non-slash-command multi-block shape unchanged.
