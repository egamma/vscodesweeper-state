# Issue #179872 — "Accept all Current/Incoming" does not work when selecting multiple files (in Source Control Tab)

[https://github.com/microsoft/vscode/issues/179872](https://github.com/microsoft/vscode/issues/179872)

## Summary

This remains a credible bulk-action bug: multiple users confirmed the failure, and the reporter supplied a recording from VS Code 1.101.2 after a maintainer requested current evidence. Current source still intends to process every selected SCM resource, but the runtime failure has not been diagnosed or superseded by a fixing commit.

## Change summary

Accept All Current and Accept All Incoming affect only the context file, or do nothing, when multiple conflicted files are selected in Source Control.

## Best solution

Trace the SCM context-menu arguments through `RepositoryPaneActionRunner` into the merge-conflict extension and restore reliable processing of every selected conflicted file, while preserving command-palette and single-file behavior.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/commandHandler.ts`, `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/api/common/extHostSCM.ts`
- **Validation:** Create two text files with Git conflict markers, select both under Source Control's Merge Changes group, and invoke both Accept All Current and Accept All Incoming from the context menu; each command must resolve the chosen side in both files, while invoking it on one file must affect only that file.
- **Behavior:**

  > When multiple conflicted files are selected in Source Control, Accept All Current and Accept All Incoming must apply the chosen side to every selected file. The command must not silently fall back to only the right-clicked file or do nothing. Single-file invocation and editor-level Accept All behavior must remain unchanged. Acceptance requires exercising both commands with at least two selected conflicted files.
- **Trace:**

  > `RepositoryPaneActionRunner` in `src/vs/workbench/contrib/scm/browser/scmViewPane.ts` gathers selected SCM resources and forwards them as individual command arguments. `ExtHostSCM` in `src/vs/workbench/api/common/extHostSCM.ts` converts marshalled SCM resources to extension resource states, after which `CommandHandler.registerTextEditorCommand` in `extensions/merge-conflict/src/commandHandler.ts` chooses the bulk path only when every argument exposes `resourceUri`; `acceptAllResources` then builds one workspace edit across the documents. This is the same path introduced by commit 039a49a5eab688800b0226cf2c4addc797c94a86 for https://github.com/microsoft/vscode/issues/63621, yet the 2025 recording confirms a runtime failure. Diagnosis should determine where the selection or argument shape diverges without changing single-file, command-palette, save, staging, or merge-editor semantics. The multi-repository behavior in https://github.com/microsoft/vscode/issues/134370 is related but a distinct configuration-specific path.
