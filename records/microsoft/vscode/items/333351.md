# Issue #333351 — # selector in CSS is misinterpreted as color

[https://github.com/microsoft/vscode/issues/333351](https://github.com/microsoft/vscode/issues/333351)

## Summary

The false color decorator remains reproducible from current source: the language-agnostic default provider recognizes hex-shaped CSS selectors in PHP documents. The later `bug` classification confirms this should remain open despite the available setting workaround.

## Change summary

CSS ID selectors whose names resemble hexadecimal colors receive incorrect color decorators when embedded in PHP documents.

## Best solution

Make the default document color detection distinguish CSS ID-selector syntax from standalone color values while preserving generic color decorators in languages without a specialized provider.

## Evidence

- **current source path:** src/vs/editor/contrib/colorPicker/browser/defaultDocumentColorProvider.ts registers DefaultDocumentColorProvider for `*`, and src/vs/editor/common/languages/defaultDocumentColorsComputer.ts applies a context-free regex that accepts 3-, 4-, 6-, and 8-digit `#` tokens at line starts or after whitespace. A selector such as `#abcdef {` therefore produces color information on current main.
- **provider selection:** src/vs/editor/contrib/colorPicker/browser/color.ts falls back to the default provider when no language-specific provider returns colors, explaining why the problem appears in PHP while embedded CSS in HTML can be handled by a language-aware provider.
