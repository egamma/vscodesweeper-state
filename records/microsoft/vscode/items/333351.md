# Issue #333351 — # selector in CSS is misinterpreted as color

[https://github.com/microsoft/vscode/issues/333351](https://github.com/microsoft/vscode/issues/333351)

## Summary

The CSS language server only decorates real CSS/SCSS/Less documents; what the reporter sees in PHP is the generic fallback "default document color provider" that heuristically flags any `#`+hex-like token in any language, and its own maintainer (aeschli) confirmed this on the linked PR and pointed to the existing `editor.defaultColorDecorators` setting — this is expected, controllable heuristic behavior, not a CSS-server bug.

## Change summary

In PHP files (embedded CSS-like content), ID selectors such as `#333` are shown with an inline color swatch as if they were hex colors.

## Best solution

Close as as-designed: the false positive comes from the generic fallback color provider (src/vs/editor/contrib/colorPicker/browser/defaultDocumentColorProvider.ts, registered for '*' via DefaultDocumentColorProviderFeature) applying the regex heuristic in defaultDocumentColorsComputer.ts to any language lacking a dedicated color provider. Users can disable it globally or per-language with `editor.defaultColorDecorators: "never"` (e.g. scoped to `[php]`).

- **Proposed comment:**

  > Thanks for the report. This isn't the CSS language server misfiring in PHP — the CSS server only decorates actual `.css`/`.scss`/`.less` documents. What you're seeing is VS Code's generic fallback "default color decorators" heuristic, which applies to any language without its own color provider and flags anything shaped like `#` + 3/4/6/8 hex digits, including ID selectors that happen to look like hex values. This was confirmed on the linked PR by the CSS features maintainer. You can turn it off for PHP with:
  > 
  > ```json
  > "[php]": { "editor.defaultColorDecorators": "never" }
  > ```
  > 
  > Closing as as-designed given the existing setting covers this.
