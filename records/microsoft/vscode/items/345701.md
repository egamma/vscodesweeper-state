## Evidence

- **Current-source diagnosis:** At checkout revision 53d2211d37ea4112096159c6efb75d513c8d975e, src/vs/base/common/mime.ts still uses /^(.+)\/(.+?)(;.+)?$/. For Multipart/FORM-DATA; boundary="AbC/DeF", the greedy first group consumes through AbC, making the parameter slash the separator; lowercasing groups 1 and 2 consequently changes the boundary to abc/def. Both overloads share this implementation.
- **Intended behavior and existing coverage:** src/vs/base/common/mime.ts explicitly states that parameters must not be lowercased. The normalize test in src/vs/base/test/common/mime.test.ts checks preservation of uppercase parameters but contains no parameter value with a slash. Diagnosis was by source inspection; no tests or builds were run.

Its fetched conversation explicitly links this issue and describes restricting the type match and adding regression cases for boundaries, SOAP action URLs, multiple parameters, and both overloads.
