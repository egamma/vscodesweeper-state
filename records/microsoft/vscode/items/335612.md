# Issue #335612 — Automatic session cleanup can archive or delete using stale eligibility after a GitHub refresh

[https://github.com/microsoft/vscode/issues/335612](https://github.com/microsoft/vscode/issues/335612)

## Summary

Team-authored, well-diagnosed race condition: the deletion and archival paths in AgentHostSessionLifecycle check settings/eligibility before an awaited GitHub PR refresh but never re-check those same local facts after the await resolves, so a setting change or state change during the pending refresh is silently ignored. Traced this directly in the current code — real, actionable, and no fix has landed yet.

## Change summary

Automatic session archival/deletion can act on stale eligibility (disabled setting, session resumed, or manual archive) because local checks aren't re-validated after the final awaited GitHub refresh completes.

## Best solution

In agentHostSessionLifecycle.ts, re-evaluate the settings/session-state checks that currently precede the final `await this._arePullRequestsComplete(...)` so they run again after that await resolves (for both the archive dispatch around line 162-179 and the delete callback's final `&&` chain around line 193-205), closing the check-then-act window.
