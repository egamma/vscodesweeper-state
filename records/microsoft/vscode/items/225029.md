- **Behavior:**

  > The built-in Source Control Graph can be opened as an editor tab so users can inspect complex histories without sidebar width constraints. The editor surface retains the existing graph's history navigation, repository selection, filtering, and contextual actions. Opening a commit diff alone does not satisfy this requirement. Full Git Graph extension parity and additional destructive Git operations are outside this MVP.
- **Trace:**

  > src/vs/workbench/contrib/scm/browser/scm.contribution.ts registers the graph as a movable SCMHistoryViewPane, not an editor. ViewContainerLocation in src/vs/workbench/common/views.ts offers only sidebar, panel, and auxiliary-bar locations, so ordinary view movement does not provide editor-tab hosting. In src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts, SCMHistoryViewPane extends ViewPane, scopes context keys to the view, and creates and clears its model through body-visibility changes. The existing viewChanges action opens a multi-diff editor for commit contents, not the graph. The unresolved technical boundary is how editor hosting preserves those lifecycle and context assumptions; this review did not establish a bounded implementation. Preserve existing graph behavior and Git operation semantics, and coordinate with https://github.com/microsoft/vscode/issues/242754 without treating that newer issue as a duplicate target.
