## Summary

Both reported bugs are still present on current main: the legacy issue reporter's `updatePublicRepoLink` adds duplicate click/auxclick listeners each time it is called (lines 361–362 of baseIssueReporterService.ts), causing the repo link to open multiple times. The legacy reporter path is still active (wizard is behind a config flag). Keeping open.

## Change summary

Issue reporter repo link opens multiple times due to duplicate event listeners, and the repo link is not created when selecting an extension via the top menu.

## Best solution

Move the `addEventListener` calls inside the `if (!issueRepoName)` branch (the element-creation guard at line 349) so listeners are registered only once when the element is first created, not on every update. The second bug (link not created when selecting an extension via menu) should also be investigated in the same area — the `updatePublicRepoLink` method may not be called or may lack the extension URI in that code path.
