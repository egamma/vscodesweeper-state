# Issue #286719 — Webview input fields fail to capture focus when clicking window to return

[https://github.com/microsoft/vscode/issues/286719](https://github.com/microsoft/vscode/issues/286719)

## Summary

Still reproduces on main: the webview focus-restore path (`_doFocus` in webviewElement.ts → `focus` message → `activeFrame.contentWindow.focus()` in pre/index.html) focuses the iframe window generically without forwarding the click target, so OS window-activation clicks on input fields inside webviews land on `<body>` instead of the clicked element. Desktop-only (Electron), unfixed.

## Change summary

Clicking an input field inside a webview to re-activate the VS Code window does not focus that input — focus falls to the webview's `<body>` instead.

## Best solution

The focus-restore path needs to either (1) capture the mousedown target during window activation and forward it to the inner frame, or (2) let the Electron/Chromium click-through behavior deliver the event natively to the iframe content. The fix likely touches `src/vs/workbench/contrib/webview/browser/webviewElement.ts` (`_doFocus` / `handleFocusChange`) and possibly `src/vs/workbench/contrib/webview/browser/pre/index.html` (the `focus` message handler). An upstream Electron/Chromium iframe activation bug may also be involved — worth checking whether Electron's `will-focus` or `focus` event on the BrowserWindow swallows the click before it reaches the iframe.

- **polling-based focus tracking:** Focus is tracked via a 250ms polling interval in pre/index.html (line 61–76) using `document.hasFocus()`, which detects focus changes but cannot relay which element was clicked during window activation.
