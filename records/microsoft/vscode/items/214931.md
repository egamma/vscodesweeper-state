# Issue #214931 — Quotes around paths with spaces are not honored when running tasks

[https://github.com/microsoft/vscode/issues/214931](https://github.com/microsoft/vscode/issues/214931)

## Summary

Keep open: current task command construction still omits PowerShell's call operator for an already-quoted executable path. The discussion also contains a separately confirmed cmd.exe regression that needs diagnosis before treating the entire report as resolved.

## Change summary

Shell tasks should execute paths containing spaces correctly, including paths supplied by command variables, without requiring platform-specific task definitions.

## Best solution

Make the task launcher handle already-quoted executable paths correctly in PowerShell while preserving argument boundaries and existing cross-platform behavior. Diagnose the custom cmd.exe bootstrap failures separately so a PowerShell correction does not prematurely close the remaining reports.

## Evidence

- **Current source defect:** In src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1628–1725, _buildShellCommandLine's needsQuotes returns false when a string already has matching enclosing quotes. quoteIfNecessary consequently reports quoted=false, and commandQuoted remains false. The Windows PowerShell/pwsh branch adds '& ' only when commandQuoted is true, so an already-double-quoted Python executable followed by arguments takes exactly the missing-call-operator path reported in the thread.
- **Variable resolution and launch boundary:** In terminalTaskSystem.ts, _resolveCommandAndArgs and _resolveVariable preserve command-variable results as strings. _createShellLaunchConfig passes those results to _buildShellCommandLine and joins Windows shell arguments into a command-line string. Unquoted executable paths containing spaces receive automatic quoting and the call operator; already-quoted paths do not. Existing automatic quoting therefore covers only part of the reported behavior.
- **Confirmed reproduction and workaround:** https://github.com/microsoft/vscode/issues/214931#issuecomment-2416872908 supplies the task, generated PowerShell invocation, and 'C:\Program' failure. https://github.com/microsoft/vscode/issues/214931#issuecomment-2912043320 confirms that adding the '&' call operator works, whereas quoting alone does not. No tasks were executed during this read-only review.
- **Python-side quoting is not a complete fix:** https://github.com/microsoft/vscode-python/issues/23028#issuecomment-2002611304 records the decision to double-quote interpreter paths. https://github.com/microsoft/vscode-python/issues/23028#issuecomment-2023375800 reports that the quoted path still fails, and https://github.com/microsoft/vscode-python/issues/23028#issuecomment-2023765917 distinguishes working cmd.exe execution from failing pwsh execution.
