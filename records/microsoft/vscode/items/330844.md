# Issue #330844 — Modern UI: panelSection.border is not rendered between panel sections

[https://github.com/microsoft/vscode/issues/330844](https://github.com/microsoft/vscode/issues/330844)

## Summary

Traced this in source and it's a real gap: the Modern UI CSS override only redraws a top separator (matching the vertical/sidebar case) and never restores a left border for horizontally-stacked panel sections, even though it unconditionally strips both borders.

## Change summary

When Modern UI (workbench.experimental.modernUI) is enabled and a panel has multiple horizontally-stacked sections, the panelSection.border separator between them is invisible.

## Best solution

Add a horizontal-orientation rule in src/vs/workbench/contrib/styleOverrides/browser/media/paneHeaders.css (mirroring the existing ::before top-separator rule) that redraws a left border using panelSection.border when `.monaco-pane-view.horizontal` — PaneView already toggles a `horizontal`/`vertical` class on the pane-view element (src/vs/base/browser/ui/splitview/paneview.ts) to key off.

## Evidence

- **override strips both borders unconditionally:** src/vs/workbench/contrib/styleOverrides/browser/media/paneHeaders.css lines 28-31 set `border: none !important` on `.monaco-pane-view .pane` and `.pane > .pane-header` regardless of PaneView orientation.
- **only the vertical case is redrawn:** Lines 39-53 of the same file redraw a top separator via a `.pane-header::before` pseudo-element using panelSectionHeader.border/panelSection.border as a fallback chain, but this only produces a horizontal (top) line — there is no equivalent left-border rule for horizontally stacked sections.
- **normal (non-Modern-UI) behavior:** src/vs/base/browser/ui/splitview/paneview.ts line 353 sets `this.element.style.borderLeft` from `styles.leftBorder` (panelSection.border) only when orientation === Orientation.HORIZONTAL, and line 352 sets `borderTop` from headerBorder (panelSectionHeader.border) only when VERTICAL — confirming the two color tokens map to two distinct layout cases that the override CSS only handles one of.
- **color token definitions:** src/vs/workbench/common/theme.ts lines 547/549 confirm panelSectionHeader.border is documented for vertical stacking and panelSection.border for horizontal stacking, matching the reporter's exact repro (Explorer moved into a horizontal panel).
