# Issue #230122 — Inconsistent button order between editor and panel

[https://github.com/microsoft/vscode/issues/230122](https://github.com/microsoft/vscode/issues/230122)

## Summary

Keep open as an accepted, under-discussion consistency improvement. Current main still deliberately places pane-container actions after the view overflow, while editor close remains view-scoped; a maintainer needs to choose whether visual consistency or scope grouping governs the shared ordering.

## Change summary

Make the overflow and close-button order consistent between editor headers and panel or side-bar headers.

## Best solution

Establish one predictable ordering rule for close and overflow controls across editor, panel, and side-bar headers while preserving a clear indication that editor close affects a view and panel or side-bar close affects the container.

- **Behavior:**

  > Editor, panel, and side-bar headers should present close and overflow controls according to one predictable ordering rule. Closing an editor must still close only that editor, while closing a panel or side bar must still hide the entire container. View actions must continue to overflow or hide independently of non-hideable container actions. Validate the result with tabs disabled and with toolbar width constrained enough to show the overflow control.
- **Trace:**

  > CompositePart creates the view-scoped title toolbar in src/vs/workbench/browser/parts/compositePart.ts. AbstractPaneCompositePart.createTitleArea in src/vs/workbench/browser/parts/paneCompositePart.ts appends a separate global toolbar after it; the panel and auxiliary-side-bar close actions enter that toolbar through MenuId.PanelTitle and MenuId.AuxiliaryBarTitle. The no-tabs editor close action is registered in MenuId.EditorTitle in src/vs/workbench/browser/parts/editor/editor.contribution.ts and remains editor-scoped. Commit https://github.com/microsoft/vscode/commit/462ce94707760fb92315e292055d4e5c8a3cd5a8 later added a separator between pane scopes without resolving the ordering inconsistency. Preserve command semantics, action visibility, and overflow behavior; the uncertainty begins at which visual ordering rule should win.
- **Open decisions:**
  - Should all affected headers place Close before the overflow control for visual consistency, or should container headers retain Close after overflow to communicate the global-action boundary and the editor ordering change instead?
