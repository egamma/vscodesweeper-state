# Issue #18058 — Evaluate selected expression on hover while debugging?

[https://github.com/microsoft/vscode/issues/18058](https://github.com/microsoft/vscode/issues/18058)

## Summary

Selected-expression evaluation remains missing from the debug hover; the existing console and watch commands are workarounds, not equivalent behavior. Keep this accepted Backlog request open as the canonical discussion, with evaluation safety and interaction design settled before implementation.

## Change summary

Allow a selected JavaScript or TypeScript expression to be evaluated and displayed in the debug hover while execution is paused.

## Best solution

Provide selection-aware debug inspection without unexpectedly executing side effects, preserving ordinary symbol hovers. Reconcile the explicit-evaluation interaction discussed in the earlier PR with the later EvaluatableExpressionProvider direction before implementing it.

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugHover.ts`, `src/vs/workbench/contrib/debug/common/debugUtils.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/test/browser/debugHover.test.ts`

Verify ordinary unselected symbol hovers remain unchanged and use a counter-mutating function to confirm that execution occurs only under the agreed consent policy. Add automated coverage for selection boundaries and the chosen evaluation trigger.
- **Behavior:**

  > While paused in a JavaScript or TypeScript debug session, users should be able to inspect a selected compound expression through the debug hover rather than copying it into the console. Ordinary symbol hovers must retain their existing behavior. Acceptance must cover selected-expression results, hovering outside the selection, and whether side-effecting expressions execute only after explicit consent or under a deliberately enabled policy.
- **Trace:**

  > DebugHoverComputer.compute in src/vs/workbench/contrib/debug/browser/debugHover.ts obtains an expression from getEvaluatableExpressionAtPosition using only a model and position; evaluate submits that expression with the 'hover' context. The helper in src/vs/workbench/contrib/debug/common/debugUtils.ts delegates to language providers or a single-line fallback and never receives the editor selection. SelectionToReplAction and SelectionToWatchExpressionsAction in src/vs/workbench/contrib/debug/browser/debugEditorActions.ts demonstrate existing selected-text evaluation, but not the requested presentation. https://github.com/microsoft/vscode/pull/83388 was closed unmerged after discussion of explicit evaluation and configurable consent. Later discussion on https://github.com/microsoft/vscode/issues/18058 points toward EvaluatableExpressionProvider, and related expression-range reports were consolidated here. Preserve ordinary hover behavior and debug-adapter evaluation contracts; the uncertainty is the intended execution and consent behavior, not merely where to read selected text.
- **Open decisions:**
  - Should selecting and hovering automatically evaluate only expressions the debugger can prove side-effect-free, or should the hover offer an explicit action capable of evaluating the full selection?
  - Should users be able to opt into automatic evaluation of potentially side-effecting selections, or must those evaluations always require an explicit action?

## Evidence

- **Current hover does not consume the selection:** In src/vs/workbench/contrib/debug/browser/debugHover.ts, DebugHoverComputer.compute passes only the model and hovered position to getEvaluatableExpressionAtPosition. Its evaluate method evaluates the resulting expression with the 'hover' context. Neither operation reads the editor selection.
- **Expression-provider support is not selection evaluation:** src/vs/workbench/contrib/debug/common/debugUtils.ts:getEvaluatableExpressionAtPosition asks registered providers for an expression at a position, or falls back to a single-line expression extractor. This supports language-aware hover ranges but does not itself deliver arbitrary selected-expression evaluation.
- **Existing-capability check:** src/vs/workbench/contrib/debug/browser/debugEditorActions.ts implements editor.debug.action.selectionToRepl and editor.debug.action.selectionToWatch, both of which read selected text. They display results through the console or watch view rather than the requested hover. Searches found no debug.evaluateSelectedText or debug.evaluateSelectionOnHover setting in the inspected debug and TypeScript sources.
