# Issue #254952 — Slow calls to getRepositoryFetchUrls for larger repos for codebase search

[https://github.com/microsoft/vscode/issues/254952](https://github.com/microsoft/vscode/issues/254952)

## Summary

Fixed on main by the issue author themselves; the performance improvements shipped in 1.116.0, so this can be closed as completed.

## Change summary

Calls to `getRepositoryFetchUrls` were too slow for large repos (100k+ files) during codebase search indexing, because each file triggered an expensive per-file git process spawn and object creation.

## Best solution

Keep the shipped fix in commit c4f2857249a (1.116.0). The fix parallelizes `isIgnored` checks, skips expensive `repoToRepoContext` observable creation, adds cancellation checks, and avoids redundant observable creation in `waitForRepositoryState`. No further change needed.
