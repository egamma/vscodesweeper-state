# Issue #254952 — Slow calls to getRepositoryFetchUrls for larger repos for codebase search

[https://github.com/microsoft/vscode/issues/254952](https://github.com/microsoft/vscode/issues/254952)

## Summary

The performance issue has been addressed through multiple shipped fixes: parallel isIgnored checks, skipping expensive RepoContextImpl creation, and a repo-root cache in RemoteContentExclusion that avoids calling getRepositoryFetchUrls for every file. All fixes shipped in 1.116.0+.

## Change summary

Calls to getRepositoryFetchUrls were per-file and too slow for large repos (100k+ files) during codebase search indexing.

## Best solution

Keep the shipped fixes — the repo-root cache in RemoteContentExclusion (commit 6f65015521c) and the parallelization/optimization in commit c4f2857249a eliminate the per-file getRepositoryRoot process spawn. No further change needed.
