# Issue #295924 — Copilot Chat stuck at "getting chat ready" on Remote SSH with ulimit -v restriction (WASM OOM)

[https://github.com/microsoft/vscode/issues/295924](https://github.com/microsoft/vscode/issues/295924)

## Summary

Keep open pending verification of the exact 16 GB Remote SSH scenario. Current main includes Node's automatic low-virtual-memory adaptation, but that upstream fix does not conclusively cover a process that has already consumed most of a limit large enough for one WASM cage, and Copilot still has no clearly identified actionable-error path for residual allocation failures.

## Change summary

Copilot Chat fails to initialize on memory-restricted Remote SSH hosts and should report the WASM virtual-memory failure with its available workaround instead of remaining at the setup screen.

## Best solution

First verify Remote SSH and Copilot Chat with the current bundled Node runtime under the reported 16 GB `RLIMIT_AS`. If allocation still fails, the runtime threshold should be corrected upstream and Copilot's activation/setup path should surface an actionable localized error rather than a generic readiness timeout.

## Evidence

- **confirmed root cause:** https://github.com/microsoft/vscode/issues/251777 and https://github.com/microsoft/vscode-remote-release/issues/11027 contain maintainer diagnosis and multiple confirmations that restricted `RLIMIT_AS` causes Node/V8's WASM trap-handler cage allocation to fail; the documented workaround is `NODE_OPTIONS="--disable-wasm-trap-handler"`.
- **upstream fix:** https://github.com/nodejs/node/commit/b411f904135bee50ddd1658719ede70db991579f changes `src/node.cc` to inspect `RLIMIT_AS` before enabling the WASM trap handler and adds a 3 GB limited-memory test. Its documentation explicitly notes that allocation can still fail when the limit permits an initial cage but later leaves insufficient address space.
- **runtime adoption:** https://github.com/microsoft/vscode/pull/332935 updated `remote/.npmrc` to Node 24.20.0, which includes the upstream behavior; current main now specifies Node 24.21.0 in `remote/.npmrc`.
- **remaining uncertainty:** The report's trigger is a 16 GB virtual-memory cap with approximately 12 GB already mapped before Copilot initializes. The upstream check compares the process limit with the reservation needed for one cage and therefore does not by itself prove that this exact remaining-address-space condition is fixed.
- **current error path:** `extensions/copilot/src/extension/extension/vscode/extension.ts` awaits experimentation initialization and contribution activation blockers without a specialized handler for WASM allocation failures; `extensions/copilot/src/platform/parser/node/languageLoader.ts` also returns `Parser.Language.load(...)` errors directly.
