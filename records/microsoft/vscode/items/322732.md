## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/services/contextmenu/electron-browser/contextmenuService.ts`, `src/vs/platform/contextview/browser/contextMenuHandler.ts`
- **Validation:** On macOS, produce a known Debug Console log line and select a middle substring entirely within the viewport. Compare direct Cmd+C with right-click followed by the context-menu Copy action and with dismissing the menu followed by Cmd+C; each paste must equal the selected substring. Repeat across multiple lines and with native and custom context menus, then separately test a selection spanning scrolled content.
- **Behavior:**

  > Selecting a Debug Console log fragment and right-clicking it must not discard the selection. Copying that selection must paste exactly the selected text rather than the whole log entry or a truncated fragment. Direct Cmd+C and context-menu Copy should both work, while copying an entry without a text selection must retain its existing behavior.
- **Trace:**

  > In src/vs/workbench/contrib/debug/browser/repl.ts, Repl.onContextMenu forwards the clicked element to context-menu actions, and debug.replCopy reads the live DOM selection only when the action runs. If that selection is empty, it copies the element's value instead. Context-menu dispatch runs through src/vs/workbench/services/contextmenu/electron-browser/contextmenuService.ts; the HTML implementation in src/vs/platform/contextview/browser/contextMenuHandler.ts focuses the menu. Inspection identifies the relevant boundary but does not establish which event clears selection on macOS, so reproduction is the first step. Preserve no-selection element copying and clipboard-context evaluation behavior, and do not assume scrolling virtualization is the same defect. The older related report https://github.com/microsoft/vscode/issues/268456 describes context-menu copy truncation on Linux but does not confirm this report's selection-loss trigger.
