# Issue #336839 — Ensure enterprise Copilot OTel settings override environment variables

[https://github.com/microsoft/vscode/issues/336839](https://github.com/microsoft/vscode/issues/336839)

## Summary

Source-confirmed gap: the OTel config resolver blends policy-backed defaults into the ordinary `setting*` inputs to `resolveOTelConfig` instead of the `policy*` inputs, so conflicting environment variables win for enablement, exporter type, endpoint, protocol, content capture, service name, and headers. A locked regression test in the repo explicitly documents this as current behavior, matching the issue's own account that it's an accepted, not-yet-fixed gap.

## Change summary

Environment variables (e.g. COPILOT_OTEL_ENABLED, OTEL_EXPORTER_OTLP_ENDPOINT) can currently override enterprise-managed Copilot OTel policy settings; they should not for policy-managed fields.

## Best solution

In extensions/copilot/src/platform/otel/common/otelConfigResolution.ts, route policy-backed defaultValues through the existing `policy*` parameters of `resolveOTelConfig` (extensions/copilot/src/platform/otel/common/otelConfig.ts already implements policy > env > setting precedence for every field) instead of folding them into `setting*`, mirroring how `policyCaptureIdentity`/`policyResourceAttributes` are already wired; then update the 'preserves existing effective-setting resolution and env precedence' test to assert the new, intended precedence.
