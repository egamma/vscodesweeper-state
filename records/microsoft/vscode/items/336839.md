# Issue #336839 — Ensure enterprise Copilot OTel settings override environment variables

[https://github.com/microsoft/vscode/issues/336839](https://github.com/microsoft/vscode/issues/336839)

## Summary

Confirmed on main: `resolveOTelConfigFromSettings` in otelConfigResolution.ts feeds enterprise policy-backed defaults into `resolveOTelConfig`'s `setting*` inputs instead of its `policy*` inputs, so process environment variables (e.g. `OTEL_EXPORTER_OTLP_ENDPOINT`, `COPILOT_OTEL_ENABLED`) still win over managed OTel policy — this is a real enterprise-policy-bypass/data-governance gap, so it stays open rather than closed.

## Change summary

Enterprise-managed Copilot OTel settings (enablement, endpoint, content capture, etc.) can be overridden by process environment variables because the resolver treats managed defaults as ordinary settings, not policy.

## Best solution

In resolveOTelConfigFromSettings (extensions/copilot/src/platform/otel/common/otelConfigResolution.ts), when hasEnterpriseSettings is true, route the recognized managed fields through resolveOTelConfig's policy* parameters instead of setting*, so the existing policy>env precedence in otelConfig.ts actually applies; add regression coverage for env-override attempts (endpoint redirection, disable-via-env, file-export diversion) using the existing TestOTelSettings harness.

## Evidence

- **precedence bug:** extensions/copilot/src/platform/otel/common/otelConfig.ts documents/implements precedence as policy > env > setting for enabled/endpoint/captureContent/etc.; since managed values arrive as `setting*`, env vars listed in snapshotOTelEnv (COPILOT_OTEL_ENABLED, OTEL_EXPORTER_OTLP_ENDPOINT, ...) outrank them.
