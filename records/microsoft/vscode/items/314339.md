# Issue #314339 — localhost is always blocked when chat.agent.networkFilter is enabled

[https://github.com/microsoft/vscode/issues/314339](https://github.com/microsoft/vscode/issues/314339)

## Summary

Confirmed on current main: `matchesDomainPattern` rejects `localhost` from the allowlist because the `wellKnownDomainSuffixes` heuristic fires on user-supplied patterns that lack a dot. An open PR (#317732) exists to fix this.

## Change summary

When `chat.agent.networkFilter` is enabled, `localhost` in `allowedNetworkDomains` is silently ignored because the domain-normalization heuristic rejects single-label hostnames.

## Best solution

The fix should ensure that `normalizeDomain` skips the `wellKnownDomainSuffixes` heuristic when processing user-supplied allow/deny patterns (as opposed to domains extracted from freeform terminal text). PR https://github.com/microsoft/vscode/pull/317732 is the active fix attempt — review and land it.
