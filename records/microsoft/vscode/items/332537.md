# Issue #332537 — Troubles installing dictation functionality manually

[https://github.com/microsoft/vscode/issues/332537](https://github.com/microsoft/vscode/issues/332537)

## Summary

Real, traceable gap in the new dictation feature: a network-blocked download of the Foundry Local *runtime* is generically classified and surfaced as if the *model* download failed, pointing users at the wrong recovery action (model-only local-package import) with no supported offline path for the runtime itself.

## Change summary

On restricted networks, dictation's error message and 'Install from Local Package' recovery only address a blocked model download, not a blocked runtime download, leaving users to reverse-engineer a manual runtime install.

## Best solution

Give runtime-provisioning failures in ensureFoundryLocalRuntime() (foundryLocalRuntime.ts) a distinct errorCode (mirroring the 'runtime' code already used in the streaming-failure path at localTranscriptionService.ts:590) instead of falling through generic classifyModelError() keyword matching in the _openSession catch (localTranscriptionService.ts:430-436), then extend the offline-install UX (installDictationModelAction.ts / chatSpeechToTextService.ts:_failModelSession) and the accessibility voice docs to cover installing the runtime tarball locally, not just the model.

## Evidence

- **misleading classification:** src/vs/platform/localTranscription/node/localTranscriptionService.ts:430-436 catches any _ensureModel() failure (including a runtime-provisioning failure from ensureFoundryLocalRuntime() at line 487) and classifies it with the generic keyword-based classifyModelError() (lines 58-76), which has no awareness that the failure came from the runtime leg rather than the model leg.
- **misattributed UI message:** src/vs/workbench/contrib/chat/browser/speechToText/chatSpeechToTextService.ts:1256-1272 _failModelSession() only checks errorCode 'network'/'notFound' to decide whether to show 'Could not download the {model} speech-to-text model... Install from Local Package...' — a runtime download failure with a network-shaped message hits this same branch, naming the model when the runtime is actually what failed.
- **no runtime install path:** installDictationModelAction.ts (INSTALL_DICTATION_MODEL_COMMAND_ID) only imports a model package into chatDictationModels; there is no equivalent supported action for the runtime tarball under chatDictationRuntime, matching the reporter's need to manually place files and a .complete-win32-x64 marker themselves.
- **runtime provisioning design:** src/vs/platform/localTranscription/node/foundryLocalRuntime.ts documents that the native runtime is downloaded on demand from VS Code's CDN per product.dictationRuntime and is a separate leg from the model download, confirming these are two distinct failure points conflated by one error message.
