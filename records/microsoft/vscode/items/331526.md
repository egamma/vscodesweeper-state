# Issue #331526 — Agent host cannot read project-scope customizations in a remote window: slash commands are missing until the first turn

[https://github.com/microsoft/vscode/issues/331526](https://github.com/microsoft/vscode/issues/331526)

## Summary

Well-diagnosed bug with a matching open fix PR (#331527, 'Fixes #331526') already up — the issue should stay open until that PR merges rather than being closed now.

## Change summary

In a remote/dev-container window, the agent host resolves project working directories with a vscode-remote: URI its own file service can't read, so project-scope customizations (slash commands, rules, MCP servers, hooks) are silently missing until an SDK turn populates its own command list.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/331527, which adds a toHostLocalUri conversion in src/vs/platform/agentHost/common/agentHostUri.ts and applies it to the host-side disk scans in src/vs/platform/agentHost/node/claude/claudeAgentSession.ts; keep the issue open until that merges, and consider whether the same working-directory URI issue applies to the Codex customization scan noted as unverified in both the issue and the PR.
