# Issue #298873 — Custom models did not properly using think method (kimi2.5, glm5)

[https://github.com/microsoft/vscode/issues/298873](https://github.com/microsoft/vscode/issues/298873)

## Summary

This is a satellite of the better-diagnosed, assigned https://github.com/microsoft/vscode/issues/323172, which tracks the same root cause: BYOK reasoning models not properly surfacing thinking content. The core `reasoning_content` field support was added in commit a21f814cede (May 2026), which covers models that send it as a separate field; the remaining work (models sending `reasoning` or inline `<think>` tags) is tracked by #323172.

## Change summary

Custom BYOK models (Kimi, GLM, Qwen) do not render thinking/reasoning content properly — the raw `<think>` tags appear inline or reasoning is silently dropped.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/323172, which is assigned to vritant24 and tracks the remaining BYOK reasoning-field parsing work. The `reasoning_content` field was already added in commit a21f814cede; what remains is handling additional field names and edge cases (like `delta.reasoning` only, or inline `<think>` tags when the server doesn't use a structured reasoning field).
