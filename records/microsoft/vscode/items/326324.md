# Issue #326324 — SSH askpass shows yes/no host-fingerprint prompt instead of PIN input for FIDO2/security-key authentication

[https://github.com/microsoft/vscode/issues/326324](https://github.com/microsoft/vscode/issues/326324)

## Summary

Confirmed from source: the SSH askpass handler only special-cases passphrase prompts, so OpenSSH's FIDO2 PIN prompt falls through to the host-fingerprint yes/no quick pick instead of a password input box, breaking security-key signed Git operations when the integrated askpass is used.

## Change summary

handleSSHAskpass() misclassifies the FIDO2/security-key 'Enter PIN for authenticator:' prompt as a host-key confirmation instead of showing a password input box.

## Best solution

Extend the prompt classification in extensions/git/src/askpass.ts to recognize PIN/security-key prompts (not just 'passphrase') and route them to the same masked InputBox path used for passphrases, leaving the yes/no quick pick only for genuine host-authenticity prompts.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`
- **Validation:** Manually verify: configure an SSH remote with a FIDO2 verify-required key, trigger a git operation requiring the key, and confirm VS Code shows a masked PIN input box (not the yes/no quick pick) and authentication succeeds; also confirm genuine host-key confirmation prompts still show the yes/no quick pick.
- **Behavior:**

  > When OpenSSH's ssh-sk-helper asks for a FIDO2/security-key PIN (e.g. 'Enter PIN for authenticator:'), VS Code's integrated askpass must show a masked password input box, matching the existing behavior for 'Enter passphrase for key ...' prompts. The host-key authenticity yes/no quick pick must continue to appear only for genuine 'are you sure you want to continue connecting' prompts. Acceptance: a FIDO2 verify-required key's PIN prompt is answerable via the input box and the operation succeeds; host-key confirmation prompts are unaffected.
- **Trace:**

  > extensions/git/src/askpass.ts, handleSSHAskpass() (around line 117): the only branch recognized is `/passphrase/i.test(request)` (line 122), which renders a masked InputBox; everything else falls into the block starting at line 145 that reads `argv[6]` as a host and `argv[15]` as a fingerprint and shows a yes/no QuickPick — these argv offsets are specific to OpenSSH's authenticity-prompt invocation and are not valid for a PIN-prompt invocation. The fix must extend prompt classification (e.g. detect 'PIN'/'authenticator' alongside 'passphrase') without breaking the existing passphrase or host-key-confirmation paths — do not alter askpassManager.ts or the non-SSH handleAskpass() path. Reported in https://github.com/microsoft/vscode/issues/326324 (root cause already diagnosed by the reporter and independently confirmed above); no related fix exists on main.
- **Open decisions:**
  - Should the PIN-detection regex be narrow (e.g. match 'PIN for authenticator' verbatim) or broader (any prompt containing 'pin'), given other SSH key types or future OpenSSH versions might phrase the prompt differently?
  - Should the placeholder/prompt text shown to the user explicitly say 'PIN' (distinct from 'Passphrase') so users understand it's a security-key PIN, not a regular key passphrase?
