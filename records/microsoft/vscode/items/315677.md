# Issue #315677 — Agents window: Chat context menu commands in the modal editor not working

[https://github.com/microsoft/vscode/issues/315677](https://github.com/microsoft/vscode/issues/315677)

## Summary

The defect remains source-reproducible on current main: generic chat context actions cannot reveal an Agents Window session widget and therefore silently return without acting. Keep this accepted team-authored bug open while deciding whether each modal-editor command should target the active session or be hidden.

## Change summary

Chat-related editor context-menu commands such as Add to Chat, Explain, and Code Review do nothing when invoked from an Agents Window modal editor.

## Best solution

Define a consistent policy for chat commands in Agents Window modal editors, then either make supported commands operate on the active session chat or hide unsupported entries. Preserve the existing behavior of these commands in ordinary VS Code windows.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts`, `src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts`, `src/vs/sessions/contrib/chat/browser/chatView.ts`
- **Validation:** In an Agents Window session, open a file in the modal editor and invoke Add File to Chat, Add Selection to Chat, Explain, and Code Review; every supported command must affect the active session/editor and every unsupported command must be absent. Repeat Add File and Add Selection in a regular VS Code window to verify existing chat targeting is unchanged.
- **Behavior:**

  > Chat commands exposed in an Agents Window modal editor must not silently do nothing. Supported attachment and code-assistance commands should operate on the active session and current file or selection; commands that cannot be supported should not appear. The same commands in ordinary VS Code windows must retain their current targeting and behavior.
- **Trace:**

  > Attach File and Attach Selection run through `withChatView` in src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts. Agents Window widgets use `ChatAgentLocation.Chat`, causing that helper to call `ChatWidgetService.revealWidget`; `revealSessionIfAlreadyOpen` in src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts recognizes standard chat views and editors but not Sessions-owned widgets, so the action receives no widget and returns. Explain and Code Review are contributed separately through src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts and must follow the same chosen modal-editor policy. The boundary is command targeting and visibility in the Agents Window; do not change normal-window chat behavior or the Sessions layout contract. Related reports are https://github.com/microsoft/vscode/issues/328684 and https://github.com/microsoft/vscode/issues/318793.
- **Open decisions:**
  - Should Add to Chat, Explain, and Code Review target the active Agents Window session from a modal editor, or should some or all of these context-menu commands be hidden there?

## Evidence

- **current source path:** In src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts, `withChatView` calls `ChatWidgetService.revealWidget()` whenever the last-focused widget has `ChatAgentLocation.Chat`; attach actions return early when that lookup yields no widget.
- **Agents Window incompatibility:** src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts limits `revealSessionIfAlreadyOpen` to the standard Chat view, chat editors, and quick chat. It does not recognize Sessions-owned chat widgets, although src/vs/sessions/contrib/chat/browser/chatView.ts creates them with `ChatAgentLocation.Chat`.
- **independent confirmation:** The younger report https://github.com/microsoft/vscode/issues/328684 independently confirms that Add File and Add Selection silently no-op in the Agents Window and identifies the same `withChatView` path. Because it was created after this re-reviewed issue, it cannot serve as the canonical duplicate.
- **open product decision:** https://github.com/microsoft/vscode/issues/318793 separately asks whether Add to Chat, Explain, and related file-context entries should be hidden in the Agents Window, so the intended command set remains a user-visible decision.
