# Issue #80155 — Convert inline comment to block comment, and vice-versa

[https://github.com/microsoft/vscode/issues/80155](https://github.com/microsoft/vscode/issues/80155)

## Summary

Keep this accepted Backlog request open: the existing comment commands add or remove delimiters but do not convert between line comments and the illustrated formatted block comment. No verified older canonical owns the same request.

## Change summary

Add commands to convert selected JavaScript line comments into a formatted block comment and convert that block back into line comments.

## Best solution

Provide explicit comment-conversion actions that preserve comment text and indentation without changing the existing toggle commands. Establish the supported language scope before implementing the illustrated JavaScript conversion and its reverse.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/comment/browser/comment.ts`, `src/vs/editor/contrib/comment/browser/blockCommentCommand.ts`, `src/vs/editor/contrib/comment/browser/lineCommentCommand.ts`, `src/vs/editor/contrib/comment/test/browser/blockCommentCommand.test.ts`, `src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts`
- **Validation:** Add command-level tests using the existing testCommand harness for the issue's exact four-line JavaScript input, expected decorated block, and reverse conversion. Cover indentation, selection preservation, undo, and unchanged existing toggle behavior; run the relevant comment-command suites using scripts/test.sh with targeted --run selectors.
- **Behavior:**

  > Selecting the four JavaScript // comment lines in the issue should allow conversion to the illustrated /** block with one leading * per content line. Reverse conversion should restore the line-comment text without retaining block delimiters or decorative stars. Preserve indentation and comment content, and keep both transformations undoable. Existing Toggle Line Comment and Toggle Block Comment behavior must remain unchanged.
- **Trace:**

  > src/vs/editor/contrib/comment/browser/comment.ts registers four existing comment actions, each delegating to LineCommentCommand or BlockCommentCommand rather than a conversion operation. BlockCommentCommand._createAddBlockCommentOperations inserts only enclosing tokens; its removal counterpart deletes only those tokens, so neither transforms interior prefixes or decoration. LineCommentCommand independently processes line prefixes and falls back to block operations when line comments are unsupported. The current editor.comments settings control spacing and empty-line handling, not conversion. Existing command tests use testCommand with registered language comment configurations, providing an executable validation harness. The unresolved product boundary is whether the illustrated JavaScript capability should extend to other language comment syntaxes; do not alter existing toggle semantics or infer documentation-comment behavior for other languages.
- **Open decisions:**
  - Should conversion initially support only the illustrated JavaScript comment forms, or be available across languages that declare both line-comment and block-comment syntax?

## Evidence

- **requested capability:** https://github.com/microsoft/vscode/issues/80155 supplies concrete JavaScript input and expected output: four // comments become a /** ... */ block with leading * decoration, with reverse conversion also requested.
- **existing commands do not cover conversion:** src/vs/editor/contrib/comment/browser/comment.ts registers editor.action.commentLine, editor.action.addCommentLine, editor.action.removeCommentLine, and editor.action.blockComment. These invoke separate line-comment or block-comment commands; there is no conversion action in this registration.
- **source boundary:** BlockCommentCommand._createAddBlockCommentOperations in src/vs/editor/contrib/comment/browser/blockCommentCommand.ts inserts the configured opening and closing tokens around the selection without removing its // prefixes or creating decorated interior lines. Its removal operation deletes the enclosing tokens, not block-comment decoration. LineCommentCommand in src/vs/editor/contrib/comment/browser/lineCommentCommand.ts independently adds or removes line prefixes.
- **settings and workaround:** EditorComments in src/vs/editor/common/config/editorOptions.ts exposes editor.comments.insertSpace and editor.comments.ignoreEmptyLines, neither of which enables conversion. Removing line comments and then toggling a block comment is a multi-command workaround and still does not produce the requested /** block with leading * decoration.
- **canonical search:** Repository searches for comment conversion and line/block-comment terminology found no verified older open issue with the same observable request. The thread's https://github.com/microsoft/vscode/issues/67732 concerns selection-based commenting, https://github.com/microsoft/vscode/issues/80000 concerns choosing block comments for partial-line selections, https://github.com/microsoft/vscode/issues/77104 concerns individually toggling mixed commented and uncommented lines, and https://github.com/microsoft/vscode/issues/9311 concerns nested block comments in languages without line comments. All four are closed and do not own this conversion request.
