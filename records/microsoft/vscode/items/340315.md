# Issue #340315 — Copilot CLI shim recurses infinitely (fork bomb) when `/home` is a symlink

[https://github.com/microsoft/vscode/issues/340315](https://github.com/microsoft/vscode/issues/340315)

## Summary

Confirmed on current main: the PATH-stripping logic in copilotCLIShim.ts uses plain string matching against `__dirname` instead of resolving symlinks, so on systems where the global-storage path traverses a symlink (e.g. Fedora Atomic's `/home -> var/home`), the shim never removes itself from PATH and recurses into itself indefinitely, exhausting memory and freezing the system.

## Change summary

The Copilot CLI terminal shim can recurse infinitely and exhaust system memory when the extension's global storage path contains a symlink component (e.g. a symlinked `/home`).

## Best solution

Fix the PATH-stripping in copilotCLIShim.ts (line 34) to compare resolved/real paths instead of raw string equality against `__dirname`, and/or add a recursion guard env var (e.g. `COPILOT_SHIM_ACTIVE`) so the shim can never fork-bomb regardless of root cause — exactly as the reporter suggests.
