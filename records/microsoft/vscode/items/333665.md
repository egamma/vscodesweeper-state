# Issue #333665 — Agent host: file watches fail with ENOPRO in a remote window, because the host is handed vscode-remote URIs it cannot resolve

[https://github.com/microsoft/vscode/issues/333665](https://github.com/microsoft/vscode/issues/333665)

## Summary

Already fixed: PR #333296 (merged as db46a82c) translates working-directory URIs to host-local `file:` before they reach the agent host, which is exactly what makes the ENOPRO watch failures in this report possible. The reporter, who diagnosed the root cause, independently confirmed the fix on current source and closed their own competing PR as superseded.

## Change summary

In a dev container/remote window, the agent host tries to watch `vscode-remote://` URIs it has no file system provider for, so customization and workspace watches silently fail with ENOPRO.

## Best solution

Keep the shipped translation fix (db46a82c, targeting milestone 1.136.0); no further change needed here. If watches still appear dead after upgrading, the separate cause tracked by the client-side working-directory filtering (mentioned as #330979/#334048 in the comments) is the next thing to check, not this namespace mismatch.
