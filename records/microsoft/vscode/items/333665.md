# Issue #333665 — Agent host: file watches fail with ENOPRO in a remote window, because the host is handed vscode-remote URIs it cannot resolve

[https://github.com/microsoft/vscode/issues/333665](https://github.com/microsoft/vscode/issues/333665)

## Summary

The reporter root-caused this to the agent host receiving vscode-remote:// working directories it can't resolve, and confirmed in a follow-up comment that #333296 fixes it by filtering working directories to host-addressable schemes before they're sent — code matching that description exists on main today, so this can be closed as completed.

## Change summary

In a dev container window, the agent host's file watches throw ENOPRO because vscode-remote:// URIs (workspace folder, .claude customizations, session attachments) are handed to a host that only understands file: paths.

## Best solution

Keep the shipped fix: `_hostAddressableWorkingDirectories` in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts (lines ~5855-5867) filters working directories to the host's own scheme before sending them, dropping/falling back on any the host can't address — this is exactly the mechanism the reporter says resolves the ENOPRO. Track the separate 'no working directories at all' case under #330979/#334048 rather than here.
