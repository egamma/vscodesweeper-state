# Issue #311920 — Agent profiles and namespacing for Copilot custom agents

[https://github.com/microsoft/vscode/issues/311920](https://github.com/microsoft/vscode/issues/311920)

## Summary

This remains a valid feature request: current main has neither qualified custom-agent names nor named activation profiles, and a maintainer explicitly agreed that qualifying enterprise agents would be useful. The open related PR improves source visibility in the picker but does not satisfy either central request.

## Change summary

Add namespace-aware identities for custom agents and profiles that control which user-level agents are active in each context.

## Best solution

Review https://github.com/microsoft/vscode/pull/326247 as a limited picker-clarity improvement, then define the public identity, collision, invocation, and activation semantics needed for qualified agent names and profile-based filtering across discovery, the picker, and subagent routing.

## Evidence

- **maintainer direction:** A VS Code maintainer concluded in the issue discussion that qualifying the names of enterprise instructions and agents would be valuable.
- **identity gap on main:** src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts derives an agent's display name from frontmatter or the filename and assigns its internal id from the file URI; the supported agent header attributes contain no namespace or publisher field.
- **lookup behavior on main:** src/vs/workbench/contrib/chat/common/chatModes.ts implements findModeByName by returning the first custom mode whose name or id matches, so there is no qualified-name resolution contract for colliding display names.
- **open partial implementation:** https://github.com/microsoft/vscode/pull/326247 is open and references this issue. It groups picker entries by PromptsStorage and adds accessible source descriptions, but does not add namespace identity, collision handling, profile selection, or profile-based routing.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/312256 is newer than this re-reviewed issue and concerns duplicate picker entries from local and organization sources; it does not own the broader namespace and activation-profile requirements.
