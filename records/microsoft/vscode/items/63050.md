# Issue #63050 — Ability to apply a final sort to QuickPick results

[https://github.com/microsoft/vscode/issues/63050](https://github.com/microsoft/vscode/issues/63050)

## Summary

Keep open: the stable QuickPick API still lacks a way to prioritize selected items while retaining built-in fuzzy ordering for the remaining results. The related sorting proposal preserves supplied order instead, so it does not fully cover the requested post-ranking customization.

## Change summary

Allow extensions to promote selected QuickPick items after fuzzy ranking while preserving the relative ranking of other matches.

## Best solution

Provide a supported QuickPick ordering contract that permits priority items without sacrificing built-in matching and ranking for the rest. Coordinate its design with the existing sorting discussion, while retaining this issue's distinct post-ranking requirement.

- **Validation:** After choosing the contract, add focused QuickPick ordering tests with several matching items and one promoted item: verify promotion across changing queries, preservation of built-in relative ranking for ordinary matches, unchanged matching/highlighting, and unchanged behavior for pickers that do not opt in.
- **Behavior:**

  > An extension wants designated QuickPick items to appear ahead of other matching items while retaining VS Code's fuzzy ordering for the remaining results. Providing items in a preferred order currently does not ensure that order survives a nonempty query. Acceptance should cover changing queries, priority placement, unchanged matching and highlighting, and preservation of the ordinary results' relative ranking. The report requests ordering control, not a new visibility rule for nonmatching items.
- **Trace:**

  > QuickInputList in src/vs/platform/quickinput/browser/quickInputList.ts filters and highlights items in filter(), then its tree sorter calls compareEntries for nonempty queries when sortByLabel is true. compareEntries uses label highlights and compareAnything without an extension customization stage. ExtHostQuickPick in src/vs/workbench/api/common/extHostQuickOpen.ts forwards sortByLabel, but its declaration remains in vscode.proposed.quickPickSortByLabel.d.ts rather than the stable QuickPick interface. Disabling sorting preserves supplied order but loses built-in ranking of ordinary matches; alwaysShow changes visibility only. https://github.com/microsoft/vscode/issues/73904 discusses preserving extension order, while https://github.com/microsoft/vscode/issues/27317 lists this request as separate unfinished work. Preserve existing default picker behavior and do not expand the request into custom filtering or highlighting.
- **Open decisions:**
  - Should the supported public contract expose the built-in ranked results for arbitrary final reordering, as requested, or offer a narrower item-priority mechanism that promotes designated items while retaining built-in ranking for the remainder?
