# Issue #251013 — Incorrect `editor.suggest.showWords` replacements for completion items if an LSP response takes too long

[https://github.com/microsoft/vscode/issues/251013](https://github.com/microsoft/vscode/issues/251013)

## Summary

Confirmed bug with the suggest overwrite logic when `editor.suggest.insertMode` is `replace` (the HTML default) and completions arrive after the user has already typed ahead. The maintainer reproduced it, acknowledged the defect, and there is an open PR (#276973) from the reporter. Keeping open for the fix to land.

## Change summary

Accepting a word-based completion in replace mode clobbers characters beyond the intended replacement range when the user types quickly before suggestions appear.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/276973 (or an equivalent fix) that corrects the `overwriteAfter` calculation in the suggest accept path so it accounts for cursor movement from typing. The fix likely lives in `src/vs/editor/contrib/suggest/browser/completionModel.ts` or the suggest accept logic. jrieken said he'd pick this up.
