# Issue #260672 — Instructions: Allow filtering instructions to specific modes

[https://github.com/microsoft/vscode/issues/260672](https://github.com/microsoft/vscode/issues/260672)

## Summary

A real mode-scoping gap remains on current main. The issue is team-authored and the discussion leaves an unresolved public metadata-contract decision, so it should remain open for design.

## Change summary

Allow instruction files to declare the chat, coding-agent, or code-review modes in which they should be considered.

## Best solution

Define a stable instruction-file selector whose identifiers cover interactive agents and code-review tasks, then carry it through discovery and every automatic-instruction consumer while preserving `applyTo` path filtering. Unscoped instructions should retain their current behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/languageProviders/promptValidator.ts`, `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`, `extensions/copilot/src/extension/review/node/githubReviewAgent.ts`
- **Validation:** Add focused parser, validator, discovery, and automatic-collection tests proving that scoped instructions are included only for matching modes, remain conjunctive with `applyTo`, and that unscoped instructions retain current behavior; add a review-path test for the chosen code-review identifier.
- **Behavior:**

  > An `.instructions.md` file can declare the modes or task contexts in which it applies. It is automatically considered only in matching contexts, with any existing `applyTo` file-pattern condition still enforced. Files without the new selector behave exactly as they do today. Acceptance includes interactive agent and code-review contexts and verifies that unrelated modes do not receive the instruction.
- **Trace:**

  > Instruction discovery in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts parses `name`, `description`, and `applyTo`, then carries `sessionTypes` only from the discovered prompt path. Automatic collection in src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts and extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts already has session-type filtering infrastructure. The SCM review path in extensions/copilot/src/extension/review/node/githubReviewAgent.ts separately loads agent instructions and settings, so the trace becomes cross-consumer at that boundary. Preserve existing path-glob semantics, extension-contributed `sessionTypes`, and behavior for instruction files without the new metadata. https://github.com/microsoft/vscode/issues/299447 documents the narrower SCM-review discovery gap but is newer than this issue.
- **Open decisions:**
  - Should the public selector use user-facing task identifiers such as `agent` and `copilot-code-review`, infrastructure session-type identifiers, or a separately defined stable vocabulary?
  - Which review surfaces must the first contract cover: local SCM review, GitHub Copilot code review, or both?
  - Should a mode-scoped instruction appear in customization discovery outside matching modes, or be hidden entirely there as well as excluded from automatic attachment?
