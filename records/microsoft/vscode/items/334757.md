# Issue #334757 — Support cursor in decoration attachments (before / after)

[https://github.com/microsoft/vscode/issues/334757](https://github.com/microsoft/vscode/issues/334757)

## Summary

This is a valid, currently unsupported extension API request for attachment-specific cursor styling. It should remain open and be routed to the editor API owners for a product/API decision.

## Change summary

Allow extensions to specify a CSS cursor for `before` and `after` editor decoration attachments without changing the cursor over the decorated text.

## Best solution

If accepted by the editor API owners, expose `cursor` on `ThemableDecorationAttachmentRenderOptions` and carry it through the extension-host conversion, internal attachment render options, and attachment CSS-rule generation while preserving the existing top-level cursor behavior.

## Evidence

- **conversion gap:** `ThemableDecorationAttachmentRenderOptions.from` in `src/vs/workbench/api/common/extHostTypeConverters.ts` copies attachment styling fields but has no cursor field, while the enclosing decoration converter explicitly forwards `options.cursor`.
- **rendering gap:** `IContentDecorationRenderOptions` in `src/vs/editor/common/editorCommon.ts` omits cursor, and `getCSSTextForModelDecorationContentClassName` in `src/vs/editor/browser/services/abstractCodeEditorService.ts` does not collect cursor CSS; the inline-class path does.
- **no canonical found:** Repository issue searches for decoration attachment cursor support found no older open issue with the same observable request. https://github.com/microsoft/vscode/issues/326158 concerns mouse-selection hit testing around injected content, not attachment cursor styling.
