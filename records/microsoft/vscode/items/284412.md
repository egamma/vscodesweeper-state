# Issue #284412 — "Checkout Branch" in "Source Control" panel does not do what it says.

[https://github.com/microsoft/vscode/issues/284412](https://github.com/microsoft/vscode/issues/284412)

## Summary

Consolidate this with the open, more-discussed remote-checkout issue: both report that selecting a remote branch silently checks out its local tracking branch at a different commit. Current source confirms the shared behavior.

## Change summary

Make remote-branch checkout accurately communicate or honor the selected remote revision when an existing local tracking branch differs.

## Best solution

Resolve the misleading remote-checkout behavior consistently across the branch picker and SCM graph under https://github.com/microsoft/vscode/issues/286359, preserving local work rather than introducing an automatic destructive reset.

Its discussion confirms the behavior on 1.107.1 and independently on Windows with 1.115.0. Although newer, it is the more-discussed report of the same underlying work; no prior-review restriction applies here.
- **Shared current-source behavior:** At checkout HEAD eef761e9628e777317a554114f0202a070e98f0b, extensions/git/src/commands.ts:166-185, CheckoutRemoteHeadItem.run, calls findTrackingBranches(this.ref.name) and checks out branches[0].name when a tracking branch exists. Commands.checkout2 at lines 2823-2845 implements the same substitution for git.graph.checkout. Neither default path checks that the selected remote and local commits match.
- **Existing capability is only a workaround:** git.checkoutDetached is registered in extensions/git/package.json and routes through CheckoutRemoteHeadItem.run's detached path, which checks out the selected ref's commit. That permits exact-revision checkout but does not resolve the misleading outcome of the ordinary remote-branch checkout action.
- **Scope and evidence to preserve:** https://github.com/microsoft/vscode/issues/284412 supplies a Windows 10 reproduction on VS Code 1.106.1 and explicitly identifies different local and remote commits. This is the same observable mismatch as the canonical, not a separate platform defect. https://github.com/microsoft/vscode/issues/237345 was also inspected; it concerns naming collisions across multiple remotes rather than this revision mismatch.
