# Issue #339036 — Regression - VS Code Secondary Sidebar Plugin Drop-down

[https://github.com/microsoft/vscode/issues/339036](https://github.com/microsoft/vscode/issues/339036)

## Summary

Confirmed regression with excellent root-cause analysis already in the thread from a VS Code collaborator: the Electron 43.6.0→43.7.3 bump (commit 0d9ade07b60, PR #336697) pulled in electron/electron#53750, which restores Chromium's SiteInstanceGroup drag-target check for same-WebContents drags — breaking drag-and-drop into extension webviews (which are cross-site iframes). Root cause lives upstream in Electron; keep open and let the Electron/webview owners decide on a patch or upstream fix.

## Change summary

Dragging files from the VS Code Explorer into an extension webview (e.g. chat panels) stopped working after the 1.140.0 Electron bump, while paste still works.

## Best solution

Either get an upstream Electron fix/patch restoring the drag exemption for VS Code's cross-site webview iframes, or add a targeted patch in VS Code's Electron build patches (similar to the removed webview_cross_drag.patch behavior) until electron/electron#53750's restriction is addressed for this legitimate same-origin-host use case.
