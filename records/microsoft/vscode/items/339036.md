# Issue #339036 — Regression - VS Code Secondary Sidebar Plugin Drop-down

[https://github.com/microsoft/vscode/issues/339036](https://github.com/microsoft/vscode/issues/339036)

## Summary

A collaborator bisected this to the Electron 43.6.0→43.7.3 bump (microsoft/vscode#336697) and identified the underlying upstream change (electron/electron#53750), which tightened the same-WebContents drag-target check so cross-site webview `<iframe>`s (how extension webviews are implemented) no longer accept drags. Current main is pinned to Electron 43.7.7 (even newer), so the regression is still present and the fix/mitigation lives upstream in Electron.

## Change summary

Dragging a file from the Explorer (or other OS/editor drag sources) into an extension webview (e.g. a chat panel) silently does nothing since the 1.140.0 Electron bump, though paste still works.

## Best solution

Track and either get Electron to special-case VS Code's legitimate same-WebContents webview drag scenario, or have VS Code carry a patch restoring the drag permission for its extension-host webview iframes, until an upstream Electron release addresses it; milestone 1.142.0 already reflects this is accepted work.
