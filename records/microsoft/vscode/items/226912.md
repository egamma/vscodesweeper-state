# Issue #226912 — Second layer of filtering after returning from `FileSearchProviderNew`'s `provideFileSearchResults(...)`

[https://github.com/microsoft/vscode/issues/226912](https://github.com/microsoft/vscode/issues/226912)

## Summary

Keep open for the API documentation clarification accepted by the maintainer. Current documentation partially explains scoring, but the newer provider contract still does not explicitly explain that returned files can be omitted by Quick Open or filtered by subsequent glob processing.

## Change summary

Clarify the filtering VS Code performs after a file search provider returns results.

## Best solution

Document the distinction between provider results and displayed Quick Open matches in the current file-search API contract, including applicable include/exclude post-processing. Preserve the intentional filtering behavior rather than introducing provider-controlled ranking or bypass options.
