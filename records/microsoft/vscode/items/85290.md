# Issue #85290 — Debugging should handle identical sources in sourceReference better

[https://github.com/microsoft/vscode/issues/85290](https://github.com/microsoft/vscode/issues/85290)

## Summary

The report describes a coherent debugger identity bug: a DAP source carrying both a disk path and `sourceReference` can create a second read-only editor and an independent breakpoint set even when its contents match the disk file. The issue should remain open because it was previously reviewed, no older canonical with the same observable symptom is identified, and current evidence does not establish that the behavior was fixed.

## Change summary

Treat a `sourceReference` source whose path and contents match the local file as the same editable source and preserve one consistent breakpoint set.

## Best solution

Define debugger source identity so an exact local-file match reuses the editable file and its breakpoints, while genuinely different runtime contents remain in a read-only debug-source editor; checksum-aware matching should be evaluated in the debug model and breakpoint binding paths.

- **Behavior:**

  > When a debug adapter returns a sourceReference source whose path and content are identical to an existing local file, VS Code should present the editable local file rather than a duplicate read-only editor, and both representations must share one breakpoint set. If the runtime source differs from disk, VS Code must continue to show the runtime content separately and read-only. Acceptance requires covering both matching and differing source cases and verifying the DAP receives a stable breakpoint list.
- **Trace:**

  > The report demonstrates that DAP Source objects with the same `path` are treated as distinct when one also has a `sourceReference`, causing separate editor resources and `setBreakpoints` requests. The likely path spans debug-source resource identity in src/vs/workbench/contrib/debug/common/debugSource.ts, editor handling in src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts, and breakpoint/source modeling in src/vs/workbench/contrib/debug/common/debugModel.ts. DAP `Source.checksums` was raised in the thread, and https://github.com/microsoft/vscode/issues/180964 later tracked checksum matching for breakpoint binding, but the available record does not prove that editor reuse and breakpoint identity were resolved. Preserve separate read-only runtime sources whenever their contents differ; do not collapse sources solely because their paths match.
- **Open decisions:**
  - Should equality be established only from a debugger-provided DAP checksum, or may VS Code fetch the sourceReference content and compare it with the local file when no checksum is supplied?
  - When equality cannot be established, should path equality preserve the current conservative separate-source behavior, or should the local editable source be preferred?
