# Issue #286296 — Support decorations that hide characters

[https://github.com/microsoft/vscode/issues/286296](https://github.com/microsoft/vscode/issues/286296)

## Summary

Keep this accepted editor-core request open: current decorations do not provide model-aware character concealment. The older prettify-symbols request is related, but does not establish the same reporter-observable requirement needed to close this re-reviewed item as a duplicate.

## Change summary

Allow extensions to hide decorated source characters without changing the document, enabling in-place Markdown presentation and other structured-text editors.

## Best solution

Provide a supported editor-decoration capability for concealing character ranges while preserving source text and coherent layout and editing behavior. Keep Markdown interpretation and application-specific presentation in extensions, and settle the editing contract with the editor owners before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/model.ts`, `src/vs/editor/common/textModelEvents.ts`, `src/vs/editor/common/viewModel/modelLineProjection.ts`, `src/vs/editor/common/viewModel/viewModelLines.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/test/browser/viewModel/modelLineProjection.test.ts`
- **Validation:** End the plan with executable projection and position-mapping tests in src/vs/editor/test/browser/viewModel/modelLineProjection.test.ts, plus an extension-driven editor check using **bold**, list bullets, and checkbox markers. Verify that concealed ranges consume no displayed character width, wrapping and hit testing match visible text, removing decorations restores the original presentation, and document contents remain unchanged. Pin caret, selection, and deletion assertions to the agreed interaction contract.
- **Behavior:**

  > An extension can conceal selected source-character ranges in the normal text editor without modifying the document. This enables hiding Markdown delimiters and list markers while extensions provide the surrounding presentation. Concealment must participate in layout and position mapping, rather than merely make glyphs transparent. Acceptance includes coherent wrapping and pointer placement, reversible decorations, unchanged source contents, and explicitly agreed caret and editing behavior.
- **Trace:**

  > The public DecorationRenderOptions contract in src/vscode-dts/vscode.d.ts offers styling and attachments, while IModelDecorationOptions in src/vs/editor/common/model.ts offers inline styling and additive injected text. LineInjectedText.applyInjectedText in src/vs/editor/common/textModelEvents.ts preserves original text, and ModelLineProjection.getViewLineContent in src/vs/editor/common/viewModel/modelLineProjection.ts renders its augmented result; whole-line hiding in viewModelLines.ts is not inline concealment. The existing Markdown custom editor is a separate webview surface, not coverage of this reusable API request. The boundary is presentation of source ranges: do not rewrite Markdown source or bundle application-specific note-taking behavior into core. https://github.com/microsoft/vscode/issues/171074#issuecomment-5703869503 supplies a related concealment prototype and interaction proposals, but those proposals are not an accepted contract. Source inspection establishes the capability gap; the complete rendering, cursor, accessibility, and extension-host integration design remains to be worked through with the editor owners.
- **Open decisions:**
  - When the caret or selection reaches a concealed range, should its source characters become visible, remain concealed with logical cursor stops, or follow an extension-selectable policy?
  - Should Backspace and Delete adjacent to concealed text edit the underlying characters normally, delete the concealed range atomically, or skip it, and is that behavior configurable by extensions?
