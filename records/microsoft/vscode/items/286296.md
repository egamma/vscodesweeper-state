# Issue #286296 — Support decorations that hide characters

[https://github.com/microsoft/vscode/issues/286296](https://github.com/microsoft/vscode/issues/286296)

## Summary

Keep open: the public decoration API still lacks a supported way to conceal source characters for in-place Markdown editing. This is accepted, team-authored Backlog work; the older prettify-symbols request is related but does not establish the same observable request required to close this re-reviewed item as a duplicate.

## Change summary

Allow extensions to hide Markdown syntax characters using editor decorations without changing the underlying document.

## Best solution

Provide an editor-core concealment primitive exposed through the decoration API, leaving Markdown interpretation and the WYSIWYG experience to extensions. Settle cursor, selection, and editing semantics before implementing the public contract.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/model.ts`
- **Validation:** Use a minimal extension to decorate Markdown delimiters, bullet markers, and checkbox syntax. Verify hidden ranges consume no visible width, wrapping and mouse placement agree with the displayed text, and cursor navigation, selection, and deletion follow the agreed contract; confirm hiding alone does not modify document contents.
- **Behavior:**

  > An extension should be able to hide Markdown syntax in the text editor while retaining the original document text. The resulting presentation should support in-place editing rather than merely painting characters transparent and leaving gaps. Acceptance should cover emphasis delimiters, bullet markers, checkbox syntax, wrapping, mouse placement, and navigation and editing across hidden ranges.
- **Trace:**

  > The public decoration interfaces in src/vscode-dts/vscode.d.ts expose CSS styling and before/after attachments but no concealment contract. IModelDecorationOptions and InjectedTextOptions in src/vs/editor/common/model.ts similarly expose inline styling and additive text, not removal of source characters from the displayed layout. GhostTextView has an internal opacity/font-size workaround, which is not a general extension capability. https://github.com/microsoft/vscode/issues/171074 contains related symbol-substitution discussion and a contributor's concealment prototype, but no verified merged fix. The boundary is a reusable editor primitive and extension API, not a bundled Markdown editor; the trace has not established the required projection, cursor, and extension-host plumbing.
- **Open decisions:**
  - Should cursor movement and selection skip concealed ranges, reveal their source while editing, or allow positions inside invisible text?
  - At a concealed range boundary, should Backspace and Delete remove the hidden source atomically, reveal it first, or step across it without deletion?
