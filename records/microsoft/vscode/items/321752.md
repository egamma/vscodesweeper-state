# Issue #321752 — Accessibility: Webview body element has invalid role="document" (WCAG 4.1.2 violation)

[https://github.com/microsoft/vscode/issues/321752](https://github.com/microsoft/vscode/issues/321752)

## Summary

The `role="document"` on the webview body is intentional and correct — it was deliberately added in 2020 (PR #93435) to fix a real accessibility problem. VS Code's root element carries `role="application"`, which causes all nested content to inherit application semantics; without the explicit `role="document"` override, screen readers would treat webview content as application UI instead of browsable document content. An accessibility expert (Marco Zehe) reviewed and approved the change.

## Change summary

Reporter requests removing `role="document"` from the webview body element, believing it is a WCAG 4.1.2 violation.

## Best solution

Keep the current behavior. The `role="document"` is a deliberate accessibility fix that restores browse-mode semantics inside VS Code's `role="application"` root. Removing it would regress screen reader behavior for all webview content.
