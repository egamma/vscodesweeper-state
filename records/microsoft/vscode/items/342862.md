# Issue #342862 — Remote agent host: reconnect with a new clientId ends in-flight turns (notDispatched) while they keep running on the host

[https://github.com/microsoft/vscode/issues/342862](https://github.com/microsoft/vscode/issues/342862)

## Summary

Keep open: current main still disposes in-flight turn observations when a replacement connection changes clientId, ending the UI request without cancelling host execution. Session reopening has an active-turn recovery path, but connection replacement does not invoke equivalent recovery.

## Change summary

Automatically recover observation of still-running remote turns after reconnecting with a new clientId, without requiring each session to be reopened.

## Best solution

Restore ongoing progress and eventual completion for affected sessions after connection replacement, without redispatching their turns. Preserve the existing teardown guarantees that prevent abandoned handlers from leaving requests pending indefinitely.

- **Trace:**

  > RemoteAgentHostContribution._reconcileConnections deletes the per-address ConnectionState on clientIdChanged and registers a new one; each old state's agent store owns its AgentHostSessionHandler. Preserve exact host-advertised identities, cancellation semantics, and the prohibition on dispatching prepared turns through a disposed handler. Treat the failed same-client reconnect attempts and terminal subscription errors as separate investigative leads rather than assuming this recovery change fixes them.
