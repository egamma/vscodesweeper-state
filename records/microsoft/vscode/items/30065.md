# Issue #30065 — Language services should be able to provide debug console IntelliSense

[https://github.com/microsoft/vscode/issues/30065](https://github.com/microsoft/vscode/issues/30065)

## Summary

This feature request is still valid — debug console completions are still exclusively sourced from the debug adapter via `session.completions()`, with no language-service integration path. Team-authored and in the Backlog milestone; keeping open.

## Change summary

Allow language services (not just debug adapters) to provide IntelliSense completions in the debug console for statically typed languages.

## Best solution

Add an opt-in registration mechanism so that a language service can indicate it supports debug console completions, then route completions through the language service (via the standard completion provider) when the focused stack frame's document language has opted in, falling back to the DA path otherwise. The change would primarily touch `src/vs/workbench/contrib/debug/browser/repl.ts` (the `onDidFocusSession` completion registration) and potentially the debug protocol/session layer.
