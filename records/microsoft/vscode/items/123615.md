# Issue #123615 — [api][commands] Open new window and a file

[https://github.com/microsoft/vscode/issues/123615](https://github.com/microsoft/vscode/issues/123615)

## Summary

Team-authored feature request (MEMBER) to extend the `vscode.newWindow` command API to accept extra arguments (files to open, resolver options) when opening a new remote window. The capability has not been implemented — the current `_remoteCLI.windowOpen` and `_files.newWindow` commands do not support passing files-to-open alongside a new-window-with-remote-authority call. Keeping open per team-authored policy.

## Change summary

Allow the `vscode.newWindow` command to accept extra arguments (e.g. files to open, resolver data) so extensions can open a new remote window and a file in one step without polluting recently-opened entries.

## Best solution

Extend `IOpenWindowOptions` (or add a new overload to the `vscode.newWindow` / `_remoteCLI.windowOpen` command) to accept `IWindowOpenable[]` items alongside `remoteAuthority`, so an extension can open a new remote window with specific files/notebooks without encoding extra data in the authority string. The relevant files are `src/vs/workbench/api/browser/mainThreadCLICommands.ts`, `src/vs/workbench/contrib/files/browser/fileActions.contribution.ts`, and `src/vs/platform/window/common/window.ts`.
