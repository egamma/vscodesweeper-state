# Issue #240172 — Allow to disable `ino` detection for workspace identity

[https://github.com/microsoft/vscode/issues/240172](https://github.com/microsoft/vscode/issues/240172)

## Summary

Keep open: local Linux folder identity still incorporates the inode unconditionally, so the requested opt-out remains missing. The maintainer supported an optional setting without changing the default; the workspace-file workaround does not satisfy that request.

## Change summary

Allow users to exclude the folder inode from workspace identity so remounting a shared filesystem does not disconnect previously saved editor state.

## Best solution

Provide an opt-in identity mode for local Linux folders with unstable inodes, preserving existing identity behavior by default. Settle how switching modes handles existing workspace state before implementing the control.

- **Behavior:**

  > A local Linux folder on a filesystem with unstable inodes can retain its workspace identity across remounts when the user explicitly opts out of inode detection. Reopening that folder restores its saved editors despite an inode change. Without opting out, existing identity behavior remains unchanged. Acceptance must also cover the agreed behavior when enabling or disabling the option on a folder with existing saved state.
- **Trace:**

  > getSingleFolderWorkspaceIdentifier in src/vs/platform/workspaces/node/workspaces.ts hashes the local folder path with folderStat.ino on Linux. The discussion confirms that a VirtualBox remount changes the inode, explaining why another saved-state location is selected. The maintainer supports an optional control in https://github.com/microsoft/vscode/issues/240172#issuecomment-2656698101, but the record does not settle the user-visible transition between existing inode-based state and opt-out state.
- **Open decisions:**
