# Issue #36249 — Terminal should support workbench.fontAliasing

[https://github.com/microsoft/vscode/issues/36249](https://github.com/microsoft/vscode/issues/36249)

## Summary

Keep open: current main has an experimental terminal font-rendering setting, but it does not establish support for all workbench.fontAliasing modes, particularly disabling antialiasing. The upstream request was declined for renderer reliability reasons, not completed, so its closure is not evidence of a fix here.

## Change summary

Make integrated-terminal text honor workbench.fontAliasing, including the none mode that disables font smoothing.

## Best solution

Retain this as the accepted terminal-rendering gap until xterm.js provides reliable control over glyph antialiasing or the VS Code area owner explicitly revisits the scope. Any eventual support should cover the requested modes on the actual terminal renderer, rather than treating the experimental grayscale option as complete coverage.

## Evidence

- **Requested behavior and ownership:** The supplied discussion for https://github.com/microsoft/vscode/issues/36249 explicitly asks for workbench.fontAliasing: none to affect terminal text. The author acknowledged that outcome and explained that drawing canvas text without antialiasing requires an xterm.js change.
- **Existing capability is partial:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:183-194 registers terminal.integrated.fontRendering with inherit and grayscale, marked experimental and advanced and included only on macOS. Although inherit is described as following workbench.fontAliasing, the registration alone does not prove that the terminal canvas honors its none mode.
- **Current renderer integration:** src/vs/workbench/contrib/terminal/browser/xterm/terminalFontRendering.ts toggles a grayscale CSS class and clears the texture atlas; its CSS applies antialiased smoothing only on high-DPI displays. XtermTerminal passes only customGlyphs when constructing the WebGL addon at src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:952-954, while allowTransparency remains tied to enableImages. These paths do not expose a renderer option for disabling glyph antialiasing.
