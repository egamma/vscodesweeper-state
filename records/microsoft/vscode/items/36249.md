# Issue #36249 — Terminal should support workbench.fontAliasing

[https://github.com/microsoft/vscode/issues/36249](https://github.com/microsoft/vscode/issues/36249)

## Summary

The capability remains absent and depends on renderer support that xterm.js declined as unreliable. Keep this open as upstream until the terminal team decides whether a limited VS Code-specific implementation is acceptable.

## Change summary

Apply `workbench.fontAliasing` consistently to integrated terminal text.

## Best solution

Determine whether VS Code should implement a documented DOM-renderer-only CSS mapping despite its limitations; otherwise retain this as an upstream limitation rather than presenting inconsistent support across renderers.

- **Proposed comment:**

  > Thanks for the continued context. The upstream implementation attempt at https://github.com/xtermjs/xterm.js/pull/5724 was closed after concluding that the CSS approach only affects the DOM renderer, while canvas and WebGL cannot support the setting consistently. The upstream request at https://github.com/xtermjs/xterm.js/issues/2464 was consequently declined as unreliable. This should remain tracked as an upstream limitation unless the terminal team chooses to support a documented DOM-renderer-only mapping in VS Code.

## Auto-fix candidate

## Evidence

- **upstream decision:** https://github.com/xtermjs/xterm.js/issues/2464 was closed as out of scope on 2026-03-12 because font smoothing is platform-specific, non-standard, unreliable, and cannot be applied consistently across DOM, canvas, and WebGL renderers.
- **implementation PR:** https://github.com/xtermjs/xterm.js/pull/5724 was closed without merging after review established that its `-webkit-font-smoothing` implementation affected only the DOM renderer.
- **current source:** `workbench.fontAliasing` is registered in `src/vs/workbench/browser/workbench.contribution.ts` and applied by `src/vs/workbench/browser/workbench.ts`; current source contains no corresponding terminal option or renderer mapping.
- **related report:** https://github.com/microsoft/vscode/issues/42392 was closed as a duplicate of this issue, confirming this remains the canonical VS Code report.
