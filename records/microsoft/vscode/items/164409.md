- **Validation:** With editor.cursorStyle set to block, pause debugging at a statement whose stack-frame start column is greater than one and place the cursor over the inline arrow without selecting text. Verify that the arrow remains recognizable rather than becoming a missing or unrelated glyph; repeat with ordinary text, a line cursor, and an inline icon after indentation. Establish an automated browser-rendering regression check for this case before implementation.
- **Behavior:**

  > A block cursor covering the inline debug stack-frame arrow with no selection must not replace the arrow with an unrelated or missing glyph. Cursor placement, dimensions, and visibility must remain correct. Ordinary text under a block cursor, line-cursor behavior, and debug decorations away from the cursor must remain unchanged. Acceptance includes the original no-selection debugging scenario and an automated rendering check that detects loss of the icon's font treatment.
- **Trace:**

  > makeStackFrameColumnDecoration in src/vs/workbench/contrib/debug/browser/callStackEditorContribution.ts injects U+EB8B with debug-top-stack-frame-column, whose codicon font is defined in browser/media/debug.contribution.css. ModelLineProjection in src/vs/editor/common/viewModel/modelLineProjection.ts includes that character in view-line content while retaining its class separately in inlineDecorations. ViewCursor._getGraphemeAwarePosition reads the injected character; _prepareRender copies it for a block cursor, but _getTokenClassName retrieves only syntax-token metadata, and render sets that character as cursor textContent without the icon class. This establishes the styling loss without executing the application. Preserve existing cursor navigation, text rendering, and debug-decoration semantics; arbitrary decoration layout effects require assessment rather than indiscriminate propagation. The remaining uncertainty is how to validate actual glyph rendering and accommodate other decorated text in the shared cursor renderer. https://github.com/microsoft/vscode/issues/227635 independently reports the same symptom; https://github.com/microsoft/vscode/issues/164409#issuecomment-1292775592 specifies the no-selection trigger.
