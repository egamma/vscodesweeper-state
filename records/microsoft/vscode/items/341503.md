# Issue #341503 — ChatApprovedAccountOrganizations: ADMX defines it as multiText (REG_MULTI_SZ), but VS Code only applies a REG_SZ JSON array on Windows

[https://github.com/microsoft/vscode/issues/341503](https://github.com/microsoft/vscode/issues/341503)

## Summary

Thanks for the detailed report and the follow-up correction. The ADMX generator renders every array/object policy as a multiText element, which can only deliver plain lines. The runtime expects a JSON array string, so ADMX-based deployments cannot activate the gate.

## Change summary

The shipped ADMX presents array-typed policies such as ChatApprovedAccountOrganizations as a multi-line list, but VS Code only applies a JSON array value, so ADMX deployments never activate the Account Policy Gate.

## Best solution

Either change the ADMX generator in build/lib/policies/objectPolicy.ts to emit a single text element documented as a JSON array, or make the policy parsing accept multi-line or REG_MULTI_SZ values as list entries. A maintainer should pick the approach, since it changes the policy contract.

## Plan brief

- **Likely files:** `build/lib/policies/objectPolicy.ts`, `src/vs/workbench/services/policies/common/accountPolicyService.ts`, `src/vs/platform/policy/common/policy.ts`
- **Validation:** Extend build/lib/test/objectPolicy.test.ts for the chosen ADMX output, or add an accountPolicyService test for the chosen value format. Then confirm in Policy Diagnostics that the gate is satisfied.
- **Behavior:**

  > An administrator deploying ChatApprovedAccountOrganizations through the ADMX shipped with VS Code can set the organization list with a UI that VS Code actually honors. Entering my-org (or the documented format) activates the Account Policy Gate and marks the policy as applied.
- **Trace:**

  > ObjectPolicy.renderADMXElements in build/lib/policies/objectPolicy.ts emits multiText for all array and object policies. The runtime side parses string values as JSON in accountPolicyService.ts, and PolicyConfiguration.parse does the same normalisation. A multiText entry arrives as plain lines, so the parse fails and the list is empty. Related: macOS managed preferences for the same policy, https://github.com/microsoft/vscode/issues/339325. Do not break JSON-valued deployments (REG_SZ, JSON, MDM profiles) that work today. The open question is which side changes: the ADMX element, or the value parsing.
- **Open decisions:**
  - Should the ADMX use a single text field documented as a JSON array, or should VS Code accept multi-line/REG_MULTI_SZ values as list entries?
  - Should the fix apply to all array and object policies generated by ObjectPolicy, or only to string-array policies such as this one?
