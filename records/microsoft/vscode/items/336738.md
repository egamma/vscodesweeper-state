# Issue #336738 — Agents window: let us center the bottom panel instead of it always spanning full width

[https://github.com/microsoft/vscode/issues/336738](https://github.com/microsoft/vscode/issues/336738)

## Summary

Valid, well-diagnosed request: the Agents window's layout deliberately hardcodes panel alignment to 'justify' and no-ops the setter, unlike the main workbench which already supports 'center' alignment with full grid logic — this is a real, scoped gap in the newer sessions layout, not a bug or duplicate.

## Change summary

Let the panel in the Agents (Sessions) window be center-aligned (spanning only chat+editor) instead of always spanning full width including the sidebar area, and support 'Toggle Maximized Panel' there.

## Best solution

Extend the sessions workbench grid (src/vs/sessions/browser/workbench.ts) to support a center-aligned panel layout mirroring the main workbench's approach in src/vs/workbench/browser/layout.ts (setPanelAlignment/adjustPartPositions), which will also make 'Toggle Maximized Panel' work there.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/workbench.ts`, `src/vs/workbench/browser/layout.ts`
- **Validation:** A sessions workbench layout test asserting the panel view's grid position/size is bounded by the editor+auxiliary bar area (not the sidebar) when alignment is set to 'center', and that toggleMaximizedPanel() succeeds instead of throwing.
- **Behavior:**

  > In the Agents window, users can set the panel alignment to 'center' so the panel spans only the chat/editor area, leaving the right sidebar (auxiliary bar) at full height. 'View: Toggle Maximized Panel' works when alignment is 'center', matching main workbench behavior. Existing 'justify' (full-width) behavior remains the default and unaffected.
- **Trace:**

  > src/vs/sessions/browser/workbench.ts hardcodes getPanelAlignment()->'justify' and setPanelAlignment() as a no-op inside a '// Position Methods (Fixed - Not Configurable)' region; the grid is built once from a single createGridDescriptor() in the constructor (~line 1557) with the panel spanning the whole width. The main workbench (src/vs/workbench/browser/layout.ts, setPanelAlignment ~2060, adjustPartPositions ~1997, isPanelMaximized ~2246) already implements 'center' vs 'justify' via grid restructuring — that's the model to follow, but the sessions grid's view set (sessionsPart, panelPart, auxiliaryBarPart, editorPart) differs from the main workbench's, so the exact nesting needs a maintainer's design pass. Do not change default 'justify' behavior or the main workbench's layout.ts.
- **Open decisions:**
  - Should the sessions grid be restructured to nest panel+editor as a sub-grid under the top-level row (like main workbench), or is a different grid topology better suited to the sessions/agents-specific parts (sessionsPart, customViewGridPart)?
  - Should center alignment be persisted per-profile like PANEL_ALIGNMENT state in the main workbench, or default off given this is a newer surface?

## Evidence

- **hardcoded no-op:** src/vs/sessions/browser/workbench.ts getPanelAlignment() always returns 'justify' and setPanelAlignment() is a no-op, under a region explicitly labeled '// Position Methods (Fixed - Not Configurable)'.
- **core already supports this:** src/vs/workbench/browser/layout.ts has a full setPanelAlignment/getPanelAlignment implementation (lines ~2060-2372) including 'center' handling and PANEL_ALIGNMENT runtime state, and isPanelMaximized() (line 2246) explicitly checks getPanelAlignment() === 'center', confirming why 'Toggle Maximized Panel' fails when alignment is fixed to 'justify'.
- **grid structure:** The sessions Workbench builds a single SerializableGrid from one fixed createGridDescriptor() (workbench.ts ~1557), so the panel spans the full grid width by construction — supporting center alignment needs a restructured/alternate grid, not a small guard.
