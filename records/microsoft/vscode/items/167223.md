# Issue #167223 — Go to Symbol in Editor doesn't auto fill symbol which current cursor locate in editor

[https://github.com/microsoft/vscode/issues/167223](https://github.com/microsoft/vscode/issues/167223)

## Summary

Selection-based autofill remains absent from the built-in command, but changing the default would remove the surrounding-symbol overview that maintainers explicitly want to preserve. Keep this accepted Backlog request open for a decision on an opt-in experience; no verified canonical or landed fix was found.

## Change summary

Allow Go to Symbol in Editor to initialize its filter from the selected editor text.

## Best solution

Preserve the existing unfiltered, cursor-relative outline by default and decide whether selection-seeded navigation merits an opt-in core experience. The reporter's Power Edit command already provides an alternative, but does not resolve the built-in request.

- **Behavior:**

  > The reporter wants selected editor text to become the initial Go to Symbol in Editor filter rather than requiring copy and paste. Today the picker offers an unfiltered outline positioned at the cursor's enclosing symbol. Planning must settle whether an opt-in experience belongs in core and define its behavior for non-symbol selections before establishing acceptance checks.
- **Trace:**

  > GotoSymbolAction.run in src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoSymbolQuickAccess.ts opens quick access with the '@' prefix and does not read selected text. QuickAccessController in src/vs/platform/quickinput/browser/quickAccess.ts supports provider default filter values and transferring an existing picker filter, but neither supplies selected editor text on this path.
