# Issue #286759 — Clarify if `FinishedCallback` is awaited or not

[https://github.com/microsoft/vscode/issues/286759](https://github.com/microsoft/vscode/issues/286759)

## Summary

The FinishedCallback interface still returns Promise<number | undefined> without clarifying whether callers await it. The related bug (#286731) was worked around but the type-level clarification requested here remains unaddressed on main.

## Change summary

Clarify (or change) the FinishedCallback return type to reflect whether its promise is actually awaited by callers.

## Best solution

Audit all call sites of FinishedCallback in extensions/copilot/src/platform/networking/ — either await the returned promise consistently (and document that contract) or change the return type to `number | undefined | Promise<number | undefined>` so callers know not to rely on awaiting. The fix lives in extensions/copilot/src/platform/networking/common/fetch.ts and its consumers.
