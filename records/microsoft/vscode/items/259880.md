# Issue #259880 — Add an option to disable collapsing (in this case we should probably not render the twistie and the guide lines)

[https://github.com/microsoft/vscode/issues/259880](https://github.com/microsoft/vscode/issues/259880)

## Summary

Keep this accepted, team-authored request open: QuickTree still lacks a non-collapsible hierarchy mode. Indent guides are already disabled, but nested items remain collapsible and display twisties.

## Change summary

Allow a quick picker to convey repository, submodule, and worktree relationships without collapse controls or guide lines.

## Best solution

Provide an opt-in QuickTree mode that retains hierarchical indentation without interactive collapsing or twisties, while preserving existing default behavior. Settle its interaction with the existing programmatic collapse API before implementation; single selection remains separate work.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/tree/quickTree.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeController.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Add browser coverage in the QuickInput suite for an opted-in three-level hierarchy: indentation remains, twisties and guides are absent, and mouse/keyboard collapse gestures cannot hide descendants. Verify the settled behavior of initially collapsed items and collapse(), plus unchanged default collapsibility and isolation when switching between picker instances. Manually check keyboard navigation and screen-reader hierarchy announcements.
- **Behavior:**

  > A quick picker can show a repository, its submodule, and that submodule's worktree as an indented hierarchy without twisties or guide lines. In the opted-in mode, user collapse gestures must not hide descendants. Existing pickers retain their current collapsible behavior by default. Acceptance includes retained hierarchy, filtering and navigation, and no mode leakage between picker instances; programmatic collapse semantics must be agreed before implementation.
- **Trace:**

  > IQuickTree and IQuickTreeItem in src/vs/platform/quickinput/common/quickInput.ts expose collapse operations and initial collapsed state, but no non-collapsible mode. QuickTree in src/vs/platform/quickinput/browser/tree/quickTree.ts forwards collapse operations and sends itemTree to QuickInputTreeController.setTreeData(). That controller marks every node with children collapsible; its options already disable indent guides. The flat-hierarchy styling in src/vs/platform/quickinput/browser/media/quickInput.css only applies when no nested items exist and removes indentation as well as twisties, so it is not the requested mode. Preserve default collapse behavior, hierarchy, filtering, checkbox semantics, and accessible navigation; single-selection adoption is separately tracked at https://github.com/microsoft/vscode/issues/258764, and public extension API exposure at https://github.com/microsoft/vscode/issues/258328. The remaining contract question is whether disabling collapsing also overrides initial collapsed state and explicit programmatic collapse calls.
- **Open decisions:**
  - Should the opt-in mode guarantee that descendants remain expanded, overriding IQuickTreeItem.collapsed and collapse(), or disable only user collapse interactions while retaining programmatic collapse behavior?
