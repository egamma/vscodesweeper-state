# Issue #233585 — File comparer freezes in the background

[https://github.com/microsoft/vscode/issues/233585](https://github.com/microsoft/vscode/issues/233585)

## Summary

The defect remains in current main: closing a diff cancels its view model, but the running synchronous worker computation is not cancelled and can delay subsequent comparisons.

## Change summary

Closing a slow comparison should stop it from blocking later diff computations.

## Best solution

Make abandoned diff-worker jobs preemptible or isolate them so a newly opened comparison does not wait for obsolete work. Cover closing a long-running diff followed by opening a small diff.

## Evidence

- **current cancellation path:** src/vs/editor/browser/widget/diffEditor/diffProviderFactoryService.ts calls IEditorWorkerService.computeDiff without passing the CancellationToken; it checks cancellation only after the worker promise resolves.
- **synchronous worker computation:** src/vs/editor/common/services/editorWebWorker.ts performs $computeDiff synchronously through diffAlgorithm.computeDiff, so the worker cannot process a subsequent request until that computation returns.
- **independent confirmations:** Two commenters independently confirmed blocked comparisons on VS Code 1.95.2 and 1.95.3: https://github.com/microsoft/vscode/issues/233585#issuecomment-2470011601 and https://github.com/microsoft/vscode/issues/233585#issuecomment-2525454273.
