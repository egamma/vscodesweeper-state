# Issue #290962 — Terminal tool command is very horizontally cramped

[https://github.com/microsoft/vscode/issues/290962](https://github.com/microsoft/vscode/issues/290962)

## Summary

Keep open: current source still reserves command-row width for a non-shrinking toolbar and surrounding spacing, so newer collapsible presentations do not fully address the reported readability concern. This team-authored UX request needs a narrow design decision, not a judgment close.

## Change summary

Give terminal commands more usable horizontal space in sidebar chat without sacrificing access to terminal actions.

## Best solution

Make command text the primary content of the terminal-tool row, with secondary actions consuming less permanent horizontal space. Agree on action visibility and placement while preserving keyboard access, command readability, and existing terminal behavior.

Check running and completed states, wrapping, absence of text/action overlap, and keyboard access to every available action; also check the background-shell view that shares these CSS classes.
- **Behavior:**

  > Terminal commands in a reasonably sized sidebar chat should remain readable rather than losing substantial horizontal space to secondary controls. The finished design should provide measurably more usable command width without hiding command text beneath actions. Terminal actions must remain discoverable and keyboard accessible in running and completed states. Validate expanded terminal rows as well as collapsed presentations.
- **Trace:**

  > ChatTerminalToolProgressPart constructs a command block and appends an ActionBar to the same title element. chatTerminalToolProgressPart.css makes that title a horizontal flex row and prevents the action bar from shrinking, so controls and gaps directly reduce command width. The existing thinking and simple-collapsible settings change presentation but do not remove this inner layout. sessionBackgroundShellOutputView.ts also uses the title and action-bar classes, so shared-style effects need checking. Preserve command execution, output retention, terminal status decorations, and action semantics; the uncertainty is the user-facing toolbar placement and reveal behavior, not the terminal pipeline.
- **Open decisions:**
  - Should secondary terminal actions remain persistently visible outside the command's text column, or appear as an overlay on hover and keyboard focus?
