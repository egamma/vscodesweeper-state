# Issue #334663 — Agent Merge: retry timed-out CI jobs once before giving up

[https://github.com/microsoft/vscode/issues/334663](https://github.com/microsoft/vscode/issues/334663)

## Summary

A real gap remains: Agent Merge supports agent-requested workflow reruns, but current main does not classify timeout failures and automatically retry qualifying jobs once. This team-authored request has no fixing commit or merged PR that references https://github.com/microsoft/vscode/issues/334663, so the protected-item rule also requires it to stay open.

## Change summary

Automatically retry a required CI job once when evidence indicates a potentially transient timeout, while preventing repeated retries across Agent Merge turns.

## Best solution

Give Agent Merge a bounded, stateful timeout-recovery policy: retry a qualifying workflow attempt once, surface a second failure for investigation, and leave ordinary or ambiguous failures in the existing repair flow. A maintainer must first define which GitHub check, workflow, job, or log evidence distinguishes a retryable infrastructure timeout from an ordinary timeout.
