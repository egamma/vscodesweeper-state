# Issue #28080 — [decorations] Support hover decorations over the line numbers (i.e. gutter)

[https://github.com/microsoft/vscode/issues/28080](https://github.com/microsoft/vscode/issues/28080)

## Summary

A real extension API gap remains on current main: extensions can render gutter icons, but their public decoration hover is not forwarded to the editor's dedicated glyph-margin hover field. The Backlog request has substantial demand and explicit maintainer support for a contribution.

## Change summary

Expose an extension API for showing decoration-specific hover content over gutter icons or line-number decorations.

## Best solution

Define the public gutter-hover contract, then expose a decoration option that maps to the editor model's existing `glyphMarginHoverMessage` support without changing ordinary text-decoration hover behavior.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/workbench/api/test/browser/extHostTextEditor.test.ts`
- **Validation:** Add an extension-host API test that registers a gutter decoration with hover content and asserts that the main-thread decoration receives it as `glyphMarginHoverMessage`; run the targeted workbench API unit test with `scripts/test.sh --grep "gutter hover"`.
- **Behavior:**

  > An extension can associate Markdown hover content specifically with a text-editor decoration's gutter icon. Hovering that gutter icon displays the supplied content, while hovering the decorated text retains the existing `hoverMessage` behavior. Decorations without gutter-hover content behave exactly as before, and multiple Markdown entries preserve their order.
- **Trace:**

  > The public API in `src/vscode-dts/vscode.d.ts` supports `gutterIconPath` and ordinary `DecorationOptions.hoverMessage`, but has no way to identify hover content as belonging to the gutter. `fromRangeOrRangeWithMessage` in `src/vs/workbench/api/common/extHostTypeConverters.ts` maps only the ordinary hover into `IDecorationOptions`, whose definition in `src/vs/editor/common/editorCommon.ts` likewise lacks a gutter-hover member. The editor model already supports `glyphMarginHoverMessage` in `src/vs/editor/common/model.ts`, and `GlyphHoverComputer` in `src/vs/editor/contrib/hover/browser/glyphHoverComputer.ts` renders it, so the uncertainty begins at the public API contract rather than the renderer. Preserve existing text-hover semantics and do not broaden this issue into click handling or multiple-glyph layout; those broader concerns are tracked by https://github.com/microsoft/vscode/issues/224134 and https://github.com/microsoft/vscode/issues/179725.
- **Open decisions:**
  - Should the public API add a distinct gutter-hover property, leaving `DecorationOptions.hoverMessage` text-only, or should the existing hover automatically appear over both the decorated text and its gutter icon?

## Evidence

- **public API gap:** `src/vscode-dts/vscode.d.ts` exposes `DecorationOptions.hoverMessage` and gutter icon rendering options, but no gutter-specific hover property.
- **conversion path:** `fromRangeOrRangeWithMessage` in `src/vs/workbench/api/common/extHostTypeConverters.ts` forwards the public hover only as `IDecorationOptions.hoverMessage`; `IDecorationOptions` in `src/vs/editor/common/editorCommon.ts` has no glyph-margin hover field.
- **existing internal capability:** `src/vs/editor/common/model.ts` already defines `glyphMarginHoverMessage`, and `src/vs/editor/contrib/hover/browser/glyphHoverComputer.ts` reads that field when hovering a glyph-margin lane. Core consumers including breakpoint and testing decorations already use it.
- **maintainer direction:** Maintainers stated that the internal decorator support exists and only extension-host API is needed; https://github.com/microsoft/vscode/issues/28080#issuecomment-432190319 explicitly says “PR welcome.”
- **demand:** The issue has 73 community upvotes and remains assigned to the Backlog milestone; cross-references show the missing capability affecting GitLens, Bookmarks, and Error Lens scenarios.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/224134 is a newer, broader request for click and hover events, while https://github.com/microsoft/vscode/issues/47559 is also newer and concerns broader glyph-margin interaction. Neither satisfies the stronger duplicate bar for this re-reviewed 2017 issue.
