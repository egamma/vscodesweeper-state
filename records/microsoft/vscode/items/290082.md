# Issue #290082 — Select type of browser data to delete

[https://github.com/microsoft/vscode/issues/290082](https://github.com/microsoft/vscode/issues/290082)

## Summary

The integrated browser still clears session data without offering a data-type selection. Keep this team-authored request open in browser-integration; existing storage-scope controls and history deletion do not cover the requested granularity.

## Change summary

Allow users to select which categories of integrated-browser data to delete while preserving unselected categories.

## Best solution

Provide selective clearing through the integrated browser's storage actions and session service, including the ability to preserve cookies while removing other selected data. Settle the category choices and whether DevTools-style per-site clearing belongs in the initial scope before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/features/browserDataStorageFeatures.ts`, `src/vs/workbench/contrib/browserView/common/browserView.ts`, `src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts`, `src/vs/platform/browserView/common/browserView.ts`, `src/vs/platform/browserView/electron-main/browserViewMainService.ts`, `src/vs/platform/browserView/electron-main/browserView.ts`, `src/vs/platform/browserView/electron-main/browserSession.ts`
- **Validation:** After agreeing on the categories and scope, populate an integrated-browser session with cookies and other supported storage types. Clear selected non-cookie categories and verify that those are removed while cookies and unselected categories remain; verify cancellation changes nothing and full clearing retains its existing semantics. If per-site clearing is included, verify a second origin's data remains intact.
- **Behavior:**

  > Users can choose which supported categories of integrated-browser data to delete instead of resetting the entire browser session. Selecting non-cookie data must allow cookies to remain intact, and cancellation must leave all data unchanged. Acceptance must verify both removal of selected categories and preservation of unselected categories. The supporting comment additionally requests DevTools-style per-site clearing, whose inclusion needs a scope decision.
- **Trace:**

  > The storage actions in src/vs/workbench/contrib/browserView/electron-browser/features/browserDataStorageFeatures.ts distinguish storage scopes but invoke clearing without category options. The renderer service and model contracts in the workbench and platform common/browserView.ts files forward operations to BrowserViewMainService and BrowserView. All clearing paths reach BrowserSession.clearData(), which unconditionally clears trust, history, permissions, and Electron browsing data. Separate history deletion exists in browserHistoryFeature.ts, but is not a general selective-clear facility. The source establishes a missing capability, not a defect in the current all-data command. Preserve existing session isolation, sharing rules, and full-reset behavior; do not treat the comment's per-site request as an already agreed expansion. The request and supporting use case are recorded at https://github.com/microsoft/vscode/issues/290082.
- **Open decisions:**
  - Which categories should users be able to select independently, and should browsing history, permissions, and certificate-trust decisions be selectable alongside cookies, cache, and site storage?
  - Should the initial feature clear selected categories across the existing session scope only, or also offer current-site clearing as requested in the supporting comment?
