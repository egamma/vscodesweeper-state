# Issue #248227 — PHP Autoindent is stupid

[https://github.com/microsoft/vscode/issues/248227](https://github.com/microsoft/vscode/issues/248227)

## Summary

The PHP statement-continuation case remains reproducible from current source: Enter inherits the indentation of the final string line rather than the statement's starting line. The related array-indentation fix addresses different rules, and no verified canonical owns this exact symptom.

## Change summary

Restore the statement's original indentation after pressing Enter following a semicolon that ends a multiline PHP string concatenation.

## Best solution

Make PHP indentation recognize the end of a continued statement without disturbing indentation inside surrounding blocks or ongoing expressions. Establish the statement-boundary handling needed for this case before changing shared autoindent behavior.

No tests were executed during this read-only review.
- **Behavior:**

  > After a multiline PHP string concatenation ends with a semicolon, pressing Enter should place the next statement at the indentation of the original assignment, not its continuation lines. The reported top-level example should return to column one. Inside a block, the next line should retain the block's indentation; unfinished expressions and existing bracket/control-statement indentation must remain unaffected.
- **Trace:**

  > The built-in PHP language configuration has no rule for completed concatenated statements. The Enter path in cursorTypeEditOperations.ts reaches getIndentForEnter in src/vs/editor/common/languages/autoIndent.ts; getInheritIndentForLine defaults to honoring the previous line's indentation when PHP's rules do not recognize it as temporary. For the supplied example this preserves the four spaces before the final string literal. The existing PHP suite in src/vs/editor/contrib/indentation/test/browser/indentation.test.ts supplies an editor typing harness. The unresolved technical boundary is reliable recovery of the statement's starting indentation: the inspected PHP rules are line-local, while the shared inheritance function serves other languages and preserves intentional indentation. Do not treat the bracket-only fix in https://github.com/microsoft/vscode/pull/258016 as resolving this case or broaden the work to unrelated array/HTML indentation.

## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/248227 provides a three-line PHP concatenation, the Enter trigger after the terminating semicolon, and the expected return to the assignment's indentation; it reports the same behavior with extensions disabled.
- **Current PHP rules:** extensions/php/language-configuration.json has no indentation or onEnter rule that recognizes completion of a multiline concatenation. Its indentNextLinePattern handles unbraced control statements, not the manually indented string continuation in this report.
- **Source-confirmed Enter path:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts invokes getIndentForEnter for full autoindent. In src/vs/editor/common/languages/autoIndent.ts:304–353, that function uses getInheritIndentForLine with the default honorIntentialIndent=true. Neither the final string line nor its predecessor matches PHP's statement/control indentation rules, so the inheritance branch returns the final string line's leading whitespace instead of finding the assignment's starting indentation.
- **Related fix does not cover this trigger:** https://github.com/microsoft/vscode/pull/258016 merged as 8d2287f6f7d61d8311497ff09887717fed5e6f2a to fix https://github.com/microsoft/vscode/issues/248229. Its diff removes bracket alternatives from PHP's increase/decrease patterns and normalizes two rule representations; it adds no handling for semicolon-terminated string continuations. That closed array report is neither a valid duplicate canonical nor proof that this report is fixed.
