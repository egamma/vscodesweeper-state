# Issue #266365 — Why are all 3 prompt entries not showing in the chat welcome view?

[https://github.com/microsoft/vscode/issues/266365](https://github.com/microsoft/vscode/issues/266365)

## Summary

The issue remains necessary: current main still registers `chat.promptFilesRecommendations`, but the chat welcome path no longer consumes that setting, so configured prompt entries cannot appear. Route this to the chat customizations owners rather than closing it.

## Change summary

All configured prompt-file recommendations should appear in the chat welcome view instead of showing only one or none.

## Best solution

Restore a coherent product contract for `chat.promptFilesRecommendations`: preferably render every matching, valid configured prompt independently in the current empty state, without one unresolved entry suppressing the others. If prompt tiles were intentionally retired, remove or deprecate the setting rather than leaving a documented but nonfunctional configuration.

## Plan brief

- **Validation:** Configure three existing prompt files as `true`, open a new empty chat, and verify that all three recommendations appear and are individually actionable; then add one nonexistent configured name and verify that the three valid recommendations remain visible.
- **Behavior:**

  > The `chat.promptFilesRecommendations` setting must have an observable, consistent effect. In a new empty chat, every configured prompt whose condition matches and whose prompt file exists should be offered; an unresolved or malformed entry must not suppress valid recommendations. Selecting an entry should continue to invoke that prompt. Acceptance includes the three-valid-prompts case and the same case with one additional nonexistent prompt.
- **Trace:**

  > The original implementation arrived in https://github.com/microsoft/vscode/pull/263369 and asynchronously populated suggested prompts in `ChatWidget`, then rendered them through `ChatViewWelcomePart`. On current main, `chat.promptFilesRecommendations` remains registered in `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, and its getter remains in `src/vs/workbench/contrib/chat/common/promptSyntax/config/config.ts`, but `git grep` finds no consumer. The active empty-state path is `ChatWidget.renderWelcomeViewContentIfNeeded` → `getWelcomeViewContent` → `ChatViewWelcomePart`; its content contract no longer includes prompt recommendations. Preserve normal prompt discovery and execution semantics, and do not broaden the work into the overall welcome redesign tracked by https://github.com/microsoft/vscode/issues/251187.
- **Open decisions:**
  - Should `chat.promptFilesRecommendations` continue to populate recommendations in the current chat empty state, or should the setting be formally deprecated and removed because that surface no longer supports prompt tiles?
