# Issue #336128 — Automations: Workdays

[https://github.com/microsoft/vscode/issues/336128](https://github.com/microsoft/vscode/issues/336128)

## Summary

Real, unimplemented gap: the Automations schedule only supports manual/hourly/daily/weekly (single day-of-week) recurrence, with no weekday-only ("workdays") option — confirmed in automationDialog.ts's INTERVALS list and the cron-based schedule parsing in agentHostAutomationStore.ts. Team-authored (chrmarti is a collaborator) and parked in the On Deck holding-bin milestone, so it stays open per the feature-request rules rather than being closed for quiet activity.

## Change summary

Add a "Workdays" (Monday–Friday) recurrence option to Automations scheduling so automations don't fire on weekends.

## Best solution

Add a workdays recurrence to the Automation schedule model — likely a new AutomationInterval value or a day-range extension of the existing weekly cron field — surfaced in automationDialog.ts, computed consistently in both the legacy and Agent Host schedule stores, and reflected in AUTOMATIONS.md's blueprint schedule contract.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/automations/browser/automationDialog.ts`, `src/vs/sessions/contrib/automations/browser/automationTools.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/agentHostAutomationStore.ts`, `src/vs/sessions/contrib/sessions/browser/views/automationsView.ts`, `src/vs/sessions/contrib/sessions/browser/views/automationsAccessibility.ts`, `src/vs/sessions/AUTOMATIONS.md`
- **Validation:** A schedule-computation test asserting a 'workdays' automation's next-trigger cursor skips Saturday/Sunday and lands on the next weekday at the configured time.
- **Behavior:**

  > Users can configure an automation to recur only on weekdays (Monday–Friday) at a chosen time, so it never triggers on Saturday or Sunday. Existing manual/hourly/daily/weekly options are unaffected. Acceptance: a new schedule test confirms the computed next-trigger for a workdays automation always falls on a weekday.
- **Trace:**

  > Interval options are enumerated in automationDialog.ts's INTERVALS array and the AutomationInterval type in automationTools.ts; actual schedule-to-cron and cron-to-schedule conversion (including the weekly single-day case) lives in agentHostAutomationStore.ts's parseCronValue/toCronExpression helpers (~lines 1179-1227). AUTOMATIONS.md documents the blueprint schedule contract as daily/weekly cron only — this is the boundary that needs extending, not the run-execution or authority-transition logic elsewhere in that spec.
- **Open decisions:**
  - Should 'workdays' be a new top-level AutomationInterval value, or should the existing weekly schedule support a day-range/multi-day selection that a 'workdays' preset maps onto?
  - Does the blueprint (.automation.md) cron format need to support day ranges (e.g. 1-5) to preserve a workdays schedule on export/import, per AUTOMATIONS.md's current daily/weekly-only cron contract?

## Evidence

- **no workdays option:** src/vs/sessions/contrib/automations/browser/automationDialog.ts defines INTERVALS as only manual/hourly/daily/weekly (lines ~74-79); no weekday-range or 'workdays' entry exists.
- **cron model is single-day, not range-based:** src/vs/sessions/contrib/providers/agentHost/browser/agentHostAutomationStore.ts parseCronValue/toCronExpression handles a single scheduleDay (0-6) for 'weekly' (lines ~1197-1227); there's no range (e.g. 1-5) parsing for a workdays-style schedule.
- **spec constraint:** src/vs/sessions/AUTOMATIONS.md states blueprint schedules are 'manual-only, a relative hourly cadence, or a five-field cron expression... for daily and weekly schedules' — a workdays recurrence would need this contract extended too.
