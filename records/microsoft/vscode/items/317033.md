# Issue #317033 — Markdown keeps scrolling to a specific position when switching tabs

[https://github.com/microsoft/vscode/issues/317033](https://github.com/microsoft/vscode/issues/317033)

## Summary

Keep open: current source repeatedly reapplies the last Markdown preview position whenever the source editor becomes active, overriding subsequent manual scrolling. The defect is bounded and ready for an implementation session.

## Change summary

After leaving Markdown preview, switching back to the source tab resets its viewport to the preview's remembered position.

## Best solution

Preserve the initial preview-to-source scroll handoff without overriding the source editor's subsequent viewport on ordinary tab or editor-group activation. Address the retained preview-position state in the Markdown extension and cover repeated activation with a regression test.

## Evidence

- **Current-source activation path:** extensions/markdown-language-features/src/preview/previewManager.ts: MarkdownPreviewManager's onDidChangeActiveTextEditor listener retrieves getPreviousStaticEditorLineByUri for every activated Markdown source editor and calls scrollEditorToLine whenever a remembered line exists. There is no transition-specific restriction or consumption of that position.
- **Persistent stale position:** extensions/markdown-language-features/src/preview/topmostLineMonitor.ts: setPreviousStaticEditorLine stores preview positions in #previousStaticEditorInfo, while getPreviousStaticEditorLineByUri returns the entry without deleting it. Source-editor scrolling updates the separate #previousTextEditorInfo map, leaving the preview position unchanged. This conclusively explains repeated resets after the reporter manually scrolls elsewhere.
