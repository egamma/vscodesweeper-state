# Issue #239006 — Editor GPU: The viewport rendering strategy stops working after > 20k lines

[https://github.com/microsoft/vscode/issues/239006](https://github.com/microsoft/vscode/issues/239006)

## Summary

Keep open: the current viewport GPU renderer mixes rebased line coordinates with absolute scroll coordinates, explaining blank rendering after scrolling sufficiently far. An open PR references this issue, but its DOM fallback change does not address that coordinate mismatch.

## Change summary

Prevent GPU-rendered editor text from disappearing when scrolling beyond roughly 20,000 lines.

## Best solution

Keep GPU line positions and scroll offsets in the same coordinate space across large-scroll rebasing boundaries. Review the linked PR against this specific scrolling trigger rather than treating its DOM fallback regression test as proof that the issue is resolved.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/239006 reports that scrolling past roughly 20,000 lines suddenly blanks the editor, including previously visible lines. The February 2026 comment reports continued impact but supplies no additional reproduction details.
- **Source reproduction: coordinate rebasing:** src/vs/editor/common/viewLayout/linesLayout.ts:642–650 introduces bigNumbersDelta once the starting vertical offset reaches 500,000 pixels, subtracts it from currentLineRelativeOffset, and returns those rebased offsets as relativeVerticalOffset at lines 719–723. The threshold depends on line height, consistent with an approximate line-count boundary.
- **Source reproduction: missing compensation:** src/vs/editor/browser/gpu/renderStrategy/viewportRenderStrategy.ts computes glyph Y positions from viewportData.relativeVerticalOffset but uploads absolute scrollTop at line 165. src/vs/editor/browser/gpu/renderStrategy/fullFileRenderStrategy.wgsl.ts subtracts that scroll offset from cell positions, while src/vs/editor/browser/viewParts/viewLinesGpu/viewLinesGpu.ts:160–161 sets the viewport Y offset to zero. Once bigNumbersDelta becomes nonzero, visible glyphs are displaced off-screen by that delta; the DOM renderer instead adjusts scrollTop by viewportData.bigNumbersDelta in viewLines.ts. This was traced read-only, not executed.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/295684 is OPEN with no merge timestamp and explicitly references this issue. Its diff marks ViewLine invalid after removing its DOM node for GPU rendering and adds a DOM → GPU → DOM regression test. That fixes a separate fallback path but does not change viewport coordinate rebasing or GPU scroll offsets.

The former tracks the overall WebGPU renderer project rather than this observable large-scroll defect. https://github.com/microsoft/vscode/issues/282517 concerns a single long line disappearing while typing and was created later; neither satisfies the stronger duplicate bar for this re-reviewed issue.
