# Issue #173888 — Could we have vscode.open and vscode.diff support customize open mode?

[https://github.com/microsoft/vscode/issues/173888](https://github.com/microsoft/vscode/issues/173888)

## Summary

Keep open: current main still lacks per-tree-item activation-mode control, and this accepted Backlog request exceeded the 20-upvote threshold.

## Change summary

Allow an extension tree item to choose whether its open or diff command activates on a single, double, or other click independently of the global list open mode.

## Best solution

Preserve consistent open-command semantics and evaluate this as a TreeItem or tree-view activation API, where an extension could declaratively select a supported activation gesture without overloading `vscode.open` or `vscode.diff`.

## Evidence

- **current source:** src/vs/platform/list/browser/listService.ts derives activation from `workbench.list.openMode` and supports only an internal `openOnSingleClick` boolean; pointer and double-click handlers generate the open event.
- **tree command flow:** src/vs/workbench/browser/parts/views/treeView.ts executes a TreeItem command only after `tree.onDidOpen` and passes the resulting `IOpenEvent` context to the internal open/diff commands, leaving no TreeItem-level activation choice.
- **existing API options:** src/vs/workbench/api/common/extHostApiCommands.ts and extHostTypeConverters.ts expose editor options such as preview, view column, focus, and selection for `vscode.open` and `vscode.diff`, but no click or activation mode.
