# Issue #340052 — Folder that is currently open in a window is not presented in the New Session picker

[https://github.com/microsoft/vscode/issues/340052](https://github.com/microsoft/vscode/issues/340052)

## Summary

Fresh, team-authored bug report (filed today by a VS Code maintainer, with repro steps and a screenshot) about the Agents Window's New Session folder picker not listing a folder that is actively open in another editor window. No fix exists yet, so this stays open regardless of the team-authored protections.

## Change summary

After opening a new folder in an editor window, that folder does not appear in the Agents Window's 'New Session' folder picker even though it's visibly open in the background.

## Best solution

Diagnose why SessionsRecentWorkspacesService's VS Code-recent-folders refresh (sessionsRecentWorkspacesService.ts, _refreshVSCodeRecentWorkspaces/getRecentWorkspaces) misses a folder that was just opened — likely a staleness/race between the main-process addRecentlyOpened call (windowsMainService.ts) and the picker's cached onDidChangeRecentlyOpened-driven refresh — and make the picker reliably include it.

## Plan brief

- **Likely files:** `src/vs/sessions/services/sessions/browser/sessionsRecentWorkspacesService.ts`, `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`
- **Validation:** A test or manual check that, after opening a new folder window, immediately opening the New Session picker in the Agents window shows that folder in the list.
- **Behavior:**

  > Opening a new folder in an editor window should make that folder immediately selectable from the Agents Window's 'New Session' folder picker, the same as any other recently opened folder. Currently it is visibly open (seen in the background) but absent from the picker list. Acceptance: open a freshly created folder in a window, then open New Session in the Agents Window — the folder appears in the list without needing to restart or wait.
- **Trace:**

  > SessionsRecentWorkspacesService.getRecentWorkspaces() (src/vs/sessions/services/sessions/browser/sessionsRecentWorkspacesService.ts) builds its VS Code-recent list from `_vsCodeRecentFolders`, refreshed only on `workspacesService.onDidChangeRecentlyOpened` or at construction via `_refreshVSCodeRecentWorkspaces()`. The main process does add the folder to recently-opened synchronously when the window opens (windowsMainService.ts, addRecentlyOpened call around line 490), so the likely gap is on the renderer/picker side — either the change event doesn't reach the Agents window process promptly, or the picker reads a stale snapshot cached before the event lands. Do not touch the 'agents'-sourced own-history path (storedOwn) which is unrelated; scope the fix to the VS Code-recent-folders ingestion/refresh path. Where the uncertainty starts: whether this is a timing race (fixable with a forced re-fetch when the picker opens) or a dedup/filter bug (e.g. MAX_VSCODE_RECENT_WORKSPACES truncation, or `_includeVSCodeFolder` exclusion) silently dropping the entry.
- **Open decisions:**
  - Is the picker's VS Code-recent-folders list being refreshed reactively but just hasn't received the event yet, or is it reading a cached/stale list at display time — does the fix belong in the refresh trigger or in a forced re-fetch on picker open?
  - Should the picker also directly enumerate currently-open windows/folders (not just the recently-opened history) so an actively open folder is guaranteed to show even if the history update is delayed?

## Evidence

- **picker data source:** src/vs/sessions/services/sessions/browser/sessionsRecentWorkspacesService.ts getRecentWorkspaces() merges own 'agents' history with `_vsCodeRecentFolders`, which is populated by `_refreshVSCodeRecentWorkspaces()` reacting to `workspacesService.onDidChangeRecentlyOpened`.
- **recent-opened write path:** src/vs/platform/windows/electron-main/windowsMainService.ts (~line 478-490) calls `this.workspacesHistoryMainService.addRecentlyOpened(recents)` synchronously when a folder window is opened, so the entry should exist in VS Code's recent list almost immediately — the picker's failure to show it points to a refresh/race issue on the renderer side rather than the folder simply never being recorded.
