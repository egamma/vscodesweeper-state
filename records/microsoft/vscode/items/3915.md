# Issue #3915 — Render errors & warnings in gutter

[https://github.com/microsoft/vscode/issues/3915](https://github.com/microsoft/vscode/issues/3915)

## Summary

Native error and warning gutter indicators remain missing on current main, despite substantial demand and explicit maintainer support. Keep this accepted editor-rendering request open; the related styling request is newer and cannot replace it under the re-review rules.

## Change summary

Render line-level error and warning indicators in the editor gutter alongside precise diagnostic markings in the text.

## Best solution

Provide consistent native diagnostic gutter indicators that remain usable alongside breakpoints and other gutter decorations. A maintainer should settle presentation and enablement semantics before implementation in the editor marker-decoration pipeline.

## Plan brief

- **Likely files:** `src/vs/editor/common/services/markerDecorationsService.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/model.ts`
- **Validation:** After presentation decisions, manually open a file containing both an error and a warning, verify the agreed gutter indicators and precise text markings, place a breakpoint on an affected line and confirm both remain visible and usable, then resolve the diagnostics and verify their indicators disappear. Check multiple diagnostics on one line and the chosen disabled-state behavior.
- **Behavior:**

  > Errors and warnings should have native line-level gutter indicators so users can scan the current file without locating individual squiggles. Precise diagnostic ranges in the text remain available. Diagnostic indicators must coexist with breakpoints rather than obscure or replace them, and must update when diagnostics change or disappear. Acceptance includes errors and warnings on separate lines, several diagnostics on one line, and an affected line that also contains a breakpoint.
- **Trace:**

  > MarkerDecorationsService consumes IMarkerService updates and MarkerDecorations._createDecorationOption in src/vs/editor/common/services/markerDecorationsService.ts converts each diagnostic into text, overview-ruler and minimap decorations without gutter options. The browser contribution in src/vs/editor/browser/services/markerDecorations.ts instantiates that service rather than supplying another diagnostic rendering path. src/vs/editor/common/model.ts already defines glyph-margin decoration classes and three positional lanes; editor.glyphMargin and editor.renderValidationDecorations in src/vs/editor/common/config/editorOptions.ts do not provide the requested native diagnostic mode. The supplied thread identifies breakpoint overlap as a limitation of extension workarounds, not a reason to remove breakpoint behavior. Preserve diagnostic production, existing text-range semantics and debugger interactions; alternative outline/fill styles belong to the related, newer https://github.com/microsoft/vscode/issues/9209 rather than being prerequisites for this request. The remaining uncertainty is product presentation and enablement, not whether the central gutter capability exists today.
- **Open decisions:**
  - Should native diagnostic gutter indicators be enabled by default or exposed as an opt-in editor setting?
  - What gutter placement and presentation should diagnostics use so that breakpoints remain visible and independently usable?
  - When multiple errors and warnings occur on one line, should the gutter show one highest-severity indicator or multiple indicators?

## Evidence
