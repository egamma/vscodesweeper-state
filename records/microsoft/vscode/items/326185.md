# Issue #326185 — http.noProxy config not work for agent host when request BYOK model

[https://github.com/microsoft/vscode/issues/326185](https://github.com/microsoft/vscode/issues/326185)

## Summary

Real gap traced in the agent host: when the Copilot SDK subprocess is given a resolved proxy, VS Code forwards HTTP_PROXY/HTTPS_PROXY but never NO_PROXY, so the user's `http.noProxy` exclusions (e.g. 127.0.0.1/localhost for BYOK model endpoints) never reach the subprocess and everything gets proxied.

## Change summary

Requests from the agent host to a local/BYOK model endpoint (127.0.0.1) are sent through the configured HTTP proxy even though that address is listed in `http.noProxy`.

## Best solution

In `_configureProxyEnv` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts), when a proxy is resolved and forwarded via HTTP_PROXY/HTTPS_PROXY, also compute and forward NO_PROXY/no_proxy from the `http.noProxy` configuration (already available via `IAgentHostProxyResolver`'s underlying config) so the Copilot SDK subprocess's own HTTP client bypasses the proxy for excluded hosts.
