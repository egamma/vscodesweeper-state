# Issue #292578 — Experimental: Double-Press Keybindings (single vs double-tap) (opt-in)

[https://github.com/microsoft/vscode/issues/292578](https://github.com/microsoft/vscode/issues/292578)

## Summary

Keep open: existing chords and double-modifier shortcuts do not provide the requested single-versus-double-press behavior. The current Backlog milestone represents accepted work; neither the older community-review reminders nor the related requests establish grounds for closing it.

## Change summary

Add opt-in, context-aware single/double-press keybindings with configurable timing, cancellation, repeat handling, accessible confirmations, and editor support.

## Best solution

Have the keybindings and accessibility owners settle the scope of an opt-in timing mechanism that preserves existing dispatch behavior when disabled. Coordinate timeout semantics with the older chord-fallback request and announcement behavior with the separate accessibility proposal rather than introducing conflicting contracts.

## Evidence

- **Existing capability does not cover the request:** src/vs/platform/keybinding/common/abstractKeybindingService.ts supports repeated modifier shortcuts through _singleModifierDispatch with a fixed 300 ms window, but expiration only clears the pending modifier. Ordinary chords use _scheduleLeaveChordMode with a five-second timeout and do not execute a single-command fallback; an unmatched second chord is consumed. Neither path implements the requested arbitrary-key single/double actions or normal dispatch of an intervening different key.
- **Configuration and binding contract:** src/vs/platform/keyboardLayout/common/keyboardConfig.ts registers keyboard.dispatch and keyboard.mapAltGrToCtrlAlt, not keyboard.doublePress.*. KeybindingIO.readUserKeybindingItem in src/vs/workbench/services/keybinding/common/keybindingIO.ts reads one command with key, when, args, and systemWide; it has no singleCommand/doubleCommand or announcement metadata handling.
- **Older related request, not a verified canonical:** https://github.com/microsoft/vscode/issues/140226 is open and predates this report. Its central scenario is an ordinary chord shadowing a standalone command, with discussion of configurable timeout fallback. It overlaps the timing problem but does not establish ownership of this report's same-key-only gesture, different-key cancellation and redispatch, repeat handling, or accessibility/editor contract, so it does not meet the stronger duplicate bar for this re-reviewed item.

In https://github.com/microsoft/vscode/issues/292577#issuecomment-3842754417, a maintainer says custom messages are not envisioned and suggests announcing completion, optionally with the action title.
