# Issue #185112 — Column Select / Multiple Cursors: Ability to not have cursor inserted in wrapped part of wrapped text, without need to disable line wrap

[https://github.com/microsoft/vscode/issues/185112](https://github.com/microsoft/vscode/issues/185112)

## Summary

A real capability gap remains on current main: mouse-driven column selection operates on wrapped view lines, while the equivalent keyboard cursor-above/below actions default to logical model lines. This should remain open under the existing multicursor area, but it needs a product decision on whether logical-line mouse selection replaces the current behavior or becomes an option.

## Change summary

Allow mouse-based column selection to avoid creating additional cursors in wrapped continuation segments without disabling word wrap.

## Best solution

Provide a consistent logical-line mode for mouse-driven column selection so wrapped continuation segments do not receive independent cursors, while preserving a deliberate path for users who rely on visual-line column selection.

## Plan brief

- **Likely files:** `src/vs/editor/browser/view/viewController.ts`, `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/common/cursor/cursorColumnSelection.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add a cursor controller test using `wordWrap: 'wordWrapColumn'` that performs mouse-style column selection across wrapped and unwrapped model lines, asserting the chosen logical-line mode produces at most one cursor per model line and that ordinary unwrapped column selection remains unchanged.
- **Behavior:**

  > With word wrap enabled, users need a mouse-driven column-selection behavior that does not insert independent cursors into continuation segments of the same logical line. Unwrapped column selection must continue to select the same rectangular range as today. Acceptance should cover dragging in both directions across a wrapped line and adjacent model lines, including typing after the selection without cursor positions shifting as wrapping changes.
- **Trace:**

  > Mouse gestures reach `ViewController._columnSelect` in src/vs/editor/browser/view/viewController.ts and then `CoreNavigationCommands.ColumnSelect` in src/vs/editor/browser/coreCommands.ts. That command supplies wrapped view-line numbers to `ColumnSelection.columnSelect` in src/vs/editor/common/cursor/cursorColumnSelection.ts, whose loop emits one state for every view line; this directly explains cursors in wrapped continuation segments. Keyboard Add Cursor Above/Below follows a separate logical-line path in src/vs/editor/contrib/multicursor/browser/multicursor.ts, established by https://github.com/microsoft/vscode/commit/c0d32634fb0cbf18ec82d6167ab2accc0c9f17f5. The boundary is mouse column/multicursor selection under wrapping: keyboard behavior and ordinary unwrapped rectangular selection must not regress. The uncertainty begins with whether visual-line selection remains available and how horizontal coordinates map when one model line occupies several differently indented view lines.
- **Open decisions:**
  - Should logical-line behavior become the mouse column-selection default, or be exposed as an option alongside the existing visual-line behavior?
  - When a rectangle crosses several wrapped segments belonging to one model line, which segment and horizontal coordinate determine that line's single selection?
  - Should the decision apply uniformly to Shift+multicursor dragging, middle-button column selection, and `editor.columnSelection` mode?

## Evidence

- **current source:** src/vs/editor/browser/view/viewController.ts routes Shift+multicursor mouse gestures and column-selection dragging to `_columnSelect`, which passes a view position to `CoreNavigationCommands.ColumnSelect`.
- **root cause:** src/vs/editor/browser/coreCommands.ts:461-471 passes wrapped view-line bounds to `ColumnSelection.columnSelect`; src/vs/editor/common/cursor/cursorColumnSelection.ts:12-52 then creates one cursor state for every line in that view-line range, including continuation segments of the same model line.
- **keyboard precedent:** https://github.com/microsoft/vscode/commit/c0d32634fb0cbf18ec82d6167ab2accc0c9f17f5 changed Add Cursor Above/Below to use logical lines by default for https://github.com/microsoft/vscode/issues/26393, but did not change the separate mouse column-selection path.
- **corroborating report:** https://github.com/microsoft/vscode/issues/198399 remains open with explicit steps and a recording of the same wrapped-line mouse behavior; it references this older issue as the related request, making this issue the better canonical location.
- **existing capability check:** Current source exposes the `logicalLine` argument only for the keyboard Add Cursor Above/Below actions in src/vs/editor/contrib/multicursor/browser/multicursor.ts; no equivalent mouse column-selection mode is present.
