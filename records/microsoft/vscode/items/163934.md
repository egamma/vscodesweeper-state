# Issue #163934 — Git - Sync Changes Button Should Not Pull When There Are No Incoming Changes

[https://github.com/microsoft/vscode/issues/163934](https://github.com/microsoft/vscode/issues/163934)

## Summary

The requested behavior remains missing: Sync Changes still pulls before pushing even when the displayed incoming count is zero. Keep this team-authored, accepted request open; the related reports do not provide an eligible older canonical.

## Change summary

Avoid pulling and potentially merging newly arrived remote commits when Sync Changes displays only outgoing commits.

## Best solution

Provide a one-click outgoing-only action that never automatically integrates and publishes unseen remote changes. Resolve whether this changes Sync Changes itself or uses the configurable Pull/Push action-button approach proposed by the Git maintainer in the related discussion.

- **Behavior:**

  > The report concerns an upstream-tracking branch showing outgoing commits and no incoming commits. Clicking the outgoing-only action should not pull, merge, or rebase unseen remote commits before pushing. If the remote advances after the displayed counts were computed, the operation must not automatically integrate and publish those changes without review. Acceptance should cover both a genuinely current remote and a stale zero-incoming display, with clear feedback when the push cannot proceed.
- **Trace:**

  > getSyncChangesActionButton() in extensions/git/src/actionButton.ts uses HEAD.ahead and HEAD.behind to display counts but always invokes git.sync. Commands._sync() in extensions/git/src/commands.ts forwards to Repository.sync(); Repository._sync() in extensions/git/src/repository.ts performs the pull path before deciding whether to push, without a zero-behind gate. The related maintainer discussion at https://github.com/microsoft/vscode/issues/174198#issuecomment-2451982028 favors configurable Pull/Push buttons while preserving Sync semantics. The unresolved boundary is the user-facing action contract; preserve explicit Pull/Push behavior, upstream selection, and unrelated sync configurations.
- **Open decisions:**
