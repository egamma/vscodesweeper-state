# Issue #163934 — Git - Sync Changes Button Should Not Pull When There Are No Incoming Changes

[https://github.com/microsoft/vscode/issues/163934](https://github.com/microsoft/vscode/issues/163934)

## Summary

Valid, unimplemented feature request from a team member. The sync command in the git extension still unconditionally pulls regardless of the behind count; the push side already checks `ahead > 0` but there is no corresponding `behind > 0` guard for the pull. Stays open in Backlog.

## Change summary

Skip the `git pull` step during sync when VS Code's git extension believes there are no incoming commits (behind === 0), avoiding surprise auto-merges.

## Best solution

Add a `behind > 0` guard (mirroring the existing `ahead > 0` push guard at line 2441) before calling `_pullAndHandleTagConflict` in `Repository._sync()` in `extensions/git/src/repository.ts`. This keeps sync fast when only pushing and prevents unexpected merge commits from late-arriving remote changes.
