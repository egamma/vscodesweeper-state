# Issue #283633 — Background Agents powered by Copilot CLI is a confusing design decision

[https://github.com/microsoft/vscode/issues/283633](https://github.com/microsoft/vscode/issues/283633)

## Summary

Keep open for a current capability assessment and design discussion: MCP forwarding and explicit CLI branding now address parts of the request, but they do not establish full local-agent parity. This team-authored, previously reviewed item has no verified qualifying fix or older open canonical covering the same experience.

## Change summary

Allow existing VS Code custom agents and their tools to run asynchronously in the workspace or a worktree without requiring a different harness-specific setup.

## Best solution

Make the Data and Demonstrate workflows usable asynchronously with their existing VS Code custom-agent definitions, extension-contributed MCP servers, tool discovery, and required VS Code tools. Assess those workflows against today's Agent Host integration before deciding which remaining capabilities need implementation; clearer CLI branding alone does not satisfy the central request.
