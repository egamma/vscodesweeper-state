## Plan brief

- **Likely files:** `src/vs/base/parts/request/common/requestImpl.ts`, `src/vs/workbench/services/request/electron-browser/requestService.ts`, `src/vs/platform/extensionManagement/common/extensionGalleryService.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsViews.ts`
- **Validation:** With Copilot active on an affected environment, repeatedly search the Extensions Marketplace while capturing DevTools Network and the VS Code Network log; verify Marketplace queries remain successful under a stable connection and that removing Copilot no longer changes the result. Also confirm existing proxy and offline error handling remains intact.
- **Behavior:**

  > Searching the Extensions Marketplace over a stable connection must return remote results whether Copilot is installed and active or not. Copilot background activity must not cause the Marketplace request to fail with ERR_NETWORK_CHANGED or leave only local extensions visible. Existing behavior for genuinely offline systems and configured proxies must remain unchanged.
- **Trace:**

  > The failing request is the Marketplace extensionquery POST issued by ExtensionGalleryService in src/vs/platform/extensionManagement/common/extensionGalleryService.ts. It reaches browser fetch through NativeRequestService in src/vs/workbench/services/request/electron-browser/requestService.ts and request() in src/vs/base/parts/request/common/requestImpl.ts; the resulting failure is wrapped as ExtensionGalleryError and displayed by extensionsViews.ts. The report establishes a correlation with Copilot but does not identify which network-interface event, connection reuse behavior, or request client causes it. https://github.com/microsoft/vscode/issues/260297 documents related Chromium ERR_NETWORK_CHANGED behavior but its completed retry was scoped to Copilot Chat, so do not assume it fixes or canonically owns Marketplace requests. Preserve proxy resolution, cancellation, timeout, and true-offline behavior while diagnosing this path.

## Evidence

- **reported reproduction:** The reporter's console shows the Marketplace POST to https://marketplace.visualstudio.com/_apis/public/gallery/extensionquery failing with net::ERR_NETWORK_CHANGED on Ubuntu, and reports that removing Copilot resolves the symptom.
- **independent confirmation:** A second user reproduced the extension-fetch failure on VS Code 1.109.3 on Windows with no configured proxy and with the Marketplace reachable in a browser.
- **current source path:** On current main, ExtensionGalleryService sends the Marketplace POST through IRequestService in src/vs/platform/extensionManagement/common/extensionGalleryService.ts; NativeRequestService delegates to browser fetch through src/vs/workbench/services/request/electron-browser/requestService.ts and src/vs/base/parts/request/common/requestImpl.ts.
- **visible failure handling:** src/vs/workbench/contrib/extensions/browser/extensionsViews.ts converts ExtensionGalleryError failures into the reported "Error while fetching extensions" message and falls back to local extensions, but does not explain or prevent the underlying ERR_NETWORK_CHANGED.
- **canonical search:** https://github.com/microsoft/vscode/issues/282237 concerns ERR_PROXY_CONNECTION_FAILED from environment proxy variables, while https://github.com/microsoft/vscode/issues/313045 concerns an unhandled MCP-gallery request; neither owns this Marketplace/Copilot interaction. The completed https://github.com/microsoft/vscode/issues/260297 addressed retries for Copilot Chat requests, not extension Marketplace queries.
