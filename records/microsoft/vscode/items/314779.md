# Issue #314779 — Customizations list: Tab into list does not visibly focus first entry

[https://github.com/microsoft/vscode/issues/314779](https://github.com/microsoft/vscode/issues/314779)

## Summary

Team-authored accessibility bug that still reproduces on main. The initial fix (PR #314770) added a `focusList()` method that sets focus to index 0, but it is never invoked on tab-in — so the list silently absorbs DOM focus without showing a focus indicator until an arrow key is pressed.

## Change summary

Tabbing into the Agent Customizations list does not visibly focus the first entry; the list absorbs focus silently until an arrow key is pressed.

## Best solution

Wire the list's DOM `focusin` event (when triggered by tab navigation, not programmatic focus) to call `setFocus([0])` on the underlying list widget in `aiCustomizationListWidget.ts`, matching the pattern already in `focusList()`. This is a common pattern in other workbench list/tree widgets that auto-reveal the first item on tab-in.
