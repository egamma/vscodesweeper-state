# Issue #340477 — System-wide Open Agents Window shortcut replaces the active session

[https://github.com/microsoft/vscode/issues/340477](https://github.com/microsoft/vscode/issues/340477)

## Summary

Confirmed in source: a system-wide invocation of Open Agents Window has no `reveal` argument, so `OpenAgentsWindowAction.run` infers and forwards the invoking renderer's `folderUri`, which replaces the reused window's active session with a fresh composer. The reporter's own fixing PR (https://github.com/microsoft/vscode/pull/340478) was opened and then closed unmerged the same day, so the fix hasn't landed yet.

## Change summary

A system-wide Open Agents Window keybinding, when it reuses an existing Agents Window, replaces the active session with the new-session view instead of leaving it untouched.

## Best solution

Land a version of the approach from the closed PR https://github.com/microsoft/vscode/pull/340478 (reused-window detection in the main process plus active-session preservation in the Sessions renderer), but get a maintainer's sign-off on the `reveal`/`revealNewSession` option split first since the first attempt didn't merge.

- **Trace:**

  > `OpenAgentsWindowAction.run` (src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts:336-349) infers `folderUri` from the invoking renderer whenever `args?.reveal` is undefined or `'new'`, and forwards it to `nativeHostService.openAgentsWindow` unconditionally — the system-wide keybinding path never supplies `reveal`, so this fires every time and the Sessions renderer treats the folderUri handoff as a signal to show a new/default session. Do not change behavior for callers that already pass an explicit `sessionResource` or intentionally request a new session/draft. Where the uncertainty starts: whether the right contract is a new `revealNewSession` flag (as attempted) versus changing the default meaning of the existing `reveal` option, and exactly which call sites must opt in — a maintainer should confirm the API shape before a second attempt, since the first PR didn't merge and the reason isn't recorded.
- **Open decisions:**
