# Issue #284990 — Command Palette cannot find related commands when Keyboard Shortcuts view is open

[https://github.com/microsoft/vscode/issues/284990](https://github.com/microsoft/vscode/issues/284990)

## Summary

Current behavior is by-design — EditorAction commands only appear in the Command Palette when an active text editor exists — but the UX is confusing. Team-authored issue assigned to @alexdima; keeping open for a product decision on whether to show these commands in a disabled/greyed-out state or always include them.

## Change summary

Editor-scoped commands (e.g. font zoom) vanish from the Command Palette when a non-editor view like Keyboard Shortcuts is focused, making them undiscoverable.

## Best solution

Decide whether `getCodeEditorCommandPicks()` in `src/vs/editor/contrib/quickAccess/browser/commandsQuickAccess.ts` should still return editor actions when no editor is active — possibly greyed out / disabled (as RedCMD suggested) — so they remain discoverable. The change would touch the empty-array early return at line 37 and likely the pick rendering to show a disabled state. This is a product/UX call for the editor area owner.
