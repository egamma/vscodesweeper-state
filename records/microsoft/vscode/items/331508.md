# Issue #331508 — Multi-root: a folder's customization is unreachable when another folder defines the same name

[https://github.com/microsoft/vscode/issues/331508](https://github.com/microsoft/vscode/issues/331508)

## Summary

Team-authored, thoroughly reproduced design gap: in multi-root workspaces, a same-named skill/agent from a non-primary folder is silently unreachable under any name across Claude, Codex, and Copilot harnesses. No fix exists on main yet, so this stays open (team-authored items are only closed on mechanical evidence, which isn't present here).

## Change summary

When two workspace folders each define a customization (skill/agent/command) with the same name, the non-primary folder's copy is silently dropped with no scoped alias and no diagnostic, making it permanently unreachable.

## Best solution

Extend the per-harness customization scan/merge (starting with `collectByName` in src/vs/platform/agentHost/node/claude/customizations/scan/claudeAgentSkillScan.ts, which already has folder-bucketed data via `mapDiscoveredCustomizations` before the name collapse) to expose shadowed same-named customizations under a scoped alias (e.g. `folder-b:deploy`) or surface a diagnostic, and confirm the equivalent fix is needed in Codex's and Copilot's own scan/registry code since the same collapse reproduces independently in all three harnesses.
