# Issue #346438 — Awesome Copilot plugins are not discoverable in Customizations while GitHub Feed is enabled

[https://github.com/microsoft/vscode/issues/346438](https://github.com/microsoft/vscode/issues/346438)

## Summary

Keep open for a discovery-design decision: current source and explicit tests deliberately hide Awesome Copilot whenever GitHub Feed is enabled. Independently browsing its complete catalog while retaining the feed remains an unmet request, not an established duplicate.

## Change summary

Allow browsing and searching the full Awesome Copilot marketplace without disabling GitHub Feed.

## Best solution

Provide complete Awesome Copilot catalog discovery alongside GitHub Feed in Customizations, with coherent source selection and installation identity. Decide that discovery contract before changing the existing, explicitly tested source-suppression behavior.

## Evidence

- **Current suppression rule:** src/vs/workbench/contrib/chat/browser/aiCustomization/pluginCustomizationMarketplaceProvider.ts: isPluginMarketplaceAvailableInDiscover explicitly excludes github/awesome-copilot when Marketplace and GitHub Feed are enabled and the harness provides the feed.
- **Both discovery paths affected:** src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMarketplaceWorkbenchService.ts: getProviderMarketplaces applies that exclusion; getProviderMarketplaceSources and getService consume the filtered inventory. Consequently the marketplace is absent from both source selection and native marketplace queries, independently of whether it is already registered.
- **Intentional existing behavior:** src/vs/workbench/contrib/chat/test/browser/aiCustomization/customizationMarketplaceWorkbenchService.test.ts: 'filters provider Awesome Copilot sources and results when toggling the feed' explicitly expects Awesome Copilot sources and results to disappear with the feed enabled and return when disabled. This supports classifying simultaneous discovery as a behavior-change request rather than an accidental deviation from the current contract.
- **Existing capability does not cover the request:** src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMarketplaceConfiguration.ts registers chat.customizations.marketplace.sources.publicFeed.enabled with default true. Disabling it restores the native source, as the reporter confirmed, but sacrifices the feed; the inspected source-composition path offers no independent override preserving both.

Its description does not establish ownership of independently browsing the entire Awesome Copilot plugin catalog before installation. An open-issue search for Awesome Copilot and feed returned this report and that related item, not a clearer canonical.
