# Issue #346438 — Awesome Copilot plugins are not discoverable in Customizations while GitHub Feed is enabled

[https://github.com/microsoft/vscode/issues/346438](https://github.com/microsoft/vscode/issues/346438)

## Summary

Keep open: current source deliberately suppresses Awesome Copilot discovery when GitHub Feed is enabled, but that does not satisfy independent browsing of its complete catalog. Classify the requested coexistence as a feature request; the verified workaround sacrifices GitHub Feed, and the related migration issue does not own this exact symptom.

## Change summary

Allow browsing, searching, and installing Awesome Copilot marketplace plugins without disabling GitHub Feed.

## Best solution

Provide complete marketplace discovery alongside GitHub Feed in Customizations, retaining runtime installation and policy ownership. Settle the source-presentation contract without making catalog access depend on disabling recommendations.

- **Reporter path:** src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMarketplaceWorkbenchService.ts: getProviderMarketplaces applies that predicate to provider-owned marketplaces; sources and getService consequently omit both the selectable source and its queryMarketplace provider. This directly explains the reported source disappearance and restored access when the feed is disabled.
- **Intentional existing behavior:** src/vs/workbench/contrib/chat/test/browser/aiCustomization/customizationMarketplaceWorkbenchService.test.ts: 'filters provider Awesome Copilot sources and results when toggling the feed' explicitly expects Awesome Copilot sources and results to disappear with the feed enabled. The requested coexistence changes this established behavior rather than correcting an accidental filtering branch.
