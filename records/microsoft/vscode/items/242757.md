# Issue #242757 — "Find all" with "occurrences to exclude"

[https://github.com/microsoft/vscode/issues/242757](https://github.com/microsoft/vscode/issues/242757)

## Summary

Keep this accepted feature request open: current Search supports file exclusions and manual result dismissal, but neither provides the requested plain-text exclusion of matching lines. It has 25 upvotes and was promoted to Backlog; no verified older canonical was found.

## Change summary

Allow Find in Files results to exclude lines containing a specified word or phrase without requiring a regular expression.

## Best solution

Provide an accessible, discoverable way to exclude matching lines by their text while retaining other matches in the same file. Settle how that exclusion interacts with replacement before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/searchView.ts`, `src/vs/workbench/services/search/common/search.ts`, `src/vs/workbench/contrib/search/browser/searchActionsRemoveReplace.ts`
- **Validation:** Use a file containing separate lines maintenance, dev maintenance:, staging maintenance, and prod maintenance. Search for maintenance with prod as the exclusion: only the first three lines should appear, including when all four occur in the same file. Clearing the exclusion must restore the fourth match. Verify keyboard access and screen-reader labeling, unchanged file exclusions and regex search, and Replace All behavior against the agreed exclusion contract.
- **Behavior:**

  > Users can find text across files while excluding result lines containing another literal word or phrase, without writing regex. Searching for maintenance while excluding prod retains maintenance, dev maintenance:, and staging maintenance, but omits prod maintenance even when these lines share a file. Clearing the exclusion restores the ordinary result set. Existing file include/exclude controls retain their meaning.
- **Trace:**

  > In src/vs/workbench/contrib/search/browser/searchView.ts, the query-details UI creates file-glob include/exclude inputs, and the search-query construction passes a single positive IPatternInfo plus file patterns to queryBuilder.text. src/vs/workbench/services/search/common/search.ts defines that positive content-pattern contract without an independent negative-content criterion. RemoveAction in src/vs/workbench/contrib/search/browser/searchActionsRemoveReplace.ts manually dismisses selected results through batchRemove; it does not express a reusable content exclusion. These inspected paths establish the missing capability, not a completed implementation design. Preserve existing regex behavior and file-glob exclusions; do not reinterpret the files-to-exclude field as content text. The remaining product-contract question is whether exclusion changes the searchable/replacement match set or only its presentation.
- **Open decisions:**
  - Should the exclusion remove matching lines from the search-and-replace target set, including Replace All, or only hide them from the displayed results?
