# Issue #187627 — Realtime Performance icons always show up when the view is visible

[https://github.com/microsoft/vscode/issues/187627](https://github.com/microsoft/vscode/issues/187627)

## Summary

Keep open: expanded webview views still force their title actions visible without hover. Maintainers explicitly supported whole-view hover as the better outcome, so the intentional discoverability workaround does not settle this improvement.

## Change summary

Make Realtime Performance title actions reveal on whole-view hover or focus rather than remain visible whenever the webview view is expanded.

## Best solution

Give webview view headers the same hover/focus-driven action visibility as ordinary views, including when the pointer is over the webview content. Preserve keyboard access and the explicit always-show-header-actions setting without restoring the original discoverability problem.

- **Validation:** With workbench.view.alwaysShowHeaderActions=false, debug a Node project and expand Realtime Performance: actions should hide when neither hovered nor focused, remain visible while moving between its title and webview content, and remain keyboard-accessible. Repeat with the setting true to confirm actions remain visible, and check an ordinary tree view for unchanged behavior.
- **Behavior:**

  > Realtime Performance title actions remain visible at rest because it is a webview view. The desired behavior is consistent whole-view hover and focus visibility: hovering either the title or webview content reveals the actions, and moving between them does not hide the controls. Keyboard interaction must retain access to the actions. Enabling workbench.view.alwaysShowHeaderActions must continue to keep them visible.
- **Trace:**

  > WebviewViewPane in src/vs/workbench/contrib/webviewView/browser/webviewViewPane.ts explicitly requests ViewPaneShowActions.WhenExpanded; ViewPane.renderHeader and paneviewlet.css turn that into unconditional visibility for expanded panes. https://github.com/microsoft/vscode/pull/185864 introduced the original always-visible behavior to address https://github.com/microsoft/vscode/issues/109030; maintainers in https://github.com/microsoft/vscode/issues/187627 accepted whole-view hover as the preferable follow-up. The iframe is mounted through OverlayWebview outside the pane DOM subtree, so removing the expanded-visibility override alone risks restoring the original hover-discoverability problem. The remaining investigation is how to track hover across that overlay boundary and validate transitions without disrupting other shared webview consumers. Preserve existing keyboard/focus behavior and the explicit always-show setting; unrelated webview UI changes are outside scope.

It addressed https://github.com/microsoft/vscode/issues/109030, which is closed and describes actions disappearing when the pointer enters webview content. That change explains this report rather than fixing it.
- **Maintainer-supported remaining improvement:** In the supplied discussion for https://github.com/microsoft/vscode/issues/187627, alexr00 explains that always-visible actions improved discoverability but says showing them on hover of the whole view would be ideal. connor4312 agrees that exposing hover state from the webview would be preferable. - **Existing setting does not cover the request:** workbench.view.alwaysShowHeaderActions is registered with default false in src/vs/workbench/browser/workbench.contribution.ts:710-713. The shared IWebview contract in webview.ts exposes focus, blur and messages, but no dedicated hover event; ordinary pane hover alone therefore does not establish whole-view hover.
