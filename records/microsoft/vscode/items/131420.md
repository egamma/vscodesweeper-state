# Issue #131420 — Add context key for when comments are visible

[https://github.com/microsoft/vscode/issues/131420](https://github.com/microsoft/vscode/issues/131420)

## Summary

A comment visibility context key now exists, but it tracks expanded threads anywhere in the editor rather than comments in the viewport. Keep this open because the reporter's refined requirement—avoiding an Escape binding that activates when all comments are off-screen—remains uncovered.

## Change summary

Expose a viewport-sensitive comment visibility context key for conditional Escape keybindings.

## Best solution

Provide a context key that reflects whether expanded comments are visible in the editor viewport, allowing Escape to remain available to other features when no comments are on-screen. Preserve the existing editor-wide context key's semantics for current consumers.

- **Remaining viewport gap:** In current src/vs/workbench/contrib/comments/browser/commentsController.ts:765-768, _updateCommentWidgetVisibleContext sets commentWidgetVisible from this._commentWidgets.some(widget => widget.expanded), without checking viewport intersection.
