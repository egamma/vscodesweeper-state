# Issue #166340 — A code definition window like visual studio 

[https://github.com/microsoft/vscode/issues/166340](https://github.com/microsoft/vscode/issues/166340)

## Summary

Keep this accepted backlog request open: existing navigation commands do not provide a persistent, cursor-following definition window. It has 29 upvotes, and no verified open canonical or landed implementation was found.

## Change summary

Provide an independent definition preview that automatically follows the selected symbol, supports multiple definitions and full-file browsing, and opens selected locations in another editor group.

## Best solution

Resolve whether this should be an opt-in built-in navigation surface or an extension-delivered experience, then provide a persistent definition preview without changing ordinary Peek Definition behavior. Preserve this accepted request while that product boundary is decided.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts`, `src/vs/editor/contrib/gotoSymbol/browser/peek/referencesController.ts`, `src/vs/editor/contrib/gotoSymbol/browser/peek/referencesWidget.ts`, `extensions/references-view/package.json`
- **Validation:** With a language provider and a sample containing cross-file and multiple-definition symbols, move the cursor between symbols without invoking a command and verify the independent preview follows. Scroll the source without losing the preview, browse beyond the target definition in its file, inspect all returned definitions, double-click a preview location to open it in a second editor group, and navigate from a symbol inside the preview. Existing Peek Definition and Open Definition to the Side must remain unchanged.
- **Behavior:**

  > The requested preview automatically displays definitions when the user places the cursor on a symbol, without requiring a definition command or modifier-click. It remains outside the source editor's inline scrolling area and permits browsing the surrounding target file. Multiple definitions remain available, as clarified by the reporter. Double-clicking a preview location opens that file and location in a second editor group, while selecting another symbol within the preview navigates to its definition.
- **Trace:**

  > Definition navigation is registered in src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts through PeekDefinitionAction and OpenDefinitionToSideAction. ReferencesController.toggleWidget in peek/referencesController.ts creates ReferenceWidget against the invoking editor; referencesWidget.ts implements that preview as an embedded PeekViewWidget. The stablePeek and definitionLinkOpensInPeek settings adjust dismissal and gesture behavior, not placement or cursor-following. extensions/references-view/package.json supplies a separate result-tree surface, but its registrations do not deliver this automatic definition-preview workflow. No implementation or open canonical covering the full request was established. The maintainer's out-of-box concern in https://github.com/microsoft/vscode-cpptools/issues/10130#issuecomment-1317001469 predates the later acceptance of https://github.com/microsoft/vscode/issues/166340. Preserve current explicit navigation behavior and avoid making automatic definition requests part of the default editor experience without a product decision.
- **Open decisions:**
  - Should the persistent, cursor-following definition preview be an opt-in built-in VS Code surface or an extension-delivered capability?

## Evidence

- **Accepted community demand:** https://github.com/microsoft/vscode/issues/166340 has 29 community upvotes and the Backlog milestone. The November 24, 2022 comment records promotion after meeting the community threshold; the March 18, 2026 comment renews interest.
- **Existing commands only partially cover the request:** src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts registers editor.action.peekDefinition and editor.action.revealDefinitionAside. These provide explicitly invoked inline previews or side-editor navigation, not an independent preview that automatically follows cursor selection.
- **Peek remains editor-embedded:** ReferenceWidget in src/vs/editor/contrib/gotoSymbol/browser/peek/referencesWidget.ts extends PeekViewWidget and is documented as a zone widget inside the editor. ReferencesController.toggleWidget in peek/referencesController.ts creates it against the current editor and shows it at a range. editor.stablePeek only prevents closing on double-click or Escape; editor.definitionLinkOpensInPeek changes the definition mouse gesture, not the preview's placement or automatic activation.
- **Separate references view is not equivalent:** extensions/references-view/package.json contributes references.preferredLocation and explicitly invoked references, implementations, and hierarchy views. Its registered surface does not supply the requested cursor-following, full-file definition preview.
- **Earlier scope concern, followed by backlog acceptance:** In https://github.com/microsoft/vscode-cpptools/issues/10130#issuecomment-1317001469, a VS Code maintainer said this was not something wanted out of the box and directed development to https://github.com/microsoft/vscode/issues/166340. That statement predates this issue's November 24 backlog acceptance; it supports an opt-in-versus-extension decision, not a decline that overrides the later triage.
- **Canonical search:** Repository searches for code-definition windows, definition panels, automatic definitions, pinned Peek, and cursor-following or docked definitions found no verified open equivalent. https://github.com/microsoft/vscode/issues/54162 describes a similar window but is closed following a 2019 backlog cleanup, so it cannot be a duplicate canonical.
