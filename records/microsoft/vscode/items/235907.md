# Issue #235907 — No reset location action when moving SCM graph out of container and right clicking title header with default activity bar

[https://github.com/microsoft/vscode/issues/235907](https://github.com/microsoft/vscode/issues/235907)

## Summary

The missing action remains source-reproducible on current main: with the default Activity Bar, the title-header context menu bypasses the location actions that contain “Reset Location.” The older related issue was closed after explicitly identifying this as a separate remaining bug, so it is not a duplicate canonical.

## Change summary

A separately moved Source Control Graph view lacks a “Reset Location” action when its title header is right-clicked with the default Activity Bar layout.

## Best solution

Make the standalone moved view’s title-header menu expose the applicable location-reset action while preserving the existing distinction between view actions and unrelated container actions.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/paneCompositePart.ts`, `src/vs/workbench/browser/parts/paneCompositeBar.ts`
- **Validation:** In a development build with the Activity Bar in its default position, move Source Control Graph out of the Source Control container, right-click its title header, verify “Reset Location” is present, invoke it, and verify Graph returns to its default Source Control container without adding unrelated container actions to ordinary view-title menus.
- **Behavior:**

  > When a movable view such as Source Control Graph has been moved out of its default container, right-clicking its title header must offer “Reset Location” regardless of whether the Activity Bar is in its default or title-integrated position. Invoking the action must return the view to its default container and focus the restored surface. Existing context-menu actions for views that have not moved must remain unchanged.
- **Trace:**

  > The Source Control Graph is registered as movable in src/vs/workbench/contrib/scm/browser/scm.contribution.ts. In src/vs/workbench/browser/parts/paneCompositePart.ts, onTitleAreaContextMenu uses the composite-bar menu only when that bar is rendered in the title; otherwise it asks PaneComposite for view context actions. The location-aware actions, including “Reset Location,” are assembled separately by PaneCompositeBar.getContextMenuActionsForComposite() in src/vs/workbench/browser/parts/paneCompositeBar.ts, so the default-layout title path never receives them. Preserve the existing separation between view-specific actions and unrelated container controls; the reported boundary is the applicable location action for a moved standalone view. The earlier consistency work at https://github.com/microsoft/vscode/issues/233328 explicitly left https://github.com/microsoft/vscode/issues/235907 outstanding.
