# Issue #241858 — CDPATH suggestions do not work well with ZSH auto completion

[https://github.com/microsoft/vscode/issues/241858](https://github.com/microsoft/vscode/issues/241858)

## Summary

Keep open: current source still cannot resolve a trailing-slash relative cd argument through CDPATH. An open PR explicitly targets this defect, so the next step is reviewing that implementation rather than starting competing work.

## Change summary

After zsh completes a cd argument to a CDPATH folder name with a trailing slash, terminal suggestions should offer absolute paths within that folder rather than resolve it only against the current directory.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/314617 if it correctly handles CDPATH-resolved folders and preserves ordinary relative-path completion. Keep this issue open until the implementation merges and the reported zsh workflow is verified.

## Evidence

- **Confirmed remaining source defect:** In src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts:321–363, resolveResources treats `cd vscode-vsce/` as relative, stats URI.joinPath(cwd, normalizedFolder), and returns undefined when that folder does not exist under cwd. It never tries the matching CDPATH location before returning, so the reporter's trailing-slash input cannot produce the requested absolute-folder completions.
- **Existing CDPATH support does not cover the trigger:** The CDPATH block at src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts:548–592 enumerates immediate children of CDPATH entries, but runs after the failing cwd-relative resolution. `terminal.integrated.suggest.cdPath: "absolute"` changes labels in that later block; it does not resolve `vscode-vsce/` against CDPATH.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/314617 is currently OPEN with no merge commit. Its body explicitly says `Fixes #241858` and describes a fallback for relative cd arguments that fail cwd resolution, producing absolute completions under the matching CDPATH folder.
- **Discussion distinguishes two problems:** In https://github.com/microsoft/vscode/issues/241858, Tyriar separately identified unintended trigger-character activation and missing relative-path handling after a CDPATH folder. https://github.com/microsoft/vscode/issues/241588 is closed and concerns navigation-triggered suggestions; it does not own the remaining CDPATH resolution defect.
- **Workaround and changed defaults:** The reporter's `terminal.integrated.suggest.suggestOnTriggerCharacters: false` workaround suppresses automatic popup activation, not incorrect path resolution. That setting now defaults to false in src/vs/workbench/contrib/terminalContrib/suggest/common/terminalSuggestConfiguration.ts:124–128, while CDPATH mode defaults to absolute at lines 167–177; neither supplies the missing trailing-slash resolution.
