# Issue #204961 — Custom keybindings for scrolling notebook cell output into view and for scrolling inside the focussed cell output

[https://github.com/microsoft/vscode/issues/204961](https://github.com/microsoft/vscode/issues/204961)

## Summary

Keep open: existing commands focus output or center the whole cell, but do not fully cover output-specific reveal and rebindable scrolling within output. The related issues inspected do not establish an older canonical covering both requests.

## Change summary

Expose commands to reveal the active notebook cell's output and scroll within focused output using custom keybindings.

## Best solution

Provide notebook output navigation commands that users can bind without changing the active cell or interfering with editable renderer content. Coordinate the reveal experience with https://github.com/microsoft/vscode/issues/238214 while retaining this issue's distinct custom-keybinding requirement.

The plan should establish automated coverage for the agreed command and webview behavior.
- **Behavior:**

  > Users need keyboard-invocable navigation to the active cell's output even when a long input separates it from the viewport. They also need configurable keys to scroll within focused output rather than relying on mouse scrolling or fixed native arrow behavior. Acceptance should cover long cells, repeated reveal, directional scrolling, and preservation of ordinary text editing and renderer interactions. Behavior at the internal output's scroll boundary remains to be agreed.
- **Trace:**

  > In src/vs/workbench/contrib/notebook/browser/contrib/navigation/arrow.ts, notebook.cell.focusInOutput delegates to NotebookEditorWidget.focusNotebookCell, while notebook.centerActiveCell reveals the whole cell. The output branch in src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts sends focus through BackLayerWebView and reveals the cell if outside the viewport. In src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts, focusFirstFocusableOrContainerInOutput performs DOM focus, and native keyboard/wheel handlers operate within the webview; no dedicated directional output-scroll command was found in the inspected registrations. This establishes a capability gap, not a runtime-confirmed defect. Preserve existing cell navigation, default bindings, and editable renderer behavior. https://github.com/microsoft/vscode/issues/140148 concerns notebook paging, while https://github.com/microsoft/vscode/issues/238214 supplies related long-cell display context; neither absorbs this request.
- **Open decisions:**
