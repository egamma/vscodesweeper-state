# Issue #294976 — Remote index stuck on "checking status"

[https://github.com/microsoft/vscode/issues/294976](https://github.com/microsoft/vscode/issues/294976)

## Summary

Still reproduces on main: the ADO code search status endpoint can return HTML (e.g., an auth redirect page) with a 200 status, and the code calls `result.json()` without guarding against non-JSON content, causing a SyntaxError that leaves the repo state stuck at CheckingStatus. The 401/403 auth fix (commit 9e2a9e36812) improved HTTP error handling but did not address this 200-with-HTML scenario.

## Change summary

Remote workspace index stays stuck on 'Checking status' when the Azure DevOps endpoint returns HTML instead of JSON (likely an auth redirect with a 200 status).

## Best solution

Guard `result.json()` in `AdoCodeSearchService.getRemoteIndexStateImpl` (extensions/copilot/src/platform/remoteCodeSearch/common/adoCodeSearchService.ts) against non-JSON responses: check the Content-Type header before parsing, or wrap the `.json()` call in a try/catch and return a descriptive error (e.g. `not-authorized` or `generic-error` with a message noting the HTML response). Also transition the repo state to `CouldNotCheckIndexStatus` instead of leaving it at `CheckingStatus` so the UI reflects the failure.
