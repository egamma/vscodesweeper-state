## Change summary

## Evidence

- **Independent confirmation:** https://github.com/microsoft/vscode/issues/250296 reports both sidebars becoming narrow after display inactivity on Windows 11 with VS Code 1.100.2. The May 1, 2026 comment by fehbari independently confirms the same behavior after PC sleep; the September 24, 2025 comment additionally describes widths reverting to approximately 300 pixels when switching display setups.
- **Current layout path:** src/vs/workbench/browser/layout.ts constructs the workbench grid with proportionalLayout: false. Layout.layout(), around lines 1753–1770, reads the current client dimensions and passes them to workbenchGrid.layout().
- **Plausible mechanism, not a confirmed current reproduction:** src/vs/base/browser/ui/splitview/splitview.ts:841–878 redistributes a size delta from current view sizes when proportions are absent. resize() clamps those sizes, and distributeEmptySpace() allocates subsequent space by priority. SidebarPart and AuxiliaryBarPart have Low layout priority, while EditorPart has High priority. This can explain sidebars remaining narrow after a constrained layout, but source inspection does not establish which dimensions Windows reports during the supplied sleep/display-off trigger.
- **Nearby fix does not establish resolution:** https://github.com/microsoft/vscode/commit/8ef958807693b22e3c83a9f2ace226e8ca995c28 fixes a different trigger: toggling a right-positioned primary sidebar under Modern UI while activity-bar visibility changes. Its onViewChange redistribution change does not establish that display-off or sleep-induced width loss is fixed.
- **Older related request is not a verified duplicate canonical:** https://github.com/microsoft/vscode/issues/208658 is open and older. It describes widths collapsing during monitor/resolution changes, but requests responsive layouts, layout saving, or layout APIs; its discussion does not establish ownership of this Windows sleep/display-off defect. It is related evidence, not a sufficiently verified canonical for this re-reviewed report.
- **Width customization is separate:** https://github.com/microsoft/vscode/issues/158603 is open and concerns configurable, view-specific sidebar widths. That overlaps the setting suggested in later comments, but does not absorb the original report of existing widths being lost after display inactivity.
