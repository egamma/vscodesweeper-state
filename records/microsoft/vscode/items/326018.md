# Issue #326018 — Settings schema shows valid color customization properties as invalid

[https://github.com/microsoft/vscode/issues/326018](https://github.com/microsoft/vscode/issues/326018)

## Summary

Reporter gives a precise, minimal repro (theme-scoped `workbench.colorCustomizations` entry flagged invalid in settings.json on a recent Insiders build) with a screenshot, and a second commenter says others are seeing it too — this needs a themes-area maintainer to confirm against the current build; I traced the schema wiring in themeConfiguration.ts/colorThemeData.ts and it looks like it should permit the reported key, so the regression (if real) is likely subtle.

## Change summary

settings.json marks a theme-scoped color customization property (e.g. `"[Dark+]": { "activityBarBadge.background": ... }` under `workbench.colorCustomizations`) as schema-invalid even though it matches a real, registered theme and color id.

## Best solution

A themes-area maintainer should reproduce on a current Insiders build against `updateColorThemeConfigurationSchemas` in src/vs/workbench/services/themes/common/themeConfiguration.ts (the function that rebuilds the `workbench.colorCustomizations` allOf/patternProperties schema per installed theme) to see whether the theme-specific schema is failing to register or refresh for this theme, or whether the JSON validator is misapplying the nested `additionalProperties: false` under `[Dark+]`.
