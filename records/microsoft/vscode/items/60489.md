# Issue #60489 — [html] proper support of XHTML

[https://github.com/microsoft/vscode/issues/60489](https://github.com/microsoft/vscode/issues/60489)

## Summary

Proper XHTML parsing remains a real gap, but an exact later request was explicitly closed as an extension candidate. Current main still treats `.xhtml` as HTML, so the established outcome is to provide dedicated XHTML semantics through an extension rather than expand the built-in HTML mode.

## Change summary

Add XML-compliant XHTML parsing so self-closing elements, explicit closing tags, and quoted attribute requirements are handled correctly.

## Best solution

Provide a dedicated XHTML language mode through an extension, combining XML parsing rules with the relevant HTML authoring features instead of changing HTML parsing semantics in core.

## Vision fit

- **Fit:** rejected
- **Reason:** A specialized XHTML language mode can be delivered through the extension system without adding niche parsing behavior to the default editor.
- **Evidence:** Values and guardrails: “The power lives in extensions” and “Out of the box, VS Code is a text editor: lightweight and fast.”
