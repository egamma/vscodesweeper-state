Invalid configuration, unsupported targets, and file conflicts remain explicit errors; standalone MCP servers and other plugin providers retain existing behavior.
- **Trace:**

  > The merged persistence groundwork is documented at https://github.com/microsoft/vscode/pull/347318 and explicitly leaves the full migration to https://github.com/microsoft/vscode/issues/347317. CopilotAgent.setPluginEnabled already handles global/repository mutations and refresh, while CopilotCliAgentPluginDiscovery in agentPluginServiceImpl.ts still supplies a global-only callback and a workbench enablement default. agentPluginActions.ts still constructs Session actions and sends host-owned decisions through setCustomizationEnablement. resolveCustomizationEnablement in shared/customizationEnablementGate.ts still applies host decisions to plugin publication. The remaining uncertainty is the complete ownership and refresh path across Copilot discovery, UI consumers, and remote management; these consumers were not exhaustively traced. Preserve genuinely client-owned plugins, other providers, standalone MCP semantics, and existing persistence error handling.
