# Issue #127113 — Command to change the state of a markdown cell

[https://github.com/microsoft/vscode/issues/127113](https://github.com/microsoft/vscode/issues/127113)

## Summary

Keep open: existing commands change Markdown cells between editing and preview, but the notebook extension API does not expose the corresponding state changes needed for Live Share synchronization. The Backlog milestone records accepted work; the earlier community-process closures do not establish that this capability was delivered.

## Change summary

Expose Markdown cell editing/preview state transitions so Live Share can synchronize presentation state as well as text.

## Best solution

Provide an extension-facing contract for observing a Markdown cell's editing/preview state and applying the corresponding state to the intended notebook editor. Existing edit commands cover only part of this request; the remaining work belongs in the notebook editor API bridge.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/browser/mainThreadNotebookEditors.ts`, `src/vs/workbench/api/common/extHostNotebookEditors.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHost.api.impl.ts`, `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`
- **Validation:** Using a notebook and an extension consumer, click the Markdown pencil and checkmark and verify each transition is observable with the correct editor, cell, and state. Apply the corresponding transition in a second notebook editor and verify presentation changes without modifying cell text, losing focus unexpectedly, or creating a synchronization loop.
- **Behavior:**

  > Live Share currently synchronizes Markdown cell text but cannot reliably synchronize whether the cell is being edited or rendered. An extension must be able to observe both pencil and checkmark transitions and apply the corresponding presentation state to the intended peer editor. Acceptance should cover both directions, unchanged cell contents, and isolation between editors displaying the same notebook.
- **Trace:**

  > The checkout's markupCell.ts consumes an internal editStateChanged signal, while notebookBrowser.ts declares notebook.cell.quitEdit. Current main's editActions.ts implements notebook.cell.edit through focusNotebookCell and notebook.cell.quitEdit through updateEditState(CellEditState.Preview). MainThreadNotebookEditors.handleEditorsAdded forwards selection and visible-range events, but the inspected stable NotebookEditor API and proposed notebookLiveShare declarations expose no editing-state notification. The remaining uncertainty is the extension-facing contract and its editor-targeting semantics, not whether edit commands exist. Keep text synchronization and notebook execution semantics unchanged; https://github.com/microsoft/vscode/issues/121313 concerns execution and is not a canonical for this work.
- **Open decisions:**
  - Should Markdown editing state be exposed as a general notebook-editor API available to extensions or as a narrower collaboration-oriented contract?
  - Should programmatically applying a peer's state preserve the recipient's current focus and selection, or reproduce the focus changes of the existing interactive edit commands?
