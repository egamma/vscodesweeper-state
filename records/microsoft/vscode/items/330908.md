# Issue #330908 — Extension command titles lose localization after installing/updating an extension until full restart (VS Code 1.133)

[https://github.com/microsoft/vscode/issues/330908](https://github.com/microsoft/vscode/issues/330908)

## Summary

Traced conclusively in the source: the extension-scan path used for install/update (`scanUserExtensionAtLocation`/`scanLocalExtension` in the node extension management service) never forwards a `language` to `IExtensionsScannerService.scanExistingExtension`, so `findMessageBundles` in `extensionsScannerService.ts` falls back to the unlocalized `package.nls.json` for that extension until a full app restart re-scans everything with the correct locale.

## Change summary

Extension command titles lose localization for a just-installed/updated extension until VS Code is fully restarted, because the incremental scan omits the active display language.

## Best solution

Plumb the active display language into the install/update scan path in src/vs/platform/extensionManagement/node/extensionManagementService.ts (scanUserExtensionAtLocation → ExtensionsScanner.scanUserExtensionAtLocation → scanExistingExtension) so the ScanOptions.language is populated the same way scanExtensions() already does at line ~573, instead of leaving it undefined.

## Evidence

- **missing language on install/update scan:** src/vs/platform/extensionManagement/node/extensionManagementService.ts line 608-609 (`scanUserExtensionAtLocation`) and line 868-878 (`scanLocalExtension`) call `this.extensionsScannerService.scanExistingExtension(location, type, { includeInvalid: true })` with no `language` key, unlike the full scan at line 570-578 which explicitly threads `language` through `UserExtensionsScanOptions`/`scanAllExtensions`.
- **caller confirmation:** scanUserExtensionAtLocation/scanLocalExtension are invoked from the install/extract/update flow (lines 142, 178, 500, 628, 696, 716, 768-799, 1171 of the same file), i.e. exactly the incremental-rescan path the reporter describes, while full profile scans (used at startup and on profile switch) go through scanUserExtensions with a language, matching why a full restart or profile switch restores localization.
