# Issue #259112 — Auto-update to host architecture when running under emulation

[https://github.com/microsoft/vscode/issues/259112](https://github.com/microsoft/vscode/issues/259112)

## Summary

Keep open: current macOS updates still select the installed process architecture, so an Intel installation migrated to Apple silicon does not automatically become native. The existing emulation warning requires a manual download, and the related issues do not qualify as duplicate canonicals.

## Change summary

Automatically migrate an emulated Intel macOS installation to the native Apple silicon build through updates.

## Best solution

Make the macOS update flow migrate translated Intel installations to native ARM64 while preserving existing update controls and successful installation/relaunch behavior. Coordinate with the related universal-build update work without treating that different starting configuration as a replacement for this report.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`
- **Validation:** On Apple silicon, update an older signed Intel-only build running under Rosetta and confirm the installed application relaunches natively as ARM64 with user data intact. Check that native Intel and ARM64 installations retain their respective feeds, universal-build behavior remains unchanged for this scope, and disabled updates remain disabled; add focused feed-selection coverage for these cases.
- **Behavior:**

  > An Intel-only VS Code installation copied from an Intel Mac to Apple silicon should transition to the native ARM64 build through its normal update flow rather than remain under emulation indefinitely. Acceptance requires completing the update and relaunching natively, not merely producing an ARM64 download URL. Existing update controls and user data must remain respected, and native installations must continue receiving appropriate updates.
- **Trace:**

  > DarwinUpdateService.buildUpdateFeedUrl in src/vs/platform/update/electron-main/updateService.darwin.ts selects the universal asset override or process.arch, so translated Intel processes continue requesting the Intel feed. doCheckForUpdates and doDownloadUpdate use that selection with Electron autoUpdater; createUpdateURL in src/vs/platform/update/electron-main/abstractUpdateService.ts includes the current commit in the request. Existing app.runningUnderARM64Translation detection in src/vs/code/electron-main/app.ts only triggers a manual-download warning. Source inspection establishes the missing selection behavior but does not establish whether the complete signed cross-architecture replacement and relaunch succeeds or how the service handles architecture changes at the same commit. Investigate those boundaries before treating feed selection as sufficient; preserve universal-build behavior and other platforms for this issue. Related universal-to-native work remains separately tracked at https://github.com/microsoft/vscode/issues/295548 and https://github.com/microsoft/vscode/issues/295579.
