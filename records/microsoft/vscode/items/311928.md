# Issue #311928 — Settings UI shows undefined for default values in nested configuration keys

[https://github.com/microsoft/vscode/issues/311928](https://github.com/microsoft/vscode/issues/311928)

## Summary

The supplied example still loses the child setting's default in current source: configuration registration accepts both keys, but the value tree cannot store a child beneath a string-valued parent. Keep this open for configuration-model review; this affects runtime reads as well as Settings UI.

## Change summary

Settings with a scalar-valued key and a dotted descendant produce missing defaults and inconsistent runtime values.

## Best solution

Resolve the mismatch between accepted configuration declarations and runtime representation, rather than masking undefined values in Settings UI. Configuration owners should settle whether overlapping scalar and descendant keys are supported or explicitly rejected, including compatibility with existing extension settings.
