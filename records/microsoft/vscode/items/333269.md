## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/241730 is open and was created on 2025-02-24, before this report. An extension author explicitly asks how to track API finalization at https://github.com/microsoft/vscode/issues/241730#issuecomment-3542857258; a maintainer responds at https://github.com/microsoft/vscode/issues/241730#issuecomment-3570471457: "I think we can track this on this issue. When this issue is closed we will have finalized the API." This covers the same observable limitation: extension authors cannot yet adopt a finalized expandable-hover API.
- **Capability exists only as a proposed contract:** Current src/vscode-dts/vscode.proposed.editorHoverVerbosityLevel.d.ts declares VerboseHover, HoverContext, and the contextual HoverProvider signature. These declarations are absent from src/vscode-dts/vscode.d.ts, whose HoverProvider still exposes the three-argument provideHover signature. src/vs/platform/extensions/common/extensionsApiProposals.ts continues to register editorHoverVerbosityLevel as a proposal.
- **Existing TypeScript support does not satisfy finalization:** extensions/typescript-language-features/package.json opts into editorHoverVerbosityLevel, and extensions/typescript-language-features/src/languageFeatures/hover.ts uses VerboseHover and verbosityDelta. This confirms the reporter's distinction between an existing built-in implementation and a stable API available for general extension adoption.
- **Other related issues have different roles:** https://github.com/microsoft/vscode/issues/210904 is a closed test-plan item for the original proposed API, and https://github.com/microsoft/vscode/issues/195394 is the closed original capability request. The open https://github.com/microsoft/vscode/issues/232685 concerns TypeScript expandable-hover testing and iteration; the explicit finalization commitment is instead on https://github.com/microsoft/vscode/issues/241730.
