# Issue #333269 — Finalize editorHoverVerbosityLevel so other extensions can offer verbose hovers

[https://github.com/microsoft/vscode/issues/333269](https://github.com/microsoft/vscode/issues/333269)

## Summary

The stable extension API still lacks hover verbosity support, so the requested finalization remains necessary. Existing hover commands and TypeScript's proposed-API access do not provide a supported public contract for other extensions.

## Change summary

Finalize the hover verbosity API so third-party extensions can publish expandable and collapsible hovers using stable VS Code APIs.

## Best solution

Have the API owners settle and finalize the public hover verbosity contract in src/vscode-dts/vscode.d.ts, preserving existing hover providers and the editor's expansion controls. Reconcile the earlier API revision work before promoting the proposal.

- **Still proposed:** src/vscode-dts/vscode.proposed.editorHoverVerbosityLevel.d.ts still contains VerboseHover, canIncreaseVerbosity, canDecreaseVerbosity, HoverContext.verbosityDelta, previousHover, and the extended provideHover signature. Runtime implementation is not equivalent to API finalization.
- **Existing capability checked:** extensions/typescript-language-features/package.json explicitly enables editorHoverVerbosityLevel. src/vs/editor/contrib/hover/browser/hoverActionIds.ts defines editor.action.increaseHoverVerbosityLevel and editor.action.decreaseHoverVerbosityLevel, but those user commands do not supply a stable extension-provider contract.

The remaining request concerns supported public API access, not implementing hover expansion from scratch.
