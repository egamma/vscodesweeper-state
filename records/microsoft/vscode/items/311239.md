# Issue #311239 — GitHub copilot Chat makes a helper renderer eating memory all the way up till crash

[https://github.com/microsoft/vscode/issues/311239](https://github.com/microsoft/vscode/issues/311239)

## Summary

This is a confirmed Copilot Chat memory leak in large Remote-SSH workspaces that eventually crashes the renderer. It remains reproducible in newer releases and should be routed to the Chat and memory-leak owners.

## Change summary

Prevent Copilot Chat initialization or workspace indexing from consuming unbounded renderer memory in large Remote-SSH workspaces.

## Best solution

Profile Copilot Chat startup against a representative large Remote-SSH workspace, including the workspace-index database fallback, then bound or release the retained indexing/session data before it reaches the renderer heap limit.

## Evidence

- **independent confirmations:** Two additional users confirmed the same failure, including Ubuntu under WSL, while the reporter correlated memory growth with remote workspace size.
- **current reproduction cluster:** https://github.com/microsoft/vscode/issues/324809 reproduces the same idle Remote-SSH renderer OOM on VS Code 1.127.0, measures sustained memory growth, and confirms that disabling Copilot Chat stops it.
- **additional diagnostics:** https://github.com/microsoft/vscode/issues/313762 reports the same idle Remote-SSH renderer OOM on 1.118.1 and supplied a crash dump and CPU trace.
- **source correlation:** extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts:170-182 opens the workspace index database and falls back to an in-memory SQLite database on failure, matching the reported log; the available evidence does not yet prove this is the leak's root cause.
