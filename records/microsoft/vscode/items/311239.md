# Issue #311239 — GitHub copilot Chat makes a helper renderer eating memory all the way up till crash

[https://github.com/microsoft/vscode/issues/311239](https://github.com/microsoft/vscode/issues/311239)

## Summary

Keep open as a confirmed renderer-memory crash in AI-enabled remote workspaces. Independent reports reproduce the same failure, and current source still contains a workspace-indexing path matching the reported database fallback and workspace-size sensitivity.

## Change summary

Enabling Copilot Chat in a large Remote-SSH workspace causes renderer memory to grow by multiple gigabytes until the window crashes.

## Best solution

Diagnose and bound Copilot workspace-indexing memory use in remote workspaces, particularly when the persistent SQLite database cannot be opened and indexing falls back to memory. Validate with a large Remote-SSH workspace and renderer/extension-host memory profiles before and after the correction.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts`, `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/codeSearchChunkSearch.ts`, `extensions/copilot/src/platform/workspaceChunkSearch/test/node/externalIngest.spec.ts`
- **Validation:** Open a large Remote-SSH workspace with Copilot Chat enabled and an unavailable Copilot index storage path, sample renderer and extension-host memory through initialization for at least 15 minutes, and verify memory remains bounded and the window does not crash; repeat with AI disabled as the control.
- **Behavior:**

  > An AI-enabled Remote-SSH window must remain stable while Copilot initializes workspace search, including for workspaces containing many files. Failure to open the persistent indexing database must not cause unbounded renderer or extension-host memory growth. Acceptance requires bounded memory and no renderer crash during a sustained large-workspace reproduction, while preserving codebase search behavior.
- **Trace:**

  > The issue records rapid renderer growth only in AI-enabled remote windows, with severity correlated to workspace size and an exact `Failed to create database. Falling back to in-memory db` log. ExternalIngestIndex in extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts currently takes that fallback and its reconcileDbFiles method materializes every `**/*` search result before filtering and recording candidates. Independent reports at https://github.com/microsoft/vscode/issues/312925 and https://github.com/microsoft/vscode/issues/324809 corroborate the Remote-SSH indexing/OOM path, but neither establishes whether the retained allocation is the URI result set, SQLite state, indexing payloads, or renderer-side chat state. Profile both the local renderer and remote extension host before narrowing the change. Do not alter normal chat rendering, non-remote indexing semantics, or exclusion behavior without evidence that those paths participate.

## Evidence

- **independent confirmations:** Two commenters on https://github.com/microsoft/vscode/issues/311239 independently report the same AI-enabled crash behavior, including one reproduction under WSL; the reporter also established that growth scales with remote workspace size.
- **matching later reproduction:** https://github.com/microsoft/vscode/issues/312925 reports the same Remote-SSH, Copilot codebase-indexing, renderer code-5 crash on Apple Silicon. It is newer than this re-reviewed issue and therefore cannot serve as its duplicate canonical.
- **current-version corroboration:** https://github.com/microsoft/vscode/issues/324809 documents later Remote-SSH renderer OOM reproductions and an A/B result where `chat.disableAIFeatures: true` kept memory stable and prevented crashes.
- **source trace:** extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts emits the report's exact `Failed to create database. Falling back to in-memory db` message and replaces the persistent SQLite database with `:memory:`.
- **workspace-size path:** ExternalIngestIndex.reconcileDbFiles in extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts requests `**/*` with `Number.MAX_SAFE_INTEGER`, retains the returned URI array while processing it, and records candidates in SQLite. This matches the reported dependence on workspace file count, although it does not by itself identify the allocation responsible for the renderer crash.
- **canonical search:** The older https://github.com/microsoft/vscode/issues/303387 concerns renderer OOM while rendering a large active chat response, and https://github.com/microsoft/vscode/issues/294050 concerns extension-host resets. Neither reports the same idle Remote-SSH initialization/indexing symptom required for a duplicate close on this re-reviewed item.
