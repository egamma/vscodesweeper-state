# Issue #244876 — Update status-bar item icon & text spacing to not use spaces (" ")

[https://github.com/microsoft/vscode/issues/244876](https://github.com/microsoft/vscode/issues/244876)

## Summary

Keep open: current status-bar rendering still uses text whitespace for icon-to-text separation; existing spacing tokens control other dimensions, not this gap. The maintainer endorsed the tokenization direction, and the linked broader effort is now closed without establishing completion of this request.

## Change summary

Control status-bar icon-to-text spacing through a CSS variable rather than space characters embedded in labels.

## Best solution

Give status-bar icon-to-text separation a consistent, token-controlled layout treatment. Establish compatibility expectations for extension-authored labels before changing how existing whitespace is displayed.

## Plan brief

- **Validation:** Extend the StatusbarEntryItem browser suite to cover icon-plus-text, multiple icon/count groups, text-only labels and progress labels under the chosen compatibility contract. In a rendered workbench, vary the spacing token and verify that icon-to-text separation changes without duplicate whitespace gaps; check existing extension labels and both standard and modern UI.
- **Behavior:**

  > Status-bar icon-to-text separation should be controlled consistently by a CSS spacing variable rather than requiring literal separator spaces in label text. Changing that variable should change the rendered separation for supported label shapes, including progress labels. Text content, accessible names and activation behavior must remain intact. Acceptance must cover existing extension-authored labels as well as built-in labels, with their whitespace compatibility behavior agreed before implementation.
- **Trace:**

  > StatusbarEntryItem.update in src/vs/workbench/browser/parts/statusbar/statusbarItem.ts forwards entry.text to StatusBarCodiconLabel. Ordinary labels pass through SimpleIconLabel and renderLabelWithIcons, which preserve surrounding text substrings; the progress branch explicitly inserts a non-breaking space. statusbarpart.css retains whitespace with white-space: pre, while modernUI/browser/media/statusBar.css tokenizes outer spacing but not icon-to-text separation. Problems labels in markers.contribution.ts provide a concrete multiple-icon/count case with literal separator spaces. StatusBarItem.text in src/vscode-dts/vscode.d.ts exposes mixed icon/text strings to extensions, so the uncertainty is the observable treatment of existing separator whitespace, not whether tokens are desirable. Preserve unrelated SimpleIconLabel consumers, text-only spacing, ARIA labels, commands and progress-animation stability. The maintainer endorsed the broader tokenization direction at https://github.com/microsoft/vscode/issues/244876#issuecomment-3027148515, but https://github.com/microsoft/vscode/issues/248725 is closed and its font-token successor does not complete this work.
- **Open decisions:**
  - Should token-controlled separation apply automatically to existing extension-authored icon/text strings, replacing their adjacent separator whitespace, or should legacy strings retain their current rendering while a distinct supported representation receives token-controlled spacing?

## Evidence
