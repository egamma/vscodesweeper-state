# Issue #74094 — TextEditorDecoration applied to incorrect range if racing with user edits

[https://github.com/microsoft/vscode/issues/74094](https://github.com/microsoft/vscode/issues/74094)

## Summary

The race condition between setDecorations and user edits is still present on main — no version checking is performed when applying decorations, unlike applyEdit which does check. An open PR (#172672) exists but has not been merged. Keeping open as the issue remains valid with 32 upvotes.

## Change summary

TextEditorDecoration ranges are applied without accounting for concurrent edits, causing decorations to land on the wrong text.

## Best solution

Land a version-aware decoration path: either merge and refine the approach in the open PR (https://github.com/microsoft/vscode/pull/172672) — which adds version checking similar to `applyEdit` — or implement an equivalent mechanism in `extHostTextEditor.ts` and `mainThreadEditor.ts` that rejects or adjusts decoration ranges when the document version has advanced. The open PR is a concrete starting point for that conversation.
