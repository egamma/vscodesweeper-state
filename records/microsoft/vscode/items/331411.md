# Issue #331411 — Codex harness does not load Codex-style instructions or MCP servers from all workspace roots

[https://github.com/microsoft/vscode/issues/331411](https://github.com/microsoft/vscode/issues/331411)

## Summary

Fresh, team-authored bug report (following up on a multi-root Codex test) describing Codex not loading AGENTS.md instructions or `.codex/config.toml` MCP servers for non-primary workspace roots; a second contributor confirmed the underlying problem also affects single-folder workspaces, so this is a real, reproduced defect that needs area-owner triage rather than a close.

## Change summary

In a multi-root workspace, only the first workspace root's Codex-style AGENTS.md instructions and `.codex/config.toml` MCP servers are loaded by the Codex harness; secondary roots' instructions/MCP servers are missing, and a commenter reports the same gap even for single-folder workspaces.

## Best solution

Have the agent-host/codex owners investigate why per-root AGENTS.md/`.codex/config.toml` discovery only covers `workingDirectories[0]` (see `buildCodexResumeParams` in src/vs/platform/agentHost/node/codex/codexLaunchConfig.ts, which sets `cwd` from index 0 and forwards `runtimeWorkspaceRoots` but leaves per-root instruction/MCP loading to the codex-rs binary) and confirm whether the fix belongs in how VS Code invokes codex per root or in codex's own multi-root handling; the single-folder regression noted in the comment suggests something is broken even in the primary-root path and should be reproduced first.
