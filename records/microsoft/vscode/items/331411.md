# Issue #331411 — Codex harness does not load Codex-style instructions or MCP servers from all workspace roots

[https://github.com/microsoft/vscode/issues/331411](https://github.com/microsoft/vscode/issues/331411)

## Summary

Keep open as an upstream Codex customization-discovery gap. Current VS Code passes all runtime workspace roots, but Codex still derives native project instructions and `.codex/config.toml` behavior from its primary working directory; the broader multi-root tracker does not fully absorb this report's native MCP and single-folder evidence under the stronger re-review duplicate bar.

## Change summary

Make Codex sessions load native `AGENTS.md` instructions and `.codex/config.toml` MCP servers from every applicable workspace root.

## Best solution

Add Codex app-server support for discovering native instructions and project configuration across explicit customization roots on start, resume, and fork, while retaining the primary `cwd`; then validate that VS Code passes those roots consistently and exposes each root's native MCP servers.

## Evidence

- **upstream limitation:** https://github.com/openai/codex/issues/38372 provides a standalone app-server reproduction showing that `runtimeWorkspaceRoots` records both roots while native `AGENTS.md` discovery uses only the primary `cwd`; the upstream issue remains open.
- **current source:** src/vs/platform/agentHost/node/codex/codexAgent.ts passes all session roots through `runtimeWorkspaceRoots` at `thread/start`, while src/vs/platform/agentHost/node/codex/codexCustomizations.ts states that its `AGENTS.md` scan only projects provider-loaded instructions into AHP state rather than applying them.
- **native MCP boundary:** src/vs/platform/agentHost/node/shared/sessionMcpDiscovery.ts scans every root only for `.mcp.json`; it does not parse project `.codex/config.toml`. Native Codex configuration therefore remains provider-owned.
- **related tracker:** https://github.com/microsoft/vscode/issues/321651 is older and tracks general multi-root harness support, including the same secondary-root `AGENTS.md` failure, but its checklist separately confirms generic `.mcp.json` discovery and does not establish coverage of this report's native `.codex/config.toml` and single-folder observations.
- **later partial change:** Commit 56e3866850f841bf51599b0d1c697bc21a704203 added workspace instruction projection and Codex E2E coverage after this report, but neither the commit nor its PR https://github.com/microsoft/vscode/pull/332932 references https://github.com/microsoft/vscode/issues/331411, and it does not make the host apply native secondary-root instructions.
- **confirmed report:** A VS Code team member confirmed in https://github.com/microsoft/vscode/issues/331411 that the failure was also observed with a single folder, so the report contains evidence beyond the broader multi-root symptom.
