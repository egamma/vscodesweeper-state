# Issue #119811 — when clause contexts for emmet editing

[https://github.com/microsoft/vscode/issues/119811](https://github.com/microsoft/vscode/issues/119811)

## Summary

The requested cursor-sensitive Emmet context is still missing. An older open request covers exposing the embedded language, but does not fully cover an Emmet-applicability context that reflects language mappings; retain this accepted Backlog request under discussion.

## Change summary

Expose a when-clause context that lets Emmet editing shortcuts override standard commands only where Emmet applies, including embedded-language regions and configured language mappings.

## Best solution

Define an Emmet-applicability context for conditional editing shortcuts, coordinating with the embedded-language context work without changing editorLangId's document-level meaning. Settle how configured mappings and embedded regions determine applicability before implementation.

## Evidence

- **Existing capability does not cover the request:** src/vs/editor/common/editorContextKeys.ts defines editorLangId as the editor's language identifier; src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts sets its value from model.getLanguageId(), not the embedded language at the cursor.
- **Emmet configuration and activation:** extensions/emmet/package.json registers emmet.includeLanguages, emmet.excludeLanguages and emmet.triggerExpansionOnTab, but none exposes cursor-sensitive applicability for arbitrary Emmet editing shortcuts. extensions/emmet/src/emmetCommon.ts registers the editing commands and completion providers without publishing an Emmet context through setContext.
- **Mapping is a distinct requirement:** extensions/emmet/src/util.ts implements getMappingForIncludedLanguages() and getEmmetMode(), including configured mappings and exclusions. These determine Emmet support separately from a raw embedded-language identifier; the issue explicitly asks for applicability reflecting emmet.includeLanguages.
- **Older related request verified:** https://github.com/microsoft/vscode/issues/107989 is open, was created on 2020-10-02, and requests a language-at-cursor context for embedded-language keybindings. Its body and discussion overlap the generic alternative in this report, but do not establish ownership of the full Emmet-specific mapping/applicability contract, so it does not clear the re-review duplicate bar.
