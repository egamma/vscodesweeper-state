# Issue #263408 — Git - Differentiate between submodules and normal repos on virtual drives (Winows)

[https://github.com/microsoft/vscode/issues/263408](https://github.com/microsoft/vscode/issues/263408)

## Summary

Real bug: on Windows virtual/mapped drives, `git rev-parse --show-superproject-working-tree` returns the physical path, but the parent repository lookup in `repository.ts` compares against the virtual drive path — so the parent is never found and submodules appear flat instead of nested. The issue is still present on main.

## Change summary

Submodules are not shown as children of their parent repository in the Source Control view when working from a Windows virtual/mapped drive.

## Best solution

The parent resolution at `extensions/git/src/repository.ts:960-961` should normalize `superProjectPath` via realpath comparison (similar to how `Model.getRepositoryExact` already resolves real paths at model.ts:944-947) so the parent repository is found even when the opened path and the git-reported path differ due to drive mapping.
