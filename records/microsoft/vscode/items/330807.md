# Issue #330807 — Copilot chat overview shows number of lines added/removed when there is none

[https://github.com/microsoft/vscode/issues/330807](https://github.com/microsoft/vscode/issues/330807)

## Summary

Real, independently-confirmed bug (two reporters, Windows and macOS): the sessions overview keeps showing a stale +N/-M change chip for a session after all edits were kept, even though opening that session shows no pending changes. Tracing the client code shows this is architecturally plausible — a background session's chip is only cleared when the agent host explicitly sends an updated `changes` aggregate in a delta, and the client intentionally treats an absent field as "not included" rather than "cleared" to avoid clobbering the chip on partial snapshots.

## Change summary

The chat/agent sessions overview list shows a lingering lines-added/removed change count for a session whose edits have already been kept, and the count doesn't clear until the session is reopened (and sometimes not even then from the overview).

## Best solution

Needs a maintainer/agent-host owner to confirm whether the host omits the `changes` delta field when a background session's outstanding edits are fully kept (rather than sending an explicit zero-aggregate), and if so have it always emit the updated aggregate on keep/discard so `setChangesSummary` (or the `changes.changes !== undefined` guard at baseAgentHostSessionsProvider.ts:1396/5450) actually clears stale chips.
