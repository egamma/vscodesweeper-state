# Issue #330807 — Copilot chat overview shows number of lines added/removed when there is none

[https://github.com/microsoft/vscode/issues/330807](https://github.com/microsoft/vscode/issues/330807)

## Summary

Traced a real discrepancy in the Agent Sessions overview's diff-stat computation vs. its pending-edit indicator, which plausibly explains the report, but the fix requires a maintainer decision on intended semantics, so routing to the area rather than closing or auto-fixing.

## Change summary

The multi-chat-sessions overview list keeps showing a non-zero lines added/removed count for a chat session even after all edits in that session were reviewed and kept, while the session's own file-changes view correctly shows nothing pending.

## Best solution

Decide in src/vs/workbench/contrib/chat/common/chat.ts (awaitStatsForSession) and src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts (getSessionMetadataSync) whether the overview's insertions/deletions badge should reflect only pending (unkept) edits — mirroring hasPendingEdits' filter on ModifiedFileEntryState.Modified — or remain a lifetime diff summary; if the former, filter awaitStatsForSession's reduce to entries with state Modified so the badge disappears once edits are kept.

- **Proposed comment:**

  > Thanks for the report and the screenshots — this looks like it comes from how the session overview computes its lines-added/removed badge. In chat.ts's awaitStatsForSession, the diff totals are summed across all edited entries in the editing session regardless of whether they were kept or undone, while the in-session pending-changes indicator (hasPendingEdits) filters to only entries still in the Modified state. That mismatch can leave the overview showing a non-zero diff count for a session where nothing is actually pending anymore. Routing to the chat/multi-chat-sessions area for a decision on whether the badge should reflect only pending edits.

## Auto-fix candidate

- **Auto-fixable:** no
- **Rationale:** The discrepancy is clearly traceable in source, but whether the badge should show a lifetime diff summary or only pending edits is a product/design call, not a mechanical bug fix — changing the filter without that decision risks breaking an intended feature (a persistent 'this session touched N files' summary).

## Evidence

- **unfiltered diff sum:** src/vs/workbench/contrib/chat/common/chat.ts:56-71 (awaitStatsForSession) sums linesAdded/linesRemoved across ALL model.editingSession.entries.get() with no filter on entry state, so accepted ('kept') entries still contribute to the reported added/removed counts.
- **pending-edit indicator is filtered:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts:886 computes hasPendingEdits by filtering entries to state.get() === ModifiedFileEntryState.Modified — a different (correct) filter than the one used for stats, so the two signals can disagree.
- **overview rendering:** src/vs/workbench/contrib/chat/browser/agentSessions/localAgentSessionsController.ts:220-224 renders chatDetail.stats.added/removed directly as the changes badge whenever stats is present, with no gating on hasPendingEdits.
