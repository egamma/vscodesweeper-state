# Issue #342307 — BYOK custom endpoint: modelOptions values are silently dropped or overridden

[https://github.com/microsoft/vscode/issues/342307](https://github.com/microsoft/vscode/issues/342307)

## Summary

Keep open: current source confirms that thinking-model interception deletes explicitly configured temperature values after they are applied. The arbitrary-key request overlaps existing work, but neither related issue fully owns this report; its claim that the schema accepts top_k also needs correcting.

## Change summary

Prevent explicit custom-endpoint sampling configuration from being silently discarded, and clarify the supported contract for additional request-body parameters.

## Best solution

Resolve explicit temperature handling at the final custom-endpoint request boundary while preserving unspecified-value defaults and API-specific constraints. Coordinate additional body parameters with https://github.com/microsoft/vscode/issues/321372 and its open implementation PR rather than creating a competing extra-body mechanism.

## Evidence

- **Confirmed temperature deletion:** extensions/copilot/src/extension/byok/node/openAIEndpoint.ts:291–350 applies configured temperature and top_p through _applyConfiguredModelOptions during createRequestBody. At lines 414–416, interceptBody unconditionally deletes body.temperature when capabilities.supports.thinking is true. Thus thinking:true with modelOptions.temperature:0 or 1 loses that value after configuration is applied.
- **Custom-endpoint adoption:** extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts:createOpenAIEndPoint forwards both thinking and modelOptions into model metadata and constructs CustomEndpointOAIEndpoint, which inherits the affected OpenAIEndpoint behavior. extensions/copilot/src/platform/networking/common/networking.ts invokes endpoint.interceptBody(body) on the outgoing request path.
- **Schema contradicts part of report:** extensions/copilot/package.json:2194–2217 describes modelOptions as sampling parameters that override defaults, declares only temperature and top_p, and sets additionalProperties:false. Therefore top_k is not schema-supported on current main, although _applyConfiguredModelOptions also confirms that unrecognized keys are not forwarded. Arbitrary forwarding is an additional capability, not an already-supported modelOptions contract.
- **Existing coverage misses final interception:** extensions/copilot/src/extension/byok/vscode-node/test/customEndpointProvider.spec.ts contains tests for configured sampling values, null omission, explicit per-request precedence, and multiple API formats. Those sampling tests inspect createRequestBody results without subsequently calling interceptBody, so they do not establish that configured temperature survives the actual outgoing path.
- **Related precedence issue is not a full duplicate:** https://github.com/microsoft/vscode/issues/336736 is open and concerns generic Agent per-request values overriding model-level sampling constraints. This report additionally identifies unconditional thinking-model deletion and unsupported body keys; fixing request-option precedence alone would not resolve those behaviors.
- **Additional-body work already has an implementation candidate:** https://github.com/microsoft/vscode/issues/321372 is open and requests extra body/query/header parameters. Its discussion links https://github.com/microsoft/vscode/pull/329215, verified open and unmerged, which proposes extraBody specifically for top_k and chat_template_kwargs. This covers the second case's forwarding direction, but does not establish a fix for the separately reported temperature deletion.
- **Earlier model-options implementation is insufficient:** https://github.com/microsoft/vscode/pull/323532 merged support for configured temperature/top_p and null omission, closing https://github.com/microsoft/vscode/issues/321514. Current main still contains the later unconditional temperature deletion, so that earlier implementation is not grounds to close this report as completed.
