# Issue #322679 — Middle-click paste Primary Selection doesn't work after copying a file

[https://github.com/microsoft/vscode/issues/322679](https://github.com/microsoft/vscode/issues/322679)

## Summary

Keep this reopened report open: the discussion distinguishes Explorer-triggered, persistent file-path pasting from the general primary-selection problem. The reproduction is independently corroborated, but its cause and a current-main fix remain unverified.

## Change summary

After copying a file in Explorer, middle-click pastes its path instead of subsequently selected text.

## Best solution

Restore independent primary-selection pasting after Explorer file-copy operations, without changing ordinary clipboard or file-copy behavior. Diagnose the native clipboard and editor paste boundary before deciding whether this shares a fix with the older report.

- **Behavior:**

  > Copying and pasting a file in Explorer must not make subsequent middle-click editor pastes insert that file's path. With primary-selection support enabled, middle-click must paste the subsequently selected text and continue following later selections. Ordinary clipboard pasting and Explorer file-copy behavior must remain unchanged.
- **Trace:**

SelectionClipboard separately writes selected editor text to the 'selection' clipboard, while TextAreaInput processes browser paste-event data. A commenter corroborates the exact file-copy trigger at https://github.com/microsoft/vscode/issues/202594#issuecomment-5435504590 and distinguishes it from ordinary selection pasting at https://github.com/microsoft/vscode/issues/202594#issuecomment-5449995165. The remaining uncertainty is whether the stale path originates in native clipboard state or editor paste-event processing; current source does not prove either. Preserve clipboard separation, existing selectionClipboard configuration semantics, and file-copy behavior; do not assume the older issue has the same root cause.
