# Issue #319573 — Please suppress modal dialogs for connection problems

[https://github.com/microsoft/vscode/issues/319573](https://github.com/microsoft/vscode/issues/319573)

## Summary

Feature request to use non-modal notifications instead of modal dialogs for remote connection loss and reconnection prompts. The current behavior in RemoteAgentConnectionStatusListener is intentional — it uses ProgressLocation.Dialog for reconnection progress and dialogService.confirm for permanent failures — but the reporter has a reasonable point that modal dialogs block workflow. Routing to the remote area owner for a product call.

## Change summary

Replace modal dialogs for remote connection loss/reconnection with non-blocking notifications or status bar indicators.

## Best solution

The remote connection status listener in `src/vs/workbench/contrib/remote/browser/remote.ts` already has partial logic to switch from Dialog to Notification when quick input is visible. The area owner could evaluate making non-modal notifications the default (or adding a setting), reserving the modal confirm dialog only for permanent failure. This is a product-direction decision for the remote team.

## Vision fit

- **Fit:** unclear
- **Reason:** The request touches UX consistency (value: simple, uniform UI) but could go either way — modal dialogs are more visible for critical state, while notifications are less disruptive.
