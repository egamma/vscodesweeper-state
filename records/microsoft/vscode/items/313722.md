# Issue #313722 — [Bug] Infinite "Compacted conversation" loop triggered on 2nd turn after file modification (Context token miscalculation)

## Summary

Multiple independent users confirmed the second-turn compaction loop, and current source explicitly treats low-headroom compaction and repeated summarization as defects. Main contains several related safeguards, but no commit conclusively addresses this report's unchanged-model, post-file-edit trigger, so there is not enough evidence for a completed close.

## Change summary

After an agent modifies a file, the next user turn can repeatedly compact the conversation despite the displayed context usage being low.

## Best solution

Reproduce the two-turn file-edit scenario on current main with and without large MCP tool schemas, correlate the context widget, local render count, server-reported prompt tokens, and background summarizer state, then add a regression test ensuring one completed tool-call turn cannot trigger repeated low-usage compaction.

- **Behavior:**

  > An agent conversation remains usable after a file-modifying first turn. A short second prompt must proceed normally when the effective context is below the compaction threshold, and a single compaction must never cause another compaction loop. Acceptance should cover both ordinary tools and a large MCP tool schema while ensuring genuinely over-budget conversations still compact.
- **Trace:**

  > The compaction decision is orchestrated in AgentIntentInvocation.buildPrompt in extensions/copilot/src/extension/intents/node/agentIntent.ts. It combines rendered-message tokens, tool-schema tokens, and the latest TurnTokenUsageMetadata, consumes completed BackgroundSummarizer results before rendering, and may start another background pass after rendering. BackgroundSummarizationThresholds and the state machine live in extensions/copilot/src/extension/prompts/node/agent/backgroundSummarizer.ts. Current guards address same-iteration re-triggering and stale summaries after model or context-size changes, but the report uses an unchanged model and specifically follows a file-edit tool turn; establish whether stale server usage, tool-schema accounting, or summarizer state crosses iterations before changing behavior. Do not weaken compaction for genuinely over-budget prompts or remove tool-schema tokens from the effective context calculation. Related but non-conclusive fixes are https://github.com/microsoft/vscode/commit/15bd7994c436c45036df0a849ac03fa8c63fe9a6 and https://github.com/microsoft/vscode/commit/867957b91668e6ca32a9f0a3f8ba78da451afbf6.
