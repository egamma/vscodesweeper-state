# Issue #280999 — Message reappears after checkpoint

[https://github.com/microsoft/vscode/issues/280999](https://github.com/microsoft/vscode/issues/280999)

## Summary

The defect remains traceable on current main: retry bypasses the cleanup that removes checkpoint-disabled requests, allowing the discarded second message to become visible again ahead of the retried first message. This team-authored bug must remain open, and no explicitly linked fixing commit supports a completed close.

## Change summary

Retrying an earlier chat request after restoring a checkpoint revives a discarded later message in the wrong transcript position.

## Best solution

Make retry apply the same checkpoint-disabled-request cleanup as a normal send before appending the replacement request, with a regression test covering restore-between-two-messages followed by retry of the first message.
