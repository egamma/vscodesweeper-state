# Issue #333259 — Remote agent-host sync drops a skill's sibling references/ files, breaking Markdown links from SKILL.md

[https://github.com/microsoft/vscode/issues/333259](https://github.com/microsoft/vscode/issues/333259)

## Summary

Confirmed by tracing the code: SyncedCustomizationBundler.bundle() in syncedCustomizationBundler.ts reads and writes only the exact SKILL.md URI passed in — there is no logic anywhere in that file or in agentHostLocalCustomizations.ts that parses Markdown links from SKILL.md or copies sibling reference files, so a skill's supporting files never make it into the remote bundle.

## Change summary

Remote-synced skills only bundle SKILL.md itself; files it links to via relative Markdown links (e.g. references/notes.md) are never copied to the remote, so those links break in a Remote-SSH session.

## Best solution

Extend SyncedCustomizationBundler.bundle() (or a pre-pass in agentHostLocalCustomizations.ts) to parse relative Markdown links out of a skill's SKILL.md and copy the referenced sibling files into the same relative path under skills/{skillName}/ in the synthetic bundle, mirroring how the local/extension-host path keeps the whole containing folder on disk.

## Evidence

- **loose file enumeration is single-URI:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLocalCustomizations.ts resolveCustomizationRefs() pushes `{ uri: entry.uri, type: entry.type, ... }` per prompt file (ISyncableFile) into `looseFiles`, one entry per SKILL.md, with no expansion to sibling files.
