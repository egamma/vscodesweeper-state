# Issue #346855 — Option to let webviews receive dropped files without holding Shift

[https://github.com/microsoft/vscode/issues/346855](https://github.com/microsoft/vscode/issues/346855)

## Summary

The requested opt-in remains missing: current source requires Shift to let webviews receive file drops. Keep this open for a decision on extension-controlled versus user-controlled routing; the related Shift-drop regression work does not cover that choice.

## Change summary

Allow opted-in webviews to receive file drops without Shift while preserving default workbench routing.

## Best solution

Define a supported opt-in drop-routing contract for webviews, preserving existing defaults and an explicit way to drop into the workbench. Decide whether this belongs to each extension's webview options or a user setting before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/webview/browser/webviewWindowDragMonitor.ts`, `src/vs/workbench/contrib/webview/browser/webviewElement.ts`, `src/vs/workbench/contrib/webview/browser/pre/index.html`, `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostWebview.ts`
- **Validation:** Using a minimal extension with both a WebviewPanel and WebviewView, drag a Finder file onto each opted-in target without Shift and verify its drop handler receives the file. Verify the chosen modifier returns routing to the workbench, non-opted-in webviews retain existing behavior, and Explorer/editor drags remain functional.
- **Behavior:**

  > Extensions using webviews as file-drop targets currently require users to hold Shift even for ordinary external file drops. An explicit opt-in should let those targets receive unmodified drops while leaving existing defaults unchanged. Acceptance must cover both webview panels and views, preserve a deliberate workbench-drop gesture, and avoid regressions in internal resource dragging.
- **Trace:**

  > WebviewWindowDragMonitor handles outer-window drag events, and WebviewElement.handleDragEvent redispatches forwarded inner events into that same path. Separately, handleInnerDragStartEvent in pre/index.html requests iframe blocking for file dragenter without Shift; WebviewElement handles drag-start unconditionally. WebviewOptions and serializeWebviewOptions currently offer no routing control. The uncertainty is the public ownership and modifier contract, not whether the current paths require Shift. Preserve default routing and the internal-resource behavior being addressed separately by https://github.com/microsoft/vscode/pull/321275 and https://github.com/microsoft/vscode/pull/344153.
- **Open decisions:**
  - Should opt-in routing be controlled per webview by its extension, or by a user setting?
  - For an opted-in target, should Shift explicitly route drops back to the workbench, and should that contract cover internal resource drags as well as external files?

## Evidence

- **Current routing:** src/vs/workbench/contrib/webview/browser/webviewWindowDragMonitor.ts routes DRAG and DRAG_OVER without Shift to windowDidDragStart(). In webviewElement.ts, that method blocks iframe drag events; forwarded inner drag messages are redispatched to the outer window.
- **Independent blocking path:** src/vs/workbench/contrib/webview/browser/pre/index.html:832–867 sends drag-start for unhandled file dragenter events without Shift and forwards file drag events carrying shiftKey. webviewElement.ts:336–342 handles both messages, confirming that preventing dragenter alone does not provide the requested opt-out.
- **Existing-capability check:** src/vscode-dts/vscode.d.ts:9900–9949 exposes no file-drop routing option in WebviewOptions, and src/vs/workbench/api/common/extHostWebview.ts:282–305 serializes no such option. Searches found neither enableFileDrop nor dropWithoutShift; webview.contribution.ts registers no equivalent setting or command.
- **Related implementation is narrower:** https://github.com/microsoft/vscode/pull/321275 is open and changes routing based on internal resource transfer types, not an opt-in contract for receiving file drops without Shift. https://github.com/microsoft/vscode/pull/344153 explicitly retains the Shift gesture and leaves external file routing unchanged, so it does not fulfill this request.
- **Discussion and demand:** The reporter supplies a macOS Finder-drop experiment and a prototype at https://github.com/4lemon/vscode-drop-without-shift, cites demand at https://github.com/anthropics/claude-code/issues/26784, and offers either an API option or a setting. The sole commenter volunteers implementation but does not settle that product choice.
