# Issue #267911 — Allow customizing "Sync Changes" behavior to exclude git push

[https://github.com/microsoft/vscode/issues/267911](https://github.com/microsoft/vscode/issues/267911)

## Summary

The prominent Git action button still cannot be configured to pull without pushing. Keep this accepted Backlog request open: existing safeguards are partial workarounds, and the verified related issues do not own the same request.

## Change summary

Allow users to select pull-only or fetch-and-pull behavior instead of pull-and-push for the prominent Git action button.

## Best solution

Provide an explicitly labeled pull-only choice in the Git action-button surface while preserving the existing pull-and-push meaning of Sync Changes. The Git owner should decide whether that choice is persistent configuration or a dropdown action.

## Evidence

- **Current action-button capability:** extensions/git/src/actionButton.ts, getSyncChangesActionButton(), reads the sync visibility flag from git.showActionButton but hardcodes command 'git.sync'. Unlike the commit button, the returned sync button has no secondaryCommands. Hiding the button does not provide the requested pull-only replacement.
- **Current operation semantics:** extensions/git/src/repository.ts:2549–2605, Repository._sync(), optionally fetches through git.fetchOnPull, performs the pull, then pushes when the branch is ahead and the remote is writable. There is no user-selected pull-only mode on this path; the read-only-remote exception does not cover ordinary writable remotes.
- **Existing safeguards are not coverage:** extensions/git/src/commands.ts:4278–4317 uses git.confirmSync to warn that the operation will pull and push, and git.rebaseWhenSync selects rebasing. Separate git.pull and fetch commands exist, as the reporter acknowledges, but neither changes the prominent button into a non-pushing action.
- **Linked issue verified:** https://github.com/microsoft/vscode/issues/193143 is open and predates this report, but requests recommending Force Push after rebasing. It does not cover configurable pull-only behavior in ordinary workflows, so it fails the re-reviewed-item same-symptom duplicate bar.
- **Canonical search:** Additional open-issue searches for sync customization and pull-only buttons found https://github.com/microsoft/vscode/issues/174088. Its body and discussion request separate Fetch, Pull, Push and Sync toolbar icons, not configuration of the Sync Changes action button; it is related UX work, not a verified canonical for this request.
