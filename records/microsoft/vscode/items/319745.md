# Issue #319745 — VS Code crashes on startup with TypeError when http.noProxy is a string

[https://github.com/microsoft/vscode/issues/319745](https://github.com/microsoft/vscode/issues/319745)

## Summary

Confirmed in source: `http.noProxy` is schema-typed as `string[]` but no runtime guard handles a plain string value — `|| []` only catches nullish, so `.map()` crashes the main process. Still unfixed on main.

## Change summary

VS Code crashes on startup when `http.noProxy` is set to a plain string instead of an array.

## Best solution

Add a runtime type guard in `windowImpl.ts` (and `proxyResolver.ts`) that coerces a string value into a single-element array before calling `.map()`, so a misconfigured setting degrades gracefully instead of crashing. A similar guard should be applied in the proxy resolver's `getNoProxyConfig` lambda.

  > VS Code's main process crashes on startup when the user sets `http.noProxy` to a plain string (e.g. `"example.com"`) instead of an array. The crash is at src/vs/platform/windows/electron-main/windowImpl.ts line 1132: `(this.configurationService.getValue<string[]>('http.noProxy') || []).map((item) => item.trim()).join(',')`. The `|| []` fallback only catches `undefined`/`null`; a non-empty string is truthy, and `String.prototype.map` does not exist, causing an unrecoverable TypeError in the main process. The same pattern exists in src/vs/workbench/api/node/proxyResolver.ts line 53: `getExtHostConfigValue<string[]>(configProvider, isRemote, 'http.noProxy') || []`. Fix both sites by normalizing the value: if the retrieved value is a string, wrap it in an array (`[value]`); if it's not an array at all, fall back to `[]`. Use `Array.isArray()` for the check. Do NOT change the setting schema, the configuration service, or any other call sites. Validate with a test that mocks the configuration service to return a plain string for `http.noProxy` and asserts no TypeError is thrown and the result is correctly joined.
