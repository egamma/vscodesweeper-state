# Issue #319745 — VS Code crashes on startup with TypeError when http.noProxy is a string

[https://github.com/microsoft/vscode/issues/319745](https://github.com/microsoft/vscode/issues/319745)

## Summary

The startup crash remains source-reproducible on current main: the main-process window initialization unconditionally calls `.map()` on the configured `http.noProxy` value. This is a bounded proxy-configuration bug and should remain open, classified as a bug, and routed to the proxy area.

## Change summary

Prevent a malformed string value for `http.noProxy` from crashing VS Code during startup.

## Best solution

Harden main-process proxy configuration so non-array `http.noProxy` values are treated as absent, preserving the existing environment-variable fallback and valid-array behavior, with regression coverage for startup using a malformed setting.
