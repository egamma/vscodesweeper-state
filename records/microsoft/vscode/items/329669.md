# Issue #329669 — Kimi K2.7 consistently fails with Server Error 500 in VS Code Copilot local session side chat

[https://github.com/microsoft/vscode/issues/329669](https://github.com/microsoft/vscode/issues/329669)

## Summary

Multiple independent reporters confirm the same failure (identical Server Error 500 / GH Request Id format, later a RAI-filter message) using the Kimi K2.7 model specifically in the Copilot Chat 'Local' session mode, while the same model works via CLI, subagents, the Agents window, and the 'Copilot' session mode — this points at how the local session builds its request (likely MCP tool-context size) rather than at model access itself.

## Change summary

Kimi K2.7 requests fail with a backend Server Error 500 (and later a Responsible-AI-filter rejection) specifically when using the local agent session in the Copilot Chat side panel, but work in every other Copilot surface.

## Best solution

Have the Copilot Chat/agent host team investigate how the 'Local' session mode constructs requests to model backends with smaller context budgets (Kimi K2.7) versus the 'Copilot' session path — the latest comment reports the failure disappears when all MCP servers are disabled, suggesting the local session is sending an oversized context (full MCP tool schemas) that this backend rejects.
