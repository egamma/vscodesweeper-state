# Issue #338019 — Autopilot automatically answers user questions instead of waiting for input

[https://github.com/microsoft/vscode/issues/338019](https://github.com/microsoft/vscode/issues/338019)

## Summary

Autopilot is documented and implemented to auto-approve everything and push the model to keep going without stopping for confirmation — this matches the reported behavior by design, not a defect.

## Change summary

Autopilot mode answers/chooses on the user's behalf instead of pausing when Copilot poses a question requiring explicit user input.

## Best solution

Keep Autopilot's autonomous behavior as documented; users who want the model to pause for confirmations should use a lower permission level (Default/Assisted/Auto Approve) instead of Autopilot.

  > Thanks for the detailed report. This looks like the intended behavior of Autopilot: it's designed to auto-approve tool calls and keep working autonomously rather than pause for confirmation — the permission picker describes it as "Auto-approve all tool calls and continue until the task is done," and the underlying loop explicitly nudges the model to make its own call on open questions instead of stopping (see extensions/copilot/src/extension/intents/node/toolCallingLoop.ts). If you want Copilot to pause and ask before proceeding, the Default or Auto Approve permission levels are a better fit than Autopilot (currently in Preview). Closing as as-designed, but please reopen if you think Autopilot should behave differently for explicit multiple-choice confirmations.
