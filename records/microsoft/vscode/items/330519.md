# Issue #330519 — Remote-WSL keeps old VS Code Server versions indefinitely, accumulating 6.55 GB

[https://github.com/microsoft/vscode/issues/330519](https://github.com/microsoft/vscode/issues/330519)

## Summary

The Remote-WSL client-side server cache (the `%USERPROFILE%\vscode-remote-wsl` folder and its version-pruning logic) lives in the Remote Development extensions, tracked in microsoft/vscode-remote-release, not in this repo — a `git grep` of the checkout finds no `vscode-remote-wsl` handling anywhere under `extensions/` or `src/vs`. Per the Remote-WSL topology, this should be moved to that tracker rather than closed-and-refiled.

## Change summary

Old VS Code Server version directories accumulate indefinitely (61 versions, 6.55 GB) under the Windows-side Remote-WSL cache instead of being pruned after an update.

## Best solution

Move this issue to microsoft/vscode-remote-release, where the Remote-WSL extension's server-download/cache logic actually lives; the two related closed issues cited by the reporter (vscode-remote-release#2852, #3746) confirm that is the established home for this cleanup behavior. A fix would add pruning of stale commit-hash directories under the cache root when a new server version is installed.
