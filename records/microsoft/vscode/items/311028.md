# Issue #311028 — Agents: Increase visibility of branch/worktree

[https://github.com/microsoft/vscode/issues/311028](https://github.com/microsoft/vscode/issues/311028)

## Summary

Keep open for design: current main provides some branch visibility, but does not fully deliver persistent branch/worktree orientation. The related end-to-end issue is newer and explicitly preserves this narrower report.

## Change summary

Keep the active branch and worktree visibly identifiable throughout an agent session, and explain the merge destination before approval.

## Best solution

Provide persistent, session-specific location context that remains understandable while scrolling, switching sessions, and handling approvals, with explicit source and destination information before integration actions. Coordinate the design with https://github.com/microsoft/vscode/issues/336620 without closing this report into that newer umbrella.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/sessionWorkspace.ts`, `src/vs/sessions/browser/parts/sessionHeaderBar.ts`, `src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts`, `src/vs/sessions/contrib/changes/browser/changesView.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsTitleBarWidget.test.ts`, `src/vs/sessions/test/browser/sessionHeader.test.ts`
- **Validation:** Manually create two isolated sessions on different branches, scroll beyond their initial exchanges, switch and display sessions side by side, and trigger a needs-input state. Verify that each relevant session's location remains identifiable and that its integration approval identifies the source and destination before execution; cover the selected presentation contract with focused header/title-bar tests.
- **Behavior:**

  > Users should be able to identify the active branch and distinguish an isolated worktree from the original checkout without searching the transcript or relying on hover. The context should remain understandable after scrolling and when switching between parallel sessions. Before approving an integration action, users should understand where the changes will land. Pending creation must not present the original checkout as an established isolated worktree.
- **Trace:**

  > SessionsTitleBarWidget already renders workspace and worktree-branch text in its normal state, but approval and needs-input states replace that content. getSessionWorkspaceDisplayInfo in src/vs/sessions/browser/sessionWorkspace.ts omits branch text for folder sessions and withholds pending-worktree paths. SessionHeaderBar currently presents titles and actions, while sessionHoverContent supplies detailed branch/worktree identity as secondary hover content. CreatePullRequestWidget already explains source/base direction; equivalent coverage across other integration actions remains to be traced. Preserve truthful pending state and provider-neutral session ownership, and do not expand this request into branch naming, automatic cleanup, or the full Git workflow redesign. Coordinate with https://github.com/microsoft/vscode/issues/336620, whose body explicitly retains this narrower issue.
- **Open decisions:**
  - Should persistent location identity belong to each session/chat header, or to the active-session command center with a defined presentation during approval states and side-by-side sessions?
  - What location information must be visible at rest—branch and isolation status, or also the worktree directory—and which details may remain secondary?
