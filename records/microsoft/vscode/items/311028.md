# Issue #311028 — Agents: Increase visibility of branch/worktree

[https://github.com/microsoft/vscode/issues/311028](https://github.com/microsoft/vscode/issues/311028)

## Summary

Keep open: this team-authored Backlog request still describes a real Agents Window orientation and trust gap. Current main exposes branch/worktree details primarily in a Sessions-list hover, while the persistent session header shows only status, title, and actions.

## Change summary

Keep the active repository, worktree, and branch persistently visible, and identify merge destinations before users approve Git operations.

## Best solution

Give every active session persistent, accessible location identity—repository, checkout/worktree, and branch—and make each mutating Git action state its source, destination, and remote effect before approval. The presentation should remain calm and compact while ensuring this safety-critical context is not confined to transient hover or transcript content.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/sessionHeaderBar.ts`, `src/vs/sessions/browser/parts/media/chatCompositeBar.css`, `src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts`, `src/vs/sessions/contrib/changes/browser/changesView.ts`, `src/vs/sessions/contrib/changes/browser/createPullRequestWidget.ts`, `src/vs/sessions/contrib/applyCommitsToParentRepo/browser/applyChangesToParentRepo.ts`, `src/vs/sessions/test/browser/sessionHeader.test.ts`
- **Validation:** Add focused session-header and Git-action UI tests or component fixtures verifying that repository/worktree/branch identity remains visible and screen-reader-readable after transcript scrolling and session switching, and that each merge/apply/PR approval names its source and destination branches before execution.
- **Behavior:**

  > An active Agents Window session must continuously identify its repository or project, whether it uses a checkout or worktree, and its current branch without requiring transcript scrolling or pointer hover. Switching sessions must update that identity immediately. Before Commit, Apply/Merge, Sync, or Create PR crosses a local or remote boundary, the UI must identify the source and destination and describe the operation being approved. The same information must be available to keyboard and screen-reader users, and compact layouts must not silently remove the only persistent identity cue.
- **Trace:**

  > Current session workspace models already expose `gitRepository.workTreeUri`, `branchName`, and `baseBranchName`. `getFolderLocation` in src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts adapts worktree and branch data for the rich Sessions-list hover, while `SessionHeaderBar._updateHeader` in src/vs/sessions/browser/parts/sessionHeaderBar.ts reads only status, title, and rename capability. Create PR has a branch-direction presentation in `CreatePullRequestWidget.updateRepository`, but Apply Changes resolves and merges the worktree branch inside `ApplyChangesToParentRepoAction.run` without an equivalent visible target contract. The boundary is the Agents Window session identity and its mutating Git actions; do not change Git branch semantics or make hover the sole source of critical context. The broader design inventory at https://github.com/microsoft/vscode/issues/336620 is useful context but explicitly preserves this narrower report.
- **Open decisions:**
  - Should persistent location identity live in every session/chat header, remain pinned within the transcript as proposed in the thread, or use both presentations across desktop and compact layouts?
  - Which Git operations require an explicit confirmation surface, and what source, destination, and local-versus-remote details must each surface show before approval?
  - For multi-folder sessions or chats operating in different worktrees, should the persistent identity represent the session-wide workspace, the active chat's working location, or both?
