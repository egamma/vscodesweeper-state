# Issue #128527 — editor.scrollbar.scrollByPage doesn't work correctly when Option-clicking (Mac)

[https://github.com/microsoft/vscode/issues/128527](https://github.com/microsoft/vscode/issues/128527)

## Summary

A real macOS interaction gap remains on current main: when page scrolling is enabled, scrollbar clicks always page regardless of the Option modifier. The request is already routed correctly but has no community or maintainer traction, so it should remain open as under discussion rather than receive a speculative close.

## Change summary

Make Option-clicking an editor scrollbar track jump directly to the clicked position on macOS even when `editor.scrollbar.scrollByPage` is enabled.

## Best solution

Define whether VS Code's shared scrollbar should follow the macOS Option-click convention globally or only for editor scrollbars, then add modifier-aware behavior without changing ordinary page-scrolling clicks or other platforms.

## Evidence

- **setting wiring:** src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts passes `scrollbar.scrollByPage` into the shared SmoothScrollableElement and updates it on configuration changes; there is no editor-level modifier override.
- **existing capability:** src/vs/editor/common/config/editorOptions.ts describes `editor.scrollbar.scrollByPage` as controlling whether clicks page or jump to the clicked position. The setting provides either behavior globally, but not the requested macOS Option-click inversion.
