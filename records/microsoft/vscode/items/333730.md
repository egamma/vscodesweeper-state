# Issue #333730 — Automations showing unread badge for unread archived sessions

[https://github.com/microsoft/vscode/issues/333730](https://github.com/microsoft/vscode/issues/333730)

## Summary

Confirmed on current main: the automation unread-run checks (`isUnreadAutomationRun` in automationsView.ts and `hasUnreadRun` in sessionsList.ts) only test `!session.isRead`, never `session.isArchived`, so an archived-but-unread session's automation run still triggers the unread badge/dot and keeps the "Mark all as read" button visible — unlike the session list row rendering, which correctly gates on `!isRead && !isArchived` (sessionsList.ts:983).

## Change summary

Automations view shows an unread badge / 'Mark all as read' state for automation runs whose underlying session has been archived, even though it is otherwise unread.

## Best solution

Add an `!session.isArchived.read(reader)` guard alongside the existing `!session.isRead` checks in `isUnreadAutomationRun` (automationsView.ts:958-960) and the `hasUnreadRun` computation (sessionsList.ts:1286-1293), matching the pattern already used for row rendering at sessionsList.ts:983.
