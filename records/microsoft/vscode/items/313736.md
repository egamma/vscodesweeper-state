# Issue #313736 — Call Stack visual selection can remain on previous thread after per-thread step, despite activeStackItem changing

[https://github.com/microsoft/vscode/issues/313736](https://github.com/microsoft/vscode/issues/313736)

## Summary

The issue remains valid on current main: a focus change can update the debug model while the Call Stack tree is refreshing, allowing the refresh to preserve or restore the previous visual selection. No older issue with the same observable symptom was found.

## Change summary

Keep the Call Stack tree's selected row synchronized with the active thread and frame after stepping a non-selected thread.

## Best solution

Ensure CallStackView applies the latest focused stack frame after any in-flight tree refresh completes, so stale tree-selection restoration cannot override the debug model's focus.

- **Behavior:**

  > When a per-thread step changes VS Code's active debug thread or frame, the Call Stack view must finish with that same frame selected and emphasized. This must hold even when the focus change occurs while the Call Stack tree is refreshing. Existing expansion, reveal, and editor-focus behavior must remain unchanged. Acceptance requires a controlled asynchronous test in which the final tree selection contains only the latest focused frame.
- **Trace:**

  > CallStackView in src/vs/workbench/contrib/debug/browser/callStackView.ts refreshes through an asynchronous RunOnceScheduler callback. The focus listener defers selection only while `isScheduled()` is true, but RunOnceScheduler clears that state before invoking the async runner, leaving the `tree.updateChildren()` interval unprotected. CompressibleAsyncDataTree rendering in src/vs/base/browser/ui/tree/asyncDataTree.ts snapshots and restores selection around rendering, so a selection update made during that interval can be superseded by the stale selection. DebugSession.handleStop and DebugService.focusStackFrame already move DebugViewModel to the correct stopped thread/frame, matching the reporter's activeStackItem instrumentation; keep those model and editor-focus semantics unchanged. https://github.com/microsoft/vscode/issues/322448 concerns a different focus-transfer behavior and is not a canonical duplicate.
