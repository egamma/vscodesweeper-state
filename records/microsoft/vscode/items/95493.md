# Issue #95493 — Add support for `font-stretch`

[https://github.com/microsoft/vscode/issues/95493](https://github.com/microsoft/vscode/issues/95493)

## Summary

Keep this accepted, well-supported request open: current editor configuration still lacks font-stretch support, and existing font-family and variable-font settings do not cover selecting static expanded or condensed faces. The canonical search found no older open issue owning the same request; a newer width-control request was explicitly closed as a duplicate of this one.

## Change summary

Support selecting expanded or condensed editor font faces through font-stretch without changing font height or uninstalling other font variants.

## Best solution

Provide supported editor font-width selection that is consistently reflected in rendering, character measurement, and layout. Preserve default behavior and verify that width selection works with bold and italic faces, rather than relying on platform-specific font-name aliases.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/config/fontInfoFromSettings.ts`, `src/vs/editor/common/config/fontInfo.ts`, `src/vs/editor/browser/config/domFontInfo.ts`, `src/vs/editor/browser/config/fontMeasurements.ts`, `src/vs/editor/browser/gpu/raster/glyphRasterizer.ts`, `src/vs/editor/test/browser/config/fontMeasurements.test.ts`
- **Validation:** With normal and expanded static faces installed together, verify supported width selection at unchanged font size and line height on Windows and macOS, including normal, bold, italic, selection, cursor placement, and wrapping. Add focused configuration, DOM font application, and font-measurement cache tests; verify the chosen behavior with GPU acceleration enabled and disabled, and confirm unchanged rendering when width selection is unset.
- **Behavior:**

  > Users should be able to select an installed expanded or condensed editor font face without uninstalling sibling faces or depending on platform-specific font-name aliases. Changing width must not change the configured font size or line height, and measurement, cursor placement, selection, and wrapping must agree with the rendered text. Normal, bold, and italic text should honor the selected width where matching faces exist. Existing behavior remains unchanged when no width selection is configured.
- **Trace:**

  > EditorFontVariations in src/vs/editor/common/config/editorOptions.ts exposes font-variation-settings, which does not supply CSS width-face matching for static fonts. createBareFontInfoFromValidatedSettings and createBareFontInfoFromRawSettings in src/vs/editor/common/config/fontInfoFromSettings.ts feed BareFontInfo in src/vs/editor/common/config/fontInfo.ts; neither carries stretch, and applyFontInfo in src/vs/editor/browser/config/domFontInfo.ts does not apply it. FontMeasurementsImpl in src/vs/editor/browser/config/fontMeasurements.ts persists measured font state, and the GPU GlyphRasterizer separately constructs canvas fonts, so compatibility across those consumers remains to be designed. Preserve default font selection and existing variation settings; do not treat the terminal anecdotes as a settled requirement for a new terminal setting. https://github.com/microsoft/vscode/issues/179521 was closed in favor of this issue, while the newer font regressions linked in the discussion do not resolve its central capability gap.
- **Open decisions:**
  - Should the public editor width setting accept CSS named stretch values, percentages, or both?
  - What precedence should apply when width selection and editor.fontVariations explicitly specifying the wdth axis are configured together?
  - Must the initial feature provide equivalent width selection in both DOM and GPU rendering, and what user-visible behavior is acceptable if a renderer cannot support it?

## Evidence

- **Existing-capability check:** src/vs/editor/common/config/editorOptions.ts registers editor.fontVariations as explicit CSS font-variation-settings, but contains no fontStretch or font-stretch option. Variable-font axis control is not equivalent to selecting static width faces within a font family.
- **Current font pipeline:** src/vs/editor/common/config/fontInfoFromSettings.ts carries family, weight, size, ligatures, variations, line height, and letter spacing into BareFontInfo. src/vs/editor/common/config/fontInfo.ts has no stretch field in its font state or cache identity, and src/vs/editor/browser/config/domFontInfo.ts applies those existing properties without applying font-stretch.
- **Workarounds do not cover the request:** The discussion at https://github.com/microsoft/vscode/issues/95493 reports successful Expanded or hyphenated font-name aliases on some platforms, but also failures with italic faces and particular weights. Installing only extended variants prevents using normal-width variants elsewhere; the June 2024 comments explicitly retain that requirement.
- **Canonical ownership:** https://github.com/microsoft/vscode/issues/179521 is closed, and the maintainer comment https://github.com/microsoft/vscode/issues/179521#issuecomment-1839288133 identifies it as a duplicate of this request. Searches for font-stretch, condensed fonts, and expanded fonts found no verified older open canonical covering this request. https://github.com/microsoft/vscode/issues/58301 concerns theme text shadows, not font-width selection.
- **Accepted demand:** The issue has 128 community upvotes and a Backlog milestone. The May 2020 bot comment records promotion after meeting the community threshold; age alone does not justify retiring the accepted request.
- **Related regressions are distinct:** https://github.com/microsoft/vscode/issues/214390 and https://github.com/microsoft/vscode/issues/214805 describe font-weight and font-family regressions in VS Code 1.90. Their closed status does not establish implementation of the separate font-stretch setting requested here.
- **Implementation boundary and inspection limits:** src/vs/editor/browser/config/fontMeasurements.ts serializes and caches measured font information, while src/vs/editor/browser/gpu/raster/glyphRasterizer.ts constructs canvas font strings. Width selection therefore needs a rendering-and-measurement design, not only a CSS assignment. The checkout is shallow, so the absence of a matching local history entry is not proof that no historical fix exists; no runtime validation was performed.
