# Issue #348360 — Stop button throws away all context from the turn

[https://github.com/microsoft/vscode/issues/348360](https://github.com/microsoft/vscode/issues/348360)

## Summary

Keep open: current source contains a cancellation path that leaves the turn without its accumulated tool-call metadata. The crash-recovery confirmation raises a related persistence concern that still needs separate diagnosis.

## Change summary

Preserve completed agent work in subsequent model context when a turn is stopped or interrupted.

## Best solution

Ensure stopping an agent preserves completed tool calls and results in follow-up context while clearly recording the interruption. Investigate crash recovery separately; preserving available conversation state should not depend on retaining unavailable model-internal reasoning.

- **Behavior:**

  > Stopping a multi-step agent turn must stop further work without making completed tool calls and their results disappear from the next prompt. Follow-up context must distinguish completed work from interrupted or unexecuted actions. Check immediate continuation and restored-session behavior separately. Do not equate preserving available transcript state with guaranteeing retention of all model-internal reasoning.
- **Trace:**

  > ToolCallingLoop.throwIfCancelled assigns CanceledResult directly to the Turn before throwing; that result has no accumulated tool-call metadata. After earlier rounds, _runLoop can catch the cancellation and return accumulated rounds, and DefaultIntentRequestHandler builds richer metadata, but Turn.setResponse rejects replacement of an already-cancelled response. Turn.rounds consequently falls back to an empty round on that cached object. addHistoryToConversation in chatParticipantRequestHandler.ts prefers cached turns, whereas restoration rebuilds from response parts and result metadata. The cancellation path is source-confirmed; whether the crash report loses metadata before persistence or during restoration remains unresolved. Preserve prompt-filtering rules, normal completed-turn behavior, and immediate cancellation semantics.
