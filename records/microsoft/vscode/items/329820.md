# Issue #329820 — "revealFileInOS" - doesn't work within devcontainer

[https://github.com/microsoft/vscode/issues/329820](https://github.com/microsoft/vscode/issues/329820)

## Summary

Confirmed in source: `toLocalFileUri` in fileCommands.ts only maps `vscode-remote` resources back to a local path for the `wsl` remote (via `\\wsl$\...`), so any other remote authority — including Dev Containers — falls through to `undefined` and `revealResourcesInOS` silently does nothing. Real, reproducible gap; not previously reported as an open canonical (the near-identical #329790 from the same author was closed as a duplicate of this one, so this is the surviving/canonical report).

## Change summary

`revealFileInOS` (and the 'Reveal in File Explorer' context menu entry) does nothing when the active workspace is a Dev Container, even though the analogous WSL case was fixed to work.

## Best solution

Extend `toLocalFileUri` in src/vs/workbench/contrib/files/electron-browser/fileCommands.ts to resolve a host-visible path for Dev Container resources where one exists (e.g. via the container's bind-mount/workspace source path), similar to the existing WSL branch; where no host path can be resolved, surface a clear message instead of silently no-op'ing. Likely needs coordination with the Dev Containers extension/remote authority resolver for the container-to-host path mapping.
