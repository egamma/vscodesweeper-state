# Issue #329820 — "revealFileInOS" - doesn't work within devcontainer

[https://github.com/microsoft/vscode/issues/329820](https://github.com/microsoft/vscode/issues/329820)

## Summary

The behavior is confirmed by the current source, but supporting host-file reveal for Dev Container resources requires container-aware path mapping owned by the Remote Development family. This should be moved to microsoft/vscode-remote-release rather than closed.

## Change summary

Support revealing a Dev Container file in the Windows host's File Explorer through the revealFileInOS command and context menu.

## Best solution

The Dev Containers integration should expose a container-to-host path mapping and contribute the reveal action where that mapping exists, while leaving unmappable container resources hidden rather than silently invoking an invalid host path.

## Evidence

- **current source:** src/vs/workbench/contrib/files/electron-browser/fileActions.contribution.ts limits the Reveal in File Explorer menu to file and vscode-userdata resources, so it is absent for vscode-remote Dev Container resources.
- **unsupported authority:** src/vs/workbench/contrib/files/electron-browser/fileCommands.ts accepts vscode-remote resources only when getRemoteName(resource.authority) is 'wsl'; a Dev Container authority reaches the undefined return and revealFileInOS does nothing.
- **prior WSL fix:** https://github.com/microsoft/vscode/pull/299492 fixed https://github.com/microsoft/vscode/issues/299491 specifically by translating WSL resources to \\wsl$ UNC paths. It did not add a corresponding mapping for Dev Containers.
- **ownership:** Dev Containers is a VS Code-team-owned Remote Development extension tracked in https://github.com/microsoft/vscode-remote-release, so policy calls for transferring the issue rather than closing it as caused by an extension.
