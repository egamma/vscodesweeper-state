# Issue #340090 — Copilot Chat: background commands running counter only increases after commands finish

[https://github.com/microsoft/vscode/issues/340090](https://github.com/microsoft/vscode/issues/340090)

## Summary

Keep open: an independent commenter confirms a background-command count persisting after reboot and session restoration. Current source supports decrementing when lifecycle updates arrive, but the affected completion/restoration path remains undiagnosed; the related attached-server reports do not establish a duplicate.

## Change summary

Ensure the background-command indicator stops counting completed, failed, cancelled, or explicitly stopped commands, including after restoring a chat.

## Best solution

Reconcile the chat indicator with actual command lifecycle state across completion and restoration, preserving legitimately running servers. First determine whether the affected session uses terminal-invocation metadata or provider background-work state, then cover the failing path end to end.

- **Behavior:**

  > The running-command indicator must represent commands that are actually active, not historical terminal invocations. Successful completion, failure, cancellation, and explicit stopping must remove the corresponding command from the count. A legitimately running persistent server must remain counted. Restoring a conversation must not resurrect finished commands as running, and a session with no active commands must show no running-command count.
- **Trace:**

  > getPersistentActivityLabel in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts has two counting sources: an authoritative provider backgroundShellCount when available, otherwise activity aggregated from current and previous response tool invocations. The fallback predicate isActiveBackgroundTerminalToolInvocation in chatToolPartUtilities.ts treats background-marked invocations without an exit code as active; the tracker already supports decrementing on notified state changes. AgentHostSessionHandler.backgroundShellCount instead counts shell entries in chat backgroundWork. Existing renderer tests demonstrate decrementing when the relevant updates are supplied, but do not establish that the affected real session supplies them or reconciles restored state. The independent report at https://github.com/microsoft/vscode/issues/340090#issuecomment-6100472889 confirms persistence after reboot, not the precise failed transition. Diagnosis must identify the session's provider and trace command completion through its counting source; do not change foreground-turn completion policy or detach legitimate servers to hide the count. The attached-server lifecycle work at https://github.com/microsoft/vscode/issues/336348 is related but not demonstrated to fix this symptom.
