# Issue #262614 — Copilot Chat startup experience is slow on certain devices, some options do not appear and messaging to user is unclear

[https://github.com/microsoft/vscode/issues/262614](https://github.com/microsoft/vscode/issues/262614)

## Summary

Keep open: maintainers confirmed the multi-minute startup delay and accepted caching and clearer intermediate UI as areas to investigate. Current source improves signed-out and unavailable-model messaging, but no linked fix or evidence establishes that slow-device activation and model availability are resolved.

## Change summary

On slower devices, Copilot Chat takes minutes to become ready, initially omits the model picker, and delays explaining that sign-in or setup is required until after a request.

## Best solution

Profile the Copilot extension activation and model-publication path on a constrained device, then ensure the chat input remains informative and usable while authentication and model discovery are pending. Preserve the current explicit signed-out and Restricted Mode states while addressing the underlying startup latency.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/extension/vscode/extension.ts`, `extensions/copilot/src/extension/conversation/vscode-node/conversationFeature.ts`, `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts`
- **Validation:** Record a cold-start performance scenario on a constrained Windows device that measures time from opening Chat to an informative model-picker state and to usable models; the plan should establish a regression threshold and verify signed-out, signed-in, and slow model-discovery paths.
- **Behavior:**

  > Opening Copilot Chat on a slower device must immediately show an informative model control or status rather than an absent picker. While Copilot is activating, the UI must distinguish waiting from required sign-in and must not wait for a submitted request to explain the state. Model selection should become available promptly once authentication and model discovery complete, with a measurable cold-start threshold established by the plan.
- **Trace:**

  > The confirmed symptom is that the model dropdown remains absent for minutes because the Copilot extension has not finished becoming ready. In extensions/copilot/src/extension/extension/vscode/extension.ts, baseActivate awaits experimentation initialization and ContributionCollection.waitForActivationBlockers(); ConversationFeature in extensions/copilot/src/extension/conversation/vscode-node/conversationFeature.ts waits for a token or settled authentication, and LanguageModelAccess in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts obtains authentication and endpoints before publishing models. The workbench-side ModelPickerWidget now has explicit setup-required, Restricted Mode, and post-trust activation states, so those states must not regress. The uncertainty begins at which awaited operation dominates on a constrained machine and whether model metadata can safely appear before full extension activation; https://github.com/microsoft/vscode/issues/265486 provides related timing evidence but not a fix for this issue.
