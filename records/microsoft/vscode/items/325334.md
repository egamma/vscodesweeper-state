# Issue #325334 — Mermaid built-in extension point to register further icons .

[https://github.com/microsoft/vscode/issues/325334](https://github.com/microsoft/vscode/issues/325334)

## Summary

Valid feature request: the built-in mermaid extension hardcodes two icon packs (logos, mdi) in `extensions/mermaid-markdown-features/preview-src/shared/iconPackConfig.ts` with no extension point for third-party extensions to register additional ones. This is a real gap worth routing to the markdown area.

## Change summary

Allow third-party extensions to register custom icon packs with the built-in Mermaid diagram renderer in the Markdown preview.

## Best solution

Add a contribution point (e.g. in `package.json` contributes, or via the markdown preview scripts/plugins mechanism) so extensions can supply additional Mermaid icon packs beyond the hardcoded `logos` and `mdi`. The implementation would likely touch `extensions/mermaid-markdown-features/preview-src/shared/iconPackConfig.ts` and the mermaid initialization in `index.ts` (`registerMermaidAddons`). Alternatively, a setting like `markdown-mermaid.additionalIconPacks` could allow configuration-driven registration.

## Evidence

- **hardcoded icon packs:** `extensions/mermaid-markdown-features/preview-src/shared/iconPackConfig.ts` exports a fixed array of two icon packs (`logos` and `mdi`) with no dynamic registration mechanism.
- **no extension point:** `registerMermaidAddons()` in `extensions/mermaid-markdown-features/preview-src/shared/index.ts` (line 129–134) calls `mermaid.registerIconPacks(iconPacks)` with only the hardcoded list; no contribution point or API is exposed for third-party extensions.
- **mermaid supports it:** The upstream Mermaid library's `registerIconPacks` API accepts arbitrary icon pack arrays (per https://mermaid.ai/open-source/config/icons.html), so the limitation is in VS Code's wiring, not in Mermaid itself.
