# Issue #337840 — Agent Host user MCP servers are grouped as Built-In in Customizations

[https://github.com/microsoft/vscode/issues/337840](https://github.com/microsoft/vscode/issues/337840)

## Summary

Confirmed in the checkout: `getMcpEntryGroup` in mcpListWidget.ts has no branch for `session-server-item` other than falling through to `'builtin'`, and `_buildTopLevel` in mcpCustomizationController.ts builds top-level MCP customizations with no source/provenance field at all — exactly the regression the reporter traced to #337399. This is a real, well-diagnosed bug; already correctly labeled and needs no routing.

## Change summary

Agent Host (Copilot CLI harness) MCP servers configured by the user in ~/.copilot/mcp-config.json show up under the 'Built-In' group instead of 'User' in Chat: Open Customizations.

## Best solution

Thread a bounded source classification for top-level Agent Host MCP customizations (mcpCustomizationController.ts's `_buildTopLevel`) through `IAgentHostMcpServer` into `getMcpEntryGroup`, but first confirm what provenance data the Copilot CLI SDK's MCP inventory (`rpc.mcp.list` / session events) actually exposes today — copilotAgentSession.ts logs an SDK `source` field per server but currently discards it rather than propagating it into `_toSdkMcpServer`/`_mcpCustomizations.applyAll`.

- **Trace:**
