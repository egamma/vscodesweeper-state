# Issue #337840 — Agent Host user MCP servers are grouped as Built-In in Customizations

[https://github.com/microsoft/vscode/issues/337840](https://github.com/microsoft/vscode/issues/337840)

## Summary

Carries `verification-found`, so this stays open regardless — it is mid-verification and was already reopened once. On top of that, a maintainer comment and the current source both show the underlying UI has since changed (issue #338000 replaced the tabbed/grouped MCP list with a single tree that only shows one 'Installed' section), so the originally reported symptom (empty User group, everything under Built-In) doesn't currently manifest the same way, but the root classification gap in `getMcpEntryGroup`/`_buildTopLevel` for Agent Host top-level session servers still exists in the code.

## Change summary

Agent Host MCP servers configured by the user (via Copilot CLI's `~/.copilot/mcp-config.json`) are classified as Built-In instead of User in the Customizations MCP list, because top-level session-server entries carry no source/provenance classification.

## Best solution

A maintainer needs to decide whether grouped rendering is coming back (in which case `getMcpEntryGroup` in src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts still needs the source classification carried through from `IAgentHostMcpServer`/`McpCustomizationController._buildTopLevel`) or whether the new flat tree view (from #338000) makes the original grouping bug moot; either way this should be re-verified against the current single-list tree UI before closing.
