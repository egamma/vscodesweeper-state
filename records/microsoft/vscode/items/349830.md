# Issue #349830 — Open in VS Code from Agents creates a second WSL dev container

[https://github.com/microsoft/vscode/issues/349830](https://github.com/microsoft/vscode/issues/349830)

## Summary

Keep open: current source still launches workspace containers using the host-native path but hands WSL workspaces to the editor using a UNC path, consistent with the reported identity mismatch. The report provides sufficient steps to retest current main; end-to-end reuse with Dev Containers 0.475.0 and Podman remains unverified.

## Change summary

Opening an Agents-created WSL Dev Container in the editor should reuse the running container rather than create another.

## Best solution

Make container identity consistent across the Agents launcher and editor handoff while preserving WSL-native execution paths and distribution identity. Investigate the core handoff first; the required Dev Containers extension alone does not establish extension ownership.
