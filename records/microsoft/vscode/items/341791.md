# Issue #341791 — Copilot Chat blocks the extension host for 10–20 s during activation by calling `os.cpus()` repeatedly in telemetry setup

[https://github.com/microsoft/vscode/issues/341791](https://github.com/microsoft/vscode/issues/341791)

## Summary

Thanks for the detailed profile. On current main, Copilot Chat calls `os.cpus()` once in `githubTelemetrySender.ts` and twice per `AzureInsightReporter` (the helper runs from both `createAppInsightsClient` and the constructor). On machines where `os.cpus()` takes seconds, this blocks the extension host. Copilot Chat is in scope here, so this stays open as a bounded perf fix.

## Change summary

Telemetry setup calls `os.cpus()` repeatedly during activation, blocking the extension host for 10–20 s on many-core Linux machines with slow cpufreq reads.

## Best solution

Compute the CPU model string once (lazily and memoized, ideally off the activation critical path) and share it between the GitHub telemetry sender and the Azure reporter. Also drop the duplicate `configureReporter` call in the `AzureInsightReporter` constructor.
