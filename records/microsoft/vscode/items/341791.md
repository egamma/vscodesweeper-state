# Issue #341791 — Copilot Chat blocks the extension host for 10–20 s during activation by calling `os.cpus()` repeatedly in telemetry setup

[https://github.com/microsoft/vscode/issues/341791](https://github.com/microsoft/vscode/issues/341791)

## Summary

Thanks for the detailed analysis. The repeated synchronous `os.cpus()` calls are still present in Copilot Chat's telemetry setup on main, so this stays open. The slow `os.cpus()` itself is environment-specific (older kernel, 224 CPUs), but the repeated call is avoidable.

## Change summary

Copilot Chat telemetry setup calls `os.cpus()` several times per logger creation, blocking the extension host for seconds on many-core machines where it is slow.

## Best solution

Compute the CPU model string once, lazily and cached at module level, and share it between githubTelemetrySender.ts and azureInsightsReporter.ts. Also drop the duplicate `configureReporter()` call in the AzureInsightReporter constructor.
