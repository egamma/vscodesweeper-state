# Issue #116322 — Git - Adopt `execInstallFolder` for askpass

[https://github.com/microsoft/vscode/issues/116322](https://github.com/microsoft/vscode/issues/116322)

## Summary

The requested adoption remains missing: Git still contributes concrete askpass paths derived from its installation or storage directory. Keep this accepted Git debt open; the newer Windows workaround covers only part of the original motivation.

## Change summary

Use late-resolved `${execInstallFolder}` paths for Git's terminal askpass environment instead of installation-specific absolute paths.

## Best solution

Make terminal askpass contributions resilient to installation-directory changes while preserving concrete paths for Git processes launched directly by the extension and the existing Windows content-addressed storage behavior.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `extensions/git/src/askpassManager.ts`, `extensions/git/src/terminal.ts`, `extensions/git/src/main.ts`, `extensions/git/src/test/askpassManager.test.ts`

Separately verify that direct extension-launched Git receives executable absolute paths and Windows content-addressed paths remain unchanged. Confirm the corresponding behavior in a remote terminal before implementation is considered complete.
- **Behavior:**

  > Git terminal authentication should not retain obsolete installation-specific askpass script paths when a newly created terminal resolves its environment after an installation-directory change. Direct Git operations launched by the extension must continue receiving usable concrete paths. Existing Windows content-addressed askpass storage must remain effective. Acceptance must cover local and remote terminal creation; changing the environment of already-running terminals is outside this cleanup.
- **Trace:**

  > extensions/git/src/main.ts calls getAskpassPaths(__dirname, context.globalStorageUri.fsPath, logger), then passes those paths to Askpass. askpass.ts stores concrete paths in this.env and exposes that object through both getEnv() and getTerminalEnv(); terminal.ts persists the latter through environmentVariableCollection.replace(). The terminal collection infrastructure resolves placeholders at application time, and execInstallFolder maps to getAppRoot(), but no Git contribution uses it. askpassManager.ts now deliberately uses stable content-addressed copies on Windows user/system installations, so the original request cannot be applied as an unconditional replacement of every path. The remaining uncertainty is the resolver root and path shape on remote terminal creation, plus regression coverage for separating terminal contributions from direct Git subprocess environments. https://github.com/microsoft/vscode/issues/115053 supplies the prerequisite infrastructure; https://github.com/microsoft/vscode/issues/282020 explains the Windows compatibility boundary.

## Evidence
