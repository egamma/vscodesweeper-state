# Issue #202912 — Becoming unresponsive: Crash 

[https://github.com/microsoft/vscode/issues/202912](https://github.com/microsoft/vscode/issues/202912)

## Summary

A VS Code collaborator already attributed the hang to Electron's shell.openExternal when no default browser is configured on Linux (e.g. Kali); current main still calls shell.openExternal directly with no timeout/fallback for that case, so this is correctly an upstream-tracked item, not something to close. The prior implemented-on-main close citing commit 51df2a1 was refuted and must not be re-cited.

## Change summary

VS Code becomes unresponsive and eventually crashes when the Settings Sync sign-in flow tries to open the system browser but no default browser is configured (observed on Kali Linux).

## Best solution

Keep tracking as upstream (Electron's shell.openExternal has no built-in timeout/no-default-browser signal on Linux); consider adding a timeout or user-facing error in VS Code's doOpenShellExternal path as a mitigation, or document the need for a default browser in troubleshooting docs.
