# Issue #338346 — Edit Configuration doesn't work in Agewnts Window in the MCP Details View

[https://github.com/microsoft/vscode/issues/338346](https://github.com/microsoft/vscode/issues/338346)

## Summary

Fresh, team-authored bug (still being actively investigated by two maintainers the same day it was filed) — 'Edit Configuration' in the MCP details view fails to open the config file when that view is shown inside the Agents Window. No fix exists yet; keeping open is required for a team-authored item without a citable commit.

## Change summary

Clicking 'Edit Configuration' on an MCP server's detail view in the Agents Window does not open mcp.json at the server's location, even with the setting as a user-level setting.

## Best solution

Diagnose why EmbeddedMcpServerDetail.editConfiguration()'s IEditorService.openEditor call doesn't surface the editor in the Agents Window — the MCP details view renders inside the Custom View Grid Part, which is mutually exclusive with the Editor part in singlePaneWorkbench.ts; confirm whether opening the editor should first switch away from the Custom View Grid (via revealEditorOnOpen/_applyCustomViewGridVisibility) and implement that.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/embeddedMcpServerDetail.ts`, `src/vs/sessions/browser/singlePaneWorkbench.ts`, `src/vs/sessions/browser/workbench.ts`
- **Validation:** A test (or manual repro) confirming that clicking Edit Configuration on an MCP server detail while the Agents Window shows a Custom View reliably opens/reveals the underlying mcp.json editor at the server's location.
- **Behavior:**

  > In the Agents Window (Sessions), opening an MCP server's details and clicking 'Edit Configuration' should open the backing mcp.json file at the server's configuration location, exactly as it does in the regular workbench. Today it silently fails to open/reveal the file when the MCP details view is shown as a Custom View in the Agents Window.
- **Trace:**

  > editConfiguration() in embeddedMcpServerDetail.ts unconditionally calls IEditorService.openEditor(); this is the same call used in the regular workbench, which works there. The Agents Window layout (src/vs/sessions/LAYOUT.md, workbench.ts) treats the Editor part and the Custom View Grid Part as mutually exclusive top-level surfaces, and singlePaneWorkbench.ts already has custom revealEditorOnOpen()/(_applyCustomViewGridVisibility) logic for switching between them for at least one other case (docked Changes/Files). It is not yet established whether that reveal logic covers the MCP-details Custom View case, or whether the open call is failing for a different reason (e.g. source.uri resolution, selection range). This needs tracing with the actual Agents Window running, which the plan should start with.
- **Open decisions:**
  - When 'Edit Configuration' is clicked while a Custom View (like MCP details) is active, should the Agents Window automatically hide the Custom View Grid and reveal the Editor part, or should it open the editor alongside/behind the custom view in some other arrangement?

## Evidence

- **code path:** src/vs/workbench/contrib/chat/browser/aiCustomization/embeddedMcpServerDetail.ts editConfiguration() calls this.editorService.openEditor({resource: source.uri, options: {selection, pinned: true}}) — a normal IEditorService call that should work per src/vs/sessions/LAYOUT.md ('Editors must be opened through IEditorService').
- **layout constraint:** src/vs/sessions/LAYOUT.md: 'At most one high-priority surface is visible in the main horizontal chain: normally the Sessions Part, or the Custom View Grid while a custom view is active' — the MCP details editor is rendered as a Custom View (contrib/aiCustomizationTreeView), so the Editor part may stay hidden when Edit Configuration tries to open a file there.
- **existing reveal logic:** src/vs/sessions/browser/singlePaneWorkbench.ts revealEditorOnOpen() and workbench.ts _applyCustomViewGridVisibility()/_CUSTOM_VIEW_EXCLUSIVE_PARTS handle editor-part visibility around custom views for a different case (docked Changes/Files detail); it's not yet confirmed whether the same logic correctly reveals the editor for this MCP-config-edit case.
