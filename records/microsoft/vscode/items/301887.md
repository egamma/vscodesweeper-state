# Issue #301887 — Global Search result clicks do not expose selection/range to Custom Editor (webview) extensions

[https://github.com/microsoft/vscode/issues/301887](https://github.com/microsoft/vscode/issues/301887)

## Summary

Genuine API gap: `resolveCustomTextEditor` has no mechanism to pass a target selection/range to custom editors when opened from Global Search results. The request is valid and no existing API covers it. An earlier report (#289785) by the same author exists but is less detailed and untriaged; this issue is the better canonical. Currently in the Backlog Candidates community voting process with 5 upvotes.

## Change summary

Custom editors (webview-based) receive no selection or range information when opened via Global Search result clicks, so they cannot scroll to or highlight the matched text.

## Best solution

Extend the `CustomTextEditorProvider.resolveCustomTextEditor` API (and its readonly counterpart) to accept an optional `options` parameter carrying a `selection`/`Range`, analogous to `TextDocumentShowOptions.selection`. This would let custom editors respond to navigation requests from Search, Go to Definition, and similar surfaces. The earlier report https://github.com/microsoft/vscode/issues/289785 should be closed as a duplicate of this one. Implementation would touch `src/vs/workbench/api/common/extHostCustomEditors.ts`, the `vscode.d.ts` API surface, and the custom editor input resolution path.
