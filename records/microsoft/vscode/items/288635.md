# Issue #288635 — Investigate sed flexible delimiters

[https://github.com/microsoft/vscode/issues/288635](https://github.com/microsoft/vscode/issues/288635)

## Summary

Still open on main: the sed auto-approve deny rules in terminalChatAgentToolsConfiguration.ts only match forward-slash delimiters (e.g. `s/…/…/e`), but sed supports any character as a delimiter (e.g. `s|…|…|e`, `s#…#…#e`). The dangerous `e` and `w` substitution flags can bypass the deny regex with a non-slash delimiter. No fix has landed.

## Change summary

The sed auto-approve deny rules should account for flexible delimiters, not just forward slashes, to properly block dangerous `s///e`, `s///w`, and `;W` patterns.

## Best solution

Update the sed deny regexes in `src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalChatAgentToolsConfiguration.ts` (lines ~347–348) to match any single-character delimiter rather than only `/`. For example, change `s\/.*\/.*\/[ew]` to match `s<delim>…<delim>…<delim>[ew]` for any non-alphanumeric delimiter character. Add corresponding test cases in the existing test file.
