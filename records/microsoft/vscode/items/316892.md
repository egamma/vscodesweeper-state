# Issue #316892 — Allow extensions to use any theme background in the Status Bar

[https://github.com/microsoft/vscode/issues/316892](https://github.com/microsoft/vscode/issues/316892)

## Summary

The extension API still restricts status bar backgrounds to warning and error colors. Earlier maintainer decisions oppose unrestricted extension colors, but do not settle this request's explicit user-consent mechanism; keep it open for a product decision.

## Change summary

Allow users to opt into extension-controlled status bar backgrounds using additional theme colors or arbitrary colors, optionally per extension.

## Best solution

Decide whether explicit user consent warrants expanding StatusBarItem.backgroundColor while retaining the existing default restriction and theme readability guarantees. If accepted, define the permitted colors and global versus per-extension control before implementation.

## Evidence

- **Current API restriction:** src/vs/workbench/api/common/extHostStatusBar.ts: ExtHostStatusBarEntry.ALLOWED_BACKGROUND_COLORS contains only statusBarItem.errorBackground and statusBarItem.warningBackground; the backgroundColor setter discards every other color ID. This restriction is unconditional, so user consent cannot currently enable the requested colors.
- **Existing capability does not cover the request:** src/vscode-dts/vscode.d.ts documents the same two supported background colors. StatusBarItem.color permits foreground customization, but that does not provide additional backgrounds such as statusBarItem.prominentBackground.
- **Earlier scope decision:** https://github.com/microsoft/vscode/issues/140437 is closed as out of scope and concerned allowing prominentBackground. https://github.com/microsoft/vscode/issues/140437#issuecomment-1010414608 recommends standard items or state icons. The user-consent proposal appears later in https://github.com/microsoft/vscode/issues/140437#issuecomment-3851423406, without a subsequent maintainer decision in the retrieved discussion; the earlier decline does not establish rejection of that full proposal.
- **Maintainer concern:** https://github.com/microsoft/vscode/issues/152053#issuecomment-1155580694 explicitly opposes opening backgrounds to arbitrary colors because of distraction, clutter, and contrast issues. That establishes the rationale for the existing restriction, not a decision on a user-controlled opt-in.
