# Issue #242628 — Feature Request: Persist Extension List Sorting in the Extensions Sidebar

[https://github.com/microsoft/vscode/issues/242628](https://github.com/microsoft/vscode/issues/242628)

## Summary

Keep open: this accepted Backlog request reached 20 community upvotes, and current main still has no setting for a durable extension-list sort preference. Existing workspace-scoped query restoration only partially covers the requested user-level behavior.

## Change summary

Persist the user's preferred Extensions sidebar sorting across view reopenings, restarts, and relevant workspaces.

## Best solution

Give the Extensions view durable, predictable sorting semantics, either through a user/profile-scoped default-sort setting or by remembering the last selected sort order. The chosen behavior should preserve explicit search queries and respect which sort modes are valid for installed versus Marketplace results.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsViewlet.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/contrib/extensions/common/extensionQuery.ts`
- **Validation:** Add Extensions view tests that select each supported sort mode, recreate the view container and simulate a new workspace/window according to the chosen scope, then assert the expected sort query is restored without overriding an explicit search or using an unsupported sort mode.
- **Behavior:**

  > A sorting choice in the Extensions view remains effective for the persistence scope selected by the maintainer, including after the view is reopened and VS Code restarts. Installed-extension and Marketplace views use only sorting modes supported in their respective contexts. Explicit search queries and filters remain intact, and clearing a search does not unexpectedly discard the durable preference. Acceptance should cover name, install-count, rating, published-date, and update-date applicability.
- **Trace:**

  > Sort actions in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts update the search box with an @sort token. Query parsing lives in src/vs/workbench/contrib/extensions/common/extensionQuery.ts, and result ordering is applied in src/vs/workbench/contrib/extensions/browser/extensionsViews.ts. ExtensionsViewPaneContainer in src/vs/workbench/contrib/extensions/browser/extensionsViewlet.ts currently restores `query.value` from a workspace-scoped machine memento and saves it only when `isLocalExtensionsQuery` accepts the current query, so there is no user/profile-wide default and Marketplace sorting is not retained through that path. Preserve explicit query semantics and gallery capability checks; do not make unsupported sort modes available merely to satisfy persistence.
- **Open decisions:**
  - Should VS Code expose a user/profile-scoped default-sort setting, remember the most recently selected sort automatically, or support both with the explicit setting taking precedence?
  - Should one preference govern every Extensions view context, or should installed extensions and Marketplace searches retain separate sort choices because their supported sort modes differ?
