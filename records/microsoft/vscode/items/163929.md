# Issue #163929 — Renames returning empty placeholders are not handled correctly

[https://github.com/microsoft/vscode/issues/163929](https://github.com/microsoft/vscode/issues/163929)

## Summary

The rename widget's accept logic at line 496 of renameWidget.ts silently cancels when newName equals currentName (empty string), and the input field sizing/population doesn't fully respect an empty placeholder from the provider. The issue is still present on current main with partial improvement (rename edits are now called) but the empty placeholder UX remains broken.

## Change summary

When a rename provider returns an empty string as the placeholder text, the rename widget either pre-fills with the range text or silently discards the user's input.

## Best solution

The rename widget should respect empty-string placeholders: show an empty input field (already partially working), and ensure the accept logic at `renameWidget.ts:496` doesn't cancel valid non-empty input when `currentName` is empty. The `under-discussion` label is appropriate since the team needs to decide whether empty placeholders are a supported API contract.
