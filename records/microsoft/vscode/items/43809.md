# Issue #43809 — Git - Support prompting for GPG password

[https://github.com/microsoft/vscode/issues/43809](https://github.com/microsoft/vscode/issues/43809)

## Summary

Keep open: built-in commit signing still lacks a VS Code-integrated GPG passphrase prompt. The existing signing and askpass settings do not cover this request, which has 101 upvotes and remains distinct from the newer remote-signing report.

## Change summary

Provide an integrated GPG passphrase prompt when signing commits through Source Control, including remote development without a usable graphical pinentry.

## Best solution

Support an on-demand GPG pinentry interaction with VS Code's UI while preserving existing external pinentry and agent-forwarding workflows. Establish the configuration and remote-session behavior before implementation; pre-unlocking keys or requiring a desktop prompt does not fully satisfy the request.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `extensions/git/src/git.ts`, `extensions/git/src/main.ts`, `extensions/git/src/ipc/ipcServer.ts`, `extensions/git/package.json`

Commit through Source Control: the integrated prompt should permit a signed commit verified by git verify-commit HEAD; cancelling should create no commit and release the pending operation. Confirm configured external pinentry, unsigned commits, and existing HTTPS/SSH askpass behavior remain unchanged.
- **Behavior:**

  > A user signing a commit through Source Control can enter the GPG passphrase in VS Code when no external graphical prompt is available, including remote sessions. The interaction occurs when signing needs the passphrase, rather than requiring a separate key-unlock action. Successful entry produces a verifiable signed commit; cancellation completes without creating a commit or leaving the operation hanging. Existing external pinentry and agent-forwarding workflows must remain usable.
- **Trace:**

  > Repository.commit in extensions/git/src/git.ts adds -S and delegates to Git._exec/Git.spawn, which use non-terminal child processes and reserve stdin for commit input. Askpass in extensions/git/src/askpass.ts already supplies masked UI through Git IPC, but its protocol and environment cover only HTTPS and SSH, not GPG pinentry. extensions/git/src/ipc/ipcServer.ts provides the existing handler transport; extension activation wiring is in extensions/git/src/main.ts. The source establishes the missing capability, not a universally failing GPG configuration: native pinentry works for several commenters. https://github.com/microsoft/vscode/issues/130415 records a related remote failure but is not an older canonical; https://github.com/microsoft/vscode-remote-release/issues/1022 concerns a separate forwarding path. Design uncertainty starts at how a GPG agent selects and associates a VS Code prompt across local and remote sessions. Preserve signing configuration, external pinentry, and existing authentication behavior; private-key forwarding or copying is not required by this request.
- **Open decisions:**
  - Should integrated GPG prompting require explicit pinentry configuration, or activate automatically for Source Control signing when external prompting is unavailable?
  - When a GPG agent serves multiple VS Code windows or remote sessions, which window receives the prompt, and what should happen if that window disconnects?

## Evidence

- **Askpass supports different protocols:** extensions/git/src/askpass.ts registers GIT_ASKPASS and SSH_ASKPASS; Askpass.handle accepts only https or ssh requests. - **Non-terminal execution:** Git._exec and Git.spawn in extensions/git/src/git.ts:624–708 launch child processes rather than an interactive terminal; commit messages use stdin, and stdin is otherwise ignored when no input is supplied.
