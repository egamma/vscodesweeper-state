# Issue #345291 — Workspaceless chats require a workspace switch before editing a named folder

[https://github.com/microsoft/vscode/issues/345291](https://github.com/microsoft/vscode/issues/345291)

## Summary

Keep open: current main still instructs workspaceless agents to attach a workspace before repository modifications. This requests a deliberate workflow change, not a failure to follow the existing implementation.

## Change summary

Allow a workspaceless chat to edit an explicitly named existing folder without first changing its workspace.

## Best solution

Separate editing an explicitly requested folder from adopting that folder as the chat's workspace, while preserving scratch defaults and existing authorization requirements. Establish the runtime and edit-tracking boundaries before changing the shared guidance.
