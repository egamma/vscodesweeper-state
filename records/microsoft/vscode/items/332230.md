# Issue #332230 — Subprocess environment breaks GDK apps that do not support Wayland

[https://github.com/microsoft/vscode/issues/332230](https://github.com/microsoft/vscode/issues/332230)

## Summary

The report matches Chromium's GTK initialization leaking GDK_BACKEND into child processes. An exact upstream fix is already included in the Electron version selected by current main; retain this as upstream under the review policy rather than proposing an upstream close.

## Change summary

Prevent VS Code's selected GTK backend from being imposed on subprocesses, allowing X11-only GTK applications to launch from a Wayland session.

## Best solution

Use the adopted upstream fix that restores the original GDK_BACKEND after GTK initialization, preserving explicitly configured user values rather than forcing an additional backend. Confirm the reporter's RPM/Wayland/Emacs scenario with a VS Code build using the fixed Electron runtime; no separate terminal workaround is indicated.
