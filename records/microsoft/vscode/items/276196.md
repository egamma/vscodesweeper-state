Keep open: current source handles spaces by converting them to hyphens, but MCP server names containing @ or / can still produce references the chat parser cannot recognize. The related whitespace fix does not resolve the full report, and no qualifying older canonical was found.

## Change summary

Ensure selecting an MCP server with special characters from the # completion picker creates a recognized server tool-set reference rather than plain text.

## Evidence

- **Current reference generation:** src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts constructs the server tool-set referenceName with server.definition.label.toLowerCase().replace(/\s+/g, '-'). This handles spaces but leaves @ and / intact.
- **Completion-to-parser mismatch:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts:1393-1432 offers enabled tool sets using item.referenceName and inserts the literal # reference. In src/vs/workbench/contrib/chat/common/requestParser/chatRequestParser.ts, variableReg accepts only word characters, underscores, and hyphens; tryToParseVariable then performs an exact toolSetsByName lookup. A server named team/server is offered as #team/server, but the parser extracts team rather than team/server; a name beginning with @ does not match at all.
- **No general normalization downstream:** src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts:createToolSet passes the reference name through getSpecedToolSetName, which only maps known GitHub and Playwright aliases. Other names containing @ or / remain unchanged. The parser explicitly supports hyphens, so the report's hyphen case is not established as a remaining defect.
