# Issue #336152 — `executeTask()` activates *all* extensions with a task provider when the task came from `fetchTasks()`

[https://github.com/microsoft/vscode/issues/336152](https://github.com/microsoft/vscode/issues/336152)

## Summary

Verified in source: mainThreadTask.ts's `$getTaskExecution`/`$executeTask` call `this._taskService.getTask(workspace, value.id, true)` without the optional 4th `type` argument, so a fetched-then-executed task falls through to `_getGroupedTasks({type: undefined})` → `_activateTaskProviders(undefined)` → `_getActivationEvents(undefined)`, which activates every registered task type instead of just the task's own. This is exactly the pre-#178679 failure mode reintroduced at the extension-host entry points.

## Change summary

`vscode.tasks.executeTask()` on a task obtained via `fetchTasks()` activates every extension with a taskDefinition, not just the matching type's providers, because the task type is dropped when the task is round-tripped as an `ITaskHandleDTO`.

## Best solution

Thread the task type through the handle DTO end-to-end (add `type?: string` to `ITaskHandleDTO`, populate it in `TaskHandleDTO.from()`, and pass it as the 4th arg in both `getTask()` calls in mainThreadTask.ts), mirroring the fix in PR #178679 for the sibling bug #175821.
