# Issue #331384 — External sessions not showing up in agents window?

[https://github.com/microsoft/vscode/issues/331384](https://github.com/microsoft/vscode/issues/331384)

## Summary

The original CLI-session path has gained external discovery and import support, but current main still omits extension-contributed sessions that appear in the editor's Chat > Sessions list. This remains a source-confirmed cross-surface inconsistency and should be routed to the Agents Window and external-agent owners.

## Change summary

Show externally created CLI and extension-provided conversations in the Agents Window when VS Code already discovers them in the editor's Chat > Sessions list.

## Best solution

Provide a provider-neutral bridge from compatible `IChatSessionsService` contributions into the Agents Window catalog, with an explicit fallback that opens the owning extension UI when native continuation is unsupported.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatSessionsService.ts`, `src/vs/sessions/services/sessions/common/sessionsProvider.ts`, `src/vs/sessions/services/sessions/browser/sessionsProvidersService.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessions.contribution.ts`
- **Validation:** Add a targeted Sessions integration test that registers a synthetic extension-backed chat-session contribution, publishes a conversation visible to the editor session list, and verifies that the Agents Window lists it and invokes the agreed native-open or owning-extension fallback action.
- **Behavior:**

  > A conversation discoverable in the editor's Chat > Sessions list should not disappear from the separate Agents Window solely because its provider is extension-contributed. Compatible sessions should be listed with their provider and workspace metadata. When the Agents Window cannot continue a session natively, the row should expose the agreed action for opening its owning extension surface rather than silently omitting it. Existing Copilot Cloud and Agent Host external-session behavior must remain unchanged.
- **Trace:**

  > The editor catalog is owned by `IChatSessionsService` in src/vs/workbench/contrib/chat/common/chatSessionsService.ts, where extensions can register session contributions and item controllers. The Agents Window instead consumes only providers from `ISessionsProvidersService` and aggregates them in `SessionsManagementService`; no generic adapter connects those registries. The current Copilot adapter explicitly accepts only Cloud sessions, while local CLI sessions are delegated to Agent Host providers. Commit 5243c88d9daf83215536aeb71d18b72cace7378a added External sectioning and import for Agent Host sessions but did not address extension-contributed editor sessions. Preserve provider-neutral Sessions architecture and do not broaden the Copilot Cloud adapter into an owner for unrelated extension types.
- **Open decisions:**
  - Should every extension-contributed session type appear in the Agents Window, or must a contribution explicitly declare Agents Window compatibility?
  - For a listed session that cannot be continued through the Agents Window, should activation open the owning extension UI directly or present a read-only session with a separate open action?

## Evidence

- **separate catalogs on main:** The editor registers extension-provided session types and controllers through `IChatSessionsService` in src/vs/workbench/contrib/chat/common/chatSessionsService.ts, while the Agents Window aggregates only `ISessionsProvider` instances registered with src/vs/sessions/services/sessions/browser/sessionsProvidersService.ts.
- **restricted Agents Window adapter:** src/vs/sessions/contrib/providers/copilotChatSessions/COPILOT_CHAT_SESSIONS_PROVIDER.md and browser/copilotChatSessions.contribution.ts explicitly limit that adapter to Copilot Cloud; browser/copilotChatSessionsProvider.ts filters existing sessions to `AgentSessionProviders.Cloud`, leaving arbitrary extension-provided sessions without an Agents Window provider.
- **partial later implementation:** Commit 5243c88d9daf83215536aeb71d18b72cace7378a added the Agents Window External section and Agent Host session import action, but it did not bridge extension-contributed editor sessions and does not reference this issue.
- **confirmed user-visible symptom:** https://github.com/microsoft/vscode/issues/331384#issuecomment-5632021439 reports that a Codex extension conversation appears in editor Chat > Sessions but not in the separate Agents Window on VS Code 1.137.0.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/335215 is newer and covers only rediscovery of Agent Host sessions created after startup; it does not own the broader extension-session catalog mismatch and cannot be the canonical duplicate for this re-reviewed issue.
