# Issue #331429 — Copilot Chat renders internal <vscode_codeblock_uri isEdit subAgentInvocationId=...> tags for subagent edit blocks

[https://github.com/microsoft/vscode/issues/331429](https://github.com/microsoft/vscode/issues/331429)

## Summary

Team-authored regression (1.132.0 → 1.133.0) with independent corroboration from at least two other users who traced their own debug logs and found the same symptom — the raw `<vscode_codeblock_uri>` tag never appears in the model's transcript, confirming it's a Chat rendering-layer defect, not an authored one. No fix commit referencing this issue exists on main, so per the hard keep-open rule for team-authored items this stays open pending an explicit fix.

## Change summary

During multi-subagent Copilot Chat workflows, the internal `<vscode_codeblock_uri isEdit subAgentInvocationId=...>` marker is shown as raw text in the Chat view instead of being converted into a file/edit UI block.

## Best solution

Trace why the `codeblockUri` merge in src/vs/workbench/contrib/chat/common/widget/annotations.ts (the `item.kind === 'codeblockUri'` branch, ~line 121) sometimes appends the marker text after the enclosing code fence has already closed (likely due to interleaved/parallel subagent streaming reordering parts), so the tag lands as literal markdown outside the fenced block instead of being consumed by codeBlockRendererSync in chatMarkdownContentPart.ts.
