# Issue #331429 — Copilot Chat renders internal <vscode_codeblock_uri isEdit subAgentInvocationId=...> tags for subagent edit blocks

[https://github.com/microsoft/vscode/issues/331429](https://github.com/microsoft/vscode/issues/331429)

## Summary

Traced a plausible root cause in the subagent tool-collapsing pipeline: raw `<vscode_codeblock_uri isEdit subAgentInvocationId=...>` markers are only converted to file/edit UI when `getSubagentPart` finds a matching `ChatSubagentContentPart` among already-rendered parts; if that lookup misses (streaming/ordering race with multiple parallel subagent edits), the markdown falls back to literal tag text instead of a UI block — matching both reports (regression from 1.132 to 1.133, multiple subagents each editing multiple files).

## Change summary

In Copilot Chat agent sessions using subagents, internal `<vscode_codeblock_uri isEdit subAgentInvocationId=...>` marker tags leak into the visible chat transcript instead of rendering as file/edit UI, alongside empty gray placeholder blocks.

## Best solution

Chat/Copilot team should investigate the ordering between subagent tool-invocation part creation and markdown codeblock-uri rendering in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts (renderMarkdown, ~line 4270, and getSubagentPart at line 2984) for the case of multiple parallel subagents each producing several edit blocks — likely a race where the markdown part streams in before its subagent's ChatSubagentContentPart exists in renderedParts, causing a silent fallback to literal tag text.
