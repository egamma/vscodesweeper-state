# Issue #22364 — Alt + Numpad keybindings insert characters into editor

[https://github.com/microsoft/vscode/issues/22364](https://github.com/microsoft/vscode/issues/22364)

## Summary

Keep this as the canonical tracking issue for native Alt-code input occurring after an Alt+numpad shortcut executes. A maintainer identified the upstream dependency, multiple reports confirm the symptom, and no verified fix or older canonical was found.

## Change summary

Prevent Alt+numpad shortcuts from additionally inserting an Alt-code character when Alt is released.

## Best solution

Resolve the native-input interaction in Electron/Chromium, or establish a reliable VS Code mitigation that suppresses character input from consumed shortcuts without breaking intentional Alt-code entry. Keep this issue as the tracking point; the requested cross-platform scope needs separate confirmation beyond the demonstrated Windows behavior.

- **Recent confirmation:** https://github.com/microsoft/vscode/issues/22364#issuecomment-4158773358 reports the same behavior in March 2026 with NumLock off: Alt+numpad4 navigates backward but inserts a diamond on Alt release, while repeated presses produce another Alt-code character. This also contradicts relying on Visual Studio behavior as proof that the native interaction is already solved.
