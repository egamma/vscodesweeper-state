# Issue #339511 — Codex agent: overlapping thread restarts before the first turn lose the conversation

[https://github.com/microsoft/vscode/issues/339511](https://github.com/microsoft/vscode/issues/339511)

## Summary

Detailed, source-confirmed race condition in the Codex agent host restart path, with a fixing PR (#339512) already open — keep open and let the linked PR land rather than closing or marking agent-ready.

## Change summary

Overlapping Codex thread restarts before the first turn can leave the session pointing at a thread that doesn't contain the first exchange, losing conversation history on reload.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339512, which serializes `_restartThreadWithCurrentTools` per session and guards restarts against an in-flight claimed turn.
