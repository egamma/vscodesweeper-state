# Issue #62569 — [scss] rename not working for placeholder selectors

[https://github.com/microsoft/vscode/issues/62569](https://github.com/microsoft/vscode/issues/62569)

## Summary

The defect remains in the current CSS language service: rename replaces the complete placeholder token, including its leading `%`, with the requested name. Keep this open and classify it as upstream until the language service preserves SCSS selector syntax during rename.

## Change summary

Renaming an SCSS placeholder selector removes its leading percent sign from both the declaration and `@extend` references.

## Best solution

Fix placeholder rename ranges in `microsoft/vscode-css-languageservice` so `%foo` becomes `%foobar`, add an SCSS navigation test covering declaration and `@extend` edits, then consume the corrected language-service release in VS Code.

## Evidence

- **VS Code delegation:** `extensions/css-language-features/server/src/cssServer.ts` handles rename by passing the document, position, and new name directly to `vscode-css-languageservice.doRename`; VS Code applies no placeholder-specific transformation.
- **current upstream defect:** Current `src/services/cssNavigation.ts` in https://github.com/microsoft/vscode-css-languageservice/blob/1c00d690ee38c7dfb137df8de1a6ddf571ea9b36/src/services/cssNavigation.ts uses the complete highlighted node range for `prepareRename` and replaces every complete highlight range with `newName` in `doRename`, so syntax included in the range is discarded.
- **placeholder range:** Current SCSS navigation tests at https://github.com/microsoft/vscode-css-languageservice/blob/1c00d690ee38c7dfb137df8de1a6ddf571ea9b36/src/test/scss/scssNavigation.test.ts assert that a placeholder declaration and its `@extend` reference are highlighted as the full text `%r1`; those are therefore the full ranges replaced during rename.
- **bundled dependency:** `extensions/css-language-features/server/package.json` and its lockfile currently consume `vscode-css-languageservice` 7.0.0-next.2, keeping ownership of the faulty rename calculation in that dependency.
