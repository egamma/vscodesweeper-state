# Issue #328684 — [Bug]"Add File to Chat" silently does nothing in the Agents Window

[https://github.com/microsoft/vscode/issues/328684](https://github.com/microsoft/vscode/issues/328684)

## Summary

Traced on main: attach actions in the Agents Window all go through `withChatView()` in chatContextActions.ts, which falls back to `ChatWidgetService.revealWidget()`/`reveal()` when the last-focused widget's location is `ChatAgentLocation.Chat` — but that reveal logic only knows how to open/find the workbench `ChatViewId` view or a `ChatEditorInput`, neither of which exists in the separate Agents Window (`src/vs/sessions`) layer, so it silently returns `undefined` and every caller no-ops.

## Change summary

"Add File/Selection/Folder/Pinned Editors/Search Results to Chat" silently do nothing when triggered from the Agents Window because they all short-circuit on an undefined widget from `withChatView()`.

## Best solution

Teach `withChatView` (or `ChatWidgetService.reveal`) to resolve/attach to the actually-focused widget when it lives in the Agents Window rather than assuming a workbench `ChatViewPane`/`ChatEditorInput` host — e.g. by preferring `getWidgetBySessionResource` for the active session as the reporter suggested — since Agents Window widgets are a separate viewContext kind that `reveal()` doesn't currently recognize.

- **Agents Window uses ChatAgentLocation.Chat:** src/vs/sessions/contrib/chat/browser/chatView.ts:196,310 acquires/creates its chat sessions with `ChatAgentLocation.Chat`, so `withChatView`'s special-case branch always triggers there.
