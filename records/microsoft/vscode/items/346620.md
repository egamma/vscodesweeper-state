# Issue #346620 — Extension tree views leak one DisposableStore per node until "Set maximum size exceeded"

[https://github.com/microsoft/vscode/issues/346620](https://github.com/microsoft/vscode/issues/346620)

## Summary

The per-node DisposableStore retention is confirmed in current main. Keep this open while the linked, unmerged fix PR is reviewed.

## Change summary

Repeated extension tree refreshes retain disposed node stores until the view's backing Set reaches its size limit and child loading fails.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/346727 after confirming that node resources are released on refresh, replacement, and view disposal without accumulating stores on the view.

## Evidence

- **Current-source retention:** src/vs/workbench/api/common/extHostTreeViews.ts:945-976 registers every new node's DisposableStore through this._register(), but the returned node's dispose() only disposes that child store. _refreshNode() and _createAndRegisterTreeNode() create replacement nodes and dispose the old ones without removing their stores from the view.
- **Ownership mechanism:** src/vs/base/common/lifecycle.ts:416-557 shows Disposable._register() adding objects to the owner's _store._toDispose Set. DisposableStore.dispose() clears its own contents, not its membership in a parent's Set; removing that membership requires an explicit parent-store operation.
- **Repeated-refresh path:** ExtHostTreeView._fetchChildrenNodes() in src/vs/workbench/api/common/extHostTreeViews.ts:756-788 invalidates cached children and creates nodes for fetched rows. _clearNodes() and _clearAll() at lines 1112-1125 dispose nodes, but do not unlink their stores from the view's store. Thus repeated refreshes retain one store per newly created node.
- **Reporter reproduction:** https://github.com/microsoft/vscode/issues/346620 supplies a 12,000-row provider reproduction, measured per-refresh growth, and a V8 RangeError stack from a 1.140 serve-web build. Source inspection confirms the retention mechanism; no runtime reproduction was performed in this read-only review.
- **Open implementation candidate:** Public GitHub API inspection confirms https://github.com/microsoft/vscode/pull/346727 is open and unmerged. Its body explicitly says 'Resolves #346620' and describes node-scoped disposal plus a repeated-refresh regression test in src/vs/workbench/api/test/browser/extHostTreeViews.test.ts. It is not evidence of a landed fix.
