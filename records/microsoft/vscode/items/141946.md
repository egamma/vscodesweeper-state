# Issue #141946 — Extra parameter for TextEditorEdit.insert to specify not moving a selection position that's at the insertion position

[https://github.com/microsoft/vscode/issues/141946](https://github.com/microsoft/vscode/issues/141946)

## Summary

A real editor API gap remains on current main, but the selection-affinity semantics require API design discussion. Keep this Backlog request open as under discussion.

## Change summary

Allow TextEditorEdit.insert callers to keep selections anchored at the insertion position while shifting selections after it.

## Best solution

Add an insertion-affinity option to TextEditorEdit that applies consistently to tracked selections in every editor showing the document, rather than requiring extensions to reset the active editor's selection asynchronously.
