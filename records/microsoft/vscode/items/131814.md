# Issue #131814 — Is there a "Format Selection As ..." command?

[https://github.com/microsoft/vscode/issues/131814](https://github.com/microsoft/vscode/issues/131814)

## Summary

Keep this accepted, well-supported request open: current selection-formatting commands choose providers for the containing document, not a separately chosen language. No verified older open canonical owns the same request; the closed related reports do not resolve this gap.

## Change summary

Allow selected text to be formatted as a chosen language without changing the containing document's language, optionally inferring the language from a Markdown fence.

## Best solution

Provide a selection-formatting workflow that can use a different language while preserving the surrounding document. Agree on explicit language selection versus fence-language inference and the embedded-content formatting contract before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/format/browser/formatActions.ts`, `src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts`, `src/vs/editor/contrib/format/browser/format.ts`, `src/vs/editor/common/languageFeatureRegistry.ts`
- **Validation:** In a Markdown document containing an unformatted JSON fence and surrounding prose, select only the JSON and invoke the agreed workflow. Verify JSON formatting is applied, the fence and prose remain unchanged, the document stays Markdown, cancellation makes no edits, and undo restores the original text. Repeat explicit language selection in a non-Markdown mixed-language document and verify existing Format Selection and Format Selection With behavior remains unchanged.
- **Behavior:**

  > Users should be able to format selected text using a language different from the containing document without copying it into another editor or changing the document's language. The primary example is JSON inside a Markdown fence; the discussion also requests explicit language selection in other mixed-language files. Acceptance must preserve surrounding content, the containing language, cancellation behavior, and undo. Whether fence metadata supplies the language automatically remains a product decision.
- **Trace:**

  > FormatSelectionAction in src/vs/editor/contrib/format/browser/formatActions.ts operates on the existing editor model. FormatSelectionMultipleAction in src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts chooses a provider from documentRangeFormattingEditProvider.ordered(model), and LanguageFeatureRegistry in src/vs/editor/common/languageFeatureRegistry.ts matches the containing model's language. The range-formatting path in src/vs/editor/contrib/format/browser/format.ts passes that same model to the provider; it contains no separate target-language selection. This establishes the capability gap by source inspection, without executing or modifying the checkout. https://github.com/microsoft/vscode/issues/183466#issuecomment-1564975871 records extension limitations, while https://github.com/microsoft/vscode/issues/14447#issuecomment-262736975 warns that embedded formatting may depend on host-language context. Preserve existing formatter selection and defaults; persistent syntax-highlighting ranges are outside this request. Uncertainty begins at the user-visible language-selection and embedded-content contract, not at whether the current picker already provides it.
- **Open decisions:**
  - Should the operation always prompt for a language, or infer it from a recognized Markdown fence with an explicit override?
  - Should the selected text be treated as a standalone snippet of the chosen language, or must formatting preserve host-language context and embedded indentation semantics?
