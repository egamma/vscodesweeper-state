# Issue #169127 — Search: combine results of single line in search window

[https://github.com/microsoft/vscode/issues/169127](https://github.com/microsoft/vscode/issues/169127)

## Summary

Keep this accepted, 20-upvote request open: the Search view still represents individual occurrences as separate rows. Search Editor already combines same-line results, but it is a different surface and does not settle the thread's question about replacing individual occurrences in grouped rows.

## Change summary

Offer grouped Search view results that display all occurrences on a source line in one row.

## Best solution

Provide an optional compact presentation in the Search view while preserving occurrence counts and precise navigation. Decide how users select and replace individual occurrences within a grouped row before implementation.

Select and navigate to a later occurrence on the long if line, then verify that an individual replacement affects only the intended occurrence under the agreed interaction contract. Check keyboard and screen-reader access and unchanged ungrouped behavior.
- **Behavior:**

  > Searching for a term repeated several times on one source line should offer a Search view presentation with one result row for that line and all occurrences highlighted. Grouping must not lose occurrences, change the total match count, or prevent precise navigation. The existing presentation should remain available. Acceptance includes the supplied Python sample and selecting a later occurrence on its long conditional line; individual replacement behavior must be agreed before implementation.
- **Trace:**

  > textSearchResultToMatches in src/vs/workbench/contrib/search/browser/searchTreeModel/match.ts creates one MatchImpl per rangeLocation, and FileMatchImpl in searchTreeModel/fileMatch.ts retains those individual matches for both provider results and open text models. MatchRenderer.renderElement in searchResultsView.ts renders one occurrence and associates its toolbar with that match; SearchAccessibilityProvider also exposes occurrence-specific information. Current search.contribution.ts settings control expansion and tree/list layout, not same-line grouping. Search Editor's matchesToSearchResultFormat in searchEditorSerialization.ts already deduplicates displayed source lines and preserves multiple match ranges, establishing an alternative surface rather than fulfilling this Search view request. Preserve occurrence identity, counts, replacement precision, and existing ungrouped behavior. The uncertainty begins at the grouped row's user interaction contract, explicitly raised in https://github.com/microsoft/vscode/issues/169127; no runtime validation was performed in the read-only checkout.
- **Open decisions:**
  - In a grouped row, how does the user select and navigate among individual occurrences with the mouse and keyboard?
  - When replacement is active, does the grouped row's replace action replace the selected occurrence or every occurrence on that source line, and how is its target made clear?
