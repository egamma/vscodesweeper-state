# Issue #169127 — Search: combine results of single line in search window

[https://github.com/microsoft/vscode/issues/169127](https://github.com/microsoft/vscode/issues/169127)

## Summary

The Search view intentionally uses one row per match, while the built-in Search Editor already consolidates matches from the same source line. Prior maintainer decisions explicitly establish this product boundary.

## Change summary

Add an option for the Search view to display multiple matches from one source line in a single result row.

## Best solution

Keep one-row-per-match navigation and replacement in the Search view, and use the Search Editor when a line-oriented, consolidated presentation is preferred.

## Vision fit

- **Fit:** rejected
- **Reason:** A second presentation mode and dedicated setting for one workbench component conflicts with the preference for uniform UI behavior and limited configuration sprawl.
- **Evidence:** Values and guardrails: simple, uniform UI and UI interactions; UI consistency beats per-feature customization.

- **Proposed comment:**

  > Thanks for the request and the community feedback. The Search view intentionally keeps one row per match so that navigation and individual replacement remain unambiguous, including when later matches are outside the view’s narrow width. The built-in Search Editor provides the line-oriented alternative: it emits each source line once and highlights all matches on that line. This follows the existing maintainer decision documented at https://github.com/microsoft/vscode/issues/82566#issuecomment-542294286, so I suggest closing this as designed.

## Evidence

- **maintainer decision:** In https://github.com/microsoft/vscode/issues/82566#issuecomment-542294286, the Search maintainer states that the view is intended to show individual results and retains the invariant “1 row = 1 result.”
- **current Search view:** src/vs/workbench/contrib/search/browser/searchTreeModel/match.ts:12-17 creates one MatchImpl for every range location, and searchResultsView.ts:453-483 renders each match as its own tree row.
- **existing capability:** src/vs/workbench/contrib/searchEditor/browser/searchEditorSerialization.ts:84-106 uses seenLines to emit each source line once while retaining every match range, providing the requested consolidated presentation in the built-in Search Editor.
- **configuration check:** The Search settings registered in src/vs/workbench/contrib/search/browser/search.contribution.ts include result collapsing, line numbers, sorting, and view mode, but no same-line grouping mode.
- **prior scope review:** The same request was previously declined in https://github.com/microsoft/vscode/issues/31817 and https://github.com/microsoft/vscode/issues/84234; maintainers directed line-oriented code reading toward the Search Editor.
