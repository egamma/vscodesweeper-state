# Issue #329621 — Support selecting specific weekdays for Automations (e.g., Mon/Wed/Fri)

[https://github.com/microsoft/vscode/issues/329621](https://github.com/microsoft/vscode/issues/329621)

## Summary

Keep open: current main offers a local Monday–Friday preset, but weekly schedules still select only one day, leaving arbitrary combinations such as Monday/Wednesday/Friday unsupported in the editor. The related cron requests do not establish an older canonical covering this same simple weekday-selection experience.

## Change summary

Allow one Automation to run on multiple selected weekdays without creating separate automations.

## Best solution

Provide an editable, round-trippable weekday selection across the Automation dialog, agent tools, and portable definitions while preserving existing schedules. Coordinate with the cron scheduling work, retaining provider-owned execution and explicitly handling provider capability differences.

- **Behavior:**

  > Users can create and edit one weekly Automation that runs on any nonempty selection of weekdays, including Monday/Wednesday/Friday, without duplicating it. Saving and reopening preserves the selected days, and execution occurs only on those days at the configured time. Existing daily, single-day weekly, and Monday–Friday schedules retain their behavior. Agent configuration and portable import/export preserve the same supported schedule semantics without silently dropping days.
- **Trace:**

  > The dialog in src/vs/sessions/contrib/automations/browser/automationDialog.ts stores a single state.day, matching IAutomationSchedule.scheduleDay in src/vs/workbench/contrib/chat/common/automations/automation.ts and the tool parser in automationTools.ts. AgentHostAutomationStore.projectSchedule recognizes single days and the fixed Monday–Friday preset; arbitrary lists become custom and non-editable, although the Agent Host cron parser already accepts comma-separated values. This establishes a missing editing and round-trip contract, not a missing low-level cron list parser. Preserve provider-owned execution, legacy schedules, and the distinction between Agent Host local-time scheduling and Cloud fixed-UTC recurrence documented in src/vs/sessions/AUTOMATIONS.md. Related design work is https://github.com/microsoft/vscode/issues/329209 and https://github.com/microsoft/vscode/issues/339781; neither settles how this simple picker should behave across providers. The remaining uncertainty is provider availability and the user-visible timezone contract, not checkbox versus multi-select implementation.
- **Open decisions:**
  - Should the initial weekday picker support both Agent Host and Cloud automations, or be explicitly limited to Agent Hosts until Cloud can preserve the same schedule?
  - For Cloud schedules, should selected weekdays follow the existing fixed-UTC recurrence contract, including daylight-saving shifts, or promise local weekday/time recurrence?
