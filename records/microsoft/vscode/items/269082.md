# Issue #269082 — In diff editor, add a button to copy from right to left when possible + change caption based on context

[https://github.com/microsoft/vscode/issues/269082](https://github.com/microsoft/vscode/issues/269082)

## Summary

Keep this accepted Backlog request open: current actions still copy only left to right and retain revert terminology for writable file comparisons. The older bidirectional-arrow request covers the copying requirement, but does not fully own this report's context-sensitive captions.

## Change summary

Provide right-to-left block copying when the destination is writable, with diff action captions and icons appropriate to file comparison versus source-control review.

## Best solution

Make writable file comparisons support clearly labeled copying in both directions while preserving revert semantics for source-control comparisons. Coordinate the reverse-copy behavior with https://github.com/microsoft/vscode/issues/153620 and resolve the caption/context contract here.

Manually compare two writable files and a Git working-tree diff: verify directional controls, captions, keyboard accessibility, and unchanged source-control staging behavior without swapping panes.
- **Behavior:**

  > When comparing two writable files, users should be able to copy a differing block in either direction without exchanging pane positions. Captions should describe copying rather than reverting when the comparison is between independent files. Reverse copying must not be offered into a read-only destination, and source-control review must retain meaningful revert and stage actions. Acceptance includes insertion, deletion, replacement, undo, and accessible action labels.
- **Trace:**

  > The current hunk and selection menus register diffEditor.revert in src/vs/editor/browser/widget/diffEditor/diffEditor.contribution.ts with unconditional revert wording and mode-dependent icons. RevertHunkOrSelection in commands.ts dispatches to DiffEditorWidget methods that always read the original model and edit the modified model. DiffEditorWidget already publishes original- and modified-writability context keys; gutterFeature.ts supplies the toolbar mapping context, while revertButtonsFeature.ts implements a separate legacy arrow surface. The existing workbench swap command reverses the comparison input rather than copying a block in place. Coordinate the reverse-copy requirement with https://github.com/microsoft/vscode/issues/153620 and the source-control icon discussion with https://github.com/microsoft/vscode/issues/238078. Preserve staging, read-only protection, diff mapping semantics, and undo behavior; uncertainty starts at how comparison context determines user-visible captions and icons.
- **Open decisions:**
  - Should copy versus revert captions be determined solely by destination writability, or by whether the comparison represents source-control history versus independent files, including comparisons where only one independent file is writable?

## Evidence

- **Existing capability and remaining gap:** src/vs/editor/browser/widget/diffEditor/diffEditor.contribution.ts registers diffEditor.revert as "Revert Block" and "Revert Selection", gated by modified-side writability and inline mode, not comparison context. DiffEditorWidget.revert, revertRangeMappings, and revertFocusedRangeMappings in diffEditorWidget.ts copy original-model text into the modified editor; these paths provide no opposite-direction action.
