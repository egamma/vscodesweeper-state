# Issue #329183 — GitHub Copilot chat web request confirmation dialog does not correctly linkify URLs with spaces

[https://github.com/microsoft/vscode/issues/329183](https://github.com/microsoft/vscode/issues/329183)

## Summary

Traced on current main: the single-URL confirmation dialog in fetchPageTool.ts builds the confirmation message from the raw, un-encoded URL string and relies on markdown autolinking rather than an explicit `[text](url)` link, so a URL containing a literal space (e.g. a query string with an un-encoded space) only gets linkified up to the first whitespace.

## Change summary

The Copilot 'Fetch web page?' confirmation dialog truncates the clickable link at the first space in a URL instead of linking the full (percent-encoded) URL.

## Best solution

In prepareToolInvocation (src/vs/workbench/contrib/chat/electron-browser/builtInTools/fetchPageTool.ts), build the single-URL confirmationMessage as an explicit markdown link — display text as the raw/decoded URL, href as the properly percent-encoded URL (uri.toString() without skipEncoding, or an explicit encode of the display string) — mirroring the existing `singularAsLink` branch used for long URLs (lines ~216-229), instead of depending on markdown autolink of a bare string.
