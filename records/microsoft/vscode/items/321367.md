# Issue #321367 — Custom Editor feature does not work with Virtual Documents

[https://github.com/microsoft/vscode/issues/321367](https://github.com/microsoft/vscode/issues/321367)

## Summary

Confirmed from source: `TextResourceEditorInput` (used for virtual documents from `TextDocumentContentProvider`) does not override `toUntyped()`, so the 'Reopen Editor With' command silently bails out. The `editor.associations` setting also doesn't take effect because the open path for virtual documents bypasses the editor resolver. This is a real gap with no fix on main.

## Change summary

Custom Editor features ('Reopen Editor With', `editor.associations`) do not work with virtual documents created via `TextDocumentContentProvider`, because the editor input for those documents cannot be serialized to an untyped form.

## Best solution

Implement `toUntyped()` on `TextResourceEditorInput` (or its parent `AbstractTextResourceEditorInput`) to return a valid `IResourceEditorInput` for virtual documents, enabling the editor resolver to offer alternative editors. Also ensure the initial open path (`showTextDocument` / `vscode.open`) respects `editor.associations` by routing through the editor resolver for non-`file` schemes.
