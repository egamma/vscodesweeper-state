# Issue #289094 — Incorrect warning "The model wants to edit files outside of your workspace" (if using symlinks?)

[https://github.com/microsoft/vscode/issues/289094](https://github.com/microsoft/vscode/issues/289094)

## Summary

Keep open: another reporter confirms the warning with symlinked directories over Remote SSH, and current edit-confirmation code still checks resolved targets against workspace paths. The related merged fix addresses nonexistent-file reads, not this existing-file editing scenario.

## Change summary

Copilot repeatedly requests outside-workspace edit approval for existing files accessed through symlinked workspace folders.

## Best solution

Establish the intended approval behavior for explicitly opened symlinked workspace roots versus links escaping those roots, then ensure edit confirmation consistently recognizes the former without weakening protection for the latter. Investigate this in the built-in Copilot edit-confirmation path; the related nonexistent-file fix does not establish resolution.
