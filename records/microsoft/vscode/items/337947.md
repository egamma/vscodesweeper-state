# Issue #337947 — Allow me to stash the changes made by copilot in a session

[https://github.com/microsoft/vscode/issues/337947](https://github.com/microsoft/vscode/issues/337947)

## Summary

This is a valid, currently missing chat-editing capability that should be routed to the chat editing owners. Current main can keep, undo, inspect, and persist session edits, but it has no action for temporarily shelving one session's changes and reapplying them later.

## Change summary

Allow users to temporarily remove changes attributed to one Copilot chat session and reapply those changes later.

## Best solution

Provide a session-scoped shelve and reapply workflow that preserves unrelated user edits and changes from other sessions, with explicit conflict handling when the saved changes can no longer be applied cleanly.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSessionStorage.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`
- **Validation:** Extend the chat editing action, service, and storage tests to cover shelving one session's edits, preserving unrelated workspace changes, restoring the shelved edits, and surfacing conflicts without overwriting newer content.
- **Behavior:**

  > A user can temporarily remove the outstanding changes attributed to one chat session and later reapply them from that session. Unrelated user changes and changes attributed to other sessions remain untouched. The operation remains discoverable after leaving or reopening the session, and a conflicting reapply must not silently overwrite newer content.
- **Trace:**

  > The current toolbar in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts offers Keep, Undo, Explain, and View All Edits. IChatEditingSession in src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts tracks session-specific entries, snapshots, and diffs, while ChatEditingSessionStorage persists initial contents, the recent snapshot, and the timeline. The built-in Git API supports repository-level stashes, but it does not inherently encode chat-session or overlapping-hunk ownership. A maintainer identified this capability and the prerequisite attribution/lifecycle work at https://github.com/microsoft/vscode/issues/253864#issuecomment-3594506685. Keep the scope on user-controlled shelving of one session; the agent-triggered Git-stash tracking bug in https://github.com/microsoft/vscode/issues/297985 and partial cloud-change reapplication in https://github.com/microsoft/vscode/issues/291756 are related but distinct behaviors.
- **Open decisions:**
  - Should a session stash be VS Code-managed session state that also works outside Git repositories, or a real Git stash exposed through repository history?
  - When a file contains overlapping user edits or edits from multiple chat sessions, should shelving operate only on attributable hunks, include the whole file, or block and ask the user to resolve ownership?
  - How long should a shelved session remain reapplicable: only for the current workspace session, across reloads, or for the lifetime of the saved chat?

## Evidence

- **current action surface:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts registers Keep, Undo, Explain, and View All Edits actions for the chat editing toolbar, but no stash, shelve, or reapply action.
- **current session model:** IChatEditingSession in src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts exposes snapshots, undo/redo, accept/reject, and per-session diffs, but no operation that temporarily removes and later reapplies a session's outstanding changes.
- **persisted edit state:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSessionStorage.ts already persists each session's initial file contents, recent snapshot, and timeline, establishing relevant state but not a user-visible shelved state.
- **maintainer direction:** A maintainer explicitly described future support for "stashing changes from chat sessions and reapplying them later" while noting that multiple-session attribution requires broader lifecycle work: https://github.com/microsoft/vscode/issues/253864#issuecomment-3594506685.
- **canonical check:** https://github.com/microsoft/vscode/issues/253864 is older and related, but its observable request is automatic acceptance when starting sessions, committing, or switching modes; it does not request the same user-triggered per-session stash workflow, so it does not meet the stronger duplicate bar for this re-reviewed item.
