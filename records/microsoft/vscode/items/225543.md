# Issue #225543 — Allow Shift+Tab to focus on first attachment in Quick Chat

[https://github.com/microsoft/vscode/issues/225543](https://github.com/microsoft/vscode/issues/225543)

## Summary

Keep open: Quick Chat still places attachments after the input in DOM order, and the inspected code does not provide the requested Shift+Tab attachment navigation. This team-authored Backlog request has no verified fixing commit or qualifying duplicate.

## Change summary

Allow Shift+Tab from Quick Chat's input to reach the first attachment instead of following the unrelated preceding tab stop.

## Best solution

Provide predictable backward keyboard navigation from the Quick Chat input to its attachments, consistent with panel chat. Establish how this interacts with editor indentation and existing keyboard navigation before implementation, and document the resulting behavior in Chat accessibility help.

- **Behavior:**

  > Quick Chat currently requires forward tabbing through intervening controls to reach attached context. The desired experience is that Shift+Tab from its input reaches the first attachment, providing keyboard access comparable to panel chat. Acceptance should cover one and multiple attachments, visible focus, subsequent navigation and removal, and unchanged behavior when there are no attachments. The interaction with editor indentation mode must be settled before implementing the shortcut.
- **Trace:**

  > QuickChat.render in src/vs/workbench/contrib/chat/browser/widgetHosts/chatQuick.ts creates a compact ChatWidget inside a Quick Input widget. Its attachment handler provides left/right navigation within already-focused attachments, but the inspected input handler and chat action registrations do not provide the requested backward entry shortcut. The attachment introduction was completed by https://github.com/microsoft/vscode/pull/225538; https://github.com/microsoft/vscode/issues/225499#issuecomment-2287314034 explicitly leaves this navigation request outstanding. Preserve panel-chat behavior, attachment selection and removal, Quick Chat dismissal, and unrelated editor shortcuts. The trace establishes the DOM-order gap, but does not establish runtime keybinding precedence between the editor and Quick Input host.
- **Open decisions:**
