# Issue #346444 — Integrated browser: don't dim the page for hovers (tab hovers, tooltips)

[https://github.com/microsoft/vscode/issues/346444](https://github.com/microsoft/vscode/issues/346444)

## Summary

The existing maintainer decision explicitly covers tooltip-triggered browser dimming: the screenshot represents a temporarily noninteractive page. This requests an exception to that intentional behavior, rather than reporting an implementation defect.

## Change summary

Keep the integrated browser undimmed while transient hovers overlap its screenshot placeholder.

## Best solution

Retain the existing pause indication under the documented design decision. Exempting hovers would require an explicit product-design reconsideration, since the native page remains hidden and noninteractive during the screenshot swap.

- **Reason:** Reducing repeated brightness changes addresses accessibility and workbench interaction comfort, although that does not override the established design decision.

## Evidence

- **Verified design precedent:** https://github.com/microsoft/vscode/issues/327685 is closed as NOT_PLANNED with *as-designed. Its report explicitly includes tooltips overlapping the browser, so the precedent covers this report's hover-triggered dimming; it is not an eligible open duplicate target.
- **Maintainer explanation:** https://github.com/microsoft/vscode/issues/327685#issuecomment-5098690860 explains that any overlapping workbench element requires hiding the native WebContentsView and displaying a screenshot. Dimming deliberately communicates that the page cannot currently be interacted with, including when the overlap comes from a tooltip.
- **Accessibility feedback considered:** https://github.com/microsoft/vscode/issues/327685#issuecomment-5349281197 independently describes eye discomfort from repeated dimming when IntelliSense appears. This supports the usability concern, but the inspected discussion contains no subsequent maintainer reversal of the design decision.
- **Current implementation and capability check:** src/vs/workbench/contrib/browserView/electron-browser/overlayManager.ts categorizes monaco-hover as BrowserOverlayType.Hover. WebContentsViewHost._refreshOverlayObscured treats every overlapping overlay as obscuring; _shouldShowPage hides the native page and _refresh activates the pause element. There is no hover exemption or registered browser dimming setting in the inspected browser contribution sources.
- **Blur already differs on main:** src/vs/workbench/contrib/browserView/electron-browser/media/browser.css applies a 15% editor-background tint to the visible pause overlay. Screenshot blur is now restricted to browser-container--dragging, not ordinary hovers. https://github.com/microsoft/vscode/pull/289247 replaced the earlier blur presentation with deliberate pause feedback; it does not implement the requested hover exemption.
