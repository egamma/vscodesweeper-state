# Issue #306227 — Copilot Agent Skill Validation Conflicts with "skill" Language ID (Cadence SKILL Programming Language)

[https://github.com/microsoft/vscode/issues/306227](https://github.com/microsoft/vscode/issues/306227)

## Summary

The collision remains on current main: every open model with language ID `skill` is treated as an agent skill and validated, regardless of its filename or location. This is a bounded core bug and should remain open for a path-aware validation fix.

## Change summary

Prevent Cadence SKILL source files using the `skill` language ID from receiving agent-skill diagnostics.

## Best solution

Restrict prompt validation for `PromptsType.skill` to actual `SKILL.md` resources recognized as agent skills, while preserving all supported workspace, personal, configured, and extension-contributed skill locations.

- **Behavior:**

  > A Cadence source file such as `example.il` may use the `skill` language ID without being interpreted or diagnosed as an agent skill. Actual agent `SKILL.md` files in supported skill locations continue to receive agent-skill validation. Acceptance requires that the Cadence model has no `prompts-diagnostics-provider` markers while a malformed genuine skill file still reports its missing metadata.
- **Trace:**

  > `PromptValidatorContribution.acquire()` in `src/vs/workbench/contrib/chat/browser/promptSyntax/promptFileContributions.ts` maps `model.getLanguageId()` through `getPromptsTypeForLanguageId()` and creates `ModelTracker` solely from that result. `getPromptsTypeForLanguageId()` in `src/vs/workbench/contrib/chat/common/promptSyntax/promptTypes.ts` maps every `skill` model to `PromptsType.skill`; `ModelTracker.validate()` consequently calls `PromptValidator.validate()`, whose skill branch emits the missing-name marker. The boundary is model eligibility for agent-skill validation: do not rename the Cadence language, remove validation from genuine skills, or restrict skills to `.github/skills`, because `promptFileLocations.ts` supports additional default and configured sources. The external report https://github.com/herbertagosto/code-skill/issues/15 confirms the collision but does not replace the core fix.

## Evidence

- **source reproduction:** `src/vs/workbench/contrib/chat/browser/promptSyntax/promptFileContributions.ts` derives `promptType` exclusively from `model.getLanguageId()` and constructs a `ModelTracker` for every `skill` model; `ModelTracker.validate()` then invokes `PromptValidator` without checking the resource path or filename.
- **diagnostic path:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptTypes.ts` maps the shared language ID `skill` directly to `PromptsType.skill`, while `promptValidator.ts` reports the missing-name diagnostic whenever that type is supplied.
- **language collision:** `extensions/prompt-basics/package.json` contributes the agent-skill language with ID `skill`, so an external Cadence extension or `files.associations` entry using the same ID enters the core validation path.
- **supported locations:** `src/vs/workbench/contrib/chat/common/promptSyntax/config/promptFileLocations.ts` defines multiple valid skill roots (`.agents`, `.github`, `.claude`, personal, and configurable locations), so the fix should use the existing skill-discovery model rather than hard-code only `.github/skills`.
- **related reports:** https://github.com/herbertagosto/code-skill/issues/15 records the same collision in the third-party language extension, but it does not own the erroneous VS Code validation path. The later https://github.com/microsoft/vscode/issues/310130 is not an older same-symptom canonical for this re-reviewed issue.
