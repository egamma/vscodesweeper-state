# Issue #288087 — Reveal in Explorer View doesnt work if explorer is moved to middle column

[https://github.com/microsoft/vscode/issues/288087](https://github.com/microsoft/vscode/issues/288087)

## Summary

Confirmed on current main: the search result action assumes the Explorer is in the primary side bar, so moving it to the panel prevents the file from being selected. Keep the issue open while the directly linked fixing PR is reviewed.

## Change summary

Reveal in Explorer View from search results fails when the Explorer view has been moved from the primary side bar.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/334276, which delegates the search action to the location-independent Reveal in Explorer command and adds regression coverage.

## Evidence

- **current source:** In src/vs/workbench/contrib/search/browser/searchActionsFind.ts, RevealInSideBarForSearchResultsAction.run opens VIEWLET_ID_FILES specifically at ViewContainerLocation.Sidebar, retrieves the Explorer view from that container, and calls setExpanded/select there. This directly reproduces the reported failure when Explorer has been moved to the panel or secondary side bar.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/334276 is open, contains `Fixes #288087`, identifies the same hard-coded side-bar lookup, and changes the action to use the generic location-independent `revealInExplorer` command with regression tests.
- **reporter confirmation:** The reporter confirmed that the problem remained after upgrading from VS Code 1.108.0.
