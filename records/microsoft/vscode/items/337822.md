# Issue #337822 — Authentication Loop with GitHub Copilot Enterprise (GHE)

[https://github.com/microsoft/vscode/issues/337822](https://github.com/microsoft/vscode/issues/337822)

## Summary

Fresh, well-corroborated regression: multiple independent users on Windows, Ubuntu, and macOS ARM64 confirm a repeated re-auth loop for GitHub Copilot Enterprise (GHE) sign-in starting in 1.139, resolved by rolling back to 1.138. The team has already tagged it `recent-regression`/`new release`, so this is clearly on the radar; keeping open pending a maintainer bisect since the shallow checkout here prevents pinpointing the exact introducing commit.

## Change summary

Signing in to GitHub Copilot with a GitHub Enterprise (GHE, *.ghe.com) instance repeatedly re-prompts for authentication instead of completing sign-in, after upgrading to VS Code 1.139.

## Best solution

Bisect the 1.138→1.139 changes touching extensions/github-authentication (the enterprise/session flow in src/flows.ts, src/common/env.ts's isHostedGitHubEnterprise/isSupportedTarget checks, and session validation in the auth provider) with a real *.ghe.com test tenant to find why sessions aren't recognized as valid after the OAuth callback.

  > Signing in to Copilot against a GitHub Enterprise (*.ghe.com) tenant in VS Code 1.139 completes the browser OAuth flow but VS Code re-prompts for sign-in almost immediately afterward, looping indefinitely; on 1.138 sign-in persists normally.
