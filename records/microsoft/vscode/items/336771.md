# Issue #336771 — Terminal: user-overridden built-in "PowerShell" profile path is ignored on Windows, falls back to Windows PowerShell 5.1

[https://github.com/microsoft/vscode/issues/336771](https://github.com/microsoft/vscode/issues/336771)

## Summary

Confirmed on current main: VS Code's configuration model deep-merges the built-in `PowerShell` profile default (`{source:'PowerShell'}`) with the user's override object, so the resolved profile ends up with both `source` and `path` keys — and `getValidatedProfile` checks `source` first, silently discarding the user's `path` array and falling back to auto-detected PowerShell 5.1.

## Change summary

A user-supplied `path` array for the reserved `PowerShell` terminal profile name on Windows is ignored in favor of auto-detected Windows PowerShell 5.1.

## Best solution

In `getValidatedProfile` (src/vs/platform/terminal/node/terminalProfiles.ts), check for an explicit `path` before falling back to `source` when both are present on the merged profile object, since the settings schema never intends both to be set by the user simultaneously — an explicit `path` should win.

## Evidence

- **config deep-merge:** src/vs/platform/configuration/common/configurationModels.ts mergeContents() (line ~219) recursively merges default and user object-typed settings key-by-key; terminal.integrated.profiles.windows default defines PowerShell as {source:'PowerShell', icon}, so a user override that only sets {icon, path} for the 'PowerShell' key ends up merged into {source, icon, path} at runtime.
- **source-precedence bug:** src/vs/platform/terminal/node/terminalProfiles.ts getValidatedProfile() (line 199) checks `hasKey(profile, {source:true})` first; since the merged object always carries `source:'PowerShell'` from the default, the user's `path` array is never consulted, and the auto-detected pwsh source paths (which don't include custom install locations) are used instead, ultimately falling back to the WindowsPowerShell v1.0 path at line 103.
- **schema intent:** The JSON schema for terminal.integrated.profiles.windows (src/vs/platform/terminal/common/terminalPlatformConfiguration.ts ~250) models `source` and `path` variants as mutually exclusive (`anyOf` with `required: ['source']` vs a path-only variant), confirming both keys co-existing at runtime is a merge artifact, not user intent.
