# Issue #117728 — Feedback on folding UX for notebook

[https://github.com/microsoft/vscode/issues/117728](https://github.com/microsoft/vscode/issues/117728)

## Summary

Keep open for the remaining notebook folding hierarchy and range-preview improvements. Current hidden-cell counts address folded-state discoverability in part, but the existing controls do not cover the full request.

## Change summary

Make notebook heading hierarchy, the range affected by folding, and collapsed sections easier to recognize.

Agree on a notebook folding presentation that communicates nested section scope before collapsing, while retaining the existing hidden-cell count and expand affordance. ## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`, `src/vs/workbench/contrib/notebook/browser/view/cellParts/markupCell.ts`, `src/vs/workbench/contrib/notebook/browser/view/cellParts/foldedCellHint.ts`, `src/vs/workbench/contrib/notebook/browser/controller/foldingController.ts`, `src/vs/workbench/contrib/notebook/browser/media/notebookFolding.css`
- **Validation:** Manually open a notebook with H1, nested H2/H3 sections, intervening code cells, and a following peer heading. Verify that the agreed hierarchy cue distinguishes nesting, the folding preview identifies exactly the cells subsequently hidden, and collapsing retains an accurate hidden-cell count and working expand control.
- **Behavior:**

  > Users should understand which notebook headings contain subordinate sections and which cells a folding action will hide before activating it. Collapsed sections should remain visibly discoverable. Acceptance should use nested Markdown headings with code cells and a following peer heading, checking that the indicated range matches the actual folded cells and excludes the next peer section.
- **Trace:**

  > In the checkout, notebookEditorWidget.ts assigns a shared gutter position to folding indicators, and MarkupCell.layoutFoldingIndicator in view/cellParts/markupCell.ts switches icons based on folding state rather than heading depth. The GitHub main implementation of FoldedCellHint already renders hidden-cell counts and an expand affordance, so that part must be preserved. FoldingController handles chevron activation and applies hidden ranges; the inspected hover CSS reveals the icon rather than previewing that range. notebook.showFoldingControls changes visibility, while indented sticky headers are a separate contextual surface. The unresolved boundary is the user-visible presentation of hierarchy and range scope, not the existing folding semantics. Coordinate visual choices with https://github.com/microsoft/vscode/issues/199787, which is related styling work rather than a canonical duplicate.
- **Open decisions:**
  - Should heading depth be communicated persistently in the cell gutter, or only through a contextual section guide?
  - Should the range preview appear only on chevron hover, or also through keyboard focus, and how should nested section boundaries be distinguished?
