# Issue #330364 — Support top-level model in managed settings while retaining permissions.model

[https://github.com/microsoft/vscode/issues/330364](https://github.com/microsoft/vscode/issues/330364)

## Summary

Confirmed on main: VS Code only reads the legacy `permissions.model` managed-settings key (via `COPILOT_MODEL_KEY` in copilotManagedSettings.ts), with no support yet for a top-level `model` key. This is a concrete, well-specified enterprise managed-settings gap worth routing to the chat/policy owners.

## Change summary

Add support for reading a new top-level `model` managed setting (across server, file, and native MDM), taking precedence over the legacy `permissions.model`, while still honoring `permissions.model` for existing deployments.

## Best solution

Extend `COPILOT_MODEL_KEY`/`managedModelValue()` in src/vs/platform/policy/common/copilotManagedSettings.ts so the normalized managed-settings bag also exposes a top-level `model` key, with `model` taking priority over `permissions.model` when both are present, keeping the existing scalar-flattening pipeline (`flattenManagedSettingsValue`) consistent across server/file/native MDM sources.
