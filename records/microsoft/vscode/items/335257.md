# Issue #335257 — Copilot Chat: nested runSubagent calls rejected 3 levels deep even when target agent is in the calling agent's agents: allow-list

[https://github.com/microsoft/vscode/issues/335257](https://github.com/microsoft/vscode/issues/335257)

## Summary

Keep open: this is a source-confirmed regression on current main. Nested `runSubagent` validation reads the root request's allow-list rather than the invoking subagent's forwarded allow-list, incorrectly rejecting valid depth-three delegation.

## Change summary

Nested custom agents cannot invoke their own allowed subagents because allow-list validation remains bound to the root chat agent.

## Best solution

Validate each nested invocation against its immediate caller's `modeInstructions.allowedSubagents`, while preserving root-level enforcement and the existing nesting-depth limit. The caller context must remain correct for concurrent sibling subagents rather than relying on session-global stack state.

## Evidence

- **current source:** On current main, `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts` obtains `currentModeInstructions` from `model.getRequests().at(-1)` in `invoke` and `getCurrentModeInstructions`, and both preparation and invocation validate against that value. The selected child allow-list is forwarded in `agentRequest.modeInstructions`, but the next invocation does not read it.
- **confirmed regression:** Commit d679b159e16d15d24e364b627ab85e144899ead0 (https://github.com/microsoft/vscode/commit/d679b159e16d15d24e364b627ab85e144899ead0), merged through https://github.com/microsoft/vscode/pull/331442, introduced both `validateSubagentAllowed` calls and the child allow-list forwarding.
