# Issue #335257 — Copilot Chat: nested runSubagent calls rejected 3 levels deep even when target agent is in the calling agent's agents: allow-list

[https://github.com/microsoft/vscode/issues/335257](https://github.com/microsoft/vscode/issues/335257)

## Summary

Real functional bug still present on main: the subagent allow-list check always looks at `model.getRequests().at(-1)?.modeInfo?.modeInstructions` for the whole session, not the modeInstructions of whichever agent is currently making the nested call, so deeper nesting levels are validated against the wrong (likely root) allow-list.

## Change summary

Nested `runSubagent` calls three levels deep are rejected even when the immediate calling agent's allow-list permits the target agent.

## Best solution

In src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts, replace the `model.getRequests().at(-1)` lookup used by `validateSubagentAllowed`/`getCurrentModeInstructions` with a mechanism that tracks the *currently invoking* subagent's own modeInstructions per nesting level (not just the session's last top-level request), so the allow-list check reflects the direct caller at any depth.
