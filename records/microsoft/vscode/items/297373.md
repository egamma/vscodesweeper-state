# Issue #297373 — Allow the agent to check if the user interacted with the browser

[https://github.com/microsoft/vscode/issues/297373](https://github.com/microsoft/vscode/issues/297373)

## Summary

Keep open: browser tools expose current page state but do not explicitly tell the agent that the user interacted between calls. The related newer control-state request does not supersede this older, team-authored request under the re-review rules.

## Change summary

Inform the agent on its next browser tool call when the user has interacted with the shared browser since its previous call.

## Best solution

Provide a reliable, page-specific user-interaction indication in browser tool responses while preserving sharing and network-policy boundaries. Keep this notification request distinct from the broader proposal to lock pages or pause automation.

## Plan brief

- **Likely files:** `src/vs/platform/browserView/electron-main/browserView.ts`, `src/vs/platform/browserView/common/browserView.ts`, `src/vs/platform/browserView/node/playwrightTab.ts`, `src/vs/workbench/contrib/browserView/electron-browser/tools/browserToolHelpers.ts`
- **Validation:** In an Electron browser-tool integration scenario, share a page, make a browser tool call, interact with the page manually, and make another call: its response must identify intervening user interaction. Repeat with automation-only input and with another page to check attribution and isolation; confirm private or network-blocked page information is not disclosed.
- **Behavior:**

  > An agent using a shared integrated-browser page can learn on its next browser tool call that the user interacted with that page in the meantime. A changed snapshot alone is insufficient because it does not explain who changed the page. Agent-generated input must not be reported as human interaction, and activity on another page must not be misattributed. This request does not require locking user input or automatically pausing the agent.
- **Trace:**

  > BrowserView in src/vs/platform/browserView/electron-main/browserView.ts tracks a private last-user-gesture timestamp for popup handling. PlaywrightTab.getSummary in src/vs/platform/browserView/node/playwrightTab.ts supplies page snapshots and diagnostic events, and browserToolHelpers.ts forwards that summary into tool results without human-interaction metadata. These paths establish the missing notification, but the inspection did not establish a reliable discriminator between native human input and CDP-injected input or complete the cross-process propagation trace. Preserve existing sharing, network-policy, popup, and automation behavior. https://github.com/microsoft/vscode/issues/341287 is related broader control-state work, not authority to add locking or pause semantics here.
