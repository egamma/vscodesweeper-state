# Issue #229233 — "Ghost" entry created when switching between "new file" and "new folder" in Explorer pane with compact folders enabled

[https://github.com/microsoft/vscode/issues/229233](https://github.com/microsoft/vscode/issues/229233)

## Summary

The confirmed Explorer bug remains source-reproducible on current main: starting the second create action replaces the active editable item without completing the first placeholder, and compressed-tree rendering can retain that stale entry.

## Change summary

Switching between New File and New Folder while a compact folder is selected leaves a nonexistent ghost entry in the Explorer.

## Best solution

Ensure that starting a file or folder creation cleanly completes the existing create interaction before the next temporary Explorer item is rendered, without changing normal create, cancel, or compact-folder behavior.

- **Behavior:**

  > With `explorer.compactFolders` enabled, starting New File and then New Folder, or the reverse, must replace the active creation input without leaving any additional Explorer entry. Cancelling the remaining input must leave the model and tree identical to the filesystem. Normal creation under compact and non-compact folders must remain unchanged. Acceptance is a regression test proving there is at most one temporary child throughout the switch and none after cancellation.
- **Trace:**

  > The two commands converge on `openExplorerAndCreate` in src/vs/workbench/contrib/files/browser/fileActions.ts. That function adds a `NewExplorerItem` before calling `ExplorerService.setEditable`, even when another temporary item is already editable; only the original item's `onFinish` removes that item. In src/vs/workbench/contrib/files/browser/views/explorerViewer.ts, compressed rendering finds the currently editable element within the compressed node, and disposing the previous input calls `done(false, false)`, which skips `onFinish`. This leaves the previous tree/model placeholder lifecycle incomplete when the second command refreshes the compressed branch. Keep the boundary to switching active create interactions: do not alter committed file creation, rename behavior, or general compact-folder compression.
