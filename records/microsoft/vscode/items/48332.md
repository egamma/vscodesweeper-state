# Issue #48332 — end keyword matching for Ruby, Lua, Julia, Elixir, Crystal and others

[https://github.com/microsoft/vscode/issues/48332](https://github.com/microsoft/vscode/issues/48332)

## Summary

A real core capability gap remains for language-aware matching of constructs such as `if/else/end`. This Backlog request has 39 community upvotes and already carries the correct area labels.

## Change summary

Support matching and navigation between keyword-delimited blocks in Ruby, Lua, Julia, Elixir, Crystal, and similar languages.

## Best solution

Extend the editor bracket model to represent multi-stage block constructs and contextual keywords, then enable the capability in applicable built-in language configurations and expose it reliably to external language extensions.

## Evidence

- **current built-in behavior:** extensions/ruby/language-configuration.json and extensions/lua/language-configuration.json still register only punctuation bracket pairs; their block keywords are used for indentation but not bracket matching.
- **core limitation:** src/vs/editor/common/languages/supports/languageBracketsConfiguration.ts models brackets as two-element open/close pairs, while src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts maps each textual token to one opening or closing token. This does not model intermediate constructs such as `else`.
- **partial workaround:** https://github.com/microsoft/vscode/issues/176694 documents user-configured `editor.language.brackets` pairs, but also records incorrect or incomplete handling for `do`, inline forms, strings, macros, and intermediate keywords.
- **related remaining work:** https://github.com/microsoft/vscode/issues/170369 remains open for three-or-more-element colorized constructs such as `if/then/else/end`; it is related but narrower than this request's matching and navigation scope.
