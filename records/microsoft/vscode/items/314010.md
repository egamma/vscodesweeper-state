# Issue #314010 — Bug: Tools that work in custom agents (local) and in Copilot CLI (default agent), break when both are combined

[https://github.com/microsoft/vscode/issues/314010](https://github.com/microsoft/vscode/issues/314010)

## Summary

Well-documented bug report showing that built-in tools (askQuestions, todo) are available when using a custom agent locally and when using the default agent with Copilot CLI, but break specifically when combining a custom agent with Copilot CLI delegation. No fix found on main. Routing to the agent host area.

## Change summary

Built-in tools like `#tool:todo` and `#tool:vscode/askQuestions` become unavailable when a custom agent (.agent.md) delegates execution to Copilot CLI, despite working in both local custom-agent sessions and default-agent CLI sessions.

## Best solution

Investigate the tool-forwarding path in `agentHostActiveClientService.ts` and `agentHostSessionHandler.ts` to ensure that when a custom agent (mode) is selected and the session target is Copilot CLI, the same client tools are resolved and sent to the agent host as in local sessions and default-agent CLI sessions. The `getClientTools(sessionType)` call likely receives a different sessionType or the custom agent's tool references aren't being bundled into the agent host session configuration.
