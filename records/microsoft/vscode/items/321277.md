# Issue #321277 — Coding agent wasting credits when waiting on command completion

[https://github.com/microsoft/vscode/issues/321277](https://github.com/microsoft/vscode/issues/321277)

## Summary

The terminal tool has received multiple rounds of anti-polling guidance and sync-mode improvements since this was filed (commits c2d6b5a81c8, a3ebc7b2f2d, 76ed37db800 on current main), but the underlying behavior is model-dependent — Gemini 3.5 Flash may still ignore the do-not-poll instructions. Route to area owners for evaluation on latest builds.

## Change summary

The coding agent polls terminal output with sleep commands instead of waiting for command completion, wasting credits on long-running scripts.

## Best solution

The terminal tool's system prompt now explicitly forbids polling and sleep commands, and sync mode waits for completion automatically. The reporter should test on the latest VS Code Insiders (1.125+) where these improvements shipped. If the issue persists with specific models (Gemini 3.5 Flash), the area owners may need to add stronger model-specific steering or enforce sync mode for one-shot commands. The second commenter's scenario (Gradle tasks timing out and restarting) may need separate investigation around the idle-silence timeout heuristic.
