# Issue #204972 — Merge editor: set boundary sashes

[https://github.com/microsoft/vscode/issues/204972](https://github.com/microsoft/vscode/issues/204972)

## Summary

The merge editor still lacks the boundary-sash integration requested here, and the discussion supports adding it. Keep this accepted Backlog request open; the related multi-diff request concerns a different editor.

## Change summary

Connect merge-editor horizontal and vertical sashes to surrounding workbench sashes so their junctions support simultaneous resizing.

## Best solution

Give the merge editor the same connected-resize interaction as the diff editor, including after changing merge-editor layouts or toggling the base view. Preserve existing independent resizing and layout persistence.

Repeat after mixed/column layout changes and base-view toggles, and confirm dragging away from junctions still resizes only the selected divider.
- **Behavior:**

  > The merge editor should support simultaneous resizing where its internal horizontal or vertical divider meets a surrounding workbench sash, matching existing connected-sash behavior. The reported sidebar/horizontal-divider junction must resize both boundaries in one drag. Connections should remain usable after layout changes and base-view toggles. Independent divider resizing and persisted layout behavior must remain unchanged.
- **Trace:**

  > MergeEditor in src/vs/workbench/contrib/mergeEditor/browser/view/mergeEditor.ts owns a MutableDisposable<Grid<IView>> and replaces its SerializableGrid in setGrid whenever applyLayout rebuilds the layout. It does not override EditorPane.setBoundarySashes or assign the grid's boundarySashes, so the workbench's boundary-sash forwarding currently reaches an inherited no-op. Grid and GridView already expose and propagate boundary sashes; the diff editor provides existing connected-sash prior art. Keep the scope to merge-editor adoption, not a redesign of shared grid or sash behavior. https://github.com/microsoft/vscode/issues/204971 concerns a separate multi-diff editor and must not absorb this request. The remaining planning work is establishing an executable UI regression check, since the existing merge-editor tests cover model and mapping behavior rather than sash interaction.
