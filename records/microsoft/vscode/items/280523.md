# Issue #280523 — Ranges reported as by the model do not match the file

[https://github.com/microsoft/vscode/issues/280523](https://github.com/microsoft/vscode/issues/280523)

## Summary

The issue remains valid: LLMs still produce inaccurate line ranges in chat responses. Significant work has improved the linkification instructions and infrastructure (symbol linkifier, inline code symbol linkifier, tree-sitter fallback for symbol anchors), but the fundamental LLM line-counting inaccuracy reported here is an inherent model limitation that hasn't been fully resolved. The team discussion favors symbol-based links over line-number links, and that direction has seen investment but no commit references this issue as fixed.

## Change summary

LLM-reported line number ranges in chat responses do not match actual file locations, producing misleading file links.

## Best solution

Continue investing in symbol-based references (e.g. `file.ts#registerStateActions`) over line-number links — the symbol linkifier and tree-sitter fallback work (commit 9384620560b) moves in this direction. The prompt instructions could further de-emphasize line-number links in favor of symbol anchors. The remaining gap is that models still hallucinate line numbers when they do use them, which is hard to fix without post-hoc validation of model-emitted ranges against actual file content.
