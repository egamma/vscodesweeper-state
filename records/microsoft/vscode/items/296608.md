# Issue #296608 — Error when searching after opening file by clicking link in terminal with line number

[https://github.com/microsoft/vscode/issues/296608](https://github.com/microsoft/vscode/issues/296608)

## Summary

Still reproducible on main: URIs with fragments (e.g. `#L65`) from terminal links (or Markdown links) pass through to the search model unstripped, causing `createAndConfigureFileMatch` to throw because the fragment makes the path comparison fail. No fix has landed.

## Change summary

Opening a file via a terminal link that includes a line-number fragment (e.g. `file.php#L65`) breaks the Search panel — every subsequent search throws "is not a descendant of" because the URI fragment is not stripped before the path-containment check.

## Best solution

Strip the URI fragment (e.g. `uri.with({ fragment: '' })`) before the `isEqualOrParent` check in `createAndConfigureFileMatch` (`src/vs/workbench/contrib/search/browser/searchTreeModel/folderMatch.ts` ~line 508). Additionally, the terminal link opener should strip fragments and convert them to line/column selections so the editor jumps to the right line without polluting the URI.
