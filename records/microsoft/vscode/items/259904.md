# Issue #259904 — "allow for session" in notebook inline chat should allow for that notebook until it is closed

[https://github.com/microsoft/vscode/issues/259904](https://github.com/microsoft/vscode/issues/259904)

## Change summary

Make a notebook inline-chat session approval persist across inline interactions in that notebook until the notebook closes.

Provide notebook-scoped approval continuity across inline-chat interactions, ending when the notebook closes without granting approval to other notebooks. First trace the active notebook-tool confirmation contribution and its interaction with the shared approval service.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/inlineChat/browser/inlineChatNotebook.ts`, `src/vs/workbench/contrib/inlineChat/browser/inlineChatSessionServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/tools/languageModelToolsConfirmationService.ts`, `src/vs/workbench/contrib/chat/common/tools/languageModelToolsConfirmationService.ts`
- **Validation:** With notebook inline-agent behavior enabled and a tool requiring confirmation, grant session approval in notebook A, finish the inline interaction, then invoke the same tool from another cell in A: it should remain approved. Notebook B must still require approval, and closing and reopening A must require approval again. Verify existing workspace/profile approvals and managed approval restrictions remain unchanged.
- **Behavior:**

  > A session approval granted through notebook inline chat remains effective for subsequent inline interactions in that notebook while it stays open. Completing an interaction or moving to another cell must not require the same approval again. The grant must not authorize another notebook and must expire when its notebook closes. Existing broader explicit approvals and enterprise restrictions retain their behavior.
- **Trace:**

  > The default LanguageModelToolsConfirmationService in src/vs/workbench/contrib/chat/browser/tools/languageModelToolsConfirmationService.ts uses GenericConfirmStore with tool/combination-keyed memory entries; this default does not express notebook identity or notebook-close expiry. The confirmation reference in src/vs/workbench/contrib/chat/common/tools/languageModelToolsConfirmationService.ts carries chatSessionResource, and registered tool contributions can override default approval behavior. InlineChatNotebookContribution in src/vs/workbench/contrib/inlineChat/browser/inlineChatNotebook.ts accepts sibling cell sessions when a new session starts, while inlineChatSessionServiceImpl.ts disposes settled inline sessions. The remaining diagnosis is to identify which confirmation contribution the notebook tool actually uses and how notebook identity and lifetime reach that path; the shared service alone does not prove the complete behavior. Preserve approval isolation, managed restrictions, and non-notebook approval semantics. https://github.com/microsoft/vscode/issues/259903 tracks this request explicitly; https://github.com/microsoft/vscode/issues/258605 concerns related but distinct sequential-cell confirmation friction.
