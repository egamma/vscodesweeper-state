# Issue #331690 — VScode update redownloading patch

[https://github.com/microsoft/vscode/issues/331690](https://github.com/microsoft/vscode/issues/331690)

## Summary

Real, well-diagnosed bug: the remote CLI's DownloadCache unconditionally discards a fully-staged server download if the process is killed just before the final rename, forcing a wasteful re-download. An open PR already fixes this with 'Fixes #331690' and unit tests, so this should stay open until that PR merges.

## Change summary

After VS Code Remote/WSL is closed right as a server-update download finishes but before the final rename, the next launch re-downloads the whole patch instead of reusing the already-complete staged files.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/331752, which adds a completion marker to DownloadCache::create() in cli/src/download_cache.rs so a fully-staged download from an interrupted run is reused instead of re-fetched; close this issue once that PR merges.
