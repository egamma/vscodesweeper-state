# Issue #336671 — Background agent idle notifications falsely report multi-turn agents as complete

[https://github.com/microsoft/vscode/issues/336671](https://github.com/microsoft/vscode/issues/336671)

## Summary

Confirmed on current main: `agent_idle` is translated into terminal completion wording even though the same multi-turn agent remains resumable. This team-authored issue should stay open as a bounded Agent Host correctness bug.

## Change summary

Present background-agent idle notifications as a nonterminal waiting state rather than saying the reusable agent is complete.

## Best solution

Differentiate `agent_idle` from `agent_completed` in the shared Copilot notification translation, retaining the wake-up behavior while using nonterminal wording consistently in live and restored transcripts.

- **Behavior:**

  > When a multi-turn background agent enters `agent_idle`, its notification states that the current turn finished and the agent is waiting or otherwise remains available for follow-up; it must not claim that the agent itself is complete. An `agent_completed` notification continues to use terminal completed or failed wording. The same distinction appears in notifications received live, appended during an active parent turn, and reconstructed from persisted history. Resuming the idle agent can therefore coexist with its earlier notification without producing contradictory completion and running states.
- **Trace:**

  > The defect is in `buildCopilotSystemNotification` in src/vs/platform/agentHost/node/copilot/copilotSystemNotification.ts: its distinct `agent_idle` branch currently emits `Background agent {0} is complete`. CopilotAgentSession uses this helper for live `ResponsePartKind.SystemNotification` parts, while mapSessionEvents uses it for history replay, so the same semantic error reaches both paths. Existing assertions in copilotAgentSession.test.ts and mapSessionEvents.test.ts pin the incorrect text and provide direct fail-before/pass-after coverage. Keep `startsTurn: true`, notification routing, agent lifecycle state, resumption behavior, and `agent_completed` completed/failed wording unchanged; the reported defect is limited to the user-visible semantics of `agent_idle`. The wording originated in https://github.com/microsoft/vscode/pull/323805.
