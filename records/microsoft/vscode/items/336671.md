# Issue #336671 — Background agent idle notifications falsely report multi-turn agents as complete

[https://github.com/microsoft/vscode/issues/336671](https://github.com/microsoft/vscode/issues/336671)

## Summary

Confirmed on main: `buildCopilotSystemNotification` in copilotSystemNotification.ts hard-codes 'is complete' wording for the nonterminal `agent_idle` event, and that permanent system-notification part is never revised when the agent later resumes — producing the contradictory UI described. Real, well-diagnosed, bounded fix.

## Change summary

When a multi-turn background agent goes idle after finishing a turn, VS Code's system notification says the agent 'is complete', which is contradicted once the parent resumes it with write_agent.

## Best solution

Give the `agent_idle` branch of buildCopilotSystemNotification nonterminal wording (e.g. 'finished its turn and is waiting for follow-up'), reserving 'is complete'/'failed' language for `agent_completed`, and update the existing copilotAgentSession.test.ts assertions that currently pin the old wording.
