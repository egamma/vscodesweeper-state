# Issue #148609 — Caps Lock Activated Indication in message box that requires a password 

[https://github.com/microsoft/vscode/issues/148609](https://github.com/microsoft/vscode/issues/148609)

## Summary

Keep open: password quick inputs still lack a VS Code-provided Caps Lock indication, and a maintainer explicitly supported adding one. The matching open report is newer, so it cannot replace this previously reviewed issue as the canonical.

## Change summary

Show a Caps Lock indication while entering passwords in quick inputs, including Git and SSH prompts.

## Best solution

Provide a consistent, accessible Caps Lock indication in the shared password quick-input surface without replacing caller-provided validation messages or changing password handling. Retain this older accepted request as the tracking issue for the matching newer report.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputBox.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`
- **Validation:** Exercise a quick InputBox with password=true: enable Caps Lock before opening it, toggle Caps Lock while focused, and verify the indication reflects the detected state without revealing the password or blocking acceptance. Repeat with caller-provided validation text, then reopen a non-password input and verify no indication leaks into it. Check macOS, Windows, Linux, and screen-reader presentation; add browser tests for modifier-state transitions and shared-widget reuse.
- **Behavior:**

  > Password quick inputs should indicate when Caps Lock is active so users can recognize a likely cause of an incorrect password. The indication should update as Caps Lock changes and should not appear in ordinary text quick inputs. Password masking, acceptance, cancellation, and caller-provided validation must remain unchanged. Acceptance should cover Caps Lock already enabled before opening the prompt, toggling while focused, shared-widget reuse, and accessible presentation.
- **Trace:**

  > InputBox.password and InputBox.update in src/vs/platform/quickinput/browser/quickInput.ts propagate password mode to QuickInputBox. The password setter in src/vs/platform/quickinput/browser/quickInputBox.ts only changes the underlying HTML input type; neither that wrapper nor src/vs/base/browser/ui/inputbox/inputBox.ts contains Caps Lock detection. QuickInput.update owns prompt and validation rendering, which must remain intact. The missing capability is shared quick-input UX, not SSH-specific connection handling; do not change Git or Remote-SSH authentication protocols or broaden this work to the proxy-credentials window. https://github.com/microsoft/vscode/issues/235582 reports the same symptom but is newer. The record settles the goal and shared surface, but not the visual presentation or its relationship to existing validation content; native platform behavior also remains unverified.
- **Open decisions:**
  - Should Caps Lock appear as a persistent inline indicator beside the password field or as a separate warning message, and how should it remain discoverable when caller-provided validation is displayed?
