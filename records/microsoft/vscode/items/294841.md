## Evidence

- **Current Azure rejection:** extensions/copilot/src/extension/byok/vscode-node/azureProvider.ts imports hasExplicitApiPath from customOAIProvider.ts, whose implementation recognizes only /responses and /chat/completions. The reported https://<resource>.services.ai.azure.com/anthropic/v1/messages URL therefore misses both the explicit-path check and the Azure hostname branches, reaching 'Unrecognized Azure deployment URL'.
- **Protocol support is missing, not merely URL acceptance:** AzureBYOKModelProvider extends AbstractCustomOAIBYOKModelProvider. customOAIProvider.ts:createOpenAIEndPoint selects Responses metadata only for /responses; azureProvider.ts:azureSupportedEndpointsForUrl likewise never selects Messages. AzureOpenAIEndpoint in extensions/copilot/src/extension/byok/node/azureOpenAIEndpoint.ts supplies Entra authorization but has no Anthropic-specific integration.
- **Existing capability and discussion:** The June 9 comment on https://github.com/microsoft/vscode/issues/294841 reports success with vendor customendpoint, while July 9 reports an authentication failure and October 7 reports a working secret-input configuration. This supports an API-key alternative, but does not fix vendor azure or establish its Entra path.
