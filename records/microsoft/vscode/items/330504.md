# Issue #330504 — New tab (non-existing file) ignores User/Workspace settings

[https://github.com/microsoft/vscode/issues/330504](https://github.com/microsoft/vscode/issues/330504)

## Summary

Real bug: reporter confirmed the untitled-file indentation setting is overridden by the pasted content's own indentation, but only for new/unsaved files (never for existing files). Tracing the source shows a plausible mechanism specific to untitled documents that doesn't apply to file-backed editors, so this stays open pointed at the likely code path rather than a confirmed one-line fix.

## Change summary

Pasting code into a brand-new (untitled) tab silently adopts the pasted snippet's indentation (tabSize/insertSpaces) instead of respecting the user's `editor.detectIndentation: false` and explicit tabSize/insertSpaces settings; existing files are unaffected.

## Best solution

Investigate `UntitledTextEditorModel.onModelContentChanged` (src/vs/workbench/services/untitled/common/untitledTextEditorModel.ts), which calls `autoDetectLanguage()` on every content change including paste — for untitled docs this can flip the language id (e.g. plaintext -> typescript) after paste, which triggers `ModelService._onDidChangeLanguage` -> `getCreationOptions`/`_setModelOptionsForModel` (src/vs/editor/common/services/modelService.ts) to recompute and reapply model options. This recompute path exists only because untitled docs start language-less and get auto-detected post-paste; file-backed editors already have a resolved language before any paste happens, which matches the reporter's exact repro delta. Confirm whether the recomputed options for the newly-detected language correctly carry the user's `editor.detectIndentation`/`tabSize`/`insertSpaces`, and fix the scope/timing bug if not.

- **untitled-only auto language detection:** src/vs/workbench/services/untitled/common/untitledTextEditorModel.ts:398-422 calls `this.autoDetectLanguage()` on EVERY content change (including paste) for untitled documents only; file-backed editors already have a fixed language, so they never hit this path after a paste.
- **language-change triggers option recompute:** src/vs/editor/common/services/modelService.ts `_onDidChangeLanguage` (around line 554) recomputes `getCreationOptions` for the new language and applies them via `_setModelOptionsForModel` (line 237), which is the only place indentation/tabSize could be reapplied after the document already has content.
