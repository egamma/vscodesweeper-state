# Issue #330504 — New tab (non-existing file) ignores User/Workspace settings

[https://github.com/microsoft/vscode/issues/330504](https://github.com/microsoft/vscode/issues/330504)

## Summary

Confirmed on current main: language detection after a whole-document paste into an untitled editor unconditionally re-detects indentation, overriding the user's disabled `editor.detectIndentation` setting. Route this to the untitled-editor area as a source-confirmed bug.

## Change summary

Pasting code into a new untitled file changes its tab and space options based on the pasted content even when `editor.detectIndentation` is false.

## Best solution

Preserve automatic language detection for whole-document pastes while honoring the resolved `editor.detectIndentation` setting before changing the model's indentation options.

  > When code is pasted as the complete contents of a new untitled editor, VS Code may detect and apply its language. If the resolved `editor.detectIndentation` setting is false, the paste must not change `editor.tabSize`, `editor.indentSize`, or `editor.insertSpaces`; when it is true, existing paste-time indentation detection remains available. Acceptance requires both disabled and enabled setting cases to pass.
- **Trace:**
