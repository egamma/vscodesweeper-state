## Evidence

- **Confirmed regression and recent reproduction:** The discussion at https://github.com/microsoft/vscode/issues/224704 supplies NVDA mouse-tracking setup, a working VS Code 1.91 baseline, independent confirmation, and continued failure on 1.115.0. The September 2026 comment isolates the failure to desktop Electron, with working Chrome/vscode.dev and a minimal Electron 29 versus modern Electron reproduction.
- **Verified upstream ownership:** https://github.com/electron/electron/issues/42945 remains open and identifies Electron 30.0.0-beta.8 as the first failing build. Its reproduction and accessibility-tree inspection associate the regression with https://github.com/electron/electron/pull/41256: an empty native container intercepts accessibility hit tests above web content.
- **Fix candidate is not merged:** https://github.com/electron/electron/pull/53460 is OPEN, with no merge commit or merged timestamp. It explicitly fixes the upstream issue by correcting contentView hit targeting and hiding childless containers from accessibility-tree navigation; its author reports Linux hit-test verification but explicitly has not verified Windows with NVDA/Inspect.exe.
- **Current VS Code integration boundary:** src/vs/platform/windows/electron-main/windowImpl.ts:774-800 constructs the desktop window using new electron.BrowserWindow(options). The reported native BrowserWindow accessibility hierarchy is therefore on VS Code's actual window path, rather than an installed extension's rendering path. No relevant fix appeared in the inspected commit-message search.
- **Canonical search:** Repository search for NVDA mouse tracking found no older open report owning this regression. https://github.com/microsoft/vscode/issues/277895 was created in November 2025 and attributes similar symptoms to Chromium 140-143, unlike this Electron 30 regression. https://github.com/microsoft/vscode/issues/237085 and https://github.com/microsoft/vscode/issues/237087 were created in December 2024 and describe editor-text and menu hit-testing failures with the workaround installed; neither qualifies as an older canonical for this re-reviewed item.
- **Workaround is not resolution:** The thread documents the mouseEnhancement NVDA add-on as a temporary workaround and reports substantial performance costs. https://github.com/nvaccess/nvda/issues/17108 discusses compensating for the same covering-container problem; its closed state does not establish that Electron or VS Code shipped a fix.
