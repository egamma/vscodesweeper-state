# Issue #325429 — Mouse drag selection stops working in Monaco editor after resuming from sleep

[https://github.com/microsoft/vscode/issues/325429](https://github.com/microsoft/vscode/issues/325429)

## Summary

The report describes mouse drag selection failing after sleep resume, but the system is running on Microsoft Basic Render Driver (software GPU) with no real graphics driver — a highly unusual environment. The strong correlation with the graphics driver reset shortcut (Win+Ctrl+Shift+B) and the fact that terminal selection still works suggest this is an Electron/Chromium input-pipeline issue triggered by the degraded graphics state, not a VS Code editor defect. More information is needed to verify.

## Change summary

Mouse drag text selection in the editor stops working after resuming Windows from sleep; only a full Windows restart restores it.

Determine whether this reproduces with a proper GPU driver installed (the system info shows Microsoft Basic Render Driver — a software fallback). If it does, file upstream against Electron/Chromium's pointer-event handling after compositor suspend/resume. If it's specific to the software renderer, the fix belongs in the graphics driver or Electron's input pipeline, not in VS Code's editor layer.
