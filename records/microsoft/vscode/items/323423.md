# Issue #323423 — Invalid slash sub-command should respond with the valid options instead of a flat error

[https://github.com/microsoft/vscode/issues/323423](https://github.com/microsoft/vscode/issues/323423)

## Summary

Keep open: existing sub-command completions do not provide recovery guidance after an invalid command is submitted. The current host delegates runtime-command validation to the SDK, and no verified fix or older canonical issue establishes that this team-authored request is completed.

## Change summary

Show valid sub-command options when a slash command rejects an unsupported argument, rather than returning a dead-end error.

## Best solution

Invalid sub-command responses should identify the supported options while preserving the rejection and leaving valid invocations unchanged. Establish the current SDK response first, then coordinate runtime-provided guidance with the Agent Host's error presentation rather than maintaining a separate hardcoded command vocabulary.
