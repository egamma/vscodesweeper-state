# Issue #300042 — Steering obliterates applied patch from GPT-5.4

[https://github.com/microsoft/vscode/issues/300042](https://github.com/microsoft/vscode/issues/300042)

## Summary

The maintainer explicitly confirmed that steering intentionally skips pending tool calls, including a patch still being generated. Propose closing as designed; use queueing when the current request should finish before processing the follow-up.

## Change summary

Preserve a generated but not-yet-executed patch when a steering message arrives during generation.

## Best solution

Retain the intentional distinction between steering and queueing: steering redirects the current work, while queueing lets it finish. Users wanting the latter can select Queue or set chat.requestQueuing.defaultAction to queue.
