# Issue #316537 — Open in agents fails to recognize WSL2

[https://github.com/microsoft/vscode/issues/316537](https://github.com/microsoft/vscode/issues/316537)

## Summary

Confirmed on current main: the 'Open in Agents' action explicitly drops the workspace folder URI when the scheme is not `file` (e.g. WSL's `vscode-remote`), so the agents window opens without the WSL workspace context. The WSL agent host infrastructure exists in the agents window but is not wired into the handoff path.

## Change summary

Clicking 'Open in Agents' from a WSL-connected VS Code window does not carry over the WSL remote workspace, landing in the local Windows home directory instead.

## Best solution

Extend the `openAgentsWindow` handoff to forward the remote authority and folder URI for `vscode-remote` workspaces (WSL, SSH, etc.), so the agents window can resolve the workspace via the appropriate remote agent host provider. The fix likely touches `OpenWorkspaceInAgentsWindowAction.run()` in `src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts` and may need corresponding handling in `windowsMainService.ts` and the agents window's folder-selection IPC handler.
