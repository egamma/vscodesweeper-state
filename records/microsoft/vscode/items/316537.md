# Issue #316537 — Open in agents fails to recognize WSL2

[https://github.com/microsoft/vscode/issues/316537](https://github.com/microsoft/vscode/issues/316537)

## Summary

Keep open: current source still discards the WSL workspace during a folder-only Open in Agents handoff, even though manual WSL connections now exist. The later language-server errors are useful additional evidence, but their relationship to the workspace-handoff defect is not established.

## Change summary

Opening Agents from a WSL2 project loses the selected Linux workspace and leaves the window in a local Windows context.

## Best solution

Preserve the originating WSL distribution and exact Linux project folder through the Agents workspace handoff, using the WSL agent-host provider rather than treating the path as a local Windows folder. Investigate the reported language-server startup errors separately unless reproduction establishes the same cause.

  > Opening Agents from a WSL2 project must retain the originating distribution and exact Linux project directory whenever the action requests workspace selection. - **Trace:**

  > OpenWorkspaceInAgentsWindowAction.run passes the editor workspace URI to the native window service.
