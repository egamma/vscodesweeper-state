# Issue #238996 — Filtering of output channels should run asynchronously and avoid locking up the renderer

[https://github.com/microsoft/vscode/issues/238996](https://github.com/microsoft/vscode/issues/238996)

## Summary

The renderer-blocking path remains on current main: every filter change synchronously scans the complete output model before updating hidden areas. This accepted Backlog performance bug should remain open.

## Change summary

Filtering large output channels blocks the renderer while every line or log entry is synchronously matched.

## Best solution

Keep output filtering responsive by processing large models across multiple renderer turns, while ensuring obsolete work is cancelled when the filter, model, or active channel changes.
