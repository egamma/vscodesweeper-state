# Issue #348862 — Copilot sessions: agent edits skip the Keep/Discard review, so individual changes can't be approved or denied

[https://github.com/microsoft/vscode/issues/348862](https://github.com/microsoft/vscode/issues/348862)

## Summary

Keep open as a possible regression in the restored Copilot review experience. Keep/Undo support was added after the original SDK transition, but this report targets 1.146.0; its new-session steps suffice to retest and do not establish that the earlier implementation resolved it.

## Change summary

Copilot CLI sessions lack the per-range review controls available in Local sessions.

## Best solution

Determine why a new Copilot session does not attach or display the existing editor review integration, then restore independent Keep/Undo decisions for supported text-file changes. Preserve the existing distinction between writing edits to disk and acknowledging their review.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSnapshotController.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostEditReview.ts`
- **Validation:** In an editor window, enable chat.editor.workingSet.enabled and the working-set Keep and Undo preference, start a new Copilot CLI session, and request two separated edits in an ordinary UTF-8 text file. Verify both ranges receive review controls, keeping one leaves it intact, and undoing the other reverts only that range; compare with Local.
- **Behavior:**

  > Supported text-file edits in a new Copilot session should remain independently reviewable when review controls are enabled. Keeping one range must not acknowledge another, and undoing one range must preserve the other. Edits may already be on disk before review.
- **Trace:**

  > AgentHostSessionHandler attaches AgentHostEditReview through AgentHostSnapshotController when working-set and review preferences permit it. AgentHostEditReviewEntry exposes per-range operations through diffInfo, so this is not an absent API or an unimplemented blanket capability. The uncertainty starts at reproducing why that existing path is not visible in the reported session. Preserve explicit review-disable preferences and existing unsupported-file boundaries. The restoration and known limitations are documented at https://github.com/microsoft/vscode/issues/339363#issuecomment-6346982654.

- **Existing capability and activation gates:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.editor.workingSet.enabled with default true in editor windows. agentHostSessionHandler.ts derives reviewEnabled from that setting and reviewPreferences.keepUndoEnabled, then attaches AgentHostEditReview for eligible global sessions.
- **Per-range implementation exists:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostEditReview.ts overrides AgentHostEditReviewEntry.diffInfo with per-change keep and undo operations. agentHostSnapshotController.ts exposes review entries and supportsKeepUndo only while a review is attached; source inspection alone does not establish which condition failed for the reporter.
- **Review is not a write barrier:** https://github.com/microsoft/vscode/issues/339363#issuecomment-6134276862 clarifies that Local edits were already on disk before Keep; the missing pending-review presentation and selective undo are the actionable discrepancy.
