## Summary

Thanks for the tracking report. The bug is still present on main: wrapAgentHostUri only guards against an empty path, so a non-empty rootless path (e.g. 'foo') still reaches URI.from with an authority and throws. An open fix PR exists and has not merged, so this stays open.

## Change summary

Wrapping an agent-host URI whose path does not start with '/' throws a UriError in toAgentHostUri.

## Best solution

Land the open fix https://github.com/microsoft/vscode/pull/339814 so wrapAgentHostUri normalizes rootless paths to start with '/'. Consider a try/catch around the mapHostUri callers so a bad URI cannot raise an unhandled error.
