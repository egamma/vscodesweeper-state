# Issue #333203 — First usage of skill command from agent plugin is not recognized

[https://github.com/microsoft/vscode/issues/333203](https://github.com/microsoft/vscode/issues/333203)

## Summary

Traced conclusively in current main: `hasPromptSlashCommand` in promptsServiceImpl.ts lazily kicks off async hydration of `knownPromptSlashCommandNames` but returns synchronously against the still-empty set on the very first call, so the `<cmd>:<sub>` fallback used to resolve plugin skill commands (e.g. `dummy:print-hello-world`) fails exactly once before the cache is warm — matching the reported 'first usage not recognized, works after that' symptom.

## Change summary

The first time a slash command for a skill from a custom agent plugin is used, it isn't recognized as a valid command (no highlighting, sent as plain text); subsequent uses of the same command work fine.

## Best solution

Fix the hydration race in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts so `hasPromptSlashCommand` doesn't answer against an empty cache on its very first invocation — either by eagerly warming `knownPromptSlashCommandNames` earlier (e.g. on service construction or first prompt-file discovery), or by having the chat input widget re-parse/re-render already-typed text once `onDidChangeSlashCommands`/hydration resolves.
