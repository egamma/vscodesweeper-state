# Issue #333203 — First usage of skill command from agent plugin is not recognized

[https://github.com/microsoft/vscode/issues/333203](https://github.com/microsoft/vscode/issues/333203)

## Summary

Detailed, screenshot-documented repro of a real timing issue with custom agent-plugin skills: the very first `/skill` invocation from a newly-added `chat.pluginLocations` plugin is shown as recognized in the input (blue highlight, autocomplete) but is sent as plain text and never expands the `SKILL.md` content; every subsequent invocation of the same skill works. This points at a race between the completion provider's customization snapshot and the send-time customization state the provider actually uses to expand the command.

## Change summary

First use of a skill from a custom agent plugin (added via `chat.pluginLocations`) is not executed as a skill even though autocomplete recognizes it; only later invocations work.

## Best solution

Investigate the Copilot agent's customization synchronization path in src/vs/platform/agentHost/node/copilot/copilotAgent.ts and src/vs/platform/agentHost/node/agentHostSkillCompletionProvider.ts: the completion provider calls agent.getChatCustomizations() to power autocomplete, but the actual send path may rely on a separately-cached/round-trip-stale customization snapshot inside the provider that hasn't yet registered the newly-discovered plugin's skill at first send. Per AGENTS.md §8b the provider's reconciled customization view is 'never more than one host round-trip stale' — that one-round-trip gap looks like the exact window this bug falls into for a skill added via a fresh custom plugin.
