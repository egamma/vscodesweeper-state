# Issue #336797 — Agent Host loses BYOK Custom Endpoint context limits: context usage hidden and 1M model compacted at 128K

[https://github.com/microsoft/vscode/issues/336797](https://github.com/microsoft/vscode/issues/336797)

## Summary

Real, well-documented bug: a BYOK Custom Endpoint model's configured context window (e.g. 1M tokens) is not honored by the Agent Host's compaction/budget logic, which silently falls back to a 128K limit and hides the context-usage indicator. The reporter's own debug event stream (currentTokens/tokenLimit values) is a credible confirmed repro; I traced the renderer→node BYOK propagation code on main and it looks structurally correct, so the exact failure point (likely a session-start timing race, an id/provider mismatch at model-selection time, or something inside the opaque Copilot SDK package) is not yet pinned down.

## Change summary

Agent Host loses the configured maxInputTokens/maxOutputTokens for a BYOK Custom Endpoint model, defaulting the session budget to 128K and hiding the context-usage bar.

## Best solution

Add diagnostics (or a targeted repro) around session creation for a large-context BYOK model to confirm whether `resolveByokSessionConfig`'s `models`/`providers` payload (src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts) is actually populated and correctly matched by the Copilot SDK at session-start time, versus a stale/empty `byokLmBridgeRegistry` read due to a startup race; once the failure point is found, fix the mapping or the race there.
