# Issue #336797 — Agent Host loses BYOK Custom Endpoint context limits: context usage hidden and 1M model compacted at 128K

[https://github.com/microsoft/vscode/issues/336797](https://github.com/microsoft/vscode/issues/336797)

## Summary

Detailed, specific report (exact debug-stream token counts, direct inspection of the Agent Host model entry showing maxInputTokens=0/maxOutputTokens=0) of a real propagation gap for BYOK Custom Endpoint context limits; already correctly labeled agent-host, but the exact break point in the renderer→bridge→host chain needs diagnosis before a fix.

## Change summary

A BYOK Custom Endpoint model's configured maxInputTokens/maxOutputTokens (e.g. 1M-token window) are lost by the time the Agent Host builds its session/compaction budget, which silently falls back to 128K and hides the context-usage indicator.

## Best solution

Trace the BYOK model metadata pipeline (extensions/copilot's CustomEndpointBYOKModelProvider → workbench ILanguageModelsService registry → AgentHostByokLmHandler.listModels() → the node-side ByokLmBridgeRegistry/IPC channel → CopilotAgent._refreshByokModels()/resolveByokSessionConfig) to find where maxInputTokens/maxOutputTokens become 0/undefined for a large custom-endpoint model, then fix that specific hop.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts`, `src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts`
- **Validation:** A reproduction (or an agent-host e2e/unit test) that registers a BYOK Custom Endpoint model with maxInputTokens=936000/maxOutputTokens=64000 and asserts the Agent Host's session model entry and compaction budget reflect the full window rather than 128000/0.
- **Behavior:**

  > A BYOK Custom Endpoint model configured with a large context window (e.g. 936000 input + 64000 output) should have those exact limits available to the Agent Host: the model entry read by CopilotAgent must show non-zero maxInputTokens/maxOutputTokens, the context-usage indicator must be visible, and automatic compaction must trigger near ~80% of the configured window rather than at ~102400/128000.
- **Trace:**

  > The chain is: extensions/copilot's CustomEndpointBYOKModelProvider registers a renderer LM with maxInputTokens/maxOutputTokens set (customEndpointProvider.ts:160-163) → AgentHostByokLmHandler.listModels() maps that into IByokLmModelInfo (agentHostByokLmHandler.ts:175-186, already unit-tested) → pushed over IPC into node/byokLmBridgeRegistry.ts → CopilotAgent._refreshByokModels() (copilotAgent.ts:2144-2161) and resolveByokSessionConfig() (copilotSessionLauncher.ts:580-587) both forward the fields onward. Every read site inspected preserves non-zero values when present, so the defect is either a timing/race (bridge snapshot read before the renderer pushes real limits) or something specific to the reporter's 'chat-completions' apiType/config shape not covered by existing tests — this needs a live repro or added test coverage to pin down before changing code. Do not restructure the BYOK bridge/IPC contract; the fix should be localized to whichever hop is found to drop the values.
- **Open decisions:**
  - Is the zeroing a one-time race (host reads the bridge snapshot before the renderer's BYOK metadata is fully populated, e.g. right after reload) or a persistent mapping bug for a specific config shape (apiType: chat-completions, contextWindow-derived maxInputTokens)?
  - Does the existing agentHostByokLmHandler/byokLmBridgeRegistry test suite need a new case mirroring the reporter's exact config (contextWindow-only maxInputTokens derivation) to catch this?
  - Is the 128000 compaction fallback happening inside this repo's copilot-sdk wiring, or is it a default inside the external @github/copilot-sdk package that only manifests when maxContextWindowTokens/maxPromptTokens arrive as 0/undefined?

## Evidence

- **renderer→host bridge:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts:161-194 (listModels) correctly maps metadata.maxInputTokens/maxOutputTokens into IByokLmModelInfo, and this mapping is unit-tested in agentHostByokLmHandler.test.ts with non-zero values — no obvious defect here.
- **host-side consumption:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2144-2161 (_refreshByokModels) and node/copilot/copilotSessionLauncher.ts:580-587 (resolveByokSessionConfig) both forward maxContextWindowTokens/maxPromptTokens/maxOutputTokens through to the AgentModelInfo and the copilot-sdk ProviderModelConfig respectively — also structurally correct on read.
- **extension-side registration:** extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts:160-163 shows maxInputTokens/maxOutputTokens are set from the model config when building modelCapabilities — the renderer-side registry entry itself looks correctly populated.
- **no smoking gun found:** Every layer traced propagates the fields when present; the exact drop point (e.g. a timing/race issue where the bridge snapshot is read before BYOK metadata refreshes, or an apiType='chat-completions' specific path) was not isolated from source alone.
