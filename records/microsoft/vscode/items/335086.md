# Issue #335086 — Copilot Chat BYOK OpenAI-Responses custom endpoint fails on 2nd turn with "previous response not found" since ~1.134: request no longer sends store:true

[https://github.com/microsoft/vscode/issues/335086](https://github.com/microsoft/vscode/issues/335086)

## Summary

The reported second-turn failure remains supported by current source: custom endpoints can omit store while reusing response IDs, and the reported not_found error bypasses recovery. Keep this open; the older related report describes a different observable failure and does not meet the re-review duplicate bar.

## Change summary

Custom Responses endpoints that retain responses only with explicit store:true fail on the second turn when retention is unspecified.

## Best solution

Make multi-turn Custom Endpoint Responses conversations reliable without silently overriding explicit retention preferences. Resolve whether unspecified retention should request storage or preserve the server default with full-history recovery, then cover the reported gateway response.
