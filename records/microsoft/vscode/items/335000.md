# Issue #335000 — In-app update opens the browser and only downloads the update ZIP — it never installs (no "Restart to Update") on an official User setup install

[https://github.com/microsoft/vscode/issues/335000](https://github.com/microsoft/vscode/issues/335000)

## Summary

The reported symptom exactly matches the code path VS Code takes when it treats a Windows install as the ZIP/archive type rather than the Inno-Setup ('User setup') type — `doDownloadUpdate` for `UpdateType.Archive` only calls `openExternal` on the update URL and never applies anything, with no 'Restart to Update' step. Whether that misclassification is actually happening on this reporter's machine can't be confirmed without a live Windows repro, but the mechanism is real and worth routing to the Windows update owner.

## Change summary

On an official Windows User-setup install, clicking 'Check for Updates' opens a browser to download a ZIP but never installs the update or shows 'Restart to Update'.

## Best solution

Have the Windows update owner check why `isInnoSetupInstall()` (src/vs/platform/update/electron-main/win32UpdateType.ts) would return false for this install — i.e. confirm whether `unins000.exe` is actually present next to `process.execPath` for the reporter's layout — since a false result there routes the whole update flow into the Archive/manual-download branch in updateService.win32.ts instead of the background inno_updater path.
