# Issue #335000 — In-app update opens the browser and only downloads the update ZIP — it never installs (no "Restart to Update") on an official User setup install

[https://github.com/microsoft/vscode/issues/335000](https://github.com/microsoft/vscode/issues/335000)

## Summary

Confirmed bug: the update-type detector hardcodes a check for `unins000.exe`, so User-setup installs whose uninstaller got renumbered (e.g. `unins001.exe`, which the reporter and a collaborator both reproduced) are misclassified as archive installs and fall back to the browser-download ZIP path with no apply/restart step. A collaborator confirmed the bug and opened a fix PR, so this should stay open until that PR lands.

## Change summary

In-app update misdetects a Windows User-setup install as an archive install when the Inno Setup uninstaller isn't named exactly `unins000.exe`, so updates only download a ZIP via the browser instead of applying in-app with a Restart to Update prompt.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/335206 (or an equivalent fix) so `isInnoSetupInstall`/`getWin32UpdateType` in src/vs/platform/update/electron-main/win32UpdateType.ts detect a Setup install without relying solely on the exact filename `unins000.exe`; close this issue once that merges and ships.

## Evidence

- **root cause in source:** src/vs/platform/update/electron-main/win32UpdateType.ts: `isInnoSetupInstall` only checks `fileExists(path.join(path.dirname(executablePath), 'unins000.exe'))`; if that exact file isn't present, `getWin32UpdateType()` returns `UpdateType.Archive` instead of `UpdateType.Setup`, matching the reported browser-ZIP-only behavior.
- **collaborator confirmation:** dmitrivMS (COLLABORATOR) wrote 'I found the bug, and will attempt to fix it' and confirmed 'we have code that explicitly checks for unins000.exe ... but the installer may create those with other indices under certain conditions, and then we don't detect the install any longer.'
- **reporter reproduction:** DinoFeng found `unins001.exe` instead of `unins000.exe` after reinstalling during troubleshooting; renaming the install dir and reinstalling restored `unins000.exe` and fixed in-app updates.
- **open fix PR:** https://github.com/microsoft/vscode/pull/335206 ('update: detect Windows setup installs from product target') is open and targets this exact detection logic; not yet merged into main (this is a shallow, single-commit checkout so full history isn't visible, but the current win32UpdateType.ts on main still has the unins000.exe-only check with no related recent commit).
