# Issue #86223 — Proxy configuration doesn't allow URLs with port number AND pac files

[https://github.com/microsoft/vscode/issues/86223](https://github.com/microsoft/vscode/issues/86223)

## Summary

The reported validation is intentional: `http.proxy` configures a static proxy endpoint, not a PAC script URL. Electron already provides the separate `--proxy-pac-url` launch option for this scenario.

## Change summary

Allow an authenticated PAC URL containing an explicit port and path in the `http.proxy` setting.

## Best solution

Keep `http.proxy` limited to static proxy endpoints and use the existing `--proxy-pac-url=https://user:password@proxyurl.com:8080/file.pac` launch option, or the operating system's PAC configuration, for automatic proxy scripts.

- **Fit:** unclear
- **Reason:** PAC configuration is valid networking support, but the vision does not specify whether it should also be represented through the static `http.proxy` setting.

  > Thanks for the report. The `http.proxy` setting is intended for a static proxy endpoint, so paths such as `/file.pac` are not accepted. ## Evidence

- **current setting contract:** src/vs/platform/request/common/request.ts registers `http.proxy` with a pattern that accepts a proxy scheme, host, optional credentials and port, but no file path.
- **current application path:** src/vs/platform/windows/electron-main/windowImpl.ts applies `http.proxy` through Electron's `proxyRules` and explicitly sets `pacScript: ''`, confirming that the setting represents a static proxy rather than a PAC URL.
- **existing PAC capability:** https://github.com/microsoft/vscode/issues/203438 demonstrates that VS Code accepts `--proxy-pac-url=http://127.0.0.1:8000/proxy.pac`; its netlog confirmed that the PAC file was loaded, although that separate report concerned a Linux request fallback.
