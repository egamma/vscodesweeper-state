# Issue #333875 — LabelService resource home lookup scales with all registered session homes

[https://github.com/microsoft/vscode/issues/333875](https://github.com/microsoft/vscode/issues/333875)

## Summary

Freshly filed, self-diagnosed performance bug by a VS Code team member with a captured 6.45s renderer hang trace; the linear scan in LabelService is confirmed in current source and no fix has landed, so this stays open for the proposed indexing work.

## Change summary

LabelService.findHomeFormatter/findFormatting scan every registered home formatter on each getUriLabel/getUriHome call, so cost grows with the number of registered agent-session homes, causing multi-second hangs when many sessions exist.

## Best solution

Index home formatters by scheme/authority/path (e.g. a prefix tree for exact home paths, small fallback scan for authority globs) in src/vs/workbench/services/label/common/labelService.ts so unrelated URI lookups don't scan every registered session home, with a regression test asserting O(1)-ish lookup cost independent of session count.
