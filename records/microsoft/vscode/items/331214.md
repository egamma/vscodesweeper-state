# Issue #331214 — Migrate Customizations to Agent Host Harnesses: disable for Claude & Codex

[https://github.com/microsoft/vscode/issues/331214](https://github.com/microsoft/vscode/issues/331214)

## Summary

Confirmed on main: the 'Migrate User Data' category is offered whenever any agent-host harness is active and the setting is enabled, with no check that the active harness (Claude/Codex) actually supports `.agent.md`/`.instructions.md` targets, so users are offered a migration that has nowhere useful to land.

## Change summary

The 'Migrate User Data' customizations tab should be hidden for harnesses (Claude, Codex) that don't support `.agent.md`/`.instructions.md` files.

## Best solution

In aiCustomizationManagementEditor.ts's getEnabledMigrationCategories()/refreshCustomizationMigrationInfo(), exclude userDataMigrationCategory when promptsService.getSourceFolders() returns no folders for its sourceTypes (agent/instructions) on the active harness, consistent with how other pickers already use getSourceFolders() to detect harness support.
