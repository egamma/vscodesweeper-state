# Issue #81808 — [css] css.lint.hexColorLength seems to be now irrelevant

[https://github.com/microsoft/vscode/issues/81808](https://github.com/microsoft/vscode/issues/81808)

## Summary

The gap remains in the current CSS language service: its parser creates `HexColorValue` nodes only for already-valid lengths, making the `hexColorLength` lint check unreachable for the reported seven-digit value. Keep this open as an upstream language-service issue.

## Change summary

Make `css.lint.hexColorLength` report invalid hexadecimal color lengths instead of the generic property-value parse error.

## Best solution

Update the CSS language-service parser to represent all syntactically hexadecimal `#...` values as `HexColorValue`, audit consumers for invalid lengths, and add validation tests before consuming the resulting service version in VS Code.

## Evidence

- **current parser:** https://github.com/microsoft/vscode-css-languageservice/blob/main/src/parser/cssParser.ts `_parseHexColor` accepts only 3, 4, 6, or 8 hexadecimal digits, so `#ccc0003` does not become a `HexColorValue` and instead reaches the generic property-value error path.
- **unreachable lint path:** https://github.com/microsoft/vscode-css-languageservice/blob/main/src/services/lint.ts `visitHexColorValue` reports `Rules.HexColorLength` only when a `HexColorValue` has a length other than 4, 5, 7, or 9 characters, but the current parser cannot produce such a node for an ordinary invalid-length literal.
- **bundled dependency:** extensions/css-language-features/server/package.json delegates CSS parsing and linting to `vscode-css-languageservice` (`^7.0.0-next.2`), placing the root fix in that dependency.
- **maintainer direction:** A VS Code maintainer confirmed in https://github.com/microsoft/vscode/issues/81808 that the intended approach is to create a hex-color node for hexadecimal values of invalid length and ensure all consumers tolerate those nodes.
