# Issue #338817 — Theme-defined `modernEditorTab.activeBackground` is not set

[https://github.com/microsoft/vscode/issues/338817](https://github.com/microsoft/vscode/issues/338817)

## Summary

Plausible, well-documented bug in the new/experimental Modern UI tabs theming: the reporter shows (with before/after screenshots) that a theme-defined `modernEditorTab.activeBackground` in a theme's `colors` section is ignored, while the same key set via `workbench.colorCustomizations` works. I traced the generic theming pipeline (color registration, theme-file parsing, CSS-variable generation) and found nothing that should special-case this color differently from a user customization — both paths flow through the same `ColorThemeData.getColor`/`generateColorThemeCSS` code, so I could not pin down the exact divergence from source alone.

## Change summary

A color theme extension's `colors` entry for `modernEditorTab.activeBackground` has no effect on the rendered active-tab background, even though the identical `workbench.colorCustomizations` override works.

## Best solution

Confirm with a running instance whether the theme-loaded value actually lands in `ColorThemeData.colorMap['modernEditorTab.activeBackground']` and whether `generateColorThemeCSS` picks it up; if it does land but is still overridden, look for a later CSS rule or caching path (e.g. a stale/pre-generated modern-UI stylesheet) that re-applies a default before the extension theme's colors are available.
