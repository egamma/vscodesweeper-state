# Issue #338817 — Theme-defined `modernEditorTab.activeBackground` is not set

[https://github.com/microsoft/vscode/issues/338817](https://github.com/microsoft/vscode/issues/338817)

## Summary

Traced the exact defect in the checkout: the Modern UI tab-color code only checks `theme.getColorCustomization()` to decide whether a modern tab color is explicitly set, and that method only inspects user `workbench.colorCustomizations`, never the theme file's own `colors` section — so a theme-authored `modernEditorTab.activeBackground` is silently ignored while the identical user override works, exactly as reported. This is a real, bounded bug, worth keeping open and fixing.

## Change summary

Modern UI (experimental) editor tabs ignore a color-theme-defined `modernEditorTab.activeBackground` (and sibling modern tab colors), even though the same value set via `workbench.colorCustomizations` works.

## Best solution

In src/vs/workbench/services/themes/browser/modernTabColorCustomizations.ts, switch the 'is this modern color explicitly set' checks from `theme.getColorCustomization(id)` to `theme.defines(id)` so theme-file colors are treated the same as user customizations, while still reading the actual value via `theme.getColor(id)`.
