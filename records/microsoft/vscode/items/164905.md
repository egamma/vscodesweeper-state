# Issue #164905 — Starving extension host can block file navigation

[https://github.com/microsoft/vscode/issues/164905](https://github.com/microsoft/vscode/issues/164905)

## Summary

Keep open: built-in file search still depends on extension-host execution, and the affinity setting offers optional isolation rather than guaranteeing responsive navigation. The maintainer's unsuccessful reproduction warrants retesting the supplied initialization scenario, not declaring the requested isolation implemented.

## Change summary

Keep Quick Open file navigation responsive when another extension starves the extension host, including during TypeScript initialization.

## Best solution

Establish whether extension-host contention still delays Quick Open in the reported workspace, then provide an isolation boundary for built-in file search if confirmed. Preserve extension-contributed search providers and remote-workspace behavior rather than assuming extension affinity alone resolves the dependency.
