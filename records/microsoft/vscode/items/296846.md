# Issue #296846 — Adding support for deleting individual or multiple memory files at a time

[https://github.com/microsoft/vscode/issues/296846](https://github.com/microsoft/vscode/issues/296846)

## Summary

Keep open: the current memory picker supports viewing files, while the clearing command deletes all memories; neither provides user-controlled deletion of individual files or a selected group. The related memory test plan explicitly acknowledges this missing capability, and no qualifying canonical or fixing commit was established.

## Change summary

Allow users to delete one or several selected memory files without clearing all stored memories.

## Best solution

Provide selective deletion in the Copilot memory-management UI, preserving unselected files across user, repository, and session scopes. Agree on the selection and confirmation experience before implementation.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/tools/vscode-node/tools.ts`, `extensions/copilot/package.json`, `extensions/copilot/package.nls.json`
- **Validation:** In a development extension host, create multiple user, repository, and current-session memory files. Delete one file, then a selected group; verify only the selected files disappear from storage and the picker. Cancel deletion and verify all files remain. Verify viewing files and Clear All Memory Files retain their existing behavior.
- **Behavior:**

  > Users can deliberately delete an individual memory file or a selected group without deleting unrelated memories. The operation must identify the targeted files and preserve unselected files in every scope. Acceptance checks cover single-file deletion, multi-file deletion, cancellation, and unchanged viewing and clear-all behavior.
- **Trace:**

  > The related test plan at https://github.com/microsoft/vscode/issues/296844 identifies selective deletion as missing. In extensions/copilot/src/extension/tools/vscode-node/tools.ts, github.copilot.chat.tools.memory.showMemories enumerates user, repository, and active-session files into a view-only single-selection picker; github.copilot.chat.tools.memory.clearMemories instead removes entire storage directories. extensions/copilot/src/extension/tools/node/memoryTool.tsx already supports path-specific deletion through MemoryTool._localDelete, but that is an agent-tool path, not a user-management surface. Preserve storage-scope resolution and existing agent-tool behavior; expanding visibility to other sessions is separate work discussed at https://github.com/microsoft/vscode/issues/297363. The remaining uncertainty is the user-facing selection and confirmation contract, not whether selective filesystem deletion is possible.
- **Open decisions:**
  - Should selective deletion be available within Show Memory Files, or through a separate deletion command?
  - Should both individual and multi-file deletion require confirmation, and what selected-file information should that confirmation display?
