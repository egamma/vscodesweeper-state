Keep open: the discussion confirms a substantial Electron protocol performance regression, and current main still uses the affected handler. A maintainer has committed to reverting the API usage, with an open mitigation PR that should be resolved before considering closure.

## Evidence

- **Controlled reproductions:** https://github.com/microsoft/vscode/issues/341401 contains controlled CI comparisons and macOS A/B measurements isolating the protocol handler. The October 28 maintainer comment adds Windows measurements on October 27 main with Electron 43.8.3: 7.5–8.1 seconds with protocol.handle plus net.fetch versus 2.4–2.6 seconds with registerFileProtocol.
- **Current source retains affected path:** src/vs/platform/protocol/electron-main/protocolMainService.ts registers Schemas.vscodeFileResource through defaultSession.protocol.handle in handleProtocols(). Allowed requests pass through handleResourceRequest() to createFileResponse(), which awaits net.fetch(pathToFileURL(path).toString()). The reported loading path remains present; source inspection alone does not measure its performance.

On October 28 they state that the runtime fix is being prioritized but will take time to reach the release line.

This matches the maintainer's October 28 commitment to revert to the deprecated API; it is pending mitigation, not a landed fix.
