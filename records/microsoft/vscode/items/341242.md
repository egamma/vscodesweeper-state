# Issue #341242 — [macOS] Cmd+V does not paste into a page in the integrated browser when it is in a floating window

[https://github.com/microsoft/vscode/issues/341242](https://github.com/microsoft/vscode/issues/341242)

## Summary

Thanks for the detailed report. The source confirms it: on macOS, when an auxiliary window has focus, the menubar is rebuilt with action items disabled, so the Edit → Paste role item (and its Cmd+V key equivalent) does nothing.

## Change summary

On macOS, Cmd+V does not paste into a page in an integrated browser tab that is in a floating window.

## Best solution

Keep the role-bearing Edit menu items (cut, copy, paste, and the like) enabled in menubar.ts when an auxiliary window has focus, so the roles act on the focused web contents.

- **Validation:** Manual check on macOS: move an integrated browser tab to a new window, focus an input and press Cmd+V. The text should paste, and Cmd+C, Cmd+X, Cmd+A and Cmd+Z should work too. Other menu items must remain disabled.
- **Behavior:**

  > With an auxiliary window focused on macOS, the Edit menu items backed by roles (undo, redo, cut, copy, paste, selectAll) stay enabled, so the standard shortcuts work in pages in floating browser windows. Other menu items keep their current disabled state.
- **Trace:**

  > In menubar.ts, onDidChangeWindowFocus sets noActiveMainWindow when the focused window is an auxiliary window. setMenu then builds action items with enabled=false unless they have a fallback handler. createMenuItem sets role 'paste' on editor.action.clipboardPasteAction. The preload in src/vs/platform/browserView/electron-browser/preload-browserView.ts lets Cmd+V through to the page, so the menu role does the paste. Do not change enablement for non-Edit items, and do not change the non-macOS path. Related: https://github.com/microsoft/vscode/issues/286633.
