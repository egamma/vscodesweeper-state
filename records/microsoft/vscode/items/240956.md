# Issue #240956 — Memory spike crash

[https://github.com/microsoft/vscode/issues/240956](https://github.com/microsoft/vscode/issues/240956)

## Summary

Keep open in the Git area: the reporter confirmed that disabling built-in Git prevents the remote extension-host crash and identified excessive tags as the trigger. Current source still enumerates and buffers all refs, but the precise allocation responsible for the crash needs diagnosis.

## Change summary

Opening a tag-heavy repository over SSH causes rapid memory growth and crashes the remote extension host while built-in Git initializes.

## Best solution

Make built-in Git initialization and refresh reliable for repositories with very large tag sets, preserving existing branch and tag functionality. First distinguish extension-host buffering and ref retention from Git subprocess memory consumption; reducing tag fetching alone would not address repositories that already contain the tags.

- **Trace:**

  > Repository.updateModelState in extensions/git/src/repository.ts calls getRefs with an empty query and retains the complete result in _refs. Its getRefs wrapper supplies the configured branch sort order; Repository.getRefs in extensions/git/src/git.ts enumerates unrestricted refs unless its caller supplies a count or pattern.
