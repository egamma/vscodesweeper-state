# Issue #224596 — Explorer: Smart paste when code in clipboard

[https://github.com/microsoft/vscode/issues/224596](https://github.com/microsoft/vscode/issues/224596)

## Summary

A real capability gap remains: Explorer paste handles file resources and native file data, but not source text from the clipboard. The request is accepted in the Backlog and has no verified canonical issue, so it should remain open under discussion despite limited community traction.

## Change summary

When source code text is pasted into Explorer, create a file containing it and suggest an appropriate filename.

## Best solution

Design an Explorer paste flow that recognizes clipboard source text, obtains a filename or language suggestion, and lets the user confirm or edit the result without changing ordinary file copy-and-paste behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/fileActions.ts`, `src/vs/workbench/contrib/files/test/browser/fileActions.test.ts`
- **Validation:** Add targeted file-actions tests that invoke Explorer paste with clipboard source text and verify the agreed filename/confirmation behavior and file contents, while existing resource and native-file paste cases remain unchanged.
- **Behavior:**

  > Pasting recognizable source-code text while Explorer has focus should offer to create a file in the selected directory, with the clipboard text preserved exactly and a suitable filename proposed. The user must be able to confirm or edit the filename before creation. Copying and pasting filesystem resources or native files must continue to behave exactly as it does today, and ordinary non-code clipboard text must follow the agreed fallback behavior.
- **Trace:**

  > Explorer paste is registered as filesExplorer.paste and handled by pasteFileHandler in src/vs/workbench/contrib/files/browser/fileActions.ts. getFilesToPaste currently returns only URI paths from IClipboardService.readResources() or native File objects from a FileList; it never reads or classifies clipboard text. The existing data branch already demonstrates the file-creation boundary through ResourceFileEdit contents, while src/vs/workbench/contrib/files/test/browser/fileActions.test.ts contains the focused handler test suite. Keep filesystem-resource paste, native-file paste, incremental naming, undo, and overwrite semantics unchanged. The uncertainty starts at the product contract for recognizing code and generating or confirming the filename.
- **Open decisions:**
  - Should smart paste require Copilot availability, use deterministic language detection, or expose both paths with different fallback behavior?
  - Must the user always confirm or edit the proposed filename before file creation, or may high-confidence suggestions create immediately?
  - What should Explorer do when clipboard text is empty, plain prose, or too ambiguous to classify as source code?
