## Change summary

Custom Option-key shortcuts on macOS enter dead-key composition instead of reliably executing their assigned commands.

## Best solution

The Windows Ctrl+Alt observation is not established as the same cause and should not be treated as diagnosed by this consolidation.

- **Same reported characters and combinations:** https://github.com/microsoft/vscode/issues/41024#issuecomment-439203765 explicitly reports Option+N inserting a tilde and Option+U inserting a diaeresis. https://github.com/microsoft/vscode/issues/41024#issuecomment-707322500 identifies Option+E as the same issue, covering the accent-producing combination in this report's focus-editor chord.
- **Maintainer-confirmed dependency defect:** A maintainer reproduced the canonical failure with a built-in command at https://github.com/microsoft/vscode/issues/41024#issuecomment-356662985, observed that preventDefault did not suppress the character at https://github.com/microsoft/vscode/issues/41024#issuecomment-363066178, and reproduced it in Chrome at https://github.com/microsoft/vscode/issues/41024#issuecomment-423240438. This supports dependency ownership rather than blaming an installed extension.
- **Current source boundary:** src/vs/workbench/services/keybinding/browser/keybindingService.ts:274-303 registers keyboard listeners, dispatches keybindings, and calls preventDefault when dispatch requests it. This matches the event-cancellation boundary identified in the canonical discussion; source inspection alone does not establish that current Chromium still reproduces the native composition failure.
- **Related reports are not fixing evidence:** https://github.com/BetterThanTomorrow/calva/issues/2362 was closed after directing attention to this VS Code backlog issue, not after a fix; its maintainer suggested rebinding or the command palette. https://github.com/jasonwilliams/vscode-helix/issues/41 remains open and links this issue for the same Option+I circumflex symptom.
