# Issue #329551 — `run_factory` should not accept an unconstrained factory name

[https://github.com/microsoft/vscode/issues/329551](https://github.com/microsoft/vscode/issues/329551)

## Summary

Well-diagnosed report, but the `run_factory` tool and its JSON schema (including the unconstrained `name` field) are not defined in microsoft/vscode — they're a Copilot CLI built-in tool surfaced through the `@github/copilot-sdk` dependency, so the actual fix boundary is upstream in the CLI/SDK, not in this repo's code.

## Change summary

The Copilot CLI's `run_factory` tool accepts any free-form string for `name`, letting the model repeatedly invent and retry nonexistent factory names instead of being constrained to registered ones.

## Best solution

Track this against the Copilot CLI / `@github/copilot-sdk` tool schema (owned by the CLI server, version pinned in package.json as `^1.0.9-preview.3`) rather than as a vscode core code change — the fix (dynamic enum, required-unless-resumeFromRunId, or pre-flight registry check) has to land in the SDK/CLI's tool definition, since VS Code only observes `tool.execution_start`/`system.notification` events for tools it doesn't itself schema-define.
