# Issue #250403 — Pressing keep should close any opened diff editors

[https://github.com/microsoft/vscode/issues/250403](https://github.com/microsoft/vscode/issues/250403)

## Summary

The requested behavior remains incomplete on current main: Keep closes some chat-created diff surfaces, but the global Keep action does not close every open chat diff editor. This team-authored Backlog request should remain open while the desired unconditional-versus-configurable behavior is decided.

## Change summary

Close chat-owned diff editors after the user keeps all agent edits, either by default or through a setting.

## Best solution

After Keep completes, close every diff editor associated with the accepted chat editing session while leaving unrelated diff editors untouched. Decide whether that behavior is unconditional or controlled by a setting.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingActions.test.ts`

- **Behavior:**

  > When the user presses Keep for a chat editing session, every open diff editor representing that session's accepted changes should close. Diff editors unrelated to the session must remain open. The behavior must be consistent whether the diff was opened from an inline change, the changed-files list, or the session multi-diff view; if configurable, both setting states need coverage.
- **Trace:**

  > ChatEditingAcceptAllAction in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts delegates only to IChatEditingSession.accept(). ChatEditingCodeEditorIntegration.toggleDiff in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts closes matching single-file diff inputs through an entry-state autorun, but that listener exists only for diffs opened through toggleDiff. The multi-diff action in chatEditingEditorActions.ts separately closes its own active editor after accepting, so invoking Keep from the chat toolbar bypasses that closure. Preserve unrelated diff editors and per-file Keep/Undo semantics; the unresolved boundary is whether session-wide closure is always enabled or exposed as a setting.
- **Open decisions:**
  - Should Keep always close all diff editors owned by the accepted chat session, or should users opt into that behavior through a setting?
