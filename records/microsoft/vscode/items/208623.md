# Issue #208623 — Stage / Revert toolbars focus order weird

[https://github.com/microsoft/vscode/issues/208623](https://github.com/microsoft/vscode/issues/208623)

## Summary

Keep open: current gutter rendering can put Stage/Revert toolbars in creation order rather than visual order, producing the reported reversed Shift+Tab traversal. The issue already has the appropriate diff-editor routing.

## Change summary

Make keyboard traversal between diff hunk Stage/Revert toolbars follow their vertical visual order.

## Best solution

Ensure diff gutter toolbars retain top-to-bottom sequential focus order as hunks enter the viewport or change, with Shift+Tab traversing bottom-to-top. Preserve existing toolbar arrow navigation, action semantics, and focus on retained controls.

## Evidence

- **Reported expectation:** https://github.com/microsoft/vscode/issues/208623 describes Shift+Tab visiting the upper Stage/Revert toolbar before the lower one, contrary to the expected bottom-to-top order. The reporter is a MEMBER; the issue is accepted as a bug in Backlog.
- **Current source reproduction:** In src/vs/editor/browser/widget/diffEditor/utils/editorGutter.ts, EditorGutter.render appends each newly visible hunk container with appendChild but leaves retained containers in their existing DOM positions. Start with only a lower hunk visible, then scroll upward until an upper hunk enters while the lower one remains visible: DOM order becomes lower, upper, so reverse sequential focus visits upper, lower. Existing nodes are never reordered by line range.
- **Visual order differs from DOM order:** EditorGutter.render assigns each container's style.top from its line position. src/vs/editor/browser/widget/diffEditor/style.css absolutely positions gutter children, so those visual coordinates do not correct sequential keyboard order.
- **Keyboard path:** src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts constructs a MenuWorkbenchToolBar for each gutter item. src/vs/base/browser/ui/actionbar/actionbar.ts makes the first eligible action focusable, and actionViewItems.ts implements this with tabIndex = 0. Ordinary Shift+Tab is not intercepted by the action bar, leaving cross-toolbar traversal dependent on DOM order.
