# Issue #171353 — Git - Add support for cancelling long commit operation (including its pre-commit script)

[https://github.com/microsoft/vscode/issues/171353](https://github.com/microsoft/vscode/issues/171353)

## Summary

Keep this accepted Git feature request open: current source still provides no cancellation path for commits or their running hooks. The existing sync setting does not cover this request, and no verified older open canonical supersedes it.

## Change summary

Allow users to cancel a long-running Source Control commit, including its pre-commit hook, without restarting VS Code.

## Best solution

Provide user-requested cancellation for commits in the built-in Git extension, including termination of the running hook and recovery of usable Source Control state. Settle whether cancellation is opt-in or available by default, and validate process termination and repository recovery across supported platforms.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/git.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`
- **Validation:** In a disposable repository, configure a pre-commit hook that starts a long-running child process, stage a file, and commit through Source Control. Invoke cancellation and verify that the commit and hook child terminate, progress ends, the commit message and staged changes remain available, no post-commit sync starts, and a subsequent normal commit succeeds. Repeat on macOS, Linux, and Windows; verify ordinary successful commits and existing Sync cancellation remain unchanged. These checks were not executed during this read-only review.
- **Behavior:**

  > A user who starts a Source Control commit with a long-running pre-commit hook can cancel that pending operation without restarting VS Code. Cancellation must stop the commit and its running hook, release the busy state, and preserve the pending commit message and user changes rather than treating cancellation as success. A cancelled commit must not launch its post-commit sync, and the repository must remain usable for another commit. Normal commits, hook execution, signing, and existing Sync behavior remain unchanged.
- **Trace:**

  > The git.commit command in extensions/git/src/commands.ts reaches commitWithAnyInput, smartCommit, and Repository.commit in extensions/git/src/repository.ts. Repository.commit awaits Operation.Commit, including optional staging and the lower-level commit, then performs success cleanup and the post-commit command. The lower-level commit in extensions/git/src/git.ts invokes exec without a cancellation token; its shared exec helper already accepts tokens but kills only the immediate child explicitly, leaving descendant termination unverified. Repository.run refreshes model state on failure and ends operation tracking in finally, while SourceControl progress only observes that state. git.supportCancellation is currently consumed in _sync, not commit. This trace establishes the missing capability, not a validated termination design; preserve Git's normal hook/signing semantics and do not expand this issue into cancellation of every remote operation. Related references are https://github.com/microsoft/vscode/issues/66821 and https://github.com/microsoft/vscode/issues/316766.
- **Open decisions:**
  - Should commit cancellation be controlled by the existing opt-in git.supportCancellation setting, or be available by default independently of Sync cancellation?
