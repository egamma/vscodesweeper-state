# Issue #321905 — Chat implicit "active selection" context stays stuck after its source document is closed/deleted

[https://github.com/microsoft/vscode/issues/321905](https://github.com/microsoft/vscode/issues/321905)

## Summary

The defect remains on current main: implicit selection context is not invalidated by document closure or deletion, and the preservation logic can retain the previous value when no replacement code context exists.

## Change summary

Closing or deleting the document behind Chat's implicit active-selection context leaves that selection visible and included in later requests.

## Best solution

Invalidate an implicit selection as soon as its backing editor, model, or resource ceases to be valid, and preserve a user's suppression of that stale context across submissions until a genuinely new implicit context is produced.

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts, ChatImplicitContextContribution subscribes to active-editor and cursor/model-change events but not editor closure, model removal, or resource deletion. A deleted document can therefore retain its existing Location until another subscribed event occurs.
- **retention path:** ChatImplicitContextContribution.updateImplicitContext deliberately skips setValues when newValue is undefined but editorService.activeEditor remains truthy and implicit context already has a value. This preserves the stale selection when focus moves to a non-code editor such as Chat.
- **suppression reset:** ChatImplicitContexts.setValues recreates every ChatImplicitContext and initializes enabled from the collection-wide _enabled value. A per-context disable is therefore lost when updateImplicitContext republishes the same stale selection.
- **canonical search:** The older open reports https://github.com/microsoft/vscode/issues/267826, https://github.com/microsoft/vscode/issues/316051, and https://github.com/microsoft/vscode/issues/321103 concern unavailable prompt-file selections, cross-session active-file targeting, and disabled implicit-context settings respectively; none reports the same observable stale-selection-after-document-removal symptom required for a re-reviewed duplicate close.
