# Issue #334497 — Extend the logic behind loadability of skills. Boolean is not the way to go!

[https://github.com/microsoft/vscode/issues/334497](https://github.com/microsoft/vscode/issues/334497)

## Summary

Reasonable, if loosely written, feature request: today a SKILL.md/AGENTS.md can only set `disable-model-invocation` as a global boolean, with no way to scope a skill's auto-discovery to a subset of agents — routing to the chat customizations area for a product decision rather than closing.

## Change summary

Requests a finer-grained mechanism than the current boolean `disable-model-invocation` frontmatter field, so a skill can be scoped to (or excluded from) specific agents instead of being globally auto-loadable or not.

## Best solution

A maintainer familiar with the skills/agents customization schema (`extensions/copilot/assets/prompts/skills/agent-customization/references/skills.md` and `agents.md`, and the discovery code in `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`) should judge whether an allow-list/agent-scoping field for skill discovery is worth adding, versus leaving this to prompt/description tuning.
