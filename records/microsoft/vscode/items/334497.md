# Issue #334497 — Extend the logic behind loadability of skills. Boolean is not the way to go!

[https://github.com/microsoft/vscode/issues/334497](https://github.com/microsoft/vscode/issues/334497)

## Summary

Genuine, unaddressed gap: SKILL.md frontmatter today only supports a boolean `disable-model-invocation` for autoloading, with no way to scope a skill's discovery/loading to a specific subset of agents, unlike custom agents (`agents:` allowlist) or instruction files (`excludeAgent`).

## Change summary

Requests a more granular mechanism than the `disable-model-invocation` boolean to restrict which agents can discover/load a given skill, so a large skill library doesn't flood every agent's context.

## Best solution

Extend the SKILL.md schema with an agent-scoping attribute analogous to the custom agent `agents:` allowlist / instruction file `excludeAgent`, so a skill can declare which agents may discover/load it (likely in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts and the skill discovery/scan logic in src/vs/platform/agentPlugins and src/vs/platform/agentHost).
