# Issue #107015 — Buttons and commands associated with a custom editor are gone under a certain scenario

[https://github.com/microsoft/vscode/issues/107015](https://github.com/microsoft/vscode/issues/107015)

## Summary

Still a real edge case on current main — when a user's `files.associations` overrides a language defined by an extension, `resourceLangId` reflects the override, causing `when` clauses that rely on the extension-defined language to fail. The `activeCustomEditorId` context key exists as a workaround but doesn't fully solve the mismatch for extension authors who reasonably expect their language and custom editor to coexist.

## Change summary

Custom editor title buttons/commands disappear when user's `files.associations` setting overrides the extension-defined language for the same file extension.

## Best solution

Either document that extension authors should use `activeCustomEditorId` instead of `resourceLangId` for custom editor menus, or consider exposing the 'contributed language' separately from the 'effective language' so both can coexist. The fix area is `src/vs/workbench/common/contextkeys.ts` (`_setLangId`) or custom editor documentation.
