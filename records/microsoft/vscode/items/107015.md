# Issue #107015 — Buttons and commands associated with a custom editor are gone under a certain scenario

[https://github.com/microsoft/vscode/issues/107015](https://github.com/microsoft/vscode/issues/107015)

## Summary

Keep open for the custom-editor owner's assessment: current source still makes the reported language condition false after the XML association. VS Code now exposes activeCustomEditorId as an independent menu condition, but that does not fix the original contributions automatically; the supplied sample changes are sufficient to retest.

## Change summary

Custom-editor title buttons and palette commands disappear when their resourceLangId condition conflicts with a user-configured file association.

## Best solution

Use activeCustomEditorId with the custom editor's viewType for actions belonging to that editor, independently of the resource's language. The area owner should determine whether guidance resolves this accepted report or whether a remaining core defect exists; resourceLangId should continue reflecting the effective language.
