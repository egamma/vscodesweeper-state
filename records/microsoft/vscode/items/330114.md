# Issue #330114 — Agent Host doesn't discover hooks from installed plugins (discoverHooks() lacks a plugin search root)

[https://github.com/microsoft/vscode/issues/330114](https://github.com/microsoft/vscode/issues/330114)

## Summary

Verified against current main: `discoverHooks()` in sessionCustomizationDiscovery.ts really is a hand-rolled scanner limited to a hardcoded `searchRoots`/`fixedDiscoveryFiles` list (`.github/hooks`, `.copilot/hooks`, and a few fixed settings files) with no entry for installed-plugin hook files, while `discoverAgents`/`discoverSkills` delegate to the Copilot SDK's own plugin-aware discovery RPCs — exactly the asymmetry the reporter describes. This is a discovery/listing gap, not a functional one: `copilotSessionLauncher.ts` already converts parsed plugin hooks via `toSdkHooks(pluginsWithoutDirs.flatMap(p => p.hooks), ...)` at session launch, so plugin hooks do execute — they just never show up in the Hooks page.

## Change summary

Installed Copilot/Claude-format plugins' `hooks.json`/`hooks/hooks.json` never appear in the Agent Host's Hooks customization list, even though the same plugins' skills and agents are listed correctly and the hooks do run.

## Best solution

Extend `discoverHooks()` in src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts to surface installed-plugin hooks for listing — either by adding plugin-materialized directories (from AgentPluginManager, see src/vs/platform/agentHost/node/agentPluginManager.ts) as additional hook search roots, or by reusing the already-parsed plugin hook data (`IParsedHookGroup`, consumed via `toSdkHooks` in copilotSessionLauncher.ts) so the Hooks page reflects the same set of hooks that actually execute in a session.

## Evidence

- **hand-rolled hook scanner:** src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts lines 141-159 define `searchRoots` with only `.github/hooks` (workspace) and `.copilot/hooks` (user) as Hook-type roots, and `fixedDiscoveryFiles` (lines 168-179) only adds `.github/copilot/settings.json` and `.claude/settings.json` variants — no installed-plugin path anywhere.
- **asymmetric discovery:** discoverAgents() (line 614) and discoverSkills() (line 701) call `client.rpc.agents.discover(...)` / `client.rpc.skills.discover(...)` (SDK-native, plugin-aware), while discoverHooks() (line 714) only calls the local `_discoverHookRoot`/`_discoverFixedHookFiles` scanners against the static `searchRoots`/`fixedDiscoveryFiles` lists — confirming the reporter's root-cause analysis.
- **hooks do execute (not a functional gap):** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts line 849 calls `toSdkHooks(pluginsWithoutDirs.flatMap(p => p.hooks), ...)` at session launch, so installed-plugin hooks are wired into the running session even though they're absent from the discovery/listing path — this is a UI/listing bug, not a broken-hooks bug.
