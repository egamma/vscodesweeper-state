# Issue #339806 — Clicking into a migration entry should also have a migrate button

[https://github.com/microsoft/vscode/issues/339806](https://github.com/microsoft/vscode/issues/339806)

## Summary

Team-authored UX follow-up on the recently-added customization migration dashboard: clicking into a migration entry opens a detail view via `openCustomization`/`openMigrationItem` that currently lacks a migrate action, forcing users back to the list. No fix commit is present in this checkout, so it stays open; team-authored issues are protected from judgment closes anyway.

## Change summary

Clicking into a migration entry to view its details does not offer a way to migrate that entry directly from the detail view.

## Best solution

Surface the existing per-category/per-item migrate action in the detail view opened by openCustomization in aiCustomizationManagementEditor.ts, so users don't have to navigate back to the dashboard list to migrate the item they just inspected.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationDashboard.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts`
- **Validation:** A test in aiCustomizationManagementEditor.test.ts or customizationMigrationDashboard.test.ts asserting a migrate action is present/invocable when a migration entry's detail view is opened.
- **Behavior:**

  > Opening a migration entry's detail view (via clicking the entry in the migration dashboard tree) should show a Migrate action so the user can migrate that entry without returning to the dashboard list. The action should behave the same as the existing per-category Migrate button (migrateMigrationGroup / migrateCategory) for that single entry. Acceptance: a test confirms the detail view exposes a working migrate control for a migration entry.
- **Trace:**

  > customizationMigrationDashboard.ts wires tree.onDidOpen -> openMigrationItem -> callbacks.openCustomization(entry, entry.storage), which aiCustomizationManagementEditor.ts:3942's openCustomizationItem renders as the detail panel; the existing migrate action (migrateMigrationGroup/migrateCategory, lines 649-653 and 683-685) is only rendered in the group-row actions, not in the detail panel. The boundary is the detail-panel rendering/toolbar in openCustomizationItem — don't change the dashboard's list-level migrate buttons or bulk selection logic. Where uncertainty starts: whether migrating from the detail view should also respect the per-item selection/manual-review state (migrateDisabled, manualReviewReason) and what happens to the detail view after a successful single-item migrate (close it, show a success state, refresh the list).
- **Open decisions:**
  - Should migrating a single entry from the detail view close/refresh the detail panel, or keep it open showing an updated/migrated state?
  - Should the detail-view migrate action be disabled for manual-review entries the same way the group-level button is, or always enabled since the user explicitly opened it?
