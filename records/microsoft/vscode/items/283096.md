# Issue #283096 — Error activating the extension in tests of another extension

[https://github.com/microsoft/vscode/issues/283096](https://github.com/microsoft/vscode/issues/283096)

## Summary

Still reproduces on main: `UnifiedEnvironmentVariableCollection.getScopedEnvironmentVariableCollection` calls `this._register()` without checking whether the collection has been disposed, throwing when an extension activates after teardown (e.g. during tests).

## Change summary

Calling `getScopedEnvironmentVariableCollection` on an already-disposed `UnifiedEnvironmentVariableCollection` throws because `_register` is invoked on a disposed `DisposableStore`.

## Best solution

Guard `getScopedEnvironmentVariableCollection` in `UnifiedEnvironmentVariableCollection` (src/vs/workbench/api/common/extHostTerminalService.ts ~line 1089) so it either checks `isDisposed` before calling `_register`, or uses a local `DisposableStore` for scoped-collection event listeners that survives the parent's disposal gracefully.
