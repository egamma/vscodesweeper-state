# Issue #181935 — [html] Allow renaming images using F2

[https://github.com/microsoft/vscode/issues/181935](https://github.com/microsoft/vscode/issues/181935)

## Summary

A real HTML tooling gap remains on current main: rename handles HTML symbols and embedded JavaScript, but not a local resource referenced by an image `src`. The Backlog milestone indicates the request was accepted for consideration, and no older canonical owns this same behavior.

## Change summary

Allow F2 on a local HTML image `src` to rename both the referenced image file and its HTML reference.

## Best solution

Define rename semantics for local HTML resource links, then support an atomic workspace edit that renames the image resource and updates the relevant HTML references while rejecting remote URLs, missing files, and destination collisions.

## Plan brief

- **Likely files:** `extensions/html-language-features/server/src/modes/htmlMode.ts`, `extensions/html-language-features/server/src/htmlServer.ts`, `extensions/html-language-features/server/src/test/rename.test.ts`
- **Validation:** Extend the HTML language server rename tests with a local `<img src="./cat.gif">` case that verifies the resulting workspace edit renames the resource and updates the expected reference scope, plus negative cases for remote URLs and destination collisions.
- **Behavior:**

  > Invoking F2 on the local path in an HTML image `src` offers a file rename and applies the chosen name to both the referenced resource and the intended HTML references as one workspace edit. Remote URLs and paths that cannot be safely renamed must not offer resource rename. Existing tag rename and embedded JavaScript rename behavior must remain unchanged. Acceptance includes positive coverage for a relative image path and negative coverage for unsupported or unsafe targets.
- **Trace:**

  > The HTML server advertises rename support in extensions/html-language-features/server/src/htmlServer.ts and dispatches to the language mode at the cursor. `getHTMLMode().doRename` in extensions/html-language-features/server/src/modes/htmlMode.ts currently delegates directly to `htmlLanguageService.doRename`, with no path that resolves a document link to a workspace resource or emits a resource rename. The existing extensions/html-language-features/server/src/test/rename.test.ts suite exercises embedded JavaScript rename only. https://github.com/microsoft/vscode/issues/31141 is related only by the F2 surface and does not own this resource-link behavior. Keep tag and embedded-language symbol rename semantics outside the scope of this work.
- **Open decisions:**
  - Should renaming from one `img src` update only that attribute, every HTML reference to the same resource in the current document, or references across the workspace?
  - Is the feature initially limited to local `img src` values, or should the same contract cover other file-backed HTML attributes such as `script src`, `link href`, and `source src`?
  - May the F2 input change only the target file name, or may it also move the resource by accepting a different relative path?

## Evidence

- **current source gap:** extensions/html-language-features/server/src/modes/htmlMode.ts implements `doRename` by delegating directly to `htmlLanguageService.doRename`; the path contains no local-resource resolution or file rename operation for `src` values.
- **server capability:** extensions/html-language-features/server/src/htmlServer.ts advertises `renameProvider: true`, but routes requests only to the active language mode's `doRename`; current tests in extensions/html-language-features/server/src/test/rename.test.ts cover embedded JavaScript symbols, not referenced resources.
- **candidate canonical rejected:** https://github.com/microsoft/vscode/issues/31141 is older and open, but it tracks renaming JavaScript symbols inside `<script>` elements, not renaming files referenced by HTML attributes; it does not report the same observable symptom required for this re-reviewed item.
