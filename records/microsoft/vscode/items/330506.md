# Issue #330506 — Files signed by "Code Sign Test (DO NOT TRUST)" publisher

[https://github.com/microsoft/vscode/issues/330506](https://github.com/microsoft/vscode/issues/330506)

## Summary

Reporter found several bundled native DLLs (ffmpeg.dll, libegl.dll, libglesv2.dll, vk_swiftshader.dll, vulkan-1.dll) in the 1.133 Windows build signed with the placeholder "Code Sign Test (DO NOT TRUST)" certificate instead of the production release certificate — a genuine build/release-pipeline defect already acknowledged via the maintainer-applied `regression`/`new release`/`vscode-build` labels.

## Change summary

Some Electron/Chromium-bundled DLLs in the 1.133 Windows installer are signed with a test-only certificate rather than the real Microsoft signing cert.

## Best solution

Release engineering needs to check the Windows codesign step (build/azure-pipelines/win32/codesign.ts and build/azure-pipelines/common/codesign.ts) for the 1.133 build to see why these Electron-bundled native binaries were skipped or picked up a leftover test-signed artifact, and re-sign/re-release the affected files.
