# Issue #337749 — Do not show customization migration UI in a user's first chat session

[https://github.com/microsoft/vscode/issues/337749](https://github.com/microsoft/vscode/issues/337749)

## Summary

Real, well-scoped follow-up to the just-merged zero-count fix (PR #337738): current main still has no concept of a user's 'first chat session,' so the migration hint/card can appear the very first time a user opens an Agent Host chat even when it's technically accurate. Worth keeping open, but the exact definition of 'first session' needs a maintainer call before implementation.

## Change summary

Suppress the customization migration hint (chat notification) and the welcome-page migration card during a user's first chat session, even when real migratable customizations exist.

## Best solution

Add an explicit 'first session' gate (in addition to the existing candidate-count and dismissed/shown-once gates) to both `collectCustomizationMigrationHint` in chatServiceImpl.ts and the welcome-page migration card in aiCustomizationWelcomePagePromptLaunchers.ts, once a maintainer decides what 'first session' means and how it's detected.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationWelcomePagePromptLaunchers.ts`
- **Validation:** On a user's first-ever Agent Host chat session with pre-existing migratable customizations, neither the in-chat migration notification nor the welcome-page migration card should appear; on a subsequent session they should appear as today.
- **Behavior:**

  > When a user starts their first chat session (scope TBD by maintainer) and has customizations that would normally trigger the migration hint, the migration UI should stay hidden for that first session; from the next session onward, it should behave as it does today (governed by the existing candidate-count, dismissed, and shown-once gates). Acceptance: manual check that the hint/card is absent on session #1 with real candidates present, and present on session #2+.
- **Trace:**

  > Traced two surfaces that would need the new gate: the in-chat progress notification built by collectCustomizationMigrationHint/showCustomizationMigrationHint (chatServiceImpl.ts, ~lines 1688-1953), and the welcome-page card in renderCustomizationMigrationCard (aiCustomizationWelcomePagePromptLaunchers.ts, ~lines 386-409). Both already gate on real candidate counts (thanks to https://github.com/microsoft/vscode/pull/337738) and on per-session/per-workspace dismissal, but neither tracks whether this is the user's first-ever chat session. Do not touch the existing candidate-count computation in customizationMigrationServiceImpl.ts — the new check is additive, gating on top of it.
- **Open decisions:**
  - What defines a user's 'first chat session' here — first Agent Host session ever (global or profile-scoped), first session in the current workspace, or first message sent in a newly created session?
  - Should the suppression apply to just the in-chat notification, just the welcome-page card, or both?
  - How should 'first session' be detected and persisted — a new storage key, reuse of existing chat session history/store counts, or something else?
