# Issue #337749 — Do not show customization migration UI in a user's first chat session

[https://github.com/microsoft/vscode/issues/337749](https://github.com/microsoft/vscode/issues/337749)

## Summary

Active, unresolved design discussion — a team member commented the day this was reviewed proposing to broaden the scope beyond chat to the agents window, so the exact trigger and gating logic aren't settled yet. Milestone is the Backlog Candidates holding bin, so normal upvote/age rules apply and there's no reason to close.

## Change summary

Suppress the chat customization migration notice under the chat input during a user's first chat session, only showing it when there's actual prior customization state to migrate.

## Best solution

Design and implement a 'not on first use' gate for ChatCustomizationMigrationNotice (src/vs/workbench/contrib/chat/browser/aiCustomization/chatCustomizationMigrationNotice.ts), but first resolve aeschli's follow-up about also suppressing it for first-time agents window users — that changes what 'first session' means and where the gate lives.

## Plan brief

- **Behavior:**

  > On a user's very first chat (and possibly agents window) session, the customization migration notice under the chat input must not appear even if migratable customization state exists. Once the user is past their first session, the notice should show normally per existing hint/dismissal logic. Acceptance: a new test confirms the notice is suppressed on session #1 and shown afterward when a hint exists.
- **Trace:**

  > ChatCustomizationMigrationNotice (src/vs/workbench/contrib/chat/browser/aiCustomization/chatCustomizationMigrationNotice.ts) currently gates visibility only on computeMigrationHint() returning a hint, per-workspace dismissal storage, and chatEntitlementService sentiment — there is no concept of 'first session' anywhere in the chat contrib to hook into. The boundary: don't touch the existing dismissal/hint computation, only add a suppression condition for the first-use case. Where the uncertainty starts: aeschli's 2026-09-29 comment (see issue body) proposes extending this to the agents window's first use too, which may require a broader onboarding-state concept shared across chat and agents surfaces rather than a local flag in this file. Related: https://github.com/microsoft/vscode/issues/337738.
- **Open decisions:**
  - Should the suppression apply only to the first chat session, or also to a user's first time opening the agents window, as aeschli proposed?
  - How is 'first session' defined and persisted (e.g., a new storage flag, reuse of an existing onboarding/first-run signal)?
