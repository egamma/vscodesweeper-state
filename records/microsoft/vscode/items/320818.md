# Issue #320818 — Regression: spaces render too wide with a custom monospaced font

[https://github.com/microsoft/vscode/issues/320818](https://github.com/microsoft/vscode/issues/320818)

## Summary

Confirmed upstream Chromium rendering issue: the reporter verified the same space-width regression on vscode.dev in Chrome, and alexdima (team member) is actively investigating. The issue should stay open as an upstream tracker.

## Change summary

Spaces render wider than other monospace characters in the editor with certain custom fonts, breaking column alignment — a regression tied to Chromium's rendering of U+00A0 (non-breaking space).

## Best solution

Track as an upstream Chromium text-rendering regression. VS Code renders spaces as U+00A0 (`&nbsp;`) in the editor DOM (see `src/vs/editor/common/viewLayout/viewLineRenderer.ts`), and the reporter confirmed Chromium renders that glyph wider than U+0020 for their custom font despite identical font metrics. The fix likely needs to come from Chromium, or VS Code would need a workaround for affected fonts. alexdima is already engaged.
