# Issue #331704 — Allow disabling GitHub Copilot as an Agent Host provider without disabling Chat

[https://github.com/microsoft/vscode/issues/331704](https://github.com/microsoft/vscode/issues/331704)

## Summary

Current main still has the reported capability gap: Copilot Agent Host registration is unconditional, while Claude and Codex have provider-specific settings. The request should remain open as a feature request because existing settings do not cover it and no older issue owns the same observable behavior.

## Change summary

Add a provider-specific control that disables Copilot Agent Host participation and Copilot-specific Chat offerings without disabling Chat or other providers.

## Best solution

Provide a Copilot provider enablement setting that is honored consistently by Agent Host startup, new-session provider selection, and Copilot model/promotion surfaces, while preserving existing session data and leaving Claude, Codex, BYOK, and third-party providers available.

- **Fit:** aligned
- **Reason:** A provider-scoped opt-out improves settings fidelity and user control within VS Code's AI-assisted development surface without disabling the broader Chat experience.

- **Validation:** Add targeted tests showing that disabling the Copilot provider prevents copilotcli from being advertised for new sessions and removes Copilot unavailable-model and upgrade entries, while Codex remains selectable and persisted Copilot sessions are not deleted.
- **Behavior:**

  > Users can disable the Copilot Agent Host provider without disabling Chat. With the control disabled, Copilot is absent from new-session provider choices and Copilot-hosted models, sign-in prompts, upgrade actions, quota messaging, and promotions are absent from Chat, while other configured providers remain usable. Existing Copilot session data is retained and the default behavior remains unchanged when the control is enabled or unset.
- **Trace:**

  > Current main registers CopilotAgent unconditionally in both src/vs/platform/agentHost/node/agentHostMain.ts and agentHostServerMain.ts. Claude and Codex already have settings declared in common/agentService.ts, registered in common/agentHostStarter.config.contribution.ts, forwarded by the Electron and Node starters, and checked before provider registration. Workbench filtering in shouldSurfaceLocalAgentHostProvider also handles only Claude and Codex, while local Agent Host model pickers enable unavailable featured models independently. The boundary must include provider advertisement and Copilot-specific model/promotion presentation without changing other Copilot features listed as out of scope or deleting persisted sessions. Related requests https://github.com/microsoft/vscode/issues/330934 and https://github.com/microsoft/vscode/issues/331464 do not cover this complete behavior.
