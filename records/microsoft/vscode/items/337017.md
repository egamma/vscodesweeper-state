# Issue #337017 — Remote workspace appears 3 times in remote picker

[https://github.com/microsoft/vscode/issues/337017](https://github.com/microsoft/vscode/issues/337017)

## Summary

Fresh, credible report (with two screenshots showing the duplicate/confusing entries) about the Agents Window remote/dev-container workspace picker listing the same workspace multiple times after creating Dev Container sessions in WSL; already correctly labeled (bug, containers, agents-window, agent-host), so this stays open for a maintainer to diagnose rather than needing re-routing.

## Change summary

The remote/dev-container picker in the Agents Window shows the same WSL/Dev Container workspace repeated (up to 3 times, in different formats) instead of a single consolidated entry.

## Best solution

Extend the recent-workspace consolidation logic in sessionWorkspacePicker.ts (currently only dedupes LOCAL vs GITHUB group entries via `_useConsolidatedRemoteWorkspaces`/`localRepositoryIds`) to also collapse duplicate REMOTE-group entries that represent the same underlying workspace across different provider instances (e.g. plain WSL vs. Dev-Container-in-WSL providers).

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/devContainerAgentHostSessionsProvider.ts`
- **Validation:** A picker test asserting that recent workspaces representing the same underlying folder/repo across a WSL host and its Dev Container provider variant collapse into a single entry.
- **Behavior:**

  > Creating one or two Dev Container sessions in a WSL environment should not cause the same workspace to appear as multiple separate rows in the remote/session workspace picker; each distinct physical workspace should show as one (or one plus its explicit Dev Container mode toggle), not 3 look-alike entries.
- **Trace:**

  > sessionWorkspacePicker.ts already consolidates LOCAL vs GITHUB recent-workspace duplicates via `_useConsolidatedRemoteWorkspaces()`/`localRepositoryIds` (lines ~1558-1579), but nothing collapses duplicate REMOTE-group entries produced by separate provider instances (WSL provider vs. Dev-Container-in-WSL provider) for what is the same folder — traced via `rg` through sessionWorkspacePicker.ts and the remoteAgentHost/devContainerAgentHost provider classes; no test or fix for this specific cross-provider case was found on main. Where uncertainty starts: whether the fix is a new consolidation key (e.g. by resolved folder URI/host authority) or something in how the multiple providers are registered for the same WSL connection in the first place.
- **Open decisions:**
  - Should duplicate entries be consolidated by folder URI, repository ID, or resolved host authority, and does that key differ between WSL and true remote hosts?
  - When a workspace is reachable through both a plain WSL provider and a Dev-Container-in-WSL provider, which single row (and label/description) should be shown, and does the existing mode-toggle submenu (Use Local / Use Remote / Use Dev Container) already cover the same concept?

## Evidence

- **provider architecture:** src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts and devContainerAgentHostSessionsProvider.ts each register distinct provider instances/labels per connection; the picker groups recent workspaces by `providerId`, which likely explains near-duplicate rows for the same physical workspace surfaced through different providers.
