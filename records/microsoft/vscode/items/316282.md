# Issue #316282 — Copilot CLI session fails in detached HEAD state due to incorrect branch selection

[https://github.com/microsoft/vscode/issues/316282](https://github.com/microsoft/vscode/issues/316282)

## Summary

Still reproduces on main: when in detached HEAD state, headBranchName is undefined, so resolveBranchSelection returns undefined and the UI auto-selects the first branch in the list (typically main/master), which doesn't match the actual worktree state. No fix has landed.

## Change summary

Starting a Copilot CLI session from a detached HEAD folder auto-selects an incorrect branch, causing a runtime error on prompt submission.

## Best solution

Handle the detached HEAD case in sessionOptionGroupBuilder.ts: when headBranchName is undefined, either omit the branch picker entirely, show a '(detached HEAD)' read-only indicator, or resolve the current commit SHA as the selected ref so the session doesn't attempt to use a non-checked-out branch. The copilotCLIChatSessions.ts getRepositoryProperties path (line ~1571) already correctly yields undefined repositoryProperties for detached HEAD — the gap is in the branch picker UI and session initialization that consumes the selected branch.
