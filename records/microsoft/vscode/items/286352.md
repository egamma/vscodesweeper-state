# Issue #286352 — Wrapped file edit pills don't look great

[https://github.com/microsoft/vscode/issues/286352](https://github.com/microsoft/vscode/issues/286352)

## Summary

The polish gap remains on current main: narrow chat responses can wrap a long filename inside the bordered edit pill while leaving the status label on the preceding line. The issue should stay open, with a UX decision between moving the complete pill to a new line and truncating its filename.

## Change summary

Keep file-edit pills visually compact and coherent when long filenames exceed the available chat width.

## Best solution

File-edit activity should remain a coherent, easily scanned row at narrow widths, without creating a tall chip whose filename wraps independently of its icon and diff counts. Choose either whole-pill wrapping or single-line filename truncation, then apply that behavior consistently across both edit-pill consumers.
