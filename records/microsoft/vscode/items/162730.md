# Issue #162730 — Consider to change default layout for merge editor

[https://github.com/microsoft/vscode/issues/162730](https://github.com/microsoft/vscode/issues/162730)

## Summary

The first-use merge editor layout is still mixed; remembering a user's column-layout selection does not deliver the requested default. Keep this under discussion for the suggested comparison of layouts; the older discoverability issue does not own the same observable request.

## Change summary

Consider making the three-column vertical layout the default merge editor experience.

## Best solution

Choose the first-use layout using evidence about conflict completion and abandonment across available editor sizes, while preserving explicit user layout preferences. Keep layout discoverability and default base visibility as separate decisions.

Evaluate whether three columns should replace the mixed first-use layout or whether available space should determine the initial arrangement. Previously saved explicit layout preferences and existing base-visibility choices must remain respected.
- **Trace:**

  > MergeEditorLayoutStore in src/vs/workbench/contrib/mergeEditor/browser/view/mergeEditor.ts defaults to mixed and restores profile-scoped saved state. Existing telemetry in src/vs/workbench/contrib/mergeEditor/browser/telemetry.ts records layout and conflict-session outcomes, but the inspected source does not establish an experiment result. The uncertainty is which first-use behavior the project should adopt, not how to render columns. Preserve saved preferences, merge semantics, and base visibility; https://github.com/microsoft/vscode/issues/160314 concerns discoverability and https://github.com/microsoft/vscode/issues/165628 concerns base visibility, neither substitutes for this decision.
- **Open decisions:**
  - Should users without a saved layout receive a fixed column layout, retain mixed layout pending evaluation, or receive an initial layout selected from available editor space?
