# Issue #137686 — Git - Sync Changes button pushes to different branch than current branch

[https://github.com/microsoft/vscode/issues/137686](https://github.com/microsoft/vscode/issues/137686)

## Summary

The current source still explicitly pushes to the pull upstream, overriding Git's configured push destination. Keep this issue open while the linked fixing PR is reviewed; it has not merged.

## Change summary

Push and Sync can send commits to the upstream branch or repository instead of honoring the configured push destination.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/323650 so default Push and Sync honor Git's push configuration while retaining the upstream as the pull/rebase source. Ensure the confirmation accurately describes those potentially different destinations and explicit push commands retain their existing behavior.

## Evidence

- **Current source confirms the wrong destination:** In extensions/git/src/repository.ts, Repository._sync assigns remoteName = head.upstream.remote and pushBranch = `${head.name}:${head.upstream.name}`, then passes both explicitly to _push. For feature tracking origin/main, the push therefore targets origin feature:main; for a triangular workflow tracking upstream/main, it targets upstream rather than the configured origin push remote.
- **Explicit arguments bypass Git push configuration:** Repository.push in extensions/git/src/repository.ts:2504-2513 constructs the same upstream remote/refspec. Repository._push at lines 2834-2836 forwards these arguments, and extensions/git/src/git.ts:2565-2604 appends them to the git push command. This prevents Git's normal default-destination selection from honoring push.default=current, remote.pushDefault, or branch-specific pushRemote on these paths.
- **Confirmation shares the incorrect assumption:** extensions/git/src/commands.ts:4290-4308 formats the Sync confirmation using HEAD.upstream.remote and HEAD.upstream.name for both pull and push, then invokes repository.sync(HEAD, rebase). The source therefore matches the reporter's origin/main confirmation as well as the incorrect push destination.
- **Confirmed triangular workflow:** https://github.com/microsoft/vscode/issues/137686#issuecomment-2338545510 supplies the complete configuration and reproduction: main tracks upstream/main, remote.pushDefault is origin, and Sync pushes to upstream/main instead of origin/main. Other supplied comments independently confirm that push.default=current does not resolve the problem.
- **Open fixing PR:** Verified https://github.com/microsoft/vscode/pull/323650 is OPEN and explicitly declares Fixes for this issue. It proposes honoring Git's configured push target, retaining upstream-based pulls, updating confirmation/tooltips, and exercising current and triangular push workflows. Its claimed test results are PR-author evidence, not checks executed during this read-only review.
- **Canonical search does not justify consolidation:** Verified https://github.com/microsoft/vscode/issues/182510 and https://github.com/microsoft/vscode/issues/158644 are open related reports, but both were created after this issue and cannot be canonical targets under the re-review rule. The older open https://github.com/microsoft/vscode/issues/70136 concerns pull failure when a remote-tracking ref differs from the remote branch name, not successful pushes to the wrong destination. The thread-linked https://github.com/microsoft/vscode/issues/135186 and https://github.com/microsoft/vscode/issues/135208 are closed and concern pull/fast-forward failures.
