# Issue #112362 — Snippet transformation does not work with nested snippets

[https://github.com/microsoft/vscode/issues/112362](https://github.com/microsoft/vscode/issues/112362)

## Summary

Keep open: nontrivial nested snippet insertion still removes the outer placeholder's transformation in current source. Plain-text completions now bypass structural merging, so the original simple example may behave better, but that does not resolve the broader maintainer-confirmed defect.

## Change summary

Preserve outer snippet transformations when accepting completions or inserting snippets inside their active placeholders.

## Best solution

Retain meaningful outer transformation behavior across nested insertion without breaking inner tabstop navigation or mirrors. A maintainer should settle when transformations run for nested snippets with editable placeholders; preserve the existing plain-text insertion fast path.

- **Behavior:**

  > Accepting a completion or inserting a nested snippet within an outer placeholder must not silently discard the outer transformation. Plain-text insertion should continue to produce the expected transformed mirror when leaving the outer placeholder. For nested snippets with editable tabstops, the transformation must use the appropriate completed outer value at the maintainer-approved navigation boundary. Acceptance must cover both the resulting text and preservation of inner tabstop navigation and mirrors.
- **Trace:**

  > Accepted suggestions reach SnippetController2.insert through src/vs/editor/contrib/suggest/browser/suggestController.ts, and an existing session routes to SnippetSession.merge. Current SnippetSession.merge bypasses structural merging for trivial snippets, so the original plain-type completion case must be distinguished from nontrivial nested insertion. In src/vs/editor/contrib/snippet/browser/snippetSession.ts, OneSnippet.merge replaces every active outer placeholder with nested children and removes its decoration; the removed placeholder's transform is not retained, while OneSnippet.move executes transformations from current placeholder metadata. Existing snippetSession.test.ts covers merging, nested mirrors, and transformations separately. The maintainer's discussion in https://github.com/microsoft/vscode/issues/112362 explicitly leaves complex nested transformation semantics unresolved; uncertainty starts at the observable timing and value used when inner editable placeholders remain active. Preserve trivial insertion behavior, nested navigation, mirrors, and ordinary transformations; fallback-variable syntax requests in later comments are not the demonstrated merge defect.
- **Open decisions:**
