# Issue #275522 — Ghost text completion is not visible if it only consists of whitespaces

[https://github.com/microsoft/vscode/issues/275522](https://github.com/microsoft/vscode/issues/275522)

## Summary

Keep open: whitespace-only inline suggestions still lack a dedicated visual cue in the current source. An open PR explicitly addresses this request and should be reviewed before considering completion.

## Change summary

Make pending whitespace-only inline completions visibly distinguishable from whitespace already in the document.

## Best solution

Review https://github.com/microsoft/vscode/pull/275528 against both reported cases: indentation-only suggestions and the remaining space after typing a suggestion's non-whitespace text. Preserve existing acceptance and cancellation behavior while making the pending whitespace recognizable.

## Evidence

- **Reporter-observable gap:** https://github.com/microsoft/vscode/issues/275522 describes indentation-only suggestions and a remaining suggested space after manually typing `static`; moving the cursor cancels that space, revealing that it was never inserted.
- **Current source:** In src/vs/editor/contrib/inlineCompletions/browser/view/ghostText/ghostTextView.ts, _nonWhitespaceCount removes whitespace before counting characters. _extraClassNames requires a truthy nonWhitespaceCount before adding `short-text`, so zero-non-whitespace suggestions do not receive its dotted underline. ghostTextView.css has no dedicated whitespace-only style.
- **Existing-capability check:** src/vs/editor/common/core/editorColorRegistry.ts registers editorGhostText.background and editorGhostText.border; the background defaults to null and the border defaults to null in ordinary light/dark themes. Customizing these colors can highlight all ghost text, but does not provide the requested automatic whitespace-only cue. The additional-lines renderer in ghostTextView.ts explicitly uses renderWhitespace = 'none'.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/275528 is verified OPEN with mergedAt null and body `Fixes #275522`. Its diff adds a whitespace-only class for nonempty injected text whose trimmed length is zero, plus background and border styling. It is a pending implementation, not a landed fix.
- **Related visibility improvement is not full coverage:** https://github.com/microsoft/vscode/issues/284517 is closed and concerns distinguishing a suggested slash from existing text. The maintainer's verification comment at https://github.com/microsoft/vscode/issues/284517#issuecomment-3800783585 describes dotted underlining for short non-whitespace text; current source excludes the zero-non-whitespace case reported here.

The related closed short-character report is neither an open duplicate target nor proof that whitespace-only visibility is resolved.
