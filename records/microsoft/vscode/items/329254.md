# Issue #329254 — Add option to sort extensions view with available updates first

[https://github.com/microsoft/vscode/issues/329254](https://github.com/microsoft/vscode/issues/329254)

## Summary

Reasonable request that isn't fully covered by current behavior: the Installed extensions view only puts outdated extensions first as an implicit fallback ordering, not as a selectable, persistent sort option, so the gap the reporter describes is real.

## Change summary

Add a selectable sort option in the Extensions view that keeps extensions with available updates pinned to the top of the list.

## Best solution

Extend the existing @sort: mechanism in src/vs/workbench/contrib/extensions/browser/extensionsViews.ts (currently installs/rating/name/publishedDate/updateDate) with an explicit 'updates available' sort mode, distinct from the current default-only outdated-first bucketing in filterInstalledExtensions (lines ~503-533), so it stays selected/stable as the user updates extensions one at a time.
