# Issue #186299 — Consider to bubble up partially checked state

[https://github.com/microsoft/vscode/issues/186299](https://github.com/microsoft/vscode/issues/186299)

## Summary

The requested partial-selection indication is still missing from extension-contributed tree views: current code represents mixed children as an unchecked parent. Keep this accepted Backlog request open; newer tri-state work concerns a different tree surface and does not supersede it.

## Change summary

Show a partially checked parent checkbox when some, but not all, descendant tree items are checked.

## Best solution

Support an accessible mixed-selection state in extension-contributed tree views while preserving existing checked/unchecked propagation and manual-management behavior. Decide whether mixed state is derived presentation only or also an explicit extension API state before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/common/views.ts`, `src/vs/workbench/browser/parts/views/treeView.ts`, `src/vs/workbench/browser/parts/views/checkbox.ts`, `src/vs/workbench/api/common/extHostTreeViews.ts`
- **Validation:** Use an extension-contributed tree with a parent and two checkbox children: checking one child must distinguish the parent from both fully unchecked and fully checked; checking both and clearing both must restore those respective states. Repeat with nested ancestors, keyboard interaction, screen-reader state announcements, and manageCheckboxStateManually enabled according to the agreed contract.
- **Behavior:**

  > An extension-contributed tree should distinguish partial child selection from no selection on its parent checkbox. All-checked and all-unchecked children must remain distinguishable from mixed selection, including for assistive technology. Acceptance should cover nested ancestors and preserve the documented behavior of manually managed checkboxes.
- **Trace:**

  > The original test plan https://github.com/microsoft/vscode/issues/186164 locates this request in the extension TreeItem API. In src/vs/workbench/browser/parts/views/treeView.ts, setCascadingCheckboxUpdates detects mixed children but collapses that result to parent.isChecked = false. The internal checkbox contract in src/vs/workbench/common/views.ts and the public TreeItemCheckboxState enum in src/vscode-dts/vscode.d.ts are binary, and TreeItemCheckbox in src/vs/workbench/browser/parts/views/checkbox.ts renders that binary state. This establishes a missing capability rather than a violation of the documented API. Preserve existing propagation and manual-management contracts unless the maintainer explicitly approves changing them; the uncertainty is whether mixed state is presentation derived by VS Code or an extension-visible state. The QuickTree icon discussion at https://github.com/microsoft/vscode/issues/258460 concerns a separate surface, not completion of this request.
- **Open decisions:**
  - Should partial selection be derived only for automatically managed tree checkboxes, or should extensions also be able to supply and observe an explicit mixed state through the public API when managing checkboxes manually?
