# Issue #153903 — Automatically Run task does not wait for postCreateCommand in a Dev Container

[https://github.com/microsoft/vscode/issues/153903](https://github.com/microsoft/vscode/issues/153903)

## Summary

Keep this accepted request open and move it to the Dev Containers tracker for lifecycle coordination. The existing `waitFor: "postCreateCommand"` option is directly relevant, but its effect on automatic task startup has not been verified here.

## Change summary

Allow automatically launched folder-open tasks to wait until Dev Container package installation in postCreateCommand finishes.

## Best solution

Use the existing Dev Container lifecycle barrier, `waitFor: "postCreateCommand"`, if it reliably delays folder-open tasks until installation completes. The Dev Containers owner should verify that integration and address any remaining ordering gap without changing automatic task timing for ordinary workspaces.

- **Reported ordering and corroboration:** https://github.com/microsoft/vscode/issues/153903 describes package installation in postCreateCommand overlapping tasks configured with runOptions.runOn = folderOpen. The November 2023 commenter independently reports tasks failing because those dependencies are not yet installed; another commenter confirms the issue in December 2024.
- **Current core task behavior:** src/vs/workbench/contrib/tasks/browser/runAutomaticTasks.ts: RunAutomaticTasks._tryRunTasks waits for task reconnection, workspace trust and task-system information, then discovers and runs folderOpen tasks. This contribution has no explicit Dev Container postCreateCommand completion barrier.
- **Existing capability:** https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json defines waitFor with postCreateCommand as an allowed value and updateContentCommand as the default. Its description specifies which lifecycle command must finish before execution continues in the background while the UI starts. This directly addresses initialization ordering, but the extension-to-core task interaction was not executed or conclusively traced.
- **Task configuration boundary:** src/vs/workbench/contrib/tasks/common/jsonSchema_v2.ts exposes runOn values default, folderOpen and worktreeCreated. dependsOn and dependsOrder sequence other tasks, not Dev Container lifecycle commands; they do not directly express the requested dependency.
- **Discussion workaround:** The July 2025 comment at https://github.com/microsoft/vscode/issues/153903 suggests using postAttachCommand for the task command. That is a lifecycle-based workaround, not confirmation that the existing folderOpen task waits for package installation.
