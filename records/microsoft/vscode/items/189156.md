# Issue #189156 — [scss] Cannot open `.scss` files using `@use` import syntax

[https://github.com/microsoft/vscode/issues/189156](https://github.com/microsoft/vscode/issues/189156)

## Summary

The SCSS link-resolution defect remains credibly reproduced across Windows and macOS, including newer VS Code versions, and the Backlog milestone does not prevent keeping it open. Navigation inconsistently handles relative Sass imports, partial filenames, and different invocation methods.

## Change summary

Make Go to Definition and link-following navigation resolve relative SCSS `@use` and `@import` targets, including Sass partial filename conventions.

## Best solution

Unify SCSS document-link and definition resolution in the built-in CSS language features so relative paths resolve Sass partials consistently across Ctrl/Cmd-click, F12, and Ctrl+F12.

## Plan brief

- **Likely files:** `extensions/css-language-features/client/src/cssClient.ts`, `extensions/css-language-features/server/src/cssServer.ts`
- **Validation:** Add or extend CSS language-feature tests with two PascalCase sibling folders and an SCSS partial imported through a relative `@use`/`@import`; verify document links and definition navigation resolve the same target for Ctrl/Cmd-click, F12, and Ctrl/Ctrl+F12-equivalent providers.
- **Behavior:**

  > In an SCSS file, navigation from a relative `@use` or `@import` path must open the referenced stylesheet. Sass partial forms that omit the leading underscore and `.scss` extension must resolve where Sass accepts them. Ctrl/Cmd-click, Go to Definition, and Go to Type Definition must not disagree about the same import target. Existing navigation for explicit filenames and same-directory imports must remain unchanged.
- **Trace:**

  > The report and confirmations establish failures in the built-in SCSS navigation flow with extensions disabled, across Windows and macOS. The latest comment narrows the remaining uncertainty: Ctrl+click can succeed while F12 and Ctrl+F12 fail, suggesting separate document-link and definition-provider resolution paths in `extensions/css-language-features/client/src/cssClient.ts` and `extensions/css-language-features/server/src/cssServer.ts`. A commenter also identifies Sass partial expansion (`misc` to `_misc.scss`) as directory-sensitive. https://github.com/microsoft/vscode/issues/142836 is related but closed and did not resolve this symptom. Keep the boundary to SCSS import target resolution; CSS URL navigation and unrelated language features must not change.
- **Open decisions:**
  - Should Go to Type Definition on an SCSS import intentionally resolve the stylesheet target like Go to Definition, or should only Ctrl/Cmd-click and F12 be covered?

## Evidence

- **original reproduction:** The reporter reproduced on VS Code 1.80.2 with extensions disabled: Ctrl+click on a relative `@use` or `@import` target reports `Unable to open` instead of opening the SCSS file.
- **independent confirmations:** Independent comments confirm the failure on macOS 1.85.1 and again in January 2025; another report shows resolution fails for an imported `_misc.scss` partial when the Sass-valid underscore and extension are omitted.
- **remaining inconsistency:** The May 2025 comment reports Ctrl+click working while F12 and Ctrl+F12 still fail, indicating that at least one navigation path remains broken rather than the central issue being conclusively resolved.
- **related prior issue:** https://github.com/microsoft/vscode/issues/142836 was cited by a commenter but was already closed without resolving this observable symptom, so it is not an open canonical duplicate.
