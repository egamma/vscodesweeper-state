## Summary

Keep this protected plan-item open: decoration value parsing still happens inside both GPU render strategies, so the requested early validation and DOM fallback remain incomplete. The issue already has the correct editor-gpu routing.

## Change summary

Move inline-decoration style parsing and validation into ViewGpuContext so unsupported values are rejected before GPU rendering.

## Best solution

Have GPU eligibility account for whether decoration values can actually be parsed, allowing unsupported lines to use DOM rendering without render-strategy errors. Preserve existing supported decoration behavior across both full-file and viewport rendering.
