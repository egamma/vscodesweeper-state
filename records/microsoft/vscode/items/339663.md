# Issue #339663 — Agent Host: switching models silently clears custom agent selection and tool allowlist

[https://github.com/microsoft/vscode/issues/339663](https://github.com/microsoft/vscode/issues/339663)

## Summary

A re-reviewed item staying open: I traced a real asymmetry in the turn-send path that plausibly causes exactly this symptom, but it isn't a confirmed, airtight fix — the conditional guard that should mirror the model-change path is missing for agent changes, and whether that's the actual bug (vs. an intentional per-turn resync) needs a maintainer call.

## Change summary

Switching the selected model in an Agent Host chat clears the active custom agent (and its tool allowlist), expanding the live tool surface unexpectedly.

## Best solution

In AgentSideEffects._sendTurnMessage (src/vs/platform/agentHost/node/agentSideEffects.ts), `agent.chats.changeModel` is only invoked when `message.model` is set, but `agent.chats.changeAgent` runs unconditionally on every turn with whatever `message.agent` is (possibly undefined) — decide whether an absent `message.agent` should mean 'leave unchanged' (mirroring the model guard) or is intentionally authoritative per turn, then fix the asymmetry.

The boundary: do not touch unrelated send-path logic (checkpointing, attachments, Codex model bookkeeping) — only the agent/model selection-update gating. Where the uncertainty starts: I did not trace the client-side (workbench) code that populates `message.agent` on an outgoing turn to confirm it is in fact omitted on a plain model switch versus always carrying the current selection forward.
- **Open decisions:**
