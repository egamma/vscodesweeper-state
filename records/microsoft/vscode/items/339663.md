[https://github.com/microsoft/vscode/issues/339663](https://github.com/microsoft/vscode/issues/339663)

## Summary

Fresh, well-documented report with concrete Agent Host log excerpts showing the custom agent being deselected on a model switch, which in turn drops the agent's tool allowlist; I traced a plausible host-side mechanism but could not conclusively pin the fix location, so this needs a maintainer's diagnosis rather than a close.

## Change summary

Switching the selected model in an Agent Host (Copilot) chat silently clears the active custom agent selection, so its `tools:` allowlist stops being enforced and the full tool registry becomes available.

## Best solution

A maintainer should confirm whether `AgentSideEffects._sendTurnMessage` (src/vs/platform/agentHost/node/agentSideEffects.ts:2063-2069) unconditionally calling `agent.chats.changeAgent(chatUri, message.agent, ...)` on every turn — even when no agent change was intended — is what clears the selection when `message.agent` arrives undefined, versus the behavior originating in the renderer's mode-carry-forward logic or the vendored Copilot Agent SDK (not present in this checkout) reacting to `session.setModel`.
