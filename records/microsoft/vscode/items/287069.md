# Issue #287069 — start must be before end

[https://github.com/microsoft/vscode/issues/287069](https://github.com/microsoft/vscode/issues/287069)

## Summary

Still reproduces on main: a race condition in the inline completions screen reader path causes the 'start must be before end' assertion when the line text is shorter than the ghost text parts' column positions.

## Change summary

Screen reader rendering of inline completions throws 'start must be before end' when the line text has been shortened after the ghost text was computed.

## Best solution

Guard `renderForScreenReader` in ghostText.ts against the case where `lineText` is shorter than the last part's column — either clamp part columns to the available text length, or bail early when the text is stale. The caller in `inlineCompletionsController.ts` re-reads the line after awaiting but the ghost text parts may reference stale column positions.
