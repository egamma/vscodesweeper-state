# Issue #258173 — Split terminal with inherited paths does not work when starting from a WSL terminal

[https://github.com/microsoft/vscode/issues/258173](https://github.com/microsoft/vscode/issues/258173)

## Summary

Still reproduces on main: the `getCwdForSplit` function in the 'inherited' case calls `getSpeculativeCwd()` which returns a raw Linux path string from WSL cwd detection. This string is then passed as the `cwd` to `createTerminal`, but the path format (a Linux path like `/home/user/...`) is not properly handled in the Windows/WSL bridging context, causing a launch failure. No fixing commit found.

## Change summary

Splitting a WSL terminal with the default 'inherited' split cwd setting fails with a path error because the detected Linux cwd path is not properly translated for the WSL terminal launch context.

## Best solution

The `getCwdForSplit` function (in `src/vs/workbench/contrib/terminal/browser/terminalActions.ts`) needs to handle the WSL/remote case for 'inherited' mode — either by converting the detected cwd into a proper URI via `_pathService.fileURI()` (as `getCwdResource` does), or by ensuring the cwd string is passed through the remote path resolution layer before being used to launch the split terminal. The fix likely lives in `terminalActions.ts` (the `getCwdForSplit` function) and possibly `terminalInstance.ts` (`getSpeculativeCwd`).
