# Issue #337400 — MacOS: Ctrl+T and Ctrl+P cancel if window focus is taken away

[https://github.com/microsoft/vscode/issues/337400](https://github.com/microsoft/vscode/issues/337400)

## Summary

Quick Open / Go to Symbol intentionally close when the window loses focus — this is the default `ignoreFocusOut: () => false` behavior wired into the blur handler, not a macOS-specific bug, so this can be closed as as-designed.

## Change summary

Ctrl+P / Ctrl+T quick pickers lose their typed text and close when the app window loses and regains focus.

## Best solution

Keep the current behavior — quick pickers are meant to close on window blur to avoid a stale/disconnected picker lingering behind the user; no code change needed.

- **Proposed comment:**

  > Thanks for the report! This is expected behavior rather than a bug: Quick Open (Ctrl+P) and Go to Symbol (Ctrl+T) are designed to close whenever the VS Code window loses focus, so switching to another app and back dismisses the picker along with whatever you'd typed. This applies on all platforms, not just macOS — some other quick pickers opt in to staying open on focus loss, but the main navigation pickers intentionally do not. Closing as as-designed, but feel free to open a feature request if you'd like an option to keep it open across focus changes.

## Evidence

- **default option:** src/vs/platform/quickinput/browser/quickInputService.ts:76 sets `ignoreFocusOut: () => false` for the default quick input host used by Go to File (Ctrl+P) and Go to Symbol (Ctrl+T).
- **blur handler:** src/vs/platform/quickinput/browser/quickInputController.ts:348-351 registers `focusTracker.onDidBlur` which calls `this.hide(QuickInputHideReason.Blur)` whenever `ignoreFocusOut` is false — exactly reproducing the reported symptom of the picker disappearing after an app switch.
- **opt-in escape hatch:** Callers that want persistence across focus loss pass `ignoreFocusLost: true` (e.g. quickInputController.ts:561, 664); the main Quick Open entry points do not set this, so the close-on-blur behavior is deliberate rather than an oversight.
