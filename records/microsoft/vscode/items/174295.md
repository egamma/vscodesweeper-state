# Issue #174295 — Multiple Import Organizers results in corrupted code

[https://github.com/microsoft/vscode/issues/174295](https://github.com/microsoft/vscode/issues/174295)

## Summary

The corruption path remains present on current main, and the open PR https://github.com/microsoft/vscode/pull/328186 directly targets it with regression coverage. Keep the issue open while that human-owned fix is reviewed.

## Change summary

Multiple code-action providers receive the same pre-edit document state, allowing later stale edits to duplicate or corrupt code during save.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/328186 so save-time code actions are queried and applied sequentially by provider, with each provider observing edits from the preceding provider.

- **current source:** In src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts, CodeActionOnSaveParticipant obtains one aggregated CodeActionSet through getCodeActions at lines 411-440 and only afterward applies every returned action at lines 419-426. getCodeActions queries the matching providers concurrently, so their edits are based on the same document state.
