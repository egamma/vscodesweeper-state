# Issue #114049 — Git - Improve missing Git user/name behavior

[https://github.com/microsoft/vscode/issues/114049](https://github.com/microsoft/vscode/issues/114049)

## Summary

Keep open: the auto-detection setting exists, but missing Git identity still produces a modal error without an in-editor configuration action. This remains the established issue for improving that experience, with a maintainer having redirected a matching request here.

## Change summary

Improve missing Git author identity handling through configurable auto-detection, less disruptive messaging, and an in-editor way to configure user.name and user.email.

## Best solution

Provide an actionable missing-identity experience in the built-in Git extension that lets users explicitly configure their commit identity without leaving VS Code. Preserve git.requireGitUserConfig and settle configuration scope and notification behavior before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/git.ts`, `extensions/git/package.json`, `extensions/git/src/test/smoke.test.ts`
- **Validation:** With a disposable test repository and isolated Git configuration, attempt a Source Control commit with user.name or user.email missing; verify the approved notification and configuration flow, cancellation without configuration changes or a commit, and successful committing after explicit configuration. Check that existing identities and git.requireGitUserConfig=false retain their behavior, and that configuration affects only the user-selected scope. These checks were not executed during this read-only review.
- **Behavior:**

  > When a Source Control commit cannot proceed because Git author identity is missing, users should be able to understand and resolve the problem within VS Code. The existing git.requireGitUserConfig setting already addresses optional auto-detection and must remain available. Identity configuration must be explicit, preserve existing values, and make its scope clear; cancelling must not change configuration or create a commit. Acceptance should cover either identity field missing, successful committing after configuration, cancellation, and unchanged behavior for already-configured repositories.
- **Trace:**

  > The normal commit path in extensions/git/src/repository.ts reads git.requireGitUserConfig and passes requireUserConfig to Repository.commit in extensions/git/src/git.ts, which conditionally adds user.useConfigOnly=true. handleCommitError checks user.name and user.email and emits the corresponding missing-configuration error codes. The command error handler in extensions/git/src/commands.ts maps both codes to a modal error with Learn More and generic diagnostic actions, without a configuration flow. Repository exposes local and global configuration reads and a local setConfig operation, but the record does not settle the write scope for this feature. Preserve existing Git identity resolution, commit requirements, authentication, and terminal behavior; GitHub sign-in is not equivalent to selecting commit author identity. https://github.com/microsoft/vscode/issues/144738 was explicitly consolidated here, while https://github.com/microsoft/vscode/issues/303523 requests a distinct profile-only override. The remaining uncertainty is the user-facing configuration scope and whether failed commits should use warning rather than error presentation.
- **Open decisions:**
  - Should identity configuration be repository-local only, or offer an explicit choice between repository-local and global configuration, and which scope should be the default?
  - When an identity requirement prevents a commit, should VS Code retain error presentation or use a warning, and should the prompt remain modal?

## Evidence

Setting it to false permits Git to guess identity; it does not provide identity-entry UI. The author's confirmation is https://github.com/microsoft/vscode/issues/114433#issuecomment-761130259.
