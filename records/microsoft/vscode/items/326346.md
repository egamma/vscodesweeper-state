# Issue #326346 — Copilot Chat sessions not synchronized even though chat.sessionSync.enabled is true

[https://github.com/microsoft/vscode/issues/326346](https://github.com/microsoft/vscode/issues/326346)

## Summary

Confirmed in source: session sync resolves the repo via GitHub.com's repo API (`_resolveRepository`/`getGitHubRepoInfoFromContext` in remoteSessionExporter.ts), so it only works for GitHub.com-hosted remotes by design — a maintainer confirmed this in the thread. The thread has since turned into a concrete ask (from a second reporter) to extend sync to other remote providers (Bitbucket, Azure Repos), which is a real, unaddressed gap worth routing rather than closing.

## Change summary

chat.sessionSync.enabled does not sync local chat sessions when the workspace's git remote is not hosted on github.com (e.g. internal Bitbucket, Azure Repos), and there's a side effect where enabling it also breaks local /chronicle results for those repos.

## Best solution

Keep open as a feature request to extend session-sync's repo-resolution beyond github.com remotes (or make cloud sync gracefully coexist with local /chronicle indexing when the repo isn't github.com-backed); route to the Copilot Chat / sessions area owners who maintain extensions/copilot/src/extension/chronicle.
