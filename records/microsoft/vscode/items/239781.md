# Issue #239781 — Runtime error when renaming an existing folder into a nested folder structure

[https://github.com/microsoft/vscode/issues/239781](https://github.com/microsoft/vscode/issues/239781)

## Summary

The defect remains on current main: Explorer accepts `foo/bar` while renaming folder `foo`, then the file service rejects moving the folder into its own descendant and surfaces a runtime error. This is a bounded validation bug that should remain open.

## Change summary

Renaming an existing folder to a nested path beneath itself passes Explorer validation and produces a runtime error.

## Best solution

Explorer rename validation should reject destinations equal to or nested beneath the folder being renamed, while preserving supported multi-segment paths for creating new resources and for valid moves outside the source subtree.
