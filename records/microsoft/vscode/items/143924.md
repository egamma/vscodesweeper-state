# Issue #143924 — Delay starting the web worker extension host until activating first extension

[https://github.com/microsoft/vscode/issues/143924](https://github.com/microsoft/vscode/issues/143924)

## Summary

Still valid: the browser extension service (`extensionService.ts`) always eagerly starts the web worker extension host, unlike the desktop side which already supports `LazyAutoStart`. The requested optimization has not been implemented for the browser path. Team-authored issue — keeping open.

## Change summary

Delay launching the web worker extension host in vscode.dev until the first extension actually needs to activate, avoiding the cost of spinning up an unused worker.

## Best solution

Apply the same `LazyAutoStart` startup mode used on the desktop side (via `LocalWebWorkerExtHostEnablement.Lazy` in `nativeExtensionService.ts`) to the browser `BrowserExtensionHostFactory.createExtensionHost` in `src/vs/workbench/services/extensions/browser/extensionService.ts`. The `LazyCreateExtensionHostManager` infrastructure already handles the deferred creation.
