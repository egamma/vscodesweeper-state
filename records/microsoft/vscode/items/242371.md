- **Canonical includes local reports:** https://github.com/microsoft/vscode/issues/211443#issuecomment-2551771786 explicitly notes that the problem may not be limited to remote terminals. The broader local OSC file-link report https://github.com/microsoft/vscode/issues/204274 was consolidated there by https://github.com/microsoft/vscode/issues/204274#issuecomment-2551771116.
- **Current source boundary:** src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts routes OSC activation through TerminalUrlLinkOpener with URI.parse(text). In terminalLinkOpeners.ts, TerminalUrlLinkOpener.open already handles the file scheme, but _openFileSchemeLink stats the unchanged file URI and falls back to external opening on failure. Unlike terminalLinkResolver.ts resolveLink, this path does not rewrite file URIs to vscode-remote using the terminal's remote authority. This supports the canonical remote-resolution diagnosis rather than a blanket absence of file-scheme support.
- **Evidence to preserve:** The supplied July 2026 comment reports the failure with a Windows 11 client and Ubuntu 22.04.4 Remote-SSH server, both VS Code 1.128.0, and an accompanying red error dialog while clicking Claude Code hyperlinks. These are additional environment and error details for the canonical file-link failure.
- **Distinct hover issue:** https://github.com/microsoft/vscode/issues/241646 remains OPEN. A maintainer confirmed that direct modifier-click could work while the blue hover-popup hyperlink did not: https://github.com/microsoft/vscode/issues/241646#issuecomment-3617786561. That narrower activation problem is related but is not the sole scope of this report.
