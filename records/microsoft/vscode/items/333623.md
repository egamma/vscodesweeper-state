# Issue #333623 — Chat session emptied by checkpoint restore becomes permanently unreachable and flickers in the sessions list

[https://github.com/microsoft/vscode/issues/333623](https://github.com/microsoft/vscode/issues/333623)

## Summary

Well-traced bug: when a checkpoint restore removes all requests from a session, `getHistorySessionItems` filters it out via `!entry.isEmpty` while the live path `shouldBeInHistory` has no such check, so the session vanishes from the list once evicted — and a linked PR is already open to fix it, so this should stay open pending that PR landing.

## Change summary

Restoring a chat session's checkpoint to the first request empties the session, after which it is filtered out of the Chat Sessions list forever (and flickers while still loaded), even though the full transcript remains on disk.

## Best solution

Land https://github.com/microsoft/vscode/pull/333629 (or an equivalent fix) so `getHistorySessionItems` and `shouldBeInHistory` agree, and an emptied-but-titled session is not treated the same as a never-used new chat.
