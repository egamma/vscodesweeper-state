# Issue #284987 — Restore to last checkpoint and canceling adds broken checkpoint redo to bottom

[https://github.com/microsoft/vscode/issues/284987](https://github.com/microsoft/vscode/issues/284987)

## Summary

The bug remains source-reproducible on current main: Restore to Last Checkpoint mutates the checkpoint and composer before confirmation, while cancellation only clears the checkpoint. The existing cancellation regression coverage exercises the per-message restore action, not this command.

## Change summary

Canceling Restore to Last Checkpoint leaves premature UI state, including a broken checkpoint redo affordance at the bottom of chat.

## Best solution

Make the Restore to Last Checkpoint command side-effect free until confirmation succeeds, preserving both the checkpoint presentation and composer when the user cancels. Cover this command explicitly in the chat editing actions tests.
