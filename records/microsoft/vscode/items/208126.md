# Issue #208126 — [linked rename] HTML doesn't rename or auto-fill non-ASCII tags

[https://github.com/microsoft/vscode/issues/208126](https://github.com/microsoft/vscode/issues/208126)

## Summary

The gap remains on current main and originates in the bundled HTML language service: its scanner still recognizes element names with an ASCII-oriented `\w` expression, so `é` terminates the parsed tag name. Keep this open while the parser is corrected upstream and the updated dependency is adopted by VS Code.

## Change summary

HTML linked editing and automatic closing truncate tag names at non-ASCII characters.

## Best solution

Update `microsoft/vscode-html-languageservice` so its scanner accepts the full set of characters permitted in HTML tag names, add Unicode coverage for parsing, tag completion, and linked editing, then consume that language-service release in VS Code.

## Evidence
