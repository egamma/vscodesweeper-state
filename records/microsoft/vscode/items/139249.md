# Issue #139249 — Custom Buttons and Labels for QuickPicks

[https://github.com/microsoft/vscode/issues/139249](https://github.com/microsoft/vscode/issues/139249)

## Summary

Keep open: extensions still cannot expose the labeled confirmation controls used by SimpleFileDialog. This team-authored Backlog request has maintainer support, and neither current API capabilities nor the canonical search establishes grounds for closure.

## Change summary

Allow extensions to provide labeled QuickPick buttons so navigating folder items and confirming the final choice can be separate actions.

## Best solution

Design a supported QuickPick API for explicit, labeled confirmation in navigation-oriented wizards, consistent with existing quick-input controls. Settle the public button and event contract before implementation rather than treating an icon-only workaround as complete coverage.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostQuickOpen.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Exercise an extension-created single-select QuickPick containing folder items: clicking an item navigates without finalizing, while a visible labeled confirmation control completes the current choice. Verify custom text, keyboard accessibility, exactly-once event delivery and unchanged existing icon-button behavior; add coverage in the quick-input browser suite and extension API bridge tests for the approved contract.
- **Behavior:**

  > An extension wizard needs item activation to navigate into folders and a separate, visible text-labeled action to confirm the current choice. Existing icon-only buttons are a workaround, not the requested labeled confirmation experience. Acceptance should demonstrate both actions independently in an extension-created single-select QuickPick, with accessible keyboard operation and no change to ordinary QuickPick behavior.
- **Trace:**

  > The public QuickPick and QuickInputButton declarations in src/vscode-dts/vscode.d.ts expose icon buttons at multiple locations but no labeled confirmation control. Internal IQuickPick in src/vs/platform/quickinput/common/quickInput.ts already supports ok/okLabel and customButton/customLabel/onDidCustom; SimpleFileDialog uses these in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts. ExtHostQuickInput.buttons in src/vs/workbench/api/common/extHostQuickOpen.ts serializes icon metadata, location and toggle, while MainThreadQuickOpen forwards the existing acceptance and button events. The remaining uncertainty is the public contract for exposing labeled actions, not whether the renderer already has such controls. Preserve existing icon-button behavior, default item acceptance and SimpleFileDialog semantics. The navigation-versus-confirmation use case and maintainer acceptance are recorded at https://github.com/microsoft/vscode/issues/139249#issuecomment-998388831 and https://github.com/microsoft/vscode/issues/139249#issuecomment-999656836.
- **Open decisions:**
  - Should the public API expose a dedicated labeled confirmation control, or allow general text-labeled QuickInputButton actions?
  - Should explicit confirmation fire the existing onDidAccept event or a separate button event, and what selection should extensions observe when confirming the current folder rather than a listed child?
