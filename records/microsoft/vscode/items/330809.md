# Issue #330809 — Agents Window - Customization: Plugins updated not working correctly

[https://github.com/microsoft/vscode/issues/330809](https://github.com/microsoft/vscode/issues/330809)

## Summary

Traced the git-source update path in `updateAllPlugins`: for plugins installed directly from a GitHub/GitUrl repo (not the relative-path marketplace case), the actual `git pull` is only attempted when `hasSourceChanged()` says the marketplace descriptor's ref/sha differs from what's installed — but a plugin tracking a branch with no pinned sha never trips that check, so `repo.update()` (which does the real pull) is skipped entirely and the local clone goes stale forever.

## Change summary

'Update Plugins' does not fetch/pull new commits for a plugin installed from a remote git repository, and the local plugin list doesn't refresh without an Agents Window restart for relative-path plugins either.

## Best solution

In `PluginInstallService.updateAllPlugins` (src/vs/workbench/contrib/chat/browser/pluginInstallService.ts, ~lines 452-465), stop gating the git independentGitTasks branch on `hasSourceChanged()` for GitHub/GitUrl sources — always call `_pluginRepositoryService.updatePluginSource()` for those and let `repo.update()`'s own fetch/pull + HEAD comparison (already correct in pluginSources.ts `AbstractGitPluginSource.update()`) decide whether anything changed; keep the `hasSourceChanged` gate only where it's meaningful (npm/pip version pinning).
