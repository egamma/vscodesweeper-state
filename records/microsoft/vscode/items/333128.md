# Issue #333128 — Integrated Browser: Chrome DevTools remote-debugging frontend fails with `(blocked:origin)` / "Unsafe attempt to load URL ... from frame with URL chrome-error://chromewebdata/" when not using Remote-SSH/WSL port forwarding

[https://github.com/microsoft/vscode/issues/333128](https://github.com/microsoft/vscode/issues/333128)

## Summary

Well-documented, brand-new report of a Chromium Private Network Access (PNA) failure specific to the Integrated Browser when a remote-debugging port is reached via a plain SSH tunnel rather than VS Code's own Remote-SSH/WSL port forwarding; needs owner triage, not a close.

## Change summary

The Integrated Browser fails to load the Chrome DevTools frontend against a manually SSH-tunneled remote-debugging port, blocked by Chromium's Private Network Access preflight, whereas the same flow works via VS Code's built-in Remote-SSH/WSL port forwarding.

## Best solution

Route to the Integrated Browser owners (src/vs/platform/browserView, src/vs/workbench/contrib/browserView) to confirm whether VS Code's Remote-SSH/WSL port-forwarding proxy is answering the PNA CORS preflight (e.g. adding `Access-Control-Allow-Private-Network: true`) and, if so, whether the same header injection could be applied for the local-tunnel case in the browserView session's webRequest pipeline.
