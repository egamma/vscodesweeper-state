# Issue #329647 — Codex runs server tools that need confirmation without asking the user

[https://github.com/microsoft/vscode/issues/329647](https://github.com/microsoft/vscode/issues/329647)

## Summary

Team-authored, precisely diagnosed bug: traced in the checkout that Codex's dynamic-tool RPC handler and event mapper never consult `IServerToolGroup.requiresConfirmation()`, so server tools that should prompt (session/chat creation, deletion, sending messages, viewing unreviewed comments) execute silently, unlike Claude and Copilot CLI which gate the same tools. Kept open per team-authored protection (no cited fixing commit yet).

## Change summary

Codex's agent host runs server tools flagged as requiring user confirmation (create_session, create_chat, send_message, delete_session, viewUnreviewedComments) without ever showing an approval card, unlike the Claude and Copilot CLI harnesses.

## Best solution

In `_handleDynamicToolCallRpc` (src/vs/platform/agentHost/node/codex/codexAgent.ts), check `host.requiresConfirmation(params.tool)` for server tools and route through a `pendingCommandApprovals.registerAndFire` wait (mirroring the existing `_handleMcpToolApprovalViaCard` pattern at codexAgent.ts:1873-1899) instead of executing immediately; also stop hardcoding `confirmed: ToolCallConfirmationReason.NotNeeded` in codexMapAppServerEvents.ts:731 for tools that require confirmation.
