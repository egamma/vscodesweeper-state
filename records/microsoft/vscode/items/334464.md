# Issue #334464 — [Remote-SSH][Agent Host] Changed-file diff treats remote Linux file: URI as a local Windows path

[https://github.com/microsoft/vscode/issues/334464](https://github.com/microsoft/vscode/issues/334464)

## Summary

Verified duplicate: this is the same Agent Host / Remote-SSH file-URI bug already reported and actively discussed in an open, broader/equal-scope issue, so consolidating there is the right call.

## Change summary

Over Remote-SSH, the Agent Host changed-files diff wraps a remote `file:` URI as if it were local (since `wrapAgentHostUri` returns the original URI unchanged whenever `connectionAuthority === 'local'`), so Windows renders the remote POSIX path with backslashes and fails to resolve it instead of opening it via the `vscode-remote://` filesystem provider.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/333447, which tracks the same root cause (Agent Host `file:` URIs assumed to be locally-resolvable) — the eventual fix should map Agent Host `file:` resources back into the active Remote-SSH client resource space (e.g. via the local agent-host connection wrapping in src/vs/platform/agentHost/common/agentHostUri.ts) rather than assuming `connectionAuthority === 'local'` implies same-filesystem access.
