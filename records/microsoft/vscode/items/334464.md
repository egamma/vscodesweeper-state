# Issue #334464 — [Remote-SSH][Agent Host] Changed-file diff treats remote Linux file: URI as a local Windows path

[https://github.com/microsoft/vscode/issues/334464](https://github.com/microsoft/vscode/issues/334464)

## Summary

Verified duplicate: this is the same Remote-SSH Agent Host changed-file diff bug already open in issue #333447 (filed a few days earlier by a different reporter, same symptom, no fix landed) — proposing to consolidate there while carrying over this report's deeper root-cause tracing.

## Change summary

Over Remote-SSH, clicking a changed file in an Agent Session's diff summary opens the working-tree side as a mangled local Windows path (backslashes, no vscode-remote:// authority) instead of the actual remote resource, and fails with 'file not found'.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/333447, which tracks the identical Remote-SSH changed-file-diff defect. Whoever picks it up should use this report's tracing: src/vs/platform/agentHost/common/agentHostUri.ts's wrapAgentHostUri() assumes connectionAuthority === 'local' means the renderer can access the same filesystem, which breaks when a plain file: URI from the agent host reaches a Remote-SSH client — it needs to map back into the current Remote-SSH resource space (vscode-remote://) instead.

- **source trace:** src/vs/platform/agentHost/common/agentHostUri.ts:108 wrapAgentHostUri() only special-cases connectionAuthority === LOCAL_AGENT_HOST_AUTHORITY ('local'); it assumes the client and agent host share a filesystem in that case. For Remote-SSH, whether this check fires depends on how agentHostAuthority(info.address) resolves the remote agent host's address — if it lands on a non-local authority the URI should already be wrapped as vscode-agent-host://, so the actual defect likely sits further along the changed-files path (agentHostResponseFileChanges.ts) or in how the wrapped URI's filesystem provider resolves back through the Remote-SSH connection rather than in this single check alone.
- **reporter workaround:** Reporter's diagnostic patch mapping the file: URI to scheme vscode-remote with the active ssh-remote+<host> authority resolved the diff correctly, confirming the fix belongs in the Agent Host <-> Remote-SSH resource mapping.
