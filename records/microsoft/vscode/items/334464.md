# Issue #334464 — [Remote-SSH][Agent Host] Changed-file diff treats remote Linux file: URI as a local Windows path

[https://github.com/microsoft/vscode/issues/334464](https://github.com/microsoft/vscode/issues/334464)

## Summary

Verified duplicate of the earlier, fully-equivalent https://github.com/microsoft/vscode/issues/333447, which reports and traces the same root cause (Remote-SSH agent-session changed-file diffs mishandling the working-tree URI) and is still open — consolidating here.

## Change summary

On Remote-SSH, clicking a changed file in an Agent Host chat session's diff summary opens the remote POSIX path as if it were a local Windows path, failing to resolve the file.

## Best solution

Fix `wrapAgentHostUri` in src/vs/platform/agentHost/common/agentHostUri.ts (and its use in agentHostResponseFileChanges.ts) so the `connectionAuthority === 'local'` short-circuit doesn't assume the renderer and agent host share a filesystem when the workspace itself is a Remote-SSH connection — map the resource back into the client's actual `vscode-remote://` authority instead. Track and land the fix under the earlier report, https://github.com/microsoft/vscode/issues/333447.
