# Issue #134888 — Feature Request: Bracket Pair Guides - Hover

[https://github.com/microsoft/vscode/issues/134888](https://github.com/microsoft/vscode/issues/134888)

## Summary

Keep open: current editor features provide scope context and bracket navigation, but not the requested interactive guide preview. This team-authored Backlog request has supporting discussion and an explicitly consolidated duplicate; no qualifying fix or older canonical covering its full scope was found.

## Change summary

Provide an interactive bracket or indentation guide preview showing block endpoints, with navigation to the previewed lines.

## Best solution

Design an on-demand block-endpoint preview in the editor's guide and bracket-matching area, complementing rather than duplicating Sticky Scroll. Settle the mouse and keyboard activation contract before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/indentGuides/indentGuides.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/contrib/stickyScroll/browser/stickyScrollController.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** After agreeing the activation contract, exercise a long nested block with both endpoints outside the viewport: activate its guide preview, verify the correct opening and closing lines, and select each endpoint to navigate. Check nested-pair disambiguation, any approved keyboard activation, and unchanged ordinary selection, Go to Bracket and Sticky Scroll interactions.
- **Behavior:**

  > Users should be able to inspect the endpoints of a block from its guide without scrolling away from their current context, including when neither endpoint is visible. The preview should identify the opening and closing lines and allow navigation to each. Discussion also requests keyboard-triggered context when the caret is beside a closing brace whose opening line is off-screen. Acceptance must distinguish this on-demand interaction from the scope context already available through Sticky Scroll.
- **Trace:**

  > IndentGuidesOverlay in src/vs/editor/browser/viewParts/indentGuides/indentGuides.ts renders bracket and indentation guides but has no preview interaction in the inspected path. BracketMatchingController in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts resolves matching or enclosing brackets for decorations and editor.action.jumpToBracket, without displaying endpoint context. StickyScrollController in src/vs/editor/contrib/stickyScroll/browser/stickyScrollController.ts already supports scope-header navigation and Shift-click navigation to the ending line, so that existing behavior must remain intact. The source establishes a missing interaction, not a broken existing contract; uncertainty begins with activation semantics and what plain indentation guides should preview. https://github.com/microsoft/vscode/issues/146415 was explicitly consolidated here, while https://github.com/microsoft/vscode/issues/55075 tracks the related but narrower closing-tag context. Rich language-specific headers discussed in https://github.com/microsoft/vscode-cpptools/issues/6430 are not established requirements for this generic endpoint preview.
- **Open decisions:**
  - Should the initial feature require modifier-hover on a guide, also support direct closing-bracket hover, or additionally appear automatically when the caret is beside a closing brace with an off-screen opening line?
  - Should plain indentation guides expose indentation-scope boundaries, or should the initial preview be limited to syntactically matched bracket pairs?

## Evidence

These operate on the sticky header, not a hovered guide or a caret-triggered matching-bracket preview.
