# Issue #176984 — Workspace edits with metadata do not show labels that docs say are rendered prominently

[https://github.com/microsoft/vscode/issues/176984](https://github.com/microsoft/vscode/issues/176984)

## Summary

The default preview still groups by file rather than exposing metadata labels as prominent group headers. Keep this accepted Backlog request open: the existing grouping command is a workaround, and the newer API-control request does not supersede this broader default-behavior request.

## Change summary

Make workspace-edit metadata labels prominent without requiring users to manually enable grouping, or clarify the API's conditional rendering contract.

## Best solution

Resolve the default label-presentation contract in the bulk-edit preview with the API owners, coordinating with https://github.com/microsoft/vscode/issues/207580. Make the documented behavior match the chosen presentation while preserving users' explicit grouping preferences.
