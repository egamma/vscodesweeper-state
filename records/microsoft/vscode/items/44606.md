# Issue #44606 — Allow extensions to add coloured markers in the gutter similar to source control

[https://github.com/microsoft/vscode/issues/44606](https://github.com/microsoft/vscode/issues/44606)

## Summary

Keep open: extensions can render gutter images, but the decoration API still does not expose arbitrary coloured markers in the SCM line-decoration strip. A maintainer supported extending the decoration API, and the related quick-diff proposal does not cover arbitrary execution or coverage states.

## Change summary

Expose SCM-style coloured gutter markers to non-source-control extensions, with explanatory tooltips.

## Best solution

Provide a theme-aware decoration API for arbitrary line-state markers without requiring a source-control provider or an original document to diff. Settle coexistence with SCM markers and whether click handling belongs in this proposal before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/test/browser/services/decorationRenderOptions.test.ts`
- **Validation:** Use an extension-host sample to mark arbitrary lines with two distinct state colours, update those states, and inspect tooltip behavior in light, dark, and high-contrast themes while SCM changes and breakpoints coexist. Extend decorationRenderOptions.test.ts to cover the agreed rendering contract, and run the targeted suite with scripts/test.sh --run src/vs/editor/test/browser/services/decorationRenderOptions.test.ts.
- **Behavior:**

  > A non-SCM extension can mark arbitrary lines with SCM-style coloured indicators representing extension-defined states, such as hot-reloaded versus executed code. Updating the state changes the marker colour without requiring an original document or a computed diff. Markers can explain their state through tooltips and remain distinguishable across supported themes. Acceptance must cover simultaneous SCM markers and breakpoints; click interaction is not required by the original use case and needs an explicit scope decision.
- **Trace:**

  > The public ThemableDecorationRenderOptions in src/vscode-dts/vscode.d.ts currently exposes gutterIconPath and gutterIconSize, and extHostTypeConverters.ts forwards these image options. AbstractCodeEditorService in src/vs/editor/browser/services/abstractCodeEditorService.ts renders them through glyphMarginClassName. SCM instead uses linesDecorationsClassName and linesDecorationsTooltip in src/vs/workbench/contrib/scm/browser/quickDiffDecorator.ts, establishing that the requested visual surface differs from existing gutter icons. The related proposed quick-diff API in src/vscode-dts/vscode.proposed.quickDiffProvider.d.ts serves document differences, not arbitrary execution-state markers; its tracking issue is https://github.com/microsoft/vscode/issues/169012. Preserve existing image decorations, breakpoint interactions, and SCM behavior. The unresolved boundary is the public contract for placement, competing markers, tooltip content, and optional clicks, rather than a confirmed defect in existing behavior.
- **Open decisions:**
  - Should extension markers share the SCM line-decoration strip, and what should users see when SCM and extension markers cover the same line?
  - Should the initial API support only colours and explanatory tooltips, or also clickable markers as requested by another commenter?
