# Issue #299231 — Unable to open a specific conversation after clicking

[https://github.com/microsoft/vscode/issues/299231](https://github.com/microsoft/vscode/issues/299231)

## Summary

Keep this canonical bug open: multiple reporters supplied matching logs showing indexed chat sessions whose backing files disappear, and current main still silently replaces an unrestorable local session with a new one. The related newer report was explicitly closed as a duplicate of this issue.

## Change summary

Local Copilot Chat history can become inaccessible after a workspace transition or restart because its session index remains while the corresponding JSON/JSONL file is missing.

## Best solution

Identify why session files and index entries diverge across workspace transitions or shutdown, preserve the session data across that lifecycle, and ensure selecting an unrestorable history entry reports a meaningful localized error rather than silently creating a blank session.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts`, `src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/editor/chatEditorInput.test.ts`
- **Validation:** Extend the ChatSessionStore tests with a realistic Save Workspace As/reopen lifecycle that preserves and reloads an indexed session, and extend ChatEditorInput tests to assert that an indexed local session with missing backing files does not silently resolve to a new blank session.
- **Behavior:**

  > A local chat listed in session history remains openable after Save Workspace As, window shutdown, and reopening. Its history must not be lost because the workspace storage identity changed. If the backing data genuinely cannot be recovered, selecting the history entry must surface a meaningful error and must not silently substitute a new blank conversation. Existing creation of genuinely new local chats remains unchanged.
- **Trace:**

  > `ChatSessionStore` derives local persistence from the current workspace ID and handles `IWorkspaceEditingService.onDidEnterWorkspace` by copying session files, but reports after commit 7393b0ec6071aca9ba95635a36588affb09db549 show that index entries can still outlive both expected backing files. `ChatSessionStore.readSessionFromLocation` logs both missing files and returns `undefined`; `ChatService.acquireOrRestoreLocalSession` returns that result; `ChatEditorInput.resolve` then calls `startNewLocalSession`, producing the silent failure. First reproduce the divergence with the real Save Workspace As/reopen lifecycle and determine whether the missed path is migration ordering, shutdown persistence, or storage-scope/index handling. Keep malformed-but-present JSONL recovery tracked separately in https://github.com/microsoft/vscode/issues/308730, and do not change normal untitled-session fallback behavior.

## Evidence

- **confirmed reports:** Three reporters reproduced inaccessible sessions after reopening or changing a workspace; the logs in https://github.com/microsoft/vscode/issues/299231#issuecomment-4050188979 and https://github.com/microsoft/vscode/issues/299231#issuecomment-4060561288 show both `.jsonl` and `.json` files missing while the session remains selectable.
- **current source path:** `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts` (`readSessionFromLocation`) catches missing log and flat files and returns `undefined`; `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` (`acquireOrRestoreLocalSession`) propagates that result, and `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts` (`resolve`) then calls `startNewLocalSession` without surfacing the failed restoration.
- **existing migration insufficient:** Commit 7393b0ec6071aca9ba95635a36588affb09db549 added workspace-ID transition migration before this issue was filed, and current `ChatSessionStore.handleWorkspaceTransition` copies session files and flushes the new index. Reports against later builds show a remaining lifecycle or persistence path not covered by that migration.
- **canonical status:** The newer same-symptom report https://github.com/microsoft/vscode/issues/301098 was closed by a maintainer as a duplicate of this issue, carrying its Remote-SSH and delayed-recovery evidence here.
- **distinct corruption issue:** https://github.com/microsoft/vscode/issues/308730 concerns malformed JSONL files with missing initial records or BOMs, whereas this issue's logs show the backing files do not exist; it does not absorb this missing-file case.
