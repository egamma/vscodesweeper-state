# Issue #178994 — `terminal.goToRecentDirectory` is not shell-aware

[https://github.com/microsoft/vscode/issues/178994](https://github.com/microsoft/vscode/issues/178994)

## Summary

The requested REPL-aware directory navigation remains missing on current main. Keep this accepted Backlog request open; the discussion supports a shell-integration property, but its substitution and escaping contract needs design.

## Change summary

Allow REPL-like programs to declare their directory-change syntax instead of receiving a hard-coded shell cd command.

## Best solution

Define a shell-integration contract that lets participating REPLs supply directory-change syntax, including path quoting and mapping semantics. Honor it in Go to Recent Directory while preserving existing behavior for terminals that do not participate.

- **Behavior:**

  > Go to Recent Directory should work in a participating REPL using that program's directory-change syntax rather than assuming shell cd syntax. Selecting a directory in Julia should not require switching into shell mode. Paths containing spaces, quotes, and platform-specific separators must follow the agreed protocol semantics. Terminals that do not advertise this capability retain existing behavior, including Alt/Option insertion without execution.
- **Trace:**

  > The action in src/vs/workbench/contrib/terminalContrib/history/browser/terminal.history.contribution.ts calls TerminalHistoryContribution.runRecent('cwd'), which reaches showRunRecentQuickPick in terminalRunRecentQuickPick.ts. Its accept handler hard-codes cd and delegates only path preparation to instance.preparePathForShell; terminalEnvironment.ts supplies existing shell quoting and mapping, not REPL command syntax. ShellIntegrationAddon._doHandleVSCodeSequence in src/vs/platform/terminal/common/xterm/shellIntegrationAddon.ts recognizes Cwd and other OSC 633 P properties but no directory-change template. The discussion at https://github.com/microsoft/vscode/issues/178994 supports a property-based design and identifies unresolved quoting and mapping requirements; https://github.com/microsoft/terminal/pull/14864 provides related interoperability context, not a landed VS Code implementation. Preserve ordinary shell navigation, command-history execution, and Alt/Option semantics. The uncertainty starts at the advertised property's public substitution, path representation, and lifecycle contract.
- **Open decisions:**
  - What placeholder and escaping contract allows a REPL to express its directory-change syntax: does substitution provide a raw path or an already quoted argument, and how are literal placeholder characters represented?
  - Does the advertised contract also control path separators and platform mappings, or does it receive the path after VS Code's existing shell-specific conversion?
  - When a REPL exits or another program takes over the terminal, how is its advertised directory-change behavior reset so subsequent selections use the correct syntax?
