# Issue #334076 — Chat Sessions panel loses all history except current run after tunnel restart — no state.vscdb/chat.ChatSessionStore.index fallback for agent-host storage backend

[https://github.com/microsoft/vscode/issues/334076](https://github.com/microsoft/vscode/issues/334076)

## Summary

Keep open: the supplied tunnel-restart steps suffice to retest, but source inspection does not confirm the proposed agent-host index failure. Current main separates browser-backed chat history from extension transcripts and now includes a sessions_v2 agent-host catalog, so the host-side diagnostics alone cannot establish where history disappeared.

## Change summary

Previously accumulated Copilot Chat sessions disappear from the Sessions panel after restarting a Windows tunnel host, although extension transcript files remain on disk.

## Best solution

Preserve access to existing conversations across tunnel restarts by first identifying the Sessions provider and its authoritative persisted catalog. Diagnose browser workspace identity/storage and remote provider discovery separately; do not assume extension transcripts or an empty agent-host sessions table are the UI's source of truth.

- **Behavior:**

  > Previously saved conversations should remain listed and reopenable after restarting a Remote Tunnel host and reconnecting to the same logical workspace. The reported failure leaves only current-run conversations visible while older extension transcript files remain intact. Acceptance should exercise both host restart and CLI update/reconnect, preserve existing conversation contents, and avoid exposing unrelated workspaces' sessions.
- **Trace:**

  > LocalAgentSessionsController combines live sessions with ChatService.getHistorySessionItems, which reads ChatSessionStore's persisted index. ChatSessionStore.internalGetIndex reads chat.ChatSessionStore.index through IStorageService; browser workspace storage uses IndexedDB keyed by workspace.id, so absence of host state.vscdb is not evidence of a missing browser index. Extension SessionTranscriptService writes a separate transcript format under extension storageUri, and agentHostDatabase now has both sessions and sessions_v2 catalogs. Source inspection establishes these boundaries but does not identify which provider supplied the reporter's visible entries or what changed during restart. First reproduce the supplied flow and identify that provider and its authoritative storage before determining the defect. Preserve workspace isolation and existing transcript formats; a transcript-recovery feature is not automatically the fix for persistence failure. Related workspace-transition work is https://github.com/microsoft/vscode/issues/301793 and https://github.com/microsoft/vscode/pull/305109, while orphan recovery is tracked at https://github.com/microsoft/vscode/issues/305818.
