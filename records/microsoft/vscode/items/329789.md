# Issue #329789 — '<' and '>' are not colored correctly in left shift assignment and right shift assignment

[https://github.com/microsoft/vscode/issues/329789](https://github.com/microsoft/vscode/issues/329789)

## Summary

Reproducible bug: bracket-pair colorization mismatches '<'/'>' inside <<=, >>=, >>>= in TS/TSX (and likely other bracket-enabled languages); an open PR (#329810) already targets the root cause with tests, so this should stay open pending review/merge rather than being auto-fixed or closed.

## Change summary

In TypeScript/TSX (and similar languages), '<' and '>' inside the compound bitwise-shift-assignment operators (<<=, >>=, >>>=) are miscolored and mismatched as if they were bracket pairs.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/329810, which adds a lookahead guard to `prepareBracketForRegExp` in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts so <<=, >>=, >>>= are excluded from bracket-pair matching, plus corrects the mismatched `.ts`-suffixed scope name RedCMD flagged in extensions/typescript-basics/package.json (unbalancedBracketScopes for the tsx grammar lists `keyword.operator.assignment.compound.bitwise.ts` instead of `.tsx` or the base scope).
