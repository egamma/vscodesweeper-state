# Issue #350418 — Style tokens: provide find match highlight colors for High Contrast themes

[https://github.com/microsoft/vscode/issues/350418](https://github.com/microsoft/vscode/issues/350418)

## Summary

Keep open: high-contrast find colors currently rely on borders rather than backgrounds, leaving a genuine gap for CSS Custom Highlight consumers. Existing border tokens do not satisfy the requested background-color capability.

## Change summary

Provide theme-compatible find-match background colors for CSS Custom Highlights in high-contrast themes.

## Best solution

Have the theming and accessibility owners decide how to expose usable high-contrast highlight colors without compromising the editor’s existing border-based presentation. Preserve distinguishable active and other matches, with readable foreground contrast.

## Evidence

- **Current token definitions:** src/vs/platform/theme/common/colors/editorColors.ts:148–174 registers editor.findMatchBackground and editor.findMatchHighlightBackground with null hcDark/hcLight defaults, while editor.findMatchBorder and editor.findMatchHighlightBorder use activeContrastBorder. The missing backgrounds reflect the existing high-contrast representation, not absent token registrations.
- **CSS variable export:** src/vs/workbench/contrib/webview/browser/themeing.ts:67–73 exports a registered color only when theme.getColor(entry.id) returns a value. Consequently, registered find background tokens with unresolved high-contrast values do not become webview CSS variables.
- **Existing-capability boundary:** The existing find border tokens support border-based decorations, but CSS ::highlight styling does not support borders. Neither those tokens nor consumer-authored fallback colors provide the requested theme-supplied background colors.
- **Reporter clarification and workaround:** https://github.com/microsoft/vscode/issues/350418#issuecomment-7171083388 supplies selection-derived color-mix fallbacks and screenshots for dark, light, and both high-contrast themes. The body explicitly withdraws the foreground-token request; the remaining request concerns background availability.
- **Canonical search:** Open-issue searches for findMatchHighlightBackground with contrast, Custom Highlight, and high-contrast webview find styling did not establish a canonical issue owning this capability. The inspected results concerned editor selection-color conflicts and search-result navigation rather than high-contrast CSS highlight tokens.
