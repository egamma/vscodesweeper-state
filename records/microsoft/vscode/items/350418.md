# Issue #350418 — Style tokens: provide find match highlight colors for High Contrast themes

[https://github.com/microsoft/vscode/issues/350418](https://github.com/microsoft/vscode/issues/350418)

## Summary

The requested capability remains missing: High Contrast defaults use borders rather than find-match backgrounds, leaving CSS Custom Highlight consumers without background tokens. Keep open for a theming decision; existing overrides and overlays are workarounds, not default coverage.

## Change summary

Provide theme-derived find-match background colors usable with the CSS Custom Highlight API in High Contrast themes.

## Best solution

Establish an accessible background/foreground color contract for borderless find highlights, while preserving existing High Contrast editor styling. The theming owners should decide whether existing token defaults or a separate fallback contract should provide it.

## Evidence

- **Current defaults:** src/vs/platform/theme/common/colors/editorColors.ts:148-174 explicitly assigns null hcDark/hcLight defaults to editor.findMatchBackground and editor.findMatchHighlightBackground, while providing activeContrastBorder defaults for editor.findMatchBorder and editor.findMatchHighlightBorder. This supports classification as a requested capability, not an accidental missing registration.
- **CSS variable export:** WebviewThemeDataProvider.getWebviewThemeData in src/vs/workbench/contrib/webview/browser/themeing.ts exports registered colors only when theme.getColor(entry.id) returns a value. Null High Contrast background defaults therefore do not produce the requested CSS variables.
- **Existing capability check:** workbench.colorCustomizations is registered in src/vs/workbench/services/themes/common/themeConfiguration.ts, and ColorThemeData.setCustomColors applies overrides. Users can supply these background colors manually, but that does not supply theme-derived defaults to extension consumers; the existing border tokens do not deliver the requested background-only highlighting.
