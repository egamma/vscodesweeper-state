# Issue #76545 — Hyper modifier is unknown

[https://github.com/microsoft/vscode/issues/76545](https://github.com/microsoft/vscode/issues/76545)

## Summary

The request remains necessary: VS Code's keybinding model still has no Hyper/Mod3 modifier, and no canonical issue or shipped capability in the supplied discussion absorbs the request. Its Backlog milestone and low reaction count do not provide a factual reason to close it.

## Change summary

Recognize Linux Hyper/Mod3 as a modifier so users can record and assign Hyper-based keyboard shortcuts.

## Best solution

Define the intended cross-platform semantics for Hyper, then extend the keyboard-event normalization, keybinding parser/resolver, dispatch serialization, and keybinding recorder while preserving existing Ctrl/Shift/Alt/Meta behavior.

## Plan brief

- **Likely files:** `src/vs/base/common/keyCodes.ts`, `src/vs/base/common/keybindings.ts`, `src/vs/platform/keybinding/common/keybinding.ts`, `src/vs/platform/keybinding/common/keybindingParser.ts`, `src/vs/platform/keybinding/common/keybindingResolver.ts`, `src/vs/platform/keybinding/common/keybindingsRegistry.ts`, `src/vs/platform/keybinding/test/common/keybindingResolver.test.ts`
- **Validation:** Add and run targeted keybinding parser/resolver and Linux keyboard-mapper tests proving a Hyper/Mod3 chord records, serializes, resolves, and dispatches distinctly while existing modifiers remain unchanged.
- **Behavior:**

  > On Linux, a key exposed by the browser as Hyper/Mod3 can be recorded in the Define Keybinding dialog and used in a keyboard shortcut chord. The resulting binding must be representable in keybindings.json, survive reload, and dispatch without being confused with Ctrl, Shift, Alt, Meta, or Caps Lock. Existing shortcuts and modifier mappings must remain unchanged.
- **Trace:**

  > The issue reports that Caps Lock remapped to Hyper/Mod3 is not recognized as a modifier by VS Code's keybinding recorder, even with extensions disabled. Current keybinding concepts are centered on Ctrl, Shift, Alt, and Meta across src/vs/base/common/keyCodes.ts, src/vs/base/common/keybindings.ts, and the parser/resolver under src/vs/platform/keybinding/common/. The uncertainty begins at platform semantics: a maintainer must decide whether Hyper is a first-class modifier in the portable keybinding grammar or a Linux-only dispatch capability, and how it is represented without breaking serialized keybindings or extension keybinding contributions. The existing Escape-remapping report https://github.com/microsoft/vscode/issues/32037 is related input handling but does not own this feature's scope.
- **Open decisions:**
  - Should Hyper be a first-class portable keybinding modifier or a Linux-only modifier recognized by the native/browser dispatch layer?
  - What stable token should represent Hyper in keybindings.json and extension keybinding contributions?
  - Should support rely on KeyboardEvent.getModifierState('Hyper'), a Linux native key-code path, or both?
