# Issue #76545 — Hyper modifier is unknown

[https://github.com/microsoft/vscode/issues/76545](https://github.com/microsoft/vscode/issues/76545)

## Summary

This remains a valid but low-demand Backlog feature request: current keybinding parsing and dispatch still model only Ctrl, Shift, Alt, and Meta, so Hyper/Mod3 is not supported. No verified canonical issue or existing setting covers the request; the community feature-request process should decide whether to expand the keybinding contract.

## Change summary

Recognize Linux Hyper/Mod3 as a modifier that can be recorded, configured, and dispatched in VS Code keybindings.

## Best solution

Decide whether Hyper should become a first-class keybinding modifier across parsing, serialization, recording, resolution, and Electron/browser dispatch; if accepted, define stable syntax and behavior before implementing the cross-layer change.

## Plan brief

- **Likely files:** `src/vs/base/common/keybindings.ts`, `src/vs/base/common/keybindingsParser.ts`, `src/vs/platform/keybinding/common/abstractKeybindingService.ts`, `src/vs/workbench/services/keybinding/browser/keyboardLayoutService.ts`, `src/vs/workbench/services/keybinding/browser/keyboardMapperFactory.ts`, `src/vs/workbench/services/preferences/browser/keybindingWidgets.ts`
- **Validation:** Add parser/serialization tests for the chosen Hyper keybinding syntax and mapper/dispatch tests showing a Hyper+Key event resolves to the configured command while existing Ctrl/Shift/Alt/Meta chords remain unchanged; manually verify recording Caps Lock mapped to Mod3 on Linux in the Define Keybinding widget.
- **Behavior:**

  > When the operating system maps a physical key such as Caps Lock to Hyper/Mod3, VS Code can record that modifier and use Hyper+Key combinations as keybindings. The chosen keybindings.json syntax round-trips through editing and display, and dispatch invokes the configured command. Existing Ctrl, Shift, Alt, Meta, chord, and scan-code keybindings retain their current behavior.
- **Trace:**

  > The current common representation in src/vs/base/common/keybindings.ts has only ctrlKey, shiftKey, altKey, and metaKey. src/vs/base/common/keybindingsParser.ts recognizes and serializes only those modifier families, while keyboardLayoutService.ts and the platform keyboard mappers construct resolved keybindings from the same four booleans; the recording UI therefore has no end-to-end Hyper value to preserve. The request is broader than a widget recognition tweak and crosses the keybinding public syntax and dispatch contract. Keep remapped ordinary keys and existing modifier semantics unchanged, and do not treat the bot-suggested https://github.com/microsoft/vscode/issues/32037 as canonical because that report concerns remapped Escape rather than a fifth modifier.
- **Open decisions:**
  - What stable token should keybindings.json expose for the modifier: `hyper`, Linux/X11 `mod3`, or aliases that normalize to one canonical form?
  - Should Hyper support be Linux-only, or should the public keybinding contract define cross-platform behavior for browser/Electron events that expose Hyper?
  - When the host event APIs do not expose a distinct Hyper modifier bit, should VS Code decline the binding on that environment or derive it from platform-specific native key information?
