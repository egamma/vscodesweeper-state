# Issue #333177 — Stop on an agent host turn can immediately restart the same turn

[https://github.com/microsoft/vscode/issues/333177](https://github.com/microsoft/vscode/issues/333177)

## Summary

Keep open: the current client still removes its dispatched-turn guard on cancellation before delayed host state necessarily arrives, allowing the cancelled turn to be adopted as a new request. The related closed report explicitly identifies this issue as the canonical version to work from.

## Change summary

Prevent Stop from creating another request for the same client-dispatched turn when host state arrives after cancellation.

## Best solution

Make cancellation and server-initiated-turn detection consistently recognize ownership of the cancelled turn despite delayed host updates, while preserving detection of genuinely new server-initiated turns.
