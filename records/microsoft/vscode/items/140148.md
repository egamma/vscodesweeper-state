# Issue #140148 — Page down and page up do not work in Jupyter notebooks

[https://github.com/microsoft/vscode/issues/140148](https://github.com/microsoft/vscode/issues/140148)

## Summary

Keep open: the discussion confirms notebook paging problems, with a renewed report in September 2026, and current source still separates editor-caret paging from cell-focus paging. The remaining work needs a decision about viewport scrolling versus caret/focus navigation; no verified fix or older same-symptom canonical was found.

## Change summary

Make keyboard paging reliably navigate notebooks and oversized outputs without getting stuck or jumping backward, including when a cell editor has focus.

## Best solution

Define notebook paging behavior across cell-editor, cell-container, and output focus, then address the navigation and dynamic-height scrolling problems in the notebook editor. Preserve text selection and unrelated list navigation while making oversized outputs traversable by keyboard.

- **Behavior:**

  > Notebook users report that Page Up/Down stops progressing in an editable cell or moves cell focus instead of traversing a large output, and that rendering can undo a paging movement. Keyboard navigation must provide a reliable way to traverse outputs larger than the viewport. Acceptance must cover editor, cell-container, and output focus, both paging directions, and delayed output-height measurement. The maintainer must settle whether plain paging scrolls the notebook viewport or retains caret/focus navigation in each focus context.
- **Trace:**

  > In src/vs/workbench/contrib/notebook/browser/contrib/navigation/arrow.ts, notebook.cell.cursorPageUp/cursorPageDown delegate to editor cursor commands using getPageSize; notebook.focusTop/focusBottom exclude inputFocus. The list commands in src/vs/workbench/browser/actions/listCommands.ts call List.focusNextPage/focusPreviousPage in src/vs/base/browser/ui/list/listWidget.ts, which combine scrolling with focus changes. NotebookCellList.updateElementHeight2 in src/vs/workbench/contrib/notebook/browser/view/notebookCellList.ts handles dynamic height changes and focus anchoring, but this review did not establish the precise backward-jump trigger on current main. The owner acknowledgment at https://github.com/microsoft/vscode/issues/140148#issuecomment-1067454920 identifies both keybinding and measurement problems; the later question at https://github.com/microsoft/vscode/issues/140148#issuecomment-5946369923 leaves their intended navigation contract unresolved. Keep unrelated workbench-list behavior, text selection, and output-input keyboard handling outside the change unless the agreed contract specifically requires otherwise.
- **Open decisions:**
  - Should plain Page Up/Down scroll only the notebook viewport when a cell container or non-input output is focused, or continue moving cell focus?
  - When a cell editor has text focus, should Page Up/Down and Cmd+Up/Down retain editor caret navigation, navigate the notebook, or provide an explicitly separate notebook-scrolling gesture?
