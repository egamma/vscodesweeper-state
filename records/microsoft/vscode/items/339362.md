# Issue #339362 — UTD checks synchronized between clients based on extension publish time, causes DDoS effect on Marketplace

[https://github.com/microsoft/vscode/issues/339362](https://github.com/microsoft/vscode/issues/339362)

## Summary

Confirmed in source: autoUpdateExtensions() reschedules the next update check to fire exactly at the quarantine-delay expiry (soonestDelayRemaining), synchronizing all clients' subsequent polling onto that moment for any widely-installed extension — a real, broad-impact issue. An open PR already targets this exact fix, so it should stay open for that PR to land rather than be treated as a fresh agent task.

## Change summary

The 12-hour publish-quarantine period causes all VS Code clients with a given extension installed to reschedule their next update check to the same quarantine-expiry timestamp, creating synchronized traffic spikes against the Marketplace.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339365 ("extensions: keep update checks on polling cadence"), which appears to address exactly this by decoupling the delayed re-check timer from the regular polling cadence/jitter.

## Evidence

- **root cause in source:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts:2290-2306 — autoUpdateExtensions() computes getAutoUpdateDelayRemaining() per extension, and when a delay remains it sets delayedAutoUpdateCheckTimer to fire eventuallyCheckForUpdates(true) after exactly `soonestDelayRemaining` ms (the quarantine expiry), overriding the normal polling cadence (ExtensionsWorkbenchService.UpdatesCheckInterval) for all clients that saw the extension in quarantine.
- **delay source:** getAutoUpdateDelayRemaining (line ~1249) computes delay from extension.gallery.lastUpdated and AutoUpdateDelayConfigurationKey (default 12h), matching the issue's description of the 12-hour quarantine window introduced for publisher-trust/security reasons.
- **linked fix in progress:** Open PR https://github.com/microsoft/vscode/pull/339365 "extensions: keep update checks on polling cadence" appears to be the maintainer-authored fix for this exact synchronization bug.
