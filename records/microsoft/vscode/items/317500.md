# Issue #317500 — Language model per-model settings are saved to the wrong provider group when multiple groups share the same vendor

[https://github.com/microsoft/vscode/issues/317500](https://github.com/microsoft/vscode/issues/317500)

## Summary

The reported first-write routing defect is fixed on current main: settings for a model without an existing configuration now resolve its owning provider group before falling back to vendor matching. Propose closing as completed.

## Change summary

Save per-model options to the provider group that exposed the selected model, rather than the first group sharing its vendor.

## Best solution

Retain the ownership-based resolution introduced by fa3b663f7234b8a6965d921bbe2f855c13e54a17. Keep the broader existing-settings collision case tracked separately at https://github.com/microsoft/vscode/issues/322408.
