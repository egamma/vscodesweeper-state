# Issue #315102 — Copilot Chat rich text copy/paste loses formatting for tables and code blocks

[https://github.com/microsoft/vscode/issues/315102](https://github.com/microsoft/vscode/issues/315102)

## Summary

A real Chat export gap remains: the message Copy action intentionally produces Markdown, while selection copy cannot reliably represent embedded Monaco code editors as rich HTML. No older issue reports the same table-and-code-block symptom, so this should be routed to the Chat area for a product decision rather than closed as a duplicate.

## Change summary

Provide a reliable way to copy Copilot Chat responses as rich HTML so tables and code blocks retain their structure in applications such as Teams, Outlook, and Word.

## Best solution

Add a distinct rich-text copy path for complete Chat responses that emits portable HTML with semantic tables and formatted code blocks, while retaining the existing Markdown copy behavior for Markdown-oriented workflows.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts`
- **Validation:** Exercise a rendered Chat response containing a Markdown table and fenced code block, invoke the chosen rich-copy surface, and assert that the clipboard text/html flavor contains a semantic table and the complete code text in a formatted block; then paste into Word or Teams and verify both structures remain intact while the existing Markdown-copy path remains unchanged.
- **Behavior:**

  > Users need a deliberate way to copy an entire Chat response as rich text. In that mode, a rendered Markdown table must paste as a real table and every fenced code block must retain all text, monospacing, and block structure in common HTML-aware applications. The existing portable Markdown workflow must remain available. Acceptance should cover one response containing headings, lists, a table, and multiple code blocks, including a code block between ordinary paragraphs.
- **Trace:**

  > The current response Copy action in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts writes only portable Markdown through IClipboardService.writeText. Native selection copy is handled in ChatListWidget.handleCopy, but current custom HTML handling only sanitizes links and images; commit https://github.com/microsoft/vscode/commit/f303fd73d506a3fc1c1db9b2068d1127c9cfff23 deliberately leaves other styling to the browser. ChatMarkdownContentPart replaces fenced Markdown with CodeBlockPart, whose contents live in separate CodeEditorWidget instances, establishing why a surrounding DOM selection may omit code. Preserve portable-link sanitization and the existing Markdown result; the uncertainty starts at the public copy interaction and how much rendered styling the HTML contract should carry.
- **Open decisions:**
  - Should rich HTML be exposed as a separate “Copy as Rich Text” action, or should the existing response Copy action change format with Markdown offered separately?
  - Should the rich-text contract preserve only semantic structure such as tables, lists, and code blocks, or also preserve VS Code theme colors and syntax highlighting?

## Evidence

- **current copy action:** src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts implements workbench.action.chat.copyItem by calling IClipboardService.writeText(toPortableMarkdown(...)); it does not write a text/html clipboard flavor. A maintainer also described right-click Copy as intentionally copying Markdown in https://github.com/microsoft/vscode/issues/280165#issuecomment-3618192589.
- **code-block boundary:** Chat Markdown code fences are replaced by CodeBlockPart instances in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts. CodeBlockPart renders each block through a separate CodeEditorWidget in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts, so a normal DOM selection spanning the response cannot reliably serialize code-block contents into the surrounding rich HTML.
- **recent clipboard work is narrower:** Merged commit https://github.com/microsoft/vscode/commit/f303fd73d506a3fc1c1db9b2068d1127c9cfff23 sanitizes internal links and images during selection copy. Its handleCopy path in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts delegates unchanged selections to the browser and does not serialize tables or embedded code editors, so its diff does not resolve this report's trigger.
- **canonical search:** The older open issues https://github.com/microsoft/vscode/issues/313539 and https://github.com/microsoft/vscode/issues/280165 concern lost or incorrectly generated link targets. Neither owns the reporter-observable symptom of tables flattening and code blocks disappearing or losing block formatting.
- **continued demand:** The reporter confirmed after multiple upgrades that the limitation remained, another user kept the request active, and the issue has three community upvotes.
