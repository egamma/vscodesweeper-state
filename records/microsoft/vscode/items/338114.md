# Issue #338114 — CLI agent host supervisor evicts the running Remote-SSH server from the shared server cache; on an NFS home this leaves a broken install (ServerNotExecutable)

[https://github.com/microsoft/vscode/issues/338114](https://github.com/microsoft/vscode/issues/338114)

## Summary

Keep open: current source still permits eviction of running editor servers and repeatedly reuses a partially deleted installation. The report provides detailed reproductions; this is a defect in the core Rust CLI, not grounds to transfer it merely because Remote-SSH exposes the failure.

## Change summary

Prevent supervisor cache maintenance from deleting running editor servers, losing other processes' cache bookkeeping, and leaving reconnects stuck on ServerNotExecutable.

## Best solution

Make shared server-cache maintenance safe across editor and supervisor processes, and allow incomplete installations with missing executables to recover without conflating them with genuine permission failures. Preserve reclamation of unused versions and existing permission-error reporting.

## Plan brief

- **Likely files:** `cli/src/download_cache.rs`, `cli/src/state.rs`, `cli/src/commands/agent_host.rs`, `cli/src/tunnels/agent_host.rs`, `cli/src/tunnels/code_server.rs`, `cli/src/tunnels/control_server.rs`, `cli/src/tunnels/paths.rs`
- **Validation:** Add Rust regression tests exercised with cargo test --manifest-path cli/Cargo.toml covering active-server survival across more than five cache entries, independent cache instances preserving each other's updates, and recovery from an existing installation missing server/bin/code-server. Re-run the issue's isolated NFS reproduction to confirm reconnect succeeds after the old processes stop, while genuine execute-permission errors remain explicit.
- **Behavior:**

  > Downloading agent-host releases must not remove files belonging to a running editor server. Independent CLI processes must not erase each other's server-cache bookkeeping. An installation left incomplete by partial deletion must not cause every subsequent reconnect to fail permanently because its directory still exists. Acceptance includes active-server survival beyond the retention limit, preserved cross-process cache entries, successful recovery of a missing executable, and unchanged handling of genuine permission failures.
- **Trace:**

  > The supervisor receives LauncherPaths::server_cache in cli/src/commands/agent_host.rs, and AgentHostManager::ensure_downloaded and run_update_loop in cli/src/tunnels/agent_host.rs use the same DownloadCache as CodeServer::setup. DownloadCache::touch in cli/src/download_cache.rs deletes the oldest directory without a running-server check; its creation locks do not cover eviction or shared LRU state. PersistedState in cli/src/state.rs caches state per process, allowing later writes to discard another process's entries. Following partial deletion, create accepts the surviving directory, ensure_executable reports ServerNotExecutable, and handle_serve in cli/src/tunnels/control_server.rs deliberately avoids eviction for that error. The source confirms these paths, while https://github.com/microsoft/vscode/issues/338114 provides the NFS and local-filesystem observations. Planning must establish a race-safe lifecycle across editor and agent-host consumers and account for DownloadCache's CLI/web-server consumers; generic PersistedState also serves authentication, tunnel, and other state and must not acquire unrelated behavioral changes. The uncertainty is the complete concurrency and recovery contract, not whether deleting a running installation is acceptable; retain permission-error diagnostics and avoid unrelated Remote-SSH or supervisor-startup policy changes.

## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/338114 supplies real CLI/server runs on NFS and local XFS: release downloads delete a running editor installation, NFS leaves a partial directory, and subsequent reconnects repeatedly fail with ServerNotExecutable. A separate run demonstrates a supervisor overwriting an editor process's newer lru.json entry. The issue has no comments or linked closing PRs.
- **Shared cache and eviction remain:** cli/src/commands/agent_host.rs constructs AgentHostManager with ctx.paths.server_cache and eagerly calls ensure_downloaded. cli/src/tunnels/agent_host.rs::run_update_loop downloads later versions after checking only its own managed server. cli/src/download_cache.rs::touch retains five entries and calls remove_dir_all on the oldest without checking whether an editor server is running.
- **Cross-process bookkeeping defect:** cli/src/state.rs::PersistedStateContainer::load_or_get retains a process-local state snapshot; PersistedState::update modifies that snapshot and overwrites the file. Its mutex does not coordinate independent processes. DownloadCache's per-entry creation lock does not protect lru.json updates or eviction.
- **Persistent reconnect failure:** cli/src/download_cache.rs::create returns immediately when the target directory exists, without checking completeness. cli/src/tunnels/code_server.rs::setup therefore accepts a partially deleted installation, while start fails at ensure_executable with ServerNotExecutable. cli/src/tunnels/control_server.rs::handle_serve evicts only ServerUnexpectedExit, leaving this missing-binary failure unrepaired.
- **Existing lifecycle precedent:** cli/src/tunnels/paths.rs::prune_stopped_servers checks ServerPaths::get_running_pid before deletion, unlike DownloadCache::touch. CodeServer::get_running reuses an editor server without refreshing its cache entry.
