# Issue #326215 — Agent Window: Provide more context in the subagent dropdown

[https://github.com/microsoft/vscode/issues/326215](https://github.com/microsoft/vscode/issues/326215)

## Summary

Keep open: current main partially improves the dropdown by grouping active and completed subagents and listing newer entries first, but rows still omit the requested model, elapsed or recent-activity context, and usage information. This is also a protected team-authored product request with no explicitly linked completing change.

## Change summary

Make the Agents window subagent dropdown distinguish running and recently active workers by showing useful status, timing, model, and optional usage context.

## Best solution

Enrich each subagent row with a compact hierarchy: task title as the leading information, status and model as supporting context, and elapsed or recent-activity timing where available; keep cost or token details secondary to avoid turning the dropdown into a monitoring dashboard. Preserve active-first ordering and expose the same information in accessible row descriptions.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionBackgroundActivitiesControl.ts`, `src/vs/sessions/contrib/chat/test/browser/sessionBackgroundActivitiesControl.test.ts`, `src/vs/workbench/browser/chatPills.ts`
- **Validation:** Extend the SessionBackgroundActivitiesControl unit tests to assert active-first/newest-first ordering and the model, status/activity, timing, and accessible descriptions published for representative running and completed subagents; then verify the dropdown remains keyboard navigable and announces that metadata.
- **Behavior:**

  > The subagent dropdown must let a user identify which workers are active, which were created or updated most recently, and which model each worker uses without opening every child chat. Active work should remain above completed work, with task title leading and compact status, model, and timing context supporting it. Any usage or cost information should be secondary rather than competing with the task identity. Keyboard and screen-reader users must receive equivalent row context.
- **Trace:**

  > The Agents window builds these rows in SessionBackgroundActivitiesControl._collectSubagents and _entry in src/vs/sessions/contrib/chat/browser/sessionBackgroundActivitiesControl.ts. Current main already groups active versus completed chats and reverses each group into newest-first order, but _entry publishes only a truncated title and icon. IChat in src/vs/sessions/services/sessions/common/session.ts already exposes createdAt, updatedAt, status, modelId, and description; IChatPillEntry in src/vs/workbench/browser/chatPills.ts supports badge, hover, and ariaDescription presentation. Preserve provider neutrality and the existing active/completed filtering; do not expand this dropdown-specific work into the heartbeat, cancellation, or parent-transcript behavior tracked by https://github.com/microsoft/vscode/issues/326533.
- **Open decisions:**
  - Which metadata must remain visible on every dropdown row—status, model, and elapsed or last-activity time—and which should appear only in hover or expanded details to preserve a calm, scannable hierarchy?
  - Should token or credit usage be part of this first dropdown experience, or remain a separately scoped secondary detail until all session providers expose comparable usage data?

## Evidence

- **current implementation:** src/vs/sessions/contrib/chat/browser/sessionBackgroundActivitiesControl.ts groups entries into “Subagents: In Progress” and “Subagents: Completed” and reverses chat creation order so newer subagents appear first, partially covering the request.
- **remaining gap:** SessionBackgroundActivitiesControl._entry currently supplies only id, truncated title, agent icon, and open behavior; it does not populate the dropdown entry badge, hover, or accessible description with model, elapsed time, current activity, or usage.
