# Issue #313192 — Folding Strategy: Brackets

[https://github.com/microsoft/vscode/issues/313192](https://github.com/microsoft/vscode/issues/313192)

## Summary

This is a distinct, still-open feature request for bracket-aware folding, currently undergoing the established Backlog Candidates upvote process. The older related folding issue concerns displaying the ending brace on the collapsed line rather than selecting bracket pairs as the folding-range strategy, so it does not meet the stronger duplicate bar for this re-review.

## Change summary

Add a bracket-based `editor.foldingStrategy`, optionally combinable with indentation folding, to derive folding ranges from VS Code's bracket-pair model.

## Best solution

Evaluate a bracket-based folding-range provider in the editor folding model that reuses token-aware bracket-pair data, including embedded-language behavior, while preserving the existing `auto` and `indentation` strategies and defining how mixed bracket-and-indentation ranges are prioritized.

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketPairsTree/bracketPairsTree.ts`

- **Behavior:**

  > Users can select a bracket-based folding strategy that creates foldable regions from token-aware matching bracket pairs, including valid pairs in embedded-language regions. Brackets in comments or strings must follow the existing bracket-pair model rather than being folded as structural delimiters. Existing `auto` and `indentation` behavior remains unchanged. If a combined mode is chosen, acceptance tests must define deterministic handling of overlapping bracket and indentation ranges.
- **Trace:**

  > The request extends the folding-strategy selection used by the editor folding contribution and would need to connect folding-range production to the editor's bracket-pair model. Likely boundaries are src/vs/editor/contrib/folding/browser/folding.ts and foldingModel.ts for strategy/range handling, and src/vs/editor/contrib/bracketMatching/browser/bracketPairsTree/bracketPairsTree.ts for the existing bracket data source. Preserve language-provider precedence under `auto`, indentation behavior, folding limits, cancellation, and range ordering. https://github.com/microsoft/vscode/issues/3352 is related only to collapsed-range presentation and does not own this behavior. The uncertainty begins at the public semantics: whether `brackets` replaces indentation entirely or is combined with it, and how overlapping ranges should resolve.
- **Open decisions:**
  - Should the public option provide bracket-only folding, a combined bracket-and-indentation mode, or both?
  - When bracket-derived and indentation-derived ranges overlap without identical boundaries, which range should users see and navigate?
