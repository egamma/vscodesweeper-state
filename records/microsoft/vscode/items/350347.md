# Issue #350347 — Workbench components should react to workspace folder changes instead of onDidChangeLocation

[https://github.com/microsoft/vscode/issues/350347](https://github.com/microsoft/vscode/issues/350347)

Keep open: current source still contains location-specific workbench subscriptions and confirms the event-ordering concern. The assigned 1.149.0 milestone also protects this scheduled cleanup from closure.

## Change summary

Consolidate non-UI folder-location reactions onto workspace-folder events and clarify outgoing-folder state availability.

## Best solution

Have non-location-UI consumers use workspace-folder events while preserving their existing state-saving and restoration semantics. Establish the folder-change event contract, including location-change metadata and outgoing-folder availability, before migrating consumers.
