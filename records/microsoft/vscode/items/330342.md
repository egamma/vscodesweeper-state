# Issue #330342 — Downloaded update lost on quit, triggers re-download

[https://github.com/microsoft/vscode/issues/330342](https://github.com/microsoft/vscode/issues/330342)

## Summary

Real, source-traceable defect: on macOS VS Code delegates entirely to Electron's native autoUpdater with only in-memory state, so a downloaded-but-not-installed update is forgotten on quit and re-downloaded on relaunch. Already correctly labeled (install-update, macos) and a collaborator has already weighed in, so this just needs to stay open pending a design/Electron-capability decision.

## Change summary

On macOS, quitting before clicking Update loses the already-downloaded update package, forcing a full re-download on next launch instead of detecting and reusing (and verifying) the cached file.

## Best solution

Persist/verify the downloaded update package across relaunches so `doCheckForUpdates`/`onUpdateAvailable` in `updateService.darwin.ts` can detect an already-downloaded, checksum-valid package instead of re-invoking `electron.autoUpdater.checkForUpdates()` from scratch; this likely needs either extra state tracking in `abstractUpdateService.ts` or added capability from Electron's Squirrel.Mac autoUpdater, as the collaborator noted.

## Evidence

- **source trace:** src/vs/platform/update/electron-main/updateService.darwin.ts fully delegates download/state to `electron.autoUpdater` (Squirrel.Mac); `onUpdateDownloaded` only calls `this.setState(State.Ready(...))`, an in-memory state with no persistence of the downloaded package across process restarts.
- **doCheckForUpdates re-triggers download:** `doCheckForUpdates` always calls `electron.autoUpdater.checkForUpdates()` again on relaunch with no check for an existing cached/downloaded package.
- **prior report closed not_planned:** The reporter's earlier issue https://github.com/microsoft/vscode/issues/303341 was closed as not-planned on the assumption an Electron bug (electron/electron#50200) was the cause and fixed by Electron 42.7.0, but the reporter re-confirmed on 2026-08-11 the behavior persists on VS Code 1.132.1 / Electron 42.7.1 and filed this new issue instead of reopening the closed one.
- **collaborator response:** dmitrivMS (COLLABORATOR) commented on this issue that it 'may require Electron work since we don't have as much control over the update on macOS and rely on Electron to manage it' — acknowledging the issue but not yet resolving it.
