# Issue #330342 — Downloaded update lost on quit, triggers re-download

[https://github.com/microsoft/vscode/issues/330342](https://github.com/microsoft/vscode/issues/330342)

## Summary

Real, still-open defect, but the root cause lives in Electron's macOS auto-updater (Squirrel.Mac), which VS Code delegates to entirely and doesn't control — a collaborator already flagged this as likely requiring upstream Electron work, so it stays open and classified as upstream rather than closed.

## Change summary

On macOS, an update downloaded via Electron's autoUpdater is not reused after quitting/relaunching without installing it; the next update check re-downloads the same package from scratch instead of detecting and verifying the already-downloaded file.

## Best solution

Track this as upstream against Electron/Squirrel.Mac's autoUpdater persistence behavior; VS Code's DarwinUpdateService (src/vs/platform/update/electron-main/updateService.darwin.ts) has no independent download-cache/verification layer of its own on macOS — it just calls electron.autoUpdater.checkForUpdates()/quitAndInstall() and relies on Electron to manage the downloaded package across restarts. A prior report with the identical title (https://github.com/microsoft/vscode/issues/303341) was closed as not-planned after a maintainer attributed it to a specific Electron bug (electron/electron#50200) that was since fixed, but the reporter confirmed afterward that the underlying symptom persists — so that close doesn't cover the full remaining scope and this report correctly reopens the gap.
