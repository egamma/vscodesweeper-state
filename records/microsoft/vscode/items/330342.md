# Issue #330342 — Downloaded update lost on quit, triggers re-download

[https://github.com/microsoft/vscode/issues/330342](https://github.com/microsoft/vscode/issues/330342)

## Summary

Keep open: the reporter retested after the previously suspected Electron fix and still observed the redundant download. Current source continues to delegate downloads to Electron; the supplied steps suffice to retest, but source inspection alone cannot establish whether the staged package survives or is reused.

## Change summary

Preserve and reuse an already-downloaded macOS update after Cmd+Q and relaunch instead of downloading the same update again.

## Best solution

Establish whether Electron/Squirrel loses the staged update or VS Code fails to recover its readiness, then ensure a valid pending update remains installable without another package download. Preserve the distinction between ordinary quit and an explicit request to update.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`
- **Validation:** Using a signed macOS build with an available update, finish downloading, quit with Cmd+Q without selecting Update, relaunch, and check for updates. Record updater events, ShipIt state, and network transfers to verify that the same valid package is reused without another full download and can subsequently be installed.
- **Behavior:**

  > A fully downloaded macOS update should remain usable after an ordinary Cmd+Q and relaunch. Checking for updates should recognize the same valid pending package rather than transfer it again. Validate actual package reuse, not merely a change in the displayed update state, and confirm that explicit installation still succeeds.
- **Trace:**

  > DarwinUpdateService in src/vs/platform/update/electron-main/updateService.darwin.ts delegates checks, download completion, and installation to Electron's autoUpdater. AbstractUpdateService in src/vs/platform/update/electron-main/abstractUpdateService.ts starts with in-memory state and enters Idle during initialization; the Darwin service has no explicit staged-package recovery path. That absence does not establish a defect by itself because Electron/Squirrel owns the downloaded artifacts. Diagnosis must distinguish a real repeat transfer from transient checking/downloading events and identify whether the package is removed or merely not recognized. The reporter rejected the earlier presumed resolution at https://github.com/microsoft/vscode/issues/303341#issuecomment-5258649762, and the maintainer identified possible Electron ownership at https://github.com/microsoft/vscode/issues/330342#issuecomment-5259209247. Preserve integrity verification and existing explicit-install semantics; do not infer that ordinary quit must automatically install the update.
