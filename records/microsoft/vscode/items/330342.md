# Issue #330342 — Downloaded update lost on quit, triggers re-download

[https://github.com/microsoft/vscode/issues/330342](https://github.com/microsoft/vscode/issues/330342)

## Summary

Keep open: the reporter explicitly retested after the earlier presumed Electron fix and still sees the same update downloaded again after quitting. The macOS update path delegates package handling to Electron, so the remaining defect needs investigation at that boundary rather than another presumed-fixed close.

## Change summary

A downloaded macOS update is downloaded again after Cmd+Q, relaunch, and Check for Updates.

## Best solution

Ensure a valid, already-downloaded update remains reusable across a normal quit and relaunch. Establish whether Electron/Squirrel loses the staged package or VS Code fails to recover its availability, and address the responsible layer without making ordinary quit imply an update restart.

- **Validation:** On a signed macOS build with an available update, download it fully, record the target version and updater logs, quit with Cmd+Q without selecting Update, relaunch, and select Check for Updates. - **Behavior:**

  > The reporter observes another full download of the same update after downloading it, quitting with Cmd+Q, relaunching, and checking for updates. A valid downloaded package should remain reusable across that sequence, with installation available without downloading the payload again. Ordinary quit need not automatically install the update. Acceptance must distinguish a repeated payload download from a lightweight update-feed check and verify that explicit installation still succeeds.
- **Trace:**

  > DarwinUpdateService in src/vs/platform/update/electron-main/updateService.darwin.ts uses Electron autoUpdater for package download and installation; onUpdateDownloaded changes the process-local state to Ready. AbstractUpdateService in src/vs/platform/update/electron-main/abstractUpdateService.ts initializes to Idle and offers a postInitialize hook, but the Darwin subclass does not restore pending-update state there. The source establishes delegation and missing VS Code-side restoration, not whether Electron/Squirrel deletes, ignores, or successfully reuses its staged package. Begin with the reported quit/relaunch sequence on a signed build and inspect updater logs and payload transfer. Preserve explicit-install semantics and unrelated platform update behavior. The previous report https://github.com/microsoft/vscode/issues/303341 contains a post-closure retest; https://github.com/electron/electron/issues/50200 concerns a different installation-race trigger and must not be assumed to resolve this case.
