# Issue #272483 — Add icon for selection in chat

[https://github.com/microsoft/vscode/issues/272483](https://github.com/microsoft/vscode/issues/272483)

## Summary

The visual inconsistency remains on current main: the built-in `#selection` completion is emitted without a selection-specific icon, despite an appropriate codicon now existing. No older issue with the same observable symptom was found, so this should remain open as chat input polish.

## Change summary

Show a recognizable selection icon beside the `#selection` item in the chat input completion list.

## Best solution

Render the existing `Codicon.selection` for the `#selection` completion while retaining its visible text and accessible label. Keep the change scoped to completion presentation; selection attachment behavior should remain unchanged.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/editor/common/languages.ts`
- **Validation:** With a non-empty editor selection, open Chat and type `#`; verify that the `#selection` completion displays the selection codicon, remains keyboard-selectable and screen-reader-labeled as selection, and inserts the same file-range reference as before.
- **Behavior:**

  > When an editor has a non-empty selection and the user invokes `#` completions in Chat, the `#selection` row should display the standard selection icon used elsewhere in VS Code. Its text, description, keyboard behavior, accessible name, and inserted file-range reference must remain unchanged. Other completion kinds must retain their existing icons and ordering.
- **Trace:**

  > BuiltinDynamicCompletions in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts creates the selection entry as `CompletionItemKind.Text`, so the suggestion row has no distinguishing icon. The entry still creates a `vscode.selection` reference carrying the active resource and range. A dedicated `Codicon.selection` now exists in src/vs/base/common/codiconsLibrary.ts and is already used by the find widget, but completion rendering maps icons through kinds in src/vs/editor/common/languages.ts rather than accepting a per-item codicon. Keep the boundary to presentation: do not alter selection capture, inserted text, reference data, or generic suggest-widget behavior for unrelated consumers. The icon is supplemental and must not replace the visible or accessible `#selection` label.
