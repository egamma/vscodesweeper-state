# Issue #277310 — Wrong symbol information in cloud diff editor

[https://github.com/microsoft/vscode/issues/277310](https://github.com/microsoft/vscode/issues/277310)

## Summary

Keep open: current source exposes a document-identity collision that can produce wrong symbol locations between the two cloud diff revisions. This team-authored report has neither a verified canonical duplicate nor a qualifying fixing commit.

## Change summary

Cmd-hover in a completed cloud session's changed-file diff reports symbol locations that do not match the displayed revision.

## Best solution

Ensure language-feature requests distinguish the base and head cloud documents and return locations corresponding to the displayed content. Investigate the boundary between Copilot's PR content URIs and the built-in TypeScript client's virtual-file identity without substituting local checkout content.

- **Current-source collision:** extensions/typescript-language-features/src/typescriptServiceClient.ts:776-790, toTsFilePath includes scheme, authority, path and fragment but omits query. Consequently, base and head URIs for an unchanged filename map to the same TS server filepath. In extensions/typescript-language-features/src/tsServer/bufferSyncSupport.ts:491-494 and 594-610, syncedBuffers uses that filepath as its normalized key, and openTextDocument skips opening a second document when the key already exists. Requests from the second revision therefore use the first revision's synchronized content.
