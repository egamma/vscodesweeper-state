# Issue #229115 — Cannot move multi-cell selection within Jupyter notebook using alt+up/down arrows

[https://github.com/microsoft/vscode/issues/229115](https://github.com/microsoft/vscode/issues/229115)

## Summary

Keep open: the current movement commands still resolve to the active cell rather than the selected group. The existing notebook-commands classification is appropriate, and no verified canonical issue absorbs this request.

## Change summary

Make Alt+Up/Down move the entire contiguous notebook-cell selection rather than only its active cell.

## Best solution

Have notebook keyboard movement honor the contiguous selected group, preserving cell order and selection after moving. Preserve explicit cell-toolbar targeting and existing single-cell behavior.

## Evidence

- **Existing capability does not cover the request:** Current main src/vs/workbench/contrib/notebook/browser/contrib/cellCommands/cellCommands.ts:27–80 registers notebook.cell.moveUp and notebook.cell.moveDown on Alt+Up/Down as NotebookCellAction commands, forwarding their cell context to moveCellRange. These commands exist, but do not provide selected-group movement on this path.
- **Active-cell selection takes precedence:** Current main src/vs/workbench/contrib/notebook/browser/controller/coreActions.ts:79–91 constructs the active-editor context with both cell: activeCell and selectedCells. In controller/cellOperations.ts:188–209, moveCellRange chooses the singleton range for context.cell; it reads editor.getSelections() only when context.cell is absent. This explains why the active cell moves instead of the selected group.
