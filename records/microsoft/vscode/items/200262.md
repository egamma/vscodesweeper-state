# Issue #200262 — Deleted collapsed folders remain visible until explorer refresh

[https://github.com/microsoft/vscode/issues/200262](https://github.com/microsoft/vscode/issues/200262)

## Summary

The stale collapsed-child behavior was fixed after this report by clearing cached children when a collapsed AsyncDataTree node is refreshed. The Explorer deletion path now reaches that logic, so this can be closed as completed.

## Change summary

Deleting the sole collapsed child folder should immediately remove it from the Explorer instead of leaving a stale row until refresh.

## Best solution

Keep the shipped AsyncDataTree stale-child cleanup from commit 7b3282b42e8e3e3048fe43d611d41ce31c35b3c7; it removes the cached deleted child during the Explorer's existing parent refresh.
