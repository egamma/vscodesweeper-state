- **Current source:** src/vs/editor/common/core/editorColorRegistry.ts still registers editorGhostText.foreground with hcDark: null and hcLight: null, while editorGhostText.border has explicit high-contrast defaults. Switching between the two built-in high-contrast themes therefore still reaches the null foreground defaults identified by the reporter.
- **Verified canonical:** https://github.com/microsoft/vscode/issues/146670 was verified OPEN. Its discussion explicitly identifies the same hcDark: null, hcLight: null registration and requests changing the default foreground values, including for VS Code's built-in high-contrast themes.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/146670#issuecomment-1087619126 accepts a contribution changing the defaults. https://github.com/microsoft/vscode/issues/146670#issuecomment-1088465771 cautions that the proposed ordinary-theme colors lack sufficient contrast and calls for at least 3:1, preferably 4.5:1.
- **Scope and distinct evidence:** This report adds an extension consumer of editorGhostText.foreground on VS Code 1.95.1, macOS Darwin arm64 24.0.0. It identifies the same null defaults rather than a separate extension defect; choosing suitable non-null defaults in the canonical addresses this central request too.
- **Rendering distinction:** src/vs/editor/contrib/inlineCompletions/browser/view/ghostText/ghostTextView.css uses --vscode-editorGhostText-foreground for nonsyntax-highlighted ghost text and supplies a separate border token. A null foreground default is not itself an explicitly transparent color, nor proof that built-in inline suggestions are invisible.
- **Canonical search:** A repository issue search for editorGhostText.foreground and contrast returned this report, the verified canonical, and a separate syntax-highlighted suggestion-opacity request. The verified canonical directly owns the high-contrast default-color work.
