# Issue #330048 — Offer "Continue in..." when Copilot credits run low in the Agents window

[https://github.com/microsoft/vscode/issues/330048](https://github.com/microsoft/vscode/issues/330048)

## Summary

Keep open: current source supports cross-harness continuation in the Agents window, but the inspected credit-limit surfaces do not offer continuation into Codex. This team-authored request remains distinct from general session-porting and billing tracking.

## Change summary

Offer continuation of a Copilot session into Codex when credits are exhausted and the user is already signed into ChatGPT.

## Best solution

Make an eligible Codex continuation discoverable at the Agents window's Copilot credit-limit interruption, preserving conversation context through the existing handoff infrastructure. Decide whether to offer it only at exhaustion or also in approaching-limit warnings.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatQuotaNotification.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuotaExceededPart.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts`, `src/vs/sessions/contrib/chat/browser/agentHostDelegation.ts`, `src/vs/workbench/contrib/chat/test/browser/chatQuotaExceededPart.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatQuotaNotification.test.ts`
- **Validation:** Extend the relevant quota UI tests to assert that the agreed Agents-window quota state offers Codex continuation only when eligible. Manually verify that activating it from an exhausted Copilot session creates a Codex session with prior conversation context and the same workspace, while signed-out or unavailable Codex states do not expose an unusable action.
- **Behavior:**

  > When Copilot credits interrupt a session in the Agents window, a user already signed into ChatGPT can discover and explicitly choose to continue in Codex. Continuation preserves the prior conversation as context and retains the source workspace. It must not silently switch harnesses or discard the original session. Acceptance includes an eligible signed-in case and an unavailable or signed-out Codex case; offering the action before exhaustion remains a product decision.
- **Trace:**

  > ChatQuotaExceededPart currently renders the quota error with budget-management or upgrade actions. ChatQuotaNotificationContribution separately constructs exhausted and approaching-limit input notifications; its approaching-limit path can offer Switch to Auto, but neither path offers Codex continuation. ChatContinueInSessionActionItem.actionProvider already enumerates delegatable agent-host contributions, and CreateRemoteAgentJobAction.run prepares cross-type handoffs with transcript context. The Agents window imports agentHostDelegation.ts, whose generic handler creates a target session in the active session's workspace and sends the attached context. Source inspection establishes available handoff infrastructure, but not runtime Codex authentication eligibility or the best contextual UI placement. Keep full-fidelity session porting outside this feature's scope; that distinct work is tracked at https://github.com/microsoft/vscode/issues/323970.
- **Open decisions:**
  - Should the offer appear only when credits are exhausted, as described in the body, or also before exhaustion in approaching-limit warnings?
  - Should the contextual offer appear in the quota-error response, the chat-input notification, or both?
