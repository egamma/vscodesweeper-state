## Plan brief

- **Likely files:** `src/vs/platform/actionWidget/browser/actionWidget.css`, `src/vs/platform/actionWidget/browser/actionList.ts`, `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`
- **Validation:** Manually open the Agent Host workspace picker's Dev Container submenu, focus/hover the 'Use Dev Container' row, and confirm the focus outline no longer overlaps the label text at default zoom.
- **Behavior:**

  > In the Agent Host workspace picker, opening a folder's submenu and focusing/hovering the 'Use Dev Container' (or 'Use Local'/'Use Remote Host') row should draw the focus/selection outline cleanly around the row without visually overlapping the item's text or check icon. Acceptance: manual visual check of the submenu at default and larger zoom levels shows no overlap for any checked-state row.
- **Trace:**

  > The submenu rows are built with `checked` actions in sessionWorkspacePicker.ts's createWorkspaceModeActions and rendered by the shared action-list widget, which prefixes a check/blank codicon (actionList.ts ~L2773/2799) before the `.title` label inside a flex row (`display:flex; gap:6px; align-items:center` in actionWidget.css). Focused rows get an inset outline (`outline-offset:-2px`) from actionWidget.css:94-99. The reporter's screenshot shows this outline overlapping the label text specifically in this submenu; the exact trigger (icon width vs. outline inset vs. row min-height) hasn't been isolated from source alone — that's the open question. Do not change the outline styling for other action-widget consumers (context menus, code actions) without confirming they aren't already correct; scope the fix to the checked-item layout path if that's the root cause.
- **Open decisions:**
  - Is the overlap specific to checked/radio-style submenu rows (icon + label) or does it affect all action-widget rows generically?
  - Is the root cause the outline inset (-2px) versus the row's flex layout/padding, or a check-icon width change from a recent PR?

## Evidence

- **screenshot:** Issue includes a screenshot from the reporter (a VS Code collaborator) showing the focus border overlapping the 'Use Dev Container' text; filed while testing the dev-container submenu PR referenced as #335485.
- **component:** The submenu items are built via toAction({..., checked: ...}) in src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts (createWorkspaceModeActions) and rendered through the shared action list widget (src/vs/platform/actionWidget/browser/actionList.ts), which draws a check/blank codicon before the label based on `checked`.
- **focus styling:** src/vs/platform/actionWidget/browser/actionWidget.css:94-99 applies `outline: 1px solid var(--vscode-menu-selectionBorder, transparent); outline-offset: -2px;` to `.monaco-list-row.action.focused`; no recent commit touching this file addresses an overlap with checked-item labels (git log on the file's only recent change is unrelated, #336769).
