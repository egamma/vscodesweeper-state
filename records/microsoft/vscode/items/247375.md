# Issue #247375 — Add MCP Allow List to MDM Policy

[https://github.com/microsoft/vscode/issues/247375](https://github.com/microsoft/vscode/issues/247375)

## Summary

Keep open: the requested `ChatAllowedMcpServers` enterprise policy now exists, but it does not yet prevent every disallowed server from running through delegated Agent Host sessions. This accepted Backlog request remains useful as the broad governance requirement while the confirmed enforcement gaps are completed.

## Change summary

Allow administrators to define and enforce an enterprise-managed allowlist of approved local and remote MCP servers.

## Best solution

Enforce the existing `ChatAllowedMcpServers` and `ChatDeniedMcpServers` policies at every MCP launch boundary, including servers forwarded to Agent Host, discovered by Agent Host from workspace `.mcp.json`, migrated configurations, and provider-built-in servers. The same resolved server identity and restrictive allow/deny semantics should apply regardless of which runtime launches the server.

## Plan brief

- **Likely files:** `src/vs/platform/mcp/common/allowedMcpServersService.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLocalCustomizations.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupport.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`
- **Validation:** Extend the MCP policy and Agent Host suites so non-allowlisted HTTP and stdio servers are unavailable when forwarded by VS Code, discovered from workspace `.mcp.json`, or restored after migration, while matching servers remain usable; run `./scripts/test.sh --grep "enterprise MCP policy|AllowedMcpServersService"`.
- **Behavior:**

  > An administrator can configure an MCP allowlist through enterprise policy, and only matching servers may be installed, started, or expose tools. Enforcement must be identical for local chat and delegated Agent Host sessions, including workspace-discovered and migrated servers. Tightening the policy must prevent an already configured disallowed server from remaining usable. Matching local commands and remote URL patterns must continue to work.
- **Trace:**

  > The policy surface was added by https://github.com/microsoft/vscode/pull/326226 and is registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. Local enforcement flows through AllowedMcpServersService in src/vs/platform/mcp/common/allowedMcpServersService.ts. https://github.com/microsoft/vscode/issues/328241 confirms that delegated Agent Host launches can bypass that service; https://github.com/microsoft/vscode/pull/333291 addresses VS Code-forwarded servers but explicitly excludes runtime-discovered workspace `.mcp.json` servers and provider-built-in servers. The boundary is MCP policy enforcement: preserve the existing matcher grammar and allow/deny precedence, and do not broaden this into unrelated tool or sandbox policy work.
- **Open decisions:**
  - Should provider-built-in MCP servers, including the provider's GitHub MCP server, be governed by the same enterprise allowlist, and what stable administrator-visible identity should represent them?
