# Issue #229940 — Source Control Graph - "Go to file" opens full path and does not update explorer

[https://github.com/microsoft/vscode/issues/229940](https://github.com/microsoft/vscode/issues/229940)

## Summary

Keep this accepted request open: current main improves the historical file's title but still opens the read-only commit resource rather than the editable workspace file. The closely related open request is newer, so it cannot absorb this re-reviewed item as a duplicate.

## Change summary

Provide convenient access to an editable workspace file from an SCM Graph commit's multi-file diff, with normal file naming and Explorer reveal.

## Best solution

Provide clearly distinguished access to the working-tree file from historical multi-diffs while retaining access to the committed version and respecting Explorer auto-reveal settings. Settle which action is primary, and coordinate the overlapping newer request at https://github.com/microsoft/vscode/issues/250938.

Manually open a commit whose file differs from the working tree: verify editable-file access, retained historical contents, normal workspace naming, and Explorer selection with explorer.autoReveal enabled; disabling auto-reveal must remain respected. These checks were not executed during this read-only review.
- **Behavior:**

  > Viewing a commit's multi-file diff must offer convenient access to the corresponding editable workspace file when it exists. Opening that file should use normal workspace naming and existing Explorer auto-reveal behavior. Users must retain a way to inspect the committed version without substituting current contents for historical contents. Acceptance should distinguish the two versions using a file changed after the selected commit and verify that navigation respects Explorer settings.
- **Trace:**

  > SCM Graph opens historical multi-diffs through ScmHistoryItemResolver; resolveDiffSource currently gives each item change.modifiedUri as its goToFileUri. GoToFileAction.run opens that target and its supplied historical title. Commit https://github.com/microsoft/vscode/commit/3eec502f99b258439e52c955de237403fc9dafd6 deliberately restored committed-content navigation after the earlier resolver change. Existing git.openFile provides working-tree access from an already-open historical editor, but not directly through the multi-diff action. The resolver test already asserts historical-target and revision-title behavior. Preserve historical diff contents, ordinary SCM working-tree navigation, and explorer.autoReveal semantics; do not broadly reinterpret all Git URIs. The remaining uncertainty is the user-facing action contract, shared with the newer related request https://github.com/microsoft/vscode/issues/250938; the linked implementation attempt https://github.com/microsoft/vscode/pull/238763 was rejected and is closed.
- **Open decisions:**
  - Should the historical multi-diff's primary file action open the editable working-tree file, or retain committed-file navigation and expose a separate, clearly labeled working-tree action?
