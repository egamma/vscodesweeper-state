# Issue #126964 — Tree item focus should avoid jumping when tree items change

[https://github.com/microsoft/vscode/issues/126964](https://github.com/microsoft/vscode/issues/126964)

## Summary

Still open — the original general fix (bf495694c7c) was reverted in Dec 2023 by d95f2e01ab8 (PR #201309) because it caused regressions. Focus preservation was moved back to per-tree implementations (Explorer, workspace trust), leaving custom tree views without automatic focus stabilization when items are removed. No subsequent general solution has landed.

## Change summary

When a focused tree item is removed during a tree refresh, focus jumps to the tree root instead of moving to a neighbor element — particularly affecting custom tree views.

## Best solution

Implement focus preservation for custom tree views specifically, as joaomoreno suggested in comment 6. This likely belongs in the tree view integration layer (e.g. `src/vs/workbench/browser/parts/views/` or `src/vs/workbench/api/browser/mainThreadTreeViews.ts`) rather than as a blanket behavior in `src/vs/base/browser/ui/list/listWidget.ts`, since the general approach caused regressions (https://github.com/microsoft/vscode/issues/174768).
