# Issue #126964 — Tree item focus should avoid jumping when tree items change

[https://github.com/microsoft/vscode/issues/126964](https://github.com/microsoft/vscode/issues/126964)

## Summary

Keep open: current custom-tree refresh handling still drops item focus when the focused element disappears. The original general fix was deliberately reverted, while Explorer received its own preservation logic; that does not resolve the reopened custom-tree case.

## Change summary

Preserve keyboard focus on a neighboring item when a custom tree refresh removes the focused item.

## Best solution

Provide focus continuity for custom tree views when refresh removes the focused item, without restoring the global list focus/selection behavior reverted by PR 201309. Preserve existing focus when its item survives and leave Explorer's separate handling intact.
