## Change summary

Prevent recurring macOS Command Line Developer Tools installation prompts during startup without requiring local tools or disabling remote Git integration.

## Best solution

## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/main.ts`
- **Validation:** On macOS 26.6 without Command Line Developer Tools, launch with Git enabled, quit, and relaunch repeatedly; no developer-tools installation dialog should appear. Connect to a remote workspace with Git installed remotely and verify Source Control status and diff remain functional. Also check local Git discovery with a working non-Apple Git installation.
- **Behavior:**

  > The reporter sees a macOS Command Line Developer Tools installation dialog on every VS Code startup despite dismissing it, including in 1.135.0. Starting and restarting without local developer tools should not repeatedly request installation. This must not require disabling Git globally or impair Git operations in remote workspaces. Acceptance includes repeated prompt-free local launches and functioning remote Source Control.
- **Trace:**

  > In extensions/git/src/main.ts, _activate calls createModel when Git is enabled; createModel reads git.path and invokes findGit in extensions/git/src/git.ts. findGit tries configured paths through findSpecificGit before findGitDarwin, whose normal Apple-Git branch checks xcode-select -p and avoids git execution for exit code 2. Source inspection establishes these paths but not whether macOS 26.6 returns another result, a configured path bypasses the guard, or another startup caller invokes an Apple tool. Diagnose the actual process and command before selecting a fix; preserve working local Git installations and remote Git behavior. https://github.com/microsoft/vscode/issues/236120 is related, but its devcontainer-file trigger has not been connected to this startup report.
