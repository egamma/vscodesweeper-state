# Issue #258764 — QuickTree API - Allow single selection

[https://github.com/microsoft/vscode/issues/258764](https://github.com/microsoft/vscode/issues/258764)

## Summary

Keep open: current QuickTree remains checkbox-oriented, and IQuickInputService.pick still creates a flat QuickPick. The maintainer's repository → submodule → worktree scenario needs more than the suggested two-level separator workaround.

## Change summary

Allow callers to pick one item from a hierarchical QuickTree through IQuickInputService.pick.

## Best solution

Provide an opt-in hierarchical single-item picking contract in the core quick-input service, supporting selectable repositories at different depths while preserving existing flat QuickPick and checkbox-based QuickTree behavior. Settle the caller-facing API contract before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputService.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/tree/quickTree.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeController.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeRenderer.ts`, `src/vs/platform/quickinput/browser/tree/quickInputTreeAccessibilityProvider.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Add targeted quick-input tests using a repository → submodule → worktree hierarchy: accepting an item at each depth returns exactly that item, cancellation returns undefined, and expansion does not inadvertently accept. Run scripts/test.sh --run src/vs/platform/quickinput/test/browser/quickinput.test.ts after implementation; also exercise keyboard navigation and confirm existing flat picking and checkbox-tree consumers retain their behavior.
- **Behavior:**

  > A core caller can present a hierarchy and obtain exactly one selected item through IQuickInputService.pick. The motivating SCM hierarchy includes a repository, its submodule and that submodule's worktree; selection must not be limited to leaf nodes. Expanding or collapsing nodes must remain distinct from accepting a choice, and cancellation returns no selection. Existing flat QuickPick calls and checkbox-based QuickTree consumers retain their current behavior.
- **Trace:**

  > IQuickInputService.pick currently delegates through QuickInputService to QuickInputController.pick, which always creates a QuickPick and consumes a flat items array. IQuickTree instead exposes checkedLeafItems and checkbox events; QuickTree.show/update always enable the checkbox-oriented controls, and QuickInputTreeController registers checkbox interactions despite disabling multiple tree-row selection. Existing consumers include chatToolPicker.ts, languageModelToolsConfirmationService.ts and createPluginAction.ts; their selection semantics must remain unchanged. The source establishes the missing capability, but does not establish how callers distinguish hierarchical inputs from structurally similar flat items through the pick contract. Public extension API exposure is separate work tracked by https://github.com/microsoft/vscode/issues/258328, and lazy loading is separate work tracked by https://github.com/microsoft/vscode/issues/258655; neither is required to satisfy this request.
- **Open decisions:**
  - What caller-facing contract should distinguish hierarchical single selection in IQuickInputService.pick: an explicit tree-mode option, a tagged hierarchical input, or automatic interpretation of children? This choice must preserve existing flat-pick calls, including items carrying additional caller metadata.

## Evidence

The final comment explicitly requires repository → submodule → worktree depth, beyond the two-level full-length QuickPick separators suggested earlier.
- **Existing service does not provide hierarchical picking:** src/vs/platform/quickinput/common/quickInput.ts:1007–1009 declares pick overloads for QuickPick inputs; src/vs/platform/quickinput/browser/quickInputController.ts:481–590 unconditionally creates a QuickPick and assigns the supplied array to input.items. It does not construct a QuickTree or traverse IQuickTreeItem.children.
- **QuickTree still exposes checkbox selection:** src/vs/platform/quickinput/common/quickInput.ts:1093–1240 exposes checkedLeafItems and checkbox events but no canSelectMany mode. The checked property's documentation mentions canSelectMany, but that property is absent from IQuickTree and its implementation.
