# Issue #297767 — multi line terminal commands look odd

[https://github.com/microsoft/vscode/issues/297767](https://github.com/microsoft/vscode/issues/297767)

## Summary

The awkward multi-line presentation remains explainable from current source: the simplified terminal header places the raw command, including line breaks, in one inline code element. This team-authored UI-polish report should remain open because no explicitly linked fix or older same-symptom canonical was found.

## Change summary

Make multi-line terminal commands display coherently in simplified Chat terminal-tool headers instead of appearing as disconnected, unevenly indented code fragments.

## Best solution

Define a compact collapsed representation for multi-line commands while keeping the complete command available through the expanded terminal-tool content or another existing detail affordance. Cover completed, running, and narrow-width layouts with component screenshot fixtures.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatTerminalToolProgressPart.css`, `src/vs/workbench/test/browser/componentFixtures/chat/chatWidget.fixture.ts`
- **Validation:** Add completed and running component screenshot fixtures whose terminal command contains newline characters, at standard and narrow widths, and verify the chosen collapsed representation remains coherent while the full command is available from the terminal-tool details.
- **Behavior:**

  > A running or completed terminal tool with a multi-line command must have a compact, readable collapsed header rather than disconnected code fragments with misleading indentation. The complete command must remain discoverable without changing command execution or terminal output. Acceptance should cover completed, running, standard-width, and narrow-width Chat layouts.
- **Trace:**

  > The simplified terminal path starts in `ChatTerminalToolProgressPart._createCollapsibleWrapper` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts. It truncates `displayCommand` by raw character count without handling newlines, then `ChatTerminalThinkingCollapsibleWrapper._setCodeFormattedTitle` assigns that text directly to one inline `<code>` element. The accompanying Chat CSS gives inline code padding/background but defines no presentation for a non-intention multi-line command, matching the fragmented appearance in the report. Existing component fixtures use only a semicolon-separated single-line terminal command. Keep the boundary to terminal-tool header presentation and its fixtures; terminal execution, output rendering, and expansion behavior must not change. The surface originated in https://github.com/microsoft/vscode/pull/296870.
- **Open decisions:**
  - Should a collapsed multi-line command be flattened into one line, represented by its first line with an omission indicator, or retain a deliberately formatted multi-line summary?
  - Where should the complete untruncated command remain available when the collapsed header uses a summary: the expanded content, the existing hover, or both?
