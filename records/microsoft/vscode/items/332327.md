# Issue #332327 — PowerShell hook crashes with empty $PLUGIN_ROOT when a non-primary workspace folder's .github/hooks/*.json is invoked in a multi-root workspace

[https://github.com/microsoft/vscode/issues/332327](https://github.com/microsoft/vscode/issues/332327)

## Summary

Traced the reported flow in current main and it does not reproduce: hook discovery is already scoped to the primary working directory only, so a non-primary folder's `.github/hooks/*.json` is never surfaced to the session and can't hit the PowerShell `Join-Path`/`PLUGIN_ROOT` failure described.

## Change summary

PowerShell hook wrapper crashes with an empty `$PLUGIN_ROOT` when a non-primary workspace folder's repository-level hook is invoked in a multi-root session.

## Best solution

No code change needed on current main — `SessionCustomizationDiscovery.discoverHooks` (src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts) only scans `_hookWorkingDirectories` (primary folder, index 0), and `CopilotAgent.computeFolderPickerDecision` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts:1424-1447) exists specifically to let the user pick which folder's hooks lead when more than one folder has them. If the reporter can still reproduce on the latest build, the next step is to check whether their session's working-directory ordering actually has folder B as index 0/primary.
