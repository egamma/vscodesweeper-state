# Issue #332327 — PowerShell hook crashes with empty $PLUGIN_ROOT when a non-primary workspace folder's .github/hooks/*.json is invoked in a multi-root workspace

[https://github.com/microsoft/vscode/issues/332327](https://github.com/microsoft/vscode/issues/332327)

## Summary

Keep open for a focused Windows retest: current source excludes non-primary hooks from customization discovery, but actual file-hook execution remains runtime-owned, so that exclusion does not establish that the reported failure is fixed. The supplied multi-root steps and PowerShell exception are sufficient to retest without an info-needed timeout.

## Change summary

A session anchored to folder B invokes folder A's repository hook with an empty PLUGIN_ROOT, producing a PowerShell Join-Path error.

## Best solution

Ensure repository-hook execution respects the session's effective primary working directory on both creation and resume, without invoking unrelated folders' hooks. First distinguish runtime file-hook discovery from the host's customization inventory; if the error persists, establish the execution path before choosing the fix.
