# Issue #324509 — Background todo agent experiment silently disables `manage_todo_list`, breaking custom instructions and workflows

[https://github.com/microsoft/vscode/issues/324509](https://github.com/microsoft/vscode/issues/324509)

## Summary

Confirmed in current source: when the `BackgroundTodoAgentEnabled` experiment is active, the `manage_todo_list` tool is silently removed from the main agent's allowed tools (agentIntent.ts line 298–300) with no user-facing notification or graceful degradation. Custom instructions referencing the tool break without explanation. Still present on main with no fix.

## Change summary

The `BackgroundTodoAgentEnabled` experiment silently disables the `manage_todo_list` tool from the main agent, causing custom instructions that reference it to fail with no notification or fallback.

## Best solution

When the background todo agent experiment is active, either keep `manage_todo_list` as an alias/passthrough so the agent doesn't claim the tool doesn't exist, or inject a system-prompt note explaining the tool is now managed in the background. At minimum, log the experiment state to the Copilot output channel so users can diagnose the discrepancy. The fix would touch `extensions/copilot/src/extension/intents/node/agentIntent.ts` (the tool-gating logic around line 298) and possibly the prompt construction in the backgroundTodoAgent directory.
