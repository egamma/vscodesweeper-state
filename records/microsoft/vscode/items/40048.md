# Issue #40048 — Minimap Enhancement: Show Preview Tooltip

[https://github.com/microsoft/vscode/issues/40048](https://github.com/microsoft/vscode/issues/40048)

## Summary

Keep this accepted minimap enhancement open: current settings and hover handling do not provide a readable code preview without scrolling. With 69 upvotes and related requests already consolidated here, it merits a maintainer-led design session rather than a cleanup close.

## Change summary

Show a readable preview of approximately 7–8 nearby source lines when hovering the minimap, without moving the editor viewport.

## Best solution

Provide a lightweight, transient code preview anchored to the hovered minimap location while preserving existing click and drag navigation. Settle activation defaults and whether scrollbar hover is included before implementation; retain this issue as the canonical request.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/minimap/minimap.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** The plan should establish a runnable editor UI check: hover an off-screen minimap location in a long file and verify a readable nearby-line preview appears while scroll position, selection, and focus remain unchanged; move away and verify dismissal. Repeat with left/right minimaps, proportional/fit/fill modes, folding and wrapping, then verify existing click and drag navigation.
- **Behavior:**

  > Hovering a location in the minimap should allow the user to read approximately 7–8 nearby source lines without scrolling away from their current editing position. The preview must correspond to the hovered location and must not change selection or editor focus. Moving away should dismiss the transient preview, and existing minimap click and drag navigation must remain available. Acceptance checks should cover both minimap sides, sizing modes, folded and wrapped content, and file boundaries; activation defaults and scrollbar coverage remain to be decided.
- **Trace:**

  > IEditorMinimapOptions and EditorMinimap in src/vs/editor/common/config/editorOptions.ts expose visibility, sizing, scale, slider and section-header controls but no code-preview capability. InnerMinimap in src/vs/editor/browser/viewParts/minimap/minimap.ts tracks mouse entry and exit, while pointer-down translates canvas coordinates into navigation or dragging. Minimap.getLineContent and revealLineNumber account for sampled minimap lines, so interpreting a hovered location must respect the existing view-line and sampling mappings. The trace establishes the missing capability, not a selected preview architecture or its performance characteristics. Preserve existing navigation, editor state and rendering performance; a public minimap extension API is an alternative requested by the reporter, not a prerequisite for the built-in outcome. Related hover requests were consolidated here, including https://github.com/microsoft/vscode/issues/76586 and https://github.com/microsoft/vscode/issues/84245.
- **Open decisions:**
  - Should code previews appear on ordinary minimap hover by default, or require an explicit opt-in or modifier?
  - Should the initial capability cover only the minimap, or also hovering the scrollbar/overview ruler as requested in the discussion?
