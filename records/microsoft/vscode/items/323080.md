# Issue #323080 — Markdown preview that includes Mermaid diagrams renders the latter in an unreadable fashion when using dark theme

[https://github.com/microsoft/vscode/issues/323080](https://github.com/microsoft/vscode/issues/323080)

## Summary

The attached diagram explicitly selects Mermaid's `base` theme and hardcodes a light palette, overriding VS Code's adaptive Mermaid theme. Preserving those authored colors is expected behavior.

## Change summary

Automatically make Mermaid diagrams with explicitly hardcoded light colors readable in a dark Markdown preview.

## Best solution

Keep honoring diagram-local Mermaid configuration. Authors who want theme adaptation should remove the explicit light `init` directive and use the default `markdown-mermaid.darkModeTheme: "vscode"` behavior.

## Evidence

- **reproduction source:** The attached `test.md` begins with `%%{init: {"theme": "base", "themeVariables": ...}}%%` and explicitly sets `background` to `#ffffff` and multiple text colors to `#111111`, so the unreadable dark-mode result comes from document-authored light colors.
- **current behavior:** `extensions/mermaid-markdown-features/package.json` defaults both `markdown-mermaid.lightModeTheme` and `markdown-mermaid.darkModeTheme` to `vscode`; `preview-src/shared/vsCodeTheme.ts` derives readable colors from the active VS Code theme when that default is used.
- **maintainer precedent:** In https://github.com/microsoft/vscode/issues/271370, the Mermaid maintainer explained that hardcoded diagram colors cannot reliably be corrected by VS Code, distinguishing them from theme-derived colors.
- **adaptive theme implementation:** Commit 80afb57617705c037c65ab9bd2d4c6cb3defa8e3 added the VS Code-derived Mermaid theme for diagrams that do not override it.
