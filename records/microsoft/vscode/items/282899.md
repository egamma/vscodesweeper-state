# Issue #282899 — Fetch should get images from GitHub issues for better context

[https://github.com/microsoft/vscode/issues/282899](https://github.com/microsoft/vscode/issues/282899)

## Summary

Keep open: current fetch preserves image references or alt text, but does not supply embedded GitHub issue images as visual model context. This team-authored Backlog request remains valid; no verified canonical or fixing commit was found.

## Change summary

Include downloaded GitHub issue images alongside their surrounding fetched text so agents can understand visual context.

## Best solution

Provide multimodal fetch results that preserve the association between issue text and embedded images. Settle how image context survives query-based chunk selection and token budgeting, while preserving existing network approval and filtering behavior.

Cover query pruning, text-only models, failed image downloads, and existing network restrictions in extractor and fetch-tool tests; no checks were executed during this read-only review.
- **Behavior:**

  > Fetching a GitHub issue whose screenshot contains essential information should provide that image as visual model context, not merely an image URL or alt text. The result should preserve which surrounding text the image explains. Acceptance should cover an image-capable model, query-based content selection, and unchanged text-only fetching. The plan must define observable fallback behavior when images cannot be included.
- **Trace:**

  > WebPageLoader.extractAccessibilityTreeContent calls convertAXTreeToMarkdown in src/vs/platform/webContentExtractor/electron-main/cdpAccessibilityDomain.ts, whose image branch produces a URL reference or placeholder rather than image data. WebContentExtractResult in src/vs/platform/webContentExtractor/common/webContentExtractor.ts exposes successful content as a string. The internal FetchWebPageTool passes web extraction results onward and separately supports local image data. The Copilot wrapper in extensions/copilot/src/extension/tools/vscode-node/fetchWebPageTool.tsx assumes one content part per input URL, chunks text through UrlChunkEmbeddingsIndex, and renders image data separately when available; inline multimodal webpage context is not represented by this flow. Preserve existing URL approval, network filtering, text fetching, and local-image behavior. The historical discussion at https://github.com/microsoft/vscode-copilot/issues/15263#issuecomment-2764567151 leaves query/image selection unresolved; it was migrated to https://github.com/microsoft/vscode/issues/282899 rather than completed.
- **Open decisions:**
  - When a query selects only some webpage chunks, should images be included only with retained surrounding text, or should all issue-content images remain available independently?
  - What user-observable image count or size limits and fallback behavior should apply when an image cannot fit the model budget or the selected model does not support images?
