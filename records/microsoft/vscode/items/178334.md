# Issue #178334 — Weird code indentation C++

[https://github.com/microsoft/vscode/issues/178334](https://github.com/microsoft/vscode/issues/178334)

## Summary

The reported extra indentation remains traceable in current source: Enter uses the continued parameter line's indentation rather than the function's scope. Keep this maintainer-confirmed issue open; the related reports examined do not establish an older canonical with the same observable symptom.

## Change summary

Pressing Enter after a C++ function's opening brace incorrectly carries parameter-continuation indentation into the body and closing brace.

## Best solution

Make Enter indentation distinguish a continued function signature from its enclosing scope, producing a four-space body and an unindented closing brace in the supplied example. Plan the scope-context boundary in the shared editor indentation pipeline while preserving existing language-specific Enter rules.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages/enterAction.ts`, `src/vs/editor/common/languages/supports/onEnter.ts`, `src/vs/editor/common/languages/languageConfigurationRegistry.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `extensions/cpp/language-configuration.json`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add focused editor-controller regression cases using the supplied C++ signature with four-space indentation. Typing Enter between {} must produce an eight-column-free, four-space body line with the caret there and a zero-indent closing brace; typing Enter after the opening brace with an existing body must likewise insert only four spaces. Both cases must fail before the change and pass afterward, alongside existing Enter indentation cases.
- **Behavior:**

  > For the supplied C++ function declaration split across two lines, continuation indentation must not become the function body's base indentation. With four-space indentation, Enter between the opening and closing braces must place the caret four spaces into the body and place the closing brace at column one. Enter immediately after the opening brace when a body already exists must also insert a four-space body line. Ordinary single-line declarations and existing language-specific Enter behavior must remain unchanged.
- **Trace:**

  > The C++ configuration in extensions/cpp/language-configuration.json declares {} brackets but has no matching custom Enter rule for this signature. OnEnterSupport.onEnter selects IndentOutdent between the braces or Indent after the opening brace. getEnterAction in src/vs/editor/common/languages/enterAction.ts obtains the current line's four leading spaces from getIndentationAtPosition, and EnterOperation._enter preserves that base while adding another indentation level. This conclusively explains both reported outcomes without running the editor. The trace establishes the whitespace error but not a robust way to recover the declaration's scope across C++ syntax and other language consumers; the plan must establish that boundary before implementation. Preserve unrelated Enter rules and avoid treating disabling auto-indent or invoking a formatter as resolution. The maintainer's scope-awareness direction is recorded at https://github.com/microsoft/vscode/issues/178334#issuecomment-2107053229.
