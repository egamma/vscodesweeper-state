# Issue #347146 — Running 'python' in pwsh shell doesn't change the terminal tab title to be 'python'

[https://github.com/microsoft/vscode/issues/347146](https://github.com/microsoft/vscode/issues/347146)

## Summary

Keep open: the Python-from-PowerShell case remains unconfirmed, but current source lacks the Windows process monitoring used by regular terminals. The report's steps and Node/cmd comparisons suffice to retest the recently changed agent-host terminal path.

## Change summary

Running Python interactively from PowerShell in the Windows Agents window should update the terminal tab title from pwsh to python.

## Best solution

Make agent-host terminal titles reflect the running Python interpreter on Windows while preserving working Node/cmd behavior, explicit terminal names, and title restoration after the interpreter exits. First reproduce the shell-specific difference and distinguish process-derived titles from application-emitted title sequences.

- **Behavior:**

  > In a Windows Agents-window PowerShell terminal, entering the Python REPL should display python as the terminal title rather than pwsh. Leaving the REPL should restore the shell title. Existing Node and cmd cases and explicitly named terminals must remain unchanged. The supplied report is sufficient for the initial manual reproduction.
- **Trace:**

  > AgentHostTerminalManager initializes titles from the shell and polls ptyProcess.process only on non-Windows platforms in src/vs/platform/agentHost/node/agentHostTerminalManager.ts. Regular TerminalProcess instead connects WindowsShellHelper process-tree observations to process-title properties. AgentHostPty forwards host title changes, while TerminalInstance also accepts application-emitted title sequences, so the exact reason Node/cmd work and Python/pwsh does not remains unconfirmed. Compare those inputs on Windows before attributing the entire symptom to the missing monitor. Preserve non-Windows behavior, explicit names, and conforming hosts' advertised titles; do not introduce client-side assumptions about remote process trees. The intended process-title behavior is documented in https://github.com/microsoft/vscode/issues/346374 and its preceding implementation https://github.com/microsoft/vscode/pull/345387.
