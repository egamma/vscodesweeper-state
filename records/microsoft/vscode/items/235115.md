# Issue #235115 — Copilot Chat - attached code block hover feedback

[https://github.com/microsoft/vscode/issues/235115](https://github.com/microsoft/vscode/issues/235115)

## Summary

This team-authored Backlog item should remain open. Current main still renders pasted-code previews from a plain Markdown string without a file icon or explicit truncation state, and it inserts an extra blank line before the code.

## Change summary

Polish pasted-code attachment hovers with a file-type icon, balanced header and body layout, regular-weight filenames, trimmed leading whitespace, and an explicit incomplete-preview indicator.

## Best solution

Give pasted-code attachments a consistent hover in both the chat input and rendered request history: a calm file header with the appropriate decorative file icon and regular filename, consistently spaced code content without an artificial leading blank line, and an accessible indication whenever the preview omits content.

- **Behavior:**

  > Hovering a pasted-code attachment shows a clearly structured file header and code preview in both the chat input and request history. The filename uses regular emphasis, the file-type icon supports identification without duplicating screen-reader output, and the code body has consistent breathing room with no artificial leading blank line. If the preview omits code, it communicates that state visibly and accessibly. Short previews remain complete and do not show a truncation indication.
- **Trace:**

  > PasteAttachmentWidget in src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts constructs the attachment label and hover used by input and history rendering. The attachment pill receives language-specific file icon classes at lines 781-792, while the hover at lines 797-802 is a plain MarkdownString with no icon or truncation metadata and an extra blank line after the opening fence. ChatAttachmentsContentPart routes paste entries to this widget, so the behavior is shared across rendered attachment surfaces. Keep paste serialization, copied-source navigation, deletion behavior, and non-paste attachment hovers unchanged. The uncertainty starts at the large-preview contract: the issue requests an incomplete-content indicator but does not settle whether long previews should clip, scroll, or offer expansion.
- **Open decisions:**
  - For oversized pasted-code previews, should the hover show a clipped excerpt with an accessible ellipsis/expansion affordance, or preserve the full code in a scrollable hover while indicating that more content is off-screen?
