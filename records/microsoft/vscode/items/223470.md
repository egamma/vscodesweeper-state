# Issue #223470 — Scroll momentum transferred between different scrollables

[https://github.com/microsoft/vscode/issues/223470](https://github.com/microsoft/vscode/issues/223470)

## Summary

This remains a valid cross-cutting scrolling bug: momentum wheel events can reach a different ScrollableElement after the pointer moves, and horizontally scrolling surfaces then reinterpret the residual vertical delta. The current source still contains this path, and a maintainer confirmed that the problem affects more than tabs.

## Change summary

Keep an active momentum-scroll gesture from transferring to another scrollable surface when the pointer moves.

## Best solution

Momentum from one physical gesture should remain associated with its originating scrollable until that gesture ends, while a genuinely new gesture over another surface must continue to scroll it normally. This belongs in the shared ScrollableElement behavior rather than a tabs-only workaround.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`
- **Validation:** On macOS with a Magic Mouse, start a high-momentum vertical scroll in a long editor and move the pointer over an overflowing tab bar before momentum ends: the tab bar must remain stationary. After momentum ends, a new vertical gesture over the tab bar must still scroll it horizontally; repeat against another pair of ScrollableElement surfaces.
- **Behavior:**

  > Momentum generated while scrolling one surface must not begin scrolling a different surface merely because the pointer moves over it before the gesture decays. This must hold for the editor-to-tab-bar scenario and other ScrollableElement pairs. A new, intentional gesture over the second surface must continue to work, including vertical-to-horizontal scrolling in the tab bar.
- **Trace:**

  > Each ScrollableElement installs its own wheel listener in src/vs/base/browser/ui/scrollbar/scrollableElement.ts and _onMouseWheel applies every event delivered to that element. MouseWheelClassifier is global but only distinguishes physical wheels from touch-style devices; it does not identify gesture boundaries or remember the originating element. MultiEditorTabsControl.createTabsScrollbar in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts enables scrollYToX, so residual vertical momentum reaching the tabs is converted into horizontal movement. The issue video and maintainer confirmation establish the observable behavior, while the uncertainty begins at how to distinguish momentum continuation from a new gesture using the event information available on supported platforms. Preserve intentional scrolling, nested-scroll propagation, smooth scrolling, and existing wheel sensitivity behavior.
- **Open decisions:**
  - Which event characteristics reliably delimit a Magic Mouse or trackpad gesture across supported browsers and operating systems?
  - Should gesture ownership be coordinated globally among ScrollableElement instances or only suppress continuation when the axis-conversion behavior changes?
  - How should nested scrollables and boundary propagation behave while an existing momentum gesture is still active?

## Evidence

- **maintainer confirmation:** A VS Code maintainer confirmed that the behavior occurs across all ScrollableElement instances, not only tabs: https://github.com/microsoft/vscode/issues/223470#issuecomment-2331847079
- **current source path:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts registers a wheel listener per element and immediately applies every received delta in ScrollableElement._onMouseWheel; MouseWheelClassifier classifies the device but does not retain gesture ownership across elements.
- **tab conversion:** src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts creates the tabs ScrollableElement with scrollYToX enabled, while ScrollableElement._onMouseWheel converts an incoming vertical delta to horizontal movement. Residual momentum delivered after the pointer reaches the tabs therefore produces the reported tab-bar movement.
