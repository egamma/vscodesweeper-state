# Issue #223470 — Scroll momentum transferred between different scrollables

[https://github.com/microsoft/vscode/issues/223470](https://github.com/microsoft/vscode/issues/223470)

## Summary

Still reproduces on main: macOS delivers momentum wheel events to whichever element is under the cursor, and VS Code's scrollable elements have no mechanism to reject momentum events that originated from a different scrollable. No fix has landed.

## Change summary

On macOS with a Magic Mouse, scroll momentum from one scrollable (e.g. the editor) transfers to another (e.g. tab bar) when the cursor moves, causing unintended horizontal tab scrolling.

## Best solution

Add momentum-phase awareness to the scrollable element's wheel handler: track which scrollable element initiated the scroll gesture and ignore momentum-phase wheel events that arrive on a different scrollable. The fix would live in `src/vs/base/browser/ui/scrollbar/scrollableElement.ts` — potentially using a shared sentinel or timestamp to detect cross-element momentum transfer. As the team member comment confirms, this affects all scrollable elements, not just tabs.
