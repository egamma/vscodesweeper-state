# Issue #223470 — Scroll momentum transferred between different scrollables

[https://github.com/microsoft/vscode/issues/223470](https://github.com/microsoft/vscode/issues/223470)

## Summary

Keep open and classify as upstream: Chromium retargets inertial wheel events as the pointer moves, while VS Code's independent scrollable listeners consume those events at the new target. The current source still exposes this behavior, and no open canonical issue or merged fix was found.

## Change summary

Prevent momentum from a scroll gesture started in one scrollable from moving another scrollable after the pointer crosses into it.

## Best solution

Chromium should keep inertial wheel events associated with the scrollable where the gesture began. If an upstream change is unavailable, any VS Code mitigation should operate centrally across ScrollableElement instances rather than special-casing editor tabs.

## Evidence

- **confirmed platform behavior:** In the substantially identical https://github.com/microsoft/vscode/issues/34547, a VS Code maintainer reproduced the problem on macOS with a Magic Mouse and identified Chromium's delivery of continuing inertial scroll events over newly hovered UI elements as the cause: https://github.com/microsoft/vscode/issues/34547#issuecomment-330903153.
- **current source path:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts registers a wheel listener independently on each scrollable and _onMouseWheel applies every received delta to that instance; there is no cross-instance gesture-origin tracking.
- **tab manifestation:** src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts creates the tab ScrollableElement with scrollYToX enabled, so a retargeted vertical momentum event becomes horizontal tab movement.
- **existing inertia detection:** MouseWheelClassifier in src/vs/base/browser/ui/scrollbar/scrollableElement.ts can recognize Magic Mouse or trackpad-like input, and src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts includes Apple Magic Mouse event samples, but the classifier does not retain or enforce a gesture's originating scrollable.
- **prior report is not canonical:** https://github.com/microsoft/vscode/issues/34547 is closed; its 2017 closure was backlog cleanup based on roadmap timing rather than a fix or an enduring as-designed decision, so it cannot serve as a duplicate target.
