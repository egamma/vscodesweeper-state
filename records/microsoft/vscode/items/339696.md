# Issue #339696 — Agents - I can only select a synthesizer model if I select a judge model

[https://github.com/microsoft/vscode/issues/339696](https://github.com/microsoft/vscode/issues/339696)

## Summary

Team-authored test feedback (0 days old) on the still-in-testing session comparison feature (tracked by #339373). Traced the code: `SessionComparisonModelSelection` in sessionComparisonModelSelection.ts intentionally gates the 'synthesizer' step behind a selected judge (`canGoNext` requires `judge !== undefined` to leave the 'judge' step), so the UI can't currently reach synthesizer selection without picking a judge first — matching what the reporter observed. Whether that coupling is intended (synthesis described as happening "after review") or should be relaxed is a product decision, so this stays open pending maintainer input.

## Change summary

In the Agents window model-comparison picker, the synthesizer model can only be selected if a judge model has also been selected — reporter expected to be able to pick a synthesizer independently.

## Best solution

A maintainer should decide whether synthesis should be allowed without a judge model (decoupling the two in SessionComparisonModelSelection.state/next()), or whether the current judge-gates-synthesizer flow is intentional and just needs clearer copy/UI affordance.
