# Issue #293076 — File decorator colors do not display on a fresh install

[https://github.com/microsoft/vscode/issues/293076](https://github.com/microsoft/vscode/issues/293076)

Keep open: the report supplies sufficient steps to retest first-launch decoration colors, with additional corroboration for newly opened folders. Decoration styling has changed since the report, but inspection establishes neither a current reproduction nor a fixing commit.

## Change summary

Explorer file-decoration colors are missing on first launch with fresh storage and a new profile, then appear after changing themes or reloading.

## Plan brief

- **Likely files:** `src/vs/workbench/services/decorations/browser/decorationsService.ts`, `src/vs/workbench/browser/labels.ts`, `src/vs/workbench/services/themes/browser/workbenchThemeService.ts`, `src/vs/workbench/services/themes/browser/colorThemeCss.ts`
- **Validation:** Using disposable user data and a fresh profile on Windows, open a Git repository with a modified tracked file. Before any theme change or reload, verify the Explorer label uses its Git decoration color; compare with the same file after switching themes and reloading. Repeat with an already initialized profile and with decoration colors explicitly disabled.
- **Behavior:**

  > With decoration colors enabled, opening a Git repository in a fresh profile should display the expected modified-file colors on the initial launch. Changing themes or reloading should not be necessary to activate those colors. Validate the first-launch case against subsequent launches, and preserve the behavior of explicitly disabling decoration colors.
- **Trace:**

  > Explorer resource labels apply decoration color classes in src/vs/workbench/browser/labels.ts, while DecorationRule in src/vs/workbench/services/decorations/browser/decorationsService.ts generates CSS using theme color variables. WorkbenchThemeService initially applies stored or default theme data and later initializes themes asynchronously; generateColorThemeCSS emits the registered color variables. Inspection did not establish whether the missing color originates in variable publication, decoration availability, or rendering order, so reproduction is the first diagnosis step. Preserve provider semantics, configured color-disable behavior, and ordinary theme switching. https://github.com/microsoft/vscode/issues/337786 offers a related trust-transition scenario, but a shared root cause is not established and that newer issue is not a duplicate canonical.
