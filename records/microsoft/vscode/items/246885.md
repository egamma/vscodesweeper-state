- **Independent confirmations:** The discussion at https://github.com/microsoft/vscode/issues/246885 includes multiple confirmations of accumulating installations; the August 2026 report identifies .vscode-server/cli/servers, approximately 27 GB of unused servers, disk exhaustion, and a nightly deletion workaround. These are historical user confirmations, not an executed current-main reproduction.
- **Existing automatic retention:** cli/src/download_cache.rs defines KEEP_LRU = 5 and DownloadCache::touch attempts to delete the least-recently-used tracked entry. cli/src/state.rs constructs server_cache under root/servers, and cli/src/tunnels/code_server.rs routes its setup through server_cache.create. Automatic retention therefore already exists for this CLI installation path, but that does not prove Remote-SSH installs participate correctly or that all accumulated directories are tracked.
- **Existing manual cleanup:** cli/src/commands/tunnels.rs exposes explicit pruning, and cli/src/tunnels/paths.rs provides prune_stopped_servers, which excludes running servers. These manual mechanisms do not satisfy the report's requirement for reliable automatic cleanup after Remote-SSH updates.

It is not an open canonical and supplies no fixing commit.

It is relevant cleanup work, but the different connection type does not establish an identical installation defect.
