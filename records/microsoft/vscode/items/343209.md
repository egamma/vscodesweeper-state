# Issue #343209 — Pinned tasks are not retained in a newly created workspace

[https://github.com/microsoft/vscode/issues/343209](https://github.com/microsoft/vscode/issues/343209)

## Summary

Keep open: current source exposes both a workspace-storage preservation gap and presentation-dependent task pin matching that can explain pins disappearing during workspace conversion. The reporter also confirmed persistence on the latest stable release after the upgrade request.

## Change summary

Retain pinned tasks when saving a workspace under a new identity or converting a folder into a multi-root workspace.

## Best solution

Preserve task pins through workspace transitions and continue recognizing the same tasks when their displayed folder qualification changes. Investigate storage migration and pin identity together so fixing one does not leave the other failure intact.

- **Storage preservation gap:** NativeWorkspaceEditingService.enterWorkspace in src/vs/workbench/services/workspaces/electron-browser/workspaceEditingService.ts explicitly calls storageService.switch(result.workspace, true) to preserve data. RemoteStorageService.switchToWorkspace in src/vs/platform/storage/common/storageService.ts accepts preserveData but closes the old storage and initializes the destination without copying its entries; AbstractStorageService.switchData in src/vs/platform/storage/common/storage.ts only emits change notifications.
- **Pin identity changes during folder conversion:** TaskQuickPick._createTaskEntry supplies label, description and detail without an id. quickPickPin.ts matches these presentation fields, including description. AbstractTaskService.needsFolderQualification and getTaskDescription in src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts change ordinary folder-task descriptions from undefined to the folder name when entering a multi-root workspace, preventing previously stored pins from matching even if their storage survives.
