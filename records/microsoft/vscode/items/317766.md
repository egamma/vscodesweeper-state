# Issue #317766 — git-commit editor syntax highlighting should respect git.inputValidationSubjectLength

[https://github.com/microsoft/vscode/issues/317766](https://github.com/microsoft/vscode/issues/317766)

## Summary

The requested configuration-aware commit-editor highlighting is still missing on current main. Keep the request open and route it to Git; the existing SCM validation regression does not cover this editor behavior.

## Change summary

Make commit-message editor length highlighting honor the configured subject limit instead of fixed 50/72-character boundaries.

## Best solution

Provide consistent, configuration-aware length feedback between the SCM input and COMMIT_EDITMSG editor while preserving other Git syntax highlighting. The Git owner should settle the editor warning/error boundaries and optional body-line behavior before implementation.

These thresholds are static and do not reference configuration.
- **Existing capability does not cover the request:** GitCommitInputBoxDiagnosticsManager in extensions/git/src/diagnostics.ts reads git.inputValidationSubjectLength and git.inputValidationLength, but its text-change listener accepts only vscode-scm documents. extensions/git-base/package.json registers the static grammar for COMMIT_EDITMSG and MERGE_MSG; extensions/git-base/src/extension.ts registers folding, not configuration-aware length highlighting.
- **Partial workaround:** extensions/git/package.json supplies [git-commit] editor.rulers defaults of 50 and 72. Customizing editor.rulers changes visual guides, not the grammar's warning/error scopes, so it does not satisfy the central ask. git.inputValidationLength already supplies a separate non-subject threshold for SCM diagnostics.
