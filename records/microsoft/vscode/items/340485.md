# Issue #340485 — autoDetectColorScheme doesn't follow live OS theme changes on Linux/KDE Wayland: bundled Electron's nativeTheme.shouldUseDarkColors stays stale

[https://github.com/microsoft/vscode/issues/340485](https://github.com/microsoft/vscode/issues/340485)

## Summary

Thorough, well-diagnosed report: VS Code's main-process theme service reads electron.nativeTheme.shouldUseDarkColors as expected (themeMainServiceImpl.ts), but the reporter shows the bundled Electron binary fails to update that value on KDE/Wayland while a vanilla Electron build of the identical version does — pointing at something specific to how VS Code's Electron is built/packaged rather than at VS Code's own TypeScript. No fix exists on main for this file, and the true root cause likely isn't even visible in this source tree.

## Change summary

window.autoDetectColorScheme doesn't react to live OS dark/light switches on Linux KDE Wayland because the bundled Electron's nativeTheme.shouldUseDarkColors never updates after startup, even though upstream Electron of the same version does.

## Best solution

Needs someone with access to VS Code's Electron build/packaging pipeline to compare against vanilla Electron and find what differs (GN build flags, GTK/portal watcher wiring, etc.) — this isn't fixable purely from src/vs/platform/theme/electron-main/themeMainServiceImpl.ts, which just consumes nativeTheme as-is.
