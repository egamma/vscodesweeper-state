## Evidence

- **Runtime isolation:** https://github.com/microsoft/vscode/issues/340485 reports that the same minimal nativeTheme app receives updated events but stale shouldUseDarkColors values under VS Code's binary, while Arch electron43 of the same version follows transitions. This isolates the failure below the workbench, although it does not establish which build or upstream change causes it.
- **Independent confirmation:** The supplied 2026-10-31 comment on https://github.com/microsoft/vscode/issues/340485 confirms failed live switching on Fedora/GNOME Wayland with correctly emitted portal transitions. Renderer media queries briefly change and revert, and another Electron application exhibits the behavior, supporting an Electron-level problem rather than a KDE-only defect.
- **Current main event path:** src/vs/platform/theme/electron-main/themeMainServiceImpl.ts:98-101 forwards every nativeTheme updated event through getColorScheme(); lines 115-117 retain themeSource='system' on Linux, and lines 165-168 read dark directly from nativeTheme.shouldUseDarkColors. Stale native values therefore propagate through the existing live-update path.
- **Workbench boundary:** src/vs/workbench/services/themes/electron-browser/nativeHostColorSchemeService.ts subscribes to native color-scheme events and emits changes only when dark or highContrast differs. src/vs/workbench/services/themes/browser/workbenchThemeService.ts:453-462 restores the preferred theme on those changes. These paths explain why an unchanged runtime value prevents switching; source inspection cannot reproduce the native runtime defect.
- **Related reports, not verified canonicals:** https://github.com/microsoft/vscode/issues/179431 describes missing live theme switching on KDE/X11; https://github.com/microsoft/vscode/issues/187280 describes inverted runtime theme switching on KDE/Wayland. Their bodies were inspected, but current open status and ownership of this binary-specific failure were not verified, so neither supports a duplicate close under the re-review rules.
