# Issue #326962 — Bug / UX Flaw: workbench.action.openAgentsWindow breaks default text editing binding (Toggle Block Comment)

[https://github.com/microsoft/vscode/issues/326962](https://github.com/microsoft/vscode/issues/326962)

## Summary

Confirmed via source: the default Linux Ctrl+Shift+A binding for 'Toggle Block Comment' is shadowed by the Agents Window command's own Ctrl+Shift+A binding, which outranks it via KeybindingWeight and has no editorTextFocus exclusion — still present on current main. Keeping open since the fix is a keybinding-design call (chord vs when-clause guard) for a maintainer, not a mechanical patch.

## Change summary

workbench.action.openAgentsWindow's Ctrl+Shift+A keybinding overrides editor.action.blockComment's identical default Linux binding because it has no editorTextFocus guard and a higher registration weight.

## Best solution

A maintainer should decide between the reporter's two options in src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts (lines ~140-152): add a negated EditorContextKeys.editorTextFocus (or similar) to the `when` clause so it yields to editor commands, or move Open Agents Window to a chord (e.g. Ctrl+K Ctrl+A) consistent with how other secondary panels are bound.
