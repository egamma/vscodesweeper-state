# Issue #134336 — Restore all windows when closing them all at once

[https://github.com/microsoft/vscode/issues/134336](https://github.com/microsoft/vscode/issues/134336)

## Summary

Keep open: current source still distinguishes OS-level closing of all windows from application exit, leaving the requested session-restoration gap. This issue already owns the work, with two later reports explicitly directed here by the area maintainer.

## Change summary

Restore the complete previous window session after using the Linux or Windows shell action to close all VS Code windows.

## Best solution

Make OS-level close-all preserve the same restorable window session as File > Exit while retaining ordinary single-window close semantics. Establish whether Electron exposes a reliable distinction before choosing the integration approach.

## Plan brief

- **Likely files:** `src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts`, `src/vs/platform/windows/electron-main/windowsStateHandler.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`
- **Validation:** On Linux/GNOME and Windows, open two distinct folder windows with identifiable editor state, set window.restoreWindows to all, invoke the shell's close-all action, and relaunch without arguments: both windows and their editor state should return. Compare with File > Exit, and verify that individually closing one window before exiting does not unexpectedly restore that discarded window.
- **Behavior:**

  > Using the operating system's close-all action should preserve the complete VS Code window session for restoration, rather than reopening only the last window. With window.restoreWindows set to all, reopening without arguments should restore both folder windows and their editor state, matching File > Exit. Explicitly closing an individual window must retain its existing semantics, and other restoreWindows modes must remain respected.
- **Trace:**

  > LifecycleMainService.registerWindow treats native close events as UnloadReason.CLOSE; application quit is recognized separately through before-quit. WindowsStateHandler documents the close-all event order on Linux and Windows and saves only windows still present at shutdown, with a separate lastClosedState fallback. WindowsMainService.doGetPathsFromLastSession consumes that persisted state, so the existing all and preserve settings do not reconstruct the discarded session. The unresolved boundary is whether current Electron or native platform integration can reliably distinguish shell close-all from independent individual closes; the source trace alone does not establish such a signal. Preserve individual-close behavior, shutdown vetoes, and macOS quit semantics. Maintainer discussion in https://github.com/microsoft/vscode/issues/134336 identifies the event distinction as the obstacle, and https://github.com/microsoft/vscode/issues/183629#issuecomment-1572424241 confirms this issue owns the requested behavior.
