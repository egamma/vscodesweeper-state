# Issue #331266 — "Copilot CLI" can still show when session migration is enabled

[https://github.com/microsoft/vscode/issues/331266](https://github.com/microsoft/vscode/issues/331266)

## Summary

Team-authored bug report (roblourens) describing a real race condition between legacy Copilot CLI session discovery and Agent Host migration; filed hours ago with no fix yet, so it stays open regardless of how clear the diagnosis is.

## Change summary

When session migration is enabled, legacy `copilotcli:` sessions can still be opened and shown as open even after (or during) their Agent Host twin's migration, because `getSessions()` only dedupes once the Agent Host entry exists and open legacy sessions aren't redirected when the twin arrives.

## Best solution

In the sessions provider layer (likely `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts` and the chat sessions provider dedupe logic referenced by `chatSessionsService.ts`), suppress migration-eligible legacy `copilotcli:` rows before Agent Host discovery completes and route explicit opens of legacy URIs through a migration-aware resolution path rather than the raw extension-host provider.
