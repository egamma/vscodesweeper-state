# Issue #240067 — Git - Fixed alignment-column for git 'inline blame' annotations, regardless of line-length

[https://github.com/microsoft/vscode/issues/240067](https://github.com/microsoft/vscode/issues/240067)

## Summary

Keep open: built-in Git blame still follows line length, and no existing setting provides the requested minimum alignment column. The related annotation-gutter proposal is newer and does not satisfy the duplicate bar for this re-reviewed issue.

## Change summary

Allow inline Git blame annotations to begin at a consistent configurable column when the active line is shorter than that column.

## Best solution

Provide an optional minimum-column alignment mode for built-in Git blame, retaining line-relative placement by default and keeping annotations after code on longer lines. Resolve the column and wrapping semantics before implementation; a general right-side gutter API is related but not required by this request.

## Plan brief

- **Likely files:** `extensions/git/src/blame.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`
- **Validation:** In an Extension Development Host with git.blame.editorDecoration.enabled enabled, move the cursor between committed lines shorter than the selected alignment column and verify annotations share that starting column. Check a longer line, tabs, word wrap, horizontal scrolling, and an unset alignment option; annotations must not overlap code or alter document text, and the existing default placement must remain unchanged.
- **Behavior:**

  > Inline Git blame currently shifts horizontally as the active line changes length. The requested optional mode gives annotations a common minimum starting column for shorter lines while allowing them to follow code on longer lines. Acceptance should cover short and long lines, tabs, wrapping, and narrow editor widths without changing document contents. Existing behavior remains available when the option is unset.
- **Trace:**

  > In extensions/git/src/blame.ts, getEditorDecorationRange anchors annotations at the line end, and GitBlameEditorDecoration._createDecoration supplies an after decoration with a constant 50px margin. _onDidChangeConfiguration reads the metadata template and hover controls but no alignment setting; extensions/git/package.json and package.nls.json likewise expose no positioning option. This establishes the missing capability from source without executing the editor. Keep blame computation, template formatting, hover behavior, and status-bar presentation outside the scope. https://github.com/microsoft/vscode/issues/336057 proposes a related general annotation gutter API, but neither settles this request's semantics nor serves as its canonical. The remaining product uncertainty is how a configured column maps to displayed text and wrapped lines.
- **Open decisions:**
  - Does the alignment value represent a rendered editor column accounting for tab expansion and character width, or a fixed visual offset measured in editor character cells?
  - With word wrap enabled, should blame remain after the final wrapped segment and align within that visual line, or use another explicitly defined placement?
