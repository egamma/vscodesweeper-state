# Issue #327986 — Inline suggestions suppress the suggest widget entirely: no completion request is ever sent while typing

[https://github.com/microsoft/vscode/issues/327986](https://github.com/microsoft/vscode/issues/327986)

## Summary

Traced in source: the behavior is the documented contract of editor.quickSuggestions.other's default value ('offWhenInlineCompletions'), not a bug in editor.inlineSuggest.suppressSuggestions (which the reporter checked). Closing as as-designed with an explanation of the actual controlling setting.

## Change summary

With an inline-completions provider active (e.g. Copilot), the suggest widget never triggers while ghost text is showing, and no completion request is ever sent.

## Best solution

Keep the current default (avoids showing ghost text and the suggest widget stacked on top of each other), and clarify in docs/settings description that editor.quickSuggestions.other (not editor.inlineSuggest.suppressSuggestions) is what governs this trade-off; users who want both can set quickSuggestions.other to "on".

- **Proposed comment:**

  > Thanks for the very thorough investigation here. What you're seeing is intentional, but it's governed by a different setting than the one you checked.
  > 
  > `editor.inlineSuggest.suppressSuggestions` isn't the relevant switch — the actual control is `editor.quickSuggestions.other`, whose default value is `"offWhenInlineCompletions"` (not `"on"`), see src/vs/editor/common/config/editorOptions.ts. As the setting's own description says, this disables the suggest widget while inline completions (ghost text) are showing, to avoid stacking both UIs. The suppression happens in `_waitForInlineCompletionsAndTrigger` in suggestModel.ts: if ghost text is already visible when a new quick-suggest trigger would fire, it bails out before ever asking the language server for completions — which matches your tsserver log evidence exactly.
  > 
  > Setting `"editor.quickSuggestions": { "other": "on" }` (as confirmed by another commenter) restores the suggest widget alongside inline completions. Closing as as-designed, but this does highlight that the setting naming/documentation could be clearer about which option actually controls this interaction.
