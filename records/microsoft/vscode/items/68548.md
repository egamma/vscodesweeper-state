# Issue #68548 — [html] [custom data] allow to give custom HTML tags/attributes a higher completion rank

[https://github.com/microsoft/vscode/issues/68548](https://github.com/microsoft/vscode/issues/68548)

## Summary

A real capability gap remains: HTML custom data still cannot influence completion ranking or visually distinguish custom entries. The request should stay open for design because it has a direct CSS precedent but unresolved HTML API and presentation semantics.

## Change summary

Allow custom HTML data providers to rank custom tags and attributes above standard completions and optionally identify them visually.

## Best solution

Extend the HTML custom-data contract in vscode-html-languageservice with relevance metadata modeled on CSS custom data, apply it through completion `sortText`, and decide whether custom entries also receive a stable visual marker before updating VS Code's language-service dependency.

## Plan brief

- **Likely files:** `extensions/html-language-features/server/package.json`, `extensions/html-language-features/server/package-lock.json`, `extensions/html-language-features/server/src/customData.ts`
- **Validation:** Add vscode-html-languageservice completion tests asserting that higher-relevance custom tags and attributes sort ahead of lower-relevance and built-in entries without changing insertion text, then run the targeted HTML language-service completion suite and VS Code HTML language-feature server tests after the dependency update.
- **Behavior:**

  > HTML custom-data authors can declare that selected custom tags and attributes are more relevant than ordinary entries. Completion ordering honors that metadata while preserving the labels, filtering, and insertion behavior of both custom and built-in completions. If custom entries are visually identified, the indicator must not become part of the inserted tag or attribute name.
- **Trace:**

  > The current vscode-html-languageservice custom-data schema and `ITagData`/`IAttributeData` contracts contain no relevance metadata, and `src/services/htmlCompletion.ts` creates tag and attribute completion items without `sortText`. CSS custom data established a numeric relevance precedent in https://github.com/microsoft/vscode-css-languageservice/commit/2588430083334cdd161ab9ac60d4997abc175341. VS Code consumes the published HTML language service through `extensions/html-language-features/server/package.json`; its `src/customData.ts` forwards tag and attribute objects to `newHTMLDataProvider`. The boundary is completion ranking and identification only: do not remove standard HTML suggestions, change fuzzy filtering, or alter inserted names. The related https://github.com/microsoft/vscode/issues/62976 is completed foundational work, not a duplicate owner.
- **Open decisions:**
  - Should HTML adopt CSS custom data's numeric relevance range and default semantics exactly, or expose a simpler custom-versus-built-in priority contract?
  - Should custom entries receive a visible marker in addition to ranking, and if so which completion-item presentation field should carry it without changing filtering or insertion?

## Evidence

- **current source gap:** At vscode-html-languageservice commit fcdf373c4c30579f668bf9198270573ede893497, `src/htmlLanguageTypes.ts` exposes no relevance field on `ITagData` or `IAttributeData`, and `src/services/htmlCompletion.ts` emits tag and attribute completion items without `sortText`.
- **schema gap:** The current https://github.com/microsoft/vscode-html-languageservice/blob/main/docs/customData.schema.json defines tag and attribute metadata but no relevance or priority property.
- **existing precedent:** https://github.com/microsoft/vscode-css-languageservice/commit/2588430083334cdd161ab9ac60d4997abc175341 added numeric relevance metadata and mapped it to completion `sortText` for CSS custom data; the VS Code team member commenting on this issue cited that implementation.
- **VS Code integration:** `extensions/html-language-features/server/package.json` consumes `vscode-html-languageservice`, while `extensions/html-language-features/server/src/customData.ts` passes custom tag and attribute objects into its data provider. Shipping the capability therefore requires an upstream language-service change followed by a dependency update.
- **related issue:** https://github.com/microsoft/vscode/issues/62976 implemented the broader Web Components custom-data capability and explicitly created this issue to track ranking and visual identification; it is not an open canonical duplicate.
