# Issue #233131 — Terminal: failed link detection on WSL filesystem when wordSeparators contains slashes

[https://github.com/microsoft/vscode/issues/233131](https://github.com/microsoft/vscode/issues/233131)

## Summary

The trace points to incorrect working-directory resolution rather than slash-based parsing, but current reproduction is not established. Request an updated trace with an existing target file before deciding whether a terminal-link fix remains necessary.

## Change summary

Relative paths on a WSL filesystem fail to become verified terminal links when slash separators expose the word-link fallback.

## Best solution

Existing relative file paths should resolve against the terminal's actual working directory and remain clickable across the whole path, independently of word-selection separators. First establish whether current shell integration still supplies the malformed WSL working directory shown in the report.
