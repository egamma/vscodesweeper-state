# Issue #233131 — Terminal: failed link detection on WSL filesystem when wordSeparators contains slashes

[https://github.com/microsoft/vscode/issues/233131](https://github.com/microsoft/vscode/issues/233131)

## Summary

Keep open: the supplied task examples and trace logs suffice to retest the WSL path-resolution failure, but current Windows/WSL behavior could not be confirmed through read-only inspection. Current source includes WSL-specific resolution and shell-integration decoding that must be checked against the older report; neither a concrete fix nor a matching open canonical was established.

## Change summary

Relative paths printed by build tasks on a WSL filesystem fall back to individual search words when terminal word separators include slashes.

## Best solution

Existing files relative to the task's working directory should become verified full-path terminal links on WSL regardless of word-selection separators. Diagnose the malformed working-directory candidate before changing separator behavior, preserving ordinary Windows and Linux link resolution.
