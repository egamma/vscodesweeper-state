# Issue #233131 — Terminal: failed link detection on WSL filesystem when wordSeparators contains slashes

[https://github.com/microsoft/vscode/issues/233131](https://github.com/microsoft/vscode/issues/233131)

## Summary

Still present on main: when the user adds slashes to `terminal.integrated.wordSeparators`, the word link detector splits file paths at slash boundaries, producing single-component search links (e.g. `foo`) instead of full-path file links. The local link detector parses the full path correctly but its resolved candidate fails to validate on WSL-mounted filesystems, leaving the broken word link as the only click target. No fix commit exists.

## Change summary

Terminal link detection falls back to per-word search links when slashes are in `wordSeparators` and local file resolution fails on WSL paths.

## Best solution

The word link detector (`terminalWordLinkDetector.ts`) should exclude slash characters from its separator regex when splitting text — or the local link detector should improve its WSL path resolution so the higher-priority file link survives validation. The fix likely touches `terminalWordLinkDetector.ts` (to not split on path separators) or `terminalLocalLinkDetector.ts` / `terminalLinkHelpers.ts` (to handle `\\wsl.localhost\\` paths more robustly). The setting description already warns about `:` but should also mention `/` and `\`.
