# Issue #350378 — Reconsider support for commenting on deleted lines in inline diff view

[https://github.com/microsoft/vscode/issues/350378](https://github.com/microsoft/vscode/issues/350378)

## Summary

Keep open: commenting on deleted lines remains unsupported in inline diffs, and switching to side-by-side does not satisfy the requested workflow. The predecessor closed through community voting, not because support shipped or the capability was rejected on technical grounds.

## Change summary

Support review comments on deleted lines without leaving inline diff view.

## Best solution

Consider original-side comment creation and thread display within inline diffs, preserving original-file line attribution and existing side-by-side behavior. The comments and diff-editor owners should assess this capability through the feature-request process.

- **Current capability gap:** src/vs/workbench/contrib/comments/browser/commentsController.ts:765–777 identifies the original editor when diffEditor.renderSideBySide is false; displayCommentThread at lines 1195–1202 explicitly skips that editor. This prevents original-side thread display in the requested inline layout.
- **Existing settings do not cover the request:** src/vs/workbench/contrib/comments/browser/comments.contribution.ts registers comment visibility, Comments-view behavior, and inline/floating thread styles. Neither thread style bypasses the original-editor exclusion in displayCommentThread. diffEditor.renderSideBySide=true is a workaround that changes the layout the reporter wants to retain.
- **Deleted-line surface:** src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/inlineDiffDeletedCodeMargin.ts provides copy and revert actions for rendered deleted lines, but no review-comment action or comment-thread integration.
