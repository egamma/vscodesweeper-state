# Issue #140261 — terminal.integrated.defaultProfile and terminal.integrated.automationProfile behaves differently

[https://github.com/microsoft/vscode/issues/140261](https://github.com/microsoft/vscode/issues/140261)

## Summary

Keep open: inline automation profiles now support args and env, but referencing an existing profile by name remains unsupported. This accepted Backlog request has 28 upvotes, and the related npm-arguments issue covers different work.

## Change summary

Allow terminal.integrated.automationProfile to reference a named terminal profile and reuse its shell arguments and environment.

## Best solution

Support named executable-backed profiles for task/debug automation while retaining existing inline automation-profile configuration. Establish whether extension-contributed profiles are included, and preserve task-specific shell and environment overrides.

- **Trace:**

  > terminalPlatformConfiguration.ts currently limits automationProfile to object/null, although its inline schema already includes args and env. BaseTerminalProfileResolverService._getUnresolvedAutomationShellProfile rejects string values through _isValidAutomationProfile, and _getUnresolvedDefaultProfile falls back to the ordinary default. TerminalProfileService.getDefaultProfile demonstrates named selection restricted to non-auto-detected profiles; the adjacent agent-host resolver also supports names but is not enabled on the task path. ## Evidence
