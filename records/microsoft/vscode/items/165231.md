# Issue #165231 — Use the Flyweight pattern to encode tokens

[https://github.com/microsoft/vscode/issues/165231](https://github.com/microsoft/vscode/issues/165231)

## Summary

The requested memory optimization remains unimplemented on current main: lexical tokens are still stored as pairs of 32-bit end offsets and metadata values. This team-authored Backlog item is an active design request under discussion and should remain open.

## Change summary

Encode frequently repeated token metadata through a compact dictionary representation to reduce token-storage memory.

## Best solution

Define a compact token representation that materially reduces memory while preserving constant-time metadata and offset access, editing behavior, and background-tokenizer serialization. A maintainer should first choose the dictionary scope and overflow/fallback format, then validate the design with correctness tests and representative memory measurements.

## Plan brief

- **Likely files:** `src/vs/editor/common/tokens/lineTokens.ts`, `src/vs/editor/common/tokens/contiguousTokensStore.ts`, `src/vs/editor/common/tokens/contiguousTokensEditing.ts`, `src/vs/editor/common/tokens/contiguousMultilineTokens.ts`, `src/vs/editor/common/tokens/contiguousMultilineTokensBuilder.ts`, `src/vs/editor/test/common/model/tokensStore.test.ts`, `src/vs/editor/test/common/core/lineTokens.test.ts`
- **Validation:** Run the targeted editor token-store and line-token unit tests, add round-trip/editing coverage for compact and overflow representations, and compare retained token bytes on a representative large TypeScript file against the current Uint32-pair baseline.
- **Behavior:**

  > Tokenized text should retain exactly the same token boundaries and decoded metadata while consuming substantially less memory when metadata values repeat. Long tokens, files with many distinct metadata values, edits, embedded-language tokens, and serialization round trips must remain correct. Acceptance requires equivalent LineTokens results before and after encoding, passing token-store tests, and a repeatable memory measurement showing a meaningful reduction on a representative large source file without a material token-access regression.
- **Trace:**

  > Current main stores alternating 32-bit end offsets and metadata in LineTokens and ContiguousTokensStore (src/vs/editor/common/tokens/lineTokens.ts and contiguousTokensStore.ts). ContiguousTokensEditing mutates that representation directly, and ContiguousMultilineTokens plus ContiguousMultilineTokensBuilder serialize and deserialize the raw Uint32 arrays, so the format boundary spans storage, edits, worker transport, and readers. The source confirms the requested flyweight representation has not landed. Preserve tokenization semantics, random token lookup, language/metadata decoding, edit correctness, and transport round trips; the uncertainty begins at dictionary lifetime and the representation used when offsets or metadata cardinality exceed the compact form.
- **Open decisions:**
  - Should the metadata dictionary be scoped per line, token block, text model, or language/theme generation?
  - Which compact and fallback encodings provide the best memory reduction without materially slowing random lookup and edits?
  - Should background-tokenizer serialization adopt the compact format directly or translate at the model boundary?
  - How should dictionaries be invalidated or rebuilt when language identifiers or token-theme metadata change?

## Evidence

- **current representation:** src/vs/editor/common/tokens/contiguousMultilineTokens.ts documents that every token occupies two Uint32Array entries: a 32-bit endOffset followed by 32-bit metadata.
- **model storage:** src/vs/editor/common/tokens/contiguousTokensStore.ts still stores each line as Uint32Array | ArrayBuffer | null, and LineTokens in src/vs/editor/common/tokens/lineTokens.ts directly indexes the alternating 32-bit offset/metadata entries.
- **format dependencies:** src/vs/editor/common/tokens/contiguousTokensEditing.ts mutates 32-bit end offsets in place, while src/vs/editor/common/tokens/contiguousMultilineTokens.ts serializes the raw arrays; a compact representation therefore needs coordinated editing and serialization semantics.
