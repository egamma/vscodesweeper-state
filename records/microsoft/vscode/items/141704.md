## Evidence

- **Tracking scope:** https://github.com/microsoft/vscode/issues/141704 explicitly inventories multiple independent clipboard challenges rather than reporting one bounded defect. Partial completion does not establish completion of this umbrella.
- **Current browser workarounds:** src/vs/platform/clipboard/browser/clipboardService.ts still installs installWebKitWriteTextWorkaround for Safari/WebKit, listens to click and keydown to initiate deferred clipboard writes, falls back from writeText to document.execCommand('copy'), and uses navigator.clipboard.readText for reads.
- **Parity remains incomplete:** src/vscode-dts/vscode.d.ts exposes only readText and writeText on the public Clipboard interface. The internal IClipboardService adds image reads and resource operations, and BrowserClipboardService implements these, but it does not provide the full HTML, rich-text, image-write, format-enumeration, and arbitrary-buffer surface listed in the issue.
- **Editor compatibility remains relevant:** src/vs/editor/contrib/clipboard/browser/clipboard.ts still avoids default browser cut/copy/paste command keybindings to prevent security prompts and special-cases Firefox paste support through queryCommandSupported('paste'). https://github.com/microsoft/vscode/issues/184958 is open and tracks that narrower Firefox detection problem; it is newer than this re-reviewed inventory.
- **Broader feedback is not a canonical duplicate:** https://github.com/microsoft/vscode/issues/150744 is open, was created on 2022-05-30 after this issue, and explicitly links this issue as its clipboard-specific inventory. It does not qualify as an older same-symptom canonical for this re-review.
