# Issue #339504 — Removing several remote agent hosts at once briefly renames the remaining ones to their address

[https://github.com/microsoft/vscode/issues/339504](https://github.com/microsoft/vscode/issues/339504)

## Summary

Confirmed in source: `RemoteAgentHostService._reconcileConnections` rebuilds `_names` from the desired set before running the stale-connection removal loop, so each `_removeConnection` fired for a host not yet reached reports the remaining hosts by address instead of their configured name — matching the reported `nameChanged=true` log sequence. An open PR (#339505) already fixes this with a test, so the issue stays open pending that merge rather than being closed now.

## Change summary

Removing multiple configured remote agent hosts in one edit makes the Agents window briefly treat the not-yet-removed hosts as renamed to their raw address, tearing down and re-registering their agent/session/log state for no reason.

## Best solution

Land https://github.com/microsoft/vscode/pull/339505, which reorders `_reconcileConnections` to remove dropped hosts before rebuilding `_names`, eliminating the spurious rename churn.
