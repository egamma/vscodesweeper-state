# Issue #297149 — Signed out user model picker drop down

[https://github.com/microsoft/vscode/issues/297149](https://github.com/microsoft/vscode/issues/297149)

## Summary

Keep open: maintainers accepted improving the signed-out model picker, but the thread has not settled whether it should show only Free-eligible models with a sign-in action or also unavailable featured models with upgrade actions. Current main partially improves the list but does not implement the proposed signed-out sign-in funnel.

## Change summary

Make the signed-out Copilot model picker informative and direct users into the appropriate sign-in or account-creation flow.

## Best solution

Settle the signed-out picker composition, then present the eligible Free models with a clear sign-in action that opens VS Code's account sign-in flow, while reserving upgrade actions for users and models where upgrading is actually required.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItems.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemSections.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemPrimitives.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/modelPicker/modelPickerItems.test.ts`
- **Validation:** Add focused model-picker unit coverage for ChatEntitlement.Unknown with anonymous access, asserting the chosen model list and CTA command, then run ./scripts/test.sh --grep "signed-out".
- **Behavior:**

  > When a user can access Chat anonymously but is not signed in to GitHub Copilot, the model picker should not appear abbreviated or imply that a credit card is required to begin using Copilot Free. It should show the model choices selected for this state and a clear account action whose label and destination match the agreed funnel. Free, paid, enterprise, and already-signed-in picker behavior must remain unchanged. Acceptance requires focused tests for the signed-out item list and the command invoked by its CTA.
- **Trace:**

  > The picker obtains its control manifest in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts and filters it through getModelPickerControlModels in modelPickerItems.ts. For ChatEntitlement.Unknown, that helper currently retains only available targeted featured models; modelPickerRequiresSetup in modelPickerPresentation.ts prevents anonymous users from entering the existing setup-required sign-in presentation. Unavailable promoted rows are constructed by createUnavailableModelItem in modelPickerItemPrimitives.ts, where the non-enterprise action is always workbench.action.chat.upgradePlan. The existing setup-required path in modelPickerItemSections.ts already demonstrates a command-backed sign-in item, and workbench.actions.accounts.signIn is defined by the default-account service. Keep changes limited to signed-out/anonymous presentation and do not alter upgrade behavior for authenticated Free users or paid-model eligibility. https://github.com/microsoft/vscode/issues/297151 was consolidated into this issue and supplies the same anonymous-access evidence.
- **Open decisions:**
  - For signed-out anonymous users, should the picker show only Free-eligible models with a Sign In action, or also show unavailable paid featured models with Upgrade actions?
