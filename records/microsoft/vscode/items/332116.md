# Issue #332116 — Create session from PR shows "Session not found on backend: copilotcli:/<UUID>"

[https://github.com/microsoft/vscode/issues/332116](https://github.com/microsoft/vscode/issues/332116)

## Summary

Team-authored (alexdima, MEMBER) day-old bug report about the new 'Create session from PR' flow; a hard keep-open rule applies regardless, and there is no cited fix commit or duplicate to justify a close.

## Change summary

Creating an agent session from a GitHub pull request sometimes surfaces 'Session not found on backend: copilotcli:/<UUID>' instead of opening the session.

## Best solution

Likely a race between showing the session and the backend actually registering it: `_configureAndSendNewSession` in src/vs/sessions/services/sessions/browser/sessionsManagementService.ts invokes `createOptions?.onSessionCreated?.(session)` (which drives `showSession` in src/vs/sessions/contrib/github/browser/pullRequestSessionCreation.ts) right after the provider mints a local/'eager' session object, before the Agent Host backend has necessarily registered that session URI (the ProtocolError thrown from src/vs/platform/agentHost/node/agentService.ts). Needs a trace of the exact timing versus `AgentService`/`AgentSessionRegistry` registration to confirm and then either defer navigation or make the UI resilient to a not-yet-registered session.
