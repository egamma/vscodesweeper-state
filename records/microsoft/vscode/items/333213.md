# Issue #333213 — Source Control - Git - Show submodule diffs properly, or at least not an error

[https://github.com/microsoft/vscode/issues/333213](https://github.com/microsoft/vscode/issues/333213)

## Summary

Clicking a submodule (gitlink) entry in a commit/graph diff currently surfaces a raw 'Unable to read file' error because the git extension has no special handling for submodule pointer entries when resolving diff content — a real, unaddressed gap, not something already covered elsewhere.

## Change summary

Opening a submodule change from the SCM graph/commit diff view throws an error instead of showing a submodule-appropriate diff (e.g. old/new commit SHAs).

## Best solution

In extensions/git/src, detect gitlink entries (mode 160000) when building the diff/resource list for a commit and route them to a dedicated submodule-diff renderer (showing before/after commit SHAs, and ideally the sub-repo's own commit log) instead of trying to read them through the normal file/text diff pipeline (fileSystemProvider.ts's getObjectDetails/buffer path).
