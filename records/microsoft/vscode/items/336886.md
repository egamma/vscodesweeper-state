# Issue #336886 — Diff View menu shows wrong selected layout with workspace-folder-specific `diffEditor.renderSideBySide`

[https://github.com/microsoft/vscode/issues/336886](https://github.com/microsoft/vscode/issues/336886)

## Summary

Confirmed on current main by tracing the source exactly as the reporter describes: the Diff View submenu's `toggled` expressions read `config.diffEditor.renderSideBySide` through the plain (non-resource-scoped) configuration service, while the actual diff editor and its commands resolve the setting per the modified resource — so a workspace-folder override on one side of the diff can make the menu disagree with what's actually rendered.

## Change summary

In a multi-root workspace with a folder-specific `diffEditor.renderSideBySide` override, the Diff View submenu's checked item (Inline/Side by Side/Automatic) doesn't match the diff editor's actual rendered layout.

## Best solution

Make the Diff View submenu's `toggled` expressions resource-aware by reusing/extending the diff editor's own per-widget context keys (e.g. `EditorContextKeys.diffEditorInlineMode`, already bound in diffEditorWidget.ts to `!this._options.renderSideBySide`) instead of the global `config.diffEditor.renderSideBySide` context key, and add an analogous per-widget context key for `useInlineViewWhenSpaceIsLimited` if needed to fully cover the Side-by-Side/Automatic entries.
