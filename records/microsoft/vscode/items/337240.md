# Issue #337240 — Scrollbars on Terminal, Debug Output, etc. panels need buttons for precision scrolling

[https://github.com/microsoft/vscode/issues/337240](https://github.com/microsoft/vscode/issues/337240)

## Summary

The requested single-line scrollbar buttons are already covered by an older, verified open request for traditional scrollbars. Consolidate there while preserving this report's specific Terminal and Debug Console accessibility requirements.

## Change summary

Provide clickable scrollbar buttons for precise line-by-line scrolling in output panels without requiring a mouse wheel or touchpad gestures.

## Best solution

Track the capability in https://github.com/microsoft/vscode/issues/15106, including its application to Terminal and Debug Console output; keyboard scrolling alone does not fulfill the requested pointer-operated controls.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/15106 is OPEN and was created on 2016-11-07. Its body explicitly requests up/down and left/right scrollbar arrows that scroll one line per click, as part of an optional traditional scrollbar presentation; it does not restrict the request to editor tabs.
- **Same observable accessibility limitation:** https://github.com/microsoft/vscode/issues/15106#issuecomment-383505409 describes difficulty scrolling with a notebook touchpad and no wheel; https://github.com/microsoft/vscode/issues/15106#issuecomment-612988973 describes long lists where arrow keys and Page Up/Down are inadequate; https://github.com/microsoft/vscode/issues/15106#issuecomment-1921787447 explicitly requests single-line mouse scrolling and discusses disability-related accessibility. This establishes the same missing controls, not merely a related visual preference.
- **Existing capability is only partial:** src/vs/workbench/contrib/terminal/browser/terminalActions.ts registers workbench.action.terminal.scrollUp and workbench.action.terminal.scrollDown for single-line keyboard scrolling. These address precision through the keyboard but do not provide the requested clickable scrollbar buttons. The terminal scrollbar options in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts configure width and the overview ruler, not arrow buttons; Debug Console creates its output tree in src/vs/workbench/contrib/debug/browser/repl.ts without enabling scrollbar arrows.
- **Reporter-supplied related requests:** https://github.com/microsoft/vscode/issues/22636 is closed and discusses editor scrollbar arrows, including an editor.scrollbar workaround; it is not an eligible duplicate target. https://github.com/microsoft/vscode/issues/142590 is closed and concerns editor-tab-strip overflow arrows, a different surface. Neither establishes that the output-panel accessibility requirement is satisfied or declined.
- **Unique evidence to retain:** https://github.com/microsoft/vscode/issues/337240 describes long Terminal and Debug Output content, disabled touchpad gestures/tapping, and possible arthritis-related difficulties. The follow-up requests buttons on all scrollbars while identifying output panels as the minimum functional need; that scope fits the broader canonical request.
