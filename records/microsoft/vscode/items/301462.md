# Issue #301462 — [UX]: Settings menu does not indicate when user settings are overridden by settings.json files in a multi-root workspace

[https://github.com/microsoft/vscode/issues/301462](https://github.com/microsoft/vscode/issues/301462)

## Summary

Confirmed in source: the override indicator logic in `settingsTreeModels.ts` checks `workspaceValue`, `userRemoteValue`, and `userLocalValue` but never checks `workspaceFolderValue`, so folder-level overrides in multi-root workspaces produce no visual indicator in the Settings UI.

## Change summary

In a multi-root workspace, settings overridden via a folder's `.vscode/settings.json` show no 'Also modified in' indicator in the Settings editor.

## Best solution

Add a check for `workspaceFolderValue` (and its language overrides) in the `update()` method of `SettingsTreeSettingElement` in `settingsTreeModels.ts`, similar to the existing checks for `workspaceValue`/`userRemoteValue`/`userLocalValue`, so that folder-level overrides appear in the indicator.
