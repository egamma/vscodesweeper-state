# Issue #200758 — Closing floating window should close, not redock dirty editors

[https://github.com/microsoft/vscode/issues/200758](https://github.com/microsoft/vscode/issues/200758)

## Summary

Keep open: current source closes editors that need no confirmation but still moves confirmation-requiring editors back to the main window. This is the remaining work the maintainer explicitly retained, and the request has sufficient community support for the Backlog.

## Change summary

Closing a floating window should close its dirty editors through the normal save-confirmation flow rather than redocking them.

## Best solution

Support closing confirmation-requiring editors from the floating window, preserving unsaved changes and allowing cancellation to keep the window open. Decide whether this replaces the existing redocking behavior or is configurable before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/auxiliaryEditorPart.ts`, `src/vs/workbench/browser/parts/editor/editorGroupView.ts`, `src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts`, `src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts`
- **Validation:** Manually open a dirty editor in a floating window and close that window. Verify Save preserves the edit and closes the editor/window, Don't Save closes without redocking, and Cancel retains the window and unsaved content. Repeat with mixed clean/dirty editors and confirm clean-only closure remains unchanged.
- **Behavior:**

  > Closing a floating window should offer the normal save choices for editors requiring confirmation instead of moving them to the main window. Saving must preserve edits, discarding must close the editors, and cancelling must leave the window and unsaved content available. Clean-only window closure must retain its existing behavior. The maintainer must settle whether the requested behavior is the default or configurable.
- **Trace:**

  > AuxiliaryEditorPart registers an onUnload listener that calls AuxiliaryEditorPartImpl.close(). Its doClose(true) first closes non-confirming editors through EditorGroupView.closeAllEditors({ excludeConfirming: true, force: true }), then merges remaining groups into the main part. EditorGroupView.shouldConfirmClose determines the excluded editors. The auxiliary-window service separately handles unload vetoes and window.confirmBeforeClose, so asynchronous editor confirmation must be considered before the window unloads. The remaining scope is explicitly retained in https://github.com/microsoft/vscode/issues/200758 after https://github.com/microsoft/vscode/pull/246169; preserve unsaved-change safety and existing clean-editor closure.
- **Open decisions:**
  - Should closing dirty editors with save confirmation replace redocking by default, or should users be able to choose between these behaviors through a setting?
