# Issue #200758 — Closing floating window should close, not redock dirty editors

[https://github.com/microsoft/vscode/issues/200758](https://github.com/microsoft/vscode/issues/200758)

## Summary

A meaningful gap remains for dirty editors, and this Backlog request exceeded the 20-upvote threshold. Current main still redocks editors requiring confirmation when their floating window closes.

## Change summary

Closing a floating window should close its dirty editors through an appropriate confirmation flow instead of redocking them into the main window.

## Best solution

Design a floating-window close flow that confirms and closes dirty editors without moving them to the main editor part, potentially retaining redocking as a configurable preference. The implementation belongs in the auxiliary editor lifecycle and editor-close confirmation handling.
