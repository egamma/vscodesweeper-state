# Issue #156423 — Smooth scrolling has limited upper speed and causes skipping to make up

[https://github.com/microsoft/vscode/issues/156423](https://github.com/microsoft/vscode/issues/156423)

## Summary

Verified duplicate: the open smooth-scrolling discussion covers this Logitech free-spin case and the same underlying mismatch between wheel input and VS Code's fixed-duration animation.

## Change summary

Fast flywheel input can outrun editor smooth scrolling, leaving a queued distance that is traversed with a visible jump after scrolling stops.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/185891 and make editor smooth scrolling remain synchronized with high-rate wheel input without abrupt catch-up jumps.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/185891 is open and broadly tracks replacing Monaco's fixed-step animated scrolling with input-synchronized Chrome-style behavior; its discussion explicitly describes Logitech free-spin wheels and VS Code's inability to stop or reverse at the input position.
- **current source:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts computes each wheel delta from getFutureScrollPosition() and extends the pending target through setScrollPositionSmooth(), so rapid input can accumulate ahead of the rendered position.
- **jump path:** src/vs/base/common/scrollable.ts restarts a fixed-duration animation from the current rendered state when its target changes; SmoothScrollingOperation._initAnimation() uses two separated animation segments once the distance exceeds 2.5 viewports, producing an intentional middle-distance jump.
- **existing test evidence:** src/vs/base/test/common/scrollable.test.ts records the large-distance behavior: the 500-line case advances from line 29 at 25 ms to line 482 at 50 ms.
- **related fix is distinct:** https://github.com/microsoft/vscode/pull/189656 fixed https://github.com/microsoft/vscode/issues/187283 only for terminal trackpad handling in xtermTerminal.ts; that report explicitly said editor smooth scrolling behaved differently and the PR did not change the shared editor animation.
