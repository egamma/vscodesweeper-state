# Issue #333460 — Agent does not receive search/codebase in its tool definitions.

[https://github.com/microsoft/vscode/issues/333460](https://github.com/microsoft/vscode/issues/333460)

## Summary

Traced the gating logic on main: for Copilot Agent Host sessions, `semantic_search`/`#codebase` is intentionally withheld from the model's tool definitions unless the experimental, default-off `chat.copilot.semanticSearch.enabled` setting is turned on — the old tools-picker toggle for this tool is explicitly deprecated and no longer controls availability for these sessions.

## Change summary

The semantic codebase search tool never appears in the tool definitions sent to the model for Copilot Agent Host sessions (main agent or subagents), even though it's shown as enabled in the tools picker/custom-agent frontmatter, while explicit `#codebase` invocation still works.

## Best solution

Point the reporter at `chat.copilot.semanticSearch.enabled` (off by default, tagged experimental/advanced) to opt in; separately, the team may want to either surface this setting in the tools picker or stop showing the now-deprecated per-tool toggle for Copilot sessions so the UI doesn't imply the picker controls this.

## Evidence

- **gate in tool-list builder:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts, `_getClientTools()` (~L376-401): for `isCopilotSession`, the semantic-search tool is only included when `semanticSearchEnabled` (from `CopilotSemanticSearchEnabledSettingId`) is true; toolset-based enablement is bypassed for it.
- **toolset skipped as deprecated:** The 'search' toolset carrying `copilot_searchCodebase` is marked `deprecated: true` in the shipped code path, and `_getClientTools()` does `if (ts.deprecated) continue;` before computing `enabledToolIds` — so toggling it in the tools picker has no effect for Copilot sessions.
- **setting default:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts (~L1638-1644): `chat.copilot.semanticSearch.enabled` defaults to `false`, tags `['experimental','advanced']`, description: 'When disabled, semantic search is unavailable.'

- **explicit-reference path differs:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts `_resolveClientTool()` (~L2700-2707) resolves `semantic_search` calls for Copilot sessions regardless of the setting, explaining why manually typing `#codebase` still works even though the tool isn't advertised to the model.
