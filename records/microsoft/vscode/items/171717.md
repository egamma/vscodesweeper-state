# Issue #171717 — Bug blocking texts with ctrl+shift+arrow

[https://github.com/microsoft/vscode/issues/171717](https://github.com/microsoft/vscode/issues/171717)

## Summary

Keep open: the reporter isolated the selection-anchor problem to accessibility mode, and a maintainer confirmed reproduction. Intentional screen-reader word boundaries do not establish that restarting selection from the original cursor is intentional; no concrete fixing commit or eligible canonical was found.

## Change summary

On Windows with accessibility support enabled, switching from Shift+LeftArrow to Ctrl+Shift+LeftArrow should extend selection from its active endpoint rather than restart from its original cursor.

## Best solution

Preserve the selection anchor and active endpoint when switching between character and native word selection in the editor's accessibility input path, while retaining screen-reader-compatible word boundaries. First confirm the exact interaction on current Windows builds and pin it with a browser-level regression check.
