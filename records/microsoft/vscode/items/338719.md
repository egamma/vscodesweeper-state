# Issue #338719 — AI Customization does not show the source of built-in MCP servers

[https://github.com/microsoft/vscode/issues/338719](https://github.com/microsoft/vscode/issues/338719)

## Summary

Confirmed in source: the MCP detail panel falls back to the literal, non-clickable label 'mcp.json' whenever a server has no `source` (i.e. built-in/extension-provided servers), which is misleading rather than merely absent — a real UX bug worth fixing, but the exact provenance text/behavior needs a maintainer call before implementation.

## Change summary

The AI Customization MCP server detail page (and its `...` menu) gives no indication that a selected server is built in, and shows no provider/source information for it.

## Best solution

Thread the already-available provenance data (extensionId / plugin via collectionId, both present on IMcpBuiltinItemEntry) into IMcpServerDetailInput, and have EmbeddedMcpServerDetail.renderItem show a real 'Built-in' / 'Provided by extension X' / 'Plugin: X' label instead of the fake 'mcp.json' fallback when `source` is undefined.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/embeddedMcpServerDetail.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts`
- **Validation:** After the change, selecting a built-in MCP server with no `source` should render an explicit built-in/provider indicator instead of the string 'mcp.json', and should not show a non-functional source link.
- **Behavior:**

  > Selecting a built-in MCP server in the AI Customization editor's detail panel should clearly indicate it is built in and, when known, name its provider (extension or plugin) — never display a fake 'mcp.json' filename with no way to open it. The `...` menu should offer something meaningful for provenance (or omit 'Show Configuration' cleanly) when there is no backing file. Acceptance: built-in servers with no file source show a real built-in/provider label in the detail header instead of 'mcp.json', and the source-link affordance is not shown when there is nothing to open.
- **Trace:**

  > EmbeddedMcpServerDetail.renderItem (embeddedMcpServerDetail.ts:249-292) computes `sourceLabel` unconditionally as `server.source ? basename(...) : 'mcp.json'` and toggles the link class only on `!!server.source` — so the literal fallback text is always 'mcp.json' regardless of whether the server is file-backed. Meanwhile createInstalledMcpServerDetailInput (mcpListWidget.ts:1601-1641) discards the `extensionId` and `collectionId` already present on IMcpBuiltinItemEntry (mcpListWidget.ts:1573-1583) instead of turning them into a provider label; `getPluginUriFromCollectionId` (used at mcpListWidget.ts:445) is the existing helper for plugin provenance. Boundary: do not change source resolution for file-backed (user/workspace) servers — `source`, config loading, and the existing edit/open-configuration flow for those must stay intact; this only affects the no-`source` fallback path.
- **Open decisions:**
  - What exact label/format should the detail header show for a built-in server with no file source (e.g. 'Built-in', 'Provided by extension X', 'Plugin: X') — and should it differ between extension-provided and plugin-provided built-ins?
  - Should the '...' menu offer an alternative action (e.g. jump to the owning extension in the Extensions view) in place of 'Show Configuration' when there is no backing file, or simply omit that menu item?

## Evidence

- **misleading fallback:** src/vs/workbench/contrib/chat/browser/aiCustomization/embeddedMcpServerDetail.ts:270 sets `const sourceLabel = server.source ? basename(server.source.uri) : 'mcp.json';` — for built-in servers with no `source`, the panel still displays the literal string 'mcp.json' (non-clickable, no href) even though no such file backs it.
- **detail input has no builtin/provider field:** createInstalledMcpServerDetailInput (mcpListWidget.ts:1601-1641) only sets `source` from `localSource ?? activeSessionSource`; nothing is passed through for `extensionId` or plugin provenance that IMcpBuiltinItemEntry already carries (mcpListWidget.ts:1573-1583, `createBuiltinEntry` takes `extensionId`; `getPluginUriFromCollectionId(element.collectionId)` is already used for a list-row hover at mcpListWidget.ts:445-459, but never reaches the detail panel).
- **existing partial precedent:** The list row already shows plugin provenance via a hover (`localize('fromPlugin', "Plugin: {0}", plugin.label)`) but this only covers plugin-sourced builtins, not extension-provided ones, and doesn't reach the detail page at all.
