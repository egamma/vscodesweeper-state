# Issue #327479 — Unresponsive for 30–90s intermittently

[https://github.com/microsoft/vscode/issues/327479](https://github.com/microsoft/vscode/issues/327479)

## Summary

Real, still-open UI freeze corroborated by four independent reporters (including a VS Code team member) across different setups, all pointing at the account/policy network path (DefaultAccount / AccountPolicyGate fetching entitlement, token, and managed-settings endpoints) stalling the extension host during activation; no fix commit exists on main yet.

## Change summary

VS Code window intermittently freezes fully unresponsive for 30–90s, apparently while the extension host is blocked fetching Copilot account/policy data over the network.

## Best solution

Investigate whether `DefaultAccountService`'s request pipeline (src/vs/workbench/services/accounts/browser/defaultAccount.ts, the `request()`/managed-settings fetch path) or its callers can block extension activation/UI when a request hangs or is retried without a bounded timeout in all code paths; add resilience (e.g. guaranteed timeout, non-blocking activation) so a slow/failed network call to `copilot_internal/*` or `managed_settings` cannot freeze the whole window.
