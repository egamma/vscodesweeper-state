# Issue #223553 — Node process in terminal not killed when VSCode is closed (Windows)

[https://github.com/microsoft/vscode/issues/223553](https://github.com/microsoft/vscode/issues/223553)

## Summary

This is the canonical issue for child processes surviving VS Code shutdown on Windows — three other issues (#232384, #234986, #308450) were closed as duplicates of it. The bug appears unresolved on current main: no fix commit references this issue, and the terminal shutdown path relies on node-pty's kill() which may not terminate the full process tree on Windows. Keeping open as it has community traction (7 upvotes, multiple confirmations) and serves as the consolidation point.

## Change summary

Node child processes (e.g. vite dev server) are not killed when VS Code is closed on Windows, leaving orphaned processes holding ports.

## Best solution

Investigate whether node-pty's kill on Windows via conpty properly terminates the entire process tree on shutdown. The fix likely lives in `src/vs/platform/terminal/node/terminalProcess.ts` — the `_kill()` method calls `this._ptyProcess.kill()` but may need explicit process-tree termination on Windows. The conpty update to 1.25 (commit 262ba6d42f3) may have improved this, but no targeted fix for this issue exists.
