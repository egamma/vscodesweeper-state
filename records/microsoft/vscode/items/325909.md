# Issue #325909 — Extensions Auto Update enterprise policy is overridden by user settings

[https://github.com/microsoft/vscode/issues/325909](https://github.com/microsoft/vscode/issues/325909)

## Summary

Confirmed in current source: the extensions.autoUpdate policy sets the effective config value to 'on', but per-extension and per-publisher auto-update overrides (and the 'Disable Auto Update for Extensions' checkbox/menu) are never checked against the policy lock, so a user can silently defeat an organization policy. This has a real milestone (1.134.0), so it stays open per policy regardless of the strength of the evidence.

## Change summary

When extensions.autoUpdate is locked by an enterprise policy, per-extension/publisher auto-update toggles and the global 'Disable Auto Update for Extensions' action can still override it, instead of being disabled/greyed out.

## Best solution

Add a policy-lock guard (using the existing `configurationService.inspect(AutoUpdateConfigurationKey).policyValue !== undefined` pattern already used elsewhere, e.g. src/vs/workbench/services/configuration/common/configurationEditing.ts:512) to ToggleAutoUpdateForExtensionAction.update()/run() in extensionsActions.ts and to updateAutoUpdateEnablementFor/shouldAutoUpdateExtension in extensionsWorkbenchService.ts, and disable the 'Disable Auto Update for Extensions' command's precondition when the setting is policy-managed.

## Evidence

- **per-extension toggle ignores policy:** src/vs/workbench/contrib/extensions/browser/extensionsActions.ts:1091 (`ToggleAutoUpdateForExtensionAction.update()`) only checks `getAutoUpdateValue() === 'on'` and extension enablement state — never inspects whether the config is policy-locked, so the checkbox stays enabled and clickable even under a mandatory policy.
