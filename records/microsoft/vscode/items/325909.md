# Issue #325909 — Extensions Auto Update enterprise policy is overridden by user settings

[https://github.com/microsoft/vscode/issues/325909](https://github.com/microsoft/vscode/issues/325909)

## Summary

Legitimate policy-enforcement bug: on current main, `shouldAutoUpdateExtension`'s per-extension opt-out list and the 'Disable Auto Update for Extensions' pin-everything action both bypass the `extensions.autoUpdate` policy value. An open PR (#329748) already fixes it with `Fixes #325909`, so this should stay open pending merge rather than being closed now.

## Change summary

When `extensions.autoUpdate` is locked by an enterprise/GPO policy, users can still disable auto-update for individual extensions or for all extensions via the 'Disable Auto Update for Extensions' menu action, silently defeating the org policy.

## Best solution

Land the linked fix in https://github.com/microsoft/vscode/pull/329748, which adds a policy-lock check (`isAutoUpdateConfigLockedByPolicy()` via `configurationService.inspect(...).policyValue`) and a context key so the per-extension checkbox and the 'Disable Auto Update for Extensions' action are disabled/hidden when the policy is in force.
