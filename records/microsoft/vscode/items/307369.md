# Issue #307369 — chat.agentFilesLocations and chat.agentSkillsLocations should support glob/wildcard patterns

[https://github.com/microsoft/vscode/issues/307369](https://github.com/microsoft/vscode/issues/307369)

## Summary

The requested general glob support was explicitly declined by the owning maintainer because recursively discovering agents and skills would add repeated filesystem-search cost. Current source intentionally accepts explicit locations only, and both settings are now deprecated in favor of supported customization locations.

## Change summary

Allow wildcard paths in `chat.agentFilesLocations` and `chat.agentSkillsLocations` so nested repositories can expose agents and skills without enumerating each directory.

## Best solution

Keep generic recursive glob discovery out of these settings; use explicit locations or multi-root workspaces, and consider a standardized bounded discovery convention if this repository layout becomes common.

## Vision fit

- **Fit:** rejected
- **Reason:** Unbounded recursive discovery for every agent request conflicts with VS Code's performance guardrail, particularly for a workflow that can use explicit workspace roots.
- **Evidence:** Public roadmap value: “Performance trumps functionality.” The extension ecosystem and lightweight-default guardrails also favor bounded configuration over recurring broad filesystem scans.
