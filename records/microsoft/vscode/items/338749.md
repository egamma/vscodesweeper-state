## Summary

Genuine, unimplemented feature request filed today with modest community support (4 reactions); no existing mechanism resolves versionless model-family aliases in custom-agent frontmatter to the newest model, so it stays open for maintainer consideration rather than any close.

## Change summary

Let the `model:` field in custom-agent (`.agent.md`) frontmatter accept a versionless family alias (e.g. "GPT Luna") that resolves to the newest available stable model in that family/provider instead of pinning an exact version.

If pursued, extend the model resolution/matching logic (e.g. `findBestMatchingModel` and the frontmatter model-parsing path in `chatInputModelUtils.ts` / custom-agent metadata loading) to support a documented family-alias syntax that picks the newest non-preview model per provider, with clear UI feedback on the resolved model; should likely be designed together with the related prompt-file latest-model request (#297210).
