# Issue #322242 — "Input needed" is very difficult to spot

[https://github.com/microsoft/vscode/issues/322242](https://github.com/microsoft/vscode/issues/322242)

## Summary

Keep open: the merged treatment improved visibility, but the team-author explicitly confirmed afterward that the input-needed state remained too subtle. Current main has several attention signals, but their prominence and interaction states still need a deliberate UX decision.

## Change summary

Make agent sessions waiting for user input sufficiently prominent that users do not overlook them for extended periods.

## Best solution

Provide an unmistakable persistent input-needed signal across the Agents Window title area and session list, including selected and focused rows, while retaining a non-animated equivalent for reduced-motion users.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/media/sessionsList.css`, `src/vs/sessions/contrib/sessions/browser/media/blockedSessionsList.css`, `src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsTitleBarWidget.test.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.fixture.ts`
- **Validation:** Add or update an Agents Window component fixture and screenshot coverage showing a session entering input-needed state while unselected, selected, focused, and under reduced motion; verify the chosen persistent signal remains clearly distinguishable in each state.
- **Behavior:**

  > When an agent session requires user input, the Agents Window must expose a persistent signal that is readily noticeable without requiring the user to inspect every row. The signal must remain meaningful when the affected row is selected, focused, or hovered, and reduced-motion users must receive an equally clear non-animated treatment. Normal running and completed sessions must remain visually distinct and unchanged.
- **Trace:**

  > The first treatment landed in https://github.com/microsoft/vscode/pull/322924, after which the reporter confirmed that visibility improved but remained insufficient. Current row feedback is implemented by the needs-input selectors and session-needs-input-accent-pulse keyframes in src/vs/sessions/contrib/sessions/browser/media/sessionsList.css; its selector deliberately suppresses the accent for selected, focused, and hovered rows. SessionsTitleBarWidget in src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts independently renders a persistent requires-input command-center state and consumes a transient blink, styled in blockedSessionsList.css. The boundary is attention presentation for the existing needs-input state: session status semantics, approval behavior, and unrelated list selection styling should not change.
- **Open decisions:**
  - Which persistent visual hierarchy should carry the primary input-needed signal when the affected session row is selected or focused: the command-center title area, the row itself, or both?
  - How prominent should the persistent state remain after the initial attention animation ends, including for users with reduced motion enabled?

## Evidence

- **partial implementation:** https://github.com/microsoft/vscode/pull/322924 merged a pulsing yellow row background and reduced-motion fallback, but described itself as addressing rather than closing this issue.
- **remaining gap confirmed:** After testing the merged treatment, the author said it had improved substantially but still needed to be more obvious: https://github.com/microsoft/vscode/issues/322242#issuecomment-4887542592.
- **current row behavior:** src/vs/sessions/contrib/sessions/browser/media/sessionsList.css applies session-needs-input-accent-pulse only while a needs-input row is not selected, focused, or hovered; reduced motion receives an 8% static warning-color fill.
- **current title signal:** src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts renders a persistent requires-input command-center state plus a transient blink; src/vs/sessions/contrib/sessions/browser/media/blockedSessionsList.css supplies its orange label, border, fill, and reduced-motion handling.
- **protected team direction:** The issue is team-authored, and multiple maintainers accepted improving the attention treatment; the post-merge feedback shows the requested polish was not considered complete.
