# Issue #322242 — "Input needed" is very difficult to spot

[https://github.com/microsoft/vscode/issues/322242](https://github.com/microsoft/vscode/issues/322242)

## Summary

Keep open for the remaining attention-indicator polish: the linked improvement landed, but the author subsequently confirmed that waiting sessions still need greater prominence. Current source retains the subtle background pulse; neither a complete fix nor an older canonical owning this same symptom was established.

## Change summary

Make sessions waiting for user input noticeable enough that users do not mistake them for sessions still making progress.

## Best solution

Agree on the remaining visual hierarchy for attention-needed sessions in the Agents Window, building on the existing pulse and title treatment. Validate that blocked sessions stand out during normal multi-session monitoring without sacrificing selection visibility, theme support, or reduced-motion accessibility.

Confirm the waiting session is readily identifiable, selection remains clear, and the attention treatment clears when input is supplied.
- **Behavior:**

  > A session awaiting user input must be easy to distinguish from sessions still working during routine multi-session monitoring. The existing pulse improved discoverability, but the author explicitly requested greater prominence afterward. Acceptance should establish an agreed attention hierarchy across normal and reduced-motion presentation while preserving legible selection and theme support.
- **Trace:**

  > SessionsList's reactive row rendering in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts derives SessionStatus and toggles needs-input. The matching CSS currently supplies a three-second background pulse peaking at a 12% warning tint, suppresses it during selection/focus/hover, and uses an 8% static tint for reduced motion; attention-needed titles use strongForeground. https://github.com/microsoft/vscode/pull/322924 introduced the pulse, but https://github.com/microsoft/vscode/issues/322242#issuecomment-4887542592 records residual feedback after it landed. The shared agent sessions viewer has a parallel treatment, and application-icon badges provide a separate awareness channel. The uncertainty is the desired remaining visual emphasis, not whether the initial improvement shipped. Keep session execution/status semantics unchanged and preserve accessible non-animated presentation and selection visibility.
- **Open decisions:**
  - What additional visual prominence should an attention-needed session have beyond the current pulse and strong title, and should that emphasis remain visible while its row is selected, focused, or hovered?
