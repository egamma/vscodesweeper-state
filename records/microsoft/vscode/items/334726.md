# Issue #334726 — Copilot Chat stalls after listDirectory/textSearch in Remote-SSH workspace on VS Code 1.136.1

[https://github.com/microsoft/vscode/issues/334726](https://github.com/microsoft/vscode/issues/334726)

## Summary

Real, well-documented report with a second independent confirmation in the comments; traced part of the root-cause hypothesis in source (listDirTool has no pagination/limit), but the described stall goes beyond output size, so this needs maintainer investigation rather than a close.

## Change summary

Copilot Chat's agent loop stalls indefinitely after listDirectory/textSearch tool calls in large Remote-SSH workspaces on 1.136.1, with a workaround of disabling those tools or downgrading to 1.135.0.

## Best solution

Add bounded/paginated output (and possibly exclusion handling) to ListDirTool in extensions/copilot/src/extension/tools/node/listDirTool.tsx, but first correlate with the two related open issues (#324907, #332431) and the reporter's extension-host CPU/socket-timeout evidence to determine whether this is the same underlying race/poisoning bug or a distinct remote-channel regression introduced between 1.135.0 and 1.136.1.

## Evidence

- **unbounded listDirectory:** extensions/copilot/src/extension/tools/node/listDirTool.tsx calls `this.fsService.readDirectory(uri)` and renders every entry via a mapped `<TextChunk>` list with no limit, pagination, or exclusion filtering — matching the reporter's claim.
- **related issue 1:** https://github.com/microsoft/vscode/issues/324907 (open, no labels) reports the same unbounded list_dir output poisoning chat context on very large directories over a remote tunnel.
- **related issue 2:** https://github.com/microsoft/vscode/issues/332431 (open, no labels) reports a silent multi-minute agent-loop stall after file/search tools complete, with no corresponding log output — closer to this report's 'tool completes but turn never continues' symptom.
- **independent confirmation:** Comment from marcoskirsch corroborates the stall on 1.136.1 over Remote-SSH with extension-host CPU spikes and `unacknowledgedMessage` socket timeouts, and confirms the same tool-disabling workaround.
- **version regression:** Reporter states the issue is absent on VS Code 1.135.0 in the same workspace, suggesting a regression between 1.135.0 and 1.136.1 rather than a long-standing design limitation.
