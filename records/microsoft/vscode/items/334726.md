# Issue #334726 — Copilot Chat stalls after listDirectory/textSearch in Remote-SSH workspace on VS Code 1.136.1

[https://github.com/microsoft/vscode/issues/334726](https://github.com/microsoft/vscode/issues/334726)

## Summary

Keep open as a confirmed Remote-SSH/Copilot regression: two users report agent turns stalling with the same large-workspace setup, while the editor and SSH connection remain usable. The older related issues cover narrower or materially different tool paths and do not meet the stronger duplicate bar for this re-reviewed item.

## Change summary

Copilot Agent turns stall indefinitely when listDirectory or textSearch is enabled in a large Remote-SSH workspace, despite the remote workspace remaining otherwise responsive.

## Best solution

Diagnose the 1.135.0-to-1.136.1 regression across Copilot request preparation, file-tool execution, and Remote-SSH extension-host transport, then ensure large search results are bounded and every stalled tool or request path completes or surfaces an explicit timeout/error.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/toolCallingLoop.ts`, `extensions/copilot/package.json`, `extensions/copilot/src/platform/search/vscode-node/searchServiceImpl.ts`, `src/vs/platform/remote/common/remoteAgentConnection.ts`

- **Behavior:**

  > In a large Remote-SSH workspace, enabling listDirectory or textSearch must not leave a Copilot Agent turn indefinitely at Loading or Connecting. A large tool result must be bounded, and every request-preparation or tool-execution path must either continue the turn or return an explicit timeout/error. Existing Explorer, terminal, SCM, and other search-tool behavior must remain responsive. Acceptance includes separate checks for listDirectory, textSearch, a fresh chat, and a chat containing a previously large result.
- **Trace:**

  > The report isolates a regression between VS Code 1.135.0/Copilot Chat 0.63.0 and 1.136.1/0.64.1, with an independent confirmation at https://github.com/microsoft/vscode/issues/334726#issuecomment-5438790619. extensions/copilot/package.json contributes copilot_listDirectory without caller-visible pagination controls, while extensions/copilot/src/extension/intents/node/toolCallingLoop.ts owns agent-loop orchestration and recognizes ListDirectory and FindTextInFiles as investigating tools. The text-search API path is represented by extensions/copilot/src/platform/search/vscode-node/searchServiceImpl.ts, and the reported unacknowledged-message timeout is logged through src/vs/platform/remote/common/remoteAgentConnection.ts. The uncertainty starts at whether the regression occurs while collecting/registering tools, serializing a large tool result, scheduling the next model request, or starving Remote-SSH IPC; logs from the report suggest more than one of these paths may be involved. Keep ordinary remote file browsing, terminal operation, and unaffected search tools outside the behavioral change. Related issues https://github.com/microsoft/vscode/issues/324907 and https://github.com/microsoft/vscode/issues/332431 provide useful comparison cases but do not fully own this symptom.

## Evidence
