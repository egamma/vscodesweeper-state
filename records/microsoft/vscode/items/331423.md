# Issue #331423 — Markdown Editor: expose a command to toggle Editing / Locked mode

[https://github.com/microsoft/vscode/issues/331423](https://github.com/microsoft/vscode/issues/331423)

## Summary

Well-scoped feature request: the Markdown Editor's Editing/Locked toggle currently has no dedicated command, confirmed by checking the extension's package.json and command-registration code, so no keybinding can be assigned to it today.

## Change summary

Expose the Markdown Editor's Editing/Locked mode toggle as a VS Code command that can be bound to a keyboard shortcut.

## Best solution

Add a new `$generated` command (e.g. `markdown.editor.toggleLocked`) alongside the existing generated commands in extensions/markdown-language-features/package.json, forward it the same way registerMarkdownEditorCommands does in src/extension.shared.ts, and wire the webview's `case 'command'` handler in markdown-editor-src/editor.ts to flip `model.readonlyMode` (mirroring the `setReadonly` message path in markdownEditorProvider.ts) — following the same pattern PR #329414 used for cursor/navigation commands.

## Evidence

- **readonly state is internal only:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts handles a `setReadonly` webview message (persisting the choice via #globalState) but nothing triggers it from a VS Code command; markdown-editor-src/editor.ts sets `model.readonlyMode` only from `initialState.readonly` at construction (line 88), with the actual UI toggle logic living in the external `@vscode/markdown-editor` package, not in this checkout.
- **existing extension pattern:** src/extension.shared.ts `registerMarkdownEditorCommands` auto-registers any package.json command marked `$generated: true` and forwards it to `provider.executeCommand`, which posts `{ type: 'command', command }` to the webview — the same mechanism PR #329414 used for cursor/selection commands, and the natural place to add a toggle-lock command.
