## Summary

Team-authored bug report (alexr00), confirmed reproducible by the author even after a reload — migration telemetry is missing for a legacy Copilot CLI session that was renamed before the migrate setting was toggled on. No fix commit references this issue, so it stays open.

## Change summary

Enabling `chat.agentSessions.migrateLegacyCopilotCli` and opening a renamed legacy Copilot CLI session migrates it, but no `agentHost.legacyCopilotCliMigration` telemetry event is emitted, unlike the same flow in the Agents window.

## Best solution

Trace why `_doRestoreSession` / `_reportLegacyMigration` in src/vs/platform/agentHost/node/agentService.ts doesn't fire for a renamed session opened from the classic Sessions view — likely a different restore/lookup path than the Agents window uses for the same session — and align the two so telemetry is emitted consistently regardless of rename or which surface opens the session.
