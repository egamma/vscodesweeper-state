# Issue #167742 — [remote tunnels] no notification shows up

[https://github.com/microsoft/vscode/issues/167742](https://github.com/microsoft/vscode/issues/167742)

## Summary

The reported notification gap remains visible in current source: a stale or missing synced tunnel-use value prevents registration of the listener needed to observe its subsequent update. The issue should remain open for a bounded fix and regression test.

## Change summary

Starting a remote tunnel on one machine can fail to notify another synced machine that does not have the Remote Tunnels extension installed.

## Best solution

Ensure the recommendation contribution observes future `remoteTunnelServiceUsed` synchronization changes even when the value is initially absent or stale, while preserving the existing extension-installed, machine-name, timeout, and do-not-show-again checks.

- **Behavior:**

  > When Remote Tunnels is not installed and Settings Sync delivers a fresh `remoteTunnelServiceUsed` value for another machine, VS Code shows the existing Remote Tunnels recommendation even if the previously stored value was absent or expired when the workbench contribution initialized. It does not recommend the extension for the current machine, after the recommendation was disabled, when the extension is installed, or for an expired value. Repeated storage changes must not produce duplicate recommendations.
- **Trace:**

  > The recommendation flow is `RemoteTunnelWorkbenchContribution.recommendRemoteExtensionIfNeeded` in src/vs/workbench/contrib/remoteTunnel/electron-browser/remoteTunnel.contribution.ts. `shouldRecommend()` correctly applies the installed-extension, stored preference, timestamp, and host-name checks, but the `onDidChangeValue` subscription is created only when that predicate is already true; an absent or stale initial value therefore disables observation of the later synced update. The tunnel-start action writes the fresh user-targeted application value under `remoteTunnelServiceUsed` in the same file. Commit https://github.com/microsoft/vscode/commit/3f5e862837114d8f7475471e0e765a5f658a78f1 ensures the inactive machine has an intended tunnel name for comparison, but the subscription gate remains. Keep the change within recommendation lifecycle handling and its unit tests; do not alter tunnel startup, Settings Sync semantics, or general notification policy.
