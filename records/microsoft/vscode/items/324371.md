# Issue #324371 — Cannot read properties of undefined (reading 'length') when built-in search tool returns 0 matches

[https://github.com/microsoft/vscode/issues/324371](https://github.com/microsoft/vscode/issues/324371)

## Summary

Thanks for the detailed report — this looks like a real rendering defect: the chat webview's tool-result renderer (used for Copilot's built-in search tools, via the same tsx-tree renderer implicated in the closed #260622) crashes on an undefined text field, and here it's triggered purely by Copilot's own 0-match search branch, not by user-controllable input, so the prior 'author should null-coalesce' rationale from #260622 doesn't cover this case.

## Change summary

The chat panel shows a red 'Cannot read properties of undefined (reading length)' error whenever a built-in search tool (grep_search/semantic_search/file_search) returns 0 matches in agent mode, even though the tool call itself succeeds.

## Best solution

Add a defensive null/undefined guard for the text node in the tool-result tsx renderer (the same shared renderer implicated in https://github.com/microsoft/vscode/issues/260622), and verify the 0-match branch of extensions/copilot/src/extension/tools/node/findTextInFilesTool.tsx never hands an undefined text field into that render tree; since the exact stack is minified and the renderer may live in a bundled/external component, this needs a maintainer with build tooling to pin down the precise call site.
