# Issue #335666 — Customization migrations - not seeing a failure in case of a name conflict

[https://github.com/microsoft/vscode/issues/335666](https://github.com/microsoft/vscode/issues/335666)

## Summary

Team-authored bug report (author is a VS Code maintainer) filed today while testing the in-development customization migration feature; traced the silent auto-rename behavior in source, so it stays open for the feature owner to add a visible warning/notice.

## Change summary

When a migrated customization's name conflicts with an existing one, the migration silently renames it with a `-2` suffix instead of surfacing any warning to the user.

## Best solution

In the migration completion UI (aiCustomizationManagement / customizationMigrationDashboard), surface a notice or warning when the resolved candidate name differs from the requested name, so users aren't silently left with a renamed item.
