# Issue #334714 — Agents session resume rejects older subagent.selected events missing agentDisplayName

[https://github.com/microsoft/vscode/issues/334714](https://github.com/microsoft/vscode/issues/334714)

## Summary

Real, reproducible regression, but the actual JSONL reader that enforces the required `agentDisplayName` field lives inside the bundled `@github/copilot` / `@github/copilot-sdk` runtime (package.json pins `@github/copilot@1.0.83-2`, `@github/copilot-sdk@1.0.13-preview.4`), not in this repo's TypeScript — VS Code only writes/points at `events.jsonl` and delegates parsing/resume validation to that SDK, so the fix (tolerant parsing or a fallback to `agentName`) has to land upstream in the Copilot runtime.

## Change summary

Resuming an older Agents-window session whose persisted `subagent.selected` events predate the `agentDisplayName` field now fails JSONL validation and makes the whole session unopenable.

## Best solution

File/track the schema-compat fix in the Copilot CLI/SDK's own repo (the JSONL reader in `@github/copilot`/`@github/copilot-sdk` should treat `agentDisplayName` as optional, falling back to `agentName`, and should not reject an entire log for one legacy event); on the VS Code side, `src/vs/platform/agentHost/node/copilot/buildSessionEvents.ts` already documents that "the Copilot SDK owns the authoritative event-format schema version", confirming there's no local validation step to patch here.
