# Issue #334714 — Agents session resume rejects older subagent.selected events missing agentDisplayName

[https://github.com/microsoft/vscode/issues/334714](https://github.com/microsoft/vscode/issues/334714)

## Summary

Credible, well-investigated regression, but the actual JSONL session reader/validator that rejects the older `subagent.selected` events lives in the bundled `@github/copilot` runtime (a compiled dependency of the Copilot extension, `extensions/copilot/package.json` pins `@github/copilot ^1.0.73`), not in vscode's own TypeScript source — I found no JSONL parser, no `SubagentSelectedData` schema, and no matching error string anywhere in this repo, so there's nothing here to fix directly.

## Change summary

Resuming an older Agents session fails because the bundled Copilot session reader now requires `agentDisplayName` on `subagent.selected` events that older builds wrote without it, with no fallback/migration.

## Best solution

The Copilot CLI/agent runtime team (owner of the `@github/copilot` package that ships the session store reader) needs to add backward-compatible parsing — default `agentDisplayName` to `agentName` when absent, and avoid failing the whole JSONL file on one non-conforming line. VS Code itself only surfaces the `session.resume` failure; the fix belongs upstream in that dependency, then flows into vscode via a version bump of the bundled package.
