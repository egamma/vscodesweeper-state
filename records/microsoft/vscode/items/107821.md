# Issue #107821 — Git conflict resolution "accept both changes" deletes lines not related with the conflict

[https://github.com/microsoft/vscode/issues/107821](https://github.com/microsoft/vscode/issues/107821)

## Summary

Keep open: current main still allows a stale CodeLens conflict object to edit outdated line ranges when different conflicts are accepted before CodeLens refresh completes, which can delete unrelated source lines.

## Change summary

Rapidly accepting successive merge conflicts through the inline CodeLens actions can apply the second resolution to stale line ranges and delete unrelated lines.

## Best solution

Ensure every inline conflict-resolution action targets a conflict resolved against the current document version, or safely declines an action whose captured conflict ranges became stale. Rapidly resolving consecutive conflicts must produce the same content as resolving them after each CodeLens refresh.

- **Behavior:**

  > Resolving two different merge conflicts in rapid succession through the inline CodeLens actions must resolve exactly those two conflicts. No unrelated line may be removed or replaced, regardless of whether CodeLens refresh has completed between actions. Acceptance should cover Accept Current, Accept Incoming, and Accept Both, and should verify that deliberate repeated activation of one already-applied action remains harmless.
- **Trace:**

  > MergeConflictCodeLensProvider in extensions/merge-conflict/src/codelensProvider.ts captures an IDocumentMergeConflict object in each command. CommandHandler.accept in extensions/merge-conflict/src/commandHandler.ts trusts that object for the `known-conflict` path, while DocumentMergeConflict.applyEdit in extensions/merge-conflict/src/documentMergeConflict.ts reads and replaces the current document using ranges captured before earlier edits shifted the file. The `applied` guard added by https://github.com/microsoft/vscode/commit/5597167c4c523e89ba114e364fe3314df6695b67 prevents repeated application of the same object but does not protect a different stale conflict object. Preserve the existing resolution semantics, blank-line behavior tracked separately by https://github.com/microsoft/vscode/issues/123721, and command-palette behavior; the boundary is stale inline-action identity and range validation. No existing merge-conflict extension test files were found, so the plan must establish a repeatable integration or extension-host validation before implementation.

## Evidence

- **current source path:** extensions/merge-conflict/src/codelensProvider.ts constructs commands whose arguments retain IDocumentMergeConflict objects and their parsed ranges; extensions/merge-conflict/src/commandHandler.ts accepts that known conflict directly, and extensions/merge-conflict/src/documentMergeConflict.ts reads and replaces the current document using those captured ranges.
- **source reproduction:** After resolving one conflict, later conflicts move in the document, but a still-visible CodeLens for another conflict can invoke its previously captured object. Its `applied` flag is still false, so `applyEdit` uses the stale range against the modified document and can replace unrelated lines.
- **partial prior fix:** Commit https://github.com/microsoft/vscode/commit/5597167c4c523e89ba114e364fe3314df6695b67 fixed https://github.com/microsoft/vscode/issues/79125 by preventing the same DocumentMergeConflict object from being applied twice. It does not protect a different conflict object whose range became stale after the first edit.
- **canonical status:** The younger report https://github.com/microsoft/vscode/issues/191038 was closed explicitly as a duplicate of this issue, supporting this issue as the canonical report for rapid successive conflict actions.
- **distinct related issue:** https://github.com/microsoft/vscode/issues/123721 remains open but concerns preservation of a single blank line, not stale ranges and unrelated-line deletion, so it does not own this bug.
- **continued impact:** Multiple commenters independently reproduced unrelated-line deletion when accepting successive conflicts before the previous CodeLens disappeared; comments in January 2024 still reported the behavior after the narrower December 2022 double-click fix.
