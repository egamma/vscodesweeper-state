# Issue #257639 — right-to-left display in search mode

[https://github.com/microsoft/vscode/issues/257639](https://github.com/microsoft/vscode/issues/257639)

## Summary

Keep open: the report has concrete steps (paste long Hebrew text, enable word wrap, find a word) and a second reporter confirms a related shift with ASCII text, but this is a rendering/bidi-reordering symptom I cannot confirm without running the editor, so it stays a valid unconfirmed bug rather than a needs-info or a close. The steps as written are sufficient for a maintainer to retest on a current build.

## Change summary

When a find match is highlighted, words on the affected line shift position in right-to-left (and sometimes long ASCII) wrapped text, and the original layout returns only after leaving the find/search view.

## Best solution

Confirm on current main and, if it reproduces, fix how find-match inline decorations split a wrapped line into separate spans in the editor's line renderer (src/vs/editor/common/viewLayout/viewLineRenderer.ts together with src/vs/editor/browser/viewParts/viewLines/viewLine.ts), since per-span bidi resolution is the likely cause of the reordering; if it turns out to be the broader unsupported-RTL story, fold it into https://github.com/microsoft/vscode/issues/11770 explicitly rather than leaving it implicit.
