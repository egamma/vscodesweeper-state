# Issue #312431 — Completion of PowerShell parameters in terminal doesn't work

[https://github.com/microsoft/vscode/issues/312431](https://github.com/microsoft/vscode/issues/312431)

## Summary

Keep open: the current completion pipeline discovers PowerShell command names but does not obtain parameters for Get-ChildItem. An independently reported parameter-completion regression was explicitly consolidated here; the related open issues do not own the same observable symptom.

## Change summary

Restore PowerShell cmdlet parameter suggestions when Ctrl+Space is pressed after a command such as Get-ChildItem -.

## Best solution

Make terminal IntelliSense provide PowerShell cmdlet parameters for the current command and cursor position while preserving command-name and path completion. Establish a performant completion contract before implementation rather than treating command discovery as parameter completion.

- **Behavior:**

  > In an integrated PowerShell terminal with an empty profile, Ctrl+Space currently suggests command names but does not suggest parameters after Get-ChildItem -. Completion should offer valid parameters for the command at the cursor, filter a partial parameter prefix, and insert the selected parameter without damaging the preceding command. Existing command-name and path suggestions must remain functional. Acceptance includes the reported Windows/PowerShell setup and a second built-in cmdlet, without introducing noticeable terminal stalls.
- **Trace:**

  > getPwshGlobals in extensions/terminal-suggest/src/shell/pwsh.ts retrieves command and alias metadata, not contextual parameter completions. The registered provider in extensions/terminal-suggest/src/terminalSuggestMain.ts combines these globals with availableSpecs, then calls getCompletionItemsFromSpecs; Get-ChildItem has no spec, and discovered globals are added only for command tokens. TerminalCompletionService aggregates providers and resolves resource fallbacks, while the current language-server path supports only Python and shellIntegration.ps1 has no TabExpansion2 completion bridge. Source inspection establishes the missing parameter source, but not a performant design for recovering it or Windows runtime behavior. Preserve existing command/path completion and keep Starship rendering, disabled-shell-integration key handling, and newly defined function discovery outside this report's acceptance boundary. https://github.com/microsoft/vscode/issues/295891 was consolidated here; https://github.com/microsoft/vscode/issues/285640#issuecomment-3704963389 records the performance problems with earlier session-derived completion.
- **Open decisions:**
  - Should restored parameter completion reflect the active PowerShell session, including imported modules and custom argument completers, or initially cover installed cmdlet metadata independently of session state?
