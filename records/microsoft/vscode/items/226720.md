# Issue #226720 — `FileSearchProviderOptions#session` should not be `undefined`

[https://github.com/microsoft/vscode/issues/226720](https://github.com/microsoft/vscode/issues/226720)

## Summary

Still reproduces on main: when `config.cacheKey` is falsy, `FileSearchManager.getSessionTokenSource` returns `undefined`, so `session` passed to the search-extension provider is `undefined` even though `FileSearchProviderOptions#session` is typed as always-present `unknown`. A prior review's implemented-on-main claim (commit 0e62f015) was already refuted by an independent re-review, and I found no later fix.

## Change summary

`FileSearchProviderOptions#session` can be `undefined` at runtime despite the public type saying it always has a value, breaking providers that use it as a WeakMap key.

## Best solution

In src/vs/workbench/services/search/common/fileSearchManager.ts, ensure `session` is always a defined value (object or token) even when there is no cache key to track a persistent SessionLifecycle for — e.g. synthesize a one-off session object for that single search instead of leaving it undefined.
