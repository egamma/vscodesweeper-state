# Issue #336821 — Editing repository .md file floods renderer process

[https://github.com/microsoft/vscode/issues/336821](https://github.com/microsoft/vscode/issues/336821)

## Summary

Credible, specific, cross-version-confirmed repro (typing in a git-tracked .md file pegs a CPU core; non-repo or non-md files are unaffected), already carrying `recent-regression`. I found a strong but unconfirmed candidate in the new observable-based markdown rich-link presentation code, which is the only markdown+git-specific machinery on current main — but I can't prove it's the CPU sink without a profile, so this needs a diagnosis pass before any fix.

## Change summary

Editing a markdown file that is part of a git repository causes sustained high CPU usage in the renderer process; the same file outside a repo, or non-markdown files, do not trigger it.

## Best solution

Capture a CPU profile of the renderer while reproducing, and check whether it points at extensions/markdown-language-features/src/preview/linkPresentation/{linkPresentationService,gitLinkPresentationResolver,workspaceLinkPresentationResolver}.ts (the new git/workspace rich-link resolvers, which are the only markdown-specific code that depends on the file being in a git repo) or at Git decorations/NES; fix the hot path once identified (e.g. missing debounce or a reactive loop in the `@vscode/observables` autorun chain).
