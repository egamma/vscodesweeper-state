# Issue #342690 — Customizations can't install plugins for the Copilot harness in remote windows: "The selected agent does not support SDK plugin installation"

[https://github.com/microsoft/vscode/issues/342690](https://github.com/microsoft/vscode/issues/342690)

## Summary

The remote installation gap remains in current source: Customizations delegates to an optional plugin-install method that the editor remote client does not implement. Keep this older, well-diagnosed report open; the newer WSL report corroborates the same failure.

## Change summary

Installing marketplace plugins from Customizations fails when the selected Copilot harness runs on a remote host.

## Best solution

Support installation through the owning remote Copilot provider while preserving SDK-owned inventory and exact session/chat context. Unsupported hosts should expose installation unavailability before offering an actionable Install control.

- **Behavior:**

  > In a Remote Tunnels or WSL window, installing a marketplace plugin from Customizations for a Copilot harness should install it for that remote provider and make it available in new sessions. Installation must use the same authoritative inventory as provider plugin commands. Existing local installation behavior must remain unchanged. A host without installation support must communicate that limitation before offering an actionable Install control.
- **Trace:**

  > CustomizationMarketplaceInstallService.install() delegates to the active harness provider after marketplace trust handling. AgentHostCustomizationMarketplaceInstallProvider.install() requires IAgentHostService.installPlugin for configuredPlugin and providerPlugin resources, but EditorRemoteAgentHostServiceClient supplies no implementation; the local client delegates through AgentHostManagementService. The uncertainty starts at how remote management operations can reach the owning provider across the supported transport and capability boundaries; that path has not been fully traced. Preserve exact advertised session/chat identities, trust handling, and SDK-owned inventory rather than introducing a second persistent store. The intended ownership is documented in https://github.com/microsoft/vscode/issues/338975; https://github.com/microsoft/vscode/issues/349560 corroborates the current symptom.
