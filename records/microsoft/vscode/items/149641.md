# Issue #149641 — Unify inline edit experience

[https://github.com/microsoft/vscode/issues/149641](https://github.com/microsoft/vscode/issues/149641)

## Summary

The accepted, team-authored debt remains on current main: Explorer and terminal tabs still implement separate inline input renderers, while Local History still moves focus to a Quick Input. No fixing commit, open canonical, or other factual close applies, so the Backlog item should remain open.

## Change summary

Provide a reusable inline-edit renderer that gives list and tree surfaces a consistent rename experience and enables additional consumers such as Outline.

## Best solution

Establish a composable list/tree renderer with a documented editing contract, then migrate Explorer, terminal tabs, and Timeline/Local History while preserving necessary domain-specific validation and selection behavior. The resulting primitive should be reusable by other list-based views such as Outline.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/list/list.ts`, `src/vs/base/browser/ui/list/listWidget.ts`, `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`, `src/vs/workbench/contrib/timeline/browser/timelinePane.ts`, `src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts`, `src/vs/base/test/browser/ui/list/listWidget.test.ts`
- **Validation:** Add focused list-renderer lifecycle tests covering start, accept, cancel, validation, blur, disposal, and row recycling; then manually verify rename in Explorer, terminal tabs, and Local History remains inline and preserves each agreed selection, icon, and validation behavior.
- **Behavior:**

  > Renaming an editable item in Explorer, terminal tabs, or Timeline should remain anchored to that row rather than moving focus to a separate input surface. Enter accepts, Escape cancels, validation remains visible and accessible, and row recycling or cancellation must not commit stale text. The agreed icon, initial-selection, and blur semantics should be consistent unless a documented consumer option intentionally differs. Existing Explorer filename-extension selection and validation behavior must remain available.
- **Trace:**

  > Explorer editing is implemented directly by FilesRenderer.renderInputBox in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts; terminal editing independently duplicates the InputBox lifecycle in TerminalTabsRenderer._renderInputBox in src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts. Local History rename in src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts still uses IQuickInputService.createInputBox, while Timeline rows are rendered by TimelineTreeRenderer in src/vs/workbench/contrib/timeline/browser/timelinePane.ts. The existing PipelineRenderer in src/vs/base/browser/ui/list/listWidget.ts is internal infrastructure for focus, selection, and accessibility composition, not an editable-row component available to these consumers. https://github.com/microsoft/vscode/issues/145236 confirms that Timeline inline rename was intentionally consolidated into this renderer-level debt. Preserve consumer-specific validation, Explorer's file-icon updates and filename-part selection, terminal title persistence, Local History source updates, keyboard accessibility, and renderer disposal; unrelated list rendering and extension tree-view APIs are outside this issue unless explicitly added to scope.
- **Open decisions:**
  - During editing, should every row keep its icon visible, hide it, or expose an explicit per-consumer option?
  - Which initial text-selection behaviors are part of the shared contract: select all by default with an Explorer filename-stem option, or preserve each consumer's current policy?
  - Should losing focus accept edits consistently across all consumers, cancel them consistently, or remain an explicit per-consumer behavior?

## Evidence

- **current Explorer path:** src/vs/workbench/contrib/files/browser/views/explorerViewer.ts still contains FilesRenderer.renderInputBox, including Explorer-specific icon rendering, filename-stem selection, validation, F2 selection cycling, and blur handling.
- **current terminal path:** src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts still contains TerminalTabsRenderer._renderInputBox as a separate InputBox implementation; it selects the complete title and clears the row action bar while editing.
- **current Timeline path:** src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts still implements workbench.action.localHistory.rename with IQuickInputService.createInputBox, so renaming leaves the Timeline row rather than editing it inline.

It does not expose the reusable editable-row renderer requested here; IListRenderer in src/vs/base/browser/ui/list/list.ts remains the low-level lifecycle contract.
