# Issue #304713 — View References as Tree

[https://github.com/microsoft/vscode/issues/304713](https://github.com/microsoft/vscode/issues/304713)

## Summary

Keep this accepted, community-supported request open: References still groups results by file without the requested directory hierarchy or list/tree switch. A maintainer explicitly consolidated the older matching request into this issue.

## Change summary

Add a directory-tree presentation of reference results alongside the existing file-list presentation, consistent with Search and Source Control.

## Best solution

Offer switchable list and directory-tree presentations in the built-in References view while preserving semantic results and existing navigation. Plan the initial mode and persistence semantics with the area owner, taking account of the earlier preference for reusable resource-tree support.

## Plan brief

- **Likely files:** `extensions/references-view/src/references/model.ts`, `extensions/references-view/src/references/index.ts`, `extensions/references-view/src/tree.ts`, `extensions/references-view/src/navigation.ts`, `extensions/references-view/package.json`, `extensions/references-view/package.nls.json`
- **Validation:** In an Extension Development Host, list semantic references spanning sibling and nested directories and multiple workspace roots. Verify tree mode groups them by directory, switching back restores the file-list presentation without changing results, and reference opening, F4/Shift+F4 navigation, removal, refresh, and keyboard traversal still work. Verify initial mode and reload behavior against the maintainer-approved persistence contract.
- **Behavior:**

  > References currently presents a root-level list of files with reference occurrences beneath each file, making large result sets difficult to understand by directory. Users should be able to switch between that existing presentation and a directory-tree presentation of the same semantic references. Switching must not change which references were found or their target locations. Acceptance includes nested-directory and multi-root results, keyboard access to both modes, and unchanged reference opening, navigation, removal, and refresh behavior.
- **Trace:**

  > ReferencesTreeInput.resolve in extensions/references-view/src/references/model.ts constructs ReferencesModel and ReferencesTreeDataProvider; the model sorts locations into FileItem objects and the provider exposes only file/reference nodes. SymbolsTree in extensions/references-view/src/tree.ts hosts this provider through a shared tree also used for call and type hierarchies. ReferencesModel supplies navigation, highlighting, removal, copying, and drag resources, so directory presentation must preserve those contracts rather than change reference discovery. References command registration is in src/references/index.ts, and configuration and menus are in package.json. The existing references.preferredLocation setting selects the destination surface, not its layout. Historical review at https://github.com/microsoft/vscode-references-view/pull/54#issuecomment-537042017 favored reusable resource-tree behavior; https://github.com/microsoft/vscode/issues/81757 tracks the related API question but does not settle this feature's default or persistence. Keep call/type hierarchy presentations and language-provider semantics outside this request's scope.
- **Open decisions:**
  - Should References initially retain the existing file-list presentation or default to directory-tree mode?
  - Should the selected presentation persist across reloads, and if so should it be workspace-specific or shared across workspaces?
