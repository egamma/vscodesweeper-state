# Issue #283285 — Update VS Code Insiders Fails regularly when following the instructions to restart

[https://github.com/microsoft/vscode/issues/283285](https://github.com/microsoft/vscode/issues/283285)

## Summary

Valid Windows update bug — the Inno Updater fails with 'Access is denied' (os error 5) when renaming the running executable during update. Multiple users confirm. Several related fixes have landed since this was filed (double-update fix, COM surrogate termination, skip-if-already-installing), but none directly address this specific file-lock scenario, and the problem persists per recent comments.

## Change summary

VS Code Insiders update fails on Windows with 'Access is denied' when the Inno Updater tries to rename the running executable.

## Best solution

The Inno Updater needs better handling of locked executables — either retry logic with backoff, or ensuring the running VS Code process fully exits before the rename is attempted. The fix belongs in the update service (src/vs/platform/update/electron-main/updateService.win32.ts) or the inno_updater Rust binary itself (build/win32/).
