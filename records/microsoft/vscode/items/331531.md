This matches delayed non-trigger-character completions here, rather than merely sharing an AI-related root cause.
- **Current source explains the wait:** src/vs/editor/contrib/suggest/browser/suggestModel.ts:387-530 routes automatic suggestions through _waitForInlineCompletionsAndTrigger when quickSuggestions is offWhenInlineCompletions and an enabled inline provider exists. While inline state is loading, it waits; a 750 ms timeout triggers language suggestions. SuggestModel.trigger at lines 535-592 then calls provideSuggestionItems with CompletionTriggerKind.Invoke unless a trigger character was supplied.
- **Existing configurable coexistence:** src/vs/editor/common/config/editorOptions.ts:3794-3835 defines editor.quickSuggestions, defaults other to offWhenInlineCompletions, and supports on. In SuggestModel._doTriggerQuickSuggest, on bypasses the inline-resolution wait. https://github.com/microsoft/vscode/issues/317863#issuecomment-4519342542 documents this configuration, and https://github.com/microsoft/vscode/issues/317863#issuecomment-4567293868 explicitly keeps the canonical open for discussion. This restores independent language triggering, but does not implement AI ranking or a unified multiple-candidate list.
- **Related upstream PR is not a VS Code fix:** https://github.com/hudson-trading/slang-server/pull/468 changes completion-context accuracy when backspacing and retyping identifiers. Its description explicitly says inline suggestions may need to be disabled to see the benefit and links this report; it does not change VS Code's inline-versus-language scheduling.
