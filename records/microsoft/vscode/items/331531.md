# Issue #331531 — Intellisense: AI Inline suggestions block LSP suggestions-  they should race instead

[https://github.com/microsoft/vscode/issues/331531](https://github.com/microsoft/vscode/issues/331531)

## Summary

Real, well-diagnosed request: on main, `SuggestModel._waitForInlineCompletionsAndTrigger` (src/vs/editor/contrib/suggest/browser/suggestModel.ts, lines ~458-521) already bounds the wait for inline completions to 750ms before firing the LSP quick-suggestions trigger, but it's still a sequential wait-then-trigger, not a true race — so the reporter's core ask (query both concurrently) is not yet implemented.

## Change summary

Requests that AI inline-completion requests and LSP completion requests race instead of the LSP request waiting on inline completions to resolve/timeout first, and floats the idea of merging single-token AI suggestions into the completions widget/ranking.

## Best solution

Route to the suggest/inline-completions owners as a concrete architecture proposal: replace the existing bounded wait-and-trigger pattern in suggestModel.ts's `_waitForInlineCompletionsAndTrigger` with a true concurrent request, or at least evaluate lowering/removing the 750ms gate for invoked (non-auto) completions, which the reporter says are hit hardest.

## Evidence

- **current mechanism on main:** src/vs/editor/contrib/suggest/browser/suggestModel.ts:387-455 shows quick suggestions only trigger immediately when `editor.quickSuggestions` isn't 'offWhenInlineCompletions'; when it is (the default for 'other' tokens per src/vs/editor/common/config/editorOptions.ts:3774), it calls `_waitForInlineCompletionsAndTrigger` instead of triggering right away.
- **bounded but still sequential:** src/vs/editor/contrib/suggest/browser/suggestModel.ts:502-520 waits for the inline-completion model's state via autorun, with a `disposableTimeout(...,750,...)` fallback — i.e. LSP quick suggestions are delayed up to 750ms behind inline completions rather than requested concurrently, which is the exact behavior the reporter is describing (just now capped instead of unbounded).
- **related maintainer-documented decision:** https://github.com/microsoft/vscode/issues/317863 is an open, actively-discussed issue where project maintainer @alexdima explains the 1.121 default change to `editor.quickSuggestions: offWhenInlineCompletions` and gives the settings workaround (`"other": "on"`); it covers the default-value/UX debate but not this issue's specific 'race the two providers' implementation ask, so it's related context rather than a duplicate target.
- **workaround exists today:** Setting `editor.quickSuggestions.other` to `on` (as documented in #317863) restores immediate LSP triggering without waiting on inline completions, though it loses the offWhenInlineCompletions declutter behavior.
