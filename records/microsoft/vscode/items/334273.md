# Issue #334273 — Managed sandbox policy can be dropped when policy sources disagree

[https://github.com/microsoft/vscode/issues/334273](https://github.com/microsoft/vscode/issues/334273)

## Summary

Real, source-confirmed bug: managed-settings resolution picks a single winning channel per key by fixed precedence (native MDM > server > file) rather than composing conflicting `sandbox.enabled` values in the restrictive direction the Copilot runtime uses, so a device-level `false` can suppress a server-forced `true`.

## Change summary

VS Code's managed-settings resolver can silently drop a server-forced sandbox-enabled policy when a lower- or higher-precedence source disagrees, leaving new chats on a runtime that doesn't enforce the intended sandbox.

## Best solution

Give `sandbox.enabled` (and likely `sandbox.allowBypass`) a dedicated restrictive-direction composition rule in `pickManagedSettings`/`AgentHostEnablementService` instead of the generic single-winner-per-key precedence, so VS Code's `managedSandboxEnforced` always agrees with the Copilot runtime's own composed sandbox decision; this is a design/security decision best made by the sandbox-policy owners, likely alongside the sibling issues (#334274, #334275) filed in the same review pass.
