# Issue #225835 — Automatically Convert Windows File Paths to WSL Paths When Dragged into VS Code Terminal

[https://github.com/microsoft/vscode/issues/225835](https://github.com/microsoft/vscode/issues/225835)

## Summary

A real path-interoperability gap remains for Windows files dropped into remote WSL terminals. The request is already correctly routed and accepted into the Backlog, while the related open issue covers terminal links rather than dropped input.

## Change summary

Convert dropped Windows file paths such as `C:/Users/...` into WSL paths such as `/mnt/c/Users/...` before inserting them into a WSL terminal.

## Best solution

Provide a WSL-aware path translation hook across the local UI and remote terminal boundary, then use it from terminal drag-and-drop handling. Preserve the existing conversion behavior for locally hosted WSL shells.

- **Reason:** Removing local/remote path impedance advances VS Code's durable remote-development experience.

## Evidence

- **current source:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts routes dropped files through `sendPath`, but src/vs/workbench/contrib/terminal/common/terminalEnvironment.ts only calls `getWslPath(..., 'win-to-unix')` when the terminal backend OS is Windows; a remote WSL backend instead normalizes the local URI to a `C:/...`-style path.
- **maintainer analysis:** A maintainer described the same remote-WSL limitation and the missing UI-to-WSL conversion hooks at https://github.com/microsoft/vscode/issues/232613#issuecomment-2449504755.
- **related issue:** https://github.com/microsoft/vscode/issues/96941 remains open but concerns detecting `/mnt/...` paths in terminal output as links, not converting Windows paths inserted through drag-and-drop.
- **existing partial support:** https://github.com/microsoft/vscode/pull/170216 and commit c8688a73682d71f6bc7e6cd569fc80083b329f0c added shell-aware path preparation, including conversion for locally hosted WSL terminals, but did not provide the remote WSL mapping requested here.
