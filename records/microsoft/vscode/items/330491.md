# Issue #330491 — Move Chat into Side Bar silently loses imported chats

[https://github.com/microsoft/vscode/issues/330491](https://github.com/microsoft/vscode/issues/330491)

## Summary

Well-diagnosed, source-confirmed bug: moving an imported chat editor to the sidebar closes the editor before the destination view can load the session, and imported sessions are deliberately excluded from disk persistence, so the conversation is unrecoverably lost.

## Change summary

Using Chat: Import Chat... then Move Chat into Secondary Side Bar silently discards the imported conversation instead of moving it.

## Best solution

In chatMoveActions.ts's moveToSidebar, acquire/retain a reference to the imported session's model (or otherwise keep it alive) before closing the source editor, and release it only after the destination view has loaded it — or, simpler, disable the move-to-view actions for imported (unpersisted) chats until they're converted into a normal local session.

## Evidence

- **closes before load:** src/vs/workbench/contrib/chat/browser/actions/chatMoveActions.ts moveToSidebar() calls editorService.closeEditor(...) before view.loadSession(chatEditorInput.sessionResource), releasing the editor's last model reference before the destination can acquire it.
- **no persistence for imported chats:** src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts shouldStoreSession() (line 373) explicitly excludes `session.isImported` sessions from disk persistence, and shouldBeInHistory() (line 518) excludes them from history.
- **load falls through to disk read:** acquireOrRestoreLocalSession() (chatServiceImpl.ts line 603) first tries acquireExistingSession (now gone after close), then falls back to `_chatSessionStore.readSession(localSessionId)`, which returns nothing for an unpersisted imported session, so the reference resolves to undefined and the conversation is lost with no error shown.
