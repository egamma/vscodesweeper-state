# Issue #303033 — Multiple active browser tools in GitHub Copilot Chat create ambiguous command routing and break autonomous/programmatic usage

[https://github.com/microsoft/vscode/issues/303033](https://github.com/microsoft/vscode/issues/303033)

## Summary

Valid feature request for tool conflict detection when multiple browser-capable tools are active (built-in browser tools + Chrome DevTools MCP). No conflict-detection mechanism exists on current main for this scenario. The issue is largely AI-generated and verbose but identifies a real UX gap. Related issues exist for MCP dedup (#316362) and tool name uniqueness (#319716), but neither fully owns this specific browser-tool-ambiguity scenario. Keeping open as a feature request.

## Change summary

When both the built-in browser chat tools and Chrome DevTools MCP extension are active, browser commands route ambiguously with no user-facing warning.

## Best solution

The broader tool-conflict detection question is partially addressed by dedup work in the MCP layer (https://github.com/microsoft/vscode/issues/316362). The best end state is a general mechanism in the tool registration layer that detects overlapping tool capabilities and surfaces a clear conflict warning or precedence choice — not browser-specific but applicable to all tool categories. If a browser-specific solution is pursued, it belongs in `src/vs/workbench/contrib/browserView/electron-browser/tools/browserTools.contribution.ts` or the chat tool registration layer. Consider whether https://github.com/microsoft/vscode/issues/316362 should absorb the broader 'tool conflict visibility' concern.
