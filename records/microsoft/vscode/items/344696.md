# Issue #344696 — Modern UI: Command Palette has no entrance animation whenever frosted glass is active

[https://github.com/microsoft/vscode/issues/344696](https://github.com/microsoft/vscode/issues/344696)

## Summary

The animation inconsistency remains in current source. Quick-input motion is deliberately suppressed to preserve backdrop blur, with an explicit test enforcing that behavior; keep this open for a motion-and-material design decision rather than closing it as fixed.

## Change summary

Make Modern UI popup entrance motion consistent with the motion setting regardless of whether frosted glass is enabled.

## Best solution

Provide consistent, reduced-motion-aware popup entrances without breaking backdrop blur or fixed-position hover placement. The Modern UI owner should agree on the intended motion/material behavior before changing the existing suppression contract.

## Evidence

- **Quick-input suppression remains:** src/vs/workbench/contrib/modernUI/browser/media/frostedGlass.css:19–24 still applies animation: none and will-change: auto to non-overlay quick inputs whenever the supported frosted-glass styles apply, independently of the motion setting.
- **Existing motion capability does not cover glass:** src/vs/platform/quickinput/browser/media/quickInput.css:16–19 provides quick-input-widget-open under modern-ui.monaco-enable-motion, but the more-specific glass selector overrides it. Disabling glass restores this path, but does not satisfy the request to retain both effects.
- **Intentional material safeguard:** src/vs/workbench/contrib/modernUI/test/browser/frostedGlass.test.ts contains 'suppresses quick input motion without retaining backdrop isolation', explicitly expecting no opening or closing animation when glass is supported. The production CSS explains that persistent opacity animation would isolate the blur from the workbench backdrop.
- **Action-widget distinction:** frostedGlass.css:40–46 applies action-widget-scale-open to action-widget-animated pickers. src/vs/platform/actionWidget/browser/actionWidget.css defines that keyframe but applies its ordinary entrance animation only to action-widget-dropdown, so dropdowns already have non-glass motion while other animated pickers lack the corresponding general rule.
- **Lifecycle boundary:** src/vs/platform/quickinput/browser/quickInputController.ts removes the settled marker when showing a hidden widget and settles entrance motion on animationend or before displaying an item hover. Any revised motion must preserve viewport positioning of those hovers.
