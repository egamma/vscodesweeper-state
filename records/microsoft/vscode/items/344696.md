# Issue #344696 — Modern UI: Command Palette has no entrance animation whenever frosted glass is active

[https://github.com/microsoft/vscode/issues/344696](https://github.com/microsoft/vscode/issues/344696)

## Summary

Keep open for motion-consistency polish: current main explicitly suppresses Command Palette animation under frosted glass, and a regression test requires that suppression to protect backdrop rendering. The linked merged PR introduced this behavior; it does not resolve the request for a glass-safe entrance animation.

## Change summary

Make Modern UI popup entrance animations consistent with motion preferences regardless of whether frosted glass is enabled.

## Best solution

Provide consistent entrance motion without breaking backdrop blur, popup positioning, or reduced-motion behavior. The area owner should review replacing the explicitly tested quick-input suppression, while distinguishing ordinary animated action widgets from dropdowns that already animate without glass.

## Evidence

- **Current quick-input behavior:** src/vs/platform/quickinput/browser/media/quickInput.css:16-19 applies quick-input-widget-open when Modern UI and motion are enabled. src/vs/workbench/contrib/modernUI/browser/media/frostedGlass.css:19-24 overrides it with animation: none and will-change: auto under supported frosted-glass conditions, explicitly to avoid isolating the blur from the workbench backdrop.
- **Intentional, tested rendering tradeoff:** src/vs/workbench/contrib/modernUI/test/browser/frostedGlass.test.ts:459-497 contains 'suppresses quick input motion without retaining backdrop isolation'. It explicitly expects no opening or closing animation when glass is supported, even with monaco-enable-motion, while retaining blur(12px) on the paint layer. This supports classifying the requested improvement as polish rather than an accidental violation of the current implementation contract.
- **Action-widget distinction:** The action-widget-animated scale entrance is applied inside frostedGlass.css:40-43. However, src/vs/platform/actionWidget/browser/actionWidget.css:21-24 separately applies action-widget-dropdown-open to Modern UI dropdowns without requiring glass. The report's broader claim that action-widget pickers never animate without glass therefore needs to distinguish these two widget paths.
- **Existing settings do not cover the central ask:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.reduceMotion and workbench.modernUIFrostedGlass independently. Disabling glass restores the ordinary quick-input animation but removes the requested material; changing workbench.reduceMotion does not bypass the glass-specific suppression. Neither setting delivers animation and frosted glass together.
- **Asynchronous activation:** FrostedGlassContribution in src/vs/workbench/contrib/modernUI/electron-browser/frostedGlass.contribution.ts starts initializeGPUCompositing asynchronously and applies modern-ui-frosted-glass only after GPU compositing is confirmed. This supports the reported startup-dependent change in animation behavior, though the reported timing was not executed or measured during this review.

Its later cross-reference at https://github.com/microsoft/vscode/pull/337468#issuecomment-6463531461 identifies https://github.com/microsoft/vscode/issues/344696 as a follow-up concerning these animation couplings, not as work completed by that PR.
