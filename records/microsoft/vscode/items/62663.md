# Issue #62663 — API should support to create a folder

[https://github.com/microsoft/vscode/issues/62663](https://github.com/microsoft/vscode/issues/62663)

## Summary

Keep open: explicit folder creation remains missing from the public WorkspaceEdit API, despite existing filesystem and internal bulk-edit support. The related request is newer, so it cannot replace this re-reviewed, team-authored issue as the duplicate canonical.

## Change summary

Allow extensions and language-server integrations to express folder creation in a WorkspaceEdit without creating and deleting a temporary file.

## Best solution

Expose explicit folder creation through the public WorkspaceEdit contract, with defined existing-target semantics and normal edit lifecycle behavior. Coordinate the overlapping folder-creation work with https://github.com/microsoft/vscode/issues/340426 while keeping its additional copying request distinct.

An extension-host acceptance check should apply the folder edit and observe the normal creation events. No tests were executed during this read-only review.
- **Behavior:**

  > Extensions need to create a folder explicitly as part of a WorkspaceEdit, including an empty folder, without creating and deleting a placeholder file. The operation should participate in normal workspace-edit lifecycle behavior and undo/redo. Acceptance should cover a new target, existing directories and files under the agreed collision policy, and unchanged existing file creation, deletion, and rename behavior.
- **Trace:**

  > The public WorkspaceEdit declaration in src/vscode-dts/vscode.d.ts and its implementation in src/vs/workbench/api/common/extHostTypes/workspaceEdit.ts have no explicit folder-creation operation. WorkspaceEdit.from in src/vs/workbench/api/common/extHostTypeConverters.ts serializes resource operations, while CreateOperation.perform in src/vs/workbench/contrib/bulkEdit/browser/bulkFileEdits.ts already supports an internal folder discriminator and an inverse delete operation. workspace.fs.createDirectory exists but does not represent an edit or deliver the documented workspace creation events, so it does not satisfy the thread's resource-operation requirement. The source establishes the gap, not an approved public signature or collision contract. Preserve existing resource-operation behavior and avoid expanding this request into file copying. Coordinate with https://github.com/microsoft/vscode/issues/340426, which includes the same folder gap plus a separate copying capability; LSP alignment may also need coordination with https://github.com/microsoft/language-server-protocol/issues/272.
- **Open decisions:**
  - Should folder creation be exposed as a distinct WorkspaceEdit method or as an explicit option on the existing creation operation?
  - What should the public operation do when its target is an existing directory or a regular file, including the meaning of overwrite and ignoreIfExists?
