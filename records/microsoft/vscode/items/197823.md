## Summary

Keep this as the canonical Android AltGr report: multiple users confirm that character entry invokes Alt+Digit shortcuts, and removing those bindings restores typing. Current source preserves the reported modifier-conflict path; no concrete fixing commit or older canonical covering the same symptom was established.

## Change summary

Android hardware-keyboard AltGr combinations invoke editor-switching shortcuts instead of inserting layout-specific symbols.

## Best solution

Make AltGr character entry coexist with ordinary Alt shortcuts in the web keybinding pipeline. First establish the affected Android browser's complete modifier-state events so the correction preserves genuine Alt shortcuts and existing desktop AltGr behavior.

- **Behavior:**

  > On Android hardware keyboards, AltGr combinations intended to type layout-specific symbols currently activate Alt+Digit shortcuts instead. The expected result is insertion of the requested character without switching editors. Ordinary Alt+Digit shortcuts must continue working, and desktop keyboard behavior must remain unchanged. Acceptance includes the reported German combinations and the independently reported AZERTY number-row combinations under default bindings.
- **Trace:**

  > StandardKeyboardEvent in src/vs/base/browser/keyboardEvent.ts preserves altKey independently of altGraphKey. Both MacLinuxKeyboardMapper.resolveKeyboardEvent and FallbackKeyboardMapper.resolveKeyboardEvent preserve that Alt modifier when constructing dispatch chords; BrowserKeyboardMapperFactory.getKeyboardMapper selects the latter for keyCode dispatch. WorkbenchKeybindingService._registerKeyListeners dispatches those chords and prevents default when a shortcut handles them. Independent reporters confirm that removing Alt+Digit bindings restores typing, but the full text log at https://github.com/microsoft/vscode/issues/197823#issuecomment-3909263079 is a Linux comparison rather than the failing Android event signature. Diagnosis must establish the Android key, code, altKey, ctrlKey, and getModifierState('AltGraph') values before concluding where the distinction can safely be made. Preserve genuine Alt shortcuts, desktop modifier conventions, and keyboard.mapAltGrToCtrlAlt semantics; do not remove default shortcuts globally. https://github.com/microsoft/vscode/issues/271402 was explicitly consolidated into this issue, while the related Nordic report at https://github.com/microsoft/vscode/issues/197826 is newer.
