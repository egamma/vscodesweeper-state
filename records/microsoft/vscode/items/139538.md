# Issue #139538 — [json] support references in schema associations

[https://github.com/microsoft/vscode/issues/139538](https://github.com/microsoft/vscode/issues/139538)

## Summary

The capability remains missing in the JSON language service: schema associations register the complete fragment-bearing URI as a schema resource but never select the referenced subschema. This issue is the older canonical report and should remain open while the upstream language-service work is tracked.

## Change summary

Allow `json.schemas` associations and document `$schema` declarations to target a subschema using a URI fragment.

## Best solution

Implement JSON Pointer and anchor fragment selection for top-level schema handles in `microsoft/vscode-json-languageservice`, then update VS Code's bundled language-service dependency while preserving whole-document schema associations.

## Evidence

- **maintainer assessment:** A VS Code maintainer confirmed that schema associations currently accept only a schema resource, not a schema reference, and identified `jsonSchemaService.ts` as the implementation location.
- **current VS Code path:** `extensions/json-language-features/server/src/jsonServer.ts` passes each configured `url` unchanged as `SchemaConfiguration.uri`; VS Code currently consumes `vscode-json-languageservice` 6.0.0-next.4.
- **upstream source gap:** Current `microsoft/vscode-json-languageservice` `JSONSchemaService.registerExternalSchema` normalizes the full URI and associates that handle with the file pattern, while `SchemaHandle.getUnresolvedSchema` loads that URI directly; unlike `$ref` resolution, this path contains no operation that selects the URI fragment's subschema.
- **upstream tracking:** https://github.com/microsoft/vscode-json-languageservice/issues/123 remains open for the same observable limitation, but it was created after this issue, so the stronger re-review rule makes this older VS Code issue the canonical report rather than a duplicate.
- **canonical evidence:** https://github.com/microsoft/vscode/issues/179270 and https://github.com/microsoft/vscode/issues/242070 were both closed by a maintainer as duplicates of this issue, confirming that this thread owns the remaining work.
