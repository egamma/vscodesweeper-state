# Issue #86564 — Support local paths in hover MarkdownString

[https://github.com/microsoft/vscode/issues/86564](https://github.com/microsoft/vscode/issues/86564)

## Summary

A prior review's fix citation (commit a068ebee8db7a76b36ae259c96b130e81931e98f, which only finalized the already-proposed API) was refuted. I found the actual implementing commit — 69896100ed4c84cda2b605a10ad339a5da8913bb (PR #142055, merged 2022-02-03) — which added `MarkdownString.baseUri`, the `resolveWithBaseUri` resolution logic in `markdownRenderer.ts`, AND wired the TypeScript extension's hover provider to pass the document's own URI as `baseUri`. This is the exact reported flow (JSDoc hover link to a same-directory file) and it is confirmed adopted on the hover call path on current `main`.

## Change summary

Relative file/image paths in hover MarkdownString (e.g. JSDoc links) resolved to the workspace root instead of the defining file's directory, unlike markdown preview.

## Best solution

Treat as fixed: MarkdownString.baseUri (stable API) plus the TS extension's hover/completions/signatureHelp call sites resolve relative links against the document URI, matching the markdown-preview behavior the reporter wanted.
