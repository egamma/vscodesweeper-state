# Issue #115157 — Modify issue reporter description text when signed in

[https://github.com/microsoft/vscode/issues/115157](https://github.com/microsoft/vscode/issues/115157)

## Summary

Keep open: the legacy reporter still promises a GitHub preview even when its signed-in Create action immediately publishes the issue. The newer reporter has not removed the legacy path, and the discussion confirms that the misleading wording can affect pre-submission review of sensitive information.

## Change summary

Make issue-reporter instructions accurately distinguish immediate issue creation from previewing an editable draft on GitHub.

## Best solution

Make the legacy reporter's description instructions match the selected submission behavior across bug, performance, and feature reports, clearly distinguishing editing before publication from editing an already-created issue. Rich-text editing and image uploads are an alternative enhancement, not necessary to resolve this wording defect.

## Evidence

- **Current misleading instructions:** Current main, inspected through GitHub's read-only contents API, retains 'You will be able to edit your issue and add screenshots when we preview it on GitHub' in src/vs/workbench/contrib/issue/browser/baseIssueReporterService.ts at lines 1206, 1223, and 1226, covering bug, performance, and feature descriptions.
- **Direct creation differs from preview:** In baseIssueReporterService.ts, issueReporter.create calls createIssue(true), whereas issueReporter.preview calls createIssue(false). With githubAccessToken, a GitHub target, and shouldCreate, createIssue calls submitToGitHub, which POSTs the issue before opening its URL. The unconditional preview promise therefore does not describe the Create action.
- **Legacy path remains reachable:** The local checkout's src/vs/workbench/contrib/issue/browser/issueFormService.ts routes web reporting to openAuxIssueReporterLegacy. src/vs/workbench/contrib/issue/electron-browser/nativeIssueFormService.ts also preserves the legacy route when issueReporter.wizard.enabled is false. The newer wizard does not establish that this issue is fixed.
- **Confirmed observable consequence:** At https://github.com/microsoft/vscode-remote-release/issues/7308#issuecomment-1271491106, a reporter explicitly confirms that there was no preview and the issue became public immediately. Maintainer chrmarti's supplied comment endorses the concern that 'preview' misleads users who need to remove sensitive data.
- **Canonical search:** Searches for issue-reporter preview and signed-in description reports found https://github.com/microsoft/vscode/issues/117657, which remains open but requests an optional draft workflow rather than correcting the misleading instructions. It is also newer than this re-reviewed issue, so it is not an eligible duplicate canonical.
