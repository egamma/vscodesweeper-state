[https://github.com/microsoft/vscode/issues/168471](https://github.com/microsoft/vscode/issues/168471)

## Change summary

- **Validation:** After agreeing the convention, compare a two-action notification, a comment reply/edit form, and a horizontal confirmation dialog on Windows, macOS, and Linux. Verify both group alignment and primary/secondary ordering against the agreed matrix, and check that keyboard focus order matches visual order and existing default/cancel actions remain intact.
- **Behavior:**

  > Primary actions currently appear in differing positions across dialogs, notifications, comments, and GitHub Pull Requests surfaces. Comparable surfaces should follow an agreed, predictable placement convention, with explicit exceptions where native platform expectations warrant them. Acceptance must distinguish where the button group sits from where the primary action sits within that group, and preserve keyboard and default/cancel behavior.
- **Trace:**

  > Dialog.rearrangeButtons in src/vs/base/browser/ui/dialog/dialog.ts implements platform-specific ordering, while dialog.css independently aligns horizontal groups to the trailing edge. Notifications render supplied action order in NotificationTemplateRenderer.renderButtons in src/vs/workbench/browser/parts/notifications/notificationsViewer.ts, with the first action primary; comments independently float form buttons right in src/vs/workbench/contrib/comments/browser/media/review.css. These source paths establish differing mechanisms, not a universally incorrect side. The platform concern is explicit in https://github.com/microsoft/vscode/issues/168471#issuecomment-1343005041. GitHub Pull Requests examples belong to microsoft/vscode-pull-request-github and require coordination rather than assuming all surfaces live in this checkout. Preserve native dialog semantics and action identity; the unresolved boundary is which custom surfaces should share which placement rule.
- **Open decisions:**
  - Should comparable custom workbench forms and notifications place the primary action on a fixed side across platforms, or follow each platform's dialog ordering?
  - Which differences between dialogs, notifications, inline comment forms, and PR forms are intentional exceptions rather than alignment inconsistencies?
