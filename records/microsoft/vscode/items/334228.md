# Issue #334228 — Make chat sessions available across workspaces (global chat history)

[https://github.com/microsoft/vscode/issues/334228](https://github.com/microsoft/vscode/issues/334228)

## Summary

Keep this accepted, well-supported request open: classic chat storage remains workspace-scoped, and the linked implementation PR was closed without merging. An older request covers cross-workspace discovery, but does not cover this report's additional pinned-session retention and multi-root interoperability requirements.

## Change summary

Make classic Copilot chat history accessible across workspaces, preserve pinned conversations through workspace lifecycle changes, and support multi-root session visibility in the Agents window.

## Best solution

Provide durable profile-wide access to classic conversations with workspace metadata and filtering, without losing pinned sessions when workspace storage is retired. Coordinate discovery with the older shared-history request, and establish cross-workspace resume and multi-root interoperability semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts`, `src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts`
- **Validation:** Extend the ChatSessionStore unit suite to cover discovering and reading a conversation from a different workspace, migration of existing histories, concurrent-window updates, and pinned-session survival after originating workspace storage is retired. Manually verify current-workspace/all-workspaces filtering and visibility of classic chats created in a three-folder workspace in the Agents window.
- **Behavior:**

  > A user can discover and read classic Copilot conversations from another workspace without replacing the current workspace. History retains workspace attribution and offers current-workspace and all-workspaces filtering. Pinned conversations survive retirement of the originating workspace's storage. Existing conversations remain available after migration, and independent open windows must not overwrite each other's history. The latest report additionally asks that classic conversations created in multi-root workspaces be accessible in the Agents window.
- **Trace:**

  > ChatSessionStore in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts chooses transcript storage by workspace identity and reads/writes its index with getIndexStorageScope(); only empty windows use application-scoped history. handleWorkspaceTransition and migrateSessionsToNewWorkspace copy transcripts on a transition but retain workspace-specific storage boundaries. AgentSessionsCache in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts separately persists session state at workspace scope, while ChatSessionStore.trimEntries limits indexed sessions by recency. https://github.com/microsoft/vscode/pull/338191 attempted the global-history change but was closed unmerged. https://github.com/microsoft/vscode/issues/301414 overlaps discovery, and https://github.com/microsoft/vscode/issues/336524 owns the narrower archive-restart bug. The classic storage gap is established; the exact multi-root Agents-window visibility path and safe cross-workspace continuation contract remain to be diagnosed. Preserve profile boundaries, existing transcript contents, and explicit deletion semantics; do not assume global discovery authorizes applying another workspace's edits.
- **Open decisions:**
  - Should a conversation opened outside its originating workspace be read-only, continue in its original workspace, or become editable against the current workspace?
  - Should the initial delivery include classic multi-root conversations in the Agents window, or should that interoperability requirement be tracked separately?
  - Does pinning protect sessions from every automatic retention policy, or specifically from workspace-lifecycle cleanup?
