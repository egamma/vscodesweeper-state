# Issue #309537 — `Failed to create worktree. Proceeding without isolation.`

[https://github.com/microsoft/vscode/issues/309537](https://github.com/microsoft/vscode/issues/309537)

## Summary

Keep open for an actionable worktree-failure recovery experience. Current Agent Host code prevents fallback and exposes diagnostics, but requires starting another session rather than offering the recovery choices requested here; the team-authored, accepted request has no verified complete fix.

## Change summary

Offer useful diagnostics and a way to recover from failed worktree creation without unexpectedly working in the main checkout.

## Best solution

Provide an explicit recovery flow in the Agents Window that preserves the user's isolation choice and pending request, with actionable failure details. Settle whether recovery retries the existing session or starts a replacement, and when retrying without transferring changes is applicable.

- **Behavior:**

  > When a user requests a new isolated session and worktree creation fails, they should understand the failure and have an explicit way to recover without unexpectedly running in the main checkout. The report requests retrying or creating without transferring local changes, where that transfer is responsible for the failure. Current protection against continuing in the original checkout must remain intact. Acceptance should cover actionable diagnostics, successful recovery after correcting the cause, and preservation of the user's pending request and isolation intent.
- **Trace:**

  > The exact warning originates in FolderRepositoryManager.initializeFolderRepository in extensions/copilot/src/extension/chatSessions/vscode-node/folderRepositoryManagerImpl.ts; it returns the source folder when createWorktree returns undefined, and its existing unit test asserts that behavior. Change migration occurs after creation, so the reported file counts do not prove transfer caused the failure. The current local Agents Window provider is Agent Host, according to the Copilot Chat sessions provider specification. WorktreeIsolation.resolveOnFirstSend in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts now stores and rethrows creation failures, reports diagnostics, and directs the user to start a new session; it does not offer an in-session retry. The design must establish recovery ownership across this host lifecycle and baseAgentHostSessionsProvider.ts without weakening fail-closed behavior or unnecessarily changing the legacy path. https://github.com/microsoft/vscode/issues/336620 provides related cross-surface design context, not a duplicate canonical.
- **Open decisions:**
  - Should recovery retry the failed session in place, or create a replacement session while preserving its prompt, branch, and agent selections?
  - Should creation failures and change-transfer failures expose different recovery choices, including retrying without transferring local changes only when that can address the failure?
