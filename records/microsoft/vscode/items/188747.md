# Issue #188747 — ptyHost starts when there is only a terminal renderer

[https://github.com/microsoft/vscode/issues/188747](https://github.com/microsoft/vscode/issues/188747)

## Summary

Still valid on current main: the ptyHost process is launched even when the terminal only needs a renderer (e.g. via `customPtyImplementation`). No fix commit references this issue, and the eager connection path in `localTerminalBackend.ts` remains unchanged.

## Change summary

The ptyHost process starts unnecessarily when a terminal is opened with only a renderer and no backing shell process (e.g. Dev Containers container log).

## Best solution

Defer ptyHost connection in `LocalTerminalBackend` so it only launches when an actual process creation or attachment is requested, not when the terminal subsystem activates for renderer-only use. The fix likely lives in `src/vs/workbench/contrib/terminal/electron-browser/localTerminalBackend.ts` — the `_connectToDirectProxy` call chain should be gated so renderer-only terminals (those using `customPtyImplementation`) never trigger it.
