[https://github.com/microsoft/vscode/issues/326320](https://github.com/microsoft/vscode/issues/326320)

## Summary

This matches a well-established cluster of open reports on the same root cause (chat/agent session rename not propagating to the sessions list or persisting on reopen); https://github.com/microsoft/vscode/issues/316393 is the oldest open report with the same repro shape (rename doesn't update list, requires refresh, sometimes reverts), so this reads as a duplicate rather than a distinct defect.

## Change summary

Renaming a Copilot Chat/agent session doesn't update the sessions list immediately, still shows the old name at the top of the reopened session, and reverts to the old name after backing out or relaunching.

## Best solution

Consolidate the rename-doesn't-persist reports onto https://github.com/microsoft/vscode/issues/316393 (oldest, same repro) — the underlying fix likely lives in the agent-host session title sync path (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts, the SessionTitleChanged dispatch/onChange title-watch logic) and in how the Agent Sessions list/view model refreshes on session state change.
