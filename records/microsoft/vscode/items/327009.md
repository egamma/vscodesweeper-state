# Issue #327009 — Agent Mode: Cant view diffs in WSL

[https://github.com/microsoft/vscode/issues/327009](https://github.com/microsoft/vscode/issues/327009)

## Summary

Real, well-diagnosed bug still present on main: the Agent Host filesystem provider registers WSL connections under the distro's original-case authority (e.g. `wsl__Ubuntu`) but URI serialization always lowercases authorities, so any `vscode-agent-host://` URI that round-trips through `.toString()`/`URI.parse()` (diff view, plan webview) ends up looking up a lowercased authority that was never registered.

## Change summary

Viewing agent-changes diffs (and the plan.md webview) for an Agents Window session running in WSL fails with 'No connection for authority: wsl__<distro>'.

## Best solution

Normalize WSL (and any other case-sensitive) connection authorities to a single canonical case at both registration and lookup — e.g. lowercase in `agentHostAuthority()` (src/vs/platform/agentHost/common/agentHostUri.ts) before building the authority string, and/or make `AHPFileSystemProvider._getConnection`'s `_authorities` map lookup case-insensitive (src/vs/platform/agentHost/common/agentHostFileSystemProvider.ts) — so a URI that has been lowercased by `URI.toString()`/`URI.parse()` still resolves to the connection registered for the same distro.

## Evidence

- **registration keeps original case:** src/vs/platform/agentHost/common/agentHostUri.ts:agentHostAuthority() only replaces `:` with `__` for an address matching `/^[a-z0-9.:\-]+$/`; a WSL address like `wsl:Ubuntu` (capitalized distro name, as `wsl --list` reports stock distros) does not match that all-lowercase regex, and callers such as remoteAgentHost.contribution.ts:849 (`agentHostAuthority(address)` then `registerAuthority(authority, connection)`) store whatever case the distro name carries.
- **serialization always lowercases authority:** src/vs/base/common/uri.ts:_asFormatted() (used by URI.toString()) unconditionally does `authority = authority.toLowerCase()` for every scheme, per RFC 3986 host case-insensitivity — so any vscode-agent-host:// URI that gets stringified and re-parsed (e.g. for a webview src or a diff editor input) loses the original distro casing.
- **lookup is case-sensitive:** src/vs/platform/agentHost/common/agentHostFileSystemProvider.ts:_getConnection() (lines 549-592) does a plain `Map<string, IAuthorityEntry>.get(authority)` with no case normalization, so a lowercased authority misses the entry registered under the original case and throws 'No connection for authority: <authority>' (lines 553/572).
- **community diagnosis matches:** Comment by Swannbm (2026-08-12) independently traced the same mismatch from live logs: sessions registered under `wsl__Ubuntu` while the failing resource URI carries `wsl__ubuntu`, and notes it would affect any default-cased WSL distro (Ubuntu, Debian).
- **not fixed by adjacent PR:** PR https://github.com/microsoft/vscode/pull/328011 ('Fix agent host diff file paths', merged, commit 53ad121699ab641b2d61757f3989011e41968b0d) only fixes legacy session-db URI paths and Windows drive-letter label casing — it does not touch authority registration or lookup, and a reporter confirmed the bug persists on 1.132.1 after that PR shipped.
- **reporter count:** 3 independent reporters (original + 2 comments) across VS Code 1.129.1–1.134.0, 6 upvotes, all describing the same WSL authority failure across the diff view and the plan.md webview.
