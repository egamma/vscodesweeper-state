# Issue #327009 — Agent Mode: Cant view diffs in WSL

[https://github.com/microsoft/vscode/issues/327009](https://github.com/microsoft/vscode/issues/327009)

## Summary

Reproducible bug: viewing diffs (and per a second reporter, the session plan panel) for a WSL-hosted Agents-window session fails with 'No connection for authority: wsl__<distro>' even though the WSL connection is live at the time, per two independent reports with matching stack traces through agentHostFileSystemProvider.ts's `_getConnection`.

## Change summary

In the Agents window, opening a file diff (or the plan view) for a WSL agent-host session throws a FileSystemError 'No connection for authority' despite the WSL connection being active.

## Best solution

Investigate why the authority string computed for the vscode-agent-host:// URI used by the diff/plan resolution path doesn't match the authority key registered via `registerAuthority` for the live WSL connection (agentHostFileSystemProvider.ts's `_authorities` map, keyed by `agentHostAuthority(connection.address)`); a second reporter suspects a case-mismatch between the distro name used to build the URI and the one used at registration.

- **authority registration:** Authorities are registered via `registerAuthority(authority, connection)` (src/vs/platform/agentHost/common/agentHostFileSystemProvider.ts:230) keyed by `agentHostAuthority(connection.address)` (src/vs/platform/agentHost/common/agentHostUri.ts:146), called from src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHost.contribution.ts:847; for WSL the address is `wsl:<distro>` (src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:181).
- **second confirmation:** A second reporter (Swannbm) confirms on 1.132.1 stable with a different distro (Ubuntu) and a second affected surface (the plan panel via `resolveWebview`), and observes the underlying WSL connection is otherwise healthy at the failure time, pointing at an authority-string mismatch rather than a dropped connection.
- **no fix on main:** `git log --oneline -- src/vs/platform/agentHost/common/agentHostFileSystemProvider.ts` shows the latest change (802ccf1e) is unrelated to WSL authority resolution; no fix for this specific case is present on main.
