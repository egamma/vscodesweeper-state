# Issue #340273 — StandAlone terminal

[https://github.com/microsoft/vscode/issues/340273](https://github.com/microsoft/vscode/issues/340273)

## Summary

The standalone-terminal request is already tracked by the older, open canonical issue. Its scope includes using VS Code's terminal independently of a workspace or main editor window, rather than merely opening a floating terminal.

## Change summary

Provide a standalone VS Code terminal whose use and running processes are independent of the workspace editor window.

## Best solution

Consolidate this request into https://github.com/microsoft/vscode/issues/34442, preserving the requirement that closing the workspace editor must not terminate processes in the independent terminal.

It predates this report and covers the same observable limitation: terminal use depends on an editor/workspace window.
- **Maintainer-defined scope:** https://github.com/microsoft/vscode/issues/34442#issuecomment-508834722 describes launching a terminal not associated with any workspace. https://github.com/microsoft/vscode/issues/34442#issuecomment-3897140905 explicitly identifies the remaining requirement for a main window to be open. This directly matches the request for terminal use independent of the editor, satisfying the stronger duplicate bar for a re-reviewed item.
- **Existing terminal windows are partial coverage:** src/vs/workbench/contrib/terminal/browser/terminalActions.ts registers workbench.action.terminal.newInNewWindow, creating a terminal in AUX_WINDOW_GROUP with compact auxiliary-window options. This provides a separate terminal window within the existing workbench, not an independently launched terminal application; the canonical issue's body explicitly distinguishes these capabilities.
- **Process lifetime and workaround:** src/vs/workbench/contrib/terminal/browser/terminalService.ts, _onWillShutdown, preserves attached processes for reload but otherwise disposes the terminal instances it handles. src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts defines terminal.integrated.confirmOnExit as an optional shutdown warning and persistentSessionReviveProcess as restoring history and recreating processes, not keeping arbitrary running jobs alive. These settings do not fulfill the central standalone-terminal request.
- **Report-specific evidence to retain:** https://github.com/microsoft/vscode/issues/340273 specifically motivates independence with accidentally closing an editor window and losing a running process, and with terminal-only use without opening repository code. This is an acceptance requirement for the canonical standalone-terminal work, not a separate reported defect.
