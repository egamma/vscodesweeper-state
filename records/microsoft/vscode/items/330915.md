# Issue #330915 — agent host: derive MCP customization id from ownership instead of publication position

[https://github.com/microsoft/vscode/issues/330915](https://github.com/microsoft/vscode/issues/330915)

## Summary

Keep open: current main still mints top-level MCP identities from provider/session/name and retains sticky promotion, while durable enablement depends on separately supplied ownership. The requested cleanup remains necessary; the related migration and integration trackers do not replace this specific work.

## Change summary

Make MCP customization identity ownership-derived and independent of publication order without changing existing durable enablement keys.

## Best solution

Establish a consistent ownership-based identity across nested and promoted MCP publications, preserving existing global/workspace decisions and restored session behavior. First trace persisted ID consumers and provider publication paths so the transition does not orphan existing state.

- **Behavior:**

  > The same owned MCP server should have the same customization identity whether published nested under its plugin or promoted before plugin discovery completes. Existing global and workspace enablement keys must remain byte-for-byte unchanged, and previously disabled servers must remain disabled across new sessions and restoration. Lifecycle updates and user actions must continue targeting the correct server throughout discovery and reload.
- **Trace:**

  > McpCustomizationController.buildMcpTopLevelCustomizationId currently embeds provider and session, while _applyOne selects child identity when available and makes top-level promotion sticky otherwise. _buildTopLevel and resolveCustomizationEnablement independently consume ownership maps to recover durable enablement identity. AgentHostCustomizationEnablementService.getCustomizationEnablementKey separates durable ownership keys from session keys, but session decisions are persisted using customization IDs through _persistSession. This establishes a compatibility surface beyond the reported global-key invariant; the trace has not yet enumerated all provider child-ID producers, restored snapshots, or client ID consumers. Preserve existing durable keys, scope inheritance, SDK server names, channel routing, and opaque host-advertised client identities. https://github.com/microsoft/vscode/issues/332083 tracks this cleanup as a dependency rather than replacing it.
