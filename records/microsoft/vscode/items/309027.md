# Issue #309027 — Create new session from current worktree

[https://github.com/microsoft/vscode/issues/309027](https://github.com/microsoft/vscode/issues/309027)

## Summary

Keep open: current New Session inherits the repository location rather than the existing managed worktree, while New Nested Session offers a different, capability-dependent workflow. The newer Git/worktree umbrella explicitly preserves this narrower request and is not an eligible duplicate target.

## Change summary

Make it easy to start a fresh conversation in the worktree used by an existing agent session.

## Best solution

Provide a discoverable fresh-conversation flow that retains the exact current worktree and its edits without creating another worktree. Decide whether the existing nested-chat model should fulfill this workflow or whether an independent session sharing the worktree is required.

- **Behavior:**

  > After working with an agent in an isolated worktree, the user can easily begin a fresh conversation against that same worktree. The conversation starts without the previous transcript, retains the existing filesystem changes, and does not create another worktree or switch to the parent checkout. Acceptance must verify the effective working directory, not merely the displayed repository label. Whether the conversation is nested or independently listed remains a product decision.
- **Trace:**

  > NewChatInSessionsWindowAction in src/vs/sessions/contrib/chat/browser/newSessionAction.ts inherits ISession.workspace.uri. buildAgentHostSessionWorkspace in src/vs/sessions/common/agentHostSessionWorkspace.ts distinguishes that repository identity from the effective worktree workingDirectory. AddChatToSessionAction in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts instead opens an additional chat through ISessionsService.openNewChatInSession, and the Agent Host provider creates it within the existing backend session. These paths establish the location and session-model distinction, but do not settle the desired product semantics. Preserve ordinary New Session behavior and provider capability boundaries. https://github.com/microsoft/vscode/issues/336620 supplies broader design context without replacing this request.
- **Open decisions:**
  - Should a fresh conversation in the current worktree be a nested chat within the existing session, or an independent session with its own list identity and lifecycle?
