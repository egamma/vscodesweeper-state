# Issue #337944 — `code tunnel prune` broken because of case mismatch

[https://github.com/microsoft/vscode/issues/337944](https://github.com/microsoft/vscode/issues/337944)

## Summary

Confirmed in source: server folders are created with a capitalized quality name (e.g. `Stable-<commit>`) but `Quality::try_from` in cli/src/options.rs only matches lowercase strings, so `get_all_servers`/`prune` silently skips every real folder. An open PR already fixes this, so the issue stays open pending that merge rather than being closed now.

## Change summary

`code tunnel prune` never deletes any server folders because it can't parse the capitalized `Stable-<commit>` / `Insiders-<commit>` directory names it itself creates.

## Best solution

Land https://github.com/microsoft/vscode/pull/338909 (case-insensitive Quality parsing) or an equivalent fix so `tunnel prune` recognizes the folder names the CLI itself creates.

## Evidence

- **folder naming:** cli/src/tunnels/paths.rs get_server_folder_name() formats `{quality}-{commit}` using Quality's Display impl, which calls get_capitalized_name() ("Stable", "Insiders", "Exploration") — options.rs lines ~32-39, ~58-62.
- **parsing mismatch:** cli/src/tunnels/paths.rs get_all_servers() splits the dirname on '-' and calls options::Quality::try_from(quality), whose impl (cli/src/options.rs lines 64-76) only matches lowercase "stable"/"insiders"/"insider"/"exploration", silently `continue`-ing (skipping) any folder that doesn't match — so real `Stable-<commit>` dirs are never enumerated or pruned.
- **no fix on main:** git log -- cli/src/options.rs cli/src/tunnels/paths.rs shows no related change; the case-sensitive match is still present on current main.
- **open fix PR:** https://github.com/microsoft/vscode/pull/338909 is an open, unmerged PR titled 'Make CLI Quality parsing case-insensitive so tunnel prune handles Stable-<commit> folders' that targets exactly this defect.
