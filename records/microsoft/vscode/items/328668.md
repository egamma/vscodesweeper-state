# Issue #328668 — The built-in npm support extension errors and causes launch delay when encountering certain .modules.yaml

[https://github.com/microsoft/vscode/issues/328668](https://github.com/microsoft/vscode/issues/328668)

## Summary

Real bug in the built-in npm extension's package-manager detection: it calls the bundled `which-pm@2.1.1` module without a try/catch, and that module throws an uncaught TypeError when a pnpm-style `node_modules/.modules.yaml` exists but lacks a `packageManager` field — exactly matching the reported stack trace and symptoms (empty NPM Scripts view, 3-4s preLaunchTask delay).

## Change summary

A malformed/incomplete `node_modules/.modules.yaml` (missing `packageManager`) makes the built-in npm extension throw, breaking the NPM Scripts view and delaying preLaunchTask execution.

## Best solution

In extensions/npm/src/preferred-pm.ts, wrap the `whichPM(pkgPath)` call (line 99) in a try/catch so a malformed or incomplete `.modules.yaml` falls back gracefully instead of throwing an unhandled rejection that propagates through detectPackageManager into the task/script providers.
