# Issue #328668 — The built-in npm support extension errors and causes launch delay when encountering certain .modules.yaml

[https://github.com/microsoft/vscode/issues/328668](https://github.com/microsoft/vscode/issues/328668)

## Summary

Keep open: the bundled which-pm dependency still dereferences a missing packageManager field in .modules.yaml, and the built-in npm extension propagates that failure during task discovery. The exception is established from source; the reported debug-launch delay was not independently verified.

## Change summary

A .modules.yaml file without packageManager breaks built-in npm script discovery and reportedly delays an unrelated debug preLaunchTask.

## Best solution

Make package-manager detection tolerate metadata without packageManager in which-pm, then adopt the corrected behavior in the built-in npm extension so script discovery remains usable. Preserve valid package-manager detection and verify the unrelated shell preLaunchTask is no longer delayed.
