# Issue #183437 — Mouse wheel scroll does not respect windows mouse settings

[https://github.com/microsoft/vscode/issues/183437](https://github.com/microsoft/vscode/issues/183437)

## Summary

This is the same request as the now-closed #263245 (which didn't reach 20 upvotes as a feature request). The root cause is upstream: Electron/Chromium's `wheelDeltaY` reports 120 per notch regardless of the Windows scroll-lines setting, so VS Code's normalization in `StandardWheelEvent` (dividing by 120) always yields ~1 line per notch. VS Code provides `editor.mouseWheelScrollSensitivity` as a manual workaround. Given the low community traction and upstream ownership, proposing duplicate close against the canonical report.

## Change summary

VS Code ignores the Windows 'Lines to scroll at a time' mouse setting, always scrolling a fixed number of lines per wheel notch.

## Best solution

The root cause is in Electron/Chromium's WheelEvent handling on Windows — `wheelDeltaY` does not incorporate the OS scroll-lines setting. VS Code already offers `editor.mouseWheelScrollSensitivity` as a multiplier workaround. A true fix would require Electron/Chromium to propagate the Windows setting into the delta, or VS Code to read the Windows registry value and scale accordingly — both are significant. The canonical issue #263245 was closed for insufficient upvotes; this older issue could serve as the canonical if kept, but community interest is very low (1 upvote over 3+ years).
