# Issue #293800 — Remote Tunnels fails to open workspace when path contains Chinese(non-ascii) characters.

[https://github.com/microsoft/vscode/issues/293800](https://github.com/microsoft/vscode/issues/293800)

## Summary

Keep open: the discussion confirms that escaped folder names can prevent a real workspace from opening through vscode.dev tunnels. The related open report describes the same failure but is newer, so it cannot replace this previously reviewed issue under the stronger duplicate rule.

## Change summary

Opening a tunnel link to an existing folder containing Chinese or other escaped characters fails with "Workspace does not exist" and displays an encoded workspace path.

## Best solution

Ensure tunnel URLs round-trip the original filesystem path through vscode.dev workspace initialization, without confusing encoded characters with literal percent sequences. Coordinate with the related remote-release report while retaining this older report until a concrete fix or eligible canonical is established.
