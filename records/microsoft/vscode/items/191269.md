## Evidence

- **Reported trigger and diagnosis:** https://github.com/microsoft/vscode/issues/191269 reports unreadable text after pressing Alt+Z on long build-task output. After the reporter supplied settings and an animation, Tyriar identified canvas stretching beyond the maximum texture size, linked https://github.com/xtermjs/xterm.js/issues/4186, and suggested Terminal: Set Fixed Dimensions as a workaround.
- **Upstream disposition:** https://github.com/xtermjs/xterm.js/issues/4186 reproduces stretched WebGL terminal text with term.resize(8000, 40). It is closed, but https://github.com/xtermjs/xterm.js/issues/4186#issuecomment-3695426382 says the case is out of scope; this is not evidence of a landed fix.
- **Current mitigation:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts defines Constants.MaxCanvasWidth = 4096. TerminalInstance.toggleSizeToContentWidth, lines 2245–2267, limits the content-derived column count using that constant divided by font.charWidth. This is a relevant mitigation, not proof of correct rendering on the reporter's GPU and display configuration.
- **Renderer boundary:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts loads @xterm/addon-webgl in _enableWebglRenderer. Terminal font measurement in src/vs/workbench/contrib/terminal/browser/terminalConfigurationService.ts distinguishes CSS and device-pixel dimensions, so source inspection alone does not establish whether the cap avoids the reported environment-dependent stretching.
- **Related historical report:** https://github.com/microsoft/vscode/issues/152767 describes similar distortion after entering very large fixed dimensions and is closed. https://github.com/microsoft/vscode/issues/152767#issuecomment-1853913602 mentions the 4096-pixel cap, but supplies no fixing commit and does not confirm resolution of this issue's content-width-toggle trigger.
