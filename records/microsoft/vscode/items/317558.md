# Issue #317558 — Copilot agent "Failed to retrieve command output" with Oh My Posh + zsh on macOS

[https://github.com/microsoft/vscode/issues/317558](https://github.com/microsoft/vscode/issues/317558)

## Summary

Real bug — Oh My Posh on zsh can break shell integration markers that the run_in_terminal tool relies on for output capture. The zsh shell integration script notably lacks Oh My Posh detection (unlike bash/fish/PowerShell), and the broader shell integration/command detection parity gap is actively tracked in the related issue #317789.

## Change summary

Copilot agent's `run_in_terminal` tool reports 'Failed to retrieve command output' when Oh My Posh prompt is active in zsh on macOS, because shell integration markers are disrupted.

## Best solution

Two improvements needed: (1) Add Oh My Posh detection to `shellIntegration-rc.zsh` (check for `POSH_SESSION_ID` and emit `PromptType=oh-my-posh`, as bash/fish/PowerShell scripts already do) — this is a small fix in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-rc.zsh`. (2) The deeper issue of shell integration marker robustness with custom prompt themes is tracked by https://github.com/microsoft/vscode/issues/317789 — this specific report should be linked there as an affected scenario. The execute strategies in `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy/` fall back to marker-based output retrieval when command detection fails, but markers can be unreliable when prompt themes rewrite hooks.
