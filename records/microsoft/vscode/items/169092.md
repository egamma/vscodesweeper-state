[https://github.com/microsoft/vscode/issues/169092](https://github.com/microsoft/vscode/issues/169092)

## Summary

Keep open for a maintainer-led discoverability design: current Command Center labeling still does not explain command execution before interaction. The older search-icon report was explicitly consolidated into this issue, and neither the existing capabilities nor the related customization request establish completion.

## Change summary

Make the Command Center icon and placeholder communicate command execution as well as file navigation without adding visual clutter.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts`, `src/vs/workbench/browser/actions/quickAccessActions.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** After selecting a design, inspect an empty window, a named workspace, a custom window.title, and hidden editor tabs, including compact and noncompact Command Center presentations. Confirm the agreed affordance communicates command execution without hover, remains legible at narrow widths, and preserves keyboard activation, file navigation, and access to Show and Run Commands; use a short user task to check discoverability.
- **Behavior:**

  > User research found that the Command Center's search presentation led users toward file navigation while few discovered command execution. The desired outcome is an at-rest affordance that communicates both capabilities without becoming busy. Acceptance should cover empty windows, workspace titles, custom titles, and the current compact presentation. File navigation, command execution, and keyboard accessibility must remain available.
- **Trace:**

  > CommandCenterCenterViewItem in src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts supplies the label and Search tooltip; its nested CommandCenterQuickPickItem._getLabel() honors workspace names, custom window.title, and file names when tabs are hidden. Compact mode hides the search icon but retains the title-oriented label. workbench.action.quickOpenWithModes in src/vs/workbench/browser/actions/quickAccessActions.ts already opens Quick Access with mode help, and src/vs/workbench/contrib/quickaccess/browser/quickAccess.contribution.ts supplies the Show and Run Commands entry. The gap is discoverability before opening the picker, not missing command execution. Preserve existing navigation and configured Quick Access behavior; the uncertainty is the intended default presentation and treatment of window titles. https://github.com/microsoft/vscode/issues/150787 was explicitly consolidated into this issue, whereas https://github.com/microsoft/vscode/issues/185316 concerns separate toolbar customization.
- **Open decisions:**
  - What default label and icon should communicate both navigation and command execution without making the Command Center visually busy?
  - Should the Command Center continue displaying workspace and custom window titles, or should that information move elsewhere when an explicit capability label is shown?
