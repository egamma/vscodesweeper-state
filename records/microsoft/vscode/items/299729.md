# Issue #299729 — After noProxy is configured, the request fails.

[https://github.com/microsoft/vscode/issues/299729](https://github.com/microsoft/vscode/issues/299729)

## Summary

Plausible bug: setting `http.noProxy` without an explicit `http.proxy` triggers `session.setProxy()` with empty `proxyRules` and empty `pacScript`, which overrides Chromium's system proxy auto-detection and breaks requests that depended on the system proxy. The issue needs routing to the proxy area owner.

## Change summary

Configuring `http.noProxy` (even with irrelevant domains) causes network requests to fail when the user relies on system-level proxy auto-detection rather than an explicit `http.proxy` setting.

## Best solution

In `src/vs/platform/windows/electron-main/windowImpl.ts`, the `setProxy()` call should only override system proxy settings when an explicit `http.proxy` is configured; when only `http.noProxy` is set, the code should either skip calling `setProxy()` entirely or pass through the system proxy configuration (e.g. `mode: 'system'`) instead of overriding with empty `proxyRules` and empty `pacScript`. @chrmarti owns this area.

## Evidence

- **code path:** src/vs/platform/windows/electron-main/windowImpl.ts lines 1113-1143: when `http.noProxy` changes and `http.proxy` is not set, `proxyRules` is `''` and `pacScript` is `''`, which is passed to `session.setProxy()`, overriding system proxy auto-discovery with a direct-connection config.
- **Electron behavior:** Electron's `session.setProxy({ proxyRules: '', pacScript: '' })` tells Chromium to use DIRECT for all URLs (no system proxy fallback), whereas not calling `setProxy()` at all lets Chromium use the OS system proxy (WPAD/PAC).
- **user scenario:** Reporter is behind a corporate proxy (no external network access without proxy). Without `http.noProxy`, requests succeed via system proxy. With `http.noProxy` configured (irrelevant domains), `setProxy()` is called with empty proxy rules, killing system proxy auto-detection.
