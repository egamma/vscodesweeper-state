# Issue #273271 — Git - Generate Commit Message: Improvements (model selection and include context from chat)

[https://github.com/microsoft/vscode/issues/273271](https://github.com/microsoft/vscode/issues/273271)

## Summary

Keep open: current source supports a shared utility-model override, but Source Control commit generation still receives no chat discussion. This accepted Backlog request has 23 upvotes, and the verified related issues do not own its full scope.

## Change summary

Improve Source Control commit-message generation through model control and optional chat context that explains why changes were made.

## Best solution

Provide an explicit, repository-relevant way to include chat rationale in commit-message suggestions while preserving diff accuracy and suggestion-only behavior. Clarify the existing shared model override and decide whether commit-specific model selection and usage visibility need a separate surface.

- **Behavior:**

  > A developer generating a commit-message suggestion from Source Control can deliberately include relevant chat discussion so the message explains both the actual change and its rationale. The staged diff remains authoritative about what changed; unrelated discussions must not influence the suggestion. Generation continues to populate the commit input without staging files or creating a commit. The model used must follow the agreed selection contract, with the existing shared utility override clearly distinguished from any commit-specific choice.
- **Trace:**

  > The command handler in conversationFeature.ts delegates to GitCommitMessageServiceImpl, whose _doGenerateCommitMessage gathers staged changes when present, otherwise working-tree and untracked changes, then recent Git commit subjects. GitCommitMessageGenerator requests copilot-utility-small and renders GitCommitMessagePrompt with no conversation input. ProductionEndpointProvider already resolves chat.utilitySmallModel overrides, so model selection is not wholly absent; that override is shared across other utility consumers. GitCommitMessagePrompt includes dedicated custom instructions but no chat history, confirming the rationale gap without executing generation. Preserve staged-change preference, content-exclusion handling, custom instructions, cancellation and suggestion-only behavior. Related context requests are https://github.com/microsoft/vscode/issues/281985 and https://github.com/microsoft/vscode/issues/282165; the narrower model-setting request is https://github.com/microsoft/vscode/issues/328619. The unresolved boundary is which conversation the user authorizes and whether this action needs model controls independent of the shared setting.
- **Open decisions:**
  - When chat context is enabled, should the action use the active conversation or let the user explicitly select a repository-relevant conversation?
  - Should chat inclusion be a per-generation choice or a persistent preference, and what should happen when no relevant conversation is available?
  - Is the shared chat.utilitySmallModel override sufficient with better discoverability, or should commit generation expose an independent model choice and action-specific usage information?
