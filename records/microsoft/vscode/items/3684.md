# Issue #3684 — Ctrl-K must cut up to the end of the line into the clipboard

[https://github.com/microsoft/vscode/issues/3684](https://github.com/microsoft/vscode/issues/3684)

## Summary

The default macOS Ctrl-K binding still deletes text without retaining it for paste. Keep this accepted Backlog request open: it has 40 upvotes, and configurable command sequences do not resolve the requested default behavior.

## Change summary

Make macOS Ctrl-K retain text deleted through the end of the line so it can be pasted back.

## Best solution

Provide a native-compatible cut-to-line-end default for macOS while preserving explicitly deletion-only commands. Settle whether retained text belongs in the system clipboard or a separate kill buffer before changing the default.

The requested outcome is that users can recover that text through paste or yank, rather than losing it from their editing flow. - **Trace:**

- **Open decisions:**
  - Should default macOS Ctrl-K write to the system clipboard, as the issue initially requests, or retain text in a separate kill buffer with Ctrl-Y retrieval, preserving the system clipboard?

## Evidence

- **Current default remains deletion-only:** src/vs/editor/contrib/linesOperations/browser/linesOperations.ts: DeleteAllRightAction registers deleteAllRight with macOS Ctrl-K. Its _getRangesToDelete selects the remaining line text, or the following newline at line end; AbstractDeleteAllToBoundaryAction.run replaces those ranges with empty strings without writing to a clipboard or kill buffer.
- **Existing capability is an opt-in workaround:** src/vs/workbench/contrib/commands/common/commands.contribution.ts registers runCommands and awaits each command sequentially. Together with cursorEndSelect in src/vs/editor/browser/coreCommands.ts and editor.action.clipboardCutAction in src/vs/editor/contrib/clipboard/browser/clipboard.ts, this supports a user-configured select-and-cut binding without a macro extension. It does not change the default Ctrl-K behavior or supply native kill-buffer semantics.
