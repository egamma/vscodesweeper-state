# Issue #338536 — Same workspace peer chats: Hovering peer chats only shows diff details when the peer chat is currently selected

[https://github.com/microsoft/vscode/issues/338536](https://github.com/microsoft/vscode/issues/338536)

## Summary

Team-authored bug filed while testing the new same-workspace peer chat hover work (referencing the just-merged https://github.com/microsoft/vscode/issues/338220); the video shows a peer chat's diff pill only appearing once that chat is selected, which matches the changeset service's lazy compute gating in code. No fix commit exists on main, so this stays open.

## Change summary

In a same-workspace multi-chat session, hovering a peer (non-selected) chat does not show its diff stats, even though hovering the currently selected chat does.

## Best solution

Decide whether peer-chat changeset diffs should be computed eagerly for all chats in a session (so hover always has data) or lazily triggered by the hover itself, and wire the hover data path (getChatSummaryHoverData / readChatChangesStats in sessionHoverContent.ts and sessionChangesStatsCache.ts) to request/await that data for the hovered chat instead of only the active one.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts`, `src/vs/sessions/services/sessions/common/sessionChangesStatsCache.ts`, `src/vs/platform/agentHost/node/agentHostChangesetService.ts`
- **Validation:** A test asserting that hovering a non-selected peer chat in a same-workspace multi-chat session surfaces the same diff stats (files/insertions/deletions) as hovering the currently selected chat.
- **Behavior:**

  > Hovering any peer chat in a same-workspace multi-chat session should show that chat's own diff stats (files/insertions/deletions), regardless of whether it is the currently selected/active chat. Today the diff pill only renders for the active chat; other peer chats show no diff details on hover until selected.
- **Trace:**

  > The hover content for a chat comes from getChatSummaryHoverData in src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts, which calls getChatBranchDiffStats -> readChatChangesStats (src/vs/sessions/services/sessions/common/sessionChangesStatsCache.ts) against chat.changesets/chat.changes observables. Diff computation for a chat's changeset appears gated by an `_activeStaticComputes` tracking set in src/vs/platform/agentHost/node/agentHostChangesetService.ts, which plausibly only actively computes/refreshes changesets for the chat currently in focus. Do not change the active-chat diff pill's own behavior or the cumulative session-level stats aggregation; the boundary is specifically what data is available/requested for a chat that is not the active selection. Related: https://github.com/microsoft/vscode/issues/338220.
- **Open decisions:**
  - Should the changeset service eagerly compute/maintain diff stats for every peer chat in a session, or only lazily fetch them on-demand when a hover targets that specific chat?
  - If lazy, is a brief loading/placeholder state acceptable in the hover while the peer chat's diff is fetched, or must the pill always be immediately available?
