# Issue #332798 — huge gap appeared between window right edge and the scrollbar

[https://github.com/microsoft/vscode/issues/332798](https://github.com/microsoft/vscode/issues/332798)

## Summary

Traced this to the Modern UI 'floating panels' experiment: EditorPart.layout() in editorPart.ts subtracts horizontal/vertical margins (getFloatingPaneCompositeHorizontalMargins + the EDITOR_FRAME_BORDER_WIDTH border reservation) whenever isFloatingPanelsEnabled() is true, which insets the editor (and its scrollbar) from the real window edge — breaking the classic Fitts'-law 'fling to the screen edge' scrollbar grab. Several reporters confirm the same modernUI rollout is causing usability regressions and the team is actively iterating (a new 'Window > Density: Layout' setting was added but a commenter confirms it doesn't fix this specific gap), so this is a live design/UX issue for the owning team, not something to close.

## Change summary

Enabling the new default Modern UI (floating panels) leaves a gap between the window's right edge and the scrollbar, making it much harder to grab the scrollbar by aiming for the screen edge.

## Best solution

The floating-panels margin logic in src/vs/workbench/browser/parts/editor/editorPart.ts (layout()) needs a UX fix from the modernization workstream — e.g. not inset the outermost edge scrollbar the same way non-outer edges are inset, or keep the scrollbar hit-target flush with the true window edge even when the editor content is visually inset. This is an active-development area (see the assigned owners on the related issue) rather than a simple isolated bug fix.

## Evidence

- **workaround confirmed:** Comment from gjsjohnmurray: setting `workbench.experimental.modernUI: false` restores the old (edge-flush) behavior, confirmed working by the reporter and a second commenter.
