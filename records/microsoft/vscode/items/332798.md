# Issue #332798 — huge gap appeared between window right edge and the scrollbar

[https://github.com/microsoft/vscode/issues/332798](https://github.com/microsoft/vscode/issues/332798)

## Summary

This is a real UX side-effect of the active 'Modern UI Update' experiment (`workbench.experimental.modernUI`, `experiment: { mode: 'auto' }`), not a random regression: the setting intentionally floats the editor/panels as cards with gaps, which pushes the scrollbar away from the window's physical edge and breaks the classic 'aim for the edge, grab the scrollbar' Fitts's-law trick. Disabling the setting (per the contributor's workaround) restores the old behavior, confirming the cause.

## Change summary

After Modern UI floating-panel styling was enabled (auto-experiment or manually), a visible gap appears between the window's right edge and the scrollbar, making it harder to grab the scrollbar by aiming at the screen edge.

## Best solution

As the Modern UI floating-panels experiment (src/vs/workbench/browser/parts/editor/editorPart.ts, layout() reserving `EDITOR_FRAME_BORDER_WIDTH` margins plus modernUI/media/*.css gaps) is tuned, consider whether the scrollbar drag hit-target should still extend to the physical window edge even when the editor content floats inward, so long-press-at-edge scrollbar grabbing keeps working.

- **setting is an active auto-experiment:** src/vs/workbench/browser/workbench.contribution.ts line ~834: `[LayoutSettings.MODERN_UI]` default is `false` but carries `experiment: { mode: 'auto' }`, meaning some users (like the reporter, whose A/B list includes `enable_editor_pane_layout`) get it turned on automatically without opting in via settings.
