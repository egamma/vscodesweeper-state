## Evidence

- **Reported trigger and isolation:** https://github.com/microsoft/vscode/issues/337570 reports an opaque 4px border with window.titleBarStyle=custom on Ubuntu 24.04, X11 and xfwm4 4.18, including with extensions disabled. Changing the window-manager name removes the band on the same setup; native title bars also avoid it.
- **Upstream behavioral fix:** https://github.com/electron/electron/pull/54390 is merged, with merge commit 18ed29f47d733b5d05238e5c7c969271a00f3e5f. Its diff changes shell/browser/ui/views/electron_frame_view_layout_linux.cc::GetRestoredFrameBorderInsets() to return empty insets when !supports_client_frame_shadow(), explicitly avoiding the solid 4px resize border. This removes the band but does not enable client-side shadows.
- **Current adoption path:** The checkout's .npmrc targets Electron 43.7.7. src/vs/platform/windows/electron-main/windows.ts:209-234 constructs custom-title-bar windows with titleBarStyle='hidden', frame=false on Linux, and optional titleBarOverlay, placing the reported configuration on Electron's frameless-window path. The reporter identifies 43.7.6 and later as including the backport; no graphical reproduction was executed.
- **Remaining upstream distinction:** https://github.com/microsoft/vscode/issues/337570#issuecomment-5912090437 explicitly distinguishes border removal from restoring shadows. It identifies https://chromium-review.googlesource.com/c/chromium/src/+/8463012 as restricting the obsolete xfwm4 workaround to versions before 4.17, and says the change landed in Chromium 156 rather than the Chromium version bundled with Electron 43.
- **Additional symptom is not yet diagnosed:** https://github.com/microsoft/vscode/issues/337570#issuecomment-5933087885 supplies a fullscreen pixel-clipping screenshot but only tentatively attributes it to the same regression. That comment does not establish whether the Electron border fix resolves it.
- **Canonical review:** https://github.com/microsoft/vscode/issues/334285 is open but concerns modern workbench UI density, typography and layout, not the same xfwm4 native-window border symptom. Searches for xfwm4 and grey border did not establish an older open canonical with the same observable symptom, as required for this re-reviewed item.
