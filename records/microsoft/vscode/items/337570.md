# Issue #337570 — Linux (Xfce/xfwm4): grey border on left, right and bottom of the window since 1.139 (Electron 43 regression)

[https://github.com/microsoft/vscode/issues/337570](https://github.com/microsoft/vscode/issues/337570)

## Summary

Well-diagnosed upstream regression: root cause traced to a Chromium X11 heuristic (`X11Window::CanSetDecorationInsets()` treating any WM named `Xfwm4` as broken) surfacing after VS Code's Electron 43 bump in 1.139.0. Already correctly labeled `upstream`/`electron`/`regression`; no VS Code-owned fix exists yet, so this stays open pending upstream Chromium/Electron action.

## Change summary

Since upgrading to Electron 43 (VS Code 1.139.0), Xfce/xfwm4 X11 users with the custom title bar see a 4px opaque grey border on the left/right/bottom window edges instead of the normal transparent shadow.

## Best solution

No core VS Code code change is warranted: the defect lives in Chromium's X11Window::CanSetDecorationInsets() heuristic. Track the linked Chromium bug (https://issues.chromium.org/u/1/issues/40804717) and Electron issue (https://github.com/electron/electron/issues/52024); consider an Electron version bump once fixed upstream, or evaluate the app-side `frame:false`/`hasShadow:false` workaround only if upstream remains stalled for a long time.
