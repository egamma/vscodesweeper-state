# Issue #322207 — Feature Request/Regression: Extension update lifecycle causes aggressive cache invalidation and hardware resource exhaustion

[https://github.com/microsoft/vscode/issues/322207](https://github.com/microsoft/vscode/issues/322207)

## Summary

The reported cache invalidation and resource-intensive re-indexing are owned by Kilo Code, not VS Code's extension-update lifecycle: current source keeps extension storage paths stable across versions and already supports disabling auto-update per extension.

## Change summary

Preserve local AI indexes across extension updates and require consent before an update triggers expensive re-indexing.

## Best solution

Kilo Code should retain and reconnect its index under `globalStorageUri` across upgrades, and throttle or request consent before rebuilding it. Users can disable Auto Update for this individual extension in the meantime.

## Vision fit

- **Fit:** rejected
- **Reason:** Lifecycle policy for one extension's expensive local index belongs in that extension rather than adding a specialized compute classification and prompt to VS Code core.
- **Evidence:** Values and guardrails: “The power lives in extensions,” while the default product should remain lightweight with a simple, uniform UI.

## Evidence

- **stable global storage path:** `src/vs/workbench/api/common/extHostStoragePaths.ts` implements `globalValue` as `<globalStorageHome>/<lowercase extension identifier>` and `workspaceValue` as `<workspaceStorageHome>/<workspace id>/<extension identifier>`; neither path includes the extension version.
- **update lifecycle:** `src/vs/platform/extensionManagement/node/extensionManagementService.ts` identifies an existing installation as `InstallOperation.Update` and adds the new version to the profile without running the uninstall lifecycle that removes global storage.
- **existing update control:** `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts` registers `workbench.extensions.action.toggleAutoUpdateForExtension` in the installed extension's context menu, while `extensionsWorkbenchService.ts` excludes individually disabled extensions from automatic updates.
- **extension ownership:** The report attributes the cache reset and re-indexing behavior specifically to the third-party `kilocode.kilo-code` extension; its active tracker is https://github.com/Kilo-Org/kilocode.
