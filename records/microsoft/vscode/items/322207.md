# Issue #322207 — Feature Request/Regression: Extension update lifecycle causes aggressive cache invalidation and hardware resource exhaustion

[https://github.com/microsoft/vscode/issues/322207](https://github.com/microsoft/vscode/issues/322207)

## Summary

The reported cache invalidation and re-indexing are owned by the third-party Kilo Code extension: VS Code derives global storage from the stable extension identifier, not its installed version. VS Code also already lets users disable automatic updates for an individual extension.

## Change summary

Preserve expensive extension indexes across updates and require user confirmation before an update triggers substantial re-indexing.

## Best solution

Kilo Code should retain or reconnect its index across activation and updates, validate backend availability before declaring the index absent, and throttle or confirm expensive rebuilding itself. Users who need manual update timing can disable Auto Update specifically for Kilo Code in the Extensions view.

## Vision fit

- **Fit:** rejected
- **Reason:** Persistence and compute policy for a specialized indexing workload belong in the extension that owns the index and initiates the work, while core should remain lightweight.
- **Evidence:** Values and guardrails: “The power lives in extensions” and “Out of the box, VS Code is a text editor: lightweight and fast.”

  > Thanks for the detailed report. VS Code's `globalStorageUri` is based on the stable extension identifier rather than the installed version, and Auto Update can already be disabled specifically for Kilo Code from its Extensions view context menu; the decision to discard or rebuild the index and consume these resources is made by Kilo Code. Please report the persistent re-indexing to https://github.com/Kilo-Org/kilocode/issues so the extension can preserve or reconnect its index and avoid an automatic full rebuild.

## Evidence

- **existing update control:** src/vs/workbench/contrib/extensions/browser/extensionsActions.ts defines workbench.extensions.action.toggleAutoUpdateForExtension, and extensionsWorkbenchService.test.ts verifies disabling auto-update for one extension while global auto-update remains enabled.

- **extension tracker:** Kilo Code is maintained in https://github.com/Kilo-Org/kilocode, outside the VS Code team's extension roster.
