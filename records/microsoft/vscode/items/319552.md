# Issue #319552 — Windows: PowerShell Store detection throws ENOENT when scanning %LOCALAPPDATA%\Microsoft\WindowsApps

[https://github.com/microsoft/vscode/issues/319552](https://github.com/microsoft/vscode/issues/319552)

## Summary

Confirmed on main: `findPSCoreMsix()` in `src/vs/base/node/powershell.ts` guards with `existsDirectory` but leaves the subsequent `readdir` unprotected — if the directory is absent or inaccessible at read time, the ENOENT propagates and aborts shell detection. A small try/catch returning null would let detection fall through to Windows PowerShell.

## Change summary

PowerShell Store detection throws an unhandled ENOENT when `%LOCALAPPDATA%\Microsoft\WindowsApps` cannot be read, aborting shell profile detection.

## Best solution

Wrap the `pfs.Promises.readdir(msixAppDir)` call on line 212 of `src/vs/base/node/powershell.ts` in a try/catch that returns `null` on failure, so Store PowerShell detection degrades gracefully and the detector continues to find Windows PowerShell.
