# Issue #224685 — "Copy Call Stack" in Debug uses the wrong path separator when debugging cross platform

[https://github.com/microsoft/vscode/issues/224685](https://github.com/microsoft/vscode/issues/224685)

## Summary

The cross-platform path defect remains on current main: Copy Call Stack formats each source through `URI.fsPath`, which replaces forward slashes with the local Windows separator even when the source belongs to a remote Linux session. The issue is correctly routed to debug and should remain open for a bounded fix.

## Change summary

Make Copy Call Stack preserve the remote source's path formatting instead of applying the client operating system's separator.

## Best solution

Format stack-frame source URIs through VS Code's URI label service when producing copied call stacks, preserving function names, line numbers, in-memory source labels, and existing line-ending behavior.

Acceptance requires a regression test covering a URI formatter whose output differs from `URI.fsPath`.
- **Trace:**

  > The `debug.copyStackTrace` command in src/vs/workbench/contrib/debug/browser/debugCommands.ts obtains the selected frame and serializes every frame through `StackFrame.toString()`. That method in src/vs/workbench/contrib/debug/common/debugModel.ts uses `source.uri.fsPath`; src/vs/base/common/uri.ts shows that `uriToFsPath` rewrites `/` to `\` according to the client-side `isWindows` value, not the remote filesystem. Debug surfaces already obtain remote-aware presentation through `ILabelService.getUriLabel`, including CallStackView. The closed, unmerged https://github.com/microsoft/vscode/pull/224686 confirms the intended boundary but its malformed test must not be copied. ## Evidence

- **current source:** `debug.copyStackTrace` in src/vs/workbench/contrib/debug/browser/debugCommands.ts still copies `frame.thread.getCallStack().map(sf => sf.toString())`; `StackFrame.toString()` in src/vs/workbench/contrib/debug/common/debugModel.ts formats non-memory sources with `this.source.uri.fsPath`.
- **root cause:** `uriToFsPath` in src/vs/base/common/uri.ts replaces every `/` with `\` whenever the client-side `isWindows` flag is true, directly explaining the reported Linux path `/home/vmware/foo.py` becoming `\home\vmware\foo.py` on a Windows Remote-SSH client.
- **existing pattern:** The debug UI already uses `ILabelService.getUriLabel`, including the stack-frame hover in src/vs/workbench/contrib/debug/browser/callStackView.ts, so remote-aware URI presentation is available in this area.
- **unmerged fix attempt:** https://github.com/microsoft/vscode/pull/224686 proposed using URI label formatting and adding coverage, but it was closed unmerged after its new test failed and the author did not address the review question: https://github.com/microsoft/vscode/pull/224686#discussion_r1786893981.
