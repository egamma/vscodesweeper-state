# Issue #98343 — Resize Pane actions for all panes

[https://github.com/microsoft/vscode/issues/98343](https://github.com/microsoft/vscode/issues/98343)

## Summary

Keep open: current commands resize workbench parts and editor groups, but do not provide equivalent keyboard resizing for individual non-terminal views. The maintainer-accepted request remains necessary, and a later sidebar-resizing report was explicitly consolidated into this issue.

## Change summary

Provide keyboard-accessible resize actions across workbench panes, including individual views outside the terminal.

## Best solution

Provide a consistent keyboard-resizing model for individual workbench views and their containing parts, with command names that distinguish the two targets. Preserve existing terminal split behavior and decide the observable targeting and directional semantics with the layout owner.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/layoutActions.ts`, `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/parts/views/viewPaneContainer.ts`
- **Validation:** After agreeing on targeting semantics, use keyboard-only checks with two expanded views in the sidebar and two in the panel: resize the focused individual view relative to its sibling, verify container-targeted commands still resize the containing part, and verify existing editor-group and terminal-split resize actions retain their behavior.
- **Behavior:**

  > Keyboard users should be able to resize individual non-terminal workbench views, rather than having only their containing sidebar or panel resized. Existing container-size commands provide partial coverage but do not satisfy the individual-view use case acknowledged in the discussion. Acceptance should include multiple expanded views in both sidebar and panel layouts, clear command target names, and unchanged existing editor-group and terminal-split behavior.
- **Trace:**

  > BaseResizeViewAction in src/vs/workbench/browser/actions/layoutActions.ts resolves focus to a workbench Parts value and calls IWorkbenchLayoutService.resizePart. The implementation in src/vs/workbench/browser/layout.ts resizes entire sidebar, panel, and auxiliary-bar parts, while editor focus can resize the active editor group. ViewPaneContainer in src/vs/workbench/browser/parts/views/viewPaneContainer.ts already exposes individual-pane sizing through resizePane and getPaneSize, but the inspected generic commands do not use it. Terminal directional actions in src/vs/workbench/contrib/terminal/browser/terminalActions.ts have their own active-group behavior and should retain it. https://github.com/microsoft/vscode/issues/222196 was explicitly consolidated into this issue; https://github.com/microsoft/vscode/issues/145890 concerns a separate, narrower directional editor-resizing request. The remaining uncertainty is the user-visible command model for choosing individual views versus containing parts and the meaning of directional resizing outside terminals.
- **Open decisions:**
  - Should existing Increase/Decrease Current View Size commands continue to target containing parts with clarified names, or change to target individual focused views while container resizing gets separate commands?
  - For non-terminal views, should resizing expose orientation-aware increase/decrease actions or explicit left/right/up/down actions, and which neighboring boundary should a directional action move?
