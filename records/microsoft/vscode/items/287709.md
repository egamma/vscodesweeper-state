# Issue #287709 — For Background Agents, let me choose the branch name. For important for tracking tickets.

[https://github.com/microsoft/vscode/issues/287709](https://github.com/microsoft/vscode/issues/287709)

## Summary

Keep open: current code offers descriptive automatic names, branch prefixes, and base-branch selection, but these do not provide explicit per-session branch naming for ticket tracking. No verified older canonical owns that specific request.

## Change summary

Let users choose the branch name created for a Background Agent session, including ticket identifiers.

## Best solution

Provide an optional user-chosen name for a new isolated session's branch while retaining automatic naming when no name is supplied. Settle the naming contract and its placement in session creation before implementation.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/chatSessions/vscode-node/sessionOptionGroupBuilder.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessions.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorktreeServiceImpl.ts`, `src/vs/platform/agentHost/common/sessionConfigKeys.ts`, `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`, `src/vs/platform/agentHost/node/shared/agentBranchNameGenerator.ts`
- **Validation:** Create an isolated Background Agent session with a chosen ticket-oriented name and inspect its actual Git branch and displayed session branch. Verify that omitting a name preserves automatic naming, invalid or conflicting names receive explicit feedback under the agreed contract, and base-branch selection remains independent.
- **Behavior:**

  > Users starting an isolated Background Agent session should be able to choose a branch name suitable for tracking a ticket rather than accepting only an automatically generated name. The resulting Git branch and session display should agree with the naming contract approved by the maintainer. Users who do not supply a name retain automatic naming. Acceptance should cover a ticket-oriented name, an omitted name, invalid input, and an existing-name conflict.
- **Trace:**

  > The legacy Copilot flow separates selected branch options from newBranch: CopilotCLIChatSessions.generateNewBranchName derives the latter from the prompt, while ChatSessionWorktreeServiceImpl.generateBranchName applies prefixes and collision suffixes. The newer host flow likewise separates the base branch from generated worktree naming: SessionConfigKey.Branch identifies the base, and WorktreeIsolation passes prompt and prefix to AgentBranchNameGenerator. The prefix is read-only session configuration and the generator has no exact-name input. Preserve base-branch selection, automatic defaults, worktree isolation, and existing-session identity; renaming active sessions is outside the reported creation request. https://github.com/microsoft/vscode/issues/299417 is related automatic-naming work, not an older canonical. The unresolved boundary is the user-visible naming contract and where users supply it.
- **Open decisions:**
  - Does a supplied name specify the complete Git branch name, or a suffix under the existing copilot/ or agents/ prefix?
  - Where should users enter the name during Background Agent session creation, including delegation into a new session?
  - If the requested name already exists, should creation require a different name or offer an explicitly confirmed alternative?
