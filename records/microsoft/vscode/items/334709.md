# Issue #334709 — Search: case conversion reinterprets literal dollar sequences in captured text

[https://github.com/microsoft/vscode/issues/334709](https://github.com/microsoft/vscode/issues/334709)

## Summary

Confirmed real bug in `replaceWithCaseOperations` on current main: it builds a replacement string containing raw captured text (which may itself contain `$1`, `$&`, `$$` sequences) and hands it to `String.prototype.replace`, so those literal dollar sequences get reinterpreted as replacement syntax. There's already an open PR fixing this, so it should be reviewed/landed rather than auto-fixed here.

## Change summary

When Replace-in-Files applies a case-conversion (`\U`, `\u`, `\L`, `\l`) to a captured group, dollar sequences (`$1`, `$&`, `$$`) that are part of the captured file content get corrupted because they're reinterpreted by `String.replace`.

## Best solution

Land or iterate on the linked fix PR https://github.com/microsoft/vscode/pull/334710, which addresses this by escaping/preserving literal dollar sequences in the case-converted captured text before it's passed to `String.replace` in src/vs/workbench/services/search/common/replace.ts.
