# Issue #212072 — Color-highlight popups

[https://github.com/microsoft/vscode/issues/212072](https://github.com/microsoft/vscode/issues/212072)

## Summary

Keep open for a quick-input visibility design decision. Theme customization provides a workaround, but does not establish that the default credential prompt is sufficiently noticeable; the closely matching open design issue is newer and cannot serve as a duplicate target under the re-review rules.

## Change summary

Make credential prompts and similar input popups more noticeable when users are watching the terminal.

## Best solution

Improve the attention hierarchy of input-required overlays through a consistent, theme-aware treatment rather than unconditional red/yellow flashing. Coordinate the design with https://github.com/microsoft/vscode/issues/237637 while retaining this older report's terminal-authentication scenario.

- **Behavior:**

  > A user watching terminal output should notice when Git is waiting for credentials in a quick-input popup rather than mistake the command for a hang. The improvement must preserve readable, theme-compatible input and existing keyboard interaction. Acceptance should cover the terminal-authentication scenario and ordinary quick inputs across light, dark and high-contrast themes, including reduced-motion mode. Red/yellow flashing is the reporter's suggested mechanism, not an agreed acceptance requirement.
- **Trace:**

  > Git HTTP and SSH credential requests in extensions/git/src/askpass.ts call window.showInputBox with ignoreFocusOut enabled. The shared quick-input controller applies theme colors in updateStyles, and quickInput.css supplies overlay elevation and an opening animation gated on modern UI and enabled motion. Existing quickInput color tokens allow a manual contrast workaround; the report does not establish broken focus or credential handling. The uncertainty is which default attention treatment should be used and whether it applies to every quick input or only input-required prompts. Coordinate with the newer design discussion at https://github.com/microsoft/vscode/issues/237637, whose comments independently describe missed Git-login prompts. Preserve authentication semantics, password masking, keyboard focus and reduced-motion behavior; do not expand this into unrelated theme or font work.
- **Open decisions:**
  - Should the stronger attention treatment apply to all quick inputs or specifically to prompts that block an operation pending user input?
  - Should the default treatment emphasize the overlay continuously while it is open, or provide an arrival-only attention cue?
