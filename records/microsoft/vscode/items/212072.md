# Issue #212072 — Color-highlight popups

[https://github.com/microsoft/vscode/issues/212072](https://github.com/microsoft/vscode/issues/212072)

## Summary

Keep open for a quick-input visibility design decision: keyboard focus does not address the reporter's difficulty noticing a credential prompt while watching the terminal. Existing color customization is a workaround; the closely matching open reports are newer and cannot be duplicate canonicals for this re-reviewed issue.

## Change summary

Make credential prompts and similar input-requiring popups more visually noticeable when they interrupt terminal work.

## Best solution

Agree on a theme-aware attention treatment for input-requiring quick-input widgets, preserving readability and consistency with other quick-input surfaces rather than mandating red/yellow flashing. Coordinate the design with the related quick-input visibility exploration.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/quickInputService.ts`, `src/vs/platform/theme/common/colors/quickpickColors.ts`
- **Validation:** After choosing a design, trigger a Git credential prompt from the integrated terminal while attention remains on terminal output. Check its discoverability and readability in light, dark, and high-contrast themes; compare ordinary command-palette and file-picker interactions, preserve keyboard focus, and check reduced-motion behavior if animation is selected.
- **Behavior:**

  > A user waiting for a terminal Git command can overlook the credential input even when it receives keyboard focus, mistaking the command for a hang. Required input should be visually discoverable without relying on noticing the caret. Validate the chosen treatment across light, dark, and high-contrast themes while preserving keyboard interaction and the readability of ordinary quick-input widgets. Red/yellow flashing is the reporter's suggested approach, not a settled acceptance requirement.
- **Trace:**

  > QuickInputController.show in src/vs/platform/quickinput/browser/quickInputController.ts already focuses the input and resets validation decoration; this report does not establish a focus bug. QuickInputController.updateStyles and QuickInputService in src/vs/platform/quickinput/browser/quickInputService.ts use shared theme colors registered in src/vs/platform/theme/common/colors/quickpickColors.ts. Global workbench.colorCustomizations can increase contrast, but affects other quick-input uses too. Related evidence in https://github.com/microsoft/vscode/issues/216913 confirms the same terminal/password visibility problem, and https://github.com/microsoft/vscode/issues/237637 explores border, shadow, and backdrop treatments. Both are newer than this re-reviewed issue, so neither is a duplicate-close target. The uncertainty is the intended visual treatment and whether it applies to all quick input or only particular required-input scenarios; preserve existing focus, validation-severity semantics, and theme customization.
- **Open decisions:**
  - Should the attention treatment apply to all quick-input widgets or only input-required prompts such as credentials?
  - Should prominence come from persistent theme-aware contrast/elevation, a backdrop, or a transient attention cue?
