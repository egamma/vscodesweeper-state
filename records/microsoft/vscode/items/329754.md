# Issue #329754 — Settings Sync does not sync profile associations across machines

[https://github.com/microsoft/vscode/issues/329754](https://github.com/microsoft/vscode/issues/329754)

## Summary

Well-researched gap, confirmed in source: workspace/folder-to-profile associations (`profileAssociations`) are read/written entirely outside the Settings Sync pipeline, so they never travel with a synced profile to a new machine.

## Change summary

Settings Sync syncs profiles themselves but not the workspace/folder-to-profile association map, so folders reopen in Default on a new machine.

## Best solution

Extend Settings Sync (or the profile sync resource) to carry `StoredProfileAssociations`/`PROFILE_ASSOCIATIONS_KEY` from src/vs/platform/userDataProfile/common/userDataProfile.ts, with a best-effort path-matching fallback as the reporter suggests (option 1 in the issue); needs a maintainer design call on portability across differing absolute paths (options 2/3 in the issue).
