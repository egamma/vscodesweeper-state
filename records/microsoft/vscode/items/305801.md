# Issue #305801 — Sessions: No way to differentiate between sessions windows when you pop out editors

[https://github.com/microsoft/vscode/issues/305801](https://github.com/microsoft/vscode/issues/305801)

## Summary

A real gap remains on current main: popped-out session editors can all receive the static native title "Agents", making them indistinguishable in OS window switchers. This team-authored, On Deck request has maintainer support and no older canonical issue, so it should remain open.

## Change summary

Make each popped-out chat session window's native title identify the session it contains.

## Best solution

Give each auxiliary session window a title derived from its own active chat or session, updating when that title changes while retaining a clear Agents fallback. A maintainer should first settle the exact title composition and whether auxiliary windows follow their scoped editor or the globally active Agents session.

## Plan brief

- **Likely files:** `src/vs/sessions/electron-browser/parts/titlebarPart.ts`, `src/vs/sessions/browser/parts/titlebarPart.ts`, `src/vs/sessions/test/browser/titlebarPart.test.ts`
- **Validation:** Add focused title-service coverage with two auxiliary chat editor parts asserting that each document.title reflects its own ChatEditorInput title, updates after a title change, and does not alter the other auxiliary window; also verify the agreed fallback when no session is resolved.
- **Behavior:**

  > When two chat sessions are opened in separate auxiliary windows, each OS-level window title identifies the session displayed in that window so users can distinguish them in the task switcher or window menu. The title updates when that session is renamed or the window's active session editor changes. A window without a resolved session retains an agreed Agents fallback, and the main Agents window remains distinguishable.
- **Trace:**

  > OpenAgentSessionInNewWindowAction in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts sends each selected session to AUX_WINDOW_GROUP. AuxiliaryEditorPart normally creates a scoped WindowTitle for non-custom title bars, but the Agents custom native path creates AuxiliaryNativeTitlebarPart instead. NativeTitlebarPart.createContentArea in src/vs/sessions/electron-browser/parts/titlebarPart.ts writes the same localized "Agents" document.title for every target window, while the Sessions TitleService intentionally does not render WindowTitle. ChatEditorInput.getName() already resolves the session title from the live model, active registry, or persisted session data. Keep the boundary to Sessions-owned title behavior: do not change regular workbench auxiliary-window titles or the underlying chat-title model. The related https://github.com/microsoft/vscode/issues/335396 concerns configurable center-toolbar identity and is not a canonical for this per-window behavior.
- **Open decisions:**
  - Should each auxiliary window title follow the chat editor active in that window, or the globally active session in the main Agents window?
  - Should the native title be the session title alone or compose it with an Agents/product suffix, and what fallback should appear before the session resolves?
