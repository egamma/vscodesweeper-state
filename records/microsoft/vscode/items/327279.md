# Issue #327279 — Terminal tab actions become unresponsive during frequent OSC title updates

[https://github.com/microsoft/vscode/issues/327279](https://github.com/microsoft/vscode/issues/327279)

## Summary

Traced and confirmed in source on current main: every title-change event triggers an unthrottled full list refresh in TerminalTabList, which destroys/recreates row DOM (action bar buttons, rename input box) whenever a terminal emits frequent OSC title updates, breaking clicks and closing the rename editor mid-interaction.

## Change summary

Frequent OSC title updates (e.g. from an agent CLI) make terminal tab actions like trash, split, and rename unresponsive until the updates stop.

## Best solution

In src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts, debounce/throttle the refresh() triggered by onAnyInstanceTitleChange (e.g. via RunOnceScheduler, already used elsewhere in base/common/async.ts) instead of doing a synchronous full splice() on every title event, and avoid forcing domFocus() to cancel an in-progress rename purely because an unrelated instance's title changed.

- **Fix prompt:**

  > In src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts, TerminalTabList wires `this._terminalService.onAnyInstanceTitleChange(() => this.refresh())` (and similarly onAnyInstanceIconChange) directly to `refresh()`, which synchronously does `this.splice(0, this.length, this._terminalGroupService.instances.slice())` — a full re-render of every row on every single title change event. When a terminal emits OSC title sequences rapidly (e.g. an agent CLI printing progress in its title, as little as every 50ms), this causes the action bar buttons (trash/split) and the rename InputBox created in `_renderInputBox` to be destroyed and recreated between a user's mousedown/click, making the actions appear to do nothing, and causes an open rename edit box to close immediately because `refresh()`'s default `cancelEditing = true` path (`if (cancelEditing && this._terminalEditingService.isEditable(undefined)) { this.domFocus(); }`) fires on every title-change refresh, forcing focus away from the input regardless of which instance's title changed. Fix by coalescing refresh calls triggered by high-frequency title/icon events — e.g. introduce a `RunOnceScheduler` (from src/vs/base/common/async.ts, already used patterns exist in the codebase) to batch multiple refresh() calls within a short window (e.g. one animation frame or ~50-100ms) into a single splice, and/or scope the `cancelEditing` check so an in-progress rename is only cancelled when the edited instance itself changes, not on every unrelated title update. Do not change the unrelated refresh triggers (onDidChangeInstances, onDidChangeGroups, theme changes, etc.) or the rename UX for the instance actually being renamed. Validate with a test that fires onAnyInstanceTitleChange rapidly and asserts splice/refresh is called at most once per debounce window, and that an active rename editableData for instance A survives a title change fired for instance B.

## Evidence

- **unthrottled refresh:** terminalTabsList.ts line 132: `this._terminalService.onAnyInstanceTitleChange(() => this.refresh())` fires on every OSC title change with no debounce.
- **full re-render:** refresh() (line 234-240) calls `this.splice(0, this.length, this._terminalGroupService.instances.slice())`, replacing all list rows on every call.
