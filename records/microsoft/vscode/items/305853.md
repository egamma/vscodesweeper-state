# Issue #305853 — Expose `chatSessionResource` to `LanguageModelChatProvider.provideLanguageModelChatResponse()`

[https://github.com/microsoft/vscode/issues/305853](https://github.com/microsoft/vscode/issues/305853)

## Summary

A real API gap remains on main and the issue is already correctly routed. The optional session-resource design addresses the concern that language-model requests can also originate outside chat.

## Change summary

Expose the owning chat session URI to language-model providers for requests originating from a VS Code chat session.

## Best solution

Extend `ProvideLanguageModelChatResponseOptions` with an optional opaque session URI, populated only for chat-owned requests and left undefined for direct `LanguageModelChat.sendRequest()` calls. The API team should settle the privacy and lifetime semantics before implementation.
