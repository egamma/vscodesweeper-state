# Issue #146334 — Markdown preview switches to latest open markdown document

[https://github.com/microsoft/vscode/issues/146334](https://github.com/microsoft/vscode/issues/146334)

## Summary

Keep open: the document-switching symptom was independently confirmed and remains present in the current source. Preview locking provides a workaround, but does not settle this accepted report's request for independent reading state or establish that reopening preserves its scroll position.

## Change summary

Preserve a Markdown preview's document and reading position when its source editor is closed and Markdown files are subsequently opened.

## Best solution

Establish the intended reader-state behavior for previews whose source editor has closed, then preserve that state without unexpectedly changing ordinary unlocked-preview following and scroll synchronization. Confirm the reopening scroll-reset case separately from the already-confirmed document switch.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/src/preview/preview.ts`, `extensions/markdown-language-features/src/preview/previewManager.ts`, `extensions/markdown-language-features/src/preview/topmostLineMonitor.ts`
- **Validation:** In an Extension Development Host, open a long Markdown file and its preview, close the source, scroll the preview, reopen the source, and check the reading position. Then close the source and open a different Markdown file to check preview identity. Repeat with a locked preview and with the source remaining open to verify the agreed following and synchronization contract.
- **Behavior:**

  > The reporter uses Markdown preview as a reader after closing the source editor. Reopening that source should not unexpectedly discard the preview's reading position, and opening an unrelated Markdown file should not unexpectedly replace the reading document. Document switching is independently confirmed; the reopening scroll reset still needs verification. Acceptance must cover those two sequences separately and retain the agreed behavior of ordinary unlocked and locked previews.
- **Trace:**

  > DynamicMarkdownPreview in extensions/markdown-language-features/src/preview/preview.ts listens to active text-editor changes and updates an unlocked preview whenever a different Markdown document becomes active; it does not distinguish whether the original source editor remains open. The built-in markdown.showLockedPreviewToSide command already prevents document following, but matching editor visible-range events still reach the preview through TopmostLineMonitor and can request scrolling independently of lock state. MarkdownPreviewManager handles static-preview scroll restoration separately, so conclusions about that path must not be assumed to apply to dynamic previews. The exact reopening reset was not established from source and must be reproduced first. https://github.com/microsoft/vscode/issues/147718 contains related independent-reading-position reports, but is younger and does not absorb this issue. No implementation should broadly remove existing following or synchronization without settling the intended observable contract.
- **Open decisions:**
  - Should closing the source editor automatically make an unlocked preview retain its document until an explicit preview command, or should independent reading remain an explicitly selected mode?
  - When reopening a source editor whose preview has been scrolled independently, should the preview's reading position take precedence over the source editor's restored position while normal scroll synchronization is enabled?

## Evidence

- **Report and confirmation:** https://github.com/microsoft/vscode/issues/146334 provides separate sequences for losing scroll position after reopening the source and switching preview content after opening another Markdown file. The June 10, 2022 contributor comment confirms the latter, cannot reproduce the former, and asks for feedback before changing automatic following.
- **Current document-switching path:** extensions/markdown-language-features/src/preview/preview.ts:791-800 registers DynamicMarkdownPreview's active-editor listener. An unlocked preview updates to any different active Markdown document with a viewColumn; there is no condition exempting a preview whose original source editor was closed. This matches the report's steps 6-8.
- **Existing capability and its limits:** extensions/markdown-language-features/src/commands/showPreview.ts exposes markdown.showLockedPreviewToSide, registered in extensions/markdown-language-features/package.json. It creates a locked preview, which bypasses automatic document switching. Locking does not disable the topmost-line listener in DynamicMarkdownPreview: that listener still scrolls a matching preview when TopmostLineMonitor reports editor visible-range changes.
- **Scroll synchronization boundary:** extensions/markdown-language-features/src/preview/topmostLineMonitor.ts forwards Markdown editor visible-range changes through onDidChanged.
