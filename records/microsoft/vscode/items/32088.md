# Issue #32088 — Provide an API to show hover-like tooltip

[https://github.com/microsoft/vscode/issues/32088](https://github.com/microsoft/vscode/issues/32088)

## Summary

A meaningful stable-API gap remains despite improvements to keyboard-triggered hovers. This Backlog request has 34 upvotes and should remain open while the proposed expandable-hover API is evaluated and finalized.

## Change summary

Allow extensions to programmatically show custom editor hover content and progressively widen that content through repeated keyboard commands.

## Best solution

Finalize a supported editor hover verbosity API and document reliable trigger/refresh semantics for extension commands. The existing proposed API and ongoing expandable-hover testing provide the likely implementation path.

## Evidence

- **stable API gap:** src/vscode-dts/vscode.d.ts exposes HoverProvider for contributing hover data, but no dedicated API for showing or refreshing a one-off custom hover.
- **existing command:** src/vs/editor/contrib/hover/browser/hoverActions.ts implements editor.action.showHover with immediate, non-focusing behavior, addressing several keyboard UX complaints but not establishing the requested stable custom-hover API.
- **proposed implementation:** src/vscode-dts/vscode.proposed.editorHoverVerbosityLevel.d.ts defines progressive hover verbosity, but extensions/typescript-language-features/package.json still consumes it through enabledApiProposals rather than the stable API.
