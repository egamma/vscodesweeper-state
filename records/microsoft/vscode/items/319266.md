# Issue #319266 — VS Code's terminal fails to load PowerShell modules yet they successfully load in Windows Terminal (PowerShell 7+)

[https://github.com/microsoft/vscode/issues/319266](https://github.com/microsoft/vscode/issues/319266)

## Summary

Verified duplicate of #47816: VS Code on Windows inherits its environment from the parent process, so tools installed in user-PATH-only locations (fzf, oh-my-posh) are missing when VS Code is launched from the Start menu/Taskbar rather than from a terminal that already has the full PATH. The canonical issue requests a fresh environment block for terminals on Windows, which would solve this.

## Change summary

PowerShell modules depending on user-PATH binaries (fzf, oh-my-posh) fail to load in VS Code's terminal when launched from the Start menu, because VS Code inherits a stale or incomplete environment from its parent process on Windows.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/47816 — implementing fresh environment resolution for Windows terminals would deliver exactly the fix needed here. The reporter's workaround (launching VS Code from a terminal with `code .`) confirms the root cause is environment inheritance.
