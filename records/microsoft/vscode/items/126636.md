[https://github.com/microsoft/vscode/issues/126636](https://github.com/microsoft/vscode/issues/126636)

## Summary

Keep open for the remaining request to trust a test workspace at launch without disabling Workspace Trust altogether. The discussion confirms a working command-line workaround for the original failures, but it does not deliver that narrower capability; this team-authored Backlog item has no verified factual close.

## Change summary

Allow automated extension tests to launch with a specifically trusted workspace without editing persistent settings or disabling Workspace Trust globally.

## Best solution

Have the Workspace Trust owner decide whether to support explicit, test-launch-scoped trust while preserving normal Restricted Mode behavior. Keep the existing --disable-workspace-trust workaround documented separately from testing with Workspace Trust enabled.
