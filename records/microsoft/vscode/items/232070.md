# Issue #232070 — Git - diff view does not work for PDF files

[https://github.com/microsoft/vscode/issues/232070](https://github.com/microsoft/vscode/issues/232070)

## Summary

Keep open: the Git resource provider still applies text conversion when reading historical files, consistent with the reported replacement of PDF bytes by extracted text. The related reports do not satisfy the stronger duplicate bar for this re-reviewed item.

## Change summary

Historical PDF revisions should remain readable in Git comparisons instead of being replaced by text-conversion output.

## Best solution

Ensure historical PDF resources used by binary viewers provide the requested revision's PDF bytes, while preserving intentional text-conversion workflows. Establish the resource contract before changing the shared Git content path.

- **Behavior:**

  > A historical PDF opened from Source Control or the Source Control Graph can expose extracted text instead of the PDF revision, preventing binary viewers from opening it. The working-tree PDF remains intact, producing inconsistent comparison sides. Acceptance must cover both working-tree-versus-commit and commit-versus-commit comparisons with an explicit PDF conversion driver. Intentional textconv comparisons must retain their agreed behavior.
- **Trace:**

  > GitFileSystemProvider.readFile in extensions/git/src/fileSystemProvider.ts resolves the Git revision and delegates to Repository.buffer in extensions/git/src/repository.ts. The underlying method in extensions/git/src/git.ts unconditionally includes --textconv in git show and returns the resulting bytes. The conditional failure is corroborated by https://github.com/microsoft/vscode/issues/115614#issuecomment-919716441; the reporter's exact conversion configuration remains unverified. The boundary is historical Git content delivery, not PDF rendering or the newer HTTP 401 regression at https://github.com/microsoft/vscode/issues/299813. Preserve legitimate textconv behavior represented by https://github.com/microsoft/vscode/issues/206612. The unresolved contract is how raw binary resource reads and intentional converted text comparisons should coexist.
- **Open decisions:**
