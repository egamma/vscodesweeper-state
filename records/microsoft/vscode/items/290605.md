# Issue #290605 — Don't hardcode agent sessions

[https://github.com/microsoft/vscode/issues/290605](https://github.com/microsoft/vscode/issues/290605)

## Summary

The debt remains on current main: agent-session identity, presentation, and capabilities are still encoded through provider-specific enums and switches. The related core PR was closed without merging, while the existing contribution metadata already provides a foundation for removing this duplication.

## Change summary

Derive agent-session presentation and behavior from registered session contributions instead of hardcoded provider identifiers.

## Best solution

Make registered `IChatSessionsExtensionPoint` metadata the source of truth for names, descriptions, icons, ordering, and delegation capabilities, retaining explicit core logic only for behavior that cannot be represented as a contribution capability. This belongs in the chat session service and agent-sessions view integration.

## Vision fit

- **Fit:** aligned
- **Reason:** Provider-neutral agent sessions support the current direction toward one agent host serving multiple harnesses and reduce friction when adding future agents.
- **Evidence:** Durable themes: AI-assisted development and extension-ecosystem API hygiene; it also aligns with current multi-harness agent-host priorities.
