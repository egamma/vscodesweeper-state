# Issue #312110 — PendingMigrationError: navigator is now a global in nodejs thrown during module load on remote VS Code server,   causing repeated renderer crashes and Remote SSH disconnections

[https://github.com/microsoft/vscode/issues/312110](https://github.com/microsoft/vscode/issues/312110)

## Summary

Verified duplicate of #252077: same root cause (the navigator migration guard in extensionHostProcess.ts throwing PendingMigrationError when extensions access `navigator` at module load time on Node.js v21+). This report adds Copilot-specific detail but the underlying defect and fix boundary are identical — consolidating on the canonical issue.

## Change summary

The bundled Copilot extension accesses `navigator` at module load time on the remote extension host (Node.js v22), triggering VS Code's PendingMigrationError guard, which destabilizes the remote extension host and cascades into renderer crashes and Remote SSH/WSL disconnections.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/252077, which tracks the navigator migration guard problem across all affected extensions including Copilot. The fix is either to make the guard in `src/vs/workbench/api/node/extensionHostProcess.ts` (lines 140–149) less disruptive (e.g. suppress the error for built-in extensions, or switch the default of `extensions.supportNodeGlobalNavigator` to `true`), or to guard all top-level `navigator` accesses in the bundled Copilot extension (`extensions/copilot/src/util/vs/base/common/platform.ts` line 100). The Copilot-specific and WSL reproduction details from this report should carry over to the canonical issue.

## Evidence

- **navigator guard code:** src/vs/workbench/api/node/extensionHostProcess.ts lines 140–149: `Object.defineProperty(globalThis, 'navigator', { get: () => { onUnexpectedExternalError(new PendingMigrationError(...)); return undefined; } })` — this is the guard that fires PendingMigrationError for any top-level navigator access.
- **Copilot navigator access:** extensions/copilot/src/util/vs/base/common/platform.ts line 100: `typeof navigator === 'object'` triggers the getter on globalThis.navigator defined by the extension host guard, firing the PendingMigrationError.
- **setting exists but defaults off:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts line 362: `extensions.supportNodeGlobalNavigator` setting exists (default: false). When true, it passes `--supportGlobalNavigator` to the extension host, which skips the guard — but this doesn't fix built-in extensions accessing the guarded global.
- **multiple confirmations:** Comments from 5+ independent reporters (SSH, WSL, Codespaces) across VS Code versions 1.117–1.129, confirming the same crash pattern and stack trace.
