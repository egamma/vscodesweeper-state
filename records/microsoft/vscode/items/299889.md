# Issue #299889 — In WSL, Export Chat as Zip default location fails: attempts to write to a Windows-like version of the actual path that doesn't exist

[https://github.com/microsoft/vscode/issues/299889](https://github.com/microsoft/vscode/issues/299889)

## Summary

Real bug, still present on main: the export-chat-as-zip action writes via `nativeHostService.createZipFile` in the main (Windows) process, which calls `zipPath.fsPath` on a URI whose path is a WSL/Linux filesystem path — producing an invalid Windows path like `C:\home\dagood\...`. No fix has landed. Routing to the chat area for attention.

## Change summary

Exporting a chat as zip from a WSL remote session fails because the selected save path (a Linux path) is interpreted as a Windows path by the main process.

## Best solution

The fix should either write via the remote file service (IFileService) instead of the native host service, or the action should detect a remote/WSL session and handle path translation. The bug is in `src/vs/workbench/contrib/chat/electron-browser/actions/chatExportZip.ts` at line 111 where `result` (a URI from the save dialog with a Linux-style path) is passed to `nativeHostService.createZipFile`, which runs in the main process and calls `.fsPath` to get a Windows path.
