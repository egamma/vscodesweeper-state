# Issue #299889 — In WSL, Export Chat as Zip default location fails: attempts to write to a Windows-like version of the actual path that doesn't exist

[https://github.com/microsoft/vscode/issues/299889](https://github.com/microsoft/vscode/issues/299889)

## Summary

The defect remains on current main and is conclusively visible in the source: the chat export action allows a WSL destination URI, then hands it to a Windows-native ZIP writer that interprets `/home/...` as `C:\home\...`. This team-authored issue should remain open for a bounded fix.

## Change summary

Export Chat as Zip fails for the default WSL destination because the remote path is converted into a nonexistent Windows path.

## Best solution

Honor the URI returned by the save dialog: create the archive through a local temporary file when necessary, then write or move it to the selected remote destination through `IFileService`, while preserving direct native ZIP creation for local destinations.

## Evidence

- **source reproduction:** `src/vs/workbench/contrib/chat/electron-browser/actions/chatExportZip.ts` obtains a destination from `IFileDialogService.showSaveDialog` without restricting the filesystem and passes that URI directly to `INativeHostService.createZipFile`.
- **root cause:** `src/vs/platform/native/electron-main/nativeHostMainService.ts` writes the archive with `zip(zipPath.fsPath, ...)` in the local Electron main process. On a Windows client, the remote URI path `/home/...` therefore becomes the reported `C:\home\...` path.
