# Issue #204535 — Option to show intellisense only after certain number of characters typed

[https://github.com/microsoft/vscode/issues/204535](https://github.com/microsoft/vscode/issues/204535)

## Summary

Keep this accepted, well-supported request open: current suggestion settings do not provide a minimum-character threshold. The remaining product decision is which automatic suggestion modes the threshold should affect, while preserving explicit invocation.

## Change summary

Allow users to configure a minimum number of typed characters before IntelliSense suggestions appear automatically.

## Best solution

Provide an opt-in prefix-length threshold in the editor suggestion system, retaining current behavior by default and allowing explicit invocation below the threshold. Settle its interaction with trigger characters and inline suggestions before implementation.

- **Behavior:**

  > Users can choose a minimum typed-prefix length before automatic IntelliSense suggestions appear, avoiding distracting one-character popups while retaining useful completions after more input. Explicit editor.action.triggerSuggest remains available below the threshold. Existing behavior remains unchanged without opting in. Acceptance checks cover below-threshold suppression, activation at the threshold, manual invocation, and the agreed treatment of trigger characters and inline suggestion modes.
- **Trace:**

  > LineContext.shouldAutoTrigger and SuggestModel._doTriggerQuickSuggest in src/vs/editor/contrib/suggest/browser/suggestModel.ts govern ordinary automatic suggestions without a configurable length threshold. _updateTriggerCharacters separately calls trigger with auto: true and CompletionTriggerKind.TriggerCharacter; trigger is also shared with manual invocation. Configuration lives in src/vs/editor/common/config/editorOptions.ts, with the public editor option surface in src/vs/monaco.d.ts; inline quick suggestions have a separate path in src/vs/editor/contrib/suggest/browser/suggestInlineCompletions.ts. The TriggerAndCancelOracle suite in src/vs/editor/contrib/suggest/test/browser/suggestModel.test.ts already exercises typing and manual triggering. The historical patch at https://github.com/microsoft/vscode/issues/204535#issuecomment-5887967777 is not a verified implementation and its unconditional shared-trigger guard would restrict manual suggestions. Preserve current default behavior and existing provider filtering, snippet navigation, and inline-completion coordination. Uncertainty begins at whether the new threshold covers only quick-suggestion popups or additional automatic modes.
- **Open decisions:**
  - Should the threshold apply only to ordinary quick-suggestion popups, or also suppress provider trigger-character popups such as member completions after a dot?
  - Should the threshold also affect quick suggestions configured as inline ghost text or independently provided inline completions, or leave those modes unchanged?
