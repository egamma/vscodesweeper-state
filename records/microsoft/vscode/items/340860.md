# Issue #340860 — Agent Host: generic ACP provider for the Agents window

[https://github.com/microsoft/vscode/issues/340860](https://github.com/microsoft/vscode/issues/340860)

## Summary

Keep open pending a maintainer decision on the generic ACP integration direction. The requested capability is absent from the inspected main sources, and an open implementation PR already owns the fix lane.

## Change summary

Allow configured ACP-compatible agent CLIs to run as Agent Host providers in the Agents window.

## Best solution

Resolve whether ACP integration belongs in a built-in provider or behind an extension registration API, then review https://github.com/microsoft/vscode/pull/340863 against that decision. Explicitly reconcile its current enablement default and deferred discovery/filtering work with the original off-by-default proposal before accepting it.

## Evidence

- **Existing-capability check:** src/vs/platform/agentHost/node/agentHostMain.ts:190-225 registers Copilot, Claude and Codex providers; agentHostServerMain.ts likewise registers those providers, plus a scripted mock. Searches of the Agent Host, Sessions and chat sources found no acpAgent/acpAgents settings or generic ACP implementation. Existing provider toggles do not launch arbitrary ACP-compatible CLIs.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/340863 is open and unmerged, and its body explicitly says it is part of this issue. It proposes the ACP client, provider, configuration and registration paths. Its claimed manual checks are contributor-reported evidence for the PR, not evidence that the capability exists on main.
- **Proposal and PR differ:** The issue requests experimental off-by-default support. https://github.com/microsoft/vscode/pull/340863 currently describes chat.agentHost.acpAgent.enabled as default true, omits advertised fs/* capabilities, and defers native CLI discovery and dynamic Harness filtering. These differences need review rather than a completed-close verdict.
- **Related direction discussions:** https://github.com/microsoft/vscode/issues/265496 is open and locked, and requests general ACP support. https://github.com/microsoft/vscode/issues/325827 is open and requests extension registration of full Agent Host providers. These establish related product-direction discussions, but do not settle this concrete provider proposal or its linked open PR; no duplicate close is proposed for this re-reviewed item.
- **Existing alternatives are partial:** https://github.com/microsoft/vscode/issues/325827#issuecomment-5945244541 reports that an external AHP host can connect using sessions.remoteAgentHost.add, but requires manual process management and is not a first-class local harness. An external AHP host is not the requested built-in adapter for configured ACP stdio agents.
- **Discussion and external interest:** The reporter's October 22 comment asks for a direction decision and offers to rework the existing PR around an extension API. https://github.com/anomalyco/opencode/issues/53836 separately requests native AHP interoperability; that is related demand, not proof that OpenCode's existing ACP mode already integrates with VS Code.
