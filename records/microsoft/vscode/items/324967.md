# Issue #324967 — Browser: Open Integrated Browser needs an allow list

[https://github.com/microsoft/vscode/issues/324967](https://github.com/microsoft/vscode/issues/324967)

## Summary

Valid feature request with 21 upvotes (already promoted to Backlog). The integrated browser's `login` event handler only supplies credentials for the tunnel proxy — there is no setting to configure an NTLM/Negotiate auth allowlist for arbitrary origins, so the gap is real and unfixed on main.

## Change summary

Add a configurable allowlist for Integrated Windows Authentication (NTLM/Negotiate) in the VS Code integrated browser, so corporate intranet sites render without requiring unsupported Chromium startup flags.

## Best solution

Expose a setting (e.g. `browser.authServerAllowlist`) that feeds Electron's session-level `authServerWhitelist` (or the `login` event handler) for the integrated browser's BrowserView sessions. The implementation likely touches `src/vs/platform/browserView/electron-main/browserView.ts` (the `login` handler) and a new configuration contribution. Enterprise admins should also be able to push this via policy.
