# Issue #332641 — Delete permanently doesn't ask for confirmation, but also doesn't delete permanently

[https://github.com/microsoft/vscode/issues/332641](https://github.com/microsoft/vscode/issues/332641)

## Summary

The missing confirmation is confirmed in current source, and the open PR https://github.com/microsoft/vscode/pull/334051 directly fixes it with regression coverage. Keep the issue open until that PR is reviewed and merged.

## Change summary

When `explorer.confirmDelete` is false, Delete Permanently bypasses its warning even though the operation skips Trash; small files can still be restored through VS Code's separate undo mechanism.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/334051 so the setting suppresses confirmation only for move-to-trash operations while permanent deletion always prompts.

## Evidence

- **source-confirmed defect:** In src/vs/workbench/contrib/files/browser/fileActions.ts, deleteFiles currently treats `explorer.confirmDelete === false` as unconditional confirmation, before distinguishing `useTrash`; therefore Delete Permanently also skips its warning.
- **deletion semantics:** The same function creates ResourceFileEdit with `skipTrashBin: !useTrash`, so Delete Permanently does bypass Trash. Its `maxSize: MAX_UNDO_FILE_SIZE` option independently preserves VS Code undo data for files up to 5 MB, explaining why Ctrl+Z can restore a permanently deleted small file.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/334051 is open, contains `Fixes #332641`, limits the setting check to `useTrash`, and adds a test covering prompt-free trash deletion versus confirmed permanent deletion.
