Verified duplicate of an older open report covering the same blank tunnel-session conversation surface and the exact missing-presenter exception. Consolidate this report's Windows build, Safari confirmation, and multi-provider evidence there.

Saved tunnel-backed Agent Host sessions fail to display their conversation and input because the web Agents client lacks a required service registration.

## Best solution

Track the fix in https://github.com/microsoft/vscode/issues/341638: ensure web Agents can construct its chat widgets with the required continuation presenter, without loading desktop-only local-host contributions. Preserve this report's build and cross-browser evidence in the consolidation.

## Evidence

- **Verified older open canonical:** https://github.com/microsoft/vscode/issues/341638 is open and was created on 2026-10-14, before this report. Its body describes tunnel sessions appearing in the web client while their conversation contents never render—the same reporter-observable symptom.
- **Canonical discussion confirms exact defect:** https://github.com/microsoft/vscode/issues/341638#issuecomment-6198543041 identifies the identical exception, '[createInstance] agentHostPolicyContinuationService depends on agentHostPolicyContinuationPresenter which is NOT registered.' The commenter reproduced it using the published web bundle's ChatWidget and strict dependency injector, and explicitly distinguishes it from separate tunnel-service and BYOK discovery problems.
- **Current source confirms missing registration:** At checkout d1eaacc5a33577b2d5b533f5770962ad592ea705, src/vs/sessions/contrib/chat/browser/chatView.ts constructs ChatWidget, whose constructor in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts requires IAgentHostPolicyContinuationService. The service requires IAgentHostPolicyContinuationPresenter. The Sessions presenter registration is in src/vs/sessions/contrib/providers/agentHost/browser/localAgentHost.contribution.ts, imported only by sessions.desktop.main.ts; sessions.web.main.ts loads neither that contribution nor the normal editor's presenter registration. The shared continuation-service registration is loaded through sessions.common.main.ts.
- **Unique evidence retained:** https://github.com/microsoft/vscode/issues/342296 supplies Windows Insiders commit a0c6520313624aceb3f3a80eff7932be6a00405a, successful tunnel initialization and saved-session discovery, failures for both Copilot CLI and Codex sessions, and confirmation in a fresh browser tab and Safari. These details corroborate the canonical's client-side construction failure rather than establish a distinct root cause.
