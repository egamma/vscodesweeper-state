# Issue #336898 — Agents Window: Editor action buttons overlap when tab wrapping is enabled

[https://github.com/microsoft/vscode/issues/336898](https://github.com/microsoft/vscode/issues/336898)

## Summary

The wrapped Agents editor controls still share the same absolute positioning on main. Keep this reopened issue open while the directly linked fix in PR 340834 is reviewed and merged; the earlier closing PR did not resolve this defect.

## Change summary

Prevent contextual actions, layout actions, and Add Tab from overlapping when Agents Window editor tabs wrap, including Connected tabs.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/340834, confirming that both toolbars and Add Tab remain separate across wrapped layouts and that an Add Tab-only final row leaves preceding Connected tabs styled as upper-row pills.

## Evidence

- **current source confirms toolbar collision:** src/vs/workbench/browser/parts/editor/editorTabsControl.ts:207-218 creates the contextual and layout toolbar containers as siblings. With wrapping enabled, src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css:563-569 and src/vs/sessions/browser/parts/media/editorPart.css:238-243 independently position those containers at bottom: 0; right: 0. Both visible toolbars therefore occupy the same trailing location.
- **Add Tab clearance remains incomplete:** MultiEditorTabsControl.doLayoutTabsWrapping in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts:2190-2213 sums the toolbar widths into --last-tab-margin-right. However, multieditortabscontrol.css:192-193 and src/vs/workbench/contrib/modernUI/browser/media/tabs.css:86-87 apply that clearance to .tab:last-child, which does not match a trailing .tabs-bar-add-tab element. The source still contains the reported clearance gap.
- **maintainer confirmed persistence after mistaken closure:** https://github.com/microsoft/vscode/issues/336898#issuecomment-6090519155 explicitly confirms that the wrapped Agents action/Add Tab overlap still reproduces and explains that https://github.com/microsoft/vscode/pull/340635 incorrectly closed this issue while fixing terminal Close-button reveal instead. That earlier PR is not a valid fix citation.
- **Connected wrapped-row requirement:** https://github.com/microsoft/vscode/issues/336898#issuecomment-5845556465 confirms the overlap with Connected tabs and identifies a second observable case: when only Add Tab wraps, the preceding real tabs do not receive upper-row pill styling.
- **verified open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/340834 is OPEN and explicitly says Fixes #336898. Its description addresses combined toolbar positioning and measurement, final Add Tab clearance, and Connected row classification. https://github.com/microsoft/vscode/pull/340835 is also OPEN but explicitly preserves layout and addresses cap contour instead; it is not the overlap fix.
