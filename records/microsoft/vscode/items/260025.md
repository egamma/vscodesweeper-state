# Issue #260025 — Setting {"explorer.enableUndo": false} not respected when Undo file renaming

[https://github.com/microsoft/vscode/issues/260025](https://github.com/microsoft/vscode/issues/260025)

## Summary

The reported path remains present on main: disabling Explorer undo only bypasses the Explorer-focused command handler, while editor undo can still encounter the rename operation and prompt. The issue should stay open because its current bug classification bars an as-designed close, and the older design precedent conflicts with the setting's present description.

## Change summary

With `explorer.enableUndo` disabled, editor Ctrl+Z still reaches an Explorer rename operation, prompts for confirmation, and blocks access to earlier text edits when declined.

## Best solution

Clarify that disabling Explorer undo either excludes Explorer-generated file operations from every resource undo path or explicitly retains editor-context behavior, then make the setting description and implementation agree. Treat the proposed Skip behavior as a separate product choice so declining a file operation does not silently alter undo ordering.
