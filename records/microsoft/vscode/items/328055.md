# Issue #328055 — Agent host can't list model in different custom endpoints but model have same id

[https://github.com/microsoft/vscode/issues/328055](https://github.com/microsoft/vscode/issues/328055)

## Summary

Well-evidenced bug: the reporter's own logs show the workbench/local surface correctly distinguishing two custom endpoints with duplicate model IDs (via provider-group-qualified identifiers like `customendpoint/SVCS OpenAI/databricks-gpt-5-6-luna`), while the Agent Host (Copilot CLI) surface collapses to bare `customendpoint/<id>` and drops one endpoint's models entirely — a real defect in the BYOK model bridge, though I could not pin the exact failing line with full certainty given the multi-layer bridge.

## Change summary

When two custom `chatLanguageModels.json` endpoints share the same vendor and model id but differ by endpoint name/URL, the Agent Host (Copilot CLI) model picker only lists one endpoint's models instead of both, while the Local Agent correctly lists both.

## Best solution

Trace how the provider-group qualifier (the endpoint's `name`) flows from `ILanguageModelChatMetadata.modelIdentifier` through `getByokLmSelectionModelId` (src/vs/platform/agentHost/common/agentHostByokLm.ts) and `_refreshByokModels`/`resolveByokSessionConfig` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts, copilotSessionLauncher.ts) into the `SessionModelInfo` list surfaced to `AgentHostLanguageModelProvider` — something in that chain is losing the group for one of two same-vendor custom endpoints before the Copilot CLI session's available-models list is published, unlike the workbench picker which retains it.
