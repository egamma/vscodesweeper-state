# Issue #41692 — Feature Request: Contribute commands with additional arguments

[https://github.com/microsoft/vscode/issues/41692](https://github.com/microsoft/vscode/issues/41692)

## Summary

This remains a valid Backlog API request with 20 community upvotes. Current main still cannot pass declarative arguments from extension command or menu contributions.

## Change summary

Allow multiple contributed menu or Command Palette entries to invoke one extension command with different declarative arguments.

## Best solution

Design an extension API that accepts JSON-serializable arguments on individual menu contributions and forwards them to the command handler, including Command Palette entries, without requiring duplicate command implementations.

## Evidence

- **current schema:** On current main, `IUserFriendlyMenuItem` and its JSON schema in `src/vs/workbench/services/actions/common/menusExtensionPoint.ts` expose only `command`, `alt`, `when`, and `group`; `IUserFriendlyCommand` likewise has no arguments property.
- **registration path:** `src/vs/workbench/services/actions/common/menusExtensionPoint.ts:1090-1156` converts each extension menu contribution into an `IMenuItem` without retaining or forwarding arbitrary arguments.
- **execution support:** `src/vs/platform/quickinput/browser/commandsQuickAccess.ts` can execute a command pick with `commandPick.args`, and `MenuItemAction` in `src/vs/platform/actions/common/actions.ts` supports internal action arguments, but the extension contribution schema provides no route to populate them.
