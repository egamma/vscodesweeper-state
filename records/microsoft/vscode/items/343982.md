# Issue #343982 — Cloud automation runs cannot open after initial session refresh fails

[https://github.com/microsoft/vscode/issues/343982](https://github.com/microsoft/vscode/issues/343982)

## Summary

Keep open: current main still permanently gates session listing, creation, and deletion on the original rejected startup refresh, even after the controller recovers. The maintainer's follow-up establishes the recovery requirements, and the defect is bounded to the shared ChatSessionsService.

## Change summary

Allow cloud automation runs and other session operations to recover after an initial controller refresh fails.

## Best solution

Restore session operations after successful controller recovery while preserving pending-initialization waits, visible errors, cancellation, and registration isolation. Keep this in the shared ChatSessionsService with focused regression coverage, without an Automations workaround or provider API change.
