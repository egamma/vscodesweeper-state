# Issue #341375 — Agent Host: create_pull_request runs the runtime's built-in tool instead of the GitHub Pull Requests extension's tool

[https://github.com/microsoft/vscode/issues/341375](https://github.com/microsoft/vscode/issues/341375)

## Summary

Still present on main: CLIENT_TOOL_SDK_POLICIES only marks semantic search as overriding a built-in, so the forwarded create_pull_request clashes with the runtime's built-in tool. Team-authored bug with detailed logs; keep open.

## Change summary

The forwarded GitHub Pull Requests create_pull_request tool is shadowed by the runtime's built-in tool in Agent Host sessions, so the model sees the built-in's failure.

## Best solution

Mark the forwarded create_pull_request as overriding the built-in (or otherwise avoid the name clash) in _createClientSdkTools, and track separately that the extension tool cannot find the worktree repo in the Agents window.

  > When the model calls create_pull_request in a local Agent Host session, only the GitHub Pull Requests extension tool runs and its result reaches the model. - **Trace:**

  > _createClientSdkTools in copilotAgentSession.ts registers client tools under their reference name. getClientToolSdkPolicy consults CLIENT_TOOL_SDK_POLICIES, which holds only semantic search, so create_pull_request is registered without overridesBuiltInTool. The runtime's built-in tool of the same name then runs and its completion arrives after the client's. Do not change the other overrides. The separate repo-lookup failure in the PR extension (getRepoInfo) is out of scope.
- **Open decisions:**
