# Issue #127918 — Make minimap slider visible when scrolling 

[https://github.com/microsoft/vscode/issues/127918](https://github.com/microsoft/vscode/issues/127918)

## Summary

The requested transient slider behavior remains absent on current main, and this accepted Backlog item is the oldest clear issue owning that work. The existing `always` mode is a workaround, but it does not provide the requested scroll-only visibility.

## Change summary

Temporarily reveal the minimap viewport slider while the editor is being scrolled, even when `editor.minimap.showSlider` is set to `mouseover`.

## Best solution

Keep the slider hidden at rest under the mouseover configuration, reveal it during editor scrolling, and hide it again after scrolling stops without changing the existing `always` behavior.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/viewParts/minimap/minimap.ts`, `src/vs/editor/browser/viewParts/minimap/minimap.css`
- **Validation:** With a long file and `editor.minimap.showSlider: "mouseover"`, scroll using the mouse wheel and scrollbar while the pointer remains outside the minimap: the slider should appear during scrolling, disappear after scrolling stops, and remain visible on minimap hover; verify that `showSlider: "always"` remains continuously visible.
- **Behavior:**

  > When the minimap slider is configured for mouseover visibility, scrolling the editor through the wheel, touchpad, or scrollbar should temporarily reveal the slider so the viewport position is visible. It should fade out after scrolling stops unless the minimap remains hovered. The existing continuously visible `always` mode must remain unchanged.
- **Trace:**

  > The `EditorMinimap` option in src/vs/editor/common/config/editorOptions.ts currently restricts `showSlider` to `always` or `mouseover`. Minimap visibility is controlled in src/vs/editor/browser/viewParts/minimap/minimap.css, where the slider appears only through minimap hover or the slider's own `active` class. In src/vs/editor/browser/viewParts/minimap/minimap.ts, `Minimap.onScrollChanged` applies `active` to the minimap container only for the separate `autohide: scroll` mode, while slider activity is limited to direct touch or drag interaction. The boundary is slider visibility feedback: minimap autohide behavior, scrolling mechanics, slider geometry, and the existing `always` behavior must not change. A later equivalent request, https://github.com/microsoft/vscode/issues/250241, was closed through the community feature-request lifecycle rather than implemented.
- **Open decisions:**
  - Should scrolling temporarily reveal the slider whenever `showSlider` is `mouseover`, or should `showSlider` gain a separate scroll-aware value?
  - Should slider visibility use the existing minimap autohide delay or a separately defined interaction timeout?
  - Which scroll sources should count, particularly programmatic scrolling and cursor-reveal scrolling in addition to wheel, touchpad, and scrollbar input?

## Evidence

- **current configuration gap:** src/vs/editor/common/config/editorOptions.ts defines `editor.minimap.showSlider` with only `always` and `mouseover`; there is no scroll-triggered slider mode.
- **current visibility path:** src/vs/editor/browser/viewParts/minimap/minimap.css reveals `.minimap-slider` only when the minimap is hovered or the slider itself has the `active` class.
- **scroll handling:** Minimap.onScrollChanged in src/vs/editor/browser/viewParts/minimap/minimap.ts activates the whole minimap only for `editor.minimap.autohide: scroll`; it does not activate the slider, so the central request remains unsatisfied.
