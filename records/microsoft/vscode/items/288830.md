- **Behavior:**

  > Normal terminal text should retain the same apparent font weight when an existing terminal is restored or deleted and recreated. The reporter sees normal text after reload but bold-looking text after recreation on macOS 15.7.3 with VS Code 1.108.1 and extensions disabled. Acceptance requires reproducing that sequence and demonstrating consistent text rendering without changing the user's configured font weight. Intentionally bold terminal output must remain bold.
- **Trace:**

  > TerminalConfigurationService._updateConfig in src/vs/workbench/contrib/terminal/browser/terminalConfigurationService.ts normalizes the normal and bold weights separately. XtermTerminal's constructor in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts passes those configured weights directly to xterm; _enableWebglRenderer and _disposeOfWebglRenderer manage the GPU renderer lifecycle and fallback. Source inspection did not reveal a conclusive weight mutation or reproduce the visual defect, so diagnosis must first distinguish effective option changes from renderer or glyph-cache differences. Preserve existing font settings, intentional ANSI bold output, and terminal restoration semantics. Related reports https://github.com/microsoft/vscode/issues/286870 and https://github.com/microsoft/vscode/issues/299442 have different established triggers and must not be assumed to explain this report.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode/issues/288830 specifies VS Code 1.108.1, macOS 15.7.3, extensions disabled, and the sequence: create a normal-weight terminal, reload successfully, delete it, then recreate it and observe bold-looking text. No comment independently confirms this exact reproduction.
- **Current font configuration:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:254-290 defaults terminal.integrated.fontWeight to normal and fontWeightBold to bold. TerminalConfigurationService._updateConfig preserves these values, and src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:239-253 passes them directly to each new xterm instance; this does not conclusively explain the reported visual change.
- **Renderer lifecycle:** XtermTerminal._enableWebglRenderer and _disposeOfWebglRenderer in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts initialize and dispose the WebGL addon with DOM fallback on failure. Its discussion links an xterm.js glyph fix, but does not establish that the macOS recreation-triggered bold appearance was fixed; its closed state also prevents using it as a duplicate canonical.
