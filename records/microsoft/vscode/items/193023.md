# Issue #193023 — "Format Notebook" damages LaTeX in Markdown cells

[https://github.com/microsoft/vscode/issues/193023](https://github.com/microsoft/vscode/issues/193023)

## Summary

Keep open: the reporter confirmed the corruption after upgrading, and current notebook formatting still has a fallback that invokes a document formatter for every cell, including Markdown cells. The issue is accepted as a bug in the Backlog, while the exact Markdown provider responsible for the destructive edit and the intended markup-cell formatting contract remain unresolved.

## Change summary

Running Format Notebook can rewrite LaTeX source in a Markdown cell and change the rendered equation.

## Best solution

Define and enforce notebook-formatting semantics that preserve Markdown-cell LaTeX while continuing to format eligible code cells, likely in the notebook formatting contribution and its interaction with notebook-level format code actions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/contrib/format/formatting.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts`
- **Validation:** Add a targeted notebook-formatting test with a Markdown cell containing the reported LaTeX and a Python code cell, using registered mock format providers; after Format Notebook, the code cell must follow the selected formatting contract and the LaTeX source must remain unchanged.
- **Behavior:**

  > Formatting a notebook must not alter the meaning or rendering of LaTeX in Markdown cells. With the reported equation in a Markdown cell and `b=1` in a Python cell, invoking Format Notebook must preserve the Markdown source while applying the intended code formatting. The acceptance test must also establish whether an explicitly selected Markdown formatter is included or excluded by the command.
- **Trace:**

  > The reporter confirmed the issue on VS Code 1.82.1 and supplied before/after screenshots at https://github.com/microsoft/vscode/issues/193023#issuecomment-1719262642. On current main, the `notebook.format` action in src/vs/workbench/contrib/notebook/browser/contrib/format/formatting.ts first asks `CodeActionParticipantUtils.checkAndRunFormatCodeAction` for a notebook-level action; its fallback then requests document-formatting edits for every cell without checking cell kind. The notebook-level action plumbing is in src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts. The uncertainty begins at provider selection: the report had Black plus multiple Markdown-formatting extensions installed, and no comment identifies which provider emitted the destructive edit. Preserve Format Cell behavior and ordinary code-cell formatter selection unless the chosen product contract explicitly requires otherwise.
- **Open decisions:**
  - Should Format Notebook apply registered Markdown formatters to markup cells, or should the command preserve markup cells and format only code cells unless a notebook-level formatter explicitly includes them?

## Evidence

- **confirmed reproduction:** The reporter reproduced the corruption after upgrading VS Code and extensions to 1.82.1, then documented the before/after LaTeX change at https://github.com/microsoft/vscode/issues/193023#issuecomment-1719262642.
- **current source path:** src/vs/workbench/contrib/notebook/browser/contrib/format/formatting.ts runs `checkAndRunFormatCodeAction`; when no notebook-level action applies, it maps over every `notebook.cells` entry and calls `getDocumentFormattingEditsWithSelectedProvider` without filtering markup cells.
- **unresolved provider boundary:** The report lists Black Formatter together with several Markdown formatters, but the discussion does not identify which provider returned the destructive Markdown edit. Current source therefore confirms that Markdown cells can enter the formatting path, not which extension produces this exact rewrite.
- **canonical search:** Repository issue searches found no older open issue reporting the same observable symptom. https://github.com/microsoft/vscode/issues/200503 is newer, closed, and concerns intermittent blank lines in Python code cells rather than deterministic LaTeX corruption in Markdown cells.
