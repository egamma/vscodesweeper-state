# Issue #193023 — "Format Notebook" damages LaTeX in Markdown cells

[https://github.com/microsoft/vscode/issues/193023](https://github.com/microsoft/vscode/issues/193023)

## Summary

The formatter-selection defect that could send Markdown cells through an unintended formatter has been fixed on main, so this can be closed as completed.

## Change summary

Formatting an entire notebook could alter LaTeX in Markdown cells by applying an unintended Markdown formatter after the configured formatter produced no edits.

## Best solution

Keep the formatter-selection behavior introduced by commit c4653faeb1dac658945e8792b5858ef95b2da3d7: each notebook cell uses only its selected formatter, and formatting stops instead of falling through to another provider.

## Evidence

- **fix commit:** https://github.com/microsoft/vscode/commit/c4653faeb1dac658945e8792b5858ef95b2da3d7 changed src/vs/workbench/contrib/notebook/browser/contrib/format/formatting.ts from getDocumentFormattingEditsUntilResult to getDocumentFormattingEditsWithSelectedProvider.
- **root cause:** The former path iterated through formatting providers until one returned edits. With Black configured, a Markdown cell unsupported by Black could therefore fall through to another installed formatter such as Prettier, which may escape LaTeX-significant Markdown characters.
- **current behavior:** Current main selects the configured provider for each cell through FormattingConflicts.select; src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts returns no provider when the configured formatter cannot format that cell language, preventing the unintended Markdown edits.
- **related verification:** https://github.com/microsoft/vscode/issues/212124 documents and verifies the same provider-fallthrough defect, and https://github.com/microsoft/vscode/pull/212185 states that the fix prevents other formatters from running after the default formatter returns no edits.
- **release:** Shipped in 1.90.0 — the earliest release tag containing c4653faeb1 (verified against the repo's release tags).
