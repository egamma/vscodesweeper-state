# Issue #334169 — Claude agent host harness ignores ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN (cc-switch and other Anthropic-compatible relays)

[https://github.com/microsoft/vscode/issues/334169](https://github.com/microsoft/vscode/issues/334169)

## Summary

Real, currently-unaddressed parity gap: the built-in Claude harness forwards real process-env ANTHROPIC_BASE_URL/AUTH_TOKEN in native mode, but nothing in the agent host reads the env block from ~/.claude/settings.json the way the standalone Claude Code CLI/SDK does, so relay configs written there (e.g. by cc-switch) are silently ignored.

## Change summary

Request that the Agent Host's native-mode Claude harness honor ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN from ~/.claude/settings.json's env block (and process env), for parity with the standalone Claude Code CLI/extension.

## Best solution

In src/vs/platform/agentHost/node/claude/claudeSdkOptions.ts (buildSubprocessEnv / buildOptions), when resolving native-mode transport, additionally read the env object from ~/.claude/settings.json (mirroring how the CLI/Agent SDK layers it) and merge ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN into the subprocess env and account-setup detection (claudeTransportMode.ts's isClaudeAccountSetUp) so third-party-relay users are recognized as having a usable native setup.
