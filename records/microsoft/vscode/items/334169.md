# Issue #334169 — Claude agent host harness ignores ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN (cc-switch and other Anthropic-compatible relays)

[https://github.com/microsoft/vscode/issues/334169](https://github.com/microsoft/vscode/issues/334169)

## Summary

Plausible, well-traced parity gap in the very new (1.136) built-in Claude harness: the harness's native/BYO-Anthropic env construction only forwards `process.env`, not the `env` block from `~/.claude/settings.json`, so a relay configured via `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` in that file (e.g. via cc-switch) isn't picked up the way the standalone CLI/extension picks it up — but I can't fully confirm from source alone whether the bundled SDK/CLI subprocess independently re-reads that file.

## Change summary

Request that the built-in Claude agent host harness honor ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN from the process environment and from `~/.claude/settings.json`'s `env` object, for parity with the standalone Claude Code CLI/extension.

## Best solution

Have the Claude harness parse the `env` object out of `~/.claude/settings.json` (and process env) for ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN and thread it into buildSubprocessEnv/native-mode account detection (src/vs/platform/agentHost/node/claude/claudeSdkOptions.ts, claudeTransportMode.ts), so cc-switch-style Anthropic-compatible relays are detected by isClaudeAccountSetUp and usable without forcing GitHub sign-in — this needs a maintainer decision on scope (which settings.json fields to honor) before implementation.

## Evidence
