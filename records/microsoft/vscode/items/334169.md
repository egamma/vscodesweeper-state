# Issue #334169 — Claude agent host harness ignores ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN (cc-switch and other Anthropic-compatible relays)

[https://github.com/microsoft/vscode/issues/334169](https://github.com/microsoft/vscode/issues/334169)

## Summary

Plausible parity gap for BYO-Anthropic relay users, but the root cause is ambiguous between VS Code's harness env plumbing and the bundled Claude Agent SDK's own settings.json resolution — too fresh (1 day old, no maintainer triage) and too dependent on the third-party SDK's internals to verify from source alone.

## Change summary

The built-in Claude harness should honor ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN from the process env and from ~/.claude/settings.json's `env` block, the way the standalone Claude Code CLI does, so Anthropic-compatible relays (e.g. via cc-switch) work without GitHub/Anthropic sign-in.

## Best solution

A maintainer with the SDK source should confirm whether `@anthropic-ai/claude-agent-sdk`'s accountInfo()/spawn resolution reads `~/.claude/settings.json`'s `env` block for BASE_URL/AUTH_TOKEN in native mode; if it doesn't, claudeSdkOptions.ts's buildSubprocessEnv(false)/buildModelEnumerationOptions would need to fold that settings file's env into the subprocess env before native account detection runs.
