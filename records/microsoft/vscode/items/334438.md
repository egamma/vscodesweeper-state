# Issue #334438 — Agent plugin skill namespaces are dropped, causing same-named skills to shadow each other

[https://github.com/microsoft/vscode/issues/334438](https://github.com/microsoft/vscode/issues/334438)

## Summary

The reported skill-loading/dedup step lives inside the downloaded Copilot agent SDK, not in this repo's TypeScript source, so this is best tracked as an upstream defect while the maintainer (aeschli) is still triaging which harness is affected. The suggested duplicate (#302181) describes the opposite symptom (extra duplication, not a dropped skill), so it doesn't clear the re-review duplicate bar.

## Change summary

When two enabled agent plugins each ship a skill with the same `name` in SKILL.md, only one skill survives into the model context because the plugin qualification is lost during final skill loading.

## Best solution

Confirm which harness(es) are affected (aeschli's open question) and trace the actual dedup/name-collapse behavior inside the Copilot agent SDK's `skills.discover` RPC implementation (downloaded via agentSdkDownloader, not vendored in this checkout); if VS Code-side code should instead pre-namespace or pass distinguishing metadata before calling discover, that decision belongs with the Copilot Chat/Agent Host maintainers.

## Evidence

- **discovery call is a downloaded SDK RPC:** src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts's discoverSkills() calls `client.rpc.skills.discover(discoveryRequest)` and simply maps the returned `skillDiscovery.skills` list (name/description/path) without any further name-based dedup on the VS Code side.
- **SDK is an external downloaded dependency:** src/vs/platform/agentHost/node/agentSdkDownloader.ts fetches the Copilot agent SDK package at runtime (`product.agentSdks?.[pkg.id]`); its internal skill-loading/dedup logic is not part of this checkout, so the 'qualification is lost during final skill loading' behavior described in the issue cannot be traced or confirmed from src/.
- **vscode-side plugin skill handling doesn't collapse by name:** src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts's toSdkSkillDirectories()/toSdkResourceDirectories() dedups only by parent directory path, and toChildCustomizations() dedups children by `id` (not bare skill name), so the reported name-collision drop isn't introduced by this repo's own conversion code.
- **maintainer still investigating:** aeschli (CONTRIBUTOR) asked "That's with the Local harness?" and only tentatively flagged https://github.com/microsoft/vscode/issues/302181 as a "possible dup" — that issue is about skill entries appearing twice when Agent Skills Location overlaps Plugin Locations (duplication), the opposite observable symptom from a skill being silently dropped due to a name collision across two distinct plugins.
