# Issue #334438 — Agent plugin skill namespaces are dropped, causing same-named skills to shadow each other

[https://github.com/microsoft/vscode/issues/334438](https://github.com/microsoft/vscode/issues/334438)

## Summary

Thanks for the detailed report — this describes a plausible, well-diagnosed defect in agent-plugin skill loading (name collision across plugins dropping one skill), but the exact fix point sits partly outside this checkout's inspectable source, so I can't cite a concrete commit or file for a close; routing for engineering investigation is the right next step.

## Change summary

When two installed agent plugins each ship a skill with the same unqualified `name` in SKILL.md, only one skill is loaded into the model context — the other is silently dropped because plugin-qualified names are lost before final dedup.

## Best solution

An engineer familiar with the Copilot/Claude agent-plugin skill-loading path should confirm whether the final dedup happens in-tree (e.g. the `pluginSkillNames`/`commandNames` handling in src/vs/platform/agentHost/node/claude/customizations/claudeSessionCustomizationDiscovery.ts, or the RPC-returned skill list in src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts's discoverSkills) or inside the bundled @github/copilot / @github/copilot-sdk dependency, and qualify skill identity by plugin+name (not bare name) through the load path.
