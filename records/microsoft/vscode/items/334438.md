# Issue #334438 — Agent plugin skill namespaces are dropped, causing same-named skills to shadow each other

[https://github.com/microsoft/vscode/issues/334438](https://github.com/microsoft/vscode/issues/334438)

## Summary

The reporter's diagnosis matches how this repo actually wires plugin skills to the Copilot CLI SDK: VS Code deliberately hands the SDK each plugin's own root directory (`pluginDirectories`) so the SDK itself discovers and namespaces skills, rather than VS Code enumerating them explicitly (to avoid exactly this kind of duplicate/shadow bug). If same-named skills from different plugins still shadow each other, the defect is in the SDK's own plugin/skill loader, not in this repository's TypeScript.

## Change summary

Two installed Copilot agent plugins with same-named `SKILL.md` skills (e.g. both named `troubleshooting`) result in one plugin's skill silently disappearing from the model context because the plugin-qualified identity is lost before final loading.

## Best solution

Track/forward this to the `@github/copilot` CLI SDK (currently pinned at 1.0.84-5 in package.json) — its skill loader must key skills by `(plugin, name)` rather than by bare `name` when consuming `pluginDirectories`. On the VS Code side, `CopilotSessionLauncher._buildSessionConfig` (src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts) already passes each file-based plugin's own directory separately via `pluginDirectories` (line ~1034) specifically so the SDK can discover skills without collision; only non-file-backed plugins get an explicit, flattened `skillDirectories` list via `toSdkSkillDirectories(pluginsWithoutDirs.flatMap(p => p.skills))` (line ~894), which loses plugin origin by design once flattened — that path could carry qualified names too, but the primary reported case (plugins with real files on disk) already goes through the per-plugin `pluginDirectories` route, so the SDK's own naming/precedence logic is the more likely source.
