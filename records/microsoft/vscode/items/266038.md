# Issue #266038 — requesting terminal icon and terminal color control via launch.json

[https://github.com/microsoft/vscode/issues/266038](https://github.com/microsoft/vscode/issues/266038)

## Summary

Keep this accepted feature request open: tasks.json already supports terminal icon and color configuration, but the inspected debug-terminal path does not provide equivalent per-launch control. The request has 23 upvotes, was promoted to Backlog, and no matching canonical issue was established.

## Change summary

Allow launch configurations to assign persistent terminal icons and colors that distinguish applications and environments without repeated manual changes.

## Best solution

Provide per-launch terminal appearance configuration consistent with the existing tasks.json icon.id and icon.color capability. Define its behavior across terminal creation and reuse while preserving existing defaults when no appearance is configured.

- **Behavior:**

  > Users can distinguish application environments through icons and colors declared in their launch configurations, without changing each resulting terminal manually. Different launch configurations retain their intended visual identity across repeated launches. Configurations without appearance options keep existing behavior. Existing tasks.json icon and color support remains unchanged; the acceptance checks include first creation and terminal reuse.
- **Trace:**

  > The reporter's tasks.json follow-up is already supported by icon.id and icon.color in src/vs/workbench/contrib/tasks/common/jsonSchema_v2.ts, consumed by TerminalTaskSystem in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts. The inspected DAP integrated-terminal path is ExtHostDebugService.$runInTerminal in src/vs/workbench/api/node/extHostDebugService.ts: new terminals receive a fixed debug icon and no per-launch color, while DebugTerminalCollection selects reusable terminals by name and serialized shell configuration. RunInTerminalRequestArguments currently carries no appearance fields. This establishes a gap on that path, but the trace has not established how launch configuration metadata should reach every relevant debugger or adapter-created terminal. Preserve command execution, environment handling, default appearance and existing task behavior. The request and demand are recorded at https://github.com/microsoft/vscode/issues/266038.
- **Open decisions:**
  - Should launch-configured appearance apply only to terminals requested through DAP runInTerminal, or also to debug terminals created directly by debugger extensions?
  - When a debug terminal is reused, should explicit launch-configured appearance replace subsequent manual icon/color changes, or should those manual changes persist?
