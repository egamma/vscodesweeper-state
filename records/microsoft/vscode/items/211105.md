# Issue #211105 — potential listener LEAK detected, having 185 listeners already.

[https://github.com/microsoft/vscode/issues/211105](https://github.com/microsoft/vscode/issues/211105)

## Summary

Still reproduces on current main: each visible notebook outline tree element creates its own menu and registers a listener on `menu.onDidChange()`, accumulating hundreds of listeners on large notebooks with large screens. The underlying per-element menu listener pattern identified in the discussion has not been addressed.

## Change summary

Large notebooks trigger listener leak warnings because the notebook outline tree creates a per-element menu with a `menu.onDidChange()` listener for every visible element.

## Best solution

Make the menu creation or its `onDidChange` listener lazy in the notebook outline renderer — either defer menu creation until hover/interaction (as discussed in comment 4), or adopt the contributed-tree pattern from https://github.com/microsoft/vscode/pull/219964 to avoid per-element listener accumulation. The fix belongs in `src/vs/workbench/contrib/notebook/browser/contrib/outline/notebookOutline.ts`, specifically in `setupToolbarListeners` and `renderElement`.
