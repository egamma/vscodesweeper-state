# Issue #304655 — Can't contribute a boolean?

[https://github.com/microsoft/vscode/issues/304655](https://github.com/microsoft/vscode/issues/304655)

## Summary

Current main still omits boolean-only language-model configuration properties because each model-picker path requires an explicit enum. This should remain open; it is also a team-authored report, so a judgment close is not available.

## Change summary

Allow a contributed boolean language-model configuration property to appear and be changed in the model picker.

## Best solution

Define a consistent model-picker presentation for boolean properties, then expose them across the shared configuration menu, navigation configuration, and model details while preserving existing enum behavior.

- **Behavior:**

  > A language-model provider can contribute a JSON Schema property with `type: 'boolean'`, a title, a default value, and a supported configuration group. The property appears in the model configuration UI, displays its effective value, and lets the user persist either `true` or `false`. Existing enum-backed properties and read-only behavior remain unchanged.
- **Trace:**

  > The reproducer in https://github.com/microsoft/vscode-copilot-chat/pull/4678 contributes a boolean `fast` property in the `navigation` group. On current main, createModelConfigurationActions in src/vs/workbench/contrib/chat/common/languageModels.ts discards properties without `enum`; getModelConfigProperty in modelPickerModelConfig.ts and the configurable-section scan in modelPickerHover.ts impose equivalent enum-only gates. The proposed API type in src/vscode-dts/vscode.proposed.chatProvider.d.ts otherwise accepts standard JSON Schema properties. Keep the change within language-model configuration presentation and persistence; do not alter unrelated settings-schema rendering or existing enum semantics.
- **Open decisions:**

## Evidence
