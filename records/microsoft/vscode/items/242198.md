# Issue #242198 — Support contributable quick pick detectors

[https://github.com/microsoft/vscode/issues/242198](https://github.com/microsoft/vscode/issues/242198)

## Summary

Keep open: current Quick Access does not expose contributable input detectors that suggest actions from pasted content. The request is already correctly routed and accepted into Backlog, with maintainer interest in the Command Center direction.

## Change summary

Allow static input-pattern contributions to suggest relevant actions, such as Git: Clone for a repository URL, in both Command Palette and unprefixed Quick Access.

## Best solution

Define an input-detection contribution contract shared by Command Palette and unprefixed Quick Access, with the built-in Git extension supplying the repository-URL example. Settle how matched input reaches the command and how detected actions coexist with ordinary results before implementation.

- **Likely files:** `src/vs/platform/quickinput/common/quickAccess.ts`, `src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts`, `src/vs/workbench/services/extensions/common/extensionsRegistry.ts`, `extensions/git/package.json`, `extensions/git/src/commands.ts`

Check nonmatching text and overlapping detectors, and verify existing file, symbol and command searches retain their behavior. Add automated coverage for matching, command arguments and contribution lifecycle under the agreed contract.
- **Behavior:**

  > Pasting a supported input into Command Palette or unprefixed Quick Access should reveal an applicable action without requiring the user to know its command name. The motivating example is a repository URL revealing Git: Clone and carrying that URL into the selected action. Detection must not execute commands before explicit acceptance. Acceptance checks should cover both entry points, nonmatching input and preservation of existing search behavior; matching and presentation semantics remain to be agreed.
- **Trace:**

  > QuickAccessRegistry in src/vs/platform/quickinput/common/quickAccess.ts chooses a single provider by literal prefix; it does not aggregate contributed detectors. CommandsQuickAccessProvider in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts builds menu-backed command picks and optionally AI-related suggestions, while AnythingQuickAccessProvider in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts builds history, file, symbol and help results. Its caller-provided additionPicks are not an extension contribution contract. The built-in git.clone command in extensions/git/src/commands.ts already accepts a URL, so the missing capability is input recognition and action discovery, not cloning itself. Preserve existing provider prefixes, ordinary searches and extension-owned quick picks; the thread establishes the two Quick Access entry points but does not settle result ranking or command-argument binding. https://github.com/microsoft/vscode/issues/242201 is a later closed empty report, not a canonical. No open implementation PR was identified in the supplied context or related-item inspection.
- **Open decisions:**
  - What static matching contract should contributors receive: literal prefixes, regular expressions, or both, and what part of the input is matched?
  - How should the matched input or captures become command arguments, and should accepting Git: Clone bypass its repository-URL prompt?
  - Where should detected actions appear relative to ordinary results, and which result should be initially selected when multiple detectors match?
