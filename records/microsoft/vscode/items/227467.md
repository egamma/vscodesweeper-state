# Issue #227467 — API to expose the shell's actual environment to extensions

[https://github.com/microsoft/vscode/issues/227467](https://github.com/microsoft/vscode/issues/227467)

## Summary

Keep this API proposal open: shell-environment reporting is implemented as a proposed API, not a finalized stable contract. Reporting also remains temporarily restricted to five environment variables.

## Change summary

Expose the integrated shell's actual environment to extensions through a supported API.

## Best solution

Have the terminal and API owners settle the reporting scope and performance contract, then finalize or explicitly abandon the terminalShellEnv proposal. Preserve this issue as the proposal tracker rather than treating the merged shell implementations as completion.

- **Implemented extension-host surface:** src/vs/workbench/api/common/extHostTerminalShellIntegration.ts routes $shellEnvChange to setEnv and exposes the resulting environment through the shell integration object's env getter. - **Remaining reporting limitation:** src/vs/platform/terminal/node/terminalEnvironment.ts:94-103 explicitly describes a temporary hardcoded scope and requests only PATH, VIRTUAL_ENV, HOME, SHELL, and PWD. https://github.com/microsoft/vscode/issues/245695 documents prompt overhead and a possible subscription-based approach; that closed mitigation issue does not finalize this proposal.
- **Merged implementation leads:** Verified merged shell-support PRs: https://github.com/microsoft/vscode/pull/237415 for PowerShell, https://github.com/microsoft/vscode/pull/237602 for Bash, and https://github.com/microsoft/vscode/pull/240971 for fish.
