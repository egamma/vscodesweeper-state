# Issue #346205 — Agent Host in Dev Containers should respect chat.tools.urls.autoApprove

[https://github.com/microsoft/vscode/issues/346205](https://github.com/microsoft/vscode/issues/346205)

## Summary

Keep open as a feature request: current source explicitly excludes Dev Container windows from URL-approval synchronization. Local synchronization does not satisfy the requested remote behavior, and the linked permission-rules PR deliberately left it unsupported.

## Change summary

Reuse VS Code User Settings URL approvals in Dev Container Agent Host sessions, including after rebuilds and subsequent settings changes.

## Best solution

Provide a maintainer-approved way to reuse personal URL approvals on container hosts without overwriting independent host permissions or weakening managed restrictions. Decide whether this is automatic or explicitly opted into before extending synchronization.

## Evidence

- **Current capability boundary:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCopilotCliSettingsContribution.ts constructs localPermissionKeys only when environmentService.remoteAuthority is absent. Those keys translate chat.tools.urls.autoApprove into WebFetch permission rules and subscribe to setting changes; remote windows receive neither behavior.
- **Explicit container exclusion:** src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostCopilotCliSettingsContribution.test.ts:357-393 contains 'does not mirror permissions or terminal default opt-outs in remote windows', explicitly covering dev-container+container and checking that permission settings changes and host restarts do not dispatch permission updates. This is source inspection, not an executed test.
- **Reporter-linked implementation:** https://github.com/microsoft/vscode/pull/345113 merged on 2026-10-30. Its description explicitly says URL and terminal approval settings synchronize to the local host at startup and on changes, while remote agent hosts do not sync; it therefore does not implement this request.
- **Remote configuration ownership:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostRootConfigForwarder.ts:55-61 documents that remote connections are intentionally excluded from forwarding and directs remote operators to agent-host-config.json. Separate host configuration is the existing alternative, not coverage of automatic User Settings reuse.
