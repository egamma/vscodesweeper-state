# Issue #195724 — Regex Find/Replace with named capture groups

[https://github.com/microsoft/vscode/issues/195724](https://github.com/microsoft/vscode/issues/195724)

## Summary

Keep this accepted, well-supported feature request open: current editor replacement code still does not resolve named capture references. The related open report is newer, and the older reports were closed without implementing the capability.

## Change summary

Support $<name> references to named regex capture groups in Find/Replace replacements.

## Best solution

Provide consistent named-capture substitution across editor Replace, both Replace All paths, and workspace Search/Replace, without requiring numbered references as a workaround. Retain this issue as the accepted request and settle compatibility semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/find/browser/replacePattern.ts`, `src/vs/editor/contrib/find/browser/findModel.ts`, `src/vs/editor/common/model/textModelSearch.ts`, `src/vs/editor/common/model.ts`, `src/vs/workbench/services/search/common/replace.ts`, `src/vs/editor/contrib/find/test/browser/replacePattern.test.ts`, `src/vs/editor/contrib/find/test/browser/findModel.test.ts`, `src/vs/workbench/services/search/test/common/replace.test.ts`
- **Validation:** Add focused tests in replacePattern.test.ts, findModel.test.ts, and search/common/replace.test.ts using the reported input, before(?<myNamedGroup>textToMatchAndCapture)after, and replacement $<myNamedGroup>; expect textToMatchAndCapture without a numbered reference. Cover single replacement, regular and large Replace All, mixed named/numbered references, escaped dollars, and the agreed unknown-name semantics. Run the three targeted unit suites in an implementation workspace; no tests were executed in this read-only review.
- **Behavior:**

  > A regex replacement can refer to a named capture using $<name>, and the reporter's example produces textToMatchAndCapture rather than literal replacement syntax. The result must not depend on adding $1 or on which replacement execution path is selected. Existing numbered references and non-regex literal replacement remain unchanged. Acceptance includes editor Replace, regular and large Replace All, and workspace Search/Replace, with explicit tests for escaped references and the agreed handling of unknown names.
- **Trace:**

  > The editor parser in src/vs/editor/contrib/find/browser/replacePattern.ts has no named-reference representation or parser branch. createFindMatch in src/vs/editor/common/model/textModelSearch.ts discards the RegExpExecArray groups property, and FindMatch in src/vs/editor/common/model.ts is the match-data contract to inspect during planning. src/vs/editor/contrib/find/browser/findModel.ts has separate single, regular Replace All, and large Replace All paths, including a native-substitution shortcut that can behave differently from the custom builder. Workspace ReplacePattern in src/vs/workbench/services/search/common/replace.ts reaches native substitution only when hasParameters is set, explaining why a numeric reference can incidentally enable named substitution there. Preserve numbered-reference, escape, case-operation, selection, and undo behavior; adding other regex dialects is outside this request. https://github.com/microsoft/vscode/issues/206413 is a newer related report, not an older canonical. The unresolved product boundary is how newly recognized named-reference syntax treats names absent from the search pattern; the thread does not settle that compatibility behavior.
- **Open decisions:**
  - When the regex contains named groups but a replacement references an undeclared name, should VS Code follow JavaScript substitution semantics and insert an empty string, or preserve the reference literally for compatibility with existing replacements?
