# Issue #288354 — Tool progress update resets loading animation

[https://github.com/microsoft/vscode/issues/288354](https://github.com/microsoft/vscode/issues/288354)

## Summary

Still present on main: when a tool progress message text is updated, `hasSameContent` returns false, causing the entire ChatProgressContentPart to be re-rendered and resetting the spinner animation. The existing `updateMessage` method could handle text-only updates without touching the spinner, but the rendering pipeline recreates the part instead. Team-authored (CONTRIBUTOR) and milestoned On Deck — keeping open.

## Change summary

Tool progress text updates cause the spinner/loading animation to restart from the first frame instead of continuing smoothly.

## Best solution

Modify `ChatProgressContentPart.hasSameContent` in `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatProgressContentPart.ts` to return `true` when only the message text changes (not the spinner state), and instead call the existing `updateMessage` method to swap the text without recreating the spinner. Alternatively, the chat list renderer diff logic could be updated to detect content-only changes and call `updateMessage` on the existing part rather than replacing it.
