# Issue #148160 — extension.extensionKind is wrong for extensions not running on the host

[https://github.com/microsoft/vscode/issues/148160](https://github.com/microsoft/vscode/issues/148160)

## Summary

The defect remains directly visible on current main: extensions obtained from another extension host are still assigned the current host's extension kind, and both affected construction sites explicitly say that value is wrong. The issue should remain open in the existing API and extension-host areas.

## Change summary

Report the correct UI or Workspace extension kind for extensions returned from a different extension host.

## Best solution

Derive the extension kind from the host associated with each returned extension rather than applying the caller's host kind universally, with coverage for local and remote callers retrieving foreign extensions.
