# Issue #148160 — extension.extensionKind is wrong for extensions not running on the host

[https://github.com/microsoft/vscode/issues/148160](https://github.com/microsoft/vscode/issues/148160)

## Summary

Still reproduces on current main — the extensionKind for extensions from a different extension host is hardcoded to the current host's kind rather than the originating host's kind, with explicit TODO comments marking the bug in-code.

## Change summary

In a remote window, `extension.extensionKind` reports `Workspace` for all extensions accessed via `allAcrossExtensionHosts`, even those running on the local (UI) host.

## Best solution

Fix the `extensionKind` parameter passed to the `Extension` constructor in `src/vs/workbench/api/common/extHost.api.impl.ts` (lines 611 and 629) so that extensions from a different extension host receive the correct kind (UI vs Workspace) based on their actual host, not the current host. The same pattern in `extHostExtensionService.ts` (line 510) may also need adjustment for the context API path.
