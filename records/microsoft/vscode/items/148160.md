# Issue #148160 — extension.extensionKind is wrong for extensions not running on the host

[https://github.com/microsoft/vscode/issues/148160](https://github.com/microsoft/vscode/issues/148160)

## Summary

Still unfixed on main — team-authored bug with explicit TODO markers in the code acknowledging the wrong extensionKind. Keeping open per hard keep-open rule (MEMBER author).

## Change summary

In a remote window, `vscode.extensions.allAcrossExtensionHosts` reports `Workspace` as the extensionKind for all extensions, even those running on the local (UI) host.

## Best solution

Fix the `extensionKind` passed to the `Extension` constructor in `extHost.api.impl.ts` for cross-host extensions: instead of reusing the current host's kind, determine each extension's actual kind (UI vs Workspace) based on which extension host it belongs to. The two call sites at lines 611 and 629 (marked `TODO@alexdima THIS IS WRONG`) need the correct kind derived from the extension's host location.
