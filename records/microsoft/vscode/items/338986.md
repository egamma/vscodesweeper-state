# Issue #338986 — Claude Agent native model picker should show the concrete model version behind aliases such as `Opus`

[https://github.com/microsoft/vscode/issues/338986](https://github.com/microsoft/vscode/issues/338986)

## Summary

Valid, well-diagnosed request: the native Claude model picker currently shows only unversioned aliases (`Opus`, `Sonnet`, …) with no indication of the concrete model they resolve to, and the suggested fix is traceable in the code.

## Change summary

Surface the concrete resolved model behind native Anthropic model aliases (e.g. `Opus` → `claude-opus-5-5`) in the picker or a hover/detail view, while keeping the alias itself.

## Best solution

Extend `fromSdkModelInfo` in src/vs/platform/agentHost/node/claude/claudeAgent.ts to read `ModelInfo.resolvedModel` (confirmed to exist on the SDK type — see claudeAgent.test.ts fixture `{ value: 'default', resolvedModel: 'claude-sonnet-4-5-20250929', ... }`) and plumb it through `IAgentModelInfo` so the chat model picker UI can render it as a subtitle/hover, mirroring how Copilot-routed Claude models already show explicit versions.

## Evidence

- **no resolved-model projection today:** fromSdkModelInfo (src/vs/platform/agentHost/node/claude/claudeAgent.ts:170-182) only maps m.value and m.displayName into IAgentModelInfo.id/name; m.resolvedModel is never read for non-default rows.
- **resolvedModel is a real SDK field:** src/vs/platform/agentHost/test/node/claudeAgent.test.ts:1742 constructs a ModelInfo fixture with resolvedModel populated, and isSdkDefaultModel's doc comment (claudeAgent.ts:151-158) already references ModelInfo.resolvedModel for the synthetic 'default' alias — confirming the field exists and is populated by the SDK, at least for aliases.
- **contract has no slot for it:** IAgentModelInfo (src/vs/platform/agentHost/common/agent.ts:901-912) has no description/subtitle field today, so surfacing this needs a small contract addition plus a UI change in the chat model picker, not just the agentHost projection.
