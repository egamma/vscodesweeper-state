# Issue #315695 — Scroll syncing gets funky with markdown file open twice

[https://github.com/microsoft/vscode/issues/315695](https://github.com/microsoft/vscode/issues/315695)

## Summary

Still present on main: the scroll sync architecture in the markdown preview uses a URI-keyed ResourceMap in TopmostLineMonitor and a BroadcastChannel in DiffScrollSyncManager, but neither accounts for the same markdown file being open in both a diff preview and a separate split editor — scroll events from the split editor propagate to both diff sides indiscriminately.

## Change summary

Scrolling a markdown source file that is open in both a preview diff and a split editor group causes only one half of the diff to scroll.

## Best solution

The scroll sync path in `TopmostLineMonitor` (which fires `onDidChanged` keyed by URI) and the preview's listener need to disambiguate which editor instance originated the scroll when the same resource is open in multiple editor groups. The `DiffScrollSyncManager`'s BroadcastChannel relay may also need to filter or scope messages to the correct preview instance. Likely files: `extensions/markdown-language-features/src/preview/topmostLineMonitor.ts`, `extensions/markdown-language-features/src/preview/preview.ts`, and `extensions/markdown-language-features/preview-src/diffScrollSync.ts`.

## Evidence

- **root cause in source:** TopmostLineMonitor (extensions/markdown-language-features/src/preview/topmostLineMonitor.ts) uses a ResourceMap<number> keyed by URI. When the same markdown file is open in multiple editors, onDidChangeTextEditorVisibleRanges fires for all of them and the throttled update fires a single onDidChanged event — the preview cannot distinguish which editor group originated the scroll.
- **BroadcastChannel scope:** DiffScrollSyncManager (extensions/markdown-language-features/preview-src/diffScrollSync.ts) uses a BroadcastChannel keyed by channelName to sync the two diff sides, but scroll events arriving from a third editor (the split source) via the preview's own scroll listener interfere with this channel.
