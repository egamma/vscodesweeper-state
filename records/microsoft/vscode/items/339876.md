# Issue #339876 — `editorGroupHeader.tabsBackground` has no effect

[https://github.com/microsoft/vscode/issues/339876](https://github.com/microsoft/vscode/issues/339876)

## Summary

Thanks for the report — this is expected layering, not a bug: `editorGroupHeader.tabsBackground` colors the title header container, but each tab element paints its own `tab.activeBackground`/`tab.inactiveBackground` on top, fully covering that area wherever a tab sits.

## Change summary

Setting `editorGroupHeader.tabsBackground` in `workbench.colorCustomizations` doesn't visibly change the tab strip color.

## Best solution

Keep current behavior: `editorGroupHeader.tabsBackground` only shows in the empty space to the right of the tabs (and in the shrink-mode fade gradient); to recolor the tabs themselves, also set `tab.activeBackground` and `tab.inactiveBackground` (and their unfocused variants).

  > Thanks for the report! This is actually expected: `editorGroupHeader.tabsBackground` colors the title header container behind the tabs, but each tab (`tab.activeBackground` / `tab.inactiveBackground`, and their unfocused variants) paints its own opaque background on top — see `src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css`. Since those default to explicit colors rather than transparent, the tabs fully cover the header background, and `editorGroupHeader.tabsBackground` is only visible in the empty strip past the last tab. To recolor the tabs themselves, add `tab.activeBackground` / `tab.inactiveBackground` (and `tab.unfocusedActiveBackground` / `tab.unfocusedInactiveBackground`) to your `workbench.colorCustomizations`. Closing as as-designed, but feel free to reopen if you're seeing something different even with those set.

## Evidence

- **each tab paints its own background on top:** src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css lines 147-159 set `.tab { background-color: var(--vscode-tab-inactiveBackground) }` and `.tab.active { background-color: var(--vscode-tab-activeBackground) }`, which fully overlay the title container background wherever a tab exists.
- **default tab colors are explicit, not transparent:** src/vs/workbench/common/theme.ts: TAB_ACTIVE_BACKGROUND defaults to editorBackground (line 32) and TAB_INACTIVE_BACKGROUND defaults to explicit hex #2D2D2D/#ECECEC (lines 36-41), so tabs opaquely cover the header background by default.
- **EDITOR_GROUP_HEADER_TABS_BACKGROUND only used elsewhere for the shrink-mode gradient:** src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts lines 2849-2862 only read EDITOR_GROUP_HEADER_TABS_BACKGROUND to compute a fade-out gradient color, confirming it's not meant to recolor the tabs themselves.
- **community-known workaround:** Public GitHub search results show users resolving this exact confusion by also setting `tab.inactiveBackground` alongside `editorGroupHeader.tabsBackground`.
