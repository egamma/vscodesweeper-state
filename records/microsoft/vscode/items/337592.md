# Issue #337592 — BYOK custom endpoints: support dynamic/refreshable API key (apiKeyHelper) for OAuth-based gateways

[https://github.com/microsoft/vscode/issues/337592](https://github.com/microsoft/vscode/issues/337592)

## Summary

Fresh, well-articulated feature request (0 days old, 2 upvotes) confirmed against source to be a genuine gap: the customendpoint BYOK provider only accepts a static apiKey/requestHeaders string with no refresh mechanism, blocking OAuth-based gateways. The two prior issues it cites were closed only by the 60-day/<20-upvote backlog auto-close, not a maintainer technical decline, so that precedent does not settle this one.

## Change summary

Add a way for BYOK custom-endpoint model configs to obtain a fresh/short-lived credential per request (e.g. an apiKeyHelper script hook or env-var interpolation) instead of only a static apiKey string.

## Best solution

A maintainer should decide the credential-refresh design (helper-script vs. env-var/secret interpolation) for CustomEndpointBYOKModelProvider before implementation, given the security implications of running a local process to mint tokens.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts`, `extensions/copilot/src/extension/byok/vscode-node/abstractLanguageModelChatProvider.ts`, `extensions/copilot/package.json`
- **Validation:** A test in customEndpointProvider.spec.ts asserting the resolved auth header reflects a freshly-resolved (not stale) credential when the configured source is dynamic.
- **Trace:**

  > CustomEndpointBYOKModelProvider.createOpenAIEndPoint() (extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts) resolves apiKey once from configuration and passes it into CustomEndpointOAIEndpoint, whose getExtraHeaders()/_interpolateApiKey() only support a static string or the literal ${apiKey} placeholder — there is no hook to re-invoke a command or read an env var at request time. Boundary: do not change the existing static-apiKey/requestHeaders behavior for the common case; any new resolution path must be additive and opt-in via new config fields.
- **Open decisions:**
  - Should dynamic credentials be sourced via a local helper command (apiKeyHelper-style, executing user-specified shell commands) or via ${env:VAR}/secret-reference interpolation resolved at request time — these differ in security surface and are not equivalent for the user?
  - If a helper command is supported, how often is it re-invoked (every request vs. cached with a TTL), and where is that interval configured?
  - Does this land as a new `apiKeyHelper` field in the customendpoint model config schema in extensions/copilot/package.json, or as an extension of the existing `apiKey`/`requestHeaders` string syntax?
