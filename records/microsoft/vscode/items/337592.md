# Issue #337592 — BYOK custom endpoints: support dynamic/refreshable API key (apiKeyHelper) for OAuth-based gateways

[https://github.com/microsoft/vscode/issues/337592](https://github.com/microsoft/vscode/issues/337592)

## Summary

Legitimate gap confirmed in source (BYOK custom-endpoint config only supports a static `apiKey` string, no dynamic/helper mechanism), and the community process just moved it to Backlog after hitting 20 upvotes — clearly not a close candidate.

## Change summary

Add support for a dynamically refreshed BYOK custom-endpoint credential (e.g. an apiKeyHelper script or ${env:VAR} resolution) to support OAuth-based gateways like Databricks AI Gateway.

## Best solution

Design an apiKeyHelper-style hook (or secret/env resolution at request time) for extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts and byokProvider.ts so the Authorization header can be refreshed per-request instead of using a static apiKey string.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/byok/common/byokProvider.ts`, `extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts`, `extensions/copilot/src/extension/byok/vscode-node/customOAIProvider.ts`
- **Validation:** A BYOK custom-endpoint test asserting the resolved Authorization header reflects a freshly-obtained token (e.g. from a mocked helper) rather than a cached static apiKey.
- **Trace:**

  > customEndpointProvider.ts and byokProvider.ts currently resolve a single static `apiKey: string` per model config and send it verbatim as the Bearer token; there is no hook to regenerate it per request. Confirmed via grep: no `apiKeyHelper` or equivalent exists in extensions/copilot.
- **Open decisions:**
  - Should credential refresh be a local-command/script hook (apiKeyHelper, spawning a process) or a `${env:VAR}`/secret-reference resolved at request time — these differ in security surface (process execution vs env exposure) and UX?
  - How often/when should the helper be invoked — every request, on a TTL, or only on 401 retry — and should the result be cached in memory only or also persisted?
