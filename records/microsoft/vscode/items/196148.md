# Issue #196148 — Aux window: allow to configure location and size of new windows opening

[https://github.com/microsoft/vscode/issues/196148](https://github.com/microsoft/vscode/issues/196148)

## Summary

A real configuration gap remains on current main. Auxiliary windows use fixed default dimensions and computed placement, while the existing main-window dimensions setting does not govern them.

## Change summary

Allow users to configure the initial size and location behavior of newly opened auxiliary windows.

## Best solution

Add an auxiliary-window setting modeled on `window.newWindowDimensions`, then apply it in `BrowserAuxiliaryWindowService.openWindow` while preserving explicit bounds supplied by internal callers.

## Evidence

- **current source:** `src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts` uses `DEFAULT_AUX_WINDOW_SIZE` (1024x768) and computes centered bounds from the active window, with a fixed 30-pixel offset only when positions coincide; it reads no user setting.
- **existing setting boundary:** `window.newWindowDimensions` is registered in `src/vs/workbench/electron-browser/desktop.contribution.ts` and consumed by `src/vs/platform/windows/electron-main/windowsStateHandler.ts` for main windows, not auxiliary windows.
- **partial behavior change:** https://github.com/microsoft/vscode/commit/42e35009a08896a514c19b23c4580cbc66e21883 added active-window-relative placement and a fixed offset, but did not reference this issue or add configurable sizing and placement.

- **maintainer direction:** https://github.com/microsoft/vscode/issues/196148#issuecomment-1773687413 supports adding a separate setting while questioning only the proposed browser-like default.
