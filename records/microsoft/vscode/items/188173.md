# Issue #188173 — Add an API to get a terminal's selection

[https://github.com/microsoft/vscode/issues/188173](https://github.com/microsoft/vscode/issues/188173)

## Summary

Keep open as an API finalization tracker: terminal selection access exists as a proposed API, but is absent from the stable API. The api-proposal label explicitly protects this issue from closure, and maintainers deferred finalization pending the broader terminal buffer design.

## Change summary

Expose a supported extension API for reading a terminal's selected text.

## Best solution

Retain this tracker until the API owners settle selection access within the terminal buffer design and finalize a durable public contract, or explicitly abandon the proposal. Existing proposed functionality is not completion of that work.

## Evidence

- **Protected proposal tracker:** https://github.com/microsoft/vscode/issues/188173 carries api-proposal; implementation as a proposed API does not satisfy finalization and cannot justify closing this tracker.
- **Existing capability and remaining gap:** Current HEAD declares readonly Terminal.selection: string | undefined in src/vscode-dts/vscode.proposed.terminalSelection.d.ts, explicitly referencing this issue. The stable Terminal interface in src/vscode-dts/vscode.d.ts has no selection property, and src/vs/platform/extensions/common/extensionsApiProposals.ts still registers terminalSelection as a proposal.
- **Implemented proposed behavior:** src/vs/workbench/api/browser/mainThreadTerminalService.ts forwards onAnyInstanceSelectionChange through $acceptTerminalSelection; src/vs/workbench/api/common/extHostTerminalService.ts stores the selection and exposes it through the Terminal.selection getter. https://github.com/microsoft/vscode/pull/188178 is merged, but the current declarations demonstrate that this delivered proposed functionality rather than stable API finalization.
- **Explicit maintainer direction:** https://github.com/microsoft/vscode/issues/188173#issuecomment-2511246147 explains that finalization was put on hold pending full buffer access to avoid committing to an API the project would later want to replace. Earlier API discussion also raised naming, coordinates, reflow, scrollback trimming, and separation of buffer and shell concerns.
- **Related design work, not a duplicate:** Verified https://github.com/microsoft/vscode/issues/207504 is open and explores broader terminal buffer access. It was created on 2024-03-12, after this issue, and is a design exploration rather than an older report of the same observable problem; it does not meet the stronger duplicate bar for this re-reviewed item.
- **Demand and workaround limitations:** https://github.com/microsoft/vscode/issues/188173#issuecomment-2451665351 and https://github.com/microsoft/vscode/issues/188173#issuecomment-2508216123 request selected-text access for extensions. A commenter suggested copying through the clipboard, but https://github.com/microsoft/vscode/issues/188173#issuecomment-2451792825 confirms that supported access remained dependent on this proposal or the buffer API work; the suggested workaround does not establish stable API coverage.
