# Issue #299496 — Right-clicking highlights the wrong word - Word highlighting given stale cursor coordinates when focus is not in the editor

[https://github.com/microsoft/vscode/issues/299496](https://github.com/microsoft/vscode/issues/299496)

## Summary

Still reproduces on main: the word highlighter uses a stale cached query when the editor loses text focus (e.g. context menu opens), so right-clicking on a different word re-highlights the previous word instead of the newly right-clicked one.

## Change summary

Right-clicking a different word in the editor highlights the previously-clicked word instead of the right-clicked word, because the word highlighter falls back to a stale cached query when focus leaves the editor.

## Best solution

In `WordHighlighter._run()`, the `!hasTextFocus` branch (line ~637) should account for cursor position changes triggered by right-click context menu — either by updating the query from the new cursor position before falling back to the cache, or by handling the `onDidChangeCursorPosition` event even when focus is lost to the context menu. The fix is localized to `src/vs/editor/contrib/wordHighlighter/browser/wordHighlighter.ts`.
