## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/watch.ts`
- **Validation:** On Windows, open a repository in VS Code with git.autorefresh enabled, create and check out a branch in GitHub Desktop using that same working directory, return focus to VS Code, and compare its branch indicator with git branch --show-current. Verify that closing VS Code completes normally; repeat with installed extensions disabled to isolate ownership.
- **Behavior:**

  > Creating and checking out a branch externally in the same working directory should be reflected in VS Code after it regains focus and refreshes repository state. The reporter instead sees the previous branch and subsequently encounters a hang when closing VS Code. Acceptance requires the displayed branch to agree with Git's actual HEAD and normal window closure after the switch.
- **Trace:**

  > DotGitWatcher in extensions/git/src/repository.ts forwards Git-directory changes through Repository.onFileChange; extensions/git/src/watch.ts supplies filesystem watcher events. Refresh is conditioned on git.autorefresh, repository size, running operations, and window focus. Repository._updateModelState reads getHEADRef() and updates _HEAD. This establishes the relevant path but does not identify a failing stage or connect it to the closing hang. Begin with reproduction and Git output diagnostics; do not assume installed Git extensions or GitHub Desktop are responsible, and preserve intentional focus and refresh settings.
