# Issue #308102 — "Go to Symbol in Workspace..." *still* strips all results if query contains a symbol

[https://github.com/microsoft/vscode/issues/308102](https://github.com/microsoft/vscode/issues/308102)

## Summary

Keep open: current workspace-symbol filtering does not accommodate the reported qualified queries, and an open PR addresses the Rust double-colon case. Review that candidate without losing the PHP backslash case or the broader provider-query requirement.

## Change summary

Allow provider-supported qualified workspace-symbol queries to retain returned results even when the query syntax does not match the symbol's display name.

## Best solution

Review https://github.com/microsoft/vscode/pull/333391 for double-colon qualification, then resolve the remaining provider-specific filtering requirement, including PHP backslash-qualified queries. Preserve normal fuzzy matching and existing space-separated symbol/container searches.

The symbol-related setting search.quickOpen.includeSymbols in src/vs/workbench/contrib/search/browser/search.contribution.ts controls inclusion in file Quick Open, not this filtering behavior.
