# Issue #243122 — Bug: Arabic search fails to find words without diacritics (Tashkeel)

[https://github.com/microsoft/vscode/issues/243122](https://github.com/microsoft/vscode/issues/243122)

## Summary

Diacritic-insensitive text matching remains a missing capability, rather than a failure of the existing literal-search contract. Keep this open as a feature request; neither Quick Access matching nor the existing RTL reports covers the requested behavior.

## Change summary

Allow an Arabic query without Tashkeel to match file text containing those diacritics.

## Best solution

Define an optional diacritic-insensitive text-search mode while preserving existing exact matching and correct match ranges. Distinguish editor Find from workspace search when assessing implementation feasibility, since their matching engines differ.

## Evidence

- **Existing capability check:** src/vs/editor/common/model/textModelSearch.ts: SearchParams.parseSearchRequest supports regular expressions, case sensitivity, and word boundaries, but no diacritic-insensitive option. Its simple-search path uses text.indexOf(searchString), which cannot match كتاب across the intervening combining marks in كِتَابٌ.
- **Reported path is editor Find:** src/vs/editor/contrib/find/browser/findModel.ts: _findMatches delegates to the editor text model's findMatches with the query, regex, case, and whole-word options. The reported Ctrl+F scenario therefore does not depend on ripgrep; workspace text search is a separate implementation concern.
- **Maintainer discussion:** https://github.com/microsoft/vscode/issues/243122#issuecomment-3678780548 distinguishes working diacritic handling in Quick Access from text search and notes a ripgrep limitation. Quick Access searches a different surface and does not satisfy matching within file contents.
