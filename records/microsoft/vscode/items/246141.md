# Issue #246141 — Could `vscode.executeFormatDocumentProvider` and friends stop after the first provider?

[https://github.com/microsoft/vscode/issues/246141](https://github.com/microsoft/vscode/issues/246141)

## Summary

Valid request — the `vscode.executeFormatDocumentProvider` and `vscode.executeFormatRangeProvider` commands still use the `UntilResult` iteration (trying all providers until a non-empty result), while the internal notebook formatting already uses `getDocumentFormattingEditsWithSelectedProvider` that stops after one. The inconsistency is confirmed on current main and the discussion is ongoing with a maintainer question pending.

## Change summary

Change `vscode.executeFormatDocumentProvider` and `vscode.executeFormatRangeProvider` to stop after the first provider rather than iterating through all providers until a non-empty result is found.

## Best solution

Either change the `_executeFormatDocumentProvider` / `_executeFormatRangeProvider` commands to use the selected-provider variant (like notebook formatting already does), or add an option parameter to these commands that lets callers opt into first-provider-wins behavior. The maintainer's question about Quarto's notebook usage should be answered first to clarify whether the existing notebook formatting path already covers this caller's needs.
