# Issue #246141 — Could `vscode.executeFormatDocumentProvider` and friends stop after the first provider?

[https://github.com/microsoft/vscode/issues/246141](https://github.com/microsoft/vscode/issues/246141)

## Summary

The extension-facing formatting gap remains on current main: document and range formatting commands still advance to another provider after an empty result. The notebook fix does not cover these commands, and no verified open canonical issue was found.

## Change summary

Let extensions request document and range formatting without invoking another formatter when the first provider returns no edits.

## Best solution

Provide an extension-facing way to obtain edits from a single formatter, including an empty result, without applying them. An API-owner decision should settle whether this changes the existing commands or uses an opt-in option or companion command, and whether selection follows provider order or the configured default formatter.
