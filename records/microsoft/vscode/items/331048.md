# Issue #331048 — Unresolved variable triggers unwanted auto-rename

[https://github.com/microsoft/vscode/issues/331048](https://github.com/microsoft/vscode/issues/331048)

## Summary

This matches the documented `editor.acceptSuggestionOnCommitCharacter` behavior (default true): the semicolon is a commit character for JS/TS suggestions, so typing `;` right after an unresolved `field` accepts the highlighted `Field` completion — the reporter confirmed no Enter was pressed, which is consistent with a commit-character accept, not an unexplained auto-rename.

## Change summary

Typing `;` after an unresolved identifier (`field`) causes VS Code to replace it with a similarly-named import (`Field`), which the reporter did not intend.

## Best solution

Point the reporter at `editor.acceptSuggestionOnCommitCharacter` (src/vs/editor/common/config/editorOptions.ts) which they can disable to stop `;` from auto-accepting suggestions; optionally note this as feedback to the TS language service for ranking/filtering completions for already-referenced-but-unresolved names, but the current commit-character behavior itself is intentional and configurable.

  > Thanks for the detailed repro. This looks like the documented commit-character behavior: `editor.acceptSuggestionOnCommitCharacter` (on by default) treats `;` as a commit character in JS/TS, so when `Field` is the highlighted suggestion for your unresolved `field`, typing `;` accepts it — the same mechanism that would apply if you pressed Enter or Tab. You can disable that setting, or press Escape to dismiss the suggestion widget before typing `;`, to avoid this. If you think the TS language service shouldn't be offering `Field` as a completion for an already-referenced (if unresolved) `field` in the first place, that would be a separate, narrower ask worth filing against the TS suggestion ranking.
