# Issue #331048 — Unresolved variable triggers unwanted auto-rename

[https://github.com/microsoft/vscode/issues/331048](https://github.com/microsoft/vscode/issues/331048)

## Summary

This isn't a rename feature at all — it's the suggest widget accepting a highlighted completion when the semicolon commit character is typed, which is documented, intentional, and user-configurable behavior.

## Change summary

After typing a semicolon following an unresolved variable reference, VS Code replaces it with a similarly-named imported identifier as if 'auto-renaming' it.

## Best solution

Point the reporter at `editor.acceptSuggestionOnCommitCharacter` (default true) — semicolon is a commit character in JS/TS that accepts whatever suggestion is currently highlighted in the widget; disabling it, or adjusting `editor.suggestSelection`, stops the unwanted substitution. No code defect to fix.

  > Thanks for the detailed repro. This isn't an auto-rename feature — it's the suggest widget accepting a highlighted completion when you type a commit character. In JavaScript/TypeScript, `;` is one of those commit characters, and since `field` was unresolved, the language service was likely showing `Field` (the import) as the top suggestion; typing `;` accepted it instead of just inserting the semicolon.
  > 
  > You can turn this off (or make it less eager) via the `editor.acceptSuggestionOnCommitCharacter` setting, and/or tune `editor.suggestSelection` so an unrelated fuzzy match isn't pre-selected. Closing as as-designed, but please reopen if you find a case where this happens with the suggest widget clearly not visible.
