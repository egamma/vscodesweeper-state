# Issue #332493 — Feature Request: Expose settings.json configuration for integrated browser proxy

[https://github.com/microsoft/vscode/issues/332493](https://github.com/microsoft/vscode/issues/332493)

## Summary

Valid, well-diagnosed feature request: the integrated browser's local (non-remote) sessions are always set to `direct` mode and never pick up a configurable proxy, so `http.proxy` has no effect there — a contributor has already traced the code and volunteered to implement it, so this should stay open and route to the browser-integration area for a settings-design decision.

## Change summary

Add a settings.json option to configure a dedicated proxy (e.g. for local tools like Whistle) for VS Code's integrated browser, since it currently only uses the OS-level system proxy or the remote tunnel proxy.

## Best solution

Decide the settings design (a dedicated `workbench.browser.proxy` vs. reusing `http.proxy` behind an opt-in toggle, as flagged in the comment) and extend `BrowserSessionRemote`/`electron-main/browserSession.ts` (currently only setting `mode: 'direct'` or the tunnel proxy in `browserSessionRemote.ts`) to apply a locally configured proxy via `session.setProxy()`.
