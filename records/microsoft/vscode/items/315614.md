# Issue #315614 — WSL: Server download fails with "aborted" error, causing binary not found on startup

[https://github.com/microsoft/vscode/issues/315614](https://github.com/microsoft/vscode/issues/315614)

## Summary

The logs substantiate a WSL extension failure: after the client-side server download is aborted, startup proceeds without a server binary. This belongs with the VS Code-owned Remote Development family and should be transferred to microsoft/vscode-remote-release rather than closed as extension-caused.

## Change summary

Recover correctly when downloading the matching VS Code Server for WSL is aborted instead of attempting to launch a missing binary.

## Best solution

The WSL extension should ensure its fallback download completes and the server binary exists before launching, with an explicit retry or actionable failure when neither download path succeeds. The Remote Development maintainers should investigate this in microsoft/vscode-remote-release alongside the related download-failure reports.
