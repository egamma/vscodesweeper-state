[https://github.com/microsoft/vscode/issues/315614](https://github.com/microsoft/vscode/issues/315614)

## Summary

The logs confirm a Remote - WSL server-installation failure: after the client-side download aborts, startup proceeds without a server binary. Remote - WSL is VS Code-team-owned, so this should remain open and be moved to its owning tracker rather than closed as extension-caused.

## Change summary

Ensure a failed VS Code Server download does not proceed directly to startup with a missing binary when connecting to WSL.

## Best solution

In the Remote - WSL installation flow, complete or retry the WSL-side fallback before launching the server, and surface a recoverable download error when neither download path succeeds.
