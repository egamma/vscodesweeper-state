# Issue #333514 — Can't focus on output view in Agents Window while in automations view

[https://github.com/microsoft/vscode/issues/333514](https://github.com/microsoft/vscode/issues/333514)

## Summary

Keep open for a product decision: current source intentionally hides the Panel while Automations is active, but the globally registered Output command remains available and silently fails to reveal it. This team-authored issue cannot receive a judgment-based *as-designed close, and the discussion has not settled whether to support the command or hide it.

## Change summary

Prevent the Output focus command from appearing to do nothing when the Automations custom view is active in the Agents Window.

## Best solution

Make the interaction internally consistent: either invoking the Output command must transition away from Automations and reveal/focus Output, or the command must be unavailable while that full-surface view suppresses the Panel. A maintainer should choose the intended observable behavior before implementation.

- **Behavior:**

  > In the Agents Window with the Automations view active, the Output focus command must not remain available and then silently do nothing. Depending on the maintainer's decision, it must either be unavailable in that state or transition to a visible, focused Output view. The chosen behavior must work from both the Command Palette and the command's keybinding, without disturbing ordinary Output behavior outside the Automations custom view.
- **Trace:**

  > The shared Output action is registered as `workbench.action.output.toggleOutput` with `WindowEnablement.Both` in src/vs/workbench/contrib/output/browser/output.contribution.ts, and src/vs/sessions/sessions.common.main.ts loads that contribution in the Agents Window. Automations is registered as a full-surface custom view in src/vs/sessions/contrib/sessions/browser/views/automationsView.ts. In src/vs/sessions/browser/workbench.ts, `_effectiveVisible` makes the Sessions, Editor, Auxiliary Bar, and Panel parts invisible while a custom view is active; src/vs/sessions/test/browser/workbench.test.ts explicitly verifies that contract. The uncertainty begins at the product boundary: whether Output should dismiss/replace Automations or be unavailable there. Preserve normal Output behavior in standard windows and elsewhere in the Agents Window.
- **Open decisions:**
  - While Automations is active, should invoking Output dismiss or replace the custom view and reveal the Panel, or should the Output command and keybinding be unavailable until the user leaves Automations?
