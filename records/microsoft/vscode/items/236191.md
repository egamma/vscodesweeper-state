# Issue #236191 — Overtype Mode: backspace should insert spaces in its stead

[https://github.com/microsoft/vscode/issues/236191](https://github.com/microsoft/vscode/issues/236191)

## Summary

The requested behavior is still missing: regular Backspace deletes text without replacement even in overtype mode. Keep this team-authored request open; the original implementation discussion explicitly accepted the direction, and no verified canonical owns the same work.

## Change summary

Make Backspace in overtype mode replace erased text with whitespace while moving left, preserving the alignment of subsequent text.

## Best solution

Provide alignment-preserving Backspace behavior in the editor's overtype input path, retaining insert-mode behavior. Settle line-boundary and indentation semantics before implementation; exposing the mode for custom keybindings alone would not deliver the requested behavior.

Retain existing insert-mode deletion tests.
- **Behavior:**

  > In overtype mode, regular Backspace should erase text to the left by leaving whitespace in its place, rather than shifting the remaining text left. For ordinary single-character text, ab|cd should become a |cd, with the cursor moved left and cd retaining its columns. Insert-mode Backspace must remain unchanged. Acceptance should cover undo/redo and multiple cursors, with line-start and indentation behavior agreed during planning.
- **Trace:**

  > Backspace is registered as deleteLeft in src/vs/editor/browser/coreCommands.ts and delegates to DeleteOperations.deleteLeft in src/vs/editor/common/cursor/cursorDeleteOperations.ts. The ordinary path replaces the computed deletion range with an empty string; no input-mode distinction exists there. Its range calculation also handles indentation tab stops and can cross a newline, while auto-closing pairs take a separate deletion branch. The Overtype Mode suite already exists in src/vs/editor/test/browser/controller/cursor.test.ts. The discussion on https://github.com/microsoft/vscode/pull/233188 establishes maintainer support for destructive-left-arrow behavior, but does not settle line-boundary and indentation semantics. Keep typing, paste, Delete-right, and insert-mode behavior outside this change; https://github.com/microsoft/vscode/issues/236218 is related state-exposure work, not a duplicate.
- **Open decisions:**
  - At the beginning of a line in overtype mode, should Backspace preserve the newline and stop, or retain the existing line-joining behavior?
  - Within leading indentation, should overtype Backspace erase one visual column or preserve the existing indentation-tab-stop-sized movement?
