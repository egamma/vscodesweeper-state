# Issue #283655 — view/item/context command argument is undefined if treeview is in the middle of a refresh

[https://github.com/microsoft/vscode/issues/283655](https://github.com/microsoft/vscode/issues/283655)

## Summary

Confirmed race condition: during a full tree refresh, `_addAllToClear()` synchronously clears the `_elements` handle map before the async `getChildren` completes, so any inline action clicked in that window passes `undefined` to the command handler. Still present on current main.

## Change summary

Inline `view/item/context` command argument is `undefined` when the tree view is mid-refresh because the element-handle map is cleared before the refresh finishes.

## Best solution

Keep a snapshot of the old `_elements` map (or defer clearing it) until the refresh completes, so that `getExtensionElement()` can still resolve handles for items visible in the DOM during the async gap. The fix is localized to `_addAllToClear()` / `_addChildrenToClear()` in `src/vs/workbench/api/common/extHostTreeViews.ts`.
