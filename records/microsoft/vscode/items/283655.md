## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/153982 is OPEN, was created on 2022-07-02, and explicitly reports a view/item/context command sometimes receiving no TreeItem during refresh. It covers this report's full symptom plus related missing expand/collapse events, satisfying the stronger duplicate bar for a re-reviewed item.
- **Maintainer-confirmed diagnosis:** https://github.com/microsoft/vscode/issues/153982#issuecomment-1173644832 confirms that tree state is removed before the refreshed tree finishes rendering.
- **Current source confirms missing argument:** In src/vs/workbench/api/common/extHostTreeViews.ts, _refresh calls _addChildrenToClear before requesting the main-thread refresh; _addAllToClear clears _elements. _fetchChildrenNodes awaits the provider before registering replacement elements. During that interval, _convertArgument resolves the clicked handle through getExtensionElement, which returns _elements.get(handle), yielding undefined.
- **Visible action still dispatches its handle:** src/vs/workbench/browser/parts/views/treeView.ts assigns inline action context as {$treeViewId, $treeItemHandle}; MultipleSelectionActionRunner.runAction forwards that context. doRefresh awaits tree.updateChildren, while src/vs/workbench/api/common/extHostCommands.ts processes the contributed command arguments through the tree argument converter.
- **Focused reproduction to preserve:** https://github.com/bmingles/vscode-treeview-bug supplies a provider whose getChildren waits three seconds and whose window-focus listener fires a root refresh. Clicking an inline action during that delay exposes the same missing-element interval; this report observed it on VS Code 1.107.0 and macOS 15.6.1. The reproduction source was inspected without executing it.
- **Extension PR is a workaround, not a core fix:** https://github.com/deephaven/vscode-deephaven/pull/270 is merged, but its description explicitly says command handlers ignore undefined arguments so users can click again. It does not resolve the VS Code argument-conversion defect.
- **Related race is distinct:** https://github.com/microsoft/vscode/issues/192055 is open but concerns reveal/getChildren races producing already-registered-element errors, not this report's missing inline command argument. It is not the duplicate target.
