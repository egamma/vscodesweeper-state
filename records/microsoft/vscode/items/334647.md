# Issue #334647 — Chat carousel: Title links should have underline in high-contrast themes

[https://github.com/microsoft/vscode/issues/334647](https://github.com/microsoft/vscode/issues/334647)

## Summary

Contributor testing feedback (screenshots) on the new chat/question carousel: title-area markdown links don't get the underline that high-contrast themes normally force on links, while body links do. Real, narrow accessibility/contrast gap in a just-landed feature — worth routing to the chat/accessibility owners rather than closing.

## Change summary

In high-contrast themes, links rendered in the question-carousel card title lack the underline that body markdown links have.

## Best solution

Trace why the carousel title's rendered link isn't picked up by the existing HC underline rule (`.monaco-workbench.hc-black p > a` / `.monaco-workbench.hc-light p > a` in src/vs/workbench/browser/media/style.css) even though the title goes through the same `getChatMarkdownRenderOptions()` markdown pipeline as body content (src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts), then add the matching underline rule scoped to `.chat-question-title`/`.chat-card-title` in chatQuestionCarousel.css or chatCard.css so HC contrast is consistent between title and body links.

## Evidence

- **existing HC underline rule:** src/vs/workbench/browser/media/style.css:129-132 forces `text-decoration: underline` only for `.monaco-workbench.hc-black p > a` / `.monaco-workbench.hc-light p > a`; this is what makes body chat links underlined in HC themes.
- **body link styling:** src/vs/workbench/contrib/chat/browser/widget/media/chat.css:711-733 sets color for `.rendered-markdown a` in the message body but relies on the global `p > a` rule above for the underline.
- **title rendering path:** The carousel title in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts:803-817 renders via the same `getChatMarkdownRenderOptions()`/markdownRendererService pipeline as body content, so the discrepancy likely comes from card-specific CSS (chatQuestionCarousel.css:89-95, chatCard.css `.chat-card-title`) not carrying an explicit HC underline override, or the title link not landing as a direct `<p> > a` child the same way body links do.
