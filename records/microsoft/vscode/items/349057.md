## Evidence

- **Source-confirmed reload defect:** src/vs/workbench/contrib/debug/browser/disassemblyView.ts:635-673: reloadDisassembly calls clear(), which empties _referenceToMemoryAddress, then reloads instructions using the current instruction reference. For the reported transition from 0x180001950 to 0x180001954, this does not restore the breakpoint's original reference.
- **Breakpoint omitted during drawing:** src/vs/workbench/contrib/debug/browser/disassemblyView.ts:545-567: loadDisassembledInstructions derives each breakpoint address from _referenceToMemoryAddress.get(p.instructionReference), returning undefined when the original reference is absent. Consequently, the returned instruction at 0x180001954 retains isBreakpointSet: false despite the breakpoint remaining in the model.
- **Related update paths:** src/vs/workbench/contrib/debug/browser/disassemblyView.ts:304-349: added, removed, and changed breakpoint handlers use getIndexFromReferenceAndOffset; primeMemoryReference runs inside the breakpoint-change listener rather than reloadDisassembly. These paths support the reporter's cache-dependency diagnosis.
