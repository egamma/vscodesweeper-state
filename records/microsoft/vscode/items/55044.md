# Issue #55044 — Allow syntax colouring in parameters for SignatureHelp

[https://github.com/microsoft/vscode/issues/55044](https://github.com/microsoft/vscode/issues/55044)

## Summary

Keep open: current signature help still renders signature labels without syntax coloring. Active-parameter highlighting does not cover the request, and this Backlog item has 71 upvotes and already serves as the canonical report for this capability.

## Change summary

Support language-aware syntax coloring of function signatures and parameter types in the SignatureHelp popup.

## Best solution

Provide theme-consistent syntax coloring in the parameter-hints signature line while preserving readable active-parameter emphasis, plain-text fallback, and existing documentation behavior. Settle how the signature's language is determined and how active emphasis interacts with token colors before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/parameterHints/browser/parameterHintsWidget.ts`, `src/vs/editor/contrib/parameterHints/browser/parameterHints.css`, `src/vs/editor/common/languages.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** Add a browser-level signature-help rendering test using a deterministic tokenizer and a provider-supplied signature with parameter offsets: verify distinct syntax-token styling, exact label text, and correct active-parameter emphasis across parameter changes and overload navigation. Manually check TypeScript and Dart signatures in light, dark, and high-contrast themes, including plain-text fallback and unchanged documentation and screen-reader announcements.
- **Behavior:**

  > The signature line in parameter hints should distinguish language tokens, including parameter types, using the editor theme rather than rendering the entire label in one foreground color. The active parameter must remain identifiable without obscuring syntax distinctions. Signature text, parameter ranges, overload navigation, documentation, and accessibility announcements must retain their existing meaning. Acceptance includes representative TypeScript and Dart signatures, signatures without parameters, and a readable fallback when language tokenization is unavailable.
- **Trace:**

  > ParameterHintsWidget.render and renderParameters in src/vs/editor/contrib/parameterHints/browser/parameterHintsWidget.ts render SignatureInformation.label as plain text; markdown rendering is confined to documentation. The active parameter is a substring span selected by getParameterLabelOffsets, and parameterHints.css currently overrides that whole span's foreground with editorHoverWidget.highlightForeground. Both src/vs/editor/common/languages.ts and src/vscode-dts/vscode.d.ts carry string labels without explicit signature-language metadata, so language selection is not settled by the existing contract. Preserve label offsets, overload selection, documentation rendering, and announcement behavior; parameter reformatting is outside this request. https://github.com/microsoft/vscode/issues/92297#issuecomment-597289955 records the tension between active-item coloring and syntax coloring, while https://github.com/microsoft/vscode/issues/105286#issuecomment-679100530 establishes this issue as the canonical request. The uncertainty starts at the language-selection contract and the visual precedence of active emphasis over syntax colors, not at whether current rendering already supports the feature.
- **Open decisions:**
  - Should signature coloring infer the document language, or should providers be able to specify a signature language when it differs from the document?
  - Should the active parameter preserve its syntax-token foregrounds with separate emphasis, or should the existing active-parameter foreground override those colors?
