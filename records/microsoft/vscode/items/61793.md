# Issue #61793 — MSIX installer

[https://github.com/microsoft/vscode/issues/61793](https://github.com/microsoft/vscode/issues/61793)

## Summary

The requested MSIX installer remains a real gap: current main creates only a sparse AppX package for package identity while the application is still installed by Inno Setup. This team-authored, Backlog-accepted request has 81 upvotes and no verified factual close, so it must remain open.

## Change summary

Provide an official MSIX installer for the Windows desktop build, enabling packaged installation, clean removal, and package-managed updates.

## Best solution

Offer a signed MSIX as an additional official Windows distribution format while preserving VS Code's desktop capabilities, extension model, command-line integration, and existing installer choices. The installer pipeline should validate installation, launch, update, and complete removal on supported Windows versions.

## Plan brief

- **Likely files:** `build/azure-pipelines/win32/steps/product-build-win32-compile.yml`, `build/gulpfile.vscode.ts`, `build/win32/code.iss`, `resources/win32/appx/AppxManifest.xml`
- **Validation:** On a clean supported Windows VM, install a signed MSIX without the EXE installer; verify VS Code launches, CLI and extension workflows function, an upgrade preserves user data, and uninstall removes the application and package registration without affecting user data.
- **Behavior:**

  > Windows users can obtain an official signed MSIX that installs the complete VS Code desktop application rather than only registering package identity. The packaged build retains normal desktop behavior, including launching projects, command-line integration, extensions, terminals, and updates. Installing, upgrading, and uninstalling through the package lifecycle must leave application state and system registrations consistent, while the existing Windows distribution choices remain available.
- **Trace:**

  > Current main generates resources/win32/appx/AppxManifest.xml through build/gulpfile.vscode.ts, and build/azure-pipelines/win32/steps/product-build-win32-compile.yml packages only that manifest. build/win32/code.iss installs the actual application with Inno Setup and invokes Add-AppxPackage with -ExternalLocation, confirming that the AppX supplies sparse package identity rather than owning the application payload. Commit f5e06c148d8ffd4da18f37179d2be30348575124 and https://github.com/microsoft/vscode/pull/257741 expanded this identity path for permissions but did not implement an MSIX installer. Preserve the existing desktop capability, extension, CLI, terminal, and user-data contracts; do not treat the sparse identity package or Store publication alone as satisfying the request. The unresolved complexity begins at full-payload packaging, signing, update-channel integration, and compatibility validation across Windows installation modes.

## Evidence
