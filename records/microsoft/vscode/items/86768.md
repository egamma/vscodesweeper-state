# Issue #86768 — Make css auto completion items overtype on semicolon

[https://github.com/microsoft/vscode/issues/86768](https://github.com/microsoft/vscode/issues/86768)

## Summary

The requested semicolon overtyping remains unsupported by the current CSS configuration and editor overtype logic. Keep this accepted Backlog request open: the matching open report is newer, and the older Emmet report is closed and does not establish that CSS property completions satisfy this request.

## Change summary

Allow typing a semicolon immediately before a completion-inserted CSS semicolon to advance past it without inserting a second semicolon.

## Best solution

Support semicolon overtyping for CSS property completions while preserving normal semicolon insertion elsewhere and existing bracket/quote behavior. Retain this older request as the tracking item and consider consolidating the newer matching report into it.

## Plan brief

- **Likely files:** `extensions/css-language-features/server/src/cssServer.ts`, `extensions/css/language-configuration.json`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** In a CSS rule, accept a property completion that inserts a trailing semicolon, enter its value, and type ';' immediately before that terminator: the text must retain exactly one semicolon and the caret must advance past it. Check ordinary semicolon insertion, quoted CSS strings, and existing bracket/quote overtyping for unchanged behavior.
- **Behavior:**

  > CSS property completion inserts a trailing semicolon, but typing ';' immediately before that terminator does not currently advance past it. The requested behavior is to retain one semicolon and move the caret after it, allowing continued typing. Acceptance should cover property completion followed by value entry and semicolon typing, with ordinary insertion and bracket/quote overtyping preserved.
- **Trace:**

  > The CSS language server delegates completions to getLanguageService(document).doComplete2 in extensions/css-language-features/server/src/cssServer.ts, using completion settings that include completePropertyWithSemicolon. The editor's isAutoClosingOvertype in src/vs/editor/common/cursor/cursorTypeEditOperations.ts first requires a registered single-character closing pair; extensions/css/language-configuration.json contains no semicolon pair. editor.autoClosingOvertype in src/vs/editor/common/config/editorOptions.ts explicitly covers quotes and brackets, so changing that setting does not supply this capability. The unresolved boundary is how completion-inserted terminators should participate in overtyping without changing ordinary CSS semicolon typing or other languages. The matching newer report is https://github.com/microsoft/vscode/issues/224977; the closed Emmet-specific report https://github.com/microsoft/vscode/issues/60117 discusses tabstop navigation rather than demonstrating this requested behavior.
- **Open decisions:**
  - Should semicolon overtyping apply only to terminators inserted by CSS property completion, or also to pre-existing CSS declaration terminators?

## Evidence

- **Existing capability check:** extensions/css-language-features/package.json:56–60 registers css.completion.completePropertyWithSemicolon, defaulting to true. Turning it off avoids automatic insertion but does not deliver the requested overtyping behavior.
- **Current overtype boundary:** src/vs/editor/common/config/editorOptions.ts:6131–6142 defines editor.autoClosingOvertype for closing quotes and brackets.
