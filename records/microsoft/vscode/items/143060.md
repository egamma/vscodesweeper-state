# Issue #143060 — Symlink loops cause 100% CPU

[https://github.com/microsoft/vscode/issues/143060](https://github.com/microsoft/vscode/issues/143060)

## Summary

The accepted Backlog bug remains present on current main: recursive Explorer resolution follows directory symlinks without tracking resolved targets, so a single-child symlink cycle can recurse indefinitely and consume CPU.

## Change summary

Prevent cyclic directory symlinks from causing unbounded file-tree traversal and sustained CPU usage.

## Best solution

Make recursive file-stat resolution cycle-safe while preserving ordinary symlink visibility and non-cyclic directory traversal in the Explorer.

  > Resolving or displaying a directory tree containing a symlink cycle must terminate promptly instead of repeatedly traversing the cycle and consuming CPU. - **Trace:**

  > ExplorerItem.fetchChildren in src/vs/workbench/contrib/files/common/explorerModel.ts requests resolveSingleChildDescendants. DiskFileSystemProvider.readdir in src/vs/platform/files/node/diskFileSystemProvider.ts resolves a directory symlink's target type, so an ancestor link is recursively treated as another directory under a longer lexical path. Existing tests cover only an acyclic single-child chain.
