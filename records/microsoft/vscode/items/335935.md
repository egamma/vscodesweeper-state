[https://github.com/microsoft/vscode/issues/335935](https://github.com/microsoft/vscode/issues/335935)

## Summary

The reported running-instance authentication failure needs current-build confirmation and callback-routing diagnostics. Source inspection does not establish the failure, and no verified duplicate or fixing commit supports closing it.

## Change summary

GitHub sign-in returns to the browser instead of completing in an already-running VS Code instance on Debian GNOME Wayland, while launching VS Code through the callback succeeds.

## Best solution

GitHub authentication callbacks should reach the initiating VS Code window whether the application is already running or launched by the protocol handler. First establish whether the failing handoff occurs in Linux protocol registration, forwarding to the running instance, or authentication callback handling.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/335935 describes Chrome reopening the same tab after selecting the GitHub identity while VS Code 1.137.0 is running on Debian GNOME Wayland. Closing VS Code and invoking the callback again reportedly succeeds; there are no comments independently confirming reproduction.
- **Running-instance source path:** resources/linux/code-url-handler.desktop invokes the executable with --open-url %U. In src/vs/platform/launch/electron-main/launchMainService.ts, LaunchMainService.start parses forwarded protocol URLs and calls urlService.open even when a window already exists. src/vs/platform/url/common/urlIpc.ts routes callbacks containing windowId to a matching renderer connection. These paths support the intended behavior but do not conclusively explain the reported browser loop.
- **Built-in authentication ownership:** extensions/github-authentication/src/githubServer.ts constructs the did-authenticate callback through vscode.env.asExternalUri, and extensions/github-authentication/src/extension.ts registers its URI handler. This is built-in VS Code authentication, not evidence of a third-party extension defect.
