# Issue #335935 — Continue with GIthub URL Handler doesn't work when VSCode is already opened

[https://github.com/microsoft/vscode/issues/335935](https://github.com/microsoft/vscode/issues/335935)

## Summary

Traced a real gap in the second-instance/open-url path: when a protocol URL (e.g. the GitHub auth callback) arrives while VS Code is already running, only macOS explicitly asks Electron to steal focus — Windows/Linux get no equivalent window-focus call, so the existing window is never brought forward.

## Change summary

On Linux (and likely Windows), completing GitHub sign-in via the browser-based `vscode://` callback doesn't bring the already-open VS Code window to the foreground; the browser just reopens the same tab.

## Best solution

In LaunchMainService.start() (src/vs/platform/launch/electron-main/launchMainService.ts), extend the focus-on-open-url handling beyond the `isMacintosh` branch so an existing window is focused (e.g. via ICodeWindow.focus({ mode: FocusMode.Force })) when urlsToOpen.length > 0, mirroring what the normal window-open path already achieves; note Wayland's focus-stealing prevention may still limit how far this goes.

I traced the second-instance/open-url handling in `LaunchMainService.start()` — when a `vscode://` URL (like the GitHub auth callback) arrives while a window is already open, only macOS explicitly asks Electron to steal focus (`app.focus({ steal: true })`); there's no equivalent call for Windows/Linux, so the running window is never brought to the foreground. ## Evidence

- **mac-only focus:** src/vs/platform/launch/electron-main/launchMainService.ts:62-64 only calls `app.focus({ steal: true })` when `isMacintosh`; there is no equivalent window/app focus call for other platforms.
- **no focus in url branch:** In the same file's `start()`, when `urlsToOpen.length` is truthy and `windowsMainService.getWindowCount() !== 0`, no window is created and no `window.focus(...)` is invoked before `urlService.open(uri, ...)` — the existing window is never explicitly activated.
- **focus API exists:** src/vs/platform/windows/electron-main/windowImpl.ts:410-426 defines `focus({ mode: FocusMode })` including `FocusMode.Force` (which itself gates the `steal:true` electron call behind `isMacintosh`), suggesting the missing piece is simply invoking window focus in the url-open branch for non-mac platforms too.
