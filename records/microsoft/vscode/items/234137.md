# Issue #234137 — Calling openNotebookDocument with hidden notebook URI creates another untitled*.ipynb with same URI

[https://github.com/microsoft/vscode/issues/234137](https://github.com/microsoft/vscode/issues/234137)

## Summary

Team-authored bug still appears unfixed on main — no commit references this issue, and the related fix (d6f552a8879) addresses a different scenario (new untitled URI generation collisions, not re-opening an existing hidden notebook URI). Keeping open.

## Change summary

Calling `workspace.openNotebookDocument()` with an existing hidden untitled notebook URI creates a duplicate notebook instance instead of returning the existing one.

## Best solution

The resolve path in `notebookEditorModelResolverServiceImpl.ts` needs to properly handle the case where an untitled notebook model exists but its editor is hidden — likely the `ReferenceCollection` loses track of the model when it's not visible, causing `acquire` to create a new instance. The fix should ensure the reference collection or notebook service retains knowledge of hidden untitled notebooks.
