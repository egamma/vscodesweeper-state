# Issue #335780 — Fireworks agent requests fail on unsupported CoT metadata

[https://github.com/microsoft/vscode/issues/335780](https://github.com/microsoft/vscode/issues/335780)

## Summary

Traced in source: OpenAIEndpoint.getCompletionsCallback unconditionally stamps cot_id/cot_summary (and reasoning_content/reasoning when thinking is supported) onto every BYOK Chat Completions message, with no way to omit them for providers with strict schema validation like Fireworks — this matches the reported 400 'Extra inputs are not permitted' error.

## Change summary

BYOK requests to Fireworks fail because the client always forwards CAPI-specific cot_id/cot_summary reasoning metadata fields, which Fireworks' strict schema validation rejects.

## Best solution

In extensions/copilot/src/extension/byok/node/openAIEndpoint.ts, make emission of cot_id/cot_summary conditional (e.g. only for CAPI/Azure-compatible targets, or drop them when a provider is known to reject unknown fields) instead of always emitting them for every BYOK Chat Completions endpoint; the separate 400→502 surfacing/retry behavior for BYOK errors is also worth revisiting.
