# Issue #321439 — No Agent Debug logs for Agent host sessions

[https://github.com/microsoft/vscode/issues/321439](https://github.com/microsoft/vscode/issues/321439)

## Summary

Keep open: current main has partial Copilot CLI debug-log support, but it still assumes matching host/SDK session IDs and excludes other agent-host providers. The related reports are newer and narrower, so neither supersedes this team-authored issue.

## Change summary

Preserve Agent Debug Logs visibility into model, tool, cache, and usage activity for chat sessions running through the agent host.

## Best solution

Acceptance includes starting Copilot and Claude agent-host conversations, generating model/tool activity, and opening Agent Debug Logs with logging enabled: the corresponding session events must appear rather than only discovery rows. Existing disabled-logging behavior must remain unchanged.
- **Behavior:**

  > Agent-host conversations must retain the useful Agent Debug Logs visibility available for ordinary chat sessions. With logging enabled, opening a session's logs should show that conversation's model and tool activity and available usage/cache information, even when its logical session ID differs from its provider's backing ID. Coverage must include supported non-Copilot harnesses, not only Copilot CLI sessions. Disabled logging must retain its existing behavior.
- **Trace:**

  > AgentHostChatDebugContribution in src/vs/workbench/contrib/chat/browser/chatDebug/agentHostChatDebugProvider.ts is registered and gated by chat.agentHost.agentDebugLog.enabled. Its _provideChatDebugLog calls a synchronous _resolveEventsUri, which delegates to src/vs/workbench/contrib/chat/browser/copilotCliEventsUri.ts: that resolver accepts only Copilot CLI schemes and derives events.jsonl from the raw host URI ID. The missing-file path returns no provider events, while CopilotAgent.getSessionStateFile and _sdkConversationId in src/vs/platform/agentHost/node/copilot/copilotAgent.ts already distinguish host and backing identities. https://github.com/microsoft/vscode/issues/333153 confirms that mismatch in practice; https://github.com/microsoft/vscode/issues/329991 confirms missing Claude support and records maintainer interest in generic integration. The Copilot failure is understood, but the complete cross-provider event-source and normalization boundary has not been traced, so the broader issue is not a bounded implementation handoff. Preserve existing logging controls, legacy session support, and unrelated chat behavior.
