# Issue #339223 — Claude-format .claude/settings.json hooks enforced fail-closed on Windows; useClaudeHooks/useHooks/hookFilesLocations disables ignored

[https://github.com/microsoft/vscode/issues/339223](https://github.com/microsoft/vscode/issues/339223)

## Summary

Detailed, well-researched report of Claude-format hook handling denying every Copilot agent tool call on Windows; I confirmed one of the four claimed root causes directly in source (matchers are never read), which corroborates the report, but the full fail-closed chain spans multiple files/layers I could not fully trace without a Windows runtime, so this stays open rather than closing.

## Change summary

On Windows, a workspace `.claude/settings.json` with PreToolUse hooks causes every Copilot agent tool call to be denied, and the documented opt-out settings (`chat.useClaudeHooks`, `chat.useHooks`, `chat.hookFilesLocations`) have no effect.

## Best solution

A maintainer should walk through the Claude-hook discovery/execution path end to end (parseHooksFromFile → promptsServiceImpl.computeHooks → wherever PreToolUse hooks are actually executed for the Local harness) to confirm the fail-closed behavior and the Windows shell resolution, then decide whether to add matcher filtering, fix the Windows shell invocation, and/or relax fail-closed semantics for hook execution errors.

## Evidence

- **matcher ignored (confirmed in source):** extractHookCommandsFromItem in src/vs/workbench/contrib/chat/common/promptSyntax/hookSchema.ts (lines ~512-549) reads the `hooks` array inside a Claude-style matcher group but never inspects `itemObj.matcher` — every command under every matcher group for a hook type is extracted unconditionally, matching the reporter's claim that 'Local... ignores matcher values'.
- **useClaudeHooks gating exists but is only checked post-parse:** src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts computeHooks() reads PromptsConfig.USE_CLAUDE_HOOKS (default false, registered in chat.shared.contribution.ts line 2248-2256) and skips Claude-format hook files when `useClaudeHooks === false`, which should match the documented default — I could not trace why the reporter's explicit `false` setting had no effect, since that requires following the full execution path (possibly extension-side) which isn't fully visible from this checkout.
- **Windows shell execution path found (different mechanism than reporter describes):** executeHookCommand in src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts spawns `cmd.exe /c <command>` on Windows for agent-plugin-sourced hooks, not the WSL bash.exe the reporter describes — this may be a separate code path (agent plugins) from the '.claude/settings.json Local harness' hooks the issue is about, so it neither confirms nor refutes the reporter's exact mechanism.
- **related issue:** https://github.com/microsoft/vscode/issues/337374 — a related report about Claude-format plugin hooks on Windows (WSL bash, mangled paths, unset env var) that this issue explicitly distinguishes by removing the WSL-interop variable.
