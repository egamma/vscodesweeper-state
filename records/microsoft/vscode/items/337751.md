# Issue #337751 — cursor/selection jumps during chat rename

[https://github.com/microsoft/vscode/issues/337751](https://github.com/microsoft/vscode/issues/337751)

## Summary

Confirmed root cause on main: the inline rename input is unconditionally recreated (and re-`select()`ed) every time the row is re-rendered, which happens repeatedly while Autopilot drives session/status updates — explaining the visible 'random selection' while typing a rename.

## Change summary

While renaming a session/chat title during an active Autopilot run, the input's text selection jumps/resets mid-typing without the user selecting anything.

## Best solution

Guard the rename-input render path (SessionsList.renderRenameInput / the chat-item equivalent, and renderInlineRenameInput's focus/select calls) so an already-active InputBox for the same session/chat isn't torn down and re-selected on every incidental row re-render — only (re)focus/select when the rename input is genuinely being created for the first time.

## Evidence

- **immediate-autorun re-render:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts:1506-1513 wraps `renderRenameInput` in an `autorun` created fresh inside `renderElement`; autoruns execute immediately on creation, so any time this row's `renderElement` runs again while `editingSession` is already set to this session, `renderRenameInput` re-fires even though the user made no change.
- **unconditional recreate + reselect:** renderRenameInput (lines 1795-1827) and renderInlineRenameInput (lines 1057-1081) always call `DOM.clearNode(container)`, construct a brand-new `InputBox`, then `input.value = state.value; input.focus(); input.select();` — there is no check against `this.activeRenameInput` (which `beginRename` at 1782-1786 does check) before recreating, so an in-progress rename gets its DOM replaced and text fully re-selected on every such re-render.
- **trigger source:** SessionsList.refresh()/update() (lines 3940-3958) is invoked on session/status changes, which is exactly what Autopilot activity produces continuously — matching the reporter's description of selection jumping while typing during Autopilot.
- **duplicated pattern:** The chat-item renderer's renderRenameInput (lines 824-847) has the identical unconditional-recreate structure, so chat-title rename (as the issue title says 'chat rename') is likely affected the same way.
