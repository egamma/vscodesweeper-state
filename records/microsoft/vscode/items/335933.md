# Issue #335933 — Claude in the chat window doesn't show free text option when display decision choices

[https://github.com/microsoft/vscode/issues/335933](https://github.com/microsoft/vscode/issues/335933)

## Summary

Traced to a concrete default mismatch on current main: when Claude (via the built-in agent host) calls its native `AskUserQuestion` tool without an explicit `allowFreeformInput` flag, VS Code's mapper defaults it to `false`, hiding the free-text box — whereas VS Code's own `askQuestionsTool` (and the standalone Claude Code extension) default to allowing freeform input. This is a real, localized inconsistency worth fixing, not a design choice with visible rationale.

## Change summary

When using Claude as the chat harness, closed-ended clarifying questions never show a free-text fallback option, unlike the standalone Claude Code extension.

## Best solution

In `src/vs/platform/agentHost/node/claude/claudeInteractiveTools.ts:buildAskUserSessionInputQuestions`, change `allowFreeformInput: q.allowFreeformInput ?? false` to `?? true` (both the single-select and multi-select branches, lines ~113 and ~121) so it matches the default used by `askQuestionsTool.ts` (`question.allowFreeformInput ?? true`) and restores parity with the standalone extension; update the existing unit test in `claudeInteractiveTools.test.ts` that currently asserts `allowFreeformInput: false` as the unset-default.
