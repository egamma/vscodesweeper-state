# Issue #335933 — Claude in the chat window doesn't show free text option when display decision choices

[https://github.com/microsoft/vscode/issues/335933](https://github.com/microsoft/vscode/issues/335933)

## Summary

Traced this to a concrete default in the Claude agent-host integration: `buildAskUserSessionInputQuestions` in claudeInteractiveTools.ts defaults `allowFreeformInput` to `false` whenever the Claude SDK's `AskUserQuestion` tool call omits the field (which it always does in practice), so the workbench carousel never renders the freeform textarea for Claude sessions — while Codex and Copilot integrations in the same file default freeform support to `true`.

## Change summary

Feature-parity request: the built-in chat's multiple-choice prompt for the Claude harness never shows a free-text "Other" option, unlike the standalone Claude Code extension which always offers one.

## Best solution

Align the Claude AskUserQuestion mapping with the other providers by defaulting `allowFreeformInput` to `true` in `buildAskUserSessionInputQuestions` (src/vs/platform/agentHost/node/claude/claudeInteractiveTools.ts, both the singleSelect and multiSelect branches), matching how copilotAgentSession.ts and codexUserInputMapper.ts already default to allowing freeform answers; the carousel UI itself (chatQuestionCarouselPart.ts) already fully supports rendering the freeform box, so no UI change is needed.
