# Issue #307760 — Archiving sessions in slow

[https://github.com/microsoft/vscode/issues/307760](https://github.com/microsoft/vscode/issues/307760)

## Summary

The performance problem remains visible in current source: bulk archive awaits each session separately while session, group, and list observers refresh after individual changes. This team-authored On Deck issue must remain open, and no fixing commit or older canonical owns the same symptom.

## Change summary

Archiving every session in a folder blocks the renderer because the sessions list is recomputed repeatedly during the bulk operation.

## Best solution

Bulk archive should preserve provider-side archive behavior, partial-failure recovery, and undo while coalescing list-visible state changes so the folder is rendered once after the operation rather than once per session.

  > Archiving all sessions in a workspace or custom group must not block the renderer through repeated full-list rendering. All eligible sessions are archived, already archived sessions remain unchanged, and the list presents the final state in one coalesced update. Partial archive failures remain recoverable, and undo restores every successfully archived session with its prior valid group placement.
- **Trace:**

  > Bulk section and group actions call archiveSessionsWithUndo in src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts, which serially invokes archiveSession for every candidate.
