# Issue #32387 — Can't drag selected text with Ctrl to second file

[https://github.com/microsoft/vscode/issues/32387](https://github.com/microsoft/vscode/issues/32387)

## Summary

Cross-editor text dragging remains unsupported in the inspected source; the existing drag and drop settings do not provide Ctrl-drag copying into another file. Keep this older request open: the verified same-symptom reports are newer, and one was explicitly closed as a duplicate of this issue.

## Change summary

Allow selected text to be copied into another file by dragging it with Ctrl held.

## Best solution

Support cross-editor selection dragging with destination insertion feedback and Ctrl-copy semantics, preserving the source text and existing same-editor behavior. Use this issue as the older tracking report for the same-symptom requests, and settle cross-file move and undo semantics before extending the interaction.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/mouseHandler.ts`, `src/vs/editor/contrib/dnd/browser/dnd.ts`, `src/vs/editor/contrib/dnd/browser/dragAndDropCommand.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts`
- **Validation:** In a Windows build, open two writable files in side-by-side editors, select text in the first, hold Ctrl, and drag to a known insertion position in the second. Verify destination feedback, exact insertion, unchanged source text, and destination undo. Repeat with multiline text, cancellation, a read-only destination, and existing same-editor copy/move behavior; define and verify unmodified cross-file move/undo behavior if included.
- **Behavior:**

  > A user can Ctrl-drag selected text from one writable file into another editor and receive insertion-position feedback in the destination. Releasing inserts the selected text at that position without deleting or changing the source. Cancellation or an invalid destination leaves both files unchanged, and existing same-editor drag behavior remains intact. Cross-file movement without Ctrl and its undo contract need an explicit scope decision.
- **Trace:**

  > MouseDownOperation.start in src/vs/editor/browser/controller/mouseHandler.ts captures the selection drag through the originating editor's mouse monitor and view controller. DragAndDropController in src/vs/editor/contrib/dnd/browser/dnd.ts owns editor-local selection state and executes DragAndDropCommand on that editor; the command reads and edits one model in src/vs/editor/contrib/dnd/browser/dragAndDropCommand.ts. The separate DropIntoEditorController in src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts receives native dataTransfer drops, but the inspected internal selection-drag path does not supply that cross-editor payload. Preserve current same-editor behavior, modifier conventions, and incoming external-drop functionality; external-application dragging is not necessary to satisfy the original Ctrl-copy request. https://github.com/microsoft/vscode/issues/44844 was explicitly consolidated into this issue, while https://github.com/microsoft/vscode/issues/146651 and https://github.com/microsoft/vscode/issues/149184 supply newer cross-pane examples. The uncertainty is how to coordinate source and destination editors, and which user-visible move/undo and tab-switching behaviors belong in the initial scope.
- **Open decisions:**
  - Should the initial capability cover only Ctrl-copy between visible editor panes, or also dragging over an inactive tab to activate and drop into that file?
  - Should unmodified dragging move text between files in the same change, and if so, should undo restore the source deletion and destination insertion together or separately?

## Evidence

- **Current selection-drag boundary:** src/vs/editor/browser/controller/mouseHandler.ts: MouseDownOperation.start monitors the originating editor's viewLinesDomNode and emits mouse drag/drop events through that editor's view controller. src/vs/editor/contrib/dnd/browser/dnd.ts: DragAndDropController keeps the selection on its own editor instance and executes the drop command on that same editor.
- **Copy modifier does not transfer between models:** src/vs/editor/contrib/dnd/browser/dnd.ts: hasTriggerModifier recognizes Ctrl on Windows and Alt on macOS. src/vs/editor/contrib/dnd/browser/dragAndDropCommand.ts: getEditOperations reads the selected text and inserts it through a single ITextModel; copy only suppresses deletion within that model, rather than identifying a separate destination editor.
- **Existing-capability check:** src/vs/editor/common/config/editorOptions.ts registers editor.dragAndDrop with default true, but its implementation remains editor-local. editor.dropIntoEditor.enabled and src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts support incoming native DragEvent dataTransfer payloads, including plain text through DefaultTextPasteOrDropEditProvider; that receiving capability does not make the internal selection-drag path export text to another editor.
