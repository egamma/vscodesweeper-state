# Issue #329267 — Allow custom agents to select a model context window in .agent.md

[https://github.com/microsoft/vscode/issues/329267](https://github.com/microsoft/vscode/issues/329267)

## Summary

This remains a valid, accepted backlog request with 29 community upvotes. Current main supports choosing a context size per session, but custom-agent metadata carries only model preferences, so the requested reproducible per-agent behavior is still missing.

## Change summary

Allow custom agents to declare a supported model context-window profile and propagate it through validation, UI, CLI sessions, handoffs, and subagents.

## Best solution

Define a model-aware context-profile field in the custom-agent metadata contract, validate it against the selected model, and consistently apply and display the effective profile across local and Copilot CLI sessions, including handoffs and subagents.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vscode-dts/vscode.proposed.chatPromptFiles.d.ts`, `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts`, `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts`, `extensions/copilot/src/extension/chatSessions/copilotcli/vscode-node/copilotCLIChatSessionInitializer.ts`
- **Validation:** Add prompt-header completion and validation tests for supported and unsupported context profiles, plus Copilot CLI agent/session tests showing that an agent-declared profile maps to the expected contextTier, follows the agreed precedence and inheritance rules, and produces the agreed deterministic fallback.
- **Behavior:**

  > A custom `.agent.md` can select one context profile supported by its chosen model. The editor validates and completes the field, customization and session surfaces display the effective profile, and local and Copilot CLI execution honor the same selection. Unsupported profiles produce an actionable diagnostic and deterministic fallback, while agents without the field retain current behavior. Handoffs and subagents follow the agreed inheritance and override rules.
- **Trace:**

  > Custom-agent metadata is parsed through promptFileAttributes.ts, promptValidator.ts, promptFileParser.ts, and promptsServiceImpl.ts, then exposed as ChatCustomAgent in vscode.proposed.chatPromptFiles.d.ts; that contract currently carries model preferences but no context profile. The Copilot CLI model provider already defines numeric contextSize choices and resolveContextTier() in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts. However, CopilotCLIAgents.toCustomAgent() preserves only the agent's first model, and CopilotCLIChatSessionInitializer.resolveModel() returns immediately for an agent-declared model before reading per-request contextSize. The recently merged reasoning-effort precedent, https://github.com/microsoft/vscode/pull/329263, identifies the parser, validator, documentation, Agent Host converter, and tests that participate in adding model configuration metadata. Preserve existing behavior when the field is absent and do not conflate a context profile with history-reset or compaction policy.
- **Open decisions:**
  - Should the public `.agent.md` contract store a numeric token count, a model-defined profile identifier, or configuration attached to each model entry when multiple fallback models are declared?
  - When an agent-declared profile conflicts with an explicit session selection, which value wins, and exactly how should handoffs and subagents inherit or override it?
  - When the selected model does not offer the configured profile, should execution use the model default, the nearest supported size, or refuse to start after reporting the diagnostic?
