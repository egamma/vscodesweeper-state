# Issue #338780 — Agents Window: stacked Changes toolbars make Toggle Details look duplicated

[https://github.com/microsoft/vscode/issues/338780](https://github.com/microsoft/vscode/issues/338780)

## Summary

Fresh, well-diagnosed design issue: verified against source that Toggle Details (MenuId.EditorTitleLayout) and the Changes editor's own header toolbars (Menus.SessionsEditorHeaderPrimary/HeaderLayout in SinglePaneMainEditorPart) are genuinely two independent, stacked toolbar surfaces, which explains the reported visual confusion — this stays open for a maintainer/design decision on hierarchy.

## Change summary

In the Agents Window's single-pane Changes editor, narrow layouts stack Toggle Details above the Changes header's own overflow/ellipsis with little visual hierarchy, making the two look like duplicated controls.

## Best solution

Rework the visual hierarchy between the editor-title-row Toggle Details action and the Changes-specific header toolbar (SinglePaneMainEditorPart's Menus.SessionsEditorHeaderPrimary/HeaderLayout) so the two surfaces read as distinct — likely via spacing, grouping, or divider treatment in singlePaneEditorPart.ts / changesViewActions.ts rather than changing command registration.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/singlePaneEditorPart.ts`, `src/vs/sessions/contrib/changes/browser/changesViewActions.ts`, `src/vs/sessions/contrib/codeReview/browser/codeReview.contributions.ts`, `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneExistingSessionStrategy.ts`
- **Validation:** Manually verify in the narrow single-pane Changes editor that Toggle Details and the Changes header's own overflow are visually distinguishable (spacing, grouping, or divider treatment) rather than reading as one duplicated control.
- **Behavior:**

  > In the Agents Window's single-pane Changes editor, when the side pane is narrow enough that header actions become icon-only, the Toggle Details action (editor title row) and the Changes editor's own header toolbar (Run Code Review + overflow ellipsis) must be visually distinguishable as separate surfaces — not read as a duplicated or detached part of Toggle Details. Adjacent horizontal dividers (tab/header boundary, first diff card border) should not compound this by looking like redundant boundaries. Non-narrow layouts and other tab types (browser, search) are unaffected.
- **Trace:**

  > Toggle Details is contributed via MenuId.EditorTitleLayout / group 'navigation' in singlePaneExistingSessionStrategy.ts and renders in the editor title/tab row. Independently, SinglePaneMainEditorPart (singlePaneEditorPart.ts) always enables a second, full-width header wired to Menus.SessionsEditorHeaderPrimary/HeaderLayout; for the Changes editor this header's primary action is 'Run Code Review' (codeReview.contributions.ts) with secondary collapse/expand and diff-view actions behind an overflow ellipsis (changesViewActions.ts). These are two genuinely independent toolbar contribution points, confirmed by reading the registration code, not duplicate command registration. The full-width header was introduced/aligned in the PR the reporter cites as #335336. Boundary: do not merge or remove either menu contribution point; the fix is about visual hierarchy/spacing/grouping between the two surfaces, not consolidating the actions. Related but distinct: https://github.com/microsoft/vscode/issues/336898 covers title-action overlap under tab wrapping.
- **Open decisions:**
  - Should the fix add stronger visual separation (e.g. spacing/background) between the two toolbar rows, reduce the divider count, or restructure which actions live in which header?
  - Is the full-width Changes header itself the right long-term design, or should narrow single-pane layouts collapse it differently (a call tied to the #335336 header redesign)?
