# Issue #61140 — Problem matchers should restore problems on close

[https://github.com/microsoft/vscode/issues/61140](https://github.com/microsoft/vscode/issues/61140)

## Summary

Watch-task diagnostics now have a restoration workaround, but current source still relies on delayed replay rather than the coordinated builder/reconciler handoff agreed in the discussion. Keep this team-authored request open; the related API proposal is newer, and the cited fixes do not establish completion of this issue.

## Change summary

Restore retained build diagnostics when a file closes without racing live-diagnostic removal, losing problems, or showing duplicate diagnostics.

## Best solution

Complete the coordinated diagnostic-ownership model discussed here: live diagnostics take precedence for open files, while retained, version-aware builder diagnostics resume on close without timing-dependent flicker. Coordinate that work with https://github.com/microsoft/vscode/issues/74524 rather than treating the watch-task replay workaround as full completion.

- **Behavior:**

  > Build-task problems should remain available across opening and closing files even when live diagnostics use the same owner. Live diagnostics take precedence while a file is open; closing it restores the retained builder diagnostics without requiring another save or build and without timing-dependent flicker or duplicate entries. Retained results must account for the file version, since build output and unsaved editor content can differ. Acceptance should exercise repeated open/close cycles and asynchronous live-diagnostic removal.
