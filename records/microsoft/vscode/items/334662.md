# Issue #334662 — Agent Merge is not initiated for all PRs created against different base branches in one session

[https://github.com/microsoft/vscode/issues/334662](https://github.com/microsoft/vscode/issues/334662)

## Summary

Team-authored report describing a real architectural limitation in Agent Merge — session state tracks only a single `target.pullRequestUrl`, so when one Agents session creates two PRs against different base branches, only the first-discovered PR is monitored. Team-authored issues are protected from judgment closes, and this needs a design decision (multi-PR support or explicit UI) rather than a mechanical fix, so it stays open.

## Change summary

When an Agents session opens two PRs against different base branches, Agent Merge only picks up and repairs one of them instead of both (or clearly indicating the limitation).

## Best solution

Decide the intended scope for Agent Merge with multi-PR sessions: either extend `AgentMergeSessionState`/`AgentMergeTarget` in src/vs/platform/agentHost/common/agentMerge.ts and the controller in src/vs/platform/agentHost/node/agentMergeController.ts to track multiple PR targets per session, or make the current single-PR-per-session behavior explicit in the UI as requested.
