# Issue #334662 — Agent Merge is not initiated for all PRs created against different base branches in one session

[https://github.com/microsoft/vscode/issues/334662](https://github.com/microsoft/vscode/issues/334662)

## Summary

Confirmed in source: AgentMergeController's session state (`AgentMergeTarget`) only ever tracks a single `pullRequestUrl` per session (`agentMergeController.ts`), so when a session creates PRs against two different base branches, only the first-seen PR is bound and monitored — matching the reporter's observation. This is a design/architecture gap, not a trivial fix, so it stays open for a maintainer decision.

## Change summary

When one Agents session opens PRs against two different base branches, Agent Merge only attaches to and monitors one of them instead of both.

## Best solution

Extend `AgentMergeTarget`/`AgentMergeSessionState` in agentMerge.ts and the binding logic in agentMergeController.ts (`_evaluate`, lines ~443-488) to track multiple pull-request targets per session, or explicitly surface in the UI which single PR Agent Merge is bound to when only one is supported.
