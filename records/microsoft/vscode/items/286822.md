# Issue #286822 — GitHub Copilot more likely to summarize converation when switching to Agent mode

[https://github.com/microsoft/vscode/issues/286822](https://github.com/microsoft/vscode/issues/286822)

## Summary

Current source supports the reported correlation: entering Agent mode enables compaction and reduces the message budget for agent tools, so a long planning conversation can cross the limit and compact immediately before implementation. The issue remains distinct from the older summarization-quality report and should stay open as mode-transition polish.

## Change summary

Avoid automatic conversation compaction at the Agent-mode handoff from discarding or weakening the recent plan that the agent is about to implement.

## Best solution

When entering Agent mode under context pressure, preserve the latest planning turns as authoritative context for the first implementation request while compacting or pruning older material. The transition policy should also account for the additional token budget consumed by Agent-mode tools before execution begins.

- **Behavior:**

  > A long planning conversation can transition into Agent mode without losing the recent plan immediately before implementation starts. If Agent mode's additional tools make compaction necessary, the latest planning turns remain available with enough fidelity to drive the first implementation response. Existing compaction behavior for genuinely old history and already-running Agent sessions remains effective.
- **Trace:**

  > AgentIntentInvocation.buildPrompt in extensions/copilot/src/extension/intents/node/agentIntent.ts enables summarization for AgentPrompt, subtracts Agent tool-schema tokens plus a safety margin, and catches BudgetExceededError by running foreground summarization. SimpleSummarizedHistory in extensions/copilot/src/extension/prompts/node/agent/simpleSummarizedHistoryPrompt.tsx explicitly identifies an ask-to-Agent switch as an overflow case. Background compaction currently begins only after a qualifying Agent render, so it cannot prevent synchronous compaction on the first over-budget Agent request. Keep the boundary to conversation budgeting and history preservation; do not change tool availability, model context limits, or general mode capabilities. https://github.com/microsoft/vscode/issues/283446 remains related quality work rather than a canonical duplicate.
- **Open decisions:**
  - When an Agent-mode switch crosses the context budget, must the latest planning turns remain verbatim, or may they be compacted if the resulting summary explicitly preserves the plan?
  - Should the transition policy cover only the built-in Agent mode, or every mode/toolset change that materially reduces the message budget?

## Evidence

- **source trigger:** extensions/copilot/src/extension/intents/node/agentIntent.ts enables summarization only for AgentPrompt, subtracts tool-schema tokens and a 10% safety margin from the available message budget, and invokes foreground summarization when that reduced budget raises BudgetExceededError.
- **documented transition case:** extensions/copilot/src/extension/prompts/node/agent/simpleSummarizedHistoryPrompt.tsx explicitly lists “Switching from ask mode (no summarization) to agent mode” as a way history can become too large and require fallback summarization.
- **remaining first-turn gap:** The background-compaction path in extensions/copilot/src/extension/intents/node/agentIntent.ts starts only after an Agent prompt renders near its threshold; an initial switch whose larger tool budget already exceeds the limit still takes the synchronous foreground-compaction path.
- **independent confirmation:** https://github.com/microsoft/vscode/issues/286822#issuecomment-3765793721 reports the same excessive summarization behavior independently, including summaries on consecutive prompts.
- **related but not duplicate:** The older open https://github.com/microsoft/vscode/issues/283446 concerns semantic loss and fabrication within summaries, not the same observable symptom of compaction being triggered specifically at an Agent-mode transition. The closed https://github.com/microsoft/vscode/issues/284474 delivered manual compaction, while the younger https://github.com/microsoft/vscode/issues/289220 requests a different truncation strategy.
- **existing workaround is incomplete:** extensions/copilot/package.json exposes github.copilot.chat.summarizeAgentConversationHistory.enabled, but disabling all automatic compaction does not address the central request for a safe planning-to-Agent handoff.
