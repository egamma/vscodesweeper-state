# Issue #164393 — Git - diff editor cannot be opened while scanning for repositories

[https://github.com/microsoft/vscode/issues/164393](https://github.com/microsoft/vscode/issues/164393)

## Summary

Keep open: current source still makes Git diff content wait for the entire initial repository scan, even when the selected repository is already available. The reported configuration workarounds shorten scanning but do not remove this dependency.

## Change summary

Allow diffs and historical file content from an already-discovered repository to load while unrelated repository discovery continues.

## Best solution

Make Git filesystem access depend on availability of the requested repository rather than completion of workspace-wide discovery. Preserve startup handling for repositories that have not yet been discovered and existing repository-selection semantics.

## Evidence

- **Reporter-confirmed trigger:** In https://github.com/microsoft/vscode/issues/164393, the reporter explains that SCM already lists uncommitted changes, but opening their diff waits until subdirectory scanning finishes. They confirm that reducing git.repositoryScanMaxDepth to 1 or excluding large folders mitigates it, and supply a large node_modules directory with scan depth 5 as an alternative reproduction setup.
- **Current source blocks both filesystem operations:** extensions/git/src/fileSystemProvider.ts: GitFileSystemProvider.stat and readFile unconditionally await this.model.isInitialized before attempting getOrOpenRepository. Thus an already-open repository cannot serve either metadata or content while the initialization promise remains pending.
- **Initialization includes unrelated discovery:** extensions/git/src/model.ts: Model.isInitialized resolves only on the initialized state. The constructor sets that state in doInitialScan().finally(...); doInitialScan awaits Promise.all including scanWorkspaceFolders, which traverses configured subfolders and awaits their openRepository calls. Meanwhile openRepository publishes repositories through this.open(repository) and schedules status without awaiting it, allowing SCM changes to appear before the global scan finishes.
- **Diff path and workaround boundary:** extensions/git/src/repository.ts: Resource.openChange invokes ResourceCommandResolver.resolveChangeCommand, which selects vscode.diff for resources with a left-hand revision. extensions/git/package.json registers git.repositoryScanMaxDepth and git.repositoryScanIgnoredFolders; these limit discovery work but do not bypass the Git filesystem initialization barrier.
