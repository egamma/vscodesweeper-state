# Issue #305375 — User prompt triggers "allow reading external file"

[https://github.com/microsoft/vscode/issues/305375](https://github.com/microsoft/vscode/issues/305375)

## Summary

Keep open: the report and maintainer diagnosis show a user prompt's `vscode-userdata:` URI being shortened into an external filesystem path, producing an unnecessary permission prompt. Older related fixes did not cover this prompt-specific recurrence, and no older open issue clearly owns the full scope.

## Change summary

Running a user-defined prompt causes its already-attached prompt file to be treated as an untrusted external file and triggers a read confirmation.

## Best solution

Preserve or recover the trusted identity of an attached user prompt when handling its `read_file` request, while continuing to require confirmation for arbitrary external paths. Consolidate the broader customization behavior only if maintainers decide the older instruction-file issue owns prompts as well.

  > Invoking a user-defined prompt must not ask permission to read that prompt's own attached file, even if the model emits its native filesystem path instead of the original `vscode-userdata:` URI. Unrelated files outside the workspace must continue to require confirmation. Acceptance requires tests covering both the trusted prompt read and the unchanged arbitrary-external-file behavior.
- **Trace:**

  > The request attachment retains its full URI in `IPromptFileVariableEntry.value` and ID in src/vs/workbench/contrib/chat/common/attachments/chatVariableEntries.ts. The model nevertheless emitted a plain filesystem path; NativeBuiltinToolsContribution in src/vs/workbench/contrib/chat/electron-browser/builtInTools/tools.ts passes that value to ChatExternalPathConfirmationContribution, whose `getPreConfirmAction` in src/vs/workbench/contrib/chat/common/tools/builtinTools/chatExternalPathConfirmation.ts constructs a file URI and only checks working-directory and allowlist containment. The report and maintainer comment confirm this translation produces the dialog. Preserve confirmation for arbitrary external paths and avoid broad trust of the entire user-data directory. https://github.com/microsoft/vscode/issues/281799 and https://github.com/microsoft/vscode/issues/307149 demonstrate adjacent instruction and skill cases but do not conclusively settle ownership of this prompt-file case.
