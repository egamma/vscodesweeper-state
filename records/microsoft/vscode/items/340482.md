# Issue #340482 — Agents Window feels persistently sluggish, with additional freezes when switching sessions

[https://github.com/microsoft/vscode/issues/340482](https://github.com/microsoft/vscode/issues/340482)

## Summary

Thanks for the detailed traces and for narrowing it down. The reporter's follow-up says the sluggishness disappears when chat.agentSessions.sessionStorageCleanupSuggestion.enabled is turned off, with hundreds of worktrees. The cleanup service is a plausible culprit, but I could not run it to confirm that its scan causes the main-thread load, so this stays open.

## Change summary

The Agents Window is persistently laggy, with ~1s freezes when switching sessions, in a setup with hundreds of agent worktrees.

## Best solution

Make the worktree cleanup-suggestion scan in SessionWorktreeCleanupService cheap on large worktree sets, for example by rate-limiting or deferring it and keeping it off the interactive path. It should not re-run on every sessions-change event. Then confirm the traced Agent Host and in-memory filesystem timer-reset hotspots are not separate contributors.
