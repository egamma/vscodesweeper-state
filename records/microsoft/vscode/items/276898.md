# Issue #276898 — Unexpected interactions with faster NES provider

[https://github.com/microsoft/vscode/issues/276898](https://github.com/microsoft/vscode/issues/276898)

## Summary

Team-authored, confirmed bug in the faster inline-edits provider path with two concrete observable failures; no mechanical fix or verified duplicate is cited, so it must remain open.

## Change summary

With inline-edit debounce and cache delays set to zero, suggestions can change while the user types the suggested text and ghost text can flicker during cursor-left navigation.

## Best solution

Stabilize suggestion identity and visibility across rapid provider updates and cursor movement in the inline-completions/inline-edits pipeline, while preserving the normal debounce and cache behavior.

The same checks must hold independently of automatic bracket closing, while ordinary provider refreshes may still replace a suggestion when its content is genuinely no longer compatible.
- **Trace:**

  > The report exercises the inline-completions model under zero-delay inline-edit settings and records two timing-sensitive symptoms: replacement while typing the suggestion's own prefix, and visibility flicker during cursor-left movement at an accepted edit boundary. The likely path is the provider-result/cache and rebase handling in `src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsSource.ts`, coordinated with active-item selection and rendering state in `inlineCompletionsModel.ts` and edit tracking in `inlineCompletionsModelChangeRecorder.ts`. The auto-closing-brackets control in the report indicates that bracket insertion must not be assumed to be the root cause. Preserve legitimate replacement by newer incompatible provider results and normal delayed-cache behavior; scope diagnosis to stability under rapid compatible updates and cursor-only transitions.
