## Summary

Confirmed root cause on current main and a fix is already in progress: `runSnippy` in nextEditProvider.ts calls `SnippyService.handlePostInsertion` without await/.catch, so a 400 from the snippy match endpoint (source below the service's ~110-token floor) escapes as an unhandled rejection reported to telemetry. An open PR already targets this exact issue, so it should stay open pending merge rather than being closed or auto-fixed here.

## Change summary

Copilot Chat's Next Edit Suggestions 'snippy' code-referencing post-insertion check throws an unhandled 400 error ('source too short') that gets reported as unhandled application error telemetry.

## Best solution

Land the already-open fix PR https://github.com/microsoft/vscode/pull/331825, which awaits `handlePostInsertion` inside a try/catch in `runSnippy` (extensions/copilot/src/extension/inlineEdits/node/nextEditProvider.ts) and routes failures to `logService.error` instead of letting them escape as unhandled rejections.
