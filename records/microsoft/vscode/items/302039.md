# Issue #302039 — Enabling `github.copilot.chat.agentDebugLog.enabled` makes `/troubleshoot` available permanently

[https://github.com/microsoft/vscode/issues/302039](https://github.com/microsoft/vscode/issues/302039)

## Summary

Team-authored issue that remains valid. The `/troubleshoot` command's blue styling persists after disabling the setting because the chat input renders any `/foo` text as a slash command regardless of registration. The underlying gating (execution-time block in `chatServiceImpl.ts:1312` and the extension-side skill filtering in `automaticInstructionsCollector.ts:457`) works correctly at request time, but the UI presentation does not reflect the disabled state. The revert of 'Allow intellisense for troubleshoot skill' (ac2c1190cce) partially addressed this, but the cosmetic blue styling for unregistered slash commands remains a broader issue.

## Change summary

After disabling `github.copilot.chat.agentDebugLog.enabled` and reloading, `/troubleshoot` still renders with blue slash-command styling in the chat input, even though it is gated at execution time.

## Best solution

Two fixes: (1) The chat input's slash-command decoration should only apply blue styling to *registered* slash commands / skills, not to arbitrary `/word` patterns — this is the broader fix pwang347 mentioned pairing with file-linking work. (2) Optionally, the `tip.troubleshoot` tip in `chatTipCatalog.ts` should be gated behind the `fileLogging.enabled` setting so it doesn't advertise `/troubleshoot` when the skill is unavailable.
