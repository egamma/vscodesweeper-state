# Issue #151896 — Allow extensions to force-open the references view

[https://github.com/microsoft/vscode/issues/151896](https://github.com/microsoft/vscode/issues/151896)

## Summary

Keep open: current main still lacks a direct way to display supplied reference locations in the References view independently of the user's preference. An open PR proposes that API and should be reviewed before this issue is considered completed.

## Change summary

Allow extensions to show supplied reference results in the References view without changing references.preferredLocation.

## Best solution

Review https://github.com/microsoft/vscode/pull/338496 for a preference-independent showReferences API on the bundled References view extension, preserving the existing preference-sensitive command behavior.

## Evidence

- **Current command behavior:** extensions/references-view/src/references/index.ts registers editor.action.showReferences only when references.preferredLocation is 'view'. Otherwise src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts aliases it to editor.action.peekLocations, matching the reporter's configuration-dependent behavior.
- **Existing capabilities do not directly cover the request:** references-view.findReferences queries vscode.executeReferenceProvider at the active editor selection rather than accepting caller-supplied locations. extensions/references-view/src/extension.ts exports only setInput and getInput; extensions/references-view/src/references-view.d.ts requires callers of setInput to implement a complete SymbolTreeInput and model. This custom-tree API is an indirect alternative, not a direct way to display supplied locations using the built-in reference model.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/338496 was verified OPEN with mergedAt null. Its diff adds showReferences(uri, position, locations) to the exported References view API, constructs ReferencesTreeInput from supplied locations, and calls tree.setInput without consulting references.preferredLocation. This directly addresses the request but has not merged.
- **Related issue is not a canonical duplicate:** https://github.com/microsoft/vscode/issues/134405 was verified OPEN and requests a file references provider API, including listing file references and safe deletion. It does not own the same observable request to force a particular presentation for supplied locations; the reporter explicitly distinguishes the two.
- **Discussion workaround:** The provided 2025-05-14 comment suggests modifying global settings when no workspace setting exists, citing https://github.com/johnsoncodehk/tsconfig-helper/commit/c9a78b1e4df458355eff58fbd5b422ecb13e1025. That avoids creating an empty workspace settings file but still changes configuration and does not provide the requested preference-independent API.
- **Canonical search:** An open-issue search for references, view, and extensions returned this issue, the distinct file-provider proposal, and other references presentation requests; no older issue owning this exact force-open capability was established.
