# Issue #151896 — Allow extensions to force-open the references view

[https://github.com/microsoft/vscode/issues/151896](https://github.com/microsoft/vscode/issues/151896)

## Summary

A real extension API ergonomics gap remains: extensions can populate the References view through its low-level exported API, but cannot pass locations to a dedicated command that bypasses the user's preferred presentation.

## Change summary

Let extensions force supplied reference locations into the References view without temporarily changing `references.preferredLocation`.

## Best solution

Add a dedicated command in the built-in References View extension that accepts an anchor and locations, constructs `ReferencesTreeInput`, and opens the view without modifying configuration.

## Evidence

- **current implementation:** `extensions/references-view/src/references/index.ts` only intercepts `editor.action.showReferences` when `references.preferredLocation` equals `view`; there is no per-invocation override.
- **configuration workaround remains:** `extensions/typescript-language-features/src/languageFeatures/fileReferences.ts` and `extensions/markdown-language-features/src/languageFeatures/fileReferences.ts` still temporarily update `references.preferredLocation` before invoking the command.
- **existing low-level API:** `extensions/references-view/src/references-view.d.ts` exports `SymbolTree.setInput`, but callers must implement the complete `SymbolTreeInput` and tree model contracts rather than passing reference locations directly.
- **maintainer precedent:** Discussion in https://github.com/microsoft/vscode/issues/112507 explicitly identified a dedicated References view command as the alternative to overriding configuration.
- **related request:** https://github.com/microsoft/vscode/issues/134405 remains open but concerns a file-reference provider API; it does not fully cover arbitrary extension-supplied locations and presentation control.
