# Issue #336187 — Terminal Cursor Appearing 8 Chars Before End of Prompt

[https://github.com/microsoft/vscode/issues/336187](https://github.com/microsoft/vscode/issues/336187)

## Summary

The reporter traced a real, specific defect in the bash shell-integration script's PS1 construction; the exact code on current main (line 386 of shellIntegration-bash.sh) matches the described bug precisely, with a plausible one-line fix proposed — this should go to the terminal team rather than be closed.

## Change summary

When shell integration is enabled in Bash and a wrapped prompt (due to narrow terminal width) is unwrapped again, readline miscounts the invisible OSC 633 markers and leaves the cursor 8 cells left of the actual prompt end.

## Best solution

Have a terminal maintainer evaluate the reporter's proposed one-line change in src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh (moving __vsc_prompt_end outside the `\[ \]` non-printing-character markers) against readline's cursor-tracking behavior, since it directly targets the traced root cause.
