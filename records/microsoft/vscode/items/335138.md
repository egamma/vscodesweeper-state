# Issue #335138 — Codex Agent Host: recognize non-ChatGPT accounts (API key, Bedrock, Azure, local, custom providers) as usable

[https://github.com/microsoft/vscode/issues/335138](https://github.com/microsoft/vscode/issues/335138)

## Summary

Current source already admits models from configured non-ChatGPT providers, but does not expose those providers as accounts. Keep this open to resolve the remaining provider-indicator requirement and verify signed-out first-use availability rather than treating the ChatGPT account status alone as proof of an unusable harness.

## Change summary

Make configured Codex API-key, Bedrock, Azure, local, and custom providers usable and identifiable without GitHub or ChatGPT sign-in.

## Best solution

Separate native-provider usability from ChatGPT identity, preserving provider-qualified model selection and routing. Establish the minimal non-ChatGPT provider indicator and verify that first-use discovery makes a configured provider selectable while signed out of GitHub.

- **Behavior:**

  > A Codex provider configured independently of GitHub and ChatGPT is selectable when its usable model catalog is discovered, including on first use. Selecting its model sends requests through that configured provider rather than Copilot. The user can identify the active native provider without a fabricated ChatGPT identity or subscription quota. An empty catalog must not count as a usable provider, and ambient startup must retain the existing no-activation behavior.
- **Trace:**

  > codexAccountStateFromResponse() in src/vs/platform/agentHost/node/codex/codexAccountState.ts marks apiKey/other as unavailable, but _refreshCodexModels() in codexAgent.ts accepts that state and publishes models using config.model_provider; the existing non-human-provider model-refresh test confirms this intended separation. resolveAgentAuthRequirement() in baseAgentHostSessionsProvider.ts uses catalog availability, not human account status. The trace establishes existing native catalog support and missing non-ChatGPT account presentation, not a conclusive current reproduction of the entire reported picker failure. Preserve explicit activation, ChatGPT-only identity/quota metadata, provider-qualified selections, and per-conversation routing. https://github.com/microsoft/vscode/issues/329668 supplies the accepted availability contract; https://github.com/microsoft/vscode/issues/324652 is related presentation work, not a verified duplicate.
- **Open decisions:**
  - Should non-ChatGPT configurations appear as provider-status entries in Accounts, or should their identity be presented only alongside the selected model while Accounts remains reserved for human sign-ins?
