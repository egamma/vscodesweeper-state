# Issue #194102 — Git - `git.requireGitUserConfig` setting has no effect

[https://github.com/microsoft/vscode/issues/194102](https://github.com/microsoft/vscode/issues/194102)

## Summary

Still a real defect on main — the commit-error handler misattributes any commit failure to missing user.name/user.email regardless of `git.requireGitUserConfig` — and an open PR already proposes the fix, so this stays open until that PR lands or is closed.

## Change summary

Setting `git.requireGitUserConfig` to `false` still surfaces the "Make sure you configure your user.name and user.email in git" error when a commit fails for an unrelated reason.

## Best solution

Land (or reject) https://github.com/microsoft/vscode/pull/304983: `Git.handleCommitError` in extensions/git/src/git.ts should skip the user.name/user.email probe — or at least not rewrite the error code — when `requireUserConfig` is false, so the real commit failure (e.g. a failing hook) is reported instead.

## Evidence

- **setting is honored only for the commit args:** extensions/git/src/repository.ts:1469-1472 reads `git.requireGitUserConfig` and extensions/git/src/git.ts:2136-2139 uses it only to decide whether to pass `-c user.useConfigOnly=true`.
- **root cause on current main:** extensions/git/src/git.ts:2163-2187 `handleCommitError` runs `git config --get-all user.name` / `user.email` on every commit failure and rewrites the error to `GitErrorCodes.NoUserNameConfigured`/`NoUserEmailConfigured` without consulting `opts.requireUserConfig`; extensions/git/src/commands.ts:5629-5633 then shows the reported message. So with the setting false and no user config, any commit failure (e.g. a pre-commit hook) still produces this message.
- **open fix PR:** https://github.com/microsoft/vscode/pull/304983 ("fix: respect git.requireGitUserConfig setting on commit errors") is open and references this issue — a human-owned implementation candidate.
- **related report:** https://github.com/microsoft/vscode/issues/229011 describes the same misattribution for pre-commit hook failures with GIT_AUTHOR_NAME/EMAIL set; it is newer than this issue, so it is not a canonical for a duplicate close here.
