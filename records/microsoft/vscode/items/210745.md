# Issue #210745 — Diff Editor Unstage buttons

[https://github.com/microsoft/vscode/issues/210745](https://github.com/microsoft/vscode/issues/210745)

## Summary

The requested unstage buttons are still missing from the staged diff editor; existing selection commands provide only a workaround. Keep this older request as the tracking issue, with the newer matching report as supporting demand.

## Change summary

Add diff-editor buttons to unstage individual blocks or selected changes while viewing staged changes.

## Best solution

Provide index-aware Unstage Block and Unstage Selection actions alongside the existing diff-editor staging actions, without making staged documents editable or changing working-tree contents.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/src/commands.ts`, `src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts`
- **Validation:** In a temporary Git repository, stage two separated hunks and open the staged diff. Check added and deleted lines, overlapping staged/unstaged edits, and existing staging actions.
- **Behavior:**

  > When viewing staged changes, users can unstage a block or selected changes directly from diff-editor buttons, without opening a context menu or unstaging the entire file. Only the targeted changes leave the index; other staged changes and all working-tree contents remain unchanged. Staged diff documents remain read-only. Existing staging and reverting interactions retain their behavior.
- **Trace:**

  > extensions/git/package.json contributes staging actions, but no unstaging actions, to the hunk and selection gutter menus. CommandCenter.diffStageHunkOrSelection in extensions/git/src/commands.ts accepts file-scheme modified documents and stages the toolbar context's originalWithModifiedChanges, so that handler does not cover staged Git documents. CommandCenter.unstageSelectedRanges separately resolves index changes, intersects them with editor selections, inverts them, and writes the resulting index content. DiffEditorGutter in src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts builds hunk and selection mappings and supplies toolbar context; the exact mapping-to-index transformation for unstaging through this context remains to be diagnosed. Preserve staged-document read-only behavior and avoid changes to working-tree content or unrelated quick-diff commands. https://github.com/microsoft/vscode/issues/262657 corroborates the same missing UI but is newer; https://github.com/microsoft/vscode/issues/96850 addresses the distinct operation of reverting staged changes.

## Evidence

- **Missing toolbar capability:** extensions/git/package.json:2877–2890 contributes only git.diff.stageHunk and git.diff.stageSelection to diffEditor/gutter/hunk and diffEditor/gutter/selection. Both require an original Git URI with ref '~'; neither provides an unstaging action for a staged HEAD-to-index comparison.
- **Existing capability is a workaround:** extensions/git/package.json:2829–2831 exposes git.unstageSelectedRanges in the staged diff editor's context menu. extensions/git/src/commands.ts:2063–2122 implements selection-based unstaging by inverting selected index changes and writing the resulting content to the index. This does not supply the requested per-block or selection gutter buttons.
- **Staging handler cannot cover staged diffs:** extensions/git/src/commands.ts:1703–1754 routes the existing buttons through diffStageHunkOrSelection, which requires the modified URI to use the file scheme and stages originalWithModifiedChanges. Staged Git documents are not handled by that path.
- **Read-only staged documents are not the requested change:** src/vs/editor/browser/widget/diffEditor/diffEditor.contribution.ts:38–59 gates built-in revert buttons on diffEditorModifiedWritable. https://github.com/microsoft/vscode/issues/263110#issuecomment-3242713149 confirms that both sides of staged diffs are intentionally read-only; adding index operations should preserve that boundary.
