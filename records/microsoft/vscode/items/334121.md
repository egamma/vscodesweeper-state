# Issue #334121 — Multiple Agents Windows

[https://github.com/microsoft/vscode/issues/334121](https://github.com/microsoft/vscode/issues/334121)

## Summary

Reasonable request grounded in the current architecture: the Agents window is backed by a single fixed `agentSessionsWorkspace` URI, so "Open in Agents" from any VS Code window reuses/focuses the same singleton window rather than opening a distinct one per project — this is by design today, not a bug, so it should be routed as a feature request rather than closed.

## Change summary

Allow multiple independent Agents windows to be open at once, one per VS Code project/window, instead of a single shared Agents window.

## Best solution

Belongs with the Agents Window / sessions team: either let each VS Code window's "Open in Agents" target a window scoped to that project, or otherwise support multiple concurrent top-level Agents windows. Related but not identical to https://github.com/microsoft/vscode/issues/319877, which asks for splitting individual sessions into new windows from within an existing Agents window — that doesn't obviously cover launching a second independent window from a different VS Code project via the titlebar entry point, so keep this open as its own request until a maintainer determines whether the two converge on one underlying change.

## Evidence

- **singleton workspace:** src/vs/platform/windows/electron-main/windowsMainService.ts `ensureAgentsWindow()` always resolves to the single fixed `environmentMainService.agentSessionsWorkspace` URI, and `openAgentsWindow()` calls the normal `open()` path, which for an already-open workspace focuses the existing window rather than creating a second one.
- **entry point:** src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts `openCurrentWorkspaceInAgentsWindow()` is the "Open in Agents" titlebar/command-palette action invoked per VS Code window, but it always targets the same shared Agents workspace.
