# Issue #327944 — Synced customizations with the same destination are resolved nondeterministically

[https://github.com/microsoft/vscode/issues/327944](https://github.com/microsoft/vscode/issues/327944)

## Summary

Keep open: current source still reads and hashes every colliding source and writes destinations repeatedly; concurrent skill-directory enumeration can also change which resource wins. The instruction-read race described in the report has changed, but the central collision-handling defect remains.

## Change summary

Resolve synthetic-plugin destination collisions deterministically, with content, provenance, and nonce derived from the same winner and no reads of losing duplicates.

## Best solution

Establish the intended source precedence and skill-directory collision semantics, then make SyncedCustomizationBundler consistently honor that contract. Preserve existing behavior for uniquely named customizations and unrelated MCP bundling.

- **Behavior:**

  > Two customization sources that map to one synthetic-plugin destination must resolve according to an explicit precedence rule, independently of asynchronous completion timing. Destination content and provenance must identify the same winner, and losing content must not affect the nonce or require reading. A losing source's read failure must not prevent bundling the winning source. Acceptance covers the reported same-name instruction files and same-name skill directories while preserving uniquely named customizations.
- **Trace:**

  > SyncedCustomizationBundler._bundle in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/syncedCustomizationBundler.ts builds an entries array and an independent originByDest map without checking destination collisions. All entries are subsequently read and hashed, then written sequentially; Promise.all preserves instruction entry order, so the original instruction read-completion race is no longer present. Skill resource entries are appended after concurrent collectDirectoryFiles traversals, leaving their collision order timing-dependent and allowing resources from distinct roots to mix. resolveCustomizationRefs in agentHostLocalCustomizations.ts forwards loose files to synced and standalone bundles without resolving these collisions. The existing test suite provides in-memory providers and controllable stat delays, but its same-basename skill test uses different skill directory names. Keep discovery, MCP behavior, authority isolation, and noncolliding customization semantics unchanged. https://github.com/microsoft/vscode/issues/321651 supplies broader multi-root context, not a duplicate canonical; uncertainty remains over which source should win and whether a colliding skill is selected as a whole directory.
- **Open decisions:**
  - Which source precedence should determine the winner for colliding destinations, including the reported .copilot and .claude user customizations?
  - When two skill roots share a directory name, should one entire skill directory win, or should distinct resource paths from both roots remain eligible under per-destination precedence?

## Evidence

Both reported instruction paths map to rules/shared.instructions.md, and both reported skill roots map to skills/shared/SKILL.md.
- **Changed race mechanism, unresolved defect:** The current _bundle reads entries through Promise.all, which preserves their array order, and then writes fileContents sequentially. Instruction content therefore no longer wins by read-completion order for a fixed input list. However, collectDirectoryFiles runs concurrently for skills and appends associated resources after each traversal completes, so colliding skill-resource write order can still depend on traversal timing.

Editing a losing instruction changes the nonce despite unchanged final destination content; a rejected losing read rejects the bundle.
