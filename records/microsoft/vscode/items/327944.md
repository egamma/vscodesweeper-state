# Issue #327944 — Synced customizations with the same destination are resolved nondeterministically

[https://github.com/microsoft/vscode/issues/327944](https://github.com/microsoft/vscode/issues/327944)

## Summary

Confirmed on current main: asynchronous reads determine write order when customization sources map to the same destination, making the resulting content nondeterministic. This team-authored issue should remain open for an explicit precedence decision and fix.

## Change summary

Make destination-collision handling deterministic and keep content, provenance, nonce calculation, and file-read behavior consistent with the winning customization source.

## Best solution

Define source precedence at the customization-resolution boundary, deduplicate by computed destination before reading files, and pass only winners into SyncedCustomizationBundler. Add collision coverage for instruction files and same-named skill directories, including nonce stability and verification that losing sources are not read.
