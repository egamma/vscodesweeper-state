# Issue #335678 — Opening an automations file should show an action to import/add the automation

[https://github.com/microsoft/vscode/issues/335678](https://github.com/microsoft/vscode/issues/335678)

## Summary

Fresh, unimplemented feature request for the new automations feature; no import/add affordance exists yet when opening an automations file, and there's a real UX decision (editor vs. agents window behavior) worth a maintainer's input before implementation.

## Change summary

Opening an automations JSON file should surface an action (e.g. CodeLens/button) to import/add that automation, in both the agents window and the plain editor.

## Best solution

Add a CodeLens or similar affordance on automation files, following the existing precedent in mcpLanguageFeatures.ts / promptToolsCodeLensProvider.ts for config-file import actions; in the plain editor window it should open/reveal the automation in the Agents window since editor-window support doesn't exist yet.

- **Behavior:**

  > Opening a recognized automations file should present an action to import/add that automation. In the Agents window this should add it directly; in the plain editor window (which has no native automations support yet) invoking the action should switch to/open the Agents window and reveal the imported automation there.
- **Trace:**

  > No CodeLens/editor contribution currently exists for automation files under src/vs/workbench/contrib/chat/common/automations/ or aiCustomization/ — confirmed by search. The closest existing pattern is McpLanguageFeatures (src/vs/workbench/contrib/mcp/browser/mcpLanguageFeatures.ts), which registers a CodeLensProvider over mcp.json to offer add/run actions, and the prompt-file CodeLens providers under chat/browser/promptSyntax/. Depends on the automations feature landed in https://github.com/microsoft/vscode/issues/335507. Uncertainty starts at: which UI mechanism to use (CodeLens vs. notification/button) and the precise editor-window fallback behavior.
- **Open decisions:**
