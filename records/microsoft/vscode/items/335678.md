# Issue #335678 — Opening an automations file should show an action to import/add the automation

[https://github.com/microsoft/vscode/issues/335678](https://github.com/microsoft/vscode/issues/335678)

## Summary

Keep open: the existing Import Automation action requires a file picker in the Automations view, rather than offering import from an opened automation file in either window. This team-authored, accepted request remains distinct from the related import-discoverability issues.

## Change summary

Offer an import action when a .automation.md file is opened in either window, with editor-window imports opening the Agents Window and revealing the automation.

## Best solution

Provide a contextual entry point for opened automation blueprints that leads into the existing review-before-create flow. Preserve disabled-by-default imports and carry editor-window invocations into the Agents Window, revealing the resulting automation.

- **Behavior:**

  > Opening a .automation.md file should expose an understandable import/add action in both the editor and Agents Window. An invocation from the editor window should open the Agents Window and reveal the resulting automation. Cancelling review must not create an automation.
- **Trace:**

  > ImportAutomationAction in src/vs/sessions/contrib/sessions/browser/views/automationsView.ts registers sessions.automations.import in the Automations view menu and always asks for a file through IFileDialogService. These paths establish import semantics but do not establish an opened-editor action or a cross-window handoff. The trace stops at that boundary: the receiving window's resource delivery, review, and reveal mechanism still needs investigation. Preserve the existing picker, drag-and-drop, blueprint validation, and review-before-create behavior, and respect the prohibition on workbench imports from the sessions layer.
