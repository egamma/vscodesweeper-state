# Issue #330819 — Clone should offer "Clone again" when a single existing clone is found

[https://github.com/microsoft/vscode/issues/330819](https://github.com/microsoft/vscode/issues/330819)

## Summary

Well-diagnosed, source-verified request: the git clone flow only shows the existing-repository picker (with its 'Clone again' option) when 2+ cached clones exist, and silently opens the single match otherwise — a real inconsistency worth a maintainer decision, not a bug.

## Change summary

Git: Clone should show the existing-repository quick pick (with a 'Clone again' choice) even when only one cached clone is found, instead of silently opening it.

## Best solution

In extensions/git/src/cloneManager.ts, route the single-cached-repository case through chooseExistingRepository() the same way the multi-match case already does (or add the git.cloneExistingRepositoryBehavior setting the reporter suggests), so a lone existing clone still offers 'Clone again'.
