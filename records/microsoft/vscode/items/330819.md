# Issue #330819 — Clone should offer "Clone again" when a single existing clone is found

[https://github.com/microsoft/vscode/issues/330819](https://github.com/microsoft/vscode/issues/330819)

## Summary

Confirmed in the source: when exactly one cached clone matches, `tryOpenExistingRepository` in extensions/git/src/cloneManager.ts short-circuits to that repo instead of routing through `chooseExistingRepository()`, which is exactly the picker (with a 'Clone again' entry) used for 2+ matches — so the reporter's description of the inconsistency is accurate. This is a reasonable, narrowly-scoped UX consistency ask that needs a maintainer product call (always prompt vs. add a setting), not an automatic fix.

## Change summary

Request that Git: Clone show the existing-repo picker (with a 'Clone again' option) even when only one cached clone is found, instead of silently reopening it.

## Best solution

extensions/git/src/cloneManager.ts line 237 is the exact spot: `repoForWorkspace = existingCachedRepositories.length === 1 ? existingCachedRepositories[0].workspacePath : undefined` bypasses `chooseExistingRepository()` for the single-match case. A maintainer should decide whether to always show the picker or add a `git.cloneExistingRepositoryBehavior`-style setting as the reporter suggests; either is a small, well-localized change in this file.
