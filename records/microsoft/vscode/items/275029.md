# Issue #275029 — Terminal Completion: `commandLine` context sometimes includes the shell indicator and the working directory

[https://github.com/microsoft/vscode/issues/275029](https://github.com/microsoft/vscode/issues/275029)

## Summary

Still reproducible on main: when the terminal panel is resized, `PromptInputModel._doSync` can extract the prompt prefix (shell indicator + cwd) into the `value` because `_commandStartMarker`/`_commandStartX` may not correctly track the command start position after buffer reflow. No fix has landed.

## Change summary

Terminal completion `context.commandLine` sometimes includes the shell indicator and working directory prefix (e.g. `PS C:\Code\vscode>`) when the panel is resized.

## Best solution

Fix the `PromptInputModel._doSync` method in `src/vs/platform/terminal/common/capabilities/commandDetection/promptInputModel.ts` to correctly recalculate the command start position after terminal reflow/resize, so the extracted `value` contains only the user-typed command text.

## Evidence

- **bug path in source:** In `src/vs/platform/terminal/common/capabilities/commandDetection/promptInputModel.ts`, `_doSync()` (line ~282) reads from `_commandStartMarker.line` at offset `_commandStartX`. After a terminal resize/reflow, these markers may not update correctly, causing the prompt text (e.g. `PS C:\Code\vscode>`) to be included in the extracted `commandLine` value.
- **no fix on main:** git log since the issue was filed shows no resize-related changes to promptInputModel.ts; only an unrelated `clearValue onCommandFinished` change (ace789bc8da).
- **related fix:** Commit 66717e67900 (PR #275585, fixes #275546) changed the suggest addon to pass `value` instead of `prefix` to completion providers, but that addressed a different issue — the underlying prompt model bug on resize remains.
