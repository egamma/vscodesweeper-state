# Issue #339843 — MCP resource URI templates incorrectly encode non-ASCII variable values

[https://github.com/microsoft/vscode/issues/339843](https://github.com/microsoft/vscode/issues/339843)

## Summary

Confirmed from source: `pctEncode` in uriTemplate.ts percent-encodes UTF-16 code units via `charCodeAt`, not UTF-8 bytes, so non-ASCII MCP resource template variable values are mis-encoded. A fixing PR is already open, so this stays open pending that PR's review/merge rather than a close.

## Change summary

UriTemplate.resolve() percent-encodes non-ASCII variable values as raw UTF-16 code units instead of UTF-8 bytes, producing URIs that fail decodeURIComponent or decode to the wrong characters.

## Best solution

Land the already-open fix (https://github.com/microsoft/vscode/pull/339846), which switches pctEncode to UTF-8 byte encoding and makes prefix expansion count code points instead of UTF-16 units; a maintainer should review and merge that PR.

## Evidence

- **source confirmation:** src/vs/base/common/uriTemplate.ts lines 289-305: `pctEncode` iterates `str.charCodeAt(i)` (UTF-16 code units) and emits `'%' + chr.toString(16)...padStart(2,'0')`; for code points above 0xFF this produces more than 2 hex digits per unit (e.g. '中' -> %4E2D), which is not valid percent-encoding and doesn't match RFC 6570's UTF-8 byte requirement.
