# Issue #91600 — [folding] pressing Enter in collapsed region should add new line outside region

[https://github.com/microsoft/vscode/issues/91600](https://github.com/microsoft/vscode/issues/91600)

## Summary

Keep this accepted folding request open: current editing commands still insert inside the collapsed region, and the existing settings do not provide insertion after it. The remaining product decision is whether Enter should change meaning at the header or users should explicitly navigate beyond the folded content first.

## Change summary

Allow inserting a new line after a collapsed region without expanding it or modifying its contents.

## Best solution

Provide an unambiguous keyboard workflow for inserting after the entire folded region while preserving its collapsed state. The editor owner should settle whether this changes plain Enter at the header or introduces an explicit outside-the-fold cursor position, preserving ordinary header editing.

- **Behavior:**

  > Users need a keyboard workflow that inserts a newline immediately after an entire collapsed region without opening it. In the reported TypeScript example, the resulting blank line must be between //#endregion and ZZZ, with the region contents and following line unchanged. Plain Enter currently edits at the end of the header inside the fold; the finished interaction must distinguish outside-region insertion from intentional header editing. Acceptance includes keeping the fold collapsed, avoiding unintended indentation changes to following content, and undoing the insertion normally.
- **Trace:**

  > EnterOperation.getEdits and _enter in src/vs/editor/common/cursor/cursorTypeEditOperations.ts operate on the current model selection, and lineInsertAfter uses the current model line's maximum column. InsertLineAfterAction in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts delegates directly to that operation, so its existing command is not an outside-fold insertion capability. CursorMoveOperations.moveToEndOfLine targets the current line end, while FoldingDecorationProvider renders the placeholder as an after-content decoration; the inspected code does not establish a second cursor position beyond it. FoldingController.revealCursor expands regions when the cursor is inside hidden content. The maintainer explanation in https://github.com/microsoft/vscode/issues/91600 agrees with these semantics; the uncertainty is the desired replacement interaction, not the existing behavior. Preserve editing inside folds and unrelated folding-provider behavior, and investigate https://github.com/microsoft/vscode/issues/72422 for overlapping selection requirements without assuming it owns this request.
- **Open decisions:**
  - Should plain Enter at the end of a collapsed header insert after the entire region, or should users explicitly move to an outside-the-fold position before Enter while header-end typing keeps its current meaning?
