# Issue #325546 — Integrated terminal requires manual restart on every VS Code startup

[https://github.com/microsoft/vscode/issues/325546](https://github.com/microsoft/vscode/issues/325546)

## Summary

The current behavior is by design: `terminal.integrated.environmentChangesRelaunch` deliberately excludes restored/reconnected terminals (the `attachPersistentProcess` guard at line 2335 of terminalInstance.ts) to avoid silently destroying session state. The reporter is effectively requesting that auto-relaunch also cover restored terminals on startup, which is a valid enhancement request.

## Change summary

Request to automatically relaunch restored terminals on VS Code startup when extensions need to contribute environment variables, instead of showing a manual restart warning.

## Best solution

Extend the auto-relaunch logic in `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts` (around line 2335) to also cover restored/reconnected terminals that have not been interacted with, or add a dedicated setting to opt into this behavior. The tradeoff is that restored terminals may lose scroll-back history on auto-relaunch, so an opt-in approach or a brief grace period before auto-relaunching may be preferable.
