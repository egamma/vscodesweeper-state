# Issue #123332 — integrated terminal assumes GNU bash is used as user shell, passes --login

[https://github.com/microsoft/vscode/issues/123332](https://github.com/microsoft/vscode/issues/123332)

## Summary

Current source no longer automatically adds --login to the mksh fallback profile, but the requested portable login-shell invocation remains unsupported. Keep this accepted terminal-profile request open; the upstream argv0 implementation candidate is still unmerged, and no verified canonical owns the remaining work.

## Change summary

Support portable Unix login-shell startup through a hyphen-prefixed argv[0] rather than assuming shell-specific login flags.

## Best solution

Provide portable login-shell semantics in Unix terminal profiles once node-pty supports overriding argv[0], preserving explicitly configured arguments and existing non-login launches. Coordinate with the existing upstream implementation candidate rather than treating removal of the mksh launch error as completion of the broader request.

## Evidence

- **Confirmed historical regression and remaining intent:** The discussion on https://github.com/microsoft/vscode/issues/123332 confirms Homebrew mksh worked in 1.55.2 and failed with an injected --login in 1.56.0. The reporter explicitly rejects merely substituting -l and requests hyphen-prefixed argv[0]; the maintainer supplied a custom-profile workaround, which the affected user confirmed restored launch.
- **Current fallback behavior:** src/vs/workbench/contrib/terminal/browser/terminalProfileResolverService.ts:237-274, _getUnresolvedFallbackDefaultProfile, first reuses a matching available profile and otherwise adds --login only on macOS when the executable name matches zsh or bash. The generated mksh fallback receives [], so the original blanket argument injection is not present on that path.
- **Existing capability is only partial coverage:** src/vs/platform/terminal/common/terminalPlatformConfiguration.ts:36-79 supports profile args and env but exposes no loginShell or argv0 property. Its macOS defaults at lines 287-304 use -l for bash, zsh and fish. terminal.integrated.profiles.osx and terminal.integrated.defaultProfile.osx therefore allow shell-specific workarounds, not the requested portable argv[0] semantics.
- **No adoption on terminal spawn path:** src/vs/platform/terminal/node/terminalProcess.ts constructs _ptyOptions at lines 161-177 without argv0, then setupPtyProcess at lines 307-316 passes the executable, argument array and options to node-pty.spawn. This code does not implement hyphen-prefixed argv[0] login-shell startup.
- **Upstream implementation remains open:** Verified https://github.com/microsoft/node-pty/issues/472 is open and https://github.com/microsoft/node-pty/pull/627 is open with mergedAt null. The PR proposes an optional argv0 field and references the upstream issue; it is an implementation candidate, not a landed fix.
