## Summary

The Windows process-task path still prefixes the working directory before command variables are expanded. Keep this issue open while the existing fixing PR is reviewed; shell-specific workarounds do not resolve the reported behavior.

## Change summary

Process tasks using a command variable for an absolute executable path incorrectly prepend the working directory on Windows.

Review and validate https://github.com/microsoft/vscode/pull/316369 against the reported Windows process-task scenario, preserving executable lookup for ordinary commands and shell-independent argument handling. Close this issue as completed only after an adequate fix lands.
