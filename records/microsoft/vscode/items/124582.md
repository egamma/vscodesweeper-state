# Issue #124582 — User forwarded port has the first request TTFB too high

[https://github.com/microsoft/vscode/issues/124582](https://github.com/microsoft/vscode/issues/124582)

## Summary

Keep open for investigation of forwarded-port connection latency: current source still performs remote connection negotiation before forwarding each new local connection, and no existing setting establishes that this cost is avoided. Independent reports and maintainer investigation support retaining the request; neither a verified fix nor an older canonical was found.

## Change summary

Reduce the initial response delay on user-forwarded ports, including requests made after an idle period.

## Best solution

Profile new-connection setup in the core tunnel and remote-agent connection paths against direct Docker or SSH forwarding, then reduce avoidable overhead while preserving authentication and arbitrary TCP behavior. Separate connection-establishment cost from application response time before choosing an optimization.
