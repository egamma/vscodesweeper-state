# Issue #124582 — User forwarded port has the first request TTFB too high

[https://github.com/microsoft/vscode/issues/124582](https://github.com/microsoft/vscode/issues/124582)

## Summary

Persistent port-forwarding latency complaint with recent (May 2025) confirmation — the idle-connection TTFB overhead remains unaddressed on main. On Deck milestone; keeping open as a valid, still-relevant request.

## Change summary

User-forwarded ports suffer high TTFB (~300–650 ms) on the first request and after short idle periods, because the tunnel connection is set up on demand rather than kept warm.

## Best solution

Investigate keeping the tunnel connection warm (or pre-establishing it) in the tunnel service layer (`src/vs/platform/tunnel/node/tunnelService.ts`, `src/vs/platform/remote/common/remoteAgentConnection.ts`) so that forwarded-port requests don't pay the full connection-setup cost after idle periods. The latency was traced by a team member to `connectToRemoteExtensionHostAgent` — a keep-alive or connection-pooling approach in that path would address the core complaint.
