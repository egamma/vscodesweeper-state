# Issue #124582 — User forwarded port has the first request TTFB too high

[https://github.com/microsoft/vscode/issues/124582](https://github.com/microsoft/vscode/issues/124582)

## Summary

The high TTFB on forwarded ports after idle is still present on current main — the tunnel connection path (`doConnectRemoteAgentTunnel` in `remoteAgentConnection.ts`) performs a full protocol handshake on each new connection. No fix commit references this issue, and the On Deck milestone indicates accepted-but-unscheduled work. Multiple users continue to confirm the behavior through 2025.

## Change summary

User-forwarded ports in remote scenarios have high TTFB (~300-650ms) on first request and after brief idle periods due to the full protocol handshake being re-established.

## Best solution

Investigate connection pooling or keep-alive for tunnel connections in `src/vs/platform/remote/common/remoteAgentConnection.ts` (`doConnectRemoteAgentTunnel`) to avoid the full handshake on each idle-to-active transition. The related `microsoft/vscode-remote-release#5703` was closed but the core issue persists — the tunnel service layer may need to maintain warm connections for user-forwarded ports.
