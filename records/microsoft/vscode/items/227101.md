- **Existing capability and boundary:** src/vs/editor/browser/gpu/raster/glyphRasterizer.ts selects subpixel antialiasing outside macOS, creates an opaque rasterization context, fills the token-metadata background before drawing, and clears exact background-colored pixels afterward. Its background comes from TokenMetadata.getBackground and the color map, not find or diff decoration backgrounds; the file also explicitly leaves workbench.fontAliasing support as a TODO.
- **Partial implementation:** Merged https://github.com/microsoft/vscode/pull/238173, merge commit 9ce979b017541101a918a948aec1f0cd34379c14, describes itself as part of this issue and explicitly states that decoration-applied colors such as find are not supported.
- **Owner's remaining scope:** https://github.com/microsoft/vscode/issues/227101#issuecomment-2604796311 lists correct find-decoration backgrounds and diff-editor rendering as remaining work. In https://github.com/microsoft/vscode/issues/238289#issuecomment-2604797905, the owner consolidated the highlighted-text blur report into this issue rather than declaring it fixed.
- **Current decoration support:** src/vs/editor/browser/gpu/viewGpuContext.ts lists supported decoration CSS properties but does not include background-color. This supports a remaining integration gap, not a claim that every historical rendering symptom still reproduces.

Neither warrants replacing this protected item with a duplicate close.
