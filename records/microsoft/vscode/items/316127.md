# Issue #316127 — Copilot chat doesn't work over remotes

[https://github.com/microsoft/vscode/issues/316127](https://github.com/microsoft/vscode/issues/316127)

## Summary

Team-authored bug report about Copilot chat hanging over remotes. The reporter narrowed it to a specific chat session (new sessions work), and the logs show a `getRepositoryFetchUrls` error where an `output:` scheme URI is incorrectly passed to the filesystem provider. No fix has landed on main. Keeping open — the underlying URI-handling bug in the git service path is real, and the session-specific hang may be a separate issue.

## Change summary

Copilot chat hangs indefinitely over SSH/devcontainer remotes; logs show `getRepositoryFetchUrls` failing because an `output:` channel URI is passed as a file path.

## Best solution

Investigate the `getRepositoryFetchUrls` call site that passes an `output:` scheme URI (likely from `remoteContentExclusion.ts` or a tool invocation that resolves the active editor URI without filtering non-file schemes). The git service fallback path at `gitServiceImpl.ts:227` calls `URI.file(path.join(...))` on the result of `getRepositoryRoot`, which may also mishandle non-`file` scheme URIs. A guard to reject non-`file` URIs early in `getRepositoryFetchUrls` would prevent the error. The session-specific hang (comment 4) may be a separate conversation-state corruption issue worth investigating independently.
