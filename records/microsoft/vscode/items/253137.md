[https://github.com/microsoft/vscode/issues/253137](https://github.com/microsoft/vscode/issues/253137)

## Summary

Keep this meta issue open: current reports confirm that “Language model unavailable” remains a generic symptom for several distinct model-discovery failures, and no older issue with the same observable symptom supersedes this collector. The issue was reopened after an earlier fix proved insufficient and continues to receive current diagnostic evidence.

## Change summary

Copilot Chat can fail to resolve any usable language model and presents the generic “Language model unavailable” error for network, service, account, configuration, and model-routing failures.

## Best solution

Retain this as the canonical diagnostic meta issue while improving model-discovery error reporting so users can distinguish service outages, blocked endpoints, authentication or entitlement failures, invalid debug overrides, and an empty model list. Root-cause-specific defects should be fixed and tracked separately without closing the collector while the generic failure remains current.

- **recent reproduction:** A current VS Code 1.139.1 report at https://github.com/microsoft/vscode/issues/253137#issuecomment-3534894698 recorded model-fetch failures and the same UI error; the follow-up isolated stale `overrideProxyUrl` and `overrideCapiUrl` settings, demonstrating that the generic symptom remains reproducible even though that individual configuration was corrected.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/253136 tracks failures after a chat request is submitted (“Sorry, your request failed”), not the same pre-request model-unavailability symptom.
