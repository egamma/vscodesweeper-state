# Issue #332694 — Agent host: restoring multi-root sessions can fan out Git work until probes time out

[https://github.com/microsoft/vscode/issues/332694](https://github.com/microsoft/vscode/issues/332694)

## Summary

Team-authored (COLLABORATOR), well-diagnosed, unresolved performance bug filed 0 days ago with no fix yet — must stay open regardless of how convincing the analysis is; author-defined intent is protected here and there's no fix commit referencing this issue to justify a close.

## Change summary

Each restored multi-root session's `_updateMultiFolderChangesSummary` allocates its own fresh `Limiter(5)`, so concurrent session restores can fan out far more than 5 simultaneous Git processes, causing background branch-summary probes to hit the 5-second timeout and silently skip repositories.

## Best solution

Introduce a process/service-wide concurrency budget (or gate on-demand computation) shared across all `_updateMultiFolderChangesSummary` invocations and the primary-repository diff limiter, rather than a fresh per-call `Limiter(5)`; this is a design decision among the three options the reporter lists (shared budget, deferred computation, or a different timeout policy for background work) and belongs to a maintainer, not an automated fix.
