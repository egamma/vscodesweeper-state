# Issue #333204 — `Repository.setConfig()` in the built-in Git extension always uses `git config --add`, causing unbounded duplicate branch config entries

[https://github.com/microsoft/vscode/issues/333204](https://github.com/microsoft/vscode/issues/333204)

## Summary

Confirmed on current main: `Repository.setConfig()` in extensions/git/src/repository.ts unconditionally calls `git config add local <key> <value>`, so every call appends a new line instead of replacing the existing one — exactly as described. This is a real, narrow core bug worth fixing.

## Change summary

The built-in Git extension's `Repository.setConfig()` API always uses `git config --add`, so repeated calls (e.g. from the GitHub Pull Requests extension re-associating a branch with its PR) accumulate unbounded duplicate config lines instead of overwriting the value.

## Best solution

Change `setConfig` in extensions/git/src/repository.ts (line ~1146-1148) to use `git config --replace-all` instead of `--add` (git's `--replace-all` creates the entry if absent and replaces it if present, matching the documented 'set' semantics), fixing the root cause for all consumers of this API including the GitHub Pull Requests extension.
