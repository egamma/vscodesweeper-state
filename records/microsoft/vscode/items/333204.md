# Issue #333204 — `Repository.setConfig()` in the built-in Git extension always uses `git config --add`, causing unbounded duplicate branch config entries

[https://github.com/microsoft/vscode/issues/333204](https://github.com/microsoft/vscode/issues/333204)

## Summary

Confirmed on current main: `Repository.setConfig()` in the built-in Git extension always shells out to `git config --add local <key> <value>` with no existing-value check, so any caller (e.g. the GitHub Pull Requests extension writing `branch.<name>.github-pr-owner-number` on every activation/branch-switch) accumulates unbounded duplicate config lines instead of replacing the value.

## Change summary

`Repository.setConfig()` in the built-in Git extension always uses `git config --add`, causing unbounded duplicate branch config entries across extension-host reactivations.

## Best solution

Change `setConfig()` in extensions/git/src/repository.ts (line 1148-1150) to use `git config --replace-all` instead of `--add` (the `config()` helper in extensions/git/src/git.ts already builds the `--${command}` flag generically, so passing `'replace-all'` works without other changes); the two existing internal callers (mergeBaseConfigKey at lines 1795/1802) are already single-value semantics and unaffected.

  > Repository.setConfig(key, value) in extensions/git/src/repository.ts (around line 1148) calls `this.repository.config('add', 'local', key, value)`, which always runs `git config --add --local <key> <value>` (see the generic arg-builder in extensions/git/src/git.ts's `config(command, scope, key, value)` method, ~line 1403, which already supports any `--<command>` flag). Because it's an unconditional append rather than a set/overwrite, any repeated call for the same key (e.g. the GitHub Pull Requests extension re-writing `branch.<name>.github-pr-owner-number` on every extension-host reactivation) appends a new duplicate line instead of replacing the existing one, and duplicates make a later plain `git config --unset` fail with exit code 5 (multiple values), permanently stranding stale data. Fix by changing the `config('add', ...)` call in `setConfig()` to `config('replace-all', ...)` (git's `--replace-all` sets the given key to the given value, replacing all existing lines, or creates it if none exist — this preserves the intended 'set' semantics without needing a separate existing-value check).
