## Plan brief

- **Likely files:** `extensions/github/src/auth.ts`, `extensions/github/src/remoteSourceProvider.ts`, `extensions/git-base/src/remoteSource.ts`
- **Validation:** In a disposable VS Code profile, populate Clone from GitHub with a valid session, invalidate that session's token, and reopen repository discovery. Confirm authentication can be renewed and repositories become selectable without deleting stored state; also check cancellation and ordinary network failures do not produce repeated sign-in prompts. Diagnose organization SSO authorization failures separately rather than assuming they behave like invalid tokens.
- **Behavior:**

  > When credentials previously used by Clone from GitHub become invalid, repository discovery currently ends at a Bad credentials error. Users should have a supported way to restore repository discovery without editing or deleting globalStorage. Acceptance should cover renewed authentication, successful repository selection afterward, cancellation, and non-authentication failures. The exact SAML scenario needs confirmation before claiming that token renewal resolves it.
- **Trace:**

  > GithubRemoteSourceProvider.getRemoteSources in extensions/github/src/remoteSourceProvider.ts uses getOctokit from extensions/github/src/auth.ts. That helper retains a REST client after successful acquisition; later request failures do not invalidate it, and the neighboring OctokitService session-change handling applies only to its GraphQL client. With an empty repository query, getUserRemoteSources calls users.getAuthenticated followed by repos.listForAuthenticatedUser, and RemoteSourceProviderQuickPick.query in extensions/git-base/src/remoteSource.ts displays the resulting error without a recovery action. This establishes the error propagation and cache lifetime, not the author's hypothesized SAML-session limit. Preserve unrelated provider behavior, repository search semantics, and user cancellation; do not adopt the thread's destructive storage-reset workaround. https://github.com/microsoft/vscode/issues/104008 concerns a related but distinct session-notification contract.
