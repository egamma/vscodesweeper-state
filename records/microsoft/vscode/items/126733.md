# Issue #126733 — [css] Color picker for css variables

[https://github.com/microsoft/vscode/issues/126733](https://github.com/microsoft/vscode/issues/126733)

## Summary

The capability remains missing: current CSS document-color evaluation handles literal numeric components but not `var(...)` references. The issue is already correctly routed and accepted in the Backlog, while the unresolved lookup and editing semantics require design work rather than closure.

## Change summary

Show a color preview and picker for CSS color functions whose components contain custom-property references.

## Best solution

Extend `vscode-css-languageservice` document-color evaluation to resolve safe, unambiguous CSS custom-property values, while defining how the picker behaves when variables are scoped, cross-file, cyclic, or ambiguous and whether editing replaces the composed expression.

## Evidence

- **current VS Code path:** extensions/css-language-features/server/src/cssServer.ts delegates `textDocument/documentColor` directly to `vscode-css-languageservice` through `findDocumentColors`; VS Code has no separate CSS-variable color resolution layer.
- **current language-service limitation:** Current `vscode-css-languageservice` `src/services/cssNavigation.ts` visits syntax nodes and calls `getColorInformation`, while `src/languageFacts/colors.ts#getColorValue` requires numeric RGB/HSL/HWB components; a `var(...)` argument fails numeric evaluation and returns no color.
- **test coverage:** Current `vscode-css-languageservice` `src/test/css/navigation.test.ts` document-color tests cover literal hex, RGB, HSL, RGBA, and HWB values, but no custom-property substitution.
- **open design questions:** The maintainer comment at https://github.com/microsoft/vscode/issues/126733#issuecomment-865159361 identifies unresolved variable lookup and picker-edit semantics; the reporter suggests a read-only presentation at https://github.com/microsoft/vscode/issues/126733#issuecomment-865192147.
