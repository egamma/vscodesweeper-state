# Issue #326445 — workbench.colorCustomizations stop working after update to V1.130

[https://github.com/microsoft/vscode/issues/326445](https://github.com/microsoft/vscode/issues/326445)

## Summary

Verified on current main: the Modern UI floating-panels CSS still forces `background-color`/`border-color: transparent !important` on the activity bar, status bar, and title bar, which wins over the inline colors ActivitybarPart/etc. compute from `workbench.colorCustomizations` and color themes. This is a real, still-open regression with an active maintainer design discussion and no fix yet.

## Change summary

workbench.colorCustomizations (and theme colors) for the activity bar, status bar, and title bar backgrounds/borders stopped applying once `workbench.experimental.modernUI` shipped enabled by default in 1.130/1.131.

## Best solution

In src/vs/workbench/browser/media/floatingPanels.css, the transparent background/border rule for `.part.activitybar/.statusbar/.titlebar` should only apply when no explicit color override is set, e.g. by dropping `!important` (or scoping it to unset inline colors) so an inline color set by ActivitybarPart.updateStyles()/statusbar/titlebar equivalents can win, matching the pre-1.130 behavior when a customization exists. aeschli's request for themes to opt in/out of Modern UI styling on https://github.com/microsoft/vscode/issues/326445#issuecomment (2026-07-21) suggests the team wants a deliberate mechanism rather than a quick patch, so this needs a maintainer decision on approach before implementation.
