# Issue #292577 — Experimental: Keybinding Action Confirmation & ARIA Announcement System (opt-in)

[https://github.com/microsoft/vscode/issues/292577](https://github.com/microsoft/vscode/issues/292577)

## Summary

Keep open for design discussion: generic shortcut-completion announcements remain missing, and a maintainer supported exploring standardized confirmations rather than custom messages. The Backlog milestone and that direction rule out declining the request merely because it has no upvotes.

## Change summary

Provide opt-in spoken confirmation when keyboard shortcuts successfully execute, with controls to prevent excessive or duplicate announcements.

## Best solution

Define a standardized, localized completion-announcement contract in the keybinding/accessibility path, following the maintainer's preference against custom messages. Settle whether confirmations include the action title and how users select eligible shortcuts before implementing the experiment.

Manually verify with a screen reader that an opted-in shortcut announces once after completion, failed execution produces no success confirmation, and existing feature-specific feedback is preserved.
- **Behavior:**

  > Keyboard shortcuts that currently finish silently should offer optional spoken completion feedback without changing their action or dispatch behavior. The maintainer-supported direction uses standardized localized confirmations, not user-authored announcement text. The experiment must remain disabled by default and avoid redundant speech alongside existing feedback. Acceptance checks must distinguish successful asynchronous completion from invocation and failure; the final message and eligibility contract require maintainer agreement.
- **Trace:**

  > KeybindingsJsonSchema in src/vs/workbench/services/keybinding/browser/keybindingService.ts and KeybindingIO.readUserKeybindingItem in src/vs/workbench/services/keybinding/common/keybindingIO.ts expose no announcement metadata. AbstractKeybindingService's KbFound branch in src/vs/platform/keybinding/common/abstractKeybindingService.ts executes the resolved command and reports rejection, but supplies no generic completion feedback. CommandService._tryExecuteCommand fires onDidExecuteCommand immediately after the handler returns, before an asynchronous result settles, so invocation observation is not proof of successful completion. Existing AccessibilitySignal announcements cover specific events, and accessibility.verbosity.keybindingsEditor covers help hints rather than shortcut results. Preserve command return/error semantics, keybinding resolution and existing announcements; double-press dispatch in https://github.com/microsoft/vscode/issues/292578 is separate work. The maintainer comment in https://github.com/microsoft/vscode/issues/292577 excludes custom messages but leaves standardized wording and eligibility unresolved.
- **Open decisions:**
  - Should standardized confirmations announce only "completed", or include the localized action title, and should that distinction be user-configurable?
  - Should opting in enable confirmation for all eligible shortcuts, or require per-binding selection, particularly for frequent editing and navigation actions?
