# Issue #250604 — Consider to accept/keep changes on subsequent requests

[https://github.com/microsoft/vscode/issues/250604](https://github.com/microsoft/vscode/issues/250604)

## Summary

This is an active design discussion about the granularity of undo/reject in the Copilot Edits flow — specifically how manual edits made between AI requests interact with the undo mechanism. The checkpoint system has been significantly built out since filing, and related issue #265794 was closed as completed, but the broader question remains open with ongoing reports (e.g. #284873). The team placed this on 'On Deck' and labeled it 'under-discussion', indicating continued consideration.

## Change summary

Rejecting/undoing a Copilot Edit request reverts the file past manual edits made between AI requests, effectively losing work that was never part of the AI's changes.

## Best solution

The checkpoint timeline infrastructure (`chatEditingCheckpointTimelineImpl.ts`) now exists and supports per-request snapshots. The remaining design question is whether manual edits between AI requests should automatically create implicit checkpoints or be preserved through the undo flow. This issue serves as the discussion hub alongside related open issues #284873 (undo reverts committed changes) and #282069 (checkpoint behavior for added/deleted files). A maintainer decision on the undo semantics for interleaved manual + AI edits is needed.
