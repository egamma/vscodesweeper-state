# Issue #250604 — Consider to accept/keep changes on subsequent requests

[https://github.com/microsoft/vscode/issues/250604](https://github.com/microsoft/vscode/issues/250604)

## Summary

Keep open: request checkpoints now exist, but they do not automatically advance the Keep/Undo baseline when another request starts. The maintainer explicitly identified this issue as tracking that behavior, and neither related closed report establishes that it was delivered.

## Change summary

Treat a subsequent editing request as keeping preceding changes so rejecting the new edits does not discard earlier work.

## Best solution

Make subsequent requests establish the accepted baseline described by the maintainer, while retaining explicit checkpoint restoration for earlier turns. Preserve intervening manual edits and distinguish latest-request rejection from intentionally restoring an older checkpoint.
