# Issue #299383 — Copilot: Support firewalled or airgapped remote machines via SSH

[https://github.com/microsoft/vscode/issues/299383](https://github.com/microsoft/vscode/issues/299383)

## Summary

Legitimate feature request to route LLM/Copilot requests through the local machine when the remote SSH host is firewalled or airgapped. Already triaged to Backlog with 9 upvotes; no existing implementation on main covers this scenario. The comments also surface a related but distinct path-handling bug (Linux paths treated as Windows paths in Agent mode over Remote-SSH) that is tracked separately.

## Change summary

Request to route Copilot/LLM API requests through the local VS Code client when the remote SSH workspace has no internet access, enabling full AI-assisted development on firewalled machines.

## Best solution

Implement a mechanism so that when Copilot Agent mode operates on a Remote-SSH workspace, LLM API calls and tool invocations route through the local (internet-connected) client rather than the remote host, while file operations still target the remote filesystem. The path-handling bug described in comments (Linux vs Windows paths in Agent mode over SSH) overlaps with https://github.com/microsoft/vscode/issues/284417 and https://github.com/microsoft/vscode/issues/303402 and should be resolved in those issues or consolidated here if they share root cause.
