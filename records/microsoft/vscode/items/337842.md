# Issue #337842 — Agent Customizations hides MCP Servers for remote agent hosts

[https://github.com/microsoft/vscode/issues/337842](https://github.com/microsoft/vscode/issues/337842)

## Summary

Confirmed on main: `createRemoteAgentHarnessDescriptor` explicitly hides the MCP Servers section for remote agent hosts. The report is well-diagnosed and correctly labeled bug/agents-window; keeping open for design + implementation.

## Change summary

Opening Agent Customizations for a remote agent host hides the MCP Servers section entirely instead of showing it (with management or an explanation).

## Best solution

Decide (with the AI Customization / Agents Window owners) whether remote MCP servers get full read/manage support via the existing itemProvider/syncProvider plumbing, or a read-only view with an explanatory empty state, then remove `AICustomizationManagementSection.McpServers` from the `hiddenSections` list in remoteAgentHostCustomizationHarness.ts accordingly.

- **Trace:**

  > The section is hidden by `createRemoteAgentHarnessDescriptor` in src/vs/workbench/contrib/chat/browser/remoteAgentHost/remoteAgentHostCustomizationHarness.ts (lines 146-149), which lists `AICustomizationManagementSection.McpServers` in `hiddenSections` alongside `Models`. `hiddenSections` is consumed by aiCustomizationManagementEditor.ts (~line 879) and customizationsToolbar.contribution.ts to filter the sidebar/menu. The harness's `itemProvider` (AgentCustomizationItemProvider, constructed in remoteAgentHostChatContribution.ts ~line 392) is seeded from `ambientScope.customizations` (via `_activeClientService.acquireScope`), which may or may not already surface MCP-type items from the remote client — that needs checking. The only customization-type-specific action wiring in the harness today is for CustomizationType.Plugin (RemoteAgentPluginController.addConfiguredPlugin/removeConfiguredPlugin); there is no analogous MCP server add/remove path, so it's unclear whether unhiding the section alone would show usable data or an empty list.
- **Open decisions:**
  - Should remote agent hosts get full MCP server add/remove management (requiring new sync/action plumbing analogous to RemoteAgentPluginController), or a read-only listing of the remote target's configured MCP servers?
  - For remote targets that genuinely cannot support MCP management, what should the explanatory empty-state message say, and should any remediation action (e.g. a link to configure MCP another way) be offered?
  - Does unhiding the section change any existing telemetry/menu `when`-clause expectations tied to `hiddenSections` for remote harnesses (see customizationsToolbar.contribution.ts)?
