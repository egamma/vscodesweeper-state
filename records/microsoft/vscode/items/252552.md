# Issue #252552 — Support human facing comments in custom chat mode files

[https://github.com/microsoft/vscode/issues/252552](https://github.com/microsoft/vscode/issues/252552)

## Summary

Keep open: this team-authored Backlog request identifies a still-relevant authoring gap, and the discussion has not settled whether richer reader-facing guidance belongs in `description`, a dedicated frontmatter field, or non-prompt Markdown comments.

## Change summary

Allow custom chat mode authors to include human-facing usage and customization guidance that is not sent to the language model.

## Best solution

Define one consistent customization-file mechanism for human-facing documentation, preferably reusable across prompt, instruction, agent, and related Markdown formats, with clear stripping and editor-preview semantics before implementation.

## Plan brief

- **Likely files:** `extensions/copilot/src/customization/common/instructionsService.ts`, `extensions/copilot/src/customization/common/customizationService.ts`
- **Validation:** Add parser and serialization tests proving the chosen human-facing guidance is available to readers where intended, survives file editing, and is excluded from the instruction text sent to the language model.
- **Behavior:**

  > Custom chat mode authors can add usage and customization guidance intended for people without that guidance becoming model instructions. Existing mode files continue to parse unchanged. Acceptance must verify where the guidance is visible to users, that it survives normal editing, and that the model receives only the metadata and prompt content intended for it.
- **Trace:**

  > The issue distinguishes frontmatter consumed by VS Code from Markdown instructions sent to the model, and asks for a third, human-only channel. The discussion establishes that `description` is currently shown when selecting the mode, while earlier instruction handling reportedly stripped comments, but it does not settle whether that behavior should return or whether a dedicated metadata property should be introduced. Trace the customization parsing and prompt-construction paths under extensions/copilot/src/customization/common, and keep backward compatibility across existing custom mode files. Do not let human-only text enter model context or silently change the current meaning of `description`.
- **Open decisions:**
  - Should human-facing guidance use a dedicated frontmatter property, stripped Markdown comments, or the existing `description` field?
  - Should the guidance appear only in the source file, or also in mode-selection and customization UI?
