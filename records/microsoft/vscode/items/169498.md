# Issue #169498 — Debug output collapsing and expading

[https://github.com/microsoft/vscode/issues/169498](https://github.com/microsoft/vscode/issues/169498)

## Summary

This remains a valid backlog feature request with 33 community upvotes. Current VS Code supports collapsible groups supplied explicitly by a debug adapter, but it does not provide the requested general-purpose folding of ordinary debug output.

## Change summary

Allow verbose log entries or output regions in the Debug Console to be collapsed and expanded for readability.

## Best solution

Define a Debug Console folding model for ordinary output that complements existing DAP-supplied groups, with clear boundaries and predictable initial expansion behavior. The design should avoid inferring unreliable groups from arbitrary text unless that heuristic is explicitly chosen.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/common/replModel.ts`, `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/browser/replViewer.ts`, `src/vs/workbench/contrib/debug/test/browser/repl.test.ts`
- **Validation:** Extend the Debug REPL tests to create representative multiline or grouped output, verify the selected folding unit starts in the decided state, can be toggled without losing content, and leaves existing DAP `start`/`startCollapsed`/`end` group behavior unchanged.
- **Behavior:**

  > Verbose output in the Debug Console can be collapsed into a readable summary and expanded again without losing or reordering content. Existing expandable variables and debug-adapter-provided console groups continue to behave as they do today. Acceptance must cover the chosen output boundary, initial expansion state, toggle behavior, nested or adjacent output, and copying/filtering of the underlying content.
- **Trace:**

  > Ordinary DAP output flows through DebugSession in src/vs/workbench/contrib/debug/browser/debugSession.ts into ReplModel.appendToRepl in src/vs/workbench/contrib/debug/common/replModel.ts, where it becomes a leaf ReplOutputElement. ReplGroup already supplies collapsible tree children for adapters that emit OutputEvent.group values, and Repl.refreshScheduler in src/vs/workbench/contrib/debug/browser/repl.ts honors each group's requested initial state. ReplViewer renders ordinary output and groups through separate renderers. The gap is therefore ordinary output without adapter-authored group boundaries; existing DAP group semantics, expression expansion, output ordering, filtering, and copy behavior must not regress. https://github.com/microsoft/vscode/issues/34981 documents the existing semantic-group capability, while https://github.com/microsoft/vscode/issues/38109 covers the distinct Collapse All action.
- **Open decisions:**
  - What is the user-visible folding unit: each multiline OutputEvent, a user-selected range, or automatically detected adjacent log records?
  - Should newly foldable output start expanded or collapsed, and should that state be configurable or remembered?
  - Should folding remain available for output inside existing DAP groups, and if so, how should nested controls be presented without ambiguity?
