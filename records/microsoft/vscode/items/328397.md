# Issue #328397 — Remote agent host is provisioned over SSH regardless of opt-out (the #326902 fix does not reach the CLI)

[https://github.com/microsoft/vscode/issues/328397](https://github.com/microsoft/vscode/issues/328397)

## Summary

The opt-out gap remains in current source: serving an editor connection still starts the remote supervisor without consulting client enablement, and supervisor startup eagerly downloads a server. Startup is now lazy until a serve request arrives, but that does not prevent provisioning during the reported Remote-SSH connection.

## Change summary

Honor client AI opt-out before ordinary Remote-SSH connections provision a remote agent-host supervisor and its server.

## Best solution

Carry effective client disablement into the CLI's editor-serving path so opted-out Remote-SSH connections remain fully functional without initiating agent-host provisioning or update polling. Coordinate the CLI contract with Remote-SSH while preserving explicitly requested agent-host sessions.
