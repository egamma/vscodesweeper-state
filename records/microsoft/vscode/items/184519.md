# Issue #184519 — Can't resolve conflict of submodule checksum file

[https://github.com/microsoft/vscode/issues/184519](https://github.com/microsoft/vscode/issues/184519)

## Summary

Still valid on main: submodule merge conflicts cannot be resolved through the VS Code UI because the conflict-resolution code (`categorizeResourceByResolution`) greps for text conflict markers in the file, but submodule entries are gitlinks (commit SHA pointers), not text files — so the merge editor shows 0 conflicts and staging/accept actions don't work. A recent commenter confirms the issue persists in 1.128.0.

## Change summary

Submodule merge conflicts cannot be resolved in VS Code — accept current/incoming/stage actions and the merge editor all fail to handle the gitlink conflict format.

## Best solution

The git extension's merge conflict handling in `extensions/git/src/commands.ts` (specifically `categorizeResourceByResolution` around line 395) and the staging logic need to detect submodule entries (gitlinks) and offer appropriate resolution — likely `git checkout --theirs`/`--ours` followed by `git add` for the submodule path, bypassing the text-based merge editor entirely. This is a gap in the built-in git extension, not an extension-candidate item.
