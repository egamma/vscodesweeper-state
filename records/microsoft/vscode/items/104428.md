# Issue #104428 — Support touch scrolling

[https://github.com/microsoft/vscode/issues/104428](https://github.com/microsoft/vscode/issues/104428)

## Summary

A real Linux/Wayland touch-input gap remains on current main. This issue is the established canonical report and should remain open in the Backlog.

## Change summary

Enable touch-drag scrolling in the editor on Linux/Wayland without requiring the `--touch-events` switch.

## Best solution

Enable reliable touch events for Linux desktop or safely extend the editor's pointer-event path beyond phones, while checking the desktop regression that caused pointer handling to be restricted in commit 57c5c8801d7dc8f41af17c16ac07efd077abfbcc.

## Evidence

- **current source:** src/vs/editor/browser/controller/pointerHandler.ts uses PointerEventHandler only on phones; desktop falls back to TouchHandler only when `mainWindow.TouchEvent` exists.
- **touch dependency:** src/vs/base/browser/touch.ts implements scrolling from `touchstart`, `touchmove`, and `touchend`, so absent browser touch events prevent that path from operating.
- **confirmed workaround:** The issue discussion and https://github.com/microsoft/vscode/issues/98218#issuecomment-1631251531 report that launching with `--touch-events` restores touch scrolling on Linux.
- **canonical status:** A maintainer closed https://github.com/microsoft/vscode/issues/187408 as a duplicate of this issue, while the broader Android report https://github.com/microsoft/vscode/issues/313494 identifies this as one of the component-level tracking issues.
