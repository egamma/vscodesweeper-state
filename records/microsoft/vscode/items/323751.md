# Issue #323751 — Copilot agent session worktree creation silently fails when repository is in detached HEAD state

[https://github.com/microsoft/vscode/issues/323751](https://github.com/microsoft/vscode/issues/323751)

## Summary

The successful-worktree discard is still present on current main: detached HEAD fails an unconditional branch-name guard and causes the session to proceed without isolation. Keep this open; the older detached-HEAD report describes a different failure, and branchless session metadata needs a defined contract before the full fix.

## Change summary

Allow Copilot CLI sessions to use successfully created worktrees when the source repository has detached HEAD, rather than falling back to the source workspace.

## Best solution

Retain successful worktree creation independently of whether the source HEAD names a branch, honoring an explicit base branch when supplied. For branchless starts, preserve the commit-based baseline and define how target-branch-dependent actions behave without inventing an arbitrary branch.
