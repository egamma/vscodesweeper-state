[https://github.com/microsoft/vscode/issues/249371](https://github.com/microsoft/vscode/issues/249371)

Keep open: current source still allows slight pointer movement over selected text to cancel Ctrl+Click navigation. The linked implementation candidate remains open and should be reviewed before considering this resolved.

## Evidence

- **Confirmed source path:** In src/vs/editor/browser/controller/mouseHandler.ts, MouseDownOperation.start enters drag-and-drop tracking when a single click lands inside a nonempty selection. _onMouseDownThenMove emits mouseDrag without requiring movement to another text position. In src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts, the onMouseDrag subscription unconditionally calls _resetHandler(), clearing _hasTriggerKeyOnMouseDown and preventing _onEditorMouseUp from firing onExecute for Ctrl+Click.
- **Navigation consequence:** src/vs/editor/contrib/gotoSymbol/browser/link/goToDefinitionAtPosition.ts subscribes to ClickLinkGesture.onExecute to invoke gotoDefinition. Cancelling the gesture therefore explains why mouse navigation fails while F12 and context-menu navigation remain available.
- **Discussion confirms trigger:** The discussion at https://github.com/microsoft/vscode/issues/249371 includes RedCMD's independent timing-dependent reproduction on 2025-05-22. The reporter's 2025-10-06 follow-up identifies the conflict between Ctrl+Click navigation and Ctrl+drag copying; selection through Find also triggers the reported problem.
- **Open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/316839 is OPEN with no merge commit. Its description explicitly addresses this selected-text navigation failure by distinguishing incidental pointer movement from dragging. This is pending work, not evidence of a landed fix.
- **Canonical search:** Open-issue searches for Ctrl/selection/definition and selected-symbol navigation found no verified canonical for this symptom. https://github.com/microsoft/vscode/issues/34354 was inspected: it requests Ctrl+drag whole-word selection, rather than reporting failed definition navigation on an existing selection, so it does not satisfy the re-reviewed-item duplicate bar.
- **Unrelated workaround:** The Python languageServer workaround in the discussion at https://github.com/microsoft/vscode/issues/249371 addresses a commenter whose F12 and context-menu navigation also failed. It does not explain the reporter's cross-language, selection-dependent mouse-only failure.
