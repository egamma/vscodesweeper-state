# Issue #349821 — Confusing mental model of session tabs

[https://github.com/microsoft/vscode/issues/349821](https://github.com/microsoft/vscode/issues/349821)

## Summary

Keep open for a chat-area interaction decision: closing the visible chat intentionally reveals another, but the default single-title presentation obscures that model. This team-authored feedback is not grounds for a judgment close, and no verified fix or duplicate was found.

## Change summary

Make chat-area closing behavior and opening chats side by side understandable without an invisible-tab mental model.

## Best solution

Agree on a consistent, discoverable chat-area model that makes both Close and side-by-side opening predictable. Evaluate the existing multiple-tab presentation before adding another mechanism.

- **Behavior:**

Users should be able to predict whether Close dismisses the area or the current chat, and discover how to arrange two chats beside each other. Acceptance should cover multiple open chats, the last chat, the new-session composer, and keyboard closing under the agreed design.
- **Trace:**

  > The referenced test plan explicitly specifies the observed close sequence, so this is interaction-design feedback rather than a confirmed correctness defect. registerAgentsChatPartActions separates closing a chat from hiding Parts.CHAT_PART; AgentsChatPart._didCloseTab supplies the next composer after the final chat closes in Single mode. Preserve session contents and the separate editor-area workflow; the unresolved boundary is the chat area's user-visible presentation and close semantics. https://github.com/microsoft/vscode/issues/291017 concerns a different welcome-to-chat transition and does not absorb this work.
- **Open decisions:**
