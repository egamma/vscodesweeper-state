# Issue #148064 — Report Issue should warn on outdated VS Code / Extension

[https://github.com/microsoft/vscode/issues/148064](https://github.com/microsoft/vscode/issues/148064)

## Summary

The reporter now warns when a VS Code update is available, but the requested extension-version warning remains missing. Keep this team-authored Backlog request open for the remaining scope; the existing implementation does not establish completion.

## Change summary

Warn users about outdated VS Code or extensions before they submit an issue through Report Issue.

## Best solution

Preserve the existing VS Code update banner and extend the issue-reporting flow with actionable extension-update guidance. Settle whether that guidance concerns only the reported extension or all enabled extensions before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/issue/common/issue.ts`, `src/vs/workbench/contrib/issue/electron-browser/issueService.ts`, `src/vs/workbench/contrib/issue/browser/issueService.ts`, `src/vs/workbench/contrib/issue/browser/issueReporterOverlay.ts`, `src/vs/workbench/contrib/issue/electron-browser/issueReporterEditorPane.ts`, `src/vs/workbench/contrib/issue/test/browser/issueReporterOverlay.test.ts`
- **Validation:** Extend issueReporterOverlay.test.ts to exercise current and outdated extension selections under the agreed scope, including unavailable update information and switching between extensions. Verify that the existing VS Code update banner remains independent and that the agreed reporting behavior is preserved when no extension update is known.
- **Behavior:**

  > Report Issue should help users recognize outdated software before filing, while retaining diagnostic information. Current desktop reporting already warns about an available VS Code update; extension-specific guidance remains absent. Acceptance should cover an outdated extension, a current extension, unavailable update information, and changing the selected reporting target. The scope of extension checks must be agreed before implementation.
- **Trace:**

  > IssueReporterEditorPane.shouldShowUpdateBanner reads IUpdateService and supplies a live application-update flag to IssueReporterOverlay.setUpdateAvailable. NativeIssueService.populateReporterDataAsync enumerates installed extensions and exports manifest versions through IssueReporterExtensionData, but that contract carries no extension-update state. IssueReporterOverlay.updateSelectedExtension resolves reporting data, and updateTargetStatus describes the destination without comparing extension versions. The legacy BaseIssueReporterService.updateExtensionStatus likewise handles reporting metadata rather than update detection. Preserve existing diagnostic collection, extension-provided reporting destinations, and the application-update banner. https://github.com/microsoft/vscode/issues/238282 and https://github.com/microsoft/vscode/pull/242602 establish only the application-warning portion; uncertainty starts at the scope and user-facing semantics of extension guidance.
- **Open decisions:**
  - Should extension-update guidance concern only the extension selected as the report target, or all enabled extensions that could affect the reported setup?
  - Should an outdated extension produce a non-blocking warning like the current VS Code banner, or require explicit acknowledgement before submission?
