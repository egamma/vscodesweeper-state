# Issue #196943 — cursorUp/down behavior inconsistent when moving from selection

[https://github.com/microsoft/vscode/issues/196943](https://github.com/microsoft/vscode/issues/196943)

## Summary

The cursor-up/down selection-collapse behavior (up→start, down→end) is an intentional, long-standing design matching how left/right arrows handle selections. It has been stable since the original 2016 implementation and follows a common convention across text editors.

## Change summary

When pressing cursor up/down to exit a selection, the cursor collapses to the selection start (for up) or end (for down) rather than to the caret's visual position, causing unexpected column jumps when the caret is at the opposite end of the selection.

## Best solution

Keep the current behavior: moveDown collapses to selection end, moveUp collapses to selection start. This is consistent with left/right arrow selection collapse (left→start, right→end) and matches common editor conventions. The reporter's alternative (always collapse to cursor.position) would break the symmetry with horizontal arrow key behavior and surprise users who rely on the current convention.
