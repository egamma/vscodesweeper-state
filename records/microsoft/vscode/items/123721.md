# Issue #123721 — Git conflict resolution Accept Current Change "ignores" addition of a single empty line

[https://github.com/microsoft/vscode/issues/123721](https://github.com/microsoft/vscode/issues/123721)

## Summary

The defect remains directly visible on current main: accepting a side whose entire content is one newline explicitly replaces the conflict with an empty string. The older related reports concern stale CodeLens ranges and repeated clicks, not this deterministic single-empty-line loss.

## Change summary

Accept Current Change or Accept Incoming Change discards the selected side when it consists of exactly one empty line.

## Best solution

Preserve newline-only current or incoming content exactly as selected while retaining the existing behavior for genuinely empty conflict sides and for Accept Both.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/documentMergeConflict.ts`
- **Validation:** Resolve two marker blocks in an Extension Development Host: one with exactly one LF-only or CRLF-only line on the current side and one on the incoming side. Accepting that side must preserve one empty line; accepting the empty opposite side must not add a line, and existing Accept Both behavior must remain unchanged.
- **Behavior:**

  > When a merge-conflict side contains exactly one empty line, accepting that side must preserve the empty line. The behavior must work for both Current and Incoming changes and for LF and CRLF documents. A genuinely empty side must remain empty, multiple empty lines must remain intact, and Accept Both must retain its existing concatenation behavior.
- **Trace:**

  > DocumentMergeConflict.applyEdit in extensions/merge-conflict/src/documentMergeConflict.ts obtains the selected range text and delegates Current and Incoming resolutions to replaceRangeWithContent. That helper special-cases exactly '\n' and '\r\n' through isNewlineOnly and replaces the complete conflict with '', conclusively explaining why one empty line disappears while multiple empty lines and Accept Both work. The behavior dates back to the built-in extension's original implementation and remains on current main. Keep the boundary to newline-only resolution semantics; do not conflate it with the stale-CodeLens race tracked by https://github.com/microsoft/vscode/issues/107821.

## Evidence

- **source reproduction:** In extensions/merge-conflict/src/documentMergeConflict.ts, DocumentMergeConflict.applyEdit reads the selected side and passes it to replaceRangeWithContent; lines 90-101 classify exactly '\n' or '\r\n' as newline-only and replace the entire conflict range with ''. Two newlines and Accept Both bypass this branch, exactly matching the reported behavior.
- **confirmed reproduction:** https://github.com/microsoft/vscode/issues/123721#issuecomment-933867288 provides complete repository steps, confirms the behavior with extensions disabled, and reports that other Git clients preserve the line.
- **later confirmation:** https://github.com/microsoft/vscode/issues/123721#issuecomment-1599244891 confirms both Current and Incoming cases in VS Code 1.79.2 and isolates the defect to exactly one empty line.
- **not a duplicate:** https://github.com/microsoft/vscode/issues/107821 tracks stale CodeLens ranges deleting unrelated lines during successive resolutions; a maintainer explicitly identified this newline-only report as a different bug at https://github.com/microsoft/vscode/issues/107821#issuecomment-831742812.
