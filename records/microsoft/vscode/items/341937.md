# Issue #341937 — Copilot "Local" mode is missing in VS Code 1.142.0 

[https://github.com/microsoft/vscode/issues/341937](https://github.com/microsoft/vscode/issues/341937)

## Summary

The thread points to an intentional 1.142 change: Copilot Agent Host is now the default, and the local harness is hidden for policy-managed or enterprise setups unless a managed setting or user settings re-enable it. The item was reopened and sits next to the open feedback meta issue, so it stays open rather than being closed as as-designed.

## Change summary

After upgrading to 1.142.0 the Local harness option is missing from the Copilot session type picker, leaving only Copilot and Cloud.

## Best solution

Keep the discussion linked to the Agent Host feedback meta issue (https://github.com/microsoft/vscode/issues/339363). Make the enterprise opt-out (`vscode.temporaryDefaultToLocalHarness`) and the user settings that restore Local easier to discover, for example with an in-product hint when Local is hidden by policy.

- **Proposed comment:**

  > Thanks for the report. In 1.142 the Copilot Agent Host became the default harness. If your organization uses managed policy settings, Local may be hidden until an admin sets `vscode.temporaryDefaultToLocalHarness` to true in the unified managed settings. Otherwise, try `chat.editor.localAgent.enabled`, `chat.defaultToCopilotHarness: false` and `chat.editor.preferCopilotHarness: false`, then start a new chat, since existing chats keep the harness they were created with. Feedback on this direction is being collected in https://github.com/microsoft/vscode/issues/339363.
