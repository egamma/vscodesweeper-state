# Issue #43936 — Workspace ... scrollbar area is totally invisible

[https://github.com/microsoft/vscode/issues/43936](https://github.com/microsoft/vscode/issues/43936)

## Summary

Explorer scrollbar discoverability remains only partially addressed: the track can now be colored, but workbench lists still auto-hide their scrollbars without a user-facing always-visible setting. Keep this accepted Backlog request open for a UX decision rather than treating the color customization as a complete fix.

## Change summary

Make the workspace folder list's scrollbar track discoverable so users can locate it and click to navigate long lists.

## Best solution

Provide a discoverable scrollbar target in Explorer while preserving consistent workbench scrolling behavior. The UX owner should decide whether theme-level track contrast is sufficient or whether workbench lists should also offer persistent scrollbar visibility.

## Evidence

- **Requested behavior and discussion:** https://github.com/microsoft/vscode/issues/43936 asks for a visible scrollbar area when navigating hundreds of workspace folders. The supplied April 2018 comment additionally requests visibility analogous to editor.minimap.showSlider="always"; the minimap setting does not control Explorer scrollbars.
- **Existing partial capability:** Commit https://github.com/microsoft/vscode/commit/908f34c37dd98bf1e6d88e695cc8b5a4cf0addc0 adds scrollbar.background in src/vs/platform/theme/common/colors/miscColors.ts and applies it to .monaco-scrollable-element > .scrollbar in src/vs/base/browser/ui/scrollbar/media/scrollbars.css. This permits track coloring through workbench.colorCustomizations, but the registered default is null and the commit does not change scrollbar visibility.
- **Remaining source behavior:** src/vs/base/browser/ui/list/listView.ts defaults verticalScrollMode to ScrollbarVisibility.Auto and passes it to SmoothScrollableElement. src/vs/base/browser/ui/scrollbar/scrollbarVisibilityController.ts retains automatic reveal/hide behavior, and scrollbars.css applies opacity:0 to the invisible scrollbar, including its track background.
- **Settings boundary:** src/vs/editor/common/config/editorOptions.ts registers editor.scrollbar.vertical="visible" for editors. The workbench list configuration in src/vs/platform/list/browser/listService.ts exposes scrolling options but no corresponding user-facing scrollbar visibility setting; the editor option does not supply persistent visibility for Explorer.
