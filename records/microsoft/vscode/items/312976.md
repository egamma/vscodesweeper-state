# Issue #312976 — Copilot CLI with worktree mode made local changes

[https://github.com/microsoft/vscode/issues/312976](https://github.com/microsoft/vscode/issues/312976)

## Summary

Keep open: the maintainer confirmed that Worktree was selected and reproduced edits in the original workspace twice. Current source still permits this outcome after worktree creation fails, but the offline logs are needed to distinguish that fallback from a selection-state defect.

## Change summary

A new Copilot CLI session selected for worktree isolation instead edits the original workspace without creating a worktree.

## Best solution

Ensure a session selected for Worktree does not automatically execute in the original workspace when isolation cannot be established. Correlate the shared logs with session initialization before deciding whether this is the creation-failure fallback tracked in https://github.com/microsoft/vscode/issues/309537 or a separate picker-state defect.
