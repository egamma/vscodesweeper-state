# Issue #291426 — Codex sessions still appear in sessions list after uninstalling Codex

[https://github.com/microsoft/vscode/issues/291426](https://github.com/microsoft/vscode/issues/291426)

## Summary

Still open and unfixed: no commit on main references this issue. The sessions list correctly queries only registered providers via `SessionsManagementService.getSessions()`, but the Codex extension's sessions persist through a separate caching layer (likely the agent host session list store or extension-side storage) and remain visible even after the provider deregisters on extension uninstall.

## Change summary

Sessions from the Codex extension still appear in the sessions list after uninstalling the extension, showing errors when clicked.

## Best solution

Add filtering in the sessions list or the sessions management service to suppress sessions whose `providerId` no longer maps to a registered provider. The check should go in `SessionsManagementService` or `SessionsList` where sessions are collected — likely near `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts` (the `getSessions()` method) or in the agent host session list contribution that bridges cached agent-host sessions into the sessions provider. As noted in the discussion, this may also need coordination with the Codex extension to scope sessions per-workspace rather than globally.
