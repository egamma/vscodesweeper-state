# Issue #291426 — Codex sessions still appear in sessions list after uninstalling Codex

[https://github.com/microsoft/vscode/issues/291426](https://github.com/microsoft/vscode/issues/291426)

## Summary

Still unfixed on main: there is no mechanism to prune cached/persisted session entries (recency history, read/unread/pin state) when the originating session provider is uninstalled. The issue is team-authored and the described gap is real — keeping open.

## Change summary

Sessions from an uninstalled extension provider (e.g. Codex) persist in the sessions list cache and show errors when clicked because the provider scheme can no longer be resolved.

## Best solution

When restoring persisted session state (recency history, visible-sessions grid, pinned/read state), filter out entries whose provider ID does not match any currently registered provider in `ISessionsProvidersService`. The restore path in `SessionsService.restoreVisibleSessions()` and the recency history in `SessionsRecencyHistory` are the likely places to add this guard. Additionally, the sessions list UI should not render rows for sessions whose provider is gone.
