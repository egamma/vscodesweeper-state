## Evidence

- **Current source: missing frontmatter mapping:** In extensions/markdown-language-features/src/markdownEngine.ts, pluginSourceMap assigns data-line and class="code-line" to mapped tokens. However, extensions/markdown-language-features/src/extensions/yamlPreamble/yamlPreamble.ts renders the frontmatter table without those token attributes; frontMatterAttributes() emits only title and data-vscode-context.
- **Current source: unchanged heading receives frontmatter changes:** extensions/markdown-language-features/preview-src/scroll-sync.ts:getCodeLineElements indexes code-line elements, excluding the unmapped frontmatter table. For changed frontmatter lines before the first heading, getElementsForSourceLine returns the synthetic body entry as previous and the heading as next; preview-src/index.ts:markChangedLines chooses next when previous.line is negative, applying the diff background to that unchanged heading.
- **Current source: inner highlights lose their markers:** extensions/markdown-language-features/src/preview/documentRenderer.ts:injectInnerChangeMarkers inserts span elements with data-diff-start and data-diff-end into changed text. yamlPreamble.ts:formatValueHtml escapes scalar values, so these markers become text instead of DOM elements in frontmatter cells. This prevents the intended inner-change highlight ranges from identifying the edited value.
