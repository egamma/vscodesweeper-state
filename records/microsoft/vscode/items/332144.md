# Issue #332144 — Rendered Markdown diff on YAML frontmatter: edited field shows no diff, unchanged heading marked as changed

[https://github.com/microsoft/vscode/issues/332144](https://github.com/microsoft/vscode/issues/332144)

## Summary

Traced a real root cause in the rendered-Markdown-diff pipeline: the frontmatter table renderer HTML-escapes all cell values, which kills the invisible `<span data-diff-start/end>` marker tags that `documentRenderer.ts` injects into the raw source before parsing for inline diff highlighting — so the changed field never highlights inside the table. The mislabeled-heading symptom is plausibly a downstream effect of the same feature but is not independently traced.

## Change summary

In the rendered-Markdown diff view, an edited YAML frontmatter field shows no highlight in its table cell, while the unrelated heading right after the frontmatter gets a full-line changed background.

## Best solution

In extensions/markdown-language-features/src/extensions/yamlPreamble/yamlPreamble.ts, renderAsTable/formatValueHtml need to preserve the injected diff marker spans (from documentRenderer.ts's injectInnerChangeMarkers) instead of passing every value through escapeHtml verbatim; then re-check whether the heading's spurious change-indicator is a separate line-mapping bug once the frontmatter table's DOM diverges from the raw source line count.

## Evidence

- **marker injection:** extensions/markdown-language-features/src/preview/documentRenderer.ts's injectInnerChangeMarkers() inserts literal `<span data-diff-start=...>`/`<span data-diff-end=...>` tags directly into the raw markdown source text (including inside the YAML frontmatter block) before it is handed to the markdown-it engine.
- **escaped away:** extensions/markdown-language-features/src/extensions/yamlPreamble/yamlPreamble.ts renderAsTable() parses that same raw content as YAML and renders each value via formatValueHtml()/escapeHtml() (util/dom.ts), which HTML-escapes the injected span tags along with the field text — so the marker elements the webview's CSS Custom Highlight API looks for never exist in the DOM for frontmatter cells.
- **no code fix present:** No handling in yamlPreamble.ts distinguishes injected diff markers from user content; the escaping is unconditional, matching the reported 'no diff indication' on the edited cell.
