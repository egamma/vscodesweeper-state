# Issue #130332 — Editor > Minimap: Size = "fit" setting incorrectly stretches minimap on small files after an integrated terminal panel is initiated and closed from a larger file.

[https://github.com/microsoft/vscode/issues/130332](https://github.com/microsoft/vscode/issues/130332)

## Summary

This remains the canonical open issue for a current minimap `fit` defect. The source still retains minimap layout-stability state across model switches, allowing a large file's fill-like layout to affect a smaller file.

## Change summary

Prevent the `editor.minimap.size: "fit"` layout from stretching a small file after switching from a larger file or resizing the editor through the terminal panel.

## Best solution

Keep the minimap's same-model wrapping stabilization while ensuring its cached layout state cannot carry across editor model changes. Cover the large-file-to-small-file transition with a regression test.

- **Behavior:**

  > With `editor.minimap.size` set to `fit`, switching from a large file to a small file must leave the small file's minimap at its natural scale rather than stretching it to the editor height. Opening and closing the terminal panel must not change that result. Existing `fill` behavior and the stabilization of a wrapped file during width changes must remain unchanged.
- **Trace:**

  > EditorConfiguration owns a single ComputeOptionsMemory in src/vs/editor/browser/config/editorConfiguration.ts and reuses it for every model attached to the editor widget. CodeEditorWidget changes models through `_detachModel` and `_attachModel` in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts without giving that memory a model boundary. In src/vs/editor/common/config/editorOptions.ts, `_computeMinimapLayout` intentionally omits `viewLineCount` and remaining width from its cache-compatibility check; for viewport wrapping, the cached state can force `fitBecomesFill` even after the new small model's effective minimap height would fit. The same-model cache behavior exists to break a wrapping/layout feedback loop and must not be removed indiscriminately. The current behavior was independently reported and linked back here at https://github.com/microsoft/vscode/issues/306236.
