# Issue #325731 — cannot rename session name

[https://github.com/microsoft/vscode/issues/325731](https://github.com/microsoft/vscode/issues/325731)

## Summary

Rename appears broken for the original reporter, but later confirmations narrow it down to real inconsistencies: renaming works via click-to-edit on the session title and via right-click from the sessions list, but not via right-click on the active session header — likely because the header's context-menu rename action is gated to agent-host providers only while click-to-edit is gated only on `supportsRename`.

## Change summary

Renaming an agent session (Agents window) either silently fails or behaves inconsistently depending on which UI affordance is used.

## Best solution

Align the gating between `RenameSessionHeaderAction` (src/vs/sessions/contrib/sessions/browser/sessionsActions.ts, gated on ANY_AGENT_HOST_PROVIDER_RE) and `SessionHeader._isTitleEditable()` (src/vs/sessions/browser/parts/sessionHeader.ts, gated on `capabilities.supportsRename`) so right-click and click-to-edit rename are available consistently for the same session types; also look at whether comment 6's separate 'selected session is not current' report needs its own issue.

## Evidence

- **header context-menu gating:** src/vs/sessions/contrib/sessions/browser/sessionsActions.ts registers RenameSessionHeaderAction only when SessionProviderIdContext matches ANY_AGENT_HOST_PROVIDER_RE (src/vs/sessions/common/agentHostSessionsProvider.ts), so it's hidden for non-agent-host (e.g. Copilot Chat) session providers.
- **click-to-edit gating:** src/vs/sessions/browser/parts/sessionHeader.ts `_isTitleEditable()` only checks `session.capabilities.get().supportsRename`, with no provider-type restriction — explaining why click-to-edit works where right-click doesn't.
- **list-view rename:** src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts `RenameSessionAction` is gated only on `SessionSupportsRenameContext`, matching the click-to-edit path and confirming why rename from the sessions list works.
- **commenter confirmation:** str's comments (2026-08-11/12) explicitly describe the working/non-working paths: click works, list right-click works, in-session header right-click does not.
