# Issue #336380 — Debug toolbar remains active when running Flutter app without debugging

[https://github.com/microsoft/vscode/issues/336380](https://github.com/microsoft/vscode/issues/336380)

## Summary

The active controls reflect a stopped state reported by the third-party Dart/Flutter debug adapter during a no-debug launch. VS Code correctly forwards `noDebug: true`, so this should be handled in the Dart-Code extension.

## Change summary

Prevent debugging controls from appearing active while a Flutter application is running without debugging.

## Best solution

The Dart/Flutter adapter should honor the DAP `noDebug` launch argument and avoid reporting stopped threads or otherwise exposing debugger-only controls during that session.

## Evidence

- **core launch path:** src/vs/workbench/contrib/debug/browser/debugService.ts sets `config.noDebug = true` for Run Without Debugging, and src/vs/workbench/contrib/debug/browser/debugSession.ts forwards that configuration to the debug adapter.
- **DAP contract:** src/vs/workbench/contrib/debug/common/debugProtocol.d.ts defines `LaunchRequestArguments.noDebug` as instructing the adapter to launch the program without enabling debugging.
- **toolbar state:** src/vs/workbench/contrib/debug/browser/debugSession.ts derives the stopped state from adapter-reported stopped threads; src/vs/workbench/contrib/debug/browser/debugToolBar.ts enables Continue and stepping controls when that state is `stopped`.
- **extension scope:** The reproduction is specific to Dart-Code's `dart-code.flutter` 3.142.0 extension, which is not owned by the VS Code team; no equivalent core or other-debugger reproduction is reported.
