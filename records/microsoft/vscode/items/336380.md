# Issue #336380 — Debug toolbar remains active when running Flutter app without debugging

[https://github.com/microsoft/vscode/issues/336380](https://github.com/microsoft/vscode/issues/336380)

## Summary

The debug toolbar's visibility and enabled state are driven generically by the active session's reported state (CONTEXT_DEBUG_STATE) and `session.suppressDebugToolbar` — core deliberately skips sending breakpoints for noDebug sessions (debugService.ts), but any DAP session can still report itself as running/stopped. Since the only debug-capable extensions installed are Dart-Code and Flutter, the toolbar staying active in this Run-Without-Debugging scenario is almost certainly a result of how the Dart debug adapter models its noDebug session (likely to support hot reload/restart), not a core defect.

## Change summary

Debug toolbar (Continue/Step Over/Step Into/Step Out) still appears active when a Flutter app is launched with Run Without Debugging.

## Best solution

If Dart-Code's noDebug session shouldn't expose stepping affordances, it should set `suppressDebugToolbar` (or avoid reporting a 'stopped' state) on that session; this is the Dart-Code extension's responsibility, not core's generic debug toolbar logic.
