# Issue #196722 — Maximize Workbench Editor

[https://github.com/microsoft/vscode/issues/196722](https://github.com/microsoft/vscode/issues/196722)

## Summary

Keep open: existing commands maximize editor groups or hide sidebars, but do not provide the requested reversible workbench-wide toggle with conditional visibility restoration. This team-authored Backlog request has 25 upvotes; the remaining product decision is which surrounding workbench parts participate.

## Change summary

Add an editor-maximization toggle that temporarily hides surrounding workbench parts and restores the previous layout unless the user has reopened a participating part.

## Best solution

Provide a reversible editor-focused maximization command, optionally available through tab double-click, while preserving the existing group-only maximization behavior. Settle the participating workbench parts before implementation; broader focus-dependent maximization need not block this editor-specific capability.

- **Behavior:**

  > Users can temporarily maximize an editor group across the workbench with a reversible command, optionally invoked by tab double-click. Entering records the existing layout and visibility of the participating workbench parts before hiding them. Exiting restores the editor-group layout and restores saved visibility only when the participating parts remain hidden, as specified in the issue. Reopening a participating part must prevent stale visibility restoration. Existing group-only maximization remains available and unchanged; the exact set of participating parts needs a maintainer decision.
- **Trace:**

  > The tab-double-click handler in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts calls EditorPart.toggleMaximizeGroup, whose implementation in editorPart.ts only maximizes or restores the editor grid. MaximizeGroupHideSidebarAction in editorActions.ts adds one-way sidebar hiding but carries no restoration state. Layout.toggleZenMode in src/vs/workbench/browser/layout.ts supplies related visibility snapshot behavior, but its exit restores previously visible parts without the requested conditional suppression and its entry does not maximize an editor group. These source paths establish why neither existing surface covers the central ask. Preserve existing group-only actions and Zen Mode semantics rather than changing them implicitly. The uncertainty is the participating-part boundary, explicitly raised at https://github.com/microsoft/vscode/issues/196722#issuecomment-4821405544; broader terminal/view zooming at https://github.com/microsoft/vscode/issues/47661 is related but not a verified duplicate.
- **Open decisions:**
