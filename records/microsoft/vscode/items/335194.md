# Issue #335194 — Copilot 0.64.1: bulk exclusion filtering stalls shared extension host in large workspaces (Limiter.consume / Array.shift)

[https://github.com/microsoft/vscode/issues/335194](https://github.com/microsoft/vscode/issues/335194)

## Summary

Confirmed on current main: Limiter.consume() in extensions/copilot/src/util/vs/base/common/async.ts (line ~758) uses `outstandingPromises.shift()`, an O(n) array-front-removal, inside filterIngoredResources (extensions/copilot/src/platform/ignore/common/ignoreService.ts, line 71-74), which enqueues the entire search-result batch through a fixed Limiter(20). For very large result batches this becomes effectively O(n²), and the dense promise-microtask chain starves the event loop, causing the shared extension host to hang for the reported minute-scale durations. This is a real, actionable performance bug in code that ships as part of VS Code core (Copilot Chat).

## Change summary

Bulk file-exclusion filtering (filterIngoredResources -> Limiter) becomes O(n²) and stalls the shared extension host on very large search-result batches (hundreds of thousands of files).

## Best solution

Replace the Limiter's array-based outstandingPromises queue (using Array.shift()) with an O(1) dequeue structure — the repo already vendors a LinkedList (extensions/copilot/src/util/vs/base/common/linkedList.ts) suitable for this — in extensions/copilot/src/util/vs/base/common/async.ts's Limiter class, or otherwise bound/chunk the batch fed into filterIngoredResources in ignoreService.ts so a single huge search result set can't monopolize the event loop.
