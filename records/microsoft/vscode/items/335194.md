# Issue #335194 — Copilot 0.64.1: bulk exclusion filtering stalls shared extension host in large workspaces (Limiter.consume / Array.shift)

[https://github.com/microsoft/vscode/issues/335194](https://github.com/microsoft/vscode/issues/335194)

## Summary

Source on main confirms the report: filterIngoredResources in extensions/copilot/src/platform/ignore/common/ignoreService.ts enqueues the entire search-result array through a Limiter(20), whose consume() removes entries with outstandingPromises.shift() — an O(n) operation per dequeue that becomes O(n²) for very large arrays, and searchServiceImpl.ts runs this filter unconditionally. This matches the reporter's traced CPU profiles and benchmark numbers exactly.

## Change summary

In very large workspaces (100k+ files), Copilot's ignore-filtering pass on search results uses a Limiter backed by Array.shift() over the full result set, causing quadratic-time processing that stalls the shared extension host for minutes.

## Best solution

Bound or chunk the filtering work instead of enqueueing every resource into the Limiter at once (e.g. a fixed worker pool pulling from a shared index/counter, as the reporter's benchmark demonstrates, or replace outstandingPromises with an O(1) dequeue structure), in extensions/copilot/src/util/vs/base/common/async.ts (Limiter) and/or extensions/copilot/src/platform/ignore/common/ignoreService.ts (filterIngoredResources); route to the Copilot/chat team who own this extension code.
