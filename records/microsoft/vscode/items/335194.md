# Issue #335194 — Copilot 0.64.1: bulk exclusion filtering stalls shared extension host in large workspaces (Limiter.consume / Array.shift)

[https://github.com/microsoft/vscode/issues/335194](https://github.com/microsoft/vscode/issues/335194)

## Summary

Verified on current main: Copilot's `filterIngoredResources` unconditionally queues every search result through a `Limiter(20)`, and `Limiter`'s pending queue uses `Array.shift()`, giving O(n²) cost for large batches — exactly the algorithmic regression the reporter traced and benchmarked (14s for 100k items), matching the reported multi-minute shared-extension-host stall.

## Change summary

Copilot's post-search ignore-filtering pass queues the entire result array through a Limiter(20) whose pending-queue uses Array.shift(), causing quadratic-time processing and multi-minute shared extension-host stalls on very large workspaces/search results.

## Best solution

Rework `filterIngoredResources` in extensions/copilot/src/platform/ignore/common/ignoreService.ts to process the resource array with a fixed-size worker pool driven by a shared index counter (as the reporter's own 'fixed 20-worker reference' benchmark does) instead of pushing every item into `Limiter`'s array-shift-based queue, and reinstate gating the extra filtering pass so it isn't unconditionally applied in extensions/copilot/src/platform/search/vscode-node/searchServiceImpl.ts when not needed.
