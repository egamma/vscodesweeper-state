# Issue #102867 — CodeLens messes up page scrolling via cursorPageUp / cursorPageDown

[https://github.com/microsoft/vscode/issues/102867](https://github.com/microsoft/vscode/issues/102867)

## Summary

Still valid on main: the cursorPageUp/Down page size is computed as a simple `layoutInfo.height / lineHeight` division that doesn't account for CodeLens (or any view zone) extra height, so the cursor overshoots or undershoots. Already labeled feature-request, which is accurate — the current behavior is consistent (uniform line height assumption), but could be improved to account for variable-height elements.

## Change summary

cursorPageUp/cursorPageDown scrolls too far (or not far enough) when CodeLens decorations are visible, because the page size calculation assumes uniform line heights.

## Best solution

Improve the `pageSize` computation in `CursorCommon` (src/vs/editor/common/cursorCommon.ts line 129) to account for view zones (CodeLens, sticky scroll, etc.) currently visible in the viewport, or compute the effective visible-line count dynamically at scroll time rather than using the static `layoutInfo.height / lineHeight` ratio. This is a nontrivial change because the cursor layer currently doesn't have access to view-zone layout information.
