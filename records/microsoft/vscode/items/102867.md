# Issue #102867 — CodeLens messes up page scrolling via cursorPageUp / cursorPageDown

[https://github.com/microsoft/vscode/issues/102867](https://github.com/microsoft/vscode/issues/102867)

## Summary

A real gap remains on current main: cursor page navigation counts text lines rather than the rendered viewport height, so CodeLens view zones can make Page Up and Page Down move beyond the previously visible page. No broader canonical issue was found, so this accepted Backlog request should remain open for an editor-core behavior decision.

## Change summary

Make cursorPageUp and cursorPageDown account for CodeLens height so consecutive pages retain the expected visible-line overlap.

## Best solution

Define cursor page movement using rendered viewport geometry, including CodeLens and other view zones, while preserving wrapped-line, selection, and reveal behavior. The implementation should make Page Up and Page Down symmetric without changing the separate scrollPageUp and scrollPageDown commands.

## Plan brief

- **Likely files:** `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/common/cursor/cursorMoveCommands.ts`, `src/vs/editor/common/cursorCommon.ts`
- **Validation:** Add an editor browser test with CodeLens-sized view zones that invokes cursorPageDown and cursorPageUp and verifies the old bottom/top visible line remains at the opposite viewport edge; also cover wrapped lines and selection variants.
- **Behavior:**

  > With CodeLens visible, Page Down should move the cursor and viewport by one rendered page so the previous bottom visible text line becomes the new top boundary; Page Up should provide the symmetric result. The behavior must also remain correct with multiple CodeLens rows and wrapped lines. cursorPageUpSelect and cursorPageDownSelect must retain their selection semantics, while scrollPageUp and scrollPageDown remain scroll-only commands.
- **Trace:**

  > CursorPageUp and CursorPageDown in src/vs/editor/browser/coreCommands.ts substitute CursorConfiguration.pageSize and call CursorMoveCommands.simpleMove by wrapped lines, then reveal the resulting cursor. CursorConfiguration.pageSize in src/vs/editor/common/cursorCommon.ts derives only from editor height and text line height. CodeLensWidget in src/vs/editor/contrib/codelens/browser/codelensWidget.ts reserves independent pixel-height view zones, so the cursor jump can represent more rendered height than one viewport. The uncertainty starts at whether page movement should target viewport-edge positions directly or generalize page-size calculation for all variable-height view zones. Preserve wrapped-line movement, multicursor/selection behavior, cursor reveal padding, and the separate scroll-only commands.
- **Open decisions:**
  - Should cursor page navigation target positions derived from the current and destination viewport edges, or should CursorConfiguration expose a view-zone-aware page measure?
  - Should every variable-height view zone affect cursor page movement identically, or are special rules needed for zones attached to the cursor's source or destination line?
  - What overlap convention should apply when a view zone straddles a viewport boundary?

## Evidence

- **current source:** src/vs/editor/common/cursorCommon.ts computes CursorConfiguration.pageSize as `floor(layoutInfo.height / lineHeight) - 2`, without accounting for view-zone height.
- **cursor command path:** src/vs/editor/browser/coreCommands.ts resolves cursorPageUp and cursorPageDown to `viewModel.cursorConfig.pageSize` and then moves that many wrapped view lines before revealing the cursor.
- **CodeLens geometry:** src/vs/editor/contrib/codelens/browser/codelensWidget.ts implements each CodeLens row as a CodeLensViewZone with its own `heightInPx`, confirming that it consumes viewport space outside the text-line page-size calculation.
- **existing workaround is incomplete:** scrollPageUp and scrollPageDown use the editor-scroll path in src/vs/editor/browser/coreCommands.ts and do not move the cursor, so they do not cover the central request for correct cursor page navigation.
- **canonical search:** Repository issue searches for CodeLens PageDown/PageUp, cursorPageDown scrolling, and page navigation with view zones found no separate open issue owning this behavior.
