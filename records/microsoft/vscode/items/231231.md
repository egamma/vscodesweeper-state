# Issue #231231 — Retrying opening a file with a custom editor always gives the same error

[https://github.com/microsoft/vscode/issues/231231](https://github.com/microsoft/vscode/issues/231231)

## Summary

Still reproduces on main: the `@memoize` decorator on `LazilyResolvedWebviewEditorInput.resolve()` permanently caches the first resolution result — including rejected promises from errors — so "Try Again" always replays the original error. The bug is confirmed in the current source and has not been addressed.

## Change summary

Clicking "Try Again" on a custom editor that failed to open (e.g. because the file was renamed) always returns the same cached error, because the `resolve()` method is memoized and never retried.

## Best solution

Remove or replace the `@memoize` decorator on `LazilyResolvedWebviewEditorInput.resolve()` in `src/vs/workbench/contrib/webviewPanel/browser/webviewWorkbenchService.ts` with retry-aware caching that clears the cached result on error, so subsequent `resolve()` calls can re-attempt the webview resolution. The `_resolved` flag already exists and could serve as the retry guard instead of `@memoize`.
