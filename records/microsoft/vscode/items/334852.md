# Issue #334852 — Custom agents fail as subagents due to "displayName: Required" while frontmatter does not need it

[https://github.com/microsoft/vscode/issues/334852](https://github.com/microsoft/vscode/issues/334852)

## Summary

Traced the reported failure directly in current `main`: `toSdkCustomAgents` in `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts` builds the SDK `CustomAgentConfig` with `name` but never sets `displayName`, and passes `tools: null` for agents that omit `tools`. Two independent reporters hit the exact downstream validation error this predicts, so this is a real, currently-reproducible bug in VS Code's own converter, not something already fixed.

## Change summary

Repository custom agents (`.github/agents/*.agent.md`) fail when invoked as subagents with `displayName: Required` (and sometimes `tools: Expected array`), even though neither field is required in the documented frontmatter format.

## Best solution

In `toSdkCustomAgents` (src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts), populate `displayName` (e.g. derive it from the resolved `name`) on every emitted `CustomAgentConfig`, and confirm the `tools: null` shape actually satisfies the currently-bundled `@github/copilot-sdk` (1.0.13-preview.4) custom-agent validation — adjusting to omit the key or emit `[]` if the bundled SDK's runtime schema is stricter than its published `.d.ts`.
