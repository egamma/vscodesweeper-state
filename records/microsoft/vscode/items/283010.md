# Issue #283010 — Improve codelens and selection/decoration behaviour

[https://github.com/microsoft/vscode/issues/283010](https://github.com/microsoft/vscode/issues/283010)

## Summary

Keep open: current source still leaves CodeLens whitespace outside the per-line selection and background-decoration rendering. The issue is already correctly routed, and no verified older canonical or landed fix was found.

## Change summary

Make selection and multiline background decorations visually continuous across intervening CodeLens rows.

## Best solution

Ensure CodeLens gaps inside selected or background-decorated ranges participate in the corresponding background rendering, while preserving CodeLens commands, text-selection semantics, and unrelated interactive view zones.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/selections/selections.ts`, `src/vs/editor/browser/viewParts/decorations/decorations.ts`, `src/vs/editor/browser/view/viewOverlays.ts`, `src/vs/editor/browser/viewParts/viewZones/viewZones.ts`, `src/vs/editor/contrib/codelens/browser/codelensWidget.ts`
- **Validation:** In an editor with a deterministic CodeLens provider, select from a line above a lens to a line below it and verify the selection background continues through the lens gap. Repeat with a multiline whole-line background decoration. Check clearing and reversing the selection, multiple cursors, wrapping, scrolling, light/dark/high-contrast themes, CodeLens command activation, and an unrelated peek view zone. The plan should establish browser-rendering regression coverage for these cases before implementation.
- **Behavior:**

  > With CodeLens enabled, selecting a range across an intervening CodeLens row currently leaves an unpainted interruption in the selection background. Multiline background decorations similarly stop at the text-line boundaries around the lens. The expected result is visually continuous background treatment through CodeLens whitespace inside the affected range. CodeLens text must remain excluded from copied source text, its commands must remain usable, and unrelated view-zone content must retain its behavior.
- **Trace:**

  > CodeLensWidget in src/vs/editor/contrib/codelens/browser/codelensWidget.ts reserves CodeLensViewZone whitespace before the model line and places a separate CodeLensContentWidget above that line. SelectionsOverlay and DecorationsOverlay in src/vs/editor/browser/viewParts/selections/selections.ts and src/vs/editor/browser/viewParts/decorations/decorations.ts build per-text-line output; ViewOverlayLine in src/vs/editor/browser/view/viewOverlays.ts gives that output lineHeight-sized containers. ViewZones in src/vs/editor/browser/viewParts/viewZones/viewZones.ts lays out the gap separately, conclusively explaining the missing background without executing the editor. The remaining investigation is how to cover CodeLens whitespace in this shared renderer without changing other view-zone consumers or existing selection geometry, and how to pin that behavior in browser-rendering tests. https://github.com/microsoft/vscode/issues/287012 concerns decoration-versus-selection stacking and is related only at the rendering-area level, not a replacement for this issue.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/283010 describes selecting code across an enabled CodeLens row and seeing its background remain unchanged; multiline background decorations have the same discontinuity. The report includes a screenshot and has no comments or linked implementation.
- **CodeLens occupies separate whitespace:** src/vs/editor/contrib/codelens/browser/codelensWidget.ts constructs CodeLensViewZone before the lens's model line and renders the commands in a separate ABOVE content widget. The zone's DOM node is an otherwise unstyled div; neither component carries selection or background-decoration state.
- **Source-confirmed selection gap:** SelectionsOverlay._getVisibleRangesWithStyle and _actualRenderOneSelection in src/vs/editor/browser/viewParts/selections/selections.ts produce selection pieces indexed by text line. ViewOverlayLine.renderLine and layoutLine in src/vs/editor/browser/view/viewOverlays.ts size their containers to lineHeight, while src/vs/editor/browser/viewParts/viewZones/viewZones.ts allocates the intervening CodeLens height as separate whitespace. A selection crossing that whitespace therefore does not paint it.
- **Background decorations have the same boundary:** DecorationsOverlay._renderWholeLineDecorations and _renderNormalDecoration in src/vs/editor/browser/viewParts/decorations/decorations.ts also emit backgrounds into per-text-line output, not the intervening view-zone area. This supports the report's second case without attributing it to an extension.
- **Existing-capability check:** The CodeLens registrations in src/vs/editor/common/config/editorOptions.ts expose editor.codeLens, editor.codeLensFontFamily, and editor.codeLensFontSize; these control visibility and typography, not background continuity. The current CodeLens CSS likewise supplies no selection-aware background behavior.
- **Canonical search:** Searches for CodeLens selection/background/highlight and selection decorations found no verified older open issue owning this symptom. https://github.com/microsoft/vscode/issues/287012 is newer and reports selection being obscured by opaque custom decorations, not unpainted CodeLens whitespace; it does not qualify as this re-reviewed item's canonical.
