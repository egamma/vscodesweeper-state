# Issue #283010 — Improve codelens and selection/decoration behaviour

[https://github.com/microsoft/vscode/issues/283010](https://github.com/microsoft/vscode/issues/283010)

## Summary

The CodeLens background gap remains in current source: selections and ordinary range decorations paint individual text-line overlays, leaving the intervening CodeLens view-zone space unpainted. Keep this correctly routed issue open; no verified canonical duplicate or concrete fixing commit was found.

## Change summary

Make selection and multi-line background highlighting visually continuous through intervening CodeLens space.

## Best solution

Make backgrounds spanning CodeLens rows continuous in the editor renderer while preserving text-selection semantics and CodeLens interaction. Establish the boundary with other view-zone consumers before changing shared overlay geometry.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/283010 supplies concrete steps: enable CodeLens and select code spanning a CodeLens row; its background remains unchanged. The report also identifies the same discontinuity for multi-line background decorations and includes a screenshot.
- **CodeLens reserves separate vertical space:** src/vs/editor/contrib/codelens/browser/codelensWidget.ts creates CodeLensViewZone with an otherwise empty div and inserts it before the lens's source line. CodeLensContentWidget is positioned ABOVE that line; neither this path nor codelensWidget.css propagates selection or range-background state into the reserved space.
- **Current selection rendering confirms the gap:** In src/vs/editor/browser/viewParts/selections/selections.ts, SelectionsOverlay._getVisibleRangesWithStyle obtains text-line ranges and _actualRenderOneSelection emits pieces indexed by line number. In src/vs/editor/browser/view/viewOverlays.ts, ViewOverlayLine.renderLine and layoutLine constrain their containers to lineHeight, rather than extending through intervening view-zone whitespace.
- **Ordinary decorations share the limitation:** src/vs/editor/browser/viewParts/decorations/decorations.ts emits both whole-line and normal className decorations into per-line overlay output; decorations.css gives each decoration height: 100% of that line container. The separate blockDecorations renderer means the report should not be generalized to every decoration mechanism without further investigation.
- **Canonical and fix search:** Read-only GitHub searches covering CodeLens/code lens with selection, highlighting, background and decoration, plus view-zone selection/background searches, found no verified older open issue owning this same symptom. An open-PR search for 283010 returned no results. Local history is shallow, so it cannot establish comprehensive fix provenance.
