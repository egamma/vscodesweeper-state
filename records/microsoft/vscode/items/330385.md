# Issue #330385 — Markdown preview: code block copy button scrolls out of view on verticaly tall code blocks

[https://github.com/microsoft/vscode/issues/330385](https://github.com/microsoft/vscode/issues/330385)

## Summary

Well-diagnosed, distinct bug: the copy button is `position: absolute` inside `pre` (which has no `max-height`), so on a tall code block the page scrolls the button out of view along with the top of the block, with no way to copy without scrolling back up. Confirmed in current source; not a duplicate of the horizontal-scroll issue.

## Change summary

On markdown-preview code blocks taller than the viewport, the copy button scrolls off-screen with the top of the block as the page scrolls, leaving no way to copy without scrolling back up.

## Best solution

Restructure so the `pre` isn't itself the vertical scroll boundary for the button — e.g. the reporter's suggested approach of moving overflow handling to the inner `code` element and making the button `position: sticky` relative to the page, in `extensions/markdown-language-features/media/markdown.css` and `preview-src/index.ts`. Worth coordinating with https://github.com/microsoft/vscode/issues/329805, a related but distinct copy-button positioning bug (horizontal-scroll drift) in the same files — a single PR could plausibly fix both root causes together.

## Evidence

- **no max-height on pre:** extensions/markdown-language-features/media/markdown.css:414-419 sets `overflow: auto` on `pre:not(.hljs)` but no `max-height`, so a tall block grows the page rather than scrolling internally — confirming the reporter's page-scroll-not-block-scroll root cause.
- **button anchoring:** markdown.css:437-440 has `.code-block-copy-button { position: absolute; top: 8px; right: 8px; }` inside `pre { position: relative; }` (line 430-434), so the button's position is anchored to the pre's own box, which scrolls with the page.
- **append site:** extensions/markdown-language-features/preview-src/index.ts:269 does `pre.appendChild(button)`, matching the code the reporter references.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/329805 reports a different symptom (button drifts horizontally when the pre's own horizontal scrollbar is used) with a different proposed fix (wrapper div) — same code area, separate root cause, not a duplicate of this vertical-scroll report.
