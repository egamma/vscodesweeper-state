# Issue #174877 — Can't keybind escape when renaming a file in explorer view

[https://github.com/microsoft/vscode/issues/174877](https://github.com/microsoft/vscode/issues/174877)

## Summary

The bug remains on current main: Explorer handles Escape in the rename input before the window-level keybinding listener, removing input focus and causing the user's `!inputFocus` binding to run. A maintainer has already specified the intended command-based behavior, and the earlier PR was closed without merging.

## Change summary

Make Explorer rename cancellation a configurable Escape keybinding so other Escape bindings evaluate against the original input-focused context.

## Best solution

Expose rename cancellation as an Explorer command with a default Escape binding active while the rename input is focused, and remove the input element's hard-coded Escape handling. Preserve the existing Enter and F2 rename behavior and avoid changing global keybinding event ordering.
