# Issue #332845 — Provide a single "Copy full error message" button

[https://github.com/microsoft/vscode/issues/332845](https://github.com/microsoft/vscode/issues/332845)

## Summary

Keep this in community review: current hover copy buttons operate on individual blocks, not the complete error context requested here. The issue is already correctly routed, and its 60-day Backlog Candidates period has not elapsed.

## Change summary

Provide one hover action and a keybindable command to copy complete error information across separate blocks.

## Best solution

An aggregate copy action in the editor hover, available through a keybindable command, would address the remaining gap. Define which diagnostic metadata and accompanying hover blocks constitute the full error before accepting implementation.

## Evidence

- **Existing capability is per block:** src/vs/editor/contrib/hover/browser/contentHoverRendered.ts, RenderedContentHoverParts._createListenersForPart, creates a HoverCopyButton for each eligible rendered part. Its callback reads only that participant's getAccessibleContent(renderedPart.hoverPart), so separate hover blocks are not copied together.
- **Diagnostic copy has partial context:** src/vs/editor/contrib/hover/browser/markerHoverParticipant.ts, MarkerHoverParticipant.getAccessibleContent, includes the marker message and related-information messages with their locations. It does not include the primary diagnostic location, source, or code, and does not aggregate other hover parts. Existing functionality therefore covers some context, but not the full request.
- **Other copy surfaces are not equivalent:** src/vs/workbench/contrib/markers/browser/markers.contribution.ts provides Problems-panel Copy and Copy Message actions over selected markers. These require the Problems view rather than offering the requested aggregate editor-hover action; searches of the editor hover actions found no copyFullError or aggregate hover-copy command.
