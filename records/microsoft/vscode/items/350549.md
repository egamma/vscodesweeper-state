# Issue #350549 — Keep background task results in the chat that started them

[https://github.com/microsoft/vscode/issues/350549](https://github.com/microsoft/vscode/issues/350549)

## Summary

Keep open for Chat API owner consideration: the stable API does not cover delivering background results to an existing session after its request completes. The related background-task reports concern different behavior, not this extension API contract.

## Change summary

Provide a stable extension API for delivering background results to the originating chat without changing focus or creating another session.

## Best solution

Have the Chat API owners establish a session-targeted delivery contract that preserves provider ownership, permission handling, and the user's active chat. Decide the lifecycle and authorization semantics before accepting an implementation.

## Evidence

- **Stable API gap:** src/vscode-dts/vscode.d.ts:20122–20198 exposes request-scoped ChatRequest and ChatResponseStream; its chat namespace at 20383–20391 exposes createChatParticipant, not a session-targeted post-request delivery API.
- **Request lifetime boundary:** src/vs/workbench/api/common/extHostChatAgents2.ts:61–86 marks response streams closed and rejects subsequent writes; the invocation cleanup at 1102 closes the stream. Keeping an existing response stream cannot deliver results after the handler has completed.
- **Existing command does not cover the request:** SubmitAction.run in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts resolves context.widget or lastFocusedWidget. workbench.action.chat.submit is a widget submission action, not a stable extension API accepting an existing session identifier.
- **Proposed capabilities are partial:** src/vscode-dts/vscode.proposed.chatParticipantPrivate.d.ts exposes ChatRequest.sessionResource and active-panel session observation only as proposed/private additions. vscode.proposed.chatSessionsProvider.d.ts:435–471 and 527–599 supports provider-owned session history and active responses through a uniquely registered scheme; this does not supply the requested stable delivery contract for existing sessions.
