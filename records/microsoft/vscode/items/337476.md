# Issue #337476 — Modern UI abbreviates editor tabs instead of shrinking or line wrapping for `tabSizing: "shrink"` and `wrapTabs: true`

[https://github.com/microsoft/vscode/issues/337476](https://github.com/microsoft/vscode/issues/337476)

## Summary

Still open and plausible on main: the modern UI tab CSS swaps the classic clip+fade-hider truncation for an inner-label `text-overflow: ellipsis !important` with `flex: 1` and disables `.tab-fade-hider`, which changes how `tabSizing: shrink` tabs render overflow versus classic UI, matching the reported abbreviation-over-shrink/wrap behavior; confirming the exact wrap-trigger math would need a rendered repro.

## Change summary

With `tabSizing: shrink` and `wrapTabs: true`, the modern UI tab bar abbreviates tab labels (ellipsis, especially bad with duplicate filenames) instead of shrinking tab width or wrapping to a second row the way the classic UI did.

## Best solution

Decide, for modern UI's pill-tab design, whether per-tab text should ellipsize (current) or clip with a fade like classic UI, and whether the shrink/wrap thresholds in multiEditorTabsControl.ts need adjusting for the modern UI's extra chrome (icon/action reserved space) so `tabSizing: shrink`/`wrapTabs: true` behave consistently with classic UI; fix in src/vs/workbench/contrib/modernUI/browser/media/tabs.css and possibly src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/modernUI/browser/media/tabs.css`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`
- **Validation:** A component/visual fixture (see src/vs/workbench/test/browser/componentFixtures/editor/tabs.fixture.ts) rendering several same-named tabs under tabSizing: shrink + wrapTabs: true in modern UI, showing tabs shrink/wrap instead of ellipsizing to indistinguishability.
- **Behavior:**

  > With `workbench.editor.tabSizing: "shrink"` and `workbench.editor.wrapTabs: true`, when tabs no longer fit in one row the modern UI tab bar should shrink tab widths (down to the shrink min-width) and/or wrap to additional rows, the same as classic UI, rather than primarily showing abbreviated (ellipsized) labels that can make same-named files indistinguishable. Acceptance: with several open tabs sharing a filename, modern UI tabs end up at a similar width and visible-text ratio as classic UI under the same settings, instead of relying mainly on mid-text ellipsis.
- **Trace:**

  > Classic UI truncates the shrink/fixed tab label with `text-overflow: clip; flex: none` plus a separate `.tab-fade-hider` fade overlay (src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css:417-421). Modern UI instead sets `flex: 1 !important; min-width: 0; text-overflow: ellipsis !important` on the same selector and hides `.tab-fade-hider` entirely (src/vs/workbench/contrib/modernUI/browser/media/tabs.css:383-391). The outer `.tab.sizing-shrink` flex-basis/min-width rules are not overridden in modern UI's tabs.css, so the two renderers nominally share the same flex-shrink geometry for the tab itself — the divergence is isolated to how overflowing text within a tab is rendered. Do not change `multiEditorTabsControl.ts`'s wrapping/shrink computation (`updateTabsControlVisibility`, the `sizing-shrink`/`wrapTabs` class toggling around line 1774-1788/2000-2223) without first confirming via a rendered repro whether the actual shrink/wrap thresholds (not just the ellipsis styling) differ for modern UI, since extra modern-UI chrome (icon padding, action button reserved space) could also be consuming width that was available in classic UI.
- **Open decisions:**
  - Should modern UI's shrink/fixed tabs keep ellipsis styling (current), revert to classic's clip+fade-hider, or something hybrid — product/visual design call for the pill-tab aesthetic?
  - Do modern UI's extra per-tab chrome (icon/action reserved space) reduce the usable width enough that shrink/wrap thresholds themselves (not just text rendering) need adjusting?

## Evidence

- **classic CSS (clip):** src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css:417-421 sets `.tab.sizing-shrink > .monaco-icon-label > .monaco-icon-label-container { text-overflow: clip; flex: none; }` — classic UI clips text (no ellipsis) and relies on a separate `.tab-fade-hider` overlay.
- **modern CSS (ellipsis):** src/vs/workbench/contrib/modernUI/browser/media/tabs.css:383-391 instead sets `.tab:is(.sizing-shrink, .sizing-fixed) > .tab-label > .monaco-icon-label-container { flex: 1 !important; min-width: 0; text-overflow: ellipsis !important; }` and explicitly hides `.tab-fade-hider` (`display: none`) — a different truncation strategy for the same `sizing-shrink` class.
- **shared flex/width rules:** The outer `.tab.sizing-shrink` flex-basis/min-width rules (multieditortabscontrol.css:230-235) are not overridden in modernUI's tabs.css, so tab-level shrink/wrap math is nominally shared — the divergence is isolated to inner-label overflow handling, which is consistent with abbreviation appearing instead of visible shrink/wrap in the screenshots.
- **reporter repro:** Issue includes paired before/after screenshots showing identical settings and steps (Ctrl+N repeatedly) producing clip+partial-label-visible in classic UI vs ellipsis-heavy abbreviation in modern UI.
