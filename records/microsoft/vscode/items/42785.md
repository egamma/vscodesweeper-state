# Issue #42785 — Backspace at end of empty line doesn't delete whole line and go to end of above line

[https://github.com/microsoft/vscode/issues/42785](https://github.com/microsoft/vscode/issues/42785)

## Summary

Keep open: current Backspace behavior still removes indentation before joining lines, so the requested single-keystroke behavior remains missing. This accepted Backlog request has 48 upvotes; the closely matching Smart Backspace issue is newer and cannot serve as the canonical for this re-reviewed item.

## Change summary

Allow one Backspace at the end of a whitespace-only line to remove its indentation and newline and place the cursor at the preceding line's end.

## Best solution

Provide a native smart-backspace behavior in the editor deletion path, with a maintainer decision on whether it is opt-in or changes the default. Preserve ordinary deletion on nonblank lines and address the thread's need to retain indentation-only deletion when desired.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorDeleteOperations.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/cursorCommon.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add cursor-controller cases for a content line followed by a spaces-only or tabs-only line: under the chosen smart behavior, one CoreEditingCommands.DeleteLeft invocation must remove the blank line and leave the cursor at the preceding line's end. Cover undo, first-line safety, nonblank lines, selections, multiple cursors, and the retained conventional behavior. Run the targeted cursor suite through scripts/test.sh --run src/vs/editor/test/browser/controller/cursor.test.ts after implementation.
- **Behavior:**

  > Users want one Backspace at the end of an indentation-only line to remove the indentation and newline and move to the preceding line's end. Current behavior instead removes indentation first and joins lines only after reaching column 1. Acceptance should cover spaces and tabs, correct cursor placement, and undo restoring the deleted line. Ordinary text deletion and selected-text deletion must remain predictable; the maintainer must first decide how users enable this behavior and retain conventional indentation deletion.
- **Trace:**

  > Backspace is registered as deleteLeft in src/vs/editor/browser/coreCommands.ts and reaches DeleteOperations.deleteLeft in src/vs/editor/common/cursor/cursorDeleteOperations.ts. getDeleteLeftRange treats whitespace-only lines as indentation and returns a same-line range; getPositionAfterDeleteLeft crosses a line boundary only from column 1. The cursor-controller tests explicitly exercise this two-stage deletion, confirming the existing contract rather than a bug. editor.useTabStops, editor.trimAutoWhitespace, and the forward-Delete setting editor.trimWhitespaceOnDelete do not provide the requested behavior; deleteAllLeft also stops at column 1 before joining. Scope should remain the blank-line Backspace experience, not broader hungry deletion across nonblank code or unrelated Delete behavior. https://github.com/microsoft/vscode/issues/71506 describes matching demand but is newer than this report. The uncertainty is the public behavior choice: the report requests a default change, while a commenter asks to preserve an option for deleting indentation without removing the line.
- **Open decisions:**
  - Should smart blank-line Backspace replace the default behavior, be an opt-in editor setting, or be a separately bindable command while conventional Backspace remains unchanged?

## Evidence

- **Current Backspace path:** src/vs/editor/browser/coreCommands.ts:2047–2068 binds Backspace to deleteLeft and calls DeleteOperations.deleteLeft. In src/vs/editor/common/cursor/cursorDeleteOperations.ts, getDeleteLeftRange returns a same-line range to the preceding indentation stop when useTabStops is enabled; getPositionAfterDeleteLeft crosses to the preceding line only at column 1. Thus an indentation-only line requires additional Backspace presses.
- **Existing settings do not cover the request:** editor.useTabStops in src/vs/editor/common/config/editorOptions.ts controls indentation-stop deletion; disabling it instead deletes individual characters. editor.trimWhitespaceOnDelete is consumed by getDeleteRightRange for forward Delete line joining, not this Backspace path. editor.trimAutoWhitespace in src/vs/editor/common/config/editorConfigurationSchema.ts controls removal of trailing automatically inserted whitespace, not single-press backward joining.
- **Existing command is partial coverage:** DeleteAllLeftAction, command ID deleteAllLeft, in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts:752–827 deletes to column 1 when the cursor is beyond column 1 and joins the preceding line only when already at column 1. It does not alone perform the requested indentation removal and line join in one invocation.
