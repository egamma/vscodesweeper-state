# Issue #42785 — Backspace at end of empty line doesn't delete whole line and go to end of above line

[https://github.com/microsoft/vscode/issues/42785](https://github.com/microsoft/vscode/issues/42785)

## Summary

The native behavior remains missing on current main, and this Backlog request has 48 community upvotes. Keep it open as the older, more detailed report and consolidate the overlapping smart-backspace discussion here.

## Change summary

Make Backspace on an indentation-only line remove the line break and move to the end of the preceding line instead of deleting one indentation level at a time.

## Best solution

Add an opt-in smart-backspace mode to the editor deletion path, accounting for `editor.trimAutoWhitespace` and tab-stop behavior. The newer overlapping request at https://github.com/microsoft/vscode/issues/71506 should be consolidated into this older issue rather than maintained separately.

## Evidence

- **current source:** `DeleteOperations.getDeleteLeftRange` in `src/vs/editor/common/cursor/cursorDeleteOperations.ts` still deletes only to the previous indentation tab stop while the cursor is within whitespace; it joins the preceding line only after reaching column 1.
- **existing command limitation:** `deleteAllLeft` in `src/vs/editor/contrib/linesOperations/browser/linesOperations.ts` removes indentation when invoked within the line and removes the line break only when invoked again from column 1, so it does not natively provide the requested single-Backspace behavior.
- **community support:** The issue is in the Backlog milestone with 48 body upvotes, exceeding the 20-upvote promotion threshold.

- **workarounds:** Comments identify a custom keybinding and the Hungry Delete extension, but later reports describe extension reliability problems and continue to request native behavior; these are workarounds rather than coverage of the central ask.
