# Issue #330064 — Enable bypassing SSL validation and signature verification failures in integrated browser

[https://github.com/microsoft/vscode/issues/330064](https://github.com/microsoft/vscode/issues/330064)

## Summary

The integrated browser already ships exactly this capability: when a page fails TLS/certificate validation, the error interstitial offers a per-host, opt-in "Proceed anyway (unsafe)" action that trusts the specific certificate and reloads, so this looks already covered on current main rather than a gap to fill.

## Change summary

Add an opt-in way to bypass SSL/certificate validation failures when browsing in VS Code's integrated browser (for enterprise LANs with self-signed/MITM certs), ideally without exposing the bypass to agents.

## Best solution

Point the reporter at the existing "Proceed anyway (unsafe)" button on the certificate-error page (implemented via BrowserSessionTrust.trustCertificate/installCertErrorHandler in src/vs/platform/browserView/electron-main/browserSessionTrust.ts and rendered in src/vs/workbench/contrib/browserView/electron-browser/features/browserEditorErrorFeatures.ts); if their specific network failure doesn't surface that button (e.g. a MITM proxy failing below the certificate-error event, or a top-level navigation vs. subresource distinction), that would be a new, narrower report once confirmed.
