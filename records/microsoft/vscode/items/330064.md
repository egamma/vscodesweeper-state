# Issue #330064 — Enable bypassing SSL validation and signature verification failures in integrated browser

[https://github.com/microsoft/vscode/issues/330064](https://github.com/microsoft/vscode/issues/330064)

## Summary

Fresh, active thread (contributor already asked a clarifying question and the reporter answered with useful detail) about an enterprise-LAN mutual-TLS/client-cert scenario in the integrated browser; there's a real, narrow gap in browserView's cert handling worth routing to the area owner rather than closing.

## Change summary

Add an opt-in way to bypass SSL validation / auto-selected client-certificate failures in the integrated browser so enterprise LAN mTLS setups don't get stuck.

## Best solution

In src/vs/platform/browserView/electron-main, register a `select-client-certificate` handler on the browser view's WebContents (mirroring the existing `event.preventDefault()` pattern already used in src/vs/platform/webContentExtractor/electron-main/webPageLoader.ts:97) so the client can decline to send a certificate instead of Electron auto-picking one; the existing server-certificate trust flow in browserSessionTrust.ts already covers TLS validation errors, so this closes the remaining gap the reporter hit.
