# Issue #255626 — Review large context menu structures

[https://github.com/microsoft/vscode/issues/255626](https://github.com/microsoft/vscode/issues/255626)

## Summary

Keep open for a maintainer-led menu design review: current registrations still place equivalent Chat actions in different groups across Explorer, tabs, and the editor. User-configurable menus are related but do not settle the requested rules for the default menu structure.

## Change summary

Establish consistent placement and grouping rules to reduce complexity in Explorer, tab, and editor context menus.

## Best solution

Agree on a default menu hierarchy that prioritizes primary contextual actions and places equivalent secondary actions consistently across surfaces. Use this issue to settle those rules before making bounded changes to individual menu contributions; treat user customization as complementary work.

- **Trace:**

  > AttachFileToChatAction in src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts registers the same command under '5_chat', '2_chat', and '1_chat' for Explorer, tabs, and editor content respectively. src/vs/workbench/contrib/files/browser/fileActions.contribution.ts supplies neighboring file and tab action groups. The unresolved boundary is which actions should remain top-level versus move into submenus, and whether consistency means identical relative placement or an explicitly defined surface-specific hierarchy. Preserve command semantics, contextual availability, and keyboard access; do not expand this into a menus.json implementation. https://github.com/microsoft/vscode/issues/9285 tracks customization, while the newer closed https://github.com/microsoft/vscode/issues/276841 offers editor-consolidation ideas rather than a canonical for this broader review.
- **Open decisions:**
