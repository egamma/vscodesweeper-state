# Issue #331600 — Notebook Webview scroll distance is improperly reduced

[https://github.com/microsoft/vscode/issues/331600](https://github.com/microsoft/vscode/issues/331600)

## Summary

Well-diagnosed, source-verified bug: the Notebook Webview's wheel-forwarding code divides by `window.devicePixelRatio` for all Chrome versions, while the host-side `StandardWheelEvent` only does so for Chrome <=122 — the two paths have diverged since the version gate was added on the host side but not mirrored in the webview.

## Change summary

Notebook Webview mouse-wheel scrolling over Markdown/output content travels a much shorter distance than over code cells on modern (DPR-aware) Chrome, because of an extra devicePixelRatio division that the host-side scroll path no longer applies.

## Best solution

Apply the same Chrome-version gate used in src/vs/base/browser/mouseEvent.ts's StandardWheelEvent (shouldFactorDPR, chromeMajorVersion <= 122) to the wheelDelta*/devicePixelRatio division in src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts's handleWheel, or better, centralize the DPR-normalization logic so the two paths cannot drift apart again.
