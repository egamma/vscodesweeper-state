# Issue #330670 — VSCode appears to still require GitHub signin despite recent update in 1.133.0 to remove this restriction

[https://github.com/microsoft/vscode/issues/330670](https://github.com/microsoft/vscode/issues/330670)

## Summary

This is an active, still-evolving experimental feature (`chat.agentHost.allowSignedOutWhenUsable`, shipped 1.133/1.134); the reporter's follow-up shows a real remaining gap — a BYOK/local model already usable in the main Chat window isn't recognized as usable by the Agents window/Agent Host, so a signed-out air-gapped user still can't proceed past 'Add models or Sign In'.

## Change summary

After 1.134, the Agents window no longer force-prompts GitHub sign-in outright, but it still doesn't detect the reporter's already-configured local/BYOK model and offers only 'Add models' or 'Sign In', blocking use in an air-gapped network.

## Best solution

Have the Agent Host / chat team look at why a BYOK model visible to the main Chat window isn't surfaced to the signed-out Agents window gate — per src/vs/workbench/contrib/chat/browser/agentSessions/sessionTypeAvailability.ts a model must have `targetChatSessionType` set AND a resolvable `byokModelIdentifier` pointing at an `isBYOK` model that isn't hidden to count as a 'visible Agent Host BYOK model' (used in getSessionTypeAvailability/hasVisibleByokModelsTargetingSessionType and in agentHostSignedOutModelsNotification.ts); either that targeting needs to happen automatically for configured local models, or the docs/UI need to explain the extra step required.
