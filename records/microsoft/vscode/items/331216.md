# Issue #331216 — Migrate Customizations to Agent Host: Not Keyboard accessible

[https://github.com/microsoft/vscode/issues/331216](https://github.com/microsoft/vscode/issues/331216)

## Summary

Fresh, first-hand accessibility bug report from a VS Code contributor testing the new (setting-gated) customizations-to-agent-host migration; the underlying list widget does a full re-render on every enablement toggle, which plausibly explains the reported focus loss, and Space's semantics (select vs. toggle vs. fold) are genuinely ambiguous in the current implementation.

## Change summary

Keyboard navigation in the new AI Customizations management dialog is broken: pressing Space to disable a file loses list focus, and it's unclear whether Space selects, folds, or toggles enablement.

## Best solution

Audit the keyboard/ARIA model in aiCustomizationListWidget.ts (and the related toolsListWidget.ts tree) end-to-end: define one clear semantic for Space per row type, and stop commitDisplayEntries()'s full `list.splice` from dropping DOM focus on every enablement change — restore focus/selection after refresh.
