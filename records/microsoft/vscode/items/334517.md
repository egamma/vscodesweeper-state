# Issue #334517 — Codex and Claude automations do not allow checking "new worktree"

[https://github.com/microsoft/vscode/issues/334517](https://github.com/microsoft/vscode/issues/334517)

## Summary

Real, still-present bug: the automation dialog's worktree checkbox is gated by session-type capability, and for agent-host-backed session types that capability is hardcoded to only the Copilot CLI provider — Codex and Claude session types always report `supportsWorktreeConfiguration: false`, so the checkbox stays disabled regardless of whether those providers can actually use a worktree. The linked merged PR fixed unrelated automation/model and Codex-agent-path issues, not this gating. The issue also carries a real release milestone (1.138.0), which independently blocks any close proposal.

## Change summary

The "New Worktree" checkbox in the automation creation dialog is disabled/unavailable when the Codex or Claude session type (harness) is selected.

## Best solution

In `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts` (`_syncSessionTypesFromRootState`, ~line 3233), the mapped `ISessionType.supportsWorktreeConfiguration` is set via `agent.provider === CopilotCLISessionType.id`, so any agent-host agent other than Copilot CLI (including Codex and Claude) never advertises worktree support. A maintainer needs to decide the right per-provider criterion (e.g. advertise worktree support generally for agent-host session types, or gate on an actual protocol capability) and update this condition; that decision is why this shouldn't be treated as a mechanical auto-fix.
