# Issue #334360 — javascript intellisense not handling nested jsdoc parameter type with array of defined type

[https://github.com/microsoft/vscode/issues/334360](https://github.com/microsoft/vscode/issues/334360)

## Summary

Thanks for the detailed reproduction. The observed behavior is intentional because `[Inner]` is a one-element tuple type, not an array type; only its first element is contextually typed as `Inner`.

## Change summary

Treat every element of a JSDoc-annotated collection as the declared custom type for IntelliSense, hover, completion, and rename.

## Best solution

Annotate `inners` as `Inner[]`, `Array<Inner>`, or `Array.<Inner>` so every array element receives the `Inner` contextual type.

## Evidence

- **type syntax:** The reproduction declares `@property {[Inner]} inners`; TypeScript syntax defines `[Inner]` as a tuple containing exactly one `Inner`, while the TypeScript JSDoc documentation lists `Array<Inner>` and `Array.<Inner>` as array forms: https://www.typescriptlang.org/docs/handbook/jsdoc-supported-types.html
- **consistent semantics:** The first array-literal element occupies the tuple's declared position and receives the `Inner` contextual type; the second element is outside that one-element tuple, explaining why hover, completion, and rename do not associate it with the typedef.
