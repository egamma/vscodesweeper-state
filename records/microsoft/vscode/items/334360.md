# Issue #334360 — javascript intellisense not handling nested jsdoc parameter type with array of defined type

[https://github.com/microsoft/vscode/issues/334360](https://github.com/microsoft/vscode/issues/334360)

## Summary

JSDoc-driven IntelliSense for arrays of custom types is resolved entirely by the TypeScript language service bundled in extensions/typescript-language-features, not by VS Code core code, so the root cause (if confirmed) lives in microsoft/TypeScript; routing to the typescript area rather than closing.

## Change summary

When a function parameter's JSDoc type is an array of a custom/defined type, autocomplete, hover, and rename only work correctly for the first array element instead of all elements.

## Best solution

A typescript-language-features maintainer should reproduce against the bundled TypeScript version and, if confirmed, forward the JSDoc array-element type resolution defect to microsoft/TypeScript, since the type/rename logic for JSDoc-typed parameters is implemented in tsserver, not in this repo.
