# Issue #229008 — Adopt new call stack widget for exceptions

[https://github.com/microsoft/vscode/issues/229008](https://github.com/microsoft/vscode/issues/229008)

## Summary

Keep open: debug exceptions still render a linkified textual stack rather than testing's source-preview call stack widget. A maintainer explicitly accepted this adoption work, and no verified duplicate or completed implementation was found.

## Change summary

Show debug exception stacks using the source-preview call stack widget already used by testing.

## Best solution

Deliver the maintainer-endorsed exception-stack presentation using the shared CallStackWidget. First establish how exception-specific stack locations become source previews without incorrectly substituting the debugger's current paused stack.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/exceptionWidget.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts`, `src/vs/workbench/contrib/debug/browser/callStackWidget.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/testing/browser/testResultsView/testResultsViewContent.ts`
- **Validation:** Using a debug adapter that supplies exception details, stop on an exception with multiple source locations and verify navigable source previews. Include a rethrow or async case where the exception stack differs from the paused stack, missing or unavailable source locations, and exception details without a stack. Verify copy, close, keyboard access, and existing testing stack previews remain functional.
- **Behavior:**

  > Debug exceptions should present relevant stack locations with source previews comparable to the testing stack widget, making offending code understandable at a glance. Previewed locations must accurately represent the exception rather than misleadingly presenting a different paused stack. Exceptions with unavailable or unresolvable source locations must remain readable. Acceptance includes multi-frame exceptions, rethrow or async differences, missing sources, and preservation of copy, close, and accessible interaction.
- **Trace:**

  > ExceptionWidget._fillContainer() in src/vs/workbench/contrib/debug/browser/exceptionWidget.ts currently linkifies the textual exceptionInfo.details.stackTrace. DebugEditorContribution.toggleExceptionWidget() obtains thread.exceptionInfo and anchors this widget at an available paused frame. CallStackWidget in src/vs/workbench/contrib/debug/browser/callStackWidget.ts accepts structured CallStackFrame locations; testing's TestResultsViewContent.setCallStackFrames() demonstrates an actual consumer. The trace establishes the missing adoption, but not a reliable mapping from adapter-provided exception text to structured exception frames. Preserve exception-specific information, existing widget interactions, and the testing consumer; automatic parsing of arbitrary terminal output is not established as part of the maintainer's adoption commitment. The accepted direction is recorded at https://github.com/microsoft/vscode/issues/229008#issuecomment-2555975847; https://github.com/microsoft/vscode/issues/290498 documents why exception and paused stacks must not be assumed equivalent.
- **Open decisions:**
  - When exception stack text cannot be resolved into source locations, should the UI retain textual exception details alone or also offer a separately identified paused-stack preview?

## Evidence

The Backlog milestone and this commitment rule out a decline or low-traction close.
- **Existing-capability check:** src/vs/workbench/contrib/debug/browser/exceptionWidget.ts, ExceptionWidget._fillContainer(), renders exceptionInfo.details.stackTrace through LinkDetector.linkify() into a .stack-trace element. The repository search found that testing consumer, not an exception-widget consumer; the shared widget's comment claiming exception usage is not supported by the actual call sites.

IExceptionInfo in src/vs/workbench/contrib/debug/common/debug.ts carries DebugProtocol.ExceptionDetails, whereas CallStackWidget expects structured source locations. The conversion and exception-versus-paused-stack semantics remain to be established.
