# Issue #194366 — Applying Multiple Breakpoints to lines of code

[https://github.com/microsoft/vscode/issues/194366](https://github.com/microsoft/vscode/issues/194366)

## Summary

This remains a valid backlog feature request with 20 community upvotes. Current main supports toggling breakpoints at multiple cursors, but not across a selected line range or through the requested drag interaction; the gesture also needs design clarification because dragging an existing breakpoint is separately expected to move it.

## Change summary

Provide an efficient way to add breakpoints to every applicable line across a contiguous range.

## Best solution

Define a keyboard-accessible bulk-breakpoint workflow for a selected line range, with any pointer drag gesture using the same range semantics without conflicting with breakpoint movement. Preserve ordinary single-click breakpoint toggling and expose the interaction through existing debug accessibility help.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugEditorActions.ts`, `src/vs/workbench/contrib/debug/browser/breakpointEditorContribution.ts`, `src/vs/workbench/contrib/debug/browser/runAndDebugAccessibilityHelp.ts`, `src/vs/workbench/contrib/debug/test/browser/breakpoints.test.ts`
- **Validation:** Add a targeted debug editor action test proving that the chosen range interaction requests one breakpoint per intended line while existing single-line and multiple-cursor Toggle Breakpoint behavior remains unchanged; manually verify the equivalent keyboard workflow and accessibility-help text.
- **Behavior:**

  > Users should be able to add breakpoints efficiently across a contiguous range of lines without clicking every line individually. The capability must be operable from the keyboard as well as through any pointer gesture, and existing single-click breakpoint toggling must remain predictable. Acceptance should cover adding the intended range, avoiding duplicate breakpoints, and preserving current single-line and multiple-cursor behavior.
- **Trace:**

  > ToggleBreakpointAction in src/vs/workbench/contrib/debug/browser/debugEditorActions.ts currently takes only each selection's active-position line and explicitly excludes multi-line selection handling. BreakpointEditorContribution.registerListeners in src/vs/workbench/contrib/debug/browser/breakpointEditorContribution.ts adds or removes one gutter breakpoint on mouse-down and has no drag handler. The editor API exposes onMouseDrag, but the debug contribution does not consume it. https://github.com/microsoft/vscode/issues/88227 reserves overlapping design space for dragging an existing breakpoint to move it, and its attempted implementation in https://github.com/microsoft/vscode/pull/114717 was closed unmerged. Keep breakpoint movement, rich-breakpoint metadata, inline breakpoints, and existing single-click behavior outside this request unless the maintainer explicitly chooses shared gesture semantics.
- **Open decisions:**
  - Should dragging from an existing breakpoint create a range, move that breakpoint as requested by https://github.com/microsoft/vscode/issues/88227, or should range creation use a modifier or selection-based command to avoid the conflict?
  - Should bulk creation target every line in the selected range or only lines currently reported as valid breakpoint locations, and how should relocated or unverified adapter results be presented?

## Evidence

- **community demand:** The issue reached 20 body upvotes and was explicitly promoted to the Backlog by https://github.com/microsoft/vscode/issues/194366#issuecomment-1860956774.
- **current command gap:** ToggleBreakpointAction in src/vs/workbench/contrib/debug/browser/debugEditorActions.ts derives line numbers only from editor.getSelections().map(selection => selection.getPosition().lineNumber); its adjacent comment explicitly says it does not account for multi-line selections.
- **current pointer gap:** BreakpointEditorContribution.registerListeners in src/vs/workbench/contrib/debug/browser/breakpointEditorContribution.ts handles gutter onMouseDown and onMouseMove, but has no onMouseDrag handler, so current main does not implement range painting.

This issue asks to create breakpoints on every intervening line, so it does not meet the re-review requirement of the same reporter-observable behavior.
- **prior implementation status:** https://github.com/microsoft/vscode/pull/114717 attempted drag-and-drop breakpoint movement for https://github.com/microsoft/vscode/issues/88227, but it was closed without merging and did not implement range creation.
