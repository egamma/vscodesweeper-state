# Issue #98514 — Search error: ENAMETOOLONG

[https://github.com/microsoft/vscode/issues/98514](https://github.com/microsoft/vscode/issues/98514)

## Summary

Keep open: maintainers confirmed that large exclusion lists can prevent search from starting, and current source still passes those patterns directly to ripgrep as command-line arguments. This issue already owns the established duplicate cluster; the newer open report is not a valid canonical for this re-reviewed item.

## Change summary

Prevent large exclusion or inclusion lists from breaking Quick Open and text search with spawn ENAMETOOLONG.

## Best solution

Make search handle large pattern sets without exceeding process command-line limits, while preserving exclusion semantics and Search Only in Open Editors behavior. Cover both file and text search rather than removing --no-config or requiring users to abandon files.exclude.

Repeat text search with enough open-editor inclusion paths to exceed that limit and verify results remain restricted to open editors. Add executable regression coverage for large-pattern handling in both search engines, retaining existing glob and ignore-file semantics.
- **Behavior:**

  > Large exclusion lists can make Quick Open show only previously opened files and cause file or text search to fail with spawn ENAMETOOLONG. Search should still return eligible files and matches when pattern lists exceed the platform's command-line capacity, without silently dropping exclusions or widening the requested scope. Acceptance must cover both exclusion-heavy workspaces and Search Only in Open Editors with many file paths. Ordinary searches and File Explorer exclusion behavior must remain unchanged.
- **Trace:**

  > spawnRipgrepCmd in src/vs/workbench/services/search/node/ripgrepFileSearch.ts converts include and exclude patterns into -g arguments and passes the full array to cp.spawn. getRgArgs in src/vs/workbench/services/search/node/ripgrepTextSearchEngine.ts similarly expands patterns before spawning ripgrep. QueryBuilder.commonQuery and commonQueryFromFileList in src/vs/workbench/services/search/common/queryBuilder.ts explain the open-editors inclusion-list variant. The thread contains maintainer-confirmed command-length failures, and the current argument construction retains that failure mechanism; this review did not execute a reproduction. The remaining design work is how to handle large pattern sets across both engines while preserving glob precedence, ignore-file behavior, cancellation, and resource cleanup. Keep --no-config and existing files.exclude semantics: https://github.com/microsoft/vscode/issues/149727 explains why changing ripgrep configuration is not the solution. The maintainer's related discussion at https://github.com/microsoft/vscode/issues/109380#issuecomment-716751104 is a design lead, not evidence of a landed implementation.
