# Issue #202024 — Definition Completion is not invoked for non-word tokens (like ++ operators) when ctrl-hovering

[https://github.com/microsoft/vscode/issues/202024](https://github.com/microsoft/vscode/issues/202024)

## Summary

Keep open: current source still gates Ctrl-hover definition lookup on the language's word pattern, leaving operator definitions unsupported unless operators are treated as words globally. No verified older canonical issue owns this request.

## Change summary

Allow Ctrl-hover to request and preview definitions for operators such as ++ without changing the language's general word definition.

## Best solution

Support language-aware definition lookup for non-word tokens in the editor's definition-link contribution while preserving normal word-based editor behavior. The maintainer should decide whether this requires provider-specific trigger metadata or a broader lookup policy.

## Evidence

- **Current lookup gate:** src/vs/editor/contrib/gotoSymbol/browser/link/goToDefinitionAtPosition.ts:129–159: GotoDefinitionAtPositionEditorContribution.startFindDefinition calls getWordAtPosition and returns when no word exists, before invoking findDefinition. Thus a ++ token excluded by the language's word pattern cannot trigger the definition preview.
- **Existing capability is only a workaround:** src/vscode-dts/vscode.d.ts:6643–6663 exposes LanguageConfiguration.wordPattern as the language-wide word definition. Changing it can make operators eligible, as the supplied discussion explains, but also changes other word-based features. extensions/cpp/language-configuration.json:93 still excludes + and -; src/vs/editor/common/languages.ts:1551–1556 defines DefinitionProvider without independent trigger metadata.
