# Issue #131746 — Workspace trust header shadow doesn't show up if you tab through file

[https://github.com/microsoft/vscode/issues/131746](https://github.com/microsoft/vscode/issues/131746)

## Summary

The workspace trust editor's DomScrollableElement uses built-in shadows, but tabbing through focusable elements likely doesn't trigger scanDomNode/onDidScroll to update the shadow state — still present on main as no fix has addressed this keyboard-navigation shadow issue.

## Change summary

The workspace trust editor's header shadow doesn't appear when keyboard-tabbing causes the body to scroll, only when using mouse scroll.

## Best solution

After keyboard navigation causes a focus change inside the scrollable body, call `bodyScrollBar.scanDomNode()` to re-evaluate the scroll position and trigger the shadow update. A focus-in listener on the scrollable content that calls scanDomNode would address this.
