# Issue #332956 — GIT Count BAdge

[https://github.com/microsoft/vscode/issues/332956](https://github.com/microsoft/vscode/issues/332956)

## Summary

This is the same complaint already tracked, in near-identical wording, by the open https://github.com/microsoft/vscode/issues/313682 — with `scm.countBadge` set to `all`, the Activity Bar badge only reflects the focused repository's change count instead of the sum across all repositories. Proposing to consolidate on the earlier report.

## Change summary

With `scm.countBadge` set to `all`, the Source Control Activity Bar badge only shows the currently-selected repository's pending-changes count instead of the sum across all repositories.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/313682, which reports the exact same symptom (regression: badge shows only the focused repository's count even with the setting on `all`) and is still open with no traction. If pursued, the likely area is `src/vs/workbench/contrib/scm/browser/activity.ts`, where `_countBadgeRepositories` for the `'all'` case sums over `this._visibleRepositories` (from `ISCMViewService.visibleRepositories`) rather than all repositories — `visibleRepositories` can be narrowed to a single repo when `scm.repositories.selectionMode` is `single` (see `src/vs/workbench/contrib/scm/browser/scmViewService.ts` around the `runOnChange(this.selectionModeConfig, ...)` handler), which would make the `'all'` badge setting silently behave like `'focused'`.
