# Issue #155333 — Improve how we handle edit sessions which exceed the size limit

[https://github.com/microsoft/vscode/issues/155333](https://github.com/microsoft/vscode/issues/155333)

## Summary

A real gap remains: current main still rejects edit sessions above the fixed 1.9 MB client limit rather than storing them more efficiently. The Backlog milestone indicates accepted, unscheduled work, and no canonical issue owns the broader storage improvement.

## Change summary

Handle oversized Cloud Changes edit sessions through a more efficient storage strategy while retaining an abuse-prevention limit.

## Best solution

Improve the Cloud Changes serialization/storage path under `src/vs/workbench/contrib/editSessions`—for example through more compact encoding or bounded chunking—while retaining server-enforced quotas and clear failure handling.
