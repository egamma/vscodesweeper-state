# Issue #316266 — MCP stdio servers pointing to a batch file on Windows cause two issues

[https://github.com/microsoft/vscode/issues/316266](https://github.com/microsoft/vscode/issues/316266)

## Summary

Both issues are confirmed in the current source: the spawn call lacks `windowsHide: true`, and while the forceful kill (at 20s) does use `taskkill /T`, the polite kill is a no-op on Windows — so processes that don't exit on stdin close accumulate during the grace period, and the visible console window appears every time a .bat-based server starts.

## Change summary

MCP stdio servers launched from .bat files on Windows show a visible cmd.exe popup and can leave orphaned process trees when servers don't exit promptly on stdin close.

## Best solution

Add `windowsHide: true` to the spawn options in `extHostMcpNode.ts` (line 100). For orphaned processes, add a Windows-specific polite kill path in `mcpStdioStateHandler.ts` that calls `killTree` with `forceful: false` (taskkill /T without /F) — currently the `if (!isWindows)` guard skips it entirely.
