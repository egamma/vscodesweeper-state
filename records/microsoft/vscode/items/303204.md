# Issue #303204 — Searching for file using copy/pasted Excel cell text

[https://github.com/microsoft/vscode/issues/303204](https://github.com/microsoft/vscode/issues/303204)

## Summary

The bug remains source-reproducible on current main: the Explorer's window-level paste listener treats Excel's mixed text-and-image clipboard payload as a file paste even when focus is in the tree's find input. The existing bug classification bars a judgment close, and the behavior has a bounded fix and test surface.

## Change summary

Pasting a whole Excel cell into the Explorer file finder inserts its text but also incorrectly prompts to paste Excel's clipboard image payload as image.png.

## Best solution

Ensure paste events originating in the Explorer tree's find input remain text-input operations, while preserving native file paste behavior when the Explorer tree itself is the target.

- **Trace:**

  > ExplorerView in src/vs/workbench/contrib/files/browser/views/explorerView.ts registers a window-level paste listener and gates it only on Explorer focus and clipboardData.files.length. The tree find input is created inside the widget by FindWidget in src/vs/base/browser/ui/tree/abstractTree.ts, so its paste bubbles through that listener while the Explorer still reports focus. Excel supplies a mixed clipboard payload whose file is named image.png; pasteFileHandler in src/vs/workbench/contrib/files/browser/fileActions.ts consequently enters native-file confirmation. Keep native file paste on the Explorer tree unchanged and limit the regression test to distinguishing the find-input target from the file tree; the separate resize suggestion in the reporter's follow-up is out of scope.

- **observed prompt path:** src/vs/workbench/contrib/files/browser/fileActions.ts:1123-1148 treats that FileList as a native file paste and constructs the exact confirmation message "Are you sure you want to paste '{0}'?", explaining the reported image.png dialog.
