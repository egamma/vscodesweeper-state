# Issue #297470 — Should support external browsers

[https://github.com/microsoft/vscode/issues/297470](https://github.com/microsoft/vscode/issues/297470)

## Summary

Keep open: agent-driven testing in separate Edge, Chrome, and Firefox instances remains distinct from the integrated Chromium browser tools. A later maintainer comment explicitly identifies this issue as the backlog home for connecting agent tools to external browsers.

## Change summary

Allow agents to validate a feature across external Edge, Chrome, and Firefox instances, including independent subagent interactions.

## Best solution

Provide browser-specific agent automation targets without requiring other browser engines to be embedded in VS Code. First establish the supported launch/attachment model and how parallel subagents select and isolate their browser targets.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts`, `src/vs/platform/browserView/node/playwrightService.ts`, `src/vs/platform/browserView/common/playwrightService.ts`
- **Validation:** Use a local test page with an interaction and observable result. Ask three subagents to exercise it in actual Edge, Chrome, and Firefox instances; verify browser identity, independent targeting, successful interaction in each, and unchanged integrated-browser operation.
- **Behavior:**

  > A request to verify a feature in Edge, Chrome, and Firefox should allow agents to interact with each actual browser, rather than running three integrated Chromium pages. Parallel subagents must address their intended browser instances without accidentally acting on one another's targets. Acceptance should demonstrate an interaction and browser-specific result from all three browsers while preserving existing integrated-browser workflows.
- **Trace:**

  > OpenBrowserToolData and IOpenBrowserToolParams in src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts currently describe integrated-browser page creation with url and forceNew inputs. PlaywrightService._initSession in src/vs/platform/browserView/node/playwrightService.ts creates an agent-scoped browser-view group and connects playwright.chromium over that group's CDP transport. This establishes the current integrated-only path but does not establish an external-browser backend or Firefox transport. The service contract is in src/vs/platform/browserView/common/playwrightService.ts. Preserve integrated-browser sharing, approval, network restrictions, and session isolation; embedding other engines is outside this request. https://github.com/microsoft/vscode/issues/318629#issuecomment-4558861406 explicitly preserves external-browser agent connectivity while declining alternative embedded engines. The uncertainty starts at external-browser ownership, selection, and parallel subagent targeting.
- **Open decisions:**
  - Should agents launch isolated external browser instances, attach to existing user-owned instances, or support both?
  - How should browser selection and target ownership be exposed so parallel subagents reliably address separate Edge, Chrome, and Firefox instances?
