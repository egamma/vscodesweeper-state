# Issue #193347 — Ignore code move with too many changes

[https://github.com/microsoft/vscode/issues/193347](https://github.com/microsoft/vscode/issues/193347)

## Summary

Keep open: current move detection does not reject candidates based on the amount of actual edits within the detected block. Existing controls and the older related reports do not cover this accepted, team-authored request.

## Change summary

Suppress code-move annotations when the matched blocks contain too many changes to be meaningfully presented as a move.

## Best solution

Define an acceptable edit-content boundary for move detection in the advanced diff algorithm, retaining useful unchanged and lightly edited moves while presenting heavily rewritten candidates as ordinary changes.

## Evidence
