# Issue #314682 — [bug] GitHub Copilot: Raptor mini (Preview) fails with “Sorry, no response was returned” when `execute` tools are enabled

[https://github.com/microsoft/vscode/issues/314682](https://github.com/microsoft/vscode/issues/314682)

## Summary

The root cause is almost certainly model-side content filtering being triggered by tool names like 'killTerminal' and 'execute' — confirmed by multiple reporters and the workaround of disabling those tools. This is a real usability problem for the Raptor mini (Preview) model, worth routing to the Copilot area for a service-side fix or tool-name mitigation.

## Change summary

The Raptor mini (Preview) model fails with 'no response was returned' when terminal-related tools with names containing 'kill' or 'execute' are enabled, likely due to overly aggressive content safety filtering on the model side.

## Best solution

The Copilot team should investigate whether the model-side content filter can be tuned to not flag tool definition names like 'killTerminal' and 'execute'. Alternatively, VS Code could consider aliasing or renaming tool identifiers sent to models prone to content-filter false positives (e.g. 'terminateTerminal' instead of 'killTerminal'), though this is a workaround for a model-side issue.
