# Issue #286073 — `Copy Breadcrumbs Path` should not be in editor title context menu

[https://github.com/microsoft/vscode/issues/286073](https://github.com/microsoft/vscode/issues/286073)

## Summary

The placement concern remains: current main still exposes Copy Breadcrumbs Path in the editor title context menu, and the proposed breadcrumbs menu never merged. Keep this team-authored request open to settle the interaction across tab layouts; the older related requests do not report the same action-placement problem.

## Change summary

Move Copy Breadcrumbs Path from the editor title context menu to a context menu on breadcrumb items.

## Best solution

Make breadcrumb-specific copying discoverable on the breadcrumbs themselves, with an explicit invocation target rather than an implicit current-view target. Agree on the no-tabs interaction and clicked-item copy semantics before implementing the editor breadcrumbs menu.

- **Likely files:** `src/vs/base/browser/ui/breadcrumbs/breadcrumbsWidget.ts`, `src/vs/platform/actions/common/actions.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbs.ts`
- **Validation:** In Code OSS, open a file with nested document symbols and exercise breadcrumb context menus with workbench.editor.showTabs set to multiple, single, and none. Verify the agreed copy target for a clicked ancestor versus the cursor's current symbol, confirm the agreed editor-title menu placement, and verify that Command Palette invocation and keyboard breadcrumb navigation remain usable.
- **Behavior:**

  > Copy Breadcrumbs Path currently appears among editor-title file actions even though its result depends on the current symbol path. The requested experience exposes breadcrumb-specific copying directly on the breadcrumbs and removes that ambiguity from the editor title menu. Acceptance must cover multiple-tab, single-tab, and no-tabs layouts, plus an explicit outcome when the clicked breadcrumb differs from the cursor's current symbol. Existing Command Palette access and keyboard navigation must remain usable.
- **Trace:**

  > CopyBreadcrumbPath in src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts registers breadcrumbs.copyPath on MenuId.EditorTitleContext and derives clipboard text from the active editor's outline, not a clicked breadcrumb. BreadcrumbsControl wires BreadcrumbsWidget selection and focus events; the widget in src/vs/base/browser/ui/breadcrumbs/breadcrumbsWidget.ts has no context-menu event. The unmerged prototype at https://github.com/microsoft/vscode/pull/286109 identifies the widget, menu registry, breadcrumbs configuration bindings, and control as the likely boundary, but is not a landed solution. The discussion at https://github.com/microsoft/vscode/issues/286073 leaves the no-tabs menu compromise contested. Related menu requests at https://github.com/microsoft/vscode/issues/156457 and https://github.com/microsoft/vscode/issues/56494 provide coordination context, not same-symptom duplicate ownership. Keep unrelated file-management actions and broader breadcrumb-menu expansion outside this request unless explicitly approved.
- **Open decisions:**
  - Should inline breadcrumbs in single-tab and no-tabs layouts show only breadcrumb-specific actions, or retain editor-title actions alongside them?
  - When invoking Copy Breadcrumbs Path on an ancestor breadcrumb, should the copied symbol path end at that clicked item or retain the complete current cursor-derived path, and should file/folder breadcrumbs expose this action?
