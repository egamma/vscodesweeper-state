# Issue #324392 — Shell integration: executeCommand().read() stream and onDidEndTerminalShellExecution both permanently silent (zero data) for certain multi-line / subshell command shapes

[https://github.com/microsoft/vscode/issues/324392](https://github.com/microsoft/vscode/issues/324392)

## Summary

Keep this open and route it to terminal owners: the report documents repeated zero-output executions and missing completion events, with command-line corruption that the verified related reports do not fully cover. Current source exposes relevant execution-matching failure paths, but does not establish a complete diagnosis or a landed fix.

## Change summary

Bash multiline groups and subshell commands can complete visibly while their extension-facing execution streams remain empty and never finish.

## Best solution

Ensure the execution returned by executeCommand remains associated with the actual Bash command, receives its output, and completes with the corresponding end event. Diagnose shell marker emission and execution identity together rather than treating raw OSC marker delivery as the API contract.

- **Execution identity failure path:** In src/vs/workbench/api/common/extHostTerminalShellIntegration.ts, InternalTerminalShellIntegration.startShellExecution matches high-confidence starts against pending executions by command equality or isSubExecution. If neither matches, it creates a different execution; emitData feeds only currentExecution. The reported command containing an appended newline and 'boom' therefore warrants checking whether the returned execution remains pending while another execution receives output.

This is a concrete source-level lead for the grouped multiline case, not proof that the reporter's exact shell sequence takes that path.
