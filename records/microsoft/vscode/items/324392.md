# Issue #324392 — Shell integration: executeCommand().read() stream and onDidEndTerminalShellExecution both permanently silent (zero data) for certain multi-line / subshell command shapes

[https://github.com/microsoft/vscode/issues/324392](https://github.com/microsoft/vscode/issues/324392)

## Summary

This is a well-supported terminal shell-integration bug that remains relevant on main. It adds a broader zero-data failure and corrupted command-line evidence not fully owned by either existing narrower report.

## Change summary

Multi-line and subshell commands can leave both TerminalShellExecution.read() and onDidEndTerminalShellExecution permanently silent while corrupting the reported command line.

## Best solution

Correct bash command-boundary reporting so OSC 633 E/C precede output and D reliably completes both API surfaces. Add coverage for literal-newline brace groups and subshell commands, including stderr output.
