# Issue #156377 — Progressive behavior of the title bar elements

[https://github.com/microsoft/vscode/issues/156377](https://github.com/microsoft/vscode/issues/156377)

## Summary

Keep open: this team-authored design request remains unresolved on current main, and the maintainer discussion explicitly leaves the progressive compact-versus-hide behavior open. The related command-center report is newer and narrower, so it cannot absorb this re-reviewed issue.

## Change summary

Make the Command Center and layout controls progressively compact or hide as the title bar runs out of horizontal space.

## Best solution

Define and implement a consistent title-bar progression that preserves the most important controls at narrow widths, compacting the Command Center and layout controls according to an agreed priority before anything becomes inaccessible.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts`, `src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css`, `src/vs/workbench/test/browser/parts/titlebar/titlebarPart.test.ts`
- **Validation:** Extend the title-bar part tests with measured narrow-width cases that verify the agreed progression and restoration order, then manually resize a custom-title-bar window to confirm menu items, Command Center, layout controls, and window controls remain reachable.
- **Behavior:**

  > The custom title bar should adapt progressively as horizontal space decreases instead of allowing the Command Center and layout controls to crowd out other title-bar elements. The chosen compact states must remain understandable and operable, restore when space returns, and preserve access to every displaced action. Acceptance should cover wide, intermediate, and narrow widths with the menu bar, Command Center, layout controls, and window controls enabled.
- **Trace:**

  > The centered title-bar layout in src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css currently uses 20% / 60% / 20% regions, while BrowserTitlebarPart.updateTitleBarToolBarOverflow in src/vs/workbench/browser/parts/titlebar/titlebarPart.ts only removes optional center-adjacent and update toolbars. CommandCenterControl in src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts can change its rendered label/icon composition, and `workbench.layoutControl.type` already proves that layout actions have both multi-toggle and single-menu presentations, but neither responds automatically to title-bar width. The existing measured-width test in src/vs/workbench/test/browser/parts/titlebar/titlebarPart.test.ts provides a suitable validation pattern. Preserve user-selected visibility settings, window controls, and the existing menu-bar overflow behavior; the unresolved boundary is the progression and priority among compact and hidden states. Related reports: https://github.com/microsoft/vscode/issues/236302 and https://github.com/microsoft/vscode/issues/240845.
- **Open decisions:**
  - As space decreases, should the Command Center and layout controls compact to single-icon/menu forms before hiding, and in what user-visible priority order should those transitions occur?
