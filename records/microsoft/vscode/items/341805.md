# Issue #341805 — Agents window change count uses a stale local base branch when origin/<base> is unreadable

[https://github.com/microsoft/vscode/issues/341805](https://github.com/microsoft/vscode/issues/341805)

## Summary

Thanks for the detailed report. The code path still exists on main: when `git show-ref --verify` fails for an unreadable `origin/<base>`, the code falls back to the local base branch, which can be stale. The bug is real and triggers only with a corrupt ref.

## Change summary

A corrupt origin/<base> ref makes the Agents window count changes against a stale local base branch, inflating the change count.

## Best solution

Distinguish a missing remote-tracking ref from an unreadable one. For an unreadable ref, don't fall back to the local branch. Use HEAD (or the reflog creation point) as the base and log once per repository.
