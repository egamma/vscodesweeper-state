# Issue #341864 — VS Code translates URL encoding to space when opening link

[https://github.com/microsoft/vscode/issues/341864](https://github.com/microsoft/vscode/issues/341864)

## Summary

Thanks for the report. The source suggests this still happens on main: URIs that pass through the opener are decoded with toString(true) and re-encoded with encodeURI, which leaves a decoded '+' unescaped. A maintainer should check whether the earlier report (https://github.com/microsoft/vscode/issues/124704) is still open before treating this as a duplicate.

## Change summary

Ctrl+clicking a link containing percent-encoded characters such as %2B opens a URL where the encoding has been lost (a '+' reads as a space), changing the query.

## Best solution

Make the opener preserve the original percent-encoding when opening a link, for example by using the raw string or toString(false) instead of the decode-then-encodeURI path in the opener's external-URI resolution. Then add a unit test for URLs containing %2B and %3C.
