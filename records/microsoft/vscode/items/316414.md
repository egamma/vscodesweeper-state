# Issue #316414 — Copying files via dragging them into the editor throws consistent errors

[https://github.com/microsoft/vscode/issues/316414](https://github.com/microsoft/vscode/issues/316414)

## Summary

The reported path remains present on main: importing a local file through Explorer reaches an unconditional `fs.promises.chmod` after the file is copied, including on Windows. The failure needs targeted diagnosis rather than closure because the source confirms the operation but not which Windows filesystem condition makes it reject.

## Change summary

Dragging a file from Windows File Explorer into VS Code's Explorer copies it and then consistently surfaces an error from the mode-restoration `chmod` step.

## Best solution

Make local file copying complete without a post-copy permissions error on Windows while preserving Unix mode behavior and Windows read-only semantics. Diagnose the failing filesystem condition and cover it in the base filesystem copy tests before changing the shared copy helper.
