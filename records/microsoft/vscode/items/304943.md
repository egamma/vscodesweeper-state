# Issue #304943 — `code-insiders --sessions` sometimes opens VS Code instead of Sessions App

[https://github.com/microsoft/vscode/issues/304943](https://github.com/microsoft/vscode/issues/304943)

## Summary

Team-authored bug about the `--sessions` (now `--agents`) CLI flag opening the wrong window type when the Sessions App was closed via the X button rather than Cmd+Q. The agents window architecture has been substantially refactored since filing (sub-app removal in #314409, flow cleanup in #321038), which may have resolved this, but no commit references this issue — keeping open for verification.

## Change summary

Running `code-insiders --sessions` after closing the Sessions App via the X button opens VS Code Insiders instead of the Sessions App.

## Best solution

Verify whether the bug still reproduces after the agents window refactoring (sub-app removal #314409, agents window flow cleanup #321038). The launch path in `src/vs/platform/launch/electron-main/launchMainService.ts` now calls `openAgentsWindow` when `args['agents']` is set, and `src/vs/platform/windows/electron-main/windowsMainService.ts` handles the window opening with `forceNewWindow: true`. On macOS, clicking X closes only the window while the process stays alive — the second CLI invocation hits `launchMainService` which should correctly route to `openAgentsWindow`. If still reproducing, the fix likely belongs in the window-reuse logic in `windowsMainService.ts`.
