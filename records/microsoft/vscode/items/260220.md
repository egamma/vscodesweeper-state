# Issue #260220 — Copilot Chat: Search excludes files and folders that are in .gitignore

[https://github.com/microsoft/vscode/issues/260220](https://github.com/microsoft/vscode/issues/260220)

## Summary

Keep open: VS Code 1.107 added an agent-controlled way for text search to include ignored files, but the broader request for workspace-defined Copilot-specific inclusion and exclusion rules remains. This team-authored, 42-upvote Backlog feature request is protected from a judgment close and has already passed the community promotion threshold.

## Change summary

Allow workspaces to configure which files Copilot search tools include or exclude independently of `.gitignore` and general workspace exclusions.

## Best solution

Define one workspace-level Copilot search-boundary mechanism, usable consistently by file, text, and semantic search as well as remote indexing, with an explicit policy for whether `.gitignore` is honored. Preserve the 1.107 text-search override as an agent fallback rather than treating it as full coverage of workspace-defined rules.

## Plan brief

- **Likely files:** `extensions/copilot`
- **Validation:** Add integration coverage showing that a workspace-configured ignored folder is searchable by the relevant Copilot search tools while a separately configured excluded folder remains omitted, including the default `.gitignore` behavior.
- **Behavior:**

  > A workspace can define Copilot-specific file-search boundaries independently of source-control ignores. Users can make selected `.gitignore`d content available to Copilot while excluding other tracked or untracked content from applicable search and indexing tools. The behavior should be predictable without relying on the model to infer a per-call include-ignored parameter, and the default for existing workspaces must be explicitly defined. Acceptance should cover file search, text search, semantic search, and remote indexing to the extent each surface supports the shared policy.
- **Trace:**

  > VS Code 1.107 introduced an agent-controlled text-search parameter for searching ignored files, documented at https://code.visualstudio.com/updates/v1_107#_text-search-tool-can-search-ignored-files. In https://github.com/microsoft/vscode/issues/260220#issuecomment-3653023223, the maintainer confirms that this parameter is selected by the agent and that custom instructions can only hint when it should be used. That covers a single search invocation but not the issue's requested declarative boundary shared across file_search, text/grep search, semantic search, and remote indexing. The implementation surface is under extensions/copilot, but the exact files cannot be bounded until maintainers decide whether this is a dedicated ignore file, VS Code setting, or shared contract consumed by local and remote providers. Do not conflate this request with the separate behavior of already-open files entering conversational context, raised in https://github.com/microsoft/vscode/issues/260220#issuecomment-3730838469.
- **Open decisions:**
  - Should the public contract be a `.copilotignore` file, a VS Code setting, or both, and which source takes precedence when they disagree?
  - Should `.gitignore` remain honored by default with an opt-out, or should Copilot search boundaries be independent by default?
  - Must the same policy govern file search, text search, semantic search, and remote indexing, or may users configure those surfaces separately?
