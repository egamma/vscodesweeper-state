# Issue #335863 — New automation folder picker has two focus points

[https://github.com/microsoft/vscode/issues/335863](https://github.com/microsoft/vscode/issues/335863)

## Summary

Real, traceable bug in the new Automations dialog's toolbar wrapping: the workspace picker (and likely the harness/session-type picker) is rendered inside a generic `AutomationPickerActionViewItem`, whose outer container is also independently focusable, giving two tab stops for one control.

## Change summary

In the new automation dialog, the folder picker (and reportedly the New Session button) has two Tab stops instead of one; the extra, unrounded-focus stop does nothing on Space/Enter.

## Best solution

In src/vs/sessions/contrib/automations/browser/automationDialog.ts, make AutomationPickerActionViewItem's outer element permanently non-focusable (its rendered content — WorkspacePicker's own `a.action-label` trigger — already owns tabbing, click, and Enter/Space handling), so the dialog's custom Tab-order walker (registerAutomationDialogKeyboardNavigation's getFocusableElements/visibleFocusableElements) only counts the real trigger.

## Evidence

- **inner trigger always focusable:** src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts `_addTrigger()` (lines ~601-635) creates `a.action-label` with `trigger.tabIndex = 0` and its own click/Enter/Space handlers — this is the 'rounded focus' stop that works.
- **outer wrapper also focusable:** src/vs/sessions/contrib/automations/browser/automationDialog.ts `AutomationPickerActionViewItem` (line 931) extends BaseActionViewItem and calls `workspacePicker.render(container)` inside its own `render()`. BaseActionViewItem manages `this.element.tabIndex` via focus()/blur()/setFocusable() (src/vs/base/browser/ui/actionbar/actionViewItems.ts lines 180-206), so the wrapping container itself can also carry tabIndex 0 through the toolbar's roving-tabindex logic, while its bound action (AUTOMATIONS_WORKSPACE_PICKER_ACTION_ID / AUTOMATIONS_HARNESS_CHIP_ACTION_ID) is a no-op ('handled by action view item'), matching the reported 'unrounded focus, Space/Enter does nothing'.
- **custom tab-order counts both:** registerAutomationDialogKeyboardNavigation's visibleFocusableElements() (automationDialog.ts lines 118-142) filters only on `element.tabIndex < 0`, so both the outer container (when focusable) and the inner trigger anchor pass the filter and each get their own Tab stop.
- **same pattern reused elsewhere:** The same AutomationPickerActionViewItem wraps sessionTypePicker.render(container) for the harness chip (automationDialog.ts ~line 1324), and the reporter's follow-up comment says the New Session button has the same problem, suggesting a shared root cause across sessions.contrib pickers rendered via generic ActionViewItem wrappers.
