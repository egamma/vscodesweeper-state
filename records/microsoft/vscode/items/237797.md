## Summary

Keep open: commenters independently confirm recurring connection failures, and deleting cached server state or killing the server is a workaround, not evidence of a permanent fix. Current source still has a potentially relevant stale-socket reuse path; no concrete fix or verified open duplicate was found.

## Change summary

Remote-SSH connections repeatedly fail with AsyncPipeFailed(NotFound), requiring users to reset or restart the remote VS Code Server.

## Best solution

Establish why the reused remote server endpoint becomes unavailable, then make the core CLI server lifecycle recover from that condition without requiring users to delete their server installation. Preserve successful server reuse and distinguish missing endpoints from unrelated connection errors.

## Plan brief

- **Likely files:** `cli/src/tunnels/code_server.rs`, `cli/src/tunnels/control_server.rs`, `cli/src/tunnels/server_bridge.rs`, `cli/src/tunnels/paths.rs`, `cli/src/async_pipe.rs`
- **Validation:** Reproduce a Remote-SSH reconnect failure on a Linux host while retaining the cached CLI server state, collecting both Remote-SSH output and the server log. Establish an automated CLI regression scenario for the confirmed endpoint-invalidating condition; it must fail before the eventual change and pass afterward. Verify ordinary reconnects still reuse a healthy server and preserve installed extensions and settings.
- **Behavior:**

  > Connecting through Remote-SSH can repeatedly fail with AsyncPipeFailed(NotFound) until cached server state is removed or the server is killed. A previously used host should reconnect without requiring deletion of its VS Code Server installation. Acceptance should cover the diagnosed failure condition, successful reuse of a healthy server, and preservation of remote settings and extensions. Unrelated authentication, permission, and forwarding errors must remain visible rather than being treated as stale-server failures.
- **Trace:**

  > The reporter's attached log shows Remote-SSH's exec-server mode repeatedly identifying the same existing server PID. In cli/src/tunnels/code_server.rs, ServerBuilder::get_running reconstructs a socket endpoint from the existing logfile after checking process liveness. In cli/src/tunnels/control_server.rs, handle_serve caches or reuses that server, and attach_server_bridge reaches ServerBridge::new in cli/src/tunnels/server_bridge.rs; the Unix connection in cli/src/async_pipe.rs produces the reported error class when the endpoint is absent. Source inspection establishes this candidate path but not why the reporter's endpoint became unavailable, whether the cached process and endpoint remained consistent, or whether the same trigger persists on current main. Diagnose that lifecycle boundary before selecting a change; do not broaden the work into unrelated Remote-SSH forwarding or terminal CLI IPC failures. The closed related report at https://github.com/microsoft/vscode/issues/224384 provides historical corroboration, not a fixing commit or duplicate canonical.
