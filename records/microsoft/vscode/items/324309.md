## Summary

The missing capability remains valid, but the older, open multiple-workspaces issue already owns the same observable problem: switching between independent editing contexts without separate OS windows. Consolidate there while retaining this report's sidebar proposal and contributor prototype.

## Change summary

Provide a project-session sidebar that switches between live, isolated editing contexts within one visible editor window.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/43188 is OPEN, was created on 2018-02-08, and explicitly requests multiple workspaces open simultaneously in the same window. It predates this report and addresses the same user-visible limitation, satisfying the stronger duplicate bar for a re-reviewed item.
- **Independent contexts, not multi-root:** The canonical discussion explicitly distinguishes separate workspaces from multi-root workspaces at https://github.com/microsoft/vscode/issues/43188#issuecomment-1656676391. Window/taskbar clutter and independently scoped workspace panes are also described at https://github.com/microsoft/vscode/issues/43188#issuecomment-1883909583. The sidebar here is a concrete presentation proposal for that same capability.
- **Existing capabilities are partial:** In src/vs/workbench/electron-browser/actions/windowActions.ts, BaseSwitchWindow implements workbench.action.switchWindow and workbench.action.quickSwitchWindow by enumerating existing windows and calling nativeHostService.focusWindow; it does not consolidate them. src/vs/workbench/electron-browser/desktop.contribution.ts registers window.nativeTabs only for macOS. Neither supplies the requested cross-platform project-session sidebar.
- **Full contributor proposal:** https://github.com/microsoft/vscode/issues/324309#issuecomment-5671484056 describes a prototype at https://github.com/immanuelsavio/vscode/tree/feature/workspace-spaces-mvp that coordinates existing windows while preserving extension hosts, terminals, dirty editors, and workspace state. It asks for architectural feedback before a PR and documents restart, fullscreen, platform-validation, and hidden-window resource limitations; this is a design lead, not evidence of a landed fix.
- **Demonstration and related closed item:** https://github.com/microsoft/vscode/issues/324309#issuecomment-5673067187 supplies a demo of the prototype. https://github.com/microsoft/vscode/issues/293272 was also inspected: it requests single-window/taskbar consolidation but is CLOSED, so it is not a duplicate target.
