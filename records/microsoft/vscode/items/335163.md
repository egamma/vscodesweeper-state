# Issue #335163 — Agent host sets `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw generic endpoint, so Copilot CLI traces are POSTed to the wrong path (404)

[https://github.com/microsoft/vscode/issues/335163](https://github.com/microsoft/vscode/issues/335163)

## Summary

Still reproduces on current main: the Copilot agent host sets OTEL_EXPORTER_OTLP_TRACES_ENDPOINT to the raw configured OTLP endpoint while the metrics branch right next to it normalizes the same value with a signal-path helper, so any collector behind a base-path ingress silently drops trace exports.

## Change summary

Agent host sends traces to the raw generic OTLP endpoint instead of appending the OTLP `/v1/traces` signal path, so a collector expecting a path-suffixed endpoint 404s on incoming trace spans while metrics (which are normalized) succeed.

## Best solution

Normalize the traces endpoint the same way `resolveCopilotOtlpMetricsEndpoint` normalizes metrics (append `/v1/<signal>` when the URL has no path, mirroring `resolveSignalEndpoint` already used for Claude/Codex), and set `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` from that normalized value in copilotAgent.ts.
