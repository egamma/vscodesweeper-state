# Issue #335163 — Agent host sets `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw generic endpoint, so Copilot CLI traces are POSTed to the wrong path (404)

[https://github.com/microsoft/vscode/issues/335163](https://github.com/microsoft/vscode/issues/335163)

## Summary

The exact `/base` case still reproduces in current source. The recent endpoint-routing fix appends `/v1/traces` only to root URLs and deliberately leaves non-root paths unchanged, so this report remains necessary.

## Change summary

Agent Host converts a generic OTLP endpoint with a path prefix into a signal-specific trace endpoint without appending `/v1/traces`, causing trace exports to hit the wrong URL.

## Best solution

Preserve generic OTLP endpoint semantics for inherited `OTEL_EXPORTER_OTLP_ENDPOINT`, including path prefixes such as `/base`, while retaining a distinct way to represent genuinely signal-specific custom trace URLs. Keep metrics, gRPC, headers, and DB-mode routing unchanged.

- **Trace:**

  > readAgentHostOTelEnv in src/vs/platform/agentHost/node/otel/agentHostOTelService.ts stores `OTEL_EXPORTER_OTLP_ENDPOINT` as an undifferentiated `otlpEndpoint`. getNativeSdkTelemetryConfig calls resolveOtlpTracesEndpoint, whose implementation in src/vs/platform/otel/node/otlp/outboundForwarder.ts appends `/v1/traces` only for an empty or root pathname and returns `/base` unchanged.
