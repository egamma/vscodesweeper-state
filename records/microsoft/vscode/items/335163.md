# Issue #335163 — Agent host sets `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw generic endpoint, so Copilot CLI traces are POSTed to the wrong path (404)

[https://github.com/microsoft/vscode/issues/335163](https://github.com/microsoft/vscode/issues/335163)

## Summary

Traced conclusively in current main: `AgentHostOTelService.getNativeSdkTelemetryConfig()` (src/vs/platform/agentHost/node/otel/agentHostOTelService.ts, pass-through branch) assigns `traces = external` verbatim — the raw configured base URL, never appended with `/v1/traces` — while the metrics path is explicitly normalized downstream (`resolveCopilotOtlpMetricsEndpoint` / `resolveSignalEndpoint`). All three native launch paths (Copilot's `copilotAgent.ts`, Claude's `claudeSdkOptions.ts`, Codex's `codexLaunchConfig.ts`) copy `traces.endpoint` straight into their signal-specific trace env/config without normalization, so every one silently 404s traces against a bare collector base URL. This is exactly the reporter's diagnosis.

## Change summary

Agent Host sets the signal-specific `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw configured base URL instead of appending `/v1/traces`, so the Copilot CLI (and, by the same shared code path, Claude and Codex) POST traces to the wrong path and get silently 404'd.

## Best solution

Normalize the trace endpoint once at the shared source — `getNativeSdkTelemetryConfig()`'s pass-through `traces` construction — the same way DB mode already does (`${receiver.baseUrl}/v1/traces`) and the same way `resolveOtlpTracesEndpoint()` in src/vs/platform/otel/node/otlp/outboundForwarder.ts already does for the DB-mode forwarder. That fixes Copilot, Claude, and Codex simultaneously without touching each provider's launch code.
