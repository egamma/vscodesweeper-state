# Issue #335163 — Agent host sets `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw generic endpoint, so Copilot CLI traces are POSTed to the wrong path (404)

[https://github.com/microsoft/vscode/issues/335163](https://github.com/microsoft/vscode/issues/335163)

## Summary

Traced this in the current source and it holds up: when the agent host is configured with a bare OTLP base URL and pass-through export (no `chat.agentHost.otel.dbSpanExporter.enabled`), the traces endpoint handed to both the Copilot and Claude CLI subprocess is the raw, unnormalized base URL, while the metrics/logs endpoints go through path-normalization helpers that append `/v1/<signal>`. That asymmetry matches the reporter's diagnosis exactly and would cause a 404 against any collector that doesn't already terminate a bare base URL for `/v1/traces`.

## Change summary

The agent host sets `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` to the raw configured base URL instead of appending `/v1/traces`, so traces are POSTed to the wrong path and silently dropped (404) while metrics still work.

## Best solution

Normalize the traces endpoint the same way metrics/logs already are: in `copilotAgent.ts` around line 2357, replace `env['OTEL_EXPORTER_OTLP_TRACES_ENDPOINT'] = nativeTelemetry.traces.endpoint` with a call through `resolveCopilotOtlpMetricsEndpoint`-style logic parameterized for `'traces'` (or a shared helper), and do the equivalent in `claudeSdkOptions.ts` around line 344 using the existing `resolveSignalEndpoint` (which already supports `'logs'`/`'metrics'`) extended to accept `'traces'`.
