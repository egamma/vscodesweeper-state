## Evidence

- **Controlled reporter experiments:** https://github.com/microsoft/vscode/issues/339559 reports repeated crashes with persisted Microsoft session state, including three crashes with --disable-extensions and no third-party activations, versus stability for over 60 seconds after deleting authentication state. The initial sign-in was observed once; no Insiders confirmation or independent reproduction is available.
- **Restoration path:** extensions/microsoft-authentication/src/extension.ts activates MsalAuthProvider.create; src/node/authProvider.ts creates CachedPublicClientApplicationManager. In src/node/publicClientCache.ts, initialize reads publicClients-AzureCloud and reconstructs each stored client application. Ordinary rejected initialization promises are logged through Promise.allSettled, so the source alone does not establish the reported process-level termination.
- **Cache interpretation:** extensions/microsoft-authentication/src/node/publicClientCache.ts stores publicClients-AzureCloud as a JSON list of client IDs, not the serialized MSAL token cache. src/node/cachedPublicClientApplication.ts supplies pca:<clientId> to SecretStorageCachePlugin, whose beforeCacheAccess deserializes that separate secret. Deleting the reported keys therefore prevents client restoration but does not prove token-cache corruption.
- **Native broker diagnostic:** extensions/microsoft-authentication/package.json registers microsoft-authentication.implementation with default msal and alternative msal-no-broker. src/node/cachedPublicClientApplication.ts:getNativeBrokerOptions skips NativeBrokerPlugin when msal-no-broker is selected; initialize subsequently reaches _update and PublicClientApplication.getAllAccounts. This provides a targeted diagnostic comparison, not an established fix.
- **Canonical candidates ruled out:** https://github.com/microsoft/vscode/issues/296519 is open but reports long-running Copilot operations and a worker heap exhaustion, not Microsoft-session startup crash loops. https://github.com/microsoft/vscode/issues/58980 is open but concerns task problem-matcher path resolution. Neither satisfies the re-review requirement of an older canonical with the same observable symptom; additional authentication/MSAL crash searches returned no candidates.
