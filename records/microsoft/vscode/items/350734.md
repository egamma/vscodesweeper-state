## Evidence

- **Complete reproduction report:** https://github.com/microsoft/vscode/issues/350734 supplies Insiders version, concrete large-project steps, SIGABRT logs, Linux and macOS observations, plugin-enabled/disabled comparisons, and successful recovery after raising js/ts.tsserver.maxMemory. There are no comments.
- **Silent notification path:** extensions/typescript-language-features/src/typescriptServiceClient.ts:663-718 filters Copilot Chat out of pluginsForCrashPrompt but uses !plugins.length for each fallback notification. With Copilot Chat as the only plugin, neither notification branch executes.
- **Unbounded restart path:** typescriptServiceClient.ts:422 resets lastStart on each start. At 658-709, fatal shutdown requires numberRestarts > 5 and the latest run lasting under ten seconds; slower crashes reset the counter without stopping. Insiders and Code OSS reset numberRestarts after every single crash. Lines 770-771 start the service again when startService remains true.
- **Restart-generation defect:** typescriptServiceClient.ts:321-336 sets isRestarting before killing the old server and immediately starts another generation. Lines 514-524 discard old-generation exits before clearing that flag, so a new-generation crash can call serviceExited(false, apiVersion) and receive neither restart nor crash notification.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/350774 is OPEN, not merged, and explicitly says Fixes #350734. Its proposed crash policy addresses notification visibility, restart limits, suspected-OOM guidance, and restart-generation handling; an open fix proposal is not evidence of completion.
- **Product boundary:** The confirmed defects are in VS Code's built-in TypeScript extension crash handling, regardless of the upstream memory exhaustion that triggers them. The report reproduces the loop without Copilot Chat; this is not a third-party-extension closure.
