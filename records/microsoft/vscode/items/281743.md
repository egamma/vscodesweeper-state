## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/275010 is open, predates this report, and tracks the same reporter-observable symptom: Copilot completion or approval notifications leave the whole VS Code window unresponsive.
- **same Linux symptom and workaround:** A Linux Arch/KDE reporter on https://github.com/microsoft/vscode/issues/275010 reproduced the freeze when Copilot finished while unfocused and resolved it by enabling KDE's notification application; this issue's original Bazzite KDE reporter and July 2026 Fedora KDE reporter independently reported the same resolution.
- **diagnosed root cause:** Maintainer analysis in https://github.com/microsoft/vscode/issues/275010 identifies an unresponsive OS toast-notification service blocking Electron's UI thread, cites Electron commit 90e338df507f7dc7ef0cac1a09b62d2c97c95f72, and recommends disabling chat.notifyWindowOnConfirmation and chat.notifyWindowOnResponseReceived as the workaround.
- **current source path:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts sends confirmation and response-completion notifications through IHostService.showToast; those are the two notification paths implicated by the reports and workaround.
- **reopen history:** This issue was reopened on 2025-12-16 because the earlier comparison with https://github.com/microsoft/vscode/issues/268516 was explicitly retracted as the wrong trace; that does not undermine the separately verified match with the older https://github.com/microsoft/vscode/issues/275010.
