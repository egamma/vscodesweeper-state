# Issue #274100 — Git - Partial stage should auto-accept agentic changes

[https://github.com/microsoft/vscode/issues/274100](https://github.com/microsoft/vscode/issues/274100)

## Summary

Whole-file staging already accepts agent edits, but partial staging still lacks the requested correlation with unaccepted AI changes. Keep this accepted Backlog request open; maintainer interest supports planning the remaining granular behavior.

## Change summary

Automatically accept the corresponding agent edits when their changes are partially staged through Git.

## Best solution

Let SCM chunk-by-chunk review acknowledge the corresponding agent changes without accepting unrelated unstaged edits. Define how selections smaller than an AI review hunk affect acceptance before connecting Git staging to granular chat review.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingTextModelChangeService.ts`
- **Validation:** Create two separated pending agent edits in one tracked file and stage only one through git.stageChange and git.stageSelectedRanges. Verify the staged edit is accepted while the other remains pending, with working-tree text and index contents unchanged by acceptance. Also exercise a selection smaller than one AI hunk under the chosen policy, failed staging, unstaging, and existing whole-file staging.
- **Behavior:**

  > A user reviewing agent edits through the SCM diff should not need a second Keep action for changes they have already staged. Staging one of two separated agent changes should accept the corresponding change and leave the unstaged change pending. Acceptance must not alter what was staged or change working-tree text. Selection-level behavior within a single AI review hunk needs agreement; failed staging and unstaging must not acknowledge additional pending edits.
- **Trace:**

  > Whole-file staging runs through Repository.add in extensions/git/src/repository.ts and calls `_chat.editSessions.accept`; the registered command in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts accepts entire resources across editing sessions. Partial staging instead runs through CommandCenter._stageChanges in extensions/git/src/commands.ts to Repository.stage, which writes computed index contents without chat acceptance. Git selected ranges are intersections of working-tree/index diffs, whereas ChatEditingTextModelChangeService._keepHunk accepts existing mappings between the AI original and modified models. The missing work is correlating those distinct review boundaries, not adding whole-file acceptance. Preserve existing Git patch construction, whole-file acceptance, and unrelated pending edits; do not treat unstaging as acceptance. Maintainer support is recorded at https://github.com/microsoft/vscode/issues/274100#issuecomment-3473428322. The uncertainty begins when a Git selection represents only part of an AI review hunk.
- **Open decisions:**
  - When a staged selection covers only part of an AI review hunk, should that portion become accepted independently, or should the hunk remain pending until its complete change has been staged?
