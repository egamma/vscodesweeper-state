# Issue #334950 — Codex customizations should publish writable migration destinations

[https://github.com/microsoft/vscode/issues/334950](https://github.com/microsoft/vscode/issues/334950)

## Summary

Verified against current main: the three Codex discovery helpers really do omit or mark non-writable the directory records the customization-migration feature needs, so Codex migration candidates are silently filtered out. This is a real, well-diagnosed gap in an existing feature, not a scheduling or duplicate matter — keep it open for implementation.

## Change summary

Codex's customization discovery (workspace agents, root AGENTS.md instructions, and skills) doesn't publish writable `DirectoryCustomization` records for empty or synthetic destinations, so `provideSourceFolders`/`CustomizationMigrationService` finds no compatible migration targets for Codex.

## Best solution

Update src/vs/platform/agentHost/node/codex/codexCustomizations.ts so `discoverCodexWorkspaceAgents` always emits a writable `.github/agents` container (even when empty), `discoverCodexWorkspaceInstructions` represents the real writable `AGENTS.md` destination instead of `writable: false`, and `codexSkillsToContainers` is replaced/supplemented with real writable skill-destination URIs (workspace and user scope) instead of the synthetic non-writable `codex-skills:` projection — coordinated with how `DirectoryCustomization` represents a file-based instruction destination.
