# Issue #309102 — agents app: Changes view should be able to consistently compute against remote default branch's

[https://github.com/microsoft/vscode/issues/309102](https://github.com/microsoft/vscode/issues/309102)

## Summary

Keep open: Branch Changes exists, but it can remain anchored to the session's original feature branch rather than the remote default branch after a rebase. The related Agents Window reports are newer and do not qualify as canonical duplicates for this re-reviewed issue.

## Change summary

Allow an existing session's Changes view to compare its current HEAD against the remote default branch, independently of the branch from which the session started.

## Best solution

Provide a PR-style comparison against the remote default branch without requiring a new session or changing the worktree's creation base. Preserve checkpoint and session-change views; a maintainer should decide whether this comparison is an additional selectable mode or the default.

- **Validation:** In a temporary repository outside this read-only checkout, create divergent main and feature-branch histories, start a session from feature-branch, then rebase its working branch onto origin/main. The requested comparison must match the file list and numstat from git diff origin/main...HEAD, remain correct after another commit and session reload, and leave checkpoint views and worktree creation/merge targets unchanged.
- **Behavior:**

  > A session started from a feature branch can review its committed branch changes against the remote default branch after rebasing onto that branch. The comparison must exclude unrelated divergence from the original session base and match the PR-style merge-base-to-HEAD result for the same refs. Accessing it must not require abandoning conversation history or creating another session. Existing checkpoint and session-change views remain available.
- **Trace:**

  > The legacy Copilot worktree path records its creation base in chatSessionWorktreeServiceImpl.ts and uses that same base in _getWorktreeChanges. Current Agent Host Branch Changes resolves persisted META_DIFF_BASE_BRANCH or git-state baseBranchName in AgentHostChangesetService._resolveBranchBaseBranch. AgentHostGitService separately exposes defaultRemoteBranchName, so the repository already distinguishes the desired remote-default reference from the session base. The Changes dropdown selects existing provider changesets, and the worktree Branch configuration is creation-only. The boundary is review comparison: do not silently change worktree creation, merge destinations, checkpoint identity or session history. Related reports https://github.com/microsoft/vscode/issues/337532 and https://github.com/microsoft/vscode/issues/321941 identify remote-selection and non-default-base cases that the design must distinguish; neither is an eligible older canonical. The remaining uncertainty is how the new comparison is presented and represented across providers, not whether the recorded creation base can differ from the requested reference.
- **Open decisions:**
  - Should remote-default comparison be an additional selectable Changes mode, preserving the current default, or replace the default branch comparison for existing sessions?
