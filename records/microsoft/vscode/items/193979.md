# Issue #193979 — Diff Editor v2: setting for expanded unchanged regions by default

[https://github.com/microsoft/vscode/issues/193979](https://github.com/microsoft/vscode/issues/193979)

## Summary

Keep open: there is still no setting that initially expands unchanged regions while retaining their highlighting and fold controls. This team-authored Backlog request was explicitly split from the earlier options issue, and no qualifying fix or canonical duplicate was established.

## Change summary

Allow unchanged diff regions to start fully expanded while remaining individually foldable.

## Best solution

Provide an opt-in initial expansion preference for unchanged regions without disabling their decorations or folding controls. Preserve existing defaults and user-controlled expansion state during subsequent diff updates.

Verify unchanged default behavior and preservation of manual folding after edits.
- **Behavior:**

  > Users should be able to open a diff with eligible unchanged regions fully expanded while retaining unchanged-region highlighting and individual fold controls. The existing Show All Unchanged Regions command is an on-demand workaround, not the requested default preference. Acceptance should cover initial expansion, individual collapse and re-expansion, unchanged behavior without opting in, and preservation of manually adjusted regions during diff updates.
- **Trace:**

  > The parent request at https://github.com/microsoft/vscode/issues/190837 clarifies that expansion must retain highlighting and folding. DiffEditorViewModel.unchangedRegions returns no regions when hideUnchangedRegions.enabled is false, and HideUnchangedRegionsFeature derives highlighting and fold controls from that collection, so disabling the feature is not equivalent. UnchangedRegion.fromDiffs initializes regions with zero visible lines; updateUnchangedRegions separately transfers existing visibility state across edits. diffEditor.showAllUnchangedRegions already provides explicit expansion through DiffEditorWidget, but the option interface and configuration registrations expose no initialization preference. Preserve existing line-count semantics and manual visibility-state transfer; the uncertainty is the public setting contract, not whether an expanded-but-foldable state exists.
- **Open decisions:**
  - Should initial expansion be exposed as a separate preference under diffEditor.hideUnchangedRegions, or should the existing configuration evolve into an explicit disabled/collapsed/expanded mode while preserving compatibility?
