# Issue #140136 — Support Variable Substitution for Keyboard Binding Command Arguments

[https://github.com/microsoft/vscode/issues/140136](https://github.com/microsoft/vscode/issues/140136)

## Summary

Keep this accepted, well-supported request open: current keybinding dispatch still passes command arguments without general variable substitution. Command-specific support does not cover arbitrary extension commands, and a maintainer explicitly identified this issue as the preferred home for the work.

## Change summary

Support launch/task-style variable substitution in keyboard-binding command arguments, including active-file, selection, and configuration variables.

## Best solution

Provide a consistent, documented way for keybindings to resolve variables before invoking arbitrary commands, using the existing variable-resolution capabilities. Settle compatibility with literal argument strings and the supported variable families before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/keybinding/common/abstractKeybindingService.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/workbench/services/configurationResolver/common/variableResolver.ts`, `src/vs/workbench/services/configurationResolver/browser/baseConfigurationResolverService.ts`
- **Validation:** In a development build, register a diagnostic extension command that records received arguments. Invoke it through keybindings containing ${file}, ${fileDirname}, ${selectedText}, and ${config:editor.fontSize}, including nested arguments; verify values against the active editor and settings. Repeat after switching editors, check non-variable values remain unchanged, and exercise literal-placeholder and interactive-variable cases according to the agreed contract. Verify existing find-in-files substitution and snippet insertion remain unchanged.
- **Behavior:**

  > Users should be able to supply supported launch/task-style variables in keybinding arguments to arbitrary commands, without each receiving command implementing substitution. The reporter's filePath argument should reach the debugger extension as the active file path rather than the literal ${file}. Selection and configuration-variable examples should follow the agreed supported-variable contract, including nested argument values. Acceptance must check invocation-time context, unchanged non-variable values, and compatibility with commands that intentionally consume template strings.
- **Trace:**

  > WorkbenchKeybindingService._resolveUserKeybindingItems retains commandArgs unchanged in src/vs/workbench/services/keybinding/browser/keybindingService.ts. AbstractKeybindingService dispatches those arguments directly in src/vs/platform/keybinding/common/abstractKeybindingService.ts, and CommandService forwards them to the handler without substitution. Existing findInFilesCommand resolves strings within its own handler in src/vs/workbench/contrib/search/browser/searchActionsBase.ts, confirming the command-specific boundary described in the discussion. AbstractVariableResolverService.resolveAsync and BaseConfigurationResolverService's interaction-aware methods provide existing resolution machinery, but the generic keybinding path does not use it. Preserve ordinary programmatic command invocation and existing command-specific/template behavior; this request does not authorize global substitution across all command callers. The maintainer statement at https://github.com/microsoft/vscode/issues/210064#issuecomment-2048097076 favors this general work item. The remaining uncertainty is the user-visible substitution contract, not whether the gap exists.
- **Open decisions:**
  - Should substitution apply automatically to existing keybinding arguments, or require an explicit opt-in so literal ${...} strings and command-owned templates retain their current meaning?
  - Which variable families are supported: only non-interactive editor, workspace, environment, and configuration variables, or also ${command:...} and ${input:...} with their execution and prompting semantics?

## Evidence

- **Current dispatch preserves raw arguments:** src/vs/workbench/services/keybinding/browser/keybindingService.ts:483–495 retains item.commandArgs when constructing resolved bindings. src/vs/platform/keybinding/common/abstractKeybindingService.ts:393–396 passes those arguments directly to executeCommand. src/vs/workbench/services/commands/common/commandService.ts:92–100 invokes the handler with those same arguments; none of these stages performs variable substitution.
- **Existing capability is command-specific:** src/vs/workbench/contrib/search/browser/searchActionsBase.ts:92–116 implements variable resolution inside findInFilesCommand through IConfigurationResolverService.resolveAsync. That covers workbench.action.findInFiles, not the reporter's extension.extendscript-debug.evalInHost command or general keybinding arguments. The keybinding argument schema describes arguments to pass through and provides no general substitution option.
- **Reusable resolution capabilities exist:** src/vs/workbench/services/configurationResolver/common/variableResolver.ts implements resolveAsync by parsing a configuration expression and evaluating its variables. It also distinguishes interaction-aware resolution methods. The missing capability is adoption on the general keybinding invocation path, not the absence of a variable resolver.
