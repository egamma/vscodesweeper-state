# Issue #114115 — [html] support imports in embedded JavaScript

[https://github.com/microsoft/vscode/issues/114115](https://github.com/microsoft/vscode/issues/114115)

## Summary

Keep open: embedded JavaScript still lacks workspace module resolution, and an open implementation PR explicitly targets this request. The older related issues do not establish the same observable symptom required for a duplicate close on this re-reviewed item.

## Change summary

Provide IntelliSense for npm packages, local modules, and JSDoc import types used inside HTML script tags.

## Best solution

Review the embedded-script module-resolution support in https://github.com/microsoft/vscode/pull/171547 and determine whether that implementation should land. The finished HTML language support should resolve imported symbols and their types from the containing workspace, rather than offering only document-local and bundled-library IntelliSense.

## Evidence

- **Current source limitation:** extensions/html-language-features/server/src/modes/javascriptMode.ts:getLanguageServiceHost uses Classic module resolution, lists only the current embedded document and jquery as script files, and reads other files through bundled-library loading rather than workspace files. getCurrentDirectory returns an empty string. extensions/html-language-features/server/src/modes/javascriptLibs.ts:loadLibrary loads TypeScript libraries and the bundled jquery declaration file, not the HTML document's neighboring modules or npm dependencies.
- **Existing-capability check:** The configuration registrations in extensions/html-language-features/package.json contain HTML completion, formatting, hover, and validation options, but no embedded-script project or module-resolution setting. html.validate.scripts controls diagnostics, not imported-symbol IntelliSense. javascriptMode.ts filters diagnostic 2792, which can hide the original unresolved-module message without delivering the requested completions.
- **Confirmed scope in discussion:** https://github.com/microsoft/vscode/issues/114115#issuecomment-1977419777 supplies a local-module example where foo.o does not complete the exported on/off properties. https://github.com/microsoft/vscode/issues/114115#issuecomment-2624762413 confirms that JSDoc import types have the same limitation.

Its body explicitly includes Fixes #114115 and proposes replacing the built-in HTML extension's embedded-language implementation with Volar. It is an implementation candidate, not evidence of a landed fix.
