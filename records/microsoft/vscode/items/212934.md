# Issue #212934 — Show Quick pick if multiple extensions register `notebook.format` code action providers.

[https://github.com/microsoft/vscode/issues/212934](https://github.com/microsoft/vscode/issues/212934)

## Summary

The requested notebook formatter picker is still missing: current code logs a warning and selects the first action when no default is configured. Keep this team-authored Backlog follow-up open; the existing setting only partially covers the request, and no qualifying duplicate was verified.

## Change summary

Offer a Quick Pick when multiple extensions provide notebook formatting actions, integrated with notebook.defaultFormatter.

## Best solution

Provide notebook-level formatter selection that identifies the contributing extensions and persists the selected default in notebook.defaultFormatter. Settle how selection is surfaced during save-triggered formatting versus an explicit Format Notebook command before implementation.

Verify cancellation, a single provider, an existing default, and save-triggered formatting against the agreed interaction policy.
- **Behavior:**

  > When multiple extensions supply notebook formatting actions without a configured default, users should be able to choose the formatter rather than having the first action selected without an interactive choice. The picker should identify the extensions and integrate its selection with notebook.defaultFormatter. An existing valid default should remain effective, and a single extension should not require an unnecessary choice. Acceptance must cover selection, persistence, cancellation, and the agreed behavior during save-triggered formatting.
- **Trace:**

  > CodeActionParticipantUtils.checkAndRunFormatCodeAction in src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts reads notebook.defaultFormatter and requests notebook.format actions through the first cell model. applyOnSaveFormatCodeAction warns about multiple actions but selects validActions[0] when no default exists. Both FormatOnSaveParticipant and the notebook.format command use this shared path, which currently carries no explicit-versus-save interaction mode. The setting already reuses DefaultFormatter's extension metadata, while the document formatter picker in src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts persists editor.defaultFormatter. Preserve configured-default behavior, the single-action-per-extension convention, and the existing per-cell formatting fallback. The deferred picker is supported by https://github.com/microsoft/vscode/pull/212750#discussion_r1604049009; the unresolved product boundary is whether save-triggered formatting may interrupt users with selection UI.
- **Open decisions:**
  - When multiple notebook formatters are available without a default, should save-triggered formatting open the picker directly, or offer a nonblocking configuration prompt while reserving the picker for explicit formatting?
