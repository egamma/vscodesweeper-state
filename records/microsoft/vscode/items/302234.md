# Issue #302234 — Bring this Copilot CLI terminal linking into Core

[https://github.com/microsoft/vscode/issues/302234](https://github.com/microsoft/vscode/issues/302234)

## Summary

Keep open: Copilot CLI session-relative terminal linking still depends on the Copilot Chat extension, so the requested standalone capability remains missing. This team-authored request has neither a verified fixing commit nor an eligible duplicate.

## Change summary

Make Copilot CLI-generated terminal file links work without installing or activating Copilot Chat.

## Best solution

Provide session-aware terminal file linking independently of Copilot Chat, preserving ordinary terminal path resolution and the existing link-opening safeguards. Plan how standalone CLI sessions supply their file-resolution context before moving the capability into the core terminal integration.

- **Behavior:**

  > Copilot CLI-generated file links in the integrated terminal must work without Copilot Chat installed or activated. Both absolute session-state paths and session-relative files/... paths should open the intended file, with supported line/column navigation preserved. Multiple sessions must not cause a link to silently open the wrong file. Ordinary terminal links and existing resource-trust safeguards must retain their behavior.
- **Trace:**

  > The tested experience in https://github.com/microsoft/vscode/issues/301574 is implemented by CopilotCLITerminalIntegration and CopilotCLITerminalLinkProvider under extensions/copilot/src/extension/chatSessions/vscode-node/. The provider resolves relative paths against session-state directories and handles ambiguous matches with a picker; its session-directory resolver depends on ICopilotCLISessionTracker in copilotCLIChatSessions.ts and copilotCLIChatSessionsContribution.ts. Core TerminalLocalLinkDetector and TerminalLinkResolver under src/vs/workbench/contrib/terminalContrib/links/browser/ already support absolute, home-relative, and cwd-relative paths, but the inspected flow lacks that CLI session context. The unresolved architectural boundary is how independently launched CLI sessions provide terminal-affiliated resolution context without the extension's tracker; this review did not establish a complete core-side replacement path. Preserve ordinary terminal resolution, ambiguity handling, and trust checks rather than treating the request as a parser-only migration. https://github.com/microsoft/vscode/issues/293726 provides broader integration context but is not a verified duplicate.
