# Issue #342925 — Remote agent host: customization expansion asks the remote host to resolve the client's local plugin paths (file:///Users/...)

[https://github.com/microsoft/vscode/issues/342925](https://github.com/microsoft/vscode/issues/342925)

## Summary

Keep open: current source still routes client-local plugin directories through the remote host, preventing their children from appearing. The report identifies a concrete, bounded filesystem-routing defect; the existing agent-host label is appropriate.

## Change summary

Resolve client-owned customization resources on the correct filesystem instead of asking the remote agent host to enumerate client-local paths.

## Best solution

Client-owned plugins and their children should remain readable from their originating filesystem, while host-owned resources continue resolving through the owning remote connection. Customization listings and custom-agent resource links should consistently preserve that distinction.
