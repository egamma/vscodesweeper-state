# Issue #178852 — [Extension Development] parsing exception in "when" clause should default to not showing corresponding entry

[https://github.com/microsoft/vscode/issues/178852](https://github.com/microsoft/vscode/issues/178852)

## Summary

Valid feature request from a team member; the underlying behavior is confirmed in source — parse failures return `undefined` which evaluates to `true` (show everywhere). No fix has landed on main. The `under-discussion` label is appropriate while the design trade-off is considered.

## Change summary

When a `when` clause has a parsing error, the associated menu/view item shows up everywhere instead of being hidden.

## Best solution

Distinguish 'no when clause specified' (show always) from 'when clause failed to parse' (hide by default or evaluate to `ContextKeyFalseExpr`). The change would likely live in `ContextKeyExpr.deserialize()` (return a sentinel false-expr on parse failure) or in how `contextMatchesRules` handles the undefined case from extensions. Needs a design decision on whether to log a warning or surface the error to the extension author via the Problems panel.
