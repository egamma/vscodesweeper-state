## Evidence

- **Verified older canonical with the same symptom:** https://github.com/microsoft/vscode/issues/233790 is currently open and was created on 2024-11-13, before this report. Its reproduction enables GPU rendering, opens a long line, scrolls right, and presses Home: the cursor moves outside the viewport but the editor does not scroll to reveal it. This is the same automatic horizontal cursor-reveal failure, not merely related GPU work.
- **Independent confirmation:** A maintainer confirmed that the editor still failed to scroll left on Windows Insiders on 2026-01-28: https://github.com/microsoft/vscode/issues/233790#issuecomment-3813397996.
- **Current source still lacks automatic reveal:** src/vs/editor/browser/viewParts/viewLinesGpu/viewLinesGpu.ts:450 implements onRevealRangeRequest as an unconditional return true, without recording or processing horizontal reveal requests. Its _renderText updates scrollbar width but does not reveal the cursor. In contrast, src/vs/editor/browser/viewParts/viewLines/viewLines.ts:269-299 processes revealHorizontal and queues range or selection reveal requests. The missing GPU handling affects cursor reveal in either horizontal direction.
- **Linked fix attempt was not merged:** https://github.com/microsoft/vscode/pull/288334 references this issue but is closed with mergedAt and mergeCommit both null. The author closed it as overly complicated: https://github.com/microsoft/vscode/pull/288334#issuecomment-3759828325. It is not evidence of a landed fix.
- **Scrollbar availability is distinct from cursor reveal:** The supplied discussion says Insiders gained a horizontal scrollbar, and current ViewLinesGpu._updateMaxLineWidth provides scrollbar sizing. Neither establishes automatic cursor reveal; the older canonical explicitly includes that remaining behavior.
