# Issue #332763 — fix: guard against cleared view model in ChatWidget._acceptInput (fixes #332754)

[https://github.com/microsoft/vscode/issues/332763](https://github.com/microsoft/vscode/issues/332763)

## Summary

Well-traced, auto-generated (errors-fix bot) report of a real teardown race in ChatWidget._acceptInput: the view-model guard at the top of the method (chatWidget.ts:3100) doesn't protect the later unconditional `this.viewModel.model` dereference (around line 3204) after several await points, and a concurrent `setModel(undefined)`/`onDidDisposeModel` (lines 2640, 2721) can null the field in between. No fix has landed on main yet.

## Change summary

TypeError thrown from ChatWidget._acceptInput when the chat view model is cleared mid-submission by a concurrent session switch or dispose.

## Best solution

Add a re-validation of `this.viewModel` immediately before the `const model = this.viewModel.model` dereference in `_acceptInput` (chatWidget.ts) and bail out if it has been cleared, mirroring the existing guard pattern at line 3100 and the optional-chaining use at `this.viewModel?.editing`.
