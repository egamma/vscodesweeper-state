# Issue #195920 — Long/multiline test failure messages are not all readable when using actual/expected diff

[https://github.com/microsoft/vscode/issues/195920](https://github.com/microsoft/vscode/issues/195920)

## Summary

Keep open: current source still displays expected/actual values without the accompanying multiline description, and the peek title explicitly uses only its first line. Existing settings and the related open issues do not cover this request.

## Change summary

Show the full multiline failure description alongside a TestMessage.diff comparison in Test Results and the testing peek.

## Best solution

Preserve access to the complete failure description alongside the expected/actual comparison in both testing surfaces, without requiring extensions to emit a separate failure or output entry.

## Evidence

- **Current diff rendering:** src/vs/workbench/contrib/testing/browser/testResultsView/testResultsOutput.ts: DiffContentProvider.update creates models from subject.expectedUri and subject.actualUri and renders only their comparison. MarkdownTestMessagePeek.update and PlainTextMessagePeek.update reject diffable messages, so neither supplies the accompanying description.
- **Exclusive renderer selection:** src/vs/workbench/contrib/testing/browser/testResultsView/testResultsViewContent.ts: prepareTopFrame selects the first matching content provider with findAsync(this.contentProviders, p => p.update(subject)); it does not combine a description renderer with the diff renderer.
- **Peek title truncation:** src/vs/workbench/contrib/testing/browser/testingOutputPeek.ts: showInPlace calls setTitle(firstLine(renderTestMessageAsText(message.message)), ...), explicitly discarding subsequent description lines from the title.
- **Existing-capability check:** The testing configuration in src/vs/workbench/contrib/testing/common/configuration.ts has no setting to display a diff's full accompanying description. testing.showAllMessages controls messages from different test runs, not description visibility. Editor option mirroring in DiffContentProvider can affect the comparison editors but cannot reveal text absent from their models; openCurrentInEditor also chooses expected/actual models for diffable messages.
- **Canonical search:** Open-issue searches covering testing, diff, multiline, failure descriptions, and peek messages found no verified canonical for the same symptom. https://github.com/microsoft/vscode/issues/9635 concerns assembling task problem-matcher messages from output lines, while https://github.com/microsoft/vscode/issues/146799 requests switching between verbose and simple stack traces; neither owns displaying a TestMessage.diff description alongside its comparison.
- **Related extension integration:** https://github.com/dart-lang/test/issues/2123 remains open and requests raw expected/actual values in Dart test error events. It explains the integration motivation but does not own VS Code's rendering of the description supplied to TestMessage.diff.
