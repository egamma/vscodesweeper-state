Both the built-in microphone and a Bluetooth headset were tested; VS Code Speech 0.16.0 is installed.
- **Discussion does not confirm reproduction:** The sole supplied comment asks for a fix but supplies no independent reproduction, logs, workaround, or fixing PR.
- **Listening is distinct from transcription:** In src/vs/workbench/contrib/chat/electron-browser/actions/voiceChatActions.ts, SpeechToTextStatus.Started starts the listening placeholder; input updates occur separately on Recognizing or Recognized events carrying nonempty text. The visible listening state therefore does not prove that recognized text is reaching the chat controller.
- **Provider boundary:** src/vs/workbench/contrib/speech/browser/speechService.ts delegates recognition to provider.createSpeechToTextSession and logs provider Error events. src/vs/workbench/api/common/extHostSpeech.ts and src/vs/workbench/api/browser/mainThreadSpeech.ts bridge provider events into core. Inspection does not establish whether this failure originates in capture, the provider, or core event handling.
- **Current surface has evolved:** src/vs/workbench/contrib/chat/browser/actions/chatSpeechToTextActions.ts registers workbench.action.chat.toggleSpeechToText and explicitly prioritizes configured built-in dictation over the legacy voice-chat shortcut. chatSpeechToTextService.ts supports local and cloud transcription backends. Neither the newer capability nor the retained legacy path proves resolution of the reported macOS failure.
