# Issue #234402 — Allow selecting extensions when copying a profile

[https://github.com/microsoft/vscode/issues/234402](https://github.com/microsoft/vscode/issues/234402)

## Summary

A real capability gap remains on current main: profile creation can copy all extensions or none, but cannot carry an individual extension selection into the new profile. The request has passed the community threshold with 29 upvotes and is appropriately parked in the Backlog.

## Change summary

Allow users to choose individual extensions when creating a profile by copying an existing profile.

## Best solution

Add per-extension selection to the Extensions branch of the new-profile contents tree and carry that selection through profile creation, while preserving the current all-selected default and clearly handling extensions scoped to all profiles.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts`, `src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts`, `src/vs/workbench/services/userDataProfile/browser/extensionsResource.ts`
- **Validation:** Create a source profile with multiple profile-scoped extensions, select only a subset in New Profile, create the copy, and verify that only the selected profile-scoped extensions are present while the existing all-selected and no-extensions choices retain their current behavior.
- **Behavior:**

  > When copying an existing profile, expanding Extensions lets the user select which profile-scoped extensions are copied. The initial state preserves today's behavior by selecting all eligible extensions, and selecting none remains possible. Creating the profile must copy exactly the selected profile-scoped extensions without changing how other resource categories are copied. The UI must clearly represent extensions that apply to all profiles rather than implying they can be removed from only the new profile.
- **Trace:**

  > NewProfileResourceTreeRenderer in src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts currently exposes only resource-level Copy, Default, and None choices. NewProfileElement in userDataProfilesEditorModel.ts stores a single extensions copy flag and returns extension children for browsing, but its fresh ExtensionsResourceExportTreeItem has no active parent checkbox and no retained child selection. UserDataProfileImportExportService.createFromProfile then treats extensions as a boolean and invokes ExtensionsResource.copy, which copies the entire source extension set. ExtensionsResourceTreeItem already has excludedExtensions and per-child checkbox state for export flows, providing relevant prior art, but the selection is local to that tree item and is not part of IUserDataProfileCreateOptions. Keep settings, keybindings, tasks, snippets, and MCP copy semantics unchanged; the uncertainty begins at the public behavior for application-scoped extensions and the selection data carried into creation.
- **Open decisions:**
  - Should extensions marked "All Profiles" be shown as selected but non-editable with an explanation, or should they be omitted from the selectable copy list?
  - When an extension pack is selected, should profile creation copy only the selected pack entry or also automatically select and copy its pack members?

## Evidence

- **accepted demand:** The issue has 29 community upvotes, carries the feature-request and user-profiles labels, and was moved to the Backlog after exceeding the documented 20-upvote threshold.
- **current UI boundary:** src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts renders only resource-level Copy/Default/None choices in NewProfileResourceTreeRenderer. Child checkboxes appear only when an IProfileResourceTypeChildElement supplies checkbox state.
- **missing selection state:** NewProfileElement in src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts tracks ProfileResourceTypeFlags, including one boolean for all Extensions, and creates a fresh ExtensionsResourceExportTreeItem whose checkbox state is not enabled or retained for individual children.
- **all-or-nothing copy path:** createFromProfile in src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts calls ExtensionsResource.copy when resourceTypeFlags.extensions is true; ExtensionsResource.copy in extensionsResource.ts copies the complete extension set.
- **existing reusable mechanism:** ExtensionsResourceTreeItem in src/vs/workbench/services/userDataProfile/browser/extensionsResource.ts already models per-extension exclusions through excludedExtensions and child checkbox state for export flows, but that state is not connected to the new-profile creation path.
- **canonical search:** The older open issue https://github.com/microsoft/vscode/issues/40239 concerns enabling and disabling extensions from workspace configuration files, not selecting extensions while copying a profile, so it does not meet the stronger duplicate bar for this re-reviewed item.
