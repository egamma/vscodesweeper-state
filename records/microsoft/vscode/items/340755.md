# Issue #340755 — Linux: archive builds use the com.microsoft.VSCode app_id when the system package is installed

[https://github.com/microsoft/vscode/issues/340755](https://github.com/microsoft/vscode/issues/340755)

## Summary

Thanks for the detailed report. The source confirms it: src/mainImpl.ts calls setDesktopName whenever /usr/share/applications/<linuxDesktopName>.desktop exists, without checking whether the running build is the installed package. Keeping this open as a bounded fix.

## Change summary

Archive/portable Linux builds adopt the system package's desktop name (app_id) whenever the system package is also installed.

## Best solution

Only call app.setDesktopName for the installed desktop file when the running build is the installed package, for example by comparing the executable or app root against the package install dir. Archive builds should keep the desktopName from their own package.json.
