# Issue #299530 — Custom Markdown styles

[https://github.com/microsoft/vscode/issues/299530](https://github.com/microsoft/vscode/issues/299530)

## Summary

The inability to use absolute filesystem paths in `markdown.styles` is an intentional consequence of webview sandboxing, not a bug. The `localResourceRoots` restrict resource loading to workspace folders and extension-contributed roots for security. A prior feature request (#116881) for the same capability was closed without sufficient upvotes.

## Change summary

User wants `markdown.styles` to support absolute filesystem paths (e.g. `C:\Users\...\style.css`) for the Markdown preview.

## Best solution

Close as designed. The webview sandbox intentionally restricts resource loading to workspace-relative paths. The workaround is to place the CSS file inside the workspace and use a relative path. The previous feature request (https://github.com/microsoft/vscode/issues/116881) for absolute path support was closed by the community process without enough upvotes.

- **Proposed comment:**

  > Thanks for the report. The Markdown preview runs inside a sandboxed webview that intentionally restricts which local resources can be loaded — only files within the current workspace (or relative to the Markdown file) are allowed, by design. Absolute filesystem paths like `C:\Users\...\style.css` fall outside the allowed roots.
  > 
  > The workaround is to place your custom CSS file inside your workspace folder and reference it with a relative path in `markdown.styles`, e.g. `".vscode/custom.css"`. This same capability was previously requested in https://github.com/microsoft/vscode/issues/116881 and did not receive enough community upvotes to make it to the backlog.
  > 
  > Closing as designed — if you'd like to see absolute path support added, please open a new feature request so the community can weigh in.
