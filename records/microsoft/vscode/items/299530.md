Keep open for the Markdown owner to reconcile the accepted bug with the preview's intentional local-resource restrictions. Current main has refactored resource-root handling but still excludes arbitrary external stylesheet directories; the reported configuration and preview-opening steps suffice to retest, although Windows behavior was not executed.

## Change summary

Configured local CSS files fail to load in Markdown preview even though Markdown All in One applies them during HTML export.

## Best solution

Determine whether the reported stylesheet location should be supported under the Markdown preview's resource-access policy, then either address a supported-path loading defect or clarify the setting's restrictions. Do not broaden local filesystem access merely to suppress the warning.

## Evidence

- **Current resource-access boundary:** extensions/markdown-language-features/src/preview/preview.ts, #getWebviewOptions and #getLocalResourceRoots, delegates to getMarkdownLocalResourceRoots in src/util/resources.ts. That helper permits contributed roots plus workspace folders, or the Markdown file's directory outside a workspace; it does not add directories from markdown.styles.
- **Path resolution is distinct from permission:** extensions/markdown-language-features/src/preview/documentRenderer.ts, #fixHref and #computeCustomStyleSheetIncludes, converts Windows backslash absolute paths into webview URIs and resolves relative paths against the workspace or document directory. Recognizing an absolute path does not authorize loading it outside localResourceRoots.
- **Documented setting and partial workaround:** extensions/markdown-language-features/package.nls.json describes markdown.styles as URLs or local paths and explains relative-path resolution. A stylesheet inside the allowed workspace/document roots is an existing alternative, but does not provide the requested reusable external local stylesheet.
- **Discussion and historical maintainer position:** Both supplied comments identify the resource-root restriction; the second links https://github.com/microsoft/vscode/issues/116881. In https://github.com/microsoft/vscode/issues/243700#issuecomment-2729969837 the Markdown maintainer explains the restriction, citing https://github.com/microsoft/vscode/issues/45260#issuecomment-371428889. This is intentional access-control behavior, not evidence that Markdown All in One causes the preview failure.
