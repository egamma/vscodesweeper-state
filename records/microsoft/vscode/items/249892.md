# Issue #249892 — Extension Signature Verification Failed: Python

[https://github.com/microsoft/vscode/issues/249892](https://github.com/microsoft/vscode/issues/249892)

## Summary

This reopened bug remains necessary: multiple extensions fail through the same remote signature-verification path, and a second reporter confirmed the failure on VS Code 1.109.4 with a Mac-hosted Ubuntu VM. No older open issue owns the same observable symptom, and the newer related reports cannot serve as canonicals under the re-review rules.

## Change summary

Installing or upgrading extensions on some Remote-SSH Linux hosts fails because extension signature verification returns UnknownError.

## Best solution

Make remote extension installation handle verifier execution or compatibility failures without weakening signature enforcement, either by fixing the native verifier path or by performing an equivalent verified local-download path. Preserve hard failures for genuinely invalid signatures and provide actionable diagnostics for internal verifier failures.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts`, `src/vs/platform/extensionManagement/node/extensionManagementService.ts`, `src/vs/workbench/services/extensionManagement/electron-browser/remoteExtensionManagementService.ts`, `src/vs/platform/extensionManagement/test/node/extensionDownloader.test.ts`
- **Validation:** Using a fresh Remote-SSH session to an affected Lima Ubuntu VM, install Python and Pylance with signature verification enabled and confirm installation succeeds; additionally verify that a deliberately invalid signature still fails and that the selected internal-error behavior is covered by a targeted extension-management test.
- **Behavior:**

  > Installing or upgrading a legitimately signed extension in a Remote-SSH window must succeed when the remote signature-verification executable cannot operate correctly in that environment, without disabling signature verification. A genuinely invalid signature must continue to block installation. Internal verifier failures must expose enough diagnostic information to distinguish execution, platform-compatibility, and invalid-signature failures. Validate with Python/Pylance on the reported Lima remote setup and with a negative invalid-signature case.
- **Trace:**

  > The original logs show several unrelated extensions returning UnknownError/Internal Code 1 in one remote session, so the failing path is shared extension management rather than Python. ExtensionSignatureVerificationService.verify in src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts delegates to @vscode/vsce-sign and reports native failures as UnknownError; extensionManagementService.ts converts unsuccessful results to SignatureVerificationInternal. NativeRemoteExtensionManagementService.doInstallFromGallery in src/vs/workbench/services/extensionManagement/electron-browser/remoteExtensionManagementService.ts already has a local-download fallback for several remote errors, but not SignatureVerificationInternal, while remote.downloadExtensionsLocally exposes that path explicitly. The narrower ARM SIGILL report at https://github.com/microsoft/vscode/issues/321731 demonstrates one possible native-verifier failure mode but is newer and does not establish the root cause for every environment in this issue. Do not weaken rejection of invalid or untrusted signatures, and do not special-case Python or another extension identifier.
- **Open decisions:**
  - When remote signature verification fails internally for environmental or executable-compatibility reasons, should VS Code automatically retry equivalent signature verification through the local-download path, or fail installation and require the user to opt into remote.downloadExtensionsLocally?
