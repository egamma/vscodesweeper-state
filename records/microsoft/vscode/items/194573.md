# Issue #194573 — Search Files By Name Should Use Highlighted Text

[https://github.com/microsoft/vscode/issues/194573](https://github.com/microsoft/vscode/issues/194573)

## Summary

Keep this accepted Quick Open request open: current source does not seed Go to File from the editor selection, and neither linked implementation PR was merged. Maintainers have also consolidated later reports here, making this the existing canonical.

## Change summary

Allow Go to File to prefill its filename query from highlighted editor text.

## Best solution

Deliver selection-seeded Go to File while preserving explicit command arguments and existing unseeded behavior. Use the previously reviewed opt-in proposal as design evidence, and resolve its interaction with restored Quick Open input before implementation.

- **Likely files:** `src/vs/workbench/browser/actions/quickAccessActions.ts`, `src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/search.contribution.ts`, `src/vs/workbench/contrib/search/browser/searchActionsTextQuickAccess.ts`, `src/vs/workbench/browser/quickaccess.ts`
- **Validation:** With selection seeding enabled, select a filename in a focused editor and invoke Ctrl/Cmd+P: the query should contain the selection and be replaceable by typing. Repeat with search.quickAccess.preserveInput enabled and a previously accepted query to verify the agreed precedence. Confirm disabled seeding, no selection, and explicit workbench.action.quickOpen arguments retain their established behavior.
- **Behavior:**

  > Go to File currently requires users to copy selected filename text and paste it into Quick Open. The requested capability uses that selection as the initial filename query, allowing a matching file to be opened without copying or retyping. The previously reviewed proposal makes this opt-in and preserves existing behavior by default. Acceptance must cover selected-query replacement, explicit command arguments, and the agreed interaction with preserved prior input.
- **Trace:**

  > workbench.action.quickOpen in src/vs/workbench/browser/actions/quickAccessActions.ts forwards a prefix or undefined without consulting the editor. AnythingQuickAccessProvider.defaultFilterValue in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts can restore the last accepted query; src/vs/platform/quickinput/browser/quickAccess.ts applies that default unless preserveValue is set. Text-search selection extraction already exists in src/vs/workbench/contrib/search/browser/searchActionsTextQuickAccess.ts and searchView.ts, but workbench/browser must not import contrib code directly. https://github.com/microsoft/vscode/pull/197380 provides a reviewed, unmerged opt-in design and moved shared extraction into workbench/browser/quickaccess.ts. Preserve explicit prefixes, unrelated Quick Access providers, and text-search behavior; uncertainty remains over precedence between editor selection and restored input.
- **Open decisions:**
  - When selection seeding and search.quickAccess.preserveInput are both enabled, should selected editor text take precedence over the previously accepted Quick Open query?
