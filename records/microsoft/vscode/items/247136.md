# Issue #247136 — UX: Copilot pickers need alignment

[https://github.com/microsoft/vscode/issues/247136](https://github.com/microsoft/vscode/issues/247136)

## Summary

The underlying consistency concern remains relevant, but the original native-menu proposal has been overtaken by a substantially richer custom model picker. This should stay open as UX polish until maintainers decide which interaction contract the three chat-input pickers should share.

## Change summary

Align the model, mode, and session-target pickers at the bottom of Chat instead of mixing visibly or behaviorally different dropdown implementations.

## Best solution

Define a shared interaction and visual contract for chat-input pickers while preserving model-specific capabilities such as search, grouping, configuration, and provider tabs. A maintainer should first decide whether alignment means native-menu parity or consistent custom-picker behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/sessionTargetPickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts`
- **Validation:** Add or update chat-input picker browser tests and component fixtures to compare trigger active state, opening gesture, keyboard navigation, selection, Escape focus restoration, and menu-item presentation across the model, mode, and session-target pickers.
- **Behavior:**

  > The model, mode, and session-target controls at the bottom of Chat should present a coherent family of pickers: equivalent trigger states and opening, keyboard-navigation, selection, dismissal, and focus-restoration behavior. Model-only capabilities such as search, provider grouping, details, and configuration must remain discoverable unless maintainers explicitly choose the simpler native-menu design. Acceptance should cover mouse and keyboard interaction for all three controls, including Escape returning focus to the invoking control.
- **Trace:**

  > The original report observed two native dropdowns beside a custom model picker. The architecture later moved mode and session-target selection onto ChatInputPickerActionViewItem in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPickerActionItem.ts, while ModelPickerActionItem continued through the specialized ModelPickerWidget and now supports both action-widget and tabbed presentations. Commits https://github.com/microsoft/vscode/commit/cb6da5bcc3312278b7613b38ff96a19f7f7767e6 and https://github.com/microsoft/vscode/commit/e185eb32ba1926d8638fa5ba1bda68147f37db04 show the historical choice to generalize custom dropdowns rather than adopt native menus everywhere. The uncertainty begins at the desired user-visible contract: the original simple native-menu proposal conflicts with capabilities added by https://github.com/microsoft/vscode/commit/74a1af8aaea7912cefbb9614462663ee71df94f6. Do not remove model search, grouping, provider tabs, configuration, or accessibility behavior without an explicit product decision. The narrower interaction defects remain documented at https://github.com/microsoft/vscode/issues/247137.
- **Open decisions:**
  - Should the model picker retain its richer search, tabs, details, and configuration surface while matching the other pickers' trigger and navigation behavior, or should all three controls return to simple native-menu semantics with those capabilities moved elsewhere?
  - Is the desired alignment limited to interaction states and keyboard behavior, or must all three picker overlays also share the same visual structure and menu-item presentation?

## Evidence

- **current model picker:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerActionItem.ts wraps the specialized ModelPickerWidget, while modelPickerWidget.ts opens either an IActionWidgetService list or the experimental provider-tabbed picker.
- **other chat pickers:** src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts and sessionTargetPickerActionItem.ts both extend ChatInputPickerActionViewItem, whose shared implementation in chatInputPickerActionItem.ts extends ActionWidgetDropdownActionViewItem.
- **design evolution:** https://github.com/microsoft/vscode/commit/cb6da5bcc3312278b7613b38ff96a19f7f7767e6 generalized the custom action-widget dropdown, and https://github.com/microsoft/vscode/commit/e185eb32ba1926d8638fa5ba1bda68147f37db04 moved the mode picker onto it rather than converting the model picker to a native menu.
- **new model requirements:** https://github.com/microsoft/vscode/commit/74a1af8aaea7912cefbb9614462663ee71df94f6 added an experimental tabbed model picker with provider tabs, search, model details, and configuration, so the issue body's proposed simple native menu no longer covers the complete product surface.
- **related issue:** https://github.com/microsoft/vscode/issues/247137 is open and records specific native-interaction differences, but it was filed four minutes later and explicitly links back to this broader alignment issue, so it is not a valid canonical duplicate target.
