# Issue #330610 — Copilot Chat generates invalid tool schema for `terminal_last_command` when using BYOK Responses API

[https://github.com/microsoft/vscode/issues/330610](https://github.com/microsoft/vscode/issues/330610)

## Summary

Traced in source: the Responses API tool-building path in responsesApi.ts sends an empty `{}` schema (no `type: "object"`) for tools without an inputSchema, e.g. `terminal_last_command`, which strict Responses API implementations reject — exactly matching the reported 400 error. Only reproducible with a BYOK Responses-API endpoint, so keeping this as needs-review rather than a slam-dunk close.

## Change summary

Copilot Chat's BYOK Responses API request omits `type: "object"` on function tool schemas that have no declared parameters, causing strict OpenAI-compatible servers to reject the request with 'schema must be a JSON Schema of type object, got type null'.

## Best solution

In extensions/copilot/src/platform/endpoint/node/responsesApi.ts, the `functionTools.push(...)` block (around line 95-100) should default `parameters` to `{ type: 'object', properties: {} }` the same way `buildToolInputSchema` does for the Anthropic path in messagesApi.ts, and the same way buildToolSearchOutputTools already does at line 546 in the same file.
