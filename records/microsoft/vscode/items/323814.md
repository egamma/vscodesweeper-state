# Issue #323814 — Native menus are incorrectly scaled on KDE Plasma 6.6 with Global Menu enabled

[https://github.com/microsoft/vscode/issues/323814](https://github.com/microsoft/vscode/issues/323814)

## Summary

Keep open as an upstream native-menu rendering issue. Electron/Chromium owns the menu metrics, and the custom-menu workaround does not satisfy the requirement to retain KDE Global Menu integration.

## Change summary

Render native context menus at an appropriate scale on KDE Plasma while retaining Global Menu support.

## Best solution

Establish whether Plasma 6.6 exposes the known Chromium menu-metrics problem or a separate toolkit-scaling defect, then pursue the corresponding upstream correction while preserving native application-menu integration.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/323814 reports oversized fonts and spacing with window.menuStyle=native on Kubuntu 26.04, Plasma 6.6.4, at 100% display scale, including a clean profile and both Wayland and X11. Switching to custom menus corrects their appearance but reportedly removes KDE Global Menu integration.
- **Current native-menu boundary:** src/vs/workbench/services/contextmenu/electron-browser/contextmenuService.ts, NativeContextMenuService.showContextMenu, applies window zoom to popup coordinates rather than menu font or padding. src/vs/base/parts/contextmenu/electron-main/contextmenu.ts constructs Electron Menu/MenuItem objects and calls Menu.popup without supplying typography or scale overrides. The native application menu is installed through Menu.setApplicationMenu in src/vs/platform/menubar/electron-main/menubar.ts.
- **Older related report verified:** https://github.com/microsoft/vscode/issues/224515 is open and was created on 2024-08-01. Its discussion confirms oversized native-menu fonts and padding on KDE and other Linux desktops, including https://github.com/microsoft/vscode/issues/224515#issuecomment-2265127532. The full discussion was inspected, but it does not establish the Plasma 6.6/Global Menu interaction or prove that this report has the same cause; it is a related lead rather than a verified full-scope canonical.
- **Upstream ownership evidence:** In https://github.com/electron/electron/issues/42262#issuecomment-2346578790, an Electron maintainer attributes changed menu appearance to Chrome Refresh 2023. https://github.com/electron/electron/issues/42262#issuecomment-2544981851 explains that Electron will not revert that Chromium change. This supports upstream investigation, but does not conclusively diagnose this newer KDE configuration.
- **Verification limits:** Read-only source inspection cannot observe font sizing or toolkit/display behavior on the reporter's KDE environment. No runtime reproduction or behavior-changing fix commit was established, so neither a completed close nor a not-reproducible close is supported.
