# Issue #339694 — File names not showing in approval card

[https://github.com/microsoft/vscode/issues/339694](https://github.com/microsoft/vscode/issues/339694)

## Summary

Already correctly labeled and routed (bug, agent-host, containers) for this brand-new agent-host feature; traced the likely source but the behavior may be partly by design, so this stays open for the feature owner to confirm intent before any fix.

## Change summary

The compact pending-approval card in the Agent Sessions view doesn't show which file(s) a pending edit confirmation affects.

## Best solution

Have the agent-host feature owner confirm whether the compact approval card is meant to surface edited file names for `modifiedFilesConfirmation` tool calls, then either source the label from `toolSpecificData.modifiedFiles` (mirroring the existing `terminal`-kind special case) or fix the upstream confirmation-title text to include the filename.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionApprovalModel.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentSessionApprovalModel.test.ts`
- **Validation:** Update/add a case in agentSessionApprovalModel.test.ts for a modifiedFilesConfirmation tool invocation with non-empty modifiedFiles asserting the card label includes the edited file name(s).
- **Behavior:**

  > The compact pending-approval card (shown in the Agent Sessions list/title bar widget) should let the user tell which file(s) a pending edit confirmation affects, without having to open the full chat transcript. Today it shows only the generic confirmation question text for file-edit confirmations. Acceptance: for a `modifiedFilesConfirmation` tool call with one or more modified files, the card label surfaces the file name(s); terminal and other confirmation kinds are unaffected.
- **Trace:**

  > In `_trackModel` (agentSessionApprovalModel.ts), the label for any non-'terminal' toolSpecificData kind is taken from `confirmationMessages.title`/`detail`, never from `toolSpecificData.modifiedFiles`. The modifiedFiles array (built in stateToProgressAdapter.ts `toolCallStateToInvocation`, ~line 2653-2672) already carries `title: basename(edit.resource)` per file, but nothing wires it into the approval label — the only kind with special per-field label handling today is 'terminal' (building the label from the command line). An existing unit test (agentSessionApprovalModel.test.ts, 'surfaces a single-choice file approval...') currently asserts the generic-title behavior, so changing this needs to confirm that test's expectation is wrong/outdated rather than intentional. Do not touch the terminal-label path or the multi-choice ('Move'/'Copy') skip logic (`options.length !== 1`).
- **Open decisions:**
  - Should the compact approval card show edited file name(s) for modifiedFilesConfirmation tool calls, sourced client-side from toolSpecificData.modifiedFiles, or should the fix instead be to make the upstream confirmationTitle text (set by the agent host/tool) include the filename?
  - When multiple files are edited in one confirmation, should the card list all file names, a truncated subset, or just a count?

## Evidence

- **label source:** src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionApprovalModel.ts `_trackModel`: for any toolSpecificData kind other than 'terminal', the card label comes from `confirmationMessages.title` (the generic question), not from `toolSpecificData.modifiedFiles`, even though modifiedFiles entries carry `title: basename(edit.resource)` and `description` (file path).
- **title construction:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts `toolCallConfirmationMessages` (~line 2762) sets `confirmationMessages.title` from `presentation.confirmationTitle ?? tc.confirmationTitle ?? tc.displayName` — a generic string unrelated to the modifiedFiles list built a few lines earlier (~2653-2672).
- **existing test asserts current behavior:** src/vs/workbench/contrib/chat/test/browser/agentSessions/agentSessionApprovalModel.test.ts 'surfaces a single-choice file approval...' asserts `label: 'Create file?'` (the generic title) for a modifiedFilesConfirmation tool invocation with `modifiedFiles: []`, suggesting this may currently be intentional/tested rather than an obvious oversight.
