# Issue #329334 — Show response duration and token usage after each Copilot Chat response

[https://github.com/microsoft/vscode/issues/329334](https://github.com/microsoft/vscode/issues/329334)

## Summary

Current main substantially covers the request for Agent Host responses, but a real provider-coverage gap remains: elapsed time is available through `chat.verbose`, while whole-turn token totals are currently supplied only by Agent Host sessions. Keep this open as a feature request for consistent per-response usage details across Copilot Chat providers.

## Change summary

Show elapsed time and input/output token usage after every Copilot Chat response, with optional agent-wide call and tool-time totals.

## Best solution

Extend the existing response-details footer and usage model so every Copilot Chat provider can report accurate whole-turn token totals through the same hover used by Agent Host sessions; preserve the existing `chat.verbose` timing behavior and omit totals when a provider cannot report them reliably.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/common/model/chatModel.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`
- **Validation:** Add provider-path and renderer tests proving that a completed non-Agent-Host response with reported whole-turn usage exposes input/output totals through the response-details footer, while providers without reliable totals continue to omit the token breakdown.
- **Behavior:**

  > Every completed Copilot Chat response should expose its elapsed response time and, when the provider reports reliable usage, whole-turn input and output token totals. Multi-call agent turns should aggregate usage across their model calls without double-counting cached input or subagent work. Responses from providers that do not report reliable totals should not display fabricated zeroes. Existing timestamp, accessibility, and compact-footer behavior must remain intact.
- **Trace:**

  > Elapsed time already flows through `ChatResponseModel.elapsedMs` and is rendered by `renderChatResponseDetails` in `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts` when `chat.verbose` is enabled. `formatResponseTokenStats` in that file already renders per-model input, cached-input, and output totals. The data contract is `IChatUsage.modelTotals` in `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, whose source comment says only Agent Host sessions supply it today; Agent Host maps the totals in `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`. The planning boundary is usage propagation and aggregation for the remaining Copilot Chat provider paths; do not replace the established footer/hover interaction or synthesize totals from incomplete data. Existing work is documented by https://github.com/microsoft/vscode/commit/de6ea36c9e3ed055e2ff0dcd00759d672c2f4e96 and https://github.com/microsoft/vscode/commit/909ca830f1faec21594f26c37ca796e545793b32.

## Evidence

- **existing duration capability:** https://github.com/microsoft/vscode/commit/de6ea36c9e3ed055e2ff0dcd00759d672c2f4e96 added chat timestamps and elapsed response time. `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts` registers the default-enabled `chat.verbose` setting, and `chatListRenderer.ts` renders `element.model.elapsedMs` in the response footer.
- **existing token capability:** https://github.com/microsoft/vscode/commit/909ca830f1faec21594f26c37ca796e545793b32 added a keyboard-accessible response-footer hover with per-model input, cached-input, and output token totals for completed Copilot SDK Agent Host responses.
- **remaining provider gap:** `src/vs/workbench/contrib/chat/common/chatService/chatService.ts` explicitly documents that `IChatUsage.modelTotals` is supplied only by Agent Host sessions today; `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts` consequently shows no token breakdown when those totals are absent.
- **no canonical duplicate:** The older duration requests https://github.com/microsoft/vscode/issues/322892 and https://github.com/microsoft/vscode/issues/293877 are closed and therefore cannot serve as duplicate canonicals; the open telemetry issue https://github.com/microsoft/vscode/issues/317837 concerns OTLP cached-token metrics rather than response-footer metadata.
