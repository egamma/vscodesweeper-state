# Issue #113568 — Keep specific extension enabled while running Extension Bisect

[https://github.com/microsoft/vscode/issues/113568](https://github.com/microsoft/vscode/issues/113568)

## Summary

Keep open as the canonical request for retaining required extensions during Extension Bisect. Current source has automatic exceptions for remote resolvers and environment-enabled extensions, but no user-facing selection for arbitrary required extensions; later duplicate reports demonstrate continuing demand.

## Change summary

Allow users to keep selected extensions enabled throughout Extension Bisect so extension-interaction problems remain testable.

## Best solution

Provide a supported way to designate required extensions as the fixed baseline for a bisect session, rather than relying on manual enablement changes. Decide how users select that baseline and whether it persists before implementing the bounded bisect workflow change.

- **Trace:**

  > In src/vs/workbench/services/extensionManagement/browser/extensionBisect.ts, extension.bisect.start collects enabled user extensions, and ExtensionBisectService.start persists their IDs in BisectState. isDisabledByBisect applies the current search partition, except for remote resolver and environment-enabled extensions; there is no ordinary user-selected baseline in the action or persisted state. - **Open decisions:**
