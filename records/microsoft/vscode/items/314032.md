# Issue #314032 — LLM Chat completions being used  for UI decoration / title generation/ Progress Messages

[https://github.com/microsoft/vscode/issues/314032](https://github.com/microsoft/vscode/issues/314032)

## Summary

Current main still performs background utility-model requests for chat titles, inline-chat progress text, and thinking summaries. User-level routing and disable controls now cover much of the request, but the requested enterprise policy and authoritative billing/quota documentation remain unresolved.

## Change summary

Provide transparent user and enterprise controls over cloud-backed utility requests used for chat UI text, and document whether those requests consume quota or incur charges.

## Best solution

Retain the existing utility-model settings, add an enterprise-managed control governing whether hosted utility models may be used, and document the quota or billing treatment of background utility requests. The control should cover the relevant core and Copilot-owned call paths consistently rather than requiring users to disable each decoration separately.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts`, `extensions/copilot/src/extension/prompt/node/title.ts`, `extensions/copilot/src/extension/inlineChat2/node/progressMessages.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts`
- **Validation:** Add focused endpoint-routing tests proving an enforced no-hosted-utility policy prevents Copilot utility endpoint selection while preserving local/main-agent routing, then run the canonical policy export check and existing utility-model tests.
- **Behavior:**

  > When an organization disallows hosted utility models, chat UI decoration must not silently send title, progress-message, or thinking-summary requests to a Copilot-hosted model. Users may still use an allowed local or BYOK utility model, and affected UI must fall back gracefully when no utility model is available. Settings and documentation must clearly identify which background requests are covered and whether permitted hosted requests consume quota or incur charges.
- **Trace:**

  > Chat titles originate in ChatTitleProvider at extensions/copilot/src/extension/prompt/node/title.ts. Inline-chat progress generation is owned by InlineChatProgressMessages in extensions/copilot/src/extension/inlineChat2/node/progressMessages.ts, including two constructor-time prewarm requests and a contextual request per inline-chat operation. Thinking summaries are generated in ChatThinkingContentPart at src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts and already have a feature-specific disable setting. Utility-family routing is centralized in ProductionEndpointProvider at extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts, while the user-facing settings are registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. Existing routing and fallback behavior should remain unchanged when no enterprise restriction applies; the uncertainty begins at the required policy scope and billing contract.
- **Open decisions:**
  - Should the enterprise control prohibit only GitHub-hosted utility models, or disable all model-backed utility UI generation including organization-approved BYOK models?
  - Should one policy govern every built-in utility flow, or only decorative title, progress, and thinking-summary requests?
  - What quota and billing statement is authoritative for non-user-initiated utility requests, and where should that statement be documented?

## Evidence

- **title request:** extensions/copilot/src/extension/prompt/node/title.ts still resolves `copilot-utility-small` and sends a non-user-initiated `conversation-background` request from ChatTitleProvider.
- **progress requests:** extensions/copilot/src/extension/inlineChat2/node/progressMessages.ts prewarms both generate and edit caches with utility-model requests, while inlineChatIntent.ts also requests a contextual progress message for each inline-chat operation.
- **thinking-summary request:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts selects the `copilot-utility-small` alias to summarize thinking content; `chat.agent.thinking.generateTitles` can disable this specific request.
