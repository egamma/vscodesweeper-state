# Issue #109460 — Support theme icon colour in all API places

[https://github.com/microsoft/vscode/issues/109460](https://github.com/microsoft/vscode/issues/109460)

## Summary

The tracked API consistency work remains incomplete: current main still discards `ThemeIcon.color` when converting extension-provided quick input buttons. The newer related issues are narrower and younger, so this re-reviewed umbrella should remain open rather than being closed as their duplicate.

## Change summary

Honor `ThemeIcon.color` for `QuickInputButton` and update the API documentation once the remaining support is complete.

## Best solution

Complete the remaining `QuickInputButton` color plumbing across the extension-host bridge and shared quick-input button renderer, then update the `ThemeIcon.color` JSDoc. Treat https://github.com/microsoft/vscode/issues/185356 as a current reproduction and implementation discussion under this older umbrella.

- **Behavior:**

  > A `QuickInputButton` whose `iconPath` is a `ThemeIcon` with a `ThemeColor` must render that icon using the requested theme color in every quick-input button location. Buttons using an uncolored `ThemeIcon` or URI icon must retain their existing appearance. The public `ThemeIcon.color` documentation must no longer claim that only tree items honor the color once this support is present.
- **Trace:**

  > `MainThreadQuickOpen.expandIconPath` in `src/vs/workbench/api/browser/mainThreadQuickOpen.ts` currently converts a `ThemeIcon` to a class and explicitly drops its color. The receiving `IQuickInputButton` contract in `src/vs/platform/quickinput/common/quickInput.ts` has no color-bearing representation, and `quickInputButtonToAction` in `src/vs/platform/quickinput/browser/quickInputUtils.ts` feeds all title, inline, input, list-item, separator, and quick-input-tree button locations. Quick-pick item icons already carry an `iconColor` and render it through a theme CSS variable in `quickInputList.ts`, demonstrating the expected visual semantics. Keep the scope to the issue's remaining `QuickInputButton` checkbox and its JSDoc; do not broaden this change to every newer `ThemeIcon` consumer or alter uncolored icon behavior. Current corroborating discussion is at https://github.com/microsoft/vscode/issues/185356; https://github.com/microsoft/vscode/issues/111616 is a possible mechanism discussion, not a canonical replacement for this older issue.

- **remaining API limitation:** `IQuickInputButton` in `src/vs/platform/quickinput/common/quickInput.ts` still exposes only URI-based `iconPath` and a string `iconClass`, while `quickInputButtonToAction` in `src/vs/platform/quickinput/browser/quickInputUtils.ts` preserves only those representations.
