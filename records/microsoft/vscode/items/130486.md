# Issue #130486 — Stale semantic tokens across several files

[https://github.com/microsoft/vscode/issues/130486](https://github.com/microsoft/vscode/issues/130486)

## Summary

Still a valid open design issue: the `onDidChangeSemanticTokens` event remains `Event<void>` with no URI-based invalidation support. The core request — efficient cross-file semantic token refresh — has not been implemented. Partial progress (only fetching for visible documents, 7ba867b19ad) helps but doesn't address the fundamental problem, as confirmed by the Dec 2025 comment from DanTup.

## Change summary

When editing file A, semantic tokens in visible file B (which depends on A) are not efficiently refreshed — the refresh event lacks URI granularity, causing redundant re-requests or stale highlighting.

## Best solution

Extend `onDidChangeSemanticTokens` to accept an optional URI array (`Event<void | Uri[]>`) so providers can specify which files are invalidated, and coordinate with the LSP spec (https://github.com/microsoft/language-server-protocol/issues/1163). This avoids redundant re-requests for unchanged files and prevents stale tokens in dependent files. The design discussion in this issue (especially comments 16–18) outlines the approach; it needs a final decision and implementation in the VS Code API, the LSP binding, and the LSP spec.
