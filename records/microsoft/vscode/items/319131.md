# Issue #319131 — Copilot agent model settings silently ignored when model ID format doesn't match internal ID — falls back to system default with no warning

[https://github.com/microsoft/vscode/issues/319131](https://github.com/microsoft/vscode/issues/319131)

## Summary

Still reproduces on main: the agent model override settings (askAgent, implementAgent, exploreAgent) pass the raw config string directly to the agent config with no validation or fuzzy matching — a display-name-style value silently falls back to the default model. A team member acknowledged the issue but no fix has landed.

## Change summary

Copilot agent model override settings silently ignore values that don't match internal model IDs, falling back to the default with no warning.

## Best solution

Add model ID validation at the point where agent model overrides are read (e.g. in `askAgentProvider.ts`, `planAgentProvider.ts`, `exploreAgentProvider.ts`) — either resolve display names to internal IDs, or emit a warning in the Copilot output channel when a configured model string doesn't match any known model ID. The related execution subagent issue (https://github.com/microsoft/vscode/issues/320231) was fixed separately; these agent-type settings need consistent handling as the team member noted.
