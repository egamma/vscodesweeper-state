# Issue #332810 — SDK permissions: Windows filesystem-root selectors do not match drive-qualified paths

[https://github.com/microsoft/vscode/issues/332810](https://github.com/microsoft/vscode/issues/332810)

## Summary

Freshly filed, team-authored bug report (created hours ago) with a detailed, self-confirmed reproduction: a managed deny rule using a Windows filesystem-root selector (`Read(//C:/...)`) fails to match the drive-qualified native path, falling through to an approval prompt instead of an immediate denial. No fix exists on main yet.

## Change summary

On Windows, permission selectors anchored at the filesystem root (`//C:/...`) don't match native drive-qualified paths (`C:\...`), so a configured deny rule silently falls through to an interactive approval prompt instead of blocking the read.

## Best solution
