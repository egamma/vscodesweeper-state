# Issue #283833 — Remote Host WSL Disconnect

[https://github.com/microsoft/vscode/issues/283833](https://github.com/microsoft/vscode/issues/283833)

## Summary

This is a Remote SSH + WSL extension issue — the entire scenario (SSH into a remote host, switch to WSL, open a folder) is owned by the Remote Development extensions, which have their own tracker at microsoft/vscode-remote-release. Per VS Code triage practice, this should be moved there so the Remote team can investigate the regression introduced around version 1.107.

## Change summary

Opening a folder in WSL on a remote SSH host causes a disconnect/crash starting in VS Code 1.107.

## Best solution

Move this issue to microsoft/vscode-remote-release where the Remote SSH and WSL extension teams can investigate the regression. Multiple users have confirmed the problem persists through 1.109+, and the workaround of deleting .vscode-server directories is only temporary — the Remote team needs to identify what changed in the 1.107 timeframe.
