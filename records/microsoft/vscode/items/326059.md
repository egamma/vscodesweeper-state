# Issue #326059 — "Render whitespace" doesn't show NBSP

[https://github.com/microsoft/vscode/issues/326059](https://github.com/microsoft/vscode/issues/326059)

## Summary

The behavior is intentional: `editor.renderWhitespace` visualizes ordinary spaces and tabs, while Unicode highlighting is the established surface for NBSP and other unusual invisible characters. An exact predecessor was closed by the editor maintainer after Unicode highlighting shipped, so this can close as designed.

## Change summary

Extend `editor.renderWhitespace` to visualize NBSP, figure space, ideographic space, and similar Unicode whitespace characters.

## Best solution

Keep ordinary whitespace rendering and unusual-Unicode detection as separate editor features; use `editor.unicodeHighlight.nonBasicASCII` when all such characters must be visible.

## Evidence

- **current source:** On current main, `WhitespaceOverlay._applyRenderWhitespace` in `src/vs/editor/browser/viewParts/whitespace/whitespace.ts` explicitly skips every character except `CharCode.Tab` and `CharCode.Space`; the legacy `_applyRenderWhitespace` path in `src/vs/editor/common/viewLayout/viewLineRenderer.ts` likewise recognizes only those two characters.
- **maintainer precedent:** The exact earlier request https://github.com/microsoft/vscode/issues/13239 was closed as completed after an editor maintainer stated that Unicode highlighting implements this capability: https://github.com/microsoft/vscode/issues/13239#issuecomment-1344761728.
- **broader precedent:** The broader request covering other invisible characters, https://github.com/microsoft/vscode/issues/2878, was closed on the same basis: https://github.com/microsoft/vscode/issues/2878#issuecomment-1344761235.
- **existing capability:** `src/vs/editor/common/config/editorOptions.ts` registers `editor.unicodeHighlight.nonBasicASCII` and `editor.unicodeHighlight.invisibleCharacters`; the reporter confirmed that enabling `editor.unicodeHighlight.nonBasicASCII` makes the affected characters visible.
