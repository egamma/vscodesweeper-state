# Issue #314405 — Copy-button from a code-block does not work while agent is still running

[https://github.com/microsoft/vscode/issues/314405](https://github.com/microsoft/vscode/issues/314405)

## Summary

This remains a valid streaming-interaction bug on current main. An older report was closed after a fix, but this report postdates that fix, and the current rendering path still detaches and remounts the code-block element while a pointer interaction can be in progress.

## Change summary

Copying a rendered chat code block does not update the clipboard until the agent finishes streaming its response.

## Best solution

Preserve an in-progress code-block toolbar interaction across streaming Markdown renders so copying the currently visible code succeeds without waiting for the complete response. Validation should exercise the pointer interaction across an actual streaming render, not only invoke the copy command directly.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatContentCodePools.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatMarkdownContentPart.test.ts`
- **Validation:** Use a browser-level chat scenario that starts copying a visible code block, advances the streaming response through another render before releasing the pointer, and verifies that the clipboard receives the code. Repeat after streaming completes and verify that ordinary code-block reuse, toolbar visibility, and completed-response copying remain unchanged.
- **Behavior:**

  > A code block's Copy action must copy the code currently visible when activated, even while the surrounding agent response continues streaming. Streaming updates must not cancel an in-progress click or require the user to wait for response completion. Acceptance checks should cover a render occurring between pointer-down and pointer-up, copying after completion, and multiple code blocks in one response.
- **Trace:**

  > ChatMarkdownContentPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts invokes renderMarkdown during incremental streaming, disposes the previous render store, and reacquires ordinary CodeBlockPart instances from EditorPool. EditorPool in chatContentCodePools.ts resets and releases the keyed part, after which the same part and toolbar DOM can be remounted. CodeBlockPart tracks hover visibility across this cycle, but browser click dispatch can still be lost when its target is detached during the gesture; the command path in chatCodeblockActions.ts writes to IClipboardService correctly once invoked. The earlier fix in https://github.com/microsoft/vscode/pull/307978 addressed visibility for https://github.com/microsoft/vscode/issues/255290, but this report was reproduced on a later build. Preserve pooling, incremental rendering, lazy toolbar creation, and completed-response behavior; the plan should first establish a real pointer-and-rerender regression check because direct command invocation does not exercise the defect.

- **current source path:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts calls renderMarkdown during incremental streaming; renderMarkdown disposes the previous render store before obtaining the keyed CodeBlockPart again. EditorPool in chatContentCodePools.ts resets and releases that part, so its DOM element is detached and remounted during streaming.
- **interaction race:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts preserves toolbar visibility with `_isHovered` and `force-visibility`, but this does not preserve a browser click whose target is detached between pointer-down and pointer-up. The copy action itself writes `context.code` directly through IClipboardService, so the failure is in delivering the toolbar action during rerender rather than clipboard handling after dispatch.
- **related change:** Commit 6baf58bfa86dbf2c31d63b722fc074ce85c66e43 from 2026-04-22 changed the toolbar to be created lazily on mouseenter. It is included in the timeframe of the reported build and retains the detach/remount interaction path on current main.
