# Issue #147636 — Show breadcrumbs whilst debugging

[https://github.com/microsoft/vscode/issues/147636](https://github.com/microsoft/vscode/issues/147636)

## Summary

Breadcrumbs still exclude debugger-provided virtual documents, including their symbol breadcrumbs. Keep this accepted Backlog request open: the suggested duplicate is closed, and its decline does not override the improvement direction discussed here.

## Change summary

Show useful breadcrumbs for debugger-provided source documents that are not backed by a file system provider.

## Best solution

Define a degraded breadcrumbs experience for debugger-provided documents, retaining symbol navigation where an outline is available without implying that remote path siblings can be browsed. Decide whether a non-browsable source path should also appear.

- **Behavior:**

  > Opening source supplied through a debug adapter currently removes all breadcrumbs even when breadcrumbs are enabled. The intended experience should preserve useful navigation when symbol information is available, without offering filesystem operations that the source cannot support. Acceptance must cover the agreed treatment of the source path, available and unavailable outlines, and unchanged breadcrumbs for ordinary files.
- **Trace:**

  > BreadcrumbsControl.update() in src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts rejects resources without an IFileService provider before creating BreadcrumbsModel. DebugContentProvider in src/vs/workbench/contrib/debug/common/debugContentProvider.ts supplies debug-scheme text models through DAP rather than a filesystem registration. BreadcrumbsModel.getElements() combines independently configured file and outline elements, while _bindToEditor() requests an outline for breadcrumbs. The thread in https://github.com/microsoft/vscode/issues/147636 identifies both symbol breadcrumbs and a non-browsable path as possible improvements; it does not settle their presentation. Preserve normal file browsing and do not assume arbitrary virtual URI paths have filesystem hierarchy semantics. The same symptom was tracked in https://github.com/microsoft/vscode/issues/62290, but that issue is closed as out of scope and is not an available duplicate target.
- **Open decisions:**
  - For debugger-provided documents without a filesystem provider, should breadcrumbs show only available symbols, or also display a non-browsable source path?
