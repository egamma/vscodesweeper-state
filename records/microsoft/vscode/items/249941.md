## Change summary

Provide an agent tool that attributes a code snippet to relevant commits and PR messages to support documentation writing.

## Best solution

Define a read-only, snippet-scoped history tool for the built-in agent experience, using existing Git integration where appropriate. First settle whether its contract includes fetching PR messages or only returning locally available commit context.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`, `extensions/copilot/src/extension/tools/common/toolNames.ts`, `extensions/copilot/src/extension/tools/node/scmChangesTool.ts`, `extensions/copilot/src/platform/git/common/gitService.ts`, `extensions/git/src/api/api1.ts`, `extensions/git/src/git.ts`
- **Validation:** The plan should establish an executable tool test using a temporary repository with adjacent lines attributed to different commits: requesting one snippet must return its relevant commit context without unrelated-line attribution or repository modifications. If PR-message retrieval is included, test it with a mocked provider and explicit unavailable-provider behavior.
- **Behavior:**

  > An agent writing documentation can request history for a specific code snippet without constructing a shell command. The result identifies the commits relevant to that snippet and supplies the agreed historical message context, rather than unrelated working-tree changes. Acceptance should cover a snippet spanning multiple commits and clear behavior when attribution or additional message context is unavailable. The operation is read-only.
- **Trace:**

  > Current Git support already supplies blame(path) and blame2(path, ref, ignoreWhitespace) in extensions/git/src/git.ts, and the Git API exposes blame through extensions/git/src/api/api1.ts. Human-facing blame processing in extensions/git/src/blame.ts maps editor lines to blame ranges and retrieves commit messages for hovers. The Copilot tool registry in extensions/copilot/src/extension/tools/common/toolNames.ts has no dedicated blame tool; the neighboring GetScmChangesTool retrieves working-tree changes instead of history. Existing terminal execution does not remove the model's responsibility to construct Git commands. The unresolved boundary is whether the requested tool must obtain remote PR messages or only local commit context, and how its input identifies the snippet. Preserve existing blame UI and working-tree tool behavior; this review does not establish a defect in either.
- **Open decisions:**
  - Must the tool retrieve associated PR messages, or is locally available commit-message context sufficient, with PR references returned when available?
  - Does the tool accept an explicit file and line range, or must it locate a supplied code snippet and define behavior for ambiguous matches?
