## Change summary

Settings Sync repeatedly requests Microsoft sign-in after a password change despite renewed Windows and VS Code authentication.

## Best solution

Consolidate with the existing Microsoft Authentication issue only if the failing token acquisition is confirmed to match its diagnosed error.

Capture Microsoft Authentication and Settings Sync logs, trigger sync periodically, and verify successful synchronization across at least two token-renewal cycles without repeated sign-in prompts. Confirm that genuinely revoked credentials still require reauthentication.
- **Behavior:**

  > After a Microsoft password change, the user renews Windows authentication and signs into Settings Sync again, but VS Code requests another sign-in approximately every 30 minutes while still displaying the account. Successful renewed authentication should allow Settings Sync to continue through subsequent token renewals. Acceptance must verify actual synchronization, not merely account visibility, while retaining legitimate prompts when credentials require user interaction.
- **Trace:**

  > MsalAuthProvider.getSessions in extensions/microsoft-authentication/src/node/authProvider.ts exposes cached accounts for unscoped requests but requires successful silent token acquisition for scoped sessions. CachedPublicClientApplication.acquireTokenSilent in extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts delegates to MSAL and includes ID-token refresh handling and native-broker integration. UserDataSyncWorkbenchService.updateCurrentAccount clears its current account when the scoped lookup has no matching session. This establishes a plausible path for the visible discrepancy, not the reporter's root cause; diagnosis must start with the supplied Windows reproduction and correlate the acquisition failure with sync state. https://github.com/microsoft/vscode/issues/242814 separates similar symptoms by error code, while https://github.com/microsoft/vscode/issues/333975 concerns transient network failure. Preserve credential-revocation semantics and do not treat account-menu presence as proof of a usable sync token.

## Evidence

These are actionable retest steps; the report has no confirming comments or authentication logs.
- **Current account visibility and token lookup differ:** extensions/microsoft-authentication/src/node/authProvider.ts:173–199 returns cached accounts for unscoped getSessions calls, whereas getAllSessionsForPca at lines 451–544 acquires tokens for scoped requests and skips accounts on acquisition errors.
