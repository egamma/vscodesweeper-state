# Issue #333470 — Windows CLI binary reports incorrect minor version in File Properties

[https://github.com/microsoft/vscode/issues/333470](https://github.com/microsoft/vscode/issues/333470)

## Summary

Confirmed on current main: the FILEVERSION/PRODUCTVERSION bitshift in cli/build.rs packs major<<48 | minor<<16 | patch, which leaves the minor field (bits 32-47) at zero and shifts the actual minor/patch into the wrong 16-bit slots, exactly as described.

## Change summary

Windows CLI binary's File Properties version fields are malformed because the bit-packing math skips the minor-version field and shifts minor/patch into the wrong positions.

## Best solution

Fix the shift math in cli/build.rs (lines 214-215) to place major/minor in the high 32 bits and build/revision in the low 32 bits, e.g. (major << 48) | (minor << 32) | (patch << 16), matching Windows VERSIONINFO's four 16-bit fields.
