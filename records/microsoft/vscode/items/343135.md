# Issue #343135 — Copilot harness (Agent Host) ignores `timeout` from user mcp.json: remote MCP tool calls cut off at ~180 s

[https://github.com/microsoft/vscode/issues/343135](https://github.com/microsoft/vscode/issues/343135)

## Summary

Keep open for a decision on configurable MCP tool-call timeouts across harnesses. Current source confirms that timeout is neither a supported VS Code mcp.json property nor forwarded to Copilot, so this is a missing configuration capability rather than a demonstrated regression in an existing supported setting.

## Change summary

Allow long-running remote MCP tools to use a configurable timeout through VS Code's mcp.json, or clearly explain the unsupported configuration and harness difference.

## Best solution

Provide an explicit, documented timeout contract for VS Code-configured MCP servers, including its units and behavior across harnesses, and preserve supported values through discovery and SDK conversion. If maintainers choose not to support this capability, document the limitation and the runtime-native configuration alternative without implying that Local already honors the unsupported property.

- **Unsupported VS Code property:** src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts:294-342 defines mcpRemoteServerSchema with additionalProperties: false and no timeout property. src/vs/platform/mcp/common/mcpPlatformTypes.ts:47-79 likewise defines no per-server timeout. Local completing a long call therefore does not establish that it honored the supplied timeout value.
- **Forwarding path omits timeout:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupport.ts:662-684 projects HTTP launch definitions into type, transport, url and headers only. collectNonPluginMcpServers in agentHostLocalCustomizations.ts:200-215 forwards that projection, and syncedCustomizationBundler.ts serializes it into the synthetic .mcp.json.
- **Additional conversion boundaries:** normalizeMcpServerConfiguration in src/vs/platform/agentPlugins/common/pluginParsers.ts:536-591 reconstructs supported server fields without timeout. toCopilotMcpServerConfiguration in src/vs/platform/mcp/common/mcpCopilotConfiguration.ts also emits no timeout; src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:91-92 uses that converter for SDK delivery. Adding support would require an explicit configuration contract, not merely passing through one missing field at the final handoff.
- **Migration tracking is related, not a verified duplicate:** https://github.com/microsoft/vscode/issues/332782 is open and documents partial support for user mcp.json, but does not identify timeout support or this long-running-call failure. https://github.com/microsoft/vscode/issues/342924 concerns plugin loading and discovery, not per-server request deadlines; neither establishes a canonical duplicate for this report.
