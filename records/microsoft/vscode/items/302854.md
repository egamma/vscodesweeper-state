## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/302854 reports Search and Quick Open failing on Raspberry Pi 5 with 16384-byte pages, accompanied by '<jemalloc>: Unsupported system page size'; switching to 4096-byte pages restores both features.
- **Behavior-changing fix:** https://github.com/microsoft/ripgrep-prebuilt/commit/e6ca653da1abdb4f1e695d6cd318fd1e1071656d, committed 2026-03-08T04:20:45Z, changes build/build.sh in the added lines following CARGO="$(builder)" to export JEMALLOC_SYS_WITH_LG_PAGE=16 for every aarch64-musl cargo invocation. Previously the later test invocation rebuilt jemalloc with the default page configuration, undoing the release-build override. This directly changes the allocator initialization responsible for the reported abort. build/linux.yml also verifies the generated LG_PAGE definition is 16.
- **Fixed binary provenance:** The ripgrep-prebuilt v15.0.1 tag contains the fixing commit: GitHub compare reports one commit ahead and zero behind. Current microsoft/vscode-ripgrep build/platforms.js selects v15.0.1 and aarch64-unknown-linux-musl for linux/arm64; binaries.lock.json records that same target and version, and packages/ripgrep-universal/package.json identifies package version 1.18.0.
- **Adoption on the reported paths:** Current package-lock.json and remote/package-lock.json both lock @vscode/ripgrep-universal to 1.18.0. src/vs/base/node/ripgrep.ts imports its rgPath; src/vs/workbench/services/search/node/ripgrepFileSearch.ts::spawnRipgrepCmd launches that binary with --files, and ripgrepTextSearchEngine.ts launches the same binary for text search. The fix is therefore consumed by both failing surfaces, not merely available as an unused dependency. Earlier adoption is documented by https://github.com/microsoft/vscode/commit/7d59e8c22fa13f3ec1b4845fee5e5fa452eebf52, which updates @vscode/ripgrep to ^1.17.1; this dependency bump is shipping evidence, not the cited fix.
- **Matching verification:** https://github.com/microsoft/vscode/issues/299587#issuecomment-4042010765 confirms workspace search with both 4KB and 16KB ARM64 pages after the fix. https://github.com/microsoft/vscode/issues/299587#issuecomment-4069162266 explicitly confirms both global Search and Quick Open on Raspberry Pi 5, Debian, Remote-SSH, and 1.112.0-insider. https://github.com/microsoft/vscode/issues/300662#issuecomment-4130929021 confirms resolution in VS Code 1.112.0. No local hardware reproduction was attempted.
