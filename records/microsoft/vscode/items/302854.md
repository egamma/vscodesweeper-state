# Issue #302854 — Ripgrep crashes on Raspberry Pi 5 (16KB page size) causing Search and Quick Open to fail

[https://github.com/microsoft/vscode/issues/302854](https://github.com/microsoft/vscode/issues/302854)

## Summary

The bundled ripgrep binary crashes on 16KB page-size Linux kernels because its jemalloc allocator is compiled without large-page support. This is an upstream limitation in how ripgrep builds jemalloc (BurntSushi/ripgrep#2180, closed wontfix). VS Code could address it by building its bundled ripgrep with `JEMALLOC_SYS_WITH_LG_PAGE=16` or by switching ripgrep to a system allocator build.

## Change summary

VS Code's search and Quick Open features fail on Raspberry Pi 5 (and other aarch64 Linux systems with 16KB page size) because the bundled ripgrep binary crashes due to jemalloc's lack of large-page support.

## Best solution

Rebuild the bundled ripgrep (via `@vscode/ripgrep-universal`) with `JEMALLOC_SYS_WITH_LG_PAGE=16` so the jemalloc allocator supports page sizes up to 64KB, covering Raspberry Pi 5 and similar aarch64 platforms. Alternatively, build the aarch64-linux ripgrep binary without jemalloc. The fix belongs in the `@vscode/ripgrep-universal` package build configuration.
