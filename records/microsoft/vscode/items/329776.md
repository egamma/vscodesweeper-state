# Issue #329776 — Support awaited cleanup before agent-created worktrees are removed

[https://github.com/microsoft/vscode/issues/329776](https://github.com/microsoft/vscode/issues/329776)

## Summary

Well-reasoned request for a new lifecycle hook (symmetrical to `worktreeCreated`) so agent-related tooling can await cleanup before an agent worktree is removed; current code confirms no such hook exists, so this needs a product/design decision from the sessions/agent-host owners rather than a quick close.

## Change summary

Add an awaited pre-removal hook (task `runOn: worktreeRemoving` or an extension API like `onWillRemoveAgentWorktree`) so external resources provisioned via `worktreeCreated` tasks can be cleaned up before VS Code deletes the worktree.

## Best solution

A maintainer on the Agents window / agent-host team should evaluate adding a symmetrical `worktreeRemoving` task runOn (or a waitUntil-based extension API) alongside the existing `WorktreeCreatedTaskDispatcher` (src/vs/sessions/contrib/chat/browser/worktreeCreatedTaskDispatcher.ts) and `WorktreeIsolationService.removeSessionWorktree`/`_removeSessionWorktree` (src/vs/platform/agentHost/node/shared/worktreeIsolation.ts) — this is a design decision (timeout/failure semantics, applies to both archive and permanent delete) rather than a mechanical fix.

## Vision fit

- **Fit:** aligned
- **Reason:** This directly extends the agent host/session worktree isolation lifecycle, which is central to the current agent-native editor priorities, by closing a deterministic-cleanup gap in provisioning/teardown of isolated agent sessions.
- **Evidence:** Current priorities: "Agent host & harnesses — one agent host... rolling out as the default for agent sessions, with parity work on tools, terminal integration, permissions, and context" (paraphrased from internal priorities); durable theme "Extension ecosystem — API hygiene" also supports a well-scoped new extension API.
