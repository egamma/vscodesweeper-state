# Issue #325250 — Modern UI: `tab.activeBorder` color customization not respected

[https://github.com/microsoft/vscode/issues/325250](https://github.com/microsoft/vscode/issues/325250)

## Summary

Keep open: current source still has Modern UI tab overrides that hide the normal active tab border elements, so `tab.activeBorder` customization is plausibly still not respected. The issue is already routed to the relevant Modern UI/workbench tabs area, and the linked PR evidence is not enough to prove a completed fix on main.

## Change summary

Modern UI should respect existing workbench color customizations such as `tab.activeBorder` instead of suppressing the customized active tab border.

## Best solution

Have the Modern UI/workbench tabs owners decide whether the new pill-style tabs should preserve `tab.activeBorder` semantics, introduce a Modern UI-specific mapping, or explicitly document/deprecate that color token for this mode.

- **source trace:** src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts reads `TAB_ACTIVE_BORDER` / `TAB_UNFOCUSED_ACTIVE_BORDER`, toggles `tab-border-bottom`, and writes `--tab-border-bottom-color` for active tabs.

- **current theme contract:** src/vs/workbench/common/theme.ts still registers `tab.activeBorder` as the bottom border color for active editor tabs, so the token remains part of the workbench color API.
