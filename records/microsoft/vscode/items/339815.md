# Issue #339815 — fix: register extension install commands in Agents window (fixes #339804)

[https://github.com/microsoft/vscode/issues/339815](https://github.com/microsoft/vscode/issues/339815)

## Summary

Confirmed on current main: the Agents (sessions) window's extensions contribution only registers a config setting, while `workbench.extensions.installExtension`/`uninstallExtension` are registered solely in the main workbench's extensions.contribution.ts, which the sessions bundle never loads. The bot-authored report is well-diagnosed and the fix is bounded; routing to the extensions area for implementation rather than closing.

## Change summary

Invoking extension-install flows (chat agent recommendations, AI customization management, the extension URL handler) inside the Agents/sessions window throws "command 'workbench.extensions.installExtension' not found" because that command is never registered in the sessions window bundle.

## Best solution

Extract the install/uninstall/search command registrations from src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts into a shared, idempotent registerExtensionsCommands() helper and call it from src/vs/sessions/contrib/extensions/browser/extensions.contribution.ts so the sessions window registers the same commands the main workbench does.
