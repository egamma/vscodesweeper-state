# Issue #238301 — Highliting optimisation is not always correct for asymmetric highlits

[https://github.com/microsoft/vscode/issues/238301](https://github.com/microsoft/vscode/issues/238301)

## Summary

Keep open: current highlight reuse still assumes symmetric results, and existing settings do not support the requested asymmetric behavior. A maintainer has accepted the goal but left the performance and API contract unresolved; the matching newer report does not supersede this original issue.

## Change summary

Support position-dependent document highlights without retaining stale results when the cursor moves between highlighted occurrences.

## Best solution

Make the editor able to display asymmetric provider results correctly while preserving responsive highlighting. Settle whether that behavior should apply universally or be explicitly enabled before implementing it in the word highlighter.
