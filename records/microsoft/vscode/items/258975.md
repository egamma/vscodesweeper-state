# Issue #258975 — Optimize  outline view

[https://github.com/microsoft/vscode/issues/258975](https://github.com/microsoft/vscode/issues/258975)

## Summary

Keep open: the clarified request for distinguishing static and instance members remains unsupported by the generic Outline symbol contract and renderer. The issue is accepted in Backlog; the earlier performance-related links do not cover this request.

## Change summary

Visually distinguish static properties and methods from instance members in the Outline view.

## Best solution

Establish how language providers convey static-member metadata, then present that distinction consistently and accessibly in Outline. Existing symbol-kind icons and problem colors do not provide this capability.

- **Fit:** aligned
- **Reason:** Making member semantics easier to recognize supports code navigation and a consistent, self-explanatory editor interface.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/languages.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts`
- **Validation:** After agreeing the provider contract and presentation, use a document-symbol provider fixture containing static and instance properties and methods. Verify that each pair is distinguishable visually and with a screen reader, that providers without modifier metadata retain their existing presentation, and that diagnostic and deprecated decorations remain intact.
- **Behavior:**

  > Outline should let users distinguish static properties and methods from instance members without opening each declaration. The distinction should be understandable across supported themes and available to screen-reader users, not conveyed by color alone. Acceptance should cover both methods and properties, preserve existing diagnostic/deprecated information, and leave providers without the new metadata working as before.
- **Trace:**

  > DocumentSymbolRenderer.renderElement in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts derives icons from symbol kind and handles Deprecated tags, but has no static-member input. The internal DocumentSymbol and SymbolTag declarations in src/vs/editor/common/languages.ts do not expose a standardized static modifier; the public provider contract in src/vscode-dts/vscode.d.ts is a relevant design surface. Outline configuration supplies kind filters and diagnostic decorations, neither of which covers staticness. The unresolved boundary is how providers communicate this semantic information and how Outline presents it; do not infer staticness from member names or repurpose diagnostic colors. The older matching request at https://github.com/microsoft/vscode/issues/117836 is closed and does not establish an open canonical. No code was executed or modified.
- **Open decisions:**
  - Should staticness be exposed through a dedicated symbol modifier or a broader symbol-modifier contract, and which provider-facing API surface should support it?
  - What static-member presentation should Outline standardize, including its screen-reader equivalent and behavior when symbol icons are disabled?
