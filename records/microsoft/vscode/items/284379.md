# Issue #284379 — Enterprise-Managed VS Code with Extensions Marketplace

[https://github.com/microsoft/vscode/issues/284379](https://github.com/microsoft/vscode/issues/284379)

## Summary

Existing enterprise policies, private marketplaces, and profiles cover substantial parts of this request, but do not establish coverage of the proposed container-hosted environment with centrally managed project-group defaults. Keep this open as a feature request while narrowing the remaining requirement; the verified related issues cover only subsets.

## Change summary

Provide an enterprise-managed, container-hosted VS Code environment with approved extensions and profile- or project-group-specific default settings.

## Best solution

Build on existing marketplace policies and profiles rather than introduce a parallel management system. Identify the remaining editor-owned requirement for centrally distributing project-group defaults, separately from enterprise infrastructure provisioning.

## Evidence

- **Requested scope:** https://github.com/microsoft/vscode/issues/284379 requests a common customized container image deployed on physical hosts, Linux VMs, or Kubernetes, serving thousands of users with profiles or project-group tags. There are no comments establishing a narrower accepted design.
- **Existing extension governance:** src/vs/platform/extensionManagement/common/extensionManagement.ts registers extensions.allowed with the AllowedExtensions policy; allowedExtensionsService.ts evaluates publisher, extension, version, and platform restrictions. https://code.visualstudio.com/docs/enterprise/extensions documents these controls and private marketplace deployment as a Docker container.
- **Existing private marketplace and limitation:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts registers extensions.gallery.serviceUrl with the ExtensionGalleryServiceUrl policy. WorkbenchExtensionGalleryManifestService in src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryManifestService.ts reads this setting and loads an account-authorized private marketplace. https://code.visualstudio.com/docs/enterprise/extensions explicitly states that private marketplace connections from VS Code Server and VS Code for the Web are unsupported, so desktop support alone does not settle the proposed hosted deployment.
- **Existing profiles provide partial coverage:** src/vs/workbench/contrib/userDataProfile/browser/userDataProfile.ts registers profile creation, switching, and export actions. https://code.visualstudio.com/docs/configure/profiles documents shareable settings/extensions profiles and folder/workspace associations, but these capabilities do not establish centrally administered project-group defaults.
- **Canonical search:** Verified open https://github.com/microsoft/vscode/issues/27972 concerns system-wide mandatory/default settings; https://github.com/microsoft/vscode/issues/295044 concerns arbitrary settings supplied through enterprise policy; https://github.com/microsoft/vscode/issues/278066 concerns discovery of private marketplace URLs from GitHub enterprise policy; and https://github.com/microsoft/vscode/issues/242922 concerns Windows Intune deployment. Each covers only part of this broader request, so none is a verified duplicate canonical.
- **Previously completed marketplace request:** https://github.com/microsoft/vscode/issues/21839 is closed as completed and requested private extension galleries, not the full managed hosted environment described here. It is neither an open duplicate target nor proof that all of this request is implemented.
