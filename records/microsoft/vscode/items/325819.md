# Issue #325819 — Allow code to set the window title from the Terminal

[https://github.com/microsoft/vscode/issues/325819](https://github.com/microsoft/vscode/issues/325819)

## Summary

This is a valid, currently unsupported CLI feature request rather than a terminal-title bug. It should be routed to the command-line and title-bar owners for a product decision.

## Change summary

Add a CLI option that assigns a meaningful custom window title when opening a file or piped stdin content.

## Best solution

Define a per-invocation CLI title option whose lifetime and reuse-window semantics are explicit, and expose that value to the window-title formatter while preserving the existing `window.title` behavior when the option is omitted.

## Evidence

- **CLI gap:** `src/vs/platform/environment/node/argv.ts` registers the supported CLI options, but has no option for assigning a file, editor, or window title; `NativeParsedArgs` in `src/vs/platform/environment/common/argv.ts` likewise carries no such value.
- **stdin behavior:** `src/vs/code/node/cli.ts` writes piped input to a randomly named `code-stdin-*` temporary file and forwards that path for opening, so the caller cannot attach the query-oriented name requested here.
- **existing title capability:** `src/vs/workbench/browser/parts/titlebar/windowTitle.ts` derives the window title from global `window.title` template variables such as `${activeEditorShort}`; it has no per-CLI-invocation title variable. The existing setting therefore does not cover the central request.
- **canonical search:** Repository issue searches found no older open issue with the same observable request. https://github.com/microsoft/vscode/issues/192689 concerns integrated-terminal tab escape-sequence titles, not naming an editor window opened through the `code` CLI.
