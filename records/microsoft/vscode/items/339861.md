# Issue #339861 — Auto resizing behavior in the grid is confusing

[https://github.com/microsoft/vscode/issues/339861](https://github.com/microsoft/vscode/issues/339861)

## Summary

Confirmed from source: the session grid's insertion path always uses `Sizing.Split`, which only takes space from the single reference view instead of redistributing evenly across an already-even row/column, exactly matching the reported symptom. Already correctly labeled `bug`/`agents-window`; no close warranted.

## Change summary

Inserting a new chat into an already evenly-distributed row of the Agents Window session grid gives the new chat uneven width and can resize the row's height, instead of redistributing space evenly and preserving row height.

## Best solution

In `SessionGridLayout.reconcile()` (src/vs/sessions/browser/parts/sessionGridLayout.ts), use a sizing strategy that redistributes evenly when siblings are already even (e.g. `Sizing.Auto`, which the splitview API defines for exactly this case) instead of unconditionally using `Sizing.Split` for the `addView` call.

- **Auto-fixable:** yes
- **Agent readiness:** implement
- **Rationale:** Root cause traced to a single call site using the wrong Sizing strategy; the splitview API already defines `Sizing.Auto` for exactly this semantics, so the fix is a small, bounded change with a nameable failing test.
- **Likely files:** `src/vs/sessions/browser/parts/sessionGridLayout.ts`, `src/vs/sessions/test/browser/sessionGridLayout.test.ts`
- **Validation:** Add a test to src/vs/sessions/test/browser/sessionGridLayout.test.ts that reconciles three siblings into one row/column so they end up evenly sized, then reconciles a fourth entry with a placement referencing the middle sibling; assert all siblings (including the new one) end up with equal width/height in that row and that the row's overall height is unchanged. This must fail under the current `Sizing.Split` call and pass once the insertion uses even-redistribution (e.g. `Sizing.Auto`).
- **Behavior:**

  > When a new chat is added into a grid row/column whose existing siblings are already evenly sized, the new chat should take an equal share and all siblings should end up evenly redistributed, with the row's overall height unchanged. Today the new chat can land with an uneven share taken only from its immediate reference sibling, and the row can also resize vertically. Acceptance: inserting into an evenly-sized row leaves every sibling (old and new) at equal size, and the row's cross-axis extent is unchanged.
- **Trace:**

  > `SessionGridLayout.reconcile()` in src/vs/sessions/browser/parts/sessionGridLayout.ts (around line 113) calls `this.grid.value.addView(leaf, Sizing.Split, reference, direction)` unconditionally for every new entry. `Sizing.Split` (src/vs/base/browser/ui/splitview/splitview.ts) only halves the *reference view's own* space with the new view, rather than redistributing across all siblings in that branch — exactly the reported symptom. `Sizing.Auto` is defined for precisely this evenness check ('use Distribute when all pre-existing views are distributed evenly, otherwise use Split'), and `Grid.addView` (src/vs/base/browser/ui/grid/grid.ts:388-414) already has a branch handling `size.type === 'auto'`, so no plumbing changes are needed. The boundary: don't touch `moveView`'s use of `Sizing.Split` (line 130, used for drag/drop placement changes, a different interaction) or the unrelated `chatGroupsView.ts`/`desktopWorkbench.ts` call sites, which already use the correct strategy for their own insertion flows. The secondary 'resize on focus' / maximize-on-double-click feedback in the issue is a separate UX suggestion, out of scope for this fix.

## Evidence

- **root cause call site:** src/vs/sessions/browser/parts/sessionGridLayout.ts:113 — `this.grid.value.addView(leaf, Sizing.Split, reference ?? ..., direction)` is used for every placement-based insertion into the session grid.
- **Sizing semantics:** src/vs/base/browser/ui/splitview/splitview.ts:348-389 doc comments: `DistributeSizing` 'uniformly distribute the entire split view space among all views'; `SplitSizing` 'reducing the size of another view'; `AutoSizing` explicitly 'use DistributeSizing when all pre-existing views are distributed evenly, otherwise use SplitSizing' — i.e. `Sizing.Auto` is purpose-built for the exact scenario in this report.
- **contrast with sibling code:** src/vs/sessions/browser/parts/chatGroupsView.ts:612,667,742 and src/vs/sessions/browser/desktopWorkbench.ts:335 already use `Sizing.Distribute` for comparable grid insertions, showing the codebase's established pattern for even redistribution.
- **existing test doesn't cover the reported case:** src/vs/sessions/test/browser/sessionGridLayout.test.ts's 'nested insertion and removal preserve an unrelated user-sized column' test only inserts next to a lone sibling (b alone -> b+c 50/50), where Split and Distribute coincide; no test exercises inserting into a row with 2+ already-even siblings, which is the reported bug.
