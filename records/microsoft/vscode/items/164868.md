# Issue #164868 — GitHub - for VSCode not properly unlinked until VSCode restart

[https://github.com/microsoft/vscode/issues/164868](https://github.com/microsoft/vscode/issues/164868)

## Summary

Keep open: the built-in GitHub clone provider still retains its authenticated REST client after sign-out. An open PR explicitly targets this issue, so the next step is reviewing that implementation rather than closing the report or starting competing work.

## Change summary

Signing out of GitHub should stop the clone picker from using the previous account's authentication and repository results without requiring a restart.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/308927 once account removal and switching correctly invalidate the GitHub REST client and repository cache. Keep this issue open until that implementation is merged and the reported flow is resolved.

## Evidence

- **Reported trigger and maintainer diagnosis:** https://github.com/microsoft/vscode/issues/164868 reports signing out through the Accounts menu and subsequently seeing the previous account's repositories in Git: Clone until restart. In the supplied discussion, TylerLeonhardt explains that the GitHub consumer must listen for authentication session changes; lszomoru acknowledges that diagnosis.
- **Current source retains authentication:** extensions/github/src/auth.ts:getOctokit caches a Promise<Octokit> in module-level _octokit, with the client's token taken from the initial session. Successful clients are not invalidated on authentication.onDidChangeSessions. OctokitService listens to that event but clears only its separate GraphQL client, not the REST client used by cloning.
- **Clone provider uses retained client and results:** extensions/github/src/extension.ts registers GithubRemoteSourceProvider with the built-in Git remote-source API. In extensions/github/src/remoteSourceProvider.ts, getRemoteSources obtains the cached REST client; getUserRemoteSources uses it to fetch authenticated repositories when the query is empty and returns userReposCache for nonempty queries. The provider has no authentication-session change listener. This establishes the stale-account path from source without executing VS Code.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/308927 is OPEN with mergedAt null and body containing Fixes #164868. Its proposed changes cover extensions/github/src/auth.ts, extensions/github/src/remoteSourceProvider.ts, and extensions/github/src/extension.ts, targeting REST-client and repository-cache invalidation on session changes. It is not a landed fix.
