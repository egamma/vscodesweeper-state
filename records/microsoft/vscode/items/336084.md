# Issue #336084 — Support copying files from Explorer to system clipboard for pasting outside VS Code

[https://github.com/microsoft/vscode/issues/336084](https://github.com/microsoft/vscode/issues/336084)

## Summary

Real, well-described gap: VS Code's file copy in Explorer only writes an internal VS Code resource-list MIME type to the clipboard, not a native OS file-clipboard payload, so pasting into the OS file manager doesn't work. No maintainer decision or fix exists yet, and an older, broader tracking issue may already cover this, so this stays open for triage/routing rather than a close.

## Change summary

Copying a file in the Explorer only lets you paste it into another VS Code window, not into the OS file manager or other native apps.

## Best solution

Route to the file-explorer/workbench area; if implemented, it needs an Electron main-process change to write real OS clipboard file-drop formats (e.g. Windows CF_HDROP, macOS NSFilenamesPboardType, Linux text/uri-list) alongside the existing internal vscodeResourcesMime writing in BrowserClipboardService.writeResources. Worth checking first whether microsoft/vscode#164 (broader 'clipboard/drag-and-drop integration of files across applications') already tracks this exact request before duplicating effort.
