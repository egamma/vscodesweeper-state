# Issue #309502 — RunInTerminalTool` ignores `automationProfile` and incorrectly merges terminal settings on Windows

[https://github.com/microsoft/vscode/issues/309502](https://github.com/microsoft/vscode/issues/309502)

## Summary

The Windows launch failure remains in current source, but the older, open canonical issue reports exactly the same PowerShell invocation with inherited CMD arguments. Consolidate that defect there; chat-specific profile settings already provide independent shell configuration on Windows and Linux.

## Change summary

Copilot substitutes PowerShell for CMD while retaining CMD-specific launch arguments, and reporters expect automation profiles to control agent terminals.

## Best solution

Resolve the shell-and-argument mismatch under https://github.com/microsoft/vscode/issues/279327, preserving this report's initialization-script trace and failure-loop observations. Keep independent agent shell selection available through chat.tools.terminal.terminalProfile.windows and chat.tools.terminal.terminalProfile.linux rather than requiring users to change their interactive default.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/279327 is currently open and was created on 2025-11-25, before this report. Its body explicitly describes CMD default-profile arguments such as /k being passed to Windows PowerShell, causing immediate exit code 1—the same reporter-observable symptom, satisfying the stronger duplicate bar for this re-reviewed item.
- **Current source confirms the defect:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts:3498-3519, TerminalProfileFetcher.getCopilotProfile(), resolves the default profile and spreads it into the CMD fallback while replacing only path and profileName. This retains args ['/k', ...] and the CMD icon. ToolTerminalCreator._createCopilotTerminal() in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/toolTerminalCreator.ts:193-214 copies that profile's path and args into the terminal launch configuration.
- **Automation-profile expectation and existing capability:** getCopilotProfile() checks chat.tools.terminal.terminalProfile.<platform> first and otherwise calls getDefaultProfile() without allowAutomationShell. src/vs/workbench/contrib/terminal/browser/terminalProfileResolverService.ts:190-214 consults automationProfile only when that option is enabled. The chat profile settings are registered in src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalChatAgentToolsConfiguration.ts and accept an executable path plus profile properties, allowing a separate PowerShell or bash profile without changing the interactive default.
- **Established distinction from automation profiles:** https://github.com/microsoft/vscode/issues/277371 documents the separate chat.tools.terminal.terminalProfile.windows setting; the reporter confirmed it worked at https://github.com/microsoft/vscode/issues/277371#issuecomment-3532232539, and a terminal maintainer linked an explanatory FAQ at https://github.com/microsoft/vscode/issues/277371#issuecomment-3532491595. This addresses profile selection, not the still-broken fallback argument inheritance.
- **Additional evidence to preserve:** https://github.com/microsoft/vscode/issues/309502#issuecomment-4354017635 independently confirms the Windows /k launch failure and repeated agent retries. https://github.com/microsoft/vscode/issues/309502#issuecomment-5051537705 reports Linux fish being selected instead of automationProfile.linux; that selection follows the separate chat-profile configuration path and does not demonstrate a distinct argument-inheritance defect.
