# Issue #309502 — RunInTerminalTool` ignores `automationProfile` and incorrectly merges terminal settings on Windows

[https://github.com/microsoft/vscode/issues/309502](https://github.com/microsoft/vscode/issues/309502)

## Summary

Current source still substitutes PowerShell for CMD while retaining CMD arguments, and bypasses automation-profile resolution. Keep this open: the older matching Windows report covers the argument mismatch, but not this report's additional cross-platform automation-profile behavior.

## Change summary

Agent terminal creation ignores automation profiles and can launch PowerShell with arguments inherited from the default CMD profile.

## Best solution

Ensure agent terminals use arguments compatible with the selected executable, without requiring users to change their interactive default profile. Settle and document whether automation profiles participate in agent profile selection when no chat-specific profile is configured.

  > With CMD configured as the interactive default and carrying CMD-specific arguments, an agent terminal must not pass those arguments to PowerShell or fail before executing its command. Users must be able to configure an agent shell without changing their preferred interactive shell. Existing explicit chat terminal profiles must remain effective. Acceptance must cover the Windows argument mismatch and the agreed behavior when an automation profile is configured without a chat-specific profile.
- **Trace:**

  > TerminalProfileFetcher.getCopilotProfile in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts first returns a configured chat.tools.terminal.terminalProfile.<os>; otherwise it resolves the interactive default without allowAutomationShell. Its CMD fallback spreads the entire default profile and replaces the executable with PowerShell, retaining CMD arguments. ToolTerminalCreator._createCopilotTerminal in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/toolTerminalCreator.ts then copies that executable and those arguments directly into the launch configuration. This conclusively establishes the reported Windows mismatch without executing code, and the resolver's flag gate explains automation-profile bypass on Linux as well. The existing TerminalProfileFetcher test suite covers explicit custom profiles and a default Linux shell, but not the reported mismatch. Preserve ordinary interactive-terminal behavior and existing explicit chat-profile selection; agent-host SDK shell behavior is a separate path. https://github.com/microsoft/vscode/issues/279327 tracks the Windows subset, while https://github.com/microsoft/vscode/issues/334029 concerns the distinct SDK shell. The unresolved product contract is whether automation profiles should become the fallback for chat terminals rather than the interactive default.
- **Open decisions:**

## Evidence

- **Confirmed Windows failure path:** In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts:3498-3520, TerminalProfileFetcher.getCopilotProfile spreads defaultProfile and replaces only path and profileName when the executable is cmd.exe. Thus the reporter's ['/k', 'init.cmd'] arguments survive the substitution to powershell.exe.
- **Launch configuration preserves incompatible arguments:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/toolTerminalCreator.ts, ToolTerminalCreator._createCopilotTerminal, copies shellOrProfile.path into config.executable and shellOrProfile.args into config.args before calling createTerminal. This completes the source trace from the reported CMD configuration to the invalid PowerShell invocation.
- **Automation profile bypass:** TerminalProfileFetcher.getCopilotProfile calls getDefaultProfile with os and remoteAuthority, but without allowAutomationShell. In src/vs/workbench/contrib/terminal/browser/terminalProfileResolverService.ts:190-222, automation-profile selection requires that flag; _getUnresolvedAutomationShellProfile reads terminal.integrated.automationProfile.<os>. This also explains the Linux comment's selection of interactive fish instead of configured automation bash.
- **Existing targeted workaround:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalChatAgentToolsConfiguration.ts registers chat.tools.terminal.terminalProfile.windows, chat.tools.terminal.terminalProfile.linux, and chat.tools.terminal.terminalProfile.osx. TerminalProfileFetcher returns a valid chat-specific profile before consulting the default profile, allowing separate agent shell configuration; this does not repair the default fallback or honor existing automationProfile settings.
