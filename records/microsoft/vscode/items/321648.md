# Issue #321648 — Context window indicator shows higher fill immediately after compacting conversation than actual

[https://github.com/microsoft/vscode/issues/321648](https://github.com/microsoft/vscode/issues/321648)

## Summary

The stale context indicator remains source-reproducible on current main: the completed `/compact` request exposes the summarization model call's usage rather than the compacted conversation's resulting context size. A later independently reported reproduction was explicitly closed by a maintainer as a duplicate of this issue, so this canonical issue should remain open and be routed to Chat.

## Change summary

Update the context-window indicator immediately after conversation compaction so it reports the reduced context rather than the summarization request's larger token usage.

## Best solution

After successful foreground compaction, expose the resulting conversation-context usage to the indicator separately from the summarization call's usage and cost accounting. The indicator should decrease immediately, while ordinary requests and failed or no-op compactions retain their current behavior.
