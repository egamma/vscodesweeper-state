## Evidence

- **working-set save/apply:** src/vs/sessions/contrib/layout/browser/baseSessionLayoutController.ts lines ~296-323 save the outgoing session's working set on session change and apply the incoming session's working set via IEditorGroupsService.applyWorkingSet.
- **browser lifecycle veto:** src/vs/sessions/contrib/browserView/browser/sessionBrowserView.ts vetoes dispose of a BrowserEditorInput when the active session differs from its owning session, specifically to keep it alive across a session swap so it can be restored.
- **single-pane divergence:** src/vs/sessions/contrib/layout/browser/singlePane/singlePaneSidePaneVisibilityStrategy.ts tracks only two shared visibility profiles (new-session vs existing-session), not one per individual session — a plausible source of 'state lost' if the reporter is using the single-pane Agents window layout rather than the classic desktop workbench.
