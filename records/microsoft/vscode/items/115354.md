# Issue #115354 — No way to ensure an extension is prioritized as a rename provider in a language

[https://github.com/microsoft/vscode/issues/115354](https://github.com/microsoft/vscode/issues/115354)

## Summary

Still an open gap: there is no finalized extension API to control rename provider priority. The proposed `documentFiltersExclusive` API exists but has never been finalized, and issue #183075 was closed as a duplicate of this one. The 33 upvotes and cross-references from Angular, C#, PHP, and other extension ecosystems confirm ongoing demand.

## Change summary

Extensions need a way to ensure their rename provider takes priority over other providers (e.g. built-in TypeScript) for the same language.

## Best solution

Finalize the proposed `documentFiltersExclusive` API (src/vscode-dts/vscode.proposed.documentFiltersExclusive.d.ts) which already has the internal plumbing in languageFeatureRegistry.ts, or design a user-facing setting/picker for provider priority. This would let extensions like Angular Language Service reliably win rename resolution over the built-in TS/JS extension.
