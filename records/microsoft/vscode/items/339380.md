# Issue #339380 — Agents window: message sent while a tool call is running is not shown in chat (handled as steering, aborts the tool call)

[https://github.com/microsoft/vscode/issues/339380](https://github.com/microsoft/vscode/issues/339380)

## Summary

Thanks for the detailed logs — this is a real, well-documented gap in the Agents window's Claude steering UX, not something I can verify as already fixed on main. Design docs in-repo (platform/agentHost/node/claude/CONTEXT.md, section M10) confirm steering ('now'-priority) is intentionally designed to abort the in-flight turn and fold the message into the current Turn rather than starting a new one, matching the reporter's 'tool call aborted' observation. But that same doc also describes a pending-message pill that should appear while steering is in flight and clear on ack — the reporter's renderer log shows zero trace of that happening, which looks like either a rendering bug or a UX gap nobody has explicitly signed off on. Needs a maintainer/UI-owner look before any close.

## Change summary

In the Agents window, a message sent to a Claude agent session while a tool call is running is treated as a steering message: the running tool call aborts and the agent replies, but the user's message never appears in the chat UI as a visible turn or pending indicator.

## Best solution

A maintainer familiar with the Agents window chat rendering (agentHostSessionHandler.ts's pending-message sync/projection path) should confirm whether the steering pending-message pill is supposed to render here and, if so, why it isn't — or decide the UX should make steering-induced aborts more visible to the user even though the protocol intentionally keeps steering out of the Turn list.
