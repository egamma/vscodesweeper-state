# Issue #212679 — Context menus make webview on the side steal focus

[https://github.com/microsoft/vscode/issues/212679](https://github.com/microsoft/vscode/issues/212679)

## Summary

Still present on main: no fix commit references this issue, and the webview focus-tracking code path that causes the problem is unchanged. The bug has strong community signal (30 upvotes) and affects any workflow using a side-by-side webview panel.

## Change summary

Opening a context menu anywhere in VS Code (editor, sidebar, title bar) causes a webview panel in a side group to steal focus, shifting the active editor group and misplacing subsequently opened files.

## Best solution

The root cause is likely in the interaction between the webview iframe's focus-polling mechanism (`trackFocus` in `src/vs/workbench/contrib/webview/browser/pre/index.html`, which polls `document.hasFocus()` every 250ms) and how the editor group reacts to `onDidFocus` from the webview editor pane (`src/vs/workbench/contrib/webviewPanel/browser/webviewEditor.ts`). When a context menu opens, the browser may briefly focus the webview iframe (e.g. during overlay repositioning), triggering a spurious `did-focus` message that activates the webview's editor group. The fix should suppress focus-change events during context menu interactions or gate the group activation on whether the focus change was user-initiated.
