## Summary

The requested API remains absent on current main, and this team-authored feature request has an unresolved design discussion about separating cell language from execution target. Keep it open under discussion.

## Change summary

Allow notebook controllers to expose multiple runtime-specific choices with custom display names while retaining their underlying language identifiers.

## Best solution

Define a notebook API that lets extensions offer a combined language-and-runtime selection without treating execution targets as distinct language modes, likely building on notebook cell status-bar items or a dedicated extensible picker.
