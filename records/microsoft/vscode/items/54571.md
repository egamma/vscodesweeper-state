# Issue #54571 — Enhancement: finer control of word separators

[https://github.com/microsoft/vscode/issues/54571](https://github.com/microsoft/vscode/issues/54571)

## Summary

A real capability gap remains: current word separators are symmetric single-character classifications and cannot include a separator only on one side. Keep this open for design discussion rather than consolidating it with related requests that require different boundary semantics.

## Change summary

Allow word-selection separators to create a boundary before or after a character independently.

## Best solution

Design a backward-compatible extension to `editor.wordSeparators` or a language-aware boundary mechanism that can select constructs such as `\cmd` independently, then implement it in the editor word-classification and cursor-word-operation paths.
