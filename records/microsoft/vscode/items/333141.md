# Issue #333141 — The new native "Agents Window" (`Ctrl+Shift+A`) does not respect the workspace or file encoding configured in VS Code settings (e.g., Windows-1252, ISO-8859-1). This is a regression in experience compared to the standard GitHub Copilot chat extension, which respects file encoding perfectly.

[https://github.com/microsoft/vscode/issues/333141](https://github.com/microsoft/vscode/issues/333141)

## Summary

Traced this in current main: the Agents Window's resource read/write path always assumes UTF-8, with no reference to the workspace's `files.encoding`/BOM-detection settings, so a real gap exists for non-UTF-8 workspaces.

## Change summary

The Agents Window ignores the configured file encoding (e.g. windows-1252, ISO-8859-1) when the agent reads or edits a file, garbling special characters and potentially corrupting the file on write.

## Best solution

Route to the Agent Host / Agents Window area: `AgentService.resourceRead`/`resourceWrite` in src/vs/platform/agentHost/node/agentService.ts need to resolve and apply the file's/workspace's configured encoding (mirroring how `ITextFileService`/`IWorkingCopyFileService` do BOM/`files.encoding` detection for normal editors) instead of unconditionally decoding/encoding as UTF-8.

- **resourceWrite always UTF-8:** src/vs/platform/agentHost/node/agentService.ts:6145-6170 — non-base64 writes do `VSBuffer.fromString(params.data)`, which encodes as UTF-8 regardless of the target file's configured/detected encoding.
