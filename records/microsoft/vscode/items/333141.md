# Issue #333141 — The new native "Agents Window" (`Ctrl+Shift+A`) does not respect the workspace or file encoding configured in VS Code settings (e.g., Windows-1252, ISO-8859-1). This is a regression in experience compared to the standard GitHub Copilot chat extension, which respects file encoding perfectly.

[https://github.com/microsoft/vscode/issues/333141](https://github.com/microsoft/vscode/issues/333141)

## Summary

Confirmed in source: the Agents Window's resource service reads and writes files through the raw `IFileService` (bytes as-is) instead of the encoding-aware `ITextFileService`, so any file whose configured `files.encoding` isn't UTF-8 gets misread by the agent and re-saved as UTF-8, corrupting non-ASCII characters — exactly the regression described.

## Change summary

Files opened/edited by the new Agents Window ignore the workspace/file `files.encoding` setting, unlike the extension-based Copilot Chat which respects it.

## Best solution

In `src/vs/workbench/services/agentHost/common/agentHostResourceService.ts`, have `read()`/`write()` (and `create`-path in `write()`) go through `ITextFileService.read`/`.write`/`.create` (or at least resolve the resource's configured encoding via the same oracle textfiles uses) for text resources instead of calling `IFileService.readFile`/`writeFile`/`createFile` directly with raw bytes, so the Agents Window round-trips text the same way the editor and Copilot Chat extension do.
