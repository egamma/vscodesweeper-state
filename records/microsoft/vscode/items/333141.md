# Issue #333141 — The new native "Agents Window" (`Ctrl+Shift+A`) does not respect the workspace or file encoding configured in VS Code settings (e.g., Windows-1252, ISO-8859-1). This is a regression in experience compared to the standard GitHub Copilot chat extension, which respects file encoding perfectly.

[https://github.com/microsoft/vscode/issues/333141](https://github.com/microsoft/vscode/issues/333141)

## Summary

The defect remains on current main: Agent Host text resource operations assume UTF-8 and receive no resource-scoped `files.encoding` value, so Windows-1252 or ISO-8859-1 content can be decoded incorrectly and overwritten with different bytes.

## Change summary

Make Agents Window file analysis and edits honor VS Code's configured workspace- or resource-specific file encoding.

## Best solution

Carry the effective resource encoding across the VS Code-to-Agent Host boundary and use it for text reads and full-file edits while preserving the existing byte-oriented base64 path. The design must cover local and remote sessions without leaking one workspace's encoding into another.

- **Behavior:**

  > When a workspace, language, or individual resource resolves `files.encoding` to Windows-1252, ISO-8859-1, or another supported encoding, an Agents Window session reads its text correctly. Agent edits preserve that effective encoding instead of rewriting the file as UTF-8 or introducing replacement characters. UTF-8 files and byte-oriented base64 resource operations remain unchanged. The behavior must apply to both local and remote Agent Host sessions.
- **Trace:**

  > Current Agent Host resource reads in src/vs/platform/agentHost/node/agentService.ts decode raw bytes with VSBuffer.toString(), and text writes encode strings with VSBuffer.fromString(); both are UTF-8-only. ContentEncoding in src/vs/platform/agentHost/common/state/protocol/common/commands.ts distinguishes only UTF-8 text from base64 bytes. The renderer-side synchronization in src/vs/platform/agentHost/browser/agentHostProtocolClient.ts and src/vs/platform/agentHost/common/agentHostConfigurationSync.ts deliberately excludes workspace/folder configuration because host root state is shared across windows, so `files.encoding` cannot safely be added as an ordinary global mirror. Planning must trace every local and remote agent file-tool path and establish a resource-scoped encoding handoff; do not weaken binary/base64 fidelity or allow one workspace's setting to affect another.
