# Issue #325956 — Linux/X11: restored window height is clamped to 1080 on a 4K display in a mixed-resolution layout

[https://github.com/microsoft/vscode/issues/325956](https://github.com/microsoft/vscode/issues/325956)

## Summary

Confirmed in source: CodeWindow.applyState() only reapplies setBounds() after construction for isMacintosh || isWindows (windowImpl.ts line 280), so on Linux/X11 the multi-monitor bounds-correction workaround from #74872/#146499 never runs, matching the reporter's exact symptom and trace evidence; a second commenter independently reproduced the same class of restore failure on Linux/X11 with mixed-resolution displays.

## Change summary

On Linux/X11 with a mixed-resolution multi-monitor layout, restored non-maximized window height is clamped to the smaller display's height (1080) instead of the saved tall height.

## Best solution

Extend the existing post-construction setBounds() workaround in CodeWindow.applyState() (src/vs/platform/windows/electron-main/windowImpl.ts, ~line 280) to include isLinux, mirroring the isMacintosh/isWindows path; route to the windows/electron-main area owner to confirm scope (X11-only vs Wayland too) before landing.
