# Issue #330991 — HTML language service does not report unmatched or invalid closing tags

[https://github.com/microsoft/vscode/issues/330991](https://github.com/microsoft/vscode/issues/330991)

## Summary

Confirmed on main: the built-in HTML language mode has no `doValidation` implementation (unlike the embedded CSS/JS modes), so structural HTML errors like unmatched closing tags or attributes on closing tags never surface in the Problems panel — this is a genuine missing capability, not a regression.

## Change summary

Requests basic structural HTML diagnostics (unmatched/mismatched closing tags, attributes on closing tags, invalid attribute values) in the Problems panel.

## Best solution

Add a lightweight structural validation pass to the HTML language service (vscode-html-languageservice, consumed via extensions/html-language-features/server/src/modes/htmlMode.ts) that reports unmatched/mismatched closing tags and disallows attributes on end tags; route to the HTML area owners to decide scope and false-positive risk (e.g. void elements, custom/web components, embedded template syntax).
