# Issue #343010 — Support `/btw` side chats in the Chat view, not just the Agents window

[https://github.com/microsoft/vscode/issues/343010](https://github.com/microsoft/vscode/issues/343010)

## Summary

Keep open as a feature request: current source still restricts side-chat creation and `/btw` registration to the Agents window. Existing workbench actions provide integration points, not the requested Chat view capability, and no verified canonical absorbs the full request.

## Change summary

Extend context-preserving, non-interrupting side chats to the regular editor window's Chat view, including `/btw` and response-selection entry points.

## Best solution

Provide native workbench side chats through the existing IChatSideChatService contract, with slash-command and selection support that leaves the running request and main transcript unchanged. Preserve the Agents window implementation and keep workbench code independent of the sessions layer.

## Evidence

- **Current capability boundary:** src/vs/sessions/contrib/chat/browser/btwSlashCommand.contribution.ts returns before registering `/btw` when environmentService.isSessionsWindow is false; its command also requires IsSessionsWindowContext. This confirms a missing capability in regular editor windows rather than a broken promised command.
- **Provider coverage:** A source search for IChatSideChatProvider and sideChatService.registerProvider found only one production provider: SessionsSideChatProviderContribution in src/vs/sessions/contrib/chat/browser/sideChatProvider.contribution.ts. Its constructor registers only in the Agents window. src/vs/workbench/contrib/chat/common/chatSideChatService.ts explicitly anticipates a future native workbench provider.
- **Existing affordance is insufficient:** src/vs/workbench/contrib/chat/browser/widget/input/chatQueuePickerActionItem.ts offers Ask in Side Chat only when IChatSideChatService.canAskInSideChat returns true. With no regular-workbench provider, the existing menu integration does not deliver the requested behavior.
- **Alternatives do not cover the request:** The `/fork` registration in src/vs/workbench/contrib/chat/browser/chatSlashCommands.ts creates a separate conversation and does not set executeDuringRequest. The Send to New Chat path in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts cancels the current request. Neither satisfies a concurrent side question isolated from the main transcript.
- **Related reports and canonical search:** https://github.com/microsoft/vscode/issues/336511 was verified open, but its body only requests missing `/btw` and `/goal` commands without identifying the window or side-chat semantics; it is not a verified canonical for this full request. Public searches for open `/btw` reports and Chat-view side-chat titles did not establish another canonical. The supplied context also identifies https://github.com/microsoft/vscode/issues/329496 as a closed report explaining the present Agents-only boundary, not an open duplicate target.
- **Related implementation is not this capability:** The open https://github.com/microsoft/vscode/pull/330955 describes transient presentation of existing Agents-window side chats, including Sessions navigation and a chat.agentSessions setting. That description does not establish implementation of native side chats in the regular Chat view.
