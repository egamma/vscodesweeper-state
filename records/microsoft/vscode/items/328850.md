# Issue #328850 — Ctrl+tab is horrendously slow in the new update

[https://github.com/microsoft/vscode/issues/328850](https://github.com/microsoft/vscode/issues/328850)

## Summary

Fresh, plausible regression report tied to the workbench modernization work: the quick-input widget (used by Ctrl+Tab's editor picker) now plays a 250ms open / 150ms close fade-and-scale animation by default, which matches the reporter's described perceived slowdown; already correctly labeled workbench-tabs/modernization/performance, so keep it open for the modernization team to judge the tradeoff.

## Change summary

Ctrl+Tab (quick open editor picker) feels noticeably slower to complete since the new UI overhaul, reporter suspects the new fade animation.

## Best solution

Have the modernization/workbench team decide whether the quick-input open/close animation should be shortened, skipped for keyboard-driven pickers like Ctrl+Tab, or gated more conservatively — reproduction path is in src/vs/platform/quickinput/browser/media/quickInput.css (250ms open / 150ms close keyframes) and the close-animation timer in src/vs/platform/quickinput/browser/quickInputController.ts (QUICK_INPUT_CLOSE_ANIMATION_DURATION = 150ms).
