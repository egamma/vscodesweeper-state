# Issue #328850 — Ctrl+tab is horrendously slow in the new update

[https://github.com/microsoft/vscode/issues/328850](https://github.com/microsoft/vscode/issues/328850)

## Summary

Keep open to investigate the reported Modern UI Ctrl+Tab latency regression. Current source still animates the picker, but does not wait for the closing animation before opening the selected editor; the supplied steps and classic-UI comparison suffice to retest without requesting more basic information.

## Change summary

Ctrl+Tab editor switching reportedly became noticeably slower with Modern UI enabled, even with extensions disabled.

## Best solution

Preserve responsive Ctrl+Tab switching with Modern UI enabled, identifying whether the delay comes from picker presentation, rendering overhead, or editor activation before choosing a fix. Disabling motion is a useful diagnostic comparison, not a substitute for resolving the regression.
