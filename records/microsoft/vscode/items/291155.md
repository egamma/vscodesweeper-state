## Summary

Valid bug filed by a team member while testing PR #290739. The gitignore tree handling in the explorer has no fix on current main referencing this issue — the nested ignore-file update logic remains unchanged since filing.

## Change summary

Editing a root .gitignore to remove an entry fails to unhide files in nested folders and can leave the explorer in a broken state on Linux.

## Best solution

Fix the ignore-tree invalidation logic in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` so that when a .gitignore file is modified (entries removed or empty lines introduced), the explorer correctly recomputes visibility for files in nested subdirectories.
