# Issue #335451 — Assisted permissions: compound command containing a local script path always requires explicit approval (1.137.0 regression)

[https://github.com/microsoft/vscode/issues/335451](https://github.com/microsoft/vscode/issues/335451)

## Summary

Well-documented regression: VS Code's copilotSessionLauncher deliberately turns on the runtime's `enableScriptSafety` flag (per the referenced #333249 fix), and the reporter shows the runtime's own shell-script classifier then non-deterministically refuses to classify compound commands that reference a local script path, forcing manual approval. The actual classifier lives in the external `@github/copilot-sdk` runtime (not vendored in this checkout), so this needs the agent-host/Copilot team to look at the runtime side rather than a vscode source fix.

## Change summary

Since 1.137.0, assisted permissions always require explicit approval for a compound shell command (e.g. `./x; echo done`) when one part invokes a local script path, even though the same command runs unattended on 1.136.2 and the non-compound form is still auto-approved.

## Best solution

Route to the agent-host/Copilot team: the fix belongs in the runtime's script-safety classifier (in `@github/copilot-sdk`, invoked via `session.rpc.options.update({ enableScriptSafety: true })` in src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts) so that an unclassifiable compound command falls through to the LLM judge instead of forcing a manual prompt; alternatively confirm this is expected fail-closed behavior of the new safety gate and needs a docs/UX note.
