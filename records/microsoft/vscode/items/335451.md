# Issue #335451 — Assisted permissions: compound command containing a local script path always requires explicit approval (1.137.0 regression)

[https://github.com/microsoft/vscode/issues/335451](https://github.com/microsoft/vscode/issues/335451)

## Summary

Detailed, credible regression report for Assisted permissions in 1.137.0: compound shell commands naming a local script path are now declined outright instead of being handed to the LLM judge. The code that flips this on (`_applyScriptSafety` unconditionally sending `enableScriptSafety: true`) is confirmed in this repo, but the actual classifier decision logic lives inside the external `@github/copilot-sdk` dependency, so the underlying defect can't be traced or fixed from this checkout.

## Change summary

Since 1.137.0, Assisted permissions now requires explicit manual approval for any compound shell command (e.g. `./x; echo done`) that references a local script path, where the same command worked automatically on 1.136.2.

## Best solution

The script-safety classifier in @github/copilot-sdk needs to return an 'unclassifiable' signal (rather than a hard decline) for compound commands with a path-named subcommand, so Assisted permissions can fall through to the LLM judge as originally intended; this is likely an SDK-side fix, with `_applyScriptSafety` in src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts as the VS Code-side toggle point to revisit once the SDK behavior is understood.
