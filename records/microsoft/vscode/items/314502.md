# Issue #314502 — UI Pass: Search/filter within a context menu

[https://github.com/microsoft/vscode/issues/314502](https://github.com/microsoft/vscode/issues/314502)

## Summary

Keep this as the existing tracking issue for context-menu search: current custom menus do not provide text filtering, and a maintainer explicitly consolidated a newer request here. The remaining work needs a UX decision about search scope and activation.

## Change summary

Allow users to search or filter the commands available within an open context menu.

## Best solution

Define a consistent, keyboard-accessible context-menu search experience, then implement it through the shared menu infrastructure while preserving command context and existing navigation. Decide whether searching includes submenu commands and how the experience applies to native menus.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/menu/menu.ts`, `src/vs/platform/contextview/browser/contextMenuHandler.ts`, `src/vs/platform/contextview/browser/contextMenuService.ts`, `src/vs/base/test/browser/ui/menu/menu.test.ts`
- **Validation:** After the interaction contract is agreed, extend the menu browser tests to cover query matching, clearing, no matches, keyboard navigation and invoking a matching action with its original context. Manually exercise a long context menu, submenus, Escape/focus restoration and screen-reader navigation under the agreed native/custom-menu scope.
- **Behavior:**

  > Users should be able to find commands within the context menu they opened without switching to the global Command Palette. Search must retain the original invocation context and preserve action enablement. Acceptance should cover narrowing results, clearing the query, no matches, keyboard operation and running the intended command. The activation gesture, submenu coverage and native-menu behavior remain to be agreed.
- **Trace:**

  > Menu in src/vs/base/browser/ui/menu/menu.ts renders an action list and supports mnemonics, scrolling and navigation, but exposes no query-based filtering in IMenuOptions. ContextMenuMenuDelegate.transform in src/vs/platform/contextview/browser/contextMenuService.ts resolves context-specific actions, and ContextMenuHandler in src/vs/platform/contextview/browser/contextMenuHandler.ts constructs Menu with the action context. Preserve those context and execution semantics, including enabled states and focus restoration. window.menuStyle in src/vs/workbench/electron-browser/desktop.contribution.ts distinguishes custom and native presentation without providing search. The newer request at https://github.com/microsoft/vscode/issues/318213 was explicitly consolidated here by a maintainer. The public record establishes the goal but not the interaction contract; the issue body's Slack link was not inspected.
- **Open decisions:**
  - Should search be visible whenever a context menu opens, or revealed through an explicit keyboard or UI gesture?
  - Should a query match only the current menu level, or also surface commands nested inside submenus?
  - Is the initial capability limited to custom menus, and what should users selecting native menus experience?
