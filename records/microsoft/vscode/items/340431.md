# Issue #340431 — Agent host (Copilot): workspaceless chats drop the workspaceless instructions on resume, breaking the prompt cache between turns

[https://github.com/microsoft/vscode/issues/340431](https://github.com/microsoft/vscode/issues/340431)

## Summary

Confirmed from source: on resume, CopilotAgent reads `agentHost.workspaceless` from its own per-SDK-session database, but that key is only ever written into the Agent Host session's separate database — the provider-owned DB never gets it, so `storedMetadata.workspaceless` is always false and the resumed launch plan drops the workspaceless instructions block, exactly as the reporter diagnosed. New, well-diagnosed bug report from a collaborator; stays open for a fix.

## Change summary

Resuming a workspace-less Copilot chat silently drops the `<workspaceless_chat>` system-prompt block it had on turn 1, breaking the prompt cache between turns and losing scratch-directory guidance.

## Best solution

Fix `CopilotAgent._doResumeSession` so the resumed launch plan's `workspaceless` flag reflects the Agent Host session's authoritative determination (e.g. thread it through the resume-time host seam, mirroring how `origin`/`customizations` are already passed, or have the host also persist the key into the Copilot provider's own session database) instead of re-deriving it from a database that never held the key.
