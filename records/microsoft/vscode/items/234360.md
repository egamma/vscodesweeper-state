# Issue #234360 — Ability to Set Different Zoom Levels for Each Editor Group

[https://github.com/microsoft/vscode/issues/234360](https://github.com/microsoft/vscode/issues/234360)

## Summary

Independent zoom for split editor groups remains missing; existing per-window zoom and language-specific font settings only partially cover the request. Keep this accepted Backlog item open: it has 39 upvotes and team-member support, and the matching newer report cannot replace it as the canonical.

## Change summary

Allow users to adjust zoom independently for editor groups, with optional persistence.

## Best solution

Provide independently adjustable editor-group zoom without changing other groups or the surrounding workbench. First settle whether this means text-only zoom or broader scaling of editor content, including diagrams, and define its lifetime and persistence.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/fontZoom/browser/fontZoom.ts`, `src/vs/editor/common/config/editorZoom.ts`, `src/vs/editor/browser/config/editorConfiguration.ts`, `src/vs/editor/common/config/fontInfo.ts`, `src/vs/editor/browser/controller/mouseHandler.ts`
- **Validation:** In a development build, open the same text file in two editor groups, adjust the selected group's zoom, and verify only that group changes while the other group and workbench remain unchanged. Switch focus and repeat, then exercise reset, tab switching, and reload according to the chosen state lifetime. If non-text editors are included, repeat with a diagram or preview editor.
- **Behavior:**

  > Users should be able to adjust the zoom of one editor group without changing another group or the surrounding workbench. Independent levels must work even when both groups display the same file or language. Acceptance should cover adjusting each group, resetting a group, and preserving the agreed behavior when switching tabs or reloading. Whether scaling includes non-text editors and whether levels persist remain product decisions.
- **Trace:**

  > EditorFontZoomIn, EditorFontZoomOut, and EditorFontZoomReset in src/vs/editor/contrib/fontZoom/browser/fontZoom.ts all update the shared EditorZoom singleton in src/vs/editor/common/config/editorZoom.ts rather than using their ICodeEditor argument to scope the result. EditorConfiguration subscribes to the shared event in src/vs/editor/browser/config/editorConfiguration.ts, and BareFontInfo._create consumes its multiplier in src/vs/editor/common/config/fontInfo.ts. Mouse-wheel zoom in src/vs/editor/browser/controller/mouseHandler.ts also updates this singleton. Separately, window.zoomPerWindow already supports active-window workbench zoom, so that existing capability must remain intact. Language-specific editor.fontSize is a partial workaround, not group-local state. The trace establishes the text-editor limitation; it does not establish a scaling mechanism for diagram or other non-text editors. https://github.com/microsoft/vscode/issues/339486 is a newer matching request, while https://github.com/microsoft/vscode/issues/80820 concerns persistence of existing shared editor font zoom.
- **Open decisions:**
  - Should independent group zoom affect text-editor font metrics only, or also scale non-text editor content such as diagrams and previews?
  - Should the zoom level belong to the editor group across tab changes, or follow individual tabs when they move between groups?
  - Should independent zoom levels last only for the session, or persist across reloads and workspace restoration?

## Evidence

- **Existing per-window capability:** src/vs/workbench/electron-browser/desktop.contribution.ts registers window.zoomPerWindow with default true. BaseZoomAction.setZoomLevel in src/vs/workbench/electron-browser/actions/windowActions.ts targets ACTIVE_WINDOW rather than ALL_WINDOWS when enabled; this covers independent window zoom, not separate groups inside one window.
- **Editor zoom remains shared:** src/vs/editor/contrib/fontZoom/browser/fontZoom.ts implements editor.action.fontZoomIn, editor.action.fontZoomOut, and editor.action.fontZoomReset by updating the shared EditorZoom singleton in src/vs/editor/common/config/editorZoom.ts. EditorConfiguration in src/vs/editor/browser/config/editorConfiguration.ts subscribes to its changes, and BareFontInfo._create in src/vs/editor/common/config/fontInfo.ts applies the shared multiplier. These commands do not isolate zoom to the focused editor group.
- **Partial font-size workaround:** src/vs/editor/common/config/editorOptions.ts registers editor.fontSize, and src/vs/editor/common/config/editorConfigurationSchema.ts makes editor settings language-overridable. Different language font sizes can help the Python/HTML example, but do not provide independently adjustable group zoom, including two groups displaying the same language or file.
