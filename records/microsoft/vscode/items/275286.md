# Issue #275286 — Provide way to go from terminal chat back to chat

[https://github.com/microsoft/vscode/issues/275286](https://github.com/microsoft/vscode/issues/275286)

## Summary

The navigation gap remains: hidden-terminal selection displays the associated chat title but only reveals the terminal, and agent-owned terminal tabs have no corresponding-chat action. Keep this accepted Backlog request open; the discussion provides a useful starting point for a maintainer-led design.

## Change summary

Provide navigation from an agent-owned terminal to its associated chat, both in the hidden-terminal picker and after revealing the terminal in the tabs list.

## Best solution

Provide a discoverable, keyboard-accessible action that opens the specific associated chat without creating a new conversation or changing terminal visibility. Reuse the existing session association and generic terminal action infrastructure, with consistent behavior across the picker and terminal tabs.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatActions.ts`, `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`, `src/vs/workbench/contrib/terminal/browser/terminal.ts`, `src/vs/workbench/contrib/terminalContrib/chat/test/browser/terminalChatActions.test.ts`
- **Validation:** Exercise two chats with distinct agent-owned terminals: from each hidden-terminal picker item and each revealed terminal tab, invoke the navigation action and verify that the corresponding existing conversation receives focus. Verify keyboard activation, a single hidden terminal, missing or deleted session associations, and unchanged reveal, split, and kill behavior. Add targeted action tests asserting that the selected terminal's session URI, not the last active chat, is opened.
- **Behavior:**

  > Users can identify and return to the conversation associated with an agent-owned terminal. Navigation is available from both the hidden-terminal picker and the revealed terminal tabs list, including keyboard access. Opening the chat must preserve its existing history and must not create a replacement conversation or dispose the terminal. Acceptance includes two simultaneous conversations so opening the wrong or last-active chat cannot pass unnoticed.
- **Trace:**

  > ShowChatTerminalsAction.run in src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatActions.ts already obtains the owning session URI for its title, but picker acceptance only reveals the terminal; one hidden terminal bypasses the picker entirely. TerminalChatService in src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatService.ts owns the association, registered by runInTerminalTool.ts. TerminalTabsList.fillActionBar in src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts supports generic shellLaunchConfig.tabActions but has no chat navigation contribution. IChatWidgetService.openSession in src/vs/workbench/contrib/chat/browser/chat.ts provides specific-session navigation. The existing View in Chat command concerns terminal inline chat, not the parent conversation of an agent-owned terminal. Preserve existing terminal reveal, selection, split, and kill behavior, and respect disabled-AI UI gating. The discussion at https://github.com/microsoft/vscode/issues/275286 favors a generic terminal integration; uncertainty remains around where navigation should reveal the conversation and what users see when its association is unavailable.
- **Open decisions:**
  - Should navigation reveal the conversation in its existing chat surface when available, or consistently open it in the Chat view?
  - When a terminal has no resolvable associated conversation, should the navigation action be hidden, disabled, or remain available with an explicit unavailable-session message?
