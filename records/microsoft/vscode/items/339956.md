# Issue #339956 — Same-named MCP servers in different workspace roots overwrite each other, so their enablement is shared

[https://github.com/microsoft/vscode/issues/339956](https://github.com/microsoft/vscode/issues/339956)

## Summary

Keep open: current source still collapses same-named workspace-folder servers, and the customizations list can associate both entries with the surviving runtime server. Folder-scoped enablement needs to remain distinct from intentional runtime name-collision handling.

## Change summary

Same-named MCP servers configured in separate workspace roots overwrite one another and share the runtime enablement shown by their customization entries.

## Best solution

Preserve configuration-source identity through MCP discovery and customization-row matching so disabling one folder's server does not attach that decision to another. Retain the documented collision policy for runtime activation rather than treating name-based precedence as shared user intent.
