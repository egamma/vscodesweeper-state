# Issue #38125 — [Extensions] Bind package.config's activation onLanguage to configuration

[https://github.com/microsoft/vscode/issues/38125](https://github.com/microsoft/vscode/issues/38125)

## Summary

A real extension API gap remains: activation events are still derived from static extension manifests, while the suggested eager-loading pattern is only a workaround. Keep this Backlog API request open for an explicit design decision.

## Change summary

Allow an extension's language activation events to follow user-configured language identifiers.

## Best solution

Provide a performant API or declarative mechanism for activating extensions against configurable document selectors without requiring `activationEvents: ["*"]`; otherwise formally document the lightweight eager-activation pattern as the supported design.
