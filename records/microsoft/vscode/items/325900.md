# Issue #325900 — Worktrees omit gitignored .claude folder, preventing CLAUDE settings/plugins from roaming

[https://github.com/microsoft/vscode/issues/325900](https://github.com/microsoft/vscode/issues/325900)

## Summary

Current VS Code already offers documented, opt-in copying and symlinking of ignored folders, but neither automatically carries .claude into worktrees created with the reported Git command. Keep this team-authored item open for an owner decision on whether the existing guidance suffices or automatic customization inheritance is wanted.

## Change summary

Make gitignored .claude customizations available across worktrees, or clearly document their isolation and supported sharing options.

## Best solution

Make the supported .claude worktree workflow explicit using the existing inclusion and symlink settings, including their copy-versus-shared-edit semantics and limitation to VS Code-created worktrees. Decide whether agent-created worktrees additionally need automatic inheritance; do not treat ordinary git worktree add as a broken VS Code operation.

- **Proposed comment:**

  > Thanks for the context. VS Code currently supports copying an ignored `.claude` folder with `"git.worktreeIncludeFiles": [".claude/**"]`, or sharing it with `"git.worktreeSymlinkFolders": [".claude"]`; edits through the symlink also affect the source checkout. These settings apply when VS Code creates the worktree, not when you run `git worktree add` directly.
  > 
  > The general behavior is documented at https://code.visualstudio.com/docs/sourcecontrol/branches-worktrees#_include-files-when-creating-a-worktree. Leaving this open to decide whether that opt-in workflow needs Claude-specific guidance or whether agent worktrees should inherit these customizations automatically.
