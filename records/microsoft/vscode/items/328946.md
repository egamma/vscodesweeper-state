# Issue #328946 — VS Code Cannot Open .code.workspace shortcuts

[https://github.com/microsoft/vscode/issues/328946](https://github.com/microsoft/vscode/issues/328946)

## Summary

Same root cause and maintainer decision as the closed precedent https://github.com/microsoft/vscode/issues/35085: Windows `.lnk` shortcut files are not real symlinks — Node.js (and thus VS Code) sees them as opaque binary files, not resolvable paths, so VS Code cannot transparently follow a `.lnk` to the `.code-workspace` it points to. That issue was closed `*out-of-scope` on exactly this reasoning for folder shortcuts; the same applies to workspace-file shortcuts.

## Change summary

Reporter launched VS Code via a Windows `.lnk` shortcut pointing at a `.code-workspace` file, and VS Code opened the `.lnk` file itself instead of resolving it and opening the workspace.

## Best solution

Close as `*out-of-scope`, same as the 2017 precedent: `.lnk` files are a Windows Explorer shell feature, not a filesystem-level symlink Node.js can resolve, so VS Code can't reliably follow them. Recommend the reporter use a native symlink/junction (`mklink`) or a `.bat`/`.cmd` launcher (`code path\to\file.code-workspace`) instead.
