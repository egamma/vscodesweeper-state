# Issue #328946 — VS Code Cannot Open .code.workspace shortcuts

[https://github.com/microsoft/vscode/issues/328946](https://github.com/microsoft/vscode/issues/328946)

## Summary

Consolidate this report with the older, open Windows shortcut-opening issue. Opening a shortcut to a workspace is a specific case of resolving the shortcut target before deciding what VS Code should open.

## Change summary

Resolve Windows .lnk shortcuts to workspace files instead of opening the shortcut itself as an editor file.

## Best solution

Track shortcut-target resolution in https://github.com/microsoft/vscode/issues/324353, preserving this report's requirement that a .code-workspace target opens as a workspace rather than as text.

- **Current opening path:** src/vs/platform/windows/electron-main/windowsMainService.ts:978-982 sends positional CLI paths to doResolveFilePath. At lines 1168-1214, that method normalizes and stats the supplied path, attempts workspace recognition using that same path, and otherwise returns it as fileUri; no Windows shell-shortcut resolution occurs on this path.
- **Workspace recognition boundary:** src/vs/platform/workspaces/electron-main/workspacesManagementMainService.ts:107-135 rejects paths that are neither untitled workspaces nor files with the workspace extension. An ordinary .lnk therefore cannot be recognized as its .code-workspace target.

Its later comment at https://github.com/microsoft/vscode/issues/89743#issuecomment-5822920554 explicitly distinguishes the unimplemented Open with Code case and links the open canonical.
