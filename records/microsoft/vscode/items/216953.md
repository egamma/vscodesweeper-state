# Issue #216953 — Fallback on "legacy" diff algorithm if "advanced" is too slow

[https://github.com/microsoft/vscode/issues/216953](https://github.com/microsoft/vscode/issues/216953)

## Summary

Keep open: multiple reporters confirm slow or unusable large-file comparisons, and current source still has no automatic legacy fallback. The related reports do not fully own this recovery behavior, and the linked experimental PR has not merged.

## Change summary

Recover a usable comparison with the legacy algorithm when the advanced algorithm exceeds its computation budget.

## Best solution

Provide bounded recovery from advanced-diff timeouts without requiring users to permanently abandon advanced diffing, while preserving cancellation and explicit algorithm choices. Review the linked experimental PR's disposition and decide the timeout-budget semantics before pursuing a production contribution.
