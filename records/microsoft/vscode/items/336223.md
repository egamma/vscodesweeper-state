# Issue #336223 — Feature Request: Provide Cursor-like Code Edit Review UI and Extension API

[https://github.com/microsoft/vscode/issues/336223](https://github.com/microsoft/vscode/issues/336223)

## Summary

Reasonable request, but VS Code core already ships most of this UX (per-hunk keep/undo, next/previous navigation, accept/reject-all, undo/redo integration) via the chat editing session machinery built for Copilot Chat — the actual gap is a finalized public Extension API letting arbitrary third-party extensions submit reviewable edits through that same UI, which doesn't exist yet. Too fresh (1 day, 0 upvotes, no maintainer input) to call a verdict either way.

## Change summary

Add a built-in, Cursor-like inline code-edit review UI (keep/undo, prev/next navigation, accept/reject-all) plus a public Extension API so any extension — not just Copilot Chat — can submit programmatic edits as reviewable hunks.

## Best solution

Point the reporter at the existing chat editing session review UX (src/vs/workbench/contrib/chat/browser/chatEditing/*, e.g. the `chatEditing.acceptAllFiles` command and chatEditingSession.ts) which already implements the core interaction for Copilot Chat; the remaining ask — a stable, provider-agnostic public API for third-party extensions to submit reviewable edits with per-edit attribution — is a real API-design gap flagged usefully by the comment thread (overlapping-edit attribution, exclusive-lock liveness issues) and needs a maintainer/API-owner decision, not an automated close.
