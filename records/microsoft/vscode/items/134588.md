# Issue #134588 — Add setting to keep tab characters in HTML clipboard

[https://github.com/microsoft/vscode/issues/134588](https://github.com/microsoft/vscode/issues/134588)

## Summary

The requested capability remains absent on current main: syntax-highlighted HTML clipboard output still expands tabs into spaces. The issue is already correctly classified and routed, and its On Deck milestone does not justify closing an unresolved request.

## Change summary

Allow syntax-highlighted HTML copied from the editor to retain tab characters instead of expanding them into spaces.

## Best solution

Provide a deliberate HTML-copy behavior that can preserve literal tabs while retaining syntax highlighting, without changing the plain-text clipboard payload. A maintainer should first decide whether this is opt-in or the new default and verify interoperability with major rich-text consumers.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/viewModel/viewModelImpl.ts`, `src/vs/editor/common/languages/textToHtmlTokenizer.ts`, `src/vs/editor/test/common/modes/textToHtmlTokenizer.test.ts`
- **Validation:** Extend the textToHtmlTokenizer or rich-copy tests to assert that the selected policy preserves literal tab characters in clipboard HTML while retaining token spans, and run ./scripts/test.sh --grep "Editor Modes - textToHtmlTokenizer".
- **Behavior:**

  > Copying tab-indented source as syntax-highlighted HTML should be able to retain semantic tab characters when pasted into a rich-text consumer, while preserving syntax colors. The plain-text clipboard representation must remain unchanged. Space-indented source and existing syntax-token styling must also remain unchanged. Acceptance includes inspecting the generated HTML and verifying the chosen behavior against a representative rich-text consumer such as Word.
- **Trace:**

  > The clipboard pipeline in src/vs/editor/browser/controller/editContext/clipboardUtils.ts obtains rich HTML from ViewModel.getRichTextToCopy in src/vs/editor/common/viewModel/viewModelImpl.ts. ViewModel._getHTMLToCopy delegates each line to tokenizeLineToHTML in src/vs/editor/common/languages/textToHtmlTokenizer.ts, whose CharCode.Tab branch always emits enough spaces to reach the next tab stop. The existing editor.copyWithSyntaxHighlighting option only disables rich HTML entirely and is therefore a workaround rather than coverage. The boundary is the syntax-highlighted HTML flavor: plain-text copying, token colors, selection handling, and unrelated uses of tokenizeLineToHTML must not regress.
- **Open decisions:**
  - Should literal-tab preservation be opt-in through a new editor setting, or should it replace tab expansion as the default HTML-copy behavior?
  - Which HTML representation preserves tabs reliably across Word and other rich-text consumers without breaking visual alignment?
  - Should the behavior be confined to clipboard HTML generation rather than changing every consumer of tokenizeLineToHTML?

## Evidence

- **current source:** src/vs/editor/common/viewModel/viewModelImpl.ts:getRichTextToCopy builds the syntax-highlighted HTML payload and calls _getHTMLToCopy; that method passes the editor tab size to tokenizeLineToHTML.
- **tab expansion:** src/vs/editor/common/languages/textToHtmlTokenizer.ts:tokenizeLineToHTML handles CharCode.Tab by calculating the visual tab width and emitting that many ordinary or non-breaking spaces, so literal tabs cannot survive in the HTML payload.
- **existing workaround is incomplete:** The editor.copyWithSyntaxHighlighting setting registered in src/vs/editor/common/config/editorOptions.ts can suppress the HTML payload, leaving the tab-preserving plain-text flavor, but it also removes syntax coloring and therefore does not satisfy the central request.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/134588#issuecomment-939721704 confirms that VS Code intentionally writes both plain text and HTML, and identifies HTML-side tab expansion as the reason Word receives spaces.
