# Issue #319118 — Auto-completion disabled for languages with ID >= 256 due to LanguageID bits overlapping with TokenType bits

[https://github.com/microsoft/vscode/issues/319118](https://github.com/microsoft/vscode/issues/319118)

## Summary

The defect remains source-reproducible on current main: unbounded language IDs are packed into an eight-bit metadata field without masking, so IDs above 255 overwrite token-type bits and can suppress quick suggestions. The linked fixing PR was closed without merging, and no open replacement PR exists.

## Change summary

Prevent high encoded language IDs from corrupting the token type in fallback line-token metadata and disabling quick suggestions.

## Best solution

Keep the eight-bit metadata format but isolate the language-ID field when constructing default metadata, preserving `StandardTokenType.Other` for languages beyond the representable ID range without claiming to preserve their full identity in packed tokens.

- **Behavior:**

  > A language registered after the first 256 encoded language IDs must continue receiving normal quick suggestions on un-tokenized or fallback-tokenized lines. Acceptance requires a regression test crossing the metadata language-ID boundary while existing token-store tests remain unchanged.
- **Trace:**

  > `LanguageIdCodec.register` in src/vs/editor/common/services/languagesRegistry.ts increments `_nextLanguageId` without an eight-bit limit. `ContiguousTokensStore.getTokens` and `_massageTokens` both call `getDefaultMetadata`, whose unmasked language-ID operand can occupy the adjacent token-type bits defined in src/vs/editor/common/encodedTokenAttributes.ts. `SuggestModel` in src/vs/editor/contrib/suggest/browser/suggestModel.ts consumes that corrupted classification when choosing quick-suggestion behavior. The boundary is fallback metadata construction: do not redesign the packed 32-bit token format, change language registration semantics, or promise lossless language identity above the format's eight-bit capacity. ## Evidence

- **source-confirmed overflow:** `LanguageIdCodec.register` in src/vs/editor/common/services/languagesRegistry.ts allocates monotonically increasing IDs without an upper bound, while `getDefaultMetadata` in src/vs/editor/common/tokens/contiguousTokensStore.ts shifts the complete ID into metadata without applying `MetadataConsts.LANGUAGEID_MASK`.
- **metadata layout:** src/vs/editor/common/encodedTokenAttributes.ts reserves bits 0-7 for the language ID and bits 8-9 for `StandardTokenType`; therefore language ID 256 sets the first token-type bit and is decoded as a comment token.
- **user-visible path:** src/vs/editor/contrib/suggest/browser/suggestModel.ts reads `LineTokens.getStandardTokenType` and selects the corresponding quick-suggestion configuration; comment and string suggestions are normally disabled while `other` suggestions are enabled.
- **unmerged fix attempt:** https://github.com/microsoft/vscode/pull/319144 proposed masking the language-ID field and adding a regression test, but it was closed on 2026-06-04 without merging; current main still contains the unmasked expression.
- **distinct related report:** https://github.com/microsoft/vscode/issues/284742 concerns exhaustion of the separate foreground-color field and was closed through the feature-request lifecycle; it does not own this language-ID/token-type corruption.
