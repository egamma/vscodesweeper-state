# Issue #288356 — win32 input mode has modifiers only scrolling to bottom

[https://github.com/microsoft/vscode/issues/288356](https://github.com/microsoft/vscode/issues/288356)

## Summary

Still an open bug, but the root cause lives in xterm.js's win32-input-mode keyboard handling, not in VS Code's own terminal code — VS Code only passes `enableWin32InputMode` straight through as an xterm.js `vtExtensions.win32InputMode` option, so the fix belongs upstream. A prior review's implemented-on-main close citing a different commit was already refuted by a second review, and I found no new fix commit.

## Change summary

With `terminal.integrated.enableWin32InputMode` enabled, pressing (holding) a modifier key alone scrolls the terminal viewport to the bottom, interrupting scrollback review (e.g. clicking a link higher up).

## Best solution

File or track this against xtermjs/xterm.js (the `@xterm/xterm` dependency, currently pinned at ^6.1.0-beta.304 in package.json) since the win32-input-mode key encoding and any scroll-to-bottom side effect on keydown live in that library's core terminal/keyboard handling, not in src/vs/workbench/contrib/terminal. Once xterm.js fixes or guards modifier-only keydowns from forcing a scroll, bump the dependency here.
