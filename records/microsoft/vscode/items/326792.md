# Issue #326792 — Remove duplicate neighboring files computation in NES

[https://github.com/microsoft/vscode/issues/326792](https://github.com/microsoft/vscode/issues/326792)

## Summary

Empty-body self-note, but the described duplicate computation is real and traceable in current main: NES computes neighboring-file (Jaccard) snippets twice per request — once for the prompt and again for telemetry — so this belongs on the area's backlog as a legitimate perf-debt item, not closed.

## Change summary

In the NES/xtab completion flow, neighbor-file similarity snippets are computed twice per request instead of once.

## Best solution

In extensions/copilot/src/extension/xtab/node/xtabProvider.ts, reuse the `neighborSnippets` already computed via `getSnippetsForPrompt` (line ~453) for the telemetry payload instead of issuing a second `similarFilesContextService.compute()` call (line ~547-549), which re-runs `_gatherSnippets`/Jaccard similarity against the same neighbor files. Likely requires extending `INeighborFileSnippet`/the service interface to also expose the `neighborFileCount` needed for the telemetry JSON so the second call can be dropped.
