# Issue #230563 — VSCode should support an install switch to enable/disable updates

[https://github.com/microsoft/vscode/issues/230563](https://github.com/microsoft/vscode/issues/230563)

## Summary

The install-time persistence gap remains: existing settings, policy, and the launch-time --disable-updates flag do not provide the requested set-once installer control. Keep this under discussion; the related Intune request is newer, and the older matching installer request is closed without evidence of an implementation.

## Change summary

Provide an installer switch that persistently enables or disables VS Code updates for enterprise deployments without distributing user configuration files.

## Best solution

Establish whether the Windows installer should expose a persistent update-control option for managed deployments, with explicit scope and precedence relative to UpdateMode policy and user settings. Preserve normal update behavior for installations that do not opt in.

## Evidence

- **Existing setting and policy:** src/vs/platform/update/common/update.config.contribution.ts registers update.mode with none/manual/start/default and the UpdateMode policy. The reporter explicitly acknowledges JSON configuration and explains in the discussion why GPO and ADMX ingestion do not meet their cloud-managed deployment requirements.
- **Launch flag is not an installation preference:** src/vs/platform/environment/node/argv.ts:190 registers --disable-updates; src/vs/platform/environment/electron-main/environmentMainService.ts:58 derives disableUpdates from the current process arguments. AbstractUpdateService.initialize in src/vs/platform/update/electron-main/abstractUpdateService.ts:200 disables updates for that launch; this path does not persist an installer-selected preference.
- **Installer capability check:** build/win32/code.iss defines installer tasks for shortcuts, shell integration, file associations, PATH, and launching Code, but no update-control task or UpdateMode registry entry. Its update parameter identifies an update installation rather than configuring future update behavior.
- **Older matching report is not an open canonical:** https://github.com/microsoft/vscode/issues/94031 requests the same Windows installer switch for non-admin deployments but is closed. The maintainer response at https://github.com/microsoft/vscode/issues/94031#issuecomment-607064218 recommends update.mode=manual; the reporter then clarifies that an installation parameter is needed. This supplies neither an open duplicate target nor a fixing commit or explicit full-scope decline.
- **Related enterprise requests do not absorb this item:** https://github.com/microsoft/vscode/issues/242922 is open and documents the same Intune registry restriction, but was created on 2025-03-07, after this report, and requests Settings Catalog/OMA-URI management rather than an installer switch. https://github.com/microsoft/vscode/issues/229861 is older and open, but requests additional enterprise policies rather than this installation behavior; neither qualifies as a canonical for this re-reviewed item.
- **Workaround does not cover the central ask:** https://github.com/microsoft/vscode/issues/242922#issuecomment-3928062264 describes an Intune script writing UpdateMode=none directly to the policy registry key. That is a separate deployment script, not the requested installer-provided control.
