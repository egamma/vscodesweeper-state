# Issue #333841 — Deleting one file deletes the entire parent folder

[https://github.com/microsoft/vscode/issues/333841](https://github.com/microsoft/vscode/issues/333841)

## Summary

The destructive behavior remains source-reproducible on current main: starting a second rename can orphan an unfinished new-file placeholder whose resource equals its parent directory, so deleting that placeholder targets the directory.

## Change summary

Renaming another Explorer item while an unnamed new-file input is active can leave a nameless placeholder whose deletion removes its parent folder.

## Best solution

Starting another Explorer edit must cleanly cancel or finish the active new-item edit, and deletion must never treat an unfinished placeholder as its parent directory.

## Evidence

- **placeholder resource:** src/vs/workbench/contrib/files/common/explorerModel.ts constructs NewExplorerItem with an empty URI and ExplorerItem.addChild/updateResource resolves its empty name with joinPath(parent.resource, ''), making the placeholder resource equal to the parent folder.
- **orphaned edit:** src/vs/workbench/contrib/files/browser/explorerService.ts setEditable replaces this.editable without finishing the previous editable; the refresh disposes the prior input in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts via done(false, false), which deliberately does not call onFinish, so openExplorerAndCreate never removes the placeholder.
