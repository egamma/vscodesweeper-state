# Issue #304417 — changes made in terminal

[https://github.com/microsoft/vscode/issues/304417](https://github.com/microsoft/vscode/issues/304417)

## Summary

A real review gap remains for edits performed through terminal commands: current source can attribute known file-write operations, but shell approvals do not report affected files. A maintainer has already asked how the terminal could provide that signal, so this should remain open for design and implementation planning.

## Change summary

Show a final reviewable diff with keep/undo controls when Copilot changes workspace files through terminal commands.

## Best solution

Capture a per-turn before/after changeset around agent-run terminal commands and feed it into the existing chat change-review surface, without mixing unrelated pre-existing workspace modifications into the agent's changes.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/chatSessions/copilotcli/node/permissionHelpers.ts`, `extensions/copilot/src/extension/chatSessions/common/externalEditTracker.ts`, `src/vs/workbench/contrib/chat/browser/chatResponseFileChangesService.ts`
- **Validation:** Add an integration or session-level test where an approved shell command modifies a workspace file, then assert the completed response exposes that file in its reviewable changes and can undo it without reverting a pre-existing unrelated modification.
- **Behavior:**

  > When an agent-approved terminal command changes workspace files, the completed turn shows those files in the same review experience used for other agent edits. The user can inspect the final diff and keep or undo the agent-attributed changes. Existing unrelated modifications must not be presented as changes from that terminal command or reverted by its undo action.
- **Trace:**

  > Write permissions in extensions/copilot/src/extension/chatSessions/copilotcli/node/permissionHelpers.ts call ExternalEditTracker with a known edit URI, but the shell-permission path only invokes the terminal confirmation and reports no changed files. ExternalEditTracker in extensions/copilot/src/extension/chatSessions/common/externalEditTracker.ts requires target URIs before execution, which does not cover arbitrary shell side effects. Core already has a per-request review projection through IChatResponseFileChangesProvider in src/vs/workbench/contrib/chat/browser/chatResponseFileChangesService.ts, and agent-host sessions demonstrate an authoritative changeset-backed implementation. The boundary is attribution and review of files changed by the agent's terminal turn; do not treat the entire dirty working tree as agent-owned or alter ordinary terminal behavior. Related issue https://github.com/microsoft/vscode/issues/315310 is newer and broader, so it is not a canonical duplicate for this re-reviewed item.
- **Open decisions:**
  - Should terminal review contain only changes attributable to the approved command or turn, or all working-tree changes detected between turn checkpoints when concurrent and pre-existing edits cannot be distinguished?

## Evidence

- **source gap:** extensions/copilot/src/extension/chatSessions/copilotcli/node/permissionHelpers.ts routes write permissions through ExternalEditTracker with a known file URI, while handleShellPermission only requests terminal approval and receives neither the tracker nor affected URIs.
- **tracking boundary:** extensions/copilot/src/extension/chatSessions/common/externalEditTracker.ts requires an explicit URI list before calling ChatResponseStream.externalEdit, so arbitrary file changes made by a shell command are not attributable through that path.
- **existing review surface:** src/vs/workbench/contrib/chat/browser/chatResponseFileChangesService.ts already defines per-request diffs for the "Changed N files" summary, and agent-host sessions populate it from authoritative per-turn changesets in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostResponseFileChanges.ts.
- **maintainer direction:** A maintainer explicitly asked whether the terminal can report changed lines back to the chat experience: https://github.com/microsoft/vscode/issues/304417#issuecomment-4775300288.
- **related report:** https://github.com/microsoft/vscode/issues/315310 reports missing accept/undo UI for directly applied edits, but it was created after this re-reviewed issue and does not specifically establish the same terminal-change reporting path, so it is not a valid duplicate canonical.
