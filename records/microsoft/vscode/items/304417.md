# Issue #304417 — changes made in terminal

[https://github.com/microsoft/vscode/issues/304417](https://github.com/microsoft/vscode/issues/304417)

## Summary

Keep open: terminal-command approval does not provide the requested post-execution file-change review. Existing external-edit tracking supplies part of the infrastructure, but the inspected terminal tool does not connect arbitrary shell-written changes to it, and a maintainer has expressed interest in that integration.

## Change summary

Include file changes made through Copilot terminal commands in the final change overview with keep/undo controls.

## Best solution

Provide reviewable before/after file changes for supported Copilot terminal edits using the existing chat editing experience. First establish how changes are attributed to a command and which filesystem effects the review can reliably undo without affecting unrelated edits.

- **Behavior:**

  > The reporter can approve a terminal command but cannot then review its file edits through the same final overview and keep/undo experience used for direct agent edits. Supported terminal-originated file changes should appear as accurate before/after diffs associated with the responsible chat request. Keeping a change should retain it, and undoing it should restore the appropriate baseline without reverting unrelated user changes. Command-execution approval and review of the resulting file edits remain separate interactions.
- **Trace:**

  > RunInTerminalTool in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts handles terminal invocation but has no inspected connection to external-edit tracking. CommandLineFileWriteAnalyzer identifies selected write destinations for approval decisions and disclaimers, not exhaustive filesystem-change attribution. ChatEditingSession.startExternalEdits and stopExternalEdits in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts already snapshot and diff explicitly declared resources. The unresolved boundary is discovering and attributing resources modified by shell commands, including concurrent or long-running activity; the existing infrastructure alone does not settle that contract. Preserve direct-edit review behavior and existing command approval semantics. https://github.com/microsoft/vscode/issues/279040 is related API work, not a verified duplicate of this request.
- **Open decisions:**
  - Should review initially cover only explicitly identifiable command write targets, or also files discovered as changing during command execution, and how should unsupported changes be communicated?
  - Which terminal-originated filesystem effects should support Undo: text modifications only, or also file creation, deletion, and renaming?
  - When user edits or another process changes the same file during a command, what review and undo behavior should preserve those unrelated changes?
