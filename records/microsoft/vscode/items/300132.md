# Issue #300132 — The rg process uses a huge amount of CPU.

[https://github.com/microsoft/vscode/issues/300132](https://github.com/microsoft/vscode/issues/300132)

## Summary

Multiple users confirm that VS Code's file-discovery subsystem (for MCP configs, chatmode files, agent instructions) spawns excessive rg processes that saturate CPU. The issue has 8 upvotes, multiple independent confirmations, and no fix referencing it on main. Should be routed to the search and chat areas for investigation.

## Change summary

VS Code spawns hundreds of rg (ripgrep) processes for file discovery (MCP configs, chatmode files, agent instructions), consuming all available CPU and making the system unusable.

## Best solution

Investigate and throttle the file-search calls in the prompt-file discovery pipeline (`src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts`) and MCP configuration discovery (`src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts`). The fileSearch calls via `ISearchService` likely need debouncing, deduplication, or caching to prevent unbounded rg process spawning — especially when multiple windows are open and file watchers trigger re-scans. Special characters in paths (brackets) may cause glob patterns to fail silently and retry in a loop.
