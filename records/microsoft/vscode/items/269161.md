# Issue #269161 — Not sure how to instruct the model to use the reference

[https://github.com/microsoft/vscode/issues/269161](https://github.com/microsoft/vscode/issues/269161)

## Summary

Keep open: the graph's file-level Add to Chat action still attaches the committed file rather than its diff. The maintainer acknowledged this gap, but the choice between separate attachment actions and combined context remains unresolved.

## Change summary

Make a file attached from a historical commit provide enough change context for Chat to explain that commit's changes rather than inspect local modifications.

## Best solution

Provide an explicit, discoverable way to attach a selected file's historical diff from the SCM Graph while preserving access to the committed file contents. Settle whether these are separate gestures or combined context before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmHistoryChatContext.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts`, `extensions/git/src/historyProvider.ts`
- **Validation:** Use a repository with a committed file change and different uncommitted edits. From the SCM Graph, attach that historical file's changes and verify that the resolved context contains the selected commit's patch rather than local edits; confirm that historical file-content attachment remains available. Add a targeted attachment/context-resolution test asserting the selected revisions and file scope, then manually check Chat can explain the supplied historical change.
- **Behavior:**

  > A user selecting a file in a historical commit can supply its changes to Chat without requiring Chat to discover them from the working tree. The context must identify the historical change and distinguish it from unrelated local modifications. Access to the file contents at that revision must remain available. Acceptance should verify the actual attachment payload separately from model-dependent response quality.
- **Trace:**

  > The file-level graph action workbench.scm.action.graph.addHistoryItemChangeToChat in src/vs/workbench/contrib/scm/browser/scmHistoryChatContext.ts attaches modifiedUri as scmHistoryItemChange with commit metadata, but does not construct diff context. Whole-commit attachments already resolve patches through GitHistoryProvider.resolveHistoryItemChatContext in extensions/git/src/historyProvider.ts. src/vs/workbench/contrib/chat/browser/actions/chatActions.ts also supports attachHistoryItemChangeRanges backed by SCMHistoryItemChangeRangeContentProvider, establishing related infrastructure without changing the reported graph gesture. The maintainer explicitly left separate gestures versus combined context undecided at https://github.com/microsoft/vscode/issues/269161#issuecomment-3355600950. Preserve historical file navigation and do not broaden this work into general model instruction-following or the additional diff-editor gesture requested by https://github.com/microsoft/vscode/issues/316919.
- **Open decisions:**
  - Should the graph expose separate actions for committed file contents and the historical diff, or should its existing Add to Chat action attach both?
