# Issue #350664 — Copilot Agents: expose the resolved subagent target to a veto-capable hook

[https://github.com/microsoft/vscode/issues/350664](https://github.com/microsoft/vscode/issues/350664)

## Summary

Keep open: existing hooks provide either pre-execution denial or subagent information, but no documented contract combines resolved recipient identity with a pre-creation veto. The verified related requests concern different capabilities.

## Change summary

Expose the resolved delegation recipient's stable definition identity, display name, and provenance to a hook that can deny child creation.

## Best solution

Provide a documented Copilot runtime/SDK hook contract at the resolved-target, pre-creation boundary, preserving existing permission enforcement. VS Code should supply definition provenance it owns without reconstructing the recipient from model arguments or opaque digests.
