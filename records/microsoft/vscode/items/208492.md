# Issue #208492 — git conflicts - highlight for the base for diff3 conflict format

[https://github.com/microsoft/vscode/issues/208492](https://github.com/microsoft/vscode/issues/208492)

## Summary

Keep open as merge-conflict visual polish. Current main recognizes and decorates diff3 base regions, but its common-ancestor header lacks the explicit caption used for Current and Incoming, and the subdued default gray treatment does not fully address the requested differentiation.

## Change summary

Make the base section of inline diff3 conflicts as clearly highlighted and identified as the Current and Incoming sections.

## Best solution

Give the common-ancestor region a clear, accessible Base identity consistent with the Current and Incoming treatments while preserving the existing merge color theme keys and ordinary two-way conflict rendering.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/mergeDecorator.ts`, `src/vs/platform/theme/common/colors/editorColors.ts`
- **Validation:** Open a document containing diff3 markers in an Extension Development Host and verify under the default dark, light, and high-contrast themes that the base block is clearly identified, Current and Incoming remain unchanged, and ordinary two-way conflict markers render as before.
- **Behavior:**

  > In an inline diff3 conflict, the base/common-ancestor section should be as readily identifiable as the Current and Incoming sections. Its header should communicate that the section is the base without relying solely on the raw Git marker text, and its content should remain visually distinct across default dark, light, and high-contrast themes. Standard two-way conflicts and custom theme overrides must remain unchanged.
- **Trace:**

  > MergeConflictParser in extensions/merge-conflict/src/mergeConflictParser.ts already parses `|||||||` blocks into `commonAncestors`; the parsing and conflict-resolution semantics are not the gap. MergeDecorator in extensions/merge-conflict/src/mergeDecorator.ts already decorates common-ancestor content and headers using colors registered in src/vs/platform/theme/common/colors/editorColors.ts, but unlike Current and Incoming, the common-ancestor header has no `after.contentText` caption. The existing common-ancestor colors originate in https://github.com/microsoft/vscode/commit/996af4d965f4b9b3862cd7c02e28509f346bf0eb. Keep the work limited to inline conflict presentation: do not change merge parsing, accept commands, the merge editor, or ordinary two-way conflict behavior.
- **Open decisions:**
  - Should the added caption use the user-facing term “Base” from Git's diff3 format or the existing internal/theme terminology “Common Ancestor”?
  - Is an explicit caption sufficient, or should the default common-ancestor background also become more prominent across the built-in themes?

## Evidence

- **current source:** extensions/merge-conflict/src/mergeConflictParser.ts recognizes `|||||||` markers and constructs `commonAncestors` regions; extensions/merge-conflict/src/mergeDecorator.ts applies `merge.commonContentBackground` and `merge.commonHeaderBackground` decorations to them.
- **remaining gap:** In extensions/merge-conflict/src/mergeDecorator.ts, Current and Incoming headers add localized `(Current Change)` and `(Incoming Change)` captions through `after.contentText`, while `commonAncestors.header` has no equivalent Base/Common Ancestor caption.
- **existing theming:** src/vs/platform/theme/common/colors/editorColors.ts registers the common-ancestor header and content colors; the default treatment is a subdued gray, so the implementation exists but does not necessarily provide differentiation comparable to Current and Incoming.
- **history:** https://github.com/microsoft/vscode/commit/ab528897935b0957249e90d69e5985870673fd4b added diff3 parsing, and https://github.com/microsoft/vscode/commit/996af4d965f4b9b3862cd7c02e28509f346bf0eb added common-ancestor background colors, both before this report. This is therefore a request to improve the existing presentation, not an implemented-after-report close.
- **related issue:** https://github.com/microsoft/vscode/issues/133088 is older and open, but asks for pairwise original/current and original/incoming diff commands. It does not report the same observable symptom as missing or insufficient inline base-region identification, so it fails the stronger duplicate bar for this re-reviewed issue.
