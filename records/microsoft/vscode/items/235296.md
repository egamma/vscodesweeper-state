# Issue #235296 — Add to `vscode.window.createWebviewPanel` an option to open detached (new `ViewColumn`)

[https://github.com/microsoft/vscode/issues/235296](https://github.com/microsoft/vscode/issues/235296)

## Summary

A real extension API gap remains: core can open editors directly in auxiliary windows, but `createWebviewPanel` only exposes ordinary view columns. The issue is appropriately classified and parked in the Backlog.

## Change summary

Allow extensions to create a webview panel directly in a detached auxiliary window.

## Best solution

Expose an auxiliary-window target through the webview panel show options, backed by the existing `AUX_WINDOW_GROUP` editor-service path, while preserving current `ViewColumn` behavior.

- **Reason:** This closes an extension API gap around the workbench's existing auxiliary-window capability without adding new default UI.

## Evidence

- **public API gap:** src/vscode-dts/vscode.d.ts defines `ViewColumn` with Active, Beside, and numbered columns only; `window.createWebviewPanel` requires that type for its target.
- **current implementation:** src/vs/workbench/api/browser/mainThreadWebviewPanels.ts:getTargetGroupFromShowOptions maps only active, side, and numbered groups, so extensions cannot request an auxiliary window during creation.
- **core capability:** Commit 7e67ab1991fc57fce50d5224e64ce3b86b02d1a9 added internal `AUX_WINDOW_GROUP` support that creates an auxiliary editor part, but this target is not exposed through the extension API.
- **existing workaround:** The `workbench.action.moveEditorToNewWindow` command can move the active webview after creation, as documented in https://github.com/microsoft/vscode/issues/213516, but it does not provide the requested direct and deterministic creation target.
- **canonical search:** The closest matching issue, https://github.com/microsoft/vscode/issues/213516, is closed by the feature-request community process and therefore cannot serve as an open duplicate canonical.
