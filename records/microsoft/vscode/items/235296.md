# Issue #235296 — Add to `vscode.window.createWebviewPanel` an option to open detached (new `ViewColumn`)

[https://github.com/microsoft/vscode/issues/235296](https://github.com/microsoft/vscode/issues/235296)

## Summary

The requested API capability is still missing: extensions cannot ask createWebviewPanel to create a detached window directly. Existing editor-detachment commands operate on already-open editors, and the related issues inspected do not own this API request.

## Change summary

Allow extensions to create a webview panel directly in a new detached editor window instead of an existing or adjacent editor column.

## Best solution

Provide an explicit extension API destination for creating a webview panel in a new auxiliary editor window, preserving its association with the originating workspace and extension host. Decide whether this should be a shared editor-opening destination or a webview-specific option before implementation.

- **Behavior:**

  > An extension should be able to create a webview panel directly in a new detached editor window without first displaying it in the main window and then issuing a move command. The detached panel remains associated with the originating workspace and extension host, including normal messaging and disposal. Existing editor-column destinations must remain unchanged. Acceptance includes direct detached creation and regression checks for Active, Beside, numbered columns, and focus behavior.
- **Trace:**

  > The public createWebviewPanel signature in src/vscode-dts/vscode.d.ts has no detached destination. ExtHostWebviewPanels.createWebviewPanel forwards column and focus information through the protocol; ViewColumn.from converts it to active, side, or indexed groups, and MainThreadWebviewPanels.getTargetGroupFromShowOptions resolves those groups without creating an auxiliary editor part. BaseMoveCopyEditorToNewWindowAction in src/vs/workbench/browser/parts/editor/editorActions.ts demonstrates the existing createAuxiliaryEditorPart path, but it acts on already-open editors. The gap is the extension-facing opening contract, not basic floating-window infrastructure. Preserve existing column semantics and do not turn this into a new independent workspace window. https://github.com/microsoft/vscode/issues/195715 addresses iframe reparenting, while https://github.com/microsoft/vscode/issues/193267 addresses bottom-panel detachment; neither completes this API request. The unresolved boundary is whether detached creation becomes a general editor-opening destination or a webview-specific option.
- **Open decisions:**
  - Should detached creation be exposed as a shared ViewColumn/editor-opening destination or as a webview-specific show option?
