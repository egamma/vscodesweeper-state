[https://github.com/microsoft/vscode/issues/311551](https://github.com/microsoft/vscode/issues/311551)

## Summary

Still reproduces on main: the `findPR` retry window (7 × 1500ms ≈ 10.5s) is too short when GitHub's search API hasn't indexed a newly-created PR, causing a thrown error that surfaces to the user. The code path is unchanged on current main.

## Change summary

After delegating to the Copilot cloud coding agent, the extension fails to find the newly-created pull request because GitHub's search API hasn't indexed it within the retry window.

## Best solution

Increase the retry budget in `findPR` when called from `delegate()` (e.g. more retries or exponential backoff), or switch from the search API to the direct PR endpoint (`GET /repos/{owner}/{repo}/pulls/{number}`) which doesn't depend on search indexing. The fix is localized to `copilotCloudSessionsProvider.ts`.
