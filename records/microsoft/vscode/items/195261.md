# Issue #195261 — Running extensions editor does not wrap content properly

[https://github.com/microsoft/vscode/issues/195261](https://github.com/microsoft/vscode/issues/195261)

## Summary

The responsive-layout defect remains present on current main: Running Extensions rows have a fixed height while localized names, status messages, and activation timing can exceed the available width. The existing extensions-editor routing is appropriate, so this should remain open.

## Change summary

Make Running Extensions rows reflow their metadata and status content instead of clipping or overflowing when the editor is narrow.

## Best solution

Give the Running Extensions list a responsive row layout with sufficient dynamic height so extension names, versions, status messages, actions, and activation timing remain readable at narrow widths and with longer localized text.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts`, `src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css`
- **Validation:** In a development build, open Developer: Show Running Extensions, narrow the editor group, and use extensions with long localized names and runtime status messages; verify every row remains readable without horizontal clipping, overlap, or content escaping its row.
- **Behavior:**

  > Running Extensions must remain readable when its editor group is narrow or extension metadata is long. Names, versions, status messages, actions, activation timing, and profile timing must not overlap, clip at the editor edge, or escape their row. Wider layouts and all existing row actions must retain their current behavior.
- **Trace:**

  > AbstractRuntimeExtensionsEditor in src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts renders all row content into a WorkbenchList whose delegate always returns 70 pixels. The corresponding flex layout in src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css has no complete responsive policy for the description, messages, and right-aligned timing column. The issue screenshots demonstrate both long-message clipping and metadata/timing collision. Commit 0661ba5172b485bde9729300844df8f10e151f83 modernized the styling but retained this structural constraint. Keep the scope within the Running Extensions editor and preserve context-menu, profiling, error-reporting, and accessibility behavior.
- **Open decisions:**
  - At constrained widths, should activation and profile timing move below the extension metadata, or should secondary timing information be hidden or truncated while status messages wrap?

## Evidence

- **reported behavior:** The screenshots in https://github.com/microsoft/vscode/issues/195261 show a long extension status message clipped at the editor edge and localized extension metadata colliding with activation timing at a narrower width.
- **current source:** src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts returns a fixed height of 70 from the Runtime Extensions IListVirtualDelegate, even though each row may contain a name, version, status messages, actions, activation time, and profile time.
- **layout path:** src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css keeps each row in one flex layout; `.desc` has no minimum-width override, `.time` has no responsive reflow behavior, and message spans have no wrapping or overflow policy.
- **later styling change:** https://github.com/microsoft/vscode/commit/0661ba5172b485bde9729300844df8f10e151f83 updated spacing, typography, and icon alignment in this stylesheet but retained the fixed-height row and non-responsive content layout, so it does not resolve this report.
- **canonical search:** https://github.com/microsoft/vscode/issues/133136 proposes a broader grid redesign but does not own or specifically track the existing list's narrow-width wrapping defect.
