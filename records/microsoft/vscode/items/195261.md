# Issue #195261 — Running extensions editor does not wrap content properly

[https://github.com/microsoft/vscode/issues/195261](https://github.com/microsoft/vscode/issues/195261)

## Summary

The narrow-layout clipping remains reproducible from current source: Running Extensions rows have a fixed height and the flexible description column lacks a shrink boundary, allowing long localized names and messages to push activation details beyond the editor edge.

## Change summary

Make Running Extensions entries wrap or otherwise adapt at narrow editor widths without clipping names, status messages, or activation timing.

## Best solution

Make each runtime-extension row responsive so its name, version, status, and timing remain contained and readable at narrow widths, with no overlap between adjacent rows.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts`, `src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css`
- **Validation:** Launch the development workbench, run Developer: Show Running Extensions, narrow its editor group to roughly 650 CSS pixels, and use extensions with a long localized display name and status message; verify no content crosses the editor's right edge, all rows remain readable, and adjacent rows do not overlap.
- **Behavior:**

  > Running Extensions entries must remain contained within the editor at narrow widths. Long localized extension names, versions, status messages, and activation timing must not overlap or disappear beyond the right edge. If content wraps, the row must grow or otherwise preserve separation from adjacent entries. Wider layouts should retain their current compact presentation.
- **Trace:**

  > The current row renderer is in `AbstractRuntimeExtensionsEditor.createEditor` at src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts. Its `IListVirtualDelegate.getHeight` always returns 70, while the row markup places `.desc` and `.time` beside each other. In src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css, `.desc` is flexible but has no `min-width: 0`, and `.time` has no responsive fallback; the screenshots exhibit the resulting horizontal overflow. Commit 0661ba5172b485bde9729300844df8f10e151f83 adjusted styling but left this sizing model intact. The boundary is the Running Extensions editor: ordinary wide layouts, list virtualization, extension actions, and activation data must remain unchanged.
- **Open decisions:**
  - Should narrow rows grow dynamically to preserve wrapped status text, or should selected fields be truncated to retain the fixed 70-pixel list height?
  - At what width should activation and profile timing move below the extension metadata rather than remain a right-aligned column?
  - Should a visual regression fixture be added for the narrow layout, or should this remain an explicit manual workbench check?

## Evidence

- **reported behavior:** The issue screenshots show long Korean extension names and status text pushing or clipping activation timing at the right edge in narrow Running Extensions editor groups.
- **current source:** src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts uses an IListVirtualDelegate with a fixed 70-pixel row height, while src/vs/workbench/contrib/extensions/browser/media/runtimeExtensionsEditor.css gives `.desc` `flex: 1` without `min-width: 0`; the `.time` column has no responsive wrapping or shrinking behavior.
- **later layout change:** Commit 0661ba5172b485bde9729300844df8f10e151f83 from https://github.com/microsoft/vscode/pull/329393 updated spacing and alignment but retained the fixed row layout and did not reference or close this issue.
- **canonical search:** Repository issue searches found no open canonical issue specifically owning responsive wrapping in the Running Extensions editor.
