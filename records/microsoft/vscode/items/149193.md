# Issue #149193 — [less] The each function has incorrect linting inside a keyframes at-rule

[https://github.com/microsoft/vscode/issues/149193](https://github.com/microsoft/vscode/issues/149193)

## Summary

The false diagnostics remain explainable on current main: VS Code delegates LESS parsing to vscode-css-languageservice, whose keyframe-body parser still accepts only keyframe selectors or detached-ruleset invocations, not the `each(...)` function used here. This should remain open as an upstream parser defect.

## Change summary

Allow a LESS `each(...)` function containing generated percentage selectors inside an `@keyframes` body without false syntax diagnostics.

## Best solution

Fix the LESS parser in microsoft/vscode-css-languageservice so keyframe bodies accept valid LESS functions that expand to keyframe selectors, add the reported example as a parser validation test, then update the dependency bundled by VS Code.

## Evidence

- **VS Code integration:** extensions/css-language-features/server/src/cssServer.ts constructs the LESS service with `getLESSLanguageService` and delegates parsing and diagnostics to vscode-css-languageservice; extensions/css-language-features/server/package.json currently pins `vscode-css-languageservice` 7.0.0-next.2.
- **current parser path:** In current vscode-css-languageservice src/parser/cssParser.ts, `_parseKeyframe` parses the body exclusively through `_parseKeyframeSelector`. The LESS override in src/parser/lessParser.ts accepts `_parseDetachedRuleSetMixin()` or the base keyframe selector there, but does not try `_parseFunction()`, even though `_parseFunction()` is accepted in ordinary LESS stylesheet and ruleset bodies.
- **related fix does not cover this direction:** https://github.com/microsoft/vscode-css-languageservice/pull/502, integrated into VS Code by https://github.com/microsoft/vscode/pull/335413, permits keyframe selectors inside nested LESS/SCSS rule bodies. This report is the inverse path—an `each(...)` function directly inside a keyframes body—so that merged change does not reach the failing parser callback.
- **canonical search:** No older open microsoft/vscode issue with the same reporter-observable LESS `each(...)`-inside-`@keyframes` symptom was found; the supplied candidate canonicals are unrelated.
