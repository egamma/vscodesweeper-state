# Issue #340554 — Sandbox output analyzer treats any ENOENT as a sandbox denial, causing spurious "run unsandboxed?" approval prompts

[https://github.com/microsoft/vscode/issues/340554](https://github.com/microsoft/vscode/issues/340554)

## Summary

Thanks for the detailed report. On current main, the sandbox output analyzer's guidance still tells the model to treat any 'No such file or directory' as a sandbox error and retry unsandboxed. This causes spurious approval prompts, so the issue stays open.

## Change summary

The sandbox output analyzer treats ordinary ENOENT messages as sandbox denials and tells the model to retry with requestUnsandboxedExecution=true.

## Best solution

Remove the blanket 'No such file or directory' instruction and regex match from sandboxOutputAnalyzer.ts. Rely on explicit sandbox markers instead, or gate the match on a non-zero exit code and a path that falls inside the deny rules. Restore the negative ENOENT test case.
