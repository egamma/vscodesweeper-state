# Issue #235512 — Characters go into each other with fontLigatures and RTL characters.

[https://github.com/microsoft/vscode/issues/235512](https://github.com/microsoft/vscode/issues/235512)

## Summary

Still reproduces on main: when a line contains RTL text, the ligature-aware token splitting is entirely skipped, causing ligature glyphs (like `===` in FiraCode) to overlap with adjacent RTL characters. Recent RTL fixes (#260239, #279474) improved bidi isolation but did not address the ligature interaction.

## Change summary

Font ligatures (e.g. `===` in FiraCode) render with overlapping/corrupted characters when the same line also contains RTL text.

## Best solution

In `resolveRenderLineInput` (viewLineRenderer.ts), the RTL branch at line 509 skips `splitLargeTokens` entirely. The fix should apply ligature-aware splitting to the non-RTL portions of RTL-containing lines — split tokens that don't themselves contain RTL text the same way the non-RTL path does, while still preserving RTL token integrity.
