# Issue #195159 — TypeError: Failed to parse URL from /.vscode/extensions/rebornix.ruby-0.28.1/dist/server/tree-sitter.wasm

[https://github.com/microsoft/vscode/issues/195159](https://github.com/microsoft/vscode/issues/195159)

## Summary

The failure comes from the deprecated third-party `rebornix.ruby` extension loading WASM generated by an incompatible Emscripten version, not from VS Code core.

## Change summary

Opening a Ruby project after VS Code 1.82 causes the deprecated Ruby extension's language server to fail while loading `tree-sitter.wasm`.

## Best solution

Remove the deprecated `rebornix.ruby` extension and migrate to its maintained Ruby language tooling replacement; no VS Code core change is needed.

  > Thanks for the report and investigation. ## Evidence

- **failing component:** The reported path is inside `rebornix.ruby-0.28.1`, and the stack terminates that extension's language server while it loads `dist/server/tree-sitter.wasm`.
- **root cause:** The investigation in the discussion identifies an obsolete Emscripten runtime check: Node.js 18 exposes `fetch`, causing the generated loader to pass a local filesystem path to `fetch` and fail URL parsing.
- **maintainer assessment:** VS Code maintainer dbaeumer confirmed that this is unrelated to VS Code's general WASM support and that the Ruby language server is loading the WASM file.
- **extension status:** The affected extension repository, https://github.com/rubyide/vscode-ruby, is deprecated; the discussion identifies https://github.com/Shopify/vscode-shopify-ruby as the maintained replacement without this failure.
