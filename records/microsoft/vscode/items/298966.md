## Evidence

- **index-driven UI:** ChatSessionStore at src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts uses a `chat.ChatSessionStore.index` key in StorageService (scoped to WORKSPACE) to populate the history UI; session files on disk without an index entry are invisible.
- **prior related fix:** Commit 7393b0ec607 ('Fix chat session loss on workspace ID change', PR https://github.com/microsoft/vscode/issues/289779) merged 2026-02-10 — before this issue was filed — addresses workspace-ID-change session loss, but does not reference this issue and may not cover the Remote-WSL storage mismatch.
- **comment 4 non-WSL:** A second reporter (rijesha) sees the same symptom on plain Windows 11 v1.109.5 — sessions flash briefly on Reload Window then disappear — suggesting the problem may not be WSL-specific.
- **comment 5 analysis:** conbrocox analyzed the root cause as the UI reading only from the index in state.vscdb, not scanning the chatSessions/ folder; session files present but unregistered in the index are invisible.
