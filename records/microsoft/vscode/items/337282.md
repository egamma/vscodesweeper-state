# Issue #337282 — How Auto is displayed in experimental model picker

[https://github.com/microsoft/vscode/issues/337282](https://github.com/microsoft/vscode/issues/337282)

## Summary

Fresh, team-authored UX feedback on the experimental model picker's Auto display; a real design proposal that needs maintainer/design discussion (and coordination with the unreleased HydraFusion feature) before implementation, not a mechanical fix.

## Change summary

Proposes collapsing the model picker to a single prominent line for Auto when enabled, and progressively disclosing tier details only when Auto is disabled/enabled respectively.

## Best solution

Have the chat/model-picker design owners weigh in on the exact collapse/progressive-disclosure behavior (and how it interacts with the planned HydraFusion option) before an implementation lands in modelPickerAutoRow.ts / modelPickerItemSections.ts.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerAutoRow.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemSections.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerPresentation.ts`
- **Validation:** A modelPickerAutoRow/modelPickerItemSections test asserting the picker renders as a single collapsed row when Auto is enabled/disabled per the agreed design, once the design is settled.
- **Behavior:**

  > When Auto is enabled, the model picker should visually emphasize it (e.g., collapse or de-emphasize the other model tiers) so Auto isn't lost among other options. When Auto is disabled, the Auto configuration row itself should collapse to a single line (keeping the discount indicator) rather than showing full tier detail, using progressive disclosure. Acceptance: the picker's rendered structure matches whatever exact collapse/disclosure design is agreed with the feature owner.
- **Trace:**

  > modelPickerAutoRow.ts renders the Auto row/config UI and modelPickerItemSections.ts governs how model tiers/sections are laid out in the picker (src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/). Neither currently implements collapsing/progressive disclosure tied to Auto's enabled state. The boundary: don't touch unrelated model list/selection logic (modelPickerItems.ts, modelPickerWidget.ts) beyond what's needed to show/hide sections. Where the uncertainty starts: the precise visual treatment (what 'collapse' means concretely) and how it should anticipate the yet-unshipped HydraFusion row are open design questions from the issue itself.
- **Open decisions:**
  - Exactly what does 'collapse the rest of the model picker' look like when Auto is enabled — hidden entirely, or just visually de-emphasized?
  - What does the single-line collapsed view show when Auto is disabled (just the discount badge, or more)?
  - How should this design account for the not-yet-shipped HydraFusion row mentioned in the issue?
