# Issue #131619 — Editor resolver: untyped `editorGroupFinder#findGroup` causes issues

[https://github.com/microsoft/vscode/issues/131619](https://github.com/microsoft/vscode/issues/131619)

## Summary

The debt remains: `findGroup` in editorGroupFinder.ts still accepts `IUntypedEditorInput` and the resolver service still calls it with untyped editors. The architectural concern about incorrect `matches`/`contains` checks with untyped inputs is unresolved on current main.

## Change summary

Refactor `editorGroupFinder#findGroup` to stop accepting untyped editor inputs, avoiding broken `matches`/`contains` checks before editor type resolution.

## Best solution

Restructure the editor resolver flow so that `findGroup` is only called after the editor type is known (typed `EditorInputWithOptions`), eliminating the untyped overloads and the workarounds in `isGroupLockedForEditor`/`isActive`/`isOpened`. This requires revisiting the custom editor/webview group-finding that motivated the untyped call path (linked issue https://github.com/microsoft/vscode/issues/121322).
