# Issue #328340 — [Regression in 1.131] vscode_askQuestions auto-fills "user is not available" instead of prompting; Plan mode also auto-switches to Agent

[https://github.com/microsoft/vscode/issues/328340](https://github.com/microsoft/vscode/issues/328340)

## Summary

Real, independently-confirmed regression (a second reporter reproduced the askQuestions auto-fill on 1.134.0 with extra race-condition detail) that needs chat-team investigation into why the Autopilot code path fires when the user never chose Autopilot; not enough evidence from source alone to pin the exact trigger, so this should be routed rather than auto-closed or auto-fixed.

## Change summary

vscode_askQuestions auto-fills a 'user not available, work autonomously' answer instead of blocking, and Plan mode sometimes silently auto-switches to Agent and starts executing edits.

## Best solution

Chat team should trace why `request.modeInfo?.permissionLevel` ends up as `ChatPermissionLevel.Autopilot` (or `chat.autoReply` ends up enabled) when the user is in ordinary Plan/Agent mode — both symptoms are gated by that same check in askQuestionsTool.ts and the auto-handoff logic in chatWidget.ts, so a single root-cause investigation likely explains both; should be triaged alongside the already-open https://github.com/microsoft/vscode/issues/323274 and https://github.com/microsoft/vscode/issues/323074 (same mode-switch mechanism) since they may share a fix.

## Evidence

- **related auto-handoff mechanism:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:1682-1691 auto-triggers a handoff (e.g. Plan -> implementation) specifically 'In Autopilot mode', matching the reporter's Bug 2 symptom and the same Autopilot gating.
