# Issue #327600 — Memory tool: user memory is never auto-loaded when the memories directory is a junction/symlink (strict FileType check)

[https://github.com/microsoft/vscode/issues/327600](https://github.com/microsoft/vscode/issues/327600)

## Summary

Keep open: current source still rejects junction/symlink memory directories before reading their contents, silently producing empty memory context. The same directory checks affect session and repository memory listings; no verified duplicate or fixing commit was found.

## Change summary

Automatically load user memory and list session/repository memory when their directories are reachable through junctions or symbolic links.

## Best solution

MemoryContextPrompt should treat reachable linked directories consistently with ordinary directories across all three memory scopes, preserving the existing 200-line user-memory cap, hidden-file exclusions, and session/repository listing-only behavior.
