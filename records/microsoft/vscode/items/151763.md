# Issue #151763 — when hovers are not sticky, alt/opt key should make them temporarily sticky

[https://github.com/microsoft/vscode/issues/151763](https://github.com/microsoft/vscode/issues/151763)

## Summary

Keep open: current editor hover handling still lacks the requested temporary Alt/Option lock when sticky hovers are disabled. Both previous implementations were reverted; the newer modifier-trigger setting controls hover appearance, not temporary stickiness.

## Change summary

Allow holding Alt/Option to temporarily lock an editor hover while editor.hover.sticky remains false.

## Best solution

Provide temporary Alt/Option locking for editor hovers without changing their normal non-sticky behavior, preserving text selection, copying, and existing keyboard shortcuts. Account explicitly for the copy regression that caused the previous implementation to be reverted.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/hover/browser/contentHoverController.ts`, `src/vs/editor/contrib/hover/browser/contentHoverWidgetWrapper.ts`, `src/vs/editor/contrib/hover/test/browser/contentHover.test.ts`
- **Validation:** With editor.hover.enabled='on', editor.hover.sticky=false, and editor.hover.delay=0, show a documentation hover, hold Alt/Option, move into it, select text, and copy successfully with Ctrl/Cmd+C. Confirm normal non-sticky dismissal returns after the temporary interaction, ordinary typing and existing shortcuts remain unchanged, and sticky=true behavior is preserved. Repeat on macOS and Windows/Linux, including the Cmd+C scenario from https://github.com/microsoft/vscode/issues/236583; establish automated controller/widget coverage for lock and release transitions.
- **Behavior:**

  > Users who disable sticky editor hovers must retain automatic mouse-triggered documentation without accidental hover interaction. Holding Alt/Option while a hover is visible should temporarily keep that hover available so the user can move into it, select or copy text, and activate links. Releasing the modifier must not leave a permanent lock or change the persisted setting. Acceptance includes preserving existing sticky-hover behavior and ensuring Ctrl/Cmd+C continues to copy selected hover text.
- **Trace:**

  > ContentHoverController._shouldKeepCurrentHover and ContentHoverWidgetWrapper._startShowingOrUpdateHover use the configured sticky boolean; modifier keydown currently does not establish a temporary lock. HoverService._keyDown/_keyUp in src/vs/platform/hover/browser/hoverService.ts already implement Alt locking for the separate workbench hover stack. The modifier-trigger mode introduced by https://github.com/microsoft/vscode/pull/274001 only gates appearance through hoverUtils.ts and is not equivalent to this request. Two attempted fixes were reverted; https://github.com/microsoft/vscode/pull/236586 reverted the later attempt because https://github.com/microsoft/vscode/issues/236583 reported broken Cmd+C copying. Preserve normal hover activation, persistent settings, selection, and shortcut dispatch; changing hiding-delay semantics is outside this request. The source establishes the missing capability, but its full keyboard and pointer interaction has not been exercised; the planning session should establish regression coverage before proceeding.

## Evidence

- **Current editor behavior:** src/vs/editor/contrib/hover/browser/contentHoverController.ts: _shouldKeepCurrentHover derives stickiness from _hoverSettings.sticky; _onKeyDown ignores modifier keys without establishing an Alt lock. In contentHoverWidgetWrapper.ts, _startShowingOrUpdateHover likewise reads EditorOption.hover.sticky and can clear the hover when the pointer has no valid anchor. These paths do not supply the requested temporary override.
- **Existing capabilities do not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.hover.enabled='onKeyboardModifier' and editor.hover.sticky separately. hoverUtils.ts gates appearance using the modifier opposite editor.multiCursorModifier, not temporary locking. editor.action.showHover in hoverActions.ts can focus a hover as a keyboard workaround, but does not provide the requested hold-Alt mouse interaction.
- **Workbench precedent:** src/vs/platform/hover/browser/hoverService.ts: _keyDown sets hover-stack entries' isLocked on Alt and _keyUp unlocks them. Editor content hovers use their own controller and widget path, explaining why the existing workbench capability does not fulfill this editor request.
- **Reverted fixes and reopen:** https://github.com/microsoft/vscode/pull/236356 was merged, then reverted by https://github.com/microsoft/vscode/pull/236586.
