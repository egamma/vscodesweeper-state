# Issue #291933 — Default Trusted folders on various platforms

[https://github.com/microsoft/vscode/issues/291933](https://github.com/microsoft/vscode/issues/291933)

## Summary

Keep open for the workspace-trust owner: automatically trusting home directories and web roots would change a security boundary. Existing parent-folder trust offers an explicit-consent workaround, but does not provide the requested platform defaults.

## Change summary

Automatically trust platform-specific home directories and web-development folders, including Linux Public folders and Windows Laragon/XAMPP web roots.

## Best solution

Have the workspace-trust owner decide whether any automatic trust defaults are appropriate, accounting for untrusted content stored beneath those paths. Preserve explicit folder consent unless that security decision is approved; the existing Manage Workspace Trust command already supports user-selected parent folders.

  > Thanks for the request. Today, Workspaces: Manage Workspace Trust (`workbench.trust.manage`) lets you add a folder explicitly, and trust also applies to its subfolders. That can reduce repeated prompts for a selected development root, but it is not automatic platform-wide trust. Default trust for home directories or web roots needs review by the workspace-trust owner because files placed anywhere beneath those directories would inherit trust.

- **current trust behavior:** src/vs/workbench/services/workspaces/common/workspaceTrust.ts:255–278 initializes an absent stored trust list to an empty list. doGetUriTrustInfo at lines 369–405 defaults ordinary local resources to untrusted and checks explicitly trusted ancestor URIs; it does not automatically approve the requested home directories or web roots.

This supports one-time parent-folder approval, not zero-configuration platform defaults.
