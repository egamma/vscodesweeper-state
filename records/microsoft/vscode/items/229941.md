# Issue #229941 — Editor `z-index` challenges

[https://github.com/microsoft/vscode/issues/229941](https://github.com/microsoft/vscode/issues/229941)

## Summary

This is a valid, team-authored debt/tracking issue for systematically organizing editor z-index values. The work remains undone — current editor CSS still has ad-hoc z-index values ranging from 1 to 10000 with no documented layering scheme, and spot fixes continue to land (e.g. minimap overlap, inline edit z-index removals). Keeping open.

## Change summary

Systematically document and assign z-index values across all editor features (minimap, scrollbar, sticky scroll, zone widgets, find widget, suggest widget, etc.) to eliminate stacking-order bugs.

## Best solution

Define a centralized z-index scale (e.g. CSS custom properties or a constants file) for all editor overlay features, document the intended stacking order, and migrate the ~22 CSS files under src/vs/editor/ that currently use ad-hoc z-index values. Issue https://github.com/microsoft/vscode/issues/198122 could be absorbed into this effort as a satellite.
