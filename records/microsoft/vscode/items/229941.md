# Issue #229941 — Editor `z-index` challenges

[https://github.com/microsoft/vscode/issues/229941](https://github.com/microsoft/vscode/issues/229941)

## Summary

This remains valid editor-core debt: current main still assigns independent hard-coded stacking values across editor features, and linked overlap bugs remain open. The issue should stay open while maintainers define the intended editor-wide stacking contract.

## Change summary

Inventory editor overlays and establish consistent relative stacking behavior for the minimap, scrollbars, sticky scroll, zone widgets, and other editor widgets.

## Best solution

Define and document an editor-wide stacking hierarchy, then align each widget with that contract and cover the known scrollbar, sticky-scroll, and zone-widget overlap scenarios against regressions.

- **Behavior:**

  > Editor overlays must have a documented, consistent relative order. The minimap, scrollbar, sticky scroll, zone widgets, suggestions, parameter hints, find UI, and inline-edit UI must remain usable when their bounds overlap, while editor-owned content must not cover workbench-level UI outside the editor. Acceptance should include the linked scrollbar, comments/peek, sticky-scroll, and editor-border overlap scenarios.
- **Trace:**

  > Current main distributes hard-coded z-index values across at least 23 files: minimap.css uses 5, stickyScroll.css uses 4, zoneWidget.css uses 10, parameterHints.css uses 39, and inline-edits view.css uses 34. There is no shared editor stacking inventory or contract visible in the source. https://github.com/microsoft/vscode/issues/198122 supplies two partial ordering constraints, while https://github.com/microsoft/vscode/issues/207734 demonstrates a still-open overlap defect. The boundary is editor and editor-contribution stacking behavior; do not alter unrelated workbench overlay ordering or use this cleanup to redesign individual widgets.
- **Open decisions:**
  - What is the complete user-visible ordering among sticky scroll, scrollbars and minimap, zone widgets, and transient editor widgets when their bounds overlap?
  - Which editor overlays, if any, may intentionally escape the editor stacking context to appear above workbench-level UI?
  - Should temporary interaction UI such as suggest, parameter hints, find, rename, and inline-edit controls share one ordering tier or have distinct precedence?
