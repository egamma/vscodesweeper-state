# Issue #256486 — Add a `contexts` field to the .md metadata for a custom chat mode

[https://github.com/microsoft/vscode/issues/256486](https://github.com/microsoft/vscode/issues/256486)

## Summary

A real gap remains: current custom-agent parsing does not provide a `contexts` field, and Markdown links in an agent body are not converted into attached arbitrary-file context. The request should stay open for a contract decision rather than closing based on the reporter's workaround.

## Change summary

Allow a custom agent file to declare files, folders, or built-in context sources that are automatically attached to every request using that agent.

## Best solution

Define a supported custom-agent context contract that resolves declared resources predictably and attaches them to each request, with explicit semantics for path bases, folders, built-in contexts, missing resources, and token usage.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/service/promptsService.test.ts`
- **Validation:** Extend the prompt/custom-agent unit suites and run `scripts/test.sh --grep "PromptFileParser|ComputeAutomaticInstructions"`; acceptance requires a declared file to become request context for the selected custom agent while agents without declared context remain unchanged.
- **Behavior:**

  > A custom agent can declare reusable context resources that are attached whenever that agent handles a request. Relative paths resolve according to one documented rule, and missing or unsupported entries produce visible diagnostics rather than being silently ignored. Agents without declared contexts behave unchanged. Tests must demonstrate that a referenced workspace file reaches request context without the user attaching it manually.
- **Trace:**

  > Current metadata parsing lives in `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, while `CustomAgent.fromParsedPromptFile` in `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts` reduces an agent to textual instructions and tool references. Although `PromptBody.fileReferences` recognizes Markdown links, those references are not represented by `IChatModeInstructions` in `src/vs/workbench/contrib/chat/common/chatModes.ts`. Automatic reference traversal in `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts` starts from attached instruction variables rather than the selected agent body. The boundary is custom-agent request context: ordinary Markdown rendering, prompt-file behavior, and agents without declared context must remain unchanged. The narrower related symptom is tracked at https://github.com/microsoft/vscode/issues/336180.
- **Open decisions:**
  - Should relative paths be resolved from the custom-agent file's directory or from each workspace root?
  - Does the contract support only concrete files, or also folders and symbolic context sources such as the codebase?
  - Are declared resources eagerly attached on every request, or exposed as references that the agent reads on demand?

## Evidence

- **missing schema:** On current main, `PromptHeaderAttributes` in `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts` defines supported custom-agent metadata such as `tools`, `model`, and `context`, but no `contexts` collection matching this request.
- **agent conversion:** `CustomAgent.fromParsedPromptFile` in `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts` converts the agent body into `agentInstructions` containing only body content, tool references, and metadata; parsed `body.fileReferences` are not carried into the agent's request instructions.
- **link limitation:** `ComputeAutomaticInstructions` in `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts` follows references from instruction files already attached to the request, not from the selected custom agent body. Consequently, a Markdown link does not establish the requested general-purpose automatic attachment of an arbitrary `.sql` file.
- **related narrower report:** https://github.com/microsoft/vscode/issues/336180 is a newer open report showing the same limitation for `.agent.md` links to `.instructions.md`. It is narrower and younger than this re-reviewed issue, so it is related evidence rather than a valid canonical duplicate.
- **reporter workaround:** The reporter suggested closing after discovering Markdown-link syntax in https://github.com/microsoft/vscode/issues/256486#issuecomment-3376812235, but current request assembly does not show that an agent-body link automatically attaches arbitrary linked file contents.
