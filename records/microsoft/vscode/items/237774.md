The reported failure is a stale match count after enabling Find in Selection and changing the selected lines; extensions were disabled.
- **Current-source defect:** src/vs/editor/contrib/find/browser/findState.ts:254-263 still uses an inverted range comparison in FindReplaceState.change(). With one existing scope A and a different incoming scope B, !Range.equalsRange(A, B) makes the every/some expression true, so the enclosing negation prevents assigning B or emitting searchScope: true. src/vs/editor/contrib/find/browser/findModel.ts:156-173 relies on that event to research the new scope.

These paths substantiate stale-scope behavior without executing the application; the separate selection-loss symptom was not conclusively verified.
