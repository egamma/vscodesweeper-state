## Evidence

- **smooth-scroll gate:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts line ~545: smooth scrolling on wheel input only runs when `classifier.isPhysicalMouseWheel()` returns true; otherwise `setScrollPositionNow` (instant jump) is used.
- **classifier heuristic:** `MouseWheelClassifier._computeScore` (same file, ~line 146) scores each wheel event based on integer-ness of deltas and whether they are 'the same modulo' as the previous event — a heuristic that can misclassify a real mouse as a touchpad depending on exactly what deltaX/deltaY values the OS/compositor reports.
- **prior related fix:** https://github.com/microsoft/vscode/issues/182499 (closed, fixed by https://github.com/microsoft/vscode/pull/205122 in 2024) was a different symptom (disabling smoothScrolling wasn't respected on Wayland) caused by the same classifier logic; that confirms this heuristic is fragile across Linux input backends, but does not by itself prove today's report is the same root cause.
- **reporter evidence:** Reporter provided clear steps, VS Code 1.135.0, GNOME/Wayland (and claims reproduction on X11 too), and side-by-side videos vs. Windows, but no wheel-delta diagnostics.
