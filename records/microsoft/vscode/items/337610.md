## Change summary

Ctrl+F search in a Markdown Preview tab does not find/highlight matches once the preview has been dragged out into its own separate VS Code window.

## Evidence

- **code path candidate:** getActiveWebviewEditor() in src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts resolves the webview from the global IEditorService.activeEditor, and the show-find keybinding is gated on the `activeEditor` context key (src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts:19,30) — plausible but unconfirmed source of cross-window mismatch.
- **reparenting logic exists:** src/vs/workbench/contrib/webview/browser/webviewElement.ts `mountTo`/`_registerMessageHandler` explicitly handle moving a webview's iframe and message listeners to a new `targetWindow`, showing multi-window webview support is deliberate, non-trivial, and a plausible source of edge-case bugs like this.
