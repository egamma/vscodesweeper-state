# Issue #310887 — Remote SSH + Remote Tunnel = Failed tunnel on wrong machine

[https://github.com/microsoft/vscode/issues/310887](https://github.com/microsoft/vscode/issues/310887)

## Summary

The tunnel CLI singleton lock file (`tunnel-stable.lock`) is not cleaned up after a failed tunnel launch, causing subsequent tunnel attempts to fail with 'Access is denied' errors in an infinite retry loop. The reporter self-resolved by manually deleting the stale lock file. The underlying robustness issue remains on current main.

## Change summary

When a tunnel setup fails, a stale singleton lock file is left behind, preventing future tunnel launches until the file is manually deleted.

## Best solution

Harden the singleton acquisition in `cli/src/singleton.rs` and the retry loop in `cli/src/commands/tunnels.rs` to detect stale lock files — e.g. check if the PID recorded in the lock file is still alive, and if not, remove the lock and re-acquire. The current code retries indefinitely without any stale-lock detection.
