# Issue #344441 — ctrl+down arrow is given as a hint to open the terminal but does not do that

[https://github.com/microsoft/vscode/issues/344441](https://github.com/microsoft/vscode/issues/344441)

## Summary

Keep open: current source can advertise the accessibility-only terminal shortcut in an ordinary toolbar hover, although pressing it in an editor scrolls instead. No issue-referencing fix or verified duplicate was found; this team-authored report remains actionable.

## Change summary

Ensure the terminal hover does not advertise Ctrl+Down as a generally available terminal-opening shortcut.

## Best solution

Make the terminal entry's shortcut hint accurately reflect its availability without broadening the accessibility keybinding or overriding ordinary editor scrolling.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/344441 reports a Terminal hover advertising Ctrl+Down; its dispatch log explicitly resolves that combination to scrollLineDown under textInputFocus.
- **Terminal shortcut scope:** src/vs/workbench/contrib/terminal/browser/terminalActions.ts registers workbench.action.terminal.focus on Ctrl+Down only with accessibility mode enabled, the accessible view on its last line, and the Terminal accessible provider active. It is not a general editor-to-terminal shortcut.
- **Current hover path:** src/vs/sessions/contrib/terminal/browser/sessionsTerminalContribution.ts contributes a Terminal activity-bar entry using workbench.action.terminal.focus. SessionActivityBarActionViewItem.getTooltip in src/vs/sessions/browser/parts/sessionActivityBar.ts delegates to MenuEntryActionViewItem.getTooltip, which calls appendKeybinding without enforcing context validity.
- **Source diagnosis:** src/vs/platform/keybinding/common/abstractKeybindingService.ts defaults enforceContextCheck to false. KeybindingResolver.lookupPrimaryKeybinding in src/vs/platform/keybinding/common/keybindingResolver.ts returns a sole binding without checking its when clause, or falls back to the last binding when none matches. Consequently, the terminal hover can display the accessibility-only binding outside its activation context.
- **Normal editor behavior:** src/vs/editor/browser/coreCommands.ts registers scrollLineDown on Ctrl+Down with textInputFocus, matching the reporter's log when the terminal accessibility conditions are false.
- **Fix and canonical checks:** Issue-number commit search found no reference to 344441, and GitHub reports no linked closing PR. Searches for terminal shortcut/hover/hint and scrollLineDown found no matching canonical. https://github.com/microsoft/vscode/issues/3130 concerns mouse-shortcut customization; https://github.com/microsoft/vscode/issues/23991 concerns Linux setxkbmap mappings, not this hover.
