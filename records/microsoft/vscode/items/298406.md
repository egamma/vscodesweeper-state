# Issue #298406 — Add Remote Control Support to GitHub Copilot Chat

[https://github.com/microsoft/vscode/issues/298406](https://github.com/microsoft/vscode/issues/298406)

## Summary

Partially implemented: the Copilot CLI harness already supports a `/remote` command with on/off/status and QR-code pairing (via Mission Control), but the broader ask — remote control across all Copilot Chat session types and from GitHub Mobile / any browser — remains an open feature request with strong community traction (42 upvotes, well above the 20-upvote Backlog threshold).

## Change summary

Allow users to connect to an ongoing local Copilot Chat session from a mobile device or browser, keeping messages in sync across surfaces.

## Best solution

The Copilot CLI harness already ships `/remote` (enable/disable/status with QR code). The remaining work is (1) surfacing remote-control support in additional agent harnesses — the Codex protocol types exist (`RemoteControlEnableResponse`, etc.) but are explicitly ignored in `codexAgent.ts` — and (2) building or integrating the mobile/browser companion surface. Issue https://github.com/microsoft/vscode/issues/316946 is a closely related but narrower request (mobile companion UX specifically); the two should be linked but are not strict duplicates since this issue covers the full remote-control lifecycle. Keep open for the agent-experience team to scope the remaining harness and companion work.

- **Evidence:** Aligns with current agent-host and agents-window priorities; the Copilot CLI harness already ships the `/remote` command as a first step.
