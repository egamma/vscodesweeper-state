# Issue #336175 — Product icon font does not scale in smart completion popups with editor/terminal zoom

[https://github.com/microsoft/vscode/issues/336175](https://github.com/microsoft/vscode/issues/336175)

## Summary

Confirmed from source: both the editor and terminal suggest widgets hardcode icon dimensions (`.icon { height: 16px; width: 16px }`) and the shared codicon glyph (`.codicon[class*='codicon-'] { font: normal normal normal 16px/1 codicon }`) at a fixed 16px, while the widget root's font-size is set dynamically from editor/terminal zoom — so text scales but icons stay fixed, causing the clipping/mismatch the reporter shows.

## Change summary

Product icons (codicons) in the editor and terminal smart-completion popups do not scale with editor/terminal zoom, unlike the completion text.

## Best solution

Make the `.icon`/`.suggest-icon` box sizing and the codicon glyph font-size relative (e.g. `1em`/`16px` derived from the widget's own font-size) instead of a hardcoded 16px, in both suggest.css copies (editor and terminal/simple-suggest) so icons track the dynamically-set root font-size the same way text does.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/suggest/browser/media/suggest.css`, `src/vs/workbench/services/suggest/browser/media/suggest.css`, `src/vs/base/browser/ui/codicons/codicon/codicon.css`
- **Validation:** Manually zoom the editor (editor.action.fontZoomIn) and terminal (workbench.action.terminal.fontZoomIn) with a completion/suggest popup open, and confirm the icon glyph and its container scale in proportion to the popup text instead of staying fixed at 16px.
- **Trace:**

  > The suggest/completion widgets (editor: src/vs/editor/contrib/suggest/browser; terminal: src/vs/workbench/services/suggest/browser) dynamically set the popup root's font-size from the current editor/terminal zoom level in suggestWidgetRenderer.ts / simpleSuggestWidgetRenderer.ts. Text elements inherit and scale from that root font-size, but `.icon` boxes are hardcoded to 16x16px in both suggest.css files, and the shared `.codicon` glyph font in src/vs/base/browser/ui/codicons/codicon/codicon.css is hardcoded to `16px/1`, so icons never scale — matching the reporter's screenshot of cut-off/misaligned icons. Boundary: codicon.css is used product-wide, so any fix must not globally change icon sizing outside suggest widgets without a decision on scope; the exact handling of the separately reported 'Insert (↵)' hint text also needs confirming before implementation.
- **Open decisions:**
  - Should codicon glyph sizing be made relative (em-based) globally, or should the suggest widgets override codicon font-size locally to avoid unintended effects elsewhere in the product?
  - Should the `.icon` background-image box scale in lockstep with the codicon glyph, and via what mechanism (CSS custom property tied to the dynamically-set root font-size, or a JS-computed inline style)?
  - Does the 'Insert (↵)' hint text scaling issue share the same root cause, or does it need a separate fix?
