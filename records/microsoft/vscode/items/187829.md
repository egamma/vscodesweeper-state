# Issue #187829 — vscode does not automatically open closed repos when a file is opened

[https://github.com/microsoft/vscode/issues/187829](https://github.com/microsoft/vscode/issues/187829)

## Summary

Keep open for a decision on optional file-triggered reopening. Current VS Code improves manual reopening discoverability, but still does not provide the requested automatic behavior; this accepted Backlog item should not be declined as designed.

## Change summary

Allow users to reopen manually closed Git repositories automatically when opening a file inside them, without navigating a repository picker.

## Best solution

Decide whether to offer opt-in file-triggered reopening in the built-in Git extension while preserving persistent manual closure as the default. The existing reopen action addresses discoverability, not the reporter's workflow of temporarily hiding inactive repositories.

- **Behavior:**

  > Users managing many repositories want closure to temporarily declutter source control, with a repository returning when they open one of its files. The current manual reopen picker and title-bar action do not deliver that automatic workflow. A maintainer must decide whether to support an opt-in alternative while retaining the established persistent-closure default. Acceptance should distinguish file-triggered reopening from background discovery and verify both policies across window reloads.
- **Trace:**

  > In extensions/git/src/model.ts, Model.onDidChangeVisibleTextEditors honors git.autoRepositoryDetection and calls Model.openRepository, whose default openIfClosed=false causes the persisted closed-repository guard to stop discovery. ClosedRepositoriesManager stores closedRepositories in workspaceState, and Model.close records explicit closure. In extensions/git/src/commands.ts, git.reopenClosedRepositories already bypasses this guard intentionally; extensions/git/package.json exposes it in the Source Control Repositories title bar. https://github.com/microsoft/vscode/pull/184708 and https://github.com/microsoft/vscode/issues/186155 establish the persistent-closure baseline. Preserve trust checks, ignored-repository handling, existing discovery settings, and explicit manual reopening. The unresolved question is the supported user-visible reopening policy, not where to place a guard or which helper to use.
