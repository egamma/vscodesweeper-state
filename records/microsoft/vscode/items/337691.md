# Issue #337691 — New windows are blank after VS Code package is upgraded while an older instance is running on Linux

[https://github.com/microsoft/vscode/issues/337691](https://github.com/microsoft/vscode/issues/337691)

## Summary

Detailed, plausible report (deleted-binary /proc evidence, screenshot, confirmed on latest 1.139.0), but the failure depends on exact apt-upgrade timing versus window creation and I can't confirm the specific failing path from source alone — asking for the blank window's DevTools console output and main.log around the failure would let a maintainer actually pin this down instead of leaving it as a vague open report.

## Change summary

When the vscode apt package is upgraded on disk while an existing instance keeps running, opening a new window (via Ctrl+Shift+N or `code`) through that running instance renders a blank, totally unresponsive window instead of a working editor.

## Best solution

Root-cause where the main process fails to render a new window after the on-disk resources have been replaced (likely a stale renderer bundle/asar mismatch or IPC failure between the old in-memory main process and the new-window bootstrap) — likely candidates are src/vs/code/electron-main/app.ts (second-instance window creation) and src/vs/platform/launch/electron-main/launchMainService.ts (second-instance argv handling); if confirmed, either detect the mismatch and show the existing 'reload/relaunch' style notification instead of a dead window, or otherwise fail gracefully.
