- **Behavior:**

  > After apt upgrades VS Code while an older instance remains running, requesting a new window must not leave an empty, unusable window. Acceptance must include preserving those edits and a defined, usable outcome for the new-window request.
- **Trace:**

## Evidence

Extensions are disabled; existing windows continue working, and --user-data-dir=/tmp/vscode-test-instance succeeds. The reporter reaffirmed the upgraded versions in the September 24 follow-up.
- **Installation replacement evidence:** The issue includes /proc/87005/exe pointing to '/usr/share/code/code (deleted)', establishing that the surviving process uses a replaced executable. These paths explain why a surviving process can encounter replaced installation resources, but do not conclusively reproduce a blank window.

Source inspection alone cannot verify the behavior of the installed executable and Electron renderer after that replacement.
