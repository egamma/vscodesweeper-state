# Issue #309782 — Infinite marker re-registration loop in clearAllMarkers causes UnresponsiveSampleError

[https://github.com/microsoft/vscode/issues/309782](https://github.com/microsoft/vscode/issues/309782)

## Summary

Keep open: independent reports confirm renderer freezes and crashes, including the original marker-clearing stack on 1.141.0. Current source still synchronously recreates disposed start markers while the tracker is active; stopping tracking before command submission does not protect every active-tracker window.

## Change summary

Prevent the chat terminal tool's start-marker recreation from causing an unbounded disposal cascade during terminal buffer clearing.

## Best solution

Make the shared start-marker tracker safe during marker disposal and buffer transitions while preserving transient-prompt recovery and command-output boundaries. Cover alternate-buffer teardown with a bounded regression test; investigate the reported scrollback-trimming entry point without assuming it has the identical cause.
