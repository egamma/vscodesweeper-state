# Issue #331568 — A pasted image renders as a broken thumbnail when its attachment has no contentType

[https://github.com/microsoft/vscode/issues/331568](https://github.com/microsoft/vscode/issues/331568)

## Summary

Confirmed defect on main: `attachment.contentType.startsWith('image/')` is dereferenced unguarded in four places, and an attachment record lacking `contentType` throws instead of rendering. An open PR (#331569) already targets this exact fix, so this should stay open and land via that PR rather than being closed or auto-fixed here.

## Change summary

A restored chat attachment whose stored record has no `contentType` field throws in `.startsWith('image/')` and renders as a broken thumbnail instead of the image.

## Best solution

Land the linked PR https://github.com/microsoft/vscode/pull/331569 ("Render an embedded attachment that has no content type"), which should guard all four dereference sites (stateToProgressAdapter.ts, codexPromptResolver.ts x2, claudeClientToolResult.ts / copilotAgentSession) against a missing contentType and fall back to a sane default so legacy on-disk records render instead of throwing.
