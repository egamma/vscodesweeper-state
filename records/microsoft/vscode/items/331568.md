# Issue #331568 — A pasted image renders as a broken thumbnail when its attachment has no contentType

[https://github.com/microsoft/vscode/issues/331568](https://github.com/microsoft/vscode/issues/331568)

## Summary

Confirmed on main: `stateToProgressAdapter.ts` dereferences `attachment.contentType.startsWith('image/')` without a null guard, so an embedded resource attachment persisted without `contentType` throws and renders as a broken thumbnail. A fixing PR is already open, so this should stay open until it merges.

## Change summary

Attachments restored from a session database that lack a `contentType` field crash the restore path and render as a broken image instead of the actual thumbnail.

## Best solution

Land the guard in the already-open fix PR (https://github.com/microsoft/vscode/pull/331569), which addresses the unguarded `contentType` dereference across `stateToProgressAdapter.ts`, `codexPromptResolver.ts`, and `copilotAgentSession`.
