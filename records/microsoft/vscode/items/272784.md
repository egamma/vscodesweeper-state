# Issue #272784 — Allow webviews and custom editors to customize tab tooltips

[https://github.com/microsoft/vscode/issues/272784](https://github.com/microsoft/vscode/issues/272784)

## Summary

Keep open: the current API still cannot set a webview tab tooltip independently of its title. Custom editors already show a resource path when no custom title is supplied, but supplying a title replaces that tooltip too; no verified open canonical covers this same request.

## Change summary

Allow extensions to customize webview and custom-editor tab tooltips independently of tab titles, and consider a resource-path default for custom editors.

## Best solution

Provide an independently configurable tab-tooltip contract for WebviewPanel that also works for custom editors. Settle the custom-editor fallback behavior through API review, preserving existing tab-title customization.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostWebviewPanels.ts`, `src/vs/workbench/api/browser/mainThreadWebviewPanels.ts`, `src/vs/workbench/contrib/webviewPanel/browser/webviewEditorInput.ts`, `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts`
- **Validation:** Use the webview and custom-editor extension samples with a short title and a distinct long tooltip; verify tab hover shows the tooltip without changing the title, dynamic updates work, clearing the override uses the agreed fallback, and existing title-only extensions retain the agreed compatibility behavior.
- **Behavior:**

  > Extensions should be able to display contextual information in a webview or custom-editor tab tooltip independently of the short tab title. Updating either value must not unintentionally overwrite the other. Acceptance checks should cover ordinary webviews, resource-backed custom editors, dynamic updates, and clearing an override. The default tooltip for custom editors with an extension-provided title remains a product decision.
- **Trace:**

  > WebviewPanel currently exposes title but no tooltip in src/vscode-dts/vscode.d.ts. Title updates pass through ExtHostWebviewPanel and MainThreadWebviewPanels.$setTitle to WebviewInput.setWebviewTitle; WebviewInput.getTitle returns the same name used for the tab. CustomEditorInput.getTitle returns the extension-provided title before considering its existing URI-label fallbacks. The related title-customization work at https://github.com/microsoft/vscode/issues/105299 does not supply independent tooltip control. Preserve custom-editor save, undo, resource identity, and title customization; the review did not establish tooltip serialization or restoration semantics.
- **Open decisions:**
  - For a resource-backed custom editor with a custom title but no explicit tooltip, should the tooltip continue repeating that title or default to the resource path?
  - Should an explicitly configured tooltip survive editor restoration, or must the extension reapply it when restoring the panel?
