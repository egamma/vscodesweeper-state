# Issue #312053 — AgentHost: Drive TODOs UI

[https://github.com/microsoft/vscode/issues/312053](https://github.com/microsoft/vscode/issues/312053)

## Summary

Keep open: current Agent Host tool adaptation does not populate the native TODO checklist, and the discussion establishes maintainer demand. This remains the older tracking request; newer missing-checklist reports do not justify closing it as a duplicate.

## Change summary

Expose Agent Host task progress through VS Code's existing TODO checklist instead of relying on extension-host SQL interception.

## Best solution

Provide an interoperable, structured TODO projection into the existing chat checklist, keeping task status consistent across subsequent messages. Coordinate the protocol contract with the open Codex TODO proposal rather than developing competing shared infrastructure.

- **Likely files:** `src/vs/platform/agentHost/common/agent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/chat/common/tools/chatTodoListService.ts`
- **Validation:** In an Agent Host Copilot chat with chat.tools.todos.showWidget enabled, create pending TODOs, mark one active and then completed, and verify the native checklist reflects each change and remains visible when sending a subsequent message. Exercise reload/reconnect according to the agreed persistence contract, and cover the chosen structured-data adapter with focused unit tests, including hosts that omit optional TODO support.
- **Behavior:**

  > Agent Host task planning should drive the same native TODO checklist used by other chat flows. Creating tasks and changing their statuses should update the visible titles, statuses, and progress count without requiring users to inspect SQL tool output. Sending another message should not temporarily discard an unchanged checklist. Acceptance must also establish the intended reload/reconnect behavior and preserve ordinary chat behavior for hosts without TODO support.
- **Trace:**

  > The native checklist consumes IChatTodoListService, and ChatToolInvocationPart populates it when toolSpecificData.kind is 'todoList'. Current Agent Host stateToProgressAdapter.ts does not produce that data for its completed tool-call path, and agentHostSessionHandler.ts has no TODO projection. CopilotAgentSession.getSessionPlan already reads structured SQL rows and dependencies, but the inspected exposure is for Mission Control rather than the native checklist. The uncertainty begins at how authoritative TODO snapshots are published and restored through an interoperable host/client contract, not at widget visibility. Preserve advertised chat identities, tolerate absent optional support, and do not change SQL execution semantics or unrelated tool rendering. Coordinate shared protocol work with https://github.com/microsoft/vscode/pull/332099; the subsequent-message symptom is recorded in https://github.com/microsoft/vscode/issues/317126.
- **Open decisions:**
  - Should the Agent Host checklist restore authoritative TODO state after reconnect or window reload, or initially support only live updates retained across messages?
