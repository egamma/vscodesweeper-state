# Issue #342857 — Chat history rename does not persist when switching tabs or reloading the window

[https://github.com/microsoft/vscode/issues/342857](https://github.com/microsoft/vscode/issues/342857)

## Summary

Verified duplicate of the open chat-title persistence report: both describe a custom name appearing saved and reverting when the conversation is reopened. Consolidate this report's reload sequence and Windows/SSH environment into the existing issue.

## Change summary

Preserve manually renamed chat conversation titles across selection changes, reopening, and window reloads.

## Best solution

Track the persistence fix in https://github.com/microsoft/vscode/issues/316994 so renaming an unloaded conversation updates the title used when its full session is restored, not only its history entry.

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/316994 is open and was created on 2026-05-18. Its full report describes renaming an existing conversation, navigating away, and reopening it to find the previous or generated title restored—the same observable failure as this report.
- **Discussion confirms the persistence boundary:** https://github.com/microsoft/vscode/issues/316994#issuecomment-5215239432 independently confirms the problem and reports that renaming while the conversation is loaded, with its history list visible, persists correctly. https://github.com/microsoft/vscode/issues/316994#issuecomment-5215318536 agrees with that workaround; https://github.com/microsoft/vscode/issues/316994#issuecomment-5713327971 adds another confirmation.
- **Current-source failing path:** In src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts, setChatSessionTitle updates customTitle only if the session model is loaded, then calls ChatSessionStore.setSessionTitle. In src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts:510-517, that method changes only the index title. saveState writes session content only for live models, leaving an unloaded session's serialized customTitle unchanged.
- **Selection explains the title reversal:** ChatService.getSessionTitle uses the index title before loading, but prefers the model title afterward. acquireOrRestoreLocalSession reads the serialized session, and ChatModel initializes _customTitle from initialData.customTitle in src/vs/workbench/contrib/chat/common/model/chatModel.ts:3159. Thus an unloaded conversation can show its renamed index title after reload and revert to its old serialized title when opened, matching the reported trigger.
- **Additional evidence to retain:** https://github.com/microsoft/vscode/issues/342857 supplies a concrete reload-then-select sequence on VS Code 1.142.0, Windows 11 x64 with a Linux Remote-SSH workspace. This extends the canonical's environment evidence without establishing a separate defect.
