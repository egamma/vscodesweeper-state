# Issue #331289 — Agent host: after a client reconnects, new client tool calls are still attributed to the disconnected client and fail immediately

[https://github.com/microsoft/vscode/issues/331289](https://github.com/microsoft/vscode/issues/331289)

## Summary

Keep open: current source retains the reported stale-owner selection mechanism, but the lifecycle transition that leaves a departed contributor registered has not been conclusively established on unmodified main. The report supplies sufficient steps and logs to retest despite subsequent lifecycle changes; the proposed fix PR closed without merging.

## Change summary

After a client reconnects with a new identity, newly created client-tool calls can retain the departed client's identity and repeatedly fail despite a live replacement.

## Best solution

Ensure reconnect reconciliation keeps the provider's tool registry consistent with active clients, so subsequent calls reach a live contributor without separating tool ownership from the advertised description and schema. Establish the failing lifecycle sequence on unmodified main before choosing the repair; changing every shared tool's ownership to newest-client-wins would alter existing multi-client behavior.
