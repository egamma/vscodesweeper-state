# Issue #331289 — Agent host: after a client reconnects, new client tool calls are still attributed to the disconnected client and fail immediately

[https://github.com/microsoft/vscode/issues/331289](https://github.com/microsoft/vscode/issues/331289)

## Summary

Well-diagnosed, source-confirmed bug in the Claude client-tool ownership model, and there's already an open fixing PR referencing this exact defect — keeping open so the PR can land rather than closing or auto-fixing over it.

## Change summary

After a client reconnects with a new clientId, later client-tool calls stay permanently attributed to the disconnected client and fail forever, because ActiveClientToolSet.ownerOf falls back to first-inserted-contributor and the stale entry is never pruned.

## Best solution

Land https://github.com/microsoft/vscode/pull/331300 ("Resolve a client tool to the client that is still there"), which appears to address exactly this by passing/using a preferred/live clientId in ownerOf and/or fixing removeActiveClient's guard so the stale registry entry gets pruned on disconnect.
