# Issue #331289 — Agent host: after a client reconnects, new client tool calls are still attributed to the disconnected client and fail immediately

[https://github.com/microsoft/vscode/issues/331289](https://github.com/microsoft/vscode/issues/331289)

## Summary

Well-traced defect in the agent host's client-tool attribution after a reconnect, confirmed against current source, and an open PR (#331300) already targets the exact fix — the issue should stay open until that PR lands, not be closed preemptively.

## Change summary

After a client reconnects with a new clientId, subsequent calls to a client-contributed tool (e.g. integrated browser) keep being routed to the disconnected client and fail permanently instead of routing to the still-active client that provides the same tool.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/331300, which is titled to resolve exactly this ('Resolve a client tool to the client that is still there'); also verify the related design gap tracked in https://github.com/microsoft/vscode/issues/330899 about client tools executing off the stream-mapper ready state rather than SDK invocation, since both affect the same attribution path.
