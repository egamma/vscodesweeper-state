# Issue #172210 — Remove extension host start delay

[https://github.com/microsoft/vscode/issues/172210](https://github.com/microsoft/vscode/issues/172210)

## Summary

The normal desktop extension-host startup path still uses an idle callback with a 50 ms timeout. Keep this open to investigate the performance regression that caused the original removal to be reverted; the pre-reopen merged PR does not establish completion.

## Change summary

Remove the historical extension-host startup deferral without regressing workbench startup performance.

## Best solution

Establish why earlier extension-host initialization regressed the performance bot, then eliminate unnecessary scheduling delay while preserving initial rendering and extension-dependent editor restoration.

Removing unnecessary deferral must preserve initial workbench responsiveness and successful restoration of editors requiring extensions. - **Trace:**

## Evidence

The 50 ms argument is an idle-callback timeout, not an unconditional 50 ms sleep; the scheduling deferral remains.
