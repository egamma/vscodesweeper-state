# Issue #318168 — VS Code 1.121.0: Open Chat (Plan) keybinding no longer works (`workbench.action.chat.openPlan`)

[https://github.com/microsoft/vscode/issues/318168](https://github.com/microsoft/vscode/issues/318168)

## Summary

The regression remains on current main: custom-mode commands are derived only from the last-focused chat widget and are removed when no widget supplies modes, so `workbench.action.chat.openPlan` is not a stable, discoverable keybinding command. The later chat-tip fix prevents one dead-link path but explicitly does not restore the command's former global availability.

## Change summary

Restore a reliable and discoverable keyboard shortcut contract for opening Chat directly in Plan mode.

## Best solution

Ensure users can bind and invoke Plan mode before focusing Chat, either by preserving the former `workbench.action.chat.openPlan` compatibility command or by providing an explicit migration to the stable `workbench.action.chat.open` command with `{ "mode": "Plan" }` arguments.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts`
- **Validation:** Add a chat action-registration test that starts with Plan available but no focused chat widget, verifies the supported Plan-opening command is discoverable and executable, and verifies it remains usable after focus leaves the widget.
- **Behavior:**

  > A user can configure a keyboard shortcut that opens Chat directly in Plan mode without first focusing a chat widget. The supported command is visible in Keyboard Shortcuts whenever Plan mode is available, and the binding does not become an unknown command after Chat loses focus. Existing Ask, Agent, Edit, and generic `workbench.action.chat.open` behavior must remain unchanged.
- **Trace:**

  > The regression was introduced by https://github.com/microsoft/vscode/pull/316273: `ChatAgentActionsContribution` moved from persistent local-mode registration to `chatWidgetService.lastFocusedWidget?.input.currentChatModesObs`. In current `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `_syncModeActions(undefined)` disposes all custom-mode actions, while `ModeOpenChatGlobalAction` in `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts` derives IDs such as `workbench.action.chat.openPlan` from the mode name. The generic `workbench.action.chat.open` path accepts a mode argument and remains functional. https://github.com/microsoft/vscode/pull/328262 fixed only the onboarding tip's dead command link and should not be treated as resolving configured keybindings. Preserve session-specific mode semantics and avoid changing built-in Ask, Agent, and Edit command registration; the uncertainty is the public compatibility contract for custom-mode commands.
- **Open decisions:**
  - Should `workbench.action.chat.openPlan` remain a stable global command for backward-compatible keybindings, or should the parameterized `workbench.action.chat.open` command become the sole supported contract with an explicit compatibility or migration path?

## Evidence

- **source reproduction:** On current main, `ChatAgentActionsContribution` in `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts` reads modes from `chatWidgetService.lastFocusedWidget`; `_syncModeActions(undefined)` disposes every dynamic mode action. Thus `workbench.action.chat.openPlan` is absent before a qualifying widget is focused and can disappear again afterward.
- **regression commit:** https://github.com/microsoft/vscode/pull/316273, merged as https://github.com/microsoft/vscode/commit/f1b1bdf69950042e562b94209c0a357cfb97650d, changed custom-mode action registration from persistent local modes to the focused widget's session-scoped modes and introduced the clearing path.
- **independent confirmation:** A second reporter confirmed the same failure on VS Code 1.125.1 for macOS, while the original report demonstrates that the stable `workbench.action.chat.open` command with a Plan-mode argument still works.
- **continuing impact:** Telemetry comments on https://github.com/microsoft/vscode/issues/318168 report the missing `workbench.action.chat.openPlan` command through 1.131.0-insider across Windows, macOS, and Linux.
- **later fix is narrower:** https://github.com/microsoft/vscode/pull/328262 only changed the Plan onboarding tip to use the stable parameterized command and guard dynamic commands; its description explicitly retains focused-widget-dependent registration, so it does not restore the Keyboard Shortcuts entry or existing user bindings reported here.
- **canonical search:** The matching telemetry issues https://github.com/microsoft/vscode/issues/313734 and https://github.com/microsoft/vscode/issues/328231 are closed and concern clicking a chat-tip link rather than the same Keyboard Shortcuts regression; no older open issue with the same observable symptom was found.
