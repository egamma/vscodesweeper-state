# Issue #60697 — Can't Install local user update due to `\\bin` folder being used by another process

[https://github.com/microsoft/vscode/issues/60697](https://github.com/microsoft/vscode/issues/60697)

## Summary

Still reproduces in 2026 — external processes (Skype, f.lux, SkypeBridge, etc.) hold file handles on VS Code's bin directory, blocking the inno_updater from completing. Recent issue #308524 confirms the same class of file-lock failure persists on current builds. The canonical sibling #52855 tracks the broader data-loss aspect; this issue focuses specifically on the bin-directory lock. Both remain valid.

## Change summary

Windows user-setup update fails because external processes hold a lock on the `\bin` directory, preventing deletion during the update sequence.

## Best solution

The inno_updater (now v0.21.0) should enumerate and identify the locking process before attempting deletion, either waiting longer with exponential backoff, or reporting the offending process to the user so they can close it. The update sequence should also ensure rollback safety so a failed delete never leaves the installation in a broken state (tracked more broadly by https://github.com/microsoft/vscode/issues/52855).
