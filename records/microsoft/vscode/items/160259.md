# Issue #160259 — Structural diff that understands syntax

[https://github.com/microsoft/vscode/issues/160259](https://github.com/microsoft/vscode/issues/160259)

## Summary

Keep open: current diff options provide whitespace filtering and move detection, but do not cover syntax-aware structural comparison. No verified older canonical owns the full request; the existing diff-editor routing and Backlog placement remain appropriate.

## Change summary

Offer syntax-aware structural diffs that emphasize meaningful code changes and suppress formatting-only differences.

## Best solution

Design an optional syntax-aware comparison mode for the standard diff editor, preserving textual comparison as the fallback. Establish supported languages and the treatment of syntax-significant whitespace before choosing an implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/browser/widget/diffEditor/diffProviderFactoryService.ts`, `src/vs/editor/common/services/editorWebWorker.ts`, `src/vs/editor/common/diff/documentDiffProvider.ts`, `src/vs/editor/test/node/diffing/fixtures.test.ts`
- **Validation:** The plan should define executable diff fixtures containing formatting-only reflow, a real code change mixed with reformatting, syntax-significant whitespace, and unsupported or invalid syntax. Verify the chosen mode suppresses only agreed formatting differences, retains meaningful changes, preserves textual fallback, and stays within an agreed computation-time budget; run the existing diff fixture suite when implementing.
- **Behavior:**

  > Developers should be able to compare code structurally in the standard diff editor so formatting-only changes do not obscure meaningful edits. Actual code changes must remain visible, including whitespace that affects the language's syntax. Acceptance cases should cover reformatting alone, reformatting mixed with a code edit, and unsupported or invalid syntax. Existing textual comparison must remain available.
- **Trace:**

  > The current worker comparison path in src/vs/editor/common/services/editorWebWorker.ts extracts line arrays and delegates to ILinesDiffComputer; the default implementation aligns textual lines and refines character differences. The external implementation also receives text without language or syntax context. Configuration in src/vs/editor/common/config/editorConfigurationSchema.ts exposes whitespace filtering and move detection but no structural mode. The trace establishes the missing capability, not a selected parser, language-service integration, or safe structural-to-text range mapping. Preserve current textual behavior and responsiveness; https://github.com/microsoft/vscode/issues/191453 is related outline-aware alignment work, while https://github.com/microsoft/vscode/issues/43026 covers whitespace filtering rather than structural comparison.
- **Open decisions:**
  - Which languages should the initial structural mode support, and what should users see when a language is unsupported or either side cannot be parsed?
  - Which syntax-preserving differences should the mode suppress, and should users be able to reveal those differences without leaving the comparison?
  - Should structural comparison be an explicit per-comparison opt-in or a persistent diff-editor setting?
