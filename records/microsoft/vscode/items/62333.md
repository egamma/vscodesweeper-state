# Issue #62333 — [css] Add @media and @supports to CSS breadcrumbs

[https://github.com/microsoft/vscode/issues/62333](https://github.com/microsoft/vscode/issues/62333)

## Summary

A real gap remains on current main: CSS breadcrumbs now include `@media` document symbols, but `@supports` blocks are still omitted. The issue already has the correct CSS area label and an accepted Backlog milestone, so it should remain open.

## Change summary

Include enclosing `@media` and `@supports` rules in CSS breadcrumbs so developers can see the active conditional context.

## Best solution

Extend the CSS language service's document-symbol collection to emit nested `@supports` symbols, with navigation tests, then update VS Code's bundled language-service version. The existing `@media` behavior should remain unchanged.

## Evidence

- **current VS Code path:** extensions/css-language-features/server/src/cssServer.ts handles document-symbol requests by returning `getLanguageService(document).findDocumentSymbols2(document, stylesheet)`, so CSS breadcrumbs derive their hierarchy from the bundled CSS language service.
- **partial existing capability:** The current CSS language-service implementation in https://github.com/microsoft/vscode-css-languageservice/blob/main/src/services/cssNavigation.ts explicitly collects `nodes.Media` as an `@media …` module symbol, so the media-query portion of the request is already covered.
- **remaining gap:** The same `collectDocumentSymbols` implementation handles rule sets, variables, mixins, functions, keyframes, font faces, media queries, and scopes, but has no branch emitting a document symbol for `@supports`; therefore breadcrumbs still cannot show that enclosing condition.
- **related issue checked:** https://github.com/microsoft/vscode/issues/61125 is closed and concerns completion suggestions for media queries, not breadcrumb or document-symbol navigation, so it is neither an open canonical nor the same requested behavior.
- **canonical search:** Searches for open VS Code issues covering CSS breadcrumbs, media-query breadcrumbs, or support-rule document symbols found no older issue with the same reporter-observable request.
