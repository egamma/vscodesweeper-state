# Issue #200896 — Restart button is often not visible

[https://github.com/microsoft/vscode/issues/200896](https://github.com/microsoft/vscode/issues/200896)

## Summary

Keep open: a maintainer reproduced incorrect notebook context keys, and users continued reporting missing Restart controls through June 2026. No verified fix or qualifying canonical duplicate establishes that this reopened report is resolved.

## Change summary

The notebook Restart button intermittently disappears despite an active kernel, sometimes alongside an ineffective restart command.

## Best solution

Restore consistent notebook-specific restart availability across window, editor-group, and focus changes. Diagnose the boundary between core notebook context scoping and Jupyter's context-key updates before choosing the owning implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`
- **Validation:** Open notebooks with active Python kernels in two VS Code windows, switch focus between windows and notebook/plain-text editor groups, and restart kernels repeatedly. Restart must remain available whenever the selected kernel supports it, and invoking it must restart the intended notebook's kernel; repeat with a Dev Container and capture context-key values during any failure.
- **Behavior:**

  > An active notebook with a restart-capable kernel must retain its Restart action through window switching, editor-group changes, and kernel restarts. The toolbar action and command must operate on the intended notebook rather than becoming unavailable because another editor gains focus. Validate with two notebook windows and a split containing plain-text editors, including repeated focus transitions and restarts.
- **Trace:**

  > NotebookEditorWidget creates a scoped context-key service in src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts, supplies it to NotebookEditorWorkbenchToolbar in _registerNotebookActionsToolbar, and reparents it through setParentContextKeyService. A maintainer previously reproduced jupyter.kernel.isjupyter becoming false and jupyter.notebookeditor.canrestartNotebookkernel disappearing, but the available source does not establish whether the incorrect update originates in core context propagation or Jupyter. Reproduce on current builds and correlate those keys with active notebook, window, and editor-group transitions before defining the implementation boundary. Preserve legitimate kernel capability gating and notebook isolation; do not make Restart unconditional. Related investigation is tracked at https://github.com/microsoft/vscode-jupyter/issues/16189; https://github.com/microsoft/vscode-jupyter/pull/15916 was diagnostic logging only and never merged.
