# Issue #267596 — Feature: Toggle custom Copilot instructions per chat session

[https://github.com/microsoft/vscode/issues/267596](https://github.com/microsoft/vscode/issues/267596)

## Summary

A real per-session customization gap remains: current settings can suppress automatic instructions globally or per workspace, but current main has no session-specific override. The request is already in Backlog and should stay open for a product decision about prompt-versus-session scope.

## Change summary

Allow a chat prompt or session to temporarily exclude automatically applied custom instruction files while leaving them enabled by default elsewhere.

## Best solution

Add session-level instruction inclusion state to the chat input/session model and honor it in both core and extension-side automatic instruction collection, while retaining the existing settings as defaults. The UI and persistence semantics need maintainer agreement before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`
- **Validation:** Extend `src/vs/workbench/contrib/chat/test/common/promptSyntax/computeAutomaticInstructions.test.ts` to verify that two sessions can independently include and exclude applying instructions while preserving the configured default; add the corresponding extension collector test if extension-side collection remains supported.
- **Behavior:**

  > Custom instruction files remain enabled by default. A user can temporarily suppress their automatic inclusion for the chosen chat scope without deleting, renaming, or editing the instruction files and without affecting other chat sessions. Explicitly attached context must retain its documented behavior. Acceptance requires demonstrating that two simultaneous sessions can have different instruction-inclusion states and that a session with no override follows the existing configuration.
- **Trace:**

  > Automatic instruction collection currently runs in `ChatServiceImpl._sendRequestAsync` through `ComputeAutomaticInstructions`, whose `addApplyingInstructions` method reads `chat.includeApplyingInstructions` directly from configuration. When `chat.experimental.collectInstructionsInExtension` is enabled, collection instead occurs in `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`, which also reads configuration directly. Chat session option infrastructure already exists in `src/vs/workbench/contrib/chat/common/chatSessionsService.ts`, but the record does not establish whether this control should use provider session options, chat input state, or a one-request send option. Existing global settings from https://github.com/microsoft/vscode/pull/289731 must remain the default and must not be silently rewritten by a temporary override. The younger https://github.com/microsoft/vscode/issues/323266 concerns persistent per-customization management and should remain separate unless maintainers deliberately consolidate the product designs.
- **Open decisions:**
  - Should the control apply only to the next submitted prompt, to the entire current session, or offer both scopes?
  - Should the override disable only automatically matched `*.instructions.md` files, or also referenced instructions, repository-wide instruction files, and AGENTS.md?
  - Should a session-level choice be restored with chat history, or reset to the configured default whenever the session is reopened?
  - Where should the control appear so its active state is visible without adding persistent clutter to every chat input?

## Evidence

- **existing capability is incomplete:** Merged https://github.com/microsoft/vscode/pull/289731 added `chat.includeApplyingInstructions` and `chat.includeReferencedInstructions`; `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts` reads these from `IConfigurationService`, so they are configuration-level controls rather than per-session state.
- **current request path:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` constructs `ComputeAutomaticInstructions` for each request using mode, tools, subagents, and session type, but passes no session-specific instruction-inclusion option.
- **second collection path:** `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts` likewise reads `chat.includeApplyingInstructions` and `chat.includeReferencedInstructions` directly from configuration, so an eventual design must account for extension-side collection as well as core collection.
- **related closed request:** https://github.com/microsoft/vscode/issues/282422 was completed by the global settings, but its discussion explicitly related this issue and described a separate clean-context request; the merged implementation does not supply the requested per-session toggle.
- **younger related issue:** https://github.com/microsoft/vscode/issues/323266 requests persistent per-item and category toggles in the Customizations view. It was created after this re-reviewed issue and does not present the same session-specific behavior, so it cannot serve as the duplicate canonical.
