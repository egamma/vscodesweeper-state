# Issue #305872 — Sessions: Allow creating cloud sessions for local folders

[https://github.com/microsoft/vscode/issues/305872](https://github.com/microsoft/vscode/issues/305872)

## Summary

Keep open: a maintainer explicitly designated this team-authored issue to track cloud-session creation from local folders. Current main contains likely-covering support behind an experimental setting, but no fixing commit or linked PR references this protected issue, and the setting remains disabled by default in stable.

## Change summary

Allow a local folder backed by a GitHub repository to be used when creating a Copilot Cloud session.

## Best solution

Make local GitHub-backed folders reliably offer both the local and Cloud harnesses in the stable Agents Window experience, preserving the selected repository when switching between them. Confirm whether this should graduate with the unified workspace picker or become available independently.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessionsConfiguration.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/test/browser/copilotChatSessionsProvider.test.ts`, `src/vs/sessions/contrib/chat/browser/sessionTypePicker.ts`, `src/vs/sessions/contrib/chat/test/browser/sessionTypePicker.test.ts`
- **Validation:** Run the focused CopilotChatSessionsProvider and SessionTypePicker unit tests, including “getSessionTypes offers Cloud for a local workspace with a GitHub remote”, and verify in a stable-quality configuration that selecting a local GitHub-backed folder offers both eligible harnesses and creates the Cloud draft against the matching GitHub repository.
- **Behavior:**

  > Selecting a local folder whose Git repository has a GitHub remote offers Copilot Cloud as an available session harness alongside applicable local harnesses. Choosing Cloud creates the task against that same GitHub repository, while switching harnesses preserves the user's folder selection. A local repository without a GitHub remote must not offer Cloud, and existing GitHub-repository selection remains unchanged.
- **Trace:**

  > Current main already traces most of the behavior through CopilotChatSessionsProvider.getSessionTypes and createNewSession in src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts. getSessionTypes asynchronously resolves .git/config and advertises CopilotCloudSessionType for a GitHub-backed file URI; _getCloudWorkspaceForLocalRepository maps it to the provider's github-remote-file workspace before draft creation. The focused provider test confirms this flow, and SessionTypePicker obtains choices through ISessionsManagementService.getSessionTypesForFolder. The path is currently gated by sessions.chat.unifiedWorkspacePicker.enabled, registered as experimental and disabled by default for stable builds. Preserve rejection of non-GitHub local repositories and do not alter unrelated remote, sandbox, or local-agent-host selection behavior. PR https://github.com/microsoft/vscode/pull/335301 is likely covering work but does not reference https://github.com/microsoft/vscode/issues/305872.
- **Open decisions:**
  - Should local-folder Cloud session creation become available only when the unified workspace picker graduates to stable, or should this capability be enabled independently of that broader picker experiment?
