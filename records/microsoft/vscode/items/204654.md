# Issue #204654 — Unwanted scrolling in macOS with native trackpad and pinch zoom gesture.

[https://github.com/microsoft/vscode/issues/204654](https://github.com/microsoft/vscode/issues/204654)

## Summary

The macOS trackpad bug remains open and has attracted two closed, unmerged fix attempts, so there is no landed fix that supports closing it. The concrete reproduction and implementation discussion are sufficient to keep it in the editor input backlog.

## Change summary

A macOS pinch gesture vertically scrolls a long editor even when `editor.mouseWheelZoom` is disabled, instead of doing nothing.

## Best solution

Handle macOS pinch-generated wheel events so disabling `editor.mouseWheelZoom` suppresses the gesture without changing ordinary trackpad scrolling or mouse-wheel behavior. A maintainer should first resolve how to distinguish pinch input reliably, informed by the two closed implementation attempts.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `src/vs/base/browser/ui/scrollbar/scrollableElementOptions.ts`
- **Validation:** On macOS, open a long file with `editor.mouseWheelZoom` disabled and verify that a pinch gesture neither zooms nor scrolls, while ordinary two-finger scrolling and physical mouse-wheel scrolling remain unchanged; repeat with `editor.mouseWheelZoom` enabled to verify pinch zoom still works.
- **Behavior:**

  > On macOS, when `editor.mouseWheelZoom` is disabled, performing a trackpad pinch gesture over a long editor must neither zoom nor vertically scroll the document. Normal two-finger trackpad scrolling and physical mouse-wheel scrolling must continue to work. When `editor.mouseWheelZoom` is enabled, pinch zoom behavior must remain available.
- **Trace:**

  > The report traces the unwanted movement to the scrollbar wheel path, where the pinch arrives as a wheel event and is classified as a physical mouse wheel. Two implementation attempts, https://github.com/microsoft/vscode/pull/239432 and https://github.com/microsoft/vscode/pull/256144, were closed without merging, which leaves the intended classifier/event-boundary treatment unresolved. Investigation should remain within editor/scrollable wheel handling and must not suppress legitimate trackpad or mouse scrolling on macOS or alter non-macOS behavior.
- **Open decisions:**
  - Which browser wheel-event characteristics reliably distinguish a macOS pinch gesture from ordinary two-finger scrolling and a physical mouse wheel across supported Electron versions?
  - Should pinch suppression live in the shared scrollable element path or at the editor mouse-wheel-zoom boundary to avoid changing other scrollable workbench surfaces?
  - What automated or platform-specific validation can cover real macOS gesture events without relying only on synthetic wheel events?
