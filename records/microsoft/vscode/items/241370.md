# Issue #241370 — Incorrect indentation after C multi-line comment blocks

[https://github.com/microsoft/vscode/issues/241370](https://github.com/microsoft/vscode/issues/241370)

## Summary

Keep open for the remaining typing defect: full auto-indentation can inherit the closing comment line's extra space after an unindented blank line. Two participants confirmed that pasting was corrected in 1.104.x, but that partial resolution does not complete this report.

## Change summary

Prevent C block-comment alignment whitespace from reappearing as code indentation when Enter is pressed on subsequent blank lines.

## Best solution

Make successive new lines after a completed C block comment retain the surrounding code indentation without reviving the comment's alignment space. Diagnose the shared indentation inheritance boundary before implementation, preserving intentional indentation and the already-corrected paste behavior.

- **Likely files:** `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/common/languages/supports/indentationLineProcessor.ts`, `extensions/cpp/language-configuration.json`
- **Validation:** With editor.autoIndent set to full, use a C file containing a top-level block comment whose closing line is ' */', followed by an empty line. Press Enter repeatedly on that empty line and verify every new line remains at column 1. Repeat inside an indented function and verify the surrounding code indentation is retained. Add an executable editor regression test covering these sequences and preservation of intentionally indented blank lines; retain a paste regression check for the previously corrected behavior.
- **Behavior:**

  > After a completed C block comment, repeated Enter presses must not reintroduce the extra alignment space used before the closing */. At top level, successive blank lines remain at column 1; inside a function, they retain the surrounding code indentation. The issue's September confirmations establish that paste behavior improved separately, so correcting typing must not regress pasting or comment continuation.
- **Trace:**

  > EnterOperation._enter in src/vs/editor/common/cursor/cursorTypeEditOperations.ts falls through to getIndentForEnter under full auto-indentation when no explicit enter rule applies. In src/vs/editor/common/languages/autoIndent.ts, getPrecedingValidLine skips the current blank line, and getInheritIndentForLine can recover one leading space from the preceding ' */' line; getIndentForEnter then returns that space as afterEnter. ProcessedIndentRulesSupport and IndentationLineProcessor do not remove comment alignment whitespace, and extensions/cpp/language-configuration.json has no empty-line rule covering this transition. This establishes the remaining typing mechanism without running the editor. The uncertainty is the safe boundary of a change to shared inheritance behavior: its effects on intentional indentation, other languages, and other consumers have not been fully enumerated. Preserve those behaviors and the resolved paste path; https://github.com/microsoft/vscode/issues/243100 is a related but distinct repeated-Enter case, not a duplicate target.

## Evidence

- **Confirmed remaining behavior:** In https://github.com/microsoft/vscode/issues/241370, the reporter's September 25 comment and wovano's September 29 confirmation distinguish the resolved paste behavior in 1.104.1/1.104.2 from the still-failing typing behavior. Earlier confirmations cover Windows and Linux.
- **Current source inheritance path:** In src/vs/editor/common/languages/autoIndent.ts, getPrecedingValidLine skips empty and whitespace-only lines. getInheritIndentForLine defaults honorIntentialIndent to true and returns the leading whitespace of the preceding nonignored line. For a blank line following a closing comment line containing ' */', that preceding line contributes one space.
- **Enter consumes the inherited space:** getIndentForEnter in src/vs/editor/common/languages/autoIndent.ts calls getInheritIndentForLine for the next line and uses its indentation as afterEnter. In src/vs/editor/common/cursor/cursorTypeEditOperations.ts, EnterOperation._enter inserts that indentation under EditorAutoIndentStrategy.Full when no explicit enter action applies. The C configuration in extensions/cpp/language-configuration.json supplies indentation rules but no rule for an empty line after a block comment; indentationLineProcessor.ts removes brackets from comment tokens, not comment alignment whitespace.
