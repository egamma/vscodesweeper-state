# Issue #298494 — User setup cannot be updated when running as admin user without UAC

[https://github.com/microsoft/vscode/issues/298494](https://github.com/microsoft/vscode/issues/298494)

## Summary

The update blocker remains in current source: user installations running elevated are disabled without checking whether UAC is enabled. Keep this team-authored issue open; the maintainer explicitly distinguished fixing the repeated notification from enabling updates in this scenario.

## Change summary

Allow Windows user installations to update for administrator accounts when UAC is disabled.

## Best solution

Support the UAC-disabled administrator scenario throughout the Windows user-install update flow while preserving the existing restrictions for explicitly elevated processes with UAC enabled. Treat notification suppression as separate from restoring update functionality.

## Evidence

- **Current source confirms the blocker:** src/vs/platform/update/electron-main/updateService.win32.ts, Win32UpdateService.initialize(), checks productService.target === 'user' and nativeHostMainService.isAdmin(undefined), sets State.Disabled(DisablementReason.RunningAsAdmin), and returns before super.initialize(). This directly explains the reported unavailable update action; the branch makes no UAC distinction.
- **Elevation detection does not distinguish UAC state:** src/vs/platform/native/electron-main/nativeHostMainService.ts:827-835 implements isAdmin() on Windows by calling native-is-elevated. Together with the unconditional updater guard, an elevated administrator token in the reported UAC-disabled configuration still disables user-install updates. This was traced read-only, not executed on Windows.
- **Maintainer intent:** https://github.com/microsoft/vscode/issues/298494#issuecomment-4219123718 says the repeated notification will be fixed but that making updates work is a separate issue. Notification improvements therefore do not establish completion of this report.
