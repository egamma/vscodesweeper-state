# Issue #8939 — Show quick open results as preview while navigating through them

[https://github.com/microsoft/vscode/issues/8939](https://github.com/microsoft/vscode/issues/8939)

## Summary

Keep open: filename Quick Open still does not automatically preview highlighted files. This accepted Backlog request has substantial demand, and existing preview settings and Quick Search do not cover its central ask.

## Change summary

Preview file contents while navigating filename Quick Open results, without accepting each result or accumulating permanent tabs.

## Best solution

Provide reversible file previews while navigating Quick Open, preserving keyboard focus in the picker and restoring the prior editor on cancellation. Agree on the preview presentation and activation policy before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/quickTextSearch/textSearchQuickAccess.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** On a workspace with several similarly named files, open workbench.action.quickOpen, type a matching filename fragment, and navigate the results with arrow keys. Verify the highlighted file is previewed without accepting it, typing remains in the picker, repeated navigation does not accumulate permanent tabs, Escape restores the prior editor, and Enter retains the chosen file. Repeat with an existing dirty editor, rapid navigation, preview settings disabled, and file@symbol navigation to establish compatibility with the chosen policy.
- **Behavior:**

  > Filename Quick Open should let users inspect the highlighted file before accepting it. Moving between results should update the preview without accumulating permanent tabs or taking typing focus away from the picker. Cancellation should restore the prior editor, as preferred in the report, and acceptance should retain the selected file. The maintainer must settle how this behavior is activated and presented.
- **Trace:**

  > AnythingQuickAccessProvider.provide() in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts listens for active-item changes but only reveals editor-symbol ranges; ordinary file items open through acceptance. workbench.editor.enablePreviewFromQuickOpen controls accepted-editor pinning, not live previews. The same provider already uses editorViewState.openTransientEditor() for file@symbol navigation and restores view state on explicit cancellation. src/vs/workbench/contrib/search/browser/quickTextSearch/textSearchQuickAccess.ts provides neighboring prior art for debounced active-result previews and restoration. Preserve dirty and pinned editors, picker focus, existing acceptance modifiers, and symbol-navigation behavior; editor-picker Ctrl+Tab previews are a follow-on request rather than required scope. The maintainer's suggest-widget comparison leaves presentation unresolved, while https://github.com/microsoft/vscode/issues/243483 confirms that pre-accept filename preview is the central capability.
- **Open decisions:**
  - Should automatic filename previews be enabled by default, opt-in, or activated explicitly while browsing Quick Open?
  - Should file contents appear in a transient workbench editor, as originally requested, or in a picker-associated preview surface?

## Evidence

- **Current filename-navigation gap:** In src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts, AnythingQuickAccessProvider.provide() handles active-item changes only by decorating and revealing editor-symbol picks. Ordinary file picks open through their accept callback in createAnythingPick(), not when highlighted. The shared src/vs/platform/quickinput/browser/pickerQuickAccess.ts invokes that callback on acceptance.
