# Issue #336377 — `"workbench.experimental.modernUIEditorTabStyle": "connected"` ignores `tabActiveBorder` color

[https://github.com/microsoft/vscode/issues/336377](https://github.com/microsoft/vscode/issues/336377)

## Summary

Confirmed via the reporter's screenshots and a source trace: the connected Modern UI tab style hardcodes the active tab's bottom border to transparent, so a custom `tab.activeBorder` color renders in pill style but is silently dropped in connected style.

## Change summary

With `workbench.experimental.modernUIEditorTabStyle` set to `connected`, a custom `tab.activeBorder` color customization has no visible effect on the active tab, unlike the `pill` style where it renders correctly.

## Best solution

Decide (as a maintainer/design call) whether `connected` style should honor `tab.activeBorder` at all, given its documented intent is to make the active tab and editor content 'read as one document well' with no seam — then either plumb the customized color into `connectedEditorTabs.css`'s `.tab.active > .tab-fill` rule or document the override as intentional.

Worth a design call on whether `connected` should honor this color at all, given it's meant to visually merge the active tab with the editor surface.

## Evidence

- **screenshot repro:** Reporter's two screenshots (both with `"tab.activeBorder": "#000000"` set) show a visible black underline on the active tab in pill style, and no border at all in connected style.
- **root cause line:** src/vs/workbench/contrib/modernUI/browser/media/connectedEditorTabs.css line 163 sets `--modern-ui-editor-tab-active-border: transparent;` unconditionally for `.modern-ui-connected-editor-tabs ... .tab.active > .tab-fill`, which is the CSS variable consumed by the border-bottom rule at tabs.css line 315.
- **base hiding rule:** src/vs/workbench/contrib/modernUI/browser/media/tabs.css line 279-281 also hides the classic `.tab-border-bottom-container` (which is what JS populates from `TAB_ACTIVE_BORDER` in multiEditorTabsControl.ts) with `display: none !important` for all Modern UI tab styles, so the only path left for a bottom border is the `--modern-ui-editor-tab-active-border` variable.
- **design intent doc:** src/vs/workbench/contrib/modernUI/README.md line 25 documents that connected style deliberately makes the active tab and editor body 'read as one document well' using `editor.background`, suggesting the transparent border may be partly intentional but is not documented as overriding user color customizations (only foreground customizations are explicitly called out as still applying).
