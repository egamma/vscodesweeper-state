# Issue #334542 — Render PRs/Issues and attached context as pills within the chat input vs as attachments

[https://github.com/microsoft/vscode/issues/334542](https://github.com/microsoft/vscode/issues/334542)

## Summary

Keep open as the team-authored umbrella for a deliberate Chat attachment-presentation redesign. The narrower GitHub-link treatment was explicitly rolled back pending a consistent design for all attachments, and current main still renders most context in separate attachment containers.

## Change summary

Represent GitHub issue and pull-request context, together with other attached context, as compact pills within the Chat prompt instead of a separate attachment row.

## Best solution

Define a unified inline-reference contract for Chat and the Agents composer, including which attachment kinds can be represented inline, whether they remain agent-facing context attachments, and how positional editing, opening, removal, restoration, and accessibility work across both surfaces.

- **Behavior:**

  > Regular Chat and the Agents composer should present the agreed attachment kinds as compact references within the prompt rather than as a separate attachment row. GitHub issue and pull-request references must remain recognizable and clickable while preserving the complete agent-facing URL or context payload. Copy/paste, undo/redo, drafts, history restoration, keyboard opening/removal, and screen-reader labeling must preserve the references without losing attached context. Attachment kinds intentionally excluded from inline treatment must continue to render and function consistently.
- **Trace:**

  > The earlier implementation in https://github.com/microsoft/vscode/pull/334068 converted pasted GitHub URLs into ranged inline decorations and stopped adding context attachments; https://github.com/microsoft/vscode/pull/334544 reverted that behavior specifically until a design exists for all attachments. Current workbench Chat renders attachment widgets through `ChatInputPart.renderAttachedContext()` in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, while ranged editor decorations are maintained by `ChatDynamicVariableModel` in src/vs/workbench/contrib/chat/browser/attachments/chatDynamicVariables.ts. The Agents composer separately renders a pill row through `NewChatContextAttachments.renderAttachedContext()` in src/vs/sessions/contrib/chat/browser/newChatContextAttachments.ts. Preserve agent-visible payloads, attachment limits and warnings, restoration, and existing open/remove keyboard behavior; do not reduce rich attachments to decorative text without an equivalent accessible interaction. The uncertainty begins at the product contract for non-text attachments and for whether inline placement carries prompt ordering semantics.
- **Open decisions:**
  - Which attachment kinds, especially images, notebook outputs, terminal commands, and other rich context, must become inline pills versus retain a separate preview treatment?
  - Should attachments without an existing text range be inserted at the caret and participate in prompt ordering, or appear in a fixed pill region visually integrated into the editor?
  - For pasted GitHub issue and pull-request URLs, should the inline pill remain a fetched context attachment, remain only full URL prompt text as in the reverted implementation, or combine both semantics?
