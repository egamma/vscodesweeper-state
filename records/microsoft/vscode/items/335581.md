# Issue #335581 — Agent Host WorkIQ MCP remains Running after XAA assertion expires

[https://github.com/microsoft/vscode/issues/335581](https://github.com/microsoft/vscode/issues/335581)

## Summary

Well-diagnosed, freshly filed bug with concrete code citations already correctly labeled `bug`/`ai-customizations`; current main confirms the gap the reporter describes, so this should stay open for a fix rather than any triage close.

## Change summary

WorkIQ MCP servers keep showing as Running/authenticated after their enterprise-managed (XAA) assertion expires, because credential expiry isn't propagated to the SDK auth response and the failed tool call isn't surfaced as an auth-required transition.

## Best solution

Have `CopilotAgentSession.resolveMcpAuthentication` forward the token's expiry (already computed in agentHostAuth.ts) into the SDK auth response so proactive renewal can be scheduled, and treat an OBO/assertion-expiry tool failure as a trigger to flip the server to `McpServerStatus.AuthRequired` in mcpListWidget.ts rather than leaving it at `Ready`.
