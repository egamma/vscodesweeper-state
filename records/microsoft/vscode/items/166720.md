# Issue #166720 — Continue Working On should surface working changes with slight differences in edit session state

[https://github.com/microsoft/vscode/issues/166720](https://github.com/microsoft/vscode/issues/166720)

## Summary

Keep open: current source already supports a confirmation prompt for branch-state drift, but only behind an experimental setting that defaults to false. The linked merged PR enabled that setting historically; it does not establish completion of the default experience requested here.

## Change summary

Surface recoverable working changes when Continue Working On reaches the same repository and branch at a different commit, rather than silently skipping them.

## Best solution

Make pending changes discoverable in the normal Continue Working On flow when only the commit differs, while retaining explicit user confirmation before applying them. Decide whether to promote the existing partial-match prompt or provide another default recovery surface.

- **Reason:** Making working changes discoverable across development environments improves the existing remote-development workflow without requiring automatic synchronization.

  > When Continue Working On reaches the same repository and branch at a different commit, users can discover and retrieve their stored working changes. Acceptance should demonstrate a visible recovery opportunity in the agreed normal flow, no application before explicit confirmation, and successful restoration after confirmation. Exact identity matches and unrelated repositories retain their existing behavior.
- **Trace:**

That path is gated by workbench.experimental.cloudChanges.partialMatches.enabled, whose current default is false; otherwise no matching folder is selected and no changes are applied. https://github.com/microsoft/vscode/pull/166721 historically enabled the experimental setting but current source does not retain that default. - **Open decisions:**
