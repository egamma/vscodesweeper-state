# Issue #318381 — Add a setting to not resolve shell configuration and not inherit environment from cli

[https://github.com/microsoft/vscode/issues/318381](https://github.com/microsoft/vscode/issues/318381)

## Summary

Valid feature request: VS Code already has a CLI flag (`--force-disable-user-env`) that skips shell environment resolution, but no persistent *setting* to achieve the same without passing a flag every launch. The gap is real — a user-facing setting would make the workaround discoverable and permanent.

## Change summary

Add a user-facing setting to persistently disable shell environment resolution, instead of requiring the `--force-disable-user-env` CLI flag on every launch.

## Best solution

Add a boolean setting (e.g. `application.shellEnvironmentResolution` with values like `auto`/`disabled`) in `src/vs/workbench/electron-browser/desktop.contribution.ts` alongside the existing `application.shellEnvironmentResolutionTimeout`, and honor it in `src/vs/platform/shell/node/shellEnv.ts` (where `--force-disable-user-env` is already checked). This would make the existing CLI-only workaround accessible as a persistent preference.
