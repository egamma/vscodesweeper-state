# Issue #289905 — Allow the user to open the PR from the agent list entry context menu

[https://github.com/microsoft/vscode/issues/289905](https://github.com/microsoft/vscode/issues/289905)

## Summary

The requested context-menu entry and grouping remain missing on current main. Cloud sessions now also represent tasks without a PR, so the browser action's destination needs to be distinguished before adopting the proposed PR-specific label.

## Change summary

Expose separate, clearly named actions for opening a cloud session's pull request inside VS Code or externally, grouped with Close Pull Request.

## Best solution

Provide a discoverable in-editor PR action alongside explicitly named external PR navigation in the cloud-session context menu, with PR operations grouped separately from session operations. Preserve task-page navigation for the newer task-based sessions without mislabeling it as PR navigation.

- **Behavior:**

  > A cloud session with an attached pull request should expose an explicit context-menu action that opens that PR inside VS Code. External PR navigation should clearly identify its destination, and PR operations should be visually separated from chat-session operations and grouped with Close Pull Request. - **Trace:**

  > The cloud-session menu contributions in extensions/copilot/package.json place openInBrowser in navigation@10 and Close Pull Request in 1_edit@10; package.nls.json retains the generic browser label. Preserve task navigation, existing PR-card behavior, and the distinction between viewing a PR and checking out its branch. The older https://github.com/microsoft/vscode/issues/288193 concerns automatic artifact selection, not this explicit context-menu interaction.
- **Open decisions:**
