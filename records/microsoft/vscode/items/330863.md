# Issue #330863 — Weird tab titles on macOS since 1.132

[https://github.com/microsoft/vscode/issues/330863](https://github.com/microsoft/vscode/issues/330863)

## Summary

Confirmed by source: `workbench.experimental.modernUI` is registered with `experiment: { mode: 'auto' }` in workbench.contribution.ts, so `ConfigurationDefaultOverridesContribution` fetches an A/B treatment via `IWorkbenchAssignmentService` and silently overrides the setting's *default* value (not the user's settings.json) after extensions/assignments resolve — explaining why it appears only after a restart and only for some users/platforms. This is intentional rollout tooling for the modern UI effort, but the lack of any in-product notice is legitimate feedback worth tracking rather than dismissing.

## Change summary

Editor tab and panel titles changed to a heavier/bolder font on macOS starting in 1.132 with no visible setting change, traced to the modern UI experiment silently flipping on.

## Best solution

Consider surfacing a one-time notification/toast (or release-notes callout) when an auto-mode experiment materially changes visual appearance, and document the explicit opt-out (`"workbench.experimental.modernUI": false` in user settings, which overrides the experiment-provided default) — this belongs with the workbench/UI-modernization workstream, not a code defect to fix.

  > Thanks for the detailed report and screenshots. This isn't a settings bug in the traditional sense — `workbench.experimental.modernUI` ships with `experiment: { mode: 'auto' }`, so VS Code fetches an A/B treatment for it (via the experimentation/assignment service) and applies it as a *default* value once extensions and assignments are resolved, which explains why it only shows up after a restart and only for some users. It doesn't write anything into your settings.json — you can override it back explicitly by adding `"workbench.experimental.modernUI": false` to your user settings, which takes precedence over the experiment-provided default. That said, the lack of any visible notice when an experiment changes core visual appearance is a fair concern worth keeping open for the team to consider (e.g. a one-time notification when this kind of experiment flips a visual default).
