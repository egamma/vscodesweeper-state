[https://github.com/microsoft/vscode/issues/306296](https://github.com/microsoft/vscode/issues/306296)

## Summary

Keep open under discussion: workspace-scoped history and session renaming already exist, but they do not establish the requested automatic project-context continuity and isolation across workflows. No verified canonical covers the full remaining request, and inactivity alone does not justify closing it.

## Change summary

Provide project-scoped chat history and reusable project context, with optional automatic context discovery and workspace pinning.

## Best solution

Separate the already-supported history-scoping and renaming requests from the remaining project-memory expectations. Define which context should persist and be restored when returning to a project, building on existing workspace storage and repository-memory capabilities rather than adding a parallel session system.

## Evidence

- **Existing workspace-scoped history:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts:65–85 selects workspaceStorageHome/<workspaceId>/chatSessions for folder/workspace windows; only empty windows use shared emptyWindowChatSessions storage. The premise that all chat history is global does not describe this storage path.
- **Workspace transitions have separate semantics:** ChatSessionStore.handleWorkspaceTransition and migrateSessionsToNewWorkspace copy existing sessions when entering a workspace, preserving originals. Workspace-keyed storage therefore does not by itself guarantee the strict separation the reporter expects for every switching workflow.
