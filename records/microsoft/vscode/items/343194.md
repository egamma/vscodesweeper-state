# Issue #343194 — PowerShell tool Disabled in PC, cannot use git bash as alternative shell

[https://github.com/microsoft/vscode/issues/343194](https://github.com/microsoft/vscode/issues/343194)

## Summary

Keep open: another enterprise independently confirms that agent commands fail when PowerShell is blocked despite configuring Git Bash. A maintainer identifies missing runtime/SDK shell-selection propagation, and current source does not establish that this Windows path has been fixed.

## Change summary

Copilot agent shell execution fails on Windows with administratively blocked PowerShell instead of using the configured Git Bash alternative.

## Best solution

Provide policy-respecting shell selection for Windows Copilot execution, with the configured executable and matching command language honored by the runtime. Preserve command results, cancellation, and delegated execution rather than relying on model-generated shell workarounds.

- **Behavior:**

  > Copilot shell commands must remain usable on Windows when PowerShell is blocked but the configured alternative shell is permitted. The reported Git Bash configuration should select an executable capable of running the requested Git command, with matching shell syntax. Acceptance includes successful trivial and Git commands, correct exit status, and cancellation. Organization restrictions must remain enforced.
- **Trace:**

  > The report and independent enterprise confirmation are recorded at https://github.com/microsoft/vscode/issues/343194; a collaborator identifies missing runtime/SDK shell-selection propagation. TerminalProfileFetcher.getCopilotProfile honors the explicit chat terminal profile for run-in-terminal, but this is a different execution surface from SDK-native shell tools. CopilotSessionLauncher currently excludes Windows from createShellTools, while ShellManager resolves its executable through AgentHostTerminalManager.getDefaultShell. The remaining uncertainty is which runtime configuration seam can carry executable selection into the actual Windows tool and delegated execution paths. Related https://github.com/microsoft/vscode/issues/346022 and https://github.com/microsoft/vscode/issues/348088 provide lifecycle and initialization context, not verified duplicate ownership. Preserve approvals and organization restrictions; do not treat permitting an alternative shell as permission to bypass a blocked executable.
