# Issue #195581 — [Accessibility] Accessible View does not get dynamically updated in Jupyter Notebook cell output

[https://github.com/microsoft/vscode/issues/195581](https://github.com/microsoft/vscode/issues/195581)

## Summary

Keep open: the notebook Accessible View still captures a one-time output snapshot, so live progress remains unavailable without reopening it. The maintainers supported this enhancement, and no verified canonical issue or landed implementation was found.

## Change summary

Update an open notebook output Accessible View as the cell produces or replaces output.

## Best solution

Provide live output updates through the notebook Accessible View while keeping screen-reader navigation usable during streaming. Agree on reading-position behavior before implementation, using the terminal's existing dynamic Accessible View as precedent.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts`, `src/vs/workbench/contrib/notebook/browser/viewModel/cellOutputTextHelper.ts`, `src/vs/workbench/contrib/notebook/browser/notebookAccessibilityHelp.ts`
- **Validation:** Run a notebook cell that prints an initial line, then prints another line each second with flushing. Open its output with Alt+F2 before execution finishes and verify later lines appear without reopening. Also check output replacement, clearing, changes in another cell, closing/reopening the view, and the agreed cursor behavior with NVDA or VoiceOver. Add provider-level regression coverage for appended and replaced output and listener teardown.
- **Behavior:**

  > An open notebook output Accessible View should reflect subsequent output from the cell it represents, including streamed print output and progress updates, without requiring the user to close and reopen it. Replaced or cleared output should not leave stale text. Output from unrelated cells should not replace the viewed cell's content. Acceptance includes a timed-print notebook scenario and an explicit check that updates follow the agreed reading-position behavior without disrupting keyboard navigation or focus restoration.
- **Trace:**

  > In src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts, getAccessibleOutputProvider obtains the selected cell, evaluates getAllOutputsText once, and captures the resulting string in provideContent. The provider supplies no onDidChangeContent event. NotebookCellTextModel in src/vs/workbench/contrib/notebook/common/model/notebookCellTextModel.ts already emits separate structural-output and output-item change events, including stream appends. The shared Accessible View rerenders on provider.onDidChangeContent, and terminalAccessibleBufferProvider.ts demonstrates dynamic content and configurable reading-position behavior. The missing refresh path is established by source inspection; no code was executed. Keep output formatting, selected-cell identity, and focus restoration intact; cross-cell navigation and index labels are separate requests at https://github.com/microsoft/vscode/issues/188535 and https://github.com/microsoft/vscode/issues/189362. The remaining product uncertainty is whether incoming notebook output should move the reading position or preserve it.
- **Open decisions:**
  - When notebook output updates while Accessible View is open, should the reading position remain fixed, follow new output, or follow only when the reader is already at the end?

## Evidence

- **Current source confirms the missing capability:** src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts:getAccessibleOutputProvider computes outputContent once with getAllOutputsText and returns that captured string from provideContent. Its AccessibleContentProvider has no onDidChangeContent event, so output arriving after Alt+F2 cannot refresh the open view.
- **Existing refresh infrastructure:** src/vs/platform/accessibility/browser/accessibleView.ts exposes AccessibleContentProvider.onDidChangeContent. src/vs/workbench/contrib/accessibility/browser/accessibleView.ts:368-371 subscribes to that event and rerenders the provider. src/vs/workbench/contrib/terminalContrib/accessibility/browser/terminalAccessibleBufferProvider.ts provides current buffer text and fires the event from refresh(), matching the terminal precedent linked in the discussion.
- **Notebook output change boundary:** src/vs/workbench/contrib/notebook/common/model/notebookCellTextModel.ts exposes onDidChangeOutputs and onDidChangeOutputItems. spliceNotebookCellOutputs emits structural changes; replaceOutput and changeOutputItems emit item changes, including appended stream data. The notebook Accessible View currently subscribes to neither.
