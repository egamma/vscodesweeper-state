# Issue #195581 — [Accessibility] Accessible View does not get dynamically updated in Jupyter Notebook cell output

[https://github.com/microsoft/vscode/issues/195581](https://github.com/microsoft/vscode/issues/195581)

## Summary

Still unimplemented on main: the notebook accessible view provides a static content snapshot and does not wire up dynamic content updates via the `onDidChangeContent` mechanism that the AccessibleContentProvider supports.

## Change summary

Notebook cell output Accessible View should dynamically update its buffer as new output arrives (e.g., pip download progress or progressive print statements).

## Best solution

Wire `onDidChangeContent` in `NotebookAccessibleView` (src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts) to notebook output-change events so the accessible view buffer refreshes when cell outputs update, similar to how the terminal's accessible buffer re-reads content on each `provideContent` call.

## Evidence

- **no dynamic wiring on main:** src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts creates an AccessibleContentProvider without passing onDidChangeContent (the 11th constructor arg is omitted), so the view is never refreshed after initial open.
- **infrastructure exists:** AccessibleContentProvider in src/vs/platform/accessibility/browser/accessibleView.ts accepts an optional `onDidChangeContent?: Event<void>` parameter that triggers a refresh of the accessible view content.
- **terminal precedent:** The terminal accessible buffer (src/vs/workbench/contrib/terminalContrib/accessibility/browser/terminalAccessibleBufferProvider.ts) re-reads buffer content on each provideContent() call, serving as the model mentioned by @meganrogge in the comments.
