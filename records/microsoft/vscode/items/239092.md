# Issue #239092 — Improve publisher trust dialog while creating the profile

[https://github.com/microsoft/vscode/issues/239092](https://github.com/microsoft/vscode/issues/239092)

## Summary

The requested profile-creation polish remains missing on current main. This maintainer-authored feature request is accepted in the Backlog and should stay open for the profile and extension-management owners.

## Change summary

Improve profile creation by expanding its extension list, showing extension publishers, and making the publisher-trust prompt specific to profile creation.

## Best solution

During profile creation, show the included extensions expanded with their publisher display names, then present one trust prompt whose copy explains that trusting the publishers is required to create the profile. Preserve the existing generic wording for ordinary extension installations.

## Plan brief

- **Likely files:** `src/vs/workbench/services/userDataProfile/browser/extensionsResource.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts`, `src/vs/workbench/services/extensionManagement/common/extensionManagement.ts`, `src/vs/workbench/services/extensionManagement/common/extensionManagementService.ts`
- **Validation:** Create a profile from a template containing extensions from untrusted publishers and verify that the Extensions node starts expanded, each extension shows its publisher name, exactly one profile-specific trust prompt appears, cancellation prevents profile creation, and an ordinary Marketplace installation retains the generic install wording.
- **Behavior:**

  > Creating a profile from a template displays its included extensions expanded by default, with the publisher name visible for every extension. If any publishers are not trusted, one dialog explains the trust decision in the context of creating that profile. Accepting continues profile creation and cancellation stops it; ordinary extension installation behavior and wording remain unchanged.
- **Trace:**

  > Profile extension entries originate in `IProfileExtension` and `ExtensionsResourceTreeItem.getChildren` in src/vs/workbench/services/userDataProfile/browser/extensionsResource.ts, then pass through `NewProfileElement.getChildrenForResourceType` in src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts to `ProfileResourceChildTreeItemRenderer` in userDataProfilesEditor.ts. The model currently carries no publisher display name, and ContentsProfileRenderer sets the tree input without expanding Extensions. Profile application calls `IWorkbenchExtensionManagementService.requestPublisherTrust`, whose implementation delegates directly to the shared generic `checkForTrustedPublishers` dialog. The boundary is profile creation: do not alter generic Marketplace trust wording or weaken publisher verification and cancellation semantics. The precursor fix and intended follow-up are documented in https://github.com/microsoft/vscode/issues/238964 and https://github.com/microsoft/vscode/pull/239093.
