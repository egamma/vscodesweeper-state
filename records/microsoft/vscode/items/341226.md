# Issue #341226 — Web: no extension activates when an extension uses `onFileSystem:file` and the browser lacks `showDirectoryPicker`

[https://github.com/microsoft/vscode/issues/341226](https://github.com/microsoft/vscode/issues/341226)

## Summary

Thanks for the detailed report. The cycle you describe matches current main: the storage stat awaits ensureActivation('file'), the web FileService has no file provider without showDirectoryPicker, and it joins on onFileSystem:file activation, which waits on the storage path. Stays open; the reporter has a candidate fix and is asking for direction.

## Change summary

Web workbench in browsers without showDirectoryPicker deadlocks all extension activation when an extension has an onFileSystem:file activation event and a trusted folder is open.

## Best solution

Break the cycle so the extension host's storage-path stat does not await onFileSystem:file activation (for example, not awaiting $ensureActivation in the extHostFileSystemConsumer shortcut paths, or skipping the join for the file scheme). A maintainer in the remote/web area should confirm the direction.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostFileSystemConsumer.ts`, `src/vs/workbench/services/extensions/common/abstractExtensionService.ts`, `src/vs/workbench/api/common/extHostStoragePaths.ts`
- **Validation:** Extension host test asserting that stat on a file-scheme URI resolves when onFileSystem:file activation is pending.
- **Behavior:**

  > With a trusted folder open in a web workbench lacking showDirectoryPicker, extensions with onFileSystem:file must not block activation of other extensions. Reloading must activate all extensions normally.
- **Trace:**

  > ExtHostStoragePaths.whenReady stats the storage URI via ExtHostFileSystemConsumer, which awaits $ensureActivation('file'). The main-side FileService.activateProvider awaits joiners because no file provider exists in this web setup, and AbstractExtensionService joins activateByEvent('onFileSystem:file'). That waits on an extension whose context waits on the storage path. Do not change activation semantics for real provider schemes.
- **Open decisions:**
  - Fix on the extension host side (don't await ensureActivation when the provider is local) or on the main side (don't join onFileSystem:file when the extension host owns the provider)?

## Evidence

- **storage stat:** src/vs/workbench/api/common/extHostStoragePaths.ts stats the storage URI (file scheme) when a folder is open.
- **join:** src/vs/workbench/services/extensions/common/abstractExtensionService.ts joins onFileSystem:<scheme> for every scheme except vscode-remote.
- **file service:** src/vs/platform/files/common/fileService.ts activateProvider awaits the joiners when no provider for the scheme is registered.
