# Issue #333816 — Native MDM ignores documented object-form plugin marketplaces

[https://github.com/microsoft/vscode/issues/333816](https://github.com/microsoft/vscode/issues/333816)

## Summary

Confirmed on current main: native MDM delivers `extraKnownMarketplaces` as a raw JSON string that bypasses the normalization the file/cloud managed-settings channel applies, so a documented object-form entry never reaches the marketplace UI even though nothing else about it is wrong. No labels or milestone yet, so routing to the chat area.

## Change summary

Enterprise-managed plugin marketplaces delivered via native MDM in the documented object form (`{name: {source: {...}, autoUpdate}}`) are silently dropped instead of being fetched.

## Best solution

Make `readConfiguredMarketplaces` in marketplaceReference.ts accept nested object entries for `chat.plugins.extraMarketplaces` (not just strings), mirroring the object-parsing already done for `parseMarketplaceObjectEntry`/`normalizeExtraKnownMarketplaces` on the file-managed-settings path, so both delivery channels for the same policy behave identically.

- **Trace:**

  > readConfiguredMarketplaces (src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts, ~line 58) iterates Object.entries(extraObj) and returns `[]` for any dict value that isn't a string, before ever reaching parseExtraMarketplaceConfigValue. That silently drops nested-object entries that JSON.parse can legitimately produce from a native-MDM string, per GitHub's own docs (native MDM carries the same logical value as server-managed settings, JSON-encoded as a string). The file/cloud managed-settings channel avoids this because normalizeExtraKnownMarketplaces (src/vs/platform/policy/common/copilotManagedSettings.ts) already converts the same object shape into the canonical string dict before it ever reaches configuration — but native MDM values go straight from NativePolicyService (src/vs/platform/policy/node/nativePolicyService.ts) through the generic PolicyConfiguration JSON parse in src/vs/platform/configuration/common/configurations.ts, never through that normalizer. Boundary: do not touch the generic PolicyConfiguration parsing or the other STRUCTURED_MANAGED_SETTINGS keys (enabledPlugins, strictMarketplaces, MCP allow/deny lists, otel keys) — this fix is scoped to extraMarketplaces dict-value handling, reusing the existing object-parsing logic already present for parseMarketplaceObjectEntry rather than duplicating it. Related: https://github.com/microsoft/vscode/blob/35e20f9dcd9a5c16f9cda64be1a1db0788922d69/src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts#L52-L70 (cited in the issue).

## Evidence

- **still drops non-string entries:** src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts readConfiguredMarketplaces: `if (typeof value !== 'string') { return []; }` inside the Object.entries(extraObj) loop — a nested object value for a marketplace name is discarded before parseExtraMarketplaceConfigValue/parseMarketplaceObjectEntry ever run.
- **config schema expects strings only:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts ChatConfiguration.ExtraMarketplaces declares `additionalProperties: { type: ['string'] }`, so the generic PolicyConfiguration JSON.parse of a native-MDM string value produces whatever shape the admin sent, unconstrained by that schema at parse time.
- **file/cloud channel does normalize objects:** src/vs/platform/policy/common/copilotManagedSettings.ts normalizeExtraKnownMarketplaces() + extraKnownMarketplacesToConfigDict() convert the same documented `{name: {source, autoUpdate}}` shape into the canonical string dict — but this normalization only runs for the file/cloud managed-settings pipeline (normalizeManagedSettings), not for values delivered through NativePolicyService (src/vs/platform/policy/node/nativePolicyService.ts), which stores whatever PolicyValue the OS returns directly.
- **existing test coverage:** src/vs/workbench/contrib/chat/test/common/plugins/pluginMarketplaceService.test.ts already has 'readConfiguredMarketplaces converts policy dict to named marketplace entries' exercising only string-valued dict entries — no case for a nested object value, matching the gap.
