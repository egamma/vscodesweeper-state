# Issue #111016 — [html] move mdn link to the right

[https://github.com/microsoft/vscode/issues/111016](https://github.com/microsoft/vscode/issues/111016)

## Summary

This remains a valid hover usability request: disabling MDN references does not address users who need the link but accidentally activate it. No verified older canonical owns the same observable symptom, and the Backlog milestone does not block continued consideration.

## Change summary

Change HTML/CSS hover presentation or link activation so users do not accidentally open the MDN reference while moving the pointer through the hover.

## Best solution

Preserve MDN references while making activation deliberate and consistent with editor hover interactions, preferably through a general hover-link interaction rather than a one-off layout position.

## Plan brief

- **Likely files:** `extensions/html-language-features`, `extensions/css-language-features`, `src/vs/editor/contrib/hover`
- **Validation:** Manually open HTML and CSS property hovers, move the pointer through the documentation toward adjacent editor lines, and verify the MDN page is not opened accidentally while an intentional documented interaction still opens it.
- **Behavior:**

  > HTML and CSS property hovers must continue to expose the MDN reference without making ordinary pointer movement likely to open an external browser. Users must have a clear, deliberate way to activate the reference. Existing hover content and intentional reference navigation should remain available.
- **Trace:**

  > The report distinguishes this request from https://github.com/microsoft/vscode/issues/97979: removing references is not acceptable because users still need the documentation. The reported interaction is the MDN link at the bottom of HTML/CSS property hover content intercepting pointer movement; a second user confirmed it with a screenshot and noted that hover delay does not solve it. Investigation should trace where HTML/CSS language-feature hover markdown creates the MDN link and how the editor hover renderer activates links. Keep the scope to deliberate MDN-link activation and do not remove reference content or broadly change unrelated markdown links.
- **Open decisions:**
  - Should MDN references remain single-click links in a less collision-prone hover position, or require a modifier/double-click wherever they are displayed?
  - Should the chosen interaction apply only to MDN references or uniformly to external links in editor hovers?

## Evidence

- **distinct from disable request:** The maintainer linked https://github.com/microsoft/vscode/issues/97979 as a setting to remove the link, while the later commenter explicitly needs MDN references retained and reports accidental activation caused by their current placement.
- **confirmed user scenario:** A second user described repeatedly opening the browser while moving the pointer toward the line above and supplied a screenshot plus alternatives such as moving the link or requiring a modifier click.
- **related items do not provide a canonical:** The supplied related items https://github.com/microsoft/vscode/issues/137503 and https://github.com/microsoft/vscode/issues/141460 are closed and therefore cannot serve as duplicate canonicals; this re-reviewed issue also requires an older canonical with the same observable symptom.
- **existing workaround is incomplete:** The existing `css.hover.references` direction removes references entirely; it does not preserve the reference while preventing accidental activation, which is the central ask.
