# Issue #337257 — Clicking on a chat scrolls the Session List

[https://github.com/microsoft/vscode/issues/337257](https://github.com/microsoft/vscode/issues/337257)

## Summary

Team-authored bug filed today (protected from judgment closes regardless); traced conclusively in source — `syncActiveChatSelection` in sessionsList.ts always calls `tree.reveal(chatItem, 0.5)` on every active-chat change, which unconditionally centers the item and scrolls the list even when it is already fully visible.

## Change summary

Clicking a chat in the Agents/Sessions window list causes the session list to scroll, even though the clicked item is already visible.

## Best solution

In `syncActiveChatSelection` (src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts), avoid forcing a centered reveal on every activeChat change — only scroll when the target chat item isn't already visible, e.g. by dropping the fixed `0.5` relativeTop (or checking `getRelativeTop`/visibility first) so a click on an already-visible chat is a no-op for scroll position.

## Evidence

- **root cause call site:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts:4044 — `this.tree.reveal(chatItem, 0.5)` runs inside `syncActiveChatSelection`, called from an autorun (lines 3543-3552) that fires whenever `activeSession.activeChat` changes, which happens on clicking a chat.
- **reveal semantics:** src/vs/base/browser/ui/list/listWidget.ts:1972-1997 — when `relativeTop` is a number, `reveal()` unconditionally computes and sets a new `scrollTop` to center the element at that relative position; it does not first check whether the element is already fully visible (that branch is only taken when `relativeTop` is omitted).
- **no existing guard:** No visibility check (e.g. `getRelativeTop`) precedes the `reveal(chatItem, 0.5)` call, so every click that changes the active chat re-centers it, producing the reported scroll jump.
