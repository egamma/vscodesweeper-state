# Issue #42203 — Support assigning numeric value to "editor.wrappingIndent"

[https://github.com/microsoft/vscode/issues/42203](https://github.com/microsoft/vscode/issues/42203)

## Summary

Numeric wrapping indentation remains unsupported: the merged deepIndent addition supplies another preset, not arbitrary numeric values. Keep this accepted Backlog request open; the related open requests are newer and describe different indentation semantics, so they are not valid duplicate targets for this re-reviewed item.

## Change summary

Allow configurable numeric indentation for soft-wrapped continuation lines instead of only named presets.

## Best solution

Define numeric wrapping-indent semantics that let continuation lines remain visually distinct from block indentation, while preserving existing presets and accessibility behavior. Resolve whether numbers represent spaces or tab-size multipliers before extending the editor option and both wrapping strategies.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts`, `src/vs/editor/browser/view/domLineBreaksComputer.ts`, `src/vs/editor/test/common/viewModel/monospaceLineBreaksComputer.test.ts`
- **Validation:** After agreeing on numeric semantics, exercise soft wrapping with tab sizes 2 and 4 and numeric amounts that existing presets cannot express, including the requested fractional case if supported. Verify both simple and advanced wrapping strategies, unchanged named presets, narrow wrapping widths, and the existing accessibility override; add targeted option-validation and line-break tests.
- **Behavior:**

  > Users want soft-wrapped continuation lines to have a configurable indentation amount distinct from normal block indentation. The existing none, same, indent, and deepIndent presets must retain their behavior. Acceptance should demonstrate a numeric amount unavailable through the presets under multiple tab sizes and both wrapping strategies. Whether numeric values count spaces or indentation levels, and whether fractional values are accepted, must be settled before those checks can specify exact expected columns.
- **Trace:**

  > WrappingIndentOption in src/vs/editor/common/config/editorOptions.ts accepts four string presets and falls back to Same for numbers. The simple wrapping path computes additional tab stops in computeWrappedTextIndentLength in src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts; the advanced path derives additionalIndentSize in src/vs/editor/browser/view/domLineBreaksComputer.ts. Both currently consume the WrappingIndent enum, whose numeric members are preset identifiers rather than user-specified indentation amounts. Preserve the screen-reader override in WrappingIndentOption.compute and do not change document text, formatting, or normal block indentation. https://github.com/microsoft/vscode/pull/50542 added only deepIndent; https://github.com/microsoft/vscode/issues/169804 and https://github.com/microsoft/vscode/issues/312719 describe related but distinct semantics. The remaining uncertainty is the public meaning of numeric values, not whether arbitrary values already work.
- **Open decisions:**
  - Should a numeric value specify additional spaces relative to the parent line, or a multiplier of the configured tab size?
  - Should fractional numeric values such as 1.5 be supported, and how should non-integral resulting column counts be rounded?
