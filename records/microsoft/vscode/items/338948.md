# Issue #338948 — Modern UI - Connected Tabs hover background alignment discrepancy

[https://github.com/microsoft/vscode/issues/338948](https://github.com/microsoft/vscode/issues/338948)

## Summary

Traced to a real inconsistency in the default color math: the opaque tab-action background (`modernEditorTab.hoverActionBackground`) is always composited over `editor.background` (src/vs/workbench/common/theme.ts:729), but the connected tab bar's actual backdrop is `editorGroupHeader.connectedTabsBackground` (README.md:157) — when the hover color has alpha, the close-button patch is flattened against the wrong base, producing the visible seam the reporter describes.

## Change summary

In Modern UI's connected tab style, the close-button's opaque hover background doesn't match the tab's own semi-transparent hover background, leaving a visible rectangle/seam.

## Best solution

Reconsider the base color(s) `opaque()` composites against for tab-action backgrounds so they track the actual rendered backdrop per tab style (e.g. `editorGroupHeader.connectedTabsBackground` for connected tabs) rather than always `editor.background`; this likely touches several sibling color registrations (active/hover/selected action backgrounds) in src/vs/workbench/common/theme.ts, not just one.

## Evidence

- **opaque compositing:** src/vs/workbench/common/theme.ts:729 registers MODERN_EDITOR_TAB_HOVER_ACTION_BACKGROUND as `opaque(MODERN_EDITOR_TAB_HOVER_BACKGROUND, editorBackground)` — always flattened against editor.background regardless of tab style.
- **mismatched backdrop:** src/vs/workbench/contrib/modernUI/README.md:157 documents `editorGroupHeader.connectedTabsBackground` (defaulting to `editorGroupHeader.tabsBackground`) as the actual background behind connected tabs — a different color than `editor.background` in many themes, so the opaque composite can visibly mismatch the real backdrop.
- **rendering path:** src/vs/workbench/contrib/modernUI/browser/media/tabs.css:405-453 paints a gradient fading the tab's (semi-transparent) hover background into the solid `--modern-ui-editor-tab-action-hover-background` right before the close button, so any base-color mismatch shows up exactly as reported: an edge discontinuity at the tab-actions boundary.
- **scope:** Several sibling colors use the same `opaque(..., editorBackground)` pattern (activeActionBackground, activeHoverActionBackground, selectedActionBackground at theme.ts lines ~725-733), so a correct fix likely needs to reconsider all of them together, not just the hover case.
