# Issue #267245 — No way to escape from VisualMode to NormalMode on Jupyter Focused Cell

[https://github.com/microsoft/vscode/issues/267245](https://github.com/microsoft/vscode/issues/267245)

## Summary

The Escape key in a notebook cell exits cell editing focus before the Vim extension can process it to leave Visual Mode. A team member has already triaged and is investigating — keeping open for resolution.

## Change summary

Pressing Escape in a Jupyter Notebook focused cell with Vim Visual Mode active loses cell focus instead of transitioning to Normal Mode.

## Best solution

The `QuitEditCellAction` Escape binding (in `src/vs/workbench/contrib/notebook/browser/controller/editActions.ts`) guards against `hasNonEmptySelection` but the Vim extension's Visual Mode selection may not set that context key, or another Escape path fires first. The notebook cell's Escape handling should yield to extensions (like Vim) that need to process Escape first when the editor is in a non-normal state. Rebornix is already cc'd — likely needs a `when` clause refinement or weight adjustment so Vim can intercept Escape before the cell exits editing.

This guard should prevent firing during Visual Mode selections, but the Vim extension may not set `hasNonEmptySelection` or another Escape path at line 127-131 (NOTEBOOK_OUTPUT_FOCUSED) may interfere.
