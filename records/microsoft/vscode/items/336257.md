# Issue #336257 — VSCode terminal wraps multiline command by truncating command to single line and did not provide override

[https://github.com/microsoft/vscode/issues/336257](https://github.com/microsoft/vscode/issues/336257)

## Summary

This is bash's own readline 'horizontal-scroll-mode' single-line editing behavior over SSH, not something the VS Code terminal renders or controls — the terminal is a raw PTY passthrough, and the same `<`/`>` truncation happens in any terminal emulator connected to that remote bash session.

## Change summary

Long commands typed at a bash prompt over SSH are shown truncated with `<`/`>` markers instead of wrapping across multiple lines, and `terminal.integrated.wrap` doesn't fix it.

## Best solution

Close as as-designed — the wrapping/truncation of the input line is decided by the remote bash/readline session (its `horizontal-scroll-mode` variable and reported terminal width), not by VS Code's terminal. Point the reporter at readline's `set horizontal-scroll-mode off` (in `~/.inputrc`) as the actual control, and note `terminal.integrated.wrap` is not a real VS Code setting.

What you're seeing is bash/readline's own single-line editing behavior (`horizontal-scroll-mode`) when a command line is longer than the terminal width — it truncates the visible line with `<`/`>` markers rather than wrapping, and this happens the same way in any terminal emulator connected to that shell, not just VS Code's integrated terminal. `terminal.integrated.wrap` isn't an actual VS Code setting (searching the source turns up no such config), so that's likely from an unrelated tool. Closing as as-designed since VS Code's terminal is faithfully passing through the remote shell's own line-editing behavior.
