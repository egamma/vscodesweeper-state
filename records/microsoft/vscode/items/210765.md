# Issue #210765 — ChatResponseCommandButtonPart's should have a way to signal they've been 'used'

[https://github.com/microsoft/vscode/issues/210765](https://github.com/microsoft/vscode/issues/210765)

## Summary

Keep open: current command-button APIs still cannot express dynamic enablement or a used state. The adopted text-edit workaround addresses the original Apply Changes scenario, but the discussion explicitly retains the broader API request and leaves response-scoped context lifetime unresolved.

## Change summary

Let chat participants signal that a response command button is no longer available after its action has been used.

## Best solution

Provide extension-controlled enablement for chat response command buttons, following the direction proposed in the discussion, with well-defined response isolation and cleanup. Settle the public state-lifetime contract before implementation rather than automatically making every command button single-use.
