# Issue #350028 — Sandbox profiles: concurrent windows can lose a host's last-known profile assignment

[https://github.com/microsoft/vscode/issues/350028](https://github.com/microsoft/vscode/issues/350028)

## Summary

Keep open: current source still permits concurrent windows to overwrite different hosts' remembered sandbox assignments. The assigned 1.149.0 milestone also explicitly protects this scheduled work from closure.

## Change summary

Preserve different hosts' last-known sandbox profile assignments when windows update shared storage concurrently.

## Best solution

Make remembered-assignment updates atomic across windows while preserving unavailable-state and explicit Default semantics. Verify delayed propagation between independent window caches retains both hosts, their disconnected profile display, and deletion protection.

## Evidence

- **Confirmed lost-update path:** src/vs/platform/agentHost/common/sandboxProfiles.ts: readSandboxProfileAssignments reads the APPLICATION_SHARED array through getObject; rememberSandboxProfileAssignment filters that cached array and replaces the entire stored value with storage.store. Two windows starting with the same empty cache write [A] and [B], so the later replacement loses A. This is a source trace, not an executed reproduction.
- **Observable consequences:** src/vs/workbench/contrib/sessions/providers/remoteAgentHost/browser/remotesTable.ts:552-562 uses readKnownHostSandboxProfile for disconnected hosts and selects Default when no assignment remains. src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/sandboxProfilesInput.ts:293-306 derives deletion protection from readSandboxProfileAssignments, so the lost entry also removes that protection.
- **Existing atomic storage boundary:** src/vs/platform/storage/common/storage.ts declares compareAndSwapApplicationSharedValue for atomic machine-only shared updates. src/vs/workbench/services/storage/electron-browser/storageService.ts:34-36 forwards it to the shared storage channel; rememberSandboxProfileAssignment currently does not use it.
- **Existing coverage:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/test/browser/sandboxProfiles.test.ts:182-188 covers unavailable state retaining an assignment and explicit Default clearing it, but that test uses one storage instance rather than independent caches with delayed propagation.
- **Related but distinct:** https://github.com/microsoft/vscode/issues/349914 is open, but describes windows overwriting live host-wide sandbox root configuration through AgentHostSandboxForwarder. This report concerns a separate renderer-side remembered-assignment array and its disconnected-host consumers, not the same failing storage path.
