# Issue #303044 — Support shipping TS-Go as a bundled extension with pre-release support

[https://github.com/microsoft/vscode/issues/303044](https://github.com/microsoft/vscode/issues/303044)

## Summary

The generic built-in auto-update groundwork now exists on main, but TS-Go is neither bundled nor configured for it, and the stable/nightly semver publishing problem remains unresolved. The accepted On Deck request should stay open in the TypeScript area.

## Change summary

Bundle the TS-Go language extension as the eventual replacement for the existing TypeScript extension while supporting stable and opt-in nightly release channels.

## Best solution

Ship TS-Go as a bundled extension with release builds selected for Stable and pre-release builds selected for Insiders, while preserving TypeScript's published version identity and providing a deliberate migration from `vscode.typescript-language-features`.

## Plan brief

- **Likely files:** `product.json`, `src/vs/platform/extensionManagement/common/extensionsScannerService.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts`, `src/vs/platform/extensionManagement/test/node/extensionsScannerService.test.ts`, `extensions/typescript-language-features/src/commands/useTsgo.ts`
- **Validation:** Extend the extension-management tests to verify that Stable selects and auto-updates only the TS-Go release channel while Insiders selects only the pre-release channel, then validate that a fresh product build exposes TS-Go without requiring a separate user installation.
- **Behavior:**

  > VS Code ships with TS-Go available as a bundled language extension instead of requiring users to install a separate preview extension. Stable builds consume release versions and Insiders builds consume pre-release nightly versions, with no channel mixing. Published extension versions retain a coherent relationship with TypeScript's npm versions. Existing users transition without duplicate active TypeScript language providers or loss of their selected channel.
- **Trace:**

  > The generic opt-in mechanism is present in `product.json`, `ExtensionsScannerService`, and `ExtensionsWorkbenchService`, but only `GitHub.copilot-chat` currently uses it. `ExtensionsScannerService` marks allow-listed built-ins for forced gallery updates only on Stable, so the Insiders pre-release selection and TS-Go adoption are not represented there. `extensions/typescript-language-features/src/commands/useTsgo.ts` still probes separate stable and nightly TS-Go extension IDs and treats their absence as requiring installation. PR https://github.com/microsoft/vscode/pull/308756 supplies generic update groundwork but does not implement this issue. Preserve the maintainer-stated Stable/release and Insiders/pre-release separation, and do not broaden the work into unrelated Marketplace update behavior.
- **Open decisions:**
  - Should Stable and Insiders consume channels of one Marketplace extension identity, or separate stable/nightly identities, given that Marketplace versioning cannot represent TypeScript's stable and semver-prerelease versions in one shared version space?
  - What user-visible migration contract should apply to existing installations of `typescriptteam.vscode-typescript`, `typescriptteam.vscode-typescript-nightly`, and the bundled `vscode.typescript-language-features` extension?

## Evidence

- **current configuration:** `product.json` lists only `GitHub.copilot-chat` in `builtInExtensionsEnabledWithAutoUpdates`; neither `typescriptteam.vscode-typescript` nor its nightly variant is configured or bundled through this mechanism.
- **main code path:** `src/vs/platform/extensionManagement/common/extensionsScannerService.ts` sets `forceAutoUpdate` only for allow-listed system extensions when product quality is `stable`; `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts` then includes those extensions in gallery update checks.
- **remaining TS-Go gap:** `extensions/typescript-language-features/src/commands/useTsgo.ts` still recognizes separate `typescriptteam.vscode-typescript` and `typescriptteam.vscode-typescript-nightly` IDs and reports that TS-Go is not installed when neither is present, confirming that current main has not completed the bundled replacement.
- **landed groundwork:** https://github.com/microsoft/vscode/pull/308756 merged generic fixes for scanning and updating built-in extensions enabled for auto-update, but it does not reference https://github.com/microsoft/vscode/issues/303044 or adopt TS-Go on the reported path.
- **maintainer direction:** https://github.com/microsoft/vscode/issues/303044#issuecomment-4089428633 proposes locking release versions to Stable and pre-release versions to Insiders, while https://github.com/microsoft/vscode/issues/303044#issuecomment-4087121405 explains that Marketplace versioning cannot currently preserve both npm-compatible stable and prerelease semver in one version space.
- **canonical search:** Focused searches found no older open issue with the same observable request; the nearby built-in auto-update issues concern regressions in the generic mechanism rather than ownership of TS-Go bundling and release-channel support.
