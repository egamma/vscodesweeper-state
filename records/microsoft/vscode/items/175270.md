# Issue #175270 — FR: Allow extension views to be defined as a fixed height.

[https://github.com/microsoft/vscode/issues/175270](https://github.com/microsoft/vscode/issues/175270)

## Summary

Valid, unimplemented feature request for an extension API that lets views declare a fixed height (not proportionally scaled). No existing setting, API, or canonical duplicate covers this. Sits in Backlog with 8 upvotes — below the 20-upvote promotion threshold but worth keeping open for the community process.

## Change summary

Allow extension-contributed views to declare a fixed height in package.json so they don't scale proportionally when the viewport resizes.

## Best solution

Add an optional `fixedHeight` (or similar) property to the view contribution point in `package.json` and wire it through the view pane layout in `src/vs/workbench/browser/parts/views/viewPane.ts` so that panes with this flag maintain their user-set height when the container resizes, only scaling when space is insufficient. This is an API addition that touches the extension manifest schema and the SplitView layout distribution logic.
