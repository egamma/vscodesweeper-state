# Issue #302245 — Poor completion sorting for whole words in JSON settings

[https://github.com/microsoft/vscode/issues/302245](https://github.com/microsoft/vscode/issues/302245)

## Summary

Still reproduces on main — the scoring algorithm in filters.ts penalizes matches late in a word regardless of camelCase boundaries, so typing 'modal' ranks 'useModal' lower than closer-to-start matches. No fix has been committed; the discussion between the author and jrieken about reducing the penalty for camelCase transitions is still open.

## Change summary

Typing a whole camelCase segment (e.g. 'modal') in JSON settings autocomplete does not surface the matching setting 'workbench.editor.useModal' in the top results because late-word matches are penalized.

## Best solution

Adjust the scoring in `src/vs/base/common/filters.ts` (around the gap/skip penalty logic, lines ~828-895) to reduce the penalty when the matched substring aligns with a full camelCase segment boundary deep in the word. The `under-discussion` label is appropriate — this needs jrieken's input on the right trade-off between prefix-favoring and camelCase-segment matching.
