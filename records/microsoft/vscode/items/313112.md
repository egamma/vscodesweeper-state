# Issue #313112 — Agents: Enable right-click context menu options for files in Changes panel

[https://github.com/microsoft/vscode/issues/313112](https://github.com/microsoft/vscode/issues/313112)

## Summary

Keep open: the Changes file list still lacks the right-click file menu available in Files. The matching newer request adds useful demand but cannot replace this older, previously reviewed issue.

## Change summary

Provide context-menu actions on file names in the Agents Window Changes panel, comparable to those in Files.

## Best solution

Provide applicable file actions directly from Changes file rows, with correct session-resource targeting and keyboard access. Decide which Files actions belong on this surface rather than copying every Explorer operation indiscriminately.

Invoke the same menu with Shift+F10 on a focused row. Repeat in list/tree modes and the modal Changes sidebar, and confirm existing file opening, inline actions, and Files menus remain unchanged.
- **Behavior:**

  > Users can invoke applicable file actions directly from file names in the Agents Window Changes panel without switching to Files. The menu is available through right-click and keyboard invocation, and operations target the selected session's resource rather than another workspace. Acceptance checks cover the approved action set, clicked-file and multi-selection targeting, and unchanged existing navigation. The exact action set remains a maintainer decision.
- **Trace:**

  > ChangesViewPane.createChangesTree in src/vs/sessions/contrib/changes/browser/changesView.ts constructs the shared WorkbenchCompressibleObjectTree used by the main Changes list and renderSidebarList, but does not register onContextMenu. ChangesTreeRenderer supplies scoped inline actions through MenuId.AgentsChangeInlineToolbar, which does not deliver the requested right-click menu. SessionsExplorerView in src/vs/sessions/contrib/files/browser/filesView.ts inherits ExplorerView; ExplorerView.onContextMenu supplies MenuId.ExplorerContext with clicked-resource, selection, and context-key handling. These are the relevant existing behaviors, not a prescribed implementation. Preserve session/worktree targeting, existing inline actions, and file-opening behavior; do not assume all Explorer mutation commands apply to historical, deleted, or remote changes. https://github.com/microsoft/vscode/issues/328730 adds a specific request for discard/revert, while https://github.com/microsoft/vscode/issues/318793 concerns filtering editor-content menus rather than file-row menus.
- **Open decisions:**
  - Should Changes offer the full applicable Files menu or a smaller review-oriented action set, and should this request include per-file Discard/Revert Changes?
