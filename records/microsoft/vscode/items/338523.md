# Issue #338523 — "\b" search (with regex enabled) will report false positives if next letter contains diacritics

[https://github.com/microsoft/vscode/issues/338523](https://github.com/microsoft/vscode/issues/338523)

## Summary

Reproduced: native JavaScript `RegExp` `\b` treats only ASCII `[A-Za-z0-9_]` as word characters, so a diacritic like `ä` in "Bänder" is treated as a non-word char and creates a boundary right after `B`. VS Code's editor Find passes the user's regex straight to the native `RegExp` engine with no post-processing, so this is a real, in-scope defect in the editor search feature, not something already fixed on main.

## Change summary

Regex search with `\bB\b` incorrectly matches inside words like "Bänder" because diacritic letters aren't treated as word characters by `\b`.

## Best solution

Make `\b`/`\B` word-boundary matching in the editor's regex search Unicode-aware (e.g. reusing the existing `WordCharacterClassifier` logic already used for the separate "whole word" option) so boundaries respect letters with diacritics, rather than falling back to native ASCII-only JS `\b` semantics.
