# Issue #341760 — Agent Host: remote prompts with command-… source missing from VS Code chat

[https://github.com/microsoft/vscode/issues/341760](https://github.com/microsoft/vscode/issues/341760)

## Summary

Thanks for the detailed report. The cited skip is still on main: any `user.message` whose `source` is not `user` (including `command-<id>` from /remote prompts sent via GitHub.com) is treated as synthetic and dropped, so the prompt never reaches the turn or history. The assistant's response then arrives with no active turn, which matches the logged 'Markdown delta emitted with no active turn; dropping'. The right way to tell remote-prompt command sources apart from other SDK-injected sources is not established, so this is a confirmed defect but not an implement-ready fix.

## Change summary

Prompts sent from GitHub.com to a remote-enabled Copilot Agent Host session are not shown in VS Code chat, and their responses are dropped.

## Best solution

Treat `command-*` sourced user messages (remote steering prompts) as genuine user prompts in the live handler, and in history replay and instruction telemetry. Begin a provider-initiated turn for them so the response renders, while still skipping other SDK-injected sources.
