## Summary

Real concern about reload discarding active agent state, but the report is thin — VS Code already has a lifecycle veto that warns before reload when a chat/agent session is in progress, so it's unclear whether that safeguard didn't fire, was dismissed, or doesn't cover the reporter's specific scenario (external CLI agents, dev container disconnect).

## Change summary

Clicking 'Reload Window' (from the Extensions update prompt) reloads the whole process, disconnecting the Dev Container and losing in-progress Codex/Claude Code/Copilot agent context, with no clear warning.

## Best solution

Confirm with the reporter whether a 'session in progress, are you sure you want to reload?' dialog appeared (src/vs/workbench/contrib/chat/electron-browser/chatLifecycle.ts / chat.contribution.ts already implements this for ShutdownReason.RELOAD); if it didn't fire for their scenario, investigate whether shouldWarnForSessionShutdown's isSessionInProgressStatus check misses idle-but-unsaved sessions or externally-hosted agent providers (Codex/Claude Code via agent host), and extend coverage there.

## Evidence

- **existing safeguard:** src/vs/workbench/contrib/chat/electron-browser/chat.contribution.ts's ChatLifecycleHandler already vetoes onBeforeShutdown for ShutdownReason.RELOAD and shows a confirm dialog ('The session will stop if you reload the window.') via confirmSessionShutdown in chatLifecycle.ts, gated on shouldWarnForSessionShutdown(session, reason) which checks isSessionInProgressStatus.
- **possible gap:** shouldWarnForSessionShutdown only warns when a session status is 'in progress' (or for local agent-host targets only on QUIT) — if the reporter's Codex/Claude Code/Copilot session was idle or run through a provider not covered, no dialog would appear, matching what they describe (no mention of any prompt).
- **extensions reload path:** Extensions view 'Reload Window' prompts call hostService.reload() (e.g. src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts:1602), which should route through the same reload lifecycle veto as any other reload trigger.
