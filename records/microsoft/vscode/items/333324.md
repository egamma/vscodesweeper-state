# Issue #333324 — VS Code Reload Window Can Discard Active Agent State

[https://github.com/microsoft/vscode/issues/333324](https://github.com/microsoft/vscode/issues/333324)

## Summary

The reporter narrowed this to valid UX polish: the Extensions view's “Reload Window” action does not communicate that active extension-host, agent, and remote work may be interrupted. The claimed permanent session loss remains unverified, but the wording concern is directly confirmed in current source and belongs with the existing extensions-view routing.

## Change summary

Clarify the extension-update reload affordance so users understand its impact on active agent and remote work before invoking it.

## Best solution

Keep terminology consistent with VS Code's established window-reload operation while adding enough context, deferral, or confirmation in the Extensions surface to warn about interruption of active work. The area owner should decide whether that explanation is always shown or only when interruptible work can be detected.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsActions.test.ts`
- **Validation:** Add or update targeted extension-workbench tests to assert the approved reload message and action copy, then manually verify the Extensions update affordance while active work is present and confirm that users can defer without triggering IHostService.reload().
- **Behavior:**

  > When an extension update requires a window reload, the Extensions surface must clearly communicate that invoking the action can interrupt active extension-host, agent, and remote work. Users must be able to defer the reload. The standard Developer: Reload Window command and ordinary extension restart behavior should remain unchanged unless the maintainer explicitly chooses broader terminology.
- **Trace:**

  > The restart-required notification is assembled in src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts and calls IHostService.reload() directly when any updated extension requires ExtensionRuntimeActionType.ReloadWindow. The per-extension action in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts exposes the same label and call. Current source therefore confirms the potentially ambiguous affordance, but not the reported permanent loss of sessions or shutdown of the dev container. Keep the first pass bounded to extension-update reload affordances; do not redesign agent persistence or globally rename workbench.action.reloadWindow without a separate decision.
- **Open decisions:**
  - Should the Extensions surface retain “Reload Window” with explanatory warning text, or use different action wording specifically for extension-required reloads?
  - Should the warning appear for every extension-required reload, or only when VS Code can detect active agent, task, terminal, or remote work?
