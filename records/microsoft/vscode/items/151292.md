# Issue #151292 — Workbench navigation commands stop working inside WebView when switching to another editor and back

[https://github.com/microsoft/vscode/issues/151292](https://github.com/microsoft/vscode/issues/151292)

## Summary

Still reproduces on main: after switching editors within the same group and back to a webview, the iframe may not regain document.activeElement status, so key events aren't forwarded through handleKeyEvent and navigation commands stop working. The `help wanted` label is appropriate — no fix has landed.

## Change summary

Workbench navigation keybindings (navigateLeft/Right) stop working from inside a WebView after switching to another editor in the same group and back.

## Best solution

Fix the webview focus restoration path so that when a webview editor regains visibility in its group, the iframe reliably becomes document.activeElement (or relax the isActiveElement guard in handleKeyEvent to also accept the webview's internal _focused state). The fix likely touches src/vs/workbench/contrib/webview/browser/webviewElement.ts (isActiveElement / handleFocusChange) and potentially the webview editor's setVisible/focus lifecycle.
