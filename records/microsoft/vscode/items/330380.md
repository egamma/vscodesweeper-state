# Issue #330380 — CLI migration setting shows sessions that didn't come from vscode

[https://github.com/microsoft/vscode/issues/330380](https://github.com/microsoft/vscode/issues/330380)

## Summary

Confirmed defect reported by a team member while testing a new setting, and there is already an open fixing PR (#330392, 'Fixes #330380') that traces the exact root cause; keep open until that PR merges rather than closing prematurely.

## Change summary

Enabling chat.agentSessions.migrateLegacyCopilotCli surfaces and migrates sessions from the GitHub Copilot app (not VS Code) because adoption only checked for the presence of a marker file, not its origin field.

## Best solution

Land https://github.com/microsoft/vscode/pull/330392, which changes _isExtensionHostCliSession in src/vs/platform/agentHost/node/copilot/copilotAgent.ts to require the marker's origin field equal 'vscode' (treating missing-origin markers as legacy-eligible for backward compatibility) before adopting a session.
