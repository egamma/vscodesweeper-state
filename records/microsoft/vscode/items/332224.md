# Issue #332224 — Custom glyphs are disabled in auxiliary terminal windows

[https://github.com/microsoft/vscode/issues/332224](https://github.com/microsoft/vscode/issues/332224)

## Summary

Traced and confirmed on current main: the auxiliary-window guard from PR #330777 is still in place and disables all custom glyphs (not just the crashing pattern-glyph path) whenever a terminal is detached into its own window. The upstream xterm.js fix has merged, but VS Code hasn't consumed a version containing it yet, so this stays open pending that dependency bump and guard removal — already correctly labeled `bug`/`upstream`/`regression`.

## Change summary

Moving a terminal to an auxiliary (dedicated) window disables all custom glyph rendering (box drawing, Powerline, Braille, progress, etc.), not just the pattern-glyph path that originally crashed.

## Best solution

Once @xterm/addon-webgl ships a release containing xtermjs/xterm.js#6128 (OffscreenCanvas-based pattern source with main-document fallback), bump the pinned version in package.json and remove the `ownerDocument === this._mainDocument` guard in `_getWebglCustomGlyphs()` (src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts) so custom glyphs stay enabled in dedicated windows.
