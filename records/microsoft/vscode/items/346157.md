- **Global configuration has partial compatibility:** src/vs/platform/mcp/common/mcpCopilotGlobalConfiguration.ts:21-49 rejects interactive inputs and '${input:' but does not blanket-reject '${secret:...}'. This differs from the issue's description of both writers, but accepting the string alone does not implement prompting or secret management.
- **Session callback gap:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:1757-1763 registers permission, user-input, elicitation, and MCP OAuth callbacks, but not onMcpSecretRequest. Searches across src and extensions/copilot found no onMcpSecretRequest, mcp.secrets, or needs-secret integration.
- **Existing secret capability is not full coverage:** src/vs/platform/agentHost/node/copilot/customizations/copilotCustomizationInstallations.ts:66-67,565-569,2114-2126 handles configured-installation secret answers with keychain storage and '${installation-secret:...}' references. That path is distinct from resolving arbitrary '${secret:<id>}' entries in workspace and Copilot-global configuration files.
