## Summary

Keep open: current main still synthesizes HydraFusion picker entries when the runtime catalog omits them, preserving the reported availability mismatch. The related telemetry tracking issue does not replace this user-facing defect.

## Change summary

Prevent users from selecting HydraFusion when their runtime cannot execute it under account policy or rollout eligibility.

## Best solution

Make runtime admission authoritative for selectable HydraFusion models, with discovery and turn execution agreeing on account, policy, rollout, and experimental-mode eligibility. Coordinate the runtime/SDK contract with VS Code catalog consumption rather than duplicating admission rules in the host.
