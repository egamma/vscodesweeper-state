# Issue #339959 — HydraFusion is offered in the picker to users whose runtime rejects every turn

[https://github.com/microsoft/vscode/issues/339959](https://github.com/microsoft/vscode/issues/339959)

## Summary

Confirmed on main: `_publishModels` in copilotAgent.ts injects HydraFusion into the picker purely from the `chat.copilot.hydraFusion.enabled` setting, with no visibility into the runtime's stricter session-level admission gate, exactly as described. This is a fresh, well-diagnosed, team-authored report with a concrete proposed fix spanning the runtime and the client — stays open for implementation.

## Change summary

VS Code offers HydraFusion in the model picker even to users whose runtime will reject every HydraFusion turn, inflating its error rate and leading users to a dead end.

## Best solution

Make the runtime's client-level models.list authoritative for HydraFusion admission (same gate as turn execution), then have VS Code's _publishModels stop injecting HydraFusion unconditionally and instead trust that list — picked up via an SDK bump; optionally show a disabled entry with a policy.state reason per the existing Free-user upgrade UX.
