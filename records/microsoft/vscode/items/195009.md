# Issue #195009 — [webviews] deserializeWebviewPanel is not called when switching workspace trust to restricted

[https://github.com/microsoft/vscode/issues/195009](https://github.com/microsoft/vscode/issues/195009)

## Summary

Still present on main: the webview panel serialization/deserialization path has no workspace-trust-aware restore logic. When trust changes to restricted and an extension is stopped/restarted, `deserializeWebviewPanel` is not invoked for surviving webview panels, leaving them orphaned.

## Change summary

When workspace trust is set to restricted, extensions are restarted but `deserializeWebviewPanel` is not called for existing webview panels, rendering them unusable.

## Best solution

When workspace trust changes trigger an extension host restart, the webview panel restore flow (in `src/vs/workbench/contrib/webviewPanel/browser/webviewEditorInputSerializer.ts`) should trigger deserialization for panels whose owning extension was stopped and restarted, similar to what happens on window reload.
