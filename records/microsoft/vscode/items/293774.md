# Issue #293774 — Add Selection to Chat incompatible with standalone copilot chat window?

[https://github.com/microsoft/vscode/issues/293774](https://github.com/microsoft/vscode/issues/293774)

## Summary

Keep open: the supplied steps suffice to retest selection retention in a detached Chat window, but the exact failure was not confirmed through read-only inspection. Chat window/session handling has changed since 1.109.0; neither a verified canonical nor a fixing commit covering this behavior was established.

## Change summary

An explicitly added editor selection disappears from a detached Chat window's pending prompt after switching editor tabs.

## Best solution

Ensure explicitly attached selections retain their original file and range when editor tabs change, including with Chat in a separate window. First distinguish a failed explicit attachment during focus transfer from replacement of implicit active-editor context.

- **Behavior:**

  > An editor selection explicitly added through Add Selection to Chat must remain attached to the pending prompt when the user switches editor tabs. This must work when Chat is in a separate window as well as when docked. Acceptance checks should distinguish the retained explicit attachment from implicit context that legitimately follows the active editor, and confirm the original file/range is included on submission.
- **Trace:**

  > AttachSelectionToChatAction.run in src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts resolves the Chat widget before reading the active editor and selection. ChatWidgetService.revealSessionIfAlreadyOpen in src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts can open and focus a Chat editor in another window and wait for focus transfer. The historical explanation at https://github.com/microsoft/vscode/issues/248885#issuecomment-2882261082 identifies activeTextEditorControl as unsuitable once the Chat editor is active, but the current report's exact path was not confirmed. ChatAttachmentModel stores explicit URI/range entries separately from ChatImplicitContextContribution, which updates implicit context on editor changes. ## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/293774 specifies VS Code 1.109.0 on Windows 11, moving Chat into a new window, invoking Add Selection to Chat from the editor context menu, and switching to another editor tab. No comments confirm or resolve the report.
- **Explicit attachment path:** src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts: AttachSelectionToChatAction.run awaits withChatView before reading activeTextEditorControl and activeEditor, then calls widget.attachmentModel.addFile(activeUri, range). The ordering makes focus transfer relevant, but does not conclusively establish the reported disappearance.
- **Explicit versus implicit context:** src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentModel.ts stores explicit file/range entries in a Map; its file watcher removes them on file deletion, not editor-tab changes. By contrast, ChatImplicitContextContribution in src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts subscribes to active-editor changes and replaces implicit context values. These are distinct paths requiring runtime differentiation.
