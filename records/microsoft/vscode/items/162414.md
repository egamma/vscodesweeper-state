## Evidence

- **Confirmed reproduction in discussion:** https://github.com/microsoft/vscode/issues/162414 includes specific steps copying this issue's title from Safari on iPad, with search, command palette and terminal accepting the text. Independent commenters reproduced browser-to-editor failures on versions 1.75.1, 1.77.0, 1.83.0, 1.84.1 and 1.89.1; the original report used disabled extensions.
- **Current basic paste path:** src/vs/editor/browser/controller/editContext/clipboardUtils.ts: ClipboardEventUtils.getTextData reads plain text and, when it is empty and editor metadata is absent, substitutes clipboard file names. NativeEditContext's paste listener in src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts passes that result to the view controller. A file-only RTFD payload therefore explains the reported filename, but source inspection cannot prove that current macOS still supplies that payload.
- **Current provider paste path:** src/vs/editor/browser/dataTransfer.ts: toExternalVSDataTransfer converts clipboard files into URI-list entries. CopyPasteController.handlePaste in src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts dispatches those representations to providers; PathProvider in browser/defaultProviders.ts can insert file paths. Neither this conversion nor the basic filename fallback extracts the text represented by an RTFD item.
