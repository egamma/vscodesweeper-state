# Issue #171457 — Allow line specific word wrap toggling

[https://github.com/microsoft/vscode/issues/171457](https://github.com/microsoft/vscode/issues/171457)

## Summary

This remains a valid backlog feature request with strong community support: it received 47 upvotes and was explicitly promoted to the Backlog. The related language-aware wrapping issue overlaps with automatic Markdown handling but does not fully own this broader request for explicit line-specific wrap control across formats.

## Change summary

Allow selected lines or ranges to remain unwrapped while word wrapping stays enabled for the rest of a document.

## Best solution

Define editor-level semantics for mixed wrapped and unwrapped view lines, then extend the wrapping and horizontal-scroll model so designated ranges remain on one visual line without changing document text. Language-aware exclusions such as Markdown tables could build on that primitive, but the design must also cover manual ranges and non-Markdown formats.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/viewParts/lines/viewLines.ts`, `src/vs/editor/browser/viewModel/viewModelImpl.ts`
- **Validation:** Add editor browser tests covering a document with wrapping enabled and a designated unwrapped range: ordinary lines wrap, designated lines remain single visual lines, horizontal scrolling reveals their full content, and editing or moving the range updates the layout correctly.
- **Behavior:**

  > A document can keep word wrapping enabled globally while designated lines or ranges remain unwrapped. Wrapped and unwrapped content must coexist without changing the document text, and horizontal scrolling must expose the full width of unwrapped lines without disturbing wrapped-line layout. Acceptance should cover manual designation, edits that move or invalidate ranges, and at least Markdown-table and reStructuredText-style content.
- **Trace:**

  > The request crosses editor wrapping configuration, view-model line projection, and horizontal layout rather than being only a Markdown feature. Likely entry points are src/vs/editor/common/config/editorOptions.ts, src/vs/editor/browser/viewModel/viewModelImpl.ts, and src/vs/editor/browser/viewParts/lines/viewLines.ts. The related open issue https://github.com/microsoft/vscode/issues/164267 concerns automatic language-aware wrapping and may consume the same lower-level capability, but it does not cover explicit per-line control or the reported reStructuredText case. The boundary is view presentation: document contents, formatter behavior, and language semantics must remain unchanged.
- **Open decisions:**
  - Should unwrapped ranges be selected manually, supplied by language features through decorations, or support both sources?
  - How should range state track insertions, deletions, undo, file reloads, and editor restoration?
  - Should horizontal scrolling be global for the editor viewport or constrained to the unwrapped visual lines?
  - Is the first supported scope a generic editor primitive or language-aware wrapping for structured Markdown and reStructuredText constructs?
