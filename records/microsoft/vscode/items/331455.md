# Issue #331455 — Copilot Chat OTel export only emits utility-model spans, never the active chat model (GPT-5/Claude)

[https://github.com/microsoft/vscode/issues/331455](https://github.com/microsoft/vscode/issues/331455)

## Summary

Real, independently-confirmed bug in Copilot Chat's OTel export: current main does contain a `chat ${model}` span construction with a real `gen_ai.request.model` in chatMLFetcher.ts, but two independent reporters (across 0.61.0/1.133.0 and 0.62.0/1.134.0) show that only utility spans from the `copilotLanguageModelWrapper` debug name (languageModelAccess.ts) actually reach the exporter, so the main conversation turn's model/agent never shows up in the OTLP/sqlite output.

## Change summary

Copilot Chat's OTel export never emits a span for the actively selected chat model (GPT-5/Claude); every exported span is tagged gen_ai.agent.name=copilotLanguageModelWrapper / gpt-4o-mini-2024-07-18, which are background utility calls, not the visible conversation.

## Best solution

An engineer familiar with the OTel pipeline needs to trace why the Agent-mode conversation loop's real inference span (extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts ~line 1041, `chat ${chatEndpointInfo.model}`) and the `invoke_agent` span (extensions/copilot/src/extension/intents/node/toolCallingLoop.ts ~line 1264) aren't reaching the configured exporter, versus why the vscode.lm wrapper span in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts (debugName 'copilotLanguageModelWrapper') dominates the output — likely a config/sampling/export-filter gap rather than a missing feature, since the span-construction code for the real model already exists on main.
