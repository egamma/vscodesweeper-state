## Summary

Detailed, forensic-quality bug report (raw OTLP payloads for two model selections, attached vscode-otel-bug-report.md) claiming the actual conversation-turn chat span is never exported, only utility/wrapper spans — plausible but I could not pin the exact defect by reading the source, so this needs maintainer/OTel-owner investigation rather than a close.

## Change summary

Copilot Chat's OTel export never emits a `chat` span for the user's selected conversation model (GPT-5/Claude); only background utility calls (title summarization via `copilot-utility-small`) and the public `vscode.lm` API wrapper (`copilotLanguageModelWrapper`) show up in captured OTLP/SQLite output.

## Best solution

An OTel maintainer should trace why the agent-mode conversation's `chat` span (created in extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts with debugName set from defaultIntentRequestHandler.ts's `${location}/${intentId}`, e.g. `agent/agent`) never reaches the DiagnosticSpanExporter/SqliteSpanExporter for long-running streaming/tool-calling agent turns, while short single-shot requests (title, wrapper) do — likely a span-not-ended or context-propagation gap specific to the agent tool-calling loop.
