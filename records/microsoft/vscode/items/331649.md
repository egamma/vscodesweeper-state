# Issue #331649 — [Error] [GitHub.copilot-chat] unhandlederror-Task API request failed: 503 Service Unavailable

[https://github.com/microsoft/vscode/issues/331649](https://github.com/microsoft/vscode/issues/331649)

## Summary

Traced on main: `provideChatSessionItems` in copilotCloudSessionsProvider.ts calls `_backend.fetchSessionList(...)` with no try/catch, so a transient 503 (or any) Task API failure becomes an unhandled promise rejection surfaced to the error-telemetry dashboard, instead of being handled gracefully the way the background-refresh path already does.

## Change summary

A Task API 503 during a manual/foreground chat-sessions refresh throws an unhandled `TaskApiError` instead of failing gracefully.

## Best solution

Wrap the `fetchSessionList` call (and subsequent processing) inside `provideChatSessionItems` in a try/catch, mirroring the pattern already used in the background-refresh scheduler (log via `this.logService.error` and fall back to cached/empty items) so transient Task API outages don't surface as unhandled errors.
