# Issue #123987 — [html] allow to configure html formatter for other languages

[https://github.com/microsoft/vscode/issues/123987](https://github.com/microsoft/vscode/issues/123987)

## Summary

The requested user-configurable language mapping still does not exist, while the later extension contribution point only lets extension authors opt languages into HTML support. This must remain open because the HTML owner explicitly classified it as a feature request and placed it in the Backlog after explaining the preferred extension-owned design.

## Change summary

Allow users to configure the built-in HTML formatter as the formatter for other language identifiers such as Django HTML or Jinja HTML.

## Best solution

Keep language ownership with template-language extensions: they should opt into the HTML language server through `htmlLanguageParticipants`, with the remaining activation problem tracked by https://github.com/microsoft/vscode/issues/160585. A user-controlled override should proceed only if the HTML owner revisits the accepted Backlog item and explicitly accepts the unsupported-formatting expectations it would create.

## Vision fit

- **Fit:** rejected
- **Reason:** A core setting that forces HTML behavior onto arbitrary languages cuts against extension-owned language capabilities and adds configuration for a niche compatibility path.
- **Evidence:** Value and guardrail: “The power lives in extensions”; capabilities that can be supplied through the extension API generally belong with the language extension.
