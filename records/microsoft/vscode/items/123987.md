# Issue #123987 — [html] allow to configure html formatter for other languages

[https://github.com/microsoft/vscode/issues/123987](https://github.com/microsoft/vscode/issues/123987)

## Summary

The HTML area maintainer explicitly placed template-language formatting with the owning language extension, and current VS Code provides an extension contribution for reusing the HTML language server. A user-controlled core override would expose unsupported syntax as HTML, so this is best closed as an extension candidate.

## Change summary

Allow users to select the built-in HTML formatter for Django, Jinja, and other HTML-derived language modes.

## Best solution

The extension that contributes the Django or Jinja language should opt that language into the HTML language server through `htmlLanguageParticipants`, or provide its own formatter when its syntax needs different handling.

## Vision fit

- **Fit:** rejected
- **Reason:** Support for a specialized template language belongs with its language extension, which can define the compatibility boundary and avoid making unsupported behavior part of VS Code core.
- **Evidence:** Value and guardrail: “The power lives in extensions”; capabilities that can be delivered through the extension mechanism should generally remain outside the lightweight core.

## Evidence

- **maintainer position:** The HTML area maintainer stated in https://github.com/microsoft/vscode/issues/123987#issuecomment-925624690 that Django syntax is not reliably compatible with the HTML formatter and that the proper solution is a Django extension implementing the formatter.
- **extension integration:** Commit cef02dae8d29da2388b0f43221ae79f5a86a3bf3 (https://github.com/microsoft/vscode/commit/cef02dae8d29da2388b0f43221ae79f5a86a3bf3) added the `htmlLanguageParticipants` contribution for extensions to register custom language IDs with the HTML language server.
- **current source:** On current main, extensions/html-language-features/client/src/languageParticipants.ts builds the document selector from contributed `htmlLanguageParticipants`, and extensions/html-language-features/client/src/htmlClient.ts registers HTML range formatting against that selector. extensions/handlebars/package.json demonstrates the contribution.
- **remaining distinction:** Current main does not expose the requested user setting; participation is deliberately declared by the extension that owns the language, preserving responsibility for syntax compatibility.
