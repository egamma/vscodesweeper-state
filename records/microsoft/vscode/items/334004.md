# Issue #334004 — Instructions buggy when running in WSL

[https://github.com/microsoft/vscode/issues/334004](https://github.com/microsoft/vscode/issues/334004)

## Summary

Traced in source: `promptsHome` (and user data profile locations generally) always resolve to the local/client-side profile folder — `src/vs/platform/userDataProfile/common/userDataProfile.ts` joins `location` (the profile's local storage path) with `'prompts'` — so 'User' scope instructions are, by design, stored and read from the local machine even in a WSL remote window, exactly like user settings/snippets/keybindings. That explains both symptoms the reporter sees, but it's unclear whether the maintainers consider this working-as-intended or a gap worth fixing for remote scenarios, and the thread with aeschli is still active, so this shouldn't be closed yet.

## Change summary

In a WSL remote window, 'New Instructions (User)' only offers a Windows-side path, and instructions placed by hand under the WSL `.vscode-server` profile folder are never loaded.

## Best solution

A maintainer with prompts/AI-customization ownership should confirm whether user-scope instructions are intentionally local-only (consistent with user settings/snippets architecture) or whether remote-aware resolution should be added; if intentional, an `*as-designed` close referencing the profile architecture would be appropriate, otherwise this needs product/architecture work in `src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts` and `askForPromptSourceFolder.ts`.
