# Issue #334004 — Instructions buggy when running in WSL

[https://github.com/microsoft/vscode/issues/334004](https://github.com/microsoft/vscode/issues/334004)

## Summary

Freshly filed, no maintainer triage yet beyond the automated version-check comment. Tracing the source confirms the reported behavior: the 'User' instructions/prompts location is resolved from the client-side user data profile with no remote-authority awareness, so in a WSL/SSH remote window it always points at the local Windows path and never the remote `.vscode-server` side, and manually-placed remote files aren't picked up either.

## Change summary

In a remote WSL window, 'New Instructions (User)' only offers a Windows-side path (not the remote .vscode-server location), and hand-created instructions on the WSL side aren't loaded into chat.

## Best solution

A maintainer needs to decide whether 'User' prompts/instructions should become remote-authority-aware (mirroring how remote-scoped settings.json works) or whether this is intentionally client-only like other user-profile data — the resolution happens in `IUserDataProfile.promptsHome` (src/vs/platform/userDataProfile/common/userDataProfile.ts) and is consumed unconditionally in `promptsServiceImpl.ts` (`this.userDataService.currentProfile.promptsHome`) with no `remoteAuthority`/`Schemas.vscodeRemote` branch.
