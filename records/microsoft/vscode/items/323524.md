# Issue #323524 — can't drag workspace section down

[https://github.com/microsoft/vscode/issues/323524](https://github.com/microsoft/vscode/issues/323524)

## Summary

The workspace-section reorder gap remains visible in current source: header drags are accepted only when the immediate drop target is another top-level header, so dragging downward over an expanded workspace's child session is ignored. This team-authored bug should remain open for a focused fix.

## Change summary

Allow a promoted workspace section to be dragged back down or positioned below another workspace section in the Agents Window sessions list.

## Best solution

Make top-level workspace-header reordering resolve the intended neighboring section even when a downward drop lands on that section's first descendant, while preserving fixed-section restrictions, workspace promotion, and persisted ordering.

- **Behavior:**

  > In workspace grouping, a workspace section promoted from the more-workspaces group can subsequently be dragged both upward and downward. Dropping immediately below another workspace header places the dragged workspace after that complete workspace section, even when the pointer is over its first child row. Fixed sections remain invalid targets, and the resulting order persists.
- **Trace:**

  > The report comes from the drag-and-drop coverage in https://github.com/microsoft/vscode/issues/323084. Current SessionsListDragAndDrop in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts recognizes a dragged workspace header, but onHeaderDragOver and drop accept the immediate target only when headerRefOf returns a group or workspace-section identity. Tree DnD supplies the actual child session when a downward gesture crosses into an expanded workspace, so that path returns no target and performs no reorder. SessionsList.reorderSection and SessionSectionOrderService.spliceSectionOrder already support after-target moves; preserve their promotion, ordering, and persistence semantics. Do not make pinned, archived, date, show-more, or other fixed sections reorderable.

## Evidence

- **current source:** In src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, SessionsListDragAndDrop.onHeaderDragOver and drop call headerRefOf(targetElement); headerRefOf recognizes only ISessionGroupItem and workspace ISessionSection values, so a child session reached while dragging downward is rejected instead of resolving its containing workspace.
- **ordering path:** SessionsList.reorderSection delegates to ISessionSectionOrderService using _topLevelOrder, and spliceSectionOrder already supports moving an item after a target. The remaining gap is therefore bounded to resolving the drop target in the tree DnD path rather than the persisted-order algorithm.
- **expected behavior:** The referenced test plan https://github.com/microsoft/vscode/issues/323084 explicitly requires workspace headers to move before or after another workspace and persist; the report was filed while exercising that scenario.
