# Issue #214909 — Terminal does not detect failure in activated environments when activated using PS1 script

[https://github.com/microsoft/vscode/issues/214909](https://github.com/microsoft/vscode/issues/214909)

## Summary

Still reproduces on main: the shell integration PS1 script reads `$?` at the top of its `Prompt()` function (line 107), but when Python's `activate.ps1` wraps the prompt, intermediate operations in activate's prompt handler reset `$?` to `$true` before VS Code's prompt runs, so exit codes are always reported as 0.

## Change summary

Terminal command decorations (colored dots) always show success (blue) instead of failure (red) when the PowerShell prompt has been wrapped by Python's `activate.ps1` virtual environment activation script.

## Best solution

Capture `$?` (and potentially `$LASTEXITCODE`) earlier in the prompt chain or use a PSReadLine handler to preserve the exit code before any prompt wrapper can clobber it. The fix lives in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1` around the `FakeCode` computation on line 107. One approach: leverage PSReadLine's `CommandValidationHandler` or `AddToHistory` handler to stash the exit code in a global before any prompt function runs.
