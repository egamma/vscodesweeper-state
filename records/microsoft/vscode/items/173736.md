# Issue #173736 — Code action not working even though command is invoked

[https://github.com/microsoft/vscode/issues/173736](https://github.com/microsoft/vscode/issues/173736)

## Summary

This remains a valid nested code-action cancellation bug on current main. The team-authored issue is accepted in the On Deck milestone, and no referenced fix or verified canonical supports closing it.

## Change summary

Applying a quick fix from the editor lightbulb can cancel a second code-action request invoked by that fix, leaving the delegated action unapplied.

## Best solution

Ensure that the automatic quick-fix refresh after applying an outer action cannot cancel a still-running manual code-action request started by that action's command, while preserving cancellation for genuinely superseded requests.

## Evidence

- **confirmed root cause:** A maintainer traced the failure to the nested `source.organizeImports` request being cancelled when completion of the original lightbulb action retriggers quick fixes: https://github.com/microsoft/vscode/issues/173736#issuecomment-1421621479.
- **current source:** `CodeActionController.applyCodeAction` in src/vs/editor/contrib/codeAction/browser/codeActionController.ts retriggers an automatic Quick Fix request in its `finally` block. `CodeActionModel.setState` in src/vs/editor/contrib/codeAction/browser/codeActionModel.ts cancels the previous request whenever the new state is installed.
- **timing race remains:** `CodeActionModel` delays a manual-to-automatic state transition by a fixed 500 ms, but then installs the automatic state and cancels the prior manual request. A nested provider taking longer than that window still loses its result, so the source retains the reported failure mode.
- **not an established fix:** Commit https://github.com/microsoft/vscode/commit/a49c81edea6647684eee87d204e50feed9c455f6 added the 500 ms transition delay for https://github.com/microsoft/vscode/issues/210817, not this issue, and does not remove the timeout-dependent cancellation.
- **continued reports:** Independent users reported the same behavior in 2024, including https://github.com/microsoft/vscode/issues/173736#issuecomment-2516420708.
- **canonical search:** The related open https://github.com/microsoft/vscode/issues/174295 concerns ordering and corruption when multiple import organizers apply edits concurrently, not cancellation of a command-triggered nested action; it is not the same observable symptom required for a re-reviewed duplicate close.
