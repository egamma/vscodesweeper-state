# Issue #158996 — "Follow link" hover is not linkified on markdown links

[https://github.com/microsoft/vscode/issues/158996](https://github.com/microsoft/vscode/issues/158996)

## Summary

Keep open: current source still renders “Follow link” as plain text for unresolved document links, while resolving the target only when opening it. This issue already owns the reported behavior, including two later reports closed as duplicates.

## Change summary

Make the “Follow link” hover action clickable for Markdown document links whose targets are resolved lazily.

## Best solution

Provide the same clickable hover navigation for lazily resolved document links as for links with known targets, in the editor link contribution. Preserve lazy target resolution and existing modifier-click navigation rather than substituting placeholder targets.

## Evidence

- **Current source confirms the defect:** src/vs/editor/contrib/links/browser/links.ts:362–397, getHoverMessage, calls appendLink only when link.url exists; otherwise it returns appendText containing “Follow link” and the keyboard hint. LinkOccurrence._getOptions uses this function for both active and inactive decorations.
- **Resolution happens on opening, not hover:** In src/vs/editor/contrib/links/browser/links.ts, _onEditorMouseMove activates the existing decoration without resolving its link, whereas openLinkOccurrence calls link.resolve(CancellationToken.None). src/vs/editor/contrib/links/browser/getLinks.ts:50–67 invokes the provider's resolveLink only when the initial URL is absent. This directly matches the reported trigger: hover an unresolved Markdown link and receive a non-clickable action.
- **Discussion establishes the intended behavior:** The discussion at https://github.com/microsoft/vscode/issues/158996 diagnoses lazy resolution, recommends resolving on hover, and records that supplying a placeholder URI prevents documentLink resolution.
