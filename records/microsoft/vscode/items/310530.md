# Issue #310530 — VSCode Agentic app - Choose start branch

[https://github.com/microsoft/vscode/issues/310530](https://github.com/microsoft/vscode/issues/310530)

## Summary

A real capability gap remains on current main: the Agents Window exposes branch selection for local Copilot sessions but deliberately provides no branch state or picker for Cloud sessions. Older reports describe related default-branch behavior, but not the same branch-picker symptom in the same surface, so the stronger re-review duplicate bar is not met.

## Change summary

Allow users creating a Cloud agent session in the Agents Window to choose the branch from which the session starts.

## Best solution

Extend the Cloud new-session contract to enumerate selectable remote branches, preserve the selected base ref, and pass it through both supported Cloud provisioning paths while reusing the existing shared branch-picker UI.

- **Validation:** Add focused provider and picker tests proving that a Cloud draft lists eligible branches, records a selection, and forwards the selected base ref when the first request provisions or delegates the session; run the corresponding Copilot Chat sessions provider and branch-picker test suites.
- **Behavior:**

  > When composing a Cloud agent session, the user can choose an eligible branch from the selected repository before sending the first prompt. The Cloud task starts from that selected branch rather than always using the repository default. The selected branch remains visible in the composer, while creating a Cloud session without changing the selection retains the maintainer-approved default behavior.
- **Trace:**

  > The shared picker already exists in src/vs/sessions/contrib/chat/browser/branchPicker.ts and is adapted for Copilot sessions by src/vs/sessions/contrib/providers/copilotChatSessions/browser/branchPicker.ts. Its action is currently gated to Copilot CLI in copilotChatSessionsActions.ts. RemoteNewSession in copilotChatSessionsProvider.ts cannot supply branch data or retain a selection, and the Cloud sandbox provisioning path explicitly omits `baseRef`; the regular Cloud path crosses into extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts. The boundary is Cloud new-session configuration: existing local CLI/worktree branch behavior and committed-session branch metadata must remain unchanged. Related reports https://github.com/microsoft/vscode/issues/303677 and https://github.com/microsoft/vscode/issues/296899 establish demand for non-default Cloud starting branches but do not settle the picker and default-selection contract.
- **Open decisions:**
  - When a Cloud session is created from a local repository, should the picker initially select the checked-out branch when that branch exists remotely, or continue selecting the repository default?
  - Should selectable starting points be limited to remote branch names, or must the public contract also accept tags or commit SHAs?
  - Must branch selection work identically for every Cloud execution backend, or should the control appear only when the selected backend advertises base-ref support?
