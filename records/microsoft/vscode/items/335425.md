# Issue #335425 — Integrated terminal inserts IME-committed text twice (WeChat IME voice input, Windows)

[https://github.com/microsoft/vscode/issues/335425](https://github.com/microsoft/vscode/issues/335425)

## Summary

This is the latest instance of a recurring IME double-insertion family in the integrated terminal, and the reporter's own isolation testing (editor area and native conhost unaffected, only xterm.js-backed terminal affected) plus the terminal source confirm VS Code delegates composition/textarea handling entirely to the bundled @xterm/xterm dependency rather than intercepting it — same root cause as prior reports, one of which (https://github.com/microsoft/vscode/issues/135940) was labeled `upstream` and the linked xtermjs/xterm.js#3533 (opened by the terminal's own VS Code maintainer) targets the same IME family in xterm.js itself.

## Change summary

WeChat IME voice-input text gets inserted twice in the integrated terminal (pwsh and cmd) on Windows, while the same dictation works correctly in the editor area and in a standalone conhost window.

## Best solution

Route to the terminal-input area for triage against xterm.js; the actual fix (handling TSF/IME commit events that arrive as a whole-sentence compositionend rather than per-keystroke input) belongs in @xterm/xterm's composition handling, likely to be tracked/fixed upstream at xtermjs/xterm.js rather than in this repo's glue code.
