# Issue #335425 — Integrated terminal inserts IME-committed text twice (WeChat IME voice input, Windows)

[https://github.com/microsoft/vscode/issues/335425](https://github.com/microsoft/vscode/issues/335425)

## Summary

Well-diagnosed report (isolation tests rule out editor/Chromium/shell layers), and the pattern matches VS Code's own history of routing terminal double-insertion bugs to xterm.js's CompositionHelper — but this specific TSF whole-sentence commit (voice input) scenario isn't covered by any currently open canonical, so it needs its own triage rather than a duplicate close.

## Change summary

WeChat IME's voice-input feature, which commits a full recognized sentence via the TSF commit channel rather than incremental keystrokes, causes the integrated terminal (xterm.js-backed) to insert the committed text twice; the editor area and native consoles are unaffected.

## Best solution

Route to the terminal/terminal-input area for maintainers to confirm and forward upstream to xterm.js's CompositionHelper (src/browser/input/CompositionHelper.ts) — the same code path implicated in the prior fixed reports (https://github.com/microsoft/vscode/issues/135940, https://github.com/microsoft/vscode/issues/141578) that were closed as duplicates of https://github.com/xtermjs/xterm.js/issues/3533. This looks like a TSF full-sentence-commit variant of that class of bug that resurfaced with a different IME.
