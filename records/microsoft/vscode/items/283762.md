# Issue #283762 — VSCode loses connection with remote after "Developer: Restart Extension Host"

[https://github.com/microsoft/vscode/issues/283762](https://github.com/microsoft/vscode/issues/283762)

## Summary

The defect remains on current main: Restart Extension Host stops every extension host, including the local host responsible for resolving the remote authority, and then attempts to restart without performing the full remote reconnection flow. Multiple reporters reproduced this with external extensions disabled, and a maintainer confirmed the architectural cause.

## Change summary

Running Developer: Restart Extension Host in a remote window drops the remote connection and immediately requires a window reload.

## Best solution

Ensure the command cannot leave a remote window disconnected. A maintainer should decide whether remote windows transparently perform Reload Window, as suggested in the thread, or whether VS Code should introduce a narrower restart path that preserves the local resolver host.

## Plan brief

- **Likely files:** `src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts`, `src/vs/workbench/services/extensions/common/abstractExtensionService.ts`, `src/vs/workbench/services/extensions/test/browser/extensionService.test.ts`, `src/vs/workbench/browser/actions/windowActions.ts`
- **Validation:** In local and remote-window test configurations, invoke workbench.action.restartExtensionHost and verify that local windows retain the existing stop/start behavior while remote windows remain connected or intentionally enter the selected full-reload flow without showing "Cannot reconnect. Please reload the window."
- **Behavior:**

  > Developer: Restart Extension Host must not leave a remote window disconnected and asking the user to reload manually. Local-window behavior must remain unchanged. In a remote WSL, SSH, or Dev Container window, invoking the command should complete through the maintainer-selected reconnection or reload behavior without presenting the immediate "Cannot reconnect" failure.
- **Trace:**

  > RestartExtensionHostAction in src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts calls stopExtensionHosts() and startExtensionHosts() without considering IWorkbenchEnvironmentService.remoteAuthority. AbstractExtensionService._doStopExtensionHosts in src/vs/workbench/services/extensions/common/abstractExtensionService.ts stops all extension-host managers, while the issue thread confirms that the local extension host owns remote authority resolution. ReloadWindowAction in src/vs/workbench/browser/actions/windowActions.ts delegates to IHostService.reload() and is the existing full-reconnection path suggested by the maintainer. Preserve the current local restart behavior and do not conflate this deterministic command failure with the unrelated spontaneous WSL/container crashes discussed later in the thread.
- **Open decisions:**
  - In a remote window, should Restart Extension Host transparently perform a full Reload Window, or should it preserve/recreate the resolver host while restarting only the remaining extension hosts?
  - If a full reload is selected, should the command retain its existing label and execute immediately, or communicate that remote-window state restoration is broader than an extension-host restart?

## Evidence

- **confirmed reproduction:** The reporter reproduced after Developer: Reload With Extensions Disabled, another Windows/WSL user independently confirmed the exact steps, and the linked demonstration at https://github.com/microsoft/vscode-remote-release/issues/11091#issuecomment-3089593347 shows the failure with the Vue extension disabled.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/283762#issuecomment-3659562702 explains that the local extension host manages the remote connection, so restarting it requires the full connection flow; the maintainer suggested redirecting the command to Reload Window in remote mode.
- **current source:** src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts:746-764 still implements RestartExtensionHostAction by calling IExtensionService.stopExtensionHosts() followed by startExtensionHosts(), with no remote-window branch or reload.
- **stop scope:** src/vs/workbench/services/extensions/common/abstractExtensionService.ts:739-760 implements the stop operation through _extensionHostManagers.stopAllInReverse(), confirming that the command does not preserve the local extension host that resolves the remote authority.
- **no canonical or fix:** The exact-symptom search found no separate open canonical issue. https://github.com/microsoft/vscode-remote-release/issues/11091 is closed and covered broader spontaneous extension-related disconnects; it directed this extension-independent command reproduction into the present issue.
