# Issue #291058 — Showing this blocks any other hovers from showing up

[https://github.com/microsoft/vscode/issues/291058](https://github.com/microsoft/vscode/issues/291058)

## Summary

The defect remains on current main: a sticky context-usage hover rejects unrelated delayed hovers, including status-bar hovers. The source clearly distinguishes nested hovers, so unrelated hovers can replace the sticky hover without breaking custom hovers inside it.

## Change summary

Opening the chat context-usage details prevents unrelated status-bar and workbench hovers from appearing until the details are dismissed.

## Best solution

Update the shared hover service so a hover requested outside a sticky hover replaces it, while preserving the existing nested-hover stack for hover targets inside the sticky widget.
