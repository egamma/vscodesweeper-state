# Issue #273813 — Running a prompt without having the tools installed should show a warning in chat

[https://github.com/microsoft/vscode/issues/273813](https://github.com/microsoft/vscode/issues/273813)

## Summary

This team-authored Backlog request identifies a real chat-customization gap: prompt files can reference unavailable tools or MCP servers without warning or offering a path to install them. No verified older canonical with the same observable behavior or concrete implementing commit is present, so it should remain open.

## Change summary

Detect tools and MCP servers referenced by prompt files that are not installed, warn the user before running the prompt, and provide installation guidance or a one-click install action.

## Best solution

Add prompt-reference validation to the chat customizations flow, surface unavailable tool or MCP dependencies before execution, and connect resolvable dependencies to the existing MCP/tool installation experience.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization`, `extensions/copilot`
- **Validation:** Add prompt-customization tests covering a prompt with an unavailable tool or MCP dependency: the warning must identify the dependency before execution, while prompts whose dependencies are available must run without the warning.
- **Behavior:**

  > When a prompt file references a tool or MCP server that is unavailable, VS Code warns the user and identifies the missing dependency before the prompt proceeds. When the dependency has a resolvable installation source, the warning provides a direct installation path. Prompts whose referenced tools and servers are available continue without additional friction.
- **Trace:**

  > The request spans prompt-file dependency discovery in the core chat customizations surface and the existing tool/MCP availability and installation flows. The current `chat-tools` and `chat-customizations` labels identify the owning areas, but the issue record does not settle whether validation occurs while authoring, when selecting the prompt, or only when running it. - **Open decisions:**

  - When installation metadata cannot be resolved uniquely, should VS Code offer search/discovery or only identify the missing tool or MCP server?
