# Issue #323413 — Side bar stays closed after window reload & resize

[https://github.com/microsoft/vscode/issues/323413](https://github.com/microsoft/vscode/issues/323413)

## Summary

The bug remains source-reproducible on current main: reloading discards the controller's in-memory record that the sidebar was automatically hidden, so widening the window cannot restore it. This team-authored report should remain open as a bounded responsive-layout bug.

## Change summary

Preserve the distinction between an automatically collapsed Sessions sidebar and a manually closed sidebar across window reloads, so widening the restored window reopens only the former.

## Best solution

Make the responsive Sessions layout retain enough state across reloads to restore a sidebar that it auto-collapsed, while continuing to respect a sidebar the user closed manually.

- **Behavior:**

  > When the responsive Sessions layout automatically hides the sidebar because a window is narrow, closing and reopening that window must not turn the automatic hide into a manual preference. Widening the restored window must show the sidebar again. A sidebar explicitly closed by the user before reload must remain closed, and the existing non-reload responsive behavior must remain unchanged.
- **Trace:**

  > The responsive path is `_registerResponsiveSidebar` in src/vs/sessions/contrib/layout/browser/desktopSessionLayoutController.ts. It records automatic ownership only in the in-memory `_sidebarAutoHidden` boolean; controller recreation resets that flag even though the workbench restores the sidebar as hidden, so the later constrained-to-unconstrained transition cannot restore it. The current D7 tests in src/vs/sessions/contrib/layout/test/browser/desktopSessionLayoutController.test.ts cover same-lifetime widening and an already-hidden reload state but omit the reported auto-hide/reload/widen sequence. Preserve the boundary established by D7 and https://github.com/microsoft/vscode/issues/323333: automatic hides are reversible when space returns, while manual closes remain authoritative.

## Evidence

- **source trace:** In src/vs/sessions/contrib/layout/browser/desktopSessionLayoutController.ts, `_sidebarAutoHidden` is initialized to `false` and only set when `_setSidebarAutoHidden(true)` runs during the current controller lifetime. After reload, widening reaches the unconstrained branch but cannot call `_setSidebarAutoHidden(false)` because that marker has been lost.
- **expected behavior:** The D7 contract in src/vs/sessions/contrib/layout/browser/desktopSessionLayoutController.md says an automatically hidden sidebar is shown again when the window grows, while only a sidebar closed by the user should remain closed.
- **test gap:** src/vs/sessions/contrib/layout/test/browser/desktopSessionLayoutController.test.ts covers widening during one controller lifetime and preserving an already-hidden sidebar across reload, but it does not cover auto-hide followed by reload and widening; the latter follows the reported failing path.
