# Issue #226878 — No events fired for a restored terminal

[https://github.com/microsoft/vscode/issues/226878](https://github.com/microsoft/vscode/issues/226878)

## Summary

Team-authored bug that appears still valid. A partial fix for reconnected terminals landed in 47b27ab160e (shell integration change notification), but the core issue — shell execution start/end events not firing for restored extension-contributed terminals — likely remains, as the fix was explicitly marked 'wip' for a related issue (#234672) and only addresses the `$shellIntegrationChange` notification, not the execution event pipeline.

## Change summary

Shell execution events (onDidStartTerminalShellExecution, onDidEndTerminalShellExecution) are not fired for extension-contributed terminals after a window reload restores them.

## Best solution

Ensure that when a persistent terminal is restored and its command detection capability is already active, the event wiring in `mainThreadTerminalShellIntegration.ts` picks up execution events (onCommandExecuted, onCommandFinished) for that terminal. The `createOnInstanceCapabilityEvent` multiplexer uses `onDidCreateInstance` which may not re-fire for restored instances whose capabilities were already attached before the ext host connected.
