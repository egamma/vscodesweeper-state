# Issue #280716 — Fetch 'Allow and review' UI is confusing

[https://github.com/microsoft/vscode/issues/280716](https://github.com/microsoft/vscode/issues/280716)

## Summary

Keep open: current source still separates fetching from approving results without fully explaining that sequence, and the fetch disclaimer is absent from the result-review surface. Skip now has an explanatory tooltip, but that only partially addresses the report.

## Change summary

Clarify what fetch approval permits, when fetched content is reviewed, what Skip declines, and where the content-risk warning appears.

## Best solution

Make the fetch and result-approval surfaces explain their distinct consequences while preserving existing approval behavior. Agree on stage-specific wording and warning placement before implementing the remaining UI polish.

- **Validation:** With default approvals and an untrusted URL not explicitly included in the user's prompt, trigger a fetch and inspect both confirmation stages. Verify that the first explains fetching followed by result review, declining it prevents execution, approving it opens result review, and declining results does not authorize their use. Check the agreed warning placement, visible action wording, tooltips, and keyboard-accessible descriptions at each stage.
- **Behavior:**

  > Users should understand that permission to fetch a page and permission to use its returned content are separate decisions. The first confirmation should explain what will run and when review happens; the result confirmation should explain what accepting or skipping the returned content means. The risk explanation should appear at the stage or stages agreed by the maintainer. Acceptance includes checking both approval and skip paths without changing existing approval or trust semantics.
- **Trace:**

  > FetchWebPageTool.prepareToolInvocation in src/vs/workbench/contrib/chat/electron-browser/builtInTools/fetchPageTool.ts produces the fetch title, URL message, confirmResults flag, and content-risk disclaimer. AbstractToolConfirmationSubPart renders the actual secondary button as the generic "Skip" for both stages. ChatToolPostExecuteConfirmationPart presents returned content under "Approve Tool Result" but does not render the fetch disclaimer. Source inspection establishes these presentation differences without executing the UI. Keep trust evaluation, automatic approvals, network restrictions, and execution/result-confirmation state transitions unchanged; the remaining uncertainty is the user-facing explanation and warning placement. Maintainer agreement is recorded at https://github.com/microsoft/vscode/issues/280420#issuecomment-3603788927.
- **Open decisions:**
  - Should the content-risk warning appear at both fetch approval and result approval, or should those stages carry different warnings explaining their respective consequences?
  - Should the visible actions explicitly distinguish fetching from accepting returned content, or should the existing shared Allow/Skip labels remain with clearer explanatory text?
