# Issue #293884 — Configure default directory/pattern for git worktrees

[https://github.com/microsoft/vscode/issues/293884](https://github.com/microsoft/vscode/issues/293884)

## Summary

Keep open: current source supports choosing and remembering a manual worktree destination, but does not cover configurable repository/branch path templates for automatically created worktrees. The verified related issues cover different symptoms or explicitly preserve this narrower request.

## Change summary

Allow configuring the default worktree directory and naming pattern with repository and branch variables, including in the Agents Window.

## Best solution

Provide a documented worktree-location configuration that supports centralized repository/branch layouts and works consistently across manual Git commands and agent-created worktrees. Design its scope and template contract before implementation, preserving existing worktree locations and trust boundaries.

- **Validation:** After the configuration contract is chosen, verify that manual Git worktree creation and a new isolated agent session both use a configured centralized repository/branch layout. Exercise a branch containing '/', concurrent sessions, window reload, and an unset configuration; confirm existing worktrees retain their locations and trust does not extend to unrelated directories. Add focused path-resolution and isolation tests in the identified suites.
- **Behavior:**

  > Users can configure where newly created worktrees live and derive their directory names from repository and branch information. A centralized layout outside the repository should work for both manual Git worktree creation and automatic agent isolation. Unconfigured behavior and existing worktree locations remain unchanged. Acceptance includes safe branch-name handling, non-conflicting concurrent creation, and correct session restoration.
- **Trace:**

  > Commands.getWorktreePath in extensions/git/src/commands.ts reads a remembered per-repository destination or constructs a sibling <repo>.worktrees path; users can override it interactively, but cannot supply a reusable template. Agent worktree creation in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts instead obtains a hard-coded root from getWorktreesRoot in common/worktreePaths.ts. That shared module also derives trust provenance and reverse repository identity from the directory shape, so arbitrary configured placement requires tracing those consumers before implementation. Preserve existing worktree identity, restoration, cleanup, and trust boundaries; do not treat an entire centralized worktree container as trusted. https://github.com/microsoft/vscode/issues/336620 provides broader design context but explicitly retains this request. The remaining uncertainty is the public configuration/template contract and how all location-dependent consumers will support it.
- **Open decisions:**
  - Should one configuration govern both manual Git commands and agent-created worktrees, or should users be able to configure those workflows independently?
  - Which template variables and transformations are supported, and what directory naming behavior should users see when simultaneous sessions resolve to the same repository/branch path?

## Evidence

- **Existing manual capability is partial:** extensions/git/src/commands.ts:3633-3714, Commands.getWorktreePath, offers an editable destination and folder picker. Its default uses per-repository WORKTREE_ROOT_STORAGE_KEY state or a sibling <repo>.worktrees directory, then appends worktreeName; this is not a configurable variable-based template. extensions/git/package.json exposes worktree include/symlink settings but no destination-template setting.
