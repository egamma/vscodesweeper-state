# Issue #281116 — Feature Request: Allow handsoff with resetting context window for custom agent

[https://github.com/microsoft/vscode/issues/281116](https://github.com/microsoft/vscode/issues/281116)

## Summary

This remains a valid custom-agent workflow request: handoffs currently lack an explicit contract for full, summarized, or cleared conversation context. The related orchestrator-flow item is newer and does not meet the stronger duplicate bar for this re-reviewed issue.

## Change summary

Allow custom-agent handoffs to choose whether the destination receives full conversation history, a summary, or a fresh context, optionally with selected artifacts.

## Best solution

Define a handoff context policy in custom-agent metadata, with explicit full-history, summarized-history, and fresh-context modes plus a bounded way to pass selected files or generated artifacts. Preserve the current behavior as the compatibility default and document exactly what each mode sends.

## Plan brief

- **Likely files:** `extensions/copilot`
- **Validation:** Add coverage that exercises each approved handoff context mode and verifies the destination agent receives exactly the intended conversation history and selected artifacts, while an unspecified mode retains today's behavior.
- **Behavior:**

  > A custom-agent handoff can explicitly choose what conversational context the destination receives: the existing full history, a summarized history, or a fresh context. If selected artifacts are supported, the destination receives only those declared inputs in addition to the handoff prompt. Existing handoff declarations without the new option retain their current behavior. Acceptance requires each mode to produce a predictable destination request and the fresh-context mode not to leak prior user or assistant turns.
- **Trace:**

  > The request belongs to the custom-agent handoff contract under `extensions/copilot`, and the issue's front-matter examples identify the public configuration surface that needs design. The current workaround (`send: false`, `/clear`, then manually attach `plan.md`) proves the desired workflow is possible but not declarative. The related https://github.com/microsoft/vscode-internalbacklog/issues/6598 may inform orchestration design, but it is newer and does not replace this issue. Preserve existing declarations and default context behavior; do not conflate this request with nested/background-agent execution, which is a broader workflow raised separately in the comments.
- **Open decisions:**
  - Should the public handoff contract offer exactly full-history, summarized-history, and fresh-context modes, and which mode remains the default for declarations that omit it?
  - Should a fresh or summarized handoff support an explicit list of files or generated artifacts as destination context, and what variable/reference forms are part of that public contract?
  - Does summarized-history mode use the existing automatic conversation compaction semantics, or a handoff-specific summary whose contents are user-visible and controllable?
