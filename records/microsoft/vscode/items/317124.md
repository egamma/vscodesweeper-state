# Issue #317124 — Agents web: ongoing session should display disconnected after tunnel host is killed.

[https://github.com/microsoft/vscode/issues/317124](https://github.com/microsoft/vscode/issues/317124)

## Summary

Keep open: current main has explicit connection-status propagation and session recovery UI, but those paths do not establish that killing a tunnel host settles an ongoing response correctly. The report already supplies sufficient steps to retest; the current failure remains unverified rather than missing information.

## Change summary

An ongoing Agents web session remains stuck evaluating or working after its tunnel host is killed instead of clearly indicating disconnection.

## Best solution

Ensure host loss reaches the open session's connection presentation and response lifecycle so it cannot indefinitely appear to be working without a disconnected indication. First retest the supplied tunnel-kill scenario against the current recovery implementation, preserving transient reconnection and recoverable conversation history.
