# Issue #229502 — SCM Graph - Picked repository is not remembered after restart

[https://github.com/microsoft/vscode/issues/229502](https://github.com/microsoft/vscode/issues/229502)

## Summary

The graph still forgets an explicitly selected repository on reload: its selection is initialized to Auto and never persisted. Keep this accepted Backlog bug open; the related indicator issue does not cover restoring the selection.

## Change summary

Remember the Source Control Graph's explicitly selected repository across window reloads and restarts.

## Best solution

Restore the graph's explicit repository selection when the same workspace reopens, while preserving Auto's active-repository tracking. Address persistence in the SCM graph view model without conflating it with the separate selection-indicator request.

- **Behavior:**

  > An explicit Source Control Graph repository selection is lost when the window reloads, returning the graph to Auto. Reopening the same workspace should retain that explicit selection once the repository is available, and changing the active editor should not replace it. Selecting Auto must continue to follow the active repository across reloads. Validate both modes with a two-repository workspace and a repeatable restoration check.
- **Trace:**

  > SCMHistoryViewPane.pickRepository() in src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts delegates to SCMHistoryViewModel.setRepository(), which updates only _selectedRepository. Each new model initializes that observable to 'auto'; its constructor restores reference filters and view mode but not repository selection. The graphRepository derived observable uses the explicit selection when present and otherwise follows ISCMViewService.activeRepository. Preserve those existing in-session semantics and the repository-removal cleanup; reference-filter persistence and SCM repository visibility are separate concerns. https://github.com/microsoft/vscode/issues/229643 covers the indicator, not restoration. The source diagnosis is complete, but the existing scmHistory.test.ts suite tests graph conversion rather than this model's lifetime, so the planning session must establish a runnable persistence regression check.
