Keep open: dynamic line-height changes still update layout without preserving the viewport's model anchor, matching the reported shift during selection. The maintainer explicitly deferred this work pending the variable-height API decision; the linked viewport report was closed as a duplicate of this issue, not as fixed.

## Change summary

Preserve the visible selection and viewport position when asynchronously applied variable line heights change editor layout.

## Plan brief

- **Likely files:** `src/vs/editor/common/viewModel/viewModelImpl.ts`, `src/vs/editor/common/viewLayout/viewLayout.ts`
- **Validation:** In an editor with variable line heights enabled, scroll into a document and select visible text, then asynchronously increase decoration line heights above the viewport. Verify that the selected content retains its viewport position and model selection; repeat while dragging, with wrapping enabled, and when removing the decorations. Establish a regression test for the settled anchoring behavior before implementation.
- **Behavior:**

  > Asynchronously applied variable line heights must not shift the viewport away from text the user is selecting. The report involves reloading, beginning a selection, and then receiving larger line heights after TypeScript resolves. Acceptance should cover an existing selection and an active drag while heights above the viewport change, without altering ordinary selection or scrolling behavior.
- **Trace:**

  > ViewModel._registerModelEvents in src/vs/editor/common/viewModel/viewModelImpl.ts handles onDidChangeLineHeight by updating custom heights through ViewLayout.changeSpecialLineHeights. That path updates content dimensions without restoring a model-relative viewport anchor, unlike _onConfigurationChanged, which uses _captureStableViewport and recoverViewportStart. This establishes the viewport displacement from source; the exact pointer-drag consequences were not executed. The maintainer explicitly deferred implementation pending the public provider-versus-decoration decision in https://github.com/microsoft/vscode/issues/247607#issuecomment-2871859881; current source uses decorations, but that alone does not establish that the API decision was finalized. Preserve existing decoration ownership filtering, wrapping semantics, and normal selection behavior. https://github.com/microsoft/vscode/issues/248510 was consolidated into this report, while https://github.com/microsoft/vscode/issues/249967 addresses a separate wrapping contract.
- **Open decisions:**
  - Does the maintainer still intend a dedicated variable-line-height provider, or is the decoration-based public contract now the settled direction for this preservation work?
