# Issue #193210 — Problems filtering: multi-word text patterns and passing a few patterns at a time

[https://github.com/microsoft/vscode/issues/193210](https://github.com/microsoft/vscode/issues/193210)

## Summary

This remains the accepted Backlog request and canonical issue for richer Problems filtering. Current main supports repeatable source filters, but arbitrary message text is still represented as one fuzzy query with one global negation, so the central gap remains.

## Change summary

Allow the Problems filter to combine multiple positive and negative text patterns, including multi-word phrases.

## Best solution

Define a coherent Problems-filter grammar for multiple include and exclude clauses, exact phrases, and their interaction with existing file-glob and `@source:` syntax, then apply it consistently in tree and table modes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/markers/browser/markersFilterOptions.ts`, `src/vs/workbench/contrib/markers/browser/markersTreeViewer.ts`, `src/vs/workbench/contrib/markers/browser/markersTable.ts`, `src/vs/workbench/contrib/markers/browser/messages.ts`, `src/vs/workbench/contrib/markers/test/browser/markersFilterOptions.test.ts`
- **Validation:** Extend the MarkersFilterOptions unit suite with positive, negative, mixed, multi-word, quoted-literal, file-glob, and `@source:` combinations, then verify equivalent marker visibility in Problems tree and table modes.
- **Behavior:**

  > The Problems filter can express more than one text condition at a time, including excluding multiple independent messages and excluding a specific multi-word phrase. Existing single fuzzy-text filters, file globs, and `@source:` filters retain their current behavior. Equivalent expressions produce the same visible problems in tree and table modes. The accepted grammar must make literal `!`, quoting, and combinations of positive and negative clauses predictable.
- **Trace:**

  > FilterOptions in src/vs/workbench/contrib/markers/browser/markersFilterOptions.ts removes repeatable `@source:` clauses, but stores all remaining text as one `textFilter` with one leading-negation flag. Filter.filterMarker in markersTreeViewer.ts and MarkersTable.reset in markersTable.ts each evaluate that one fuzzy query against message, source, code, or file fields and invert the aggregate match when negated. Comma-separated parsing currently feeds only the resource include/exclude glob matchers, so it must not be mistaken for multiple diagnostic-message conditions. Existing source filtering is independently represented and tested in markersFilterOptions.test.ts and should remain compatible. The uncertainty starts at the public grammar: the thread proposes whitespace, pipes, quotes, and regexes without a maintainer selecting their observable semantics.
- **Open decisions:**
  - Which public syntax distinguishes separate AND/OR text clauses, negated clauses, and an exact multi-word phrase while remaining compatible with existing fuzzy text and comma-separated file globs?
  - Should a positive or negative text clause match when its terms occur across different marker fields, or only when one field such as the message independently satisfies the whole clause?
  - Should regular expressions be supported, or should the grammar remain a bounded fuzzy/exact-clause language?

## Evidence

- **current source:** In src/vs/workbench/contrib/markers/browser/markersFilterOptions.ts, `FilterOptions.textFilter` remains a single `{ text, negate }` value; lines 108-109 derive one global negation solely from whether the remaining filter starts with `!`.
- **matching path:** src/vs/workbench/contrib/markers/browser/markersTreeViewer.ts and markersTable.ts pass that one text string to the fuzzy matcher and invert the single combined result, so independent clauses such as `!abc !def` or a positive clause combined with a negative clause are not represented.
- **partial existing capability:** Current main parses repeatable positive and negative `@source:` clauses through `SOURCE_FILTER_REGEX`, so examples involving known providers can use filters such as `!@source:cSpell !@source:ts-styled-plugin`; this does not cover arbitrary message phrases or mixed text expressions.
