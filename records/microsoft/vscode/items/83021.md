# Issue #83021 — OS specific properties in Tasks.json to overwrite build shell doen't work

[https://github.com/microsoft/vscode/issues/83021](https://github.com/microsoft/vscode/issues/83021)

## Summary

Keep open: current source still does not apply top-level platform-specific shell options to configured TypeScript tasks. Existing automation profiles provide a workaround, but do not implement the requested tasks.json inheritance.

## Change summary

Allow a shared tasks.json to select a platform-specific build shell for contributed TypeScript tasks.

## Best solution

Define and support platform-specific option inheritance for contributed tasks in the task configuration parser and schema, preserving explicit per-task overrides. Coordinate the overlapping global-options report without folding this older issue into its newer counterpart.

## Evidence

- **Reported scope and maintainer clarification:** The supplied configuration uses type 'typescript', not 'shell'. The maintainer subsequently acknowledged that task-level platform properties were unavailable for contributed task types: https://github.com/microsoft/vscode/issues/83021#issuecomment-545323563. The earlier successful shell-task example therefore does not establish coverage of this request.
- **Current parser boundary:** In src/vs/workbench/contrib/tasks/common/taskConfiguration.ts:1734–1822, TaskParser.from applies CustomTask.fillGlobals only to custom shell/process tasks. Its contributed-task branch calls ConfiguringTask.from without globals. ConfiguringTask.from reads options from the individual task, and createCustomTask at lines 1677–1723 combines those options with the provider's options; top-level platform defaults do not enter that path.
- **Current schema boundary:** src/vs/workbench/contrib/tasks/common/jsonSchema_v2.ts:414–495 builds contributed-task schemas from taskConfiguration with additionalProperties:false. That configuration includes options but no windows, osx, or linux properties, so the proposed task-level platform override remains unavailable for the TypeScript task.
- **Existing capability is a workaround:** terminal.integrated.automationProfile.windows, .osx, and .linux are registered in src/vs/platform/terminal/common/terminalPlatformConfiguration.ts for tasks and debugging, and resolved in src/vs/workbench/contrib/terminal/browser/terminalProfileResolverService.ts. They allow an automation shell distinct from the interactive shell, but operate through settings rather than the requested platform-specific defaults in tasks.json.
- **Duplicate direction already established:** https://github.com/microsoft/vscode/issues/83117 is closed, and the maintainer explicitly identified it as a duplicate of this issue: https://github.com/microsoft/vscode/issues/83117#issuecomment-545321385. - **Related newer report:** https://github.com/microsoft/vscode/issues/159135 is open and reports global options/presentation being ignored for contributed cppbuild tasks. It was created on 2022-08-25, after this issue, and does not report the same platform-specific shell symptom; it does not meet the stronger duplicate bar for this re-reviewed item.
