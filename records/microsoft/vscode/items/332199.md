# Issue #332199 — Chat input history leaks across sessions

[https://github.com/microsoft/vscode/issues/332199](https://github.com/microsoft/vscode/issues/332199)

## Summary

Real bug confirmed by tracing the source: ChatHistoryNavigator/ChatInputPart.setHistoryKey exists specifically to scope input history per session (and is exercised by unit tests with per-session keys), but no production code path in the chat widget ever calls it, so ChatWidgetHistoryService keys history only by location and leaks it across sessions. An open PR already targets this exact fix, so it should not be closed as completed until that lands.

## Change summary

Up-arrow history navigation in the chat input recalls prompts from a different, unrelated chat session instead of staying scoped to the active session.

## Best solution

Land (or review) https://github.com/microsoft/vscode/pull/332200, which should wire session/model changes in ChatWidget to call ChatInputPart.setHistoryKey(...) with a per-session key so ChatWidgetHistoryService.getKey() produces distinct history buckets per session.
