# Issue #126311 — Workspace Trust - Declared Untrusted Folders

[https://github.com/microsoft/vscode/issues/126311](https://github.com/microsoft/vscode/issues/126311)

## Summary

Keep this accepted Backlog request open: current Workspace Trust supports trusted parents, but not persistent untrusted exceptions beneath them. This issue already owns the consolidated discussion, has 48 upvotes, and needs a maintainer decision on the trust-rule contract.

## Change summary

Allow explicitly untrusted locations to enter Restricted Mode automatically, including exceptions beneath trusted parents that return to untrusted on reopening.

## Best solution

Provide user-controlled untrusted location rules without requiring users to reorganize repositories. Resolve whether this extends the existing trusted-parent model or also permits an opt-in trust-everything-else mode before implementing the persistence and override semantics.

- **Behavior:**

  > Users want designated untrusted locations to open automatically in Restricted Mode without reorganizing their repository layout. Such locations must remain exceptions to trusted parents, and a temporary trust choice must not erase the rule for the next launch. Nonexcluded locations must follow the agreed trust model, with existing defaults unchanged unless the user explicitly opts into different behavior. Acceptance checks must cover excluded children, unaffected siblings, reopening, and temporary trust.
- **Trace:**

  > WorkspaceTrustManagementService in src/vs/workbench/services/workspaces/common/workspaceTrust.ts persists positive URI trust entries only: loadTrustInfo filters out false entries, doSetUrisTrust(false) deletes exact entries, and doGetUriTrustInfo inherits matching parent trust. Settings and commands in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts do not expose negative location rules; the management UI is in workspaceTrustEditor.ts and the service contract is in src/vs/platform/workspace/common/workspaceTrust.ts. - **Open decisions:**

## Evidence

- **Current capability gap:** In src/vs/workbench/services/workspaces/common/workspaceTrust.ts, loadTrustInfo removes entries whose trusted flag is false. doSetUrisTrust(false) removes an exact trusted entry rather than recording a denial, and doGetUriTrustInfo inherits trust from matching parents. Consequently, an explicitly untrusted child cannot persist as an exception beneath a trusted parent.
- **Existing settings are partial alternatives:** src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts registers workbench.trust.manage and security.workspace.trust.startupPrompt, security.workspace.trust.untrustedFiles, security.workspace.trust.emptyWindow, and security.workspace.trust.enabled. These manage positive trust, prompting, loose files, empty windows, or global enablement; none supplies persistent negative location rules. https://code.visualstudio.com/docs/editing/workspaces/workspace-trust explicitly documents that trusting a parent trusts all subfolders and removes the usual Don't Trust button for an inherited-trust child.
