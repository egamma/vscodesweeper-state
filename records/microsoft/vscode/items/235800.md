## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode/issues/235800 describes Windows 11 24H2, three monitors, opening the top-right gear menu in fullscreen on the middle monitor, and seeing approximately one quarter of the menu. It includes fullscreen and windowed screenshots and reports the same behavior with extensions disabled.
- **Current custom-menu positioning:** src/vs/base/browser/ui/contextview/contextview.ts, ContextView.doLayout, measures the window viewport using innerWidth/innerHeight and calls layout2d. src/vs/base/common/layout.ts, layout and layout2d, flip or overlap menus when the preferred placement lacks room. These intended boundary protections do not conclusively explain the reported clipping.
- **Native versus custom boundary:** src/vs/platform/window/common/window.ts, hasNativeContextMenu, selects the implementation according to window.menuStyle and title-bar configuration. src/vs/workbench/services/contextmenu/electron-browser/contextmenuService.ts computes native anchor coordinates, while src/vs/base/parts/contextmenu/electron-main/contextmenu.ts passes them to Electron Menu.popup. The report does not establish which implementation produced the screenshots.
- **Positioning change is not a verified fix:** https://github.com/microsoft/vscode/commit/907f8163c095603e5b5c6dacd1a85cec900f8dd9 changes ContextView positioning-origin measurement for static containers and related layout cases. It does not establish that fullscreen clipping on the reporter's three-monitor setup is resolved, so it is not sufficient evidence for a completed close.
- **Canonical search:** Searches for fullscreen menu clipping, menus on multiple monitors, and menus cut off at screen boundaries found no verified canonical for this specific problem. https://github.com/microsoft/vscode/issues/201532 is open but concerns native menus appearing on another monitor, primarily on macOS; this report instead describes clipping on the current monitor. https://github.com/microsoft/vscode/issues/302741 is open but concerns focus-related menus rendering behind the window. Neither establishes the same underlying defect.
