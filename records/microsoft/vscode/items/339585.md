# Issue #339585 — `code --agents` in WSL should open that repo immediately

[https://github.com/microsoft/vscode/issues/339585](https://github.com/microsoft/vscode/issues/339585)

## Summary

Keep open to verify WSL context preservation through the CLI launch. Current main includes explicit CLI folder handoff and WSL agent-host support, but those capabilities do not establish that this launch selects the originating WSL repository; the reported command and terminal observation suffice to retest.

## Change summary

Launching `code --agents` from a WSL repository should select that repository and its WSL execution environment rather than defaulting to Windows.

## Best solution

Preserve the originating WSL distribution and repository through the CLI-to-Agents handoff, selecting the corresponding remote workspace without a second manual connection. First distinguish lost launch context from the Agents window's local terminal behavior, since PowerShell alone does not establish which host a session uses.
