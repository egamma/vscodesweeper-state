# Issue #339585 — `code --agents` in WSL should open that repo immediately

[https://github.com/microsoft/vscode/issues/339585](https://github.com/microsoft/vscode/issues/339585)

## Summary

Traced on main: `code --agents` only resolves a folder from explicit `folder-uri`/`file-uri`/positional CLI paths (`resolveAgentsWindowFolder` + `doExtractPathsFromCLI` in `src/vs/platform/windows/electron-main/agentsWindow.ts` and `windowsMainService.ts`); with no path argument it never falls back to the invoking cwd or remote authority, so the Agents window opens as a plain local window even when launched from a WSL shell — same as bare `code` with no args. Whether `--agents` should special-case cwd (and remote context) when no path is given is a product decision, not an obvious bug fix, so this stays open for a maintainer call rather than closing.

## Change summary

Running `code --agents` from a WSL shell with no explicit folder opens the Agents window as a local (non-remote) window instead of targeting the current WSL repo.

## Best solution

Decide whether `--agents` (optionally only when invoked through the WSL/remote CLI shim) should implicitly use the invoking cwd as the folder, then thread that through `resolveAgentsWindowFolder`/`doExtractPathsFromCLI` in src/vs/platform/windows/electron-main/agentsWindow.ts and windowsMainService.ts.

## Evidence

- **no implicit folder resolution:** src/vs/platform/windows/electron-main/agentsWindow.ts resolveAgentsWindowFolder() only returns a folder when extractPaths(cli) yields a single-folder workspace from explicit CLI paths; with no path arg, paths is empty and folderUri stays undefined.
- **doExtractPathsFromCLI has no cwd fallback:** windowsMainService.ts doExtractPathsFromCLI() (around line 935) only resolves folder-uri/file-uri/cli._ positional paths; it never substitutes the invoking process cwd or a remote authority when none are given.
- **agents window itself is always local:** ensureAgentsWindow() (windowsMainService.ts ~line 313) opens a fixed local agentSessionsWorkspace file with no remoteAuthority; the actual repo/session is only pushed afterward via the 'vscode:selectAgentsFolder' IPC message using the (possibly undefined) folderUri.
