# Issue #336722 — Workspace exception does not cover hidden home directories such as `~/.julia/dev`

[https://github.com/microsoft/vscode/issues/336722](https://github.com/microsoft/vscode/issues/336722)

## Summary

Confirmed in source: the hidden-home-directory protection branch in the edit-approval checker is function-valued and returns immediately without the workspace-folder exception the sibling (macOS `~/Library` / Windows `APPDATA`) branch already applies, so any workspace under a dotfile like `~/.julia/dev` is stuck requiring confirmation regardless of `chat.tools.edits.autoApprove`.

## Change summary

Workspaces located inside a hidden home directory (e.g. `~/.julia/dev`) never get the workspace-folder exception that VS Code already grants for `~/Library` or `%APPDATA%`, so edit approval prompts can't be auto-approved there.

## Best solution

Give the hidden-home-directory patterns in `allPlatformPatterns` the same workspace-folder exception the `specializedPatterns` string branch already has in `makeUriConfirmationChecker`, so files inside an approved workspace under a dotfile home directory go through normal `chat.tools.edits.autoApprove` handling.
