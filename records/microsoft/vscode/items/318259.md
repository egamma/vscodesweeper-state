# Issue #318259 — chat.agent.allowedNetworkDomains ignored for localhost; browser/page tools still blocked by network domain policy

[https://github.com/microsoft/vscode/issues/318259](https://github.com/microsoft/vscode/issues/318259)

## Summary

Confirmed bug: normalizeDomain() rejects localhost/127.0.0.1/::1 patterns from settings because they fail the wellKnownDomainSuffixes heuristic check (intended for freeform text extraction, not user-configured allowlists). The domain from a URL passes (fromUrl:true skips the check), but the pattern from settings doesn't.

## Change summary

chat.agent.allowedNetworkDomains entries like 'localhost', '127.0.0.1', and '::1' are silently rejected by the domain normalization heuristic, making it impossible to allowlist local addresses.

## Best solution

In matchesDomainPattern, normalize the pattern with fromUrl:true (or a new flag) so that user-configured domain patterns bypass the wellKnownDomainSuffixes heuristic, which is only appropriate for freeform-text extraction. Alternatively, add localhost and IP literals to the normalization as special cases.
