# Issue #339302 — Empty code blocks shown in main chat for file edits made by a subagent

[https://github.com/microsoft/vscode/issues/339302](https://github.com/microsoft/vscode/issues/339302)

## Summary

This narrower report (empty code blocks left in the main chat from a subagent's file edits) is the same underlying rendering defect as the older, open, maintainer-assigned issue #331429, which already describes both raw <vscode_codeblock_uri subAgentInvocationId=...> tags and 'empty gray placeholder blocks' from subagent edit/file operations — proposing a duplicate close to consolidate.

## Change summary

When a subagent edits files via replace_string_in_file/multi_replace_string_in_file, the markdown fence parts around the codeblockUri marker lack a subAgentInvocationId and leak into the main response as empty code blocks (57 in one run).

## Best solution

Fold this report into https://github.com/microsoft/vscode/issues/331429, which already tracks the same subagent-edit-block rendering defect (raw tags plus empty placeholder blocks) and is assigned to a maintainer; the fix likely belongs in the chat content-part splitting logic that associates markdown/codeblockUri parts with a subAgentInvocationId (chatSubagentContentPart.ts / chatListRenderer.ts).
