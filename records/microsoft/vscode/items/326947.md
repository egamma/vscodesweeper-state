# Issue #326947 — Agents window: chat response not rendered even though the data was returned (UI stops updating mid-stream; a window resize recovers it)

[https://github.com/microsoft/vscode/issues/326947](https://github.com/microsoft/vscode/issues/326947)

## Summary

Well-diagnosed, still-open bug filed by a team member. The described height-reconciliation race in the chat list virtualizer is confirmed in the current source — no fix has landed on main. Keeping open for a code fix.

## Change summary

In the Agents window, streaming chat responses freeze mid-render because the virtualized tree's content height stops tracking the real DOM height, and the scroll-down button is hidden by _scrollLock, leaving no recovery without a window resize.

## Best solution

Fix the height-reconciliation path so that rapid streaming reliably propagates row-height changes to the tree's scroll model. The key files are chatListRenderer.ts (fireItemHeightChange's early-return and deferred-scheduling paths) and chatListWidget.ts (_scrollLock hiding the scroll-down button even when auto-scroll has stalled). A secondary safety net: when _scrollLock is true but the tree hasn't grown in N seconds despite an active turn, force a re-measure or show the scroll-down button.
