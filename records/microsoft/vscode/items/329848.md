# Issue #329848 — Support MCP protocol revision 2026-07-28 negotiation

[https://github.com/microsoft/vscode/issues/329848](https://github.com/microsoft/vscode/issues/329848)

## Summary

Legitimate, currently-unimplemented gap: VS Code's MCP client only speaks the initialize-handshake protocol (2025-11-25) and has no support for the new 2026-07-28 stateless negotiation (`server/discover`, per-request `_meta` protocol version), so it correctly fails against modern-only servers. Too fresh (1 day, no maintainer/community signal) to judge scope beyond keeping it open and routed.

## Change summary

Add support for negotiating the MCP 2026-07-28 protocol revision (server/discover probing, per-request _meta protocolVersion, Streamable HTTP headers) alongside the existing initialize-handshake path.

## Best solution

Extend the MCP client (mcpServerRequestHandler.ts, modelContextProtocol.ts, mcpGatewaySession.ts) to probe modern servers via `server/discover` before falling back to the legacy `initialize` handshake, per the spec's documented backward-compatibility guidance — this is a real protocol-support feature that needs an MCP-owner design decision, not an automatic fix.

## Evidence

- **gateway side:** src/vs/platform/mcp/node/mcpGatewaySession.ts lists `MCP_SUPPORTED_PROTOCOL_VERSIONS` up to `2025-11-25` only, confirming 2026-07-28 is genuinely unsupported on current main.
- **spec confirmation:** modelcontextprotocol.io/docs/2026-07-28/learn/versioning confirms 2026-07-28 is now the 'current' revision, replacing the initialize handshake with per-request `_meta` protocolVersion negotiation and an optional `server/discover` RPC, with documented backward-compatibility guidance for older initialize-based clients/servers.
- **related report:** https://github.com/microsoft/vscode/issues/308766 (still open) shows VS Code already lags behind even the prior 2025-11-25 revision in some negotiation paths, consistent with this being an ongoing area of MCP version-negotiation gaps rather than a one-off.
