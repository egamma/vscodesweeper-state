# Issue #329848 — Support MCP protocol revision 2026-07-28 negotiation

[https://github.com/microsoft/vscode/issues/329848](https://github.com/microsoft/vscode/issues/329848)

## Summary

Confirmed on main: VS Code's MCP client only speaks the legacy `initialize`-handshake era (`LATEST_PROTOCOL_VERSION = "2025-11-25"` in modelContextProtocol.ts), so a modern-only 2026-07-28 Streamable HTTP server correctly rejects the initialize request and the legacy SSE fallback also fails as described — this is a real gap, not a bug in existing behavior.

## Change summary

Add dual-era negotiation so the VS Code MCP client can probe/connect to servers implementing the new stateless 2026-07-28 protocol revision (per-request `_meta` version, `server/discover`), falling back to the legacy `initialize` handshake for 2025-11-25-and-earlier servers.

## Best solution

Implement modern-era support in src/vs/platform/mcp (modelContextProtocol.ts schema types, mcpServerRequestHandler.ts, mcpGatewaySession.ts) that probes with `server/discover` (or reacts to `UnsupportedProtocolVersionError`) before falling back to the current initialize-based flow, following the upstream TypeScript SDK's `versionNegotiation` pattern; this is a nontrivial protocol/transport change for the MCP area owners to design, not a quick patch.
