# Issue #127919 — Emmet on VSCode does not resolve for shorthands with multiple curly braces

[https://github.com/microsoft/vscode/issues/127919](https://github.com/microsoft/vscode/issues/127919)

## Summary

Still present on main — the upstream @emmetio/abbreviation parser throws on unescaped consecutive curly braces. VS Code could pre-escape before passing to the parser, but no fix has landed. Keeping open as an upstream/integration issue.

## Change summary

Emmet abbreviations with multiple curly braces (e.g. `div{{{test}}}`) fail to expand because the upstream parser doesn't handle them.

## Best solution

Either the upstream @emmetio/abbreviation parser needs to support nested/consecutive braces, or @vscode/emmet-helper should pre-escape braces before calling the parser. The fix belongs partly in emmetio/emmet (parser) and partly in VS Code's emmet integration (escaping before expansion). As rzhao271 noted, escaping closing braces works — VS Code could apply that transformation automatically.
