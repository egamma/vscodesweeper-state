[https://github.com/microsoft/vscode/issues/332001](https://github.com/microsoft/vscode/issues/332001)

## Summary

The core ask — a compact density option for Modern UI — has already landed via the merged PR https://github.com/microsoft/vscode/pull/332330 (merge commit 0b8153e6b5b646a77aaa6de4f244dc20c51f9396, merged 2026-08-24), and `ModernUIDensity.Compact` plus the `workbench.modernUI.density` setting exist on current main (src/vs/workbench/contrib/modernUI/browser/modernUI.contribution.ts, src/vs/workbench/services/layout/browser/layoutService.ts). However, the PR body says only "Related to" this issue (not a closing keyword), and the issue's own scope explicitly goes further — per-property controls, flush/abutting layout, and behavior across zoom/panel positions/accessibility — with a fresh comment today still requesting more (removing padding in fullscreen). Keeping open to track the remaining investigation items rather than closing on a partial, self-referenced implementation.

## Change summary

Investigate and ship a supported density setting (e.g. Compact/Default/Comfortable) for Modern UI to reclaim editor space without disabling Modern UI entirely.

## Best solution

Core mechanism (compact density mode) has shipped in PR #332330; the remaining open surface is the finer-grained requests in the issue and its comments — e.g. flush/near-flush abutting parts, per-property controls, and full-bleed compact mode in fullscreen (raised in the most recent comment). Consider splitting concrete residual asks (like the fullscreen-padding request) into focused follow-up issues once the Compact mode ships broadly, while keeping this issue open as the umbrella for the density investigation.
