# Issue #336694 — # [copilot] convertToApiChatMessage silently drops Document content parts — PDF attachments never reach LanguageModelChatProvider extensions

[https://github.com/microsoft/vscode/issues/336694](https://github.com/microsoft/vscode/issues/336694)

## Summary

Confirmed on current main: `convertToApiChatMessage` in extChatEndpoint.ts has branches for Text, Image, CacheBreakpoint, and Opaque content parts but none for Document, so PDF attachments rendered by the prompt pipeline are silently dropped before reaching third-party `LanguageModelChatProvider` extensions.

## Change summary

PDF/document content parts are dropped when converting internal chat messages to the public `vscode.LanguageModelChatMessage` API, so BYOK/custom chat providers never see PDF attachments.

## Best solution

Add a `Document` branch to `convertToApiChatMessage` in extChatEndpoint.ts that mirrors the existing `Image` branch, producing a `vscode.LanguageModelDataPart` from `contentPart.documentData` — consistent with how `anthropicMessageConverter.ts`, `responsesApi.ts`, and `messagesApi.ts` already handle `Raw.ChatCompletionContentPartKind.Document`.
