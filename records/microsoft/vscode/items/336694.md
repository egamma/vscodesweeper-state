The PDF conversion omission remains present on current main: rendered Document parts are discarded before extension providers receive the request. Keep this open while the existing PDF-support PR, which contains the missing conversion, is reviewed.

ExtensionContributedChatEndpoint.makeChatRequest2 invokes this conversion at lines 196-200 and sends the converted messages through languageModel.sendRequest at line 238, conclusively dropping PDF content before the provider call.

Its extChatEndpoint.ts diff adds a Document/application/pdf branch that constructs LanguageModelDataPart from decoded documentData.data and documentData.mediaType, directly addressing this report. It uses Fixes syntax for the related capability issue, not this issue.
