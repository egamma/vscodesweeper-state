# Issue #175807 — [html] Path completion isn’t working with the `srcset` attribute

[https://github.com/microsoft/vscode/issues/175807](https://github.com/microsoft/vscode/issues/175807)

## Summary

A real gap remains in the HTML language service: current path completion recognizes `src` and `href`, but not `srcset`, and its replacement logic does not account for `srcset` candidate lists and descriptors. No older same-symptom canonical issue was found, so this should remain open under the existing HTML area.

## Change summary

Provide file-path completions for each image candidate inside HTML `srcset` attribute values.

## Best solution

Extend `vscode-html-languageservice` path completion to recognize `srcset` on `img` and `source`, parse the active comma-separated image candidate without replacing descriptors or neighboring candidates, add focused completion tests there, and then consume the updated language-service version in VS Code.

- **upstream source gap:** On current https://github.com/microsoft/vscode-html-languageservice/blob/main/src/languageFacts/dataManager.ts, `isPathAttribute` accepts all `src` and `href` attributes plus a fixed tag/attribute map, but neither path identifies `srcset`.
- **candidate-list handling:** Current https://github.com/microsoft/vscode-html-languageservice/blob/main/src/services/pathCompletion.ts treats an attribute value as one path and derives its replacement range from the last slash and whitespace; it has no parsing for comma-separated `srcset` candidates or `1x`/`2x`/width descriptors.
- **independent confirmation:** Two commenters reported the missing completion, including a distinction between density and width descriptors: https://github.com/microsoft/vscode/issues/175807#issuecomment-1496095520 and https://github.com/microsoft/vscode/issues/175807#issuecomment-1536215969.
