# Issue #226092 — [Accessibility] Support audio cue for commented range

[https://github.com/microsoft/vscode/issues/226092](https://github.com/microsoft/vscode/issues/226092)

## Summary

Valid accessibility feature request — no audio cue / accessibility signal for commented ranges exists on current main. The comments contrib has no AccessibilitySignal integration, and no signal is registered for commenting ranges. The discussion between the author and a team member is constructive and still under consideration.

## Change summary

Add an accessibility signal (audio cue) that plays when the cursor enters a commented range in the editor, so screen reader users can discover comments during line-by-line navigation.

## Best solution

Register a new `AccessibilitySignal` for commented ranges in `src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts`, wire it into the comments contribution (`src/vs/workbench/contrib/comments/`) to fire when the cursor lands on a line with an active comment thread, and add a corresponding verbosity setting (disabled by default, as the author suggested). The accessible help dialog for comment threads should mention this cue.
