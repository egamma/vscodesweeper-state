# Issue #286093 — Agent sessions - recent list update before session is loaded

[https://github.com/microsoft/vscode/issues/286093](https://github.com/microsoft/vscode/issues/286093)

## Summary

The premature update remains possible on current main: opening marks the session read before provider activation and session loading complete, allowing the reactive recent-session list to change while the user is still waiting. This team-authored issue has no issue-linked fixing commit or verified duplicate, so it should remain open.

## Change summary

Keep the recent sessions UI stable, or replace it with an explicit loading state, while an unread cloud-agent session is being loaded.

## Best solution

Present a stable loading state for the selected session before changing its read-dependent list placement. A maintainer should first choose whether that means immediately replacing the list with a chat loading shell or retaining the selected row with progress until the chat widget is ready.

  > Selecting an unread cloud-agent session must immediately provide stable feedback that this specific session is opening. While loading is pending, the recent-session surface must not visibly reshuffle or make the selected session disappear without replacing it with a session-specific loading presentation. - **Trace:**

  > The default open path in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsOpener.ts calls `session.setRead(true)` before awaiting `activateChatSessionItemProvider`, `canResolveChatSession`, and `chatWidgetService.openSession`. The nearby older issue https://github.com/microsoft/vscode/issues/280544 concerns startup restoration rather than this click/read-state transition, while https://github.com/microsoft/vscode/issues/281961 only changed recent-list capacity. Uncertainty starts at the interim presentation contract: the thread proposes both opening a chat loading shell immediately and retaining the selected list entry with progress.
