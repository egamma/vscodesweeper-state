# Issue #70824 — Ability to vary completion item insertion (based on chosen commit character?)

[https://github.com/microsoft/vscode/issues/70824](https://github.com/microsoft/vscode/issues/70824)

## Summary

A real API gap remains: completion acceptance cannot vary insertion text or additional edits according to the accepting key or commit character. The related open issue covers only suppressing the commit character, so this request remains independently useful and should stay open for API design.

## Change summary

Allow completion providers to select different insertion text and additional edits based on how a completion item is accepted.

## Best solution

Design a completion API that exposes the acceptance method and permits corresponding edit variants, with matching support in the suggest controller and LSP where applicable. Coordinate it with, but keep it distinct from, the narrower suppression work in https://github.com/microsoft/vscode/issues/42544.

## Evidence

- **current API gap:** src/vscode-dts/vscode.d.ts defines one CompletionItem.insertText value, one set of additionalTextEdits, and commitCharacters only as string[]; it provides no per-acceptance edit variants.
- **current acceptance path:** src/vs/editor/contrib/suggest/browser/suggestCommitCharacters.ts:38-43 accepts the selected item when a matching character is typed but does not pass that character into the insertion path; src/vs/editor/contrib/suggest/browser/suggestController.ts:677-686 consequently inserts the same completion.
- **partial existing capability:** CompletionItem.range supports separate inserting and replacing ranges, implementing the append-versus-replace work discussed in https://github.com/microsoft/language-server-protocol/issues/793, but both modes still use the same insertion text and additional edits.
- **distinct related issue:** https://github.com/microsoft/vscode/issues/42544 remains open for suppressing an inserted commit character; a maintainer explicitly distinguished that request from selecting different text edits based on the commit character.
