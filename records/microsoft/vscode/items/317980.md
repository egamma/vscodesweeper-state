# Issue #317980 — Remote Extension Host: transparent recovery on server replacement (follow-up to #317774)

[https://github.com/microsoft/vscode/issues/317980](https://github.com/microsoft/vscode/issues/317980)

## Summary

A real remote-development continuity gap remains: extension-host reconnection still takes the permanent-failure path and recreates the host rather than transparently initializing the replacement process. Keep this open until the prerequisite management-connection work in the still-open PR is resolved.

## Change summary

Recover and reinitialize a remote extension host transparently when remote-server replacement invalidates its reconnection token.

## Best solution

After https://github.com/microsoft/vscode/pull/317774 is settled, extend its fresh-session mechanism to the extension-host connection while preserving the existing full-restart fallback. The design must explicitly reestablish extension-host initialization and workbench RPC state rather than treating the new process as an ordinary socket reconnection.
