# Issue #343866 — Plugins and skills within plugins should show a 'last updated at' and authors

[https://github.com/microsoft/vscode/issues/343866](https://github.com/microsoft/vscode/issues/343866)

## Summary

Keep open: repository links now help investigate provenance, but author and last-updated metadata remain missing. The maintainer explicitly preserved this issue for that remaining work.

## Change summary

Show authorship and source-update timestamps for plugins and their individual skills.

## Best solution

Define authoritative authorship and freshness metadata for plugins and individual skills, then expose it consistently in Chat Customizations details. Distinguish publisher identity from individual authorship and avoid presenting installation times as source-update times.

- **Validation:** Extend the existing plugin provider and embedded detail tests with authoritative metadata fixtures and missing-metadata cases. Manually inspect a plugin containing two skills with different authors/update dates; verify their metadata remains distinct and existing repository links still work.
- **Behavior:**

  > Plugin and individual skill details should let users understand who created or updated the artifact and how current its source is without inspecting GitHub history. Publisher ownership must not be presented as individual authorship. Source-update timestamps must not be confused with installation or download times. Acceptance checks should cover distinct skill metadata, absent metadata, and unchanged repository navigation.
- **Trace:**

  > The current installed-plugin detail path in src/vs/workbench/contrib/chat/browser/aiCustomization/embeddedAgentPluginDetail.ts exposes version and repository provenance. Marketplace details expose publisher identity, and getPluginPublisher in pluginCustomizationMarketplaceProvider.ts derives that identity from repository ownership rather than contributor history. IMarketplacePlugin and IMarketplaceJson in common/plugins/pluginMarketplaceService.ts lack the requested metadata; the shared customization marketplace resource contract likewise provides publisher fields but not author/update fields. https://github.com/microsoft/vscode/pull/344864 deliberately implements only source navigation and explicitly leaves https://github.com/microsoft/vscode/issues/343866 open. The unresolved boundary is where authoritative per-plugin and per-skill metadata originates and what its displayed meaning is; preserve validated repository links and do not fabricate missing values.
- **Open decisions:**
  - Should authorship identify the original creator, the latest updater, or both, and how should these differ from the publisher?
  - Should 'Last updated' describe the installed revision or the latest available source revision?
  - Which authoritative metadata sources should be supported for plugins and individual skills, and how should unavailable metadata appear?
