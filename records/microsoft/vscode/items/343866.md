# Issue #343866 — Plugins and skills within plugins should show a 'last updated at' and authors

[https://github.com/microsoft/vscode/issues/343866](https://github.com/microsoft/vscode/issues/343866)

## Summary

Keep open as a feature request: current plugin details expose version and source information, but not the requested individual authorship and content-update history. This team-authored request needs a decision on what those metadata mean before implementation.

## Change summary

Show authorship and last-updated information for plugins and their included skills so teammates can assess ownership and freshness.

## Best solution

Expose clearly labeled provenance and freshness in the shared customization details for plugins and included skills. Establish whether the metadata describe the installed content or the latest published content, and distinguish the creator from the last contributor.

- **Behavior:**

  > Users inspecting a team plugin or one of its included skills should be able to identify its authorship and content freshness without interpreting a version number. Labels must distinguish creator, last contributor and publisher wherever those represent different people or organizations. Acceptance checks should cover distinct plugin-level and skill-level metadata and items whose provenance is unavailable.
- **Trace:**

  > EmbeddedAgentPluginDetail.renderFacts currently shows version, marketplace and location, while IAgentPlugin and IMarketplacePlugin provide no author or content-update timestamp. Included skills use INamedPluginResource, which likewise has no provenance fields. AICustomizationManagementEditor.openCustomizationItem first opens the parent plugin for plugin-owned skills, with subsequent navigation into the skill detail. The marketplace adapter's getPluginPublisher derives a repository owner, which does not establish individual authorship. The testing scenario is documented in https://github.com/microsoft/vscode/issues/343667. Uncertainty starts at the authoritative metadata source and whether freshness refers to installed or currently published content; preserve existing installation, enablement and navigation semantics.
- **Open decisions:**
  - Should 'Last Updated' describe the installed revision or the latest published content, and how should the UI distinguish them when they differ?
  - Should attribution identify the original creator, the last contributor, or both, and what should users see when individual attribution is unavailable?
