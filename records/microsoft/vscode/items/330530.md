# Issue #330530 — Markdown editor: source-visible ordered-list markers shift with proportional digit widths

[https://github.com/microsoft/vscode/issues/330530](https://github.com/microsoft/vscode/issues/330530)

## Summary

Well-diagnosed rendering-alignment bug in the new Markdown WYSIWYG editor, but the actual styling code (`.md-list-gutter`) lives in the private `@vscode/markdown-editor` npm package built from an external `vscode-team-tools` repo, not in this checkout, so I cannot independently verify or fix it here — routing to the markdown-editor area.

## Change summary

In the Markdown editor's source-marker view, sibling ordered-list markers (`1.` vs `2.`) and their nested gutter/indentation dots shift horizontally because proportional digit widths combine with a shrink-to-fit, right-pinned gutter.

## Best solution

A markdown-editor area owner should evaluate applying `font-variant-numeric: tabular-nums` to ordered markers in `.md-list-gutter` (in the `vscode-team-tools`/`@vscode/markdown-editor` source, not this repo), decide how that shifts nested-gutter alignment relative to the root bullet column, and add a regression test comparing sibling marker left edges.
