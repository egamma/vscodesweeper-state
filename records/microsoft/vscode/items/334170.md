# Issue #334170 — Claude sessions never appear in Agent Sessions view — chat discovery race condition swallows "SDK not ready" as success

[https://github.com/microsoft/vscode/issues/334170](https://github.com/microsoft/vscode/issues/334170)

## Summary

Traced in source and confirmed: `_startClaudeCodeChatDiscovery` in claudeAgent.ts wraps its work in `retry(fn, 5000, 3)`, but the SDK-not-ready branch logs and returns normally instead of throwing, so `retry` treats a deferred first attempt as a completed success — nothing ever re-runs discovery once the SDK becomes ready, matching the reporter's log trace and confirmed workaround.

## Change summary

Claude/Anthropic external sessions never appear in the Agent Sessions view because the one-shot chat-discovery pass silently no-ops when the SDK isn't yet resolvable at startup, and nothing automatically retries it once the SDK becomes ready.

## Best solution

In src/vs/platform/agentHost/node/claude/claudeAgent.ts, `_startClaudeCodeChatDiscovery` needs to actually retry (or be event-driven) when `canLoadWithoutDownload()` is false at the first pass — either by throwing there so the existing `retry()` wrapper keeps polling long enough to cover the typical 2-4s SDK-ready delay, or by wiring an SDK-readiness signal that calls `_restartChatDiscovery()` automatically (today `_restartChatDiscovery` is only invoked from the explicit download/reload gestures in `agentSdkSetupChannel.ts`, not from ambient SDK availability). This needs a maintainer decision since the current 'return, don't throw' behavior is a deliberate design choice per the inline comment, and the wrong fix could reintroduce unwanted retry storms for the true not-downloaded case.
