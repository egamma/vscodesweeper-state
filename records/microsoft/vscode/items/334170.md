# Issue #334170 — Claude sessions never appear in Agent Sessions view — chat discovery race condition swallows "SDK not ready" as success

[https://github.com/microsoft/vscode/issues/334170](https://github.com/microsoft/vscode/issues/334170)

## Summary

Traced on main: `_startClaudeCodeChatDiscovery()` wraps its pass in `retry()` (base/common/async.ts) but returns normally (never throws) when `canLoadWithoutDownload()` is false, so `retry` counts it as a completed attempt with zero retries — discovery never re-runs once the SDK becomes locally resolvable seconds later, matching the reporter's log trace exactly.

## Change summary

Claude/Anthropic external sessions never appear in the Agent Sessions view because the one-shot chat-discovery pass silently no-ops when the SDK-readiness check races false at startup, and nothing automatically re-triggers it once the SDK becomes ready.

## Best solution

In src/vs/platform/agentHost/node/claude/claudeAgent.ts, `_startClaudeCodeChatDiscovery()`'s deferred-not-ready branch needs to actually retry (or subscribe to SDK-becomes-local and call `_restartChatDiscovery()`) instead of returning as if complete; the existing inline comment explains a deliberate 'don't retry, only downloading helps' rationale that turns out to be wrong for the already-cached/locally-resolvable case the reporter hit, so a maintainer should decide between bounded retries vs. an explicit readiness-changed hook rather than a blind throw-instead-of-return patch.
