# Issue #241391 — Sync Settings fails with Microsoft login and Run as different user - Error Code: -2147023584

[https://github.com/microsoft/vscode/issues/241391](https://github.com/microsoft/vscode/issues/241391)

## Summary

Keep open as an upstream Microsoft Identity/WAM issue affecting Windows “Run as different user.” Current VS Code offers a broker-free authentication workaround, but that does not establish that the default broker path is fixed.

## Change summary

Allow Microsoft authentication and Settings Sync to recover successfully when VS Code runs under a different Windows user than the desktop session.

## Best solution

Resolve the cross-user authentication failure in the Microsoft Identity/WAM runtime and confirm the original two-account Settings Sync scenario. Until then, retain the broker-free option and update workaround guidance to use "microsoft-authentication.implementation": "msal-no-broker" rather than the removed "classic" value.

## Evidence

- **Reported trigger and diagnosis:** The report describes Windows 11 with two hybrid AD/Entra users, launching VS Code as a different user, and subsequent Settings Sync reauthentication failing with -2147023584. In the supplied discussion, the authentication maintainer identifies the Microsoft Identity OS broker as the failing component; the reporter confirms that running under the desktop user does not meet the on-premises resource-access requirement.
- **Current source and workaround:** extensions/microsoft-authentication/package.json:113–124 registers microsoft-authentication.implementation with default "msal" and alternative "msal-no-broker"; "classic" is no longer an allowed value. package.nls.json:8 describes the alternative as browser authentication for native-broker problems. getNativeBrokerOptions in extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts returns undefined only when broker use is disabled or unavailable; otherwise CachedPublicClientApplication passes NativeBrokerPlugin into MSAL. extensions/microsoft-authentication/src/extension.ts requests a reload when this configuration changes. This bypass is not proof that cross-user WAM authentication now works.
