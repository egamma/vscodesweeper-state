# Issue #164402 — Git - operations using SSH with a FIDO/U2F key trigger a host authentication dialog

[https://github.com/microsoft/vscode/issues/164402](https://github.com/microsoft/vscode/issues/164402)

## Summary

The SSH askpass handler still interprets security-key user-presence requests as host authenticity requests. Keep this issue open: the previous fix attempt was never merged, and the newer notification issue does not replace this report.

## Change summary

Git operations with FIDO/U2F SSH keys show an incorrect host fingerprint dialog and do not correctly handle authenticator PIN requests.

## Best solution

Make the built-in Git SSH authentication flow distinguish host verification, key passphrases, authenticator PIN entry, and user-presence requests. Preserve genuine host verification while allowing security-key Git operations to complete without a spurious confirmation dialog.

Check genuine unknown-host verification and ordinary passphrase authentication remain unchanged; also exercise the reported SSH commit-signing path.
- **Behavior:**

  > Git operations using ecdsa-sk or ed25519-sk keys must not display a host authenticity dialog for a request to confirm physical presence. Keys requiring a PIN must allow PIN entry and subsequent touch confirmation through the GUI authentication flow. Genuine unknown-host verification and ordinary key passphrase entry must continue working. Acceptance checks should cover fetch, push, cancellation, and the reported SSH commit-signing scenario without relying on terminal or ssh-agent workarounds.
- **Trace:**

  > SSH_ASKPASS_REQUIRE is forced in Askpass's SSH environment in extensions/git/src/askpass.ts. extensions/git/src/ssh-askpass.sh forwards split prompt arguments through extensions/git/src/askpass-main.ts to Askpass.handleSSHAskpass. The handler tests only for 'passphrase' before treating every remaining request as host authenticity; tracing the reporter's exact presence prompt produces host 'key' and a missing fingerprint. https://github.com/microsoft/vscode/pull/165976 proposed suppressing that presence prompt but was closed unmerged and did not establish complete PIN handling. Preserve real host verification, HTTPS authentication, and terminal authentication behavior. https://github.com/microsoft/vscode/issues/321300 and https://github.com/microsoft/vscode/pull/319747 concern interaction hints, not a replacement for this classification defect. The uncertainty is the executable validation of the complete OpenSSH PIN/touch lifecycle across the reported environments; current tests cover askpass script management rather than prompt handling.

## Evidence

- **Current source confirms the original defect:** extensions/git/src/ssh-askpass.sh forwards the whitespace-split SSH prompt to askpass-main.ts, which sends argv to Askpass.handleSSHAskpass in extensions/git/src/askpass.ts. That handler recognizes only requests containing 'passphrase'; everything else falls through to host verification. For 'Confirm user presence for key ED25519-SK SHA256:...', argv[3] is 'Confirm', argv[6] is 'key', and argv[15] is absent, producing the reported 'key' fingerprint dialog. Current formatting substitutes an empty string for the missing fingerprint rather than fixing the classification.
- **Fix attempt was abandoned:** https://github.com/microsoft/vscode/pull/165976 is closed with mergedAt null. Its diff added a user-presence branch before authenticity handling, but that branch is absent from current source. The author explicitly closed the unmerged PR in https://github.com/microsoft/vscode/pull/165976#issuecomment-2108863174.
- **Confirmed impact and incomplete workarounds:** The discussion on https://github.com/microsoft/vscode/issues/164402 includes independent confirmations, PIN-required keys blocking GUI synchronization in VS Code 1.88.0, and Windows/WSL reports affecting signing and push/pull. Terminal operations, ssh-agent configuration, and connection multiplexing help some reporters but do not supply correct built-in prompt handling.
