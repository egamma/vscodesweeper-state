# Issue #348676 — Consider making the same experience for screenshot app and vscode window

[https://github.com/microsoft/vscode/issues/348676](https://github.com/microsoft/vscode/issues/348676)

## Summary

Keep open as a feature request: app-window screenshots still lack the interactive area-selection experience available when capturing VS Code. Cropping an attached image is available, but does not provide the requested capture-time interaction.

## Change summary

Offer interactive region selection when capturing another application's window for chat.

## Best solution

Provide a consistent whole-window-or-region selection experience for app-window screenshots, preserving cancellation and the existing full-window capture workflow.

## Evidence

- **Linked test plan:** https://github.com/microsoft/vscode/issues/348214 explicitly distinguishes click-or-drag selection for VS Code screenshots from immediate app-window capture. - **Current app-window path:** src/vs/workbench/contrib/chat/electron-browser/actions/chatAppWindowScreenshotActions.ts registers workbench.action.chat.pickAppWindowScreenshot. captureAppWindowScreenshot calls IAppWindowScreenshotService.capture, converts the returned whole-window image into an attachment, and registers it as editable without invoking interactive region selection.
- **Existing capability and remaining gap:** src/vs/workbench/contrib/screenshotTool/browser/screenshotTool.ts defines capture(targetWindow) as click-or-Enter for the window and drag for an area. In electron-browser/appWindowScreenshot.ts, IAppWindowScreenshotOptions only offers window picking, and capture returns the captured window image. browser/screenshotAnnotation.ts supports Crop after attachment, which is a workaround rather than the requested capture-time parity.
