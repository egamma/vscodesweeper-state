# Issue #54503 — Improve readability of diagnotic hovers

[https://github.com/microsoft/vscode/issues/54503](https://github.com/microsoft/vscode/issues/54503)

## Summary

Keep open: resizing and wider hovers address part of the request, but diagnostic text still lacks indentation-aware wrapping and formatted content. This accepted Backlog request has 23 upvotes, and no verified canonical issue covers its full remaining scope.

## Change summary

Make long, nested diagnostic messages easier to read without losing their indentation hierarchy when displayed in editor hovers.

## Best solution

Agree on a diagnostic-hover presentation that preserves nested-message readability at narrow widths while retaining existing resizing and navigation. Coordinate formatted diagnostic content with https://github.com/microsoft/vscode/issues/54272 rather than treating that narrower request as a duplicate target for this entire issue.

Add browser-rendering coverage for the agreed wrapping or scrolling behavior; the current Content Hover tests cover positioning rather than diagnostic indentation.
- **Behavior:**

  > Long nested diagnostics should remain understandable when the hover cannot fit their original lines. Existing hover resizing helps but does not guarantee readable hierarchy after wrapping. Acceptance should exercise multiple nesting levels, narrow and wide hover sizes, and complete access to the message while preserving existing hover actions and keyboard interactions. Formatted diagnostic content is related work already tracked separately, not a prerequisite that automatically resolves the wrapping request.
- **Trace:**

  > MarkerHoverParticipant._renderMarkerHover() in src/vs/editor/contrib/hover/browser/markerHoverParticipant.ts renders the whole diagnostic as editor-font plain text with whiteSpace = 'pre-wrap'. ContentHoverWidget in src/vs/editor/contrib/hover/browser/contentHoverWidget.ts already implements resizing, dimension retention, and horizontal scrolling methods, so those capabilities must not be mistaken for an explicit non-wrapping diagnostic mode. EditorHover in src/vs/editor/common/config/editorOptions.ts exposes no width or wrapping-mode setting. Current source establishes partial coverage and the remaining presentation gap; no runtime layout check was performed. Keep ordinary Markdown hovers and diagnostic navigation behavior outside the change's behavioral scope. Coordinate any formatted-content contract with https://github.com/microsoft/vscode/issues/54272; uncertainty remains over the desired wrapping experience rather than ownership of the existing plain-text renderer.
- **Open decisions:**
  - Should nested diagnostics use indentation-preserving wrapping by default, offer an opt-in non-wrapping horizontal-scroll mode, or expose both presentations?
