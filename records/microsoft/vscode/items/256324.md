# Issue #256324 — We should show test progress inline inside chat

[https://github.com/microsoft/vscode/issues/256324](https://github.com/microsoft/vscode/issues/256324)

## Summary

Keep open: current source provides textual test progress in chat, but not the collapsible test tree explicitly requested when this issue was reopened. The existing testing/chat labels already route the remaining work appropriately.

## Change summary

Show agent-triggered test runs as a collapsible inline tree with live test status inside chat.

## Best solution

Provide an inline, collapsible test hierarchy associated with the agent's test run so users can inspect progress without leaving their current work. Settle the tree's interaction and history behavior before implementation, preserving existing test execution and cancellation semantics.

- **Validation:** Run an agent request that invokes runTests against a test provider exposing nested suites, passing and failing cases, and a slow test. Confirm an inline tree can expand and collapse while statuses update, focus remains in the editor, completion retains the agreed result presentation, and cancellation still stops the run. Verify keyboard navigation and screen-reader labels for the tree, then reload the chat to check the chosen history behavior.
- **Behavior:**

  > When an agent runs tests, users can inspect a collapsible hierarchy of suites and test cases within the chat conversation rather than switching to a testing view. The hierarchy reflects live test states and the completed outcome while the user continues editing. Acceptance should cover nested suites, passing and failing tests, expansion during execution, keyboard access, cancellation, and the agreed behavior when reopening chat history.
- **Trace:**

  > RunTestTool in src/vs/workbench/contrib/testing/common/testingChatAgentTool.ts captures a LiveTestResult, subscribes to its changes, and currently emits aggregate textual progress through _monitorRunProgress. Its result contains a text summary rather than a structured tree payload. ChatToolInvocationPart.createToolInvocationSubPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatToolInvocationPart.ts has specialized rendering for other tool data but no test-tree path; ChatToolProgressSubPart renders generic progress messages. The original implementation at https://github.com/microsoft/vscode/pull/257350 predates the explicit reopening clarification at https://github.com/microsoft/vscode/issues/256324#issuecomment-3140438035. Preserve existing test selection, execution, coverage, and cancellation behavior; terminal output is a separate surface and is not equivalent to the requested hierarchy. The trace establishes the missing presentation, but does not settle which test interactions or persisted history the new tree should expose.
- **Open decisions:**
  - Should the inline tree be a progress-and-results view only, or also expose test actions such as rerun, debug, and opening failure details?
  - When chat history is reopened, should the tree retain the run's recorded outcomes or only be available while the corresponding test result remains in the testing service?
