# Issue #165175 — Switching between User and Workspace settings often selects a different entry

[https://github.com/microsoft/vscode/issues/165175](https://github.com/microsoft/vscode/issues/165175)

## Summary

Still present on main: switching between User/Workspace scope rebuilds the entire settings model without preserving the TOC selection. The handler has a TODO acknowledging this limitation.

## Change summary

Switching between User and Workspace settings scope causes the TOC selection to jump to a different entry because the model is fully rebuilt without preserving the focused category.

## Best solution

In `onDidSettingsTargetChange` (settingsEditor2.ts), save the current `tocFocusedElement` identity (e.g. its settings group id) before calling `onConfigUpdate`, then after the rebuild, find and re-focus the matching TOC entry in the new model. The TODO at line ~921 already notes this.
