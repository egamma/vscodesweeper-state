# Issue #307350 — visual: TreeView items without icons shift parent indentation

[https://github.com/microsoft/vscode/issues/307350](https://github.com/microsoft/vscode/issues/307350)

## Summary

Confirmed visual bug in `alignIconWithTwisty()` — the sibling-based heuristic at line 1669 of treeView.ts causes parent-level indentation to shift when a child lacks an icon. An open PR (#308165) targets this fix, and a follow-up API proposal (#325080) addresses the deeper design limitation. Keeping open for the PR to land.

## Change summary

TreeView items without icons cause sibling and parent indentation to shift inconsistently due to the `alignIconWithTwisty` heuristic.

## Evidence

- **source trace:** The bug is in `src/vs/workbench/browser/parts/views/treeView.ts` line 1669: `alignIconWithTwisty()` returns true/false based on whether siblings have icons, propagating alignment changes to the entire parent level when any child lacks an icon.
- **open fix PR:** https://github.com/microsoft/vscode/pull/308165 is open and targets this issue with `Fixes #307350`. It proposes returning `false` in the no-parent-icon case to prevent the sibling-driven indentation shift.
- **follow-up API proposal:** https://github.com/microsoft/vscode/issues/325080 proposes a `TreeViewOptions.indentation` API to let extensions explicitly control alignment, addressing the deeper design limitation that a per-item heuristic cannot satisfy all tree layouts.
- **no fix on main:** git log --grep 307350 finds no commits; the bug remains on current main.
