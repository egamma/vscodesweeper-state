# Issue #304880 — Individual project theming

[https://github.com/microsoft/vscode/issues/304880](https://github.com/microsoft/vscode/issues/304880)

## Summary

Existing workspace theme settings cover basic per-project theming, but the discussion identifies a remaining UX gap: choosing a personal project theme without changing shared repository settings or maintaining separate profiles. Keep this open as a feature request; the verified related issues do not meet the re-review duplicate bar.

## Change summary

Provide a convenient built-in way to choose and remember different themes for individual projects.

## Best solution

Make project-specific theme selection convenient while preserving shared settings and ordinary folder-opening workflows. Evaluate the personal persistence requirement alongside https://github.com/microsoft/vscode/issues/40233 rather than introducing a separate theme-only configuration mechanism without a product decision.

- **Proposed comment:**

  > Thanks for the request and the additional context. You can already select an installed theme through `workbench.colorTheme` in Workspace Settings, and `workbench.action.selectTheme` provides the theme picker. The remaining gap described here is remembering a personal theme for each project without changing shared settings or maintaining separate profiles. The local-settings proposal at https://github.com/microsoft/vscode/issues/40233 is related to that persistence requirement, but does not cover the same theme-selection experience.

## Evidence

- **Existing capability:** src/vs/workbench/services/themes/common/themeConfiguration.ts registers workbench.colorTheme with installed-theme enum values and workbench.colorCustomizations. Its ThemeConfiguration.setColorTheme and writeConfiguration methods support existing configuration targets, including workspace settings, so basic per-project themes already exist.
- **Picker behavior:** src/vs/workbench/contrib/themes/browser/themes.contribution.ts registers workbench.action.selectTheme. InstalledThemesPicker applies accepted selections with the 'auto' target; ThemeConfiguration.writeConfiguration delegates this to configurationService.updateValue. This supplies an installed-theme picker, not a dedicated personal project-theme persistence surface.
- **Discussion and workaround limits:** https://github.com/microsoft/vscode/issues/304880#issuecomment-4133843739 suggests Peacock. https://github.com/microsoft/vscode/issues/304880#issuecomment-4157641366 explains why workspace settings, separate profiles, and external .code-workspace files involve unwanted sharing or workflow trade-offs, reports an attempted extension, and proposes a local override file.
