# Issue #227009 — Support reverse search in tree find

[https://github.com/microsoft/vscode/issues/227009](https://github.com/microsoft/vscode/issues/227009)

## Summary

A real gap remains in the shared tree find widget: current main can focus the first/next match but provides no reverse-match action. The older debug-console request is narrower and cannot absorb this shared tree capability, so this team-authored request should remain open.

## Change summary

Add reverse match navigation to tree find so the Debug Console can replace its separate filter widget with the shared find experience.

## Best solution

Define consistent previous/next navigation for the shared tree find controller, then let the Debug Console adopt that complete find experience and retire its overlapping filter widget once https://github.com/microsoft/vscode/issues/225417 is resolved.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/tree/abstractTree.ts`, `src/vs/workbench/contrib/debug/browser/repl.ts`
- **Validation:** Exercise a tree with multiple matching nodes and verify forward and reverse actions visit matches in order with wrapping behavior decided by the plan; then verify Debug Console find provides the same navigation without regressing search-history keys.
- **Behavior:**

  > Tree find must allow users to move both forward and backward through matching tree elements. Reverse navigation must select and reveal the preceding match predictably, while search-history navigation and non-matching tree focus remain usable. In the Debug Console, the completed shared find experience should cover the navigation capability currently motivating the separate filter widget.
- **Trace:**

  > The shared implementation is FindWidget and FindController in src/vs/base/browser/ui/tree/abstractTree.ts. FindWidget currently reserves Up/Down for input history and Enter for returning focus to the tree; FindController.applyPattern focuses the first matching node through focusNext, while AbstractTree already exposes both focusNext and focusPrevious. The Debug Console enables tree find in src/vs/workbench/contrib/debug/browser/repl.ts but still owns a separate ReplFilter and FilterWidget. Keep generic match navigation in the shared tree-find boundary and do not change unrelated tree keyboard navigation or remove the Debug Console filter before https://github.com/microsoft/vscode/issues/225417 is complete. The related https://github.com/microsoft/vscode/issues/226716 establishes the desired terminal-like Debug Console experience but does not settle the exact shared-widget interaction.
- **Open decisions:**
  - Should reverse tree-find navigation be exposed through terminal-style previous/next controls with match-position feedback, through keyboard actions only, or through both?
  - When reverse navigation reaches the first match, should it wrap to the final match or stop and announce the boundary?

## Evidence

- **current source gap:** src/vs/base/browser/ui/tree/abstractTree.ts: FindWidget treats Up/Down as search-history navigation and Enter as returning focus to the tree; FindController.applyPattern only calls tree.focusNext and exposes no previous-match operation.
- **debug console integration:** src/vs/workbench/contrib/debug/browser/repl.ts enables the shared tree find widget but still constructs and persists a separate ReplFilter/FilterWidget, matching the cleanup motivation in the report.
- **open prerequisite:** https://github.com/microsoft/vscode/issues/225417 remains open and tracks finding matches in Debug Console output, which this issue explicitly names as a prerequisite.
- **related but narrower request:** https://github.com/microsoft/vscode/issues/226716 is older and requests terminal-style previous/next controls specifically for Debug Console find. It overlaps the desired symptom but does not own the broader shared tree-find capability requested here, so it does not meet the stronger duplicate bar for this re-review.
