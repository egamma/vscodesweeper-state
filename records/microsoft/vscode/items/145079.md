# Issue #145079 — [Codespaces] machine-overridable, experimental setting changes its value when the focus changes

[https://github.com/microsoft/vscode/issues/145079](https://github.com/microsoft/vscode/issues/145079)

## Summary

Still reproduces on main: the settings tree filter in settingsTree.ts skips scope filtering when the target is USER_LOCAL, so machine-overridable settings (which shouldn't appear in the User tab in a remote/Codespaces context) are shown and then revert on focus change. The attempted fix (PR #163239) was closed without merging.

## Change summary

In Codespaces, machine-overridable settings appear in the User settings tab and revert to default on focus change because they are not filtered out for remote USER_LOCAL scope.

## Best solution

In settingsTree.ts, extend the scope-filtering condition (currently at ~line 2449) to also filter USER_LOCAL settings in remote contexts, removing machine-overridable settings that cannot be written to user-local scope. The matchesScope logic in settingsTreeModels.ts already returns false for MACHINE_OVERRIDABLE under USER_LOCAL+isRemote, but it's never called for USER_LOCAL in the tree filter.
