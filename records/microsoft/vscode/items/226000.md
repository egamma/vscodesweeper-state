# Issue #226000 — Diff Editor: in-file search should reveal only a small fragment of unchanged region

[https://github.com/microsoft/vscode/issues/226000](https://github.com/microsoft/vscode/issues/226000)

## Summary

Keep open: current source still expands unchanged regions from an edge rather than revealing a small window around a search match. A maintainer explicitly requested this separate feature request; no verified canonical or completed implementation supersedes it.

## Change summary

Reveal search matches inside collapsed diff regions with only contextLineCount surrounding lines, consistently in both editors.

## Best solution

Support localized search-result disclosure in the diff editor while preserving unrelated collapsed regions and existing manual expansion behavior. Plan the search-specific interaction and its effect on previously revealed context before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts`, `src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts`, `src/vs/editor/test/browser/widget/diffEditorWidget.test.ts`
- **Validation:** Extend the DiffEditorWidget2 browser suite with a long unchanged block containing an interior search match. Navigate to that match in each pane with contextLineCount set to 3 and assert that the match plus three surrounding lines on each side are visible while distant unchanged lines remain hidden. Cover repeated navigation and preservation of explicitly expanded regions; run the targeted diffEditorWidget.test.ts suite after implementation.
- **Behavior:**

  > With unchanged regions collapsed, navigating to an interior search match should reveal the match and contextLineCount lines before and after it, bounded by available lines. Distant unchanged text should remain collapsed instead of exposing the entire distance from a region edge. The original and modified panes should provide equivalent disclosure. Acceptance checks should cover both panes, repeated search navigation, and unchanged manual expansion behavior.
- **Trace:**

  > HideUnchangedRegionsFeature observes cursor-position changes and sends selection endpoints to DiffEditorViewModel.ensureOriginalLineIsVisible and ensureModifiedLineIsVisible with FromCloserSide. These methods locate a containing hidden region and delegate to UnchangedRegion.showOriginalLine or showModifiedLine, whose state consists of top and bottom visible-line counts; this path does not use contextLineCount or create a match-centered visible island. UnchangedRegion.setVisibleRanges can represent separated hidden ranges during diff recomputation, which explains why the reporter's edit-and-revert workaround can retain a small visible fragment, but search navigation does not use that path. The existing browser suite src/vs/editor/test/browser/widget/diffEditorWidget.test.ts constructs diff widgets and inspects unchanged-region state. Preserve diff mappings, manual disclosure controls, and unrelated cursor-navigation behavior. The maintainer endorsed investigating this feature in https://github.com/microsoft/vscode/issues/193834#issuecomment-2296064944; uncertainty remains over the lifetime of search-created disclosure and whether it applies beyond search navigation.
- **Open decisions:**
  - When navigating to another match or closing Find, should previously search-revealed fragments remain visible or collapse again, while preserving manually expanded regions?
  - Should localized context disclosure apply only to Find-result navigation, or also to other programmatic cursor and selection navigation into hidden regions?
