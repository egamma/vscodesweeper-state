# Issue #286361 — Error: AbstractContextKeyService has been disposed

[https://github.com/microsoft/vscode/issues/286361](https://github.com/microsoft/vscode/issues/286361)

## Summary

Still reproduces on main: closing a split diff editor triggers a disposed-context-key-service error because `clearInput()` in textDiffEditor.ts calls `super.clearInput()` (which can dispose the scoped context key service) before calling `setModel(null)`, and the latter triggers context key updates via the observable/transaction pipeline that hit the already-disposed service.

## Change summary

Closing a second diff editor in a split layout throws 'AbstractContextKeyService has been disposed' because context key updates fire after the scoped service is disposed.

## Best solution

Guard the context key update path in `setDiffModel` (or `bindContextKey` callbacks) so that setting the model to null during teardown does not fire context key evaluations against a disposed service. Alternatively, reorder `clearInput()` in `textDiffEditor.ts` so the model is cleared before calling `super.clearInput()`. The fix likely touches `src/vs/workbench/browser/parts/editor/textDiffEditor.ts` (clearInput ordering) or `src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts` (disposal guard in setDiffModel).
