# Issue #190426 — Set output height limit and scrolling for non-text stream outputs

[https://github.com/microsoft/vscode/issues/190426](https://github.com/microsoft/vscode/issues/190426)

## Summary

Keep open: current HTML rendering still does not apply the height limit and scrolling available for text outputs. This team-authored request remains necessary, and maintainers have explicitly consolidated matching reports here.

## Change summary

Allow large non-text notebook outputs, including rich dataframes and tables, to have a configurable height limit with internal scrolling.

## Best solution

Provide bounded, optionally scrollable rich outputs without requiring conversion to plain text or opening a separate data viewer. Settle the non-text height-setting semantics while preserving independent output presentation controls and the ability to disable internal scrolling.

## Plan brief

- **Likely files:** `extensions/notebook-renderers/src/index.ts`, `src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts`, `src/vs/workbench/contrib/notebook/browser/view/renderers/backLayerWebView.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/cellCommands/cellCommands.ts`
- **Validation:** In a trusted notebook, display a tall HTML table, a short HTML table, and a long plain-text output. With scrolling enabled and the agreed height limit, verify the tall table is bounded and all rows remain reachable by wheel and keyboard; the short table stays naturally sized. Toggle notebook.cell.toggleOutputScrolling and verify the rich output expands and becomes bounded again. Disable scrolling and verify unrestricted rich-output height, while preserving text-output behavior and output presentation menus.
- **Behavior:**

  > Large rich notebook outputs such as HTML dataframes and R tables should support a height limit and internal scrolling without switching to plain text or opening another viewer. Short outputs should retain their natural height, and every row of a bounded output must remain accessible. Users must be able to disable internal scrolling, including through the existing output-scrolling command. Existing text-output behavior and independent output presentation controls must remain intact.
- **Trace:**

  > In extensions/notebook-renderers/src/index.ts, renderOutputItem() dispatches text/html to renderHTML(), which appends the rich content without reading scrolling settings or output metadata. renderText() and renderStream() instead consult scrollingEnabled() and apply the scrollable class, whose CSS consumes --notebook-cell-output-max-height. BackLayerWebView._generateStyles() currently derives that height from text line count and line height, while ToggleCellOutputScrolling changes metadata.scrollable and resets individual renderers. Maintainers identify this issue as the HTML-scrolling request in https://github.com/microsoft/vscode/issues/206740#issuecomment-1997869591 and consolidate https://github.com/microsoft/vscode/issues/209156 here. Aggregate scrolling across mixed outputs is distinct work discussed in https://github.com/microsoft/vscode/issues/206226; do not assume it is required for this request. The source establishes the built-in HTML gap, but not the desired public height-setting contract or the coverage contract for third-party renderers.
- **Open decisions:**
  - Should rich-output height reuse notebook.output.textLineLimit translated through the output line height, or have an independent height setting with explicit non-text semantics?
  - Should the initial capability cover built-in rich renderers, or guarantee the same height and scrolling behavior for third-party notebook renderers as well?
