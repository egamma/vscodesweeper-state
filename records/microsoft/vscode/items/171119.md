# Issue #171119 — Hidden panels create actions that are disposed of on startup 

[https://github.com/microsoft/vscode/issues/171119](https://github.com/microsoft/vscode/issues/171119)

## Summary

The underlying perf issue persists on current main: `onDidRegisterViewContainers` still eagerly calls `updateCompositeBarActionItem` (which creates actions via `getCompositeActions`) for all containers before checking visibility with `showOrHideViewContainer`. Actions for hidden containers are now cached rather than disposed, but the unnecessary instantiation work on startup remains.

## Change summary

Hidden panel view containers have their composite actions eagerly created on startup even though they will be immediately hidden, wasting instantiation work.

## Best solution

In `onDidRegisterViewContainers` (src/vs/workbench/browser/parts/paneCompositeBar.ts), check `shouldBeHidden` before calling `updateCompositeBarActionItem` so that actions are only created for containers that will actually be shown, deferring action creation for hidden containers until they become visible.
