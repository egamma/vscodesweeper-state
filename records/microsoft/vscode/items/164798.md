# Issue #164798 — Offer "Resolve In Merge Editor" In Command Palette

[https://github.com/microsoft/vscode/issues/164798](https://github.com/microsoft/vscode/issues/164798)

## Summary

The requested Command Palette entry is still missing: Git explicitly hides its existing Resolve in Merge Editor command. Keep this accepted, team-authored request open; the related accessibility reports do not provide an older canonical covering the same observable gap.

## Change summary

Make Resolve in Merge Editor discoverable and invokable from the Command Palette.

## Best solution

Expose the existing Git merge-opening workflow through the Command Palette for an applicable active file, preserving its merge and rebase behavior. Agree on command visibility when no applicable file is active, and coordinate with the related keyboard-accessibility work without making that broader work a prerequisite.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/src/commands.ts`, `extensions/git/src/model.ts`
- **Validation:** In a development build, create a Git merge conflict, open the conflicted file as a normal text editor, open the Command Palette, search for Resolve in Merge Editor, and invoke it without arguments. Verify that the same file opens with the correct base, current, incoming, and result resources; repeat for a rebase conflict. Check the agreed visibility behavior with a clean file, no active text editor, and an already-open merge editor, and verify the existing editor-title action remains functional.
- **Behavior:**

  > A user viewing a Git-conflicted file in a normal text editor can discover Resolve in Merge Editor in the Command Palette and invoke it using the keyboard. Invocation opens the merge editor for that file with the same inputs and result as the existing editor-title action. Ordinary merge and rebase conflicts retain their existing semantics. Acceptance includes checking the agreed availability when the active editor is not an applicable conflicted file; adding a default keybinding or changing the in-editor button's tab order is outside this request.
- **Trace:**

  > extensions/git/package.json registers git.openMergeEditor but explicitly hides it from commandPalette with when: false; its editor/title contribution already has applicability conditions for a conflicted active resource. Commands.openMergeEditor in extensions/git/src/commands.ts already handles argument-free invocation by taking the active TabInputText URI and delegates to _open.mergeEditor after constructing merge resources. extensions/git/src/model.ts maintains git.mergeChanges and git.activeResourceHasMergeConflicts, which support the existing title-action context. The internal OpenMergeEditor action is argument-driven and does not itself provide an equivalent palette entry. Preserve the existing resource construction, rebase handling, and title-action behavior. https://github.com/microsoft/vscode/issues/247685 provides corroborating demand and related keyboard-accessibility discussion, but is newer and broader; https://github.com/microsoft/vscode/issues/159029 concerns interaction inside the merge editor. The remaining product question is availability outside the applicable active-file context, not which helper or registration structure to use.
- **Open decisions:**
  - When no applicable conflicted text file is active, should Resolve in Merge Editor be absent from the Command Palette or remain discoverable but disabled?
