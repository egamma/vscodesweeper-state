# Issue #316577 — Ctrl+Tab causes Tab key to get stuck

[https://github.com/microsoft/vscode/issues/316577](https://github.com/microsoft/vscode/issues/316577)

## Summary

Plausible keyboard handling bug: when Ctrl is released before Tab during quick navigate (Ctrl+Tab), the picker closes on Ctrl keyup but the subsequent Tab keyup may not be consumed, causing stray Tab insertions in the editor. The report is thin on exact reproduction but the mechanism is plausible from the source. However, the reporter's own Comment 2 identifies the sequence and this is Linux ARM64 specific — keeping open rather than needs-info since the reporter has already provided useful debugging detail and a third party confirmed it.

## Change summary

Releasing Ctrl before Tab during rapid Ctrl+Tab switching causes Tab key events to leak into the active editor, inserting unwanted tabs.

## Best solution

Investigate the quick navigate keyUp handler in `src/vs/platform/quickinput/browser/quickInput.ts` (the `registerQuickNavigation` method): when the picker is dismissed on modifier keyup, any pending non-modifier key (Tab) that was part of the chord should be suppressed or consumed so it doesn't leak to the editor underneath. This is likely a missing `e.preventDefault()`/`e.stopPropagation()` or a need to track that Tab was part of the quick-navigate chord.

## Evidence

- **mechanism:** src/vs/platform/quickinput/browser/quickInput.ts registerQuickNavigation() listens for keyUp on the modifier key (Ctrl) to close the picker and accept selection. If Ctrl releases before Tab, the picker closes but the Tab keydown already fired — the subsequent Tab keyup (or the original Tab keydown that was meant for the picker) hits the editor.
- **reporter detail:** Comment 2 identifies the problematic sequence: Ctrl↓ Tab↓ Ctrl↑ Tab↑ (rapid), vs the expected Ctrl↓ Tab↓ Tab↑ Ctrl↑. This is a race between modifier release and the non-modifier key.
- **third-party confirmation:** Comment 3 by Visclodev confirms the same issue persisting for months.
- **platform:** Reported on Fedora Linux Asahi Remix (ARM64), VS Code 1.120.0. May be more visible on Linux due to keyboard event delivery timing.
