# Issue #63388 — Indent/Outdent with tab key does not honor editor.autoIndent=false

[https://github.com/microsoft/vscode/issues/63388](https://github.com/microsoft/vscode/issues/63388)

## Summary

Keep open: disabling automatic indentation still leaves selected-block indentation snapping each line independently to tab stops, losing relative alignment. Disabling editor.useTabStops provides fixed-width block indentation, but does not settle the reported autoIndent behavior or justify reversing the maintainer's reopened bug triage.

## Change summary

Preserve relative whitespace alignment when indenting or outdenting selected blocks with automatic indentation disabled.

## Best solution

Resolve the intended relationship between editor.autoIndent and editor.useTabStops for block indentation, with explicit coverage for ordinary block comments and mixed-depth case labels. Retain the existing fixed-width mode and avoid conflating selected-block indentation with the separate single-cursor Tab and Enter behavior.

## Evidence

- **Current-source reproduction:** In src/vs/editor/common/commands/shiftCommand.ts, ShiftCommand.getEditOperations selects its snapping branch solely from useTabStops. With four-space indentation, leading whitespace lengths 4 and 5 both become 8 on indent; on outdent they become 0 and 4. These are the reporter's alignment-breaking outcomes, independent of disabling automatic indentation.
