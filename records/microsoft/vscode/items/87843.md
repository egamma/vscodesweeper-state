- **Behavior:**

  > Calling Terminal.sendText immediately after window.createTerminal({ name, pty }) must deliver the input to that pseudoterminal's handleInput once initialization completes. Default execution sends the normalized input with its terminating carriage return; shouldExecute=false sends no additional terminator. Delivery must not require terminal.show, arbitrary timeouts, or creating the terminal during extension activation. Acceptance includes repeating the sequence with a newly created replacement terminal after disposal.
- **Trace:**

  > The discussion confirms historical failures, including intermittent delivery, but current-main reproduction remains unverified. ExtHostTerminal.sendText forwards through MainThreadTerminalService.$sendText, whose instance lookup awaits the creation promise stored by $createTerminal. TerminalInstance.sendText normalizes input and delegates to TerminalProcessManager.write, which waits for ptyProcessReady before TerminalProcessExtHostProxy forwards input back through $acceptProcessInput to ExtHostPseudoterminal.input. ExtHostPseudoterminal.startSendingEvents attaches output listeners and calls pty.open before emitting readiness. The existing Extension pty terminals API tests do not cover this delivery contract; diagnosis should begin there rather than assume the old async hypothesis still applies. Preserve the synchronous public createTerminal/sendText API and existing normal-terminal input behavior; the thread's Thenable suggestion is not an accepted API requirement.
