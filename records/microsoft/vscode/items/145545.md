# Issue #145545 — Consider incomplete vs complete results from inline completion provider

[https://github.com/microsoft/vscode/issues/145545](https://github.com/microsoft/vscode/issues/145545)

## Summary

Keep open for an inline-completion API decision: current source still lacks CompletionList-style complete/incomplete result semantics. The proposed forward-stability option addresses a narrower case and does not establish that this request is completed.

## Change summary

Consider distinguishing complete and incomplete inline-completion results, including their default and re-request semantics.

## Best solution

Have the inline-completions API owner establish whether providers need list-completeness semantics beyond enableForwardStability, and document the resulting default and re-request contract. Preserve the existing contract until that product/API decision is made.
