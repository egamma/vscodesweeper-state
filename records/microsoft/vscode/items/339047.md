[https://github.com/microsoft/vscode/issues/339047](https://github.com/microsoft/vscode/issues/339047)

## Summary

The original report is too vague on its own ("won't recreate its internal directories"), but a commenter's trace pins this to an interaction between the Remote - SSH and Dev Containers extensions (an ENOPRO filesystem-provider error resolving a .devcontainer.json over vscode-remote://). Both extensions are in the VS Code-team-owned Remote Development family, so this should be routed/moved to the owning tracker rather than closed here.

## Change summary

Remote-SSH sessions fail to reconnect / recreate expected remote directories when the Dev Containers extension is also active, surfacing an ENOPRO file-system-provider error for .devcontainer.json.

## Best solution

Move this to microsoft/vscode-remote-release, where Remote-SSH and Dev Containers issues are triaged together; the fix likely involves ensuring the vscode-remote fs provider is registered/available before Dev Containers probes for .devcontainer.json during reconnect.
