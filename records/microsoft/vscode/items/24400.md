# Issue #24400 — Support args for `editor.action.trimTrailingWhitespace` command

[https://github.com/microsoft/vscode/issues/24400](https://github.com/microsoft/vscode/issues/24400)

## Summary

The auto-save reason argument is implemented, but trimming a document selected by URI without an active editor remains unsupported. Keep this request open for that remaining capability; the linked merged PR addressed only part of the ask.

## Change summary

Allow extensions to invoke editor.action.trimTrailingWhitespace for a specified document and distinguish automatic saves from manual trimming.

## Best solution

Retain the existing { reason: 'auto-save' } behavior and assess an explicit document-targeting contract that lets extensions trim an inactive document without changing editor focus.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/linesOperations/browser/linesOperations.ts`, `src/vs/editor/browser/editorExtensions.ts`, `src/vs/editor/common/commands/trimTrailingWhitespaceCommand.ts`, `src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts`
- **Validation:** Validate command execution with document A active and document B supplied as the target: only B is trimmed, A and editor focus remain unchanged, and B can be trimmed without a visible editor. Verify existing no-argument execution and { reason: 'auto-save' } cursor preservation remain unchanged.
- **Behavior:**

  > Extensions can already request cursor-preserving trimming in the active editor with { reason: 'auto-save' }, but cannot direct this command at an inactive document. The remaining goal is explicit document-targeted trimming without opening or focusing that document. Acceptance should cover an inactive target, no visible editor for the target, unchanged non-target content and focus, and compatibility with existing command calls.
- **Trace:**

  > TrimTrailingWhitespaceAction in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts accepts only a reason object and executes TrimTrailingWhitespaceCommand against its editor. EditorCommand.runEditorCommand in src/vs/editor/browser/editorExtensions.ts chooses the focused or active editor, so the current dispatch cannot honor a target URI. The merged https://github.com/microsoft/vscode/pull/35778 implemented cursor preservation for automatic saves, not document targeting. TrimWhitespaceParticipant in src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts demonstrates model-based trimming during saves, but is not an arbitrary-document command contract. Preserve existing editor-focused execution and auto-save cursor semantics; uncertainty starts at the public argument shape and whether document targeting belongs in this editor action or a separate model-oriented command.
- **Open decisions:**
  - Should inactive-document trimming extend editor.action.trimTrailingWhitespace or be exposed through a separate document-oriented command?
  - If the existing command is extended, what argument contract identifies the target URI while preserving current { reason: 'auto-save' } callers?

## Evidence

- **Partial implementation:** https://github.com/microsoft/vscode/pull/35778 is merged. Its body explicitly references https://github.com/microsoft/vscode/issues/24400, but its diff adds only args.reason === 'auto-save' and cursor preservation, not a URI argument.
- **Current command contract:** src/vs/editor/contrib/linesOperations/browser/linesOperations.ts:450-495 defines TrimTrailingWhitespaceArgs with only reason?: 'auto-save'. TrimTrailingWhitespaceAction.run operates on the supplied editor's selection and model; it does not resolve a requested document URI.
- **Remaining document-targeting gap:** src/vs/editor/browser/editorExtensions.ts:302-329 selects the focused or active code editor before invoking an EditorAction. The registered handler at line 159 forwards one argument object. Passing the requested URI and positional reason does not target an inactive document.
- **Existing capability check:** src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts:48-85 implements files.trimTrailingWhitespace per resource during saving, preserving cursor positions for SaveReason.AUTO. This covers automatic save-time cleanup but not an extension's explicit invocation of editor.action.trimTrailingWhitespace against an arbitrary inactive document.
- **Canonical search:** Repository searches for trimTrailingWhitespace, inactive-document whitespace trimming, and editor command URI targeting did not establish an open canonical for the remaining request. https://github.com/microsoft/vscode/issues/871 was read and remains open, but requests command-sequence keybindings rather than document-targeted trimming; it is not a duplicate.
