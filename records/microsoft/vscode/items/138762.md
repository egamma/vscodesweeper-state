# Issue #138762 — Code Lenses are trimmed to the line length

[https://github.com/microsoft/vscode/issues/138762](https://github.com/microsoft/vscode/issues/138762)

## Summary

Keep open: current CodeLens rendering remains single-row and does not provide the requested multiline overflow behavior. The request has 33 upvotes and was accepted into the Backlog; the command picker provides access to hidden commands but does not satisfy the inline-display request.

## Change summary

Display CodeLens commands on additional rows when multiple lenses on the same source line exceed the available width.

## Best solution

Provide an editor-owned overflow presentation that keeps all CodeLens commands discoverable without overlapping source text. Decide whether additional inline rows should be automatic or opt-in, while preserving the existing command picker.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/codelens/browser/codelensController.ts`, `src/vs/editor/contrib/codelens/browser/codelensWidget.ts`, `src/vs/editor/contrib/codelens/browser/codelensWidget.css`
- **Validation:** Use a CodeLens provider returning several long commands on one source line, then narrow and widen the editor. Under the chosen presentation policy, verify every command is visible and clickable, source text never overlaps the lenses, resizing updates reserved space, and codelens.showLensesInCurrentLine continues to offer all commands.
- **Behavior:**

  > Multiple CodeLens commands attached to one source line can exceed the available inline width, leaving some actions hidden. The requested outcome is additional display rows so all commands remain visible and usable. Acceptance should cover narrow and wide editor layouts, commands from multiple providers, editor resizing, and sufficient vertical space above source text. Existing single-row presentation when commands fit and the current-line command picker must remain functional.
- **Trace:**

  > CodeLensContribution in src/vs/editor/contrib/codelens/browser/codelensController.ts groups lenses by their starting source line and supplies one calculated codeLensHeight per CodeLensWidget. In codelensWidget.ts, CodeLensContentWidget.withCommands combines commands into one span, and CodeLensViewZone reserves the supplied height. codelensWidget.css explicitly prevents wrapping and hides overflow; the generic content-widget layout caps non-overflow widgets at editor contentWidth. These paths establish that multiline presentation is absent, not that clipping follows the source line's character count. The command codelens.showLensesInCurrentLine already provides a picker for all commands and should remain unchanged in purpose. The remaining uncertainty is the product policy for additional rows and their impact on editor layout, not extension ownership: https://github.com/microsoft/vscode/issues/138762.
- **Open decisions:**
  - Should overflowing CodeLens commands automatically occupy additional rows, or should multiline presentation be opt-in while the default remains single-row?

## Evidence

- **Accepted community demand:** https://github.com/microsoft/vscode/issues/138762 has 33 community upvotes. The December 11, 2021 bot comment records promotion to the Backlog after meeting the community threshold.
- **Current single-row rendering:** src/vs/editor/contrib/codelens/browser/codelensController.ts groups lenses by range.startLineNumber and creates one CodeLensWidget per group. CodeLensContentWidget.withCommands in codelensWidget.ts appends those commands into one span, while codelensWidget.css uses inline-flex, white-space: nowrap and overflow: hidden without flex wrapping.
- **Width and height boundary:** CodeLensContentWidget sets allowEditorOverflow to false; src/vs/editor/browser/viewParts/contentWidgets/contentWidgets.ts limits such widgets to editor contentWidth. The controller supplies a single calculated codeLensHeight to the view zone rather than measuring additional command rows. This supports the overflow concern, but does not establish literal clipping to the source line's character length.
- **Existing capability is a workaround:** src/vs/editor/contrib/codelens/browser/codelensController.ts registers codelens.showLensesInCurrentLine, which gathers commands for the current line and offers them through a quick picker. editor.codeLens, editor.codeLensFontFamily and editor.codeLensFontSize control visibility and typography, not multiline display; neither the picker nor a smaller font fulfills the requested inline presentation.
- **Discussion does not settle core presentation:** The December 10, 2021 user comment on https://github.com/microsoft/vscode/issues/138762 suggests that the macro extension also expose actions in its context menu. That is an extension-side UX alternative, not evidence that editor CodeLens overflow has been resolved or declined.

The checkout is shallow, so its file history cannot establish a historical fixing commit; current source still lacks multiline presentation.
