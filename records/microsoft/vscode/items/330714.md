# Issue #330714 — Agents window: pasted content from another workspace's response is not visible in the target input

## Summary

Plausible bug in the new Agents window's cross-session paste handling, but I couldn't pin the exact defect from source alone and can't execute a multi-workspace Agents window repro from this checkout, so I'm asking the reporter for a bit more setup detail rather than guessing at the mechanism.

## Change summary

Copying agent-response text from one workspace's Agents window session and pasting it into a different workspace's chat input creates a 'pasted text attachment' reference, but the attachment's content isn't actually available to the model in the target session.

## Best solution

Trace how `IChatPasteTargetService`/`CopyAttachmentsProvider` and the plain-text `createPastedTextArtifact` path (src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts) interact with the Agents window's session/attachment resolution in src/vs/sessions — likely the attachment value is being dropped or not correctly forwarded to the target session/agent host when source and destination are different workspace sessions, rather than a general paste-provider bug (the redo()/addAttachments() path embeds the text value inline, so the loss point is probably session-specific attachment resolution, not the paste provider itself).
