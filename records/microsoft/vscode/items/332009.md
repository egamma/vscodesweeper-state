# Issue #332009 — In-product PR viewer stuck. No way to open in external web browser

[https://github.com/microsoft/vscode/issues/332009](https://github.com/microsoft/vscode/issues/332009)

## Summary

Fresh, plausible report: when the Agents Window opens a PR via the in-product GitHub Pull Request webview (OpenPullRequestAction in pullRequestActions.ts), there's no fallback action to force-open the PR in an external browser if that webview gets stuck. No maintainer or duplicate signal yet, so this should be routed to the right area rather than closed.

## Change summary

When the built-in PR viewer webview hangs/gets stuck, the user has no way to open the same pull request in their external web browser instead.

## Best solution

Add an explicit 'Open in Browser' fallback (or always-available action) alongside/within the in-product PR webview shown by OpenPullRequestAction in src/vs/sessions/contrib/github/browser/pullRequestActions.ts, so users aren't stuck when the embedded webview fails to load; currently openExternal is only used as a fallback when the extension isn't installed or urlService.open() rejects, not when the webview itself hangs after opening.
