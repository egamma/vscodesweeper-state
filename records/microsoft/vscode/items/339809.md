# Issue #339809 — Should dismissing migration banner dismiss section or vice versa

[https://github.com/microsoft/vscode/issues/339809](https://github.com/microsoft/vscode/issues/339809)

## Summary

Team-authored design question about the brand-new AI Customization migration flow (filed by its own author minutes after testing PR #339525): the migration banner and the migration section track dismissal independently, and the author is explicitly asking which should drive the other — this needs a maintainer design decision, not a close.

## Change summary

Dismissing the MCP migration section does not also dismiss the top banner that links to it (or vice versa), leaving the two surfaces out of sync.

## Best solution

A maintainer should decide the intended relationship (single shared dismissal state vs. two intentionally independent ones) for the AI Customization migration UI, then align the banner dismissal (chatCustomizationMigrationNotice.ts, storage key `chat.customizationMigrationNotice.dismissed.<workspace>`) with whatever marks a migration section/category as handled.
