# Issue #312106 — Agent dropdown popup obscures click target — description tooltip intercepts selection

[https://github.com/microsoft/vscode/issues/312106](https://github.com/microsoft/vscode/issues/312106)

## Summary

The click-interception path remains possible on current main: agent descriptions open a separate pointer-active flyout which can be clamped over its originating row when neither side has sufficient space. This should be routed to the chat input picker area rather than closed.

## Change summary

Agent-description flyouts can cover an agent row and intercept the click intended to select that agent.

## Best solution

Ensure action-list description flyouts never overlap the selectable row that opened them, including constrained-window layouts, while preserving mouse and keyboard access to intentionally interactive flyout content.

- **Trace:**

  > ModePickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts supplies agent descriptions through `IActionWidgetDropdownAction.hover`. ActionWidgetDropdown in src/vs/platform/actionWidget/browser/actionWidgetDropdown.ts forwards that configuration to ActionListWidget, whose `_showSubmenuForElement` in src/vs/platform/actionWidget/browser/actionList.ts creates an absolute, pointer-active panel. The horizontal layout chooses the roomier side and then clamps the panel to the viewport; when neither side has sufficient space, that clamp can move the panel across the list row. Commit https://github.com/microsoft/vscode/commit/b9a6d9b4db54513b516588d982c21e268b45ee9f deliberately made flyout interaction retain focus, so the boundary is placement for ordinary description flyouts: do not disable pointer interaction for flyouts containing intentional controls or change row keyboard navigation.
