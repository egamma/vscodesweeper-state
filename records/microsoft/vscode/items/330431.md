# Issue #330431 — Important color customizations are still ignored in modern UI mode

[https://github.com/microsoft/vscode/issues/330431](https://github.com/microsoft/vscode/issues/330431)

## Summary

Modern UI's editor tabs deliberately use a dedicated `modernTab.*` color namespace for active/hover background and foreground instead of the classic `tab.*` keys — confirmed directly in current main's color registrations and CSS. The requested capability (customizing tab colors under Modern UI) already exists, just under new keys, so this reads as as-designed rather than a bug.

## Change summary

Reporter says `tab.*` color customizations (background/border) have no effect once Modern UI mode is enabled, hurting accessibility/contrast for editor tabs.

## Best solution

Keep the Modern UI tab redesign's dedicated token set; point the reporter at `modernTab.activeBackground`, `modernTab.hoverBackground`, `modernTab.activeForeground`, and `modernTab.hoverForeground` in `workbench.colorCustomizations` for active/hover tab colors under Modern UI, and note that `tab.selectedBorderTop`/`tab.activeBorderTop` are still respected there. A worthwhile follow-up (not required for this close) would be a release-notes/settings-description callout that Modern UI renames these tokens, to reduce confusion for users migrating existing customizations.
