# Issue #330300 — Markdown previewer sometimes incorrectly renders ranges of text in math mode

[https://github.com/microsoft/vscode/issues/330300](https://github.com/microsoft/vscode/issues/330300)

## Summary

The supplied currency example matches the bundled math parser's delimiter logic, which contradicts its documented whitespace rules. Keep this open: the remaining work belongs in the parsing dependency, and no verified canonical or fixing commit was found.

## Change summary

Prevent literal currency dollar signs from turning several lines of Markdown prose into an inline math expression.

## Best solution

Resolve the delimiter behavior in @vscode/markdown-it-katex so currency prose follows the documented syntax while valid math remains supported, then adopt that correction in the built-in Markdown preview.

## Evidence

- **Exact trigger:** https://github.com/microsoft/vscode/issues/330300 supplies a complete paragraph with an opening currency dollar sign in 'as $ /' and a second in '0.00138 $/audio-h'. The reporter describes repeatable math rendering between those signs, including after restarting VS Code.
- **Built-in adoption:** extensions/markdown-math/src/extension.ts enables math by default and installs @vscode/markdown-it-katex through extendMarkdownIt. extensions/markdown-math/package-lock.json resolves that dependency to 1.1.2; this is built-in preview behavior, not evidence against an installed third-party extension.
- **Parser trace:** https://github.com/microsoft/vscode-markdown-it-katex/blob/v1.1.2/src/index.ts: isValidInlineDelim accepts the first dollar sign because its preceding character is whitespace, and accepts the second as a closer because its following character is '/'. inlineMath searches for the next unescaped dollar sign across the paragraph and places the intervening prose in a math_inline token. Neither opening-right whitespace nor closing-left whitespace is rejected.
- **Documented expectation:** https://github.com/microsoft/vscode-markdown-it-katex/blob/v1.1.2/README.md, Syntax, states that an opening dollar sign must have a non-space character immediately to its right and a closing dollar sign must have a non-space character immediately to its left. Both currency signs in the reported example violate those documented delimiter conditions.
- **Existing workaround:** extensions/markdown-math/package.json registers markdown.math.enabled with default true; setting it to false prevents installation of the preview math plugin. Escaping literal dollar signs is also documented by the dependency. These workarounds do not correct delimiter handling while retaining ordinary unescaped currency prose and math support.
- **Canonical search:** Searches for Markdown math, dollar signs, and currency found https://github.com/microsoft/vscode/issues/334935 and https://github.com/microsoft/vscode/issues/335663. Both are newer than this re-reviewed issue and concern different surfaces: the hybrid Markdown editor and source syntax highlighting, respectively. The older https://github.com/microsoft/vscode/issues/223545 concerns highlighting of legitimate multiline formulas; its open candidate fix https://github.com/microsoft/vscode/pull/304800 changes TextMate grammar, not preview parsing. None is a verified canonical for this report.
