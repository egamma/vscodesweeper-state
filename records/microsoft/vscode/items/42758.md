# Issue #42758 — [json] improve property suggestions with oneOf

[https://github.com/microsoft/vscode/issues/42758](https://github.com/microsoft/vscode/issues/42758)

## Summary

This remains a valid JSON IntelliSense gap with multiple independent confirmations and no verified canonical issue or completed fix. The Backlog milestone and 15 upvotes support retaining it for design and implementation.

## Change summary

Offer property and value suggestions from every plausible `oneOf` branch while the JSON document is still incomplete.

## Best solution

Evolve schema matching in the JSON language service so completion can consider temporarily invalid `oneOf` branches, then narrow suggestions once entered properties identify a branch, without weakening validation results.

## Plan brief

- **Likely files:** `extensions/json-language-features/server/src/jsonServerMain.ts`
- **Validation:** Add JSON language-service completion tests using both schemas from the issue: an empty object must suggest properties from all plausible `oneOf` branches, and entering a branch-specific property must narrow subsequent suggestions while existing validation tests remain unchanged.
- **Behavior:**

  > When editing an incomplete JSON object governed by `oneOf`, completion should offer properties from every branch that is still plausible, including properties whose absence currently makes a branch fail `required` validation. For value alternatives such as object, string, and array, completion should retain all plausible choices. Once entered content identifies a branch, suggestions should narrow to that branch, while strict document validation remains unchanged.
- **Trace:**

  > The thread traces the behavior to the JSON language service's schema matching in `src/parser/jsonParser.ts`: completion consumes matching schemas produced by validation, but validation excludes a `oneOf` branch when required properties are absent from the still-incomplete object. The VS Code integration is under `extensions/json-language-features`, while the diagnosed core algorithm is maintained in `microsoft/vscode-json-languageservice`; determine whether the service can expose completion-tolerant matches without changing validation semantics. Preserve normal `oneOf` validation and avoid continuing to union unrelated branch suggestions after the user's entered properties disambiguate the schema. The issue and reproductions are at https://github.com/microsoft/vscode/issues/42758.
- **Open decisions:**
  - At what point should branch-specific entered content stop unioning suggestions from the other `oneOf` alternatives?
  - Should completion tolerate only missing `required` properties when matching incomplete branches, or all validation failures that can arise while a value is partially typed?
