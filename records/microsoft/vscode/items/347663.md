# Issue #347663 — Agents window “Open in Editor” opens a new folder window instead of the existing workspace window

[https://github.com/microsoft/vscode/issues/347663](https://github.com/microsoft/vscode/issues/347663)

## Summary

Keep open: the current handoff loses the workspace-file identity, and the return path opens folders that cannot match the existing workspace-file window. The related reports do not establish a canonical for this specific round-trip failure.

## Change summary

Preserve the originating Remote SSH workspace-file context when returning from Agents to an existing editor window.

## Best solution

The reported single-folder workspace round trip should return to its existing Remote SSH editor without replacing the workspace-file context. Preserve session-specific worktree destinations and remote authority rather than changing general window matching to equate folders with workspace files.

- **Return path:** In src/vs/sessions/electron-browser/actions/vscodeActions.ts, openSessionInVSCode reads the selected chat's workspace folders, converts their workingDirectory values into IFolderToOpen entries, and calls nativeHostService.openWindow with forceNewWindow: true. It does not request the originating workspace file.
- **Conclusive window-matching mismatch:** src/vs/platform/windows/electron-main/windowsFinder.ts: findWindowOnWorkspaceOrFolder matches a workspace-file window only against its configPath, not against contained folders. windowsMainService.ts:675–735 uses that helper before opening unmatched folders. Thus a folder request cannot reuse the reported .code-workspace window; removing forceNewWindow alone would not restore its identity.
