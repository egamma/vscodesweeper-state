## Summary

The intermittent Open Editors selection collapse remains confirmed on macOS and Windows. A merged selection-preservation change covered editor metadata refreshes, but a later confirmation shows that Ctrl/Cmd-click selection can still collapse, so this needs further diagnosis rather than closure.

## Change summary

Ctrl/Cmd-right-clicking a second Open Editors entry intermittently collapses the multi-selection and prevents the Compare Selected action from appearing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/views/openEditorsView.ts`, `src/vs/base/browser/ui/list/listWidget.ts`, `src/vs/workbench/contrib/files/test/browser/openEditorsView.test.ts`
- **Validation:** Exercise Ctrl/Cmd-right-click repeatedly on a second file in Open Editors on macOS and Windows and verify that both entries remain selected and Compare Selected appears; finish with an automated regression test reproducing the relevant list/context-menu event sequence.
- **Behavior:**

  > With two file editors shown in Open Editors, Ctrl/Cmd-right-clicking the second entry must retain both entries in the selection while opening the context menu. The menu must offer Compare Selected, and invoking it must compare those two files. Repeated attempts, metadata updates, and focus changes must not intermittently collapse the selection; the existing Select for Compare workflow remains unchanged.
- **Trace:**

  > OpenEditorsView in src/vs/workbench/contrib/files/browser/views/openEditorsView.ts synchronizes list selection with active-editor changes through focusActiveEditor and also refreshes list elements on editor model events. MouseController in src/vs/base/browser/ui/list/listWidget.ts handles modifier selection and context-menu focus as separate events, which is the likely boundary for the reported timing-sensitive collapse. Commit https://github.com/microsoft/vscode/commit/571383e6a39b7bcb4b097b8ab404b189b8f864 stabilized identities and metadata-refresh selection, and src/vs/workbench/contrib/files/test/browser/openEditorsView.test.ts covers refresh/resort preservation, but the later report confirms the context-menu path remains. Diagnose the exact event that resets selection before choosing whether the correction belongs in Open Editors or shared list handling; avoid changing right-click selection semantics for unrelated WorkbenchList consumers.
