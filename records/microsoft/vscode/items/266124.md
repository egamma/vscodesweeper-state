# Issue #266124 — Hookup LanguageModelDataPart to chat ouput renderers

[https://github.com/microsoft/vscode/issues/266124](https://github.com/microsoft/vscode/issues/266124)

## Summary

The requested integration remains missing on current main: chat participants cannot push a LanguageModelDataPart through ChatResponseStream and have it rendered by a contributed chat output renderer. The closed implementation attempt was never merged, so this accepted On Deck API work should remain open.

## Change summary

Allow chat participants to emit LanguageModelDataPart content directly to contributed chat output renderers without routing it through a tool call.

## Best solution

Carry LanguageModelDataPart through the chat participant progress, model, persistence, and view-model layers as typed data content, then render it through IChatOutputRendererService while preserving existing tool-result and Markdown code-block rendering.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.proposed.chatParticipantAdditions.d.ts`, `src/vs/workbench/api/common/extHostChatAgents2.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/contrib/chat/common/model/chatModel.ts`, `src/vs/workbench/contrib/chat/common/model/chatViewModel.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/api/test/common/extHostChatAgents2.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`
- **Validation:** Add targeted unit coverage proving that pushing a LanguageModelDataPart emits a data progress DTO with unchanged MIME type and bytes, and that ChatListItemRenderer passes that data to a stub IChatOutputRendererService; run the matching extHostChatAgents2 and chatListRenderer unit-test selectors.
- **Behavior:**

  > A chat participant can push a LanguageModelDataPart containing bytes and a MIME type into its ChatResponseStream. If a chat output renderer supports that MIME type, its output appears inline in the response without a tool call. The MIME type and bytes reach the renderer unchanged, and existing Markdown code-block and tool-result rendering remain unchanged. The response must also remain valid when restored or rerendered.
- **Trace:**

  > ChatResponseStream.push is implemented in src/vs/workbench/api/common/extHostChatAgents2.ts and delegates ordinary parts to ChatResponsePart.from in src/vs/workbench/api/common/extHostTypeConverters.ts; that converter has no LanguageModelDataPart branch and currently returns empty markdown for unsupported parts. The progress DTO derives from chat response-content types in src/vs/workbench/api/common/extHost.protocol.ts, while IChatRendererContent in src/vs/workbench/contrib/chat/common/model/chatViewModel.ts and renderChatContentPart in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts contain no direct data-content path. IChatOutputRendererService.renderOutputPart already supplies the MIME renderer boundary in src/vs/workbench/contrib/chat/browser/chatOutputItemRenderer.ts. The earlier unmerged implementation is https://github.com/microsoft/vscode/pull/268098, and the broader API proposal is https://github.com/microsoft/vscode/issues/257761. Keep the scope to direct participant-produced data; do not change existing tool-call or Markdown code-block behavior.

## Evidence

- **missing API path:** On current main, src/vscode-dts/vscode.d.ts declares ChatResponseStream.push(part: ChatResponsePart), while LanguageModelDataPart is a language-model message/response type rather than a ChatResponsePart; the proposed overload in src/vscode-dts/vscode.proposed.chatParticipantAdditions.d.ts likewise does not include LanguageModelDataPart.
- **missing conversion:** src/vs/workbench/api/common/extHostChatAgents2.ts routes push() through ChatResponsePart.from, but src/vs/workbench/api/common/extHostTypeConverters.ts has no LanguageModelDataPart branch and falls back to an empty markdownContent DTO for unsupported parts.
- **missing renderer integration:** src/vs/workbench/contrib/chat/browser/chatOutputItemRenderer.ts exposes IChatOutputRendererService.renderOutputPart for MIME data, but src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts has no data-content case in renderChatContentPart.
- **unmerged implementation attempt:** https://github.com/microsoft/vscode/pull/268098 explicitly attempted to fix this issue across the extension-host converter, chat model, and renderer, but it was closed without merging on 2025-09-24.
- **parent API proposal:** https://github.com/microsoft/vscode/issues/257761 remains open and tracks the broader custom chat-widget API; this issue is the narrower direct-participant data-source integration identified by that proposal, not a re-review duplicate with the same observable symptom.
