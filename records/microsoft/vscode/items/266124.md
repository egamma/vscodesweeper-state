# Issue #266124 — Hookup LanguageModelDataPart to chat ouput renderers

[https://github.com/microsoft/vscode/issues/266124](https://github.com/microsoft/vscode/issues/266124)

## Summary

Still unimplemented on main: the feature request to hook up LanguageModelDataPart to chat output renderers has not landed — the related PR #268098 was closed without merging, and the commit from that branch is not on main. The plumbing for IChatResponseDataPart exists in the internal types and type converters, but data parts are not wired into the chat response stream for direct rendering by chat participants. Valid work item, keeping open.

## Change summary

Allow chat participants to push LanguageModelDataPart into the response stream and have it rendered by registered chat output renderers, enabling extension-driven rich content without tool calls.

## Best solution

Complete the integration started in the closed PR https://github.com/microsoft/vscode/pull/268098: wire LanguageModelDataPart through the chat response stream (extHostChatAgents2.ts → chatModel → content parts) so that data parts with registered mime types are rendered via IChatOutputRendererService, analogous to how tool output data parts are already rendered in chatToolOutputPart.ts.
