## Change summary

Fonts installed for the current Windows user stop rendering in VS Code after reboot, despite working immediately after installation.

## Best solution

## Plan brief

- **Likely files:** `src/vs/editor/browser/config/domFontInfo.ts`, `src/vs/editor/browser/config/charWidthReader.ts`, `src/vs/editor/browser/config/fontMeasurements.ts`
- **Validation:** On Windows 11 using a standard user account, install JetBrains Mono for the current user, select it with editor.fontFamily, verify rendering, reboot, and reopen VS Code with extensions disabled. Verify that the selected font still renders without reinstalling it or clearing caches; compare availability in Windows Terminal, Notepad, and a minimal browser/Electron page to establish ownership.
- **Behavior:**

  > A font installed for the current Windows user works immediately but becomes unavailable to VS Code after reboot. It should remain usable without administrator privileges, all-users installation, cache deletion, or reinstallation. Acceptance requires checking the selected font before and after an actual Windows reboot, not merely reloading the editor. The existing all-users installation workaround must continue to work.
- **Trace:**

  > The issue discussion contains multiple independent confirmations, but this review did not reproduce on current main. applyFontInfo in src/vs/editor/browser/config/domFontInfo.ts supplies the CSS family, and DomCharWidthReader in charWidthReader.ts measures the resulting browser rendering. FontMeasurementsImpl in fontMeasurements.ts restores persisted measurements as untrusted and later evicts them; this does not prove that the OS font remains discoverable. Failures in other Windows applications point toward an OS-level boundary, while https://github.com/microsoft/vscode/issues/236805 reports the same symptom with the font still working in Word and was explicitly consolidated here by a maintainer. The investigation must distinguish font availability from cached measurements before selecting a fix; do not assume that changing measurement eviction resolves installation persistence. Preserve configured family names and avoid requiring elevated installation.
