- **Same observable symptom and base-selection mechanism:** In https://github.com/microsoft/vscode/issues/228418#issuecomment-2506012080, the reporter identifies branch.main.vscode-merge-base=origin/main and confirms that changing it to upstream/main makes Auto show the desired upstream history. This report names the same configuration mechanism for branch.fix-XXX and asks to automate that preference rather than manually correct it.
- **Current source still has the gap:** extensions/git/src/repository.ts:1774-1817, Repository.getBranchBase, honors a cached remote base, otherwise resolves the creation branch from its reflog and caches that branch's immediate upstream. getUpstreamBranch at lines 1864-1877 follows the configured tracking remote directly; it does not discover the fork's contribution target. A feature branch created from main tracking origin/main therefore still selects origin/main.
- **Existing capabilities are workarounds:** src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:1394-1408, _resolveHistoryItemFilter, constructs Auto from the current, tracking and base refs. The registered workbench.scm.action.graph.pickHistoryItemRefs action permits manual ref selection, and Repository.getBranchBase accepts an explicit branch.<name>.vscode-merge-base override. Neither automatically chooses upstream/main for newly created feature branches.
