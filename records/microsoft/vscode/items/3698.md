# Issue #3698 — Hover message/tooltip on ruler when defining decorators

[https://github.com/microsoft/vscode/issues/3698](https://github.com/microsoft/vscode/issues/3698)

## Summary

The extension-decoration API still does not provide hover messages on overview-ruler marks. Keep this accepted Backlog request open: existing content hovers do not cover it, and no qualifying canonical duplicate was found.

## Change summary

Allow extensions to display informational tooltips when users hover decoration marks in the editor overview ruler without scrolling to the decorated text.

## Best solution

Support extension-provided information on overview-ruler decorations while preserving scrollbar navigation and existing text hovers. Settle the hover-message contract and overlapping-marker behavior before implementation; a magnifying-glass preview is optional additional scope.

- **Behavior:**

  > Extensions need to expose information when a user hovers an overview-ruler decoration, including decorations whose source lines are off screen. Existing hoverMessage behavior on decorated text does not satisfy this request. Acceptance should demonstrate the approved tooltip contract without scrolling and preserve existing text hovers and scrollbar navigation. Overlapping marks need deterministic, maintainer-approved behavior; a source-code magnifying-glass preview is not required to satisfy the central ask.
- **Trace:**

  > The public decoration API in src/vscode-dts/vscode.d.ts exposes ruler colors and lanes separately from per-decoration hoverMessage. AbstractCodeEditorService's decoration options in src/vs/editor/browser/services/abstractCodeEditorService.ts construct color/lane ruler metadata, while DecorationsOverviewRuler in src/vs/editor/browser/viewParts/overviewRuler/decorationsOverviewRuler.ts draws compressed canvas rectangles without hover handling. ContentHoverWidgetWrapper supplies built-in text-range anchors, and MarkdownHoverParticipant consumes hover messages from decorations on that anchored line; this establishes why ordinary decoration hovers do not cover off-screen ruler marks. The unresolved boundary is the public message contract and how compressed, overlapping marks select content, not a confirmed regression. Preserve existing content-hover semantics and scrollbar interaction. https://github.com/alefragnani/vscode-bookmarks/issues/19 records a dependent use case and was closed for lack of progress rather than implementation.
- **Open decisions:**
  - Should overview-ruler tooltips reuse DecorationOptions.hoverMessage automatically, or require a separately opted-in ruler message?
  - When multiple decorations overlap the hovered ruler position, should the tooltip combine their messages or select one by a defined priority?
