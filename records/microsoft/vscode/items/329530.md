# Issue #329530 — vs code crashes on standard user (non-admin rights)

[https://github.com/microsoft/vscode/issues/329530](https://github.com/microsoft/vscode/issues/329530)

## Summary

The reporter's own follow-up investigation (comment 6) traced the crash to their organization's Endpoint Privilege Management (EPM) policy (`ChildProcessBehavior=AllowRunElevatedRuleRequired`) blocking VS Code's internal child processes (GPU/renderer/utility) from inheriting elevation — not a VS Code or Electron defect. Switching the EPM rule to `AllowRunElevated` resolved it on the same 1.132.0/1.133.0 builds, so this doesn't reproduce as a general VS Code problem.

## Change summary

VS Code crash-loops at startup (GPU/renderer/network service launch failures, crashpad self-terminate) when launched by a standard (non-admin) Windows user under a specific enterprise Endpoint Privilege Management policy.

## Best solution

Close as not-reproducible against VS Code's own code — the root cause is a third-party EPM elevation-inheritance policy on the reporter's managed devices, already resolved by the reporter adjusting that policy; the speculative Electron 42.8.0 cherry-pick (https://github.com/microsoft/vscode/pull/329594, closed unmerged) is no longer needed since the runtime bump wasn't the actual fix.
