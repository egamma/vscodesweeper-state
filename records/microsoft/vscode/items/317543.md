# Issue #317543 — chat view incorrectly highights non-matched custom prompt name

[https://github.com/microsoft/vscode/issues/317543](https://github.com/microsoft/vscode/issues/317543)

## Summary

Confirmed on current main: a syntactically valid but unresolved prompt command remains a slash-prompt part, and the submitted-request renderer highlights every such part. The accepted Backlog bug should remain open for a bounded rendering fix.

## Change summary

Do not highlight a custom prompt slash command in submitted chat history when its case-sensitive name did not resolve and the prompt was not applied.

## Best solution

Render a submitted slash prompt as decorated only when that prompt was successfully resolved and attached to the request; otherwise preserve it as ordinary request text. Keep case-sensitive matching unchanged, as confirmed by the maintainer.
