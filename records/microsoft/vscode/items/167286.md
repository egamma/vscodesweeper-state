# Issue #167286 — Use quickpick with search and toggles to toggle the setting value per language

[https://github.com/microsoft/vscode/issues/167286](https://github.com/microsoft/vscode/issues/167286)

## Summary

Keep this accepted Backlog request open: current Settings UI still links to individual language overrides rather than showing their boolean values in a searchable, directly editable picker. The request has 21 upvotes, and the reporter clarified that its scope is boolean settings.

## Change summary

Provide a searchable picker that displays and toggles a boolean setting's values across language overrides.

## Best solution

Provide a focused, accessible way to inspect and edit per-language boolean values from the setting's override indicator. Settle how the picker represents inherited defaults and chooses the configuration target before implementation, without expanding this request to non-boolean settings.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/settingsEditorSettingIndicators.ts`, `src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`, `src/vs/workbench/contrib/preferences/browser/preferencesActions.ts`
- **Validation:** Exercise a boolean setting such as editor.formatOnSave with a global true value, an explicit false language override, and a language-default false override. Verify the picker shows the applicable values, filters by language, and edits only the intended language and configuration target; check keyboard and screen-reader operation, cancellation, and unchanged non-boolean override navigation.
- **Behavior:**

  > Users should be able to inspect a boolean setting's per-language values and change them from a searchable picker associated with its override indicator, without navigating into each language separately. The reporter explicitly scoped this request to booleans. Acceptance should cover explicit overrides and language-specific defaults, discoverable language search, and keyboard-accessible editing. The selected persistence and configuration-target semantics must be visible and predictable.
- **Trace:**

  > SettingsTreeIndicatorsLabel.updateScopeOverrides in src/vs/workbench/contrib/preferences/browser/settingsEditorSettingIndicators.ts builds scope links and default-language links, not editable values. SettingsEditor2 in src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts handles those links by applying language and setting filters; updateChangedSetting separately constructs language override identifiers for writes. ConfigureLanguageBasedSettingsAction in src/vs/workbench/contrib/preferences/browser/preferencesActions.ts provides an existing language picker, but it only navigates to language-specific settings. Source inspection establishes the interaction gap, not a runtime defect. Preserve non-boolean navigation, configuration precedence, and managed/read-only restrictions. The remaining uncertainty concerns what a picker toggle means for inherited defaults and which configuration target it edits; the thread at https://github.com/microsoft/vscode/issues/167286 does not settle those contracts.
- **Open decisions:**
  - Should the picker show one effective value per language for the currently selected configuration target, or separate editable entries for overrides at different targets?
  - For a language-specific default, should toggling create an explicit override only, and should users also have a distinct action to return to the inherited value?
