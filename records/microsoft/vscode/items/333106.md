# Issue #333106 — vscode always uses Windows version of mcp.json even when connected to WSL

[https://github.com/microsoft/vscode/issues/333106](https://github.com/microsoft/vscode/issues/333106)

## Summary

VS Code already separates local vs. remote MCP user configuration the same way it does for user settings — there's a dedicated 'MCP: Open Remote User Configuration' command that opens/creates the mcp.json on the WSL side, shown only when connected to a remote. Workspace-level .vscode/mcp.json already resolves against the remote filesystem naturally.

## Change summary

Requests that VS Code load mcp.json from the WSL (remote) side instead of always using the Windows (local) user mcp.json when connected to WSL.

## Best solution

Point the reporter to the existing 'MCP: Open Remote User Configuration' command (workbench.mcp.openRemoteUserMcpJson), which creates/opens a separate mcp.json on the remote (WSL) machine, mirroring the long-standing local/remote split used for user settings.

## Evidence

- **remote user mcp command:** src/vs/workbench/contrib/mcp/browser/mcpCommands.ts defines OpenRemoteUserMcpResourceCommand (id workbench.mcp.openRemoteUserMcpJson, title 'Open Remote User Configuration'), gated on RemoteNameContext.notEqualsTo(''), which resolves `remoteUserDataProfileService.getRemoteProfile(...).mcpResource` — a distinct mcp.json living on the remote (WSL) side.
- **command registration:** src/vs/workbench/contrib/mcp/browser/mcp.contribution.ts registers OpenRemoteUserMcpResourceCommand alongside OpenUserMcpResourceCommand, and mcpMigration.ts already picks the remote vs local command id based on `isRemote`.
- **workspace config:** .vscode/mcp.json (workspace-level) is resolved through the normal workspace configuration/filesystem path, which is already remote-aware when the workspace folder is opened in WSL — it isn't tied to the Windows side.
