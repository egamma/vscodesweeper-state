# Issue #333106 — vscode always uses Windows version of mcp.json even when connected to WSL

[https://github.com/microsoft/vscode/issues/333106](https://github.com/microsoft/vscode/issues/333106)

## Summary

VS Code already ships a separate, remote-side MCP configuration for exactly this scenario — the reporter just needs to use it instead of the local/Windows one.

## Change summary

Reporter wants VS Code, when connected to WSL, to load a WSL-side mcp.json instead of (or maintain separately from) the Windows-side one.

## Best solution

Point the reporter at the `MCP: Open Remote User Configuration` command (`OpenRemoteUserMcpResourceCommand`, id `McpCommandIds.OpenRemoteUserMcp`), which opens a distinct mcp.json stored on the remote (WSL) profile via `IRemoteUserDataProfilesService.getRemoteProfile().mcpResource` — separate from the local `MCP: Open User Configuration` file. Servers defined there run in the WSL environment, so stdio servers that only work on Linux can be defined there instead of duplicated in the Windows file.
