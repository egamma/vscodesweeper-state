# Issue #346743 — Agent Host: parallel background subagents block indefinitely on unresolved shell approvals; parent turn cannot time out or cancel them

[https://github.com/microsoft/vscode/issues/346743](https://github.com/microsoft/vscode/issues/346743)

## Summary

Keep open: the discussion contains independent confirmation of subagents blocked on inaccessible shell approvals, and current source leaves interactive approvals pending without a deadline. The related approval-visibility issue overlaps, but does not fully cover this report's timeout and individual-subagent cancellation requirements.

## Change summary

Make parallel subagent approval waits visible and recoverable without cancelling the entire parent turn.

## Best solution

Ensure the parent chat exposes actionable child approvals and accurately distinguishes waiting from execution. Decide approval-expiry semantics and coordinate individual-subagent cancellation with the Copilot runtime, preserving manual authorization.

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/node/agentSideEffects.ts`, `src/vs/platform/agentHost/common/pendingRequestRegistry.ts`, `src/vs/platform/agentHost/node/copilot/copilotBuiltinToolAllowlist.ts`
- **Validation:** Reproduce with four background children in a manual-mode Copilot Agent Host session, leaving two shell approvals unanswered. Verify both approvals are discoverable and actionable from the parent, blocked children display waiting status, resolving one request affects only its child, and individual cancellation leaves siblings and the parent usable. Validate any chosen expiry policy with controlled time and ensure expired or cancelled requests never execute commands or create reusable grants.
- **Behavior:**

  > Parallel background subagents must not appear to be executing when they are awaiting user approval. Their pending approvals must be discoverable and actionable from the parent chat without inspecting logs. A user must be able to recover an individual blocked child without abandoning unrelated results or cancelling the entire parent turn. Approval expiry, if adopted, must produce an explicit non-approval outcome and never authorize execution.
- **Trace:**

  > CopilotAgentSession._handlePermissionRequest registers a PendingRequestRegistry promise, publishes pending_confirmation with the tracked parentToolCallId, and awaits an external response without a deadline. AgentSideEffects routes that signal to the child chat; source inspection did not establish where parent presentation loses the actionable request. CopilotAgentSession.abort ends all active children, while stopBackgroundWork handles shell entries rather than arbitrary subagents. The runtime built-in allowlist exposes background agent dispatch and observation but no individual-agent stop tool. Independent shell-approval confirmation is recorded at https://github.com/microsoft/vscode/issues/346035#issuecomment-6688205955; coordinate the visibility investigation there without assuming it owns expiry and cancellation. Preserve manual approvals, managed denials, existing shell-stop behavior, and sibling task independence; command read-only classification is an optional separate concern.
- **Open decisions:**
  - Should interactive subagent approvals expire automatically, and if so after what interval and with what user-visible outcome?
  - Should individual-subagent cancellation be available to the user only, or also to the parent agent through a runtime tool?
