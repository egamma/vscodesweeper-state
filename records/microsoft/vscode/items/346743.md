# Issue #346743 — Agent Host: parallel background subagents block indefinitely on unresolved shell approvals; parent turn cannot time out or cancel them

[https://github.com/microsoft/vscode/issues/346743](https://github.com/microsoft/vscode/issues/346743)

## Summary

Keep open: a November 26 confirmation reports missing shell approvals and blocked background work on Windows after the earlier approval-routing fix. The report supplies enough detail to investigate; timeout and individual cancellation semantics still need a maintainer decision.

## Change summary

Background subagents awaiting hidden shell approvals remain running indefinitely and cannot be cancelled individually by the parent.

## Best solution

Ensure every pending subagent approval remains visible and actionable through the Copilot Agent Host and parent chat. Diagnose the remaining delivery failure, then settle timeout and individual cancellation behavior without weakening manual approval requirements.

- **Validation:** Reproduce in manual permission mode with one background subagent issuing the reported PowerShell command, then with multiple parallel subagents. Verify every approval appears, Allow/Skip settles the corresponding call, and unrelated work continues. Extend the Copilot session and side-effects tests for the diagnosed event ordering; validate timeout and individual cancellation against the maintainer-approved contract.
- **Behavior:**

  > A background subagent requiring shell approval must expose an actionable approval and visibly indicate that it is waiting for input. This must work for single, parallel, and nested subagents, including commands with parser warnings. Allow or Skip must settle the matching request without affecting unrelated subagents. Timeout and individual cancellation behavior must be agreed before those capabilities are implemented.
- **Trace:**

  > CopilotAgentSession records permission-event agent IDs and uses them to recover parentToolCallId when a permission precedes tool start; the ordering is covered by copilotAgentSession.test.ts. AgentSideEffects routes pending_confirmation and publishes confirmation state, creating a missing tool row when needed. https://github.com/microsoft/vscode/pull/347513 fixed that earlier ordering case, but https://github.com/microsoft/vscode/issues/346743#issuecomment-7200249724 confirms a later single-subagent failure with a parser warning. The unresolved boundary is whether the permission loses child attribution, fails to reach protocol state, or disappears during frontend approval discovery. Trace that boundary before assigning a root cause; preserve manual approvals, explicit denials, and existing working confirmation behavior. https://github.com/microsoft/vscode/issues/350158 supplies additional nested and single-subagent evidence.
- **Open decisions:**
  - Should interactive subagent approvals expire automatically, and if so after what interval and with what visible denial or partial-result behavior?
  - Should individual subagent cancellation be available to the user, the parent agent, or both, and should it cancel that subagent's descendants?
