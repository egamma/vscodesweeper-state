## Evidence

- **Confirmed recurring failures:** The complete report contains symbolicated SIGABRT stacks in uv__epoll_ctl_flush and uv__io_poll. The reporter confirmed continued crashes through September at https://github.com/microsoft/vscode/issues/286663#issuecomment-5692680111; another user confirmed recurring failures and loss of execution state at https://github.com/microsoft/vscode/issues/286663#issuecomment-4917840054.
- **Earlier resolution claim withdrawn:** The apparent improvement after upgrading to 1.109 was explicitly withdrawn at https://github.com/microsoft/vscode/issues/286663#issuecomment-3888228094. UV_USE_IO_URING=0 and changing from Oracle UEK to RHCK did not reliably prevent crashes, so neither is established resolution evidence.
- **Open implementation candidate:** https://github.com/microsoft/vscode-python/pull/26174 is currently OPEN with mergedAt null and explicitly references this report. Its production diff removes fs.close(fd) from the socket close handler in src/client/common/pipes/namedPipes.ts: net.Socket already owns and closes the descriptor, and the redundant close can affect another resource after descriptor reuse. This is an extension-side ownership defect, not proof of a VS Code core or libuv defect.
- **Positive but incomplete patch confirmation:** The PR author reports two crash-free days, and another affected user reports no crashes after applying the patch at https://github.com/microsoft/vscode-python/pull/26174#issuecomment-5942877581. The same user endorsed the patch in this issue at https://github.com/microsoft/vscode/issues/286663#issuecomment-5942887826. No corresponding confirmation from the original reporter is present.
- **Existing PR verification:** The maintainer-side verification record at https://github.com/microsoft/vscode-python/pull/26174#issuecomment-6044915310 reports passing real-FIFO descriptor-reuse regressions and existing reader-consumer tests. These are recorded results, not tests executed during this read-only review.
- **Current checkout boundary:** src/vs/server/node/extensionHostConnection.ts, ExtensionHostConnection.start, launches bootstrap-fork with --type=extensionHost and records process exit code and signal. This matches the reported crashing process but does not establish the native abort's root cause. Available git history contains no commit explicitly referencing this issue; no completed fix is established.

A search for uv__epoll_ctl_flush in microsoft/vscode returned this report alone; no older, verified canonical with the same observable symptom was established.
