# Issue #346884 — Agents Window: Add a split button for review-comment submission modes

[https://github.com/microsoft/vscode/issues/346884](https://github.com/microsoft/vscode/issues/346884)

## Summary

Keep open: the comments Submit control still lacks explicit delivery modes. The composer picker provides a reusable pattern, but does not satisfy this request.

## Change summary

Offer queue, steer, and stop-and-send modes when submitting review comments, with non-disruptive queueing as the default.

## Best solution

Provide explicit delivery choices on the comments Submit control, preserving the current request when queueing, including while it awaits input. Keep feedback contents and target identity consistent across modes, acknowledge acceptance promptly, and handle child-chat routing separately.

## Evidence

- **Existing comments action:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackEditorActions.ts:76-105 registers a single Submit Feedback action and calls submitFeedback(sessionResource), without a delivery-mode choice.
- **Submission contract:** src/vs/workbench/contrib/sessions/browser/agentFeedback.ts:91-107 exposes query, selected feedback, target chat, background submission, and acceptance options, but no queue, steer, or interruption mode. AgentFeedbackService._sendActOnFeedbackRequest in src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts:835-860 passes only onRequestAccepted to widget.acceptInput.
- **Non-disruptive queueing gap:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:4041-4060 cancels a request awaiting input when there are no pending requests, before applying queue semantics. The current feedback submission path therefore does not guarantee the requested uninterrupted Add to Queue behavior.
- **Existing capability is partial:** src/vs/workbench/contrib/chat/browser/widget/input/chatQueuePickerActionItem.ts implements Add to Queue, Steer with Message, and Stop and Send for composer input. The setting chat.requestQueuing.defaultAction controls the composer queue button; neither exposes those choices on the comments Submit action.
- **Acceptance already supported:** AgentFeedbackService._sendActOnFeedbackRequest marks feedback submitted and resolves success from onRequestAccepted rather than waiting for queued execution. This existing behavior should be preserved across any new modes.
- **Related requests are distinct:** Read https://github.com/microsoft/vscode/issues/342819, which requests selection-bound feedback staging in the regular editor, and https://github.com/microsoft/vscode/issues/346885, which reports child-chat targeting and navigation-dependent submission. Neither owns the explicit delivery-mode picker requested here.
