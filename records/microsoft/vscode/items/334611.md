# Issue #334611 — sticky request overlaps with the editable input that has the same content

[https://github.com/microsoft/vscode/issues/334611](https://github.com/microsoft/vscode/issues/334611)

## Summary

Real, reproducible-in-source UI overlap bug in the brand-new prompt-timeline sticky header, filed the same day the feature landed (referencing #334481, no fix on main yet) — team-authored, so this stays open rather than being closed on judgment alone.

## Change summary

The sticky pinned-request header can visually overlap the same request's inline edit box when a user double-clicks to edit a scrolled-past request.

## Best solution

In PromptTimelineWidgetContrib._createStickyHeader (src/vs/workbench/contrib/chat/browser/promptTimeline/promptTimelineWidgetContrib.ts), also gate sticky.setVisible on whether the pinned/active request is the one currently being edited (viewModel.editing / ChatContextKeys.currentlyEditing), so the header hides while its own request is in edit mode.
