# Issue #347630 — [Live Share] Guest window closes immediately on join due to unregistered vsliveshare.join.reload.workspaceId

[https://github.com/microsoft/vscode/issues/347630](https://github.com/microsoft/vscode/issues/347630)

## Summary

The evidence points to Live Share's extension-owned join and cleanup logic, with an independent confirmation that registering its setting resolves the failure. Propose closing as caused by an extension maintained outside the VS Code team.

## Change summary

Prevent Live Share guests from immediately losing their collaboration workspace when the extension cannot read its join-session setting.

## Best solution

Live Share should preserve its join-session state under VS Code's configuration rules and avoid treating an unavailable setting as an aborted join. Track that correction in the Live Share project rather than weakening core workspace-trust filtering.

## Evidence

- **Extension-local failure and workaround:** https://github.com/microsoft/vscode/issues/347630 identifies ms-vsliveshare.vsliveshare 1.1.122 as executing workbench.action.closeFolder when its session setting is unavailable. The reporter says adding the setting to the extension manifest resolves the failure; Nishikiyama independently confirms both the failure and workaround.
- **Configuration boundary on current main:** src/vs/platform/configuration/common/configurationModels.ts, ConfigurationModelParser.shouldInclude, rejects unregistered settings when skipUnregistered is enabled. src/vs/workbench/services/configuration/browser/configuration.ts enables that option for untrusted workspace and folder configuration. This supports a configuration interaction but not the report's blanket assertion that every unregistered setting is always filtered.
- **Extension API read path:** src/vs/workbench/api/common/extHostConfiguration.ts, getConfiguration().get(), reads the supplied configuration model and returns the default for an undefined value; it does not itself impose a blanket registration requirement.
- **Owning project:** https://github.com/microsoft/live-share identifies itself as the Visual Studio Live Share feedback project. Its https://github.com/microsoft/live-share/blob/main/CONTRIBUTING.md directs Live Share problem reports to that project's issue tracker; Live Share is not one of the VS Code-team-owned extensions covered by the transfer roster.
- **Related report is not a verified duplicate:** https://github.com/microsoft/vscode/issues/347801 describes version-dependent join failures with a closeRequested ReferenceError in Live Share's WebSocket handling. That is insufficient to establish the same root cause as this report's missing workspace setting and explicit closeFolder invocation.
