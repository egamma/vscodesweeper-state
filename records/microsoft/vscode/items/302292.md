# Issue #302292 — Allow custom-guardrails for autopilot's report `task_complete`

[https://github.com/microsoft/vscode/issues/302292](https://github.com/microsoft/vscode/issues/302292)

## Summary

Team-authored feature request for user-configurable completion guardrails on the `task_complete` tool. The existing Stop hook infrastructure (`StopHookInput`/`StopHookOutput` in the chat hook service) partially addresses the mechanism — it can block the agent from stopping and instruct it to continue — but the issue's central ask (a user-facing way to define custom 'done' criteria like linting/tests/builds that the agent must verify before calling `task_complete`) remains unimplemented as a first-class feature.

## Change summary

Allow users to define custom completion guardrails (e.g. linting, tests, builds) that the agent must verify before calling `task_complete`.

## Best solution

Build on the existing Stop hook infrastructure (`extensions/copilot/src/platform/chat/common/chatHookService.ts`) and the `task_complete` tool (`src/vs/workbench/contrib/chat/common/tools/builtinTools/taskCompleteTool.ts`). The feature likely involves: (1) a user-facing setting or `.github/copilot-hooks.yml` entry to declare completion criteria, (2) appending those criteria to the `task_complete` model description or the continuation prompt, and (3) optionally running deterministic checks after the agent claims completion. The work sits in the chat/agent-mode area.
