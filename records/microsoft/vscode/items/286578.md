# Issue #286578 — Defer InlineCompletionsModel to after the editor has opened

[https://github.com/microsoft/vscode/issues/286578](https://github.com/microsoft/vscode/issues/286578)

## Summary

The requested deferral has not been implemented — InlineCompletionsModel is still eagerly created via derivedDisposable the moment a text model is available, with no post-open scheduling. Keeping open as a valid perf debt item filed by a team contributor.

## Change summary

Defer InlineCompletionsModel initialization until after the editor has fully opened to reduce editor-switch latency.

## Best solution

Add a deferral gate (e.g. an idle callback or a post-layout signal) in the InlineCompletionsController so the InlineCompletionsModel is not instantiated synchronously during the editor-open microtask chain. The change is localized to `src/vs/editor/contrib/inlineCompletions/browser/controller/inlineCompletionsController.ts` around the `derivedDisposable` at line 99.
