# Issue #286578 — Defer InlineCompletionsModel to after the editor has opened

[https://github.com/microsoft/vscode/issues/286578](https://github.com/microsoft/vscode/issues/286578)

## Summary

Keep open: current source still constructs InlineCompletionsModel synchronously when an initialized editor controller changes text models. The existing delayed contribution registration does not defer this per-model work; the reported 7 ms cost has not been remeasured.

## Change summary

Move inline-completion model initialization out of the critical path for opening and switching editors.

## Best solution

Defer per-text-model inline-completion initialization until editor presentation is no longer blocked, while preserving completion triggers and cross-file next-edit behavior. Establish the scheduling and lifecycle boundary with a current performance trace before implementing the optimization.
