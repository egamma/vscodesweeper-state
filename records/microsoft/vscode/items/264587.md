# Issue #264587 — report issue window not re-focused on command

[https://github.com/microsoft/vscode/issues/264587](https://github.com/microsoft/vscode/issues/264587)

## Summary

Still present on main: the legacy issue reporter aux-window path calls `window.focus()` in `hasToReload()` but this does not reliably bring the auxiliary window to the foreground on desktop OSes, so the command appears to do nothing. The newer wizard path (editor-based, Singleton) should handle re-reveal correctly, but the legacy path remains the default.

## Change summary

Running the 'Report Issue' command a second time does not re-surface the already-open issue reporter auxiliary window when it is behind the main VS Code window.

## Best solution

In `IssueFormService.hasToReload()` (src/vs/workbench/contrib/issue/browser/issueFormService.ts), replace the bare `this.issueReporterWindow.focus()` with a mechanism that reliably brings the auxiliary window to the foreground — e.g. using `IAuxiliaryWindowService` or the native host service to raise/activate the window, or closing and reopening the reporter. Alternatively, since the wizard path (editor-based, Singleton input) already handles re-reveal, the fix scope may narrow once the wizard becomes the default.
