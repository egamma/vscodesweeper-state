# Issue #327114 — Error with trying to configure launch settings when a setting with `@hasPolicy` exists

[https://github.com/microsoft/vscode/issues/327114](https://github.com/microsoft/vscode/issues/327114)

## Summary

Verified duplicate of the older open configuration-writing regression at https://github.com/microsoft/vscode/issues/282418. Both reports reach the same standalone `launch` write path and fail with the identical policy error.

## Change summary

Configuring a dynamically provided launch configuration fails whenever any setting is managed by system policy, leaving `launch.json` incomplete.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/282418 and correct policy validation for whole-file standalone configuration writes so an unrelated managed setting does not block updating `launch.json`.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/282418 is open, predates this report, and reports the identical `Unable to write undefined because it is configured in system policy` failure while writing the standalone `launch` configuration.
- **shared source path:** The dynamic configuration gear handler in src/vs/workbench/contrib/debug/browser/debugConfigurationManager.ts calls `Launch.writeConfiguration`, which invokes `configurationService.updateValue('launch', ..., ConfigurationTarget.WORKSPACE_FOLDER)`.
- **source-confirmed root cause:** src/vs/workbench/services/configuration/common/configurationEditing.ts maps a whole standalone `launch` write to an operation whose `key` is undefined, then `validate` calls `configurationService.inspect(operation.key)`. The resulting aggregate policy value makes any managed setting trigger ERROR_POLICY_CONFIGURATION and produces the reported `undefined` message.
- **unique reproduction detail:** This report confirms that the same defect affects VS Code's Configure Launch Configuration gear action for dynamically supplied configurations, including C# Dev Kit configurations.
