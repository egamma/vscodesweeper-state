# Issue #336063 — Typing in Markdown Preview Find brings another VS Code window to the front

[https://github.com/microsoft/vscode/issues/336063](https://github.com/microsoft/vscode/issues/336063)

## Summary

Only has the auto `triage-needed` label; the reporter gives a precise, plausible repro (a webview find widget in one window stealing focus to an unrelated auxiliary window) that lines up with a second report on the same theme, but I could not pin the exact focus-stealing code path via source inspection alone, so this needs area-owner routing and manual verification rather than a close.

## Change summary

When a tab has been moved to a separate ('auxiliary') window, typing in the Markdown Preview's Find widget in the main window causes the unrelated auxiliary window to steal focus and come to the front after ~2 seconds, interrupting the search.

## Best solution

Route to the webview/multi-window focus owners: the Markdown Preview's Ctrl+F find is implemented as an in-webview JS search (src/vs/workbench/contrib/webview/browser/webviewElement.ts `find`/`updateFind`), so the likely culprit is an auxiliary-window/webview focus-routing path that activates the wrong BrowserWindow; should be investigated together with the related report #334860 which also implicates find-in-webview + auxiliary window interaction.
