# Issue #339064 — Selecting Copilot Harness removes Local harness permanently

[https://github.com/microsoft/vscode/issues/339064](https://github.com/microsoft/vscode/issues/339064)

## Summary

Real, actively-investigated bug in the new experimental Agent Host harness picker: selecting the Copilot harness makes Local disappear from the picker even though `chat.editor.localAgent.enabled` defaults to true, and two commenters confirm explicitly setting that setting (plus the Copilot-preference settings) restores it — a maintainer (lramos15) is already engaged asking for the effective setting value, so this is mid-investigation, not a close candidate.

## Change summary

After picking the Copilot harness in the chat session-type picker, the Local harness option disappears permanently from the picker and cannot be restored via settings or restart.

## Best solution

Once the maintainer confirms the reporter's effective `chat.editor.localAgent.enabled`/`chat.defaultToCopilotHarness`/`chat.editor.preferCopilotHarness` values (likely flipped by a startup experiment arm per the `experiment: { mode: 'startup' }` tags on these settings in src/vs/platform/agentHost/common/agentHostEnablementService.ts), either fix the picker visibility logic (isEditorLocalAgentEnabled / isNewChatSessionTypeUsable in src/vs/workbench/contrib/chat/common/constants.ts) so it doesn't desync from the documented default, or clarify why the experiment cohort disables Local without surfacing that to the user.
