## Change summary

## Evidence

- **verified older canonical:** https://github.com/microsoft/vscode/issues/234488 is OPEN and was created on 2024-11-23, before this report. Its body explicitly names git.stage and says opening a tracked file makes the command run only on that file, ignoring the other highlighted files; context-menu and inline actions work. This is the same reporter-observable symptom, satisfying the stronger duplicate bar for a re-reviewed item.
- **current source explains the limitation:** extensions/git/src/commands.ts:1514-1530, CommandCenter.stage, falls back to getSCMResource() when resource arguments are absent and replaces the input with a single resource. getSCMResource() at lines 5702-5738 resolves the active editor URI rather than SCM multi-selection. src/vs/workbench/contrib/scm/browser/scmViewPane.ts:467-485, RepositoryPaneActionRunner.runAction, supplies selected resources to menu actions, explaining the difference from keyboard invocation.
- **maintainer explanation and workaround:** https://github.com/microsoft/vscode/issues/207066#issuecomment-2548673782 explains that a git.stage keybinding acts on an opened file because the command lacks access to list selection. https://github.com/microsoft/vscode/issues/234488#issuecomment-2504755681 suggests opening the selected resources' context menu and choosing the action as a workaround; that does not provide the requested direct staging shortcut.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/339786 is OPEN but was created on 2026-10-05, after this report, and requests extension API access to SCM selection. https://github.com/microsoft/vscode/issues/207066 primarily concerns focus loss after staging.
