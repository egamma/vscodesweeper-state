# Issue #251459 — Allow Extensions to Register In-Process MCP Servers via In-Memory Transport

[https://github.com/microsoft/vscode/issues/251459](https://github.com/microsoft/vscode/issues/251459)

## Summary

Valid feature request: the current MCP API only exposes Stdio and HTTP transport types — no in-memory/in-process transport exists on main. The request for extensions to act as MCP servers via an in-memory transport remains unimplemented and is a natural extension of the existing API surface.

## Change summary

Allow VS Code extensions to register an in-process MCP server using an in-memory transport, avoiding the need for external processes or networked endpoints.

## Best solution

Add a new `McpInMemoryServerDefinition` (or equivalent) transport type alongside the existing `McpStdioServerDefinition` and `McpHttpServerDefinition`, wiring it through `McpServerTransportType` in `src/vs/workbench/contrib/mcp/common/mcpTypes.ts` and exposing it in the `vscode.d.ts` API surface. This lets extensions implement MCP servers directly in-process with access to their own auth, workspace state, and lifecycle.
