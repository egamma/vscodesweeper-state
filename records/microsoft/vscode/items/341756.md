# Issue #341756 — Bundled microsoft-authentication logs the full MSAL account JSON — including `aio`, `sid`/`sub` and ID-token claims — on every start

[https://github.com/microsoft/vscode/issues/341756](https://github.com/microsoft/vscode/issues/341756)

## Summary

Thanks for the detailed report. The source matches it: the MSAL logger is created with logLevel Trace and PII logging enabled, so MSAL account details can reach the extension's log file. Because this is a possible credential or account-data exposure, it stays open for a human maintainer to handle.

## Change summary

The bundled microsoft-authentication extension logs full MSAL account objects, including ID-token claims and identifiers, to its on-disk log file.

## Best solution

Stop enabling PII logging and Trace-level MSAL logging unconditionally in the extension. Filter or redact account-dump records such as 'MSAL Account JSON chunk', and log only a correlation id, account count and outcome.
