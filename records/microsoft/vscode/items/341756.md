# Issue #341756 — Bundled microsoft-authentication logs the full MSAL account JSON — including `aio`, `sid`/`sub` and ID-token claims — on every start

[https://github.com/microsoft/vscode/issues/341756](https://github.com/microsoft/vscode/issues/341756)

## Summary

Thanks for the detailed report. The bundled microsoft-authentication extension forwards MSAL log messages to its output channel without checking whether they contain PII, so this looks real. It is security-sensitive (account identifiers and token claims written to disk), so it stays open for a maintainer to handle.

## Change summary

The microsoft-authentication extension writes full MSAL account JSON, including aio, sid/sub and ID-token claims, to its log file on every start.

## Best solution

In extensions/microsoft-authentication, filter or drop MSAL records flagged as PII (or the 'MSAL Account JSON' warnings) before they reach the output channel. Also reconsider piiLoggingEnabled: true in cachedPublicClientApplication.ts.
