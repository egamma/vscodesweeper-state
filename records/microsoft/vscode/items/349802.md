# Issue #349802 — Remote agent host added with a private key file can't reconnect after the SSH connection drops

[https://github.com/microsoft/vscode/issues/349802](https://github.com/microsoft/vscode/issues/349802)

## Summary

The private-key reconnect defect remains in current source: reconnect reconstructs authentication from SSH configuration rather than the explicitly selected key. The SSH-config workaround does not resolve the supported Private Key File workflow.

## Change summary

Reuse the selected non-default private key when reconnecting a remote agent host after its SSH connection drops.

## Best solution

Automatic recovery and explicit Connect should authenticate with the key selected during the original connection, without requiring the user to repeat setup or edit SSH configuration. Preserve existing credential sanitization and SSH-config-based connection behavior.
