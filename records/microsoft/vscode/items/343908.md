# Issue #343908 — Undo after nesting a pinned session brings it back unpinned and in the other session's group

[https://github.com/microsoft/vscode/issues/343908](https://github.com/microsoft/vscode/issues/343908)

## Summary

The Undo path restores a standalone session but not its original list placement: the replacement session lacks the original pin and inherits the destination session's custom group. Current source confirms the reported gap, so this should remain open.

## Change summary

Undoing a session nest should restore the original session's pinned state and custom-group placement despite its replacement session ID.

## Best solution

Make nesting Undo restore the session's pre-move list placement through the Sessions-owned presentation services. Preserve ordinary chat promotion's existing group inheritance and leave the destination session's placement unchanged.
