# Issue #118115 — API: Allow extensions to render a table in a view

[https://github.com/microsoft/vscode/issues/118115](https://github.com/microsoft/vscode/issues/118115)

## Summary

Keep open: native tables exist internally, but extensions still cannot contribute a native table view through the public API. This api-proposal tracking issue is protected from closure and has substantial community demand.

## Change summary

Expose an extension API for native multi-column table views without requiring a custom webview.

## Best solution

API owners should define and finalize an extension-facing table-view contract backed by the existing workbench table infrastructure, including accessible navigation and row actions. Preserve this issue as the proposal tracker; webviews do not resolve the native-control requirement.

- **Reason:** A native table-view API would let extensions provide consistent, accessible interfaces without independently rebuilding workbench controls.

- **Contribution boundary:** src/vs/workbench/api/browser/viewsExtensionPoint.ts:116–131 restricts contributed view types to 'tree' and 'webview'.
