# Issue #254641 — Feature Request: Colored line scopes for *JSX*

[https://github.com/microsoft/vscode/issues/254641](https://github.com/microsoft/vscode/issues/254641)

## Summary

Keep this accepted feature request open: existing bracket guides do not connect JSX opening and closing elements according to their nesting. The older HTML request is related, but does not establish ownership of the same JSX-specific guide behavior required for a duplicate close on this re-review.

## Change summary

Provide bracket-style colored scope guides and corresponding colorization for nested JSX elements.

## Best solution

Extend the editor's structural-guide support to recognize matching JSX elements, including fragments, self-closing elements, and embedded expressions, while preserving existing JavaScript and TypeScript bracket behavior. Coordinate with the HTML tag-colorization request without treating it as a verified duplicate.

## Plan brief

- **Likely files:** `src/vs/editor/common/model/guidesTextModelPart.ts`, `src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/bracketPairsTree.ts`, `extensions/javascript/package.json`, `extensions/javascript/tags-language-configuration.json`, `extensions/typescript-basics/package.json`, `src/vs/editor/test/common/model/bracketPairColorizer/getBracketPairsInRange.test.ts`
- **Validation:** End the plan with a runnable JSX/TSX check: enable editor.guides.bracketPairs and inspect nested elements, fragments, self-closing siblings, and elements containing JavaScript expressions. Verify that guides connect matching element boundaries, nesting colors remain consistent, self-closing elements do not consume a later closing tag, and existing braces, parentheses, comparisons, and generic types retain their behavior. Define automated pairing/guide assertions alongside the existing bracket-pair model tests once the structural representation is chosen.
- **Behavior:**

  > JSX and TSX users want colored scope guides comparable to existing bracket-pair guides, reflecting element nesting rather than each tag's individual angle delimiters. Matching opening and closing elements should delimit the same scope, including fragments; self-closing elements must not create unmatched scopes. Embedded JavaScript expressions must retain their existing bracket guides and colorization. Acceptance includes nested elements, fragments, self-closing siblings, embedded expressions, and unchanged ordinary JavaScript/TypeScript bracket behavior. The later adjacent-closing-bracket color complaint is separate from this feature's acceptance contract.
- **Trace:**

  > GuidesTextModelPart.getLinesBracketGuides in src/vs/editor/common/model/guidesTextModelPart.ts obtains ranges from the text model's bracket-pair tree and assigns guide colors by nesting level. BracketPairsTree in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/bracketPairsTree.ts builds those ranges through its bracket tokenizer/parser. JSX and TSX grammars map tag scopes to jsx-tags through extensions/javascript/package.json and extensions/typescript-basics/package.json; extensions/javascript/tags-language-configuration.json contains literal delimiter configuration, not semantic element pairing. The established gap is element-level scope recognition; the uncertainty starts at how to represent that structure without degrading incremental editing performance or existing bracket matching. https://github.com/microsoft/vscode/issues/137504 supplies related HTML requirements and failed delimiter-based workarounds, but is not a verified same-symptom canonical for this re-review. https://github.com/microsoft/vscode/issues/131003 records the historical distinction between coloring literal angle brackets and matching complete JSX elements. Preserve existing expression and generic-type behavior; do not fold the later adjacent-bracket bug into this feature without a separate diagnosis.
- **Open decisions:**
  - Should JSX element scopes use the existing bracket-pair guide and colorization controls, or should users be able to enable element scopes independently?
  - Which parts of matching JSX elements should receive nesting colors: tag delimiters only, or tag names as well?
