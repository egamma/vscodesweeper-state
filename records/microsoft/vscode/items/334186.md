# Issue #334186 — Send x-opencode-session header on API requests (required by OpenCode Go from 09/05)

[https://github.com/microsoft/vscode/issues/334186](https://github.com/microsoft/vscode/issues/334186)

## Summary

The ask — hardcoding a specific third-party vendor's custom header into Copilot Chat's core request path — is already solvable with the existing, documented `requestHeaders` mechanism for custom-endpoint/BYOK models, so no core change is warranted; a general-purpose knob already covers this rather than special-casing one provider.

## Change summary

OpenCode Go now requires an `x-opencode-session` header on inference requests; requester wants Copilot Chat to send it automatically for their models.

## Best solution

Point users at the existing `requestHeaders` field for custom-endpoint models (extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts, and documented at code.visualstudio.com/docs/agent-customization/language-models#_add-a-custom-endpoint-model) — as several commenters already confirmed works. Vendor-specific auto-session-ID generation, if wanted, belongs in a dedicated OpenCode provider extension (several already exist in the wild), not hardcoded into core's generic chat request pipeline.

- **Reason:** Core already exposes a general `requestHeaders` mechanism for custom endpoints instead of hardcoding any single vendor's header requirement, which matches the value of keeping the base editor/chat pipeline lean and letting configuration/extensions carry vendor-specific needs.

- **Proposed comment:**

  > Thanks for the report, and sorry for the disruption. Copilot Chat doesn't special-case individual model providers' custom headers in its core request path, but the custom-endpoint model config already supports arbitrary `requestHeaders` per model — see https://code.visualstudio.com/docs/agent-customization/language-models#_add-a-custom-endpoint-model. Several users in this thread (see the `requestHeaders: { "x-opencode-session": ... }` example) confirm this unblocks OpenCode Go today. A fully automatic per-conversation session ID would need a dedicated OpenCode provider extension rather than a core change — a few already exist in the community. Closing as working as designed, but happy to reopen if the static-header workaround turns out insufficient.
