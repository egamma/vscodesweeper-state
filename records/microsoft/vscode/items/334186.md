# Issue #334186 — Send x-opencode-session header on API requests (required by OpenCode Go from 09/05)

[https://github.com/microsoft/vscode/issues/334186](https://github.com/microsoft/vscode/issues/334186)

## Summary

This asks Copilot Chat core to hardcode a single third-party inference vendor's custom header requirement; that's not something core should special-case, and the existing per-endpoint `requestHeaders` config already lets users add it themselves.

## Change summary

OpenCode Go's managed-inference API now requires an `x-opencode-session` header on every request; the reporter wants Copilot Chat to send it automatically for custom-endpoint models pointed at that API.

## Best solution

Keep this out of core — the `requestHeaders` option on custom endpoint model configuration (extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts) already lets users set a static `x-opencode-session` value per VS Code's own custom-endpoint docs; a per-conversation-stable ID could be built as a small community extension/wrapper if a static value isn't sufficient.

## Vision fit

- **Fit:** rejected
- **Reason:** Hardcoding a specific commercial vendor's custom header/naming convention into core chat request plumbing conflicts with keeping the product provider-agnostic and pushes vendor-specific business logic into the base editor rather than an extension or user configuration.
- **Evidence:** "The power lives in extensions" and the guardrail that a capability achievable via the existing extension/config API generally belongs there, not in core.
