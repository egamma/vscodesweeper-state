# Issue #334186 — Send x-opencode-session header on API requests (required by OpenCode Go from 09/05)

[https://github.com/microsoft/vscode/issues/334186](https://github.com/microsoft/vscode/issues/334186)

## Summary

Already accepted into the Backlog via the community upvote process (82 upvotes, moved there 2026-09-26), which bars any decline close (`*as-designed`/`*out-of-scope`/`*question`) per the holding-bin rule; staying open for the community/backlog process, same as the prior review.

## Change summary

Requests that VS Code's built-in model-provider request pipeline send a stable per-conversation `x-opencode-session` header on every outbound inference request, as OpenCode Go's gateway now requires it.

## Best solution

The literal ask (hardcoding a competitor-named header) is extension territory — several community extensions (OpenCode for Copilot Chat, opencode-go-copilot-provider, vscode-unify-chat-provider) already do this. The real remaining gap, documented in detail by @BIT-Orange, is that the existing `requestHeaders` custom-endpoint config only supports a static value, not a per-conversation dynamic one; that general capability is tracked by the broader https://github.com/microsoft/vscode/issues/316794 (custom headers / stable session identifiers for BYOK providers), which should absorb the design work if the team decides to build it.

## Vision fit

- **Fit:** rejected
- **Reason:** Hardcoding a specific third-party vendor's custom header name in core directly conflicts with 'simple, uniform UI' and 'the power lives in extensions' — this is squarely extension-candidate territory, as several commenters (e.g. wbsch, diegovilar) independently note.
- **Evidence:** Values: "The power lives in extensions... authors can write powerful extensions." / "Simple, uniform UI and UI interactions."
