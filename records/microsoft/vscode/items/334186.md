# Issue #334186 — Send x-opencode-session header on API requests (required by OpenCode Go from 09/05)

[https://github.com/microsoft/vscode/issues/334186](https://github.com/microsoft/vscode/issues/334186)

## Summary

VS Code core has no built-in 'OpenCode Go' vendor — Copilot Chat's custom/BYOK endpoint provider already supports a per-model `requestHeaders` override, which is exactly what's needed here, and third-party extensions already automate it for OpenCode Go specifically.

## Change summary

Requester wants Copilot Chat's outbound inference requests to always include a vendor-specific `x-opencode-session` header for OpenCode Go routing.

## Best solution

Point users at the existing custom-endpoint `requestHeaders` config (or the community extensions that already wire this up) rather than baking a single third-party vendor's custom header into core chat request plumbing.

## Vision fit

- **Fit:** rejected
- **Reason:** Hard-coding a specific third-party inference vendor's proprietary routing header into core chat requests runs against keeping the editor lean and vendor-neutral; the existing generic `requestHeaders` extensibility point is the right mechanism, and the specific integration belongs in an extension.
- **Evidence:** Values: "The power lives in extensions" and "Out of the box, VS Code is a text editor: lightweight and fast."

- **Proposed comment:**

  > Thanks for the report and for the detailed context. VS Code doesn't ship a built-in OpenCode Go provider, so Copilot Chat requests to it go through the generic custom/BYOK endpoint path, which already supports a per-model `requestHeaders` override — you (or your users) can set `x-opencode-session` there today, as described at https://code.visualstudio.com/docs/agent-customization/language-models#_add-a-custom-endpoint-model. A few community extensions (e.g. https://marketplace.visualstudio.com/items?itemName=OnesoftQwQ.opencode-go-copilot-provider) already automate this for OpenCode Go specifically. Baking one vendor's proprietary routing header into core chat requests isn't something we'd want to hardcode; this is best served by the existing extensibility point or a dedicated extension.

## Evidence

- **existing capability:** extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts and customOAIProvider.ts already read a `requestHeaders` field from IChatModelInformation and apply it to every outbound request (see also byokProvider.ts:71,181-182), which is precisely the per-model static header mechanism this issue asks for.
- **documented workaround:** Comment https://github.com/microsoft/vscode/issues/334186#issuecomment (tianrodez, 2026-09-07) shows the official docs path: set `requestHeaders: { "x-opencode-session": "..." }` under a custom endpoint model in chatLanguageModels.json.
- **no core OpenCode Go vendor:** There is no OpenCode/OpenCode Go-specific provider anywhere under extensions/copilot/src/extension/byok — access is only via the generic custom-endpoint/OpenAI-compatible path or third-party extensions (e.g. OnesoftQwQ/opencode-go-copilot, SmallMain/vscode-unify-chat-provider), confirming this is an integration a maintainer would route to extensions, not core.
- **commenter confirmation:** https://github.com/microsoft/vscode/issues/334186#issuecomment (diegovilar, 2026-09-21) states VS Code doesn't ship an OpenCode Go provider and that extensions have already 'fixed' this.
