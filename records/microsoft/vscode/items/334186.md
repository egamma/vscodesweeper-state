# Issue #334186 — Send x-opencode-session header on API requests (required by OpenCode Go from 09/05)

[https://github.com/microsoft/vscode/issues/334186](https://github.com/microsoft/vscode/issues/334186)

## Summary

This asks VS Code core to hardcode a proprietary header for one third-party inference vendor's routing needs, but the custom-endpoint model config already supports arbitrary `requestHeaders` (confirmed in extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts and documented publicly), and multiple commenters already show this exact workaround working — so the existing capability covers the request and it isn't something core should special-case.

## Change summary

Requester (the OpenCode Go inference provider) wants Copilot Chat to always send a vendor-specific `x-opencode-session` header on outbound inference requests routed through their API.

## Best solution

Point users at the existing `requestHeaders` field in custom endpoint model configuration (chatLanguageModels.json), which already lets any user attach `x-opencode-session` (or any other header) per model — no core change needed; a generic per-conversation-ID header mechanism, if ever pursued, would need to be vendor-agnostic and is a separate, much narrower ask than this ticket.

## Vision fit

- **Fit:** rejected
- **Reason:** Hardcoding one external vendor's custom header into core outbound requests conflicts with keeping VS Code a lean, uniform editor where vendor-specific behavior is handled via configuration or extensions, not baked into the base product.
- **Evidence:** Values: "Out of the box, VS Code is a text editor: lightweight and fast" and "Simple, uniform UI and UI interactions" — baking in a single named vendor's proprietary header is the opposite of a uniform, vendor-neutral interface.
