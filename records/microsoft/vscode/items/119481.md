# Issue #119481 — Data breakpoints: support modifying current breakpoint access type

[https://github.com/microsoft/vscode/issues/119481](https://github.com/microsoft/vscode/issues/119481)

## Summary

Keep open: current source still lacks an access-type editor for existing variable data breakpoints. Creation-time access selection and the newer address-editing workflow do not cover this request, and no open canonical was identified.

## Change summary

Allow users to change an existing data breakpoint's access type using the debug adapter's advertised accessTypes.

## Best solution

Expose supported access types when editing an existing data breakpoint in the Breakpoints view, preserving its conditions and other state while updating the adapter and persisted configuration. Agree on the editing interaction before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/breakpointsView.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/debug/common/debugModel.ts`, `src/vs/workbench/contrib/debug/browser/debugService.ts`, `src/vs/workbench/contrib/debug/test/browser/breakpoints.test.ts`
- **Validation:** Extend the breakpoint tests to verify changing accessType preserves the breakpoint's identity, conditions, enabled state, and serialized DAP/storage values. Exercise the agreed UI against an adapter advertising read, write, and readWrite; verify unsupported choices are unavailable and cancellation leaves the breakpoint unchanged.
- **Behavior:**

  > Users can change an existing variable data breakpoint between the access types advertised by its adapter without deleting and recreating it manually. The displayed access type, adapter request, and persisted breakpoint agree after the change. Conditions, hit conditions, enabled state, and breakpoint identity remain intact. Unsupported access types cannot be selected, and cancelling editing makes no change.
- **Trace:**

  > DataBreakpoint in src/vs/workbench/contrib/debug/common/debugModel.ts retains accessTypes and serializes accessType through toDAP() and toJSON(), but accessType is readonly and updateDataBreakpoint() only updates conditions. The matching IDebugService contract in common/debug.ts and implementation in browser/debugService.ts have the same restricted update shape; the service already stores and sends updated data breakpoints. browser/breakpointsView.ts exposes condition/hit-count editors, while its separate MemoryBreakpointAction offers access selection only during address-based creation/replacement. Creation actions in debugCommands.ts, variablesView.ts, and watchExpressionsView.ts already respect advertised access types and are not the missing capability. Related discussion at https://github.com/microsoft/vscode/issues/113922 supports integrated access-type UI, but does not settle the interaction for editing existing breakpoints. Keep adapter capabilities, creation semantics, and unrelated breakpoint kinds unchanged.
- **Open decisions:**
  - Should existing data breakpoints expose supported access types directly as checked context-menu choices, or through a dedicated Edit Access Type command and picker?

## Evidence

- **Current model and update contract:** src/vs/workbench/contrib/debug/common/debugModel.ts:1221–1280 stores DataBreakpoint.accessTypes but declares accessType readonly; toDAP() and toJSON() serialize the creation-time value. DebugModel.updateDataBreakpoint() at line 2055 and the service contract in common/debug.ts:1263 accept only condition and hitCondition.
- **Existing editing capabilities do not cover the request:** src/vs/workbench/contrib/debug/browser/breakpointsView.ts registers debug.editBreakpoint and hit-count editing, but neither edits accessType. workbench.debug.viewlet.action.editDataBreakpointOnAddress invokes MemoryBreakpointAction, which offers an access-type picker but is restricted to address-based breakpoints and removes/recreates the breakpoint; it does not provide editing for existing variable data breakpoints.
- **Creation support is distinct:** src/vs/workbench/contrib/debug/browser/debugCommands.ts creates data breakpoints with read, write, or readWrite. variablesView.ts and watchExpressionsView.ts derive creation actions from the adapter's accessTypes; this does not modify an existing breakpoint.
