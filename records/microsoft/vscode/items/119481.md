# Issue #119481 — Data breakpoints: support modifying current breakpoint access type

[https://github.com/microsoft/vscode/issues/119481](https://github.com/microsoft/vscode/issues/119481)

## Summary

A real gap remains on current main: VS Code stores and displays a data breakpoint's access type but offers no UI or model API to change it after creation. The request has no current community traction, so it should remain open under discussion rather than enter an implementation lane.

## Change summary

Allow users to change an existing data breakpoint between the access types supported by its debug adapter.

## Best solution

Provide an edit action in the Breakpoints view that offers the breakpoint's stored `accessTypes`, updates `accessType`, persists the selection, and resends data breakpoints to the active debug session. A maintainer should first settle whether this is a separate quick-pick action or part of the existing breakpoint editing experience.

## Evidence

- **current source gap:** `src/vs/workbench/contrib/debug/browser/breakpointsView.ts` renders `DataBreakpoint.accessType` and lets users edit condition and hit count, but registers no action for changing the access type of an existing variable data breakpoint.
- **model boundary:** `DataBreakpoint.accessType` is readonly in `src/vs/workbench/contrib/debug/common/debugModel.ts`, while `updateDataBreakpoint` in `debug.ts`, `debugModel.ts`, and `debugService.ts` accepts only `condition` and `hitCondition`; the current update path therefore cannot apply the requested change.
- **deliberate deferral:** In https://github.com/microsoft/vscode/pull/117835#issuecomment-800566440, the maintainer explicitly asked to split existing-breakpoint access-type updates from the initial access-type support and reconsider them after more user feedback. The merged PR https://github.com/microsoft/vscode/pull/117835 consequently covers creation only.
- **related issue:** The broader https://github.com/microsoft/vscode/issues/83649 is closed and directed missing functionality into follow-up issues, so it cannot serve as an open duplicate canonical. Searches found no other open issue owning this specific request.
- **existing capability check:** The test plan at https://github.com/microsoft/vscode/issues/119197 verifies selecting access types while creating data breakpoints and enabling, disabling, or removing them, but does not include changing an existing breakpoint's access type.
