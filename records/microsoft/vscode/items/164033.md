# Issue #164033 — Show file size and date modified in file explorer.

[https://github.com/microsoft/vscode/issues/164033](https://github.com/microsoft/vscode/issues/164033)

## Summary

This accepted Backlog request remains necessary: current VS Code can sort Explorer entries by modification time but does not display file size or modification date visually or to screen readers. With 169 upvotes and no older open issue covering the same observable behavior, it should remain open.

## Change summary

Show file size and last-modified date alongside Explorer entries and include that metadata in their accessible labels.

## Best solution

Add configurable Explorer metadata display for file size and modification date, with equivalent information in each item's screen-reader label and without imposing metadata-resolution cost when the feature is disabled. Preserve the existing modified-time sorting behavior and compact tree interactions.

- **Fit:** aligned
- **Reason:** Making useful file metadata available visually and to screen readers advances both accessibility and the workbench's core file-navigation experience.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/common/explorerModel.ts`, `src/vs/workbench/contrib/files/browser/explorerService.ts`, `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `src/vs/workbench/contrib/files/browser/files.contribution.ts`, `src/vs/workbench/contrib/files/browser/media/explorerviewlet.css`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`
- **Validation:** Extend the Files - ExplorerView tests and run `scripts/test.sh --grep "Files - ExplorerView"`; verify enabled metadata is rendered and included in the ARIA label, disabled metadata preserves the current row and label, and narrow-width truncation does not hide the filename.
- **Behavior:**

  > Explorer users can enable persistent file-size and last-modified metadata without opening a hover or separate view. Screen readers announce the same enabled metadata with each file name. Existing modified-time sorting remains functional, filenames remain usable in narrow Explorer widths, and disabling metadata preserves the current Explorer presentation and avoids unnecessary metadata work.
- **Trace:**

  > FilesRenderer.renderStat and FilesRenderer.getAriaLabel in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts currently expose only the file name. ExplorerItem in src/vs/workbench/contrib/files/common/explorerModel.ts carries mtime but not size, while ExplorerItem.fetchChildren and ExplorerService request metadata only for the modified sort order because resolving it is potentially expensive. The existing explorer.sortOrder setting in src/vs/workbench/contrib/files/browser/files.contribution.ts covers sorting only. Styling for the flex-based, ellipsized row is in src/vs/workbench/contrib/files/browser/media/explorerviewlet.css. Keep file nesting, compressed-folder navigation, rename input, decorations, and existing sort semantics unchanged; the uncertainty begins at the visible metadata layout, defaults, and directory scope.
- **Open decisions:**
  - Should file size and modification date be shown by default, or controlled by independently configurable Explorer settings?
  - Should metadata appear as compact trailing text or as aligned columns, particularly when the Explorer is narrow?
  - Is the initial scope files only, or should directories also show metadata; if directories are included, should size mean the directory entry size or a recursively calculated total?

## Evidence

- **current rendering gap:** In src/vs/workbench/contrib/files/browser/views/explorerViewer.ts, FilesRenderer.renderStat renders only the resource/name label, while FilesRenderer.getAriaLabel returns only element.name; neither surface exposes size or modification time.
- **current model boundary:** ExplorerItem in src/vs/workbench/contrib/files/common/explorerModel.ts stores mtime but no size, and fetchChildren resolves metadata only when explorer.sortOrder is modified because metadata resolution can be expensive.
- **partial existing capability:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers explorer.sortOrder=modified, which sorts entries by last-modified time but does not display the timestamp or file size, so it does not satisfy the central request.
