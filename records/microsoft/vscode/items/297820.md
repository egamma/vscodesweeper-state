# Issue #297820 — Chat Participant: pasted image references can have 0-byte payload

[https://github.com/microsoft/vscode/issues/297820](https://github.com/microsoft/vscode/issues/297820)

## Summary

Current main does provide non-empty pasted-image bytes through the proposed `ChatReferenceBinaryData.data()` method, but third-party participants have no documented stable contract for consuming that value. The observed zero length comes from treating the `data` function itself as a byte buffer, so the remaining valid work is API finalization or stable documentation rather than a payload-generation bug.

## Change summary

Provide chat participants with a documented stable API for reading pasted-image reference bytes.

## Best solution

Finalize an extension-facing binary-reference contract, or otherwise document a stable supported way for chat participants to resolve pasted-image bytes. The contract should make clear that binary data is retrieved asynchronously rather than exposed as a `Uint8Array` property.

## Evidence

- **proposed API contract:** src/vscode-dts/vscode.proposed.chatReferenceBinaryData.d.ts defines `data(): Thenable<Uint8Array>`, while stable src/vscode-dts/vscode.d.ts leaves ChatPromptReference.value as `unknown`; therefore this capability is not a documented stable participant API.
- **observed zero-length cause:** The reporter's linked extension source at https://github.com/koenvanwijk/devbuddy-vscode-extension/issues/6 checks `value.data` as though it were byte data and passes that function to `new Uint8Array(...)`; it does not invoke and await `value.data()`, which explains the reported zero-byte diagnostic.
