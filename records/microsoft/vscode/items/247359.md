# Issue #247359 — ViewColumn.Below API

[https://github.com/microsoft/vscode/issues/247359](https://github.com/microsoft/vscode/issues/247359)

## Summary

Keep this accepted API request open: the current API cannot explicitly select a below-active placement independently of the user's split-direction setting. It has 27 upvotes, and the older equivalent requests were closed for insufficient votes, not implemented or declined on technical grounds.

## Change summary

Expose an extension API for opening an editor below the active editor rather than relying on the configured side-by-side direction.

## Best solution

Provide an explicit downward-placement API while preserving the setting-dependent behavior of ViewColumn.Beside. An API design session should settle the public shape and whether downward placement reuses an existing group or always creates a new row.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/workbench/services/editor/common/editorGroupFinder.ts`, `src/vs/workbench/api/test/common/extHostTypeConverters.test.ts`
- **Validation:** After the API contract is agreed, use an extension opening a document below the active editor with workbench.editor.openSideBySideDirection set first to right and then to down. Verify downward placement in both cases, the agreed behavior with an existing lower group, unchanged ViewColumn.Beside behavior, and normal resolved TextEditor.viewColumn values. Add conversion coverage in src/vs/workbench/api/test/common/extHostTypeConverters.test.ts.
- **Behavior:**

  > Extensions should be able to request placement below the active editor without changing the user's default side-by-side direction. The request must work with the default direction set to either right or down. Existing ViewColumn.Beside and numbered-column behavior must remain unchanged. Acceptance must cover both an absent lower group and an already-existing lower group under the agreed placement contract.
- **Trace:**

  > The public ViewColumn enum in src/vscode-dts/vscode.d.ts has no explicit downward value. ViewColumn.from in src/vs/workbench/api/common/extHostTypeConverters.ts maps Beside to SIDE_GROUP, and the SIDE_GROUP branch in src/vs/workbench/services/editor/common/editorGroupFinder.ts chooses the direction from configuration and reuses or creates a group. MainThreadEditors in src/vs/workbench/api/browser/mainThreadEditors.ts passes converted positions through columnToEditorGroup before opening editors. The existing setting provides a user-wide workaround, not per-opening directional control. https://github.com/microsoft/vscode/issues/211772 and https://github.com/microsoft/vscode/issues/84113 establish prior demand but were closed for insufficient votes. Preserve existing placement defaults and resolved column numbering; uncertainty remains in the new public contract, not whether the current enum already exposes it.
- **Open decisions:**
  - Should the public contract add ViewColumn.Below alone, add symmetric explicit Right and Below values, or expose direction through an opening option?
  - Should an explicit below request reuse an existing lower editor group, as Beside does, or always create a new row as the issue's wording suggests?

## Evidence
