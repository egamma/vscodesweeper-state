# Issue #324130 — Insiders regression: Extensions have no pre-release version after the release version is installed and reload window is done

[https://github.com/microsoft/vscode/issues/324130](https://github.com/microsoft/vscode/issues/324130)

## Summary

Keep open: a team member reproduced this Insiders-only regression on multiple machines, and the current extension workbench path still depends on gallery metadata that can suppress the pre-release switch after reload. As a team-authored issue, it cannot be closed without a fixing commit or PR explicitly referencing https://github.com/microsoft/vscode/issues/324130, and none was found.

## Change summary

Installing an extension's release version in Insiders and reloading removes the menu option for switching to its available pre-release version.

## Best solution

Ensure that reloading an installed release extension preserves or reconstructs accurate pre-release availability from Marketplace data, so the Extensions view continues to offer "Switch to Pre-Release Version" whenever a compatible pre-release exists.

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts`, `src/vs/platform/extensionManagement/common/extensionGalleryService.ts`, `src/vs/platform/extensionManagement/node/extensionManagementService.ts`, `src/vs/platform/extensionManagement/test/common/extensionGalleryService.test.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsWorkbenchService.test.ts`
- **Validation:** Add a targeted extension workbench or gallery-service regression test that installs/models a release extension with a compatible pre-release, recreates the service as a window reload would, and asserts that `hasPreReleaseVersion` remains true and the pre-release toggle remains enabled.
- **Behavior:**

  > When an extension has both a compatible release and pre-release version, installing the release version and reloading the window must not remove the option to switch to pre-release. The option must remain available in Insiders exactly as it does before reload and in stable VS Code. Extensions without a compatible pre-release must remain unaffected. Acceptance requires a reload-lifecycle regression test that fails with the reported metadata state and passes with accurate pre-release availability.
- **Trace:**

  > After reload, ExtensionsWorkbenchService.matchInstalledExtensionsWithGallery in src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts rematches local installations with Marketplace results using the persisted `local.preRelease` preference. Extension.hasPreReleaseVersion prefers the resulting gallery object's flag, and TogglePreReleaseExtensionAction in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts exits early when that flag is false. Gallery conversion in src/vs/platform/extensionManagement/common/extensionGalleryService.ts derives the flag from product overrides or the first raw gallery version, while installation metadata in src/vs/platform/extensionManagement/node/extensionManagementService.ts does not independently record the existence of a pre-release when the selected version is a release. The report confirms the resulting symptom on multiple Insiders machines, but the record does not establish whether the incorrect value originates in the Marketplace response, its conversion, or persisted metadata. Keep the boundary to extension version-channel discovery and reload restoration; do not change compatibility rules or expose incompatible pre-release versions.
