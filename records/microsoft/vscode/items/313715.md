# Issue #313715 — Copilot Chat does not show correct context window size on local Ollama models.

[https://github.com/microsoft/vscode/issues/313715](https://github.com/microsoft/vscode/issues/313715)

## Summary

Verified duplicate: the incorrect context window display is caused by ollamaProvider.ts reading the architecture-level `context_length` from Ollama's `/api/show` metadata instead of the runtime `num_ctx` — exactly the root cause diagnosed in #311705, which is the better-scoped canonical issue.

## Change summary

Copilot Chat displays an incorrect (inflated) context window size for local Ollama models because it reads the base model's architecture metadata rather than the runtime `num_ctx` parameter.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/311705, which tracks the same root cause (nominal `context_length` vs. runtime `num_ctx`) and additionally covers the missing token-usage propagation. The fix belongs in `extensions/copilot/src/extension/byok/vscode-node/ollamaProvider.ts` — the `_getOllamaModelInfo` method should prefer the runtime `num_ctx` value (available in the Ollama `/api/show` response's `parameters` field or via `/api/ps`) over the architecture-level `context_length`.

## Evidence

- **root cause in source:** extensions/copilot/src/extension/byok/vscode-node/ollamaProvider.ts line 149 reads `model_info['<arch>.context_length']` from Ollama's `/api/show` response, which is the base model's architecture default (e.g. 256k for gemma4), not the runtime `num_ctx` (64k as configured in the user's Modelfile).
- **UI display path:** src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts line 142 shows `maxInputTokens + maxOutputTokens` as 'Context Size' — since the input is inflated, the displayed value is wrong.
- **canonical issue:** https://github.com/microsoft/vscode/issues/311705 is open and diagnoses the same code path: nominal `context_length` vs. runtime `num_ctx`, and additionally covers missing token-usage propagation. Filed 2026-04-24, same `model-byok` label.
- **additional reports:** https://github.com/microsoft/vscode/issues/299907 and the commenter on this issue both confirm the same symptom across different Ollama models and platforms.
