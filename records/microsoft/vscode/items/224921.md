# Issue #224921 — Vimium or Vim easymotion like keyboard navigation for the whole UI

[https://github.com/microsoft/vscode/issues/224921](https://github.com/microsoft/vscode/issues/224921)

## Summary

Keep this accepted accessibility request open: existing keyboard-navigation commands do not provide Vimium-style hints over UI controls. It has 35 upvotes and was promoted to Backlog; no verified open canonical or implementation was found.

## Change summary

Provide a keyboard-invoked hint mode for navigating and activating controls throughout the VS Code UI without a mouse, including on Linux.

## Best solution

Design an opt-in workbench hint-navigation experience with the accessibility owner, establishing which controls and surfaces it supports and how selection interacts with focus and activation. Preserve existing keyboard navigation and assess the earlier shortcut-mode rejection against this subsequently accepted request.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/navigationActions.ts`, `src/vs/workbench/contrib/accessibility/browser/accessibility.contribution.ts`, `src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts`
- **Validation:** After agreeing the supported surfaces, run a keyboard-only Linux desktop scenario: invoke hint mode, select visible targets in the editor toolbar, sidebar and panel, exercise the agreed menu behavior, and cancel with Escape. Verify the agreed focus/activation result, focus restoration, and that ordinary typing, Tab navigation, F6/Shift+F6 and existing shortcuts remain unchanged outside hint mode.
- **Behavior:**

  > The user wants a Vimium-style mode that displays keyboard hints over UI controls and lets them select a target without moving through every intervening control or remembering each command shortcut. Existing part-navigation shortcuts do not satisfy that interaction. Acceptance should include keyboard-only operation on Linux, predictable cancellation and focus restoration, and unchanged normal keyboard behavior when the mode is inactive. The supported targets and whether selecting a hint focuses or activates its control must be agreed before implementation.
- **Trace:**

  > In src/vs/workbench/browser/actions/navigationActions.ts, BaseFocusAction cycles visible workbench parts through IWorkbenchLayoutService, while BaseNavigationAction navigates views and editor groups; neither enumerates individual controls or renders target hints. src/vs/workbench/contrib/accessibility/browser/accessibility.contribution.ts is the existing registration surface for accessibility configuration, help and accessible-view services. Targeted source searches found no matching hint-mode contribution, but target discovery and coverage across menus, webviews and separate windows have not been traced. https://github.com/microsoft/vscode/issues/124002 contains an earlier rejection of shortcut mode, whereas https://github.com/microsoft/vscode/issues/224921 subsequently earned Backlog acceptance. Preserve existing keyboard and accessibility behavior; do not reinterpret the reporter's unspecified button/menu complaints as diagnosed bugs or assume unrestricted extension access to workbench DOM.
- **Open decisions:**
  - Which surfaces must the first version cover: workbench-owned controls only, or also menus, editor content, extension webviews and auxiliary windows?
  - Does selecting a hint focus the target, activate it immediately, or expose separate focus and activation operations?
