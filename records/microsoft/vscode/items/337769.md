# Issue #337769 — Edit tracking slows down bulk text-model loading

[https://github.com/microsoft/vscode/issues/337769](https://github.com/microsoft/vscode/issues/337769)

## Summary

Keep open: current source still rebuilds edit-tracking model lists for each unopened model added, before applying the opened-at-least-once filter. The related lazy-loading and bulk-cleanup issues cover distinct work, not a verified duplicate.

## Change summary

Avoid rebuilding edit-tracking document lists when bulk loading files that have never been opened, while retaining tracking for previously opened models until disposal.

## Best solution

Make the editTelemetry workspace and annotation pipeline exclude never-opened models before tracking-object creation and tracked-list propagation. Preserve first-open enrollment, tracking after tab closure, and cleanup on model disposal; verify reduced work without claiming the recorded 3.4 seconds as measured savings.
