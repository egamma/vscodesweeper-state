# Issue #330717 — Copilot chat loses backspace binding

[https://github.com/microsoft/vscode/issues/330717](https://github.com/microsoft/vscode/issues/330717)

## Summary

Keep open and route to Chat input/editor ownership. Two users independently report that chat appears focused while navigation and deletion keystrokes remain routed to the code editor, across Windows and Linux; the older related report only covers popped-out chat and does not absorb the broader workspace-window symptom.

## Change summary

Chat intermittently retains text entry while routing Backspace and arrow keys to the previously focused code editor, especially with multiple workspace or detached chat windows.

## Best solution

Diagnose the cross-window focus handoff and ensure that clicking or focusing a chat input makes it the sole recipient of text-editing and navigation keys in both ordinary workspace windows and detached chat editors.

- **Behavior:**

  > When the user clicks or otherwise focuses a Copilot Chat input, all typing, deletion, and cursor-navigation keys must apply exclusively to that input. This must remain true after switching between VS Code windows, returning from debugging, and using a detached chat window. Acceptance requires repeated focus transitions without Backspace or arrow keys modifying the previously focused code editor.
- **Trace:**

  > ChatEditor.focus in src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts delegates to ChatWidget.focusInput, which delegates through ChatInputPart.focus to the embedded editor. The issue and https://github.com/microsoft/vscode/issues/260560 show a split-focus state in which ordinary text reaches chat while command-like keys continue to affect the code editor; https://github.com/microsoft/vscode/issues/321787 confirms the detached-window variant. Current source inspection does not reveal which window or editor lifecycle event leaves the old editor active, so diagnosis should begin around cross-window activation and focus restoration, including EditorPanes.shouldRestoreFocus. Preserve normal editor focus restoration and all existing chat keybindings; the boundary is eliminating simultaneous or stale focus ownership, not changing Backspace behavior itself.
