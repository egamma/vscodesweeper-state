# Issue #330717 — Copilot chat loses backspace binding

[https://github.com/microsoft/vscode/issues/330717](https://github.com/microsoft/vscode/issues/330717)

## Summary

Two independent reporters on different OSes (Windows, Ubuntu) and recent VS Code versions describe the same symptom: keystrokes typed in the chat input (especially backspace/arrow keys) get routed to the background editor instead of the chat widget, intermittently, until a restart 'fixes' it. This looks like a real focus-tracking bug in the chat input/detached chat window, but it's transient and I can't trace a concrete root cause in the source without reproducing it live.

## Change summary

In some (workspace / detached) chat windows, keyboard input meant for the Copilot Chat input box is intermittently routed to the underlying text editor instead, so backspace and arrow keys silently affect the wrong buffer.

## Best solution

Route to the chat/input-focus owners to investigate why chat widget focus/keybinding context (e.g. the chat input's context-key scoping or the detached-window focus tracking) can silently lose precedence to the editor; likely candidates are the chat input part's focus tracking and the keybinding `when`-clause scoping for `inChatInput`-style context keys in src/vs/workbench/contrib/chat/browser/.
