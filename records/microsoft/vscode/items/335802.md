# Issue #335802 — Modern UI - Add padding to Chat session widgets

[https://github.com/microsoft/vscode/issues/335802](https://github.com/microsoft/vscode/issues/335802)

## Summary

Real, narrow Modern UI compact-density gap: the chat/agent-session list item's internal vertical padding isn't tightened for compact density the way sibling list rows are, which plausibly produces the uneven/oversized padding shown. Not a duplicate of the broader compact-density tracking issue, which is an exploratory umbrella, not the same reported symptom — keeping open.

## Change summary

In Modern UI with Compact layout density, chat session widgets (sidebar and chat editor) show padding that looks too generous/uneven compared to the rest of the compact UI.

## Best solution

Add a `.modern-ui.modern-ui-compact` override for the agent-session item paddings (`.agent-session-item`, `.agent-session-item-row`, `.agent-session-section-row`) in padding.css, matching how the horizontal list-row inset and scrollable-element padding are already reduced for compact density elsewhere in the same file.

- **Behavior:**

  > In Compact layout density with Modern UI enabled, the vertical padding around chat session items (in the sidebar view and the chat editor) should visually match the tightened rhythm already applied to other list rows and containers in compact mode — not the same spacing used in Default/Comfortable density. Default/Comfortable density visuals are unchanged.
- **Trace:**

  > padding.css already special-cases compact density for horizontal insets (`.monaco-list-row` left/right, `.agent-sessions-viewer .monaco-scrollable-element` padding) via `.modern-ui.modern-ui-compact` selectors, but the vertical paddings on `.agent-session-item`, `.agent-session-item-row`, and `.agent-session-section-row` are defined only under the base `.modern-ui` selector with no compact override, so they stay constant across densities. The boundary: do not touch the chat-viewpane exclusions already in place for the horizontal list-row rule, and do not change Default/Comfortable values. Related: https://github.com/microsoft/vscode/issues/332001 (broader density design work) is where the general density system lives, but this specific gap can land independently.
- **Open decisions:**
