# Issue #325729 — runSubagent BYOK Custom Endpoint model naming

[https://github.com/microsoft/vscode/issues/325729](https://github.com/microsoft/vscode/issues/325729)

## Summary

Valid feature request: custom endpoint BYOK models all share the vendor string `customendpoint`, making them indistinguishable in the `runSubagent` tool's model list. The `asQualifiedName` function in `languageModels.ts` formats every custom endpoint model as `ModelName (customendpoint)`, so agents cannot differentiate between providers. Relates to known BYOK naming issues the team is already tracking.

## Change summary

Allow BYOK custom endpoint models to display a user-defined provider/vendor name instead of the generic `customendpoint` string, so the `runSubagent` tool can disambiguate models from different providers.

## Best solution

The `asQualifiedName` function at `src/vs/workbench/contrib/chat/common/languageModels.ts:313` should use the provider's `displayName` (or the user-configured `name` field from `chatLanguageModels.json`) instead of the raw `vendor` id when building qualified names. This would make models distinguishable both in the picker and when enumerated by MCP tools like `runSubagent`. Issue https://github.com/microsoft/vscode/issues/318748 covers a related display-name problem and the team acknowledged it as a known issue — this request could be folded into the same fix effort.
