# Issue #326158 — Mouse selection snapping around decoration before/after content: both edges of injected content should snap to the adjacent position

[https://github.com/microsoft/vscode/issues/326158](https://github.com/microsoft/vscode/issues/326158)

## Summary

This remains a source-reproducible editor hit-testing bug: injected text is collapsed to one document position without preserving both visual edges as mouse snap candidates. Route it to editor core rather than closing it.

## Change summary

Mouse selection near wide decoration-injected text snaps using the injected width, causing endpoints and anchors to land one character early.

## Best solution

Make editor mouse hit testing treat both visual edges of injected content as the same adjacent document position, while preserving current keyboard cursor-stop behavior and selection across the injected content.
