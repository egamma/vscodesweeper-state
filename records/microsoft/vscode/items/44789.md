# Issue #44789 — Overview ruler becomes redundant

[https://github.com/microsoft/vscode/issues/44789](https://github.com/microsoft/vscode/issues/44789)

## Summary

Keep open: current source still enlarges the scrollbar thumb independently of overview markers, so the thumb is not an exact viewport indicator in sufficiently long files. Existing settings offer partial workarounds, but neither they nor a verified canonical issue cover the requested improvement.

## Change summary

Make the overview ruler communicate visible lines accurately in long files without misleading cursor, search, and diagnostic marker placement relative to the scrollbar thumb.

## Best solution

Preserve a usable scrollbar drag target while making the actual visible range distinguishable from its artificially enlarged thumb. The editor-scrollbar owner should settle the presentation before implementation; disabling markers alone does not deliver accurate navigation.

## Evidence

- **Reported scenario:** https://github.com/microsoft/vscode/issues/44789 describes placing the cursor midway through a 2000–3000-line TypeScript file and scrolling it to the viewport top. The reporter also supplied font size 14, default line height, 1920×1080 resolution, and occurrence at both zoom levels 2 and 0; the comments contain no confirmed fix or canonical duplicate.
- **Current scrollbar geometry:** src/vs/base/browser/ui/scrollbar/scrollbarState.ts explicitly sets MINIMUM_SLIDER_SIZE = 20 to keep the thumb clickable. ScrollbarState._computeValues clamps the proportional thumb height to that minimum, then maps scroll position over the remaining track. Consequently, an enlarged thumb cannot represent the exact visible fraction of a sufficiently long document.
- **Current marker geometry:** src/vs/editor/browser/viewParts/overviewRuler/decorationsOverviewRuler.ts, DecorationsOverviewRuler._render, maps decorations and cursor positions using canvasHeight / viewLayout.getScrollHeight(). It does not use the scrollbar's minimum-thumb-adjusted ratio. This supports the reported visual mismatch, rather than proving that the underlying document positions are wrong.
- **Existing-capability check:** src/vs/editor/common/config/editorOptions.ts registers editor.hideCursorInOverviewRuler and supports overviewRulerLanes = 0; DecorationsOverviewRuler._render hides its canvas when lanes are zero. These remove information rather than reconcile viewport and marker geometry. editor.minimap.size and editor.minimap.showSlider configure a separate navigation surface, not the overview ruler's viewport representation.
- **Canonical-search results:** Read https://github.com/microsoft/vscode/issues/85418: it is open but requests unconditional removal of distracting overview decorations, not accurate long-file viewport indication. Read https://github.com/microsoft/vscode/issues/206995: it is open and reports related alignment symptoms, but does not establish the same minimum-thumb cause or own this request's full scope. https://github.com/microsoft/vscode/issues/118029 is closed and concerns page-scrolling behavior. Searches for overview-ruler positioning, long files, scrollbar markers, and minimum-thumb terminology found no verified canonical.
