# Issue #335710 — Secondary Side Bar with Copilot Chat disappears when opening Markdown files

[https://github.com/microsoft/vscode/issues/335710](https://github.com/microsoft/vscode/issues/335710)

## Summary

The discussion clarifies that the titlebar control moves into overflow, rather than the Secondary Side Bar itself disappearing. This is covered by an older, verified open request for width-based titlebar action overflow.

## Change summary

Keep titlebar controls visible when Markdown contributes additional editor actions and sufficient window width remains.

## Best solution

Consolidate the width-based overflow request in https://github.com/microsoft/vscode/issues/226423, preserving this report's Markdown-triggered disappearance of the Secondary Side Bar control as another concrete example.

That encompasses this reporter's requested width-based handling when Markdown actions are contributed.
- **Current source retains count-based overflow:** src/vs/workbench/browser/parts/titlebar/titlebarPart.ts:681-694 constructs the action toolbar with overflowBehavior.maxItems set to 12. createActionToolBarMenus places editor actions before layout actions. src/vs/platform/actions/browser/toolbar.ts:168-195 moves non-exempt actions into the secondary menu based on a count, without measuring their available width.
- **Existing capabilities do not satisfy the central request:** Right-click hiding of actions and workbench.editor.editorActionsLocation can reduce titlebar pressure; workbench.layoutControl.type can consolidate layout controls. These are workarounds, not width-responsive overflow. BrowserTitlebarPart.updateTitleBarToolBarOverflow at titlebarPart.ts:946-960 measures width only to hide separate center-adjacent and update toolbars; it does not replace the main action toolbar's count limit.
