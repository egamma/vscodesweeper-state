# Issue #332387 — Agents window: Can't seem to select certain messages in chat nav bar

[https://github.com/microsoft/vscode/issues/332387](https://github.com/microsoft/vscode/issues/332387)

## Summary

Traced a plausible root cause on current main: the chat/session nav (chat outline) only re-selects the active entry when its `onDidChange` fires, but `ChatOutline` fires that event solely when the request list changes — not when the focused tree item changes via reveal/click — so navigating between messages leaves the nav bar's highlight stale or absent for most entries.

## Change summary

In the Agents window chat nav bar, clicking most messages jumps the transcript to the right spot but the clicked message never gets highlighted as selected in the nav list.

## Best solution

Give IChatWidget/ChatListWidget a public focus-change event (chatListWidget.ts already listens to `this._tree.onDidChangeFocus` internally at line 643 but doesn't re-emit it) and have `ChatOutline` (src/vs/workbench/contrib/chat/browser/chatOutline.ts) subscribe to it and fire `_onDidChange`, so `outlinePane.ts`'s `revealActiveElement`/`tree.setSelection` (line 338, driven by `newOutline.onDidChange` at line 346) re-syncs the highlighted row whenever the underlying chat tree's focus moves.

- **outline consumer wiring:** src/vs/workbench/contrib/outline/browser/outlinePane.ts line 346 only calls `revealActiveElement` (which does `tree.setSelection([item])` at line 338) inside `newOutline.onDidChange(...)` — selection only refreshes when the outline signals a change.

- **reveal() doesn't trigger a refresh:** `ChatOutline.reveal()` (line 273-277) calls `_widget.reveal(item)` / `_widget.focus(item)`, changing tree focus, but neither call is followed by an `_onDidChange` fire, so the outline pane/nav list never re-selects the newly focused row.
