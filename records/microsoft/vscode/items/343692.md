# Issue #343692 — Copilot Chat model selection icons are confusing and inconsistent

[https://github.com/microsoft/vscode/issues/343692](https://github.com/microsoft/vscode/issues/343692)

## Summary

Keep open for model-picker design review: current source still uses different icon semantics for provider tabs and the selected model. This leaves a real provider-identification gap, rather than demonstrating a routing defect.

## Change summary

Make selected-model icons consistently distinguish Copilot-hosted models from BYOK models, including identically named models across harnesses.

## Best solution

Establish a consistent provider-identity convention for the collapsed model selector and provider tabs, so users can distinguish Copilot from BYOK without opening the picker. Decide how model-family branding and status indicators should coexist with that convention before implementation.

## Evidence

There are no comments establishing an accepted icon convention or linking an implementation.
- **Selected-model icon semantics remain:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelProviderIcons.ts: getModelProviderIcon derives icons from vendor/family/id/name, returns a generic icon for most isBYOK models, and explicitly avoids branding the entire Copilot catalogue with the Copilot icon. getModelPickerIcon gives metadata.statusIcon precedence. These rules do not consistently identify the hosting provider.
- **Provider tabs use a separate identity:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabs.ts: buildModelPickerDestinations groups models by provider and uses the provider's declared icon or a provider-name fallback. By contrast, modelPickerWidget.ts:890-893 renders getCompactModelPickerIcon for the selected model when showModelIcon is enabled.
- **Existing-capability check:** Provider tabs and provider-labelled search results identify provenance while browsing, but do not satisfy the request for at-a-glance identification in the collapsed selector. Searches of chat contribution registrations found no setting that switches selected-model icons to provider-tab identity.
