## Change summary

Font remeasurement via _readFromDomElements in charWidthReader.ts consumes excessive CPU time during display change events, flagged by the built-in CPU profiler as a PerfSampleError.

## Best solution

Optimize the font measurement path in charWidthReader.ts — the _readFromDomElements loop reads offsetWidth for each request element, forcing synchronous layout. Consider batching reads, caching results across identical font configurations, or deferring measurement to requestAnimationFrame to reduce layout thrashing. The throttled delayer in displayChangeRemeasureFonts.ts already limits event frequency but doesn't help with the per-measurement cost.
