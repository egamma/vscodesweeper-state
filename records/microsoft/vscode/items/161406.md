# Issue #161406 — Git - credentials popup show directly password instead of username

[https://github.com/microsoft/vscode/issues/161406](https://github.com/microsoft/vscode/issues/161406)

## Summary

Keep open for diagnosis of authentication during parallel private-dependency installs. The discussion confirms the password-only symptom, and current source contains a relevant concurrency defect, but that defect does not yet explain every reported host and configuration.

## Change summary

Installing multiple private Git dependencies together can show a password prompt without a usable preceding username prompt and prevent installation.

## Best solution

Make concurrent Git authentication requests complete without losing credentials or displacing required prompts in the built-in Git askpass flow. Establish whether the authority-cache defect explains the npm reproduction before treating the GitHub-specific report as the same work.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `extensions/git/src/askpass-main.ts`, `extensions/git/src/ipc/ipcServer.ts`, `extensions/github/src/credentialProvider.ts`
- **Validation:** In a trusted VS Code window, install two private git+https dependencies together with integrated terminal authentication enabled and compare with individual installs. Record askpass request ordering without credential values; verify both dependencies install successfully. Also exercise the parallel git ls-remote reproduction from https://github.com/microsoft/vscode/issues/230033 and check a non-GitHub host to distinguish provider-cache failures from interactive-prompt interference.
- **Behavior:**

  > Installing multiple private Git dependencies in one npm install must complete authentication for each Git process without dropping required username input or presenting an unusable password-only exchange. A username prompt is not required when a credential provider or Git credential helper already supplies the username. Acceptance compares concurrent and sequential installs and confirms that ordinary single-repository authentication remains unchanged.
- **Trace:**

  > Askpass.handleAskpass in extensions/git/src/askpass.ts receives requests through askpass-main.ts and IPCServer.onRequest in extensions/git/src/ipc/ipcServer.ts. Requests are handled independently; provider credentials share an authority-keyed cache whose entry is consumed by the first password request, so interleaved exchanges can exhaust it prematurely. https://github.com/microsoft/vscode/issues/230033 demonstrates this mechanism with concurrent GitHub requests. The built-in provider in extensions/github/src/credentialProvider.ts handles only github.com, whereas the original discussion names other hosts; uncertainty begins at whether those cases lose interactive prompts, receive password requests directly from Git, or fail outside VS Code. Preserve valid password-only requests when a username is already known, existing credential-helper behavior, and SSH authentication semantics. No live reproduction was performed in this read-only review.

## Evidence

- **Reported reproduction and workaround:** https://github.com/microsoft/vscode/issues/161406 describes npm install with two private git+https dependencies on Windows 11; installing dependencies individually avoids the problem. The reporter confirmed persistence after updating to 1.71.2 and again in January 2023. A September 2024 commenter independently reported the password-only symptom on Ubuntu, although their failure outside VS Code suggests that some configurations may have another cause.
- **Maintainer consolidation:** https://github.com/microsoft/vscode/issues/124349 is closed, and the maintainer comment at https://github.com/microsoft/vscode/issues/124349#issuecomment-2539927591 identifies this issue as its duplicate target. That report concerns npm triggering HTTPS authentication despite an SSH dependency URL; it supplies additional context, not a fixing commit or an open canonical.
- **Current-source concurrency defect:** In extensions/git/src/askpass.ts, Askpass.handleAskpass caches provider credentials by authority and deletes the entry after the first password request. Two username requests followed by two password requests therefore leave the second password request falling through to window.showInputBox. extensions/git/src/ipc/ipcServer.ts dispatches requests independently, without serializing these authentication exchanges.
- **Related open report and scope limit:** https://github.com/microsoft/vscode/issues/230033 is verified open and provides an explicit parallel git ls-remote reproduction and the same authority-cache diagnosis. Its demonstrated case uses GitHub credential-provider authentication; extensions/github/src/credentialProvider.ts supplies credentials only for github.com. This issue also reports other private Git hosts, so the narrower provider-cache diagnosis is not sufficient proof that the newer report absorbs its full scope.
- **Existing configuration is a workaround:** extensions/git/package.json and package.nls.json register git.terminalAuthentication and git.useIntegratedAskPass. Askpass.getTerminalEnv honors these settings, allowing terminal authentication to bypass the integrated handler, but disabling that handler does not repair concurrent authentication.
- **Verification limits:** Inspection was read-only; no npm installation or interactive authentication reproduction was executed. The checkout is shallow and contains only one history commit, so local history cannot establish a fixing commit. The reproduced status reflects the discussion's confirmations, not a live current-main npm reproduction.
