# Issue #141806 — Saving as on restored custom editor triggers spurious save confirmation

[https://github.com/microsoft/vscode/issues/141806](https://github.com/microsoft/vscode/issues/141806)

## Summary

Still reproduces on main: after restoring a dirty custom editor from backup, `saveAs` never clears `_defaultDirtyState`, so the old editor input remains dirty and triggers a spurious save confirmation when closed.

## Change summary

Save-As on a restored dirty custom editor triggers an unwarranted save confirmation for the original document.

## Best solution

In `CustomEditorInput.saveAs()`, clear `_defaultDirtyState` after a successful `saveCustomEditorAs` so the old editor input no longer reports itself as dirty. The fix is localized to `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts`.
