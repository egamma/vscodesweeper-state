# Issue #87944 — Diff editor: Differentiate unimportant differences

[https://github.com/microsoft/vscode/issues/87944](https://github.com/microsoft/vscode/issues/87944)

## Summary

Keep this accepted, well-supported request open: current diff settings do not distinguish configurable minor changes from important changes. The verified related issues cover narrower or different behavior, not this request's full scope.

## Change summary

Allow configurable or language-aware classification of minor differences, with distinct presentation and optional exclusion from diff navigation.

## Best solution

Provide an opt-in way to distinguish minor differences while preserving the original text and visibility of substantive edits. Agree on the classification rules and their effects on highlighting, navigation, and the overview ruler before implementation.

- **Validation:** After agreeing on the behavior, add diff fixtures containing both substantive changes and selected minor changes, asserting original-to-modified range mappings remain accurate. Manually compare files containing timestamp-only, comment-only, and substantive edits in side-by-side and inline views; verify the agreed highlighting, navigation, and overview-ruler behavior, and confirm disabling the feature restores existing behavior.
- **Behavior:**

  > Users need to focus on substantive differences without losing awareness that other text changed. Examples include timestamps in logs, comments, case in case-insensitive languages, and repeated http-to-https substitutions. The requested capability extends beyond ignoring whitespace or collapsing unchanged regions. Acceptance should verify mixed important/minor changes, preservation of the original displayed text, and consistent behavior in inline and side-by-side views; the exact classification and navigation rules remain a product decision.
- **Trace:**

  > DiffEditorViewModel in src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts invokes IDocumentDiffProvider with whitespace, timeout, and move options. The provider contract in src/vs/editor/common/diff/documentDiffProvider.ts returns changes and moves without an importance category. DefaultLinesDiffComputer computes textual differences, and the external diff adapter does not enable a minor-change policy either. Existing settings only suppress leading/trailing whitespace differences or hide unchanged regions. src/vs/editor/test/node/diffing/fixtures.test.ts provides range-mapping fixtures and reconstruction checks, but the eventual classification and UI behavior need their own acceptance coverage. Preserve default diff behavior, text fidelity, and accurate mappings; do not automatically assume comments or strings are semantically irrelevant. Related requests at https://github.com/microsoft/vscode/issues/43026 and https://github.com/microsoft/vscode/issues/225587 cover subsets, not substitutes for this work.
- **Open decisions:**
  - Should the initial classification mechanism support user-defined text patterns, language-aware categories, or both?
  - Should minor differences remain distinctly highlighted but be skipped by navigation and the overview ruler, or should users choose separately between differentiation and complete suppression?
  - Should classification rules apply per comparison, per language, or through persistent workspace/user configuration?
