# Issue #327469 — SSH session fails to connect with "uname is not recognized as a name or cmdlet" when connecting to Windows 11 host

[https://github.com/microsoft/vscode/issues/327469](https://github.com/microsoft/vscode/issues/327469)

## Summary

Confirmed from source: the SSH agent host connection path unconditionally runs `uname -s` / `uname -m` (line 727–728 of sshRemoteAgentHostService.ts) and `resolveRemotePlatform` only handles Linux and Darwin — Windows SSH hosts are entirely unsupported, so connecting to one fails immediately.

## Change summary

SSH agent host sessions fail when connecting to a Windows remote because `uname` is a Unix command unavailable on Windows, and the platform resolver has no Windows path.

## Best solution

Add Windows platform detection in the SSH connection path — either by trying a Windows-compatible command (e.g. checking for PowerShell/cmd first, or using `ver`/environment variables) or by accepting a platform hint in configuration. `resolveRemotePlatform` in sshRemoteAgentHostHelpers.ts also needs a `win32` / `windows_nt` branch, and `_ensureCLIInstalled` needs a Windows CLI artifact path.
