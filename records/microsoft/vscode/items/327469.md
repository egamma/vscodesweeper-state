# Issue #327469 — SSH session fails to connect with "uname is not recognized as a name or cmdlet" when connecting to Windows 11 host

[https://github.com/microsoft/vscode/issues/327469](https://github.com/microsoft/vscode/issues/327469)

## Summary

Verified duplicate of the earlier-filed, still-open canonical issue tracking this exact defect — the Agents SSH connect flow hardcodes a `uname -s` probe with no Windows/PowerShell fallback, and both issues describe the identical failure and fix scope.

## Change summary

Agents SSH connection to a Windows host fails immediately because the remote-platform probe runs `uname -s`, which PowerShell doesn't recognize.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/316712, which already tracks replacing the hardcoded `uname -s`/`uname -m` probe in `sshRemoteAgentHostService.ts` with a shell/OS-neutral detection (or an explicit PowerShell fallback) so Windows SSH targets can connect.
