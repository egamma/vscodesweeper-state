# Issue #347361 — Can't drag text into rename textboxes

[https://github.com/microsoft/vscode/issues/347361](https://github.com/microsoft/vscode/issues/347361)

## Summary

Keep open: the report provides enough detail to retest text drops into Explorer naming fields. Current main uses a shared inline-edit control, but source inspection does not establish whether the reported drop failure persists or has been fixed.

## Change summary

Dragging text into an Explorer file or folder creation/rename field fails to insert it.

## Best solution

Ensure text drops into an active Explorer naming field behave like text input without triggering Explorer resource-drop operations. Treat creating files by dropping text onto the Explorer background as a separate feature request.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `src/vs/workbench/browser/parts/views/inlineEditInputBox.ts`, `src/vs/base/browser/ui/list/listView.ts`
- **Validation:** On Linux GNOME/Wayland, drag selected document text into empty and populated Explorer fields for Rename, New File, and New Folder; verify insertion at the drop position and normal Enter/Escape behavior. Confirm ordinary file/folder drag-and-drop remains unchanged. Establish a failing browser regression test once the responsible event path is reproduced.
- **Behavior:**

  > Dragging selected text into an active Explorer file or folder naming field should insert that text rather than silently discard it. Cover both creation and rename, with empty and populated fields. Existing validation and confirmation/cancellation behavior must remain intact. Creating a file by dropping text onto the Explorer background is outside this bug's scope.
- **Trace:**

  > Explorer renderInputBox in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts composes InlineEditInputBox, whose implementation is in src/vs/workbench/browser/parts/views/inlineEditInputBox.ts. The shared input observes input events but has no explicit text-drop handling. The containing ListView intercepts dragover/drop, and FileDragAndDrop classifies resource payloads; the interaction between native input insertion and these enclosing handlers needs runtime diagnosis. No execution was performed in the read-only checkout, so no root cause is confirmed. Preserve resource-drop behavior outside active naming fields and avoid changing every consumer of the shared control without evidence that the defect is shared.
