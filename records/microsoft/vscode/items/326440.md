# Issue #326440 — AHP initialize failed: rpc error -32005: Client offered protocol versions [0.4.0], none of which are compatible with this server's version 0.6.0 (server accepts ^0.6.0)

[https://github.com/microsoft/vscode/issues/326440](https://github.com/microsoft/vscode/issues/326440)

## Summary

Still an active defect on current main: the bundled Rust `code agent` client and the bundled Agent Host server protocol version repeatedly drift apart at release time, and the merged PR referenced in the timeline (#327298) only patched one instance rather than the underlying process gap.

## Change summary

The `code agent` CLI's bundled protocol version lags the Agent Host server's protocol version within the same VS Code build, so `code agent ps`/management commands fail with an AHP initialize incompatibility error.

## Best solution

Keep every VS Code release's bundled `ahp`/`ahp-types` Rust crate versions in lockstep with `PROTOCOL_VERSION` in src/vs/platform/agentHost/common/state/protocol/version/registry.ts at build/release time, and build the `scripts/verify-release-metadata.ts` safety check mentioned in the registry.ts comment (it doesn't exist in this checkout) so a mismatched release can't ship again.

## Evidence

- **current main crate version:** cli/Cargo.lock pins `ahp` and `ahp-types` at 0.7.0 (crates.io), matching cli/Cargo.toml's `ahp = "0.7.0"` / `ahp-types = "0.7.0"`.
- **current main server protocol version:** src/vs/platform/agentHost/common/state/protocol/version/registry.ts:19 sets `PROTOCOL_VERSION = '1.0.0'` (generated, DO NOT EDIT banner, synced from the sibling agent-host-protocol repo).
- **negotiation logic:** src/vs/platform/agentHost/common/state/protocol/version/negotiation.ts:isCompatibleProtocolVersion requires the offered version's major to equal the server's current major; offered 0.7.0 vs current 1.0.0 fails this check, reproducing the same class of error reported here (originally 0.4.0 vs 0.6.0, then per comments 0.6.0 vs 0.7.0/0.7.0 vs 0.8.0).
- **client offers a single version:** cli/src/commands/agent.rs:98 sends `vec![PROTOCOL_VERSION.to_string()]` from the `ahp-types` crate — no fallback list, so any drift is a hard failure.
- **missing safety net:** registry.ts's own comment says a `scripts/verify-release-metadata.ts` validates per-client release-metadata against SUPPORTED_PROTOCOL_VERSIONS, but no such script exists in this checkout — the described guard rail isn't actually built yet.
- **related PR insufficient:** https://github.com/microsoft/vscode/pull/327298 bumped the CLI to AHP 0.6.0 but commenters confirmed the server moved to 0.7.0/0.8.0 shortly after, and now main is at 1.0.0 while the CLI crate is still 0.7.0 — the underlying sync process, not a single version bump, is the real gap.
