# Issue #326440 — AHP initialize failed: rpc error -32005: Client offered protocol versions [0.4.0], none of which are compatible with this server's version 0.6.0 (server accepts ^0.6.0)

[https://github.com/microsoft/vscode/issues/326440](https://github.com/microsoft/vscode/issues/326440)

## Summary

Still broken and, per current main, worse than reported: the CLI's Cargo.lock pins the external `ahp`/`ahp-types` crates at 0.4.0 while the in-tree AHP server protocol (src/vs/platform/agentHost/common/state/protocol/version/registry.ts) is already at 0.8.0, and the closed (unmerged) PR #327298 only chased the gap to 0.6.0 — routing to the agent-host area rather than closing.

## Change summary

`code agent ps`/`kill` fail with an AHP handshake version-negotiation error because the CLI's bundled protocol version has fallen behind the server's.

## Best solution

Coordinate a release of the `ahp`/`ahp-types` crates (microsoft/agent-host-protocol) at a version matching the current server PROTOCOL_VERSION, then bump cli/Cargo.toml's `ahp`/`ahp-types` pins (currently "0.4", cli/Cargo.lock resolves 0.4.0) to match — ideally with a process so CLI releases can't ship this far behind the server again.
