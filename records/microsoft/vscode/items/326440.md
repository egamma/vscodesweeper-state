# Issue #326440 — AHP initialize failed: rpc error -32005: Client offered protocol versions [0.4.0], none of which are compatible with this server's version 0.6.0 (server accepts ^0.6.0)

[https://github.com/microsoft/vscode/issues/326440](https://github.com/microsoft/vscode/issues/326440)

## Summary

Still reproducible on current main: the Rust CLI's vendored `ahp` crate (pinned to 0.7.0 in cli/Cargo.toml) offers an older AHP protocol version than the TypeScript server now speaks (`PROTOCOL_VERSION = '1.0.0'` in src/vs/platform/agentHost/common/state/protocol/version/registry.ts), and the server's handshake only accepts versions caret-compatible with its own current version — so `code agent ps`/`code agent kill` from the same installation as the running host fail. Two commenters (cephalin, cmelaro) confirm this recurred across 1.131–1.134 with different version pairs each time, so it's a recurring release-process gap, not a one-off.

## Change summary

`code agent ps`/`code agent kill` fail with an AHP version-negotiation error because the CLI's bundled protocol client and the Agent Host server shipped in the same VS Code build don't speak compatible protocol versions.

## Best solution

Keep the CLI's `ahp`/`ahp-types` crate version (cli/Cargo.toml) in lockstep with the TS protocol's `PROTOCOL_VERSION` (registry.ts) at release time — ideally enforced by an automated release check (the doc comment in registry.ts already references a `scripts/verify-release-metadata.ts` and per-client `release-metadata.json` that don't yet exist in this checkout) so a server-side protocol bump can't ship without the bundled CLI client being bumped too.
