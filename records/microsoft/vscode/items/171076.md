# Issue #171076 — Provide a list of deduped and nicely named codicons for use in product

[https://github.com/microsoft/vscode/issues/171076](https://github.com/microsoft/vscode/issues/171076)

## Summary

Terminal adoption and glyph deduplication have landed, but the requested user-friendly names remain missing: the shared picker still searches and displays raw icon IDs. Keep this reopened request as the remaining naming and curation work; no verified canonical absorbs it.

## Change summary

Provide a deduplicated, meaningfully named selection of icons for terminal and user-profile pickers, retaining the backing icon IDs.

## Best solution

Finish the shared icon-selection experience with meaningful display names while preserving existing icon IDs and terminal-specific choices such as Debian and Ubuntu. Settle the user-facing catalog and naming contract before implementation rather than treating the completed terminal picker adoption as completion of this request.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/icons/iconSelectBox.ts`, `src/vs/platform/theme/common/iconRegistry.ts`, `src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts`, `src/vs/workbench/services/userDataProfile/common/userDataProfileIcons.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts`
- **Validation:** In a runnable development build, open the terminal Change Icon picker and the user-profile icon picker. Verify meaningful names and backing IDs are available, searching by each finds the intended icon, equivalent catalog entries are deduplicated, Debian and Ubuntu remain selectable in the terminal, and selecting an icon preserves its existing stored ID. Add focused picker tests for the agreed naming and search contract.
- **Behavior:**

  > Users should choose icons from a deduplicated selection with meaningful names rather than needing to interpret raw codicon IDs. The backing ID remains available and selection preserves existing saved icon identifiers. The experience should work for terminal and user-profile selection without losing terminal-specific icons such as Debian and Ubuntu. Acceptance checks cover friendly-name discovery, backing-ID lookup, deduplication, and unchanged selection persistence.
- **Trace:**

  > TerminalIconPicker in src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts obtains registry contributions and retains the first direct definition for each fontCharacter. Terminal adoption landed in https://github.com/microsoft/vscode/pull/209118, but IconSelectBox in src/vs/base/browser/ui/icons/iconSelectBox.ts still accepts ThemeIcon[] and uses icon.id for filtering, tooltips, and optional focused-icon information. IconContribution in src/vs/platform/theme/common/iconRegistry.ts has description metadata, which this widget does not consume. The user-profile editor passes the curated ICONS array from src/vs/workbench/services/userDataProfile/common/userDataProfileIcons.ts through the same widget. The remaining uncertainty is the user-facing catalog and naming contract, not whether terminal adoption happened. Preserve existing persisted IDs, product-icon theming, keyboard selection, and terminal-specific choices; extension-contributed custom-icon support in https://github.com/microsoft/vscode/issues/194276 is a separate scope.
- **Open decisions:**
  - Should terminal and user-profile pickers expose one shared curated catalog, or context-specific catalogs with a common naming contract?
  - Should meaningful names be a fixed localized catalog or humanized IDs with curated overrides, and where should users see the backing ID in the current grid picker?

## Evidence

- **Reopened scope:** https://github.com/microsoft/vscode/issues/171076 was closed on 2023-09-07 and reopened that day. The author required terminal compatibility and adoption; subsequent discussion explicitly continued the deduplication and meaningful-description work.
- **Partial implementation:** https://github.com/microsoft/vscode/pull/209118 merged on 2024-04-01 with merge commit bf9f03860648e079f4b871b06ef38ff64dd8b86b. Its diff introduces TerminalIconPicker, filters repeated fontCharacter values, and replaces the terminal quick pick with WorkbenchIconSelectBox; it does not introduce friendly display names. https://github.com/microsoft/vscode/issues/199964#issuecomment-2027440489 confirms this adoption and first-entry-per-glyph selection.
- **Current capability and remaining gap:** src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts still deduplicates registry entries by fontCharacter. In src/vs/base/browser/ui/icons/iconSelectBox.ts, IIconSelectBoxOptions accepts ThemeIcon[] without display-name metadata; create() searches icon.id, renderIcons() sets the tooltip to icon.id, and focusIcon() displays icon.id when showIconInfo is enabled. Registry descriptions are not consumed by this picker.
- **User-profile coverage:** src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts uses the same WorkbenchIconSelectBox with ICONS from src/vs/workbench/services/userDataProfile/common/userDataProfileIcons.ts.
