# Issue #171076 — Provide a list of deduped and nicely named codicons for use in product

[https://github.com/microsoft/vscode/issues/171076](https://github.com/microsoft/vscode/issues/171076)

## Summary

Half of the ask has landed (the terminal icon picker now dedupes codicons by glyph), but the core 'nicely named' request — human-readable names with the raw id shown as secondary text — is still missing on main, so this stays open; a prior implemented-on-main close citing a different commit was already refuted on re-review.

## Change summary

Give the terminal/profile icon picker a deduped list of codicons with nice human-readable names (and the raw id shown as secondary/greyed text) instead of raw, duplicate-laden codicon ids.

## Best solution

Decide the curation approach (manual `registerIcon` descriptions per aeschli's suggestion vs. an automated id→name transform per hbons's suggestion), then have the terminal icon picker (and ideally the user profile icon picker) render that curated name with the id as secondary text; dedup is already solved in terminalIconPicker.ts.

  > Dedup is already solved: terminalIconPicker.ts (lines 19-36) filters iconRegistry.getIcons() by fontCharacter to remove duplicate glyphs and the blank icon. The thread (comments 7-10) never settled whether nice names should come from manually curated `registerIcon(..., description)` calls (aeschli's suggestion, with a `terminal-viewicon-*` convention so extensions can contribute) or an automated string transform of existing ids (hbons's suggestion) — that choice, plus whether to also update the user profile icon picker sandy081 explored, needs a maintainer decision before implementation.
- **Open decisions:**
  - Should nice names come from manually curated `registerIcon(id, defaults, description)` calls (with a naming convention like `terminal-viewicon-*` so extensions can contribute), or from an automated string transform of existing codicon ids?
  - Should this effort cover only the terminal tab/profile icon picker, or also the user profile icon picker that sandy081 explored separately?
  - Should the picker UI show the nice name as primary text with the id as secondary/greyed text inline, or only on hover/selection (as the current `showIconInfo` id-only display does)?

## Evidence

- **dedup already shipped:** src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts lines 19-36 filter iconRegistry.getIcons() to drop the blank icon, pure ThemeIcon aliases, and any icon whose glyph (fontCharacter) duplicates one already included — this satisfies the 'deduped' half of the request.
- **naming not implemented:** src/vs/base/browser/ui/icons/iconSelectBox.ts line 127 only sets `iconContainer.title = icon.id` (raw id as a tooltip), and terminalIconPicker.ts never passes `showIconInfo: true`, so there is no curated 'nice name' with the id shown secondarily as the issue requests.
- **most codicons still lack descriptions:** Base codicons registered via src/vs/base/common/codicons.ts generally have no `description` set in IIconRegistry (src/vs/platform/theme/common/iconRegistry.ts), so even surfacing `icon.description` wouldn't yet produce nice names for most entries — curating that list is the remaining, undone work.
