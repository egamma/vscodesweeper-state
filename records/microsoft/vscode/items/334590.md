# Issue #334590 — AHP Codex not discovering/loading skills

[https://github.com/microsoft/vscode/issues/334590](https://github.com/microsoft/vscode/issues/334590)

## Summary

Traced a real asymmetry on main: Codex's skill discovery (codexSelectedCapabilityRootCandidates in codexCustomizations.ts) only feeds `.agents/skills` and `.codex/skills` roots, while the Copilot harness explicitly scans `.github/skills` (sessionCustomizationDiscovery.ts:146) — so a `.github/skills` skill is invisible to Codex exactly as reported. This has an assigned release milestone (1.137.0) and is team-authored with no cited fix, so it stays open per policy regardless.

## Change summary

Codex-backed AHP sessions don't discover/load skills placed under the `.github/skills` convention, unlike the Copilot harness.

## Best solution

Extend Codex's capability-root feeding (currently `codexSelectedCapabilityRootCandidates` in src/vs/platform/agentHost/node/codex/codexCustomizations.ts, called from `_selectedCapabilityRoots` in codexAgent.ts) to also surface `.github/skills` — and decide whether this should also apply to the primary working directory, which today relies solely on Codex's own native `.agents`/`.codex` discovery and never sees `.github/skills` at all.
