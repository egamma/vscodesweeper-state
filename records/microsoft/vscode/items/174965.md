# Issue #174965 — Standardize how the quick pick indicates the active item

[https://github.com/microsoft/vscode/issues/174965](https://github.com/microsoft/vscode/issues/174965)

## Summary

The inconsistency remains on current main: window switching marks the current item with descriptive text, while profile switching prefixes a checkmark. Keep this team-authored design discussion open until a shared presentation is agreed.

## Change summary

Standardize how quick picks distinguish the currently applied item from other choices.

## Best solution

Agree on a consistent, accessible indication of the currently applied choice, then apply it to the window and profile pickers without conflating that state with keyboard focus or multi-select checkboxes.

- **Validation:** After agreeing on the convention, open Switch Window with two windows and Switch Profile with two profiles. Verify that the current choice uses the agreed presentation in both, remains identifiable while keyboard focus moves to another choice, and is announced meaningfully by a screen reader. Check Delete Profile separately so current-state indication is not confused with its multi-select checkboxes.
- **Behavior:**

  > Quick picks currently indicate the applied choice differently: window switching uses descriptive text, while profile switching uses a checkmark prefix. Equivalent current-state indications should follow an agreed convention and remain distinguishable from keyboard focus and selection. Acceptance should compare window and profile switching with multiple choices, including moving focus away from the currently applied item. The indication must also be understandable with a screen reader.
- **Trace:**

  > BaseSwitchWindow in src/vs/workbench/electron-browser/actions/windowActions.ts uses description "Current Window" and independently initializes focus to another window. registerSwitchProfileAction in src/vs/workbench/contrib/userDataProfile/browser/userDataProfile.ts prefixes the current profile with $(check), while registerDeleteProfileAction uses description "Current". The shared contracts in src/vs/platform/quickinput/common/quickInput.ts distinguish picked selection from activeItem focus; neither represents the applied choice. src/vs/platform/quickinput/browser/quickInputList.ts renders item labels and descriptions and derives accessible labels unless a caller supplies ariaLabel. Preserve window-switch navigation, profile-switch behavior, multi-select semantics and existing contextual descriptions. The related profile-badge discussion at https://github.com/microsoft/vscode/issues/166983 does not settle this design. Uncertainty starts with the shared visual and spoken convention, not with whether the presentations differ.
- **Open decisions:**
  - Should the currently applied choice use a checkmark, descriptive text, or both, and what common spoken wording should accompany that indication?
  - Should the convention cover only single-choice switchers, or also current-state indications in multi-select pickers such as Delete Profile?
