# Issue #325230 — Show model in readonly subagent

[https://github.com/microsoft/vscode/issues/325230](https://github.com/microsoft/vscode/issues/325230)

## Summary

The gap remains on current main: opening a read-only subagent hides the composer and its model picker, while the replacement banner only says that the chat is read-only. Keep this team-authored UI-polish request open and decide where the child model should remain visible.

## Change summary

Display the model used by a subagent within its read-only chat view.

## Best solution

Expose the active child chat's model in a stable, accessible part of the read-only view, using a friendly model name while preserving the existing compact banner and hidden composer.

- **Behavior:**

  > A read-only subagent chat identifies the model that ran it even though its composer and model picker are hidden. The model information must be available visually and to screen readers, without making the chat editable. Full-interactivity chats and archived-session messaging must retain their existing behavior.
- **Trace:**

  > IChat already exposes modelId in src/vs/sessions/services/sessions/common/session.ts. Sessions ChatView calls ChatWidget.setReadOnly for the child chat, and ChatWidget hides the entire input surface where the model picker normally communicates the selection. ChatGroupView replaces that surface with SessionReadOnlyBanner, but its current generic content contains no model metadata. The parent subagent pill gained model display through https://github.com/microsoft/vscode/pull/333171; that is partial coverage outside the opened child view. Keep the change within Sessions-owned read-only presentation and do not make subagent chats interactive or alter ordinary model selection.
- **Open decisions:**

  - When the model identifier cannot be resolved to metadata, should the UI show the raw identifier or omit model information?
