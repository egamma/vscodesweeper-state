# Issue #121205 — Add input validation support to quick picks

[https://github.com/microsoft/vscode/issues/121205](https://github.com/microsoft/vscode/issues/121205)

## Summary

Keep open: core quick picks support validation messages and severity, but extensions still cannot access that capability through the public QuickPick API. The related open issue is newer and does not qualify as a canonical for this re-reviewed report.

## Change summary

Expose quick-pick validation to extensions so workflows combining typed input and selectable choices can display validation feedback.

## Best solution

Provide an extension-facing QuickPick validation contract consistent with InputBox, reusing the existing core rendering. Settle whether error severity affects acceptance, while coordinating presentation work with the related quick-pick issue.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostQuickOpen.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`
- **Validation:** Exercise an extension-created QuickPick containing suggested choices and a choice derived from typed input. Verify validation feedback appears, updates, and clears; check info/warning/error presentation and acceptance against the agreed contract. Confirm existing InputBox validation and ordinary QuickPick selection remain unchanged.
- **Behavior:**

  > Extensions using a quick pick to combine typed input with suggested choices cannot currently display the validation feedback available to input boxes. The finished capability should let an extension communicate invalid input or selection without forcing the user into a separate input UI. Acceptance checks should cover displaying, changing, and clearing messages, severity presentation, and the agreed behavior when the user accepts while an error is present.
- **Trace:**

  > The public QuickPick interface in src/vscode-dts/vscode.d.ts lacks validationMessage, although internal IQuickPick in src/vs/platform/quickinput/common/quickInput.ts already exposes both validationMessage and severity. ExtHostInputBox in src/vs/workbench/api/common/extHostQuickOpen.ts serializes validation feedback, whereas ExtHostQuickPick does not; TransferInputBox in extHost.protocol.ts declares the message field. MainThreadQuickOpen.$createOrUpdate constructs the corresponding core widget and applies transferred properties. The merged https://github.com/microsoft/vscode/pull/187862 supplies internal severity support, not the requested API. Preserve existing InputBox behavior and normal quick-pick filtering and selection; avoid making the separate presentation discussion at https://github.com/microsoft/vscode/issues/187863 a prerequisite unless the API contract requires it. The remaining uncertainty is the public contract for acceptance while validation reports an error.
- **Open decisions:**
  - Should error validation prevent QuickPick acceptance automatically, or should acceptance remain extension-controlled while validation supplies feedback?

## Evidence

- **Existing capability and remaining API gap:** src/vscode-dts/vscode.d.ts:13086–13329 declares QuickInput and QuickPick without validationMessage; InputBox alone exposes validationMessage as string | InputBoxValidationMessage | undefined. QuickPick.prompt supplies instructional text, not severity-aware validation.
- **Core already supports validation:** src/vs/platform/quickinput/common/quickInput.ts:704–712 exposes IQuickPick.validationMessage and severity. src/vs/platform/quickinput/browser/quickInput.ts renders validation messages and severity decorations, confirming that the missing capability is extension access rather than a new core validation surface.
- **Extension-host boundary:** src/vs/workbench/api/common/extHostQuickOpen.ts implements validationMessage only on ExtHostInputBox, at lines 724–735; ExtHostQuickPick has no corresponding accessor. In src/vs/workbench/api/common/extHost.protocol.ts, validationMessage is declared on TransferInputBox rather than TransferQuickPick.
- **Maintainer discussion and partial implementation:** The supplied comments on https://github.com/microsoft/vscode/issues/121205 explicitly distinguish core support from missing API exposure. https://github.com/microsoft/vscode/pull/187862 is merged; its inspected diff adds severity to the internal IQuickPick contract and uses validation in profile creation, but does not expose it through vscode.d.ts or the extension-host QuickPick implementation.
- **Canonical search and re-review constraint:** Title-focused searches for quick-pick validation found this issue and https://github.com/microsoft/vscode/issues/187863. The latter is verified open, was created on 2023-07-13 after this report, and chiefly discusses inline versus popover presentation. It cannot replace this older re-reviewed issue. Its comments also explicitly request extension API support: https://github.com/microsoft/vscode/issues/187863#issuecomment-1860465158 and https://github.com/microsoft/vscode/issues/187863#issuecomment-4600777662.
