# Issue #333131 — Agents window: unable to create PR when remote is not origin

[https://github.com/microsoft/vscode/issues/333131](https://github.com/microsoft/vscode/issues/333131)

## Summary

Real, freshly-reported bug already labeled correctly (bug, agents-window) and milestoned 1.137.0, so it stays open regardless of how strong the fix evidence is. I traced the exact defect in the push path and it matches the reporter's log precisely.

## Change summary

Creating a PR from the Agents window silently fails when the working copy's active GitHub remote is not literally named 'origin' and the branch has no upstream yet.

## Best solution

In agentHostPullRequestOperationHandler.ts, when no upstream is configured, resolve the actual GitHub remote name (matching the already-computed gitHubState.owner/repo) via a small new agentHostGitService.ts helper instead of letting push()/git service silently default to the hardcoded 'origin' fallback.
