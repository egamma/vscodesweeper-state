# Issue #326925 — Agent sessions: PR link never shows because the tracked branch goes stale (and gets cross-contaminated between sessions)

[https://github.com/microsoft/vscode/issues/326925](https://github.com/microsoft/vscode/issues/326925)

## Summary

The central defect remains source-reproducible: current PR detection still queries GitHub with the branch snapshot stored in session metadata rather than the worktree's current HEAD. Some secondary symptoms appear addressed on current main, but the remaining stale-branch path warrants keeping this narrower report open.

## Change summary

Keep each agent session's worktree branch and PR association synchronized after branch renames or checkouts without cross-session metadata contamination.

## Best solution

Derive and persist each session's branch from its own worktree repository, react to HEAD changes by refreshing PR detection, and cover session isolation with tests using two independently changing worktrees. Separately verify whether the Chronicle database observation affects product behavior, since that database is not used by the current PR-detection path.

## Evidence

- **source reproduction:** extensions/copilot/src/extension/chatSessions/vscode-node/pullRequestDetectionService.ts reads `worktreeProperties.branchName` in `detectPullRequestForSession` and passes that persisted value to `findPullRequestByHeadBranch`; it never resolves HEAD from `worktreeProperties.worktreePath`, so renaming the worktree branch leaves PR lookup on the old name.
- **refresh limitation:** extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessions.ts calls `detectPullRequest` when an existing session is opened, but the detection still consumes the stale stored branch. No branch-change subscription updates the session metadata or triggers detection.
- **metadata progress:** extensions/copilot/src/extension/chatSessions/copilotcli/vscode-node/chatSessionMetadataStoreImpl.ts now reads the per-session file before each write and merges bulk entries using `modified` last-write-wins semantics. This appears to address the stale-cache clobbering symptom, but the available shallow checkout contains no attributable fixing commit and the stale branch path remains.
- **database boundary:** The reported `session-store.db` is implemented under extensions/copilot/src/platform/chronicle/node/sessionStore.ts, while PR detection uses IChatSessionWorktreeService metadata. Chronicle branch contamination therefore does not explain the current PR lookup directly and should be diagnosed as a separate persistence path.
