# Issue #97759 — No images in jsdoc hover or notebooks in remote/web

[https://github.com/microsoft/vscode/issues/97759](https://github.com/microsoft/vscode/issues/97759)

## Summary

Keep open: current source still cannot render images from arbitrary virtual filesystem schemes in JSDoc hovers, matching the confirmed web failure in the discussion. Remote URI rewriting and notebook rendering have evolved, but those improvements do not establish that the full report is fixed.

## Change summary

Images referenced by JSDoc markdown or notebook cells should load in remote and web workspaces as they do locally.

## Best solution

Provide supported image loading for virtual-workspace resources in hover markdown, and independently retest the notebook case against its current webview implementation. Preserve existing resource-access restrictions and working local and remote image paths.

## Evidence

- **Confirmed remaining case:** https://github.com/microsoft/vscode/issues/97759#issuecomment-1033251872 confirms that web images remained broken after the baseUri work: unknown schemes were stripped, and memfs resources had no browser-loadable transport.
- **Current source limitation:** src/vs/base/browser/markdownRenderer.ts:783-793 restricts media protocols to http, https, data, file, vscode-file, vscode-remote, and vscode-remote-resource; memfs is excluded. Its massageHref function at lines 593-608 delegates DOM image URI conversion to FileAccess.uriToBrowserUri. In src/vs/base/common/network.ts:311 onward, that conversion handles vscode-remote and native file resources, not arbitrary virtual filesystem providers. A relative image resolved against a memfs document therefore still lacks a supported rendering path.

This supplies relative resolution but does not provide browser transport for virtual filesystem schemes.
