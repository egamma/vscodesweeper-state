# Issue #303402 — Remote SSH workspace paths are handled locally in Copilot Chat UI mode, causing repeated tool failures and renderer overload

[https://github.com/microsoft/vscode/issues/303402](https://github.com/microsoft/vscode/issues/303402)

## Summary

This is the macOS manifestation of the open Remote-SSH UI-mode path-resolution defect tracked by https://github.com/microsoft/vscode/issues/284417. The current source still converts remote path strings back to local `file:` URIs, so the canonical issue fully owns the underlying failure.

## Change summary

Copilot Chat running locally against a Remote-SSH workspace repeatedly accesses remote paths through the local filesystem, causing tool failures and renderer resource exhaustion.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/284417 and fix remote workspace path round-tripping so file tools preserve the `vscode-remote` scheme; retain this report's macOS and renderer-load measurements as additional impact evidence.

- **current source:** On current main, extensions/copilot/src/platform/prompts/common/promptPathRepresentationService.ts:51-105 represents `vscode-remote` resources as filesystem paths, while extensions/copilot/src/extension/tools/node/toolUtils.ts:155-161 resolves tool paths without a remote predominant scheme, producing local `file:` URIs.
- **unique evidence:** This report extends the canonical evidence to a macOS UI host and records repeated failures accompanied by approximately 156.5% renderer CPU and 2.2 GB memory usage.
