# Issue #210436 — setting `editor.autoClosingBrackets` to `beforeWhitespace` no longer works

[https://github.com/microsoft/vscode/issues/210436](https://github.com/microsoft/vscode/issues/210436)

## Summary

The auto-closing behavior before closing braces like `}` is intentional and long-standing — the `beforeWhitespace` setting allows auto-closing before whitespace AND before closing braces, by design. The closing-brace exception has been in the codebase since 2018.

## Change summary

With `editor.autoClosingBrackets: beforeWhitespace`, typing `(` before a non-whitespace character `}` still auto-closes the bracket.

## Best solution

Keep current behavior — the closing-brace exception in `_isBeforeClosingBrace` (src/vs/editor/common/cursor/cursorTypeEditOperations.ts:345) is intentional. It ensures typing inside nested brackets works naturally (e.g. typing `(` before `)` or `}` still auto-closes). The setting description could be made more precise to mention this, but the behavior itself is correct.

  > I traced this in the current source, and the behavior is actually intentional: the `beforeWhitespace` setting means auto-closing happens before whitespace **and** before closing braces (like `}`, `)`, `]`).   > 
  > The rationale is that when you type `(` before an existing `)` or `}`, you almost always want the matching close — blocking that would make bracket nesting painful. In your case with `foo = }`, the `}` is treated as a closing brace, so auto-closing proceeds.
  > 
  > The setting description ("only when the cursor is to the left of whitespace") could arguably be more precise about this exception, but the behavior itself is by design. If you'd like a truly strict mode that never auto-closes before *any* non-whitespace character, that would be a separate feature request.
