# Issue #210436 — setting `editor.autoClosingBrackets` to `beforeWhitespace` no longer works

[https://github.com/microsoft/vscode/issues/210436](https://github.com/microsoft/vscode/issues/210436)

## Summary

The reporter reconfirmed the bug on VS Code 1.131.0 Insiders with all extensions disabled and supplied the exact cursor context requested by the maintainer. The current source test cited in the earlier comment does not cover this reported Python-language path closely enough to dismiss the confirmed reproduction.

## Change summary

With `editor.autoClosingBrackets` set to `beforeWhitespace`, typing an opening bracket before an existing non-whitespace character in a Python file still inserts the matching closing bracket.

## Best solution

Keep this in the editor auto-closing area and add a regression case that exercises the actual Python language configuration and `foo = |}` context, then trace why the language-aware auto-closing path differs from the existing synthetic test.
