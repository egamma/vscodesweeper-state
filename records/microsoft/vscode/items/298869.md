# Issue #298869 — Add pan, node selection, and export to Mermaid diagram preview

[https://github.com/microsoft/vscode/issues/298869](https://github.com/microsoft/vscode/issues/298869)

## Summary

Pan is now available on current main, including a visible pan-mode toggle, but node selection and image export remain real gaps in the bundled Mermaid viewer. Keep the broader request open and route it to the Mermaid chat area for a product decision on the remaining interactions.

## Change summary

Enhance Mermaid previews with drag-to-pan navigation, selectable nodes, and SVG, PNG, or clipboard image export.

## Best solution

Retain the existing pan controls and decide a coherent interaction model for selecting Mermaid nodes and exporting the complete rendered diagram from the bundled viewer. Coordinate the already-delivered pan behavior with https://github.com/microsoft/vscode/issues/293466 rather than treating that narrower issue as canonical for the remaining selection and export work.

## Plan brief

- **Likely files:** `extensions/mermaid-markdown-features/src/editorManager.ts`, `extensions/mermaid-markdown-features/src/extension.ts`, `extensions/mermaid-markdown-features/package.json`, `extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts`, `extensions/mermaid-markdown-features/preview-src/chat/index-editor.ts`
- **Validation:** Open a large Mermaid diagram generated in Chat in the full editor preview; verify existing pan and zoom remain functional, node activation produces the chosen visible selection/copy-or-reference behavior, and every approved export action produces a valid full-diagram file or clipboard image.
- **Behavior:**

  > Large Mermaid diagrams must remain navigable using the existing pan and zoom controls. A user should be able to activate a rendered node and receive a clear selection state with the maintainer-approved copy or Chat-reference behavior. The approved export actions must produce the complete rendered diagram, not a clipped screenshot, while preserving current copy-source and reset behavior.
- **Trace:**

  > The chat renderer opens diagrams through `MermaidEditorManager` in `extensions/mermaid-markdown-features/src/editorManager.ts`. Pan and zoom are already implemented by `PanZoomHandler` in `extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts` and wired to editor controls by `preview-src/chat/index-editor.ts`; this behavior must not regress. Commands and webview context-menu entries are declared in `package.json` and registered in `src/extension.ts`, where only reset, open, and copy-source operations currently exist. No node-selection or rendered-image export path is present. The older https://github.com/microsoft/vscode/issues/293466 owns only the pan symptom, not the remaining scope.
- **Open decisions:**
  - Should activating a Mermaid node only highlight it and expose its label for copying, or should it also create a structured reference that can be inserted into Copilot Chat?
  - Which export contracts should be supported initially: SVG, PNG, clipboard image, or all three?
  - Should export always capture the complete diagram, or should users also be able to export the currently transformed viewport?
