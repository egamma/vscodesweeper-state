# Issue #269581 — sed: command not found shows up when opening gitbash terminal

[https://github.com/microsoft/vscode/issues/269581](https://github.com/microsoft/vscode/issues/269581)

## Summary

Still reproduces on current main: the VSCODE_ENV_REPLACE/PREPEND/APPEND parsing in shellIntegration-bash.sh uses IFS=':' splitting, which corrupts PATH when Windows-format paths (containing colons) are injected via EnvironmentVariableCollections in Git Bash. Multiple community members confirm the issue. No fix has landed.

## Change summary

Opening a Git Bash terminal on Windows with extensions contributing to EnvironmentVariableCollections corrupts PATH via colon-based splitting of Windows paths, causing sed/uname/basename not found errors.

## Best solution

Fix the VSCODE_ENV_REPLACE/PREPEND/APPEND parsing in `shellIntegration-bash.sh` (lines 72–98) to handle Windows-style paths that contain colons — either use a different delimiter, detect the MINGW/MSYS environment and convert paths before splitting, or skip the env-var collection application when running under Git Bash with Windows-format paths. Issue #240539 is related (backslash escape sequences in the same code path) and should be addressed together.

- **Fix prompt:**

  > The bug is in src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh lines 72–98. The VSCODE_ENV_REPLACE, VSCODE_ENV_PREPEND, and VSCODE_ENV_APPEND variables are split on ':' using `IFS=':' read -ra ADDR <<< "$VAR"`. When running under Git Bash (MINGW/MSYS) on Windows, extension-contributed environment variable values contain Windows-format paths with colons (e.g. `PATH=C:\Windows\system32;C:\Program Files\...`), so the colon split incorrectly fragments them. This corrupts PATH, removing /usr/bin and /mingw64/bin, which makes sed, uname, and basename unavailable — and since the script itself uses sed (lines 228, 416), subsequent shell integration features also break. The fix should detect the MINGW/MSYS environment (e.g. check for MSYSTEM or MINGW_PREFIX being set) and either (a) use a different internal delimiter that doesn't conflict with Windows path colons, (b) convert Windows paths to POSIX format before the split, or (c) skip applying EnvironmentVariableCollections that would corrupt PATH in this environment. The fix must not change behavior on Linux/macOS where ':' is the correct PATH separator. Related issue https://github.com/microsoft/vscode/issues/240539 covers backslash escape handling in the same code path — be aware but don't conflate the fixes. Validate by simulating VSCODE_ENV_REPLACE with Windows-format PATH values in a MINGW bash and confirming PATH remains intact after sourcing the script.
