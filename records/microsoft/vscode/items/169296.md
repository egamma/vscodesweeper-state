# Issue #169296 — Render quick input separators as individual items instead of applying border to list item

[https://github.com/microsoft/vscode/issues/169296](https://github.com/microsoft/vscode/issues/169296)

## Summary

Keep open: ordinary quick pick separators still render on item rows, so independent section spacing and full-width separators remain missing. The request has maintainer support and is already correctly routed.

## Change summary

Render quick pick separators independently of selectable items so section boundaries can span the picker and provide breathing room around hover and focus states.

## Best solution

Give ordinary separators independent layout in the quick input list while preserving section actions, filtering, keyboard navigation, and accessibility. Agree on the vertical spacing for labelled and unlabelled sections before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** After agreeing on spacing, exercise a picker containing labelled, unlabelled, and button-bearing separators: verify full-width boundaries and independent spacing with hovered and keyboard-focused adjacent items. Add regression coverage in the quickinput browser suite for separate separator elements, filtering, selection exclusion, and button events; run that targeted suite during implementation.
- **Behavior:**

  > Ordinary quick pick separators currently inherit the layout of the following selectable item, constraining their width and section spacing. Section boundaries should span the quick pick and have independent vertical space so hovered or focused items do not crowd the border. Labelled, unlabelled, and button-bearing separators must retain their meaning without becoming selectable results. Acceptance includes visual checks of all three forms and preservation of filtering, keyboard navigation, and separator actions.
- **Trace:**

  > QuickInputList.setElements in src/vs/platform/quickinput/browser/quickInputList.ts creates QuickPickSeparatorElement only when buttons are present; other separators are stored on the following QuickPickItemElement. QuickPickSeparatorElementRenderer and QuickInputItemDelegate provide an existing standalone rendering path, but quickInput.css still draws the separator border on the padded entry. QuickInputList.filter restores inline separators onto visible items for unsorted results and deliberately omits separators for sorted search results. Preserve those filtering semantics, item selection, section-button events, and accessibility rather than expanding this into sticky-header work tracked at https://github.com/microsoft/vscode/issues/142704. The current trace establishes the rendering split; the remaining product uncertainty is the intended vertical spacing of labelled and unlabelled sections.
- **Open decisions:**
  - What vertical spacing should labelled and unlabelled standalone separators reserve, including their distance from adjacent hover and focus backgrounds?

## Evidence

- **Remaining capability gap:** src/vs/platform/quickinput/browser/quickInputList.ts:1112–1148, QuickInputList.setElements, skips standalone creation when a separator has no buttons and attaches it to the following QuickPickItemElement. Ordinary separators therefore still lack an independent layout row.
- **Partial existing capability:** QuickPickSeparatorElementRenderer in src/vs/platform/quickinput/browser/quickInputList.ts:626–681 already renders separators with buttons as separate elements; QuickInputItemDelegate gives those elements a height of 30. This conditional capability does not cover ordinary separators, and IQuickPickSeparator has no independent spacing option.
