# Issue #332258 — Disabling standalone MCP server should remove Disable (workspace) and Disable (Session) entries

[https://github.com/microsoft/vscode/issues/332258](https://github.com/microsoft/vscode/issues/332258)

## Summary

Traced on current main: disabling a standalone MCP server globally writes to the local `mcpService.enablementModel` (durable profile store), but the agent-host quick-pick/context-menu workspace and session toggles read `getCustomizationScopeEnablement(server)`, which is derived from the separate `server.enablement` (agent-host CustomizationEnablement) array — untouched by the local disable. So the labels/greying for Disable (Workspace)/Disable (Session) don't reflect the now-disabled server.

## Change summary

After disabling a standalone MCP server globally, its Disable (Workspace) and Disable (Session) context-menu entries still appear as if the server were enabled.

## Best solution

Sync the agent-host customization enablement state (or its derived presentation) with the local durable profile/workspace enablement model for standalone servers, or grey/hide the workspace and session toggle actions in getAgentHostMcpServerEnablementActions (src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts) and McpAgentHostServerOptionsCommand (src/vs/workbench/contrib/mcp/browser/mcpCommands.ts) whenever the local durable profile is disabled.
