# Issue #289091 — Add Context Usage Statistics to GitHub Copilot Session List

[https://github.com/microsoft/vscode/issues/289091](https://github.com/microsoft/vscode/issues/289091)

## Summary

A real gap remains: current main shows context usage only inside an opened chat, while session-list rows expose no usage data. No older issue with the same list-level request was found, so this re-reviewed request should remain open for product design.

## Change summary

Display context-window usage for each Copilot session in the session list so users can compare sessions without opening them individually.

## Best solution

Define a provider-neutral session usage summary and present it as a concise, accessible session-list indicator, with explicit semantics for inactive sessions and unavailable data.

## Plan brief

- **Likely files:** `src/vs/sessions/services/sessions/common/session.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts`
- **Validation:** Add a Sessions list browser test with multiple sessions asserting that available usage is rendered and updated per row, unavailable usage has the chosen fallback, and recycled rows do not retain another session's indicator.
- **Behavior:**

  > The session list should let users compare context consumption across sessions without opening each one. Every session with usable data shows a concise, accessible usage indicator whose meaning is consistent with the in-session context widget; sessions without usable data follow one defined fallback. Acceptance includes reactive updates and correct behavior when virtualized rows are reused.
- **Trace:**

  > The active-chat widget in `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts` computes usage from the latest response's prompt and completion tokens plus model context-window metadata. The provider-neutral `ISession` contract in `src/vs/sessions/services/sessions/common/session.ts` has no corresponding summary, and `AgentSessionAdapter` in `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts` does not project one. `SessionItemRenderer` in `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts` currently rebuilds the details row from workspace, diff, status, and time observables. Keep the list provider-neutral, avoid eagerly loading full transcripts for every row, preserve compact quick-chat and comparison rows, and do not change the existing in-session widget's semantics. https://github.com/microsoft/vscode/issues/287934 is related but does not own this list-level behavior.
- **Open decisions:**
  - Should each list row show the latest completed request's context-window percentage, matching the current widget, or cumulative session token/cost consumption?
  - When an inactive session lacks current model-window metadata or only has stale usage, should the list show the last-known value with a qualifier or omit the indicator?

## Evidence

- **existing capability:** The merged https://github.com/microsoft/vscode/pull/288921 added context usage only to the active chat input; current `ChatContextUsageWidget.update` in `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts` derives usage from the opened chat's latest request and response.
- **remaining source gap:** `ISession` in `src/vs/sessions/services/sessions/common/session.ts` exposes title, status, model, changes, and chat observables but no context-usage summary. `SessionItemRenderer` in `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts` renders workspace, diff statistics, status, and time without token or context-window usage.
- **provider boundary:** `AgentSessionAdapter` in `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts` projects Copilot sessions into the provider-neutral model but currently exposes no usage observable.
- **canonical search:** https://github.com/microsoft/vscode/issues/287934 is older and related to viewing session details, but it does not request the same reporter-observable behavior of comparing context usage directly in the session list; the stronger re-review duplicate bar is therefore not met.
