# Issue #325562 — Log Panel: Allow clicking `error` in AHP log to filter to errors

[https://github.com/microsoft/vscode/issues/325562](https://github.com/microsoft/vscode/issues/325562)

## Summary

The requested click-to-filter interaction is still missing: AHP error pills are passive labels, and the existing text filter does not reliably select all error entries. Keep this maintainer-authored Backlog request open; no verified canonical or referenced fix was found.

## Change summary

Allow activating the AHP log's error pill, and other appropriate pills, to filter the displayed entries.

## Best solution

Provide an accessible error-filter interaction in ChatDebugWireLogView that selects the same entries counted and styled as errors, while preserving log inspection and text search. Settle how pill filters compose with text search and how users clear them before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatDebug/chatDebugWireLogView.ts`
- **Validation:** Use an AHP log containing a successful response, a JSON-RPC error whose message lacks 'error', a ChatError action and a pending request. Verify mouse and keyboard activation of the error filter shows exactly the error-classified entries, clearing restores the list, text search follows the agreed composition semantics, and row expansion and live refresh continue to work.
- **Behavior:**

  > The AHP Log offers a direct, keyboard-accessible way to filter to errors by activating an error pill. The resulting list includes every entry represented by the error classification, even when its message does not contain the word 'error'. Users can clearly identify and clear the active filter. Existing text search, row inspection and live updates remain usable.
- **Trace:**

  > ChatDebugWireLogView in src/vs/workbench/contrib/chat/browser/chatDebug/chatDebugWireLogView.ts owns the summary chips, row status labels and filtering. renderSummary/appendChip create passive summary spans, while buildRow creates passive status spans inside an expandable header. computeVisible currently filters only through matchesFilter; isErrorEntry supplies the semantic classification used for both counts and row styling. A literal text search is therefore not equivalent to selecting errors. Preserve request/response pairing, pagination, lazy detail rendering and live refresh; this request does not require changing protocol capture or payload-content search. The related content-search request at https://github.com/microsoft/vscode/issues/325572 is separate. The remaining uncertainty is the user-visible relationship between pill selection, text search and clearing.
- **Open decisions:**
  - Should activating an error pill apply an independent filter combined with the current text search, or replace the current search?
  - Should activating an already selected pill clear its filter, or should clearing use a separate explicit control?
