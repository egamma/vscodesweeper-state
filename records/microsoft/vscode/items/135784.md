# Issue #135784 — [PWA] Register vscode.dev as file handler for well-supported file types

[https://github.com/microsoft/vscode/issues/135784](https://github.com/microsoft/vscode/issues/135784)

## Summary

Keep open: the inspected source supports opening local files through a browser picker, but does not provide the requested PWA file-handler registration or launch consumer. This team-authored Backlog request remains the canonical thread; the linked report was closed as its duplicate, not as implemented.

## Change summary

Allow the installed vscode.dev PWA to register for supported file types and open files directly from the operating system's file manager.

## Best solution

Provide browser-supported OS file associations for an agreed set of text/code formats, with launched files opening as editable local files in the web workbench. Establish the supported formats and launch-window behavior before implementation, and verify the deployed vscode.dev manifest as well as the shared workbench integration.

- **Behavior:**

  > An installed vscode.dev PWA can be selected from the operating system's file manager to open an agreed set of supported text/code files. Acceptance must cover launching with the PWA closed and already running, the agreed multi-file behavior, and unchanged picker-based workflows in browsers without File Handling support.
- **Trace:**

  > The checked-in resources/server/manifest.json has no file_handlers member, and tracked-source searches found no launchQueue consumer. WebFileSystemAccess in src/vs/platform/files/browser/webFileSystemAccess.ts supplies existing capability checks and handle guards, but these are not File Handling registration. The deployed vscode.dev manifest ownership and the appropriate launch lifecycle integration remain to be established; the shared OSS manifest alone cannot establish deployment behavior. Preserve existing local-file permissions, saving, and unsupported-browser behavior, and keep folder associations outside this request. https://github.com/microsoft/vscode/issues/143936 was explicitly consolidated into this issue, while the Monaco prototype linked in the discussion is only supporting feasibility evidence.
- **Open decisions:**
  - Which MIME types and file extensions should the installed PWA advertise initially: the desktop association set or a deliberately smaller web-supported set?
  - When files are launched while the PWA is already running, should they open in the existing workbench or a new window, and how should a multi-file launch be grouped?
