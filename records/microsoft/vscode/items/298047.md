# Issue #298047 — Using gh Auth for authentication 

[https://github.com/microsoft/vscode/issues/298047](https://github.com/microsoft/vscode/issues/298047)

## Summary

Keep this accepted authentication request open: the inspected Copilot sign-in path does not reuse GitHub CLI credentials, and the request has 36 community upvotes. The existing authentication-github label is appropriate; credential precedence and account-selection behavior need a maintainer decision.

## Change summary

Allow Copilot in VS Code to authenticate using existing gh authentication or supported token environment variables instead of requiring a separate sign-in.

## Best solution

Provide a supported credential-reuse path for Copilot that honors GitHub host, account selection, and extension authorization boundaries while preserving existing interactive sign-in. Establish how CLI and environment credentials interact with an already selected VS Code account before implementation.

## Plan brief

- **Likely files:** `extensions/github-authentication/src/flows.ts`, `extensions/github-authentication/src/githubServer.ts`, `extensions/github-authentication/src/github.ts`, `extensions/github-authentication/package.json`, `extensions/copilot/src/platform/authentication/vscode-node/session.ts`, `extensions/copilot/src/platform/authentication/vscode-node/authenticationService.ts`, `extensions/copilot/src/platform/authentication/vscode-node/copilotTokenManager.ts`
- **Validation:** In an isolated VS Code profile with no GitHub session and a valid gh-authenticated account entitled to Copilot, verify that the agreed credential-reuse flow enables a Copilot chat request without a separate browser login. Repeat with conflicting VS Code and CLI accounts, missing or invalid CLI credentials, and a different GitHub host; verify the agreed account precedence, visible failure behavior, and unchanged interactive fallback. Add automated coverage for credential selection and fallback in the authentication suites.
- **Behavior:**

  > A user already authenticated through gh can use that account for Copilot in VS Code without repeating browser authentication. The thread also requests reuse of supported token environment variables. Acceptance must establish which account is used when existing VS Code, CLI, and environment credentials disagree, and what the user sees when credentials are missing or rejected. Existing interactive sign-in must remain available, and credentials must stay bound to the intended GitHub host.
- **Trace:**

  > AuthenticationService.getGitHubSession in extensions/copilot/src/platform/authentication/vscode-node/authenticationService.ts delegates to the session helpers in session.ts, which use vscode.authentication account and session APIs. CopilotTokenManager._auth consumes the resulting session token; it does not discover CLI credentials. GitHubServer.login in extensions/github-authentication/src/githubServer.ts selects from getFlows in flows.ts, whose registered flows are browser OAuth, device code, and manual PAT entry. The manual PAT flow is not equivalent to automatic CLI reuse and is filtered out for supported GitHub.com clients. Preserve account identity checks, host separation, scope authorization, and interactive sign-in; do not assume that changing Copilot CLI session authentication alone satisfies regular Copilot Chat. The remaining uncertainty is the user-visible credential-selection and consent contract, not whether the inspected flow already reads gh credentials. The requested capability and community acceptance are recorded at https://github.com/microsoft/vscode/issues/298047.
- **Open decisions:**
  - When VS Code already has a selected GitHub account, should CLI or environment credentials be fallback-only, explicitly selectable, or take precedence?
  - Should reuse of external credentials require an explicit sign-in choice or consent, or occur automatically within the existing extension authorization flow?
  - Should the initial supported contract include token environment variables alongside gh authentication, and what precedence should apply when both are present?
