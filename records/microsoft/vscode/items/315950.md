# Issue #315950 — Gemini 3.1 Pro (Preview) bypassed VS Code tools and used the terminal

[https://github.com/microsoft/vscode/issues/315950](https://github.com/microsoft/vscode/issues/315950)

## Summary

Gemini 3.1 Pro (Preview) frequently chooses terminal shell redirects over the built-in Edit tool in agent mode, leading to out-of-band file modifications that bypass VS Code's undo stack. The original report (#296764) was closed after being understood as an approval-bypass issue, but this re-report clarifies it's a tool-selection/integration problem. Needs investigation by the agent behavior and tools teams to determine whether the root cause is model-side, tool-presentation-side, or both.

## Change summary

Gemini 3.1 Pro in agent mode prefers shell redirects to edit files instead of using the built-in Edit tool, causing out-of-band changes that can't be undone.

## Best solution

Investigate why Gemini 3.1 Pro selects terminal commands over the Edit tool — this may require adjusting how tools are presented to this model, adding model-specific prompting, or coordinating with Google on model behavior. The agent-behavior and chat-tools owners should reproduce and diagnose whether the Edit tool is failing silently (causing fallback) or the model simply prefers shell commands. If upstream, file with Google and track as upstream.
