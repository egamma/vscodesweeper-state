# Issue #332073 — Agent host: a Claude session shows nothing more once the parent resumes after a background subagent

[https://github.com/microsoft/vscode/issues/332073](https://github.com/microsoft/vscode/issues/332073)

## Summary

Confirmed on current main: `ClaudeSdkPipeline._processMessages` derives `turnId` from `this._queue.peekParent()`, and `ClaudeSdkMessageRouter.handle` silently drops any message once `turnId` is undefined — exactly as described, still present in `src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts` and `claudeSdkMessageRouter.ts`. An open PR already targets this, so this should stay open pending review/landing rather than being auto-fixed or closed.

## Change summary

After a Claude parent turn spawns a background subagent and its own turn ends, further parent output (and, per the comments, entire abandoned subagent turns) is silently dropped by the router instead of rendering, with no error logged.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/332075, which the author is running as a working patch for the primary case; the author's follow-up comments show the anchor-based fix doesn't cover window-restart or truly-abandoned-turn cases (tracked separately in https://github.com/microsoft/vscode/issues/333931 and https://github.com/microsoft/vscode/issues/333174), so a durable fix likely also needs a terminal/watchdog path for orphaned turns.
