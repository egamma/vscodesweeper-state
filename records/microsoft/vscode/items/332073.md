# Issue #332073 — Agent host: a Claude session shows nothing more once the parent resumes after a background subagent

[https://github.com/microsoft/vscode/issues/332073](https://github.com/microsoft/vscode/issues/332073)

## Summary

Verified against current main: `ClaudeSdkPipeline._processMessages` (src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts:679) derives `turnId` from `this._queue.peekParent()`, and `ClaudeSdkMessageRouter.handle` (claudeSdkMessageRouter.ts:74) silently returns when `turnId === undefined` — exactly the reported defect, with no logging on the drop path. An open PR (#332075) already carries the fix with `Fixes #332073`, so this should stay open until that PR lands rather than being closed now.

## Change summary

After a Claude agent-host parent turn spawns a background subagent and its own turn ends, every subsequent SDK message (parent output after the subagent resumes) is silently dropped by the router because `turnId` is undefined, so the chat stops rendering until the session is reopened.

## Best solution

Land https://github.com/microsoft/vscode/pull/332075, which anchors turnId-less messages to the turn that spawned the still-active background subagent (via a resume anchor on the subagent registry) instead of dropping them; that PR also supersedes the narrower fix in #331872.
