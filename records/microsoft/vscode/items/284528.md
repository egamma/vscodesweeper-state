- **Validation:** On current VS Code on Windows with extensions disabled, open a folder, hide the primary sidebar using View: Toggle Primary Side Bar Visibility, exit normally, and reopen the same folder. - **Behavior:**

  > The reporter hides Explorer, restarts VS Code, and finds Explorer visible again, including after upgrading from 1.105.1. Reopening the same workspace should retain the primary sidebar's previous visibility. Acceptance checks cover both hidden and visible states across a normal exit and restart, with extensions disabled; reload is a comparison case rather than a substitute for restarting.
- **Trace:**

  > In src/vs/workbench/browser/layout.ts, setSideBarHidden updates LayoutStateKeys.SIDEBAR_HIDDEN, whose storage scope is WORKSPACE. The onWillSaveState handler calls LayoutStateModel.save, and LayoutStateModel.load restores saved keys before applying defaults and overrides. Sidebar view-container restoration is gated by isVisible(Parts.SIDEBAR_PART). Source inspection establishes intended persistence but not which path fails for https://github.com/microsoft/vscode/issues/284528; diagnosis must distinguish failure to save or restore state from a later action making the sidebar visible. Preserve workspace-scoped behavior, visible-sidebar restoration, and intentional Zen Mode and auxiliary-sidebar overrides; a global always-hidden preference would not address the reported persistence defect.
