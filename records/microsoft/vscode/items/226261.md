# Issue #226261 — ERROR: unable to resolve text model content for notebook cell output

[https://github.com/microsoft/vscode/issues/226261](https://github.com/microsoft/vscode/issues/226261)

## Summary

The >500-output “show more” link still constructs a resource without an output identity, while the registered text provider requires one to locate the cell. Keep this bug open; the related open PR changes the display limit but does not repair the failing link.

## Change summary

Opening raw notebook output through the >500-output “show more” link fails with a text-model resolution error.

## Best solution

Make the overflow link reliably open the affected cell’s raw output, including outputs beyond the display limit, without changing output-rendering limits or unrelated cells. Evaluate the configurable-limit PR separately; raising the threshold does not resolve this defect.

- **Current provider cannot resolve that resource:** src/vs/workbench/services/notebook/common/notebookDocumentService.ts:69-97 parses the generated URI successfully and retains outputId as an empty string. CellInfoContentProvider registers provideOutputTextContent for this scheme in src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts:449-451; lines 612-623 search for a cell containing a matching outputId or alternativeOutputId and return null when none matches. For normally identified outputs, the overflow link therefore cannot produce a text model. This was traced in source without executing or modifying the checkout.
