# Issue #335388 — Copilot Chat: large streamed terminal output preview tanks UI performance/responsiveness

[https://github.com/microsoft/vscode/issues/335388](https://github.com/microsoft/vscode/issues/335388)

## Summary

Traced a concrete, real perf bug: the chat pane's live terminal-output mirror re-serializes and rewrites the entire buffer on every line-feed/cursor event with no cap on output volume, which explains the reported sluggishness/freeze for very large agent-run command output.

## Change summary

Running an agent terminal command with very large output (tens of MB) makes the inline chat terminal preview render everything and tanks VS Code's UI responsiveness.

## Best solution

Cap or throttle the live mirror in src/vs/workbench/contrib/terminal/browser/chatTerminalCommandMirror.ts (e.g. rate-limit `_scheduleFlush`/`_doFlushDirtyRange` and/or cap the amount of buffer content it serializes and writes per update) so the chat preview doesn't need to re-serialize and rewrite megabytes of VT text on every line-feed, mirroring the size cap already applied to the text sent to the model in outputHelpers.ts.

## Evidence

- **model-side truncation only:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/outputHelpers.ts truncateLargeOutput() caps text returned to the model at MAX_OUTPUT_LENGTH=20000 chars, but this only affects what's sent to the LLM, not what the terminal UI renders — matching the reporter's own observation.
- **mirror re-serializes whole buffer per event:** src/vs/workbench/contrib/terminal/browser/chatTerminalCommandMirror.ts _startStreaming() subscribes to onCursorMove/onLineFeed/onWriteParsed/onData and calls _handleCursorEvent -> _scheduleFlush -> _doFlushDirtyRange, which calls this._getCommandOutputAsVT(this._xtermTerminal) (full-buffer VT serialization) and writes the (possibly large) diff into a second detached xterm instance on essentially every terminal line — no size/line cap is applied before this work is scheduled, only a microtask-level dedup.
- **related-but-distinct issue:** https://github.com/microsoft/vscode/issues/316976 covers streaming rendering correctness (duplication/disappearing output) on Windows, a different symptom/root cause from this pure-performance report, so it is not treated as a duplicate canonical.
