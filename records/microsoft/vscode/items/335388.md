# Issue #335388 — Copilot Chat: large streamed terminal output preview tanks UI performance/responsiveness

[https://github.com/microsoft/vscode/issues/335388](https://github.com/microsoft/vscode/issues/335388)

## Summary

Traced a real perf bug in the chat terminal-preview mirror: on every streaming update it re-serializes the full command output range and writes it into a detached xterm even though only ~10 rows are ever shown, causing the O(n²) sluggishness/freezes reported for large outputs.

## Change summary

Running an agent tool-call terminal command with very large output makes the VS Code UI sluggish or frozen while the inline chat terminal preview streams.

## Best solution

In DetachedTerminalCommandMirror (src/vs/workbench/contrib/terminal/browser/chatTerminalCommandMirror.ts), bound the per-flush work to what the collapsed preview can actually show (MAX_OUTPUT_ROWS in chatTerminalToolProgressPart.ts) instead of re-serializing/writing the whole growing executedMarker→cursor range via getRangeAsVT on every onLineFeed/onWriteParsed/onData event; a maintainer should decide whether to throttle flush frequency, cap the serialized range, or both without breaking the expand-to-full-output view.

## Evidence

- **unbounded serialization:** xtermTerminal.ts getRangeAsVT() (around line 1056) serializes from startMarker to endMarker, and when no endMarker exists yet (mid-stream) end defaults to `this.raw.buffer.active.length - 1` — the entire buffer up to the current cursor, not a bounded window.
- **per-line re-serialize + write:** chatTerminalCommandMirror.ts _startStreaming() (line 633) wires onCursorMove/onLineFeed/onWriteParsed/onData to _handleCursorEvent → _scheduleFlush → _doFlushDirtyRange (lines 652-756), which calls _getCommandOutputAsVT (→ getRangeAsVT) and detachedRaw.write() on essentially every incoming output event, redoing full-range serialization repeatedly as output grows.
- **display is capped, serialization is not:** chatTerminalToolProgressPart.ts defines MAX_OUTPUT_ROWS = 10 (line 73) for the rendered preview box, but the mirror backing it is fed the unbounded VT text rather than a range sized to what's displayed.
