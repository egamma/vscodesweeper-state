# Issue #343201 — Git - View Stash does not show untracked files in folders

[https://github.com/microsoft/vscode/issues/343201](https://github.com/microsoft/vscode/issues/343201)

## Summary

The reported defect remains present in the current source: nested untracked files are assigned the wrong stash reference. Keep this open while the already-linked fixing PR is reviewed; it has not merged.

## Change summary

Show nested untracked files in View Stash when the stash includes untracked files.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/343202 so View Stash resolves both root-level and nested untracked files from the stash's third parent, while preserving tracked-file behavior.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/vscode/issues/343201 provides complete reproduction steps: stash a tracked change, top.txt, and src/feature/new.ts using --include-untracked, then open Git: View Stash. The nested file is omitted despite being counted, and its Git filesystem lookup uses the stash commit rather than its third parent.
- **Current source confirms the defect:** extensions/git/src/repository.ts:2676-2677 calls this.repository.lstree(ref) without recursive options. extensions/git/src/git.ts:1676-1690 builds git ls-tree -l and adds -r only when options.recursive is true, so nested untracked file paths are not enumerated.
- **Wrong-reference selection:** extensions/git/src/commands.ts:4754-4785, Commands._viewStash, compares each changed file's full path against getObjectFiles results. A nested file cannot match its containing directory entry, so modifiedUriRef becomes stash.hash instead of stashUntrackedFilesParentCommit, where that file actually exists.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/343202 was verified through the GitHub API as open with merged_at null. Its body explicitly references this issue with closing syntax, proposes recursive enumeration, and describes a regression test covering root-level and nested untracked files. That test was not executed during this read-only review.
