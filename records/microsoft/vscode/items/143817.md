# Issue #143817 — Allow for disabling certain languages from auto language detection

[https://github.com/microsoft/vscode/issues/143817](https://github.com/microsoft/vscode/issues/143817)

## Summary

Keep open: current settings can disable detection or favor familiar languages, but cannot exclude selected languages from detection results. This team-authored Backlog request remains a distinct capability gap, with supporting discussion and no verified older canonical.

## Change summary

Allow users to restrict automatic language detection to languages they use, excluding unwanted candidates such as CoffeeScript or Perl.

## Best solution

Provide an explicit candidate-language restriction in the language detection area, honored by both detection models without changing manual language selection. Settle the configuration contract and its scope across automatic detection, hints, and explicitly invoked detection before implementation.

Cover both model-preference settings, default unrestricted behavior, and explicit manual language selection; manually exercise an unsaved scratch editor with the configured restriction.
- **Behavior:**

  > Users can keep automatic language detection enabled while preventing selected unwanted languages from being chosen. Restrictions must apply regardless of which detection model is preferred, including when the excluded language would otherwise rank first. With no restriction configured, existing behavior remains unchanged, and users can still manually select an excluded language. Acceptance checks must include an eligible alternative and a case with no eligible detection result.
- **Trace:**

  > BaseTextEditorModel.doAutoDetectLanguage() in src/vs/workbench/common/editor/textEditorModel.ts gates detection using the current language, then requests detection without supportedLangs. LanguageDetectionService.detectLanguage() in src/vs/workbench/services/languageDetection/browser/languageDetectionWorkerServiceImpl.ts reads history and model-preference settings but no candidate-language configuration. LanguageDetectionWorker.$detectLanguage() in src/vs/workbench/services/languageDetection/browser/languageDetectionWebWorker.ts already accepts an optional supportedLangs restriction for neural and regexp detection; an empty list currently means unrestricted detection, which matters if a future restriction leaves no eligible candidates. Configuration lives in src/vs/workbench/browser/workbench.contribution.ts, while hints and an explicit detection command use the service from src/vs/workbench/contrib/languageDetection/browser/languageDetection.contribution.ts. Preserve existing explicit-language protections and manual language selection; this request does not require retraining models or changing filename associations. https://github.com/microsoft/vscode/issues/143910 concerns model precedence, and https://github.com/microsoft/vscode/issues/239991 provides related exclusion demand rather than a canonical replacement. The remaining uncertainty is the public configuration contract and whether restrictions also govern hints and explicitly invoked detection.
- **Open decisions:**
  - Should users configure excluded language IDs or an explicit allowed-language subset?
  - Should candidate restrictions apply only to automatic language switching, or also to language-detection hints and explicitly invoked detection?

## Evidence

- **Existing settings do not cover the request:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.editor.languageDetection, workbench.editor.historyBasedLanguageDetection, and workbench.editor.preferHistoryBasedLanguageDetection. The language-scoped enablement setting prevents switching away from the current language; it does not exclude that language as a detection result. History settings influence model weighting or precedence, not explicit candidate eligibility.
- **Current automatic detection path:** src/vs/workbench/common/editor/textEditorModel.ts, BaseTextEditorModel.doAutoDetectLanguage(), checks isEnabledForLanguage() against the current language and then calls detectLanguage(resource) without a candidate restriction. src/vs/workbench/services/languageDetection/browser/languageDetectionWorkerServiceImpl.ts forwards optional supportedLangs supplied by callers, but does not derive a restriction from user configuration.
- **Internal filtering is not a user-facing capability:** src/vs/workbench/services/languageDetection/browser/languageDetectionWebWorker.ts, LanguageDetectionWorker.$detectLanguage(), filters neural results through optional supportedLangs and passes that list to the regexp model. The normal text-editor automatic detection call does not supply this list, so this internal capability does not satisfy the request.
- **Discussion distinguishes exclusion from weighting:** https://github.com/microsoft/vscode/issues/143817#issuecomment-1049286222 explicitly distinguishes removing languages from consideration from merely weighting against them. https://github.com/microsoft/vscode/issues/143817#issuecomment-2276390655 describes JSON/JSONC snippets in unsaved editors being detected as CoffeeScript; another commenter also requests the feature.
