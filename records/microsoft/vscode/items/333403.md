# Issue #333403 — Remove Emmet from autocomplete for import statements

[https://github.com/microsoft/vscode/issues/333403](https://github.com/microsoft/vscode/issues/333403)

## Summary

Real, traceable defect: Emmet's location validation for JSX/TSX only backtracks for unescaped `<`/`>` characters and has no awareness of JS/TS string-literal contexts, so an import/require module-specifier string with no enclosing JSX tag is wrongly treated as a valid Emmet abbreviation location.

## Change summary

Emmet CSS/HTML abbreviation expansion fires inside import/require path strings in JS/TS(X) files, corrupting the import statement when accepted (e.g. `'#components/space'` expands into `<div id="components" /><space />`).

## Best solution

In extensions/emmet/src/defaultCompletionProvider.ts, extend the existing js/ts 'noise' filter (around the `abbreviation.startsWith('this.')` check) to also suppress completions when the abbreviation sits inside a string literal used as an import/require specifier, since isValidLocationForEmmetAbbreviation's tag-backtracking in abbreviationActions.ts has no concept of string literals.
