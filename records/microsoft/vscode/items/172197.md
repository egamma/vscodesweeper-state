# Issue #172197 — Make Portable mode easier to migrate to

[https://github.com/microsoft/vscode/issues/172197](https://github.com/microsoft/vscode/issues/172197)

## Change summary

Make transferring an existing VS Code installation's data and extensions into Portable mode easier than the documented manual procedure.

## Best solution

Provide an intentional, assisted migration path for an existing installation, distinct from enabling a fresh portable installation. Agree on the supported migration scope and entry point before implementation, preserving existing data and installation restrictions.

## Plan brief

- **Likely files:** `src/bootstrap-node.ts`, `src/vs/platform/environment/node/userDataPath.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfile.ts`, `src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts`
- **Validation:** After the migration contract is agreed, use an isolated existing installation containing identifiable settings, keybindings, snippets, extensions, and workspace state. Follow the assisted migration into a supported portable distribution, restart it, and verify the agreed data is present, portable storage is used, and the source installation remains intact; also check fresh portable startup and unsupported Windows installer distributions retain their existing behavior.
- **Behavior:**

  > Users migrating an existing VS Code installation to Portable mode currently must locate, copy, and rename data directories manually. The desired outcome is an assisted path that reduces those steps while retaining the agreed settings, extensions, and state. Enabling a fresh portable installation is not the requested change. Acceptance must verify migration into a supported portable distribution without damaging the original installation.
- **Trace:**

  > The current migration documentation at https://code.visualstudio.com/docs/setup/portable#_migrate-to-portable-mode still describes manual directory copying. configurePortable in src/bootstrap-node.ts detects an existing portable directory and configures environment variables; doGetUserDataPath in src/vs/platform/environment/node/userDataPath.ts then selects its user-data subdirectory. Profile export is exposed by workbench.profiles.actions.exportProfile in src/vs/workbench/contrib/userDataProfile/browser/userDataProfile.ts and implemented by UserDataProfileImportExportService in src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts, but it is not complete installation migration. The trace establishes storage selection and adjacent transfer facilities, not an existing migration orchestrator. Preserve fresh Portable mode behavior and supported-distribution restrictions. The unresolved boundary is what data the assisted operation promises to transfer and where users initiate it; https://github.com/microsoft/vscode/issues/172197 settles neither.
- **Open decisions:**
  - Should assisted migration preserve the complete user-data directory and installed extensions, including workspace/session state, or offer a narrower settings/profile transfer?
  - Should users initiate migration from the existing installation by choosing a portable destination, or from the portable installation by choosing an existing source?
