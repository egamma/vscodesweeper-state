# Issue #341050 — "npm" MCP Servers No Longer Found in Search Since Version 1.138

[https://github.com/microsoft/vscode/issues/341050](https://github.com/microsoft/vscode/issues/341050)

## Summary

Thanks for the detailed report. The source confirms that registry packages whose registryType is not one of the supported values are skipped, so "npx" and "uvx" entries are never offered. This looks like a deliberate move to strict registry-spec types, but I couldn't confirm that from a maintainer, so the issue stays open for a maintainer to decide.

## Change summary

Private-registry MCP servers with registryType "npx" or "uvx" no longer appear in the gallery since 1.138; only "npm" entries do.

## Best solution

A maintainer should decide whether to map common non-spec aliases (npx to npm, uvx to pypi) in toSupportedPackageRegistryType, or to keep strict spec types and document that. If strict, the unsupported-setup fallback could show these servers instead of silently dropping them.
