# Issue #58301 — Allow text-shadow to be used in themes

[https://github.com/microsoft/vscode/issues/58301](https://github.com/microsoft/vscode/issues/58301)

## Summary

Keep this accepted Backlog request open: supported theme-defined text shadows remain missing, and the thread demonstrates sustained demand with 68 upvotes. CSS injection and installation-file edits achieve the effect but do not provide a supported theme capability.

## Change summary

Allow themes to declare editor text shadows, including neon glow effects, without injecting CSS or modifying installed files.

## Best solution

Define a supported, opt-in editor-theming contract for text shadows so theme extensions can deliver the effect without patching VS Code. A maintainer should settle theme-wide versus token-specific styling and user override semantics before implementation, with unchanged default rendering and explicit performance and accessibility checks.

- **Behavior:**

  > Theme extensions should be able to produce editor text-shadow effects through a supported declaration rather than modifying VS Code's installation or injecting CSS. Themes without that declaration must retain existing rendering. Acceptance includes loading a minimal glow theme, switching between glow and ordinary themes without stale styling, and checking the agreed user-override behavior. The supported scope and parameter semantics require a product decision before these checks can become a precise contract.
- **Trace:**

  > The current token settings schema in src/vs/workbench/services/themes/common/colorThemeSchema.ts explicitly enumerates supported properties and rejects additional properties; text shadows are absent. In src/vs/editor/common/languages/supports/tokenization.ts, generateTokensCSSForColorMap and generateTokensCSSForFontMap generate existing color and font styling but no shadows. Theme interpretation in src/vs/workbench/services/themes/common/colorThemeData.ts and shared contracts in src/vs/platform/theme/common/themeService.ts are likely investigation points, not an established complete implementation boundary. The supplied discussion confirms that CSS-based effects are possible but currently depend on unsupported customization. Uncertainty starts at the public styling contract and its renderer, accessibility, and performance implications; https://github.com/microsoft/vscode/issues/95493 is related typography work, not a duplicate.
- **Open decisions:**

  - What shadow parameters should themes expose, and should users have a supported override or disable control independent of the active theme?
