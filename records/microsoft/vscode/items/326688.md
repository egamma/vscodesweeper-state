# Issue #326688 — Surface assisted permissions as built-in

[https://github.com/microsoft/vscode/issues/326688](https://github.com/microsoft/vscode/issues/326688)

## Summary

This team-authored feature request identifies a real transparency and customization gap in Assisted permissions. Current main exposes the permission mode but delegates risk classification to the Copilot SDK without surfacing its evaluator prompt, so the request should remain open and route to the Agent Host area.

## Change summary

Expose the Assisted permissions risk-evaluation prompt as a discoverable built-in customization that users can adapt for different projects.

## Best solution

Provide a documented, safely bounded built-in customization for Assisted permissions risk policy, with an explicit user/workspace or project scope. The design should also decide whether the same customization contract applies to Local Chat, as requested in the discussion.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionPermissions.ts`
- **Validation:** Add targeted Agent Host permission tests using the fake Copilot SDK boundary to assert that a scoped risk-policy customization reaches Assisted permissions without altering manual or allow-all modes; if Local Chat is included, add the equivalent harness test.
- **Behavior:**

  > Users can inspect the criteria used by Assisted permissions to evaluate tool-call risk and provide a supported override at the scope selected by maintainers. Different projects can apply different criteria without changing unrelated chat prompts. Manual permissions and Allow all retain their current behavior. The selected contract explicitly states whether Local Chat uses the same policy.
- **Trace:**

  > The Agent Host picker maps `assisted` to the Copilot provider in src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionPermissions.ts. CopilotAgentSession in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts translates that value to SDK permission mode `assisted`, sends it through `session.rpc.permissions.setMode`, and consumes SDK-generated recommendations and reasons; no evaluator prompt crosses the current host boundary. CopilotSessionLauncher separately builds the conversation system message and customization inputs, so that existing surface should not be assumed to control the permission classifier. The referenced test plan is https://github.com/microsoft/vscode/issues/326555. Preserve managed-policy restrictions and the semantics of manual and allow-all modes; uncertainty begins at the public customization and provider contract.
- **Open decisions:**
  - Should the editable risk policy be scoped per user, workspace/project, or both, and which scope wins when values differ?
  - Should users replace the complete evaluator prompt or only append constrained project-specific risk guidance?
  - Should one customization govern both Agent Host and Local Chat, or should the two harnesses expose separate policies?
