## Change summary

## Best solution

The fix likely needs either the tool layer to resolve an attachment snapshot path back to its originating workspace file before editing, or clearer signaling in the write-confirmation prompt that the target lives under agentSessionData rather than the workspace.

- **possible unsaved-editor inlining path:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:5716-5726 (_convertVariableToAttachment) and :5639 (_buildUnsavedEditorAttachment) inline a dirty/untitled file's live buffer as an EmbeddedResource for Copilot CLI/Codex (_backendInlinesUnsavedEditors, line 5624), which then always gets snapshotted to a real file under the attachments dir via agentService.ts's _writeAndRewrite (unconditionally rewritable per _isRewritableAttachment, line 3809-3811).
