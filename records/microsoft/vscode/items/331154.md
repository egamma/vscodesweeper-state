# Issue #331154 — Agent edited the generated attachment copy rather than the actual file in the workspace

[https://github.com/microsoft/vscode/issues/331154](https://github.com/microsoft/vscode/issues/331154)

## Summary

Traced this to a real defect in the agent-host attachment pipeline for path-reading backends (Copilot CLI / Codex): when the currently-open file is dirty/unsaved, the client inlines its live text as an `EmbeddedResource`, the Agent Host snapshots that blob to `{userDataPath}/agentSessionData/{session}/attachments/{id}/file_<name>`, and rewrites the attachment to a plain `Resource` pointing at that snapshot path — so the provider's `file` reference (`displayName: SKILL.md`, `path: .../attachments/.../file_SKILL.md`) no longer carries any link back to the real workspace file, and an edit tool call naturally lands on the snapshot copy instead.

## Change summary

Agent edited a session-attachment snapshot copy of the open SKILL.md file instead of the real workspace file.

## Best solution

In the unsaved-editor inlining path (agentHostSessionHandler.ts `_buildUnsavedEditorAttachment`) and/or the Agent Host attachment rewrite (`agentService.ts:_writeAndRewrite`/`_rewriteSingleAttachment`), preserve a pointer to the original workspace `file:` URI on the rewritten attachment (e.g. via `_meta`) so provider-specific converters like `copilotAgentSession.ts:_toSdkAttachment` can hand the agent the real workspace path for edits while still using the inlined text for up-to-date context — rather than silently substituting the session-attachments-folder path as the file's location.

## Evidence

- **snapshot + rewrite:** src/vs/platform/agentHost/node/agentService.ts `_isRewritableAttachment`/`_writeAndRewrite` (lines ~4133-4260): EmbeddedResource attachments are unconditionally written to `{sessionDataDir}/attachments/{uuid}/{basename}` and rewritten to a plain `Resource` attachment pointing at that snapshot, with no reference back to the original workspace URI.
- **provider consumption:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts `_toSdkAttachment` (lines ~2457-2477) forwards the rewritten Resource's `uri.fsPath` as the file `path` with `displayName: attachment.label` (the original basename) — giving the SDK a mismatched path/name pair that looks like the real file.
- **reporter confirmation:** https://github.com/microsoft/vscode/issues/331154#issuecomment (comment by DonJayamanne/jruales) confirms the open file was SKILL.md, matching the attachment basename `file_SKILL.md` seen in the reported snapshot path.
