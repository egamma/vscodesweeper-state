# Issue #294056 — MCPs that need to be started for a given prompt are auto-enabled

[https://github.com/microsoft/vscode/issues/294056](https://github.com/microsoft/vscode/issues/294056)

## Summary

The current source still allows newly discovered MCP tools to become enabled after a prompt explicitly selects no tools. Keep this team-authored report open: the startup-to-selection path supports the reported defect, and no qualifying fix or canonical duplicate was established.

## Change summary

Running a prompt with `tools: []` unexpectedly enables tools discovered when a previously unstarted MCP server starts.

## Best solution

Preserve a prompt's explicit tool selection when tools or toolsets register during MCP startup, including keeping `tools: []` empty. Maintain the normal defaults for unrestricted chat sessions; the less-specific Pylance observation should not expand the fix without separate confirmation.

McpLanguageModelToolContribution._syncTools in src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts registers discovered tools and lazily creates their toolset, allowing both to appear after the prompt selection was recorded.

A newly discovered MCP toolset therefore defaults on and enables its members despite the earlier empty selection. ChatWidget.getModeRequestOptions and ChatServiceImpl's request-tools autorun propagate updated tool selection to the request.
