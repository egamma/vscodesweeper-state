# Issue #172378 — define a key as ctrl at windows, cmd at macos

[https://github.com/microsoft/vscode/issues/172378](https://github.com/microsoft/vscode/issues/172378)

## Summary

The requested portable modifier is still missing from user keybindings: internal CtrlCmd support does not expose an equivalent key name in keybindings.json. Keep the existing keybindings/under-discussion classification; the older related request concerns selecting another platform's keymap, not the same observable capability.

## Change summary

Allow one user-defined keybinding to use Command on macOS and Control on Windows and Linux through a portable modifier name.

## Best solution

Consider a portable modifier in the user-keybinding syntax that preserves existing literal ctrl/cmd behavior and avoids duplicating command and when clauses. This needs a keybindings-owner product decision rather than treating internal CtrlCmd or extension-manifest platform overrides as existing coverage.

- **Current user-keybinding parser:** src/vs/workbench/services/keybinding/common/keybindingIO.ts, KeybindingIO.readUserKeybindingItem, passes the key string directly to KeybindingParser.parseKeybinding. In src/vs/base/common/keybindingParser.ts, _readModifiers recognizes ctrl, shift, alt, meta, win and cmd; ctrl sets the Control flag and cmd sets the Meta flag. No primary or CtrlCmd modifier is recognized.
- **Existing capabilities do not cover the ask:** src/vs/base/common/keybindings.ts, createSimpleKeybinding, maps the internal numeric CtrlCmd flag to Meta on macOS and Control elsewhere. Separately, src/vs/workbench/services/keybinding/browser/keybindingService.ts supports mac/linux/win overrides through the extension contribution path in _asCommandRule and bindToCurrentPlatform. Neither provides a portable modifier token in user keybindings.json; the reporter's conditional pair remains a workaround.
