# Issue #209552 — Git - beyond a symbolic link error

[https://github.com/microsoft/vscode/issues/209552](https://github.com/microsoft/vscode/issues/209552)

## Summary

The current Git ignore-check path still propagates the reported error for descendants of directory symlinks. Keep this accepted, team-authored bug open; the newer matching report cannot replace it under the re-review rules.

## Change summary

Prevent Git ignore checks on paths beneath directory symlinks from producing extension-host errors.

## Best solution

Define how Git decorations and quick diff should treat resources reached through directory symlinks, then prevent unsupported path checks without hiding genuine Git failures or losing ignore results for unrelated files.

## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/decorationProvider.ts`, `extensions/git/src/quickDiffProvider.ts`, `extensions/git/src/test/smoke.test.ts`
- **Validation:** Add an extension-host Git regression check using a disposable repository with a directory symlink, a file beneath that link, and an ordinary ignored file. Exercise Repository.checkIgnore and decoration requests together: the symlink case must follow the chosen policy without the reported error, the ordinary file must retain its ignore result, and unrelated Git failures must remain observable. Repeat with a quick-diff request for the symlink descendant.
- **Behavior:**

  > Browsing a repository containing directory symlinks can cause the built-in Git extension to report a fatal 'beyond a symbolic link' error for files reached through those links. These resources should receive a defined decoration and quick-diff treatment without recurring errors from unsupported Git probes. Ordinary files in the same request must retain correct ignore results. Genuine Git failures must remain visible rather than being indiscriminately suppressed.
- **Trace:**

  > Repository.checkIgnore in extensions/git/src/repository.ts submits all repository-descendant paths to git check-ignore -v -z --stdin and rejects the entire operation on the reported exit code 128. GitIgnoreDecorationProvider.checkIgnoreSoon in extensions/git/src/decorationProvider.ts logs that rejection and rejects every queued request, including requests for unrelated paths. The reporter's NUL-delimited stdout matches this command's output format, confirming the source path without execution. GitQuickDiffProvider in extensions/git/src/quickDiffProvider.ts checks the resource's own symbolic-link flag but not its ancestors before using the same ignore-check API. The boundary is read-only Git resource handling; preserve staging, repository discovery, and genuine error diagnostics. https://github.com/microsoft/vscode/issues/305699 corroborates the symptom in a newer pnpm setup, while https://github.com/microsoft/vscode/issues/38365#issuecomment-344525129 records why blanket diagnostic suppression is unsuitable. The remaining uncertainty is the intended resource behavior beneath directory symlinks, not whether the current error path exists.
- **Open decisions:**
  - Should Git decorations and quick diff omit resources beneath directory symlinks, evaluate the link boundary, or use the resolved target when it belongs to the same repository?
