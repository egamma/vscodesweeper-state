## Evidence

- **Long-command defect on main:** src/vs/workbench/api/node/extHostTunnelService.ts:108–115 returns false immediately for commands longer than 500 characters. Consequently, the reported 549-byte server command bypasses the existing out/server-main.js exclusion.
- **Agent-host defect and candidate flow:** The same helper recognizes neither /vscode/bin/ nor out/bootstrap-fork. At lines 143–144, findPorts adds a socket-mapped process when this helper returns false; findCandidatePorts reads /proc command lines and calls findPorts. The reported Codespaces agent-host signature therefore remains eligible. This was traced read-only, without executing VS Code.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/346720 references this issue and proposes removing the length cutoff and extending process exclusions. Its review at https://github.com/microsoft/vscode/pull/346720#discussion_r4499820870 identifies missing independent bootstrap-fork coverage; the proposed changes are not present in the checkout.
- **Existing discussion and workaround:** https://github.com/microsoft/vscode/issues/346711 supplies concrete process signatures and an ignore-pattern workaround. The automated upgrade suggestion does not confirm resolution, and configurable ignores do not repair the built-in self-exclusion behavior.
