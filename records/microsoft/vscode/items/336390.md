# Issue #336390 — Expanded Codex support in the agent host does not work

[https://github.com/microsoft/vscode/issues/336390](https://github.com/microsoft/vscode/issues/336390)

## Summary

Confirmed, actively-diagnosed bug: Codex/ChatGPT-subscription models can't populate until the Codex harness is selected, but the harness picker won't let you select it until models are already visible — a deadlock traced to getSessionTypeAvailability in sessionTypeAvailability.ts. No fix has landed yet, so this correctly stays open.

## Change summary

With only a ChatGPT subscription (or Copilot Free) signed in, the Codex harness is greyed out / shows an Upgrade prompt in both the Chat sidebar and the Agents window, and only a manual command workaround unlocks it for the current session.

## Best solution

Redesign getSessionTypeAvailability (and the model-loading trigger it depends on) so Codex/ChatGPT-subscription models are checked or pre-loaded without requiring the harness to already be selected — the maintainer (Giuspepe) has already scoped the root cause and workarounds in the thread; a follow-up PR should close the loop.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/sessionTypeAvailability.ts`, `src/vs/sessions/contrib/chat/browser/sessionTypePicker.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts`
- **Validation:** A test in sessionTypeAvailability (or an integration test covering the Codex harness) asserting that a ChatGPT-subscription-only (no Copilot models) or Copilot-Free user sees the Codex harness as Available/selectable without first invoking the manual workaround command.
- **Behavior:**

  > A user signed into only a ChatGPT subscription (or a Copilot Free account plus ChatGPT) should see the Codex harness as selectable in both the Chat sidebar and the Agents window on first launch, without needing to run a manual command or restart. After selecting it, ChatGPT-provided models should load and persist across a VS Code restart, not just for the current session.
- **Trace:**

  > getSessionTypeAvailability (src/vs/workbench/contrib/chat/browser/agentSessions/sessionTypeAvailability.ts:79-113) gates availability on hasAnyModelTargetingSessionType(languageModelsService, type), but Codex models are only registered with languageModelsService after the harness has actually been used once — creating a chicken-and-egg lock described by Giuspepe in the issue thread. Do not change the SignInRequired / BYOK signed-out paths, which work correctly per the same function's other branches; the fix must specifically address how ChatGPT-subscription-backed models are detected or lazily surfaced before first harness selection, and how that state persists across a restart (comment 8 notes the fix currently only lasts for the running session).
- **Open decisions:**
  - Should Codex/ChatGPT-subscription model availability be probed eagerly (e.g. a lightweight capability check) instead of waiting for full model registration, and if so at what point in startup?
  - Should Copilot Free users see Codex as Available/NoModels rather than UpgradeRequired when a ChatGPT subscription alone can supply models?
  - Should the harness-selected state (and its unlocked models) persist across restarts, or should it be re-derived from account state each launch?

## Evidence

- **maintainer diagnosis:** Comment by Giuspepe (CONTRIBUTOR) on 2026-09-17 explicitly confirms this as a bug: 'we deliberately wait until you explicitly choose to use it before loading models... That creates a deadlock: you need to select Codex to load the models, but you can't select it because the models haven't loaded.'
- **source trace:** src/vs/workbench/contrib/chat/browser/agentSessions/sessionTypeAvailability.ts:79-113 getSessionTypeAvailability returns UpgradeRequired/NoModels based on hasAnyModelTargetingSessionType(languageModelsService, type) — which is only populated after the harness has been used once, matching the reported deadlock exactly.
- **no fix on main:** git log on sessionTypeAvailability.ts / sessionTypePicker.ts / agentHostChatInputPicker.ts shows no commit addressing this since the report; still reproducible on current main.
- **multiple confirmations:** Comments from bgriffith, njoubert, dingwen07, MtkN1 all corroborate the same symptom across different account/entitlement combinations (ChatGPT-only, Copilot Free + ChatGPT, GitHub signed-in vs signed-out).
