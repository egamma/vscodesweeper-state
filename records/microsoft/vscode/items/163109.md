# Issue #163109 — Merge Editor: Give an option to allow to use checkboxes

[https://github.com/microsoft/vscode/issues/163109](https://github.com/microsoft/vscode/issues/163109)

## Summary

Keep open: current source retains a hidden checkbox toggle, but does not provide the requested supported switch between checkboxes and text actions. The request has 40 upvotes, and a maintainer explicitly consolidated another report into this issue.

## Change summary

Provide an option to use checkbox-based conflict resolution instead of text-based actions in the three-way merge editor.

## Best solution

Settle whether checkbox-based resolution should become a supported presentation option, preserving the default text-action experience and access to all merge states. If accepted, make the option discoverable and ensure users can accept and undo either input without losing smart-combination, ordering, or manual-resolution controls.

- **Behavior:**

  > Users want an optional checkbox-based presentation for the three-way merge editor, with clear per-input acceptance state and reversible selection in the input panes. The existing text-action presentation should remain the default. Acceptance must cover selecting and deselecting either side, both-input combinations, ordering, and manually edited results without losing necessary actions. The maintainer must first decide which text actions remain visible in checkbox mode and whether this becomes a supported, discoverable preference.
- **Trace:**

  > CodeEditorView reads mergeEditor.showCheckboxes as an unregistered setting; InputCodeEditorView uses it to create gutter items, and MergeConflictGutterItemView already maps input states to checkbox icons and accept/undo behavior. MergeEditor.setViewZones nevertheless passes codeLensesVisible: true, and ViewZoneComputer creates text-action rows from that flag, so the historical mergeEditor.showCodeLenses workaround is not wired into the current path. mergeEditor.contribution.ts does not register either presentation setting. The uncertain boundary is the public presentation contract, not how to connect these existing components: the maintainer documented eight merge states at https://github.com/microsoft/vscode/issues/163109#issuecomment-1278955426. Preserve merge algorithms, default text actions, and the distinction between smart combination and ordered concatenation. https://github.com/microsoft/vscode/issues/162871 was explicitly consolidated into this issue; https://github.com/microsoft/vscode/issues/159029 is related accessibility work, not a duplicate.
- **Open decisions:**
  - Should checkbox-based resolution become a supported, discoverable preference, rather than remain an unsupported hidden setting?
  - In checkbox mode, should text actions disappear from the input panes only, remain alongside checkboxes, or be replaced elsewhere while retaining ordering, smart/non-smart combination, and manual-resolution controls?

Checkboxes therefore remain available in source, but this alone does not provide a supported alternative presentation.
