# Issue #335227 — When using custom endpoints, virtual tools cause the model to fail to accurately discover the tools

[https://github.com/microsoft/vscode/issues/335227](https://github.com/microsoft/vscode/issues/335227)

## Summary

Real, unaddressed gap for BYOK/custom-endpoint users: virtual-tool grouping and its (mostly fixed-model) naming pipeline don't adapt well to large arbitrary MCP toolsets, and tool-search plus manual group tuning aren't exposed for custom endpoints — but there's no maintainer response or community signal yet, and the fix requires product decisions rather than a bounded patch.

## Change summary

For custom/BYOK endpoint models with large MCP toolsets, virtual-tool grouping produces inaccurate group names/categorization and the reporter can't enable tool-search or manually adjust groups to compensate.

## Best solution

A maintainer should decide whether tool-search (extensions/copilot/src/extension/tools/node/toolSearchTool.ts, gated via modelSpecificToolApplies in vscode-node/toolsService.ts) should be extendable to custom/BYOK endpoints, and whether the fixed 'copilot-utility-small' categorization endpoint in virtualToolGrouper.ts needs a fallback strategy for large heterogeneous toolsets; in the meantime the existing `chat.virtualTools.threshold` setting (settable to 0) is a workaround worth surfacing to the reporter.

## Evidence

- **fixed naming model:** virtualToolGrouper.ts hardcodes CATEGORIZATION_ENDPOINT = 'copilot-utility-small' for describeBulkToolGroups (virtualToolSummarizer.tsx) — group names/descriptions are generated by a fixed small internal model regardless of the user's selected custom endpoint, so quality issues stem from the clustering/naming pipeline itself, not just the chosen chat model.
- **tool-search gating:** toolsService.ts (vscode-node) gates the ToolSearchTool via modelSpecificToolApplies(definition, endpoint), consistent with the report that tool-search isn't exposed for arbitrary custom endpoints.
