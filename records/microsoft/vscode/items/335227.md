# Issue #335227 — When using custom endpoints, virtual tools cause the model to fail to accurately discover the tools

[https://github.com/microsoft/vscode/issues/335227](https://github.com/microsoft/vscode/issues/335227)

## Summary

Fresh, well-diagnosed report with real code-level roots: virtual-tool categorization quality depends on the connected model, and the tool_search tool is gated to a hardcoded allowlist of Copilot-native model families that excludes BYOK/custom endpoints — worth keeping open for the chat/tools team to weigh in on.

## Change summary

With a custom/BYOK endpoint and a large (100+) MCP tool set, virtual-tool grouping produces inaccurate group names/descriptions and mis-categorizes tools, and there's no way to enable tool_search or manually adjust groups for custom-endpoint models.

## Best solution

Two distinct asks likely belong together in the tools/virtualTools area: (1) reconsider or make configurable the ToolSearchTool model-family allowlist in extension/tools/node/toolSearchTool.ts so tool_search can be enabled for BYOK/custom models, and (2) improve or document the fallback when the connected model's own categorization quality (VirtualToolGrouper) is poor — e.g. surfacing github.copilot.chat.virtualTools.threshold as a documented escape hatch for users who want to disable grouping entirely.

## Evidence

- **tool_search allowlist:** extensions/copilot/src/extension/tools/node/toolSearchTool.ts hardcodes a list of eligible model families (gpt-5.4/5.5/5.6-*, claude-* families) for the ToolSearchTool — custom/BYOK endpoint models are not in this list, so tool_search cannot be used with them, matching the report's step 6.
- **grouping is model-driven:** extension/tools/common/virtualTools/virtualToolGrouper.ts (VirtualToolGrouper) performs categorization; naming/grouping quality is generated via the connected model, so a smaller/different custom-endpoint model naturally produces worse categorizations than Copilot's own models — this is inherent to the design, not an obvious code bug.
- **possible workaround exists but undocumented for this use case:** platform/configuration/common/configurationService.ts defines ConfigKey.VirtualToolThreshold (github.copilot.chat.virtualTools.threshold); toolGrouping.ts's computeToolGroupingMinThreshold maps a value <= 0 to Infinity, which would disable virtual-tool grouping altogether — but this only avoids grouping, it doesn't fix categorization quality or enable tool_search for custom models.
