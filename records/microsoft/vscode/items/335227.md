# Issue #335227 — When using custom endpoints, virtual tools cause the model to fail to accurately discover the tools

[https://github.com/microsoft/vscode/issues/335227](https://github.com/microsoft/vscode/issues/335227)

## Summary

Verified duplicate: the older open issue tracks the same user-visible failure where large MCP tool catalogs are hidden behind inaccurate or incomplete virtual discovery, leaving the model unable to find the required tool.

## Change summary

Custom-endpoint models fail to discover appropriate MCP tools when a large tool catalog is collapsed into inaccurate generated virtual-tool groups.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/319330 and ensure every tool in a large MCP server remains semantically discoverable through either tool search or accurate `activate_*` groups, including for custom endpoints. Preserve this report's `list_issues` misclassification as a concrete validation case.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/319330 is open, predates this report, and describes the same observable symptom: with 100+ tools from one MCP server, virtualization exposes only a misleading subset through `tool_search` or `activate_*` groups, preventing the model from finding the needed tools.
- **same product path:** Both reports concern semantic discovery within a large MCP catalog rather than tool execution itself. This report adds the custom-endpoint case and the specific example that `list_issues` appears under repository management, but that evidence fits the canonical issue's broader requirement that all registered tools be accurately discoverable.
- **current source:** extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts bypasses virtual grouping only when `endpoint.supportsToolSearch` is true; otherwise it invokes ToolGrouping. extensions/copilot/src/extension/tools/common/virtualTools/virtualToolGrouper.ts clusters MCP tools using embeddings and generates each `activate_*` name and description through `describeBulkToolGroups`, matching the reported failure path.
- **custom endpoint capability routing:** extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts derives `supportsToolSearch` from endpoint metadata or `modelSupportsToolSearch`, while extensions/copilot/src/platform/endpoint/common/chatModelCapabilities.ts recognizes supported model families and permits a per-model family override. Endpoints outside that recognized path continue through virtual grouping, so the custom-endpoint detail should be retained on the canonical issue.
