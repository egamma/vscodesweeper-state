# Issue #317422 — Can't Re-Open Different Projects Easily in VS Code

[https://github.com/microsoft/vscode/issues/317422](https://github.com/microsoft/vscode/issues/317422)

## Summary

Keep open for a product decision about a curated project list independent of recent history. VS Code already restores workspace tabs, but the inspected project-opening surface does not provide the separate list the reporter explicitly requests.

## Change summary

Provide an in-app list of selected projects that reopens each project's saved editor tabs without relying on recent history.

## Best solution

Decide whether curated project selection should be part of the existing workspace-opening UI, while retaining the existing workspace-scoped editor restoration. Consider the related recent-item pinning request without treating pinning within history as automatically equivalent to a separate project list.

- **Existing project-opening capability:** src/vs/workbench/browser/actions/windowActions.ts registers workbench.action.openRecent. BaseOpenRecentAction.run builds a searchable picker from recently opened folders, workspaces, files, and unsaved-workspace backups, then opens the selected workspace. Its item controls do not provide favorites or a separate curated project collection.
- **Existing tab restoration:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.editor.restoreEditors with default true. src/vs/workbench/browser/parts/editor/editorPart.ts stores and reloads editor UI state through a workspace-scoped memento.
