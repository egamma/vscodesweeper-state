## Evidence

- **reporter confirmation:** https://github.com/microsoft/vscode/issues/295255 provides explicit steps using `man man` on macOS, reports the first Option-click blanks the pager, and distinguishes clicks from successful Option-drag selection. The reporter subsequently confirmed the same failure on 1.109.3 with extensions disabled.
- **current VS Code integration:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts registers `terminal.integrated.altClickMovesCursor` with default true and `terminal.integrated.macOptionClickForcesSelection` with default false. src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts passes both options into xterm.js and updates them when configuration changes. These settings expose the competing behaviors but do not prove the reported blanking is fixed.
- **upstream input path:** https://github.com/xtermjs/xterm.js/blob/master/src/browser/services/SelectionService.ts implements `_handleMouseUp`: a short Alt-click with at most one selected character and `altClickMovesCursor` enabled calls `moveToCellSequence` and emits the resulting input. https://github.com/xtermjs/xterm.js/blob/master/src/browser/input/MoveToCell.ts explicitly generates vertical and horizontal arrow sequences for the alternate buffer. This explains why the first click can affect a running pager whereas dragging a longer selection does not; the exact bundled behavior and pager response were not executed.
