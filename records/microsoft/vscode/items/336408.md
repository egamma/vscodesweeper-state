# Issue #336408 — Testing: automatic result eviction leaves extension-host run trackers retained

[https://github.com/microsoft/vscode/issues/336408](https://github.com/microsoft/vscode/issues/336408)

## Summary

Traced and confirmed on current main: the automatic history-eviction path in TestResultServiceImpl.push() disposes the evicted result but never fires the `removed` change event, so the extension host never learns to release its run tracker. An open PR (https://github.com/microsoft/vscode/pull/336409) already targets this exact gap, so the issue should stay open pending review/merge of that PR rather than being auto-fixed here.

## Change summary

When automatic test-result history eviction removes an old result, the extension host is never notified, so it keeps the corresponding run tracker alive indefinitely.

## Best solution

Land (or a maintainer reviews) https://github.com/microsoft/vscode/pull/336409, which adds the missing `changeResultEmitter.fire({ removed: [removed] })` call to the ordinary eviction branch in testResultService.ts so mainThreadTesting.ts can forward `$disposeRun` and extHostTesting.ts can release the tracker.
