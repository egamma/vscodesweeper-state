# Issue #336408 — Testing: automatic result eviction leaves extension-host run trackers retained

[https://github.com/microsoft/vscode/issues/336408](https://github.com/microsoft/vscode/issues/336408)

## Summary

Confirmed on main: TestResultServiceImpl.push() disposes an evicted result's DisposableStore but never fires the `removed` change event that the ordinary clear() path does, so the extension host's run tracker is never released. An open PR (#336409) already fixes this — the issue should stay open until it merges.

## Change summary

Automatic test-result history eviction disposes the renderer-side result without notifying the extension host, leaving run trackers retained in extHostTesting's request/run-ID maps.

## Best solution

Land the linked PR https://github.com/microsoft/vscode/pull/336409, which makes the eviction branch in push() fire `changeResultEmitter({ removed: [removed] })` like clear() already does, so mainThreadTesting can forward `$disposeRun` and extHostTesting can release the tracker.
