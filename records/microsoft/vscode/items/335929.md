# Issue #335929 — Setting `permissions.ask` breaks all auto-allow settings in all GitHub Copilot Harnesses

[https://github.com/microsoft/vscode/issues/335929](https://github.com/microsoft/vscode/issues/335929)

## Summary

A maintainer has already investigated this and added an explicit 'Current scope' note to the issue body stating that external managed-rule presence (even an empty `ask` list) intentionally activates default-ask today, that the unrelated client-injection fix doesn't change this path, and that this should stay open to track the desired cross-client semantics — so this must not be closed as resolved.

## Change summary

Setting any `permissions.ask` value (including an empty list) in enterprise managed-settings.json causes GitHub Copilot clients (CLI, App, VS Code) to prompt for approval on every action, overriding all local auto-approve settings and removing 'allow for session' options.

## Best solution

Design and document the intended cross-client semantics for managed-rule presence vs. an empty ask list (should an empty list mean 'no additional asks' rather than 'ask for everything'), coordinated with the Copilot SDK/managed-settings owners — the current default-ask-on-presence behavior is acknowledged as unintuitive but is not yet a settled decision.
