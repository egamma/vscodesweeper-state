## Evidence

Its discussion contains independent confirmations.
- **Current source explains the discrepancy:** In extensions/git/src/commands.ts:1300-1326, CommandCenter.openFile converts an explicitly supplied git URI to a working-file URI. With no argument, it calls getSCMResource and, when that returns nothing, uses the active editor's document URI unchanged. getSCMResource at lines 5710-5746 only returns files present in working-tree, index, or merge resource groups; after committing, those entries can be absent. The fallback therefore retains a git revision URI, whose provider is registered with isReadonly: true in extensions/git/src/fileSystemProvider.ts:57.
- **Matching toolbar command:** extensions/git/package.json:2752-2768 registers git.openFile in editor/title for Git diff editors and Git revision editors. The canonical's reproduction names this exact command and distinguishes toolbar invocation from argumentless keybinding invocation.
