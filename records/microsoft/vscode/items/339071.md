# Issue #339071 — New sessions created from a custom group are not kept in that group

[https://github.com/microsoft/vscode/issues/339071](https://github.com/microsoft/vscode/issues/339071)

## Summary

Team-authored bug with a clear, well-diagnosed trace, and an open PR (#339105) already fixing it — per policy this stays open for the linked PR to land, not for a close or auto-fix.

## Change summary

A session created via 'New Session' from a custom group's header no longer stays in that group; it falls back to normal workspace/date grouping because a provisional session is now published (via onDidChangeSessions, added by #337741) before durable group membership is applied.

## Best solution

Review and land the linked PR https://github.com/microsoft/vscode/pull/339105 ('sessions: Preserve custom group for starting sessions'), and consider adding an integration test covering custom-group placement during the provisional-publication interval, as the reporter notes none exists.
