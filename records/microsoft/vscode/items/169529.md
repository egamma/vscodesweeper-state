# Issue #169529 — Parts that are hidden should not render DOM nodes

[https://github.com/microsoft/vscode/issues/169529](https://github.com/microsoft/vscode/issues/169529)

## Summary

The issue remains valid: hidden or disabled workbench parts (e.g. titlebar in native mode, hidden activity bar) still render full DOM trees. The NativeTitlebarPart class exists but extends BrowserTitlebarPart and creates content DOM; `setViewVisible(false)` in the grid only hides by collapsing the split-view size to 0, keeping all DOM nodes. Team-authored (CONTRIBUTOR), On Deck milestone — keeping open.

## Change summary

Hidden or disabled workbench parts (titlebar, activity bar, status bar, etc.) should not render DOM nodes at all, to avoid unnecessary style recalcs and improve resize/layout performance.

## Best solution

Implement lazy DOM creation for parts that can be hidden: defer `createContentArea` until the part becomes visible, or remove DOM nodes on hide for parts unlikely to toggle often (native titlebar being the most impactful). The grid's `setViewVisible` should be complemented by a part-level mechanism that avoids rendering. The sbatten comment in the thread already outlined the right approach — a lightweight NativeTitlebarPart that provides the ITitleService interface without the full DOM. The broader pattern (activity bar, status bar, etc.) would follow the same principle.
