# Issue #327635 — Testing: We should proactively move VS Code pet when ask user question tool is shown

[https://github.com/microsoft/vscode/issues/327635](https://github.com/microsoft/vscode/issues/327635)

## Summary

A real interaction gap remains: the pet reacts when a question needs input but does not horizontally avoid the question carousel's Submit control. This team-authored request should stay open for behavior design and implementation.

## Change summary

Move the VS Code pet out of the way when an ask-user question UI would otherwise be obscured.

## Best solution

Keep question-carousel controls unobstructed by automatically placing the pet in a safe available area while input is required, without losing the user's chosen resting position.

- **Behavior:**

  > When an ask-user question appears, the pet must not cover its Submit button or other interactive footer controls. If the current pet position conflicts, it moves to an available safe position; reduced-motion mode reaches the same unobstructed result without spatial animation. Dismissing or answering the question must leave subsequent manual pet positioning predictable. Acceptance includes collision, dismissal, constrained-width, and reduced-motion cases.
- **Trace:**

  > The question carousel creates its right-aligned Submit button in `ChatQuestionCarouselPart.renderFooter` and `renderSingleQuestionFooter` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts. `ChatPetWidget` observes `response.isPendingConfirmation` and changes the rendered state to `clapping`, but `_updateRestingPosition` retains the existing default or anchored horizontal position. `ChatInputPart.getChatPetPlatformTop` can vary vertical platform height by the pet's current center, yet its horizontal platform providers do not express an exclusion region or select another position. Preserve dragging, persisted user anchors, keyboard hopping, airborne physics, confirmation clapping, and the visual-only semantics of the pet; the scope is automatic avoidance while the question UI is active. The linked test-plan item is https://github.com/microsoft/vscode/issues/327558.
- **Open decisions:**
  - Should question avoidance be temporary, restoring the user's prior horizontal position when the question disappears, or should the automatically selected position become the new persisted resting position?
