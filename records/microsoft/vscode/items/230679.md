# Issue #230679 — "Save File" dialog is not visible in KDE after upgrade to 1.94.0

[https://github.com/microsoft/vscode/issues/230679](https://github.com/microsoft/vscode/issues/230679)

Keep open as an upstream native-dialog issue: the discussion confirms an Electron/KDE reproduction, and neither a verified fix for this path nor an eligible older duplicate canonical was established. The existing labels already route it appropriately.

## Change summary

Saving a new file on Kubuntu 24.04 starts an invisible kdialog process and leaves VS Code blocked waiting for the dialog.

## Best solution

Resolve the Electron/Chromium KDE dialog selection and MIME-database compatibility problem so native open/save dialogs appear and complete normally on affected systems. Retain the simple-dialog workaround without treating it as restoration of the native-dialog behavior.

The maintainer's final comment instead identifies KDE dialog runtime detection and links https://github.com/electron/electron/pull/42045#issuecomment-2484841772, which describes inadequate validation of the selected kdialog executable. These establish upstream ownership but do not prove resolution of every affected configuration.
- **Current native save path:** src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts routes pickFileToSave through nativeHostService.showSaveDialog unless simplified dialogs are enabled. src/vs/platform/dialogs/electron-main/dialogMainService.ts then awaits electron.dialog.showSaveDialog(window, options); the inspected VS Code layer does not implement KDE backend selection. Reading this delegation cannot establish whether an affected Linux runtime now succeeds.
