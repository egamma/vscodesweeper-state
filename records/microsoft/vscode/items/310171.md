# Issue #310171 — File links in terminal behave incorrectly when the file contains unicode characters

[https://github.com/microsoft/vscode/issues/310171](https://github.com/microsoft/vscode/issues/310171)

## Summary

The example matches intentional editor column semantics: terminal links use UTF-16 columns, and a position inside an emoji's surrogate pair is moved before that pair. The position after the emoji is column 9, not column 8.

## Change summary

The reporter expects file.py:2:8 to position the cursor after the emoji in #hello👋.

## Best solution

Preserve the existing UTF-16 navigation contract and explain that file.py:2:9 addresses the position after the emoji; counting displayed characters is not equivalent to counting editor columns.

- **Proposed comment:**

  > Thanks for the report. Terminal file links use the editor's UTF-16 column numbering, rather than a count of displayed characters. In `#hello👋`, the emoji occupies two UTF-16 code units: column 7 is before it, column 8 falls inside it, and column 9 is after it. The editor intentionally moves a position inside a surrogate pair before the character, so `file.py:2:9` will navigate to the position you expected. Replacing the emoji with an ASCII character makes column 8 the end of the line, which explains the difference.
