# Issue #310171 — File links in terminal behave incorrectly when the file contains unicode characters

[https://github.com/microsoft/vscode/issues/310171](https://github.com/microsoft/vscode/issues/310171)

## Summary

Confirmed bug on current main: terminal link column numbers are passed directly to the editor without any UTF-16 code-unit conversion, so files containing multi-code-unit characters (emoji, CJK, etc.) get incorrect cursor positioning when following a link.

## Change summary

Following a terminal file link with a column number lands on the wrong character when the target line contains emoji or other multi-code-unit Unicode characters.

## Best solution

In the terminal link opening path (TerminalLocalFileLinkOpener.open), convert the parsed column from Unicode code-point offset to the editor's UTF-16 code-unit column. This is complex because different tools report columns in different encodings (bytes, code points, or UTF-16), so a heuristic or configuration may be needed — similar to LSP's PositionEncodingKind.
