# Issue #32129 — SCM - Support altCommand for SCM resources

[https://github.com/microsoft/vscode/issues/32129](https://github.com/microsoft/vscode/issues/32129)

## Summary

Keep open: current SCM resource activation still lacks the requested modifier-click alternative. The inline Open File action and git.openDiffOnClick setting offer alternatives, but neither satisfies the explicitly requested interaction.

## Change summary

Allow modifier-clicking an SCM resource row to open the editable file instead of its diff.

## Best solution

Provide a provider-aware alternate resource-opening gesture in SCM, retaining ordinary-click behavior and resolving conflicts with existing selection and side-by-side modifiers. The maintainer already accepted this direction; the remaining work needs a gesture and API-contract decision.

- **Fit:** aligned
- **Reason:** A convenient alternate interaction for reviewing and editing changed files advances the developer inner loop without adding persistent UI.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/contrib/scm/common/scm.ts`, `src/vs/workbench/api/common/extHostSCM.ts`, `src/vs/workbench/api/browser/mainThreadSCM.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vscode-dts/vscode.d.ts`, `extensions/git/src/repository.ts`
- **Validation:** With a modified tracked file and git.openDiffOnClick=true, verify that ordinary row activation opens the diff and the agreed modifier-click opens the editable working-tree file without targeting an inline icon. Check Windows/Linux and macOS, both multiple-selection modifier settings, side-by-side opening, and providers without alternate behavior; add automated SCM dispatch and extension-host contract coverage for the agreed semantics.
- **Behavior:**

  > Users should be able to open a modified file for editing by modifier-clicking its SCM row, while ordinary activation retains the configured default. The existing inline action is not equivalent because it requires targeting a small icon. Acceptance must cover the agreed gesture across desktop platforms, preserve selection and editor-opening conventions, and leave providers without alternate behavior compatible.
- **Trace:**

  > SCMViewPane.open in src/vs/workbench/contrib/scm/browser/scmViewPane.ts dispatches a resource's single command or its open method; neither branch chooses an alternate command. SourceControlResourceState in src/vscode-dts/vscode.d.ts and ISCMResource in src/vs/workbench/contrib/scm/common/scm.ts expose no alternate command, while MainThreadSCMResource.open passes only preserveFocus to the extension-host resource-command path. Git's ResourceCommandResolver in extensions/git/src/repository.ts chooses its default from git.openDiffOnClick, which does not address per-click alternation. ResourceNavigator and the selection controller in src/vs/platform/list/browser/listService.ts already assign meanings to modifier clicks, so uncertainty starts at the gesture and provider contract rather than at whether the requested capability exists. Preserve ordinary activation, configurable defaults, and compatibility with other SCM providers. https://github.com/microsoft/vscode/issues/40077 was consolidated into this item; https://github.com/microsoft/vscode/issues/338133 supplies a newer report of the same need.
- **Open decisions:**
  - Which modifier gesture should invoke alternate opening on each platform, and how should it coexist with multiple selection and side-by-side opening?
  - Should alternate activation execute a provider-declared alternate command or open the resource URI directly, and what should users observe when a provider supplies no alternate behavior?

## Evidence

- **Accepted requirement:** In https://github.com/microsoft/vscode/issues/32129, the reporter explicitly distinguished modifier-clicking the whole row from aiming at the inline Open File icon. The maintainer's 2018-09-17 response accepted the request and identified altCommand support from the API, or similar, as necessary.
- **Existing capabilities are partial:** extensions/git/package.json registers git.openDiffOnClick, default true, and inline git.openFile2/git.openChange actions. ResourceCommandResolver.resolveDefaultCommand in extensions/git/src/repository.ts selects either the file or diff command from that setting; it changes the default for all clicks rather than providing a per-click alternate.
- **Current activation and API:** src/vscode-dts/vscode.d.ts:16487-16525 exposes only one command on SourceControlResourceState. src/vs/workbench/contrib/scm/browser/scmViewPane.ts:1708-1736 executes that command or calls resource.open; it does not select an alternate command from the modifier state. ISCMResource in src/vs/workbench/contrib/scm/common/scm.ts likewise has no alternate-command field.

Its selection controller also supports Alt as the multiple-selection modifier, so choosing an alternate-opening gesture requires an explicit compatibility decision.
