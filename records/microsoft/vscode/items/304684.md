# Issue #304684 — Generate Commit Message succeeds in DevContainer but does not populate SCM input box

[https://github.com/microsoft/vscode/issues/304684](https://github.com/microsoft/vscode/issues/304684)

## Summary

Real bug: in a DevContainer, the workspace path (`/workspaces/...`) and the opened repository path (`/home/jude/...`) diverge, so `getRepositoryExact` fails to resolve the repository via `realpath` (ENOENT). The commit message is generated successfully but the writeback to `repository.inputBox.value` silently fails because the repository object used by Copilot's `getRepository(rootUri)` does not match the one the SCM view is displaying.

## Change summary

Generate Commit Message succeeds in a DevContainer but the generated message is not written into the SCM input box due to a repository path resolution mismatch.

## Best solution

Fix the path resolution in `extensions/git/src/model.ts` so that `getRepositoryExact` (and the broader `getOpenRepository` / `openRepository` flow) can match a workspace-mapped path like `/workspaces/X` against a repository opened at a different real path like `/home/user/.../X` inside a DevContainer. Alternatively, the Copilot `getRepository` call in `extensions/copilot/src/extension/prompt/vscode-node/gitCommitMessageServiceImpl.ts` could be made more resilient to this mismatch. The Git extension's `getRepositoryRootRealPath` already handles symlinks but doesn't account for DevContainer bind-mount mappings where both the workspace folder URI and the repo root resolve to different absolute paths.
