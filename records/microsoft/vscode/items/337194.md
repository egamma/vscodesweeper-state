# Issue #337194 — MCP HTTP redirects: allow/deny policy is not re-evaluated on the redirect destination

[https://github.com/microsoft/vscode/issues/337194](https://github.com/microsoft/vscode/issues/337194)

## Summary

Confirmed on current main: the MCP HTTP redirect loop in McpHTTPHandle._fetch never re-evaluates the allow/deny policy against the redirect destination, and only strips four fixed header names on cross-origin hops — a real enterprise-policy bypass and credential-leak gap. An open PR (#337261) already targets this exact fix, so per policy the issue stays open pending that PR landing rather than being triaged as a fresh work item.

## Change summary

MCP HTTP transport follows redirects without re-checking the org's allow/deny policy on the destination, and only strips a fixed set of credential headers cross-origin.

## Best solution

Land (or continue reviewing) PR https://github.com/microsoft/vscode/pull/337261, which enforces destination policy and contains redirected credentials in McpHTTPHandle._fetch — that closes the gap described here.
