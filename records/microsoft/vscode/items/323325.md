# Issue #323325 — `~/.copilot/` folder ignores portable mode

[https://github.com/microsoft/vscode/issues/323325](https://github.com/microsoft/vscode/issues/323325)

## Summary

Valid feature request — the Copilot home directory (`~/.copilot/`) is hardcoded to `$HOME` (or `XDG_STATE_HOME`) and does not check `VSCODE_PORTABLE`. Related to the still-open #184646 (`.vscode/cli/` ignores portable mode) and #314806 (`COPILOT_HOME` env var request), but distinct enough to stand on its own as it specifically asks for portable-mode awareness.

## Change summary

The `~/.copilot/` folder is always created under the user's home directory, ignoring VS Code's portable mode (`VSCODE_PORTABLE` env var).

## Best solution

Update `getCopilotHome()` and sibling helpers in `extensions/copilot/src/extension/chatSessions/copilotcli/node/cliHelpers.ts` to check `VSCODE_PORTABLE` first and place `.copilot` state inside the portable data directory when set. Coordinate with #314806 (COPILOT_HOME env var) and #184646 (CLI portable mode) since they share the same pattern of ignoring portable mode for user-home directories.
