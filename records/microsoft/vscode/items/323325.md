# Issue #323325 — VS Code Portable - `~/.copilot/` folder ignores portable mode

[https://github.com/microsoft/vscode/issues/323325](https://github.com/microsoft/vscode/issues/323325)

## Summary

Keep open: current source still creates Copilot state under the user's home directory when portable mode is active and COPILOT_HOME is unset. The implemented environment-variable override is a workaround, not automatic portable-mode support.

## Change summary

Keep VS Code-managed Copilot state inside the portable installation instead of creating ~/.copilot by default.

## Best solution

Make the default Copilot state location honor portable mode consistently across the bundled extension and local Agent Host, while preserving explicit COPILOT_HOME overrides and non-portable behavior.

## Evidence

- **Portable startup:** src/bootstrap-node.ts, configurePortable(), detects the portable data directory and sets VSCODE_PORTABLE. It does not set COPILOT_HOME or change the operating-system home directory.
- **Source-confirmed folder creation:** extensions/copilot/src/extension/chatSessions/copilotcli/node/cliHelpers.ts:11-16 resolves the state directory to ~/.copilot/ide when COPILOT_HOME is unset, without consulting VSCODE_PORTABLE. CopilotCLIContrib._startMcpServer() in copilotcli/vscode-node/contribution.ts calls createLockFile(); copilotcli/vscode-node/lockFile.ts:77-100 recursively creates that directory and writes the lock file. This directly explains the reported folder appearing outside a portable installation.
- **Local Agent Host default:** src/vs/platform/environment/common/copilotHome.ts:9-10 likewise resolves COPILOT_HOME or userHome/.copilot, with no portable fallback. src/vs/platform/agentHost/node/copilot/copilotAgent.ts:3218 passes that resolved value as COPILOT_HOME to the runtime.
