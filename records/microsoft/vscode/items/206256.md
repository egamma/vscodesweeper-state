# Issue #206256 — microsoft visual studio not deleting old extenstnios - still.. like MS systematic solution

[https://github.com/microsoft/vscode/issues/206256](https://github.com/microsoft/vscode/issues/206256)

## Summary

Keep this canonical extensions-cleanup bug open. Multiple Windows and macOS users confirm obsolete versions surviving many full restarts, a maintainer reopened the issue after identifying a profile-cleanup gap, and the latest report includes logs showing partially deleted folders.

## Change summary

Obsolete extension versions remain on disk indefinitely despite repeated full VS Code restarts, consuming substantial storage.

## Best solution

Make startup cleanup reliably remove extension versions unused by every profile, isolate failures so one malformed or undeletable folder cannot block other removals, and retain actionable logging for folders that still cannot be deleted.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/node/extensionsWatcher.ts`, `src/vs/platform/extensionManagement/node/extensionManagementService.ts`
- **Validation:** Create temporary extension and profile data containing an obsolete valid version, an obsolete folder with a missing package.json, and one simulated deletion failure; run startup cleanup and assert that every independently removable obsolete folder is deleted, active profile versions remain, and failures are logged without blocking the rest.
- **Behavior:**

  > After all VS Code processes are closed and the application is restarted, extension versions unused by every profile should be removed from disk. A malformed or undeletable obsolete folder must not prevent cleanup of unrelated obsolete versions. Versions referenced by any profile must remain intact, and persistent deletion failures must be visible in the Shared log.
- **Trace:**

  > ExtensionsWatcher.initialize in src/vs/platform/extensionManagement/node/extensionsWatcher.ts populates all profile references and calls deleteExtensionsNotInProfiles, which records unused versions in `.obsolete`. Startup invokes ExtensionManagementService.cleanUp from src/vs/code/electron-utility/sharedProcess/contrib/extensions.ts; ExtensionsScanner.deleteExtensionsMarkedForRemoval in src/vs/platform/extensionManagement/node/extensionManagementService.ts scans recognized user extensions and deletes matching `.obsolete` entries. The investigation should establish whether stale profile references, scan rejection of partially deleted folders, filesystem deletion failures, or more than one of these paths accounts for the surviving directories. Keep active versions in every profile and the delayed-until-full-restart safety model unchanged. https://github.com/microsoft/vscode/issues/292825 is a related newer profile-specific report, while this issue remains the older canonical.

## Evidence

- **maintainer diagnosis:** A maintainer confirmed at https://github.com/microsoft/vscode/issues/206256#issuecomment-2045608451 that extensions inactive in every profile were not being cleaned up, then reopened the issue on 2024-04-09 after the earlier close.
- **current reproductions:** Independent reports in the thread confirm obsolete versions surviving many full restarts on Windows through VS Code 1.115 and on macOS, including one installation where 2.4 GB of a 4.2 GB extensions directory was obsolete.
- **current cleanup path:** src/vs/platform/extensionManagement/node/extensionsWatcher.ts initializes profile membership and marks versions absent from all profiles for removal in ExtensionsWatcher.deleteExtensionsNotInProfiles; src/vs/platform/extensionManagement/node/extensionManagementService.ts then processes `.obsolete` entries in ExtensionsScanner.deleteExtensionsMarkedForRemoval.
- **failure boundary:** ExtensionsScanner.deleteExtensionsMarkedForRemoval scans only recognized user extensions before deleting them. The latest report describes an old folder whose package.json is already missing, so that malformed leftover may no longer be discoverable through scanAllUserExtensions and can remain indefinitely.
- **canonical search:** The open https://github.com/microsoft/vscode/issues/292825 is a newer, narrower report about profiles and cannot be the canonical for this re-reviewed 2024 issue. Conversely, https://github.com/microsoft/vscode/issues/213844 and https://github.com/microsoft/vscode/issues/215540 were closed explicitly in favor of this issue.
