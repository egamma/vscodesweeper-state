## Change summary

Desktop port forwarding exits when an adopted existing tunnel returns HTTP 404 with a Tunnel Expiration response.

## Best solution

Desktop forwarding should recover from an expired, unusable tunnel rather than repeatedly adopting it and exiting. Investigate the CLI adoption path and the service's list-versus-lookup behavior, preserving active tunnels and surfacing unrelated failures.

## Plan brief

- **Likely files:** `cli/src/tunnels/dev_tunnels.rs`, `cli/src/commands/tunnels.rs`
- **Validation:** Establish a controlled tunnel-management scenario that lists an inactive matching tunnel but returns HTTP 404 with Tunnel Expiration on lookup; desktop forwarding must subsequently start successfully without repeatedly adopting that tunnel. Also check that a valid existing tunnel is reused, an active tunnel is not disrupted, and unrelated service errors remain visible.
- **Behavior:**

  > Desktop port forwarding currently exits when it adopts a listed tunnel that the service rejects as expired. Forwarding should recover to a usable tunnel without requiring reinstalling VS Code or switching to the browser. Acceptance must cover successful forwarding after the expiration response, normal reuse of valid tunnels, protection of active tunnels, and visible unrelated failures.
- **Trace:**

  > The reporter's logs at https://github.com/microsoft/vscode/issues/321555#issuecomment-4715432543 match DevTunnels::create_tunnel in cli/src/tunnels/dev_tunnels.rs: it selects a listed same-name tunnel, logs adoption, and propagates the subsequent lookup error. Desktop forwarding enters this path from forward in cli/src/commands/tunnels.rs and uses separate forwarding persistence and tags. get_or_create_tunnel already handles a persisted lookup returning 404 or 403, but its creation path can rediscover an unusable tunnel. Source inspection confirms the abort, not why the service lists the expired object. Existing tests in dev_tunnels.rs exercise hostname cleanup and protocol-error detection rather than management-response sequences; the planning session needs to establish a controlled acceptance check. Keep authentication, privacy, active-tunnel ownership, and normal remote-tunnel behavior unchanged.
