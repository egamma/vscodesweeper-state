# Issue #325910 — Display Jupyter Cell ID

[https://github.com/microsoft/vscode/issues/325910](https://github.com/microsoft/vscode/issues/325910)

## Summary

Keep open as a feature request: the existing cell-position indicator does not expose the persistent Jupyter cell ID requested for Copilot conversations. No verified canonical or existing display capability was found; the request can remain in the community discussion process.

## Change summary

Expose persistent Jupyter cell IDs in the notebook editor so users can identify specific cells when communicating with Copilot.

## Best solution

Evaluate a discoverable, on-demand way to inspect and copy a cell's persisted Jupyter ID without adding permanent notebook clutter. The notebook UI should distinguish that stable identity from the cell's current position.

## Evidence

- **Existing capability is positional, not persistent:** src/vs/workbench/contrib/notebook/browser/contrib/editorStatusBar/editorStatusBar.ts: ActiveCellStatus._getSelectionsText computes getCellIndex(activeCell) + 1 and displays 'Cell {0} of {1}'. This identifies the current position, not the persisted Jupyter cell ID.
- **Persistent IDs are preserved:** extensions/ipynb/src/serializers.ts: getCellMetadata retains cell metadata, and createCodeCellFromNotebookCell and createRawCellFromNotebookCell serialize cellMetadata.id into the Jupyter cell's id field. The requested identifier exists independently of the positional status indicator.
- **Existing-capability search:** Read-only searches of notebook configuration and action registrations, notebook UI code, and extensions/ipynb found no dedicated setting or command displaying or copying the persisted cell ID. Opening notebook JSON is not equivalent to the requested elegant editor presentation.
- **Canonical search:** Repository issue searches covered cell IDs, identifiers, cell numbers, notebook references, and Copilot cell IDs. The verified open https://github.com/microsoft/vscode/issues/189362 requests positional cell numbers in Accessible View output, not persistent Jupyter IDs for conversations, so it does not absorb this request.
