# Issue #331074 — About dialog shows commit hash in OS field (1.133.0)

[https://github.com/microsoft/vscode/issues/331074](https://github.com/microsoft/vscode/issues/331074)

## Summary

Confirmed root cause on main: the OS field shows the commit hash because nls.ts's placeholder regex only reads the first digit of the match, so `{10}` resolves to `args[1]` (commit) instead of `args[10]` (OS). Multiple independent reporters confirm the symptom, and I reproduced it with the exact template string used by the About dialog.

## Change summary

Help → About shows the git commit hash in the OS field instead of the actual OS/version string.

## Best solution

Fix `_format` in src/vs/nls.ts to parse the full placeholder index (e.g. `parseInt(rest, 10)`) instead of taking only `rest[0]`, so double-digit placeholders like `{10}` resolve correctly; this also protects any future localize() call with 10+ arguments, not just the About dialog string in src/vs/platform/dialogs/electron-browser/dialog.ts.

- **Fix prompt:**

  > In src/vs/nls.ts, the internal `_format(message, args)` function (used by `localize`/`localize2`) replaces `{n}` placeholders via `message.replace(/\{(\d+)\}/g, (match, rest) => { const index = rest[0]; const arg = args[index]; ... })`. The bug is that `rest[0]` only takes the FIRST CHARACTER of the captured digit string `rest` (a string, e.g. '10'), instead of using the full numeric value as the array index — so for a two-digit placeholder like `{10}`, `index` becomes the string '1' (JS coerces `args['1']` to `args[1]`), silently pulling the wrong argument. This was confirmed to be the exact cause of https://github.com/microsoft/vscode/issues/331074, where the About dialog's `OS: {10}` placeholder (in src/vs/platform/dialogs/electron-browser/dialog.ts, `createNativeAboutDialogDetails`, an 11-argument localize call) resolves to `args[1]` (the commit hash) instead of `args[10]` (the OS string). Fix by using the full captured digit string as the index (e.g. `const index = Number(rest);` or `parseInt(rest, 10)`) so any placeholder number, single- or multi-digit, maps to the correct argument. Do not change the overall regex, the pseudo-localization block below it, or the public `localize`/`localize2` signatures — this is a one-line/couple-line fix confined to the index computation inside `_format`. Add a unit test (likely in the existing nls test suite, or a new test file alongside src/vs/nls.ts if none exists) asserting that a message with a `{10}` (or higher) placeholder resolves to the correct 11th (or later) argument rather than being reinterpreted as a lower single-digit index; the test must fail before the fix and pass after.
