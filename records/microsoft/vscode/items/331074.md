# Issue #331074 — About dialog shows commit hash in OS field (1.133.0)

[https://github.com/microsoft/vscode/issues/331074](https://github.com/microsoft/vscode/issues/331074)

## Summary

Confirmed root cause in current main: the `_format` helper in `src/vs/nls.ts` reads only the first character of a multi-digit placeholder index, so `{10}` resolves to `args[1]` instead of `args[10]` — this is exactly why the About dialog's OS field (placeholder `{10}`) shows the commit (`args[1]`).

## Change summary

In Help → About, the OS field shows the build commit hash instead of the OS version string.

## Best solution

Fix `_format` in src/vs/nls.ts to parse the full placeholder index (e.g. `parseInt(rest, 10)` as `src/vs/base/common/strings.ts`'s `format` already does) rather than taking only `rest[0]`; this is a one-line, high-confidence fix with a clear regression test.

  > In src/vs/nls.ts, the internal `_format(message, args)` helper (used by `localize`) has a bug: `result = message.replace(/\{(\d+)\}/g, (match, rest) => { const index = rest[0]; const arg = args[index]; ... })`. For a placeholder with a multi-digit index like `{10}`, the regex capture group `rest` is the string "10", but the code takes only `rest[0]` (the character "1"), so it looks up `args["1"]` (== `args[1]`) instead of `args[10]`. This causes any localized string with 10 or more positional arguments to substitute the wrong value for placeholders `{10}`, `{11}`, etc. — confirmed as the root cause of GitHub issue microsoft/vscode#331074, where the About dialog's `Version: {0}\nCommit: {1}\n...OS: {10}` message (built in src/vs/platform/dialogs/electron-browser/dialog.ts `createNativeAboutDialogDetails`) shows the Commit value in the OS field. Add a unit test for `localize`/`_format` (or a small wrapper if `_format` isn't exported) with 11+ args verifying that `{10}` substitutes `args[10]` and not `args[1]`, so it fails before the fix and passes after. ## Evidence

- **root cause:** src/vs/nls.ts `_format()`: `result = message.replace(/\{(\d+)\}/g, (match, rest) => { const index = rest[0]; const arg = args[index]; ... })` — for a two-digit placeholder like `{10}`, `rest` is the string "10" and `rest[0]` is just "1", so `args["1"]` (== `args[1]`) is used instead of `args[10]`.
- **trigger site:** src/vs/platform/dialogs/electron-browser/dialog.ts `createNativeAboutDialogDetails()` builds the about string with `localize({...}, "Version: {0}\nCommit: {1}\n...OS: {10}", version, commit, date, electron, electronBuildId, chromium, node, v8, copilotRuntime, copilotSdk, osString)` — 11 args, so `{10}` (OS) is the first placeholder affected by the bug, and it collides with `{1}` (Commit), matching the reporter's exact symptom.
- **correct counterpart:** src/vs/base/common/strings.ts's `format()` does this correctly: `const idx = parseInt(group, 10);` — confirming the nls.ts version is the regression, not an intentional design.
- **corroboration:** Multiple independent reporters (comments by Risae, xguarch) confirm the same OS-field-shows-commit symptom on Windows and macOS at 1.133.0.
