# Issue #324113 — Virtual tool grouping silently drops tools mid-session; error blames the user ("currently disabled by the user")

[https://github.com/microsoft/vscode/issues/324113](https://github.com/microsoft/vscode/issues/324113)

## Summary

Still reproduces on main: the virtual tool grouper has multiple paths that silently drop tools, and the error message misattributes the failure to user action. The `chat.virtualTools.threshold` setting is also not wired into the grouping gate.

## Change summary

Virtual tool grouping can silently lose tools mid-session, and the error incorrectly blames the user for disabling them.

## Best solution

Fix the lossy paths in VirtualToolGrouper: (1) `_generateEmbeddingBasedGroups` returns `[]` for small toolsets instead of returning the tools ungrouped; (2) `_allocateSlots` can assign 0 slots, causing tools to vanish; (3) wire `VirtualToolThreshold` into the grouping gate in `addGroups()`; (4) distinguish 'tool not in current toolset (regrouped)' from 'disabled by user' in the error message.

## Evidence

- **lossy small-toolset path:** extensions/copilot/src/extension/tools/common/virtualTools/virtualToolGrouper.ts line 377-379: `_generateEmbeddingBasedGroups` returns `[]` when `tools.length <= MIN_TOOLSET_SIZE_TO_GROUP` (2), silently dropping those tools instead of returning them ungrouped.
- **zero-slot allocation:** Same file line 266-270: `_allocateSlots` gives 0 slots to overflow toolsets (`i >= availableSlots`), and `_processToolset` is never called for those, dropping all their tools.
- **threshold setting not wired:** The `chat.virtualTools.threshold` / `ConfigKey.VirtualToolThreshold` setting is computed in `toolGrouping.ts:computeToolGroupingMinThreshold` and exposed as `toolGroupingService.threshold`, but `VirtualToolGrouper.addGroups()` never reads it — it uses only `START_GROUPING_AFTER_TOOL_COUNT` (64) and `START_BUILTIN_GROUPING_AFTER_TOOL_COUNT` (20).
- **misleading error message:** extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx line 272-274: the check `!availableTools.find(t => t.name === ...)` catches both user-disabled tools and regrouped-away tools, but the error says 'currently disabled by the user'.
- **related issues closed differently:** https://github.com/microsoft/vscode/issues/324978 (closed COMPLETED) and https://github.com/microsoft/vscode/issues/324979 (closed NOT_PLANNED) are related but neither fixes the root cause in the grouper code on main.
