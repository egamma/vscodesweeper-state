# Issue #331769 — Agents window incorrectly parses SSH config

[https://github.com/microsoft/vscode/issues/331769](https://github.com/microsoft/vscode/issues/331769)

## Summary

Confirmed in source: `parseSSHConfigHostEntries` (src/vs/platform/agentHost/common/sshConfigParsing.ts) splits a `Host` line's value with a plain `/\s+/` regex, which doesn't honor OpenSSH double-quote syntax, so a quoted alias like `Host "Dev Instance (EU)"` is split into three bogus host tokens (`"Dev`, `Instance`, `(EU)"`) shown in the Agents window's SSH host picker.

## Change summary

SSH config Host aliases containing quoted, space-separated names are split into multiple incorrect entries in the Agents window's SSH host list, unlike the Remote-SSH extension which parses quoting correctly.

## Best solution

Make `parseSSHConfigHostEntries` quote-aware for the Host directive's value, similar to the existing `parseSSHPathList` helper in the same file which already tokenizes double-quoted, space-containing values correctly for `ssh -G` output.

That naive split doesn't understand OpenSSH's double-quote syntax for Host patterns containing spaces (e.g. `Host "Dev Instance (EU)"`), so a quoted alias is fragmented into multiple bogus host strings, which is exactly what the linked GitHub issue reports being shown (split across multiple lines) in the Agents window's SSH host picker, versus the Remote-SSH extension's picker which parses it correctly as one entry.
