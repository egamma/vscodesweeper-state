# Issue #305547 — When the key with scan code `KeyV` is remapped to key code `.`, `[ctrl]+.` is resolved to `editor.action.clipboardPasteAction`

[https://github.com/microsoft/vscode/issues/305547](https://github.com/microsoft/vscode/issues/305547)

## Summary

Verified duplicate of the long-standing canonical issue #23991 — setxkbmap/xkb remappings on Linux are not respected because VS Code dispatches on the physical scan code (keyCode) rather than the remapped key character. The bépo layout is one instance of this class of bug.

## Change summary

When xkb remaps a physical key (e.g. KeyV → '.'), Ctrl+remapped-key dispatches based on the original scan code (Ctrl+V → paste) instead of the remapped character (Ctrl+. → quickFix).

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/23991 which tracks the root cause (xkb remappings not reflected in keyboard dispatch on Linux). Fixing that canonical issue resolves this specific bépo-layout manifestation.
