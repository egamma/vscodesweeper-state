# Issue #226975 — Rename widget logging

[https://github.com/microsoft/vscode/issues/226975](https://github.com/microsoft/vscode/issues/226975)

## Summary

The noisy trace logging was commented out as a workaround (FIXME at line 320), but the underlying debt — the rename widget not being properly unmounted from the editor after use, causing repeated `afterRender` calls with `position: null` — remains unaddressed on current main.

## Change summary

RenameWidget floods trace logs because it isn't properly unmounted from the editor after a rename completes, causing repeated afterRender callbacks.

## Best solution

Properly unmount/remove the RenameWidget content widget from the editor when the rename operation completes, so `afterRender` is no longer called repeatedly with `position: null`. The fix belongs in `src/vs/editor/contrib/rename/browser/renameWidget.ts` around the lifecycle of adding/removing the widget via `editor.addContentWidget`/`editor.removeContentWidget`.
