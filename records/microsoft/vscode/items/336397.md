# Issue #336397 — Request: (Copilot) Api to expose current model to chat session

[https://github.com/microsoft/vscode/issues/336397](https://github.com/microsoft/vscode/issues/336397)

## Summary

Reasonable ask for the built-in Copilot Chat agent to have lightweight self-introspection of its own model identity, distinct from the existing extension-facing `ChatRequest.model` API; no maintainer has weighed in and the design is undecided, so route to the chat area rather than close.

## Change summary

Give the model running a Copilot chat session an efficient way to know which model it currently is, instead of only being inferable by scanning the full session log.

## Best solution

A maintainer decides whether this is delivered as a small system-prompt/context addition or a callable tool exposing model id/family for the active turn, scoped to the built-in Copilot Chat agent (extensions/copilot or the workbench chat contrib), separate from the existing stable `ChatRequest.model` used by third-party participants.

## Plan brief

- **Likely files:** `extensions/copilot`, `src/vs/workbench/contrib/chat`
- **Validation:** A test or manual check confirming the agent can report its exact current model id/family within a chat turn without needing to parse the full session transcript.
- **Behavior:**

  > When asked, the Copilot Chat agent should be able to state which model is currently handling the session (e.g. model id/family) without needing to scan the entire session log for it. This should work for the default built-in agent flow, not just for third-party chat participants that already receive `ChatRequest.model`.
- **Trace:**

  > Third-party extension participants already get model identity via `ChatRequest.model` (src/vscode-dts/vscode.d.ts:19855-19903, `LanguageModelChat`). No equivalent lightweight mechanism was found for the built-in Copilot agent to inform itself of its own model identity mid-turn; a commenter confirms the only current path is scanning the full session log. The boundary: this should not change the existing stable `ChatRequest.model` extension API, only add a self-introspection path for the built-in agent.
- **Open decisions:**
  - Should model identity be injected as system-prompt/context on every turn, or exposed as an on-demand callable tool?
  - Should this always be included, or gated behind a setting/opt-in given it's extra context sent to the model on every request?

## Evidence

- **existing extension API:** src/vscode-dts/vscode.d.ts:19855-19903 already exposes `ChatRequest.model: LanguageModelChat` (id/family/name/vendor) to third-party chat participants, but this issue is about the built-in Copilot agent introspecting its own identity mid-session, which is a different surface.
- **commenter workaround:** A commenter notes the model can currently infer its identity only by scanning the full session log ('Canonical model ID: ...'), calling this wasteful — supporting that no efficient built-in mechanism exists today.
- **low signal so far:** Only 1 upvote and no maintainer engagement 10 days in; not yet strong enough for a design commitment, just routing.
