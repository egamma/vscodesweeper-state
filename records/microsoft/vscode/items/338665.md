# Issue #338665 — Remote agent host over SSH keeps reconnecting while a large message is still downloading

[https://github.com/microsoft/vscode/issues/338665](https://github.com/microsoft/vscode/issues/338665)

## Summary

Confirmed, well-diagnosed bug (reporter is a maintainer with detailed byte-level analysis) with an open, author-authored fixing PR already in flight — keep open until that PR merges rather than closing now.

## Change summary

After laptop sleep/wake over SSH, the Agent Host protocol client's liveness watchdog only resets on a fully-parsed inbound message, so a connection still receiving one large in-progress snapshot download (tens of MB, taking 25+ seconds) gets force-closed as dead and reconnects, restarting the same slow download repeatedly.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338721, which resets the liveness timers on any inbound data (via a new onDidReceiveData transport listener and _recordInboundTraffic()) rather than only on a complete parsed message — this directly credits an in-progress download as proof of life.

## Evidence

- **open fixing PR:** https://github.com/microsoft/vscode/pull/338721 (open, unmerged, merge_commit/merged_at both null as of check) by the issue author lramos15, body 'Fix #338665'. Diff adds `transport.onDidReceiveData` listener calling new `_recordInboundTraffic()` to reset watchdog timers on any inbound bytes, not just complete messages.
- **not yet on main:** git log on src/vs/platform/agentHost/browser/agentHostProtocolClient.ts shows the latest merge is PR #338798, unrelated to this fix; the file does not yet contain the onDidReceiveData change.
- **detailed maintainer diagnosis:** lramos15's comment breaks down the 95MB snapshot as 45 subscribed state channels (32 subagent chats, 3 default chats), with a single 35MB chat subscribe message causing repeated timeouts.
