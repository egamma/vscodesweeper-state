# Issue #337848 — SDK hangs due to spamming listSessions

[https://github.com/microsoft/vscode/issues/337848](https://github.com/microsoft/vscode/issues/337848)

## Summary

Confirmed real and still open on main: `_discoverCopilotChats` in copilotAgent.ts unconditionally lists the entire SDK session catalog (`client.rpc.sessions.list`) on every discovery scan, even when only a handful of candidates are pending retry, which matches the reporter's traced 174s `listMs` full-catalog scans against a ~5,000-session store. This is an active, team-authored, milestoned bug under investigation, not something to close.

## Change summary

Agent Host's Copilot session discovery repeatedly performs full, expensive SDK `listSessions` scans (every ~5-10s under retry) even when only a few candidates need rechecking, causing runaway CPU and session hangs.

## Best solution

Avoid a full catalog enumeration per scan: either cache/reuse the last catalog for unwatched candidates, add a scoped SDK query keyed to the pending candidate IDs, or increase the backoff/coalescing for the recurring 'incomplete marker' retries in copilotAgent.ts's `_discoverCopilotChats` / CopilotChatDiscovery, so cost scales with pending candidates (currently 1-3) rather than total SDK sessions (currently ~5,000).
