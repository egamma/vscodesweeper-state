# Issue #339799 — Does Docker need to be running to mark session as done?

[https://github.com/microsoft/vscode/issues/339799](https://github.com/microsoft/vscode/issues/339799)

## Summary

Team-authored issue, so no judgment close applies regardless of the design intent found in source. Traced the code: archiving a Dev Container-backed session always tries to reconnect and remove the container first, so Docker (or the container runtime) must be reachable — this matches the reporter's observation, but whether that's the right behavior (vs. deferring cleanup) is a maintainer call, not something to close from here.

## Change summary

Marking a Dev Container session as done fails if Docker/the container runtime isn't running, with the author asking whether that dependency is intentional.

## Best solution

Decide whether archiving a Dev Container session should require a live connection to remove the container (and if so, surface a clear, actionable error telling the user to start Docker) or should be resilient — marking the session done locally and deferring container/worktree cleanup until the runtime is next available.

- **Trace:**

  > remoteAgentHostSessionsProvider.ts `archiveSession()` (around line 415) calls `_ensureDevContainerConnection()` before `_setDevContainerSessionArchived()`; if the Dev Container's connection can't be (re)established, both throw, and the Mark as Done action fails end-to-end with a disconnected error. Do not change the live container removal/worktree cleanup for the normal (connected) path.
- **Open decisions:**
  - Should Mark as Done for a Dev Container session succeed locally when the container runtime (Docker) is unreachable, deferring container/worktree cleanup to the next time it's available?

## Evidence

- **archive requires live connection:** src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts archiveSession() calls `await this._ensureDevContainerConnection()` then `_setDevContainerSessionArchived(sessionId, true)` before removing the container; `_ensureDevContainerConnection` throws `devContainerAgentHost.reconnectFailed` if `this._devContainerLifecycle.connect()` doesn't produce a connection (e.g. Docker not running).
- **error on disconnect:** _setDevContainerSessionArchived throws `devContainerAgentHost.archiveDisconnected` ('Unable to archive Dev Container session … while disconnected') when there is no live connection, matching the reporter's failed action.
- **documented design:** REMOTE_AGENT_HOST_SESSIONS_PROVIDER.md: 'Archiving first records the remote archived state, then removes the container before removing its mounted worktree without waiting for the idle countdown' — confirming container removal, and thus a live runtime, is part of today's archive flow.
