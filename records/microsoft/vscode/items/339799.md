# Issue #339799 — Does Docker need to be running to mark session as done?

[https://github.com/microsoft/vscode/issues/339799](https://github.com/microsoft/vscode/issues/339799)

## Summary

Team-authored bug report (already labeled bug/containers/agent-host) describing that marking a dev-container-backed agent session as done (and a second comment: deleting one) fails when the underlying container/Docker isn't running — this is a real, unresolved gap, so it stays open; no fix commit exists yet since the issue is two days old.

## Change summary

Marking a session as done (or deleting it) fails silently/with an error when the session's dev container (and therefore Docker) isn't currently running.

## Best solution

Decide whether archive/delete/mark-as-done state for container-backed sessions should be mutable locally (cached and synced once reconnected) or should require a live container connection with a clear, actionable error message instead of a raw failure — likely in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts where `canArchive`/`_isArchived` are derived from connection/session state.

- **Trace:**

  > canArchive/isArchived state for container-backed sessions in baseAgentHostSessionsProvider.ts is derived partly from the session's RemoteAgentHostConnectionStatus; when the backing container (and thus the agent host connection) is down, archive-capability appears to depend on that connection, producing the failure the reporter and commenter saw for mark-as-done and delete respectively.
