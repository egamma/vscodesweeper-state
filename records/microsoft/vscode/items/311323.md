# Issue #311323 — gemini-cli not reflected in terminal title

[https://github.com/microsoft/vscode/issues/311323](https://github.com/microsoft/vscode/issues/311323)

## Summary

Still a valid bug: gemini-cli runs as `node` on macOS, and if it doesn't emit an OSC title sequence containing 'gemini', the existing detection in terminalInstance.ts won't fire — the tab title stays 'node'. The code has the pattern ready but depends on the CLI actually emitting the sequence.

## Change summary

Running `gemini` in the integrated terminal shows 'node' as the tab title instead of 'gemini'.

## Best solution

The terminal process-name detection (`generalShellTypeMap` in `terminalProcess.ts`) maps 'gemini' correctly, but gemini-cli's actual process is reported as 'node'. Either detect it from the command-line arguments (argv inspection for the gemini script path, similar to the Windows `windowsShellHelper.ts` approach at line 52), or ensure the fallback OSC-title detection works. The fix belongs in `src/vs/platform/terminal/node/terminalProcess.ts` (Unix process detection) to handle the case where the binary is node but the script is gemini.
