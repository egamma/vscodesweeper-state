# Issue #325952 — CopilotAH: support more custom agent properties

[https://github.com/microsoft/vscode/issues/325952](https://github.com/microsoft/vscode/issues/325952)

## Summary

Still open on main: the custom-agent converter in copilotPluginConverters.ts only forwards `name`, `description`, `tools`, `model`, and `prompt` — properties like `reasoning-effort` are not yet passed through, and the larger ask (letting Copilot do the reading) is unimplemented.

## Change summary

Support additional custom agent frontmatter properties (e.g. `reasoning-effort`) in the Copilot Agent Host, ideally by delegating file reading to the Copilot SDK.

## Best solution

Either extend `toSdkCustomAgents` in `copilotPluginConverters.ts` to forward all unknown frontmatter properties as pass-through config, or — as the issue suggests — delegate the entire agent-file reading to the Copilot SDK so VS Code no longer needs to discover and parse each property individually. The model-migration concern (local VS Code models → Copilot models) would need a thin adapter layer even in the delegation approach.
