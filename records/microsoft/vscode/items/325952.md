# Issue #325952 — CopilotAH: support more custom agent properties

[https://github.com/microsoft/vscode/issues/325952](https://github.com/microsoft/vscode/issues/325952)

## Summary

The named reasoning-effort capability has landed, and most file-backed plugin agents now use SDK discovery, but selected agents and agents without file-backed plugin directories still pass through VS Code's finite frontmatter projection. Keep this team-authored request open for the remaining property-parity and model-translation design; the linked changes do not establish completion of its full scope.

## Change summary

Support Copilot custom-agent properties without maintaining a separate incomplete parser, while accommodating VS Code model identifiers.

## Best solution

Make SDK-supported custom-agent properties behave consistently whether an agent is discovered through a plugin directory or explicitly selected. Establish the model-identifier compatibility contract before completing the remaining SDK handoff work.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/test/node/copilotPluginConverters.test.ts`
- **Validation:** Extend the copilotPluginConverters tests to compare the agreed supported properties for explicitly selected and directory-discovered agents, retaining selection and deduplication coverage. Finish with a runtime check using the same agent through both paths and model identifiers covered by the agreed compatibility contract.
- **Behavior:**

  > Custom-agent properties supported by the Copilot runtime should not disappear because an agent is explicitly selected instead of discovered from a plugin directory. reasoning-effort already works and must remain supported. Selected agents must still activate successfully, and an agent must not appear twice. Acceptance includes equivalent supported-property behavior across the two loading paths and defined handling of VS Code model identifiers.
- **Trace:**

  > toSdkCustomAgents in src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts reads frontmatter and constructs a finite CustomAgentConfig projection. toSdkSessionCustomAgents delegates ordinary file-directory plugin agents to runtime discovery but explicitly projects the selected agent and agents without file-backed plugin directories. CopilotSessionLauncher supplies both the projected customAgents and pluginDirectories to the SDK; the source documents a startup selection constraint that prevents assuming directory discovery alone is sufficient. https://github.com/microsoft/vscode/pull/329263 implements reasoning-effort, and https://github.com/microsoft/vscode/pull/325963 implements a disable-model-invocation mapping, so neither should be redone. Existing converter tests pin selection and deduplication behavior. Preserve customization enablement and non-agent plugin resources; uncertainty starts at the runtime's alternative loading contracts and the intended model-identifier migration semantics.
- **Open decisions:**
  - Which VS Code model identifiers or ordered model lists must remain compatible with Copilot custom agents, and what should users observe when a declared model has no available Copilot equivalent?
