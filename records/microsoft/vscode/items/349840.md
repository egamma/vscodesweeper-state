# Issue #349840 — Agents: sessions of a deleted Dev Container environment still offer Connect

[https://github.com/microsoft/vscode/issues/349840](https://github.com/microsoft/vscode/issues/349840)

## Summary

Keep open: the report provides sufficient steps to retest the misleading recovery action after permanent deletion. Current source unregisters the environment provider, but the retained-session presentation remains unconfirmed; no fixing commit or matching canonical was established.

## Change summary

Sessions belonging to a permanently deleted Dev Container should explain that deletion and stop offering Connect.

## Best solution

Make permanent environment deletion distinguishable from a temporary disconnection in retained session presentation, without changing recovery for existing environments or silently deleting session history.

- **Behavior:**

  > After successful deletion of a Dev Container environment, selecting one of its retained sessions must not present the environment as temporarily unreachable or offer Connect. The presentation must explain that the environment was deleted and the session cannot continue there. Ordinary disconnection of an existing environment must retain its normal recovery actions; session history must not be silently deleted.
- **Trace:**

  > RemotesModel.deleteDevContainer delegates to DevContainerEnvironments.delete, which disconnects, removes the container, removes persisted inventory, and disposes the provider registration. Preserve normal disconnected-host recovery and avoid equating provider withdrawal with session deletion. https://github.com/microsoft/vscode/issues/348707 concerns a separate idle-stop/recreation race.
