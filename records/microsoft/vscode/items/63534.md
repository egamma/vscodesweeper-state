# Issue #63534 — Support for global or project-level variables

[https://github.com/microsoft/vscode/issues/63534](https://github.com/microsoft/vscode/issues/63534)

## Summary

Keep open: current snippet expansion does not support arbitrary user- or project-defined variables, and the request has 20 community upvotes. The related identity-variable PR covers only a narrow use case, not configurable values such as declaration style or statement terminators.

## Change summary

Allow shared snippets to resolve user-overridable variables defined outside their bodies through configuration or environment values.

## Best solution

Define a scoped custom-variable contract for the existing snippet system, including configuration precedence, empty-string values, and interaction with built-in variables. Coordinate with the active identity-variable work without treating that narrower capability as completion of this request.

## Evidence

- **Remaining capability gap:** src/vs/editor/contrib/snippet/browser/snippetSession.ts:567–575 and 642–650 construct resolver chains for model, clipboard, selection, comments, time, workspace, and random values. Neither chain includes a resolver for arbitrary configuration or environment variables.
- **Existing-capability check:** src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts registers editor.snippets.codeActions.enabled and snippet-file schemas, but no custom-variable map. src/vs/editor/contrib/snippet/browser/snippet.md documents built-in variables, defaults, choices, and transforms; none supplies external shared values. src/vs/workbench/contrib/snippets/browser/snippetsFile.ts converts unknown variables without defaults into editable placeholders, rather than resolving user configuration.
- **Demand and accepted scope:** https://github.com/microsoft/vscode/issues/63534 has 20 body upvotes and is assigned to Backlog. Its July 2023 comment supplies a concrete editor.snippets.variables example for an author signature; the original report additionally requires arbitrary style values, including an empty statement terminator.
- **Older related issue is not the same request:** https://github.com/microsoft/vscode/issues/10561 is open and older, but requests executing functions during snippet expansion. That is not the same observable capability as resolving externally configured static variables, so it does not satisfy the stronger duplicate bar for this re-reviewed item. https://github.com/microsoft/vscode/issues/2809 concerns interpolation within settings values, not snippet expansion.
- **Closed related issues do not settle this scope:** https://github.com/microsoft/vscode/issues/59557 concerns variables declared inside snippets and was closed through backlog cleanup. https://github.com/microsoft/vscode/issues/130325#issuecomment-899338950 declines extension-provided resolvers because extension-host calls are asynchronous; that reasoning does not establish that locally available configuration values must also be declined.
- **Active partial implementation:** https://github.com/microsoft/vscode/pull/315156 is open and targets https://github.com/microsoft/vscode/issues/64599, adding TM_FULLNAME and TM_EMAIL with fixed environment fallbacks. It does not expose arbitrary custom variables or project-level overrides. The maintainer explicitly links this broader request in https://github.com/microsoft/vscode/issues/64599#issuecomment-4483314431.
