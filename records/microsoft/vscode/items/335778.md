# Issue #335778 — Agents Window PRs: Unclear when PR opens in-product vs in-browser

[https://github.com/microsoft/vscode/issues/335778](https://github.com/microsoft/vscode/issues/335778)

## Summary

Team-authored report of a real inconsistency, confirmed in source: the session-list PR hover forces the link into the browser while the equivalent `Open Pull Request` command allows the GHPR extension to open it in-product — team-authored issues can't be judgment-closed anyway, so this stays open pending a fix.

## Change summary

Selecting a PR from the session-list hover always opens it in the browser, while a PR link shared in chat opens in-product via GHPR — inconsistent behavior with no visible way to control it.

## Best solution

Align `getPullRequests()` in src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts with the existing `OpenPullRequestAction` (src/vs/sessions/contrib/github/browser/pullRequestActions.ts:64): pass `allowContributedOpeners: true` alongside `openExternal: true` so the GHPR extension's contributed opener can intercept and open the PR in-product, matching the chat-link path.
