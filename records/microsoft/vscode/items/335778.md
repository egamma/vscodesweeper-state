# Issue #335778 — Agents Window PRs: Unclear when PR opens in-product vs in-browser

[https://github.com/microsoft/vscode/issues/335778](https://github.com/microsoft/vscode/issues/335778)

## Summary

Team-authored report of an inconsistency in the Agents Window; I traced a concrete root cause in the session hover code, so this stays open pending a fix rather than any close.

## Change summary

PR links opened from a session's chat response open in-product (via GHPR's contributed opener), but PR links opened from the session-list hover panel always open in the external browser.

## Best solution

In src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts, getPullRequests()'s onOpen calls openerService.open(ref.uri, { openExternal: true }) without allowContributedOpeners; sessionArtifacts.ts's openExternal (used for chat-response links) passes { openExternal: true, allowContributedOpeners: true, fromUserGesture: true }, letting GHPR's contributed opener intercept it. Aligning the hover's onOpen call with that same option set would make both paths behave consistently.
