# Issue #329750 — API-provided terminal editor icon is not preserved across window reload or restart

[https://github.com/microsoft/vscode/issues/329750](https://github.com/microsoft/vscode/issues/329750)

## Summary

Real, well-diagnosed bug: an API-provided terminal icon isn't retained through the reattach path when a persisted editor terminal is revived (reload or restart), likely because the icon assignments in TerminalInstance's process-property handlers (e.g. the InitialCwd reset at terminalInstance.ts) can lose the `attachPersistentProcess.icon` value under lazy reattach/revival timing. A contributor (kKrishGupta) has already confirmed the repro and the author has approved them taking it up, so this is best left for their PR.

## Change summary

The custom ThemeIcon set via `TerminalOptions.iconPath` for an editor-location terminal reverts to the default shell icon after a window reload or full VS Code restart once the terminal is reattached/revived.

## Best solution

Let the volunteering contributor's fix land: ensure the icon captured in `ISerializedTerminalEditorInput`/`attachPersistentProcess` survives the reattach/revive flow in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts (icon-reset call sites around the InitialCwd property handler and `_createProcess`) and add a regression test covering both reload and full restart.
