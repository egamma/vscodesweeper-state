# Issue #312058 — Bulk export chat command

[https://github.com/microsoft/vscode/issues/312058](https://github.com/microsoft/vscode/issues/312058)

## Summary

A real capability gap remains: current main exports only the focused chat session, not all non-archived sessions in a workspace. The request has no established older duplicate and should remain open under discussion while its session scope and archive format are designed.

## Change summary

Add a command that exports every non-archived chat session in the current workspace to a selected folder, optionally as a zip archive.

## Best solution

Provide a workspace-scoped bulk export that writes each non-archived session using a deterministic, collision-safe filename and preserves the existing importable chat format. A maintainer should first settle whether contributed and agent-host sessions are included and whether zip is an alternative output mode.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts`, `src/vs/workbench/contrib/chat/common/chatSessionsService.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatImportExport.test.ts`
- **Validation:** Add an action test with multiple current-workspace sessions asserting that bulk export writes one importable export per non-archived session, excludes archived sessions, and produces distinct filenames for duplicate titles.
- **Behavior:**

  > Users can invoke a bulk chat export for the current workspace and select an output destination. Every in-scope non-archived session is exported in the existing importable format, while archived and out-of-scope sessions are omitted. Duplicate or filesystem-unsafe titles must not overwrite another export. Cancellation must leave the workspace and session state unchanged.
- **Trace:**

  > The existing `workbench.action.chat.export` action in src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts serializes only `IChatWidgetService.lastFocusedWidget` through `ChatModel.toExport()`. Session enumeration is available through `IChatSessionsService.getChatSessionItems(...)` in src/vs/workbench/contrib/chat/common/chatSessionsService.ts, but the visible model in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts combines provider items with computed archived state. The uncertainty begins at provider and workspace scope: local chats, contributed sessions, and agent-host sessions do not necessarily share the same loading and serialization path. Preserve the existing single-session export and import format, and do not broaden this issue into backup, restore, workspace migration, or cross-machine synchronization tracked by https://github.com/microsoft/vscode/issues/326268.
- **Open decisions:**
  - Should bulk export include every non-archived session shown for the workspace, including contributed and agent-host providers, or only locally stored VS Code chat sessions?
  - Should the command always export separate files into a selected folder, or offer a zip archive as an alternative user-visible output mode?

## Evidence

- **current implementation:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts registers only `workbench.action.chat.export`; its handler reads `IChatWidgetService.lastFocusedWidget`, obtains that single model, and writes one `model.toExport()` result.
- **zip capability:** src/vs/workbench/contrib/chat/electron-browser/actions/chatExportZip.ts also exports only the focused model, and its `workbench.action.chat.exportAsZip` command is gated to internal entitlement; it does not provide bulk workspace export.
- **session enumeration boundary:** src/vs/workbench/contrib/chat/common/chatSessionsService.ts exposes `getChatSessionItems(...)` and `getChatSessionHistory(...)`, while archived state is represented on session items and in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts. Bulk export therefore must define which session providers belong to the current workspace.
- **related issue:** https://github.com/microsoft/vscode/issues/326268 is open and requests broader export, import, backup, and workspace-migration support, including exporting all workspace sessions. It was created after this re-reviewed issue and covers additional observable behavior, so it cannot be the older same-symptom canonical required for a duplicate close.
- **canonical search:** Searches for open issues covering bulk chat export, exporting all chat sessions, and chat-session backup found no older open canonical that owns this request.
