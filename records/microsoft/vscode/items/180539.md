# Issue #180539 — TreeError [SearchView] Unknown compressed tree node

[https://github.com/microsoft/vscode/issues/180539](https://github.com/microsoft/vscode/issues/180539)

## Summary

Team-authored error-telemetry issue. The search view's tree refresh has been significantly reworked with throttling and `hasNode` guards (commits 84f4e213b63, 0729b0fb6f8), which likely mitigate this race condition, but no commit directly references #180539 so cannot propose a completed close for this team-authored item.

## Change summary

The search view's compressed tree throws 'Unknown compressed tree node' when `setChildren` is called with an element that was removed from the tree before the refresh completed.

## Best solution

Verify via error telemetry whether this error still fires on recent builds. If the throttle refactor (#231533) and `hasNode` guard (#231399) eliminated the race, close as fixed. If it still fires, the remaining unguarded path is in `RefreshTreeController.refreshTree` where `updateChildren(element)` can still hit a stale node — add a `hasNode` check or catch-and-ignore the TreeError there.
