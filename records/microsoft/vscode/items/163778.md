# Issue #163778 — Support file paths as links even when outside the workspace

[https://github.com/microsoft/vscode/issues/163778](https://github.com/microsoft/vscode/issues/163778)

## Summary

Keep this accepted request open: current Output link detection still requires a literal workspace-root prefix, so ordinary paths outside the workspace remain unsupported. Related open requests cover different capabilities, while maintainers have consolidated additional outside-workspace reports here.

## Change summary

Detect clickable file paths in Output channels even when they lie outside the workspace or use a different spelling of a workspace path.

## Best solution

Extend Output's built-in path-link coverage beyond literal workspace-root prefixes while preserving responsive processing of large output channels. Settle whether broader detection is enabled by default or opt-in, and coordinate remote file-URI handling with the related request without conflating the two scopes.

## Evidence

- **Current capability gap:** src/vs/workbench/contrib/output/common/outputLinkComputer.ts: OutputLinkComputer.computePatterns builds patterns only from workspace folders; createPatterns prepends the escaped literal workspace path to every pattern. $computeLinks iterates only those patterns. This excludes ordinary outside-workspace paths and the comment's /path/to/others/../workspace/file spelling before resource normalization can occur.
- **Provider boundary and existing capabilities:** src/vs/workbench/contrib/output/browser/outputLinkProvider.ts: updateLinkProviderWorker registers the Output/Log provider only when workspace folders exist, and OutputLinkWorkerClient supplies only those folders to $setWorkspaceFolders. Output configuration and command registrations in output.contribution.ts expose no broader path-detection switch. DocumentLinkProvider can supply extension-specific links, but does not provide automatic built-in detection for arbitrary channel output.
- **Maintainer classification:** The supplied discussion at https://github.com/microsoft/vscode/issues/163778 records bpasero's 2022-11-10 classification as a feature request because workspace-only detection is intentional, historically for performance reasons. The 2023-12-15 comment adds a concrete alternate-path-spelling case and suggests an opt-in switch; neither that switch nor default broader detection is an agreed design.
