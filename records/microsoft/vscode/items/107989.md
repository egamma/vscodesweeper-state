# Issue #107989 — Add when clause context for language at active cursor

[https://github.com/microsoft/vscode/issues/107989](https://github.com/microsoft/vscode/issues/107989)

## Summary

Keep this accepted feature request open: current source still exposes the document language, not the embedded language at the cursor, to when clauses. The 47 upvotes and concrete keybinding examples support planning the context-key contract; no verified canonical or landed implementation was found.

## Change summary

Expose the language ID at the active cursor position as a when-clause context so keybindings can distinguish embedded languages within one document.

## Best solution

Provide a cursor-language context alongside the unchanged editorLangId, allowing keybindings to combine embedded-language and outer-document conditions. Agree on its selection and tokenization semantics without implying that language-specific commands automatically understand arbitrary host documents.

## Plan brief

- **Likely files:** `src/vs/editor/common/editorContextKeys.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`
- **Validation:** Add editor context-key tests using a tokenized model with distinct host and embedded language IDs: move the primary cursor between regions and verify the agreed context value while editorLangId remains unchanged. Cover token updates at a stationary cursor, model replacement/removal, and the agreed multi-selection behavior; manually verify two commands sharing one shortcut dispatch by embedded-language conditions.
- **Behavior:**

  > Users need when clauses to distinguish the language at the active cursor from the document's outer language. A shortcut should be able to select different commands in host and embedded regions while retaining editorLangId for outer-document restrictions. Acceptance should cover crossing language boundaries, tokenization updates without cursor movement, model changes, and the agreed behavior for multiple selections. This feature does not make command handlers aware of arbitrary embedding syntax.
- **Trace:**

  > EditorModeContext in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts binds EditorContextKeys.languageId and assigns model.getLanguageId(), so the existing context remains document-wide. TextModel.getLanguageIdAtPosition delegates to TokenizationTextModelPart.getLanguageIdAtPosition, which obtains a language ID from line-token metadata; comment and snippet code already use that internal capability. extensions/typescript-basics/package.json supplies the JSX embedded-language mappings mentioned in the discussion. Preserve existing editorLangId semantics, provider availability checks, and command behavior; this is a context exposure request, not universal embedded-language formatting or execution. The remaining uncertainty is the new public context's behavior for multiple selections and unavailable or pending tokenization. The maintainer's host-document concern is recorded at https://github.com/microsoft/vscode/issues/107989#issuecomment-947516033.
- **Open decisions:**
  - For multiple selections spanning different languages, should the context report the primary cursor's language or indicate that the selection is mixed?
  - When embedded-language tokenization is unavailable or pending, should the context temporarily report the document language or an explicit unknown value?

## Evidence

- **Existing capability does not cover the request:** src/vs/editor/common/editorContextKeys.ts declares editorLangId as the editor's language identifier. In src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts:2327-2408, EditorModeContext binds that key and assigns model.getLanguageId(); its update subscriptions cover model/language and provider changes, not a cursor-dependent language value. The inspected context registrations contain no equivalent cursor-language key.
- **Embedded-language information already exists internally:** src/vs/editor/common/model/textModel.ts:2104-2105 delegates getLanguageIdAtPosition to tokenization. src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts:362-365 resolves the language from the token at the supplied position. Comment commands and snippetVariables.ts consume this information, but those internal behaviors do not expose it to when clauses.
