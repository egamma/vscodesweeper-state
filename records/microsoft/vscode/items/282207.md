# Issue #282207 — Specify GitHub Copilot LLM specifically for summarizing conversation history

[https://github.com/microsoft/vscode/issues/282207](https://github.com/microsoft/vscode/issues/282207)

## Summary

A real gap remains: current main has no user-facing summarization-model setting, and agent background compaction still invokes the active chat endpoint. A newer issue requests substantially the same capability, but because this re-reviewed issue is older it should remain the consolidation point rather than being closed as its duplicate.

## Change summary

Allow users to select a dedicated language model for conversation summarization instead of always using the active chat model.

## Best solution

Define one model-selection contract covering automatic, background, foreground, and manual compaction, with a documented default and fallback when the selected model is unavailable or incompatible. Consolidate the newer request at https://github.com/microsoft/vscode/issues/320346 into this older issue.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`, `extensions/copilot/package.nls.json`, `extensions/copilot/src/platform/configuration/common/configurationService.ts`, `extensions/copilot/src/extension/intents/node/agentIntent.ts`, `extensions/copilot/src/extension/prompt/node/summarizer.ts`, `extensions/copilot/src/extension/intents/node/test/agentSummarizeCommand.spec.ts`
- **Validation:** Add endpoint-provider tests demonstrating that a configured summarization model receives automatic and manual compaction requests while the selected chat model continues handling ordinary turns, plus coverage for the unset and unavailable-model fallback behavior.
- **Behavior:**

  > Users can designate a model for conversation compaction independently of the model handling ordinary chat turns. The chosen model is used consistently for the compaction operations included in the agreed scope, while existing behavior remains the default when no preference is configured. If the selected model cannot be used, the product follows a documented, observable fallback rather than leaving the conversation stuck. Acceptance tests must distinguish the endpoint receiving compaction from the endpoint receiving normal agent requests.
- **Trace:**

  > Automatic agent compaction flows through `AgentIntentInvocation._startBackgroundSummarization` in extensions/copilot/src/extension/intents/node/agentIntent.ts and currently sends the request through `this.endpoint`, the active conversation endpoint. `ChatSummarizerProvider.provideChatSummary` in extensions/copilot/src/extension/prompt/node/summarizer.ts instead obtains the fixed internal `copilot-utility-small` endpoint, so summarization paths already differ. Configuration declarations expose compaction enablement, threshold, and mode in extensions/copilot/package.json and configurationService.ts, but no model selector. Preserve prompt-compaction semantics, summary persistence, and ordinary chat model selection; the uncertainty is the public scope and fallback contract, not whether the capability is currently present. The newer matching request is https://github.com/microsoft/vscode/issues/320346.
- **Open decisions:**
  - Should one preference govern automatic background/foreground compaction and explicit `/compact`, or should users be able to choose models for those operations independently?
  - Should the default remain the active chat model, use a VS Code-managed utility model, or vary by compaction path?
  - When the configured model is unavailable or lacks required context/tool capabilities, should compaction fall back to the active model, a managed utility model, or stop with an actionable error?

## Evidence

- **current source:** extensions/copilot/src/extension/intents/node/agentIntent.ts uses `this.endpoint.makeChatRequest2` in `_startBackgroundSummarization`, so agent compaction continues to use the active conversation endpoint.
- **different summarization path:** extensions/copilot/src/extension/prompt/node/summarizer.ts selects the internal `copilot-utility-small` endpoint in `ChatSummarizerProvider.provideChatSummary`; this is fixed internally rather than selected by the user and does not cover the AgentIntent compaction path.
- **configuration gap:** extensions/copilot/package.json exposes enablement, threshold, and summarization-mode settings, but no setting for selecting a summarization model.
