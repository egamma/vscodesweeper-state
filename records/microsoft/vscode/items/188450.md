# Issue #188450 — Allow different indentation settings in sections of the file

[https://github.com/microsoft/vscode/issues/188450](https://github.com/microsoft/vscode/issues/188450)

## Summary

Keep this accepted Backlog request open: current indentation settings and APIs remain document-wide, so they cannot preserve tabs outside an embedded YAML block while inserting spaces inside it. The request has 30 upvotes, and the older related issues inspected do not cover the same observable behavior.

## Change summary

Allow sections of a single document, such as embedded YAML in a Vue SFC, to use different indentation settings.

## Best solution

Design region-aware indentation options in the editor core, with a supported way for embedded-language tooling to identify the applicable settings. Preserve document-wide defaults outside configured regions and define how selections spanning regions behave.

- **Reason:** A missing core indentation contract for embedded-language tooling supports language experiences and extension authors without requiring a Vue-specific feature in the default editor.

Include simultaneous cursors in both regions and the maintainer-selected cross-region selection behavior. Manually verify the supplied Vue custom-block example with detection disabled and document-wide insertSpaces false.
- **Behavior:**

  > A Vue SFC can retain tab indentation in its ordinary blocks while using spaces in an embedded YAML custom block. Pressing Tab inside that configured YAML region must not insert an indentation tab, and pressing Tab outside it must retain the document's existing behavior. Acceptance checks should exercise both locations and simultaneous cursors, without converting unrelated existing text. The design must specify how a selection spanning regions is indented.
- **Trace:**

  > ModelService.getCreationOptions in src/vs/editor/common/services/modelService.ts resolves indentation settings for one model language and resource. CursorConfiguration in src/vs/editor/common/cursorCommon.ts copies those model-wide options, and TabOperation in src/vs/editor/common/cursor/cursorTypeEditOperations.ts uses the same insertSpaces value across selections, including its literal-tab branch. TextEditorOptions in src/vscode-dts/vscode.d.ts likewise has no regional options contract. This establishes the limitation from source, but not the product contract for identifying regions or resolving overrides. Preserve existing document-wide defaults, ordinary Tab behavior and unrelated text; replacing the entire file's indentation style does not satisfy the request. The existing controller tests in src/vs/editor/test/browser/controller/cursor.test.ts provide a validation starting point. https://github.com/microsoft/vscode/issues/73559 is related embedded-language work, not a duplicate of this regional whitespace-style request.
- **Open decisions:**
  - Should regional indentation follow recognized embedded-language settings automatically, be explicitly supplied by extensions for ranges, or support both with defined precedence over document options?
  - What indentation behavior should apply to a selection spanning regions with different indentation settings?
