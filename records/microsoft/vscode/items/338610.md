# Issue #338610 — CustomExecution task terminals bypass the shell executeCommand guard

[https://github.com/microsoft/vscode/issues/338610](https://github.com/microsoft/vscode/issues/338610)

## Summary

Confirmed in source: the CustomExecution branch of terminalTaskSystem.ts omits `type: TaskTerminalType` on its shellLaunchConfig, so mainThreadTerminalShellIntegration's `instanceSupportsExecuteCommandApi` guard (which checks `shellLaunchConfig.type !== 'Task'`) never fires for custom-execution task terminals. Real, well-diagnosed bug; stays open pending a fix.

## Change summary

executeCommand() on a CustomExecution task terminal's shellIntegration returns a shell execution instead of throwing, letting command text reach a task-owned pseudoterminal as input.

## Best solution

Add `type: TaskTerminalType` to the shellLaunchConfig object built for RuntimeType.CustomExecution in terminalTaskSystem.ts (around line 1534-1545) so it matches the ProcessExecution/Shell path, closing the guard bypass.

## Evidence

- **guard check:** src/vs/workbench/api/browser/mainThreadTerminalShellIntegration.ts:141-143 — `instanceSupportsExecuteCommandApi` returns `instance.shellLaunchConfig.type !== 'Task'`.
- **normal task path sets type:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1207 — `_createShellLaunchConfig` (used for Shell/ProcessExecution tasks) sets `const type = TaskTerminalType;` and includes it in the returned config.
- **CustomExecution path omits type:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1533-1545 — the RuntimeType.CustomExecution branch builds shellLaunchConfig with `isFeatureTerminal: true` but no `type` field, so the guard's `!== 'Task'` check evaluates true and lets executeCommand through.
- **related open PR:** https://github.com/microsoft/vscode/pull/338611 ("terminal: release consumed shell execution output") references this issue but per the issue body addresses an independent terminal-stream retention concern, not this specific type-guard bypass; no merged fix commit exists on main.
