# Issue #341326 — Agents window: Claude shows no models for a normal claude.ai login (account check ignores OAuth login), and SDK is never re-downloaded after an update

## Summary

Keep open for the SDK-update/download problem: current main has download-consent and setup guidance, but this report postdates the earlier fix and its steps suffice to retest. The separate claude.ai subscription rejection is intentional under the maintainer-confirmed integration restriction, not an account-detection fix to implement.

## Change summary

Claude becomes unavailable after an SDK-version update, and existing claude.ai subscription logins produce an empty native model catalog.

## Best solution

Verify that an SDK-version update leaves a reachable download or first-use setup path, independently of account eligibility. Preserve the current subscription-authentication restriction unless the integration agreement changes, and distinguish that restriction from a missing SDK in setup guidance.

- **Behavior:**

  > After an application update changes the pinned Claude SDK version, users must not need to manually extract SDK archives or create completion markers. A missing SDK must have a reachable setup path, with progress and refreshed availability after installation. Verify both first-time setup and previously consented downloads. An installed SDK must remain distinguishable from an unsupported claude.ai subscription login; this work does not enable subscription authentication.
- **Trace:**

  > The original report describes a local macOS cache containing only the previous SDK version, repeated passive deferrals, and no visible download trigger. Current ClaudeAgent._refreshModels skips native enumeration when canLoadWithoutDownload is false, then refreshes AgentSdkSetupChannel. The earlier setup change is https://github.com/microsoft/vscode/commit/e3c3c4524e85a24bbe0066cee5cfe3c6c0ec8532, but it predates the affected build and is not a verified resolution here. Keep the subscription-account predicate outside this diagnosis: https://github.com/microsoft/vscode/issues/333738#issuecomment-5737308066 establishes the restriction, and https://github.com/microsoft/vscode/pull/334233 already contains the alternative proposal. Additional remote-connection setup is separately reported at https://github.com/microsoft/vscode/issues/339496 and must not be assumed to explain the local case.
