# Issue #307533 — Sessions: Pinning while in progress removes pin after completed

[https://github.com/microsoft/vscode/issues/307533](https://github.com/microsoft/vscode/issues/307533)

## Summary

The defect remains source-reproducible on current main: pin state is stored under the in-progress draft's session ID, but draft graduation replaces it with a committed session ID without migrating that list-owned state.

## Change summary

A session pinned while its first turn is in progress loses the pin and returns to its project group after becoming a committed session.

## Best solution

Preserve the pinned state when an in-progress draft graduates into its committed session, while leaving explicit unpinning, grouping, archiving, and definitive-deletion cleanup unchanged.

- **Trace:**

The Copilot Chat provider's first-send path in src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts replaces the untitled draft with a committed session through `onDidReplaceSession`; SessionsManagementService then refreshes the list with the old session removed and the replacement changed. ## Evidence

- **current source path:** src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts fires `onDidReplaceSession` with the draft and committed sessions after the first request materializes the committed resource; the two sessions can have different IDs.
- **root cause:** src/vs/sessions/services/sessions/browser/sessionsListModelService.ts stores pins in `_pinnedSessionIds` keyed by `session.sessionId` and subscribes to `onDidChangeSessions` and `onDidDeleteSession`, but not `onDidReplaceSession`. The committed replacement therefore does not inherit the draft ID's pin.
- **observable outcome:** src/vs/sessions/services/sessions/browser/sessionsManagementService.ts reports a replacement with the old session in `removed` and the committed session in `changed`; src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts recomputes placement through `isSessionPinned`, so the replacement falls back to its project/workspace section.
- **canonical search:** No older open issue with the same pin-loss-on-completion symptom was found. https://github.com/microsoft/vscode/issues/304046 concerned only the visual indication of pinned sessions, while https://github.com/microsoft/vscode/issues/318552 is newer and requests an in-session pin action.
