# Issue #203841 — Git - Display blame information in the editor gutter

[https://github.com/microsoft/vscode/issues/203841](https://github.com/microsoft/vscode/issues/203841)

## Summary

Keep open: built-in blame annotations still cover selected lines at the end of the text, not whole-file blame in the gutter. Maintainers explicitly distinguished and accepted the gutter work; 50 upvotes support retaining it in the Backlog.

## Change summary

Display whole-file Git blame metadata alongside the corresponding lines in the editor gutter.

## Best solution

Provide an on-demand whole-file gutter blame view in the built-in Git experience, preserving existing inline and status-bar blame. Settle its presentation and interaction contract with the Git and editor owners before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/blame.ts`, `extensions/git/package.json`, `src/vscode-dts/vscode.d.ts`
- **Validation:** After agreeing on the presentation, open a tracked file containing multiple commits, activate whole-file blame, and verify that metadata appears beside all visible lines without moving the caret. Scroll, edit and stage lines to check alignment and uncommitted attribution; disable the view and confirm existing inline/status-bar blame and editor gutter controls remain functional.
- **Behavior:**

  > Users can inspect Git blame for a whole file alongside its lines in the editor gutter rather than moving the caret to inspect each line individually. Metadata remains aligned while scrolling and reflects committed versus uncommitted lines. Existing inline and status-bar blame remain available with their current behavior. Acceptance must include a multi-commit file, scrolling, working-tree edits and staged edits; the presentation and activation contract must be agreed first.
- **Trace:**

  > GitBlameController in extensions/git/src/blame.ts retrieves and caches resource blame, maps working-tree/index changes, then reduces presentation data to active selection lines in _updateTextEditorBlameInformation. GitBlameEditorDecoration renders after-text annotations at end-of-line ranges; extensions/git/package.json exposes only editor-decoration and status-bar blame controls. The distinction from whole-file gutter blame is explicit at https://github.com/microsoft/vscode/issues/205424#issuecomment-2242566431. The public decoration contract in src/vscode-dts/vscode.d.ts offers gutter icons and before/after attachments, but the trace does not establish a suitable textual gutter column. Preserve current inline/status-bar semantics, change decorations and editor gutter interactions. Uncertainty begins at the user-visible gutter layout and activation contract, not at whether selected-line annotations already satisfy the request.
- **Open decisions:**
  - Should whole-file blame use a dedicated expandable gutter column or a separate blame editor presentation?
  - How should users activate and dismiss whole-file blame, and should that state persist per editor or across reloads?
  - Which metadata and commit interactions should the gutter expose while preserving line numbers, folding controls and change indicators?
