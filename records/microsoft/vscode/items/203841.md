# Issue #203841 — Git - Display blame information in the editor gutter

[https://github.com/microsoft/vscode/issues/203841](https://github.com/microsoft/vscode/issues/203841)

## Summary

Keep open: built-in blame annotations still show information after selected lines or in the status bar, not in a multi-line editor gutter. The request has 50 upvotes and explicit maintainer interest; it needs a gutter interaction design rather than closure against the completed inline-blame feature.

## Change summary

Display Git blame metadata alongside multiple lines in the editor's left gutter.

## Best solution

Provide an on-demand gutter blame view in the built-in Git experience, retaining normal editing and existing blame surfaces. Agree how metadata shares space with line numbers, change indicators, and breakpoint controls before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/blame.ts`, `extensions/git/package.json`
- **Validation:** After design agreement, open a tracked file containing lines from several commits, activate gutter blame, and verify metadata is visible beside multiple lines without moving the caret. Check scrolling, wrapped lines, uncommitted edits, and coexistence with line numbers, change indicators, and breakpoints; deactivation must restore the normal editor layout and existing inline/status-bar blame must remain functional.
- **Behavior:**

  > Users need to inspect blame metadata for multiple lines simultaneously on the left side of the editor, rather than moving the caret to obtain each line's metadata. Existing end-of-line decorations and the status bar do not satisfy that goal. Acceptance should demonstrate correct line-to-commit alignment while scrolling and editing, with normal editor controls still usable. The presentation and activation contract require maintainer agreement.
- **Trace:**

  > GitBlameController._updateTextEditorBlameInformation in extensions/git/src/blame.ts retrieves resource blame information but constructs the displayed LineBlameInformation array only for active selection lines. GitBlameEditorDecoration renders that array through after decorations at end-of-line ranges; configuration in extensions/git/package.json exposes only editor-decoration and status-bar surfaces. The remaining work is explicitly separated from inline blame in https://github.com/microsoft/vscode/issues/203841#issuecomment-2504138588 and awaits further context in https://github.com/microsoft/vscode/issues/203841#issuecomment-3632091661. Preserve existing inline/status-bar behavior and commit-to-line correctness. The trace establishes the capability gap, not whether a suitable gutter surface can be delivered through the existing extension API; investigate that boundary during planning without assuming a core-editor change is necessary.
- **Open decisions:**
  - What metadata and grouping should the gutter display, and how should it coexist with line numbers, change indicators, and breakpoint controls?
  - How should users activate and dismiss gutter blame, and should its enabled state survive switching files or reloading the window?
