# Issue #334581 — Thinking level is not supported for this model (Gemini 2.5 Pro)

[https://github.com/microsoft/vscode/issues/334581](https://github.com/microsoft/vscode/issues/334581)

## Summary

Traced a plausible client-side bug in the BYOK Gemini native provider: it always uses the Gemini 3-style `thinkingConfig.thinkingLevel` enum whenever a model's catalog entry lists supported reasoning-effort levels, with no differentiation for Gemini 2.5-generation models, which the Gemini API rejects with exactly the reported "Thinking level is not supported for this model" error.

## Change summary

Sending any agent prompt to Gemini 2.5 Pro fails with a 400 'Thinking level is not supported for this model' error instead of a normal response.

## Best solution

In extensions/copilot/src/extension/byok/vscode-node/geminiNativeProvider.ts, only populate thinkingConfig.thinkingLevel for model generations that actually support the level-based API (e.g. Gemini 3.x), and fall back to omitting thinkingConfig (or using thinkingBudget) for Gemini 2.5-generation models like gemini-2.5-pro.
