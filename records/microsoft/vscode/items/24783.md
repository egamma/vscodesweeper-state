# Issue #24783 — vscode reads AltGr key as cursor-left move through X11 connections

[https://github.com/microsoft/vscode/issues/24783](https://github.com/microsoft/vscode/issues/24783)

## Summary

Still reproduces on current main — AltGr is misinterpreted as cursor-left in X11-forwarded and remote desktop sessions. The `keyboard.dispatch: keyCode` workaround exists but breaks other shortcuts (Ctrl+/). The issue is correctly labeled `help wanted` and remains a real gap in keyboard handling for remote Linux sessions.

## Change summary

AltGr key press is interpreted as a cursor-left movement when VS Code runs over X11 forwarding or remote desktop connections on Linux.

## Best solution

Fix the keyboard event handling in the `code` dispatch mode to correctly distinguish AltGr from arrow key events when running under X11 forwarding. The root cause is likely in how the keyboard layout service (src/vs/workbench/services/keybinding/) translates scan codes received via X11 — AltGr generates a Left key event in the `code` dispatch path. The fix should handle this without requiring users to switch to `keyCode` dispatch, which breaks other shortcuts.
