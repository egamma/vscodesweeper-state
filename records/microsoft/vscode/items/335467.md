# Issue #335467 — Add support for tmux as default shell

[https://github.com/microsoft/vscode/issues/335467](https://github.com/microsoft/vscode/issues/335467)

## Summary

Existing tmux terminal profiles do not cover using tmux as the system login shell during VS Code startup. Keep this request open: the shell-environment resolver still assumes shell-compatible command-line arguments, and no verified canonical owns this specific capability.

## Change summary

Allow VS Code to resolve its startup environment without an error when tmux is configured as the user's default system shell.

## Best solution

Establish supported startup-environment behavior for a tmux system shell in the shell-environment resolver, independently of integrated-terminal profile selection. Confirm the reporter's system-shell configuration and choose an appropriate underlying-shell resolution strategy before implementation.

## Evidence

- **Reported error:** The screenshot in https://github.com/microsoft/vscode/issues/335467 reads: "Unable to resolve your shell environment: Unexpected exit code from spawned shell (code 1, signal null)". This concerns startup environment resolution, not simply choosing an integrated-terminal profile.
- **Existing capability and its boundary:** src/vs/platform/terminal/common/terminalPlatformConfiguration.ts:305–307 and 355–357 already define tmux profiles for macOS and Linux; terminal.integrated.defaultProfile.osx and terminal.integrated.defaultProfile.linux select terminal profiles. These settings do not select the system shell used by startup environment resolution.
- **Current source path:** src/vs/base/node/shell.ts:getSystemShellUnixLike selects SHELL, falling back to userInfo().shell. src/vs/platform/shell/node/shellEnv.ts:doResolveUnixShellEnv uses that executable, has no tmux-specific branch, and passes ['-i', '-l', '-c'] plus a Node environment-printing command through its generic branch. A nonzero exit produces the exact error shown in the screenshot. This establishes a missing compatibility path, but no runtime reproduction was performed.
- **Candidate canonical excluded:** https://github.com/microsoft/vscode/issues/195768 is open but concerns fish profile discovery and default selection, including Homebrew PATH lookup. Its report does not establish ownership of startup environment resolution when tmux itself is the system shell.
- **Distinct tmux request:** https://github.com/microsoft/vscode/issues/90696 is open and requests tmux control-mode integration with native tabs, panes, and persistent sessions. That capability would not by itself resolve this report's startup environment error.
- **Readiness evidence:** The issue has no comments, community upvotes, or linked implementation candidate. The source identifies the compatibility boundary, but the intended environment source when the system shell is tmux is not established.
