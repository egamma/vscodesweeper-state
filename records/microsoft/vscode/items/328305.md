# Issue #328305 — new profile that use extensions from default profile  will enable extensions that disabled in default profile

[https://github.com/microsoft/vscode/issues/328305](https://github.com/microsoft/vscode/issues/328305)

## Summary

Current main reproduces the reported state mismatch: sharing the Default profile's extension manifest does not share or initialize its disabled-extension state. This should be routed to User Profiles to define and implement consistent enablement inheritance.

## Change summary

A profile using extensions from the Default profile starts extensions that are disabled in the Default profile as enabled.

## Best solution

When creating a profile that uses the Default profile's extensions, initialize or resolve extension enablement consistently from the Default profile while preserving the intended profile-specific override model. The change belongs in the user-profile creation and profile-scoped extension enablement integration.
