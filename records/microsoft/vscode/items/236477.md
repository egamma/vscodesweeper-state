# Issue #236477 — Debug: Search inside collapsed nodes

[https://github.com/microsoft/vscode/issues/236477](https://github.com/microsoft/vscode/issues/236477)

## Summary

Keep open: this accepted Backlog request has 26 community upvotes, and searching recursively through variables that have not been expanded remains a meaningful debugger capability gap.

## Change summary

Add Debug Variables filtering that searches names and values inside collapsed object and collection nodes.

## Best solution

Define a Debug Adapter Protocol-backed recursive variable-search capability so adapters can search lazily loaded children without forcing the client to expand and fetch an unbounded object graph, then expose it through the Variables view.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/variablesView.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/debug/common/debugModel.ts`, `src/vs/workbench/contrib/debug/common/debugProtocol.d.ts`
- **Validation:** Add debugger tests using a mock adapter with nested, initially unexpanded variables; searching must return matching descendant names and values without prior expansion, respect the agreed result and traversal limits, and leave ordinary Variables expansion unchanged.
- **Behavior:**

  > The Debug Variables view should be able to find matching variable names and values beneath collapsed nodes without requiring users to expand the object graph first. Search must remain responsive for large or cyclic structures and clearly communicate partial or bounded results. Existing expansion, paging, and evaluation behavior must remain unchanged when search is inactive.
- **Trace:**

  > The Variables view owns the user-facing tree, while variable children are supplied lazily by the debug adapter through the debug model and protocol declarations. A client-only filter cannot inspect descendants that have not been requested, and recursively issuing ordinary variables requests risks unbounded traversal, expensive evaluations, and adapter-specific behavior. Keep the scope to Variables-tree search and its adapter contract; Data Wrangler export and console serialization are workarounds, not part of this feature. No older issue reporting the same observable symptom was identified in the supplied related-item data.
- **Open decisions:**
  - Should recursive search be a new optional Debug Adapter Protocol request implemented by adapters, or may VS Code traverse ordinary variables requests client-side when an adapter lacks search support?
  - What user-visible limits apply to depth, result count, latency, cancellation, and cyclic object graphs, and how should truncated results be indicated?
  - Should results match names, rendered values, or both, and should matching descendants be shown in a flattened result list or by revealing their ancestor paths?
