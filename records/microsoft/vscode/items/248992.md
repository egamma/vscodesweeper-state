# Issue #248992 — error in processing .gitignore file

[https://github.com/microsoft/vscode/issues/248992](https://github.com/microsoft/vscode/issues/248992)

## Summary

The defect remains source-reproducible on current main: in a multi-root workspace, the Explorer applies a root `.gitignore` rule matching the root folder's name to the rendered workspace-root node itself, causing that node to disappear. The same folder works when opened alone because a single-folder Explorer does not render that root as a filterable tree element.

## Change summary

Keep an added workspace folder visible when its own `.gitignore` contains an entry matching the folder name, while still hiding a same-named file inside it.

## Best solution

The Explorer's gitignore filtering must never exclude the workspace-root node based on that root's own `.gitignore`; matching descendants, including the same-named build artifact, should remain excluded.

## Evidence

- **source reproduction:** In src/vs/workbench/contrib/files/browser/views/explorerViewer.ts, FilesFilter.isVisible passes every rendered ExplorerItem, including a multi-root workspace-root item, to isIgnored; isIgnored then finds that root's IgnoreFile and calls isPathIncludedInTraversal for the root resource itself.
- **matching behavior:** In src/vs/workbench/services/search/common/ignoreFile.ts, a slashless entry such as `XYZ_component` becomes `**/XYZ_component`, which matches the `/.../XYZ_component` workspace-root path as well as the intended same-named child file. There is no guard excluding the IgnoreFile's own directory from matching.
