# Issue #339204 — Add integrated browser support for new permissions-based Domain rules (Local and Agent Host)

[https://github.com/microsoft/vscode/issues/339204](https://github.com/microsoft/vscode/issues/339204)

## Summary

Freshly filed, team-authored security gap report; confirmed from source that AgentNetworkFilterService only reads legacy ChatAgentNetworkFilter/AllowedNetworkDomains/DeniedNetworkDomains settings and has no knowledge of managed permissions.deny/allow Domain rules, so a managed restriction can be bypassed via the integrated browser. Security-sensitive and team-authored — hard keep-open rules both apply; no fix has landed.

## Change summary

The integrated browser's network filter only honors legacy ChatAgentNetworkFilter settings, not newer policy-managed permissions.deny/allow Domain rules, letting a managed block be bypassed via browser navigation.

## Best solution

Extend AgentNetworkFilterService (or its browser-facing caller) to also consult the managed permissions Domain rules alongside the legacy allow/deny lists, ensuring managed denies always win, without turning permissions.allow into a mandatory safelist for manual browsing.
