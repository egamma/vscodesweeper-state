# Issue #55075 — Show Opening Tag when Closing Tag Selected

[https://github.com/microsoft/vscode/issues/55075](https://github.com/microsoft/vscode/issues/55075)

## Summary

Keep this accepted backlog request open: Sticky Scroll provides useful context but does not guarantee a preview of the opening tag or block corresponding to the closing delimiter at the cursor. Maintainers explicitly consolidated related reports here; the remaining cursor-triggered preview warrants an editor design session.

## Change summary

Show an off-screen matching opening tag or block header in a compact preview when the cursor is beside its closing delimiter.

## Best solution

Provide a cursor-triggered editor preview of the exact matching opening context, including standalone-brace and multiline headers, without requiring navigation away from the closing delimiter. Settle its interaction with Sticky Scroll before implementing language-consistent support for tags and brackets.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/contrib/stickyScroll/browser/stickyScrollController.ts`, `src/vs/editor/contrib/stickyScroll/browser/stickyScrollModelProvider.ts`, `src/vs/editor/common/config/editorOptions.ts`, `extensions/emmet/src/matchTag.ts`
- **Validation:** Validate with a long nested HTML document and brace-based Rust or TypeScript sample: scroll the relevant opener out of view, place the caret beside the closing delimiter, and verify that the preview identifies its exact opening context without scrolling or moving the caret. Include nesting beyond the Sticky Scroll line limit, a brace on its own line, multiline headers, visible openers, and Sticky Scroll enabled and disabled.
- **Behavior:**

  > When the cursor is beside a closing tag or bracket whose opening context is off screen, the editor should expose that exact opening context without moving the cursor or scrolling the document. For an opening brace on its own line, the preview should include the preceding header; multiline conditions should retain the context requested in the discussion. Deep nesting must not cause the selected pair's header to disappear behind unrelated scope headers or a sticky-line limit. Acceptance should cover HTML tags and brace-based code, with visible openers and both Sticky Scroll states.
- **Trace:**

  > BracketMatchingController in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts already computes matching bracket ranges on cursor changes but only creates decorations; its navigation actions move the cursor and reveal the destination. StickyScrollController.findScrollWidgetState selects headers from viewport-intersecting candidates up to a configured limit, while StickyModelProvider derives candidates from outline or folding models, so neither establishes a caret-specific preview. HTML tag navigation is separately available through Emmet's parsed HtmlFlatNode open/close ranges in extensions/emmet/src/matchTag.ts; that command is not itself a general editor preview provider. The unresolved technical boundary is a language-consistent source of matching tags and meaningful header spans alongside ordinary bracket matching. Preserve existing matching, navigation and Sticky Scroll behavior. Related guide-hover design is tracked at https://github.com/microsoft/vscode/issues/134888; the older consolidated request remains https://github.com/microsoft/vscode/issues/55075.
- **Open decisions:**
  - When Sticky Scroll already displays the exact matching opening context, should the cursor-triggered preview be suppressed or still appear?
  - Should cursor-triggered opening-context previews be enabled by default or require an explicit editor setting?

## Evidence

- **Accepted demand:** https://github.com/microsoft/vscode/issues/55075 has 57 community upvotes and the Backlog milestone; the April 2021 bot comment explicitly records promotion after sufficient community support.
- **Existing capability is partial:** src/vs/editor/common/config/editorOptions.ts registers editor.stickyScroll.enabled, editor.stickyScroll.maxLineCount and editor.stickyScroll.defaultModel. StickyScrollController.findScrollWidgetState in src/vs/editor/contrib/stickyScroll/browser/stickyScrollController.ts:616–650 selects viewport-intersecting scope headers and stops at the sticky-line limit; it does not select the matching opener from the caret position. StickyModelProvider uses outline, syntax-folding or indentation models rather than exact cursor-selected tag matching.
- **Current matching commands do not preview:** BracketMatchingController._recomputeBrackets and _updateBrackets in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts find matching ranges and apply decorations, not an opening-context preview. editor.action.jumpToBracket changes selection and reveals the destination. Likewise, editor.emmet.action.matchTag in extensions/emmet/src/matchTag.ts changes selection and calls revealRange; it is a navigation workaround, not the requested stationary preview.
- **Discussion distinguishes the remaining gap:** The supplied February 2024 comments identify Sticky Scroll as a native workaround, but the March 2024 comment explains that it can display unnecessary lines or omit the relevant header in deeply nested code, and reports inadequate Rust support in the suggested extensions. Earlier discussion also distinguishes breadcrumbs from block-header context and requests preceding or multiline header text.

Its primary request concerns modifier-assisted hover on bracket or indentation guides, with later comments also requesting caret-triggered previews.
