# Issue #44711 — Provide activation reason to extensions in activate call

[https://github.com/microsoft/vscode/issues/44711](https://github.com/microsoft/vscode/issues/44711)

## Summary

A real API gap remains on current main, and this accepted Backlog request has 21 community upvotes. Keep it open for API design rather than closing or reclassifying it.

## Change summary

Expose why an extension was activated so it can tailor initialization to the triggering command, language, workspace match, or other cause.

## Best solution

Design an extension API that exposes the triggering activation event while representing restarts, dependencies, imperative activation, and future causes without a closed enumeration. The API should preserve useful event-specific context where available, such as a command identifier or matched workspace resource.
