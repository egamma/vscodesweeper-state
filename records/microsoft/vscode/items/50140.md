# Issue #50140 — Support syntax highlighting with tree-sitter

[https://github.com/microsoft/vscode/issues/50140](https://github.com/microsoft/vscode/issues/50140)

## Summary

Keep open: current main has experimental Tree-sitter highlighting for bundled languages, but not the extension grammar contribution support central to this request. The existing area labels are appropriate, and 738 upvotes demonstrate substantial demand.

## Change summary

Allow language extensions to contribute Tree-sitter grammars for syntax highlighting alongside TextMate grammars.

## Best solution

Define a supported extension contribution contract for Tree-sitter grammars and highlighting queries, building on the existing tokenizer while preserving TextMate compatibility. Coordinate that contract with the ongoing exploration rather than treating bundled-language experiments as completion of this request.

  > Thanks for the context. Experimental Tree-sitter highlighting is available for bundled languages through settings such as `editor.experimental.preferTreeSitter.typescript` and `editor.experimental.preferTreeSitter.css`. That does not yet let language extensions contribute their own Tree-sitter grammars and highlighting queries, so this request remains open. Related implementation progress is tracked in https://github.com/microsoft/vscode/issues/210475.

## Plan brief

- **Likely files:** `src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts`, `src/vs/workbench/services/textMate/common/TMGrammars.ts`, `src/vs/editor/common/services/treeSitter/treeSitterLibraryService.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/common/model/tokens/treeSitter/treeSitterSyntaxTokenBackend.ts`, `src/vs/workbench/test/electron-browser/treeSitterTokenizationFeature.test.ts`
- **Validation:** The plan should establish an extension-host acceptance scenario: install an extension contributing a custom-language Tree-sitter grammar and highlighting queries, open and edit a file, and verify syntax colors update without a TextMate grammar. Repeat with an existing TextMate-only extension to verify unchanged behavior, and exercise grammar selection according to the agreed contract.
- **Behavior:**

  > Language-extension authors should be able to reuse a Tree-sitter grammar for native syntax highlighting without also maintaining a TextMate grammar or a custom semantic-token adapter. Contributed highlighting must update after edits and remain compatible with the agreed theme mapping. Existing TextMate-only extensions must continue working unchanged. Acceptance should include a custom-language extension whose packaged grammar and queries work through normal extension installation.
- **Trace:**

  > TreeSitterLibraryService currently resolves grammar WASM from the bundled @vscode/tree-sitter-wasm package and highlighting/injection queries from editor resources, rather than extension contributions. TokenizationTextModelPart already selects TreeSitterSyntaxTokenBackend according to supportsLanguage; that backend obtains the grammar and queries through ITreeSitterLibraryService. The contributes.grammars schema in TMGrammars.ts remains explicitly TextMate-oriented. This establishes a native implementation foundation but leaves the author-facing contribution contract undefined. Preserve existing TextMate contributions and avoid expanding this request into folding, indentation, or general syntax-tree access. Coordinate with https://github.com/microsoft/vscode/issues/210475, whose discussion anticipates contributed SCM files but does not settle the public contract.
- **Open decisions:**
  - What public manifest contract should extensions use to contribute Tree-sitter grammar WASM and highlighting/injection queries, including supported grammar compatibility versions?
  - When a language has both TextMate and Tree-sitter grammars, what user-visible selection and fallback behavior should apply, and how should competing extension contributions be resolved?
