# Issue #50140 — Support syntax highlighting with tree-sitter

[https://github.com/microsoft/vscode/issues/50140](https://github.com/microsoft/vscode/issues/50140)

## Summary

Keep open: current main has experimental Tree-sitter highlighting for four bundled languages, but it does not yet provide the general grammar contribution model requested here. The Backlog request has 739 community upvotes, and the newer exploration issue documents that the remaining design work is still active rather than completed.

## Change summary

Support Tree-sitter grammars as an alternative syntax-highlighting source alongside TextMate grammars.

## Best solution

Finish the Tree-sitter tokenization architecture with a supported contribution model for language grammars and highlighting queries, while preserving TextMate fallback and existing theme behavior. Coordinate that design with the ongoing exploration at https://github.com/microsoft/vscode/issues/210475.

## Plan brief

- **Likely files:** `src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts`, `src/vs/editor/common/services/treeSitter/treeSitterLibraryService.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/workbench/test/electron-browser/treeSitterTokenizationFeature.test.ts`
- **Validation:** Extend the Tree-sitter tokenization integration tests to load a contributed test grammar and highlighting query, verify expected tokens after initial parsing and incremental edits, and verify TextMate fallback when no Tree-sitter contribution is available.
- **Behavior:**

  > Language support can supply a Tree-sitter grammar and highlighting queries as an alternative to a TextMate grammar. Files using that language receive correct initial and incremental syntax highlighting while retaining compatibility with existing color themes. Languages without a Tree-sitter contribution continue using their existing TextMate tokenization without behavior changes. Invalid or unavailable Tree-sitter contributions fail safely and preserve the fallback tokenizer.
- **Trace:**

  > Current tokenization selects TreeSitterSyntaxTokenBackend from src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts when ITreeSitterLibraryService reports support. TreeSitterLibraryService in src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts currently derives support from experimental per-language settings, loads only bundled WASM files, and reads bundled .scm queries from src/vs/editor/common/languages. The parser, incremental tree, token store, and theme mapping already exist; the uncertainty begins at the contribution and lifecycle boundary needed to make grammars available beyond the four bundled experiments. Preserve TextMate fallback, semantic-token layering, and existing theme scope behavior. Coordinate the plan with https://github.com/microsoft/vscode/issues/210475; the earlier exploratory PR https://github.com/microsoft/vscode/pull/161479 is closed and unmerged.
- **Open decisions:**
  - Should the supported end state expose Tree-sitter grammars to extensions, remain limited to grammars bundled by VS Code, or provide both with different trust and compatibility guarantees?
  - What public contribution contract should define grammar WASM resources, highlight and injection queries, language identifiers, versioning, and failure fallback?
  - Should contributed Tree-sitter highlighting be explicitly selected per language or automatically preferred when available, and how should that choice interact with TextMate and semantic tokens?

## Evidence

- **partial implementation:** Current main contains a Tree-sitter token backend under src/vs/editor/common/model/tokens/treeSitter/ and switches to it from src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts when the language-specific experimental setting is enabled.
- **limited language scope:** src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts hard-codes css, typescript, ini, and regex support and loads their WASM grammars from VS Code's bundled @vscode/tree-sitter-wasm resources.
- **experimental surface:** src/vs/editor/common/config/editorConfigurationSchema.ts exposes editor.experimental.preferTreeSitter.css, .typescript, .ini, and .regex, all defaulting to false; current source therefore provides neither general nor stable Tree-sitter grammar support.
- **remaining contribution model:** The open exploration https://github.com/microsoft/vscode/issues/210475 explicitly lists designing a contribution model among its goals, confirming that the central extension-facing capability remains unresolved.
- **re-review duplicate bar:** https://github.com/microsoft/vscode/issues/210475 was created in 2024, after this 2018 issue, so it cannot be the canonical duplicate for this re-reviewed item. The older https://github.com/microsoft/vscode/issues/216 is broader and asks for alternatives to TextMate tokenizers generally, not the same specific Tree-sitter grammar support.
- **community demand:** The issue has 739 community upvotes and is assigned to the Backlog milestone, well above the feature-request promotion threshold.
