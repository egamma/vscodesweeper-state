# Issue #50140 — Support syntax highlighting with tree-sitter

[https://github.com/microsoft/vscode/issues/50140](https://github.com/microsoft/vscode/issues/50140)

## Summary

Keep open: experimental Tree-sitter highlighting exists for selected bundled languages, but extension authors still lack general grammar contribution support. The newer exploration issue records progress, not grounds to close this re-reviewed request.

## Change summary

Support Tree-sitter grammars for syntax highlighting alongside TextMate grammars.

## Best solution

Complete the extension-facing Tree-sitter grammar and highlighting-query contribution story while retaining TextMate compatibility. Coordinate the public contract and remaining work with https://github.com/microsoft/vscode/issues/210475 rather than treating its limited built-in support as completion.

## Plan brief

- **Likely files:** `src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts`, `src/vs/workbench/services/textMate/common/TMGrammars.ts`, `src/vs/editor/common/services/treeSitter/treeSitterLibraryService.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/common/config/editorConfigurationSchema.ts`
- **Validation:** The plan should define a desktop-and-web extension fixture contributing a non-bundled Tree-sitter grammar and highlighting queries. Verify initial highlighting and incremental edits, theme compatibility, and unchanged TextMate highlighting when Tree-sitter is not selected.
- **Behavior:**

  > Language extension authors should be able to provide Tree-sitter grammars and highlighting queries for syntax highlighting without maintaining a parallel TextMate grammar solely for VS Code. Selected bundled-language experiments do not satisfy this authoring requirement. Acceptance should demonstrate a non-bundled language supplied by an extension, correct highlighting after edits, and continued TextMate behavior for languages not using Tree-sitter.
- **Trace:**

  > TreeSitterLibraryService in src/vs/workbench/services/treeSitter/browser/treeSitterLibraryService.ts loads bundled WASM grammars and built-in query files; it currently has no extension resource discovery on that path. The experimental settings in src/vs/editor/common/config/editorConfigurationSchema.ts cover CSS, TypeScript, INI and regex. TokenizationTextModelPart already chooses Tree-sitter or the existing tokenizer backend, while contributes.grammars in src/vs/workbench/services/textMate/common/TMGrammars.ts remains TextMate-specific. The remaining uncertainty is the public contribution and selection contract, not whether Tree-sitter infrastructure exists. Preserve TextMate compatibility and existing themes; folding, indentation and general syntax-tree APIs are outside this syntax-highlighting request. Coordinate with https://github.com/microsoft/vscode/issues/210475, whose discussion explicitly leaves extension contributions unfinished, and the broader API discussion at https://github.com/microsoft/vscode/issues/216.
- **Open decisions:**
  - What public extension manifest contract should expose Tree-sitter grammar, highlighting-query and injection-query resources?
  - When both TextMate and Tree-sitter grammars are available for a language, what determines selection and how can users override it?
