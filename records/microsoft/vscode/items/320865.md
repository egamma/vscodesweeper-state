# Issue #320865 — FLAC files open as binary instead of Media Preview

[https://github.com/microsoft/vscode/issues/320865](https://github.com/microsoft/vscode/issues/320865)

## Summary

The reported association defect remains in current main: Audio Preview excludes .flac files despite the release notes explicitly listing FLAC preview support. Keep this open; the source confirms a registration gap, not a missing codec.

## Change summary

Make FLAC files discoverable and openable through the built-in Audio Preview editor.

## Best solution

Bring the built-in media-preview editor association into agreement with documented FLAC support while preserving existing audio associations and explicit text-editor choices.

## Evidence

- **Current source confirms the trigger:** In extensions/media-preview/package.json, vscode.audioPreview has builtin priority but its sole filenamePattern is *.{mp3,wav,ogg,oga}. Opening a .flac file therefore does not match this editor's contributed selector.
- **Editor resolution path:** src/vs/workbench/contrib/customEditor/browser/customEditors.ts:170–177 registers editors with their contributed filenamePattern. CustomEditorInfo.matches in src/vs/workbench/contrib/customEditor/common/customEditor.ts likewise requires a matching selector, confirming the missing FLAC association in source.
- **Documented intended behavior:** https://code.visualstudio.com/updates/v1_72#_builtin-preview-for-some-audio-and-video-files explicitly lists FLAC among supported audio preview formats. https://code.visualstudio.com/updates/v1_71#_ffmpeg-codecs-support also documents FLAC codec support; both sections were checked against the release-note source.
- **Existing playback path:** extensions/media-preview/src/audioPreview.ts registers vscode.audioPreview and passes the resource URI to its webview. extensions/media-preview/media/audioPreview.js constructs an HTML Audio object from that URI without an additional filename-extension allowlist. Actual FLAC playback was not executed.
- **Canonical and implementation search:** Repository searches for FLAC and audio/media preview found no verified canonical for this association defect. https://github.com/microsoft/vscode/issues/167685 concerns AAC audio in MP4 webviews, while https://github.com/microsoft/vscode/issues/147190 concerns accessibility audio cues; neither reports the same symptom. The issue timeline contained no linked implementation, and an open-PR search for FLAC returned none.
