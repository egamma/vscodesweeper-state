# Issue #334167 — Primary Side Bar width resets after toggling visibility (Ctrl+B)

[https://github.com/microsoft/vscode/issues/334167](https://github.com/microsoft/vscode/issues/334167)

## Summary

Genuine, widely-confirmed regression in 1.136.x: the Primary Side Bar's custom width is not restored after Ctrl+B toggling, reproduced by multiple independent reporters with extensions disabled, and already established as the canonical for at least three other duplicate reports — this stays open pending a maintainer fix, not a triage close.

## Change summary

Toggling the Primary Side Bar hidden/visible with Ctrl+B resets its width to the minimum instead of restoring the previously dragged width.

## Best solution

Investigate the sidebar visibility/width restore path around `setSideBarHidden` and `workbenchGrid.setViewVisible` in src/vs/workbench/browser/layout.ts together with the splitview's `cachedVisibleSize` handling in src/vs/base/browser/ui/splitview/splitview.ts — several commenters report the new 'Layout Density: Compact' / Modern UI setting masks the bug, suggesting the regression is tied to a recently-added layout-density/floating-panels code path interacting with cached-size restoration.
