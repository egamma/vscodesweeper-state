# Issue #334167 — Primary Side Bar width resets after toggling visibility (Ctrl+B)

[https://github.com/microsoft/vscode/issues/334167](https://github.com/microsoft/vscode/issues/334167)

## Summary

Fresh, well-documented regression: two independent commenters (Linux Mint and macOS, extensions disabled) confirm the exact same 100%-reproducible repro of the primary side bar losing its custom width whenever it's toggled via Ctrl+B, and one notes it's new versus 1.135.x. This needs a real triage/fix, but with only a single-commit shallow checkout here I can't diff against the pre-regression state to pinpoint the exact commit or file.

## Change summary

After manually widening the Primary Side Bar, hiding and re-showing it with Ctrl+B resets it back to minimum/default width instead of preserving the custom size.

## Best solution

A maintainer (or someone with full history) should bisect 1.135.x → 1.136.0 around the sidebar visibility/grid-resize path (src/vs/workbench/browser/layout.ts `setSideBarHidden`/`workbenchGrid.setViewVisible`, and the cached-visible-size handling in src/vs/base/browser/ui/splitview/splitview.ts) to find what changed; the abstract cached-visible-size mechanism itself looks sound on current main, so the regression is likely in something that resizes/re-triggers layout around the toggle (e.g. viewlet activation or the newer floating-panels/Modern UI work) rather than the core splitview logic.
