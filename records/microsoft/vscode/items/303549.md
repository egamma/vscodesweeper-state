# Issue #303549 — GitHub Copilot 1.112 severely reduces usefulness of context window meter.

[https://github.com/microsoft/vscode/issues/303549](https://github.com/microsoft/vscode/issues/303549)

## Summary

Verified duplicate: the older open context-widget issue tracks the same user-visible problem—the displayed percentage does not correspond to the point where compaction occurs. This report adds useful evidence about the separately rendered response reserve but requires no distinct implementation.

## Change summary

Include the response-token reserve in the context meter's reported utilization so the percentage indicates proximity to compaction.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/293125 and make the context widget communicate effective capacity consistently, either by incorporating the response reserve into its headline percentage or displaying the reserve and compaction threshold quantitatively.
