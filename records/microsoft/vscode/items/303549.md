# Issue #303549 — GitHub Copilot 1.112 severely reduces usefulness of context window meter.

[https://github.com/microsoft/vscode/issues/303549](https://github.com/microsoft/vscode/issues/303549)

## Summary

Current main intentionally reports only consumed tokens in the headline percentage while rendering the response reserve as a separate band, so the reported usability gap remains. Route this to the context-widget owners for a product decision about whether the primary meter should represent actual usage or effective capacity before compaction.

## Change summary

Make the context-window meter account numerically for tokens reserved for the response so it communicates proximity to compaction.

## Best solution

Have the headline meter communicate effective available capacity by incorporating the remaining response reserve, while retaining the detailed breakdown that distinguishes consumed tokens from reserved tokens. The label and accessible description should make those semantics explicit.
