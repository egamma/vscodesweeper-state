# Issue #311029 — Agents: Session scoping

[https://github.com/microsoft/vscode/issues/311029](https://github.com/microsoft/vscode/issues/311029)

## Summary

Keep open as a team-authored Agents Window UX request. Current main has improved workspace selection and out-of-workspace file visibility, but no issue-referencing fix establishes the intended behavior when an existing session starts operating on another repository.

## Change summary

Prevent or correctly handle reusing a locally scoped agent session for a cloud repository so files, changes, and PR behavior follow the active repository.

## Best solution

Give each session an explicit repository/workspace boundary and require a new session or deliberate retargeting when work moves elsewhere. The Agents Window should then refresh file/change tracking for that target and avoid committing directly to a protected default branch.
