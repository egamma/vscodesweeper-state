# Issue #242764 — editor.setDecorations does not render all contentText correctly

[https://github.com/microsoft/vscode/issues/242764](https://github.com/microsoft/vscode/issues/242764)

## Summary

Distinct decoration texts still collide in the current editor's render-option subtype cache, causing later labels to reuse earlier content. Keep this accepted editor-core bug open; the source establishes a bounded defect with an executable regression check.

## Change summary

Ensure distinct before.contentText values render their own labels when supplied through editor.setDecorations.

## Best solution

Decoration subtype identity must distinguish unequal render options even when their hashes collide, while retaining reuse for equivalent options and correct cleanup across updates and editors.
