# Issue #350225 — Agents window: agent feedback comment stays on its original line after the agent edits the file, and is still submitted for a deleted file

[https://github.com/microsoft/vscode/issues/350225](https://github.com/microsoft/vscode/issues/350225)

## Summary

Keep open: current source preserves the original feedback range through subsequent edits and submits accepted comments without checking whether their files still exist. This affects both the displayed anchor and the location delivered to the agent.

## Change summary

Keep agent feedback anchors valid after file edits and prevent deleted-file comments from being submitted as current line-specific feedback.

## Best solution

Give feedback an explicit validity contract across edits and deletion, shared by its editor presentation, submission eligibility, and agent-visible representation. Preserve comment text while distinguishing trustworthy current locations from outdated context.

- **Validation:** Extend agentFeedbackService.test.ts and agentFeedbackEditorWidgetContribution.test.ts with the reported sequence: comment on line 2, insert two lines and rewrite the target, then delete the file and submit. Run those suites through ./scripts/test.sh with targeted --run selectors; assert that displayed and submitted locations agree with the chosen validity contract and deleted-file feedback is not delivered as an ordinary current range.
- **Behavior:**

  > An unsubmitted feedback comment must not silently point to unrelated code after another agent turn edits its file. After inserting two header lines, the comment must either identify the appropriate current code location or clearly indicate that its context is outdated. After deletion, the comment must be flagged or excluded from normal submission rather than delivered with an apparently valid current range. Comment text must remain recoverable, and unaffected comments must retain normal submission behavior.
- **Trace:**

  > AgentFeedbackEditorWidgetContribution builds widgets from stored feedback ranges and does not observe model content edits to reconcile those ranges. AgentFeedbackEditorWidget uses the stored range for its line label, highlighting, and positioning. AgentFeedbackService.submitFeedback selects accepted items without validating their resource or context; AnnotationsAgentFeedbackItemsBackend round-trips the range, and serializeComment in agentFeedbackServerTools.ts returns it to the agent unchanged apart from coordinate conversion. IAgentFeedback currently has lifecycle state and captured codeSelection but no explicit outdated-anchor state. The trace establishes the defect without execution; the unresolved boundary is the observable treatment of rewritten and deleted targets, not which helper implements it. Preserve session routing, feedback authorship, comment text, and unrelated submission-failure recovery.
- **Open decisions:**
  - When the commented code is rewritten, should feedback track a confidently mapped replacement or become explicitly outdated, and can outdated feedback still be submitted?
  - For a deleted file, should feedback be excluded from Submit Feedback or remain explicitly submittable as deleted-file context without claiming a current line range?
