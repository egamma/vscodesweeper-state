# Issue #196510 — Attempting to open a large file crashes vscode

[https://github.com/microsoft/vscode/issues/196510](https://github.com/microsoft/vscode/issues/196510)

## Summary

The large-file crash remains credibly reproduced and correctly routed to the text-buffer area. Current main still allows local files below 1 GB to bypass confirmation, including the reported 710 MB file.

## Change summary

Opening a very large local text file can freeze and crash the VS Code window before any size warning appears.

## Best solution

Keep this as the canonical crash report and make large-file admission respect realistic renderer heap requirements, either by lowering or dynamically calculating the confirmation threshold and by avoiding full-memory representations. Coordinate the deeper text-buffer work with https://github.com/microsoft/vscode/issues/167719.

## Evidence

- **current source:** src/vs/platform/files/common/files.ts sets the local large-file confirmation limit to 1024 MB, while src/vs/workbench/common/editor/resourceEditorInput.ts applies that limit when resolving files. The reported 710 MB file therefore bypasses confirmation on current main.
- **continued reproduction:** https://github.com/microsoft/vscode/issues/196510#issuecomment-3499040475 reports the same failure with extensions disabled in VS Code 1.105.1.
- **independent confirmations:** https://github.com/microsoft/vscode/issues/196510#issuecomment-2567209557 reports that increasing Chromium's memory allowance works around the failure, and https://github.com/microsoft/vscode/issues/196510#issuecomment-2839688004 independently confirms that workaround.
