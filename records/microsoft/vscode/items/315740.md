# Issue #315740 — `Go to symbol` open to side button does nothing

[https://github.com/microsoft/vscode/issues/315740](https://github.com/microsoft/vscode/issues/315740)

## Summary

The mismatch remains on current main: Go to Symbol still offers an Open to the Side button, while the Agents Window single-pane editor deliberately rejects creation of a side editor group. The later split-tracking issues are younger than this re-reviewed report, so neither qualifies as its duplicate canonical.

## Change summary

The Go to Symbol quick pick exposes an Open to the Side action in the Agents Window even though activating it cannot open a side editor group.

## Best solution

Align the symbol picker's affordance with the Agents Window layout contract: either suppress Open to the Side while single-pane splitting is unsupported, or make it create a real side group when the broader split-support work is implemented.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts`, `src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoSymbolQuickAccess.ts`, `src/vs/sessions/browser/parts/singlePaneEditorPart.ts`
- **Validation:** Add a targeted quick-access test proving that, under the chosen single-pane contract, triggering the symbol item's side action either is not offered or opens a distinct editor group; normal Go to Symbol navigation and standard-workbench side opening must remain unchanged.
- **Behavior:**

  > In the Agents Window, every action presented by Go to Symbol must perform the behavior its label promises. When the active layout does not support editor groups, the picker must not present an Open to the Side action that silently reuses the current group. Ordinary symbol navigation must continue to select the requested symbol, and Open to the Side must remain available and functional in workbench layouts that support splitting.
- **Trace:**

  > AbstractGotoSymbolQuickAccessProvider in src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts unconditionally adds the side-opening item button when `openSideBySideDirection` has a value. GotoSymbolQuickAccessProvider in src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoSymbolQuickAccess.ts handles that button by opening the active editor with `SIDE_GROUP`. In the Agents Window single-pane layout, SinglePaneMainEditorPart.addGroup in src/vs/sessions/browser/parts/singlePaneEditorPart.ts returns the existing group, deliberately preventing the requested split. Commit 49f9fd4a2882d883c707a83cb792209494927506 established that restriction, and https://github.com/microsoft/vscode/issues/331469 tracks eventual full split support. Keep standard workbench behavior and the separate Sessions chat grid out of scope.
- **Open decisions:**
  - While the Agents Window single-pane layout intentionally supports only one editor group, should Go to Symbol omit Open to the Side, or should this issue remain blocked on implementing real editor splitting through https://github.com/microsoft/vscode/issues/331469?

## Evidence

- **current source:** src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts adds the Open to the Side item button whenever `openSideBySideDirection` is configured, and src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoSymbolQuickAccess.ts routes it through `IEditorService.openEditor(..., SIDE_GROUP)` without checking whether the active editor part supports another group.
- **single-pane restriction:** src/vs/sessions/browser/parts/singlePaneEditorPart.ts returns the existing group from `addGroup`, while src/vs/sessions/LAYOUT.md explicitly states that the single-pane main editor rejects open-to-side and programmatic group-creation requests.
- **later partial fix:** Commit 49f9fd4a2882d883c707a83cb792209494927506 (https://github.com/microsoft/vscode/commit/49f9fd4a2882d883c707a83cb792209494927506) disabled unsupported editor splits, but the verification discussion at https://github.com/microsoft/vscode/issues/331470#issuecomment-5399118448 confirms that Open to the Side remained visible and did not open a side group.
- **related future work:** https://github.com/microsoft/vscode/issues/331469 is open and tracks full split/grid support, but it was created after this issue and therefore cannot be the duplicate canonical under the re-review policy.
