# Issue #130208 — Ctrl+f overwrites X11's Primary selection buffer.

[https://github.com/microsoft/vscode/issues/130208](https://github.com/microsoft/vscode/issues/130208)

## Summary

Keep open: current source still programmatically selects the seeded Find input, matching the reported Electron/X11 PRIMARY-selection problem. The suggested settings are partial workarounds, and no verified fix or eligible older open canonical was found.

## Change summary

Preserve Linux PRIMARY selection when opening Find or Search automatically selects a prefilled query.

## Best solution

Resolve the Electron/X11 behavior that publishes programmatic input selections to PRIMARY while preserving normal mouse-selection copying and Find's select-to-replace interaction. Distinguish that input behavior from VS Code's explicit publication of editor selections when navigating search matches.

Its discussion reports persistence with Electron 37.2.3 in August 2025.

Current src/vs/editor/common/config/editorOptions.ts:1820–1829 accepts 'selection' and 'never' rather than the historical comment's 'none'. These settings change seeding, not the native input-selection behavior, and do not guarantee preservation when Find contains an existing query.
