# Issue #336919 — Closing and reopening vscode with an undocked chat window will reopen a completely blank window instead of the chat

[https://github.com/microsoft/vscode/issues/336919](https://github.com/microsoft/vscode/issues/336919)

## Summary

Keep open: current source can still select and reveal a restored auxiliary chat editor before establishing that it resolved successfully, matching the reported blank-window failure. The related merged PR protects session data during moves but does not test or directly repair restart restoration.

## Change summary

Reopening VS Code after moving a chat to an auxiliary window can leave that session reopening as a completely blank, unusable window.

## Best solution

Make restored auxiliary chat editors recover safely: reopening the session must display its chat, or discard an unresolved stale editor and open a valid replacement. Cover the close/restart/reopen lifecycle rather than only the in-process move.
