# Issue #274867 — Bracket Pair Colorization misinterprets double braces {{ }} in Twig templates

[https://github.com/microsoft/vscode/issues/274867](https://github.com/microsoft/vscode/issues/274867)

## Summary

Keep open while the explicitly linked implementation PR is reviewed. Multi-character bracket support already exists, but the requested default template-language coverage is not fully provided by the current configurations.

## Change summary

Color Twig expression, statement, and comment delimiters as atomic bracket pairs rather than nested individual braces.

## Best solution

Review https://github.com/microsoft/vscode/pull/320527 against all three requested delimiter pairs and the actual Twig language configuration. Preserve ordinary nested-brace behavior in non-template languages rather than applying template delimiter recognition indiscriminately.

- **Existing capability:** src/vs/editor/common/config/editorConfigurationSchema.ts registers editor.language.colorizedBracketPairs, and src/vs/editor/common/languages/languageConfigurationRegistry.ts reads it with a language override. LanguageBracketsConfiguration in src/vs/editor/common/languages/supports/languageBracketsConfiguration.ts accepts multi-character pairs; BracketTokens.getRegExpStr in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts orders configured alternatives so {{ is matched before {. The central engine therefore does not lack multi-character delimiter support.
- **Current default coverage:** extensions/handlebars/language-configuration.json already registers {{/}} and {{{/}}} in brackets. extensions/html/language-configuration.json registers individual braces and explicitly sets colorizedBracketPairs to an empty array; it does not register the three requested Twig delimiter pairs. Existing configuration support is a workaround, not automatic Twig coverage, and the claimed identical HTML result is not established by this source.
- **Discussion and scope boundary:** The contributor comment on https://github.com/microsoft/vscode/issues/274867 supplies language-configuration pairs for {{/}}, {%/%}, and {#/#}, consistent with the source-supported mechanism. The later comment reports the reverse problem for consecutive closing braces in a mathematical expression; that cautions against treating repeated braces as template delimiters across all languages.
