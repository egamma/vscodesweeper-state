# Issue #287159 — Git - checkout picker should display git worktree information

[https://github.com/microsoft/vscode/issues/287159](https://github.com/microsoft/vscode/issues/287159)

## Summary

The Git checkout picker still lacks worktree information before selection. Keep this accepted, team-authored request open; existing conflict prompts do not cover it, and no eligible canonical or explicitly linked fix was found.

## Change summary

Display worktree information alongside relevant branches in the Git checkout picker.

## Best solution

Make branch-to-worktree associations understandable before a user selects a checkout target, with branch identity remaining primary and worktree context secondary. Agree on the information displayed while preserving existing checkout and conflict-handling behavior.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/api/git.d.ts`
- **Validation:** In a repository with a main checkout and a linked worktree on another branch, open Git: Checkout to... and verify the agreed worktree context is visible before selection. Repeat with git.showReferenceDetails enabled and disabled, confirm an unassociated branch remains distinguishable, and verify branch selection, remote/tag entries and existing worktree-conflict actions retain their behavior.
- **Behavior:**

  > The Git checkout picker should expose worktree context for associated branches before the user chooses a target. Today it displays branch and commit information, with worktree conflicts explained only after selection. Acceptance should verify the agreed information for associated and unassociated branches with reference details both enabled and disabled. Existing checkout behavior and conflict recovery remain unchanged.
- **Trace:**

  > Commands._checkout in extensions/git/src/commands.ts builds its rows through createCheckoutItems, CheckoutRefProcessor and CheckoutItemsProcessor. CheckoutItem inherits BranchItem and RefItem presentation, which contains no worktree association; the processor only adds remote-action buttons. Repository.getWorktrees in extensions/git/src/repository.ts and Worktree in extensions/git/src/api/git.d.ts provide the relevant name, path, ref, main and detached data. The source establishes the missing display capability, but the title-only request does not settle which worktree fields users should see. Keep the scope within the built-in Git checkout picker: do not change checkout semantics, worktree lifecycle or Agents Window surfaces. https://github.com/microsoft/vscode/issues/336620 is related orientation work, not a canonical for this request.
- **Open decisions:**
  - Should associated branch rows show only that the branch is checked out in a worktree, or also identify that worktree by name or filesystem path?
