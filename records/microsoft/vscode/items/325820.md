# Issue #325820 — Inconsistent transient retry handling and unnecessary Content-Length header in AgentHost networking

[https://github.com/microsoft/vscode/issues/325820](https://github.com/microsoft/vscode/issues/325820)

## Summary

Confirmed real bugs on main and the author already has an open PR fixing both with regression tests — keep open until that PR lands rather than closing as implemented.

## Change summary

AgentHostRequestService doesn't retry ECONNRESET/EPIPE/ETIMEDOUT for idempotent requests, and OtlpHttpForwarder's Fetch path manually sets the forbidden Content-Length header.

## Best solution

Land the author's own PR https://github.com/microsoft/vscode/pull/325821, which adds the three error codes to TRANSIENT_ERROR_CODES in agentHostRequestService.ts and drops the manual content-length header from the fetch branch in outboundForwarder.ts, plus tests.

## Evidence

- **retry gap confirmed:** src/vs/platform/agentHost/node/agentHostRequestService.ts lines 18-26 define TRANSIENT_ERROR_CODES containing EAI_AGAIN, ECONNREFUSED, EHOSTDOWN, EHOSTUNREACH, ENETDOWN, ENETUNREACH, EPROTO — ECONNRESET/EPIPE/ETIMEDOUT are absent, so isTransientError() (line 30) returns false for them and the retry loop (line 76) treats them as terminal even for idempotent GET/HEAD/OPTIONS requests.
- **content-length confirmed:** src/vs/platform/otel/node/otlp/outboundForwarder.ts _sendOnce() sets 'content-length': String(body.length) in both the fetch() headers object and the http.request() headers object; Fetch treats Content-Length as a forbidden header that runtimes compute automatically, so only the http.request() path should set it explicitly.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/325821 (same author, 'Fixes #325820') adds the three codes to TRANSIENT_ERROR_CODES and removes content-length from the fetch branch, with regression tests in agentHostRequestService.test.ts and outboundForwarder.test.ts. It is still OPEN, not merged.
