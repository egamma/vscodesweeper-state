# Issue #22917 — `editor.fontFamily` in settings should suggest list of available monospace fonts

[https://github.com/microsoft/vscode/issues/22917](https://github.com/microsoft/vscode/issues/22917)

## Summary

Keep open: current source provides installed-font suggestions for JSON settings, but neither monospace filtering nor a font picker in the graphical Settings editor. The thread explicitly reopened this request to preserve its monospace-specific scope and community support.

## Change summary

Suggest available monospace fonts when editing editor.fontFamily so users do not have to discover and type exact font names.

## Best solution

Provide discoverable monospace-font suggestions for editor.fontFamily while preserving manually entered font families and fallback lists. Coordinate with the general font-picker work at https://github.com/microsoft/vscode/issues/128355 without losing this request's monospace requirement.

## Evidence

- **Existing capability is partial:** src/vs/base/browser/fonts.ts implements getFonts using queryLocalFonts and maps every returned family into getFontSnippets, with no monospace classification. getFontSnippets returns no suggestions outside Electron.
- **JSON settings integration exists:** src/vs/editor/common/config/editorConfigurationSchema.ts::registerEditorFontConfigurations attaches the font snippets to editor.fontFamily.defaultSnippets. src/vs/workbench/browser/parts/editor/editor.contribution.ts calls this registration with getFontSnippets. These are suggestions for all enumerated families, not the requested monospace list.
- **Graphical Settings gap:** src/vs/workbench/contrib/preferences/browser/settingsTree.ts::AbstractSettingTextRenderer.renderTemplate constructs an ordinary InputBox; SettingTextRenderer does not consume defaultSnippets or provide a font dropdown.
