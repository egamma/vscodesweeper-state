# Issue #164008 — Custom Editor wan't activated if open the file without any running vscode app

[https://github.com/microsoft/vscode/issues/164008](https://github.com/microsoft/vscode/issues/164008)

## Summary

This is a duplicate of the better-diagnosed https://github.com/microsoft/vscode/issues/325506, which describes the same cold-start custom editor activation bug with detailed diagnostic info (forceFile/override state, activation event traces). Consolidating there.

## Change summary

Custom editors are not activated when a file is opened via CLI or shell association on a cold start (no running VS Code instance); they only activate after VS Code is already running.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/325506, which has a better diagnosis pointing to the editor resolver not having the custom editor registration ready during cold-start file resolution. The fix likely involves ensuring the `ContributedCustomEditors` memento-cached registrations (or extension point handlers) run before the initial file open is resolved in `editorResolverService`.
