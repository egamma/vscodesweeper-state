# Issue #309038 — [Unhandled Error] potential listener LEAK detected, popular

[https://github.com/microsoft/vscode/issues/309038](https://github.com/microsoft/vscode/issues/309038)

## Summary

Still reproduces on main: `NotebookOutlineRenderer.renderElement` creates a per-entry `IMenu` via `menuService.createMenu(MenuId.NotebookOutlineActionMenu, ...)`, each subscribing to the shared `PersistedMenuHideState.onDidChange` emitter. With enough visible outline entries, the listener count exceeds the leak-detection threshold. No fix has landed — the attempted PR #309157 was closed without merge.

## Change summary

Opening a notebook with many cells triggers a 'potential listener LEAK detected, popular' error in the outline panel because each visible entry independently subscribes to a shared menu-state emitter.

## Best solution

Refactor the notebook outline renderer to either share a single `IMenu` instance (swapping the scoped context per entry) or use a lazy/deferred menu pattern that avoids N simultaneous subscriptions on the shared `PersistedMenuHideState.onDidChange` emitter. The fix lives in `src/vs/workbench/contrib/notebook/browser/contrib/outline/notebookOutline.ts`, specifically the `renderElement` / `setupToolbarListeners` path.
