# Issue #337807 — Add a customization breakdown and migration explanation tooltip

[https://github.com/microsoft/vscode/issues/337807](https://github.com/microsoft/vscode/issues/337807)

## Summary

This remains a real Customizations navigation gap: current main shows only a total count and warning dot, without a hover breakdown or migration explanation. The request is aligned with the Agents experience and should stay open for the tooltip's information design to be settled.

## Change summary

Add an accessible tooltip to the Customizations navigation entry that breaks down active workspace customizations and explains its migration warning.

## Best solution

The Customizations row should expose a managed, keyboard-accessible hover that updates with the active session and harness, summarizes the enabled customizations using an agreed grouping, and includes the applicable migration explanation without requiring the management editor to be opened.

- **Behavior:**

  > The Customizations navigation entry should explain its total without requiring users to open the management editor. Its hover should identify the enabled customizations relevant to the active workspace and explain why the migration warning is present when attention is required. The same meaningful information must be available to keyboard and screen-reader users, and it must update when the active workspace, harness, counts, or migration state changes.
- **Trace:**

  > SessionSectionRenderer in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts currently renders a numeric count and an aria-hidden migration indicator, while SessionsAccessibilityProvider exposes only the total and a generic migration phrase. CustomizationsNavigationState in src/vs/sessions/contrib/sessions/browser/customizationsNavigationState.ts projects the underlying state down to `totalCount` and a migration boolean; `computeMigrationHint` returns richer information that is currently discarded. Per-section counts already come from `readCustomizationCount` and `CUSTOMIZATION_ITEMS` in src/vs/sessions/contrib/sessions/browser/customizationsToolbar.contribution.ts. Keep the existing click behavior, count semantics, harness visibility filtering, and management-editor navigation unchanged; the uncertainty is limited to the tooltip's user-visible grouping and explanation depth.
- **Open decisions:**
  - Should the breakdown group enabled customizations by type, by workspace/user provenance, or expose both dimensions?
  - Should the warning show the migration service's actionable category/count details, or a shorter generic explanation with migration details reserved for the management editor?

## Evidence
