# Issue #337807 — Add a customization breakdown and migration explanation tooltip

[https://github.com/microsoft/vscode/issues/337807](https://github.com/microsoft/vscode/issues/337807)

## Summary

Legitimate, verifiable gap: the Sessions sidebar's Customizations row (count + migration indicator) has no hover explanation today, even though the underlying breakdown and migration-hint data already exist in the model layer — this is a real, bounded polish item, not something to close.

## Change summary

Add a tooltip to the Sessions sidebar's 'Customizations' row explaining the per-category count breakdown and, when shown, the migration warning indicator.

## Best solution

Wire a hover tooltip onto the Customizations row's count/migration-indicator elements in sessionsList.ts, sourcing the breakdown from the existing CUSTOMIZATION_ITEMS/readCustomizationCount per-category counts and the migration explanation from ICustomizationMigrationService.computeMigrationHint's message, following the existing setupDelayedHover pattern already used elsewhere in this same view.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/browser/customizationsNavigationState.ts`, `src/vs/sessions/contrib/sessions/browser/customizationsToolbar.contribution.ts`
- **Validation:** A sessionsList/sessionsView test confirming the Customizations row exposes a hover with the expected breakdown text (and migration explanation text when customizationMigrationsAvailable is true).
- **Behavior:**

  > Hovering the Customizations row's count (and, when shown, its migration indicator) in the Sessions sidebar reveals a tooltip: the count tooltip lists the per-category breakdown (e.g. 'Plugins: 2, MCP Servers: 1, Skills: 3, …'); the migration-indicator tooltip explains that customization files were found that could be migrated and briefly why. Hovering elsewhere in the sidebar is unaffected, and the row's existing click/keyboard/aria-label behavior is unchanged.
- **Trace:**

  > The row is rendered in SessionSectionRenderer.renderElement() in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts (around lines 2111-2127), which already reactively updates template.count.textContent from customizationsCount and toggles template.migrationIndicator via customizationMigrationsAvailable, but sets up no hover. Per-category counts are already computed by CUSTOMIZATION_ITEMS/readCustomizationCount in customizationsToolbar.contribution.ts, and the migration explanation text is already produced by ICustomizationMigrationService.computeMigrationHint() (consumed today only as a boolean in customizationsNavigationState.ts). The boundary: do not change the count/indicator's existing update logic, click handling, or accessibility aria-labels — only add a hover surfacing data that already exists. Related pattern: src/vs/sessions/contrib/aiCustomizationTreeView/browser/aiCustomizationOverviewView.ts's setupDelayedHoverAtMouse() usage.
- **Open decisions:**
  - Should the count tooltip show a live per-category breakdown (computed reactively like the section counts) or a simpler static summary?
  - Should the migration-indicator tooltip reuse computeMigrationHint()'s actual message text (async, may need loading/caching) or a fixed generic explanation of what the indicator means?
  - Does the tooltip attach to the whole row, or separately to the count and migration-indicator sub-elements?

## Evidence

- **no tooltip today:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts renderElement() for CUSTOMIZATIONS_SECTION_ID (around line 2111-2127) sets template.count.textContent and toggles template.migrationIndicator visibility, but registers no hover/tooltip — only an aria-label is set for accessibility (lines 2549-2555).
- **breakdown data exists:** src/vs/sessions/contrib/sessions/browser/customizationsToolbar.contribution.ts exports CUSTOMIZATION_ITEMS and readCustomizationCount(), already used by readTotalCustomizationCount() to sum a per-category (plugins, MCP servers, skills, etc.) breakdown for the row's total count.
- **migration hint data exists:** src/vs/sessions/contrib/sessions/browser/customizationsNavigationState.ts calls migrationService.computeMigrationHint(), which (per test/common/chatService/chatService.test.ts) already produces a descriptive message and per-category counts — currently only reduced to a boolean (migrationAvailableValue) for the indicator, discarding the explanatory message.
- **existing pattern to follow:** src/vs/sessions/contrib/aiCustomizationTreeView/browser/aiCustomizationOverviewView.ts already uses hoverService.setupDelayedHoverAtMouse() for a similar section-row tooltip, showing the intended UI pattern is established in this codebase.
