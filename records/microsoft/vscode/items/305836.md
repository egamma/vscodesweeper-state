# Issue #305836 — chatImplicitContext: chatContextService return values bypass ignore policy; setValues() lacks staleness guard

[https://github.com/microsoft/vscode/issues/305836](https://github.com/microsoft/vscode/issues/305836)

## Summary

Current main still has a source-confirmed ignore-policy gap for provider-supplied implicit context, so the issue remains necessary. The claimed monotonic accumulation is not supported because setValues() disposes the previous map, although redundant rebuilding may still cause avoidable churn.

## Change summary

Ensure contributed implicit chat context respects ignored-file policy and avoid unnecessary replacement of unchanged implicit-context entries.

## Best solution

Define and enforce ignore semantics for contributed tab context before it reaches ChatImplicitContexts, covering both text-editor and webview paths, with regression tests proving ignored resources cannot supply model context. Treat equality-based setValues() suppression as a separate bounded performance improvement rather than a memory-leak fix.

- **webview path:** The same file assigns webview context to newValue at lines 259-264, while line 272 deliberately derives no URI for StringChatContextValue, so the fileIsIgnored() gate does not inspect either its triggering uri or optional resourceUri.
- **provider resolution:** src/vs/workbench/contrib/chat/browser/contextContrib/chatContextService.ts constructs StringChatContextValue with both the triggering uri and optional provider resourceUri, and later resolves its model-facing value through the provider; neither stage applies ILanguageModelIgnoredFilesService.
- **accumulation claim refuted:** ChatImplicitContexts.setValues() in src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts calls _values.clearAndDisposeAll() before rebuilding entries, so old ChatImplicitContext instances and their DisposableStores are disposed rather than accumulated. Repeated equivalent assignments still rebuild the collection and fire onDidChangeValue.
