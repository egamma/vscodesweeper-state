# Issue #341839 — Allow create_session to set the mode / approval level of the new session (e.g. Autopilot / auto-approve)

[https://github.com/microsoft/vscode/issues/341839](https://github.com/microsoft/vscode/issues/341839)

## Summary

Thanks for the detailed request. The gap is real on current main: the `create_session` schema has no mode or approval parameter, and nothing in the independent-session path copies the creator's approval level. A maintainer needs to choose the shape first: explicit parameters, inheritance, or both, with a never-escalate rule.

## Change summary

Let `create_session` set, or inherit from its creator, the mode and approval level (e.g. Autopilot / auto-approve) of the session it creates.

## Best solution

Extend `create_session` in sessionServerTools.ts so a new session or chat starts with an approval level no higher than its creator's, inherited by default or set through an optional capped parameter. Show the resulting level in the Agents window straight away.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/shared/sessionServerTools.ts`, `src/vs/platform/agentHost/test/node/sessionServerTools.test.ts`
- **Validation:** A sessionServerTools test showing that a session created via `create_session` gets the creator's approval level, or an explicit lower one, and that a request above the creator's level is rejected or clamped.
- **Behavior:**

  > A session created with `create_session` starts at an approval level and mode chosen by the creator, never higher than the creator's own. If nothing is specified, it behaves as the maintainers decide: inherit or default. The Agents window shows the new session's level immediately. Existing calls without the new options keep working.
- **Trace:**

  > `create_session` is defined and handled in src/vs/platform/agentHost/node/shared/sessionServerTools.ts: the input schema, `getCreateSessionArgs`, and the handler that builds `IAgentCreateSessionConfig` for independent sessions. The handler only inherits `defaults.config` for a same-provider source, and `currentSession` chats use the per-chat `chatMutable` config path described in AGENTS.md §8f. What I did not establish is how approvals are keyed in `chatMutable` config per provider (Copilot's effective approval mode, Claude's permission mode, Codex's permissions preset) or how autoApprove is represented. That mapping is where the design starts. Do not touch the provider-specific approval enforcement.
- **Open decisions:**
  - Should omitted parameters inherit the creator's mode and approval level, or keep today's defaults?
  - Should the tool accept an explicit mode and approval enum, and may it only lower the creator's level, never raise it?
  - Which approval levels and modes are expressible across providers (Copilot, Claude, Codex), and what happens if the target provider lacks the requested level?
