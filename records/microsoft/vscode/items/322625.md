# Issue #322625 — Memory str_replace tool silently drops large newString values (coerces to string "undefined")

[https://github.com/microsoft/vscode/issues/322625](https://github.com/microsoft/vscode/issues/322625)

## Summary

The report describes a plausible serialization-boundary bug where large tool parameters are silently dropped, but the root cause is ambiguous — it could be model-side (truncated JSON output), the VS Code LM API serialization layer, or the Copilot extension's parameter handling. The memory tool code itself does not validate that `new_str` is defined before passing it to `String.replace()`, which would produce the described `undefined` coercion. Keeping open; needs investigation to distinguish model-side from host-side truncation.

## Change summary

The memory tool's str_replace command silently writes the literal string "undefined" when newString exceeds ~4000–5000 characters, causing silent data loss.

## Best solution

Add a runtime guard in `_localStrReplace` (memoryTool.tsx) to reject `undefined`/empty `new_str` with an error rather than silently coercing. Then investigate whether the VS Code `LanguageModelToolCallPart` parsing path or the model itself is dropping large parameter values, and add size-limit documentation or chunking guidance to the tool schema if the limit is inherent.
