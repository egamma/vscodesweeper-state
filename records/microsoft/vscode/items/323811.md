# Issue #323811 — New chat sessions always leak

[https://github.com/microsoft/vscode/issues/323811](https://github.com/microsoft/vscode/issues/323811)

## Summary

The leak remains explicit on current main: every successful untitled-to-real contributed-session materialization acquires an `IChatModelReference` that is intentionally never disposed. Keep this team-authored bug open while designing a lifecycle handoff that does not regress first-request session preservation.

## Change summary

Release or transfer ownership of the model reference created when a new contributed chat session is materialized, without allowing the session to disappear during its first request.

## Best solution

Establish an explicit ownership handoff from `ChatService._materializeUntitledSession` to the active chat view or editor, then dispose the temporary reference once that owner has acquired its own reference. Preserve first-request session rebinding, concurrent-send serialization, and untitled-to-real resource aliasing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts`, `src/vs/workbench/contrib/chat/test/common/chatService/chatService.test.ts`
- **Validation:** Add lifecycle coverage that materializes an untitled contributed session, transfers it to each supported host, completes the first request, closes or switches the host, and asserts through `getChatModelReferenceDebugInfo()` that no materialization-owned reference remains while the active host still preserves the session; run `scripts/test.sh --grep "untitled session materialization"` plus the targeted host test.
- **Behavior:**

  > Creating the first request in an untitled contributed chat session must preserve and display the newly materialized real session. The temporary reference used during materialization must not remain after an active view or editor has assumed ownership. Switching away from or closing that owner must allow the real model to be disposed when no other legitimate references remain. Concurrent first sends must continue to create only one real session.
- **Trace:**

  > `ChatService._materializeUntitledSession` in `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` calls `loadRemoteSession`, retains the returned `tempRef`, and deliberately never disposes it. `ChatModelStore` in `src/vs/workbench/contrib/chat/common/model/chatModelStore.ts` confirms that this outstanding reference prevents model disposal. The earlier disposal and committed-session notification in 96a69e3d03d6aaaeabb60fce9ba43ab8418a6d13 were reverted by 6bc5ae80de9caffb21e9eb58e18b5ca24fa2d6e8 through https://github.com/microsoft/vscode/pull/310891 because the new session was not preserved. The editor host acquires ownership through `ChatEditorInput.updateModel`, while the view pane's ownership transition depended on the disabled committed-session event; the plan must trace both hosts and the asynchronous first-request boundary. Keep resource aliasing, input/model transfer, read-only handling, and serialized materialization behavior unchanged.

## Evidence

- **current source:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` in `_materializeUntitledSession` acquires `tempRef` through `loadRemoteSession` and explicitly says not to dispose it; the reference is neither returned nor registered with a disposable owner.
- **reference semantics:** `src/vs/workbench/contrib/chat/common/model/chatModelStore.ts` tracks every acquired reference until `dispose()` and destroys the model only after the final reference is released, so the abandoned materialization reference permanently retains its model.
- **regression history:** Commit 6bc5ae80de9caffb21e9eb58e18b5ca24fa2d6e8, merged through https://github.com/microsoft/vscode/pull/310891, intentionally removed disposal while acknowledging that this reintroduced sessions not being cleaned up; it reverted part of 96a69e3d03d6aaaeabb60fce9ba43ab8418a6d13 because disposing and firing the commit event had broken session preservation.
- **ownership gap:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts` swaps to the materialized model with `setModel`, but the widget itself does not acquire a model reference. `ChatEditorInput.updateModel` does acquire one, while `ChatViewPane` relies on the currently disabled committed-session event, so ownership differs across hosts.
- **canonical search:** No older open issue was found for the same observable per-session reference leak. https://github.com/microsoft/vscode/issues/324809 is newer and reports renderer OOM rather than this specific materialization-reference ownership defect, so it does not satisfy the stronger re-review duplicate bar.
