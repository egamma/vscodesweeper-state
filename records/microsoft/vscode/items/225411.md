# Issue #225411 — Clean up context menus

[https://github.com/microsoft/vscode/issues/225411](https://github.com/microsoft/vscode/issues/225411)

## Summary

Keep open: current source still exposes Go to actions individually and uses different clipboard/share group structures across editor and notebook menus. This team-authored design proposal has no verified complete fix or qualifying canonical duplicate; agree the remaining organization before implementing.

## Change summary

Reduce context-menu clutter and establish consistent navigation, Copy, Share, and Copilot grouping across editors and notebooks.

## Best solution

Agree a shared default grouping and ordering convention for editor and notebook context menus, then apply it without changing command behavior or extension contribution contracts. Coordinate with the related menu-structure discussion while keeping user-configurable menus a separate capability.

Verify the agreed navigation hierarchy and relative Copy/Share/Copilot placement, exercise keyboard access to moved actions, and confirm their existing command behavior and conditional visibility remain unchanged.
- **Behavior:**

  > Default editor and notebook context menus should present a clear hierarchy and predictable placement for equivalent action groups. The current proposal considers consolidating Go to actions and consistently placing Copy, Share, and Copilot toward the bottom, but the sketch is not a final specification. Acceptance requires the agreed grouping to be visible across the selected surfaces, with moved commands still reachable by keyboard and retaining their existing behavior. User-created folders and arbitrary command pinning are separate requests, not requirements of this cleanup.
- **Trace:**

  > GoToDefinitionAction and the other navigation actions in src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts still register directly in MenuId.EditorContext, while Peek has its own submenu. src/vs/editor/contrib/clipboard/browser/clipboard.ts supplies the editor clipboard and Share groups; CellOverflowToolbarGroups and the notebook Share registration in src/vs/workbench/contrib/notebook/browser/controller/coreActions.ts use a different grouping scheme, with notebook clipboard contributions in src/vs/workbench/contrib/notebook/browser/contrib/clipboard/notebookClipboard.ts. Existing per-item hiding in src/vs/platform/actions/common/menuService.ts does not establish consistent defaults. Copilot registrations and the complete set of affected surfaces have not been traced, so the plan must establish that boundary before execution. Preserve command IDs, keybindings, provider/context gating, and extension contribution contracts. Coordinate with https://github.com/microsoft/vscode/issues/255626; https://github.com/microsoft/vscode/issues/9285 remains the separate user-customization request.
- **Open decisions:**
  - Should all Go to actions move into a submenu, or should frequently used navigation actions remain at the root alongside Peek?
  - What common relative ordering should Copy, Share, and Copilot use across editor and notebook menus, and which surface-specific exceptions are intentional?
