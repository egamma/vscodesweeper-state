## Summary

Keep open as an unresolved upstream accessibility issue. Electron has an open fix candidate, while the discussion establishes that forcing NVDA to use UIA is not a generally acceptable replacement for working legacy mouse tracking.

- **Reporter narrowed the regression:** Comments 6–10 on https://github.com/microsoft/vscode/issues/277895 establish that the reporter used Mouse Enhancement, disabling UiaProvider restored that compatibility path, and forcing NVDA's Chromium UIA setting to Yes enabled native tracking but caused problems in other applications. This supersedes the body's assumption that a missing Chromium 144 fix explains the failure.
- **NVDA upstream remains unresolved:** https://github.com/nvaccess/nvda/issues/19276 is open. Its maintainer explicitly rejects switching the global default to UIA because Chromium's UIA implementation has other deficiencies: https://github.com/nvaccess/nvda/issues/19276#issuecomment-3584037731. Mouse Enhancement 0.8.2 is described only as temporary mitigation: https://github.com/nvaccess/nvda/issues/19276#issuecomment-3590931310.
- **Electron reproduction and fix candidate:** https://github.com/electron/electron/issues/42945 is open and documents a regression between Electron 30.0.0-beta.7 and beta.8 associated with https://github.com/electron/electron/pull/41256. A later standalone reproduction reports working Electron 29.4.6 and failing modern Electron, with an empty native container intercepting MSAA hit tests: https://github.com/electron/electron/issues/42945#issuecomment-5575765450.
- **Fix has not merged:** https://github.com/electron/electron/pull/53460 is OPEN with no merge commit. It targets the container hit-testing defect and reports Linux accessibility checks, but explicitly lacks Windows NVDA/Inspect.exe verification. It is an implementation candidate, not evidence of a completed fix.
