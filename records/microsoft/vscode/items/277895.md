## Evidence

- **Reporter-confirmed configuration dependency:** In https://github.com/microsoft/vscode/issues/277895, comments dated November 21–24, 2025 confirm that disabling UiaProvider restores the Mouse Enhancement add-on workflow, while forcing NVDA's Chromium UIA setting enables native tracking but causes problems in other applications. The maintainer distinguishes this transition problem from the older legacy hit-testing defect.
- **Upstream UIA limitation remains tracked:** https://github.com/nvaccess/nvda/issues/19276 is open. Its maintainer explains at https://github.com/nvaccess/nvda/issues/19276#issuecomment-3584037731 that NVDA cannot switch its default to UIA because Chromium's UIA implementation has other deficiencies. The add-on author reports a temporary mitigation in Mouse Enhancements 0.8.2 at https://github.com/nvaccess/nvda/issues/19276#issuecomment-3590931310, explicitly not a complete solution.
- **Confirmed Electron reproduction:** https://github.com/electron/electron/issues/42945 is open. https://github.com/electron/electron/issues/42945#issuecomment-5575765450 provides a standalone reproduction, working Electron 29.4.6 baseline, failing Electron 30–44 builds, and working Chrome/vscode.dev comparison. It attributes silent mouse tracking to an empty native container intercepting MSAA AccessibleObjectFromPoint hit tests.
- **Unmerged upstream fix candidate:** https://github.com/electron/electron/pull/53460 is an open draft with no merge timestamp and declares Fixes electron/electron#42945. Its proposed contentView targeting changes address the empty-container hit-test interception. The author reports Linux accessibility checks but explicitly has not verified Windows NVDA/Inspect.exe behavior; this is not a landed fix.
- **Older related report does not establish full duplicate coverage:** https://github.com/microsoft/vscode/issues/224704 is open, was created August 3, 2024, and reports the same silent-hover symptom across the workbench. It tracks the legacy Electron defect, but this report additionally documents the Chromium 142 UIA transition breaking an existing add-on workaround. The shared Electron reproduction does not establish that resolving the older report also resolves that compatibility behavior; the stronger re-review duplicate bar is not met for the full scope.
- **Current checkout boundary:** The checkout's .npmrc targets Electron 43.7.7. src/mainImpl.ts preserves user-supplied enable-features and disable-features switches but does not explicitly override UiaProvider or AccessibilityHitTestPointCopy. src/vs/workbench/services/accessibility/electron-browser/accessibilityService.ts manages screen-reader support, not native Windows hit testing. A newer bundled runtime alone is not evidence of resolution; no build or execution was performed.
