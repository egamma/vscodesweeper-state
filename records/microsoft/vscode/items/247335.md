# Issue #247335 — QuickDiffProvider is not refreshable

[https://github.com/microsoft/vscode/issues/247335](https://github.com/microsoft/vscode/issues/247335)

## Summary

Keep open under the existing SCM discussion: returning null already suppresses decorations, but neither the stable nor proposed QuickDiffProvider API exposes a dedicated invalidation event. Existing refresh mechanisms provide partial coverage, not proof that the requested independent notification capability is unnecessary.

## Change summary

Allow SCM extensions to invalidate a file's quick-diff original-resource mapping when it transitions between versioned and unversioned states.

## Best solution

Settle whether QuickDiffProvider should expose an explicit invalidation contract for per-file original-resource changes, including transitions to and from null. Document the existing SCM resource-change and original-content refresh mechanisms, distinguishing their coverage from independent mapping invalidation.

- **existing API coverage:** src/vscode-dts/vscode.d.ts:16423-16433 exposes QuickDiffProvider.provideOriginalResource with ProviderResult<Uri>, but no invalidation event. src/vs/workbench/contrib/scm/common/quickDiffService.ts:getQuickDiffs skips null or undefined original resources. src/vscode-dts/vscode.proposed.quickDiffProvider.d.ts adds registration, secondary providers, IDs and labels, not original-resource change notifications.
- **maintainer guidance:** https://github.com/microsoft/vscode/issues/247335#issuecomment-2896930568 points to Git's FileSystemProvider notification mechanism. Current extensions/git/src/fileSystemProvider.ts:onDidChangeOriginalResource emits FileChangeType.Changed for original-resource URIs; this is an existing content-refresh mechanism, not a dedicated QuickDiffProvider mapping event.
- **current refresh boundary:** src/vs/workbench/contrib/scm/browser/quickDiffModel.ts subscribes to SCM onDidChangeResources, provider-registration changes, working-model changes and resolved original-model content changes. triggerDiff re-queries original resources, so SCM resource updates can refresh mappings. However, a null original has no resolved original model whose content-change event can drive refresh, and neither public provider interface exposes independent mapping invalidation.
