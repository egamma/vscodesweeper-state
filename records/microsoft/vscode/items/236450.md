# Issue #236450 — Expose native support for USB, HID and Serial device access in VS Code (Desktop)

[https://github.com/microsoft/vscode/issues/236450](https://github.com/microsoft/vscode/issues/236450)

## Summary

Keep open: desktop extension access to USB, HID and Serial devices remains a distinct gap, and the request has already qualified for the Backlog with 45 upvotes. The linked implementation PR is still open and should be reviewed rather than treating the capability as completed.

## Change summary

Expose Electron-backed USB, HID and Serial device authorization and access to extensions in desktop VS Code.

## Best solution

Review https://github.com/microsoft/vscode/pull/198047 against the current desktop architecture and settle its supported extension-host scope and device-consent behavior. Land an accepted implementation that enables desktop extensions to access authorized devices without bundling native device-access packages.

## Evidence

- **Accepted community demand:** https://github.com/microsoft/vscode/issues/236450 has 45 community upvotes and the Backlog milestone. The December 24, 2024 bot comment explicitly confirms that the request passed the community threshold; another commenter identifies embedded/FPGA development with devcontainers as a use case.
- **Existing commands do not establish desktop support:** src/vs/workbench/browser/window.ts:481-496 registers workbench.experimental.requestUsbDevice, workbench.experimental.requestSerialPort and workbench.experimental.requestHidDevice. Their implementations in src/vs/base/browser/deviceAccess.ts delegate to navigator device APIs; these commands alone do not supply Electron device-selection integration.
- **Desktop permission boundary remains:** src/vs/code/electron-main/app.ts:261-299 configures the default session's permission request/check handlers using allowlists that do not include USB, HID or Serial permissions. This does not provide the requested extension device-authorization path.
- **Newer hardware support belongs to a different surface:** src/vs/platform/browserView/electron-main/browserSessionPermissions.ts:204-266 does implement USB, Serial and HID chooser handling, but BrowserSessionPermissions is installed on BrowserSession instances. src/vs/platform/browserView/electron-main/browserSession.ts creates separate vscode-browser partitions; this is integrated-browser support, not adoption by the desktop extension command path.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/198047 was verified OPEN with mergedAt null. Its body proposes device-selection UI and IPC integration and explicitly limits concrete device access to browser-only web extensions running in the desktop web extension host. The author links this issue in https://github.com/microsoft/vscode/pull/198047#issuecomment-2550858525 and describes the missing Electron chooser-to-UI wiring in https://github.com/microsoft/vscode/pull/198047#issuecomment-2561262852.
- **Canonical search:** Open-issue searches for WebUSB, WebSerial, device access and USB/device titles found no verified older open canonical owning this desktop request. https://github.com/microsoft/vscode/issues/116761 was inspected and is closed; it concerns browser WebUSB exposure, not completion of this desktop capability. The related open PR is an implementation candidate, not a duplicate target.
