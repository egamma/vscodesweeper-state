# Issue #192371 — Enable support for notebooks at the "select language" mode

[https://github.com/microsoft/vscode/issues/192371](https://github.com/microsoft/vscode/issues/192371)

## Summary

Keep this accepted feature request open: notebook creation is available through New File and a dedicated command, but not through Select Language Mode as requested. It has 35 upvotes, was promoted to Backlog, and no verified older canonical owns the same request.

## Change summary

Allow users to start a notebook, including supported Jupyter and polyglot notebook formats, from an untitled editor's Select Language Mode picker.

## Best solution

Provide a discoverable notebook-creation entry from the language-selection workflow without treating notebook document formats as cell languages. Settle how that entry handles existing text and extension-provided notebook formats before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorStatus.ts`, `src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts`, `extensions/ipynb/package.json`, `extensions/ipynb/src/ipynbMain.ts`
- **Validation:** In an empty untitled text editor, invoke workbench.action.editor.changeLanguageMode and verify that the agreed notebook entry opens a real notebook document rather than assigning a pseudo-language to the text model. Check installed notebook formats, cancellation, and the agreed non-empty-document behavior; verify ordinary language changes, existing New File notebook creation, and cell-language selection remain unchanged.
- **Behavior:**

  > Users want to start a notebook from the Select Language Mode workflow used when beginning an untitled file. The resulting editor must contain a real notebook document, not a text file labeled with a notebook format. Acceptance should cover Jupyter notebooks and the agreed scope of installed polyglot notebook providers. Existing text must not be silently discarded, and ordinary text-language selection must retain its behavior.
- **Trace:**

  > ChangeLanguageAction in src/vs/workbench/browser/parts/editor/editorStatus.ts constructs its picker from registered language names and changes the active text editor's language through setLanguageId; there is no notebook-creation branch in the inspected current source. Notebook creation is already exposed separately: NewFileTemplatesManager in src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts collects MenuId.NewFile contributions, and extensions/ipynb/package.json contributes ipynb.newUntitledIpynb. That command in extensions/ipynb/src/ipynbMain.ts opens a real jupyter-notebook document with an empty Python cell. The distinction between document formats and cell languages is reinforced by https://github.com/microsoft/vscode-jupyter/issues/14249 and https://github.com/microsoft/vscode/issues/133486. The unresolved boundary is what the language-picker entry promises for non-empty text and extension-contributed formats; this review did not establish a generic notebook-provider creation contract. Preserve ordinary language-mode changes, notebook cell-language choices, and existing creation commands.
- **Open decisions:**
  - Should Select Language Mode offer individual notebook formats directly, or a notebook-creation entry that opens the existing file-type chooser?
  - Should notebook creation be offered only for empty untitled editors, or also for editors containing text; if the latter, what happens to that text and its original editor?
  - Should the entry support every installed notebook creation contribution, including polyglot formats, or initially support only Jupyter notebooks?
