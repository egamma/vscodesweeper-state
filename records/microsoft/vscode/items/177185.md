# Issue #177185 — Remove invalid entries from Recent Opened etc.

[https://github.com/microsoft/vscode/issues/177185](https://github.com/microsoft/vscode/issues/177185)

## Summary

Keep this accepted, well-supported request open: current code removes individual entries or clears history, but does not provide selective bulk cleanup of missing paths. This issue already serves as the canonical for three duplicates; the remaining product choices warrant a maintainer-led design session.

## Change summary

Provide selective cleanup of nonexistent paths in Recently Opened and potentially other stored-path lists, with optional visual indications of validity.

## Best solution

Provide a deliberate way to clean confirmed-missing recent files, folders, and workspaces while retaining valid or temporarily unavailable entries. Decide separately whether validity indicators and Workspace Trust cleanup belong in the same feature, since trust entries express authorization rather than browsing history.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/windowActions.ts`, `src/vs/platform/workspaces/common/workspaces.ts`, `src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts`, `src/vs/workbench/services/workspaces/browser/workspacesService.ts`, `src/vs/workbench/contrib/workspaces/browser/recentRemoteFolderPruner.ts`, `src/vs/workbench/contrib/workspace/browser/workspaceTrustEditor.ts`
- **Validation:** The plan should establish a runnable history-cleanup test using a mixed list of existing and authoritatively missing files, folders, and workspace files: cleanup removes only confirmed-missing entries. Include unavailable providers, disconnected remotes, permission failures, and entries with unsaved backups, which must remain intact. Manually verify the chosen user-facing action in workbench.action.openRecent and ensure ordinary single-entry removal and Clear Recently Opened retain their behavior.
- **Behavior:**

  > Users with deleted or moved temporary files and projects should be able to clean invalid Recently Opened entries without clearing useful history or removing entries one by one. Existing paths and resources whose availability cannot be determined must remain. Entries representing unsaved work must retain their existing protection. The issue also suggests validity indicators and cleanup of other stored-path lists; those extensions of scope require explicit agreement before they become acceptance criteria.
- **Trace:**

  > BaseOpenRecentAction.run in src/vs/workbench/browser/actions/windowActions.ts renders stored recent entries and delegates individual removal to IWorkspacesService; it does not classify path validity. WorkspacesHistoryMainService.getRecentlyOpened and BrowserWorkspacesService.getRecentlyOpened restore history without general existence-based pruning. WindowsMainService.resolvePath removes an individual failed local open, while pruneRecentRemoteFolderIfMissing handles only the current vscode-remote single-folder workspace and preserves non-FILE_NOT_FOUND failures; its test in src/vs/workbench/contrib/workspaces/test/browser/recentRemoteFolderPruner.test.ts documents that boundary. Neither mechanism satisfies bulk cleanup, and vscode-vfs deleted branches remain outside the remote pruner. WorkspaceTrustEditor deletion changes trust through setUrisTrust, so authorization cleanup must not be treated as ordinary history removal. Preserve unsaved-backup safeguards and avoid adding blocking network checks to picker opening. https://github.com/microsoft/vscode/issues/189242 supplies the offline-preservation requirement, and https://github.com/microsoft/vscode/issues/314961 demonstrates the related over-removal risk.
- **Open decisions:**
  - Should selective cleanup be an explicit user-invoked action, run automatically, or support both behaviors?
  - Should the first delivery include validity indicators without deleting entries, or provide cleanup alone?
  - Should this feature cover Recently Opened only, or also offer an explicitly separate cleanup action for Workspace Trust authorization entries?
