# Issue #212508 — After updating to version 1.89 my $HOME path is incorrect. And not able to change it.

[https://github.com/microsoft/vscode/issues/212508](https://github.com/microsoft/vscode/issues/212508)

## Summary

Verified duplicate of #240539 — the root cause is that `_encodeColons()` in `environmentVariableCollection.ts` only encodes colons but not backslashes before values are decoded with `echo -e` in the bash shell integration script. Windows paths containing backslash sequences like `\t`, `\n` etc. are misinterpreted as escape characters, corrupting `$HOME` and other env vars. Issue #240539 is the canonical tracker with the open fix PR #240614.

## Change summary

Git Bash `$HOME` path is corrupted when shell integration is enabled because backslashes in Windows paths are treated as escape sequences during environment variable decoding.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/240614 which adds backslash encoding in the TypeScript side (`_encodeColons` → encode both colons and backslashes) so `echo -e` decoding in `shellIntegration-bash.sh` no longer misinterprets Windows path separators. The canonical issue https://github.com/microsoft/vscode/issues/240539 tracks this fix.

## Evidence

- **root cause in source:** `src/vs/platform/terminal/common/environmentVariableCollection.ts` line 109-111: `_encodeColons()` only replaces `:` with `\x3a` but does NOT encode backslashes. The bash script at `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh` lines 76/85/94 uses `echo -e` to decode values, which interprets unencoded backslash sequences (e.g. `\t` in `C:\Users\takka` becomes a tab).
- **canonical issue:** https://github.com/microsoft/vscode/issues/240539 is open and tracks exactly this: backslash path separators interpreted as escape sequences when HOME is set in bash terminal.
- **open fix PR:** https://github.com/microsoft/vscode/pull/240614 is an open PR that fixes the missing backslash encoding in the shell integration environment variable values, and explicitly references this issue (#212508) in its description.
- **user confirmation:** Comment 5 by takkasila confirms the exact mechanism: username starting with 't' causes `\t` to become a tab. Multiple commenters confirm disabling shell integration resolves the issue.
