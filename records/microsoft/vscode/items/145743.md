# Issue #145743 — Have a `TabKindCustomDiff`

[https://github.com/microsoft/vscode/issues/145743](https://github.com/microsoft/vscode/issues/145743)

## Summary

The custom-diff tab API gap remains on current main: both inline and side-by-side custom-editor diffs are exposed with an unknown tab input. Keep this older Backlog request open and consolidate the newer RFC into its API design rather than treating this re-reviewed item as a duplicate of a younger issue.

## Change summary

Expose custom-editor diff tabs through a typed tab input containing the original and modified resources instead of returning no recognized input kind.

## Best solution

Define a consistent public tab-input contract for custom-editor diffs across the supported inline and side-by-side layouts, then consolidate the use case and discussion from https://github.com/microsoft/vscode/issues/271526 into this older request.

## Plan brief

- **Likely files:** `src/vs/workbench/api/browser/mainThreadEditorTabs.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHostEditorTabs.ts`, `src/vs/workbench/api/common/extHostTypes.ts`, `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/test/browser/mainThreadEditorTabs.test.ts`, `src/vs/workbench/api/test/browser/extHostEditorTabs.test.ts`
- **Validation:** Add tab API unit coverage for custom-editor diffs in the MainThreadEditorTabs and ExtHostEditorTabs suites, then run `scripts/test.sh --grep 'MainThreadEditorTabs|ExtHostEditorTabs'`; each supported custom-diff layout must expose the original URI, modified URI, and custom editor view type instead of an unknown input.
- **Behavior:**

  > Extensions inspecting window.tabGroups should receive a typed custom-diff input when VS Code opens two resources through a custom editor's diff workflow. The input must identify the original and modified resources and the custom editor view type. Text, notebook, ordinary custom-editor, and unknown tab classifications must remain unchanged. Acceptance covers every supported custom-editor diff layout, including the Git comparison scenario described in https://github.com/microsoft/vscode/issues/271526.
- **Trace:**

  > MainThreadEditorTabs._editorInputToDto in src/vs/workbench/api/browser/mainThreadEditorTabs.ts currently recognizes only text and notebook DiffEditorInput children and has no CustomEditorDiffInput branch, so custom diffs become UnknownInput. CustomEditors.createDiffEditorInput in src/vs/workbench/contrib/customEditor/browser/customEditors.ts can produce an inline CustomEditorDiffInput or a DiffEditorInput containing custom-editor inputs, depending on capabilities and `diffEditor.renderSideBySide`. The transport union in src/vs/workbench/api/common/extHost.protocol.ts and the conversion in src/vs/workbench/api/common/extHostEditorTabs.ts consequently have no custom-diff representation. Preserve all existing tab-input classifications and keep the work scoped to the tab/custom-editor API rather than changing diff rendering behavior. The newer same-use-case report is https://github.com/microsoft/vscode/issues/271526; the older split-tab issue https://github.com/microsoft/vscode/issues/145688 does not cover this contract.
- **Open decisions:**
  - Should every custom-editor diff layout expose the same public tab-input type, including inline custom diffs, capability-based side-by-side custom diffs, and legacy paired custom-editor inputs?
  - Is the intended public contract limited to observation through window.tabGroups, or must the custom editor being resolved also receive explicit diff-context information?

## Evidence

- **current source gap:** src/vs/workbench/api/browser/mainThreadEditorTabs.ts::_editorInputToDto recognizes text and notebook children inside DiffEditorInput, but not custom-editor children; it also has no branch for CustomEditorDiffInput, so these paths fall through to TabInputKind.UnknownInput.
- **missing protocol and API types:** src/vs/workbench/api/common/extHost.protocol.ts defines TextDiffInputDto and NotebookDiffInputDto but no custom diff DTO, while src/vscode-dts/vscode.d.ts exposes TabInputTextDiff and TabInputNotebookDiff but no TabInputCustomDiff.
- **active custom diff paths:** src/vs/workbench/contrib/customEditor/browser/customEditors.ts creates either CustomEditorDiffInput or a DiffEditorInput containing custom-editor inputs, depending on custom-editor diff capabilities and layout configuration; neither shape is represented by the tab API.
- **renewed extension demand:** The open Backlog RFC https://github.com/microsoft/vscode/issues/271526 reports the same missing TabInputCustomDiff capability from an extension author's Git diff workflow, but it was created in 2025 and therefore cannot be the canonical duplicate target for this re-reviewed 2022 issue.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/145688 concerned generic split-in-editor-group tabs and was closed after those tabs were reported as TabKindText; it does not own the custom-editor diff API requested here.
