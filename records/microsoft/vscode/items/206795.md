# Issue #206795 — Double-clicking on `...` used as argument value selects more than `...`

[https://github.com/microsoft/vscode/issues/206795](https://github.com/microsoft/vscode/issues/206795)

## Summary

The reported over-selection remains explainable directly from current source: consecutive punctuation is selected as one separator run, including the ellipsis and surrounding delimiters. Keep this accepted bug open; deciding how ellipsis selection should differ from general punctuation selection needs editor-owner input.

## Change summary

Double-clicking a Python ellipsis argument should select only the three dots, without adjacent assignment operators, parentheses, or colons.

## Best solution

Make the Python ellipsis independently selectable in both reported examples while preserving established selection behavior for other punctuation and normal words. Establish whether that behavior is Python-specific or a language-independent ellipsis rule before changing the shared editor selection contract.

## Evidence

In src/vs/editor/common/cursor/cursorWordOperations.ts, _findStartOfWord and _findEndOfWord scan across consecutive separators without distinguishing their characters. WordOperations.word selects that entire run: '=...)):' in Query(default=...) and '(...)' in Field(...). This conclusion is from source inspection, not execution.
- **Core editor owns the selection path:** src/vs/editor/browser/view/viewController.ts dispatches ordinary double-click word selection through CoreNavigationCommands.WordSelect. Its WordCommand in src/vs/editor/browser/coreCommands.ts calls CursorMoveCommands.word, which delegates to WordOperations.word. This path uses configured character classes rather than asking the Python extension for argument-token boundaries, consistent with the maintainers' discussion in https://github.com/microsoft/vscode/issues/206795.
- **Existing setting is a tradeoff, not a complete fix:** editor.wordSeparators is registered in src/vs/editor/common/config/editorOptions.ts. Removing '.' makes the ellipsis a regular-character run and separates it from the surrounding punctuation in these examples, but also changes ordinary dotted-name selection. That configuration does not provide token-aware ellipsis selection while retaining the existing treatment of other dots.
