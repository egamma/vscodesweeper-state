# Issue #153620 — Allow merging from right to left with diff arrows view

[https://github.com/microsoft/vscode/issues/153620](https://github.com/microsoft/vscode/issues/153620)

## Summary

Keep open: current diff actions still copy only from left to right, and swapping sides does not provide bidirectional merging in a stable comparison layout. This team-authored Backlog request has substantial community support; neither a qualifying fix nor an older open canonical was verified.

## Change summary

Allow copying diff changes from right to left when the left-hand file is editable, without swapping the comparison sides.

## Best solution

Provide an accessible reverse-copy action in the diff editor while preserving the comparison orientation and respecting destination editability. A maintainer should settle its presentation alongside the existing forward-copy controls before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/features/revertButtonsFeature.ts`, `src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts`, `src/vs/editor/browser/widget/diffEditor/commands.ts`, `src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts`, `src/vs/editor/browser/widget/diffEditor/components/diffEditorEditors.ts`
- **Validation:** Compare two editable files with additions, deletions, and replacements. Copy an individual change in each direction without swapping sides; verify only the destination changes and each operation can be undone. Repeat with a read-only left side and confirm reverse copying is unavailable while existing left-to-right behavior remains intact. Verify keyboard access and action labels for the chosen presentation.
- **Behavior:**

  > Users comparing two editable files can copy a differing block from either file into the other without changing which file appears on each side. Copying changes only the destination and remains undoable. A read-only destination must not offer an executable copy action. Existing source-control comparisons and left-to-right copying retain their current semantics.
- **Trace:**

  > RevertButtonsFeature renders right-pointing glyphs on the modified editor and delegates to DiffEditorWidget.revert or revertRangeMappings. Both methods read original-model text and edit only the modified model; diffEditor.revert follows the same direction through its toolbar and cursor paths. DiffEditorGutter supplies the newer hunk and selection toolbars, so the presentation decision must account for that surface as well as legacy arrows. Original-side editing is represented by originalEditable and applied in DiffEditorEditors. The existing workbench.action.compareEditor.swapSides command replaces the diff input with reversed sides, which explains the documented workaround but does not satisfy orientation-preserving merging. Preserve read-only protections, existing forward-copy semantics, and diff freshness checks; unrelated staging and whitespace requests are outside this scope. https://github.com/microsoft/vscode/issues/269082 is a newer related request, not a canonical for this report.
- **Open decisions:**
  - Should reverse copying appear as a second visible directional action when both sides are editable, or be exposed through a context-menu or modifier interaction with the existing action?
