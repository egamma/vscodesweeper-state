# Issue #189058 — Ghost text hover sometimes has empty rendering

[https://github.com/microsoft/vscode/issues/189058](https://github.com/microsoft/vscode/issues/189058)

## Summary

The suggest-widget path can still leave the ghost-text hover's count permanently blank, even after the provider returns. Keep this report open; the related hover report is newer and cannot serve as the canonical for this re-reviewed issue.

## Change summary

The ghost-text hover sometimes displays navigation arrows without a suggestion count after triggering the suggest widget.

## Best solution

Make the hover accurately represent the active suggest-widget augmentation state rather than waiting for a count derived from the separate standalone-completion state. Settle the count and navigation semantics together so the display does not imply alternatives that the navigation commands cannot select.

- **Trace:**

  > InlineCompletionsHoverParticipant.renderHoverParts supplies model.inlineCompletionsCount and triggers an explicit request. Navigation in _deltaSelectedInlineCompletionIndex also uses standalone _inlineCompletionItems, so exposing an augmentation count without deciding navigation behavior risks misleading controls. - **Open decisions:**
  - While the suggest widget owns the selection, should the hover expose a count and navigable augmentation alternatives, or represent only the currently selected augmentation without alternative-navigation controls?
