# Issue #315033 — Inconsistent merge conflict action labels (“Accept Current” vs “Accept Current Change”) across VS Code UIs

[https://github.com/microsoft/vscode/issues/315033](https://github.com/microsoft/vscode/issues/315033)

## Summary

Confirmed: the merge-conflict extension's codelens uses "Accept Current Change" while its own command palette entry uses "Accept Current", and the 3-way merge editor renders "Accept Current" (from the git extension's title). This is a real, minor label inconsistency across merge/conflict UIs that remains on current main.

## Change summary

The same merge-resolution action is labeled "Accept Current Change" in the inline codelens but "Accept Current" in the command palette and 3-way merge editor.

## Best solution

Align the labels: either add "Change" consistently or remove it consistently across `extensions/merge-conflict/package.nls.json` (command palette titles), `extensions/merge-conflict/src/codelensProvider.ts` (codelens labels), and the git extension's merge-editor input titles in `extensions/git/src/commands.ts`. The codelens "Accept Current Change" / "Accept Incoming Change" phrasing is more descriptive and likely the better canonical form.
