# Issue #320779 — Refactor de paquete

[https://github.com/microsoft/vscode/issues/320779](https://github.com/microsoft/vscode/issues/320779)

## Summary

VS Code intentionally opens files modified by refactoring so users can review changes. The `files.refactoring.autoSave` setting (default: true) already auto-saves them. The request for Eclipse-like silent refactoring is a design choice VS Code explicitly diverges from.

## Change summary

User wants Java package rename to not open modified files as tabs, behaving silently like Eclipse.

## Best solution

Close as designed. VS Code shows affected files so users can review and undo per-file if needed. The `files.refactoring.autoSave` setting (defaulting to `true` in `src/vs/workbench/contrib/bulkEdit/browser/bulkEditService.ts`) already handles auto-saving. If the Java extension's package refactoring doesn't trigger auto-save, that's an issue for the Red Hat Java extension tracker.
