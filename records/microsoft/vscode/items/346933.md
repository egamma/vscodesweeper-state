# Issue #346933 — Inbox mode: The two sessions lists have confusing scrolling and expansion

[https://github.com/microsoft/vscode/issues/346933](https://github.com/microsoft/vscode/issues/346933)

## Summary

Keep open as actionable Inbox Mode usability feedback. Independent scrolling and upward category expansion are intentional today, but that does not resolve the reported difficulty understanding the boundary.

## Change summary

Make Inbox Mode scrolling boundaries and category expansion understandable without sessions appearing to disappear between regions.

## Best solution

Preserve session discoverability and orientation while scrolling and expanding Done. Decide whether to retain two clearly delineated regions or adopt one scrolling list before changing the layout contract.

- **Behavior:**

  > In desktop Inbox Mode, users lose orientation where the upper and lower session lists meet, especially when expanding Done moves the boundary upward. The finished interaction should make scrolling ownership and expansion predictable while keeping every session reachable. Acceptance should cover overflowing lists, Done expansion and collapse, window resizing, and keyboard navigation.
- **Trace:**

  > SessionsList in src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts creates a vertical SplitView containing the primary tree and inboxTree. layoutInbox() recalculates lower-region size from content height, primary capacity, and an optional user-selected size, explaining the reported upward growth. The associated sessionsList.css clips each region and supplies a focus-visible keyboard separator without its own resting visual treatment. Existing sessionsList browser tests deliberately assert footer growth, bottom anchoring, and space reclamation, so this is not conclusively an implementation violation. The parent test item https://github.com/microsoft/vscode/issues/346666 specifically invites evaluation of this interaction. Preserve triage state, category membership, selection, search, session reachability, and phone behavior; uncertainty begins with the intended desktop scrolling model, not session classification.
- **Open decisions:**
  - Should desktop Inbox Mode retain independently scrolling, resizable regions with a clearer boundary, or present all categories in one scrolling list?
  - If the split remains, should expanding Done automatically reclaim upper-region space as today, or preserve the divider position and scroll within the lower region?
