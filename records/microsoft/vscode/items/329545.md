# Issue #329545 — Custom Endpoint BYOK models disappear after upgrading to VS Code 1.132 unless chat.agentHost.byokModels.enabled is manually enabled

[https://github.com/microsoft/vscode/issues/329545](https://github.com/microsoft/vscode/issues/329545)

## Summary

Confirmed on main: `chat.agentHost.byokModels.enabled` (src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts) really does default to `false` and gates whether extension-provided BYOK models are wired into agent-host sessions, and it's tagged `experimental`/`advanced` (hidden/de-emphasized in Settings UI search) — this matches the reporter's experience of previously-working Custom Endpoint models silently disappearing after upgrading, with no visible toggle or migration message.

## Change summary

Existing Custom Endpoint/BYOK chat models stop appearing in the model picker after upgrading to 1.132 because the new agent-host BYOK bridge setting defaults to off and isn't easily discoverable.

## Best solution

This looks like a rough edge in the ongoing agent-host BYOK migration (owned by src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts and agentService.ts) — the team should either auto-migrate/detect previously configured BYOK models, surface the setting more prominently (or default it on) during rollout, or add an explicit notification explaining why models vanished; needs a maintainer/product call on the migration strategy rather than a one-line code fix.
