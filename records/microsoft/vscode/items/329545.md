# Issue #329545 — Custom Endpoint BYOK models disappear after upgrading to VS Code 1.132 unless chat.agentHost.byokModels.enabled is manually enabled

[https://github.com/microsoft/vscode/issues/329545](https://github.com/microsoft/vscode/issues/329545)

## Summary

Traced to a real, intentional-but-disruptive default flip: `chat.agentHost.byokModels.enabled` was changed from `true` to `false` in commit c5447dfca41 (#327658, 2026-07-27), so anyone who upgrades without knowing about this new, experiment-gated setting silently loses their previously working Custom Endpoint/BYOK model — a genuine gap in migration/communication, not a duplicate or extension issue.

## Change summary

Existing Custom Endpoint BYOK models stop appearing in the model picker after upgrading to 1.132 because the new agent-host BYOK bridge setting defaults to off, and the setting isn't easily discoverable in the Settings UI.

## Best solution

The agent-host/BYOK team should either ship a migration (auto-enable the bridge when a user already has BYOK models configured) or add a clear one-time notification/settings surfacing when BYOK models silently stop working due to this flag, in src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts and the related BYOK bridge wiring in copilotAgent.ts/copilotSessionLauncher.ts.
