# Issue #313563 — Incremental CI/CD pipeline execution based on changed modules

[https://github.com/microsoft/vscode/issues/313563](https://github.com/microsoft/vscode/issues/313563)

## Summary

Valid feature request for incremental CI/CD execution that has earned its Backlog spot via 20 community upvotes. No existing work or duplicate found. The request targets the engineering system, which is a legitimate area, though the complexity of VS Code's build graph makes this non-trivial.

## Change summary

Run only the relevant subset of CI build steps and tests based on which files/modules a PR actually changes, instead of always running the full pipeline.

## Best solution

The engineering team should evaluate feasibility of dependency-graph-based selective test/build execution in the Azure Pipelines configuration (under `build/azure-pipelines/`). A gradual approach — starting with coarse-grained skip rules (e.g. docs-only, extensions-only changes) before fine-grained module-level analysis — would reduce risk. This is an internal engineering decision that should stay with the team.
