# Issue #299174 — A running Copilot agent results in high CPU usage (> 70% CPU time spent on "Recalculate style")

[https://github.com/microsoft/vscode/issues/299174](https://github.com/microsoft/vscode/issues/299174)

## Summary

This remains a well-evidenced performance bug: the supplied trace attributes severe agent-time slowdown to renderer style recalculation, and multiple users confirm the current symptom, including a useful main-window versus separate-window distinction. It should stay open for chat UI performance investigation.

## Change summary

Running a Copilot agent, especially while showing its changes in the main window, causes sustained style recalculation that makes VS Code and the machine severely unresponsive.

## Best solution

Profile the Copilot chat and changes rendering path in the main workbench window, identify the DOM or CSS invalidation repeatedly triggering codicon selector matching and style recalculation, and constrain updates so active agent progress does not continuously restyle the workbench.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser`, `extensions/copilot`
- **Validation:** Run an agent task with its changes visible in the main window and capture a renderer performance trace; verify that style recalculation no longer dominates CPU time, then repeat with chat in a separate window and confirm normal editor interaction in both layouts.
- **Behavior:**

  > Starting a Copilot agent and displaying its generated changes must not make the workbench or the rest of the machine unresponsive. Agent progress and change rendering should remain interactive in both the main workbench and a separate chat window. Acceptance requires a repeatable trace showing that style recalculation no longer dominates renderer CPU, alongside responsive typing, clicking, and tab switching during the task.
- **Trace:**

  > The supplied Chromium trace attributes more than 70% of CPU time during the slowdown to style recalculation. User reports narrow the hot scenario to agent changes displayed with chat in the main window; the separate-window presentation is reportedly unaffected. Another observation points to repeated failed `codicon` CSS selector matching, although turning file icons off did not stop it, so the selector may be incidental or shared infrastructure rather than the root cause. Investigation should trace DOM mutations and style invalidations across the chat response, progress, and changes-rendering path under src/vs/workbench/contrib/chat/browser and extensions/copilot. Preserve agent output behavior and separate-window behavior; this issue is about eliminating pathological renderer work, not reducing visible progress updates.

## Evidence

- **performance trace:** The reporter supplied a trace captured during the slowdown; a roughly two-second slice is 14 MB and shows more than 70% CPU time in style recalculation while the Copilot agent is active.
- **independent confirmation:** A second user reports immediate severe slowdown when opening agent-made changes with chat in the main window, while opening chat and changes in a separate window is unaffected.
- **selector observation:** A commenter observed large numbers of failed `codicon` selector matches during the lag; disabling file icons did not remove the selector activity.
