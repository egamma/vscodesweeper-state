- **Behavior:**

  > Starting an agent and receiving streaming file edits must not make the workbench, editors, or other VS Code windows progressively unusable. Typing, scrolling, tab switching, and opening the changed-files summary should remain responsive while edits and diff decorations update. Acceptance requires a before/after renderer trace of the reported scenario showing that repeated style recalculation no longer dominates CPU time, while changed-file review and diff controls continue to work.
- **Trace:**

  > The report at https://github.com/microsoft/vscode/issues/299174 includes a renderer trace showing style recalculation consuming most CPU during active agent work; commenters additionally observe codicon selector matching and a main-window-only slowdown. ChatEditingCodeEditorIntegration._updateDiffRendering in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts rebuilds decorations, view zones, rendered deleted lines, and hunk widgets as document diffs change. renderChangesSummaryFileList in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatChangesSummaryPart.ts relayouts and replaces the changed-files list whenever its observable diffs update. Profiling must determine whether the dominant invalidation originates in editor diff rendering, the changed-files list, chat response rendering, or an interaction between them; do not fold in unrelated long-session memory growth or notification freezes tracked elsewhere.

## Evidence

- **performance trace:** The report includes a trace captured during the slowdown at https://github.com/user-attachments/files/25738682/trace.slice.json and identifies more than 70% of CPU time under style recalculation.
- **independent confirmations:** Comments on https://github.com/microsoft/vscode/issues/299174 report immediate severe lag when showing agent changes, improvement when Chat is in a separate window, and widespread failed codicon selector matching during the slowdown.
- **related issue scope:** https://github.com/microsoft/vscode/issues/292086 is older and also concerns forced relayouts around agent diff decorations, but its trigger is explicitly opening a changed file; it does not clearly absorb this report's broader slowdown beginning as soon as the agent starts work.
- **distinct long-session issue:** https://github.com/microsoft/vscode/issues/297349 tracks progressive degradation from long chat histories, whereas this report describes rapid degradation during active agent work, so it is related but not the same observable scenario.
- **current source path:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts updates diff decorations, removes and recreates view zones, renders deleted lines, and lays out per-hunk widgets in _updateDiffRendering; src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatChangesSummaryPart.ts also relayouts and replaces the changed-files list as diffs update. These are concrete profiling candidates, but the trace has not yet isolated one as the root cause.
