# Issue #162336 — Terminal hover positioning is unfriendly

[https://github.com/microsoft/vscode/issues/162336](https://github.com/microsoft/vscode/issues/162336)

## Summary

Keep open: terminal link hovers still use link-range geometry rather than the pointer's horizontal position. The linked editor improvement explicitly left terminal positioning outstanding, and no verified canonical issue absorbs this request.

## Change summary

Position terminal link hovers near the hovered portion of a long link so their contents and actions are easier to reach.

## Best solution

Make terminal link hover positioning account for the pointer while preserving wrapped-link highlighting, viewport constraints, and link activation behavior. Agree on the horizontal anchoring behavior, then cover ordinary detected links and OSC 8 links consistently.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/widgets/terminalHoverWidget.ts`, `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLink.ts`, `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts`, `src/vs/workbench/contrib/terminalContrib/links/test/browser/terminalLinkManager.test.ts`
- **Validation:** Manually echo https://github.com/microsoft/vscode/pull/162335 and hover its trailing number: the hover should remain close enough to enter without traversing back to the link's start. Repeat with a wrapped link, near both viewport edges, and with an OSC 8 link. Add browser tests for the agreed horizontal positioning contract and run scripts/test.sh --run src/vs/workbench/contrib/terminalContrib/links/test/browser/terminalLinkManager.test.ts, preserving existing hover cancellation and invalidation checks.
- **Behavior:**

  > Hovering the trailing portion of a long terminal link currently positions the hover using the link range rather than the pointer, making the hover harder to enter. The finished behavior should keep the hover accessible near the hovered portion, including when the link wraps or approaches a viewport boundary. Ordinary detected links and OSC 8 links should behave consistently. Link activation, modifier behavior, hover delay, highlighting, and dismissal must remain unchanged.
- **Trace:**

  > TerminalLink.hover receives pointer coordinates but uses them for scheduling rather than forwarding them through the tooltip callback. TerminalLinkManager._tooltipCallback and the OSC 8 hover handler construct range-and-dimension-only target options; TerminalHover.attach builds CellHoverTarget rectangles from that range. The shared IHoverTarget contract supports an explicit x coordinate, but the terminal target does not expose one. This establishes the missing positioning input without executing the UI; the precise desired anchoring rule remains undecided. Keep the scope on terminal link hovers, not general editor positioning or terminal tab hovers. https://github.com/microsoft/vscode/pull/163970 addressed editor positioning only, and https://github.com/microsoft/vscode/issues/180739 points terminal hover accessibility back to this issue.
- **Open decisions:**
  - Should a terminal link hover's leading edge anchor at the pointer's horizontal position, subject to viewport constraints, or should it retain link-start alignment whenever the resulting hover already spans the pointer?

## Evidence

- **Current terminal positioning path:** In src/vs/workbench/contrib/terminalContrib/links/browser/terminalLink.ts, TerminalLink.hover receives a MouseEvent and tracks pageX/pageY for hover scheduling, but its tooltip callback passes only the link, viewport range, and modifier callbacks. TerminalLinkManager._tooltipCallback constructs ILinkHoverTargetOptions without pointer coordinates; the OSC 8 hover callback also omits them.
- **Range-based target remains:** src/vs/workbench/contrib/terminal/browser/widgets/terminalHoverWidget.ts defines ILinkHoverTargetOptions without pointer coordinates. CellHoverTarget creates target rectangles from the link's viewportRange, and TerminalHover.attach passes that target to showInstantHover without a horizontal override. src/vs/platform/hover/browser/hoverWidget.ts defaults to left anchor alignment and supports an explicit target.x, which this terminal target does not supply.
- **Existing capability does not cover the ask:** IHoverTarget in src/vs/base/browser/ui/hover/hover.ts already supports an absolute x coordinate, including MouseEvent.pageX, but the terminal call path does not adopt it. TerminalHover.attach checks terminal.integrated.showLinkHover to suppress the hover; disabling it does not provide pointer-relative positioning or make hover actions easier to reach.
- **Editor fix excluded terminal:** https://github.com/microsoft/vscode/pull/163970 is merged, but its description says 'Helps with #162336 (for the editor)' and its changed files are editor/Monaco files, not terminal files. The supplied October 19, 2022 maintainer comment explicitly says to retain this issue for terminal positioning; the December 10, 2024 comment confirms the behavior on stable 1.95.3.
