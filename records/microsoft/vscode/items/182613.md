# Issue #182613 — respect Shebangs (#!) for langauge detection

[https://github.com/microsoft/vscode/issues/182613](https://github.com/microsoft/vscode/issues/182613)

## Summary

Keep open: a maintainer confirmed that typing the Python shebang can leave the language set to Shell Script, while pasting it or choosing Auto Detect succeeds. Current source still treats automatic detection differently from the language picker's first-line detection; the related TypeScript work does not establish a fix for this report.

## Change summary

Typing a Python shebang should select Python without requiring a manual Auto Detect action.

## Best solution

Make automatic detection honor the completed, recognized Python shebang consistently with the language picker, while preserving explicitly selected languages. First confirm the incremental-typing scenario on the current build, since automatic re-evaluation already exists in the source.

## Evidence

- **Python shebang support already exists:** extensions/python/package.json registers firstLine as ^#!\s*/?.*\bpython[0-9.-]*\b, covering #!/usr/bin/env python. Missing recognition of Python itself is therefore not the established problem.
- **Current automatic path:** UntitledTextEditorModel.onModelContentChanged in src/vs/workbench/services/untitled/common/untitledTextEditorModel.ts calls autoDetectLanguage on content changes. BaseTextEditorModel.doAutoDetectLanguage in src/vs/workbench/common/editor/textEditorModel.ts re-runs detection unless the language was explicitly selected or detection is disabled; automatic language changes are excluded from explicit-selection tracking. The maintainer's original no-re-evaluation hypothesis is not conclusively supported by current source.
- **First-line detection differs between paths:** The Auto Detect branch in src/vs/workbench/browser/parts/editor/editorStatus.ts passes textModel.getLineContent(1) to guessLanguageIdByFilepathOrFirstLine before invoking heuristic detection. LanguageDetectionWorkerClient.detectLanguage in src/vs/workbench/services/languageDetection/browser/languageDetectionWorkerServiceImpl.ts instead makes a URI-only quick guess and otherwise delegates content to the detection worker. This establishes a remaining path discrepancy, but does not prove the worker's current prediction for incremental Python shebang input.
