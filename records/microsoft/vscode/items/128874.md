# Issue #128874 — Provide a picker of opened editors excluding duplicates

[https://github.com/microsoft/vscode/issues/128874](https://github.com/microsoft/vscode/issues/128874)

## Summary

Keep this accepted feature request open: current editor pickers still list group-specific entries and open selections in their originating groups. The 28-upvote request is not covered by Quick Open or the reporter's extension workaround.

## Change summary

Provide a searchable, deduplicated list of currently open files across all editor groups that opens the selected file in the last active group.

## Best solution

Offer an opt-in, group-agnostic open-file picker in the workbench editor quick-access area, retaining the existing group-specific navigation commands. Decide its command or option surface before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorQuickAccess.ts`, `src/vs/workbench/browser/parts/editor/editorActions.ts`, `src/vs/workbench/browser/parts/editor/editor.contribution.ts`
- **Validation:** Open file A in two editor groups and file B only in the other group, then focus the first group and invoke the proposed picker. Verify that A appears once, B is searchable, closed workspace files are absent, and selecting B opens it in the initially active group without removing its other copy. Repeat invocation from the sidebar to verify last-active-group targeting, and confirm existing group-specific picker commands retain their behavior.
- **Behavior:**

  > Users working without tabs need a searchable list containing only currently open files across every editor group, with each file listed once. Selecting a file opens it in the group active when the picker was invoked, or the last active editor group when invoked outside an editor. A copy already open elsewhere remains available there. Acceptance covers duplicate files across groups, a file open only in another group, exclusion of closed files, and invocation from outside the editor.
- **Trace:**

  > In src/vs/workbench/browser/parts/editor/editorQuickAccess.ts, AllEditorsByAppearanceQuickAccess and AllEditorsByMostRecentlyUsedQuickAccess supply group-specific editor identifiers to BaseEditorQuickAccessProvider. Its item construction performs no deduplication, and acceptance opens the editor through its stored groupId, conclusively explaining why these providers do not deliver the requested workflow. ActiveGroupEditorsByMostRecentlyUsedQuickAccess omits other groups, while ordinary Quick Open in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts includes history and workspace file results. Commands and provider registrations live in editorActions.ts and editor.contribution.ts. Preserve the existing group-specific navigation, closing controls, and editor identity semantics; this request does not require moving or closing other copies. The reporter's extension is a workaround, not native coverage. https://github.com/microsoft/vscode/issues/204942 concerns moving editors and is related but distinct. The remaining product uncertainty is how users opt into the new picker behavior.
- **Open decisions:**
  - Should group-agnostic selection be exposed as a separate command and quick-access prefix, or as an opt-in mode of an existing all-editors picker?

## Evidence

- **Current picker behavior:** src/vs/workbench/browser/parts/editor/editorQuickAccess.ts: AllEditorsByAppearanceQuickAccess.doGetEditors collects each group's editor entries; AllEditorsByMostRecentlyUsedQuickAccess.doGetEditors preserves the editor service's group-specific identifiers. BaseEditorQuickAccessProvider.doGetEditorPickItems maps these entries without deduplication, and its accept callback explicitly calls getGroup(groupId)?.openEditor(...), targeting the originating group.
