# Issue #205594 — Are InlineCompletionsProvider handleDidPartiallyAcceptCompletionItem and handleDidShowCompletionItem experimental features expected to be moved out of proposed?

[https://github.com/microsoft/vscode/issues/205594](https://github.com/microsoft/vscode/issues/205594)

## Summary

The requested callbacks remain proposed and runtime-gated on current main, so the stable-API gap is still real. Keep this accepted Backlog request open for API-owner finalization; it has 21 upvotes and an explicit maintainer commitment.

## Change summary

Finalize inline-completion visibility and partial-accept callbacks so published extensions can observe suggestion usage through the stable API.

## Best solution

Finalize a documented stable lifecycle callback contract for inline-completion providers. API owners should decide whether lifetime notifications belong in that first increment and whether the newly requested next-edit and provider-metadata capabilities need separate finalization items.

- **Behavior:**

  > A published extension using the stable InlineCompletionItemProvider API should be able to observe when its suggestion is shown and when a user partially accepts it, without inferring those actions from document changes. Acceptance includes registration and callback dispatch without proposal access for the members selected for finalization; lifetime, next-edit, and provider-metadata scope must be settled with the API owners.
- **Trace:**

  > The stable provider interface in src/vscode-dts/vscode.d.ts contains only provideInlineCompletionItems, while the requested callbacks remain in src/vscode-dts/vscode.proposed.inlineCompletionsAdditions.d.ts.
