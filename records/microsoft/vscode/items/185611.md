# Issue #185611 — getOnTypeFormattingEdits not triggered on selected code

[https://github.com/microsoft/vscode/issues/185611](https://github.com/microsoft/vscode/issues/185611)

## Summary

The requested capability remains missing: current source explicitly skips on-type formatting when typing leaves a non-empty selection. Keep this team-authored, accepted Backlog request open; the maintainer supports allowing this scenario, and no verified fix or canonical duplicate was found.

## Change summary

Allow on-type formatting providers to run when typing a trigger character surrounds selected text, enabling automatic f-string conversion.

## Best solution

Support the single-selection surround case in the editor's on-type formatting contribution, with a defined provider-position contract and preserved selection behavior. Retain existing opt-in formatting, provider trigger filtering, cancellation, and multi-cursor behavior.

- **Validation:** Use a registered on-type provider with { as a trigger and editor.formatOnType enabled. Repeat with reverse selections and confirm disabled formatting, non-trigger characters, ordinary empty-selection typing, and multi-cursor behavior remain unchanged.
- **Behavior:**

  > Typing { around selected text inside a string currently surrounds the text but does not invoke the on-type formatting provider. The desired capability is for a registered provider to handle that typing event when format-on-type is enabled, allowing it to add an f prefix without losing the surrounded selection. Acceptance should cover forward and reverse selections, the provider's position argument, and selection preservation after returned edits. Existing disabled-formatting and non-trigger behavior must remain unchanged.
- **Trace:**

  > FormatOnType._update in src/vs/editor/contrib/format/browser/formatActions.ts registers an onDidType listener for the first provider's trigger characters. Its _trigger rejects a non-empty selection before calling getOnTypeFormattingEdits; SurroundSelectionCommand.computeCursorState in src/vs/editor/common/commands/surroundSelectionCommand.ts deliberately leaves the enclosed text selected. getOnTypeFormattingEdits in src/vs/editor/contrib/format/browser/format.ts calls the provider with one Position and the typed character, not a selection range. The remaining contract question is which position represents the typed trigger after surrounding; the existing call uses editor.getPosition(), which is at the selected content's end in this path. Preserve provider ordering, trigger filtering, cancellation, and existing multi-cursor exclusion; changing those is outside this request. The related report https://github.com/microsoft/pylance-release/issues/4489 was closed because the missing capability belongs here, not because it was fixed. Source was inspected without executing or modifying the checkout.
- **Open decisions:**
  - For a trigger character that surrounds selected text, should the on-type provider receive the post-edit selection's active position, as the existing call does, or the position immediately after the inserted opening character?
