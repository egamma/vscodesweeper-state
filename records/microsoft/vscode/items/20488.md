# Issue #20488 — [html] prevent that embedded grammars can corrupt syntax highlighting of rest of document

[https://github.com/microsoft/vscode/issues/20488](https://github.com/microsoft/vscode/issues/20488)

## Summary

Keep open as the canonical upstream tokenizer limitation: current HTML highlighting still relies on TextMate rule-stack state, allowing an unterminated embedded grammar construct to consume the host document beyond its closing tag. A 2026 report of the same observable CSS leak was closed as a duplicate of this issue.

## Change summary

Prevent malformed or incomplete embedded-language syntax from corrupting highlighting and triggering retokenization beyond the host language's closing delimiter.

## Best solution

Add host-boundary semantics to `vscode-textmate` so an enclosing grammar can force its closing delimiter to terminate an embedded grammar regardless of the embedded rule stack, or replace this path with a parser that isolates embedded regions. Preserve this issue as the canonical integration tracker until HTML no longer depends on the leaking TextMate behavior.

## Evidence

- **current source:** `src/vs/workbench/services/textMate/browser/tokenizationSupport/textMateTokenizationSupport.ts` calls `IGrammar.tokenizeLine2(line, state, 500)` and returns its `ruleStack` as the next-line state without a separate host-language boundary capable of overriding an embedded grammar's open state.
- **HTML grammar:** `extensions/html/syntaxes/html.tmLanguage.json` still embeds `source.css` inside the `<style>` begin/end rules, so containment continues to depend on TextMate grammar-stack behavior.
- **active dependency:** `package.json` currently depends on `vscode-textmate` 9.3.2. Tree-sitter preferences exist for CSS, TypeScript, INI, and regex, but no HTML Tree-sitter tokenizer replaces the outer HTML TextMate path.
- **recent confirmation:** https://github.com/microsoft/vscode/issues/313279 reported the same observable failure in VS Code 1.118—invalid CSS inside `<style>` breaking highlighting throughout the remaining HTML—and was closed as a duplicate pointing to this issue.
- **canonical check:** https://github.com/microsoft/vscode/issues/216 is older but requests alternatives to TextMate generally rather than reporting this same host-boundary symptom. The more specific https://github.com/microsoft/vscode/issues/70614 and the Tree-sitter exploration at https://github.com/microsoft/vscode/issues/210475 are both newer, so neither qualifies as the canonical target for this re-reviewed item.
