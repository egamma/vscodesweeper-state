# Issue #20488 — [html] prevent that embedded grammars can corrupt syntax highlighting of rest of document

[https://github.com/microsoft/vscode/issues/20488](https://github.com/microsoft/vscode/issues/20488)

## Summary

Keep open as the established collection point for embedded-grammar leakage. Current source still delegates boundary handling to TextMate, and a 2026 report documents the same CSS-to-HTML leakage; neither a verified fix nor an older canonical with the same symptom was established.

## Change summary

Prevent incomplete embedded CSS or JavaScript from carrying its syntax-highlighting state beyond the enclosing HTML closing tag.

## Best solution

Establish reliable embedded-language boundaries through compatible grammar recovery or coordinated vscode-textmate support, preserving HTML highlighting after closing tags even when embedded code is incomplete. Retain this issue as the focused record rather than folding it into a general request for another tokenization engine.

## Evidence

- **Maintainer diagnosis and intended ownership:** https://github.com/microsoft/vscode/issues/20488#issuecomment-281033051 explains that entering nested TextMate states deactivates the enclosing end rule, rejects diverging from TextMate semantics, and suggests grammar-level recovery rules. https://github.com/microsoft/vscode/issues/20488#issuecomment-279958285 confirms matching behavior in TextMate itself.
- **Deliberately retained collection point:** After the initial compatibility-based closure, a maintainer explicitly reopened the issue to collect related reports: https://github.com/microsoft/vscode/issues/20488#issuecomment-329102521. A subsequent accidental closure was also reversed: https://github.com/microsoft/vscode/issues/20488#issuecomment-353370640.
- **Current grammar boundary remains nested:** extensions/html/syntaxes/html.tmLanguage.json:1814-1822 wraps source.css with an end lookahead for </style>. extensions/css/syntaxes/css.tmLanguage.json:1710-1731 enters a property-list state on '{' whose end is '}', with no HTML closing-tag escape. These rules retain the structure implicated by the thread's incomplete-CSS example.
- **Current integration delegates to upstream engine:** src/vs/workbench/services/textMate/common/TMGrammarFactory.ts passes embedded-language metadata to loadGrammarWithConfiguration. src/vs/workbench/services/textMate/browser/tokenizationSupport/textMateTokenizationSupport.ts calls the grammar's tokenizeLine2 and carries its ruleStack forward; it does not independently enforce HTML embedded ranges. package.json declares vscode-textmate ^9.3.2.
- **Workaround does not cover full scope:** https://github.com/microsoft/vscode/issues/20488#issuecomment-353666956 explains why begin/while recovery works for line-delimited Markdown fences but still leaks for inline closing delimiters such as HTML permits. The earlier successful Vetur experiment therefore does not establish resolution of this issue.
- **Recent matching report:** https://github.com/microsoft/vscode/issues/313279 reports on VS Code 1.118 that an incomplete '#test' CSS selector inside <style> corrupts highlighting throughout subsequent HTML, with extensions disabled and a complete sample. Its discussion points back here: https://github.com/microsoft/vscode/issues/313279#issuecomment-4348013038. This is corroborating report evidence, not an executed reproduction against this checkout.
- **Canonical search:** Verified that https://github.com/microsoft/vscode/issues/70614 is open, but it is a newer, narrower JavaScript case and cannot absorb this older re-reviewed report. https://github.com/microsoft/vscode/issues/216 is older and open, but requests an alternative to TextMate rather than reporting the same embedded-boundary symptom. Searches for embedded-grammar reports did not establish an eligible canonical.
