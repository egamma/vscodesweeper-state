# Issue #338446 — Clipped corners and missing borders in Modern High Contrast themes

[https://github.com/microsoft/vscode/issues/338446](https://github.com/microsoft/vscode/issues/338446)

## Summary

Fresh, well-documented visual bug in the experimental Modern UI feature's High Contrast handling — the reporter's screenshots show clipped editor/tab corners and missing borders that contradict the feature's own documented HC design, but pinning the exact CSS fix for all three symptoms needs a maintainer to actually render and inspect it.

## Change summary

In 'Default High Contrast Light' with the Modern UI experiment enabled, the main editor and tabs have clipped rounded corners, the tab close button is off-center with a missing left border, and the editor actions bar is missing its right border.

## Best solution

A maintainer (or an agent session with a running instance) should reproduce with `workbench.experimental.modernUI` enabled and the 'Default High Contrast Light' theme, then adjust the HC-specific rules in src/vs/workbench/contrib/modernUI/browser/media/{roundedCorners.css, editorBorder.css, tabs.css} so the single enclosing HC frame (as described in the module's README) doesn't clip against the outer editor-part radius, and restore the tab/action-bar borders that are lost when the HC 'transparent card stroke' rule is combined with the connected-tabs frame.

## Evidence

- **feature area:** src/vs/workbench/contrib/modernUI/browser/media/ is a large, actively developed module (roundedCorners.css, editorBorder.css, tabs.css) gated behind the `.modern-ui` class toggled by the `workbench.experimental.modernUI` setting; it already has extensive HC-specific rules (contrastBorder/contrastActiveBorder, `:is(.hc-black, .hc-light)` selectors).
- **documented intent vs. screenshots:** The module's README states that in high contrast 'one rounded editor-group frame continuously encloses the title and editor surface on all four sides' and that 'the surrounding editor-area card stroke is transparent in HC... so it does not create a second frame' — the reporter's screenshots (clipped corners, missing tab/action-bar borders) show this composition breaking down, i.e. the shipped CSS deviates from its own documented design.
- **plausible cause:** editorBorder.css always applies `border-radius: var(--vscode-cornerRadius-large)` + `overflow: hidden` to `.part.editor`, while the HC-specific connected-tab frame logic in tabs.css/connectedEditorTabs.css independently manages HC borders — a radius/border mismatch between the outer editor frame and the inner HC group frame is a likely source of the clipped-corner/missing-border symptoms, but I could not execute the UI to confirm the exact rule(s) at fault.
