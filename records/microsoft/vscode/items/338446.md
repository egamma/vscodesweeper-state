# Issue #338446 — Clipped corners and missing borders in Modern High Contrast themes

[https://github.com/microsoft/vscode/issues/338446](https://github.com/microsoft/vscode/issues/338446)

## Summary

Detailed, credible report with screenshots of three distinct visual defects in the experimental Modern UI feature under High Contrast themes. I traced at least one concrete gap in the code (tabs.css only paints a border on active/selected/hover/focus tabs in HC mode, leaving plain inactive tabs with no border at all), which corroborates the report; the other two symptoms (editor corner clipping, missing editor-actions border) are plausible but not conclusively traced.

## Change summary

In 'Default High Contrast Light' (and likely other HC themes) with the Modern UI experiment enabled, the main editor's rounded corners look clipped, editor tabs are missing their left border and have an off-center close button, and the editor actions bar is missing its right border.

## Best solution

Audit the Modern UI HC overrides in src/vs/workbench/contrib/modernUI/browser/media/tabs.css and editorBorder.css so every tab state (not just active/selected/hover/focus) gets a visible border in HC themes, and add an HC-specific check for the editor-part border/corner treatment and the editor-actions separator so they render consistently with non-HC themes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/modernUI/browser/media/tabs.css`, `src/vs/workbench/contrib/modernUI/browser/media/editorBorder.css`, `src/vs/workbench/contrib/modernUI/browser/media/padding.css`

- **Behavior:**

  > With the Modern UI experiment enabled and a High Contrast theme active, the editor part's rounded corners should show a visible contrast border (not look clipped), every editor tab — not just the active/hovered/focused one — should show a visible left border, the tab close ('x') button should be centered within its hit area, and the editor actions bar (far right of the tab bar) should show its right-side separator border, matching the visual treatment already present for non-HC themes.
- **Trace:**

  > Confirmed gap: src/vs/workbench/contrib/modernUI/browser/media/tabs.css sets --modern-ui-editor-tab-border to transparent for all tabs (line 35) and only re-adds a real border for .tab:is(.active,.selected):not(:focus), :hover, and :focus under :is(.hc-black,.hc-light) (lines 824-840) — a tab that is none of those (the common case: an inactive, unfocused, non-hovered tab) gets no border at all in HC. The editor-part border/radius in editorBorder.css has no HC-specific guard at all, unlike tabs.css and roundedCorners.css which do; EDITOR_GROUP_BORDER resolves to a real contrastBorder color in HC (src/vs/workbench/common/theme.ts), so the exact cause of the 'clipped corner' look there, and of the missing editor-actions right border, is not yet pinned down from source alone — do not assume a single shared root cause across all three symptoms without confirming each independently. Boundary: this is HC-theme-specific styling only; do not change non-HC Modern UI tab/border behavior.

## Evidence

- **tab border gap:** src/vs/workbench/contrib/modernUI/browser/media/tabs.css line 35 sets --modern-ui-editor-tab-border: transparent for all tabs, and the HC-specific border overrides at lines 824-840 only target .tab:is(.active, .selected):not(:focus), :hover, and :focus — a plain inactive, non-hovered, non-focused tab in HC mode has no border rule at all, so its edge stays transparent.
- **editorGroup border token:** src/vs/workbench/common/theme.ts EDITOR_GROUP_BORDER resolves to contrastBorder in HC (#0F4A85 hcLight / #6FC3DF hcDark per src/vs/platform/theme/common/colors/baseColors.ts), so editorBorder.css's border should theoretically render in HC; I could not conclusively trace why corners still appear clipped, so this part remains unconfirmed.
- **no HC guard in editorBorder.css:** src/vs/workbench/contrib/modernUI/browser/media/editorBorder.css has no :is(.hc-black, .hc-light) exclusion or adjustment, unlike tabs.css and roundedCorners.css which do carve out HC-specific rules elsewhere — suggesting this module may not have been audited for HC yet.
- **feature is new/experimental:** Modern UI (workbench.experimental.modernUI) is an actively evolving experimental feature; this is a 2-day-old report with no comments yet, consistent with early dogfooding feedback rather than a stale issue.
