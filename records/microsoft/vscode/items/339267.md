# Issue #339267 — ChatApprovedAccountOrganizations policy enabled prevents GHE sign-in

[https://github.com/microsoft/vscode/issues/339267](https://github.com/microsoft/vscode/issues/339267)

## Summary

Traced in source: when the `ChatApprovedAccountOrganizations` policy is active and no account is yet signed in, `AccountPolicyGateContribution` forces the Chat/Copilot entitlement UI hidden (`chatEntitlementService.setForceHidden(true)`), which removes the title-bar Sign In entry point and the Chat setup dialog that normally offers a 'Continue with GHE.com' provider choice. The only remaining affordance is the gate's own notification 'Sign In' button, which calls the generic `workbench.actions.accounts.signIn` command — this always uses the configured default (non-enterprise) GitHub provider unless a separate enterprise-provider setting is also configured, so it never surfaces the GHE picker. This matches the reporter's exact symptoms.

## Change summary

With the ChatApprovedAccountOrganizations policy enabled, the normal GHE-aware sign-in UI is hidden and the fallback sign-in path only offers regular github.com auth, blocking GHE sign-in.

## Best solution

Decide how sign-in should work while the Account Policy gate is unsatisfied and no account exists yet: either exempt a GHE-capable sign-in affordance from `chatEntitlementService.setForceHidden`, or make the gate notification's 'Sign In' action route through the full chat setup/provider-picker flow (`ChatSetupController`/`chatSetupRunner.showDialog`) instead of the bare `DEFAULT_ACCOUNT_SIGN_IN_COMMAND`.
