# Issue #232125 — Shortcuts for auto indentation not working

[https://github.com/microsoft/vscode/issues/232125](https://github.com/microsoft/vscode/issues/232125)

## Summary

The shortcuts dispatch correctly; the remaining gap is Python-aware reindentation without full formatting. Current source deliberately skips languages without indentation rules, including the bundled Python configuration, but the existing bug triage should not be overturned by a decline close based on older precedent.

## Change summary

Support indentation-only alignment of existing Python code through Reindent Lines and Reindent Selected Lines in scripts and notebook cells.

## Best solution

Provide a safe indentation-only operation for Python that preserves code content and block semantics, or have the editor owner explicitly decide the supported boundary. Treat this as a language-aware reindentation capability rather than a keyboard shortcut failure; full formatting does not satisfy the reporter's requirement.

In src/vs/editor/contrib/indentation/common/indentation.ts, that function returns an empty edit list when the language configuration has no indentRulesSupport.
- **Bundled Python capability gap:** extensions/python/package.json registers extensions/python/language-configuration.json for Python. That configuration supplies brackets and onEnterRules but no indentationRules. The reindent helper therefore has a source-visible no-op path for the bundled configuration; on-enter indentation is not a substitute for reindenting existing code, and Black formatting changes more than the reporter wants. Installed extensions may contribute additional language configuration, so this does not establish every detail of the reporter's runtime.
- **Intentional limitation, not established shortcut regression:** https://github.com/microsoft/vscode/issues/111088#issuecomment-941740993 explicitly states that skipping Reindent Lines when indentation rules are absent is intentional to avoid incorrect changes. This supports classifying the missing capability as a feature request, but the precedent predates this issue's accepted bug triage and does not justify an as-designed close.
