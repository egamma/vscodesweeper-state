# Issue #339724 — Suggestions missing from /plugins disable

[https://github.com/microsoft/vscode/issues/339724](https://github.com/microsoft/vscode/issues/339724)

## Summary

Confirmed in source: `/plugin enable`/`/plugin disable` completions require `plugin.marketplace` to be set, while `/plugin update`/`uninstall` also admit unambiguous direct-installed plugins — this inconsistency is pinned by an existing unit test, so it may be intentional rather than an oversight; keeping open pending a maintainer call on whether enable/disable should mirror update/uninstall's direct-plugin handling.

## Change summary

`/plugin disable` (and `/plugin enable`) offer no completions for a directly-installed plugin (no marketplace), even though the same plugin shows up for `/plugin update` and `/plugin uninstall`.

## Best solution

Decide whether enable/disable completions should extend the same `directPluginNameCounts`-based unambiguous-direct-plugin allowance already used for uninstall/update (copilotSlashCommandCompletionProvider.ts lines 192-207), then update the candidate filter and its pinned test accordingly.
