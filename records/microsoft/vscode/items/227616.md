# Issue #227616 — Allow banning certain symbols or sort them based on usage counts

[https://github.com/microsoft/vscode/issues/227616](https://github.com/microsoft/vscode/issues/227616)

## Summary

Team-authored feature request with two distinct asks — symbol-level banning and usage-count sorting of auto-imports. Existing settings (`autoImportFileExcludePatterns`, `autoImportSpecifierExcludeRegexes`) partially address module-level exclusion but don't cover per-symbol banning or usage-based ranking. Stays open as a valid enhancement.

## Change summary

Allow banning specific symbols from auto-import suggestions and/or sorting suggestions by usage frequency in the project.

## Best solution

The module-level exclusion part is partially addressed by existing `autoImportFileExcludePatterns` (resource-scoped, already configured in VS Code's own `.vscode/settings.json`) and the newer `autoImportSpecifierExcludeRegexes`. For the VS Code repo's specific pain point (Disposable from `vscode` module), `autoImportSpecifierExcludeRegexes` with a pattern like `^vscode$` or `autoImportFileExcludePatterns` targeting the vscode typings could help. The remaining gap is per-symbol granularity and usage-count-based sorting — these would need TypeScript Server support. Worth confirming whether the existing settings suffice for the original scenario before pursuing deeper symbol-level work.
