# Issue #301220 — Locked `Explore.agent.md` frontmatter appears editable using `Configure Tools...` but actually isn't

[https://github.com/microsoft/vscode/issues/301220](https://github.com/microsoft/vscode/issues/301220)

## Summary

The misleading edit path remains on current main: the tools CodeLens is offered for read-only agent models and directly changes the in-memory model without ensuring the change can be saved. Keep this open, with a maintainer decision on whether generated built-in agents should suppress the affordance or enter an explicit editable-copy/unlock flow.

## Change summary

Prevent Configure Tools from appearing to persist changes to a locked built-in agent when those changes cannot be saved.

## Best solution

Make Configure Tools respect the agent resource's read-only state and never report an apparently successful edit that will disappear. A maintainer should choose between hiding or disabling the CodeLens for immutable generated agents and offering an explicit supported unlock or editable-copy workflow.

- **Behavior:**

  > Configure Tools must not make a locked built-in agent appear successfully edited when the selected tools cannot be persisted. After the interaction, either no edit affordance is available for the immutable resource or the user has explicitly entered a supported editable state whose changes survive closing and reopening the file. Writable custom agent files must continue to expose Configure Tools and persist their selections.
- **Trace:**

  > PromptToolsCodeLensProvider in src/vs/workbench/contrib/chat/browser/promptSyntax/promptToolsCodeLensProvider.ts unconditionally creates the CodeLens for supported prompt files with a tools attribute. Its command passes the model to PromptFileRewriter.rewriteTools, which applies pushEditOperations directly in src/vs/workbench/contrib/chat/browser/promptSyntax/promptFileRewriter.ts without consulting the resource's read-only state. ExploreAgentProvider in extensions/copilot/src/extension/agents/vscode-node/exploreAgentProvider.ts regenerates Explore.agent.md from configuration through CachedAgentFileWriter, so silently treating the generated file as normally writable is outside the safe boundary. Preserve Configure Tools behavior for ordinary writable .agent.md files and avoid changing tool-name serialization or picker selection semantics. The uncertainty starts at the intended locked-resource UX: suppress the edit affordance, or provide an explicit durable unlock/editable-copy path.
- **Open decisions:**
  - For generated read-only built-in agents, should Configure Tools be hidden or disabled, or should activating it explicitly create/unlock a durable editable customization?
