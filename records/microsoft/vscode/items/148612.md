# Issue #148612 — Parenthesis and brace matching within RegExps

[https://github.com/microsoft/vscode/issues/148612](https://github.com/microsoft/vscode/issues/148612)

## Summary

Keep open: built-in bracket matching still excludes regular-expression tokens, and the maintainer explicitly reopened this request to explore matching rather than colorization. The extension mentioned in the discussion is a useful workaround, not evidence that the built-in request is complete.

## Change summary

Highlight the matching parenthesis, brace, or bracket when the cursor is on a structural delimiter inside a regular expression.

## Best solution

Provide regex-aware matching that distinguishes structural delimiters from escaped characters and character-class contents, without pairing across separate literals. First agree on the initial language coverage and establish how incomplete expressions remain isolated from surrounding source.

- **Validation:** After agreeing on language coverage, exercise the actual shipped grammar in integration or manual checks: with editor.matchBrackets enabled, place the cursor on structural delimiters in /((?:[)])blah)/ and /a{2,3}/ and verify their matching highlights; escaped delimiters and the literal ) inside [)] must not become group pairs. Verify /(/ + variable + /)/ never pairs across literals or corrupts matching in subsequent code, and retain existing bracket-matching tests.
- **Behavior:**

  > In supported languages, placing the cursor on a structural regex parenthesis, bracket, or quantifier brace highlights its matching delimiter using the editor's existing matching interaction. Escaped delimiters and delimiter-like characters inside character classes must not be mistaken for enclosing group delimiters. Incomplete expressions must not create matches across separate literals or disturb matching in surrounding source. Acceptance must exercise real language tokenization, not merely a synthetic language that treats every delimiter as code.
- **Trace:**

  > BracketMatchingController delegates highlighting to model.bracketPairs in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts. The bracket-tree tokenizer requires StandardTokenType.Other, while the legacy matcher uses ignoreBracketsInToken to exclude regexes; shipped JavaScript regex scopes remain string.regexp.js without an embedded regex language or delimiter token-type overrides. The JavaScript grammar already distinguishes groups, quantifiers, and character classes, but their availability for syntax coloring does not establish safe bracket pairing during malformed edits. https://github.com/microsoft/vscode/issues/144736 supplies bracket-scope controls but does not itself complete this request. https://github.com/RedCMD/regex-syntax-highlighter-vscode demonstrates a separate embedded-language approach for JS/TS; it is not adopted by the built-in grammar. Preserve ordinary string/comment exclusion, surrounding-language matching, and editor.matchBrackets semantics; nested colorization is not required by this report. The remaining design boundary is initial language coverage and validating isolation while expressions are incomplete.
- **Open decisions:**
  - Should the initial built-in capability cover JavaScript/TypeScript regex literals only, or also other language regex forms such as the Python examples discussed in the thread?
