Keep and Undo are now implemented in the Copilot harness, but preserving the user's Local selection is a separate concern that current selection logic does not unconditionally satisfy. Keep this open: the verified related issues cover different portions of the request, not its full scope.

- **Inline review already implemented:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostEditReview.ts implements file-level and individual-change keep/undo through AgentHostEditReviewEntry and AgentHostEditReview. agentHostSessionHandler.ts attaches this review when the working set and Keep/Undo preferences are enabled. The registered setting chat.editor.workingSet.enabled in chat.shared.contribution.ts describes these controls in both the working set and editor.
- **Maintainer update and merged implementation:** https://github.com/microsoft/vscode/issues/339363#issuecomment-6346982654 explicitly announces the return of inline Keep/Undo, including review between agent edits, and lists limitations for existing sessions and unsupported file types. https://github.com/microsoft/vscode/pull/342469 is merged. This addresses the review-controls portion, not the separate request to preserve Local.
- **Preference persistence has an override:** src/vs/workbench/contrib/chat/common/chatSessionTypePreference.ts persists chat.userSelectedSessionType at profile scope. However, getDefaultNewChatSessionTypeAndReasonFromServices in common/constants.ts:576-618 bypasses a remembered Local selection when isCopilotHarnessPreferred is true and replaces a resolved Local selection with AgentHostCopilot. This establishes a remaining product-policy question, but does not prove that an update triggered the reporter's particular switch.

Neither alone owns both requested outcomes, so neither establishes a full-scope duplicate.
