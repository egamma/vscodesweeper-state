# Issue #246026 — Settings Search returning options that have no clear relation to the search

[https://github.com/microsoft/vscode/issues/246026](https://github.com/microsoft/vscode/issues/246026)

## Summary

Still reproduces on main: the local settings search falls back to non-contiguous substring matching (`matchesSubString`) when no closer match exists, returning noise for queries like 'bisect' that partially scatter-match many key IDs.

## Change summary

Searching settings for a term with no real match (e.g. 'bisect') returns many irrelevant results due to overly permissive non-contiguous fuzzy matching.

## Best solution

Add a minimum quality threshold or scoring cutoff in the `LocalSearchProvider.searchModel` filtering logic so that when only `NonContiguousQueryInSettingId` matches exist (the weakest tier), results are suppressed or shown with a 'no exact matches' indicator rather than presented as real results. The fix belongs in `src/vs/workbench/contrib/preferences/browser/preferencesSearch.ts` around the `filteredMatches` filtering logic.
