# Issue #345518 — Links in the Inbox details don't properly go through opener

[https://github.com/microsoft/vscode/issues/345518](https://github.com/microsoft/vscode/issues/345518)

## Summary

Inbox PR links still bypass contributed external openers on current main. The detail-pane handler calls the opener service without the option that enables GHPR handling; the related hover fix does not cover this path.

## Change summary

Make Inbox detail PR links honor the contributed opener so eligible links open in the GHPR webview rather than the browser.

## Best solution

Bring Inbox PR navigation into parity with the session hover, honoring contributed opener selection and retaining browser fallback when no contributed opener handles the link.
