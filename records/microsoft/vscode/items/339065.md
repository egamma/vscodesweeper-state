# Issue #339065 — Dictation cleanup: allow any chat model available to the user/organization instead of a hard-coded model ID

[https://github.com/microsoft/vscode/issues/339065](https://github.com/microsoft/vscode/issues/339065)

## Summary

Fresh, well-diagnosed feature request (0 days old, no maintainer input yet): current main confirms the setting, constant, and alias really are hard-coded to gpt-5.6-luna, with silent fallback to copilot-utility-small when unavailable. The ask is reasonable and narrowly scoped, but it's too new to judge demand or design direction, so it stays open for discussion.

## Change summary

Let `dictation.experimental.llmCleanupModel` accept any chat model ID the user/org has enabled, instead of only `auto | copilot-utility-small | gpt-5.6-luna`, so dictation cleanup doesn't silently regress when an org's model policy excludes the hard-coded default.

## Best solution

Relax the setting's enum to a free-form model ID (or a dynamic enum sourced from the user's selectable models) in chat.shared.contribution.ts, and have chatSpeechToTextService.ts validate/select the configured model the same way other chat model pickers do, falling back only when the ID truly doesn't resolve — while leaving the core-only `copilot-dictation-cleanup-luna` alias untouched as requested.
