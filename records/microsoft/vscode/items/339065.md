# Issue #339065 — Dictation cleanup: allow any chat model available to the user/organization instead of a hard-coded model ID

[https://github.com/microsoft/vscode/issues/339065](https://github.com/microsoft/vscode/issues/339065)

## Summary

Young (2 days old), well-diagnosed feature request parked in Backlog Candidates per the standard 60-day bot message — not stale, and the hard-coding it describes is confirmed on current main. Keeping open per the upvote/age policy for Backlog Candidates; no canonical duplicate owns this specific ask.

## Change summary

Allow `dictation.experimental.llmCleanupModel` to accept any chat model ID the current user/org can already use, instead of only `auto`/`copilot-utility-small`/the hard-coded `gpt-5.6-luna`.

## Best solution

Relax the setting's enum/validation and `_getLlmCleanupModel()` in chatSpeechToTextService.ts to accept any model ID available to the user (validated against their selectable chat models), with a visible fallback hint when the configured model isn't available — a maintainer should decide the validation/fallback UX before implementation.
