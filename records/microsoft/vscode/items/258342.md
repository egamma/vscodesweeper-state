# Issue #258342 — `Chat: Show Chats` command doesn't respect Chat in Editor

[https://github.com/microsoft/vscode/issues/258342](https://github.com/microsoft/vscode/issues/258342)

## Summary

The legacy `Chat: Show Chats` command has been retired, and the replacement Agents sessions UI intentionally uses a consistent default destination with an explicit “Open as Editor” action rather than inferring the destination from focus.

## Change summary

Make chat-history selection preserve the current chat surface, opening sessions in an editor when invoked from a chat editor.

## Best solution

Keep the current Agents sessions workflow: open sessions in the standard chat surface by default and use the explicit “Open as Editor” action when an editor tab is desired.

## Vision fit

- **Fit:** rejected
- **Reason:** Context-dependent opening behavior conflicts with the preference for predictable, uniform UI interactions, while the current UI offers an explicit editor-opening action.
- **Evidence:** Value and guardrail: “Simple, uniform UI and UI interactions.”

- **legacy command retired:** Merged PR https://github.com/microsoft/vscode/pull/282947 and commit https://github.com/microsoft/vscode/commit/87e0a7c4aec4ca01d3585d22962bbd05cfbfca10 retired `workbench.action.chat.history` and its `ChatHistoryAction` in favor of the Agents sessions picker.
- **current behavior:** On current main, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsOpener.ts` opens ordinary selections using `ChatViewPaneTarget`, while `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts` provides the explicit `Open as Editor` action (`workbench.action.chat.openSessionInEditorGroup`).
