# Issue #341034 — Agent Host: a GitHub sign-in in one window shows "Sign in to use GitHub Copilot" in every other open window, and each sign-in re-triggers the rest

## Summary

Thanks for the detailed logs. The report is complete but I couldn't confirm the cause from source. The cited log line is the benign 'forward the replacement token' path and doesn't show where the sign-in modal comes from, so the report stays open for a maintainer to retest with several windows.

## Change summary

With several windows open, one GitHub sign-in makes every other window show the Copilot sign-in modal, and each of those sign-ins repeats it.

## Best solution

Find which Agent Host or Copilot path raises the interactive sign-in after a kind=replacement session change, and make it reuse the new session silently. Consider consolidating with the related multi-account issue if the root cause matches.

  > A GitHub session replacement (same account and scopes) triggered in one window must be picked up silently by every other window. No Copilot sign-in modal appears, and no cascade of further interactive logins follows. Acceptance: reproduce with several windows, then confirm no modal appears after the change.
- **Trace:**

  > revokeAuthenticationForRemovedSessions in agentHostAuth.ts re-resolves the session and forwards it, which should be silent. Find what actually raises the 'Sign in to use GitHub Copilot' modal. Likely candidates are the Agent Host token-rejected or 401 handling and the startup path that reports noToken. The reported 401 'Bad credentials' and the 429 during startup are also leads. Do not change how DefaultAccount reconciles sessions, since it already behaves correctly. Related: https://github.com/microsoft/vscode/issues/340493.

## Evidence

- **log line origin:** 'Authenticating for resource after session removal' is logged in revokeAuthenticationForRemovedSessions (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts, ~L670). It runs only when a replacement session resolves, and it forwards that token to the host. It does not itself prompt, so the modal likely comes from another path, such as the host rejecting the token (the 401 'Bad credentials' in the report) or a separate sign-in trigger.
- **related issue:** https://github.com/microsoft/vscode/issues/340493 is related (account selection with multiple accounts) but is not the same symptom.
- **second reporter:** A second user in the thread reports the same cross-window prompt, so it is not isolated to one machine.
