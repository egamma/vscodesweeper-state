# Issue #235173 — Git - Don't show inline blame while dragging selection

[https://github.com/microsoft/vscode/issues/235173](https://github.com/microsoft/vscode/issues/235173)

## Summary

The inline blame annotation still follows intermediate selection positions in current source. Keep this open in the Git area; detecting selection completion requires further investigation across the editor and extension-host boundary.

## Change summary

Suppress inline Git blame annotations during mouse-drag selection and restore them after the selection is completed.

## Best solution

Inline blame should remain hidden throughout an active selection drag, including pauses while the mouse button is held, and appear at the final selected position after release. Preserve ordinary cursor navigation, completed selections, and status-bar blame behavior.

- **Behavior:**

  > With inline Git blame enabled, dragging a multiline selection currently moves the annotation with the selection endpoint. The annotation should be absent while selection dragging is active and return for the final endpoint after release. A pause with the mouse button still held must not restore the annotation. Completed selections and ordinary cursor navigation should retain blame annotations, and status-bar blame should remain unchanged.
- **Trace:**

## Evidence

- **Current-source reproduction:** In src/vs/editor/browser/controller/mouseHandler.ts, MouseDownOperation._onMouseDownThenMove dispatches selection updates during dragging. src/vs/workbench/api/browser/mainThreadEditor.ts forwards changed selections through onDidChangeCursorSelection. - **Throttle does not wait for release:** extensions/git/src/decorators.ts implements throttle by serializing/coalescing asynchronous calls, not by waiting for mouse release or selection completion.
