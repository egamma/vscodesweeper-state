# Issue #335218 — Composite view containers should not silently inherit the first view's title and icon

[https://github.com/microsoft/vscode/issues/335218](https://github.com/microsoft/vscode/issues/335218)

## Summary

Confirmed in source: a merged/composite view container's title and icon are indeed taken from the first visible view descriptor, with no generic fallback and no way to rename or re-icon the group — this is a genuine, unaddressed gap rather than something already covered by existing UI.

## Change summary

When multiple views are dragged into one container, request a generic 'group' label/icon fallback (and ideally rename/re-icon support) instead of silently inheriting the first view's title and icon.

## Best solution

Product decision needed in the workbench/views area: introduce a generic fallback title/icon in ViewContainerModel.updateContainerInfo (src/vs/workbench/services/views/common/viewContainerModel.ts, around lines 349-360) when there are 2+ visible views and no explicit user-assigned name, and consider extending storage/state to support user-set composite container names/icons similar to editor group labels.
