# Issue #335218 — Composite view containers should not silently inherit the first view's title and icon

[https://github.com/microsoft/vscode/issues/335218](https://github.com/microsoft/vscode/issues/335218)

## Summary

Confirmed against current main: composite view containers do inherit the first visible view's title/icon with no generic fallback or rename affordance, exactly as described — this is a real gap, but it's a product/UX decision (default behavior change plus a new rename/icon-pick UI) rather than a bug or something auto-fixable.

## Change summary

When 2+ views are grouped into a custom container, the container silently takes on the first view's title/icon instead of a neutral 'group' identity, with no way to rename or re-icon it.

## Best solution

Product decision needed in src/vs/workbench/services/views/common/viewContainerModel.ts (updateContainerInfo) on whether multi-view containers should fall back to a generic label/icon, paired with a new rename/custom-icon affordance similar to editor group or profile renaming — likely a workbench core-UX feature rather than an extension concern.
