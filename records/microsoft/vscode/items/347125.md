## Evidence

- **Current source confirms the defect:** src/vs/platform/files/node/diskFileSystemProvider.ts:329-359 opens the file and awaits this.write(handle, 0, content, 0, content.byteLength) exactly once, discarding the returned byte count. Its doWrite method at lines 643-658 returns Promises.write(...).bytesWritten; a successful short write therefore reaches normal completion without writing the remainder.
- **Service and IPC reachability:** FileService.writeFile in src/vs/platform/files/common/fileService.ts selects doWriteUnbuffered for a complete VSBuffer and returns resolved metadata without checking input length against saved size. DiskFileSystemProviderClient.writeFile forwards the buffer through the channel, and src/vs/platform/files/node/diskFileSystemProviderServer.ts:139-142 delegates directly to the disk provider.
- **Existing contrasting behavior:** FileService.doWriteBuffer in src/vs/platform/files/common/fileService.ts loops over actual bytesWritten and advances both offsets until the requested length is complete. The unbuffered disk provider lacks that completion behavior; atomic writes also delegate to its doWriteFile method.
- **Concrete native reproduction:** https://github.com/microsoft/vscode/issues/347125 supplies a macOS Node 24.22.1 reproduction using a child-only 1,024-byte RLIMIT_FSIZE and a 2,048-byte service/IPC write, which resolves with a 1,024-byte file.
