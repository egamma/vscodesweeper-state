# Issue #158120 — Trivial pollution of workbench.action.terminal.runRecentCommand list

[https://github.com/microsoft/vscode/issues/158120](https://github.com/microsoft/vscode/issues/158120)

## Summary

Partially addressed — the nonce-based trust system is now implemented (commands sent via `633;E` without a matching nonce are marked `isTrusted: false`), and space collapsing landed in PR #158198. However, the "Run Recent Command" quick pick (`showRunRecentQuickPick`) does not yet use `isTrusted` to warn users or preview untrusted commands, and the blocking issue #153095 (multiline quick pick details) remains open. The remaining work is still valid.

## Change summary

Commands injected into the terminal via malicious escape sequences can silently appear in the "Run Recent Command" quick pick list, potentially tricking users into executing hidden payloads.

## Best solution

Extend `showRunRecentQuickPick` in `src/vs/workbench/contrib/terminalContrib/history/browser/terminalRunRecentQuickPick.ts` to surface the `isTrusted` flag on commands — either by filtering untrusted entries, adding a visual warning indicator, or requiring confirmation before executing an untrusted command (similar to the rerun-command confirmation already in `decorationAddon.ts`). Landing https://github.com/microsoft/vscode/issues/153095 (multiline quick pick details) would further help by letting users preview the full command text.
