# Issue #326017 — Enabling (not using) Copilot Chat crash-loops the extension host with a V8 out-of-memory abort

[https://github.com/microsoft/vscode/issues/326017](https://github.com/microsoft/vscode/issues/326017)

## Summary

The detailed A/B test, process sampling, V8 crash reports, and observed `git add --pathspec-from-file` process establish a real Copilot-triggered extension-host OOM. The older crash-loop reports do not own this pathspec/checkpoint-specific root cause, and current source still contains the implicated Git operations, so this should remain open for diagnosis.

## Change summary

Enabling Copilot Chat in a large clean repository rapidly exhausts the extension-host heap while Copilot session code stages thousands of paths through a temporary Git index.

## Best solution

Determine which restored-session or activation-time path invokes workspace-change/checkpoint collection without chat interaction, then ensure that collection remains bounded and excludes ignored artifacts so enabling Copilot cannot crash the shared extension host.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorkspaceFolderServiceImpl.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorktreeCheckpointServiceImpl.ts`, `extensions/copilot/src/platform/git/vscode-node/utils.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/test/chatSessionWorkspaceFolderService.spec.ts`
- **Validation:** Reproduce with a clean large repository containing substantial ignored build output and existing Copilot session metadata: enabling Copilot without opening chat must keep the extension host alive with bounded memory, must not stage ignored artifacts into a temporary index, and existing session change/checkpoint tests must continue to pass.
- **Behavior:**

  > Enabling Copilot Chat must not scan or stage a clean workspace's ignored build artifacts, exhaust the extension-host heap, or restart the host when no chat request has been made. Existing sessions may still expose accurate tracked, untracked, and deleted-file changes when explicitly resolved. Acceptance requires the reported large-workspace startup scenario to remain stable and session change/checkpoint behavior to remain correct.
- **Trace:**

  > The reporter observed `git add -A --pathspec-from-file=.../vscode-sessions-*/pathspec.txt` immediately before each V8 OOM, with pathspecs containing thousands of ignored paths. Current main creates those files in ChatSessionWorkspaceFolderService.getWorkspaceChanges and ChatSessionWorktreeCheckpointService._writeWorktreeTree; getUncommittedFilePaths obtains entries from RepoContext change groups. CopilotCLIChatSessionItemProvider can build session changes, although lazy loading is now enabled by default, so the trace has not established which activation-time refresh or restored-session path still invokes the expensive operation. Preserve explicit session change display and checkpoint semantics; the boundary is preventing idle activation from performing unbounded workspace staging. https://github.com/microsoft/vscode/issues/318595 is related but has a separately diagnosed transcript-retention cause, and https://github.com/microsoft/vscode/pull/318862 addresses a different Git-status concurrency failure.

## Evidence

- **confirmed reproduction:** The reporter repeatedly observed the extension host grow from about 1.2 GB to 5 GB in 12 seconds and abort in V8 OOM; disabling only Copilot Chat stopped the loop and re-enabling it restored the failure.
- **matching source path:** extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorktreeCheckpointServiceImpl.ts:262-278 and chatSessionWorkspaceFolderServiceImpl.ts:221-243 create `vscode-sessions-*` pathspec files and execute `git add -A --pathspec-from-file=...`, matching the process and artifacts observed by the reporter.
- **unresolved trigger:** On current main, getUncommittedFilePaths in extensions/copilot/src/platform/git/vscode-node/utils.ts:98-120 derives paths from Git repository change groups, while lazy session-item loading defaults to enabled in configurationService.ts. That does not yet explain a clean repository producing roughly 9,573 ignored-artifact paths during activation, so the exact current trigger remains unresolved.
- **distinct from earlier canonical candidate:** https://github.com/microsoft/vscode/issues/318595 is older and reports the same visible restart loop, but its diagnosed cause is retention of Claude transcript strings during cross-agent session synchronization. This report instead captures temporary pathspec files and a running Git staging operation, evidence of a distinct root cause.
- **prior Git fix insufficient:** https://github.com/microsoft/vscode/pull/318862 fixed a different startup crash by throttling initial Git repository status calls. It merged before this issue's VS Code 1.128.1 reproduction and does not change Copilot's temporary-index/pathspec code.
