# Issue #339269 — Copilot agent host: every ~/.copilot/instructions file is in the system prompt twice

[https://github.com/microsoft/vscode/issues/339269](https://github.com/microsoft/vscode/issues/339269)

## Summary

Well-researched duplicate-content bug confirmed against current main's agent-host customization discovery code; the fix spans this repo and the bundled @github/copilot SDK the reporter could only inspect as minified JS, so it needs a maintainer decision on which side de-dupes before an agent can implement it.

## Change summary

Every file under ~/.copilot/instructions is included twice (byte-identical) in the agent host's system prompt, because it is both merged by the Copilot runtime's own discovery and re-submitted as an `instructionDirectories` entry by the agent host.

## Best solution

Either have discoverRules/toSdkInstructionDirectories in sessionCustomizationDiscovery.ts and copilotPluginConverters.ts skip directories the runtime already merges into its `user-copilot-instructions` source, or push a dedup-by-path/content fix into the bundled SDK — a maintainer with visibility into the @github/copilot package needs to pick the side.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`, `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`
- **Validation:** A session-state events.jsonl capture (or an agentHost test asserting the built SDK config) showing each ~/.copilot/instructions file appears exactly once in instructionDirectories/system prompt, for a session with both user and project instruction files present.
- **Trace:**

  > discoverRules() in sessionCustomizationDiscovery.ts pushes one RuleCustomization per file returned by `client.rpc.instructions.discover`, with no distinction for files that the SDK's own merged `user-copilot-instructions` source already covers (user config dir). toSdkInstructionDirectories() in copilotPluginConverters.ts then turns those rule file paths into directory entries sent back to the SDK as `instructionDirectories`. Because the bundled @github/copilot runtime's own dedup (not in this repo's source — it's in the minified `@github/copilot` package) only hashes content for `home`/`repo`/`model` source types and otherwise dedups by id, the merged user source and the per-file `vscode-instructions/external/<path>` sources end up as distinct ids and both survive. Where the uncertainty starts: which discovery call inside the SDK attributes the user instructions folder to the agent host's directory list in the first place, since that logic is only visible as minified JS.
- **Open decisions:**
  - Should the agent host filter the user config instructions directory out of instructionDirectories before handing it to the SDK, or should the fix live in the bundled runtime's dedup (content/path based instead of id based)?
  - Is there a maintainer who owns the @github/copilot bundle who can confirm the exact discovery source attributing the user folder, since the reporter could not determine this from the minified code?

## Evidence

- **discoverRules:** src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:571-620 turns every file returned by `client.rpc.instructions.discover` into a RuleCustomization keyed by its own uri, including files under the user's ~/.copilot/instructions folder — nothing here filters out a directory the runtime already merges on its own.
- **toSdkInstructionDirectories:** src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:243-262 extracts the parent directory of each rule file (including user ones) and passes it back to the SDK via `instructionDirectories`, matching the reporter's step 2/3 trace exactly — confirms the vscode-side half of the mechanism on current main.
- **AGENT_INSTRUCTION_FILENAMES:** sessionCustomizationDiscovery.ts:84 only special-cases agents.md/claude.md/gemini.md/copilot-instructions.md for alwaysApply treatment, which matches why copilot-instructions.md is deduped but other *.instructions.md files are not.
- **unverifiable half:** Reporter states steps 1, 3, 4 (the runtime's own merge/dedup logic) live only in the minified @github/copilot bundle, not in this repository's source — cannot independently confirm those from the checkout.
