# Issue #339269 — Copilot agent host: every ~/.copilot/instructions file is in the system prompt twice

[https://github.com/microsoft/vscode/issues/339269](https://github.com/microsoft/vscode/issues/339269)

## Summary

Freshly filed, unusually well-diagnosed report with concrete file/line citations; tracing the current main source confirms the mechanism it describes is plausible, but the final duplication depends partly on the bundled `@github/copilot` SDK's own dedup logic, which isn't in this checkout — keeping open for a maintainer/agent to confirm end-to-end and decide where the fix belongs.

## Change summary

Every file under `~/.copilot/instructions/` is injected into the Copilot agent host system prompt twice (once via the runtime's own home-instructions discovery, again via the host's explicit `instructionDirectories`), adding ~9KB of duplicated context per request with ~12 small instruction files.

## Best solution

In `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts` (`toSdkInstructionDirectories`/`instructionDirectories` construction) and `sessionCustomizationDiscovery.ts` (`discoverRules`/`toDirectoryCustomizations`), avoid re-feeding directories (notably the user home `~/.copilot/instructions`) that the SDK runtime already discovers and merges on its own — mirroring the existing 'rely on SDK discovery to avoid duplicates' comment that today only applies to plugin directories, not instruction/skill directories.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`, `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`
- **Validation:** Launch a Copilot CLI agent host session with a populated `~/.copilot/instructions/` folder and inspect `events.jsonl`'s `system.message` to confirm each instruction file's content appears exactly once after the fix.
- **Behavior:**

  > When a user has files under `~/.copilot/instructions/`, each file's content should appear exactly once in the agent host's system prompt, matching the Local agent's behavior and the behavior already correct for `.github/instructions` project files and `~/.copilot/copilot-instructions.md`.
- **Trace:**

  > `copilotSessionLauncher.ts` builds `instructionDirectories` from `plugins.flatMap(p => p.instructions)` (toSdkInstructionDirectories, ~line 996), where `plugins` is derived from `DirectoryCustomization`s produced by `sessionCustomizationDiscovery.ts:discoverRules`/`toDirectoryCustomizations`, which does not exclude the user-home instructions directory (grouped explicitly via `_userHome` in `getDiscoveredDirectories`). This directory is then handed to the SDK as an explicit `instructionDirectories` entry even though the SDK's own `instructions.discover` already surfaces and merges those same files as a `user-copilot-instructions` source — the suspected duplication point described by the reporter. The exact SDK-side merge/dedup behavior (which only hashes content for `type` home/repo/model) lives in the bundled `@github/copilot` package, not in this repo, so it could not be fully confirmed from source alone. Do not touch handling of workspace `.github/instructions` files (already deduped correctly) or plugin-owned instruction directories (already excluded via `pluginsWithoutDirs`).
- **Open decisions:**
  - Should the Agent Host simply drop the user-home instructions directory from `instructionDirectories` (since the runtime already discovers it), or should the fix instead target the SDK's cross-source dedup (by resolved path/content) so other similar host-fed directories don't risk the same duplication?
  - Is there a reason the host currently feeds `instructionDirectories`/`skillDirectories` explicitly at all for non-plugin sources, given the adjacent code comment says plugin directories are deliberately NOT fed explicitly to avoid duplicates — should instructions/skills follow the same pattern?

## Evidence

- **instructionDirectories construction:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:996 builds `instructionDirectories = toSdkInstructionDirectories(plugins.flatMap(p => p.instructions))` from discovered rule customizations, with no exclusion for the user home instructions directory; a nearby comment at line ~980 notes 'rely on the SDK to discover... to avoid duplicates' but that logic is scoped to plugin directories via `pluginsWithoutDirs`, not instructions/skills.
- **rule discovery includes home files:** src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:587-613 (`discoverRules`) turns every `instructionDiscovery.sources` entry into a `RuleCustomization` unless its type/location is 'plugin'; user-home instruction files (type 'home') are kept and marked `alwaysApply`, then their containing directory flows into `toDirectoryCustomizations` → `mapToParsedPlugin` → `instructionDirectories`.
- **home-directory grouping:** getDiscoveredDirectories() (sessionCustomizationDiscovery.ts:~290-325) explicitly groups per-file user-home instruction discoveries under `this._userHome` as a `DiscoveredType.AgentInstruction` directory, confirming the host treats the user instructions folder as its own discovered unit separate from the runtime's native handling.
- **uncertainty acknowledged by reporter:** The reporter states they could not confirm from the minified `@github/copilot` bundle which discovery path makes the agent host include the user folder, and that the final content-hash dedup (by type home/repo/model) lives in SDK code outside this repository — so full confirmation requires exercising the actual session, not just reading src/vs.
