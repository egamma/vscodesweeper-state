# Issue #347221 — Agents window: let the agent start a PR review session from a pull request link (e.g. `open_pr_session` tool)

[https://github.com/microsoft/vscode/issues/347221](https://github.com/microsoft/vscode/issues/347221)

## Summary

Keep open: the UI supports PR-backed sessions, but the agent-facing tools still cannot request one. The assigned 1.150.0 milestone also bars a cleanup close.

## Change summary

Let an agent turn a pull request link into an isolated, PR-linked review session with attached context and confirmation.

## Best solution

Expose the existing PR-session capability through the agent host's session tools, preserving isolation, PR association, context and confirmation. Settle whether this starts an independent session or continues the current conversation before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/serverToolNames.ts`, `src/vs/platform/agentHost/node/shared/sessionServerTools.ts`, `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`, `src/vs/sessions/contrib/github/browser/createSessionFromPullRequestAction.ts`
- **Validation:** After settling the contract, exercise a session with local uncommitted changes and a PR-review prompt: approval must produce the selected PR checkout, association and context without changing the original checkout; rejection must create no session or worktree. Add focused session-tool tests for the agreed creation/continuation behavior and invalid or unavailable repositories.
- **Behavior:**

  > A user asking an agent to review a PR link can enter a proper PR-backed review environment instead of relying on shell checkout in the current folder. The environment contains the requested PR checkout, its session association and review context. The operation follows confirmation and preserves unrelated local work. Acceptance must establish the agreed conversation-continuity behavior and explicit handling when the repository is unavailable.
- **Trace:**

  > SessionServerToolName and ICreateSessionArgs currently expose no PR-session input. applyCreateSessionTool supports delegation and workspace isolation, but does not resolve a PR supplied by the user. The UI command in createSessionFromPullRequestAction.ts separately passes pullRequestUrl and attaches PR context through createAndSendNewChatRequest. WorktreeIsolation._resolvePullRequestWorkingDirectory already resolves a PR against a matching repository remote and creates a managed checkout. Preserve existing ordinary session creation, repository matching, credential boundaries and confirmation behavior. The related parity umbrella is https://github.com/microsoft/vscode/issues/331567; it records the broader gaps rather than settling this feature's public contract.
- **Open decisions:**
  - Should opening a PR review create an independent session, continue the current conversation in the PR environment, or offer both?
  - Is checkout always worktree-isolated, or should explicit clean-folder in-place checkout be supported?
  - Should the same tool also create issue-backed sessions, or remain PR-specific?
  - When the selected host lacks the repository, should the operation refuse, offer repository setup, or select another host?
