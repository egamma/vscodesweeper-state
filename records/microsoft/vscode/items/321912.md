# Issue #321912 — Corporate Controls: Whitelist/Block Extensions by Tag

[https://github.com/microsoft/vscode/issues/321912](https://github.com/microsoft/vscode/issues/321912)

## Summary

A real enterprise-security gap remains: the existing AllowedExtensions policy supports extension IDs, publishers, versions, and a wildcard, but cannot govern the `language-models` tag. Keep this open for human security and policy review because it concerns potential disclosure of sensitive data to third-party model providers.

## Change summary

Allow enterprise administrators to permit or block extensions by Marketplace tag, particularly third-party language-model providers.

## Best solution

Define a trustworthy enterprise-policy contract that can deny extensions carrying the `language-models` tag while preserving explicit administrative exceptions. The design must specify rule precedence and enforcement for Marketplace installs, already-installed extensions, remote extension hosts, and installations without trusted tag metadata.

- **source-confirmed gap:** src/vs/platform/extensionManagement/common/allowedExtensionsService.ts evaluates ID, publisher, version, prerelease status, and target platform but has no tag rule. src/vs/platform/extensionManagement/common/abstractExtensionManagementService.ts also strips an IGalleryExtension down to ID and publisher before the installation check, despite IGalleryExtension exposing `tags`.
- **requested tag exists:** src/vs/platform/extensionManagement/common/extensionManagement.ts defines `LANGUAGE_MODEL_CHAT_PROVIDER_EXTENSION_TAG` as `language-models`; src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts uses that tag to find third-party model-provider extensions.
- **existing capability is partial:** https://github.com/microsoft/vscode/issues/84756 delivered the base extension allow/block policy and is closed as completed, but the current implementation does not cover tag-based grouping.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/40239 concerns workspace configuration for enabling or disabling named extensions, while https://github.com/microsoft/vscode/issues/314414 concerns server-side enforcement in Remote-SSH; neither reports this issue's tag-based corporate-control requirement.
- **protected security concern:** The report explicitly concerns sensitive data being sent to unapproved model providers, so the security-sensitive hard keep-open rule applies and the policy boundary should be decided by human maintainers.
