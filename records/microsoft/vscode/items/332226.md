# Issue #332226 — Integrated browser pop ups are not shared with the agent automatically

[https://github.com/microsoft/vscode/issues/332226](https://github.com/microsoft/vscode/issues/332226)

## Summary

This is intentional: child browser views spawned via window.open/popups deliberately do not inherit agent sharing from their parent, per an explicit comment in the browser view service. The agent can still request access to the new page via the existing `open_browser_page` tool/sharing flow, so this is a security/consent boundary rather than a bug.

## Change summary

Pop-up windows opened from an integrated-browser page (OAuth, window.open, modals) are not automatically added to the agent's shared browser context.

## Best solution

Keep the current design — child views share host/owner/storage but not agent access by design (src/vs/platform/browserView/electron-main/browserViewMainService.ts:442-450, `_createNativeBrowserView`). The existing `list_browser_pages` / `open_browser_page` tools already let the agent discover and request sharing of unshared pages including popups (src/vs/workbench/contrib/browserView/electron-browser/tools/listBrowserPagesTool.ts, browserToolHelpers.ts `getBrowserPagesContext`), which covers the reporter's workflow without auto-granting access to unconsented pop-ups.

## Vision fit

- **Fit:** aligned
- **Reason:** Requiring explicit consent before an agent can observe a spawned window (e.g. an OAuth login popup) fits the project's security guardrails for the AI-assisted development surface.
- **Evidence:** Durable theme: Security — workspace trust, process sandboxing, and safe handling of sensitive surfaces; auto-sharing OAuth/login popups with an agent without consent would cut against that.
