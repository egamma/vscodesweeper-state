# Issue #332226 — Integrated browser pop ups are not shared with the agent automatically

[https://github.com/microsoft/vscode/issues/332226](https://github.com/microsoft/vscode/issues/332226)

## Summary

Traced this in the source: popup/child views (window.open, OAuth popups, new windows) deliberately do NOT inherit the parent page's agent-sharing state — this is an explicit, commented design choice in the main-process view creation code, not an oversight.

## Change summary

Pop-up windows spawned from the integrated browser (OAuth logins, modals, window.open) are not automatically shared with the agent, so the agent can't see or act on their content.

## Best solution

If this is to change, it needs a deliberate product/security decision on how a child popup should re-request (or inherit) agent consent — e.g. an abbreviated re-prompt for popups spawned from an already-shared page in `BrowserViewMainService._createChildView`/`setAudiences` (src/vs/platform/browserView/electron-main/browserViewMainService.ts, src/vs/platform/browserView/electron-main/browserView.ts). Until a maintainer opts into that, current behavior (private-by-default, per-page consent) stands as designed.

- **Proposed comment:**

  > Thanks for the report. This is actually intentional: when the integrated browser spawns a child window (a pop-up from `window.open`, an OAuth login window, etc.), it deliberately does not inherit the parent page's agent-sharing state — see the comment in `_createChildView` in `browserViewMainService.ts` ("Child views share their host, owner, and storage, but do not implicitly inherit agent access"). Sharing is a per-page, user-consented action (`setSharedWithAgent`), which matters especially for OAuth/login pop-ups. Extending this to auto-share (or streamline re-consent for) child pop-ups would be a deliberate product/security decision, so I'm closing this as as-designed for now — feel free to open a feature request if you'd like to propose a specific consent flow for this case.

## Evidence

- **explicit design comment:** src/vs/platform/browserView/electron-main/browserViewMainService.ts:442 — '// Child views share their host, owner, and storage, but do not implicitly inherit agent access.' directly above the `_createChildView` callback used for popups/window.open.
- **popup creation path:** src/vs/platform/browserView/electron-main/browserView.ts:181-222 — `setWindowOpenHandler` creates a child BrowserView via `_createChildView(details.url, options, {...})` without passing `initialAudiences`, so the popup starts with an empty `audiences` array.
- **sharing is per-page opt-in:** src/vs/workbench/contrib/browserView/common/browserView.ts `setSharedWithAgent()` shows sharing requires explicit user consent via a confirm dialog ('Share this browser page with the agent?') per page/view id, matching the documented 'pages are private until shared' privacy gate from the integrated-browser architecture.
