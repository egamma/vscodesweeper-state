- **Behavior:**

  > Users should be able to initiate code review directly from the agreed changed-files surfaces in chat and agent sessions without navigating to SCM. The action must review the originating session's changes rather than an unrelated active session or repository. Acceptance should cover the selected local and remote providers, keyboard invocation, and appropriate availability when review is unsupported or there are no changes.
- **Trace:**

  > RunSessionCodeReviewAction in src/vs/sessions/contrib/codeReview/browser/codeReview.contributions.ts already exposes sessions.codeReview.run in the Agents Window Changes editor header and submits /code-review to the resolved session. Its visibility excludes virtual workspaces, and its execution differs for sessions supporting multiple chats. The workbench chat input in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts uses separate editing-session toolbar menus; chatChangesSummaryPart.ts renders per-response changed-file summaries with a view-all action. extensions/copilot/package.json exposes existing SCM review commands, which do not by themselves supply the requested chat placement. https://github.com/microsoft/vscode/issues/277913 was deliberately consolidated into this issue. Preserve existing SCM review semantics and session targeting; uncertainty starts at which remaining surfaces and remote providers the product intends to support.
- **Open decisions:**
  - Should code review be exposed on the aggregate chat changed-files surface, per-response changed-file summaries, or both, and should per-response invocation review only that turn?
  - Which remote or cloud session providers should expose this action, and is a session-list entrypoint still part of the intended scope?
