# Issue #317783 — too fast scrolling when drag&drop into editor (holding shift)

[https://github.com/microsoft/vscode/issues/317783](https://github.com/microsoft/vscode/issues/317783)

## Summary

Still reproduces on main: the auto-scroll speed formula in TopBottomDragScrollingOperation._getScrollSpeed uses outsideDistance proportionally but applies high minimum floors (30/60/200 lines/sec) and multiplies by viewportInLines, which makes scrolling disproportionately aggressive when the editor viewport is small (split views, terminal open). No fix has landed since the issue was filed.

## Change summary

Drag-and-drop into a small editor viewport with Shift held triggers uncontrollably fast auto-scrolling because the scroll speed formula doesn't scale down for small viewports.

## Best solution

Adjust the scroll speed formula in `TopBottomDragScrollingOperation._getScrollSpeed()` (src/vs/editor/browser/controller/dragScrolling.ts) to cap or dampen the speed for small viewports — the minimum floors (30, 60, 200) and the `viewportInLines` multiplier combine to make scrolling far too aggressive when only a few lines are visible. The team member (alexdima) is already investigating in the comments.

The formula computes `viewportInLines * (multiplier + outsideDistanceInLines)` with high minimum floors (30, 60, 200 lines/sec).
