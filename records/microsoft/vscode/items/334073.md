# Issue #334073 — Autopilot doesn't work well with folding steps before final response

[https://github.com/microsoft/vscode/issues/334073](https://github.com/microsoft/vscode/issues/334073)

## Summary

The Autopilot completion sequence still misclassifies a short `task_complete` summary as the final response and folds the earlier substantive answer. An independent trace confirms the behavior, a maintainer identifies double completion as a bug, and current source retains the responsible positional heuristic.

## Change summary

Prevent Autopilot's trailing task-completion bookkeeping from displacing or folding a substantive final answer.

## Best solution

Preserve the substantive answer as the primary visible response while presenting any task-completion summary as secondary completion information. Keep the general behavior for genuine `markdown -> tool -> final markdown` sequences unchanged.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotToolDisplay.ts`, `src/vs/platform/agentHost/node/copilot/mapSessionEvents.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/platform/agentHost/test/node/mapSessionEvents.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`
- **Validation:** Add a regression test for `substantive Markdown -> bookkeeping tool -> task_complete summary -> turn complete` that asserts the substantive answer remains outside the completed-work disclosure, while the existing genuine `markdown -> tool -> final markdown` behavior remains unchanged.
- **Behavior:**

  > When Autopilot emits a substantive answer before invoking `task_complete`, that answer remains the primary visible final response. A shorter completion summary must not cause the answer to be folded into completed-work details. Completion information may remain visible according to the chosen UX, and genuine final Markdown emitted after ordinary tools must continue to be treated as the final answer. Acceptance requires regression coverage for both sequences.
- **Trace:**

  > The independent trace at https://github.com/microsoft/vscode/issues/334073#issuecomment-5722218089 confirms that content is not lost in the SDK or AHP stream; the categorization changes in the renderer. `mapSessionEvents.ts` appends `task_complete` as an ordinary Markdown response part using `getTaskCompleteMarkdown` from `copilotToolDisplay.ts`. `getFinalResponseStartIndex` in `chatListRenderer.ts` then chooses the last non-empty contiguous Markdown run, and `updateCompletedResponseDisclosure` folds everything before that position. Existing tests establish each mechanism separately but omit their interaction. The boundary is the completion-summary/final-response classification: do not change ordinary multi-step response folding or treat every post-tool Markdown block as bookkeeping.
- **Open decisions:**
  - When a substantive answer precedes `task_complete`, should the completion summary remain visible as a trailing adjunct, be combined with the answer, or be suppressed as redundant?
  - Should bookkeeping-aware final-response selection apply specifically to Autopilot's `task_complete` sequence, or to a broader explicitly identified class of bookkeeping tools?

## Evidence

- **independent reproduction:** https://github.com/microsoft/vscode/issues/334073#issuecomment-5722218089 traces an independent Insiders occurrence end-to-end: the 2,956-character answer reached AHP intact, `task_complete` then produced shorter root Markdown, and the renderer folded the substantive answer after selecting the trailing Markdown run.
- **maintainer confirmation:** https://github.com/microsoft/vscode/issues/334073#issuecomment-5722290167 explicitly identifies double task completion as a bug and explains that the current UI uses contiguous Markdown sequences because bookkeeping tools are not distinguished.
