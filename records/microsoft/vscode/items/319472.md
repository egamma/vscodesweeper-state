# Issue #319472 — Get  --ozone-platform found error when launching agent host on linux

[https://github.com/microsoft/vscode/issues/319472](https://github.com/microsoft/vscode/issues/319472)

## Summary

Still reproduces on main: `--ozone-platform` is defined as a top-level CLI option but is not marked `global` nor included in the `agent` subcommand's options, so when the `agent` subcommand is parsed, `--ozone-platform` hits the unknown-option error path. Linux installations can inject this flag (e.g. Snap wrapper, desktop env), causing agent host launch to fail.

## Change summary

Running `code-insiders agent host` on Linux fails with an unexpected `--ozone-platform` argument error because the flag is not propagated into the `agent` subcommand's option scope.

## Best solution

Either mark `ozone-platform` as `global: true` in `src/vs/platform/environment/node/argv.ts` so it passes through all subcommands, or add it to the `agent` subcommand's options — or have the subcommand parser silently ignore Electron/Chromium flags that are irrelevant to non-GUI subcommands. The fix is small and localized to the `OPTIONS` definition in `argv.ts`.
