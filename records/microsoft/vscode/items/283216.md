# Issue #283216 — Chat: Copy/Insert Buttons should always be visible

[https://github.com/microsoft/vscode/issues/283216](https://github.com/microsoft/vscode/issues/283216)

## Summary

The gap remains on current main: code-block actions are anchored to the block's top and normally appear only on hover or focus, so they leave the viewport while scrolling through a long block. A newer accessibility report supports the same direction but cannot be the duplicate canonical for this re-reviewed, older issue.

## Change summary

Keep Copy, Insert at Cursor, and Insert into Terminal actions available while the user scrolls through a long chat code block.

## Best solution

Provide a consistently discoverable code-block action surface that remains reachable while its code block is in view, including for keyboard and alternative-input users, without obscuring code or displaying actions for the wrong block.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/codeBlockPart.css`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts`
- **Validation:** Use a chat component fixture or manual Chat view scenario containing a code block taller than the viewport: scroll its top out of view and verify Copy, Insert at Cursor, and Insert into Terminal remain discoverable and keyboard reachable while that block is visible, disappear or transfer correctly when it leaves view, and do not obscure code at narrow widths.
- **Behavior:**

  > While any portion of a long chat code block remains visible, its applicable Copy, Insert at Cursor, and Insert into Terminal actions remain discoverable and operable without scrolling back to the block's top. Keyboard focus and alternative-input access must expose the same actions. The action surface must not obscure code, claim the wrong code block, or remain after its block leaves the viewport.
- **Trace:**

  > CodeBlockPart creates `.interactive-result-code-block-toolbar` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts and lazily instantiates its MenuWorkbenchToolBar on hover, editor focus, or screen-reader mode. src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/codeBlockPart.css anchors that toolbar absolutely at the code block's top and hides it outside hover/focus, which explains why it leaves the viewport during a long-block scroll. Screen-reader mode already has a dedicated always-created/labelled path; preserve that behavior and the lazy-toolbar performance boundary for large responses. The related accessibility request is https://github.com/microsoft/vscode/issues/311729, but it is newer and therefore not a canonical duplicate for this re-reviewed issue.
- **Open decisions:**
  - Should persistent in-view actions be the default for every user, or an accessibility/user setting while the current hover presentation remains the default?
  - When multiple code blocks are simultaneously visible, should each show its own actions or should one action surface follow the active code block?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/codeBlockPart.css positions `.interactive-result-code-block-toolbar` absolutely at `top: -15px`, hides it with `opacity: 0` and `pointer-events: none`, and reveals it only for hover, focus, or `force-visibility`; it is not sticky within the visible portion of a long block.
- **interaction path:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts creates the toolbar for hover, editor focus, or screen-reader mode and removes `force-visibility` after mouseleave, confirming that ordinary pointer users do not receive a persistent in-view toolbar.
- **related accessibility report:** https://github.com/microsoft/vscode/issues/311729 is open and requests persistently visible chat action buttons for voice and eye-tracker users. It reports the same discoverability direction but was created after this issue, so the stronger re-review duplicate rule prevents using it as this issue's canonical.
- **existing actions:** src/vs/workbench/contrib/chat/browser/actions/chatCodeblockActions.ts registers Insert At Cursor and Insert into Terminal, but command availability does not keep the code-block toolbar visible during scrolling.
