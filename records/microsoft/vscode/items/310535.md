# Issue #310535 — VSCode Agentic app - askquestions

[https://github.com/microsoft/vscode/issues/310535](https://github.com/microsoft/vscode/issues/310535)

## Summary

The request remains necessary: current main recognizes when a Copilot Cloud task is waiting for input, but it does not expose the structured askQuestions interaction available to local and Agent Host sessions. No older open issue was found with the same observable symptom.

## Change summary

Allow server-run Copilot Cloud sessions in the Agents Window to ask structured questions, wait independently, and resume when their answers are submitted.

## Best solution

Cloud tasks should publish structured input requests that reuse VS Code's existing question-carousel UI, with answers routed back to the correct task so several cloud sessions can wait and resume independently.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionContentBuilder.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/taskTurnStreamer.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/test/copilotCloudSessionsProvider.spec.ts`
- **Validation:** Add a Copilot Cloud provider test with two concurrent tasks that each enter `waiting_for_user` with distinct structured questions; submitting each carousel must send its answer only to the corresponding task and transition that task out of NeedsInput.
- **Behavior:**

  > A Copilot Cloud agent can ask one or more structured clarifying questions and pause until the user responds. The Agents Window shows the same question controls used by local sessions, identifies every waiting cloud session, and resumes only the session whose answer was submitted. Multiple cloud sessions may wait concurrently without replacing or misrouting one another's questions.
- **Trace:**

  > Local chat registers `AskQuestionsTool` in src/vs/workbench/contrib/chat/common/tools/builtinTools/tools.ts, while Copilot CLI bridges SDK input requests through extensions/copilot/src/extension/chatSessions/copilotcli/vscode-node/askUserQuestionHandler.ts. The server-run cloud path instead maps `waiting_for_user` to NeedsInput in copilotCloudSessionsProvider.ts and renders Task API events through copilotCloudSessionContentBuilder.ts and taskTurnStreamer.ts; those paths expose no structured question payload or answer callback. Freeform `sendFollowUpToTask` steering should remain available and must not be conflated with answering an identified question request. The uncertainty starts at the cloud Task API contract needed to carry question identity, options, and answer submission.
- **Open decisions:**
  - Which Task API event payload and response operation will define the durable structured-question contract between server-run Copilot Cloud tasks and VS Code clients?

## Evidence

- **local capability:** src/vs/workbench/contrib/chat/common/tools/builtinTools/tools.ts registers AskQuestionsTool for local chat, and extensions/copilot/src/extension/chatSessions/copilotcli/vscode-node/askUserQuestionHandler.ts invokes it and routes carousel answers for Copilot CLI sessions.
- **cloud gap:** extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts maps Task API `waiting_for_user` to `ChatSessionStatus.NeedsInput`, but its input path only sends a freeform follow-up through `sendFollowUpToTask`; it has no structured question-answer operation.
- **rendering boundary:** extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionContentBuilder.ts and taskTurnStreamer.ts render Task API events and generic tool requests, but contain no question-carousel or askQuestions handling for server-run cloud tasks.
- **canonical search:** https://github.com/microsoft/vscode/issues/313437 is newer and concerns tool-name compatibility for custom agents delegated to Copilot CLI, not structured questions from server-run Copilot Cloud sessions, so it is not a canonical duplicate.
