# Issue #233232 — Terminal suggest: Contextually aware suggestions after git status

[https://github.com/microsoft/vscode/issues/233232](https://github.com/microsoft/vscode/issues/233232)

## Summary

Keep open: existing file completions and Git-specific generators provide partial coverage, but do not carry recently displayed paths into subsequent commands such as rm. No verified older canonical owns this request; the remaining scope needs a product decision.

## Change summary

Suggest recently displayed git-status file paths when completing arguments for subsequent cleanup commands, potentially generalized to verified terminal file links.

## Best solution

Extend terminal file-argument suggestions to reuse relevant recently displayed paths without replacing ordinary filesystem completion. First settle whether this is Git-specific context or a general recent-file-link capability, including how long that context remains relevant.

## Plan brief

- **Likely files:** `extensions/terminal-suggest/src/terminalSuggestMain.ts`, `extensions/terminal-suggest/src/completions/git.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalSuggestAddon.ts`
- **Validation:** In a disposable repository, create modified tracked and untracked files in nested directories, including filenames with spaces; run git status, then request argument suggestions for rm and git checkout without executing them. Verify the agreed contextual candidates, correct shell escaping, unchanged ordinary completions, and the agreed behavior after changing directories or opening another terminal.
- **Behavior:**

  > After displaying git status, users should be able to select relevant displayed file paths as arguments to subsequent cleanup commands without copying them manually. Existing filesystem suggestions must remain available, and accepting a path must not execute the command automatically. Acceptance should cover nested paths, filenames with spaces and multiple arguments. The intended scope and lifetime of output-derived context must be agreed before implementation.
- **Trace:**

  > The built-in terminal-suggest extension derives completions from command specs in extensions/terminal-suggest/src/terminalSuggestMain.ts. Git generators in extensions/terminal-suggest/src/completions/git.ts already query repository state for selected Git commands, whereas the rm spec requests generic filesystem paths. TerminalCompletionService.resolveResources in src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts resolves resources from the current argument and working directory, without recent-output-link context on the inspected path. SuggestAddon in src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalSuggestAddon.ts requests provider completions for the current prompt. The remaining uncertainty is the source and lifetime of contextual candidates, not ordinary file completion; preserve existing command acceptance and filesystem behavior. https://github.com/microsoft/vscode/issues/239244 concerns command history and https://github.com/microsoft/vscode/issues/224505 concerns provider extensibility; neither is a verified duplicate.
- **Open decisions:**
  - Should contextual file suggestions be limited to paths displayed by git status, or include recently verified local file links from other terminal output?
  - How long should displayed paths remain eligible, and should changing the working directory or terminal session discard that context?
  - Should contextual paths be promoted within ordinary file suggestions or presented as a distinct suggestion group?
