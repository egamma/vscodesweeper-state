# Issue #339472 — Agent Host permission picker exposes Configure Keybinding, but command implementation is a no-op

[https://github.com/microsoft/vscode/issues/339472](https://github.com/microsoft/vscode/issues/339472)

## Summary

Confirmed from source: every Agent Host picker Action2 (`OpenAgentHostAutoApprovePickerAction` and its siblings in agentHostChatInputPicker.contribution.ts) has a deliberately empty `run()`, so a keybinding assigned via the exposed 'Configure Keybinding' option invokes the command but does nothing — only the direct DOM click handler on the custom action view item opens the picker. The sibling `OpenPermissionPickerAction` in chatExecuteActions.ts already shows the correct fix pattern (resolve `IChatWidgetService.lastFocusedWidget` and call a widget method), so this is a real, fixable gap rather than an as-designed limitation.

## Change summary

Agent Host permission/mode pickers expose 'Configure Keybinding' in their context menu, but the underlying command is a no-op, so an assigned keybinding does nothing (only mouse click works).

## Best solution

Give each Agent Host picker command (OpenAgentHostAutoApprovePickerAction, OpenAgentHostModePickerAction, OpenAgentHostPermissionModePickerAction, OpenAgentHostCodexApprovalsPickerAction, OpenAgentHostFolderPickerAction) a real `run()` that resolves the focused chat widget and opens the picker, mirroring how `OpenPermissionPickerAction.run()` already calls `widget.input.openPermissionPicker()`.
