# Issue #335117 — Opening a session that needs input from a fullscreen Browser preview does not show chat

[https://github.com/microsoft/vscode/issues/335117](https://github.com/microsoft/vscode/issues/335117)

## Summary

Plausible, well-described gap in the single-pane layout's session-switch/detail-panel logic when the editor area is maximized on a Browser tab; the repo's own state-machine doc explicitly scopes its transition matrix to 'not maximized', and the single-pane strategy files have no maximize-aware handling, so a session switch while maximized likely doesn't restore/focus chat as expected.

## Change summary

Switching to a different session (via the title bar 'needs input' indicator) while the current session's Browser tab is maximized/fullscreen leaves the new session's chat hidden instead of revealing it.

## Best solution

In the single-pane layout strategy (contrib/layout/browser/singlePane/), make session-switch handling maximize-aware: un-maximize (or otherwise force-reveal chat) when the incoming session needs input, mirroring how the desktop controller already treats maximize as an explicit state ([D5] rules in desktopSessionLayoutController.ts). SINGLE_PANE_SCENARIOS.md's transition matrix should be extended to cover maximized transitions once the behavior is decided.
