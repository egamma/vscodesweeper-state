- **Behavior:**

  > Users reviewing a diff should be able to opt out of cycling from the final change back to the first. With the option enabled, repeated Next Change invocations at the final change must not restart the review; normal navigation between changes must continue to work. Preserve current wrapping when the option is not enabled. Planning should settle the corresponding first-change behavior and whether reaching a boundary provides feedback or disables the toolbar control.
- **Trace:**

  > DiffEditorCommandsService.navigateInDiffEditor in src/vs/workbench/browser/parts/editor/diffEditorCommandsService.ts delegates to DiffEditorWidget.goToDiff in src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts. The widget chooses the first or last mapping as an unconditional fallback, and its EOF branch also selects the first mapping. DiffEditorOptions, diffEditorDefaultOptions, and editorConfigurationSchema contain no navigation-loop control; editor.find.loop is a separate search option and diffEditor.wordWrap only changes text layout. Toolbar availability currently depends on EditorContextKeys.hasChanges. The existing DiffEditorWidget2 browser suite provides a widget/model harness for acceptance checks. Preserve default navigation, search-loop semantics, text wrapping, and cross-file navigation; the latter is distinct work described in https://github.com/microsoft/vscode/issues/296607. The same request appears in the newer https://github.com/microsoft/vscode/issues/207118, while the older https://github.com/microsoft/vscode/issues/28743 was declined historically rather than implemented.
