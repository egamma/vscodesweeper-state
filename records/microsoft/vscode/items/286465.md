# Issue #286465 — New task is created when one already exists from folder

[https://github.com/microsoft/vscode/issues/286465](https://github.com/microsoft/vscode/issues/286465)

## Summary

Confirmed team-filed bug: tasks launched via folder navigation vs. recent-task-run produce different identity keys (`getMapKey()`), so the system creates a duplicate instead of offering to terminate and re-run. No fix has landed on main.

## Change summary

Running an npm task by navigating to its folder creates a new task instance instead of recognizing the already-running task and offering to terminate/re-run it.

## Best solution

Normalize task identity so that `getMapKey()` (or the comparison used in `_restart` / `isTaskRunning` at `abstractTaskService.ts:2164`) produces the same key regardless of whether the task was launched from folder navigation or from the recent-tasks list. The fix likely lives in `src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts` and/or the `getMapKey()` overrides in `src/vs/workbench/contrib/tasks/common/tasks.ts`.
