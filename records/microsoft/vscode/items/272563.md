# Issue #272563 — Build Failure: 1ES PT artifact collection error - missing .build/logs and .build/crashes directories

[https://github.com/microsoft/vscode/issues/272563](https://github.com/microsoft/vscode/issues/272563)

## Summary

Team-authored build-infrastructure issue that remains valid — the Darwin pipeline declares `.build/logs` artifact collection (condition: succeededOrFailed) but the test steps never ensure that directory exists, so 1ES artifact collection can fail when no test writes logs there. Keeping open for the team to address.

## Change summary

The macOS CI pipeline fails at 1ES artifact collection because `.build/logs` and `.build/crashes` directories may not exist when artifact publishing runs.

## Best solution

Add `mkdir -p .build/logs .build/crashes` early in `build/azure-pipelines/darwin/steps/product-build-darwin-test.yml` (similar to what `product-smoke-flaky-darwin.yml` already does at line 53) so the directories always exist when 1ES attempts artifact collection. Alternatively, add `condition: and(succeededOrFailed(), eq(variables['Agent.OS'], ...))` guards or make the artifact output conditional on directory existence.
