# Issue #332901 — Pinning mechanism for symbol detail hover panel

[https://github.com/microsoft/vscode/issues/332901](https://github.com/microsoft/vscode/issues/332901)

## Summary

Reasonable ask, but VS Code already ships a closely related mechanism (`editor.hover.sticky`, default true, plus `editor.hover.hidingDelay`) that keeps the hover open while the mouse is over it or text is being selected inside it — the request may be more about a specific drag-selection edge case than a wholly missing capability, so it's worth a closer look rather than an outright close.

## Change summary

Add a way to pin/lock the symbol hover panel open so its contents can be selected and copied without the hover disappearing mid-drag.

## Best solution

Investigate whether the existing sticky-hover and in-widget text-selection logic in src/vs/editor/contrib/hover/browser/contentHoverController.ts (see `_shouldKeepCurrentHover`, `isTextSelectedWithinContentHoverWidget`, and the mouse-down drag-hide path in `_onEditorMouseMove`) has a gap when a drag-select starts just inside the widget boundary; if a real gap is confirmed, either fix the sticky/selection heuristics or consider a dedicated pin affordance as a targeted enhancement to the hover area.

- **existing selection-preservation logic:** src/vs/editor/contrib/hover/browser/contentHoverController.ts:185-221 (`_shouldKeepCurrentHover`) already special-cases keeping the hover open when the mouse is on the sticky widget or text is being selected within it (`isTextSelectedWithinContentHoverWidget`).
