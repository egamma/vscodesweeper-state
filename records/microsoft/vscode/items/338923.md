## Summary

Thanks for the detailed report. A second user confirms it on 1.141.0 (macOS), so it is still live. The error points at a global AMD `define` in the notebook webview that the bundled Mermaid/fastdom code picks up. I could not run it, so I'm leaving it open and unverified. ## Change summary

Mermaid blocks in Jupyter notebook Markdown cells stop rendering with `Ge.default.extend is not a function`, apparently because a global AMD `define` exists in the webview.

## Best solution

Make the notebook Mermaid bundle robust to a global AMD `define`/`define.amd` in the webview. Options are bundling or shimming fastdom so it takes its CommonJS path, or hiding `define` while the Mermaid chunk initialises. First identify what injects `define` (the Jupyter or Python extension's renderers, or the notebook preload) and report to the owner if it is external.
