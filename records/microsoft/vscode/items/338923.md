# Issue #338923 — VS Code Stopped Rendering Mermaid Blocks in Jupyter Notebook (VS Code `1.140.0`)

[https://github.com/microsoft/vscode/issues/338923](https://github.com/microsoft/vscode/issues/338923)

## Summary

Traced in source: VS Code intentionally injects a global `requirejs`/AMD `define` into the notebook webview for `.ipynb` files (backLayerWebView.ts, 'Python notebooks assume that requirejs is a global'). The newly-bundled Mermaid notebook renderer ships a UMD-wrapped dependency (fastdom, pulled in transitively via mermaid/cytoscape) whose feature-detection of `define`/`define.amd` picks the wrong export branch in that context, matching the reporter's exact console error — a real, bounded but architecturally sensitive conflict between two legitimate features.

## Change summary

Mermaid diagrams in Jupyter notebook Markdown cells fail to render (TypeError: Ge.default.extend is not a function) because a bundled UMD dependency misdetects the notebook's injected AMD loader.

## Best solution

Shadow/neutralize the global `define` inside the mermaid notebook-renderer bundle (e.g. an esbuild banner like `var define;` scoped to that output chunk) or otherwise ensure the mermaid bundle doesn't observe the AMD loader VS Code injects for ipynb compatibility, without breaking the requirejs-dependent renderers (e.g. ipywidgets) that rely on the global today.
