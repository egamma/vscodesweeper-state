# Issue #163280 — View Zone Alignment Bug When Word Wrap Is On

[https://github.com/microsoft/vscode/issues/163280](https://github.com/microsoft/vscode/issues/163280)

## Summary

Keep open: merge-editor alignment still counts model lines rather than wrapped display height, so corresponding changes can drift apart with word wrap enabled. This team-authored issue is already the canonical report for the later confirmed duplicate.

## Change summary

Keep corresponding merge-editor changes and alignment spacers vertically aligned when word wrapping adds different display heights to the panes.

## Best solution

Make merge-editor alignment account for rendered line heights and remain correct when wrapping or pane widths change, while preserving existing unwrapped alignment and scrolling behavior.

## Evidence

The author explicitly identifies line wrapping as the cause in https://github.com/microsoft/vscode/issues/163280#issuecomment-1287112554.
- **Current source defect:** In src/vs/workbench/contrib/mergeEditor/browser/view/viewZones.ts, ViewZoneComputer.computeViewZones compares model line numbers plus accumulated spacer line counts, then Spacer.create uses heightInLines. No wrapped display-height measurement enters this calculation. Differing wrap counts therefore add vertical height that the alignment spacers do not compensate for.
- **Scrolling compounds the misalignment:** In src/vs/workbench/contrib/mergeEditor/browser/view/scrollSynchronizer.ts, ScrollSynchronizer._shouldLock always locks the two input panes together, and alignScrolling copies their pixel scrollTop directly. Equal scroll offsets cannot restore correspondence when wrapped content has unequal heights.
- **Later confirmation belongs here:** https://github.com/microsoft/vscode/issues/274407 reports the same observable problem on VS Code 1.105.1: long lines added to one input cause corresponding changes to become offset after enabling word wrap. Its closure was a duplicate consolidation, not a fix; the maintainer explicitly points back to this issue in https://github.com/microsoft/vscode/issues/274407#issuecomment-3659903786.
