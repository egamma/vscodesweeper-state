# Issue #337976 — Build/Package fails at prepareBuiltInCopilotRipgrepShim due to .moduleignore stripping @github/copilot/sdk

[https://github.com/microsoft/vscode/issues/337976](https://github.com/microsoft/vscode/issues/337976)

## Summary

Confirmed on main by tracing the source: build/.moduleignore unconditionally strips @github/copilot/** (line 226) while prepareBuiltInCopilotRipgrepShim in build/lib/copilot.ts hard-requires extensions/copilot/node_modules/@github/copilot/sdk to exist, so the documented local-source packaging path (packageCopilotExtensionStream) throws exactly as reported.

## Change summary

Building VS Code from source and running a packaging gulp task (e.g. `npm run gulp vscode-linux-x64`) fails in prepareBuiltInCopilotRipgrepShim because .moduleignore strips the @github/copilot/sdk directory the shim step expects.

## Best solution

A maintainer who owns the Copilot packaging pipeline should decide whether the fix is loosening build/.moduleignore (keep @github/copilot/package.json and sdk/**, as the reporter's workaround does) or instead pointing prepareBuiltInCopilotRipgrepShim at @github/copilot-sdk (which the surrounding code and its own comment say is the actual runtime VS Code uses) — then apply that and extend build/lib/test/copilot.test.ts to cover the local packageCopilotExtensionStream path.
