# Issue #337976 — Build/Package fails at prepareBuiltInCopilotRipgrepShim due to .moduleignore stripping @github/copilot/sdk

[https://github.com/microsoft/vscode/issues/337976](https://github.com/microsoft/vscode/issues/337976)

## Summary

Confirmed in source: build/.moduleignore's blanket `@github/copilot/**` exclusion strips the extension's local `sdk/` subdirectory and `package.json`, which `prepareBuiltInCopilotRipgrepShim` in build/lib/copilot.ts then requires to exist — breaking local from-source packaging builds. This is a real, reproducible build bug, not a runtime/user-facing defect.

## Change summary

Local (non-CI) packaging of the built-in Copilot extension fails because .moduleignore strips @github/copilot/sdk before prepareBuiltInCopilotRipgrepShim expects it to be present.

## Best solution

Add negation rules to build/.moduleignore (e.g. `!@github/copilot/package.json` and `!@github/copilot/sdk/**`) so packageCopilotExtensionStream preserves the SDK directory the shim step needs, mirroring the existing negation pattern already used elsewhere in that file for re-added platform packages.
