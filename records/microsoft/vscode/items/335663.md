# Issue #335663 — Markdown: escaped `\$` opens an inline math span and hides highlighting until the next `$`

[https://github.com/microsoft/vscode/issues/335663](https://github.com/microsoft/vscode/issues/335663)

## Summary

Confirmed defect in current main's TextMate grammar, and an open PR already fixes it — keep open pending that PR landing rather than closing as completed.

## Change summary

In plain Markdown editing (not preview), an escaped `\$` is misparsed as opening an inline math span, suppressing highlighting (e.g. of code spans) until the next `$`.

## Best solution

Land https://github.com/microsoft/vscode/pull/335664, which fixes the lookbehind in both `math_inline_single` and `math_inline_double` rules to also reject a preceding backslash, plus updates the colorize test fixtures.

## Evidence

- **grammar bug confirmed:** extensions/markdown-math/syntaxes/md-math-inline.tmLanguage.json on main still has `(?<=\s|\W|^)(?<!\$)(\$)(.+?)(\$)(?!\$)(?=\s|\W|$)` for math_inline_single (and the analogous double-dollar rule); `(?<!\$)` only rejects a preceding literal `$`, not a preceding backslash, so `\$` is treated as an unescaped opener exactly as reported.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/335664 ('Do not open inline math on an escaped dollar sign in markdown') changes both lookbehinds to `(?<![\\$])`, which correctly excludes both `$` and `\` as the preceding character, and adds colorize fixtures/results covering the escaped-dollar case; PR is open/unmerged as of this review (git log confirms the grammar file's last commit is unrelated, #336834).
- **related but distinct:** Issue references https://github.com/microsoft/vscode/issues/334935 as a related-but-different WYSIWYG-renderer issue; a commenter also links https://github.com/microsoft/vscode/issues/223545 and https://github.com/microsoft/vscode/pull/304800 on the broader math-katex package, which is a separate concern from this tokenizer regex bug.
