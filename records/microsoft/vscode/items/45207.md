# Issue #45207 — [json] External schemas referenced from schema not updated

[https://github.com/microsoft/vscode/issues/45207](https://github.com/microsoft/vscode/issues/45207)

## Summary

The bug should remain open: a VS Code maintainer confirmed the behavior, and multiple later reports say dependent schemas still remain stale, including after using “JSON: Clear Schema Cache.” The command is a workaround rather than coverage of the requested automatic invalidation.

## Change summary

Changes to a local JSON schema referenced through `$ref` are not automatically reflected in validation and IntelliSense for documents using the parent schema.

## Best solution

Invalidate and reload the complete dependency graph of a JSON schema when any local referenced schema changes, then revalidate affected JSON documents without requiring a restart, parent-schema edit, or manual cache reset.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add an integration test that opens a JSON document using a local parent schema with a relative `$ref`, changes the referenced schema's enum, and verifies diagnostics update without editing the parent schema, clearing the cache, or restarting.
- **Behavior:**

  > When an open JSON document uses a local schema that transitively references another local schema, saving a change to the referenced schema must automatically refresh validation and IntelliSense. Changing an allowed enum value must remove acceptance of the old value and report or complete the new value without touching the parent schema, invoking “JSON: Clear Schema Cache,” or restarting VS Code. Direct parent-schema refresh behavior must remain unchanged.
- **Trace:**

  > The issue's minimal three-file setup confirms that direct changes to schema.json trigger revalidation while changes to color-schema.json do not, indicating that refresh tracks the root schema but not its referenced dependencies. The JSON extension client/server and JSON language service schema cache/watch integration are the likely path, beginning in extensions/json-language-features/client/src/jsonClient.ts and extensions/json-language-features/server/src/jsonServer.ts. Later comments show the manual cache-clear command is not a reliable substitute. The related https://github.com/microsoft/vscode/issues/88354 concerns an HTTP-referenced local schema and is closed, so it must not be used as a duplicate canonical. Preserve remote-schema caching and avoid broad cache clearing when only one local dependency changes; the plan should first identify how referenced URIs are recorded and how affected root schemas/documents can be revalidated.
