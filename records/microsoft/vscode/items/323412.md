# Issue #323412 — Confused a bit about the done button

[https://github.com/microsoft/vscode/issues/323412](https://github.com/microsoft/vscode/issues/323412)

## Summary

Keep open as actionable UX polish: current main gives Mark as Done reversible archive semantics and Delete Chat permanent semantics, but the reported confusion shows that distinction is not sufficiently clear in the UI. This is team-authored test-plan feedback, so a judgment close is also barred.

## Change summary

Make the reversible Mark as Done action clearly distinguishable from permanent chat deletion.

## Best solution

Preserve the reversible archive/restore lifecycle and permanent deletion as distinct operations, while making their labels, placement, and consequences understandable without relying on documentation. The Agents Window owner should decide whether wording, confirmation text, or action placement best communicates that distinction.

- **Validation:** Exercise Mark as Done, Restore, and Delete Chat in an Agent Host session and verify that users can identify which action is reversible before invoking it; retain automated assertions that the archive/restore and permanent-delete commands remain distinct.
- **Behavior:**

  > Users should understand before acting that Mark as Done removes a session or chat from the active view but allows it to be restored, whereas Delete Chat permanently removes it. The two actions must remain distinguishable wherever they appear. Acceptance should cover marking an item done, restoring it, and permanently deleting a chat without presenting the operations as equivalent.
- **Trace:**

  > The issue came from the multi-chat lifecycle test plan at https://github.com/microsoft/vscode/issues/323330. getChatSessionArchiveActionPresentation in src/vs/platform/chat/common/sessionArchiveActions.ts models Mark as Done together with Restore, while src/vs/sessions/browser/parts/chatCompositeBar.ts constructs a separate Delete Chat action that calls ISessionsManagementService.deleteChat. Session-level action registration is in src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts. The boundary is the existing reversible archive/restore versus irreversible deletion behavior; do not collapse those semantics. The uncertainty begins at the presentation layer: the record does not settle whether wording, placement, affordance, or confirmation should carry the distinction.
- **Open decisions:**
  - Should the reversible lifecycle action continue to be presented as Mark as Done, or use archive-oriented wording that communicates restorability more directly?
  - Where should the UI communicate that Delete Chat is permanent and Mark as Done is reversible: in labels, action placement, confirmation text, or a combination?
