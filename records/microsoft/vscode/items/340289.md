# Issue #340289 — Disabled workspace MCP servers can block every Agents Window chat turn

[https://github.com/microsoft/vscode/issues/340289](https://github.com/microsoft/vscode/issues/340289)

## Summary

Thorough, well-diagnosed report confirmed on current main: disabling a workspace MCP server can make every subsequent Agents Window chat turn for that workspace fail before it reaches the model. Keeping open for a fix; the report already pinpoints both defects with file/line precision.

## Change summary

A disabled workspace MCP server absent from the SDK's passive inventory (or transiently reported `not_configured`) is wrongly treated as needing a `session.mcp.disable` call, which rejects with 'No MCP host initialized' and aborts the whole chat turn.

## Best solution

In `_doReconcileMcpServerEnablement` (copilotAgentSession.ts), only call `mcp.disable` when the passive inventory explicitly reports `enabled: true` (treat an absent entry as nothing-to-disable), and stop `_translateSdkMcpStatus`/`_toSdkMcpServer` from letting a transient `not_configured` status get persisted as a global customization disable — only an explicit `disabled` status should be mirrored that way.
