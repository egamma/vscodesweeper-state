# Issue #190974 — env.shell API should not be the empty string on start up

[https://github.com/microsoft/vscode/issues/190974](https://github.com/microsoft/vscode/issues/190974)

## Summary

Still reproduces on current main: `_defaultProfile` in `ExtHostTerminalService` starts as `undefined`, so `getDefaultShell()` returns `''` until the main process sends the profile via `$acceptDefaultProfile`. The author's comment 3 confirms this was harder to fix than anticipated and remains unresolved despite #160694 being closed for the `onDidChangeShell` event finalization.

## Change summary

The `env.shell` extension API returns an empty string at startup because the default terminal profile hasn't been resolved yet when the extension host launches.

## Best solution

Cache the resolved default shell path across sessions (e.g. in storage) so `_defaultProfile` is pre-populated before the extension host starts, then fire `onDidChangeShell` if the real resolution differs. The fix lives in the terminal profile resolution path between `src/vs/workbench/contrib/terminal/` (main-side profile resolution) and `src/vs/workbench/api/common/extHostTerminalService.ts` (ext-host consumption). The author's comment 3 notes that profile resolution depends on workspace context and variable resolution, making a simple pre-launch call infeasible — a cached-optimistic approach is the viable path.
