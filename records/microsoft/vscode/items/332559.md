# Issue #332559 — You're running in a KDE environment but the OS keyring is not available for encryption. Ensure you have kwallet running.

[https://github.com/microsoft/vscode/issues/332559](https://github.com/microsoft/vscode/issues/332559)

## Summary

A commenter traced this to an Electron/Chromium OSCrypt bug: the kwallet backend probes the KWallet4-era D-Bus object path (/modules/kwalletd) which kwalletd6 on Plasma 6 no longer exports at that path, causing OSCrypt to fall back to basic/plaintext storage and VS Code to show this warning regardless of --password-store. This is an upstream Electron defect, already filed there, so VS Code core keep-open pending an Electron fix.

## Change summary

VS Code shows a persistent 'OS keyring is not available' warning on KDE/Plasma 6 even though KWallet (kwalletd6) is running.

## Best solution

Track the upstream Electron fix at https://github.com/electron/electron/issues/53230 (kwallet backend using KWallet4-era D-Bus path on Plasma 6); once Electron corrects the object path probe and VS Code bumps its Electron version, this should resolve. No VS Code-side code change is implicated.
