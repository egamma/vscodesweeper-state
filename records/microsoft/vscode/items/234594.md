# Issue #234594 — Indicate that version property should not be used for reporting telemetry

[https://github.com/microsoft/vscode/issues/234594](https://github.com/microsoft/vscode/issues/234594)

## Summary

Team-authored debt issue requesting better indication that certain telemetry property names (like `version`) are reserved by common properties and will be silently overwritten. Still unfixed on main — the `mixin` call in telemetryService.ts overwrites extension-supplied properties without warning.

## Change summary

Extensions using reserved telemetry property names like `version` get their values silently overwritten by common properties, with no compile-time or runtime indication.

## Best solution

Either document/warn about reserved common-property names (e.g. `version`, `sessionID`, `commitHash`) so extension authors avoid collisions, or change the mixin order/strategy in `telemetryService.ts` to namespace common properties (prefixed with `common.` as some already are). The fix likely touches `src/vs/platform/telemetry/common/telemetryService.ts` and `commonProperties.ts`, and may also need API-level typing changes.
