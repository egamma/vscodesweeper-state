# Issue #92978 — Report task execution result in onDidEndTask

[https://github.com/microsoft/vscode/issues/92978](https://github.com/microsoft/vscode/issues/92978)

## Summary

Keep this API proposal open: current onDidEndTask still exposes no execution result, and the existing process-exit and proposed problem-matcher events do not provide a unified task outcome. The api-proposal label independently prevents a cleanup close; API owners must settle and finalize the contract.

## Change summary

Expose task success or failure to extensions, including outcomes involving failed dependencies and tasks without an underlying process.

## Best solution

Define a task-level outcome contract covering execution failure, dependency failure, termination, and non-process execution, with an explicit decision about problem-matcher errors. Finalize that contract through the task API proposal rather than requiring extensions to infer outcomes from separate events.

## Evidence

- **Stable API gap:** src/vscode-dts/vscode.d.ts:9290 defines TaskEndEvent with only execution. TaskProcessEndEvent exposes exitCode, but tasks.onDidEndTaskProcess explicitly does not fire for tasks without an underlying process; it is not a general task-result API.
- **Current event transport:** src/vs/workbench/api/browser/mainThreadTask.ts:494-503 forwards exitCode only for ProcessEnded; End forwards only TaskExecutionDTO. src/vs/workbench/api/common/extHostTask.ts:524-538 likewise fires onDidEndTask with execution alone.
- **Partial proposed capability:** src/vscode-dts/vscode.proposed.taskProblemMatcherStatus.d.ts exposes onDidEndTaskProblemMatchers with hasErrors. This reports problem-matcher processing separately, remains proposed, and does not add an overall result to TaskEndEvent.
- **Dependency outcome boundary:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:535-599 waits for dependency summaries and returns a nonzero dependency exitCode before executing the parent command. Internal dependency summaries therefore exist, but the inspected public end-event contract does not expose them as a task-level result.
- **Maintainer-supported contract discussion:** The supplied discussion on https://github.com/microsoft/vscode/issues/92978 records maintainer support for passing an outcome, while explicitly questioning whether it should be a process exit code or a broader result incorporating problem matchers. No settled public contract is recorded.
- **External workaround is explicitly partial:** https://github.com/microsoft/vscode-docker/pull/1827 is merged, but its description says it listens to Docker-owned build/run events and cannot detect failures from arbitrary non-Docker dependencies. It explicitly retains https://github.com/microsoft/vscode/issues/92978 as the missing VS Code API capability.
