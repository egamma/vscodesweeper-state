# Issue #279576 — bracket pair colorization incorrectly renders `>` in C# markdown code fence

[https://github.com/microsoft/vscode/issues/279576](https://github.com/microsoft/vscode/issues/279576)

## Summary

Still reproduces on main: the markdown-basics grammar's unbalancedBracketScopes only covers markdown-native scopes (links, list markers) but not the C# operator scopes (e.g. keyword.operator.relational.cs) that appear inside fenced code blocks, so `>` is incorrectly colorized as an unmatched bracket. An open PR (#282153) addresses this but is blocked on merge permissions.

## Change summary

Bracket pair colorization renders `>` as red (unmatched bracket) inside C# markdown code fences, even though it is an operator, not a bracket.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/282153 (or a similar change) that adds C#/TypeScript operator scopes to the `unbalancedBracketScopes` list in `extensions/markdown-basics/package.json`. The PR has been reviewed but needs someone with merge permissions to unblock it.
