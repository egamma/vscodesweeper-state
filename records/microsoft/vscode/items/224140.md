# Issue #224140 — Slashes in `terminal.integrated.cwd` converted to backslashes on Linux remote host and Windows host

[https://github.com/microsoft/vscode/issues/224140](https://github.com/microsoft/vscode/issues/224140)

## Summary

Still reproduces on main: the variable resolver uses the local platform's path separator (win32 backslash) when resolving variables like `${relativeFileDirname}` for a remote Linux terminal, producing invalid paths. No fix has landed.

## Change summary

When VS Code runs on Windows with a remote Linux host, `terminal.integrated.cwd` and task `cwd` paths with resolved variables use backslashes instead of forward slashes, causing 'directory does not exist' errors.

## Best solution

The variable resolver in `src/vs/workbench/services/configurationResolver/common/variableResolver.ts` uses `paths.relative()` / `paths.dirname()` which dispatch to `win32` on Windows hosts. For remote scenarios, the resolver (or the terminal's `getCwd` in `terminalEnvironment.ts`) should normalize separators to match the remote OS. The fix likely belongs in the terminal layer — normalizing backslashes to forward slashes when the backend OS is Linux/macOS.
