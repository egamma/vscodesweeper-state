# Issue #330316 — Agent Host: Create PR fails for restored sessions missing separate GitHub metadata

[https://github.com/microsoft/vscode/issues/330316](https://github.com/microsoft/vscode/issues/330316)

## Summary

Traced the exact defect on main: refreshSessionGitState only calls setSessionGitHubState inside the `!objectEquals(previousGitState, gitState)` branch, so a restored session whose persisted `_meta.git` already matches the freshly probed git state never gets `_meta.github` backfilled, even though githubOwner/githubRepo are present — leaving PR creation to fail with the reported error.

## Change summary

Restored Agent Host sessions with GitHub-backed repos fail 'Create PR' because `_meta.github` was never populated when only `_meta.git` was persisted and the git state comes back unchanged.

## Best solution

In AgentHostGitStateService.refreshSessionGitState (src/vs/platform/agentHost/node/agentHostGitStateService.ts), reconcile `_meta.github.owner/repo` from `gitState.githubOwner/githubRepo` whenever missing, independent of the `objectEquals(previousGitState, gitState)` check, per the reporter's own suggested fix.
