## Evidence

- **Current-source defect:** In src/vs/workbench/api/common/extHostTypeConverters.ts, ChatSessionItem.from returns the session DTO without iconPath. An extension setting item.iconPath to a custom ThemeIcon therefore loses that value at serialization.
- **Observable fallback:** src/vs/workbench/api/browser/mainThreadChatSessions.ts:644 assigns this.iconPath = dto.iconPath. In src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsModel.ts:759, custom providers use session.iconPath ?? Codicon.terminal; line 788 also prefers item.iconPath. The missing DTO field consequently selects the terminal fallback.
- **Remaining API mismatch:** src/vscode-dts/vscode.proposed.chatSessionsProvider.d.ts:310 declares iconPath?: IconPath, while src/vs/workbench/contrib/chat/common/chatSessionsService.ts:255 and MainThreadChatSessionItem accept only ThemeIcon. Passing ThemeIcon through does not cover the report's URI and light/dark variants.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/337651 was verified OPEN with mergedAt null. Its body references this issue with Fixes syntax, explicitly limits the change to ThemeIcon, and reports converter tests failing before and passing after the proposed change. Those are PR-author results, not tests executed during this review.
- **Discussion:** The September 24 comment independently identifies the omitted converter field and proposes the same ThemeIcon-only scope, leaving URI rendering for a separate change. The earlier upgrade suggestion supplies no evidence that this defect was fixed.
