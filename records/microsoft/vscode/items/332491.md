# Issue #332491 — Copilot start a new session and consume tokens automatically

[https://github.com/microsoft/vscode/issues/332491](https://github.com/microsoft/vscode/issues/332491)

## Summary

Traced this to a real bug in the chat widget's Autopilot handoff logic: `renderChatSuggestNextWidget()` in chatWidget.ts unconditionally re-fires the auto-send handoff whenever it's called with `permissionLevel === Autopilot` and a completed response carrying handoffs — and it's called unconditionally at the end of `setViewModel(...)` (which runs on every session switch), not just from the fresh 'completedRequest' event. That matches the report exactly: navigating back to the session list or opening a new session while the widget still carries Autopilot permission state re-executes 'Start implementation' without user input.

## Change summary

After running a Plan-mode session with the 'Autopilot' permission, backing out to the session list or opening a new session has a high chance of automatically re-triggering the 'Start implementation' handoff and running the agent again, silently burning tokens.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts, make the Autopilot auto-handoff idempotent per completed request (e.g. only fire from the live 'completedRequest' event, or track that a given request's handoff was already auto-executed) so `renderChatSuggestNextWidget()` calls from `setViewModel`/mode-change paths don't replay it when a session is reopened.
