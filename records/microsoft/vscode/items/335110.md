# Issue #335110 — Linux Remote-SSH Copilot shim blocks installer prompt and leaves CLI outside terminal PATH

[https://github.com/microsoft/vscode/issues/335110](https://github.com/microsoft/vscode/issues/335110)

## Summary

Traced and confirmed in current-main source: the Linux/macOS Copilot CLI bootstrap shim keeps its own readline.Interface open on process.stdin while synchronously spawning the interactive install script with inherited stdio, which is consistent with the nested installer's `/dev/tty` PATH prompt not receiving input as described.

## Change summary

The Linux Copilot CLI shim's own readline interface interferes with the nested installer's interactive PATH prompt, and a successful install still leaves the CLI outside the non-login terminal's PATH.

## Best solution

In extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIShim.ts, close or pause the module-level `rl` readline.Interface before invoking `installCopilotCLI` (which calls runNpm/runBrew/runCurl/runWget with `stdio: 'inherit'`), re-creating it afterward for any subsequent prompts; separately, after a successful install, resolve/launch the newly installed binary directly (or otherwise account for non-login-shell PATH) instead of relying on the terminal's inherited PATH.
