# Issue #335110 — Linux Remote-SSH Copilot shim blocks installer prompt and leaves CLI outside terminal PATH

[https://github.com/microsoft/vscode/issues/335110](https://github.com/microsoft/vscode/issues/335110)

## Summary

Confirmed on main: `copilotCLIShim.ts` creates a readline interface on stdin at module scope and never closes it before synchronously spawning the interactive installer with inherited stdio, matching the reporter's diagnosis exactly. Real, still-open bug in a Remote-SSH Linux/macOS flow, worth fixing.

## Change summary

On Linux/macOS Remote-SSH, the Copilot CLI bootstrap shim's own open readline interface blocks the nested installer's `/dev/tty` PATH prompt, so the user can't respond and the installed CLI stays outside the terminal's PATH.

## Best solution

In extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIShim.ts, close (`rl.close()`) the module-level readline interface before calling `installCopilotCLI`/`runCurl`/`runWget`/`runNpm`/`runBrew` (which spawnSync with `stdio: 'inherit'`), and recreate it afterward only if still needed for `pressKeyToExit`; also consider having the shim source the newly installed binary's directory into `env.PATH` for the current process before re-invoking `copilot`.
