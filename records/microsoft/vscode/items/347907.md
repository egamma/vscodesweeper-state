## Evidence

- **Draft lifecycle:** src/vs/workbench/contrib/sessions/browser/sessionsManagementService.ts:552-610 deletes abandoned drafts through deleteNewSession and emits onDidDiscardNewSession or onDidReplaceNewDraftSession, not a catalog removal. The event contracts in common/sessionsManagement.ts distinguish abandonment from graduation.
- **Review and canvas retention:** src/vs/sessions/contrib/codeReview/browser/codeReviewService.ts stores getPRReviewState results in _prReviewBySession; _registerSessionListeners only cleans removed or archived sessions. src/vs/sessions/contrib/canvases/electron-browser/sessionCanvasService.ts adds observed chat owners to knownOwners, but removes them only for catalog removal, archival, or chat deletion. Neither handles the draft abandonment events.
- **Approval retention:** src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionApprovalModel.ts creates _approvals entries on lookup or model tracking. Removed chat models dispose their trackers and set the observable value to undefined, but never delete the map entry.
- **Agent-host identity retention:** src/vs/platform/agentHost/browser/agentHostConnectionsService.ts:216-261 permanently registers canonical entries in _backendSessions and _frontendByBackend. Disposing registerSessionResourceAlias removes only the alias and restores canonical reverse mapping; no canonical unregister path exists. BaseAgentHostSessionsProvider.deleteNewSession disposes its draft without releasing these canonical registrations.
- **Existing cleanup precedent:** src/vs/workbench/contrib/sessionChanges/browser/changesViewService.ts:248-255 explicitly releases draft state on both abandonment events. This confirms that ordinary catalog removal is not the complete draft-lifetime signal.
