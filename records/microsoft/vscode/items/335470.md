# Issue #335470 — Git: wrong upstream name when branch.<name>.merge is not under refs/heads/, Source Control Graph shows no history

[https://github.com/microsoft/vscode/issues/335470](https://github.com/microsoft/vscode/issues/335470)

## Summary

Traced and confirmed in the current source: getBranches() in extensions/git/src/git.ts unconditionally strips 11 characters from `upstreamRef` assuming a `refs/heads/` prefix, which corrupts the upstream name whenever `branch.<name>.merge` points to a ref outside `refs/heads/` (e.g. a mirror remote with a refspec that maps to `refs/remotes/...`). This breaks Source Control Graph history for that branch.

## Change summary

When a branch's configured upstream merge ref isn't under refs/heads/ (e.g. mirrored remotes), VS Code derives a bogus upstream ref name and Source Control Graph shows no history.

## Best solution

In extensions/git/src/git.ts, only strip the `refs/heads/` prefix from `upstreamRef` when it actually starts with that prefix; otherwise fall back to the already-refspec-mapped short name from `%(upstream:short)`, exactly as the reporter's proposed one-line fix does.
