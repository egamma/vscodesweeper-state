# Issue #335470 — Git: wrong upstream name when branch.<name>.merge is not under refs/heads/, Source Control Graph shows no history

[https://github.com/microsoft/vscode/issues/335470](https://github.com/microsoft/vscode/issues/335470)

## Summary

The reported upstream-name corruption remains directly traceable on current main and causes the Source Control Graph to discard history after Git rejects the fabricated ref. Classify this as a bug and route it to Git; the older related reports do not establish a canonical for this specific remote-mirror symptom.

## Change summary

Resolve upstream names correctly when a remote fetch refspec maps refs outside refs/heads/, so the Source Control Graph can display history.

## Best solution

The built-in Git extension should identify the valid local tracking ref for the reported mirror configuration without corrupting its name. Preserve ordinary upstream handling and existing Pull/Sync semantics, with regression coverage for the nonstandard remote-ref case.
