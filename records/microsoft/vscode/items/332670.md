# Issue #332670 — [Perf] Agents Window hangs for 12s when switching sessions

[https://github.com/microsoft/vscode/issues/332670](https://github.com/microsoft/vscode/issues/332670)

## Summary

Fresh, well-diagnosed team-authored performance bug with a traced repro and profiling data; the described `getSession()` bottleneck is confirmed on current main, so this stays open and gets routed to the sessions/agent-host area for a fix.

## Change summary

Switching sessions in the Agents Window can freeze the renderer for 6+ seconds, caused by a partially-deleted worktree exposing thousands of spurious changed files plus an O(n) `getSession()`/feedback-overlay lookup pattern that scales badly.

## Best solution

Three separate fixes are outlined and should likely become their own tracked items: (1) harden `removeWorktree`/`recreateWorktreeOnUnarchive` in the agent host git service against partial-deletion races, (2) dedupe/short-circuit the agent-feedback overlay's per-multi-diff-URI lookup so a no-feedback session doesn't scan every candidate, and (3) give `ISessionsManagementService.getSession()` (sessionsManagementService.ts:275) an O(1) resource-keyed lookup instead of rebuilding `_getMergedSessions()` and linearly scanning with `extUri.isEqual` on every call.
