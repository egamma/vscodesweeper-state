# Issue #332670 — [Perf] Agents Window hangs for 12s when switching sessions

[https://github.com/microsoft/vscode/issues/332670](https://github.com/microsoft/vscode/issues/332670)

## Summary

The measured per-file feedback loop was fixed, but this team-authored issue deliberately covers additional contributing defects that remain on current main: unarchive still trusts directory existence alone, and `getSession()` still rebuilds and scans all provider catalogs. Keep it open until those concerns are split into owned issues or resolved.

## Change summary

Switching away from an Agents Window session with thousands of reported changes blocked the renderer for several seconds.

## Best solution

Retain the merged feedback-loop mitigation, then split and resolve the remaining worktree-recovery and session-catalog lookup concerns. Unarchiving should repair an existing but invalid checkout, and frequently used session lookup should avoid rebuilding every provider catalog.

- **Likely files:** `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`, `src/vs/platform/agentHost/test/node/shared/worktreeIsolation.test.ts`, `src/vs/platform/agentHost/node/agentHostGitService.ts`, `src/vs/platform/agentHost/test/node/agentHostGitService.integrationTest.ts`, `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts`

- **Behavior:**

  > Switching sessions must remain responsive even when the outgoing session reports thousands of changed files. Unarchiving a session whose worktree path exists but whose checkout is incomplete must restore a usable checkout rather than publishing all tracked files as deleted. Session lookup used by renderer interactions must not repeatedly rebuild every provider catalog. Existing provider ordering, hidden-session resolution, migration behavior, and feedback early-exit behavior must remain unchanged.
- **Trace:**

  > The original trace confirmed that the feedback overlay multiplied an expensive session lookup across thousands of multi-diff resources. Commit 02d171319fb95e7f6db090942f5eaadba4d1a97d removed that multiplication in src/vs/sessions/contrib/agentFeedback, and commit 64ae77d65333f488e904836026aa59968069d188 completed cache invalidation for provider changes. The remaining worktree path is `WorktreeIsolationService._recreateWorktreeOnUnarchive` in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts, which currently treats successful `fs.access` as sufficient proof of a healthy checkout. The remaining lookup path is `SessionsManagementService.getSession` in src/vs/sessions/services/sessions/browser/sessionsManagementService.ts, which still rebuilds `_getMergedSessions()` and linearly compares resources. Preserve the merged feedback behavior and do not fold the separate cleanup-lifecycle requests in https://github.com/microsoft/vscode/issues/329776 or https://github.com/microsoft/vscode/issues/332442 into this work without confirming their distinct scopes.

- **merged narrow fix:** https://github.com/microsoft/vscode/pull/332708 merged as commit 02d171319fb95e7f6db090942f5eaadba4d1a97d and explicitly references this issue. It deduplicates feedback work by session and memoizes session resolution, with a 4,000-candidate regression test.
- **follow-up hardening:** Commit 64ae77d65333f488e904836026aa59968069d188 from https://github.com/microsoft/vscode/pull/332720 invalidates the feedback lookup memo when providers change, but remains confined to AgentFeedbackService.
- **remaining worktree defect:** On current main, `WorktreeIsolationService._recreateWorktreeOnUnarchive` in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts returns immediately after `fs.access(meta.worktreePath.fsPath)` succeeds; it does not validate that an existing checkout is registered and healthy, matching the partial-directory failure described in the issue.
- **remaining lookup cost:** On current main, `SessionsManagementService.getSession` in src/vs/sessions/services/sessions/browser/sessionsManagementService.ts still calls `_getMergedSessions()`, which invokes every provider's `getSessions()`, and then performs a linear `extUri.isEqual` search.
- **scope explicitly incomplete:** The merged PR states that the archived-worktree lifecycle and the `getSession()` lookup contract were not addressed. The related open issues https://github.com/microsoft/vscode/issues/329776 and https://github.com/microsoft/vscode/issues/332442 concern cleanup hooks and deletion cleanup respectively, not the exact partial-checkout recovery case.
