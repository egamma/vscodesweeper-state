# Issue #105888 — Line height setting consistency

[https://github.com/microsoft/vscode/issues/105888](https://github.com/microsoft/vscode/issues/105888)

## Summary

The editor portion is implemented, but explicit font-relative line heights remain unsupported for suggestions and the Debug Console. Keep this accepted backlog request open; the Output override documented by a maintainer addresses independent configuration, not the remaining unit inconsistency.

## Change summary

Support consistent font-relative line-height configuration across editor suggestions, the Debug Console, and Output.

## Best solution

Extend font-relative line-height support to suggestions and the Debug Console while preserving existing pixel values and automatic defaults. Retain Output's language-specific editor overrides rather than coupling its typography to terminal settings.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidget.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidgetDetails.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/browser/replViewer.ts`
- **Validation:** After agreeing on setting semantics, compare suggestion rows/details and Debug Console input/output at two font sizes using an explicit multiplier, an existing pixel value, and zero. Verify multipliers scale consistently, pixel values retain their agreed meaning, automatic defaults remain intact, and row sizing matches rendered text.
- **Behavior:**

  > Users can explicitly configure font-relative line heights for suggestions and the Debug Console instead of relying only on pixels or automatic inheritance. Changing each surface's font size scales its relative line height consistently. Existing pixel configurations and zero/default behavior remain compatible according to the agreed setting contract. Output remains independently configurable through its language-specific editor override.
- **Trace:**

  > EditorLineHeight in src/vs/editor/common/config/editorOptions.ts already supports multiplier semantics, delivered by https://github.com/microsoft/vscode/pull/125601. In the same file, suggestLineHeight remains an integer option; SuggestWidget.getLayoutInfo consumes it directly, and suggestWidgetRenderer.ts and suggestWidgetDetails.ts also consume the explicit value as a resolved height. ReplOptions.update in src/vs/workbench/contrib/debug/browser/repl.ts interprets nonzero debug.console.lineHeight as pixels, while replViewer.ts uses the resulting numeric height for row sizing. The reporter identified these remaining settings at https://github.com/microsoft/vscode/issues/105888#issuecomment-1090482890; the Output override is documented at https://github.com/microsoft/vscode/issues/105888#issuecomment-1348147894. The unresolved contract is how to add multipliers without unexpectedly reinterpreting previously valid small pixel values. Do not change terminal or Markdown multiplier semantics, editor.lineHeight behavior, or Output's configuration ownership.
- **Open decisions:**
  - Should suggestions and the Debug Console adopt editor.lineHeight's numeric threshold semantics, reinterpreting existing positive values below 8, or expose an unambiguous relative-value form that preserves every existing pixel value?
