## Change summary

Opening an Agents Window session before the Agent Host chat catalog hydrates the default chat's backend URI throws an uncaught 'The chat could not be found.' error from the fire-and-forget auto mark-read call.

## Best solution

In baseAgentHostSessionsProvider.setChatReadState, treat an unresolved backend URI for the default (fragment-less) chat as a benign startup no-op instead of throwing, while keeping the throw for a chat resource that genuinely has no match.
