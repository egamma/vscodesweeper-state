# Issue #340059 — [Error] unhandlederror-The chat could not be found.

[https://github.com/microsoft/vscode/issues/340059](https://github.com/microsoft/vscode/issues/340059)

## Summary

Genuine, source-confirmed bug: `markRead`/`setChatReadState` is called fire-and-forget from at least five call sites and the underlying provider throws `"The chat could not be found."` when `getBackendChatResource` can't resolve the chat (e.g. a race before `_lastSessionStates` is populated, or the chat/session having been removed), producing the unhandled rejection in this telemetry bucket. Keeping open for a fix; already auto-flagged via the `*fix` label.

## Change summary

Marking a session/chat as read can throw "The chat could not be found." as an unhandled promise rejection when the backend chat resource can't be resolved.

## Best solution

Swallow/log the error where `markRead`/`setChatReadState` is invoked without awaiting (mirroring the existing `.catch(onUnexpectedError)` pattern already used elsewhere in sessionsList.ts), ideally centralized in `SessionsManagementService.markRead`/`_setMainChatReadState` so every caller benefits.
