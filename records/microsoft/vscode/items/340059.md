[https://github.com/microsoft/vscode/issues/340059](https://github.com/microsoft/vscode/issues/340059)

## Summary

Keep open: current main still throws when opening a session whose default chat backend URI has not hydrated. The related fix proposal documents this exact race, but its pull-request creation failed and the proposed behavior is absent from current source.

## Change summary

Opening an Agent Host session before its default chat metadata arrives produces an unhandled chat-not-found error during automatic marking as read.

## Best solution

Make automatic default-chat read transitions tolerate incomplete startup metadata without fabricating a backend URI, while preserving genuine missing-chat errors and allowing the read transition after hydration. Reuse the diagnosis and candidate patch recorded at https://github.com/microsoft/vscode/issues/340063, with focused regression coverage before landing.
