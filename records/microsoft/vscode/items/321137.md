# Issue #321137 — The setting "task.allowAutomaticTasks" is not supported in non default profiles, while the settings file it is defined in does get synced across profiles

[https://github.com/microsoft/vscode/issues/321137](https://github.com/microsoft/vscode/issues/321137)

## Summary

The setting is deliberately application-scoped, so ignoring a value in a non-default profile is consistent with the current configuration contract. Independent control per profile remains an unmet feature request; route it to the tasks owner rather than closing it as a bug or duplicating the workspace-level request.

## Change summary

Allow each profile to control automatic task execution independently through task.allowAutomaticTasks.

## Best solution

Have the tasks owner assess profile-specific user consent for automatic tasks while preserving workspace-trust checks and the prohibition on workspace-controlled authorization. Setting the value in the Default profile enables automatic tasks across profiles today, but does not provide the requested independence.

  > Thanks for the report. `task.allowAutomaticTasks` is currently application-scoped: its value comes from the Default profile and applies across profiles, while a value entered only in another profile is ignored. Setting it to `"on"` in the Default profile enables automatic tasks in trusted workspaces across profiles, but does not provide independent control per profile.

## Evidence

- **Profile resolution explains the report:** src/vs/workbench/services/configuration/browser/configurationService.ts:getLocalUserConfigurationScopes selects PROFILE_SCOPES for non-default profiles; src/vs/workbench/services/configuration/common/configuration.ts excludes APPLICATION from those scopes. ApplicationConfiguration in src/vs/workbench/services/configuration/browser/configuration.ts instead reads application settings from defaultProfile.settingsResource.
- **Existing capability is only a workaround:** src/vs/workbench/contrib/tasks/browser/runAutomaticTasks.ts checks workspace trust and the effective task.allowAutomaticTasks value before running folder-open tasks. workbench.action.tasks.manageAutomaticRunning updates the user setting, but neither it nor the current setting registration offers independent per-profile authorization. The Default profile value applies across profiles; automatic tasks are not categorically unsupported outside the Default profile.
- **Unsupported profile values are intentional:** src/vs/workbench/contrib/preferences/browser/preferencesRenderers.ts:handleLocalUserConfiguration explicitly marks application-scoped settings in non-default profile settings files as unsupported.
