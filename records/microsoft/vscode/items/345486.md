# Issue #345486 — Remote Tunnel Access not restored on startup since 1.143.1: session is reset before Microsoft auth provider is ready

[https://github.com/microsoft/vscode/issues/345486](https://github.com/microsoft/vscode/issues/345486)

## Summary

Keep open: current main still allows startup to mistake undeclared authentication providers for a missing saved session, permanently disabling Remote Tunnel Access. The report supplies sufficient reproduction steps and timing evidence; the destructive fallback is confirmed in source.

## Change summary

Restore saved Remote Tunnel Access reliably when authentication provider discovery finishes after workbench startup.

## Best solution

Tunnel restoration should resolve the saved session after authentication discovery is ready, without treating temporary provider unavailability as an explicit request to disable remote access. Preserve existing explicit turn-off behavior and token-storage safeguards.
