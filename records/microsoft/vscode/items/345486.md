# Issue #345486 — Remote Tunnel Access not restored on startup since 1.143.1: session is reset before Microsoft auth provider is ready

[https://github.com/microsoft/vscode/issues/345486](https://github.com/microsoft/vscode/issues/345486)

## Summary

Keep open: current source still allows startup discovery to mistake an undeclared authentication provider for a missing session and permanently disable saved Remote Tunnel Access. The report supplies sufficient reproduction steps and timing evidence.

## Change summary

Restore saved Remote Tunnel Access reliably when authentication provider discovery finishes after tunnel initialization begins.

## Best solution

Tunnel restoration should distinguish unfinished authentication discovery from a genuinely unavailable saved session, preserving the saved configuration while discovery is pending and restoring access once the existing session becomes available.
