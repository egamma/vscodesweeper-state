# Issue #335402 — Disabling an extension does not take effect in the Agents Window

[https://github.com/microsoft/vscode/issues/335402](https://github.com/microsoft/vscode/issues/335402)

## Summary

The defect remains source-reproducible on current main: the Agents Window inherits the default profile's installed extensions but reads disabled-extension state from separate Agents-profile storage. This team-authored issue must remain open, and no commit explicitly referencing it was found.

## Change summary

Disabling an extension in the Editor Window should also prevent that extension from running after the Agents Window restarts.

## Best solution

Make extension enablement in the Agents Window consistently follow the profile state from which its extension list is inherited, including cross-window updates and restart behavior, without sharing unrelated profile-global state.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/common/extensionEnablementService.ts`, `src/vs/sessions/sessions.common.main.ts`, `src/vs/platform/userDataProfile/common/userDataProfile.ts`, `src/vs/workbench/services/extensionManagement/test/browser/extensionEnablementService.test.ts`
- **Validation:** Add a focused extension-enablement test using distinct default and Agents profile storage: disabling an installed extension through the default/editor profile must make the Agents Window enablement service report it disabled after initialization or restart, while unrelated profile storage remains isolated.
- **Behavior:**

  > An extension disabled in the Editor Window must not activate in the Agents Window after that window restarts. Re-enabling it must restore the Agents Window's normal capability and allow-list checks. Extensions that are enabled remain unaffected, and unrelated Agents-profile state must stay isolated.
- **Trace:**

  > The Agents profile is created with `extensions: true` in AGENTS_WINDOW_PROFILE_FLAGS at src/vs/platform/userDataProfile/common/userDataProfile.ts, so it uses the default profile's extension inventory. Disabled extensions are not part of that resource: GlobalExtensionEnablementService in src/vs/platform/extensionManagement/common/extensionEnablementService.ts stores DISABLED_EXTENSIONS_STORAGE_PATH under StorageScope.PROFILE. The Agents Window independently registers that service in src/vs/sessions/sessions.common.main.ts, and ExtensionEnablementService._isDisabledGlobally in src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts reads from it when deciding activation. Therefore the inherited extension inventory and enablement state come from different profiles. Preserve all existing Agents Window capability filtering and do not solve this by broadly sharing unrelated global profile state.

## Evidence

- **source reproduction:** src/vs/platform/userDataProfile/common/userDataProfile.ts defines AGENTS_WINDOW_PROFILE_FLAGS with `extensions: true` but without `globalState`, so the Agents Window inherits the default profile's extension list while retaining separate profile storage.
- **enablement storage:** src/vs/platform/extensionManagement/common/extensionEnablementService.ts stores and reads DISABLED_EXTENSIONS_STORAGE_PATH at StorageScope.PROFILE; the Agents Window registers this GlobalExtensionEnablementService independently in src/vs/sessions/sessions.common.main.ts.
- **activation path:** src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts determines DisabledGlobally through globalExtensionEnablementService.getDisabledExtensions(), so the Agents Window consults its own profile's disabled list rather than the editor/default profile's list.
