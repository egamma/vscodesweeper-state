# Issue #62277 — Surface the 'origin and 'presentationHint' attributes of a Source in the Loaded Scripts Explorer

[https://github.com/microsoft/vscode/issues/62277](https://github.com/microsoft/vscode/issues/62277)

## Summary

A real Loaded Scripts presentation gap remains on current main: the renderer ignores both `Source.presentationHint` and `Source.origin`, despite the Call Stack consuming those attributes. No older canonical issue was found, so this Backlog request should remain open.

## Change summary

Show a debug source's presentation hint and origin consistently in the Loaded Scripts Explorer.

## Best solution

Make Loaded Scripts honor source presentation hints consistently with Call Stack and expose the source origin without obscuring its path. A maintainer should first choose whether origin belongs in the row or only in its hover.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/loadedScriptsView.ts`, `src/vs/workbench/contrib/debug/browser/media/debugViewlet.css`, `src/vs/workbench/contrib/debug/test/browser/loadedScriptsView.test.ts`
- **Validation:** Exercise a Loaded Scripts tree entry backed by a DAP Source containing `origin` and `presentationHint: 'deemphasize'`; verify the chosen origin presentation and Call Stack-consistent deemphasis, while a source without either attribute remains unchanged. Add focused renderer coverage if the debug-view test harness can host it; otherwise document and run this as a manual debug-adapter scenario.
- **Behavior:**

  > A source shown in Loaded Scripts reflects its DAP `presentationHint` consistently with the same source in Call Stack. When the source has an `origin`, that information is available from the Loaded Scripts entry in the maintainer-selected location. Sources without these attributes retain their current label, hover, icon, and interaction behavior.
- **Trace:**

  > The source model already exposes `origin` and `presentationHint` in src/vs/workbench/contrib/debug/common/debugSource.ts. LoadedScriptsRenderer.render in src/vs/workbench/contrib/debug/browser/loadedScriptsView.ts currently sends ResourceLabels only a name, resource, path-derived title, file kind, and matches, so both attributes are dropped at rendering. Call Stack provides the consistency reference in StackFramesRenderer.renderElement in src/vs/workbench/contrib/debug/browser/callStackView.ts, with `isFrameDeemphasized` in src/vs/workbench/contrib/debug/common/debug.ts handling source-level deemphasis. Keep path compression, filtering, source opening, session/folder rows, and sources lacking these optional attributes unchanged. The uncertainty begins at origin presentation: the issue permits either inline italic text or a second hover line.
- **Open decisions:**
  - Should a source's `origin` appear as inline secondary text in the Loaded Scripts row, or as a second line in the hover while preserving the existing path title?

## Evidence

- **current source gap:** src/vs/workbench/contrib/debug/browser/loadedScriptsView.ts:699-729 renders a source using its resource and path-derived title only; it never reads `Source.presentationHint` or `Source.origin`.
