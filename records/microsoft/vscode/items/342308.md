# Issue #342308 — [Feature Request]: Public API for user-defined local agent harnesses and runtimes

[https://github.com/microsoft/vscode/issues/342308](https://github.com/microsoft/vscode/issues/342308)

## Summary

A supported third-party harness contract remains a real API gap: current session-provider registration is proposed, and Agent Host startup registers built-in providers internally. Keep this open for an API-owner decision; the related requests overlap but do not establish ownership of the full cross-surface, tool-access, and portable-session contract.

## Change summary

Provide a stable public contract for custom local agent runtimes with native harness selection, permitted tools, lifecycle management, and documented capabilities.

## Best solution

Define a bounded public extensibility contract using the existing session-provider and Agent Host infrastructure, coordinated with the related registration and API-finalization requests. Decide the supported tool-access and session-portability guarantees before committing to the full acceptance criteria.

  > An extension can supply its own agent runtime independently of model-provider selection without importing private VS Code modules. Acceptance includes predictable streaming, cancellation, errors, permitted tool execution, and documented restoration and portability semantics. Local and remote execution placement and secret scoping must be explicit.

The trace establishes missing stable registration, not that every requested tool or portability capability is absent. - **Open decisions:**
  - What is the first supported public contract: native session-provider integration, Agent Host runtime-provider registration, or both, and which surfaces must support it?
