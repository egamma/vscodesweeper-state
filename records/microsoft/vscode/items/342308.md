# Issue #342308 — [Feature Request]: Public API for user-defined local agent harnesses and runtimes

[https://github.com/microsoft/vscode/issues/342308](https://github.com/microsoft/vscode/issues/342308)

## Summary

A supported public runtime-integration contract remains missing. Existing session APIs and AHP connections provide partial integration, while the older external-provider request does not explicitly own this report's full cross-surface, tool-access, and portable-session requirements.

## Change summary

Provide a stable public extension contract for user-owned local agent runtimes, including native discovery, permitted tools, lifecycle, capabilities, and documented local/remote behavior.

## Best solution

Define the supported third-party runtime boundary using the existing session and AHP infrastructure where appropriate, with explicit tool authorization, lifecycle ownership, and compatibility guarantees. Coordinate registration work with https://github.com/microsoft/vscode/issues/325827 without losing the broader acceptance criteria here.

Exercise documented local and remote configurations and the agreed export/import contract; no execution was performed during this read-only review.
- **Behavior:**

  > An extension can integrate a user-owned runtime without private VS Code imports or changing source. The runtime is discoverable in the supported native surfaces independently of its model provider and without an unnecessary Copilot subscription. Tool permissions, cancellation, errors, unsupported capabilities, and session recovery have explicit observable behavior. Acceptance includes a public sample, documented secret/configuration scope, and lifecycle and conformance checks.
- **Trace:**

  > The stable declaration provides chat participants, models, and tool invocation, while native session registration remains behind the chatSessionsProvider proposal in extHost.api.impl.ts. agentHostMain.ts internally registers the supplied runtimes; experimental workspace WebSocket configuration already connects conforming hosts to editor Chat. Existing AHP interoperability must be preserved, including advertised identities and negotiated capabilities. The unresolved boundary is how extension-managed runtime registration relates to these existing seams and which lifecycle, tool-access, and portability guarantees become public. Coordinate with https://github.com/microsoft/vscode/issues/325827; do not treat model-provider support or a specific ACP adapter as completion of this contract.
- **Open decisions:**
  - Should the supported extension contract register providers inside the VS Code Agent Host, manage external AHP runtime processes, or support both?
  - Which native tools and approval guarantees must third-party runtimes receive consistently across Chat and the Agents window?
  - What session export/import and compaction guarantees are mandatory, and which may remain explicitly provider-specific?
