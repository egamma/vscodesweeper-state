## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/325827 is open, predates this report, and explicitly requests an Extension API for complete Agent Host implementations with custom SDKs, dynamic picker registration, local/remote orchestration, capability declarations, and session lifecycle ownership—not merely prompt agents or model providers.
- **Canonical discussion covers independent local runtimes:** https://github.com/microsoft/vscode/issues/325827#issuecomment-5443830217 describes an independent runtime requiring tools, MCP, permissions, persistence, streaming, cancellation, and recovery. https://github.com/microsoft/vscode/issues/325827#issuecomment-5945244541 describes an interoperable external AHP host whose remaining gaps are first-class local harness registration, process management, workspace scoping, and lifecycle coupling. These are the same missing integration boundary identified here.
- **Existing capabilities are partial, not completion:** src/vscode-dts/vscode.d.ts exposes chat.createChatParticipant, lm.invokeTool, and lm.registerLanguageModelChatProvider. Session integration exists in src/vscode-dts/vscode.proposed.chatSessionsProvider.d.ts, but src/vs/workbench/api/common/extHost.api.impl.ts gates createChatSessionItemController and registerChatSessionContentProvider behind the chatSessionsProvider proposal; src/vs/workbench/contrib/chat/browser/chatSessions/chatSessions.contribution.ts likewise gates the chatSessions contribution. These do not establish the requested stable runtime-registration contract.
- **Current internal registration boundary:** src/vs/platform/agentHost/node/agentHostMain.ts explicitly registers CopilotAgent, ClaudeAgent, and CodexAgent through providerService.registerProvider. The registry contract in src/vs/platform/agentHost/node/agentHostProviderService.ts is an internal platform service, not a stable vscode extension API.
- **Related requests distinguished:** https://github.com/microsoft/vscode/issues/340294 and https://github.com/microsoft/vscode/issues/340680 concern consistency and reliability across existing agent experiences. https://github.com/microsoft/vscode/issues/340860 proposes a particular ACP implementation and explicitly references the extension-registration alternative in https://github.com/microsoft/vscode/issues/325827. The latter is the direct canonical for this report's central API request.
