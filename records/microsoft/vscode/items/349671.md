# Issue #349671 — First input can be lost after opening a custom editor with preserveFocus beside a text editor

[https://github.com/microsoft/vscode/issues/349671](https://github.com/microsoft/vscode/issues/349671)

Keep open: the attached script-free extension provides sufficient steps to retest the reported missing input on current main. Current source has focus guards, but inspection does not establish which asynchronous callback defeats focus preservation or that the reported behavior is fixed.

## Change summary

Opening a custom editor beside a focused text editor with preserveFocus can leave the first typing command without a focused text-editor target.

## Best solution

Identify the focus transition in the custom-editor/webview lifecycle and ensure background editor opening does not reclaim focus from the text editor. Preserve intentional webview focusing and existing Quick Pick protections.
