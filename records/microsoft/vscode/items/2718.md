# Issue #2718 — Git - Automatically insert line breaks in git commit messages

[https://github.com/microsoft/vscode/issues/2718](https://github.com/microsoft/vscode/issues/2718)

## Summary

Keep open: current VS Code provides manual hard-wrap quick fixes and visual wrapping, but neither automatically inserts newlines before committing. This accepted, well-supported request remains distinct from the related ruler and character-count requests.

## Change summary

Optionally insert real line breaks at a configurable column automatically when committing a Git message.

## Best solution

Provide opt-in automatic hard wrapping for commit-message bodies in the built-in Git workflow, preserving existing behavior when disabled. Settle subject handling and preservation of structured text before implementing automatic message transformation.

  > The requested outcome is automatic insertion of real newlines into commit-message text before it is committed, rather than visual word wrapping or a manually invoked quick fix. Users should be able to opt in and choose the wrapping column, with existing behavior retained when disabled. Acceptance must inspect the stored Git commit message, not its on-screen appearance. Subject handling and preservation of structured message content require an explicit contract.
- **Trace:**

  > Commands.commitWithAnyInput in extensions/git/src/commands.ts reads the SCM input and forwards it through smartCommit without wrapping. GitCommitInputBoxCodeActionsProvider in extensions/git/src/diagnostics.ts already constructs manual newline-inserting edits using configurable subject/body thresholds, but its line-oriented algorithm does not establish automatic paragraph-formatting semantics. The merged https://github.com/microsoft/vscode/pull/95266 supplies full-editor authoring, not automatic hard wrapping. Preserve disabled-mode behavior, existing commit variants, and trailer semantics; visual rulers and character-count improvements are separate work. Uncertainty begins with which message structures may be transformed automatically and whether subject wrapping is part of the supported contract.
- **Open decisions:**

  - Should the initial option cover only messages supplied through the SCM input, or also messages authored in the full commit editor?
