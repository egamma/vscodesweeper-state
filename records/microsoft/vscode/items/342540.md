# Issue #342540 — Copilot in WSL fails behind Kerberos/Negotiate proxy since 1.142.0: copilot-sdk rt_network no longer uses Windows-side proxy auth and certificates

[https://github.com/microsoft/vscode/issues/342540](https://github.com/microsoft/vscode/issues/342540)

## Summary

Keep open as a reported Copilot remote-networking regression. Current main launches a native runtime with forwarded proxy configuration, but that does not establish Windows credential or certificate inheritance; the supplied steps and logs suffice to retest without requesting more information.

## Change summary

Copilot in WSL fails behind an authenticating, TLS-inspecting proxy unless Kerberos credentials and the corporate CA are separately installed inside WSL.

## Best solution

Restore supported local-proxy authentication and certificate behavior for Copilot's native-runtime requests in WSL, including managed-settings resolution. First reproduce the Windows-to-WSL boundary and determine which integration or runtime component must supply that behavior, without weakening certificate validation.
