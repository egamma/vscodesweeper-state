# Issue #335781 — Copilot Agent: If a agent creates a new session with create_session the new session should be aware of the parent session

[https://github.com/microsoft/vscode/issues/335781](https://github.com/microsoft/vscode/issues/335781)

## Summary

Reasonable, freshly-filed request about the Agent Host's `create_session` tool: the host tracks parent/child session provenance for UI purposes, but deliberately does not expose it to the spawned agent's own context, forcing users to hand-roll a parent-session-URI workaround that the model sometimes gets wrong. No maintainer has weighed in yet (0 upvotes, 0 comments, just filed), so this needs product triage rather than an automated verdict.

## Change summary

Requests that a session created via `create_session` be told (in-context) which session/chat spawned it, or alternatively that the parent auto-receive a completion notification, instead of relying on the agent to correctly copy a parent-session URI into the child prompt.

## Best solution

A maintainer decision is needed on whether to surface creation provenance to the agent's own context (e.g. injecting the resolved parent session/chat reference into the spawned session's initial prompt) or add an opt-in completion notification back to the parent — this touches the `create_session` server tool and the existing 'creating session, chat, and turn... does not define a hierarchy, grant communication privileges, or trigger lifecycle notifications' provenance design in src/vs/platform/agentHost/node/shared/sessionServerTools.ts and AGENTS.md.
