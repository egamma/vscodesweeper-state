# Issue #335781 — Copilot Agent: If a agent creates a new session with create_session the new session should be aware of the parent session

[https://github.com/microsoft/vscode/issues/335781](https://github.com/microsoft/vscode/issues/335781)

## Summary

Confirmed against the Agent Host multi-chat spec and the `create_session` code path: the parent/chat/turn provenance recorded when `create_session` spawns an independent session is explicitly scoped to UI placement and source identification, and is documented as deliberately not granting communication privileges, defining a hierarchy, or triggering lifecycle notifications to the child agent — matching current shipped behavior, so this is as-designed rather than a gap.

## Change summary

Requests that a session spawned via the `create_session` server tool automatically know (or be told) it is a child of a parent session, so it can reliably message the parent back on completion without the creating agent having to paste the parent's session URI into the prompt.

## Best solution

If this direction is ever revisited, it would be a deliberate product decision (e.g. surfacing the creation reference through `get_current_session`, or auto-notifying the parent on child completion) — not a bug fix. Today's intentional boundary (provenance is UI-only, no auto-messaging) is documented in `src/vs/platform/agentHost/AGENTS.md` and matches the code in `sessionServerTools.ts`.

  > Thanks for the detailed writeup and for sharing your workaround/skill. This is actually the intended current design: when `create_session` spawns an independent session, the parent/chat/turn link it records is used only for related-session placement, source identification, and session-list presentation in the UI — it deliberately does not grant communication privileges, define a hierarchy, or trigger automatic lifecycle notifications back to the parent. So today, if a child session needs to notify its parent, the creating agent has to pass that information explicitly (as you're doing), and there's no automatic "child session, tell your parent on completion" behavior. Making that automatic would be a deliberate product change to session orchestration, not a bug, so I don't think this is something to track as an open defect here.
