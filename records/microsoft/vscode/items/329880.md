# Issue #329880 — [Perf] Agent Host listSessions spawns hundreds of Git processes

[https://github.com/microsoft/vscode/issues/329880](https://github.com/microsoft/vscode/issues/329880)

## Summary

Real, well-documented perf regression from #328375 (added synchronous list-time worktree normalization capped at a 100-entry LRU) — confirmed on main at src/vs/platform/agentHost/node/agentService.ts:334 (`new LRUCache<string, URI>(100)`), and already has an open fixing PR that references this issue, so this stays open pending that PR landing rather than being closed now.

## Change summary

Agent Host's listSessions enrichment thrashes two 100-entry normalization caches on large worktree catalogs, spawning hundreds of redundant `git worktree list` processes and stalling session-list rendering for tens of seconds.

## Best solution

Land (or iterate on) the open fix in https://github.com/microsoft/vscode/pull/329882, which sizes both normalization caches to the provider catalog and persists aggregate change counts in the startup cache; the reporter also names a good follow-up (moving legacy repair off the synchronous listing path) that could become a separate tracked item once the immediate fix ships.
