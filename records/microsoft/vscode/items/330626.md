# Issue #330626 — Simple file dialog: clicking a child of / updates the path but does not refresh the folder contents (regression in 1.133.0)

[https://github.com/microsoft/vscode/issues/330626](https://github.com/microsoft/vscode/issues/330626)

## Summary

Real, well-diagnosed regression in the simple file dialog's navigation-shortcut guard, and there's already an open PR (#330629) that fixes it and links this issue — so this stays open pending that PR landing, not a fresh fix or a close.

## Change summary

In the simple (remote/WSL) file dialog, clicking a child entry while at the root folder `/` updates the path text but doesn't refresh the folder listing, making it impossible to browse out of root by clicking.

## Best solution

Land the already-open fix in https://github.com/microsoft/vscode/pull/330629, which excludes trailing-separator-normalized root children from the 'same directory, just filter' shortcut in `handleValueChange`, and adds a regression test for navigating from POSIX root.

## Evidence

- **root cause traced in source:** src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts:514 short-circuits with `if (resources.extUriIgnorePathCase.isEqual(this.currentFolder, resources.dirname(filePickBoxUri))) { this.setActiveItems(value); return; }` — skipping `tryUpdateItems`/`updateItems`. When `currentFolder` is `/` and the clicked child's dirname is also `/` (root has no distinct 'without trailing separator' form the way `/home/user` vs `/home/user/` do), this incorrectly treats descending into a root child as 'still browsing the same folder', so the listing is never refreshed.
