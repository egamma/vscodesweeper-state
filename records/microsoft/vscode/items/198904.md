# Issue #198904 — When actions.find has a "User" source, workbench.action.terminal.focusFind stops working

[https://github.com/microsoft/vscode/issues/198904](https://github.com/microsoft/vscode/issues/198904)

## Summary

Keep open: a maintainer confirmed the edit-and-revert failure, and current source still retains a higher-priority user binding after that sequence. No verified fix or older canonical reporting the same terminal-search symptom was found.

## Change summary

Editing and restoring the Find shortcut's when clause leaves a user override that prevents Ctrl+F from opening terminal search.

## Best solution

Make the reported edit-and-revert workflow preserve normal terminal Find behavior without weakening intentional user overrides. First reproduce the current dispatch outcome and establish the appropriate boundary between restoring defaults and retaining explicit customizations.

- **Trace:**

KeybindingResolver appends overrides after defaults and resolves in reverse order, so restoring identical text does not restore default precedence. The editor Find condition includes editorIsOpen, while terminal Find is a separate, normally higher-weight default registration. The uncertainty is whether returning to default values should itself restore default priority or whether the Find interaction should preserve terminal dispatch while retaining a user override.
