# Issue #300191 — Sessions with Codex are set as "unread sessions"

[https://github.com/microsoft/vscode/issues/300191](https://github.com/microsoft/vscode/issues/300191)

## Summary

The core report — external agent sessions (Codex, Claude Code) spuriously appearing as unread — is partially addressed by recent fixes (33e004b6221, c012a3eae30) but commenters confirm it still reproduces as of June 2026. A maintainer acknowledged the 'global sessions' aspect is upstream (Codex), but VS Code's read-state tracking still has a role. Keeping open as the bug persists.

## Change summary

Agent sessions from external providers (Codex, Claude Code) are persistently marked as unread in the chat panel, accumulating badges the user cannot clear without manually opening each session.

## Best solution

The VS Code side should ensure that when an external/agent-host session is initially synced (or re-synced across workspaces), its read state is either inherited from the provider or defaults to read rather than unread. The fixes in #315582 and #315783 addressed part of this, but the remaining gap is that sessions completing outside the active workspace still get marked unread on re-sync. The session read-state logic in agentSessionsModel.ts and sessionsListModelService.ts needs a heuristic that avoids marking a session unread when the user never initiated it locally.
