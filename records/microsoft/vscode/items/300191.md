# Issue #300191 — Sessions with Codex are set as "unread sessions"

[https://github.com/microsoft/vscode/issues/300191](https://github.com/microsoft/vscode/issues/300191)

## Summary

Keep open: multiple reporters confirm unwanted unread badges, including sessions becoming unread again after changing folders. Current source still has workspace-local fallback read tracking, but provider-owned read state now exists, so the affected Codex integration needs diagnosis before attributing the remaining failure.

## Change summary

Codex sessions already viewed externally or explicitly marked read in VS Code appear as unread, including after switching folders.

## Best solution

Make the workbench preserve acknowledged read state for the same external session across folders and honor externally reported read state where available. Investigate the Codex provider boundary separately from its upstream global-session visibility issue; retain badges for genuinely new, unread activity.
