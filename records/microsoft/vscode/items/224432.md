# Issue #224432 — Finalize viewcontainer menu contribution

[https://github.com/microsoft/vscode/issues/224432](https://github.com/microsoft/vscode/issues/224432)

## Summary

Keep this team-authored API-finalization tracker open: current main still exposes `viewContainer/title` only through the proposed API and retains the temporary debug-only validation. The public contract and eligible view-container scope remain to be finalized.

## Change summary

Finalize the proposed `viewContainer/title` menu contribution point with a stable, enforceable scope for eligible view containers.

## Best solution

Define which built-in or extension-contributed view containers may receive title-menu actions, enforce that contract through parsed context-key expressions, and graduate the contribution point only after its manifest behavior and diagnostics are validated.

## Plan brief

- **Likely files:** `src/vs/workbench/services/actions/common/menusExtensionPoint.ts`, `src/vs/platform/extensions/common/extensionsApiProposals.ts`, `src/vscode-dts/vscode.proposed.contribViewContainerTitle.d.ts`
- **Validation:** Use an Extension Development Host with manifest fixtures contributing to `viewContainer/title`: verify an approved container contribution is accepted and rendered, while disallowed or insufficiently constrained contributions receive the finalized diagnostic and cannot appear.
- **Behavior:**

  > Extensions should have a stable `viewContainer/title` menu contribution contract for the view containers that VS Code intentionally exposes. Contributions outside that scope must be rejected or constrained consistently rather than accepted through a fragile textual check. Acceptance must cover a valid contribution appearing in the intended container and invalid contributions producing the documented diagnostic without appearing elsewhere.
- **Trace:**

  > The proposed surface entered through https://github.com/microsoft/vscode/pull/212499 and remains gated by `contribViewContainerTitle` in `src/vs/workbench/services/actions/common/menusExtensionPoint.ts`. The same file currently checks whether the raw `when` string contains `viewContainer == workbench.view.debug`, which the maintainer identified as temporary and insufficient for finalization. The proposal remains registered in `src/vs/platform/extensions/common/extensionsApiProposals.ts`, with `src/vscode-dts/vscode.proposed.contribViewContainerTitle.d.ts` as an empty marker. Keep the scope to this title-menu contract; the separate debug-view context-menu work is tracked by https://github.com/microsoft/vscode/issues/227169.
- **Open decisions:**
  - Which built-in view-container identifiers are part of the stable contribution contract initially: debug only, or an explicit broader allowlist?
  - May extensions contribute title actions to extension-defined view containers, or only to approved built-in containers?
  - When a contribution's `when` clause does not guarantee an eligible container, should VS Code reject it or enforce an additional container condition while reporting a warning?
