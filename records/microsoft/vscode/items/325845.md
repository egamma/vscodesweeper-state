# Issue #325845 — Agent host: corrupt (7-byte) pasted-image attachment is persisted without validation and reproducibly crashes the renderer (SIGTRAP in image decode) on session open

[https://github.com/microsoft/vscode/issues/325845](https://github.com/microsoft/vscode/issues/325845)

## Summary

Current main retains the reported crash chain: Agent Host persists image bytes without validating them, and the restored request UI reads those bytes into an image preview. This security-sensitive renderer denial-of-service must remain open for human handling.

## Change summary

A truncated pasted-image attachment is persisted into Agent Host session state and repeatedly crashes the renderer when that session is reopened.

## Best solution

Prevent invalid or partial image snapshots from becoming durable session references, commit valid snapshots atomically, and make restored image cards fall back to a non-decoding broken-image state when persisted bytes are invalid. Existing valid image, text, selection, and remote-client attachment behavior must remain intact.

- **renderer decode path:** src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts:548-589 reads hydrated attachment bytes from the persisted resource and passes them to createImageElements; lines 633-709 construct the image-preview content without validating the encoded image first.
- **existing tests expose the gap:** src/vs/platform/agentHost/test/node/agentService.test.ts:4669-4864 covers successful attachment snapshots, metadata preservation, and failed reads, but has no case rejecting a short successful image read or ensuring an incomplete write cannot become the persisted reference.
