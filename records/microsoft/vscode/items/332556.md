# Issue #332556 — Extension activation telemetry's `codeLoadingTime` is misleading

[https://github.com/microsoft/vscode/issues/332556](https://github.com/microsoft/vscode/issues/332556)

## Summary

Real, still-open design gap: `codeLoadingTime` for ESM extensions is wall-clock time around an `await import()`, which can be inflated by concurrently activating extensions; a proposed fix was tried and rejected by a maintainer, so the underlying problem remains unaddressed.

## Change summary

For ESM extensions, `codeLoadingTime` telemetry can include time spent on other extensions' concurrent async work, overstating the reporting extension's true load cost.

## Best solution

Needs a maintainer-approved design (e.g. the event-loop-contention estimate the reporter suggests, or another approach) rather than the synchronous `require(esm)` workaround that was tried in PR #332571 and rejected as undesirable; belongs in the extension host activation/telemetry code (`src/vs/workbench/api/common/extHostExtensionActivator.ts`, `extHostExtensionService.ts`).
