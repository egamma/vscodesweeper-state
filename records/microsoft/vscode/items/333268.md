# Issue #333268 — Automations: guard deletion against concurrent definition changes

[https://github.com/microsoft/vscode/issues/333268](https://github.com/microsoft/vscode/issues/333268)

## Summary

Team-authored follow-up from a merged PR, and current main confirms the gap: `deleteAutomation` in automationService.ts deletes purely by ID with no comparison to the descriptor the user last saw, so this stays open for implementation work.

## Change summary

Automation deletion should atomically verify the current automation still matches the descriptor shown at confirmation time, distinguishing deleted/changed/already-deleted outcomes instead of blindly deleting by ID.

## Best solution

Add a guarded delete (e.g. `deleteAutomationIfUnchanged`) mirroring the existing `updateAutomationIfUnchanged` pattern across `IAutomationStore`/`IAutomationService`/provider routing/legacy storage/Agent Host storage, per the issue's own implementation direction; belongs in src/vs/sessions/contrib/automations/browser/automationService.ts and providerAutomationService.ts plus the corresponding storage backends.
