# Issue #339891 — Measuring more worktree than asked to clean up?

[https://github.com/microsoft/vscode/issues/339891](https://github.com/microsoft/vscode/issues/339891)

## Summary

Traced in the new Agent Sessions worktree-cleanup feature: opening the Manage Agent Session Worktrees editor always measures every worktree-bearing session (not just the ones the user intended to clean up), so the progress notification can look like it's scanning far more than the '2 worktrees' the suggestion banner called out — confusing, but may be partly intentional since the editor needs the full list to let the user pick.

## Change summary

The worktree-cleanup progress notification appears to scan more worktrees than the number the user actually asked to clean up.

## Best solution

Clarify the scope mismatch: either make the 'Measuring...' progress text explicit that it's building the full manageable list (not just the suggested N), or special-case the flow triggered directly from the suggestion banner's quick action to only measure the pre-selected candidates.
