- **Behavior:**

  > An authenticated GitHub MCP server can successfully execute calls while a subsequent tool remains blocked behind an authentication card. Clicking Authenticate reports that the server is already ready, and Cancel reportedly leaves the operation waiting. Authentication state must accurately reflect the pending tool's requirements, and cancellation must produce a settled tool outcome rather than indefinite waiting.
- **Trace:**

  > The November 23 logs match authenticateMcpServer in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCustomizationService.ts, which returns false for a Ready server. ChatToolAuthenticationSubPart invokes that method without consuming its result and delegates Cancel to the invocation state. AgentHostSessionHandler renders authentication from the tool's AuthRequired status and dispatches ChatToolCallComplete on cancellation. The unresolved boundary is why the host tool remains AuthRequired while server customization state is Ready, and whether cancellation reaches and releases the pending provider operation. Preserve legitimate authentication requirements and avoid blindly replaying side-effecting GitHub calls. The remote connection fix at https://github.com/microsoft/vscode/pull/348685 addresses a different failure; https://github.com/microsoft/vscode/issues/349250 identifies a distinct side-chat lookup failure.
