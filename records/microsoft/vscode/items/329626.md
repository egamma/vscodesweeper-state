# Issue #329626 — Auto model selection should offer quality, balanced, and economy routing profiles

[https://github.com/microsoft/vscode/issues/329626](https://github.com/microsoft/vscode/issues/329626)

## Summary

The exact capability requested — quality/balanced/economy routing profiles for Auto, with a picker, server-side per-tier routing, and post-response transparency about the resolved model/fallback — already exists in the current codebase (eco/balanced/max tiers), but it's gated behind an off-by-default experiment and isn't yet reflected in public docs, so it's not something most users can point to today; keeping this open lets a maintainer confirm rollout status and close it once the tier system ships broadly.

## Change summary

Add user-selectable Auto routing profiles (quality/balanced/economy) with transparency into the resolved model and subagent inheritance of the chosen profile.

## Best solution

Confirm this is superseded by the in-progress `chat.autoMode.tiers.enabled` (experiment `copilotchat.autoModeTiersEnabled`) rollout — eco/balanced/max tiers, per-tier `/auto` routing, and the 'Routed to {model}' resolution UI already implement nearly everything asked for; once that experiment ships to 100% and docs are updated, this can close as covered. If subagent tier inheritance isn't yet wired the same way, that's the remaining gap to verify.

## Evidence

- **tiers already implemented:** extensions/copilot/src/platform/endpoint/common/autoModeTiers.ts defines `autoModeTiers = ['eco','balanced','max','fast']` with `selectableAutoModeTiers = ['eco','balanced','max']` offered in the model picker — matching the requested economy/balanced/quality profiles.
- **picker UI + labels:** extensions/copilot/src/extension/conversation/common/languageModelAccess.ts `getAutoModeTierLabel`/`getAutoModeTierDescription` render 'Eco: Cheaper models for everyday tasks', 'Balanced: Balances capability and cost', 'Max: Most capable models, higher cost'; wired into the model configuration schema via `buildAutoModeTierSchemaProperty` in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts.
- **server-side per-tier routing:** extensions/copilot/src/platform/endpoint/node/automodeService.ts resolves a tier per session (`_resolveTier`) and posts it to the router (`POST /auto`), with `areAutoModeTiersSupported()` gating the feature behind an experiment.
- **experiment-gated, not GA:** extensions/copilot/src/platform/configuration/common/configurationService.ts: `AutoModeTiersEnabled = defineSetting('chat.autoMode.tiers.enabled', ConfigType.ExperimentBased, false, ..., { experimentName: 'copilotchat.autoModeTiersEnabled' })` — default false, so most users don't currently see this.
- **resolution transparency:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatAutoModeResolutionContentPart.ts renders a collapsible 'Routed to {model}' part with confidence/fallback detail, addressing the transparency ask.
- **not a clean duplicate:** The keyword-matched https://github.com/microsoft/vscode/issues/329680 is about user-defined task-type→model rules, a different (complementary) mechanism, not the same profile-routing request.
