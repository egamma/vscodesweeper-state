# Issue #268701 — Enahnce chat.mcp.discovery.enabled to support cline cline_mcp_settings.json

[https://github.com/microsoft/vscode/issues/268701](https://github.com/microsoft/vscode/issues/268701)

## Summary

The requested Cline import remains absent on current main: external MCP discovery supports Claude Desktop, Copilot CLI, Windsurf, and Cursor, but not Cline. The request is accepted in the Backlog and no older canonical issue was found, so it should remain open.

## Change summary

Discover MCP server definitions from Cline's `cline_mcp_settings.json` alongside the other supported external MCP configurations.

## Best solution

Add Cline as a separately configurable external discovery source, using the existing filesystem discovery adapter architecture and Cline's supported per-platform configuration locations.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts`, `src/vs/workbench/contrib/mcp/common/discovery/nativeMcpDiscoveryAdapters.ts`, `src/vs/workbench/contrib/mcp/common/discovery/nativeMcpDiscoveryAbstract.ts`, `src/vs/workbench/contrib/mcp/test/common/nativeMcpDiscoveryAdapters.test.ts`
- **Validation:** Extend the native MCP discovery adapter tests to assert that enabling the Cline source watches each approved per-platform `cline_mcp_settings.json` location, disabling it watches none, and valid `mcpServers` entries produce server definitions.
- **Behavior:**

  > When Cline discovery is enabled under `chat.mcp.discovery.enabled`, VS Code discovers MCP servers from Cline's configuration without requiring users to duplicate those definitions. Cline discovery is independently configurable and disabled by default, matching the existing external discovery sources. Existing Claude Desktop, Copilot CLI, Windsurf, and Cursor discovery behavior must remain unchanged.
- **Trace:**

  > `ExternalDiscoverySource`, its labels, and the generated setting schema originate in `src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts`. `NativeFilesystemMcpDiscovery` in `src/vs/workbench/contrib/mcp/common/discovery/nativeMcpDiscoveryAbstract.ts` instantiates the native adapters, while `nativeMcpDiscoveryAdapters.ts` maps each source to a file and reuses `claudeConfigToServerDefinition` for the common `mcpServers` shape. The path and enablement contract is covered by `src/vs/workbench/contrib/mcp/test/common/nativeMcpDiscoveryAdapters.test.ts`. The two linked attempts, https://github.com/microsoft/vscode/pull/268702 and https://github.com/microsoft/vscode/pull/268703, were closed unmerged and should not be treated as the design; preserve the current opt-in discovery and trust behavior.
- **Open decisions:**
  - Should Cline discovery cover only the macOS Code global-storage path reported here, or all supported Cline configuration locations on macOS, Windows, and Linux?
