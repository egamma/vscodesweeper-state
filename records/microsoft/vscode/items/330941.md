# Issue #330941 — Session list change counts show the whole branch divergence, not the session's changes

[https://github.com/microsoft/vscode/issues/330941](https://github.com/microsoft/vscode/issues/330941)

## Summary

Well-diagnosed and self-corrected report: the sessions-list chip intentionally sources the branch changeset (per #323852, a deliberate maintainer decision pinned by a characterization test), but for a local session started on a long-lived shared branch that number is the whole branch divergence, not the session's own footprint — a real UX gap in an intentional design, not a code defect, so this needs a maintainer product call on which changeset feeds the chip rather than an automatic fix.

## Change summary

The change-count chip in the agent sessions list shows the entire branch's divergence from its base, rather than the specific session's own edits, when the session runs on a pre-existing long-lived branch.

## Best solution

A maintainer should decide whether the sessions-list chip should source from the already-computed `session` changeset (baseline-checkpoint vs latest-turn-checkpoint diff via computeFileDiffsBetweenRefs, agentHostChangesetService.ts:1541-1566) instead of the branch changeset for non-branch-owning sessions, or explicitly relabel the chip to make clear it reflects branch divergence rather than session work; a prior attempt to anchor on the baseline checkpoint directly (#330942) was tried and reverted because baseline checkpoints are parentless snapshots unsuitable as a merge-base diff root.

- **deliberate design precedent:** Issue/PR #323852 ('Agents - use branch changes diff summary for sessions list and session title') is merged, authored by maintainer lszomoru, milestone 1.128.0 — confirming the branch-diff source for the list chip is intentional, not accidental.
