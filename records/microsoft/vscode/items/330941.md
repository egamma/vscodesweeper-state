# Issue #330941 — Session list change counts show the whole branch divergence, not the session's changes

[https://github.com/microsoft/vscode/issues/330941](https://github.com/microsoft/vscode/issues/330941)

## Summary

Well-diagnosed, real bug — the session-list change chip is sourced from the branch-wide diff instead of the session's own checkpoint diff — and there's already an open, non-draft PR (#331345) with 'Fixes #330941' actively fixing exactly this. Keep open until that merges.

## Change summary

The change count shown against a session in the Agent Sessions list reflects the whole branch's divergence from its upstream, not the edits that session actually made, so on a long-lived shared branch every session shows an identical, ever-growing, misleading number.

## Best solution

Land and merge PR https://github.com/microsoft/vscode/pull/331345, which moves the write path to derive the chip from the `changeKind: 'session'` changeset (baseline checkpoint vs. latest turn checkpoint) and removes the branch-derived read-path fallback that was persisting the wrong number; the reporter also flags multi-folder sessions (`_updateMultiFolderChangesSummary`) as sharing the same defect and explicitly out of scope for that PR, so a follow-up may still be needed there.
