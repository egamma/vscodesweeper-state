# Issue #338819 — Custom OpenAI-compatible models: `reasoning_content` is never sent back when the provider streams it without an id

[https://github.com/microsoft/vscode/issues/338819](https://github.com/microsoft/vscode/issues/338819)

## Summary

Confirmed on main: OpenAIEndpoint.getCompletionsCallback only echoes reasoning back when the provider supplied an id, so SGLang/vLLM-style servers that stream reasoning_content with no id never get their reasoning replayed, degrading thinking models exactly as described. This is a real, bounded bug in the BYOK Chat Completions path.

## Change summary

For custom OpenAI-compatible thinking models, streamed reasoning_content is dropped from later requests whenever the provider's delta carries no id (cot_id/reasoning_opaque/signature).

## Best solution

In OpenAIEndpoint.getCompletionsCallback (extensions/copilot/src/extension/byok/node/openAIEndpoint.ts), echo reasoning_content/reasoning whenever text is present and the model supports thinking, independent of whether an id was supplied; only set cot_id/cot_summary when an id exists, since ThinkingDataInMessage.cot_id is optional and CAPIChatMessage happily serializes reasoning_content alone.

## Evidence

- **gating bug:** extensions/copilot/src/extension/byok/node/openAIEndpoint.ts:159-168 — getCompletionsCallback only runs its whole body `if (data?.id)`, so reasoning_content is only ever set when an id was derived.
- **id sources:** extensions/copilot/src/platform/thinking/common/thinkingUtils.ts getThinkingDeltaId() only returns a value for cot_id/reasoning_opaque/signature — plain reasoning_content/reasoning/thinking text with none of those never yields an id, matching the report for SGLang/vLLM.
- **id is optional downstream:** ThinkingDelta (thinking.ts) has a text-only variant with id optional, and CAPIChatMessage = OpenAI.ChatMessage & ThinkingDataInMessage where cot_id is optional — nothing requires an id to send reasoning_content over the wire.
- **related but non-fixing PR:** https://github.com/microsoft/vscode/pull/338874 (open, draft) reworks historical Chat-Completions reasoning replay for a different issue (#338820) and explicitly states in its own description: 'standard Chat Completions deltas without an ID still reproduce independent #338819' — i.e. it does not fix this report.
- **existing test pattern:** extensions/copilot/src/extension/byok/node/test/openAIEndpoint.spec.ts already has an analogous case ('issue #312746: emits reasoning_content on assistant tool-call message...') that a new id-less test could mirror.
