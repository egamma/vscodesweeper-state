# Issue #338415 — remote AH entries in recent folders do not show their remote

[https://github.com/microsoft/vscode/issues/338415](https://github.com/microsoft/vscode/issues/338415)

## Summary

Fresh, team-authored bug report (no comments yet) — traced a plausible root cause in the Windows jump-list code, but the exact fix location needs a design call, so this stays open for planning rather than a confirmed implement.

## Change summary

On Windows, a workspace opened via Agent Host's 'open in editor' shows up in the taskbar jump list without the remote tag that other remote entries get.

## Best solution

Ensure the recent-entry added when a window enters a workspace directly (bypassing the normal open flow) carries a label/description that reflects its remote authority, so `getWindowsJumpListLabel` in workspacesHistoryMainService.ts can render the same remote tag as other entries.

## Plan brief

- **Likely files:** `src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts`, `src/vs/platform/workspaces/electron-main/workspacesManagementMainService.ts`
- **Validation:** Manually verify on Windows: connect to an Agent Host tunnel, open a session workspace via 'open in editor', close that window, then right-click the taskbar icon and confirm the jump list entry shows the same remote tag/description as other remote entries.
- **Behavior:**

  > When a workspace is opened remotely (e.g. via Agent Host's 'open in editor') and its window is later closed, the resulting entry in the Windows taskbar jump list ('Recent Folders & Workspaces') should show the same remote-host tag/decoration that other remote recent entries show, instead of a plain local-looking title/description.
- **Trace:**

  > The recent entry for this scenario is added by `onDidEnterWorkspace` in src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts (around line 80), which calls `addRecentlyOpened` with only `workspace` and `remoteAuthority` — no `label`. `getWindowsJumpListLabel` in the same file only decorates title/description when a `recentLabel` string is present (via `splitRecentLabel`); its URI fallback (`basename` + `renderJumpListPathDescription`) does not add any remote tag regardless of `remoteAuthority`. Other, apparently-tagged remote entries likely get their label from a renderer-side `addRecentlyOpened` call carrying an explicit label (see workspaceCommands.ts:294-314) computed via `ILabelService`, which the main process does not have access to. Do not change the general jump-list layout or the file-scheme path; the fix should focus on how a label/host-name reaches this specific main-process add call, or on adding remote-aware fallback formatting for non-file URIs.
- **Open decisions:**
  - Should the fix compute/pass a labeled recent entry from the renderer side when Agent Host opens a workspace directly, or should the main-process jump-list fallback itself learn to format non-file (remote) URIs with a host/remote tag?
  - If formatting is added in the main process, what should the remote tag look like for an Agent Host authority versus existing SSH/WSL/dev-container authorities — should it reuse the same convention or a new one specific to Agent Host?

## Evidence

- **add path without label:** src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts:80 — `onDidEnterWorkspace` calls `this.addRecentlyOpened([{ workspace: event.window... , remoteAuthority: event.window.remoteAuthority }])` with no `label`, unlike the browser-side add calls (workspaceCommands.ts:301-314) which can carry an explicit label.
- **jump list fallback:** getWindowsJumpListLabel (same file, ~line 491) only uses a decorated title/description when `recentLabel` is present (via splitRecentLabel); otherwise for a URI it falls back to `basename(workspace)` / `renderJumpListPathDescription`, which just does `uri.toString()` for non-file schemes — no remote/host tag is added in that fallback path.
- **no labelService in main:** WorkspacesHistoryMainService (electron-main) has no ILabelService dependency, so it cannot itself compute a nice remote/host label — any such decoration has to arrive already-formed from the renderer or be added via a different mechanism.
