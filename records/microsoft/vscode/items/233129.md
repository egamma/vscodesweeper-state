## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/operation.ts`
- **Validation:** On Windows with git.autorefresh enabled, modify files, commit externally, complete an interactive rebase that edits an earlier commit, then create and stage additional files. After returning focus to VS Code and allowing pending refreshes to finish, compare Source Control with git status --porcelain and verify that Rebasing disappears after the rebase completes, without manual Refresh or Reload Window. Capture Git trace output and repeat until the original failure is reproducible before selecting a regression test.
- **Behavior:**

  > The reported failure leaves Source Control showing an obsolete repository snapshot after command-line commits or completed interactive rebases; subsequent changes may also be missing. Manual Refresh corrects the file groups and rebase indicator. With automatic refresh enabled, those surfaces should converge to the actual repository state once external operations finish and the window is focused. Acceptance must cover both removal of committed changes and appearance of newly staged changes without manual refresh.
- **Trace:**

  > Repository combines working-tree events and DotGitWatcher events in extensions/git/src/repository.ts and routes them through onFileChange, eventuallyUpdateWhenIdleAndWait, and updateWhenIdleAndWait. onFileChange discards events while OperationManager.isIdle() is false; extensions/git/src/operation.ts defines that state using active non-read-only operations. _updateModelState refreshes both rebaseCommit and changed-file groups, explaining why failure to refresh could leave both stale. The thread establishes the symptom and successful manual refresh, but does not establish whether watcher delivery, operation timing, or huge-repository suppression causes this particular case. https://github.com/microsoft/vscode/pull/303205 proposed a related timing change but was withdrawn without merging, so its diagnosis must not be adopted as proven. Preserve existing autorefresh opt-out, focus behavior, and throttling; unrelated Agents-window baseline behavior is outside this report. Begin by reproducing the Windows external-commit/rebase workflow and correlating filesystem events, operation state, and git status execution.
