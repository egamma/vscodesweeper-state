# Issue #338879 — MCP gallery rejects command-allowlisted package servers across registries and managed-settings sources

[https://github.com/microsoft/vscode/issues/338879](https://github.com/microsoft/vscode/issues/338879)

## Summary

Thanks for the detailed report. A VS Code member has already confirmed this as a gallery-admission bug: package-only gallery entries carry no command in the identity checked against a serverCommand allowlist, so they are rejected before installation. It stays open as accepted work.

## Change summary

Gallery MCP servers defined only by packages are blocked by a serverCommand allowlist because the admission identity has no command.

## Best solution

Make gallery admission evaluate package-derived command candidates using the same resolution logic as installation, then recheck the final resolved configuration before execution. Deny precedence must be kept, and a match for one candidate must not authorize a different command or endpoint.

## Plan brief

- **Likely files:** `src/vs/platform/mcp/common/allowedMcpServersService.ts`
- **Validation:** Unit tests asserting that a package-only gallery server whose resolved command matches an allowed serverCommand is admitted, and that a non-matching or denied one is blocked.
- **Behavior:**

  > A gallery MCP server defined only by packages can be installed when its resolved launch command matches a serverCommand allowlist entry. Non-matching candidates and denied entries stay blocked. A match on one package or remote candidate must not authorize a different resolved command or endpoint. The final configuration is rechecked before execution. This should work for default and custom registries, and for file-delivered and server-delivered managed settings.
- **Trace:**

  > The gallery branch of AllowedMcpServersService.toIdentity() in src/vs/platform/mcp/common/allowedMcpServersService.ts supplies only name and first remote URL, per comment 1; I did not re-trace this in the checkout. The uncertainty starts at how to reuse the install-time package-to-command resolution without a second approximation. Do not change runtime name validation (https://github.com/microsoft/vscode/issues/341730) or matcher semantics (issue 341800 per comment 2).
- **Open decisions:**
  - When a server has multiple package or remote candidates, is it admitted if any candidate matches the allowlist, or must all of them match?
  - How should candidates with unresolved inputs or variables be treated at gallery time: blocked, or admitted and rechecked at execution?
