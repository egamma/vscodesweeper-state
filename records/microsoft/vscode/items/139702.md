# Issue #139702 — file://// URL not recognised

[https://github.com/microsoft/vscode/issues/139702](https://github.com/microsoft/vscode/issues/139702)

## Summary

VS Code's URI parser intentionally follows RFC 3986 §3.3, which forbids paths beginning with '//' when no authority component is present. The reporter acknowledges the RFC forbids this and requests a non-standard extension — this is by design.

## Change summary

Request to support non-standard `file:////path` URIs (four slashes) which RFC 3986 explicitly forbids.

## Best solution

Keep current behavior: `_validateUri` in `src/vs/base/common/uri.ts` correctly implements RFC 3986 §3.3. Users should use `file:///proc/...` (three slashes) since consecutive slashes in paths are normalized by the OS anyway. The non-standard extension isn't worth the spec violation.

- **Proposed comment:**

  > Thanks for the discussion. VS Code's URI parser intentionally follows RFC 3986 §3.3, which states that when no authority component is present, the path cannot begin with `//`. This is implemented in `src/vs/base/common/uri.ts` and is working as designed.
  > 
  > The correct form is `file:///proc/sys/fs/inotify/max_user_instances` (three slashes: two for `file://` authority separator + one for the absolute path root). On Linux, consecutive slashes in filesystem paths are equivalent to a single slash, so `//proc/...` and `/proc/...` resolve identically — no information is lost by using the RFC-compliant form.
  > 
  > Closing as by-design since this follows the RFC specification.
