# Issue #333255 — Show organization-wide AI credit pool consumption in Copilot usage indicator

[https://github.com/microsoft/vscode/issues/333255](https://github.com/microsoft/vscode/issues/333255)

## Summary

A real gap remains: current VS Code shows an Enterprise user's own consumed credits but has no organization-wide consumption value. This Backlog Candidates request should remain open while the team decides the permission, privacy, and billing semantics for exposing that shared-pool data.

## Change summary

Show authorized Copilot Business or Enterprise users how much of their organization's shared monthly AI credit pool has been consumed alongside their personal usage.

## Best solution

Have the Copilot service provide an authorized organization-level usage snapshot, then present it as a clearly separate Organization row in the existing usage dashboard. VS Code should not derive the aggregate client-side and should disclose only the exact value or coarse range permitted for the signed-in user.

- **Validation:** Extend the chat status dashboard tests with authorized exact organization usage, authorized coarse-range usage if selected, and unavailable or unauthorized organization data; verify personal usage remains unchanged and organization details appear only in the permitted cases.
- **Behavior:**

  > For a Copilot Business or Enterprise account, the usage dashboard distinguishes the signed-in user's consumed credits from the organization's shared-pool consumption when the service authorizes that information. The organization display uses the disclosure granularity selected by maintainers and clearly identifies its billing period or reset. When organization data is unavailable or unauthorized, VS Code must not infer it from personal usage or expose stale or private billing information. Existing personal, capped-quota, and non-organization displays remain unchanged.
- **Trace:**

  > Current quota state is represented by `IQuotaSnapshot` in src/vs/workbench/services/chat/common/chatEntitlementService.ts; its `creditsUsed` field is explicitly personal aggregate consumption without a denominator. `ChatStatusDashboard.render` and `createCreditsUsedIndicator` in src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts render that value, with Enterprise coverage in src/vs/workbench/contrib/chat/test/browser/chatStatusDashboard.test.ts. The extension-host quota bridge runs through extensions/copilot/src/platform/chat/common/chatQuotaService.ts and extensions/copilot/src/extension/chat/vscode-node/chatQuota.contribution.ts, but no organization-wide snapshot is currently modeled. The uncertainty starts at the upstream authorization and disclosure contract, not at the existing personal-usage rendering. Keep personal usage semantics, individual budget percentages, and quota-exhaustion behavior outside the scope of this request. Related personal-usage work is documented at https://github.com/microsoft/vscode/issues/319589.
- **Open decisions:**
  - Which signed-in organization members may see organization-wide consumption, and should unauthorized users see no row or an explicit unavailable state?
  - Should permitted users see exact used and total credits, a percentage, or only coarse consumption bands?
  - Does organization consumption represent only the included monthly pool, or also paid overage, and how should that distinction appear?
  - When the organization snapshot is delayed or stale, should the dashboard show its age, retain the previous value, or hide it?
