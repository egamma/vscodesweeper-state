# Issue #332501 — Agent Host session load causes child-chat subscription storm and memory spike

[https://github.com/microsoft/vscode/issues/332501](https://github.com/microsoft/vscode/issues/332501)

## Summary

Team-authored regression report with a precise bisect and root cause, and current main still contains the unguarded `externalChanges.get()` call in `_isFileInSessionScope` — no fix has landed yet, so this stays open and already carries the right milestone/labels.

## Change summary

Reopening a large Agent Host session with many subagent chats triggers a synchronous, unobserved `.get()` read on the session's `externalChanges` observable for every visible changed-file editor, creating a subscribe/unsubscribe storm across all child-chat observables and a large memory/AHP-traffic spike.

## Best solution

Fix `AgentFeedbackService._isFileInSessionScope` (src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts, line ~569) so the external-changes scope check doesn't force recomputation of the unobserved `externalChanges` derived — e.g. read it without triggering a full subscribe/unsubscribe cycle, or cache/memoize the check — restoring the pre-#331079 baseline (~43 MB / ~85 child snapshots) while keeping the new external-changes scope semantics.
