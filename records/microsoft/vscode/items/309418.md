# Issue #309418 — Confirmation Carousel: Displays empty dirname for some directories on Windows

[https://github.com/microsoft/vscode/issues/309418](https://github.com/microsoft/vscode/issues/309418)

## Summary

The Windows drive-root defect remains source-reproducible on current main: confirmation file widgets derive visible text from a basename that is empty for `C:\`, while their hover uses the non-empty full URI label. This should remain open as a bounded chat UI bug.

## Change summary

Show a visible directory label in confirmation-carousel file widgets when the referenced Windows directory is a drive root.

## Best solution

Ensure an inline file widget always has a meaningful visible and accessible label for URI roots, while preserving basename labels for ordinary files and directories.

## Evidence

- **source reproduction:** In `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatInlineAnchorWidget.ts`, `InlineAnchorWidget` sets `filePathLabel` from `ILabelService.getUriBasenameLabel(location.uri)`, but sets the hover from `getUriLabel(location.uri, { relative: true })`; this directly explains the empty visible label with a populated tooltip.
- **root cause:** `src/vs/workbench/services/label/common/labelService.ts` implements `getUriBasenameLabel` by applying `win32.basename` to the formatted label. A Windows drive-root label such as `C:\` therefore produces an empty basename.
