# Issue #195449 — Restore fullscreen windows to the correct displays

[https://github.com/microsoft/vscode/issues/195449](https://github.com/microsoft/vscode/issues/195449)

## Summary

Keep open: current source explicitly attempts to restore fullscreen windows to their saved physical display, but the reported macOS failure cannot be confirmed through source inspection alone. The supplied steps suffice to retest; the suggested duplicate concerns Mission Control desktop placement rather than the same physical-monitor symptom.

## Change summary

A workspace quit in fullscreen on a secondary macOS display reopens fullscreen on the primary display.

## Best solution

Make fullscreen restoration reliably preserve the physical display when it remains connected. First reproduce the monitor mismatch and distinguish incorrect saved display information from a native fullscreen transition overriding the requested position.

- **Behavior:**

  > A fullscreen workspace should reopen fullscreen on the same physical display when that display remains available. The report describes restoration onto the primary display instead, with a temporary workaround involving a quit in windowed mode on the secondary display. Acceptance requires repeating the quit/relaunch sequence on a dual-monitor macOS setup without losing display placement. Restoring an exact Mission Control Space is a separate requirement.
- **Trace:**

  > CodeWindow.serializeWindowState in src/vs/platform/windows/electron-main/windowImpl.ts records the display matching the fullscreen bounds, while retaining prior windowed dimensions and coordinates. The trace does not establish whether the reported failure comes from persisted state, display matching, or Electron/macOS fullscreen placement.
