# Issue #335708 — Web: Use AI Features fails because chat setup command is not registered

[https://github.com/microsoft/vscode/issues/335708](https://github.com/microsoft/vscode/issues/335708)

## Summary

Real regression, traced in source: on pure web without a remote connection VS Code intentionally disables Copilot setup, but a status-bar/menu affordance still offers 'Use AI Features', which invokes the now-unregistered `workbench.action.chat.triggerSetup` command — a genuine UI/registration mismatch, not something to close.

## Change summary

In VS Code Insiders for the Web (no remote connection), selecting 'Use AI Features' from the Copilot status menu errors because the setup command isn't registered, and there's no sign-in affordance in the Accounts menu either.

## Best solution

In src/vs/workbench/services/chat/common/chatEntitlementService.ts (the isWeb && !remoteAuthority && !isSessionsWindow branch, ~line 453) Copilot is deliberately hidden by setting the `chatSetupHidden` context key; the surface that still shows 'Use AI Features' (chatStatusEntry.ts's getSetupEntryProps/menu, or an equivalent Accounts-menu contribution) needs to respect that same hidden state so no dead action is exposed — or, if serverless web setup should actually work, ChatSetupContribution's early-return in chatSetupContributions.ts needs to register the command regardless.

## Evidence

- **web gating sets hidden:** src/vs/workbench/services/chat/common/chatEntitlementService.ts line 453-456: `if ((isWeb && !environmentService.remoteAuthority && !environmentService.isSessionsWindow)) { ChatEntitlementContextKeys.Setup.hidden.bindTo(...).set(true); return; }` — Copilot is intentionally disabled on serverless web, and `this.context`/`this.requests` are left undefined.
- **command registration bails out:** src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts lines 91-95: `ChatSetupContribution` returns early (never calling `registerActions`, which registers `CHAT_SETUP_ACTION_ID` = 'workbench.action.chat.triggerSetup') whenever `chatEntitlementService.context`/`requests` are undefined — exactly the state produced by the web gating above.
- **status bar still offers the action:** src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusEntry.ts getSetupEntryProps() (line 395) sets `command: CHAT_SETUP_ACTION_ID` for the Copilot status item; this is the likely source of the non-functional 'Use AI Features' entry the reporter clicked.
