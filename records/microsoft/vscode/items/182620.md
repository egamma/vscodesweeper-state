# Issue #182620 — Changes lost in python notebook on undo

[https://github.com/microsoft/vscode/issues/182620](https://github.com/microsoft/vscode/issues/182620)

## Summary

Verified duplicate: the older open issue tracks the same notebook undo behavior, where undoing cell creation unexpectedly removes populated cells and recovery is unclear.

## Change summary

Pressing Cmd+Z while the notebook, but not a cell editor, has focus can remove a populated cell without an apparent recovery path.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/139197 and make structural notebook undo safer there, either by excluding cell creation from the undo stack or providing a reliable, discoverable recovery path.

- **current source:** src/vs/workbench/contrib/notebook/browser/contrib/undoRedo/notebookUndoRedo.ts routes Undo to NotebookViewModel.undo() whenever the notebook editor has focus; src/vs/workbench/contrib/notebook/test/browser/contrib/notebookUndoRedo.test.ts confirms that undoing a cell insertion removes the cell.
- **remaining gap:** Commit 694b6ab0348587195dcb6974b4d2c788e4915646 only prevents notebook undo when focus is outside the notebook; it does not change structural undo while the notebook itself is focused.
