# Issue #318786 — Unable to resolve workspace folder in ExtHost sessions (ENOPRO: No file system provider found for resource 'unknown:/')

[https://github.com/microsoft/vscode/issues/318786](https://github.com/microsoft/vscode/issues/318786)

## Summary

Still present on main: ExtHost sessions fall back to `unknown:///` when no repo URI is available, and that scheme has no file-system provider, causing the ENOPRO error. A partial mitigation landed (graceful fallback in `openNewSession`), but the root cause — `unknown:///` being assigned as the workspace folder — remains.

## Change summary

ExtHost sessions assign `unknown:///` as the workspace folder URI when no repo URI is available, causing ENOPRO errors and an inaccessible file system.

## Best solution

Fix the root cause in the ExtHost sessions path: either register a no-op file-system provider for the `unknown` scheme, or prevent `unknown:///` from being used as a resolvable workspace folder in `copilotChatSessionsProvider.ts` (line ~1289) and the downstream consumers. The graceful fallback in `sessionsService.ts` (commit 1d2c9c20a35) only masks the error for `openNewSession`; other code paths still hit the unresolvable URI.
