# Issue #350169 — Canvas activation can be remembered for the wrong folder location after overlapping or failed switches

[https://github.com/microsoft/vscode/issues/350169](https://github.com/microsoft/vscode/issues/350169)

## Summary

Keep open: current source still allows canvas activation to be attributed to the requested folder location rather than the location owning the displayed editors. The assigned 1.149.0 release milestone also bars a cleanup close.

## Change summary

Preserve each folder location's canvas activation state across overlapping switches and failed working-set restoration.

## Best solution

Make canvas restoration consume authoritative folder-location switch ownership, including failure and fallback boundaries, while preserving ordinary round trips, hidden-chat behavior, and source-control working sets. Include the maintainer-requested Quick Open consumer when designing the shared contract.

- **Overlapping-switch ownership mismatch:** src/vs/workbench/contrib/canvases/electron-browser/canvasService.ts:146-152 sets settledLocation from the current workspace folder whenever generic working-set application ends. If C is requested while B is applying, this records C although B's editors were applied. rememberActiveCanvasesByLocation then uses that incorrect leaving location when recording activation.
- **Failure path confirmed from source:** src/vs/workbench/browser/parts/editor/editorParts.ts:883-909 emits the applying=false event in finally even when a missing working-set state returns false before closing any editor. CanvasService therefore advances settledLocation to B while A's canvas remains open; the subsequent empty fallback can save A's activation under B.
- **Authoritative owner already differs:** src/vs/workbench/contrib/workspaces/browser/folderLocationWorkingSets.ts captures leaving and entering in switchWorkingSet and advances its private owner only after tryApply succeeds. Its failed-target/empty-fallback sequence is not represented by CanvasService's generic completion listener.
