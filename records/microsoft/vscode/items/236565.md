# Issue #236565 — [CLI] code devcontainer as subcommand for code CLI

[https://github.com/microsoft/vscode/issues/236565](https://github.com/microsoft/vscode/issues/236565)

## Summary

This remains a well-supported feature request, but the requested CLI-to-Dev-Container workflow is owned by the VS Code Dev Containers extension. It should be moved to microsoft/vscode-remote-release and consolidated with the older open issue that tracks the same observable capability.

## Change summary

Add a VS Code CLI command or option that opens a local or WSL project directly in its Dev Container without first opening a local window and invoking Reopen in Container.

## Best solution

Move this issue to microsoft/vscode-remote-release and consolidate its 116 upvotes and WSL-specific workflow evidence into https://github.com/microsoft/vscode-remote-release/issues/2133. The Dev Containers implementation should provide a supported one-step CLI entry point while preserving normal rebuild, reopen, and failed-build recovery behavior.
