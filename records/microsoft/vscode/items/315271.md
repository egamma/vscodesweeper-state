# Issue #315271 — Deleting git worktrees closes the git repository, which cannot be reopened without closing the folder

[https://github.com/microsoft/vscode/issues/315271](https://github.com/microsoft/vscode/issues/315271)

## Summary

Keep open: current source contains a worktree-deletion path that disposes the main repository's SCM provider while retaining its model entry, preventing reopening. This conclusively explains the reported symptom for an unopened worktree nested inside the main repository, although the reporter did not specify their worktree location.

## Change summary

Deleting a Git worktree should not remove the surviving main repository from Source Control or require closing its workspace folder to recover.

## Best solution

Make worktree-deletion cleanup affect only the repository representing the deleted worktree, preserving the main repository's SCM provider and operational state. Cover nested worktrees that have not been opened separately, alongside normal opened-worktree deletion.
