# Issue #349931 — Manage remote environments: Offer restart distribution in more menu

[https://github.com/microsoft/vscode/issues/349931](https://github.com/microsoft/vscode/issues/349931)

## Summary

Keep open: Restart Distribution exists in troubleshooting but is missing from More Actions. The Available status deliberately includes stopped distributions that Connect can start, so changing that presentation needs a product decision.

## Change summary

Expose Restart Distribution in the environment's More Actions menu and clarify the status of terminated WSL distributions.

## Best solution

Make WSL recovery discoverable directly from More Actions while retaining the existing restart confirmation. Decide whether stopped-but-startable distributions should retain Available status or receive a distinct presentation without disabling Connect.

- **Behavior:**

  > WSL environment recovery should be discoverable directly from More Actions rather than requiring navigation into troubleshooting. Restart must retain its warning that all programs in the distribution will stop. A terminated distribution's status should communicate the agreed meaning consistently with its Connect hover, and Connect must remain usable to start an installed distribution. Acceptance covers menu eligibility, cancellation, successful restart, and unchanged non-WSL menus.
- **Trace:**

  > In src/vs/workbench/contrib/sessions/providers/remoteAgentHost/browser/, remotesTable.ts constructs the overflow menu without a restart action, while remoteEnvironmentDetails.ts dispatches the existing troubleshooting restart to RemotesModel.restartWSLDistribution. That model operation already confirms, terminates, refreshes, and reconnects. computeAvailability marks stopped installed WSL distributions offline with startsOnConnect true; getRemoteStatusGroup then treats their connection eligibility as Available, and remotesWidget.test.ts explicitly expects this. remoteTroubleshooting.ts also restricts restart eligibility, so exposing it for stopped distributions would change observable behavior. Preserve Connect's ability to start distributions and the existing destructive-operation warning; unrelated connection types are outside scope. The report arose from https://github.com/microsoft/vscode/issues/349553.
- **Open decisions:**
  - Should stopped-but-startable WSL distributions remain Available, appear Offline, or receive a distinct stopped presentation?
