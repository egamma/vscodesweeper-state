# Issue #239502 — Allow quotes in default link provider for source locations

[https://github.com/microsoft/vscode/issues/239502](https://github.com/microsoft/vscode/issues/239502)

## Summary

Keep this accepted request open: current Output link detection still excludes the closing quote before numeric line/column suffixes. Terminal detection has a quote-trimming path that may already cover the reported example, but that does not satisfy the requested Output support.

## Change summary

Recognize MLIR source locations formatted as "/path/to/file.c":row:col and navigate to the indicated line and column.

## Best solution

Support the quoted-path numeric location format in Output link detection while preserving existing formats and workspace restrictions. Verify the same example through terminal detection and opening before deciding whether any terminal change remains necessary.

- **Behavior:**

  > MLIR emits source locations with quotes around the filename and numeric coordinates outside those quotes. Following a recognized location should open the actual file at the specified row and column, without treating the delimiting quotes as filename characters. Output links for files within the existing supported workspace scope should retain the coordinates. The same simple location should work in an editor terminal, and existing unquoted formats should remain unchanged.
- **Trace:**

  > OutputLinkComputer.createPatterns in src/vs/workbench/contrib/output/common/outputLinkComputer.ts excludes quotes from the path and permits numeric coordinates only immediately after that path; the closing quote therefore prevents the location captures used by detectLinks to construct the URI fragment. Existing acceptance patterns are exercised in src/vs/workbench/contrib/output/test/browser/outputLinkProvider.test.ts. Terminal parsing is separate: detectLinksViaSuffix records the opening quote as a prefix, TerminalLocalLinkDetector.detect tries a candidate with the trailing quote removed, and TerminalLocalFileLinkOpener consumes the retained suffix for selection. Source inspection establishes the Output gap but suggests that the terminal example may already work; that end-to-end behavior was not executed. Preserve Output's workspace-folder scope, terminal filesystem validation, and existing supported location formats. The requested behavior and reporter clarification are recorded at https://github.com/microsoft/vscode/issues/239502; the older https://github.com/microsoft/vscode/issues/236602 concerns a different HTTP-URL symptom.
