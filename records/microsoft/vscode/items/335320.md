# Issue #335320 — Using /btw opens a split chat instead of the subchat treatment

[https://github.com/microsoft/vscode/issues/335320](https://github.com/microsoft/vscode/issues/335320)

## Summary

Confirmed in source: `/btw` goes through `openAndSendSideChat` in sideChatOrchestration.ts, which calls `splitChatToSide` (a side-by-side split group), while the sessions UI has a distinct subagent/subchat visual pattern (tabs + indented list entry) driven by `openChatToSide` and the `chatSubagentOpenChat.ts` opener registry. The report accurately describes a real UI inconsistency between these two code paths; deciding which treatment `/btw` should use is a product/design call, so this stays open for a maintainer.

## Change summary

`/btw` opens a side-by-side split chat and reuses the parent's loading indicator, instead of using the sessions app's subchat presentation (tabs, indented child entry, distinct loading state).

## Best solution

A sessions/agents maintainer should decide whether `/btw` side chats should render via the existing subagent/subchat visual pattern (chatSubagentOpenChat.ts, openSubagentChat.ts) instead of `splitChatToSide` in sideChatOrchestration.ts, and if so, unify the two chat-opening code paths.
