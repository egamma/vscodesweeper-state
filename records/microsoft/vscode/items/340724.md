# Issue #340724 — Support Alt+click to open links beside the originating panel

[https://github.com/microsoft/vscode/issues/340724](https://github.com/microsoft/vscode/issues/340724)

## Summary

Team-authored feature request that is not yet implemented. Markdown link activation drops the mouse event before the handler runs, so the modifier cannot reach the opener. The change spans several layers and needs a design decision first, so this stays open.

## Change summary

Alt+click on a link (for example in a chat response) should open the target in an editor group beside the clicked view, leaving the source visible.

## Best solution

Pass the modifier state from markdown link activation through the action handler to IOpenerService.open({ openToSide }), then handle it in the contributed openers (the GitHub issue editor, webview and custom editors).

## Plan brief

- **Likely files:** `src/vs/base/browser/markdownRenderer.ts`, `src/vs/editor/browser/services/openerService.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`
- **Validation:** A unit test that activates a rendered markdown link with altKey set and asserts the opener is called with openToSide: true, and is not called with it for a plain click.
- **Behavior:**

  > Alt+click on a link in a chat response opens the target in an editor group beside the group or panel that contains the clicked link. The source stays visible and unchanged. A plain click behaves exactly as before. External-only targets are unaffected. An adjacent group is reused instead of creating a new split on every click.
- **Trace:**

  > The base markdown renderer's activateLink (src/vs/base/browser/markdownRenderer.ts, around line 553) receives the StandardMouseEvent but calls options.actionHandler(href, mdStr) without it, so the Alt key is lost. IOpenerService.open already supports openToSide (opener.ts:22), but contributed openers (webview or custom editors such as the GitHub issue editor) must also honour it. Placement must be relative to the group hosting the clicked view, not the last active group. Do not change ordinary-click behavior or the base-layer API shape beyond what is needed to carry the modifier.
- **Open decisions:**
  - Should the modifier be Alt alone, or follow the editor convention of Ctrl/Cmd+Alt for open to side?
  - When the chat is in a panel or sidebar rather than an editor group, which group is beside it, and should an existing adjacent group be reused?

## Evidence

- **link activation drops the event:** src/vs/base/browser/markdownRenderer.ts activateLink calls options.actionHandler?.(href, mdStr) without passing the mouse event, so the Alt key state is lost before the handler runs.
- **opener support exists:** ia IOpenerService options already include openToSide (src/vs/platform/opener/common/opener.ts:22) and the opener service honours it (src/vs/editor/browser/services/openerService.ts:100 and 279). Only the link-to-opener plumbing is missing.
- **precedent:** Other chat parts already map Alt to side opening: chatMultiDiffContentPart.ts:132 and chatSubagentOpenChat.ts:391.
