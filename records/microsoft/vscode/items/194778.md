# Issue #194778 — Productivity idea, related to selecting proposed options by keyboard number 1-9

[https://github.com/microsoft/vscode/issues/194778](https://github.com/microsoft/vscode/issues/194778)

## Summary

Keep this accepted feature request open: current suggestion commands do not provide numbered 1–9 selection, and the request has 21 community upvotes. The remaining product decision is how numeric shortcuts should interact with ordinary typing.

## Change summary

Display numbers beside code-completion suggestions and allow selecting the corresponding suggestion with keyboard keys 1–9.

## Best solution

Provide an optional, discoverable numbered-selection interaction in the editor suggestion widget, preserving ordinary digit entry and existing completion navigation. Settle shortcut activation and whether selection also inserts the completion before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/suggest/browser/suggestController.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidget.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/suggest/test/browser/suggestController.test.ts`
- **Validation:** After agreeing the interaction, add targeted suggest-controller tests for selecting numbered entries, unavailable indices, hidden-widget behavior, and preservation of ordinary digit entry. Manually verify that displayed numbers match their targets after filtering and scrolling, and that existing arrow, Tab, and Enter interactions remain unchanged.
- **Behavior:**

  > Users can identify completion suggestions by displayed numbers and target a corresponding entry through a keyboard shortcut instead of repeated arrow navigation. The numbering must accurately identify the targeted suggestion as the list filters or scrolls. Ordinary digit entry and existing completion navigation must remain available. Acceptance checks should cover all supported indices, fewer than nine suggestions, a hidden widget, and the agreed selection-versus-insertion behavior.
- **Trace:**

  > SuggestController in src/vs/editor/contrib/suggest/browser/suggestController.ts accepts the currently focused item and exposes relative, page, first, and last navigation, but no indexed-selection command. SuggestWidget in src/vs/editor/contrib/suggest/browser/suggestWidget.ts owns list focus and navigates with focusNext, focusPrevious, focusFirst, and focusLast. ItemRenderer in src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts creates completion rows without number hints; editor.suggest.selectionMode in src/vs/editor/common/config/editorOptions.ts concerns initial focus rather than shortcuts. This establishes a missing interaction, not a broken existing behavior. Preserve completion ranking, provider contracts, insertion semantics outside the new interaction, and current keyboard navigation. https://github.com/microsoft/vscode/issues/194778 supplies the requested behavior and accepted community demand, but does not settle how digit typing is distinguished from numbered selection.
- **Open decisions:**
  - Should numbered selection use bare digits in an explicitly activated mode, or modifier-key shortcuts that preserve ordinary digit typing while suggestions are visible?
  - Should a numbered shortcut only focus its suggestion, or immediately accept and insert it?
  - Should numbers identify the first nine entries in the filtered list, or the currently visible entries when the user scrolls?
