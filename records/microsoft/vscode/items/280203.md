# Issue #280203 — agent doesn't try re-calling failed MCP

[https://github.com/microsoft/vscode/issues/280203](https://github.com/microsoft/vscode/issues/280203)

## Summary

Valid feature request acknowledged by a team member (connor4312) who scoped the approach to tools with `idempotentHint` or `readOnlyHint`. The related PR #280215 was closed without merging, and no equivalent retry logic for failed MCP tools has landed on main. Milestone is On Deck, so it stays open awaiting implementation.

## Change summary

When an MCP tool call fails and the server is manually restarted, the agent should retry the failed MCP call instead of ending the conversation.

## Best solution

Implement MCP tool call retry logic scoped to tools declaring `idempotentHint` or `readOnlyHint`, as connor4312 outlined. The tool-calling loop in `src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts` (and possibly the Copilot extension's `toolCallingLoop.ts`) would need to detect MCP server recovery and re-issue the failed call rather than treating the failure as terminal.
