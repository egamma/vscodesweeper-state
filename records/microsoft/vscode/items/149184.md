# Issue #149184 — Allow drag-and-dropping text across panels of split editor (and possibly even to other applications)

[https://github.com/microsoft/vscode/issues/149184](https://github.com/microsoft/vscode/issues/149184)

## Summary

The current selection-drag implementation still operates within the source editor. An older open issue covers dragging across split editors, but does not clearly own this report's additional request to drag text out to other applications, so a full-scope duplicate close is not established.

## Change summary

Allow selected text to be moved between split editor panes, with optional outbound dragging to other applications.

## Best solution

Coordinate cross-pane support with https://github.com/microsoft/vscode/issues/32387 and establish whether outbound application dragging belongs in the same capability or a separate follow-up. Preserve normal within-editor move/copy behavior and undo semantics.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/mouseHandler.ts`, `src/vs/editor/contrib/dnd/browser/dnd.ts`, `src/vs/editor/contrib/dnd/browser/dragAndDropCommand.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts`
- **Validation:** Manually select text and drag it between horizontal and vertical split panes containing both the same document and different documents. Verify destination feedback, cut-and-paste-equivalent movement, modifier-copy behavior, cancellation, and undo without lost or duplicated text. If outbound export is included, verify VS-Code-to-another-text-editor dragging on Linux and the other supported desktop platforms; retain existing incoming and within-editor drops.
- **Behavior:**

  > A selected text range can be dragged from one split editor pane to another, with an insertion indicator in the destination and a result equivalent to cut and paste. Existing within-pane movement and modifier-based copying remain available. Cancellation must leave the text unchanged, and successful transfers must have coherent undo behavior. The reporter additionally requests dragging selected text into other applications; that scope must be settled before defining its acceptance criteria.
- **Trace:**

  > DragAndDropController in src/vs/editor/contrib/dnd/browser/dnd.ts stores _dragSelection per editor and executes DragAndDropCommand against that editor. MouseHandler in src/vs/editor/browser/controller/mouseHandler.ts monitors the source editor's pointer interaction and emits its internal drag/drop events; the inspected path does not publish a native text drag payload. DropIntoEditorController in src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts receives native DataTransfer drops, which is a separate incoming path. The uncertainty starts at coordinating source and destination edits, undo, and any native outbound transfer contract. Preserve existing within-editor interactions and incoming drops. Coordinate the split-editor requirement with https://github.com/microsoft/vscode/issues/32387, whose discussion explicitly records the same limitation; its verified scope does not clearly include exporting text to other applications.
- **Open decisions:**
  - Should this work include outbound dragging into other applications, or deliver cross-pane movement first with outbound export tracked separately?
  - If outbound dragging is included, should dropping into another application copy the selection by default or remove it from VS Code after a successful move?

## Evidence

- **Existing capability and remaining gap:** src/vs/editor/common/config/editorOptions.ts registers editor.dragAndDrop with default true. In src/vs/editor/contrib/dnd/browser/dnd.ts, DragAndDropController retains a selection on its own _editor and executes DragAndDropCommand on that same editor; it does not transfer the selection to another editor or application.
- **Current drag path:** src/vs/editor/browser/controller/mouseHandler.ts starts pointer monitoring on the source editor's viewLinesDomNode and emits mouse-drag/drop events through its own view controller. This is the internal selection-drag path, not a native dragstart/DataTransfer export.
- **Incoming drops are not outbound support:** src/vs/editor/contrib/dropOrPasteInto/browser/dropIntoEditorController.ts handles editor.onDropIntoEditor and consumes an incoming DragEvent.dataTransfer. That receiving capability does not make editor selections draggable into other panes or applications.
- **Older overlapping issue verified:** https://github.com/microsoft/vscode/issues/32387 is currently open and was created on 2017-08-12. Its discussion explicitly reports inability to drag selected text across splits and between windows: https://github.com/microsoft/vscode/issues/32387#issuecomment-820495248. This matches the central split-pane symptom, but outbound dragging to other applications is not explicitly established as its scope.
- **Prior consolidation precedent:** https://github.com/microsoft/vscode/issues/44844 reported selected-text dragging between split tabs and was closed as a duplicate of the older issue: https://github.com/microsoft/vscode/issues/44844#issuecomment-423638228. This supports consolidating the split-pane portion, not assuming coverage of the additional application-export behavior.
- **Direction of external transfer matters:** https://github.com/microsoft/vscode/issues/42094 concerned dragging text from other applications into VS Code; a maintainer confirmed that receiving support existed in https://github.com/microsoft/vscode/issues/42094#issuecomment-1204504210. This report already distinguishes successful Firefox-to-VS-Code drops from missing outbound drops.
- **Demand and accepted scope:** The issue is accepted into Backlog, has five body upvotes, and two later commenters request the capability. Neither age nor the incoming-drop implementation establishes that its requested work is completed.
