# Issue #331257 — Extra text in migrated session title

[https://github.com/microsoft/vscode/issues/331257](https://github.com/microsoft/vscode/issues/331257)

## Summary

Real, freshly-filed bug from a team member with direct screenshots showing stray `<reminder>` scaffolding and a rendered newline in migrated session titles; the reporter themselves is still unsure why the second line only shows after migration, so this needs more diagnosis before any close, and as a team-authored bug it can only be closed with a cited fix commit anyway.

## Change summary

After migrating a legacy Copilot CLI session into the Agent Host, the session's title shows SDK-injected `<reminder>` text and a newline (so only the first line appears in the sessions list), and it's unclear whether a pre-existing custom title survives migration.

## Best solution

Trace why a migrated/adopted session's title bypasses the normal title pipeline: `AgentHostSessionTitleController._normalizeTitle` (src/vs/platform/agentHost/node/agentHostSessionTitleController.ts) trims/collapses whitespace and `mapSessionEvents.ts`'s `stripPromptScaffolding` (src/vs/platform/agentHost/node/copilot/mapSessionEvents.ts:67-83) strips `<reminder>`/`<userRequest>` blocks for live sessions, but the legacy-adoption path in `CopilotAgent.ensureChatAdopted` / `_readExtensionHostCliCustomTitle` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2981-3029) reads and carries over `customTitle` raw, and any auto-generated title for a migrated session may not be going through the same normalization/strip step — that mismatch is the most likely place the extra reminder text and newline are surviving into the migrated title.
