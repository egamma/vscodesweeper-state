# Issue #349873 — Windows: a PowerShell hook's exit code 2 is reported as 1, so a hook warning becomes a failure

[https://github.com/microsoft/vscode/issues/349873](https://github.com/microsoft/vscode/issues/349873)

## Summary

Keep open as an upstream Copilot runtime dependency. A maintainer confirms that PowerShell loses the hook's exit code before VS Code receives it; the runtime fix remains the prerequisite.

## Change summary

Preserve native hook exit codes through PowerShell so exit code 2 produces a warning instead of a failure and retry.

## Best solution

The Copilot runtime should preserve the hook command's exit status, then VS Code should consume the corrected runtime and verify the reported Windows warning flow without repeating the prompt.
