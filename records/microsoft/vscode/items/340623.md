## Summary

Thanks for the report. The workload is confirmed on main: 24 batches of 12 shell calls, run with OTel on and off. Nothing has changed it, so the issue stays open. The work is team-authored test-runtime tuning, and the right workload size depends on what the original regression needs.

## Change summary

Cut the Windows runtime of the two OTel concurrency integration tests without losing real shell execution, concurrent logging, both modes, or regression detection.

## Best solution

Reduce batchCount and/or batchSize in copilotOtel.integrationTest.ts to the smallest workload that still reproduces the original lock-stall regression. Confirm this by running the smaller workload against a build with the regression, ideally on Windows CI.
