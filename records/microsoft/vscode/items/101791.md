# Issue #101791 — Allow DAP progress notifications to be shown more prominently than the status bar

[https://github.com/microsoft/vscode/issues/101791](https://github.com/microsoft/vscode/issues/101791)

## Summary

This remains a valid, well-supported debug UX request: DAP progress is surfaced, but the protocol and workbench do not let an adapter distinguish low-priority background work from user-blocking operations that merit a prominent notification. The Backlog milestone, debug/feature-request labels, and 51 upvotes all support keeping it open.

## Change summary

Allow debug adapters to request a more prominent presentation for user-initiated DAP progress, such as launching, building, or hot reload, while retaining subtle status-bar presentation for background work.

## Best solution

Define a DAP-compatible presentation hint for progress-start events and have VS Code's debug progress handling map that hint to an existing prominent notification/progress surface, while preserving the current subtle default for adapters that omit it.

  > The report originates from Dart/Flutter replacing custom notifications with standard DAP progress events and losing the prominent presentation users relied on. The issue is already accepted into the debug Backlog and has 51 upvotes. Preserve the current default for existing adapters and do not make all debug progress globally prominent; the uncertainty begins at the public hint shape and how prominent progress should behave in the notification UI.
