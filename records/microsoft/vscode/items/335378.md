## Evidence

- **source-confirmed race:** On current main, ClaudeAgentSession.completeClientToolCall in src/vs/platform/agentHost/node/claude/claudeAgentSession.ts calls PendingRequestRegistry.respond. In src/vs/platform/agentHost/common/pendingRequestRegistry.ts, respond returns false and discards the value when the SDK handler has not registered yet, leaving a later register call unresolved.
- **canonical issue:** https://github.com/microsoft/vscode/issues/322990 is older, open, labeled bug and agent-host, and its discussion identifies the same observable browser-tool hang and the same dropped source=client-dispatch completion race. A later confirmation reproduces it in VS Code 1.139.0 on local macOS.
- **open fix:** https://github.com/microsoft/vscode/pull/330730 is open and changes the Claude completion path to respondOrBuffer, with a regression test where the result arrives before the SDK registers. Its description explicitly fixes https://github.com/microsoft/vscode/issues/322990.
- **distinct remaining defect:** This report additionally records steering messages reaching Claude but disappearing from the UI when subscription to claude:/<session>/changeset/turn/<request-id> fails with Resource not found. That separate rendering/subscription behavior is not covered by https://github.com/microsoft/vscode/issues/322990 or https://github.com/microsoft/vscode/pull/330730.
