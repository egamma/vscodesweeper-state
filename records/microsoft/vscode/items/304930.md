# Issue #304930 — Sensitive Data Masking

[https://github.com/microsoft/vscode/issues/304930](https://github.com/microsoft/vscode/issues/304930)

## Summary

This accepted Backlog request has 26 community upvotes, and current main still provides whole-file exclusion rather than selective local masking. The older related exclusion request does not absorb the distinct requirement to retain useful context while redacting sensitive paths and spans.

## Change summary

Mask user-defined sensitive filenames and content spans locally across every Copilot prompt and tool-context path, with visibility into what was redacted.

## Best solution

Define one enforceable model-bound data policy covering explicit attachments, inferred active-editor context, searches, inline chat, and agent tool results, while preserving the unmasked data in the local UI. Design the precedence and failure semantics as a security boundary before implementing the individual integrations.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`, `extensions/copilot/src/platform/ignore/common/ignoreService.ts`, `extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts`, `extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts`, `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliPromptResolver.ts`, `extensions/copilot/src/extension/tools/node/toolUtils.ts`, `extensions/copilot/src/extension/log/vscode-node/requestLogTree.ts`
- **Validation:** Add targeted Vitest contract coverage for classic chat, inferred active-editor context, Copilot CLI attachments, and tool reads proving matched values and paths are absent from the model-bound payload while unmatched text and the local UI reference remain unchanged; include invalid-pattern and overlapping-match cases.
- **Behavior:**

  > Users can define local sensitive-path and sensitive-content rules, and matching data is masked before any model-bound Copilot request regardless of whether it came from an explicit attachment, the active editor, inline chat, search, or an agent tool. The local chat UI continues to identify the real resource, while request diagnostics disclose that masking occurred without recording the secret value. Multiple and overlapping findings must have deterministic output, and unmatched context must remain intact. Acceptance requires contract tests demonstrating that the original sensitive path or value never appears in each supported outbound context path.
- **Trace:**

  > Current exclusion is a whole-resource boolean exposed by `IIgnoreService.isCopilotIgnored` in extensions/copilot/src/platform/ignore/common/ignoreService.ts and implemented for `.copilotignore` and remote rules in extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts. Classic chat constructs active-editor context in `IDocumentContext.inferDocumentContext` and removes ignored references in `ChatParticipantRequestHandler.sanitizeVariables`; Copilot CLI independently turns references into SDK attachments in `CopilotCLIPromptResolver`; tool reads enforce exclusion through extensions/copilot/src/extension/tools/node/toolUtils.ts. This confirms the selective-redaction gap and shows that no single existing serialization boundary currently covers every requested source. The boundary is model-bound context only: local documents, editor buffers, displayed filenames, and persisted source files must remain unchanged. https://github.com/microsoft/vscode/issues/278829 remains related but tracks full exclusion rather than partial masking.
- **Open decisions:**
  - May a workspace-controlled `.copilot-sensitive` file weaken or replace user or organization-level rules, or must higher-trust rules always remain additive and non-overridable?
  - When a configured pattern is invalid, too expensive, or cannot be evaluated, should the request fail closed, omit the affected resource, or proceed with a visible warning?
  - Must content replacement preserve exact character offsets by matching the original span length, or should it use a fixed semantic token even when subsequent offsets change?
