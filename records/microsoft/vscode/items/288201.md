# Issue #288201 — "add ___ to chat" doesn't work when chat hasn't been previously opened

[https://github.com/microsoft/vscode/issues/288201](https://github.com/microsoft/vscode/issues/288201)

## Summary

Keep open: chat initialization and input synchronization have evolved, but the current source still exposes a potential first-open attachment race rather than proving this resolved. The original reload-and-attach steps are sufficient to retest; no additional reporter information is needed.

## Change summary

Attachments added through an “Add to Chat” action should survive initial chat session restoration after a window reload.

## Best solution

Ensure attachments explicitly added while the chat view first opens reach the initialized session without being overwritten by restored input state. Verify the initial-reveal sequence while preserving normal session-switch and persisted-draft behavior.
