# Issue #318766 — Chat input: Look into number of dropdowns and interactive vs. plan mode

[https://github.com/microsoft/vscode/issues/318766](https://github.com/microsoft/vscode/issues/318766)

## Summary

Keep this team-authored UX exploration open. Current main contains an experimental partial consolidation of Agent Host mode and permissions, but the broader question of dropdown count and the relationship between native chat modes and Interactive/Plan session modes remains an explicit maintainer design concern.

## Change summary

Consolidate the chat input's dropdowns and clarify how Interactive and Plan modes relate across native chat and Agent Host sessions.

## Best solution

Establish one coherent chat-input model for selecting agents, interaction modes, and permissions, with Plan and Interactive consistently discoverable across native and Agent Host sessions. The existing experimental combined mode-and-permissions picker is a useful implementation candidate, but maintainers should decide which concepts share a control and which remain distinct.

## Evidence

- **partial implementation on main:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostModePickerPresentation.ts implements a combined Agent Mode and Permissions popup, while src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts gates it to compatible Copilot Agent Host sessions through `shouldCombineModeAndPermissions`.
- **still experimental:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.experimentalModePermissionsPicker`, defaults it off for stable builds, and describes it specifically as a combined mode-and-permissions picker rather than a complete consolidation of all chat-input concepts.
- **remaining mode split:** src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts still has separate native and custom-agent-target mode paths, while Agent Host session modes are rendered through agentHostChatInputPicker.ts; current source therefore retains distinct mode models and picker paths.
- **maintainer direction:** In https://github.com/microsoft/vscode/issues/328256#issuecomment-5136649083, a maintainer identified the confusion as Plan moving to a different picker and stated that the UX should be iterated. That later issue is closed and points back to this broader, older tracker rather than replacing it.
