# Issue #227365 — Issue Reporter should include warning if VSCode is not pure

[https://github.com/microsoft/vscode/issues/227365](https://github.com/microsoft/vscode/issues/227365)

## Summary

Keep open: current main records an impure installation in diagnostics and the generated issue body, but it does not present an explicit warning in the Issue Reporter UI. This team-authored Backlog request also has explicit maintainer support, so a judgment close is barred.

## Change summary

Show a warning in the Issue Reporter when the integrity service detects that the VS Code installation has been modified.

## Best solution

Surface a clear, non-blocking warning in the Issue Reporter when `isInstallationPure` is false while retaining the existing `Modes: Unsupported` and system-information evidence for maintainers.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/issue/browser/issueReporterOverlay.ts`, `src/vs/workbench/contrib/issue/electron-browser/issueReporterEditorPane.ts`, `src/vs/workbench/contrib/issue/test/browser/issueReporterOverlay.test.ts`, `src/vs/workbench/contrib/issue/test/browser/testReporterModel.test.ts`
- **Validation:** Add targeted Issue Reporter browser tests asserting that an impure installation produces the chosen warning behavior, a pure installation does not, and submitted issue text still contains `Modes: Unsupported`; run those two issue-reporter test suites.
- **Behavior:**

  > When the integrity check reports a modified installation, the Issue Reporter should clearly communicate that state instead of leaving it only in expanded diagnostics or generated issue text. Pure installations must not show the warning. The existing `Modes: Unsupported` marker and integrity evidence in submitted reports must remain available to maintainers.
- **Trace:**

  > `NativeIssueService` in `src/vs/workbench/contrib/issue/electron-browser/issueService.ts` already obtains `IIntegrityService.isPure()` and publishes `isInstallationPure`; `IssueReporterEditorPane` forwards the asynchronously resolved value to the overlay model. `IssueReporterModel.serialize()` converts a false value into `Modes: Unsupported`, while `IssueReporterOverlay` currently uses it only for the System Info row and has no explicit warning path. The integrity service already owns the global corrupt-installation notification, so this work should remain scoped to the Issue Reporter and must not alter checksum coverage or global integrity prompting. The motivating extension-modification case is https://github.com/microsoft/vscode/issues/227023.
- **Open decisions:**
  - Should the requested warning be visible to the reporter in the Issue Reporter UI, or is the intended contract limited to stronger integrity evidence in the submitted issue body?
