# Issue #337582 — Show /btw chats as children of their main session in the Sessions tree

[https://github.com/microsoft/vscode/issues/337582](https://github.com/microsoft/vscode/issues/337582)

## Summary

Reasonable Sessions-window UX request, but it's brand new (0 days old, 1 upvote, no maintainer input) and its premise doesn't fully match current architecture, so it should stay open for more traction and design input rather than being closed or fast-tracked.

## Change summary

Nest a `/btw` side chat under its originating session in the Sessions tree instead of letting it appear disconnected.

## Best solution

Clarify the actual gap first: side chats are already excluded from the sessions-list chat rows (`getSessionListChats` in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts filters out `ChatOriginKind.SideChat`) and are surfaced only inside the originating session's own tab strip, so today they don't show as separate top-level Sessions-tree entries at all — the real ask may be making an in-progress side chat's activity visible from the session row (e.g. via the header/Conversations affordance) rather than literal tree nesting; a maintainer should pin down the desired visual before implementation.
