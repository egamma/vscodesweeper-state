# Issue #280071 — Markdown code segments in chat disappear after editing last prompt.

[https://github.com/microsoft/vscode/issues/280071](https://github.com/microsoft/vscode/issues/280071)

## Summary

The intermittent blank-code-block rendering defect was fixed on main by forcing code-block editors to render again after attachment to the DOM. This directly addresses the reported behavior where resizing or otherwise triggering layout made the missing content reappear.

## Change summary

Editing or canceling an edited chat prompt could leave Markdown code-block editors visible but empty until the chat panel was resized.

## Best solution

Keep the deferred post-attachment editor render added in commit 78cb1a6ccd703198d87c91be689827c41a13feb0; it prevents detached-DOM render passes from leaving chat code blocks blank.

## Evidence

- **confirmed symptom:** The reporter reproduced blank code-block contents in VS Code 1.114.0 and found that horizontally resizing the chat panel repainted them; another user independently confirmed the behavior in https://github.com/microsoft/vscode/issues/280071.
- **root cause and fix:** https://github.com/microsoft/vscode/pull/308414 identifies the root cause as CodeBlockPart render passes being dropped while the editor DOM is detached, matching content that reappears after resize or hover. Commit https://github.com/microsoft/vscode/commit/78cb1a6ccd703198d87c91be689827c41a13feb0 adds `this.editor.renderAsync(true)` at the end of `CodeBlockPart.render()` so view lines are painted after attachment.
- **current main:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts retains the deferred `editor.renderAsync(true)` call and documents that setText/setLanguage/layout renders can otherwise be dropped while the element is disconnected.
