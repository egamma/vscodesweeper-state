# Issue #166296 — Notebook "variable provider" API

[https://github.com/microsoft/vscode/issues/166296](https://github.com/microsoft/vscode/issues/166296)

## Summary

Keep open as an API proposal tracking issue: the notebook variable provider is implemented, but remains behind proposed-API gating rather than finalized in the stable extension API. The api-proposal protection applies regardless of the landed implementation.

## Change summary

Expose a notebook variable provider API so extensions can supply variables and their children to the built-in variable viewer.

## Best solution

Retain this issue for API-owner review and eventual finalization or explicit abandonment of the proposed contract. Coordinate any notebook-independent provider design with https://github.com/microsoft/vscode/issues/204031 without treating that separate request as a replacement for this API proposal.

## Evidence

- **Proposal remains experimental:** src/vscode-dts/vscode.proposed.notebookVariableProvider.d.ts declares NotebookController.variableProvider, NotebookVariableProvider, NotebookVariablesRequestKind, VariablesResult, and Variable. These declarations are absent from stable src/vscode-dts/vscode.d.ts.
- **Runtime proposal gate:** src/vs/workbench/api/common/extHostNotebookKernels.ts:236-242 calls checkProposedApiEnabled(extension, 'notebookVariableProvider') before registering the provider and forwarding notebook-specific change events. Its $provideVariables method invokes the provider with a NotebookDocument and supports retrieving child variables. The central capability exists, but is not a finalized public API.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/166296#issuecomment-1802891887 records agreement to expose a simple provider API rather than require extensions to implement a synthetic debug adapter. The current proposed declaration follows that provider model.
- **Notebook scope confirmed:** https://github.com/microsoft/vscode/issues/166296#issuecomment-2494768663 explains that native REPL integration still uses a backing notebook and NotebookController; it does not establish a notebook-independent variable provider.
- **Related issue is not a canonical duplicate:** Verified https://github.com/microsoft/vscode/issues/204031 is open and specifically requests variable providers for non-notebook REPL and test processes. It is newer than this re-reviewed issue and addresses a distinct scope extension, not completion of this API proposal. Searches for variable-provider and notebook-variable API issues found no verified older canonical owning this proposal.
- **Hard keep-open rule:** The issue carries api-proposal and was authored by a MEMBER. Proposed implementation does not complete API tracking; finalization or abandonment remains an API-owner decision.
