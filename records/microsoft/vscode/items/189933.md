# Issue #189933 — Focusing another window while dragging a file from the FileExplorer causes a TreeError

[https://github.com/microsoft/vscode/issues/189933](https://github.com/microsoft/vscode/issues/189933)

## Summary

The exact failure path remains on current main: returning from another window can leave a stale dragged ExplorerItem, and the drop handler queries its tree collapse state without checking that the node still exists. The resulting TreeError is caught and displayed as the reported error dialog, so this should remain open for a bounded drag-and-drop fix.

## Change summary

Switching windows during an Explorer file drag can show a TreeError dialog when the file is released back over the Explorer.

## Best solution

Make Explorer drag-and-drop tolerate a dragged source that is temporarily absent from the rendered async tree after a focus transition, without showing an error dialog or changing normal move/copy behavior.
