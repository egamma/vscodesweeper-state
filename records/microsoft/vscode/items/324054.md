# Issue #324054 — Copilot agent continues after file edit before user selects Keep or Undo

[https://github.com/microsoft/vscode/issues/324054](https://github.com/microsoft/vscode/issues/324054)

## Summary

The issue remains valid on current main: Keep/Undo controls the user's acceptance of an edit, but tool completion and the agent loop are intentionally decoupled from that decision, allowing subsequent commands and edits while confirmation remains pending.

## Change summary

Pause the Copilot agent after a file edit until the user resolves the pending Keep or Undo decision, or avoid presenting that decision as workflow-blocking.

## Best solution

Define and implement consistent confirmation semantics in the core chat editing pipeline: either make pending edit review block subsequent agent tool execution, or redesign the UI and wording so Keep/Undo clearly represents reversible post-application review rather than approval.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing`
- **Validation:** Add or extend a chat editing integration test that leaves an edit in pending Keep/Undo state and verifies the chosen contract: either the next agent tool invocation is withheld until review resolves, or the UI no longer represents the state as pending approval.
- **Behavior:**

  > After an agent edits a file and VS Code displays Keep/Undo, the product must communicate and enforce one coherent contract. If this is approval, no later agent command or edit may start until the user chooses Keep or Undo. If it is reversible post-application review, the UI must make clear that the agent may continue and that Undo can affect a sequence of dependent edits. Acceptance should cover both Keep and Undo while another tool call is queued.
- **Trace:**

  > The report concerns the boundary between agent tool completion and chat edit review in src/vs/workbench/contrib/chat/browser/chatEditing. Current main treats the edit tool's completion as separate from the later Keep/Undo review state, so the agent loop can continue while the UI still exposes unresolved review controls. This is core Copilot Chat behavior, not an external extension issue. Preserve ordinary edit application and rollback behavior; the unresolved point is the public interaction contract between review state and subsequent tool execution.
- **Open decisions:**
  - Should Keep/Undo be a blocking approval gate that pauses all subsequent agent tool execution, or a non-blocking reversible review state?
  - If review remains non-blocking, should Undo revert only the selected edit or all later dependent edits in the same agent turn?
