# Issue #345421 — Secondary button background color is transparent

[https://github.com/microsoft/vscode/issues/345421](https://github.com/microsoft/vscode/issues/345421)

## Summary

Dark Modern's transparent secondary button background is an explicit design change, not a missing theme value. The screenshot's CSS fallback cannot replace a defined transparent color; overlapping controls need an appropriate container background.

## Change summary

Restore an opaque secondary button background so underlying content does not show through.

## Best solution

Preserve Dark Modern's intentional secondary button styling. Floating custom controls should provide their own surface background rather than assume button.secondaryBackground is opaque; users preferring filled buttons can override that token through workbench.colorCustomizations.

- **Fit:** aligned
- **Reason:** Keeping secondary controls readable and visually consistent fits the core UX direction, without requiring every theme to use opaque button fills.
- **Evidence:** Values: Simple, uniform UI and UI interactions; durable theme: Workbench & core UX.

  > Thanks for the report. Dark Modern intentionally sets `button.secondaryBackground` to transparent; this changed in https://github.com/microsoft/vscode/pull/280457. A defined transparent color does not activate a CSS `var()` fallback, so floating controls need a background on their containing surface, as in your workaround. If you prefer filled secondary buttons, you can override `button.secondaryBackground` in `workbench.colorCustomizations`.

## Evidence

- **Intentional styling change:** https://github.com/microsoft/vscode/commit/dccac3528532c9ecff35a8625c44404499796d26, from https://github.com/microsoft/vscode/pull/280457, explicitly changes Dark Modern's button.secondaryBackground from #313131 to #00000000 and adjusts its hover background. The commit describes updating secondary button styles, establishing deliberate design rather than an accidentally absent value.
- **Current checkout:** extensions/theme-defaults/themes/dark_modern.json:19 still explicitly defines button.secondaryBackground as #00000000. src/vs/platform/theme/common/colors/inputColors.ts registers a separate default based on listHoverBackground, and Light Modern specifies #E5E5E5; transparency is not a universally missing secondary button token.
- **Reporter screenshots:** The screenshots attached to https://github.com/microsoft/vscode/issues/345421 show a Cancel button overlapping property rows and a .property-editor button.cancel rule using var(--vscode-button-secondaryBackground, ...). Because the token is defined as transparent, the var() fallback is not selected. This explains why supplying a container background changes the result.
- **Related issue is distinct:** https://github.com/microsoft/vscode/issues/291850 concerns an unassigned secondary button background and links https://github.com/microsoft/vscode/pull/291859. That differs from this report's explicitly assigned transparent Dark Modern color; neither it nor the general https://github.com/microsoft/vscode/issues/295783 theme tracker establishes a duplicate.
- **Existing customization:** src/vs/workbench/services/themes/common/workbenchThemeService.ts defines workbench.colorCustomizations, which permits overriding the registered button.secondaryBackground color without changing the theme's default design.
