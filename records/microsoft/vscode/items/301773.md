# Issue #301773 — Search: Mode reuseEditor doesn't take you to the correct line in the source code editor after you make changes in the source code editor

[https://github.com/microsoft/vscode/issues/301773](https://github.com/microsoft/vscode/issues/301773)

## Summary

The stale-line navigation path remains in current source: Search Editor navigation uses line numbers captured by the search, without accounting for subsequent source edits. The report provides sufficient steps, and no verified canonical or fixing commit was identified.

## Change summary

Search Editor results navigate to outdated source positions after lines are inserted or deleted in the source editor.

## Best solution

Make Search Editor navigation remain accurate for surviving matches after source edits, with explicit behavior for deleted matches. Coordinate the workbench search-result snapshot and built-in search-result definition provider without silently navigating to unrelated code.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/searchEditor/browser/searchEditor.ts`, `src/vs/workbench/contrib/searchEditor/browser/searchEditorSerialization.ts`, `extensions/search-result/src/extension.ts`
- **Validation:** In two editor groups, search a C file containing separated foo() calls, delete lines before surviving matches, and verify double-click navigation still reaches the corresponding surviving calls; repeat with insertions. Add automated coverage for coordinate changes and the agreed deleted-match behavior.
- **Behavior:**

  > Search Editor navigation becomes inaccurate after the underlying source is edited. After inserting or deleting lines before a surviving match, double-clicking its result should reach that match rather than unrelated code. Define what users see when the selected match itself has been deleted. Verify both active-group and side-group navigation.
- **Trace:**

  > SearchEditor.registerEditorListeners dispatches double-click navigation to definition commands. The built-in provider in extensions/search-result/src/extension.ts obtains target coordinates from parseSearchResults, which reads literal line numbers serialized by matchToSearchResultFormat. No source-edit translation exists on this path, so reparsing the unchanged results still yields old coordinates. The workbench owns search execution and snapshot replacement, while the extension owns location resolution; the trace does not establish a shared live-position lifecycle. Preserve existing path resolution, context-line navigation, and truncated-line column handling. The report is https://github.com/microsoft/vscode/issues/301773.
- **Open decisions:**
  - When an edit deletes the match represented by a result row, should navigation invalidate that row, refresh the results, or navigate to the former location with an explicit stale-result indication?
