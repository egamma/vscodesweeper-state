# Issue #339693 — Agents - clicking "Number of Runs" closes the dialog

[https://github.com/microsoft/vscode/issues/339693](https://github.com/microsoft/vscode/issues/339693)

## Summary

Team-authored bug report with a video repro, filed hours ago — stays open per the team-authored protection rules regardless, but it's also a real, source-confirmed defect: the model-picker popup's blur handler dismisses the whole dialog when the nested 'Number of Runs' select-box dropdown opens.

## Change summary

In the Agents compare-models dialog, clicking the 'Number of Runs' dropdown closes the whole picker instead of opening the count selector.

## Best solution

Extend the focus-blur exclusion in TabbedActionListWidget.show() to also treat focus inside `.monaco-select-box-dropdown-container` as still-within-the-popup, matching the existing exclusions for `.action-widget-hover` and `.action-list-submenu-panel`.

  > When the Agents compare-models dialog is in the 'Attempts' step with a single model selected, clicking the 'Number of Runs' control must open its dropdown of run counts without closing the surrounding model-picker popup. Acceptance: a focus/blur simulation moving focus into the select-box's dropdown container does not trigger the popup's hide().
- **Trace:**

  > The count control is a `SelectBox` (src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts:585-595) rendered inside the picker's footer. Opening it moves DOM focus into `.monaco-select-box-dropdown-container` (src/vs/base/browser/ui/selectBox/selectBoxCustom.ts:202), which is rendered via its own ContextView and lives outside the picker's `container` element. The picker's blur handler in src/vs/platform/actionWidget/browser/tabbedActionListWidget.ts:770-779 calls `hide()` on any blur unless the new active element is inside `.action-widget-hover` or `.action-list-submenu-panel` — it has no exception for the select-box dropdown, so the whole popup closes. Boundary: only the exclusion check in that blur handler should change; do not alter the SelectBox component, the count derivation logic, or other dismissal paths (Escape, click-outside-the-whole-picker) which are intentional and covered by existing tests.

- **rendering:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts:585-595 renders that count as a `SelectBox` inside the workflow footer, with its own `contextViewLayer`.
- **select-box dropdown DOM:** src/vs/base/browser/ui/selectBox/selectBoxCustom.ts:202-568 shows the SelectBox opens its own `.monaco-select-box-dropdown-container` via a separate `showSelectDropDown` context view, appended outside the picker's own container.
- **root cause:** src/vs/platform/actionWidget/browser/tabbedActionListWidget.ts:766-779: the popup's `focusTracker.onDidBlur` calls `hide()` whenever focus leaves `container`, excluding only `.action-widget-hover` and `.action-list-submenu-panel` — it does not exclude `.monaco-select-box-dropdown-container`, so opening the count dropdown blurs and immediately closes the whole picker.
- **existing test scaffold:** src/vs/platform/actionWidget/test/browser/tabbedActionListWidget.test.ts already has focus/blur dismissal tests (e.g. 'Escape from a Details radio dismisses the entire popup') that a new test for this exclusion could follow.
