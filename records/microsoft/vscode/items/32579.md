# Issue #32579 — [themes] Disable Italic Option Feature Request

[https://github.com/microsoft/vscode/issues/32579](https://github.com/microsoft/vscode/issues/32579)

## Summary

This remains the canonical, strongly supported request for a global way to suppress theme-provided italics. Current TextMate and semantic-token customizations require separate, incomplete workarounds, so the central accessibility gap remains.

## Change summary

Add an editor setting that globally disables italic token styling supplied by color themes.

## Best solution

Provide a documented token-font-style control that consistently suppresses italics across both TextMate and semantic token rendering, with explicit precedence over theme rules. A maintainer should first settle whether the public contract remains italic-specific or generalizes to bold, underline, and strikethrough.

## Plan brief

- **Likely files:** `src/vs/workbench/services/themes/common/themeConfiguration.ts`, `src/vs/workbench/services/themes/common/workbenchThemeService.ts`, `src/vs/workbench/services/themes/common/colorThemeData.ts`, `src/vs/workbench/services/themes/test/node/tokenStyleResolving.test.ts`
- **Validation:** Extend the `Themes - TokenStyleResolving` suite and run `scripts/test.sh --grep "Themes - TokenStyleResolving"`; verify the selected global control removes italics from both TextMate and semantic tokens while leaving colors and non-disabled styles unchanged.
- **Behavior:**

  > Users can disable theme-provided italic styling globally without enumerating token scopes or maintaining parallel workarounds. The control applies consistently to TextMate and semantic tokens across themes and languages. Token colors and font styles not selected for suppression remain unchanged, and changing themes does not restore the suppressed style.
- **Trace:**

  > Theme settings are registered in src/vs/workbench/services/themes/common/themeConfiguration.ts and typed in src/vs/workbench/services/themes/common/workbenchThemeService.ts. ColorThemeData in src/vs/workbench/services/themes/common/colorThemeData.ts maintains separate customTokenColors and customSemanticTokenRules paths; the existing test coverage is in src/vs/workbench/services/themes/test/node/tokenStyleResolving.test.ts. TextMate selector parsing in src/vs/workbench/services/themes/common/textMateScopeMatcher.ts does not accept `*`, while semantic selectors do, explaining why the documented workarounds only partially cover the request. Keep the scope to editor token presentation: the terminal rendering report in the thread is a separate font-packaging scenario, and https://github.com/microsoft/vscode/issues/25895 separately tracks synthesized italic faces.
- **Open decisions:**
  - Should the public setting disable only italics as originally requested, or expose a general contract for independently suppressing italic, bold, underline, and strikethrough styles?
  - Should global suppression always win over both theme rules and explicit user token customizations, or may a more specific user-authored rule re-enable a suppressed style?

## Evidence

- **remaining source gap:** src/vs/workbench/services/themes/common/themeConfiguration.ts registers editor.tokenColorCustomizations and editor.semanticTokenColorCustomizations, but no global token font-style suppression setting.
- **separate rendering paths:** src/vs/workbench/services/themes/common/colorThemeData.ts applies custom TextMate rules through customTokenColors and semantic rules through customSemanticTokenRules, requiring users to configure both systems.
- **TextMate wildcard limitation:** src/vs/workbench/services/themes/common/textMateScopeMatcher.ts tokenizes only named scope identifiers; `*` is not a valid selector token. Consequently, the commonly suggested wildcard TextMate rule cannot provide a true global override.
- **partial existing capability:** A semantic rule such as `"*": { "italic": false }` can suppress semantic-token italics, while TextMate tokens still require enumerating scopes. Comments from 2023–2026 confirm that combining both workarounds remains theme- and language-dependent.
- **canonical issue:** https://github.com/microsoft/vscode/issues/92396 and https://github.com/microsoft/vscode/issues/41464 were closed in favor of this issue; no older open issue found owns the same global theme-style request.
- **distinct related issue:** https://github.com/microsoft/vscode/issues/25895 is older and open, but concerns Chromium synthesizing an italic font face when a font lacks one, not disabling theme-authored token italics.
- **community demand:** The issue is in the Backlog with 150 community upvotes, well above the 20-upvote promotion threshold, and includes accessibility feedback from visually impaired users.
