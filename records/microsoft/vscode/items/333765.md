# Issue #333765 — Bundled Anthropic BYOK rejects stable vscode.lm User-only requests with empty system block

[https://github.com/microsoft/vscode/issues/333765](https://github.com/microsoft/vscode/issues/333765)

## Summary

Still present on current main: apiMessageToAnthropicMessage always returns a system TextBlockParam initialized to an empty string, and AnthropicLMProvider sends `system: [system]` unconditionally, so any stable vscode.lm request with only User/Assistant messages is rejected by Anthropic with 400 'system: text content blocks must be non-empty'. Worth fixing in the BYOK Anthropic provider with a regression test.

## Change summary

The bundled Anthropic BYOK provider sends an empty system text block for User-only requests, so third-party vscode.lm consumers get an upstream HTTP 400.

## Best solution

Omit the `system` parameter in AnthropicLMProvider's MessageCreateParams when the converted system block has empty text and no cache_control, so User/Assistant-only requests from the stable vscode.lm API reach the model.

## Evidence

- **defect on main:** extensions/copilot/src/extension/byok/common/anthropicMessageConverter.ts: apiMessageToAnthropicMessage initializes `const systemMessage: TextBlockParam = { type: 'text', text: '' }` and returns it unchanged when no System-role message is present (verified at main 3b486b1ff92ac032974c6f589e7d5a46fe486067).
