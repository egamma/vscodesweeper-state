# Issue #333765 — Bundled Anthropic BYOK rejects stable vscode.lm User-only requests with empty system block

[https://github.com/microsoft/vscode/issues/333765](https://github.com/microsoft/vscode/issues/333765)

## Summary

Confirmed real defect in the bundled Anthropic BYOK provider: it always sends an Anthropic `system` block even when it's empty, which Anthropic's API rejects with a 400. This breaks every third-party `vscode.lm` request that uses only stable User/Assistant roles.

## Change summary

Bundled Anthropic BYOK provider sends `system: [{type:'text', text:''}]` even when no system message was provided, causing Anthropic to reject the request with a 400 invalid_request_error.

## Best solution

In extensions/copilot/src/extension/byok/vscode-node/anthropicProvider.ts, only include `system` in the request params when `system.text` is non-empty or `system.cache_control` is set (as the reporter suggests), consistent with how apiMessageToAnthropicMessage in anthropicMessageConverter.ts builds the system block.
