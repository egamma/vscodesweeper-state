# Issue #327787 — Export and Import chat currently not retain session info after opening and closing

[https://github.com/microsoft/vscode/issues/327787](https://github.com/microsoft/vscode/issues/327787)

## Summary

Keep open as a feature request: exported chats remain snapshots, and reopening the file does not reconnect to the conversation continued after import. The older related reports do not cover the same observable symptom closely enough to justify a duplicate close on this re-review.

## Change summary

Offer a choice between importing a separate conversation and reopening or updating the same conversation so subsequent turns remain accessible through the saved file.

## Best solution

Define an explicit resume-versus-copy workflow in the chat import/export surface, with clear persistence semantics and no unexpected overwriting of exported snapshots. Reopening a saved chat should offer an understandable way to recover its continued conversation without searching the session list.

## Evidence

- **existing export/import behavior:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts registers workbench.action.chat.export and workbench.action.chat.import. Export writes model.toExport() once; import reads the selected file and opens a session from its parsed data, without retaining the input file URI as a backing file or presenting an update-versus-copy choice.
- **session identity gap:** In src/vs/workbench/contrib/chat/common/model/chatModel.ts:3489–3550, toExport() serializes the conversation but omits sessionId; toJSON() adds that identity for internal persistence. Reimporting the exported snapshot therefore cannot identify and reconnect to the previously continued session through this format.
- **partial workaround:** workbench.action.chat.forkConversation in src/vs/workbench/contrib/chat/browser/actions/chatForkActions.ts creates a separate session with a new sessionId. Forking and manually exporting again can preserve continued work, but neither supplies the requested same-session reopening or update choice.
