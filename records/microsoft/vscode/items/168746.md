# Issue #168746 — [Accessibility] Word wrap does not work in diff view (F7 and Shift+F7)

[https://github.com/microsoft/vscode/issues/168746](https://github.com/microsoft/vscode/issues/168746)

## Summary

Keep open: the F7/Shift+F7 Accessible Diff Viewer still renders unwrapped logical lines independently of editor wrapping settings. Maintainers accepted this accessibility improvement, and no verified canonical or covering implementation was found.

## Change summary

Honor word wrapping when reviewing diff chunks through the F7/Shift+F7 Accessible Diff Viewer.

## Best solution

Provide wrapping in the custom Accessible Diff Viewer, with screen-reader navigation that makes long changed lines easier to review. Establish whether wrapped segments should be separately navigable and announced, while preserving diff identity and navigation between changes.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/components/accessibleDiffViewer.ts`, `src/vs/editor/browser/widget/diffEditor/components/accessibleDiffViewer.css`
- **Validation:** With screen-reader mode enabled, open a diff containing long added, deleted, and unchanged lines; enable wrapping and enter the Accessible Diff Viewer using F7 and Shift+F7. Verify wrapping at narrow and wide viewport widths, agreed navigation and announcement behavior for wrapped content, and unchanged next/previous-difference, Enter-to-reveal, and Escape-to-close behavior. Repeat with wrapping disabled.
- **Behavior:**

  > The F7/Shift+F7 Accessible Diff Viewer currently ignores word wrapping, making long changed lines difficult to review with a screen reader. Enabled wrapping should make that content reviewable within the available width, including original deleted lines and modified added lines. Acceptance must cover both visible wrapping and the agreed screen-reader navigation and announcement behavior; wrapping disabled and navigation between diff chunks must retain their existing behavior.
- **Trace:**

  > AccessibleDiffViewerNext/Prev in src/vs/editor/browser/widget/diffEditor/commands.ts delegate through DiffEditorWidget to AccessibleDiffViewer in components/accessibleDiffViewer.ts. Its View uses custom DOM rendering rather than a wrapped editor view model: _createRow() assigns a single line-height cell, _getLineHtml() renders the complete model line, and accessibleDiffViewer.css uses white-space: pre. Existing diffEditor.wordWrap handling in components/diffEditorEditors.ts affects the ordinary subeditors, not this custom rendering. ViewModel navigation and row aria-labels operate on whole logical lines, so the uncertainty is how wrapping should affect screen-reader review, not whether ordinary editor wrapping already solves the request. Preserve change grouping, original/modified line attribution, focus restoration, and reveal/staging selection semantics. Maintainer acceptance is recorded at https://github.com/microsoft/vscode/issues/168746#issuecomment-1346469429, and the long-line accessibility impact is confirmed at https://github.com/microsoft/vscode/issues/172606#issuecomment-1418506717.
- **Open decisions:**
  - Should wrapped segments become separately navigable and announced in the Accessible Diff Viewer, or should wrapping remain visual while arrow navigation and announcements continue to operate on complete logical lines?

## Evidence

- **Maintainer acceptance:** https://github.com/microsoft/vscode/issues/168746#issuecomment-1346469429 explicitly identifies F7/Shift+F7 as custom diff-chunk rendering and calls wrapping support a good feature request, distinct from ordinary editor wrapping.
- **Current command path:** src/vs/editor/browser/widget/diffEditor/commands.ts:205–248 maps F7 and Shift+F7 to editor.action.accessibleDiffViewer.next and editor.action.accessibleDiffViewer.prev. DiffEditorWidget delegates these to AccessibleDiffViewer.next()/prev(), which opens the custom View.
- **Existing capability does not cover the request:** src/vs/editor/common/config/editorConfigurationSchema.ts:257–265 registers diffEditor.wordWrap with off/on/inherit. components/diffEditorEditors.ts applies that option to the ordinary original and modified editors. In contrast, components/accessibleDiffViewer.ts View._createRow() creates a fixed-line-height cell, and _getLineHtml() renders the entire model line without consulting wrapping options; accessibleDiffViewer.css applies white-space: pre and table-row layout.
- **Screen-reader acceptance boundary:** components/accessibleDiffViewer.ts builds one ViewElement per logical source line, navigates those elements through ViewModel.goToNextLine()/goToPreviousLine(), and assigns the complete line content to each row's aria-label. Visual wrapping alone would not necessarily reduce the amount announced or provide navigation through wrapped segments.
- **Related discussion preserves this work:** https://github.com/microsoft/vscode/issues/172606#issuecomment-1418506717 identifies unwrapped long lines in the F7 viewer as cognitively overloading. The maintainer then favored addressing this F7 experience in https://github.com/microsoft/vscode/issues/172606#issuecomment-1419006000; that closed issue is not a duplicate canonical.
- **Canonical search:** Open-issue searches for diff wrapping, accessibility wrapping, diff review, and accessible diff found no verified older issue owning this symptom. https://github.com/microsoft/vscode/issues/209648 was inspected: it requests a staging button, not wrapping, and is newer than this re-reviewed report.
