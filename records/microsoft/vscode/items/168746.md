# Issue #168746 — [Accessibility] Word wrap does not work in diff view (F7 and Shift+F7)

[https://github.com/microsoft/vscode/issues/168746](https://github.com/microsoft/vscode/issues/168746)

## Summary

Wrapping remains missing from the F7/Shift+F7 accessible diff viewer, independently of ordinary diff-editor wrapping. Keep this accepted accessibility request open; current source still renders whole logical lines, and the related issues do not own the same request.

## Change summary

Support word wrapping when reviewing long diff lines through F7/Shift+F7 with a screen reader.

## Best solution

Provide wrapping in the accessible diff viewer that makes long changes manageable for screen reader users, using existing wrapping preferences where appropriate. Settle how wrapped portions are navigated and announced before implementing; visual wrapping alone would leave the current whole-line announcements unchanged.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/components/accessibleDiffViewer.ts`, `src/vs/editor/browser/widget/diffEditor/components/accessibleDiffViewer.css`
- **Validation:** Open a diff containing long inserted, deleted, and unchanged lines with screen reader mode enabled; compare wrapping off and on, enter with F7 and Shift+F7, resize the viewport, and navigate with Up/Down. Verify the chosen wrapped-content reading behavior, complete content access, correct original/modified line identification, and unchanged difference navigation and Escape focus restoration.
- **Behavior:**

  > The F7/Shift+F7 accessible diff viewer currently ignores wrapping preferences and presents long logical lines as single navigation and announcement units. Screen reader users should be able to review these changes in manageable wrapped portions when wrapping is enabled. Acceptance must cover inserted, deleted, and unchanged content, viewport resizing, and the selected screen reader navigation behavior. Turning wrapping off must retain the existing unwrapped experience, and difference navigation and return-to-editor behavior must remain intact.
- **Trace:**

  > The F7 and Shift+F7 actions in src/vs/editor/browser/widget/diffEditor/commands.ts reach AccessibleDiffViewer through DiffEditorWidget. In components/accessibleDiffViewer.ts, View._createRow assigns a single-line cell height and an aria-label containing the complete logical line; View._getLineHtml renders that complete line, while ViewModel navigation advances between logical-line entries. The companion CSS uses white-space: pre, and the viewer does not consume the diffWordWrap configuration used by DiffEditorEditors. This establishes that ordinary diffEditor.wordWrap support does not satisfy this request. The uncertainty is the accessible reading contract: visual wrapping alone does not shorten the whole-line aria-label or change arrow navigation. Keep ordinary diff-editor wrapping and unrelated word-diff navigation outside the scope; https://github.com/microsoft/vscode/issues/166472 addresses a distinct capability.
- **Open decisions:**
  - When wrapping is enabled, should Up/Down navigate and announce individual wrapped portions, or retain one focusable and announced unit per logical line?
