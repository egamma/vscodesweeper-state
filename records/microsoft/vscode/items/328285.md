# Issue #328285 — Agents window: make GitHub issue filing reliable across MCP, browser, and CLI

[https://github.com/microsoft/vscode/issues/328285](https://github.com/microsoft/vscode/issues/328285)

## Summary

Team-authored report (eleanorjboyd) of a concrete, reproducible failure chain in Agent Host's GitHub tooling: a `command -v gh` PATH check silently fails to find Homebrew's gh, the agent then wrongly infers no GitHub access is available, and falls back to a signed-out integrated browser session. This is a real defect in tool orchestration/environment detection, not a design call, so it stays open and should be routed to the agent-host/agents-window owners.

## Change summary

Requests a deterministic GitHub write path for the Agents window/Agent Host so filing issues doesn't bounce unreliably between MCP tools, the integrated browser session, and a possibly PATH-limited `gh` CLI.

## Best solution

Have the Agent Host shell setup include standard package-manager bin paths (e.g. /opt/homebrew/bin) or otherwise probe `gh` more robustly than a bare `command -v` && short-circuit, and prefer a single canonical GitHub write path (MCP tool with issue-creation scope, or an authenticated `gh`) instead of falling through to a possibly-signed-out browser session; likely touches Agent Host shell/environment setup and the GitHub MCP/tool selection logic referenced by the author's related issues.
