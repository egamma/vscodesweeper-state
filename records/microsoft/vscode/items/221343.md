# Issue #221343 — Packaging task has poor parallelization

[https://github.com/microsoft/vscode/issues/221343](https://github.com/microsoft/vscode/issues/221343)

## Summary

Valid engineering debt — the gulp packaging pipeline still has limited parallelization. Some incremental improvements have landed (e.g. parallel setup packages in commit 012f108a4b5) and a new esbuild-based build system is under development in build/next/, but the core packaging task referenced here hasn't been fundamentally reworked for parallelism.

## Change summary

The gulp vscode-linux-x64 packaging task uses ~1 core out of many available, making the build unnecessarily slow.

## Best solution

The ongoing migration to the esbuild-based build system (build/next/) may address this naturally. Otherwise, the gulp packaging pipeline in build/gulpfile.vscode.js and build/gulpfile.vscode.linux.js needs parallelization of its file-copy, minification, and bundling steps.
