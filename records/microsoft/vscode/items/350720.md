# Issue #350720 — P2 Settings editor rebuilds the TF-IDF index of all settings on every search query

[https://github.com/microsoft/vscode/issues/350720](https://github.com/microsoft/vscode/issues/350720)

## Summary

Current main still rebuilds the settings TF-IDF index on every nonempty query. Keep this open while the directly linked fixing PR is reviewed; no competing agent implementation is needed.

## Change summary

Reuse the settings TF-IDF index across searches on an unchanged settings model to avoid repeated main-thread tokenization and allocation.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/350771, preserving search results and refreshing the index when the settings model changes. Evaluate the separately mentioned debounce latency independently.

- **Repeated tokenization:** src/vs/base/common/tfIdf.ts:114–139 synchronously iterates every document chunk and computes term frequencies through splitTerms and countMapFrom. Thus consecutive queries on the same model repeat document indexing; the reported timing magnitude was not independently measured.
- **Default search path:** PreferencesSearchService retains its RemoteSearchProvider, which retains TfIdfSearchProvider, in src/vs/workbench/contrib/preferences/browser/preferencesSearch.ts. The path is gated by workbench.settings.enableNaturalLanguageSearch, registered with default true in src/vs/workbench/contrib/preferences/common/preferencesContribution.ts:117–123.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/350771 was verified OPEN with no merge commit and explicitly states Fixes #350720. Its diff moves index construction into the model-change branch and reuses the calculator for scoring; its proposed test checks two builds across three searches spanning two models. This is pending work, not a landed fix.
- **Scope boundary:** The linked PR explicitly leaves the two search debouncers unchanged. Current src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts:302–308 still creates both 200 ms delayers; that separate observation does not invalidate the index-reuse fix.
