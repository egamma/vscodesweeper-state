# Issue #234814 — Git - Command `git.openFile` does not do the same thing as the "Open File" icon button on a file that has been committed in diff view

[https://github.com/microsoft/vscode/issues/234814](https://github.com/microsoft/vscode/issues/234814)

## Summary

Still reproduces on main: when `git.openFile` is invoked via keybinding (no argument) from a committed-file diff view, the fallback path at line 1319 uses the raw active editor URI (a git: scheme readonly URI) without converting it to a file: URI, unlike the button path which hits the `isGitUri` conversion at line 1302.

## Change summary

The `git.openFile` command opened from a keybinding on a committed diff view opens a readonly editor instead of the writable working file, because the keybinding fallback path doesn't convert git: URIs to file: URIs.

## Best solution

In `extensions/git/src/commands.ts`, add an `isGitUri` check in the fallback branch (around line 1319-1321) so that when the active editor's URI is a git: URI, it is converted to a file: URI before opening — mirroring the logic at lines 1302-1303.
