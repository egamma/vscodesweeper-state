# Issue #320120 — Powershell doesn't open correctly for Next.js app router files

[https://github.com/microsoft/vscode/issues/320120](https://github.com/microsoft/vscode/issues/320120)

## Summary

This is a duplicate of #138526 — PowerShell (Windows PowerShell 5.1) interprets square brackets in directory paths as wildcard patterns when the cwd is set at the process level via ConPTY. The VS Code team previously investigated this and closed it as out-of-scope since the cwd is set at the OS process spawn level and other shells handle it correctly.

## Change summary

PowerShell terminal fails to open at the correct directory when the path contains square brackets (e.g., Next.js app router `[lang]`, `[...slug]` folders).

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/138526 — the root cause is Windows PowerShell 5.1's treatment of square brackets as wildcard patterns in path arguments, which was already investigated and deemed a PowerShell-side issue. The reporter's fallback path (`C:\WINDOWS\System32\WindowsPowerShell\v1.0`) confirms Windows PowerShell 5.1. Upgrading to PowerShell 7+ or using a different shell is the workaround.
