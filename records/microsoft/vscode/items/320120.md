[https://github.com/microsoft/vscode/issues/320120](https://github.com/microsoft/vscode/issues/320120)

## Summary

The reported fallback directory matches the established PowerShell startup defect for paths containing square brackets. Keep this open as upstream: the matching VS Code reports are closed, and the historical PowerShell Core fix does not establish that Windows PowerShell is fixed.

## Change summary

PowerShell should preserve the requested terminal starting directory when Next.js route folder names contain square brackets.

## Best solution

Preserve literal starting-directory semantics in Windows PowerShell, or assess a narrowly scoped VS Code compatibility workaround for that shell. Distinguish Windows PowerShell from modern PowerShell before treating the historical upstream fix as resolution.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/320120 reports that opening PowerShell for C:\Project\src\app\[lang]\(wiki)\[...slug]\page.tsx starts in C:\WINDOWS\System32\WindowsPowerShell\v1.0 instead of the file directory, including with extensions disabled. Other shells preserve the intended directory.
- **Matching confirmed report:** https://github.com/microsoft/vscode/issues/234935 describes the identical square-bracket-directory and System32 startup symptom. A team member confirmed reproduction at https://github.com/microsoft/vscode/issues/234935#issuecomment-2539908552; a later maintainer identified PowerShell as upstream at https://github.com/microsoft/vscode/issues/234935#issuecomment-3640280882.
- **Upstream diagnosis and fix scope:** https://github.com/PowerShell/PowerShell/issues/5752 documents PowerShell starting in its home directory when the inherited cwd contains square brackets. The merged https://github.com/PowerShell/PowerShell/pull/7240 attributes this to globbing Directory.GetCurrentDirectory(). https://github.com/microsoft/vscode/issues/70432#issuecomment-482661749 confirms success with pwsh 6, not the Windows PowerShell executable implicated here.
- **Current source boundary:** src/vs/platform/terminal/node/terminalProcess.ts preserves the supplied cwd in _ptyOptions and passes those options to node-pty spawn in setupPtyProcess. src/vs/platform/terminal/node/terminalEnvironment.ts injects shellIntegration.ps1 for powershell.exe but does not reset the directory using Set-Location -LiteralPath; shellIntegration.ps1 likewise contains no such startup correction. This supports the upstream boundary, but is not an executed Windows reproduction.
- **Canonical search:** Searches for PowerShell bracket paths, cwd, and System32 found the matching historical reports https://github.com/microsoft/vscode/issues/234935 and https://github.com/microsoft/vscode/issues/70432, both closed. Neither is an eligible open duplicate canonical, and no older open report with the same observable symptom was verified.
