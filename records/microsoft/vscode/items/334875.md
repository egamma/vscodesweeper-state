# Issue #334875 — VS Code 1.136: Copilot Editor Preview Features policy incorrectly hides native Claude Agent Host harness

[https://github.com/microsoft/vscode/issues/334875](https://github.com/microsoft/vscode/issues/334875)

## Summary

Traced this in source: the Claude harness setting is deliberately forced off by the `Claude3PIntegration` policy whenever the account disables chat preview features or is governed by any managed settings at all — this is documented, intentional coupling, not a regression, so I'd close it as-designed rather than a bug.

## Change summary

Reports that upgrading to 1.136 hides the native Claude Agent Host harness from the picker when the signed-in Copilot org has Editor Preview Features disabled, even though Claude is independently authenticated via Anthropic OAuth.

## Best solution

Keep the current coupling (it's intentional governance), but consider a follow-up polish item to surface a clear 'hidden by organization policy' message in the harness picker instead of silently omitting Claude — that's a distinct, smaller ask than the reported 'incorrectly hides' framing.

  > Thanks for the detailed diagnosis. This is intentional: the `Claude3PIntegration` policy (backing `chat.agentHost.claudeAgent.enabled`) is designed to force the Claude harness off whenever the signed-in Copilot organization disables chat preview features or applies any managed settings — independent Anthropic OAuth doesn't change that, because managed settings are enforced by the Copilot runtime and never reach the Claude harness, so leaving it available would give a governed user an ungoverned path around the org's controls. That said, your secondary point is fair — the picker silently drops Claude with no explanation. Feel free to file that as a separate, focused ask for a 'hidden by organization policy' indicator in the harness picker.
