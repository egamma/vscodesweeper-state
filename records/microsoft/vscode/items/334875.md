# Issue #334875 — VS Code 1.136: Copilot Editor Preview Features policy incorrectly hides native Claude Agent Host harness

[https://github.com/microsoft/vscode/issues/334875](https://github.com/microsoft/vscode/issues/334875)

## Summary

Thanks for the detailed diagnosis. What you found is the intended mechanism, not a regression: `chat.agentHost.claudeAgent.enabled` is deliberately governed by the `Claude3PIntegration` policy (with `github.copilot.chat.claudeAgent.enabled` as a `policyReference`), so a Copilot organization's Editor Preview Features setting is designed to gate the Claude harness in the editor regardless of how Claude itself is authenticated.

## Change summary

In 1.136, a Copilot organization's Editor Preview Features policy silently hides the Claude Agent Host harness from the picker even when Claude is authenticated independently via Anthropic OAuth, with no indication to the user why it disappeared.

## Best solution

Keep the current policy-gating behavior (it's an intentional org-wide control), but consider a separate, narrower UX improvement: surface a 'hidden by organization policy' indicator in the harness picker instead of silently omitting the entry — worth filing as its own polish/feature request against the Chat Customizations / policy UI area.
