# Issue #340144 — Agent sessions: Added MCP servers do not appear in Customizations until a new session

[https://github.com/microsoft/vscode/issues/340144](https://github.com/microsoft/vscode/issues/340144)

## Summary

Credible, specific report of a real sync gap: adding an MCP server to an active agent session writes to the session's root config on a channel the Customizations view doesn't appear to refresh from until the session restarts. The architecture docs for this subsystem describe exactly this class of bug (a publish path that skips the resolution/republish boundary), but I could not conclusively pin the exact broken link (host-side republish vs. client resubscribe) without running a live session.

## Change summary

An MCP server added for an active agent session does not show up in Chat: Open Customizations > MCP Servers until a new agent session is started; the view should also surface the server's scope.

## Best solution

Trace the live round-trip for WorkbenchAgentHostCustomizationService.addMcpServer() (writes via target.setRootConfigValue → RootConfigChanged) against the session-state subscription that feeds onDidChangeCustomizations/getMcpServers, confirm whether the provider's republish actually re-enters within one host round-trip as AGENTS.md §8b requires, and fix whichever side (host republish or client refresh-on-view-open) is stale; also surface scope (session/workspace/global) in the MCP Servers list entry as requested.

- **Trace:**
