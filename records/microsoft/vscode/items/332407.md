# Issue #332407 — New Agent Host chat can miss MCP tools when created during multi-root configuration refresh

[https://github.com/microsoft/vscode/issues/332407](https://github.com/microsoft/vscode/issues/332407)

## Summary

Fresh, team-authored, well-evidenced bug report (filed today) describing a startup race where a newly created Copilot Agent chat can run its first turn with a stale/empty MCP tool snapshot in multi-root workspaces; no fix exists yet on main, so this should be routed to the chat/MCP area for a real fix.

## Change summary

A Copilot Agent chat created immediately after adding new MCP server configs in a multi-root workspace can dispatch its first prompt before Agent Host MCP discovery/tool sync completes, so the model runs with no MCP tools even though a `session/serverToolsChanged` event fired just before the prompt.

## Best solution

In the Agent Host chat creation/first-turn dispatch path, gate (or re-check) tool snapshot readiness against pending MCP discovery/sync before sending the first prompt, so new chats either wait briefly for in-flight `serverToolsChanged` events or pick up the latest snapshot at send time rather than a stale one captured at session materialize time.

## Evidence

- **similar known race class in this codebase:** src/vs/platform/agentHost/node/claude/phase6.5-plan.md documents a related ordering bug where `session/serverToolsChanged` fired before `AgentService` had registered session state (fixed for the fork-session path by deferring materialize until first `sendMessage`); this issue is a parallel race for fresh (non-forked) sessions that isn't covered by that fix.
- **no existing fix on main:** No commit or code in src/vs/platform/agentHost/ currently gates first-turn dispatch on MCP tool-sync completion for newly created sessions; the reporter's repro is from a build on 2026-08-24, the same day this issue was filed.
