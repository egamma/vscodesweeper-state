# Issue #117554 — When processing setBreakpoints response treat undefined source.path the same as undefined source

[https://github.com/microsoft/vscode/issues/117554](https://github.com/microsoft/vscode/issues/117554)

## Summary

The defect remains on current main: a verified breakpoint response containing `source: {}` replaces the breakpoint's original file URI with an empty debug URI. The related Go issue worked around the behavior in Delve and explicitly moved the unresolved VS Code-side problem here.

## Change summary

Treat an empty breakpoint `Source` in a `setBreakpoints` response like an omitted source while preserving meaningful sources such as those with a `sourceReference`.

## Best solution

Keep the breakpoint's original URI when the adapter returns an empty source object, while retaining existing handling for sources with a path or positive source reference. Cover both cases in the debug breakpoint model tests.
