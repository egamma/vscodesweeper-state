# Issue #146671 — [scss] interpolation validation issues

[https://github.com/microsoft/vscode/issues/146671](https://github.com/microsoft/vscode/issues/146671)

## Summary

A real SCSS parsing gap remains in the bundled vscode-css-languageservice: interpolated identifiers used as function names are not represented as function calls. The existing related issues cover different or narrower symptoms, so this should remain open and be classified as upstream.

## Change summary

Valid SCSS interpolation in dynamic function calls and keyframe-related syntax produces false parser diagnostics and disrupted highlighting.

## Best solution

Extend the SCSS parser and parser tests in microsoft/vscode-css-languageservice to accept interpolation followed by function arguments and cover the complete reported snippet, then update VS Code's bundled language-service dependency.

## Evidence

- **delegated validation:** extensions/css-language-features/server/src/cssServer.ts obtains getSCSSLanguageService from vscode-css-languageservice and delegates parsing and doValidation to it; VS Code contains no separate SCSS parser for this path.
- **current dependency:** extensions/css-language-features/server/package.json currently bundles vscode-css-languageservice ^7.0.0-next.2.
- **parser gap:** Current upstream src/parser/scssParser.ts recognizes interpolation in identifiers, but _parseTermExpression does not recognize interpolation as a dynamic function call; the parser tests contain interpolation cases but no equivalent of `transform: #{$function}(0)`. Source: https://github.com/microsoft/vscode-css-languageservice/blob/1c00d690ee38c7dfb137df8de1a6ddf571ea9b36/src/parser/scssParser.ts
