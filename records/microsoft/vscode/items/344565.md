## Evidence

The author independently records the same measurement at https://github.com/microsoft/vscode/issues/344521#issuecomment-6444075912.
- **Plain titles still enter markdown rendering:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatConfirmationWidget.ts:103-135 renders titles through IMarkdownRendererService even when their input is a string; toMdString wraps strings with MarkdownString.appendText. src/vs/base/browser/markdownRenderer.ts:224-259 parses markdown and calls domSanitize.safeSetInnerHtml.
- **Repeated initial rendering:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatToolInputOutputContentPart.ts:122-128 constructs ChatQueryTitlePart and immediately calls setOptions. That method reassigns the existing title and renders it again, so this caller performs two initial title renders.
- **Thinking metadata precedes deferred body rendering:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts:2351 calls trackToolMetadata before appendItem decides whether to defer the body. At lines 2842-2854 metadata processing performs extractedTitles.includes and requests a collapsed-title update. However, setTitle at lines 3109-3133 rejects completed response elements, and additional conversation/persistent-reasoning branches exist; the exact restored state must be established before attributing every append to a markdown render.
