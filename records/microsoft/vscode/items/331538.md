# Issue #331538 — Copilot external ingest falls back to memory when workspace storage directory is absent

[https://github.com/microsoft/vscode/issues/331538](https://github.com/microsoft/vscode/issues/331538)

## Summary

Confirmed on main: ExternalIngestIndex builds the on-disk SQLite path from `storageUri` and passes it straight to `DatabaseSync` without creating the parent directory, so a workspace with a not-yet-created extension storage folder silently falls back to an in-memory index. An open PR already fixes this and references the issue, so the right next step is reviewing/landing that PR, not closing here.

## Change summary

Copilot's external-ingest index falls back to an in-memory SQLite database whenever the extension's workspace-storage directory hasn't been created yet, because the disk path's parent folder is never created before opening the database.

## Best solution

Land https://github.com/microsoft/vscode/pull/331539, which creates the file-scheme workspace-storage directory before opening `codebase-external.sqlite` and adds a regression test for an absent nested storage directory; keep the existing in-memory fallback for genuine failures.
