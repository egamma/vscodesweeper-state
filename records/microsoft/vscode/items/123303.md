# Issue #123303 — Cursors are not merged in this case

[https://github.com/microsoft/vscode/issues/123303](https://github.com/microsoft/vscode/issues/123303)

## Summary

Still reproduces on current main: the fix from PR #123896 was closed without merging, and the intersecting-selection filter was never applied. The bug remains in `addSelectionToNextFindMatch()` at line 349 of multicursor.ts.

## Change summary

When `editor.multiCursorMergeOverlapping` is false and Cmd+D is pressed, duplicate/overlapping cursors are created instead of being merged, because the next-match selection is concatenated without filtering out intersecting existing selections.

## Best solution

Apply the fix from the closed PR: in `MultiCursorSession.addSelectionToNextFindMatch()` (src/vs/editor/contrib/multicursor/browser/multicursor.ts ~line 349), filter `allSelections` to exclude any that intersect with `nextMatch` before concatenating, even when `multiCursorMergeOverlapping` is false. The same treatment should be considered for `addSelectionToPreviousFindMatch()` at line 400.

The fix: replace `allSelections.concat(nextMatch)` with `allSelections.filter(s => !s.intersectRanges(nextMatch)).concat(nextMatch)` — even when merge-overlapping is disabled, the find-next-match action should still replace intersecting selections.
