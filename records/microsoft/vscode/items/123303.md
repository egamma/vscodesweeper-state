# Issue #123303 — Cursors are not merged in this case

[https://github.com/microsoft/vscode/issues/123303](https://github.com/microsoft/vscode/issues/123303)

## Summary

Still reproduces on main: the fix from PR #123896 was never merged, and `addSelectionToNextFindMatch` at line 349 of multicursor.ts still blindly concatenates without filtering intersecting selections when `multiCursorMergeOverlapping` is false.

## Change summary

When `editor.multiCursorMergeOverlapping` is false, pressing Cmd+D (Add Selection to Next Find Match) creates overlapping cursors instead of merging them for the find-next case.

## Best solution

Apply the approach from the closed PR #123896: in `addSelectionToNextFindMatch` (src/vs/editor/contrib/multicursor/browser/multicursor.ts, line 349), filter out existing selections that intersect with `nextMatch` before concatenating, so the initial cursor-to-word-select transition doesn't produce overlapping cursors. The same fix likely applies to `addSelectionToPreviousFindMatch` at line 400.
