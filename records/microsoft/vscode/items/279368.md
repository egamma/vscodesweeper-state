# Issue #279368 — GitHub Copilot chat tab doesn't honor `Alt+Left` "Back" to restore tab after close.

[https://github.com/microsoft/vscode/issues/279368](https://github.com/microsoft/vscode/issues/279368)

## Summary

The bug remains source-reproducible on current main: closing a chat disposes its typed editor input, which removes the chat from navigation history, leaving `Alt+Left` with no entry to restore.

## Change summary

Closing a Copilot chat editor should retain a restorable navigation-history entry so Windows `Alt+Left` can reopen it like a closed text editor.

## Best solution

Give closed chat sessions a durable, resolvable navigation-history representation while preserving the existing behavior for transient or unresolved chats and other editor types.

## Evidence

- **source reproduction:** src/vs/workbench/services/history/browser/historyService.ts stores non-file schemes as typed EditorInput instances in EditorHelper.preferResourceEditorInput; EditorNavigationStack.addOrReplace then registers an on-dispose callback that removes those entries. Closing the chat therefore deletes its navigation stop before workbench.action.navigateBack runs.
- **missing durable representation:** src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts does not override EditorInput.toUntyped(), while src/vs/workbench/common/editor/editorInput.ts defaults that method to undefined. ChatEditorInputSerializer exists for workbench restoration, but the navigation-history path does not use it.
- **trigger and outcome:** The reported sequence activates a chat navigation entry, then closing the tab disposes that ChatEditorInput. Its disposal removes the entry and flattens the remaining stack, so Alt+Left (workbench.action.navigateBack) has no chat location to open.
