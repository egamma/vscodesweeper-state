# Issue #210186 — reopen "Keyboard shortcut for copy of line doesn't work on Linux" #6197

[https://github.com/microsoft/vscode/issues/210186](https://github.com/microsoft/vscode/issues/210186)

## Summary

The Linux keybinding for Copy Line Up/Down is intentionally Ctrl+Shift+Alt+Arrow. The original issue #6197 was closed because the conflict is with the Linux desktop environment (workspace switching), not a VS Code bug. The reporter can rebind via Preferences > Keyboard Shortcuts.

## Change summary

Request to change the default Linux keybinding for Copy Line Up/Down because Ctrl+Shift+Alt+Arrow conflicts with common Linux desktop workspace-switching shortcuts.

## Best solution

Close as designed — VS Code already provides the keybinding (Ctrl+Shift+Alt+Arrow on Linux, registered in `src/vs/editor/contrib/linesOperations/browser/linesOperations.ts`), and the conflict is with the OS desktop environment. Users can rebind to Shift+Alt+Arrow or any other combo via File > Preferences > Keyboard Shortcuts.

  > Thanks for raising this. The keybinding for Copy Line Up/Down on Linux is `Ctrl+Shift+Alt+Up/Down` — it's intentionally different from Windows/macOS (`Shift+Alt+Up/Down`) to avoid other conflicts.
  > 
  > The conflict described in the original issue (#6197) is between VS Code and the Linux desktop environment (GNOME/KDE workspace switching), which intercepts the keys before they reach VS Code. This is an OS-level configuration, not a VS Code bug.
  > 
  > The recommended solution is to either:
  > 1. Disable the conflicting workspace-switching shortcut in your desktop environment settings, or
  > 2. Rebind the command in VS Code via **File > Preferences > Keyboard Shortcuts** (search for "Copy Line").
  > 
  > Since this is working as designed — VS Code does bind the shortcut, but the OS intercepts it first — I'm closing this as *as-designed*.
