# Issue #230944 — `files.restoreUndoStack` should take effect immediately

[https://github.com/microsoft/vscode/issues/230944](https://github.com/microsoft/vscode/issues/230944)

## Summary

Keep open: the setting is read dynamically when models are disposed, but previously retained undo stacks can still be restored after disabling it. This team-authored follow-up identifies a remaining live-configuration gap, not the already-fixed model leak.

## Change summary

Make changes to files.restoreUndoStack affect subsequent file reopen operations without reloading the window.

## Best solution

Honor the current setting when reopening files, including files whose undo history was retained before the setting changed. Establish whether disabling restoration discards that retained history or temporarily suppresses its restoration, while preserving undo in currently open editors and shared undo-stack behavior.

- **Behavior:**

  > Changing files.restoreUndoStack must affect subsequent file reopen operations without a window reload. A file closed while restoration was enabled must not regain its retained edits through Undo when reopened after restoration is disabled. Disabling restoration must not erase the working undo history of an editor that remains open. Acceptance checks must cover both toggle directions and the agreed treatment of history retained before disabling.
- **Trace:**

  > ModelService._shouldRestoreUndoStack in src/vs/editor/common/services/modelService.ts reads the current configuration, and _onWillDispose uses it when deciding whether to retain ordinary model history. However, _createModelData restores previously disposed model history on matching contents without checking the current setting; _updateModelOptions does not reconcile this retained history on configuration changes. This establishes a remaining cached-history case, not a blanket startup-only configuration read. The original reporter identified this follow-up after verifying https://github.com/microsoft/vscode/issues/230453#issuecomment-2402782865; the model-reference leak discussed in https://github.com/microsoft/vscode/issues/230635 is separate. The unresolved product boundary is whether disabling restoration permanently discards previously retained history or suppresses its restoration while disabled.
- **Open decisions:**
  - Should disabling files.restoreUndoStack permanently discard undo history already retained for closed files, or preserve it for restoration if the setting is re-enabled before those files are reopened?
