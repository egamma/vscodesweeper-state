# Issue #331608 — Agent Host: Click to open doesn't work for skills used as slash commands in message being edited

[https://github.com/microsoft/vscode/issues/331608](https://github.com/microsoft/vscode/issues/331608)

## Summary

Traced this to a stale editor reference: the chat input's slash-command click-to-open handlers are subscribed once, at ChatWidget construction, to whichever editor `widget.inputEditor` returns at that moment (the main bottom input part) — but decorations (hover text, styling) are recomputed dynamically each update and correctly follow the active editor, so they render fine even after the active editor switches.

## Change summary

When editing a previously-sent chat message that references a skill via a slash command, the rendered link shows a 'Click to open <file>' hover but clicking it does nothing.

## Best solution

In InputEditorDecorations (chatInputEditorContrib.ts), stop binding onMouseDown/onMouseUp once at construction to a captured editor instance; instead re-subscribe (or resolve the target editor dynamically) whenever the widget's active input editor changes between the main inputPart and the inline editing inputPart, so click-to-open works consistently in both editors.
