## Evidence

- **Current dispatcher:** src/vs/workbench/api/common/extHostFileSystemEventService.ts:288–316 creates one shared emitter, passes its event to every FileSystemWatcher, and broadcasts each $onFileEvent batch. The constructor's dispatcher callback at lines 98–131 loops through every enabled event category and calls parsedPattern for each event without base-path candidate selection.
- **Relative-pattern amplification:** src/vs/base/common/glob.ts:393–413, wrapRelativePattern, checks options.isEqualOrParent(path, arg2.base) before matching. Therefore unrelated file events still incur a containment check for every subscribed relative watcher; the reported amplification is source-reproducible without executing the workload.
- **Built-in TypeScript trigger:** extensions/typescript-language-features/src/typescriptServiceClient.ts handles createFileWatcher by constructing RelativePattern(Uri.file(path), '*'); createFileSystemWatcher registers a separate vscode.workspace.createFileSystemWatcher for each request. This confirms the built-in source of numerous single-file watcher subscriptions.

It proposes indexing relative watchers by base path and reports reduced glob-check counts; these measurements are PR-author evidence, not independently executed validation.
