# Issue #306294 — Easier change of selection for "Find in selection"

[https://github.com/microsoft/vscode/issues/306294](https://github.com/microsoft/vscode/issues/306294)

## Summary

Verified duplicate: the older open Backlog issue https://github.com/microsoft/vscode/issues/116827 owns the same observable problem—changing the editor selection while Find/Replace is open does not update the stored Find in Selection range—and its broader scope fully covers this request.

## Change summary

Provide a one-click way to replace the active Find in Selection range with the editor's current selection, disabling the mode for an empty selection.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/116827 and design the selection-refresh behavior there, preserving this report's specific proposal that the current selection replace the stored scope with one action.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/116827 is open, predates this report, is assigned to the Backlog milestone, and explicitly requests that Find in Selection repeat when the selection changes while Find/Replace remains open.
- **same observable symptom:** Both reports concern selecting a new range while the Find/Replace widget is open and the active search scope remaining the previous range; the canonical's automatic refresh would fully satisfy the central need behind this report's one-click refresh proposal.
- **maintainer consolidation precedent:** The nearly identical request https://github.com/microsoft/vscode/issues/95356 asked to update the Find in Selection range without toggling the mode; a maintainer explicitly closed it as covered by https://github.com/microsoft/vscode/issues/116827 in https://github.com/microsoft/vscode/issues/95356#issuecomment-1349936066.
- **current source behavior:** On current main, CommonFindController.toggleSearchScope in src/vs/editor/contrib/find/browser/findController.ts captures current selections only when enabling the scope and clears the scope when already enabled. The corresponding toggle handler in src/vs/editor/contrib/find/browser/findWidget.ts follows the same two-state behavior and provides no action to replace an active scope directly.
