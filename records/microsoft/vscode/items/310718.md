# Issue #310718 — Code executable has improper permissions under Red Hat Linux.

[https://github.com/microsoft/vscode/issues/310718](https://github.com/microsoft/vscode/issues/310718)

## Summary

The RPM spec template uses `%defattr(-,root,root)` which preserves the build-time file permissions; the `bin/code` executable ends up 775 instead of 755 because no explicit `%attr` overrides it. This is a valid packaging bug affecting STIG-compliant RHEL environments.

## Change summary

The VS Code RPM package installs `bin/code` with mode 775 instead of 755, violating DISA STIG V-257882.

## Best solution

Add `%attr(0755, root, root) %{_datadir}/%{name}/bin/%{name}` in the RPM spec template (`resources/linux/rpm/code.spec.template`) before the general `%{_datadir}/%{name}/` glob, or change `%defattr(-,root,root)` to `%defattr(0755,root,root,0755)` to default all files to 755.
