# Issue #329584 — Risk assessment dialog box covers proposed code.

[https://github.com/microsoft/vscode/issues/329584](https://github.com/microsoft/vscode/issues/329584)

## Summary

Credible, screenshot-backed report that the async risk-assessment footer banner on terminal tool confirmations can end up overlapping the tail of a long command instead of pushing it fully into view; routing to the chat/terminal-confirmation area for a maintainer to trace the exact layout interaction.

## Change summary

The risk-assessment footer banner shown under a terminal tool confirmation covers the last line(s) of a long proposed command, and isn't dismissable until Allow/Skip is chosen.

## Best solution

A chat maintainer should verify the interaction between the terminal command editor's height (src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolConfirmationSubPart.ts) and the async-loading risk badge footer (toolRiskBadgeHelper.ts / toolRiskBadgeWidget.ts, inserted via footerBanner in chatConfirmationWidget.ts) to ensure the confirmation widget always grows to accommodate the badge rather than overlapping the command text, and confirm the row-height ResizeObserver in chatListRenderer.ts actually fires in time for this case.

- **async footer growth:** createToolRiskBadge (toolRiskBadgeHelper.ts) shows a short 'Assessing risk…' state synchronously, then asynchronously replaces it with a possibly longer explanation via widget.setAssessment() in toolRiskBadgeWidget.ts — the footer can grow well after the confirmation widget's initial layout.
