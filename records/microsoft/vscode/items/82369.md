# Issue #82369 — Extension proxy doe not tunnel https to http

[https://github.com/microsoft/vscode/issues/82369](https://github.com/microsoft/vscode/issues/82369)

## Summary

Keep open: extension networking now delegates to @vscode/proxy-agent, whose current implementation supports HTTPS through HTTP proxies, but that does not establish that the reported Axios failure is resolved. The supplied environment, request scenario, error, and workaround suffice to retest without requesting more basic information.

## Change summary

HTTPS requests from extensions fail behind an HTTP proxy configured through HTTPS_PROXY unless the extension supplies its own tunneling agent.

## Best solution

Establish whether an extension's Axios request succeeds through an HTTP CONNECT proxy under the default extension proxy configuration, distinguishing VS Code patch behavior from Axios's own proxy handling. Resolve any confirmed integration defect in the responsible layer and retain a regression check for that request path.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/82369 describes Ubuntu 18.04.3, VS Code 1.39.1, HTTPS_PROXY containing an HTTP URL, and extension HTTPS requests failing with 'socket hang up'. Supplying tunnel.httpsOverHttp together with Axios proxy:false avoids the failure; this identifies a concrete scenario but does not establish which layer causes it.
- **Current extension-host integration:** src/vs/workbench/api/node/proxyResolver.ts passes process.env into createProxyResolver, patches both http and https through createHttpPatch in createPatchedModules, and supplies those patched modules to extensions through configureModuleLoading. package.json declares @vscode/proxy-agent ^0.45.0; the original implementation has materially changed.
- **Existing proxy configuration:** src/vs/platform/request/common/request.ts registers http.proxySupport with default 'override'. Extension proxying is an existing supported behavior, not a request for a new networking feature.
