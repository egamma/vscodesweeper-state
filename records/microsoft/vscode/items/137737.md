# Issue #137737 — Add a command to run/debug tests with the current filter from anywhere

[https://github.com/microsoft/vscode/issues/137737](https://github.com/microsoft/vscode/issues/137737)

## Summary

The requested capability remains missing: filtered run/debug commands still require an active Test Explorer. Keep this accepted Backlog request open; rerunning the last run offers a partial workaround, not execution of the current filter.

## Change summary

Allow running or debugging tests matching the current Test Explorer filter without returning to that view.

## Best solution

Provide globally invocable run/debug commands that honor the current Test Explorer filter without requiring that view to be active. Preserve the existing run-all behavior and decide the public command and no-filter semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/testing/browser/testExplorerActions.ts`, `src/vs/workbench/contrib/testing/browser/testingExplorerView.ts`, `src/vs/workbench/contrib/testing/common/constants.ts`
- **Validation:** With a test provider exposing matching and nonmatching tests, apply a Test Explorer filter, switch to File Explorer, and invoke the agreed run/debug commands. Verify that only matching tests execute and Test Explorer need not become active; change the filter and repeat to distinguish current-filter execution from rerunning a historical request. Cover the agreed no-filter behavior and confirm testing.runAll/testing.debugAll remain unchanged.
- **Behavior:**

  > Users should be able to run or debug tests matching the current Test Explorer filter while working in File Explorer or another workbench view. Execution must use the current filter, not merely repeat the last test run. Acceptance checks should cover both run and debug, exclude nonmatching tests, and verify that returning to Test Explorer is unnecessary. The behavior when no filter or initialized explorer exists must be agreed before implementation.
- **Trace:**

  > ExecuteSelectedAction in src/vs/workbench/contrib/testing/browser/testExplorerActions.ts gets include/exclude tests from TestingExplorerView.getTreeIncludeExclude(). Its ViewAction base in src/vs/workbench/browser/parts/views/viewPane.ts resolves only an active view, so invoking it after switching away returns without running tests. Filtering currently depends on tree visibility and profile eligibility in src/vs/workbench/contrib/testing/browser/testingExplorerView.ts, rather than merely a text argument. RunOrDebugAllTestsAction runs collection roots, while RunOrDebugLastRun reuses a historical request; neither provides current-filter execution from another view. Preserve run-all and historical-rerun semantics, and avoid changing shared ViewAction behavior for unrelated views. https://github.com/microsoft/vscode/issues/147288 addresses automatic view opening, not this capability.
- **Open decisions:**
  - Should existing testing.runSelected/testing.debugSelected commands gain global behavior, or should dedicated filtered run/debug commands expose this capability?
  - When no filter or initialized Test Explorer exists, should the command run all eligible tests, initialize and apply the saved filter, or report that no filtered selection is available?
