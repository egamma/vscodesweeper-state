# Issue #242153 — Allow using custom variables in setting values

[https://github.com/microsoft/vscode/issues/242153](https://github.com/microsoft/vscode/issues/242153)

## Summary

Valid feature request with strong community support (25 upvotes, promoted to Backlog). Variable resolution in settings remains opt-in per individual setting; no universal resolution has been implemented. Stays open as a backlog item.

## Change summary

Allow ${config:...} variable substitution universally across all setting values, not just the few settings that individually opt in.

## Best solution

Implement a universal variable-resolution pass in the configuration service so that ${config:...} (and potentially other variables) are resolved for all settings, not only those whose consumers explicitly call the configuration resolver. This is a cross-cutting change in `src/vs/workbench/services/configurationResolver/` and/or the configuration reading layer. Related issue https://github.com/microsoft/vscode/issues/44755 (workspace-file variable support) is complementary but distinct — both could share infrastructure.
