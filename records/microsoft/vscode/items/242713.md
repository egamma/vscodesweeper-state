# Issue #242713 — Terminal search blocks renderer

[https://github.com/microsoft/vscode/issues/242713](https://github.com/microsoft/vscode/issues/242713)

## Summary

The upstream xterm.js performance work this issue was tracked against (xtermjs/xterm.js#5176, closed as completed) landed a fix that current VS Code main already pulls in via its locked @xterm/addon-search version, and VS Code's terminal search calls directly into the now-optimized code path — so this appears resolved on main.

## Change summary

Typing/backspacing in terminal search with a large scrollback (e.g. 50000 lines) blocks the renderer for ~300ms per keystroke.

## Best solution

Treat as fixed by the upstream decoration-lookup optimization (xtermjs/xterm.js PR #5902, merged into the commit tree behind VS Code's current @xterm/addon-search ^0.17.0-beta.301) — no core change needed; confirm on latest Insiders if still slow.
