# Issue #338376 — Notebook hover, signature help, and cell “More Actions” menu are clipped near the editor boundary

[https://github.com/microsoft/vscode/issues/338376](https://github.com/microsoft/vscode/issues/338376)

## Summary

Fresh, single-reporter bug but the root cause is verifiable in source: the notebook editor's code-cell editors (and markup-cell editors) never wire up an `overflowWidgetsDomNode`, unlike the notebook diff editor's cell editors which do — so hover/parameter-hint content widgets are constrained to the narrow cell editor container and clip when horizontal space is tight (split editor group, sidebar open).

## Change summary

Notebook cell hover, signature help, and the cell '...' toolbar menu get visually clipped when there isn't much horizontal room to the right of the cell.

## Best solution

Wire `overflowWidgetsDomNode: this.notebookEditor.getOverflowContainerDomNode()` into the code-cell editor options in cellRenderer.ts and re-enable the currently-commented-out line in markupCell.ts, mirroring what notebookDiffList.ts / diffComponents.ts already do for the diff editor's cell editors; separately verify whether the cell title toolbar's dropdown menu has its own distinct clipping cause (likely a CSS overflow/anchor issue) before folding it into the same fix.

## Evidence

- **missing overflow wiring:** src/vs/workbench/contrib/notebook/browser/view/renderers/cellRenderer.ts:287 creates the code-cell CodeEditorWidget from `this.editorOptions.getDefaultValue()` plus a few overrides, with no `overflowWidgetsDomNode` set.
- **disabled in markup cells too:** src/vs/workbench/contrib/notebook/browser/view/cellParts/markupCell.ts:338 has `// overflowWidgetsDomNode: this.notebookEditor.getOverflowContainerDomNode()` commented out — the capability exists but isn't used for normal editing.
- **diff editor does it correctly:** src/vs/workbench/contrib/notebook/browser/diff/notebookDiffList.ts:588/623 and diff/diffComponents.ts (several call sites) DO pass `overflowWidgetsDomNode: notebookEditor.getOverflowContainerDomNode()`, and notebookEditorWidget.ts:1140 implements `getOverflowContainerDomNode()` — so the container and API already exist, just unused on the main editing path.
