# Issue #341574 — Agent Host (Copilot SDK) chats never start OAuth sign-in for remote HTTP MCP servers — browser never opens

[https://github.com/microsoft/vscode/issues/341574](https://github.com/microsoft/vscode/issues/341574)

## Summary

Keep open: the report provides concrete OAuth failure logs, a local-harness comparison, and an independent macOS confirmation. Current source has an MCP authentication bridge, but its presence does not establish that this challenge reaches interactive sign-in; no fixing commit or verified duplicate was established.

## Change summary

Remote HTTP MCP servers requiring OAuth remain unauthenticated in Copilot SDK Agent Host chats because explicit authentication never opens browser sign-in.

## Best solution

Make explicit Start/Authenticate complete the remote MCP OAuth flow through VS Code's authentication services and return the resulting credentials to the requesting SDK session. First isolate whether the reported challenge fails before the SDK callback, during challenge metadata publication, or at the interactive workbench handoff.
