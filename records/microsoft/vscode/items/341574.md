# Issue #341574 — Agent Host (Copilot SDK) chats never start OAuth sign-in for remote HTTP MCP servers — browser never opens

[https://github.com/microsoft/vscode/issues/341574](https://github.com/microsoft/vscode/issues/341574)

## Summary

Thanks for the detailed report. The steps and logs are complete and a second user confirms it on macOS. I could not run it. The agent host does have MCP auth-required handling, so the failure is probably in how the SDK's OAuth challenge reaches VS Code. This needs maintainer triage.

## Change summary

OAuth sign-in for remote HTTP MCP servers never starts under the Agent Host Copilot SDK harness; the server stays in needs-auth with no browser prompt.

## Best solution

Find why the SDK's rmcp 401 OAuthChallenge does not produce an auth request that VS Code acts on, or whether the SDK should emit one at all. Then make the agent host surface the authorization flow, as the local harness does.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionWrapper.ts`
- **Validation:** With a remote HTTP MCP server that returns a 401 OAuth challenge, start it under the agent host Copilot harness and confirm the browser sign-in opens. Add an agent host test where the SDK reports needs-auth and an auth-required state with an authorization request is emitted.
- **Behavior:**

  > Starting or authenticating a remote OAuth-protected MCP server under the Agent Host Copilot harness opens the browser sign-in, as the local harness does. After consent the server leaves needs-auth and its tools load.
- **Trace:**

  > The SDK's rmcp transport quits on the OAuthChallenge, then session.mcp.startServer fails with 'requires authentication'. After that, authenticationStateChanged fails with 'still requires authentication'. copilotAgentSession.ts translates McpAuthRequest events into McpAuthRequirement and the AuthRequired state. First establish whether the SDK emits an MCP auth request for this case. If it does not, the fix is upstream in the SDK or its adoption. Do not change the local harness path.

## Evidence

- **reporter logs:** The rmcp worker quits on OAuthChallenge (401). agenthost.log shows the 'requires authentication' / 'still requires authentication' warnings from AgentSideEffects, and no authorization URL is ever sent.
- **code path:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts around lines 4145-4180 handles MCP auth requests, and around lines 5642-5669 calls session.rpc.mcp.oauth.authenticationStateChanged. I did not trace why no auth request arrives for this server.
- **confirmation:** A second user reports the same on macOS, with MCP configs in .vscode or .mcp.json.
- **workaround:** The local chat agent authenticates the same server. Disable chat.defaultToCopilotHarness and chat.editor.preferCopilotHarness, then restart.
