# Issue #329892 — Expose contextSizeOptions for BYOK models

[https://github.com/microsoft/vscode/issues/329892](https://github.com/microsoft/vscode/issues/329892)

## Summary

Keep open: current BYOK configuration supports a single context-window limit, but does not expose selectable context-size presets. The related Agent Host issue is newer and concerns losing configuration already supplied by an extension, not declaring these presets.

## Change summary

Allow BYOK model definitions to declare context-size choices for the existing model configuration selector without duplicating model definitions.

## Best solution

Support declarative context-size presets for BYOK models through the existing configuration selector, with explicit default and token-budget semantics. Keep the separate Agent Host configuration-projection problem tracked independently.

- **Reason:** Reusing the existing model selector makes BYOK configuration more consistent with built-in models without adding a separate UI surface.

- **Validation:** Extend the BYOK model-info Vitest suite to verify context-size choices appear with and without reasoning-effort support and preserve existing models when omitted. Manually configure one BYOK model with two presets, switch between them in normal Chat, and verify the effective prompt budget follows the selected preset without duplicating the model.
- **Behavior:**

  > A user can declare multiple context-size presets for one BYOK model and select them through the existing model configuration control. Selecting a preset changes the effective context budget without creating another model definition. Models without presets retain their existing limits and selector behavior. Acceptance should cover a model without reasoning-effort support as well as one exposing both controls; preset defaults and whether values include the output reservation require agreement.
- **Trace:**

  > BYOKModelCapabilities and resolveModelTokenLimits in extensions/copilot/src/extension/byok/common/byokProvider.ts currently represent one fixed context window, defined as input plus output. byokKnownModelToAPIInfoWithEffort in extensions/copilot/src/extension/byok/vscode-node/byokModelInfo.ts exposes only reasoningEffort configuration and exits early when it is absent. CustomEndpointProvider consumes configured models and constructs endpoint capabilities, while extensions/copilot/package.json declares the editable model configuration schema. The built-in getContextSizeOptions path in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts uses pricing tiers and modelMaxPromptTokens to construct contextSize choices, so copying its numbers would not by itself settle the BYOK input-versus-total-window contract. Preserve existing token limits, reasoning-effort behavior, and model identity when presets are omitted. https://github.com/microsoft/vscode/issues/333017 tracks the distinct loss of extension-supplied configuration in Agent Host; it is not a duplicate or proof that this declarative capability exists.
- **Open decisions:**
  - Should declared context-size preset values represent the total input-plus-output window, like BYOK contextWindow, or the prompt budget used by the built-in selector?
  - How should a model definition specify its default preset, and what selection should apply when no explicit default is supplied?
