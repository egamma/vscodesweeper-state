# Issue #169426 — Inside of Jupyter Notebook cannot replace text with a multi-line text

[https://github.com/microsoft/vscode/issues/169426](https://github.com/microsoft/vscode/issues/169426)

## Summary

Keep open: the notebook replacement field still uses a single-line input, so the requested multiline-paste capability remains missing. No verified older canonical owns this symptom; the existing notebook-find classification is appropriate.

## Change summary

Allow pasted multiline replacement text to retain its line breaks when replacing cell source within a notebook.

## Best solution

Bring the notebook Find/Replace replacement field into parity with the text editor by supporting literal multiline replacement text for Replace and Replace All, while preserving existing keyboard and replacement-pattern behavior.

## Evidence

- **Existing-capability check:** Current upstream src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindReplaceWidget.ts constructs ContextScopedReplaceInput without flexibleHeight. src/vs/base/browser/ui/findinput/replaceInput.ts coerces that omitted option to false, and src/vs/base/browser/ui/inputbox/inputBox.ts selects an input rather than a textarea when flexibleHeight is false. This matches the reported loss of literal line breaks on paste.
- **Text-editor comparison:** src/vs/editor/contrib/find/browser/findWidget.ts passes flexibleHeight, flexibleWidth and flexibleMaxHeight to its ContextScopedReplaceInput. The underlying shared widget therefore has multiline support, but the notebook replacement field does not enable it. The inspected notebook configuration registration provides find filters, not a setting that enables multiline replacement input.
- **Replacement execution:** src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts reads the replacement pattern and passes the resulting strings to viewModel.replaceOne or viewModel.replaceAll. Existing pattern processing does not address literal multiline text being flattened at the input field.
