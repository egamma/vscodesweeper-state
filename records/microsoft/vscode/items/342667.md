# Issue #342667 — Prevent accidental loss of AI chats when using “Start Over”

[https://github.com/microsoft/vscode/issues/342667](https://github.com/microsoft/vscode/issues/342667)

## Summary

Keep open: existing confirmations protect file edits, not every conversation affected by Start Over. The related archive-confirmation request concerns a different action, and the available evidence does not establish that this conversation-safety request is already covered.

## Change summary

Protect conversations from accidental Start Over activation through confirmation or a discoverable recovery action.

## Best solution

Make Start Over safe for conversation-only sessions as well as sessions with file edits, using a consistent confirmation or clearly discoverable recovery experience. Verify the existing checkpoint Redo behavior before describing conversation removal as irreversible.

## Evidence

- **Existing confirmation does not cover all conversations:** In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts, StartOverAction invokes restoreSnapshotWithConfirmation. Its helper prompts only when entriesModifiedInRequestsToRemove.length > 0 and chat.editing.confirmEditRequestRemoval is true. A conversation without matching file edits does not receive this modal safeguard.
- **Setting checked:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.editing.confirmEditRequestRemoval with default true and describes confirmation before removing a request and its associated edits. Enabling it does not remove the helper's file-edit requirement.
- **Inline confirmation is also conditional:** In src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts, discardEditsActionNeedsConfirmation requires an AgentHostSnapshotController and at least one affected request with file edits. ChatRestoreCheckpointActionViewItem therefore does not provide a general conversation-only Start Over confirmation.
- **Recovery capability requires distinction:** src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts registers workbench.action.chat.redoEdit2 with tooltip 'Reapply discarded workspace changes and chat', gated by chatEditingCanRedo. ChatEditingSession.restoreSnapshot and redoInteraction navigate the checkpoint timeline, while ChatModel.setCheckpoint blocks requests rather than directly deleting them. These are recovery leads, not proof that the reporter's session was recoverable or that the requested general safeguard is satisfied.

Its discussion at https://github.com/microsoft/vscode/issues/319666#issuecomment-4608659850 specifically suggests unarchiving. Start Over instead follows the checkpoint-restoration action, so the archive issue has not been established as owning this distinct behavior.
