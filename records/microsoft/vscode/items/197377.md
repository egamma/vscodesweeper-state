# Issue #197377 — workspaceFolder variable substitution in launch.json or tasks.json should use URI for virtual filesystems

[https://github.com/microsoft/vscode/issues/197377](https://github.com/microsoft/vscode/issues/197377)

## Summary

The original bug remains on current main: the fix (PR #235954) was merged but then reverted (commits 0a5a4d6bb1b, a1d56fd8a25) because it broke extensions. The `workspaceFolder` variable still resolves via `fsPath` even for non-file schemes, so the reported problem persists.

## Change summary

${workspaceFolder} variable substitution uses fsPath instead of URI form for virtual (non-file://) filesystem workspaces, producing unusable paths for extensions.

## Best solution

Re-approach the fix with a backward-compatible strategy — e.g. introduce a new variable like `${workspaceFolderUri}` or add an opt-in mechanism so extensions can declare readiness for URI-form substitution. The fix site is `src/vs/workbench/services/configurationResolver/common/variableResolver.ts` around line 215. The previous attempt showed that changing `${workspaceFolder}` behavior directly breaks existing extensions.
