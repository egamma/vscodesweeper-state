# Issue #323131 — Markdown Paste - Cannot read properties of undefined (reading 'line')

[https://github.com/microsoft/vscode/issues/323131](https://github.com/microsoft/vscode/issues/323131)

## Summary

Keep open: the Markdown language server incorrectly interprets standard LSP edit ranges as arrays, matching the confirmed paste failure. Both the upstream fix and a VS Code compatibility workaround remain open PRs, so neither establishes a completed fix.

## Change summary

Prevent Markdown-to-Markdown link-aware paste from throwing when the language server reads an edit range.

## Best solution

Review the upstream fix in https://github.com/microsoft/vscode-markdown-languageserver/pull/25 and adopt the corrected server in the built-in Markdown extension. Coordinate that adoption with the pending compatibility workaround at https://github.com/microsoft/vscode/pull/332424; verify link rewriting and separately retest the reported cursor jump.

## Evidence

- **Current client path:** extensions/markdown-language-features/src/languageFeatures/updateLinksOnPaste.ts: prepareDocumentPaste attaches Markdown link-rewrite metadata, and provideDocumentPasteEdits requests updated edits when that metadata and pasted text are present. src/client/client.ts:59–65 serializes those edits with lsp.TextEdit.replace(toLspRange(edit.range), edit.newText), producing standard LSP ranges rather than tuples.
- **Upstream defect:** Read https://github.com/microsoft/vscode-markdown-languageserver/blob/main/src/server.ts:291–299. The getUpdatePastedLinksEdit handler accesses edit.range[0].line and edit.range[1].line, although the request declares lsp.TextEdit[] with object-shaped ranges. This explains the reported undefined.line failure; copyPasteController.ts is where the rejected provider request surfaces, not the root cause.
- **Pending implementation candidates:** Verified https://github.com/microsoft/vscode-markdown-languageserver/pull/25 and https://github.com/microsoft/vscode/pull/332424 are both OPEN. The upstream PR accepts standard LSP edits directly; the VS Code PR explicitly says Fixes #323131 and proposes a temporary tuple-format compatibility workaround. An open linked fix PR blocks a completed-close proposal and competing agent implementation.
- **Dependency adoption:** extensions/markdown-language-features/package.json and package-lock.json still specify vscode-markdown-languageserver 0.5.0. The inspected checkout still sends standard LSP ranges; no completed adoption of either pending fix was established.
- **Confirmed impact and workaround:** The August 17 comment at https://github.com/microsoft/vscode/issues/323131 reports controlled macOS reproductions between two Markdown editors and matching provider failures at paste times. Setting markdown.editor.updateLinksOnPaste.enabled to false bypasses the failing provider but disables link/reference rewriting, so it is a workaround rather than resolution. The additional focus-return cursor jump is repeatable in the report but its causal connection to the provider failure remains unproven.
- **Canonical search:** An open-issue search for getUpdatePastedLinksEdit returned only this issue. https://github.com/microsoft/vscode/issues/298733 was verified CLOSED and reports a similar error, so it cannot serve as an open duplicate canonical; the current handler still contains the implicated range-array access.
