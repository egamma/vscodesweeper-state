# Issue #88227 — Ability to drag and drop breakpoints

[https://github.com/microsoft/vscode/issues/88227](https://github.com/microsoft/vscode/issues/88227)

## Summary

This remains a valid, well-supported Backlog feature request: 40 community upvotes and maintainer agreement establish demand, while the linked implementation attempt was closed without landing. Current source still supports editing or removing rich breakpoints but does not provide breakpoint drag-and-drop.

## Change summary

Allow users to move conditional breakpoints and logpoints between source lines by dragging them, with a practical alternative for distant lines.

## Best solution

Add breakpoint and logpoint relocation in the editor gutter while preserving conditions, hit conditions, log messages, enabled state, and mode; provide an accessible keyboard or command-based move flow for distant lines and users who cannot use drag-and-drop.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/workbench/contrib/debug/browser/breakpointsView.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts`, `src/vs/workbench/contrib/debug/common/debugModel.ts`
- **Validation:** Add targeted debug/editor tests showing that moving conditional breakpoints and logpoints preserves all rich properties and does not alter ordinary gutter click behavior; complete a keyboard-only accessibility check for the selected non-pointer move flow.
- **Behavior:**

  > Users can relocate a breakpoint or logpoint to another valid source line without recreating it. The moved item preserves its condition, hit condition, log message, enabled state, and breakpoint mode, while ordinary gutter click behavior remains unchanged. Moving across a long file must not require dragging through the whole document, and the capability must be operable without pointer drag. Acceptance includes moving rich breakpoints and logpoints within an editor, handling an invalid target predictably, and preserving all breakpoint metadata.
- **Trace:**

  > The issue is the older Backlog request and has 40 upvotes plus explicit maintainer support. The previous simple implementation attempt at https://github.com/microsoft/vscode/pull/114717 is closed and did not land; the thread says richer drag rendering and cross-editor behavior depended on https://github.com/microsoft/vscode/issues/114776. The likely path spans editor drag handling in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts and breakpoint presentation/model code in src/vs/workbench/contrib/debug/browser/breakpointsView.ts, src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts, and src/vs/workbench/contrib/debug/common/debugModel.ts. Preserve existing gutter click, breakpoint editing, and debug-adapter synchronization semantics; decorator drag-and-drop requested in https://github.com/microsoft/vscode/issues/120674 is a separate extension API concern and should remain out of scope. The uncertainty starts at the public interaction contract: source-only versus cross-editor movement, whether move and copy are both included, and which non-pointer flow handles distant lines.
- **Open decisions:**
  - Should the first supported contract move breakpoints only within one source editor, or also between editors/files?
  - Is modifier-drag copying part of this feature, or should the initial contract support relocation only?
  - What non-pointer interaction should expose relocation to a chosen line: a breakpoint command that prompts for a line, keyboard cut/paste semantics, or both?
