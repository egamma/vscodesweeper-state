# Issue #335237 — editor.suggest.insertMode: "insert" not respected for completions using LSP InsertReplaceEdit (clangd 23.1.0+)

[https://github.com/microsoft/vscode/issues/335237](https://github.com/microsoft/vscode/issues/335237)

## Summary

Well-diagnosed report: the reporter captured the raw LSP `InsertReplaceEdit` response showing a correctly-scoped `insert` range, yet VS Code applies the wider `replace` range while `editor.suggest.insertMode` is at its default `insert`. I traced the core insertMode branching in src/vs/editor/contrib/suggest/browser/suggestController.ts (line ~576-581, selects editReplaceEnd vs editInsertEnd based on the insertMode option) and the range normalization in src/vs/editor/contrib/suggest/browser/suggest.ts (~104-120), and both look structurally correct on main, so I can't pinpoint the exact defect from source alone — it may be in how the suggest widget recomputes/filters ranges as the user types, or in how the extension host converts the provider's `range.inserting/replacing` object (extHostLanguageFeatures.ts `_convertCompletionItem`).

## Change summary

With editor.suggest.insertMode set to "insert" (default), accepting a completion whose provider supplied an LSP InsertReplaceEdit deletes text beyond the typed prefix instead of only replacing it, matching "replace" mode behavior.

## Best solution

Needs an editor/suggest owner to reproduce with clangd 23.1.0+ (or a minimal test extension returning a CompletionItem with range: {inserting, replacing}) and step through SuggestController#_insertSuggestion and CompletionItem range normalization in suggest.ts to find where the replace range leaks through when insertMode is 'insert'.
