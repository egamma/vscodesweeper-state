# Issue #243751 — Add `Run Without Debug` button in `Run and Debug` Activity Bar

[https://github.com/microsoft/vscode/issues/243751](https://github.com/microsoft/vscode/issues/243751)

## Summary

This remains a valid Backlog feature request with 28 community upvotes. Current main still exposes only Start Debugging in the Run and Debug view title, while Start Without Debugging remains available through less-visible command, menu, keybinding, and Touch Bar surfaces.

## Change summary

Make running the selected launch configuration without debugging directly discoverable from the Run and Debug view, potentially alongside the existing Start Debugging button and under a renamed Run view.

## Best solution

Give Start Without Debugging first-class access beside the selected launch configuration in the Run and Debug view, using a toolbar presentation that keeps the two launch modes clear without adding unnecessary chrome. A maintainer should first settle whether this is two peer actions or a split action, and whether the established Run and Debug name changes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugViewlet.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/browser/runAndDebugAccessibilityHelp.ts`
- **Validation:** Add a debug contribution test asserting that the chosen Run and Debug view-title presentation exposes both workbench.action.debug.start and workbench.action.debug.run under the intended context conditions, then manually verify both actions launch the configuration selected in the existing picker with and without debugging.
- **Behavior:**

  > The Run and Debug view must make both launch modes discoverable for the configuration selected in its existing picker. One action starts debugging and the other starts the same configuration without debugging; their labels, icons, tooltips, keyboard access, and screen-reader descriptions must distinguish the modes. Existing F5, Ctrl+F5, Run-menu behavior, configuration selection, and active-debug-session controls must remain unchanged.
- **Trace:**

  > The selected launch configuration is consumed by both commands in src/vs/workbench/contrib/debug/browser/debugCommands.ts: workbench.action.debug.start starts it normally, while workbench.action.debug.run delegates with noDebug: true. The gap is in src/vs/workbench/contrib/debug/browser/debugViewlet.ts, where MenuId.ViewContainerTitle registers only workbench.action.debug.start with the launcher visibility conditions. The visible view name is registered in src/vs/workbench/contrib/debug/browser/debug.contribution.ts, and the existing accessibility help in src/vs/workbench/contrib/debug/browser/runAndDebugAccessibilityHelp.ts currently documents Start Debugging but not Start Without Debugging. Keep command semantics, picker behavior, docked-toolbar behavior, and debug-session controls outside the scope of this UI change. No older open canonical with the same observable request was identified; https://github.com/microsoft/vscode/issues/150663 is broader configuration-flow work, not this toolbar affordance.
- **Open decisions:**
  - Should the view title show Run and Start Debugging as two peer icon actions, or use a split action that keeps one primary while exposing the other adjacent to it?
  - Should the established Run and Debug view name remain, or change to Run to represent both launch modes?
