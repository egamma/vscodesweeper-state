# Issue #333975 — Microsoft Authentication loses Settings Sync session after macOS sleep/network interruption; restarting extension host restores valid session

[https://github.com/microsoft/vscode/issues/333975](https://github.com/microsoft/vscode/issues/333975)

## Summary

A VS Code maintainer (TylerLeonhardt) confirmed this against the current implementation: a transient MSAL network_error during sleep is treated the same as a genuinely absent session, so Settings Sync flips to unauthenticated with no connectivity-driven recovery, while the cached account is never actually deleted (explaining why an extension host restart immediately restores it). This is a real, confirmed bug that stays open as the tracking issue for the broader auth-layer fix.

## Change summary

After a macOS sleep/network interruption, a transient MSAL token-acquisition failure causes Microsoft Authentication to report 0 sessions and Settings Sync to prompt for sign-in, even though the persisted session is still valid (restarting the extension host recovers it without any interactive auth).

## Best solution

Have the Microsoft Authentication provider distinguish transient acquisition failures (e.g. network_error) from truly absent/revoked/interaction-required sessions, so consumers like Settings Sync don't have to infer state from an empty session list and can recover once connectivity returns; the maintainer has designated this issue as the tracker for that authentication-layer fix, with https://github.com/microsoft/vscode/issues/336860 opened as a narrower, evaluated-in-parallel Settings Sync mitigation.
