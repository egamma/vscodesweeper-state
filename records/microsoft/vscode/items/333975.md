# Issue #333975 — Microsoft Authentication loses Settings Sync session after macOS sleep/network interruption; restarting extension host restores valid session

[https://github.com/microsoft/vscode/issues/333975](https://github.com/microsoft/vscode/issues/333975)

## Summary

Traced in current main: getAllSessionsForPca in the built-in microsoft-authentication provider treats any acquireTokenSilent failure (including a transient network_error from sleep/wake) as 'account has no session', with no distinction from a genuinely invalid/expired token — matching the reported symptom that a restart (which re-reads the still-valid MSAL cache) immediately restores the session.

## Change summary

After macOS sleep with a transient network failure, Settings Sync's Microsoft Authentication incorrectly reports 0 sessions even though the persisted MSAL cache is still valid, forcing an unnecessary re-auth prompt until the extension host is restarted.

## Best solution

In extensions/microsoft-authentication/src/node/authProvider.ts's getAllSessionsForPca catch block (around lines 530-540), distinguish transient/network failures from real auth failures (similar to the existing ServerError/userCanceled checks elsewhere in the file) so a network_error doesn't cause the account to be dropped from the session list; likely needs a retry or fallback-to-cached-account-info strategy, which is a design decision for the auth team.
