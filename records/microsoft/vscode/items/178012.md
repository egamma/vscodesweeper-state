# Issue #178012 — Always show arrow in suggest item

[https://github.com/microsoft/vscode/issues/178012](https://github.com/microsoft/vscode/issues/178012)

## Summary

The default suggest UI still hides its documentation arrow until pointer hover; existing keyboard and optional status-bar controls do not solve first-use discoverability. Keep this team-authored request open for a design decision, supported by another maintainer encountering the same discovery problem.

## Change summary

Make suggestion documentation discoverable without hovering over a completion, through a persistent affordance or initially expanded details.

## Best solution

Provide a discoverable documentation control in the default suggest widget while keeping completion labels primary and preserving keyboard access. A maintainer should choose between a persistent affordance and initially expanded, collapsible documentation before implementation.

- **Behavior:**

  > Users opening completion suggestions with documentation should be able to discover that documentation without first hovering over the focused row or already knowing a shortcut. The default collapsed interface currently hides that capability. Acceptance should cover a fresh profile, pointer-independent discovery, expansion and collapse, and continued keyboard access. Existing completion acceptance and readable suggestion labels must remain unchanged.
- **Trace:**

  > ItemRenderer in src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts creates the readMore chevron and enables its toggle handler when canExpandCompletionItem reports available details. src/vs/editor/contrib/suggest/browser/media/suggest.css hides the affordance with visibility: hidden and reveals it only on focused:hover; separate selectors suppress it for docs-side and with-status-bar states. SuggestWidget.toggleDetails controls expansion, and _isDetailsVisible reads expandSuggestionDocs from profile storage with default false. suggestController.ts registers toggleSuggestionDetails and the optional Show More/Show Less status-bar controls; those alternatives do not address default first-use discovery. The related discussion at https://github.com/microsoft/vscode/issues/247574#issuecomment-2837653645 independently exposes the discovery difficulty, but its missing-description work is separate. Preserve completion acceptance, documentation eligibility, existing keyboard access, and user collapse preferences; the unresolved boundary is the default presentation, not the ability to render documentation.
- **Open decisions:**
  - Should the default suggest UI expose a persistent documentation affordance while retaining collapsed details, or initially show collapsible documentation?
  - If a persistent affordance is chosen, should it appear only on the focused expandable suggestion or on every expandable suggestion?
