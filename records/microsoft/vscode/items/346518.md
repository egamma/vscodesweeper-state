# Issue #346518 — Remote-SSH(from Mac) to Windows waits 300 seconds for Agent Host Supervisor before opening the workspace

[https://github.com/microsoft/vscode/issues/346518](https://github.com/microsoft/vscode/issues/346518)

## Summary

Keep open: current CLI source still awaits supervisor readiness before checking or starting the editor server, allowing an optional component to delay editing for 300 seconds. The related download report does not supersede this blocking-startup issue.

## Change summary

Prevent unavailable Agent Host Supervisor startup from blocking ordinary Remote-SSH workspace opening for five minutes.

## Best solution

Allow ordinary remote editing to proceed independently of slow or failed supervisor provisioning, while preserving agent-host connectivity when available. Resolve the startup and bridge-availability contract in the core CLI rather than transferring this report solely because Remote-SSH exposes it.

Acceptance must cover already-ready, failed, and delayed supervisor readiness and explicitly establish what agent functionality users receive when readiness occurs after the workspace opens.
- **Trace:**

  > command_shell() in cli/src/commands/tunnels.rs creates a lazy shared ensure_supervisor_running() future and passes it into the control server. handle_serve() in cli/src/tunnels/control_server.rs awaits it before even checking the editor server; spawn_supervisor_and_wait_ready() in cli/src/commands/agent_host.rs can wait 300 seconds. - **Open decisions:**
