# Issue #208368 — [folding] fold only code

[https://github.com/microsoft/vscode/issues/208368](https://github.com/microsoft/vscode/issues/208368)

## Summary

This remains a valid Backlog feature request with 23 community upvotes. Current folding-level commands still collapse comment ranges, and neither an existing command nor a broader canonical issue fully provides the requested code-only folding behavior.

## Change summary

Allow level-based folding to collapse code while leaving block comments visible.

## Best solution

Provide a coherent code-only folding workflow in the editor folding contribution, while resolving whether this should be a persistent exclusion option, a dedicated command, or composition with an Unfold All Block Comments command. The related open PR should be reviewed as a possible building block, but it does not by itself make level folding exclude comments.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Extend the editor folding tests with typed code and comment ranges, then verify the chosen code-only workflow collapses code at each requested level while leaving comment ranges expanded and preserving existing Fold Level and Fold All behavior.
- **Behavior:**

  > Users can invoke the selected code-only folding workflow at a folding level without collapsing block-comment ranges at that level. Existing general folding commands retain their established behavior unless the chosen public option is enabled. Comment handling works for providers that return FoldingRangeKind.Comment and has defined behavior for indentation-based ranges without type metadata.
- **Trace:**

  > FoldLevelAction in src/vs/editor/contrib/folding/browser/folding.ts delegates directly to setCollapseStateAtLevel in src/vs/editor/contrib/folding/browser/foldingModel.ts, whose filter considers level, collapse state, and selected lines but not FoldingRegion.type. Comment types are already represented by FoldingRangeKind.Comment and consumed by FoldAllBlockCommentsAction through setCollapseStateForType. https://github.com/microsoft/vscode/issues/85783 tracks the narrower inverse command, and https://github.com/microsoft/vscode/pull/250410 is an open implementation of that command; planning should determine whether landing it sufficiently supports composition or whether level folding needs its own public behavior. Keep ordinary Fold Level semantics and non-comment folding providers outside the selected opt-in behavior unchanged.
- **Open decisions:**
  - Should code-only folding be a persistent editor setting affecting existing Fold Level commands, a separate family of commands, or a single composable command paired with Unfold All Block Comments?
  - When a folding provider does not identify comment ranges with FoldingRangeKind.Comment, should the feature fall back to language comment tokens or leave those untyped ranges unchanged?

## Evidence

- **current source:** src/vs/editor/contrib/folding/browser/folding.ts defines FoldLevelAction using setCollapseStateAtLevel without filtering FoldingRangeKind.Comment, while the only comment-specific action is editor.foldAllBlockComments.
- **available model capability:** src/vs/editor/contrib/folding/browser/foldingModel.ts exposes setCollapseStateForType and FoldingRegions retains provider range types, but the level-folding path does not use them to exclude comments.
- **community demand:** The request reached 23 upvotes and was moved to the Backlog after passing the documented 20-upvote threshold.
- **canonical search:** https://github.com/microsoft/vscode/issues/85783 is older and reports the same comment-folding pain, but requests only an Unfold All Block Comments command; that narrower command does not fully own this issue's broader request to prevent comments from folding at every level.
- **related implementation:** https://github.com/microsoft/vscode/pull/250410 is open and adds editor.unfoldAllBlockComments for https://github.com/microsoft/vscode/issues/85783. It provides a partial two-step workaround but does not change editor.foldLevel1 through editor.foldLevel7.
- **existing canonical status:** https://github.com/microsoft/vscode/issues/225673 was closed as a duplicate of this issue, confirming that this item currently serves as the canonical request for avoiding comment folding.
