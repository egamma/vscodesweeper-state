# Issue #294657 — Highliting optimisation is not always correct for asymmetric highlits

[https://github.com/microsoft/vscode/issues/294657](https://github.com/microsoft/vscode/issues/294657)

## Summary

Team-authored feature request with an open PR (#294658) that adds an `editor.occurrencesHighlight.asymmetric` setting. The PR is still open and under review — keeping the issue open until it lands.

## Change summary

The word highlighter's optimization assumes document highlights are symmetric, causing stale highlights when a language server returns asymmetric results (e.g., Dart pattern bindings, TypeScript shorthand properties).

## Best solution

Land or refine https://github.com/microsoft/vscode/pull/294658, which adds a language-overridable `editor.occurrencesHighlight.asymmetric` setting so the optimization only skips re-fetching within the original query word range. The assignee (@Yoyokrazy) should review the PR's approach against comment 5's simpler suggestion (always re-query when moving between highlight ranges, no setting needed).
