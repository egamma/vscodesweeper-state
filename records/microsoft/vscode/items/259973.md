# Issue #259973 — Allow MCP Servers in non-agent mode

[https://github.com/microsoft/vscode/issues/259973](https://github.com/microsoft/vscode/issues/259973)

## Summary

The request remains partially unmet: current Ask supports additional tools and exposes the tool picker through its custom-agent representation, but it does not restrict MCP choices to tools explicitly annotated as read-only and requiring no confirmation. The existing `chat-mcp` routing and On Deck milestone should remain.

## Change summary

Allow informational MCP tools in Ask mode while preserving a reliable read-only boundary.

## Best solution

Let Ask expose MCP tools whose metadata explicitly marks them read-only and whose invocation requires neither pre- nor post-execution confirmation, using the existing tool picker with an Ask-specific eligibility scope. Tools without those guarantees should remain unavailable in Ask.

- **Trace:**

MCP registration in `src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts` already derives confirmation properties from `readOnlyHint` and `openWorldHint`, but the picker does not use those properties to establish an Ask-specific boundary. Preserve Agent mode behavior and non-MCP tool selection; the unresolved boundary is the default enablement of qualifying MCP tools in Ask.
- **Open decisions:**

## Evidence

- **maintainer direction:** A maintainer proposed exposing tools with `readOnlyHint: true` that require no confirmation and noted that other modes would need a scoped tool picker: https://github.com/microsoft/vscode/issues/259973#issuecomment-3160660154.
- **existing Ask capability:** `extensions/copilot/src/extension/agents/vscode-node/askAgentProvider.ts` defines Ask as a read-only custom agent with a fixed default tool list plus the experimental `github.copilot.chat.askAgent.additionalTools` setting; MCP tools are not automatically selected based on their annotations.
- **current picker behavior:** `src/vs/workbench/contrib/chat/common/chatModes.ts` represents custom agents, including Ask, as `ChatModeKind.Agent`, so `ConfigureToolsAction` in `src/vs/workbench/contrib/chat/browser/actions/chatToolActions.ts` is available. `ChatSelectedTools.entriesMap` builds the picker from all prompt-referenceable tools and has no Ask-specific read-only filter.
- **available safety metadata:** `src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts` maps MCP `readOnlyHint` and `openWorldHint` to pre- and post-approval behavior, so the current source carries the metadata needed to distinguish informational tools from tools that may mutate state or require confirmation.
- **remaining gap:** The current picker can session-enable tools omitted from Ask's default configuration, including non-read-only MCP tools. Ask's prompt instructs the model not to modify files, but that instruction is not the annotation-based eligibility boundary described in the issue.
