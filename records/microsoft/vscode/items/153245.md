# Issue #153245 — All files & folders collapsed in Explorer view on start-up

[https://github.com/microsoft/vscode/issues/153245](https://github.com/microsoft/vscode/issues/153245)

## Summary

The shared Explorer state-restoration race was fixed after this report. Current main serializes tree-input initialization and preserves the restored state, so the WSL startup path can no longer replace it with an empty collapsed snapshot.

## Change summary

Explorer expansion state was lost whenever a single-folder WSL window restarted.

## Best solution

Treat this as completed by https://github.com/microsoft/vscode/commit/1bd2fc7937140bf342459ff895a87dff9b219eec, which fixed the shared asynchronous Explorer initialization path used by remote folders.

## Evidence

- **confirmed original defect:** A maintainer reproduced the WSL single-folder startup failure in https://github.com/microsoft/vscode/issues/153245#issuecomment-1175115337; disabling extensions did not affect it.
- **trigger and root cause:** In VS Code 1.68.1, ExplorerView.setTreeInput in src/vs/workbench/contrib/files/browser/views/explorerView.ts called tree.setInput immediately. Overlapping initialization calls from visibility and remote root/model changes could therefore read getViewState() after an input existed but before its asynchronous children were ready, replacing the persisted expansion state with an empty collapsed state—the same shared race diagnosed at https://github.com/microsoft/vscode/issues/187788#issuecomment-1635336527.
- **fix commit:** https://github.com/microsoft/vscode/commit/1bd2fc7937140bf342459ff895a87dff9b219eec adds setTreeInputPromise, awaits the previous Explorer tree initialization before starting another, and stores the recovered view state after collapse-state synchronization. Those diff lines directly prevent the reporter's restart-time state from being overwritten.
- **current main:** src/vs/workbench/contrib/files/browser/views/explorerView.ts:835-867 retains the serialized setTreeInput path and restores workbench.explorer.treeViewState from workspace storage; ExplorerService callers at src/vs/workbench/contrib/files/browser/explorerService.ts:129-134 now flow through that serialization.
- **release:** Shipped in 1.81.0 — the earliest release tag containing 1bd2fc7937 (verified against the repo's release tags).
