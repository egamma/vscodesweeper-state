- **Behavior:**

  > Restarting a window opened on a WSL folder should preserve the Explorer's expanded and collapsed nodes. The report identifies both Remote Explorer and the WSL `code` launcher as affected, while a saved WSL workspace appears unaffected. First establish whether current builds still exhibit this difference; acceptance requires repeated restarts to preserve manually chosen expansion state without changing local or saved-workspace behavior.
- **Trace:**

  > ExplorerView stores tree.getViewState() on storageService.onWillSaveState and restores it in doSetTreeInput() through tree.setInput(input, viewState), in src/vs/workbench/contrib/files/browser/views/explorerView.ts. Single-folder input selection differs from workspace input, including when a root has an error. ExplorerDataSource.getChildren() in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts resolves remote children asynchronously and has distinct single-folder root-error handling. A maintainer confirmed the original failure at https://github.com/microsoft/vscode/issues/153245#issuecomment-1175115337, but source inspection did not establish the current failing transition. Diagnose persistence versus remote initialization before choosing an implementation; preserve existing workspace and local-folder semantics.
