# Issue #266476 — Improve handoff workflow between cloud and local chat sessions

[https://github.com/microsoft/vscode/issues/266476](https://github.com/microsoft/vscode/issues/266476)

## Summary

Keep open: current main supports conversation delegation and initial commit/push assistance, but cloud follow-ups still bypass local-change synchronization. The broader round-trip workflow remains necessary; verified related requests are newer and do not cover its full scope.

## Change summary

Make local-to-cloud-to-local iteration preserve conversation continuity and clearly coordinate branch synchronization.

## Best solution

Build on the existing continuation and cloud-session surfaces to provide a linked round-trip workflow with explicit branch freshness and synchronization affordances. Agree on consent and conflict behavior before integrating local edits into cloud follow-ups.

- **Behavior:**

  > Users can iterate between local work and a cloud task without reconstructing the conversation or guessing whether their code has reached the other side. A local continuation remains visibly associated with its originating cloud task. Returning to cloud work makes the status of local edits explicit, and incoming cloud commits are discoverable before local iteration resumes. Acceptance must cover the full seven-step flow in the report, including cancelled synchronization and divergent branches.
- **Trace:**

  > ContinueChatInSessionAction and CreateRemoteAgentJobAction in src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts already provide cross-provider delegation with transcript and repository context. CopilotCloudSessionsProvider in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts assists initial delegation with commit/push confirmation, using CopilotCloudGitOperationsManager. Existing-session follow-ups take a separate path to backend.sendFollowUpToTask and do not invoke that initial synchronization flow. Task-content refresh must not be mistaken for local Git fetch/pull. The uncertainty starts at the intended consent, branch-update, and conflict behavior of the round trip, rather than whether initial delegation exists. Preserve existing delegation and cancellation behavior; do not broaden this into account-wide conversation memory. Related narrower work is https://github.com/microsoft/vscode/issues/275963 and https://github.com/microsoft/vscode/issues/302107.
- **Open decisions:**
  - When sending a cloud follow-up with local edits, should synchronization require explicit confirmation, be opt-in automatic, or remain a separate action?
  - When the remote branch advances or diverges, should the workflow only indicate freshness and offer retrieval, or automatically update the local checkout under defined safe conditions?
  - Should local continuation create a linked independent conversation or present the cloud task and local work as one continuing conversation?
