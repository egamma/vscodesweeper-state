# Issue #185316 — Command Center customization

[https://github.com/microsoft/vscode/issues/185316](https://github.com/microsoft/vscode/issues/185316)

## Summary

Keep this accepted, 57-upvote request open: current Command Center controls do not let users add or edit arbitrary command buttons. The linked configurable-menus request is related, but does not establish the same Command Center-specific behavior required for a duplicate close on this re-review.

## Change summary

Allow users to add and edit icon-bearing command buttons beside the Command Center navigation controls.

## Best solution

Provide opt-in command-button customization through a consistent workbench customization model, retaining the existing default layout. Coordinate with the user-configurable menus work while explicitly deciding how users configure this Command Center surface.

- **Fit:** aligned

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts`, `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/services/actions/common/menusExtensionPoint.ts`
- **Validation:** In a development window, use the agreed customization surface to add a built-in command and an installed extension command with icons beside navigation; verify each invokes the selected command, editing updates the button, and removing customization restores the default layout. Check keyboard access and accessible names, and verify reload behavior against the agreed persistence contract.
- **Behavior:**

  > Users want visible, customizable command buttons beside navigation in the Command Center, including commands supplied by extensions. Existing visibility toggles and editor-action relocation do not satisfy that request. Acceptance should demonstrate adding and editing icon-bearing buttons and invoking the selected commands without changing the uncustomized default experience. The configuration surface and persistence semantics must be agreed before implementation.
- **Trace:**

  > CommandCenterControl in src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts renders MenuId.CommandCenter using MenuWorkbenchToolBar with HiddenItemStrategy.NoHide; CommandCenterCenterViewItem renders the central registry-defined action groups. Title-bar composition lives in src/vs/workbench/browser/parts/titlebar/titlebarPart.ts, and existing visibility configuration is registered in src/vs/workbench/browser/workbench.contribution.ts. Extension menu contribution contracts are defined in src/vs/workbench/services/actions/common/menusExtensionPoint.ts. Source inspection established the existing rendering and visibility mechanisms, not an implemented user customization contract. Coordinate the design with https://github.com/microsoft/vscode/issues/9285, which the maintainer linked as mostly related, while preserving this report's specific placement requirement. Preserve navigation, command execution semantics, and the default layout; uncertainty starts at how user-authored customization is represented, exposed, and persisted.
- **Open decisions:**
  - Should users configure these buttons through a shared menu-customization document, a dedicated setting, or an interactive customization surface?
  - Is the button configuration user/profile-wide or workspace-specific, and should it participate in Settings Sync?
