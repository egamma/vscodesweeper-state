# Issue #319177 — Recommend Config-Driven Approach to Avoid Magic Numbers in Copilot-Generated Code

[https://github.com/microsoft/vscode/issues/319177](https://github.com/microsoft/vscode/issues/319177)

## Summary

This is a valid but broad product request to change Copilot's default code-generation guidance. Current custom instructions provide project-specific control, but they do not satisfy the request for a context-sensitive default across all users, so the request should remain open for product discussion.

## Change summary

Teach Copilot to prefer validated configuration layers over hardcoded values when generated code contains tunable, environment-specific, operational, deployment-specific, or security-sensitive values.

## Best solution

Evaluate a context-sensitive generation guideline that distinguishes genuinely tunable values from invariants without imposing configuration-file boilerplate on small examples. Preserve custom instructions as the immediate project-specific mechanism, and only change the global default if prompt evaluations show a consistent quality improvement across languages and project types.
