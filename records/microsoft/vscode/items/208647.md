# Issue #208647 — [jsonl] Support `JSON` formatter in `JSONL`

[https://github.com/microsoft/vscode/issues/208647](https://github.com/microsoft/vscode/issues/208647)

## Summary

JSONL formatting remains unsupported on current main, but the JSON maintainer explained that proper language-service support requires broader adaptation and that a dedicated formatter extension is substantially easier. The Backlog milestone indicates the request remains accepted for consideration, so it should stay open under discussion rather than be closed solely on extension-fit grounds.

## Change summary

Allow Format Document to format each JSON value in a JSON Lines document without switching the document language to JSON.

## Best solution

Prefer a focused JSONL formatter extension unless the JSON maintainers decide to add complete JSONL semantics to vscode-json-languageservice; merely registering JSONL with the existing JSON client would expose language features whose single-document assumptions do not match JSON Lines.

## Vision fit

- **Fit:** rejected
- **Reason:** A specialized JSONL formatter can be delivered through the extension API without expanding the built-in JSON language service and therefore fits the extension ecosystem better than core.
- **Evidence:** Values and guardrails: "The power lives in extensions" and capabilities that can be built well with the extension API generally belong in an extension.

- **formatter boundary:** extensions/json-language-features/client/src/jsonClient.ts registers its document range formatter against the complete language-participant selector and forwards formatting to the JSON language server; JSONL therefore cannot be enabled as an isolated formatter by the proposed one-line registration.
