# Issue #327415 — Blocked: `net::ERR_CONNECTION_CLOSED` for every plan write attempt on GitHub Copilot

[https://github.com/microsoft/vscode/issues/327415](https://github.com/microsoft/vscode/issues/327415)

## Summary

Keep open: an independent reporter confirms that longer Copilot Agent tasks terminate with connection-closed errors while short requests work. Neither a fix nor an older canonical covering the same observable plan-writing failure has been established.

## Change summary

Long-running Copilot planning and file-generation tasks fail with net::ERR_CONNECTION_CLOSED instead of completing.

## Best solution

Identify where the connection closes during a failing Agent turn by correlating Copilot request logs, streaming progress, and tool execution. Restore reliable completion of long plan-generation tasks without assuming that the generic firewall message identifies the cause.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/327415 describes repeated failures after requesting a plan file with Claude Sonnet 5 and Opus 5, despite compaction and reduced thinking effort. In https://github.com/microsoft/vscode/issues/327415#issuecomment-5075430300, the reporter confirms that requesting the plan as conversation output instead succeeds.
- **Independent reproduction:** https://github.com/microsoft/vscode/issues/327415#issuecomment-5083111045 confirms the same error on VS Code 1.130.0 on macOS, particularly during long planning and multi-step Agent tasks. Short requests succeed; interrupted responses retry and ultimately fail to complete. This corroborates the Windows report, but does not establish the transport or service root cause.
- **Current error-handling path:** extensions/copilot/src/platform/networking/vscode-node/electronFetcher.ts classifies errors whose messages start with net:: as fetcher errors. BaseFetchFetcher.getUserMessageForFetcherError in extensions/copilot/src/platform/networking/node/baseFetchFetcher.ts supplies the generic firewall advice, and ChatMLFetcher.processError in extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts:2136-2217 maps recognized fetcher errors to NetworkError. The displayed advice therefore does not prove a firewall problem or a file-write defect.
- **Canonical search:** Verified that https://github.com/microsoft/vscode/issues/253136 and https://github.com/microsoft/vscode/issues/253137 remain open. Their bodies cover general failed requests and model availability, respectively, rather than establishing the same long-running plan-write symptom. The older open https://github.com/microsoft/vscode/issues/295424 contains ERR_CONNECTION_CLOSED logs, but a matching error code alone does not establish that it owns this report's specific failure.
- **Related but distinct streaming failure:** https://github.com/microsoft/vscode/issues/321432 is open and older, but describes a streaming socket that never closes and leaves the Agent turn hanging indefinitely. This report instead observes a connection-closed error followed by unsuccessful retries; the related streaming investigation is useful context, not a verified duplicate under the re-review symptom requirement.
- **No demonstrated covering fix:** Inspected networking change f173dada5229da9fadda70e5c63b736ea0d81bb6, https://github.com/microsoft/vscode/commit/f173dada5229da9fadda70e5c63b736ea0d81bb6. It replaces JSON serialization with lone-surrogate sanitization, but the report contains no evidence of malformed surrogate input linking that change to the failing long-running requests. It is not sufficient grounds for a completed close.
