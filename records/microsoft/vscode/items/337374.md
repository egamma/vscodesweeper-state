# Issue #337374 — Agent hooks on Windows: Claude-format ${CLAUDE_PLUGIN_ROOT} hook fails - Local harness spawns WSL bash, passes a backslashed Windows path, and never sets the env var

[https://github.com/microsoft/vscode/issues/337374](https://github.com/microsoft/vscode/issues/337374)

## Summary

Thanks for the detailed report. It has concrete steps and a Claude Code control, but I could not run it or confirm a fix. No fixing commit or PR is visible, so this stays open. It likely shares a root cause with the related Windows hooks issue.

## Change summary

On Windows, a Claude-format plugin hook using ${CLAUDE_PLUGIN_ROOT} runs under WSL bash with a backslashed path, and CLAUDE_PLUGIN_ROOT is not set in the hook process.

## Best solution

Pick the Windows hook shell in the hook executor (prefer Git Bash for bash hooks). Substitute the plugin root in a form the chosen shell can resolve. Set CLAUDE_PLUGIN_ROOT in the spawned environment, as the docs state.
