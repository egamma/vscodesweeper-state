# Issue #290715 — Zen Mode is not using space well while center mode.

[https://github.com/microsoft/vscode/issues/290715](https://github.com/microsoft/vscode/issues/290715)

## Summary

The remaining space-utilization request is covered by the older, open centered-layout issue: opening a sidebar retains editor-area margins instead of using the available workbench space. Centered Layout can already be toggled independently while staying in Zen Mode.

## Change summary

Make centered Zen Mode use space better on smaller displays and allow sidebars to occupy the otherwise empty margins.

## Best solution

Consolidate the remaining layout work in https://github.com/microsoft/vscode/issues/60900, preserving this report's 14-inch laptop and 27-inch monitor scenario. Use the existing Toggle Centered Layout command for independently disabling centering without exiting Zen Mode.

These cover the remaining space-utilization request, not merely a related layout area.
- **Existing independent toggle:** src/vs/workbench/browser/actions/layoutActions.ts:66-96 registers workbench.action.toggleCenteredLayout in the Command Palette and View > Appearance, without excluding Zen Mode. It calls centerMainEditorLayout independently of toggleZenMode. src/vs/workbench/browser/workbench.zenMode.contribution.ts also registers zenMode.centerLayout, and src/vs/workbench/browser/layout.ts:1543-1546 applies changes to that setting while Zen Mode is active.
- **Remaining capability gap:** src/vs/workbench/browser/parts/editor/editorPart.ts:1077 and 1475-1479 constructs and sizes CenteredViewLayout inside the editor part. src/vs/base/browser/ui/centered/centeredViewLayout.ts computes both margins from that part's width and gives each empty margin a minimum size of 60. workbench.editor.centeredLayoutFixedWidth changes width preservation, while workbench.editor.centeredLayoutAutoResize handles multiple editor columns or complex editors; neither makes sidebars consume the workbench's centering margins.
