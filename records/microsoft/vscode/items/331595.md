# Issue #331595 — Agent host: a replayed client tool from a subagent is handled on the parent chat after a restart

[https://github.com/microsoft/vscode/issues/331595](https://github.com/microsoft/vscode/issues/331595)

## Summary

Well-grounded design writeup of a real gap: a replayed client tool call from a subagent, surviving a VS Code restart, gets routed to the parent chat instead of its subagent chat because none of the routing state (`_innerToParent`, `_subagentChats`, restored-subagent discovery) survives or is rebuilt across a restart. The fix requires coordinated changes and is explicitly contingent on the broader restructuring discussed in #330899, so this should be routed to the agent-host owners for a design call rather than closed or auto-fixed.

## Change summary

After a VS Code restart, a subagent's replayed client tool call is handled/attributed on the parent chat instead of the subagent chat that originally owned it.

## Best solution

Have the agent-host/Claude-provider owners decide whether to implement the three coordinated changes described (prime the inner->parent edge from the SDK's persisted subagent store, restore a subagent chat for a dangling `Task`, and populate `_subagentChats` on restore) or fold this into the larger client-tool-execution restructuring tracked in #330899 first; the reporter has offered to implement once a direction is chosen.
