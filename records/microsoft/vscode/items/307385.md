# Issue #307385 — Chat: Plan Mode immediately starts implementation when in Autopilot mode

[https://github.com/microsoft/vscode/issues/307385](https://github.com/microsoft/vscode/issues/307385)

## Summary

Keep this accepted Backlog request open and route it to the Plan-agent area. Current main intentionally auto-sends Plan's implementation handoff under Autopilot, but the discussion and 26 upvotes support deciding whether an explicit Plan selection should instead preserve a review boundary.

## Change summary

Prevent an explicitly selected Plan-mode session from automatically starting implementation merely because Autopilot is enabled.

## Best solution

Define a clear interaction between explicit Plan selection and Autopilot: users choosing Plan should have a predictable opportunity to review the completed plan, either through a review pause or an explicit permission transition, without losing Autopilot's end-to-end behavior in workflows that intentionally request it.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`
- **Validation:** Add a chat widget test covering a completed Plan response with Autopilot enabled and assert the chosen review-boundary semantics: explicit Plan selection must either retain the handoff for user review or perform the explicitly approved transition, without unexpectedly submitting `Start implementation`.
- **Behavior:**

  > When a user explicitly selects Plan mode while Autopilot is enabled, the resulting planning-to-implementation transition must be predictable and clearly match the selected contract. A completed plan must not unexpectedly impersonate a user action or destroy the opportunity to review when the chosen semantics require a pause. End-to-end Autopilot workflows that intentionally opt into automatic continuation must remain supported. Acceptance should cover completing a plan, presenting or executing its handoff as specified, and preserving any existing draft.
- **Trace:**

  > Current main implements the automatic transition in ChatWidget.renderChatSuggestNextWidget at src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:1853-1862: when the current permission level is Autopilot, it selects the first `send` handoff and invokes handleNextPromptSelection. Mode changes also call renderChatSuggestNextWidget through onDidChangeCurrentChatMode around lines 2721-2725, so explicit mode selection participates in this path. ChatSuggestNextWidget separately renders manual and Autopilot handoff controls in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSuggestNextWidget.ts. Preserve normal non-Autopilot handoffs, explicitly requested end-to-end Autopilot behavior, drafts, and response-mode attribution; the uncertainty is the intended public contract when the user explicitly chooses Plan while Autopilot remains active.
- **Open decisions:**
  - When a user explicitly selects Plan while Autopilot is active, should completion pause for plan review, or should Autopilot continue automatically into implementation?
  - If explicit Plan selection creates a review boundary, should Autopilot remain enabled but wait at the handoff, or should selecting Plan visibly downgrade the permission level to Bypass Approvals?
