# Issue #24830 — More font options

[https://github.com/microsoft/vscode/issues/24830](https://github.com/microsoft/vscode/issues/24830)

## Summary

Keep open: current token customization supports selective style overrides, but does not fully provide the requested editor-wide suppression of italics or bold. This accepted Backlog request also owns maintainer-directed font-customization follow-ups; no verified older canonical covers its full scope.

## Change summary

Provide font-style controls that can suppress editor italics or bold, with discussion also requesting separate fonts for different styles.

## Best solution

Define a consistent editor-level contract for suppressing unwanted font styles across syntax and semantic highlighting while retaining other theme styling. Assess the separate-font request against existing per-token fontFamily support rather than treating all font customization as missing.

Manually verify the selected control with a theme applying italic comments and bold keywords, semantic highlighting enabled and disabled, and a theme switch. No checks were executed during this read-only review.
- **Behavior:**

  > Users want to prevent unwanted italic or bold editor text without editing each theme's individual token rules. Existing scope-based overrides only partially meet this goal. Acceptance should demonstrate the chosen control consistently across syntax and semantic highlighting, preserve unrelated colors and decorations, and leave default rendering unchanged when the control is not enabled. Separate font families and custom bold weights are related requests that require an explicit scope decision.
- **Trace:**

  > themeConfiguration.ts registers the existing token customization settings, while colorThemeSchema.ts exposes TextMate fontStyle and fontFamily. ColorThemeData.resolveScopes selects TextMate styles by specificity; semantic style definitions and explicit boolean overrides live in tokenClassificationRegistry.ts. tokenization.ts emits the italic/bold classes and per-token font-family CSS. These paths establish partial existing coverage, not a universal suppression contract. Keep existing token customization and default theme behavior compatible; do not broaden this into workbench font customization. https://github.com/microsoft/vscode/issues/120425 records the maintainer's decision to track bold customization here, while https://github.com/microsoft/vscode/issues/32579 separately discusses global italic suppression. Uncertainty starts at the intended precedence of a global control and whether alternate font faces or weights belong in the same deliverable.
- **Open decisions:**
  - Should suppression override every resolved italic/bold style, including explicit user token rules, or suppress only styles supplied by themes and language providers?
  - Should the first deliverable cover independent italic/bold suppression only, or also include style-specific font families and configurable bold weights requested in the discussion and linked follow-up?
