# Issue #24830 — More font options

[https://github.com/microsoft/vscode/issues/24830](https://github.com/microsoft/vscode/issues/24830)

## Summary

A meaningful gap remains: advanced token rules can suppress styles or select another font per token, but VS Code has no simple global control for disabling italic or bold styling. Keep this Backlog request open for a product decision.

## Change summary

Add controls to disable bold or italic editor styling and choose alternate fonts for styled text.

## Best solution

Decide whether to add global font-style controls in the editor configuration while retaining `editor.tokenColorCustomizations` for scope-specific overrides. Avoid duplicating the per-token font-family support already present on main.

- **Reason:** Font accessibility and editor customization are relevant, but additional global toggles also create configuration and UI complexity.
- **Evidence:** The durable accessibility theme supports readable font choices, while the public guardrail favors uniform UI and theme-level mechanisms over one-off visual toggles.

## Evidence

- **remaining source gap:** Current main still emits fixed `.mtki { font-style: italic; }` and `.mtkb { font-weight: bold; }` rules in src/vs/editor/common/languages/supports/tokenization.ts, without an editor-level switch.
- **existing advanced workaround:** `editor.tokenColorCustomizations.textMateRules` supports overriding `fontStyle`; users documented setting it to an empty string in https://github.com/microsoft/vscode/issues/32579, but this requires identifying and overriding token scopes.
- **partial implementation:** Commit 79e3994280ff914844114eb9a28a725a4f16780a added per-token `fontFamily` support through color-token customization, satisfying the alternate-font portion for selected scopes but not providing global no-italic/no-bold controls.
