# Issue #202189 — Notebook/Cell code actions not available in editor context menu

[https://github.com/microsoft/vscode/issues/202189](https://github.com/microsoft/vscode/issues/202189)

## Summary

The requested context-menu discoverability remains missing: Source Action filters for source.* actions, not notebook.source.* actions. Related open notebook-menu work is newer than this report, so it does not qualify as a duplicate target under the re-review rules.

## Change summary

Expose notebook-level source code actions through notebook and cell-editor context menus instead of requiring save-time configuration.

## Best solution

Provide a discoverable notebook-source-action entry in the notebook contribution, with a clear distinction between cell-scoped and notebook-scoped actions. Coordinate with the related notebook context-menu work while preserving existing save-time behavior and ordinary editor source actions.

## Evidence

- **Current source-action command:** src/vs/editor/contrib/codeAction/browser/codeActionCommands.ts:183–222 registers editor.action.sourceAction and defaults its filter to CodeActionKind.Source. src/vs/editor/contrib/codeAction/common/types.ts:22–26 defines notebook and source as separate kind roots, so notebook.source.organizeImports.ruff is outside the default Source Action filter.
- **Existing save-time capability is not menu coverage:** src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts separates notebook-prefixed actions from cell actions. Notebook actions run against the first cell's model on explicit save, while ordinary configured actions run across cells. This supports the reported save workflow but does not supply the requested context-menu entry.
- **Formatting does not satisfy the request:** src/vs/workbench/contrib/notebook/browser/contrib/format/formatting.ts registers notebook.format and invokes checkAndRunFormatCodeAction. That exposes notebook formatting, not a general picker for notebook.source.* actions such as organize imports.
