# Issue #248124 — Cannot drag a file back into VS Code after deleting it

[https://github.com/microsoft/vscode/issues/248124](https://github.com/microsoft/vscode/issues/248124)

## Summary

Keep open: the supplied Windows Recycle Bin steps suffice to retest, but source inspection cannot confirm the native drag payload. The drop-handling code has changed since 1.99.3, without an identified fix for this specific behavior or a verified duplicate.

## Change summary

Dragging a deleted file from Windows Recycle Bin into the VS Code Explorer fails, although dragging files from ordinary folders works.

## Best solution

Establish what Windows supplies when dragging from Recycle Bin, then make Explorer import support that transfer or identify the native dependency limitation. Preserve the ability to choose a destination rather than treating Restore to the original location as equivalent.

- **Behavior:**

  > A file deleted to Windows Recycle Bin cannot be dragged into the VS Code Explorer, while ordinary filesystem files can. The desired outcome is that the user can recover the file into the selected destination with its original name and contents. Acceptance includes both the original folder and a different destination, without regressing ordinary external file imports. The existing Restore menu workaround is not equivalent because it restores to the original location.
