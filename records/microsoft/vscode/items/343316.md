# Issue #343316 — OAuth MCP server calls fail with 401 after adding a workspace folder replaces the extension host; Reload Window restores access

[https://github.com/microsoft/vscode/issues/343316](https://github.com/microsoft/vscode/issues/343316)

## Summary

Keep open: current source retains authentication providers bound to a disposed extension-host RPC, matching the reported cancellation followed by an unauthenticated 401. The report supplies sufficient reproduction steps, and the related reports describe different triggers and authentication paths.

## Change summary

Preserve working OAuth MCP authentication when adding a workspace folder replaces the extension host.

## Best solution

Ensure authentication providers owned by a replaced extension host cannot remain selectable through its dead RPC, while allowing the replacement host to recover authentication from persisted credentials. Preserve providers belonging to other live hosts and existing consent behavior.
