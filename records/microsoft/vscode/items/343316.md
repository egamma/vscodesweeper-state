# Issue #343316 — OAuth MCP server calls fail with 401 after adding a workspace folder replaces the extension host; Reload Window restores access

[https://github.com/microsoft/vscode/issues/343316](https://github.com/microsoft/vscode/issues/343316)

## Summary

Keep open: current source retains authentication providers backed by a disposed extension-host RPC connection, matching the canceled token lookup and subsequent 401 after adding a workspace folder. The report supplies sufficient reproduction details, and Reload Window is a workaround rather than a fix.

## Change summary

Preserve working OAuth MCP authentication across extension-host replacement when a single-folder window becomes a multi-root workspace.

## Best solution

Authentication providers must follow their owning extension host's lifecycle so subsequent MCP authentication uses a live provider and retains persisted sign-in state. Cover host replacement with a regression test without resetting OAuth registrations or deleting stored tokens.
