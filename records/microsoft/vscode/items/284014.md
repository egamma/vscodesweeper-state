# Issue #284014 — Files open in the same "floating" window as Chat

[https://github.com/microsoft/vscode/issues/284014](https://github.com/microsoft/vscode/issues/284014)

## Summary

Current main still routes file links into the active detached Chat window because its editor group is not locked. This is a confirmed, bounded Chat editor bug and should remain open for the Chat area.

## Change summary

File and function links clicked in a detached Chat window open beside Chat instead of in the main editor window.

## Best solution

Keep the detached Chat editor group reserved for Chat so ordinary file-link navigation selects a non-locked group in the main editor window, without changing explicit side-by-side navigation.

## Evidence

- **source reproduction:** src/vs/workbench/contrib/chat/browser/actions/chatMoveActions.ts opens Chat in AUX_WINDOW_GROUP, making the new auxiliary group active, but does not lock that group.
- **link routing:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts:912-929 opens clicked files with an undefined preferred group unless the user explicitly requests side-by-side opening.
- **root cause:** src/vs/workbench/services/editor/common/editorGroupFinder.ts resolves an unspecified target to the active group and redirects elsewhere only when that group is locked; therefore the active, unlocked detached Chat group receives the file.
- **locking configuration:** src/vs/workbench/browser/parts/editor/editorConfiguration.ts enables automatic locking by default for terminal, browser-preview, and process-explorer editors, but not workbench.editor.chatSession.
- **triage direction:** The existing contributor comment on https://github.com/microsoft/vscode/issues/284014 identifies editor-group locking and the terminal auxiliary-window behavior as the intended precedent.
