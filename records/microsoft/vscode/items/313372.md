# Issue #313372 — [Agents] Forked sessions do not use the default approval settings

[https://github.com/microsoft/vscode/issues/313372](https://github.com/microsoft/vscode/issues/313372)

## Summary

Still reproduces on main: the forkChat path in the agent host sessions provider does not propagate the source session's permission level or read the user's configured default permission level — it creates the new chat without any approval/permission configuration.

## Change summary

Forked sessions in the Agents window ignore the user's default approval setting (e.g. Bypass Approvals) and revert to the normal approval level.

## Best solution

The `forkChat` method in `baseAgentHostSessionsProvider.ts` should either inherit the permission level from the source session/chat or read the user's configured default via `ChatConfiguration.DefaultPermissionLevel` (as the copilot sessions provider does in `_defaultPermissionLevel()`). The fix should live in `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts` around line 3063 where `createChat` is called.
