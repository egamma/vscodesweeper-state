# Issue #333799 — Duplicate claude --resume processes accumulate per-message in Agents window, causing turn to complete but UI to stay stuck on "Processing"

[https://github.com/microsoft/vscode/issues/333799](https://github.com/microsoft/vscode/issues/333799)

## Summary

Thanks for the detailed report — the symptom matches a real gap in the Claude agent-host subprocess lifecycle: ordinary rebinds tear down the previous SDK subprocess fire-and-forget instead of awaiting its exit, so a slow-to-die process can keep running (and keep consuming CPU) alongside the freshly spawned resume process while the UI has already moved on to the new one.

## Change summary

Sending follow-up messages into a long-running Claude agent chat causes multiple `claude --resume=<sessionId>` processes for the same session to accumulate, eventually leaving the Agents window UI stuck on "Processing" even though the turn actually finished.

## Best solution

In `ClaudeSdkPipeline._rebindQuery` (src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts), the old warm subprocess is torn down via `void Promise.resolve(oldWarm[Symbol.asyncDispose]())...` (not awaited), unlike `shutdownAndWait()` which correctly awaits both `warm[Symbol.asyncDispose]()` and `query.return()` before proceeding. Bringing the ordinary rebind path in line with `shutdownAndWait`'s await-the-actual-exit contract (or otherwise fencing a rebind so the previous subprocess is confirmed gone before the new one is wired up as the UI's live source) looks like the natural fix, but this file's extensive phase-plan history shows the abort/rebind sequencing here is deliberately intricate, so this needs a maintainer familiar with that design rather than a blind change.
