# Issue #321881 — VS Code can become stuck reopening the Agent login window and prevent access to the normal editor

[https://github.com/microsoft/vscode/issues/321881](https://github.com/microsoft/vscode/issues/321881)

## Summary

Confirmed bug on current main: the agents window is not excluded from window-state persistence, so closing the normal editor before the agents window records it as `lastActiveWindow`, causing only the agents window to reopen on next launch. An unmerged fix exists on branch `dev/dmitriv/skip-agents-window-restore` but has no open PR yet.

## Change summary

Closing the normal VS Code editor before the Agent login window causes only the Agent window to reopen on next launch, locking users out of the normal editor.

## Best solution

Land the fix from `dev/dmitriv/skip-agents-window-restore` (commit eac6323415c): filter sessions windows out of `lastActiveWindow` selection in `saveWindowsState()` and out of `lastClosedState` tracking in `onBeforeCloseWindow()` in `src/vs/platform/windows/electron-main/windowsStateHandler.ts`. A PR should be opened for this branch.

## Evidence

- **source trace:** In `src/vs/platform/windows/electron-main/windowsStateHandler.ts` lines 163-166, `saveWindowsState()` picks the last active window without filtering `isSessionsWindow`, so the agents window can become `lastActiveWindow` in persisted state.
- **source trace (lastClosedState):** Line 254 of the same file sets `lastClosedState` for any window when `getWindowCount() === 1`, including the agents window — this feeds into `lastActiveWindow` on next restore.
- **unmerged fix:** Commit eac6323415c on branch `dev/dmitriv/skip-agents-window-restore` (2026-06-15) adds `isSessionsWindow` guards at both sites but has not been merged to main and has no open PR.
- **multiple confirmations:** Five independent reporters confirmed the bug across versions 1.125.0 through 1.130.0 on Windows and Linux.
