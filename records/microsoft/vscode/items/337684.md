# Issue #337684 — Agent Host chat stays Working after final answer while an attached background server runs

[https://github.com/microsoft/vscode/issues/337684](https://github.com/microsoft/vscode/issues/337684)

## Summary

Team-authored (hediet, MEMBER) and hard-protected from any judgment close regardless of merit; independently, this is a rigorously diagnosed real bug in the turn-completion contract that stays open on its own facts.

## Change summary

An attached background shell (e.g. a dev server) keeps the Agent Host chat in 'Working' indefinitely after the model's final answer, because the SDK withholds the terminal `session.idle` event while it runs.

## Best solution

Design a completion signal that separates 'foreground conversational work is done' from 'the SDK session still owns a running background process', likely requiring a coordinated change between the copilot-sdk/runtime's idle semantics and the host's onIdle handler in copilotAgentSession.ts, so completed turns don't wait on unrelated attached shells.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`
- **Validation:** A test or manual check that a turn with a final answer and a still-running attached background shell (mode: 'async', no detach) reaches a completed UI state (not stuck 'Working'), while the shell keeps running and its own status is separately surfaced.
- **Behavior:**

  > When the assistant delivers a final answer while an attached background command (e.g. a dev server started without `detach: true`) is still running, the chat should reach a completed/idle UI state rather than remaining 'Working' indefinitely. The background task should remain visibly running (as its own status), distinct from the conversational turn's completion. A later prompt answered while the same background task runs should also complete normally.
- **Trace:**

  > The only turn-completion path is `wrapper.onIdle` in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:6056, which the SDK fires as a terminal `session.idle`; per the reporter's controlled repro against the installed copilot-runtime.exe, that event is withheld whenever an attached background shell task is running, even after `assistant.turn_end` for the final answer. The host currently has no signal that separates 'foreground model/tool work has ended' from 'this session still holds an attached background process' — do not simply complete on every `assistant.turn_end` (it also fires between tool rounds) and do not auto-detach background commands (changes their intended cleanup semantics). Where the new boundary should be drawn (new SDK event vs. host-side foreground-completion heuristic) is the open design question.
- **Open decisions:**
  - Should the fix introduce a new SDK/runtime signal that distinguishes 'foreground turn complete' from 'session still owns background work', or should the host infer foreground completion from existing events (e.g. tracking active tool calls/pending messages) without relying on `session.idle` for UI purposes?
  - How should the UI represent a completed answer with a still-running background task — does 'Working' become a task-specific status, or does the turn simply complete while the task is shown separately?
  - Does this require a coordinated change to the `@github/copilot-sdk`/runtime package (outside this repo), and if so, what is the compatibility story for hosts talking to older runtime versions?

## Evidence

- **confirmed sole completion path:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:6056 registers `wrapper.onIdle(...)` as the only handler that calls `_completeActiveTurn`/clears the active turn; there is no alternate path keyed off `assistant.turn_end` alone, matching the report's claim that turn completion is entirely gated on the SDK's `session.idle`.
- **no existing attached/background carve-out:** Searching copilotAgentSession.ts for 'attachmentMode'/'executionMode'/'background' shell handling shows only detached-task logic (line 1962, `task.attachmentMode === 'detached'`); nothing distinguishes an attached background shell from foreground turn completion for idle purposes, confirming the gap is unaddressed on main.
- **author's own controlled repro:** The report includes an isolated reproduction against the exact installed copilot-runtime.exe with a fake model, showing `assistant.turn_end` fires but `session.idle` does not while an attached background command runs, and resumes only when the shell exits.
