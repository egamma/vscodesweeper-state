# Issue #160987 — [scss] Wrongly shown selector in SCSS

[https://github.com/microsoft/vscode/issues/160987](https://github.com/microsoft/vscode/issues/160987)

## Summary

The incorrect selector hover remains in the current CSS language service: a `[name="jmeno"]` attribute is mistaken for the element name. The issue should remain open and correctly routed to the existing CSS/LESS/SCSS area while the upstream model is fixed.

## Change summary

Show `<element name="jmeno">`, rather than `<jmeno>`, when hovering an SCSS attribute selector such as `[name="jmeno"]`.

## Best solution

Fix `microsoft/vscode-css-languageservice` so its selector model stores the element/tag name separately from HTML attributes, add a hover regression test for `[name="jmeno"]`, and then consume the corrected language-service release in `extensions/css-language-features/server`.

## Evidence

- **current upstream source:** https://github.com/microsoft/vscode-css-languageservice/blob/main/src/services/selectorPrinting.ts still stores both element names and selector attributes through `Element.addAttr`; `MarkedStringPrinter.doPrintElement` then treats `findAttribute('name')` as the tag name and omits that attribute from the rendered element.
- **dependency on main:** extensions/css-language-features/server/package.json currently consumes `vscode-css-languageservice` 7.0.0-next.2, so the affected hover behavior is supplied by that upstream dependency.
- **maintainer diagnosis:** In https://github.com/microsoft/vscode-css-languageservice/pull/299, the maintainer confirmed that `<jmeno>` is wrong and identified the collision between the model's element-name storage and the valid HTML `name` attribute. That PR was closed unmerged on 2026-09-08 because its proposed output was not the correct fix.
- **canonical check:** https://github.com/microsoft/vscode/issues/20488 concerns embedded grammar corruption and syntax highlighting, not the incorrect selector hover shown here, so it does not meet the stronger same-symptom duplicate bar for this re-reviewed issue.
