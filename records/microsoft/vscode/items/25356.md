# Issue #25356 — Problem saving keybindings

[https://github.com/microsoft/vscode/issues/25356](https://github.com/microsoft/vscode/issues/25356)

## Summary

The accidental chord-recording scenario remains possible on current main, and the Backlog request already has appropriate feature/UX classification. Existing confirmation and clearing controls mitigate it but do not provide the requested validation.

## Change summary

Warn about or prevent accidentally saving a keybinding sequence that begins with an unintended printable key.

## Best solution

Improve the keybindings editor recorder in `keybindingWidgets.ts` with a non-blocking warning or clearer replacement affordance for suspicious sequences, while preserving valid unmodified chords such as `g g`.

## Evidence

- **current source:** `src/vs/workbench/contrib/preferences/browser/keybindingWidgets.ts` records every resolved keyboard event as the next chord and performs no validation based on modifiers or likely accidental ordering.
- **existing mitigation:** The same widget requires Enter to accept and handles Escape separately; maintainer Alex Dima also explained these controls in the issue, but they do not detect or warn about the reported accidental sequence.
- **valid behavior constraint:** Current keybinding infrastructure intentionally supports sequences of chords, including unmodified keys, so blanket rejection or automatic reversal could invalidate legitimate bindings.
- **canonical search:** The related open request https://github.com/microsoft/vscode/issues/179018 concerns recording more than two chords and does not own this validation/accidental-input UX request.
