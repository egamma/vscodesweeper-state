## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/browser/terminalProcessManager.ts`
- **Validation:** On Windows with Git Bash as the default profile, repeatedly open and focus the integrated terminal and type a known command; also maximize/unmaximize the panel and immediately type the next character. Compare intended input, terminal display, and the command actually executed, with trace logging around input transmission. After diagnosis, establish a repeatable failing check and verify it passes without changing PowerShell or programmatic sendText behavior.
- **Behavior:**

  > Git Bash in the Windows integrated terminal intermittently omits the first typed character, producing an incorrect command. The report is independently confirmed on 1.133.0 and 1.136.0 and is especially noticeable after opening a terminal through the Claude Code shortcut. Every typed character should reach the shell once, including immediately after opening, focusing, or resizing the terminal. Acceptance must check the command received by the shell, not merely its visual echo.
- **Trace:**

  > TerminalInstance in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts forwards xterm onData to _handleOnData and then TerminalProcessManager.write; sendText uses a separate entry point into the same manager. TerminalProcessManager in src/vs/workbench/contrib/terminal/browser/terminalProcessManager.ts awaits PTY readiness and forwards or queues the complete input string, while setDimensions handles resizing separately. Inspection did not establish where the character disappears, and no runtime reproduction was attempted in the read-only checkout. The related discussion at https://github.com/microsoft/vscode/issues/275625#issuecomment-3735924908 provides a resize/immediate-typing trigger, but https://github.com/microsoft/vscode/issues/275625#issuecomment-4136229585 distinguishes it from programmatically sent commands. Preserve existing shell profiles, input semantics, and programmatic command behavior; do not assume the older PowerShell/revive fix resolves this report. The first investigation should locate the loss using Windows input/PTY traces before deciding whether the defect belongs in VS Code or an upstream component.
