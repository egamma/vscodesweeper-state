# Issue #209188 — Using a vscode:// link with ?new-window or ?reuse-window still hijacks existing window

[https://github.com/microsoft/vscode/issues/209188](https://github.com/microsoft/vscode/issues/209188)

## Summary

Confirmed bug: the protocol URL handler in handleProtocolUrl only checks for `windowId=_blank` to decide whether to open a new window; the `?new-window` and `?reuse-window` query params are completely ignored, so the URL always reuses the existing window regardless of these parameters.

## Change summary

Using vscode:// remote links with `?new-window` or `?reuse-window` query parameters ignores those parameters and always hijacks the existing window.

## Best solution

In `src/vs/code/electron-main/app.ts` `handleProtocolUrl`, add handling for `new-window` and `reuse-window` query parameters (similar to the existing `windowId=_blank` check) to set `shouldOpenInNewWindow` appropriately before the openable is processed.
