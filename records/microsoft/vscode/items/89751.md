# Issue #89751 — Untitled file title gets in my way when trying to save

[https://github.com/microsoft/vscode/issues/89751](https://github.com/microsoft/vscode/issues/89751)

## Summary

Keep open: the simple save dialog still explicitly reinserts the suggested filename when accepting a folder, and the untitled-label setting does not remove that interaction. This team-authored, On Deck request has maintainer design interest and remains the canonical thread for later reports of the same annoyance.

## Change summary

Allow users to navigate folders in the simple save dialog without repeatedly restoring an unwanted generated filename.

## Best solution

Make the suggested filename available without obstructing keyboard folder navigation in SimpleFileDialog. Settle the proposed distinction between typed navigation and explicit folder selection, or the author's alternative explicit suggestion row, while preserving intentional filename retention.

## Plan brief

- **Likely files:** `src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts`, `src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts`
- **Validation:** After choosing the interaction contract, add focused cases to simpleFileDialog.test.ts and run scripts/test.sh --run src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts. - **Behavior:**

  > Saving a content-bearing untitled editor through the simple file dialog should allow uninterrupted navigation through nested folders without repeatedly imposing an unwanted generated filename. A user who wants the suggested filename should still have a predictable way to retain or choose it. Acceptance must distinguish typed path segments, keyboard folder acceptance, and mouse folder selection, and must cover both content-derived labels and ordinary Untitled names. Existing-file Save As behavior and deliberate custom filenames must remain predictable.
- **Trace:**

  > SimpleFileDialog.pickResource in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts captures the default basename as this.trailing. onDidAccept passes that stored name into a forced updateItems call whenever a folder is accepted; updateItems appends it and places the cursor before it. Typed path changes also travel through handleValueChange and tryUpdateItems, so they should not be assumed identical to folder acceptance. workbench.editor.untitled.labelFormat changes label derivation but does not control this retention mechanism. The thread offers two different interaction directions without settling one. https://github.com/microsoft/vscode/issues/145656 records the related expectation that filenames survive navigation and must not be treated as a duplicate or casually regressed. Keep the scope in the simple dialog rather than changing untitled tab naming or native save dialogs.
- **Open decisions:**
  - When navigating folders, should the suggested filename remain inline only for explicit mouse selection, remain inline for keyboard folder acceptance as well, or be available through an explicit 'Save as' suggestion instead?
