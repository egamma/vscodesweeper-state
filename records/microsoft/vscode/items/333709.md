# Issue #333709 — Automatically allow `read_file` access to Copilot terminal-output artifacts

[https://github.com/microsoft/vscode/issues/333709](https://github.com/microsoft/vscode/issues/333709)

## Summary

Traced and confirmed on main: the read-tool auto-approval path only recognizes SDK-spilled `copilot-tool-output-*.txt` temp files in `os.tmpdir()`, not the `<cacheHome>/copilot-terminal-output/` files the terminal tool writes — even though that directory is already registered as a sandbox read root per #330797. A small, localized addition closes the gap.

## Change summary

Extend the file-read auto-approval logic so VS Code-created `copilot-terminal-output-*.txt` files (written when terminal output exceeds the inline size limit) don't require a manual external-file confirmation for `read_file`, mirroring the existing SDK spill-file exception and the terminal sandbox's read-root exception.

## Best solution

Add a sibling check to `isCopilotSdkToolOutputTempFile` in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts (~line 3449) that recognizes files under `getTerminalOutputDirectory(cacheHome)` matching the `copilot-terminal-output-<uuid>.txt` basename pattern written by largeOutputFileWriter.ts, and auto-approves reads of them the same way the SDK tool-output exception does.
