# Issue #333709 — Automatically allow `read_file` access to Copilot terminal-output artifacts

[https://github.com/microsoft/vscode/issues/333709](https://github.com/microsoft/vscode/issues/333709)

## Summary

Real, well-diagnosed gap: large `run_in_terminal` output spilled to `<cacheHome>/copilot-terminal-output/` isn't recognized by the extension's `read_file`/`grep_search` access checks the way `chat-session-resources/` is, forcing an unnecessary external-file confirmation. A VS Code maintainer (roblourens, MEMBER) has already reproduced the double-spill flow in code and is actively working out the fix approach, so this should stay open and be resolved through that discussion.

## Change summary

Requesting that VS Code automatically grant `read_file`/`grep_search` access to the Copilot terminal-output spill files under `copilot-terminal-output/`, matching the existing automatic exception for `chat-session-resources/`.

## Best solution

Let the maintainer discussion (roblourens) settle on one of the two proposed fixes — either add `copilot-terminal-output` to the direct-read auto-approval alongside `isCopilotSdkToolOutputTempFile`-style checks in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, or have run_in_terminal spill directly into chat-session-resources via extensions/copilot/src/extension/prompts/node/chatDiskSessionResourcesImpl.ts instead of a separate core directory — then land whichever unifies the two spill mechanisms.
