# Issue #333709 — Automatically allow `read_file` access to Copilot terminal-output artifacts

[https://github.com/microsoft/vscode/issues/333709](https://github.com/microsoft/vscode/issues/333709)

## Summary

Keep open: current source still has the double-spill path and requires confirmation for the original terminal-output file. The maintainer has endorsed consolidating on existing session-resource paging rather than adding another file-access exception.

## Change summary

Allow Copilot to recover complete large terminal results through file-reading tools without an additional external-file confirmation.

## Best solution

Use the existing Copilot session-resource mechanism as the single owner of large terminal-result paging, following the maintainer's stated direction. Preserve independent output compaction and ordinary external-file confirmation behavior, and leave Agent Host unchanged.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/largeOutputFileWriter.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/outputHelpers.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalOutput.ts`, `extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx`, `extensions/copilot/src/extension/tools/node/toolUtils.ts`
- **Validation:** In the local Copilot harness with default generic paging and terminal output compaction disabled, run a command producing more than 20000 characters with identifiable beginning, middle, and ending markers. Verify that the complete result is recoverable through a session resource without an external-file confirmation or a second spill-file hop. Cover the result handoff in runInTerminalTool and ToolResult tests, and verify that unrelated external-file reads still require confirmation, small results remain usable, and existing compaction and paging-disabled behavior retain their documented semantics.
- **Behavior:**

  > Large run_in_terminal results should remain recoverable without requiring the user to approve a second read of an internally generated output artifact. With default generic paging, the agent should reach the complete result through the existing trusted session-resource flow rather than a preview that points to another external file. Acceptance should check beginning, middle, and ending content beyond the core size limit, unchanged small-result behavior, and continued confirmation for unrelated external files. Independent terminal output compaction and Agent Host behavior are outside the requested change.
- **Trace:**

  > RunInTerminalTool currently applies optional compaction and then passes outputForResult to LargeOutputFileWriter.processOutput, which replaces output above 20000 characters with a preview referencing a cache file. ToolResult.onText in extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx can subsequently page that preview into chat-session-resources at the default 8192-character threshold. getFileExternalConfirmation in extensions/copilot/src/extension/tools/node/toolUtils.ts trusts session resources, but the original terminal cache file falls through to external-file confirmation. The maintainer's chosen direction is recorded at https://github.com/microsoft/vscode/issues/333709#issuecomment-5501363707; it settles consolidation versus another access exception. The remaining planning work is to verify the complete terminal-result handoff supplies the generic paging prerequisites and enumerate the directory helper, cleanup, descriptions, sandbox-root wiring, and tests that depend on the terminal-specific spill convention. Preserve general file-access checks, generic paging configuration and fallback semantics, terminal metadata and images, independent compaction, and Agent Host behavior.

- **Current terminal spill path:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts:2523-2525 still calls LargeOutputFileWriter.processOutput after optional compaction. browser/largeOutputFileWriter.ts writes results exceeding MAX_OUTPUT_LENGTH to copilot-terminal-output and returns a truncated reference; browser/outputHelpers.ts defines MAX_OUTPUT_LENGTH as 20000.
