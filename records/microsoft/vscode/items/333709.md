# Issue #333709 — Automatically allow `read_file` access to Copilot terminal-output artifacts

[https://github.com/microsoft/vscode/issues/333709](https://github.com/microsoft/vscode/issues/333709)

## Summary

Real, well-diagnosed gap confirmed in source: getFileExternalConfirmation() in extensions/copilot/src/extension/tools/node/toolUtils.ts has explicit exceptions for chat-session-resources, debug logs, and transcripts, but no exception for the core terminal tool's copilot-terminal-output spill directory (written by src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/largeOutputFileWriter.ts) — so read_file on a file the agent was explicitly told to inspect triggers an avoidable external-file confirmation. A maintainer (roblourens) confirmed the root cause and design; no PR has landed yet.

## Change summary

read_file requires an external-file confirmation for VS Code-created copilot-terminal-output spill files, even though the same files are already trusted for the terminal sandbox and for run_in_terminal.

## Best solution

Add an automatic read-access exception in extensions/copilot/src/extension/tools/node/toolUtils.ts (getFileExternalConfirmation) for files under <cacheHome>/copilot-terminal-output/ — either by recognizing the path directly (mirroring the existing isDebugLogUri/isTranscriptUri/isSessionResourceUri checks) or by consolidating the double-spill flow so the terminal tool reuses chat-session-resources directly, per the maintainer's comment.
