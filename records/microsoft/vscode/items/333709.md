# Issue #333709 — Automatically allow `read_file` access to Copilot terminal-output artifacts

[https://github.com/microsoft/vscode/issues/333709](https://github.com/microsoft/vscode/issues/333709)

## Summary

Confirmed gap in current code: the extension's external-file confirmation check (`getFileExternalConfirmation` in toolUtils.ts) has no exception for the core-written `copilot-terminal-output` directory, so `read_file` on the very path the truncated terminal-output tool result tells the agent to inspect triggers an avoidable confirmation prompt. A MEMBER has already engaged with a detailed root-cause analysis, so this is actively being considered rather than needing routing.

## Change summary

When `run_in_terminal` output is spilled to a `copilot-terminal-output` file, `read_file` access to that file still requires an external-file confirmation instead of being auto-approved like other internal session resources.

## Best solution

Add an automatic file-access exception for the core-owned `copilot-terminal-output` directory alongside the existing checks (`isSessionResourceUri`, `isDebugLogUri`, `isTranscriptUri`) in `getFileExternalConfirmation`, or resolve it at the layering level the maintainer described (session-resource paging exposing the underlying core path). Either fix belongs in `extensions/copilot/src/extension/tools/node/toolUtils.ts`.
