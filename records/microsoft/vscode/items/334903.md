# Issue #334903 — Prev/Next navigation widget is above all editors

[https://github.com/microsoft/vscode/issues/334903](https://github.com/microsoft/vscode/issues/334903)

## Summary

The defect remains source-reproducible on current main: the multi-diff navigation toolbar is cleared asynchronously after the editor lifecycle has already moved to another editor. This team-authored issue should remain open for the bounded lifecycle fix and regression test.

## Change summary

The Changes editor's floating previous/next navigation toolbar remains visible above other editors, such as Browser, after switching tabs.

## Best solution

Ensure the multi-diff editor clears its view model and content-toolbar state during the synchronous editor-hide lifecycle, with a regression test proving no toolbar or model state survives into the next editor.

## Evidence

- **source trace:** On current main, `MultiDiffEditor.clearInput()` in `src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditor.ts` awaits `super.clearInput()` before clearing `_contentOverlay` and the widget view model, introducing an asynchronous gap during editor replacement.
- **editor lifecycle:** `EditorPanes.doHideActiveEditorPane()` in `src/vs/workbench/browser/parts/editor/editorPanes.ts` invokes `clearInput()` without awaiting it, then immediately hides/removes the old pane and activates the replacement, so deferred multi-diff cleanup can overlap the newly shown editor.
- **overlay visibility:** `MultiDiffEditorContentMenuOverlay` displays the floating toolbar whenever its resource remains defined and menu actions exist; `src/vs/editor/browser/widget/multiDiffEditor/style.css` positions that toolbar as an absolute overlay, while `src/vs/editor/contrib/floatingMenu/browser/floatingMenu.css` gives it z-index 10.
