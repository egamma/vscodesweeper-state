# Issue #341010 — Agents Window - Customizations: Enabling/disabling a plugin not working

[https://github.com/microsoft/vscode/issues/341010](https://github.com/microsoft/vscode/issues/341010)

## Summary

Keep open: a maintainer reproduced workspace-disabled plugins exposing skills on latest Insiders, and current source still publishes only their global enablement. The separate report of enabled plugins missing skills remains unconfirmed and already has a targeted clarification request.

## Change summary

- **Behavior:**

  > A plugin disabled for the applicable workspace must not contribute skills to a new Agents window chat in that workspace, even when globally enabled. Enabled plugins with valid discovered skills must remain available. Re-enabling restores availability, and a workspace-only change must not disable the plugin globally or in another workspace. The separately reported enabled-plugin discovery failure is not yet diagnosed and must not be treated as confirmed by this reproduction.
- **Trace:**

  > The maintainer reproduced the workspace-disable failure on latest Insiders in https://github.com/microsoft/vscode/issues/341010#issuecomment-6692257247. resolveCustomizationRefs in agentHostLocalCustomizations.ts publishes plugin enablement using readProfileEnabled only, although EnablementModel.readEnabled resolves workspace overrides first. AgentHostActiveClientService observes plugin.enablement changes and schedules publication, so a refresh can still resend the same global-only decision. The existing resolveCustomizationRefs test explicitly preserves global publication despite workspace overrides. AgentHostCustomizationEnablementService.applyClientGlobalEnablement consumes only Global entries and resolves host-owned workspace decisions separately by working directory; the trace has not established how the client workspace override should reach that host scope across all relevant sessions. Preserve global inheritance, host-owned decisions, and URI-space boundaries; do not collapse a workspace override into a global disable. https://github.com/microsoft/vscode/issues/329753 concerns a different disabled-store consolidation and is related background, not a duplicate.
