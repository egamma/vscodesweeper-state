[https://github.com/microsoft/vscode/issues/318234](https://github.com/microsoft/vscode/issues/318234)

## Summary

Plausible indentation bug in the apply_patch parser. The prior fix for missing indentation (commit c84c205deaa, issue #262549) broadened the additionalIndentation computation to always run, which may overcorrect in edge cases. The report lacks exact file content for a definitive reproduction, but the code path in parser.ts lines 404-431 is a credible source of the described symptom. No fix exists on current main.

## Change summary

The apply_patch tool adds an extra leading space when replacing an indented line with a slightly different indentation level.

## Best solution

Investigate the indentation adjustment logic in `extensions/copilot/src/extension/tools/node/applyPatch/parser.ts` (lines 404-431), specifically how `additionalIndentation` interacts with `transformIndentation` when the guessed `srcIndentStyle` and `targetIndentStyle` differ. The fix in commit c84c205deaa (#1329) for the inverse problem (missing indentation) broadened the adjustment to apply unconditionally, which likely overcorrects in cases where indentation styles are guessed differently between patch content and file content. A corpus test reproducing this exact scenario (Markdown fenced code block, 2→3 space change) should be added.
