# Issue #331141 — Pet shifting chat content based on window focus

[https://github.com/microsoft/vscode/issues/331141](https://github.com/microsoft/vscode/issues/331141)

## Summary

Team-authored, reopened issue with an assigned real milestone (1.137.0) — both hard keep-open rules. The merged fix (PR #331278) addressed the original 'pet disappears entirely' complaint, but the reporter's follow-up (distracting motion when cmd+tab-ing between VS Code windows) still reproduces in current source, and the maintainers are actively negotiating the exact desired behavior in the thread.

## Change summary

The chat pet still animates/relocates (blinks in and out) when switching focus between VS Code windows, which the reporter finds distracting, even after the initial 'single pet' fix landed.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/chatPetWidgetService.ts, the `onDidChangeFocusedWidget` listener calls `activate()`/`setHost()` on every focused-widget change including plain window-to-window focus switches (e.g. cmd+tab) with no chat interaction — justschen already proposed narrowing this to only re-home the pet when swapping between the editor and agents window (not on every OS-level focus change). That distinction still needs to be implemented and confirmed by roblourens.
