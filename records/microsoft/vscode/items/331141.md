# Issue #331141 — Pet shifting chat content based on window focus

[https://github.com/microsoft/vscode/issues/331141](https://github.com/microsoft/vscode/issues/331141)

## Summary

Team-authored issue that was reopened after the first fix (PR #331278) reduced but didn't eliminate the distracting animation — the pet still blinks in/out when switching between OS-level windows via cmd+tab, and it carries a real version milestone (1.136.0), so this stays open regardless of staleness or reopen status.

## Change summary

The chat pet's transition animation (attach/detach) still triggers distractingly when switching between VS Code application windows via OS-level focus changes (cmd+tab), not just when moving between the editor and agents windows.

## Best solution

justschen already proposed the right direction in the thread: only trigger the pet's attach/detach animation when swapping between the editor and agents windows within VS Code, not on OS-level app focus changes (cmd+tab out and back). That likely means gating ChatPetWidgetCoordinator.activate() (src/vs/workbench/contrib/chat/browser/widget/chatPetWidgetService.ts) or the chatWidgetService focus-change plumbing on genuine last-focused-widget changes rather than window blur/focus, so returning to the same VS Code window doesn't replay the transition.
