# Issue #251101 — Add onType rules similar to onEnter rules

[https://github.com/microsoft/vscode/issues/251101](https://github.com/microsoft/vscode/issues/251101)

## Summary

Keep open: current language configuration still lacks declarative on-type rules with the requested contextual matching. The existing brace-outdent heuristic has additional safeguards now, but those do not implement this maintainer-authored request.

## Change summary

Allow language configurations to specify contextual indentation rules for typed characters, analogous to onEnterRules.

## Best solution

Define a contextual on-type indentation contract in the editor language-configuration system, preserving brace outdent and selection-surround behavior. Settle its interaction with existing indentation rules before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages/languageConfiguration.ts`, `src/vs/editor/common/languages/languageConfigurationRegistry.ts`, `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/workbench/contrib/codeEditor/common/languageConfigurationExtensionPoint.ts`, `src/vscode-dts/vscode.d.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add targeted cursor tests demonstrating contextual outdent when typing an opening brace after an unbraced if, preserved wrapping of the selected multiline expression from https://github.com/microsoft/vscode/issues/224584, and unchanged behavior for languages without the new rules. Run the selected tests through scripts/test.sh after implementation; no tests were executed during this read-only review.
- **Behavior:**

  > Language authors should be able to describe indentation adjustments on typing using the previous line and text before and after the edited range. The motivating case is outdenting an opening brace beneath an unbraced if without breaking selection wrapping. Acceptance must cover the positive outdent case, the linked selection-wrapping scenario, and compatibility for languages that do not declare new rules.
- **Trace:**

  > LanguageConfiguration currently defines onEnterRules and IndentationRule, while the language-configuration extension point parses and maps those fields. getIndentActionForType in src/vs/editor/common/languages/autoIndent.ts performs on-type indentation through line-based rules and a guarded brace-outdent heuristic; no declarative contextual on-type contract is present. The current empty-selection and whitespace safeguards mean the historical regression cannot be assumed to remain unchanged. The maintainer discussion at https://github.com/microsoft/vscode/issues/224584#issuecomment-2959369889 establishes the motivation for this request, not a finalized API. Existing format-on-type providers are a separate programmatic mechanism. Preserve selection surrounding, intentional manual indentation, and existing language behavior while the new contract is designed.
- **Open decisions:**
  - Should matching on-type rules replace the existing indentation heuristic for configured languages, or run alongside it, and which result takes precedence?
  - Should the initial public contract support only outdent actions or a broader set of indentation actions analogous to onEnterRules?

## Evidence

- **Capability gap:** src/vs/editor/common/languages/languageConfiguration.ts exposes onEnterRules and line-based indentationRules, but no onTypeRules. src/vs/workbench/contrib/codeEditor/common/languageConfigurationExtensionPoint.ts:418–443 maps those existing fields into the editor configuration without an equivalent on-type field.
- **Current typing behavior:** src/vs/editor/common/languages/autoIndent.ts:getIndentActionForType still combines shouldIndentNextLine(previousLine) with shouldIncrease(textAroundRangeWithCharacter). Its current safeguards require an empty selection, inferred indentation matching actual indentation, whitespace-only surrounding text, and an auto-closing opening character; this remains a heuristic rather than configurable contextual rules.
- **Existing alternatives are partial:** editor.autoIndent selects existing indentation strategies, while editor.formatOnType enables formatting after typing. src/vscode-dts/vscode.d.ts:4598–4615 exposes OnTypeFormattingEditProvider for programmatic formatting edits, not declarative previous-line/before-range/after-range rules in language configuration.
