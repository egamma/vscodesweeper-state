# Issue #313111 — Agents: Consider moving `+` for sub-sessions to the tab title level

[https://github.com/microsoft/vscode/issues/313111](https://github.com/microsoft/vscode/issues/313111)

## Summary

The original top-level ambiguity has been mitigated by renaming and relocating the action, but the requested tab-level affordance remains deliberately absent on current main. This team-authored Backlog request also has explicit maintainer agreement, so it should remain open for a product decision.

## Change summary

Place the control for creating another chat within a session alongside that session's chat tabs so it is not mistaken for creating an independent session.

## Best solution

Provide an unambiguous, contextual creation affordance adjacent to the session's chat tabs, with wording or hover text that clearly distinguishes a new chat in the current session from a new independent session.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/chatCompositeBar.ts`, `src/vs/sessions/browser/parts/media/chatCompositeBar.css`, `src/vs/sessions/contrib/sessions/browser/sessionsActions.ts`, `src/vs/sessions/test/browser/chatCompositeBar.test.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsActions.test.ts`
- **Validation:** Run `scripts/test.sh --grep "ChatCompositeBar|Sessions - Actions"`; acceptance requires the chosen contextual affordance to appear only for sessions supporting multiple chats, invoke `sessions.chatCompositeBar.addChat`, and remain distinguishable from independent-session creation.
- **Behavior:**

  > Users must be able to tell whether a creation control starts an independent session or another chat inside the current session before activating it. For sessions supporting multiple chats, the in-session action should be contextually associated with the chat tabs and clearly identified as operating within the current session. Independent-session creation and sessions without multi-chat support must remain unchanged.
- **Trace:**

  > The in-session creation command is `sessions.chatCompositeBar.addChat` in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts; it calls `ISessionsService.openNewChatInSession` and is currently contributed to the session-header overflow and session-list surfaces. ChatCompositeBar in src/vs/sessions/browser/parts/chatCompositeBar.ts renders the tab row and a `Menus.SessionBarToolbar` action container, but src/vs/sessions/test/browser/chatCompositeBar.test.ts explicitly asserts that no New Chat control is rendered in the tab bar. The issue's behavioral concern is independently corroborated by https://github.com/microsoft/vscode/issues/316160. Keep the session/chat creation semantics, provider capability gating, keyboard shortcut, and unrelated tab behavior out of scope; the uncertainty begins at the desired presentation of the existing command.
- **Open decisions:**
  - Should the tab-level affordance be a directly visible plus control beside the tabs, or should the current explicit “New Chat in This Session” action remain named and visible within the tab-level toolbar?
