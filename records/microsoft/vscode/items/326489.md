# Issue #326489 — GitHub Copilot context window size difference of over 300K when switching models.

[https://github.com/microsoft/vscode/issues/326489](https://github.com/microsoft/vscode/issues/326489)

## Summary

This is a support question rather than an actionable defect: context usage reflects the selected model's own prompt construction and reported token accounting, so token counts are not expected to remain constant across models.

## Change summary

Explain why the context usage indicator changes substantially when an existing conversation switches between models with equal advertised context-window limits.

## Best solution

Keep the context indicator based on each model request's reported token usage; users should treat counts from different model families as model-specific rather than as a model-independent measurement of stored conversation history.

## Evidence

- **source behavior:** extensions/copilot/src/extension/intents/node/toolCallingLoop.ts reports `fetchResult.usage.prompt_tokens` and `completion_tokens` from the model response to the context widget, rather than deriving a model-independent size from the persisted conversation.
- **widget calculation:** src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts computes usage as the latest response's `promptTokens + completionTokens` against the selected model's context-window metadata.
- **model-specific tokenization:** extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts selects the tokenizer from each model's capability metadata, and extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts performs token counting through that endpoint-specific tokenizer.
- **conversation retained:** The report at https://github.com/microsoft/vscode/issues/326489 says switching back to Claude restored the greater-than-500K reading, which is evidence against conversation history having been summarized or discarded.
