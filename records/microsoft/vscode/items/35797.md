# Issue #35797 — Can we support CR line endings as well as LF and CRLF?

[https://github.com/microsoft/vscode/issues/35797](https://github.com/microsoft/vscode/issues/35797)

## Evidence

- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/302617 is OPEN with mergedAt null. Its body explicitly references this issue and proposes CR support in core enums, text buffers, model services, files.eol, the status-bar selector, and extension APIs. It is not a landed fix.
- **Current normalization path:** In src/vs/editor/common/model/pieceTreeTextBuffer/pieceTreeTextBufferBuilder.ts, PieceTreeTextBufferFactory._getEOL returns only '\r\n' or '\n' and counts standalone CR toward the CRLF majority. For CR-only input it selects CRLF; create() replaces standalone CR with that selected sequence when normalization is enabled. Recognizing CR as a separator therefore does not preserve CR as the document's EOL.
- **Existing capability check:** src/vs/workbench/contrib/files/browser/files.contribution.ts restricts files.eol to '\n', '\r\n', and 'auto'. In src/vs/workbench/browser/parts/editor/editorStatus.ts, workbench.action.editor.changeEOL offers only LF and CRLF. src/vs/editor/common/model.ts likewise defines only LF and CRLF for DefaultEndOfLine and EndOfLineSequence. None delivers the central request.
- **Duplicate and canonical checks:** The comment suggesting https://github.com/microsoft/vscode/issues/31286 does not justify consolidation: that issue is verified CLOSED. https://github.com/microsoft/vscode/issues/127 is OPEN but requests opting out of mixed-line-ending normalization, not the same observable missing CR mode required by the re-review duplicate bar. https://github.com/microsoft/vscode/issues/48063 is OPEN but covers the narrower cross-file search-and-replace corruption case and is younger than this report.

The discussion identifies concrete uses in HL7v2 healthcare messages, industrial protocols, retro computing, and Squeak/Pharo files, with reports of unwanted conversion on save. The Joomla example was corrected in-thread to concern LF and is not evidence for CR demand.
