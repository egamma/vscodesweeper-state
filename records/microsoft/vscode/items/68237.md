# Issue #68237 — Search with non-standard encodings not supported

[https://github.com/microsoft/vscode/issues/68237](https://github.com/microsoft/vscode/issues/68237)

## Summary

Keep open: workspace search still delegates encoding support to ripgrep, whose encoding backend does not cover CP437 and CP850. The editor's broader encoding support and the thread's partial workarounds do not satisfy this accepted request.

## Change summary

Support workspace searches, including accented characters, in legacy encodings such as CP437 and CP850 without converting the files.

## Best solution

Resolve the encoding limitation in ripgrep's transcoding backend and adopt that support on VS Code's workspace-search path. Preserve this issue as the existing backlog record; using a different encoding or searching only decoded open buffers is not equivalent.
