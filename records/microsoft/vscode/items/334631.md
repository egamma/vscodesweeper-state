# Issue #334631 — Agent host renders nothing for a skill that runs in a subagent

[https://github.com/microsoft/vscode/issues/334631](https://github.com/microsoft/vscode/issues/334631)

## Summary

Well-diagnosed report with code-level tracing that checks out against current main: a skill-spawned subagent has no tool-use id, so `SubagentRegistry` (keyed on `toolUseId`, see `claudeSubagentRegistry.ts:64/144-148`) never registers it, and the parent turn's zero-token `result` message is discarded in `claudeSdkPipeline.ts`'s `result` branch (around line 692) without ever becoming a response part — so the turn completes with a blank bubble even though the work finished successfully.

## Change summary

A skill invoked as a subagent (e.g. built-in /code-review) produces no visible chat output at all, even though the underlying agent completes real work recoverable from the SDK transcript; related symptoms include background-subagent launches being hidden almost immediately and a chat becoming permanently unusable after a cancelled skill-subagent turn.

## Best solution

Route to the Claude agent-host owners: (1) surface the `result` message's text as a response part when the turn spent zero model tokens, per the reporter's proposed guard in `claudeSdkPipeline.ts`; (2) reconsider keying `SubagentRegistry`/`recordSpawn` on something present for skill-spawned agents, not only a `Task`-call `toolUseId`; (3) separately review the `run_in_background` tool-call `presentation: "hiddenAfterComplete"` UX and the `shutdownAndWait`/session-reuse race described in the later comments, since those are distinct (if related) defects bundled into one report.
