# Issue #334631 — Agent host renders nothing for a skill that runs in a subagent

[https://github.com/microsoft/vscode/issues/334631](https://github.com/microsoft/vscode/issues/334631)

## Summary

Deeply traced, verifiable bug report: skill-invoked subagents (e.g. /code-review) spawn without a Task tool_use id, so ClaudeSubagentRegistry (keyed on toolUseId) never registers them and no subagent chat opens; the parent turn's result text is then discarded by ClaudeSdkPipeline instead of surfaced. Confirmed via current source, so this should be routed to the agent host area, not closed.

## Change summary

A skill run as a Claude subagent (and separately, a backgrounded subagent) produces no visible chat output even though the work completes and is recoverable from the SDK transcript; a related path can also permanently wedge a chat session.

## Best solution

In src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts, surface the `result` message's text as a response part when the turn produced zero response parts/tokens (as the reporter's local patch does), and separately fix SubagentRegistry/claudeSubagentResolver to recognize skill-spawned sidechain agents that lack a toolUseId; the `hiddenAfterComplete` presentation and wedged-session-reuse issues are related but distinct follow-ups worth tracking alongside this.

## Evidence

- **registry keyed on toolUseId:** src/vs/platform/agentHost/node/claude/claudeSubagentRegistry.ts: SubagentSpawn is constructed with `constructor(readonly toolUseId: string)` and SUBAGENT_TOOL_NAMES/SUBAGENT_ID_SUFFIX_REGEX only observe Task/Agent tool_use blocks — a skill-spawned sidechain agent with no toolUseId has no path to registration, matching the report.
- **result text discarded:** src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts around line 691-708: on `message.type === 'result'` the pipeline calls `this._router.handle(message, ...)`, then only settles the queue head and fires ChatTurnComplete — it never reads result text as a response part. `claudeSdkMessageRouter.ts` has no handling for 'result' either (grep found zero matches), confirming the text is dropped.
- **wedged-session code:** claudeSdkPipeline.ts `shutdownAndWait()` docstring: 'Awaiting that is what lets a caller safely reuse the --session-id (the CLI rejects a fresh spawn while <id>.jsonl still exists...)' matches the exact text quoted in comment 4, corroborating the reporter's trace of the session-reuse deadlock.
