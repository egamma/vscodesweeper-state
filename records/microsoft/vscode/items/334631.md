# Issue #334631 — Agent host renders nothing for a skill that runs in a subagent

[https://github.com/microsoft/vscode/issues/334631](https://github.com/microsoft/vscode/issues/334631)

## Summary

A well-diagnosed, source-traced defect in the Claude agent host: subagents spawned by the skill runner (rather than a `Task` tool call) are never registered in `SubagentRegistry` because it is keyed on `toolUseId`, and `ClaudeSdkPipeline`'s `result` branch discards the SDK `result` message's text without ever creating a response part — so the turn completes with an empty bubble even though real work happened. Two related symptoms (hidden `run_in_background` subagent launches, and a permanently unresumable chat after cancelling a skill-subagent-only first turn) are also traced but unfixed on main.

## Change summary

A skill run as a subagent (e.g. the built-in `/code-review`) produces zero visible chat output during and after its run, even though the work completes and is recoverable from the SDK transcript.

## Best solution

In the agent host's Claude pipeline, surface the `result` message's text as a response part when a turn completes having emitted zero response parts and spent no model tokens (guarding against duplicating a normal turn's already-streamed assistant text) — likely in src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts and/or claudeMapSessionEvents.ts's `mapResult`. The related run_in_background presentation issue and the unresumable-session-after-cancel issue are separate, larger fixes needing their own design (progress surfacing during subagent runs, and CLI transcript persistence for skill-subagent-only turns) and should likely be tracked as follow-ups if not already covered by https://github.com/microsoft/vscode/issues/333174 (unverified as a canonical — could not fetch its content in this environment to confirm scope).

## Evidence

- **registry keyed on toolUseId:** src/vs/platform/agentHost/node/claude/claudeSubagentRegistry.ts:SubagentRegistry stores spawns in `_spawns = new Map<string, SubagentSpawn>()` keyed by `toolUseId`, populated via `recordSpawn(toolUseId, ...)`; a skill-spawned agent (no `Task` tool_use, thus no `toolUseId`) has no entry point into this map, matching the issue's claimed root cause.
- **result text discarded:** src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts around line 692: `if (message.type === 'result') { const completed = this._queue.settleHead(); ... }` only logs `completed?.sdkUuid` and conditionally fires `ChatTurnComplete`; it never reads `message.result` text into a response part. src/vs/platform/agentHost/node/claude/claudeMapSessionEvents.ts's `mapResult` (lines 449-521) only emits `ChatUsage` and, for errors, a `ChatError`/error response part — no code path turns a successful `result.result` string into a normal response part.
