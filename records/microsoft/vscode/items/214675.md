# Issue #214675 — Diff Editor: setting for the word similarity heuristic threshold

[https://github.com/microsoft/vscode/issues/214675](https://github.com/microsoft/vscode/issues/214675)

## Summary

The requested control is still missing: the advanced diff algorithm retains a hardcoded word-similarity threshold, and existing algorithm selection does not expose it. Keep this accepted Backlog request open; a maintainer has explicitly consolidated another report here.

## Change summary

Allow Monaco consumers and VS Code users to configure when the advanced diff expands character changes into whole-word changes.

## Best solution

Provide an agreed control over word-expansion sensitivity while preserving current default output and protection against distracting random matches. Decide the public Monaco option and VS Code setting semantics using both small-edit examples and larger-replacement fixtures.

- **Behavior:**

  > Users want to control whether partially changed words retain character-level unchanged spans or are highlighted as whole-word replacements. The control must work through the supported Monaco options and agreed VS Code configuration surface without requiring the legacy algorithm. With no explicit override, existing diff output must remain unchanged. Acceptance should cover small identifier edits, threshold boundaries, and larger replacements where character alignment can introduce distracting random matches.
- **Trace:**

  > DefaultLinesDiffComputer.refineDiff calls extendDiffsToEntireWordIfAppropriate, whose equal-character comparison remains hardcoded to 2 / 3 in heuristicSequenceOptimizations.ts:280. The public editor options, configuration schema, document-diff options and line-diff options expose no corresponding sensitivity control; DiffEditorViewModel.computeDiff currently supplies whitespace, timeout and move options. The refinement path also performs forced subword expansion when requested and then removeShortMatches and removeVeryShortMatchingTextBetweenLongDiffs, so setting this one threshold to zero would not by itself guarantee a globally minimal character diff. ExternalLinesDiffComputer forwards a separate set of options to @vscode/diff, leaving backend applicability to establish. Preserve the current default, whitespace handling, timeout behavior and existing subword consumers unless the approved public contract explicitly changes them. Maintainer context is at https://github.com/microsoft/vscode/issues/210310#issuecomment-2150856346, and https://github.com/microsoft/vscode/issues/234275#issuecomment-2531134388 establishes this issue as the discussion target.
- **Open decisions:**
  - Should the supported public contract expose a numeric similarity threshold, named diff modes, or a numeric Monaco option paired with named VS Code modes?
  - Does a character-mode or zero-threshold choice disable only whole-word expansion, or promise character-level output that also bypasses other match-suppression heuristics?
  - Should the control apply only to the built-in advanced algorithm, or have equivalent semantics for advanced-external and advanced-wasm?
