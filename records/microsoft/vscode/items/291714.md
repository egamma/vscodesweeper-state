# Issue #291714 — Support starting cloud sessions for a specific repository in multi-repo workspaces

[https://github.com/microsoft/vscode/issues/291714](https://github.com/microsoft/vscode/issues/291714)

## Summary

Still a real, unresolved gap: there is no way today to target a specific local repo/folder when starting a cloud session from a multi-root workspace. A prior review's implemented-on-main claim (commit e2091bf2...) was already refuted by a second review, so I'm not re-citing it; the only related code I found (a `RepoPicker` widget) is scaffolding that isn't wired up yet, so this stays open.

## Change summary

Let users explicitly choose which repository/folder a cloud session should target when the workspace has multiple repos open.

## Best solution

Wire up the existing (currently unused) `RepoPicker` widget in src/vs/sessions/contrib/chat/browser/repoPicker.ts into the cloud session creation flow so a user can pick among the open workspace's local repos the same way `_browseForGitHubContext` already disambiguates multi-folder GitHub context in copilotChatSessionsProvider.ts.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/repoPicker.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`
- **Validation:** A test asserting that starting a new cloud session from a multi-root local workspace presents a repo/folder picker and the created session's workspace root matches the picked folder.
- **Behavior:**

  > When starting a cloud session from a workspace containing multiple local repositories/folders, the user should be able to explicitly pick which repo the session targets (mirroring the Source Control view's per-file repo targeting), instead of the session silently defaulting to an arbitrary folder or requiring a second VS Code window.
- **Trace:**

  > `_browseForGitHubContext` in copilotChatSessionsProvider.ts (~line 2355) already disambiguates among multiple workspace folders for the GitHub-context-attachment flow via `_pickRepository()`/`RepositoryPicker` (repositoryPicker.ts), but the normal 'start a cloud session from this local workspace' path does not appear to call into that same disambiguation for choosing the session's target repo. A standalone `RepoPicker` widget (src/vs/sessions/contrib/chat/browser/repoPicker.ts, added in commit 3a7c8e0181efe20e985490ab60dc5f434b48e5eb) implements the picker UI/storage behavior described in this issue but has no current callers anywhere in the codebase — confirmed via repo-wide grep. The open question is where in the session-creation flow this widget should be invoked and how it should coexist with the existing GitHub-context picker.
- **Open decisions:**
  - Should repo targeting be exposed per-session-creation (a picker shown when starting a new cloud session) or as a persistent per-workspace default, and where in the UI (chat input area vs. a dedicated Sessions view control)?
  - Should the already-built `RepoPicker` widget be wired into this flow, or does it serve a different purpose that first needs clarifying with its original author?
  - How should this interact with the existing `_browseForGitHubContext` disambiguation so there's one consistent repo-selection experience across local and GitHub-context entry points?
