# Issue #335919 — Cannot connect to remote agent host

[https://github.com/microsoft/vscode/issues/335919](https://github.com/microsoft/vscode/issues/335919)

## Summary

Reopened, team-authored bug tracking a real transport/client ownership defect that still reproduces on main (confirmed again with WSL on 2026-09-24); an open draft PR (#336330) already targets the architectural fix, so this stays open pending that PR landing rather than any close.

## Change summary

Reconnecting to a remote agent host (SSH or WSL) after an existing live connection is reused sends a fresh `initialize` request on an already-initialized transport, which the host rejects with `-32601 Method not found: initialize`, breaking the connection until automatic recovery kicks in.

## Best solution

Land the architectural fix tracked in draft PR https://github.com/microsoft/vscode/pull/336330, which enforces that a newly constructed protocol client always gets a fresh, uninitialized transport while a live transport keeps its existing protocol client; the narrower quick fix in #336315 only patched the SSH folder-picker path and WSL still hits the same root cause via `WSLRemoteAgentHostMainService.connect()` returning an existing live connection to a new protocol client.
