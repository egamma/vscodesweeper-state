# Issue #289467 — Give me control over empty state URI resolution in ChatContent Provider

[https://github.com/microsoft/vscode/issues/289467](https://github.com/microsoft/vscode/issues/289467)

## Summary

Keep open: current APIs let providers choose the real session URI on first send, but core still creates untitled resources and can pass them to the content provider for an empty session. This team-authored, reopened request has no verified issue-referencing fix; the closely matching open requests are newer and cannot serve as canonicals under the re-review rules.

## Change summary

Let chat-session extensions control empty-session URI creation and resolution without interpreting core-generated untitled URI conventions.

## Best solution

Define the provider-facing contract for blank-session identity and creation timing, then make the new-session and content-resolution paths honor it. Build on the existing controller creation callback rather than treating first-send URI materialization as complete coverage of the empty-state request.
