# Issue #267927 — SCM Graph item hover position incorrect after Issue Reporter opened and moved to second display

[https://github.com/microsoft/vscode/issues/267927](https://github.com/microsoft/vscode/issues/267927)

## Summary

This remains a confirmed multi-display workbench-hover bug with no linked fix or verified duplicate. The SCM hover implementation has since been refactored, but current source does not establish that the unfocused-window positioning defect was corrected.

## Change summary

Keep SCM Graph item hovers anchored to their rows after the Issue Reporter is moved to another display while the main window remains unfocused.

## Best solution

Reproduce the sequence against current main on Windows with two displays, determine whether the stale coordinate space originates in the generic hover layout or Issue Reporter window handling, and keep pointer hovers aligned without requiring the main window to regain focus.

- **Behavior:**

  > SCM Graph item hovers must remain positioned beside the hovered row, with the pointer aimed at that row, regardless of which VS Code window currently has focus or which display contains the Issue Reporter. Moving the Issue Reporter to another display must not change the coordinate space used by the main-window hover. Validate both before and after refocusing the main window, and in sidebar and panel graph locations.
- **Trace:**

  > The original Windows two-display sequence is team-confirmed in https://github.com/microsoft/vscode/issues/267927, but it has not been reconfirmed after the SCM hover refactor. SCM Graph rows now register delayed hovers in `HistoryItemRenderer._getHoverOptions()` in src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts. `HoverService` selects the target window/container in src/vs/platform/hover/browser/hoverService.ts, while `HoverWidget.layout()` in src/vs/platform/hover/browser/hoverWidget.ts derives coordinates from zoom-adjusted target bounds and target-window dimensions. The Issue Reporter is created through src/vs/workbench/contrib/issue/electron-browser/issueReporterService.ts; diagnosis should establish whether moving that window changes shared display, zoom, or focus state observed by the hover path. Preserve normal hover placement, SCM content, and Issue Reporter focus behavior; the scope is the stale cross-window coordinate state, not a redesign of SCM hovers.
