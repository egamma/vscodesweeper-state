# Issue #92177 — API for reading current word-wrap state (and toggling it) on a TextDocument

[https://github.com/microsoft/vscode/issues/92177](https://github.com/microsoft/vscode/issues/92177)

## Summary

A real extension API gap remains: extensions can invoke the toggle command, but cannot read the effective wrapping state or deterministically set it. This older, broader Backlog issue should remain the canonical request.

## Change summary

Expose the effective word-wrap state and deterministic wrapping control to extensions.

## Best solution

Design this as TextEditor-level API, likely through TextEditorOptions and onDidChangeTextEditorOptions, because effective wrapping is editor state. Consolidate the narrower open-on-wrap request at https://github.com/microsoft/vscode/issues/136927 into this API design.

## Evidence

- **current API gap:** src/vscode-dts/vscode.d.ts exposes tab size, indentation, cursor style, and line numbers through TextEditorOptions, but no word-wrap state or setter.
- **internal capability:** src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts tracks effective wrapping through EditorOption.wrappingInfo and stores a model-scoped transient override, but this state is not bridged through the extension-host API.
- **partial workaround:** The built-in editor.action.toggleWordWrap command exists, but a blind toggle cannot reliably disable wrapping and later restore the prior state.
- **related request:** https://github.com/microsoft/vscode/issues/136927 is open and asks only for setting initial wrapping when an extension opens a document, a subset of this issue's read-and-control API.
- **prior discussion:** https://github.com/microsoft/vscode/issues/70485 was auto-closed through info-needed after discussion of one mirroring use case; it did not implement the API or resolve the broader extension scenarios documented here.
