# Issue #239989 — Editor support for crossing out or otherwise marking symbols with specific doc-comment annotations (as is done for @deprecated)

[https://github.com/microsoft/vscode/issues/239989](https://github.com/microsoft/vscode/issues/239989)

## Summary

Keep open in the accepted Backlog: VS Code has APIs for extensions to decorate or strike through ranges, but no built-in configurable annotation policy providing the requested path-aware symbol restrictions.

## Change summary

Support configurable doc-comment annotations such as `@testonly` or `@restricted` that visually mark symbol usages outside allowed files or directories.

## Best solution

Implement the policy in a language-aware extension using existing diagnostics or editor decorations. Keep core work limited to a concrete editor or language API gap if an extension cannot reliably identify and decorate restricted symbol usages.
