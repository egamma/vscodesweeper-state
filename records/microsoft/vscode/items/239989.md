# Issue #239989 — Editor support for crossing out or otherwise marking symbols with specific doc-comment annotations (as is done for @deprecated)

[https://github.com/microsoft/vscode/issues/239989](https://github.com/microsoft/vscode/issues/239989)

## Summary

Keep this accepted Backlog request open: existing APIs can render the requested markings, but the inspected built-in surface does not provide configurable, usage-site-sensitive doc-comment restrictions. A maintainer should settle the annotation semantics and extension-versus-built-in boundary before implementation.

## Change summary

Mark references to annotated symbols when their use violates configurable testing, directory, or other restrictions without declaring those symbols deprecated.

## Best solution

Provide annotation-aware symbol-use feedback through a language-aware provider, retaining the existing editor decoration and diagnostic mechanisms where sufficient. First determine whether an extension can deliver the accepted scope or whether a concrete language-service or editor API capability is missing.

- **Trace:**

  > The inspected TypeScript diagnostic path is tsDiagnosticToVsDiagnostic in extensions/typescript-language-features/src/typeScriptServiceClientHost.ts, which maps language-service reportsDeprecated into editor diagnostic tags rather than interpreting annotations itself. editor.showDeprecated in src/vs/editor/common/config/editorOptions.ts is a rendering toggle, not an annotation policy. src/vscode-dts/vscode.d.ts already exposes text decorations and diagnostics, so the investigation must distinguish missing symbol analysis from missing editor rendering capability.
