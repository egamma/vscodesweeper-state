# Issue #229506 — SCM Graph - Render code backticks

[https://github.com/microsoft/vscode/issues/229506](https://github.com/microsoft/vscode/issues/229506)

## Summary

Inline code formatting remains missing from SCM Graph commit subjects on current main. Keep this accepted Backlog request open: the existing tree-label formatting does not cover it, and the older matching report was explicitly consolidated into this issue.

## Change summary

Render backtick-delimited inline code in SCM Graph commit subjects instead of displaying the delimiters literally.

## Best solution

Support inline code spans within SCM Graph commit subjects while preserving plain-text content, search highlighting, accessibility, and compact row layout. Decide whether this remains an SCM capability or also extends the MarkdownString label contract for extension-contributed trees.

- **Behavior:**

  > SCM Graph currently displays backtick-delimited code literally within commit subjects. The requested result is inline-code presentation within an otherwise ordinary single-line subject, without requiring users to open the hover. Acceptance should cover mixed prose and code, unchanged plain subjects, working search highlights, compact row layout, and meaningful accessible text. This request does not require general Markdown documents, links, or block rendering in graph rows.
- **Trace:**

  > HistoryItemRenderer.renderTemplate and renderElement in src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts create an IconLabel and pass historyItem.subject directly to setLabel; toHistoryItemHoverContent is a separate Markdown-rendered surface. Preserve graph topology, author rendering, badges, actions, and existing hover behavior; the uncertainty is whether the new observable capability should also become part of extension-contributed tree labels.
