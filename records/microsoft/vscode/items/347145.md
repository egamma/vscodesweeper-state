# Issue #347145 — Sandboxing: find better UI than placeholder text, for showing sandbox is enabled

[https://github.com/microsoft/vscode/issues/347145](https://github.com/microsoft/vscode/issues/347145)

## Summary

Keep open for design iteration: current main still appends the sandbox status to the placeholder, exactly the presentation this report asks to improve. The original implementation and its verification issue do not resolve this follow-up.

## Change summary

Replace the parenthetical sandbox-enabled placeholder suffix with a more polished status presentation.

## Best solution

Agree on a calm, consistent sandbox-status affordance for editor chat and the Agents window, then replace the placeholder treatment without changing sandbox enforcement or session-specific state.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputSandboxContribution.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputEditorContrib.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts`
- **Validation:** Manually compare the approved presentation in editor chat and the Agents window: toggle sandboxing, switch between differently configured chats, type and clear input, and narrow the window until Permissions enters overflow. Verify the intended visible status and screen-reader description remain accurate without changing submitted text.
- **Behavior:**

  > Sandbox-enabled chats currently append a parenthetical status to the empty input placeholder. The goal is a clearer, more polished presentation consistent across editor chat and the Agents window. Acceptance should cover enabled, disabled, unavailable, session-switching, and narrow-layout states, with accessible status information. The replacement's placement and visibility while typing need agreement before implementation.
- **Trace:**

  > getSandboxPlaceholder in chatInputSandboxContribution.ts constructs the suffix; chatInputEditorContrib.ts and chatWidget.ts consume it, while bindSandboxPlaceholder reconciles editor-option changes. AgentHostChatInputPicker also has an approval-trigger shield and accessible sandbox label, but combined mode/permissions rendering takes a separate branch. The original suffix was deliberately delivered by https://github.com/microsoft/vscode/pull/345997; this issue requests subsequent design refinement, not a synchronization fix. Preserve authoritative sandbox state, policy enforcement, submitted prompt contents, and session-switching behavior. The uncertainty begins at the user-visible replacement design, not the existing state plumbing.
- **Open decisions:**
  - Should sandbox status be represented within the Permissions control or as a separate chat-input status affordance?
  - Should the replacement remain visible while typing, or appear only when the input is empty?
