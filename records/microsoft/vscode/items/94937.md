# Issue #94937 — Truncate and copy large values from the debug console

[https://github.com/microsoft/vscode/issues/94937](https://github.com/microsoft/vscode/issues/94937)

## Summary

This team-authored Backlog request remains necessary: current core can recover full clipboard text only for expressions entered into the Debug Console, not values emitted through output events such as `console.log`. With 26 community upvotes and a newer report explicitly redirected here, it should remain the canonical issue.

## Change summary

Keep large Debug Console values safely truncated on screen while allowing users to copy their complete, untruncated representation.

## Best solution

Preserve bounded Debug Console rendering while defining a client/DAP contract that lets Copy retrieve the complete value for output-event values. Consolidate the overlapping work from https://github.com/microsoft/vscode/issues/187784 into this older canonical issue.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/browser/debugSession.ts`, `src/vs/workbench/contrib/debug/common/replModel.ts`, `src/vs/workbench/contrib/debug/common/debugProtocol.d.ts`, `src/vs/workbench/contrib/debug/test/browser/repl.test.ts`
- **Validation:** Extend the Debug REPL tests with a mock adapter output value whose displayed representation is truncated, then verify the chosen Copy action writes the complete representation while rendered output remains bounded; run `scripts/test.sh --grep "Debug - REPL"`.
- **Behavior:**

  > Large values emitted to the Debug Console remain bounded on screen so they cannot make the workbench unresponsive. A user can invoke Copy on a supported truncated value and receive its complete representation rather than the visible truncated text. Existing copying for selected text and expressions entered directly into the Debug Console remains unchanged, and adapters without the new capability retain their current fallback behavior.
- **Trace:**

  > The Debug Console Copy action in src/vs/workbench/contrib/debug/browser/repl.ts re-evaluates only ReplEvaluationResult using the DAP `clipboard` context. Ordinary output events become ReplOutputElement instances through src/vs/workbench/contrib/debug/browser/debugSession.ts and src/vs/workbench/contrib/debug/common/replModel.ts; copying them falls back to their already-truncated output string. The DAP OutputEvent shape in src/vs/workbench/contrib/debug/common/debugProtocol.d.ts has no evaluateName or full-value clipboard representation, matching the maintainer diagnosis in https://github.com/microsoft/vscode/issues/187784. The boundary is Debug Console output copying and safe rendering: do not remove output-size protection, alter Variables-view copying, or change selected-text semantics. The uncertainty begins at the public contract for obtaining complete output-event values.
- **Open decisions:**
  - Should complete copying be supported by moving truncation into the client so VS Code retains raw output, or by extending DAP with an explicit full-value/clipboard representation for output events?

## Evidence

- **current source gap:** src/vs/workbench/contrib/debug/browser/repl.ts:1190-1221 re-evaluates clipboard content only when the selected element is a ReplEvaluationResult. ReplOutputElement values instead fall back to element.toString(), so adapter-truncated output remains truncated when copied.
- **protocol boundary:** src/vs/workbench/contrib/debug/common/debugProtocol.d.ts:208-255 defines output events with display text and an optional variablesReference, but no evaluateName or full clipboard representation for the emitted value.
- **output data flow:** src/vs/workbench/contrib/debug/browser/debugSession.ts:1167-1190 converts an output event into a ReplOutputElement; src/vs/workbench/contrib/debug/common/replModel.ts:18-66 retains and copies the event's output string, which cannot recover content already truncated by the adapter.
- **related open issue:** https://github.com/microsoft/vscode/issues/187784 is a newer open report of the same full-copy limitation. A maintainer confirms there that evaluated expressions can be re-evaluated, while ordinary console output needs a new DAP mechanism; because it was created in 2023, it cannot be the canonical duplicate for this re-reviewed 2020 issue.

- **existing workaround:** The thread documents `copy(expression)` as a JavaScript-specific workaround, but that does not provide the requested UI action for arbitrary Debug Console output.
