# Issue #94937 — Truncate and copy large values from the debug console

[https://github.com/microsoft/vscode/issues/94937](https://github.com/microsoft/vscode/issues/94937)

## Summary

Keep open: copying full values is partially supported for evaluated expressions, but logged output still falls back to its potentially truncated representation. This team-authored Backlog request has 26 upvotes, maintainer support, and a remaining capability gap; no qualifying fix or older same-symptom canonical was established.

## Change summary

Provide a discoverable way to copy complete large values from the Debug Console while keeping their displayed representation safely bounded.

## Best solution

Support copying the complete value behind logged output without requiring users to reconstruct an expression or disable protective truncation. Resolve the UI-versus-adapter truncation and retrieval contract with the debug owners, preserving existing expression-copy behavior.

- **Behavior:**

  > Large logged values should remain safely bounded in the Debug Console while offering a discoverable way to copy their complete contents. Copying must retrieve the underlying value rather than its truncated preview, without requiring the user to enter copy(expr). Acceptance should compare a copied long string with its original contents, including data omitted from the preview. Existing expression copying and ordinary text selection must remain unchanged.
- **Trace:**

  > debug.replCopy in src/vs/workbench/contrib/debug/browser/repl.ts delegates to tryEvaluateAndCopy, which only re-evaluates ReplEvaluationResult using the clipboard context. ReplOutputElement and ReplVariableElement in src/vs/workbench/contrib/debug/common/replModel.ts expose their stored representations, so the fallback cannot recover adapter-omitted content. src/vs/workbench/contrib/debug/browser/replViewer.ts renders these different element types through separate renderers. The maintainer diagnosis at https://github.com/microsoft/vscode/issues/187784#issuecomment-1636230352 identifies the missing retrieval contract for logged output. The original thread favors UI-side truncation but does not settle that contract; retain protective display limits and do not treat unlimited rendering as the solution. The related requests are newer, and https://github.com/microsoft/vscode/issues/282565 explicitly consolidates onto this issue.
- **Open decisions:**
  - Should full-value availability come from transmitting complete values for UI-side truncation, or from an adapter/protocol capability that retrieves complete values on demand while retaining adapter-side previews?
