# Issue #322416 — New chat issue title changes twice

[https://github.com/microsoft/vscode/issues/322416](https://github.com/microsoft/vscode/issues/322416)

## Summary

Team-filed polish issue about chat titles updating twice (once from user input, once from agent-generated title). Keeping open — author is a MEMBER and the behavior needs a product decision on whether to settle the title once or allow dynamic updates.

## Change summary

When a new chat is created in the Agents window, the title visibly changes twice — first from the user's message, then from the agent's interpretation — creating a confusing UX where the user expects dynamic updates that don't continue.

## Best solution

Decide on a single title-setting strategy: either set the title once from the first user message and let the agent refine it only via an explicit rename API call, or commit to dynamic title updates throughout the conversation. The title logic lives in `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts` (lines ~2148 for initial set, and the `setTitle` command for agent-driven updates). The initial title is set from `query.split('\n')[0]`, then the agent host later calls `setTitle` again — suppressing the second update or debouncing it would fix the double-change.
