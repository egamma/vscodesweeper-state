# Issue #110794 — [json] no IntelliSense when all-optional branch matches

[https://github.com/microsoft/vscode/issues/110794](https://github.com/microsoft/vscode/issues/110794)

## Summary

This team-authored Backlog feature request describes a real completion gap for `oneOf` schemas when one branch already accepts the current object, and there is no verified older canonical with the same observable symptom. It should remain open for the JSON language-service owners.

## Change summary

Offer properties from mutually exclusive `oneOf` object branches even when an all-optional branch already matches the current empty object.

## Best solution

Define completion behavior for ambiguous `oneOf` matches, then update the JSON language service so useful properties from viable branches remain available without suggesting combinations forbidden by the schema.

## Plan brief

- **Likely files:** `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add a JSON completion test using the issue's three-branch draft-07 schema: completion in an empty object should produce the maintainer-approved proposals, while completion after choosing one mutually exclusive property must not suggest an invalid combination.
- **Behavior:**

  > Given a JSON Schema `oneOf` with mutually exclusive object branches, including a branch whose properties are all optional and which therefore already matches an empty object, completion should still provide useful properties from other viable branches according to the chosen ambiguity policy. After a property selects one branch, completion must continue respecting `additionalProperties: false` and must not suggest properties that create an invalid cross-branch combination. Acceptance should cover the exact schema from https://github.com/microsoft/vscode/issues/110794 and the same schema without the all-optional branch.
- **Trace:**

  > The report isolates the behavior to JSON schema completion for `oneOf`: adding an all-optional branch changes proposals in an empty object from `dockerFile` and `image` to none. The VS Code JSON extension delegates language features through `extensions/json-language-features/server/src/jsonServer.ts`; the detailed completion logic may reside in its JSON language-service dependency, so the plan must trace that boundary before assigning implementation ownership. Preserve schema validation semantics and `additionalProperties: false`; this work concerns completion candidates, not changing which instances validate. https://github.com/microsoft/vscode/issues/82024 is broader infrastructure work and does not own this specific symptom.
- **Open decisions:**
  - When several `oneOf` branches currently validate because one branch has no required discriminator, should completion offer the union of properties from all viable branches, or only properties from branches that would make the instance more specific?
  - Once the user has entered a property unique to one branch, should suggestions be restricted immediately to that branch even if another all-optional branch still validates?
