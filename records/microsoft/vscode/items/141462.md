# Issue #141462 — Disable extension action on setting and make setting read only when it is overridden

[https://github.com/microsoft/vscode/issues/141462](https://github.com/microsoft/vscode/issues/141462)

## Summary

Keep open for a settings-editor design decision: extension-default attribution exists, but there is still no setting-context action to disable its contributing extension. The thread does not confirm the ineffective-checkbox defect, and making a setting read-only merely because an extension changes its default would conflict with the current editable configuration model.

## Change summary

Provide a way to disable an extension from a setting whose default it overrides, and clarify whether such settings should remain editable.

## Best solution

Resolve the extension-management affordance in the settings editor while preserving the distinction between an extension-contributed default and an enforced value. Decide whether the setting should offer direct extension disablement or navigation to extension management before implementation.

- **Behavior:**

  > A setting whose default comes from an extension identifies that source, but its context menu currently offers no way to disable the contributor. The desired improvement makes managing that contributor discoverable from the affected setting. An extension changing a default must remain distinguishable from an enforced read-only value. Acceptance should cover explicit user/workspace values, language-specific defaults, and settings with multiple contributing sources; the original ineffective-toggle observation must be retested separately.
- **Trace:**

- **Open decisions:**
