# Issue #86457 — iPadOS: cannot move panes around (activity bar, panel)

[https://github.com/microsoft/vscode/issues/86457](https://github.com/microsoft/vscode/issues/86457)

## Summary

The iPadOS drag-and-drop gap remains in current source and should stay open as the oldest focused report. Route it to the existing workbench drag-and-drop area.

## Change summary

Support moving activity-bar items, views, and panels with an iPad mouse or trackpad.

## Best solution

Extend the shared drag-and-drop handling in `src/vs/base/browser/dom.ts` and `src/vs/workbench/browser/dnd.ts` with a pointer-event fallback for platforms that do not emit native HTML drag events. Consolidate the matching evidence from https://github.com/microsoft/vscode/issues/147394 here while retaining https://github.com/microsoft/vscode/issues/85254 as the broader Mobile Safari umbrella.

## Evidence

- **current source:** `DragAndDropObserver` in `src/vs/base/browser/dom.ts` still listens only for native HTML drag events (`dragstart`, `dragover`, `drop`, and related events), with no pointer-event emulation.
- **affected path:** `CompositeDragAndDropObserver.registerDraggable` in `src/vs/workbench/browser/dnd.ts` sets `element.draggable = true` and depends on `DragAndDropObserver`, leaving the reported iPadOS path unsupported.
- **confirmed matching report:** https://github.com/microsoft/vscode/issues/147394 independently confirms the same behavior on vscode.dev with both an iPad Magic Keyboard trackpad and a Logitech mouse.
- **umbrella issue:** https://github.com/microsoft/vscode/issues/85254 remains open and lists drag-and-drop of views and panels as a Mobile Safari gap, but this issue is the older, more focused implementation report.
