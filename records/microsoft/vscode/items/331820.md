# Issue #331820 — Agent Host session restore is canceled by no-op proxy configuration restart

[https://github.com/microsoft/vscode/issues/331820](https://github.com/microsoft/vscode/issues/331820)

## Summary

Well-traced, source-confirmed bug: a strict-equality comparison between an unset Kerberos SPN (`undefined`) and a synchronized empty string (`""`) in CopilotAgent's proxy-refresh path triggers a spurious CopilotClient restart, which tears down live SDK chat entries mid-restore and surfaces as a sticky `Couldn't open session / Canceled` error even though the session is healthy.

## Change summary

Restoring a previously open Agents Window session after a VS Code restart can show a persistent 'Couldn't open session / Canceled' error, even though the session is intact and a retry loads it fine.

## Best solution

In `_applyProxyEnv`/`_refreshProxy` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts), normalize an empty-string proxy/Kerberos-SPN value to `undefined` before storing (`_appliedProxyKerberosSpn`) and before comparing against the freshly-resolved effective value, so a no-op configuration sync no longer triggers `_requestClientRestart`/`_applyPendingClientRestart` while a session restore is in flight.
