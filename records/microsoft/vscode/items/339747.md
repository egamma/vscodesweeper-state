# Issue #339747 — Agents - do not show the table when there are no worktrees to clean up

[https://github.com/microsoft/vscode/issues/339747](https://github.com/microsoft/vscode/issues/339747)

## Summary

Confirmed on current main: SessionWorktreeCleanupEditor always renders the header row, empty list, and disabled Clean Up button even when there are zero eligible worktrees, instead of showing an information banner as the team-filed follow-up requests. Team-authored, clear UI polish, worth keeping open and planning the exact trigger condition before implementing.

## Change summary

The 'Open worktree cleanup' editor shows an empty table with a disabled Clean Up button when there are no worktrees eligible for cleanup; it should show an informational banner instead.

## Best solution

In SessionWorktreeCleanupEditor.renderRows (src/vs/sessions/contrib/sessionInputBanners/browser/sessionWorktreeCleanupEditor.ts), when there are no eligible worktrees, replace the header row / empty list / disabled 'Clean Up Worktrees' button with an info banner conveying the same summary text, keeping the age selector and automatic-cleanup settings section intact.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessionInputBanners/browser/sessionWorktreeCleanupEditor.ts`, `src/vs/sessions/contrib/sessionInputBanners/browser/media/sessionWorktreeCleanupEditor.css`
- **Validation:** Manually open the 'Open worktree cleanup' editor in a state with zero eligible worktrees for the selected age and confirm an info banner renders instead of the empty table/disabled button, with an equivalent aria-live announcement to what the summary region currently provides.
- **Behavior:**

  > When there are no worktrees eligible for cleanup at the selected 'untouched for' age, the editor should show an informational banner explaining there is nothing to clean up, instead of an empty table and a disabled 'Clean Up Worktrees' button. Changing the age selector to a value where eligible worktrees exist should restore the normal table/button view. The automatic-cleanup settings section and age selector should remain usable regardless.
- **Trace:**

  > SessionWorktreeCleanupEditor.renderRows() (src/vs/sessions/contrib/sessionInputBanners/browser/sessionWorktreeCleanupEditor.ts) computes `eligible` from `this.worktrees` filtered to `cleanupState === 'eligible'`, builds the summary text/recentNote, then unconditionally appends the header row to `this.list` and iterates `eligible` to add data rows — when `eligible.length === 0` this yields a header-only table, and `updateCleanupButton()` leaves the button disabled. The boundary: do not touch `load()`'s data-fetching, the automatic-cleanup section (`renderAutomaticCleanup`), or the age-selector controls — only the summary-row/list/button rendering path should branch on the empty-eligible case. Related: filed against microsoft/vscode#339374 (testing issue, no public URL content reviewed beyond the reference).
- **Open decisions:**
  - Should the banner replace the view only when `eligible.length === 0`, or also factor in whether there are zero worktrees total (vs. some 'too recent' ones still tracked by recentNote)?
  - Should the age selector and 'Clean Up Worktrees' summary row remain visible alongside the banner, or be hidden entirely while the banner is shown?
