# Issue #302124 — Sessions: Context and codebase understanding is not transferred between sessions on the same repository

[https://github.com/microsoft/vscode/issues/302124](https://github.com/microsoft/vscode/issues/302124)

## Summary

Keep open for a focused assessment of repository-level context reuse: current main has memory and cross-session retrieval infrastructure, but that does not establish automatic carry-forward of prior codebase analysis. The team-authored request and maintainer discussion support retaining it until the remaining experience is defined and verified.

## Change summary

Let a new session reuse essential codebase understanding gathered in earlier sessions on the same repository without requiring manual scratchpad management.

## Best solution

Build on the existing repository-memory and session-retrieval capabilities rather than introducing another independent store. Establish whether new sessions should proactively recall relevant analysis or guide users through an explicit carry-forward action, then verify that this avoids redundant repository analysis.

- **Likely files:** `extensions/copilot/src/extension/tools/node/memoryContextPrompt.tsx`, `extensions/copilot/src/extension/tools/node/memoryTool.tsx`, `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx`, `src/vs/platform/agentHost/common/copilotCliConfig.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`
- **Validation:** In a controlled repository, have session A establish and retain a distinctive, correct codebase finding, then start an independent session B on the same repository. Verify that B retrieves and uses the finding through the agreed automatic or guided workflow without repeating the full analysis; repeat in an unrelated repository to check scope isolation and with memory disabled to check existing controls.
- **Behavior:**

  > A new session on the same repository should be able to build on essential codebase understanding established in a previous session without requiring the user to maintain and attach a scratchpad manually. Carry-forward should remain concise rather than importing an entire conversation. Acceptance should demonstrate reuse of a known prior finding, reduced redundant analysis, repository isolation, and respect for existing memory controls. Whether reuse happens proactively or through a guided explicit action remains a product decision.
- **Trace:**

  > The local Copilot agent prompt includes MemoryContextPrompt on new chats when the memory tool is available; that component exposes repository-memory filenames and instructions for consulting saved notes. MemoryTool resolves repository notes into workspace storage independently of the current session ID, while session notes remain session-scoped. Agent Host's CopilotSessionLauncher enables the SDK session store by default for non-ephemeral sessions and separately adopts opt-in cloud or repository memory settings. These paths establish storage and retrieval infrastructure, but the inspection did not establish an end-to-end mechanism that captures prior codebase analysis and recalls it for a fresh same-repository session. Preserve provider boundaries, existing opt-in controls, and independent-session semantics while assessing the experience. https://github.com/microsoft/vscode/issues/301174 concerns explicit local-transcript search, and https://github.com/microsoft/vscode/issues/334251 concerns surface-specific tool availability; neither resolves this request's full contract.
- **Open decisions:**
  - Should a fresh same-repository session proactively recall relevant saved analysis, or should the user initiate a guided carry-forward action?
  - Should continuity retain curated repository facts only, or also selected conversation decisions and task context?
