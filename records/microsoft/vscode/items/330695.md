# Issue #330695 — `editor.allowVariableFonts: false` silently prevents extension editor decorations from rendering

[https://github.com/microsoft/vscode/issues/330695](https://github.com/microsoft/vscode/issues/330695)

## Summary

Traced and confirmed in current main: ModelDecorationOptions.affectsFont (src/vs/editor/common/model/textModel.ts:2543) treats any truthy fontWeight/fontStyle string — including the literal value "normal" — as "uses variable fonts", and filterFontDecorations then drops the whole decoration node in intervalTree.ts rather than just its font styling. This is a real, narrow defect worth fixing, not a hard-close case.

## Change summary

Setting editor.allowVariableFonts (or allowVariableFontsInAccessibilityMode) to false silently drops entire extension decorations whenever their render options include fontWeight/fontStyle, even when the value is just "normal" and doesn't actually require variable-font support.

## Best solution

Narrow the affectsFont check in ModelDecorationOptions (src/vs/editor/common/model/textModel.ts, line ~2543) so that fontWeight/fontStyle values of "normal" (or unset/default) don't mark a decoration as font-affecting, so filterFontDecorations in intervalTree.ts no longer discards the whole decoration (background color etc.) for decorations that don't actually rely on variable fonts.
