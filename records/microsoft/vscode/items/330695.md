# Issue #330695 — `editor.allowVariableFonts: false` silently prevents extension editor decorations from rendering

[https://github.com/microsoft/vscode/issues/330695](https://github.com/microsoft/vscode/issues/330695)

## Summary

Traced conclusively on main: `editor.allowVariableFonts: false` causes `filterFontDecorations()` to drop entire decoration nodes (not just font-related CSS) whenever `affectsFont` is true, and `affectsFont` is computed as a truthy check on `fontWeight`/`fontStyle` regardless of value — so `fontWeight: 'normal'` triggers the drop exactly as reported.

## Change summary

Setting `editor.allowVariableFonts` to `false` silently discards whole decorations (background color included) whenever their render options include any `fontWeight`/`fontStyle`/`fontFamily`/`fontSize` property, even a no-op value like `"normal"`, instead of only ignoring the variable-font-specific behavior.

## Best solution

Rework the `filterFontDecorations` mechanism so it only strips the font-affecting CSS properties from a decoration's render options (or exempts `fontWeight`/`fontStyle` values of `"normal"`/unset from `affectsFont`) instead of excluding the whole decoration node in `src/vs/editor/common/model/intervalTree.ts`'s `search()`/`intervalSearch()`. This likely belongs with whoever owns the variable-fonts and GPU-renderer decoration work (see the linked test plan #253007 and #237584).
