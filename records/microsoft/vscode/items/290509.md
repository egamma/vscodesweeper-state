# Issue #290509 — Git: Stash editor redirects to wrong stash when new stashes are created

[https://github.com/microsoft/vscode/issues/290509](https://github.com/microsoft/vscode/issues/290509)

## Summary

Valid bug confirmed in current source: stash editors are keyed by mutable index (`stash@{N}`), so when indices shift after a new stash is created, opening or operating on a stash targets the wrong one. An open PR (#288616) from the reporter addresses this; keeping open pending review of that PR.

## Change summary

Git stash editor uses the stash index as its identity, causing it to show and operate on the wrong stash when indices shift after new stashes are created.

## Best solution

Review and land PR https://github.com/microsoft/vscode/pull/288616 which switches the stash editor identity from the mutable index to the immutable commit hash. The fix touches `extensions/git/src/commands.ts` (and possibly `artifactProvider.ts`) — the stash URI construction (`toGitUri` with `stash@{N}`) and the stash-lookup regex paths all need to use the commit hash instead.
