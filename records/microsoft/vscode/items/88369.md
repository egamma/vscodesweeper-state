# Issue #88369 — Git - 'Revert selected ranges' should work on individual lines, not hunks

[https://github.com/microsoft/vscode/issues/88369](https://github.com/microsoft/vscode/issues/88369)

## Summary

Keep open: current source still reverts an entire intersecting hunk rather than only the selected lines. This remains the canonical report for that behavior, with a bounded path suitable for implementation.

## Change summary

Make Git: Revert Selected Ranges revert selected changed lines without discarding neighboring unselected changes in the same hunk.

## Best solution

Provide line-granular reversion in the built-in Git command, consistent with selected-range staging, while preserving the existing whole-hunk revert action and Git index contents.

- **Behavior:**

  > When adjacent lines contain unrelated Git working-tree edits, Git: Revert Selected Ranges must restore only the selected changed lines and preserve unselected edits, even within the same diff hunk. A cursor without an expanded selection targets its changed line, rather than the entire hunk. Multiple selections must not discard changes between them. Acceptance checks compare the complete saved document and unchanged index for a three-line replacement; the existing explicit whole-hunk revert action remains unchanged.
- **Trace:**

  > CommandCenter.revertSelectedRanges in extensions/git/src/commands.ts obtains working-tree LineChanges and retains only complete changes that intersect none of the editor selections. _revertChanges passes those retained changes to applyLineChanges in extensions/git/src/staging.ts, rebuilding from the Git baseline; consequently any intersecting hunk disappears in full. This is conclusively visible for a three-line equal-length replacement with only its middle line selected. stageSelectedChanges already uses toLineRanges and intersectDiffWithRange for finer granularity, and the latter has an equal-length line-mapping heuristic; its pure-deletion limitations are separate work tracked at https://github.com/microsoft/vscode/issues/9475.
