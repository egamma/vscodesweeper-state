# Issue #253608 — Make sticky scroll take into account line heights when the cursor moves

[https://github.com/microsoft/vscode/issues/253608](https://github.com/microsoft/vscode/issues/253608)

## Summary

Keep open: cursor reveal still reserves space using the configured maximum sticky-line count and the default line height, rather than the widget's position-dependent height. This team-authored request has a concrete remaining gap; the related older requests do not establish the same variable-height symptom required for a duplicate close on re-review.

## Change summary

Make cursor reveal account for variable-height sticky lines so keyboard navigation never hides the cursor behind sticky scroll.

## Best solution

Make editor cursor reveal respect the sticky widget's height at the destination, including variable line heights and changes in sticky scopes during scrolling. Coordinate this with the related cursor-reveal work without treating configurable line-count padding as equivalent coverage.

## Evidence

- **Current reveal heuristic:** src/vs/editor/browser/viewParts/viewLines/viewLines.ts:720-745 computes surroundingLines as max(cursorSurroundingLines, stickyScroll.maxLineCount), then paddingTop as context multiplied by the default _lineHeight. It does not obtain the actual or destination-dependent sticky widget height.
- **Widget supports variable heights:** src/vs/editor/contrib/stickyScroll/browser/stickyScrollWidget.ts:_findRenderingData reads getLineHeightForPosition for individual sticky lines. _renderRootNode accumulates rendered stickyLine.height and calls _setHeight(top + lastLineRelativePosition). This actual height is exposed by StickyScrollController.stickyScrollWidgetHeight, but is absent from the cursor-reveal calculation.
- **Existing settings do not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.stickyScroll.enabled, maxLineCount, defaultModel and scrollWithEditor. editor.cursorSurroundingLines controls a line-count margin; neither that setting nor maxLineCount provides position-dependent variable-height clearance. Disabling sticky scroll removes the requested feature rather than satisfying the request.
