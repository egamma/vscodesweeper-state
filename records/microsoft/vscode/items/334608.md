# Issue #334608 — Agents: prompted about uncommitted changes on cloud session start, but Changes panel is empty

[https://github.com/microsoft/vscode/issues/334608](https://github.com/microsoft/vscode/issues/334608)

## Summary

Traced this in the source and it's a real gap: the cloud-session uncommitted-changes prompt and the Changes panel use entirely different data paths, so the panel can never show what the prompt is asking about, right when the user needs it most to decide safely.

## Change summary

When starting a cloud agent session, VS Code asks whether local uncommitted changes should be pushed along, but the Changes panel has no way to preview those changes to inform that decision.

## Best solution

Either surface a local git diff preview in the same prompt/panel before the PR exists, or (if that's architecturally out of reach for Cloud sessions) improve the prompt copy to tell users to check their source-control view first — the current combination silently offers a review path that doesn't work, in src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsChangesets.ts and extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts.

  > Thanks for the report — I traced this in the source and can confirm the gap. The cloud-session start prompt (`copilotCloudSessionsProvider.ts`) asks about local uncommitted changes, but the Changes panel's changeset resolvers for Cloud sessions (`copilotChatSessionsChangesets.ts`) never register an "Uncommitted Changes" changeset, and the other changesets depend on a GitHub PR existing — which it doesn't yet at that point — so the panel is empty by design, not a rendering bug. - **Changes panel architecture:** src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsChangesets.ts createChangesets(): `if (sessionType !== AgentSessionProviders.Cloud) { changesets.push(new UncommittedChangesChangeset(...)); }` — the Uncommitted Changes changeset is explicitly never created for Cloud sessions.
- **empty resolver for new sessions:** GitHubRepositoryChangesetResolver.resolve() (same file) returns undefined unless `gitHubInfo.pullRequest?.number` is set — there is no PR yet moments after starting a cloud session, so Branch/All/LastTurn changesets all resolve empty, matching the reported blank panel.
