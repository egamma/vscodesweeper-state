# Issue #143516 — Git - $GIT_INDEX_FILE is set after newly starting VS Code as a git editor

[https://github.com/microsoft/vscode/issues/143516](https://github.com/microsoft/vscode/issues/143516)

## Summary

Keep open: current source still propagates the inherited GIT_INDEX_FILE into terminal and Git subprocess environments, matching the reported failure. The issue already has the appropriate git routing, and a second user reported the problem in May 2026.

## Change summary

Starting VS Code as Git's commit editor leaks a temporary GIT_INDEX_FILE into subsequent terminals and Source Control operations, producing incorrect repository status.

## Best solution

Prevent the commit editor's temporary index environment from contaminating ordinary repository operations and later windows, while preserving commit editing and explicitly configured subprocess environments. The solution needs to cover application environment inheritance, not only the Git extension or the terminal.

- **Behavior:**

  > A cold launch of VS Code as the editor for a path-limited Git commit must not leave the commit's temporary index controlling ordinary terminal or Source Control operations. A subsequent window must likewise show the repository's real status rather than misleading untracked files. Completing the commit message must still allow the original Git process to finish its intended commit. Validate both the initial editor window and a later window, preserving unrelated environment variables and explicit terminal configuration.
- **Trace:**

  > src/vs/code/node/cli.ts copies process.env and, on macOS, forwards its entries through open --env; the inherited GIT_INDEX_FILE is not excluded. CodeMain.patchEnvironment in src/vs/code/electron-main/main.ts retains that environment, while getResolvedShellEnv in src/vs/platform/shell/node/shellEnv.ts skips shell resolution for normal CLI launches. LocalProcessExtensionHost._start obtains the shell environment, and Git.spawn in extensions/git/src/git.ts subsequently merges process.env into Git subprocesses. Independently, createTerminalEnvironment copies baseEnv and sanitizeProcessEnvironment does not remove GIT_INDEX_FILE, conclusively preserving the reported override. The remaining investigation is the complete initial-launch, existing-instance and subsequent-window environment lifecycle: a terminal-only change would leave Source Control affected, and a Git-only change would leave terminals affected. Preserve the parent Git process, commit-message waiting behavior, unrelated Git configuration and explicit subprocess environment overrides; do not generalize this report into blanket removal of all GIT_* variables.
