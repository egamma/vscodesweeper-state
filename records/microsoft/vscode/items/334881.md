# Issue #334881 — Serious cross-session security issues with the read tool on remote host

[https://github.com/microsoft/vscode/issues/334881](https://github.com/microsoft/vscode/issues/334881)

## Summary

Security-sensitive cross-session data exposure report — read tools in one remote/container window allegedly return file contents from an unrelated SSH host connected in a different window. This needs a human security review, not an automated triage close, regardless of how thin the current reproduction detail is.

## Change summary

When two windows are connected to different remote targets (a host via SSH and a container on that host), Copilot's read tools (read_file, list_dir, grep_search, file_search) in the second window return results from the first window's host instead of the correct target.

## Best solution

A maintainer with remote/agent-host and Copilot tools context should investigate whether tool execution is somehow resolving against the wrong remote authority/extension host when multiple remote connections are open simultaneously (possible session or workspace-URI mixup) — likely spanning src/vs/platform/remote or the agent host session wiring plus extensions/copilot/src/extension/tools/node. Needs a controlled repro (two windows, two distinct remote targets) before further triage.
