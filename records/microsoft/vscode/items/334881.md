# Issue #334881 — Serious cross-session security issues with the read tool on remote host

[https://github.com/microsoft/vscode/issues/334881](https://github.com/microsoft/vscode/issues/334881)

## Summary

This describes a potential cross-session information disclosure (agent read tools in one remote/SSH-connected window returning content from a different host/container connected in another window) — a security-sensitive report that must stay open for a human to investigate regardless of staleness or thin reproduction detail.

## Change summary

When two VS Code windows are connected to different remote targets (host vs. a container on that host) via SSH, agent read tools (read_file, list_dir, grep_search, file_search) in the second window appear to return results from the first window's remote host rather than the second window's actual target.

## Best solution

A maintainer with access to the agent/tool-execution routing code (likely in the extension host / remote agent tooling, possibly `extensions/copilot` or the remote resolver layer) needs to reproduce this with two concurrently connected remote windows and trace whether tool execution context (cwd/session/remote authority) is being cross-wired between windows; this needs a security-aware investigation, not a routine triage close.
