# Issue #331193 — Minimap renders huge section-header text over LaTeX files for prose lines starting with the word region

[https://github.com/microsoft/vscode/issues/331193](https://github.com/microsoft/vscode/issues/331193)

## Summary

Confirmed on current main: the LaTeX folding-marker regex in extensions/latex/latex-language-configuration.json treats a bare prose line starting with the word "region" as a folding/section-header start, which the minimap then renders as an oversized section header. The reporter already opened an upstream fix PR; keeping this open for a maintainer to land the corresponding change here.

## Change summary

Any LaTeX prose line beginning with the bare word "region" is misdetected as a folding region marker, causing a large bogus section header to render in the minimap.

## Best solution

Update the `folding.markers.start`/`end` regex in extensions/latex/latex-language-configuration.json (lines 111-112) to require the `%` comment character before `region`/`endregion` while still allowing bare `\begingroup`/`\endgroup`, matching the upstream fix at https://github.com/jlelong/vscode-latex-basics/pull/137.

- **Fix prompt:**

  > The built-in LaTeX language configuration at extensions/latex/latex-language-configuration.json (lines 111-112) defines folding markers as `"start": "^\\s*%?\\s*(region|\\\\begingroup)\\b"` and `"end": "^\\s*%?\\s*(endregion|\\\\endgroup)\\b"`. Because the `%` comment prefix is optional (`%?`), any plain prose line in a .tex/.ltx/.ctx/.sty/.cls/.bbx/.cbx file that begins with the bare word `region` (e.g. 'region the encoder fails to cover...') is misparsed as a folding-region start. Since `editor.minimap.showRegionSectionHeaders` defaults to on and findSectionHeaders.ts (src/vs/editor/common/services/findSectionHeaders.ts) does not require region headers to be in comments, the rest of that line renders as an oversized section-header banner overlaid on the minimap, plus a bogus fold in the gutter. Fix by requiring the `%` comment marker for `region`/`endregion` while still allowing bare (uncommented) `\begingroup`/`\endgroup`, which are real TeX commands, and their commented variants — i.e. change the patterns to `"start": "^\\s*(%\\s*region|%?\\s*\\\\begingroup)\\b"` and `"end": "^\\s*(%\\s*endregion|%?\\s*\\\\endgroup)\\b"`, matching the reporter's proposed fix and the upstream jlelong/vscode-latex-basics#137 PR. Do not change any other folding/indentation rules in this file, and don't touch findSectionHeaders.ts — the region-header rendering logic is correct given proper folding markers. Validate by adding a test (in extensions/latex's test folder or a suitable folding-provider unit test) asserting a bare-prose line starting with 'region' produces no folding range, while '% region' and '\begingroup' still do; the test must fail against the current regex and pass after the change.
