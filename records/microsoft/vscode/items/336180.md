# Issue #336180 — Custom agent Markdown link does not load referenced .instructions.md file

[https://github.com/microsoft/vscode/issues/336180](https://github.com/microsoft/vscode/issues/336180)

## Summary

Traced the gap on main: when a custom agent (`.agent.md`) is selected directly, its parsed content is exposed only as `IChatRequestModeInstructions.content`/`toolReferences` (src/vs/workbench/contrib/chat/common/model/chatModel.ts:388-396) and the agent's own URI is never fed into `ComputeAutomaticInstructions.collect()` (src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts), so `_addReferencedInstructions` (line 575) never walks the agent file's markdown links — it only starts from variables already tagged `isPromptFileVariableEntry`, which is why `.prompt.md` references work (the prompt file itself is seeded into `attachedContext`) but `.agent.md` references don't.

## Change summary

A Markdown link inside a custom agent's `.agent.md` file to a `.instructions.md` file is not resolved into chat context when the agent is selected directly, even though the same link works from a `.prompt.md` file or with `applyTo: "**"`.

## Best solution

Thread the active custom agent's URI (available as `IChatRequestModeInstructions.uri`) into `ComputeAutomaticInstructions.collect()` in `chatServiceImpl.ts`'s `collectInstructions` (~line 1643-1663), and extend `_addReferencedInstructions` in computeAutomaticInstructions.ts to seed its traversal with that URI's file references, mirroring how `copilotEntries` are handled in `_addAgentInstructions` (lines 284-290).
