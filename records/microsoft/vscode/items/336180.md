# Issue #336180 — Custom agent Markdown link does not load referenced .instructions.md file

[https://github.com/microsoft/vscode/issues/336180](https://github.com/microsoft/vscode/issues/336180)

## Summary

Still a real gap on current main: referenced-instruction resolution only walks prompt-file variable entries, and the selected custom agent's `.agent.md` is never seeded into that set — so Markdown links inside an agent file are never resolved, while the same link from a `.prompt.md` or `copilot-instructions.md` is. Worth routing to the chat area; the report's repro matrix is complete and the fix needs the active agent URI plumbed into instruction collection.

## Change summary

A Markdown link from a custom `.agent.md` to a `.instructions.md` file is not resolved into the request context, although the same link works from a `.prompt.md` file and the instruction file loads when it carries `applyTo: "**"`.

## Best solution

Plumb the active custom agent's file URI into instruction collection (`IChatSendRequestOptions.instructionContext` in src/vs/workbench/contrib/chat/common/chatService/chatService.ts) and seed it into the variable set that `ComputeAutomaticInstructions._addReferencedInstructions` walks, so agent-file Markdown references resolve the same way prompt-file references already do — including the subagent path in runSubagentTool and the extension-side collector for parity.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts`, `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`
- **Validation:** A test in src/vs/workbench/contrib/chat/test/common/promptSyntax/computeAutomaticInstructions.test.ts asserting that, with `chat.includeReferencedInstructions` enabled and a custom agent selected, an `.instructions.md` file linked by relative Markdown path from the agent's `.agent.md` is added as an `InstructionReference` entry — failing before the change, passing after.
- **Behavior:**

  > With `chat.includeReferencedInstructions` enabled, selecting a custom agent whose `.agent.md` body contains a relative Markdown link to a `.instructions.md` file must add that instruction file to the request context, exactly as the same link already does from a `.prompt.md` file. The Custom Instructions diagnostics should list it (`context included: [1] <name>.instructions.md`), and transitive references from that instruction file should be followed the same way. Instruction files with no `applyTo` and no incoming reference must still not be auto-attached, and behavior with the setting disabled must be unchanged.
- **Trace:**

  > `ComputeAutomaticInstructions._addReferencedInstructions` (src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts) seeds its traversal only from variable entries passing `isPromptFileVariableEntry`; the selected custom agent's `.agent.md` is never added to that set by `collect()`, and `IChatSendRequestOptions.instructionContext` (src/vs/workbench/contrib/chat/common/chatService/chatService.ts ~2102) carries only `modeKind`/`enabledTools`/`enabledSubAgents`, so the collector cannot know which agent file is active. Prompt files work because chatWidget.ts:3579 inserts them as root `PromptFile` entries; copilot-instructions.md works because `_addAgentInstructions` re-feeds its entries through the same walk. The boundary: do not change `addApplyingInstructions`/`applyTo` semantics, do not start injecting the agent body itself as an instruction entry (it is already the system prompt), and keep the existing `chat.includeReferencedInstructions` gate. Uncertainty starts at the plumbing surface — where the active agent URI is known at send time (`modeInstructions?.uri` appears in chatServiceImpl.ts ~1029/1543), and whether the subagent path (runSubagentTool.ts ~327, which starts from an empty variable set) and the extension-side collector (extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts, used when `CollectInstructionsInExtension` is true) must land the same behavior for parity.
- **Open decisions:**
  - Should references from the active custom agent file be gated by the existing `chat.includeReferencedInstructions` setting, or always followed (since the agent author deliberately linked them)?
  - Should the referenced files appear in the Custom Instructions diagnostics as 'Referenced by <agent>.agent.md', and should the agent file itself be surfaced there as a reference root?
  - Does the same resolution apply when the agent runs as a subagent via the Run Subagent tool, and must the extension-side collector reach parity in the same change?

## Evidence

- **reference walk is seeded only from prompt-file variable entries:** src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts `_addReferencedInstructions` builds its `todo` queue solely from `attachedContext.asArray()` entries that pass `isPromptFileVariableEntry`; nothing else contributes roots.
- **the active agent file is never added to that set:** `collect()` in the same file adds applying instructions, agent instructions (copilot-instructions.md / AGENTS.md via `listAgentInstructions`) and the customizations index, but never a variable entry for the selected `.agent.md`. `getCustomAgents` is used only to list subagent names in the `<agents>` index block.
- **the agent URI is not even available to the collector:** The caller in src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts (~line 1960) constructs `ComputeAutomaticInstructions` from `options.instructionContext`, whose type in src/vs/workbench/contrib/chat/common/chatService/chatService.ts (~line 2102) is only `{ modeKind, enabledTools, enabledSubAgents }` — no mode/agent file URI. The subagent path in src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts (~line 327) starts from an empty `ChatRequestVariableSet` for the same reason.
- **why the reporter's control experiments pass:** A prompt file IS inserted as a root variable entry (`toPromptFileVariableEntry(parseResult.uri, PromptFileVariableKind.PromptFile, ...)` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:3579), and copilot-instructions.md entries are explicitly re-fed through `_addReferencedInstructions` in `_addAgentInstructions`. `applyTo: "**"` bypasses references entirely via `addApplyingInstructions`.
- **no history check possible:** The provided checkout is a shallow clone (single commit 19fd9935), so no `git log`/`git blame` forensics or fix-commit search was possible; the trace above is from current main's source only.
