## Evidence

- **Source-confirmed formatting loss:** extensions/git/src/hover.ts, appendContent, replaces every newline with two newlines before appending Markdown. An original single newline becomes a Markdown paragraph boundary, while an original blank line becomes four newlines, which does not preserve an additional empty paragraph. Both therefore receive equivalent paragraph treatment.
- **Graph rendering path:** extensions/git/src/historyProvider.ts calls getHistoryItemHover with the commit message. src/vs/workbench/contrib/scm/browser/scmHistory.ts, toHistoryItemHoverContent, renders those Markdown sections; scm/browser/media/scm.css assigns the same margin to their paragraphs. This supports the reported loss of relative paragraph spacing without executing the UI.
- **Related but different symptom:** https://github.com/microsoft/vscode/issues/270925 reports single newlines appearing as paragraph breaks. It shares the formatter but does not report the same blank-line-loss symptom, so it does not satisfy the stronger duplicate bar for this re-reviewed item.
- **Overlapping open implementation:** https://github.com/microsoft/vscode/pull/301633 is open and changes appendContent through formatMessageForHoverMarkdown, preserving paragraph boundaries while joining ordinary prose lines. Its diff also changes SCM hover list margins. It references the older newline issue, not this report; it is neither a landed fix nor proof that this report's full formatting expectation is satisfied.
