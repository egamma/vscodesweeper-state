This remains a valid chat-persistence bug: current source contains a confirmed failure path that can leave a session non-durable, and several newer reports corroborate disappearing or truncated histories. It should be routed to the chat area and remain open while the linked draft fix is reviewed and the other persistence failure modes are investigated.

## Change summary

Copilot Chat sessions intermittently disappear or become unrecoverable after extended use, reloads, updates, or shutdown transitions.

## Best solution

Keep this older, broad report as the tracker for intermittent session-history loss. Review the targeted serializer fallback in https://github.com/microsoft/vscode/pull/309286, then separately harden shutdown, index, malformed-log recovery, and incomplete-write paths so previously persisted history cannot silently disappear.

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts, ChatSessionStore.writeSession catches an exception from dataSerializer.write(), warns that the session will be lost if the window closes, then rethrows; the outer catch only reports the error, so the session data and index update are not completed.
- **open fix attempt:** https://github.com/microsoft/vscode/pull/309286 is an open draft PR referencing this issue and adds a full-snapshot fallback for that serializer-failure path. Its author explicitly limits the claim to one concrete missing-session failure mode rather than all reports.
- **independent confirmation:** https://github.com/microsoft/vscode/issues/309284 reports the same user-visible disappearance while background work continues, with an additional confirmation on Stable in July 2026.
- **on-disk evidence:** https://github.com/microsoft/vscode/issues/333143 documents a long-running session being replaced by a single empty initial snapshot on VS Code 1.135.0, confirming that session-history loss remained observable on a substantially newer build.
- **distinct persistence failures:** https://github.com/microsoft/vscode/issues/307348 and https://github.com/microsoft/vscode/issues/308730 remain open with concrete malformed or incomplete JSONL evidence. They are narrower failure modes rather than suitable canonicals for this older broad report.
