## Summary

Keep open: the merge editor still requires text models and does not provide an image-conflict viewing workflow. The older binary-conflict report concerns ineffective resolution actions, not the same opening failure, so it does not meet the re-review duplicate bar.

## Change summary

- **current SCM routing:** extensions/git/src/repository.ts: ResourceCommandResolver.resolveChangeCommand routes both-modified or both-added conflicts to git.openMergeEditor when git.mergeEditor is enabled, without distinguishing images from text. extensions/git/src/commands.ts: Commands.openMergeEditor forwards the base, incoming, current and output URIs to _open.mergeEditor.
- **remaining capability gap:** src/vs/workbench/contrib/mergeEditor/browser/mergeEditorInput.ts: MergeEditorInput.resolve delegates to a text-based input-model factory. - **existing settings are partial workarounds:** extensions/git/package.json registers git.mergeEditor, currently defaulting to false, and git.openDiffOnClick. Disabling merge-editor routing or setting git.openDiffOnClick to false can select ordinary file opening, but neither supplies image-aware merge viewing or conflict resolution.
