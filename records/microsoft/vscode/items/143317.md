# Issue #143317 — Some Unicode characters collide in VS Code Explorer view but not on file system

[https://github.com/microsoft/vscode/issues/143317](https://github.com/microsoft/vscode/issues/143317)

## Summary

The collision remains directly visible in current source: Explorer lowercases every child name for case-insensitive providers, causing JavaScript's Unicode case folding to map both `K` and `k` to the same key. This team-authored, accepted Backlog bug should remain open for a bounded Explorer model fix.

## Change summary

Explorer hides one of two distinct Windows directories when their names collide under JavaScript Unicode lowercasing.

## Best solution

The Explorer model should preserve every distinct directory entry returned by the Windows file-system provider while retaining case-insensitive lookup for names Windows itself considers equivalent.
