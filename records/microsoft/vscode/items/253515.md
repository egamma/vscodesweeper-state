# Issue #253515 — Support `content` instead of `url` for vscode:chat-* links

[https://github.com/microsoft/vscode/issues/253515](https://github.com/microsoft/vscode/issues/253515)

## Summary

The requested capability remains absent on current main: chat customization links accept only an HTTP(S) `url=` source. This member-authored Backlog request should remain open while the embedded-content URL contract and confirmation experience are designed.

## Change summary

Allow `vscode:chat-prompt/install`, `chat-instructions/install`, and agent/mode install links to carry prompt content directly instead of requiring a publicly fetchable URL.

## Best solution

Define a bounded, safely encoded `content` parameter for chat customization install links, preserving destination and filename selection while presenting confirmation text appropriate for embedded rather than remotely fetched content.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/promptSyntax/promptUrlHandler.ts`, `src/vs/workbench/contrib/chat/test/browser/promptSyntax/promptUrlHandler.test.ts`
- **Validation:** Run `./scripts/test.sh --grep "PromptUrlHandler"` with coverage for encoded multiline content, each supported chat customization route, malformed or oversized content, cancellation, filename selection, and unchanged `url=` handling.
- **Behavior:**

  > A supported `vscode:chat-*/install` link can carry customization text directly, allowing content from authenticated or otherwise non-public sources to be imported without a network fetch. The user must still explicitly confirm the operation and choose the destination and filename. Existing HTTP(S) `url=` links must continue to work unchanged, while malformed or excessive embedded content must fail safely without creating a file.
- **Trace:**

  > PromptUrlHandler in src/vs/workbench/contrib/chat/browser/promptSyntax/promptUrlHandler.ts recognizes all four relevant install routes, but lines 69-94 accept only `url=`, validate HTTP(S), and fetch through IRequestService. The resulting text then enters the shared folder, filename, create-file, and opener flow at lines 96-111. Filename prompting can operate without a URL-derived initial value through askForPromptFileName in src/vs/workbench/contrib/chat/browser/promptSyntax/pickers/askForPromptName.ts. Preserve the existing remote URL behavior and route coverage; the uncertainty begins at the externally visible encoding, size policy, and warning semantics for embedded content. The newer related request https://github.com/microsoft/vscode/issues/269564 concerns authenticated sources but is not an older duplicate canonical.
- **Open decisions:**
  - Is the public `content` parameter percent-encoded UTF-8 text, base64-encoded text, or another explicitly versioned representation?
  - What content-size limit should the link contract enforce, and what user-visible failure should occur when that limit is exceeded?
  - What confirmation details should be shown for embedded content, where no remote URL is accessed but external input will still be written as a customization file?
