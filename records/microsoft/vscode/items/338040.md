# Issue #338040 — Copilot telemetry messages are truncated or lack structured content classification

[https://github.com/microsoft/vscode/issues/338040](https://github.com/microsoft/vscode/issues/338040)

## Summary

Traced on main: `sendEngineMessagesTelemetry` in chatStream.ts serializes the raw message array as-is (`messagesJson: JSON.stringify(messages)`), and while `multiplexProperties` already compresses/chunks it (capped at 50×8192 chars ≈ 400KB), nothing adds a structured content-type taxonomy for `thinking`/`redacted_thinking`/`reasoning_text` blocks before serialization — so both complaints (hard truncation past the cap, and no classification metadata) are real, but fixing them is a cross-cutting telemetry-schema design decision, not a bounded patch.

## Change summary

Copilot chat/agent telemetry (`engine.messages`, `conversation.messageText`) can still truncate very long payloads past the existing chunking cap, lacks structured content-type classification for thinking/reasoning/redacted content, and sometimes emits malformed JSON in summary-like fields.

## Best solution

A maintainer with telemetry-pipeline context should design a content-type classification schema (or reuse one) applied before `JSON.stringify(messages)` in extensions/copilot/src/platform/networking/node/chatStream.ts, decide whether to raise/redesign the `MAX_CONCATENATED_PROPERTIES` cap in extensions/copilot/src/platform/telemetry/common/telemetry.ts for edge-case oversized conversations, and audit the malformed-JSON summary path the reporter found.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/networking/node/chatStream.ts`, `extensions/copilot/src/platform/telemetry/common/telemetry.ts`, `extensions/copilot/src/platform/thinking/common/thinkingUtils.ts`, `extensions/copilot/src/extension/byok/common/anthropicMessageConverter.ts`
- **Validation:** A telemetry unit test (alongside extensions/copilot/src/extension/test/node/telemetry.spec.ts) asserting `engine.messages` payloads for thinking/redacted_thinking/reasoning content carry a classification field and remain valid JSON after chunking.
- **Behavior:**

  > Telemetry consumers should be able to reconstruct full conversations without truncation (or receive an explicit, documented drop signal instead of silent partial data), and every emitted message/content entry should carry a machine-readable classification of its purpose/visibility (answer, summary, thinking, redacted, context, etc.), with all structured fields remaining valid, parseable JSON.
- **Trace:**

  > Where uncertainty starts: whether to raise the `MAX_CONCATENATED_PROPERTIES` cap, add a distinct truncation-signal field, or redesign chunking entirely for pathological long conversations; and what taxonomy/field name to standardize for content classification across the different provider message shapes (Anthropic thinking blocks, OpenAI reasoning fields, plain assistant text). Do not change the existing chunk/compress mechanics for the common case — only decide the edge-case behavior and the new classification contract.
- **Open decisions:**
  - Should oversized payloads past the chunk cap get a higher cap, a different transport, or just an explicit truncation marker instead of silent loss?
  - What classification taxonomy/field name should be standardized across providers for message content purpose (summary vs. thinking vs. redacted vs. answer)?
  - Is the malformed-JSON summary payload a distinct bug in a specific code path, or a byproduct of the missing classification design — needs its own repro before scoping a fix?

## Evidence

- **serialization site:** extensions/copilot/src/platform/networking/node/chatStream.ts:456-462 `sendEngineMessagesTelemetry` does `messagesJson: JSON.stringify(messages)` with no content-type tagging before emitting `engine.messages`.
- **chunking cap:** extensions/copilot/src/platform/telemetry/common/telemetry.ts `multiplexProperties`: `messagesJson` is in `ALWAYS_COMPRESSED_CHUNK_KEYS` and is chunked, but capped at `MAX_CONCATENATED_PROPERTIES = 50` × `MAX_PROPERTY_LENGTH = 8192` (≈400KB compressed) — payloads beyond that are silently dropped/truncated, matching Issue 1.
- **untagged content types:** extensions/copilot/src/platform/thinking/common/thinking.ts and anthropicMessageConverter.ts carry `thinking`/`redacted_thinking`/`reasoning_text`/`reasoning_opaque` fields on message content, but no classification is added specifically for the telemetry payload, matching Issue 2.
- **related but narrower:** https://github.com/microsoft/vscode/issues/299952 asks only to make JSON truncation configurable for `engine.messages`; it doesn't cover the structured-classification or malformed-JSON parts of this report, so it isn't a canonical duplicate — noting as related.
