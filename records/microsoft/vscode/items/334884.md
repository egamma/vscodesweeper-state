# Issue #334884 — Marking a deleted file as viewed is broken

[https://github.com/microsoft/vscode/issues/334884](https://github.com/microsoft/vscode/issues/334884)

## Summary

Fresh, credible bug report and I traced a real defect in the source: for deleted files, the Agents Window changes-review 'Viewed' toggle compares the wrong URI, so the checkbox never durably reflects the reviewed state and flickers back.

## Change summary

In the Agents Window multi-diff changes view, marking a deleted file as 'Viewed' causes the checkbox to flicker instead of staying checked.

## Best solution

Fix the resource-identity mismatch for deleted files: `changesetReviewActions.ts`'s reviewed-file list and `AgentHostChangeset.setReviewState`'s matching both fall back to `originalUri` (the content-ref snapshot URI) when `modifiedUri` is absent, but the toolbar/context-key resource for a deleted file is `change.uri` (== `beforeUri`), which is a different URI than `originalUri`/`beforeContentUri`. Match consistently on the change's primary resource (the same `getChangeResource`-style logic already used in changesMultiDiffSourceResolver.ts) instead of `modifiedUri ?? originalUri`.

## Evidence

- **resource construction:** src/vs/platform/agentHost/common/fileEditDiff.ts normalizeFileEdit(): `resource = afterUri ?? beforeUri`; for a deletion (no afterUri) `resource === beforeUri`, while `beforeContentUri` (a canonicalized content-ref URI, see canonicalizeSessionDbUri) is a distinct URI used only for fetching the pre-edit snapshot.
- **diffToChange mapping:** src/vs/sessions/contrib/providers/agentHost/browser/agentHostDiffs.ts diffToChange(): sets `uri = map(normalized.resource)`, `modifiedUri = afterUri && map(afterUri)` (undefined for deletions), `originalUri = beforeContentUri && map(beforeContentUri)` — so for deleted files `originalUri !== uri`.
- **toggle/list mismatch:** src/vs/sessions/contrib/changes/browser/changesetReviewActions.ts builds `reviewedFiles` via `change.modifiedUri?.toString() ?? change.originalUri?.toString()`, and the MultiDiffEditorFileToolbar `toggled` condition compares `SessionChangesFileResourceContext` (set from `getChangeResource(change)` == `change.uri`, per changesMultiDiffSourceResolver.ts line ~86-88) against that same reviewedFiles list — for a deleted file this compares `uri` against `originalUri`, which never match.
