## Evidence

- **Threshold-dependent execution:** src/vs/editor/contrib/find/browser/findModel.ts:522-525 routes whole-file Replace All to _largeReplaceAll when matchesCount reaches MATCHES_LIMIT, defined as 19999. The reported 20,000-line input therefore takes this path.
- **Capture metadata corruption:** src/vs/editor/contrib/find/browser/findModel.ts:559-563 passes the complete native replacement callback arguments to buildReplaceString. In src/vs/editor/contrib/find/browser/replacePattern.ts, _substitute treats entries below matches.length as capture values. With regex x and replacement $1, that entry is the native match offset: zero becomes empty text, and subsequent offsets become replacement text.
- **Literal dollars expanded twice:** src/vs/editor/contrib/find/browser/findModel.ts:565 supplies the already-built static replacement directly as a native String.replace template. This reinterprets literal $$ and $&; _regularReplaceAll instead inserts the built replacement strings through ReplaceAllCommand.
- **Existing open implementation:** https://github.com/microsoft/vscode/pull/346873 was verified through the GitHub API as open with merged_at null. Its body explicitly says Fixes #346872 and describes correcting both callback metadata handling and static dollar expansion, with seven large-input cases and small-input controls.
