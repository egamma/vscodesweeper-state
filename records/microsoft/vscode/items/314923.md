# Issue #314923 — extensions.allowed should support version range

[https://github.com/microsoft/vscode/issues/314923](https://github.com/microsoft/vscode/issues/314923)

## Summary

This is an accepted Backlog feature request with 23 community upvotes, and current main still supports only exact extension versions rather than ranges or exclusions. The request should remain open for policy-contract design and implementation.

## Change summary

Allow `extensions.allowed` policies to express version comparisons, ranges, and negated version/platform rules.

## Best solution

Define a backward-compatible range and exclusion grammar for `extensions.allowed`, then apply it consistently when evaluating gallery and installed extensions while preserving existing boolean, `stable`, exact-version, and platform-specific behavior.

- **Fit:** aligned
- **Reason:** More expressive extension allowlisting strengthens enterprise extension governance and security response without adding default UI or runtime cost for users who do not configure the policy.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/common/allowedExtensionsService.ts`, `src/vs/platform/extensionManagement/common/extensionManagement.ts`, `src/vs/platform/extensionManagement/test/common/allowedExtensionsService.test.ts`
- **Validation:** Extend the AllowedExtensionsService unit suite with table-driven cases for `>`, `>=`, `<`, bounded ranges, exclusions, platform-qualified exclusions, prerelease versions, conflicting rules, and backward-compatible exact-version behavior; run the targeted `AllowedExtensionsService` tests.
- **Behavior:**

  > `extensions.allowed` should let administrators allow extension versions using comparison or range expressions and exclude a specific version/platform combination. A policy such as `>=2025.8.1` should admit qualifying versions and reject older ones, while an exclusion should override the applicable allowance according to the chosen documented precedence. Existing boolean, `stable`, exact-version, multiple-version, wildcard, publisher, and platform-qualified policies must retain their behavior. Acceptance includes range boundaries, prerelease handling, exclusions, conflicting entries, and exact-version compatibility.
- **Trace:**

  > The policy is registered in src/vs/platform/extensionManagement/common/extensionManagement.ts, where extension-specific arrays currently accept arbitrary strings but describe only exact versions and optional platforms. AllowedExtensionsService in src/vs/platform/extensionManagement/common/allowedExtensionsService.ts parses each entry with `VersionRegex` and accepts it only when the parsed version equals the extension version; this conclusively leaves ranges and inversion unsupported on current main. Existing behavioral coverage is in src/vs/platform/extensionManagement/test/common/allowedExtensionsService.test.ts. Keep publisher lookup, wildcard fallback, `stable` prerelease filtering, unknown-version handling, and the established exact `version@platform` behavior unchanged. The uncertainty starts at the externally visible policy grammar and the precedence rules when positive and negative entries both match.
- **Open decisions:**
  - Which public range grammar should the policy support: only the requested comparison operators, or a documented semantic-version range syntax including compound ranges and prerelease semantics?
  - When positive and negated entries both match an extension version, does any matching exclusion always win, or does array order determine the result?
  - Should negation be valid only for extension-specific version entries, or also for publisher and wildcard policy forms?

## Evidence

- **accepted demand:** https://github.com/microsoft/vscode/issues/314923 has 23 community upvotes and was moved to the Backlog after meeting the documented 20-upvote threshold.
- **current implementation gap:** src/vs/platform/extensionManagement/common/allowedExtensionsService.ts defines `VersionRegex` for one literal semantic version with an optional `@platform`, and `AllowedExtensionsService.isAllowed` compares the parsed value using strict equality (`v !== version`); comparator ranges and negated entries are not interpreted.
