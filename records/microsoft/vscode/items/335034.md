# Issue #335034 — Codex Agent Host fails in workspaces using only an extension-registered filesystem

[https://github.com/microsoft/vscode/issues/335034](https://github.com/microsoft/vscode/issues/335034)

## Summary

Traced on main: the Codex Agent Host's working-directory pipeline in codexAgent.ts converts workspace URIs to `.fsPath` in many places without ever checking the URI scheme, so a workspace backed only by an extension-registered (non-`file://`) filesystem provider yields an empty/invalid path that the Rust side rejects as `AbsolutePathBuf deserialized without a base path` — matches the report closely, and this is a real gap, not a close.

## Change summary

Codex Agent Host cannot start a turn in a workspace whose only resources come from an extension-registered filesystem provider, because it assumes a native (`file://`) absolute path.

## Best solution

In src/vs/platform/agentHost/node/codex/codexAgent.ts, add explicit scheme handling for the working-directory/cwd resolution path (reject or gracefully substitute a managed temp folder when the workspace URI isn't `file://`, instead of blindly calling `.fsPath`); likely belongs alongside the closely related https://github.com/microsoft/vscode/issues/335037 which tracks the same non-native-filesystem gap for Agent Host file tools — a maintainer should confirm whether these two should be consolidated into one tracking issue.
