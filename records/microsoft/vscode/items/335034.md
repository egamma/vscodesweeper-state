# Issue #335034 — Codex Agent Host fails in workspaces using only an extension-registered filesystem

[https://github.com/microsoft/vscode/issues/335034](https://github.com/microsoft/vscode/issues/335034)

## Summary

Genuine, traceable gap: Codex Agent Host session creation blindly calls `.fsPath` on the workspace's working-directory URI without a scheme guard, so a non-`file://` (extension-registered) filesystem provider produces an invalid `cwd` that the Rust-side Codex process rejects as an unparseable absolute path.

## Change summary

Codex Agent Host fails to start a turn (`AbsolutePathBuf deserialized without a base path`) in workspaces whose only resources come from an extension-registered (non-`file://`) filesystem provider, while the classic Codex extension handles the same workspace fine.

## Best solution

In `src/vs/platform/agentHost/node/codex/codexAgent.ts`, session-start paths (e.g. `_startChatBacking`, `_deferChatBacking`) should apply the same scheme/absolute-path validation already used in `setWorkingDirectory` (line ~4169: `workingDirectory.scheme !== Schemas.file || !isAbsolute(...)`), and either fall back to a managed temp working directory or surface a clear error instead of forwarding a non-native URI's `.fsPath` as `cwd` to `thread/start`.
