# Issue #311200 — Clicking a row in "customizations" doesn't open that item

[https://github.com/microsoft/vscode/issues/311200](https://github.com/microsoft/vscode/issues/311200)

## Summary

Still reproduces on main as of the latest comment (June 4, 2026). The section parameter from a customizations view row click is not correctly forwarded when the editor opens — prior revert of the welcome-page-always behavior left the click-to-section navigation broken. Team-authored, keeping open.

## Change summary

Clicking a specific section row (e.g. 'Skills') in the customizations view opens the previously-active section instead of the clicked one.

## Best solution

Fix the click handler or command invocation path so that clicking a row in the customizations view passes the correct section ID to `selectSectionById` when the editor opens. The issue likely lives in how the section argument flows through the `AICustomizationManagementCommands.Open` command to the editor pane — the `selectSectionById` method itself works, but the caller may not be passing the section, or the editor may be restoring a persisted section that overrides it.
