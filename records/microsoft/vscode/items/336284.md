# Issue #336284 — Terminal: mouse release is never reported to the pty in any tracking mode or encoding; 1002 drag-motion missing too

[https://github.com/microsoft/vscode/issues/336284](https://github.com/microsoft/vscode/issues/336284)

## Summary

Well-documented report, but the mouse-tracking protocol encoding (press/release/motion escape sequences sent to the pty) is implemented entirely inside the `@xterm/xterm` dependency, not VS Code's own terminal code — this is a dependency (upstream) issue, so it stays open pending investigation in xterm.js rather than being closed.

## Change summary

In the integrated terminal, mouse button-release events (and 1002 button-drag motion) are never encoded/reported to the pty in any tracking mode (SGR 1006 or legacy X10), even though press events and 1003 any-motion events are reported correctly.

## Best solution

Confirm/trace this in xterm.js's own mouse-tracking handler (the library VS Code depends on via `@xterm/xterm`, currently pinned at ^6.1.0-beta.304 per package.json) — a fix would land upstream and then be picked up via a dependency bump in VS Code; no VS Code-owned terminal code implements this encoding path (no matches for VT200/X10/mouse-report logic under src/vs/workbench/contrib/terminal).
