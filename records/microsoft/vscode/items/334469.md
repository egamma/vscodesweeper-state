# Issue #334469 — Make Ctrl-P dirname/ focus dirname in Explorer

[https://github.com/microsoft/vscode/issues/334469](https://github.com/microsoft/vscode/issues/334469)

## Summary

Keep open as a feature request: Quick Open still lacks directory results offering Explorer and terminal actions. Existing commands provide the individual operations, but no verified open canonical owns this combined workflow.

## Change summary

Entering an existing directory path ending in '/' in Ctrl-P should offer actions to reveal and focus that directory in Explorer or open a terminal there.

## Best solution

Have the Quick Open owner assess directory-path action picks that reuse existing Explorer reveal and terminal-working-directory behavior without disrupting file search. Folder search infrastructure is related, but does not itself deliver the requested actions.

## Evidence

- **Current Quick Open capability:** src/vs/workbench/contrib/search/browser/searchQuickAccess.contribution.ts registers workbench.action.quickOpen as Go to File. In anythingQuickAccess.ts, getAbsolutePathFileResult and getRelativePathFileResults accept only stat.isFile; createAnythingPick offers split-editor opening and history removal, not directory Explorer/terminal actions.
- **Existing operations are partial coverage:** src/vs/workbench/contrib/files/browser/fileCommands.ts implements revealInExplorer by selecting a supplied workspace URI and focusing Explorer. src/vs/workbench/contrib/externalTerminal/browser/externalTerminal.contribution.ts implements openInIntegratedTerminal using a directory URI as cwd. Neither exposes the requested dirname/ action list in Ctrl-P.
- **Related open infrastructure request:** https://github.com/microsoft/vscode/issues/241853 is open and requests ISearchService folder searching for Explorer and chat attachments. It does not describe the same Ctrl-P directory-action workflow, so it does not meet the stronger duplicate bar for this re-reviewed item.
- **Earlier matching UX request is closed:** https://github.com/microsoft/vscode/issues/287114 requests Go to Folder and mentions opening terminals. It was closed for insufficient community upvotes, as documented at https://github.com/microsoft/vscode/issues/287114#issuecomment-4062105154, not because the capability was implemented or categorically excluded from core. It cannot serve as an open duplicate canonical.
- **Decline precedent does not cover the full request:** https://github.com/microsoft/vscode/issues/130507#issuecomment-896675501 explains that folder-name fuzzy matching already returns files inside folders. That does not cover selecting the directory itself or offering Explorer and terminal actions. Older Explorer-only requests https://github.com/microsoft/vscode/issues/54904 and https://github.com/microsoft/vscode/issues/57402 were closed through backlog grooming, without a decision covering both requested actions.
