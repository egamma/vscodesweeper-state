# Issue #339731 — Can't disable plugin with `/plugin disable`

[https://github.com/microsoft/vscode/issues/339731](https://github.com/microsoft/vscode/issues/339731)

## Summary

Traced a plausible concrete defect in the /plugin disable (and enable) handler: it resolves the matching plugin via findPlugin() (to check marketplace/enabled state and disambiguate) but then discards that resolved object and calls plugins.enable/disable with the raw user-typed string instead of the plugin's canonical name — which would explain a marketplace-qualified disable failing while a bare-name disable behaves differently. This is still an early-stage Agent Plugins 1.0 feature under active internal testing, so I can't confirm the exact SDK contract without executing it.

## Change summary

`/plugin disable name@marketplace` reports the plugin isn't installed even though it was just installed with that exact marketplace-qualified name; omitting the marketplace gives a different result.

## Best solution

In the enable/disable case of invokeCopilotPluginCommand (src/vs/platform/agentHost/node/copilot/copilotCustomizationCommandDisplay.ts), pass the resolved plugin's canonical identifier (e.g. `plugin.name`) returned by findPlugin() to plugins.enable/disable instead of the raw `rest` string, once it's confirmed what identifier format the Copilot SDK's plugins.enable/disable `names` parameter actually expects.
