# Issue #339731 — Can't disable plugin with `/plugin disable`

[https://github.com/microsoft/vscode/issues/339731](https://github.com/microsoft/vscode/issues/339731)

## Summary

Fresh, well-documented repro (screenshots across two attempts, including a clean session) of `/plugin disable` wrongly reporting an installed plugin as not installed; keeping this open for diagnosis since the matching logic involved spans both VS Code wiring code and the external Copilot SDK runtime.

## Change summary

`/plugin disable <name>@<marketplace>` (and the bare name) fails to find a plugin the user just installed with `/plugin install`, reporting it as not installed.

## Best solution

Trace why `findPlugin` in copilotCustomizationCommandDisplay.ts fails to match the just-installed plugin against the live `plugins.list()` result — likely a mismatch between the marketplace alias used at install time and the `plugin.marketplace` value returned by the Copilot SDK's `plugins.list()` RPC — then align the matching (or the SDK's reported field) so enable/disable can find installed plugins by both `name` and `name@marketplace`.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotCustomizationCommandDisplay.ts`
- **Validation:** Reproduce in a live Agent Host session: install a plugin from a marketplace, then run `/plugin disable <name>@<marketplace>` and `/plugin disable <name>` and confirm both succeed instead of reporting 'not installed'.
- **Behavior:**

  > After `/plugin install <name>@<marketplace>` succeeds, `/plugin disable <name>@<marketplace>` (and `/plugin disable <name>`, if unambiguous) must find and disable that plugin instead of reporting it as not installed. The same applies to `/plugin enable`. Acceptance: disabling/enabling an installed plugin by either form of its name succeeds and the plugin's enabled state actually changes.
- **Trace:**

  > `findPlugin()` in src/vs/platform/agentHost/node/copilot/copilotCustomizationCommandDisplay.ts filters `(await plugins.list()).plugins` by exact match of `pluginDisplayName(plugin.name, plugin.marketplace)` or `plugin.name` against the user-supplied target string; a miss returns the 'Plugin {0} is not installed.' message (`copilotPlugin.notFound`). The reporter shows this failing for a plugin installed moments earlier via `/plugin install gh-skills-builder@awesome-copilot`, and reports a different (unspecified) message when the marketplace suffix is omitted — consistent with `plugin.marketplace` from the live `plugins.list()` RPC not equaling the `awesome-copilot` alias used at install time. The RPC implementation itself lives in the external `@github/copilot-sdk` package (not in this repo), so confirming the exact mismatch requires running a live session with logging/inspection of the `list()` result, not just reading this file. Do not change the `install`/`uninstall`/`update` code paths, which are not reported as broken.
- **Open decisions:**
  - Confirm via a live session what `plugin.marketplace` actually contains for a plugin installed through a marketplace alias (e.g. does `plugins.list()` return the alias, a resolved URL, or something else) to determine whether the fix belongs in VS Code's matching logic or needs a corresponding change upstream in @github/copilot-sdk.

## Evidence

- **matching code:** src/vs/platform/agentHost/node/copilot/copilotCustomizationCommandDisplay.ts `findPlugin()` compares the user's target string against `pluginDisplayName(plugin.name, plugin.marketplace)` (`name@marketplace`) or `plugin.name` from `plugins.list()`; if the SDK's `list()` reports `marketplace` in a different form than the alias used at install (`awesome-copilot`), the match silently fails and the generic 'Plugin {0} is not installed.' message (`copilotPlugin.notFound`) is shown even though the plugin was just installed.
- **external dependency:** The actual `plugins.list/enable/disable` implementation is in `@github/copilot-sdk` (CopilotSession['rpc']['plugins']), not vendored in this checkout, so the exact shape of the returned `marketplace` field for a newly-installed plugin can't be confirmed from source alone — this needs a live session to pin down whether the bug is in VS Code's matching code or the SDK's reported data.
- **reporter confirmation:** Reporter reproduced it twice with screenshots, including in a brand-new session, and also found that omitting the marketplace suffix changes the error message, pointing at a matching/formatting mismatch rather than a one-off fluke.
- **related testing issue:** Filed against https://github.com/microsoft/vscode/issues/339612, an umbrella 'Test: Copilot plugin slash commands in Agent Host' tracking issue — not a duplicate target, just the parent test effort; other sibling reports (https://github.com/microsoft/vscode/issues/339724, https://github.com/microsoft/vscode/issues/339725) cover different symptoms of the same feature, not this one.
