# Issue #188572 — Open selected tab via extension API

[https://github.com/microsoft/vscode/issues/188572](https://github.com/microsoft/vscode/issues/188572)

## Summary

The requested capability is still absent on current main, has 31 community upvotes, and was accepted into the Backlog after a maintainer agreed that activating an existing tab is distinct from opening an arbitrary editor. Keep it open for API design and implementation.

## Change summary

Expose an extension API that activates an already-open editor tab represented by a `vscode.Tab`.

## Best solution

Add a narrowly scoped API for activating an existing `Tab`, including custom-editor and webview tabs, without expanding the contract to construct or open arbitrary editor inputs. The API review should settle its placement, naming, and focus semantics first.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostEditorTabs.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadEditorTabs.ts`, `src/vs/workbench/api/test/browser/extHostEditorTabs.test.ts`, `src/vs/workbench/api/test/browser/mainThreadEditorTabs.test.ts`
- **Validation:** Add tests to the ExtHostEditorTabs and MainThreadEditorTabs suites proving that activating a background `Tab` selects its exact existing `EditorInput` in the owning group without creating another tab; run `scripts/test.sh --grep 'ExtHostEditorTabs|MainThreadEditorTabs'`.
- **Behavior:**

  > Given a valid `vscode.Tab` that is already open, an extension can make that exact tab active. This must work for resource-backed editors as well as custom editors and webviews because the operation uses tab identity rather than reconstructing an input from a URI. It must not create a duplicate tab or introduce an API for opening arbitrary new inputs. Acceptance includes activating a background tab and observing it through `TabGroup.activeTab` and the existing tab-change events.
- **Trace:**

  > `TabGroups` in `src/vscode-dts/vscode.d.ts` currently exposes observation and close operations only. `ExtHostEditorTabs` in `src/vs/workbench/api/common/extHostEditorTabs.ts` already preserves `Tab` identity and resolves public objects through `_findExtHostTabFromApi`, but there is no activation method or corresponding RPC in `src/vs/workbench/api/common/extHost.protocol.ts`. `MainThreadEditorTabs` in `src/vs/workbench/api/browser/mainThreadEditorTabs.ts` maintains `_tabInfoLookup`, which associates a tab ID with its owning group and concrete `EditorInput`; that is the relevant path for operating on an existing tab. The boundary established by the issue discussion is activation only: do not add construction or opening of arbitrary editor inputs. https://github.com/microsoft/vscode/issues/148085 concerns moving tabs and remains separate.
- **Open decisions:**
  - Should the public contract be an operation on `TabGroups`, an operation on the owning `TabGroup`, or an activation method on `Tab` itself, and should it be named `activate`, `select`, or `open`?
  - When the target belongs to an inactive group, must activation also make that group active and focus its editor, or should the API expose a preserve-focus option?

## Evidence

- **current API gap:** On current main, `TabGroups` in `src/vscode-dts/vscode.d.ts` exposes tab enumeration, change events, and `close(...)`, but no method that selects or activates an existing `Tab`.
- **extension-host boundary:** `src/vs/workbench/api/common/extHostEditorTabs.ts` implements only close operations for public `Tab` objects, while `MainThreadEditorTabsShape` in `src/vs/workbench/api/common/extHost.protocol.ts` contains `$moveTab`, `$closeTab`, and `$closeGroup` but no activation RPC.
- **bounded internal path:** `src/vs/workbench/api/browser/mainThreadEditorTabs.ts` already maps each tab ID to its owning group and concrete `EditorInput` for move and close operations; existing workbench group APIs can open an existing `EditorInput` to make it active.
- **maintainer direction and demand:** The discussion at https://github.com/microsoft/vscode/issues/188572 distinguishes activation of an existing tab from opening a newly constructed input; a maintainer invited an implementation attempt, and the request entered the Backlog after receiving more than 20 upvotes.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/148085 requests moving tabs between groups, not activating an existing tab, so it does not own the same reporter-observable capability and is not a duplicate canonical.
