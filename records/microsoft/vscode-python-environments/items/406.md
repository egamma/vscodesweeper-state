# Issue #406 — Use the Prefix path for the environment when autofinding projects

[https://github.com/microsoft/vscode-python-environments/issues/406](https://github.com/microsoft/vscode-python-environments/issues/406)

## Summary

The accepted team-authored bug remains present on current main: Auto Find Projects excludes only directories named `.venv`, so project metadata inside a differently named or located selected environment prefix can still be offered as a workspace project. The existing `needs PR` label also marks this as accepted work that must remain open.

## Change summary

Auto Find Projects should ignore every `pyproject.toml` and `setup.py` beneath the workspace environment's `sysPrefix`, rather than excluding only `.venv` directories.

## Best solution

Pass access to the selected workspace environment into `AutoFindProjects`, obtain its `sysPrefix`, and filter discovered project files contained by that prefix using cross-platform normalized path containment. Preserve the `.venv` exclusion as an efficient search-level default while covering environments with arbitrary names and locations.
