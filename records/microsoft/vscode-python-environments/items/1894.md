# Issue #1894 — Automatic environment picks are saved like explicit ones; new .venv ignored

[https://github.com/microsoft/vscode-python-environments/issues/1894](https://github.com/microsoft/vscode-python-environments/issues/1894)

## Summary

The automatic-selection persistence defect remains in current main: discovery still treats the cached automatic choice as an explicit selection. Keep this team-authored report open in its existing environment area; the newer project-root preference does not repair already-saved automatic picks.

## Change summary

Automatically selected environments remain pinned after a preferred project-local .venv is created, while a fresh profile selects the new environment.

## Best solution

Preserve fast startup from cached automatic selections, but let completed discovery reconsider them while keeping explicit user choices authoritative. Establish how existing persisted selections without provenance should be treated before changing their behavior.

- **Behavior:**

  > An automatically selected tools/.venv must not permanently prevent selection of a subsequently created, preferred project-root .venv. Discovery should update the selected interpreter without requiring a fresh profile, and the resulting choice should survive reload. An explicit selection of tools/.venv must remain authoritative through discovery and reload. Cached automatic choices should remain usable during startup.
- **Trace:**

  > applyInitialEnvironmentSelection in src/features/interpreterSelection.ts passes false to setEnvironment, but the registry still invokes the manager's persistent setter. VenvManager.set writes through setVenvForWorkspace, and loadEnvMap restores that path before evaluating newly discovered candidates; the checkout and live-main source both show this chain. SysPythonManager has the equivalent workspace persistence path. The merged improvement at https://github.com/microsoft/vscode-python-environments/pull/1880 changes candidate preference only in the absence of saved state, so it leaves this defect intact. Preserve explicit selections, configured selection priorities, and current-main selection-revision safeguards; unrelated manager ranking and terminal activation changes are outside this report. The unresolved boundary is existing path-only state, which cannot reveal whether the original choice was automatic or explicit.
- **Open decisions:**
  - Should existing persisted selections without provenance remain pinned to protect possible explicit choices, or become eligible for automatic reconsideration so previously affected workspaces recover without manual intervention?
