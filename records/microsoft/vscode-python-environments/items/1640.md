# Issue #1640 — Please make `python-envs.terminal.autoActivationType` syncable to all remotes

[https://github.com/microsoft/vscode-python-environments/issues/1640](https://github.com/microsoft/vscode-python-environments/issues/1640)

## Summary

A real configuration gap remains for remote and dev-container users: the setting is declared machine-scoped, so its value is not ordinarily synchronized to new remotes. A maintainer has explicitly invited a contribution, so this should remain open and be routed to terminal activation.

## Change summary

Allow users to establish a synchronized default for `python-envs.terminal.autoActivationType` while retaining the ability to override it for an individual remote.

## Best solution

Expose a syncable user-level activation default while preserving a higher-precedence remote override for hosts that require different activation behavior. Reuse and document the existing `globalRemoteValue` → `globalLocalValue` → `globalValue` precedence in `getAutoActivationType`, and ensure the configuration declaration and Settings UI make the local default practical to set.

- **Fit:** aligned
- **Reason:** Preventing disruptive activation commands across remote sessions advances the extension's core terminal-activation correctness and rollout stability.
- **Evidence:** The vision identifies terminal activation across shells and integration with the core Python extension as durable themes, and states that "Performance and stability trumps functionality."
