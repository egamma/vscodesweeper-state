# Issue #1778 — Python Extension and Python Environment Extension both activate when `python.useEnvironmentsExtension` defaults to false

[https://github.com/microsoft/vscode-python-environments/issues/1778](https://github.com/microsoft/vscode-python-environments/issues/1778)

## Summary

Keep open: current source still allows Python Environments to activate while its commands are hidden and Python's integration gate selects the legacy backend. The status-bar fix addressed only part of the report; the related newer issues do not own its full cross-extension ownership problem.

## Change summary

Make extension activation, environment ownership, command visibility, and integration APIs agree when python.useEnvironmentsExtension defaults to false.

## Best solution

Establish one ownership contract across Python and Python Environments, including third-party consumers, and make the UI and backend consistently follow it. Coordinate with the default-change work while preserving explicit opt-out and settings precedence.

- **Behavior:**

  > With both extensions installed and experiments disabled, environment management must have one consistent owner. An unset setting must not produce an active environment backend whose selection commands are hidden or whose ownership disagrees with Python's APIs. Explicit opt-in and opt-out must remain coherent under VS Code settings precedence. Acceptance checks must cover selectors, command visibility, interpreter selection, execution, and integration API behavior.
- **Trace:**

  > src/extension.ts gates activation through isEnvironmentsExtensionEnabled in src/features/settings/settingHelpers.ts, which ignores contributed defaults and resolves explicit values per workspace folder. Its unit suite explicitly preserves activation for an unconfigured default false. package.json independently gates python-envs.set and other UI on the effective configuration value, confirming the hidden-command path. Python's src/client/envExt/api.internal.ts retains separate shouldEnvExtHandleActivation and useEnvExtension policies; the latter reads the effective value. https://github.com/microsoft/vscode-python/pull/25895 covers only the status display, while https://github.com/microsoft/vscode-python-environments/issues/1908 tracks the default rollout and https://github.com/microsoft/vscode-python-environments/issues/1892 tracks hidden UI. Preserve explicit opt-out and scope precedence; this issue does not require changing manager discovery or terminal shell behavior. The remaining uncertainty is the agreed ownership contract for an installed extension when the effective default remains false.
- **Open decisions:**
  - When Python Environments is installed but the setting is unset and its effective default is false, should environment management belong to Python Environments or remain with legacy Python, consistently across UI, execution, and public APIs?
