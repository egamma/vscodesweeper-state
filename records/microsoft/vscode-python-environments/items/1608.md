# Issue #1608 — `python-envs.terminal.autoActivationType` migration script incorrectly targets Workspace settings instead of User settings

[https://github.com/microsoft/vscode-python-environments/issues/1608](https://github.com/microsoft/vscode-python-environments/issues/1608)

## Summary

The defect remains on current main: legacy-setting migration omits the configuration target, causing VS Code to attempt a workspace write for a machine-scoped setting. Route this to terminal activation.

## Change summary

Migrating a disabled legacy terminal-activation preference tries to write the replacement setting at workspace scope instead of user scope.

## Best solution

Update the migration in `src/features/terminal/utils.ts` to explicitly target global User Settings, and extend its unit test to assert that target so the preference is persisted without a configuration error.
