# Issue #1608 — `python-envs.terminal.autoActivationType` migration script incorrectly targets Workspace settings instead of User settings

[https://github.com/microsoft/vscode-python-environments/issues/1608](https://github.com/microsoft/vscode-python-environments/issues/1608)

## Summary

Still present on current main: legacy-setting migration writes without specifying the required global target, causing VS Code to attempt a forbidden workspace update. Route this to terminal activation.

## Change summary

Migrating a disabled legacy terminal-activation setting incorrectly attempts to write the replacement setting to workspace settings.

## Best solution

Update the migration in `src/features/terminal/utils.ts` to write `terminal.autoActivationType` at `ConfigurationTarget.Global`, and adjust its unit test to require that target.
