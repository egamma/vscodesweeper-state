# Issue #1608 — `python-envs.terminal.autoActivationType` migration script incorrectly targets Workspace settings instead of User settings

[https://github.com/microsoft/vscode-python-environments/issues/1608](https://github.com/microsoft/vscode-python-environments/issues/1608)

## Summary

Still present on current main: the legacy-setting migration omits an explicit global target, so VS Code attempts a workspace write for a machine-scoped setting and rejects it. Route this confirmed bug to terminal activation.

## Change summary

Migrating a disabled legacy terminal-activation preference writes `python-envs.terminal.autoActivationType` to Workspace Settings instead of User Settings.

## Best solution

Update the legacy fallback in `src/features/terminal/utils.ts` to write `terminal.autoActivationType` with `ConfigurationTarget.Global`, and strengthen its unit test to require that target while preserving the existing effective `off` result.
