# Issue #479 — "Auto find" could be in the same quickpick

[https://github.com/microsoft/vscode-python-environments/issues/479](https://github.com/microsoft/vscode-python-environments/issues/479)

## Summary

The requested improvement remains missing: the project-creation picker still offers Auto Find before discovering whether any projects are available. Keep this accepted, team-authored request open; the maintainer comment supports avoiding the empty-result action, while integrating discovery into the initial picker still needs a UX decision.

## Change summary

Discover eligible Python projects before presenting the project picker, avoiding an Auto Find action that only produces a no-projects-found notification.

## Best solution

Make project discovery inform the initial add-project experience so users are not offered a known-empty action. Decide whether discovered projects appear directly in that picker or Auto Find remains a separate option shown only when eligible projects exist, preserving existing project-registration filtering and third-party creators.

- **Trace:**

  > The python-envs.addPythonProject command registered in src/extension.ts calls addPythonProjectCommand in src/features/envCommands.ts, which invokes pickCreator before creator.create(). pickCreator in src/common/pickers/managers.ts builds static Auto Find, Select Existing, and Create New entries. AutoFindProjects.create() in src/features/creators/autoFindProjects.ts performs discovery only after that selection, filters registered paths, displays a separate project picker, and adds selected projects through the project manager. Empty discovery currently produces an error notification, and existing unit tests assert that behavior. Preserve discovery eligibility, registration filtering, cancellation, other creator flows, and the public PythonProjectCreator contract; its current API exposes create(), not a separate discovery method. The unresolved boundary is the user-visible placement of discovered results, not whether empty discovery should be anticipated. https://github.com/microsoft/vscode-python-environments/issues/390 provides broader project-creator context but does not replace this request.
- **Open decisions:**
