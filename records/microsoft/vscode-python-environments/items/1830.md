# Issue #1830 — Python file now runs slowly

[https://github.com/microsoft/vscode-python-environments/issues/1830](https://github.com/microsoft/vscode-python-environments/issues/1830)

## Summary

Independent commenters confirm a roughly five-second delay before Python commands launch, with downgrading to 1.36.0 or disabling this extension restoring responsiveness. Keep this report as the investigation anchor and route it to terminal activation; the verified sibling report is related, but does not establish a broader canonical owner.

## Change summary

Running a Python file incurs a roughly five-second terminal preparation delay before the command and its output appear.

## Best solution

Restore prompt command dispatch on already-ready terminals while preserving startup synchronization for newly created terminals. Diagnose the extension's shell-integration wait separately from any delay inside VS Code's executeCommand path, coordinating with https://github.com/microsoft/vscode-python/issues/26179.

## Plan brief

- **Likely files:** `src/features/terminal/runInTerminal.ts`, `src/features/terminal/utils.ts`, `src/features/terminal/terminalManager.ts`, `src/test/features/terminal/runInTerminal.unit.test.ts`, `src/test/features/terminal/utils.unit.test.ts`
- **Validation:** Measure Run Python File dispatch for a trivial script on first and repeated runs in PowerShell and Command Prompt, with shell integration available and unavailable; repeated runs in a ready terminal must not incur the default five-second wait. Add fake-timer unit coverage distinguishing first-terminal readiness from subsequent command dispatch, while retaining the new-terminal synchronization behavior covered by the existing runInTerminal tests.
- **Behavior:**

  > Users report about five seconds between clicking Run Python File and seeing the launch command, rather than slower Python execution. Independent reports also describe delayed new-terminal startup in PowerShell and Command Prompt. A ready terminal should accept subsequent Python commands promptly without repeating a startup timeout. Newly created terminals must still initialize safely, and environment activation must complete before commands that depend on it.
- **Trace:**

  > The supplied shallow checkout predates the regression, so its runInTerminal implementation cannot establish post-regression behavior by itself. The merged diff at https://github.com/microsoft/vscode-python-environments/pull/1741 and current remote src/features/terminal/runInTerminal.ts show runInTerminal waiting whenever terminal.shellIntegration is absent. In src/features/terminal/utils.ts, waitForShellIntegration starts fresh event subscriptions on every call, and getShellIntegrationTimeout defaults to five seconds when integration is enabled; an already-idle supported shell may produce no new prompt event. TerminalManagerImpl.autoActivateOnTerminalOpen in src/features/terminal/terminalManager.ts also waits before activation. Recognized cmd terminals bypass the helper's wait, so this path does not conclusively explain all confirmations. The PR also documents a separate possible delay inside VS Code executeCommand, and https://github.com/microsoft/vscode-python/issues/26179 provides related repeated-run steps. Start by separating these timing boundaries; preserve environment selection, activation ordering, quoting, and the fish startup-race protection rather than treating removal of all waiting as the acceptance criterion.
