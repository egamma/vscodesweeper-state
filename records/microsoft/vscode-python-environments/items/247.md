# Issue #247 — Avoid creating new folders outside our existing ones

[https://github.com/microsoft/vscode-python-environments/issues/247](https://github.com/microsoft/vscode-python-environments/issues/247)

## Summary

The storage improvement remains needed: CMD shell-startup activation still creates %USERPROFILE%\.cmdrc, and shell integration does not replace that path for CMD. Route this accepted, needs-proposal item to the CMD terminal area; the existing behavior is intentional, so this is an enhancement rather than a broken activation flow.

## Change summary

Store extension-owned CMD startup scripts under the running VS Code instance's stable user-data directory instead of creating .cmdrc in the user's home directory.

## Best solution

Keep CMD shell-startup activation working while storing its extension-owned files beneath stable VS Code user data, independent of extension version directories. The proposal should account for the shared HKCU AutoRun entry, multiple VS Code installations or user-data locations, and existing startup customizations.
