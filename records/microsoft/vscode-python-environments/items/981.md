# Issue #981 — Configure environment via VSCode settings?

[https://github.com/microsoft/vscode-python-environments/issues/981](https://github.com/microsoft/vscode-python-environments/issues/981)

## Summary

A real configuration gap remains: current main can select an interpreter per workspace folder through `python.defaultInterpreterPath`, but cannot store a portable selected-environment mapping for each Python project. The existing `feature-request` and `area-environment` labels already route it correctly.

## Change summary

Allow teams to commit project-to-environment selections in VS Code workspace settings so fresh clones and containers require no manual selection.

## Best solution

Extend the project configuration model to support a portable manager-owned environment identifier or path per project, including multi-root workspaces and variables such as `${workspaceFolder}`. Selection startup should resolve that value before consulting each manager's private persisted state.
