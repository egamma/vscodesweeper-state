# Issue #981 — Configure environment via VSCode settings?

[https://github.com/microsoft/vscode-python-environments/issues/981](https://github.com/microsoft/vscode-python-environments/issues/981)

## Summary

Keep open: shared settings select an environment manager, but cannot declaratively map each Python project to a specific environment within that manager. The Pixi monorepo and preconfigured devcontainer examples establish a remaining capability gap.

## Change summary

Allow repository settings to specify each Python project's selected environment so teammates do not need to repeat manual selection.

## Best solution

Provide a portable, manager-aware project-to-environment configuration contract that works with third-party managers such as Pixi. Preserve existing manager preferences and distinguish shared configuration from each user's manual selection.

## Plan brief

- **Likely files:** `package.json`, `src/features/projectManager.ts`, `src/features/interpreterSelection.ts`, `src/features/envManagers.ts`, `src/features/settings/settingHelpers.ts`
- **Validation:** Open a fresh multi-root workspace with several named Pixi environments and repository-defined project mappings; verify each project's interpreter and newly activated terminal use its configured environment without manual selection. Repeat in a devcontainer containing both system Python and a preinstalled venv, and verify existing unconfigured workspaces retain their selection behavior.
- **Behavior:**

  > A fresh clone should associate each configured Python project with its intended environment without requiring each teammate to repeat manual selection. This must support multiple named environments from one Pixi manifest and deterministic selection in a devcontainer with multiple preinstalled interpreters. Acceptance includes matching interpreter selection and terminal activation for each configured project while preserving existing behavior when no shared environment selector is supplied.
- **Trace:**

  > package.json and PythonProjectSettings in src/features/projectManager.ts expose project paths and manager IDs, not a specific environment selector. resolvePriorityChainCore in src/features/interpreterSelection.ts returns manager-only results for pythonProjects and defaultEnvManager; applyInitialEnvironmentSelection then calls manager.get for each workspace folder. python.defaultInterpreterPath is a lower-priority workspace-level alternative, not a manager-aware project mapping. The remaining uncertainty is the public selector contract and its precedence relative to individual manual selections. Third-party managers must remain supported, and discovery configuration must not become an implicit environment choice. https://github.com/microsoft/vscode-python-environments/issues/1480 documents the same need but is closed; https://github.com/microsoft/vscode-python-environments/issues/2000 concerns a separate fallback decision.
- **Open decisions:**
  - Should shared project configuration identify an environment by a portable path, a manager-defined name or identifier, or support both through a public manager contract?
  - Should repository-defined environment mappings enforce the selection on every load or serve as defaults that an individual's explicit manual selection can override?

## Evidence

- **confirmed demand:** The reporter clarified that selecting the Pixi manager is insufficient; subsequent comments describe 19 workspace projects needing distinct named Pixi environments and devcontainers needing a deterministic choice among preinstalled interpreters.
- **configuration surface:** package.json contributes python-envs.pythonProjects with path, envManager, and packageManager, but no specific environment selector. src/features/projectManager.ts:38-44 likewise defines no environment-selection field.
- **partial existing capability:** src/features/interpreterSelection.ts:83-170 returns immediately for a configured project manager or defaultEnvManager, before considering python.defaultInterpreterPath. That interpreter-path setting can select a workspace interpreter when higher-priority manager configuration is absent, but does not express specific environment choices within the configured Pixi manager or arbitrary Python-project mappings.
- **selection commands:** src/extension.ts:484-495 registers python-envs.set and python-envs.setEnv as environment-selection commands; src/features/envCommands.ts implements interactive project selection. These commands do not provide a repository-stored declarative environment mapping.
- **documented storage boundary:** https://code.visualstudio.com/docs/python/environments explains that project settings store the environment manager while the specific selected environment is remembered separately. https://github.com/microsoft/vscode-python-environments/issues/1098 was closed for documentation updates, not implementation of the requested mapping.
- **closed related request:** https://github.com/microsoft/vscode-python-environments/issues/1480 requests project-path-to-environment-path settings, but is closed after the community-upvote window. It is neither an open duplicate target nor substantive maintainer precedent declining this capability.
