# Issue #981 — Configure environment via VSCode settings?

[https://github.com/microsoft/vscode-python-environments/issues/981](https://github.com/microsoft/vscode-python-environments/issues/981)

## Summary

A real configuration gap remains for sharing project-to-environment selections. The
existing settings can choose managers and one default interpreter per workspace folder, but they
cannot express a distinct selected environment for each Python project.

## Change summary

Allow teams to store portable project-to-environment selections in repository
or workspace settings so fresh clones and dev containers require no manual selection.

## Best solution

Extend the project configuration model with a portable environment selector,
such as a manager-defined stable identifier or workspace-relative interpreter path, and resolve it
for each Python project during initial selection. Preserve `python.defaultInterpreterPath` as the
simpler workspace-folder-level option.

## Vision fit

- **Fit:** aligned
- **Reason:** Shareable, deterministic project environment selection advances the
extension's Python Projects model and the core promise that the correct environment is selected and
activated.
- **Evidence:** The durable themes explicitly include the per-file/per-folder/per-project
environment model for Python Projects and integration flows honoring the selected environment.
