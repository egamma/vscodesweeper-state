# Issue #1485 — What is the global environment for?

[https://github.com/microsoft/vscode-python-environments/issues/1485](https://github.com/microsoft/vscode-python-environments/issues/1485)

## Summary

This is an API-usage question with a documented maintainer answer: project selections should remain project-scoped, while consuming extensions should subscribe to this extension's per-workspace environment-change API rather than relying only on the legacy global event.

## Change summary

Clarify whether a manager extension should update the legacy global interpreter when selecting a project environment, and which event consumers should use.

## Best solution

Keep manager selections scoped to their project and have consumers use `pythonEnvsApi.onDidChangeEnvironment`, falling back to the legacy Python-extension event only when this extension is unavailable. Do not synchronize the global interpreter merely to notify legacy consumers.
