# Issue #1485 — What is the global environment for?

[https://github.com/microsoft/vscode-python-environments/issues/1485](https://github.com/microsoft/vscode-python-environments/issues/1485)

## Summary

Maintainer guidance resolves the question: project and global selections are intentionally independent, and consumers should use this extension's per-workspace environment event rather than requiring manager extensions to overwrite the legacy global selection.

## Change summary

Clarify how the global environment relates to project-scoped selections and which event environment-consuming extensions should use.

## Best solution

Hatch should set only the project-scoped environment. Consumers such as Ruff and ty should subscribe to `pythonEnvsApi.onDidChangeEnvironment`, using its project URI, while retaining the legacy global event only as a fallback when this extension is unavailable.
