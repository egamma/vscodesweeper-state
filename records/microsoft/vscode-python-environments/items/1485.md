# Issue #1485 — What is the global environment for?

[https://github.com/microsoft/vscode-python-environments/issues/1485](https://github.com/microsoft/vscode-python-environments/issues/1485)

## Summary

The API guidance question has been answered in the linked discussion: global selection is a fallback, and Ruff/ty should consume project-scoped environment changes rather than require Hatch to overwrite it. Propose closing as a question, not as an implemented fix or duplicate.

## Change summary

Clarify global environment scope and how consuming extensions should follow project-scoped Hatch environment selections.

## Best solution

Keep global selection independent from project selection; consumers should use the Python Environments API's onDidChangeEnvironment and getEnvironment(uri), retaining legacy API support when necessary. The maintainer's linked guidance answers the integration question without requiring a behavior change here.

- **Proposed comment:**

  > Thanks for the context. Global selection is the fallback for files outside workspace folders, not a mirror of each project's environment. Your Hatch extension should not need to overwrite it whenever a project selection changes: consumers should use the Python Environments API's `onDidChangeEnvironment` and `getEnvironment(uri)` for scoped selections. The maintainer's explanation at https://github.com/microsoft/vscode-python-environments/issues/1491#issuecomment-4383115486 recommends supporting both APIs and preferring Python Environments when available. Closing this as an answered API question. For further support questions, please use https://github.com/microsoft/vscode-python/discussions/categories/q-a.
