## Summary

Keep open: the merged fix was followed by a confirmed failed verification and reopening, and current main again exposes the context-menu command based only on resource type. The assigned backlog milestone, `verification-found`, and accepted `needs proposal` state independently prohibit a close.

## Change summary

Hide or replace the “Add as Python Project” Explorer action for resources already represented as Python projects without preventing users from adding sibling projects.

## Best solution

Agree on a resource-aware project-management interaction that distinguishes the selected file or folder from its containing project, then implement it without hiding the action for unregistered sibling folders. The proposal should also settle whether the command remains an add action or becomes a manage/toggle action with clearer wording.
