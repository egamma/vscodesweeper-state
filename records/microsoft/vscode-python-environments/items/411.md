## Summary

Keep open: current source still silently discards syntactically malformed pyproject.toml files during dependency discovery, matching the post-fix report. The assigned December 2025 milestone independently bars a close.

## Change summary

Environment creation should provide actionable feedback for malformed pyproject.toml files instead of hiding installation errors or silently skipping dependencies.

## Best solution

Preserve TOML parse failures through dependency discovery so creation reports the affected file and error rather than silently creating an environment without its dependencies. Retain the agreed distinction between Quick Create and custom creation that does not select that file, and have the maintainer resolve the remaining behavior on this reopened issue.
