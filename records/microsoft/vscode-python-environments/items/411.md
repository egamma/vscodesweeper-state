# Issue #411 — More gracefully fail on `pyproject.toml` error

[https://github.com/microsoft/vscode-python-environments/issues/411](https://github.com/microsoft/vscode-python-environments/issues/411)

## Summary

A real gap remains on current main: TOML syntax errors are caught and converted to an empty object, allowing malformed pyproject.toml files to be silently ignored during dependency discovery. The issue is also team-authored, reopened after the cited fix, and assigned to a milestone, so it must remain open.

## Change summary

Environment creation should surface malformed pyproject.toml syntax and avoid silently creating an environment without the requested dependencies.

## Best solution

Preserve parser failures from tomlParse in src/managers/builtin/pipUtils.ts as validation errors and route them through the existing pyproject warning/cancellation flow. Add coverage for malformed dependency syntax so environment creation cannot silently treat an unparseable file as an empty project.
