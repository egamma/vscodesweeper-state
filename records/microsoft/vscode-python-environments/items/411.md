# Issue #411 — More gracefully fail on `pyproject.toml` error

[https://github.com/microsoft/vscode-python-environments/issues/411](https://github.com/microsoft/vscode-python-environments/issues/411)

## Summary

PR 1066 improved validation for several semantic errors, but malformed TOML can still be silently ignored on current main. The assigned December 2025 milestone also requires this issue to remain open.

## Change summary

Environment creation should surface actionable pyproject.toml errors before leaving users with an environment whose dependencies were not installed.

## Best solution

Extend the validation in `src/managers/builtin/pipUtils.ts` so TOML parser failures become actionable validation errors instead of an empty parsed document, while preserving the existing Open, Continue Anyway, and Cancel flow.
