# Issue #1573 — [Python Environments] default value of python-envs.workspaceSearchPaths is not respected

[https://github.com/microsoft/vscode-python-environments/issues/1573](https://github.com/microsoft/vscode-python-environments/issues/1573)

## Summary

The current default intentionally searches only the workspace root and one nested level, while the public documentation still promises recursive discovery. Keep this open to correct the documentation and evaluate a reusable workspace-relative configuration that does not restore the known performance problems.

## Change summary

Discover nested monorepo `.venv` environments by default or allow one global workspace-relative search pattern.

## Best solution

Update the public documentation to describe the actual `.venv` and `*/.venv` defaults, then decide whether a safe global workspace-relative search option can be added. Do not restore unconditional `**/.venv` scanning without addressing the documented PET timeout and large-workspace performance impact.

## Evidence

- **current default:** package.json:123-130 declares `python-envs.workspaceSearchPaths` as `[".venv", "*/.venv"]`, which cannot find `.venv` directories deeper than one nested folder.
- **intentional change:** https://github.com/microsoft/vscode-python-environments/pull/1419 deliberately replaced `./**/.venv` with the shallower defaults as a performance compromise; merged commit 3bb8ab8c51f9096f31d4322fdd9c35193eb42741.
- **performance evidence:** https://github.com/microsoft/vscode-python-environments/pull/1362 documents recursive workspace scanning causing PET timeouts and severe delays in large or remote workspaces.
- **documentation mismatch:** The current VS Code Python environments documentation says the default is `./**/.venv`, while package.nls.json:15 describes only a workspace-root `.venv` and package.json also includes one nested level.
- **global configuration gap:** src/managers/common/nativePythonFinder.ts:1636-1658 deliberately ignores a global `workspaceSearchPaths` value; `python-envs.globalSearchPaths` accepts absolute shared locations rather than a workspace-relative pattern applied to every project.
