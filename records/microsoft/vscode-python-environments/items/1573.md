# Issue #1573 — [Python Environments] default value of python-envs.workspaceSearchPaths is not respected

[https://github.com/microsoft/vscode-python-environments/issues/1573](https://github.com/microsoft/vscode-python-environments/issues/1573)

## Summary

Current main intentionally searches only the workspace root and its first-level folders by default, so recursive discovery at arbitrary depth requires explicit configuration. The public documentation still describes the superseded recursive default, while configuring one workspace-relative pattern globally remains a real unsupported request.

## Change summary

Correct the documented default and provide a way to configure workspace-relative environment search patterns once for all workspaces.

## Best solution

Update the public documentation and README to describe the actual `[".venv", "*/.venv"]` default. Separately, consider a machine-scoped setting for workspace-relative patterns so users can opt into recursive monorepo discovery globally without restoring the expensive recursive default for everyone; `python-envs.globalSearchPaths` currently covers absolute global locations instead.

- **Proposed comment:**

  > Thanks for the report and follow-up. The current default is intentionally `[".venv", "*/.venv"]`, which searches the workspace root and one folder level; the recursive `./**/.venv` default was removed in https://github.com/microsoft/vscode-python-environments/pull/1419 because of discovery-performance risks. The linked documentation is therefore stale and should be corrected. `python-envs.globalSearchPaths` supports absolute user-level locations, but it does not cover your request for one workspace-relative recursive pattern across every repository, so this should remain open for an area-owner decision on that capability.

## Evidence

- **current default:** `package.json` defines `python-envs.workspaceSearchPaths` with the default `[".venv", "*/.venv"]`, and `src/managers/common/nativePythonFinder.ts` returns that inspected default when no workspace or folder value is configured.
- **intentional change:** Commit 3bb8ab8c51f9096f31d4322fdd9c35193eb42741, merged through https://github.com/microsoft/vscode-python-environments/pull/1419, replaced `./**/.venv` with `.venv` and `*/.venv` to reduce discovery cost.
- **maintainer decision:** In https://github.com/microsoft/vscode-python-environments/issues/1366#issuecomment-4180832062, a maintainer confirmed that the intended compromise searches the root and one folder level rather than recursively.
- **documentation mismatch:** The current VS Code documentation at https://code.visualstudio.com/docs/python/environments#_configure-search-paths still says the default is `./**/.venv`, contradicting current main.
- **global capability gap:** `python-envs.globalSearchPaths` is machine-scoped but documented and implemented for absolute directories; the code deliberately ignores a global value for the resource-scoped `workspaceSearchPaths`, so it does not provide one reusable workspace-relative glob.
