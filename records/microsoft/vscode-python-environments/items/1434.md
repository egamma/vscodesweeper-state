# Issue #1434 — Startup stalls and Python environments appear missing during activation

[https://github.com/microsoft/vscode-python-environments/issues/1434](https://github.com/microsoft/vscode-python-environments/issues/1434)

## Summary

Keep open: this team-authored meta issue deliberately tracks a cluster of startup, manager-registration, and discovery failures, so it is protected from closure as a tracking artifact. The merged lazy-registration mitigation addressed part of the problem, but later reports demonstrate that third-party manager readiness can still race startup.

## Change summary

Prevent startup discovery and registration work from stalling activation or leaving built-in and third-party environment managers temporarily unavailable.

## Best solution

Retain this as the canonical performance and registration tracker while separating confirmed root causes into focused issues. The manager-readiness lifecycle should avoid blocking startup on PET or other managers, preserve configured third-party manager ownership while registration completes, and recover without requiring a reload.
