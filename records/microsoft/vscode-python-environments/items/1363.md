# Issue #1363 — Visual Studio Code failed to recognize default python interpreter path

[https://github.com/microsoft/vscode-python-environments/issues/1363](https://github.com/microsoft/vscode-python-environments/issues/1363)

## Summary

The original recursive workspace-scan failure was fixed and confirmed resolved, but
this issue now contains a concrete later reproduction on 1.30.0 where PET times out resolving a
valid interpreter. A separate request for wrapper-script support also remains undecided, so closing
the broad report would lose actionable evidence.

## Change summary

Configured default interpreter paths fail to resolve when PET hangs, and
executable wrapper scripts are rejected as interpreter paths.

## Best solution

Route the PET resolve-timeout reproduction to the environment-discovery owner
and determine why resolving `/usr/bin/python` competes with long-running manager discovery. Track
wrapper-script support as a distinct environment-selection capability so its execution, identity,
and activation semantics can be decided independently.
