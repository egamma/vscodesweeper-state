# Issue #1053 — Feature Request: activate default project python/conda environment when launching a task

[https://github.com/microsoft/vscode-python-environments/issues/1053](https://github.com/microsoft/vscode-python-environments/issues/1053)

## Summary

A real capability gap remains: current main explicitly prevents command-based activation in task terminals, while shell-startup activation is the only documented path that can prepare the environment before a task command runs. The issue already has the appropriate feature and area labels.

## Change summary

Activate the task's owning project's selected Python or conda environment before executing commands from that project's tasks.json.

## Best solution

Add task-aware activation that resolves the selected environment from the task's workspace project and makes it available before the task command starts, covering both command and shell-startup activation without overriding an explicit `off` setting. Preserve the task's input and execution semantics rather than injecting activation after its command has begun.

## Evidence

- **current source gap:** `src/features/terminal/terminalActivationState.ts` explicitly returns without activating when `isTaskTerminal(terminal)` is true, logging `Cannot activate environment in a task terminal`.
- **task detection:** `src/features/terminal/utils.ts` identifies task terminals through the proposed `TaskExecution.terminal` API, so current main can recognize these terminals but deliberately excludes them from command activation.
- **existing capability check:** `package.json` exposes only `command`, `shellStartup`, and `off` for `python-envs.terminal.autoActivationType`; the default `command` path does not satisfy this request for task terminals.
- **maintainer intent:** A maintainer accepted this as a feature request at https://github.com/microsoft/vscode-python-environments/issues/1053#issuecomment-3643147317, while another identified it as a significant regression affecting common task workflows at https://github.com/microsoft/vscode-python-environments/issues/1053#issuecomment-3635556462.
- **related report:** The closed predecessor https://github.com/microsoft/vscode-python-environments/issues/1040 documents that shell-startup activation is intended to support Tasks, but it does not cover the broader request to support task activation across activation modes.
