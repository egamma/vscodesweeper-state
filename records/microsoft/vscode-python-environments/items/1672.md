# Issue #1672 — Jupyter kernel startup delayed 30s+ with pixi environment on WSL2 (continuation of locked #1407)

[https://github.com/microsoft/vscode-python-environments/issues/1672](https://github.com/microsoft/vscode-python-environments/issues/1672)

## Summary

The 30-second delay is well-supported and remains unresolved, but the failing activation command comes from the third-party Pixi Code manager integration rather than this repository's built-in managers. Keep this open as an integration/API boundary issue while coordinating the fix with the open Pixi Code tracker.

## Change summary

Pixi-backed Jupyter kernels on WSL2 repeatedly wait 30–35 seconds because environment-variable collection invokes the non-returning `pixi shell` command.

## Best solution

Update the Pixi Code manager's execution metadata so non-interactive environment-variable collection uses a terminating command such as `pixi run`, while retaining a valid interactive activation/deactivation path. The area owner should also determine whether this extension or PET should cache the failed Pixi-as-conda probe to prevent repeated work against the same environment.

## Evidence

- **confirmed failure:** The report captures a 35,151 ms activated-environment-variable timeout on WSL2 and identifies the generated `pixi shell ... && ...` command; `pixi shell` starts an interactive shell and therefore does not reach the chained commands.
- **prior confirmations:** https://github.com/microsoft/vscode-python-environments/issues/1407 contains independent macOS, Windows, and Linux confirmations, including the same command and timeout. It was closed by the info-needed automation rather than by a fix.
- **upstream canonical:** https://github.com/renan-r-santos/pixi-code/issues/43 is open and tracks the same 30-second Jupyter startup delay. Its maintainer agrees that the component collecting variables should use `pixi run` instead of chaining commands after `pixi shell`.
- **source ownership:** Current `src/managers/builtin/utils.ts` detects Pixi environments only to recommend `renan-r-santos.pixi-code`; this repository contains no built-in Pixi activation implementation. Pixi Code's `src/pixi/utils.ts` supplies `activation: pixi shell` and separately supplies `activatedRun: pixi run ... python`.
- **API boundary:** `src/api.ts` defines `activation` and `activatedRun` as manager-provided execution metadata, while `src/features/common/activation.ts` consumes the supplied activation command without Pixi-specific behavior.
- **related report:** https://github.com/microsoft/vscode-python-environments/issues/1712 reproduces the same activation timeout on Windows but additionally reports a kernel crash, so it is related rather than a narrower canonical for this delay report.
