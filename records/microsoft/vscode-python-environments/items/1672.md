Retest the reported WSL2 project with Python Environments enabled and distinguish activation delays from repeated discovery requests.
- **Trace:**

  > The historical logs show core Python collecting variables by chaining commands after `pixi shell`, which does not return until its interactive shell exits. https://github.com/microsoft/vscode-python/commit/d0d4dede6bc9fabae3c41bdb1609c1f4090c1753 now lets System/Unknown interpreters use the non-interactive Pixi resolver; current core main retains that behavior. Locally, src/managers/builtin/utils.ts resolves Pixi interpreters through the generic System fallback despite excluding Pixi from discovery enumeration. The remaining uncertainty is whether the WSL2 timeout persists after that sibling fix and what initiates the reported reselection and repeated requests through src/managers/common/nativePythonFinder.ts. PET warnings alone do not prove their causal relationship to kernel disposal. Preserve ordinary System/venv behavior and distinguish background variable collection from intentional interactive terminal activation.
