# Issue #1672 — Jupyter kernel startup delayed 30s+ with pixi environment on WSL2 (continuation of locked #1407)

[https://github.com/microsoft/vscode-python-environments/issues/1672](https://github.com/microsoft/vscode-python-environments/issues/1672)

## Summary

The primary timeout is caused by the third-party Pixi manager extension registering the non-returning `pixi shell` command for activation. This report also adds repeated WSL2 environment probing and automatic kernel reselection that may involve the integration boundary, so it should remain open rather than be folded entirely into the upstream tracker.

## Change summary

Pixi-backed Jupyter kernels stall for 30–35 seconds during activation and may repeatedly reselect and re-probe the same environment on WSL2.

## Best solution

The Pixi manager extension should provide an API-compatible activation command that does not launch a blocking interactive shell; that work is tracked by https://github.com/renan-r-santos/pixi-code/issues/43. Separately trace the repeated kernel reselection and negative conda-detection behavior to determine whether this extension, PET, or Jupyter should cache or suppress redundant resolution attempts.
