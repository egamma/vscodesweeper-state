## Summary

Verified duplicate of the open Pixi activation-timeout cluster: the same non-returning `pixi shell` command delays environment-variable collection and can leave the Jupyter kernel without the activated environment. The canonical continuation already covers repeated kernel disposal and the same root cause.

## Change summary

A Windows Pixi-backed Jupyter kernel crashes when plotting after activated-environment collection times out twice.

## Best solution

Consolidate the investigation in https://github.com/microsoft/vscode-python-environments/issues/1672 and correct the Pixi integration so activated environment variables are obtained through a non-blocking Pixi execution path rather than chaining commands after interactive `pixi shell`. Preserve this report's Windows, Matplotlib, path-with-spaces, and exit-code evidence in the canonical cluster.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode-python-environments/issues/1672 is open and continues the confirmed Pixi activation-timeout problem: `pixi shell` starts an interactive shell, so chained environment-variable commands never run before the 30-second timeout; it also reports repeated kernel disposal and reselection.
- **independent confirmation:** https://github.com/microsoft/vscode-python-environments/issues/1407 contains independent Windows confirmation of the same 30-second timeout followed by kernel exit code `0xC06D007F` (decimal 3228369023), matching this report exactly.
- **Pixi integration source:** The current Pixi Code implementation registers `execInfo.activation` as `pixi shell --manifest-path ... -e ...` in `src/pixi/utils.ts`; this repository's `api.ts` defines that activation command as the environment-manager-provided execution path.
- **upstream integration tracker:** https://github.com/renan-r-santos/pixi-code/issues/43 remains open for this same integration defect, and its maintainer agrees that chaining commands after `pixi shell` is unsuitable and that environment-variable collection should use a `pixi run` path.
- **report controls:** The reporter reproduced the crash on Python 3.12 and 3.14, confirmed the environment works with `pixi run`, browser Jupyter, and manual kernel selection, and isolated the failure to the Python Environments plus Pixi Code integration.
