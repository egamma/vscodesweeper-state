# Issue #1925 — "Default interpreter path ... could not be resolved" for a valid path while the PET locator is still starting

[https://github.com/microsoft/vscode-python-environments/issues/1925](https://github.com/microsoft/vscode-python-environments/issues/1925)

## Summary

The checked-out source turns locator timeouts into configuration errors and retains the warning even when subsequent discovery selects a working environment. Keep this report open and route it to environment discovery; the supplied startup configuration and logs are sufficient for investigation.

## Change summary

A valid defaultInterpreterPath produces a misleading configuration warning when locator startup times out, even though discovery subsequently selects the same environment.

## Best solution

Distinguish transient locator failures from invalid interpreter settings during initial selection, preserving successful discovery fallback and actionable warnings for genuinely invalid paths. Include the expanded path in resolution diagnostics without changing the user's configured value.
