# Issue #401 — Bug: Children Projects in Settings

[https://github.com/microsoft/vscode-python-environments/issues/401](https://github.com/microsoft/vscode-python-environments/issues/401)

## Summary

The requested inheritance behavior remains absent on current main: adding any non-root project still persists a `pythonProjects` entry without checking whether a parent project has matching managers. This team-authored issue must remain open, and no canonical issue or explicitly referencing fix was found.

## Change summary

Avoid persisting a nested Python project when it inherits the same environment and package managers from its nearest configured parent.

## Best solution

Make project-setting persistence inheritance-aware in `PythonProjectManagerImpl.add` or `addPythonProjectSetting`: resolve candidate and existing entries to full URIs, find the nearest containing project within the correct workspace root, and omit or remove the child override when both managers match. Preserve explicit child overrides when they differ, including the `workspace` discriminator in multi-root workspaces.
