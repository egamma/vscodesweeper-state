# Issue #533 — switch to dependency groups for new package flow

[https://github.com/microsoft/vscode-python-environments/issues/533](https://github.com/microsoft/vscode-python-environments/issues/533)

## Summary

The dependency-groups migration remains unimplemented on current main, and the team has explicitly deferred it pending community adoption. This is team-authored, accepted work carrying `needs spike`, so it must remain open.

## Change summary

Update newly generated package projects to express development dependencies using PEP 735 dependency groups rather than a dynamic optional-dependency backed by dev-requirements.txt.

## Best solution

After dependency-group tooling has sufficient ecosystem adoption, update the new-package template and its documentation to use a `[dependency-groups]` development group, removing the generated `dev-requirements.txt` indirection while preserving an installable package configuration.

- **Fit:** aligned
- **Reason:** Adopting the community-standard dependency-group format in generated projects supports the project-generation workflow without inventing extension-specific dependency behavior.
- **Evidence:** The vision states, "We use tooling provided and loved by the Python community before creating our own," and identifies Python Projects and package understanding as durable themes.
