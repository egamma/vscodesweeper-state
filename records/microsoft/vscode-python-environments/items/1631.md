# Issue #1631 — Auto-activation forces a single environment across an entire multi-project workspace root, injecting activate commands into unrelated terminals

[https://github.com/microsoft/vscode-python-environments/issues/1631](https://github.com/microsoft/vscode-python-environments/issues/1631)

## Summary

Still present on main: terminal auto-activation can choose the workspace-root environment before considering the new terminal's cwd, causing the wrong project environment to activate. Route this confirmed correctness bug to terminal activation.

## Change summary

Auto-activation applies one workspace-root environment to terminals opened in unrelated subprojects.

## Best solution

Resolve the environment from the terminal's initial cwd and most-specific project before any workspace-wide fallback; when no unambiguous match exists, avoid automatic activation rather than injecting a potentially wrong environment. The workspace-specific opt-out request should also be evaluated separately from shell-startup behavior.

## Evidence

- **source defect:** src/features/terminal/utils.ts:200-225 returns the sole registered project's environment at lines 203-204 and exits at lines 217-219; terminal cwd is only consulted afterward, so it cannot override a workspace-root selection.
- **activation path:** src/features/terminal/terminalManager.ts:98-109 handles every newly opened non-skipped terminal and activates the environment returned by getEnvironmentForTerminal.
- **project model:** src/features/projectManager.ts:118-152 always registers each workspace root as a project, which makes the single-project fast path applicable even when the root merely contains independent subprojects.
- **setting limitation:** package.json:92-106 declares python-envs.terminal.autoActivationType with scope "machine", confirming that it cannot currently be overridden for this workspace.
- **intended behavior:** A maintainer stated in https://github.com/microsoft/vscode-python-environments/issues/34#issuecomment-2510057501 that terminals are project-affine and activation should be based on the terminal cwd at creation, so the reported root-wide selection contradicts established intent.
