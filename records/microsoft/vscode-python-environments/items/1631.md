# Issue #1631 — Auto-activation forces a single environment across an entire multi-project workspace root, injecting activate commands into unrelated terminals

[https://github.com/microsoft/vscode-python-environments/issues/1631](https://github.com/microsoft/vscode-python-environments/issues/1631)

## Summary

The wrong-environment activation path is present on current main: terminal creation resolves the workspace-root project environment before consulting the terminal cwd. Route this to terminal activation and environment resolution.

## Change summary

Auto-activation applies one workspace-root environment to terminals opened in unrelated subprojects of a multi-project folder.

## Best solution

Resolve the terminal's cwd to its most specific project/environment before falling back to the workspace-root selection, and avoid automatic activation when sibling environments make that fallback ambiguous. Making `python-envs.terminal.autoActivationType` resource-scoped would also provide a per-workspace escape hatch.
