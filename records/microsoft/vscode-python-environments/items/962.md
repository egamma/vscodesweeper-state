# Issue #962 — Experimental roll out shell startup as default

[https://github.com/microsoft/vscode-python-environments/issues/962](https://github.com/microsoft/vscode-python-environments/issues/962)

## Summary

Keep open: this is a team-authored rollout and reliability-tracking issue, which is explicitly protected as a long-lived process artifact. The central work remains incomplete because shell-startup activation is available but the declared default is still command activation.

## Change summary

Make shell-startup activation reliable and well-tested, then progressively make it the default terminal activation mode.

## Best solution

Retain this issue as the rollout owner while the terminal team completes refactoring and coverage across supported shells, then deliberately changes `python-envs.terminal.autoActivationType` from `command` to `shellStartup` when reliability is sufficient. Continue tracking shell-specific defects separately rather than treating partial child work as completion.
