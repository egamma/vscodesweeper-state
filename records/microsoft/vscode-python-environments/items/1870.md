# Issue #1870 — External Conda environment appears twice after restart

[https://github.com/microsoft/vscode-python-environments/issues/1870](https://github.com/microsoft/vscode-python-environments/issues/1870)

## Summary

Keep open: the report establishes a repeatable startup race that duplicates a saved external Conda environment, and the vulnerable insertion remains on live main despite discovery refactoring. This team-authored issue has neither a verified canonical duplicate nor an explicitly linked landed fix.

## Change summary

Restarting VS Code can insert two objects for the same selected external Conda prefix, producing an extra interpreter-picker entry until refresh.

## Best solution

Make Conda collection population maintain one underlying entry per environment path when background discovery overlaps refresh, while preserving the saved selection and the intentional Recommended picker copy. The defect belongs in this extension's Conda manager, not PET's Windows path-casing deduplication.
