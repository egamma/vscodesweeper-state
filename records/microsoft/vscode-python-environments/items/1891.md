# Issue #1891 — Interpreter picker waits for unrelated environment discovery

[https://github.com/microsoft/vscode-python-environments/issues/1891](https://github.com/microsoft/vscode-python-environments/issues/1891)

## Summary

Keep open: the supplied main checkout still delays picker presentation until every manager returns, withholding Browse and the already-known recommended environment. The controlled reproduction and source trace establish a picker-responsiveness defect, not a failure to execute Python in project B.

## Change summary

Show the environment picker with known choices while unrelated discovery continues, incorporating late results without disrupting selection or reopening a dismissed picker.

## Best solution

Make environment selection in src/common/pickers/environments.ts responsive independently of full discovery, with a loading indication and safe incremental updates. Preserve Browse, creation, back navigation, focus, and dismissal behavior, and keep healthy choices usable when a manager fails.
