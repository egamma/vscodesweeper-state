# Issue #1500 — python.terminal.executeInFileDir no longer uses "cd" to switch the working directory

[https://github.com/microsoft/vscode-python-environments/issues/1500](https://github.com/microsoft/vscode-python-environments/issues/1500)

## Summary

Still present on current main: `python.terminal.executeInFileDir` determines the dedicated terminal's initial cwd, but rerunning the file reuses that terminal without restoring its directory. Route this reproducible regression to the terminal and bash areas.

## Change summary

Rerunning a Python file with `python.terminal.executeInFileDir` enabled no longer changes a reused terminal back to the file's directory.

## Best solution

Restore the setting's per-run behavior by changing to the file directory before executing Python in a reused dedicated terminal, while retaining terminal reuse and handling command construction correctly across supported shells. Add coverage for creating the terminal, simulating a user cwd change, and rerunning the same file.

## Evidence

- **source reproduction:** `src/features/terminal/terminalManager.ts` returns an existing terminal immediately from `dedicatedTerminals` before reading `python.terminal.executeInFileDir`; the configured file-directory cwd is applied only when creating a new terminal.
- **execution path:** `src/features/terminal/runInTerminal.ts` executes Python directly and does not inspect or apply `options.cwd`, so nothing restores the cwd after the user changes directory in the reused terminal.
- **command integration:** `src/features/envCommands.ts` reuses `getDedicatedTerminal(item, project, envFinal)` for subsequent runs and passes the project URI as `cwd`; current unit tests verify terminal reuse but do not cover restoring the file directory before rerunning.
- **existing documentation:** `README.md` documents `python.terminal.executeInFileDir` as setting the terminal working directory to the directory containing the executed Python file rather than the project root; the observed reused-terminal behavior no longer maintains that result.
