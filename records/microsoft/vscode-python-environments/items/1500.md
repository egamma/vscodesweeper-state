# Issue #1500 — python.terminal.executeInFileDir no longer uses "cd" to switch the working directory

[https://github.com/microsoft/vscode-python-environments/issues/1500](https://github.com/microsoft/vscode-python-environments/issues/1500)

## Summary

The reporter supplied the requested confirmation and logs: rerunning a file after manually changing directory still ignores executeInFileDir. The execution path retains this gap; route to the terminal area rather than requesting information again or closing.

## Change summary

With python.terminal.executeInFileDir enabled, rerunning a Python file in a reused terminal does not restore the file's directory, breaking relative-path operations.

## Best solution

Restore per-run file-directory behavior across the core Python command and Python Environments execution boundary, while preserving terminal reuse and the public API's documented creation-only cwd semantics. The reporter's October response supplies sufficient evidence to move this out of the information-request stage.

- **Behavior:**

  > When python.terminal.executeInFileDir is enabled, every Run Python File in Terminal invocation executes from the file's directory, including after the user changes the reused terminal's directory. Relative-path reads must work on the second run as they do on the first. Terminal reuse and interpreter selection remain unchanged. Disabling the setting must not introduce a new per-run directory reset.
- **Trace:**

  > The reporter confirmed the failure on Python Environments 1.38.0 and supplied both terminal output and execution logs at https://github.com/microsoft/vscode-python-environments/issues/1500#issuecomment-5946934567. In the checkout, TerminalManagerImpl.getDedicatedTerminal and getProjectTerminal return cached terminals before directory initialization, and runInTerminal sends only the Python invocation. PythonEnvironmentApiImpl in src/features/pythonApi.ts connects those operations; live main retains the relevant behavior despite later API-file refactoring. The core Python CodeExecutionManager.executeUsingExtension computes cwd from executeInFileDir and forwards it through src/client/envExt/api.internal.ts, whereas its legacy TerminalCodeExecutionProvider changes directory before every file execution. The public PythonTerminalExecutionOptions contract explicitly makes cwd creation-only, so restoring command behavior must not silently reinterpret cwd for all execution API consumers. The unresolved boundary is how per-run file execution intent reaches the shared execution path without affecting unrelated consumers; their compatibility has not been fully traced. Treat the reporter's separate terminal-focus observation as secondary and do not claim it is fixed by directory handling.

## Evidence

- **Reporter confirmed reproduction:** https://github.com/microsoft/vscode-python-environments/issues/1500#issuecomment-5946934567 confirms executeInFileDir is enabled and reproduces with Python 2026.6.0 and Python Environments 1.38.0. After cd folder, Run Python File in Terminal sends the same absolute script path without restoring the directory; echo $PWD confirms execution remains in development/folder.
- **Execution logs establish the boundary:** The October response includes Python Environments logs showing runInTerminal: sendText on the first run and runInTerminal: executeCommand on the second. Neither command includes a directory change, matching the terminal transcript rather than an interpreter-discovery or conda-activation failure.
- **Terminal reuse bypasses directory initialization:** In the checkout, src/features/terminal/terminalManager.ts:321-367, TerminalManagerImpl.getDedicatedTerminal returns a cached terminal at lines 329-333 before reading executeInFileDir. The setting determines cwd only for terminal creation at lines 347 and 357. getProjectTerminal similarly returns cached terminals without updating their directory. src/features/terminal/runInTerminal.ts executes Python through either shell integration or sendText without a directory change.
- **Core command loses legacy per-run behavior:** https://github.com/microsoft/vscode-python/blob/main/src/client/terminals/codeExecution/terminalCodeExecution.ts calls setCwdForFileExecution before each legacy executeFile invocation, sending cd when executeInFileDir is enabled. The extension-backed path in https://github.com/microsoft/vscode-python/blob/main/src/client/terminals/codeExecution/codeExecutionManager.ts instead passes cwd through https://github.com/microsoft/vscode-python/blob/main/src/client/envExt/api.internal.ts to the environment execution API.
- **Public contract constrains the solution:** src/api.ts:1240-1244 explicitly documents PythonTerminalExecutionOptions.cwd as used only to create the terminal. src/features/pythonApi.ts:357-377 passes that directory to terminal acquisition and then calls runInTerminal. Unconditionally enforcing options.cwd on every public API invocation would change the existing contract, not merely repair the Run Python File command.

Read-only inspection of the live main terminalManager.ts and runInTerminal.ts confirms the same cached-terminal and no-directory-reset behavior.
