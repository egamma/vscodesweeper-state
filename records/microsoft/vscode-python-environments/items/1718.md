# Issue #1718 — Cannot select venv environment

[https://github.com/microsoft/vscode-python-environments/issues/1718](https://github.com/microsoft/vscode-python-environments/issues/1718)

## Summary

The trace identifies a concrete PET interpreter-probe failure rather than the automatic-selection behavior tracked in https://github.com/microsoft/vscode-python-environments/issues/1468. PET returns the selected venv without version metadata, after which this extension cannot construct a valid environment, so the report should remain open with the upstream ownership recorded.

## Change summary

Selecting a Windows venv outside the workspace fails because its interpreter cannot be resolved and the extension falls back to global Python.

## Best solution

Fix the PET interpreter probe so this Windows venv returns its version and other required metadata, then confirm that manual selection succeeds through this extension's existing resolver path. The likely owning component is microsoft/python-environment-tools; no open canonical issue for this failure was identified.
