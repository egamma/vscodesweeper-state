# Issue #41 — Show create `venv` when users attempt to install packages to global

[https://github.com/microsoft/vscode-python-environments/issues/41](https://github.com/microsoft/vscode-python-environments/issues/41)

## Summary

This accepted, team-authored feature request still represents a gap on current main: package installation proceeds directly against the selected global environment without offering to create a venv. The existing `needs PR` label requires keeping it open for implementation.

## Change summary

Offer to create and use a virtual environment when a user attempts to install packages into a global Python environment.

## Best solution

Add a guard to the package-management command flow that detects a global environment and offers the existing venv creation workflow before installing, while retaining an explicit path for users who intend to modify the global environment.

- **Reason:** Steering package installation toward an isolated environment supports safe environment lifecycle and package-management workflows without reimplementing manager behavior.
- **Evidence:** The durable themes explicitly include environment lifecycle and package management, while the guardrails emphasize correctness of environment selection and extra care around operations that mutate package sets.
