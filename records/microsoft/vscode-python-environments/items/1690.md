# Issue #1690 — Breaks python stack, delays venv activation, forgots settings, installs automatically even after being uninstalled.

[https://github.com/microsoft/vscode-python-environments/issues/1690](https://github.com/microsoft/vscode-python-environments/issues/1690)

## Summary

Keep open for human triage: current main can wait up to five seconds before sending
an activation command into an interactive terminal, matching the reported delay and creating a risk
that it is combined with text the user has already entered. The environment-selection,
tool-resolution, and automatic-installation claims still need trace logs and investigation across
the core Python-extension rollout boundary.

## Change summary

Installing or enabling the extension disrupts Poetry environment selection and
environment-provided tools, while delayed terminal activation can append and submit an activation
command after the user starts typing.

## Best solution

Make command-mode activation unable to submit text after the user has begun
interacting with the terminal, while preserving `shellStartup` and `off` as safe alternatives.
Separately trace why Poetry project selections and environment-based tool resolution change during
rollout; a maintainer should coordinate or transfer the automatic-installation portion to
microsoft/vscode-python if that behavior originates there.

## Evidence

- **source-reproducible delay:** `src/features/terminal/terminalManager.ts` waits for
`waitForShellIntegration(terminal)` before activation; `src/features/terminal/utils.ts` permits a
default wait of up to 5000 ms when shell integration is enabled.
- **interactive command injection path:** After that wait, `TerminalActivationImpl.activateLegacy()` in
`src/features/terminal/terminalActivationState.ts` calls `terminal.sendText(activationCommands)`,
which submits the activation command into the same interactive buffer where the user may already be
typing.

macOS confirmation; it was closed after maintainers recommended
`python-envs.terminal.autoActivationType: "shellStartup"`, not by a cited fixing commit.
- **available mitigation:** `package.json` and `package.nls.json` define
`python-envs.terminal.autoActivationType: "off"` to disable automatic activation;
`src/extension.ts` also disables this extension's behavior when `python.useEnvironmentsExtension` is
