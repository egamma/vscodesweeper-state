# Issue #241 — Consider activating the environment without environment variables

[https://github.com/microsoft/vscode-python-environments/issues/241](https://github.com/microsoft/vscode-python-environments/issues/241)

## Summary

A real gap remains: shell-startup activation still transports shell-specific activation commands through environment variables. The related cleanup removed those variables after activation but did not implement activation without them.

## Change summary

Replace environment-variable-based shell-startup activation with an extension-owned script sourced from shell profiles.

## Best solution

Centralize activation logic in extension-owned, updateable shell helpers referenced by concise profile entries, while preserving the VS Code-only and subshell guards. This should replace the per-shell activation-command environment variables rather than merely cleaning them up afterward.

## Vision fit

- **Fit:** aligned
- **Reason:** Reducing activation-state pollution and centralizing shell logic advances the project's durable terminal-activation theme and current focus on cross-shell activation correctness.
- **Evidence:** The vision identifies terminal activation across bash, cmd, fish, pwsh, and WSL as a durable theme and activation correctness across shells as a current priority.

## Evidence

- **current implementation:** src/features/terminal/shellStartupActivationVariablesManager.ts still populates VS Code GlobalEnvironmentVariableCollection entries for every shell provider when shellStartup mode is enabled.
- **shell providers:** src/features/terminal/shells/bash/bashEnvs.ts and src/features/terminal/shells/pwsh/pwshEnvs.ts still store complete activation commands in shell-specific environment variables.
- **startup scripts:** src/features/terminal/shells/bash/bashStartup.ts and src/features/terminal/shells/pwsh/pwshStartup.ts still read and execute those environment variables, so the requested environment-variable-free design is not present on main.
- **existing capability:** package.json exposes python-envs.terminal.autoActivationType=shellStartup, but that mode currently uses the environment-variable transport described above and therefore does not cover the central request.
- **related fix scope:** https://github.com/microsoft/vscode/pull/292381 fixed https://github.com/microsoft/vscode-python-environments/issues/240 by clearing activation variables after shell integration consumes them; it did not eliminate their use.
