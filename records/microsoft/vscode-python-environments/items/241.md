# Issue #241 — Consider activating the environment without environment variables

[https://github.com/microsoft/vscode-python-environments/issues/241](https://github.com/microsoft/vscode-python-environments/issues/241)

## Summary

The central request remains unimplemented: shell-startup activation on current main still transports shell-specific activation commands through environment variables. The related pollution issue reduced their lifetime but did not replace this architecture.

## Change summary

Replace environment-variable-based shell-startup activation with a concise profile entry that sources an extension-owned, updateable activation script.

## Best solution

Refactor the shell-startup path to use versioned extension-owned helpers while preserving VS Code-only guards, workspace-specific environment selection, and safe profile setup and cleanup. Coordinate this architectural work with the reliability and default-rollout tracking in https://github.com/microsoft/vscode-python-environments/issues/962.
