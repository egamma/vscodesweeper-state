# Issue #241 — Consider activating the environment without environment variables

[https://github.com/microsoft/vscode-python-environments/issues/241](https://github.com/microsoft/vscode-python-environments/issues/241)

## Summary

A distinct design gap remains: shell-startup activation on current main still transports per-shell activation commands through environment variables. The related pollution fix removes variables after use, while the rollout tracker does not necessarily deliver this request's extension-managed script mechanism.

## Change summary

Replace environment-variable-based shell-startup activation with concise profile code that sources an extension-managed, updateable script.

## Best solution

Design a cross-platform shell-startup mechanism that loads extension-managed activation logic without carrying activation commands in terminal environment variables, while preserving workspace-specific selection, the VS Code-only guard, and double-activation prevention. Coordinate it with the broader rollout tracked at https://github.com/microsoft/vscode-python-environments/issues/962 without losing this concrete requirement.

## Vision fit

- **Fit:** aligned
- **Reason:** Reducing environment pollution while making shell-startup activation easier to evolve supports the project's terminal-activation and rollout-stability direction.
- **Evidence:** Terminal activation is a durable theme, and the August 2026 priorities emphasize activation correctness across shells and rollout quality; the family value also states that "Performance and stability trumps functionality."

## Evidence

- **current implementation:** src/features/terminal/shellStartupActivationVariablesManager.ts still populates a GlobalEnvironmentVariableCollection through each shell provider's updateEnvVariables method when shellStartup mode is enabled.
- **shell scripts:** Current startup scripts read per-shell command variables such as VSCODE_PYTHON_BASH_ACTIVATE and VSCODE_PYTHON_PWSH_ACTIVATE, then evaluate their contents; see src/features/terminal/shells/bash/bashStartup.ts and src/features/terminal/shells/pwsh/pwshStartup.ts.
- **existing capability:** package.json exposes python-envs.terminal.autoActivationType=shellStartup, but there is no setting or command that provides shell-startup activation without the environment-variable transport.
- **partial related fix:** https://github.com/microsoft/vscode/pull/292381 closed https://github.com/microsoft/vscode-python-environments/issues/240 by cleaning up unused activation variables in VS Code shell integration; it does not replace this extension's environment-variable-based activation mechanism.
- **related rollout:** https://github.com/microsoft/vscode-python-environments/issues/962 is an open broad rollout/refactoring tracker for making shell startup the default, but its stated scope does not require eliminating activation environment variables, so it is related rather than a verified canonical duplicate.
