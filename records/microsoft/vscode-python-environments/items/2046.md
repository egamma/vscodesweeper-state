# Issue #2046 — getEnvironment() switches to a newly created venv without firing onDidChangeEnvironment

[https://github.com/microsoft/vscode-python-environments/issues/2046](https://github.com/microsoft/vscode-python-environments/issues/2046)

## Summary

The automatic discovery path still changes the effective project interpreter without publishing a selection-change event. Route this to the API and environment areas; the report provides sufficient reproduction details.

## Change summary

Discovering a newly created local venv changes getEnvironment(folderUri) while event-driven consumers retain the global interpreter.

## Best solution

Ensure automatically discovered project-selection transitions publish the corresponding old/new environment event so consumers remain synchronized without restarting. Preserve read-only getEnvironment semantics and explicit user selections.
