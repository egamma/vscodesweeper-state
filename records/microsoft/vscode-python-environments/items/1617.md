# Issue #1617 — No way to configure corporate pip index URL for environment creation / package install UI on Windows

[https://github.com/microsoft/vscode-python-environments/issues/1617](https://github.com/microsoft/vscode-python-environments/issues/1617)

## Summary

A real package-management configuration gap remains on current main: the extension exposes no setting for private package indexes and does not add configurable arguments to pip or uv commands. Route this to the package area for a manager-aware design rather than closing it.

## Change summary

Allow environment creation and package-install UI operations to use a corporate Python package index instead of the public default.

## Best solution

Add a manager-aware configuration path for private indexes that applies consistently to package discovery, environment-creation dependencies, and install operations while preserving each tool's native configuration behavior. Pip and uv use different configuration conventions, so the implementation should avoid assuming one shared set of raw CLI flags and should document the supported native configuration and environment-variable alternatives.

## Evidence

- **settings surface:** The contributes.configuration section of package.json contains package-manager selection and python-envs.alwaysUseUv, but no index URL, extra arguments, or equivalent package-source setting.
- **install commands:** src/managers/builtin/commands/install.ts and src/managers/builtin/utils.ts construct fixed `python -m pip install` and `uv pip install --python ...` argument lists; neither appends user-configurable package-index arguments.
- **unused configuration hook:** src/managers/base/commands/install.ts declares the `installCommandArgs` configuration section, but the concrete pip and uv command builders do not read this.config, and package.json does not contribute that setting.
- **process behavior:** src/managers/builtin/helpers.ts spawns pip and uv without replacing the child environment, so inherited environment variables remain available; however, the extension provides no documented or workspace-scoped index configuration and uv does not share pip's configuration model.
- **canonical search:** Repository searches for index-url, extra-index-url, pip.ini, and private PyPI found no open issue that concretely owns this same request.
