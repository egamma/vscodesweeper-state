# Issue #1569 — Ignoring change watch events misses fast re-creation events and leaves environment state stale

[https://github.com/microsoft/vscode-python-environments/issues/1569](https://github.com/microsoft/vscode-python-environments/issues/1569)

## Summary

Still present on current main: activation and package watchers discard change events, so a delete/create sequence normalized to a change cannot trigger their debounced refreshes. Route this actionable correctness bug to the activation and package areas.

## Change summary

Rapid or atomic replacement of watched activation and package metadata files can leave environment state stale when the filesystem reports only a change event.

## Best solution

Handle change events through the existing debounced refresh paths in `src/managers/builtin/main.ts` and `src/managers/common/packageWatcher.ts`, with unit coverage showing that a changed activation script refreshes environments and changed package metadata refreshes packages.
