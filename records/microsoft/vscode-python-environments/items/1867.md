# Issue #1867 — Closing terminal during activation breaks subsequent execution requests

[https://github.com/microsoft/vscode-python-environments/issues/1867](https://github.com/microsoft/vscode-python-environments/issues/1867)

## Summary

Keep open: the supplied main checkout still permits a terminal closed during activation to enter the reusable cache, breaking subsequent same-key execution requests. This team-authored report has a concrete reproduction and identifies a distinct lifecycle defect.

## Change summary

Closing an execution terminal during activation leaves a disposed terminal cached, preventing subsequent requests from creating a replacement.

## Best solution

Ensure project and dedicated execution-terminal caches contain only live terminals after asynchronous initialization, while preserving early activation visibility and normal sequential reuse. Verify cancellation during initialization, successful reuse, and replacement after a normally initialized terminal closes.

- **Current source lifecycle:** In src/features/terminal/terminalManager.ts, create() shows the terminal before awaiting autoActivateOnTerminalOpen(). Both getProjectTerminal() and getDedicatedTerminal() await create(), then populate their maps and register their close listeners. A close event during activation therefore precedes those listeners; neither cache insertion nor later cache lookup checks whether the terminal has exited.
- **Failure propagation and public API:** src/features/terminal/terminalActivationState.ts: TerminalActivationImpl.activate() catches activation failures and logs them without rethrowing, allowing creation to return a disposed terminal. src/features/pythonApi.ts: runInTerminal() obtains the project-cached terminal before calling src/features/terminal/runInTerminal.ts, whose show()/execution operations then encounter the disposed object.

It concerns concurrent creation and an older terminal's close callback evicting a newer live cache entry, including with activation disabled. That does not own this report's missed close event during activation or establish that resolving it necessarily prevents caching an already-disposed terminal.
