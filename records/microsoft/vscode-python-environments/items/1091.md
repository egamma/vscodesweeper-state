# Issue #1091 — Consider removing shell integration setting check

[https://github.com/microsoft/vscode-python-environments/issues/1091](https://github.com/microsoft/vscode-python-environments/issues/1091)

## Summary

The debt remains present on current main: profile setup still treats the configured shell-integration setting as evidence that injection succeeded. This team-authored follow-up should remain open until the runtime detection or caching strategy is decided and implemented.

## Change summary

Stop relying on the shell-integration enabled setting as a proxy for successful shell-integration injection.

## Best solution

Update `TerminalManagerImpl.handleSetupCheck` to base its decision on observed shell-integration availability or a reliable cached injection result, while avoiding unnecessary terminal-startup waits. Retain profile-based activation for WSL and shells that do not support VS Code shell integration.
