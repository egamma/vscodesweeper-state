# Issue #1467 — [Python Environments] automatic activation of a wrong venv on spawning new terminal

[https://github.com/microsoft/vscode-python-environments/issues/1467](https://github.com/microsoft/vscode-python-environments/issues/1467)

## Summary

Multiple users have confirmed terminals activating an environment from another project, and current main does not protect Poetry environments from a stale or incorrect project selection. This remains a correctness bug spanning environment selection and terminal activation.

## Change summary

Opening a terminal can automatically activate a Poetry or venv environment belonging to a different project, while the configured default interpreter is ignored.

## Best solution

Ensure Poetry project mappings cannot retain or return an environment belonging to another workspace project, then have terminal activation fail closed when the selected environment is inconsistent with the terminal workspace or cwd. The interaction between `python-envs.defaultEnvManager`, `python.defaultInterpreterPath`, and persisted Poetry selections should also be made explicit and deterministic.

## Evidence

- **independent confirmations:** The issue has a second report of an unrelated remembered `.venv` being activated; https://github.com/microsoft/vscode-python-environments/issues/1468#issuecomment-4443995065 independently shows PowerShell activating a venv from a different Windows project.
- **activation path:** On current main, `src/features/terminal/terminalManager.ts` handles every newly opened terminal by resolving an environment through `getEnvironmentForTerminal()` and immediately passing it to `autoActivateOnTerminalOpen()`.
- **Poetry mapping:** `src/managers/poetry/poetryManager.ts` resolves a scoped environment from its persistent `fsPathToEnv` project mapping and otherwise falls back to `globalEnv`; terminal activation has no independent check that a Poetry environment belongs to the current project.
- **setting precedence:** `src/features/interpreterSelection.ts` gives an explicitly configured `python-envs.defaultEnvManager` priority over `python.defaultInterpreterPath`. With both settings from this report present, the Poetry manager is selected before the interpreter path is evaluated.
- **related fix does not cover Poetry:** Commit 6138122018b4a872c80766ba7b026bea2cf33a27 from https://github.com/microsoft/vscode-python-environments/pull/1708 fixed sibling local-venv selection by terminal cwd, but its documented compatibility boundary deliberately preserves external environments such as Poetry.
