[https://github.com/microsoft/vscode-python-environments/issues/136](https://github.com/microsoft/vscode-python-environments/issues/136)

## Summary

Keep open for maintainer-led design: per-extension package-install approval remains a distinct gap on main. This concerns the user trust boundary, so the security-sensitive keep-open rule applies; the accepted needs-spike work should not be retired for inactivity.

## Change summary

Provide explicit, revocable per-extension consent for package installation, including one-time approval and persistent preferences.

## Best solution

Complete the package API consent design using the latest discussion's per-extension secret-storage preferences, without wildcard or publisher-based preapproval. Resolve permission-management and scope semantics before implementing the approval flow, keeping direct terminal commands outside its claimed protection.
