# Issue #1522 — [Python Environments] Activation of any other environments fail when opening file without workspace

[https://github.com/microsoft/vscode-python-environments/issues/1522](https://github.com/microsoft/vscode-python-environments/issues/1522)

## Summary

Still present on main: without a workspace, selecting an environment from a manager other than the configured default updates the global selection cache, but subsequent reads route back through the default manager. Routing this confirmed selection defect to the environment and activation areas.

## Change summary

Selecting a different Python environment for a standalone file does not change the active environment unless its manager is configured as the default.

## Best solution

Make global environment resolution honor the explicitly selected environment's manager without persisting a user-level default manager. The global selection should remain usable for standalone files even when it differs from `python-envs.defaultEnvManager`.

## Evidence

- **source trace:** `src/features/envCommands.ts:447-466` selects a standalone-file environment through `setEnvironments('global', selected)`, while `src/features/envManagers.ts:434-455` records the selected environment but intentionally does not persist a different global manager.

- **independent confirmation:** A second reporter reproduced the issue, and both reports found that explicitly setting `python-envs.defaultEnvManager` made selection work, matching the source-level manager-routing defect.
