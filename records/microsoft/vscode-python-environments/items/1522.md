# Issue #1522 — [Python Environments] Activation of any other environments fail when opening file without workspace

[https://github.com/microsoft/vscode-python-environments/issues/1522](https://github.com/microsoft/vscode-python-environments/issues/1522)

## Summary

The no-workspace manager-switch defect remains traceable on current main: selecting a conda environment updates the global cache, but subsequent global reads prefer the configured/default venv manager and can return the original interpreter. Routing this confirmed environment-selection bug to the environment and activation areas.

## Change summary

Selecting a different Python environment in a window containing only a standalone file does not reliably change the active interpreter.

## Best solution

Make an explicit global environment selection determine the manager used by subsequent no-workspace reads, without restoring the former behavior of writing manager defaults into User settings. Add coverage for switching globally from the default venv manager to a conda environment and verifying that later reads continue through conda.
