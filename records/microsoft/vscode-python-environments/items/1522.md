# Issue #1522 — [Python Environments] Activation of any other environments fail when opening file without workspace

[https://github.com/microsoft/vscode-python-environments/issues/1522](https://github.com/microsoft/vscode-python-environments/issues/1522)

## Summary

Two users confirmed that global interpreter selection can remain stuck when opening a file without a workspace, while explicitly choosing Conda as the default manager avoids the failure. The report should remain open and be routed to Conda environment selection.

## Change summary

Selecting a different interpreter for a standalone Python file does not replace the automatically selected global interpreter.

## Best solution

Ensure the global-scope picker can switch from the automatically chosen system interpreter to an environment owned by another manager without requiring `python-envs.defaultEnvManager`. The area owner should compare current-release trace logs against the global manager routing and Conda selection state.
