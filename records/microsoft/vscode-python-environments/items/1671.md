# Issue #1671 — VS Code discovers Conda environments but Python: Select Interpreter does not display them

[https://github.com/microsoft/vscode-python-environments/issues/1671](https://github.com/microsoft/vscode-python-environments/issues/1671)

## Summary

The report and an independent confirmation show a real integration failure: Conda discovery succeeds, but the core Python interpreter picker omits the results. Routing to the Conda and API areas to determine whether this repository's event/API bridge or the core extension's picker consumer drops the environments.

## Change summary

Discovered Conda environments should appear in Python: Select Interpreter without requiring manual path selection.

## Best solution

Trace the integration from `CondaEnvManager.getEnvironments('all')` through the exported API and change event into the core Python extension's interpreter picker. Fix the API/event bridge here if it loses the discovered collection; otherwise a maintainer can transfer the issue to microsoft/vscode-python.

## Evidence

- **confirmed behavior:** The reporter's Python Environments logs show eight Conda environments discovered successfully while Python: Select Interpreter omits them; another user independently confirmed the same issue.
- **source path:** `src/managers/conda/condaEnvManager.ts` stores discovered environments in `collection`, emits additions during initialization, and returns that collection for `getEnvironments('all')`.
- **API boundary:** `src/features/pythonApi.ts` implements `getEnvironments('all')` by awaiting all managers and flattening their results, so the remaining failure is at the exported API/event integration seam or in the core Python extension's interpreter-picker consumer.
- **canonical search:** Open issue https://github.com/microsoft/vscode-python-environments/issues/1454 audits other Conda selection defects, but its findings concern selection persistence, executable paths, and activation rather than discovered environments missing from the picker.
