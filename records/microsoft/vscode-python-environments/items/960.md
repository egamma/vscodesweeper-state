[https://github.com/microsoft/vscode-python-environments/issues/960](https://github.com/microsoft/vscode-python-environments/issues/960)

## Summary

Keep open: the canonical search-path resolver remains internal, so third-party managers still cannot obtain its results through the public API. This is accepted work labeled needs PR, and an open consumer PR explicitly demonstrates the duplication the request would eliminate.

## Change summary

Expose the native finder's canonical configured search paths through a supported public surface for third-party environment managers.

## Best solution

Provide a documented public search-path resolution contract that stays behaviorally aligned with native discovery, including legacy settings, folder-specific precedence, relative paths, and glob handling. Coordinate with the Pixi integration so consumers can replace copied logic with the shared capability.
