# Issue #960 — Expose helper for resolving python-env search paths (getAllExtraSearchPaths)

[https://github.com/microsoft/vscode-python-environments/issues/960](https://github.com/microsoft/vscode-python-environments/issues/960)

## Summary

A real API gap remains on current main: the canonical resolver is still internal and third-party environment managers cannot access it through PythonEnvironmentApi. The accepted `needs PR` work should remain open in the API area.

## Change summary

Expose the extension's canonical resolution of global, workspace, multi-root, and legacy environment search paths to API consumers.

## Best solution

Add a documented search-path method to PythonEnvironmentApi and its published @vscode/python-environments declarations, implemented by delegating to the existing getAllExtraSearchPaths helper so built-in and contributed managers share identical behavior.

- **Fit:** aligned
- **Reason:** Sharing canonical configuration behavior with contributed managers directly supports the extension's API-first, manager-agnostic architecture.
- **Evidence:** docs/design.md describes the extension as the entry point for environment management and says its modularity should allow individual tools and libraries to implement manager methods.
