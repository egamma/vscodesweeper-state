# Issue #1510 — extension doesn't activate python venv in terminal windows.

[https://github.com/microsoft/vscode-python-environments/issues/1510](https://github.com/microsoft/vscode-python-environments/issues/1510)

## Summary

This remains an actionable terminal-activation regression: an independent reporter confirms that activation fails in 1.30.0 and works again after downgrading to 1.28.0. No verified duplicate or fixing commit was found, so it should be routed to the activation and terminal owners.

## Change summary

Opening a terminal does not activate the selected virtual environment when the Python Environments extension is enabled.

## Best solution

Reproduce the 1.30.0 regression with command-based venv activation on Windows and Remote SSH, then trace environment resolution and the shell-integration wait in `src/features/terminal/terminalManager.ts`; terminal creation should reliably activate the environment selected for the workspace without the startup delay reported here.

## Evidence

- **cross-platform impact:** The opening report observes the failure across multiple Windows installations and Remote SSH sessions to Linux hosts, indicating that it is not limited to one shell or host.
- **current activation path:** `src/features/terminal/terminalManager.ts` handles newly opened terminals through `autoActivateOnTerminalOpen`, resolves their environment with `getEnvironmentForTerminal`, waits for shell integration, and then calls `activate`; this is the central path the reported behavior implicates.
- **documented expectation:** `README.md` and `package.json` document `python-envs.terminal.autoActivationType` with a default of `command`, which is intended to execute the selected environment's activation command in the terminal.
- **canonical search:** The open https://github.com/microsoft/vscode-python-environments/issues/664 concerns a Windows conda-specific activation failure involving `conda init`; it does not establish the same root cause as this broader venv report and is not a verified duplicate canonical.
