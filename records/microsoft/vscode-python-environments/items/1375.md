# Issue #1375 — Automated terminal activation kills all running tasks in terminals

[https://github.com/microsoft/vscode-python-environments/issues/1375](https://github.com/microsoft/vscode-python-environments/issues/1375)

## Summary

Command-based activation intentionally remains the default because it works with any shell, while non-disruptive shell-startup activation is an explicit opt-in. The reporter confirmed that option resolves the disruption, and a maintainer subsequently closed the same Ctrl+C behavior as designed.

## Change summary

Make shell-startup activation the default so automatic environment detection cannot interrupt programs running in terminals.

## Best solution

Keep the configurable activation modes: users who must preserve running terminal processes should select `python-envs.terminal.autoActivationType: "shellStartup"`, or use `"off"` where shell-startup setup is unavailable. Command activation remains the compatibility fallback for shells that shell-startup activation does not support.

- **Reason:** Avoiding interruption of user workloads advances the project's emphasis on stable, correct terminal activation, although the supported-shell compatibility tradeoff explains why it is configurable rather than the default.
- **Evidence:** The vision states that "Performance and stability trumps functionality" and identifies terminal activation correctness across shells as a durable theme and current priority.
