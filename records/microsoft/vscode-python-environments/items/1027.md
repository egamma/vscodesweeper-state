# Issue #1027 — launching a local integrated terminal from wsl will look for linux location for venv

[https://github.com/microsoft/vscode-python-environments/issues/1027](https://github.com/microsoft/vscode-python-environments/issues/1027)

## Summary

Still present on current main: terminals opened locally from a WSL window are assigned the workspace's WSL environment and receive its Linux activation command without any local-versus-remote guard. The reporter reconfirmed the problem on a newer release, and a maintainer recognized it as an edge case needing a fix.

## Change summary

Opening a local PowerShell terminal from a WSL window attempts to activate the selected WSL virtual environment using its Linux path.

## Best solution

Before automatic activation, determine whether the terminal runs in the local or remote context and only select an environment whose execution context matches it. Route this through the WSL and PowerShell terminal areas while preserving normal activation for terminals created inside WSL.
