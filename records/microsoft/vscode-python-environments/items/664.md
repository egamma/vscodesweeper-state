# Issue #664 — The automatic activation mechanism has been damaged

[https://github.com/microsoft/vscode-python-environments/issues/664](https://github.com/microsoft/vscode-python-environments/issues/664)

## Summary

The reporter confirmed after the previous close that conda shell-startup activation still fails in PowerShell 7 without `conda init`: the expected activation variable is empty and `conda activate` consequently errors. The assigned Feb Bug Bash milestone and accepted-work `needs spike` label independently require this reopened issue to remain open.

## Change summary

Conda shell-startup activation in PowerShell 7 skips the required hook because `VSCODE_PYTHON_PWSH_ACTIVATE` is not injected into new terminals.

## Best solution

Trace why `ShellStartupActivationVariablesManagerImpl` does not place the selected environment's PowerShell activation command into the workspace-scoped environment-variable collection, then ensure new PowerShell terminals receive `VSCODE_PYTHON_PWSH_ACTIVATE` containing the conda hook followed by activation. Add coverage for a Windows PowerShell 7 conda environment without `conda init`, including the scoped collection and generated startup command.

- **maintainer diagnosis:** Maintainer comments identify the likely failure as skipping the command fallback because the extension incorrectly believes pwsh is initialized, and request the activation variable specifically to isolate that path.
- **current source path:** src/features/terminal/shellStartupActivationVariablesManager.ts populates workspace-scoped environment collections through each ShellEnvsProvider; src/features/terminal/shells/pwsh/pwshEnvs.ts should replace VSCODE_PYTHON_PWSH_ACTIVATE with the generated command, and pwshStartup.ts invokes that variable from the PowerShell profile.
- **conda hook behavior:** src/managers/conda/condaUtils.ts generates PowerShell activation as `& conda-hook.ps1` followed by `conda activate <environment>` when the hook is available, so an empty injected variable prevents the intended no-`conda init` path from running.
