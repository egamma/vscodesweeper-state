# Issue #664 — The automatic activation mechanism has been damaged

[https://github.com/microsoft/vscode-python-environments/issues/664](https://github.com/microsoft/vscode-python-environments/issues/664)

## Summary

Keep open: the reporter confirmed that conda shell-startup activation works in cmd and WSL but selects the wrong PowerShell profile and fails in pwsh. The assigned Feb Bug Bash milestone and accepted `needs spike` status independently prohibit closure.

## Change summary

Conda shell-startup activation on Windows fails to activate the selected environment in PowerShell 7 without requiring `conda init`.

## Best solution

Complete the scheduled spike by reproducing this with Windows, conda, and PowerShell 7, then ensure terminal-shell detection configures the profile belonging to the terminal's actual executable and runs the conda hook before activating the selected environment.

## Evidence

- **confirmed reproduction:** The reporter tested VS Code Insiders and Python Environments 1.6.0, reporting that cmd activated correctly while pwsh still failed; supplied logs showed the selected conda environment and generated PowerShell activation commands.
- **shell-specific evidence:** The extension configured the Windows PowerShell 5 profile rather than the requested PowerShell 7 profile; the reporter confirmed WSL/bash behaved correctly.
- **current implementation:** src/features/terminal/terminalManager.ts identifies each opened terminal's shell before selecting shell-startup behavior, while src/features/terminal/shells/pwsh/pwshStartup.ts maintains separate PowerShell and pwsh profile handling—the integration between those paths is the relevant spike area.
- **conda mechanism:** src/managers/conda/condaUtils.ts generates PowerShell activation using conda-hook.ps1 followed by `conda activate`, which is intended to work without requiring the user to run `conda init`.
