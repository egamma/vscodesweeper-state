# Issue #1468 — VS Code not selecting environment in .venv/ on open with Environments extension installed

[https://github.com/microsoft/vscode-python-environments/issues/1468](https://github.com/microsoft/vscode-python-environments/issues/1468)

## Summary

The root cause was confirmed and addressed on main: the extension unintentionally saved the system environment manager at User scope, causing workspace-local environments to be ignored. Keep this open because the linked draft PR https://github.com/microsoft/vscode-python-environments/pull/1612 would remove the migration for affected settings and must be resolved first.

## Change summary

A globally saved system-manager preference prevents automatic selection and activation of a workspace-local `.venv`.

## Best solution

Retain the prevention from https://github.com/microsoft/vscode-python-environments/pull/1489 and decide whether the one-time cleanup from https://github.com/microsoft/vscode-python-environments/pull/1527 should remain. Once https://github.com/microsoft/vscode-python-environments/pull/1612 is resolved, this can be closed as fixed if current and upgrading users are no longer left with the unintended User-scoped setting.

## Evidence

- **confirmed root cause:** The reporter found `python-envs.defaultEnvManager: ms-python.python:system` in User settings and confirmed that switching it to `ms-python.python:venv` restored automatic loading of `.venv`; a maintainer identified removing the system value as the fix.
- **prevention fix:** Commit https://github.com/microsoft/vscode-python-environments/commit/1eb7b677fea420125fece06462d7320dfcfb2774 explicitly references this issue and prevents environment and package manager choices from being written to User scope.
- **existing-user mitigation:** Commit https://github.com/microsoft/vscode-python-environments/commit/a4ca6282790a5d7fb1ffc7c0068c477a8e689ea1 adds an activation-time migration that removes the unintended User-scoped system manager; current `src/features/settings/settingHelpers.ts` documents that this value causes all workspaces to ignore local `.venv` environments.
- **open linked PR:** Draft PR https://github.com/microsoft/vscode-python-environments/pull/1612 remains open and proposes reverting the one-time migration while leaving its persistent-state marker behind; the issue must remain open while that implementation decision is pending.
- **related reports:** The discussion includes independent macOS and Windows symptoms involving missing or wrong workspace activation, supporting impact beyond one machine, although https://github.com/microsoft/vscode-python-environments/issues/1467 is not proven to share this exact root cause.
