# Issue #812 — allow usage of non-global uv executable

[https://github.com/microsoft/vscode-python-environments/issues/812](https://github.com/microsoft/vscode-python-environments/issues/812)

## Summary

A real capability gap remains on current main: uv detection and execution use the literal `uv` command from the extension host's PATH, with no workspace-local executable support. The request exceeded the community-feedback threshold and should remain open for the environment/package areas.

## Change summary

Allow the extension to discover and use a workspace-local uv executable instead of requiring uv on the global PATH.

## Best solution

Resolve a workspace-scoped uv executable, including pinned installations such as `.pyprojectx/main/uv.exe`, and use that resolved path consistently for availability checks and uv package/environment operations. A configurable executable path may be safer than unrestricted workspace searching.

- **Reason:** Supporting pinned workspace installations improves the extension's manager-agnostic orchestration of community tooling without reimplementing uv.
