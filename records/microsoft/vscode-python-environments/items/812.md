# Issue #812 — allow usage of non-global uv executable

[https://github.com/microsoft/vscode-python-environments/issues/812](https://github.com/microsoft/vscode-python-environments/issues/812)

## Summary

A real capability gap remains on current main: built-in package operations invoke `uv` by name and therefore cannot use a workspace-local executable that is absent from the extension host's PATH. The request exceeded the community-feedback threshold with 10 upvotes and should remain open, routed to package management.

## Change summary

Allow package operations to use a workspace-local uv executable, such as `.pyprojectx/main/uv.exe`, instead of requiring a globally discoverable `uv` command.

## Best solution

Add workspace-aware uv executable resolution in the built-in package-management path, with an explicit and predictable selection mechanism that respects workspace trust and uses the resolved executable consistently for detection and execution. Preserve PATH-based discovery as the default fallback.
