# Issue #470 — Offer to create folder/workspace in 'Add as Python Project' flow

[https://github.com/microsoft/vscode-python-environments/issues/470](https://github.com/microsoft/vscode-python-environments/issues/470)

## Summary

Keep open: the merged change offers an Open Folder escape hatch, but does not provide an integrated folder/workspace creation flow. The maintainer explicitly called it an MVP solution, and the needs PR label marks accepted work rather than an abandoned request.

## Change summary

Offer folder or workspace creation when adding a Python project without an open workspace.

## Best solution

Complete the empty-window project onboarding experience so users can establish a new folder/workspace and continue adding their Python project. Agree on the creation and continuation behavior first; retain the existing Open Folder option for users with an existing folder.

## Plan brief

- **Likely files:** `src/features/envCommands.ts`, `src/common/pickers/managers.ts`, `src/extension.ts`, `src/features/creators/newPackageProject.ts`, `src/features/creators/newScriptProject.ts`, `docs/managing-python-projects.md`
- **Validation:** In a fresh VS Code window with no workspace, invoke the Python Projects add action and complete the agreed new-folder/workspace flow; verify the folder opens and the intended project is registered. Repeat with an existing folder and cancellation, checking that existing-folder behavior is preserved and cancellation creates no files or project entries.
- **Behavior:**

  > Users starting the Add Python Project flow without an open workspace should be offered a way to establish a new folder/workspace rather than only being redirected to open an existing folder. The current Open Folder option remains useful and should remain available. Acceptance should cover successful creation and project registration, opening an existing folder, and cancellation without unintended filesystem or project changes. Whether project creation continues automatically after opening the new workspace is not yet settled.
- **Trace:**

  > src/features/envCommands.ts:addPythonProjectCommand checks wm.getProjects().length and currently offers Open Folder, executes vscode.openFolder, and returns. This is the partial solution merged in https://github.com/microsoft/vscode-python-environments/pull/475, whose description explicitly leaves a comprehensive flow unresolved. package.json and src/extension.ts expose the separate template-creation command, but NewPackageProject.create and NewScriptProject.create require a provided root or an existing workspace folder. ExistingProjects.create handles selecting existing resources and offers Add to Workspace for outside resources; that is not new-folder creation. Preserve existing-resource registration, existing workspace template behavior, and manager-specific environment creation. https://github.com/microsoft/vscode-python-environments/issues/390 provides broader project context, not a duplicate canonical.
- **Open decisions:**
  - Should the empty-window action create and open a single folder, or also offer creation of a multi-root workspace?
  - After the new folder/workspace opens, should the original Add Python Project flow resume automatically, or should opening it and registering its default project complete the action?
