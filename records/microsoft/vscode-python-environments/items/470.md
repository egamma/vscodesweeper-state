# Issue #470 — Offer to create folder/workspace in 'Add as Python Project' flow

[https://github.com/microsoft/vscode-python-environments/issues/470](https://github.com/microsoft/vscode-python-environments/issues/470)

## Summary

The Open Folder button provides the acknowledged MVP workaround, not the more comprehensive folder/workspace creation flow. Keep this accepted request open and route it to environment management.

## Change summary

Offer folder or workspace setup when adding a Python project without an open workspace.

## Best solution

Provide a coherent folder/workspace setup path from Add as Python Project, with an explicit decision about whether project creation resumes after opening the destination. Preserve existing project-addition behavior.

## Plan brief

- **Likely files:** `src/features/envCommands.ts`, `src/extension.ts`, `src/features/creators/existingProjects.ts`
- **Validation:** In an empty VS Code window, invoke python-envs.addPythonProject and exercise the agreed folder/workspace setup flow. Verify the chosen destination opens, project addition completes according to the agreed continuation behavior, cancellation adds no project, and adding projects in an existing workspace remains unchanged.
- **Behavior:**

  > Users starting Add as Python Project without an open workspace should have a coherent way to establish the destination rather than stop at a prerequisite error. The existing Open Folder action is an acknowledged partial solution. Acceptance should cover successful setup, cancellation, and unchanged behavior in existing single-folder and multi-root workspaces.
- **Trace:**

  > src/extension.ts registers python-envs.addPythonProject and delegates to addPythonProjectCommand in src/features/envCommands.ts. Its no-project branch offers Open Folder, calls vscode.openFolder, and returns; it does not retain or resume the project-addition flow. ExistingProjects.create in src/features/creators/existingProjects.ts can add selected external resources to a workspace, but that capability is downstream of the initial guard. https://github.com/microsoft/vscode-python-environments/pull/475 and the issue discussion explicitly characterize the button as an MVP improvement. The remaining uncertainty is the intended user journey across opening a workspace, not whether the button exists. Existing project selection, creator behavior, and environment management should remain unchanged outside that journey.
- **Open decisions:**
  - After folder/workspace setup opens the destination, should Python project addition resume automatically, or should the user explicitly invoke Add as Python Project again?
