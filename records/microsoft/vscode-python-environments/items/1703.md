## Summary

The report directly demonstrates duplicate output from PET itself, making microsoft/python-environment-tools the root-cause owner. Keep this open for maintainer routing; no open canonical currently tracks the recurrence.

## Change summary

PET should deduplicate Windows Conda environments whose paths differ only by filesystem casing.

## Best solution

Fix and regression-test Windows path canonicalization in PET's Conda locator, specifically a lowercase well-known probe resolving to an existing mixed-case Miniconda installation. This extension may additionally consider defensive deduplication, but PET should emit one canonical environment.

## Evidence

- **direct PET reproduction:** The supplied `pet.exe find --list` output reports four Conda environments twice, once under `Miniconda3` and again under `miniconda3`, while the reporter verified only the mixed-case directory exists.
- **PET source:** Current `crates/pet-conda/src/environment_locations.rs` in microsoft/python-environment-tools adds lowercase `miniconda3` well-known paths and relies on `norm_case`, sorting, and `dedup`; the observed output shows that normalization path is not preventing duplicates in the shipped binary.
- **extension propagation:** `src/managers/common/nativePythonFinder.ts` appends each PET environment notification to `nativeInfo`, and `src/managers/conda/condaUtils.ts:891-918` converts every Conda result into the returned collection without path deduplication.
- **prior PET regression context:** https://github.com/microsoft/python-environment-tools/issues/14 documented the same case-only duplication and was closed by https://github.com/microsoft/python-environment-tools/pull/15; because that canonical is closed and the behavior has recurred, it is precedent rather than a valid duplicate target.
