# Issue #412 — feature request: supports `requires-python` in "create environment.." flow

[https://github.com/microsoft/vscode-python-environments/issues/412](https://github.com/microsoft/vscode-python-environments/issues/412)

## Summary

This accepted, team-authored feature remains a distinct gap on current main: the creation flows ask for a Python version without consulting the workspace pyproject.toml. The existing `needs PR` label marks it as accepted work, so it should remain open.

## Change summary

Use a workspace pyproject.toml `project.requires-python` constraint to guide Python selection during environment creation.

## Best solution

Parse the owning project's `project.requires-python` before Python selection, then filter or clearly annotate incompatible choices in the venv and conda creation flows while preserving the existing behavior when no valid constraint is present.

- **Reason:** Using project metadata to choose a compatible interpreter strengthens the core environment-creation and Python Projects workflows.
- **Evidence:** The durable environment-lifecycle and Python Projects themes cover creating the right environment for a project, while the guardrails prioritize correctness of environment selection.
