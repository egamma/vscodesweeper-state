# Issue #476 — Environment Manager viewlet - no visual  indicatior on the currently selected environment.

[https://github.com/microsoft/vscode-python-environments/issues/476](https://github.com/microsoft/vscode-python-environments/issues/476)

## Summary

A real UX gap remains: the view exposes the same check-shaped action on unselected environments and only briefly changes it after selection, so there is no persistent at-a-glance indicator. This team-authored request should remain open and be routed to the environment area for the proposed UX discussion.

## Change summary

Provide a persistent, visually distinct indication of the currently selected environment in the Environment Managers view.

## Best solution

Define the selection treatment with UX and update the Environment Managers tree item so selected state is persistently visible while retaining the distinction between global and project-scoped selection.

## Vision fit

- **Fit:** aligned
- **Reason:** Clear selected-environment state supports the extension's core environment-selection experience and its rollout-quality focus.
- **Evidence:** The durable themes identify environment switching and Python Projects as core product surfaces, while the guardrails state that correctness of activation and selection outranks additional features.

## Evidence

- **current view behavior:** package.json registers python-envs.setEnv with a $(check) icon for unselected environment rows and python-envs.setEnvSelected with $(pass-filled) only while the temporary selected context is present.
- **temporary feedback:** src/extension.ts sets the selected temporary state after python-envs.setEnv, while src/features/views/temporaryStateManager.ts clears temporary states after 2 seconds by default.
- **persistent state is not visually exposed:** src/features/views/envManagersView.ts tracks the effective selected environment, but src/features/views/treeViewItems.ts uses that state only to augment the tooltip; it does not add a persistent icon or description.
- **maintainer direction:** A MEMBER comment says the selection communication should be discussed in a UX sync, confirming that the desired treatment remains an open design decision.
