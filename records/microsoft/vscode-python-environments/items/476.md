# Issue #476 — Environment Manager viewlet - no visual  indicatior on the currently selected environment.

[https://github.com/microsoft/vscode-python-environments/issues/476](https://github.com/microsoft/vscode-python-environments/issues/476)

## Summary

The Environment Managers view still lacks a persistent, clear selection indicator; its current checkmark feedback is temporary. Route this to the environment area for the UX discussion already requested by a maintainer.

## Change summary

Clearly distinguish selected environments from the action used to select an environment in the Environment Managers view.

## Best solution

Agree on how the view communicates project and non-workspace selections, then provide a persistent indicator distinct from selection-action feedback. Existing tooltips and temporary feedback only partially address the request.

## Vision fit

- **Fit:** aligned
- **Reason:** Clear selection feedback supports the extension's Python Projects experience and its promise of selecting the right environment.
- **Evidence:** The durable themes identify Python Projects, including the per-file/per-folder/per-project environment model, as core product surface.

Repeat with different environments selected for two projects and for non-workspace files; add view-level tests asserting the agreed presentation.
- **Behavior:**

  > Users should be able to identify selected environments in the Environment Managers view without relying on a transient action icon or hovering for a tooltip. Selection feedback must distinguish the current selection from an available select action. The agreed indicator should remain accurate after switching environments and reloading, including when project and non-workspace selections differ.
- **Trace:**

  > src/extension.ts registers python-envs.setEnv and sets temporary selected state after invoking setEnvironmentCommand; python-envs.setEnvSelected is a no-op feedback command. package.json swaps their inline icons using that state, which TemporaryStateManager clears after 2000 ms. EnvManagerView.environmentChanged separately maintains an environment-ID-to-scope map, while PythonEnvTreeItem uses the supplied scope only for tooltip text and leaves the visible row presentation unchanged. The request therefore remains only partially covered, rather than demonstrably implemented. The uncertainty is which selections this manager-wide view should communicate when several project scopes coexist. Preserve environment-selection behavior and package-management actions; this request concerns presentation, not choosing a different interpreter. The maintainer requested UX discussion at https://github.com/microsoft/vscode-python-environments/issues/476#issuecomment-2963823890.
- **Open decisions:**
  - Should the manager-wide view indicate the active file's selected environment, every environment selected by any project, or separately identified project and non-workspace selections?
