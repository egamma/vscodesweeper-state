# Issue #2054 — Refreshing packages conflict with local script to remove venv

[https://github.com/microsoft/vscode-python-environments/issues/2054](https://github.com/microsoft/vscode-python-environments/issues/2054)

## Summary

Keep open: current main checks whether the executable exists and can pause watchers during extension-managed runtime updates, but neither establishes safety during external venv rebuilds. The reported commands, errors, environment details, and watcher-disable comparison suffice to retest this timing-dependent failure.

## Change summary

Automatic package refresh interferes with externally scripted venv deletion and creation, while the working watcher-disable workaround cannot be shared through workspace settings.

## Best solution

Ensure package watching does not disrupt externally managed venv rebuilds or surface transient incomplete-environment errors. Consider workspace-level control of python-envs.packageWatchers as a shared workaround; its current machine-only scope does not satisfy that request.

- **Relevant current source:** src/managers/common/packageWatcher.ts, watchPackageChangesForEnvironment, debounces create/change/delete events for 500 ms and then calls the current package manager's refresh after checking executable existence.
