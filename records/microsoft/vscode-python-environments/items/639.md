# Issue #639 — Conda environment activation does not work for R terminals

[https://github.com/microsoft/vscode-python-environments/issues/639](https://github.com/microsoft/vscode-python-environments/issues/639)

## Summary

A real gap remains: command-mode activation can inject a conda command into an R process, while shell-startup mode supports shell startup files rather than activating an R console. No open canonical issue owns this specific cross-extension behavior, and the existing off setting does not provide the requested selective activation.

## Change summary

Preserve conda activation when launching an R console without sending shell activation commands into the running R interpreter.

## Best solution

Prevent command activation from being sent to terminals whose executable is a non-shell program such as R or radian, while defining a supported way for such terminals to inherit the selected conda environment before the process starts. This likely requires coordination with the R extension rather than treating an R prompt as a supported shell.

## Evidence

- **current source:** src/features/terminal/terminalManager.ts handles every opened terminal not excluded by shouldSkipTerminalActivation(), resolves the selected Python environment, and invokes command activation when python-envs.terminal.autoActivationType is command.
- **insufficient exclusion:** src/features/terminal/utils.ts excludes only hidden terminals and PTY-based extension terminals; a regular terminal created by another extension with R or radian as its shellPath is not excluded.
- **shell detection:** src/features/common/shellDetector.ts does not recognize R or radian and ultimately falls back to the configured or platform-default shell, allowing shell activation syntax to be selected for a non-shell R process.
- **existing capability check:** package.json exposes command, shellStartup, and off for python-envs.terminal.autoActivationType, but no option selectively suppresses activation in non-shell extension terminals while retaining activation elsewhere.
- **historical report:** https://github.com/microsoft/vscode-python/issues/21933 documents the same command-injection symptom in an R terminal, but it is closed and therefore cannot serve as a duplicate canonical.
- **related rollout issue:** https://github.com/microsoft/vscode-python/issues/25291 is open but broadly tracks terminal auto-activation after the rollout; it does not own the specific requirement to launch R inside the selected conda environment.
