# Issue #639 — Conda environment activation does not work for R terminals

[https://github.com/microsoft/vscode-python-environments/issues/639](https://github.com/microsoft/vscode-python-environments/issues/639)

## Summary

A real gap remains: command-mode activation sends a shell command into the already-running R REPL, while shell-startup mode cannot make that R process inherit the selected conda environment. No open canonical issue owns this R-terminal workflow, so it should remain open for a cross-extension activation design.

## Change summary

Start R terminals inside the selected conda environment without injecting `conda activate` into the R console.

## Best solution

Coordinate with the R extension so its terminal process receives the selected conda environment at launch, while preventing this extension from sending shell activation commands to non-shell REPL terminals. The implementation likely needs an explicit integration or API path because generic terminal ownership is not currently exposed.

## Evidence

- **confirmed behavior:** The reporter showed that opening the R terminal injects `conda activate my_env` after the R prompt appears, where R rejects it as an unexpected symbol; shellStartup avoids the command but leaves the environment inactive.
- **current source:** src/features/terminal/terminalManager.ts auto-activates every newly opened terminal unless shouldSkipTerminalActivation returns true; src/features/terminal/utils.ts only skips hidden and PTY-based terminals, not terminals whose shellPath is an R executable.
- **R terminal construction:** REditorSupport/vscode-R creates `R Interactive` with ordinary TerminalOptions and sets shellPath directly to R or radian, so it is not covered by this repository's current hidden/PTY exclusions.
- **same historical limitation:** https://github.com/microsoft/vscode-python/issues/21933 documents the same invalid conda activation injection into an R terminal; it was closed after pointing to the former environment-variable experiment, not because the R workflow was unsupported or fixed permanently.
- **platform constraint:** https://github.com/microsoft/vscode/issues/163873 records that VS Code does not expose terminal ownership for reliable filtering and was closed with the expectation that the Python extension would use launch-time environment variables instead.
- **canonical search:** Open issues https://github.com/microsoft/vscode-python-environments/issues/1375 and https://github.com/microsoft/vscode-python-environments/issues/1510 concern disruption or missing activation in ordinary shell terminals and do not own the R-specific launch requirement.
