# Issue #1747 — `pet server` `configure` hangs in a filesystem-scan busy-loop on large workspaces → 30s timeout × 3 retries = ~90s 100% CPU (thermal shutdown on laptops)

[https://github.com/microsoft/vscode-python-environments/issues/1747](https://github.com/microsoft/vscode-python-environments/issues/1747)

## Summary

The report provides a deterministic PET configure reproduction, syscall measurements,
and extension logs showing repeated timeouts under sustained CPU load. Current main reduces the
default glob scope but still permits recursive configured patterns and retains a 30s/60s configure
retry path, so meaningful work remains across this extension and PET.

## Change summary

A recursive environment-directory glob over a large workspace makes PET scan at
100% CPU while the extension repeatedly times out and retries the same configuration.

## Best solution

PET should bound or cancel recursive configure-time glob expansion and terminate
malformed JSON-RPC input cleanly; a maintainer can transfer or link those parts to
microsoft/python-environment-tools. In this extension, the environment area should prevent repeated
execution of an identical timed-out configuration and surface an actionable diagnostic without
restarting into the same workload.

## Evidence

- **confirmed reproduction:** The report reproduces the configure stall directly against PET v1.20.1 for a
279,488-file workspace: the process fails to respond within 12 seconds while strace records 145,700
filesystem-related calls, including 138,906 close calls and 6,792 stat calls.
- **extension logs:** Two separate extension sessions reportedly show 30-second configure timeouts,
SIGTERM restarts, and exhaustion of three restart attempts while processing the same recursive
environmentDirectories pattern.
- **current extension source:** src/managers/common/nativePythonFinder.ts still uses 30,000ms and 60,000ms
configure timeouts, clears lastConfiguration after a timeout, and retries that configuration;
ConfigureRetryState kills PET after two consecutive timeouts, while process startup resets the
timeout state.
- **current default mitigation:** package.json on main defaults python-envs.workspaceSearchPaths to bounded patterns
`.venv` and `*/.venv`, rather than `**/.venv`, but explicitly configured recursive patterns remain
supported.
