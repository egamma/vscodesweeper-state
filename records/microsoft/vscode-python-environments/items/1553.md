# Issue #1553 — About python projects feature

[https://github.com/microsoft/vscode-python-environments/issues/1553](https://github.com/microsoft/vscode-python-environments/issues/1553)

## Summary

This is a support question about intentional project-model behavior: every VS Code workspace folder is used as a default project scope, regardless of whether its contents have been classified as Python.

## Change summary

Explain why non-Python folders in a multi-root workspace appear as Python projects.

## Best solution

Keep the documented workspace-folder default so environment selection always has a project scope; any request for an exclusion mechanism should be evaluated separately as a feature change.

- **Proposed comment:**

  > Thanks for the question. This is currently by design: the project model uses every VS Code workspace folder as a default project scope so environment selection has a scope, then allows more specific files or subfolders to be added as projects. It does not first classify the folder's contents as Python. For support questions, please use the Python extension's GitHub Discussions Q&A: https://github.com/microsoft/vscode-python/discussions/categories/q-a.
