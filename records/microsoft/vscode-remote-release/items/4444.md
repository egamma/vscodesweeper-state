# Issue #4444 — please expose `--no-check-certificate` to wslDownload.sh

[https://github.com/microsoft/vscode-remote-release/issues/4444](https://github.com/microsoft/vscode-remote-release/issues/4444)

## Summary

A real WSL setup and diagnostics gap remains for corporate TLS interception. The global wget workaround does not provide a safe, documented extension-level solution, so this should remain open and be routed to WSL/proxy ownership.

## Change summary

Expose or document a controlled way for WSL server downloads to handle corporate certificate interception instead of failing with unusable wget advice.

## Best solution

The WSL extension should detect certificate-chain failures and guide users toward trusting their corporate CA, with any certificate-check bypass made explicit and narrowly scoped rather than requiring a global `~/.wgetrc` change.
