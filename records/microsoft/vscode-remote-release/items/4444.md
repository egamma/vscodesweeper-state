# Issue #4444 — please expose `--no-check-certificate` to wslDownload.sh

[https://github.com/microsoft/vscode-remote-release/issues/4444](https://github.com/microsoft/vscode-remote-release/issues/4444)

## Summary

Keep open with the WSL owner: the documented download paths and confirmed wget workaround do not establish a supported VS Code control for this request. No verified open canonical owns the same WSL bootstrap behavior.

## Change summary

Expose certificate-validation configuration for VS Code Server downloads initiated by code from a WSL terminal, with actionable certificate-error guidance.

## Best solution

The WSL component should provide clear guidance for trusting corporate certificates during server bootstrap and decide whether a narrowly scoped certificate-validation override is appropriate. Preserve certificate verification by default rather than relying on script edits or a user-wide wget bypass.

## Evidence

- **Requested product surface:** https://github.com/microsoft/vscode-remote-release/issues/4444 describes code launched from WSL failing to download the server because a corporate certificate issuer is not trusted. The request is for a supported bootstrap configuration mechanism, not evidence that wget incorrectly validates certificates.
- **Existing-capability check:** https://code.visualstudio.com/docs/remote/wsl#_im-behind-a-proxy-and-have-connectivity-issues distinguishes Windows-side downloads when connecting from VS Code from wget downloads when launching in WSL. It documents wget proxy configuration and server environment setup, but does not establish that http.proxyStrictSSL controls certificate verification in the WSL bootstrap script. The alternative Windows-side connection path does not cover the requested code-from-WSL configuration.
- **Workaround is not implementation:** The May 2023, January 2024, and June 2024 comments in https://github.com/microsoft/vscode-remote-release/issues/4444 report that disabling certificate checks through ~/.wgetrc works. This changes wget behavior beyond the VS Code download; it is not confirmation that an extension setting shipped or that the requested error guidance improved.
- **Related items are not canonicals:** https://github.com/microsoft/vscode-remote-release/issues/6092 is open but requests certificate support inside Dev Containers, not WSL-terminal server bootstrap. https://github.com/microsoft/vscode-remote-release/issues/5179 concerns Remote - SSH using curl instead of wget and was closed through the community-upvote process, not by a fixing release.
