# Issue #9059 — Devcontainer for vscode.dev?

[https://github.com/microsoft/vscode-remote-release/issues/9059](https://github.com/microsoft/vscode-remote-release/issues/9059)

## Summary

Keep open as the canonical, strongly supported request for using Dev Containers from vscode.dev over a tunnel. Current documentation still requires the Dev Containers extension in a local VS Code desktop client, so the browser workflow remains an acknowledged capability gap.

## Change summary

Enable vscode.dev users connected through Remote Tunnels to reopen a remote-host workspace inside its Dev Container.

## Best solution

The Dev Containers component should become web-enabled by replacing its Node.js API and local-filesystem assumptions, allowing a vscode.dev tunnel session to create or attach to a container on the remote host. The narrower direct-container tunnel alternative remains separately tracked by https://github.com/microsoft/vscode-remote-release/issues/9131.

- **Fit:** aligned
- **Reason:** This advances remote/local feature parity while deepening the integration between Dev Containers, tunnels, and browser-based remote development.
- **Evidence:** The product promise is to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set," while the durable themes include Dev Container capability depth and tunnels as a first-class access path.
