[https://github.com/microsoft/vscode-remote-release/issues/10638](https://github.com/microsoft/vscode-remote-release/issues/10638)

## Summary

Keep open pending verification of the VPN-triggered DNS failure against the Remote Explorer fix released in 0.5.0. The startup-order steps and DNS diagnosis suffice to retest, but this reporter has not confirmed that the shipped fix covers ENOTFOUND.

## Change summary

Starting VS Code after Pulse Secure VPN leaves Remote Explorer empty when tunnel-service DNS resolution fails, hiding otherwise usable SSH hosts.

## Best solution

Remote Explorer should display SSH hosts even when Remote - Tunnels cannot reach its service. The Remote Explorer/tunnels owners should retest the supplied VPN startup sequence against the shipped error-handling fix and address any remaining DNS-failure case.
