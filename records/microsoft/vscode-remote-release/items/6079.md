# Issue #6079 — Custom remote installation directory for Containers

[https://github.com/microsoft/vscode-remote-release/issues/6079](https://github.com/microsoft/vscode-remote-release/issues/6079)

## Summary

Keep open as the canonical Containers request. Current documentation and the Dev Container specification expose no equivalent to `remote.SSH.serverInstallPath`, while continued reports show a real need on shared or capacity-constrained home directories.

## Change summary

Allow users to choose where Dev Containers installs VS Code Server files inside a container instead of always using the remote user's home directory.

## Best solution

The Dev Containers extension should provide an equivalent to `remote.SSH.serverInstallPath` for both creating and attaching to containers, without requiring users to relocate `HOME` or maintain symbolic links.

## Evidence

- **missing capability:** The current Dev Container specification reference at https://containers.dev/implementors/json_reference/ lists no property for selecting the VS Code Server installation directory, and the FAQ at https://code.visualstudio.com/docs/devcontainers/faq documents copying the server into the container without documenting a configurable destination.
- **canonical status:** A maintainer closed https://github.com/microsoft/vscode-remote-release/issues/6837 in favor of this issue, and https://github.com/devcontainers/spec/issues/702 was subsequently closed because https://github.com/microsoft/vscode-remote-release/issues/6079 already tracks the request.
- **community demand:** The issue reached the Backlog milestone with 25 body upvotes, and later comments identify shared network homes, filesystem pressure, watcher exhaustion, permission failures, and stale server installations as continuing use cases.
- **distinct related request:** https://github.com/microsoft/vscode-remote-release/issues/10444 and https://github.com/microsoft/vscode-remote-release/issues/9529 focus on the host-side `.vscode-remote-containers` directory; they do not supersede this request for the `.vscode-server` installation inside target containers.
