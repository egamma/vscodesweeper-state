# Issue #5937 — Azure CLI credentials not passed through to container

[https://github.com/microsoft/vscode-remote-release/issues/5937](https://github.com/microsoft/vscode-remote-release/issues/5937)

## Summary

Keep this accepted Dev Containers request open: documented credential sharing does not establish automatic Azure CLI authentication forwarding, and no verified canonical owns that capability.

## Change summary

Reuse the host's Azure CLI login inside a dev container without requiring a separate container login.

## Best solution

The Dev Containers owner should evaluate an explicit, opt-in mechanism for reusing host Azure CLI authentication, with clear credential-access boundaries. Installing the Azure CLI feature alone should not be mistaken for enabling authentication sharing.

## Vision fit

- **Fit:** aligned
- **Reason:** Reusing host authentication would reduce a local-to-container workflow gap within the existing Dev Containers architecture.
- **Evidence:** The public vision emphasizes remote/local parity: "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
