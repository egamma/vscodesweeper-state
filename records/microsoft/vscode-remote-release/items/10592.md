# Issue #10592 — Dev Containers doubles the size of gitconfig when using shared HOME folder

[https://github.com/microsoft/vscode-remote-release/issues/10592](https://github.com/microsoft/vscode-remote-release/issues/10592)

## Summary

Keep open: the shared-HOME configuration and reconnect/reload steps suffice to retest the reported doubling. Later credential-copy reports do not establish that this self-copy defect is fixed or owned elsewhere.

## Change summary

Dev Containers repeatedly appends a shared .gitconfig to itself, growing the file and slowing Git.

## Best solution

Dev Containers should avoid copying or appending Git configuration when the host and container paths reference the same file, while preserving normal configuration sharing. Retest the supplied shared-HOME scenario on current releases and verify repeated reloads leave the file unchanged.

## Evidence

- **Concrete trigger and impact:** https://github.com/microsoft/vscode-remote-release/issues/10592 specifies remoteEnv.HOME pointing to a shared folder and doubling after connecting or reloading. The reporter subsequently describes hundreds of MB of configuration and severe Git slowdown: https://github.com/microsoft/vscode-remote-release/issues/10592#issuecomment-2630588531.
- **Maintainer expectation:** https://github.com/microsoft/vscode-remote-release/issues/10592#issuecomment-2573200119 says appending should occur only when existing configuration contains nothing beyond filter and safe sections, and offers dev.containers.copyGitConfig=false. This is a workaround, not confirmation of a self-copy fix.
- **Documented capability:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents automatic copying of the local .gitconfig into the container on startup; it does not document repeated self-appending as intended behavior.
- **Canonical search:** Searches covering gitconfig, shared configuration, growth, and appending found no verified open canonical for whole-file doubling. https://github.com/microsoft/vscode-remote-release/issues/4632 concerns configuration defaults and credential-helper placement; https://github.com/microsoft/vscode-remote-release/issues/11023 concerns configuration not being copied after postCreateCommand creates it.
- **Later related behavior:** https://github.com/microsoft/vscode-remote-release/issues/11869#issuecomment-5803453093 withdraws its copyGitConfig-setting allegation after moving the setting to host User settings; its remaining defect is lifecycle hooks skipped after a failed copy, not successful self-appending. This provides setting-scope context but neither a canonical nor resolution of this report.
- **Distinct closed report:** https://github.com/microsoft/vscode-remote-release/issues/10484 addresses repeated safe.directory entries, with verification discussion in November–December 2024. It is closed and does not establish a fix for this later report's entire-file doubling.
