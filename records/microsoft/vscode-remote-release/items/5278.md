# Issue #5278 — Attach to running docker container by name in CLI and document code remote CLI options

[https://github.com/microsoft/vscode-remote-release/issues/5278](https://github.com/microsoft/vscode-remote-release/issues/5278)

## Summary

The supported CLI still lacks an attach command for arbitrary running containers, and the documented attach workflow remains UI-only. Keep the accepted request open and route it to the containers CLI surface.

## Change summary

Provide and document a supported CLI command for opening VS Code attached to an existing container by name or ID.

## Best solution

The Dev Containers extension should expose and document a supported attach command that accepts a container name or ID and workspace path, replacing reliance on the undocumented encoded `vscode-remote://attached-container` URI.

- **Reason:** A supported container-attach CLI deepens Dev Container workflows and makes existing remote capability easier to automate reliably.
- **Evidence:** The durable themes identify Dev Container capability depth as a continuing investment area, while the product promise is to open folders in containers with VS Code's full feature set.

## Evidence

- **current documentation:** https://code.visualstudio.com/docs/devcontainers/attach-container documents attaching to an existing container only through the Command Palette or Remote Explorer; it does not document a CLI equivalent.
- **CLI capability gap:** https://code.visualstudio.com/docs/devcontainers/devcontainer-cli lists `up`, `build`, `run-user-commands`, `read-configuration`, `features`, `templates`, and `exec`, plus a VS Code-provided `open` command, but no command for attaching to an arbitrary running container.
- **maintainer position:** https://github.com/microsoft/vscode-remote-release/issues/5278#issuecomment-991447477 proposes adding an `attach` command to the devcontainer CLI; the issue remains in the Backlog with 11 community upvotes.
- **unofficial workaround:** https://github.com/microsoft/vscode-remote-release/issues/5867#issuecomment-975401635 describes the `attached-container` folder URI as not officially supported and explicitly states that the CLI did not support attaching to an existing container.
- **distinct related request:** https://github.com/microsoft/vscode-remote-release/issues/2133 concerns launching a project defined by `.devcontainer`, whereas this issue targets an arbitrary container started by another tool, so it is not a canonical duplicate.
