# Issue #2323 — Remote Containers - Allow to specify --project-directory for docker-compose

[https://github.com/microsoft/vscode-remote-release/issues/2323](https://github.com/microsoft/vscode-remote-release/issues/2323)

## Summary

Keep this as the canonical Dev Containers request for configurable Compose project-directory behavior. A maintainer recently consolidated the matching request here; documented environment settings and compose-file workarounds do not provide explicit project-directory control.

## Change summary

Allow Dev Containers to specify Docker Compose's --project-directory so sibling applications can share a root .env file and resolve project-relative paths consistently.

## Best solution

The Dev Containers component should provide spec-aligned control over Compose's project directory without requiring duplicated .env files or placeholder compose files. Preserve this issue as the product-side tracker, coordinating with the related --env-file request without treating that narrower option as full coverage.

## Evidence

- **Canonical ownership:** https://github.com/microsoft/vscode-remote-release/issues/8594 is closed as a duplicate of this issue. The maintainer's 2026-11-16 comment explicitly identifies this issue as tracking --project-directory behavior and carries over the contributor-directory layout and empty root compose-file workaround: https://github.com/microsoft/vscode-remote-release/issues/8594#issuecomment-6928072439.
- **Existing-capability check:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md documents dockerComposeFile, service, runServices, and workspaceFolder for Compose, but no project-directory property. runArgs and build.context are image/Dockerfile-specific; workspaceFolder selects the folder opened inside the container, not Compose's host-side project directory.
- **Environment settings are not equivalent:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents remoteEnv for editor subprocesses and service env_file for container environment variables. These do not select Compose's project directory or supply interpolation values for build arguments; the maintainer explicitly distinguishes service env_file from build-argument support at https://github.com/microsoft/vscode-remote-release/issues/4585#issuecomment-789619358.
- **Related request and workaround:** https://github.com/microsoft/vscode-remote-release/issues/4885 remains open for --env-file support. Its root placeholder compose-file workaround changes file ordering and relative-path behavior rather than exposing project-directory control: https://github.com/microsoft/vscode-remote-release/issues/4885#issuecomment-1487002576. It is related, not a verified canonical for the full project-directory request.
- **Current Compose behavior:** https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/ documents project-directory-based .env lookup, with --project-directory overriding the first compose-file directory. This may improve the original root-compose layout on current Compose versions, but documentation alone neither confirms resolution in Dev Containers nor delivers explicit directory control.
