# Issue #2323 — Remote Containers - Allow to specify --project-directory for docker-compose

[https://github.com/microsoft/vscode-remote-release/issues/2323](https://github.com/microsoft/vscode-remote-release/issues/2323)

## Summary

A real capability gap remains: the current Dev Container specification has no equivalent to Docker Compose's `--project-directory`. This older, supported report is the best canonical issue; the newer identical request should consolidate here.

## Change summary

Allow Docker Compose-based dev containers to specify the project directory used for relative paths, project naming, and `.env` discovery.

## Best solution

Retain this as the canonical request and consolidate https://github.com/microsoft/vscode-remote-release/issues/8594 into it. The containers team should coordinate a spec-level project-directory or constrained Compose-arguments property through https://github.com/devcontainers/spec, then implement it consistently in Dev Containers tooling.

## Evidence

- **spec gap:** The current devcontainer.json reference at https://containers.dev/implementors/json_reference/ documents `dockerComposeFile`, `service`, and related Compose properties but no project-directory or general Compose-arguments property.
- **documented workaround:** Current guidance at https://code.visualstudio.com/remote/advancedcontainers/connect-multiple-containers uses relative `dockerComposeFile` paths to a common root-level Compose file. This can avoid some failures but does not provide the requested project-directory control.
- **same request:** https://github.com/microsoft/vscode-remote-release/issues/8594 is open and independently demonstrates the same missing `--project-directory` capability with logs from Dev Containers 0.295.0; it is newer than this issue and therefore is the satellite rather than the canonical.
- **related active demand:** https://github.com/microsoft/vscode-remote-release/issues/4885 remains open for the narrower `--env-file` option and contains recent demand for a constrained `dockerComposeArgs` surface, confirming that existing configuration still does not cover Compose invocation options.
