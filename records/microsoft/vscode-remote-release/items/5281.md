# Issue #5281 — Select VSCode Server volume by custom name

[https://github.com/microsoft/vscode-remote-release/issues/5281](https://github.com/microsoft/vscode-remote-release/issues/5281)

## Summary

Keep this accepted Dev Containers request open: disabling the cache unblocks the workflow but forfeits the caching capability the reporter wants to retain. No verified shipped cache-naming setting or open canonical superseding this issue was found.

## Change summary

Allow users to customize the extension-managed cache volume name so multiple users on a permission-restricted Docker host can retain caching without volume-name conflicts.

## Best solution

Dev Containers should support a configurable cache volume name while preserving existing caching behavior and defaults. Document how this cache differs from workspace volumes and mounts that persist installed extensions.
