# Issue #1357 — Remote-WSL: Reopen Folder in Windows fails if workspace path includes symbolic link

[https://github.com/microsoft/vscode-remote-release/issues/1357](https://github.com/microsoft/vscode-remote-release/issues/1357)

## Summary

Keep open: the supplied symlink setup and command sequence suffice to retest the Windows-reopen failure. Current documentation uses the renamed WSL: Reopen in Windows command, but neither documentation nor the thread establishes that this path-resolution defect was fixed.

## Change summary

Reopening a WSL workspace in Windows reports 'Path does not exist' when its path traverses a symbolic link to a Windows-mounted directory.

## Best solution

The WSL extension should reopen the actual Windows-backed project directory when the WSL workspace path contains a symbolic link. Retest the supplied steps on current versions and, if still failing, correct the reopen path translation without requiring users to bypass the symlink.
