# Issue #6615 — Can't Connect to WSL Host when WSL login shell is nushell

[https://github.com/microsoft/vscode-remote-release/issues/6615](https://github.com/microsoft/vscode-remote-release/issues/6615)

## Summary

Keep open as an accepted WSL feature request. Newer Nushell releases resolved the original connection failure, but the broader request to make server startup independent of non-POSIX login-shell parsing remains valid and was placed in Backlog in December 2025.

## Change summary

Make WSL server startup bypass the configured login shell so non-POSIX shells cannot reinterpret the bootstrap command.

## Best solution

The WSL extension should invoke its Bourne-compatible bootstrap path without passing it through the user's configured login shell; the component owner should validate the proposed WSL invocation or an equivalent supported mechanism.
