# Issue #11789 — Cannot reconnect to ssh agent in the same terminal after reload window when useLocalServer is false

[https://github.com/microsoft/vscode-remote-release/issues/11789](https://github.com/microsoft/vscode-remote-release/issues/11789)

## Summary

Keep open for Remote - SSH: the supplied steps and before/after logs suffice to retest agent forwarding in a surviving terminal. The historical fix concerns the opposite connection mode, and no verified open canonical or confirmed resolution covers this report.

## Change summary

SSH agent forwarding stops working in an existing remote terminal after Reload Window when remote.SSH.useLocalServer is false.

## Best solution

Remote - SSH should preserve a usable SSH_AUTH_SOCK for surviving terminals when terminal-mode connections restart. Investigate why reload changes the extension-managed socket alias rather than updating the alias already inherited by the terminal.

## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11789 supplies six steps, VS Code 1.132.1, Remote - SSH 0.124.0, Windows OpenSSH 9.5p2, and Debian 13/Ubuntu 24.04 targets. ssh-add -l works before Reload Window and then reports 'Error connecting to agent: No such file or directory'; the reporter also describes the same failure on Linux with useLocalServer=false. There are no independent confirmations or failed maintainer reproduction attempts.
- **Socket alias changes across reload:** In https://github.com/microsoft/vscode-remote-release/issues/11789, the initial connection sets SSH_AUTH_SOCK to /run/user/1000/vscode-ssh-auth-sock-627049484; reload sets it to /run/user/1000/vscode-ssh-auth-sock-296011276 while reusing server PID 289. Both logs show successful connection establishment and completion of 'Update SSH_AUTH_SOCK', narrowing investigation to the surviving terminal's socket reference rather than a failed SSH connection.
- **Documented connection modes:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting documents useLocalServer=false as Terminal Mode, the Windows default, with a separate connection for each window and reload. It does not establish that losing agent access in surviving terminals is intended; switching modes is a workaround, not resolution of this mode's defect.
- **Historical fix does not establish resolution:** https://github.com/microsoft/vscode-remote-release/issues/7859 is closed and explicitly reproduced with useLocalServer=true, stating false was unaffected. The maintainer's failed reproduction at https://github.com/microsoft/vscode-remote-release/issues/7859#issuecomment-2549473146 concerns that older report, not the newly reported false-mode failure.
