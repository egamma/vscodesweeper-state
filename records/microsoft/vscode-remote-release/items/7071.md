# Issue #7071 — Using dockerComposeFile via podman-compose, resolves Dockerfile in wrong directory (ENOENT on Dockerfile)

[https://github.com/microsoft/vscode-remote-release/issues/7071](https://github.com/microsoft/vscode-remote-release/issues/7071)

## Summary

This remains a confirmed Dev Containers bug: podman-compose leaves the build context relative, causing Dockerfile lookup from the extension directory. A detailed reproduction confirms it still occurs in Dev Containers 0.437.0.

## Change summary

Resolve relative Docker Compose build contexts against the compose file directory when using podman-compose.

## Best solution

The Dev Containers CLI should normalize podman-compose's relative build context against the directory containing the compose file before resolving the Dockerfile path.
