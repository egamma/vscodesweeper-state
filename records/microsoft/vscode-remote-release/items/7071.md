# Issue #7071 — Using dockerComposeFile via podman-compose, resolves Dockerfile in wrong directory (ENOENT on Dockerfile)

## Summary

Keep this correctly routed Dev Containers bug open: the January 2026 report supplies a complete reproduction on 0.437.0, extending the original 0.245.0 failure across several extension generations. Those steps suffice to retest; no current-release resolution or qualifying canonical duplicate was established.

## Change summary

Dev Containers resolves a relative podman-compose build context against the extension directory, causing Dockerfile ENOENT failures.

## Best solution

Dev Containers should resolve relative Compose build contexts against the appropriate Compose-file directory before locating the Dockerfile, following the maintainer's identified CLI integration fix. Retain this issue as the canonical tracker until the bundled extension behavior is fixed and confirmed; absolute paths remain a workaround.
