# Issue #10587 — Option to remove git credential config options from global git config in devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/10587](https://github.com/microsoft/vscode-remote-release/issues/10587)

## Summary

A real Dev Containers gap remains: lifecycle commands and dotfiles can work around host-only credential configuration, but there is no documented option to filter these entries automatically. The existing containers and feature-request labels are appropriate.

## Change summary

Allow Dev Containers to omit host credential-helper sections whose executables are unavailable inside the container.

## Best solution

Dev Containers should remove or suppress host-only credential helpers when installing its forwarded helper, while preserving unrelated credential settings. The containers owner should determine whether this should be automatic or configurable.

## Vision fit

- **Fit:** aligned
- **Reason:** Safely reusing Git credentials without leaking host-specific executable paths improves local/remote workflow parity in dev containers.
- **Evidence:** The public product promise is to let users open a folder remotely and retain VS Code's full feature set; credential forwarding is part of that parity.

## Evidence

- **workarounds only:** https://github.com/microsoft/vscode-remote-release/issues/10587#issuecomment-2623930389 recommends postStartCommand or a dotfiles-provided .gitconfig; both require users to replace or modify configuration rather than automatically filtering inaccessible helpers.
