# Issue #8983 — [remote] close remote connection should connect to hosting remote

[https://github.com/microsoft/vscode-remote-release/issues/8983](https://github.com/microsoft/vscode-remote-release/issues/8983)

## Summary

Keep open: this team-authored Backlog request identifies a real nested-remote UX gap, and the thread contains neither a verified duplicate nor a referenced public fix.

## Change summary

Closing an inner Dev Container connection should return the window to its hosting SSH connection instead of disconnecting the entire remote chain.

## Best solution

The remote connection command should recognize nested authorities, remove only the innermost authority, and reopen an empty window on the outer SSH host. The remote, containers, and SSH owners should preserve the existing full-disconnect behavior through a separately named command if needed.

## Vision fit

- **Fit:** aligned
- **Reason:** Preserving the outer connection makes nested remote workflows behave more predictably and supports reliable movement among projects on a remote host.
- **Evidence:** The vision identifies connection reliability and reconnection as a durable theme and treats remote-development parity with local workflows as a core value.
