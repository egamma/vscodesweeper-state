# Issue #9269 — Cannot clone repository into container volume with "features", with zscaler

[https://github.com/microsoft/vscode-remote-release/issues/9269](https://github.com/microsoft/vscode-remote-release/issues/9269)

## Summary

Keep open: the log identifies a Docker/BuildKit certificate-trust failure behind Zscaler, not a failure downloading the feature itself. Later bootstrap certificate improvements do not establish that this builder-side failure is resolved.

## Change summary

Cloning into a container volume fails with features enabled behind Zscaler, while reopening a local clone succeeds.

## Best solution

Establish certificate trust in the Docker/BuildKit environment used by Clone Repository into Container Volume and compare it with the working local-clone build. The containers owner should distinguish builder configuration from any remaining bootstrap certificate-propagation gap before deciding whether extension work remains.

## Evidence

- **Concrete failure:** https://github.com/microsoft/vscode-remote-release/issues/9269 supplies configuration, steps, and logs: docker buildx fails resolving docker.io/docker/dockerfile:1.4 because fetching https://auth.docker.io/token returns 'x509: certificate signed by unknown authority'. Disabling Zscaler or removing the feature avoids the failure.
- **Certificate trust boundary:** https://docs.docker.com/engine/network/ca-certs/ documents that HTTPS-inspecting proxies require certificate trust on the Docker host and separately inside containers. Adding a certificate to the eventual development image does not establish trust for an earlier Docker image-resolution request.

There is no confirmation on this report that this resolves its Docker/BuildKit authorization failure.
