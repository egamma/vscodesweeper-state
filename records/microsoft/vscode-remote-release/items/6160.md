# Issue #6160 — Support ${localWorkspaceFolder} when cloning in volume

[https://github.com/microsoft/vscode-remote-release/issues/6160](https://github.com/microsoft/vscode-remote-release/issues/6160)

## Summary

A real Dev Containers capability gap remains: cloning into a volume provides no portable workspace-volume identity that Docker-from-Docker configurations can reuse. Docker now supports mounting volume subpaths, removing the original upstream blocker, but there is no evidence that the extension exposes the required volume name and subpath.

## Change summary

Allow one devcontainer configuration to reference the workspace consistently when the repository is either bind-mounted locally or cloned into a Docker volume.

## Best solution

Dev Containers should expose the workspace volume name and subpath, or provide equivalent mount translation, so Docker-from-Docker configurations work consistently across local folders, cloned volumes, and CI. The component owner should design this around Docker's current `volume-subpath` support rather than assigning a misleading host path to `${localWorkspaceFolder}`.
