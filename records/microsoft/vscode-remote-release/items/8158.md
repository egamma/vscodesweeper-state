# Issue #8158 — Disable `docker compose ... build`

[https://github.com/microsoft/vscode-remote-release/issues/8158](https://github.com/microsoft/vscode-remote-release/issues/8158)

## Summary

Keep open: the maintainer accepted exploring startup without an explicit Compose build, and the documented prebuilt-image workflows do not establish coverage of the requested pull-first, build-if-missing behavior. No verified canonical owns this product request.

## Change summary

Allow Dev Containers to prefer a published Compose service image and build locally only when that image is unavailable, rather than always invoking an explicit build.

## Best solution

The containers component should support Compose's pull-first/build-fallback workflow where no additional image build is required, while preserving necessary Features and UID-update handling. Coordinate the shared CLI behavior with https://github.com/devcontainers/cli/issues/1100 and retain this issue for the extension-facing outcome.
