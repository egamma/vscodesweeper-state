# Issue #6243 — Feature Request: allow opening remote workspaces through extensions

[https://github.com/microsoft/vscode-remote-release/issues/6243](https://github.com/microsoft/vscode-remote-release/issues/6243)

## Summary

A real API gap remains: Codespaces has a protocol-handler workaround and Dev Containers has an extension-specific command, but there is still no documented, stable mechanism for extensions to open arbitrary remote workspaces.

## Change summary

Provide extension authors with a documented API for opening local or remote workspaces across Dev Containers, Codespaces, and other remote providers.

## Best solution

The remote components and VS Code extension API owners should define a stable, documented workspace-opening contract that remote providers can implement, rather than requiring extensions to depend on provider-specific undocumented commands and URI handlers.

## Vision fit

- **Fit:** aligned
- **Reason:** A supported remote-workspace API would improve parity between local and remote workspace-management experiences.
- **Evidence:** The vision identifies parity as a core value: remote development should provide VS Code's full feature set while the workspace runs remotely.
