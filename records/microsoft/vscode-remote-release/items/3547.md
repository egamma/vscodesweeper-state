# Issue #3547 — Attach to Kubernetes Pod does not use kubectl provided by Kubernetes Extension

[https://github.com/microsoft/vscode-remote-release/issues/3547](https://github.com/microsoft/vscode-remote-release/issues/3547)

## Summary

A real Dev Containers integration gap remains: Kubernetes can manage its own kubectl installation and path, while the pod-attach command independently expects kubectl on PATH. The issue is already correctly routed and highlighted for planning.

## Change summary

Make Attach Visual Studio Code to a Kubernetes pod use the kubectl selected or installed by the Kubernetes extension, or provide an equivalent configurable path.

## Best solution

The Dev Containers Kubernetes attach flow should obtain the effective kubectl executable and active cluster configuration from the Kubernetes extension, with an explicit Dev Containers setting only if that integration is unavailable. The containers component owns this interoperability work.
