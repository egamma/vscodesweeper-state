# Issue #9251 — using vs code CLI from within tunnel connection

[https://github.com/microsoft/vscode-remote-release/issues/9251](https://github.com/microsoft/vscode-remote-release/issues/9251)

## Summary

Keep open: a maintainer confirmed that the injected remote-terminal CLI lacks tunnel commands and designated this issue to track their eventual adoption. Current documentation covers tunnel management through the standalone CLI, not through the injected command.

## Change summary

Expose tunnel management subcommands through the `code` command injected into terminals connected to a remote tunnel.

## Best solution

The CLI, tunnels, and server owners should make the injected remote `code` command delegate tunnel subcommands to the full CLI while preserving editor-forwarding behavior such as `code file`.

## Vision fit

- **Fit:** aligned
- **Reason:** Providing the full CLI through a tunnel-connected terminal advances the documented goal of a unified local and remote VS Code experience.
- **Evidence:** The public VS Code Server documentation says the project wants a “unified VS Code experience no matter how you use the editor, whether it's local or remote,” and describes tunnels and the CLI as core server surfaces: https://code.visualstudio.com/docs/remote/vscode-server
