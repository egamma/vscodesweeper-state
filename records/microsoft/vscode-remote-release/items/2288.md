[https://github.com/microsoft/vscode-remote-release/issues/2288](https://github.com/microsoft/vscode-remote-release/issues/2288)

## Summary

Keep open: this team-authored request has no verified duplicate or referenced public fix. Current documentation avoids the problem through Docker's WSL 2 backend but does not provide the requested automatic diagnosis for legacy drive sharing.

## Change summary

Detect Docker Desktop bind-mount failures caused by invalid Windows drive-sharing credentials and present actionable recovery guidance.

## Best solution

The Dev Containers component should recognize the `/host_mnt/... permission denied` signature and explain how to restore file sharing, if the affected Docker Desktop configuration remains supported. Otherwise, the component owner should explicitly decide the request's disposition.
