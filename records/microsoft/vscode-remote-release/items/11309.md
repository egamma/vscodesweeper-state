# Issue #11309 — Dev Container build fails with podman and HyperV

[https://github.com/microsoft/vscode-remote-release/issues/11309](https://github.com/microsoft/vscode-remote-release/issues/11309)

## Summary

The isolated reproduction shows a Podman Hyper-V filesystem-sharing failure rather than a Dev Containers defect: running `podman events` directly makes `/mnt/c` return I/O errors. Keep this open as an upstream Podman compatibility issue.

## Change summary

Dev Containers cannot start a container from a Windows workspace because Podman under Hyper-V loses access to the `/mnt/c` host share.

## Best solution

Podman should preserve the Hyper-V host filesystem share while its events command is active. After an upstream correction, the Dev Containers owner should retest its event-monitoring path against the fixed Podman release.
