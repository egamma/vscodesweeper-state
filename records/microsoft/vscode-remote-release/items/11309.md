Keep open as an upstream Podman/Hyper-V filesystem issue: the reporter demonstrates that running and cancelling Podman's events command makes /mnt/c inaccessible independently of VS Code. No verified canonical or confirmed resolution covers this failure.

- **Actual failure stage:** The complete log at https://github.com/microsoft/vscode-remote-release/issues/11309 shows Podman 5.6.2 accepting version and inspection commands, then failing during `podman run` with `statfs /mnt/c/Users/.../debian-dev-container: input/output error`. This is a workspace bind-mount/startup failure, not an image-build error.

It also states that Dev Containers interacts with CLIs rather than container engines directly; this setting does not repair VM filesystem sharing.
