# Issue #2353 — uriTransformer.js consume 100% CPU in WSL

[https://github.com/microsoft/vscode-remote-release/issues/2353](https://github.com/microsoft/vscode-remote-release/issues/2353)

## Summary

Keep open as an upstream WSL platform issue and route it accordingly. The original failure was traced to WSL1 lacking CLOCK_REALTIME support for glibc 2.31, rather than to the Remote - WSL extension.

## Change summary

The remote extension-host process consumes a CPU core on WSL1 after upgrading the distribution to glibc 2.31.

## Best solution

Confirm whether any current reports remain after the upstream WSL fix shipped in Windows 20H2 Build 19042.487. Any remaining occurrence should include current WSL and Windows versions so the WSL owner can determine whether it has a distinct cause.
