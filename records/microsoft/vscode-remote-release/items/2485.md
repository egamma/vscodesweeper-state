# Issue #2485 — Add ability to specify container name in `devcontainer.json`

[https://github.com/microsoft/vscode-remote-release/issues/2485](https://github.com/microsoft/vscode-remote-release/issues/2485)

## Summary

The requested deterministic container naming is already supported: image/Dockerfile configurations can pass Docker's `--name` through `runArgs`, while Compose configurations use `container_name` and the documented project-name controls.

## Change summary

Allow a Dev Container configuration to assign a predictable Docker container name for automation such as `volumes-from`.

## Best solution

Keep the existing Docker-native naming surfaces and clarify them in Dev Containers documentation: use `runArgs` with `--name` for image/Dockerfile configurations, or Compose's `container_name` and project-name settings for Compose configurations.

- **Proposed comment:**

  > Thanks for the request and the examples. This is supported through the existing Docker-specific configuration surfaces. For an image or Dockerfile configuration, use:
  > 
  > ```json
  > "runArgs": ["--name", "hello-world"]
  > ```
  > 
  > `runArgs` is documented at https://containers.dev/implementors/json_reference/ as passing arguments to `docker run`. For Docker Compose configurations, use the service's `container_name`; project naming is documented at https://code.visualstudio.com/remote/advancedcontainers/set-docker-compose-project-name. The later image-name and volume-label concerns are distinct from assigning the container name and should be tracked separately.

## Evidence

- **Dev Container specification:** https://containers.dev/implementors/json_reference/ documents `runArgs` as Docker CLI arguments used when running an image/Dockerfile container; Docker's `--name` can therefore be supplied as `"runArgs": ["--name", "hello-world"]`.
- **thread confirmations:** https://github.com/microsoft/vscode-remote-release/issues/2485#issuecomment-1156342780 provides the working `runArgs` configuration, and multiple later commenters confirm that it solves deterministic container naming.
- **Compose documentation:** https://code.visualstudio.com/remote/advancedcontainers/set-docker-compose-project-name documents that VS Code respects Compose's top-level `name` and `COMPOSE_PROJECT_NAME`; the thread also confirms Compose's `container_name` handles the individual container name.
