# Issue #2485 — Add ability to specify container name in `devcontainer.json`

[https://github.com/microsoft/vscode-remote-release/issues/2485](https://github.com/microsoft/vscode-remote-release/issues/2485)

## Summary

The original request is already supported: runArgs can assign a deterministic Docker container name at creation time, and multiple commenters confirm using it successfully. Later requests about image names and Compose metadata are separate concerns.

## Change summary

Allow devcontainer.json to specify a predictable container name for automation such as volumes-from.

## Best solution

Use the existing runArgs property for image/Dockerfile configurations and container_name for Compose services. Preserve the distinction between the UI display name, Docker container name, image tag, and Compose project name.

- **Proposed comment:**

  > Thanks for the request and the examples shared here. You can specify the Docker container name before creation in devcontainer.json with:
  > 
  > ```json
  > "runArgs": ["--name", "my-devcontainer"]
  > ```
  > 
  > The documented runArgs property passes arguments to Docker when creating an image/Dockerfile-based container: https://containers.dev/implementors/json_reference/#image-specific. This gives automation a known name to use with --volumes-from, without renaming afterward.
  > 
  > For Docker Compose, use container_name on the service. The devcontainer.json name property controls the UI display name. The original container-naming request is therefore supported; image naming and Compose volume-label behavior are separate requests.

## Evidence

- **Existing capability:** https://containers.dev/implementors/json_reference/#image-specific documents runArgs as Docker CLI arguments used when running the container. Setting "runArgs": ["--name", "my-devcontainer"] supplies the requested name at creation time rather than renaming afterward.
- **Thread confirmations:** https://github.com/microsoft/vscode-remote-release/issues/2485#issuecomment-1156342780 provides the exact runArgs naming configuration; https://github.com/microsoft/vscode-remote-release/issues/2485#issuecomment-1722584736 reports successful naming, and https://github.com/microsoft/vscode-remote-release/issues/2485#issuecomment-2789829245 thanks the contributor for that solution in April 2025.
- **Display-name distinction:** https://containers.dev/implementors/json_reference/#general-properties defines name as the dev container name displayed in the UI, not the Docker runtime name. The original body requests a predictable runtime name, which runArgs supplies without requiring name to change semantics.
- **Compose support:** The thread reports using service-level container_name successfully. https://code.visualstudio.com/remote/advancedcontainers/set-docker-compose-project-name separately documents supported Compose project naming through top-level name or COMPOSE_PROJECT_NAME; project naming is distinct from individual container naming.
- **Related history:** https://github.com/microsoft/vscode-remote-release/issues/2590 was closed in favor of this issue, and https://github.com/microsoft/vscode/issues/117142#issuecomment-789588890 likewise directs naming discussion here. Neither is an open duplicate target or proof of a landed fix; this proposal rests on the documented configuration and user confirmations.
