# Issue #2485 — Add ability to specify container name in `devcontainer.json`

[https://github.com/microsoft/vscode-remote-release/issues/2485](https://github.com/microsoft/vscode-remote-release/issues/2485)

## Summary

The requested capability already exists through the documented container-runtime configuration surfaces. `runArgs` accepts Docker's `--name` option for image/Dockerfile configurations, while Docker Compose configurations support `container_name` and an explicit project name.

## Change summary

Allow a deterministic Docker container name to be specified for a Dev Container.

## Best solution

Keep `devcontainer.json.name` as the UI-facing name and use the existing runtime-specific naming mechanisms: `runArgs` with `--name` for image/Dockerfile configurations, or Compose `container_name` for Compose configurations.

- **Fit:** aligned
- **Reason:** Deterministic container configuration fits the durable theme of deep, spec-aligned Dev Container capabilities.
- **Evidence:** The public Dev Container reference defines `name` as a UI display name and `runArgs` as Docker CLI arguments used when running an image- or Dockerfile-based container: https://containers.dev/implementors/json_reference/

- **Proposed comment:**

  > Thanks for the request and discussion. The central capability is available through the existing runtime-specific configuration:
  > 
  > - For an image or Dockerfile configuration, use `"runArgs": ["--name", "hello-world"]`. `runArgs` is documented at https://containers.dev/implementors/json_reference/.
  > - For Docker Compose, set `container_name` on the service. The Compose project name can be configured as documented at https://code.visualstudio.com/remote/advancedcontainers/set-docker-compose-project-name.
  > 
  > The `devcontainer.json` `name` property remains the display name shown in supporting tools rather than the Docker container name, so the current separation is working as designed.
