# Issue #11032 — buildx fails to build extended Dockerfile for devcontainer features due to DeadlineExceeded on podman

[https://github.com/microsoft/vscode-remote-release/issues/11032](https://github.com/microsoft/vscode-remote-release/issues/11032)

## Summary

The failure reproduces in standalone buildx through Podman's Docker-compatibility socket, which does not propagate the proxy environment to the BuildKit builder. This is an upstream Podman/buildx integration defect rather than a Dev Containers extension bug.

## Change summary

Dev-container feature builds time out behind a corporate proxy when Podman's Docker-compatibility mode starts a BuildKit builder without the required proxy environment.

## Best solution

Podman's Docker-compatibility layer should propagate proxy configuration when creating the buildx builder; the upstream Podman issue should own that fix. Keep this report open as the Dev Containers integration reference until the upstream behavior is resolved or the containers team adopts a safe workaround.
