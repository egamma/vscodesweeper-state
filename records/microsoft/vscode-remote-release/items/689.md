# Issue #689 — Use existing Node to connect

[https://github.com/microsoft/vscode-remote-release/issues/689](https://github.com/microsoft/vscode-remote-release/issues/689)

## Summary

A real capability gap remains: current documentation still describes an automatically installed VS Code Server whose platform requirements depend on its shipped Node.js runtime. Route this footprint-reduction request to the SSH and server owners.

## Change summary

Allow Remote - SSH to use a compatible Node.js already installed on the remote host instead of always deploying the bundled runtime.

## Best solution

The SSH and VS Code Server owners should evaluate a supported system-Node mode with strict compatibility checks and fallback to the bundled runtime, reducing installation size on constrained hosts without compromising native-module compatibility.
