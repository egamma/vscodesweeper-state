# Issue #2888 — The variable localWorkspaceFolderBasename should be replaced with empty when not available

[https://github.com/microsoft/vscode-remote-release/issues/2888](https://github.com/microsoft/vscode-remote-release/issues/2888)

## Summary

Keep open: current documentation still identifies these variables as unsupported when cloning into a container volume, and the unresolved-placeholder behavior remains a design gap. This team-authored item has no verified duplicate or public fixing commit referencing it.

## Change summary

Replace `${localWorkspaceFolderBasename}` with an empty string rather than leaving the placeholder intact when no local workspace folder exists.

## Best solution

The Dev Containers component should explicitly handle unavailable local-workspace variables instead of passing literal placeholders through, then document the chosen behavior. The decision should be reconciled with the fail-fast alternative tracked at https://github.com/microsoft/vscode-remote-release/issues/5547.
