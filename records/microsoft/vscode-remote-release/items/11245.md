# Issue #11245 — Generated script does not recognize linux-arm64

[https://github.com/microsoft/vscode-remote-release/issues/11245](https://github.com/microsoft/vscode-remote-release/issues/11245)

## Summary

Keep open for an SSH-owner scope decision. The team-authored report demonstrates that the default exec-server path fails on unsupported openSUSE Tumbleweed aarch64 while the legacy path works, but there is no verified fix or canonical duplicate.

## Change summary

Retain a working Remote - SSH connection path for openSUSE aarch64 when the default exec-server CLI cannot start.

## Best solution

The SSH owner should decide whether to support this openSUSE configuration, then either make the exec-server CLI compatible or retain the legacy server path as a documented fallback. Testing should compare both paths and capture the remote CLI log to identify why `cli-alpine-arm64` exits without a listening port.
