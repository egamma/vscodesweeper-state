# Issue #3034 — Does not respect workspaceMount, workspaceFolder when using "Open repository in container"

[https://github.com/microsoft/vscode-remote-release/issues/3034](https://github.com/microsoft/vscode-remote-release/issues/3034)

## Summary

A real Dev Containers capability gap remains: repository-in-volume workflows still force the checkout under `/workspaces` instead of honoring the configured workspace location. The issue is correctly classified and routed, and no broader open canonical or documented setting fully covers the request.

## Change summary

Honor `workspaceFolder` and, where possible, adapt `workspaceMount` when cloning a repository into a container volume.

## Best solution

The Dev Containers extension should let volume-cloned repositories use the configured `workspaceFolder`, translating compatible `workspaceMount` destinations to the extension-managed volume while retaining `/workspaces/<repository>` as the default.
