# Issue #3034 — Does not respect workspaceMount, workspaceFolder when using "Open repository in container"

[https://github.com/microsoft/vscode-remote-release/issues/3034](https://github.com/microsoft/vscode-remote-release/issues/3034)

## Summary

Keep open: cloning into a container volume still lacks substantiated support for placing the repository at the configured absolute path. Documented manual-volume workflows and the latest comment's PWD workaround do not satisfy the original request.

## Change summary

Honor the configured repository location when opening or cloning a repository directly into a dev container volume.

## Best solution

The Dev Containers extension should adapt the cloned-volume mount to expose the repository at the configured target and open the matching workspaceFolder. Preserve this product request separately from related Compose startup and workspace-variable issues.

That manual alternative does not establish support for the requested direct-clone workflow.

Its maintainer explanation at https://github.com/microsoft/vscode-remote-release/issues/5388#issuecomment-1259437096 says the volume is initially mounted at /workspaces before configuration contents are known; its workaround retains that location.
