# Issue #11039 — Problems with the vscode plugin remotessh connecting to a remote server

[https://github.com/microsoft/vscode-remote-release/issues/11039](https://github.com/microsoft/vscode-remote-release/issues/11039)

## Summary

Keep this as a request for lower-library compatibility, not an SSH defect: the reported host falls below the documented server requirements. The available sysroot workaround does not provide a supported server built for glibc 2.17, and no verified canonical owns this request.

## Change summary

Provide a VS Code Server compatible with older remote Linux libraries, including glibc 2.17.

## Best solution

The SSH/server owners should decide whether to offer lower-library compatibility or retain the current minimum requirements. Document the existing custom-sysroot option for the reporter without treating that unsupported workaround as delivery of the requested compatible server.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/11039 explicitly requests a lower-version-compatible server after Remote - SSH 0.120.0 with VS Code 1.101.1 rejects the remote libraries. There are no comments establishing a fix or a maintainer decline.
- **Documented compatibility boundary:** https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions states that, starting with VS Code 1.99, prebuilt servers require glibc 2.28 or later. https://code.visualstudio.com/docs/remote/linux also lists kernel >= 4.18 and libstdc++ >= 3.4.25; glibc 2.17 is outside these requirements.
- **Existing capability is a workaround:** https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions documents VSCODE_SERVER_CUSTOM_GLIBC_LINKER, VSCODE_SERVER_CUSTOM_GLIBC_PATH, and VSCODE_SERVER_PATCHELF_PATH for supplying a newer-library sysroot. It explicitly calls this an unsupported technical workaround, not a server compatible with the host's original older libraries.
