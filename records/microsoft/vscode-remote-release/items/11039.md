# Issue #11039 — Problems with the vscode plugin remotessh connecting to a remote server

[https://github.com/microsoft/vscode-remote-release/issues/11039](https://github.com/microsoft/vscode-remote-release/issues/11039)

## Summary

This is a valid request for Remote - SSH support on legacy glibc systems, not a product defect: glibc 2.17 is below the documented requirement. The custom-sysroot workaround is available but explicitly unsupported, so it does not fully satisfy the request.

## Change summary

Provide a VS Code Server compatible with glibc 2.17 and older libstdc++, allowing Remote - SSH to connect to legacy Linux hosts.

## Best solution

The SSH/server owners should decide whether to ship and maintain a legacy-compatible server build; otherwise, improve the documented custom-sysroot path while retaining the supported glibc 2.28 baseline.

## Vision fit

- **Fit:** rejected
- **Reason:** Official glibc 2.17 support conflicts with the documented supported-host baseline and the vision's guardrail of pragmatic limits on legacy environments.
- **Evidence:** The Remote Development Linux documentation lists kernel 4.18, glibc 2.28, and libstdc++ 3.4.25 as the baseline and identifies CentOS/RHEL 7-class systems as unsupported: https://code.visualstudio.com/docs/remote/linux
