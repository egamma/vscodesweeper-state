# Issue #11755 — Support client-side localhost port forwarding over Remote Tunnels

[https://github.com/microsoft/vscode-remote-release/issues/11755](https://github.com/microsoft/vscode-remote-release/issues/11755)

## Summary

Keep open during the active Backlog Candidates window. Current Remote Tunnels forwarding produces a Dev Tunnels URL rather than the requested client-side localhost endpoint, so a meaningful capability gap remains.

## Change summary

Add optional client-side localhost port forwarding for services reached through Remote Tunnels while retaining Dev Tunnels endpoints.

## Best solution

The tunnels component should support binding a remote service to a client loopback port, alongside the existing shareable Dev Tunnels address, so localhost-dependent OAuth, cookie, CORS, WebSocket, and SDK workflows work remotely.
