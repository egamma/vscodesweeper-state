# Issue #9652 — [devcontainers] Warn users using Docker Desktop on Linux

[https://github.com/microsoft/vscode-remote-release/issues/9652](https://github.com/microsoft/vscode-remote-release/issues/9652)

## Summary

A real Dev Containers diagnosability gap remains: Docker Desktop on Linux can expose bind-mounted workspaces with ownership incompatible with a non-root container user. The related rootless-Docker issue covers the underlying limitation but not this Docker-Desktop-specific warning closely enough to make this a duplicate.

## Change summary

Detect Docker Desktop on Linux and warn when its file-sharing UID mapping may make a bind-mounted workspace unwritable.

## Best solution

Dev Containers should detect the `desktop-linux` context and present targeted guidance only when the workspace ownership is incompatible with the configured container user, avoiding a blanket warning on current Docker Desktop versions.

## Evidence

- **related rootless limitation:** https://github.com/microsoft/vscode-remote-release/issues/4646 remains open and documents the same UID-mapping class of bind-mount failures, including maintainer discussion of volumes or running as container root; it concerns rootless Docker generally rather than specifically owning a Docker Desktop warning.
- **current Docker behavior:** Docker's Linux FAQ explains that Docker Desktop uses VirtioFS and maps the host user to UID 0 in containers: https://docs.docker.com/desktop/troubleshoot-and-support/faqs/linuxfaqs/#how-do-i-enable-file-sharing. Its current installation documentation also notes that Docker Desktop 4.35 and later no longer requires manual ID-mapping configuration, so detection should test the actual incompatible state rather than warn every Linux user.
- **existing Dev Containers surface:** https://code.visualstudio.com/remote/advancedcontainers/add-nonroot-user documents `remoteUser`, `containerUser`, and automatic UID/GID updates for Docker CE/EE on Linux, but does not provide the requested Docker Desktop on Linux warning.
