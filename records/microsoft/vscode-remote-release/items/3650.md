# Issue #3650 — Build image with user defined tag

[https://github.com/microsoft/vscode-remote-release/issues/3650](https://github.com/microsoft/vscode-remote-release/issues/3650)

## Summary

This is now fully covered by the broader open Dev Container specification proposal for universal image naming, building, and reuse. Consolidating there keeps the extension aligned with the shared specification.

## Change summary

Allow devcontainer.json to assign a user-defined name and tag to an image built from a Dockerfile or Docker Compose service.

## Best solution

Follow https://github.com/devcontainers/spec/issues/74, whose proposed `build.imageNames` semantics cover single-container and Docker Compose workflows. Preserve this issue's branch-derived tags, multi-container naming, and registry-publishing use cases in that discussion.

## Evidence

- **canonical specification proposal:** https://github.com/devcontainers/spec/issues/74 is open and proposes `build.imageNames` for exactly this behavior, with explicit examples covering Dockerfile builds, Docker Compose, prebuilt images, and multiple image tags.
- **current partial capability:** https://code.visualstudio.com/docs/devcontainers/devcontainer-cli documents `devcontainer build --image-name <name>:<tag>` for explicit prebuild and publishing workflows, but this does not provide the requested persistent devcontainer.json property used automatically when opening or rebuilding.
- **spec gap remains:** The current schema at https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json exposes Dockerfile build options but no supported `tag` or `imageNames` property; https://github.com/devcontainers/spec/issues/578 also tracks the related build/image schema mismatch.
