# Issue #11508 — Project names in DevContainer environment become unusable; lets make it

[https://github.com/microsoft/vscode-remote-release/issues/11508](https://github.com/microsoft/vscode-remote-release/issues/11508)

## Summary

Keep open for Dev Containers naming improvements: existing customization only partially addresses the request, and the verified related reports do not own its full scope of project-first labels, clearer terminology, and a container icon.

## Change summary

Make Dev Container project labels easier to distinguish by placing the project name first, avoiding confusing generic naming, and adding a container icon.

## Best solution

The Dev Containers owner should determine how to expose a distinctive project name consistently in container labels and window titles, with container context secondary. Coordinate any generic window-title or icon changes with VS Code core; a maintainer can transfer that portion to microsoft/vscode if necessary.

- **Reason:** Clear project identification makes working across multiple remote environments feel more like local development.
- **Evidence:** The public vision's parity promise is to open any folder in a container and take advantage of VS Code's full feature set.
