# Issue #11508 — Project names in DevContainer environment become unusable; lets make it

[https://github.com/microsoft/vscode-remote-release/issues/11508](https://github.com/microsoft/vscode-remote-release/issues/11508)

## Summary

Keep open as a Dev Containers naming feature request. Existing customization can provide a container name or a project-specific title, but it does not automatically preserve the local project identity or distinguish folders from multi-root workspaces.

## Change summary

Make Dev Container window titles concise and project-first, distinguish folders from workspaces, and visually identify the container context.

## Best solution

Dev Containers should expose the original project or folder name as a window-title variable and use it in a project-first default title; the component owner can coordinate any title-icon or core workbench changes with microsoft/vscode.

## Vision fit

- **Fit:** aligned
- **Reason:** Keeping remote projects as distinguishable as local projects advances the stated local/remote experience parity.
- **Evidence:** The public README promises users can "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."

## Evidence

- **existing capability gap:** The Dev Container specification documents `name` only as "A name for the dev container displayed in the UI" (https://containers.dev/implementors/json_reference/); it does not expose the original project name.
- **title customization:** VS Code documents `window.title` customization at https://code.visualstudio.com/docs/configure/custom-layout, but a per-project literal override is an awkward workaround rather than automatic project identity.
- **prior investigation:** https://github.com/microsoft/vscode-remote-release/issues/10565 requested an original-folder title variable; a maintainer noted Dev Containers could provide one, but that issue was closed for missing information rather than resolved.
- **related narrower issue:** https://github.com/microsoft/vscode-remote-release/issues/3937 remains open for ambiguous Dev Container names specifically in Windows Recent Workspaces. It corroborates the naming gap but is narrower than this cross-window title and presentation request.
