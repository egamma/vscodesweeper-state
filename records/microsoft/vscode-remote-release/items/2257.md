# Issue #2257 — WSL: pipe from stdin does not return console when closing window

[https://github.com/microsoft/vscode-remote-release/issues/2257](https://github.com/microsoft/vscode-remote-release/issues/2257)

## Summary

Fixed and shipped in VS Code 1.86: the CLI no longer implicitly applies `--wait` when reading from stdin, so the terminal prompt returns after input is consumed.

## Change summary

Piping stdin to `code-insiders -` from WSL keeps the terminal occupied after the resulting VS Code window closes.

## Best solution

Keep the shipped VS Code CLI behavior from commit 8db82d0d324ca928717008cfbef882777b0c3d95; it removes the implicit wait that caused this report.
