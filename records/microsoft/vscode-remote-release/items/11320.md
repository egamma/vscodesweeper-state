# Issue #11320 — DevContainer populate system file /etc/environment and broke sudo and su.

[https://github.com/microsoft/vscode-remote-release/issues/11320](https://github.com/microsoft/vscode-remote-release/issues/11320)

## Summary

The report provides a plausible Podman/CentOS reproduction showing that attaching changes `/etc/environment`, but it lacks the Dev Containers extension version, connection log, and independent confirmation. Request a current-version retest and diagnostic log before treating this as confirmed.

## Change summary

Attaching Dev Containers to a running container writes the connecting user's HOME into `/etc/environment`, causing `sudo -i` and `su` sessions to retain the wrong home directory.

## Best solution

The Dev Containers extension should keep its connection environment scoped to VS Code processes and avoid persisting user-specific HOME values in the container-wide `/etc/environment`; the containers owner should first confirm which attach/setup step performs the write.
