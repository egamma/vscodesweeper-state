# Issue #10041 — [devcontainer] Move docker (compose) path to Remote section / Allow override of settings by Remote section

[https://github.com/microsoft/vscode-remote-release/issues/10041](https://github.com/microsoft/vscode-remote-release/issues/10041)

## Summary

Keep open: environment-specific overrides for all three settings remain unsubstantiated as a shipped capability. The older Docker-path request overlaps, but does not own the Compose-path and WSL-execution requirements.

## Change summary

Allow remote-environment overrides of dev.containers.dockerPath, dev.containers.dockerComposePath, and dev.containers.executeInWSL to avoid manually changing settings between environments.

## Best solution

Dev Containers should resolve these settings against the originating WSL, SSH, or tunnel environment before connecting to a container. Coordinate Docker-path work with https://github.com/microsoft/vscode-remote-release/issues/8728 while retaining the Compose-path and WSL-execution requirements here.

## Evidence

This identifies a connection-time configuration gap, not evidence that remote overrides already work.
- **Existing capability check:** https://code.visualstudio.com/remote/advancedcontainers/docker-options documents selecting Podman using dev.containers.dockerPath. https://code.visualstudio.com/remote/advancedcontainers/develop-remote-host documents Docker contexts and DOCKER_HOST/DOCKER_CONTEXT for endpoint selection. Neither documents automatic per-environment overrides of the requested executable paths and executeInWSL setting.
- **Container settings are not host selection:** https://containers.dev/supporting#visual-studio-code defines customizations.vscode.settings as default settings placed into the container/machine-specific settings file. That does not establish a way to select the originating host's container executable or WSL-execution mode before connecting.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/8728 is open, older, in Backlog, and has 28 upvotes; its body and comments describe the same manual Docker/Podman switching symptom. However, it requests dockerPath overrides only, leaving this report's dockerComposePath and executeInWSL requirements unowned. https://github.com/microsoft/vscode-remote-release/issues/8817 is also open but requests workspace-scoped dockerPath only. Neither establishes full-scope duplicate ownership.
