# Issue #4841 — Add "build.secrets" field to `devcontainer.json`

[https://github.com/microsoft/vscode-remote-release/issues/4841](https://github.com/microsoft/vscode-remote-release/issues/4841)

## Summary

The requested build-time secret forwarding is implemented through build.options, and an affected user supplied a working --secret example. Propose closing as completed rather than adding a redundant build.secrets property.

## Change summary

Allow devcontainer.json to pass BuildKit --secret arguments when building the development image.

## Best solution

Use build.options to forward --secret arguments to the Dockerfile build. Feature-installation secret support discussed in the latest comment is separate work and is not required to satisfy the original request.

The working example above confirms this covers the original request, so this can be closed as completed. Exposing secrets to Feature installation steps is separate work discussed at https://github.com/devcontainers/cli/issues/1077.

## Evidence

- **Documented capability:** https://containers.dev/implementors/json_reference/#image-specific documents build.options as an array of Docker image build options passed to the Dockerfile build command. Unlike runArgs, this operates during image construction.
- **Public implementation:** https://github.com/devcontainers/cli/commit/b1f92d213dd79ad2554fe534151e8aa1dcf69987 adds options?: string[] to the Dockerfile build configuration. In src/spec-node/singleContainer.ts, the hunk beginning at line 243 reads config.build?.options and appends every entry to the build command arguments. This directly enables the reporter's requested --secret=id=...,src=... forwarding.
- **Extension adoption:** https://github.com/microsoft/vscode-remote-release/issues/3545#issuecomment-1895424823 announces availability in Dev Containers 0.333.0-pre-release. https://github.com/microsoft/vscode-remote-release/issues/9415 explicitly exercises build.options through the extension's Reopen in Container workflow, establishing that the extension uses this capability rather than it being CLI-only. The first stable shipping version was not established.
- **Matching user confirmation:** https://github.com/microsoft/vscode-remote-release/issues/4841#issuecomment-2118505706 reports using build.options with --secret=id=credentials,src=/home/user/.config/credentials.json and RUN --mount=type=secret in the Dockerfile, satisfying the original private-package build workflow.
- **Separate remaining scope:** https://github.com/microsoft/vscode-remote-release/issues/4841#issuecomment-3382615952 links https://github.com/devcontainers/cli/issues/1077, which remains open and concerns exposing secrets to generated Feature installation steps. That additional capability is distinct from forwarding secrets to the user's Dockerfile build and is not a duplicate canonical for this request.
