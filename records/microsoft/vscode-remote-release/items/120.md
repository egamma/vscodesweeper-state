# Issue #120 — Auto-connect to remote on startup

[https://github.com/microsoft/vscode-remote-release/issues/120](https://github.com/microsoft/vscode-remote-release/issues/120)

## Summary

The shipped `code --remote` option directly covers the original request to launch VS Code connected to a selected remote host.

## Change summary

Add a command-line option that starts VS Code connected to a specified SSH, WSL, or other remote environment.

## Best solution

Keep the existing generic remote CLI contract: callers can launch a remote folder or workspace with `code --remote <authority> <path>` and use that command in shortcuts.

## Vision fit

- **Fit:** aligned
- **Reason:** Direct remote launch supports the product goal of making remote folders as straightforward to open as local folders.
- **Evidence:** The public vision promises to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
