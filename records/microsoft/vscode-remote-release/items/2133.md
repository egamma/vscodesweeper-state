# Issue #2133 — Ability to launch .devcontainer project from command line

[https://github.com/microsoft/vscode-remote-release/issues/2133](https://github.com/microsoft/vscode-remote-release/issues/2133)

## Summary

The extension-installed devcontainer open command covers the original Makefile workflow, but the discussion establishes a remaining request for direct code CLI support without separately installing that command. Keep this established tracking issue open for that integration.

## Change summary

Allow a shell command to open a project's configured dev container directly, without first opening locally and accepting a reopen prompt.

## Best solution

Provide a supported code CLI entry point that delegates to Dev Containers and resolves the project's configuration without hand-encoding remote URIs. Coordinate the extension-side work here with the related CLI proposals rather than treating the editor-independent reference CLI as its replacement.

## Vision fit

- **Fit:** aligned
- **Reason:** A direct launch command makes configured remote environments easier to enter while preserving the existing client-server architecture.
- **Evidence:** The public vision promises opening any folder in a container with VS Code's full feature set and identifies dev container capability depth as a durable theme.
