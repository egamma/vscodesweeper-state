# Issue #6844 — Export `LOCAL_WORKSPACE_FOLDER` env var to docker compose

[https://github.com/microsoft/vscode-remote-release/issues/6844](https://github.com/microsoft/vscode-remote-release/issues/6844)

## Summary

A real Docker Compose capability gap remains: Dev Containers cannot declaratively expose the local workspace path or other local values to Compose interpolation. The issue is already correctly classified in the Backlog and has no verified canonical duplicate.

## Change summary

Expose the local workspace folder, or a general declarative local environment mapping, when Dev Containers invokes Docker Compose.

## Best solution

The containers component should provide a spec-aligned way to pass substituted local values such as `${localWorkspaceFolder}` into Docker Compose, avoiding generated `.env` files while preserving reuse of the Compose file in CI.

## Evidence

- **current specification:** The current Dev Container specification limits `workspaceMount` to image and Dockerfile scenarios and directs Docker Compose users to Compose mounts, which cannot interpolate `${localWorkspaceFolder}`: https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-reference.md#workspacefolder-and-workspacemount
- **workaround limitation:** Comments on https://github.com/microsoft/vscode-remote-release/issues/6844 document generated `.env` files via `initializeCommand`; the later CI/CD example explains why a repository `.env` file does not cover the central request.
- **related demand:** https://github.com/microsoft/vscode-dev-containers/issues/1677 remains open and independently reports that Compose cannot access `${localWorkspaceFolderBasename}`, reinforcing the same missing interpolation boundary without superseding this broader local-environment request.
- **canonical search:** Open issues https://github.com/microsoft/vscode-remote-release/issues/6983 and https://github.com/microsoft/vscode-remote-release/issues/9339 concern initialize-command effects and inheriting the launching process environment respectively; neither owns the specific requirement to supply workspace-derived values to Docker Compose.
