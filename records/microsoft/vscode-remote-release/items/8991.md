# Issue #8991 — DevContainers wont shutdown after Remote Connection is closed or after quitting VSCode 

[https://github.com/microsoft/vscode-remote-release/issues/8991](https://github.com/microsoft/vscode-remote-release/issues/8991)

## Summary

Keep open: the shutdown steps and subsequent cleanup logs suffice to retest, but no current-release resolution is established. The older Remote-SSH report matches the commenters' failures, without demonstrably covering the original report's unspecified Docker-host topology.

## Change summary

Dev containers remain running after closing the connection or quitting VS Code despite shutdownAction requesting container or Compose shutdown.

## Best solution

The Dev Containers owner should ensure shutdown cleanup uses the Docker execution environment that started the containers. Retest the original Dockerfile workflow separately from the Remote-SSH failures before consolidating the entire report into https://github.com/microsoft/vscode-remote-release/issues/6056.

## Evidence

- **Documented expectation:** https://containers.dev/implementors/json_reference/#general-properties defines shutdownAction as stopping containers when the tool window closes, with stopContainer defaulting for Dockerfile/image configurations and stopCompose for Compose. The original report explicitly sets stopContainer and waits 30–60 seconds.
- **Historical matching cleanup failures:** https://github.com/microsoft/vscode-remote-release/issues/8991#issuecomment-2526374920 and https://github.com/microsoft/vscode-remote-release/issues/8991#issuecomment-2565310866 show cleanup receiving its trigger but failing with docker ENOENT on Windows and macOS clients using Remote-SSH. https://github.com/microsoft/vscode-remote-release/issues/8991#issuecomment-3573401655 repeats the Windows executable failure on VS Code 1.106.2 in November 2025; these are substantive historical confirmations, not verification on today's release.
- **Older candidate and scope boundary:** Verified https://github.com/microsoft/vscode-remote-release/issues/6056 is open, dates to December 2021, and carries Backlog. It reports the same failure after reopening an SSH folder in a container, including Dockerfile and Compose configurations and missing-Docker cleanup errors. It covers the SSH commenters here, but the original report does not establish that SSH is involved; its full scope cannot safely be folded into that narrower canonical.
- **No established resolution:** The thread contains neither a maintainer fixing-release announcement nor reporter confirmation of resolution. https://github.com/microsoft/vscode-remote-release/issues/7754 concerns an older stopCompose regression and is closed, but does not establish resolution of this later stopContainer report. https://github.com/microsoft/vscode-remote-release/issues/10875 requests administrator controls and does not own this shutdown defect.
