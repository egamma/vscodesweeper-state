# Issue #11326 — Remote SSH to Windows Server fails on reading log file with Cannot find path

[https://github.com/microsoft/vscode-remote-release/issues/11326](https://github.com/microsoft/vscode-remote-release/issues/11326)

## Summary

Keep open for Remote - SSH investigation: the complete logs and timing workaround suffice to retest Windows bootstrap readiness. Later releases introduced additional startup behavior, but no evidence establishes that this earlier failure is fixed.

## Change summary

Remote - SSH rejects a Windows Server connection before the CLI log and listening port become available.

## Best solution

The SSH component should investigate its Windows bootstrap readiness deadline and handle delayed log creation and port discovery with bounded waiting and accurate failure diagnostics. Retest the supplied Windows Server 2025 scenario before deciding whether a product change remains necessary.

## Evidence

- **Complete failure report:** https://github.com/microsoft/vscode-remote-release/issues/11326 supplies macOS-to-Windows Server 2025 connection steps, VS Code 1.106.0 and Remote - SSH 0.120.0 versions, configuration, and logs for both useLocalServer modes. Plain SSH succeeds; extension bootstrap returns exitCode 200 with an empty listeningOn value.
- **Readiness deadline:** The generated script included in https://github.com/microsoft/vscode-remote-release/issues/11326 launches the CLI asynchronously, polls for its listening port for four seconds, then reads the log on failure. The terminal-mode log reports that the temporary file does not exist; the separately supplied server log contains a listening address. These are issue-provided logs, not public product-source findings.
- **Workaround is not a shipped fix:** The initial improvement after letting the VM settle was superseded by https://github.com/microsoft/vscode-remote-release/issues/11326#issuecomment-3589712715: the reporter observed recurrence at approximately 6 ms disk latency and reported that adding a one-second delay between StartCli and port collection restored connectivity. No maintainer release announcement or current-release resolution confirmation follows.

The former concerns Remote - SSH 0.123.0 supervisor startup and initial server download; the latter requests configurable timeouts for endpoint-protection delays. Neither establishes ownership of this earlier missing-log failure with an already installed CLI.
- **Documented diagnostic distinction:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting distinguishes useLocalServer connection modes from useExecServer bootstrap behavior and recommends testing with useExecServer disabled. That is a diagnostic comparison, not evidence that the reported exec-server failure is resolved.
