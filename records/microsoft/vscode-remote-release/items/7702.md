# Issue #7702 — Upgrade to 0.266.1 spawns dev_containers_target_stage which does not exist

[https://github.com/microsoft/vscode-remote-release/issues/7702](https://github.com/microsoft/vscode-remote-release/issues/7702)

## Summary

Keep open: the supplied configuration, logs, and version comparison suffice to retest the unwanted execution of stages after build.target. Related reports explain the non-BuildKit failure mode, but do not establish resolution for this SSH-hosted setup or a qualifying canonical for this re-reviewed issue.

## Change summary

Dev Containers builds unwanted Dockerfile stages despite build.target being set to dev, breaking a configuration that worked in 0.251.0.

## Best solution

The containers owner should retest the supplied multi-stage configuration without buildx and ensure generated metadata stages do not force unrelated stages to execute. BuildKit is a documented workaround, but its availability does not establish that the reported fallback-path regression is resolved.
