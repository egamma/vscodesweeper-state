# Issue #5761 — WSL2: make VS Code Server work with automount disabled

[https://github.com/microsoft/vscode-remote-release/issues/5761](https://github.com/microsoft/vscode-remote-release/issues/5761)

## Summary

Keep open: disabling WSL2 automount remains an unsupported but well-substantiated isolation scenario, with recent users still relying on selective read-only mounts. The issue is already correctly classified in the Backlog with significant community support.

## Change summary

Allow the WSL extension to start and connect to VS Code Server without mounting Windows drives inside the distribution.

## Best solution

The WSL extension should bootstrap its scripts and server payload without depending on a drvfs-mounted Windows path, while preserving the normal WSL connection workflow when automount is disabled.

## Vision fit

- **Fit:** aligned
- **Reason:** Removing the Windows-mount dependency would improve WSL integration fidelity and preserve the local-quality remote experience for intentionally isolated distributions.
- **Evidence:** The public WSL documentation promises a local-quality development experience regardless of where code is hosted, while the vision identifies WSL integration fidelity as a durable theme.
