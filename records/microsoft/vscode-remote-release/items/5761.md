# Issue #5761 — WSL2: make VS Code Server work with automount disabled

[https://github.com/microsoft/vscode-remote-release/issues/5761](https://github.com/microsoft/vscode-remote-release/issues/5761)

## Summary

Keep open: experimental scriptless startup has resolved the same failure for another reporter, but this thread has not confirmed mount-free operation. The Windows-filesystem isolation concern also requires human review rather than a cleanup close.

## Change summary

Allow the WSL extension to install, start, and connect to VS Code Server with Windows-drive automount disabled and no substitute Windows-directory mounts.

## Best solution

The WSL owner should validate remote.WSL.experimental.scriptLessStartup against this configuration, including server installation and updates, and make mount-free startup a supported path. Retain this issue until that path satisfies the isolation workflow without selective mounts or switching to SSH.
