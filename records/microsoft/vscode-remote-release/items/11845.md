# Issue #11845 — Dev Containers: concurrent server installs into the shared `vscode` volume race in `mv -n`, aborting container start and leaving a nested duplicate

[https://github.com/microsoft/vscode-remote-release/issues/11845](https://github.com/microsoft/vscode-remote-release/issues/11845)

## Summary

Keep open with the existing containers routing: detailed interleaved logs identify concurrent server-install failures, corroborated by another user. Newer extension versions exist, but no fix or current-version resolution is confirmed; the supplied steps suffice to retest.

## Change summary

Concurrent Dev Containers server installs into the shared vscode volume abort workspace startup and leave nested duplicate server directories.

## Best solution

The Dev Containers installer should coordinate concurrent installs or publish a complete server atomically, allowing losing installers to reuse the winner without nesting payloads or aborting startup. Verify simultaneous window restoration against a missing server commit; serial reopening is only a workaround.
