The linked configuration and workflow suffice for retesting; closure of the original error report does not establish resolution here.

## Change summary

Pass the host user's UID/GID to the devcontainer CLI when Clone Repository in Container Volume runs it as root inside a temporary container.

## Best solution

The Dev Containers extension should preserve the originating host user's identity through the temporary-container CLI invocation so explicit updateRemoteUserUID requests use the correct UID/GID. Retest the linked Debian configuration with an additional host bind mount accessible only to that user.
