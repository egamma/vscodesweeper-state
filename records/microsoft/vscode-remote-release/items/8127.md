# Issue #8127 — Cloning repo in named volume fails with docker rootless

[https://github.com/microsoft/vscode-remote-release/issues/8127](https://github.com/microsoft/vscode-remote-release/issues/8127)

## Summary

Keep open for Dev Containers: the reported clone workflow and socket mismatch provide sufficient steps to retest. A configurable socket path has since shipped, but neither automatic DOCKER_HOST handling nor the TCP case is confirmed resolved.

## Change summary

Cloning a repository into a named volume fails because the bootstrap container uses /var/run/docker.sock instead of the configured rootless Docker endpoint.

## Best solution

Dev Containers should make its named-volume bootstrap use the selected Docker endpoint consistently, including rootless Unix sockets and TCP connections. Retest the supplied workflow with the current extension and distinguish the manual dockerSocketPath workaround from any remaining endpoint-propagation defect.
