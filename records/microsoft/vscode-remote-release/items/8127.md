# Issue #8127 — Cloning repo in named volume fails with docker rootless

[https://github.com/microsoft/vscode-remote-release/issues/8127](https://github.com/microsoft/vscode-remote-release/issues/8127)

## Summary

The original report and two independent confirmations indicate that the Dev Containers volume-bootstrap path ignored DOCKER_HOST, but the latest evidence is from 2024 and does not establish whether current releases remain affected. A current-version retest and creation log are needed.

## Change summary

Make Clone Repository in Container Volume use the Docker endpoint from DOCKER_HOST instead of assuming /var/run/docker.sock.

## Best solution

The Dev Containers bootstrap flow should propagate DOCKER_HOST and connect through its configured Unix or TCP endpoint, mounting a socket only when the endpoint is a Unix socket. The component owner should first confirm the behavior on the current extension using a fresh creation log.
