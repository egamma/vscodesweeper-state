# Issue #5293 — High GPU Usage if WSL is Disconnected

[https://github.com/microsoft/vscode-remote-release/issues/5293](https://github.com/microsoft/vscode-remote-release/issues/5293)

## Summary

Keep open: the workload, disconnection sequence, and GPU measurements provide a usable retest scenario. The report targets 2021 releases; there is no confirmation of current reproduction or resolution, and no verified canonical owns the GPU spike.

## Change summary

GPU utilization rises sharply while VS Code is disconnected from WSL after a large build or file operation.

## Best solution

The WSL owner should retest the supplied workload and identify which local process consumes GPU resources during disconnection. If the excess rendering originates in the core workbench, a maintainer can transfer this to microsoft/vscode; the underlying WSL disconnect may require separate diagnosis.

## Evidence

Large file moves reportedly trigger the same sequence.
- **Historical evidence, not a confirmed fix:** The report identifies VS Code 1.57.1, WSL extension 0.56.5, Windows build 19043.1052, and Ubuntu 20.04. Its log captures successful reconnection after restarting WSL, not the GPU spike; there are no comments confirming reproduction or resolution.
- **Related reports do not establish duplication:** https://github.com/microsoft/vscode-remote-release/issues/4795 is open and concerns WSL disconnections, while https://github.com/microsoft/vscode-remote-release/issues/2919 is open and concerns remote node memory growth. Neither establishes ownership of this report's excessive GPU utilization during disconnection.
- **Diagnostic boundary:** https://code.visualstudio.com/docs/remote/troubleshooting documents WSL: Show Log and distinguishing WSL-extension failures from upstream WSL problems. Disconnection alone does not establish that the GPU spike is an upstream defect.
