# Issue #4271 — Expose host IANA Timezone to development containers in Windows

[https://github.com/microsoft/vscode-remote-release/issues/4271](https://github.com/microsoft/vscode-remote-release/issues/4271)

## Summary

A real capability gap remains: Dev Containers can forward an existing host environment variable, but Windows does not ordinarily expose its IANA time zone that way. The correctly routed Backlog request should remain open.

## Change summary

Expose the Windows host's IANA time-zone identifier so development containers can automatically configure their local time zone.

## Best solution

The Containers component should detect the host's IANA time zone and expose it through a spec-aligned substitution or environment mechanism. If this requires a new devcontainer.json variable, coordinate that addition through https://github.com/devcontainers/spec rather than creating an extension-only format fork.

## Evidence

- **current specification:** The current devcontainer.json reference at https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson supports `${localEnv:VARIABLE_NAME}` but lists no predefined host-time-zone variable; therefore it only covers this request when the user first creates a suitable host environment variable.
- **confirmed gap:** In https://github.com/microsoft/vscode-dev-containers/issues/307#issuecomment-1121510682, a maintainer documents setting `TZ` through `containerEnv` but explicitly confirms that automatically deriving it from the host is unavailable.
- **existing workaround:** The reporter's workaround at https://github.com/microsoft/vscode-remote-release/issues/4271#issuecomment-751815767 manually converts the Windows zone and forwards it with `${localEnv:TZ}`; it demonstrates feasibility but does not provide the requested automatic capability.
