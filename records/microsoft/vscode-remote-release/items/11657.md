# Issue #11657 — When connecting from a Linux client to a Windows SSH host, Remote-SSH fails in the exec-server bootstrap path if the VS Code Server still needs to be downloaded on the remote.

[https://github.com/microsoft/vscode-remote-release/issues/11657](https://github.com/microsoft/vscode-remote-release/issues/11657)

## Summary

Verified duplicate: this regression is another manifestation of the hardcoded Windows server-start timeout already tracked by the broader open issue. The additional evidence shows that a first-run server download, not only endpoint protection, can exceed that window.

## Change summary

Remote-SSH 0.123.0 fails to bootstrap a Windows SSH host when the first-run VS Code Server download takes longer than its four-second startup window.

## Best solution

Consolidate the Windows startup-timeout work on https://github.com/microsoft/vscode-remote-release/issues/11578 and ensure its solution also accommodates first-run server downloads before checking whether the agent host is listening.
