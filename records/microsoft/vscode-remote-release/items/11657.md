# Issue #11657 — When connecting from a Linux client to a Windows SSH host, Remote-SSH fails in the exec-server bootstrap path if the VS Code Server still needs to be downloaded on the remote.

[https://github.com/microsoft/vscode-remote-release/issues/11657](https://github.com/microsoft/vscode-remote-release/issues/11657)

## Summary

Keep open for the SSH owner to retest the first-install bootstrap timeout using the supplied steps and logs. One affected user reports success on VS Code 1.122, but that does not establish that the download-dependent failure is resolved.

## Change summary

Remote-SSH aborts Windows exec-server startup before the first-run server download finishes.

## Best solution

The SSH component should allow first-run server download and initialization to finish before declaring Windows exec-server startup unsuccessful. Retest with the server absent rather than already cached to distinguish a genuine fix from a successful subsequent connection.

These May confirmations do not establish current-release reproduction.
