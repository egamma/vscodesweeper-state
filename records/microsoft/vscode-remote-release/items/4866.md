# Issue #4866 — SingleSignOn Federation

[https://github.com/microsoft/vscode-remote-release/issues/4866](https://github.com/microsoft/vscode-remote-release/issues/4866)

## Summary

Keep open: the current AWS-specific SSO paths do not satisfy the requested provider-neutral, secure token handoff for Remote - SSH. Because this involves exposing authentication tokens to SSH and ProxyCommand processes, it requires explicit security and ownership design by maintainers.

## Change summary

Provide an enterprise SSO flow that lets Remote - SSH use federated identity for cloud-backed SSH connections without manually storing OIDC tokens or private keys.

## Best solution

Remote - SSH should define a provider-neutral, secure credential-broker integration with VS Code authentication providers, while AWS, Google, and other provider extensions own their token acquisition and exchange logic. Raw tokens should not be placed in broadly accessible files or environment variables without a reviewed security model.

## Evidence

- **demonstrated gap:** The reporter demonstrated AWS SSM ProxyCommand access using an Azure AD OIDC token stored manually in C:\temp, but the central request is to eliminate that unsupported and error-prone token handling.
- **maintainer assessment:** https://github.com/microsoft/vscode-remote-release/issues/4866#issuecomment-826469335 identifies a possible integration between VS Code authentication providers and Remote - SSH, while explicitly noting unresolved safety and implementation implications.
- **current AWS capability:** AWS CLI documentation at https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html supports IAM Identity Center profiles federated through providers such as Azure AD, but this is an AWS-specific CLI flow rather than the requested cloud-neutral VS Code token handoff.
- **related implementation:** AWS Toolkit 3.39.0 added EC2 connection commands using Remote - SSH, documented in https://github.com/aws/aws-toolkit-vscode/issues/941#issuecomment-2539726009, but that does not cover the broader Azure AD/OIDC federation interface requested here.
- **security sensitivity:** The proposed design would make identity tokens available to spawned SSH or ProxyCommand processes; the thread itself flags token exposure as requiring careful security analysis.
