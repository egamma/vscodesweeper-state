# Issue #986 — Remote extension installation ignores proxy settings 

[https://github.com/microsoft/vscode-remote-release/issues/986](https://github.com/microsoft/vscode-remote-release/issues/986)

## Summary

This remains the canonical request for remote extension-installation paths to honor proxy and certificate configuration consistently. Route it to Dev Containers and extension installation; current documentation still acknowledges incomplete CLI proxy support.

## Change summary

Make automatic remote extension installation use the same proxy and trusted-certificate configuration as installation through the VS Code UI.

## Best solution

The Dev Containers bootstrap and remote extension-installation CLI should consistently inherit supported proxy settings and system certificates without requiring insecure TLS overrides. Keep this issue as the canonical tracker while consolidating narrower container and SSH reports into it.

- **Reason:** Consistent extension installation across local and remote environments directly advances remote-development parity and connection diagnosability.
- **Evidence:** The public product promise is to let users open remote folders and retain VS Code's full feature set; reliable server lifecycle and diagnosability are durable themes.
