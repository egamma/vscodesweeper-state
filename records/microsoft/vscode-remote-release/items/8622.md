# Issue #8622 — Allow workspace paths which only exist in devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/8622](https://github.com/microsoft/vscode-remote-release/issues/8622)

## Summary

Keep open: the request is to persistently suppress the absolute-path warning for a workspace with intentionally container-only folders. The documented mounting and workspace-opening capabilities do not establish that this warning can be disabled, and no same-symptom open canonical was verified.

## Change summary

Allow a workspace-level opt-in to reopen multi-root workspaces with container-only absolute paths without repeated warnings.

## Best solution

The Dev Containers component should provide an explicit, persistent opt-in for intentionally container-only workspace paths while retaining warnings by default. Opening the workspace after connecting is an alternative workflow, not equivalent to suppressing the warning in the reporter's existing workflow.

- **Fit:** aligned
- **Reason:** Reducing friction when opening container-only source trees supports full-featured remote development and dev container capability depth.
- **Evidence:** The public vision promises opening any folder in a container with VS Code's full feature set and identifies dev container capability depth as a durable theme.
