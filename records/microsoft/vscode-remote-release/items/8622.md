# Issue #8622 — Allow workspace paths which only exist in devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/8622](https://github.com/microsoft/vscode-remote-release/issues/8622)

## Summary

Verified duplicate: the open canonical issue tracks automatically opening a container-resident multi-root workspace, including the same multiple-named-volume scenario. That solution avoids opening container-only absolute paths locally and encountering this warning.

## Change summary

Allow a workspace to reference absolute paths that exist only through volumes mounted inside its dev container without showing a local-path warning.

## Best solution

Consolidate on https://github.com/microsoft/vscode-remote-release/issues/3665 and let Dev Containers select and open a configured `.code-workspace` after connecting, when its container-only paths are available.

## Vision fit

- **Fit:** aligned
- **Reason:** Supporting workspaces whose source trees live in container volumes advances the goal of providing a full local-quality development experience regardless of where the code is located.
- **Evidence:** The Dev Containers documentation states that the extension can open any folder inside or mounted into a container and provide a local-quality experience regardless of where the code is located: https://code.visualstudio.com/docs/devcontainers/containers
