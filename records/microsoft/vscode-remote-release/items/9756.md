[https://github.com/microsoft/vscode-remote-release/issues/9756](https://github.com/microsoft/vscode-remote-release/issues/9756)

## Summary

Keep open: the reopened issue tracks Dev Containers selecting an incompatible fallback runtime when reconnecting through an old SSH/container URI. Runtime selection improved after the report and Linux requirements have since changed, but the thread provides sufficient steps to retest and no confirmation that the remaining case was resolved.

## Change summary

Reconnecting to a container through a legacy Linux SSH host after updating VS Code can select a Node runtime requiring unavailable GLIBC versions.

## Best solution

The containers owner should retest the documented old-URI reconnection path and establish whether compatibility checking covers the fallback when Remote-SSH has not installed its runtime. Distinguish that selection defect from failures on hosts outside today's supported Linux requirements.
