# Issue #6561 — Support both container volume and bind mount workspaces with single docker-compose devcontainer config

[https://github.com/microsoft/vscode-remote-release/issues/6561](https://github.com/microsoft/vscode-remote-release/issues/6561)

## Summary

Keep this accepted Dev Containers request open: the parent-folder workaround supports the primary service, but does not deliver consistent workspace mounts across Compose services. A maintainer explicitly consolidated an earlier report here, and a newer report confirms the remaining limitation.

## Change summary

Support one Docker Compose devcontainer configuration for both local bind-mounted and cloned-volume workspaces, including access from additional services.

## Best solution

Dev Containers should provide supported workspace-source resolution or mount rewriting across Compose services without bootstrap-container introspection or separate configurations. Retain this issue as the broader tracking item and use the newer multi-service report to inform the design.

## Evidence

- **Regression fixed, feature still missing:** The reporter confirmed the working-directory regression was resolved in Remote-Containers 0.232.4, but separately asked for supported access to the workspace volume; a maintainer confirmed that was unsupported: https://github.com/microsoft/vscode-remote-release/issues/6561#issuecomment-1092980462 and https://github.com/microsoft/vscode-remote-release/issues/6561#issuecomment-1094663749.
- **Partial existing capability:** The maintainer's ../..:/workspaces mount with workspaceFolder=/workspaces/${localWorkspaceFolderBasename} supports both opening modes for the selected service: https://github.com/microsoft/vscode-remote-release/issues/6561#issuecomment-1514212696. It does not establish automatic sharing of the cloned volume with other services; the alternative of multiple devcontainer.json files also does not satisfy the single-configuration ask.
- **Documentation and specification check:** https://code.visualstudio.com/docs/devcontainers/create-dev-container#_use-docker-compose documents explicit Compose volumes for source mounting. https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md lists workspaceMount under image/Dockerfile properties, while Compose workspaceFolder selects the folder to open; neither documents automatic bind/volume switching across services.
- **Existing tracking ownership:** The earlier multi-service report was closed with a maintainer's explicit 'Continuing in' link to this issue: https://github.com/microsoft/vscode-remote-release/issues/5587#issuecomment-1853564094. - **Newer confirmation of remaining scope:** https://github.com/microsoft/vscode-remote-release/issues/10728 is open and reports missing workspace files in a second Compose service despite the primary service using the parent-folder workaround. A maintainer acknowledged the limitation and proposed bind-to-volume rewriting using Docker 26 subfolder support: https://github.com/microsoft/vscode-remote-release/issues/10728#issuecomment-2681499634. This newer, narrower report does not supersede the broader request.
