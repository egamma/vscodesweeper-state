# Issue #6561 — Support both container volume and bind mount workspaces with single docker-compose devcontainer config

[https://github.com/microsoft/vscode-remote-release/issues/6561](https://github.com/microsoft/vscode-remote-release/issues/6561)

## Summary

This remains a valid Dev Containers capability gap: current configuration can select a bind mount or named volume, but cannot dynamically expose the cloned workspace volume across Docker Compose services while retaining the same local-bind configuration.

## Change summary

Allow one Docker Compose dev-container configuration to work with both locally bind-mounted workspaces and repositories cloned into container volumes, including access from secondary services.

## Best solution

The Dev Containers component should provide a stable mechanism that maps the active workspace source into all requested Compose services regardless of whether it is a bind mount or cloned volume. Rewriting applicable bind mounts to volume-subfolder mounts, as discussed in the newer report, is one possible implementation.
