# Issue #7155 — devcontainer vscode settings not taking effect in remote container

[https://github.com/microsoft/vscode-remote-release/issues/7155](https://github.com/microsoft/vscode-remote-release/issues/7155)

## Summary

Keep open for the Containers component: persisted home volumes retain the marker that suppresses reapplying changed dev-container settings, and a maintainer identified the behavior and its compatibility tradeoff. The related installation-directory request does not cover this settings-reconciliation gap.

## Change summary

Reapply updated `customizations.vscode` settings after rebuilding a dev container whose home directory persists in a Docker volume.

## Best solution

The Dev Containers extension should reconcile configured defaults with persisted user customizations when a container is recreated, likely by recording container identity or creation time without overwriting subsequent user edits. The component owner should decide the merge semantics separately from the configurable installation-directory work.
