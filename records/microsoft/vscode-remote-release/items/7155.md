# Issue #7155 — devcontainer vscode settings not taking effect in remote container

[https://github.com/microsoft/vscode-remote-release/issues/7155](https://github.com/microsoft/vscode-remote-release/issues/7155)

## Summary

Keep open for a Dev Containers settings-refresh decision: persisting the home directory also preserves the initialization marker, preventing updated customizations from being applied after rebuilding. Configurable server placement is related work, not a canonical for this settings-refresh behavior.

## Change summary

Allow rebuilt dev containers to apply updated VS Code customization defaults when the server settings directory persists across container creation.

## Best solution

Dev Containers should define a refresh policy that recognizes a newly created container while preserving deliberate user settings changes, potentially through an explicit opt-in. Track configurable server placement separately in https://github.com/microsoft/vscode-remote-release/issues/6079.
