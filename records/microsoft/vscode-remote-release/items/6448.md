# Issue #6448 — Transfer environment from ssh session to new EH

[https://github.com/microsoft/vscode-remote-release/issues/6448](https://github.com/microsoft/vscode-remote-release/issues/6448)

## Summary

Keep open in the SSH Backlog: the maintainer confirmed that one server environment is shared per remote account, then explicitly classified this later request as a feature and suggested transferring selected variables to each new extension host.

## Change summary

Give each Remote - SSH extension host the environment of its initiating SSH session when several developers share one remote system account.

## Best solution

Remote - SSH should transfer an explicit, safely scoped set of environment variables from each initiating SSH connection to its new extension host, preventing one developer's values from leaking into another developer's session under a shared account.

## Vision fit

- **Fit:** aligned
- **Reason:** Per-connection environment fidelity closes a behavior gap between ordinary SSH sessions and Remote - SSH while preserving the existing client-server architecture.
- **Evidence:** The durable SSH theme calls for matching what plain SSH can do inside the extension's connection path, and the parity value says remote development should feel like local development.
