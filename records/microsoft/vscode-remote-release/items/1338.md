# Issue #1338 — Support Termux on Android/aarch64

[https://github.com/microsoft/vscode-remote-release/issues/1338](https://github.com/microsoft/vscode-remote-release/issues/1338)

## Summary

Keep this as the existing Termux support request. The February 2026 workaround demonstrates feasibility, but requires additional installation and script modifications and does not establish supported, automatic Remote - SSH operation.

## Change summary

Support connecting Remote - SSH to Android/aarch64 Termux hosts despite their different runtime libraries and filesystem layout.

## Best solution

The SSH and VS Code Server owners should evaluate a maintained Termux installation and startup path covering runtime compatibility, executable paths, and server updates. Use the reported glibc workaround as implementation context, not as proof that first-class support has shipped.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/1338 documents an existing aarch64 Node executable failing because it expects /lib/ld-linux-aarch64.so.1 rather than Android's /system/bin/linker64. Replacing Node exposed additional native-library and executable-path failures, so architecture support alone does not deliver the request.
- **Existing-capability check:** https://code.visualstudio.com/docs/remote/linux documents glibc-based ARM64 SSH hosts and server native-library prerequisites, not Termux support. https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions documents VSCODE_SERVER_CUSTOM_GLIBC_LINKER, VSCODE_SERVER_CUSTOM_GLIBC_PATH, and VSCODE_SERVER_PATCHELF_PATH, explicitly describing the sysroot approach as an unofficial technical workaround.
- **Workaround does not complete support:** The February 17, 2026 comment in https://github.com/microsoft/vscode-remote-release/issues/1338 reports success on three Android devices without root or proot. Its linked guide, https://turgenev.hatenablog.com/entry/2026/02/11/121330, additionally requires shebang rewriting and LD_PRELOAD handling and describes adjustments for changed server staging behavior. This is community-managed compatibility, not a maintainer-announced and reporter-confirmed product fix.
- **Canonical ownership:** https://github.com/microsoft/vscode-remote-release/issues/3769#issuecomment-720717834 explicitly closes the related Termux report because this issue already covers its request. The related issue is closed and therefore cannot be a duplicate target.
- **Canonical search:** Tracker searches for Termux and Android/bionic found no verified open canonical superseding this request. https://github.com/microsoft/vscode-remote-release/issues/103 is closed and concerns older Linux libraries; its linked diagnostic discussion does not establish delivery of Android/Termux support.
