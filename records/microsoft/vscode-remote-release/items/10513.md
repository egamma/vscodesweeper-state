# Issue #10513 — [Remote-SSH Bug]: First connection failing 50% of the time, and then retry works

[https://github.com/microsoft/vscode-remote-release/issues/10513](https://github.com/microsoft/vscode-remote-release/issues/10513)

## Summary

Keep open: the logs show a Remote-SSH startup race, and several independent users continued confirming the first-attempt failure through April 2026. Retry is a workaround, not resolution.

## Change summary

Remote-SSH intermittently reads an empty server-listening address on the first connection after idle time or reboot, while an immediate retry succeeds.

## Best solution

The SSH component should make the server-start handshake wait or retry until the CLI log contains a valid listening address. The fix should cover ordinary local filesystems as well as the related network-filesystem case.
