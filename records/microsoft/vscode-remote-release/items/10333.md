# Issue #10333 — `ignoreSync` for path settings element

[https://github.com/microsoft/vscode-remote-release/issues/10333](https://github.com/microsoft/vscode-remote-release/issues/10333)

## Summary

The current Dev Containers and Remote - SSH manifests still synchronize these machine-specific path settings by default. Keep this open and add SSH routing because the cleanup spans both extensions.

## Change summary

Exclude four local executable and configuration path settings from Settings Sync by default.

## Best solution

Dev Containers and Remote - SSH should retain application scope for these client-side settings while marking them `ignoreSync`, preventing paths from leaking between machines without changing remote-window placement semantics.

## Evidence

- **current extension metadata:** The current Marketplace manifests for https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers and https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh declare all four settings with application scope and no `ignoreSync` metadata.
- **scope semantics:** A VS Code maintainer explains at https://github.com/microsoft/vscode/issues/230047#issuecomment-2555512159 that machine-scoped settings are automatically excluded from sync, while non-machine settings require `ignoreSync`; https://github.com/microsoft/vscode/issues/230047#issuecomment-2574905098 further explains that machine scope changes where settings are configured in remote windows.
- **existing workaround:** https://code.visualstudio.com/docs/configure/settings-sync#_configuring-synced-data documents `settingsSync.ignoredSettings`, but requiring every user to list these paths manually does not provide the requested safe default.
