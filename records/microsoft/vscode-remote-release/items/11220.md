# Issue #11220 — Ripgrep pinned at 100% cpu when connecting to remote server.

[https://github.com/microsoft/vscode-remote-release/issues/11220](https://github.com/microsoft/vscode-remote-release/issues/11220)

## Summary

Multiple users report sustained ripgrep CPU saturation after opening large remote workspaces, including a recent confirmation. The existing workaround reduces scanning but does not resolve the underlying unbounded work, so this should remain open and be routed as an SSH file-watching performance issue.

## Change summary

Opening a large directory through Remote - SSH launches ripgrep scans that saturate the remote host for 10–15 minutes.

## Best solution

The SSH/VS Code Server owner should identify the subsystem launching ripgrep from its full command line and process tree, then ensure large remote workspaces honor exclusions and avoid unbounded startup scanning. `files.watchExclude` is a useful mitigation but should not be required to prevent severe CPU saturation.
