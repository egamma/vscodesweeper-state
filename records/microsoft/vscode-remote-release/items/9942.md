# Issue #9942 — Auto install local extensions (not on the marketplace) when connecting to a remote

[https://github.com/microsoft/vscode-remote-release/issues/9942](https://github.com/microsoft/vscode-remote-release/issues/9942)

## Summary

The requested behavior already exists through `remote.defaultExtensionsIfInstalledLocally`: current VS Code copies a locally installed extension to the remote when no Marketplace version is available. A recent commenter also confirmed this with an unpublished extension.

## Change summary

Automatically install a locally developed, unpublished extension when connecting to an SSH remote.

## Best solution

Use `remote.defaultExtensionsIfInstalledLocally` rather than `remote.SSH.defaultExtensions`; the existing installation path falls back to packaging and transferring the local extension when it has no Marketplace entry.

## Vision fit

- **Fit:** aligned
- **Reason:** Making locally available workspace extensions usable over SSH supports the goal of local-development feature parity in remote environments.
- **Evidence:** The Remote Development promise is to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
