# Issue #9454 — Preinstalled server+extensions environment for SSH hosts (similar to "offline"/airgapped host)

[https://github.com/microsoft/vscode-remote-release/issues/9454](https://github.com/microsoft/vscode-remote-release/issues/9454)

## Summary

Keep this accepted SSH feature request open: download fallbacks and manual staging do not fully deliver a reusable, preinstalled server-and-extensions environment. The team continues using this issue to track offline SSH needs.

## Change summary

Support preprovisioned SSH hosts containing the server and extensions, without downloading or installing them on connection, with explicit handling of incompatible client versions.

## Best solution

Remote - SSH should provide a supported way to discover and reuse preprovisioned server and extension assets, including when both endpoints are offline. Define compatibility checks and report incompatible versions explicitly rather than promising arbitrary older-server compatibility.

## Evidence

- **Distinct preinstallation requirement:** At https://github.com/microsoft/vscode-remote-release/issues/9454 the reporter distinguishes preinstallation from offline downloading and says remote.SSH.serverInstallPath still requires a client-commit-specific directory. The issue was reopened on 2024-02-21 after its proposed consolidation into https://github.com/microsoft/vscode-remote-release/issues/1242.
- **Existing capabilities are partial:** https://code.visualstudio.com/docs/remote/ssh documents remote.SSH.localServerDownload for downloading locally and transferring, Extensions: Install from VSIX... for manual offline installation, and remote.SSH.defaultExtensions for automatic installation. These do not document reuse of a complete preinstalled environment across client versions without connection-time installation.
- **Partial implementation, remaining work:** https://github.com/microsoft/vscode/pull/238815 merged on 2025-02-11 and proxies failed remote extension installations through a locally connected workbench; its description requires local Marketplace access. https://github.com/microsoft/vscode-remote-release/issues/9454#issuecomment-2675221843 explicitly identifies the remaining case where neither endpoint can download the matching server.
- **Workaround is version-specific:** https://github.com/microsoft/vscode-remote-release/issues/9454#issuecomment-2358513715 describes manually staging CLI and server packages for VS Code 1.93.0 under exact commit-specific paths. This helps offline setup but does not establish supported cross-version reuse or complete extension preprovisioning.
- **Project tracking direction:** https://github.com/microsoft/vscode-remote-release/issues/11133#issuecomment-3225734161 redirects another offline Remote-SSH request into this issue. https://github.com/microsoft/vscode-remote-release/issues/9454#issuecomment-2658133598 records its acceptance into Backlog after sufficient community support.
- **Canonical search:** Verified open https://github.com/microsoft/vscode-remote-release/issues/1399 concerns offline installation and server-package delivery, while https://github.com/microsoft/vscode-remote-release/issues/1718 concerns preinstallation in Dev Containers using devcontainer.json. Neither establishes ownership of the full SSH-host server-and-extensions reuse request; https://github.com/microsoft/vscode-remote-release/issues/9994 covers only extension-installation delegation.
