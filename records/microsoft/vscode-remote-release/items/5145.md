# Issue #5145 — Running VS Code server inside a genie bottle

[https://github.com/microsoft/vscode-remote-release/issues/5145](https://github.com/microsoft/vscode-remote-release/issues/5145)

## Summary

This accepted Backlog request is misrouted as containers work; it concerns how the WSL extension launches its server and should remain open with the WSL owner. Native WSL systemd reduces the genie-specific need, but the documented environment script still does not provide the requested process-launch wrapper.

## Change summary

Allow users to wrap or customize the WSL extension's server launch command so the server can start inside a required process namespace.

## Best solution

The WSL component should provide a supported, generic server-launch wrapper if process-namespace customization remains in scope, avoiding patches to extension-owned scripts. Native WSL systemd covers the common systemd requirement, so implementation should not be genie-specific.
