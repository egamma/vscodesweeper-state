# Issue #5145 — Running VS Code server inside a genie bottle

[https://github.com/microsoft/vscode-remote-release/issues/5145](https://github.com/microsoft/vscode-remote-release/issues/5145)

## Summary

Keep this accepted request open and correct its routing from containers to WSL. A maintainer explicitly consolidated the older report here; native WSL systemd support does not establish that the requested genie launch customization is delivered.

## Change summary

Allow the WSL extension to launch VS Code Server inside a genie PID namespace without repeatedly patching wslServer.sh.

## Best solution

The WSL component should provide a supported server-launch wrapper or equivalent namespace-entry mechanism that preserves client-managed server installation and version matching. Retain this issue as the canonical request and distinguish genie integration from native WSL systemd support.

## Evidence

- **Precise requested capability:** https://github.com/microsoft/vscode-remote-release/issues/5145#issuecomment-855586878 explains that the server launches outside genie's PID namespace and requests wrapping its launch with genie -c or inheriting the invoking code command's namespace. This is not merely a request to start a systemd service.
- **Confirmed canonical ownership:** https://github.com/microsoft/vscode-remote-release/issues/4381 is closed; a maintainer's December 2024 comment explicitly closes it in favor of this issue: https://github.com/microsoft/vscode-remote-release/issues/4381#issuecomment-2540175000. Searches for genie and WSL namespace, wrapper, systemd, and hook requests found no verified open replacement canonical.
- **Existing capability check:** https://code.visualstudio.com/docs/remote/wsl#_advanced-environment-setup-script documents ~/.vscode-server/server-env-setup for commands and environment changes before server startup, but does not document a server-launch wrapper or PID-namespace inheritance. The reporter explicitly distinguishes this setup hook from the requested launch customization.
- **Native systemd is an alternative, not proof of delivery:** https://learn.microsoft.com/en-us/windows/wsl/systemd documents native systemd support in WSL 0.67.6+ through [boot] systemd=true. This can remove the need for genie in some environments, but does not supply configurable genie -c launching for users retaining a bottle.
- **Workaround and acceptance:** The discussion at https://github.com/microsoft/vscode-remote-release/issues/5145 records patches breaking across WSL extension updates, including 0.66.0, rather than a supported fix. The request reached Backlog and has 55 upvotes. https://github.com/arkane-systems/genie/issues/172 documents the same patch workaround and closed without establishing a product implementation.
