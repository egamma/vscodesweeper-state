# Issue #7714 — Remote tunnels for all users in a GitHub organization

[https://github.com/microsoft/vscode-remote-release/issues/7714](https://github.com/microsoft/vscode-remote-release/issues/7714)

## Summary

This remains a well-supported backlog gap: the underlying Dev Tunnels service supports GitHub-organization ACLs, but the VS Code tunnel CLI does not expose them. Route it to the tunnels and CLI owners rather than closing it.

## Change summary

Allow a CI-created remote tunnel to grant access to members of specified GitHub organizations or teams, preferably locking the session to the first authorized user.

## Best solution

The tunnels/CLI implementation should expose a GitHub-organization access-control option backed by Dev Tunnels ACLs while preserving the VS Code Server's single-user model, such as locking each tunnel session to the first authorized organization member.

## Evidence

- **current VS Code behavior:** https://code.visualstudio.com/docs/remote/tunnels states that tunnel hosts and clients must authenticate with the same GitHub or Microsoft account and that a server instance supports only one user or client at a time.
- **available service capability:** https://learn.microsoft.com/azure/developer/dev-tunnels/security documents GitHub-organization access, while https://learn.microsoft.com/azure/developer/dev-tunnels/cli-commands#advanced-manage-dev-tunnel-access exposes it in the underlying service as `devtunnel access create TUNNELID --org ORG`.
- **missing CLI integration:** The current public `code tunnel` arguments in https://github.com/microsoft/vscode/blob/main/cli/src/commands/args.rs expose server, machine-name, authentication, and service options but no organization ACL option; https://github.com/microsoft/vscode/blob/main/cli/src/tunnels/dev_tunnels.rs currently constructs relevant access-control entries with `organization: None`.
- **maintainer assessment:** The issue discussion identifies Dev Tunnels ACL integration as the required stepping stone and proposes locking access to the first authorized user to avoid unsafe multi-user secret sharing; the reporter agreed with that design.
