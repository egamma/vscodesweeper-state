# Issue #7714 — Remote tunnels for all users in a GitHub organization

[https://github.com/microsoft/vscode-remote-release/issues/7714](https://github.com/microsoft/vscode-remote-release/issues/7714)

## Summary

This remains a well-supported backlog feature request: current tunnels require the same account at both ends and provide no GitHub organization or team ACL. Route it to the tunnels and CLI owners while retaining code-server involvement for the single-user security constraints.

## Change summary

Allow a CI-hosted remote tunnel to authorize members of specified GitHub organizations, teams, or repositories, potentially locking the session to the first authorized user.

## Best solution

The tunnels and CLI components should provide an organization-scoped ACL with first-user session locking, preserving the VS Code Server's single-user security model while enabling controlled CI debugging access.
