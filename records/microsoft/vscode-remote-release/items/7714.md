# Issue #7714 — Remote tunnels for all users in a GitHub organization

[https://github.com/microsoft/vscode-remote-release/issues/7714](https://github.com/microsoft/vscode-remote-release/issues/7714)

## Summary

Keep this accepted feature request open: documented tunnel access still requires the same account at both ends, rather than organization membership with first-user claiming. Maintainers explicitly track the broader access-control work here, and the thread's credential-exposure concern requires human security judgment.

## Change summary

Allow eligible GitHub organization or team members to claim a CI-created remote tunnel, locking access to the first connecting user.

## Best solution

The CLI, tunnels, and VS Code Server owners should evaluate organization-scoped authorization with the reporter-approved first-user lock, defining how subsequent connections and remote extension credentials remain isolated. Retain this issue as the existing access-control tracking venue rather than redirecting it to a narrower report.
