# Issue #8965 — Can't specify platform for Docker image in DevContainers

[https://github.com/microsoft/vscode-remote-release/issues/8965](https://github.com/microsoft/vscode-remote-release/issues/8965)

## Summary

Keep open as the strongest canonical report for a confirmed Dev Containers platform-selection bug: the extension pulls the Dockerfile base image for the host architecture before honoring its explicit amd64 platform.

## Change summary

Honor the requested Docker platform when inspecting and pulling a cross-architecture Dockerfile base image.

## Best solution

Dev Containers should propagate the Dockerfile or build platform to its preliminary image inspection and pull operations. Related reports https://github.com/microsoft/vscode-remote-release/issues/8737 and https://github.com/microsoft/vscode-remote-release/issues/9115 should consolidate here because this issue has maintainer confirmation, a documented workaround, and stronger community signal.

## Evidence

- **maintainer reproduction:** A team member confirmed observing the issue at https://github.com/microsoft/vscode-remote-release/issues/8965#issuecomment-1750537070.
- **root cause and workaround:** A maintainer explained that runArgs only affect container startup and confirmed that pre-pulling with `docker pull --platform=linux/amd64` works around the extension's architecture-blind pull: https://github.com/microsoft/vscode-remote-release/issues/8965#issuecomment-2513778824.
- **current capability gap:** The current Dev Container specification documents `build.options` as options for the Docker build command and `runArgs` as options for the run command, but provides no image-platform property governing the extension's preliminary pull: https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md.
- **related reports:** Open issues https://github.com/microsoft/vscode-remote-release/issues/8737 and https://github.com/microsoft/vscode-remote-release/issues/9115 show the same cross-architecture inspect/pull failure; this report is the better canonical because it has direct maintainer confirmation, 17 upvotes, and a Backlog milestone.
