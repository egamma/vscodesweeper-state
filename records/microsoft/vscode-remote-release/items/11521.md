# Issue #11521 — Angular port forwarding hangs

[https://github.com/microsoft/vscode-remote-release/issues/11521](https://github.com/microsoft/vscode-remote-release/issues/11521)

## Summary

The failure was reproduced by multiple users and isolated to forwarded ports not reaching Angular when localhost resolves to IPv6. The IPv4 workaround restores access but does not resolve the underlying Dev Containers forwarding gap.

## Change summary

An Angular development server using its default localhost binding cannot be reached through an automatically or explicitly forwarded Dev Container port.

## Best solution

Dev Containers port forwarding should reach services bound through either IPv4 or IPv6 localhost resolution and promptly surface connection failures instead of leaving browser requests pending.

## Evidence

- **independent reproduction:** The reporter and another affected user reproduced the failure with Angular running inside a Dev Container; the original report includes current Insiders and Dev Containers extension versions.
- **confirmed workaround:** https://github.com/microsoft/vscode-remote-release/issues/11521#issuecomment-4514517737 confirms that binding Angular explicitly with `ng s --host 127.0.0.1` makes the forwarded application reachable; another affected user confirmed the same result.
- **IPv6 diagnosis:** https://github.com/microsoft/vscode-remote-release/issues/11521#issuecomment-4514895538 shows localhost resolving to `::1` and reports that removing the IPv6 localhost mapping also restores forwarding, narrowing the failure to address-family handling.
- **canonical distinction:** https://github.com/microsoft/vscode-remote-release/issues/11614 tracks failure to close a forwarded client socket after ECONNREFUSED, but it does not own this report's separate inability to reach a service listening through IPv6 localhost.
