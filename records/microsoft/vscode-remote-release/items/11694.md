# Issue #11694 — Support WSL "native" container runtime

[https://github.com/microsoft/vscode-remote-release/issues/11694](https://github.com/microsoft/vscode-remote-release/issues/11694)

## Summary

Basic WSLC support now exists in the Dev Containers pre-release through the Docker Path setting, but important workflows remain unsupported. Keep this open as the broader feature request and route it to the Dev Containers owner.

## Change summary

Support Microsoft's native WSL container runtime as a Dev Containers backend without requiring Docker Desktop or Podman.

## Best solution

The Dev Containers extension should graduate its WSLC integration to stable support and document the supported workflow, while resolving runtime-specific gaps such as WSL-filesystem projects and BuildKit-dependent features in their focused issues.

## Evidence

- **runtime status:** https://learn.microsoft.com/en-us/windows/wsl/wsl-container documents `wslc.exe` as the native WSL container CLI and states that the required WSL 2.9.3 version remains pre-release.
- **remaining extension gap:** https://github.com/microsoft/vscode-remote-release/issues/11750 remains open for Dev Containers failing when a WSLC-backed project resides on the WSL filesystem, while the equivalent Windows-filesystem workflow succeeds.
- **remaining BuildKit gap:** https://github.com/microsoft/vscode-remote-release/issues/6856 remains open; a maintainer confirmed that the Dev Containers extension does not expose the CLI option for disabling BuildKit, which limits WSLC configurations using features.
