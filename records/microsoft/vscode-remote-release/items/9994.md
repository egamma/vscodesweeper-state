# Issue #9994 — Introduce new remote server flag to always redirect default extension installation to workbench

[https://github.com/microsoft/vscode-remote-release/issues/9994](https://github.com/microsoft/vscode-remote-release/issues/9994)

## Summary

A real gap remains: the shipped fallback retries locally only after remote installation fails, while this team-authored request asks to bypass remote installation entirely. The issue remains the canonical tracker for that capability.

## Change summary

Add a remote-server flag that directs default-extension installation through the local workbench instead of first attempting it on the remote host.

## Best solution

The VS Code server/CLI should expose an explicit always-install-locally mode that Remote - SSH and Dev Containers can select before connection, avoiding remote marketplace attempts and their possible timeouts in restricted networks.

- **Reason:** Avoiding unnecessary remote downloads improves server startup reliability and support for constrained or air-gapped environments.
