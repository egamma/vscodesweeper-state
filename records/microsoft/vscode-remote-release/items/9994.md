# Issue #9994 — Introduce new remote server flag to always redirect default extension installation to workbench

[https://github.com/microsoft/vscode-remote-release/issues/9994](https://github.com/microsoft/vscode-remote-release/issues/9994)

## Summary

Keep open: the shipped fallback retries failed server-side extension installations through the workbench, but does not proactively bypass remote installation attempts. The dedicated flag proposal was closed without merging, and maintainers continue to use this issue to track the remaining capability.

## Change summary

Allow remote server startup to defer default extension installation to the local workbench without first attempting downloads on the remote.

## Best solution

Provide an explicit server option to hand startup extension requests directly to the workbench, and wire Dev Containers and Remote - SSH to use it where appropriate. Preserve the existing failure fallback for other configurations.
