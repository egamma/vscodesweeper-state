- **Reported trigger and affected path:** https://github.com/microsoft/vscode-remote-release/issues/11689 describes correctly displayed Chinese becoming mojibake when copied from OpenCode's TUI on VS Code 1.123.0; ordinary shell output copies correctly. The linked discussion at https://github.com/anomalyco/opencode/issues/30068#issuecomment-4639641252 reproduces the same corruption with raw OSC 52 outside OpenCode, identifying the integrated terminal clipboard path rather than container locale.
- **Public fix and exact behavior change:** https://github.com/microsoft/vscode/commit/4b47f077e45ed0923c948ea53d717021f206e72a updates package.json's @xterm/addon-clipboard dependency from 0.3.0-beta.220 to 0.3.0-beta.285. The included upstream fix https://github.com/xtermjs/xterm.js/pull/6002 changes addons/addon-clipboard/src/ClipboardAddon.ts Base64.decodeText from returning atob(data)'s binary string to decoding base64 bytes through TextDecoder. This preserves Chinese Unicode characters when the TUI writes OSC 52 clipboard content through VS Code's local integrated terminal, including remote-container terminals.
- **Maintainer-confirmed release:** https://github.com/microsoft/vscode/issues/319821#issuecomment-4692259980 explicitly identifies the same VS Code commit and upstream fix and announces delivery in VS Code 1.125. The core issue is closed, so it is resolution evidence, not an open duplicate target.
- **Reporter-confirmed resolution:** https://github.com/microsoft/vscode-remote-release/issues/11689#issuecomment-4761291659 confirms on June 21 that copying Chinese from OpenCode in the remote/dev-container environment now works correctly with VS Code 1.125.1 and Dev Containers 0.459.1.
