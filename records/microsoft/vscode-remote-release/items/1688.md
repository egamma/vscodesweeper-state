# Issue #1688 — Save as admin option.

[https://github.com/microsoft/vscode-remote-release/issues/1688](https://github.com/microsoft/vscode-remote-release/issues/1688)

## Summary

This remote-specific request is a verified duplicate of the open VS Code core issue that owns elevated writes for FileSystemProvider-backed files. The documented sudoedit workaround does not provide the requested native Explorer and save flow.

## Change summary

Allow users in SSH, WSL, and container workspaces to browse and save protected files through temporary privilege elevation.

## Best solution

Implement elevated writes in VS Code's shared FileSystemProvider/file-service layer and have remote workspaces consume that support. Consolidate the cross-transport requirements on https://github.com/microsoft/vscode/issues/48659.

## Vision fit

- **Fit:** aligned
- **Reason:** Providing local-style elevated saves in remote workspaces advances the stated goal of feature parity between local and remote development.
- **Evidence:** The product promise is to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
