# Issue #1688 — Save as admin option.

[https://github.com/microsoft/vscode-remote-release/issues/1688](https://github.com/microsoft/vscode-remote-release/issues/1688)

## Summary

The native capability remains missing across remote file-system providers; the sudoedit workaround does not provide Explorer-based elevated saves and has a recent failure report. Keep this as the remote-facing tracker and route it to file I/O.

## Change summary

Allow users connected through Remote Development to save protected files through a temporary, explicitly authorized elevation rather than running the remote session as root.

## Best solution

Coordinate with https://github.com/microsoft/vscode/issues/48659 to add an elevated-write mechanism for FileSystemProvider, then support that mechanism across the SSH, WSL, and container remote file systems without elevating the entire VS Code Server process.

## Vision fit

- **Fit:** aligned
- **Reason:** Providing the local Save as Admin experience through remote file systems closes a clear local-versus-remote parity gap.
- **Evidence:** The public product promise is to let users open remote folders and take advantage of VS Code's full feature set; elevated saving already exists for applicable local files but is unavailable through remote FileSystemProvider implementations.
