# Issue #7917 — Error Clone in Volume with private image

[https://github.com/microsoft/vscode-remote-release/issues/7917](https://github.com/microsoft/vscode-remote-release/issues/7917)

## Summary

Keep open as diagnostic polish rather than a private-image bug: authentication and image retrieval succeeded, but the BusyBox image lacks the runtime prerequisites for VS Code Server. The remaining gap is detecting this unsupported environment and presenting a clear error.

## Change summary

Clone Repository in Container Volume reports an opaque server-start failure when the selected private image is based on BusyBox.

## Best solution

Dev Containers should detect that a BusyBox-based container cannot satisfy VS Code Server prerequisites and report the unsupported environment clearly, while preserving the working private-registry authentication flow.
