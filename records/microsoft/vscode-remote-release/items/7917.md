# Issue #7917 — Error Clone in Volume with private image

[https://github.com/microsoft/vscode-remote-release/issues/7917](https://github.com/microsoft/vscode-remote-release/issues/7917)

## Summary

Keep open: the thread identifies missing runtime dependencies in BusyBox images, not failed private-registry authentication. A maintainer proposed detecting this unsupported environment and explaining the failure; no confirmed implementation or eligible duplicate was found.

## Change summary

Cloning into a container volume successfully retrieves a private BusyBox-based image but fails when starting the VS Code Server.

## Best solution

The image must provide the VS Code Server's documented runtime dependencies. Dev Containers should retain the maintainer-proposed diagnostic work: identify incompatible minimal images and explain the missing prerequisites rather than implying a registry problem.
