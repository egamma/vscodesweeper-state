# Issue #6608 — Document the security model of VSCode Remote Development

[https://github.com/microsoft/vscode-remote-release/issues/6608](https://github.com/microsoft/vscode-remote-release/issues/6608)

## Summary

Keep open for human security review: current documentation explains remote extensions' access to client resources, but does not fully consolidate the compromised-server threat model, credential sharing, and sandbox limitations requested here. The security-sensitive keep-open rule applies.

## Change summary

Document Remote Development's client-server trust boundary, local resource exposure, and the protections and limitations of Restricted Mode and sandboxing.

## Best solution

The Remote Development owners should publish a discoverable security-model guide spanning SSH and Dev Containers, building on the existing API and credential-sharing documentation. Explicitly distinguish trusting workspace contents from trusting the server, and describe supported mitigations without promising isolation that the product does not provide.

## Evidence

- **Established trust boundary:** https://github.com/microsoft/vscode-remote-release/issues/6608#issuecomment-1112960548 states that the server and client share a trust boundary, users should connect only to trusted servers, and dev containers should not be used as a sandbox. This answers part of the question but is not a consolidated security guide.
- **Existing capability documentation:** https://code.visualstudio.com/api/advanced-topics/remote-extensions#execution-location-and-access-to-client-resources explicitly states that remote workspace extensions are not isolated from client resources. It distinguishes remote Node execution from client-routed filesystem, clipboard, command, and webview operations, substantially addressing the execution-location questions without fully documenting a malicious server's threat model.
- **Restricted Mode limitations:** https://code.visualstudio.com/docs/editing/workspaces/workspace-trust describes restrictions on automatic workspace-code execution and warns that Workspace Trust cannot prevent a malicious extension from executing code. It does not establish Restricted Mode as protection against an attacker-controlled VS Code Server.
- **Credential sharing is documented but remains relevant:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents automatic .gitconfig copying, credential-helper reuse, SSH-agent forwarding, and GPG sharing. https://github.com/microsoft/vscode-remote-release/issues/6608#issuecomment-1120775595 says forwarding follows folder trust; the requested clarification concerns the security implications and limits of that trust decision, not merely setup instructions.
