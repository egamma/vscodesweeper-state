[https://github.com/microsoft/vscode-remote-release/issues/10386](https://github.com/microsoft/vscode-remote-release/issues/10386)

## Summary

Keep open: later Podman improvements do not establish that the bootstrap container honors the selected CLI. The supplied steps and log suffice to retest the specific Docker rejection of --userns keep-id.

## Change summary

Cloning into a container volume uses Docker inside the bootstrap container despite Podman settings, causing Podman-specific user-namespace arguments to fail.

## Best solution

The Dev Containers owner should preserve Podman-compatible execution through bootstrap and recovery workflows, including user-namespace options. Retest the supplied volume-cloning scenario before treating general Podman permission improvements as resolving this defect.
