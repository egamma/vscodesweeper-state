# Issue #10386 — Bootstrap container not compatible with podman (desktop).

[https://github.com/microsoft/vscode-remote-release/issues/10386](https://github.com/microsoft/vscode-remote-release/issues/10386)

## Summary

The 2024 log clearly demonstrates the bootstrap path invoking Docker against Podman, but no current-release reproduction confirms that the failure remains after subsequent Podman compatibility improvements. A focused retest is needed.

## Change summary

Clone Repository in Container Volume fails with rootless Podman because the bootstrap container invokes Docker with Podman-only `--userns keep-id` arguments.

## Best solution

The Dev Containers bootstrap and recovery paths should honor the configured Podman CLI throughout container creation rather than passing Podman-specific arguments through Docker. Confirm this workflow on current releases before deciding whether further containers-component work remains.
