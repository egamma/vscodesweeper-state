# Issue #4897 — Clone Repo in Container Volume: Generic clone command

[https://github.com/microsoft/vscode-remote-release/issues/4897](https://github.com/microsoft/vscode-remote-release/issues/4897)

## Summary

Keep open: documented branch selection and lifecycle hooks do not cover arbitrary clone options or bootstrapping a .devcontainer stored in a submodule. No verified open canonical owns the full request, and the Backlog milestone does not justify declining it.

## Change summary

Allow users to customize the Git clone command used by Clone Repository in Container Volume, including recursive and single-branch cloning.

## Best solution

The Dev Containers extension should provide an advanced clone-options surface before configuration discovery, covering recursive submodules and single-branch cloning while retaining the existing URL workflow.

## Evidence

- **Remaining product requirement:** https://github.com/microsoft/vscode-remote-release/issues/4897 requests customizable clone commands, not only branch selection. Its September 2024 comment explains that initializeCommand cannot supply the workaround when .devcontainer itself is a submodule.
- **Existing capability check:** https://code.visualstudio.com/docs/devcontainers/containers documents Clone Repository in Container Volume accepting repository identifiers, Git URIs, GitHub branch URLs, and PR URLs. Selecting a branch does not establish support for --single-branch or arbitrary clone arguments.
- **Lifecycle workaround boundary:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md defines initializeCommand as a command configured in devcontainer.json that runs during initialization. It can initialize submodules once configuration is available, but does not supply a clone-command override before discovering configuration stored in an uninitialized submodule.
- **Related closed requests:** https://github.com/microsoft/vscode-remote-release/issues/6890 and https://github.com/microsoft/vscode-remote-release/issues/8258 request recursive cloning only; both were closed for insufficient candidate upvotes, not a shipped fix. Neither is an open canonical or a full-scope technical decline precedent.
