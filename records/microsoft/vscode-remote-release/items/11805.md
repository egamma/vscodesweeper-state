# Issue #11805 — Remote-SSH Bug: reconnect forfeits its 3-hour grace on the first attempt when a managed socket closes mid-connect

[https://github.com/microsoft/vscode-remote-release/issues/11805](https://github.com/microsoft/vscode-remote-release/issues/11805)

## Summary

Keep open: the supplied outage steps, versions, and correlated logs suffice to retest premature reconnect abandonment, including the silently disconnected extension host. Later reports use newer releases but different failure paths; they neither confirm resolution nor establish a canonical duplicate for this managed-socket failure.

## Change summary

Remote-SSH permanently abandons reconnection after a transient managed-socket close, despite announcing a three-hour grace period, sometimes leaving the remote extension host unavailable without a prompt.

## Best solution

The SSH owner should retest the documented outage sequence and ensure transient managed-socket connection failures remain retryable within the grace period, while preserving genuinely permanent failures. Coordinate with the VS Code core reconnect owner as needed and ensure terminal extension-host disconnection is surfaced to the user.
