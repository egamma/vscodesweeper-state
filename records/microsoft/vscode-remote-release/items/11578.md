# Issue #11578 — Feature Request: Make Remote-SSH server start timeout configurable on Windows

[https://github.com/microsoft/vscode-remote-release/issues/11578](https://github.com/microsoft/vscode-remote-release/issues/11578)

## Summary

A real Remote - SSH configuration gap remains for slow Windows server startup in endpoint-protected environments. The documented settings do not expose this readiness timeout, and the related download-timeout issue does not cover the pre-deployed-server scenario.

## Change summary

Allow users to increase the Remote - SSH exec-server startup/readiness timeout for Windows hosts.

## Best solution

The Remote - SSH owner should make the Windows exec-server readiness timeout configurable per user or host, or replace the fixed short wait with adaptive readiness handling that accommodates delayed first execution without changing the normal connection path.

## Vision fit

- **Fit:** aligned
- **Reason:** Accommodating delayed server startup on a supported Windows SSH host advances the project's connection-reliability and server-lifecycle themes.
- **Evidence:** The public Remote - SSH documentation lists Windows Server as supported and describes Remote development as providing a local-quality experience regardless of where code is hosted: https://code.visualstudio.com/docs/remote/ssh
