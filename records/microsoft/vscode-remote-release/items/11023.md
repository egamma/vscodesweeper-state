# Issue #11023 — .gitconfig not copied if dev container action creates a .gitconfig

[https://github.com/microsoft/vscode-remote-release/issues/11023](https://github.com/microsoft/vscode-remote-release/issues/11023)

## Summary

Keep open: the linked merged PR corrects documentation, but does not change Git configuration copying for the supplied postCreateCommand reproduction. The report contains sufficient configuration, versions, and observed output to retest; no current-release resolution is established.

## Change summary

Creating a container .gitconfig in postCreateCommand prevents the host's Git name and email from being copied into the container.

## Best solution

The Dev Containers owner should explicitly document the copy ordering and existing-file exception, and decide whether lifecycle-created configuration should coexist with imported host identity without overwriting container settings. The corrected common-utils advice addresses one workaround, not the extension behavior reported here.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11023 supplies a minimal javascript-node devcontainer.json with postCreateCommand running git config --global codespaces-theme.hide-status 1. On Dev Containers 0.417.0 / VS Code 1.100.3, the resulting .gitconfig contains that setting and the credential helper but lacks the host identity.
- **Workaround, not confirmed fix:** In https://github.com/microsoft/vscode-remote-release/issues/11023, the maintainer suggested postStartCommand on June 18, 2025, and the reporter confirmed that alternative avoids the issue. This does not establish that the original postCreateCommand scenario was fixed.
- **Merged PR scope:** https://github.com/devcontainers/features/pull/1391 references this issue and merged on December 12, 2025. Its entire diff changes src/common-utils/README.md advice from postCreateCommand to postStartCommand; it changes neither extension copy behavior nor the reporter's supplied configuration.
- **Documented promise and known exception:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials says the local .gitconfig is automatically copied on startup. https://github.com/microsoft/vscode-remote-release/issues/4632#issuecomment-1495924470 explains that copying occurs after postCreateCommand and dotfiles installation and is skipped if either creates .gitconfig. The public guide does not explain that exception.
- **Canonical search:** Verified open https://github.com/microsoft/vscode-remote-release/issues/4632 discusses broader configuration controls and this ordering exception, but does not clearly own correcting this lifecycle scenario. https://github.com/microsoft/vscode-remote-release/issues/4722 concerns copying before dotfiles installation, while https://github.com/microsoft/vscode-remote-release/issues/11869 concerns copy errors aborting later hooks; neither establishes a canonical covering the full reported behavior.
