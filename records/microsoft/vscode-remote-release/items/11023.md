# Issue #11023 — .gitconfig not copied if dev container action creates a .gitconfig

[https://github.com/microsoft/vscode-remote-release/issues/11023](https://github.com/microsoft/vscode-remote-release/issues/11023)

## Summary

The extension intentionally preserves an existing container `.gitconfig`; `postCreateCommand` runs before host configuration copying, while `postStartCommand` runs afterward. The misleading common-utils guidance was corrected in a merged public PR.

## Change summary

Copy the host `.gitconfig` even when `postCreateCommand` has already created a container `.gitconfig`.

## Best solution

Keep the non-overwriting behavior and use `postStartCommand` for commands that modify global Git configuration after the host configuration is copied. The common-utils documentation now recommends that ordering.
