# Issue #6897 — Use hosts from `portsAttributes` to detect when a port should be forwarded

[https://github.com/microsoft/vscode-remote-release/issues/6897](https://github.com/microsoft/vscode-remote-release/issues/6897)

## Summary

Keep open: this team-authored On Deck request remains the canonical gap for recognizing configured non-localhost hosts across automatic forwarding and link-opening paths. Current documentation permits `host:port` keys in `portsAttributes`, but does not establish that these detection paths honor them.

## Change summary

Use hostnames configured in `portsAttributes` when deciding whether URLs from terminals, debugging, terminal links, or `openExternal` require port forwarding.

## Best solution

The remote port-forwarding owner should apply configured `portsAttributes` hostnames consistently across terminal output, debug output, terminal links, and `openExternal`, so Docker Compose service URLs such as `http://db:5432` resolve through the existing tunnel.
