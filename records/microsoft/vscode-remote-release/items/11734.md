# Issue #11734 — Remote SSH: server shuts down after reconnect due to hardcoded 5-minute extension host timer triggered by IPC failure

[https://github.com/microsoft/vscode-remote-release/issues/11734](https://github.com/microsoft/vscode-remote-release/issues/11734)

## Summary

The logs show a credible Remote - SSH server termination after reconnect, but the proposed SIGPIPE/timer root cause has only one reporter and no team or independent confirmation. Requesting a current-version retest and complete logs before routing this as a confirmed server reconnect defect.

## Change summary

Recover from stale extension-host IPC after a long Remote - SSH disconnection instead of terminating the extension host and server shortly after reconnection.

## Best solution

The VS Code Server reconnect path should replace an extension host whose IPC channel has failed rather than allowing the short grace timer to terminate the resumed session. The SSH/server owner needs complete current-release logs to confirm that SIGPIPE precedes this lifecycle consistently.
