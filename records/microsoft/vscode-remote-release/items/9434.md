The report contains useful reproduction steps and a failure log, but only demonstrates the bug on January 2024 releases and has no current confirmation. A retest is needed before the Containers team can determine whether this filename-specific failure remains.

## Change summary

Reopening a remote multi-root workspace in a Dev Container fails with `spawn ENOTDIR` when the workspace file is named exactly `.code-workspace`.

## Best solution

The Dev Containers extension should treat `.code-workspace` as a workspace file rather than a directory when constructing the remote container launch context. First confirm the behavior on current VS Code, Dev Containers, and Remote - SSH releases and collect a current Dev Containers log.
