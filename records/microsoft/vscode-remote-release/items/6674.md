# Issue #6674 — NixOS-WSL Issues with Remote WSL Extension

[https://github.com/microsoft/vscode-remote-release/issues/6674](https://github.com/microsoft/vscode-remote-release/issues/6674)

## Summary

A real NixOS compatibility gap remains: the VS Code Server cannot run as-is on NixOS-WSL without configuring nix-ld or patching its bundled Node.js binary. The request is already correctly classified in the Backlog and has no verified canonical issue.

## Change summary

Support launching the VS Code Server on NixOS-WSL without requiring users to replace or patch its bundled Node.js executable.

## Best solution

The WSL and VS Code Server components should detect non-FHS NixOS environments and use a compatible server-launch strategy, or explicitly document the support boundary. Existing nix-ld and Node replacement instructions are environment workarounds rather than native coverage of the request.

## Evidence

- **current compatibility guidance:** The current NixOS-WSL guide at https://github.com/nix-community/NixOS-WSL/blob/main/docs/src/how-to/vscode.md states that the VS Code Remote server cannot run as-is because its Node.js binary expects /lib64/ld-linux-x86-64.so.2; it recommends either enabling nix-ld or patching the server.
- **documented support boundary:** https://code.visualstudio.com/docs/remote/linux explains that server prerequisites are driven by the bundled Node.js runtime, lists known-working distributions without NixOS, and describes non-standard Linux configurations as community-supported.
- **reported failure:** The issue log shows the downloaded server's node executable failing with 'No such file or directory'; https://github.com/microsoft/vscode-remote-release/issues/6674#issuecomment-1341741223 confirms that installing nixos-vscode-server is only a workaround.
