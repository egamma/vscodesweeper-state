# Issue #7319 — Latest version of Remote Containers causes an error when building my devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/7319](https://github.com/microsoft/vscode-remote-release/issues/7319)

## Summary

Keep open as a confirmed Dev Containers build regression. Multiple users reproduced the misleading missing-target failure, and maintainers classified and retained it as a container bug in the Backlog.

## Change summary

Dev Containers fails with a missing generated target-stage error when its appended Dockerfile stage follows a trailing continuation character in the user's Dockerfile.

## Best solution

Dev Containers should detect a dangling Dockerfile continuation before appending its generated stage and report the malformed instruction directly, rather than failing with the unrelated-looking `dev_containers_target_stage` error.

## Evidence

- **confirmed reproduction:** Several users reproduced the same `dev_containers_target_stage could not be found` failure, including https://github.com/microsoft/vscode-remote-release/issues/7319#issuecomment-1304229656, and confirmed that removing the final Dockerfile continuation character restores the build.
- **root cause:** The generated Dockerfile shown in the thread appends the extension's target stage immediately after a user `RUN` instruction ending in `\`, causing the appended `FROM` line to be consumed as a continuation rather than parsed as a new stage.
- **maintainer disposition:** A maintainer changed the issue from `info-needed` to `bug`, scheduled it for January 2023, then retained it in On Deck and ultimately Backlog on 2026-04-13; it is already correctly routed to `containers`.
