# Issue #5547 — Fail fast when `devcontainer.json` uses unsupported variables

[https://github.com/microsoft/vscode-remote-release/issues/5547](https://github.com/microsoft/vscode-remote-release/issues/5547)

## Summary

A real diagnostics gap remains: clone-in-volume workflows can pass unavailable workspace variables through to Docker, producing an unrelated-looking volume-name error. The issue is already correctly routed to Dev Containers and volumes.

## Change summary

Detect unavailable devcontainer.json variables before invoking Docker and report a clear configuration error.

## Best solution

The Dev Containers extension should validate context-dependent variables before container creation and identify the unsupported variable and clone-in-volume context. Where a stable volume identifier is intended, the diagnostic can suggest `${devcontainerId}` without treating it as complete coverage of every local-path use.

- **current documentation:** https://code.visualstudio.com/docs/devcontainers/containers#_variables-in-devcontainerjson defines `${localWorkspaceFolder}` as the path of the locally opened folder, which is unavailable when the repository exists only inside a container volume.
