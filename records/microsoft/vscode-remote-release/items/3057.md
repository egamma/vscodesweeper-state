# Issue #3057 — RunArgs for docker-compose 

[https://github.com/microsoft/vscode-remote-release/issues/3057](https://github.com/microsoft/vscode-remote-release/issues/3057)

## Summary

A real capability gap remains: the current Dev Container specification supports `runArgs` only for non-Compose containers. Manually starting Compose provides a workaround but does not provide persistent launch arguments.

## Change summary

Allow Dev Containers using Docker Compose to pass arguments such as `--force-recreate` or `--renew-anon-volumes` to `docker compose up`.

## Best solution

Define Compose launch arguments in the public Dev Container specification, then implement them consistently in the Dev Containers extension and reference CLI. Until then, document manually starting the services with the required flags before reopening the folder.

  > Thanks for the request. The current Dev Container schema still limits `runArgs` to image/Dockerfile configurations and has no Docker Compose equivalent. As a workaround, you can run `docker compose up` manually with `--force-recreate` or `--renew-anon-volumes` before reopening the folder; Dev Containers will attach to the already-running service. A durable solution should be defined in the public Dev Container specification at https://github.com/devcontainers/spec so supporting tools can implement it consistently.

## Evidence

- **current specification gap:** At https://github.com/devcontainers/spec/blob/c95ffeed1d059abfe9ffbe79762dc2fa4e7c2421/schemas/devContainer.base.schema.json, `runArgs` belongs to `nonComposeBase`; `composeContainer` exposes `dockerComposeFile`, `service`, `runServices`, `workspaceFolder`, `shutdownAction`, and `overrideCommand`, but no Compose invocation-arguments property.
- **documented workaround:** https://code.visualstudio.com/docs/devcontainers/create-dev-container states that Dev Containers attaches when the configured Compose services were started manually, allowing `docker compose up --force-recreate --renew-anon-volumes` to be run before reopening. This is a manual workaround rather than configuration coverage.
- **canonical review:** https://github.com/microsoft/vscode-remote-release/issues/3972 concerns dynamically generated arguments for standalone Docker, while https://github.com/microsoft/vscode-remote-release/issues/4885 concerns Compose `--env-file`; neither owns this request for general Compose `up` arguments.
