# Issue #3057 — RunArgs for docker-compose 

[https://github.com/microsoft/vscode-remote-release/issues/3057](https://github.com/microsoft/vscode-remote-release/issues/3057)

## Summary

Keep open: the documented Compose configuration still lacks an equivalent of runArgs for passing -V or --force-recreate. Manual Compose startup is a workaround, and the related reports do not provide a valid open canonical.

## Change summary

Allow configuring additional docker compose up arguments when Dev Containers starts a Compose environment.

## Best solution

The Dev Containers component should provide a supported way to configure Compose startup options, including anonymous-volume renewal and forced recreation. Any format proposal may need spec coordination, but the extension-side implementation remains work for this tracker.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/3057 explicitly requests -V or --force-recreate on docker-compose up; https://github.com/microsoft/vscode-remote-release/issues/3057#issuecomment-732682658 adds another user's need. The issue already carries containers and feature-request.
- **Existing-capability check:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md defines runArgs under image/Dockerfile-specific properties. Its Compose-specific properties include dockerComposeFile, service, runServices, and workspaceFolder, but no equivalent for arbitrary up arguments.
- **Workaround does not cover configuration:** https://code.visualstudio.com/docs/devcontainers/create-dev-container#_use-docker-compose documents starting Compose manually and having VS Code attach to the running service. This permits externally chosen startup flags but does not configure the extension's own Compose invocation. https://docs.docker.com/reference/cli/docker/compose/up/ distinguishes --force-recreate from -V/--renew-anon-volumes; rebuilding alone is not documented as covering both.
- **Same capability, closed precedent:** https://github.com/microsoft/vscode-remote-release/issues/6539 requested upArgs specifically for -V and was consolidated into https://github.com/microsoft/vscode-remote-release/issues/6298. The latter is closed following the 60-day upvote process, not a shipped implementation or a maintainer scope decision: https://github.com/microsoft/vscode-remote-release/issues/6298#issuecomment-1094163588. Neither is an eligible duplicate target.
- **Open related items are not canonicals:** https://github.com/microsoft/vscode-remote-release/issues/4885 remains open but principally tracks --env-file, not forced recreation or anonymous-volume renewal. https://github.com/microsoft/vscode-remote-release/issues/3972 remains open but requests dynamically generated Docker run arguments. Searches for Compose runArgs, arguments, flags, recreation, and upArgs did not establish an open canonical owning this report's requested behavior.
