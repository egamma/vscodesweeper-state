# Issue #6925 — [Feature Request] Support for `--user-data-dir` and `--extensions-dir` on WSL

[https://github.com/microsoft/vscode-remote-release/issues/6925](https://github.com/microsoft/vscode-remote-release/issues/6925)

## Summary

A real WSL CLI capability gap remains: current Profiles provide configuration isolation and sharing, but do not provide caller-selected remote user-data and extension directories. Route this longstanding Backlog request to the WSL and CLI owners.

## Change summary

Allow the WSL `code` launcher to honor `--user-data-dir` and `--extensions-dir` so tools can create isolated VS Code instances.

## Best solution

The WSL launcher and remote server lifecycle should safely propagate caller-selected user-data and extension directories, or expose an equivalent supported mechanism that preserves isolated instances and remote extension sets.
