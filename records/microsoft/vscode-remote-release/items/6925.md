# Issue #6925 — [Feature Request] Support for `--user-data-dir` and `--extensions-dir` on WSL

[https://github.com/microsoft/vscode-remote-release/issues/6925](https://github.com/microsoft/vscode-remote-release/issues/6925)

## Summary

Keep this accepted feature request open and route it to WSL. Profiles and portable mode provide related customization capabilities, but neither establishes support for launching from WSL with both requested directory overrides.

## Change summary

Support custom user-data and extension directories when launching VS Code from WSL so vscode-manager can create isolated instances.

## Best solution

The WSL owner should define how both directory overrides map to Windows-side user data and local versus remote extensions, then support an isolated launch path usable by vscode-manager. Coordinate the remote-extension-directory portion with the older related request without dropping the user-data-directory requirement.
