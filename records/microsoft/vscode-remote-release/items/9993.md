# Issue #9993 — Host networking causes an explosion of Docker processes

[https://github.com/microsoft/vscode-remote-release/issues/9993](https://github.com/microsoft/vscode-remote-release/issues/9993)

## Summary

Keep open for Dev Containers: the complete host-networking reproduction suffices to retest beyond the reported 2024 versions. Maintainers accepted a prevention approach, but no verified implementation or open canonical establishes that the runaway forwarding is resolved.

## Change summary

Connecting to a forwarded port in a host-networked dev container creates rapidly multiplying Docker processes and exhausts memory.

## Best solution

Dev Containers should prevent self-referential port forwarding when the container shares the host network, using the tunnel-provider approach accepted in the thread. Retest the supplied minimal configuration on current releases; avoiding forwarded ports remains a workaround, not a product fix.
