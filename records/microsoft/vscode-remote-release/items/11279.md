# Issue #11279 — Cannot build java project or node project in container, permission denied

[https://github.com/microsoft/vscode-remote-release/issues/11279](https://github.com/microsoft/vscode-remote-release/issues/11279)

## Summary

Keep open as a rootless Docker bind-mount compatibility issue: the logs show permission-sensitive build operations failing on a Windows-backed workspace. The recent Podman workaround does not establish resolution of the reporter's Docker configuration.

## Change summary

Allow Maven and Node tooling to build Windows-backed workspaces as the non-root container user when using rootless Docker through WSL2.

## Best solution

Determine whether Docker's rootless UID mapping combined with WSL's Windows-backed filesystem permits the required ownership and metadata operations, then document a supported Dev Containers configuration or workaround. The supplied projects and logs suffice to investigate; selecting a different user under Podman is not a verified Docker solution.

- **Canonical candidates do not establish the exact symptom:** Verified open candidates https://github.com/microsoft/vscode-remote-release/issues/9125 and https://github.com/microsoft/vscode-remote-release/issues/10608 discuss parent-directory writability or root-owned workspace files. There is no confirmation that this resolves the original rootless Docker Java or Node reproductions.
