# Issue #9855 — Better handle remote linux-based OSs that do not follow FHS

[https://github.com/microsoft/vscode-remote-release/issues/9855](https://github.com/microsoft/vscode-remote-release/issues/9855)

## Summary

Keep open in Backlog: the request passed the repository's community threshold with 14 upvotes, and the documented pre-staging workaround does not address the repeated download loop or provide native non-FHS support.

## Change summary

Remote - SSH should handle VS Code Server startup failures on non-FHS Linux systems without repeatedly deleting and downloading the server.

## Best solution

The SSH/server installation path should stop retrying after a deterministic runtime failure and preserve enough state for diagnosis or patching; longer term, the SSH component can decide whether to support NixOS directly.
