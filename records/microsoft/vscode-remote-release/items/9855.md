# Issue #9855 — Better handle remote linux-based OSs that do not follow FHS

[https://github.com/microsoft/vscode-remote-release/issues/9855](https://github.com/microsoft/vscode-remote-release/issues/9855)

## Summary

Keep this accepted SSH feature request open: available compatibility workarounds do not establish that failed Node startup now stops repeated downloads or preserves the installation for patching. No verified canonical owns that same observable behavior.

## Change summary

Handle non-FHS remote hosts gracefully instead of repeatedly deleting and downloading a server whose Node binary cannot run.

## Best solution

Remote - SSH's server-installation flow should stop retrying an incompatible runtime, explain the failure, and preserve a usable opportunity to patch or pre-stage the server. Retest the supplied NixOS scenario on current releases to determine which handling improvements remain necessary.
