# Issue #10675 — Cannot install Code Tunnel as a service on MacOS

[https://github.com/microsoft/vscode-remote-release/issues/10675](https://github.com/microsoft/vscode-remote-release/issues/10675)

## Summary

The macOS tunnel-service installer still writes its launchd plist directly into the user's home directory, matching the reported failure and independent diagnosis. This is a public VS Code CLI defect that should remain open and be transferred to microsoft/vscode.

## Change summary

Installing a Code Tunnel service on macOS registers its launchd plist in the wrong directory and fails to start the service.

## Best solution

A maintainer can transfer this to microsoft/vscode, where the CLI implementation lives. The macOS service manager should install the plist under the appropriate user LaunchAgents directory and load it in the user's launchd domain.
