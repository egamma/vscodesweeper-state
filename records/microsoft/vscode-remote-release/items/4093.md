# Issue #4093 — Clone repository in container volume / docker compose / path to repository

[https://github.com/microsoft/vscode-remote-release/issues/4093](https://github.com/microsoft/vscode-remote-release/issues/4093)

## Summary

Keep open: documented workspace substitutions do not establish a container-wide environment variable for a Compose-started service. The related issues do not meet the same-observable-symptom duplicate bar for this re-reviewed request.

## Change summary

Expose the actual cloned repository path to Docker Compose container startup processes so lsyncd can synchronize sources without a hard-coded workspace directory.

## Best solution

Dev Containers should provide a supported way to pass the resolved clone-in-volume repository path into the Compose service's startup environment. Preserve this product-side request while coordinating related workspace and Compose environment work.

The linked sample's .devcontainer/docker-compose.yml starts lsyncd as the service command, while .devcontainer/lsyncd.conf hard-codes /workspaces/vscode-remote-test-1: https://github.com/aheissenberger/vscode-remote-clone-repo-docker-compose/tree/master/.devcontainer.
- **Existing capability is partial:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md documents ${containerWorkspaceFolder} and lifecycle commands running from workspaceFolder. However, https://code.visualstudio.com/remote/advancedcontainers/environment-variables states that Compose configurations support only remoteEnv in devcontainer.json; it affects VS Code subprocesses, not the whole container. These capabilities do not directly supply the path to this Compose-started lsyncd process.
