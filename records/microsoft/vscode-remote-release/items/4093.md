# Issue #4093 — Clone repository in container volume / docker compose / path to repository

[https://github.com/microsoft/vscode-remote-release/issues/4093](https://github.com/microsoft/vscode-remote-release/issues/4093)

## Summary

A real Dev Containers gap remains: Docker Compose cannot consume the dynamically resolved repository-volume path when starting the development and sibling services. Existing workspace variables only partially address the request.

## Change summary

Expose the resolved container-volume workspace path to Docker Compose so the development container and sibling services can use the cloned repository without hard-coded paths.

## Best solution

Dev Containers should provide a stable Docker Compose substitution or generated environment value for the resolved workspace path and volume, allowing the primary and sibling services to mount or reference the same cloned content.
