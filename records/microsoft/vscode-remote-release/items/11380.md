# Issue #11380 — Remote SSH requires scp -O; need configurable extra flags and option to skip server transfer

[https://github.com/microsoft/vscode-remote-release/issues/11380](https://github.com/microsoft/vscode-remote-release/issues/11380)

## Summary

Keep open as a Remote - SSH feature request: documented download controls only partially address the requested transfer restrictions, and no verified canonical covers both legacy SCP configuration and manual-bootstrap reuse.

## Change summary

Allow configurable SSH/SCP arguments and connecting with a compatible preinstalled server without client-initiated transfers.

## Best solution

The SSH component should decide on a supported legacy-SCP configuration and transfer-free bootstrap path that recognizes the required preinstalled server. Coordinate the offline-installation overlap with existing requests without losing the distinct SCP argument requirement.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/11380 requests configurable SCP/SSH arguments, compatible-server detection, and suppression of client transfers on Windows 11 connecting to RHEL 9.6. The February 2026 comment reports the same issue but provides no fixing-release confirmation.
- **Existing capability is partial:** https://code.visualstudio.com/docs/remote/ssh documents remote.SSH.localServerDownload, including never downloading locally, and remote.SSH.configFile for SSH configuration. These address download-source selection and SSH config options, but do not establish configurable scp -O arguments or guaranteed reuse of a manually installed server on an offline host.
- **Younger request is not canonical:** https://github.com/microsoft/vscode-remote-release/issues/11382 is open and was created later on December 16, 2025. It requests an SCP executable path for WSL/DevSpaces, not legacy-SCP flags plus transfer-free bootstrap, so it does not meet this re-reviewed item's canonical bar.
- **Offline overlap does not cover full scope:** https://github.com/microsoft/vscode-remote-release/issues/1399 is open and tracks complete offline installation; https://github.com/microsoft/vscode-remote-release/issues/9454 is open in Backlog and tracks preinstalled SSH environments. Neither owns the complete configurable SSH/SCP argument request.
- **Prior decline is narrower:** https://github.com/microsoft/vscode-remote-release/issues/10406#issuecomment-2702199962 declines legacy SCP support. That precedent does not decide this report's additional manual-bootstrap and transfer-suppression requests. https://github.com/microsoft/vscode-remote-release/issues/9103 and https://github.com/microsoft/vscode-remote-release/issues/9341 were closed after insufficient candidate upvotes, not shipped fixes, and cannot serve as duplicate canonicals.
- **Installation paths need differentiation:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-Troubleshooting explains that remote.SSH.useExecServer bootstraps a minimal control server before launching the full server and requires full Remote-SSH logs for troubleshooting. Recognizing a manually installed full server alone may not satisfy that bootstrap path; the reported transfer is not enough to establish a product regression.
