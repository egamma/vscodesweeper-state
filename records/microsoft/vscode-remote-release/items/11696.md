# Issue #11696 — Volume mount does not resolve path correctly

[https://github.com/microsoft/vscode-remote-release/issues/11696](https://github.com/microsoft/vscode-remote-release/issues/11696)

## Summary

The symptoms match documented Docker-outside-of-Docker bind-mount limitations, rather than an established Dev Containers defect. Clarify the workspace mount and Docker daemon topology before deciding whether any extension work remains.

## Change summary

Single-file bind mounts used by Docker Compose inside a dev container appear as directories in sibling containers.

## Best solution

Establish whether Compose connects to the host daemon or an inner daemon. For host-daemon access, use daemon-visible source paths for host-backed workspaces or the documented Docker-in-Docker approach for volume-backed workspaces; investigate Dev Containers only if the failure persists with valid daemon-visible files.

This explains the reported symptom if the scripts are absent at the resolved daemon-side paths, without proving that this is the reporter's actual topology.
