# Issue #6605 — Workspace can't be opened in devcontainer when workspace-file is a symbolic link outside of the workspace folder

[https://github.com/microsoft/vscode-remote-release/issues/6605](https://github.com/microsoft/vscode-remote-release/issues/6605)

## Summary

The logs and maintainer diagnosis identify a plausible WSL path-resolution defect, but the latest confirmation is from 2023 and does not establish that it still reproduces on current Dev Containers releases. A current retest and log are needed.

## Change summary

Opening a symlinked workspace file in a WSL-hosted dev container resolves the link target and searches for `.devcontainer` relative to the wrong directory.

## Best solution

Dev Containers should preserve the workspace file's logical symlink path when locating the workspace and `.devcontainer` configuration across WSL path conversion. First confirm the behavior on current VS Code, Dev Containers, and WSL versions with a fresh creation log.
