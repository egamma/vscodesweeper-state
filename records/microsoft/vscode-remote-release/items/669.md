# Issue #669 — Unsupported architecture: armv6l

[https://github.com/microsoft/vscode-remote-release/issues/669](https://github.com/microsoft/vscode-remote-release/issues/669)

## Summary

Keep this as the canonical ARMv6 support request. Current documentation still excludes ARMv6, and maintainers have directed subsequent requests here; the unresolved decision is whether a usable remote development experience is feasible on 512 MB devices.

## Change summary

Enable Remote - SSH development on ARMv6 devices such as the original Raspberry Pi Zero W and Pi 1.

## Best solution

The SSH and VS Code Server owners should assess ARMv6 runtime support and memory feasibility before committing to support these devices. Retain this issue as the central tracking request; file-mount workarounds do not deliver remote extension execution and IntelliSense.

## Evidence

- **Existing-capability check:** https://code.visualstudio.com/docs/remote/linux lists ARMv7l and ARMv8/AArch64 support, not ARMv6. https://code.visualstudio.com/docs/remote/ssh#_system-requirements requires 1 GB RAM and recommends 2 GB; its documented settings do not supply an ARMv6 server runtime.
- **Maintainer feasibility concern:** https://github.com/microsoft/vscode-remote-release/issues/669#issuecomment-640986010 explains that 512 MB devices may suffer disconnects, unavailable IntelliSense, failed file opening, and crashes. The maintainer deferred support pending confidence that it would work rather than announcing a fix or permanently declining the request.
- **Canonical ownership:** https://github.com/microsoft/vscode-remote-release/issues/1691#issuecomment-544380450 and https://github.com/microsoft/vscode-remote-release/issues/3260#issuecomment-651151247 explicitly close matching reports as duplicates of this issue. A later ARMv6 request on Remote - SSH 0.110.1 was also directed here: https://github.com/microsoft/vscode-remote-release/issues/9754#issuecomment-2067258300.
- **Canonical search:** Tracker searches for armv6, Pi Zero, and ARM support found no open replacement owning this capability. https://github.com/microsoft/vscode-remote-release/issues/3468 concerns improving the unsupported-architecture message, not implementing ARMv6 support.
- **Partial workarounds:** The discussion at https://github.com/microsoft/vscode-remote-release/issues/669 suggests SSHFS and https://github.com/SchoofsKelvin/vscode-sshfs for editing files. These do not satisfy the request to run development tooling and remote extensions directly on the board.
