# Issue #2795 — [docker-compose] Only rebuild target "service" on container rebuild

[https://github.com/microsoft/vscode-remote-release/issues/2795](https://github.com/microsoft/vscode-remote-release/issues/2795)

## Summary

The existing `runServices` property covers this request by limiting Compose build and startup operations to the listed services plus the primary `service`. Using `shutdownAction: "none"` also preserves containers used by other VS Code windows.

## Change summary

Allow rebuilding one Docker Compose service without rebuilding or disrupting unrelated services used by other Dev Container windows.

## Best solution

Configure each service's `devcontainer.json` with `runServices` containing only that service and use `shutdownAction: "none"` when sibling containers must remain running.

- **Proposed comment:**

  > Thanks for the request. This is supported by listing only the target service in `runServices` for each `devcontainer.json`, for example `"runServices": ["backend"]`; the primary `service` is also included automatically. The Dev Container tooling applies that service list to both Compose build and startup. When multiple VS Code windows share the Compose project, set `"shutdownAction": "none"` so closing or rebuilding one environment does not stop sibling containers. The multi-container setup is documented at https://code.visualstudio.com/remote/advancedcontainers/connect-multiple-containers.
