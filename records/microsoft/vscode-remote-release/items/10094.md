## Summary

Request the failing container-start log and missing environment versions to distinguish WSLg socket initialization from Dev Containers mount recovery. The maintainer suggested resolving the symlink target, but neither reproduction nor resolution is confirmed.

## Change summary

An existing dev container cannot reopen after reboot when its automatically mounted WSLg socket path disappears despite the socket remaining under /mnt/wslg/runtime-dir.

## Best solution

The Dev Containers owner should establish whether restarting an existing container retains an unavailable socket mount, then evaluate the maintainer's resolved-path approach while preserving Wayland support. Investigate WSLg initialization separately if the missing symlink is an upstream defect.
