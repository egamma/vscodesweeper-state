# Issue #6586 — devcontainer.json does not pick up parameters from the env file and does not pass them to docker-compose

[https://github.com/microsoft/vscode-remote-release/issues/6586](https://github.com/microsoft/vscode-remote-release/issues/6586)

## Summary

Keep open: the request is to define a workspace path once for both devcontainer.json and Docker Compose, not merely load container environment variables. Documented capabilities and the related initializeCommand fix do not fully provide that shared configuration.

## Change summary

Allow one variable source to supply both devcontainer.json workspaceFolder and the corresponding Docker Compose volume path without duplicating values or using host-specific scripts.

## Best solution

The Dev Containers component should support a spec-aligned shared variable source for configuration substitution and Compose invocation. Coordinate with the related environment-file and local-variable proposals, while retaining this report's requirement to synchronize workspaceFolder with an arbitrary Compose mount target.

- **Existing-capability check:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents Compose .env loading, service env_file, and remoteEnv. - **Substitution boundary:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md#variables-in-devcontainerjson documents ${localEnv:VARIABLE_NAME} for host environment values and restricts ${containerEnv:VARIABLE_NAME} to remoteEnv. A preconfigured host environment is an alternative, but the reference does not provide the requested declarative shared file source; workspaceMount is listed under image/Dockerfile-specific properties.
- **Related fix does not complete this request:** https://github.com/microsoft/vscode-remote-release/issues/7377#issuecomment-1315189645 announces an initializeCommand ordering fix in Dev Containers 0.264.0-pre-release, confirmed at https://github.com/microsoft/vscode-remote-release/issues/7377#issuecomment-1315348288. It restores generating .env before Compose runs, not portable shared substitution between devcontainer.json and Compose.
