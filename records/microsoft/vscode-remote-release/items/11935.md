# Issue #11935 — WSLc integration: Windows-side attach implicitly accesses the default WSL distro's HOME

[https://github.com/microsoft/vscode-remote-release/issues/11935](https://github.com/microsoft/vscode-remote-release/issues/11935)

## Summary

Route this WSLc helper-placement improvement to Dev Containers. The report distinguishes service-forwarding initialization from container HOME resolution; no verified fix or canonical issue covers the requested Windows-or-container execution and storage model.

## Change summary

Avoid implicitly initializing helpers in the default regular WSL distribution when attaching from Windows to a WSLc container.

## Best solution

Dev Containers should make WSLc helper execution and storage specific to Windows or the selected container, rather than implicitly using a separate default WSL distribution. The owner should determine which forwarding services can operate in those contexts without removing useful functionality.
