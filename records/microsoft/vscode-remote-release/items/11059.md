# Issue #11059 — GPG signing failed inside container on remote server

[https://github.com/microsoft/vscode-remote-release/issues/11059](https://github.com/microsoft/vscode-remote-release/issues/11059)

## Summary

The logs confirm that Dev Containers forwards the GPG-agent socket from the container to the remote SSH host, but they do not establish why signing subsequently fails. A current-version retest and agent diagnostics are needed to distinguish a forwarding defect from remote-host pinentry configuration.

## Change summary

GPG keys stored on an SSH host are visible inside its dev container, but signing through the forwarded GPG agent fails with “No such file or directory.”

## Best solution

The Dev Containers owner should verify that nested Remote-SSH-to-container GPG forwarding reaches the remote host's agent-extra socket with a usable pinentry context. If configuration is required, document that remote-host setup; otherwise fix the forwarding path.
