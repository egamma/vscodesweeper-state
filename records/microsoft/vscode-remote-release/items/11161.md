# Issue #11161 — No environment GITHUB_TOKEN available.

[https://github.com/microsoft/vscode-remote-release/issues/11161](https://github.com/microsoft/vscode-remote-release/issues/11161)

## Summary

The thread establishes a host-environment configuration question, not a demonstrated Dev Containers defect. The reporter's remaining question is how to provide the supported GITHUB_TOKEN before VS Code starts.

## Change summary

Make GITHUB_TOKEN available when downloading a GitHub-hosted Feature tarball, rather than only inside the running container.

## Best solution

Use the existing host-environment authentication mechanism for Feature downloads, keeping it separate from container runtime variables. Close this as a usage question with concrete guidance rather than claiming the reporter confirmed a fix.

- **Proposed comment:**

  > Thanks for the context. `runArgs: ["--env-file", "..."]` sets variables in the running container; it does not supply credentials to the host-side Feature downloader. As explained above, `GITHUB_TOKEN` needs to be exported in the host environment before VS Code starts. Fully quit VS Code, then launch it with `code .` from a terminal where the variable is exported. This mechanism does not require an additional GitHub extension. Keep the token out of committed files and public logs.
