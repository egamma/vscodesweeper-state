# Issue #7525 — Unable to use keys forwarded by Windows ssh-agent <=8.8 with ssh client >=8.9

[https://github.com/microsoft/vscode-remote-release/issues/7525](https://github.com/microsoft/vscode-remote-release/issues/7525)

## Summary

Confirmed upstream incompatibility between OpenSSH for Windows agents before 8.9 and OpenSSH clients 8.9 or newer. The existing upstream classification is correct, and upstream issues remain open under this tracker's policy.

## Change summary

SSH authentication inside a Dev Container fails when a newer container SSH client uses keys forwarded by an older Windows ssh-agent.

## Best solution

Keep this classified as an upstream Windows OpenSSH interoperability issue and direct affected users to upgrade OpenSSH for Windows from https://github.com/PowerShell/Win32-OpenSSH/releases; no Dev Containers defect requiring an extension change is established.

## Evidence

- **maintainer reproduction:** A maintainer reproduced the failure on Windows and observed that the forwarded key was listed by `ssh-add -l` while authentication with the newer container SSH client still failed.
- **upstream cause:** The maintainer traced connection termination to OpenSSH for Windows code at https://github.com/PowerShell/openssh-portable/blob/ad957f89e03e3254e27a6b6dfc28c9dd79d3fb3f/contrib/win32/win32compat/ssh-agent/connection.c#L173.
- **version pairing:** The reporter used OpenSSH_for_Windows_8.6p1, while the failing Ubuntu 22.04 container used OpenSSH 8.9p1; Ubuntu 20.04 with OpenSSH 8.2p1 worked.
- **upstream resolution:** The maintainer recommended upgrading through https://github.com/PowerShell/Win32-OpenSSH/releases, and the reporter identified an available 9.1 package.
