# Issue #11117 — Remote-SSH extension checking OS logic bug

[https://github.com/microsoft/vscode-remote-release/issues/11117](https://github.com/microsoft/vscode-remote-release/issues/11117)

## Summary

Keep open as the canonical report: a later independent report reproduces the same Windows misclassification when `uname` returns a MINGW signature. The existing `ssh` routing is correct.

## Change summary

Remote - SSH times out on Windows hosts when a Unix-compatible `uname` executable in PATH causes the host platform probe to misclassify Windows.

## Best solution

Remote - SSH should recognize Windows-related `uname` signatures case-insensitively, including MINGW and CYGWIN, and continue with the Windows server setup path. This older, broader issue should own the shared platform-detection defect represented by the narrower Git Bash report.
