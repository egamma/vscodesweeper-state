# Issue #11117 — Remote-SSH extension checking OS logic bug

[https://github.com/microsoft/vscode-remote-release/issues/11117](https://github.com/microsoft/vscode-remote-release/issues/11117)

## Summary

This remains a credible Remote - SSH platform-detection bug: Windows hosts exposing Unix-compatible `uname` output can be misclassified, causing connection timeouts. A later report reproduces the same probe failure on Remote - SSH 0.122.0.

## Change summary

Make Remote - SSH reliably recognize Windows hosts when `uname` is available and reports Windows_NT, MINGW, MSYS, or Cygwin identifiers.

## Best solution

The SSH component should normalize and comprehensively classify Windows-compatible `uname` output before selecting the remote installation path, while honoring an explicit Windows platform selection.
