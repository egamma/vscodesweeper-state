# Issue #6472 — Same workspace path for definitions with docker-compose as for definitions using single image/Dockerfile. Possible?

[https://github.com/microsoft/vscode-remote-release/issues/6472](https://github.com/microsoft/vscode-remote-release/issues/6472)

## Summary

A real capability gap remains: Docker Compose cannot directly use devcontainer substitutions such as `${localWorkspaceFolderBasename}` for its volume target. Existing workarounds either expose sibling folders or lose the distinctive workspace name, so this Backlog request should remain open.

## Change summary

Give Docker Compose-based dev containers the same automatic, repository-specific workspace path available to image- and Dockerfile-based configurations.

## Best solution

The Dev Containers tooling should provide a portable way for Compose configuration to consume the resolved workspace basename when defining the mount target, ideally through the dev container specification rather than a generated `.env` file.

## Evidence

- **spec limitation:** The Dev Container reference documents `${localWorkspaceFolderBasename}` for values in `devcontainer.json`, while Compose mounts remain defined in the separate Compose file: https://containers.dev/implementors/json_reference/
- **workarounds incomplete:** The maintainer suggested `${COMPOSE_PROJECT_NAME}` or mounting the parent folder, but a follow-up explains that mounting the parent exposes unrelated sibling projects: https://github.com/microsoft/vscode-remote-release/issues/6472#issuecomment-1920899409
- **existing alternative:** Using a fixed `/workspace` path avoids generating an environment file but deliberately gives up the repository-specific path and window identity requested here: https://github.com/microsoft/vscode-remote-release/issues/6472#issuecomment-2166650836
- **related specification gap:** https://github.com/devcontainers/spec/issues/307 remains open and similarly tracks the inability to use devcontainer substitutions in Compose project configuration, but it does not own this issue's distinct workspace-mount request.
