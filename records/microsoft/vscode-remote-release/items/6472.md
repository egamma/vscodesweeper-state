# Issue #6472 — Same workspace path for definitions with docker-compose as for definitions using single image/Dockerfile. Possible?

[https://github.com/microsoft/vscode-remote-release/issues/6472](https://github.com/microsoft/vscode-remote-release/issues/6472)

## Summary

Keep this accepted Compose feature request open: documented devcontainer mounts offer an alternative, but do not expose the workspace basename to Compose interpolation. No verified canonical owns that remaining request.

## Change summary

Make the opened workspace's basename available to Docker Compose so its volume destination can match the image/Dockerfile workspace path without generating an .env file.

## Best solution

The Dev Containers owner should document the variable-aware mounts alternative and decide whether to expose the workspace basename to Compose's invocation environment. Preserve this issue for the Compose-side capability rather than merging it into unrelated variable or multi-container requests.
