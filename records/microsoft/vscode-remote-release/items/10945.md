## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode-remote-release/issues/3567 is OPEN and was created on 2020-08-25. It requests a platform-independent host-home variable because HOME/USERPROFILE substitution produces incorrect cross-platform paths. Its discussion also requests platform-specific configuration and describes using the same concatenation for volume mappings. This owns the portable path capability needed by the present mount example.
- **Existing capability and limitation:** https://code.visualstudio.com/remote/advancedcontainers/add-local-file-mount documents ${localEnv:HOME}${localEnv:USERPROFILE} in mount sources. https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson documents blank substitution for unset variables and environment-variable defaults, but these do not provide an unconditional platform-independent home-directory variable. The canonical explains why concatenation fails when both variables are set.
- **Unresolved workaround:** In https://github.com/microsoft/vscode-remote-release/issues/10945, a maintainer suggested concatenating USERPROFILE and HOME on 2025-05-12. On 2025-07-27 the reporter said it failed on two Linux machines and three VS Code versions. This is not a confirmed resolution; the cross-platform mount example should remain represented in the canonical.
- **Different conditional-mount request:** https://github.com/microsoft/vscode-remote-release/issues/5322 is open but requests skipping mounts whose sources do not exist. Its author explicitly distinguishes that request from Windows/Linux path handling at https://github.com/microsoft/vscode-remote-release/issues/5322#issuecomment-4104512570. Skipping a mount would not deliver this reporter's required host-directory mapping.
