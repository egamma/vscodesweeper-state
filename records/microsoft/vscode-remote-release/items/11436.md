[https://github.com/microsoft/vscode-remote-release/issues/11436](https://github.com/microsoft/vscode-remote-release/issues/11436)

## Summary

Keep open as a WSL file-access bug: the detailed comparison with Remote - SSH and an independent confirmation indicate that sshfs-mounted directories are incorrectly exposed as empty specifically through the WSL extension.

## Change summary

Make files within sshfs/FUSE mounts visible in VS Code Explorer when a folder is opened through the WSL extension.

## Best solution

The WSL component should determine why its remote file-service path cannot enumerate this FUSE mount while the terminal and Remote - SSH can, then align Explorer access with the underlying WSL filesystem view.
