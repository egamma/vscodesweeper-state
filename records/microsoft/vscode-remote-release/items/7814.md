# Issue #7814 — Gpg agent not forwarded when using devcontainer through remote-ssh

[https://github.com/microsoft/vscode-remote-release/issues/7814](https://github.com/microsoft/vscode-remote-release/issues/7814)

## Summary

Keep open: Dev Containers still lacks a documented way to select the local versus SSH-host GPG agent, and current workarounds do not satisfy the requested automatic behavior.

## Change summary

Allow users opening a dev container through Remote - SSH to choose whether GPG credentials come from the local client or the remote Docker host.

## Best solution

The Dev Containers component should offer an explicit GPG-agent source setting, or reliably select an agent containing usable keys, while preserving the existing remote-first default for compatibility.

## Vision fit

- **Fit:** aligned
- **Reason:** Predictable credential forwarding closes a local-versus-remote parity gap in a supported combined Remote - SSH and Dev Containers workflow.
- **Evidence:** The public product promise is to “Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set.”
