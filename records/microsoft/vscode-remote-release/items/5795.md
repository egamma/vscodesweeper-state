# Issue #5795 — Support docker-compose 3.9 profiles 

[https://github.com/microsoft/vscode-remote-release/issues/5795](https://github.com/microsoft/vscode-remote-release/issues/5795)

## Summary

Keep open as the canonical feature request: current Dev Container configuration still has no direct way to activate Docker Compose profiles, and a current-release report demonstrates the resulting build failure.

## Change summary

Allow Dev Containers to select Docker Compose profiles, preferably through a profiles property in devcontainer.json.

## Best solution

The Dev Containers component should coordinate a spec-level profiles property with https://github.com/devcontainers/spec and implement consistent profile activation across Compose configuration, build, start, and shutdown commands.

## Evidence

- **current specification gap:** The current Dev Container JSON reference at https://containers.dev/implementors/json_reference/ lists dockerComposeFile, service, runServices, and workspaceFolder as Compose-specific properties, but no property for activating profiles.
- **available Compose mechanism:** Docker documents profile activation through --profile or COMPOSE_PROFILES at https://docs.docker.com/compose/how-tos/profiles/, so the missing capability is passing this selection consistently through Dev Containers.
- **current reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11454 reports the same underlying gap on Dev Containers 0.437.0: configuration sees profiled services, but the generated Compose build command omits profile activation and reports no services to build.
- **workarounds are incomplete:** The thread documents environment-variable, runServices, generated override-file, and !reset workarounds, while later Windows/WSL and macOS reports say COMPOSE_PROFILES is not reliably propagated. None provides the requested explicit profile selection.
- **demand and ownership:** The issue is already in the Backlog with 37 upvotes, carries the containers and feature-request labels, and the newer report points back to it as the canonical request.
