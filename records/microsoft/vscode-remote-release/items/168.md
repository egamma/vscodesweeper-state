# Issue #168 — Local tasks

[https://github.com/microsoft/vscode-remote-release/issues/168](https://github.com/microsoft/vscode-remote-release/issues/168)

## Summary

Keep this accepted Backlog feature open: local terminals shipped separately, but tasks still cannot select the local client as their execution target. This is the canonical request, with sustained demand across SSH, containers, WSL, and tunnels.

## Change summary

Allow tasks in a remote VS Code window to run explicitly on the local client instead of the remote environment.

## Best solution

Extend the VS Code task model with an explicit local-or-remote execution target while retaining remote execution as the default and clearly identifying the selected authority. This issue should remain the canonical remote-workflow requirement while the remote and core task-system owners coordinate implementation.

## Vision fit

- **Fit:** aligned
- **Reason:** Mixed local and remote task orchestration supports the stated goal of making remote development provide VS Code's full feature set without abandoning the established client-server architecture.
- **Evidence:** The public vision promises users can "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set"; an execution-target option would improve parity within the existing architecture.
