# Issue #8912 — [Remote-SSH Bug]: Session keyring corrupted by remote-ssh, breaks azcopy

[https://github.com/microsoft/vscode-remote-release/issues/8912](https://github.com/microsoft/vscode-remote-release/issues/8912)

## Summary

Keep open in the Backlog: multiple users demonstrated that Remote - SSH terminals inherit a revoked Linux session keyring after the persistent server outlives its original SSH session. The request passed the repository's community threshold with 33 upvotes, and no documented capability or canonical issue covers it.

## Change summary

Ensure terminals created by a persistent Remote - SSH server receive a valid Linux session keyring after the original SSH session ends.

## Best solution

Remote - SSH should establish an independent session keyring for the long-lived VS Code Server before it detaches from the original sshd session, preventing subsequently created terminals from inheriting a revoked keyring.

## Evidence

- **independent reproductions:** The reporter reproduced the failure on vanilla RHEL 8, and another user independently reproduced it on Fedora 37 with the revoked `_ses` keyring visible in `/proc/keys`: https://github.com/microsoft/vscode-remote-release/issues/8912#issuecomment-1707072504 and https://github.com/microsoft/vscode-remote-release/issues/8912#issuecomment-1709131864.

The thread's `keyctl new_session` workaround also does not cover PowerShell.
