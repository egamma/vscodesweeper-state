# Issue #8912 — [Remote-SSH Bug]: Session keyring corrupted by remote-ssh, breaks azcopy

[https://github.com/microsoft/vscode-remote-release/issues/8912](https://github.com/microsoft/vscode-remote-release/issues/8912)

## Summary

Keep the accepted SSH backlog request open: the thread diagnoses session-keyring revocation when the server outlives its initial SSH session, and neither a confirmed fix nor a matching canonical was found.

## Change summary

Provide a valid Linux session keyring for remote server descendants after SSH disconnects and reconnects, so azcopy and token-dependent tools remain usable.

## Best solution

The SSH and VS Code Server owners should establish a session-keyring lifecycle compatible with the persistent server, including terminals running PowerShell. Retest the supplied disconnect/reconnect scenario with current connection modes and review credential-lifecycle implications before choosing an implementation.
