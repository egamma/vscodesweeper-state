# Issue #2365 — [Feature Request] Set Remote WSL as default run option without depending on the workspace

[https://github.com/microsoft/vscode-remote-release/issues/2365](https://github.com/microsoft/vscode-remote-release/issues/2365)

## Summary

Keep open: the request is for a workspace-independent WSL default when launching VS Code or opening files and folders from Windows. Documented connection commands and the thread's launcher workaround do not provide that default, and the verified related issue covers only WSL network paths.

## Change summary

Allow users to make WSL the default development environment for ordinary Windows launches and file or folder opens without restoring a workspace or using a terminal.

## Best solution

The WSL component should retain this broader opt-in default-launch request for an explicit product decision, including how incoming Windows paths map into the selected distribution. Coordinate WSL network-path detection with https://github.com/microsoft/vscode-remote-release/issues/3216 without treating that narrower request as a replacement.
