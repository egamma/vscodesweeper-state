# Issue #11063 — SSH explorer can't determine user from match block

[https://github.com/microsoft/vscode-remote-release/issues/11063](https://github.com/microsoft/vscode-remote-release/issues/11063)

## Summary

Keep open for the SSH owner: the supplied configuration and Explorer action suffice to retest the reported username-selection failure. Newer Match-related reports do not establish that this behavior was fixed or belongs to a canonical issue.

## Change summary

Connecting through Remote Explorer omits the username associated with a 1Password-generated Match Host/User entry, preventing selection of its identity file.

## Best solution

The SSH owner should determine how Explorer represents host/user combinations in bookmark configurations while preserving OpenSSH Match semantics. Explicit user@host connections provide a workaround, but do not resolve automatic selection from the existing Explorer entry.
