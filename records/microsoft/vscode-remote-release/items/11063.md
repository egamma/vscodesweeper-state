# Issue #11063 — SSH explorer can't determine user from match block

[https://github.com/microsoft/vscode-remote-release/issues/11063](https://github.com/microsoft/vscode-remote-release/issues/11063)

## Summary

This appears to be a remaining gap in Remote - SSH's Match-block parsing, but the report has no versions, logs, or current-release confirmation. A retest is needed before the SSH owner can determine whether the explorer still loses the target user.

## Change summary

Make the SSH Remote Explorer preserve the target user from a combined `Match Host ... User ...` block so selecting the host activates its identity configuration.

## Best solution

Remote - SSH should represent this conditional target as `user@host`, or otherwise preserve the user criterion when invoking SSH. First confirm the behavior on the current extension and collect the effective `ssh -G` configuration and Remote - SSH log.
