# Issue #8154 — Tunnels to incorrect port number (local port + 1)

[https://github.com/microsoft/vscode-remote-release/issues/8154](https://github.com/microsoft/vscode-remote-release/issues/8154)

## Summary

The thread isolates the port collision to WSL reserving the container's port through wslhost.exe before VS Code forwards it. This is correctly classified as upstream and should remain open while the current WSL behavior lacks an active canonical report.

## Change summary

WSL transiently reserves a container's listening port on Windows, causing Dev Containers to auto-forward to the next available port.

## Best solution

WSL should avoid exposing Docker-internal ports that are not listening in the WSL host; Dev Containers can then retain the requested local port instead of correctly falling back to the next available one.
