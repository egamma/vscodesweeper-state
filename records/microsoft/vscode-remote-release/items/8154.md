# Issue #8154 — Tunnels to incorrect port number (local port + 1)

[https://github.com/microsoft/vscode-remote-release/issues/8154](https://github.com/microsoft/vscode-remote-release/issues/8154)

## Summary

Keep open as upstream: the reporter demonstrated WSL occupying the requested Windows port before VS Code forwards it. Both linked WSL reports were closed for inactivity, not verified resolution, and the August 2026 report indicates remaining impact.

## Change summary

Automatically forwarding a container service selects the requested local port plus one because WSL temporarily occupies the requested port.

## Best solution

WSL should avoid reserving Windows ports for unpublished container listeners, allowing Dev Containers forwarding to retain the requested port. Preserve this upstream tracking item and distinguish the later mirrored-networking port conflicts from the original WSL 1.1.3 case before treating either as resolved.

- **Concrete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/8154#issuecomment-1459814065 supplies a clean python:3.9-bullseye container and netcat reproduction. Docker inspection shows bridge networking, empty PortBindings, and PublishAllPorts=false.
- **Upstream reports are not duplicate targets:** https://github.com/microsoft/WSL/issues/9763 explicitly describes this container-port reservation and VS Code's incremented-port fallback, but its closing comment at https://github.com/microsoft/WSL/issues/9763#issuecomment-2462074438 cites inactivity. https://github.com/microsoft/WSL/issues/9751 was likewise automatically closed for inactivity; a user's WSL 1.2.5 resolution report there does not establish resolution of this thread's later cases.
- **Workaround has a networking-mode limitation:** The reporter's workaround at https://github.com/microsoft/vscode-remote-release/issues/8154#issuecomment-1460560114 disables localhostForwarding. https://learn.microsoft.com/en-us/windows/wsl/wsl-config documents that this setting is ignored with networkingMode=mirrored, consistent with the July 2024 comment reporting that the workaround fails in mirrored mode. The documented ignoredPorts option permits Linux-side binding despite Windows port use; it does not establish that VS Code can retain the same Windows forwarding port.
