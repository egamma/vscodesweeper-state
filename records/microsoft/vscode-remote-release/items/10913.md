# Issue #10913 — Connect in Window forgets current VSCode profile (when not default) unless a recent directory/workspace is chosen

[https://github.com/microsoft/vscode-remote-release/issues/10913](https://github.com/microsoft/vscode-remote-release/issues/10913)

## Summary

The current-window remote connection path incorrectly applies `window.newWindowProfile`, despite that setting governing new windows. Independent SSH and WSL reports, including a recent workaround, indicate the cross-remote profile integration bug remains relevant.

## Change summary

Connecting to SSH or WSL in the current window replaces the active non-default profile with the profile configured for new windows.

## Best solution

A maintainer can transfer this to microsoft/vscode's user-profiles area. The current-window remote URI/open-folder path should preserve the active profile, while genuinely new remote windows may continue honoring `window.newWindowProfile`.
