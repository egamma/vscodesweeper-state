# Issue #11466 — Podman cannot use features behind an MitM proxy when the source is in a volume

[https://github.com/microsoft/vscode-remote-release/issues/11466](https://github.com/microsoft/vscode-remote-release/issues/11466)

## Summary

Verified duplicate: the open canonical issue tracks this same Podman bootstrap BuildKit failure behind a proxy, including certificate failures when adding features to a repository cloned into a volume.

## Change summary

Dev Container feature builds fail under Podman when volume-hosted source is used behind a TLS-intercepting proxy because the bootstrap BuildKit builder does not trust the corporate certificate.

## Best solution

Consolidate on https://github.com/microsoft/vscode-remote-release/issues/11050. The Dev Containers bootstrap path should configure its BuildKit builder with the applicable proxy and certificate trust or use the Podman build path consistently.
