# Issue #11469 — Preserve / bring Copilot session data across remote targets

[https://github.com/microsoft/vscode-remote-release/issues/11469](https://github.com/microsoft/vscode-remote-release/issues/11469)

## Summary

Keep open and broaden routing beyond containers: the requested automatic session portability spans WSL, SSH, and rebuilt dev containers, while the documented mount workaround covers only persistence and has unresolved concurrency concerns.

## Change summary

Automatically preserve or transfer Copilot CLI and VS Code Chat session data when users rebuild containers or move between remote targets.

## Best solution

Define session storage and synchronization that safely supports transitions among local, WSL, SSH, and container environments. The remote components should coordinate with the Copilot session owner rather than requiring users to mount implementation-specific data directories.
