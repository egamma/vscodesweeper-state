# Issue #8817 — dev.containers.dockerPath should be a workspace setting

[https://github.com/microsoft/vscode-remote-release/issues/8817](https://github.com/microsoft/vscode-remote-release/issues/8817)

## Summary

Keep this accepted Dev Containers request open: documented engine selection does not establish workspace-level overrides. The older related request concerns per-remote configuration, not switching repositories on the same host, so it does not meet the re-review duplicate bar.

## Change summary

Allow each workspace to select its Docker or Podman executable through dev.containers.dockerPath.

## Best solution

Dev Containers should support workspace-specific engine selection without repeatedly editing application settings. Define how host-side executable selection interacts with workspace trust and prevent container image or Feature metadata from overriding that choice.
