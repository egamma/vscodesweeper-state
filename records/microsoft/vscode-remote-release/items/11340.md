# Issue #11340 — Disable executables installed over SSH

[https://github.com/microsoft/vscode-remote-release/issues/11340](https://github.com/microsoft/vscode-remote-release/issues/11340)

## Summary

Keep open as a request for control over remote installation, rather than a demonstrated installation bug. Remote - SSH intentionally installs VS Code Server, but the documented alternatives do not provide the requested integrated, installation-free workflow.

## Change summary

Allow browsing remote files and using an SSH terminal without automatically installing or running remote executables.

## Best solution

The SSH owner should decide whether to offer explicit installation consent or a lightweight access mode while preserving the existing server-backed workflow. Document SSHFS plus a local terminal running ssh as an alternative, without presenting it as an equivalent Remote - SSH mode.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/11340 reports successful SSH access followed by unexpected node memory consumption on a roughly 1 GB Gentoo host, and explicitly asks to disable installed executables. There are no comments establishing a fix, decline, or reproduction of a distinct memory defect.
- **Intentional server installation:** https://code.visualstudio.com/docs/remote/ssh explicitly states that the extension installs VS Code Server on the remote OS. It lists 1 GB RAM as required and recommends at least 2 GB; installation itself is documented behavior, not evidence of a remote-extension bug.
- **Existing settings do not cover the ask:** https://code.visualstudio.com/docs/remote/ssh#_what-are-the-connectivity-requirements-for-the-vs-code-server-when-it-is-running-on-a-remote-machine-vm documents remote.SSH.localServerDownload as controlling where the server is downloaded, not whether it is installed. https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting describes remote.SSH.useLocalServer as SSH connection reuse and remote.SSH.useExecServer as bootstrapping before the full server; neither is an installation-free file-and-terminal mode.
- **Alternative and cleanup:** https://code.visualstudio.com/docs/remote/troubleshooting#_using-sshfs-to-access-files-on-your-remote-host documents mounting remote files through SSHFS. The same guide's cleaning-up section documents Remote-SSH: Uninstall VS Code Server from Host..., but uninstalling does not supply an ongoing server-free Remote - SSH workflow.
- **Canonical search:** Repository searches for SSH without a server, installation opt-out, lightweight access, serverless access, and consent did not establish an open canonical owning this request. https://github.com/microsoft/vscode-remote-release/issues/5906 concerns transferring installation scripts through CyberArk, still requires remote installation, and is closed; it is not a duplicate target.
- **Memory diagnosis remains separate:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting#performance-issues requires identifying the high-memory process by its full command arguments and distinguishing server-main.js from an extension host or extension child. This report does not provide that evidence, so the memory observation cannot establish a specific server defect or root cause.
