# Issue #10869 — `screen` command extremely slow (~11s) in Remote-SSH terminal due to massive poll(POLLNVAL) loop

[https://github.com/microsoft/vscode-remote-release/issues/10869](https://github.com/microsoft/vscode-remote-release/issues/10869)

## Summary

The detailed trace and two independent confirmations support a current Remote-SSH performance defect. The issue is already correctly routed and no canonical report or resolution is evident.

## Change summary

GNU Screen takes roughly 11 seconds to start in a Remote-SSH integrated terminal while repeatedly polling invalid file descriptors.

## Best solution

The SSH/server owner should investigate which descriptors the remote terminal environment exposes or inherits and prevent the million-iteration POLLNVAL loop, while preserving normal terminal process behavior.
