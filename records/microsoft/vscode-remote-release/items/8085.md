# Issue #8085 — Non-Buildkit: Builds stages past the one specified in `build.target`

[https://github.com/microsoft/vscode-remote-release/issues/8085](https://github.com/microsoft/vscode-remote-release/issues/8085)

## Summary

Keep open: the supplied Dockerfile structure and configuration suffice to retest the unwanted release-stage build. Docker's builder defaults have evolved since the report, but neither that change nor the recommendation to install buildx confirms resolution of the legacy-builder path.

## Change summary

Dev Containers appends a target stage after the original Dockerfile, causing the legacy Docker builder to execute stages beyond the configured build.target.

## Best solution

The containers owner should retest the supplied legacy-builder scenario and ensure Dockerfile augmentation preserves the requested target boundary. BuildKit is a documented workaround, not evidence that the non-BuildKit regression was fixed.

## Evidence

- **Concrete regression report:** https://github.com/microsoft/vscode-remote-release/issues/8085 supplies VS Code 1.75.1, Rancher Desktop 1.7.0 with Docker 20.10.21-rd, a three-stage Dockerfile structure, build.target="build", and the generated Dockerfile ending in dev_containers_target_stage. Opening the container unexpectedly also builds the later release stage, even without configured Features.
- **Documented builder distinction:** https://docs.docker.com/build/building/multi-stage/#differences-between-legacy-builder-and-buildkit states that the legacy builder processes every stage preceding its selected target, whereas BuildKit processes only dependencies. Appending the generated target after release explains the reported behavior; Docker's normal handling of a target in the original Dockerfile would stop before release.
- **Existing capability and workaround:** https://containers.dev/implementors/json_reference/#image-specific documents build.target as the Docker build target. The contributor's 2023-02-23 comment at https://github.com/microsoft/vscode-remote-release/issues/8085 recommends installing buildx because BuildKit skips unused stages, but supplies no reproduction attempt, fixing release, or reporter confirmation.
- **Canonical search:** Searches for build.target, BuildKit, and stages found no verified canonical with the same observable symptom. https://github.com/microsoft/vscode-remote-release/issues/7702 concerns a failing generated-target build rather than unwanted later-stage execution; https://github.com/microsoft/vscode-remote-release/issues/7582 and https://github.com/microsoft/vscode-remote-release/issues/9605 concern TARGETARCH image resolution.
