# Issue #7766 — Allow localEnv in feature environment variables.

[https://github.com/microsoft/vscode-remote-release/issues/7766](https://github.com/microsoft/vscode-remote-release/issues/7766)

## Summary

Keep open: feature-defined containerEnv substitution remains a distinct request, not satisfied by devcontainer.json substitution or automatic X11 forwarding. The related spec proposal does not establish that the Dev Containers extension delivers this capability.

## Change summary

Allow ${localEnv:VARIABLE} references in devcontainer-feature.json containerEnv values without requiring each consuming project to configure them.

## Best solution

Coordinate substitution semantics with https://github.com/devcontainers/spec/issues/434 and implement the agreed behavior in Dev Containers. Retain this issue for the product-side capability so feature consumers no longer need matching devcontainer.json entries.

- **Central request and remaining scope:** https://github.com/microsoft/vscode-remote-release/issues/7766 explicitly requests substitution inside devcontainer-feature.json, not devcontainer.json. The reporter clarified this distinction, and the June 2024 comment supplies a separate host-USER use case beyond DISPLAY.
- **Existing capability check:** https://containers.dev/implementors/json_reference/#general-properties documents ${localEnv:MY_VARIABLE} in devcontainer.json containerEnv. https://containers.dev/implementors/features/#devcontainer-feature-json-properties lists feature containerEnv but does not document equivalent localEnv substitution. Project-level configuration is a workaround, not the requested self-contained feature behavior.
- **X11 workaround is narrower:** In https://github.com/microsoft/vscode-remote-release/issues/7766, the maintainer explains that DISPLAY is automatically forwarded into VS Code's container process, not as a container environment variable. The reporter explicitly states the feature is intended to be more generally useful.
- **Related spec work is not a product canonical:** https://github.com/devcontainers/spec/issues/434 is open and requests localEnv substitution in feature metadata. A maintainer acknowledged the request at https://github.com/devcontainers/spec/issues/434#issuecomment-1962156740; a July 2026 commenter still reports the issue. Resolving a spec proposal alone would not demonstrate delivery in the Dev Containers extension.
