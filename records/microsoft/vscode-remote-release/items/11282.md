# Issue #11282 — Attached to wrong container

[https://github.com/microsoft/vscode-remote-release/issues/11282](https://github.com/microsoft/vscode-remote-release/issues/11282)

Keep open: an independent user confirmed attachment to the wrong container and supplied concrete shared-directory reproduction steps, addressing the information gap. The newer shared-server report describes connection refusal rather than successful attachment to another container, so it does not meet the re-review duplicate bar.

## Change summary

Attaching to a second running container can connect the editor to the first container when both share the VS Code Server directory.

## Best solution

The containers owner should ensure server discovery and connection state distinguish containers sharing a home directory. Retest the supplied two-container reproduction and investigate shared server metadata alongside the related connection-refusal report without assuming their fixes are identical.
