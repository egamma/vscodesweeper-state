# Issue #11389 — Cannot connect to windows host because uname is not found

[https://github.com/microsoft/vscode-remote-release/issues/11389](https://github.com/microsoft/vscode-remote-release/issues/11389)

## Summary

The supplied excerpt shows Remote - SSH correctly identifying Windows after `uname` fails, while the later failure involves a Windows command path being interpreted by bash. A current, complete log and environment details are needed to identify the actual failing path.

## Change summary

Remote - SSH fails to install or start the remote extension host on a Windows host without `uname`.

## Best solution

The SSH component should reproduce this on a supported stock Windows OpenSSH host without `uname`, then ensure the Windows bootstrap and extension-install commands do not pass Windows paths through a Unix shell.
