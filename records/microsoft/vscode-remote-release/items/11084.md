# Issue #11084 — localEnv in devcontainer does not have either $HOST or $HOSTNAME

[https://github.com/microsoft/vscode-remote-release/issues/11084](https://github.com/microsoft/vscode-remote-release/issues/11084)

## Summary

Keep open: the supplied configuration, launch method, and Docker log suffice to retest the empty hostname substitution. The report predates current releases, but neither resolution nor whether the cause is Dev Containers or VS Code's startup environment has been established.

## Change summary

Dev Containers substitutes an empty HOST or HOSTNAME into runArgs despite the hostname being visible in the local zsh terminal.

## Best solution

The containers owner should compare desktop-launch and fully restarted terminal-launch behavior with an exported HOSTNAME to distinguish startup-environment acquisition from substitution failure. If the defect is in VS Code's general shell-environment resolution, a maintainer can transfer this to microsoft/vscode.
