## Summary

The log confirms that `${localEnv:HOST}` resolves empty, but the remaining diagnostic—whether launching VS Code from a terminal exposes the variable—was never completed. A current-version retest is needed to distinguish a Dev Containers defect from the desktop launcher's environment.

## Change summary

Dev Containers substitutes an empty value for host variables defined by zsh, causing container creation with `--add-host` to fail.

## Best solution

The containers owner should confirm whether `localEnv` receives `HOST` when VS Code inherits it at process launch. If terminal launch works, the environment must be configured for the desktop session or the hostname supplied explicitly; otherwise, investigate Dev Containers' local-variable substitution.
