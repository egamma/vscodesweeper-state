# Issue #11084 — localEnv in devcontainer does not have either $HOST or $HOSTNAME

[https://github.com/microsoft/vscode-remote-release/issues/11084](https://github.com/microsoft/vscode-remote-release/issues/11084)

## Summary

The substitution is working as designed: `${localEnv:...}` reads the environment inherited by the VS Code process, while the desktop-launched process does not inherit variables initialized later by zsh.

## Change summary

Make `${localEnv:HOST}` or `${localEnv:HOSTNAME}` resolve shell-provided hostnames when VS Code is launched from an Arch Linux desktop shortcut.

## Best solution

Keep the current Dev Containers behavior. Launch VS Code from a terminal where the variable is exported, or define the hostname in the desktop session environment before starting VS Code.

- **Proposed comment:**

  > Thanks for the context. `${localEnv:...}` reads variables inherited by the VS Code process; it does not read variables initialized later by the integrated terminal's zsh. Because VS Code is being started from a desktop shortcut, `HOST` and `HOSTNAME` are absent from that process environment. Please launch `code` from a terminal where the variable is exported, or define it in the desktop session environment before starting VS Code. The documented environment-variable behavior is described at https://code.visualstudio.com/remote/advancedcontainers/environment-variables.
