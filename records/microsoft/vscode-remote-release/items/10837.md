# Issue #10837 — Fallback to previous container if failing to build

[https://github.com/microsoft/vscode-remote-release/issues/10837](https://github.com/microsoft/vscode-remote-release/issues/10837)

## Summary

Keep open: documented recovery and prebuild workflows do not restore the last working development environment after a failed rebuild. The request is already correctly routed to containers and accepted into Backlog; no verified canonical owns the same capability.

## Change summary

Offer reuse of the last working container or image when rebuilding a dev container fails.

## Best solution

The Dev Containers extension should retain a last-known-working environment and offer to reopen it after a failed rebuild, with explicit retention and cleanup behavior. A complete build-history interface is optional; retaining one working environment satisfies the reporter's central ask.
