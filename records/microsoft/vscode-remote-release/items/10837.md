# Issue #10837 — Fallback to previous container if failing to build

[https://github.com/microsoft/vscode-remote-release/issues/10837](https://github.com/microsoft/vscode-remote-release/issues/10837)

## Summary

This remains a valid, already-routed Dev Containers availability request. Documented recovery workflows allow local or recovery-container access after failure, but do not restore the last successful development environment.

## Change summary

Preserve and reopen the previous working dev container when rebuilding its replacement fails.

## Best solution

Dev Containers should retain or identify the last successful container image during rebuild and offer an explicit rollback or reopen command after failure, without replacing the existing recovery workflow.

## Evidence
