# Issue #11037 — DevContainer buildx re-pulls image although it already exists on the host

[https://github.com/microsoft/vscode-remote-release/issues/11037](https://github.com/microsoft/vscode-remote-release/issues/11037)

## Summary

Keep open for the containers owner: the named-volume workflow, configuration, and matching layer-download logs suffice to retest cache reuse with Podman. The recorded versions are old, but no current reproduction or confirmed fix establishes that repeated downloads are resolved.

## Change summary

Dev Containers repeatedly downloads base-image layers during named-volume rebuilds despite those layers already existing in the host's Podman image store.

## Best solution

The containers owner should distinguish expected separation between Podman's image store and BuildKit's cache from loss of reusable builder state across rebuilds, then preserve that state or correct builder selection if the bootstrap workflow discards it. Proxy fixes alone do not establish that this cache-reuse problem is resolved.
