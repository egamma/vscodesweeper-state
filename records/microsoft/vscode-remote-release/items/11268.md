# Issue #11268 — Memory leak from repeatedly spawing process

[https://github.com/microsoft/vscode-remote-release/issues/11268](https://github.com/microsoft/vscode-remote-release/issues/11268)

## Summary

Keep open as an upstream memory-retention issue triggered by Dev Containers polling. Related reports implicate Windows driver behavior, but neither a fix for this reporter nor an open canonical owning the retained-process leak is established.

## Change summary

Repeated docker.exe and conhost.exe launches leave retained process memory that accumulates until Windows becomes unusable.

## Best solution

Determine which Windows driver or system component retains the exited processes and pursue that upstream fix, using standalone Docker invocations to separate retention from extension polling. Track reducing excessive Dev Containers polling in https://github.com/microsoft/vscode-remote-release/issues/9627 without treating that mitigation as resolution of this leak.

## Evidence

- **Reported retention:** https://github.com/microsoft/vscode-remote-release/issues/11268 documents Dev Containers 0.427.0, VS Code 1.105.1 and Windows build 26100 on a Ryzen 9 7950X. A second affected user reports approximately 6 GB of page-table memory associated with docker.exe and conhost.exe; there is no resolution confirmation.
- **Upstream diagnosis:** https://github.com/docker/for-win/issues/14027 is open and reproduces retained processes through standalone docker context ls calls. Its reporter subsequently observed retention when starting other applications, and https://github.com/docker/for-win/issues/14027#issuecomment-2088425489 confirms an AMD driver downgrade resolved that reporter's case. This supports an upstream cause but does not prove the same driver or fix applies here.
- **Maintainer precedent:** https://github.com/microsoft/vscode-remote-release/issues/9804#issuecomment-2295884570 attributes the related leak to an AMD driver and requests driver-update testing. That issue closed for missing information, not a confirmed product fix.
- **Existing consolidation:** https://github.com/microsoft/vscode-remote-release/issues/10795 is closed and describes the same retained docker.exe/conhost.exe objects. Its maintainer explicitly points to this issue at https://github.com/microsoft/vscode-remote-release/issues/10795#issuecomment-3642991237, supporting keeping this report as the consolidation point.
- **Polling is related, not full coverage:** https://github.com/microsoft/vscode-remote-release/issues/9627 is open and owns excessive Docker-context polling, with a current-version confirmation at https://github.com/microsoft/vscode-remote-release/issues/9627#issuecomment-6242376962. Reducing launches mitigates exposure but does not establish cleanup of retained Windows process objects. https://github.com/microsoft/vscode-remote-release/issues/11377 instead concerns SSH reconnection and extension-host memory on macOS, not this failure.
