# Issue #11268 — Memory leak from repeatedly spawing process

[https://github.com/microsoft/vscode-remote-release/issues/11268](https://github.com/microsoft/vscode-remote-release/issues/11268)

## Summary

The accumulated zombie processes are an upstream Windows/driver resource-leak
triggered by frequent Docker CLI polling, not a Dev Containers memory leak. The issue is already
correctly classified and serves as the canonical report for possible extension-side mitigation.

## Change summary

Repeated Docker CLI polling from Dev Containers leaves terminated docker.exe
and conhost.exe processes consuming page-table memory on affected Windows systems.

## Best solution

The upstream Windows or driver component should release terminated-process
resources correctly; Dev Containers can reduce the impact by avoiding unnecessary Docker polling or
sharing it across windows.
