# Issue #4405 — Remote-Containers commands do not receive selection objects from remote Docker extension

[https://github.com/microsoft/vscode-remote-release/issues/4405](https://github.com/microsoft/vscode-remote-release/issues/4405)

## Summary

Keep this as the established tracker for missing selections across extension hosts. Later maintainer comments explicitly retain this issue as canonical; documented attachment workarounds do not restore selection passing or resolve volume inspection.

## Change summary

Preserve the selected Docker volume or container when invoking local Dev Containers commands from a remote extension's view.

## Best solution

Dev Containers and Docker integration should exchange a minimal selected-resource identifier across extension hosts, potentially through the selection-lookup command proposed in the thread. Retain this product-side tracker while evaluating that workaround; the closed core proposal is not a duplicate target.

## Evidence

- **Maintainer diagnosis and proposed remedy:** In https://github.com/microsoft/vscode-remote-release/issues/4405, the maintainer explains that Docker runs remotely in WSL while Remote-Containers runs locally on Windows, preventing selection delivery. A selection-lookup command is proposed; missing selections also produce a redundant container picker.
- **Established canonical:** https://github.com/microsoft/vscode-remote-release/issues/9206#issuecomment-1833967306 explicitly tracks the redundant Docker attachment picker under this issue. https://github.com/microsoft/vscode-remote-release/issues/10228#issuecomment-2342884229 repeats that ownership in September 2024 and identifies Remote Explorer as a workaround.
- **Related open issue is narrower:** https://github.com/microsoft/vscode-remote-release/issues/5849 remains open with 18 upvotes, but concerns Kubernetes attachment failing with 'No Pod name found', not the full Docker volume-inspection and container-selection scope here. Its maintainer explicitly attributes the cause to this issue at https://github.com/microsoft/vscode-remote-release/issues/5849#issuecomment-975927351; it does not satisfy the re-review duplicate bar.
- **Core dependency is closed without implementation:** https://github.com/microsoft/vscode/issues/111238 documents the cross-extension-host object-passing limitation and was closed as out of scope in December 2023. That closed proposal cannot serve as a duplicate canonical, and its decision does not establish that the proposed extension-level workaround should be declined.
- **Related shipped change preserves the limitation:** https://github.com/microsoft/vscode-remote-release/issues/6054#issuecomment-2342680343 announces Kubernetes attachment support in Dev Containers 0.386.0-pre-release but explicitly says the remote context-menu action still shows a picker due to limitations. The subsequent confirmation verifies attachment support, not restored selection passing.
- **Existing capability is only a workaround:** https://code.visualstudio.com/docs/devcontainers/attach-container documents 'Dev Containers: Attach to Running Container...' and Remote Explorer's inline attach action. These bypass the problematic Docker context-menu workflow; they do not demonstrate a fix for cross-host selection delivery or volume inspection.
