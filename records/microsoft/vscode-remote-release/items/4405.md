# Issue #4405 — Remote-Containers commands do not receive selection objects from remote Docker extension

[https://github.com/microsoft/vscode-remote-release/issues/4405](https://github.com/microsoft/vscode-remote-release/issues/4405)

## Summary

Keep open as an upstream VS Code extension-host limitation with a current Dev Containers impact. The core request was declined, but multiple later reports confirm that selecting a Docker object remotely still causes Dev Containers to ask for the same selection again.

## Change summary

Pass a Docker tree selection to Dev Containers commands across local and remote extension hosts, avoiding a redundant picker.

## Best solution

Dev Containers and the Docker extension should implement an extension-level selection lookup or another narrow handoff because the general VS Code core change was declined. The containers owner should coordinate that workaround while preserving this issue as the canonical tracker.

## Evidence

- **root cause:** A maintainer explains that the Docker tree runs in the remote WSL extension host while Dev Containers runs locally, so VS Code does not pass the selected object between them: https://github.com/microsoft/vscode-remote-release/issues/4405#issuecomment-772284409
- **upstream decision:** The exact cross-extension-host behavior was tracked by https://github.com/microsoft/vscode/issues/111238 and closed as not planned on 2023-12-13, without a fix.
- **workaround design:** A maintainer proposed having the Docker extension expose a command that Dev Containers could call to retrieve the current selection when no object is passed: https://github.com/microsoft/vscode-remote-release/issues/4405#issuecomment-772288203
- **continued reproduction:** The 2024 comment reports the same redundant container picker, while https://github.com/microsoft/vscode-remote-release/issues/9206 was consolidated into this issue after reproducing the same remote-host boundary.
