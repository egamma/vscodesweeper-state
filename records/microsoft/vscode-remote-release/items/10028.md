# Issue #10028 — Cannot connect multiple VS code windows to single docker container, despite menu options available

[https://github.com/microsoft/vscode-remote-release/issues/10028](https://github.com/microsoft/vscode-remote-release/issues/10028)

## Summary

Keep open: the documented multi-window capability has a remaining UX gap when attaching a second window to a container whose remembered folder is already open. The existing workaround does not make the Remote Explorer attach actions behave as labeled.

## Change summary

Allow separate VS Code windows to open different folders in one running container without the attach action focusing an existing window.

## Best solution

Dev Containers should let the attach-in-new-window action open an empty container window when its remembered folder is already open, or provide the setting suggested by the maintainer. This preserves folder reuse while making the explicit new-window action effective.

## Evidence

- **confirmed gap:** https://github.com/microsoft/vscode-remote-release/issues/10028 contains multiple confirmations through July 2026 that both Remote Explorer attach actions focus the first window instead of opening a different folder in another window.
- **maintainer diagnosis:** A maintainer explains in https://github.com/microsoft/vscode-remote-release/issues/10028 that Dev Containers automatically reopens the remembered folder and suggests either opening an empty window or adding a setting; VS Code currently exposes no extension API for detecting other open workspace URIs.
- **documented capability:** https://code.visualstudio.com/docs/devcontainers/faq documents opening another window and attaching to an already running container, while https://code.visualstudio.com/docs/devcontainers/attach-container documents that an attached-container configuration without workspaceFolder opens an empty window.
- **workaround is incomplete:** Setting Window: Open Folders In New Window allows opening another folder from an already attached window, but the October 2025 confirmation shows that Attach in Current Window and Attach in New Window still do not perform their advertised actions.
- **related issues:** https://github.com/microsoft/vscode-remote-release/issues/1737 is closed and led to the current new-window menu commands; https://github.com/microsoft/vscode-remote-release/issues/10646 tracks a distinct disconnection problem, as explicitly separated by the maintainer.
