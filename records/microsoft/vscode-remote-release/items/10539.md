# Issue #10539 — When rebuilding a dev container with dirty changes ask the user if they want to sync with the remote

[https://github.com/microsoft/vscode-remote-release/issues/10539](https://github.com/microsoft/vscode-remote-release/issues/10539)

## Summary

Keep open: the confirmed clean-worktree improvement explicitly excludes pending changes, and this request tracks the remaining opt-in synchronization flow. No verified canonical or documented capability covers that flow.

## Change summary

Offer to synchronize upstream repository changes before rebuilding a volume-cloned dev container even when its working tree has local modifications.

## Best solution

Dev Containers should offer an optional remote-update check before rebuilding a dirty volume-cloned repository, preserving local changes and allowing the user to decline synchronization. Decide how conflicts should be handled before using updated configuration for the rebuild.
