# Issue #10539 — When rebuilding a dev container with dirty changes ask the user if they want to sync with the remote

[https://github.com/microsoft/vscode-remote-release/issues/10539](https://github.com/microsoft/vscode-remote-release/issues/10539)

## Summary

A real Dev Containers workflow gap remains: rebuilds pull remote changes only when the repository cloned into the container volume is clean. This team-authored Backlog request is correctly routed and has no verified canonical duplicate.

## Change summary

When rebuilding a container-volume workspace with uncommitted changes, offer to synchronize remote commits before rebuilding so updated dev-container configuration is applied.

## Best solution

The Dev Containers rebuild flow should detect upstream changes in a dirty repository and offer a conflict-safe synchronization path that preserves local work before rebuilding.
