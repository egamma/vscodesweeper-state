# Issue #11363 — Error showed when use container

[https://github.com/microsoft/vscode-remote-release/issues/11363](https://github.com/microsoft/vscode-remote-release/issues/11363)

## Summary

Keep open as a Podman-specific filesystem-permission issue: the complete log shows a root-owned /tmp with mode 0755 preventing the vscode user from creating Java's socket, and the reporter confirms Docker works. The evidence identifies the immediate cause but not which build or runtime step changes the permissions.

## Change summary

Opening the supplied Java dev container with Podman leaves /tmp unwritable and workspace files root-owned, preventing the Java language server from connecting.

## Best solution

Determine whether the Podman build or runtime produces the incorrect /tmp permissions and workspace ownership, then address that behavior in the owning runtime or image/build tooling. Retain this report for the containers owner until ownership is established; the Java extension's socket failure is a consequence, not evidence of an extension defect.
