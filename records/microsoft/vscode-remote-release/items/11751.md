# Issue #11751 — Remote-SSH 0.124.0 remote child processes do not reliably inherit lowercase proxy variables

[https://github.com/microsoft/vscode-remote-release/issues/11751](https://github.com/microsoft/vscode-remote-release/issues/11751)

## Summary

Keep open for investigation of the reported lowercase-proxy regression. The supplied steps suffice to retest beyond the July versions, but there is no independent confirmation, verified fix, or canonical covering this behavior.

## Change summary

Remote startup and extension networking reportedly regress with lowercase-only proxy variables and recover after adding uppercase equivalents and restarting the server.

## Best solution

The SSH component owner should distinguish shell-environment capture from proxy-variable interpretation in the server and affected extensions. Preserve lowercase variables if propagation regressed, and document the supported behavior across launch paths.

## Evidence

- **Actionable regression report:** https://github.com/microsoft/vscode-remote-release/issues/11751 supplies VS Code 1.128.1, Remote-SSH 0.124.0, Ubuntu versions, reproduction steps, networking comparisons, and a log excerpt. Adding uppercase variables and NO_PROXY before a fresh session reportedly restores connectivity; no comments independently confirm the defect.
- **Root cause remains unverified:** The issue's interactive-shell curl tests establish proxy availability, not the environment inherited by the server or extension processes. The workaround also adds NO_PROXY and restarts the session, so it does not isolate dropped lowercase variables from proxy interpretation or stale process environments.
- **Documented workaround is not proof of intended restriction:** https://code.visualstudio.com/docs/remote/troubleshooting#_ssh-tips documents HTTP_PROXY and HTTPS_PROXY in the remote ~/.bashrc. It does not establish that lowercase variables must be discarded or that previously working lowercase-only networking is intentionally unsupported.

- **Investigation guidance:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-Troubleshooting requests complete Remote-SSH logs and identifies separate server-log locations for legacy and Exec Server modes. Those logs and a comparison of proxy-variable names in actual server/extension processes would help localize this report without assuming an upstream or third-party extension cause.
