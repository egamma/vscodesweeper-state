[https://github.com/microsoft/vscode-remote-release/issues/11368](https://github.com/microsoft/vscode-remote-release/issues/11368)

## Summary

Keep open: the report supplies reproducible steps, diagnostic output, and a Docker 28 control test for a Dev Containers auto-start regression. Later Docker-version and startup reports do not establish resolution or a matching canonical; the existing steps suffice for a current-release retest.

## Change summary

Dev Containers skips automatically launching Docker Desktop on macOS when Docker CLI 29 reports that the daemon is unavailable.

## Best solution

The Dev Containers owner should retest the supplied stopped-Docker scenario and restore daemon-unavailable detection for Docker CLI 29 without treating unrelated connection failures as launch requests. Preserve the working Docker 28 behavior.
