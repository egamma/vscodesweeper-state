# Issue #9195 — Remote - Tunnels does not forward to localhost when using VS Code client

[https://github.com/microsoft/vscode-remote-release/issues/9195](https://github.com/microsoft/vscode-remote-release/issues/9195)

## Summary

Keep open as the canonical Tunnels bug: multiple reports confirm that desktop clients receive a devtunnels URL instead of localhost forwarding, breaking OAuth and general TCP workflows. This team-authored issue already has the correct component label.

## Change summary

Remote Tunnels should support forwarding remote ports to the desktop client's localhost rather than exposing them only through HTTPS devtunnels URLs.

## Best solution

The Tunnels/dev-tunnels connection path should offer client-side loopback forwarding for desktop clients while retaining hosted devtunnels URLs where appropriate. Consolidate the newer overlapping request into this established canonical issue.
