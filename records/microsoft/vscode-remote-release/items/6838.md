# Issue #6838 — [remote] Drag and dropping a \\wsl$\ file to a WSL window results in watcher issues.

[https://github.com/microsoft/vscode-remote-release/issues/6838](https://github.com/microsoft/vscode-remote-release/issues/6838)

## Summary

Keep open: a maintainer reproduced the incorrect Windows-path handling and proposed automatic Linux-path conversion. The supplied steps and logs suffice for retesting on current releases; there is no verified fix or same-symptom canonical.

## Change summary

Dropping a same-distro file from Windows File Explorer into a WSL window opens its Windows UNC path, causing watcher failures and stale editor contents.

## Best solution

The WSL integration should open dropped files from the window's own distro through their remote Linux paths, preserving file watching and access by Linux tooling. Retest the documented drag-and-drop scenario on current releases before deciding whether implementation work remains.
