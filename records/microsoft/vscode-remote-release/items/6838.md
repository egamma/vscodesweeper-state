# Issue #6838 — [remote] Drag and dropping a \\wsl$\ file to a WSL window results in watcher issues.

[https://github.com/microsoft/vscode-remote-release/issues/6838](https://github.com/microsoft/vscode-remote-release/issues/6838)

## Summary

This remains a reproduced WSL integration bug: dragging a distro file from Windows Explorer opens its UNC resource in the WSL window instead of converting it to the equivalent Linux path, causing file-watcher failures. No open canonical found owns this exact behavior.

## Change summary

Convert dragged \\wsl$ files to Linux paths when they belong to the distro backing the current WSL window.

## Best solution

The WSL integration should translate an incoming UNC resource for the active distro into its Linux path before opening it, ensuring editors, watchers, and Linux-hosted tools all use the same resource.
