# Issue #11538 — Remote-SSH fails to recover from stale server metadata after system crash

[https://github.com/microsoft/vscode-remote-release/issues/11538](https://github.com/microsoft/vscode-remote-release/issues/11538)

## Summary

Keep open: the merged core keepalive fix detects silent connection failures but does not establish recovery from stale Remote-SSH metadata after a crash. The supplied SIGKILL steps, versions, and logs suffice to retest; no subsequent resolution is confirmed.

## Change summary

Remote-SSH reuses dead local connection metadata after an unclean shutdown, preventing reconnection and defeating the built-in server cleanup command.

## Best solution

Remote-SSH should validate cached local connection state before reuse, discard invalid metadata, and establish a fresh connection when its IPC socket or SOCKS listener is gone. Its cleanup command should remain usable when the cached local connection is dead.
