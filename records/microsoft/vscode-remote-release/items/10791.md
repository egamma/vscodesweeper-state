# Issue #10791 — X applications can not start in devcontainer under Xwayland because of missing X authentication

[https://github.com/microsoft/vscode-remote-release/issues/10791](https://github.com/microsoft/vscode-remote-release/issues/10791)

## Summary

Keep open: automatic Xwayland authentication remains an actionable Dev Containers request. The thread provides a custom-script workaround, not evidence that the extension now supplies this integration.

## Change summary

Use the host's XAUTHORITY data so X applications launched inside a dev container work under Wayland without manual authentication setup.

## Best solution

The Dev Containers owner should evaluate automatic use of the host's XAUTHORITY file in its existing X display forwarding, preserving authentication rather than requiring relaxed host access controls. The supplied sample and initialization workaround provide concrete starting points.
