# Issue #3454 — WSL 2 connection lost after too much time in Modern Standby

[https://github.com/microsoft/vscode-remote-release/issues/3454](https://github.com/microsoft/vscode-remote-release/issues/3454)

## Summary

Keep open: the overnight Modern Standby steps suffice to retest, and no confirmation establishes that this report is resolved. Connection handling and related resume fixes have changed since the reports, but neither a full-scope fix nor an eligible duplicate canonical is verified.

## Change summary

WSL 2 sessions fail to reconnect after prolonged Modern Standby despite the distro remaining running, forcing window reloads or WSL restarts.

## Best solution

The WSL component should verify overnight reconnection on current releases and preserve existing server sessions when the distro remains healthy. Separate failures involving Wsl/Service/E_UNEXPECTED into the upstream WSL investigation rather than attributing every standby failure to that cause.
