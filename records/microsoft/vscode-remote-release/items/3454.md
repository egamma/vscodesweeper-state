# Issue #3454 — WSL 2 connection lost after too much time in Modern Standby

[https://github.com/microsoft/vscode-remote-release/issues/3454](https://github.com/microsoft/vscode-remote-release/issues/3454)

## Summary

Keep open: multiple users still reproduce failed WSL reconnection after standby on recent releases, and the latest maintainer investigation identifies another plausible wall-clock-time defect in VS Code's connection handling.

## Change summary

VS Code should restore its WSL 2 connection after a long Modern Standby period without requiring the window or WSL service to be restarted.

## Best solution

The WSL and VS Code connection owners should make reconnect timers resilient to suspended wall-clock time and verify recovery while the WSL distro remains healthy. Reports where WSL itself returns `Wsl/Service/E_UNEXPECTED` should remain separated as upstream WSL failures.
