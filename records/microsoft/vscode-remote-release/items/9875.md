# Issue #9875 — using "vscode-remote://attached-container" url from wsl erroneously converts slashes to backslashes

[https://github.com/microsoft/vscode-remote-release/issues/9875](https://github.com/microsoft/vscode-remote-release/issues/9875)

## Summary

Keep open to investigate the reported remote-URI slash conversion. The supplied command and environment suffice to retest against current releases; the older versions and absence of confirmations do not establish resolution.

## Change summary

Launching an attached-container URI from WSL reportedly converts /server/ui into a file path containing Windows backslashes.

## Best solution

The containers owner should retest the WSL-to-container CLI handoff, separating URI path preservation from file-versus-folder selection. Preserve Linux separators in remote paths and use --folder-uri for the intended directory-opening operation.
