# Issue #11222 — Allow using only single connection for certain servers to support distributed cluster servers

[https://github.com/microsoft/vscode-remote-release/issues/11222](https://github.com/microsoft/vscode-remote-release/issues/11222)

## Summary

The documented per-host OpenSSH ControlMaster configuration already addresses dynamically assigned cluster nodes by multiplexing Remote - SSH's two sessions through one underlying connection.

## Change summary

Allow Remote - SSH to use one connection when successive SSH sessions may reach different cluster nodes.

## Best solution

Keep the current architecture and use a host-specific ControlMaster configuration on supported macOS/Linux clients, ensuring both Remote - SSH sessions reach the same cluster node.

- **Proposed comment:**

  > Thanks for the request. Remote - SSH documents this cluster-routing scenario and supports it through OpenSSH connection multiplexing on macOS/Linux clients. A host-specific SSH configuration such as `ControlMaster auto`, `ControlPath ~/.ssh/sockets/%r@%h-%p`, and `ControlPersist 600` makes the extension's two SSH sessions share one underlying connection and therefore reach the same node. See https://code.visualstudio.com/docs/remote/troubleshooting#_connecting-to-systems-that-dynamically-assign-machines-per-connection.

- **per-host configuration:** The documented ControlMaster, ControlPath, and ControlPersist options can be placed in the affected SSH Host stanza, limiting the behavior to that server; this is supported on macOS/Linux clients.
