# Issue #11222 — Allow using only single connection for certain servers to support distributed cluster servers

[https://github.com/microsoft/vscode-remote-release/issues/11222](https://github.com/microsoft/vscode-remote-release/issues/11222)

## Summary

Keep open: the documented ControlMaster workaround only covers some clients, and socket mode disables the extension's connection multiplexing. No verified canonical owns the full request for single-connection socket access to dynamically assigned cluster nodes.

## Change summary

Allow Remote - SSH to start the server and forward its Unix socket through one SSH connection when separate connections reach different cluster nodes.

## Best solution

The SSH component should determine how to retain node affinity through server startup and Unix-socket forwarding without requiring TCP listeners or independently routed connections. Coordinate with the existing socket/local-server investigation while preserving this cluster-specific requirement.

## Evidence

- **requested capability:** https://github.com/microsoft/vscode-remote-release/issues/11222 describes a provider that disallows TCP listeners and routes separate SSH connections to different nodes. Sharing home directories through Ceph does not make a Unix socket usable from another node.
- **existing-capability check:** https://code.visualstudio.com/docs/remote/troubleshooting#_connecting-to-systems-that-dynamically-assign-machines-per-connection documents the two-connection node-affinity problem and recommends OpenSSH ControlMaster for macOS/Linux clients. This is a conditional workaround, not documented cross-platform single-connection support.
- **socket-mode limitation:** https://code.visualstudio.com/docs/remote/troubleshooting#_improving-security-on-multi-user-servers documents remote.SSH.remoteServerListenOnSocket and explicitly states that socket mode disables connection multiplexing. The documentation does not establish that the reporter's combined constraints are already satisfied.
- **related investigation:** https://github.com/microsoft/vscode-remote-release/issues/6086 is open in On Deck. Its maintainer-defined scope is using remoteServerListenOnSocket with useLocalServer, per https://github.com/microsoft/vscode-remote-release/issues/6086#issuecomment-1351895665. That is related, but the discussion does not establish that resolving those settings together guarantees single-connection forwarding for dynamically assigned nodes.
- **candidate excluded:** https://github.com/microsoft/vscode-remote-release/issues/1257 is open but describes repeated disconnects when opening a large workspace, including disruption of existing ControlMaster sessions. It does not own the socket/node-affinity capability requested here.
