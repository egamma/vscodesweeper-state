# Issue #8728 — dev.containers.dockerPath should work as remote.containers.dockerPath did

[https://github.com/microsoft/vscode-remote-release/issues/8728](https://github.com/microsoft/vscode-remote-release/issues/8728)

## Summary

Keep open in the Backlog: the current application-scoped Docker Path setting does not cover users who need different Docker-compatible CLIs for different remote hosts or WSL distributions. The request has substantial community support and no documented contextual alternative.

## Change summary

Allow `dev.containers.dockerPath` to vary by remote host or workspace as the former `remote.containers.dockerPath` setting did.

## Best solution

The Dev Containers extension should support selecting the Docker-compatible CLI at remote or workspace scope while retaining an application-level default, allowing Docker and Podman environments to coexist without repeatedly editing global settings.
