# Issue #11556 — [Remote-SSH Bug]: spawn rg ENOENT on global search when .code-workspace folder uses vscode-remote:// URI

## Summary

Keep open: the workspace example and search steps suffice to retest, but no current-release confirmation or verified fix establishes resolution since the reported VS Code 1.113 failure. The related older report was closed for missing information, not because this behavior was fixed.

## Change summary

Global search fails with ripgrep ENOENT when an SSH workspace defines its folder using a vscode-remote URI, while opening the folder directly works.

## Best solution

Restore search parity between saved remote workspaces and directly opened SSH folders, checking the reported URI-to-filesystem-path conversion before spawning ripgrep. If reproduction localizes the defect to core workspace/search handling rather than Remote - SSH, a maintainer can transfer this to microsoft/vscode.
