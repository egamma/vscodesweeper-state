# Issue #9296 — Cannot start a dev container when connected to WSL2 through VSCode Tunnels

[https://github.com/microsoft/vscode-remote-release/issues/9296](https://github.com/microsoft/vscode-remote-release/issues/9296)

## Summary

Keep open in the Backlog: direct Tunnel-to-Container support exists, but the nested Tunnel-to-WSL-to-Container workflow remains unsupported and has many independent confirmations. This older, better-supported report should remain the canonical issue.

## Change summary

Support reopening a WSL2 workspace in a Dev Container when the Windows host is reached through Remote Tunnels.

## Best solution

The Dev Containers component should execute WSL and container operations on the tunneled Windows host rather than the local client, coordinating with the Tunnels and WSL components for nested remote-authority handling.
