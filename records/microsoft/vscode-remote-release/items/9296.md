# Issue #9296 — Cannot start a dev container when connected to WSL2 through VSCode Tunnels

[https://github.com/microsoft/vscode-remote-release/issues/9296](https://github.com/microsoft/vscode-remote-release/issues/9296)

## Summary

Keep the accepted nested Tunnels -> WSL2 -> Dev Containers capability open. Documented direct container access and the available attachment workaround do not establish that rebuilding a container from the tunneled WSL workspace works.

## Change summary

Allow Reopen in Container to build and open a dev container from a WSL2 workspace reached through a Windows tunnel.

## Best solution

The Dev Containers owner should make container lifecycle commands execute against the remote WSL environment rather than attempting to launch wsl on the client. Coordinate with WSL and Tunnels owners, retaining this report until the nested workflow is supported or a canonical covering its failure is verified.
