# Issue #11246 — Various SSH timeout usability issues

[https://github.com/microsoft/vscode-remote-release/issues/11246](https://github.com/microsoft/vscode-remote-release/issues/11246)

## Summary

A concrete Remote - SSH recovery-flow gap remains: after the documented timeout, Retry repeats the insufficient limit and Open Settings cannot be used until the remote window is closed. The existing configurable timeout addresses advance configuration, not recovery from this state.

## Change summary

Make SSH timeout recovery easier by offering a higher-timeout retry or allowing the connection timeout setting to be changed without first closing the remote window.

## Best solution

Remote - SSH should let users recover directly from its timeout notification, either by retrying with a larger temporary timeout or by opening an editable user-level `remote.SSH.connectTimeout` setting before reconnecting.
