# Issue #11872 — Dev Containers stabilization watchers trigger O(n) security.selinux reads every second

[https://github.com/microsoft/vscode-remote-release/issues/11872](https://github.com/microsoft/vscode-remote-release/issues/11872)

## Summary

Keep open for Dev Containers investigation: the VS Code 1.139.0 report supplies concrete watcher commands and syscall traces sufficient to retest on current releases. No subsequent fix, resolution confirmation, or canonical issue covering the unnecessary xattr polling was established.

## Change summary

Dev Containers stabilization watchers repeatedly invoke long-format GNU ls, causing per-entry SELinux xattr reads and substantial audit overhead in an otherwise idle container.

## Best solution

Dev Containers should detect settings and extension-directory changes without requesting ACL or SELinux metadata, while preserving timestamp precision and existing stabilization behavior. The suggested stat command uses whole-second mtimes, so it is not a behavior-preserving replacement without further refinement.
