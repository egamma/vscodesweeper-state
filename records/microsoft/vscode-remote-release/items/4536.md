# Issue #4536 — Constantly losing WSL connection 

[https://github.com/microsoft/vscode-remote-release/issues/4536](https://github.com/microsoft/vscode-remote-release/issues/4536)

## Summary

The WSL disconnect and endless reconnect failure remains current, with independent reports through August 2026. The thread combines extension workload pressure, WSL memory exhaustion, and upstream sleep/resume failures, so it should remain open as the broader connection tracker rather than be closed against a narrower cause.

## Change summary

VS Code loses its WSL connection during normal work and can remain stuck reconnecting while the WSL filesystem or terminal becomes unavailable.

## Best solution

The WSL component should distinguish VS Code Server or extension-host resource exhaustion from failures of the WSL service, improve recovery when the remote endpoint disappears, and route diagnosed platform failures to their corresponding microsoft/WSL issues.
