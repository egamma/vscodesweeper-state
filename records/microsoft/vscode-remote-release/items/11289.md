# Issue #11289 — SSH-Remote Extension Host will not Initialize if Unless Force the Server to Download

[https://github.com/microsoft/vscode-remote-release/issues/11289](https://github.com/microsoft/vscode-remote-release/issues/11289)

## Summary

Keep open: the connect–Reload Window sequence and logs suffice to retest the server-reuse failure. Releases have advanced since the reported 1.104 regression, but neither a confirmed fix nor a canonical covering this specific trigger is established.

## Change summary

Reloading an SSH window stalls remote extension-host initialization until the installed server binaries are removed and downloaded again.

## Best solution

The SSH owner should compare successful fresh-server startup with failed server reuse on the reported Windows-to-RHEL connection, using server and remote extension-host logs to distinguish initialization failure from transport loss. Restore reliable reload and reconnection without requiring server reinstallation.

## Evidence

- **Concrete trigger and failure:** https://github.com/microsoft/vscode-remote-release/issues/11289 supplies a connect–Developer: Reload Window reproduction and reports regression from 99.x to 104.0. Logs show an existing RHEL x64 server being reused, successful forwarding, subsequent SSH connection reset, and 'The remote extension host took longer than 60s to send its ready message.' These establish a startup/reconnection stall, not a demonstrated process crash.
- **Historical corroboration:** https://github.com/microsoft/vscode-remote-release/issues/11289#issuecomment-3529076538 independently confirms the failure and recovery after removing vscode-server/bin. This November 2025 confirmation supports the report but does not establish reproduction on current releases.
- **Older related reports are not verified canonicals:** https://github.com/microsoft/vscode-remote-release/issues/7497 remains open but describes extension-host timeouts associated with workload, code lenses, and installed extensions rather than this deterministic reload/server-reuse trigger. https://github.com/microsoft/vscode-remote-release/issues/9488 remains open but documents save-related stalls and JavaScript heap exhaustion. Shared reconnect symptoms do not establish ownership of this re-reviewed report.
- **Newer failure modes differ:** https://github.com/microsoft/vscode-remote-release/issues/11538 concerns dead local IPC/SOCKS metadata after an unclean client shutdown, whereas this report establishes forwarding before a remote readiness timeout. https://github.com/microsoft/vscode-remote-release/issues/11358 concerns navigator PendingMigrationError during resolver activation; that error is absent from this report. Neither is a verified canonical for the reported reload failure.
- **Authoritative diagnostic guidance:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting recommends checking Developer Tools after SSH connects, inspecting the server log at the location printed during startup, and comparing connection modes. Its server-reset command is a troubleshooting workaround, not proof that recurring reinstallation is intended or that this issue is resolved.
