# Issue #11850 — On Windows, ssh discovery uses the Git for Windows fallback even when ssh was already found in PATH, breaking ProxyJump

[https://github.com/microsoft/vscode-remote-release/issues/11850](https://github.com/microsoft/vscode-remote-release/issues/11850)

## Summary

Keep open for Remote - SSH: the logs show local-server mode selecting Git's SSH after successfully finding Windows OpenSSH in PATH, contrary to documented precedence. The supplied reproduction is sufficient to retest; resolution on a newer release is not established.

## Change summary

Remote - SSH's Windows client discovery overrides a successful PATH match with Git's fallback client, breaking ProxyJump connections.

## Best solution

Remote - SSH should honor documented PATH-first discovery consistently across connection modes, using Git's installation path only when PATH discovery fails. Keep explicit remote.SSH.path selection as a workaround, not a replacement for correcting automatic discovery.
