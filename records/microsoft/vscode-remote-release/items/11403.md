# Issue #11403 — Cannot re-connect to windows host

[https://github.com/microsoft/vscode-remote-release/issues/11403](https://github.com/microsoft/vscode-remote-release/issues/11403)

## Summary

Keep open: the linked fix PR explicitly references this issue and remains unmerged. Later reports show the same Windows reconnect failure; the existing steps and logs suffice to retest without requesting more information.

## Change summary

Reconnecting to a running Windows server fails when configured extensions are installed through Bash instead of a Windows-native script launcher.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/328660, then verify reconnecting with non-empty remote.SSH.defaultExtensions on Windows. The proposed fix belongs to the public VS Code CLI used by Remote-SSH; a maintainer can transfer this to microsoft/vscode if needed.

## Evidence

- **Concrete reconnect trigger:** https://github.com/microsoft/vscode-remote-release/issues/11403 provides versions, settings, logs, and steps: first connection succeeds, but Reload Window or another connection fails after 'Found running server' and 'Installing extensions...'. The error shows Bash consuming backslashes in the Windows code-server.cmd path.
- **Open implementation candidate blocks closure:** https://github.com/microsoft/vscode/pull/328660 is verified open and unmerged, with 'Fixes microsoft/vscode-remote-release#11403' in its body. Its proposed cli/src/tunnels/code_server.rs diff replaces unconditional capture_command("bash", ...) with a platform-aware script command and individual extension arguments. This is pending work, not a landed fix.
- **Workarounds are not shipped resolution:** https://github.com/microsoft/vscode-remote-release/issues/11403#issuecomment-3706824219 reports that killing the running server restores connection; https://github.com/microsoft/vscode-remote-release/issues/11403#issuecomment-4108325321 reports success with useExecServer disabled. The shim test on VS Code 1.131.0 and Remote-SSH 0.124.0 at https://github.com/microsoft/vscode-remote-release/issues/11403#issuecomment-5165709658 explicitly describes a local workaround, not confirmation of an official fix.
- **Related reports do not supersede this issue:** https://github.com/microsoft/vscode-remote-release/issues/11911 remains open and reports the same first-connect-success/reload-failure pattern on VS Code 1.142.0 and Remote-SSH 0.128.0, but is younger and has no milestone; the fixing PR references this older issue. https://github.com/microsoft/vscode-remote-release/issues/11947 explicitly distinguishes its ENOTSUP socket-handoff failure from this Bash extension-installation failure. Canonical searches for Windows extension installation and Bash reconnect failures yielded no additional candidates.
- **Authoritative troubleshooting:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting recommends testing useExecServer disabled and explains that exec-server mode bootstraps a control server before launching the full server. That diagnostic workaround does not establish that reconnect failure in the enabled mode is intentional or resolved.
