# Issue #11193 — downloaded wsl server cache in windows side never be clean

[https://github.com/microsoft/vscode-remote-release/issues/11193](https://github.com/microsoft/vscode-remote-release/issues/11193)

## Summary

This remains a valid WSL cache-management request: obsolete Windows-side server downloads accumulate across upgrades, and no documented retention or cleanup control covers the central ask. The older, better-routed report should remain open as the canonical issue.

## Change summary

Automatically prune obsolete WSL server downloads on Windows and consider storing the cache under LocalAppData instead of the user-profile root.

## Best solution

The WSL extension should bound the Windows-side server cache by retaining only the current and a small number of recent downloads, while placing disposable cache data in an appropriate LocalAppData location. The component owner should also consolidate the newer matching report into this issue.
