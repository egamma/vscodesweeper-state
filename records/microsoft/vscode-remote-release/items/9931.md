# Issue #9931 — permissions on volume mounts not set to remoteUser

[https://github.com/microsoft/vscode-remote-release/issues/9931](https://github.com/microsoft/vscode-remote-release/issues/9931)

## Summary

Keep this accepted Dev Containers feature request open: documented ownership workarounds do not provide automatic permissions for arbitrary named volumes, particularly before server initialization. No verified canonical owns the full remaining request.

## Change summary

Provide named-volume ownership matching remoteUser, or an early privileged initialization mechanism that avoids hard-coded per-mount repairs.

## Best solution

The containers owner should define an opt-in way to initialize declared named-volume permissions for the resolved remote user before server setup, without changing existing entrypoint requirements or unexpectedly rewriting persistent data ownership.
