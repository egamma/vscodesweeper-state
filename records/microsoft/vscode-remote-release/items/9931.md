# Issue #9931 — permissions on volume mounts not set to remoteUser

[https://github.com/microsoft/vscode-remote-release/issues/9931](https://github.com/microsoft/vscode-remote-release/issues/9931)

## Summary

Keep open: this team-authored feature request reached the 10-upvote threshold and was accepted into the Backlog. The documented ownership workaround requires known paths and elevated lifecycle commands, leaving dynamic named-volume scenarios unresolved.

## Change summary

Provide a supported way to make named volumes writable by the configured non-root container or remote user before VS Code and lifecycle commands access them.

## Best solution

The Dev Containers owner should design an explicit, opt-in mechanism that adjusts named-volume ownership before server startup and lifecycle hooks, including dynamically selected Clone in Named Volume targets. Any new devcontainer.json or Feature property should be coordinated with the open Dev Container specification.
