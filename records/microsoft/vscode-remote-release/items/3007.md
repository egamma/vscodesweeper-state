# Issue #3007 — Add envFile to devcontainer.json and handle missing env file gracefully

[https://github.com/microsoft/vscode-remote-release/issues/3007](https://github.com/microsoft/vscode-remote-release/issues/3007)

## Summary

Keep open: documented env-file support still does not cover optional files with warnings in Dockerfile/image dev containers. Recovery containers and initialization scripts are workarounds, and the verified related issues do not own this remaining capability.

## Change summary

Add an envFile configuration property that warns rather than aborting container creation when an optional environment file is missing.

## Best solution

The Dev Containers component should support explicitly optional environment files with a clear warning, coordinating any new devcontainer.json property with the specification. Preserve failures for required files rather than silently ignoring all missing configuration.

## Evidence

- **Existing capability check:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables still documents runArgs: ["--env-file", "..."] for Dockerfile/image containers, not an optional envFile property. Automatic .env loading is attributed to Docker Compose, not to all dev containers.
- **Public schema:** https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json defines runArgs, containerEnv, remoteEnv, and host-side initializeCommand, but no envFile property. These existing properties do not directly provide the requested warning-and-continue behavior.
- **Partial Compose capability:** https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/ documents env_file.required: false since Compose 2.24.0. This silently ignores missing files in Compose scenarios; it does not deliver the requested warning or cover the reporter's Docker runArgs workflow.
- **Thread direction and workaround limits:** https://github.com/microsoft/vscode-remote-release/issues/3007#issuecomment-641651403 clarifies that VS Code 1.46 recovery containers are error-recovery tools and discusses a possible property for non-Compose scenarios. https://github.com/microsoft/vscode-remote-release/issues/3007#issuecomment-1942968611 identifies host-platform limitations of touch/cp and offers paired Windows/Unix scripts, not native optional-file handling.
- **Canonical search:** Verified open https://github.com/microsoft/vscode-remote-release/issues/2706 concerns selecting an existing Compose environment file; https://github.com/microsoft/vscode-remote-release/issues/4885 concerns Compose project naming; https://github.com/microsoft/vscode-remote-release/issues/3150 concerns automatic loading of an existing .env. None owns this report's missing-file warning behavior or satisfies the re-review duplicate bar.
- **Cross-repository boundary:** https://github.com/devcontainers/cli/issues/772 requests secrets-file values in containerEnv rather than remoteEnv. It does not cover optional missing files or establish that the Dev Containers extension ships this capability, so it is related context rather than a canonical duplicate.
