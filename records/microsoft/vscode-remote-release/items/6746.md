# Issue #6746 — Alterating PATH env invalidate project bazel cache

[https://github.com/microsoft/vscode-remote-release/issues/6746](https://github.com/microsoft/vscode-remote-release/issues/6746)

## Summary

Keep open: maintainers discussed making remote CLI PATH injection optional, but the thread establishes only a workaround, not a shipped solution. No verified open canonical owns the Bazel cache-invalidation problem.

## Change summary

Prevent version-dependent remote CLI PATH entries from invalidating Bazel caches across VS Code updates and between dev-container and docker-run builds.

## Best solution

Dev Containers and the VS Code Server owners should provide a supported way to preserve the container's build PATH, such as optional remote CLI PATH injection. Any stable-link alternative must also preserve cache compatibility with docker-run builds and avoid conflicts between concurrent VS Code versions.

## Vision fit

- **Fit:** aligned
- **Reason:** Preserving build-cache compatibility makes development inside VS Code containers behave more like the same environment outside VS Code.
- **Evidence:** The public parity promise is to open any folder in a container and take advantage of VS Code's full feature set; dev-container capability depth is a durable theme.
