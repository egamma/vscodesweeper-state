# Issue #6746 — Alterating PATH env invalidate project bazel cache

[https://github.com/microsoft/vscode-remote-release/issues/6746](https://github.com/microsoft/vscode-remote-release/issues/6746)

## Summary

A real Dev Containers gap remains: VS Code injects a version-specific remote CLI path that changes Bazel action keys, while the documented environment controls and shell workaround do not provide a supported way to disable that injection. The issue is already correctly classified and parked in Backlog.

## Change summary

Provide a stable or optional remote CLI PATH entry so VS Code updates do not invalidate Bazel caches inside dev containers.

## Best solution

Dev Containers and the VS Code Server should provide a supported way to disable the remote CLI PATH injection or expose it through a stable path, while preserving the current CLI behavior by default.
