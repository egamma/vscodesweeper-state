# Issue #11648 — Provide a way to reset Remote-SSH connection state without reloading the window

[https://github.com/microsoft/vscode-remote-release/issues/11648](https://github.com/microsoft/vscode-remote-release/issues/11648)

## Summary

VS Code core explicitly treats a workbench window and its remote extension-host process as one lifecycle, so reconnecting that window to a newly started host after token invalidation is unsupported by design.

## Change summary

Add an extension-callable command that clears stale reconnection tokens and reconnects to a restarted remote server without reloading the window.

## Best solution

Keep the established window/extension-host lifecycle, while improving state restoration across the required reload and presenting a clear recovery action when a reconnection token is rejected. Those improvements belong in microsoft/vscode rather than a Remote-SSH reset command.

  > Thanks for the detailed analysis. VS Code core has already considered this lifecycle in https://github.com/microsoft/vscode/issues/204830, including the same unknown-reconnection-token failure after a backend restart. The maintainer decision there is that a workbench window and its remote extension host live together, so an existing window cannot reconnect to a newly started extension-host process.
  > 
  > The documented Close Remote Connection and Kill VS Code Server commands do not preserve the current session, but exposing a reset command cannot change that core lifecycle. Given that established design, this request should be closed as designed; state restoration across the required reload would need to be improved in microsoft/vscode.

## Evidence

- **core design precedent:** https://github.com/microsoft/vscode/issues/204830 reports the same unknown-token failure after a remote server restart and requests reconnection without reloading. A VS Code maintainer states that this is by design because a window and extension host live together and the same window cannot connect to a new remote extension-host process.
- **existing commands:** https://code.visualstudio.com/docs/remote/ssh documents File > Close Remote Connection, while https://code.visualstudio.com/docs/remote/troubleshooting documents Remote-SSH: Kill VS Code Server on Host. Neither preserves the current window while replacing its remote extension host, so no documented command already provides the requested behavior.
