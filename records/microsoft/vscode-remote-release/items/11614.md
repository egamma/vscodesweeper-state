Keep open: the report supplies concrete steps to retest socket cleanup after a refused upstream connection. There is no current-release confirmation or verified fix since the April report, and the related forwarding issues do not own this error-propagation gap.

## Change summary

Forwarded ports leave accepted local client sockets hanging after the remote target refuses the connection.

## Best solution

The SSH/VS Code Server forwarding owners should reproduce the no-listener case and ensure upstream connection failures promptly terminate the accepted downstream socket without disrupting the remote session.
