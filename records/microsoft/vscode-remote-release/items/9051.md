# Issue #9051 — [WSL] Cannot open `code` via integrated terminal in VS Code when systemd is enabled

[https://github.com/microsoft/vscode-remote-release/issues/9051](https://github.com/microsoft/vscode-remote-release/issues/9051)

## Summary

Keep open: the discussion points to WSL/systemd removing or mis-owning the runtime directory containing VS Code's IPC sockets. Workarounds have mixed results, and there is no confirmed shipped fix for this report.

## Change summary

Running code from an integrated WSL terminal stops opening VS Code after several minutes with systemd enabled because its IPC socket disappears.

## Best solution

Restore a persistent, correctly owned user runtime directory through WSL/systemd session handling, following the upstream investigation. The WSL component owner should retain this report until that resolves the integrated-terminal workflow or establishes a separate server-side recovery requirement.
