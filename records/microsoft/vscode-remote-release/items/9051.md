# Issue #9051 — [WSL] Cannot open `code` via integrated terminal in VS Code when systemd is enabled

[https://github.com/microsoft/vscode-remote-release/issues/9051](https://github.com/microsoft/vscode-remote-release/issues/9051)

## Summary

Keep open as WSL integration debt. Multiple users observed the integrated terminal retaining an unusable IPC socket after the systemd-managed runtime directory disappeared or became inaccessible, and the issue is already accepted in the Backlog.

## Change summary

Keep the `code` command functional in WSL integrated terminals when systemd changes or recreates `/run/user/$UID`.

## Best solution

The WSL integration should avoid retaining a stale `VSCODE_IPC_HOOK_CLI` endpoint when the systemd user runtime directory changes, or recover the CLI connection when that endpoint disappears. The component owner should also distinguish extension recovery work from underlying WSL/systemd runtime-directory failures.
