# Issue #11005 — dev.containers.executeInWSL causes containers to run dev containers even on local windows

[https://github.com/microsoft/vscode-remote-release/issues/11005](https://github.com/microsoft/vscode-remote-release/issues/11005)

## Summary

Keep open for the Dev Containers owner: the reported problem is premature initialization, not an automatically started container. The supplied folder-opening workflow and setting suffice to retest; newer WSL initialization reports do not establish that this behavior was fixed or superseded.

## Change summary

Opening an ordinary Windows workspace with dev.containers.executeInWSL enabled unexpectedly triggers Dev Containers initialization without a container command.

## Best solution

The Dev Containers owner should retest opening the vscode and xterm.js workspaces with executeInWSL enabled and defer unnecessary initialization until a container operation requires it. Preserve intentional WSL execution for explicitly requested container workflows.
