# Issue #11005 — dev.containers.executeInWSL causes containers to run dev containers even on local windows

[https://github.com/microsoft/vscode-remote-release/issues/11005](https://github.com/microsoft/vscode-remote-release/issues/11005)

## Summary

The Containers extension initializes its WSL path unnecessarily in ordinary local Windows workspaces when `dev.containers.executeInWSL` is enabled. A maintainer acknowledged the premature initialization, and the reporter later confirmed it across two repositories.

## Change summary

Avoid initializing Dev Containers through WSL in an ordinary local Windows workspace until container functionality is requested.

## Best solution

The Containers extension should defer its WSL initialization until the workspace or an explicit command requires Dev Containers, while preserving `dev.containers.executeInWSL` for actual container operations.
