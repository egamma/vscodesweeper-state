# Issue #5233 — No support for the --extensions-dir flag when using WSL

[https://github.com/microsoft/vscode-remote-release/issues/5233](https://github.com/microsoft/vscode-remote-release/issues/5233)

## Summary

Keep this accepted WSL feature request open: the documented extension-management capabilities do not establish support for choosing the remote extension directory. This remains the older, maintainer-discussed report of that specific gap.

## Change summary

Allow users to select a custom directory in the WSL filesystem for remote extensions, rather than always using ~/.vscode-server/extensions.

## Best solution

The WSL component should provide a supported remote-extension-directory configuration with explicit server-wide semantics. Retain this issue as the focused tracking item and coordinate the overlapping isolated-instance request without conflating directory placement with per-workspace extension activation.
