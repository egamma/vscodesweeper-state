# Issue #11261 — vscode leaks `node` processes over time

[https://github.com/microsoft/vscode-remote-release/issues/11261](https://github.com/microsoft/vscode-remote-release/issues/11261)

## Summary

Keep this report open and route it to Dev Containers: the November 26 confirmation identifies accumulating, unused container helpers after reloads, including in a local container without SSH. No verified canonical owns the full reported behavior.

## Change summary

Repeated connection interruptions and window reloads leave old Dev Containers helper processes running, accumulating memory usage.

## Best solution

Dev Containers should retire superseded helpers after reconnect or reload while preserving active sessions. Investigate the reported IPC socket handoff alongside the original before-and-after process lists; SSH alone does not explain the local-container confirmation.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11261 provides VS Code 1.105.1, macOS and Ubuntu versions, a VPN disconnect/reconnect followed by Reload Window, attached logs, and successive process lists showing older /tmp/vscode-remote-containers-server helpers surviving while new ones start.
- **Recent independent confirmation:** https://github.com/microsoft/vscode-remote-release/issues/11261#issuecomment-7199978849 reports the same helper accumulation on November 26, 2026 in a local Dev Container on Windows/WSL2 with Docker Desktop: 75 helpers consuming roughly 1.1 GB after four days. The commenter reports that replacement helpers take over the IPC socket while old helpers remain alive.
- **Related issue is not canonical:** https://github.com/microsoft/vscode-remote-release/issues/11377 is open but principally reports client-side Remote - SSH memory growth while disconnected. Its author distinguishes server-side orphan processes and points those back to this report: https://github.com/microsoft/vscode-remote-release/issues/11377#issuecomment-3720572140.
- **Proxy leak has different scope:** https://github.com/microsoft/vscode-remote-release/issues/11557 is open but concerns node -e TCP proxies accumulating with two windows and host networking, not superseded /tmp/vscode-remote-containers-server helpers. It is newer, has one upvote and no milestone, and does not satisfy the re-review canonical bar.
- **Older cleanup reports do not establish equivalence:** Canonical searches also found https://github.com/microsoft/vscode-remote-release/issues/10843, which diagnoses failed process-group cleanup under Podman/crun with symlinked installs, and https://github.com/microsoft/vscode-remote-release/issues/6346, which concerns stale sockets and files. Neither establishes the same full observable failure as this reload-driven process accumulation.
