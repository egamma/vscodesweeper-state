# Issue #11016 — DevTunnels: Support SSH-Forwarded Tunnels with remoting

[https://github.com/microsoft/vscode-remote-release/issues/11016](https://github.com/microsoft/vscode-remote-release/issues/11016)

## Summary

This is a valid Remote Tunnels feature gap rather than an SSH issue: VS Code exposes remote ports through HTTPS dev-tunnel addresses but does not document an integrated client-local forwarding option. Route it to the tunnels component for consideration.

## Change summary

Add a Remote Tunnels option that forwards a remote service to localhost through the tunnel instead of exposing it through an HTTPS dev-tunnel address.

## Best solution

The Remote Tunnels Ports view should offer authenticated client-local TCP forwarding, equivalent to `devtunnel connect`, alongside the existing HTTPS forwarded address. The tunnels component owns the integration; the standalone CLI remains a workable but incomplete workaround.

## Vision fit

- **Fit:** aligned
- **Reason:** Native local forwarding would improve tunnel fidelity, connection usability, and compatibility with services that cannot operate correctly behind the hosted HTTPS endpoint.
- **Evidence:** The Remote Tunnels documentation describes a local-quality development experience over secure tunnels, while connection reliability and tunnels as a mainstream access path are stated product themes: https://code.visualstudio.com/docs/remote/tunnels
