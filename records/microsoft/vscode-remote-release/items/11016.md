# Issue #11016 — DevTunnels: Support SSH-Forwarded Tunnels with remoting

[https://github.com/microsoft/vscode-remote-release/issues/11016](https://github.com/microsoft/vscode-remote-release/issues/11016)

## Summary

A real Remote Tunnels capability gap remains: VS Code exposes the hosted HTTPS address but does not document a native localhost-forwarding mode equivalent to `devtunnel connect`. The issue is currently misrouted to SSH and should go to the tunnels component.

## Change summary

Add a per-port option that binds a Remote Tunnels forwarded port to localhost through the authenticated SSH transport instead of exposing only its hosted HTTPS address.

## Best solution

The Remote Tunnels port-forwarding experience should offer an authenticated local-loopback mode equivalent to `devtunnel connect`, while retaining the hosted HTTPS mode as an option.
