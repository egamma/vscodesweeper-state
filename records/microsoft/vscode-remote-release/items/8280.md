# Issue #8280 — Unable to run podman dev containers on a UNC path

[https://github.com/microsoft/vscode-remote-release/issues/8280](https://github.com/microsoft/vscode-remote-release/issues/8280)

## Summary

Keep open as a Podman UNC workspace-mount limitation, distinct from the resolved Wayland socket problem. This team-authored report has neither a verified canonical duplicate nor qualifying fix evidence.

## Change summary

Opening a Samba-hosted UNC workspace in a Podman dev container fails because Podman rejects the workspace bind-mount source.

## Best solution

Podman's Windows mount handling needs to support the Samba workspace path, or the containers owner should establish a compatible mounting approach. Retest the recorded command with current Podman and Dev Containers versions before deciding whether extension-side work remains.
