# Issue #1872 — Don't resume last remote connection on startup / Close connection on exit

[https://github.com/microsoft/vscode-remote-release/issues/1872](https://github.com/microsoft/vscode-remote-release/issues/1872)

## Summary

The existing `window.restoreWindows` setting already covers the clarified request: setting it to `none` prevents the previous remote window from reopening at startup.

## Change summary

Provide a way to prevent VS Code from reconnecting to the last remote workspace when it starts.

## Best solution

Keep remote windows governed by VS Code's standard restoration behavior; users who do not want automatic reconnection can set `"window.restoreWindows": "none"`.

## Vision fit

- **Fit:** aligned
- **Reason:** Using the standard window-restoration setting for remote workspaces preserves behavioral parity between local and remote development.
- **Evidence:** The product promise emphasizes taking advantage of VS Code's full feature set when working remotely.

  > Thanks for the request. This is controlled by the existing VS Code window-restoration setting rather than `files.hotExit`.
