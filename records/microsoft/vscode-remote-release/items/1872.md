# Issue #1872 — Don't resume last remote connection on startup / Close connection on exit

[https://github.com/microsoft/vscode-remote-release/issues/1872](https://github.com/microsoft/vscode-remote-release/issues/1872)

## Summary

The requested startup behavior already exists: setting "window.restoreWindows": "none" prevents restoring the previous remote workspace. A maintainer explicitly documented this configuration for the same scenario before this report was filed.

## Change summary

Allow VS Code to start without automatically reconnecting to the last remote workspace.

## Best solution

Use the existing application-level window.restoreWindows setting rather than adding a separate remote startup preference. Exiting VS Code already closes the remote connection; restoring its workspace establishes a new connection.

## Vision fit

- **Fit:** aligned
- **Reason:** Predictable remote startup behavior supports local-quality remote development, and the existing shared window setting provides that control.
- **Evidence:** Layer 1 emphasizes parity: remote development should feel like local development.

- **Proposed comment:**

  > Thanks for the report. To start without reopening the previous remote workspace, set "window.restoreWindows": "none" in your local User settings. This disables restoration of both local and remote windows; files.hotExit does not control window restoration.
  > 
  > This is the existing control for the behavior described, as explained in https://github.com/microsoft/vscode-remote-release/issues/461#issuecomment-496382823. Exiting VS Code closes the remote connection; restoring a remote workspace on the next launch reconnects it.

## Evidence

- **Central ask:** https://github.com/microsoft/vscode-remote-release/issues/1872 and the reporter's May 2020 comment clarify that the central request is not to resume the last remote session on startup; the optional dialog is an alternative way to achieve that outcome.
- **Explicit maintainer guidance:** https://github.com/microsoft/vscode-remote-release/issues/461#issuecomment-496382823 addresses the same startup reconnection scenario. The maintainer explains that reopening a remote workspace intentionally re-establishes its connection and that window.restoreWindows controls this behavior. This guidance predates the report; the closed issue is precedent, not a duplicate canonical.
- **Existing setting:** The public VS Code core setting definition at https://github.com/microsoft/vscode/blob/eed41ffe7badc68947f39cd80e8e876e635d9f54/src/vs/workbench/electron-browser/desktop.contribution.ts#L182-L195 defines window.restoreWindows at application scope. Its none value says: 'Never reopen a window. Unless a folder or workspace is opened (e.g. from the command line), an empty window will appear.' This covers the requested startup behavior, although it also disables restoration of local windows.
- **Connection lifecycle documentation:** https://code.visualstudio.com/docs/remote/ssh#_disconnect-from-a-remote-host documents File > Close Remote Connection and states that exiting VS Code closes the remote connection. Connection closure and subsequent workspace restoration are separate behaviors.
