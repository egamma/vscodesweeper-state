# Issue #11460 — remote.SSH.localServerDownload ignored when opening remote Docker containers via Remote-SSH (“Open in VS Code” copies server from client)

[https://github.com/microsoft/vscode-remote-release/issues/11460](https://github.com/microsoft/vscode-remote-release/issues/11460)

## Summary

The local download is documented Dev Containers behavior, not evidence that Remote - SSH ignores its setting. Route to containers as a request to prefer remote-side server downloads on metered connections; the related fallback request does not cover that preference.

## Change summary

Allow remote containers to download the VS Code Server using the remote connection instead of downloading locally and transferring it.

## Best solution

Dev Containers should own the decision about a remote-first server-download option, separately from remote.SSH.localServerDownload. Coordinate with the existing fallback request, while retaining this item's requirement to avoid local downloads even when they succeed.
