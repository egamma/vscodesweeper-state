# Issue #11460 — remote.SSH.localServerDownload ignored when opening remote Docker containers via Remote-SSH (“Open in VS Code” copies server from client)

[https://github.com/microsoft/vscode-remote-release/issues/11460](https://github.com/microsoft/vscode-remote-release/issues/11460)

## Summary

The documented Dev Containers installation path downloads VS Code Server on the client and copies it into the container; `remote.SSH.localServerDownload` governs Remote - SSH installations, not the separate container server lifecycle.

## Change summary

Allow a container on a remotely accessed Docker daemon to download VS Code Server directly instead of transferring it through the client.

## Best solution

Keep the documented Dev Containers installation behavior and use a persistent VS Code Server volume to avoid repeated transfers. A direct container-side download mode would require a separate Dev Containers feature rather than changing the Remote - SSH setting.

- **Reason:** Reducing repeated server transfers over mobile or constrained links fits the project's performance and server-lifecycle themes, although the requested control does not currently exist.
