# Issue #1711 — Add support for input variables to runArgs

[https://github.com/microsoft/vscode-remote-release/issues/1711](https://github.com/microsoft/vscode-remote-release/issues/1711)

## Summary

Consolidate with the older, open command-substitution request: both ask to compute host values such as UID/GID and substitute them into runArgs. Existing environment-variable and UID-mapping support does not provide the requested generic mechanism.

## Change summary

Support command-backed input variables in devcontainer.json runArgs, including dynamically computed host UID/GID values.

## Best solution

Track command-derived runArgs values in https://github.com/microsoft/vscode-remote-release/issues/1050, retaining this report's named inputs and command-argument configuration as an implementation proposal for the Dev Containers component.

## Evidence

- **Verified canonical:** https://github.com/microsoft/vscode-remote-release/issues/1050 is currently open and was created on 2019-07-29, before this report. Its body explicitly requests command substitution in runArgs using id -u and id -g; its discussion extends the same mechanism to other configuration properties.
- **Same central request:** https://github.com/microsoft/vscode-remote-release/issues/1711 requests command-backed ${input:uid} and ${input:gid} values in runArgs. Passing those values as environment variables rather than --user changes their destination, not the missing capability: evaluating host commands before substituting their results into container arguments.
- **Existing capability boundary:** https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson documents host environment and predefined variables, but not command-backed inputs. https://code.visualstudio.com/docs/reference/variables-reference#_input-variables documents inputs for launch.json and tasks.json, not devcontainer.json.
- **Partial alternatives:** https://code.visualstudio.com/remote/advancedcontainers/add-nonroot-user documents automatic UID/GID matching through remoteUser/containerUser and updateRemoteUserUID; this does not expose arbitrary command results as input variables. https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents runArgs --env-file, which requires a separate file rather than delivering the requested inline input mechanism.
