# Issue #9339 — Launch a dev container using current process' environment

[https://github.com/microsoft/vscode-remote-release/issues/9339](https://github.com/microsoft/vscode-remote-release/issues/9339)

## Summary

A real capability gap remains: documented environment forwarding requires enumerating variables or materializing an env file, neither of which supports this dynamic 1Password workflow. The request earned 14 upvotes and was accepted into the Backlog, so it should remain open.

## Change summary

Allow a dev container launched from VS Code to inherit dynamically supplied environment variables from the launching process without listing every variable or writing secrets to disk.

## Best solution

The Dev Containers extension should provide an explicit, secure way to forward selected or bulk process environment into container creation without duplicating variable names or persisting resolved secrets. The design should preserve the current explicit behavior by default.

## Evidence

- **documented capability gap:** The official documentation at https://code.visualstudio.com/remote/advancedcontainers/environment-variables supports individual `${localEnv:NAME}` mappings or an env file, but does not document bulk inheritance from the process that launched VS Code.
- **spec limitation:** The Dev Container metadata reference at https://containers.dev/implementors/json_reference/ defines `containerEnv` and `remoteEnv` as explicit name-value maps; it provides no wildcard or inherit-current-process option.
- **workaround is incomplete:** https://github.com/microsoft/vscode-remote-release/issues/9446 documents generating a temporary resolved env file and passing it through `runArgs`, but this persists secrets on disk and the narrower pipe proposal was closed through the candidate process.
