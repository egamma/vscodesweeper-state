# Issue #9339 — Launch a dev container using current process' environment

[https://github.com/microsoft/vscode-remote-release/issues/9339](https://github.com/microsoft/vscode-remote-release/issues/9339)

## Summary

Keep this accepted Dev Containers request open: documented environment mappings and env files do not fully cover launch-time process environment forwarding from Windows/WSL. The thread identifies remaining limitations, and no verified canonical owns the same request.

## Change summary

Allow dev containers launched through a secrets-injecting CLI to consume that invocation's environment without duplicating variable lists or writing resolved secrets to a temporary file.

## Best solution

The Dev Containers owner should define an explicit, opt-in way to forward the invoking process's selected environment into container sessions, including Windows/WSL launches. Preserve project isolation rather than implicitly copying every host variable.
