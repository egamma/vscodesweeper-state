# Issue #7874 — devcontainer.json: Extensions installed by VSIX are not installed automatically in devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/7874](https://github.com/microsoft/vscode-remote-release/issues/7874)

## Summary

Keep the accepted Dev Containers request open: explicit VSIX paths and manual installation do not establish automatic recovery of locally installed private extensions by ID after rebuilding. The verified related issues do not own this same container-specific behavior.

## Change summary

Automatically install a locally available, non-Marketplace extension when its ID is listed in devcontainer.json and the container is rebuilt.

## Best solution

Dev Containers should support resolving configured private-extension IDs from the local installation when Marketplace lookup fails. Retest that exact rebuild workflow, distinguishing it from explicit container-side VSIX paths and SSH's automatic-extension settings.
