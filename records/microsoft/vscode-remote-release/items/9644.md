# Issue #9644 — Cannot open in container from WSL filesystem through tunnels

[https://github.com/microsoft/vscode-remote-release/issues/9644](https://github.com/microsoft/vscode-remote-release/issues/9644)

## Summary

Keep open: this team-authored Backlog request covers the unsupported tunnel-to-WSL-to-container composition, with multiple users confirming the gap. Existing tunnel-to-Windows-container support and the attach workaround do not provide rebuild or restart functionality from the WSL workspace.

## Change summary

Allow Dev Container build and reopen commands from a WSL workspace reached through a tunnel to a Windows host.

## Best solution

Dev Containers, Tunnels, and WSL should support composed remote resolution so container lifecycle commands execute in the tunneled host's WSL environment. The existing attach-to-running-container workflow should remain a workaround rather than the end state.
