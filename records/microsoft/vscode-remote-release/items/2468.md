# Issue #2468 — Containers: make opening a container from Dockerfile a nice experience

[https://github.com/microsoft/vscode-remote-release/issues/2468](https://github.com/microsoft/vscode-remote-release/issues/2468)

## Summary

Keep open for the Dockerfile-first entry point: today's guided workflow automates building and connecting, but does not document the requested Dockerfile context-menu action. A maintainer explicitly agreed to improve this experience, so a decline close would contradict the thread.

## Change summary

Provide a Dockerfile context-menu action that selects a local folder, builds and starts its container, and opens the folder without manual Docker lifecycle commands.

## Best solution

The Dev Containers component should connect a Dockerfile-first action to the existing guided container-creation workflow, asking for additional build or runtime options only when needed. Preserve devcontainer.json for reproducibility while removing the need to understand image and container management for simple cases.

## Vision fit

- **Fit:** aligned
- **Reason:** Making container setup accessible without manual Docker lifecycle management advances the promise of opening any folder in a container.
- **Evidence:** The public product promise is to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
