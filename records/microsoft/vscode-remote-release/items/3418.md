# Issue #3418 — ${execPath} has wrong value in a Container Remote

[https://github.com/microsoft/vscode-remote-release/issues/3418](https://github.com/microsoft/vscode-remote-release/issues/3418)

## Summary

A documented workaround exists, but it does not provide the requested remote executable variable. Keep this Backlog Candidate open as under discussion because maintainers confirmed that `${execPath}` must remain local and supported adding a separate remote path.

## Change summary

Provide a task and launch variable such as `${remoteExecPath}` that resolves to the VS Code CLI inside the active remote container.

## Best solution

VS Code's variable resolver should expose the remote server CLI path separately while preserving `${execPath}` for local extension-host debugging. The containers owner should coordinate the task/launch variable surface with VS Code core.

- **Fit:** aligned
- **Reason:** Allowing remote tasks to invoke the current remote VS Code window closes a local-versus-remote workflow parity gap.
- **Evidence:** The public vision identifies parity gaps as core work: remote environments should provide VS Code's full feature set while tools run against the remote environment.
