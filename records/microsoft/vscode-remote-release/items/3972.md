# Issue #3972 — Feature request: Allow dynamic "runArgs" for docker

[https://github.com/microsoft/vscode-remote-release/issues/3972](https://github.com/microsoft/vscode-remote-release/issues/3972)

## Summary

The central capability remains missing: current Dev Container configuration supports static `runArgs` with variable substitution, but not script-generated or conditional arguments. This accepted Backlog request has substantial community support and no verified canonical that fully owns it.

## Change summary

Allow host-side logic to generate conditional arguments used when creating a Dev Container.

## Best solution

Define a portable, structured Dev Container spec mechanism for host-generated creation inputs, then implement it consistently in the Dev Containers extension and CLI. Coordinate with https://github.com/devcontainers/spec/issues/743, while preserving this older issue's specific conditional `runArgs`, device, and mount requirements.

## Evidence

- **current specification gap:** The current schema at https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json still defines `runArgs` only as an array and provides no command-generated argument form.
- **partial existing capabilities:** The documented `mounts` mechanism supports `${localEnv:...}` substitution, and `hostRequirements.gpu: optional` covers automatic GPU enablement, but neither handles arbitrary conditional devices, volumes, or other Docker arguments: https://containers.dev/implementors/json_reference/
- **related spec work:** https://github.com/devcontainers/spec/issues/743 is open and requests substitution from values generated by `initializeCommand`, but it is newer and broader rather than a verified replacement for this issue's specific dynamic `runArgs` requirements.
- **continued demand:** The issue has 21 body upvotes and distinct examples involving optional volumes, USB/serial devices, and host-dependent configuration; its most recent related discussion was in June 2026.
