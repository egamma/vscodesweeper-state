# Issue #11487 — Restore  support for remote Centos 7

[https://github.com/microsoft/vscode-remote-release/issues/11487](https://github.com/microsoft/vscode-remote-release/issues/11487)

## Summary

This requests restoring official support for a deliberately unsupported legacy platform, rather than reporting broken supported behavior. Route it to the SSH and server owners for an explicit support-matrix decision.

## Change summary

Restore official Remote - SSH and VS Code Server support for CentOS 7.

## Best solution

The SSH and VS Code Server owners should decide whether the maintenance and testing cost justifies restoring CentOS 7 to the supported matrix. Unless that changes, retain the documented custom-sysroot workaround for users unable to migrate.

## Evidence

- **support matrix:** https://code.visualstudio.com/docs/remote/linux lists CentOS 7 as unsupported because it lacks glibc 2.28 and libstdc++ 3.4.25; official support starts at CentOS/RHEL 8.
- **documented workaround:** https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions documents connecting through Remote - SSH with a custom sysroot and patchelf, while explicitly stating that this is not an officially supported scenario.
- **implemented compatibility path:** https://github.com/microsoft/vscode/issues/231623 was completed to allow unsupported Linux remotes to use custom glibc and libstdc++ libraries; it provides a workaround but does not restore official CentOS 7 support.
- **prior scope decision:** https://github.com/microsoft/vscode-remote-release/issues/9564 was closed as out of scope when requesting CentOS 7 glibc/libstdc++ support guidance, showing the previous maintenance position without conclusively deciding this renewed feature request.
