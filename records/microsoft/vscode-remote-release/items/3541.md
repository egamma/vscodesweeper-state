## Summary

Consolidate this request into the older, verified-open variable-substitution request, which explicitly includes reading VS Code configuration values in devcontainer.json. The requested capability remains undocumented; this is a duplicate proposal, not a claim that it already ships.

## Change summary

Allow devcontainer.json variable substitution to read user settings for mounts, build arguments, run arguments, and other supported string values.

The Dev Containers implementation should address that use case alongside the canonical request's broader variable support.

- **existing-capability check:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md#variables-in-devcontainerjson documents localEnv, containerEnv, workspace variables, and devcontainerId, but not config or localConfig lookup. Environment substitution remains a workaround, not coverage of the requested user-settings source.
- **report-specific requirements:** https://github.com/microsoft/vscode-remote-release/issues/3541 requests ${localConfig:my.data_dir} for a per-user bind mount and equivalent support in build.args and runArgs. Its commenter specifically wants an alternative to Docker Compose .env substitution; these details should remain linked from the canonical.
