# Issue #3096 — Persistent SSH session

[https://github.com/microsoft/vscode-remote-release/issues/3096](https://github.com/microsoft/vscode-remote-release/issues/3096)

## Summary

Keep open: configurable SSH reconnection grace time now addresses longer disconnects, but does not establish indefinite preservation and reattachment of live runtime state after closing VS Code. This accepted Backlog request remains broader than the verified related issues.

## Change summary

Allow users to close VS Code and reconnect days later to the same live remote terminals, REPLs, and runtime state without an expiry.

## Best solution

The SSH component should coordinate server lifetime and client session reattachment to provide an explicit opt-in persistent session with intentional cleanup. Build on the existing grace-time setting while addressing client closure and restoration of the original live processes, not merely terminal relaunch.

## Evidence

- **Central requirement:** https://github.com/microsoft/vscode-remote-release/issues/3096 explicitly distinguishes an infinite lifetime from a configurable timeout: after closing the local client for days, the original Julia REPL and other runtime state should remain alive.
- **Existing capability and remaining gap:** https://github.com/microsoft/vscode-docs/blob/main/remote-release-notes/v1_107.md documents remote.SSH.reconnectionGraceTime and --reconnection-grace-time, which keep the server alive until the configured grace period expires. This covers longer disconnects but does not document an indefinite mode or restoration of all live session state after client closure.
- **Terminal persistence is not live-state preservation:** https://code.visualstudio.com/docs/terminal/advanced#_persistent-sessions distinguishes process reconnection on window reload from process revive on restarting VS Code, which relaunches the process. terminal.integrated.enablePersistentSessions therefore does not establish preservation of an existing REPL's in-memory state across the requested workflow.
- **Workarounds and prototype:** https://github.com/microsoft/vscode-remote-release/issues/3096#issuecomment-2503195670 describes tmux as a workaround. https://github.com/microsoft/vscode-remote-release/issues/3096#issuecomment-6213594775 presents a VSCodium/open-remote-ssh prototype for persistent terminals and reattachment, explicitly lacking server-version migration handling; it is not a shipped Microsoft product fix.
- **Canonical ownership:** Verified https://github.com/microsoft/vscode-remote-release/issues/440 is open but requests configurable timeout, a subset expressly distinguished in this report. Verified https://github.com/microsoft/vscode-remote-release/issues/1790 is open but requests Eternal Terminal transport support, not the same client-closure/session-preservation behavior. Searches for persistent sessions, detach, keep-alive, and auto-shutdown found no verified canonical owning the full remaining ask.
- **Related implementation scope:** https://github.com/microsoft/vscode/pull/274910 merged configurable reconnection grace time. https://github.com/microsoft/vscode/pull/273060 addresses premature reconnect failure and is closed without merging. Neither establishes completion of the full persistent-session request.
