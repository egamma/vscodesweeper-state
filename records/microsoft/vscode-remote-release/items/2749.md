# Issue #2749 — "Code" CLI does not have advanced options while trying to install a .vsix extension on my remote Linux VM over the SSH session

[https://github.com/microsoft/vscode-remote-release/issues/2749](https://github.com/microsoft/vscode-remote-release/issues/2749)

## Summary

The requested remote CLI extension-management capability shipped in VS Code 1.53, including installation from VSIX files in an SSH window's integrated terminal. Propose closing as completed, supported by public implementation commits and explicit release documentation.

## Change summary

Support installing packaged VSIX extensions through the remote code CLI rather than rejecting --install-extension.

## Best solution

Use the shipped remote CLI command, code --install-extension /remote/path/extension.vsix, from the connected SSH window's integrated terminal; no additional capability is needed for this request.

## Evidence

- **Reported trigger and scope:** https://github.com/microsoft/vscode-remote-release/issues/2749 describes running code --install-extension with a VSIX in the integrated terminal of a Remote - SSH window on VS Code 1.44.0; the remote CLI rejects the option and omits extension-management help. These are the public IPC and workbench portions of the integrated-terminal remote CLI path.
- **Exact VSIX support:** https://github.com/microsoft/vscode/commit/dc5883895072774484c6cc1cb7631a8e2c72e1dc, committed 2021-01-18T22:35:51Z, changes CLIServerBase.manageExtensions around lines 166–179 to recognize .vsix inputs, parse their URIs, and forward them to _remoteCLI.manageExtensions. https://github.com/microsoft/vscode/commit/847300e49a9eee0b2d073b61df7f1ec69c7758fc changes that command around lines 36–47 to revive VSIX URIs before calling installExtensions. Together they implement the reporter's VSIX installation path.
- **Shipping and venue confirmation:** https://github.com/microsoft/vscode-docs/blob/main/remote-release-notes/v1_53.md explicitly announces under Visual Studio Code Remote Core that code in the integrated terminal of remote windows supports --install-extension idOrPathToVSIX, --force, uninstalling, and listing extensions, restricted to the remote extension host. This covers SSH remote windows, not only the separately documented WSL-shell feature.

Its maintainer announcement at https://github.com/microsoft/vscode-remote-release/issues/2589#issuecomment-762823009 confirms the same integrated-terminal capability. The open related request https://github.com/microsoft/vscode-remote-release/issues/2704 concerns automatic default extensions for WSL, which is different remaining work.

The reported Ubuntu 14.04 host needs separate compatibility consideration when upgrading; that does not leave the requested CLI capability unimplemented.
