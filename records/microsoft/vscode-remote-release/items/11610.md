# Issue #11610 — Terminating old extension host agent" SIGKILLs in-flight postCreateCommand (exit 137) when a second window attaches

[https://github.com/microsoft/vscode-remote-release/issues/11610](https://github.com/microsoft/vscode-remote-release/issues/11610)

## Summary

The report provides a detailed same-session correlation between agent cleanup and the terminated postCreateCommand, but there is no independent confirmation or maintainer reproduction. A current-version retest and complete logs are needed.

## Change summary

Attaching a second window can mistake a transient `code --install-extension` process for an old extension host agent and SIGKILL its entire process group, terminating postCreateCommand with exit 137.

## Best solution

The Dev Containers agent-cleanup path should distinguish long-running server agents from one-shot CLI commands and avoid terminating unrelated processes sharing their process group. The containers owner should confirm the supplied reproduction against the current extension before choosing the safest process-identification change.
