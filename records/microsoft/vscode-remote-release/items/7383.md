# Issue #7383 — Open Folder in Dev Container shows only local folders

[https://github.com/microsoft/vscode-remote-release/issues/7383](https://github.com/microsoft/vscode-remote-release/issues/7383)

## Summary

Keep this accepted feature request open: documented folder-opening and volume-mount capabilities do not cover launching a separate dev container from a volume-backed subdirectory's own configuration. No verified canonical owns the same folder-picker limitation.

## Change summary

Allow selecting a volume-backed folder inside the current dev container and opening its own devcontainer.json in a separate container window.

## Best solution

Dev Containers should support discovering a subdirectory's configuration inside an existing container volume and launching a separate dev container against that source without requiring a local checkout.

## Evidence

The November 24, 2022 team comment records sufficient community support and acceptance into Backlog; this is not an expired Backlog Candidate.
- **Existing folder-opening capability is partial:** https://code.visualstudio.com/remote/advancedcontainers/configure-separate-containers documents File > Open Folder for subdirectories, explicitly opening them inside the same container. That does not launch a different container using the subdirectory's own configuration.
- **Existing mount configuration is partial:** https://code.visualstudio.com/remote/advancedcontainers/change-default-source-mount and https://code.visualstudio.com/remote/advancedcontainers/develop-remote-host document workspaceMount and workspaceFolder for named volumes. The latter still directs users to select a local folder containing devcontainer.json; neither documents selecting a configuration that exists only inside the current container volume.
- **Volume performance motivation:** https://code.visualstudio.com/remote/advancedcontainers/improve-performance documents improved macOS and Windows performance from cloning into named volumes. This supports the thread's motivation for avoiding a local bind-mounted checkout, but does not establish that the requested selection workflow exists.
