# Issue #7383 — Open Folder in Dev Container shows only local folders

[https://github.com/microsoft/vscode-remote-release/issues/7383](https://github.com/microsoft/vscode-remote-release/issues/7383)

## Summary

Keep open: this accepted Backlog request still describes a meaningful gap for volume-backed projects. Current multiple-configuration and Switch Container support does not clearly provide the requested remote-folder picker and separate-window workflow.

## Change summary

Allow a folder stored inside a container volume to be selected and opened in a new Dev Container window using that subfolder's devcontainer.json.

## Best solution

Dev Containers should let Open Folder in Container browse the current volume-backed filesystem and launch the selected subfolder's configuration in a separate window, preserving access to the source volume.

## Vision fit

- **Fit:** aligned
- **Reason:** The request advances volume-backed Dev Container capability and avoids macOS bind-mount performance penalties while preserving the normal folder-opening workflow.
- **Evidence:** The public Dev Containers documentation says the extension lets users “open any folder inside (or mounted into) a container,” and identifies isolated container volumes as the higher-performance option on macOS and Windows: https://code.visualstudio.com/docs/devcontainers/containers
