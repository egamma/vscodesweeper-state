# Issue #10168 — VSCode freezing when adding folder to workspace while working on remote Linux machine

[https://github.com/microsoft/vscode-remote-release/issues/10168](https://github.com/microsoft/vscode-remote-release/issues/10168)

## Summary

Keep open while the linked implementation candidate is reviewed: multiple users confirm SSH workspace-transition freezes, including an October 2026 report. The existing steps and newer clean-profile reproduction provide enough evidence to retest; no shipped fix is established.

## Change summary

Adding the first or second folder to an SSH window can freeze VS Code while converting it into a multi-root workspace.

## Best solution

Review https://github.com/microsoft/vscode/pull/343997 and verify that preserving the managed remote connection through workspace migration resolves this report's folder-addition and Save Workspace As hangs. Retain this older issue as the tracking report, using the newer clean-profile logs to guide SSH and core workspace-lifecycle validation.

Comments identify the initial transition to a multi-root workspace as the trigger; subsequent folder additions work. - **Open implementation candidate blocks closure:** https://github.com/microsoft/vscode/pull/343997 is OPEN and explicitly references this issue. Its proposed change preserves extension hosts carrying managed remote connections until workspace migration completes; its reported SSH checks support the hypothesis but do not establish a merged or shipped fix.
- **Current clean-profile reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11941 is OPEN and reports the same single-folder-to-workspace hang on VS Code 1.145.0 with Remote-SSH 0.128.0. Three clean-profile runs reproduce a roughly 20-second hang followed by a reconnect failure; logs show the local extension host terminating before remote configuration reads complete. Both remote.SSH.useLocalServer values reproduce.
