# Issue #5453 — Create container from existing container volume

[https://github.com/microsoft/vscode-remote-release/issues/5453](https://github.com/microsoft/vscode-remote-release/issues/5453)

## Summary

The existing Clone Repository in Container Volume workflow already recreates the development container without overwriting its existing repository volume, and the reporter confirmed this meets the request.

## Change summary

Allow a development container deleted independently of its repository volume to be recreated from the devcontainer configuration stored in that volume.

## Best solution

Keep the existing volume-reuse behavior of Dev Containers: Clone Repository in Container Volume; users can enter the same repository URL to recreate and reopen the development container while preserving the volume.

- **Evidence:** The durable themes identify dev-container capability depth as an area of continuous investment, while the public documentation describes isolated container volumes as a supported workspace model.
