# Issue #9011 — Extension host crashes with VS Code Go

[https://github.com/microsoft/vscode-remote-release/issues/9011](https://github.com/microsoft/vscode-remote-release/issues/9011)

## Summary

Keep open: the linked investigation contains concrete reproduction details and Node invalid-opcode logs, but no confirmed fix. VS Code has advanced since the 1.82–1.83 reports; the supplied steps suffice for retesting without treating the closed Go issue as resolution.

## Change summary

Launching gopls triggers repeated remote extension-host crashes on certain virtualized Linux hosts.

## Best solution

The SSH and VS Code Server owners should investigate the Node invalid-opcode crash using the documented gopls trigger and VM comparisons. If the defect belongs to the core extension-host runtime, a maintainer can transfer this to microsoft/vscode; VMware involvement remains a hypothesis, not an established upstream cause.
