# Issue #6056 — Container reopened from Remote-SSH not stopping after closing the window

[https://github.com/microsoft/vscode-remote-release/issues/6056](https://github.com/microsoft/vscode-remote-release/issues/6056)

## Summary

Keep open: users continue to report that closing an SSH-backed Dev Container leaves it running despite shutdownAction. VS Code 1.140's automatic cleanup is explicitly Agents-window-only, and the newer overlapping reports do not qualify as canonicals for this re-reviewed issue.

## Change summary

Closing a Dev Container opened through Remote - SSH fails to stop its container or Compose services.

## Best solution

The Dev Containers extension should honor stopContainer and stopCompose on the remote Docker host after the main VS Code window disconnects. Investigate the shutdown-monitor Docker executable/context failures reported here, preserving this older issue as the SSH-backed shutdown tracking item.

## Evidence

- **Expected shutdown behavior:** https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json defines shutdownAction: stopContainer as stopping the container on editor disconnect and stopCompose as stopping all Compose containers. The reporter explicitly tried stopContainer, so the existing property does not resolve the reported failure.
- **Persistent failure:** https://github.com/microsoft/vscode-remote-release/issues/6056#issuecomment-1090895068 independently confirms both Dockerfile and Compose failures. https://github.com/microsoft/vscode-remote-release/issues/6056#issuecomment-6354472440 reports the main-window SSH-backed shutdown problem still present in October 2026.
- **Shutdown-monitor diagnosis:** https://github.com/microsoft/vscode-remote-release/issues/6056#issuecomment-1778194162 reports Docker executable lookup failing in shutdownMonitorProcess with Dev Containers 0.315.1 while using a remote Linux server. This is a concrete diagnostic lead, not proof that every report shares that root cause.
- **New cleanup does not cover this window:** https://code.visualstudio.com/updates/v1_140#_automatic-dev-container-cleanup explicitly limits chat.agentHost.devContainer.enabled and chat.agentHost.devContainer.idleTimeout cleanup to the Agents window. It does not establish a fix for the main-window Remote-SSH reopening workflow.
- **Earlier fix insufficient:** https://github.com/microsoft/vscode-remote-release/issues/7754 is a closed Compose shutdown regression involving cloned container volumes. Although one commenter reported success with pre-release 0.294.0, https://github.com/microsoft/vscode-remote-release/issues/6056#issuecomment-1567212650 and subsequent reports show no durable resolution of this issue's full SSH-backed scope.
- **Canonical search:** Verified open https://github.com/microsoft/vscode-remote-release/issues/8818 and https://github.com/microsoft/vscode-remote-release/issues/8991 contain overlapping shutdown failures. Both were created in 2023, have no milestone, and have fewer upvotes than this 2021 issue, so neither meets the re-reviewed-item canonical bar. The older https://github.com/microsoft/vscode-remote-release/issues/3512 requests container removal and an explicit cleanup command rather than fixing SSH-backed automatic shutdown.
