# Issue #3593 — New environment configuration file: /etc/devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/3593](https://github.com/microsoft/vscode-remote-release/issues/3593)

## Summary

Keep open: the rewritten request is for a dedicated, shell-independent environment script, not merely enabling login-shell probing. Current userEnvProbe support addresses the earlier examples and attached-container configuration, but does not deliver that remaining capability; no qualifying open canonical was found.

## Change summary

Add optional, default-enabled sourcing of /etc/devcontainer to supply scripted environment variables independently of userEnvProbe and ordinary shell startup files.

## Best solution

The Dev Containers owners should decide whether to support a dedicated environment-script probe, coordinating any shared configuration property with devcontainers/spec while retaining extension implementation tracking here. The thread suggests extracting exported variables once rather than wrapping every command in a shell.
