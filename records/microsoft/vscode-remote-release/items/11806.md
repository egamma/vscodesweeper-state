## Summary

Route to containers as an upstream DNS issue. The resolver defect is independently confirmed, and the reporter verified a resolver-side workaround; keep the documentation and optional bootstrap mitigation decision open.

## Change summary

Document or mitigate SSH clone failures in the Alpine bootstrap container when a resolver returns NXDOMAIN for an existing hostname's AAAA query.

## Evidence

- **isolated dependency failure:** https://github.com/microsoft/vscode-remote-release/issues/11806 supplies a minimal getaddrinfo(AF_UNSPEC) reproduction without Git or SSH, reproduces with OpenSSH 9.7p1, and confirms that host-global core.sshCommand = ssh -o AddressFamily=inet makes the bootstrap clone succeed. This isolates the failure from the pinned SSH package and extension credential propagation.
- **upstream confirmation:** https://github.com/pi-hole/FTL/issues/3039 remains open. In https://github.com/pi-hole/FTL/issues/3039#issuecomment-5421154203, an upstream maintainer reproduces the failure, identifies dnsmasq's is_local_answer() and the parent/child local= interaction, and reports sending a patch upstream.
- **resolver workaround confirmed:** In https://github.com/pi-hole/FTL/issues/3039#issuecomment-5431649634, the same reporter confirms that pairing local=/lua.lan/ with address=/lua.lan/10.0.0.3 changes the AAAA response from NXDOMAIN to NOERROR. This is a configuration workaround, not evidence of a shipped Dev Containers fix.
- **existing capability and remaining work:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents copying the local .gitconfig into containers; the issue separately verifies core.sshCommand propagation during bootstrap cloning. The existing override avoids this failure but globally constrains Git SSH connections to IPv4, so it does not deliver transparent dual-stack handling or the requested troubleshooting documentation.
