# Issue #6817 — Auto-detect docker in WSL when not available in Windows

[https://github.com/microsoft/vscode-remote-release/issues/6817](https://github.com/microsoft/vscode-remote-release/issues/6817)

## Summary

Keep open: the reporter confirmed that manually enabling Execute in WSL works, but explicitly requested automatic Windows-first fallback afterward. No verified shipped implementation or eligible canonical establishes that this remaining request is satisfied.

## Change summary

Automatically discover Docker in the default WSL2 distribution when opening a repository in a container from Windows without local Docker.

## Best solution

The Dev Containers extension should offer Windows-first Docker discovery with fallback to the default WSL2 distribution, including the cloneInVolume URI entry point, while preserving explicit execution choices. Establish whether current releases already provide that exact behavior before retiring this Backlog request.
