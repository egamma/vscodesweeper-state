# Issue #6186 — Run separate VS Code servers per workspace in the same remote to enable different env variables per workspace.

[https://github.com/microsoft/vscode-remote-release/issues/6186](https://github.com/microsoft/vscode-remote-release/issues/6186)

## Summary

Keep open in the Backlog: Remote - SSH still shares one server environment across workspaces on the same host, preventing concurrent project-specific RemoteCommand environments. Dev containers provide an environment-isolation workaround but do not cover direct SSH workflows without containers.

## Change summary

Allow each Remote - SSH workspace on the same host to use an isolated VS Code server and its own RemoteCommand environment.

## Best solution

The Remote - SSH component should support workspace- or connection-scoped server instances, or another isolation key that prevents incompatible RemoteCommand environments from sharing a server. Existing server reuse should remain the default where isolation is unnecessary.

## Vision fit

- **Fit:** aligned
- **Reason:** Independent workspace environments improve Remote - SSH fidelity and make remote development behave more like separate local workspaces.
- **Evidence:** The Remote Development promise is to “Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set,” while SSH breadth and fidelity are identified as a durable theme.
