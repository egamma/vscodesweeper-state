# Issue #11829 — "Attach Visual Studio Code" from Container Tools ignores the resolved container's context, reopens picker on outermost/default daemon

[https://github.com/microsoft/vscode-remote-release/issues/11829](https://github.com/microsoft/vscode-remote-release/issues/11829)

## Summary

Keep open for Dev Containers investigation: the concrete DinD steps suffice to retest the wrong-daemon selection. Current documentation describes Docker-context configuration, but neither it nor the related discussions establishes that nested-window context resolution is fixed.

## Change summary

Attaching to a selected nested Docker container opens a replacement picker against the outer daemon instead of preserving the selected container and its context.

## Best solution

Dev Containers should preserve the intended Docker endpoint through nested-window attachment, coordinating with Container Tools where necessary. Investigate endpoint resolution separately from the known cross-extension-host limitation that loses the selected tree object.
