## Summary

Keep open for tunnel CLI recovery investigation: the complete verbose trace places the failure at relay reconnect/respawn, before Extension Host shutdown. The report targets CLI 1.112.0 rather than current builds, but supplies sufficient configuration, steps, and logs to retest; no verified fix or matching canonical was found.

## Change summary

A systemd-managed code tunnel remains alive but offline indefinitely after relay EOF, a transient DNS failure, and respawn into an existing singleton.

## Best solution

The tunnel CLI should restore relay hosting after a transient reconnect failure, or exit unsuccessfully if it cannot recover so the service supervisor can restart it. Investigate the singleton/respawn transition identified in the supplied logs rather than assuming Extension Host shutdown initiates the failure.
