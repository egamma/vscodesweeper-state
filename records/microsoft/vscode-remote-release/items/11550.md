# Issue #11550 — [Remote Tunnels] Tunnel process becomes zombie (silent, no relay reconnect) after all clients disconnect and Extension Host shuts down

[https://github.com/microsoft/vscode-remote-release/issues/11550](https://github.com/microsoft/vscode-remote-release/issues/11550)

## Summary

A detailed current-version trace shows the tunnel remaining alive but offline after a transient relay/DNS failure, with a second user reporting similar relay retry behavior. No canonical issue or confirmed fix was found, so this should remain open and be routed to the tunnels/CLI owners.

## Change summary

The code tunnel service can permanently stop communicating with the relay while its processes remain alive, preventing systemd from restarting it.

## Best solution

The tunnel CLI should recover relay registration after transient endpoint or DNS failures; if recovery becomes impossible, it should exit nonzero so the installed systemd service can restart it.
