# Issue #3708 — remote.containers.repositoryConfigurationPaths doesn't work with WSL / SSH / Clone in Volume

[https://github.com/microsoft/vscode-remote-release/issues/3708](https://github.com/microsoft/vscode-remote-release/issues/3708)

## Summary

Keep open as the maintainer-selected tracking issue for external repository configurations across remote container workflows. The extension now uses dev.containers settings and a CLI-backed configuration path, but the original steps suffice to retest; neither a confirmed fix nor a broader open canonical was found.

## Change summary

External repository container configurations fail across WSL, SSH, and clone-in-volume workflows, including passing a Windows UNC configuration path to Docker Compose running inside WSL.

## Best solution

The Dev Containers component should resolve external configuration files in the filesystem context where its commands execute, translating or making files available across host boundaries as appropriate. Retest the supplied WSL case and the consolidated remote-Docker clone-in-volume case before considering this resolved.
