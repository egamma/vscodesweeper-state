# Issue #11402 — Devcontainer launch fails when Docker Desktop WSL Integration is disabled

[https://github.com/microsoft/vscode-remote-release/issues/11402](https://github.com/microsoft/vscode-remote-release/issues/11402)

## Summary

Keep open to investigate the automatically added WSLg mount, which makes a Windows-side, volume-backed dev container depend on disabled Docker WSL integration. Releases have advanced since the report, but its steps and logs suffice to retest; no confirmed product fix or verified open canonical was found.

## Change summary

Dev container startup fails with Docker Desktop WSL integration disabled because an automatically supplied Wayland bind mount requires the unavailable distro mount service.

## Best solution

The containers owner should determine whether optional WSLg forwarding should be skipped when Docker cannot mount from that distro, preserving Windows-side volume-backed startup. Enabling integration is a workaround, not evidence that the reported regression was fixed.
