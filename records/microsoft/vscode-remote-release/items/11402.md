# Issue #11402 — Devcontainer launch fails when Docker Desktop WSL Integration is disabled

[https://github.com/microsoft/vscode-remote-release/issues/11402](https://github.com/microsoft/vscode-remote-release/issues/11402)

## Summary

The detailed log shows Dev Containers injecting a WSLg socket mount that Docker Desktop cannot access while distro integration is disabled, but there is no current-version confirmation. A retest should determine whether this remains a Dev Containers regression or is covered by the Wayland-socket setting.

## Change summary

Allow a volume-based Dev Container to launch through Docker Desktop without requiring WSL distro integration solely for an automatically added WSLg socket mount.

## Best solution

The Dev Containers component should avoid adding the WSLg bind mount when Docker Desktop cannot access the selected distro, or emit a clear configuration diagnostic. First confirm the current behavior with `dev.containers.mountWaylandSocket` disabled.

## Evidence

- **failure log:** https://github.com/microsoft/vscode-remote-release/issues/11402 shows Dev Containers 0.435.0 adding a `\\wsl.localhost\Ubuntu\...\wayland-0` bind mount; Docker rejects it because `/run/guest-services/distro-services/ubuntu.sock` is absent.
- **configuration dependency:** The reporter confirms that enabling Docker Desktop WSL integration resolves the failure. Docker documents that distro integration enables direct Docker access from and interaction with that WSL distribution: https://docs.docker.com/desktop/features/wsl/
