# Issue #11433 — Problems starting a VS Code server in OpenSUSE Leap 16.0

[https://github.com/microsoft/vscode-remote-release/issues/11433](https://github.com/microsoft/vscode-remote-release/issues/11433)

## Summary

Keep open as the canonical OpenSUSE Leap 16 report: several users reproduced the CLI startup hang, isolated it to the valid `seed=JITTER` OpenSSL configuration, and confirmed the workaround. Newer releases still exhibit the same OpenSSL configuration incompatibility.

## Change summary

Remote - SSH hangs at "Waiting for server log..." because the bundled VS Code CLI cannot start with OpenSUSE Leap 16's OpenSSL random configuration.

## Best solution

The VS Code CLI/server lifecycle owner should prevent the bundled OpenSSL from hanging on the host's valid `seed=JITTER` configuration, without requiring users to modify system-wide crypto configuration or disable the exec server. Consolidate the newer diagnostics from issue 11721 here because this older report captures the same underlying OpenSSL incompatibility.

## Evidence

- **confirmed reproduction:** Multiple users reproduced the failure on OpenSUSE Leap 16 and SLES 16; two commenters confirmed that removing `seed=JITTER` from `/etc/ssl/openssl.cnf` restores Remote - SSH connectivity.
- **isolated cause:** The thread's strace comparison shows the CLI reading the host OpenSSL policy before hanging, while ordinary applications continue to use that configuration successfully.
- **current-release evidence:** https://github.com/microsoft/vscode-remote-release/issues/11721 reports the same CLI hang through VS Code 1.127; later diagnostics identify embedded OpenSSL 3.1.4 and confirm that replacing the host OpenSSL configuration resolves it.
- **workaround limitation:** Disabling `remote.SSH.useExecServer` or modifying the system-wide OpenSSL configuration avoids the failure but does not address the CLI compatibility defect.
