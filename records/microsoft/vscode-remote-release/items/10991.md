[https://github.com/microsoft/vscode-remote-release/issues/10991](https://github.com/microsoft/vscode-remote-release/issues/10991)

## Summary

Keep open as upstream under the policy against closing platform-owned issues. WSL 2.7.1 has a confirmed fix for the original connection failure, but the later Java test-runner refusal needs separate diagnosis.

## Change summary

Allow reliable WSL connections with networkingMode=VirtioProxy and localhostForwarding=true without fixed-port workarounds.

## Best solution

The WSL platform should handle dynamically assigned localhost ports without extension patches or fixed-port settings; WSL 2.7.1 delivers the reported connection fix. Determine whether the remaining Java test-runner refusal occurs on that WSL version and shares the platform defect before treating it as remaining work here.
