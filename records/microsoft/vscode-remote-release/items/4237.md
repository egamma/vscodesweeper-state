# Issue #4237 — Improve moving from image to name based configuration

[https://github.com/microsoft/vscode-remote-release/issues/4237](https://github.com/microsoft/vscode-remote-release/issues/4237)

## Summary

A real usability gap remains: Dev Containers supports separate image- and name-level configurations, but provides no documented way to migrate an existing image configuration to a container name without manually copying its contents.

## Change summary

Provide a discoverable UI for listing attached-container configurations and moving or copying an image-level configuration to a named container.

## Best solution

Dev Containers should offer a supported command to copy or move a selected image-level attached-container configuration to a selected container name, preserving its workspace folder, extensions, and settings.

## Evidence

- **current capability:** Current documentation at https://code.visualstudio.com/docs/devcontainers/attach-container supports image-level and container-name-level files through separate commands, but documents no operation that binds, copies, or migrates an existing image configuration to a name.
- **remaining gap:** The reporter already used name-level configuration successfully; the requested improvement is replacing the manual copy from imageConfigs to nameConfigs with a discoverable supported workflow.
- **related issue:** https://github.com/microsoft/vscode-remote-release/issues/4013 remains open but asks to create a named configuration before attaching, not to migrate an existing image configuration, so it does not own the full request.
- **shared-image behavior:** https://github.com/microsoft/vscode-remote-release/issues/1557 remains open and confirms that named configurations for different containers can start empty, reinforcing that existing commands do not carry an image configuration into the new name-level file.
