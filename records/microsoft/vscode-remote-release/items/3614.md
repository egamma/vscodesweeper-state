# Issue #3614 — Suggestion: use overrideCommand as false by default

[https://github.com/microsoft/vscode-remote-release/issues/3614](https://github.com/microsoft/vscode-remote-release/issues/3614)

## Summary

The current behavior is intentional but the requested separation remains unresolved. The public specification still exposes only `overrideCommand`, while the broader open spec proposal explicitly tracks an entrypoint property.

## Change summary

Separate command and entrypoint overriding so image entrypoints are preserved by default while Dev Containers can still install a non-terminating command.

## Best solution

Resolve the configuration shape in https://github.com/devcontainers/spec/issues/2, including defaults and backward compatibility, then have Dev Containers adopt that specification without breaking existing `overrideCommand` configurations.

## Evidence

- **current specification:** https://containers.dev/implementors/json_reference/ still documents only `overrideCommand`: it replaces the image's default startup command, defaults to true for image/Dockerfile configurations, and can be set to false when the image command must run.
- **intentional behavior:** https://github.com/microsoft/vscode-remote-release/issues/259 records the earlier bug fix that deliberately made `overrideCommand: true` override ENTRYPOINT; the maintainer explanation in this issue says this maximizes the number of images that start successfully by default.
- **remaining gap:** The current public configuration does not provide independent command and entrypoint controls, so `overrideCommand: false` is only a coarse workaround and does not satisfy the central request.
- **spec proposal:** https://github.com/devcontainers/spec/issues/2 is open and explicitly includes an `entrypoint` property, linking back to this issue's proposed `overrideEntrypoint`; a later update lists several implemented properties but not entrypoint, indicating this part remains unresolved.
