# Issue #3614 — Suggestion: use overrideCommand as false by default

[https://github.com/microsoft/vscode-remote-release/issues/3614](https://github.com/microsoft/vscode-remote-release/issues/3614)

## Summary

Keep open: the documented overrideCommand setting preserves ENTRYPOINT and CMD together, but does not provide the independent controls requested here. A maintainer proposed a backward-compatible split; the default for entrypoint overriding remains undecided.

## Change summary

Separate CMD and ENTRYPOINT overriding, allowing the image entrypoint to run by default while replacing its command.

## Best solution

The Dev Containers owner should resolve the proposed overrideCmd/overrideEntrypoint design with the Dev Container spec, preserving existing configurations and explicitly deciding the new defaults. Keep the extension implementation tracked here rather than folding it into a related spec proposal.

## Evidence

- **Maintainer-proposed change:** https://github.com/microsoft/vscode-remote-release/issues/3614#issuecomment-724125719 proposes deprecating overrideCommand and introducing overrideCmd and overrideEntrypoint without breaking existing configurations, while leaving the entrypoint default undecided. This later proposal prevents treating the earlier defense of current behavior as a decline decision.
- **Existing capability does not cover the full ask:** https://code.visualstudio.com/remote/advancedcontainers/start-processes documents that Dockerfile-based containers override both the default entrypoint and command, and overrideCommand:false disables that behavior. It preserves both rather than independently overriding CMD while retaining ENTRYPOINT.
- **Current specification:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md documents overrideCommand as defaulting to true for image/Dockerfile configurations and false for Docker Compose. That configuration-dependent default does not deliver the requested independent entrypoint control.
- **Related spec work is not a canonical:** https://github.com/devcontainers/spec/issues/2 is open and proposes common runtime properties, including entrypoint explicitly described as useful with this issue's proposed overrideEntrypoint. It does not own delivery of the separate controls in the Dev Containers extension.
- **Canonical search:** Tracker searches for overrideEntrypoint, overrideCommand with entrypoint, and overrideCommand with default found no other open canonical covering this request. https://github.com/microsoft/vscode-remote-release/issues/3593 concerns shell environment configuration; https://github.com/microsoft/vscode-remote-release/issues/3345 concerns Toolbox integration. Neither reports the same requested behavior.
