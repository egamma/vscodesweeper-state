# Issue #6096 — WSL2 terminal doesn't source .profile

[https://github.com/microsoft/vscode-remote-release/issues/6096](https://github.com/microsoft/vscode-remote-release/issues/6096)

## Summary

Keep this accepted WSL feature request open: documented configuration provides workarounds, but not automatic inheritance of the login-profile environment. The maintainers acknowledged the startup risks and subsequently accepted the request into Backlog; neither a complete fix nor a qualifying canonical was verified.

## Change summary

Make profile-defined environment variables, including ~/.local/bin on PATH, available in WSL integrated terminals without manual startup configuration.

## Best solution

The WSL extension owners should decide how to provide login-profile environment parity without letting misconfigured startup scripts block server startup. Build on the existing server-env-setup hook rather than introducing another equivalent script mechanism; keep first-terminal profile-selection defects separate from this server-environment request.
