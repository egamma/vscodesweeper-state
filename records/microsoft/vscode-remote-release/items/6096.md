# Issue #6096 — WSL2 terminal doesn't source .profile

[https://github.com/microsoft/vscode-remote-release/issues/6096](https://github.com/microsoft/vscode-remote-release/issues/6096)

## Summary

Keep open in the Backlog: the team accepted this feature request after it exceeded the 10-upvote threshold, and maintainers confirm that sourcing login profiles during WSL server startup remains an unresolved but risky design problem.

## Change summary

Provide a safe way for Remote - WSL terminals or server startup to load the user's login-profile environment, including PATH additions from ~/.profile.

## Best solution

The WSL extension owner should design an explicit, recoverable environment-initialization mechanism that cannot block server startup when a profile is misconfigured. The first-terminal profile restoration defect tracked in VS Code core may address one symptom but does not cover the broader server-environment request.
