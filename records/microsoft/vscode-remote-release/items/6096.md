# Issue #6096 — WSL2 terminal doesn't source .profile

[https://github.com/microsoft/vscode-remote-release/issues/6096](https://github.com/microsoft/vscode-remote-release/issues/6096)

## Summary

Keep open in the Backlog: the documented omission of shell startup scripts is intentional risk mitigation, but the team accepted this as a sufficiently supported feature request rather than resolving it as designed.

## Change summary

Have WSL remote terminals inherit environment changes from `.profile`, particularly additions such as `$HOME/.local/bin`.

## Best solution

The WSL component should provide a safe, explicit way to initialize the server and first terminal from the user's profile without allowing a broken startup script to prevent connection. The existing `server-env-setup` and login-shell workarounds are useful but do not fully provide reliable default profile loading.
