# Issue #10445 — [Remote-SSH Bug]: AFS - 2nd connection always fails - Failed to parse remote port from server output

[https://github.com/microsoft/vscode-remote-release/issues/10445](https://github.com/microsoft/vscode-remote-release/issues/10445)

## Summary

Keep open as the canonical AFS connection issue. Logs, independent reports, and maintainer analysis identify a regression in the exec-server path reading its live log from AFS; the available workarounds do not address the underlying compatibility gap.

## Change summary

Remote - SSH's second connection fails on AFS home directories because the exec-server startup path cannot reliably read the listening port from an open log file.

## Best solution

The SSH component should obtain the exec server's port through an AFS-safe mechanism, such as a closed status file, rather than parsing a concurrently open log. Preserve `remote.SSH.serverInstallPath` on local storage and disabling `remote.SSH.useExecServer` as documented workarounds.
