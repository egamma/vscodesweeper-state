# Issue #11947 — Windows host, exec server: after a network drop the window loops "reconnect, drop after 20 s" with `write ENOTSUP` in `_sendSocketToExtensionHost`

[https://github.com/microsoft/vscode-remote-release/issues/11947](https://github.com/microsoft/vscode-remote-release/issues/11947)

## Summary

Route to Remote - SSH: two independent Windows-host setups reproduce an exec-server reconnect loop with matching ENOTSUP socket-handoff errors. Disabling exec-server mode restores operation, but does not resolve the default-mode defect.

## Change summary

Reconnect to an existing Windows remote extension host without repeated timeouts or restarting the host and losing its session.

## Best solution

The SSH and VS Code Server owners should investigate Windows socket handoff during exec-server reconnection and restore reuse of the running extension host. The named-pipe explanation is a concrete hypothesis to verify, not an established root cause.
