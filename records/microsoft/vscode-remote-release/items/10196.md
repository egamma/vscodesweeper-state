# Issue #10196 — Unable to Start and Authenticate Remote Tunnel with Company Microsoft SSO

[https://github.com/microsoft/vscode-remote-release/issues/10196](https://github.com/microsoft/vscode-remote-release/issues/10196)

## Summary

A real Remote Tunnels capability gap remains for Microsoft accounts hosted in sovereign clouds. Generic Microsoft authentication shipped, but the available evidence does not show that the tunnel flow supports Azure US Government endpoints.

## Change summary

Allow Remote Tunnel hosting and vscode.dev access to authenticate company Microsoft SSO accounts backed by Azure US Government.

## Best solution

The Tunnels authentication flow should use the appropriate sovereign-cloud Microsoft provider and endpoint on both the host and vscode.dev sides. The tunnels owner should determine whether this can reuse VS Code's existing `microsoft-sovereign-cloud` provider or requires corresponding service support.

## Evidence

- **generic Microsoft authentication:** https://github.com/microsoft/vscode-remote-release/issues/8908 documents that Microsoft authentication was added for tunnels through `code tunnel user login --provider microsoft`, but it does not establish sovereign-cloud support.
- **sovereign provider prerequisite:** https://github.com/microsoft/vscode/issues/162539 implemented the separate `microsoft-sovereign-cloud` authentication provider and explains that consuming extensions must intentionally adopt it; Azure US Government uses https://login.microsoftonline.us/.
- **current documentation:** https://code.visualstudio.com/docs/remote/tunnels states that tunnel hosts and clients may authenticate with the same GitHub or Microsoft account, but documents no sovereign-cloud selection or endpoint configuration.
- **remaining gap:** The report reaches the organization's SSO flow but returns to vscode.dev while the tunnel host remains at “Signing in to your account,” consistent with the generic Microsoft flow not completing for the reported `.onmicrosoft.us` tenant.
