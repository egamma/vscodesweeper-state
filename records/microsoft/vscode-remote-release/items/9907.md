# Issue #9907 — GLIBC version dependency on legacy server

[https://github.com/microsoft/vscode-remote-release/issues/9907](https://github.com/microsoft/vscode-remote-release/issues/9907)

## Summary

Keep open for the containers/server owners to assess the historical ARMv7 legacy-runtime mismatch. The supplied platform comparison and loader errors suffice to retest the reported release; subsequent support changes do not establish that this defect was fixed.

## Change summary

The VS Code 1.89.1 legacy server fails to start in a Debian Stretch ARMv7 dev container because its Node binary requires unavailable glibc symbols.

## Best solution

The containers/server owners should determine whether the ARMv7 legacy artifact violated its intended compatibility baseline and resolve or explicitly document that historical mismatch. For current development, use a supported container architecture and distribution rather than assuming that skipping prerequisite checks supplies missing runtime libraries.
