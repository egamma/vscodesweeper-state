# Issue #10003 — Extend support for variables in `mount` syntax to include containerEnv, among others in devcontainer spec

[https://github.com/microsoft/vscode-remote-release/issues/10003](https://github.com/microsoft/vscode-remote-release/issues/10003)

## Summary

Keep open: the documented variables do not provide container-user home-directory expansion for mount targets, and a maintainer proposed a pre-creation image-environment expression. The related spec discussion does not replace the extension-side work.

## Change summary

Support resolving container environment or user-home information when configuring dev-container mounts.

## Best solution

The Dev Containers component should coordinate pre-creation variable semantics with the spec, then implement an unambiguous way to resolve mount targets from image or effective-user information. Preserve this product-side request until that capability ships; image HOME alone should not be assumed to identify an overridden remote user's home.

## Evidence

- **Existing capability does not cover the request:** https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson restricts ${containerEnv:VARIABLE_NAME} to remoteEnv and defines it as reading an environment variable after the container is running. localEnv and workspace variables do not expose the container user's home directory for mount targets.
- **Maintainer-proposed enhancement:** https://github.com/microsoft/vscode-remote-release/issues/10003#issuecomment-2188413385 explains that mounts are needed before container creation and proposes image-environment semantics or a new ${imageEnv:...} expression. This is an accepted improvement direction, not grounds for an as-designed decline.
- **Related spec issue, not a product canonical:** https://github.com/devcontainers/spec/issues/282 is open and describes the same unresolved ${containerEnv:HOME} mount-target use case; this reporter explicitly linked their request there. A spec decision alone would not ship the Dev Containers extension capability.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/2697 is open and older, but its examples concern remoteUser environment expansion and initializeCommand config expansion, not this report's mount-target home resolution. Searches for containerEnv mounts, imageEnv, and home-directory mounts did not establish another canonical meeting the re-review same-symptom requirement.
