# Issue #11548 — Support `--goto` with dev containers

[https://github.com/microsoft/vscode-remote-release/issues/11548](https://github.com/microsoft/vscode-remote-release/issues/11548)

## Summary

The existing CLI already supports this by combining `--goto` with `--file-uri`; the reported commands used those switches separately.

## Change summary

Open a file inside an attached Dev Container at a specified line and column from the local `code` CLI.

## Best solution

Keep the existing VS Code CLI behavior and direct users to pass the remote file through `--file-uri` while enabling `--goto`.

## Vision fit

- **Fit:** aligned
- **Reason:** Equivalent local and remote code navigation directly advances the stated remote-development parity goal.
- **Evidence:** The Remote Development promise is to let users open remote folders and take advantage of VS Code's full feature set.

- **Proposed comment:**

  > Thanks for the report. This is already supported by combining the two switches:
  > 
  > ```bash
  > code \
  >   --folder-uri "vscode-remote://attached-container+[container-hex]/path-to-project" \
  >   --goto \
  >   --file-uri "vscode-remote://attached-container+[container-hex]/path-to-project/file.ext:5:10"
  > ```
  > 
  > `--goto` enables line/column parsing, while the remote URI still needs to be supplied through `--file-uri`. The first attempted command omitted `--goto`; the second passed the URI as a positional path instead of a file URI.
