## Summary

Consolidate this request with the older, open project-directory request: both describe having to duplicate a shared Compose .env file into individual workspaces.

## Change summary

Reuse a shared .env beside an external docker-compose.yml for Compose interpolation without copying it into the current project.

## Best solution

Track the Dev Containers change in https://github.com/microsoft/vscode-remote-release/issues/2323: configurable Compose project-directory selection should let multiple workspaces reuse the same Compose configuration and interpolation environment.

In https://github.com/microsoft/vscode-remote-release/issues/4220#issuecomment-749527159, a maintainer distinguishes service env_file from this request; the reporter explicitly confirms Compose-file interpolation in https://github.com/microsoft/vscode-remote-release/issues/4220#issuecomment-749556955.
- **Existing capability boundary:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents automatic .env loading beside the Compose file and service-level env_file. https://containers.dev/implementors/json_reference/#compose-specific lists dockerComposeFile but no project-directory override. Automatic discovery may cover straightforward current setups, but service env_file and Docker runArgs do not provide explicit Compose interpolation-file selection.
- **Project-directory solution:** https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/ documents that --project-directory determines the directory used for default .env discovery. Selecting the shared Compose directory addresses this report's co-located external docker-compose.yml and .env without copying either.
