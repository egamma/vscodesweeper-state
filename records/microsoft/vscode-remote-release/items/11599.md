# Issue #11599 — Extension host crashes with "callback not provided" when DISPLAY forwarding target is unreachable

[https://github.com/microsoft/vscode-remote-release/issues/11599](https://github.com/microsoft/vscode-remote-release/issues/11599)

## Summary

Keep open with the existing containers routing: the report provides concrete steps and logs for an X11 connection failure escalating into an extension-host crash. Behavior on releases since Dev Containers 0.454.0 remains unconfirmed, but the supplied steps suffice to retest.

## Change summary

Starting an X11 client in a devcontainer crashes the extension host when the forwarded DISPLAY target refuses connections.

## Best solution

Dev Containers should handle X11 forwarding connection errors explicitly, failing the individual connection without terminating the extension host or disrupting the container session. Verify the supplied unreachable-target reproduction and the reported muxrpc callback diagnosis before implementing a targeted fix.

## Evidence

- **Product boundary and workaround:** The reporter says the container process survives while the extension host fails, and disabling DISPLAY or locally replacing the throwing callback avoids the crash. The unavailable X server explains the connection refusal, not the extension-host failure; these workarounds do not establish a shipped fix.

Its maintainer explanation at https://github.com/microsoft/vscode-remote-release/issues/7983#issuecomment-1459822002 says incrementing display numbers is expected; it does not resolve crashes when a forwarding target is unreachable.
