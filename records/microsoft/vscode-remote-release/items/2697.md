# Issue #2697 — Support ALL doc'd variables.

[https://github.com/microsoft/vscode-remote-release/issues/2697](https://github.com/microsoft/vscode-remote-release/issues/2697)

## Summary

Keep open: documented environment and workspace substitutions cover part of this request, but not configuration-variable expansion in initializeCommand or the broader requested variable support. Maintainers identified additions worth considering, and no verified canonical owns the full remaining scope.

## Change summary

Expand supported VS Code variables consistently across string values in devcontainer.json, including configuration references in initializeCommand.

## Best solution

The Dev Containers owner should define which additional variables can resolve before container startup, particularly ${config:docker.host} in initializeCommand, and implement and document that supported subset. Coordinate portable format changes with the Dev Container spec without losing the extension-side implementation work tracked here.

## Evidence

- **Existing capability and remaining gap:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md#variables-in-devcontainerjson documents ${localEnv:VARIABLE_NAME}, workspace paths and basenames, ${containerEnv:VARIABLE_NAME} restricted to remoteEnv, and ${devcontainerId}. These address environment and workspace substitutions but do not document ${config:docker.host}, executable-path substitutions, or universal support for the VS Code variable catalog.
- **Maintainer direction:** https://github.com/microsoft/vscode-remote-release/issues/2697#issuecomment-609854675 explains startup-time and local/container ambiguity constraints, while explicitly listing config and local/container executable paths as possible additions. This supports a scoped enhancement rather than a decline close.
- **Partial implementation:** https://github.com/microsoft/vscode-remote-release/issues/2697#issuecomment-618909798 attributes workspace-variable additions to https://github.com/microsoft/vscode-remote-release/issues/2473, which is closed. Those additions do not satisfy the configuration-reference example or the full request; the subsequent documentation announcement contains no reporter confirmation of complete resolution.
- **Environment example clarified:** https://github.com/microsoft/vscode-remote-release/issues/2697#issuecomment-609846231 states that remoteUser already expands other environment variables and suggests USERNAME is unset. That example alone does not establish a remote-extension bug.
- **Canonical search:** Searches for variable support, substitution, interpolation, and greedyVariableInterpolation found no verified full-scope canonical. The older open https://github.com/microsoft/vscode-remote-release/issues/1050 requests shell-command substitution, not the same configuration-variable symptom. The open https://github.com/microsoft/vscode-remote-release/issues/3418 concerns execPath in tasks and explicitly refers back to this issue for devcontainer.json additions; neither absorbs this request.
- **Documented product boundary:** https://code.visualstudio.com/docs/reference/variables-reference documents substitution for debugging, tasks, and selected settings, not every JSON string. Its narrower existing contract does not deliver this issue's requested Dev Containers enhancement.
