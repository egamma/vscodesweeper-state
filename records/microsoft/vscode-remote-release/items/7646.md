# Issue #7646 — Node file changes not detected running in docker container in vs code

[https://github.com/microsoft/vscode-remote-release/issues/7646](https://github.com/microsoft/vscode-remote-release/issues/7646)

## Summary

Keep open as an upstream file-notification issue: the logged Windows-backed workspace matches Docker's documented limitation on Linux container inotify events. Moving outside OneDrive did not resolve it, and no current-release resolution is confirmed.

## Change summary

Node development processes inside a dev container fail to detect saved TypeScript changes that are detected when running locally on Windows.

## Best solution

Separate Docker/WSL filesystem event delivery from Dev Containers behavior using the supplied reproduction on Linux-backed storage and the Windows bind mount. Linux-backed workspaces or container volumes are documented alternatives; reliable notifications for the original Windows-backed workflow require the container filesystem backend to deliver those events.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/7646 supplies a sample repository, npm commands, and the exact TypeScript file to edit. Multiple Node watchers fail inside the container while the local Windows workflow works.
- **Windows-backed workspace:** https://github.com/microsoft/vscode-remote-release/files/10168967/blah.txt records Dev Containers 0.262.3 with VS Code 1.71.2 and a Docker bind mount from a Windows F: drive into /workspaces/containers-windows-watch-no-worky. The sample devcontainer.json uses the standard Ubuntu image without a custom workspace mount.
- **Documented upstream limitation:** https://docs.docker.com/desktop/features/wsl/best-practices/ states that Linux containers only receive inotify file-change events when the original files are stored in the Linux filesystem, explicitly identifying automatic reload workflows as affected. This matches the logged Windows-source bind mount, although the original Docker backend mode was not explicitly recorded.
- **Thread follow-up:** In https://github.com/microsoft/vscode-remote-release/issues/7646, the reporter confirmed that moving outside OneDrive did not help. Later commenters described completion and Explorer/source-control refresh symptoms, but did not establish a current-release reproduction or confirm a fix.
- **Related reports, not a demonstrated canonical:** https://github.com/microsoft/vscode-remote-release/issues/8470 is open and describes tsc --watch failing on Windows-backed container storage, with discussion of WSL storage and container warnings. https://github.com/microsoft/vscode-remote-release/issues/9282 is open but requests Docker Compose watch integration rather than owning the underlying filesystem-notification fix.

These change the storage arrangement; they do not demonstrate that notifications on the reporter's original Windows bind mount have been fixed.
