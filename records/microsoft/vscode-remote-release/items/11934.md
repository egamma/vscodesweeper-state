# Issue #11934 — podman: "userns_mode: keep-id" is still needed for Compose-based Dev containers

[https://github.com/microsoft/vscode-remote-release/issues/11934](https://github.com/microsoft/vscode-remote-release/issues/11934)

## Summary

Keep this product-side report open and route it to Dev Containers/Podman. The linked CLI report supplies a minimal reproduction and a recent independent confirmation that Compose containers still require manual keep-id configuration.

## Change summary

Compose-based Podman dev containers need equivalent automatic user-namespace handling to image-based containers so non-root users can write to bind-mounted workspaces.

## Best solution

Coordinate the Compose namespace fix with https://github.com/devcontainers/cli/issues/1300 and ship it through Dev Containers, preserving explicit userns_mode settings. Keep this extension report until the product-side behavior is resolved; the CLI issue alone does not establish a shipped extension fix.

## Evidence

- **Reporter-observed remaining gap:** https://github.com/microsoft/vscode-remote-release/issues/11934 reports that Compose containers still need userns_mode: keep-id, unlike plain containers; the reporter explicitly links https://github.com/devcontainers/cli/issues/1300.
- **Reproduction and independent confirmation:** https://github.com/devcontainers/cli/issues/1300 provides paired image/Compose configurations on CLI 0.87.0 and rootless Podman 5.8.2: the Compose workspace appears as root:0 and the non-root remoteUser cannot write. https://github.com/devcontainers/cli/issues/1300#issuecomment-6515146056 independently confirms the same failure on CLI 0.90.0 and Podman 5.8.9 across aarch64 and x86_64, with userns_mode: keep-id as the workaround.
- **Earlier fix does not cover Compose:** https://github.com/devcontainers/cli/pull/985 changed only src/spec-node/singleContainer.ts, adding Podman arguments to the single-container run path. https://github.com/microsoft/vscode-remote-release/issues/10798#issuecomment-2826767753 announced Dev Containers 0.412.0-pre-release and CLI 0.76.0, but the later Compose reports demonstrate a separate remaining path.
- **Documented capability and workaround limits:** https://code.visualstudio.com/remote/advancedcontainers/docker-options documents dev.containers.dockerPath=podman and Compose providers, not automatic Compose keep-id handling. Manually editing the Compose service works around the problem but does not deliver the requested parity.
- **Related reports are not verified canonicals:** https://github.com/microsoft/vscode-remote-release/issues/10215 concerns Compose image-name resolution during updateUID, and https://github.com/microsoft/vscode-remote-release/issues/11105 concerns feature-build failures on Windows. Neither establishes ownership of this Linux Compose workspace-namespace defect.
