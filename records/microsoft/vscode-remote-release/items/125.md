# Issue #125 — Share dotfiles with the host machine

[https://github.com/microsoft/vscode-remote-release/issues/125](https://github.com/microsoft/vscode-remote-release/issues/125)

## Summary

Keep open for the remaining request to share personal host configuration without a dotfiles repository or project-specific setup. The reporter accepted the repository-based solution, but explicitly acknowledged that the discussion contains uncovered use cases.

## Change summary

Allow developers to reuse selected host dotfiles inside containers without mounting their entire home directory or baking personal configuration into shared images.

## Best solution

The Dev Containers component should support user-level, selective sharing of host configuration independently of a project's configuration. Coordinate with the related default-mount requests while retaining the distinction between binding files and automatically populating persistent configuration volumes.

- **Existing repository-based personalization:** https://code.visualstudio.com/docs/devcontainers/containers#_personalizing-with-dotfile-repositories documents dotfiles.repository, dotfiles.targetPath, and dotfiles.installCommand in User Settings. These support explicit host mounts but require container/project configuration and do not document automatic selective copying into a personal configuration volume.
