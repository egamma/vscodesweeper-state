# Issue #8810 — ssh-agent forward through Remote Tunnels

[https://github.com/microsoft/vscode-remote-release/issues/8810](https://github.com/microsoft/vscode-remote-release/issues/8810)

## Summary

Keep open: this is the accepted canonical request for securely forwarding a local SSH agent into Remote Tunnels, with substantial community support and no documented native capability. Because it concerns private-key access and credential delegation, the security-sensitive keep-open rule also applies.

## Change summary

Provide SSH-agent forwarding through Remote Tunnels so remote processes can authenticate without storing private keys on the remote machine.

## Best solution

The Tunnels and VS Code Server components should provide a secure, session-scoped bridge to the client's SSH agent for terminals and remote extensions. The separate devtunnel-plus-SSH workaround does not cover ordinary processes in the VS Code tunnel session.

## Vision fit

- **Fit:** aligned
- **Reason:** Securely using local credentials from a tunnel session advances remote/local parity and strengthens Tunnels as a mainstream remote-development path.
- **Evidence:** The Remote Development promise is to "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set," while the durable themes include connection fidelity and the VS Code Server lifecycle.
