# Issue #5388 — Clone repository in container volume with Docker Compose fails due to permissions for non-existant folder

[https://github.com/microsoft/vscode-remote-release/issues/5388](https://github.com/microsoft/vscode-remote-release/issues/5388)

## Summary

Verified cross-repository duplicate: the open Dev Container specification issue owns the broader workspace-mount inconsistency across Docker Compose, local containers, clone-in-volume, and Codespaces. A factual duplicate close is permitted despite this being team-authored.

## Change summary

Cloning a Docker Compose repository into a container volume retains a host bind mount for the container-side workspace path, causing Docker Desktop to reject the nonexistent host path.

## Best solution

Consolidate the design in https://github.com/devcontainers/spec/issues/106, then have the Dev Containers extension implement its consistent workspaceFolder/workspaceMount behavior for Docker Compose and clone-in-volume scenarios.
