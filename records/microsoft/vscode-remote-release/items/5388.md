# Issue #5388 — Clone repository in container volume with Docker Compose fails due to permissions for non-existant folder

[https://github.com/microsoft/vscode-remote-release/issues/5388](https://github.com/microsoft/vscode-remote-release/issues/5388)

## Summary

Keep this accepted, team-authored Dev Containers bug open: the documented workaround does not fix arbitrary Compose workspace mounts. Docker Desktop behavior changed during the discussion, but no current-release resolution is established; the supplied configuration, steps, and logs suffice for an owner retest.

## Change summary

Cloning a Compose-based repository into a container volume retains a workspace bind mount whose container-local source path is incorrectly treated as a host path.

## Best solution

The Dev Containers component should reconcile Compose workspace bind mounts with the cloned repository volume without requiring a hardcoded /workspaces target or fictitious host shares. Coordinate the mount semantics with devcontainers/spec, while retaining this issue for the extension's startup failure.
