# Issue #10603 — `tar -xf --no-same-owner` Option Not Supported on OpenWrt Remote Host for Extracting VS Code Server

[https://github.com/microsoft/vscode-remote-release/issues/10603](https://github.com/microsoft/vscode-remote-release/issues/10603)

## Summary

Keep open for Remote - SSH: the supplied logs and successful manual extraction identify a concrete bootstrap compatibility gap. The report predates current releases but provides sufficient steps to retest; no fixing release or confirmed resolution is documented.

## Change summary

Remote - SSH installation fails on ImmortalWrt because its BusyBox tar requires explicit gzip decompression and does not accept --no-same-owner.

## Best solution

The SSH bootstrap should select supported extraction flags for minimal tar implementations, preserving ownership behavior and explicitly handling gzip. Retest the supplied ImmortalWrt case; installing standalone tar is a workaround, not evidence that the extension's compatibility gap is fixed.
