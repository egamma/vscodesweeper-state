# Issue #5322 — Conditional mounting

[https://github.com/microsoft/vscode-remote-release/issues/5322](https://github.com/microsoft/vscode-remote-release/issues/5322)

## Summary

Keep open: optional bind mounts remain a distinct, maintainer-acknowledged Dev Containers capability gap. Existing path substitution and initialization workarounds do not let shared configurations skip missing sources automatically.

## Change summary

Allow explicitly optional bind mounts to be skipped when their source files or directories do not exist, without preventing container startup.

## Best solution

Coordinate optional-mount semantics with https://github.com/devcontainers/spec/issues/132 and deliver them through Dev Containers, checking source existence on the actual Docker host while preserving failures for required mounts. Retain this issue to track the product-side delivery.

The current public schema at https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json defines Mount with type, source, and target only, disallows additional object properties, and provides initializeCommand as a script hook rather than optional-mount semantics.
