# Issue #11323 — Remote Containers error starting because of image pull failing

## Summary

Keep open for the Dev Containers owner: the reporter supplied the missing configuration detail, explaining why the UID-adjustment image is never loaded. Versions have advanced since the report, but the supplied steps, logs, and environment setting suffice to retest; no confirmed fix or open canonical was established.

## Change summary

Dev Containers fails to start the UID-adjusted image when BUILDX_NO_DEFAULT_LOAD=1 disables implicit image loading.

## Best solution

Ensure the Dev Containers UID-adjustment build explicitly loads the image that its subsequent docker run requires, without requiring users to change their global Buildx preference. Retest the supplied configuration on current versions before deciding whether a change remains necessary.
