# Issue #11323 — Remote Containers error starting because of image pull failing

[https://github.com/microsoft/vscode-remote-release/issues/11323](https://github.com/microsoft/vscode-remote-release/issues/11323)

## Summary

The logs and Docker documentation identify a plausible failure when `BUILDX_NO_DEFAULT_LOAD=1` prevents the generated UID-update image from entering local storage, but the thread has only one current reproduction. A retest on the latest Dev Containers release is needed before treating this as an active extension defect.

## Change summary

Dev Containers fails to start when its generated UID-update image is built without `--load` under `BUILDX_NO_DEFAULT_LOAD=1`.

## Best solution

If this still reproduces, Dev Containers should explicitly request a locally loaded output for its internal UID-update image rather than depending on Docker's configurable default-load behavior.
