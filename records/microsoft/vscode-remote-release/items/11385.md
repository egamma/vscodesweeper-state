# Issue #11385 — Startup fails when not connected to the Internet

[https://github.com/microsoft/vscode-remote-release/issues/11385](https://github.com/microsoft/vscode-remote-release/issues/11385)

## Summary

Consolidate with the verified open report tracking WSL startup failing offline when a server update is required. This report adds an Insiders log showing removal of the previous installation before the download fails.

## Change summary

Allow WSL development to remain usable offline when VS Code requires a server update.

## Best solution

Track the offline-startup gap in https://github.com/microsoft/vscode-remote-release/issues/11607, preserving this report's Insiders details. The WSL owner should ensure a matching server is available offline rather than assume an older server can serve an updated client.

## Evidence

- **Verified canonical:** https://github.com/microsoft/vscode-remote-release/issues/11607 is open and WSL-labeled. Its VS Code 1.117 reproduction starts WSL offline with a server update pending, removes the previous installation, fails to download, and leaves startup unavailable. Another affected user confirms the offline-startup problem at https://github.com/microsoft/vscode-remote-release/issues/11607#issuecomment-5391959097.
- **Same observable failure:** https://github.com/microsoft/vscode-remote-release/issues/11385 shows WSL 0.104.3 with Insiders 1.108.0 deleting the previous server installation before attempting commit cff2c318f87b2ff763290e4d5020c250f78d61f8; wget then fails resolving update.code.visualstudio.com while offline. The Insiders channel and Ubuntu 24.04 details do not establish a distinct cause.
- **Compatibility constraint:** At https://github.com/microsoft/vscode-remote-release/issues/3839#issuecomment-1094844623, a maintainer explains that client and server versions must match, acknowledges the offline-startup gap, and suggests bundling their downloads. Skipping installation and running an incompatible older server is therefore not an established supported capability.
- **Historical fix is insufficient evidence:** https://github.com/microsoft/vscode-remote-release/issues/3839#issuecomment-1437517453 announced a fix in WSL 0.76.0, but this report and the open 1.117 report describe the failure on later versions. The closed historical issue is neither a valid duplicate target nor proof this report is resolved.
- **Documented boundary:** https://code.visualstudio.com/docs/remote/wsl#_what-are-the-connectivity-requirements-for-the-wsl-extension documents outbound HTTPS requirements; https://code.visualstudio.com/docs/remote/faq#_what-are-the-connectivity-requirements-for-vs-code-server distinguishes installation downloads from local WSL transport. Neither documents automatic offline fallback to an older server. The supplied candidate https://github.com/microsoft/vscode-remote-release/issues/6092 instead concerns Dev Containers certificate trust and does not own this failure.
