# Issue #11385 — Startup fails when not connected to the Internet

[https://github.com/microsoft/vscode-remote-release/issues/11385](https://github.com/microsoft/vscode-remote-release/issues/11385)

## Summary

This may be a regression in WSL's background server-download behavior, but the lone report is eight months old and unconfirmed on current releases. A current retest is needed before routing it as an active defect.

## Change summary

Keep WSL usable offline after a VS Code update instead of removing the previous server and then failing to download its replacement.

## Best solution

The WSL extension should ensure the matching VS Code Server archive is available before an update leaves an offline user unable to connect, preserving the background-prefetch behavior introduced in WSL 0.76.0. The component owner first needs a current Insiders reproduction and WSL log to distinguish a regression from a missed prefetch window.
