# Issue #11883 — Dev Containers: .devport file is shared between containers that bind-mount the same ~/.vscode-server, causing "already running" server to be forwarded to the wrong port (WebSocket close 1006)

[https://github.com/microsoft/vscode-remote-release/issues/11883](https://github.com/microsoft/vscode-remote-release/issues/11883)

## Summary

Keep open as a Dev Containers reconnection bug: an independent November 22 reproduction on VS Code 1.147.0 confirms that shared runtime metadata still redirects connections to another container's port. Private state mounts work around the failure but do not provide automatic container-local endpoint handling.

## Change summary

Containers sharing a VS Code Server installation overwrite each other's cached server port, breaking subsequent attachments and reloads.

## Best solution

Dev Containers should keep runtime connection metadata scoped to each container instance while permitting shared installed server files, and validate cached endpoints before reusing them. Reconnecting, restarting, or recreating one container should not disrupt another.
