# Issue #11883 — Dev Containers: .devport file is shared between containers that bind-mount the same ~/.vscode-server, causing "already running" server to be forwarded to the wrong port (WebSocket close 1006)

[https://github.com/microsoft/vscode-remote-release/issues/11883](https://github.com/microsoft/vscode-remote-release/issues/11883)

## Summary

Keep the accepted Dev Containers isolation request open. Per-project Machine mounts mitigate the collision, but no verified shipped capability or open canonical covers the reported wrong-port reconnection failure.

## Change summary

Make server-port discovery container-specific when containers share ~/.vscode-server.

## Best solution

Dev Containers should isolate runtime port records per container or validate the recorded port against the detected server before reuse. Preserve shared server installations without requiring users to partition Machine data manually.
