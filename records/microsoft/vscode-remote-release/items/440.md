# Issue #440 — Configurable Remote SSH Server Timeout

[https://github.com/microsoft/vscode-remote-release/issues/440](https://github.com/microsoft/vscode-remote-release/issues/440)

## Summary

This remains a valid, well-supported feature request: Remote - SSH still lacks a documented setting for extending the server's post-disconnection lifetime. Related persistent-session work is broader and does not supersede this narrower configuration request.

## Change summary

Allow users to configure how long the Remote - SSH server preserves a disconnected session before terminating it and losing remote state.

## Best solution

Remote - SSH and the VS Code Server should expose a bounded reconnection-grace or inactivity-timeout setting, documenting the resource-retention tradeoff and coordinating its behavior with the broader persistent-session design tracked in https://github.com/microsoft/vscode-remote-release/issues/3096.

## Vision fit

- **Fit:** aligned
- **Reason:** Preserving remote state through longer connection interruptions directly advances the project's durable connection-reliability and reconnection goals.
- **Evidence:** The public Remote Development direction emphasizes connection reliability and reconnection, while https://code.visualstudio.com/docs/remote/ssh promises a local-quality development experience regardless of where code is hosted.

## Evidence

- **distinct timeout setting:** https://github.com/microsoft/vscode-remote-release/issues/462 explicitly distinguishes its initial-connect timeout from this issue's timeout after an established connection, so remote.SSH.connectTimeout does not satisfy the central request.
