# Issue #440 — Configurable Remote SSH Server Timeout

[https://github.com/microsoft/vscode-remote-release/issues/440](https://github.com/microsoft/vscode-remote-release/issues/440)

## Summary

Keep open for configurable Remote - SSH session retention: existing terminal persistence does not provide a server timeout setting. The related persistent-session request overlaps, but indefinite retention does not cover this issue's configurable retention and cleanup scope.

## Change summary

Allow users to configure the remote server's inactivity timeout so disconnected sessions retain state for an appropriate duration.

## Best solution

Remote - SSH and the VS Code Server should expose a supported retention setting that accommodates both longer reconnection windows and shorter cleanup periods. Coordinate with https://github.com/microsoft/vscode-remote-release/issues/3096 without replacing configurable duration with indefinite persistence alone.

## Evidence

- **Requested capability:** https://github.com/microsoft/vscode-remote-release/issues/440 requests a configurable inactivity timeout; its discussion describes overnight VPN disconnections losing terminals and extension state, alongside concerns about disconnected servers consuming resources. The maintainer's 2019 increase to eight hours does not establish configurability or a confirmed resolution.
- **Existing-capability check:** https://code.visualstudio.com/docs/terminal/advanced#_persistent-sessions documents terminal.integrated.enablePersistentSessions: reconnection reuses a surviving process, while revive relaunches a process with its original environment. Neither capability configures remote server retention or preserves arbitrary runtime state after server shutdown. https://code.visualstudio.com/docs/remote/ssh does not document a setting delivering the requested timeout control.
- **Established tracking ownership:** A maintainer explicitly closed the configurable idle-shutdown request as a duplicate of this issue: https://github.com/microsoft/vscode-remote-release/issues/7098#issuecomment-1227505020. This supports retaining this issue as the tracker for configurable duration.
- **Related issue is not a full-scope canonical:** https://github.com/microsoft/vscode-remote-release/issues/3096 is verified open, in Backlog, with 563 upvotes. It requests an infinite timeout and preservation across closing the client. Although it meets the re-review prominence requirement and shares session-loss symptoms, indefinite retention alone does not deliver arbitrary finite timeout configuration, particularly shorter cleanup periods.
- **Configuration versus workaround:** https://github.com/microsoft/vscode-remote-release/issues/3096#issuecomment-1617150814 describes removing --enable-remote-auto-shutdown through a shell wrapper and explicitly distinguishes permanent retention from changing the timeout value. That workaround is not a supported configurable timeout. https://github.com/microsoft/vscode-remote-release/issues/10205#issuecomment-2548530593 likewise identifies this issue as covering shutdown with a small timeout.
