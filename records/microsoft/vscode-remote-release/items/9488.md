# Issue #9488 — [Remote-SSH Bug]: the server always reconnect and auto save action stuck  always when save.

[https://github.com/microsoft/vscode-remote-release/issues/9488](https://github.com/microsoft/vscode-remote-release/issues/9488)

## Summary

Keep open: independent users confirmed the reconnection failure, and the reporter captured a remote extension-host heap exhaustion and SIGABRT. Confirmations are historical, not evidence of current-release persistence or resolution.

## Change summary

Remote SSH sessions repeatedly reconnect, stall saving, and can experience a remote extension-host crash.

## Best solution

The SSH owner should investigate extension-host responsiveness and memory growth during the save/reconnect cycle, using the existing logs and an extension-free comparison. Coordinate with VS Code core if the failure is localized to its server or extension-host machinery; the terminal exception alone does not establish that ownership.

## Evidence

- **Observed crash:** https://github.com/microsoft/vscode-remote-release/issues/9488#issuecomment-1925588228 records repeated reconnections, approximately 4 GB of extension-host heap usage, 'Reached heap limit', and process termination with SIGABRT. This proves a historical crash, but not its root cause.
- **Extension isolation:** The maintainer requested disabling remote extensions at https://github.com/microsoft/vscode-remote-release/issues/9488#issuecomment-1976891943; another affected user reported the same behavior with none installed at https://github.com/microsoft/vscode-remote-release/issues/9488#issuecomment-2371331428. Attribution to another installed extension is not established.
- **Independent confirmation:** https://github.com/microsoft/vscode-remote-release/issues/9488#issuecomment-2555640300 reports team-wide failures on VS Code 1.96.2 across Mac and Windows: port forwarding fails before the session fails, while ordinary SSH remains available. No subsequent fixing-release confirmation appears in the discussion.
- **Terminal exception is not the connection diagnosis:** https://github.com/microsoft/vscode-remote-release/issues/9488#issuecomment-2554179841 explains that the missing-pty exception represents an already-closed terminal and should only fail title/icon updates. The related https://github.com/microsoft/vscode/issues/236403 therefore does not establish ownership of the save/reconnection failure.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/7497 discusses extension-host response timeouts, while https://github.com/microsoft/vscode-remote-release/issues/1257 centers on large-workspace reconnects and watcher problems. Neither establishes the same cause as this report's save stalls and heap exhaustion. https://github.com/microsoft/vscode-remote-release/issues/10568 covers forwarded ports failing after reconnection, not the full failure reported here.
- **Repository troubleshooting guidance:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting recommends identifying the affected remote process and testing with extensions disabled for high memory usage. The supplied server logs already identify an extension-host crash; further diagnosis should distinguish that failure from the incidental terminal errors.
