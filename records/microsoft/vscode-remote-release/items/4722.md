# Issue #4722 — Copy .gitconfig before running dotfiles installation

[https://github.com/microsoft/vscode-remote-release/issues/4722](https://github.com/microsoft/vscode-remote-release/issues/4722)

## Summary

A real configuration gap remains: host Git identity is copied only after dotfiles installation, while copying it earlier would break dotfiles installers that preserve existing files. The issue is correctly routed and should remain under discussion rather than imposing either ordering globally.

## Change summary

Allow team dotfiles installers to read the host user's Git name and email by making the host `.gitconfig` available before installation.

## Best solution

The Dev Containers component should make Git-config sequencing configurable, preserving the current safe default while allowing users to opt into copying the host configuration before dotfiles installation.

## Vision fit

- **Fit:** aligned
- **Reason:** Making local Git identity reliably available during container personalization advances the goal of a local-quality development experience inside Dev Containers.
- **Evidence:** The public Remote Development vision promises users can open a folder in a container and take advantage of VS Code's full feature set, while the Git credentials documentation says the extension automatically copies the local `.gitconfig` into the container.
