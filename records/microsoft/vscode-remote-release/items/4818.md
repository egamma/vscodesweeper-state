# Issue #4818 — File watcher maxes CPU when folder contains symlink loop

[https://github.com/microsoft/vscode-remote-release/issues/4818](https://github.com/microsoft/vscode-remote-release/issues/4818)

## Summary

Keep open: the symlink, reconnect trigger, CPU profile, and recursively expanding path provide enough detail to retest. The documented replacement of Chokidar with Parcel suggests resolution, but does not verify this report's post-hibernation failure.

## Change summary

Reconnecting to a WSL workspace containing a circular directory symlink starts multiple file-watcher processes that saturate CPU.

## Best solution

Retest the supplied circular-symlink and hibernation/reconnect scenario with the current WSL server watcher, ensuring traversal terminates and reconnect does not accumulate busy watchers. If it persists in shared file-watching behavior, a maintainer can transfer this to microsoft/vscode; investigate WSL-specific process lifecycle here if reconnect is the distinguishing cause.
