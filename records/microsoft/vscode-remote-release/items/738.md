# Issue #738 — Utilize packaged system vscode server rather than pull tarball

[https://github.com/microsoft/vscode-remote-release/issues/738](https://github.com/microsoft/vscode-remote-release/issues/738)

## Summary

The system-managed RPM and server-reuse request remains distinct from today's local-download fallback. Route it to the SSH and server-installation owners; the related offline-installation requests do not establish a canonical covering system-level packaging.

## Change summary

Provide a system-installable VS Code Server RPM that Remote - SSH can launch as the connecting user instead of downloading and extracting a server tarball.

## Best solution

The Remote - SSH and VS Code Server owners should evaluate an administrator-managed server package and supported discovery path, preserving per-user execution and client/server compatibility. Offline transfer alone does not deliver the requested system-managed installation.
