# Issue #1460 — Multiple container support for multi root workspaces

[https://github.com/microsoft/vscode-remote-release/issues/1460](https://github.com/microsoft/vscode-remote-release/issues/1460)

## Summary

Keep open: current documentation still limits each window to one connected container. Switching containers or using separate windows does not deliver concurrent per-folder container environments, and no verified canonical supersedes this request.

## Change summary

Allow a multi-root workspace to start and connect each folder to its own dev container concurrently in one VS Code window.

## Best solution

Keep this issue as the Dev Containers tracking point for concurrent per-folder container environments, with container-specific terminals, debugging and extensions. The team should assess the required multi-remote workspace support rather than treating container switching or shared toolchains as equivalent.

## Evidence

- **Existing capability does not cover the ask:** https://code.visualstudio.com/remote/advancedcontainers/connect-multiple-containers explicitly states that only one container can be connected per window. Separate devcontainer.json files can start a shared Compose stack, but Dev Containers: Switch Container reloads the window into the selected container rather than connecting workspace roots concurrently.
- **Maintainer clarified the product gap:** https://github.com/microsoft/vscode-remote-release/issues/1460#issuecomment-661349224 defines this request as multiple containers concurrently in one UI instance. https://github.com/microsoft/vscode-remote-release/issues/1460#issuecomment-661399652 distinguishes separate windows, running tests in other containers, and multi-root workspaces within one container; none provides the requested per-folder environments.
- **Workarounds preserve the limitation:** https://github.com/microsoft/vscode-remote-release/issues/1460#issuecomment-1517582691 describes combining Python and Node into one container, losing separate configurations and rebuild isolation. https://github.com/microsoft/vscode-remote-release/issues/1460#issuecomment-1955991689 instead uses separate frontend and backend windows.
- **Canonical search:** Open-issue searches for multiple containers, multi-root workspaces, single-window containers and multiple remotes found no verified replacement. https://github.com/microsoft/vscode-remote-release/issues/5945 concerns shared-volume mounting, while https://github.com/microsoft/vscode-remote-release/issues/2795 concerns rebuilding only the targeted Compose service; neither owns concurrent per-folder connections.
- **Related work has different scope:** https://github.com/microsoft/vscode-remote-release/issues/387 is closed and explicitly scoped its initial workspace-opening improvement to a single container. https://github.com/microsoft/vscode-remote-release/issues/9265 describes the same concurrent multi-container workflow and is closed with a duplicate comment pointing here: https://github.com/microsoft/vscode-remote-release/issues/9265#issuecomment-6927991294.
