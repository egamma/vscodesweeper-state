# Issue #10599 — '~' parsing error in windows

[https://github.com/microsoft/vscode-remote-release/issues/10599](https://github.com/microsoft/vscode-remote-release/issues/10599)

## Summary

The log shows the expanded Windows config path losing its backslashes before OpenSSH reads it, but the report was not tested with the generated command outside VS Code and has no independent confirmation. A current-version retest is needed to distinguish Remote - SSH path handling from the Scoop SSH shim or terminal environment.

## Change summary

Using `~/.ssh/config` for `remote.SSH.configFile` on Windows produces an unusable `-F` path and prevents the SSH connection.

## Best solution

Remote - SSH should pass the expanded config-file path to OpenSSH without changing its meaning. Retesting the generated command and comparing the Scoop client with Windows OpenSSH will identify whether the SSH component or the local client shim owns the failure.
