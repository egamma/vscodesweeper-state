# Issue #6600 — Enable SSH agent forwarding for scp

[https://github.com/microsoft/vscode-remote-release/issues/6600](https://github.com/microsoft/vscode-remote-release/issues/6600)

## Summary

Keep open: documented SSH agent forwarding does not establish support for forwarding during SCP server uploads, and no verified canonical or shipped fix covers this request. The accepted Backlog item needs an explicit, security-conscious forwarding decision rather than unconditional use of -A.

## Change summary

Allow explicitly enabling SSH agent forwarding for SCP uploads of the locally downloaded VS Code Server.

## Best solution

Remote - SSH should support deliberate opt-in agent forwarding during server uploads, preserving the non-forwarding default. Evaluate the thread's proposal to honor host-specific ForwardAgent yes when constructing the SCP command, including compatibility with Cygwin clients.

- **Existing-capability check:** https://code.visualstudio.com/docs/remote/ssh documents localServerDownload as controlling local download and transfer. https://code.visualstudio.com/docs/remote/troubleshooting#_making-local-ssh-agent-available-on-the-remote documents ForwardAgent yes for remote tools, not explicit SCP forwarding. Neither documented surface establishes coverage of this upload-specific request.
- **SCP requires explicit forwarding:** https://www.openssh.com/txt/release-8.4 states that scp and sftp accept -A to explicitly enable agent forwarding and otherwise do not forward an agent even when ssh_config enables it. This supports treating the request as additional extension capability, not an OpenSSH defect.
