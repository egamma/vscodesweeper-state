[https://github.com/microsoft/vscode-remote-release/issues/10941](https://github.com/microsoft/vscode-remote-release/issues/10941)

## Summary

Keep open for Remote - SSH investigation: the supplied connection steps and full log suffice to retest the missing architecture suffix. The report concerns VS Code 1.100.0 and Remote - SSH 0.120.0; current-release resolution is unverified, and neither a fix nor an open canonical was established.

## Change summary

Remote - SSH generates cli-win32- instead of cli-win32-x64 when bootstrapping a Windows host, causing both remote and local downloads to fail with HTTP 404.

## Best solution

The SSH owner should investigate why the bootstrap loses the architecture despite the standalone probe returning x64, and ensure an empty architecture cannot produce a download request. Compare the piped PowerShell session with the interactive probe before attributing the failure to host policy.
