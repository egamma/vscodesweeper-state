# Issue #3120 — remote container activated from right click workbench menu context and maintain context of original folder after closing

[https://github.com/microsoft/vscode-remote-release/issues/3120](https://github.com/microsoft/vscode-remote-release/issues/3120)

## Summary

Keep open: documented container-opening commands do not establish coverage of launching a selected Explorer subfolder while preserving the original parent-project context. No verified canonical owns both parts of this request.

## Change summary

Launch a submodule folder in a dev container from its Explorer context menu and retain the parent project's state when the container window closes.

## Best solution

Dev Containers should provide a selected-folder launch action that leaves the parent workspace intact, preferably by opening the container in a separate window. Define the return behavior explicitly rather than requiring the user to navigate back to the parent repository.
