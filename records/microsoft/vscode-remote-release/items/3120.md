# Issue #3120 — remote container activated from right click workbench menu context and maintain context of original folder after closing

[https://github.com/microsoft/vscode-remote-release/issues/3120](https://github.com/microsoft/vscode-remote-release/issues/3120)

## Summary

A real Dev Containers workflow gap remains: current commands can open a selected folder in a container and reopen it locally, but do not provide the requested Explorer-folder shortcut or restore the original parent workspace. Keep this correctly routed feature request open for product discussion.

## Change summary

Allow an Explorer folder to be opened directly in a dev container while preserving the original parent workspace for return afterward.

## Best solution

Dev Containers should offer a folder context-menu action that opens the selected subfolder in a container without losing the originating workspace, either by using a separate window or restoring the recorded parent workspace when reopening locally.
