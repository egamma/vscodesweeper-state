# Issue #903 — Git for Windows functionality breaks when repository is open in Remote WSL

[https://github.com/microsoft/vscode-remote-release/issues/903](https://github.com/microsoft/vscode-remote-release/issues/903)

## Summary

Keep this canonical Git interoperability report open. WSL and VS Code have evolved since the historical confirmations, but the supplied steps suffice to retest; neither the documented WSL 1 workaround nor upgrading to WSL 2 establishes resolution of the full report.

## Change summary

Opening an NTFS-hosted repository through Remote WSL prevents Windows Git clients from replacing Git index or reference files.

## Best solution

The WSL component owner should retest Windows Git operations against an NTFS repository while its Remote WSL window is open, isolating file watching from Git integration. Preserve this issue as the canonical until the VS Code-dependent failures are resolved or conclusively attributed to an upstream filesystem limitation.
