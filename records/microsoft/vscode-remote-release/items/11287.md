# Issue #11287 — Custom glibc: Patchelf permission denied

[https://github.com/microsoft/vscode-remote-release/issues/11287](https://github.com/microsoft/vscode-remote-release/issues/11287)

## Summary

Keep open for investigation of Dev Containers server-volume ownership during custom-glibc patching. The supplied steps, installation log and independent historical confirmation suffice to retest; neither a current-release fix nor a matching canonical was established.

## Change summary

Custom-glibc server patching fails with permission denied when a non-root container user cannot modify the root-owned VS Code server volume.

## Best solution

The containers and code-server owners should retest installation and patching with a non-root remoteUser, including Podman keep-id, and determine a compatible installation sequence or explicitly document the limitation. Successful server startup should not leave the bundled extension-signature executable unusable with the same sysroot.
