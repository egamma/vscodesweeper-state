# Issue #11287 — Custom glibc: Patchelf permission denied

[https://github.com/microsoft/vscode-remote-release/issues/11287](https://github.com/microsoft/vscode-remote-release/issues/11287)

## Summary

The custom-glibc workaround does not support non-root Dev Container server installations because the root-owned shared server volume cannot be patched by the remote user. This remains a documented capability gap and should be routed to Dev Containers rather than closed.

## Change summary

Allow custom-glibc patching of the VS Code Server in Dev Containers configured with a non-root remote user.

## Best solution

The Dev Containers installation path should either prepare a user-owned patchable server copy before startup or perform the documented patchelf operation with appropriate ownership, including Podman keep-id environments. If that workflow cannot be supported, the documentation should clearly limit it to Remote-SSH.
