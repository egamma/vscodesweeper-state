# Issue #1333 — Support SELinux enabled systems

[https://github.com/microsoft/vscode-remote-release/issues/1333](https://github.com/microsoft/vscode-remote-release/issues/1333)

## Summary

A meaningful gap remains: SELinux users can configure or relabel mounts manually, but the default Dev Containers workspace mount still lacks automatic SELinux-aware handling. The issue is already routed to the containers area and has continued reports through Fedora 42.

## Change summary

Make default workspace bind mounts work on SELinux-enabled hosts without per-project mount overrides or manual host relabeling.

## Best solution

Dev Containers should detect the relevant Linux runtime and apply a safe SELinux-compatible workspace mount automatically, while preserving portable devcontainer configurations across SELinux and non-SELinux hosts.

## Evidence

- **existing workaround:** Maintainer guidance in https://github.com/microsoft/vscode-remote-release/issues/1333#issuecomment-911479923 uses an empty `workspaceMount` plus `runArgs` with `--volume=...:Z`; this works around rather than satisfies automatic default-mount support.
- **documentation gap:** https://code.visualstudio.com/remote/advancedcontainers/change-default-source-mount documents `workspaceMount` using Docker's `--mount` syntax, while https://docs.docker.com/engine/storage/bind-mounts/#configure-the-selinux-label lists `z` and `Z` only for `--volume` mounts.
- **current demand:** The issue has 29 upvotes, and reports through Fedora 42 continue to require host `chcon`, wrapper scripts, or project-specific configuration: https://github.com/microsoft/vscode-remote-release/issues/1333#issuecomment-3520468822.
- **no complete existing capability:** Current settings can replace the generated mount or disable SELinux labeling, but the thread shows these approaches vary by Docker, Podman, user namespaces, and image user; none provides portable out-of-the-box behavior.
