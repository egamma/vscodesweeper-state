# Issue #2447 — resources.dirname on a remote uri that is just "C:/" incorrectly results in "/"

[https://github.com/microsoft/vscode-remote-release/issues/2447](https://github.com/microsoft/vscode-remote-release/issues/2447)

## Summary

Keep open: this team-authored bug was deliberately split from the verified Windows-remote issue, and no public fixing commit referencing this issue or open canonical duplicate was found.

## Change summary

Preserve a remote Windows drive root when computing its parent so Open Folder starts at C:\ rather than \.

## Best solution

VS Code's URI resource handling should preserve the drive root when `dirname` processes a Windows remote URI for C:/. The SSH scenario then needs verification on a current Windows remote.
