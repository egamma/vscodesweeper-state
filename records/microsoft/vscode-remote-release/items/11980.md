# Issue #11980 — Dev Containers rebuild loses user-scoped `dotfiles.repository` when launched from WSL

[https://github.com/microsoft/vscode-remote-release/issues/11980](https://github.com/microsoft/vscode-remote-release/issues/11980)

## Summary

Keep open: the report provides sufficient steps and contrasting command arguments to retest the missing User-setting fallback on Dev Containers 0.475.0. Related reports do not establish that the WSL rebuild and activation-dependent failure is already owned elsewhere.

## Change summary

Rebuilding a container from WSL omits the Windows User dotfiles.repository value unless an extension-version switch precedes the rebuild without reloading.

## Best solution

The Dev Containers owner should investigate configuration resolution across ordinary rebuilds and extension activation, ensuring the local User dotfiles.repository fallback reaches run-user-commands consistently. Compare with the related remote-container reports before consolidating; their shared root cause is not yet established.
