[https://github.com/microsoft/vscode-remote-release/issues/11684](https://github.com/microsoft/vscode-remote-release/issues/11684)

The recurring icon-loading regression has a verified public fix shipped in VS Code 1.138, but the complete thread also reports remote commands failing despite extension activation. Route to the SSH owner to distinguish that remaining behavior before closing the whole report.

## Change summary

## Evidence

- **Recurrence after initial resolution:** The reporter confirmed icons worked in 1.124.2 at https://github.com/microsoft/vscode-remote-release/issues/11684#issuecomment-4694393383, but subsequent independent reports reproduced the failure on 1.136–1.137 across Windows, Linux, and macOS. The initial confirmation cannot establish resolution of the later regression.
- **Verified icon fix:** https://github.com/microsoft/vscode/commit/365b48f9bc374b5eaadb5a38bd605f940081ae3a removes the empty-referrer rejection from src/vs/code/electron-main/app.ts and dispatches valid window-authority requests through createManagedRemoteResourceRequestHandler in src/vs/platform/protocol/electron-main/managedRemoteResourceProtocol.ts. This directly addresses the thread's vscode-managed-remote-resource SVG requests failing with net::ERR_FAILED when using the SSH managed transport; protocol error bodies also become Buffers.
- **Shipping and confirmation:** A maintainer announced the fix for VS Code 1.138 at https://github.com/microsoft/vscode/issues/334144#issuecomment-5619375771. Users confirmed restored icons with useExecServer enabled at https://github.com/microsoft/vscode-remote-release/issues/11839#issuecomment-5719129293 and https://github.com/microsoft/vscode-remote-release/issues/11839#issuecomment-5720068493.
- **Distinct remaining behavior:** The complete comment at https://github.com/microsoft/vscode-remote-release/issues/11684#issuecomment-5631311180 additionally reports title-bar actions failing with command 'X' not found while remoteexthost.log confirms extension activation. The icon-resource fix does not establish that command registration or execution is repaired.
- **Canonical scope check:** https://github.com/microsoft/vscode-remote-release/issues/11839 is open and matches the invisible-icon symptom, managed-resource failure, and useExecServer workaround. Its verified resolution concerns resource loading, not the additional command-not-found behavior here, so it does not demonstrably absorb the full report.
