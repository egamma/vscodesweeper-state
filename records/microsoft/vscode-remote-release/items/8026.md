# Issue #8026 — Cannot use env.WSL_INTEROP as a remoteEnv in dev container

[https://github.com/microsoft/vscode-remote-release/issues/8026](https://github.com/microsoft/vscode-remote-release/issues/8026)

## Summary

Keep open as a valid Backlog feature request. Dev Containers intentionally filters WSL_INTEROP because its temporary socket depends on the originating WSL process, and the documented remoteEnv mechanism does not overcome that lifecycle constraint.

## Change summary

Allow a dev container launched from WSL to use the host WSL_INTEROP socket through remoteEnv.

## Best solution

The Dev Containers component should provide a safe, lifecycle-aware way to expose WSL interoperability inside a container, including keeping the originating WSL process and socket available when necessary.
