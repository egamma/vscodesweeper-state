# Issue #8026 — Cannot use env.WSL_INTEROP as a remoteEnv in dev container

[https://github.com/microsoft/vscode-remote-release/issues/8026](https://github.com/microsoft/vscode-remote-release/issues/8026)

## Summary

Keep this accepted Dev Containers request open: the maintainer confirmed deliberate WSL_INTEROP filtering, but documented environment forwarding does not address the socket-lifetime limitation. No verified open canonical or confirmed fix was found.

## Change summary

Allow the WSL host's WSL_INTEROP value to be passed into a dev container through remoteEnv.

## Best solution

The Dev Containers owner should determine how to expose a usable WSL interop socket for the container session, including preserving its originating process where necessary, rather than merely forwarding a potentially expired socket path.
