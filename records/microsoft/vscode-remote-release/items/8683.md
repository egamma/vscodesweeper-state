# Issue #8683 — Support forks in cloneInVolume links

[https://github.com/microsoft/vscode-remote-release/issues/8683](https://github.com/microsoft/vscode-remote-release/issues/8683)

## Summary

This remains a valid Dev Containers feature gap: current cloneInVolume badges clone their fixed repository URL and do not let contributors choose their GitHub fork. The existing manual clone command is only a workaround, and no broader canonical issue owns fork selection.

## Change summary

Allow an Open in Dev Containers cloneInVolume link for an upstream repository to open the contributor's fork instead.

## Best solution

The Dev Containers extension should let a cloneInVolume link offer an authenticated user's fork when one exists, while retaining the upstream repository as the default or fallback.
