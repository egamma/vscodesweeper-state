# Issue #8683 — Support forks in cloneInVolume links

[https://github.com/microsoft/vscode-remote-release/issues/8683](https://github.com/microsoft/vscode-remote-release/issues/8683)

## Summary

Keep this accepted Dev Containers request open: documented clone links target a specified repository, but do not establish a way for an upstream README link to offer the contributor's own fork. No qualifying open canonical was found.

## Change summary

Allow an upstream repository's cloneInVolume link to offer opening the developer's own fork instead.

## Best solution

Dev Containers should offer fork selection when opening a repository through cloneInVolume, preserving the upstream repository as an option. This is extension-side onboarding work, not merely a devcontainer.json format change.
