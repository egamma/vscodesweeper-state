# Issue #4024 — Automatically add SSH keys to ssh-agent

[https://github.com/microsoft/vscode-remote-release/issues/4024](https://github.com/microsoft/vscode-remote-release/issues/4024)

## Summary

Keep open: forwarding an existing SSH agent does not load its keys, and current documentation still requires explicit ssh-add. The maintainer-supported direction is opt-in loading or an empty-agent notification, preserving the user's control over credential availability.

## Change summary

Help Dev Containers users load host SSH keys when the forwarded agent is empty, without requiring machine-specific project configuration.

## Best solution

The Dev Containers component should offer an empty-agent notification with an explicit key-loading action, or a disabled-by-default user setting. Preserve deliberate key removal and support remote Docker daemons rather than universally mounting Docker Desktop's socket.

## Evidence

- **Established product direction:** https://github.com/microsoft/vscode-remote-release/issues/4024#issuecomment-749440857 proposes disabled-by-default key loading or notifying users when the agent has no keys. It rejects unconditional loading because that could undo deliberate ssh-add -D, and explains that mounting the host socket does not support remote Docker daemons. This accepted Backlog request should not receive a decline close.
- **Existing capability check:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents automatic forwarding of a running local SSH agent, but explicitly instructs users to load keys using ssh-add. That covers forwarding and manual setup, not automatic loading or an empty-agent notification.
- **Lifecycle workaround is partial:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md#lifecycle-scripts documents initializeCommand executing on the host during creation and subsequent starts. The discussion in https://github.com/microsoft/vscode-remote-release/issues/4024 reports mixed results and objections to embedding personal key paths in shared devcontainer.json files; this hook does not supply the requested user-level experience.

Neither resolution implements loading keys into an initially empty host agent.
