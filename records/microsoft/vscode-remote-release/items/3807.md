# Issue #3807 — Make Podman work without setting the executable name/path

[https://github.com/microsoft/vscode-remote-release/issues/3807](https://github.com/microsoft/vscode-remote-release/issues/3807)

## Summary

The central request remains open: current documentation still requires users to set `dev.containers.dockerPath` to `podman`, while this issue requests automatic runtime detection. The existing setting is a workaround, not coverage of the zero-configuration behavior.

## Change summary

Automatically detect and use Podman when Docker is unavailable instead of requiring users to configure the container CLI path.

## Best solution

Dev Containers should detect an available container CLI, handle the Docker-and-Podman-both-installed case explicitly, and select or prompt for Podman without requiring a compatibility package or manual path setting.
