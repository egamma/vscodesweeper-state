# Issue #11662 — Host aliases show up as distinct severs

[https://github.com/microsoft/vscode-remote-release/issues/11662](https://github.com/microsoft/vscode-remote-release/issues/11662)

## Summary

Separate SSH alias entries are intentional: a maintainer answered the same multi-name Host example by explaining that each name can have separate rules applied. Consolidating legacy aliases would be a presentation enhancement, not a failure to parse the configuration.

## Change summary

Show one server entry rather than separate SSH targets for aliases declared together as `Host server server-old`.

## Best solution

Preserve independently selectable SSH aliases and explain that entries represent connection names, not necessarily distinct machines. Automatic consolidation should not discard alias-specific connection behavior.

- **Proposed comment:**

  > Thanks for the report. `Host server server-old` is valid SSH configuration. Remote - SSH lists each name as a selectable target because other SSH rules can apply differently depending on which name you connect with, even when both reach the same machine. The same behavior was explained in https://github.com/microsoft/vscode-remote-release/issues/4050#issuecomment-731854900. Keeping both names available is therefore intentional, rather than treating them as distinct physical servers.

## Evidence

- **Exact design precedent:** https://github.com/microsoft/vscode-remote-release/issues/4050 reports `Host pi raspi` appearing as separate targets despite a shared HostName. The maintainer explicitly explains: 'They are separate names, they can have separate rules applied, and so you have to pick which one you want to connect to.' See https://github.com/microsoft/vscode-remote-release/issues/4050#issuecomment-731854900.
- **Later enhancement discussion:** https://github.com/microsoft/vscode-remote-release/issues/10152 requests the same single-entry presentation. The discussion classifies selecting only one alias as a feature request rather than an established bug: https://github.com/microsoft/vscode-remote-release/issues/10152#issuecomment-2533250883. It is closed after the community candidate window, not a verified fix or an open duplicate target.
- **SSH configuration semantics:** https://man7.org/linux/man-pages/man5/ssh_config.5.html documents whitespace-separated Host patterns and matching against the name supplied to ssh; additional Host or Match rules can distinguish those names. Sharing one Host declaration does not guarantee identical effective configurations.
- **Existing capability boundary:** https://code.visualstudio.com/docs/remote/ssh#_remember-hosts-and-advanced-settings documents SSH-config-driven targets and `remote.SSH.configFile` for selecting another configuration file. Selecting a different file is only a workaround, not automatic alias consolidation; the close rests on the exact maintainer design precedent, not a claimed grouping setting.
