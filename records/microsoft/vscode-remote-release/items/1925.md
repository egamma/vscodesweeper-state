# Issue #1925 — Remote Containers and VSCodium

[https://github.com/microsoft/vscode-remote-release/issues/1925](https://github.com/microsoft/vscode-remote-release/issues/1925)

## Summary

Propose closing as-designed: restricting the remote extensions and VS Code Server to official VS Code clients is an explicitly documented product decision, reaffirmed in 2025. This requests changing that boundary, not fixing a compatibility regression.

## Change summary

Allow VSCodium to use the Dev Containers extension fully by removing the official-client restriction.

## Best solution

Retain the documented official-client boundary for Dev Containers and the VS Code Server. Supporting VSCodium would require an explicit licensing and product-support decision, not a configuration workaround.

## Evidence

- **Explicit official-client boundary:** https://github.com/microsoft/vscode-remote-release/issues/967#issuecomment-510990794 explicitly states that the VS Code Server only supports official VS Code clients in response to a VSCodium report. This is the maintainer decision quoted in the issue under review.
- **Current documented behavior:** https://code.visualstudio.com/docs/remote/faq#_can-vs-code-server-be-installed-or-used-on-its-own states that the server is managed by a VS Code client and is not intended or licensed for other clients. Settings and manual VSIX installation do not change that documented boundary.
- **Recent reaffirmation:** https://github.com/microsoft/vscode-remote-release/issues/11186#issuecomment-3258933668 reaffirmed on September 5, 2025 that users need VS Code or VS Code Insiders to use the remote extensions, citing product-specific configuration and licensing.
- **Related requests are not canonicals:** https://github.com/microsoft/vscode-remote-release/issues/2099 is open but requests clearer incompatibility documentation, not VSCodium support. https://github.com/microsoft/vscode-remote-release/issues/6193 is open but concerns publishing Remote - WSL to Open VSX; resolving that narrower distribution request would not deliver Dev Containers support in VSCodium.
- **Workaround does not satisfy the request:** The supplied discussion at https://github.com/microsoft/vscode-remote-release/issues/1925 suggests running sshd in containers and using an open-source SSH extension. That manual alternative does not provide the requested full Dev Containers integration.
