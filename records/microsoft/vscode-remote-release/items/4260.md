# Issue #4260 — [remote] suppport --open-url in remote cli

[https://github.com/microsoft/vscode-remote-release/issues/4260](https://github.com/microsoft/vscode-remote-release/issues/4260)

## Summary

The accepted Backlog request remains valid: the remote CLI can forward URLs through its internal `--openExternal` option, but still lacks parity with the local CLI's `--open-url` flag.

## Change summary

Support the local CLI's `--open-url` option in the remote `code` stub so remote processes can activate URL handlers consistently.

## Best solution

The VS Code Server CLI should accept `--open-url` and route it through the existing remote URL-forwarding path, preserving parity with the local CLI while retaining `--openExternal` compatibility.

- **Fit:** aligned
- **Reason:** Matching local CLI URL activation from remote environments directly advances the stated goal that remote development should offer VS Code's full feature set.
- **Evidence:** The public product promise is: "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
