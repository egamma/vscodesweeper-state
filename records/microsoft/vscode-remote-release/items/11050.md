# Issue #11050 — podman buildx vs docker buildx in devcontainers, behavior inconsistent, adding features is impossible due to not found proxy

[https://github.com/microsoft/vscode-remote-release/issues/11050](https://github.com/microsoft/vscode-remote-release/issues/11050)

## Summary

Verified duplicate: the open canonical issue tracks the same bootstrap-container Buildx proxy failure when using Podman, including the identical Dockerfile frontend timeout and the need to pass proxy settings to the builder.

## Change summary

Dev Containers' Clone Repository in Volume flow invokes Docker Buildx inside its bootstrap container without the required proxy configuration instead of using the configured Podman build path, preventing features from being added.

## Best solution

Consolidate on https://github.com/microsoft/vscode-remote-release/issues/11032 and update the Dev Containers bootstrap flow to configure BuildKit with the host proxy environment or use a compatible Podman-native builder. Preserve this report's comparison with the standalone Dev Container CLI and its request for bootstrap customization as implementation evidence.
