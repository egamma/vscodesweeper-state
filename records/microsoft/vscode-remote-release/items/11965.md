# Issue #11965 — Reloading the window that created a shared port forward causes HTTP timeouts in both windows; single-window remove/re-add fails, but releasing all forwards and recreating one restores access

## Summary

Keep open: the supplied two-window reproduction and logs are sufficient to retest the stale shared forward. Related reconnect reports do not establish ownership of this failure, and neither a current fix nor independent confirmation is documented.

## Change summary

Reloading the window that created a shared SSH port forward breaks HTTP access in both windows until every forward handle is released and a fresh forward is created.

## Best solution

The SSH and shared-tunnel owners should reproduce the supplied sequence and ensure retained forwards use a live connection endpoint after their originating window reloads. If investigation confirms the defect is in VS Code core's shared-process tunnel lifecycle, a maintainer can transfer this to microsoft/vscode with the diagnostic attachment and logs.
