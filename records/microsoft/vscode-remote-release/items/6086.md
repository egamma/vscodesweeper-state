# Issue #6086 — Investigate using local server on remoteListenOnSocket

[https://github.com/microsoft/vscode-remote-release/issues/6086](https://github.com/microsoft/vscode-remote-release/issues/6086)

## Summary

Keep open as a focused Remote - SSH architectural investigation: multiple users confirmed that socket listening disables the local-server path required for RemoteCommand, and maintainers deliberately separated this constraint from the broader Slurm workflow request.

## Change summary

Allow RemoteCommand through the local-server connection path when remote.SSH.remoteServerListenOnSocket is enabled.

## Best solution

The Remote - SSH owner should determine whether local-server handling can support a server listening on a Unix socket without breaking RemoteCommand, or document the SSH constraint if it cannot. Keep general Slurm workflow design in https://github.com/microsoft/vscode-remote-release/issues/1722.
