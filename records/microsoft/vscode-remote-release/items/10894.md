# Issue #10894 — `EADDRINUSE` raised on local part when connecting to a remote server although the local port is not already used

[https://github.com/microsoft/vscode-remote-release/issues/10894](https://github.com/microsoft/vscode-remote-release/issues/10894)

## Summary

Keep open: the complete log and configuration suffice to retest this local connection failure. The reported versions are older, but neither subsequent releases nor the suggested workaround establish resolution.

## Change summary

Remote - SSH fails to initialize its exec server with local connect EADDRINUSE after successfully starting the forwarding listener.

## Best solution

The SSH component should investigate why connecting to its own forwarding listener fails on Windows, distinguishing client-side socket allocation from listener contention. Compare useExecServer modes and TCPView observations as suggested in the thread before deciding whether the cause is extension behavior or the local environment.
