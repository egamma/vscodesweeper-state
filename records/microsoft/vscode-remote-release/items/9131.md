# Issue #9131 — Open tunnel directly to a devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/9131](https://github.com/microsoft/vscode-remote-release/issues/9131)

## Summary

A real integration gap remains: the CLI can create a tunnel from inside a container, but VS Code's tunnel command still targets the host. The related web-enabled Dev Containers request is broader and does not replace this distinct workflow.

## Change summary

Allow VS Code Desktop to start and manage a Remote Tunnel directly inside the currently open dev container.

## Best solution

The Containers and Tunnels components should provide a command that installs or invokes the VS Code CLI inside the active dev container and manages its tunnel lifecycle. This can remain independently actionable while the broader vscode.dev Dev Containers work is tracked in https://github.com/microsoft/vscode-remote-release/issues/9059.

## Vision fit

- **Fit:** aligned
- **Reason:** Directly exposing a container through a tunnel advances remote-development parity and makes dev containers and tunnels work together as first-class access paths.
- **Evidence:** The vision identifies Dev Container capability depth and tunnels as mainstream access paths, while the product promise is to open a folder in a container or remote machine with VS Code's full feature set.

## Evidence

- **current documented capability:** https://code.visualstudio.com/docs/remote/tunnels documents that `code tunnel` can run on the target machine, including through a standalone CLI installation, but the VS Code UI enables access to the current host machine rather than the active dev container.
- **partial existing workflow:** The same documentation describes opening a container after connecting to a Remote Tunnels host, requiring the Dev Containers extension locally; it does not provide the requested direct in-container tunnel command for vscode.dev.
- **related request:** https://github.com/microsoft/vscode-remote-release/issues/9059 remains open and tracks making Dev Containers available in vscode.dev. - **workaround limitation:** The reporter confirms that manually installing the Code CLI and starting a tunnel inside the container works, but does not provide the requested VS Code-managed experience.
