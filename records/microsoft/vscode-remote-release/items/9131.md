# Issue #9131 — Open tunnel directly to a devcontainer

[https://github.com/microsoft/vscode-remote-release/issues/9131](https://github.com/microsoft/vscode-remote-release/issues/9131)

## Summary

Keep open: the request is desktop UI integration for creating a tunnel directly into the active dev container. Documented CLI and host-tunnel workflows do not cover that integration, and the related browser-support request is not the same observable behavior.

## Change summary

Allow the desktop tunnel command to target the active dev container rather than always the host, without manually installing and running the Code CLI inside the container.

## Best solution

The tunnels and containers owners should provide an explicit host-versus-container target when enabling tunnel access from a dev-container window, handling the container-side CLI setup. Track this separately from enabling the Dev Containers extension in vscode.dev.
