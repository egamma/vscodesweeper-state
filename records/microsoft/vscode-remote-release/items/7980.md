# Issue #7980 — Podman Hangs

[https://github.com/microsoft/vscode-remote-release/issues/7980](https://github.com/microsoft/vscode-remote-release/issues/7980)

## Summary

Multiple users confirmed that rootless Podman can leave Dev Containers waiting indefinitely when the journald event backend emits no container-start event. The documented configuration workaround identifies an upstream Podman event-delivery cause, so this should remain open for integration hardening.

## Change summary

Dev Containers hangs at “Starting container” when rootless Podman does not emit the expected start event through its journald event backend.

## Best solution

Podman should reliably publish rootless container events, while Dev Containers should avoid waiting indefinitely when an expected Podman event is absent and instead provide a timeout with actionable diagnostics.

## Evidence

- **identified dependency behavior:** A commenter reports that rootless Podman emits no events with events_logger=journald, leaving Dev Containers waiting for `podman events --filter event=start`.
- **confirmed workaround:** Another affected user confirms that setting Podman's `events_logger="file"` resolves the hang with Podman 4.9.3 and Dev Containers 0.417.0; the same extension works with Podman 4.3.1 using journald.
