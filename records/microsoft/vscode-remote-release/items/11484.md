# Issue #11484 — Setting the authentication provider when the tunnel is started

[https://github.com/microsoft/vscode-remote-release/issues/11484](https://github.com/microsoft/vscode-remote-release/issues/11484)

## Summary

The CLI already supports non-prompted provider selection through a separate login command, and maintainer guidance confirms that login and tunnel startup are intentionally separate operations.

## Change summary

Allow `--provider` directly on `code tunnel` so scripts can bypass the authentication-provider selection prompt.

## Best solution

Keep the existing login/start separation: scripts should run `code tunnel user login --provider github` or `--provider microsoft`, then start the tunnel with `code tunnel --name <name>` using the stored credential.

- **Fit:** aligned

- **Proposed comment:**

  > Thanks for the request. Provider selection is already scriptable through the dedicated login command:
  > 
  > ```
  > code tunnel user login --provider github
  > code tunnel --name "$(hostname)"
  > ```
  > 
  > Use `--provider microsoft` for a Microsoft account. The login command stores the selected credential, and tunnel startup is intentionally a separate operation, as documented by the maintainer guidance at https://github.com/microsoft/vscode/issues/207931#issuecomment-2018342545. This avoids the provider-choice prompt, so closing as designed.
