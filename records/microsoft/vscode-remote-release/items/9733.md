# Issue #9733 — automatically open code-workspace on dev container

[https://github.com/microsoft/vscode-remote-release/issues/9733](https://github.com/microsoft/vscode-remote-release/issues/9733)

## Summary

Keep open: the automatic workspace-file request overlaps an older accepted feature request, but this report also requests container discovery directly beneath SSH hosts. No verified canonical covers both capabilities.

## Change summary

Automatically open a configured .code-workspace when attaching to a remote container, and expose its containers directly in the Remote-SSH view.

## Best solution

Dev Containers should support a configured workspace-file target for attachment, coordinating that capability with https://github.com/microsoft/vscode-remote-release/issues/3665. Separately scope the SSH-host container-discovery integration before consolidating this broader report.

## Evidence

- **Two requested capabilities:** https://github.com/microsoft/vscode-remote-release/issues/9733 requests opening a workspace file automatically after SSH-to-container attachment and, separately, listing attachable containers directly in the Remote-SSH view.
- **Verified partial canonical:** https://github.com/microsoft/vscode-remote-release/issues/3665 is currently open and tracks configuring a default .code-workspace. Its https://github.com/microsoft/vscode-remote-release/issues/3665#issuecomment-1152765470 describes the same local-to-SSH-to-Docker-to-workspace sequence, but it does not own SSH-host container discovery.
- **Accepted extension-side work:** https://github.com/microsoft/vscode-remote-release/issues/3665#issuecomment-1309871437 proposes reading a workspace-file path from customizations.vscode when reopening the window. https://github.com/microsoft/vscode-remote-release/issues/3665#issuecomment-1415374873 confirms workspace-file support remains a valid request, rather than an existing settings capability.
- **Existing attachment configuration is partial:** https://code.visualstudio.com/docs/devcontainers/attach-container documents image/name-level attachment configuration and workspaceFolder, but no dedicated workspace-file property. https://github.com/microsoft/vscode-remote-release/issues/4239#issuecomment-754071847 explains that using a workspace file as workspaceFolder worked by chance, not as supported functionality.
- **Remote discovery alternatives do not establish full coverage:** https://code.visualstudio.com/remote/advancedcontainers/develop-remote-host documents direct remote attachment using DOCKER_HOST or Docker contexts, while https://code.visualstudio.com/docs/devcontainers/attach-container documents the Containers view. Neither establishes containers listed directly beneath Remote-SSH hosts. The open https://github.com/microsoft/vscode-remote-release/issues/2321 concerns multi-host container exploration, not automatic workspace-file opening.
