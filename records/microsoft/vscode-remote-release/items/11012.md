# Issue #11012 — Support for the Containerization Framework on macOS

[https://github.com/microsoft/vscode-remote-release/issues/11012](https://github.com/microsoft/vscode-remote-release/issues/11012)

## Summary

Keep open: experimental Apple-container attachment covers part of the request, but the thread identifies remaining devcontainer.json-driven creation and lifecycle integration. This issue is already the maintainer-designated tracking home.

## Change summary

Support Apple's Containerization Framework as a backend for Dev Containers on macOS.

## Best solution

The containers component should support opening and creating Apple-backed development containers from devcontainer.json, including workspace configuration and lifecycle commands. Coordinate runtime support with https://github.com/devcontainers/cli/issues/1263 while retaining the extension-side work here.

## Evidence

- **Existing capability:** https://github.com/microsoft/vscode-remote-release/issues/11012#issuecomment-3068902386 announces Dev Containers 0.424.0-pre-release's experimental 'Dev Containers: Attach to Running Apple Container' command. The setting is identified as dev.containers.experimentalAppleContainerSupport at https://github.com/microsoft/vscode-remote-release/issues/11012#issuecomment-3156720893. This establishes attachment support, not complete backend integration.
- **Partial confirmation and remaining gap:** The reporter confirms successful attachment and extensions at https://github.com/microsoft/vscode-remote-release/issues/11012#issuecomment-3073262628. A later detailed report at https://github.com/microsoft/vscode-remote-release/issues/11012#issuecomment-3647821366 describes manually creating containers, opening the workspace, and running setup scripts because the project's devcontainer.json is not read. The confirmation therefore does not establish resolution of the full request.
- **Documented alternatives do not establish coverage:** https://code.visualstudio.com/remote/advancedcontainers/docker-options documents Docker-compliant CLIs and dev.containers.dockerPath for Podman, and explicitly directs other-engine support requests to this tracker. https://code.visualstudio.com/docs/devcontainers/attach-container distinguishes attachment with a subset of configuration properties from creating containers through devcontainer.json; neither page documents complete Apple-backend support.
- **Canonical ownership:** At https://github.com/microsoft/vscode/issues/251330#issuecomment-2969382552, a maintainer explicitly identifies https://github.com/microsoft/vscode-remote-release/issues/11012 as the tracking issue. Searches for Apple-container and Containerization Framework requests did not identify another open same-repo canonical owning this work.
- **Related CLI work is not a duplicate:** https://github.com/devcontainers/cli/issues/1263 is open and requests reference-CLI support, explicitly referencing this issue. Resolving that CLI request alone does not establish that the closed-source Dev Containers extension ships the requested workflow.
- **Community workaround:** https://github.com/microsoft/vscode-remote-release/issues/11012#issuecomment-5231834070 offers a third-party Swift CLI with devcontainer.json handling and VS Code attachment. It is a workaround, not evidence that the requested first-party integration has shipped.
