# Issue #10799 — Unsaved files on a disconnected connection cannot be saved and prevent successful reconnection

[https://github.com/microsoft/vscode-remote-release/issues/10799](https://github.com/microsoft/vscode-remote-release/issues/10799)

## Summary

The failure was independently confirmed across WSL and Remote - SSH: dirty files block reconnection and cannot reliably be saved elsewhere. No open canonical owns the full cross-transport bug, so it should remain open and be routed beyond its current WSL-only classification.

## Change summary

Preserve and allow saving unsaved remote files while reconnecting after a WSL or SSH connection is lost.

## Best solution

Shared remote connection handling should permit a fresh connection without closing the window or discarding dirty editors, while Save As or local backup recovery preserves every unsaved working copy. The remote platform, WSL, and SSH owners should coordinate because the same failure occurs through both transports.
