# Issue #11831 — [Remote-SSH Bug]: after a local-server "Timed out", the reconnect builds the forwarding server against a SOCKS port the new `ssh -D` never bound (ECONNREFUSED)

[https://github.com/microsoft/vscode-remote-release/issues/11831](https://github.com/microsoft/vscode-remote-release/issues/11831)

## Summary

Keep open for Remote - SSH investigation: two logged occurrences show forwarding targeting a different SOCKS port from the spawned SSH process. The August versions lack later confirmation, but the supplied overlap scenario and logs suffice to retest.

## Change summary

Overlapping reconnect resolves can build the forwarding tunnel against a SOCKS port different from the one used by the new SSH process.

## Best solution

Remote - SSH should preserve the actual local server's SOCKS port throughout each resolve and tunnel creation, including concurrent reconnects. Investigate the reported port-state race separately from the watchdog shutdown that triggers it.
