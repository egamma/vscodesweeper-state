# Issue #7175 — Reconnection attempts after "internal libpod error" when starting a project with Podman

[https://github.com/microsoft/vscode-remote-release/issues/7175](https://github.com/microsoft/vscode-remote-release/issues/7175)

## Summary

Keep open as an upstream Podman logging compatibility issue: affected users confirmed that upgrading Podman stops the reconnects, and disabling logging helps on 3.4.4. Those results do not establish an extension fix or settle the requested handling of older distro packages.

## Change summary

Opening a Podman-backed project intermittently loses its forwarding connection with an internal libpod exit-file timeout and repeatedly reconnects.

## Best solution

Podman's logging fix owns the underlying failure; the Dev Containers owner should decide whether to document the older-version limitation and optional logging workaround or improve diagnostics. Do not disable container logging by default, since that removes podman logs functionality.

## Evidence

- **Observed failure:** https://github.com/microsoft/vscode-remote-release/issues/7175 includes Ubuntu 22.04, Podman 3.4.4, Remote-Containers 0.251.0, and logs showing an established forwarding connection terminate with code 255 after an internal libpod exit-file timeout.
- **Upgrade confirmations and remaining concern:** The reporter observed no reconnects after upgrading to Podman 4.2.1 but explicitly requested a workaround or clearer support limitations for distro-packaged versions: https://github.com/microsoft/vscode-remote-release/issues/7175#issuecomment-1245517956. Another affected user confirmed resolution on Podman 4.3: https://github.com/microsoft/vscode-remote-release/issues/7175#issuecomment-1300984271.
- **Upstream diagnosis:** https://github.com/podman-container-tools/podman/issues/13779 reproduces stdout-related hangs independently of VS Code and includes the same internal libpod exit-file error. An upstream comment identifies a fix intended for Podman 4.2: https://github.com/podman-container-tools/podman/issues/13779#issuecomment-1199504692. The upstream issue is currently open; it is related evidence, not a verified canonical for this report's full scope.
- **Workaround with tradeoff:** https://github.com/microsoft/vscode-remote-release/issues/7175#issuecomment-1645498699 reports that adding "runArgs": ["--log-driver=none"] works around the problem on Podman 3.4.4, but prevents using podman logs. This is partial mitigation, not evidence that the extension resolved the original behavior.
- **Current documented boundary:** https://code.visualstudio.com/remote/advancedcontainers/docker-options documents Podman 5+ compatibility, dev.containers.dockerPath, and that alternative Docker-compliant CLIs are not officially supported. This clarifies today's boundary but does not prove resolution for users remaining on 3.4.4.
