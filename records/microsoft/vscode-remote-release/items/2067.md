# Issue #2067 — OS specific dev containers

[https://github.com/microsoft/vscode-remote-release/issues/2067](https://github.com/microsoft/vscode-remote-release/issues/2067)

## Summary

This team-authored feature remains necessary: the current Dev Container specification has no host-OS requirement or general conditional-property mechanism. Existing environment substitution provides partial workarounds but does not cover declarations, warnings, or filtering.

## Change summary

Allow dev containers to declare supported host operating systems and apply host-specific configuration.

## Best solution

Define host-platform constraints or conditional properties in the open Dev Container specification, then have the Dev Containers extension warn, filter, or select configuration based on the effective container host. Keep this issue as the extension-facing tracker and link the corresponding devcontainers/spec proposal.

## Evidence

- **current specification gap:** The current schema at https://github.com/devcontainers/spec/blob/main/schemas/devContainer.base.schema.json limits `hostRequirements` to CPU, memory, storage, and GPU; it has no host-OS property or conditional configuration construct.
- **partial workaround:** https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson documents `${localEnv:VARIABLE_NAME}` substitution, and https://github.com/microsoft/vscode-remote-release/issues/2067#issuecomment-1666377357 demonstrates an OS-environment-variable workaround. This depends on platform-specific variables and cannot declare compatibility or warn before opening.
- **related scopes are narrower:** Open issues https://github.com/devcontainers/spec/issues/347 and https://github.com/microsoft/vscode-remote-release/issues/10945 cover system-specific `initializeCommand` and cross-platform mount paths respectively; neither owns the broader host-OS declaration and conditional-property request.
- **maintainer-defined scope:** Maintainer comments in https://github.com/microsoft/vscode-remote-release/issues/2067 distinguish this request from multiple container configurations and identify host-specific `devcontainer.json` properties and compatibility affordances as the intended work.
