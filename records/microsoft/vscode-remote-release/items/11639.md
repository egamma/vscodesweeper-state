# Issue #11639 — Lifecycle marker files in home directory break persistent home volume across rebuilds

[https://github.com/microsoft/vscode-remote-release/issues/11639](https://github.com/microsoft/vscode-remote-release/issues/11639)

## Summary

A real capability gap remains: named-volume mounts can persist the home directory, but marker state stored there prevents lifecycle and dotfiles setup from running after rebuilds. The existing containers and feature-request classification is appropriate.

## Change summary

Keep user home data across Dev Container rebuilds without persisting lifecycle markers that suppress container initialization.

## Best solution

The devcontainers CLI should store or namespace lifecycle and dotfiles markers by container environment outside the persistent home volume; a maintainer can track that portion in https://github.com/devcontainers/cli. The Dev Containers extension can separately consider an opt-in setting that provisions a per-container home volume.

- **maintainer precedent:** In https://github.com/microsoft/vscode-remote-release/issues/1153, maintainers identified persisted marker files as the reason `postCreateCommand` was skipped and stated that markers should not live in the mounted volume for this scenario.
- **related work does not cover scope:** https://github.com/microsoft/vscode-remote-release/issues/421 addressed persistence of VS Code Server and extensions, but not whole-home persistence or the current `~/.devcontainer` lifecycle markers.
