# Issue #11388 — Cannot connect to windows host with git bash as default shell

[https://github.com/microsoft/vscode-remote-release/issues/11388](https://github.com/microsoft/vscode-remote-release/issues/11388)

## Summary

Keep open: a November 2026 team-member reproduction on Remote - SSH 0.128.0 confirms the same platform-probe timeout. Terminal Mode is a confirmed workaround, not a fix for Local Server Mode, and the verified related issues do not own this exact remaining behavior.

## Change summary

Remote - SSH times out after receiving MINGW64_NT from a Windows host configured with Git Bash as its default SSH shell.

## Best solution

The SSH component should honor an explicitly configured Windows remote platform without stalling on the probe, or recognize MINGW platform output correctly. Preserve this report's macOS/Linux-client reproduction and retain Terminal Mode as an interim workaround.

## Evidence

- **Concrete original reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11388 supplies the OpenSSH DefaultShell configuration, explicit remote.SSH.remotePlatform mapping, and logs from macOS with Remote - SSH 0.122.0. Authentication succeeds, but uname -rsv returns MINGW64_NT and the connection subsequently times out.
- **Recent independent confirmation:** https://github.com/microsoft/vscode-remote-release/issues/11388#issuecomment-6677492777 confirms the identical probe timeout on November 6, 2026 with Remote - SSH 0.128.0 from Linux. The team-member commenter reports that explicit Windows platform selection does not bypass the probe and that remote.SSH.useLocalServer=false resolves their connection; the proposed probe diagnosis is thread evidence, not independently inspected product source.
- **Workaround does not resolve the defect:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting documents Local Server Mode as the default outside Windows and Terminal Mode as a separate connection mode with one connection per window. Switching modes avoids the reported failure but leaves default-mode Windows platform detection broken.
- **Older related issue is not a full canonical:** https://github.com/microsoft/vscode-remote-release/issues/11117 is open and older, but specifically reports the case-mismatched Windows_NT comparison. The recent confirmation on this issue explicitly explains that correcting that comparison would not recognize MINGW64_NT, so it does not establish ownership of this report's full fix.
