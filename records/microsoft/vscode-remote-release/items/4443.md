# Issue #4443 — Podman: .vscode-server directory creation in wrong place when remoteUser is defined

[https://github.com/microsoft/vscode-remote-release/issues/4443](https://github.com/microsoft/vscode-remote-release/issues/4443)

## Summary

Resolved by the Dev Containers CLI's automatic rootless-Podman arguments, which address the user-namespace behavior behind the incorrect `/root/.vscode-server` path.

## Change summary

Dev Containers attempted to install the VS Code Server under `/root` when a non-root `remoteUser` was used with rootless Podman.

## Best solution

Keep the shipped Podman detection that automatically supplies `--userns=keep-id`; no project-specific `runArgs` workaround is required for the original Linux scenario.
