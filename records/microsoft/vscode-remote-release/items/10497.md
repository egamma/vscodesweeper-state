# Issue #10497 — [Remote-SSH Bug]: Race condition when parsing ssh.exe -V output on Windows

[https://github.com/microsoft/vscode-remote-release/issues/10497](https://github.com/microsoft/vscode-remote-release/issues/10497)

## Summary

Keep open: an independent November 2026 confirmation on Remote - SSH 0.128.0 reproduces the indefinite hang after ssh -V. The thread identifies an unresolved completion path; the related discovery-timeout reports do not own this symptom.

## Change summary

Remote - SSH can hang indefinitely when the SSH version-check process exits before its buffered output is consumed.

## Best solution

The SSH component should consume completed stdout/stderr before classifying the executable and guarantee that every outcome, including empty output, settles the check within a bounded timeout. Preserve executable discovery and script-wrapper behavior without requiring timing workarounds.

## Evidence

- **Current independent reproduction:** In https://github.com/microsoft/vscode-remote-release/issues/10497, the November 26, 2026 comment reports Remote - SSH 0.128.0 on Windows 11 with OpenSSH_for_Windows_9.5p2: roughly one in three windows hangs after the version line, never reaches 'Running script with connection command', and continues resolveAuthority 'waiting...' without timeout. Delaying wrapper exit makes all windows connect.
- **Thread diagnosis:** The December 10, 2024 contributor response in https://github.com/microsoft/vscode-remote-release/issues/10497 identifies that the shared exit callback never resolves when both output buffers are empty. The supplied callback also clears its timeout before inspecting output, explaining why that branch can wait indefinitely. This is thread evidence, not inspection of current product source.
- **Event-ordering contract:** https://nodejs.org/api/child_process.html#event-exit states that stdio streams may still be open at exit; https://nodejs.org/api/child_process.html#event-close documents that close occurs after process termination and stdio closure. These contracts support the reported race and the proposed completion strategy, without proving the current extension implementation.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/11470 and https://github.com/microsoft/vscode-remote-release/issues/11332 are open but newer, unscheduled reports with no body upvotes. Their logs show 'ssh is not exiting, continuing' followed by executable fallback or installation-not-found errors, rather than this issue's indefinite unresolved check. They fail the re-review canonical bar. The contributor-linked https://github.com/microsoft/vscode-remote-release/issues/3731 is closed and likewise concerns slow executable checks.
- **Workaround is not resolution:** In https://github.com/microsoft/vscode-remote-release/issues/10497, the reporter's October 2025 comments describe recurrence and a delayed-parsing workaround; the November 2026 confirmation still requires delaying ssh -V wrapper exit. Neither establishes a shipped fix, and the latest confirmation supplies a concrete multi-window trigger.
