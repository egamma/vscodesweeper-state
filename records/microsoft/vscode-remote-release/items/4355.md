# Issue #4355 — Cannot start devcontainer with vscode extensions volumes

[https://github.com/microsoft/vscode-remote-release/issues/4355](https://github.com/microsoft/vscode-remote-release/issues/4355)

## Summary

Keep open as a prebuilt-image enhancement, not an unresolved connection bug. The reporter explicitly confirmed that they want the server directories included in published images; manual Dockerfile preparation does not deliver that request.

## Change summary

Pre-create appropriately owned VS Code Server and extension directories in published dev container images so extension-volume mounts work without a custom Dockerfile.

## Best solution

The containers maintainers should coordinate with https://github.com/devcontainers/images on whether published images should include these directories with the correct ownership. Resolve the image-side request rather than treating the documented Dockerfile workaround as its implementation.
