# Issue #4355 — Cannot start devcontainer with vscode extensions volumes

[https://github.com/microsoft/vscode-remote-release/issues/4355](https://github.com/microsoft/vscode-remote-release/issues/4355)

## Summary

The clarified request is for published Dev Container images to support extension-volume mounts without manual directory and ownership setup. The open, actively discussed issue https://github.com/microsoft/vscode-remote-release/issues/7690 now tracks that broader requirement and the same permission failure.

## Change summary

Pre-create writable VS Code Server directories in published Dev Container images so non-root users can mount an extensions volume without startup permission errors.

## Best solution

Consolidate on https://github.com/microsoft/vscode-remote-release/issues/7690 and provide an out-of-box Dev Containers solution that initializes extension-cache volumes with permissions suitable for the configured remote user.
