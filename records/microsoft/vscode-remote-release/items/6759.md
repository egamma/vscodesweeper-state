# Issue #6759 — Podman Usage Improvements

[https://github.com/microsoft/vscode-remote-release/issues/6759](https://github.com/microsoft/vscode-remote-release/issues/6759)

## Summary

The Podman permission and SELinux requests are implemented, but the separate request for built-in home-directory mounting remains unresolved. The existing explicit mount configuration does not cover that central ergonomic request.

## Change summary

Improve Podman defaults and provide built-in support for exposing host home-directory configuration inside dev containers.

## Best solution

Narrow this issue to the remaining Dev Containers home-mounting experience. The containers owner should decide whether to provide a secure opt-in mechanism for selected home configuration rather than mounting the entire home directory by default.

  > Thanks for the detailed request and follow-up. The Podman-specific permission and SELinux portions are now covered by https://github.com/devcontainers/cli/pull/985 and https://github.com/devcontainers/cli/pull/1045. The remaining request is the home-directory experience: an explicit host-home bind mount is documented at https://code.visualstudio.com/remote/advancedcontainers/add-local-file-mount, but there is still no built-in opt-in that avoids repeating this configuration. This should remain open for the containers owner to decide that behavior, including the credential-exposure concern raised above.
