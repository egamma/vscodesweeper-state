# Issue #1785 — Attach to container config

[https://github.com/microsoft/vscode-remote-release/issues/1785](https://github.com/microsoft/vscode-remote-release/issues/1785)

## Summary

A real capability gap remains: attached-container settings can be tied locally to an image or container name, but cannot be loaded automatically from a project-tracked configuration. This older, well-supported issue remains the strongest canonical report.

## Change summary

Allow a repository configuration to identify an externally started container and apply shared workspace, extension, and settings configuration when attaching.

## Best solution

Dev Containers should support a project-tracked attachment configuration that selects an existing named container and applies the supported attached-container properties. Keep this issue as the canonical request and consolidate the narrower https://github.com/microsoft/vscode-remote-release/issues/4584 into it.

## Vision fit

- **Fit:** aligned
- **Reason:** Shareable configuration for externally managed containers advances the goal that opening a folder in a container should provide VS Code's full development experience.
- **Evidence:** The public product promise is: "Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set."
