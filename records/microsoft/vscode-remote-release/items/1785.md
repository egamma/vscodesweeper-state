# Issue #1785 — Attach to container config

[https://github.com/microsoft/vscode-remote-release/issues/1785](https://github.com/microsoft/vscode-remote-release/issues/1785)

## Summary

Keep open: named attached-container configurations cover part of the request, but do not deliver project-tracked configuration that selects an externally managed running container. The verified related requests do not own this full scope.

## Change summary

Allow a project's devcontainer.json to select an existing container by name and apply its workspace, extensions, and settings without managing container creation.

## Best solution

Dev Containers should support a project-scoped attach-only configuration for externally managed containers. Coordinate repository-local configuration support with https://github.com/microsoft/vscode-remote-release/issues/4584 while preserving this issue's explicit container-selection requirement.

## Evidence

- **Existing capability is partial:** https://code.visualstudio.com/docs/devcontainers/attach-container#_attached-container-configuration-files documents Dev Containers: Open Named Configuration File and support for workspaceFolder, extensions, and settings. It describes local image/name-level configuration, not a repository-local devcontainer.json that selects an existing container.
- **Historical implementation did not complete this request:** https://github.com/microsoft/vscode-remote-release/issues/3198#issuecomment-651077501 announces the named-container configuration command but explicitly says the devcontainer.json change was not explored.
- **Related request is not a full-scope canonical:** https://github.com/microsoft/vscode-remote-release/issues/4584 was verified open in Backlog. It requests repository-local attached configuration loading, but does not own the full declarative attach-by-container-name behavior requested here; it is related work rather than a canonical absorbing this broader report.
- **Other name-related request concerns a different behavior:** https://github.com/microsoft/vscode-remote-release/issues/4053 was verified open and requests a custom display name for an attached container, not selecting an externally started container through project configuration.
- **Spec properties do not establish attach-only coverage:** https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md documents runArgs for running containers and dockerComposeFile/service for Compose-managed environments. These do not establish a project-scoped attach-only selector for an arbitrary externally managed running container.
