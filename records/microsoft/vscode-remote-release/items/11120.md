# Issue #11120 — VSCode Remote-SSH fails from Windows/WSL2 to RunPod container - SSH works fine from WSL terminal

[https://github.com/microsoft/vscode-remote-release/issues/11120](https://github.com/microsoft/vscode-remote-release/issues/11120)

## Summary

This is a client-configuration support question rather than evidence of a Remote - SSH defect: the Windows host lacks the required supported SSH client and instead passes a WSL wrapper command through `remote.SSH.path`.

## Change summary

Connect from Windows through WSL's SSH client to a RunPod container exposed on a nonstandard port.

## Best solution

Use a supported OpenSSH-compatible client on Windows, verify the connection from PowerShell, and define the RunPod endpoint's hostname, user, port, and key under a named SSH config host before connecting through Remote - SSH.

  > Thanks for the detailed context. Remote - SSH requires a supported OpenSSH-compatible client on the local Windows machine; a working connection inside WSL does not validate the Windows client used by VS Code. Please install Windows OpenSSH, verify the connection from PowerShell, and create a named SSH config entry containing `HostName`, `User`, `Port 10265`, and `IdentityFile`, then connect to that host alias. The supported setup is documented at https://code.visualstudio.com/docs/remote/ssh#_system-requirements and https://code.visualstudio.com/docs/remote/ssh#_remember-hosts-and-advanced-settings. For further setup help, please use StackOverflow.
