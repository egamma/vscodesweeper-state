# Issue #2578 — open remote file using vscode: URI handler

[https://github.com/microsoft/vscode-remote-release/issues/2578](https://github.com/microsoft/vscode-remote-release/issues/2578)

## Summary

A real remote deep-linking gap remains: existing CLI support can open an explicitly addressed remote file, but browser and terminal links still cannot reliably target a file in the correct SSH or Dev Container window. Keep this broader request open and route it to both components.

## Change summary

Allow external VS Code and file hyperlinks to open a remote file and line in the appropriate existing remote window.

## Best solution

The remote/code-server integration should support and document a deep-link format carrying the remote authority, file path, and line, then route it to the matching SSH or Dev Container window. Terminal OSC8 links should resolve paths against the active remote authority rather than the local host.

## Vision fit

- **Fit:** aligned
- **Reason:** Remote file links behaving like local links directly advances the project's remote/local parity goal.
- **Evidence:** The public product promise is to “Open any folder in a container, on a remote machine, or in WSL and take advantage of VS Code's full feature set.”
