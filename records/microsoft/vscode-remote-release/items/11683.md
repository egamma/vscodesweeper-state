# Issue #11683 — Increase niceness (decrease priority) for vscode processes or limit the number of processes that vscode can spawn

[https://github.com/microsoft/vscode-remote-release/issues/11683](https://github.com/microsoft/vscode-remote-release/issues/11683)

## Summary

Keep the resource-control request open and route it to the VS Code Server owners. Documented manual cleanup does not cover configurable process priority, process limits, or automatic cleanup on disconnect; the reported slowdown's cause remains unconfirmed.

## Change summary

Provide configurable priority or process limits for remote VS Code processes and an option to clean them up automatically on disconnect.

## Best solution

The code-server owners should evaluate opt-in resource controls and disconnect cleanup, preserving active sessions and user workloads. Process-level CPU and thread measurements would help distinguish server overhead from extension activity before choosing a control.
