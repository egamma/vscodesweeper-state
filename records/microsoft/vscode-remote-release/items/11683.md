# Issue #11683 — Increase niceness (decrease priority) for vscode processes or limit the number of processes that vscode can spawn

[https://github.com/microsoft/vscode-remote-release/issues/11683](https://github.com/microsoft/vscode-remote-release/issues/11683)

## Summary

This is a valid request for resource controls and automatic server cleanup, but the reported slowdown is not yet tied to a particular VS Code process. Route it to the remote server and performance owners rather than treating the unconfirmed cause as a bug.

## Change summary

Provide controls for the priority or process count of remote VS Code services and optionally terminate them when the client disconnects.

## Best solution

The VS Code Server owner should first identify which server or remote-extension processes cause the contention, then provide a supported resource-priority mechanism and reliable configurable cleanup after disconnection without terminating active sessions.
