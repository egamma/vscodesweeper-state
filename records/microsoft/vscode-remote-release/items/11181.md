# Issue #11181 — Killing install terminal closes connection 

[https://github.com/microsoft/vscode-remote-release/issues/11181](https://github.com/microsoft/vscode-remote-release/issues/11181)

## Summary

Keep open as an SSH usability improvement: terminating the terminal is consistent with the documented terminal-backed connection mode, but safely dismissing its UI after two-factor authentication remains an unresolved ask.

## Change summary

Allow the SSH login/install terminal to be dismissed after authentication without terminating the remote connection.

## Best solution

Remote - SSH should offer a discoverable way to hide the authenticated connection terminal while preserving its SSH process, and distinguish that action from disconnecting. Evaluate this alongside the separate second-factor prompt issue without conflating their scopes.

- **Documented connection ownership:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-Troubleshooting explains that remote.SSH.useLocalServer=false runs the SSH connection command inside a hidden terminal and is the Windows default. This explains why killing that terminal can disconnect; it does not establish a safe post-authentication dismissal capability.

The wiki also documents remote.SSH.useLocalServer=true as an alternative process model, but neither source establishes that it preserves this reporter's second-factor interaction while allowing the login terminal to be dismissed after authentication.
