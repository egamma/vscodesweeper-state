# Issue #10104 — Pass env variables when attach remote containers

[https://github.com/microsoft/vscode-remote-release/issues/10104](https://github.com/microsoft/vscode-remote-release/issues/10104)

## Summary

The documented attached-container configuration already supports this request through `remoteEnv`, which sets environment variables for VS Code and its subprocesses when attaching.

## Change summary

Allow environment variables to be supplied to VS Code when attaching to an already-running container.

## Best solution

Keep the existing `remoteEnv` behavior and direct users to the image- or container-name configuration opened through Dev Containers: Open Container Configuration File; container-wide variables must still be supplied when the container is created.

- **Proposed comment:**

  > Thanks for the request. This is supported through an attached-container configuration: after attaching, run **Dev Containers: Open Container Configuration File** (or **Open Named Configuration File**) and add, for example, `"remoteEnv": { "TOTO": "tata" }`. This sets variables for VS Code and its subprocesses when attaching; it cannot change the environment of the already-running container itself. See https://code.visualstudio.com/docs/devcontainers/attach-container#_attached-container-configuration-files.
