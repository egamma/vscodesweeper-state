# Issue #11030 — Failure to start devcontainer in podman on a remote box

[https://github.com/microsoft/vscode-remote-release/issues/11030](https://github.com/microsoft/vscode-remote-release/issues/11030)

## Summary

This remains the canonical report for a runtime-independent Dev Containers failure when the command lacks the expected workspace-folder context. A team member reproduced it with Docker and confirmed that opening a workspace folder first is a workaround.

## Change summary

Starting a dev container over Remote-SSH throws while converting an undefined root folder to a URI.

## Best solution

The Dev Containers extension should handle commands invoked without a usable root folder by resolving the selected container configuration or presenting a clear workspace-folder requirement instead of throwing.
