[https://github.com/microsoft/vscode-remote-release/issues/11030](https://github.com/microsoft/vscode-remote-release/issues/11030)

## Summary

Verified duplicate of the older, open canonical issue tracking the same pre-build toString exception during remote dev-container configuration. Its November 2026 reproduction also covers Podman, and this thread's folder-dependent workaround matches that diagnosis.

## Change summary

Reopening a remote SSH folder in a dev container aborts with an undefined toString exception before container creation.

## Best solution

Consolidate this report into https://github.com/microsoft/vscode-remote-release/issues/9870. The Dev Containers owner should make remote configuration generation handle unavailable common URIs without aborting, preserving this report's RHEL and Podman evidence.
