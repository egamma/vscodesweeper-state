# Issue #286 — wsl: allow to run with a non-default user

[https://github.com/microsoft/vscode-remote-release/issues/286](https://github.com/microsoft/vscode-remote-release/issues/286)

## Summary

Keep this canonical Backlog request open. Current WSL support still uses the distro's default user, while recent comments confirm demand for simultaneous VS Code windows under different users.

## Change summary

Allow each VS Code WSL connection or workspace to select a non-default user without changing and restarting the distribution.

## Best solution

The WSL extension should encode the selected user in each remote workspace location, allowing separate windows for the same distro to run as different users; a per-distro user setting would be a narrower alternative.

## Vision fit

- **Fit:** aligned
- **Reason:** Selecting the effective WSL user would improve fidelity with local and Remote-SSH workflows and remove a persistent WSL integration gap.
- **Evidence:** The durable WSL integration-fidelity theme and the product promise to provide VS Code's full feature set in WSL directly support this request.
