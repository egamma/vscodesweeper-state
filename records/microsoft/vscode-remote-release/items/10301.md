# Issue #10301 — Devcontainer doesn't work on a folder mounted in WSL

[https://github.com/microsoft/vscode-remote-release/issues/10301](https://github.com/microsoft/vscode-remote-release/issues/10301)

## Summary

Keep open as an upstream Docker Desktop issue. The failure reproduces outside Dev Containers, and disabling Docker Desktop's containerd image store restored the bind mount.

## Change summary

A dev container receives an empty workspace when the project is on an external VHDX mounted into WSL and the workspace path resolves through a symlink.

## Best solution

Docker Desktop should correctly bind-mount WSL-mounted VHDX paths regardless of whether the source uses the real path or a symlink. Track the underlying mount-type behavior in https://github.com/docker/for-win/issues/14380 while retaining this report for Dev Containers compatibility.
