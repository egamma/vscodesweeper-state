# Issue #10301 — Devcontainer doesn't work on a folder mounted in WSL

[https://github.com/microsoft/vscode-remote-release/issues/10301](https://github.com/microsoft/vscode-remote-release/issues/10301)

## Summary

Keep open as an upstream Docker Desktop mount issue: the failure also occurs without VS Code, and the maintainer identified the Docker report as the likely owner. The reported storage-driver workaround is not evidence of a shipped fix.

## Change summary

Dev containers should expose files from an externally mounted WSL VHDX workspace consistently through both real and symlinked paths.

## Best solution

Docker Desktop should bind the mounted WSL filesystem consistently regardless of the source path spelling. Keep this containers report linked to the upstream investigation, retaining the extension-side path-preservation request and debugging-path complications until their remaining scope is understood.

This provides a workaround surface, not proof that the reported behavior is resolved.
