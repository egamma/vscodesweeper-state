# Issue #1718 — Allow pre-installing VS code server and extensions in development Docker image

[https://github.com/microsoft/vscode-remote-release/issues/1718](https://github.com/microsoft/vscode-remote-release/issues/1718)

## Summary

A meaningful capability gap remains: current prebuild metadata and named-volume guidance can preserve configuration or installations, but do not officially bake a compatible VS Code Server and extension payloads into a reusable image. This well-supported request should remain open with the Dev Containers component.

## Change summary

Allow development-container images to include a compatible VS Code Server and selected extensions so new containers start without downloading and reinstalling them.

## Best solution

Dev Containers should provide a supported image-build mechanism for installing the matching server and extensions, including version compatibility handling so clients do not install a second server. Existing prebuild metadata and configurable server-download settings should remain complementary options.
