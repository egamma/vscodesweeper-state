# Issue #1399 — Complete offline installation of VSCode Remote

[https://github.com/microsoft/vscode-remote-release/issues/1399](https://github.com/microsoft/vscode-remote-release/issues/1399)

## Summary

Keep open: downloading on the client does not cover installations where both client and target lack internet access. The thread still identifies a gap in discoverable, supported offline server provisioning across remote extensions.

## Change summary

Provide an offline installation workflow using predownloaded, version-matched VS Code Server packages.

## Best solution

Dev Containers and Remote - SSH should support importing version-matched server packages acquired outside the disconnected network, with discoverable downloads and documented installation and upgrade steps. Preserve this cross-extension request; mirror configuration and offline container reconnection cover only parts of it.

## Evidence

- **Existing capability is partial:** https://code.visualstudio.com/docs/remote/faq documents remote.SSH.localServerDownload and local downloads for Dev Containers, but explicitly requires outbound HTTPS from the local machine for server installation. Extensions: Install from VSIX supports offline extension installation, not the complete server-provisioning request.
- **Maintainer-supported direction:** https://github.com/microsoft/vscode-remote-release/issues/1399#issuecomment-649525324 proposes discoverable server download links and easier local tarball placement for Remote-Containers. The documented temporary-directory workaround is not an announced completed offline-installation feature.
- **Remaining user problem:** https://github.com/microsoft/vscode-remote-release/issues/1399#issuecomment-3833939466 explicitly describes both workstation and target being offline, cumbersome CLI/server provisioning, and manually placed files being deleted before another download attempt. This supports retaining the feature request, without establishing a separately reproduced bug.
- **Older related issue is not a canonical:** https://github.com/microsoft/vscode-remote-release/issues/1242 is currently closed. Its final contributor comment, https://github.com/microsoft/vscode-remote-release/issues/1242#issuecomment-2448041026, validates downloading locally and transferring to an offline SSH host; it does not demonstrate provisioning with an offline client and explicitly redirects container feedback elsewhere.
- **Open related requests do not own the full scope:** https://github.com/microsoft/vscode-remote-release/issues/6146 remains open for configurable server download URLs; https://github.com/microsoft/vscode-remote-release/issues/9454 remains open for preinstalled SSH environments; https://github.com/microsoft/vscode-remote-release/issues/10173 remains open for offline container startup. These narrower requests do not subsume complete offline installation across the components discussed here.
