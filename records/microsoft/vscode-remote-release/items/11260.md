# Issue #11260 — Ssh-agent SSH_AUTH_SOCK dies silently on devcontainer on remote linux host

[https://github.com/microsoft/vscode-remote-release/issues/11260](https://github.com/microsoft/vscode-remote-release/issues/11260)

## Summary

Keep open: a recent independent report on VS Code 1.144.0 confirms container agent communication fails while the host agent remains healthy, with Reload Window restoring access. The existing containers routing is appropriate; related reports do not establish a canonical owning the full SSH-host and WSL scope.

## Change summary

SSH-agent forwarding inside a dev container stops working after reconnection or prolonged use, preventing SSH authentication until the forwarding bridge is recreated.

## Best solution

The Dev Containers owner should investigate recovery of the agent-forwarding bridge, coordinating with Remote - SSH for the remote-host path. Forwarded identities should remain available after reconnect without requiring Reload Window; compare the WSL sleep report before deciding whether both paths share a fix.

## Evidence

- **Concrete trigger and logs:** https://github.com/microsoft/vscode-remote-release/issues/11260 supplies steps connecting to a container on Ubuntu, verifying forwarded authentication, closing the laptop and changing access points, then observing Permission denied. Remote - SSH logs show reconnection and updating the host agent symlink; the container still cannot fetch identities.
- **Recent independent confirmation:** https://github.com/microsoft/vscode-remote-release/issues/11260#issuecomment-6525717802 reports the matching communication-with-agent failure on VS Code 1.144.0 with Docker CE inside WSL. Host ssh-add still lists the identity, and Reload Window creates a new container socket and restores access without restarting the host agent.
- **Failure localized to agent communication:** https://github.com/microsoft/vscode-remote-release/issues/11260#issuecomment-3408673281 contrasts failed ssh_fetch_identitylist communication with a successful run returning two agent keys. Disabling remote.SSH.useLocalServer together with resetting the remote server reportedly avoids the original failure, but that combined workaround does not establish the root cause.
- **Documented intended behavior:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials#_using-ssh-keys documents automatic forwarding of a running local SSH agent. Initial forwarding already works here; agent setup instructions do not resolve the reported loss of communication.
