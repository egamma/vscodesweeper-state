## Summary

Keep open for the SSH owner: authentication succeeds, but a wget server-status check fails and triggers another password-bearing connection. The report uses an older extension and host environment; its explicit folder-opening steps suffice to retest, and neither resolution nor a canonical duplicate is established.

## Change summary

Opening a remote folder after successful SSH login repeatedly requests the password instead of opening the workspace.

## Best solution

This warrants separating host prerequisites from extension compatibility, but does not prove the reported loop is fixed or solely upstream.
