# Issue #3809 — Use local Docker config when building volumeBootstrap image

[https://github.com/microsoft/vscode-remote-release/issues/3809](https://github.com/microsoft/vscode-remote-release/issues/3809)

## Summary

A meaningful gap remains: private-registry credentials gained dedicated forwarding, but the bootstrap workflow still does not transparently inherit the host Docker client's proxy configuration. Keep this broader request open and route it to the container proxy/volume owners.

## Change summary

Propagate the host Docker client configuration into the bootstrap container so repository-volume builds work with proxies and private registries.

## Best solution

Dev Containers should safely forward applicable host Docker proxy configuration and credential-helper access into bootstrap and recovery containers. The newer custom-bootstrap-image setting should remain an escape hatch for air-gapped and custom-CA environments, not the only way to reproduce host Docker behavior.
