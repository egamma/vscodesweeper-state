# Issue #7524 — Use default SSH_AUTH_SOCK on Windows

[https://github.com/microsoft/vscode-remote-release/issues/7524](https://github.com/microsoft/vscode-remote-release/issues/7524)

## Summary

Keep this team-authored SSH request open: the documented agent setup does not establish that Remote-SSH supplies the Windows named-pipe fallback when SSH_AUTH_SOCK is unset. No verified canonical or qualifying fix was found.

## Change summary

Have Remote-SSH default an unset SSH_AUTH_SOCK to the Windows OpenSSH agent service's named pipe.

## Best solution

The SSH owner should verify whether current Remote-SSH already supplies this fallback and, if not, match the Dev Containers behavior described by the author while preserving explicitly configured agent sockets.
