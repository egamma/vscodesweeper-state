# Issue #4416 — vscode install hangs at wget step if target filesystem cannot flock ~/.wget-hsts

[https://github.com/microsoft/vscode-remote-release/issues/4416](https://github.com/microsoft/vscode-remote-release/issues/4416)

## Summary

Keep open: the HSTS mitigation was rolled back for older wget compatibility, and a later report describes the NFS hang with Remote - SSH 0.114.2 ignoring wget configuration. The documented trigger and successful workaround suffice for targeted retesting; current-release resolution is unverified.

## Change summary

Prevent Remote - SSH server downloads from hanging on wget's HSTS-file locking when the remote home directory uses NFS with unreliable flock support.

## Best solution

Remote - SSH should avoid HSTS-file locking in its remote download path without passing unsupported options to older wget versions. Verify that mitigation on an affected NFS home directory; local server download is an alternative workaround, not proof that the remote download defect is resolved.

## Evidence

- **Actionable original diagnosis:** https://github.com/microsoft/vscode-remote-release/issues/4416 describes server installation blocking while wget locks ~/.wget-hsts on NFS; setting hsts=0 in ~/.wgetrc avoided the hang.
- **Mitigation rolled back:** The maintainer announced disabling HSTS at https://github.com/microsoft/vscode-remote-release/issues/4416#issuecomment-790208717, then removed the flag because wget 1.14 rejected it and proposed compatibility detection at https://github.com/microsoft/vscode-remote-release/issues/4416#issuecomment-819901279. The 0.65.3 confirmation at https://github.com/microsoft/vscode-remote-release/issues/4416#issuecomment-820137980 concerns that compatibility regression, not resolution of the original NFS hang.
- **Later unresolved symptom:** https://github.com/microsoft/vscode-remote-release/issues/4416#issuecomment-2351321666 reports the NFS wget hang with Remote - SSH 0.114.2 and says --no-config prevents the hsts=0 configuration workaround. This is historical corroboration, not a verified reproduction on today's release.
- **Canonical search:** Repository searches for wget/hsts, wget-hsts, no-hsts, and wget/NFS found no verified canonical for this locking failure. https://github.com/microsoft/vscode-remote-release/issues/10571 instead diagnosed its download hang as IPv6 connectivity: https://github.com/microsoft/vscode-remote-release/issues/10571#issuecomment-2686216706. The closed https://github.com/microsoft/vscode/issues/121327 concerns the older-wget regression and points back to this issue.
- **Documented workaround boundary:** https://code.visualstudio.com/docs/remote/ssh#_what-are-the-connectivity-requirements-for-the-vs-code-server-when-it-is-running-on-a-remote-machine-vm documents remote.SSH.localServerDownload for always downloading locally and transferring the server. That bypasses remote downloading but does not establish that wget's HSTS locking has been fixed.
