# Issue #6983 — devcontainer.json cannot use exported vars from initializeCommand

[https://github.com/microsoft/vscode-remote-release/issues/6983](https://github.com/microsoft/vscode-remote-release/issues/6983)

## Summary

Keep open: documented environment-variable support does not cover feeding values calculated by initializeCommand back into arbitrary devcontainer.json properties. Related requests do not establish a qualifying canonical for this broader, previously reviewed product request.

## Change summary

Allow host-side initialization scripts to supply dynamically calculated values for devcontainer.json properties without modifying tracked configuration.

## Best solution

The Dev Containers component should support an explicit, spec-aligned way to consume initialization-generated values before resolving configuration properties such as name and build.args. Coordinate with https://github.com/devcontainers/spec/issues/743 while retaining this issue for extension-side delivery.

## Evidence

- **Requested scope:** https://github.com/microsoft/vscode-remote-release/issues/6983 requests initialization-generated values for name, Dockerfile build arguments, proxy configuration, and other properties while keeping devcontainer.json a generic tracked template; the supplied comments contain no resolution.
- **Existing-capability check:** https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson documents ${localEnv:VARIABLE_NAME} as reading host environment variables and warns that clients may require restarting to observe changes. Its lifecycle documentation describes initializeCommand as a host command, not a mechanism for returning computed configuration variables.
- **Environment-file limitation:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents containerEnv, remoteEnv, and runArgs with --env-file. These configure container or remote-process environments; they do not supply initialization-generated substitutions for name or build.args.
- **Maintainer assessment:** https://github.com/devcontainers/cli/issues/437#issuecomment-1477617517 explicitly states that command-generated build arguments are unsupported and describes writing an initialization-time .env file for subsequent variable references as another unsupported approach. That closed CLI discussion is not a valid duplicate canonical.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/3972 is open and older, but requests dynamic docker run arguments; it does not own this report's full configuration-substitution scope, including name and build.args. https://github.com/microsoft/vscode-remote-release/issues/3007 concerns missing environment-file handling, and https://github.com/microsoft/vscode-remote-release/issues/3541 concerns reading user settings rather than initialization-generated values.
