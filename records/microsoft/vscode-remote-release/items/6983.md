# Issue #6983 — devcontainer.json cannot use exported vars from initializeCommand

[https://github.com/microsoft/vscode-remote-release/issues/6983](https://github.com/microsoft/vscode-remote-release/issues/6983)

## Summary

Verified cross-repository duplicate: the open Dev Container specification issue tracks the same missing ability to consume values generated by initializeCommand during devcontainer.json substitution.

## Change summary

Allow initializeCommand to generate user-specific values that can populate names, build arguments, proxy settings, and other devcontainer.json properties.

## Best solution

Define a portable mechanism in the Dev Container specification for host initialization to emit values consumed during configuration substitution, tracking the work in https://github.com/devcontainers/spec/issues/743 and carrying over this report's build-argument and proxy use cases.

## Vision fit

- **Fit:** rejected
- **Reason:** This is a cross-tool devcontainer.json lifecycle and substitution capability, so its authoritative design belongs in the Dev Container specification rather than the VS Code extension tracker.
- **Evidence:** The vision guardrail says, "Spec work belongs to the spec," with the extension following the open specification instead of defining a separate format behavior.
