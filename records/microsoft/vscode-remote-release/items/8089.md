# Issue #8089 — Start Docker daemon for me if it's not already started

[https://github.com/microsoft/vscode-remote-release/issues/8089](https://github.com/microsoft/vscode-remote-release/issues/8089)

## Summary

Keep this canonical request open: Docker Desktop auto-start now exists in some workflows, but current reports show version-specific regressions, insufficient startup polling, and unresolved Linux/WSL coverage.

## Change summary

Have Dev Containers start an installed but stopped Docker daemon and wait for it to become available when opening or creating a container.

## Best solution

Dev Containers should provide reliable cross-platform daemon startup with progress, readiness polling, and actionable failure handling. The containers owner should clarify remaining Linux and WSL coverage before treating the original request as fully delivered.
