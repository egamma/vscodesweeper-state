# Issue #10350 — [Remote-SSH] consider wget2

[https://github.com/microsoft/vscode-remote-release/issues/10350](https://github.com/microsoft/vscode-remote-release/issues/10350)

## Summary

The wget2 detection problem remains credibly reported on Fedora 40 and independently confirmed on Fedora 42. Keep it open and route it to the Remote - SSH installer path.

## Change summary

Remote - SSH misdetects wget2's `--no-config` support, performs unnecessary help probes when configuration files are enabled, and handles slow server downloads poorly.

## Best solution

The SSH installer should handle wget2 without relying solely on its help output and skip capability probes when curl/wget configuration files are explicitly enabled. The configurable inactivity timeout and resumable-download request should be evaluated separately by the SSH server-install owner.
