# Issue #10350 — [Remote-SSH] consider wget2

[https://github.com/microsoft/vscode-remote-release/issues/10350](https://github.com/microsoft/vscode-remote-release/issues/10350)

## Summary

Keep open for Remote - SSH installer investigation: the Fedora wget2 setup and exact false capability warning provide enough detail to retest. The latest confirmation is on VS Code 1.104.2/Fedora 42, not today's release, and neither a confirmed fix nor a canonical covering the full report was found.

## Change summary

Remote - SSH misdetects wget2's --no-config support, performs unnecessary capability probes when downloader configuration is enabled, and is requested to preserve progressing server downloads across timeouts.

## Best solution

The SSH component should verify wget2 capability detection and avoid configuration-flag probes when configuration files are explicitly enabled. Evaluate progress-aware installation timeouts separately without losing the downloader-specific defects tracked here.

## Evidence

- **Concrete installer trigger:** https://github.com/microsoft/vscode-remote-release/issues/10350 describes Fedora 40 exposing wget2 as /usr/bin/wget, an exact false '--no-config' warning, and unnecessary help probes with remote.SSH.useCurlAndWgetConfigurationFiles=true. These are specific installer behaviors, not merely an unexplained connection failure.
- **Investigation and later confirmation:** https://github.com/microsoft/vscode-remote-release/issues/10350#issuecomment-2394397256 acknowledges downloader-flavor detection difficulties and promises wget2 testing, but announces no fix. https://github.com/microsoft/vscode-remote-release/issues/10350#issuecomment-3346827461 reports the same issue on VS Code 1.104.2/Fedora 42 in September 2025; this is historical confirmation, not current-release reproduction.
- **Existing capability is only a workaround:** https://code.visualstudio.com/docs/remote/ssh#_what-are-the-connectivity-requirements-for-the-vs-code-server-when-it-is-running-on-a-remote-machine-vm documents remote.SSH.localServerDownload for downloading locally and transferring the server. That can bypass remote wget, but does not correct wget2 detection, redundant configuration probes, or provide the requested progress-aware download timeout.
