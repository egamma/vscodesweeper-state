# Issue #10470 — Forward access to the host credential/secret storage, to allow credential reuse and increased security

[https://github.com/microsoft/vscode-remote-release/issues/10470](https://github.com/microsoft/vscode-remote-release/issues/10470)

## Summary

Keep open: documented Git credential sharing does not cover generic host secret-storage access from container tools, including credentials created inside the container. The request crosses the container credential-access boundary and needs human security/design review.

## Change summary

Allow container command-line tools to reuse and manage credentials through the host OS secret store across containers and rebuilds.

## Best solution

The Dev Containers owner should evaluate an explicitly authorized host credential broker, including access controls and container-originated credential writes, alongside the related spec proposal. Keep the extension implementation request tracked here; a spec change alone would not deliver it.

## Evidence

- **Requested scope:** https://github.com/microsoft/vscode-remote-release/issues/10470 describes repeated GitHub CLI logins across containers and lost credentials after rebuilds. The author's follow-up explicitly includes tools absent from the host and credentials created from inside the container, distinguishing this from one-way secret injection.
- **Existing capability is partial:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents bidirectional reuse of a configured local Git credential helper and SSH/GPG support. It does not document a generic OS secret-store interface for arbitrary container CLI tools.
- **Environment injection is not a broker:** https://code.visualstudio.com/remote/advancedcontainers/environment-variables documents containerEnv, remoteEnv, and ${localEnv:...}. These inject environment values rather than providing container tools with a host credential-store read/write interface.
- **Spec proposal does not replace product work:** https://github.com/devcontainers/spec/issues/515 is open and explicitly identifies this issue as the VS Code implementation request. It discusses credential-helper configuration and permissions beyond environment variables; adopting that proposal would still leave extension implementation work.
- **Declarative secrets distinction:** https://github.com/devcontainers/spec/issues/198 concerns secret declarations, environment injection, and secret references. The reporter already considered it and explained why generic credential-store access, including writes from container tools, is a broader requirement.
- **Canonical search:** Searches for host credentials, secret storage, keychain, and credential forwarding found no verified canonical covering the full request. https://github.com/microsoft/vscode-remote-release/issues/11580 is open but requests declarative secret injection; it is newer, has no milestone, and has the same one upvote, so it also fails the re-review ownership bar.
