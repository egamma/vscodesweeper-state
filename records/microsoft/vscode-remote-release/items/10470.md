# Issue #10470 — Forward access to the host credential/secret storage, to allow credential reuse and increased security

[https://github.com/microsoft/vscode-remote-release/issues/10470](https://github.com/microsoft/vscode-remote-release/issues/10470)

## Summary

A real Dev Containers capability gap remains: existing credential forwarding is tool-specific and does not provide generic, controlled access to host secret storage. The issue is already correctly routed and should remain open while the corresponding dev container specification work is considered.

## Change summary

Provide dev-container command-line tools with reusable, secure access to credentials held in the host operating system's secret storage.

## Best solution

Define a portable, least-privilege credential-access mechanism through https://github.com/devcontainers/spec/issues/515, then implement that mechanism in the Dev Containers extension rather than introducing an extension-specific secret-storage protocol.

## Evidence

- **existing capability:** https://code.visualstudio.com/remote/advancedcontainers/sharing-git-credentials documents automatic forwarding for Git credential helpers, SSH agents, and GPG, but not a generic host credential or secret-storage interface usable by arbitrary container tools.
- **spec ownership:** https://github.com/devcontainers/spec/issues/515 is open and explicitly considers standardized access to host credential storage beyond environment-variable secrets; it was opened from this request to address the portable specification side.
- **partial alternative:** Declarative secrets were finalized in https://github.com/devcontainers/spec/issues/216, but VS Code implementation remains open at https://github.com/microsoft/vscode-remote-release/issues/8559 and would still not cover tools that create or retrieve credentials dynamically from inside the container.
