# Issue #9735 — Give the ability to trigger devcontainer rebuild from scripts (git hooks, etc.)

[https://github.com/microsoft/vscode-remote-release/issues/9735](https://github.com/microsoft/vscode-remote-release/issues/9735)

## Summary

Keep open in the Containers backlog: existing CLI operations can build or recreate a dev container, but they do not provide a documented, atomic way for a script or in-container Git hook to rebuild the active environment and reopen its VS Code window.

## Change summary

Allow scripts such as Git branch-switch hooks to trigger rebuilding and reopening the current dev container.

## Best solution

The Dev Containers component should provide a supported scriptable command that safely rebuilds the current workspace container and reconnects its VS Code window, including when invoked after a branch switch.

## Evidence

- **existing capability:** https://code.visualstudio.com/docs/devcontainers/devcontainer-cli documents separate `up`, `build`, `exec`, and extension-provided `open` operations, but no atomic rebuild-and-reopen command.
- **partial CLI workaround:** The current open-source CLI exposes `up --remove-existing-container` at https://github.com/devcontainers/cli/blob/58be9705761d276b5076525438bbe73642f521d5/src/spec-node/devContainersSpecCLI.ts, but removing the active container and separately opening it does not fully cover safe invocation from a hook running inside that container.
- **canonical search:** https://github.com/microsoft/vscode-remote-release/issues/8918 covers automatic rebuilding on startup after configuration changes, while https://github.com/microsoft/vscode-remote-release/issues/7540 covers building without reopening from outside the container; neither owns the full script-triggered rebuild-and-reopen request.
