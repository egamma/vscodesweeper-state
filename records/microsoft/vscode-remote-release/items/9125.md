# Issue #9125 — Dev Container: /workspaces not user writable

[https://github.com/microsoft/vscode-remote-release/issues/9125](https://github.com/microsoft/vscode-remote-release/issues/9125)

## Summary

Keep open under discussion: making the parent /workspaces directory writable raises an unresolved persistence question, distinct from incorrect ownership inside mounted projects. The latest linked workaround does not establish that the original cloning workflow is resolved.

## Change summary

Allow non-root users to clone repositories directly under /workspaces rather than only inside the mounted project folder.

## Best solution

The containers owner should settle a safe sibling-repository workflow that makes writability and rebuild persistence explicit. Preserve the distinction between this parent-directory usability issue and runtime-specific ownership failures inside mounted workspaces.
