# Issue #9125 — Dev Container: /workspaces not user writable

[https://github.com/microsoft/vscode-remote-release/issues/9125](https://github.com/microsoft/vscode-remote-release/issues/9125)

## Summary

The `/workspaces` parent is intentionally root-owned because only the mounted workspace folder is preserved; the documented `workspaceMount` property covers workflows that need the parent and sibling projects writable and persistent.

## Change summary

Make the `/workspaces` parent directory writable by the Dev Containers non-root user.

## Best solution

Keep the current safe default and use `workspaceMount` to bind-mount the local parent directory at `/workspaces` when sibling repositories must be writable and survive rebuilds. Treat failures to write inside the actual mounted workspace under rootless Docker as the separate problem tracked in https://github.com/microsoft/vscode-remote-release/issues/11279.

- **Proposed comment:**

  > Thanks for the report and discussion. The `/workspaces` parent is expected to remain root-owned because only the mounted workspace folder is preserved across rebuilds; allowing unrelated content there could create an unexpected data-loss risk.
  > 
  > For a writable, persistent `/workspaces` containing sibling projects, configure `workspaceMount` as documented at https://code.visualstudio.com/remote/advancedcontainers/change-default-source-mount, for example: `source=${localWorkspaceFolder}/..,target=/workspaces,type=bind,consistency=cached`.
  > 
  > Reports where the actual mounted workspace folder is not writable under rootless Docker are a separate problem being investigated in https://github.com/microsoft/vscode-remote-release/issues/11279.
