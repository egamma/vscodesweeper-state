# Issue #9125 — Dev Container: /workspaces not user writable

[https://github.com/microsoft/vscode-remote-release/issues/9125](https://github.com/microsoft/vscode-remote-release/issues/9125)

## Summary

Keep open: this is already routed to Dev Containers and under discussion, with multiple users reporting root-owned `/workspaces` or workspace folders across Docker Desktop, Podman, and rootless Docker setups. A maintainer raised a real design concern that making `/workspaces` writable could imply persistence that is not guaranteed, so this needs a containers decision rather than cleanup closure.

## Change summary

Dev Containers can leave `/workspaces` or workspace content owned by root, preventing non-root container users from cloning or editing there.

## Best solution

The Dev Containers owner should decide whether the parent `/workspaces` directory should be writable, documented as intentionally non-persistent, or handled through a safer supported pattern such as `workspaceMount`; the Docker Desktop/rootless ownership reports should be considered part of that decision unless split into a narrower runtime-specific bug.
