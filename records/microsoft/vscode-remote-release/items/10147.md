# Issue #10147 — Wrong WSL instance chosen for auto-mount

[https://github.com/microsoft/vscode-remote-release/issues/10147](https://github.com/microsoft/vscode-remote-release/issues/10147)

## Summary

The report identifies a plausible Dev Containers mismatch between the active Windows Docker context and the WSL distro used for Wayland auto-mounts, but only the reporter has reproduced it and the latest confirmation is from May 2025. Current versions and a fresh creation log are needed before further diagnosis.

## Change summary

Dev Containers should derive automatic WSL mounts from the environment hosting the selected container runtime rather than an unrelated default WSL distro.

## Best solution

The Dev Containers component should consistently associate Wayland and other automatic mounts with the selected Docker or Podman context, without starting or reading paths from an unrelated default WSL distro. A current creation log and environment inventory should first confirm that the mismatch remains.
