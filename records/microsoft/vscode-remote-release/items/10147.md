# Issue #10147 — Wrong WSL instance chosen for auto-mount

[https://github.com/microsoft/vscode-remote-release/issues/10147](https://github.com/microsoft/vscode-remote-release/issues/10147)

## Summary

Keep open: the supplied log demonstrates an Ubuntu Wayland mount being passed to the Windows desktop-linux Docker context, preventing container startup. The reporter last confirmed persistence in May 2025; the existing steps suffice to retest, and no verified fix or full-scope canonical was found.

## Change summary

Dev Containers selects automatic WSL GUI mounts independently of the container's Docker context, causing volume-backed and recovery containers to fail.

## Best solution

Dev Containers should make automatic GUI mounts compatible with the selected container engine and avoid injecting inaccessible WSL paths. Retest the documented Windows Docker-context scenario, distinguishing mount-source selection from Docker Desktop's WSL integration requirements.
