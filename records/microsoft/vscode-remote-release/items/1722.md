# Issue #1722 — Cluster workflow feature to allow shell commands or script to run before remote server setup (e.g. slurm) (wrap install script)

[https://github.com/microsoft/vscode-remote-release/issues/1722](https://github.com/microsoft/vscode-remote-release/issues/1722)

## Summary

Keep open as the canonical Remote - SSH request for running the server inside scheduler-managed compute jobs. RemoteCommand, tunnels, ProxyJump, and community wrappers provide partial workarounds, but recent comments confirm that clusters permitting access only through commands such as `srun --pty` still lack a supported workflow.

## Change summary

Allow Remote - SSH to wrap server installation and startup in a customizable scheduler command so the server, extensions, terminals, and debuggers run inside an allocated compute job.

## Best solution

Remote - SSH should provide a supported bootstrap or connection hook that preserves server communication while entering a Slurm, LSF, or similar job context. The design should cover clusters where compute nodes cannot be reached through ordinary SSH, rather than requiring users to replace the SSH binary with community wrappers.
