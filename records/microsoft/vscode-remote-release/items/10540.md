# Issue #10540 — Cannot connect to projects in WSL after upgrading to Windows 11 24H2 if BBR2 is enabled

[https://github.com/microsoft/vscode-remote-release/issues/10540](https://github.com/microsoft/vscode-remote-release/issues/10540)

## Summary

The evidence points to Windows 11 24H2/WSL2 networking rather than the WSL extension: changing the Windows congestion provider resolved the original report, while another user recovered by disabling mirrored networking. Keep this upstream issue open for the WSL team.

## Change summary

WSL remote connections time out after upgrading to Windows 11 24H2 when particular WSL2 networking and congestion-control configurations are enabled.

## Best solution

The WSL platform should correct the Windows 11 24H2 networking behavior affecting loopback communication; the WSL extension can retain this report to track upstream resolution and improve diagnostics for the known configuration.

## Evidence

- **maintainer diagnosis:** A maintainer confirmed that the VS Code Server started and was reachable, while the client timed out resolving the remote, localizing the failure to communication between the Windows client and WSL server.
- **upstream workaround:** The reporter restored Remote WSL by changing the Windows congestion provider from BBR2 to CTCP after identifying broken BBR2 behavior in Windows 11 24H2.
- **independent confirmation:** A second affected user restored connectivity by changing WSL2 networking from mirrored mode to the default mode, further implicating the Windows/WSL networking layer.
- **cross-application evidence:** https://github.com/siyuan-note/siyuan/issues/17710 reports another application failing under Windows with TCP BBR2 enabled, consistent with a system-level networking defect.
