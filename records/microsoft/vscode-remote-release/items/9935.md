# Issue #9935 — Opening the host's browser automatically after Dev Container startup

[https://github.com/microsoft/vscode-remote-release/issues/9935](https://github.com/microsoft/vscode-remote-release/issues/9935)

## Summary

A real Dev Containers capability gap remains: lifecycle commands cannot use the client-backed browser bridge even after post-attach, and the documented alternatives cover only narrower scenarios. The issue is correctly routed and accepted in the Backlog.

## Change summary

Allow a Dev Container lifecycle hook to open host-side URLs after VS Code has connected, including interactive authentication flows.

## Best solution

The Dev Containers extension should run `postAttachCommand` with access to the connected client's `BROWSER` or `code --openExternal` bridge, or provide an equivalent container-scoped post-connection hook. This would support arbitrary URLs and interactive CLI authentication without affecting developers who open the repository locally.

## Evidence

- **confirmed limitation:** A maintainer explained that `BROWSER` depends on the VS Code connection while lifecycle commands run separately; the March 2026 team comment notes that the documented `postAttachCommand` semantics create a reasonable expectation that the connection is available.
- **spec semantics:** The Dev Container specification defines `postAttachCommand` as running each time a tool has successfully attached: https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md
- **partial task workaround:** A `runOn: folderOpen` VS Code task successfully opens the browser, but it is repository-wide rather than Dev-Container-only; suppressing its terminal also prevents the desired progress display for long-running setup.
- **partial port capability:** The Dev Container spec supports `portsAttributes.onAutoForward: openBrowser`, but that only opens an auto-forwarded port and does not cover arbitrary URLs or interactive commands such as `az login` and `gh auth login`: https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainerjson-reference.md
- **canonical search:** The closely related https://github.com/microsoft/vscode-remote-release/issues/9309 is closed solely through the 60-day Backlog Candidates process, so it cannot serve as a duplicate canonical or establish that the capability was implemented.
