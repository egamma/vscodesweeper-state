# Issue #11847 — No 'disk full' check, just silent failures

[https://github.com/microsoft/vscode-remote-release/issues/11847](https://github.com/microsoft/vscode-remote-release/issues/11847)

## Summary

Route to Remote - SSH and VS Code Server: an independent reproduction shows disk exhaustion reported only in raw logs while the client presents cascading connection failures. Freeing space restores operation, but does not resolve the missing actionable error.

## Change summary

Surface remote disk exhaustion clearly instead of allowing server installation and agent failures to appear as unrelated connection errors.

## Best solution

Remote - SSH and VS Code Server should preserve ENOSPC/StorageFull as an actionable client error identifying the affected remote location, and avoid futile retries while storage remains exhausted. Use the supplied installation repro first, then establish whether the original mid-session agent failures need the same handling or a separate fix.

## Evidence

- **Concrete independent reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11847#issuecomment-5872493609 reports VS Code 1.139.1 with Remote-SSH 0.129.2026091815 connecting from macOS to Ubuntu with /home at 100% usage. Server unpacking reports StorageFull and errno 28, followed by socket failures, connection closure, and retries without an actionable disk-full UI message.
- **Environment trigger versus product handling:** The same comment confirms that moving ~/.vscode-server to storage with headroom makes the identical installation succeed immediately. This establishes disk exhaustion as the trigger, not that the requested error handling is fixed; the OS error already reaches the server log.
- **Related open requests do not establish full canonical ownership:** https://github.com/microsoft/vscode-remote-release/issues/5592 is open and requests host resource detection, with a comment requesting disk/quota diagnostics, but does not clearly own both ongoing-session failures and the demonstrated error-propagation defect. https://github.com/microsoft/vscode-remote-release/issues/7963 is open and requests configurable server-version housekeeping, which would not ensure clear errors when storage fills for other reasons.
- **Prior matching failure was not resolved:** https://github.com/microsoft/vscode-remote-release/issues/7206 describes server installation retrying after explicit disk-full errors. A maintainer proposed returning the disk error faster at https://github.com/microsoft/vscode-remote-release/issues/7206#issuecomment-1252987145; its subsequent closure was an information timeout, not a fix or scope decision.
