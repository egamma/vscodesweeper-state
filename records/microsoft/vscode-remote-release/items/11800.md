# Issue #11800 — Dev Containers over Remote-SSH on Windows unnecessarily invokes local wsl -l -v when connected to Linux remote host

[https://github.com/microsoft/vscode-remote-release/issues/11800](https://github.com/microsoft/vscode-remote-release/issues/11800)

## Summary

Local WSL startup for service forwarding is intentional even with remote containers. The existing dev.containers.forwardWSLServices setting provides the requested opt-out.

## Change summary

Avoid invoking local WSL when opening a dev container on a Linux Remote-SSH host.

## Best solution

Keep optional WSL service forwarding and use "dev.containers.forwardWSLServices": false in local User settings when it is unwanted. A remaining invocation with that setting disabled would warrant a separate defect investigation.

- **Proposed comment:**

  > Thanks for the report. Dev Containers can connect to local WSL to forward services even when the container runs on a remote SSH host. To disable that behavior, set "dev.containers.forwardWSLServices": false in your local User settings. This is separate from dev.containers.executeInWSL, which controls where Docker commands run.
  > 
  > This opt-out resolved the same workflow in https://github.com/microsoft/vscode-remote-release/issues/9905. If local WSL is still invoked with forwarding disabled, please provide the container log and that setting value so the remaining behavior can be investigated.
