# Issue #8103 — Cannot build a devcontainer image with Podman - Dockerfile-with-features: no such file or directory

[https://github.com/microsoft/vscode-remote-release/issues/8103](https://github.com/microsoft/vscode-remote-release/issues/8103)

## Summary

Keep open as an upstream Podman compatibility issue: the maintainer identified incorrect forwarding of the generated Dockerfile, not an extension defect. Later upstream success reports do not establish resolution of this reporter's exact failure.

## Change summary

Building a dev container with Podman fails because the generated Dockerfile-with-features is not accessible to the remote builder.

## Best solution

Podman's remote build path should correctly forward Dockerfiles outside the build context on macOS and Windows. The containers owner can retest the logged command with current Podman before deciding whether this tracking issue is resolved; the closed upstream report is related evidence, not a duplicate target.

Windows users report the corresponding Linux-prefixed C:/Users/... path.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode-remote-release/issues/8103#issuecomment-1459642943 states that the extension passes the correct path. https://github.com/microsoft/vscode-remote-release/issues/8103#issuecomment-1477844374 attributes the failure to Podman CLI forwarding of -f on Windows or Mac and directs investigation upstream.

A Windows confirmation on Podman 5.3.0-rc1 (https://github.com/podman-container-tools/podman/issues/17313#issuecomment-2448949912) therefore does not prove this exact macOS failure resolved.
- **Reporter workaround:** The original reporter confirmed that downgrading to Podman 4.3.1 worked after failures on 4.4.2 and 4.4.4: https://github.com/podman-container-tools/podman/issues/17313#issuecomment-1508452808.
