# Issue #5389 — second wsl2 user causes  /tmp/remote-wsl-loc.txt permission denied

[https://github.com/microsoft/vscode-remote-release/issues/5389](https://github.com/microsoft/vscode-remote-release/issues/5389)

## Summary

Verified duplicate: the open canonical issue tracks VS Code using the WSL distro's default user instead of the user invoking `code`, including multi-user scenarios. The shared `/tmp/remote-wsl-loc.txt` permission failure is a specific symptom of that broader limitation.

## Change summary

Launching `code .` as a second WSL2 user fails because the launcher reuses a temporary file owned by the first user and connects as the wrong user.

## Best solution

Consolidate on https://github.com/microsoft/vscode-remote-release/issues/286 and make the WSL extension honor the invoking user, including concurrent multi-user sessions; its location-discovery temporary state must also be isolated safely per user or invocation.
