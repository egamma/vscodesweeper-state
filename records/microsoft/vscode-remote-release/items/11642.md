# Issue #11642 — [Dev Containers] Incompatibility with Podman .in files

[https://github.com/microsoft/vscode-remote-release/issues/11642](https://github.com/microsoft/vscode-remote-release/issues/11642)

## Summary

A documented Podman capability is lost when Dev Containers parses and rewrites a `.in` Containerfile. The request is already correctly routed and accepted into the Backlog, with no canonical issue or complete existing capability found.

## Change summary

Preserve Podman's CPP preprocessing for `.in` Containerfiles when Dev Containers validates and augments them with Features metadata.

## Best solution

The Dev Containers tooling should preprocess Podman `.in` files before Dockerfile analysis and preserve the expanded content when generating `Dockerfile-with-features`; the containers/CLI owners should determine whether that implementation belongs in the public devcontainers CLI.

- **existing capability check:** https://containers.dev/features documents Features as reusable installation units, but they do not preserve arbitrary CPP-based composition of project-owned Containerfile fragments; the reporter also explains why available Features do not cover the required tool set.
