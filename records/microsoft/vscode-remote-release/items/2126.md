# Issue #2126 — Support WSL mount options with vscode remote

[https://github.com/microsoft/vscode-remote-release/issues/2126](https://github.com/microsoft/vscode-remote-release/issues/2126)

## Summary

Keep this accepted backlog request open: custom WSL automount metadata and fmask options still prevent the extension's scripts from executing after updates, and no documented setting covers the scenario. This is the oldest, best-supported issue in the correct tracker.

## Change summary

Allow the WSL extension to start when Windows drives use metadata and restrictive fmask mount options that leave its bundled shell scripts non-executable.

## Best solution

The WSL extension should invoke its bundled scripts through the shell rather than requiring executable permission on the Windows mount. The newer matching report at https://github.com/microsoft/vscode/issues/185775 should consolidate into this accepted WSL backlog item.
