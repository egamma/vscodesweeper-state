# Issue #11465 — User impersonation with kubectl "--as argument"

[https://github.com/microsoft/vscode-remote-release/issues/11465](https://github.com/microsoft/vscode-remote-release/issues/11465)

## Summary

Keep this accepted Backlog request open: namespace-specific Kubernetes impersonation remains a distinct Dev Containers capability, with no documented setting or verified canonical covering it.

## Change summary

Allow Dev Containers to pass a namespace-specific impersonation identity through kubectl's --as argument when attaching to Kubernetes containers.

## Best solution

The containers component should support explicit impersonation identities scoped to the selected cluster and namespace and preserve that identity throughout attachment. Kubernetes API authorization must remain authoritative; a single kubeconfig-wide identity does not satisfy the requested workflow.
