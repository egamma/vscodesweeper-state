# Issue #11067 — HostName expansion in ssh_config with Host * pattern breaks remote ssh for matching hosts

[https://github.com/microsoft/vscode-remote-release/issues/11067](https://github.com/microsoft/vscode-remote-release/issues/11067)

## Summary

Keep open for Remote - SSH: the supplied configuration, connection steps, and logs suffice to retest the malformed hostname. Later discussion reports persistence beyond the original release, but there is no current-release confirmation, verified canonical, or confirmed fix.

## Change summary

Remote - SSH corrupts wildcard HostName expansion when connecting as user@host by inserting :undefined or a port into the hostname.

## Best solution

Remote - SSH should preserve the selected username and host alias while keeping the port separate from HostName %h expansion. Retest the supplied configuration with both omitted and explicit ports, including the reported uppercase-host variant.

## Evidence

- **Complete reproduction and malformed command:** https://github.com/microsoft/vscode-remote-release/issues/11067 supplies Host srv* with HostName %h.all.domain.parts.com and Connect to Host input user@srv01. On VS Code 1.101.2 / Remote - SSH 0.120.0, the generated command passes jkleemann@srv01:undefined, producing a DNS lookup for srv01:undefined.srv.phys.tu-darmstadt.de. An explicit :22 reportedly contaminates the hostname similarly.
- **Reporter clarification rules out suggested workaround:** https://github.com/microsoft/vscode-remote-release/issues/11067#issuecomment-3734426633 confirms plain ssh user@srv01 works with the same configuration, while Remote - SSH still fails. Connecting without a username works but loses dynamic user selection; uppercase srvAB also fails while srvab works. https://github.com/microsoft/vscode-remote-release/issues/11067#issuecomment-3708310080 confirms changing HostName to Hostname does not resolve this report.
- **Later related reproduction, not current verification:** https://github.com/microsoft/vscode-remote-release/issues/11067#issuecomment-3715131617 reports the same srvAB:undefined expansion on VS Code 1.107.0 / Remote - SSH 0.122.0, while explicitly distinguishing a separate Match originalhost case. This supports persistence on a later release but does not establish reproduction on today's release.
- **Documented connection contract and troubleshooting:** https://code.visualstudio.com/docs/remote/ssh#_connect-to-a-remote-host instructs users to enter the same user@hostname that works in a terminal. The fully read https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-troubleshooting treats failure of the generated command as a likely configuration issue, not conclusive attribution; here the log shows the generated target differs from the working target before SSH performs expansion.
