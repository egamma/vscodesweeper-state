# Issue #11345 — Distinguish hosts with the same Host but different Ports in Explorer

[https://github.com/microsoft/vscode-remote-release/issues/11345](https://github.com/microsoft/vscode-remote-release/issues/11345)

## Summary

Keep open for improving the Add New SSH Host workflow when one address exposes multiple SSH endpoints. Unique aliases already distinguish targets, but manually creating them does not address the reported collision between automatically generated Host entries.

## Change summary

Distinguish SSH Explorer targets sharing an address but using different ports, including Windows and WSL endpoints.

## Best solution

Remote - SSH should detect an existing Host alias during Add New SSH Host and offer a distinct alias for the additional endpoint, preserving OpenSSH configuration semantics. Separate Windows and WSL aliases provide an immediate workaround.

## Evidence

- **Reported workflow:** https://github.com/microsoft/vscode-remote-release/issues/11345 describes using the add button for Windows and WSL SSH endpoints on different ports, producing identical Host fields that Explorer cannot distinguish.
- **Existing capability and remaining gap:** https://code.visualstudio.com/docs/remote/ssh#_remember-hosts-and-advanced-settings documents Add New SSH Host, editable SSH configuration, and configuration-backed Explorer targets. Distinct Host aliases can distinguish endpoints, but the documentation does not establish automatic collision handling when adding another port on the same address.
- **Maintainer-recommended workaround:** https://github.com/microsoft/vscode-remote-release/issues/9872#issuecomment-2106122883 recommends differently named configuration entries for different ports or users; a maintainer endorses this at https://github.com/microsoft/vscode-remote-release/issues/9872#issuecomment-2110771007. This supports aliases as the workaround, not proof that the add workflow handles collisions.
- **Canonical search:** https://github.com/microsoft/vscode-remote-release/issues/6083 reports the same target-list problem but is closed, without a fixing-release confirmation in its comments. The verified open https://github.com/microsoft/vscode-remote-release/issues/10234 concerns connection-cache collisions and incorrect terminals, not Explorer target generation, so it does not own this entire request.
- **Configuration semantics:** https://man7.org/linux/man-pages/man5/ssh_config.5.html documents Host-pattern matching and first-obtained parameter precedence. Separate Host aliases are preferable to treating repeated identical Host sections as independently selectable port-specific profiles.
