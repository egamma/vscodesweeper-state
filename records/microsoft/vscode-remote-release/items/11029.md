# Issue #11029 — Fail to read C:/Users/<username>/.ssh/config if the local username profile contains an accented character

[https://github.com/microsoft/vscode-remote-release/issues/11029](https://github.com/microsoft/vscode-remote-release/issues/11029)

## Summary

This VS Code 1.101 regression was fixed in the public VS Code core repository and shipped in 1.102.0. The fix addresses the same PowerShell environment-variable encoding corruption that prevented Remote - SSH from locating the accented profile path.

## Change summary

Remote - SSH cannot read the default SSH configuration when a Windows profile path contains accented characters.

## Best solution

Keep the shipped VS Code core fix that forces UTF-8 when PowerShell supplies environment variables; current VS Code releases should pass the correct profile path to Remote - SSH.
