# Issue #11029 — Fail to read C:/Users/<username>/.ssh/config if the local username profile contains an accented character

[https://github.com/microsoft/vscode-remote-release/issues/11029](https://github.com/microsoft/vscode-remote-release/issues/11029)

## Summary

Two users confirmed that Remote - SSH mishandles accented Windows profile paths after VS Code 1.100.3, preventing automatic SSH config discovery. This remains a concrete SSH configuration regression and should be routed with Windows and SSH-config context.

## Change summary

Preserve non-ASCII characters when Remote - SSH resolves the Windows user profile and default SSH configuration path.

## Best solution

Remote - SSH should resolve Windows environment variables and the default `~/.ssh/config` path without lossy character conversion, restoring the behavior observed in VS Code 1.100.3.
