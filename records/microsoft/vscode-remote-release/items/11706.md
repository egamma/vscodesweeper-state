## Summary

Keep open: the concrete SetEnv reproduction already includes restarting the VS Code Server, so the historical workaround does not explain this report. The supplied steps suffice for a maintainer retest; no current fix or canonical covering both directives was verified.

## Change summary

SSH-configured SetEnv and SendEnv variables are absent from the remote VS Code environment, including after restarting the server.

## Best solution

The SSH component should reproduce the supplied SetEnv case with a fresh server and determine where the accepted SSH environment is lost before reaching the remote terminal. Restore forwarding if confirmed, distinguishing it from SendEnv failures caused by the local application's inherited environment.
