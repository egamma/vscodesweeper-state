# Issue #11706 — SetEnv and SendEnv are ignored when connecting to remote host

[https://github.com/microsoft/vscode-remote-release/issues/11706](https://github.com/microsoft/vscode-remote-release/issues/11706)

## Summary

The documented server-restart workaround reportedly failed, but the required Remote - SSH log and an external environment comparison are missing. More evidence is needed to distinguish server reuse from a current SSH environment-forwarding defect.

## Change summary

Remote - SSH sessions do not inherit variables provided through OpenSSH SetEnv or SendEnv directives.

## Best solution

Confirm whether Remote - SSH starts or reuses a server without the accepted SSH environment, then have the SSH component preserve those variables when launching the remote extension host. Compare the result with the similar open SendEnv report at https://github.com/microsoft/vscode-remote-release/issues/11447.
