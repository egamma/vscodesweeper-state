# Issue #10608 — Docker rootless mounts files as root instead of my user

[https://github.com/microsoft/vscode-remote-release/issues/10608](https://github.com/microsoft/vscode-remote-release/issues/10608)

## Summary

Keep open as upstream: Docker's documented rootless UID mapping explains why the workspace appears root-owned and is unwritable by vscode. The older matching report is verified, but the explicit keep-open rule for upstream issues bars a duplicate close.

## Change summary

Allow a non-root container user to edit host-owned workspace bind mounts when using rootless Docker.

## Best solution

Docker needs configurable rootless UID mapping, tracked at https://github.com/moby/moby/issues/41497. Dev Containers owners should coordinate guidance and any runtime accommodation with https://github.com/microsoft/vscode-remote-release/issues/4646 while preserving this report's Linux distribution and rebuild evidence.

## Evidence

- **Documented root cause:** https://docs.docker.com/engine/security/rootless/uid-gid-mapping/ explicitly states that rootless Docker maps container UID 0 to the daemon user's host UID, so host-user-owned bind-mounted files appear root-owned inside the container.
- **Verified matching tracker:** https://github.com/microsoft/vscode-remote-release/issues/4646 is currently open and was created on 2021-03-10. Its reproduction describes the same root-owned workspace bind mounts and permission failures with containerUser or remoteUser. Maintainer analysis at https://github.com/microsoft/vscode-remote-release/issues/4646#issuecomment-814148749 attributes this to Docker's UID translation.
- **Upstream ownership:** https://github.com/moby/moby/issues/41497 is currently open and requests configurable rootless UID mappings so an unprivileged container user can share host-owned bind-mounted files. Upstream classification requires keeping this issue open under the supplied review policy.
- **Report and follow-up evidence:** https://github.com/microsoft/vscode-remote-release/issues/10608 includes the repository sample and confirmation that containerUser and Dockerfile USER changes did not help after rebuilds. Later users report the same symptom on Fedora Silverblue with Docker 28.1.1 and on Arch with the standard Ubuntu dev-container base image; none confirms resolution.
- **Existing settings do not resolve the mapping:** https://code.visualstudio.com/remote/advancedcontainers/add-nonroot-user documents remoteUser, containerUser and automatic UID/GID matching, but does not provide a rootless namespace-remapping solution. Running as root or switching to rootful Docker does not satisfy the requested non-root workflow.
- **Related PR is not a product fix:** https://github.com/paperless-ngx/paperless-ngx/pull/9815 is closed without merging and concerns project-specific dev-container permissions. Its reference to this issue provides no evidence of a shipped Dev Containers fix.
