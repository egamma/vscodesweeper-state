# Issue #554 — Remote Development support for nix shell

[https://github.com/microsoft/vscode-remote-release/issues/554](https://github.com/microsoft/vscode-remote-release/issues/554)

## Summary

Keep the request open and route it to remote-environment ownership, including SSH. The thread's suggested Nix extension was later reported not to work over Remote-SSH, and neither documented capabilities nor the canonical search establish that the full request is already covered.

## Change summary

Support lightweight nix-shell or lorri development environments without requiring Docker, including environment propagation to remote extensions.

## Best solution

The remote-environment owners should establish a supported way for workspace-specific Nix environments to reach language tools and extension processes, including over Remote-SSH. Evaluate native integration or a supported integration hook rather than treating container-based alternatives or terminal-only configuration as equivalent.

## Evidence

- **Requested capability and unresolved workaround:** https://github.com/microsoft/vscode-remote-release/issues/554 requests nix-shell or lorri integration as an alternative to Docker. The reporter welcomed nix-env-selector in 2019, but https://github.com/microsoft/vscode-remote-release/issues/554#issuecomment-1533691675 explicitly reports that workaround no longer functioning over Remote-SSH in 2023; there is no subsequent resolution confirmation.
- **Existing-capability check:** https://code.visualstudio.com/docs/remote/ssh documents remote extension execution and reopening SSH-hosted folders in containers, not a Nix environment mode. https://containers.dev/implementors/json_reference/ documents remoteEnv and userEnvProbe for container environments; these do not deliver the requested container-free Nix integration.
- **Third-party integration is not confirmed coverage:** https://github.com/arrterian/nix-env-selector documents selecting shell.nix or flake.nix environments, but its supported-platform list names macOS, Linux, and Windows with Remote-WSL, not an assurance of Remote-SSH support. This does not resolve the thread's explicit SSH limitation.
- **Related environment precedent:** In https://github.com/microsoft/vscode-remote-release/issues/4881#issuecomment-819752027 a maintainer describes probing the default shell's environment. That establishes environment inheritance, not workspace-specific Nix activation. Both https://github.com/microsoft/vscode-remote-release/issues/4881 and https://github.com/microsoft/vscode-remote-release/issues/4246 closed for missing information, not a confirmed implementation or a scope decision.
