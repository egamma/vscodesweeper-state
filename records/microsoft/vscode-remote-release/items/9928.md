# Issue #9928 — Opening / connecting to existing tunnels from my extension

[https://github.com/microsoft/vscode-remote-release/issues/9928](https://github.com/microsoft/vscode-remote-release/issues/9928)

## Summary

Keep open for the Remote - Tunnels team to establish a supported way for extensions to connect to a known tunnel without repeating provider and tunnel selection. Existing CLI and URI guidance offers related capabilities but does not establish coverage of this command-argument workflow.

## Change summary

Allow an extension to connect the current window to a known tunnel using its tunnel ID and authentication provider without redundant selection prompts.

## Best solution

The tunnels component should document supported connection arguments if they already exist, or provide an extension-callable connection entry point accepting the known tunnel and provider while preserving required authentication.
