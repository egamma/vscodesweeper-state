# Issue #9928 — Opening / connecting to existing tunnels from my extension

[https://github.com/microsoft/vscode-remote-release/issues/9928](https://github.com/microsoft/vscode-remote-release/issues/9928)

## Summary

A real API gap remains: current documentation supports interactive tunnel selection or opening a vscode.dev URL, but does not document a tunnel identifier argument for connecting the current window. The request is already correctly routed to the tunnels backlog.

## Change summary

Allow extensions to connect the current VS Code window to a known, authorized tunnel without repeating the provider and tunnel-selection prompts.

## Best solution

The Remote - Tunnels extension should expose a documented command argument or extension API accepting a tunnel identifier and authentication provider while retaining access checks, allowing extension-authored environment explorers to connect the current window directly.
