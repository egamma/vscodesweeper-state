# Issue #11505 — # in SSH Host Alias Breaks Service Worker URL Matching

[https://github.com/microsoft/vscode-remote-release/issues/11505](https://github.com/microsoft/vscode-remote-release/issues/11505)

## Summary

Already fixed in VS Code core: the cited commit removed the service-worker URL comparison and controller-change wait responsible for the second-open blank webview. The fix first appears in VS Code 1.118.0, so no Remote-SSH change remains.

## Change summary

Webviews become blank after their first opening when the Remote-SSH host alias contains a `#` character.

## Best solution

Keep the shipped VS Code core service-worker initialization fix; Remote-SSH can continue accepting the alias because webview startup no longer depends on matching the fragment-truncated URL.
