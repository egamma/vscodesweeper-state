# Issue #11509 — Attach to running container fails due to missing ldconfig cache

[https://github.com/microsoft/vscode-remote-release/issues/11509](https://github.com/microsoft/vscode-remote-release/issues/11509)

## Summary

The supplied log and an independent confirmation establish a current attach failure when the VS Code Server requirements check encounters a glibc installation without `/etc/ld.so.cache`. This should remain open and be routed to the code-server owner rather than treated as missing information.

## Change summary

Attaching Dev Containers to a running Debian-based container fails because the VS Code Server requirements check assumes an existing ldconfig cache.

## Best solution

The VS Code Server requirements check should tolerate a missing ldconfig cache by using a non-mutating library-discovery fallback or reporting the prerequisite clearly. Dev Containers should not blindly modify a running container's system linker cache during attachment.
