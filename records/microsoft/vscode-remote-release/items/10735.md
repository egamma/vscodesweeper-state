## Summary

Keep open: a team member provided exact reproduction steps and a screenshot showing the Dev Containers warning despite Workspace Trust being disabled. The issue is already correctly routed, and no canonical duplicate or confirmed resolution was found.

## Change summary

Suppress the first-time arbitrary-code warning when attaching to a container if Workspace Trust is globally disabled.

## Best solution

The Dev Containers extension should align its first-attach warning with `security.workspace.trust.enabled`, while retaining the warning when Workspace Trust is enabled. The containers owner should confirm the behavior on the current release before deciding whether a separate automation-safe control is necessary.
