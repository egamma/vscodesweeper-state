[https://github.com/microsoft/vscode-remote-release/issues/7834](https://github.com/microsoft/vscode-remote-release/issues/7834)

## Summary

The older, open WSL request tracks sourcing the profile when launching the server, not only terminal configuration. Consolidate this report there, preserving its ESP-IDF and extension-host environment example.

## Change summary

Have the WSL server inherit shell-startup environment variables so extension-launched CMake and other toolchains receive PATH and toolchain configuration.

## Best solution

Track the server-startup environment decision in https://github.com/microsoft/vscode-remote-release/issues/6096, including this report's ESP-IDF/CMake example. The WSL owner should determine how to provide profile inheritance without letting misconfigured shell scripts break server startup.
