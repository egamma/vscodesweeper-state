# Issue #7834 — No files (.profile/.bashrc/.bash_profile) sourced by the vscode-server process

[https://github.com/microsoft/vscode-remote-release/issues/7834](https://github.com/microsoft/vscode-remote-release/issues/7834)

## Summary

The documented WSL behavior intentionally skips shell startup files to avoid running shell-specific initialization. The supported `server-env-setup` script provides the requested extension-host environment customization.

## Change summary

Automatically source a user shell profile when starting VS Code Server in WSL so extensions inherit toolchain variables.

## Best solution

Keep startup independent of interactive shell configuration and use `~/.vscode-server/server-env-setup` to export variables or source the ESP-IDF environment script before the WSL server starts.

- **Fit:** aligned
- **Reason:** Making remote toolchains available to extensions advances the stated goal of a local-quality development experience, although the documented setup script is the intended mechanism.
- **Evidence:** The WSL documentation says the extension provides a “local-quality development experience” and documents an environment setup script for server-side customization.

- **Proposed comment:**

  > Thanks for the detailed context. WSL intentionally does not run `.profile`, `.bashrc`, or other shell startup files when starting VS Code Server because those files can contain shell-specific initialization. The supported mechanism is `~/.vscode-server/server-env-setup`, documented at https://code.visualstudio.com/docs/remote/wsl#_advanced-environment-setup-script. That Bourne-shell script can export the required variables or source the ESP-IDF environment script before the server and remote extensions start.
