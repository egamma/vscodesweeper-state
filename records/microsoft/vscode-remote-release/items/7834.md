[https://github.com/microsoft/vscode-remote-release/issues/7834](https://github.com/microsoft/vscode-remote-release/issues/7834)

## Summary

Keep this accepted WSL feature request open: the documented server environment setup hook supports explicit configuration, but does not automatically load the user's login-shell environment. Its Backlog milestone bars an as-designed decline without a later maintainer decision.

## Change summary

Initialize the WSL server and extension-host environment from shell startup files so tools such as ESP-IDF and NVM receive their environment variables.

## Best solution

The WSL owner should decide whether to provide opt-in login-shell environment initialization while preserving reliable server startup. Document server-env-setup as the existing explicit alternative, including its Bourne-shell compatibility requirement.

  > Thanks for the context. WSL intentionally starts the server without running shell startup files. The documented alternative is `~/.vscode-server/server-env-setup` (`~/.vscode-server-insiders/server-env-setup` for Insiders), processed before server startup: https://code.visualstudio.com/docs/remote/wsl#_advanced-environment-setup-script. It must be a valid Bourne shell script, so Bash-specific toolchain initialization needs care. This provides explicit environment configuration, but leaves the request for automatic login-shell initialization open.
