# Issue #11216 — "shutdownAction": "stopContainer" does not respect setting "Execute in WSL"

[https://github.com/microsoft/vscode-remote-release/issues/11216](https://github.com/microsoft/vscode-remote-release/issues/11216)

## Summary

Keep open with the containers owner: shutdown attempts to find Docker on Windows despite Execute in WSL being enabled. The July 2026 confirmation supports the report, but does not identify current versions; the existing steps and logs suffice for a maintainer retest.

## Change summary

Closing VS Code leaves a dev container running because shutdownAction: stopContainer does not execute Docker through the configured WSL environment.

## Best solution

The Dev Containers shutdown monitor should honor the same WSL execution setting and distribution used successfully during container creation, stopping the container without requiring Docker on Windows.
