# Issue #11216 — "shutdownAction": "stopContainer" does not respect setting "Execute in WSL"

[https://github.com/microsoft/vscode-remote-release/issues/11216](https://github.com/microsoft/vscode-remote-release/issues/11216)

## Summary

Verified duplicate: the open canonical issue tracks the shutdown monitor invoking Docker in the wrong execution environment, including the same missing-host-Docker failure with Execute in WSL enabled.

## Change summary

The Dev Containers shutdown monitor ignores Execute in WSL and fails to stop the container because it invokes Docker on Windows.

## Best solution

Consolidate the shutdown-monitor fix under https://github.com/microsoft/vscode-remote-release/issues/6056, ensuring shutdown commands use the same WSL execution context as container creation.
