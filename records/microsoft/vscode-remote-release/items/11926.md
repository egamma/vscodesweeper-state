# Issue #11926 — [Remote-SSH] Reconnect gives up after one attempt during a brief network outage on Windows ("Unknown error" treated as permanent)

[https://github.com/microsoft/vscode-remote-release/issues/11926](https://github.com/microsoft/vscode-remote-release/issues/11926)

## Summary

Keep open for Remote - SSH: the supplied versions, disconnect/reconnect steps, and logs suffice to retest the premature permanent failure. No confirmed fix exists in the reviewed evidence, and the related reports fail through different paths.

## Change summary

Remote - SSH stops reconnecting after a transient Windows SSH connect failure instead of retrying when connectivity returns.

## Best solution

The SSH component should identify transient connect-phase failures as retryable during reconnection while preserving permanent authentication errors. Verify the Windows 'Unknown error' and empty-output cases independently of managed-socket failures.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode-remote-release/issues/11926 supplies VS Code 1.143.1, Remote-SSH 0.128.0, Windows and remote OS details, Wi-Fi disconnect/reconnect steps, and a resolver log ending in 'Unknown error' followed by failed remote-port parsing. The reporter observed two outages across five windows; there is no independent confirmation.
- **Retry classification contrast:** https://github.com/microsoft/vscode-remote-release/issues/11926 reports that 'Connection timed out' permits 23+ retries and recovery, whereas 'Unknown error' stops retries. ConnectionAttempts 200 with ConnectTimeout 3 reportedly restores reconnection to the same extension host; this is a workaround, not demonstrated product resolution.
- **Upstream contributor, not complete ownership:** https://github.com/PowerShell/Win32-OpenSSH/issues/2482 is open and describes the Winsock errno-mapping problem behind 'Unknown error'. Correcting that message does not establish coverage of this report's separate empty-output/BadInstallScriptResult variant or the requested Remote-SSH retry handling.
- **Related but distinct failures:** https://github.com/microsoft/vscode-remote-release/issues/11805 is open but reports a managed socket rejecting with 'Connection closed', including failures after authority resolution succeeds. This report instead fails while classifying SSH process output; fixing the managed-socket rejection alone would not establish that this resolver failure is fixed. https://github.com/microsoft/vscode-remote-release/issues/11941 is also open but involves a workspace transition stopping the local extension host and producing 'Cannot resolve authority', not a network outage.
- **Troubleshooting guidance:** https://github.com/microsoft/vscode-remote-release/wiki/Remote-SSH-Troubleshooting documents comparing remote.SSH.useLocalServer modes and disabling remote.SSH.useExecServer to isolate connection paths. Those comparisons could help diagnosis, but the existing report already provides a concrete retest procedure; neither setting is documented there as resolving this failure.
