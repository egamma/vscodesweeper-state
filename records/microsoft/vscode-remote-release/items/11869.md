# Issue #11869 — postStartCommand silently skipped when git-credential-sharing copy fails, and dev.containers.copyGitConfig=false doesn't suppress the attempt

[https://github.com/microsoft/vscode-remote-release/issues/11869](https://github.com/microsoft/vscode-remote-release/issues/11869)

## Summary

Keep open for the Dev Containers owner: the settings complaint was withdrawn, but failed gitconfig copying reportedly skips both postStartCommand and postAttachCommand. The September configuration, logs, and controlled comparison suffice to retest; no later fix or current-release independent confirmation is established.

## Change summary

A failed host gitconfig copy silently prevents subsequent container lifecycle hooks from running.

## Best solution

Dev Containers should isolate optional Git configuration sharing failures from subsequent lifecycle hooks and visibly report the copy failure. Retest the supplied read-only mount scenario; disabling copying in host User settings is a workaround, not resolution of the lifecycle defect.
