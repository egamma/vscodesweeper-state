# Issue #8808 — dev container issue: Is it possible to set "fetch control manifest" as optional ?

[https://github.com/microsoft/vscode-remote-release/issues/8808](https://github.com/microsoft/vscode-remote-release/issues/8808)

## Summary

Keep open: the August 2026 comments still report long control-manifest waits, and the maintainer supported adding a VS Code setting. The available workarounds do not deliver that capability, and no verified open canonical owns the same request.

## Change summary

Allow Dev Containers users in air-gapped environments to avoid waiting for control-manifest downloads whenever they reopen or rebuild a container.

## Best solution

The Dev Containers owner should provide a supported offline manifest policy, coordinated with the reference CLI, that avoids repeated network waits while making the consequences of stale or unavailable disallow-list data explicit. Keep this focused extension request distinct from broader air-gap support.
