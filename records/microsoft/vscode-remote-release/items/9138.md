# Issue #9138 — If /tmp/devcontainercli-$USER does not exist, devcontainer fails to start

[https://github.com/microsoft/vscode-remote-release/issues/9138](https://github.com/microsoft/vscode-remote-release/issues/9138)

## Summary

Keep open as a confirmed Dev Containers bug: generated Docker Compose configuration retains references to ephemeral `/tmp/devcontainercli-$USER` build artifacts, causing startup to fail after those artifacts disappear.

## Change summary

Docker Compose-based dev containers with features fail to restart after reboot or removal of the Dev Containers CLI temporary directory.

## Best solution

Dev Containers should regenerate the feature build configuration when its temporary artifacts are missing, or store every artifact referenced by the persistent Compose overlay in a durable location.
