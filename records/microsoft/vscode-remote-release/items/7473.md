# Issue #7473 — Bootstrap Code Server Directly from Internet in Dev Containers over SSH

[https://github.com/microsoft/vscode-remote-release/issues/7473](https://github.com/microsoft/vscode-remote-release/issues/7473)

## Summary

Keep open: documented Dev Containers behavior still transfers the server from the local machine, leaving the slow-upload problem unresolved. The related fallback request only activates when local downloading fails, not when transferring a successful download is slow.

## Change summary

Allow Dev Containers over SSH to download the matching VS Code Server remotely or preinstall it without transferring the archive over the client's slow connection.

## Best solution

The Dev Containers component should provide a supported remote-first server installation option that avoids local archive transfer even when local downloading succeeds. Coordinate with https://github.com/microsoft/vscode-remote-release/issues/9414 while preserving this slow-transfer requirement.

- **Fit:** aligned
- **Reason:** Avoiding large server transfers over a slow client connection advances remote-development performance and server-lifecycle reliability.

## Evidence

- **Existing capability check:** https://code.visualstudio.com/docs/remote/faq#_what-are-the-connectivity-requirements-for-vs-code-server explicitly says Dev Containers always downloads locally and transfers into the container. remote.SSH.localServerDownload controls Remote - SSH, not the subsequent Dev Containers installation.
- **Project-designated tracking issue:** In https://github.com/microsoft/vscode-remote-release/issues/9871#issuecomment-2145110894, another user reports slow dd-to-tar server transfer on poor internet. The maintainer explicitly directs that same symptom to this issue in https://github.com/microsoft/vscode-remote-release/issues/9871#issuecomment-2147055413.
- **Related fallback is narrower:** https://github.com/microsoft/vscode-remote-release/issues/9414 is open in Backlog. Its maintainer-defined scope is downloading from the VM when local downloading fails, stated in https://github.com/microsoft/vscode-remote-release/issues/9414#issuecomment-1907560517. Successful local downloading followed by slow upload would not trigger that fallback.
- **Workaround does not deliver the requested option:** https://github.com/microsoft/vscode-remote-release/issues/9414#issuecomment-1907560517 describes manually extracting the commit-specific server into the VM's vscode volume; https://github.com/microsoft/vscode-remote-release/issues/9414#issuecomment-1908763218 confirms that workaround works. It does not provide automatic remote-first installation or a supported build-time commit argument.
