# Issue #2019 — Unable to connect to container with ssh unless SSH key is in a running SSH agent

[https://github.com/microsoft/vscode-remote-release/issues/2019](https://github.com/microsoft/vscode-remote-release/issues/2019)

## Summary

Keep open as an upstream dependency limitation. Documentation now explains that remote Docker over SSH requires the key in a running local agent, but the underlying docker-modem SSH configuration gap remains open.

## Change summary

Allow Dev Containers to connect to a remote Docker host using configured SSH keys without requiring those keys to be loaded into ssh-agent.

## Best solution

The containers connection path should eventually honor the same SSH configuration and key authentication as the Docker CLI, either through an upstream docker-modem fix or a compatible dependency path. Until then, retain the documented ssh-agent requirement and SSH-tunnel fallback.
