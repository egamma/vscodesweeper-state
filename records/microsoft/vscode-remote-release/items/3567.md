# Issue #3567 — User home directory variable (Containers)

[https://github.com/microsoft/vscode-remote-release/issues/3567](https://github.com/microsoft/vscode-remote-release/issues/3567)

## Summary

Keep open: the documented home-directory workaround still assumes HOME and USERPROFILE are mutually exclusive, leaving the reported Git Bash case uncovered. Related requests do not establish a canonical for this specific gap.

## Change summary

Provide a platform-aware local home-directory variable in devcontainer.json that works even when both HOME and USERPROFILE are set.

## Best solution

The Dev Containers component should support a platform-native home-directory substitution consistently in remoteEnv and mounts, coordinating its definition with the Dev Container spec. Preserve this issue's explicit both-variables-set requirement when coordinating related configuration work.

## Evidence

- **Specific unmet requirement:** https://github.com/microsoft/vscode-remote-release/issues/3567 describes launching VS Code through Git Bash on Windows with both HOME and USERPROFILE set, producing a concatenated invalid path. The requested variable must select the platform-native home rather than concatenate environment values.
- **Existing-capability check:** https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson lists environment and workspace substitutions, but no localUserHome variable, and still recommends ${localEnv:HOME}${localEnv:USERPROFILE}. Environment-variable defaults address unset values, not platform selection when both values exist.
- **Current product documentation:** https://code.visualstudio.com/remote/advancedcontainers/add-local-file-mount still documents the same HOME/USERPROFILE concatenation for portable home mounts. Docker Compose's separate tilde example does not supply the requested devcontainer.json variable for remoteEnv and mounts.
- **Related request is not a verified canonical:** https://github.com/microsoft/vscode-remote-release/issues/10945 is open in Backlog and requests cross-platform home-based mounts. Its reported symptom is needing to switch USERPROFILE to HOME across operating systems, not concatenation when both are set; https://github.com/microsoft/vscode-remote-release/issues/10945#issuecomment-2871275705 explicitly offers concatenation assuming one variable is empty. It therefore does not meet the same-observable-symptom duplicate bar for this re-reviewed issue.
