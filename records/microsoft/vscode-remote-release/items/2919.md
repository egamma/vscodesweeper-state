# Issue #2919 —  the node program high memory usage with Remote wsl

[https://github.com/microsoft/vscode-remote-release/issues/2919](https://github.com/microsoft/vscode-remote-release/issues/2919)

## Summary

The historical reports confirm substantial memory pressure, but they mix VS Code Server processes, extensions, workspace indexing, and WSL memory reclamation without a current-version reproduction or process command line. Current diagnostics are needed to isolate the responsible component.

## Change summary

A `.vscode-server` Node.js process grows to multiple gigabytes during extended Remote WSL sessions, eventually degrading or destabilizing the environment.

## Best solution

The WSL component owner should identify which server child process grows and determine whether the memory belongs to the extension host, a language service, file watching, or the Remote WSL server itself. A current reproduction with process command lines, extension bisect results, and the WSL log would make that investigation actionable.
