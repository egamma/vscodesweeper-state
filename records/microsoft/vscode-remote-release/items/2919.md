# Issue #2919 —  the node program high memory usage with Remote wsl

[https://github.com/microsoft/vscode-remote-release/issues/2919](https://github.com/microsoft/vscode-remote-release/issues/2919)

## Summary

Keep open for WSL performance investigation: multiple users corroborate excessive remote Node memory consumption, but no verified fix or canonical owns the full report. Extension-disabling workarounds resolve individual cases, not the original Chromium-workspace report; current-release persistence remains unconfirmed.

## Change summary

Opening a Chromium workspace in Remote - WSL causes a .vscode-server Node process to grow beyond 2 GB over time.

## Best solution

The WSL owner should distinguish server/file-watcher growth from extension-host consumption using per-process RSS and command lines while reopening the Chromium workspace. Resolve any server-side growth in its owning component, and separate extension-specific or WSL VM-reclamation cases only when attribution is established.
