# Issue #6364 — Auto-install recommended extensions

[https://github.com/microsoft/vscode-remote-release/issues/6364](https://github.com/microsoft/vscode-remote-release/issues/6364)

## Summary

Keep open: documented extension installation still requires an explicit devcontainer.json list, which does not deliver automatic reuse of workspace recommendations. The older decoupling request is related but does not explicitly own this recommendation-import behavior.

## Change summary

Allow dev containers to automatically install extensions from .vscode/extensions.json without duplicating their IDs in devcontainer.json.

## Best solution

Dev Containers should offer an opt-in way to reuse workspace recommendations for automatic installation, with exclusions for optional extensions. Coordinate with the related extension-list decoupling request while preserving this specific product requirement.

## Evidence

- **Existing capability boundary:** https://containers.dev/supporting#visual-studio-code documents customizations.vscode.extensions as an array of extension IDs to install when the container is created, supported by both Dev Containers and Codespaces. This supplies explicit installation, not a documented import of workspace recommendations.
- **Recommendations remain suggestions:** https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_workspace-recommended-extensions documents .vscode/extensions.json recommendations and an installation prompt. Its command-line section defines --list-extensions as listing installed extensions; @recommended is an Extensions-view filter, not a documented CLI recommendation-import mechanism.
- **Thread scope:** https://github.com/microsoft/vscode-remote-release/issues/6364#issuecomment-1749288667 requests separation between automatic installation and optional recommendations. https://github.com/microsoft/vscode-remote-release/issues/6364#issuecomment-1942683436 proposes recommendation import with exclusions. The earlier redundant-prompt report and IPC error are additional concerns, not confirmations that the central feature shipped.
- **Older related request:** https://github.com/microsoft/vscode-remote-release/issues/5422 is open, predates this issue, and is in Backlog. Its full body and comments request a separate, potentially gitignored per-user extension file; they do not request automatic consumption of .vscode/extensions.json recommendations. It therefore does not establish the same observable problem required for a duplicate close of this re-reviewed item.
- **Candidate issues differ:** https://github.com/microsoft/vscode-remote-release/issues/11675 and https://github.com/microsoft/vscode-remote-release/issues/11912 are open but concern failed installation of extensions already declared in devcontainer.json. Resolving those regressions would not deliver automatic reuse of workspace recommendations.
