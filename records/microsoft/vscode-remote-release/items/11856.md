Its full body describes Managed versus WebSocket authority resolution, remote SVG requests failing with net::ERR_FAILED, invisible clickable icons, and the identical useExecServer=false workaround.
- **Full symptom coverage:** https://github.com/microsoft/vscode-remote-release/issues/11839#issuecomment-5595400738 explicitly extends the canonical to editor/title icons, including claude-logo.svg and blossom-white.svg. https://github.com/microsoft/vscode/issues/334144#issuecomment-5519385479 independently documents the same failure for the bundled markdown-language-features/media/preview-dark.svg asset, so the built-in example here does not establish a separate defect.
- **Verified underlying fix:** The merged https://github.com/microsoft/vscode/pull/335241 removes the empty-referrer rejection from the managed-resource handler in src/vs/code/electron-main/app.ts and dispatches legitimate window-authority requests through createManagedRemoteResourceRequestHandler. It also replaces invalid string error bodies with Buffers. This directly addresses the reported managed-path resource rejection; useExecServer=false bypasses that path.
- **Release and resolution:** https://github.com/microsoft/vscode/issues/334144#issuecomment-5619375771 announces the fix for VS Code 1.138. The canonical reporter confirms icons work with useExecServer=true on 1.138 at https://github.com/microsoft/vscode-remote-release/issues/11839#issuecomment-5719129293, followed by another confirmation at https://github.com/microsoft/vscode-remote-release/issues/11839#issuecomment-5720068493. These are related-thread confirmations, not a retest by this reporter.
- **Tentative ancillary diagnostic:** https://github.com/microsoft/vscode-remote-release/issues/11856 explicitly presents the webview toUrl exception as possibly separate, not an established second root cause. Consolidation should preserve that observation without claiming the managed-resource fix resolves it.
