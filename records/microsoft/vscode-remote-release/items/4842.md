# Issue #4842 — Support updated env file format

[https://github.com/microsoft/vscode-remote-release/issues/4842](https://github.com/microsoft/vscode-remote-release/issues/4842)

## Summary

Keep open: documented project-name settings do not establish support for export-prefixed assignments in .env files, and no verified canonical owns this syntax-compatibility request.

## Change summary

Support Docker Compose-compatible .env syntax, including export-prefixed, quoted assignments, when determining the Compose project name.

## Best solution

The Dev Containers component should interpret export COMPOSE_PROJECT_NAME='foo' consistently with Docker Compose when constructing its project-name argument. Retest the supplied example on the current extension before deciding whether implementation work remains.

- **Upstream syntax support:** The reporter cites https://github.com/docker/compose/pull/7150, the merged change delegating .env processing to python-dotenv, and https://github.com/docker/compose/releases/tag/1.26.0. This supports the compatibility request, not proof that Dev Containers implemented it.
- **Existing-capability check:** https://code.visualstudio.com/remote/advancedcontainers/set-docker-compose-project-name documents Compose name, process-level COMPOSE_PROJECT_NAME, and plain COMPOSE_PROJECT_NAME=foo in .env. - **Why the observed override matters:** https://docs.docker.com/compose/how-tos/project-name/ states that the project-name command-line flag takes precedence over COMPOSE_PROJECT_NAME. Thus the reported explicit directory-derived argument can override the intended .env value.
