[https://github.com/microsoft/vscode-remote-release/issues/11879](https://github.com/microsoft/vscode-remote-release/issues/11879)

## Summary

The process counts and forwarding logs substantiate serious resource exhaustion, but the reproduction section only explains how to inspect the leak, not what triggers it. Request the session configuration and triggering workflow before treating this as a duplicate of the Docker reports.

## Change summary

Dev Containers proxy processes accumulate under Podman until the container exhausts its PID/thread limit and cannot start commands.

## Best solution

The containers owner should establish which Podman exec sessions leave stale proxies and ensure their lifetime remains bounded without terminating active connections. Compare a reproducible Podman case with the existing Docker relay-lifecycle reports before consolidating.
