## Summary

This was fixed by the absolute-path normalization added for coverage results and shipped in 2025.6.0, so the issue can be closed as completed.

## Change summary

Coverage configured with relative_files reports relative Windows paths that cannot open files or display gutter coverage.

## Best solution

Keep the shipped normalization from commit cd714bf25cde196854d7e78e8e0c20be54edaf55, which converts relative coverage filenames to absolute paths before sending them to VS Code.
