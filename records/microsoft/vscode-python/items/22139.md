# Issue #22139 — Support fully integrated IPython terminal

[https://github.com/microsoft/vscode-python/issues/22139](https://github.com/microsoft/vscode-python/issues/22139)

## Summary

Keep open: existing REPL commands and configurable launch arguments do not deliver the requested persistent IPython session with integrated whole-script execution. The request has 26 upvotes and is already accepted for proposal work; the verified older related issues do not cover its full scope.

## Change summary

Provide a persistent integrated IPython terminal that runs scripts through %run and leaves their variables available for subsequent interactive work.

## Best solution

Develop a proposal for an opt-in IPython terminal workflow covering session startup, whole-script execution, and subsequent interaction with the retained namespace. Coordinate selection execution with https://github.com/microsoft/vscode-python/issues/17172 while preserving ordinary script execution and the Native REPL as separate supported workflows.

## Plan brief

- **Likely files:** `package.json`, `src/client/providers/replProvider.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/terminals/codeExecution/codeExecutionManager.ts`, `src/client/envExt/api.internal.ts`, `src/test/terminals/codeExecution/terminalCodeExec.unit.test.ts`, `src/test/terminals/codeExecution/codeExecutionManager.unit.test.ts`
- **Validation:** After the session contract is agreed, open a workspace with IPython installed, run a script assigning a variable, inspect and modify that variable in the same terminal, run another script, and verify that the session remains usable with IPython magic commands. Exercise selection execution in that session and verify that default non-interactive Run Python File and Native REPL behavior remain unchanged; add terminal-provider and execution-manager tests for the agreed command and session behavior.
- **Behavior:**

  > The requested workflow provides an integrated terminal-based IPython session, runs whole scripts through %run in that session, and leaves script variables available for inspection and subsequent interactive commands. Repeated script runs and code selections should work within the chosen session lifecycle, including IPython magic commands. Acceptance must distinguish this workflow from ordinary non-interactive script execution and from the editor-based Native REPL. The reporter also asks for the session to open alongside the IDE; when that occurs requires an explicit product contract.
- **Trace:**

  > At checkout commit 918ddc05b64a5767ccc465834bc82c16d17fe1ae, ReplProvider.commandHandler starts the standard terminal provider, whose initializeRepl retains session state for selection execution. TerminalCodeExecutionProvider.getExecutableInfo supports interpreter launch arguments, but executeFile sends a fresh interpreter-and-file command rather than an IPython %run command. CodeExecutionManager additionally delegates whole-file execution to the Python Environments extension through executeUsingExtension, so that boundary must be included in the design. The Native REPL uses a separate PythonServer/notebook-controller path and is not an IPython terminal implementation. https://github.com/microsoft/vscode-python/issues/17172 covers related selection-execution behavior, not the full session lifecycle requested here. Preserve default script execution, Django shell behavior, and Native REPL behavior; the debugging/startup-script scenario in the comments is a separate scope question, not established acceptance for the original request.
- **Open decisions:**
  - Should opting into IPython change the existing Run Python File command to execute through %run in the persistent session, or expose a separate interactive-script command while keeping Run Python File non-interactive?
  - Should the opted-in session start automatically when a Python workspace opens, as requested, or start only when an interactive command is invoked?
  - What session and namespace lifecycle should users observe across repeated script runs and interpreter changes, including whether existing interactive variables are visible to the next script?

## Evidence

- **Accepted request and community demand:** The supplied context for https://github.com/microsoft/vscode-python/issues/22139 records needs proposal, community ask, and 26 opening-body upvotes. The complete Issue-Management policy at https://github.com/microsoft/vscode-python/wiki/Issue-Management identifies needs proposal as accepted feature work requiring design discussion; lack-of-traction closure does not apply.
- **Existing capability is partial:** package.json declares python.startREPL, python.startNativeREPL, python.execInREPL, python.terminal.launchArgs, and python.REPL.sendToNativeREPL. In src/client/providers/replProvider.ts, python.startREPL calls TerminalCodeExecutionProvider.initializeRepl. In src/client/terminals/codeExecution/terminalCodeExecution.ts, getExecutableInfo appends launchArgs to the selected interpreter, allowing a configuration such as -m IPython, but executeFile sends an interpreter command with the script path rather than %run into an existing IPython session.
- **Environment-extension execution path:** src/client/terminals/codeExecution/codeExecutionManager.ts:executeUsingExtension constructs arguments from python.terminal.launchArgs and the file path, then calls runInTerminal or runInDedicatedTerminal. This path also does not implement whole-script execution through %run in a persistent IPython namespace.
- **Native REPL is not equivalent:** src/client/repl/replCommands.ts routes python.execInREPL to either terminal selection execution or NativeRepl.sendToNativeRepl. src/client/repl/nativeRepl.ts creates a PythonServer and notebook controller with a variable provider. This supplies some requested interactive features, but not the terminal-based IPython workflow, magic commands, and persistent %run integration described by the reporter.
- **Verified related issue, not a canonical duplicate:** https://github.com/microsoft/vscode-python/issues/17172 is open and was created on 2021-08-31. Its concrete report concerns Shift+Enter copying code into IPython without executing it; comments discuss launchArgs and terminal-input workarounds. It does not own automatic session startup and whole-script %run execution with retained variables. It therefore fails both full-scope ownership and the same-observable-symptom requirement for this re-reviewed item.
- **Canonical search:** Open-issue searches for IPython and persistent REPL also surfaced https://github.com/microsoft/vscode-python/issues/15770 and https://github.com/microsoft/vscode-python/issues/18177. Their bodies respectively discuss separate terminals/arguments/launch configuration and possible programmatic REPL integration; neither defines the full requested IPython session workflow. The inspected cross-reference timeline for this issue contains only the related issue https://github.com/microsoft/vscode-python/issues/17172, not a linked implementation PR.
- **Maintainer direction:** The supplied December 2024 and January 2025 maintainer comments solicit specific IPython requirements and explicitly retain both terminal and Native REPL experiences. They describe Native REPL as an alternative, not an implementation or rejection of this request.
