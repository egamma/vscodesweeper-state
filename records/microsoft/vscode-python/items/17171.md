# Issue #17171 — Support setting environmental variables for the test runner

[https://github.com/microsoft/vscode-python/issues/17171](https://github.com/microsoft/vscode-python/issues/17171)

## Summary

Keep this accepted, team-authored request open: current testing adapters consume python.envFile, but do not expose test-specific environment configurations, and reliable DYLD_LIBRARY_PATH propagation has not been established. The newer configuration proposal is related design work, not a verified duplicate or delivered fix.

## Change summary

Allow users to configure environment variables for Test Explorer discovery and execution, including DYLD_LIBRARY_PATH on macOS.

## Best solution

Deliver test-specific environment configuration through the testing configuration work, while explicitly checking that DYLD_LIBRARY_PATH reaches the selected Python process on macOS. Retain this report's discovery and native-library requirements as acceptance criteria rather than treating generic env-file support as complete coverage.

## Plan brief

- **Likely files:** `package.json`, `src/client/common/variables/environmentVariablesProvider.ts`, `src/client/testing/testController/controller.ts`, `src/client/testing/testController/pytest/pytestDiscoveryAdapter.ts`, `src/client/testing/testController/pytest/pytestExecutionAdapter.ts`, `src/client/testing/testController/unittest/testDiscoveryAdapter.ts`, `src/client/testing/testController/unittest/testExecutionAdapter.ts`, `src/client/testing/common/debugLauncher.ts`, `src/client/common/process/pythonExecutionFactory.ts`
- **Validation:** On macOS, launch VS Code without DYLD_LIBRARY_PATH inherited from its parent, configure that variable through the agreed testing surface, and use a sample test module that asserts its value during import and test execution. Discover and run the sample from Test Explorer with both pytest and unittest, exercising legacy and environments-extension launch paths; include a native-library import requiring the configured directory. Verify test-specific values do not affect ordinary non-test execution and that existing python.envFile behavior remains compatible.
- **Behavior:**

  > Users must be able to supply environment variables to Test Explorer discovery and non-debug execution without launching VS Code from a specially configured shell. The original macOS case requires DYLD_LIBRARY_PATH to reach Python early enough for native-library loading. Acceptance should cover both pytest and unittest, and distinguish successful ordinary-variable configuration from successful DYLD propagation. Existing shared env-file and test-debugging workflows must remain compatible.
- **Trace:**

  > package.json declares python.envFile but no test-specific env configuration; EnvironmentVariablesProvider reads the shared file and merges inherited variables. PytestDiscoveryAdapter, PytestExecutionAdapter, and the unittest adapters obtain those variables and pass them to either the execution factory or runInBackground from the environments integration. The legacy PythonProcessService forwards execution options to ProcessService, whose raw execObservable uses child_process.spawn; this alone does not establish behavior across restricted macOS executables or environment-manager wrappers. DebugLauncher separately uses launch configuration and envFile settings. https://github.com/microsoft/vscode-python/issues/21845 contains evolving configuration designs, and https://github.com/microsoft/vscode-python/issues/23777 records prototype work and unresolved contracts. The uncertainty begins at the public configuration contract and actual macOS launch behavior; do not assume an additional env-file setting fixes DYLD sanitization or expand this work into unrelated remote path mappings.
- **Open decisions:**
  - Should test-specific environments be configured as one workspace-level override or as named configurations selectable separately for discovery and execution?
  - What precedence should apply between inherited variables, python.envFile, test-specific configuration, and existing test-debug launch settings?
