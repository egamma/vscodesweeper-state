# Issue #18871 — Consider removing extensions to prototypes of base types in favor of custom functions

[https://github.com/microsoft/vscode-python/issues/18871](https://github.com/microsoft/vscode-python/issues/18871)

## Summary

The cleanup remains necessary on current main: the extension still modifies both String.prototype and Promise.prototype. This is accepted work carrying needs PR, and no open implementation PR or broader canonical issue supersedes it.

## Change summary

Replace extensions of built-in JavaScript prototypes with ordinary utility functions to prevent collisions with other extensions sharing the extension host.

## Best solution

Move the remaining helpers in src/client/common/extensions.ts to named utility functions, migrate their call sites and tests, and remove the global String and Promise prototype modifications. Preserve the existing command-argument quoting, quote trimming, formatting, and ignored-error behavior during the migration.
