The maintainer diagnosis at https://github.com/microsoft/vscode-python-environments/issues/1830#issuecomment-5880065550 explicitly explains that the wait can repeat when reusing an existing terminal, covering this report's subsequent-run symptom.
- **Windows corroboration:** https://github.com/microsoft/vscode-python-environments/issues/1830#issuecomment-5958613456 independently reports delayed Run Python File execution with PowerShell and Command Prompt, with immediate execution after uninstalling Python Environments. This supports consolidation rather than treating the Windows report as a separate defect.
- **Current core-to-sibling execution path:** src/client/terminals/codeExecution/codeExecutionManager.ts routes the Run Python File commands through executeUsingExtension when useEnvExtension() is true. src/client/envExt/api.internal.ts then delegates runInTerminal to the Python Environments API. The likely malfunction therefore belongs to the sibling execution implementation, not a demonstrated defect in the core extension.
- **Concrete regression lead, not a fixing commit:** The merged https://github.com/microsoft/vscode-python-environments/pull/1741 adds an await waitForShellIntegration(terminal) before command dispatch whenever terminal.shellIntegration is absent in src/features/terminal/runInTerminal.ts. The canonical discussion identifies this added wait as the suspected regression; this is evidence for shared ownership, not proof of a completed fix.
