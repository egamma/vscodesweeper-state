# Issue #25629 — User scoped python.defaultInterpreterPath is constantly overwritten

[https://github.com/microsoft/vscode-python/issues/25629](https://github.com/microsoft/vscode-python/issues/25629)

## Summary

Keep open: the reporter confirmed that an unusable UV-managed interpreter triggers an unrequested fallback while the UI continues to present the broken interpreter as selected. The broader setting-write audit tracks part of the problem, but this report also contains a distinct diagnostics and state-consistency gap.

## Change summary

A broken selected interpreter silently falls back to the system Python, overwrites the user-scoped defaultInterpreterPath, and leaves the displayed interpreter state inconsistent with the interpreter actually used.

## Best solution

Coordinate the unsolicited setting-write fix with https://github.com/microsoft/vscode-python/issues/25735, while ensuring interpreter execution failures produce actionable logs or an error notification and never leave the status bar, Python extension, and Python Environments extension reporting conflicting active environments.

## Evidence

- **confirmed trigger:** The reporter manually executed the UV-managed interpreter, confirmed that it was corrupted, and observed the extension using Python 3.9 globally while the status bar continued to show the selected Python 3.11.5 environment.
- **runtime evidence:** The issue log records the selected environment changing from /usr/bin/python3 to backend/.venv/bin/python, followed by two exit-code-137 failures while running printEnvVariables.py; the user setting was then rewritten to /usr/bin/python3.
- **maintainer-confirmed related gap:** https://github.com/microsoft/vscode-python/issues/25735 is open with needs spike; a maintainer explicitly states that the setting should not change without the user asking and that the Python extension should not control it when the Python Environments extension is installed.
- **current source:** src/client/common/interpreterPathService.ts still writes global defaultInterpreterPath through InterpreterPathService.update(), and src/client/interpreter/virtualEnvs/activatedEnvLaunch.ts can invoke that write automatically with trigger 'load'.
- **diagnostics gap:** src/client/common/process/pythonEnvironment.ts logs a failed interpreter-information lookup and returns undefined, while src/client/pythonEnvironments/base/info/interpreter.ts likewise returns undefined after parse failure; neither path shown provides a user-facing failure state that reconciles the displayed and effective interpreter.
