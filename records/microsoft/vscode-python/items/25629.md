# Issue #25629 — User scoped python.defaultInterpreterPath is constantly overwritten

[https://github.com/microsoft/vscode-python/issues/25629](https://github.com/microsoft/vscode-python/issues/25629)

## Summary

Keep open: the reporter identified a broken uv-managed executable, but that does not explain away the overwritten user setting or misleading interpreter status. Interpreter resolution now includes environment-extension delegation and cached results; the supplied reload steps and logs suffice to retest, but no current-source fix for this combined behavior was established.

## Change summary

An unusable configured interpreter reportedly causes the user-scoped defaultInterpreterPath to be replaced with system Python while the status bar continues showing the original interpreter.

## Best solution

Preserve the configured default during failed interpreter resolution and make interpreter failures and any effective fallback visible and consistent with the status bar. Investigate the core setting-write and diagnostic paths alongside Python Environments integration before deciding which extension owns each remaining defect.

Healthy interpreter selection and explicit user-initiated selection must retain their existing behavior.
