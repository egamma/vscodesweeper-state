# Issue #25872 — PyTest exits when subprocess finishes execution when ran through Testing UI

[https://github.com/microsoft/vscode-python/issues/25872](https://github.com/microsoft/vscode-python/issues/25872)

## Summary

The older, open debugger report describes the same Testing UI failure: a child process exits and the parent pytest debug run ends before executing the remaining statements. Consolidate there, preserving this report's Python 3.9 subprocess.Popen reproduction and session trace.

## Change summary

Debugging a pytest test that waits for a Python subprocess prematurely ends the test run when the child exits.

## Best solution

Follow https://github.com/microsoft/vscode-python-debugger/issues/981 for the shared child-session lifecycle defect, including the Python extension's inherited test-session marker handling. Preserve subprocess debugging while allowing the parent test to continue and publish its actual result.

## Evidence

- **Verified older canonical with the same observable symptom:** https://github.com/microsoft/vscode-python-debugger/issues/981 is OPEN and was created on 2026-03-18, before this report on 2026-03-19. Its reproduction uses Testing UI -> Debug Test, waits for a child process, and observes premature termination before the next print/assert. Subsequent comments report the same remaining behavior after an attempted debugger change.
- **Reporter trace identifies the child as the terminating test session:** https://github.com/microsoft/vscode-python/issues/25872#issuecomment-4091814840 shows the parent test session starting, then Subprocess 6868 starting, and that child's termination immediately followed by result-pipe cancellation and test-run finalization. The supplied Python 3.9 subprocess.Popen sample never reaches 'App exited' or assert False.
- **Current source retains the session-identity defect:** src/client/testing/common/debugLauncher.ts:91-118 assigns __vscodeTestSessionMarker to the launch configuration and replaces ourSession whenever a started session carries that marker, without checking parentSession or retaining the original root session. A child inheriting the marker therefore replaces the parent; child termination resolves launchDebugger and invokes the completion callback. src/client/testing/testController/pytest/pytestExecutionAdapter.ts:177-184 supplies a callback that calls serverCancel.cancel().
- **Inheritance connects both reproductions to the same root cause:** https://github.com/microsoft/debugpy/blob/main/src/debugpy/adapter/clients.py, Client.notify_of_subprocess, copies self.start_request.arguments into the child configuration and does not remove __vscodeTestSessionMarker. https://github.com/microsoft/vscode-python-debugger/blob/main/src/extension/debugger/hooks/childProcessAttachService.ts copies that configuration and supplies parentSession; its removal of purpose does not remove the Python extension's marker. Both subprocess.Popen and multiprocessing children enter this shared lifecycle path.
- **Drainage change is not a fix for root-session tracking:** https://github.com/microsoft/vscode-python/pull/25981 merged commit af9755717d0bc039ed0d792fef90cc9ccbdc5ffb changes result-pipe drainage and timeout handling, not DebugLauncher session ownership. It does not establish that the parent test continues after child termination.
