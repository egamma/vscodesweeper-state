# Issue #25872 — PyTest exits when subprocess finishes execution when ran through Testing UI

[https://github.com/microsoft/vscode-python/issues/25872](https://github.com/microsoft/vscode-python/issues/25872)

## Summary

Still present on current main: the test debug launcher mistakes an inherited child debug session for the root test session, so terminating the subprocess completes the test run prematurely. Route this confirmed regression to testing and debugging.

## Change summary

Debugging a pytest test ends the Testing UI run when a Python subprocess launched by that test exits.

## Best solution

Keep the root test debug session as the lifecycle owner in `src/client/testing/common/debugLauncher.ts`; child sessions inheriting the test marker must not replace it or trigger the completion callback when they terminate.

  > Fix the premature completion of pytest debug runs when a debugged test launches a subprocess. In `src/client/testing/common/debugLauncher.ts`, `DebugLauncher.launchDebugger` currently overwrites `ourSession` whenever any started session carries `__vscodeTestSessionMarker`; debugpy child sessions inherit that marker, so the child replaces the root session and its termination invokes the completion callback. Preserve the initially captured root test session and ignore later child sessions for lifecycle completion, without changing concurrent test-run isolation or normal cancellation behavior. Add a regression test in `src/test/testing/common/debugLauncher.unit.test.ts` that starts the marked root session, starts a child session with the same inherited marker, terminates the child, and proves the launch promise remains pending until the root terminates. ## Evidence

- **source-reproduced lifecycle bug:** `src/client/testing/common/debugLauncher.ts` assigns `ourSession` whenever a started session carries the test marker, without checking whether the root session was already captured. A debugpy subprocess inherits that marker and therefore replaces the root session; its termination then satisfies `session.id === ourSession.id` and invokes the test-completion callback.
- **matching trace:** https://github.com/microsoft/vscode-python/issues/25872#issuecomment-4091814840 records the root `Debug Tests` session starting, then `Subprocess 6868` starting and terminating, immediately followed by cancellation of the result pipe and completion of all project executions. Those events match the current source path exactly.
