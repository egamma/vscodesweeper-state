# Issue #25872 — PyTest exits when subprocess finishes execution when ran through Testing UI

[https://github.com/microsoft/vscode-python/issues/25872](https://github.com/microsoft/vscode-python/issues/25872)

## Summary

Still present on main: a debugged subprocess inherits the test-session marker and can replace the tracked parent session, causing the test run to end when that subprocess terminates. Route this confirmed regression to the testing area.

## Change summary

Debugging a pytest test that launches a subprocess cancels the entire test run when the subprocess exits.

## Best solution

In src/client/testing/common/debugLauncher.ts, retain the first matching root test session rather than replacing it with inherited subprocess sessions, and complete the run only when that root session terminates. Add coverage for a child session inheriting the marker.

## Evidence

- **reporter trace:** The trace shows the parent test session starting, then subprocess session 6868 starting and terminating; at that exact termination timestamp the result pipe is cancelled and the test execution completes.
- **source trace:** src/client/testing/common/debugLauncher.ts assigns __vscodeTestSessionMarker to the launch configuration, but onDidStartDebugSession overwrites ourSession for every session carrying that marker. A subprocess inheriting the configuration can therefore become ourSession, and its termination invokes the completion callback.
- **open workstream:** https://github.com/microsoft/vscode-python/issues/25978 explicitly retains https://github.com/microsoft/vscode-python/issues/25872 as open work requiring end-to-end verification of the debug/subprocess scenario after the result-pipe drainage change.
- **related merged change:** https://github.com/microsoft/vscode-python/pull/25981 improved result-pipe drainage, but it did not change the debug-session selection logic responsible for treating the child subprocess as the tracked test session.
