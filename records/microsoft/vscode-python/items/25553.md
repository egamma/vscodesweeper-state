# Issue #25553 — Pytest discovery hangs in Remote SSH

[https://github.com/microsoft/vscode-python/issues/25553](https://github.com/microsoft/vscode-python/issues/25553)

## Summary

The remote-only discovery hang remains actionable and is traceable to the Unix discovery-pipe setup on current main. The issue is already routed to testing and should remain open while the team confirms why FIFO creation fails or stalls in this Remote SSH environment.

## Change summary

Pytest discovery remains indefinitely in progress over Remote SSH even though the same project collects successfully locally and from the pytest command line.

## Best solution

Make Unix discovery-pipe creation fail promptly on every unsuccessful `mkfifo` outcome and determine whether Remote SSH needs a fallback from `XDG_RUNTIME_DIR` to a usable temporary directory. Reproduce against the reporter's remote layout and add coverage for nonzero or stalled FIFO creation before changing the fallback behavior.

- **unsettled failure path:** In `src/client/common/pipes/namedPipes.ts`, `mkfifo()` resolves only for exit code 0 and rejects only on the child-process `error` event; a normal nonzero exit leaves its promise pending forever, which in turn leaves `WorkspaceTestAdapter.discovering` set and produces the reported `Test discovery already in progress` message.
