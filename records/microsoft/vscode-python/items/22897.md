# Issue #22897 — No python formatter installed - Local new setup or Github codespace with python extension + formatter installed

[https://github.com/microsoft/vscode-python/issues/22897](https://github.com/microsoft/vscode-python/issues/22897)

## Summary

A real onboarding gap remains after formatting moved to dedicated extensions: obsolete formatter settings are not migrated and users can install the Python extension again instead of a formatter. The maintainer explicitly accepted this issue to track migration/default-setting improvements.

## Change summary

Migrate incompatible formatter settings and provide a low-friction path to selecting an installed Python formatter.

## Best solution

Keep formatters in their dedicated extensions, but route this to the formatting area to design migration of obsolete `ms-python.python` formatter selections and coordinate improved formatter discovery with VS Code or Marketplace where necessary.

## Vision fit

- **Fit:** aligned
- **Reason:** Smoothing migration and integration with dedicated formatter extensions supports the family-of-extensions architecture without restoring built-in formatting.
- **Evidence:** The roadmap emphasizes extensibility and a family architecture built around per-tool extensions, while the tools migration deliberately moved formatters out of the core Python extension.
