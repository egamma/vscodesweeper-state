# Issue #26033 — Starting with v2026.2.0 `unittest` test discovery does not work for custom `--start-directory` (aka `-s`) in `python.testing.unittestArgs`

[https://github.com/microsoft/vscode-python/issues/26033](https://github.com/microsoft/vscode-python/issues/26033)

## Summary

The regression remains on current main: project-based testing replaces unittest's configured top-level directory with the workspace root, making a custom non-package start directory unimportable. Route this confirmed bug to the testing area.

## Change summary

Restore unittest discovery with a custom --start-directory when that directory is not importable from the workspace root.

## Best solution

Keep PROJECT_ROOT_PATH for project identity and test-tree placement, but do not pass it to unittest as an implicit --top-level-directory; preserve the user's -t value, or unittest's default of using the start directory. Add coverage for project mode with a nested non-package -s directory.
