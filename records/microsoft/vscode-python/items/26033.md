# Issue #26033 — Starting with v2026.2.0 `unittest` test discovery does not work for custom `--start-directory` (aka `-s`) in `python.testing.unittestArgs`

[https://github.com/microsoft/vscode-python/issues/26033](https://github.com/microsoft/vscode-python/issues/26033)

## Summary

Confirmed regression in project-based unittest discovery: current main replaces the configured top-level directory with the project root, making custom non-package start directories unimportable. Route this to the testing area for correction.

## Change summary

Custom unittest --start-directory discovery fails after project-based testing began forcing the workspace project root as --top-level-directory.

## Best solution

Keep PROJECT_ROOT_PATH for payload and test-tree rooting without passing it unconditionally to unittest.TestLoader.discover as top_level_dir. Add coverage for a custom start directory that is not importable from the project root.
