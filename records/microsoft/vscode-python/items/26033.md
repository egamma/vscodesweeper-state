# Issue #26033 — Starting with v2026.2.0 `unittest` test discovery does not work for custom `--start-directory` (aka `-s`) in `python.testing.unittestArgs`

[https://github.com/microsoft/vscode-python/issues/26033](https://github.com/microsoft/vscode-python/issues/26033)

## Summary

Confirmed regression still present on current main: project-based testing overrides unittest's configured top-level directory, causing discovery from a non-package subdirectory to fail. Route this to the testing area for a targeted fix.

## Change summary

Custom unittest discovery start directories stopped working when project-based testing began forcing the workspace root as `top_level_dir`.

## Best solution

Preserve the configured unittest `--top-level-directory`, or unittest's default derived from `--start-directory`, while using the project root only for payload and test-tree organization. Add a project-mode regression test using a non-package custom start directory.
