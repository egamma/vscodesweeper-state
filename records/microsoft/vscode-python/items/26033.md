# Issue #26033 — Starting with v2026.2.0 `unittest` test discovery does not work for custom `--start-directory` (aka `-s`) in `python.testing.unittestArgs`

[https://github.com/microsoft/vscode-python/issues/26033](https://github.com/microsoft/vscode-python/issues/26033)

## Summary

The discovery regression remains in current main: project-based testing unconditionally replaces unittest's import root with the project directory. The report supplies sufficient steps and diagnostics; classify it as a bug and route it to the testing area.

## Change summary

Unittest discovery should support custom start directories and honor explicit top-level-directory arguments without imposing additional package-import requirements.

## Best solution

Restore unittest-compatible discovery semantics while preserving project-scoped result reporting and ensuring discovered tests remain executable. Keep the related debug-execution report separate because it describes a different observable failure.

## Evidence

- **Current failing source path:** In python_files/unittestadapter/discovery.py, the __main__ branch unconditionally assigns top_level_dir = project_root_path when PROJECT_ROOT_PATH is set. discover_tests then passes that value to unittest.TestLoader.discover(start_dir, pattern, top_level_dir). For the reported non-package subdir/, this changes the importability requirement and produces the reported ImportError.
- **Reporter configuration reaches the override:** src/client/testing/testController/unittest/testDiscoveryAdapter.ts reads settings.testing.unittestArgs and sets mutableEnv.PROJECT_ROOT_PATH = project.projectUri.fsPath whenever a project is supplied, before either subprocess execution path. This matches the report's project-based discovery logs.
- **Argument contract:** python_files/unittestadapter/pvsc_utils.py:parse_unittest_args accepts both --start-directory/-s and --top-level-directory/-t, defaulting the latter to None so unittest uses the start directory. The discovery entrypoint overrides both that default and an explicitly supplied -t.
- **Existing coverage misses the entrypoint:** python_files/tests/unittestadapter/test_discovery.py already covers differing start and top-level directories through test_complex_tree and project-root payload behavior through test_project_root_path_with_different_cwd_and_start_dir. These call discover_tests directly and therefore bypass the environment-variable override in __main__. The same file demonstrates subprocess discovery testing through helpers.runner_with_cwd_env.
- **Related execution boundary:** python_files/unittestadapter/execution.py:run_tests derives cwd from project_root_path or start_dir and then assigns start_dir = cwd before rediscovery. Discovery changes must preserve executable test identifiers and avoid substituting project presentation metadata for the user's collection scope.
