# Issue #26065 — Activating environment takes a few seconds

[https://github.com/microsoft/vscode-python/issues/26065](https://github.com/microsoft/vscode-python/issues/26065)

## Summary

The reported delay and run-before-activation race are credible, but current main delegates terminal activation and execution readiness to the installed Python Environments extension. Keep this open for a maintainer to transfer to that sibling tracker rather than closing it from routing evidence alone.

## Change summary

Venv activation takes several seconds, allowing terminal commands and Run Python File execution to start before the selected environment is ready.

## Best solution

A maintainer should transfer this to https://github.com/microsoft/vscode-python-environments, where terminal activation timing and the createTerminal/runInTerminal readiness contract are implemented. The fix should make activation prompt and ensure execution APIs do not return until command-based activation has completed.

## Evidence

- **delegated activation:** src/client/common/terminal/activator/index.ts returns without running legacy activation when shouldEnvExtHandleActivation() is true; src/client/envExt/api.internal.ts identifies ms-python.vscode-python-envs as the owning extension.
- **delegated execution:** src/client/terminals/codeExecution/codeExecutionManager.ts awaits runInTerminal(), which forwards directly to envExtApi.runInTerminal() in src/client/envExt/api.internal.ts; readiness before script execution is therefore controlled by the sibling API implementation.
- **same-component precedent:** https://github.com/microsoft/vscode-python-environments/issues/997 reported the same roughly five-second command-activation delay and was handled in the Python Environments tracker, but it is closed and therefore cannot serve as a duplicate canonical.
- **readiness contract precedent:** https://github.com/microsoft/vscode-python-environments/issues/1078 documented that createTerminal returned before command activation completed, causing Run Python File races; it is closed, while this July 2026 report indicates equivalent behavior has recurred.
- **current report:** The reporter supplied a repeatable macOS venv scenario using Python Environments 1.36.0 and confirmed that Run Python File starts with the global interpreter before delayed activation completes; disabling terminal.integrated.initialHint only hides the indicator and does not remove the delay.
