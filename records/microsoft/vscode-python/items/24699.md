# Issue #24699 — Reactivating Terminal

[https://github.com/microsoft/vscode-python/issues/24699](https://github.com/microsoft/vscode-python/issues/24699)

## Summary

Keep open: current source still leaves “Reactivating terminals...” displayed when environment-variable activation rejects. This team-authored issue is explicitly used as the tracking home for these reports; the newer environment-extension bypass does not resolve the remaining legacy activation path.

## Change summary

Python activation can leave the terminal-reactivation status displayed indefinitely after an environment-resolution or activation failure.

## Best solution

Retain this issue as the investigation home and ensure terminal-reactivation progress finishes when activation fails, while preserving useful error reporting. Distinguish the stuck indicator from underlying interpreter-resolution failures and investigate both legacy activation and the Python Environments integration boundary.

## Evidence

- **Current source retains the indicator on rejection:** src/client/terminals/envCollectionActivation/service.ts:173–184, TerminalEnvVarCollectionService._applyCollection, shows progress, awaits _applyCollectionImpl, logs and rethrows any rejection, and calls hideProgress only after success. The catch explicitly says the indicator should remain on errors. src/client/common/application/progressService.ts confirms that hideProgress resolves the promise backing the displayed progress.
- **Environment-resolution failure reaches that path:** src/client/interpreter/activation/service.ts, EnvironmentActivationService.getActivatedEnvironmentVariables, awaits getActiveInterpreter before entering its implementation's error handling. _applyCollectionImpl awaits this method, so a rejected interpreter lookup propagates to the progress-retaining catch. This establishes the persistent-status failure path without executing the extension; it does not establish the cause of every reported activation failure or editor freeze.
- **Reporter evidence distinguishes symptom from underlying failures:** Comments dated 2025-01-31 and 2025-02-05 confirm that opting out of pythonTerminalEnvVarActivation stops the status loop without necessarily restoring extension functionality. The 2025-06-25 comment identifies a separate concrete trigger: python.pythonPath pointed to /usr/local/bin/python3, which did not exist on the SSH host; removing that setting restored functionality.
- **Related change is a conditional bypass, not a complete fix:** https://github.com/microsoft/vscode-python/commit/aff035a371ac519a80c398064322c9fa9c52a4f9 adds an early return in activate when useEnvExtension() is true. Its diff does not change _applyCollection's rejection handling, and its message references other issues rather than this one. It therefore does not establish an implemented-on-main close for this team-authored report.
