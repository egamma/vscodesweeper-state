# Issue #18315 — execSelectionInTerminal to run in now active terminal

[https://github.com/microsoft/vscode-python/issues/18315](https://github.com/microsoft/vscode-python/issues/18315)

## Summary

Keep open: selection execution still targets the extension's cached terminal rather than the user's active Python terminal. This accepted request has 14 upvotes, and neither the existing commands nor the related terminal work delivers its central ask.

## Change summary

Allow python.execSelectionInTerminal to execute normalized Python selections in the currently active Python terminal, enabling multiple independent REPL sessions.

## Best solution

Support active-terminal selection execution while retaining Python-aware indentation handling and independent REPL state. Coordinate with the newer same-symptom report at https://github.com/microsoft/vscode-python/issues/24960; this older issue should remain the reference for the requested capability.

## Plan brief

- **Likely files:** `package.json`, `src/client/terminals/codeExecution/codeExecutionManager.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/common/terminal/factory.ts`, `src/client/common/terminal/service.ts`, `src/client/envExt/api.legacy.ts`, `src/test/terminals/codeExecution/terminalCodeExec.unit.test.ts`, `src/test/common/terminals/factory.unit.test.ts`
- **Validation:** Open two Python REPL terminals with different sentinel values, alternate the active terminal, and invoke python.execSelectionInTerminal from the editor; verify each selection executes only in the selected session without restarting it. Repeat with an indented multiline selection, no terminal, and a non-Python active terminal under the agreed fallback contract, with the environments extension enabled and disabled. Add executable unit coverage for destination selection and independent REPL lifecycle state.
- **Behavior:**

  > Users should be able to send Python-aware selections to either of two existing Python REPL terminals by selecting the desired terminal before invoking python.execSelectionInTerminal. Each session must retain its own variables, and multiline normalization must remain available. Acceptance checks should demonstrate destination switching without creating an unwanted terminal or restarting a running REPL. The maintainer must settle whether this behavior is the default or opt-in, and what happens when the active terminal is not a Python REPL.
- **Trace:**

  > CodeExecutionManager.executeSelection() normalizes editor text before calling the standard TerminalCodeExecutionProvider. That provider retrieves a resource-keyed cached service and keeps one replActive promise; TerminalService retains a private terminal and per-service readiness/queue state. The selection path does not consult the active terminal, including when terminal creation delegates through ensureTerminalLegacy() to the environments extension. Preserve normalization, whole-file dedicated-terminal behavior, interpreter selection and activation contracts. Related https://github.com/microsoft/vscode-python/issues/24960 contains a matching report and an approved attempt, but https://github.com/microsoft/vscode-python/pull/25178 closed without merging. The source establishes the gap; no runtime checks were performed in this read-only review.
- **Open decisions:**
  - Should active-Python-terminal targeting replace the default behavior of python.execSelectionInTerminal, or be exposed as an opt-in setting or separate command?
  - When the active terminal is not a Python REPL, should execution start a REPL there or fall back to an extension-managed Python terminal?
