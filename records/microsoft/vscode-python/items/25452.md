# Issue #25452 — Pytest: Debug test uses incomplete python executable path

[https://github.com/microsoft/vscode-python/issues/25452](https://github.com/microsoft/vscode-python/issues/25452)

## Summary

The original incomplete-executable-path failure was fixed, but a confirmed first-run race remains: an integrated debug terminal can launch pytest before conda activation supplies environment variables. The current resolver still assumes that activation has already completed, so this should remain open and route to testing and terminal owners.

## Change summary

Ensure the first pytest debug run in a newly created integrated terminal waits for the selected conda environment to be fully activated before launching.

## Best solution

Coordinate debug-test startup with terminal environment activation, including the Python Environments extension path, or explicitly provide the selected interpreter's activated environment variables instead of assuming a newly opened integrated terminal is ready.

## Evidence

- **confirmed remaining behavior:** The reporter confirmed on the updated stable extensions that the executable path was corrected, but the first integrated-terminal debug run still starts before `conda activate my_test_env`; imports depending on activation-provided PYTHONPATH fail until the terminal is reused.
- **source path:** src/client/debugger/extension/configuration/resolvers/launch.ts only obtains activated environment variables when a custom Python is set or the console is not `integratedTerminal`; for the reported configuration it assumes the terminal already contains the right activated environment.
- **activation race:** src/client/terminals/activation.ts starts environment activation asynchronously from `onDidOpenTerminal`, leaving debug-launch startup able to proceed before `activateEnvironmentInTerminal` completes; it also delegates activation when the Python Environments extension is active.
