# Issue #23893 — Python writes `source .../.venv/bin/activate` to existing terminals

[https://github.com/microsoft/vscode-python/issues/23893](https://github.com/microsoft/vscode-python/issues/23893)

## Summary

The unsafe path remains in current source: extension activation can send an environment activation command into a restored active terminal without checking whether it contains user input. This team-authored bug must remain open because no issue-referencing fix or verified duplicate resolves the legacy path.

## Change summary

Reconnecting to a remote workspace can submit a virtual-environment activation command into an existing terminal, executing previously typed input.

## Best solution

Prevent automatic activation commands from being sent to restored or already-interacted-with terminals in the legacy terminal provider, while retaining explicit activation and new-terminal behavior. The Python Environments extension's shell-startup activation is the preferred long-term path, but the legacy path should remain safe when that extension does not handle activation.
