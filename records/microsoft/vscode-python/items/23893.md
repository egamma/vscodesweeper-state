# Issue #23893 — Python writes `source .../.venv/bin/activate` to existing terminals

[https://github.com/microsoft/vscode-python/issues/23893](https://github.com/microsoft/vscode-python/issues/23893)

## Summary

The unsafe activation path remains on current main: extension initialization can send an activation command into an existing visible terminal without checking for pending input or prior interaction. This team-authored issue must remain open, and the later reports show that related activation hazards also exist at the Python Environments extension boundary.

## Change summary

Prevent automatic environment activation from executing pending input or interrupting work in restored or previously used terminals.

## Best solution

Avoid command injection into restored or interacted-with terminals, using shell-startup activation where possible and otherwise requiring a demonstrably safe terminal state. Coordinate the legacy path in vscode-python with the activation implementation in microsoft/vscode-python-environments.
