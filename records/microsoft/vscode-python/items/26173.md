# Issue #26173 — [Linux] Extension host crashes because POSIX test-result FIFO file descriptor is closed twice

[https://github.com/microsoft/vscode-python/issues/26173](https://github.com/microsoft/vscode-python/issues/26173)

## Summary

The POSIX reader on current main still closes a socket-owned descriptor twice, matching the captured Linux extension-host crash. Keep this open while the two explicitly linked fix PRs are reviewed; neither has merged.

## Change summary

Ensure POSIX test-result FIFO cleanup closes its descriptor exactly once without closing an unrelated resource after descriptor reuse.

## Best solution

Review and land the descriptor-ownership correction in https://github.com/microsoft/vscode-python/pull/26174, coordinating with the broader FIFO lifecycle changes in https://github.com/microsoft/vscode-python/pull/26082. Preserve test-result delivery and cleanup while eliminating the extension-host crash.

## Evidence

- **Current source confirms double ownership:** src/client/common/pipes/namedPipes.ts:191-197 opens the POSIX FIFO, passes its descriptor to new net.Socket({ fd }), and schedules fs.close(fd) in the socket's close handler. The second asynchronous close remains present on current main.
- **Reported trigger and crash mechanism:** https://github.com/microsoft/vscode-python/issues/26173 supplies Linux remote-workspace pytest steps and a strace sequence showing socket/libuv closure of FIFO fd 31, reuse by a child-process socket, a filesystem-worker second close, and epoll_ctl returning EBADF. This directly connects test-pipe cleanup and concurrent descriptor activity to the native extension-host abort.
- **Testing call site:** src/client/testing/testController/common/utils.ts:114-150, startRunResultNamedPipe, generates a python-test-results FIFO and calls createReaderPipe; reader.onClose disposes the result listener. The defective shared POSIX reader is used by the reported testing flow.
- **Open targeted fix:** Verified https://github.com/microsoft/vscode-python/pull/26174 is OPEN, non-draft, and explicitly closes this issue. Its namedPipes.ts diff removes the redundant fs.close(fd) and unused noop import. The author reports isolated real-FIFO regression checks that fail with EBADF on the original implementation and two days without crashes using the patched Linux remote-workspace build; these checks were not independently executed during this review.
- **Open overlapping fix:** Verified https://github.com/microsoft/vscode-python/pull/26082 is OPEN and draft, with an explicit closing reference to this issue. It proposes directly owned nonblocking FIFO reading and single-close disposal alongside EOF, backpressure, and adapter-cleanup changes. Both open implementation candidates prohibit a completed close and a competing agent implementation.
- **Repository triage policy:** Read the complete Issue-Management policy at https://github.com/microsoft/vscode-python/wiki/Issue-Management. Its bug workflow calls for bug and appropriate area classification; the source defect and captured native crash support testing-area ownership rather than treating this as an upstream libuv defect.
