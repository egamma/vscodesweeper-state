# Issue #26267 — Packaging runtime dependencies without shipping the entire node_modules directory

[https://github.com/microsoft/vscode-python/issues/26267](https://github.com/microsoft/vscode-python/issues/26267)

## Summary

The packaging configuration already implements the central request: production webpack bundles and exclusion of the installed node_modules tree. The retained out/client/node_modules directory contains deliberately separated dependency bundles, not the entire dependency installation.

## Change summary

Reduce VSIX overhead by bundling runtime dependencies and excluding unnecessary dependency files while preserving runtime resources.

## Best solution

Keep the existing bundled packaging strategy and explain the distinction between the excluded root node_modules tree and generated dependency bundles under out/client/node_modules.

## Evidence

- **Packaging exclusions:** .vscodeignore excludes node_modules/**, src/**, build/**, out/test/**, python_files/tests/**, typings/**, types/**, source maps and bundle-analysis artifacts. The installed dependency tree is not intentionally shipped wholesale.
- **Production packaging path:** package.json scripts.package runs gulp clean, gulp prePublishBundle and vsce package. gulpfile.js runs the dependency, desktop-extension and browser webpack configurations; .github/actions/build-vsix/action.yml also runs prePublishBundle before packaging the VSIX.
- **Intentional dependency bundles:** build/webpack/common.js explicitly enumerates separated dependencies, including Unicode categories, source-map-support, sudo-prompt, node-stream-zip and xml2js. build/webpack/webpack.extension.dependencies.config.js bundles those entries into out/client/node_modules/[module].js. build/webpack/loaders/externalizeDependencies.js redirects imports to these generated bundles.
- **Documented packaging intent:** build/webpack/webpack.extension.config.js explains that pregenerated modules remain separate because they are large. The dependency webpack configuration documents why a package.json is copied next to the generated node_modules directory for Live Share extension identification. Separate worker entry points preserve the shell-execution and Windows registry worker paths.
- **Inspection limits:** Reviewed source configuration only; no VSIX was generated or inspected and no size reduction was measured. The checkout is shallow, so its boundary commit does not establish when this packaging strategy first shipped.
