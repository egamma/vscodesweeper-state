# Issue #23047 — Custom Test Discovery Option

[https://github.com/microsoft/vscode-python/issues/23047](https://github.com/microsoft/vscode-python/issues/23047)

## Summary

Keep open: the current implementation still performs workspace-wide pytest collection, and the later `needs spike` label records an explicit decision to investigate alternatives. Existing save-pattern filtering reduces refresh frequency but does not provide custom or per-file discovery.

## Change summary

Provide a customizable or incremental test-discovery path so very large pytest suites do not require collecting every test for each refresh.

## Best solution

Spike a design that supports distinct discovery configuration, allowing a pytest plugin to short-circuit collection, and coordinate it with the true per-file discovery work in https://github.com/microsoft/vscode-python/issues/4586. The implementation should retain pytest compatibility while avoiding workspace-wide collection for localized changes.
