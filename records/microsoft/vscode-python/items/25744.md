# Issue #25744 — Venv activation command leaks into stdin when running tasks on Windows

[https://github.com/microsoft/vscode-python/issues/25744](https://github.com/microsoft/vscode-python/issues/25744)

## Summary

The leak is specific to the legacy command-based activation path; the supported Python Environments `shellStartup` path avoids writing activation commands to terminal input, and the reporter confirmed that it resolves the issue.

## Change summary

Prevent virtual-environment activation commands from reaching a task process through stdin.

## Best solution

Use the Python Environments extension's `shellStartup` activation mode so activation is injected during shell startup rather than sent as terminal input; retain the legacy command path only for configurations that explicitly opt out of the environments extension.

- **current source:** src/client/common/terminal/activator/base.ts sends legacy activation commands through `terminal.sendText`, while src/client/common/terminal/activator/index.ts and src/client/envExt/api.internal.ts bypass that legacy activator when the Python Environments extension owns activation.
- **migration guidance:** https://github.com/microsoft/vscode-python/issues/25291 documents `python.useEnvironmentsExtension` and `python-envs.terminal.autoActivationType: shellStartup` as the long-term terminal-activation path.
