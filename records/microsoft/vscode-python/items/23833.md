# Issue #23833 — Python interpreter settings ignored if VS Code is launched from an activated environment

[https://github.com/microsoft/vscode-python/issues/23833](https://github.com/microsoft/vscode-python/issues/23833)

## Summary

The defect remains visible in current source: the legacy path prioritizes an inherited activated environment and writes it into workspace storage before consulting the configured interpreter. The existing environment-area and needs-spike routing is appropriate.

## Change summary

Launching VS Code from an activated environment overrides the interpreter explicitly selected for the workspace, affecting terminals, tools, and test discovery.

## Best solution

Make an explicit persisted workspace selection take precedence over VIRTUAL_ENV or CONDA_PREFIX inherited at launch, and avoid rewriting interpreter storage without a user selection. Coordinate this with the Python Environments extension rollout and the related defaultInterpreterPath audit.
