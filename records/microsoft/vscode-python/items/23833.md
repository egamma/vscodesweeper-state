# Issue #23833 — Python interpreter settings ignored if VS Code is launched from an activated environment

[https://github.com/microsoft/vscode-python/issues/23833](https://github.com/microsoft/vscode-python/issues/23833)

## Summary

The defect remains visible in current main: the legacy interpreter path explicitly replaces the workspace selection with VIRTUAL_ENV or CONDA_PREFIX whenever VS Code is launched through the CLI. The issue is already accepted for investigation under `needs spike` and correctly routed to environments, so it should remain open.

## Change summary

Launching VS Code from an activated environment overrides the interpreter previously selected for the workspace, affecting terminals, tools, and test discovery.

## Best solution

Preserve an explicit persisted workspace interpreter when VS Code inherits an activated environment, using the launch environment only when the workspace has no prior selection. The spike should also define equivalent behavior at the integration boundary with the Python Environments extension before changing the legacy selection path.
