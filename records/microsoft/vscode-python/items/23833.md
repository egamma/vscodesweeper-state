# Issue #23833 — Python interpreter settings ignored if VS Code is launched from an activated environment

[https://github.com/microsoft/vscode-python/issues/23833](https://github.com/microsoft/vscode-python/issues/23833)

## Summary

Keep open: the current legacy interpreter path still selects the launching terminal's activated environment before consulting the saved workspace interpreter, and overwrites that selection. The Python Environments integration provides a separate path, but does not establish that this remaining core-extension behavior is fixed.

## Change summary

Preserve the explicitly selected workspace interpreter when VS Code is reopened from a terminal with a different virtual environment activated.

## Best solution

Honor the saved workspace interpreter throughout interpreter resolution and execution-service creation in the core extension's legacy path. Preserve activated-environment selection for workspaces without an explicit selection, and leave the Python Environments extension's delegated path unchanged.
