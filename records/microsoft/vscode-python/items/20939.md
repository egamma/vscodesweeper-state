# Issue #20939 — Have a PR check for when a proposed API is added but the VS Code engine isn't changed

[https://github.com/microsoft/vscode-python/issues/20939](https://github.com/microsoft/vscode-python/issues/20939)

## Summary

Keep open: this team-authored engineering task remains unimplemented on main and is explicitly staged for a proposal. The prior implementation PR was closed unmerged after its comparison mechanism proved incomplete and the team deprioritized the work.

## Change summary

Add a pull-request check that rejects changes to enabled VS Code proposed APIs unless the minimum VS Code engine version is updated too.

## Best solution

Design a reliable check that compares the pull request's `enabledApiProposals` and `engines.vscode` values against the base revision, then run it from `.github/workflows/pr-file-check.yml`. The proposal should define handling for proposal additions, removals, and engine-version changes without relying on an undeclared `.original` file.
