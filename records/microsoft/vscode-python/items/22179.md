# Issue #22179 — Save before run after re-load does not save before executing

[https://github.com/microsoft/vscode-python/issues/22179](https://github.com/microsoft/vscode-python/issues/22179)

## Summary

Keep open for investigation: a maintainer confirmed the reopen-then-run failure, and subsequent reports describe it persisting through 2026 on Windows and macOS. Current code attempts to save before execution, but that alone does not establish that this lifecycle-dependent failure is fixed.

## Change summary

Running a modified Python file after reopening it can execute the previously saved contents instead of saving the latest edits first.

## Best solution

Make save-before-execution reliable across closing and reopening an editor in the terminal execution flow. First reproduce the reported lifecycle and identify whether document matching, dirty-state detection, or the save operation fails before execution proceeds.

- **Validation:** In a VS Code extension-development session, run a saved Python file that prints a marker, close its editor, reopen it through Recent Files, change the marker without manually saving, and run it again. Verify that the file on disk and terminal output both contain the new marker; repeat across editor reopen cycles and with the Python Environments integration enabled and disabled.
- **Behavior:**

  > Running an existing Python file must save its current edits before executing it, including after the editor is closed and reopened through Recent Files. The reported failure executes older disk contents and can persist until the folder is reopened. Acceptance requires the edited marker to appear both on disk and in terminal output without a manual save, before and after repeated reopen cycles.
- **Trace:**

  > CodeExecutionManager.executeFileInTerminal and executeUsingExtension both await CodeExecutionHelper.saveFileIfDirty before dispatching execution. When no URI is supplied, getFileToExecute also awaits activeEditor.document.save; with a supplied URI, saveFileIfDirty matches workspace documents by uri.path and requires exactly one dirty or untitled match. DocumentManager obtains documents and the active editor directly from VS Code, so an extension-side cached document has not been established as the cause. WorkspaceService.save returns undefined on an exception, and callers then retain the original URI and proceed; whether this occurs in the reported lifecycle remains unknown. The maintainer-confirmed reproduction and later reports are recorded at https://github.com/microsoft/vscode-python/issues/22179, but current-main reproduction was not executed. Preserve clean-file execution, terminal selection and activation, and selection-based execution; investigate the existing-file reopen scenario rather than conflating it with untitled save-dialog cancellation.
