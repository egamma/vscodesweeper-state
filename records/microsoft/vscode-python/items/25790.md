## Evidence

- **Concrete reproduction supplied:** https://github.com/microsoft/vscode-python/issues/25790 supplies print(" ".join(map(str, range(5000)))), Windows build 26100, Python 3.12.7, and a direct-python comparison in the same console. F5 and Ctrl+F5 truncate near 2610 instead of reaching 4999; no comments independently confirm this report.
- **Relevant current source:** src/client/debugger/extension/configuration/resolvers/launch.ts passes the launch configuration through DebugEnvironmentVariablesHelper.getEnvironmentVariables. In src/client/debugger/extension/configuration/resolvers/helper.ts:86-87, that helper defaults PYTHONUNBUFFERED to '1' when unspecified. This establishes a plausible launch-versus-direct-execution difference, not a reproduction of the Windows failure.
- **Upstream diagnosis:** https://github.com/python/cpython/issues/86210 is open. https://github.com/python/cpython/issues/86210#issuecomment-1093887298 documents large Windows console writes truncating under python -u but completing under buffered Python, and identifies unhandled partial writes in _textiowrapper_writeflush.
- **Matching debugger precedent:** https://github.com/microsoft/debugpy/issues/299 reports truncated large output under F5 while direct execution in the same terminal completes. Its investigation also observed truncation without debugging; https://github.com/microsoft/debugpy/issues/299#issuecomment-709327920 attributes the defect to CPython. That issue is closed and therefore is not a duplicate canonical.
- **Separate historical mitigation:** https://github.com/microsoft/vscode-python/issues/21312 was resolved by removing PYTHONUNBUFFERED from a terminal-activation experiment. Its trigger was direct terminal execution after environment activation, unlike this report where direct execution succeeds and terminal activation is disabled; that historical mitigation does not establish a fix here.
- **Canonical and ownership check:** Searches across microsoft/vscode-python, microsoft/vscode-python-debugger, microsoft/debugpy, and microsoft/vscode found no verified older, open canonical for this report's exact symptom. .github/ISSUE_TEMPLATE/config.yml routes debugger issues to https://github.com/microsoft/vscode-python-debugger/issues, and src/client/debugger/pythonDebugger.ts obtains debugpy from ms-python.debugpy. No concrete fixing commit was established.
