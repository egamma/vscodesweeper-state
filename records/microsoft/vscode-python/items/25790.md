# Issue #25790 — printing huge str gets truncated with F5 or ctrl+F5

[https://github.com/microsoft/vscode-python/issues/25790](https://github.com/microsoft/vscode-python/issues/25790)

## Summary

The truncation matches an open CPython Windows console-I/O defect triggered by the extension's unbuffered debug environment. Keep this open as upstream-tracking rather than closing an unresolved dependency issue.

## Change summary

Large single-string output is truncated on Windows when launched through F5 or Ctrl+F5, while direct buffered execution prints it completely.

## Best solution

CPython should complete https://github.com/python/cpython/issues/86210 so unbuffered Windows console writes cannot silently stop after a partial write; until then, the extension can track the impact and point affected users to a buffered launch configuration.

## Evidence

- **current source:** src/client/debugger/extension/configuration/resolvers/helper.ts sets PYTHONUNBUFFERED=1 by default for debug launches, while launch.ts defaults to integratedTerminal.
- **upstream root cause:** https://github.com/python/cpython/issues/86210 remains open and documents that unbuffered Python on Windows can lose the remainder of a partial console write; its reproducer is the same large-output pattern.
- **pending upstream fix:** https://github.com/python/cpython/pull/26678 remains open and proposes writing all bytes to the Windows console in unbuffered mode.
- **prior debugger investigation:** https://github.com/microsoft/debugpy/issues/299 traced the same F5-versus-direct-execution truncation to the CPython defect and documented buffered execution as the workaround.
