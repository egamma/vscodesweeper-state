# Issue #26177 — Starting kernel fails to properly activate conda env

[https://github.com/microsoft/vscode-python/issues/26177](https://github.com/microsoft/vscode-python/issues/26177)

## Summary

Keep open: the report supplies concrete Windows reproduction steps and logs connecting failed activation-variable collection to an unactivated notebook kernel. The newer Pixi activation fix explicitly leaves Conda behavior unchanged; the supplied steps suffice to retest this separate failure.

## Change summary

With Python Environments enabled, Windows Conda notebook kernels launch without required activation paths and crash when loading native libraries.

## Best solution

Make the core Python extension's activated-environment API return the selected Conda environment's complete variables when Python Environments owns discovery, without requiring Anaconda on the global PATH. First reproduce the configured conda.bat case and identify why legacy Conda resolution fails despite the sibling extension discovering valid activation paths.
