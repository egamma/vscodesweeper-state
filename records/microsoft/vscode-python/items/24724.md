# Issue #24724 — Error while collecting test results (Socket communication)

[https://github.com/microsoft/vscode-python/issues/24724](https://github.com/microsoft/vscode-python/issues/24724)

## Summary

The corruption path remains on current main: parallel pytest-xdist workers can independently write chunked JSON-RPC messages to one result pipe, allowing frames to interleave and test results to be lost. The issue is already correctly routed to testing and should remain open.

## Change summary

Parallel pytest-xdist execution intermittently corrupts result-pipe messages, leaving many completed tests unreported in Test Explorer.

## Best solution

Serialize xdist result reporting in python_files/vscode_pytest/__init__.py so workers cannot concurrently frame and write to the shared pipe, potentially by forwarding results through the xdist controller or synchronizing complete messages. Add coverage using multiple workers and messages larger than 4096 bytes.

## Evidence

- **source path:** python_files/vscode_pytest/__init__.py:306-349 sends each test result from pytest_report_teststatus; under xdist this hook executes in worker processes.
- **concurrent framing defect:** python_files/vscode_pytest/__init__.py:1142-1228 gives each process its own writer to the shared TEST_RUN_PIPE and emits each JSON-RPC request through separately flushed 4096-byte writes, with no cross-process serialization.
- **diagnostic evidence:** The report captures malformed JSON and a missing Content-Length header, consistent with interleaved frames, while disabling xdist or using -n1 avoids the failure.
- **maintainer assessment:** A maintainer identified the same likely mechanism: xdist child processes communicating when they should not.
