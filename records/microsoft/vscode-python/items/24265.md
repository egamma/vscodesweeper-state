# Issue #24265 — Unable to identify Python executable from path due to apostrophe

[https://github.com/microsoft/vscode-python/issues/24265](https://github.com/microsoft/vscode-python/issues/24265)

## Summary

The quoting defect remains visible on current main: PowerShell receives an unquoted interpreter path containing an apostrophe. The issue is already routed to the terminal area and marked for an accepted investigation spike, so it should remain open.

## Change summary

Running a Python file fails on Windows when the selected interpreter path contains an apostrophe.

## Best solution

Make terminal command serialization shell-aware in `src/client/common/terminal/helper.ts`, correctly quoting interpreter paths and arguments containing PowerShell metacharacters such as apostrophes, including the `sendText` fallback path.

## Evidence

- **source defect:** `src/client/common/extensions.ts:33-52` quotes command arguments only for spaces, ampersands, or parentheses; `C:/Users/BobO'Ross/.../python.exe` is therefore returned unchanged.
- **failing command path:** `src/client/common/terminal/helper.ts:68-75` prefixes PowerShell commands with `&` but passes the interpreter through the generic quoting helper, producing an unquoted command containing the apostrophe.
- **execution fallback:** `src/client/common/terminal/service.ts:194-200` sends the already-serialized command line through either shell integration or raw `sendText`, so the malformed quoting reaches the shell on current main.
