## Summary

The apostrophe failure remains visible in current source and is a specific case of the verified open shell-specific escaping report. Consolidate it there while preserving the Windows interpreter and script-path example.

## Change summary

Running Python in a Windows terminal fails when interpreter and script paths contain an apostrophe because command construction leaves it unquoted.

## Best solution

Resolve shell-specific executable and argument quoting under https://github.com/microsoft/vscode-python/issues/24126, including this Windows apostrophe case. Shell-type detection alone is insufficient; commands must preserve literal paths through both shell integration and sendText fallback.

## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode-python/issues/24126 is open, predates this report, and supplies concrete reproduction steps for special characters breaking Python terminal execution. Its explicit request is shell-specific quoting and escaping in general, including PowerShell; this apostrophe failure falls within that broader scope rather than a separate environment-discovery defect.
- **Exact failing source path:** src/client/terminals/codeExecution/terminalCodeExecution.ts: executeFile formats the script path and passes the interpreter command and arguments to TerminalService.sendCommand. src/client/common/terminal/helper.ts:68-75, buildCommandForTerminal, adds a PowerShell invocation prefix but applies the same generic string formatter to the executable and arguments.
- **Apostrophe remains unescaped:** src/client/common/extensions.ts:33-52 quotes only paths containing spaces, ampersands, or parentheses; an apostrophe alone receives no quoting or escaping. The supplied interpreter path C:/Users/BobO'Ross/AppData/Local/Programs/Python/Python312/python.exe and script path therefore reach PowerShell with literal string delimiters embedded in otherwise unquoted tokens, explaining the removed apostrophes and combined command text.
- **Both execution transports retain the defect:** src/client/common/terminal/service.ts: sendCommand builds one command string before executeCommandInternal passes it to either shellIntegration.executeCommand(commandLine) or terminal.sendText(commandLine). Neither branch repairs the quoting.
- **Maintainer diagnosis and related API:** https://github.com/microsoft/vscode-python/issues/24265#issuecomment-2400561416 identifies shell escaping as the problem. https://github.com/microsoft/vscode-python/issues/24126#issuecomment-2529028212 accepts the broader escaping work and links https://github.com/microsoft/vscode/issues/230165. That API issue is now closed following API finalization, but current command construction still does not perform shell-specific escaping; API availability is not a fix for this report.
- **Historical reports are not canonical targets:** https://github.com/microsoft/vscode-python/issues/15037 is closed for missing information, and https://github.com/microsoft/vscode-python/issues/4311 concerned debugger-generated commands and was transferred to VS Code. Neither supersedes the verified open Python terminal-escaping report.
