# Issue #26110 — Running a single test imports the whole codebase

[https://github.com/microsoft/vscode-python/issues/26110](https://github.com/microsoft/vscode-python/issues/26110)

## Summary

The performance defect is present on current main: every unittest execution performs full discovery before filtering to the selected test IDs, importing unrelated test modules on each run. This should remain open and route to the testing area.

## Change summary

Running one discovered unittest imports every test module matching the configured discovery pattern, delaying execution when unrelated modules have expensive imports.

## Best solution

Change unittest execution in `python_files/unittestadapter/execution.py` to load only the selected modules or test IDs instead of rediscovering the complete suite, while preserving custom `load_tests` behavior, scenario-generated IDs, and missing-test reporting. Add a regression test proving that running one test does not import an unrelated matching test module.
