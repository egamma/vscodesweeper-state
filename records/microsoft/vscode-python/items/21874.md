# Issue #21874 — Show Notification when Pytest Discovery Fails

[https://github.com/microsoft/vscode-python/issues/21874](https://github.com/microsoft/vscode-python/issues/21874)

## Summary

Keep this accepted, community-supported request open: current discovery errors appear in the Test Explorer and logs, but there is no opt-in failure notification. The remaining product decision is how to make failures noticeable without excessive notifications.

## Change summary

Provide an optional notification when pytest discovery fails, including when some tests are successfully discovered.

## Best solution

Agree on a low-noise notification policy in the testing area, preserving partial discovery and existing error details. Coordinate with https://github.com/microsoft/vscode-python/issues/22154, which lists this request as separate child work rather than replacing it.

- **Behavior:**

  > Users want a noticeable, optional indication that pytest discovery failed, even when partial discovery produced usable tests. The notification should make the failure understandable without requiring users to find an error node at the bottom of the test tree. Existing partial results, error details, and access to logs must remain available. Acceptance should cover enabled and disabled notification behavior, repeated discovery, successful discovery, and cancellation under the agreed policy.
- **Trace:**

  > PythonResultResolver.resolveDiscovery in src/client/testing/testController/common/resultResolver.ts forwards payloads to TestDiscoveryHandler.processDiscovery. In src/client/testing/testController/common/testDiscoveryHandler.ts, error payloads create a logged Test Explorer error node with a python.viewOutput link, while returned tests are still populated; no popup is emitted on this path. WorkspaceTestAdapter.discoverTests in src/client/testing/testController/workspaceTestAdapter.ts separately turns thrown failures into logs and tree nodes. package.json exposes no discovery-error notification setting, and src/client/extensionActivation.ts registers python.viewOutput only as an output-channel command. Preserve partial discovery and the existing quiet experience for users who do not opt in; changing pytest collection or its IPC contract is outside this request. https://github.com/microsoft/vscode-python/issues/22154 aggregates this and other presentation improvements, while https://github.com/microsoft/vscode-python/issues/17000 documents complaints about repeated popups. The source establishes the missing notification surface, but the thread does not settle when repeated or automatic failures should notify.
- **Open decisions:**
  - Should notifications be strictly opt-in, preserving the current default, or enabled by default with a disable option?
  - When enabled, should every failed discovery notify, or should repeated failures and automatic discovery use a quieter policy?
