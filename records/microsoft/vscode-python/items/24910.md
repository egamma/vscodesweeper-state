# Issue #24910 — Pytest inline error reporting

[https://github.com/microsoft/vscode-python/issues/24910](https://github.com/microsoft/vscode-python/issues/24910)

## Summary

A real testing UX gap remains: current main reports pytest discovery failures through an error node linking to the output channel, but does not associate errors with source locations. The issue is already routed to testing, and a maintainer has committed to investigating the proposed structured-output approach.

## Change summary

Surface pytest discovery failures inline at the source location responsible for the collection error.

## Best solution

Investigate a structured way to carry file and line information from pytest collection failures into the discovery payload, then attach that location to the VS Code testing error presentation. JUnit XML should be evaluated carefully because the current discovery argument filtering explicitly removes `--junit-xml` and collection failures may occur before a useful report is produced.
