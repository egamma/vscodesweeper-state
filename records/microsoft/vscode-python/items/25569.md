# Issue #25569 — .env file content isn't autoloaded into a terminal, despite coresponding settings being set.

[https://github.com/microsoft/vscode-python/issues/25569](https://github.com/microsoft/vscode-python/issues/25569)

## Summary

Terminal injection from `python.envFile` is now an opt-in capability of the official Python Environments extension; the report only configured the file path and did not have that extension installed. The reporter also asked for the issue to be closed after choosing a shell-based alternative.

## Change summary

Automatically load variables from the configured `.env` file into newly created integrated terminals.

## Best solution

Keep terminal `.env` injection in the Python Environments extension and retain its explicit opt-in behavior. Users who want it should enable the environments extension and set `python.terminal.useEnvFile` to `true`.

- **Reason:** Terminal environment injection is now owned by the dedicated Python Environments extension rather than the legacy implementation in the core Python extension.
- **Evidence:** The family-of-extensions direction moves environment-management behavior into the Python Environments extension, while vscode-python retains integration plumbing.

  > Thanks for the report and follow-up. `python.envFile` selects the file but no longer enables terminal injection by itself; that behavior is intentionally opt-in through the official Python Environments extension. To use it, install/enable `ms-python.vscode-python-envs`, set `python.useEnvironmentsExtension` to `true`, and set `python.terminal.useEnvFile` to `true`. Since the listed extensions do not include that extension and you have chosen the shell-based alternative, this can be closed as intended configuration.
