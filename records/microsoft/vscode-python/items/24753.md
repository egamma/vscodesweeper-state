# Issue #24753 — Unclear if the native REPL and terminal REPL shares the same session

[https://github.com/microsoft/vscode-python/issues/24753](https://github.com/microsoft/vscode-python/issues/24753)

## Summary

A real REPL UX gap remains: the terminal link opens a separate native REPL process without transferring command history or variables. The issue is already correctly classified and routed to the REPL area, and no canonical request owns this work.

## Change summary

Carry terminal REPL history and variables into the native REPL when it is launched from the terminal link.

## Best solution

Define the supported transition between the two independently hosted REPLs: either implement a feasible state handoff, likely beginning with command history, or make the link explicitly state that it opens a new session. The REPL area should decide which state can be transferred safely across Python processes.
