# Issue #24753 — Unclear if the native REPL and terminal REPL shares the same session

[https://github.com/microsoft/vscode-python/issues/24753](https://github.com/microsoft/vscode-python/issues/24753)

## Summary

A real gap remains: the terminal link starts an independent Native REPL process, so terminal variables and history are not transferred. The request is already correctly classified and routed to the REPL area.

## Change summary

Preserve terminal REPL variables and history when launching the Native REPL from its terminal link.

## Best solution

Use the existing terminal interpreter session when launching the Native REPL, or provide an explicit state-transfer mechanism; if that architecture is infeasible, make the link clearly state that it starts a new session.

- **Fit:** aligned
- **Reason:** A seamless state-preserving transition directly advances the project's durable REPL and run-experience theme.
- **Evidence:** The public roadmap identifies “The REPL and run experience” as a durable investment area, while current priorities include Native REPL reliability.

## Evidence

- **terminal link behavior:** src/client/terminals/pythonStartupLinkProvider.ts handles the terminal link by invoking python.startNativeREPL without passing a terminal or session handle.
- **existing capability:** package.json exposes python.REPL.sendToNativeREPL for routing subsequent editor execution to the Native REPL, but it does not transfer variables or command history from an existing terminal REPL.
