# Issue #21443 — Support viewings `numpy` `.npy` and `.npz` and `pickle` `.pkl` files natively by double clicking on them

[https://github.com/microsoft/vscode-python/issues/21443](https://github.com/microsoft/vscode-python/issues/21443)

## Summary

Keep open for the requested proposal: the team explicitly retained this request after it passed community feedback, and it now has 16 upvotes. Current main exposes no native file-opening viewer for these formats, and no verified open canonical was found.

## Change summary

Open .npy, .npz, and .pkl files directly from the Explorer into a readable data-inspection view.

## Best solution

Develop the proposal the maintainer requested, defining the inspection experience, supported data types, and behavior when Python or NumPy is unavailable, without automatic package installation. Decide whether the viewer belongs in core Python or a dedicated data-viewing extension before implementation.

## Plan brief

- **Likely files:** `package.json`, `src/client/extensionActivation.ts`, `src/client/jupyter/types.ts`
- **Validation:** The plan should define manual acceptance checks using a numeric .npy array, a multi-array .npz archive, and agreed supported .pkl contents: double-click each in the Explorer and verify the chosen inspection experience. Repeat without NumPy installed and with malformed or unsupported files; verify the agreed explanatory behavior and that opening a file does not automatically install packages.
- **Behavior:**

  > Users want to inspect .npy, .npz, and .pkl files by double-clicking them in the Explorer, without first writing a loading script. The finished proposal must specify what is displayed for arrays, archives, and supported pickle objects, including the interaction available in the view. It must define behavior when Python or NumPy is unavailable and when a file cannot be inspected. Automatic package installation is not the intended solution according to the maintainer discussion.
- **Trace:**

  > Current main at 918ddc05b64a5767ccc465834bc82c16d17fe1ae has no relevant custom editor contribution in package.json or registration in src/client/**/*.ts. src/client/extensionActivation.ts registers Python execution and REPL features, but those do not deliver direct binary-file inspection. src/client/jupyter/types.ts declares IDataViewerDataProvider without a file-opening implementation; its presence is not proof of an existing viewer. The maintainer discussion at https://github.com/microsoft/vscode-python/issues/21443 explicitly requires a thorough proposal and leaves the display and dependency contract unresolved. The suggested https://github.com/aplbrain/npyjs is a possible NumPy-format parsing lead, not demonstrated coverage of .npz and .pkl. Preserve existing execution, REPL, and sibling-extension behavior; no automatic installation should be introduced. The older https://github.com/microsoft/vscode-python/issues/17233 and related variable-explorer request https://github.com/microsoft/vscode-jupyter/issues/1148 do not own this accepted request's full scope.
- **Open decisions:**
  - What inspection experience should double-click provide for each format: a textual preview, a tabular viewer, or interactive exploration, and which array dimensions and pickle object types are supported?
  - Should inspection depend on the selected Python environment, and what should users see when Python or NumPy is unavailable, given the maintainer's position against automatic installation?
  - Should this user-facing capability ship in core Python or a dedicated data-viewing extension?
