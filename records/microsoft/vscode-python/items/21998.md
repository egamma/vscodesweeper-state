# Issue #21998 — Try avoid putting run commands into shell history

[https://github.com/microsoft/vscode-python/issues/21998](https://github.com/microsoft/vscode-python/issues/21998)

## Summary

A real gap remains: current main still sends Python run and some activation commands to terminals without a history-suppression mechanism. The request has exceeded the community threshold and now carries `needs proposal`, so it should remain open and also be routed to the terminal area for design.

## Change summary

Avoid recording Python extension-generated run and environment-activation commands in users' shell histories.

## Best solution

Design a shell-aware or VS Code-supported way to suppress history entries for extension-generated commands without changing the behavior of user-entered commands. The Python run and legacy activation paths belong in this extension, while debugger-owned terminal commands may require coordination with VS Code core.

## Evidence

- **accepted design work:** After the issue was reopened on 2023-11-16, a maintainer applied `needs proposal` on 2023-11-17; the issue now has 8 opening-post upvotes, exceeding the documented 7-vote community threshold.
- **current run path:** src/client/terminals/codeExecution/terminalCodeExecution.ts routes file execution through TerminalService.sendCommand, while src/client/common/terminal/service.ts executes the resulting command through shellIntegration.executeCommand or Terminal.sendText without requesting history suppression.
- **current activation path:** src/client/common/terminal/activator/base.ts still sends each legacy environment activation command directly with terminal.sendText(command), with no shell-history handling.
- **partial predecessor:** https://github.com/microsoft/vscode-python/issues/11039 removed unnecessary activation commands through terminal environment APIs, but it was closed before this issue was reopened and does not eliminate the current run-command path.
- **ownership boundary:** https://github.com/microsoft/vscode/issues/85887 concluded that extensions using sendText own their command-history behavior, while the discussion on this issue identifies debugger run-in-terminal handling as VS Code-owned.
- **related workaround:** https://github.com/microsoft/vscode/issues/192943 fixed propagation of terminal-profile environment variables, but remains open and does not provide a general mechanism for keeping Python-generated run commands out of shell history.
