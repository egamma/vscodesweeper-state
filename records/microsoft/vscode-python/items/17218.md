# Issue #17218 — TOC for .py files with percent markup

[https://github.com/microsoft/vscode-python/issues/17218](https://github.com/microsoft/vscode-python/issues/17218)

## Summary

Keep this accepted, community-supported request open for a proposal defining cell-based navigation in .py files. No covering capability or verified open canonical was found; the related Jupyter report was explicitly closed in favor of this issue.

## Change summary

Provide a navigable sidebar table of contents for percent-marked Python cells, including markdown sections and potentially nested section headings.

## Best solution

Agree on a cell-aware sidebar navigation experience that preserves ordinary Python symbol navigation and uses cell boundaries consistent with Jupyter. Coordinate the document-symbol and cell-execution ownership across the Python extension family while retaining this accepted issue as the requirement.

## Plan brief

- **Likely files:** `package.json`, `src/client/activation/languageClientMiddlewareBase.ts`, `src/client/activation/node/manager.ts`
- **Validation:** In an extension-development host, open a .py fixture containing named # %% code cells, a # %% [markdown] section, nested section markers, and ordinary functions/classes. Verify that the agreed sidebar presentation lists the intended headings in order, selecting an entry navigates to its source location, edits update the entries, and ordinary symbol navigation and Jupyter cell execution remain available.
- **Behavior:**

  > Users managing a large percent-marked .py file need sidebar navigation to named cells and markdown sections without converting the file into an .ipynb notebook. Selecting an entry should navigate to the corresponding source section, and editing headings or boundaries should update navigation. The accepted proposal must define how cell headings coexist with ordinary code symbols and whether nested section markers form a hierarchy. Acceptance should cover mixed code/markdown cells and preserve the existing interactive execution workflow.
- **Trace:**

  > package.json declares no cell-outline control or view. LanguageClientMiddlewareBase.provideDocumentSymbols in src/client/activation/languageClientMiddlewareBase.ts delegates document-symbol requests; callNext dispatches to an optional notebook addon or the next handler. NodeLanguageServerManager.startLanguageServer in src/client/activation/node/manager.ts installs NodeLanguageClientMiddleware, whose subclass adds no cell-outline behavior. This establishes the core extension's delegation boundary, not the behavior of every sibling language server or Jupyter component; the planning session must investigate those providers before assigning implementation ownership. https://github.com/microsoft/vscode-jupyter/issues/4496 was explicitly closed in favor of https://github.com/microsoft/vscode-python/issues/17218, so routing the request away without reconciling that decision would lose the accepted requirement. Preserve ordinary Python symbol navigation, cell execution semantics, and existing notebook behavior; notebook conversion and additional execution shortcuts are not prerequisites for the central TOC request.
- **Open decisions:**
  - Should cell headings augment the existing Outline, appear in a selectable cell-only Outline mode, or use a dedicated sidebar TOC?
  - Should the initial public behavior include nested percent-marker sections, and how should markdown headings and ordinary code symbols fit into that hierarchy?
