# Issue #24960 — Run Selection/Line in already active python interpreter terminal rather than opening a new terminal

[https://github.com/microsoft/vscode-python/issues/24960](https://github.com/microsoft/vscode-python/issues/24960)

## Summary

A real capability gap remains on main: Run Selection/Line reuses only its extension-managed REPL and cannot adopt a manually configured terminal. The latest maintainer review explicitly says the goal remains valuable, although the earlier implementation must be rewritten for the queue-based execution architecture.

## Change summary

Allow Run Selection/Line to send code to an already active, manually configured Python terminal instead of creating an extension-managed REPL.

## Best solution

Add an opt-in way for `python.execSelectionInTerminal` to adopt the active Python REPL while preserving the queue and readiness handling in `TerminalService`; implementation should target the current terminal architecture rather than revive the closed PR unchanged.

- **Evidence:** The public roadmap emphasizes terminal activation and the REPL/run experience, while recent releases prioritize queue-based REPL reliability and shell-integration alignment.
