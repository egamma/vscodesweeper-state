# Issue #24960 — Run Selection/Line in already active python interpreter terminal rather than opening a new terminal

The requested capability remains unimplemented, but the older, open terminal-selection request already owns the same work. Consolidate this report there while preserving its SLURM workflow and implementation discussion.

## Change summary

Allow Run Selection/Line to send code to an existing, manually configured Python REPL terminal instead of creating or selecting an extension-managed terminal.

## Best solution

Implement active-terminal selection under https://github.com/microsoft/vscode-python/issues/18315, preserving manually established interpreter sessions and allocated resources. Carry forward this report's SLURM use case and the closed implementation attempts when designing against the current execution architecture.

## Evidence

- **Verified older canonical with the same symptom:** https://github.com/microsoft/vscode-python/issues/18315 is currently OPEN and was created on 2022-01-19, before this report. Its body explicitly requests that python.execSelectionInTerminal use the currently open terminal instead of always targeting the terminal tracked by the extension. Its discussion also describes the command working only with the terminal it created. This matches the reporter-observable symptom and satisfies the stronger duplicate bar for a re-reviewed item.
- **Canonical owns accepted concrete work:** https://github.com/microsoft/vscode-python/issues/18315 is a concrete feature request, not an umbrella or investigation. It carries feature-request, area-terminal, needs proposal, and community ask; a maintainer confirmed community interest and kept it open in https://github.com/microsoft/vscode-python/issues/18315#issuecomment-1084920974.
- **Existing capability does not cover the ask:** package.json contributes python.execSelectionInTerminal, terminal activation settings, and python.REPL.sendToNativeREPL, but no active-terminal reuse setting. In src/client/terminals/codeExecution/codeExecutionManager.ts, executeSelectionInTerminal selects the standard execution service. TerminalCodeExecutionProvider.initializeRepl in src/client/terminals/codeExecution/terminalCodeExecution.ts reuses its tracked replActive session, while src/client/common/terminal/factory.ts caches extension terminal services rather than selecting the user's active terminal. These surfaces do not provide arbitrary manually configured REPL reuse.
- **Implementation attempts were not merged:** https://github.com/microsoft/vscode-python/pull/25158 and https://github.com/microsoft/vscode-python/pull/25178 are both CLOSED with no merge commit. The maintainer explicitly stated that reuse remains valuable and closed the latter because queue-based execution changes required a rewrite, not because the feature was rejected: https://github.com/microsoft/vscode-python/pull/25178#issuecomment-5072463494.
- **Unique evidence and related-item boundaries:** This report adds a manually configured SLURM allocation, a workaround that repurposes an extension-created REPL terminal, and maintainer-supported implementation discussion. Those details specialize the active-terminal request without establishing a separate root cause. https://github.com/microsoft/vscode-python/issues/2997 instead concerns switching between file execution and selection execution in incompatible shell/REPL states; it is not the canonical for this symptom. The closed https://github.com/microsoft/vscode/issues/246133 was explicitly identified by a maintainer as a duplicate of this report.
