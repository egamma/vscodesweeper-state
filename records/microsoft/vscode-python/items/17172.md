# Issue #17172 — Support IPython for Shift+Enter (execute line in terminal)

[https://github.com/microsoft/vscode-python/issues/17172](https://github.com/microsoft/vscode-python/issues/17172)

## Summary

Keep open: reliable Shift+Enter execution in IPython remains an accepted request with substantial community interest. Existing launch arguments and Native REPL do not deliver that capability, and no verified fix or eligible older duplicate supports closing this team-authored issue.

## Change summary

Support executing lines and selections in an IPython terminal with Shift+Enter without additional Enter presses or timing workarounds.

## Best solution

Provide reliable IPython execution through the core terminal selection command while preserving standard Python and Native REPL behavior. Retain this issue as the focused support request; use the newer IPython reports as implementation evidence rather than replacement canonicals.

## Plan brief

- **Likely files:** `src/client/terminals/codeExecution/codeExecutionManager.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/terminals/codeExecution/helper.ts`, `src/client/common/terminal/service.ts`
- **Validation:** With IPython installed and python.REPL.sendToNativeREPL false, configure python.terminal.launchArgs as ["-m", "IPython", "--no-autoindent"]. From a fresh terminal, Shift+Enter x = 5, then a selected multiline function and a call to it; verify execution without an extra Enter press, dropped input, duplicated execution, or indentation errors. Repeat in the existing session, on Windows and Linux, and with default launchArgs to verify standard Python remains unchanged.
- **Behavior:**

  > Shift+Enter should execute a Python line or selection in the configured IPython terminal rather than leaving it pending or requiring a timing macro. Both first submission during terminal startup and subsequent submissions should execute once, including multiline definitions. Standard Python terminal execution and the separate Native REPL option must retain their existing behavior.
- **Trace:**

  > package.json binds Shift+Enter to python.execSelectionInTerminal unless the Native REPL binding applies. CodeExecutionManager.executeSelection obtains and normalizes source through CodeExecutionHelper, then TerminalCodeExecutionProvider.execute initializes the terminal REPL and submits through TerminalService.executeCommand(code, true). Launch arguments can start IPython, but startup detection in terminalCodeExecution.ts looks for three > characters or times out, and queued-command readiness in common/terminal/service.ts recognizes shell 'python' or a >>> prompt rather than explicitly recognizing IPython. The historical paste-without-execution symptom and the newer no-submission symptom may involve different stages; reproduce before assigning one root cause. https://github.com/microsoft/vscode-python/issues/25915 supplies a recent startup failure configuration, while https://github.com/microsoft/vscode-python/issues/18177 is related architectural exploration, not a duplicate. Keep full-script execution, Jupyter workflows, Native REPL, and unrelated Python 3.13 indentation reports outside this focused request.
