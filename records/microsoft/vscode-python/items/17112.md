# Issue #17112 — pytest assertions should generate rich diffs

[https://github.com/microsoft/vscode-python/issues/17112](https://github.com/microsoft/vscode-python/issues/17112)

## Summary

Keep open: current pytest failure reporting still produces text-only messages, not native rich diffs. This team-authored, accepted request has 36 upvotes, and neither a verified canonical duplicate nor an issue-referencing implementation was found.

## Change summary

Display pytest assertion comparisons through VS Code's native expected-versus-actual diff experience.

## Best solution

Develop the accepted testing proposal for carrying pytest comparison data into native TestMessage diffs while retaining readable failure output. Decide the supported assertion scope and expected/actual labeling before implementation.

## Plan brief

- **Likely files:** `python_files/vscode_pytest/__init__.py`, `src/client/testing/testController/common/types.ts`, `src/client/testing/testController/common/testExecutionHandler.ts`, `python_files/tests/pytestadapter/test_execution.py`, `src/test/testing/testController/common/testExecutionHandler.unit.test.ts`
- **Validation:** Add pytest execution fixtures for supported unequal multiline strings and collections, verify complete comparison values in emitted payloads, and extend the TestExecutionHandler unit suite to assert native comparison fields. Manually run those fixtures through Test Explorer and open the native diff; verify failures outside the supported comparison scope retain their existing readable messages.
- **Behavior:**

  > Failed pytest comparisons should expose VS Code's native rich diff rather than only a formatted assertion traceback. For the comparison cases agreed in the proposal, users should see clearly labeled, complete operands even when pytest's textual summary abbreviates the difference. Existing failure messages, test locations, outcomes, and unrelated unittest behavior must remain available and unchanged.
- **Trace:**

  > pytest_report_teststatus in python_files/vscode_pytest/__init__.py currently reduces failed reports to report.longreprtext, and TestOutcome has no operand fields. ExecutionTestPayload in src/client/testing/testController/common/types.ts mirrors that text-only contract. PythonResultResolver.resolveExecution delegates to TestExecutionHandler.handleTestFailure, which creates a plain TestMessage without native comparison fields. These paths establish the missing capability, but this review did not establish a reliable operand-extraction mechanism across pytest versions and custom comparison hooks. Existing test surfaces include python_files/tests/pytestadapter/test_execution.py and src/test/testing/testController/common/testExecutionHandler.unit.test.ts. Preserve pytest's assertion semantics and existing output; syntax highlighting and general output-panel redesign are separate concerns. https://github.com/microsoft/vscode-python/issues/21861 provides related output-design context, not a duplicate or proof of implementation.
- **Open decisions:**
  - Which assertion comparisons should the initial rich-diff contract support: equality comparisons of strings and collections only, or also custom comparison hooks and other operators?
  - How should the native view label the two operands when a plain pytest assertion does not explicitly identify an expected value?
