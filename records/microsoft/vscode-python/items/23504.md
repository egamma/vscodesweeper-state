# Issue #23504 — Broken/Removed virtual environment can not be cleared

[https://github.com/microsoft/vscode-python/issues/23504](https://github.com/microsoft/vscode-python/issues/23504)

## Summary

The stale active-interpreter path can survive cache clearing on current main because clearing discovery caches does not reset the workspace interpreter selection. The existing needs-spike investigation should remain open and include the broader environments area because the report affects both locator implementations.

## Change summary

Deleting the selected virtual environment leaves an invalid interpreter path that Clear Cache and Reload Window does not remove.

## Best solution

Define and implement consistent handling for a selected environment whose executable has disappeared: either invalidate and reselect it during refresh or clearly direct users to the existing Python: Clear Workspace Interpreter Setting command. The shared interpreter-selection and persistence path should own the behavior rather than either locator alone.

## Evidence

- **cache clearing path:** src/client/common/persistentState.ts registers python.clearCacheAndReload to clear extension persistent state and the native locator cache directory, but it does not reset the configured active interpreter.
- **stale selection path:** src/client/interpreter/interpreterService.ts resolveActiveInterpreter() reads the configured pythonPath and passes an absolute path directly to getInterpreterDetails(); a removed selected executable can therefore be resolved again after the reload.
- **separate reset capability:** package.json declares python.clearWorkspaceInterpreter, and src/client/interpreter/configuration/interpreterSelector/commands/resetInterpreter.ts clears the workspace interpreter setting separately from cache clearing, including the Python Environments extension selection.
- **confirmed scope:** The report includes the failing executable invocation and states that the behavior occurred with both the JavaScript and native finders; the issue is already labeled bug and needs spike.
- **canonical search:** The open candidate https://github.com/microsoft/vscode-python/issues/24364 concerns stale discovery after an operating-system Python upgrade and additional Jupyter behavior; it does not own this report's narrower deleted-active-environment cleanup behavior.
