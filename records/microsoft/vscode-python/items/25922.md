## Plan brief

- **Likely files:** `src/client/envExt/api.legacy.ts`, `src/client/envExt/api.internal.ts`, `src/client/common/terminal/service.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`
- **Validation:** In a fresh macOS VS Code profile using system Python 3.14.4 without ipykernel, create a Python file containing print('hello'), select it, and invoke Run Selection/Line in Python Terminal. Check both a standalone file and a file inside an opened workspace folder, with Python Environments enabled and disabled. Acceptance: the terminal starts and prints hello without the reported error or installing ipykernel; repeat after restarting VS Code to exclude cached recovery.
- **Behavior:**

  > Running selected ordinary Python code in a terminal must not require ipykernel. The reported fresh installation instead produces an invalid-terminal-arguments error and executes nothing. Validate that a simple selected print statement starts a terminal and executes without ipykernel, both with and without an opened workspace folder. Recovery must persist across a restart without relying on a prior ipykernel installation.
- **Trace:**

  > CodeExecutionManager.executeSelection passes activeEditor.document.uri to TerminalCodeExecutionProvider.execute, which initializes the REPL through TerminalService.sendCommand. TerminalService.ensureTerminal delegates to src/client/envExt/api.legacy.ts ensureTerminalLegacy when the environments integration is enabled. That function throws the exact reported error whenever either the environment or Python project is missing, before calling the sibling extension's createTerminal API. The source identifies the error boundary, but this report has no logs establishing which value was missing or why installing ipykernel changed it. https://github.com/microsoft/vscode-python-environments/issues/1820 confirms a later standalone-file missing-project case and is related evidence, not an eligible duplicate canonical. Preserve normal interpreter selection, activation, and REPL submission behavior; the additional bracketed-paste symptoms in https://github.com/microsoft/vscode-python-environments/issues/684 are not established as this failure's root cause.
