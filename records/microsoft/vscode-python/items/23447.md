# Issue #23447 — Test Discovery Failing in all repos (for the Testing Panel)

[https://github.com/microsoft/vscode-python/issues/23447](https://github.com/microsoft/vscode-python/issues/23447)

## Summary

The underlying permissions failure remains possible on current main: test discovery creates its FIFO under XDG_RUNTIME_DIR without first ensuring that directory is writable. The issue is already accepted and correctly routed with area-testing and needs PR.

## Change summary

Test discovery fails in WSL2 and other Unix environments when the extension cannot create its communication pipe under /run/user/<uid>.

## Best solution

Make src/client/common/pipes/namedPipes.ts verify that XDG_RUNTIME_DIR is writable and fall back to a safe temporary directory when it is not; mkfifo should also reject nonzero exits rather than leave its promise pending.

## Evidence

- **current source:** src/client/common/pipes/namedPipes.ts:29-36 still places non-Windows pipes in XDG_RUNTIME_DIR when set, while createReaderPipe at lines 184-191 calls mkfifo there without checking whether the parent directory is writable.
- **incomplete error handling:** src/client/common/pipes/namedPipes.ts:39-50 resolves mkfifo only for exit code 0 and does not reject a nonzero exit, so a permissions failure can leave pipe creation pending.
- **partial related fix:** https://github.com/microsoft/vscode-python/commit/d1d125a6cd7201883503da173bd774b1809b5a0e switched Linux/macOS testing communication from Unix-domain sockets to FIFOs, but retained the same XDG_RUNTIME_DIR location implicated by this report.
- **confirmed root cause:** Maintainers identified Unix-domain communication under /run/user/1000 as the failure, and multiple reporters confirmed command-line discovery worked while extension discovery failed; later comments continued documenting the writable-directory workaround.
