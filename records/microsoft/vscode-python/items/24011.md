# Issue #24011 — Include cwd in repl editor tooltip in multi root cases

[https://github.com/microsoft/vscode-python/issues/24011](https://github.com/microsoft/vscode-python/issues/24011)

## Summary

Keep this accepted REPL enhancement open: current source retains the selected working directory for execution but does not pass it to the editor presentation. The existing area-repl routing is appropriate, and searches found no canonical report covering the same UI request.

## Change summary

Expose the native Python REPL's selected working directory in multi-root workspaces, preferably in the editor tab tooltip.

## Best solution

Make the selected REPL working directory inspectable in the UI without changing directory selection or execution behavior. Determine whether VS Code's REPL editor supports a tooltip directly or needs an editor API enhancement; the existing Python REPL tab identity should remain stable.

- **Likely files:** `src/client/repl/nativeRepl.ts`, `src/client/repl/replCommandHandler.ts`, `src/client/repl/replUtils.ts`
- **Validation:** Open a workspace with two folders, run Python: Start Native REPL, select one folder, and verify its path is inspectable in the agreed UI surface and matches os.getcwd() before any user directory change. Close and reopen the REPL with the other folder selected and verify the displayed path updates, while execution and existing-tab reuse continue to work.
- **Behavior:**

  > In a multi-root workspace, users should be able to inspect the working directory selected for the native Python REPL after the directory picker has closed. The issue suggests the editor tab tooltip but permits another visible UI surface. Verify that selecting either workspace folder exposes the corresponding path and does not change REPL execution, focus, or tab reuse.
- **Trace:**

  > NativeRepl.setReplDirectory in src/client/repl/nativeRepl.ts stores the chosen workspace path in this.cwd and passes it to Python server creation. NativeRepl.sendToNativeRepl does not pass that value to openInteractiveREPL in src/client/repl/replCommandHandler.ts, which presents the editor using the fixed asRepl string 'Python REPL'. src/client/repl/replUtils.ts:getExistingReplViewColumn and the persisted-editor checks in NativeRepl depend on that exact label; preserve their behavior. Source inspection establishes the missing presentation plumbing, but not whether VS Code exposes a suitable REPL editor tooltip API. The accepted request is https://github.com/microsoft/vscode-python/issues/24011; directory-selection and directory-update defects are separate work.
- **Open decisions:**
  - If the REPL editor API cannot expose a tab tooltip, which alternative UI surface should display the selected working directory?
