# Issue #24648 — Autoreload capability in native REPL

[https://github.com/microsoft/vscode-python/issues/24648](https://github.com/microsoft/vscode-python/issues/24648)

## Summary

Keep this request open and route it to the REPL area: current native REPL execution does not provide session-preserving module autoreload. The request has 8 upvotes and the community ask label, so lack-of-traction closure does not apply.

## Change summary

Add manual and automatic reloading of edited imported modules without restarting the native Python REPL session.

## Best solution

Design session-preserving reload support for the native REPL, considering established community tooling rather than a bespoke replacement. Settle the supported reload interface and compatibility guarantees before implementation; existing IPython-integration requests are related but do not establish coverage of this specific capability.

## Plan brief

- **Likely files:** `package.json`, `src/client/repl/replCommands.ts`, `src/client/repl/replController.ts`, `src/client/repl/pythonServer.ts`, `python_files/python_server.py`, `python_files/tests/test_python_server.py`, `src/test/repl/nativeRepl.test.ts`
- **Validation:** In one native REPL session, import a temporary project module and create an unrelated session variable, then edit the module. Verify manual mode keeps the old behavior until explicitly reloaded, automatic mode picks up the edit before the next execution, and both retain the unrelated variable without restarting. Check module-qualified calls and from-imported functions against the agreed compatibility contract, and measure unchanged-module execution overhead.
- **Behavior:**

  > Users should be able to edit imported project modules and use their updated behavior in the same native Python REPL session without restarting it. Provide explicit manual reload and optional automatic reload behavior comparable to the modes requested in the issue. Manual mode must not reload merely because another cell executes; automatic mode should apply changes before subsequent execution. Preserve unrelated session state and validate unchanged-module execution overhead, since the reporter explicitly identifies performance as a reason to prefer manual mode.
- **Trace:**

  > src/client/repl/replCommands.ts registers native REPL entry points, and src/client/repl/replController.ts sends cell text to PythonServer.execute. src/client/repl/pythonServer.ts starts the selected interpreter with python_files/python_server.py and transports execute requests over JSON-RPC. The Python server retains USER_GLOBALS but evaluates submissions with ordinary eval/exec, without an IPython runtime or module-reload hook; package.json exposes no native reload control. Its debugger autoReload option is a separate execution path and must not be treated as native REPL support. python_files/tests/test_python_server.py supplies an existing Python-server test surface, while src/test/repl/nativeRepl.test.ts covers native session integration. Related requests https://github.com/microsoft/vscode-python/issues/22139 and https://github.com/microsoft/vscode-python/issues/23570 concern IPython terminal integration and startup configuration, not verified duplicates. The remaining uncertainty is the user-facing interface and supported reload semantics; preserve ordinary native execution, output, input, interruption, and session lifecycle outside the agreed feature.
- **Open decisions:**
  - Should native REPL reload support expose IPython-compatible magic commands, native commands/settings, or both, and should it require IPython in the selected environment?
  - Which live-reference updates are guaranteed: module-qualified access only, or IPython-style updates to from-imported functions and existing class instances?
