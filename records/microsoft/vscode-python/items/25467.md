# Issue #25467 — Shell Integration makes REPL prompt garbled

[https://github.com/microsoft/vscode-python/issues/25467](https://github.com/microsoft/vscode-python/issues/25467)

## Summary

This remains the best canonical report for Python shell integration exposing OSC 633 sequences and corrupting REPL rendering. Multiple users confirmed it across local and remote Linux/macOS environments, and current main still installs the startup script that generates these sequences.

## Change summary

Enabling Python terminal shell integration can expose raw OSC 633 sequences and garble the Python REPL prompt and input rendering.

## Best solution

Keep this as the canonical shell-integration rendering issue and consolidate the overlapping https://github.com/microsoft/vscode-python/issues/24780 here. Update the startup integration in `python_files/pythonrc.py` so OSC 633 markers are emitted only where the terminal can consume them, while preserving prompt wrapping and command detection.

## Evidence

- **confirmed reproductions:** The issue has independent confirmations on Remote SSH, dev containers, Fedora, Ubuntu, Linux Mint, ChromeOS Linux, and macOS; reports cover uv-, mise-, and system-managed Python installations.
- **current source path:** `src/client/terminals/pythonStartup.ts` still sets `PYTHONSTARTUP` to `python_files/pythonrc.py` whenever `python.terminal.shellIntegration.enabled` is true; that script constructs the prompt from OSC 633 C/E/D/A/B sequences.
- **related fix is narrower:** https://github.com/microsoft/vscode-python/pull/25521 added readline SOH/STX delimiters and fixed the cursor-wrapping report https://github.com/microsoft/vscode-python/issues/25502, but it did not stop unsupported OSC 633 sequences from being displayed literally.
- **canonical status:** A maintainer closed https://github.com/microsoft/vscode-python/issues/25505 as a duplicate of this issue, and also identified the same report in https://github.com/microsoft/vscode/issues/271480 as a duplicate of this issue.
