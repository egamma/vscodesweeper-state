# Issue #25904 — Avoid loading `sys` and `platform` modules into namespace when running PYTHONSTARTUP in integrated terminal

[https://github.com/microsoft/vscode-python/issues/25904](https://github.com/microsoft/vscode-python/issues/25904)

## Summary

The namespace pollution remains on main and maintainers have confirmed that preventing pythonrc.py internals from leaking into user globals is worthwhile. Route this to the REPL area for an implementation that preserves prompt dependencies.

## Change summary

Keep shell-integration implementation modules and helpers out of the interactive Python namespace populated through PYTHONSTARTUP.

## Best solution

Encapsulate shell-integration state in a separate namespace or capture private dependencies so only the required prompt object enters the user's globals. Deleting the imports directly is unsafe because the installed hooks continue resolving sys and readline at prompt time.

## Evidence

- **current source:** python_files/pythonrc.py imports platform, sys, and readline at top level, so PYTHONSTARTUP execution places them in the interactive namespace; its REPLHooks, get_last_command, and PS1 methods continue resolving sys and readline from that namespace.
- **maintainer position:** When closing the outdated implementation at https://github.com/microsoft/vscode-python/pull/25651, a maintainer stated that preventing pythonrc.py internals from leaking into user globals remains worthwhile and invited a reworked implementation against current main.
- **partial workaround:** package.json declares python.terminal.shellIntegration.enabled, and src/client/terminals/pythonStartup.ts removes PYTHONSTARTUP when it is disabled, but that also disables shell integration and therefore does not satisfy the central request.
- **related implementation constraint:** https://github.com/microsoft/vscode-python/issues/26039 documents that pythonrc.py callbacks retain the user's __main__ globals, so deleting or shadowing their module dependencies can break prompt rendering rather than safely cleaning the namespace.
