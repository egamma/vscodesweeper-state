# Issue #25904 — Avoid loading `sys` and `platform` modules into namespace when running PYTHONSTARTUP in integrated terminal

[https://github.com/microsoft/vscode-python/issues/25904](https://github.com/microsoft/vscode-python/issues/25904)

## Summary

Current main still executes shell-integration helpers directly in the user's namespace, and a maintainer has confirmed that preventing this leakage remains worthwhile. Route this to the terminal and REPL areas for a design that preserves prompt object lifetimes without exposing implementation names.

## Change summary

Keep `pythonrc.py` implementation modules and helpers out of the interactive user's global namespace.

## Best solution

Execute the shell-integration implementation in an isolated namespace or module and expose only the required `sys.ps1` object, while preserving the lifetime and lookup behavior needed by the prompt hooks. Coordinate this with the shadowing fix tracked by https://github.com/microsoft/vscode-python/issues/26039 so neither internal nor user-defined names interfere with the REPL.

## Evidence

- **current source:** python_files/pythonrc.py on main imports `platform`, `sys`, and non-Windows `readline` at top level and defines its helper classes and functions in the namespace where PYTHONSTARTUP executes; there is no cleanup or namespace isolation.
- **default behavior:** package.json declares `python.terminal.shellIntegration.enabled` with default `true`, and src/client/terminals/pythonStartup.ts installs python_files/pythonrc.py through PYTHONSTARTUP when enabled, so the side effect occurs in the default integrated-terminal configuration.
- **existing setting:** `python.terminal.shellIntegration.enabled` can avoid the injected namespace only by disabling the entire Python shell integration, so it does not deliver the central request while retaining the feature.
- **maintainer position:** In https://github.com/microsoft/vscode-python/pull/25651#issuecomment-5072470043, a maintainer explicitly said preventing pythonrc.py internals from leaking into user globals remains worthwhile, while noting that the earlier function-scoping implementation needed rework to preserve prompt objects and tests.
- **related remaining work:** https://github.com/microsoft/vscode-python/issues/26039 tracks the converse namespace collision, where user assignments can break pythonrc.py prompt hooks; it is related but does not subsume this request to prevent extension internals from entering user globals.
