# Issue #25904 — Avoid loading `sys` and `platform` modules into namespace when running PYTHONSTARTUP in integrated terminal

[https://github.com/microsoft/vscode-python/issues/25904](https://github.com/microsoft/vscode-python/issues/25904)

## Summary

The namespace pollution remains on current main and maintainers have previously affirmed that preventing pythonrc.py internals from leaking into user globals is worthwhile. Route this to the terminal/REPL owners; the proposed deletion is unsafe because the installed hooks continue resolving `sys` and `readline` from the startup namespace.

## Change summary

Keep extension-owned modules and helper names out of the interactive Python namespace populated by the shell-integration PYTHONSTARTUP script.

## Best solution

Isolate the shell-integration implementation in a durable private module or otherwise capture its dependencies outside the user's `__main__` namespace, exposing only the prompt object needed by CPython. Coordinate with https://github.com/microsoft/vscode-python/pull/26045, which addresses user shadowing of the same globals but does not remove the extension's names from the namespace.

## Evidence

- **current source:** python_files/pythonrc.py on current main still imports `platform`, `sys`, and non-Windows `readline` at top level, so execution through PYTHONSTARTUP places them in the interactive namespace.
- **lifetime constraint:** REPLHooks.__init__, get_last_command, and PS1.__str__ in python_files/pythonrc.py perform global lookups of `sys` and `readline` after startup; deleting those names as proposed would cause NameError when the hooks render later prompts.
- **maintainer precedent:** https://github.com/microsoft/vscode-python/pull/25651 attempted the same namespace cleanup. When closing the outdated implementation, a maintainer explicitly said the goal remains worthwhile and invited a reworked contribution based on current main.
- **related active work:** https://github.com/microsoft/vscode-python/issues/26039 confirms that pythonrc.py shares the user's globals and tracks the converse failure caused when users shadow those names; its open fix PR https://github.com/microsoft/vscode-python/pull/26045 captures private aliases but does not fully eliminate startup-owned names from the namespace.
