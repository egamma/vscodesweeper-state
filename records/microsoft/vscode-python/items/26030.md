# Issue #26030 — Python interpreter is attempting to run .venv as the python command

[https://github.com/microsoft/vscode-python/issues/26030](https://github.com/microsoft/vscode-python/issues/26030)

## Summary

Still present on current main: activated-environment detection accepts the relative `VIRTUAL_ENV=.venv` verbatim and persists it as the interpreter path, leading the extension to execute `.venv -c ...`. Route this confirmed interpreter-selection defect to the environments area.

## Change summary

A relative `VIRTUAL_ENV` value causes the extension to persist `.venv` as the Python command and lose the manually selected interpreter after reload.

## Best solution

In `src/client/interpreter/virtualEnvs/activatedEnvLaunch.ts`, resolve a relative `VIRTUAL_ENV` against an unambiguous workspace location or decline the automatic selection when it cannot be resolved to a valid environment, preserving the existing interpreter selection. Add coverage for relative prefixes in `src/test/interpreters/virtualEnvs/activatedEnvLaunch.unit.test.ts`.
