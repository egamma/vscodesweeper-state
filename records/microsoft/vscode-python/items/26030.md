# Issue #26030 — Python interpreter is attempting to run .venv as the python command

[https://github.com/microsoft/vscode-python/issues/26030](https://github.com/microsoft/vscode-python/issues/26030)

## Summary

This is a specific, source-confirmed instance of the open activated-environment selection bug tracked by https://github.com/microsoft/vscode-python/issues/23833.

## Change summary

A relative `VIRTUAL_ENV=.venv` inherited when VS Code launches is stored and executed as though it were the Python interpreter, overriding the workspace selection after reload.

## Best solution

Consolidate on https://github.com/microsoft/vscode-python/issues/23833 and ensure its environment-selection rework resolves relative `VIRTUAL_ENV` values to valid absolute environment paths, or preserves the explicitly selected workspace interpreter.
