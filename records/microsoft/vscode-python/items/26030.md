# Issue #26030 — Python interpreter is attempting to run .venv as the python command

[https://github.com/microsoft/vscode-python/issues/26030](https://github.com/microsoft/vscode-python/issues/26030)

## Summary

The legacy interpreter-selection path still accepts the inherited relative VIRTUAL_ENV value '.venv' as an interpreter, and configuration normalization leaves it executable-shaped. Route this to environments; the supplied steps and logs identify a concrete defect, not missing information.

## Change summary

Opening or reloading a uv workspace with Python Environments disabled replaces a working interpreter selection with '.venv', which is then invoked as a Python command.

## Best solution

Ensure legacy activated-environment selection yields a usable Python executable rather than a bare environment-directory command, and leaves a valid selection usable when the inherited environment cannot be resolved. Keep this report separate from interpreter-precedence requests, which do not specifically cover executing '.venv'.
