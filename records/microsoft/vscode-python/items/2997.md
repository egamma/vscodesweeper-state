# Issue #2997 — Run Selection/Line and Run File produce error when used consecutively

[https://github.com/microsoft/vscode-python/issues/2997](https://github.com/microsoft/vscode-python/issues/2997)

## Summary

The conflicting command flow remains present on current main: terminal selection execution starts a REPL, while file execution can reuse that same terminal and send a shell command into the interpreter. The existing accepted `needs proposal` item should remain open.

## Change summary

Running a selection and then a Python file, or doing those operations in reverse, leaves the shared terminal in the wrong execution mode and produces syntax errors.

## Best solution

Make file and selection execution state-aware or give shell execution and the terminal REPL distinct terminal services, preventing either command from sending input to an incompatible prompt. The proposal should also account for the optional Native Python REPL path.

## Evidence

- **current source path:** In src/client/terminals/codeExecution/codeExecutionManager.ts, both executeFileInTerminal() and executeSelectionInTerminal() resolve the same singleton `standard` ICodeExecutionService; selection calls execute(), while file execution calls executeFile().
- **incompatible terminal reuse:** In src/client/terminals/codeExecution/terminalCodeExecution.ts, execute() calls initializeRepl() before sending Python code, but executeFile() sends the interpreter-and-file shell command through the same terminal service without checking whether that terminal currently contains a REPL.
- **shared terminal identity:** src/client/common/terminal/factory.ts caches terminal services by title and workspace; the standard provider defaults to the `Python` title, so both command paths reuse the same terminal.
- **partial alternative:** package.json declares `python.REPL.sendToNativeREPL`, but it defaults to false and only redirects selection execution; it does not resolve compatibility between the two terminal commands.
