# Issue #25507 — Allow selecting environment as kernel WITHOUT jupyter

[https://github.com/microsoft/vscode-python/issues/25507](https://github.com/microsoft/vscode-python/issues/25507)

## Summary

A real capability gap remains: the native REPL controller is tied to the current interpreter and is not exposed as an environment picker for regular notebooks. Ownership needs coordination with the Jupyter extension because standard notebook kernel selection belongs there.

## Change summary

Allow a Python environment to execute regular notebook cells without installing or using Jupyter.

## Best solution

Decide the boundary with microsoft/vscode-jupyter, then expose native Python execution as selectable per-environment notebook controllers if that experience belongs here; otherwise a maintainer can transfer the request to https://github.com/microsoft/vscode-jupyter.

## Evidence

- **current implementation:** src/client/repl/replController.ts creates a single `pythonREPL` controller for `jupyter-notebook`, bound to the interpreter path supplied when the native REPL is created.
- **controller lifecycle:** src/client/repl/nativeRepl.ts creates the controller from the current interpreter only as part of the singleton native REPL session; it does not publish one selectable controller per environment.
- **existing surface:** package.json contributes `python.startNativeREPL` and native-REPL sending settings, but no command or setting for selecting an arbitrary environment as a regular notebook kernel.
- **canonical search:** The open candidate issues https://github.com/microsoft/vscode-python/issues/25554 and https://github.com/microsoft/vscode-python/issues/25042 concern missing or disappearing Jupyter kernels, not Jupyter-free notebook execution.
