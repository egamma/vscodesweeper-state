# Issue #23820 — Python extension creates too many zsh processes after update to v2024.10.0

[https://github.com/microsoft/vscode-python/issues/23820](https://github.com/microsoft/vscode-python/issues/23820)

## Summary

The recursive process-creation path remains present on current main: the extension exposes an executable named `deactivate` through PATH while starting hidden shells that load user startup hooks, allowing automatic-venv hooks to invoke that executable recursively. This should remain open in the terminal area despite the available user-configuration workaround.

## Change summary

Opening a Python workspace with zsh and an automatic virtual-environment activation plugin can recursively create thousands of zsh and bash processes.

## Best solution

Prevent the extension-provided `deactivate` executable from being re-entered by shell startup hooks, likely by changing how the deactivation command is exposed or how the hidden initialization terminal is launched in `src/client/terminals/envCollectionActivation/`. Preserve automatic terminal activation and the user's ability to run `deactivate` without requiring users to disable their shell plugins.

## Evidence

- **source path:** `src/client/terminals/envCollectionActivation/service.ts:264-278` prepends the shell-specific deactivation-script directory to PATH, making its executable named `deactivate` available during shell startup.
- **recursive shell initialization:** `src/client/terminals/envCollectionActivation/deactivateService.ts:49-55` creates a hidden user shell with its working directory inside that deactivation-script directory; `python_files/deactivate/zsh/deactivate:43-44` performs deactivation and then launches another zsh process.
- **confirmed trigger:** The reporter captured processes executing the extension's `python_files/deactivate/zsh/deactivate` through zsh and bash, then confirmed that disabling the automatic-venv zsh hook stops the loop: https://github.com/microsoft/vscode-python/issues/23820#issuecomment-2232571840.
- **independent confirmations:** Multiple users confirmed the same zsh automatic-venv-plugin configuration and runaway process behavior, including a Linux remote case reaching thousands of shells and OOM conditions: https://github.com/microsoft/vscode-python/issues/23820#issuecomment-2241500927 and https://github.com/microsoft/vscode-python/issues/23820#issuecomment-2547359461.
- **feature origin:** https://github.com/microsoft/vscode-python/pull/22405 introduced the PATH-based deactivation mechanism in commit b68ddee506cb8330e12c27e9c6421e1e0430763a; current main retains the mechanism and no subsequent script-history commit addresses this recursion.
