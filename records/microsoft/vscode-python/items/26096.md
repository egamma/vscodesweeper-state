# Issue #26096 — Run Selection/Line in Terminal becomes extremely slow and garbled when pyreadline3 is installed in the target interpreter

[https://github.com/microsoft/vscode-python/issues/26096](https://github.com/microsoft/vscode-python/issues/26096)

## Summary

The report convincingly isolates the slowdown and display corruption to pyreadline3's Windows REPL input handling. Current main sends each normalized selection to the terminal in one `sendText` call, while an existing pyreadline3 issue independently traces the matching scrollback corruption to its screen-update implementation.

## Change summary

Installing pyreadline3 makes Shift+Enter delivery to the classic Windows terminal REPL slow and causes terminal output to be overwritten or garbled.

## Best solution

The pyreadline3 Windows input and screen-redraw implementation should handle programmatically pasted multiline input without per-character delays or scrollback corruption. Keep the Python extension's Native REPL as the available workaround while the upstream behavior is investigated.

## Evidence

- **isolated reproduction:** The reporter reproduced across multiple VS Code builds, PowerShell versions, clean settings, and disabled extensions; installing or uninstalling pyreadline3 was the sole variable, and `python.REPL.sendToNativeREPL: true` bypassed the failure.
- **current source path:** src/client/terminals/codeExecution/terminalCodeExecution.ts passes normalized code to the terminal service once, and src/client/common/terminal/service.ts sends the complete command through a single `this.terminal?.sendText(commandLine)` call; there is no extension-side character-by-character loop.
- **upstream corroboration:** https://github.com/pyreadline3/pyreadline3/issues/40 is open and independently reports pyreadline3 overwriting or dropping terminal scrollback lines on Windows; its discussion traces the corruption to pyreadline3's `_update_line()` screen-update logic.
- **workaround:** The issue confirms that the Native REPL avoids the classic terminal REPL and fully avoids the slowdown and rendering corruption.
