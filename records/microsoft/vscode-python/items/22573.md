[https://github.com/microsoft/vscode-python/issues/22573](https://github.com/microsoft/vscode-python/issues/22573)

## Summary

Keep open: current testing code still has an unbounded process-close wait that could explain the spinner when descendants remain alive. Execution now has separate legacy and Python Environments paths; the supplied daemon-start reproduction is sufficient to retest both.

## Change summary

Completed pytest runs remain busy and block subsequent runs when tests leave a subprocess running.

## Best solution

Ensure pytest execution finalizes after the runner completes without waiting indefinitely for surviving descendants, while preserving results and output. First reproduce the daemon workflow and distinguish a live runner from inherited output handles in the testing execution paths.
