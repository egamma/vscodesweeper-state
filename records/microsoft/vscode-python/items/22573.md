# Issue #22573 — Tests hang if subprocess spawned but not killed

[https://github.com/microsoft/vscode-python/issues/22573](https://github.com/microsoft/vscode-python/issues/22573)

## Summary

The current non-environments-extension pytest path can still wait indefinitely for the child-process `close` event when a spawned descendant keeps inherited stdio open. The issue is already correctly routed to the testing area and should remain open.

## Change summary

Allow a completed pytest run to leave a subprocess running without leaving Test Explorer spinning and blocking subsequent runs.

## Best solution

Decouple pytest run completion from descendant-held stdio in `src/client/testing/testController/pytest/pytestExecutionAdapter.ts`, while preserving delivery of buffered test output. Add regression coverage where the pytest process exits but an inherited stream remains open, and verify that the test run still ends.

## Evidence

- **current source path:** On current main, `src/client/testing/testController/pytest/pytestExecutionAdapter.ts` resolves `deferredTillExecClose` only from the child process's `close` event in the non-environments-extension execution path; that event waits for stdio streams to close, so a descendant retaining inherited descriptors can keep the Test Explorer run pending after pytest exits.
- **timeout does not cover this wait:** The five-second `awaitDeferredWithTimeout` in `src/client/testing/testController/common/utils.ts` is entered only after `runTestsNew` returns, so it cannot release a run already blocked waiting for `deferredTillExecClose` inside `runTestsNew`.
- **confirmed report:** The reporter supplied a configured reproduction repository and confirmed that the run completes only after every spawned subprocess is killed; a maintainer acknowledged the report and began investigating.
- **related issue is distinct:** https://github.com/microsoft/vscode-python/issues/26071 concerns an additional fixed five-second named-pipe drain delay after the test subprocess has already closed; it does not own this issue's indefinite wait caused by a lingering descendant.
- **canonical search:** The other open search leads, https://github.com/microsoft/vscode-python/issues/25553 and https://github.com/microsoft/vscode-python/issues/24978, concern test discovery failures rather than test execution remaining active after pytest completes.
