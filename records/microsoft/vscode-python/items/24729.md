# Issue #24729 — File paths placed without double quotes.

[https://github.com/microsoft/vscode-python/issues/24729](https://github.com/microsoft/vscode-python/issues/24729)

The open canonical report covers the same PowerShell execution failure caused by apostrophes in paths. Consolidate this report there, preserving its workspace-local venv reproduction.

## Change summary

Running a Python file from an RPG's directory with a local .venv fails because terminal command construction does not quote apostrophes.

## Best solution

Resolve shell-aware quoting for interpreter and script paths under https://github.com/microsoft/vscode-python/issues/24265, using this report's RPG's workspace and local .venv as an additional reproduction case.

## Evidence

- **Verified canonical:** https://github.com/microsoft/vscode-python/issues/24265 is currently open and predates this report. It describes running Python on Windows with an apostrophe in both interpreter and script paths, producing a command-resolution failure after PowerShell interprets the apostrophes.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode-python/issues/24265#issuecomment-2400561416 identifies shell escaping as the probable defect. This report's maintainer comment likewise identifies the apostrophe in RPG's as the likely trigger.
- **Current source:** src/client/terminals/codeExecution/terminalCodeExecution.ts, TerminalCodeExecutionProvider.executeFile, formats the script path with fileToCommandArgumentForPythonExt and sends the interpreter and arguments through the terminal service. src/client/common/terminal/helper.ts:68-75 constructs the PowerShell command with an '& ' prefix using the same quoting helpers for the interpreter and arguments.
- **Shared defect:** src/client/common/extensions.ts:33-52 quotes strings containing spaces, ampersands, or parentheses, but not apostrophes. Consequently, paths such as C:/RPG's/.venv/Scripts/python.exe and C:/RPG's/test.py remain unquoted in the constructed PowerShell command. The canonical's username-directory case and this workspace-directory case exercise the same defect; no distinct platform or product behavior requires a separate issue.
- **Reproduction detail to preserve:** https://github.com/microsoft/vscode-python/issues/24729 supplies Windows 10, PowerShell, Python extension 2024.22.2, Python 3.13.1, a workspace named RPG's, a locally created .venv, and a test.py containing print('ok') launched through the play button. Source inspection confirms the apostrophe-only quoting gap; no runtime reproduction was performed.
