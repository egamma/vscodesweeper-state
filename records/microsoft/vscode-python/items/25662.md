# Issue #25662 — runTests can't find tests in a file

[https://github.com/microsoft/vscode-python/issues/25662](https://github.com/microsoft/vscode-python/issues/25662)

## Summary

A real capability gap remains: runTests can select only tests already present in VS Code's discovered test collection, so an explicitly named pytest file excluded by normal discovery never reaches the Python test adapter. Keep this team-authored request open, route it to testing, and consider transferring it to VS Code core because the tool's argument handling is implemented there.

## Change summary

Allow runTests to execute a specifically supplied pytest file even when its name intentionally excludes it from normal pytest discovery.

## Best solution

Extend the VS Code runTests tool and testing-provider contract so an explicit file can trigger provider-specific collection or execution with that path, rather than requiring the file to be present in the existing test collection. A maintainer can transfer this to https://github.com/microsoft/vscode if the necessary API and tool changes are confirmed to be core-owned.

## Evidence

- **confirmed capability gap:** The reporter confirmed that `pytest tests/e2e.py` collects and runs the tests, while ordinary pytest discovery intentionally excludes the nonstandard filename; a Python maintainer concluded that runTests would need to provide run arguments and stated that this was not supported.
- **Python discovery path:** src/client/testing/testController/pytest/pytestDiscoveryAdapter.ts constructs discovery as `python -m pytest -p vscode_pytest --collect-only` plus configured `pytestArgs`; the runTests file argument is not supplied to this discovery command.
- **discovered-items-only execution:** src/client/testing/testController/controller.ts handles TestRunRequest objects containing existing TestItems, and src/client/testing/testController/pytest/pytestExecutionAdapter.ts executes the resulting test IDs rather than accepting an arbitrary file argument from the language-model tool.
- **core tool ownership:** Current VS Code core implements runTests in src/vs/workbench/contrib/testing/common/testingChatAgentTool.ts: `_getFileTestsToRun` resolves supplied paths through the existing test collection and returns "No tests found" before invoking a provider when none are present.
