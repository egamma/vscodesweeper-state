# Issue #11932 — Add "Run Tests" to launch.json

[https://github.com/microsoft/vscode-python/issues/11932](https://github.com/microsoft/vscode-python/issues/11932)

## Summary

Keep open: ordinary test runs still do not consume launch.json test configurations. This accepted, 21-upvote request remains relevant; the broader configuration proposal does not yet establish support for its launch.json-specific behavior.

## Change summary

Allow non-debug test runs to use test-specific launch.json environment variables and related launch configuration options.

## Best solution

Provide test-run-scoped environment configuration in the Python testing integration without requiring workspace-wide environment changes. Coordinate with https://github.com/microsoft/vscode-python/issues/21845 and explicitly resolve whether settings-based profiles satisfy this request or launch.json compatibility is also required.

## Plan brief

- **Likely files:** `package.json`, `src/client/testing/testController/controller.ts`, `src/client/testing/testController/unittest/testExecutionAdapter.ts`, `src/client/testing/testController/pytest/pytestExecutionAdapter.ts`, `src/client/testing/common/debugLauncher.ts`
- **Validation:** Use unittest and pytest fixtures that assert a test-only environment variable. Run them through Test Explorer without debugging and verify the selected configuration supplies the value, results appear normally, and ordinary Python debugging retains its existing environment. If launch.json compatibility is accepted, additionally verify its envFile is honored and a preLaunchTask that writes a marker completes before test execution.
- **Behavior:**

  > Users need to run tests without debugging using local, test-specific environment configuration while CI uses different values. The current debug-test configuration does not affect ordinary Test Explorer runs. Acceptance should demonstrate the intended variables reach both unittest and pytest runs without requiring global environment changes or changing ordinary debugging. The thread also requests envFile and preLaunchTask compatibility, which must be explicitly included or excluded in the agreed contract.
- **Trace:**

  > In src/client/testing/testController/unittest/testExecutionAdapter.ts, runTests obtains workspace environment variables and branches into DebugLauncher only for the Debug profile; ordinary runs spawn the Python helper directly. src/client/testing/testController/pytest/pytestExecutionAdapter.ts has the equivalent separation. src/client/testing/common/debugLauncher.ts alone reads test launch configurations, while package.json exposes debug-test purpose and resource-scoped python.envFile rather than run-specific launch configuration support. The missing capability is confirmed from source, not a deviation from an established ordinary-run contract. Preserve existing discovery, result reporting, interpreter selection, and debug-test behavior. https://github.com/microsoft/vscode-python/issues/21845 proposes settings-based profiles and explicitly leaves launch.json separate; https://github.com/microsoft/vscode-python/issues/23777 tracks that larger engineering effort. The uncertainty is whether that alternative meets this issue's launch.json-specific acceptance requirements.
- **Open decisions:**
  - Can independently selectable settings-based test profiles satisfy this request, or must ordinary Test Explorer runs also honor launch.json test configuration fields, including envFile and preLaunchTask?
