# Issue #25866 — `python.testing.autoTestDiscoverOnSaveEnabled` is running test discovery on change to any file (not just test files)

[https://github.com/microsoft/vscode-python/issues/25866](https://github.com/microsoft/vscode-python/issues/25866)

## Summary

Still present on current main: the default save pattern matches every Python file and the matching save handler triggers full test discovery. Route this confirmed regression to the testing area; the related workstream treats this issue as a distinct pending fix rather than a duplicate.

## Change summary

Saving a non-test Python file triggers full test discovery, delaying large suites and temporarily disrupting test reruns and debug restarts.

## Best solution

Narrow the default `python.testing.autoTestDiscoverOnSavePattern` to conventional pytest and unittest filenames plus `conftest.py`, while preserving user-configured patterns. Incremental test-tree updates remain separate work in https://github.com/microsoft/vscode-python/issues/25822.

## Evidence

- **source reproduction:** package.json:676-680 defines `python.testing.autoTestDiscoverOnSavePattern` with the default `**/*.py`; src/client/testing/testController/controller.ts:1125-1136 matches every saved document against that pattern and calls `refreshData.trigger`, so an ordinary non-test `.py` save enters discovery on current main.
- **declared intent mismatch:** package.nls.json:82 describes `python.testing.autoTestDiscoverOnSaveEnabled` as running discovery when saving a test file, while the shipped default matches all Python files.
- **related workstream:** https://github.com/microsoft/vscode-python/issues/25978 explicitly lists narrowing this setting's default as pending work owned by issue 25866 and says implementation and regression tests are complete locally but publication is pending; the workstream is a tracking artifact, not a duplicate canonical.
- **separate remaining behavior:** https://github.com/microsoft/vscode-python/issues/25822 tracks incremental test-tree updates and is broader than the non-test-file trigger reported here; fixing incremental updates would reduce disruption but would not eliminate unnecessary discovery on non-test saves.
- **existing workaround:** Users can currently disable `python.testing.autoTestDiscoverOnSaveEnabled` or customize `python.testing.autoTestDiscoverOnSavePattern`, but neither makes the overly broad default correct.
