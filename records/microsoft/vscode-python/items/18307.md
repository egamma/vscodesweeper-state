# Issue #18307 — Standardize how to do environment variable parsing & substitution

[https://github.com/microsoft/vscode-python/issues/18307](https://github.com/microsoft/vscode-python/issues/18307)

## Summary

Keep this accepted, meta-labeled standardization issue open: it coordinates parsing and substitution across several features, and current source still has differing implementations. Related reports and the environments-extension implementation cover portions of the work, not the full contract.

## Change summary

Standardize dotenv parsing and environment-variable substitution across debugging, testing, and terminal execution.

## Best solution

Establish a shared dotenv compatibility contract with the Python Environments and Python Debugger extensions, then ensure each execution path adopts it. Preserve this umbrella until its parsing, substitution, integration, and documentation work is accounted for.

## Evidence

- **Protected tracking scope:** https://github.com/microsoft/vscode-python/issues/18307 carries meta and needs PR and explicitly coordinates parsing, substitution, debugger integration, terminal support, and documentation. The hard exclusion for meta/tracking artifacts bars closure; needs PR also records accepted work.
- **Current parsing gaps:** src/client/common/variables/environment.ts: parseEnvFile splits input on newline before parsing; parseEnvLine does not strip inline comments. Escaped \n inside quoted values is supported, but literal multiline quoted values are not parsed as one assignment. substituteEnvVars accepts ${NAME}, while ${env:NAME} is treated as invalid.
- **Different substitution inputs:** src/client/common/variables/environmentVariablesProvider.ts: getCustomEnvironmentVariables passes this.process.env into parseFile. By contrast, src/client/debugger/extension/configuration/resolvers/helper.ts: DebugEnvironmentVariablesHelper.getEnvironmentVariables passes debugLaunchEnvVars into parseFile and merges base/process variables afterward. The local source therefore does not establish one shared substitution contract.
- **Maintainer direction and sibling implementation:** https://github.com/microsoft/vscode-python/issues/18307#issuecomment-2539794337 identifies the Python Environments extension as the intended implementation home. Its current https://github.com/microsoft/vscode-python-environments/blob/main/src/features/execution/envVarUtils.ts uses dotenv.parse, while envVariableManager.ts provides getEnvironmentVariables. These sibling capabilities alone do not prove adoption across this repository's reported execution paths.
- **Canonical search and directional scope:** https://github.com/microsoft/vscode-python/issues/20003 was closed explicitly in favor of this issue. The verified open https://github.com/microsoft/vscode-python-debugger/issues/159 covers debugger substitution, and https://github.com/microsoft/vscode-python/issues/23799 covers inline comments; neither owns the full standardization scope. Searches for dotenv and variable substitution found no verified broader canonical that supersedes this umbrella.
- **Open related PR:** https://github.com/mesonbuild/meson/pull/12435 remains open and concerns changing generated VS Code substitution syntax to ${env:PATH}. It is related integration work, not a merged implementation of this issue's complete contract.
