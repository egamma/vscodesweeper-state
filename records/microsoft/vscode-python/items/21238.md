# Issue #21238 — Add support for refreshing tests in a single project/package/module.

[https://github.com/microsoft/vscode-python/issues/21238](https://github.com/microsoft/vscode-python/issues/21238)

## Summary

Keep open: manually refreshing a selected test subtree remains unsupported. This accepted, community-supported request is not covered by multi-project discovery or the related per-file automatic-discovery request.

## Change summary

Allow refreshing discovery for a selected project, package, or module directly from Test Explorer without refreshing unrelated tests.

## Best solution

Provide a scoped Test Explorer refresh action in the Python testing integration, preserving unrelated test trees and each project's environment. Coordinate scoped discovery infrastructure with the related per-file requests without losing this issue's explicit manual-refresh requirement.

## Plan brief

- **Likely files:** `package.json`, `src/client/testing/testController/controller.ts`, `src/client/testing/testController/common/types.ts`, `src/client/testing/testController/common/resultResolver.ts`, `src/client/testing/testController/pytest/pytestDiscoveryAdapter.ts`, `src/client/testing/testController/unittest/testDiscoveryAdapter.ts`
- **Validation:** In a multi-root workspace containing multiple test projects, change tests in one module and manually refresh that container. Verify additions and removals appear there, unrelated projects are not recollected or removed, the selected project's interpreter is used, and a collection error outside the selected scope does not prevent its refresh. Repeat for pytest and unittest, including project-based and legacy workspace modes.
- **Behavior:**

  > A user can manually refresh discovery for a selected project, package, or module in Test Explorer without refreshing the entire workspace. Added and removed tests update within the selected scope while unrelated test trees remain intact. Refresh uses the selected scope's configured environment and does not depend on saving a file or enabling automatic discovery. Validate isolation with an unrelated module that has a collection error.
- **Trace:**

  > package.json currently exposes only python.copyTestId in testing/item/context; the required VS Code context-key prerequisite merged in https://github.com/microsoft/vscode/pull/182529. PythonTestController.refreshTestData and discoverTestsInWorkspace in src/client/testing/testController/controller.ts resolve file URIs to workspace-wide discovery, including all registered projects. discoverAllProjectsInWorkspace removes existing workspace project items before recollection, so that path does not preserve unrelated subtrees. PytestController.resolveChildren renders cached discovery data, and PytestTestDiscoveryAdapter.discoverTests constructs collection from configured pytestArgs rather than a selected TestItem scope. The remaining design work is scoped provider collection and partial-result reconciliation across legacy and project-based modes; preserve existing global refresh, configured environments, and run/debug behavior. Related infrastructure requests are https://github.com/microsoft/vscode-python/issues/4586 and https://github.com/microsoft/vscode-python/issues/24279, neither of which subsumes the manual container action.

The Issue-Management wiki identifies needs proposal as accepted work requiring discussion: https://github.com/microsoft/vscode-python/wiki/Issue-Management.

- **current discovery scope:** src/client/testing/testController/controller.ts:543-690 routes refreshTestData(uri) through discoverTestsInWorkspace, which resolves the containing workspace and discovers either its legacy adapter or every registered project. discoverAllProjectsInWorkspace removes the workspace's existing project test items before rediscovering all projects. The global refreshHandler passes undefined with forceRefresh.
- **partial alternatives:** python.testing.autoTestDiscoverOnSaveEnabled and python.testing.autoTestDiscoverOnSavePattern control automatic refresh triggers, not manual subtree refresh. controller.ts:1124-1138 sends the saved file URI into the workspace-scoped refresh path; PytestController.resolveChildren uses cached discovery data rather than recollecting a selected subtree.
- **related requests are not canonicals:** https://github.com/microsoft/vscode-python/issues/4586 is open, older, and has 24 upvotes, but requests automatic per-file discovery after file changes rather than manual package/module refresh. https://github.com/microsoft/vscode-python/issues/24279 is open, created October 10, 2024, and requests module/file discovery to avoid root-level collection failures; it has no milestone or body reactions and does not meet the stronger canonical bar for this re-reviewed issue.
- **multi-project support is insufficient:** https://github.com/microsoft/vscode-python/issues/25789 describes separate project trees and environments, not a user-triggered refresh of one selected container. Current controller orchestration still refreshes every project in the containing workspace.
