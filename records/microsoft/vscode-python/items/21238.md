# Issue #21238 — Add support for refreshing tests in a single project/package/module.

[https://github.com/microsoft/vscode-python/issues/21238](https://github.com/microsoft/vscode-python/issues/21238)

## Summary

Keep open: current discovery still lacks a Test Explorer action to refresh only a selected project, package, or module. The request has demonstrated community interest and is accepted for a proposal; the merged VS Code change supplied menu infrastructure, not the Python capability.

## Change summary

Allow users to refresh test discovery for a selected container without rediscovering the entire workspace.

## Best solution

Provide container-scoped rediscovery in the Python testing integration, preserving unrelated test branches and supporting recovery after collection errors. Develop the proposal alongside related per-file discovery work, without treating automatic file-change discovery as coverage of this explicit user action.

## Plan brief

- **Likely files:** `package.json`, `src/client/testing/main.ts`, `src/client/testing/testController/controller.ts`, `src/client/testing/testController/common/types.ts`, `src/client/testing/testController/common/resultResolver.ts`, `src/client/testing/testController/pytest/pytestDiscoveryAdapter.ts`, `src/client/testing/testController/unittest/testDiscoveryAdapter.ts`
- **Validation:** In a multi-root workspace with two projects and multiple test modules, add or rename tests in one module with automatic discovery disabled. Invoke the proposed container refresh and verify fresh discovery is limited to that container, unrelated branches remain unchanged, and recovery works after correcting a collection error. Repeat for pytest and unittest, and verify the existing global refresh still discovers all roots.
- **Behavior:**

  > Users need an explicit Test Explorer action to rediscover tests under a selected project, package, or module without refreshing unrelated parts of the workspace. This must launch fresh discovery rather than reveal cached children, including after a collection error has been corrected. Acceptance checks should demonstrate updated tests in the selected container, unchanged unrelated branches, and preserved global-refresh behavior in multi-root workspaces.
- **Trace:**

  > PythonTestController in src/client/testing/testController/controller.ts sends the TestController refreshHandler to refreshTestData with an undefined resource, causing discovery across all workspace roots. A resource instead selects its enclosing workspace, and project-based discovery then visits every registered project; discoverTestsForProject is an internal single-project entry point, not a contributed user action. package.json currently contributes only python.copyTestId to testing/item/context, although https://github.com/microsoft/vscode/pull/182529 supplied the controller context keys needed for Python-specific contributions. The pytest and unittest discovery adapters consume configured framework arguments and optional project metadata, without a selected-container parameter. resolveChildren reads cached data and does not satisfy fresh rediscovery. The trace establishes the missing surface but does not establish safe partial-result replacement or framework-specific scoping semantics; preserve existing framework configuration, project environments, unrelated test branches, and global refresh. Related automatic per-file work remains at https://github.com/microsoft/vscode-python/issues/4586.
- **Open decisions:**
  - Should the initial feature expose refresh at every project, package, and module container as requested, or deliberately ship a project-root-only capability first?
  - If scoped collection fails, should the selected container retain its previously discovered tests with an error indication, or replace them with the failed discovery state?
