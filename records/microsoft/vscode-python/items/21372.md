# Issue #21372 — import a library from another vscode extension

[https://github.com/microsoft/vscode-python/issues/21372](https://github.com/microsoft/vscode-python/issues/21372)

## Summary

Keep open for API design: the public Python extension API still has no way for another extension to contribute library search paths, and the existing needs-proposal label protects this accepted design work from staleness closure.

## Change summary

Allow another VS Code extension to register a bundled Python library path without requiring users to enter its installation-dependent location manually.

## Best solution

Define a lifecycle-aware contribution API for registering and removing extension-owned import paths, with clear workspace scoping and coordination with the active language server; the proposal should determine whether the public contract belongs here or in Pylance.
