# Issue #21372 — import a library from another vscode extension

[https://github.com/microsoft/vscode-python/issues/21372](https://github.com/microsoft/vscode-python/issues/21372)

## Summary

A real API gap remains: extensions can configure a static extra import path, but the public Python extension API has no supported way to contribute library paths dynamically. The existing `needs proposal` label records that maintainers want an API design before implementation, so this should remain open.

## Change summary

Allow another VS Code extension to contribute a dynamically discovered library path for Python import resolution.

## Best solution

Design an extension-contribution API that clearly separates language-server import resolution from runtime environment changes, then coordinate the IntelliSense portion with Pylance. Preserve workspace scoping and avoid requiring extensions to overwrite the user's `python.autoComplete.extraPaths` array.
