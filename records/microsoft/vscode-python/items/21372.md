# Issue #21372 — import a library from another vscode extension

[https://github.com/microsoft/vscode-python/issues/21372](https://github.com/microsoft/vscode-python/issues/21372)

## Summary

Keep open for API design: the public Python extension API still has no way for another extension to contribute library search paths, and the existing `needs proposal` label marks this as accepted design work that must not be closed for inactivity.

## Change summary

Provide an extension API through which another VS Code extension can contribute dynamically resolved Python library search paths without requiring users to enter installation-specific paths.

## Best solution

Define a disposable, resource-scoped registration API that accepts paths resolved from the contributing extension's installation URI without rewriting user settings, then establish with Pylance how those contributions reach language analysis. The proposal should specify path lifetime, workspace scope, validation, change events, and behavior when multiple extensions contribute paths.

## Vision fit

- **Fit:** aligned
- **Reason:** A library-path contribution API advances the family architecture by giving sibling and third-party extensions a stable integration point rather than requiring them to modify user configuration.
- **Evidence:** The roadmap's durable extensibility theme calls for access points and APIs through which other Python extensions can participate, while the family-of-extensions guardrail favors integration surfaces over folding every capability into the core extension.

## Evidence

- **current public API:** src/client/api/types.ts defines the public PythonExtension API for debugging and environment discovery/selection but exposes no method for registering library or analysis search paths.
- **existing setting is not equivalent:** package.json declares `python.autoComplete.extraPaths` as a resource-scoped user configuration array; it does not provide a transient, extension-owned registration with lifecycle or workspace semantics.
- **maintainer direction:** https://github.com/microsoft/vscode-python/issues/21372#issuecomment-1710608008 asks for a concrete proposal before implementation, and the issue carries `needs proposal`, which marks accepted work staged for design.
- **broader use case:** https://github.com/microsoft/vscode-python/issues/21372#issuecomment-1581299954 records a second extension whose users must copy installation-dependent paths manually, showing that the request is not limited to Ren'Py.
- **remaining gap:** The proposed setting-update helper would persistently mutate user configuration and does not address ownership, disposal, multi-root scope, or forwarding paths to the language-analysis extension.
