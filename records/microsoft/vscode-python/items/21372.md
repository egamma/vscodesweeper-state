# Issue #21372 — import a library from another vscode extension

## Summary

This should stay open: it is already labeled `needs proposal` with `area-api`/`area-environments`, and a maintainer explicitly asked for a proposal rather than rejecting the request. The ask is for an extension API surface to add library search paths, which is not covered by the existing user setting alone.

## Change summary

Expose an API so another VS Code extension can add library paths such as an SDK subfolder to Python/Pylance analysis paths without asking the user to manually edit `python.autoComplete.extraPaths`.

## Best solution

Keep this as an API/environment integration proposal until the team decides what contract should exist, likely around extension-contributed environment/library paths rather than directly mutating user settings. The next useful step is a concrete API proposal that defines scope, persistence, ownership, and how it interacts with Pylance settings.
