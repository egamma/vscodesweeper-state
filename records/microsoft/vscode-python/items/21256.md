# Issue #21256 — Modify `getActiveEnvironmentPath()` API when `resource` is passed as `undefined` in a multiroot workspace

[https://github.com/microsoft/vscode-python/issues/21256](https://github.com/microsoft/vscode-python/issues/21256)

## Summary

The requested legacy API change is no longer part of the intended architecture: the team is replacing this Python extension API with the Python Environments extension API, while the original Black failure has already been mitigated in the Black Formatter extension.

## Change summary

Define useful workspace-level behavior for `getActiveEnvironmentPath(undefined)` so formatter extensions can launch in multi-root workspaces without choosing a folder-specific interpreter.

## Best solution

Consumers should obtain project and environment assignments from the Python Environments extension API rather than adding new semantics to `getActiveEnvironmentPath(undefined)`. The legacy API should remain unchanged while consumers migrate to the replacement.

## Vision fit

- **Fit:** rejected
- **Reason:** Extending the legacy Python extension environment API conflicts with the current migration toward the dedicated Python Environments extension and the family-of-extensions architecture.
- **Evidence:** The vision identifies the Python Environments extension rollout as the dominant environment-management workstream and directs new environment-management capability toward the dedicated extension.
