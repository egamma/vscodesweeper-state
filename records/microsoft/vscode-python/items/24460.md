# Issue #24460 — Support streaming output for native python REPL

[https://github.com/microsoft/vscode-python/issues/24460](https://github.com/microsoft/vscode-python/issues/24460)

## Summary

The streaming gap remains directly visible on current main: the native REPL buffers redirected output until execution finishes. This team-authored issue is the canonical report and should remain open for an implementation.

## Change summary

Native REPL output should appear incrementally while code runs instead of being displayed only after execution completes.

## Best solution

Extend the native REPL JSON-RPC protocol to emit stdout and stderr notifications during execution, then append those chunks to the active notebook-cell execution while preserving the final status response, input handling, and silent variable requests.

## Evidence

- **source-reproducible buffering:** python_files/python_server.py redirects stdout and stderr into in-memory CustomIO buffers for the full exec_user_input call; execute() sends str_output.get_value() only after execution returns.
- **deferred notebook output:** src/client/repl/replController.ts awaits server.execute() and calls replaceOutput only after the final ExecutionResult arrives, so no cell output can be displayed while the submitted code is running.
- **protocol limitation:** src/client/repl/pythonServer.ts models execution as a single request/response containing one output string and registers no notification handler for incremental stdout or stderr.
