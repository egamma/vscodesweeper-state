# Issue #25995 — Conversion to Scripts/python.exe not working

[https://github.com/microsoft/vscode-python/issues/25995](https://github.com/microsoft/vscode-python/issues/25995)

## Summary

The requested executable-path conversion is not intended behavior, as the maintainer explains. Cross-platform workspace configuration is already supported by setting python.defaultInterpreterPath to the environment directory rather than a platform-specific executable.

## Change summary

Automatically translate a Unix-style virtual-environment executable path into the Windows Scripts/python.exe path across interpreter consumers.

## Best solution

Keep explicit executable paths platform-specific and use python.defaultInterpreterPath: "${workspaceFolder}/.venv" for portable project settings. For a workspace with an interpreter already selected, use Python: Select Interpreter to select the actual Windows executable.

- **Proposed comment:**

  > Thanks for the report. `python.defaultInterpreterPath` does not translate an explicit Unix-style executable path into a Windows executable path. For shared workspace settings, use `"python.defaultInterpreterPath": "${workspaceFolder}/.venv"` instead: the documented directory form supports the environment layout appropriate to each operating system (https://code.visualstudio.com/docs/python/settings-reference). This setting supplies the initial default only; if an interpreter has already been selected for the workspace, use **Python: Select Interpreter** (`python.setInterpreter`) to choose `.venv/Scripts/python.exe` on Windows. Closing this as intended behavior rather than a path-conversion bug.
