# Issue #25995 — Conversion to Scripts/python.exe not working

[https://github.com/microsoft/vscode-python/issues/25995](https://github.com/microsoft/vscode-python/issues/25995)

## Summary

The extension intentionally does not translate an explicit Unix interpreter path into its Windows equivalent. Current source supports a platform-neutral environment-directory value instead, so this can be closed as designed.

## Change summary

Automatically translate a shared virtual-environment executable path between Unix `bin/python` and Windows `Scripts/python.exe` layouts.

## Best solution

Keep explicit interpreter paths platform-specific, or configure `python.defaultInterpreterPath` as `${workspaceFolder}/.venv`, allowing the existing resolver to locate the platform-specific executable. No automatic rewriting of explicit executable paths is needed.

- **Proposed comment:**

  > Thanks for the report. `python.defaultInterpreterPath` does not rewrite an explicit Unix executable path into a Windows path; explicit interpreter paths are platform-specific. For a shared workspace configuration, use the environment directory (`"python.defaultInterpreterPath": "${workspaceFolder}/.venv"`) rather than appending `bin/python` or `Scripts/python.exe`—the resolver checks `Scripts/python.exe` on Windows and `bin/python` on other platforms. Also note that this setting supplies the initial default and is no longer used after an interpreter is selected for the workspace.
