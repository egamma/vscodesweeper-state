# Issue #23239 — unittest: `sys.path` is different when running from terminal vs test UI

[https://github.com/microsoft/vscode-python/issues/23239](https://github.com/microsoft/vscode-python/issues/23239)

## Summary

Keep this accepted, team-authored issue open: current unittest helpers still promote a package directory onto sys.path, explaining the reported standard-library shadowing. The environment-extension integration does not remove that Python-side mutation, and the younger matching report cannot replace this re-reviewed issue.

## Change summary

Unittest discovery and execution through the Test Explorer alter import precedence relative to equivalent terminal commands, causing project modules to shadow standard-library modules.

## Best solution

Make the unittest adapters preserve import resolution equivalent to the matching CLI discovery command, without promoting the parent of the test directory into a separate top-level import root. Preserve legitimate project imports and consolidate the matching evidence from https://github.com/microsoft/vscode-python/issues/24578 under this older issue.
