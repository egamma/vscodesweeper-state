## Change summary

## Evidence

- **Confirmed reporter trigger:** At https://github.com/microsoft/vscode-python/issues/21176, the maintainer reproduced execution dropping somevalue from [".", "--test_option", "somevalue"]. The reporter subsequently supplied new-adapter logs showing discovery retaining the value while execution passed only --test_option, and the maintainer confirmed the rewrite was active.
- **Current source preserves the defect:** src/client/testing/testController/pytest/pytestExecutionAdapter.ts:136 calls removePositionalFoldersAndFiles(pytestArgs). In pytest/arguments.ts:137-138 and 248-253, this invokes getPositionalArguments and removes every identified positional token. common/argumentsHelper.ts treats unknown --test_option as an option without a value, leaving somevalue classified as positional; both . and somevalue are therefore removed. The Python runner subsequently forwards the remaining arguments to pytest.main.
- **Verified older canonical with matching execution symptom:** https://github.com/microsoft/vscode-python/issues/11736 is OPEN and was created on 2020-05-11, before this issue's 2023-05-03 creation. Its concrete custom-argument filtering report includes https://github.com/microsoft/vscode-python/issues/11736#issuecomment-862112127: ["--result-logger", "local"] produces a selected-test execution error whose arguments contain --result-logger followed by the test ID, with local missing. This matches the observable loss of a custom option's separate value during test execution, not merely a shared area.
- **Matching workaround:** The reporter here states that --test_option=asd works whereas separate --test_option and asd fail. https://github.com/microsoft/vscode-python/issues/11736#issuecomment-2098547061 documents the same --mycustom-arg=value workaround. Current getPositionalArguments retains the single equals-form token, explaining both observations.
