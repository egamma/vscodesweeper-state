## Evidence

- **Confirmed reported trigger:** The reporter supplies [".", "--test_option", "somevalue"] and runs a test through Test Explorer. A maintainer reproduced the failure; July 2023 logs subsequently show discovery retaining the value while execution passes only --test_option, including with the rewritten adapter.
- **Current source preserves the defect:** src/client/testing/testController/pytest/pytestExecutionAdapter.ts:134-140 calls removePositionalFoldersAndFiles(pytestArgs). In pytest/arguments.ts, pytestFilterArguments invokes getPositionalArguments and removes its results. common/argumentsHelper.ts treats an unknown option as valueless, so '.' and 'somevalue' become positional arguments and are removed while '--test_option' survives. The resulting arguments feed both execution backends and the debug launcher.
- **Verified older canonical with matching execution symptom:** https://github.com/microsoft/vscode-python/issues/11736 is OPEN and was created on 2020-05-11, before this report. Its execution example at https://github.com/microsoft/vscode-python/issues/11736#issuecomment-862112127 configures ["-s", "--result-logger", "local"], but pytest receives the custom option followed by a selected test ID rather than its configured value. This matches the observable loss of a space-separated custom-option value during test execution, not merely a shared testing area.
- **Matching workaround:** This report describes --test_option=asd as a workaround. https://github.com/microsoft/vscode-python/issues/11736#issuecomment-2098547061 documents the same --custom-option=value workaround, consistent with getPositionalArguments retaining inline-value options in current source.
- **Broader proposal is related, not canonical:** https://github.com/microsoft/vscode-python/issues/21845 is OPEN, was created on 2023-08-18, and explicitly lists both reports as separate inputs to a broader configuration redesign. It is younger than this issue and is not the duplicate target.
