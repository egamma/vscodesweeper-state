# Issue #24991 — Django test discovering

[https://github.com/microsoft/vscode-python/issues/24991](https://github.com/microsoft/vscode-python/issues/24991)

## Summary

The defect remains on current main: default unittest discovery arguments include a bare `-v`, and Django discovery forwards it unchanged to `manage.py test`, whose verbosity option requires a value. The issue is already accepted and correctly routed with `area-testing` and `needs PR`, so it should remain open.

## Change summary

Django test discovery fails when the extension passes its default unittest discovery flags to `manage.py test`.

## Best solution

Translate or filter unittest-specific discovery arguments before invoking Django in `python_files/unittestadapter/django_handler.py`, ensuring verbosity has a Django-compatible value and unsupported flags are not forwarded. Add coverage for Django discovery using the extension's default `python.testing.unittestArgs`.

## Evidence

- **default configuration:** `package.json` declares the default `python.testing.unittestArgs` beginning with a standalone `-v`, followed by `-s`, `.`, `-p`, and `*test.py`.
- **current source defect:** `python_files/unittestadapter/discovery.py` passes every argument after `--udiscovery` to `django_discovery_runner`, and `python_files/unittestadapter/django_handler.py` appends those arguments unchanged to `python manage.py test --testrunner=django_test_runner.CustomDiscoveryTestRunner`.
- **confirmed behavior:** The issue log shows the resulting Django command with a bare `-v` and Django rejecting it with `argument -v/--verbosity: expected one argument`; multiple reporters confirmed that setting `python.testing.unittestArgs` to an empty or Django-compatible list avoids the failure.
- **related report:** https://github.com/microsoft/vscode-python/issues/25177 reports the same default-argument incompatibility, but it was filed later; this older, accepted `needs PR` issue is the better canonical item.
- **test gap:** `python_files/tests/unittestadapter/test_discovery.py::test_simple_django_collect` invokes discovery without the default unittest arguments, so it does not exercise the failing path.
