# Issue #4963 — Status of tests marked with pytest.mark.xfail are showing as unknown 

[https://github.com/microsoft/vscode-python/issues/4963](https://github.com/microsoft/vscode-python/issues/4963)

## Summary

The defect remains on current main: the pytest adapter maps an expected failure to skipped without checking pytest's `wasxfail` indicator. This team-authored issue is accepted testing work with `needs PR`, so it should remain open.

## Change summary

Expected pytest failures reported through `pytest.mark.xfail` appear as skipped or unknown instead of receiving the intended successful expected-failure status.

## Best solution

Update the pytest result translation in `python_files/vscode_pytest/__init__.py` to distinguish `xfail` and `xpass` reports from genuine skips using `report.wasxfail`, while preserving existing handling for ordinary passed, failed, and skipped tests. Add execution-adapter coverage for expected failures, unexpected passes, strict xpasses, and true skips.

## Evidence

- **current source:** `python_files/vscode_pytest/__init__.py` in `pytest_report_teststatus` (around lines 307-345) initializes every non-passed/non-failed call report as `skipped` and never inspects pytest's `report.wasxfail`, so an expected failure remains indistinguishable from a genuine skip on current main.
- **pytest semantics:** https://github.com/pytest-dev/pytest/issues/11847#issuecomment-1908698126 confirms that pytest reports an expected failure with outcome `skipped` plus `wasxfail`, while an unexpected non-strict pass is `passed` plus `wasxfail`; the extension must inspect both fields to distinguish these cases.
