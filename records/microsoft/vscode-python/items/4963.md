# Issue #4963 — Status of tests marked with pytest.mark.xfail are showing as unknown 

[https://github.com/microsoft/vscode-python/issues/4963](https://github.com/microsoft/vscode-python/issues/4963)

## Summary

The defect remains source-reproducible on main: pytest xfails are forwarded as skipped without inspecting `report.wasxfail`. This accepted, team-authored testing issue should remain open for implementation.

## Change summary

Expected pytest failures should be distinguished from ordinary skips and displayed with the intended successful status.

## Best solution

Update `pytest_report_teststatus` in `python_files/vscode_pytest/__init__.py` to recognize pytest's `wasxfail` metadata and emit the existing `expected-failure` outcome for an expected failure, with tests covering XFAIL, XPASS, and ordinary skips.

## Evidence

- **source-reproducible path:** `python_files/vscode_pytest/__init__.py:320-342` initializes every non-passed/non-failed call report as `skipped` and never checks `report.wasxfail`, so pytest's XFAIL report remains indistinguishable from a real skip.
- **existing outcome support:** `src/client/testing/testController/common/testExecutionHandler.ts:50-55` already maps `expected-failure` to a passed TestItem and ordinary `skipped` to skipped, but the pytest adapter does not emit `expected-failure`.
- **pytest semantics:** https://github.com/pytest-dev/pytest/issues/11847 documents that pytest intentionally reports XFAIL as `outcome == "skipped"` with `wasxfail` set, providing the discriminator the adapter must consume.
- **accepted work:** The issue is team-authored and carries `needs PR`; a maintainer also confirmed after the testing rewrite that the behavior remained unfixed.
