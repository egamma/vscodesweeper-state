# Issue #24307 — "Run Test with Coverage" runs *all* tests when test execution fails

[https://github.com/microsoft/vscode-python/issues/24307](https://github.com/microsoft/vscode-python/issues/24307)

## Summary

The reopened bug remains present on current main: an exception from the selected-test pytest invocation is misclassified as a test-ID read failure, after which the fallback launches pytest without the selected IDs and runs the full suite.

## Change summary

Prevent coverage runs from rerunning the entire test suite when the selected-test pytest invocation fails, and do not run tests when test IDs cannot be read.

## Best solution

Separate test-ID loading from pytest execution in python_files/vscode_pytest/run_pytest_script.py. A test-ID read failure should terminate without running pytest, while an exception from pytest.main should be reported without retrying the run without IDs; add regression coverage for both paths.
