# Issue #11812 — Allow "Run Python File in Terminal" button to be configurable

[https://github.com/microsoft/vscode-python/issues/11812](https://github.com/microsoft/vscode-python/issues/11812)

## Summary

Keep this accepted, team-authored request open: interpreter arguments are configurable, but the terminal Run command still does not provide script arguments or launch.json-based execution. The related reports explicitly defer to this issue, and the newer run-experience proposal cannot replace it under the re-review duplicate rules.

## Change summary

Make the editor's Python Run action configurable for interpreter and script arguments, module or launch-configuration execution, and stopping execution.

## Best solution

Agree on a configurable non-debug run contract spanning the core terminal execution path and its Python Environments integration, coordinating launch-configuration behavior with Python Debugger. Preserve the current simple file-run default while defining how users select configured execution and stop an active run.

## Evidence

- **Existing capability is partial:** package.json declares python.terminal.launchArgs, python.terminal.executeInFileDir, python.execInTerminal and python.execInDedicatedTerminal. These cover interpreter arguments, working-directory selection and dedicated-terminal execution, but do not declare a script-arguments setting or a launch-configuration mode for the terminal Run command.
- **Current execution paths:** src/client/terminals/codeExecution/terminalCodeExecution.ts: TerminalCodeExecutionProvider.executeFile supplies the file path, and getExecutableInfo prepends terminal.launchArgs. src/client/terminals/codeExecution/codeExecutionManager.ts: executeUsingExtension likewise constructs [...launchArgs, filePath] before calling runInTerminal or runInDedicatedTerminal. Neither path reads launch.json or appends configurable script arguments.
- **Related reports retain this issue as the owner:** https://github.com/microsoft/vscode-python/issues/10130 was closed explicitly in favor of this issue: https://github.com/microsoft/vscode-python/issues/10130#issuecomment-1361671745. The script-arguments request at https://github.com/microsoft/vscode-python/issues/19810 was closed for insufficient votes, but its discussion explicitly says the capability should be considered here regardless: https://github.com/microsoft/vscode-python/issues/19810#issuecomment-1244064617. Neither closed report is a duplicate canonical or proof of implementation.
- **Canonical search:** Verified https://github.com/microsoft/vscode-python/issues/15770 is open and proposes terminal arguments, new-terminal execution and launch.json configuration. It was created on 2021-03-24, after this issue's 2020-05-14 creation, and is a broader WIP proposal rather than an older report of the same observable symptom. Searches for open run/arguments and run/launch.json issues did not establish an eligible older canonical.
- **Sibling capability does not establish completion:** The Python Debugger package.json contributes debugpy.debugInTerminal and debugpy.debugUsingLaunchConfig to editor/title/run. These are separate debugging actions; their presence does not establish that python.execInTerminal supports configured non-debug execution or fulfills this request's full scope.
