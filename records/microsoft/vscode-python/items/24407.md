# Issue #24407 — Wrong path when running .py script in WSL

[https://github.com/microsoft/vscode-python/issues/24407](https://github.com/microsoft/vscode-python/issues/24407)

## Summary

The failing setup mixes a local Windows file URI with a WSL interpreter; Run Python File intentionally uses the extension host's path format. Opening the folder through Remote - WSL, which the reporter confirms works, is the supported execution model.

## Change summary

Translate Windows script paths such as c:/project/test.py into WSL mount paths when running with a WSL interpreter from a local Windows window.

## Best solution

Keep cross-OS path mapping at the VS Code Remote - WSL boundary rather than duplicating it in Python file execution; users should open the folder through Remote - WSL before selecting and running a WSL environment.

## Vision fit

- **Fit:** rejected
- **Reason:** Adding local Windows-to-WSL path translation to the Python extension would duplicate a concern already owned by VS Code's remote architecture.
- **Evidence:** The family-architecture guardrail favors keeping capabilities in their owning extension rather than absorbing them into vscode-python.

  > Thanks for the detailed follow-up. In a local Windows window, Run Python File receives a Windows file URI and therefore passes a `c:/...` path; it cannot safely treat every WSL terminal or Linux interpreter as a Remote - WSL workspace. The supported setup is to open the folder through Remote - WSL before selecting and running the WSL environment, which you confirmed works. This matches the resolution of https://github.com/microsoft/vscode-python/issues/40 through https://github.com/microsoft/vscode-python/issues/67, so I believe this can be closed as working as intended.
