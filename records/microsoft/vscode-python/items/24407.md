# Issue #24407 — Wrong path when running .py script in WSL

[https://github.com/microsoft/vscode-python/issues/24407](https://github.com/microsoft/vscode-python/issues/24407)

## Summary

The failing mixed-host workflow is not the supported WSL model: a locally opened Windows file retains its Windows URI while the selected WSL interpreter expects Linux paths. The supported Remote-WSL workflow gives both the extension and file Linux-side paths, and the reporter confirmed that it works.

## Change summary

Translate a locally opened Windows script path such as c:/project/test.py to /mnt/c/project/test.py when executing it with a WSL interpreter.

## Best solution

Keep WSL execution in a Remote-WSL window opened through Remote Explorer, where the Python extension, interpreter, terminal, and file URIs all operate in the same Linux context; do not add shell-specific Windows-to-WSL path translation to the local run command.

- **Evidence:** The durable family-architecture theme favors capabilities living in their owning extension, and the repository's established WSL support uses the VS Code Remote-WSL extension.

The command shown is mixing a locally opened Windows file (`c:/Programacion/.../test.py`) with a Python interpreter running inside WSL, so the file URI and interpreter use different filesystem namespaces.
