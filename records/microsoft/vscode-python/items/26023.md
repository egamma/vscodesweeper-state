# Issue #26023 — pytest discovery ignores per-subfolder pytest.ini / pyproject.toml [tool.pytest.ini_options] in monorepo (Windows)

[https://github.com/microsoft/vscode-python/issues/26023](https://github.com/microsoft/vscode-python/issues/26023)

## Summary

The central request is already supported by documented multi-project testing: configured Python projects receive separate pytest invocations rooted at their own directories. The workspace-wide invocation described here remains the documented fallback when the Python Environments integration is unavailable.

## Change summary

Discover and run pytest independently for monorepo subpackages so each package's pytest configuration and relative paths apply.

## Best solution

Use existing multi-project testing with packages/api and packages/core configured as Python projects and python.useEnvironmentsExtension enabled. Leave python.testing.cwd unset to retain each project's working directory; no additional pytestRoots setting is needed for this workflow.

  > Thanks for the report. Per-subfolder pytest invocation is already supported through multi-project testing: install the Python Environments extension, enable it with "python.useEnvironmentsExtension": true, and configure packages/api and packages/core as Python projects. Leave python.testing.cwd unset so each pytest invocation starts in its own project directory and can load that package's pytest.ini or pyproject.toml configuration. Without this integration, testing falls back to one workspace-wide root. The supported workflow is documented at https://github.com/microsoft/vscode-python/wiki/Multi%E2%80%90Project-Testing-in-VS-Code, so this request can be closed as covered by the existing capability.
