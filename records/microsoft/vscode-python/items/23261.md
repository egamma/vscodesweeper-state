# Issue #23261 — Select interpreter via file dialog does not properly load virtual env

## Summary

Keep open: the reporter reconfirmed the file-dialog problem in July 2026, and current source still accepts the dialog-returned path without preserving the selected symlink. Maintainers identified a VS Code dialog limitation, but the linked API request is closed and no verified open canonical owns the remaining work.

## Change summary

Selecting a virtual environment's Python symlink through Find should retain that environment's interpreter path rather than select the global interpreter it points to.

## Best solution

Resolve the VS Code file-dialog limitation or establish a supported interpreter-selection approach that preserves virtual-environment identity. A maintainer can transfer the dialog/API work to https://github.com/microsoft/vscode; manually entering the interpreter path remains a workaround, not equivalent coverage of Find.
