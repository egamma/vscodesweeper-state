# Issue #23261 — Select interpreter via file dialog does not properly load virtual env

[https://github.com/microsoft/vscode-python/issues/23261](https://github.com/microsoft/vscode-python/issues/23261)

## Summary

The macOS symlink-selection defect remains confirmed on a current VS Code build, and this issue is already staged for investigation with `needs spike`. The blocker is VS Code's file-dialog API, so the report should remain open while the host-side capability or an extension-side alternative is pursued.

## Change summary

Preserve the selected virtual-environment interpreter's symlink path when it is chosen through the file dialog on macOS.

## Best solution

Add a VS Code `OpenDialogOptions` capability that prevents macOS alias and symlink resolution, then use it from `SetInterpreterCommand._enterOrBrowseInterpreterPath`; alternatively, replace this specific native-dialog flow with a picker that preserves the selected path. The verified Positron implementation provides a concrete end-to-end precedent.
