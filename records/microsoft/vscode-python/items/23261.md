# Issue #23261 — Select interpreter via file dialog does not properly load virtual env

[https://github.com/microsoft/vscode-python/issues/23261](https://github.com/microsoft/vscode-python/issues/23261)

## Summary

Keep open: the reporter reconfirmed the macOS symlink-resolution defect on the current release, and the accepted `needs spike` work remains necessary. The underlying limitation is VS Code's file-dialog API rather than interpreter-selection logic.

## Change summary

Preserve a virtual environment's symlink path when selecting its interpreter through the file dialog on macOS.

## Best solution

Use the existing spike to pursue a VS Code dialog option that preserves aliases, then opt into it in the interpreter picker; if that API remains unavailable, investigate an extension-owned picker that retains the selected path.
