# Issue #24850 — API for Alternate Python Language Servers

[https://github.com/microsoft/vscode-python/issues/24850](https://github.com/microsoft/vscode-python/issues/24850)

## Summary

A generic alternate-language-server API remains missing on current main. The merged Pyrefly integration handles one extension through hard-coded detection, while the existing needs-proposal and needs-spike labels confirm the broader request remains accepted for investigation.

## Change summary

Expose an API through which alternate Python language-server extensions can disable or replace the Python extension's default language services without modifying user settings.

## Best solution

Define a stable API in src/client/api/types.ts for language-server extensions to register ownership of Python language services, including workspace-aware activation and disposal, then replace the Pyrefly-specific detection with that general mechanism.

- **Evidence:** The roadmap's durable extensibility theme calls for APIs and access points used by sibling extensions, while the community-tooling guardrail favors integrating existing ecosystem tools rather than building replacements in this extension.
