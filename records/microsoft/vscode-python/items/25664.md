# Issue #25664 — Django test coverage

[https://github.com/microsoft/vscode-python/issues/25664](https://github.com/microsoft/vscode-python/issues/25664)

## Summary

Django coverage is implemented and shipped: the extension starts coverage.py in-process and executes manage.py in that same process, so a configurable `coverage run` prefix is unnecessary. The separate parallel-coverage defect remains tracked by https://github.com/microsoft/vscode-python/issues/25597.

## Change summary

Allow Django unittest runs to collect coverage by running manage.py under coverage rather than as an unobserved subprocess.

## Best solution

Keep the in-process coverage implementation shipped in 2025.6.0; use https://github.com/microsoft/vscode-python/issues/25597 for the narrower remaining problem with Django parallel-test coverage.
