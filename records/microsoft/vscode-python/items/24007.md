# Issue #24007 — Repl cwd doesn't change when extending to multi root workspace

[https://github.com/microsoft/vscode-python/issues/24007](https://github.com/microsoft/vscode-python/issues/24007)

## Summary

The behavior remains present on current main: the native REPL chooses its working directory only when the singleton session is created and does not react when workspace folders change. The issue is already correctly routed to the REPL area and needs a product decision on whether to retain and expose the original directory or let the user reselect it.

## Change summary

Adding a second workspace folder does not update the running native REPL's working directory or show which folder the session remains associated with.

## Best solution

Define the expected lifecycle for a running REPL when the workspace changes, then either expose its retained working directory or provide an explicit directory-selection flow without unexpectedly changing process state. The implementation belongs in the native REPL session management under src/client/repl/.

## Evidence

- **process behavior:** src/client/repl/pythonServer.ts passes cwd only when spawning the Python server, so adding a workspace folder cannot alter the existing process working directory through the current code path.
- **original implementation scope:** https://github.com/microsoft/vscode-python/pull/23912 implemented initial-directory selection for empty, single-folder, and already-multi-root workspaces, but did not define transitions after a REPL has started.
- **related issue:** https://github.com/microsoft/vscode-python/issues/24008 concerns canceling the initial multi-root directory picker, a distinct lifecycle case rather than a canonical for workspace changes.
