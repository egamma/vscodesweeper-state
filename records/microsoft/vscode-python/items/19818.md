# Issue #19818 — Ensure default global interpreter used is the default `python` in terminal

[https://github.com/microsoft/vscode-python/issues/19818](https://github.com/microsoft/vscode-python/issues/19818)

## Summary

Keep this accepted request open: the core auto-selection path still prefers newer global interpreters rather than the Python resolved from PATH. Existing configuration offers an explicit override, but does not deliver the requested zero-configuration behavior.

## Change summary

Prefer the default Python on PATH when automatically selecting a global interpreter, fall back to the highest version, and document the selection order.

## Best solution

Make automatic global selection agree with the system's default Python while preserving explicit selections and workspace-environment precedence, and publish the resulting order. Coordinate the behavior with Python Environments, since enabled installations delegate active-environment selection there.

- **Trace:**

The comparer ranks versions descending within equivalent groups, and the global persistent-store path independently rejects lower-version replacements. PythonSettings.getPythonPath() in src/client/common/configSettings.ts substitutes that recommendation for the default python value, so the package.json default does not itself implement PATH-first selection. ## Evidence

- **Current selection behavior:** src/client/interpreter/autoSelection/index.ts calls EnvironmentTypeComparer.getRecommended() in autoselectInterpreterWithLocators(). In src/client/interpreter/configuration/environmentTypeComparer.ts, getRecommended() sorts eligible environments with compare(), which compares Python versions descending within the same location/type group; it does not prioritize the interpreter resolved by the python command on PATH.
- **Global cache behavior:** InterpreterAutoSelectionService.storeAutoSelectedInterpreter() in src/client/interpreter/autoSelection/index.ts also refuses to replace a globally preferred interpreter with a lower-version interpreter.
