[https://github.com/microsoft/vscode-python/issues/25611](https://github.com/microsoft/vscode-python/issues/25611)

## Summary

The command-availability mismatch remains in current main: enabling Pyrefly intentionally disables the Python extension's language server, but its restart command still appears without a registered handler. Keep this open in the existing IntelliSense area; the older candidates do not own this specific defect.

## Change summary

Python: Restart Language Server appears when Pyrefly is active, then fails because python.analysis.restartLanguageServer is not registered.

## Best solution

Make the Python extension's restart-command availability accurately reflect whether it manages a restartable language server, while preserving Pyrefly's independent operation and existing Pylance/Jedi restart behavior.
