# Issue #25611 — `python.analysis.restartLanguageServer` not found

[https://github.com/microsoft/vscode-python/issues/25611](https://github.com/microsoft/vscode-python/issues/25611)

## Summary

Still present on current main: the Python extension advertises its restart command for every Python editor, but does not register that command when Pyrefly causes the extension's own language-server mode to be None. The existing area-intellisense routing is appropriate.

## Change summary

Using Pyrefly exposes the Python: Restart Language Server command even though invoking it fails because the command is not registered.

## Best solution

Do not advertise the Python extension's restart command when it is not managing the active language server, or register a safe handler that clearly delegates users to the owning language-server extension. Keep reporting `languageServer: "None"` when Pyrefly owns language services, since current code intentionally uses None to disable the Python extension's built-in server.

## Evidence

- **command contribution:** package.json declares python.analysis.restartLanguageServer and exposes it whenever a Python editor or Jupyter notebook is active; its when-clause does not account for which extension owns language services.
- **missing registration path:** src/client/activation/node/manager.ts and src/client/activation/jedi/manager.ts register python.analysis.restartLanguageServer only when the Python extension starts Pylance or Jedi; src/client/languageServer/noneLSExtensionManager.ts has no corresponding registration.
- **intentional Pyrefly mode:** src/client/common/configSettings.ts explicitly selects LanguageServerType.None when meta.pyrefly is installed and pyrefly.disableLanguageServices is not true, explaining the diagnostic value and conclusively reaching the unregistered-command path on current main.
- **related issue is not canonical:** https://github.com/microsoft/vscode-python/issues/22045 concerns the command being hidden in Jupyter notebooks while Pylance is in use; it does not own this report's distinct visible-but-unregistered command path under Pyrefly.
