## Evidence

- **Reported trigger and measured impact:** https://github.com/microsoft/vscode-python/issues/25948 reports 328,987 tests collected in 10.43 seconds with CLI pytest versus 66.07 seconds through Test Explorer, with at least 10,000 parameter cases per function.
- **Independent reproduction and profiling:** https://github.com/microsoft/vscode-python/issues/25973 supplies a reproduction repository and reports 30,000 tests taking 2.21 seconds on CLI versus 39.91 seconds in Test Explorer. Its list-scan defect was addressed, but the same contributor subsequently profiled remaining overhead and linked https://github.com/microsoft/vscode-python/pull/26017 in https://github.com/microsoft/vscode-python/issues/25948#issuecomment-4769582808.
- **Remaining current-source path:** python_files/vscode_pytest/__init__.py:698-723 calls create_test_node for every collected item. At lines 838-850, create_test_node still obtains the line number through test_case.location for each item; the open PR's profile identifies the associated path computation as expensive. This confirms the implicated path remains, without establishing current end-to-end timings.
- **Open implementation candidate:** https://github.com/microsoft/vscode-python/pull/26017 is open and unmerged. It proposes avoiding path computation when obtaining line numbers and reports approximately 20% faster discovery on the contributor's suite. Its author explicitly links it to this issue, which requires keeping the issue open and agentReadiness at none.
- **Partial implementation is not completion:** https://github.com/microsoft/vscode-python/pull/25982 merged as 5389068da3a3b1b55536cd6ca6b8d51d13c43c2f to compact discovery payload paths. However, https://github.com/microsoft/vscode-python/pull/26016 remains open and reports that compaction introduced substantial overhead through pathlib.Path.relative_to; current source still uses that operation in compact_path.
- **Canonical search and prior-review bar:** Searches for pytest discovery performance and parameterized/parametrized discovery found no verified older open canonical with the same symptom. https://github.com/microsoft/vscode-python/issues/25978 was created after this report and is a workstream tracker that lists this issue separately, not a duplicate canonical. https://github.com/microsoft/vscode-python/issues/25795 concerns HIDDEN_PARAM discovery failure, a distinct observable defect; https://github.com/microsoft/vscode-python/issues/25973 is younger and closed.
- **Repository triage policy:** The complete Issue-Management policy at https://github.com/microsoft/vscode-python/wiki/Issue-Management calls for bug and area classification and distinguishes legitimate work from completed fixes.
