# Issue #25146 — Kernel picker wrongly displays `Python 2.7.undefined` for a valid `Python 3.12` kernel

[https://github.com/microsoft/vscode-python/issues/25146](https://github.com/microsoft/vscode-python/issues/25146)

## Summary

The incorrect transient version remains explainable on current main: legacy discovery infers Python 2.7 from a bare Unix `python` executable before resolving its actual version. Route this confirmed bug to the environments/API owners.

## Change summary

The notebook kernel picker initially labels a valid Python 3 interpreter as `Python 2.7.undefined`, although it launches the correct interpreter and later displays the correct version.

## Best solution

Avoid exposing the PEP 394-based Python 2.7 guess through the environments API for unresolved global interpreters; report an unknown version until discovery obtains the actual version, then ensure the update reaches Jupyter.
