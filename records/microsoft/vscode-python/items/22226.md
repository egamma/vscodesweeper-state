# Issue #22226 — Consider providing more information when prompting about a new environment.

[https://github.com/microsoft/vscode-python/issues/22226](https://github.com/microsoft/vscode-python/issues/22226)

## Summary

The legacy notification still omits the context requested, and the issue was reopened after another user misunderstood its effect. Route this accepted needs-spike work to environments; the planned migration is not evidence that the remaining experience has been resolved.

## Change summary

Make the newly detected environment notification identify the proposed environment, affected workspace folder, current interpreter, and how to reverse selection.

## Best solution

Ensure users can understand any environment-selection prompt before accepting it, without mistaking interpreter selection for adding a workspace folder. The environments owner should decide whether to improve the remaining legacy prompt or retire it through the Python Environments migration.

## Vision fit

- **Fit:** aligned
- **Reason:** Making environment selection understandable supports the getting-started experience and reliable environment management during the extension-family migration.
- **Evidence:** The supplied durable themes identify environment discovery and selection and lowering the on-ramp for new Python users; the rollout priorities emphasize integration with the Python Environments extension.

Exercise Yes, No, dismissal, and Don't show again; use the existing Virtual Environment Prompt unit suite to check selection and suppression behavior.
- **Behavior:**

  > Users encountering a newly detected environment should understand which environment and workspace folder the proposed selection concerns before accepting. They should be able to identify the current interpreter and how to return to it. The experience must not imply that accepting adds the environment directory as another workspace folder. If migration eliminates the notification, verify that outcome on the supported paths rather than assuming installation of the sibling extension is sufficient.
- **Trace:**

  > VirtualEnvironmentPrompt.activate subscribes to IComponentAdapter.onDidCreate; ComponentAdapter.onDidCreate in src/client/pythonEnvironments/legacyIOC.ts filters creation events to the relevant workspace. handleNewEnvironment chooses a workspace interpreter and compares it with the active interpreter, then notifyUser discards that context when constructing the static notification. Accepting updates the workspace-folder interpreter; existing tests cover Yes, No, suppression, and already-selected environments. python.setInterpreter provides recovery outside the prompt, while python.useEnvironmentsExtension controls migration participation. The maintainer's migration direction is recorded at https://github.com/microsoft/vscode-python/issues/22226#issuecomment-2656993717, but the record does not settle whether the surviving legacy experience should receive an interim improvement. Preserve interpreter-selection scope and existing cancellation and suppression behavior.
- **Open decisions:**
  - Should users who remain on the legacy environment experience receive a context-rich selection prompt, or should this request be fulfilled solely by retiring that prompt through the Python Environments migration?
