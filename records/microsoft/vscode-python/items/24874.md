# Issue #24874 — Feature Request: Add Repl Variables support to Python Terminal REPL.

[https://github.com/microsoft/vscode-python/issues/24874](https://github.com/microsoft/vscode-python/issues/24874)

## Summary

Keep open: variable inspection still supports the Native REPL, not the Terminal REPL requested here. The request has reached the stated seven-upvote threshold, and the verified related issues do not own this specific remaining capability.

## Change summary

Expose variables from the Python Terminal REPL in the REPL Variables view without requiring the Native REPL.

## Best solution

Provide variable inspection for the actual Terminal REPL session while preserving its terminal-based interaction. Plan the session-inspection and view integration first; the existing Native REPL implementation depends on a notebook controller and a separate PythonServer protocol.

## Plan brief

- **Likely files:** `src/client/providers/replProvider.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/repl/nativeRepl.ts`, `src/client/repl/variables/variablesProvider.ts`, `src/client/repl/variables/variableRequester.ts`, `package.json`
- **Validation:** Start Python: Start Terminal REPL, assign x = 1 and d = {'a': 2}, and verify the variable view reflects that terminal's values and supports inspecting d. Reassign and delete x and verify the view updates; repeat with a concurrent Native REPL to confirm session isolation, and confirm ordinary terminal input and output remain unchanged.
- **Behavior:**

  > Users should be able to inspect variables belonging to the Python Terminal REPL without switching to the Native REPL. Values should reflect assignments, changes, and deletions in the inspected terminal session, with expandable values consistent with the existing REPL Variables experience. Concurrent Native and Terminal REPL sessions must not display each other's namespace. Terminal interaction and normal Python output must remain usable.
- **Trace:**

  > The python.startREPL command is registered in src/client/providers/replProvider.ts and initializes the standard terminal execution service. src/client/terminals/codeExecution/terminalCodeExecution.ts starts the interpreter through sendCommand and sends code through executeCommand. Existing inspection is attached in NativeRepl.setReplController in src/client/repl/nativeRepl.ts: VariablesProvider requires a NotebookDocument, while VariableRequester obtains structured descriptions through PythonServer.executeSilently. The trace establishes that enabling python.REPL.provideVariables does not connect this provider to the terminal session; it does not establish a terminal-compatible inspection transport or presentation API. Preserve ordinary terminal execution, Native REPL inspection, and independent session namespaces; shared-session behavior requested by https://github.com/microsoft/vscode-python/issues/24753 is outside this request. The older https://github.com/microsoft/vscode-python/issues/17183 was closed after Native REPL support landed, but its later discussion confirms the terminal-specific gap.
