# Issue #24601 — DocTest unittest discovery adapter

[https://github.com/microsoft/vscode-python/issues/24601](https://github.com/microsoft/vscode-python/issues/24601)

## Summary

Keep open: current unittest discovery still lacks native doctest tree and source-location support. The existing testing-area classification is appropriate, and the discussion leaves a user-visible tree-placement decision unresolved.

## Change summary

Represent doctests loaded through unittest with correct Test Explorer hierarchy, source navigation, and editor locations.

## Best solution

Support standard doctest.DocTestSuite integration without requiring test-ID monkey-patching, while preserving ordinary unittest discovery and execution. Decide how doctests outside the discovery root appear before implementing their hierarchy and source locations.

- **Behavior:**

  > Standard doctest.DocTestSuite tests loaded by unittest should appear with meaningful hierarchy and navigate to the actual doctest source, without ID monkey-patching. Module, class, and method doctests must work with src layouts and configured discovery directories. Ordinary unittest discovery and execution must retain their current behavior. Acceptance must include the agreed presentation for sources outside the discovery root and for unavailable source locations.
- **Trace:**

  > python_files/unittestadapter/discovery.py calls build_test_tree in python_files/unittestadapter/pvsc_utils.py. The builder skips short doctest IDs and interprets all remaining IDs as module/class/method paths, rather than consuming doctest source metadata. Existing test_utils.py cases establish short-ID rejection and patched-ID inclusion, not native location support. populateTestTree in src/client/testing/testController/common/utils.ts consumes path and lineno for navigation while retaining runID mappings for execution; preserve that separation and ordinary unittest behavior. The maintainer welcomed this work at https://github.com/microsoft/vscode-python/issues/24601#issuecomment-2546481566, but the hierarchy questions at https://github.com/microsoft/vscode-python/issues/24601#issuecomment-2573180020 remain unanswered. No code was executed during this read-only review.
- **Open decisions:**
  - Should doctests whose source lies outside the discovery root appear under a dedicated logical doctest group while retaining the existing root, or should the displayed hierarchy expand to include their source locations?
  - When a doctest has no known source filename or line, should it remain visible as a runnable item without navigation, or be omitted with an explicit diagnostic?
