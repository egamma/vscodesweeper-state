# Issue #25177 — Unable to use test discovery for Django tests

[https://github.com/microsoft/vscode-python/issues/25177](https://github.com/microsoft/vscode-python/issues/25177)

## Summary

The Django discovery failure remains source-reproducible on current main: Configure Tests writes generic unittest arguments that the Django adapter forwards unchanged to `manage.py test`, where `-v` requires a value. The issue already has the correct testing-area routing and should remain open for a Django-aware configuration fix.

## Change summary

Prevent Python: Configure Tests from writing or forwarding unittest discovery arguments that are invalid for Django projects.

## Best solution

Make unittest configuration and Django discovery argument handling compatible without silently overwriting valid user settings, preserving ordinary unittest discovery behavior. Add a Django discovery regression test covering the configured `-v`, `-s`, and `-p` argument set.

## Evidence

- **source-reproducible configuration:** On current main, src/client/testing/configuration/unittest/testConfigurationManager.ts:17-35 constructs `['-v', '-s', <directory>, '-p', <pattern>]` and writes it to the workspace through `updateTestArgs`.
- **source-reproducible forwarding:** python_files/unittestadapter/discovery.py:130-138 sends the configured unittest arguments to `django_discovery_runner`; python_files/unittestadapter/django_handler.py:46-56 then appends them unchanged to `python manage.py test`. Consequently the boolean unittest `-v` reaches Django's value-taking `-v/--verbosity` option.
- **maintainer confirmation:** https://github.com/microsoft/vscode-python/issues/25177#issuecomment-2997891192 confirms that Configure Tests contributes `-v -s ./tests -p "test_*.py"`, that these unittest arguments are not applicable to Django, and that the behavior should likely be removed.
- **independent confirmations:** https://github.com/microsoft/vscode-python/issues/25177#issuecomment-3754429079 reports that Python: Configure Tests overwrites `python.testing.unittestArgs`, while https://github.com/microsoft/vscode-python/issues/25177#issuecomment-4287021421 confirms that removing the generated workspace arguments restores discovery.
