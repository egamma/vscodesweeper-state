Its comments independently confirm that removing incompatible unittestArgs restores Django discovery.
- **Same root cause and observable failure:** This report's Linux/Python 3.12 venv logs show '-v -s ./tests -p test_*.py' reaching manage.py test and producing 'argument -v/--verbosity: expected one argument'. The reporter and a subsequent commenter restored discovery by removing workspace test arguments; the discussion identifies Configure Tests as their source.
- **Current configuration source:** src/client/testing/configuration/unittest/testConfigurationManager.ts, ConfigurationManager.configure(), still constructs arguments starting with '-v', adds '-s' and '-p', and persists them using updateTestArgs(). This establishes the configuration-generated variant of the canonical defect.
- **Current Django forwarding path:** python_files/unittestadapter/discovery.py:130-138 selects Django discovery when MANAGE_PY_PATH is set and forwards the original discovery arguments. python_files/unittestadapter/django_handler.py, django_discovery_runner(), appends those arguments unchanged to manage.py test, preserving the incompatible bare '-v' and '-s'.
