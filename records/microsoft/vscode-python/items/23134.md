# Issue #23134 — Consider contributing a terminal profile for the shell-integration powered Python REPL command

[https://github.com/microsoft/vscode-python/issues/23134](https://github.com/microsoft/vscode-python/issues/23134)

## Summary

The terminal-profile capability remains missing: the existing Python REPL command does not expose a selectable or default terminal profile. Route to the terminal area; the thread contains maintainer interest, and no verified canonical or implemented equivalent was found.

## Change summary

Expose the shell-integration-powered Python REPL as a contributed terminal profile that users can select or make their default.

## Best solution

Provide a Python REPL terminal profile that honors the selected environment and existing shell-integration settings while preserving the current REPL commands. A maintainer planning session should establish its terminal-creation and environment-integration contract before implementation.

## Plan brief

- **Likely files:** `package.json`, `src/client/providers/replProvider.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/common/terminal/service.ts`, `src/client/common/terminal/factory.ts`, `src/client/terminals/pythonStartup.ts`
- **Validation:** In an Extension Development Host, verify that a Python REPL profile appears in the terminal profile picker, selecting it opens an interactive Python prompt in the selected environment, and choosing it as the default makes Terminal: Create New Terminal launch that REPL. Repeat with Python Environments integration enabled and disabled; verify shell integration respects python.terminal.shellIntegration.enabled and existing python.startREPL behavior remains unchanged.
- **Behavior:**

  > Users should be able to launch the shell-integration-powered Python REPL from the terminal profile picker and select that profile as their default. Creating a terminal through that default should open a usable Python REPL in the intended Python environment. Existing REPL commands and the shell-integration setting should retain their behavior. Acceptance includes profile discovery, explicit profile launch, default-profile launch, and correct environment selection.
- **Trace:**

  > package.json exposes python.startREPL but contributes no terminal profile, and src/client contains no registerTerminalProfileProvider registration. src/client/providers/replProvider.ts resolves the active resource and interpreter before calling the standard execution service. TerminalCodeExecutionProvider.initializeRepl in src/client/terminals/codeExecution/terminalCodeExecution.ts sends the Python executable into a shell terminal and reuses an existing active REPL; TerminalServiceFactory also caches services by terminal identity. TerminalService.ensureTerminal in src/client/common/terminal/service.ts delegates terminal creation to the environments integration when enabled, while src/client/terminals/pythonStartup.ts supplies the Python startup integration variables. The trace establishes the missing surface, but not how independent profile-created terminals participate in this lifecycle or choose a resource without an active Python editor. Preserve existing command reuse, environment activation, and shell-integration settings. The request and maintainer interest are recorded at https://github.com/microsoft/vscode-python/issues/23134.
- **Open decisions:**
  - When the Python REPL profile is used as the default in a multi-root workspace or without an active Python editor, which workspace's selected interpreter should it use, and should an unresolved choice prompt for an environment?
