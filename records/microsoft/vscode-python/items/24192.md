# Issue #24192 — Show "install Jupyter extension" only if users have rich output in REPL

[https://github.com/microsoft/vscode-python/issues/24192](https://github.com/microsoft/vscode-python/issues/24192)

## Summary

Keep this accepted, team-authored REPL request open: current source does not detect rich output or condition a Jupyter installation suggestion on it. The next useful step is the requested spike to define qualifying output and the recommendation's scope.

## Change summary

Recommend installing Jupyter for higher-fidelity REPL output only when the user's output warrants it.

## Best solution

Define which output qualifies for a Jupyter recommendation and establish a reliable detection signal in the native REPL execution path. Preserve ordinary text-only execution without unsolicited recommendations, while leaving rich rendering to Jupyter.

## Plan brief

- **Likely files:** `package.json`, `python_files/python_server.py`, `src/client/repl/pythonServer.ts`, `src/client/repl/replController.ts`, `src/client/jupyter/requireJupyterPrompt.ts`
- **Validation:** After defining qualifying output, run a native REPL acceptance check with Jupyter absent: plain text must not trigger the recommendation, an agreed rich-output example must trigger it, and installing Jupyter must suppress further installation suggestions. Existing explicit Jupyter installation entry points must retain their agreed behavior.
- **Behavior:**

  > The native Python REPL should recommend Jupyter for higher-fidelity output only when executed code produces output that meets an agreed definition of rich output. Ordinary text-only execution should not trigger that recommendation. Acceptance examples must cover qualifying and nonqualifying output and the case where Jupyter is already installed.
- **Trace:**

  > python_files/python_server.py executes user code and serializes captured text through send_response; expression results are printed rather than represented as rich MIME data. src/client/repl/pythonServer.ts exposes only status and string output in ExecutionResult, and createReplController in src/client/repl/replController.ts displays text/plain. package.json exposes python.installJupyter through the editor's interactive-run submenu, and RequireJupyterPrompt in src/client/jupyter/requireJupyterPrompt.ts handles explicit installation requests. No inspected path links the recommendation to output characteristics. The uncertainty starts at defining a trustworthy rich-output signal and deciding whether this request governs only a new REPL recommendation or also existing installation entry points. Preserve native text execution and Jupyter's ownership of rich rendering; do not turn this spike into implementing an IPython replacement. The accepted spike is recorded at https://github.com/microsoft/vscode-python/issues/24192.
- **Open decisions:**
  - Which user-observable outputs qualify as rich output for the recommendation, and which representative examples define that contract?
  - Does 'only if users have rich output' govern a new native-REPL recommendation alone, or should it also change visibility of existing explicit Jupyter installation entry points?
