# Issue #10165 — Fix environment-dependent git pre-commit hooks

[https://github.com/microsoft/vscode-python/issues/10165](https://github.com/microsoft/vscode-python/issues/10165)

## Summary

Keep open: terminal activation does not provide the requested environment integration for Source Control commits. This accepted, highly supported request still needs a proposal coordinated with VS Code's Git integration; no qualifying fix or older open canonical was found.

## Change summary

Make environment-dependent Git hooks invoked through Source Control use the Python environment selected for the repository.

## Best solution

Establish repository-scoped environment integration between Python environment selection and VS Code's Git execution, including interpreter changes and remote workspaces. Agree on which Git operations receive that environment and how multi-root repositories select it before implementation.

## Plan brief

- **Likely files:** `src/client/interpreter/activation/service.ts`, `src/client/terminals/envCollectionActivation/service.ts`, `src/client/envExt/api.internal.ts`, `package.json`
- **Validation:** Create a repository with a local language: system hook invoking a tool installed only in its selected Python environment. Launch VS Code outside that environment and verify an SCM commit finds the tool; switch to a second environment with distinguishable tool output and verify the next commit uses that selection. Repeat for separate repositories in a multi-root workspace and a remote workspace, checking that unrelated repositories and ordinary terminal activation remain unaffected.
- **Behavior:**

  > Environment-dependent hooks currently can succeed in an activated integrated terminal but fail during a Source Control commit because their tools or dependencies are absent from the Git process environment. The desired capability is for SCM commits to use the Python environment selected for the relevant repository without manual hook edits or launching VS Code from an activated shell. Acceptance must include following interpreter changes and keeping different repositories' environments separate. The scope beyond commits remains a maintainer decision.
- **Trace:**

  > EnvironmentActivationService.getActivatedEnvironmentVariables in src/client/interpreter/activation/service.ts resolves resource-specific interpreter activation variables. TerminalEnvVarCollectionService in src/client/terminals/envCollectionActivation/service.ts consumes those variables through terminal environmentVariableCollection and reacts to interpreter changes; this is terminal activation, not Git process integration. src/client/envExt/api.internal.ts delegates environment lookup and process execution to Python Environments, but the inspected bridge has no Git consumer. The exact current Git-side extension point and adoption path remain unestablished because that implementation lives in VS Code core. Preserve existing terminal behavior and avoid treating process-wide environment mutation or persistent hook rewriting as already-agreed product requirements. Coordinate with https://github.com/microsoft/vscode/issues/265613 and consider the related API discussion at https://github.com/microsoft/vscode/issues/152806; neither replaces this older accepted request.
- **Open decisions:**
  - Should the selected Python environment apply only to SCM commits and their hooks, or to all Git operations for a repository?
  - When a Git repository contains multiple Python projects with different selected environments, which selection should govern its hooks?
  - Should this integration be enabled automatically for Python repositories or require explicit user opt-in?
