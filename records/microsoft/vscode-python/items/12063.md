# Issue #12063 — allow usage of unittest's load_tests protocol in python unit tests

[https://github.com/microsoft/vscode-python/issues/12063](https://github.com/microsoft/vscode-python/issues/12063)

## Summary

Keep this accepted request open: current unittest execution still discards custom suite behavior returned by load_tests. The related unittest redesign is newer and explicitly treats this request as a separate use case, so it is not a valid duplicate target.

## Change summary

Support custom unittest suites returned by load_tests, including their suite-level setup and teardown during Test Explorer execution.

## Best solution

Preserve custom suite execution semantics while retaining Test Explorer's selected-test execution and result reporting. Coordinate with https://github.com/microsoft/vscode-python/issues/22388, but retain this concrete acceptance case until that behavior is delivered.

## Plan brief

- **Likely files:** `python_files/unittestadapter/execution.py`, `python_files/tests/unittestadapter/test_execution.py`
- **Validation:** Add an adapter regression fixture matching the reported load_tests/CustomTestSuite example, then run python -m pytest python_files/tests/unittestadapter/test_execution.py. Assert suite setup precedes the selected tests, cleanup follows execution, both tests pass when selected together, and selecting one test does not execute unselected tests. Also verify the existing empty-selection and result-reporting cases remain unchanged. No tests were executed during this read-only review.
- **Behavior:**

  > A suite returned by unittest's load_tests protocol must retain its custom execution behavior when its tests run through Test Explorer. In the reported example, the suite creates foo.txt before test_file_exists executes and removes it afterward, matching python -m unittest. Acceptance should cover running the whole reported suite and one selected test, while preserving selected-test boundaries and existing result reporting.
- **Trace:**

  > src/client/testing/testController/unittest/testExecutionAdapter.ts builds a command targeting python_files/unittestadapter/execution.py. Its run_tests function discovers a suite, recursively filters it through filter_tests, and runs the reconstructed suite with UnittestTestResult. Every recursive filter_tests call creates a base unittest.TestSuite, conclusively discarding the reported CustomTestSuite.run override even when every child test is selected. Discovery already delegates to TestLoader.discover; the missing capability is preservation of suite execution semantics, not merely invoking load_tests. The compatibility design remains unestablished for arbitrary custom suites whose behavior depends on their contents or construction contracts. Preserve existing selection, empty-selection, and result-reporting behavior; the broader unittest.main redesign at https://github.com/microsoft/vscode-python/issues/22388 is related work, not proof of delivery or a duplicate canonical.
