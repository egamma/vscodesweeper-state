# Issue #12063 — allow usage of unittest's load_tests protocol in python unit tests

[https://github.com/microsoft/vscode-python/issues/12063](https://github.com/microsoft/vscode-python/issues/12063)

## Summary

A real gap remains on current main: discovery invokes the load_tests protocol, but execution filters the returned suite into a new plain TestSuite, bypassing a custom suite's run method. The accepted needs PR item should remain open until execution preserves unittest's suite semantics.

## Change summary

Allow unittest tests run from VS Code to honor package load_tests hooks and custom TestSuite execution behavior.

## Best solution

Update the unittest execution adapter under python_files/unittestadapter/ to preserve custom suites produced by discovery while still supporting selected-test execution and result reporting. Coordinate that work with the broader unittest.main/custom-runner design in https://github.com/microsoft/vscode-python/issues/22388, but retain this issue as the concrete load_tests acceptance case.

## Evidence

- **current execution path:** python_files/unittestadapter/execution.py calls unittest.TestLoader.discover(), but filter_tests() recursively copies selected cases into a new unittest.TestSuite before runner.run(tailor), so a CustomTestSuite.run override returned through load_tests is not retained.
- **discovery support is insufficient:** python_files/unittestadapter/discovery.py also uses TestLoader.discover(), which can invoke load_tests for collection, but execution reconstructs the suite and therefore does not preserve the protocol's custom execution behavior.
- **accepted work:** The issue currently carries needs PR, which marks it as accepted work and protects it from a quiet/staleness close.
- **related design:** https://github.com/microsoft/vscode-python/issues/22388 is open and proposes switching execution to unittest.main with a custom runner, but its body says only that it might fix load_tests support; it does not establish that resolving the broader design necessarily delivers this specific behavior.
