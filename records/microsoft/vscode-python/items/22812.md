## Summary

The bug remains present on current main: the pytest adapter emits outcomes for the call phase and skipped setup only, so a failed teardown cannot replace the test's reported success. The issue is already accepted and correctly routed with `area-testing` and `needs PR`.

## Change summary

Pytest fixture teardown failures are shown in output but leave the affected tests visually marked as passed.

## Best solution

Update the pytest execution adapter in `python_files/vscode_pytest/__init__.py` to report teardown failures and preserve their exception details, with explicit behavior for function-, class-, and module-scoped fixture teardown. Add execution fixtures and assertions covering failures after `yield` without regressing setup, call, or skip outcomes.
