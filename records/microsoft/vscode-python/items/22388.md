# Issue #22388 — Switch to using unittest.main and custom runner for unittest design

[https://github.com/microsoft/vscode-python/issues/22388](https://github.com/microsoft/vscode-python/issues/22388)

## Summary

Keep this accepted, team-authored proposal open: current main still manually loads and runs ordinary unittest suites rather than delegating to unittest.main. Django support landed separately, but it does not deliver the general argument handling and suite behavior requested here.

## Change summary

Delegate ordinary unittest execution to unittest.main with an extension-integrated runner for closer command-line parity and broader argument support.

## Best solution

Complete the accepted unittest design proposal so standard unittest argument handling and custom suite behavior work through Test Explorer while preserving selected-test execution, result reporting, debugging, and coverage. Treat the argument-handling and load_tests reports as acceptance cases, not replacement trackers for this broader work.
