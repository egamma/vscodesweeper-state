# Issue #22388 — Switch to using unittest.main and custom runner for unittest design

[https://github.com/microsoft/vscode-python/issues/22388](https://github.com/microsoft/vscode-python/issues/22388)

## Summary

Keep open: this team-authored, accepted design proposal remains unimplemented on current main, has substantial community support, and already carries the correct testing-area and proposal labels.

## Change summary

Replace the unittest adapter's manual discovery, filtering, and runner invocation with unittest.main and a custom runner so standard unittest arguments and protocols work consistently.

## Best solution

Complete the testing-area proposal and migrate python_files/unittestadapter/execution.py to a unittest.main-compatible custom runner while preserving test selection and VS Code result reporting. The design should cover standard unittest arguments and the load_tests protocol tracked by https://github.com/microsoft/vscode-python/issues/12063.
