# Issue #22594 — Enable per test output correlation for pytest

[https://github.com/microsoft/vscode-python/issues/22594](https://github.com/microsoft/vscode-python/issues/22594)

## Summary

Per-test output, particularly for successful tests, remains missing on main. Keep this accepted, well-supported request open as the canonical issue; the linked VS Code API request covers a narrower presentation concern.

## Change summary

Correlate captured pytest stdout, stderr, and logging with individual test results, including successful tests, while respecting user capture settings.

## Best solution

Deliver per-test captured output through the pytest reporting and TestRun result paths. Settle how successful-test output should coexist with aggregate run output under the current VS Code API, without making the narrower API enhancement a prerequisite for all progress.

- **Behavior:**

  > Users should be able to inspect captured stdout, stderr, and logs for an individual pytest test, including a successful test when configured to show its capture. Failed-test details should retain their traceback and relevant captured output. Respect pytest capture and reporting settings rather than silently overriding them, and do not create empty output entries. Acceptance checks should distinguish individual-test output from aggregate run output and include output generated during teardown.
- **Trace:**

  > python_files/vscode_pytest/__init__.py::pytest_report_teststatus emits no message for success and only report.longreprtext for failures; it processes call reports and skipped setup reports, not teardown. PythonResultResolver.resolveExecution delegates to TestExecutionHandler, whose handleTestSuccess only marks the TestItem passed. PytestExecutionAdapter streams subprocess stdout and stderr through appendOutput without a TestItem, so changing python.testing.pytestArgs alone cannot provide correlation. Preserve debug capture behavior, existing failure locations, test identities, and unrelated unittest behavior. The contributor branch at https://github.com/microsoft/vscode-python/compare/main...garyvdm:vscode-python:test_result_captured_output is prior art, not a merged implementation. The narrower API request https://github.com/microsoft/vscode/issues/286533 is closed; uncertainty begins at the acceptable presentation of successful-test output when appendOutput also adds it to aggregate output.
- **Open decisions:**
  - Should successful-test output also appear in aggregate run output under the existing appendOutput API, or must the feature preserve aggregate progress and summary output without that duplication?
