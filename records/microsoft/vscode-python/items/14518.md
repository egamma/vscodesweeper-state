# Issue #14518 — vscode-variables only expanded in some environment vars from .env file 

[https://github.com/microsoft/vscode-python/issues/14518](https://github.com/microsoft/vscode-python/issues/14518)

## Summary

The requested substitution remains absent on current main, and the existing `needs proposal` and `partner ask` labels mark this as accepted work requiring a design decision. Keep it open so the team can define consistent `.env` variable-expansion semantics for this extension and consumers such as Jupyter.

## Change summary

Support VS Code variables such as `${workspaceFolder}` in values loaded from `python.envFile`, consistently across all environment variables.

## Best solution

Extend the environment-file parser with explicit workspace context and documented multi-root semantics, then expose the same resolved values through the environment API used by sibling extensions. Preserve the existing ordered substitution of process and earlier `.env` variables.

## Evidence

- **current source gap:** src/client/common/variables/environment.ts:125-197 parses `.env` values using only variables defined earlier in the file and the supplied process environment; `${workspaceFolder}` is therefore treated as an undefined environment variable and replaced with an empty string.
- **workspace context not passed:** src/client/common/variables/environmentVariablesProvider.ts:125-131 passes only `this.process.env` into `parseFile`; `SystemVariables.resolveAny()` is used for the `python.envFile` path itself at lines 137-151, but not for values inside that file.
- **existing capability check:** package.json declares `${workspaceFolder}/.env` as the default `python.envFile` path, while src/test/common/variables/envVarsService.unit.test.ts tests only ordered `.env` and process-environment substitution; no setting or command provides workspace-variable expansion within `.env` values.
- **maintainer classification:** A maintainer explicitly classified this as an enhancement requiring a decision among removing, retaining, or officially expanding VS Code-variable substitution; the issue now carries `needs proposal` and `partner ask`.
- **sibling-extension requirement:** https://github.com/microsoft/vscode-python/issues/20784 was closed in favor of this request as an alternative for supplying workspace-relative environment values to Jupyter, and https://github.com/microsoft/vscode-jupyter/issues/14861 independently confirmed that `${workspaceFolder}` remains unsupported.
