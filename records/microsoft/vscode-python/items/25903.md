# Issue #25903 — Misleading Shift+Enter: python.REPL.enableREPLSmartSend

[https://github.com/microsoft/vscode-python/issues/25903](https://github.com/microsoft/vscode-python/issues/25903)

## Summary

Shift+Enter intentionally runs the current selection, line, or runnable block; the Smart Send setting controls block selection rather than the keybinding itself. Existing keyboard-shortcut customization covers the requested newline behavior, so this can close as working as intended.

## Change summary

Stop Shift+Enter from unexpectedly sending the surrounding Python block to the Native REPL while editing.

## Best solution

Keep Shift+Enter as the customizable Run Selection/Line shortcut and direct users who want newline behavior to remove its Python command bindings; continue the broader Smart Send documentation work in https://github.com/microsoft/vscode-python/issues/22558.

- **Proposed comment:**

  > Thanks for the report. Shift+Enter is intentionally the Run Selection/Line shortcut; `python.REPL.enableREPLSmartSend` only changes whether it sends the smallest runnable block or the exact selection/current line. If Shift+Enter should insert a newline instead, its `python.execInREPL` and `python.execSelectionInTerminal` bindings can be removed in Keyboard Shortcuts. This matches the behavior previously clarified in https://github.com/microsoft/vscode-python/issues/23998, while broader Smart Send documentation feedback remains tracked in https://github.com/microsoft/vscode-python/issues/22558, so I believe this can be closed as working as intended.
