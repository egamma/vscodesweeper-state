# Issue #25903 — Misleading Shift+Enter: python.REPL.enableREPLSmartSend

[https://github.com/microsoft/vscode-python/issues/25903](https://github.com/microsoft/vscode-python/issues/25903)

## Summary

Shift+Enter intentionally runs Python code rather than inserting a newline, and Smart Send intentionally expands that execution to the smallest runnable block. This behavior is documented and customizable through VS Code keybindings, so the request can be closed as designed.

## Change summary

Change Shift+Enter in Python editors so it inserts a newline instead of sending the current runnable block to the terminal or native REPL.

## Best solution

Keep Shift+Enter as the default shortcut for Python's run-selection commands and let users remove or reassign the `python.execInREPL` and `python.execSelectionInTerminal` keybindings when they want editor newline behavior. Continue making the distinction clear: disabling `python.REPL.enableREPLSmartSend` changes block selection to line-by-line execution but does not disable execution.

- **Proposed comment:**

  > Thanks for the feedback. Shift+Enter is intentionally the shortcut for running Python code: with `python.REPL.enableREPLSmartSend` enabled it sends the smallest runnable block, while disabling that setting switches to selection/line execution rather than turning Shift+Enter into a newline command. If you want Shift+Enter to insert a newline, you can remove or reassign the `Python: Run Selection/Line in Python Terminal` (`python.execSelectionInTerminal`) and `python.execInREPL` bindings in Keyboard Shortcuts. Since the current behavior is the documented, customizable default, I believe this can be closed as designed.

## Evidence

- **declared keybindings:** package.json:1153-1161 intentionally binds Shift+Enter in Python editors to `python.execSelectionInTerminal` and, when native-REPL routing is enabled, `python.execInREPL`.
- **setting contract:** package.json:652-656 and package.nls.json:70 define `python.REPL.enableREPLSmartSend`, enabled by default, as sending the smallest runnable block on Shift+Enter and moving the cursor accordingly.
- **maintainer explanation:** A maintainer confirmed at https://github.com/microsoft/vscode-python/issues/22558#issuecomment-2155667482 that Shift+Enter triggers Smart Send and that turning Smart Send off retains Shift+Enter execution but sends the explicit selection or a single line.
- **existing customization:** The execution behavior is contributed as ordinary VS Code command keybindings in package.json, so users can remove or reassign the shortcuts without changing the Python extension's default behavior.
