# Issue #25903 — Misleading Shift+Enter: python.REPL.enableREPLSmartSend

[https://github.com/microsoft/vscode-python/issues/25903](https://github.com/microsoft/vscode-python/issues/25903)

## Summary

Route to the REPL area as feedback on the default shortcut: Shift+Enter intentionally executes Python code, but that does not satisfy the reporter's expectation of inserting a newline. Disabling Smart Send changes the execution scope, not the shortcut's purpose.

## Change summary

Avoid unexpected execution of an enclosing Python block when Shift+Enter is pressed while editing a TODO comment.

## Best solution

Have the REPL owner assess whether the default execution shortcut needs a usability change, while preserving deliberate run-selection workflows. Keyboard-shortcut customization already lets this reporter avoid accidental execution, but it does not decide whether the extension's default should change.

- **Proposed comment:**

  > Thanks for the feedback. Shift+Enter is currently an execution shortcut in Python files. `python.REPL.enableREPLSmartSend: false` switches from runnable-block execution to single-line execution; it does not make the shortcut insert a newline. To prevent accidental execution, you can remove or change the Shift+Enter bindings for `python.execSelectionInTerminal` and `python.execInREPL` in Keyboard Shortcuts, then assign your preferred editing action. The concern about the default shortcut remains separate from that customization.
