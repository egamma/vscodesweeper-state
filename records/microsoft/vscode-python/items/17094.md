# Issue #17094 — Test discovery flow is unusual/weird

[https://github.com/microsoft/vscode-python/issues/17094](https://github.com/microsoft/vscode-python/issues/17094)

## Summary

The test-configuration flow still presents directory and filename-pattern quick picks without making the resulting configuration readily inspectable. Keep this accepted UX request open: existing settings offer manual customization, but do not resolve the onboarding confusion, and the related proposal is not a qualifying duplicate.

## Change summary

Make test setup clearer about directory selection, suggested filename patterns, and how to inspect or customize the generated configuration.

## Best solution

Agree on an understandable first-time configuration experience in the Python extension's testing area, including how users discover the saved settings and their customization options. Coordinate with https://github.com/microsoft/vscode-python/issues/21845 without requiring the broader configuration redesign to resolve this specific UX concern.

## Plan brief

- **Likely files:** `src/client/testing/common/testConfigurationManager.ts`, `src/client/testing/configuration/index.ts`, `src/client/testing/configuration/unittest/testConfigurationManager.ts`, `src/client/testing/configuration/pytest/testConfigurationManager.ts`, `src/client/testing/common/configSettingService.ts`
- **Validation:** In an Extension Development Host, invoke python.configureTests in a fresh workspace for unittest and pytest. Verify that directory choices and suggested patterns are distinguishable from discovered files, that the agreed inspection/customization affordance reaches the settings actually saved, and that discovery still finds tests using the selected directory and pattern. Repeat with a multi-root workspace to verify configuration remains scoped to the selected folder.
- **Behavior:**

  > First-time Python test setup should make it clear what directory is being selected and that filename-pattern choices are suggestions rather than discovered files or an exhaustive customization interface. Users should be able to understand and customize the configuration produced by setup. Acceptance checks should cover unittest and pytest setup, inspecting the saved values, and successful discovery using those values in single-root and multi-root workspaces.
- **Trace:**

  > python.configureTests in src/client/testing/main.ts enters UnitTestConfigurationService in src/client/testing/configuration/index.ts. The unittest ConfigurationManager invokes TestConfigurationManager.selectTestDir and selectTestFilePattern; the latter displays five pattern-label quick picks with descriptive text. The pytest ConfigurationManager also uses selectTestDir on its interactive configuration path. Configuration changes are buffered, then persisted by TestConfigSettingsService through WorkspaceConfiguration.update, with no configuration-reveal step in the traced flow. Existing python.testing.unittestArgs and python.testing.pytestArgs allow manual edits but do not explain the generated configuration during onboarding. Preserve framework argument semantics, workspace scoping, and discovery behavior; this request does not require changing test execution or implementing the broader proposal at https://github.com/microsoft/vscode-python/issues/21845.
- **Open decisions:**
  - Should first-time setup retain explicit directory/pattern prompts with clearer presentation, or use defaults with optional customization?
  - After setup, should the saved configuration open automatically, or should users receive an explicit action to inspect it?

## Evidence

- **Current configuration flow:** src/client/testing/main.ts registers python.configureTests and invokes UnitTestConfigurationService.promptToEnableAndConfigureTestFramework. src/client/testing/configuration/unittest/testConfigurationManager.ts then calls selectTestDir and selectTestFilePattern before saving arguments.
- **Reported presentation remains:** src/client/testing/common/testConfigurationManager.ts presents directories through showQuickPick and five filename-pattern choices with patterns as labels and explanations as descriptions. These are suggested patterns, not discovered files; the reported presentation is still present.
- **Existing-capability check:** package.json declares python.testing.unittestArgs with default arguments including '-s', '.', '-p', '*test*.py', and python.testing.pytestArgs with an empty default. These settings permit manual customization, but unittest configuration still prompts for both directory and pattern. src/client/testing/configuration/index.ts applies buffered settings without opening their configuration or offering an action to inspect it; src/client/testing/common/configSettingService.ts persists them through WorkspaceConfiguration.update.
- **Discussion and acceptance:** The supplied comments independently describe confusion between suggested patterns and actual workspace files. The September 2023 maintainer comment suggests revealing the saved configuration or offering a notification action.
