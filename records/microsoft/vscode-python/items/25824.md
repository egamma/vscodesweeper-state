# Issue #25824 — failing `pytest` tests are marked as “success” when some of the subtests succeeded

[https://github.com/microsoft/vscode-python/issues/25824](https://github.com/microsoft/vscode-python/issues/25824)

## Summary

Confirmed and still present on main: multiple pytest call-phase reports share the parent node ID, and the adapter publishes only the first result, allowing an early successful subtest to mask a later failure. The issue is already correctly routed to testing and marked as needing a PR.

## Change summary

Ensure a pytest test containing successful and failing subtests is reported as failed in the VS Code Test Explorer.

## Best solution

Update the pytest adapter to aggregate reports for a node until the final parent outcome is known, then publish the failed parent result without letting an earlier subtest claim its ID. Add a pytest 9 regression fixture with a passing subtest followed by a failing one under python_files/tests/pytestadapter.
