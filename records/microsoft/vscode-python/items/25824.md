# Issue #25824 — failing `pytest` tests are marked as “success” when some of the subtests succeeded

[https://github.com/microsoft/vscode-python/issues/25824](https://github.com/microsoft/vscode-python/issues/25824)

## Summary

The defect remains directly traceable on current main: the pytest adapter publishes only the first call-phase report for a node ID, allowing a successful subtest to hide a later failure. It is already accepted and correctly routed with `area-testing` and `needs PR`.

## Change summary

Aggregate pytest subtest reports so any failed subtest marks its parent test as failed in Test Explorer.

## Best solution

Update `python_files/vscode_pytest/__init__.py` to aggregate all reports sharing a node ID and publish the final parent outcome only after accounting for failed subtests, with regression coverage for mixed passing and failing pytest 9 subtests.
