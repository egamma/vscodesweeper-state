# Issue #25134 — Vscode doesn't know which Python virtualenv to use if there there are multiple python projects opened

[https://github.com/microsoft/vscode-python/issues/25134](https://github.com/microsoft/vscode-python/issues/25134)

## Summary

Keep open: the original steps are sufficient to retest interpreter isolation between two project windows. Environment selection has since moved to the Python Environments integration, but neither a fix nor reproduction of the original failure on that path is established.

## Change summary

Opening project B in a second VS Code window incorrectly uses project A's virtualenv instead of B's previously selected interpreter.

## Best solution

Ensure each project window restores its own selected interpreter and supplies that environment to language analysis. Reproduce the original two-window sequence on the current integrated path, then identify whether selection persistence in Python Environments or the core extension's environment handoff is responsible; a maintainer can transfer this to https://github.com/microsoft/vscode-python-environments if ownership is established.
