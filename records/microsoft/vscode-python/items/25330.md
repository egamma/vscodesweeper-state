# Issue #25330 — Support for "behave" (or arbitrary) test framework

[https://github.com/microsoft/vscode-python/issues/25330](https://github.com/microsoft/vscode-python/issues/25330)

## Summary

Keep open for testing-area design: the request exceeded the documented community-feedback threshold, and current main still hard-codes pytest and unittest without a public framework-provider extension point. The linked documentation PR remains open and clarifies the limitation but does not implement the requested capability.

## Change summary

Add built-in Behave test discovery and execution, or expose an extension point through which arbitrary Python test frameworks can integrate with Test Explorer.

## Best solution

The testing area should decide whether to expose a supported test-framework provider API that reuses this extension's Python environment, discovery, execution, and debugging infrastructure. If that abstraction is not maintainable, Behave support should remain a dedicated extension using VS Code's Testing API rather than adding another hard-coded framework here.
