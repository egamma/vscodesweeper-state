# Issue #23448 — Multi-root workspace: Python resolves imports only from venv of first root-folder

[https://github.com/microsoft/vscode-python/issues/23448](https://github.com/microsoft/vscode-python/issues/23448)

## Summary

Multiple users confirm that folder-specific environments can collapse to the first root in multi-root workspaces, but the evidence spans both Pylance import resolution and Python-extension activation. No verified canonical issue or complete fix covers the report.

## Change summary

Ensure each folder in a multi-root workspace consistently uses its selected environment for import analysis and terminal activation.

## Best solution

Retest with current Python and Pylance releases and collect Python and Pylance trace logs for each workspace folder. A maintainer can then transfer the import-analysis portion to microsoft/pylance-release if Pylance receives the correct per-resource environment, while retaining any environment or terminal activation defect here.

## Evidence

- **independent confirmations:** Comments from 2024 through 2025 independently report that the first root's environment is used for other roots; one includes a Python-extension activation failure stating that command 'python.getRecommendedEnvironment' already exists.
- **current source:** src/client/activation/activationManager.ts activates services per workspace-folder URI, and src/client/interpreter/configuration/recommededEnvironmentService.ts resolves active environments using the supplied resource, so current intent is folder-specific behavior.
- **related Pylance fix is narrower:** https://github.com/microsoft/pylance-release/issues/7495 fixed the same first-folder symptom specifically for light language-server mode in Pylance 2026.2.101; it does not establish that this broader report, including terminal behavior, is resolved.
- **open Pylance variant:** https://github.com/microsoft/pylance-release/issues/6751 tracks hidden-directory files being assigned the first workspace environment, but its scope is narrower and therefore it is not a valid canonical duplicate for this report.
- **related item is not canonical:** https://github.com/microsoft/vscode-python/issues/25099 concerns a single-root Firebase environment and was closed after a local workaround, so it neither owns nor fixes this multi-root behavior.
