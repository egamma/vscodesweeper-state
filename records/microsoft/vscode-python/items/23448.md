# Issue #23448 — Multi-root workspace: Python resolves imports only from venv of first root-folder

[https://github.com/microsoft/vscode-python/issues/23448](https://github.com/microsoft/vscode-python/issues/23448)

## Summary

Keep open and route to environment selection and IntelliSense integration: several commenters confirm that import resolution uses the first root's interpreter despite separate selections. Current main fixes a later command-registration failure, but that does not establish a fix for the original 2024 report; the supplied steps suffice to retest.

## Change summary

Import resolution in a multi-root workspace uses the first folder's virtual environment instead of each file's folder-specific interpreter.

## Best solution

Establish where folder-specific interpreter information is lost between Python workspace activation and Pylance configuration, then restore independent import resolution for each root. If Python supplies the correct scoped interpreter and Pylance ignores it, a maintainer can transfer this to https://github.com/microsoft/pylance-release.

## Evidence

- **Concrete reproduction and independent confirmations:** https://github.com/microsoft/vscode-python/issues/23448 supplies two roots, separately selected Python 3.12 and 3.9 environments, and pyserial installed only in the second environment. Runtime execution succeeds there, but Pylance reports missing imports until the first root also selects that environment. Comments dated 2024-11-30 and 2025-04-08 independently confirm the first-root dependency; https://github.com/microsoft/vscode-python/issues/23448#issuecomment-3048085717 confirms it again with activation logs. These are discussion-confirmed reproductions, not a current-main execution.
- **Current source preserves resource scope:** src/client/activation/languageClientMiddlewareBase.ts:80-90 derives a URI from each configuration item's scopeUri and obtains pythonPath through getActiveInterpreter(uri). src/client/interpreter/interpreterService.ts:256-265 keys interpreter resolution by workspace folder, and resolveActiveInterpreter at lines 320-331 forwards the resource to the environments-extension bridge or scoped configuration. src/client/environmentApi.ts:159-176 also reads getSettings(resource). These intended scoped paths do not conclusively reproduce the reported first-root substitution.
- **Partial fix does not cover the original trigger:** https://github.com/microsoft/vscode-python/commit/d48d1242833c3e579d9e08ea549ba7ac3a243357, committed 2026-05-07, adds hasRegisteredCommand and an early return in RecommendedEnvironmentService.activate to prevent repeated python.getRecommendedEnvironment registration. Its test checks registration once across multiple roots, not independent import resolution. This addresses the error in the July 2025 comment, but the service's history begins in May 2025, after the original May 2024 report. The commit fixes https://github.com/microsoft/vscode-python/issues/25949, not demonstrably this issue's full scope.
