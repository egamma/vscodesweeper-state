[https://github.com/microsoft/vscode-python/issues/25735](https://github.com/microsoft/vscode-python/issues/25735)

## Summary

Keep this team-authored, accepted investigation open: current source still leaves interpreter-setting ownership unresolved, although some listed flows already delegate to Python Environments. Neither the related sibling fix nor an older overwrite report covers the full audit and API-contract question.

## Change summary

Audit interpreter-selection writes and decide whether either extension should modify python.defaultInterpreterPath when Python Environments manages selection.

## Best solution

Establish a consistent ownership contract that preserves the user-configured fallback and keeps explicit environment selection working through extension APIs. Complete the audit across global settings, workspace selection storage, prompting, and environment creation before deciding what to deprecate.

- **Setting writes differ from selection storage:** src/client/common/interpreterPathService.ts:107-135 shows that InterpreterPathService.update writes python.defaultInterpreterPath only for ConfigurationTarget.Global; workspace and workspace-folder updates write persistent selection state instead.
