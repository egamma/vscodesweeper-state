# Issue #21826 — Unit Tests with unittest do not show as failed if the setUpClass method raises an exception

[https://github.com/microsoft/vscode-python/issues/21826](https://github.com/microsoft/vscode-python/issues/21826)

## Summary

Keep open: current source still drops unittest class-setup errors because their synthetic identifiers do not match discovered TestItems. The existing area-testing and needs PR labels correctly describe the remaining work.

## Change summary

Surface setUpClass exceptions in the Testing pane and editor instead of leaving misleading previous test results.

## Best solution

Make class-setup errors visible on the affected test hierarchy with their traceback, and ensure tests prevented from running do not appear to retain a successful current result. Preserve unittest's distinction between a fixture error and a failed test assertion.
