# Issue #20211 — `${env:<VARIABLE>}`  substitution is no longer working for `.env` files

[https://github.com/microsoft/vscode-python/issues/20211](https://github.com/microsoft/vscode-python/issues/20211)

## Summary

The substitution gap remains directly visible on current main: the `.env` parser accepts `${NAME}` but deliberately leaves `${env:NAME}` unchanged. The issue already has the correct environment-area and accepted-work labels, while the broader standardization tracker has not yet settled whether this syntax should be restored or replaced.

## Change summary

Restore consistent substitution of process environment variables referenced from `.env` files, including the documented `${env:VARIABLE}` form or a clearly documented replacement.

## Best solution

Implement one dotenv-compatible substitution model in the Python Environments extension and expose it consistently to core Python-extension consumers, then document the supported syntax. Keep this concrete regression open until https://github.com/microsoft/vscode-python/issues/18307 explicitly absorbs it or the shared implementation lands.
