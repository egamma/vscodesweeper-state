# Issue #20211 — `${env:<VARIABLE>}`  substitution is no longer working for `.env` files

[https://github.com/microsoft/vscode-python/issues/20211](https://github.com/microsoft/vscode-python/issues/20211)

## Summary

Current main still handles `.env` substitution inconsistently: `${NAME}` is supported, while `${env:NAME}` is explicitly rejected by the parser. The issue is accepted environment work carrying `needs PR`, and neither the narrower debugger issue nor the broader meta tracker is a valid duplicate canonical.

## Change summary

Make environment-variable substitution syntax work consistently in `.env` files instead of requiring different forms in different extension flows.

## Best solution

Standardize `.env` parsing and substitution across the core extension and the Python Environments extension, using one documented syntax for process and earlier-file variables. Coordinate this concrete bug with the broader design work in https://github.com/microsoft/vscode-python/issues/18307 without closing it as a duplicate of that meta tracker.

## Evidence

- **process-variable path:** src/client/common/variables/environmentVariablesProvider.ts passes the current process environment to parseFile as base variables, so `${NAME}` can resolve a process variable while `${env:NAME}` cannot.
- **tests:** src/test/common/variables/envVarsService.unit.test.ts covers `${NAME}` substitution from earlier entries and base variables, but has no coverage establishing consistent `${env:NAME}` behavior.
- **accepted work:** The issue currently carries `bug`, `debt`, `area-environments`, and `needs PR`; a maintainer also stated that documentation support was being removed only until the behavior could be fixed.

- **debugger scope:** https://github.com/microsoft/vscode-python-debugger/issues/159 remains open for the narrower debugging path; the discussion on this issue explicitly distinguishes that debugger-only defect from inconsistent substitution across other consumers.
