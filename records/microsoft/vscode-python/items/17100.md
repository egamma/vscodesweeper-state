# Issue #17100 — Error discovering pytest too aggressive

[https://github.com/microsoft/vscode-python/issues/17100](https://github.com/microsoft/vscode-python/issues/17100)

## Summary

Keep open: automatic discovery still surfaces collection errors without distinguishing an autosaved, unfinished test from an explicit user action. The existing needs proposal and partner ask labels support deciding a less intrusive error-reporting policy rather than closing this accepted work.

## Change summary

Make discovery errors less intrusive while users write tests with autosave enabled, while retaining actionable errors on explicit test runs.

## Best solution

Define and implement an editing-aware discovery-error policy in the core testing integration that preserves useful test-tree state without concealing failures when users explicitly run tests. Decide which automatic discovery failures qualify for deferred presentation.

- **Fit:** aligned

- **Evidence:** The public roadmap goal is Python support that is "fast, stable, and useful to anyone writing Python code for whatever reason"; testing integration is also a durable theme.

## Plan brief

- **Likely files:** `src/client/testing/testController/controller.ts`, `src/client/testing/testController/common/resultResolver.ts`, `src/client/testing/testController/common/testDiscoveryHandler.ts`, `src/test/testing/testController/controller.unit.test.ts`, `src/test/testing/testController/common/testDiscoveryHandler.unit.test.ts`
- **Validation:** After agreeing the policy, cover automatic versus explicit discovery-error presentation in the controller and TestDiscoveryHandler unit suites. Manually discover a valid pytest file, enable autosave, append an incomplete test declaration, and verify that the editing-time presentation follows the policy; explicitly run tests and verify that the collection failure is visible, then complete the declaration and verify recovery.
- **Behavior:**

  > With autosave and automatic discovery enabled, writing an unfinished test currently produces a visible discovery error in Test Explorer. The desired experience is less disruptive during editing while retaining useful previously discovered test context and making failures actionable when tests are explicitly run. Acceptance should cover an incomplete declaration, an explicit run before it is completed, and successful discovery after completion. The exact classes of automatically discovered errors that receive deferred presentation require agreement.
- **Trace:**

  > PythonTestController.watchForTestContentChangeOnSave in src/client/testing/testController/controller.ts schedules discovery after saves, including autosaves. The pytest plugin records collection exceptions in python_files/vscode_pytest/__init__.py and sends error-status discovery payloads. PythonResultResolver.resolveDiscovery delegates to TestDiscoveryHandler.processDiscovery, which creates an error node without distinguishing an automatic save-triggered refresh from an explicit action. The handler also processes available tests despite errors, so hiding an error alone does not establish preservation of prior tree state. Preserve automatic discovery and actionable failure diagnostics; replacing pytest collection semantics or changing terminal/environment behavior is outside this request. The related unittest report at https://github.com/microsoft/vscode-python/issues/17104 was explicitly consolidated into this issue.
- **Open decisions:**
  - Should deferred presentation apply only to transient syntax or indentation errors during automatic discovery, or to every automatic discovery failure while previously discovered tests exist?
  - Should an explicit Refresh Tests action expose deferred failures immediately, as an explicit Run Tests action would, or should refresh retain the quieter editing-time presentation?

## Evidence

- **Concrete editing trigger:** https://github.com/microsoft/vscode-python/issues/17100 describes typing an incomplete def test_math2(): declaration; the reporter explicitly confirmed that autosave was enabled. The request concerns when collection failures are presented, not whether pytest should accept invalid Python.
- **Current automatic discovery path:** src/client/testing/testController/controller.ts:1125-1138 registers watchForTestContentChangeOnSave, which triggers discovery on matching saved documents when autoTestDiscoverOnSaveEnabled is true. The controller's refresh delay is 250 ms; there is no incomplete-edit presentation policy in this save handler.
- **Current error presentation:** python_files/vscode_pytest/__init__.py:186-203 records discovery exceptions, and create_compact_discovery_payload at lines 1057-1070 marks payloads as error when ERRORS is nonempty. PythonResultResolver.resolveDiscovery forwards payloads to TestDiscoveryHandler.processDiscovery, which creates a visible discovery-error node for every error payload before processing available tests, without an automatic-versus-explicit presentation distinction.

Disabling discovery on save avoids this trigger but also removes automatic discovery; these settings do not retain automatic discovery while selectively deferring intrusive errors.
