# Issue #17100 — Error discovering pytest too aggressive

[https://github.com/microsoft/vscode-python/issues/17100](https://github.com/microsoft/vscode-python/issues/17100)

## Summary

The aggressive autosave error remains source-reproducible on main, and this accepted proposal is the canonical tracker. Automatic discovery still creates a prominent error node for transient collection failures even when pytest returns discovered tests.

## Change summary

Avoid prominently reporting transient pytest discovery errors while a user is autosaving an incomplete test.

## Best solution

Distinguish watcher-triggered discovery from explicit user actions in the testing controller, preserving discovered tests and suppressing transient error nodes during autosave while still surfacing errors after an explicit refresh or run. The likely implementation boundary is `controller.ts` and `common/testDiscoveryHandler.ts`, with the existing discovery-trigger metadata carried into result handling.
