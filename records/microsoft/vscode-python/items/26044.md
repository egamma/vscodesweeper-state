# Issue #26044 — Send line to terminal does nothing after sleep or terminal crash

[https://github.com/microsoft/vscode-python/issues/26044](https://github.com/microsoft/vscode-python/issues/26044)

## Summary

Current main can retain a workspace-specific terminal and REPL-ready state after its shell process exits, causing subsequent Run Selection/Line commands to send to a dead terminal. Route this open bug to the terminal area.

## Change summary

Run Selection/Line should recreate its Python terminal when the previous terminal process dies or becomes unusable after sleep.

## Best solution

Invalidate the cached terminal and REPL state when its process exits or becomes unavailable, then create and initialize a fresh terminal on the next execution. The lifecycle handling belongs in src/client/common/terminal/service.ts and src/client/terminals/codeExecution/terminalCodeExecution.ts.

## Evidence

- **stale terminal path:** src/client/common/terminal/service.ts:213-223 treats any cached Terminal object as usable and does not inspect its exitStatus; executeCommand at lines 91-100 consequently sends directly when isReplReady remains true.
- **incomplete lifecycle reset:** src/client/common/terminal/service.ts:249-256 clears the terminal and REPL state only from onDidCloseTerminal. A shell process that exits while its terminal remains present leaves the cached object and ready state intact.
- **workspace-specific cache:** src/client/common/terminal/factory.ts:27-48 caches TerminalService instances using an identifier containing the workspace folder, matching the report that one project remains broken while another works.
- **provider cache:** src/client/terminals/codeExecution/terminalCodeExecution.ts:66-111 reuses replActive and resets it only through the terminal service's close event, so an exited process not represented as a terminal close can remain falsely active.
- **canonical search:** The open Run Selection/Line issues found concern IPython, pyreadline3, selection size, or choosing an existing terminal; none owns recovery from a terminal process dying after sleep.
