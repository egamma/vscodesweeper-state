# Issue #11736 — Argument filtering for pytest fails to handle custom arguments

[https://github.com/microsoft/vscode-python/issues/11736](https://github.com/microsoft/vscode-python/issues/11736)

## Summary

Keep open: current discovery forwards custom arguments, but execution still strips separately supplied custom-option values. The reported filtering defect remains relevant, and the newer testing-configuration proposal is related work rather than a duplicate canonical.

## Change summary

Preserve pytest custom options and their values when filtering configured arguments for Test Explorer operations.

## Best solution

Ensure pytest receives custom option/value pairs unchanged during run and debug while preserving execution of only the selected tests. Coordinate this correction with the testing-configuration proposal without making this accepted bug depend on that broader redesign.

- **Behavior:**

  > A custom pytest option registered through pytest_addoption must receive its configured value during discovery, run, and debug whether supplied as separate array entries or as --option=value. Currently the separate value is removed during execution. Acceptance requires the fixture to observe app/config.json and only the selected test to execute. Custom boolean options and ordinary test-directory arguments must retain their intended behavior.
- **Trace:**

  > PytestTestExecutionAdapter calls removePositionalFoldersAndFiles before both normal execution and debug launch construction. That function uses getPositionalArguments with static lists of recognized pytest options; unknown options are treated as valueless, so their following values are removed as test paths. Discovery now forwards the configured array after root-directory handling, and the Python execution runner forwards the already-filtered array to pytest.main. The defect is established by tracing the exact reported array through these functions, without executing code. The unresolved technical boundary is obtaining enough information about plugin-defined option arity to preserve custom values without retaining test paths that would broaden a selected run; simply assuming every unknown option consumes its next token is unsafe. Preserve current selected-test execution, known-option handling, and discovery behavior. The broader proposal at https://github.com/microsoft/vscode-python/issues/21845 is related context, not a duplicate or a prerequisite for deciding the reported expected behavior.
