# Issue #25042 — Kernel is lost in the middle of working with a notebook

[https://github.com/microsoft/vscode-python/issues/25042](https://github.com/microsoft/vscode-python/issues/25042)

## Summary

Route to environment discovery: current native API code can report an explicitly resolved, still-valid venv as deleted when a subsequent discovery refresh omits it, matching the supplied logs preceding kernel disposal. Neither related issue establishes that this reopened report is fixed or redundant.

## Change summary

Notebook kernels disappear during work because Python reports their unchanged virtual environments as removed.

## Best solution

Keep valid, explicitly resolved environments available through discovery refreshes without emitting false deletion events to Jupyter, while preserving removal of genuinely deleted environments. Address the native API reconciliation path here rather than treating the notebook symptom alone as a Jupyter routing issue.
