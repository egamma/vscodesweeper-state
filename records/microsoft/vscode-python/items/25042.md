# Issue #25042 — Kernel is lost in the middle of working with a notebook

[https://github.com/microsoft/vscode-python/issues/25042](https://github.com/microsoft/vscode-python/issues/25042)

## Summary

Keep open and route to environments: two captured incidents show the Python environment API transiently removing a still-existing venv, after which Jupyter invalidates its controller and loses the selected kernel. The issue is assigned and marked `needs PR`, and no post-reopen fix or open implementation PR was found.

## Change summary

A still-existing virtual environment is intermittently reported as deleted, causing an active notebook to lose its kernel and in-memory state.

## Best solution

Prevent transient environment-discovery changes from emitting a deletion for an interpreter that remains accessible, or preserve the active environment until deletion is verified. Coordinate that Python-side correction with the open VS Code Snap XDG issue at https://github.com/microsoft/vscode/issues/237608, since Snap path remapping may trigger the discovery instability but does not replace the need to handle environment events safely.
