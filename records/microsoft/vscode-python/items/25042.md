# Issue #25042 — Kernel is lost in the middle of working with a notebook

[https://github.com/microsoft/vscode-python/issues/25042](https://github.com/microsoft/vscode-python/issues/25042)

## Summary

Keep open and route to environments: repeated logs show the Python extension incorrectly reporting an existing virtual environment as deleted, causing Jupyter to dispose its active controller. A maintainer subsequently marked the accepted work as `needs PR`.

## Change summary

Prevent an existing virtual environment from being transiently reported as deleted and disconnecting its active notebook kernel.

## Best solution

Make environment discovery resilient to transient locator or Snap/XDG path changes so an environment is removed only after its interpreter is genuinely unavailable. Coordinate with the open VS Code Snap issue, but retain the Python-side fix unless that issue is confirmed to resolve the erroneous removal event.
