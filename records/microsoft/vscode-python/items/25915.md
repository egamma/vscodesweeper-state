- **Behavior:**

  > With IPython selected through python.terminal.launchArgs, Run Selection/Line in Python Terminal should execute the selection after the interpreter becomes ready, including on the first invocation that creates the terminal. The reporter instead receives an idle In [1]: prompt with no selected code. Acceptance requires first and subsequent selections to execute exactly once without manual terminal input, while ordinary CPython execution continues to work.
- **Trace:**

  > CodeExecutionManager.executeSelection() normalizes code and calls TerminalCodeExecutionProvider.execute(), which initializes the REPL and delegates to TerminalService.executeCommand(code, true). TerminalService queues input until startReplListener() observes either a python shell-state change or a >>> prompt; the reported IPython prompt satisfies neither textual condition. The provider's initialization timeout does not release the service's queue. This establishes a plausible blocking path, not the actual WSL event sequence: reproduce first and inspect whether shell-state readiness is absent or arrives before listener registration.
