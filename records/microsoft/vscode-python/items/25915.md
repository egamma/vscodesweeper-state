# Issue #25915 — Run selection/line in terminal fails with IPython

[https://github.com/microsoft/vscode-python/issues/25915](https://github.com/microsoft/vscode-python/issues/25915)

## Summary

The failure remains traceable on current main: terminal REPL commands are queued until a standard Python prompt is detected, but IPython's prompt never satisfies that readiness check. Route this to the terminal area as a confirmed bug.

## Change summary

Running a line or selection does not send the code when python.terminal.launchArgs starts IPython.

## Best solution

Update REPL readiness handling in src/client/common/terminal/service.ts to support IPython launched through python.terminal.launchArgs, then cover the IPython prompt and queued-command flow with terminal execution tests.

## Evidence

- **source-reproducible path:** src/client/terminals/codeExecution/terminalCodeExecution.ts uses python.terminal.launchArgs to start the configured REPL and sends normalized selections through ITerminalService.executeCommand(..., true).
- **readiness mismatch:** src/client/common/terminal/service.ts queues Python-shell commands while isReplReady is false, but its textual readiness detector only matches a trailing >>> prompt. The reported IPython prompt, "In [1]:", cannot trigger that path, leaving the selection queued.
- **matching diagnostic:** The issue log shows normalizeSelection.py completing without the subsequent "Send text to terminal" entry, consistent with the current source queuing the normalized command rather than sending it.
- **not a verified duplicate:** https://github.com/microsoft/vscode-python/issues/22139 requests a broader integrated IPython experience, including automatic startup and %run behavior; it does not own this specific regression in the existing python.terminal.launchArgs execution path.
