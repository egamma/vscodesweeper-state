# Issue #25463 — getPythonEnvironmentInfo tool fails for venv created with uv

[https://github.com/microsoft/vscode-python/issues/25463](https://github.com/microsoft/vscode-python/issues/25463)

## Summary

The failure remains in current main: an empty package result from the environments extension incorrectly falls through to the legacy `python -m pip list` path, which fails for uv-created environments without pip. Route this confirmed integration bug to the environments area.

## Change summary

Make getPythonEnvironmentInfo handle uv-created virtual environments that do not contain pip.

## Best solution

In `src/client/chat/getPythonEnvTool.ts`, treat an empty array from `getPackages` as a successful result with no packages; use the legacy pip fallback only when the environments API returns `undefined` or is unavailable.

## Evidence

- **source defect:** `src/client/chat/getPythonEnvTool.ts:77-100` accepts the environments extension package result only when `pkgs.length > 0`; an empty uv environment therefore falls through to `getPythonPackagesResponse`.
