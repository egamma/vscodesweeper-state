# Issue #25463 — getPythonEnvironmentInfo tool fails for venv created with uv

[https://github.com/microsoft/vscode-python/issues/25463](https://github.com/microsoft/vscode-python/issues/25463)

## Summary

Still present on current main: the environment extension can successfully return an empty package list for a new uv environment, but the chat tool treats that valid result as a failure and falls back to `python -m pip list`, which fails because uv-created environments do not include pip by default.

## Change summary

The environment-information chat tool fails to inspect a newly created uv virtual environment that has no pip module.

## Best solution

In `src/client/chat/getPythonEnvTool.ts`, distinguish an empty package array from an unavailable package result: return "No packages found" for an empty array and use the legacy pip fallback only when `getPackages` returns `undefined`. Route the fix through the environments area and classify the report as a bug rather than a feature request.

## Evidence

- **confirmed reproduction:** The reporter reproduced the original failure on extension version 2025.20.0 with `alwaysUseUv` enabled: a fresh `uv venv` followed by `getPythonEnvironmentInfo` returns `Error: Module 'pip' not installed.`
- **source defect:** `src/client/chat/getPythonEnvTool.ts` calls the environment extension's `getPackages`, but accepts its result only when `pkgs.length > 0`; a valid empty array therefore leaves `packages` empty and triggers the legacy fallback.
- **failing fallback:** `src/client/chat/listPackagesTool.ts` implements the non-conda fallback by executing the selected interpreter with module `pip` and arguments `list`, which produces the reported error for a fresh uv environment without pip.
- **API contract:** `src/client/envExt/types.ts` documents `getPackages` as returning an array of packages or `undefined` when packages could not be retrieved, so an empty array is a successful result and must not be conflated with `undefined`.
