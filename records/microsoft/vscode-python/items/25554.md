# Issue #25554 — Conda/Miniforge environments not detected as Jupyter kernels in VSCode (2025.x extension versions)

[https://github.com/microsoft/vscode-python/issues/25554](https://github.com/microsoft/vscode-python/issues/25554)

## Summary

This remains a confirmed cross-platform regression: environments found by the native locator are not consistently exposed through the Python API, causing interpreter and Jupyter kernel selection failures. Route it to the environments area while maintainers determine whether the fix belongs in this repository's integration layer or the Python Environments extension.

## Change summary

Conda and other discovered environments disappear from interpreter and Jupyter kernel pickers when the Python Environments integration is active.

## Best solution

Ensure environments discovered by PET are surfaced with stable absolute executable paths through the Python extension API consumed by Jupyter. Coordinate with https://github.com/microsoft/vscode-python-environments/issues/1671 and transfer or consolidate only after confirming which side of the API boundary drops the discovered environments.

## Evidence

- **confirmed regression:** The reporter isolated the regression to the Python extension and found that 2024.22.2 worked while 2025.0.0 did not; later commenters reproduced it through 2026.5 builds on macOS and Windows.
- **locator/API mismatch:** PET logs show the affected Conda environments and absolute paths are discovered, while Jupyter reports that corresponding tilde-form paths cannot be resolved through the Python API.
- **integration boundary:** src/client/envExt/envExtApi.ts converts Python Environments API records for legacy consumers, while src/client/envExt/api.internal.ts delegates exact-path resolution to the Python Environments extension.
- **independent corroboration:** https://github.com/microsoft/vscode-python-environments/issues/1671 is open and independently reports that Conda environments are discovered successfully but omitted from the interpreter picker.
- **workaround:** A Windows reporter confirmed that fully disabling the Python Environments extension restores the Conda environments, whereas python.useEnvironmentsExtension=false alone does not.
- **canonical assessment:** https://github.com/microsoft/vscode-python/issues/26057 is newer and narrower, covering a Windows Native Locator registration failure; it does not own this report's broader, older cross-platform Python API and Jupyter kernel regression.
