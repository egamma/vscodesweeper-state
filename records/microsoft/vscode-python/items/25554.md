# Issue #25554 — Conda/Miniforge environments not detected as Jupyter kernels in VSCode (2025.x extension versions)

[https://github.com/microsoft/vscode-python/issues/25554](https://github.com/microsoft/vscode-python/issues/25554)

## Summary

The regression remains active across current releases and multiple platforms, with the strongest evidence implicating the Python Environments integration. Route it to the environments area for investigation rather than closing or consolidating it into a narrower locator issue.

## Change summary

Conda environments discovered by the environment tooling are not exposed through the Python API and consequently disappear from Jupyter's kernel picker.

## Best solution

Trace environment records from the Python Environments extension through the adapter in `src/client/envExt/envExtApi.ts`, ensuring every discovered Conda environment is exported with its fully qualified executable path. A maintainer should transfer the issue to `microsoft/vscode-python-environments` only if the malformed or missing record originates there rather than in this repository's adapter.

## Evidence

- **confirmed regression:** The reporter isolated the regression to the Python extension and found that 2024.16.0 works while 2025.x does not; several later commenters independently reproduced it through Python extension 2026.5.2026070801 on macOS and Windows.
- **locator output:** PET logs supplied in the discussion show the affected Miniforge environments are discovered, while the Jupyter-facing Python API cannot find their interpreter paths.
- **integration boundary:** `src/client/envExt/envExtApi.ts` converts Python Environments API records into `PythonEnvInfo` objects consumed by this extension's discovery API, deriving executable paths in `getExecutable()` and publishing them through `getEnvs()`.
- **tilde interpretation:** `src/client/common/process/logger.ts` intentionally replaces the user's home directory with `~` in logged commands, so the displayed tildes alone do not prove that unexpanded paths are used internally.
- **current workaround:** The latest Windows confirmation reports that fully disabling the Python Environments extension restores Conda environments immediately, whereas `python.useEnvironmentsExtension: false` does not.
- **no verified canonical:** https://github.com/microsoft/vscode-python/issues/26057 is open but covers a narrower Windows Native Locator registration failure that is resolved by selecting the JS locator; it does not clearly own this cross-platform Jupyter/API regression.
- **related sibling issue:** https://github.com/microsoft/vscode-python-environments/issues/1013 reported overlapping interpreter-selection failures but was closed for missing information, so it cannot serve as a duplicate canonical.
