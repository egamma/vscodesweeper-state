# Issue #25554 — Conda/Miniforge environments not detected as Jupyter kernels in VSCode (2025.x extension versions)

[https://github.com/microsoft/vscode-python/issues/25554](https://github.com/microsoft/vscode-python/issues/25554)

## Summary

This remains a confirmed environment-discovery regression across current Python extension versions and multiple platforms. Route it to the environments area; a newer sibling report identifies a plausible compatibility-adapter failure, but the evidence does not yet prove that it accounts for this report's full history.

## Change summary

Conda and Miniforge interpreters discovered by the environment locator are omitted from the Python API and Jupyter kernel picker.

## Best solution

Make the Python Environments compatibility adapter tolerate individual Conda environments that lack Python or otherwise have nonstandard version metadata, without dropping the rest of an environment update batch. Confirm whether that explains this report and then consolidate with https://github.com/microsoft/vscode-python-environments/issues/1671 if the root cause matches.

## Evidence

- **confirmed regression:** The reporter isolated the regression to the Python extension: Jupyter 2025.9.1 discovers the environments with Python 2024.16.0, while updating only Python to 2025.17 breaks discovery.
- **current confirmations:** Several independent reports confirm the behavior through Python 2026.5 prerelease builds on macOS and Windows; the 2026-08-03 Windows report says disabling ms-python.vscode-python-envs immediately restores the Conda environments.
- **related diagnosed report:** https://github.com/microsoft/vscode-python-environments/issues/1671 is open and tracks the same missing-Conda-environments symptom. A maintainer traced that case to the Python extension compatibility adapter failing when a Conda environment has no Python, and reporters confirmed that installing Python into the empty environment restores both interpreter and Jupyter kernel selection.
- **current source:** src/client/envExt/envExtApi.ts converts every environment with parseVersion(pythonEnv.version) and processes additions in one forEach batch without isolating conversion failures; src/client/pythonEnvironments/base/info/pythonVersion.ts throws for values such as no-python. This supports the diagnosed sibling-report failure mode, but the original reporter has not confirmed an environment without Python.
- **not a verified duplicate:** The original report includes an earlier tilde-path/conda-command failure and predates the diagnosed no-python scenario, so resolving https://github.com/microsoft/vscode-python-environments/issues/1671 is not yet proven to resolve this issue's entire scope.
