# Issue #22547 — Python REPL isn't restarted after exiting and rerunning shift+enter

[https://github.com/microsoft/vscode-python/issues/22547](https://github.com/microsoft/vscode-python/issues/22547)

## Summary

The terminal REPL lifecycle defect remains present, but an older open issue already covers the same observable failure after exit(): Python selections are sent to the shell instead of restarting the interpreter. Consolidate this report into that issue, preserving the additional restored-terminal scenario.

## Change summary

After exiting a terminal Python REPL, Shift+Enter sends Python code to the underlying shell without restarting Python.

## Best solution

Resolve terminal execution-state handling under https://github.com/microsoft/vscode-python/issues/2997 so selection execution starts Python whenever the reused terminal is no longer running its REPL. Preserve this report's exit() reproduction and the restored-terminal observations in that discussion.

- **Same reporter-observable symptom:** https://github.com/microsoft/vscode-python/issues/2997#issuecomment-541017984 explicitly reproduces exiting the REPL with exit(), then running a selection: Python is not initialized again and print("hello") is executed at the command prompt. This satisfies the re-reviewed item's requirement for an older canonical with the same observable symptom, not merely a related root cause.
- **Current source retains the defect:** src/client/terminals/codeExecution/terminalCodeExecution.ts: TerminalCodeExecutionProvider.initializeRepl returns immediately when its cached replActive promise resolves true; the registered invalidation is terminal closure, not interpreter exit. execute then calls executeCommand(code, true). In src/client/common/terminal/service.ts, TerminalService marks isReplReady true after detecting Python readiness, disposes its readiness listeners, and subsequently sends Python code directly with terminal.sendText without checking that Python is still running.
- **Additional evidence to preserve:** The 2024-09-10 comment on https://github.com/microsoft/vscode-python/issues/22547 additionally reports restored terminals still named Python but running bash, zsh, or PowerShell, with imports reaching the shell, temporary freezes, and files being created. Preserve these observations as an additional lifecycle scenario; the restored-terminal path was not independently reproduced.
