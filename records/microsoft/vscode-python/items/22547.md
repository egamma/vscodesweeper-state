# Issue #22547 — Python REPL isn't restarted after exiting and rerunning shift+enter

[https://github.com/microsoft/vscode-python/issues/22547](https://github.com/microsoft/vscode-python/issues/22547)

## Summary

Still present on current main: terminal REPL state is cleared only when the terminal closes, so exiting Python leaves Shift+Enter sending Python code to the underlying shell. The existing terminal and REPL area labels already route this correctly.

## Change summary

Restart the terminal Python REPL when Shift+Enter is used after the previous REPL exited or a restored terminal no longer contains a Python process.

## Best solution

Track terminal shell-state transitions in the terminal execution service, clear the cached REPL-ready state when the terminal leaves Python, and have the next Shift+Enter relaunch the selected interpreter before sending code. Cover both explicit exit() and restored-terminal scenarios.

## Evidence

- **source defect:** src/client/terminals/codeExecution/terminalCodeExecution.ts:66-111 treats replActive as valid until onDidCloseTerminal fires; exiting Python without closing the terminal therefore skips relaunching the interpreter.
- **stale readiness state:** src/client/common/terminal/service.ts:87-101 and 108-152 set isReplReady when Python starts but do not clear it when terminal.state.shell stops being python; it is reset only when the terminal closes at lines 250-255.
- **default affected path:** package.json:658-662 keeps python.REPL.sendToNativeREPL disabled by default, so Shift+Enter uses the affected terminal REPL path for default configurations.
- **maintainer confirmation:** A maintainer confirmed on https://github.com/microsoft/vscode-python/issues/22547 that the issue remained present and should eventually be resolved.
- **related PR does not fix:** https://github.com/microsoft/vscode-python/pull/24477 was closed without merging and proposed prompting users toward the Native REPL rather than correcting stale terminal REPL state.
