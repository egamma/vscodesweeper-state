# Issue #22547 — Python REPL isn't restarted after exiting and rerunning shift+enter

[https://github.com/microsoft/vscode-python/issues/22547](https://github.com/microsoft/vscode-python/issues/22547)

## Summary

The defect remains in the default terminal-REPL path on current main: REPL state is cleared only when the terminal closes, so exiting Python leaves subsequent Shift+Enter execution targeting the shell.

## Change summary

Restart the terminal Python REPL before sending code when the previous REPL process has exited but its terminal remains open.

## Best solution

Track termination of the Python shell execution in the terminal code-execution provider and clear its active-REPL state, allowing the next Shift+Enter invocation to relaunch Python before sending code.

## Evidence

- **current source:** src/client/terminals/codeExecution/terminalCodeExecution.ts:66-109 treats replActive as valid until onDidCloseTerminal fires; exiting Python without closing the terminal never clears that state.
- **default path:** package.json:658-662 defaults python.REPL.sendToNativeREPL to false, while package.json:1428-1436 routes execution to python.execSelectionInTerminal in that configuration, so the affected terminal REPL remains the default path.
- **independent confirmation:** A user confirmed the issue in September 2024, including restored terminals sending Python statements to the underlying shell, and a maintainer confirmed in November 2024 that it remained unresolved.
