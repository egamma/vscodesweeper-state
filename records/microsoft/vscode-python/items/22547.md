# Issue #22547 — Python REPL isn't restarted after exiting and rerunning shift+enter

[https://github.com/microsoft/vscode-python/issues/22547](https://github.com/microsoft/vscode-python/issues/22547)

## Summary

The defect remains on current main: terminal REPL state is cleared only when the terminal closes, so exiting Python while leaving the shell open causes later Shift+Enter executions to send Python code directly to that shell. The issue already has the correct REPL and terminal area labels and should remain open.

## Change summary

Restart the terminal Python REPL after its interpreter exits instead of sending subsequent Shift+Enter selections to the underlying shell.

## Best solution

Track the lifecycle of the Python process within the reused terminal and invalidate the cached REPL-active state when that process exits or when a persisted terminal is restored without an active interpreter. The next Shift+Enter should then launch Python again before sending code.

## Evidence

- **current source:** src/client/terminals/codeExecution/terminalCodeExecution.ts stores successful initialization in replActive and resets it only through terminalService.onDidCloseTerminal(); exiting the Python process without closing its terminal leaves replActive truthy.
- **failing path:** TerminalCodeExecutionProvider.initializeRepl() returns after showing the terminal whenever replActive resolves true, while execute() then calls executeCommand() on that same terminal; there is no check that a Python REPL process is still running.
- **default behavior:** package.json declares python.REPL.sendToNativeREPL with default false, so Shift+Enter continues through python.execSelectionInTerminal and the affected terminal REPL path by default.
- **independent confirmation:** A later report confirms the same stale-terminal behavior after VS Code restores a terminal, including Python selections being interpreted by bash, zsh, or PowerShell; a maintainer subsequently stated that the issue still existed.
- **related PR:** https://github.com/microsoft/vscode-python/pull/24477 explicitly identifies this bug but was closed without merging; its replacement, https://github.com/microsoft/vscode-python/pull/24734, only added a link for launching the Native REPL and resolved a different issue.
- **canonical search:** Searches for open terminal-REPL restart, Shift+Enter-after-exit, and code-sent-to-shell reports found no separate open canonical issue.
