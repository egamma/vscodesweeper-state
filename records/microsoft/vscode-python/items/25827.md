# Issue #25827 — Long startup time when running a test from the suite

[https://github.com/microsoft/vscode-python/issues/25827](https://github.com/microsoft/vscode-python/issues/25827)

## Summary

Keep open: the discussion confirms Pixi test-debug startup stalls during environment-variable capture, with two logged 30-second timeouts. Current source has a non-interactive Pixi path but also retains the problematic shell fallback; no verified fix or eligible canonical covers this test-startup report.

## Change summary

Starting or debugging a single pytest test in a Pixi environment incurs a substantial delay that does not occur when running pytest from the terminal.

## Best solution

Ensure Test Explorer obtains the selected Pixi environment's variables without waiting for an interactive shell to exit, including when the Python Environments integration supplies incomplete environment classification. Preserve normal terminal activation and coordinate the shared activation behavior with the related sibling reports.

- **Current activation paths:** src/client/interpreter/activation/service.ts:getActivatedEnvironmentVariablesImpl uses getRunPixiPythonCommand when interpreter.envType is EnvironmentType.Pixi. Otherwise it can concatenate activation commands with `&& echo ... && python ...` and execute them with ENVIRONMENT_TIMEOUT=30000. src/client/pythonEnvironments/common/environmentManagers/pixi.ts:getPixiActivationCommands still constructs interactive `pixi shell`; TerminalHelper's provider fallback can select that provider even without Pixi classification.
