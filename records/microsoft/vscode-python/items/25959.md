# Issue #25959 — [Request] Treat MSYS2 / Cygwin Python as a "Linux‑like" environment – use its own shell & Unix‑style paths

[https://github.com/microsoft/vscode-python/issues/25959](https://github.com/microsoft/vscode-python/issues/25959)

## Summary

A real capability gap remains: neither the Python terminal settings nor the current environment-extension execution API can associate an interpreter with a terminal profile or shell-native path mapping. Route this Windows-specific request to the terminal and environments owners.

## Change summary

Run and debug MSYS2/Cygwin interpreters through an associated Unix-like terminal profile using shell-native executable and file paths.

## Best solution

Define MSYS2/Cygwin execution metadata at the Python Environments integration boundary so run-file can select an appropriate terminal profile and translate executable, working-directory, and script paths consistently. The debugging portion should be coordinated with microsoft/vscode-python-debugger.

## Evidence

- **missing configuration surface:** package.json exposes python.terminal activation, working-directory, focus, launch-argument, and shell-integration settings, but no terminal-profile or interpreter-to-profile mapping.
- **current run-file path:** src/client/terminals/codeExecution/codeExecutionManager.ts passes fileToExecute.fsPath to runInTerminal, while src/client/envExt/api.internal.ts delegates only cwd, args, and show; PythonTerminalExecutionOptions in src/client/envExt/types.ts has no shell/profile selection field.
- **legacy behavior:** src/client/common/terminal/service.ts creates a generic terminal with only name and visibility options, and src/client/terminals/codeExecution/terminalCodeExecution.ts merely changes backslashes in the interpreter path to forward slashes on Windows rather than performing MSYS path translation.
