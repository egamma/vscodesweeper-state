# Issue #25959 — [Request] Treat MSYS2 / Cygwin Python as a "Linux‑like" environment – use its own shell & Unix‑style paths

[https://github.com/microsoft/vscode-python/issues/25959](https://github.com/microsoft/vscode-python/issues/25959)

## Summary

Route this to terminal and environment owners: the existing settings do not provide interpreter-specific shell selection or MSYS2/Cygwin path translation. No verified open canonical covers the full request, and this issue has not entered the community-feedback process.

## Change summary

Support interpreter-associated terminal profiles and shell-appropriate paths when running MSYS2 or Cygwin Python on Windows.

## Best solution

Determine the supported shell and path contract for MSYS2 UCRT64 versus Cygwin, coordinating Python Environments terminal execution with the core extension's run integration. Debugging behavior needs coordination with https://github.com/microsoft/vscode-python-debugger rather than assuming the run-file implementation also controls debugging.

## Evidence

- **Existing capabilities are partial:** package.json:613–650 declares python.terminal activation, working-directory, focus, launch-argument and shell-integration settings, but no interpreter-to-profile mapping. The registered python.createTerminal and python.execInTerminal commands do not establish such a mapping. Selecting a workspace-wide VS Code default profile is a workaround for shell choice, not coverage of interpreter-specific profiles or Unix-root path translation.
- **Current legacy execution path:** src/client/common/terminal/service.ts:ensureTerminal creates the legacy terminal with name and hideFromUser, without an interpreter-specific shellPath. src/client/terminals/codeExecution/terminalCodeExecution.ts:getExecutableInfo replaces Windows backslashes with forward slashes; src/client/common/extensions.ts:fileToCommandArgumentForPythonExt similarly quotes and normalizes separators. Neither operation maps C:/msys64/ucrt64/bin/python.exe to /ucrt64/bin/python or translates Cygwin mount paths.
- **Python Environments integration boundary:** src/client/terminals/codeExecution/codeExecutionManager.ts:registerCommands delegates run-file execution to executeUsingExtension when useEnvExtension() is true. That method forwards the formatted file.fsPath to runInTerminal or runInDedicatedTerminal; src/client/envExt/api.internal.ts delegates those operations to the Python Environments API. This establishes a sibling-extension coordination boundary, not proof that the requested behavior is already implemented there.
