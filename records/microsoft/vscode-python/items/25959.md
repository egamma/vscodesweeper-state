# Issue #25959 — [Request] Treat MSYS2 / Cygwin Python as a "Linux‑like" environment – use its own shell & Unix‑style paths

[https://github.com/microsoft/vscode-python/issues/25959](https://github.com/microsoft/vscode-python/issues/25959)

## Summary

A real capability gap remains: terminal execution follows the Windows host and VS Code's default terminal rather than associating a shell and path namespace with the selected MSYS2 interpreter. Route this to the terminal and environments areas for a product decision.

## Change summary

Allow an MSYS2 or Cygwin interpreter to use an associated Unix-like terminal profile and translate Windows paths into that shell's path namespace.

## Best solution

Provide an opt-in interpreter-to-terminal-profile association and path translation boundary for Run Python File, while coordinating the equivalent integrated-debug-terminal behavior with the Python Debugger extension. Preserve the current VS Code default-profile behavior when no association is configured.

## Evidence

- **current terminal creation:** src/client/common/terminal/service.ts creates Python terminals with only a name and visibility options, so it does not select a terminal profile based on the active interpreter.
- **current path handling:** src/client/terminals/codeExecution/terminalCodeExecution.ts:getExecutableInfo converts backslashes to forward slashes on Windows but retains the Windows drive-path namespace; executeFile likewise passes file.fsPath, so it does not produce MSYS2 paths such as /ucrt64/bin/python or /c/Users/...
- **existing settings:** package.json exposes activation, launch-argument, working-directory, focus, and shell-integration settings under python.terminal, but no interpreter-specific terminal profile or path-translation setting.
- **related request:** https://github.com/microsoft/vscode-python/issues/22277 requested MSYS2 interactive-interpreter support but was closed after its community-feedback window; it is closed and narrower than this request, so it is neither a valid duplicate canonical nor a decision covering the full Run Python File, debugging, and path-translation scope.
- **prior Cygwin support:** https://github.com/microsoft/vscode-python/pull/17431 added Cygwin-compatible .exe shell detection, and src/client/common/terminal/shellDetectors/baseShellDetector.ts still recognizes bash and zsh executables; shell recognition does not provide interpreter-to-profile association or path translation.
