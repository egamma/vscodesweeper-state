# Issue #20425 — Python unittest runner doesn't respect arguments to pass to unittest runner

[https://github.com/microsoft/vscode-python/issues/20425](https://github.com/microsoft/vscode-python/issues/20425)

## Summary

The reported argument loss remains directly traceable on current main: the unittest adapter silently discards --silly and continues execution. Keep this accepted testing issue open; the related design proposals do not qualify as duplicate canonicals.

## Change summary

The unittest runner silently ignores unsupported arguments in python.testing.unittestArgs instead of reporting an invalid invocation.

## Best solution

Make ordinary unittest invocations report invalid configured arguments rather than running successfully after discarding them, while preserving valid unittest options and Django argument forwarding. Address this concrete defect without requiring the broader testing-configuration redesign.
