# Issue #25603 — Use env extension for execute selection

[https://github.com/microsoft/vscode-python/issues/25603](https://github.com/microsoft/vscode-python/issues/25603)

## Summary

Keep this accepted, team-authored request open: selection execution still uses the compatibility execution provider rather than the environment-extension execution API used for files. Environment selection and terminal creation already delegate indirectly, but that does not establish completion of the requested migration.

## Change summary

Extend Python Environments integration to Run Selection/Line in Python Terminal.

## Plan brief

- **Likely files:** `src/client/terminals/codeExecution/codeExecutionManager.ts`, `src/client/terminals/codeExecution/terminalCodeExecution.ts`, `src/client/envExt/api.internal.ts`, `src/client/envExt/types.ts`, `src/client/common/terminal/service.ts`, `src/test/terminals/codeExecution/codeExecutionManager.unit.test.ts`
- **Validation:** With Python Environments enabled, select an environment and execute `value = 41`, then `print(value + 1)` through python.execSelectionInTerminal; expect 42 in the agreed persistent terminal. Repeat across two configured projects and with the integration disabled, checking environment isolation, multiline Smart Send, terminal launch arguments, and focus behavior. Add targeted coverage in the existing Terminal - Code Execution Manager unit suite for enabled and disabled delegation.
- **Behavior:**

  > Run Selection/Line in Python Terminal should participate in the Python Environments execution integration when enabled. Successive selections must preserve interactive Python state and use the selected environment for the active document's project. Existing Smart Send, launch arguments, focus settings, and disabled-extension behavior must remain intact. The relationship between selection terminals and whole-file run terminals needs an explicit acceptance contract.
- **Trace:**

  > The request identifies the omission in https://github.com/microsoft/vscode-python/commit/e78934859fba927231bfdb2673cece754169ecd8. CodeExecutionManager.registerCommands branches to executeUsingExtension for file commands, while executeSelectionInTerminal obtains the standard execution provider. TerminalCodeExecutionProvider.execute initializes a REPL and submits normalized code through the legacy terminal service. That service already delegates terminal creation through ensureTerminalLegacy, and interpreter resolution also consults the environment extension, so this is not a complete absence of environment integration. The remaining uncertainty is how persistent selection execution fits the script/module-oriented runInTerminal contract in src/client/envExt/types.ts. Preserve interactive state and existing normalization; arbitrary manually opened terminal reuse requested by https://github.com/microsoft/vscode-python/issues/24960 is separate work.
- **Open decisions:**
  - Should selection execution retain a separate persistent REPL terminal per project/environment, or share the environment extension's whole-file execution terminal, including the behavior when users alternate selection and file runs?
