# Issue #24766 — Improve first-time testing (& coverage) experience

[https://github.com/microsoft/vscode-python/issues/24766](https://github.com/microsoft/vscode-python/issues/24766)

## Summary

The first-time testing gap remains on current main, and the issue is accepted for investigation under `needs spike`. The existing flow still requires explicit framework and unittest discovery configuration, while coverage depends on separately installed environment packages.

## Change summary

Make initial unittest discovery and coverage execution work with sensible defaults and environment-aware dependency installation instead of requiring several configuration and troubleshooting steps.

## Best solution

Provide no-config detection for conventional unittest projects, using the existing `test*.py` and workspace-root defaults without prompting unless discovery needs disambiguation. Coverage should use the shared environment-aware package installation flow described by the maintainer, while retaining VS Code's intentional per-test-item error presentation.
