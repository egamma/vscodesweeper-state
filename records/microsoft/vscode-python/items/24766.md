# Issue #24766 — Improve first-time testing (& coverage) experience

[https://github.com/microsoft/vscode-python/issues/24766](https://github.com/microsoft/vscode-python/issues/24766)

## Summary

Keep open as accepted testing-experience work: the `needs spike` label and maintainer response explicitly endorse a no-configuration flow, and current main still requires unittest users to complete the legacy configuration prompts.

## Change summary

Make first-time unittest discovery and coverage work with sensible defaults, clearer errors, and reliable dependency installation.

## Best solution

Automatically recognize conventional unittest projects and discover them with the existing default arguments, without requiring directory and filename-pattern prompts. Coverage dependency handling should target the selected interpreter and provide an actionable installation flow, while retaining VS Code's intentional per-item error presentation.
