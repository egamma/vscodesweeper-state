# Issue #26100 — Conda environments disappear when ms-python.vscode-python-envs is enabled

[https://github.com/microsoft/vscode-python/issues/26100](https://github.com/microsoft/vscode-python/issues/26100)

## Summary

This is a verified duplicate of an older, open report tracking Conda environments disappearing from both the interpreter picker and Jupyter kernel selector when the Python Environments compatibility adapter encounters a no-Python environment. Consolidate there, preserving this report's Ubuntu and macOS confirmations and exact parsing error.

## Change summary

Enabling Python Environments hides valid Conda environments from interpreter and notebook kernel selection, with an invalid version no-python error.

## Best solution

Follow https://github.com/microsoft/vscode-python-environments/issues/1671 for the compatibility-adapter defect in vscode-python, ensuring an environment without Python cannot prevent other valid environments from reaching either picker.

## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode-python-environments/issues/1671 is OPEN and was created on 2026-07-23, before this report. It concretely reports successfully discovered Conda environments missing from Python: Select Interpreter with Python Environments 1.36.0; its discussion also confirms missing Jupyter kernels.
- **Maintainer diagnosis and confirmed trigger:** https://github.com/microsoft/vscode-python-environments/issues/1671#issuecomment-5286173538 identifies the Python extension's compatibility adapter: conversion of a Conda environment without Python can fail and stop the remaining update batch. https://github.com/microsoft/vscode-python-environments/issues/1671#issuecomment-5322595812 confirms that both interpreter and notebook kernel selection recover after installing Python into an otherwise empty environment; the original reporter independently confirms the same trigger at https://github.com/microsoft/vscode-python-environments/issues/1671#issuecomment-5323347421.
- **Exact failing source path:** src/client/pythonEnvironments/index.ts initialize() selects createEnvExtApi() when useEnvExtension() is enabled. In src/client/envExt/envExtApi.ts, onDidChangeEnvironments() synchronously iterates the update batch and calls addEnv(), whose toPythonEnvInfo() calls parseVersion(pythonEnv.version) without isolating conversion failures. src/client/pythonEnvironments/base/info/pythonVersion.ts parseBasicVersion() throws Error(`invalid version ${versionStr}`) for no-python, interrupting the batch before subsequent valid environments are added.
- **Evidence retained from this report:** https://github.com/microsoft/vscode-python/issues/26100 supplies the exact invalid version no-python error on Ubuntu 25.10 with Python 2026.4.0, Python Environments 1.36.0, and Miniconda 25.7.0. Its confirming comment reports macOS 26.5.2 and restoration of both interpreter and Jupyter kernel lists when Python Environments is disabled. These are additional manifestations of the canonical adapter failure, not evidence of a separate platform-specific defect.
