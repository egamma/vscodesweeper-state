# Issue #21776 — Run Selection/Line in Terminal again fails when running from an Untitled file

[https://github.com/microsoft/vscode-python/issues/21776](https://github.com/microsoft/vscode-python/issues/21776)

## Summary

The confirmed REPL-routing defect remains visible on current main. The issue is already accepted with `needs PR` and correctly routed to `area-repl`.

## Change summary

Running a selection from an untitled or out-of-workspace Python document creates a different terminal service and sends code to its shell instead of reusing the active Python REPL.

## Best solution

Make selection execution reuse the active workspace REPL for untitled and out-of-workspace documents, rather than keying a second terminal service to their unmatched resource. Add coverage for switching from a workspace file to both document types.

- **source path:** src/client/terminals/codeExecution/codeExecutionManager.ts:226 passes the active document URI into execute(), including an untitled URI.
- **distinct terminal identity:** src/client/common/terminal/factory.ts:54-67 keys terminal services by the resource's workspace folder. A workspace file produces a workspace-scoped REPL ID, while an untitled or external resource produces a different empty-workspace ID.
- **failure mechanism:** src/client/terminals/codeExecution/terminalCodeExecution.ts:66-70 treats the REPL as globally active, but lines 49-63 subsequently obtain the resource-specific terminal service; after switching resources, code can therefore be sent to the newly keyed shell instead of the initialized REPL.
