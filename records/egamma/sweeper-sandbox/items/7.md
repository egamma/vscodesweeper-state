# Issue #7 — noteStats.timestampFormat is ignored, Insert Timestamp always inserts ISO

[https://github.com/egamma/sweeper-sandbox/issues/7](https://github.com/egamma/sweeper-sandbox/issues/7)

## Summary

The defect is conclusively present on current main: the Insert Timestamp command reads `noteStats.timestampFormat`, but `formatTimestamp` ignores that value and always returns an ISO timestamp. The issue already has the correct type and area labels, and no other open issue owns this work.

## Change summary

Make Insert Timestamp honor the `iso`, `date`, and `datetime` values of `noteStats.timestampFormat`.

## Best solution

Implement all three format branches in `formatTimestamp` in `src/stats.ts`, preserving full ISO output for `iso` and producing the documented date and local datetime forms for the other values. Add deterministic cases for every format to `test/stats.test.ts`.

## Evidence

- **source reproduction:** `src/extension.ts` reads `noteStats.timestampFormat` when `noteStats.insertTimestamp` runs and passes it to `formatTimestamp(new Date(), format)`.
- **root cause:** `src/stats.ts` names the second parameter `_format` and unconditionally returns `date.toISOString()`, so both `date` and `datetime` necessarily produce the same full ISO value as `iso`.
- **test gap:** `test/stats.test.ts` tests only the `iso` case; there are no assertions for `date` or `datetime`.
