# Issue #8 — Show estimated reading time next to the word count

[https://github.com/egamma/sweeper-sandbox/issues/8](https://github.com/egamma/sweeper-sandbox/issues/8)

## Summary

Reading time is an explicitly in-scope capability that current main does not provide. The only matching open report, https://github.com/egamma/sweeper-sandbox/issues/9, is newer and thinner, so under the re-review and duplicate rules it cannot be the canonical issue for this older, better-described request.

## Change summary

Show an estimated reading duration alongside the status-bar word count, with suitable presentation for short documents.

## Best solution

Keep this issue as the canonical reading-time request and decide whether the estimate belongs in the status-bar text, its tooltip, or behind a setting, including how sub-minute estimates appear. The resulting calculation belongs in src/stats.ts, with status-bar wiring in src/extension.ts, tests in test/stats.test.ts, and package.json updated only if the chosen contract adds a setting.

## Plan brief

- **Likely files:** `src/stats.ts`, `src/extension.ts`, `test/stats.test.ts`, `package.json`
- **Validation:** Run `npm test` with cases covering empty text, a sub-minute document, and a multi-minute document at the chosen words-per-minute rate; then verify in an Extension Development Host that the estimate appears in the chosen status-bar surface and updates when document text changes.
- **Behavior:**

  > Note Stats should provide an estimated reading duration derived from the current document's word count. The estimate must update with document edits and use a documented words-per-minute assumption. Empty and very short documents must have an intentional, consistent representation, and the presentation must remain glanceable without obscuring the existing word count.
- **Trace:**

  > Current main computes only words and characters in src/stats.ts through computeStats(), and formatStats() renders those values. src/extension.ts refresh() reads the active document, calls those helpers, and assigns the result to statusItem.text; the tooltip is currently static. package.json has no reading-time setting or command, so no existing capability satisfies the request. The project requires pure calculations to remain in src/stats.ts and VS Code wiring to remain in src/extension.ts; existing word and optional character-count behavior must remain intact. The newer https://github.com/egamma/sweeper-sandbox/issues/9 is the same request but cannot own this older re-reviewed issue.
- **Open decisions:**
  - Should reading time be always visible in the status-bar text, shown only in the tooltip, or controlled by a new setting?
  - What user-visible value should be shown for non-empty documents estimated below one minute, such as `< 1 min` or `1 min`?
  - What words-per-minute rate should form the documented public behavior within the requested 200–250 WPM range?

## Evidence

- **missing capability:** src/stats.ts exposes word and character counts only, while formatStats() renders only words and optionally characters; src/extension.ts passes that output directly to the status bar.
- **existing-capability check:** package.json contributes only noteStats.showCharacters and noteStats.timestampFormat plus the toggle, timestamp, and slugify commands; none provides a reading-time estimate.
- **related issue:** https://github.com/egamma/sweeper-sandbox/issues/9 requests the same reading-time capability but was created two seconds after this issue and contains only "Please show reading time like Medium does." It is therefore not an older canonical for this re-reviewed item.
