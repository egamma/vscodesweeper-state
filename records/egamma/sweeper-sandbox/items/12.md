# Issue #12 — Add a line and paragraph count

[https://github.com/egamma/sweeper-sandbox/issues/12](https://github.com/egamma/sweeper-sandbox/issues/12)

## Summary

This is an unimplemented, explicitly in-scope statistics request with no open canonical issue owning the same work. It should remain open and be routed to the status-bar area because the proposed presentation is in the item's tooltip.

## Change summary

Add document line and paragraph counts, potentially displaying them in the status bar tooltip to keep the visible label compact.

## Best solution

Define line and paragraph semantics, calculate both alongside the existing word and character statistics in `src/stats.ts`, and expose them through the status bar item in `src/extension.ts` without lengthening its glanceable default text. Pin the agreed behavior in `test/stats.test.ts`.

## Plan brief

- **Likely files:** `src/stats.ts`, `src/extension.ts`, `test/stats.test.ts`
- **Validation:** Run `npm test` with table-driven `computeStats` cases covering empty text, one line, trailing newlines, blank-line-separated paragraphs, whitespace-only blank lines, and multi-line paragraphs; then verify in an Extension Development Host that the agreed counts appear in the status bar presentation without changing the existing word/character label unexpectedly.
- **Behavior:**

  > Note Stats should report line and paragraph counts for the active document using clearly defined semantics. The information should remain glanceable and must not make the existing status bar text unnecessarily long. Acceptance should cover empty documents, trailing newlines, consecutive or whitespace-only blank lines, and paragraphs spanning multiple lines.
- **Trace:**

  > `src/extension.ts` `refresh()` reads the entire active document, passes it to `computeStats`, assigns `formatStats` to `statusItem.text`, and currently uses a static tooltip. `src/stats.ts` defines `TextStats` with only `words` and `characters`, while `test/stats.test.ts` has no line or paragraph cases. The capability is absent from the settings and commands declared in `package.json`, and no open issue owns the same request. Preserve the documented whitespace-based word-count behavior and the existing optional character display while determining the new counting and presentation contract.
- **Open decisions:**
  - What constitutes a paragraph: each non-empty line, or a block of text separated by one or more blank or whitespace-only lines?
  - How should line count handle an empty document and text ending with one or more newline characters?
  - Should line and paragraph counts always appear in the tooltip, or should either count be configurable or included in the visible status bar text?

## Evidence

- **missing capability:** `TextStats` and `computeStats` in `src/stats.ts` currently provide only word and character counts; `formatStats` likewise renders only those values.
- **current presentation:** `refresh()` in `src/extension.ts` sets a static `Note Stats — click to hide` tooltip, leaving the requested line and paragraph information absent from both the tooltip and status bar text.
- **existing surface check:** `package.json` contributes only `noteStats.showCharacters` and `noteStats.timestampFormat`; none of the existing settings or commands supplies line or paragraph counts.
- **canonical search:** The open issue list contains no issue asking for line or paragraph counts. https://github.com/egamma/sweeper-sandbox/issues/3 concerns incorrect whitespace handling in the existing word count and does not own this new capability.
