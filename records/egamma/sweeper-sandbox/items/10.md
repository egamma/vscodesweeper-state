# Issue #10 — Count only the selection when text is selected

[https://github.com/egamma/sweeper-sandbox/issues/10](https://github.com/egamma/sweeper-sandbox/issues/10)

## Summary

This is a real, currently missing status-bar capability that the project vision explicitly includes. No older open issue owns selection-based counting, while the presentation for one or multiple selections still needs a product decision.

## Change summary

Show statistics for selected text in the status bar, returning to document statistics when the selection is cleared and defining behavior for multiple selections.

## Best solution

Keep this request open and decide whether the status bar replaces the document count or presents selection and document counts together, plus whether multiple selections are aggregated. The resulting behavior belongs in the status-bar refresh and selection-event wiring in src/extension.ts, reusing the pure counting logic in src/stats.ts and adding focused tests where that logic remains VS Code-independent.

## Plan brief

- **Likely files:** `src/extension.ts`, `src/stats.ts`, `test/stats.test.ts`
- **Validation:** Run npm test for any new pure selection-statistics cases, then verify in an Extension Development Host that selecting and clearing text updates the status bar immediately and that multiple selections follow the chosen contract.
- **Behavior:**

  > When an editor has selected text, the status bar should report statistics derived from that selection rather than silently continuing to report only the whole document. Clearing the selection must immediately restore the document statistics. Multiple selections must follow an explicitly chosen aggregation rule, and selection changes must update the display without editing the document. Existing whole-document counting, character-count configuration, and hide/toggle behavior must remain unchanged.
- **Trace:**

  > src/extension.ts defines refresh(), which currently passes editor.document.getText() to computeStats and updates only for active-editor and document-content changes. It never reads editor.selection/editor.selections and has no onDidChangeTextEditorSelection listener, so moving a selection cannot affect the status item. src/stats.ts already exposes computeStats(text), meaning the counting semantics are reusable once the relevant text is identified; package.json has no setting or command that already covers the request. Keep the documented whitespace-based counting semantics and existing status-item visibility behavior unchanged. No older open canonical issue owns this work; https://github.com/egamma/sweeper-sandbox/issues/12 concerns different statistics rather than selection scope.
- **Open decisions:**
  - When text is selected, should the status bar replace the document total with selection statistics or show both values, such as "120 of 2,340 words"?
  - When multiple cursors have non-empty selections, should all selected ranges be aggregated or should only the primary selection be counted?

## Evidence

- **current code gap:** src/extension.ts refresh() always calls computeStats(editor.document.getText()), never reads editor.selection or editor.selections, and does not subscribe to onDidChangeTextEditorSelection.
- **existing capability check:** package.json contributes only noteStats.toggle, noteStats.insertTimestamp, noteStats.slugifyHeading, noteStats.showCharacters, and noteStats.timestampFormat; none provides selection-based statistics.
- **scope:** vision.md names counts derived from the document text or the selection as an in-scope capability.
- **canonical search:** The open issue list contains no older report requesting selection-based counting. https://github.com/egamma/sweeper-sandbox/issues/12 requests line and paragraph counts instead, so it would not satisfy this issue's selection behavior.
