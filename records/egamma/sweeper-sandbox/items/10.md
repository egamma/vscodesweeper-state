# Issue #10 — Count only the selection when text is selected

[https://github.com/egamma/sweeper-sandbox/issues/10](https://github.com/egamma/sweeper-sandbox/issues/10)

## Summary

Selection-aware statistics are explicitly in scope and remain missing from current main. This older, correctly labeled request should stay open; the newer selection-count request does not supersede it.

## Change summary

Show statistics for selected text, restore whole-document statistics when the selection is cleared, and support multiple selections.

## Best solution

Make the status bar respond to selection changes in src/extension.ts while keeping counting and formatting logic in src/stats.ts. Settle whether the label shows selection statistics alone or alongside document totals before implementation.

## Plan brief

- **Likely files:** `src/extension.ts`, `src/stats.ts`, `test/stats.test.ts`, `README.md`
- **Validation:** In an Extension Development Host, open 'one two three four', select 'one two' without editing, and verify the selected count is 2; clear the selection and verify the document count returns to 4. Select 'one' and 'four' with separate cursors and verify the combined selected count is 2. Check character statistics with noteStats.showCharacters enabled and the agreed selection/document presentation; add pure-helper assertions for any introduced aggregation or formatting behavior.
- **Behavior:**

  > Selecting text should immediately show statistics for that text rather than treating the whole document as the counted scope. Clearing all non-empty selections should restore document statistics without requiring an edit or editor switch. Multiple selections should contribute to the selected total, and character statistics should continue to respect noteStats.showCharacters. The maintainer must settle whether selection statistics replace the document label or appear alongside its total.
- **Trace:**

  > src/extension.ts activate() defines refresh(), which always passes editor.document.getText() to computeStats() and never reads editor.selections for counting. There is no onDidChangeTextEditorSelection subscription, so highlighting text alone does not refresh the item. src/stats.ts contains pure computeStats() and formatStats(); test/stats.test.ts exercises those helpers but not VS Code editor events. Preserve the documented word-count contract, the character-display option, toggle visibility, and hiding when no editor is active; unrelated counting and settings defects are outside this request. https://github.com/egamma/sweeper-sandbox/issues/40 is a newer report of the same central ask, not an older canonical. The remaining product uncertainty is the selection-versus-document label presentation, not the location or structure of the implementation.
- **Open decisions:**
  - While text is selected, should the status bar show only selection statistics or show selection statistics alongside whole-document totals, such as '120 of 2,340 words'?
