# Issue #6 — Slugify leaves a trailing hyphen and drops accented letters

[https://github.com/egamma/sweeper-sandbox/issues/6](https://github.com/egamma/sweeper-sandbox/issues/6)

## Summary

Current main conclusively contains both reported slug defects: punctuation becomes untrimmed edge hyphens, and accented letters are removed before slug generation. The issue is correctly labeled and remains necessary.

## Change summary

Slugify Current Line should avoid leading or trailing hyphens and retain accented letters or fold them to ASCII equivalents.

## Best solution

Define the intended accented-letter representation, then make `slugify()` in `src/stats.ts` produce clean edge-trimmed slugs and pin punctuation and diacritic cases in `test/stats.test.ts` without changing the command's line-replacement behavior.

## Plan brief

- **Likely files:** `src/stats.ts`, `test/stats.test.ts`
- **Validation:** Add slugify tests asserting no edge hyphens for punctuation-prefixed/suffixed headings and the chosen accented-letter output for `## Café menu, part 2!`, then run `npm test`.
- **Behavior:**

  > Slugifying a heading must produce a URL-friendly slug without leading or trailing separator hyphens. For `## Café menu, part 2!`, the accented letter must not disappear; it should follow the project's selected policy of either ASCII folding or Unicode preservation. Existing behavior for ordinary ASCII headings, including `## Hello World` → `hello-world`, must remain unchanged.
- **Trace:**

  > `noteStats.slugifyHeading` in `src/extension.ts` reads the current line and replaces it with the result of `slugify()` from `src/stats.ts`. The current helper strips a heading marker, lowercases, and replaces every run outside `[a-z0-9]` with `-`; this directly explains both untrimmed edge hyphens and the loss of `é`. Existing tests in `test/stats.test.ts` cover only a simple ASCII heading. The command's current-line replacement semantics and unrelated statistics and timestamp helpers must not change.
- **Open decisions:**
  - Should accented letters be normalized and folded to ASCII (`café` → `cafe`) or preserved as Unicode (`café` → `café`) in generated slugs?

## Evidence

- **current source:** `slugify()` in `src/stats.ts` lowercases the heading and applies `/[^a-z0-9]+/g`, which converts terminal punctuation to `-`, leaves that hyphen untrimmed, and treats `é` as a disallowed character rather than preserving or folding it.
- **command path:** `noteStats.slugifyHeading` in `src/extension.ts` passes the complete current line to `slugify()` and replaces the line with its result, so the helper's output is exactly what the user receives.
- **test gap:** `test/stats.test.ts` tests only `## Hello World` → `hello-world`; it has no coverage for leading or trailing punctuation or accented letters.
