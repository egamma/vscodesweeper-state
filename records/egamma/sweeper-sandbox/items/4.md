# Issue #4 — Changing noteStats.showCharacters has no effect until the window is reloaded

[https://github.com/egamma/sweeper-sandbox/issues/4](https://github.com/egamma/sweeper-sandbox/issues/4)

## Summary

The defect remains on current main: the status bar captures noteStats.showCharacters at activation and never responds to configuration changes. Keep this older, well-described report open as the canonical issue; the existing settings label correctly routes it.

## Change summary

Changing noteStats.showCharacters should immediately update the status bar without reloading the window.

## Best solution

The plan should establish an automated activation/configuration-event check for these transitions; the existing formatStats unit test alone is insufficient.
- **Behavior:**

  > Changing noteStats.showCharacters currently leaves the status bar unchanged until the window reloads. - **Trace:**

This conclusively explains both the stale display and why reloading makes the setting take effect. src/stats.ts formatStats() already handles both boolean values correctly, and test/stats.test.ts covers those pure outputs but not activation or event delivery. Preserve counting semantics, label formatting, command behavior and visibility rules; unrelated helper defects are outside this issue.
