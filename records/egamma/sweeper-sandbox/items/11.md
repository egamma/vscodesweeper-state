# Issue #11 — Command to copy the current stats to the clipboard

[https://github.com/egamma/sweeper-sandbox/issues/11](https://github.com/egamma/sweeper-sandbox/issues/11)

## Summary

This is a clear, in-scope feature gap: Note Stats computes document statistics but provides no command for copying them. The issue is already correctly classified and no open canonical issue owns the same request.

## Change summary

Add a command that copies the current document statistics to the clipboard as plain text.

## Best solution

Define a Copy Stats command in package.json, wire it to the active document and VS Code clipboard API in src/extension.ts, and keep any reusable plain-text formatting in src/stats.ts with tests in test/stats.test.ts. Before implementation, decide whether the copied fields follow noteStats.showCharacters and how this command should interact with future selection statistics.

## Vision fit

- **Fit:** aligned

- **Evidence:** vision.md lists "Counts and estimates derived from the document text or the selection" as in scope and states that the extension should "Measure, don't edit."

## Plan brief

- **Likely files:** `package.json`, `src/extension.ts`, `src/stats.ts`, `test/stats.test.ts`
- **Validation:** Run npm test with cases for the agreed plain-text stats format, then launch the Extension Development Host, invoke Note Stats: Copy Stats on a document with known counts, and verify that pasting yields exactly the agreed text.
- **Behavior:**

  > Note Stats should offer a command that copies the current statistics to the system clipboard as plain text for use outside VS Code. For a document with known word and character counts, invoking the command must place the agreed representation on the clipboard without modifying the document. The acceptance check must cover the exact field names, separators, and relationship to noteStats.showCharacters. Behavior with an empty document, no active editor, and an active selection must also be defined.
- **Trace:**

  > package.json currently contributes three commands and has no Copy Stats command. In src/extension.ts, refresh() obtains the active document text, calls computeStats from src/stats.ts, and renders it through formatStats; the existing command handlers cover toggling, timestamp insertion, and slugification only. src/stats.ts contains the pure TextStats, computeStats, and formatStats logic, while test/stats.test.ts pins helper output. The status-bar formatter includes a codicon and uses `chars`, so it is not automatically a suitable clipboard contract. Preserve the documented whitespace-based counting semantics and ensure the command does not edit the document.
- **Open decisions:**
  - Should copied text always include both words and characters, or should it follow noteStats.showCharacters and mirror the currently displayed statistics?
  - Should "current stats" mean the whole active document permanently, or follow selection-based statistics if https://github.com/egamma/sweeper-sandbox/issues/10 is implemented?
  - What exact stable plain-text format should the command use, including `characters` versus `chars` and whether numbers receive grouping separators?

## Evidence

- **existing capability check:** package.json contributes only noteStats.toggle, noteStats.insertTimestamp, and noteStats.slugifyHeading; there is no clipboard or Copy Stats command.
- **current code path:** src/extension.ts computes the active document's TextStats for the status bar, but none of its registered command handlers calls vscode.env.clipboard.writeText.
- **available pure logic:** src/stats.ts already provides computeStats and formatStats, although formatStats produces status-bar text with a codicon and abbreviated `chars`, not the requested plain clipboard representation.
- **canonical search:** The open-issue search found no other clipboard or Copy Stats request. https://github.com/egamma/sweeper-sandbox/issues/10 concerns selection-only counting and https://github.com/egamma/sweeper-sandbox/issues/12 concerns additional count types; neither would deliver this command.
